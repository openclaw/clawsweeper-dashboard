## Summary

This PR is still necessary as a maintainer decision proposal: it is not on current `main`, is stacked on the still-open RFC 0013 PR, and introduces a distinct host-lifecycle contract beyond the completed one-database snapshot primitive. The documentation is coherent and docs-only, but acceptance depends on an explicit decision about whether this broader recovery boundary belongs as an extension of RFC 0013 or as its own draft RFC tied to the core scale-to-zero work.

## What This Changes

This PR adds three draft RFC 0013 sidecar specifications for composing verified SQLite snapshots into recovery points, host-protected handoff, and readiness-gated restored Gateway admission.

## System Context

RFC 0013 defines the per-database SQLite snapshot artifact boundary; these sidecars sit above it to coordinate multiple owner artifacts and a host's shutdown and restore lifecycle. The resulting contract would guide hosts before they retire a Gateway generation and before restored Gateway work is admitted again.

  F --> G[Gateway work admission]

## Best Possible Solution

Keep RFC 0013 focused on the completed per-database SQLite artifact primitive, then accept the lifecycle contract only through an explicitly approved draft RFC or a clearly approved extension tied to https://github.com/openclaw/openclaw/issues/114145.
