## Summary

This is a substantive RFC proposal, not an already-implemented cleanup: it extends the completed SQLite artifact boundary with a new lifecycle contract for recovery-point composition, host handoff, and restored admission. The linked implementation slices are still open, and the proposed ownership split needs an explicit core maintainer decision before this documentation should be accepted.

## What This Changes

The PR adds three draft RFC 0013 sidecar specifications that define how verified SQLite snapshots can be composed into recovery points, handed off to a host, and admitted back into Gateway work after restoration.

## System Context

RFC 0013 defines the SQLite-safe snapshot artifact that state owners produce and verify. This addendum sits above that artifact boundary, combining owner snapshots and host acceptance evidence into a recovery workflow that controls when a restored Gateway may receive work.
