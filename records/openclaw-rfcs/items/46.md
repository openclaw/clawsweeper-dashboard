## Summary

This PR is still necessary as a proposed RFC boundary: it adds a new recovery-lifecycle contract above the completed SQLite snapshot primitive, and that ownership split needs an explicit maintainer product decision before it can be accepted or closed.

## What This Changes

Adds draft RFC 0013 sidecar specifications for composing owner snapshots into recovery points, handing them off to a host, and withholding Gateway work admission until restore reconciliation finishes.

## System Context

RFC 0013 defines verified snapshot artifacts for individual OpenClaw-owned SQLite databases. These proposed sidecars sit above that primitive, combining owner-selected artifacts with host acceptance and restored Gateway admission before work can resume.
