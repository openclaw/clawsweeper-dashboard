## Summary

Direct checkout inspection was blocked before any repository command could start, so this is deliberately conservative.

## What This Changes

This PR adds draft RFC 0013 sidecar specifications for composing recovery points, performing a durable final handoff, and admitting work only after restoration.

## System Context

RFC 0013 defines the SQLite-safe snapshot artifact owned by OpenClaw, while hosts control storage, ingress, process retirement, and wake behavior. These proposed sidecars sit above that artifact boundary and would define the evidence exchanged between state owners and a host before a Gateway generation can be replaced or work admitted.

## Architecture Diagram

flowchart LR
  A[Gateway state owners] --> B[Verified SQLite snapshots]
  B --> C[Aggregate recovery point]
  C --> D[Host durability acceptance]
  D --> E[Final handoff authority]
  E --> F[Fresh target restore]
  F --> G[Restored readiness check]
  G --> H[Work admission]

## Best Possible Solution

Have the snapshot and Gateway-contract owners decide whether to adopt a narrowly scoped, host-neutral sidecar contract; if accepted, keep it explicitly separate from the completed SQLite artifact contract and require future core implementation PRs to demonstrate upgrade-safe interoperability.
