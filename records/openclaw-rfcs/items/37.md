## What This Changes

This PR adds RFC 0023 and a normative sidecar defining four opt-in hosting profiles that compose readiness conditions into named local, container, reverse-proxy, and node-mode support postures.

## System Context

Hosting profiles sit above OpenClaw’s proposed readiness system: configuration, environment, or gateway arguments select a posture, which selects readiness criteria and exposes a support result. The result would feed host health/readiness consumers and release-conformance scenarios without replacing the underlying readiness evaluator.

## Best Possible Solution

Decide the readiness foundation first, then either accept a deliberately narrow initial profile catalog with explicit upgrade and conformance requirements or retain the readiness mechanism without named hosting profiles.
