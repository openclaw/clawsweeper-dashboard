## Summary

Keep this draft RFC open for an explicit product decision after the readiness dependency is settled. The proposal is coherent, opt-in, and well supported by linked packaged-runtime evidence, but merging it would establish a durable catalog, configuration contract, security posture, activation-identity model, and release-conformance commitment that cannot be accepted by automated review.

## What This Changes

Adds a draft RFC and normative v1 specification for four opt-in, release-tested hosting profiles composed over the proposed readiness-condition framework.

## Best Possible Solution

Land the readiness contract first, then adopt a small opt-in profile catalog with compatibility tests while initially treating packaged conformance as advisory; promote it to a release gate only after maintainers confirm the security predicates and the packaged upgrade matrix remains stable.
