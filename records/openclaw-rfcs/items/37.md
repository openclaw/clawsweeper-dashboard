## Summary

This documentation-only RFC remains necessary because it asks maintainers to choose a new, upgrade-sensitive hosting-support contract layered on the still-open readiness RFC. The branch is active and clean, but its product direction cannot be resolved through cleanup review alone.

## What This Changes

The PR adds RFC 0023 and a normative sidecar defining four opt-in hosting profiles—local, container, reverse-proxy, and node-mode—over the proposed readiness system.

## System Context

Hosting profiles would sit above Gateway readiness: deployment configuration selects an optional named posture, readiness evaluates the corresponding conditions, and operators consume the existing readiness and status outputs. The proposal also specifies inert catalog inspection and live validation, while runtime implementation would occur in the separate OpenClaw repository.
