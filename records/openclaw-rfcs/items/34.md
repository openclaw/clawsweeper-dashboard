## Summary

The RFC is coherent and narrowly scoped, but it remains necessary because the linked OpenClaw implementation is still open and maintainers have not accepted the proposed configuration-authority and security contract. The current head also lacks attached foreground lifecycle proof.

## What This Changes

Adds a 471-line draft RFC for opt-in ordered configuration layers with earliest-layer path ownership, limited monotonic tool-policy tightening, normal config validation, and a startup-only read-only effective snapshot.

## Best Possible Solution

Keep the RFC draft until maintainers approve the trusted-operator authority model, reconcile it explicitly with existing include/write/reload behavior, and pair acceptance with redacted foreground fresh-install and upgrade/no-flag proof from the linked implementation.
