## Summary

The live head is structurally strong, but the prior upgrade-compatibility blocker remains: an existing installation without a selected profile automatically receives the new `local` contract, whose required predicates can turn a previously healthy readiness response into 503. The draft should remain open for that correction, real rendered-document proof, and explicit maintainer acceptance of the proposed public contracts.

## What This Changes

The PR adds a 781-line draft RFC defining a canonical readiness-provider result, four standard hosting profiles, operator profile extensions, plugin readiness registration, transport projections, and release conformance gates.

## Best Possible Solution

Preserve current readiness semantics for unset upgrades, make stricter profile conformance explicit or staged, and let maintainers accept the provider/result foundation separately from the standard-profile catalog and operator-extension contract.
