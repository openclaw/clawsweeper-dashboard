## Summary

This remains a useful draft RFC, but it has a merge-blocking compatibility problem: installations that do not opt into a profile would implicitly receive new required `local` readiness criteria and could become unavailable after upgrade. The composed Docker scenario is also still unproven, so the PR needs maintainer product/API direction and contributor-supplied runtime evidence.

## What This Changes

Adds a 759-line draft RFC defining readiness-provider registration, canonical readiness conditions, built-in and operator hosting profiles, readiness projections, and release conformance testing.

## Best Possible Solution

Adopt the canonical condition/provider model incrementally, preserve existing readiness when no profile is explicitly selected, make stricter hosting conformance opt-in or migration-gated, and accept the RFC only after the discussion link and exact-head Docker failure/recovery proof are attached.
