## Summary

This RFC remains necessary: current `main` does not contain RFC 0018 or its readiness sidecars, and the linked OpenClaw implementation work is still open. The document is a coherent proposal, but its `gateway.readiness` activation rule and plugin-provider contract require explicit maintainer product and compatibility approval before acceptance.

## What This Changes

This PR adds RFC 0018 and two normative specifications for an opt-in, subject-aware Gateway readiness contract with selectable core criteria and bounded plugin providers.

## System Context

Gateway readiness determines whether an already-running OpenClaw Gateway is ready to serve work, based on startup, channel, drain, and runtime observations. This RFC would turn those observations into one structured result consumed by ready endpoints, health/status views, the CLI, operators, and optionally activated plugins.
