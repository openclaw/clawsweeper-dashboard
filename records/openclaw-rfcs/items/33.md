## Summary

The proposal is not obsolete or duplicated: current OpenClaw still uses a fixed Gateway-owned readiness evaluator and has no plugin readiness-provider registration surface. The RFC preserves legacy projections and unset-install behavior, but acceptance would create durable plugin API, configuration, response-schema, readiness-policy, and release-support contracts that need explicit owner approval. The central package-installed Docker workspace-full failure/recovery scenario also lacks real-environment proof.

## What This Changes

The PR adds an 817-line draft RFC defining canonical readiness conditions, plugin readiness providers, standard and operator hosting profiles, backward-compatible readiness projections, and release conformance.

## Best Possible Solution

Keep the RFC in draft, accept canonical normalization of existing Gateway conditions as the first stage if owners agree, and defer provider/profile public contracts until compatibility review and redacted package-installed Docker proof cover loopback rejection, workspace-full failure, no-restart recovery, legacy projections, and unset-profile upgrades.
