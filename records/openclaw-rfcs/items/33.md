## Summary

This RFC remains necessary and is not implemented on current main. The proposal is coherent and the earlier wording finding is resolved, but it must remain open because current-head real behavior proof is missing and maintainers have not yet accepted the stable core hosting-profile and compatibility boundary.

## What This Changes

Adds a 621-line draft RFC specifying four built-in hosting profiles, canonical readiness conditions, HTTP/status projections, upgrade semantics, and release conformance.

## Best Possible Solution

Adopt the backward-compatible canonical readiness condition model and local projection as the first accepted slice, preserve the existing probe envelope during migration, and require separate approval and upgrade proof for every stricter profile and blocking release gate.
