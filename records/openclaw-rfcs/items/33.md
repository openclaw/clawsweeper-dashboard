## Summary

This RFC is still necessary as a maintainer product decision: it proposes a new opt-in readiness contract, configuration surface, and plugin extension boundary rather than documenting behavior already accepted on this repository’s default branch. The linked implementation work remains open, and the RFC explicitly asks maintainers to choose the compatibility, required/advisory, and provider-registration directions before those changes can become an approved contract.

## What This Changes

The branch adds RFC 0018 and a normative sidecar specification for opt-in canonical Gateway readiness conditions, operator-selected required or advisory criteria, and activation-scoped plugin readiness providers.

## System Context

Gateway readiness turns runtime observations into `/ready` and `/readyz` responses used by operators and hosting systems. This RFC proposes a shared condition model that accepts core observations and bounded plugin observations, aggregates them, and projects one result to HTTP, status, health, and CLI surfaces.
