## Summary

Keep this draft RFC open for a maintainer security/product decision. It proposes a new cross-channel authorization contract and explicitly identifies unresolved channel classifications and a required discussion step; current evidence does not show that the proposal is already implemented or that its semantics have been accepted.

## What This Changes

Adds a draft RFC that replaces the ingress authorization path’s boolean mutable-identifier signal with ordered sender authentication strengths—`verified`, `asserted`, and `mutable`—while preserving today’s default admission behavior.

## System Context

OpenClaw channel adapters provide sender identifiers to the ingress access-control path, which applies DM and allowlist policy before authorizing inbound activity. This RFC would let that path distinguish an identifier authenticated by a transport from one merely asserted by it, affecting bundled channel adapters and authorization-policy evaluation.
