## Summary

Current main at the supplied SHA still contains the source-reproducible false-positive path. Keep this issue open because the correction is narrow but changes a fail-closed secret-scanning boundary that should be explicitly approved before implementation.

## What This Changes

Make autoreview accept identifier and member-expression assignment values as code references without weakening detection of literal credentials or concrete token formats.

## Best Possible Solution

Add a context-scoped reference classifier for pure identifiers and dotted member expressions, retain all quoted-string, URI-credential, and concrete-token checks, and cover both reported safe cases and adversarial secret-like assignments with focused regression tests.
