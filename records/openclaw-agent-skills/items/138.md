## Summary

Keep this PR open for normal merge review. The targeted guard appears to fix a reproducible malformed-session export crash while preserving valid epoch-millisecond timestamps, and the PR body includes direct before/after CLI evidence plus focused regression coverage.

## What This Changes

The PR changes the Pi/OpenClaw importer to ignore invalid numeric `message.timestamp` values instead of passing them to `Date#toISOString`, and adds regression tests for valid and invalid numeric timestamps.

## Best Possible Solution

Merge the narrow importer guard with its regression tests so malformed numeric timestamps are treated like absent timestamps and cannot abort an otherwise valid session export.

## Solution Assessment

Yes. Centralizing the conversion in a small helper, reusing `numberValue()`, and checking Date validity before ISO formatting is a narrow maintainable fix that preserves valid numeric timestamps.
