## Summary

Keep this PR open: the router-side recovery fixes look directionally right, but the receiving assist and repair workflows can still let a receipt-only duplicate success suppress every later retry for the same dispatch key after the original worker fails.

## What This Changes

The branch adds recoverable dispatch claims and receipt keys for review, assist, and repair dispatches, updates three workflows to name and dedupe keyed runs, and adds focused repair/workflow tests.

## Best Possible Solution

Keep the recoverable claim design, but make receiver-side dedupe use the same real worker-execution proof as the router before treating an older successful receipt as the owner.

## Reproduction Assessment

Yes from source inspection: if an older real assist or repair run fails after a duplicate receipt-only run exits successfully, the router retries with the same stable key, but the receiver jq gate still skips because it sees the receipt-only success.

## Solution Assessment

No; router-side execution verification is necessary, but the receiver workflows also need to distinguish real worker success from receipt-only success before suppressing retries.
