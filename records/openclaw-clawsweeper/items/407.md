## Summary

Needs changes before merge: the latest head fixes the changelog and synthetic attempt-scoping parts, but two prior automation recovery blockers remain source-supported.

## What This Changes

The PR changes command-router dispatch claiming, deterministic receipt keys, repair run-name matching, and three receiving workflows so interrupted review, assist, and repair dispatches can recover without duplicate execution.

## Best Possible Solution

Keep the recoverable claim design, but make recovery prove that the successful workflow owned the actual worker path and refresh the durable claim when a stale or failed receipt is retried.

## Reproduction Assessment

Yes from source: an older active same-key run can cause a later duplicate workflow to exit successfully from the receipt job, and if the older run later fails `dispatchClaimDecision()` will still recover the duplicate success. A stale retry also keeps the old claim because `claimDispatchCommands()` skips commands that already have a prior claim.

## Solution Assessment

No, not yet; deterministic receipt keys are the right narrow direction, but the implementation still needs owner-run proof for recovery and a fresh claim timestamp when retrying stale dispatches.
