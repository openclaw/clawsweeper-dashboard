## Summary

Current `main` still contains both reported failure modes: inner repair reviews compare against a mutable branch ref, and fallible post-flight GitHub publication occurs before the durable execution report is written. The issue remains necessary, but the credential-refresh boundary needs explicit maintainer approval.

## What This Changes

## Best Possible Solution

Persist and upload the validated result before publication, then perform one exact final synchronization/review and publish through a freshly credentialed, deterministic post-flight step.
