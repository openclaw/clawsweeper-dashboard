## Summary

Keep open: current main only prunes duplicate command acknowledgements scoped to the current requested status marker, while this issue asks for a maintainer policy on preserving, marking, or deleting older status-bearing `re_review` comments.

## What This Changes

Evaluate whether stale older-head `@clawsweeper re-review` command-status comments should be preserved, marked or edited as stale, or deleted when a newer status comment supersedes them.

## Best Possible Solution

Maintainers should choose an explicit retention policy first, then implement only that narrow behavior with tests for `re_review` versus `automerge`, trusted versus untrusted authors, current versus older heads, durable review preservation, and 404-safe deletion handling.
