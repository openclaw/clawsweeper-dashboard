## Summary

The second commit fixes both previously reported blockers, but the credential renewal still occurs after the executor has already attempted outcome-comment publication with the original long-lived step token. A long repair can therefore still end with the same 401 publication failure; durable report persistence now preserves the result, but the fresh-token half of the reported defect is not complete.

## What This Changes

Pins contributor-repair work to an immutable base, validates and reviews a tree changed by final synchronization, refreshes workflow post-flight credentials, and persists repair outcomes before publication.

## Best Possible Solution

Move outcome-comment lookup/publication out of the long-running executor into a short post-execution step authenticated with the newly minted scoped token, while retaining pre-publication report persistence and the synchronized-tree review.
