## Summary

The exact PR head remains necessary and the production design addresses the reproduced failures, but the prior P1 is unresolved: the new regression directly calls a helper rather than exercising the report-only CLI process used by the workflow. Green CI therefore does not prove that the production command loads the persisted report, publishes with the renewed credential, and avoids repair re-entry.

## What This Changes

Pins contributor-repair work to one immutable target-base SHA, performs one validation and review after a changed final synchronization, persists execution reports before publication, and renews the GitHub App token for post-flight actions.

## Best Possible Solution

Add a deterministic child-process regression that starts from a persisted deferred execution report, disables the original execution credential, invokes the compiled report-only command with a fresh publication stub, and proves successful publication with no repair, edit, validation, or review re-entry.
