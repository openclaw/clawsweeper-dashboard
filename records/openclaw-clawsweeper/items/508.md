## Summary

This PR should remain open but not merge as submitted. Its timeout wrapper usefully bounds several local git calls, yet the same patch removes the existing bounded fetch helper and leaves three synchronous network fetch paths without any deadline, contradicting the stated reliability goal.

## What This Changes

The PR adds a ten-minute timeout wrapper for direct synchronous git calls while replacing the existing timeout-bearing fetch helper with direct command-runner calls.

## Best Possible Solution

Use one shared git execution path that applies the configurable network timeout to every remote operation and a deliberate bound to local status operations, preserving existing non-timeout return semantics and adding focused regression coverage.
