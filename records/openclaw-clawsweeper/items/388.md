## What This Changes

The PR changes apply-decisions to detect stale PR head SHAs, remove stale review-derived PR labels, replace the durable review comment with a stale-review notice, and add label-sync test coverage.

## Best Possible Solution

Land the apply-layer stale-head guard after redacted real or staged apply proof shows a moved PR loses only stale review-derived labels and receives the stale-review notice while fresh-head reports keep normal label sync.

## Reproduction Assessment

Yes, at source level: current main records pull_head_sha but syncs PR review labels without comparing it to the live PR head, so a moved branch can keep old proof/rating/status labels. I did not run a live apply repro in this read-only review.

## Solution Assessment

Yes, guarding apply-decisions is the right mutation boundary because that is where stored reports become live GitHub labels and comments. The code shape is narrow, but merge should wait for real or staged apply proof.
