## Summary

The issue is still necessary on current main: the repair workflow combines a 20-minute configured Codex worker, a fixed 40-minute execution step, and a 45-minute job, while the executor can shrink later workers to a 30-second floor. Four cited current-main runs failed after substantial edit or validation work without publishing, and no open PR owns the fix.

## What This Changes

Make repair worker, fix-step, and job timeout budgets coherent so long edits leave meaningful time for validation, final review, reporting, and publication.

## Best Possible Solution

Land a bounded 30/70/75-minute worker/step/job contract with a five-minute deterministic reserve, shared validation of overrides, and tests proving a long edit still leaves useful validation and final-review capacity.
