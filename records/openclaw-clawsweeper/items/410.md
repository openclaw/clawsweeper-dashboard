## Summary

Keep this PR open: the performance direction is useful and well scoped, but the cache-hit path can carry an issue close verdict across target-branch changes without a fresh implementation check, which can let apply close from stale main-state evidence.

## What This Changes

The PR adds a review-content digest, persisted cache metadata, a cache-hit skip in the review loop, and focused tests for unchanged automatic re-reviews.

## Best Possible Solution

Keep the cache optimization, but make close proposals main-aware by including current git main state in the relevant cache key or forcing a full re-review before reusing issue close verdicts, with regression coverage for the carry-forward front matter.

## Reproduction Assessment

Yes: source inspection shows a prior complete issue close report can satisfy the new decision-agnostic cache gate while item content is unchanged, because issue digests omit current main and apply only checks item-level freshness before closing.

## Solution Assessment

No: the optimization is directionally good, but the current implementation is not the safest fix until close-decision cache reuse accounts for target-branch source state or forces a full review.
