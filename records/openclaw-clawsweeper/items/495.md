## Summary

This PR has strong exact-head proof, clean hosted checks, and correctly isolates pinned-checkout dependencies, but the final-sync path still classifies the synchronized tree against the pre-sync repair base. Upstream-only files introduced by a moving `main` can therefore look like repair changes, leaving a central acceptance case unresolved and blocking automerge.

## What This Changes

The PR adds isolated pinned-base dependency setup, external validation-blocker classification, bounded final-sync review behavior, documentation, and focused repair-lane regression coverage.

## Best Possible Solution

Preserve the actual repair-delta file set or establish its rebased equivalent after final reconciliation, then classify synchronized-tree failures against that boundary and cover the case where advanced main changes the failing file while the repair touches another file.
