## Summary

Keep this PR open: the proposed five-second timestamp-only grace period can permanently classify a real human update that occurs within that window as bot reconciliation churn, contrary to the stated requirement that later human activity remain reviewable.

## What This Changes

Adds a five-second scheduler grace period for delayed GitHub `updated_at` changes after ClawSweeper synchronizes a bot-owned review comment or label, with focused policy tests.

## System Context

The scheduler decides when repository items should be reviewed again by comparing GitHub item activity with a durable review record. Bot comment and label synchronization update that record, and the resulting due decision controls whether an item returns to the normal review cadence.

  E -->|No| G[Normal due scheduling]

## Best Possible Solution

Use an event-aware reconciliation mechanism that can identify the bot-owned mutation, or otherwise preserve ambiguous fresh activity, and prove both delayed bot synchronization and an immediate human follow-up in a disposable real GitHub setup.
