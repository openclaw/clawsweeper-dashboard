## Summary

Keep open: the referenced OpenClaw PR later self-healed on a subsequent apply pass, but current `main` still contains the freshness gate that can skip review-derived PR label restoration on the first stale-strip-plus-re-review apply pass.

## What This Changes

The issue reports that fresh PR review labels are not restored after stale-strip because open-PR label sync is gated by comment-recency freshness instead of matching review head SHA.

## Best Possible Solution

Patch the apply label-sync freshness logic so a complete same-head PR report restores review-derived labels after stale-strip without reopening stale-head label leakage.

## Reproduction Assessment

Yes from source inspection: a same-head complete PR report skips all review-derived PR label sync when `updatedSinceReview` is true, `reviewCommentOnlyUpdate` is false, and the durable comment timestamp is more than five minutes from `item.updatedAt`. I did not run an apply repro because this review is read-only and the issue already provides a live end-to-end trace.

## Solution Assessment

Yes in direction: the narrow fix should keep stale-head stripping but let complete same-head PR reports sync their derived labels, with regression coverage for stale-strip followed by command-triggered re-review.
