## Summary

Keep this PR open. Its durable-intake cutover is directionally aligned with the merged lower stack, but the current workflow still hard-codes the target repository for result publication and allows one rerun failure to abort later self-healing; its parent dispatch/recovery design in https://github.com/openclaw/clawsweeper/pull/884 also remains under maintainer-directed rework.

## What This Changes

This PR changes cluster-repair workflow intake and result publication to use durable state intents, exact-path materialization, narrower GitHub App credentials, and updated operator guidance.

## System Context

Scheduled GitCrawl intake selects one repair cluster, records it through the durable state service, and then starts a repair worker. Result publication and self-healing feed the worker outcome back into the state projection so later recovery can continue without broad state-repository writes.
