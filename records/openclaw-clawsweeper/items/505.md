## Summary

This issue remains necessary: current main assigns review publication and apply/comment-sync to the same job-level concurrency group, and the cited live run waited about three hours before a truncated `gh api --jq` subprocess failed outside the existing JSON parser retry. The reproduced P0 regression should stay open for explicit maintainer handling because its author is a repository member.

## What This Changes

Separate review publication from apply/comment-sync serialization, preserve concurrent record-tuple reconciliation, and retry complete GitHub CLI commands after truncated JSON failures.

## Best Possible Solution

Give publish and apply/comment-sync distinct per-target concurrency groups, retain conflict-aware atomic record-tuple reconciliation for every writer, add bounded whole-command retry, document the operator behavior outside release-owned `CHANGELOG.md`, and prove queue admission plus concurrent state publication in a safe harness or live run.
