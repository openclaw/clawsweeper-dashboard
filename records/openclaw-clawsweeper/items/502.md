## Summary

This draft should remain open because the new automated-merge authorization guard verifies that each credential is some GitHub App installation token, but does not prove that either token was issued by the configured ClawSweeper App. The defect affects all three merge paths using the shared helper and should be fixed before maintainer review continues.

## What This Changes

The PR adds risk-ordered staged repair validation, immutable proof traces, hardened read-only command parsing, and strict GitHub App and branch-policy checks before automated repair merges.

## Best Possible Solution

Derive token-authenticated installation App identity for both credentials, compare each identity with the configured ClawSweeper App and with the other credential, add a mismatched-App regression test, and preserve the separate least-privilege tokens and fail-closed branch-policy behavior.
