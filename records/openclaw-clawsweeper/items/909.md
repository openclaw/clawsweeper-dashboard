## Summary

Keep this PR open. The follow-up commit and successful CodeQL run appear to resolve the earlier environment-derived command-label concern, but the new shared sanitizer still leaves `Authorization: Bearer <credential>`-style text intact before the new server-side log calls. Because this is a draft security-boundary PR authored by a repository member, it needs that narrow correction and human review rather than automated cleanup.

## What This Changes

The PR adds shared operational-error sanitization, removes raw backend details from dashboard and state-blob API responses, and redacts credentials from failed Git subprocess output.

## System Context

The dashboard Worker accepts review and state-blob requests, translates storage failures into HTTP responses, and emits server-side diagnostics for operators. The repair publishing path runs Git commands to update durable review state, so its process output must be safe before it reaches CLI logs or thrown errors.
