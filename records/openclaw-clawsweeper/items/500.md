## Summary

The fast path is broadly conservative, but its final cleanup has a version-ownership race: an older duplicate delivery can remove acknowledgement state that a newer edited delivery has reused. This member-authored draft should remain open, and the race should be fixed before merge.

## What This Changes

Forwards authenticated issue-comment timestamps and body hashes through both webhook paths, then short-circuits already-terminal duplicate versions after durable ledger agreement and live GitHub comment verification.

## Best Possible Solution

Keep the exact-version suppression, but bind acknowledgement and reaction cleanup to version-specific ownership so an older terminal delivery cannot remove state established for a newer edit.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: an old duplicate can pass its final source-version check, then an edited webhook can reuse the same comment-ID acknowledgement and reaction before old cleanup removes them. The edited command still routes later, so the established symptom is lost immediate status rather than command loss.

## Solution Assessment

No as currently implemented; the fail-open suppression is appropriately narrow, but cleanup is not tied to the exact version whose terminal state was verified.
