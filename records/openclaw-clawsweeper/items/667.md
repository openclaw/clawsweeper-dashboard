## Summary

This member-authored PR addresses a real automerge trust-boundary gap, but the new comparison occurs only in the early preflight; execution fetches the source PR again later and can still check out a newer head. Keep it open for a narrow repair and maintainer review.

## What This Changes

The branch stores the head SHA reviewed during deterministic automerge planning and adds a blocked/requeue result when the live contributor head differs during repair preflight.

## Best Possible Solution

Revalidate reviewed_sha against the same live pull object used for source checkout, immediately before checkout and again before any branch publication if a later refetch is required; retain the durable blocked report and add a regression test that advances the head in this post-preflight window.
