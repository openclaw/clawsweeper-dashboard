## Summary

Keep open. Current main still lacks a proof reproduction or head-pinned attestation lane, and the requested default-off gate changes are security-sensitive product work that needs maintainer direction.

## What This Changes

The issue proposes a default-off proof reproduction and attestation lane that runs reproducible PR proof on base versus head in a network-denied sandbox and lets close-safety prefer a head-pinned attestation over model-derived proof labels.

## Best Possible Solution

Keep this as the canonical design item and, if maintainers accept the direction, land a staged default-off implementation that starts with schema, sandbox probing, and read-only attestation records before any close-safety trust change.
