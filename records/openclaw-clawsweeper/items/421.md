## Summary

Keep open. Current main still lacks a proof reproduction or attestation lane, and the request is a security-sensitive product change rather than cleanup that can be auto-closed.

## What This Changes

Add a default-off lane that reproduces declared real-behavior proof on base and head, records a head-pinned attestation, and eventually lets close-safety prefer that attestation over model-derived proof labels.

## Best Possible Solution

Keep this issue as the canonical design thread and, if maintainers accept it, land a staged implementation that starts with schema, sandbox probing, and read-only attestation records before any close-safety trust change.
