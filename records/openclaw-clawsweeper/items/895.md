## Summary

The PR’s narrow completion contract and regression coverage address the linked queue-conflict bug, but it is still necessary to obtain after-fix proof against a real durable queue endpoint before merge. The supplied Docker/Crabbox run exercises the extracted workflow callback against a local HTTP stub, so it does not yet demonstrate that the production queue emits the audited response in the end-to-end path.

## What This Changes

This PR changes exact-review completion handling so the workflow succeeds only for a queue-proven `lease_superseded` response, while generic ownership conflicts remain visible failures.

## System Context

The exact-review workflow receives a lease from the durable queue, produces a review result, and calls the queue back with its terminal outcome. The completion callback must distinguish an already-fenced lease from malformed or mismatched ownership so workflow health reflects the durable queue’s actual outcome.
