## Summary

Keep this PR open: it correctly identifies that the completion callback obscures useful diagnostics, but it changes a queue-completion failure into success without evidence that the claim-side conflict vocabulary is terminal for completion. That could turn an unrecorded review outcome into a green run and suppress recovery.

## What This Changes

The PR updates the exact-review queue completion callback to inspect HTTP responses, accept four selected 409 conflict codes as a successful no-op, and expose unexpected response bodies in workflow logs.

## System Context

The exact-review workflow claims a durable queue lease, generates and publishes a review, then reports the run outcome back to the queue. The completion result feeds the workflow’s final success/failure gate and therefore affects alerting, retries, and queue reconciliation.

## Architecture Diagram

  C --> D[Publish review result]
  D --> E[Complete queue lease]
  E --> F[Workflow success gate]
  F --> G[Alerts and recovery]

## Best Possible Solution

Document or test the completion endpoint’s terminal 409 contract, then accept only codes that prove the outcome is already durably owned; otherwise retain failure semantics while logging the response for diagnosis.
