## What This Changes

The PR removes deterministic GitCrawl cluster scoring and filtering, then adds a model-driven selector that reviews hydrated cluster evidence, selects at most one candidate, and records its rationale in the intake ledger.

## System Context

The repair-cluster intake workflow turns GitCrawl cluster data into bounded repair work: it prepares candidates, gathers current GitHub evidence, records an intake decision, and dispatches a selected job into the repair lane. This PR changes the candidate-selection policy before the existing repair-worker mutation gates run.
