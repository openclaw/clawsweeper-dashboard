## Summary

Keep open for maintainer review: this PR intentionally changes the automated repair-intake ownership boundary, but its final commit restores the removal of an existing scheduled import-limit configuration contract, so existing installations can silently get different selection behavior.

## What This Changes

This PR replaces deterministic GitCrawl cluster ranking with a model that evaluates hydrated live cluster evidence, selects at most one repair candidate, and records its rationale in the intake ledger.

## System Context

The scheduled repair-cluster intake turns GitCrawl clusters into repair jobs. It stages unprocessed clusters, gathers live GitHub evidence for them, asks the internal model to choose one useful cluster or none, then passes the selected job into the guarded repair-dispatch workflow.

## Best Possible Solution

Define and preserve a deliberate upgrade contract for existing cluster-intake settings, then land the model selector only with explicit maintainer approval of its bounded role and validation for both upgraded and fresh configurations.
