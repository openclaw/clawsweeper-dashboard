## Summary

Keep this PR open. The one-shot response-body fix is focused, but retrying every signed request after an ambiguous network failure or 5xx can repeat a state-changing operation; it needs idempotency-safe scoping and after-fix live proof before merge.

## What This Changes

The PR reads signed Worker response bodies once so failures retain their HTTP status, Worker error code, and response snippet, and adds retry handling for transient network and 5xx failures.

## System Context

ClawSweeper exports and reconciles durable review records through signed requests to its Worker service. Those requests return snapshots and state-operation results that the local export/reconcile flow consumes and reports to operators.

## Architecture Diagram

flowchart LR

  B --> C[Worker service]
  C --> D[HTTP response]
  D --> E{Success or failure}
  E -->|Success| F[Decode record payload]
  E -->|Failure| G[Structured request error]
  E -->|Transient failure| H[Retry policy]

## Best Possible Solution

Keep one-shot response parsing, but restrict automatic retries to proven idempotent operations or add a Worker-enforced idempotency key, then attach redacted evidence from a real export or reconcile run showing the improved failure behavior.
