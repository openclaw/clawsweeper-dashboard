## Label Justifications

- `P1`: The changed retry classification can silently terminate review-publication delivery for active exact-review jobs.
- `merge-risk: 🚨 message-delivery`: Treating an unsuccessful queue response as terminal success can prevent the retry path that delivers the review publication.

## Summary

Keep this PR open: its intended stale-publication handling is narrow and useful, but the new early-success branch accepts any JSON payload with `superseded: true`, including a failed or malformed queue acknowledgement. That can stop retries before the newer durable publication is confirmed as the owner of delivery.

## What This Changes

The PR changes the exact-review workflow so a documented superseded publication acknowledgement ends the stale handoff successfully instead of retrying it.

## System Context

The exact-review workflow generates a review artifact and hands its immutable publication data to a queue-backed publisher. The publisher response controls whether the workflow retries delivery, records success, or lets a newer durable publication revision take ownership.

## Architecture Diagram

flowchart LR
  A[Exact review artifact] --> B[Workflow publication handoff]
  B --> C[Queue enqueue endpoint]
  C --> D{Acknowledgement shape}
  D -->|Queued or deduped| E[Finish successfully]
  D -->|Confirmed superseded| F[Newer revision owns delivery]
  D -->|Failure or malformed response| G[Retry publication]
  F --> E

## Best Possible Solution

Accept supersession only for the queue’s complete successful acknowledgement shape, preserve retries for every other response, and add a focused regression assertion for an unsuccessful superseded-shaped payload.
