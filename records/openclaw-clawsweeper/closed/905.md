## Summary

Keep this PR open. The 180-minute workflow timeout does not cover the 35-minute coordinator-acquisition allowance plus the new 160-minute drain allowance and finalization time, so a valid deep drain can still be killed before its configured drain budget completes.

## What This Changes

This PR raises the state-materializer GitHub Actions job timeout from 60 to 180 minutes and its configured materialization runtime from 40 to 160 minutes.

## System Context

The state materializer is the durable-state publication worker: it waits for coordinator access, drains queued state changes into an atomic state-repository update, and then finishes workflow publication steps. Its GitHub Actions timeout bounds the whole job, while the materializer runtime setting bounds only the drain work within that job.

## Architecture Diagram

flowchart LR
  A[Queued state changes] --> B[State materializer job]
  B --> C[Coordinator acquisition]
  C --> D[Drain and atomic state publish]
  D --> E[Finalize and publish events]
  B --> F[GitHub Actions job timeout]
  F --> G[Completed or cancelled drain]

## Best Possible Solution

Set a whole-job budget that explicitly reserves the coordinator wait and finalization time—either increase the job timeout above the combined bound or reduce the drain budget accordingly—and attach a redacted successful deep-drain run before merging.
