## What This Changes

Repair six repair and spam workflows so GitHub App token creation receives one installation owner while `CLAWSWEEPER_ALLOWED_OWNER` remains a multi-owner policy list for repair eligibility gates.

## System Context

ClawSweeper repair and spam workflows mint a GitHub App token before they can inspect runs, publish results, or execute recovery work. The shared repair library parses the allowed-owner setting as a list for authorization gates, but the token action requires one repository-owner value for its installation lookup.

## Best Possible Solution

Use the repository owner as the scalar GitHub App token owner in every affected workflow, retain the list parser solely for authorization gates, add focused regression coverage or a workflow assertion, and verify a real post-fix run plus any deferred-publication backlog.
