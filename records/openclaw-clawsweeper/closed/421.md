Keep open. Current main still lacks the proposed proof reproduction and head-pinned attestation lane, and the remaining work changes untrusted-code execution plus close-safety trust semantics.

## What This Changes

The issue proposes a default-off lane that reruns declared PR proof on base and head in an isolated sandbox and records a head-SHA-pinned attestation for close-safety use.

## Best Possible Solution

Keep this as the canonical design item and, if maintainers accept the direction, stage a default-off implementation that lands schema, sandbox probing, and read-only attestation records before any close-safety trust change.
