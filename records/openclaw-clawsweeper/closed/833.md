## Summary

This is a current, reproducible P1 apply-lane bug: the ledger can reject the default report path after an apply pass, preventing report publication and cursor advancement. The earlier matching fix proposal at https://github.com/openclaw/clawsweeper/pull/537 was closed unmerged, so this issue remains the canonical repair target.

## What This Changes

Make ledger-enabled `apply-decisions` complete successfully with its default report path and ensure the sweep workflow publishes apply results and advances its cursor.

## System Context

`apply-decisions` consumes reviewed item reports and performs the guarded GitHub apply pass. It then writes an apply report, records the action in the immutable ledger, and feeds the report into workflow publication and cursor updates.

## Architecture Diagram

  B --> C[Apply pass]
  C --> D[Apply report path]
  D --> E[Action ledger validation]
  E --> F[Report and cursor publication]
  F --> G[Next workflow window]

## Best Possible Solution

Make the command’s default ledger-valid and update report consumers or compatibility projections so both direct CLI callers and all mutating sweep lanes complete, publish results, and advance the cursor without weakening ledger validation.
