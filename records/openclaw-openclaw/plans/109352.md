# Coding Plan for openclaw/openclaw#109352: [Bug]: Final assistant text resolution has no run boundary: delivers all assistant text after the last user-role entry of the working transcript (growing exact-prefix re-sends when a context engine rewrites the transcript)

Source report: [records/openclaw-openclaw/items/109352.md](records/openclaw-openclaw/items/109352.md)

## Summary

Keep this issue open. Current `main` still derives the attempt boundary from a mutable transcript index and retains session-assistant fallback behavior, so a context-engine rewrite can plausibly select output outside the current run; the superficially similar https://github.com/openclaw/openclaw/issues/91959 concerned cumulative provider stream snapshots within one turn and does not own this cross-run bug.

## Plan

Fix https://github.com/openclaw/openclaw/issues/109352 by making embedded-runner final assistant resolution strictly run-scoped when a context-engine plugin rewrites, condenses, or reorders the working transcript during the run. Carry the immutable current-run assistant result from attempt execution through payload construction and final metadata instead of identifying it through `prePromptMessageCount`, the last user role, or a session-wide last-assistant fallback. Preserve the generic core/plugin boundary and existing behavior when no rewrite occurs. Add regression coverage that mutates transcript length/order after the prompt boundary, runs multiple turns, proves prior assistant text is never re-sent, and covers a run whose stream emits zero assistant texts. Do not add configuration, runtime compatibility shims, provider-specific logic, or `CHANGELOG.md` edits.
