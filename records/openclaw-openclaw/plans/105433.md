## Summary

Current main and v2026.6.11 both silently discard a command job’s complete `env` map when any value is non-string, because normalization removes the field before gateway schema validation. No duplicate or open fix PR owns this concrete shipped bug, so it should remain open for a focused repair.

## Plan

Fix the shipped cron command payload normalization bug reported at https://github.com/openclaw/openclaw/issues/105433. A present `env` object containing any non-string value must not be normalized into an absent field and accepted. Keep the protocol contract string-only; make both `cron.add` and `cron.update` fail clearly through the shared normalization or validation boundary; preserve valid environment maps unchanged; and add focused regression coverage for mixed valid/non-string values.
