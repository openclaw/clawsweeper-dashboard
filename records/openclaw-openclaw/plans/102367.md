## Summary

Keep open. Current main has strong adjacent Slack ambiguous-send reconciliation, but the cron strict announce path still does not opt into that exact recovery path and still converts failed or partial durable sends into cron run errors and failure alerts, so this report is actionable and not proven fixed.

## Plan

Fix https://github.com/openclaw/openclaw/issues/102367. Cron `--announce --channel slack` strict final delivery can duplicate after an ambiguous successful Slack send and then mark the cron run failed, causing a false failure alert. Preserve core/plugin boundaries: do not hardcode Slack policy in cron. Use or extend the existing generic durable-final support check so single-text cron announces opt into exact unknown-send reconciliation only when the target channel supports it; preserve `bestEffort` behavior and avoid breaking non-Slack channels. Add focused regression coverage proving the cron strict announce path passes through exact reconciliation where supported and does not emit a false failure alert when recovery can prove the Slack send already succeeded. Stop and ask for maintainer direction if the repair would require a new config flag, a new plugin API, or changing public delivery semantics beyond this bug.
