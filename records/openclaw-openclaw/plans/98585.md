## Summary

Keep open: current main still has an actionable approval-queue bug. The Control UI removes the active approval after a successful resolve but does not refresh the gateway pending lists when the local queue becomes empty, so a missed requested event can still leave a pending approval invisible; the linked fix PR was closed unmerged.

## Plan

Fix the approval-window queue bug tracked by https://github.com/openclaw/openclaw/issues/98585. Keep the gateway protocol unchanged. In Control UI, make approval button/Escape decisions carry the active approval id, resolve that id instead of assuming the current queue head, remove only that id, and after the final locally known item is dismissed refresh both `exec.approval.list` and `plugin.approval.list` while suppressing the just-resolved id so stale list responses do not requeue it. Preserve existing behavior for stale already-resolved/not-found errors. For macOS native exec prompts, serialize prompt presentation so concurrent socket/gateway requests wait behind the active prompt instead of competing. Add focused regression tests for queued approvals, missed-event refresh after final local dismissal, explicit id routing from the view, stale refresh suppression, and native prompt serialization.
