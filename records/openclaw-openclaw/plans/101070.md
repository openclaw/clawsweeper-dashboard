Keep open: current main has partial Chrome MCP timeout and session cleanup, but the target-crash dangling-promise risk is not proven fixed because several existing-session Chrome MCP paths still call the shared tool wrapper without timeout or route-abort wiring and there is no crash-specific regression coverage.

## Plan

Fix the Chrome MCP existing-session dangling-promise path reported in https://github.com/openclaw/openclaw/issues/101070. Extend the existing `callTool`/session lease cancellation path so all route-backed Chrome MCP helpers can receive timeout and AbortSignal data, reject promptly, evict the affected cached session, and avoid raw pending promise leaks when the MCP request hangs because the target browser crashes or the route aborts. Cover at least coordinate click, evaluate/wait, snapshot/screenshot, and navigation-adjacent paths, and preserve the existing stale-selected-page reconnect behavior.
