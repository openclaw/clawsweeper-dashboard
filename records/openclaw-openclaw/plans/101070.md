## Summary

Keep open: current main and the latest release still only bound Chrome MCP calls when a timeout or AbortSignal reaches the shared wrapper, and several existing-session actions plus the wait loop still call Chrome MCP without that wiring. Related Chrome MCP fixes landed, but none clearly owns this target-browser-crash dangling-promise gap.

## Plan

Fix https://github.com/openclaw/openclaw/issues/101070 by keeping Chrome MCP existing-session requests bounded and abort-aware when a target browser crash leaves the MCP subprocess alive. Extend timeoutMs and AbortSignal propagation through Chrome MCP helpers such as fillChromeMcpElement, fillChromeMcpForm, hoverChromeMcpElement, dragChromeMcpElement, uploadChromeMcpFile, pressChromeMcpKey, resizeChromeMcpPage, evaluateChromeMcpScript, coordinate click, and waitForExistingSessionCondition as appropriate; ensure route aborts and action timeouts reach those calls; evict/close the cached session on timeout, abort, transport close, or simulated target crash. Add focused regression coverage for hanging evaluate/wait/action paths and do not broaden this into targetId alias recovery tracked separately by https://github.com/openclaw/openclaw/issues/78602 or change non-existing-session Playwright/CDP behavior.
