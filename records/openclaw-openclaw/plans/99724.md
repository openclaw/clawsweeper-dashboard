# Coding Plan for openclaw/openclaw#99724: fix(cron): preserve on-exit watchers across hot reload

Source report: [records/openclaw-openclaw/items/99724.md](records/openclaw-openclaw/items/99724.md)

## Summary

Keep open: this is a useful candidate fix for the linked cron hot-reload bug, but the current patch still reuses in-flight watchers across a supported `cron.store` change, which can complete a watcher against the wrong cron store.

## Plan

Repair PR https://github.com/openclaw/openclaw/pull/99724 by preserving on-exit watcher managers only across same-store cron hot reloads. Compare the existing cronState.storePath with the next resolved cron store path, and pass existing exitWatchers to buildGatewayCronService only when they match. When the store path differs, use shutdown/cancel semantics for the old watcher manager so an in-flight child from store A cannot persist completion or fire through store B. Add a regression test in src/gateway/server-reload-handlers.test.ts for changedPaths: ["cron.store"] with active watchers and a different nextConfig.cron.store; assert the old exitWatchers are not passed into the rebuilt cron state and are cancelled/stopped. Preserve the existing same-store hot-reload behavior and do not add new config flags or changelog edits.
