## Summary

Keep open: current main still allows Discord outbound media up to OpenClaw's 100 MB default and sends non-video caption text and the file in one Discord request, so an oversized MP3 can reject the whole reply; the queued reply path can also log dispatch completion before async delivery failures are counted.

## Plan

Fix this issue's Discord outbound reply loss when generated media exceeds Discord's default upload limit. Keep the fix in the Discord channel/plugin outbound boundary: before `sendDiscordMedia` sends a non-video file, compare the loaded media size with the effective Discord upload cap when available, defaulting conservatively to 10 MiB; do not add a new config or env option. If media is oversized, send the text without the attachment plus a short visible note that the attachment exceeded Discord's upload limit; if there is no text, send a visible failure notice. Also make sure a completely undelivered reply is not logged or surfaced as completed. Do not implement transcoding or chunking in this PR. Add focused regression coverage for text+MP3 oversized media, media-only oversized media, and dispatch/delivery accounting. Do not edit CHANGELOG.md.
