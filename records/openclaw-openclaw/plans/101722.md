## Summary

Keep open. Current main still has the permissive keyed-answer parser; the report overstates the ordinary URL/time/path fallback case, but source proof shows delimiter-bearing answers can be corrupted when the accidental left side matches a question key.

## Plan

Keep the existing ergonomic keyed reply support (`repo: openclaw`, `mode: 2`) and blank-line positional fallback behavior. Add focused regression coverage in the shared SDK harness tests and, if useful, a Codex bridge test showing a collision case. Do not add config flags, channel-specific parsing policy, or adapter-local duplicate parsers.
