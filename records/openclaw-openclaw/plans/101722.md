## Summary

Keep open. Current main still has the shared keyed-answer parser that treats delimiter-bearing lines as keyed entries; the broad URL/time examples only corrupt whole-helper output on key collision, but the shared Codex/Copilot answer bridge still lacks regression coverage for that edge.

## Plan

Fix the agent harness user-input answer parser for https://github.com/openclaw/openclaw/issues/101722. In src/agents/harness/user-input-bridge.ts, keep the shared buildAgentHarnessUserInputAnswers boundary and preserve existing supported keyed replies such as `repo: openclaw`, `mode: 2`, numbered answers, option normalization, and blank fallback-line alignment. Harden parseKeyedAnswers or its use so ordinary unkeyed answer text containing URLs, Windows paths, times, or config snippets is not treated as a keyed reply unless the line is intentionally keyed to one of the current question ids, headers, questions, or supported numeric indexes.
