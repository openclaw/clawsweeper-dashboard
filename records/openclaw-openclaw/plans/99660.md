## Summary

Keep open: current main and the latest release still expose xAI buffered TTS only; the shared streaming TTS hook exists, but xAI is skipped because its speech provider has no `streamSynthesize`, and the related implementation PRs closed unmerged.

## Plan

Implement native xAI streaming TTS for the existing speech-provider streaming contract. Add `streamSynthesize` in the xAI plugin only, using `wss://api.x.ai/v1/tts` with `text.delta` then `text.done`, consuming `audio.delta` until `audio.done`, returning a `ReadableStream<Uint8Array>` plus release cleanup. Preserve current buffered `synthesize` and `synthesizeTelephony` behavior, do not touch realtime voice/Talk gateway-relay scope, do not add `sample_rate` or `bit_rate` config knobs, and keep custom REST-compatible `baseUrl` values out of the native WebSocket path unless maintainers explicitly approve. Use the closed PRs as reference but avoid dependency/lockfile changes. Update docs to distinguish xAI streaming TTS from realtime voice and batch TTS. Include focused tests for URL/query/header shape, native-host restriction, event ordering, audio decoding, done/close, timeout/error, release cleanup, and speech-provider integration. Put release-note context in the PR body, not `CHANGELOG.md`. If credentials are available, add redacted live proof showing `text.delta`/`text.done` leading to `audio.delta`/`audio.done` and non-empty audio bytes.
