# Coding Plan for openclaw/openclaw#101049: [Bug]: msteams plugin npm install can leave an empty dependency tree — plugin loads, provider dies silently, Microsoft sees delivery errors

Source report: [records/openclaw-openclaw/items/101049.md](records/openclaw-openclaw/items/101049.md)

## Summary

Keep open: current main has plugin dependency diagnostics for inventory, but the managed npm install path still appears able to accept an installed plugin package once package metadata exists without validating that its declared runtime dependencies resolve, and doctor only treats an install record as missing when the package.json path is absent.

## Plan

Implement a generic managed-npm plugin dependency integrity guard for OpenClaw-managed npm roots. After npm install and before recording success, read the installed plugin package.json dependencies and optionalDependencies, verify required direct dependencies resolve from the installed plugin package root or managed npm root using existing dependencyStatus-style resolution, and fail/roll back with an actionable error when required deps are missing. Extend doctor to flag installed npm plugin records whose package.json exists but dependencyStatus.requiredInstalled is false, and in --fix repair by reinstalling/updating the affected downloadable plugin through explicit plugin install/update flow, not gateway startup. Keep optional dependencies advisory-only unless an existing contract says otherwise, avoid Teams-specific literals in production code, and add regression tests for an @openclaw/msteams-style missing required dependency payload.
