# Coding Plan for openclaw/openclaw#99964: Successful main sessions can roll over as .jsonl.reset when transcript mtime is newer than registry updatedAt

Source report: [records/openclaw-openclaw/items/99964.md](records/openclaw-openclaw/items/99964.md)

## Summary

Keep open. Current main and the shipped v2026.6.11 source still treat a successful `status: "done"` main session as terminal for the transcript-mtime guard, so a newer transcript mtime can force rollover and `.jsonl.reset.*` archival even when daily/idle reset freshness is otherwise valid.

## Plan

Fix https://github.com/openclaw/openclaw/issues/99964. Current main treats `status: "done"` main-session rows as eligible for the terminal-main transcript-newer-than-registry guard, so successful sessions can roll over and archive as `.jsonl.reset.*` when transcript mtime is newer than registry `updatedAt`. Preserve the original stale-terminal recovery from https://github.com/openclaw/openclaw/issues/60542 and PR https://github.com/openclaw/openclaw/pull/90576 for interrupted/error/timeout/killed or genuinely stale rows, but prevent normal successful `done` sessions from false reset rollover. Add focused regression coverage for the reported shape and update existing tests that currently assert rotation for `status: "done"`; do not add a new `session.reset` mode or implement https://github.com/openclaw/openclaw/issues/57369. No changelog edit.
