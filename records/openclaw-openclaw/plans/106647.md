## Summary

Keep this issue open: current main still combines shallow transaction snapshots with in-place mutation of nested registry entries, so rollback can retain changes made during a failed plugin registration. The report identifies a valid bounded integrity defect, although its proposed generic deep clone is not the safest repair.

## Plan

Fix plugin registration transaction rollback so a failed registration restores all transaction-owned mutable registry state. Audit `src/plugins/plugin-registration-transaction.ts` and every in-place mutation performed through `src/plugins/registry.ts`, including PluginRecord arrays/counters and existing capability entries such as middleware runtimes. Do not apply `structuredClone` to the whole registry because function-bearing handlers and schemas must remain usable; prefer immutable updates or explicit cloning/restoration of only mutable data. Add focused regression tests that prepopulate a registry, mutate nested state during a transaction, force rollback, and assert exact restoration while successful commit still retains changes. Do not change plugin SDK contracts, config, defaults, public behavior, or CHANGELOG.md. Run the focused plugin transaction tests, changed checks, and build if the final change affects loader or registry module boundaries.
