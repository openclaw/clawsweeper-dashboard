## Summary

Keep open: current main still has a source-backed WebChat ordering gap because visible item sorting only uses top-level numeric timestamps, while Gateway transcript history can expose canonical record time in `__openclaw.recordTimestampMs`. The merged live-tool ordering PR fixed an adjacent causal tool-card race, but it does not cover this merged-session history metadata case.

## Plan

Implement a narrow Control UI fix for WebChat message ordering in merged-channel sessions. Preserve existing top-level numeric timestamp ordering, but when a history message lacks a top-level timestamp, use canonical transcript metadata such as `__openclaw.recordTimestampMs` and then stable transcript sequence as the fallback ordering signal. Keep the PR scoped to WebChat render/projection helpers and tests; do not change Gateway transcript storage, WeChat plugin behavior, provider routing, config, or the live tool causal ordering introduced by https://github.com/openclaw/openclaw/pull/93184. Add regression coverage for history messages carrying `__openclaw.recordTimestampMs` without top-level `timestamp`, including a user turn that must render before its assistant reply and a live/timestamped item that must not jump ahead of canonical history. Update or replace the existing expectation that timestamped items always precede untimestamped history only when no transcript metadata exists.
