# Coding Plan for openclaw/openclaw#106570: [Bug] Circular Structure Serialization Crash in OpenAI Completions Stream Error Handler

Source report: [records/openclaw-openclaw/items/106570.md](records/openclaw-openclaw/items/106570.md)

## Summary

Current main still uses fallible `JSON.stringify(error)` inside the OpenAI Completions stream catch path, so a circular non-Error rejection can replace the original provider failure with a serialization exception and leave consumers without a terminal stream event. The closely related Google-provider report identifies the same root cause and should be fixed in the same focused change.

## Plan

Fix the provider stream error-serialization defect tracked by https://github.com/openclaw/openclaw/issues/106570 together with the same-root-cause Google report at https://github.com/openclaw/openclaw/issues/106568. Introduce or reuse one provider-neutral helper for converting unknown thrown values into a non-throwing error message: preserve `Error.message`, return string values directly, attempt useful JSON output for other values, and fall back to `String(value)` if serialization throws or produces no string. Apply it to the affected OpenAI Completions and Google stream catch paths so each still emits its terminal error event and calls `stream.end()`. Add focused regression tests using a self-referential non-Error object and assert the original stream reaches a terminal error rather than rejecting from serialization. Do not add config, change provider routing/defaults, add a serialization dependency, edit CHANGELOG.md, or broaden unrelated error behavior.
