## Summary

The source trace supports a real shared active-run bug: OpenClaw accepts and persists an attachment-bearing inbound turn but sends only its text through the steering boundary. Current Codex and Pi contracts can carry images in streaming steer requests, so the issue remains necessary and has a bounded cross-runtime repair.

## Plan

Fix https://github.com/openclaw/openclaw/issues/107434 by preserving ordered image attachments when an inbound turn is accepted into an active steer-mode run. Extend the internal shared steering payload/API rather than adding a channel-specific Telegram exception: carry the existing `FollowupRun` image data through Pi and Codex steering adapters using each dependency's supported multimodal steer contract. If the active runtime rejects steering or cannot represent an attachment type, preserve the existing acceptance-aware fallback by enqueueing the full follow-up run with its images and `imageOrder`. Add regression coverage for one and multiple staged images, ordering, unchanged text-only steering, and rejection fallback.
