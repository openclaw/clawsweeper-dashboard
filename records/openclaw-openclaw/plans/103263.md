## Summary

The revision fixes the previously reported same-process GC race, but it does not protect an active run from supported removal in another OpenClaw process: the new lease is instance memory, while the run never takes the existing Git worktree lock that non-forced removers honor.

## Plan

Fix the active session-worktree removal race on this PR branch without adding a parallel synchronization source of truth. Make `agent-command` acquire managed-worktree ownership for a root or nested cwd through a service API that holds the existing PID-tagged Git worktree lock while any local run is active, reference-counts concurrent local users, and queues same-process destructive removal until the final release. Preserve explicit `force` semantics, snapshots, idle owner guards, nested cwd behavior, and current plugin-runtime acquire/release compatibility. Add regressions for nested cwd acquisition, concurrent acquisitions without premature unlock, queued same-process idle removal, and a separate `ManagedWorktreeService` or CLI-equivalent non-force removal that is rejected while the run is active and succeeds after release. Rebase onto current main and do not change config, protocol, or unrelated agent-command behavior.
