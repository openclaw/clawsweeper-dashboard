# Coding Plan for openclaw/openclaw#105681: [Bug] Tool-Call Aborts are Treated as Successful Execution Results Instead of Throwing AbortErrors (Bash Exec)

Source report: [records/openclaw-openclaw/items/105681.md](records/openclaw-openclaw/items/105681.md)

## Summary

Current main does stop the agent run after cancellation, so the reported continued execution and resource-leak impact is overstated. However, the central classification bug remains: a cancelled foreground exec resolves a failed payload, and agent-core classifies every resolved tool execution as successful.

## Plan

Fix foreground bash exec cancellation classification for https://github.com/openclaw/openclaw/issues/105681. In `src/agents/bash-tools.exec.ts`, distinguish cancellation by the tool caller's AbortSignal from ordinary process failures: preserve `run.disableUpdates()` and foreground `run.kill()`, wait for `run.promise` plus sandbox/session cleanup to settle, then reject with the recorded signal reason or a canonical AbortError. Do not change timeout behavior, explicit process-tool kill behavior, normalized ExecProcessOutcome contracts, background/yield session survival, or agent-core's general resolved-result semantics. Add focused coverage proving a foreground abort rejects and is emitted as an error tool execution while existing background-abort and no-late-update guarantees remain intact. No config, docs, or changelog change is expected.
