## Summary

Keep open: current main still builds the PI discovery credential map by taking the first convertible profile for each provider in raw store insertion order. That bypasses the documented profile-order and OAuth-preference resolver, and OAuth conversion accepts any positive expiry timestamp rather than rejecting expired credentials; the report therefore describes a live provider-auth regression, not an obsolete setup issue.

## Plan

Repair the PI auth-discovery bridge so it no longer selects the first raw stored credential per provider. Reuse the canonical auth-profile ordering and eligibility APIs for global selection, including `auth.order`, OAuth-over-token/API-key preference, expiry filtering, aliases, and SecretRef-safe handling. Trace background model-auth/compaction callers and pass a session `authProfileOverride` where it is already available rather than introducing another provider-only fallback. Cover the related SecretRef path from https://github.com/openclaw/openclaw/issues/58106 in the same generic contract. Do not persist resolved secrets, add provider-specific exceptions, change user config shape, or edit `CHANGELOG.md`; provide release-note context in the PR body instead.
