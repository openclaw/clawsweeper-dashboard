## Summary

The prior duplicate cache-owner blocker is fixed and the contributor supplied strong live proof, but the latest head still bounds native eviction to the entrypoint directory rather than the discovered plugin package root. OpenClaw-generated plugins use nested `dist/index.js` entrypoints, so plugin-owned modules elsewhere under the package root can remain stale after restart.

Likely related people: `steipete` and `vincentkoc` for native plugin-loading history, and `xzh-icenter` for the in-process restart cache-clear boundary.

## Plan

Fix the exact-head PR by tracking each native-loaded plugin entrypoint together with its discovered plugin `rootDir`, then pass that root as `dependencyRoot` to `clearNativeRequireJavaScriptModuleCache` during in-process restart. Add a regression in `src/plugins/loader.restart-reload.test.ts` where a nested `dist/index.cjs` entry imports a plugin-owned module elsewhere under the package root, edits only that module, and verifies restart loads the new export while external/shared modules remain untouched. Preserve the explicit restart-only lifecycle, existing shared cache owner, no freshness polling, no new config or public API, and no `CHANGELOG.md` edit.
