## Summary

The latest head still misclassifies user-invoked `cron.run(..., "due")` trigger-evaluator failures as scheduled work, allowing a verification run to alter retry state and delay a later scheduled payload. Current main retains the original destructive manual-run behavior, so this PR remains necessary but is not merge-ready.

## Plan

Repair this PR so every user-invoked `cron.run(..., "due" | "force")` remains manual even when trigger evaluation errors or is unavailable, while timer-owned trigger polling still increments scheduled failure counters and applies backoff. Propagate an explicit closed execution-origin value from the caller rather than inferring scheduler ownership from `triggerEval.fired`; preserve the existing manual `deleteAfterRun`, counters, alerts, backoff, due-slot, restart, and `lastRunWasManual` behavior. Add paired regression tests for manual due evaluator failure/unavailable versus timer-owned polling. Do not change `deleteAfterRun` policy for scheduled runs, recurring-job validation/defaults, or unrelated cron persistence behavior. Do not edit `CHANGELOG.md`.
