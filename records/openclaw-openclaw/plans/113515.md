## Summary

This PR remains necessary, but it still has a bounded correctness problem: a location derived only from a QMD file hint is cached under the document ID after the authoritative local index misses. If indexing later recovers or maps that ID differently, later searches keep using the fallback until cache clearing. The session-scope addition also lacks current-head real behavior proof.

## Plan

Repair the open PR’s QMD resolver without changing the intended stale-index fallback: use normalized QMD file/collection hints for the current lookup, but cache only locations resolved from authoritative local document rows (or otherwise add a narrowly invalidatable fallback cache contract). Add a regression test that uses one resolver instance, first resolves a missing document ID via a QMD file hint, then makes the matching authoritative row available and verifies the subsequent lookup uses the authoritative location without `clearCache`. Preserve the shared-global-session change unless its behavior requires a separate owner decision. Do not edit `CHANGELOG.md`; it is release-owned.
