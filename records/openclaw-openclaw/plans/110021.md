## Summary

This PR fixes an important Matrix DM isolation bug, but its new identity-link key encoding is neither injective nor upgrade-safe: distinct opaque labels can still share a session, and existing `@`-prefixed linked-label sessions are not adopted. Likely related people: `lukeboyett` (medium confidence), who introduced the shared case-preservation registry that this PR extends.

## Plan

Repair the current PR’s identity-link provenance contract without expanding `per-peer` scope. In `src/routing/session-key.ts`, replace the leading-`@`-only transformation with an injective representation for arbitrary opaque `session.identityLinks` labels, including literal `%40` and repeated leading `@` values. In the session-store resolution path, safely adopt or migrate a released raw `@` linked-label key only when the stored origin proves it belongs to the currently linked native identity; never adopt a case-distinct native Matrix peer or another linked label. Add fresh-install and upgrade regression coverage for `@person`, `%40person`, `person`, native `@person`, and both channel-bearing DM scopes. Do not change the documented folded `per-peer` behavior, Signal direct behavior, unrelated channels, config schema, or `CHANGELOG.md`.
