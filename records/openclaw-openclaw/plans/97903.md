# Coding Plan for openclaw/openclaw#97903: fix(agent): duplicate same-session turn when the gateway connection drops after accepting a run

## Summary

Keep this PR open: the core fresh-session direction is well scoped and now has real gateway proof, but the patch still loses the accepted-run signal across the transient retry wrapper, so a later retry failure can fall back onto the original session and leave the same duplicate-turn bug reachable.

## Plan

For this PR, fix accepted gateway-run context across `agentViaGatewayCommandWithTransientRetries`. When any gateway attempt receives an accepted frame and a later retry or final retry fails with a gateway transport fallback error before a final or `in_flight` response, `agentCliCommand` must use `runGatewayEmbeddedFallbackOnFreshSession` with `fallbackReason: "gateway_connection_lost"` instead of the generic `localOpts` embedded fallback. Preserve never-accepted generic fallback, timeout fresh-session fallback, successful transient retry to `in_flight`, abort semantics, and do not add flags/config or implement the reattach-first design from https://github.com/openclaw/openclaw/issues/98200. Add focused regression coverage in `src/commands/agent-via-gateway.test.ts` for accepted -> transient close -> retry non-transient close, asserting the original session key is not reused and the fallback session is `gateway-fallback-*`.
