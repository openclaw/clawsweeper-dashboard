## Summary

The runtime localization is well-scoped and the Chinese behavior is convincingly proven, but the generated output misclassifies untranslated English strings in other locales as completed translations. That makes the i18n check falsely report clean and prevents later provider-backed syncs from translating those keys.

## Plan

For every locale where a new `settings.*` value is still English, ensure the canonical i18n pipeline records that key in locale metadata `fallbackKeys` so future provider-backed syncs can translate it; alternatively provide a genuine locale translation.
