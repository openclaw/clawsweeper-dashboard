## Summary

The watchdog addresses a real source-level QQBot liveness gap, but the new counter is connection-independent and is not reset when a socket is replaced. A previous socket’s unanswered heartbeat can therefore make a fresh socket terminate after only one missed ACK, producing avoidable reconnect churn; keep this PR open for that narrow repair and for real QQBot behavior proof.

## Plan

Repair the QQBot heartbeat-ACK watchdog proposed in https://github.com/openclaw/openclaw/pull/114902. Keep the synchronous pre-ingress ACK reset and single parse path, but reset `outstandingHeartbeats` when a gateway WebSocket is discarded or before a replacement socket begins its heartbeat lifecycle so ACK debt cannot cross reconnects. Add a focused regression test: one socket misses an ACK, is replaced, and the replacement must still tolerate its first missed ACK and only terminate after two of its own unanswered sends. Do not add config, change reconnect policy, modify core channel APIs, or edit CHANGELOG.md. Validate with `node scripts/run-vitest.mjs extensions/qqbot/src/engine/gateway/gateway-connection.test.ts` and the applicable changed-file static check; obtain a redacted real QQBot runtime proof separately before merge.
