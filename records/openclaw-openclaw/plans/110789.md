## Summary

This issue remains necessary: current `main` still starts Windows cleanup with `taskkill /T` without `/F`, then schedules the forceful fallback three seconds later. The reported restart window can therefore bypass escalation when the owning process exits first; however, forcing every termination immediately would contradict the helper’s documented graceful-shutdown contract and needs Windows runtime proof before choosing that policy.

## Plan

Investigate Windows process-tree termination in `packages/agent-core/src/harness/env/kill-tree.ts` for this issue. Preserve the documented graceful-first default unless focused Windows evidence proves a narrower exception is required. Ensure that an owned npx-launched MCP or sub-agent child cannot survive when its OpenClaw owner exits before the delayed escalation fires. Add regression coverage for Windows argument selection/timing and obtain real Windows evidence using an npx MCP server or equivalent child tree. Do not add configuration, do not broaden process targeting beyond the owned PID tree, and do not change gateway port/listener cleanup paths.
