Keep this PR open, but not merge-ready: the captioned final-mode TTS direction addresses the linked Telegram churn bug and has useful proof, yet ACP direct-dispatch cancellation can still skip the text fallback and drop suppressed reply text.

## Plan

Fix the ACP captioned-final TTS cancellation fallback on this PR branch. The bug: when captioned final TTS suppresses ACP block text and the direct dispatcher accepts a final voice payload, `dispatch-acp-delivery.ts` marks the final as delivered-to-user/media before `waitForIdle()`. If a beforeDeliver or reply_payload_sending hook later cancels that final, `reply-dispatcher.ts` records `getCancelledCounts().final`, not a failed final, so `finalizeAcpTurnOutput()` leaves `finalMediaDelivered` true and skips the text fallback. Update the ACP path to treat final cancellations as undelivered for captioned final media, add a focused regression for direct-dispatcher cancellation of a queued captioned Telegram final voice, and preserve the existing routed hook-suppression behavior plus the non-ACP settle-lifecycle recovery. Do not change config, docs direction, or the public `captionedFinalText` capability decision in this repair.
