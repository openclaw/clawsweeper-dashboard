## Summary

This PR addresses a confirmed ACP startup failure and remains necessary because current `main` and v2026.7.1 still inject unsupported thinking configuration. The ACPX capability forwarding and Codex-only aliasing are sound, but removing inherited thinking for every ACP backend introduces a blocking compatibility regression for capable backends.

## Plan

Repair this PR without changing its intended OpenCode startup fix. Keep the ACPX `getCapabilities` handle forwarding, non-mutating capability copy, and Codex-only `thinking`/`thought_level` aliases. Restore model-derived thinking for ACP spawns, then update the ACP manager/runtime-option boundary so only auto-derived typed thinking is skipped when the active backend does not advertise a compatible key; explicit `/acp set` or backend-extra writes must still fail for unsupported keys. Add regression coverage for a Codex-style backend advertising `reasoning_effort`, an OpenCode-style backend advertising only `mode` and `model`, explicit unsupported configuration, capability-array non-mutation, and non-Codex alias gating. Do not add a new public config option, provider id, runtime fallback stack, or CHANGELOG edit.
