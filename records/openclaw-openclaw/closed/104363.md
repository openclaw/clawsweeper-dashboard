## Summary

Current `main` still serializes every `cron_reconciled` dispatch behind one promise tail, so an already-running stale observer can block the replacement generation exactly as reported. This protected issue also has an open closing PR that owns the repair, so it should remain open until that PR is merged or rejected.

## What This Changes

Fix cron reconciliation so a newer scheduler generation immediately supersedes and cooperatively aborts an older in-flight external projection instead of waiting behind it.

## Best Possible Solution

Keep one lifecycle-owned signal per authoritative scheduler snapshot, abort the previous signal immediately on replacement or shutdown, dispatch the new generation without waiting for stale observer completion, and retain focused reload and invalidation regressions with aligned plugin documentation.

Yes in direction. Snapshot-owned cooperative cancellation and independent replacement dispatch directly restore the lifecycle invariant; the linked PR is the narrowest implementation path, with its public hook-context compatibility reviewed before landing.
