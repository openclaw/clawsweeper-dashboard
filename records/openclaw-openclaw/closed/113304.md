## What This Changes

Fix backup and snapshot verification on native Windows so extracted SQLite files over the legacy path-length boundary are opened through the Windows namespaced path.

## System Context

OpenClaw backup verification extracts an archived SQLite snapshot to a staging location and opens it to validate the backup. The SQLite open result determines whether `backup verify` and `backup create --verify` accept the archive as usable.

## Best Possible Solution

Add one internal Windows SQLite VFS-path normalization path at the Node SQLite boundary, use it for every staged or extracted verification database open, and add focused Windows-path regression coverage without changing archive entry names or public backup APIs.
