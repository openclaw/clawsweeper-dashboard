## Summary

Keep open. The O(1) shared-disk design addresses the current Blacksmith disk-cap failure, but the dependency fingerprint omits pnpm patch-file contents, allowing warm CI to test stale patched dependency bytes after a patch-only change.

## What This Changes

The PR replaces per-PR and manifest-keyed Node dependency sticky disks with shared per-Node-version snapshots, runtime freshness fingerprints, read-only consumers, and designated protected-branch writers.

## Best Possible Solution

Hash every pnpm patch file referenced by the workspace into the runtime dependency fingerprint, add a patch-only freshness regression guard, then capture an exact-head warm run after the installation-level disk purge.
