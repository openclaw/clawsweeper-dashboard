## Summary

Keep this PR open for a narrow correction: this exact head still turns an unreadable HTTP 409 ownership conflict into an allowed send, while the related hardened candidate at https://github.com/openclaw/openclaw/pull/101968 preserves cancellation for every 409 but is not merged.

## What This Changes

The branch replaces unbounded forwarder-conflict JSON parsing with a 64 KiB bounded read and limits the in-memory Slack mentioned-thread cache to 1,000 entries.

## Best Possible Solution

Keep the 64 KiB read limit and cache bound, but catch owner-body read failures inside the 409 branch, log an unknown owner, and always return `{ cancel: true }` for HTTP 409; then reconcile or supersede the overlapping repair with https://github.com/openclaw/openclaw/pull/101968.
