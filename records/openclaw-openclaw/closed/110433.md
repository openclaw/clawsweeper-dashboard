## Summary

The reported post-connect WebSocket payload failure is already addressed in released OpenClaw: authenticated Gateway frames allow 25 MiB, including in the reporter’s stated `v2026.6.11`; the separate 64 KiB pre-authentication cap is an intentional handshake boundary rather than the chat-history transport limit. ([raw.githubusercontent.com](https://raw.githubusercontent.com/openclaw/openclaw/v2026.6.11/src/gateway/server-constants.ts))

## What This Changes

The issue requests increasing the 64 KiB WebSocket inbound and pre-authentication limits to 25 MiB, or exposing a configuration option.

## Best Possible Solution

Keep the shipped 25 MiB authenticated Gateway limit and the 64 KiB pre-authentication guard; if the symptom persists, diagnose the actual running Gateway binary or another WebSocket hop rather than widening the unauthenticated handshake limit.
