## Summary

This issue remains necessary: current main has a source-proven regression where automated device approval is not carried into the first node capability request, and no duplicate or implementation PR owns the proposed SSH verifier. Keep it open because the narrow regression repair should be split from the default-enabled outbound-SSH trust proposal, which has a protected `maintainer` label and needs explicit security direction.

Likely related people: `steipete` (high confidence, current reconciliation and pairing architecture) and `sahilsatralkar` (medium confidence, adjacent trusted-CIDR policy).

## What This Changes

Add SSH-verified automatic approval for first-time node devices, configurable SSH verification settings, a node identity CLI, and silent first node-surface approval after automated device pairing.

## Best Possible Solution

Land a focused repair that carries approved device provenance into only the initial node-surface request, then separately design a disabled-by-default `ssh-verified` approval mode with distinct provenance, constrained destinations, strict host-key and device-key matching, and adversarial fresh-install and upgrade proof.
