## Summary

Keep open: current main has the one-time `message_tool_only` prompt, suppression after confirmed message-tool delivery, and restart/delivery-failure recovery pieces, but I did not find an in-turn reminder refresh or same-turn correction path for a plain final produced after a long tool chain. The open related PR only addresses the Codex-specific progress-send terminal-stop case, not this model-agnostic recency/withheld-final report.

## What This Changes

The issue requests a core `message_tool_only` reliability fix so long tool-heavy turns keep or recover the visible-delivery contract instead of ending with withheld plain assistant finals.

## Best Possible Solution

Keep `message_tool_only` privacy intact, but add a compact stable contract-refresh and/or same-turn recovery path that nudges the model to send the withheld final through the message tool, with regression coverage for long tool chains and no duplicate source delivery.
