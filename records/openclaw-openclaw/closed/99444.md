## Summary

Keep open for maintainer clarification: current main has the reported unguarded timestamp comparisons, but the issue’s requested “treat unparseable timestamps as non-stale” fallback already matches JavaScript’s false-on-NaN comparison behavior, so the real desired repair is ambiguous.

## What This Changes

The issue asks to add an explicit NaN guard around compaction timestamp comparisons in `AgentSession` stale-compaction checks.

## Best Possible Solution

Define one explicit compaction-boundary timestamp parsing rule for `AgentSession`: either ignore invalid boundaries with regression coverage, or add a tested fallback if stale detection must survive malformed persisted timestamps.

## Reproduction Assessment

Partly. Source inspection plus a Node probe reproduce the NaN comparison behavior in current main, but there is no high-confidence end-to-end reproduction of the claimed duplicate compaction or OOM impact.

## Solution Assessment

Unclear. An explicit `Number.isNaN` guard is a good readability and test boundary only if invalid compaction timestamps should be ignored; it does not by itself fix stale-message detection for malformed boundaries.
