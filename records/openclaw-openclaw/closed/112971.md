## Summary

Keep this PR open, but it is not ready to merge: its own rationale says the sole current production caller already passes `detached: false` on Windows, so the new shared-helper sanitizer is not shown to run on the reported `exec`/`read` failure path. The Windows PowerShell A/B proves Node’s detached-spawn behavior, not that this branch fixes the current OpenClaw regression.

## What This Changes

The branch makes OpenClaw’s shared child-process helper force `detached: false` on Windows and adds tests for the platform-specific option handling.

## System Context

Agent and gateway tools use a process adapter to start commands and capture stdout/stderr. That adapter delegates launch options to the shared spawn helper, which applies fallback attempts before returning the child process to the tool path.

## Best Possible Solution

Trace the current Windows `exec` and `read` launch path from the user-visible tool through its adapter to Node spawn, then fix the first real `detached: true` leak or the actual output-loss boundary; keep a shared guard only if that trace shows multiple callers need the invariant.
