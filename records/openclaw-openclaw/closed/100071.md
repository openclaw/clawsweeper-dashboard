## Summary

Keep open: current main and v2026.6.11 still merge same-named skill sources by keeping only the winning higher-precedence record, with no shadow metadata in status, CLI, Control UI, or doctor lint. The report is valid security/visibility hardening, but the fail-closed config piece needs maintainer product/security direction before an automated repair is safe.

## What This Changes

The issue requests load-time warnings, CLI/UI/doctor visibility, and optional fail-closed policy when higher-precedence workspace skills shadow same-named plugin or bundled skills.

## Best Possible Solution

Add first-class shadow metadata during skill loading, surface warnings and markers in `openclaw skills list`, Control UI, and doctor lint, keep documented precedence as the default, and gate any fail-closed policy behind maintainer-approved config, docs, and tests.

## Reproduction Assessment

Yes, source-level. Create a plugin or bundled skill and a workspace skill with the same `name`; current loading keeps only the workspace record, and the status/list/UI/doctor paths have no field to report the lower-precedence source.

## Solution Assessment

Unclear as a complete implementation. Warning and visibility metadata are the right first step, but fail-closed shadow denial is a compatibility-sensitive config decision that maintainers should approve before implementation.
