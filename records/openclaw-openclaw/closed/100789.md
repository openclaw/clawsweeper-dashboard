- **[P2] Prefer terminal end time for completed task ordering:** `src/gateway/server-methods/task-summary.ts:29`
  - body: `taskUpdatedAt` still sorts and exposes `updatedAt` from `lastEventAt` before `endedAt`. Terminal finalizers such as tracked gateway agent tasks can provide only `endedAt`, and the registry only updates `lastEventAt` when it is supplied, so a task with old progress can finish now but remain ordered and displayed by the stale progress time. Use `endedAt` first for non-active statuses and add that regression case.
  - confidence: 0.9
- **[P2] Filter the Recent fetch to terminal statuses:** `ui/src/pages/tasks/tasks-page.ts:107`
  - body: `refreshTasks` already fetches queued/running tasks separately, but the Recent request is an unfiltered `tasks.list` page. In a busy fan-out with 200 recently updated active tasks, that page can contain no completed/failed/cancelled rows, so the Recent section misses the last terminal tasks even though the API supports status arrays. Request the terminal statuses for this call.
  - confidence: 0.86
