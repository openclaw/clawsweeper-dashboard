## Summary

## What This Changes

The issue requests a `Number.isNaN` guard after parsing string transcript timestamps in `src/infra/session-cost-usage.ts` so malformed values fall back to `0`.

## Best Possible Solution

Review and land one canonical linked PR that keeps `loadSessionLogs` timestamps finite with focused regression coverage, then close the duplicate candidate.

## Reproduction Assessment

Yes at source level: current main directly assigns `new Date(parsed.timestamp).getTime()` in `loadSessionLogs`, and Node confirms an unparseable string produces `NaN` that serializes as `null`. I did not run a full session-file gateway repro in this read-only review.

## Solution Assessment

Yes; guarding this parse in `loadSessionLogs` is the narrow maintainable fix and matches the same module's guarded timestamp parser pattern. Because open closing PRs already exist, the next action is review and land one of them rather than queue another fix.
