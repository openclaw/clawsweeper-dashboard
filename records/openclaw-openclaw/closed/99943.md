## Label Justifications

- `P1`: The reported bug would break a configured model fallback path during long-session compaction and surface a terminal agent error despite available fallback models.
- `impact:session-state`: The affected path is compaction, which preserves usable session context when an agent transcript grows too large.
- `impact:auth-provider`: The failure mode is in provider/model failover classification and routing across configured fallback providers.

## Summary

Current main and the latest release already solve the reported compaction-timeout fallback gap: compaction results are classified through the shared failover path, plain timeout text becomes a timeout FailoverError, and the model fallback loop continues to remaining candidates.

## What This Changes

The issue reports that implicit compaction timeouts on the primary model do not advance through `agents.defaults.model.fallbacks`.

## Best Possible Solution

Keep the shipped shared failover-classifier behavior; only reopen if new logs from current release show a non-timeout compaction failure shape still classifies as non-fallbackable.

## Reproduction Assessment

No for current main: the source path now classifies timeout text as failover reason `timeout` and the fallback loop continues to other candidates. The reported failure matches an older release path, not the shipped code inspected here.

## Solution Assessment

Yes. Reusing `coerceToFailoverError` for timeout classification is the best current fix because compaction inherits the shared provider failover contract instead of adding a compaction-only synthetic error branch.
