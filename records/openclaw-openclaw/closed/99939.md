## Summary

Keep open: current main and the latest release still tell Teams agents to use `card={type,version,body}`, but the current message action path only accepts `presentation`, so the reported raw-card behavior is not implemented and is not covered by the open markdown-table PR.

## What This Changes

The issue asks for Microsoft Teams message-tool support for raw Adaptive Card JSON or richer Adaptive Card primitives for approvals and structured notifications.

## Best Possible Solution

Decide the Teams card contract explicitly: either restore a validated plugin-owned legacy `card` path, or remove the stale prompt hint and extend `presentation` with the richer Teams-safe primitives maintainers want to support.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path for the raw-card mismatch: current main and v2026.6.11 still advertise `card`, but send validation and the Teams handler only treat `presentation` as rich content. I did not run a live Teams send in this read-only review.

## Solution Assessment

Unclear as an implementation direction: restoring the old raw `card` path would address the regression, but current docs prefer the portable `presentation` contract, so maintainers should choose the supported API before implementation.
