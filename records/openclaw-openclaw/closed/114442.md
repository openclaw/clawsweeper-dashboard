- `merge-risk: 🚨 auth-provider`: Changing which polling failures retry alters the visible OAuth authorization outcome and timing for existing users.

## Summary

Keep open: current main still ends device-code authorization when the polling fetch rejects, and this PR narrows that gap, but its retry path skips the configured polling delay and it has no real after-fix behavior evidence.

## What This Changes

The branch classifies fetch timeout/abort and TypeError failures during OpenAI device-code polling as retryable while preserving immediate propagation for other errors.

## System Context

The bundled OpenAI plugin runs a device-code authorization flow for headless ChatGPT/Codex sign-in. It requests a user code, polls the OpenAI authorization endpoint, then exchanges the returned code for stored OAuth credentials or reports the failure.

## Architecture Diagram

flowchart LR
  A[User starts device-code login] --> B[OpenAI plugin requests user code]
  B --> C[Polling loop]
  C --> D{Response or transport error}
  D -->|Authorized| E[Exchange code for OAuth credentials]
  D -->|Pending or retryable failure| C
  D -->|Terminal error or cancellation| F[Report login failure]
  C -->|15-minute deadline| F

## Best Possible Solution

Retry only the intended transport failures after the same deadline-bounded poll delay used for pending authorization responses, retain immediate cancellation and terminal-error propagation, and attach redacted live terminal or runtime-log proof.
