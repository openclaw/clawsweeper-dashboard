## Summary

This PR remains necessary as a product-direction phase of the config-journal work, but its central “every config mutation” and source-attribution claims are not yet met on the production write and supported-include paths. It also has the protected `maintainer` label, so it should remain open for human-owned review rather than automated cleanup.

## What This Changes

The branch extends config auditing with origin labels, capped changed-path lists, a fingerprinted snapshot baseline, and gateway records for externally edited config files.

## Best Possible Solution

Preserve one canonical journal chokepoint that receives origin metadata on every config-writing route, explicitly journal supported include-owned mutations, and record invalid offline observations before startup validation aborts.
