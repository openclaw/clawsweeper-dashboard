## Summary

Keep open: current main still has the reported source-level regression, and no merged or open PR appears to own this exact heartbeat CLI-binding persistence fix. The regression is current-main-only relative to v2026.6.11, but it should be fixed before it ships because it can stale Claude CLI context after heartbeat runs.

## What This Changes

The issue asks for heartbeat and preserve-runtime-model CLI runs to keep preserving displayed model fields while still persisting CLI session binding writes and clears.

## Best Possible Solution

Make model-state preservation and CLI binding persistence separate decisions: heartbeat and preserveRuntimeModel should preserve displayed model/context fields while still applying CLI session binding writes or clears, with internal handoff behavior left intact.

## Reproduction Assessment

Yes at source level: a heartbeat CLI run can pass cliSessionBinding or clearCliSessionBinding into persistSessionUsageUpdate, but preserveSessionModelState makes both update branches return before applyCliSessionIdToSessionPatch runs. I did not execute a live Claude CLI heartbeat reproduction in this read-only pass.

## Solution Assessment

Yes. The narrow maintainable fix is to keep the existing model-display preservation semantics but always apply CLI binding writes/clears except for the explicitly internal preserveUserFacingSessionModelState path.
