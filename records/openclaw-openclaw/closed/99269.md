## Summary

Keep open: current `main` and latest release still contain the fail-open item-status fallback and silent projector default path, while the upstream Codex protocol uses closed status enums that make this a real protocol-drift hazard.

## What This Changes

The issue requests fail-closed Codex event projection for unknown item statuses plus rate-limited diagnostics for unknown or mismatched notifications.

## Best Possible Solution

Keep the fix in the Codex plugin projector boundary: map unknown statuses to a non-success outcome with diagnostics, warn on unknown current-turn methods and mismatched correlation, and add focused regression coverage without adding config surface.

## Reproduction Assessment

Yes, there is a high-confidence source-level reproduction path: feed a current-turn item with an unrecognized `status` and `itemStatus` returns `completed`, or feed a current-turn unknown method and the projector default drops it. I did not execute a runtime test in this read-only pass.

## Solution Assessment

Yes, the requested direction is the narrow maintainable fix: fail closed at the Codex event projector boundary and add diagnostics using the existing correlation helpers. A broader core change is not needed unless tests reveal the run-attempt queue also needs progress-counting changes.
