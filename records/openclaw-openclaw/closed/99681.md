## What This Changes

## Best Possible Solution

Fix or prove the Discord plugin’s runtime abnormal-close recovery path so 1005/1006 closes either resume or re-identify without killing the gateway process; keep any channel-scoped manual reconnect as a secondary operator fallback, not the primary fix.

## Reproduction Assessment

Yes, at source/log level with medium confidence. ## Solution Assessment

No for a process-restart workaround. The best fix is in the Discord plugin gateway lifecycle so the channel recovers its own WebSocket; a channel-scoped reconnect action could be useful, but should not replace automatic recovery unless maintainers explicitly choose that fallback.
