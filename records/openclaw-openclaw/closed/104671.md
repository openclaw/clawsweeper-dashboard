## Label Justifications

- `P2`: The latest stable release had a limited rich-table presentation defect, now fixed in current main and the v2026.7.1 beta train.
- `impact:ux-friction`: Missing vertical borders reduced table readability without blocking or losing Telegram messages.

## Summary

Current main already fixes the reported Telegram table-border problem through the existing rich-HTML path: Markdown tables now emit Telegram’s supported `bordered` and `striped` table attributes and preserve column alignment. The proposed raw-Markdown rewrite is no longer necessary and would bypass established normalization, chunking, degradation, and fallback behavior.

## What This Changes

Request raw Markdown payloads for Telegram rich messages so native table borders render instead of HTML table output.

## Best Possible Solution

Keep the current bordered/striped rich-HTML renderer and its safety/fallback planner; open a new report only if a build containing v2026.7.1-beta.1 or later still shows missing borders on a specific Telegram client.

## Solution Assessment

No; switching the whole path to raw Markdown is broader than necessary because the merged bordered-HTML fix solves the symptom while preserving normalization, structural limits, degradation reporting, and plain-text fallback.
