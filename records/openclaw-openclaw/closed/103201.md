## Summary

The current head does not address the prior P1: session parity is still cached in an unversioned process-local set, so another Gateway or CLI writer can create derived-row drift that this manager will not detect. The incremental chunk-id design and runtime proof are strong, but the cross-process session-state correctness gap blocks merge.

## What This Changes

The PR changes session-memory indexing to preserve unchanged session chunks, delete stale rows transactionally, and embed and insert only new chunks.

## Best Possible Solution

Bind cached parity to the authoritative shared SQLite index revision, or remove the shortcut and always run the id-exact probes, then add a two-manager drift-and-heal regression while preserving transactional stale-id derivation and the no-migration design.
