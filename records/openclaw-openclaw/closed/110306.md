## Label Justifications

- `P2`: A port collision can make scripts and supervisors misclassify a failed gateway start as success, but the impact is bounded to the collision path.
- `impact:other`: The concrete impact is incorrect process-exit semantics for automation and supervision, outside the more specific owned impact categories.

## Summary

Keep open: current main still treats any HTTP response below 500 from `/healthz` as a healthy existing gateway, so an unrelated listener returning 404 can make `gateway run` succeed after its bind failure. The report has a concrete, bounded core-runtime defect and carries the protected `maintainer` label.

## What This Changes

Make `openclaw gateway run` exit nonzero when its configured port is occupied by a non-OpenClaw HTTP server, while retaining graceful handling for a confirmed healthy OpenClaw gateway.

## Best Possible Solution

Require the collision probe to verify an OpenClaw-specific health response before returning success, preserve nonzero exit for every other listener, and cover both cases with focused gateway-start tests.
