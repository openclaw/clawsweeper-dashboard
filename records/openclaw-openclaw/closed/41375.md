Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Honor outbound suppression before hook replies:** `src/auto-reply/reply/dispatch-from-config.ts:213-218`
  - body: This still delivers hook-generated messages immediately after `triggerInternalHook`, before `resolveSendPolicy` runs later in the function. A session configured with sendPolicy deny can still emit hook replies, so the delivery needs to be gated by the same outbound policy as normal replies.
  - confidence: 0.91
- **[P1] Route direct hook replies to the sender:** `src/auto-reply/reply/dispatch-from-config.ts:218`
  - body: When `OriginatingTo` is absent, `ctx.To` is commonly the bot identity and `ctx.From` is the user. This target order can send message:received hook replies back to the bot, and the new test currently locks in that wrong direction by expecting `whatsapp:+2000` instead of the sender.
  - confidence: 0.93
- **[P1] Update the helper for current routeReply metadata:** `src/auto-reply/reply/internal-hook-replies.ts:48-58`
  - body: Current main's `routeReply` path requires policy/session/requester/replyDelivery metadata and `replyKind` so outbound policy, sender matching, threading, and reply_payload_sending hooks see the right context. This helper calls `routeReply` with the older minimal shape, so a rebase needs to preserve the current delivery contract instead of bypassing it.
  - confidence: 0.86
- **[P2] Validate hook messages before trimming:** `src/auto-reply/reply/internal-hook-replies.ts:28`
  - body: Managed hooks are runtime JavaScript and can accidentally push non-string values despite the TypeScript type. Calling `.trim()` directly on every entry can throw and abort the awaited command hook reply path; filter to strings before trimming and keep malformed hook output from breaking the turn.
  - confidence: 0.82
