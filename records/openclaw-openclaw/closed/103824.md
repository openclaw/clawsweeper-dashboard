## Summary

The bug is valid, but this PR is not safe to merge as scoped because it changes a shipped drain method from consume-on-read to at-least-once delivery without updating or negotiating with its clients. The original feature was intentionally merged as a server-side foundation before the mobile consumer, so the recovery fix needs an owner-confirmed protocol shape and complete client and upgrade proof rather than a Gateway-only semantic change.

## What This Changes

The PR makes `node.pending.drain` non-destructive, adds the node-only `node.pending.work.ack` RPC, and updates Gateway tests, method registration, protocol docs, and the shared Swift acknowledgement result model.

## Best Possible Solution

Preserve the shipped `node.pending.drain` behavior for legacy clients and add a capability-gated or separately named read/ack lifecycle, then migrate every supported node consumer and prove both mixed-version upgrades and lost-response redelivery.
