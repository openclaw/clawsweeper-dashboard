## What This Changes

The PR rejects Gateway and canonical-roster config writes that would silently remove existing agent entries, while allowing the supported explicit agent-deletion flows to authorize a removal.

## System Context

Gateway clients can submit whole configuration objects, and CLI or Gateway agent-management commands mutate that configuration before the config writer persists its canonical agent roster. The persisted roster controls whether agent IDs resolve for sessions, metadata, and commands.

## Architecture Diagram

## Best Possible Solution

Land a single explicit-removal contract across Gateway, CLI, and shared persistence only after redacted live Gateway proof demonstrates that stale whole-config replacement is rejected without changing disk state and that supported explicit deletion still persists successfully.
