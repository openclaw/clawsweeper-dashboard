## Summary

Keep open: current main still makes OpenClaw compaction a no-op for over-budget non-harness Claude CLI sessions solely because the backend declares native ownership, while production evidence shows that ownership did not bound the transcript and recovery can silently discard user work. The original ownership PR did not test an organically over-budget Claude session, and the open context-budget PR preserves the same deferral, so neither resolves the central problem.

## What This Changes

Fix the Claude CLI compaction ownership gap that permits unbounded sessions and silent turn loss during overflow and recovery.

## Best Possible Solution

Adopt an observable, execution-mode-aware ownership contract: retain native compaction only when it demonstrably reduces the session, otherwise safely fall back to context-engine compaction or rotate the Claude binding; surface overflow and abort outcomes inline with a visible Recover/Fix action requiring no terminal commands.
