## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P2] Track validated networks before clearing online state:** `apps/android/app/src/main/java/ai/openclaw/app/gateway/NetworkMonitor.kt:48-49`
  - body: This callback is registered for all matching networks, but `onLost` clears the single `lastOnline` flag for any one of them. If cellular is already validated and Wi-Fi drops, this can leave the monitor marked offline while the device is still online, with no later validated transition to trigger the promised reconnect; track the validated/default network set or re-check active validated connectivity before clearing.
  - confidence: 0.88
- **[P2] Use ordered capability callbacks instead of querying in onAvailable:** `apps/android/app/src/main/java/ai/openclaw/app/gateway/NetworkMonitor.kt:36`
  - body: `onAvailable` calls `getNetworkCapabilities` synchronously and then decides whether to emit. Android's callback contract makes `onCapabilitiesChanged` the ordered source for the current capabilities, so this can race with stale or null capability state; wait for the provided capabilities callback and cover that path instead.
  - confidence: 0.84
