## Summary

Keep open for maintainer security/product review: current main and the latest release intentionally reject ACP bridge per-session MCP servers, while the requested Workbench Mac-control path needs a supported trust boundary rather than a shallow code flip.

## What This Changes

The issue requests either ACP bridge support for Workbench-provided session MCP servers or a documented Gateway/agent path that lets visible Workbench agents use the same Mac-control tools without exposing connector material.

## Best Possible Solution

Choose one explicit trust boundary: preferably document or package the Workbench Mac-control MCP as an OpenClaw-managed `mcp.servers` or bundle-style plugin path with redacted secrets and proof, and only add ACP per-session MCP if maintainers approve a default-off protocol design.
