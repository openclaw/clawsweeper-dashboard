## What This Changes

Expands shared invalid-API-key matching to recognize both word orders with suffix boundaries, and adds regressions for embedded provider-error results advancing model fallback.

## System Context

OpenClaw’s model fallback loop classifies a provider failure before deciding whether to try the next configured model. Embedded agent runs supply provider error payloads to that classifier, so authentication matching determines whether a healthy later provider can serve the turn.

## Architecture Diagram

flowchart LR

  B --> C[Fallback result classifier]
  C --> D[Authentication error matcher]
  D --> E{Failure reason}
  E -->|auth| F[Try next configured model]
  E -->|unclassified| G[No fallback advance]

## Best Possible Solution

Land the narrow shared-matcher and embedded-result regression after a current-base refresh confirms the exact-head fallback proof and focused tests still hold, while preserving ordinary `INVALID_ARGUMENT` request errors outside the authentication lane.
