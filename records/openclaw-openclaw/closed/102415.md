## Summary

This PR is still necessary because current main still subtracts trajectory timestamp and sequence sentinels, so two corrupt/unparseable window lines can make the comparator return NaN. The patch is narrow, keeps the existing trajectory window ownership, and I found no blocking code or security finding.

## What This Changes

The PR exports the trajectory window line comparator for tests, changes it from subtraction to relational comparisons with a raw-line tiebreaker, and adds focused total-order tests.

## Best Possible Solution

Merge this narrow comparator hardening after the PR body satisfies the repository proof/context gate and exact-head CI is green; no broader trajectory rewrite is needed.

## Solution Assessment

Yes, this is the narrow maintainable fix: keep the existing parser/window design and replace only the unsafe subtraction comparator with finite relational comparisons plus focused regression tests. The PR rationale should not need engine-dependent sort claims; the source invariant is enough.
