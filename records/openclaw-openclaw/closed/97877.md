## Summary

Keep open: current main still blocks the reported retry path with cumulative replay metadata, and the latest release has the same behavior. Three open PRs already target this issue, so this should stay open until one canonical fix lands or maintainers reject the direction.

## What This Changes

The issue requests fixing empty-error-retry so a clean transient provider 5xx after earlier session tool calls retries or surfaces a user-facing failure instead of silently ending the session.

## Best Possible Solution

Review and land a single fix that separates current-attempt replay safety from cumulative session replay state, includes classified server_error in retry eligibility, and keeps same-attempt side effects fail-closed.
