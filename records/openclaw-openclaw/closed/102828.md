## Summary

Close: current main no longer has the reported stale-binding failure path. Current-conversation bindings resolve by canonical session key rather than `target_session_id`, and current main also recovers failed terminal session rows on the next visible turn instead of rotating into the dead-session state described here.

## What This Changes

The issue reports that failed main-session restart recovery can create a new session while `current_conversation_bindings.target_session_id` still points at the old session, causing inbound Telegram messages to be lost.

## Best Possible Solution

Keep the current-main behavior: current-conversation bindings should remain session-key based, and failed terminal rows from restart recovery should be recovered in place on visible inbound turns.

Yes. Resolving bindings by stable session key and recovering failed terminal rows in place is narrower than trying to synchronize a denormalized session-id column after every restart or rollover.
