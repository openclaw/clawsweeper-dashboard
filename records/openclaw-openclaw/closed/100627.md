## Summary

Keep open: current main and the latest release still preserve caller-provided Undici proxy `clientFactory` values, and the report touches a core SSRF/proxy security boundary that should not be auto-closed without maintainer security review.

## What This Changes

The issue asks OpenClaw to harden custom Undici proxy `clientFactory` handling so proxy-created pools cannot bypass SSRF hostname allowlist and pinned-dispatcher expectations.

## Best Possible Solution

Have security maintainers define the `clientFactory` contract, then either reject custom factories on guarded proxy paths or wrap them so pinned lookup, proxy TLS, and SSRF hostname policy expectations cannot be bypassed, with focused regression coverage.

Unclear until security review: hardening belongs near the shared proxy/SSRF helper boundary, but maintainers must first decide whether custom factories are trusted transport code or part of the guarded contract.
