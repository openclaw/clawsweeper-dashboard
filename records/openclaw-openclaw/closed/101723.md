## Summary

Close: current main and v2026.6.11 already reject missing or blank `name` values before `skill_workshop` can create a proposal, so the reported ghost-proposal path is not reachable.

## What This Changes

Require the `skill_workshop` create action to reject missing skill names so it cannot create unrecoverable ghost proposals.

## Best Possible Solution

Keep the existing action-specific runtime and service validation; any future stricter model-side discriminated schema should be tracked separately as tool-schema ergonomics with focused regression coverage.

## Maintainer Decision

Required: false

## Reproduction Assessment

No; the reported current-main path does not reproduce because `action=create` reads `name` with `required: true` before calling `proposeCreateSkill`, and the service has a second required-name guard before target resolution.

## Solution Assessment

Yes; the current action-specific runtime guard plus service-level `normalizeRequired` backstop is the narrow maintainable solution for preventing unnamed proposal writes without splitting the shared tool schema.
