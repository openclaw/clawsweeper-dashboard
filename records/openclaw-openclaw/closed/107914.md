## Label Justifications

- `P1`: Interactive channel turns can terminate after long visible work with no final explanation, leaving real users unable to distinguish an abort from a hang.
- `impact:message-loss`: The expected terminal interruption message is suppressed, and users may receive no reply or only an incomplete draft.
- `impact:ux-friction`: Users must infer the abort or consult operator logs because the originating chat provides no useful terminal status.

## Summary

The silent-abort problem is valid, but the same remaining core defect is already tracked by the earlier open canonical issue, which includes a concrete stuck-session reproduction, the missing user-facing interruption notice, and a bounded implementation path. This issue’s timeout and cancellation matrix is useful acceptance-test context rather than a separate root cause. ([github.com](https://github.com/openclaw/openclaw/issues/103905))

## What This Changes

Ensure interactive agent runs produce a concise in-channel notice when they terminate because of timeout, stuck-session recovery, cancellation, or disconnection.

## Best Possible Solution

Track one core fix in https://github.com/openclaw/openclaw/issues/103905 that converts involuntary terminal abort outcomes into a sanitized, channel-agnostic interruption payload and adds focused coverage for timeout, stuck recovery, and cancellation without adding configuration by default.

No, not exactly as proposed: the best fix is a single terminal-outcome-owned fallback payload shared by all interactive channels, without adding an `abortNotice` configuration option unless a concrete suppression contract is established.
