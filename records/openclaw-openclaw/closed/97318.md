## Summary

Keep open: current main preserves normal nonzero exec output at the exec runner layer, but the shared tool-result classifier still turns completed results with nonzero exit codes into error results, which can still poison cron delivery and agent state.

## What This Changes

The issue requests that normal subprocess nonzero exit codes from the exec tool return stdout, stderr, and exit code to the agent instead of surfacing as framework-level tool failures.

## Best Possible Solution

Align the shared tool-result classification with the exec runner contract so normal subprocess exits preserve stdout/stderr/exit code as completed results, while spawn failures, timeouts, shell 126/127 failures, and signal terminations remain explicit tool failures.

Rationale: The lower exec runtime already models normal nonzero exits as completed, but changing the shared classifier affects multiple product surfaces that use `isError` for failure accounting and delivery decisions.

Owner confidence: high

Options:

- **Make normal nonzero exits completed (recommended):** Update shared classification and cron/UI tests so normal exec exits 0-125 preserve output and exit code without setting tool-error state, while shell 126/127, timeout, signal, spawn, and denial paths remain failures.
- **Add an explicit opt-in mode:** Keep current failure accounting by default and add a documented exec option such as accepted exit codes for workflows that use semantic nonzero exits.
- **Document wrapper-only behavior:** Leave runtime behavior unchanged and document the shell wrapper workaround, accepting that cron jobs must encode semantic exit codes manually.

Yes, by source inspection: current main returns normal nonzero exec exits as completed results with output and exitCode, then `isToolResultError` converts completed `exitCode: 1` into error state. I did not run a live cron reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product boundary. The narrowest maintainable fix appears to be changing shared classification so normal exec nonzero exits stay completed, with focused tests for agent, cron, and UI consumers.
