## Label Justifications

- `P1`: The underlying regression can repeatedly resend prior assistant text in active agent and channel workflows, creating an urgent broken-delivery experience for affected users.
- `merge-risk: 🚨 message-delivery`: The changed ownership and terminal-selection logic directly determines whether final replies are current, stale, suppressed, or repeated.

## Summary

The current head appears to resolve the earlier assistant-identity and timeout/yield concerns by keeping transcript-derived state for lifecycle decisions while using a cloned, run-owned completion for final delivery. Keep this PR open because its evidence remains test/CI-only: the message-delivery boundary still needs after-fix proof from a real runtime or production-boundary setup before merge.

## What This Changes

The PR captures each model attempt’s completed assistant event, clears it on compaction retry, and carries it through settlement and terminal reply generation instead of resolving final output from mutable transcript position.

## Best Possible Solution

Keep one immutable completed-assistant snapshot per model attempt, use it exclusively for final output and metadata, retain transcript-derived assistants only for lifecycle classification, and merge only after a redacted production-boundary run demonstrates correct behavior through transcript rewrite plus retry, yield, and timeout outcomes.
