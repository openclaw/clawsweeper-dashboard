## Summary

Keep open: the reported 127/8 gap is plausible, but this patch is not merge-safe because the widened prefix can treat non-loopback hostnames beginning with 127. as local and then pass `allowPrivateNetwork` into the SSRF-guarded provider request path; the external PR also lacks after-fix real behavior proof.

## What This Changes

The PR changes the OpenAI image provider’s QA-only local endpoint check from `http://127.0.0.1:` to any `http://127.` prefix.

## Best Possible Solution

Parse the configured URL and allow only HTTP `localhost` or actual loopback IP-literal hostnames for the QA escape hatch, with regression tests for `127.0.0.2` and a `127.`-prefixed hostname rejection before merge.

## Reproduction Assessment

Yes. Source inspection is enough: the changed `baseUrl.startsWith("http://127.")` predicate matches non-loopback hostnames such as `http://127.example.test`, and that result is passed into the provider HTTP private-network allow path when the QA env var is enabled.

## Solution Assessment

No. The best fix is to parse the URL and validate the hostname as `localhost` or an actual loopback IP literal, then add focused tests for the intended 127/8 expansion and the hostname false-positive case.
