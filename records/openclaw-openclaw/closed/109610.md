## Summary

Keep open: the patch remains useful and appears correct, but merging intentionally makes exact-correlated hook metadata lossy after 1,024 outstanding snapshots, so a maintainer should accept that compatibility tradeoff.

## What This Changes

The PR caps the reply usage-state handoff at 1,024 snapshots, evicts the oldest entries after expiry pruning, and adds capacity regression coverage.

## Best Possible Solution

Retain the TTL and exact-run correlation, add the bounded oldest-entry eviction with its regression coverage, and explicitly accept the overload behavior as part of the hook's best-effort contract.

## Solution Assessment

Yes, subject to maintainer acceptance of the overload contract. A bounded TTL cache with oldest-first eviction is the narrowest maintainable fix; directly carrying metadata would avoid omissions but requires a substantially broader lifecycle refactor.
