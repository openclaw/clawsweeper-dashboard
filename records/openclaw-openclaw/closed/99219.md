## Summary

Keep open: current `main` still routes the iOS auth-step Retry Connection button through the saved last-known connection path instead of the edited manual host/token/password fields, and no linked PR currently owns this exact bug.

## What This Changes

The issue reports that iOS onboarding Authentication-step Retry Connection does not redial using edited gateway connection details, leaving users stuck until they go back and use Connect.

## Best Possible Solution

Fix auth-step Retry Connection to redial from the current manual fields and auth override when manual details are on screen, while preserving saved/discovered retry semantics elsewhere and adding focused regression coverage.

Yes, source inspection gives a high-confidence path: the auth-step button calls `retryLastAttempt()`, which calls `connectLastKnown()` instead of the manual current-field path. I did not run the simulator flow.

## Solution Assessment

## Repair Work Prompt

Fix the iOS onboarding Authentication-step Retry Connection bug reported in https://github.com/openclaw/openclaw/issues/99219. The button currently calls `retryLastAttempt()`, which calls `GatewayConnectionController.connectLastKnown()` and can either return silently with no saved connection or retry stored credentials instead of the current auth-step fields. Make manual/auth-step retries redial using the current `manualHost`, `manualPort`, `manualTLS`, `gatewayToken`, `gatewayPassword`, and pending manual auth override, matching the Connect button semantics. Preserve saved/discovered last-known retry behavior for settings, root banners, automatic retry, and discovered-gateway flows unless the current onboarding screen is explicitly retrying edited manual details. Surface a user-visible status when retry cannot run because no usable manual/current/saved endpoint exists. Add focused regression coverage or a narrow source guard for the manual auth-step retry path. Coordinate with overlapping open iOS onboarding PRs, but do not broaden this into the nearby-discovery, visual refresh, or reverse-proxy auth feature work. Do not edit release changelogs.
