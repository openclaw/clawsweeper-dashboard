## Summary

Current main provides the generic seams needed for these workflows—model-free command cron, per-job cron context in blocking/completion plugin hooks, and scheduler lifecycle observations—so a new core per-job hook schema would duplicate optional trusted-plugin policy and expand an already sensitive config surface.

## What This Changes

Add configurable per-job cron lifecycle hooks for deterministic gating, postprocessing, retries, escalation, shell execution, and webhooks.

## Best Possible Solution

Publish a code plugin through ClawHub that maps job IDs to pre-run policies, uses before_agent_run for model-free blocking, agent_end and cron lifecycle events for post/error processing, and command cron for deterministic scripts; verify manifest metadata, entrypoint, config schema, permissions and trust assumptions, secrets, installation/update docs, example policies, and live smoke proof. ClawSweeper should not open a ClawHub issue or PR, create tracking work, or publish the package for the contributor.
