## Summary

Current media-understanding documentation says the default policy intentionally describes only the first attachment and already supports opting into all images. The central behavior therefore does not appear to need a new core implementation, but I could not establish the required source-history and release provenance for an automated implemented-on-main close.

## What This Changes

The issue asks OpenClaw to automatically generate multimodal descriptions for every image in a multi-image inbound message rather than only the first one.

## System Context

Inbound channel attachments enter the shared media-understanding stage before the agent reply pipeline. That stage optionally converts images into short text descriptions while preserving the original attachments for the reply model.

## Architecture Diagram

flowchart LR

  C --> D{First or all attachments}
  D --> E[Image descriptions]

  B --> G[Original image attachments]
  G --> F

## Best Possible Solution

Document or point the reporter to `tools.media.image.attachments: { mode: "all", maxAttachments: <bounded limit> }`, preserving the cost-conscious default of processing only the first image unless an operator opts in.
