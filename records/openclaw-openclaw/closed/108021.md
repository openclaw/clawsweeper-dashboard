## Summary

Keep this issue open: current main still force-kills every PID listening on the gateway port without verifying OpenClaw ownership, and the specifically linked fix remains an open pull request that should be reviewed and landed before the issue closes.

## What This Changes

Prevent the Windows update restart helper from force-killing non-OpenClaw processes that listen on the configured gateway port.

## Best Possible Solution

Land a fail-closed Windows restart path that force-terminates only positively verified OpenClaw gateway processes, skips and reports foreign or ambiguous listeners, and is proven in a real managed-update scenario.
