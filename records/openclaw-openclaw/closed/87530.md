- **[P1] Filter voice-state packets before account-scoped joins:** `extensions/discord/src/voice/manager.ts:576`
  - body: Adding `group: voiceConnectionGroup` lets two account-scoped @discordjs/voice connections coexist in one guild, but `VoicePlugin.adapters` and `dispatchVoiceGatewayEvent` still pick the adapter by guild and forward every `VOICE_STATE_UPDATE`. @discordjs/voice stores that packet as the connection state and uses its `session_id`/`user_id` to configure networking, so account B can consume account A's state and stay stuck before Ready; carry bot/account identity into the adapter map or filter state updates before `onVoiceStateUpdate`.
  - confidence: 0.9

  - body: This path fires `params.voiceManager.autoJoin()` without awaiting it, then `finally` can call `destroy()` while the join is still blocked in `fetchChannel`/`entersState`. `destroy()` only stops sessions already registered, and the join registers the session after Ready, so shutdown can still leave an in-flight connection until timeout; await the task or make it abortable before destroying the manager.
  - confidence: 0.84
