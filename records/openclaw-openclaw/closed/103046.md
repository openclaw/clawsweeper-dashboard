## Summary

The prior exact-match finding is fixed, but the patch still leaves an availability gap: an incomplete finite oversized frame keeps the session in drain mode until every declared byte arrives, and frames after a fatal header can still be dispatched. Keep this PR open for a simpler immediate-failure repair and changed-path runtime proof.

## What This Changes

The branch adds a 10 MiB LSP response limit, cross-chunk oversized-body draining, fatal session handling, and parser/runtime regression tests.

## Best Possible Solution

Return a typed fatal parse outcome at the first oversized or unsafe header, dispatch only messages completed before that boundary, immediately fail and stop the offending session or process, and remove the persistent cross-chunk drain state.

## Maintainer Decision

## Reproduction Assessment

Yes. Send a safe-integer Content-Length above 10 MiB with only a partial body and stop sending; the drain counter remains positive, later chunks are discarded, and the session is not failed until all declared bytes arrive.

## Solution Assessment

No. Bounding hostile input is the right direction, but waiting to drain a fatal frame recreates indefinite output suppression; immediate failure at the header boundary is narrower and safer.
