## Label Justifications

- `P1`: The reported behavior prevented a normal OpenWebUI multimodal chat workflow from delivering user image input, although current code now fixes that path.
- `impact:message-loss`: The report concerns an image attachment being dropped before it reaches the agent's multimodal input.
- `maturity:stable`: This affects the documented Gateway OpenAI-compatible HTTP endpoint, which is already classified as stable in the supplied issue context.

## Summary

Close as implemented: the current Gateway accepts OpenAI-compatible `image_url` parts from the active user turn, forwards their decoded image data into the agent run, and has regression coverage for text-plus-image and image-only requests. The reported empty-image outcome targets a path fixed before this issue was filed; the present supported behavior is documented for Open WebUI as well.

## What This Changes

The issue requests reliable preservation of OpenWebUI image uploads sent as OpenAI-compatible `/v1/chat/completions` content parts so they reach OpenClaw's agent and image-capable model path.

## System Context

The Gateway's OpenAI-compatible HTTP endpoint converts a client chat-completions request into a normal OpenClaw agent run. It extracts image inputs from the active user message, validates/resolves them under the endpoint image policy, and passes them alongside the text prompt to the agent runtime.
