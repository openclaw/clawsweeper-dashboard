## Summary

This issue duplicates the still-open canonical report on stale OpenAI OAuth `subscription_limit` state: both describe a cached `blockedUntil` continuing to bypass the configured OpenAI model after the account has recovered. Consolidating the additional live evidence under the canonical issue avoids splitting one cooldown-recovery product decision across parallel reports.

## What This Changes

Stop OpenAI OAuth `subscription_limit` cooldown state from forcing fallback models for days after current account status shows the primary route is usable.

## System Context

OpenClaw records OpenAI OAuth profile availability in persisted auth-profile usage state after failures. Model fallback consults that state before attempting the configured model, so an overlong block can route work to another provider without a fresh primary-provider request.
