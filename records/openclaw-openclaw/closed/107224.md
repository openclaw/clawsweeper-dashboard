- `impact:data-loss`: The report describes explicit user-authored plugin allowlist entries being silently removed during upgrade.

- `impact:ux-release-blocker`: Affected users cannot restore their previously configured plugin workflow through the normal update or enable flow and must manually reconstruct configuration.

## Summary

This appears to be a real upgrade regression: current update orchestration preserves dropped channel configuration but has no equivalent protection for user-authored plugin allowlist entries. The exact mutation step still needs a focused current-main reproduction before implementation.

## What This Changes

Preserve user-added `plugins.allow` entries across `openclaw update` so previously trusted installed plugins can still be enabled after upgrading.

## Best Possible Solution

Make update convergence preserve explicit pre-update `plugins.allow` entries unless a named migration intentionally removes them, while retaining the allowlist as an operator-controlled security boundary and covering both successful and failed plugin-update upgrades.
