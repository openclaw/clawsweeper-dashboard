## Summary

Keep this PR open: the refreshed head fixes the prior background-session ownership blocker, but user deletion can still race the new dispatch claim and remove durable ownership while the network send continues.

## What This Changes

The PR adds a Room-backed Android chat outbox for all sends and attachments, canonical-history retirement, connection-gated command replay, pinned routing, preserved migrations, and explicit ambiguous-delivery recovery.

## Best Possible Solution

Make user deletion a queued-or-failed compare-and-set operation that loses once dispatch claims the row, while preserving canonical-history reconciliation for every request that entered the transport.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence concurrency path: render Delete for a queued row, let reconnect flush claim queued-to-sending, then execute the already-captured Delete callback while the claimed send continues.

## Solution Assessment

No, not in its current form. Journal-all admission and canonical-history retirement are the correct maintainable design, but deletion must participate in the same atomic state transition as dispatch so ownership cannot disappear mid-send.
