## Summary

Current main still loads the startup migration module graph before consulting the successful checkpoint, so same-build restarts retain the reported overhead. The issue is actively assigned, carries a protected `maintainer` label, and has open pull request https://github.com/openclaw/openclaw/pull/105099 as its direct, proof-backed candidate fix; it should remain open until that PR merges or is replaced.

## What This Changes

Avoid loading and traversing completed startup migrations on identical Gateway builds while rerunning them for fresh state, rebuilds, version changes, and builds without immutable provenance.

## Best Possible Solution

Land the linked focused fix after exact-head review confirms identical builds skip before migration imports while fresh state, changed build, changed version, and missing build provenance still complete migrations before readiness.
