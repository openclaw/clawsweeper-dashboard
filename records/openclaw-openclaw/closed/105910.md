## Summary

This remains a useful, narrowly scoped fix: the proposed add/edit guards make explicit chat-delivery intent fail visibly instead of being silently discarded for main-session system events. A cron-area owner should confirm the compatibility choice to hard-fail previously accepted commands before merge; likely related people: steipete (high confidence).

## What This Changes

The PR rejects explicit `--channel`, `--to`, `--account`, and `--thread-id` options for main-session system-event cron jobs in both `cron add` and `cron edit`, with regression coverage.

## Best Possible Solution

Adopt one documented cron-delivery invariant: reject explicit chat-delivery targeting whenever the resulting job is main-session or otherwise cannot support chat delivery, while retaining webhook delivery and implicit defaults.
