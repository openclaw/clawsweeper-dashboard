## Label Justifications

- `P2`: The gap prevents exact delivery attestation for external ingress controllers but does not break OpenClaw's durable Telegram processing.
- `impact:other`: Host controllers can overstate successful delivery because ordinary HTTP success is indistinguishable from OpenClaw's durable acceptance boundary.

## Summary

Current main confirms the response ambiguity, and this protected maintainer item should remain open for an explicit public HTTP-contract decision and a narrow Telegram-owned implementation.

## What This Changes

Expose a stable machine-readable marker on Telegram webhook responses emitted after durable update acceptance, including durable duplicates.

## Best Possible Solution

Define one documented Telegram-owned response header for durable acceptance, set it after successful new or duplicate enqueue, and assert its absence on health, route misses, authentication failures, rate limits, body errors, and enqueue failures.
