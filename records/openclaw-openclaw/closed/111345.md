## Label Justifications

- `P1`: The patch can alter cadence, retry/backoff, and one-shot deletion for existing scheduled jobs that fail to deliver output.
- `merge-risk: 🚨 compatibility`: Omitted `bestEffort` is already persisted by default delivery creation and ordinary CLI usage, so the patch changes upgrade behavior for existing jobs.
- `merge-risk: 🚨 message-delivery`: A failed announce can stop triggering retry/backoff and can allow a one-shot job to delete even though its output was not delivered.

## Summary

Keep this PR open for maintainer review: separating execution and delivery outcomes is a sound direction, but the patch silently changes omitted `bestEffort` from the established strict behavior to lenient behavior for existing persisted announce jobs and ordinary CLI-created jobs.

## What This Changes

The branch changes command-cron announce failures so a successful command retains `status: ok` and records the send failure as delivery status unless `delivery.bestEffort` is explicitly `false`.

## Best Possible Solution

Keep omission strict for already persisted and explicit announce configurations, then introduce lenient default delivery only through an explicit stored value or a maintainer-approved, tested migration and documented upgrade path.
