## Summary

Keep this PR open for repair. The new body-less wrapper still obtains the entire payload through `response.text()` before it can apply the shared byte limit, and the Firecrawl cleanup only cancels the original response when JSON parsing produced a payload; the unrelated release-checklist declaration removal also regresses its type contract.

## What This Changes

The branch adds response-body cleanup in Ollama and Firecrawl, rewrites shared HTTP error-body fallback handling, extends its tests, and removes two `validateTrustedToolingPin` declarations from the release-candidate checklist contract.

## Best Possible Solution

Use a genuinely bounded source for error snippets; when a response exposes no bounded readable body, return an empty/truncated snippet rather than materializing `response.text()`, cancel the Firecrawl original body in an unconditional cleanup path, and retain the release-checklist declarations.
