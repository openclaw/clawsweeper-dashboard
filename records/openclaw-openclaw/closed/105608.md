## Summary

Current main still accepts edits and dismissal while worktree creation is pending, then resets that accepted UI state when the earlier request completes. No duplicate or fixing PR exists, and the protected `maintainer` label requires explicit maintainer handling.

## What This Changes

Prevent the Control UI worktree-create form from accepting edits or dismissal while the create request is pending.

## Best Possible Solution

Disable repository, name, base-branch, and form-toggle interactions while creation is pending, then add focused DOM and Playwright coverage proving the submitted values remain the only accepted state until settlement.

Yes. Locking every state-changing form control during the existing create operation is the narrowest maintainable fix; honoring later edits would conflict with an already-submitted Gateway request.
