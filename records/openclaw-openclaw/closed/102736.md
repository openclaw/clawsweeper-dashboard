## Summary

Close: current main already fixes the reported session rollover by skipping the transcript-mtime guard for successful `done` main-session rows. The same root cause was tracked in https://github.com/openclaw/openclaw/issues/99964 and fixed by merged https://github.com/openclaw/openclaw/pull/99985; no release tag in this checkout contains the fix yet.

## What This Changes

The issue reports successful sessions rolling over when transcript file mtime becomes newer than the session store `updatedAt`, causing conversation context loss.

## Best Possible Solution

Keep the current shared lifecycle-helper behavior from the merged fix: successful `done` main sessions reuse their session id, while killed, timeout, and endedAt-only recovery cases remain guarded until an actual release ships it.

## Maintainer Decision

Yes, the original failure has a high-confidence source-level reproduction: a successful `done` main row with transcript mtime newer than `updatedAt` previously reached the guard. Current main no longer reproduces that failure because the shared helper returns before the mtime check for `done` rows and the Gateway test now expects reuse.

## Solution Assessment

Yes. The merged fix is the narrowest maintainable solution because it changes the shared lifecycle helper used by Gateway, CLI, and auto-reply while preserving the guard for interrupted or unsafe terminal states.
