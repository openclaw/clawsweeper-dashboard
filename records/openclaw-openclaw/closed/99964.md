## Label Justifications

- `P1`: Successful main-agent sessions can unexpectedly roll into new session ids and reset archives in the latest release, breaking active session continuity.
- `impact:session-state`: The issue affects whether the main session preserves its session id, transcript continuity, and CLI/session metadata after a successful run.
- `maturity:stable`: The affected Gateway agent admission path maps to `gateway-runtime`, scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main still routes successful `status: "done"` main sessions through the transcript-mtime freshness guard, and Gateway, CLI, and auto-reply admission can still treat that as a reason to roll the session. Three open PRs are candidate fixes, so the issue should stay open until one canonical fix lands.

## What This Changes

The issue reports successful main-agent sessions being archived as `.jsonl.reset.*` and assigned a new session id when transcript mtime is newer than `sessions.json.updatedAt`.

## Best Possible Solution

Land one canonical fix that keeps successful `done` main sessions reusable while preserving rollover/recovery behavior for missing transcripts, endedAt-only rows, and interrupted terminal states, then let that merged PR close this issue.

## Reproduction Assessment

Yes at source level: create a main-session row with `status: "done"`, an older `updatedAt`, and a transcript file whose mtime is newer; current source routes that row through the guard and blocks reuse. I did not run a writing regression script because this review is read-only.

## Solution Assessment

Yes, the best fix boundary is the shared session lifecycle guard used by Gateway, CLI, and auto-reply, with tests proving `done` rows reuse while unsafe terminal rows still rotate. The issue itself should remain open until one linked fixing PR merges.
