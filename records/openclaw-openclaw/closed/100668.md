Close: current main and the shipped v2026.6.11 tag already accept nullable cron update clears for `payload.model` and `payload.fallbacks`, delete the stored overrides, and then let the existing cron inheritance policy apply.

## What This Changes

The issue asks for cron job updates to accept `payload.model: null` and `payload.fallbacks: null` so existing jobs can clear overrides and inherit agent/global defaults again.

## Best Possible Solution

Keep the shipped nullable update clear contract: `null` clears stored cron overrides, omitted fields preserve them, and explicit arrays including `[]` remain explicit fallback policy.
