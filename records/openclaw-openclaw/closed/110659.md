## Label Justifications

- `P1`: The remaining path can silently bind a retained configuration row to another row’s credential during a normal Control UI save.
- `merge-risk: 🚨 compatibility`: The PR changes restoration behavior for saved configuration arrays while leaving an undocumented ID-reuse compatibility case unresolved.
- `merge-risk: 🚨 auth-provider`: Redacted values include provider and agent credentials, and ID reuse can associate one row’s secret with a different configuration entry.

## Summary

Keep this PR open for a maintainer decision: it fixes the demonstrated delete/reorder corruption path, but it deliberately leaves ID reuse able to restore a removed row’s redacted credential into a different row. The supplied isolated-Gateway transcript is strong real-behavior proof for the covered cases; the unresolved reuse contract remains a P1 merge blocker.

## What This Changes

The branch changes redacted config-array restoration from positional matching to client-visible unique-ID matching and adds extensive tests for reordered, deleted, inserted, and ambiguous rows.

## Best Possible Solution

Define the row-continuity contract before merge, then make the save payload or restoration protocol distinguish retained rows from reused IDs and add a focused end-to-end regression for that decision.
