## Label Justifications

- `P2`: The report describes a bounded but real webchat orchestration deadlock that stalls the parent session until manual user input.
- `impact:session-state`: The parent session can remain in an incorrect waiting state after all spawned subagent state has already settled.

## Summary

Current source does not show a runtime backstop for the reported depth-0 webchat case; the merged related fix covers yielded subagent-run parents, while this report is about a top-level requester that can still go quiet after a child completion turn ends with NO_REPLY.

## What This Changes

The issue requests a runtime backstop so a webchat orchestrator that used `sessions_spawn` plus `sessions_yield` is re-prompted or given global drain context after all spawned subagents complete, even if an intermediate completion turn emits `NO_REPLY`.

## Best Possible Solution

Add a narrow top-level requester-session drain backstop or completion-context enhancement so a session that yielded for spawned work gets one final steer/global-state nudge once its direct spawned runs have drained, without changing ordinary yielded-run pause semantics.

## Reproduction Assessment

Yes, source-reproducible with medium confidence. The report provides a concrete timeline, and current source lacks top-level requester pause/drain registry comparable to the yielded-subagent `wakeOnDescendantSettle` path.

## Solution Assessment

No, the already-merged adjacent fix is not sufficient for this exact issue. The best fix should stay in the subagent/session runtime boundary and handle depth-0 requester drain state directly rather than relying on model memory or a prompt-only workaround.
