## What This Changes

The PR adds a shared FIFO admission boundary so scheduled, direct manual, queued manual, and on-exit cron executions collectively honor `cron.maxConcurrentRuns`, with queued reservations and eligibility revalidation.

## Best Possible Solution

Keep the single service-owned admission boundary, but land it only after rebasing onto current main and demonstrating a real mixed-trigger run where the configured ceiling is never exceeded and queued reservations are released safely on disable, removal, stop, failure, and forced-disabled execution.
