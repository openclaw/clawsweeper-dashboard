## Summary

Current main has the reported cross-agent isolation defect, and this protected issue should remain open until its direct fixing PR is reviewed and either merged or rejected.

## What This Changes

Ensure each commitment extraction batch, embedded extractor run, persistence operation, and failure policy contains work from exactly one agent.

## Best Possible Solution

Land the focused linked fix after confirming every extraction batch is agent-homogeneous and a terminal failure for one agent still schedules and drains unaffected agents' queued work.

Yes at source level: enqueue completed turns for two agents within one debounce window, drain once, and inspect that current main removes both into one batch while selecting execution and persistence context from the first item. I did not execute the regression test during this read-only review.

## Solution Assessment

Yes. Selecting up to the configured limit from only the first queued agent is the narrowest maintainable repair because it preserves the existing queue, ordering, and configuration surfaces while aligning every context-sensitive operation with one agent.
