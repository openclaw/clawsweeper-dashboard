## Summary

Keep open: current main still has the env-value surrogate split, but this PR should not merge as-is because it duplicates the canonical truncation helper and changes the existing 160 UTF-16-unit cap into a 160-code-point cap.

## What This Changes

The PR changes env option log formatting to truncate long env values with `Array.from(...).slice(...).join("")` instead of raw `slice(0, 160)`.

## Best Possible Solution

Use `truncateUtf16Safe(singleLine, 160)` in `formatEnvValue`, add a focused `logAcceptedEnvOption` regression for an emoji at the 160-code-unit boundary, and include redacted real env-log proof before merge.

Yes, source-level: a long env value such as `"a".repeat(159) + "📊tail"` reaches `singleLine.slice(0, 160)` with the high surrogate at the cut boundary on current main.

## Solution Assessment

No. The inline `Array.from` approach fixes well-formedness but is not the best fix because the existing `truncateUtf16Safe` helper preserves the current UTF-16 cap and matches merged sibling fixes.
