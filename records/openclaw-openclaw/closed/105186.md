## Label Justifications

- `P2`: Tab stripping can degrade code and tabular prompt fidelity, but newlines remain intact and core runtime operation is not blocked.

## Summary

Keep this open for maintainer review: tab removal is deterministic, but the named wrapper already preserves normalized newlines, and changing the control-character policy requires an explicit prompt-security decision.

## What This Changes

Allow tagged untrusted prompt-data blocks to retain tab-sensitive formatting while preserving strict prompt-injection defenses for inline literals.

## Best Possible Solution

Define a separate reviewed sanitizer for escaped tagged data that preserves normalized LF and either approved raw tabs or a fidelity-preserving tab representation, while leaving the shared inline-literal sanitizer unchanged.

## Maintainer Decision

Required: true

Question: Should escaped tagged prompt-data blocks preserve raw horizontal tabs, render tabs as a safe visible representation, or remain intentionally lossy?

Rationale: Current source and tests define control-character stripping as prompt-injection hardening, so altering the allowed whitespace set requires explicit ownership of the security tradeoff.

Likely owner: steipete

Owner confidence: high

Options:

- **Separate block sanitizer (recommended):** Preserve normalized LF and reviewed horizontal whitespace only inside escaped tagged blocks while keeping inline literals strict.
- **Escape tabs visibly:** Represent tabs with a safe visible sequence inside tagged blocks instead of retaining raw control characters.
- **Keep lossy behavior:** Retain tab stripping and document that fidelity-sensitive callers must encode or normalize their input first.

## Reproduction Assessment

Yes for tab removal: current source deterministically strips tabs from each wrapped line. No for the reported newline removal, because the wrapper normalizes CRLF or CR and rejoins the lines using LF.

## Solution Assessment

No, relaxing `sanitizeForPromptLiteral` globally is not the best solution because inline callers rely on its strict contract; a dedicated tagged-data policy is narrower and safer.
