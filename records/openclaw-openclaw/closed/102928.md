## Summary

Keep open: current main and v2026.6.11 still override `init.signal` inside `fetchWithTimeout`, and https://github.com/openclaw/openclaw/pull/102951 is the open candidate fix to review rather than closing this issue.

## What This Changes

The issue requests that `fetchWithTimeout` preserve a caller-provided `RequestInit.signal` while still enforcing its timeout.

## Best Possible Solution

Fix `fetchWithTimeout` to compose `init.signal` through the existing timeout helper, and add regression coverage for parent abort before and while fetch is pending.

## Maintainer Decision

Required: false

## Solution Assessment

Yes, the narrow maintainable solution is to pass `init.signal` into `buildTimeoutAbortSignal` and keep the existing timeout cleanup behavior. The open candidate PR points at the right code line, but it still needs regression coverage and normal review.
