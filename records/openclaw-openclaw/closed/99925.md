## Summary

Keep open: current main still defaults session tools to tree-scoped visibility and does not provide automatic WebChat new-session recall of the immediately prior same-channel session. Existing WebChat archive/history and broader memory-continuity trackers overlap, but they do not fully own this current-session-to-parent or prior-session visibility report.

## What This Changes

Request WebChat new sessions to automatically see or retrieve recent same-user/same-channel conversation context instead of starting blind under tree-scoped session visibility.

## Best Possible Solution

Define a privacy-aware WebChat/session continuity contract that can recover recent same-user or same-channel context through existing session-history/session-memory primitives without silently broadening unrelated sessions.

## Reproduction Assessment

Yes at source level for the visibility restriction: current main defaults session tools to tree, direct history checks only the current session plus spawned children, and docs require explicit agent/all widening for unrelated same-agent sessions. I did not run a live WebChat click-plus or timeout scenario.

## Solution Assessment

No as a direct silent visibility widening: that would be privacy-sensitive and could leak unrelated sessions. The better path is a maintainer-approved WebChat parent/family/prior-session recall policy with bounded history and clear diagnostics.
