## Summary

Keep open: current main and the latest release still resolve the built-in English audio prompt and pass it with explicit audio language hints into Groq's OpenAI-compatible transcription request, matching the reported source-level failure path.

## What This Changes

Do not pass the built-in English audio transcription prompt to providers when an explicit non-English language hint is configured and no custom prompt was supplied.

## Best Possible Solution

Change shared media-understanding request construction so provider-backed audio transcription omits the implicit English default when a language hint is explicit and no prompt was configured, while preserving explicit prompts and regression coverage.

## Reproduction Assessment

Yes, at source level: current main deterministically resolves the built-in audio prompt and forwards it with the language hint into provider requests. The exact Groq output bias still needs live audio confirmation beyond the reporter's repeated audit.

## Solution Assessment

Yes, the best fix is in shared media-understanding prompt/request resolution rather than Groq-only special casing, because the same OpenAI-compatible audio helper and language/prompt contract can affect multiple providers.
