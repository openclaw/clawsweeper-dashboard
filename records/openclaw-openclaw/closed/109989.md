## Summary

Keep open for a maintainer merge-risk decision. The patch is correct, focused, and supported by real child-process proof, but it intentionally changes a damaged post-core update handoff from silent continuation to an update-resume abort, so the availability-versus-state-integrity policy should be explicitly owned before merge.

## What This Changes

The PR makes the post-core plugin install-record handoff reader ignore only omitted or missing files, reject malformed or otherwise unreadable files with path-labelled errors, and adds filesystem-backed regression coverage.

## Best Possible Solution

Use the fail-closed reader as the canonical integrity-preserving behavior, with explicit maintainer acceptance that a damaged handoff stops resume and with an actionable rerun or recovery path in the surfaced error if maintainers consider the current path label insufficient.

Question: Should post-core update resume abort when the parent plugin install-record handoff is malformed or unreadable, rather than continuing without that recovery snapshot?

Rationale: Both behaviors have user impact: continuing can silently discard install-record recovery context, while aborting can leave an update between core installation and plugin convergence or gateway restart. Repository policy requires maintainers to own this fallback and availability tradeoff.

Options:

- **Accept fail-closed resume (recommended):** Land the patch so damaged handoff state stops update resume and operators retry or repair instead of continuing with incomplete recovery context.
- **Preserve continuation policy:** Keep continuation possible only with an explicit warning and a maintainer-defined safe reconstruction path for the missing install-record snapshot.

## Reproduction Assessment

Yes. Current main's catch-all reader returns undefined for malformed JSON, and the PR provides a real post-core child-process run showing the same malformed handoff is rejected after the fix.

## Solution Assessment

Yes, technically: distinguishing optional absence from corrupt or unreadable recovery state is the narrowest integrity-preserving repair. Final acceptance still requires the maintainer to confirm that aborting resume is the intended availability policy.
