## Summary

Keep this PR open, but it is not merge-ready: the guard is acquired after async media/context preparation, so a later same-user event can acquire the guard first and cause the earlier event to be skipped.

## What This Changes

The branch adds a process-local LINE per-user in-flight guard, wires it into `createLineBot`, sends a busy reply for rapid same-user events, and adds handler tests.

## Best Possible Solution

Acquire the LINE per-user guard before async per-message preparation and add ordering regression coverage; then merge only if maintainers accept busy-skip delivery semantics, otherwise use queueing or active-turn feedback that preserves follow-up messages.
