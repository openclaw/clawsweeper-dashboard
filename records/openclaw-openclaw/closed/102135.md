## Label Justifications

- `P2`: This is a bounded ACP/media dispatch bug that can fail image turns for text-only ACP-backed models without making the whole runtime unusable.
- `impact:message-loss`: The affected image turn can fail before the ACP model processes the user message because unsupported raw image attachments are still sent.
- `impact:auth-provider`: The failure depends on model capability routing between a text-only primary ACP model and a configured image-understanding model.
- `maturity:stable`: The issue affects the Gateway runtime surface, which qa/maturity-scores.yaml lists as M4 Stable.

## Summary

Keep open: current main and the latest release still forward raw ACP image attachments after media understanding, and the open linked PR is only a candidate fix until it lands or is closed.

## What This Changes

The issue reports that ACP dispatch sends raw image attachments to a text-only ACP model even after media understanding has already converted the image into text.

## Best Possible Solution

Land or reject https://github.com/openclaw/openclaw/pull/102145; the intended fix should drop only raw current-turn images with successful image.description indexes while preserving inline, extracted, recent-history, and undescribed images.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current main shows the source path: ACP dispatch applies media understanding, resolves the same current image as an ACP attachment, and passes attachments into runTurn without described-image filtering.

## Solution Assessment

Yes. The maintainable fix is to mirror the non-ACP described-image filter instead of clearing every attachment whenever any media understanding output exists.
