## Summary

The previous blocker remains on the unchanged reviewed head: empty-content recovery is implemented only in the streaming delivery funnel, while the durable outbound funnel retains different failure and fallback behavior. The PR should remain open for the shared-predicate and durable-caller repair.

## What This Changes

The branch makes render-to-empty Telegram streaming text sends no-ops and updates reply, transcript, hook, pin, prompt-context, and voice-fallback accounting to count only delivered messages.

## Best Possible Solution

Move empty-content classification into the shared Telegram rich/plain fallback module, apply the no-op recovery to both durable and streaming text sends, and add parity tests that preserve usable fallback, parse-error, reply metadata, receipt, and accounting behavior.
