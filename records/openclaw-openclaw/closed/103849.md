## Summary

Current main still reproduces the reported metadata-loss chain: the managed Anthropic client throws a plain error, shared transport projection carries no retry timing, and AgentSession uses fixed exponential delays. No newer issue, PR, or current-main change owns the same narrow behavior, so this remains an actionable bug.

## Best Possible Solution

Add provider-generic structured retry metadata at the shared transport/AssistantMessage boundary, populate it from the real Anthropic response, and let AgentSession use a validated bounded server delay as a lower bound while retaining exponential fallback.
