## Summary

Keep open. Signed macOS build 2026.6.10 eliminated the reported TCC request storm, but current main still performs recurring full permission snapshots, creates fresh `CLLocationManager` instances, and executes the Automation authorization probe. The three linked macOS cache PRs closed unmerged, and their location-only approach would not address the broader high-frequency permission work that the reporter still measured.

## What This Changes

Stop the macOS node loop from repeatedly rebuilding and executing TCC-sensitive permission probes while keeping permission state accurate.

## Best Possible Solution

Make permission state lifecycle-owned: update callback-capable framework status when authorization changes, cache or rate-limit non-callback probes such as Automation, and publish a new node permission snapshot only when state changes or a connection handshake requires it.

## Solution Assessment

No. Reusing only `CLLocationManager` is a partial fix because the recurring full snapshot still executes other expensive permission probes; the narrow maintainable solution moves cadence, caching, and invalidation to the permission lifecycle and node-handshake owner boundary.
