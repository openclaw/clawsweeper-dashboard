## Summary

Keep open: current main has a doctor-owned JSON-to-SQLite auth import, but runtime auth reads only the per-agent SQLite store and the reported 2026.6.11 upgrade path can still leave legacy JSON credentials present but ineffective without a clear startup recovery signal.

## What This Changes

The issue asks OpenClaw to migrate or loudly warn about stranded legacy JSON auth profiles after the SQLite auth-store upgrade and to detect fallback chains that become entirely dead.

## Best Possible Solution

Keep SQLite as the canonical runtime store, but add an upgrade/startup Doctor/Fix path that detects importable legacy auth JSON by profile name and points users to the existing import, then scope fallback validation to configured defaults whose refs resolve to no usable provider/model.

## Reproduction Assessment

Yes, source-reproducible with medium confidence: current runtime reads SQLite while the existing legacy JSON import is doctor-owned, matching the reported stranded JSON shape. I did not perform the live Docker upgrade reproduction in this read-only review.

## Solution Assessment

Partly: using the existing doctor import plus a visible startup/post-upgrade warning is the best auth-store fix shape. The fallback-chain validation ask should be scoped by maintainers before implementation so it does not become a broad new startup policy surface.
