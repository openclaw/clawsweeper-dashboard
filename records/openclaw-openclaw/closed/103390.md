## Summary

This is a valid and well-proven fix direction, but the exact head still routes incomplete provisioning checkouts through normal snapshot restoration: an operator can remove a crashed provisioning row, then same-name creation restores that incomplete snapshot as ready without rerunning the setup script. The previously reported blocker therefore remains and should be repaired before merge.

## What This Changes

The PR adds crash-orphan adoption, atomic managed-worktree path claims, persisted provisioning readiness with lease heartbeats and stale-claim cleanup, plus CLI/protocol exposure and migration coverage.

## Best Possible Solution

Make explicit removal of a provisioning row perform holder-safe cleanup of its worktree, branch, and registry row without creating a snapshot; keep snapshot/restore restricted to ready rows and prove that same-name recreation completes include-copy and setup before returning ready.
