## Summary

Current `main` already suppresses default user-visible `exec`/`bash` failure warnings, including the WebChat path that uses the shared embedded-run payload builder; diagnostics remain available through verbose mode. The requested new WebChat-specific config is therefore unnecessary.

## What This Changes

The issue requests suppressing WebChat tool-failure notifications so recoverable `exec` failures do not interrupt an agent’s response flow.

## Best Possible Solution

Keep the shared default suppression and use the existing verbose controls only when an operator wants tool-failure diagnostics surfaced in chat.

## Maintainer Decision

## Solution Assessment

Yes — the existing shared runner-level verbose gate is narrower and more maintainable than adding a WebChat-only config key or a per-exec suppression parameter.
