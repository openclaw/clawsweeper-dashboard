## Summary

Keep open. Current main does not give a safe close: a correctly selected DeepSeek provider should not be claimed by Codex, but current source still has a plausible persisted selected-model path where an OpenAI session becomes OpenAI Codex once the Codex harness is enabled.

## What This Changes

The issue reports that enabling the Codex plugin changes ordinary chat runtime/model selection away from the configured DeepSeek primary and into OpenAI Codex/gpt-5.4-nano.

## Best Possible Solution

Confirm whether plugin hot reload or persisted session state promotes openai/gpt-5.4-nano, then fix selected/runtime/display model-state resolution so enabling Codex never overrides a non-OpenAI primary unless the user explicitly selects OpenAI.

No high-confidence full current-main reproduction was run.
