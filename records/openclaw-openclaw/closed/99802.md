## Summary

Keep open: this targets a real supervisor availability bug, but the patch installs stdout/stderr error handlers only when output callbacks are later registered, leaving a stream-error window before subscription; contributor real behavior proof is also mock-only.

## What This Changes

The PR adds no-op `error` listeners for child process stdout and stderr inside the `createChildAdapter` output callback setup.

## Best Possible Solution

Attach stdout/stderr stream error handlers once during child adapter initialization, keep existing data/end/close behavior, add focused regression coverage for pre-subscription stream errors, and include redacted real runtime proof.

## Reproduction Assessment

No live high-confidence reproduction was run in this read-only review. Source inspection makes the failure path credible: current main lacks stdout/stderr stream error handlers, and the PR does not attach them until after adapter creation and subscription.

## Solution Assessment

No. The no-op mitigation is plausible, but the best fix is to attach it once when the child adapter takes ownership of stdout/stderr rather than behind per-listener callbacks.
