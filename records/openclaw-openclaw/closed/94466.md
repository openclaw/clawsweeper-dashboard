## Summary

Keep open: current main still emits Gateway-managed image `url`/`openUrl` fields that the browser Control UI consumes, but the native macOS SwiftUI chat model and renderer do not carry or act on those fields. The merged macOS WKWebView file-picker PR is adjacent and does not implement native WebChat image Open/Download.

## What This Changes

The issue asks OpenClaw to restore native macOS WebChat Open/Download support for images delivered through Gateway-managed `MEDIA:` URLs while browser Control UI already works.

## Best Possible Solution

Implement native managed-image support in shared OpenClawChatUI and the macOS transport boundary with authenticated fetch, Open in Browser, and Download handling plus live macOS proof.

- **Gateway-Issued Native Media Tickets:** Add a scoped media URL contract that native clients can open directly without assuming browser-only auth behavior.
- **Defer Native Actions:** Keep browser Control UI as the supported workaround and leave native WebChat without managed-image Open/Download until a broader media contract is designed.
