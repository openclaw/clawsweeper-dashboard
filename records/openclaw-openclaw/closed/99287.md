## Summary

Keep open: the patch is useful and points in the right direction, but it does not yet cover the real runtime stale-notification drop path because `run-attempt` filters same-thread stale notifications before the new projector warning can run.

## What This Changes

The PR changes the Codex app-server projector to fail unknown item statuses as errors and add one-per-correlation warnings for ignored or unknown notifications, with focused projector tests.

## Best Possible Solution

Keep the fail-closed status mapping and warning-once pattern, but add the inactive-turn diagnostic at the actual `run-attempt` drop point with regression coverage that exercises the enqueue path.

## Reproduction Assessment

Yes: current main is source-reproducible because an unrecognized item `status` reaches `itemStatus` and returns `completed`, while unknown current-turn methods break silently. The remaining PR defect is also source-reproducible: the runtime enqueue path drops same-thread stale notifications before the projector warning can fire.

## Solution Assessment

No: the fail-closed mapping is the right fix shape, but the inactive-turn diagnostic is currently in the wrong layer for normal runtime delivery. The narrower maintainable solution is to warn at the `run-attempt` filter that actually drops those notifications.
