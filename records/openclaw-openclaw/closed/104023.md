## Label Justifications

- `P1`: The current layout breaks common narrow-window and split-pane chat workflows by hiding workspace access or crushing and clipping active content.
- `impact:ux-friction`: Users must resize, collapse panels, or avoid narrow panes to access workspace files and readable chat content.

## Summary

Current main still bases pane-owned chat panels on global viewport breakpoints, while the existing bottom dock is only a user-selected workspace mode. This remains a valid, focused Control UI bug, but the protected `maintainer` label requires human routing.

## What This Changes

Make the chat workspace rail and detail panel adapt automatically to each pane’s available width without hiding workspace access.

## Best Possible Solution

Measure each `openclaw-chat-pane` once, derive a closed pane-layout mode, automatically bottom-dock the workspace rail and stack the detail panel below the thread at narrow widths, and add Chromium/WebKit regression coverage for access, overflow, and resizing.

Yes in direction. Pane-local measurement owned by `openclaw-chat-pane` is the narrowest maintainable fix, provided it drives one canonical layout mode and reuses the existing bottom-dock styling instead of adding more viewport rules.
