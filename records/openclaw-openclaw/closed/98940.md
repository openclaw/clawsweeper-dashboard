Keep open: current head addresses the earlier blank CLI output and removes the unrelated SDK budget bump, but external contributor proof is still insufficient for the current-head pre-reject and CLI behavior, and the omitted-body JSON/API semantics need maintainer acceptance before merge.

## What This Changes

The PR changes the browser plugin responsebody path from full Playwright text decoding to content-length pre-reject plus bounded Buffer decoding, with CLI output for omitted oversized bodies and added tests.

## Best Possible Solution

Land the mitigation only after current-head real browser or terminal proof covers known-large, chunked/unknown-length, small, and CLI notice behavior, and maintainers explicitly accept or adjust the omitted-body API contract.

## Reproduction Assessment

Yes, at source level. Current main calls Playwright response.text() before trimming, and Playwright 1.60.0 text() delegates to body() and converts the full Buffer to a string; I did not run a live OOM reproduction in this read-only review.

## Solution Assessment

Mostly yes as a mitigation, but not as a complete OOM fix. The body()+subarray path is a maintainable low-risk improvement, while the content-length empty-body pre-reject needs explicit compatibility acceptance and real proof before merge.
