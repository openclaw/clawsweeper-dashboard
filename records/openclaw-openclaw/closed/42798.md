## Summary

Keep open: current main and v2026.6.11 still lack a same-binary retry/backoff for the post-Serve `tailscale status --json` read, and the remaining work is already paired with the open candidate fix at https://github.com/openclaw/openclaw/pull/91553.

## What This Changes

The issue reports a Gateway Tailscale Serve startup race where `tailscale status --json` can fail transiently after `tailscale serve --bg --yes`, producing a confusing verbose error even though the gateway continues.

## Best Possible Solution

Resolve this through https://github.com/openclaw/openclaw/pull/91553 or a narrow replacement that retries the existing status JSON read, avoids adding `gateway.tailscale.binaryPath`, suppresses non-final retry noise, and preserves quick fallback for missing binaries.
