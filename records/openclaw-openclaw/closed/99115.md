## Summary

The PR’s shared predicate is a sensible refactor, but persisting its implicit announce default in the direct-service path changes a job’s stored delivery state without fixing a missing runtime delivery path. That explicit state can then survive a target/payload transition and fail validation where the current implicit default would not, so this needs a narrow repair before merge.

## What This Changes

The branch adds a shared cron delivery-default predicate, applies it to normalization, direct service creation, and runtime delivery planning, and expands cron delivery tests.

## Best Possible Solution

Keep delivery implicit for direct-service `current` and `session:*` jobs, retain a shared predicate only where it describes runtime/default behavior, and add a regression test for changing an implicitly delivered job into a valid main/system-event job without an explicit delivery patch.

## Solution Assessment

No. Runtime delivery planning already supplies announce for omitted delivery on the affected targets, so persisting that implicit state is not the narrowest fix and introduces an update-compatibility edge.
