## Summary

Keep open: current main and the latest release still store every resolved usage-template file path in an unbounded module-level cache, and the same-author linked pull request is still open rather than a merged fix.

## What This Changes

The issue reports that the usage-bar template file cache stores each configured template path with a live `fs.watch` watcher and never evicts runtime entries.

## Best Possible Solution

Land a corrected bounded-cache fix in the usage-template loader, with watcher closure on eviction and focused regression coverage, then close this issue from the merged implementation.

## Reproduction Assessment

Yes by source inspection: each distinct valid template path can allocate an `fs.watch` watcher and is stored in `fileCache` with no size cap or runtime eviction path. I did not run a live many-template watcher exhaustion repro in this read-only review.

## Solution Assessment

Yes on direction: the fix belongs in `src/auto-reply/usage-bar/template.ts` by bounding the cache and closing evicted watchers. The currently linked pull request still needs review or repair before it should close the issue.
