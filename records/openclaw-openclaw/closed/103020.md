## Summary

This PR remains necessary because current main still has no response-header deadline for Telegram media downloads. The current head is a well-proven, mergeable implementation with no discrete correctness finding; maintainer review should focus on the intentional retry-ownership change and exact merged-head validation rather than the previous, now-obsolete conflict concern.

## What This Changes

The PR adds a separate Telegram media response-header deadline, propagates lifecycle abort signals through guarded fetches and body reads, returns cycle-aborted durable updates to the ingress queue without consuming retry budget, and adds restart, replay, shutdown, and fallback regression coverage.

## Best Possible Solution

Land one current-main-integrated implementation that keeps the header-only deadline and end-to-end cancellation, preserves durable replay without consuming retry budget, retains classic polling's best-effort partial delivery, and has one explicit retry owner for each ingress mode.
