## Summary

Keep open. Current main and the latest release still produce `toolSummary.failures` from a boolean last-error slot, so the reported aggregate undercount is real and narrow enough for a focused fix PR rather than cleanup closure.

## What This Changes

The issue reports that the existing numeric `toolSummary.failures` aggregate is capped at 0 or 1 because it is derived from a boolean last-tool-error state instead of counting failed tool calls.

## Best Possible Solution

Preserve the existing `failures` field and make it a true per-attempt count using the same tool-result error classification that feeds per-call trajectory status, with regression coverage for multiple failed calls in one turn.
