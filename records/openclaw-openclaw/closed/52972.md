## Summary

Keep open: current main and v2026.6.11 still count only structured `cron` tool adds as `successfulCronAdds`, so a successful shell-driven `openclaw cron add --at ...` can still leave the reply guard with a zero counter and append the contradictory note.

## What This Changes

The issue reports a false unscheduled-reminder note after an assistant successfully schedules a reminder through `openclaw cron add --at`.

## Best Possible Solution

Land a narrow producer-side telemetry fix that counts successful shell-driven cron adds before the reply guard runs, with negative coverage for failed, unrelated, and spoofed commands instead of hiding the note in Telegram delivery.
