## Summary

Live GitHub merged this PR after the review snapshot, so there is no conservative cleanup-close action to take here. As a patch review, the submitted fix is still not correct: the final retry-limit age gate can leave deterministic poison rows blocking later Telegram updates in the same lane for up to 24 hours.

## What This Changes

The PR modifies Telegram isolated ingress spool handling to add generalized retry backoff/dead-lettering, retryable store-read requeueing, completed-update tombstones, and regression tests.

## Best Possible Solution

Keep the tombstone and replay requeue direction, but replace the blanket 24-hour age gate with error-aware transient-outage handling so poison rows stop blocking the lane once the retry budget is spent.

## Reproduction Assessment

Yes, from source inspection. Current main has no generic retry cap for retryable spooled failures, and the merged patch keeps max-attempt rows pending until they are 24 hours old, while the drain still blocks same-lane updates behind retry-delayed rows.

## Solution Assessment

No. The tombstone/requeue direction is right, but the blanket age gate is not the best fix because it trades the infinite poison-row stall for a day-long stall; the safer shape separates transient outage retries from deterministic poison-row dead-lettering.
