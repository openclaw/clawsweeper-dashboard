## Summary

Keep open, but narrow the scope: current main already supports aliased allowlisted models, user and agent session-scoped switching, Telegram selection with active-state feedback, and persistent explicit pins; the author’s clarified multi-model onboarding goal and the broader automatic-routing/profile policy remain unimplemented and require a configuration-boundary decision.

## What This Changes

Add onboarding for multiple named models plus user- or agent-controlled, task-aware session model switching from Telegram.

## Best Possible Solution

Keep `agents.defaults.models` aliases, visibility policy, and session overrides as the single runtime model-selection authority; first add an alias-first onboarding flow that can configure several approved choices without replacing the primary, then consider richer profiles or automatic routing only through a separately approved security and configuration design.
