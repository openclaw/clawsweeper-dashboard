## Label Justifications

- `P2`: This is a bounded configuration-precedence bug affecting APNs relay request timing for operators with both a configured timeout and a blank environment value.

## Summary

This remains a necessary, narrow fix: current main still treats a whitespace-only APNs relay timeout environment value as present, so it bypasses the configured timeout and falls back to 10,000 ms. The PR reuses the resolver’s existing non-empty normalization rule, preserves nonblank override precedence and timeout clamping, and includes a focused regression test; no patch defect or security concern was found.

## What This Changes

The PR makes blank `OPENCLAW_APNS_RELAY_TIMEOUT_MS` values defer to `gateway.push.apns.relay.timeoutMs` and adds a regression test for that precedence case.

## Best Possible Solution

Merge this focused resolver normalization and regression coverage once the required checks complete, keeping blank temporary environment values equivalent to an absent override.
