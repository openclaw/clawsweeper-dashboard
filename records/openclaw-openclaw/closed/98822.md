## Label Justifications

- `P1`: The linked bug breaks long-running compaction recovery, and the proposed patch can also misroute explicit auth profiles in user-facing agent paths.
- `merge-risk: 🚨 compatibility`: Existing callers that pass a profileId without lockedProfile can change from fail-fast to silently using a different credential.
- `merge-risk: 🚨 auth-provider`: The diff changes provider auth profile routing and can select a later auth.order profile instead of the supplied profile.

## Summary

Keep open: the reported bug is real, but this PR broadens fallback for every unlocked explicit `profileId` call, which can silently bypass user-selected auth profiles outside compaction.

## What This Changes

The PR changes `resolveApiKeyForProvider` so incompatible unlocked profiles fall through to normal auth resolution, and adds resolver tests for fallback versus locked-profile fail-fast behavior.

## Best Possible Solution

Keep explicit profile resolution strict by default, add an opt-in incompatible-profile fallback flag, and pass it only from embedded and harness compaction paths with focused regression coverage.

## Reproduction Assessment

Yes at source level. Current main asserts on an inherited OpenAI OAuth profile before auth.order fallback, and the PR-introduced regression is visible because `/btw` forwards a user-sourced profile without `lockedProfile`.

## Solution Assessment

No. The best fix is the narrower compaction opt-in fallback; using `!lockedProfile` globally is too broad for current callers.
