## Label Justifications

- `P2`: This is a bounded macOS setup and update reliability improvement with platform-specific blast radius.
- `impact:ux-friction`: A transient launch can persist an unusable login path or run an unintended app copy, creating avoidable setup and recovery confusion.
- `maturity:stable`: The affected macOS Gateway host taxonomy feature is M4 Stable with q74/c88.

## Summary

Current main still exposes the reported transient-bundle persistence and early-updater behavior, so this protected macOS setup-reliability request remains necessary; maintainers should confirm the relocation and installed-copy handoff UX before implementation.

## What This Changes

Add a pre-startup macOS relocation flow for transient app bundles and make launch-at-login hydration side-effect free.

## Best Possible Solution

Add one pure, testable relocation decision before updater construction and persistent startup; preserve stable custom paths, hand off only to the same bundle identifier, relaunch exactly once, and hydrate launch-at-login without invoking persistence.
