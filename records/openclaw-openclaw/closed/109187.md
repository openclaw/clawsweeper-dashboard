## Label Justifications

- `P0`: The affected v2026.7.1 upgrade path can leave the entire gateway unavailable in an indefinite service restart loop.

## Summary

The exact foreign-harness Codex sidecar condition is already fixed: it is now diagnostic rather than startup-blocking, with regression coverage on current main and inclusion in the subsequent beta release.

## What This Changes

Fix the upgrade path so a Codex binding sidecar owned by the OpenClaw harness cannot permanently block gateway readiness when `doctor --fix` has no convergent repair.

## Best Possible Solution

Keep the unified SQLite-authoritative convergence behavior: known foreign-harness sidecars remain diagnostic notices, while ambiguous ownership, failed retirement, and archive failures continue to block startup.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source and reported-live level: v2026.7.1 classified the foreign-harness sidecar as a warning, and startup readiness failed on remaining warnings; the merged regression test directly covers that ownership state.

## Solution Assessment

Yes. Reclassifying a fully resolved foreign-harness ownership decision as a notice, while retaining fail-closed warnings for ambiguity and failed retirement, is narrower and safer than deleting all unresolved sidecars or weakening the entire startup gate.
