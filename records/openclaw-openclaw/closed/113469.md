Likely related people: `steipete` is a low-confidence routing candidate from the repository’s Kubernetes/script ownership history; the PR author is not listed as an owner solely for proposing this patch.

## What This Changes

Changes Kubernetes teardown so `--delete` removes OpenClaw-managed manifest resources while a new `--delete-namespace` option opts into deleting the entire namespace, and updates the Kubernetes installation documentation.

## System Context

The Kubernetes deployment script applies OpenClaw’s Kustomize manifests and creates a runtime Secret in an operator-selected namespace. Its teardown path affects the Deployment, Service, ConfigMap, PVC, Secret, and potentially every other workload sharing that namespace.

## Best Possible Solution

Keep scoped resource deletion as the default, require `--delete` before honoring `--delete-namespace`, document the upgrade impact for existing teardown automation, and add focused proof for both shared-namespace preservation and explicit namespace deletion.
