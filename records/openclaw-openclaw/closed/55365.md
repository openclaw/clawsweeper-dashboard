## Summary

Keep this issue open: current main and v2026.6.11 still do not reject or redact browser navigation URLs with embedded credentials before dispatch, and https://github.com/openclaw/openclaw/pull/82490 remains an open candidate fix rather than merged evidence.

## What This Changes

The issue asks for the browser tool to reject HTTP(S) URLs containing username/password userinfo, redact any surfaced credential-bearing URL text, and point users to supported authentication alternatives.

## Best Possible Solution

Keep this issue as the canonical browser credentialed-navigation tracker until the linked PR or a replacement rejects and redacts before local, proxy, Playwright, Chrome MCP, or Chromium dispatch.
