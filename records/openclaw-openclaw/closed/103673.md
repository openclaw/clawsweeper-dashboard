## Label Justifications

- `P1`: Slack’s current platform contract makes OpenClaw’s generated setup unusable for every new agent app, forcing an unsupported private manifest and runtime fork.
- `impact:session-state`: Agent View roots must become distinct, restart-safe OpenClaw sessions without regressing ordinary DM or existing Assistant session rules.
- `impact:message-loss`: Incorrect lifecycle or root propagation can detach, suppress, or misroute follow-ups, streaming updates, tool replies, and recovery output.
- `impact:ux-friction`: Operators creating a current Slack agent app cannot complete the supported setup flow without manual manifest and runtime modifications.

## Summary

This remains necessary: current `main` and the latest release still generate and implement only Slack Assistant View, while Slack’s June 30, 2026 contract requires Agent View for new apps. The requested dual-lifecycle direction is well grounded, but the protected, assigned issue needs explicit owner sponsorship because it changes an irreversible new-install default and extends several recently stabilized session-routing invariants.

## What This Changes

Add Slack Agent View setup, lifecycle, context, and root-session support for new workspace apps while preserving existing Assistant View installations.

## Best Possible Solution

Sponsor a Slack-plugin-owned dual lifecycle that generates Agent View for new apps, preserves Assistant View unchanged for installed apps, carries a closed canonical root through every delivery path, normalizes ordered Slack entities as untrusted context, and proves fresh Agent plus legacy Assistant behavior without automatic migration or a new config key unless restart evidence requires one.
