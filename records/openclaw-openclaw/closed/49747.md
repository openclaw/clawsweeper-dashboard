## Summary

Current main no longer matches the reported Slack repro shape: Slack inbound code does not put agent-prefixed session keys in `MsgContext.From`, explicit session keys bypass `resolveGroupSessionKey()`, and the restart fallback route merge that could pull from the base session has already shipped.

## What This Changes

The issue reports A2A Slack thread sessions being normalized to `webchat` and restart/announce fallback routing back through a base session.

## Best Possible Solution

Keep the current prepared Slack route/session-key separation and field-level restart fallback merge; reopen or file a new issue only with fresh runtime evidence that current Slack emits `agent:<id>:...` in `MsgContext.From` or still cross-routes a thread after restart.

## Reproduction Assessment

No. Current Slack source keeps agent-prefixed session keys in `SessionKey`/route fields and builds `From` as Slack-native user/channel/group routes; the restart fallback half is covered by current source, tests, and release-tag checks.

## Solution Assessment

Yes. Preserving prepared Slack route facts and field-merging only missing restart-route data is the narrowest maintainable solution; decoding internal agent session keys from `From` would solve a shape current Slack does not produce.
