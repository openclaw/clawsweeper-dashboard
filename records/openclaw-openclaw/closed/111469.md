## Label Justifications

## Summary

The current prompt-projection path protects the trailing tool-result batch before aggregate recovery, so the newly produced tool output is not a candidate for the empty-text fallback described here. This issue duplicates the already-closed canonical report that covered the same aggregate-elision failure mode and its user-visible effect. ([raw.githubusercontent.com](https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/embedded-agent-runner/tool-result-truncation.ts))

## What This Changes

Prevent aggregate tool-result truncation from clearing current tool outputs when frozen historical results alone exceed the prompt budget.

## Best Possible Solution

Keep the existing trailing-tool-result protection and consolidate any newly observed counterexample, exact prompt shape, and provider trace on the canonical report.
