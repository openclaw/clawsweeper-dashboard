## Label Justifications

- `P0`: Current Android paths can silently lose submitted user input around process death, gateway failure, or app upgrade.
- `impact:data-loss`: Submitted text, attachment bytes, and queued rows can disappear without a durable recovery owner.
- `impact:message-loss`: A chat send can be cleared locally and retired from the outbox before canonical history proves delivery.
- `impact:session-state`: Queued turns can be replayed or routed differently from the session state captured at submission.
- `maturity:stable`: The `android-app` feature is M4 Stable and Mobile Chat is part of its scored surface.

## Summary

Current `main` still has the central Android durability defects: online sends are not journaled before network I/O, offline attachments are rejected, and queued rows retire on an ACK that precedes canonical transcript persistence. A recent merged repair covers interrupted-send parking and Room migration safety, but the broader data-loss fix remains in the open linked PR, so this protected issue is still necessary.

## What This Changes

Make every Android chat submission durable across process death and reconnects, including attachments, canonical-history retirement, pinned routing, command replay gating, and safe Room migrations.

## Best Possible Solution

Keep one Android-owned Room outbox for every submitted text or attachment turn, pin routing at capture, retain ambiguous rows until canonical `<idempotencyKey>:user` history proof, require explicit command retry after connection changes, and preserve queued input through explicit migrations.
