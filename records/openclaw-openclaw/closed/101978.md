## Label Justifications

- `P2`: This is a normal-priority availability bugfix attempt for an edge-case temp output spill failure, with limited blast radius but a blocking correctness issue.
- `merge-risk: 🚨 availability`: The added no-op listeners can leave finalization waiting forever after an asynchronous stream error has already been emitted.

## Summary

Keep open: the PR targets a real temp-file WriteStream crash path, but the proposed no-op listeners can swallow the early stream error and leave later close/finalization promises pending instead of surfacing the filesystem failure.

## What This Changes

The PR adds no-op `error` listeners before first writes to temp-file `WriteStream` instances in the bash executor and output accumulator.

## Best Possible Solution

Record the first stream error as soon as the WriteStream is created, have close/finalization reject immediately if that error already occurred, and cover both bash executor and OutputAccumulator failure paths with focused regression proof plus a redacted live terminal/log run.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: current main writes to lazy `fs.WriteStream`s before the rejecting close listeners are attached, and a Node v24.18.0 dependency probe confirms that the PR's no-op-listener pattern can leave the later close promise pending after ENOENT. I did not run the full OpenClaw test suite because this review was required to keep the checkout read-only.

## Solution Assessment

No. The narrow intent is right, but the proposed no-op listener is not the best fix because it suppresses the only error event before the code that should reject can observe it; the durable fix should capture and replay that early error in both temp-spill implementations.

Full review comments:

- **[P1] Reject early stream errors instead of swallowing them:** `src/agents/sessions/bash-executor.ts:69`
  - body: This listener prevents the unhandled `error`, but it also consumes an open/write failure before `closeTempFile()` installs the listener that rejects. With this same pattern on Node 24, a missing-directory open error leaves the later close promise pending after the stream is already closed and errored, so bash execution can hang instead of reporting ENOENT/ENOSPC. Capture the first stream error and make finalization reject immediately.
  - confidence: 0.92
- **[P1] Propagate accumulator spill errors instead of ignoring them:** `src/agents/sessions/tools/output-accumulator.ts:224`
  - body: The accumulator gets the same no-op listener, so an early temp-file error can be swallowed before `OutputAccumulator.closeTempFile()` attaches its rejecting `once("error")` handler. That leaves callers such as the bash tool waiting in output finalization rather than receiving the filesystem error. Store the early error and have `closeTempFile()` reject when it has already happened.
  - confidence: 0.9
