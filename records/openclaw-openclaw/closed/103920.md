## Summary

Current OpenClaw and upstream Codex source both lack transcript-backed idempotent steering: OpenClaw completes steering at RPC acceptance, while Codex enqueues the optional client ID without deduplicating retries. The request remains necessary, is not superseded by either related PR, and should stay open under its protected maintainer label until the upstream capability and OpenClaw transcript owner are settled.

## What This Changes

Add capability-gated, transcript-backed same-turn steering for the Codex harness after upstream provides durable idempotent `turn/steer` acceptance.

## Best Possible Solution

Keep this as the canonical upstream-blocked tracker, then implement per-message identity and recorder completion inside the Codex plugin only when an explicit app-server capability guarantees persistent deduplication and reconciliation against the approved authoritative transcript API.
