## Summary

Keep open. Current main does clear Slack pending history for mention-gated room turns, but source, tests, and docs still show `requireMention: false` Slack rooms using a rolling processed-message window under the same “since last reply” prompt framing, so the remaining issue needs a maintainer behavior decision rather than cleanup closure.

## What This Changes

Request that Slack reset or otherwise correct its channel history window after agent replies so the injected “Chat history since last reply” context does not include messages already answered.

## Best Possible Solution

Set one Slack room-history invariant: either clear `channelHistories` only after confirmed visible replies in always-on rooms, or relabel/watermark the rolling context so prompt wording, docs, and tests agree while preserving mention-gated clears.

- **Keep rolling and relabel:** Preserve the current rolling processed-message behavior but change prompt/docs wording so it no longer claims to be strictly since the last reply.
- **Use self-watermark semantics:** Record Slack outbound self entries and select history after the last self entry, closer to Telegram’s current rolling-window design but with a larger implementation surface.

## Reproduction Assessment

Yes, at source level. Current tests and Slack prepare code show `requireMention: false` room turns retain prior processed channel messages in the history block, while mention-gated turns already use the shared clear path.

## Solution Assessment

Unclear until maintainers choose the invariant. Clearing only after confirmed visible Slack replies looks like the narrowest behavior fix, but current docs/tests also support rolling always-on context, so an intentional relabel/watermark path is possible.
