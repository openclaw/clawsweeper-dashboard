## Summary

Keep this issue open: it has the protected `maintainer` label, and the current public Control UI documentation still describes non-default absolute Gateway folders as requiring a managed worktree, so the requested direct-folder behavior needs an explicit owner decision rather than automatic cleanup.

## What This Changes

Allow a selected non-Git custom Gateway folder on the Control UI New session page to create a direct session without submitting `worktree: true`.

## Best Possible Solution

Have the New session feature owner decide whether non-Git Gateway folders are a supported direct-workspace mode; if yes, update the create-parameter rule, focused regression coverage, and Control UI documentation while leaving Gateway Git validation authoritative for explicit worktree requests.
