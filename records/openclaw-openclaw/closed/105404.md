## Label Justifications

- `P2`: The deterministic race silently loses unsaved work but is limited to the Cron editing workflow during a delayed save.
- `impact:data-loss`: A form value accepted during Saving is silently replaced by the earlier persisted value.
- `impact:ux-friction`: The pending-state UI leaves unsafe controls enabled and provides no warning or recovery path.

## Summary

Keep this issue open: current `main` confirms the reported state-loss race, no canonical duplicate or fix PR was found, and the protected `maintainer` label requires explicit maintainer handling.

## What This Changes

Make Cron saves atomic so the editor cannot accept form or navigation changes that will be discarded when the pending request settles.

## Best Possible Solution

Apply the existing busy state as an editor-wide lock for every field and exit/navigation control, with a deferred-response regression test proving controls remain disabled until settlement and then recover normally.
