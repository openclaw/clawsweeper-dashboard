## Summary

The prior blocking finding remains on the current head: the new timeout can fire while the upstream response body is streaming, but the catch path still attempts to send fresh error headers after proxy response headers may already have been sent. The PR also lacks after-fix real behavior proof for a controlled upstream stall.

## What This Changes

The PR adds an `AbortSignal.timeout(...)` boundary to the Anthropic prompt-proxy upstream fetch.

## Best Possible Solution

Keep the fetch deadline, make the catch path response-state-aware—send a 502 only before headers, otherwise destroy or cleanly terminate the downstream response—and add regression coverage plus a controlled-stall terminal proof for both pre-header and post-header timeouts.
