## Summary

The reported premature OpenRouter compaction is already tracked by a canonical open report: model context-window resolution falls back to 200,000 when the OpenRouter catalog lacks the model. The proposed use of persisted session `contextTokens` is not the right ownership boundary because current documentation defines it as a best-effort reporting value, while the model context window comes from the catalog or configuration override.

## What This Changes

The issue requests that preflight compaction use a session’s persisted context-window value instead of re-resolving an OpenRouter model and falling back to 200,000 tokens.

## Best Possible Solution

Track the provider/catalog context-window resolution defect in https://github.com/openclaw/openclaw/issues/58059, preserving a catalog/config-derived context window for compaction rather than treating session reporting counters as authoritative.
