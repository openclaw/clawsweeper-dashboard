## Summary

Keep this PR open for maintainer review. It addresses a production-observed P1 gateway loop with credible live and focused-test evidence, but the new at-most-once note-retirement policy can intentionally omit a later observer digest after a transient failure or lifecycle race and needs an explicit maintainer acceptance decision before merge.

## What This Changes

Bounds Control UI session-observer model digest attempts, stops retries when a session digest cannot be persisted, and changes selected notes to retire after every model attempt.

## System Context

The gateway's session observer consumes agent-run events and publishes lightweight digest updates to connected Control UI clients. It may call a utility model and persist the resulting digest into the session store so later observer updates can build on it.

## Best Possible Solution

Land a bounded attempt budget and missing-entry shutdown only after maintainers explicitly choose the intended observer-summary reliability contract, documenting and testing whether transiently failed selected notes are intentionally dropped or retried without reopening an unbounded billing loop.
