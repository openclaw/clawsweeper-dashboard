## Summary

Keep open: current main still returns success from the managed `paths + ref` route before chooser capture and file assignment finish, while the detached waiter suppresses failures and can consume a later unrelated chooser. The merged related PR improved guidance and timeout slack but did not repair this lifecycle defect.

## What This Changes

Make the managed-browser `paths + ref` upload flow atomic and awaited while preserving paths-only delayed arming and direct input upload behavior.

## Best Possible Solution

Add a distinct awaited managed-Playwright operation for `paths + ref` that owns chooser registration, guarded click, chooser capture, strict path revalidation, and `setFiles` under one deadline and request abort signal, with deterministic cleanup in `finally`; keep paths-only arming detached and direct input paths unchanged.
