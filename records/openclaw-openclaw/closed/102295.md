## Label Justifications

## Summary

Keep open: current main and v2026.6.11 still drop Slack bot-authored room messages for wildcard-only `allowFrom`, and the fix direction affects the owner-presence security guard added for the prior Slack bot-relay issue. The reporter also provided a prototype branch for an explicit all-bot mode, but maintainer security/product direction is still needed before a fix PR should change this boundary.

## What This Changes

The issue requests a Slack behavior or diagnostic change so `allowBots` with wildcard-only `allowFrom` no longer silently drops bot-authored room messages.

## Best Possible Solution

Keep the owner-presence guard by default, add visible Slack doctor/startup/config diagnostics for ownerless `allowBots` room setups, and only add an explicit all-bot mode if maintainers deliberately accept that security boundary with docs and tests.
