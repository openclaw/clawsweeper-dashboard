## Summary

Keep open: current main still discards the three reported RPC failures, so operators cannot distinguish failed requests from genuinely empty Overview or Usage data.

## What This Changes

Show localized error, stale-data, and retry states when Overview log-tail or Usage session-detail RPC requests fail.

## Best Possible Solution

Add independent localized errors for Overview logs, Usage time series, and Usage session logs; preserve prior data only with an explicit stale indicator, clear errors on retry or success, and render focused retry actions beside each affected panel.

Yes from source inspection: make any of the three documented RPC calls reject and the current catch paths discard the error while ending the loading state. A live browser run was not performed, so this is source-reproducible rather than runtime-reproduced.

## Solution Assessment

Yes, independent panel-level error state using the existing Logs-controller pattern is the narrowest maintainable fix; a global Gateway error would conflate unrelated requests and would not identify which retained data is stale.
