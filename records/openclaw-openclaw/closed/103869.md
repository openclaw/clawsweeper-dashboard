## Summary

Current `main` and stable v2026.6.11 contain the reported identity split: approval registration binds the persisted requester device, but approved local `node.invoke` replay omits that identity and fails the existing device check. Keep this protected issue open while the direct closing pull request remains under review.

## What This Changes

Fix approved local `host=node` `system.run` replay by presenting the persisted requester device identity bound to the approval.

## Best Possible Solution

Use the existing Gateway-call boundary to reuse, but never create or downgrade, the persisted requester identity for approval-bearing `system.run` replay while preserving ordinary device-less calls and all fail-closed checks.
