## Summary

Keep open: current main preserves the structured runtime boundary, but the inspected Control UI, TUI, export, and display paths still render assistant-authored transcript-looking text as ordinary assistant content without a visible escape or warning.

## What This Changes

The issue asks OpenClaw to prevent assistant-generated text that looks like a timestamped user transcript turn from being confused with real session history or authority.

## Best Possible Solution

Keep the structured tool authority model as-is, then add a narrow shared presentation or diagnostic guard that marks assistant-authored transcript-looking lines as non-authoritative text wherever session history is shown or exported.

## Reproduction Assessment

No high-confidence end-to-end reproduction is available. The report provides private incident forensics, and source inspection shows the visible render/export paths lack a transcript-header escape or annotation.

## Solution Assessment

Unclear as an implementation plan because maintainers need to choose the boundary. The likely best fix is shared presentation/diagnostic handling, while provider-specific output filtering would be too brittle without stronger reproduction proof.
