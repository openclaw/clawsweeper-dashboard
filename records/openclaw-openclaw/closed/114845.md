## Summary

This is a focused process-supervision repair with supplied real child-process proof and passing hosted checks, but it changes cancellation ordering for scoped replacements and carries the protected `maintainer` label. Keep it open for explicit process-runtime owner review of the current merge result rather than auto-close or automated repair.

## What This Changes

The PR makes scoped process replacements wait for earlier startups, cancel superseded scoped runs, and fence later arrivals until the replacement has started while retaining ordinary same-scope concurrency.

## System Context

The process supervisor launches and tracks child or PTY-backed work used by CLI sessions, scheduled watchers, and other supervised tasks. A caller can assign a scope so a replacement run terminates earlier work in that scope without affecting unrelated scopes.

## Best Possible Solution

Retain the owner-boundary implementation if a process-runtime reviewer confirms the current merge result preserves the documented replacement fence: cancel only predecessor runs, keep ordinary same-scope starts concurrent, and leave newer arrivals untouched.
