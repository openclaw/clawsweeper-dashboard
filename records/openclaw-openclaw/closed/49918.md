## Summary

Keep open: current `main` and the latest release still route TUI `/new` through a local empty-session switch, so the documented `command:new` hook path is still bypassed. The target-repo fix attempts are closed unmerged, and the only open closing PR is a conflicting fork PR rather than a safe close path.

## What This Changes

Restore TUI `/new` so it emits hook-visible new-session behavior while preserving isolated per-client `tui-*` sessions.

## Best Possible Solution

Restore TUI `/new` through the existing gateway/session lifecycle so `command:new`, `before_reset`, and session lifecycle hooks observe the session being left while unique `tui-*` isolation remains intact.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: current TUI `/new` calls `setEmptySession(uniqueKey)`, while the gateway reset/create paths are what emit `command:new` hooks.

## Solution Assessment

Yes on the requested behavior, but the implementation should reuse the existing gateway/session lifecycle with correct previous-session attribution rather than adding a parallel TUI-only hook event.
