## Label Justifications

- `P1`: The PR addresses an active session workflow that can display false context-full warnings and trigger harmful user reactions such as unnecessary compaction.
- `merge-risk: 🚨 session-state`: Omitting the budget write can associate stale context capacity with a newly persisted model.
- `merge-risk: 🚨 compatibility`: Existing consumers may rely on `contextTokens` remaining the current model denominator even when the usage numerator is not fresh.

## Summary

The revised head fixes the prior token-semantic error, but it now suppresses the model-budget write instead of using the existing freshness contract, which can preserve a previous model’s context budget after the session model changes. This PR also still lacks after-fix real behavior proof.

## What This Changes

The PR retains the resolved model context budget for total-token derivation while persisting `contextTokens` only when the run reports nonzero usage.

## Best Possible Solution

Keep `contextTokens` synchronized with the active model budget, use `totalTokensFresh` to suppress unknown usage in status and Control UI projections, and add regression coverage for missing usage, recovery on later usage, and model changes.
