## Summary

Keep this maintainer-labeled issue open: current main still contains the reported floor violation, while the broader consolidation should be bounded carefully so owner-specific retry semantics do not change.

## What This Changes

Consolidate retry timing so memory-host and other retry consumers cannot schedule below satisfiable server Retry-After floors.

## Best Possible Solution

Create one dependency-light retry execution/timing primitive that enforces Retry-After floors, then retain retry classification, attempt limits, abort handling, terminal-error aggregation, logging, disposal, and business-code policy in thin owner-specific adapters.

## Reproduction Assessment

Yes at source level: pass a fractional Retry-After value through the memory-host helper with a low jitter draw and Math.round can produce a delay below the supplied floor. The review did not execute a test, so this is source-reproducible rather than runtime-reproduced.

## Solution Assessment

Yes in principle, provided the shared layer owns only generic execution and floor-preserving timing. Centralizing domain-specific retry policy would be broader and less maintainable than the proposed adapter boundary.
