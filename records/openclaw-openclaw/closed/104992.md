## Label Justifications

- `P1`: Deterministic poisoned session replay breaks active tool workflows and can produce duplicate documents or silently incorrect paginated results.
- `impact:session-state`: Persisted transcript state is replayed with altered call arguments, causing the resumed model context and subsequent execution to drift.
- `impact:data-loss`: Invalid pagination cursors and duplicate-document recovery can silently omit intended records or replace the expected document result.
- `impact:security`: The defect sits at the boundary between secret-safe transcript persistence and executable model replay, so the repair must preserve confidentiality.

## Summary

Current `main` still persists redacted tool-call arguments and later replays ordinary call blocks into model history, so this is a valid session-integrity bug rather than a duplicate or already-fixed report. The new-transcript repair direction is clear, but historical entries lack provenance and require an explicit recovery policy before implementation.

## What This Changes

Prevent redacted placeholders in persisted tool-call arguments from being treated as usable values when a session is resumed.

## Best Possible Solution

Add reserved, versioned provenance to newly redacted persisted call payloads, remove the marked call and its canonically paired result from model replay, and provide a backed-up doctor migration or explicit reset path for ambiguous historical sessions without storing recoverable plaintext.
