## Label Justifications

- `P0`: The underlying regression can indefinitely block a non-technical macOS user during onboarding with no in-product recovery path.
- `merge-risk: 🚨 security-boundary`: The patch writes arbitrary shell output to temporary files with umask-derived permissions, which can expose sensitive output to another local account.

## Summary

This PR addresses a reproducible macOS onboarding blocker with a focused root-cause fix, but the current head introduces a concrete local data-exposure risk by creating command-output files with umask-derived permissions; the protected `maintainer` label also requires direct owner handling rather than automated cleanup.

## What This Changes

The branch replaces pipe-backed macOS `ShellExecutor` output reads with per-run seekable temporary files, centralizes single-winner completion, and adds retained-descriptor and repeated-timeout regression coverage.

## Best Possible Solution

Keep the root-process completion design, but create the capture directory and files with explicit owner-only permissions, clean up partial initialization failures, retain the lifecycle regression tests, and refresh exact-head macOS validation before landing.

## Reproduction Assessment

Yes. Current main awaits pipe EOF after root-process termination, and the linked `/bin/sh -c 'sleep 5 & echo ready'` path deterministically leaves that EOF pending through the background descendant.

## Solution Assessment

No, not in its current form. Returning at the launched process boundary is the narrow root-cause fix, but the filesystem confidentiality boundary must be explicit before the implementation is safe to merge.
