## Summary

Keep this PR open for revision: the timeout direction is useful, but on PowerShell 7.4+ `TimeoutSec` only bounds connection establishment, so a response that stalls after connecting can still hang. The PR also lacks after-fix Windows runtime proof. citeturn10search1turn10search3

## What This Changes

Adds 30-second timeouts to Windows installer metadata requests and 300-second timeouts to Node.js and Git binary downloads.

## Best Possible Solution

Introduce version-aware request handling that preserves Windows PowerShell 5.1 compatibility while bounding both connection establishment and stalled response reads on PowerShell 7.4+, then demonstrate both paths in a Windows runtime transcript.

## Reproduction Assessment

Yes, from source and the documented PowerShell contract: on PowerShell 7.4+, a test endpoint that accepts the connection and then stops returning response data remains unbounded by `TimeoutSec` alone. A live Windows reproduction was not supplied.

## Solution Assessment

No. Adding request limits is the correct direction, but the narrow maintainable solution must account for the separate modern PowerShell connection and operation timeout contracts while retaining PowerShell 5.1 support.
