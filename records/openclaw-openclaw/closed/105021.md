## Summary

Current main still drops cancellation at the Exa provider boundary and may continue provider fallback after a parent abort, so this focused fix remains necessary. The runtime changes follow existing plugin and guarded-fetch contracts, but the unchanged provider proof still catches its own failure sentinel and asserts only elapsed time, leaving the prior blocking finding unresolved.

## What This Changes

The PR forwards the execution AbortSignal through Exa’s provider and HTTP runtime, makes parent cancellation terminal during shared provider fallback, and adds cancellation regression and proof coverage.

## Best Possible Solution

Keep the plugin-owned signal forwarding and generic terminal-cancellation guard, but replace the provider proof with a cancellation-specific assertion and redacted evidence of an in-flight Exa-path request terminating promptly without starting fallback.
