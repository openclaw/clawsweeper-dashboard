## Summary

Keep open: the bug is valid and the helper choice is directionally right, but the patch introduces a word-boundary regression when surrogate-safe slicing backs off at an emoji boundary, and the external-PR proof is still mock/test-only.

## What This Changes

The PR changes active-memory recall summary truncation to use the existing UTF-16-safe SDK slice helper and adds a regression test for emoji-at-boundary summaries.

## Best Possible Solution

Keep the SDK helper-based fix, but preserve the existing word-boundary decision while making the returned text surrogate-safe, then add coverage for the whitespace-before-emoji boundary and attach real behavior proof.

## Reproduction Assessment

Yes for source-level reproduction: current main uses raw UTF-16 slicing in the active-memory summary path, and the PR body’s negative-control test demonstrates the dangling-surrogate failure. The new review finding is also source-reproducible by comparing old and new truncation behavior for a whitespace-before-emoji boundary.

## Solution Assessment

No: `sliceUtf16Safe` is the right helper, but this exact patch is not the best fix because it changes existing word-boundary behavior. The safer repair is to keep a boundary source equivalent to the old raw cut while ensuring the final returned text contains no dangling surrogate.
