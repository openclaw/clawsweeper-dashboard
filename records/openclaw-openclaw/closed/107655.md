## Summary

Source, live A/B logs, and independent production evidence support a real prompt-admission bug: aggregate projection can successfully bound historical tool results, yet the prompt phase still forces local overflow recovery and whole-session compaction. The linked closing pull request remains open and unmerged, so this issue is still necessary until that candidate is reviewed and landed or rejected.

Likely related people: `obviyus` introduced the aggregate-pressure recovery policy; `vincentkoc` and `steipete` have recent history on adjacent tool-result projection and embedded-runner paths.

## What This Changes

Allow a successfully aggregate-truncated prompt projection to continue through normal budget checks and provider submission instead of forcing whole-session compaction.

## Best Possible Solution

Land a narrow fix that carries the aggregate replacement count into prompt admission, continues normal post-projection checks when replacements occurred, and retains compaction for zero-replacement or genuine-overflow cases.
