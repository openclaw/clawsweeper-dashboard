## Summary

The reported repeat-update and restart-resume failure modes are already covered by current Telegram ingress, replay, and reply-session fixes, and those fixes shipped in `v2026.7.1`. The report's proposed content-hash suppression and manual file deletion would be broader and less safe than the shipped queue/session fixes.

## What This Changes

The issue requests a fix for Telegram group chats repeatedly sending the same reply, including loops that resume after a gateway restart.

## System Context

Telegram updates enter the gateway through ordered per-chat ingestion, then create or resume an agent session and deliver the resulting reply back to Telegram. The affected safeguards prevent an already-completed or repeatedly failing update from being replayed into another agent run or from leaving a chat lane permanently stuck.

## Best Possible Solution

Keep the shipped queue-backed replay, tombstone, and session-writer protections; if the loop reproduces on `v2026.7.1`, collect redacted Telegram diagnostic logs and open a focused current-version report rather than adding content-based suppression or deleting persisted user state.
