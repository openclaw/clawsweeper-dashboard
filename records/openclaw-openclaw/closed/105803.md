## Summary

Keep open: current main’s static config-defaulting path still appears to ignore the documented provider-level token limits, while the related closed issue addressed the discovered/runtime merge path rather than this path.

## What This Changes

Make provider-level `contextWindow` and `maxTokens` act as defaults for models that omit their own values.

## Best Possible Solution

Update the core model-defaulting logic to use explicit per-model limits first, then valid provider-level limits, then global defaults, while preserving context-window clamping and adding regression coverage for inheritance and overrides.

Yes. Fixing inheritance in `applyModelDefaults` is the narrowest maintainable solution because provider-level defaults are already a documented core config contract; duplicating values into every model is only a workaround.
