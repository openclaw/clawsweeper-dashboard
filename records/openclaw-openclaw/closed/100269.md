## Summary

Keep open: current main and v2026.6.11 still reject blank optional integer params, and the linked open PR is the active candidate fix. This issue should remain open until https://github.com/openclaw/openclaw/pull/100273 lands or maintainers choose a replacement fix.

## What This Changes

The issue asks OpenClaw to treat empty or whitespace-only optional integer tool parameters, especially Telegram reply/thread routing hints, as unset instead of throwing.

## Best Possible Solution

Review and land the linked shared-reader fix, or an equivalent narrow routing fix, so blank optional integer params are absent while real invalid values remain rejected.

## Reproduction Assessment

Yes. A high-confidence source reproduction is `readPositiveIntegerParam({ replyTo: "" }, "replyTo")`: blank input parses to undefined, then the wrapper throws because the raw value is non-null.

## Solution Assessment

Yes. Fixing the shared optional integer readers is the best narrow owner-boundary shape if maintainers accept the exported behavior change; otherwise the safer fallback is blank normalization at the message-routing call sites.
