## Summary

Current main still reproduces the central failure: the first Control UI locale run after the split-token follow-up passed generation and validation but received HTTP 422 while minting an App token, leaving no automation branch or generated pull request. The issue also carries the protected `maintainer` label and an active assignee, so conservative cleanup must leave it open.

## What This Changes

Restore both locale refresh workflows so generated translations publish through reviewable pull requests and exact merge instead of failing after generation.

## Best Possible Solution

Keep one shared least-privilege publisher, align each token request with the installed App permissions, then prove a non-noop publication from both locale workflows, exact-merge both generated pull requests, and verify each reconciliation run exits without regenerated changes.
