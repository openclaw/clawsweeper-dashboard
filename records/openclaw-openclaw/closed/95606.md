## Summary

Keep open: current main and the latest release still leave the recall-to-forget deletion handoff unresolved, and the broader conflicting-fact replacement/deprecation behavior needs maintainer product direction rather than cleanup closure.

## What This Changes

The issue asks for stale or incorrect memory-lancedb entries to be deletable or superseded so conflicting remembered facts do not keep appearing together.

## Best Possible Solution

Approve a narrow model-visible recall deletion selector for memory-lancedb if maintainers want immediate cleanup usability, while keeping replacement, deprecation, tombstone, and conflict semantics in the broader memory lifecycle design.
