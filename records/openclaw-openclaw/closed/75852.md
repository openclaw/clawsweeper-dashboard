## Label Justifications

- `P1`: Repeated Telegram getUpdates conflicts can make a configured channel unusable and have been reported across multiple released versions and operating systems.
- `impact:message-loss`: When the conflict loop occurs, Telegram inbound messages and commands are not received or answered.

## Summary

Keep open: merged mitigations improve Telegram transport cleanup and 409 recovery, but the central same-token long-poll overlap has post-fix live reports and is not proven resolved on current main or v2026.6.11. Current documentation promises one poller per token, so the remaining gap is a channel reliability bug rather than expected configuration behavior.

## What This Changes

Prevent a single OpenClaw gateway from creating overlapping Telegram getUpdates requests for the same bot token.

## Best Possible Solution

Enforce one polling owner per bot token across classic and isolated paths, abort and await the previous getUpdates lifecycle before replacement, recover 409s in-session with bounded backoff, and prove the behavior live on macOS plus a multi-account restart scenario.

## Solution Assessment

No definitive fix is proven yet. A per-token ownership and awaited-cancellation invariant is safer than an inter-poll delay alone, but maintainers should confirm the current live failure path before changing restart timing.
