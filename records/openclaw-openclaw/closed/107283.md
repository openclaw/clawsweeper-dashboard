## Summary

Keep this PR open but do not merge the current patch: `completed` means the process terminated normally, not that its command succeeded, and the established warning policy deliberately preserves exec failure warnings when the run produced no user-facing reply. The unchanged prior blocker remains valid because the guard would silence genuine ordinary non-zero failures alongside benign outcomes. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/agents/bash-tools.exec-runtime.ts))

## What This Changes

The PR changes the shared tool-result classifier and its tests so a finite non-zero exit code is not considered an error when the result status is `completed`.

## Best Possible Solution

Keep the shared non-zero failure signal and handle benign outcomes through an explicit accepted-exit disposition—or the existing successful-reply suppression—with regression coverage and live proof for both benign and genuine failure cases.
