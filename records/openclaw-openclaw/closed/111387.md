## Summary

Keep this issue open. Current `main` still presents a timed-out foreground exec as a raw termination reason and exposes timeout classification in background-process status without a shared ambiguous-side-effect warning, so the reported retry hazard remains actionable. citeturn8view0turn13view0

## What This Changes

Add ambiguity-safe timeout presentation for foreground exec and background process status so agents verify external state before retrying potentially non-idempotent commands.

## Best Possible Solution

Create one shared timeout outcome presentation that says a killed or timed-out command may already have completed external effects, requires state verification before retry, and applies consistently to foreground exec, process polling, and timeout completion reporting.
