## Summary

Keep open: the PR targets a real gateway large-attachment crash, but it is not merge-ready because it changes the exported MIME sniffer from full base64 validation to prefix-only validation, lacks real gateway/webchat proof, and overlaps with another open fix candidate that is not safe enough to supersede it.

## What This Changes

The PR replaces whole-string base64 validation/canonicalization in chat attachment MIME handling with prefix scanning and adds large PNG regression coverage.

## Best Possible Solution

Revise this PR to preserve full base64 validation semantics for shared callers, or coordinate with the shared media-core canonicalizer fix, then add redacted real Control UI/Gateway proof for the large screenshot send path.

## Reproduction Assessment

Yes, at source/report level but not by a live run in this read-only review. Current main sends chat attachments through full-payload base64 validation and MIME sniffing, and the linked issue provides matching v2026.6.11 gateway RangeError logs for large clipboard screenshots.

## Solution Assessment

No, not as submitted. The gateway mitigation is plausible, but the safer fix should avoid the stack issue while preserving the shared sniffer/base64 validation contract and proving the real webchat path.
