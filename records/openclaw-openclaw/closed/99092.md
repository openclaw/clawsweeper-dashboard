## Summary

Keep open. Current main and the latest release still have the one-shot Control UI mount fallback: `Keep waiting` re-arms the watchdog without retrying the failed module, so the transient gateway-restart case remains unsolved; https://github.com/openclaw/openclaw/issues/90716 overlaps on the same fallback surface but reports a distinct old-WebKit/proxy trigger.

## What This Changes

Request that the Control UI recover from transient gateway-restart module-fetch failures and show fallback copy that distinguishes gateway unreachability from extension or content-script blocking.

## Best Possible Solution

Make the static Control UI fallback perform a bounded real recovery attempt for the app bundle and use gateway-reachability-aware copy; keep any launchd throttle/config change separate unless it is independently reproduced and approved.

## Reproduction Assessment

Yes for the Control UI fallback dead-end from current source and existing test coverage: when `openclaw-app` never registers, `Keep waiting` only hides the panel and re-arms the same timer. The full macOS launchd double-restart timing was not live-reproduced in this read-only review.

## Solution Assessment

Yes, the best first fix is the narrow static fallback recovery and diagnosis path. Adding a launchd throttle config knob is broader config surface and should not be bundled into the initial bug fix without separate maintainer approval.
