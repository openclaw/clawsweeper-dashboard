## Label Justifications

- `P1`: Completed subagent work can remain invisible to a live parent workflow, causing repeated spawns and breaking real multi-agent orchestration.
- `impact:message-loss`: A completed child's frozen result is retained internally but its completion message is not delivered to the requester.
- `impact:session-state`: The parent session can remain unaware of completed children and make decisions from stale orchestration state.

## Summary

The busy embedded-requester failure is a concrete instance of the retry-limit completion-loss behavior already tracked by the older canonical issue, which covers a temporarily busy parent, the same three-attempt retry envelope, missing parent notification, and the same durable-delivery design choices.

## What This Changes

Ensure completed subagent results reach busy embedded parent sessions through durable deferred delivery or parent-visible completion state rather than expiring after a short visible-reply-based retry envelope.

## Best Possible Solution

Consolidate the gig-session evidence into https://github.com/openclaw/openclaw/issues/90178 and implement one durable completion contract there: persist or queue the child outcome for the requester, wake yielded parents on success or give-up, and avoid adding retry configuration unless the durable delivery design still requires an operator policy knob.
