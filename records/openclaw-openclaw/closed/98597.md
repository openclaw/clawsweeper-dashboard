## Summary

Keep open: the reported Telegram leak is valid and the PR fixes the happy path, but the pre-parse regex can strip literal `<parameter>` XML from code/pre HTML instead of escaping it, corrupting messages that include XML examples.

## What This Changes

The branch adds a Telegram formatter helper and regression test to remove raw `<parameter ...>` wrapper tags before Telegram HTML escaping.

## Best Possible Solution

Make parameter-wrapper stripping code/pre-aware and scoped to the rich visible-text delivery boundary, with regression tests for both the reported details block and literal XML examples.

## Reproduction Assessment

Yes, source-reproducible. Current main escapes unsupported `<parameter>` tags as visible text in the rich sanitizer path, and the linked issue gives a current-release Telegram rich-message repro; I did not run live Telegram in this read-only review.

## Solution Assessment

No. The direction is right, but a global regex before tag-aware parsing is too broad because it bypasses the existing code/pre preservation invariant.
