## Summary

Keep open for owner review: the patch is correct and well-proven, but it intentionally changes a public Gateway RPC from Node’s permissive decoding to fail-closed canonical validation, so the compatibility boundary needs explicit acceptance before merge.

## What This Changes

The PR routes realtime and transcription Talk relay audio through one strict decoder that accepts standard and URL-safe base64 while rejecting malformed or non-round-tripping input before provider delivery.

## Best Possible Solution

Define the supported relay contract as padded or unpadded standard/base64url input, reject malformed and non-round-tripping frames before any provider or event side effect, and land the shared guard after a Talk owner explicitly accepts that upgrade boundary.
