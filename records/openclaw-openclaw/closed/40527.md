## Summary

Keep open: current main and the latest release still start remote skill-bin refresh immediately for macOS nodes that advertise `system.which` or `system.run`; the old default-allowlist cause is mitigated, but the remaining readiness/backoff behavior is not resolved by a merged fix.

## What This Changes

Fix remote skill-bin probing for macOS app-backed nodes so co-located or reconnecting nodes do not spam timeout warnings or delay gateway startup while preserving legitimate remote node exec behavior.

## Best Possible Solution

Make remote skill-bin refresh readiness-aware with bounded deferral/backoff, preserve approved macOS node exec semantics, and prove both co-located and remote macOS app-node behavior with redacted live logs.
