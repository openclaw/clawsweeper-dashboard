## Summary

Current main already implements abandoned-lock recovery: synchronous auth storage inherits `proper-lockfile`’s 10-second stale reclamation, while asynchronous token refresh explicitly uses a 30-second stale threshold with retries. The reported indefinite blocking does not match current source or the pinned dependency contract.

## What This Changes

Ensure auth storage safely reclaims a lock abandoned when a process exits during token refresh.

## Best Possible Solution

Keep the dependency-owned stale-lock reclamation; if additional assurance is desired, add a focused crash-and-restart regression test rather than a second custom lock-breaking mechanism.
