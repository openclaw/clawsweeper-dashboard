## Summary

Keep this PR open: current main still treats a whitespace-only Synology Chat token as an implicit default account, while the proposed fix uses the repository’s established configured-value contract and has convincing before/after runtime proof. No blocking correctness or security finding was found.

## What This Changes

The PR makes Synology Chat account discovery ignore whitespace-only config and environment tokens and adds regression coverage for named-account enumeration with a blank environment token.

## Best Possible Solution

Land the focused shared-predicate fix after normal CI completion, preserving Synology Chat’s existing empty-channel behavior, valid default-token discovery, and named-account merging.

## Reproduction Assessment

Yes. Calling the production listAccountIds function with `SYNOLOGY_CHAT_TOKEN` set to whitespace reproduces the phantom default account before the patch, and the PR provides before/after output plus controls.

## Solution Assessment

Yes. Reusing hasConfiguredAccountValue at the plugin-owned implicit-account predicate is the narrowest maintainable fix; an inline trim would duplicate policy, while switching wholesale to createAccountListHelpers would alter Synology Chat’s intentional no-account fallback semantics.
