## Summary

The reported high-frequency failure was the shared key-order/metadata-sensitive stale-snapshot conflict, and that conflict predicate was corrected before this issue was filed and shipped in v2026.7.1. The remaining WhatsApp ingress-serialization concern is not supported by a current-version reproduction after the shared fix, while genuine session rotations retain the existing retry path.

## What This Changes

Fix WhatsApp inbound message loss caused by false reply-session initialization conflicts and evaluate whether WhatsApp also requires per-session ingress serialization.

## Best Possible Solution

Keep the shared identity-only session guard shipped in v2026.7.1; if WhatsApp still loses messages on that release, open a narrowly scoped follow-up with fresh conflict logs proving a genuine post-fix initialization race before adding channel-specific ingress serialization.

## Reproduction Assessment

Yes for the affected source and v2026.6.11 behavior: full-entry revision comparison deterministically rejects semantically identical or concurrently updated session metadata. ## Solution Assessment

Yes. Correcting the shared accessor predicate is narrower and more complete than adding a WhatsApp-only queue because it removes the demonstrated false conflict across every channel while retaining detection and retry for real session rotations.
