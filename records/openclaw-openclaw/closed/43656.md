## Review Findings

Overall confidence: 0.9

Full review comments:

- **[P1] Keep raw gatewayUrl on the existing allowlist:** `src/agents/tools/gateway-peer.ts:65-67`
  - body: The helper returns caller-provided `gatewayUrl` directly, and both new session-tool paths pass it to `callGateway` instead of `resolveGatewayOptions`. That bypasses the existing agent-tool allowlist for URL overrides, so an agent can direct these session tools at arbitrary WebSocket hosts when it supplies a token. Preserve the existing allowlist for raw `gatewayUrl` and reserve any broader routing for configured peers with an explicit security contract.
  - confidence: 0.92
- **[P1] Include idempotencyKey in remote spawn requests:** `src/agents/tools/sessions-spawn-tool.ts:167-178`
  - body: The remote `sessions_spawn` branch calls the gateway `agent` method without `idempotencyKey`, but that RPC schema requires a non-empty `idempotencyKey`. Cross-gateway spawn calls will be rejected before the remote run starts; generate and forward a stable key as the local spawn path does.
  - confidence: 0.9
- **[P2] Reject tokenless peers before calling a URL override:** `src/agents/tools/gateway-peer.ts:59-62`
  - body: Named peers can currently resolve to `{ gatewayToken: undefined }`, and the tests even cover a tokenless peer, but `callGateway` rejects explicit URL overrides unless explicit credentials are supplied. Either require a token for peer entries on this path or add a deliberate no-auth peer mode with tests; otherwise documented tokenless peers fail before reaching the remote gateway.
  - confidence: 0.86
