## Summary

Keep open: current main and v2026.6.11 still have the isolated cron to Claude CLI cleanup path that can accept returned CLI text, close the live session, and cancel the process tree, while cron outcome resolution still has no pending foreground native-tool signal. The related long-work issues overlap, but they do not fully own this issue's cron success, announce delivery, and partial-state invariant.

## What This Changes

The issue reports isolated cron agentTurn accepting a placeholder final Claude CLI response before foreground Bash finishes, then delivering it as success while cleanup kills the subprocess and leaves partial state.

## Best Possible Solution

Define a cron and Claude CLI lifecycle contract where isolated cron cannot record or deliver success while foreground native tool work is still pending; unsupported long foreground work should fail with explicit diagnostics or be routed through a durable exec/process or command-runner path.
