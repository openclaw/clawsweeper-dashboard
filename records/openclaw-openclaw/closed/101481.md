## Label Justifications

- `P2`: This is a focused iOS startup-state bug fix with limited blast radius, but the current patch can regress failed setup recovery.
- `merge-risk: 🚨 compatibility`: The route now gives saved gateway config precedence over completion markers, changing behavior for persisted app state on relaunch or upgrade.
- `merge-risk: 🚨 session-state`: The diff can misclassify incomplete gateway setup state as normal post-pair shell state.

## Summary

Keep open: the PR targets the right iOS startup route, but the new guard is too broad and can skip onboarding for a first setup attempt that only persisted an active gateway entry before connecting.

## What This Changes

This PR moves iOS startup routing so existing gateway config opens the normal shell before stale onboarding markers, and adds RootTabs presentation tests for that routing matrix.

## Best Possible Solution

Keep the fix in iOS startup routing, but distinguish completed or verified gateway configuration from in-progress persisted attempts and cover both stale successful config and failed setup attempt cases in tests.

## Solution Assessment

No, not as written: the route is the right owner boundary, but the guard treats unfinished setup state as completed configuration. The safer fix should preserve onboarding recovery for incomplete attempts while still fixing stale successful configuration.
