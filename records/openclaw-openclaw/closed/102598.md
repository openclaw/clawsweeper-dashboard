## Label Justifications

- `P1`: The issue reports a current production group-chat failure where repeated user turns receive no visible failure notice after the bot indicates activity.
- `impact:message-loss`: The affected path converts an intended rate-limit failure reply into `NO_REPLY`, suppressing the outbound channel message.

## Summary

Keep this issue open: current `main` still has the reported classifier split, and the protected `maintainer` label makes this explicit maintainer-routed work rather than cleanup-close material.

## What This Changes

The issue requests that periodic provider usage-limit failures in group chats surface user-visible rate-limit copy by honoring typed `FailoverError.reason` instead of re-parsing only error text.

## Best Possible Solution

Use one shared transient-failover classifier for both reply paths that treats raw `FailoverError` reasons `rate_limit` and `overloaded` as visible provider failures, preserves useful reset copy, and adds focused group/channel regression coverage for raw periodic-limit errors.
