## Summary

Keep open: current main still has the reported stale-snapshot auth bookkeeping writes and OAuth refresh CAS failure path, and the protected maintainer label plus auth-secret ownership make this a human-routed issue rather than a cleanup close.

## What This Changes

Prevent auth-profile bookkeeping and OAuth refresh races from reverting or discarding rotated OpenAI OAuth refresh tokens.

## Best Possible Solution

Make bookkeeping updates best-effort state-only writes that never persist stale credential snapshots, and make refreshed OAuth CAS conflicts recover or adopt safely instead of leaving a consumed token in storage.
