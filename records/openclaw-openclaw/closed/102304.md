## Summary

Do not merge the current head. The persistence-before-cleanup ordering is necessary and the underlying bug remains real, but the proposed retry is not durable across successor release and restart, so this PR needs a broader persisted-state repair.

## What This Changes

The PR moves superseded-run removal persistence ahead of artifact cleanup, restores the in-memory row when persistence fails, and adds a sweep-based retry path with regression tests.

## Best Possible Solution

Persist an explicit supersession boundary on the old run, normalize and round-trip it through the SQLite payload, clear it when constructing a fresh generation, and cover failure → successor release → restart → sweep.
