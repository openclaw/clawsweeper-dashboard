## Summary

Keep open: the latest head resolves the prior server-backoff blocker and convincingly proves active-request cancellation, but direct reuse of the run signal introduces a high-confidence request-listener lifecycle defect with the pinned MCP SDK.

## What This Changes

The PR propagates per-call AbortSignal values through bundle MCP tool, resource, and prompt execution into MCP SDK request options, makes caller aborts neutral to server backoff, and adds forwarding plus real stdio cancellation tests.

## Best Possible Solution

Forward cancellation through a per-request child signal whose parent abort listener is removed in a finally block, then cover many completed calls followed by one run abort and assert that only active work is cancelled.
