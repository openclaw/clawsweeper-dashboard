## Summary

Keep open: the OAuth fix is still at the caller after `postTokenForm` has already materialized the token endpoint body, so an oversized token error can still hit memory before the new cap runs.

## What This Changes

The PR replaces OpenAI OAuth token error and Codex image no-body response reads with `readResponseTextLimited` and adds a loopback OAuth error-boundary test.

## Best Possible Solution

Move the OAuth cap into the guarded token fetch/read lifecycle before `arrayBuffer()`, preserve SSRF guard release behavior, and prove both oversized and normal exchange/refresh errors on the real stream path.

## Reproduction Assessment

Yes. Source inspection on the PR head shows exchange and refresh both call `postTokenForm`, which awaits `response.arrayBuffer()` before the changed bounded read executes.

## Solution Assessment

No. `readResponseTextLimited` is the right primitive, but the OAuth fix needs to apply it before or inside the token fetch helper rather than after the helper has copied the full response body.
