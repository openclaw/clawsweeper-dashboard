## Summary

This PR remains necessary as a Linux Quick Chat parity feature, but it should stay open for maintainer review: it broadens the companion webview CSP so agent-configured avatar URLs may load from arbitrary `http:`/`https:` origins, and that trust boundary is a product/security policy choice rather than a mechanical follow-up. The PR has direct Linux desktop screenshots and end-to-end shortcut evidence, but its `maintainer` label also requires explicit human handling.

## What This Changes

The branch adds Linux Quick Chat agent selection, avatar display, selected-agent routing, configurable/toggleable shortcuts, animation, an additive `identityAvatarUrl` agent-summary field, and Linux documentation.

## Best Possible Solution

Keep local avatar data URIs working, then have a maintainer explicitly choose whether remote avatars are supported; if yes, document the trusted-config/network-fetch contract and narrowly constrain the allowed image origins and schemes where feasible, otherwise render a local fallback for remote URLs.
