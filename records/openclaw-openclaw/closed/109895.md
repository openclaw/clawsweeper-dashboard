## Label Justifications

## Summary

Keep this PR open: the fail-open direction addresses a real onboarding blocker, but the current head still returns a failed inspection into the inspected-model collection, allowing downstream configuration to advertise the stale model as tools-capable. The protected `maintainer` label also requires explicit maintainer handling.

## What This Changes

The PR changes Ollama interactive setup to continue after individual `/api/show` failures, report skipped models, suppress speculative pull recommendations when all inspections fail, and retain hard failure when a newly pulled model cannot be verified.

## Best Possible Solution

Keep per-model inspection fail-open, but exclude failed entries from tools-capable selection and generated model configuration—or explicitly mark them non-tools—while preserving the all-fail pull suppression, hard failure for an unverifiable newly pulled recommendation, bounded user note, and focused regression plus live configuration proof.
