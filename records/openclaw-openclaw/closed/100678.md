## Summary

Keep open: current main and the latest release do not show a supported trusted-proxy WebChat per-user sender identity or gateway-enforced per-user agent ACL, and the older related report only covers the sender half and was closed stale rather than fixed.

## What This Changes

The issue asks whether trusted-proxy WebChat can preserve authenticated per-user sender identity and enforce per-user agent access at the gateway/WebSocket layer.

## Best Possible Solution

Make an explicit supported pattern: either document separate gateways per trust boundary, or design trusted-proxy principal propagation plus gateway-enforced agent ACLs across WebChat, sessions, and other agent-addressing RPCs.
