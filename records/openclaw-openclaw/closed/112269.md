## Summary

Keep this PR open for maintainer review. The display-only design, focused tests, and supplied live CLI proof are strong, but the gateway `channels status` formatter applies phone parsing to every channel's `allowFrom` values without the new explicit presentation contract, contradicting the safety boundary that only opted-in phone fields should be formatted.

## What This Changes

Adds a `phone-number` config-presentation hint, a shared `libphonenumber-js/min` formatter, selected SMS/Signal/WhatsApp/iMessage UI hints, and readable phone rendering in Control UI and human CLI status surfaces.

## Best Possible Solution

Keep formatting channel-owned and explicitly opt-in: either carry a narrow presentation capability in the gateway status payload and gate formatting on it, or leave generic gateway-status allowlists raw while retaining formatting in config-aware status surfaces.
