## Summary

## What This Changes

Make the Control UI general settings page render custom assistant avatars through the authenticated avatar-loading path used by chat.

## Best Possible Solution

Keep https://github.com/openclaw/openclaw/issues/107853 as the canonical report and fix Quick Settings by consuming the same authenticated blob avatar URL as chat, with coverage for token-authenticated and workspace-relative avatars.

## Solution Assessment

Yes, but it should be handled once in the canonical issue: reuse the existing authenticated avatar loader and blob URL rather than adding another settings-specific fetch implementation.
