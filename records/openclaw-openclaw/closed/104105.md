## Label Justifications

- `impact:security`: A write-scoped caller-controlled ref crosses a subprocess boundary and is interpreted as Git command options.

## Summary

The report is valid on current `main`: a write-scoped caller can supply an option-like base ref, Git accepts at least `--orphan` and `--lock`, and the latter produces a foreign-locked worktree that normal removal and idle cleanup preserve. The feature is newer than `v2026.6.11`, so this should remain open for a focused pre-release fix while security handling avoids further public exploit amplification.

## What This Changes

Prevent `sessions.create.worktreeBaseRef` from being parsed as `git worktree add` options, which can create unintended or cleanup-resistant managed worktrees.

## Best Possible Solution

Before managed worktrees ship, add `--` before the explicit base ref in both `git worktree add` attempts and add service regression coverage proving valid refs still succeed while option-like refs leave no branch, worktree directory, or registry record.
