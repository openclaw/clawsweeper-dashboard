## Summary

This issue remains necessary. Current main still feeds installed service environment back into restart, so a changed configured port is not propagated into the managed service definition; recent secret-preservation work also makes this a compatibility-sensitive shared lifecycle repair.

## What This Changes

Changing `gateway.port` followed by the documented managed Gateway restart leaves the macOS LaunchAgent command and environment on the previously installed port.

## Best Possible Solution

Build a typed shared restart-refresh plan that overlays canonical restart-required fields such as the Gateway port while preserving only explicitly allowed installed secrets and service identity, then rewrite and reload each platform service when its definition changes.
