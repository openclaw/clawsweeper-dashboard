## Summary

Current main and the v2026.6.11 tag already implement the requested xAI OAuth/profile-first behavior: Grok web_search returns OAuth provider auth before configured/API-key fallback, and x_search resolves the plugin auth profile before XAI_API_KEY when no explicit tool key is configured.

## What This Changes

Report asks xAI web_search and x_search to honor xAI OAuth auth order before falling back to XAI_API_KEY.

## Best Possible Solution

Keep the shipped OAuth-first/provider-profile-first implementation and track the separate implicit cross-provider xAI tool exposure concern in its own issue.

## Reproduction Assessment

No live xAI billing-console reproduction was run. Current main and the v2026.6.11 tag source/tests verify the expected OAuth/profile-first path, so the reported failure was not reproduced on the audited code.

## Solution Assessment

Yes. The shipped implementation is the maintainable fix because it uses the existing provider auth order and plugin auth context, with API-key fallback only when explicit config exists or OAuth/profile auth is unavailable or rejected.
