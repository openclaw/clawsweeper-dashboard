## Summary

Current main has a strong foundation for this request: cooperative gateway suspension already closes new work admission and pauses cron while transports and authenticated control paths remain alive. However, it deliberately refuses suspension while work is active, expires after two minutes, is process-local rather than persistent, and has no CLI or Signal operator trigger, so the requested incident-response capability remains materially unimplemented and requires an explicit security/product decision.

## What This Changes

Add a persisted global agent pause/abort control available through the CLI and an authorized Signal direct message while keeping channel transports alive.

## Best Possible Solution

Extend the canonical gateway suspension/admission lifecycle into an explicit operator safety state with defined abort, persistence, observability, recovery, and cron semantics; expose authenticated RPC and CLI controls first, then let Signal invoke that generic owner-authorized contract without placing global product policy or hard-coded command semantics in transport code.
