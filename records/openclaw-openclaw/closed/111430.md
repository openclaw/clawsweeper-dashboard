## Summary

Keep this PR open for a narrow safety correction and human review: it fixes the earlier non-card hosted-wizard guard, but it still treats a post-send gateway error as definitely rejected and can permit replay of an answer or nudge whose server-side effects may already have occurred.

## What This Changes

The branch adds a `wizardInputPending` gateway response fact, blocks Custodian nudges while any hosted-wizard input is awaited, and refines nudge delivery, health reconciliation, and closed-question Skip handling.

## Best Possible Solution

Keep all post-send failures in the existing no-replay/uncertain state unless the gateway exposes explicit proof that the handler did not execute, then add a real redacted hosted-wizard run showing a nudge remains blocked and a rejected pre-dispatch request remains retryable.
