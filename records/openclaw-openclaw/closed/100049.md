## Summary

Keep open: current main still has the Android Talk Mode realtime tool-completion race, and this newer PR is the proof-positive landing candidate for the same work older open PR https://github.com/openclaw/openclaw/pull/99968 attempted.

## What This Changes

The PR adds a dedicated lock around Android Talk Mode realtime tool-run state, dispatches cached completions after releasing the lock, bounds cached completions, and adds a regression test.

## Best Possible Solution

Use this newer proof-positive PR as the landing candidate for the Android realtime tool-completion race, then close or supersede the older unproven duplicate once maintainers choose the canonical path.

## Reproduction Assessment

Yes from source inspection: current main shares unsynchronized realtime tool-run maps between the Gateway chat event path and the tool-call response coroutine. I did not run a local failing race harness in this read-only review, but the PR body provides after-fix device proof for the claimed ordering.

## Solution Assessment

Yes; this is the narrow owner-boundary fix because Android owns the concurrent client-side map/set state, while the Gateway already exposes the needed tool-call and submitToolResult contract. A protocol or provider change would be broader than the source evidence requires.
