## Summary

Keep open: current main and v2026.6.11 still reject exact custom-scheme origins because the Gateway allowlist compares against `URL.origin`, which is `null` for the reported schemes. Two open linked pull requests already target this exact fix, so the issue should remain open until one lands or maintainers choose a canonical replacement.

## What This Changes

The issue requests that exact `gateway.controlUi.allowedOrigins` entries such as `tauri://localhost` and `electron://localhost` be accepted instead of forcing the wildcard origin workaround.

## Best Possible Solution

Land one narrow Gateway fix that reconstructs exact hosted opaque origins only for schemes with a protocol and host, adds source and handshake regression coverage, and keeps broader wildcard or pattern policy in the separate related issues.
