## Label Justifications

- `P1`: This is a beta regression in an active agent-control command that prevents users from steering a running task when the UI receives active-run state through `hasActiveRun`.
- `impact:message-loss`: The user's `/steer` message is rejected before it reaches the active run.
- `impact:session-state`: The failure comes from one Control UI path interpreting active session state differently from the shared `hasActiveRun` helper.

## Summary

Keep open: current main still rejects a beta-style active session row when `/steer` sees `hasActiveRun: true` without `status: "running"`, and an open closing PR already targets that exact regression.

## What This Changes

The issue reports a regression where Control UI `/steer` no longer recognizes an active run in 2026.7.1 beta 2 and returns the no-active-run message instead of injecting guidance.

## Best Possible Solution

Review and land or close https://github.com/openclaw/openclaw/pull/100803 so `/steer` uses the shared active-run predicate and has regression coverage for `hasActiveRun`-only session rows.

Yes. Source inspection shows a session row with `hasActiveRun: true` and no `status: "running"` reaches the `/steer` no-active-run branch on current main, matching the reporter's beta behavior.

## Solution Assessment

Yes. The narrow maintainable fix is to reuse `isSessionRunActive` in `/steer`, because that helper is already used by sibling run-lifecycle code and preserves terminal-status behavior.
