## Summary

Keep open: the patch is a useful partial optimization, but it is not merge-ready because it still sorts every matched task before paging, so the unfiltered Control UI recent-task request remains a full-registry clone/sort; the PR also conflicts with current main and lacks real behavior proof.

## What This Changes

The PR adds a task-registry `selectTaskRecords` helper and switches the gateway `tasks.list` handler to filter through it before sorting by task activity.

## Best Possible Solution

Implement a bounded task-registry/gateway listing helper that applies filters, selects only the requested updatedAt-ordered cursor window, and clones/maps that window while preserving the current `tasks.list` response and cursor semantics.
