## Summary

Keep open: this is a focused Android gateway bug-fix PR with useful evidence, but the proposed auto-connect guard still has a blocking race that can let stale cold-start auto-connect run under a newer explicit lifecycle intent.

## What This Changes

The PR changes Android NodeRuntime gateway auto-connect intent handling, GatewaySession fire-and-forget RPC watcher startup, and gateway bootstrap auth regression tests.

## Best Possible Solution

Land this after auto-connect uses the CAS-claimed lifecycle intent as the guard token, with a regression test that forces an explicit intent between the claim and guarded launch.

No, not yet. The GatewaySession ATOMIC watcher matches the coroutines contract, but the NodeRuntime fix must bind the claimed intent into the guarded launch instead of letting launchGatewayLifecycle sample a later explicit intent.
