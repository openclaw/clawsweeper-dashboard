## Summary

The process-RPC half is sound, but the streaming HTTP listener only suppresses the fatal event; it does not settle the pending response when stdout fails before headers, so the PR still needs a narrow lifecycle repair before merge.

## What This Changes

Adds no-op stdout/stderr error listeners to the Codex sandbox process-RPC and streaming-HTTP children, plus regression tests that assert the WebSocket bridge survives emitted pipe errors.

## Best Possible Solution

Handle streaming HTTP stdout/stderr errors inside the response owner so a pre-header failure settles exactly once, while child close remains authoritative for backend finalization and socket cleanup; retain the process-RPC no-op guards.
