Implement structured telemetry for successful Session Reaper sweeps. Add a generic typed diagnostic event at the core boundary in `src/infra/diagnostic-events.ts`, emit it from `src/cron/session-reaper.ts` only after the sweep completes successfully, and include the number of session entries actually pruned. Do not emit session keys, session IDs, store paths, agent IDs, or other high-cardinality or private values. Map the event into both `extensions/diagnostics-otel` and `extensions/diagnostics-prometheus` using clear semantics that distinguish sweep executions from rows pruned; update focused tests and the public OpenTelemetry and Prometheus metric catalogs. Add core regression coverage for positive pruning and ensure throttled, disabled, failed, and zero-prune paths do not falsely report successful removals. Do not add config, environment variables, a parallel metrics subsystem, or `CHANGELOG.md` changes. Validate focused core and exporter tests plus changed-file checks.
