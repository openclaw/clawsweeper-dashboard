## Summary

Keep open: current main still defaults the bundled Codex app-server to an isolated per-agent home, and the requested opt-in native user-home/thread-management mode remains a protected product/config decision rather than already implemented behavior.

## What This Changes

The issue asks for an explicit opt-in Codex user-home mode plus owner-only native thread listing, reading, forking, renaming, archiving, and unarchiving so OpenClaw and native Codex surfaces can safely share threads.

## Best Possible Solution

Design a maintainer-approved, default-off Codex user-home mode in the bundled Codex plugin, keep isolated per-agent homes as the upgrade-safe default, and implement native-thread controls against current Codex v2 APIs with owner-only authorization, fork-first continuation, tests, docs, and live proof.
