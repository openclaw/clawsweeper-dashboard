## Summary

Keep open: current main still has the exact required-completion blocked finalization shape when a yielded run reaches completion handling without the `sessions_yield` pause marker, and no merged or open PR directly owns this exact first-turn required-completion failure.

## What This Changes

The issue reports that a required-completion subagent spawned with `sessions_spawn(mode:"run")` can finalize as blocked at its first `sessions_yield` turn, losing the later real final reply announcement.

## Best Possible Solution

Harden the subagent lifecycle so a required-completion run that ended via `sessions_yield` cannot publish a blocked terminal state until its resumed run has produced, captured, and announced the real final assistant reply.
