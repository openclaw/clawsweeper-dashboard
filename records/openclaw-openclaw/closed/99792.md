## What This Changes

## Best Possible Solution

## Reproduction Assessment

Yes. Source inspection shows current main still calls unbounded `response.json()` on both Feishu streaming-card success paths, and the PR body includes after-fix terminal output showing an 18 MiB stream rejected and canceled at the 16 MiB cap.

## Solution Assessment

Yes. Using the existing `readProviderJsonResponse` helper is the narrowest maintainable fix for these success reads, and the added `try/finally` preserves the guarded-fetch release contract on overflow or malformed JSON.
