## What This Changes

## Best Possible Solution

Handle output-stream errors according to whether the stream is data or diagnostic: settle ERROR or unreadable entries and stop tar for archive/listing stdout, keep no-op only where child close truly remains authoritative, then add focused regression coverage and redacted real dir.fetch proof.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P2] Fail archive stdout errors instead of swallowing them:** `extensions/file-transfer/src/node-host/dir-fetch.ts:279`
  - body: `handleDirFetch` builds the returned archive from `child.stdout` and resolves `Buffer.concat(chunks)` on `close`. With this no-op listener, a stdout read failure can leave partial chunks and still return an `ok: true` tar payload if the child exits 0; treat the stream error as `ERROR` and stop the child instead.
  - confidence: 0.88
- **[P3] Do not report partial tar listing output as entries:** `extensions/file-transfer/src/node-host/dir-fetch.ts:112`
  - body: `listTarEntries` uses stdout as the returned entry list. Swallowing a stdout `error` can let `close` resolve whatever partial lines were read, so `fileCount` and `entries` can be wrong; resolve the listing as unreadable or empty and stop tar instead of treating child close as authoritative.
  - confidence: 0.82
