## Summary

Keep open. Current main still spawns and unrefs the detached gateway respawn child without a ChildProcess error listener, and a direct Node probe confirms that an asynchronous spawn failure can terminate the parent process unless that listener is attached.

## What This Changes

The issue asks OpenClaw to harden detached gateway respawn so asynchronous child-process spawn failures do not crash the parent Node process.

## Best Possible Solution

Attach a best-effort child error handler in spawnDetachedGatewayProcess before unref, preserve the existing detached respawn semantics, and add a focused regression test for an asynchronously emitted child error.
