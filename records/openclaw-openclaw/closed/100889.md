## Summary

Keep open: current main still has the unbounded browser-control HTTP success `res.json()` path, and this PR applies the existing bounded-reader pattern with focused regression coverage and real loopback proof. I found no blocking code or security findings, but the new fail-closed behavior for oversized success payloads is a maintainer-visible compatibility choice before merge.

## What This Changes

The PR caps successful browser-control HTTP JSON responses at 16 MiB with `readResponseWithLimit` and adds a loopback HTTP regression test for oversized 2xx responses.

## Best Possible Solution

Land the bounded success-reader fix if maintainers accept 16 MiB as the browser-control HTTP success JSON contract, keeping the cap local to the browser client transport and preserving normal small-response behavior.
