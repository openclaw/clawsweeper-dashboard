## Label Justifications

- `P1`: Current `main` can silently lose an already accepted Signal message when monitor shutdown races with its immediate dispatch path.

## Summary

This PR remains necessary: current `main` can suppress an already accepted Signal event when shutdown lands before its immediate debounce flush. The implementation matches the existing debouncer and monitor ownership contracts, with no actionable correctness or security finding.

## What This Changes

The branch tracks Signal entries while their debounce enqueue call is active so accepted immediate and overflow flushes drain during shutdown while timer-buffered flushes and conflict retries remain canceled.

## Best Possible Solution

Keep the lifecycle distinction inside Signal, land it with the explicit immediate-drain and delayed-cancel regressions, and let exact-head CI gate the final merge.

Required: false

## Reproduction Assessment

Yes at source level: current `main` suppresses an accepted immediate Signal flush after same-tick abort, and the added production monitor-boundary regression directly exercises that race. I did not execute the test locally because this review was required to remain read-only.

## Solution Assessment

Yes. The active-enqueue marker is the narrowest maintainable fix because it follows the existing debouncer's ownership distinction, stays within the Signal plugin boundary, and preserves shutdown cancellation for delayed and retry work.
