## Summary

Keep open: current main and the latest release still do not turn assistant chat finals into native iOS APNs alerts, while background Talk remains a policy-sensitive best-effort or paused/resume behavior rather than a settled background-audio path.

## What This Changes

Request native iOS APNs notifications for assistant messages and a background Talk-mode behavior instead of foreground-only operation.

## Best Possible Solution

Define a dedicated privacy-safe assistant-reply APNs contract with generic default content, explicit preview opt-in if maintainers want previews, correct chat tap routing, and live iOS proof; keep background Talk best-effort or paused/resumable unless maintainers approve broader background audio behavior.
