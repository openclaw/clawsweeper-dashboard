## Summary

Keep open: current main and the latest release still have the reported Claude bundle-MCP mismatch, and the protected `maintainer` label blocks conservative cleanup closing. Source inspection shows the bundle helper treats `--mcp-config` as one value while the Anthropic CLI arg model treats it as variadic, so a valid multi-config setup can still leave stray positional args and skip later user server configs.

## What This Changes

The issue asks OpenClaw to handle Claude CLI variadic `--mcp-config` values consistently when stripping/injecting strict bundle-MCP args and merging user config files.

## Best Possible Solution

Add a narrow Claude arg-shape helper that collects and strips all `--mcp-config` values, merge every referenced config in order for args and resume args, and cover the variadic case with focused bundle-MCP tests.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: configure `claude-cli` backend args with `--mcp-config a.json b.json` and the current helper will consume only `a.json`, leave `b.json`, and merge only the first file. I did not run the test path because this review was read-only.

## Solution Assessment

Yes, the requested shared Claude arg-shape repair is the best direction because it makes the bundle-MCP path follow the existing Anthropic CLI variadic flag model instead of adding a second special case.
