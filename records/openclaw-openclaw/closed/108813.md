## Label Justifications

- `P0`: Current-main Discord voice admission can grant non-owner speakers access to owner-only core tools, crossing a security authority boundary.
- `merge-risk: 🚨 compatibility`: The hardening intentionally removes owner authority from existing account and legacy DM voice allowlists, so affected beta/current-main configurations may require an explicit `commands.ownerAllowFrom` entry.

## Summary

Keep open for landing: current main still lets Discord voice admission allowlists confer owner authority, while the updated branch cleanly separates admission from ownership. The prior wildcard-admission regression is fixed, and the new gateway live-output proof is sufficient; only the intentional beta compatibility change and normal draft/base refresh remain.

## What This Changes

The PR separates Discord voice access allowlists from owner-authority allowlists for `/vc` commands and voice transcript turns.

## Best Possible Solution

Keep Discord voice admission and owner authority as separate facts, use `commands.ownerAllowFrom` as the sole explicit owner source, preserve normalized account wildcard admission, then rebase and land the focused hardening with its docs and regression coverage.
