## Summary

Keep this PR open for a compatibility repair: its macOS one-shot workaround rewrites an explicit `NODE_USE_SYSTEM_CA=1` opt-in to `0`, which can break documented Keychain-only private-CA setups. The `maintainer` label also requires explicit maintainer handling rather than automated cleanup.

## What This Changes

The branch makes macOS non-interactive CLI respawns use Node’s OpenSSL-backed CA store by default and adds respawn-plan and gateway-backed process-exit regression tests.

## Best Possible Solution

Preserve an explicit operator system-CA opt-in while bypassing Keychain loading only when OpenClaw can prove the value came from its own macOS default; add focused coverage for both paths and rerun real macOS one-shot proof against a Keychain-only CA.
