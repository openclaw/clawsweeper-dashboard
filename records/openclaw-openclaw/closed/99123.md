## Summary

Keep open: current main still lets missing-role chat-event text reach Android voice extraction, and this PR targets the right helper with a focused regression test, but it needs real Android voice/TTS proof before merge.

## What This Changes

The PR changes Android voice chat-event parsing to require an explicit assistant role and adds a regression test for missing-role messages.

## Best Possible Solution

Land the narrow helper fix after redacted real Android voice/TTS proof shows a missing-role chat event does not trigger spoken output, with the focused regression test kept.

## Reproduction Assessment

Yes, source-reproducible: on current main, a payload with message.content and no message.role reaches textFromContent because the helper only rejects non-null non-assistant roles. I did not run the Gradle test in this read-only checkout.

## Solution Assessment

Yes: centralizing the stricter role check in ChatEventText covers both MicCaptureManager and TalkModeManager callers without adding duplicate TTS gates. The remaining blocker is proof from a real Android voice/TTS path, not a different code shape.
