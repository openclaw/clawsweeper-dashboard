## Summary

Current main still fails the reported path: an ACP spawn can persist a gateway-derived thinking default, while codex-acp conditionally omits any reasoning config option and acpx forwards only advertised keys, causing the manager to reject the session before its first turn. The issue is still necessary and is a narrow regression candidate rather than a duplicate of the model-specific Claude Haiku report.

## What This Changes

Fix ACP session startup so gateway-derived thinking or effort defaults do not fail acpx sessions when the active adapter does not advertise a compatible reasoning option.

## Best Possible Solution

Carry whether ACP tuning was automatically derived or explicitly requested, apply automatic reasoning defaults only through an advertised compatible key, and preserve strict explicit controls and existing timeout semantics.

## Solution Assessment

No. The proposed unconditional shared-loop skip is too broad; the repair should distinguish automatic defaults from explicit controls and map only to the adapter's advertised native reasoning key.
