## Summary

Keep open: current main and the latest release still have the resolver/dispatcher path that can turn a job-level channel-shaped failure destination into an inherited webhook route, and no merged or open canonical fix was found.

## What This Changes

The issue reports that a cron job's channel-shaped `delivery.failureDestination` without `mode` can inherit a global webhook `cron.failureDestination.mode` and silently drop the failure notification.

## Best Possible Solution

Normalize channel-shaped job-level failure destinations without `mode` to announce before global webhook mode can be reused, with focused resolver and dispatcher regression coverage.

## Solution Assessment

Yes, a narrow resolver fix is the best direction: default the channel-shaped job override to announce without weakening existing partial-inheritance and clear-field behavior.
