## Summary

Keep open: current main and the latest release still classify Codex abort markers by exact private guidance prose, while the pinned Codex app-server protocol exposes structured turn completion status. The protected maintainer label also prevents conservative cleanup closure.

## What This Changes

The issue asks OpenClaw to stop classifying Codex turn aborts by matching private Codex guidance prose and instead use structured `turn/completed` status and error fields.

## Best Possible Solution

Use `turn/completed` `Turn.status` and `Turn.error` as the abort/failure source of truth, with any replay-marker fallback keyed to marker shape rather than private guidance prose.

## Reproduction Assessment

Yes, at source level: current main still performs strict equality against copied guidance prose in the Codex app-server notification path, and upstream Codex source shows that prose is crate-private. No live Codex interruption was exercised in this read-only review.

## Solution Assessment

Yes: deriving abort/failure classification from structured `turn/completed` status/error is narrower and more stable than depending on private Codex wording, with a marker-shape fallback only if replayed history proves it necessary.
