## Summary

The issue is a confirmed current-main Control UI race, not implemented or superseded: an obsolete repository request can reject after a newer request succeeds and erase the newer branch options. The report should remain open for a focused maintainer-owned fix because the `maintainer` label is protected.

## What This Changes

Prevent a stale failed Worktrees branch lookup from clearing branch options loaded for the repository currently shown in the Control UI form.

## Best Possible Solution

Use one repository-aware current-request predicate for both fulfillment and rejection, then add a deferred two-request test proving an older failure cannot erase a newer repository's successful branch result.
