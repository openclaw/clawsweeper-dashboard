## Label Justifications

- `P1`: A deterministic reconnect resets the visible iOS conversation and breaks the mobile new-chat workflow for affected users.
- `impact:session-state`: The app loses its focused session association even though the gateway session and transcript remain intact.
- `impact:ux-friction`: Users must discover and reopen the hidden conversation through Control → Activity after every affected reconnect.

## Summary

Close as an exact duplicate of the earlier canonical report, which describes the same iOS new-chat selection loss after backgrounding and reconnecting on v2026.7.1; the detailed source tracing here should be preserved on that issue.

## What This Changes

Fix the iOS app so a newly focused chat remains selected after a same-gateway reconnect instead of falling back to the main session.

## Best Possible Solution

Keep https://github.com/openclaw/openclaw/issues/108233 as the canonical report, carry over this issue's precise source analysis, and fix the iOS owner boundary by retaining the focused session across same-gateway reconnects while clearing it on gateway or agent changes and deleted sessions, with focused tests and real device background/reconnect proof.
