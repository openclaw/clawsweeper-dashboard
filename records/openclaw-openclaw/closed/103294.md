## Summary

Keep this PR open, but do not merge it yet: the SQLite direction is sound, while unresolved concurrent snapshot writes can lose subscriptions, concurrent first-use key creation can rotate VAPID identity, and the fail-closed startup migration needs an explicit maintainer decision.

## What This Changes

The PR moves Web Push subscriptions and VAPID keys from legacy JSON files into the shared SQLite state database, adds startup migration and archival, and updates focused tests.

## Best Possible Solution

Use row-level transactional subscription mutations and an atomic insert-or-read VAPID helper, settle whether legacy import is doctor-owned or an explicitly approved startup exception, then demonstrate both fresh and upgrade behavior through an exact-head gateway run.
