## Summary

Keep open: current main has the sandbox primitives this issue cites, but it does not implement the requested opt-in session-owned lifecycle cleanup contract, and the protected maintainer label plus new config/destructive cleanup semantics require maintainer direction.

## What This Changes

The issue requests an opt-in session-owned sandbox lifecycle that deterministically reuses session-scoped sandboxes and cleans runtime, browser, registry, and non-shared workspace state when the owner resets, deletes, or reaches terminal cleanup.

## Best Possible Solution

Keep this open as a maintainer-directed core sandbox design: define an opt-in lifecycle policy, wire it through existing registry/backend/recreate primitives, and cover reset/delete/terminal child cleanup plus docs and upgrade-safe config behavior.

## Reproduction Assessment

## Solution Assessment

No, current main is not the full solution; it only provides scope, prune, recreate, registry, and separate session cleanup primitives. The best fix needs a maintainer-approved opt-in lifecycle contract built on those primitives, not an unconditional cleanup change.
