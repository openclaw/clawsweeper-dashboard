- `maturity:stable`: The issue affects `macos-gateway-host`, which is scored M4 Stable with quality 74 and completeness 88 in `qa/maturity-scores.yaml`.

## Summary

Keep open: current `main` and latest release still have the standalone macOS CLI reading and writing the home config path when only `OPENCLAW_STATE_DIR` is set, while the app, Node launcher, tests, and docs already treat `$OPENCLAW_STATE_DIR/openclaw.json` as the active config path.

## What This Changes

The issue requests that `openclaw-mac configure-remote`, `connect`, and `wizard` resolve config as `OPENCLAW_CONFIG_PATH`, then `OPENCLAW_STATE_DIR/openclaw.json`, then `~/.openclaw/openclaw.json`.

## Best Possible Solution

Add a small shared resolver for the standalone macOS CLI that matches the existing app and Node path precedence, then cover state-dir reads, state-dir writes, and explicit config-path precedence with Swift tests.

## Reproduction Assessment

Yes, from source inspection: with `OPENCLAW_STATE_DIR` set and `OPENCLAW_CONFIG_PATH` unset, the standalone CLI still resolves `loadGatewayConfig()` and `configureRemote()` to `~/.openclaw/openclaw.json`. I did not run the macOS binary in this read-only review.

## Solution Assessment

Yes, the best fix is a narrow resolver alignment in the standalone macOS CLI, not a new config option or product change. The closed linked PR has the right general shape but is not merged, so the issue remains actionable.
