## Summary

Keep this open for maintainer review: current main and the latest release still hydrate visible Telegram reply-chain media without a self-authored guard, while current tests explicitly expect bot-authored reply media to hydrate when visibility allows it. The linked open closing PR is dirty and targets older resolver/file names, so this needs a Telegram reply-media contract decision before a new repair is safe.

## What This Changes

The issue reports that Telegram reply handling can hydrate media from a bot-authored replied-to message as if it were an inbound user attachment.

## Best Possible Solution

Make the Telegram reply-chain media contract explicit, then either land a current-main guard with bot-authored and user-authored reply-media tests or close this as intended behavior with the current test contract cited.
