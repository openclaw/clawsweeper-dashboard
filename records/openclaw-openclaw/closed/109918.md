## Label Justifications

- `P1`: Busy Slack deployments can accumulate unbounded durable session rows and repeatedly run ineffective maintenance, causing substantial gateway-wide latency.
- `impact:session-state`: The issue concerns unbounded persisted channel/thread session rows and the retention rules governing conversation state.

## Summary

This report is a high-quality reproduction of the same durable Slack conversation-pointer retention gap already tracked by the older, broader canonical issue, which also covers impossible-cap write churn and remains open for the required retention-policy decision.

## What This Changes

Make inactive Slack channel and thread sessions eligible for bounded maintenance, and report when protected rows prevent configured pruning or entry caps from being enforced.

## Best Possible Solution

Keep https://github.com/openclaw/openclaw/issues/107750 as the single decision surface, preserve active durable conversation pointers, add a bounded retirement policy for inactive pointers, and stop or clearly warn about cap passes that cannot remove any eligible row.
