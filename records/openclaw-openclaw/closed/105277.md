## Summary

The retry bug is valid, but this patch retries at the wrong lifecycle boundary. The update flow invokes the helper again after phases that may mutate config, so a later retry can produce a rollback snapshot of the modified state rather than the original pre-update state. The contribution is narrowly repairable, but should not merge or be closed as superseded until one candidate proves correct behavior across the full update path.

## What This Changes

Moves pre-update snapshot deduplication marking until after a successful write and adds a regression test for retrying after a transient read failure.

## Best Possible Solution

Own snapshot creation and bounded retry at one pre-mutation update boundary, carry that result through later phases, and prohibit restart or post-doctor paths from recapturing changed config.
