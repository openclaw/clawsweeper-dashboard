## Summary

Keep this issue open. Current main and the latest release still do not make classic `streaming.enabled` transcription work for Telnyx: Telnyx only receives `stream_url` on the separate `realtime.enabled` path, while the classic streaming handler remains Twilio-shaped and setup still reports streaming as enabled for the unsupported provider combination.

## What This Changes

The issue reports that Telnyx inbound conversation mode with `streaming.enabled` and Deepgram never starts audio streaming, so no transcription or agent session begins after the greeting.

## Best Possible Solution

Make classic Telnyx streaming transcription explicit and safe: either implement Telnyx media streaming into the realtime-transcription provider path with live Telnyx proof, or fail setup/config for that unsupported combination and point users to supported Telnyx realtime or native transcription paths.

## Reproduction Assessment

Yes at source level: current main only passes Telnyx `streamUrl` when `realtime.enabled` is true, while the classic `streaming.enabled` media handler parses Twilio start/media frames. I did not run a live Telnyx call in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product behavior. The narrow safe outcome is either real Telnyx classic streaming support with live carrier proof or an explicit setup/config rejection that stops users from deploying an unsupported streaming mode.
