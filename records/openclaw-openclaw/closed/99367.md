## Summary

Current main still has a source-visible heredoc parsing bug: `summarizeExecCommand` splits the whole command into top-level stages before heredoc compaction, so body text containing shell-like separators can be displayed as extra executed stages. This should stay open as a narrow core display bug rather than being closed with the adjacent literal-newline issue or cron-shell summary work.

## What This Changes

The issue requests that exec command display summaries treat heredoc bodies as data and summarize only the launcher command line, with declined approvals shown as declined when that status is available.

## Best Possible Solution

Fix the exec display summarizer to detect heredoc redirects before top-level stage splitting, summarize only the launcher line, and add regression coverage for heredoc bodies containing JS/YAML/shell-like separators.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: a heredoc command whose body contains top-level `;`, `&&`, or `||` reaches `splitTopLevelStages(cleaned)` before heredoc compaction, so body fragments can become displayed stages. I did not run a live failing test because this review is read-only.

## Solution Assessment

Yes, the narrowest maintainable fix is to make heredoc detection happen before stage splitting in the existing exec display summarizer, with focused tests; broad channel rewrites or a new display system are not needed for the central bug.
