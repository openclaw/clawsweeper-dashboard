## Summary

The reported WhatsApp message-loss and redelivery loop is fixed on current main: reply-session initialization conflicts are classified as retryable, so the failed inbound is not marked read or finalized and the same message ID can succeed on redelivery. The broader core conflict remains separately tracked by https://github.com/openclaw/openclaw/issues/102400.

## What This Changes

Prevent WhatsApp follow-up messages from being silently finalized when reply-session initialization conflicts during an active run.

## Best Possible Solution

Keep the current WhatsApp retry classification and delayed read/finalization behavior, then resolve the remaining cross-channel initialization race through https://github.com/openclaw/openclaw/issues/102400 rather than reopening a duplicate WhatsApp repair path.
