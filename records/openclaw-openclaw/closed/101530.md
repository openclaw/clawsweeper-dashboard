## Summary

Keep open: current main still lacks an error listener on the detached launchd restart handoff child, and this PR is a focused, plausible fix with no blocking correctness finding. The main residual gap is that the test changes update mocks but do not assert listener registration or listener-before-unref ordering.

## What This Changes

The PR adds a no-op `ChildProcess` error listener before `unref()` in the macOS launchd restart handoff and updates the handoff tests' spawn mocks to include `on`.

## Best Possible Solution

Land the focused listener-before-unref fix if exact-head checks remain green, preferably with a small assertion that the handoff registers the `error` listener before `unref()`.

## Reproduction Assessment

Yes, at source level. Current main spawns the detached launchd helper and calls `unref()` without an `error` listener, and a Node 24.18.0 source/runtime check confirms missing executables report through an async child `error` event rather than the surrounding try/catch.

## Solution Assessment

Yes, this is the narrowest maintainable fix for the fire-and-forget handoff: attach a child `error` listener immediately after `spawn()` and before `unref()`. A broader spawn wrapper or launchd flow rewrite would be more invasive than this failure mode requires.
