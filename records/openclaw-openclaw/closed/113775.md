## What This Changes

This PR splits Mattermost’s inbound monitor into focused setup, post-processing, interaction, reaction, reply-turn, and shared-context modules while retaining `monitor.ts` as the runtime facade.

## System Context

Mattermost websocket and HTTP callback events enter the bundled Mattermost channel plugin, which authorizes and normalizes them into OpenClaw inbound turns before the shared reply pipeline delivers messages, previews, and reactions back to Mattermost. The refactor divides that transport lifecycle into smaller modules without intending to change the surrounding plugin SDK contracts.
