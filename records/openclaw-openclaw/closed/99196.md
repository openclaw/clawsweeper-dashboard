## Summary

Keep open: the PR targets a real source-reproducible plugin discovery bug, but the patch is not safe as written because it re-enters full plugin discovery and loses installed-index scoping semantics.

## What This Changes

The PR changes installed-index manifest registry reconstruction to rediscover `plugins.load.paths` candidates and append them to index-derived candidates.

## Best Possible Solution

Keep the persisted-index fast path, add only configured load-path/workspace candidates with existing plugin-id scoping, and back it with regression plus real setup proof.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: current main's installed-index branch passes only index candidates, and `loadPluginManifestRegistry` skips discovery when candidates are supplied; no live managed-install proof was run in this read-only review.

## Solution Assessment

Is this the best way to solve the issue? No: the fix belongs in installed-index registry construction, but this implementation uses full discovery and drops scoped semantics; the safer shape is configured-only discovery plus plugin-id filtering.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Limit extra discovery to configured candidates:** `src/plugins/manifest-registry-installed.ts:636-639`
  - body: This calls full `discoverOpenClawPlugins` whenever `plugins.load.paths` is nonempty. That helper also scans bundled and global roots, and this filter only removes roots already in the index, so unindexed bundled/global plugins can be appended to the installed-index registry. The repair should discover only the configured/workspace load-path scope or keep the persisted index as the source of truth for shared roots.
  - confidence: 0.89
- **[P2] Preserve pluginId scoping for load-path candidates:** `src/plugins/manifest-registry-installed.ts:641-642`
  - body: The existing installed-index path filters both diagnostics and index candidates by `pluginIds` before loading the registry, but added `extraCandidates` are filtered only by `rootDir`. Scoped callers such as provider or metadata requests can therefore receive unrelated load-path plugins whenever one configured path exists. Filter discovered candidates by the requested plugin ids or apply the scope after manifest load.
  - confidence: 0.84
