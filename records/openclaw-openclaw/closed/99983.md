## Summary

Keep open: current main and the latest release still build the session-maintenance warning dedupe key with `.filter(Boolean)`. The `undefined` example is outside the current warning type contract, but source inspection still shows a zero-slot fragility and no regression test for changed warning contexts.

## What This Changes

The issue asks OpenClaw to make session-maintenance warning dedupe keys positional and type-stable so changed warning limits do not get suppressed as duplicates.

## Best Possible Solution

Keep the warning delivery path and change only the private context-key encoder plus a focused regression test so every field position is encoded deterministically without adding config or compatibility surface.

## Reproduction Assessment

## Solution Assessment

Yes: a positional string encoding inside `buildWarningContext` is the narrowest maintainable fix, with one regression test in the existing warning test file.
