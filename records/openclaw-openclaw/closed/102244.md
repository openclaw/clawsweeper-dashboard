- `impact:session-state`: The reported corruption is written into the persisted session transcript and replayed on subsequent turns.

## Summary

Keep this open: current main and the latest shipped release still have the redaction-idempotency gate that can reject preservation for credential-looking opaque provider signatures, and the remaining fix needs a maintainer-owned security-boundary choice.

## What This Changes

The issue reports that transcript secret redaction can rewrite provider-owned Anthropic/Bedrock reasoning signatures when opaque base64 happens to match credential patterns, poisoning persisted session replay.

## Best Possible Solution

Preserve provider-minted opaque replay signatures only in tightly scoped signed-thinking fields, keep ordinary credential redaction intact elsewhere, and drop or repair already-poisoned Bedrock/Anthropic thinking blocks before replay.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: For provider-minted signed-thinking fields, should OpenClaw preserve structurally valid opaque replay tokens even when their bytes contain credential-shaped substrings, or keep the current redaction-idempotency gate and harden patterns/replay recovery around it?

Rationale: The current tests deliberately redact credential-shaped provider signature fields, but this report shows that policy can corrupt real opaque replay tokens; choosing the transcript redaction exemption boundary is security-sensitive maintainer intent.

Likely owner: toruvieI

Owner reason: This person authored the merged route-bound opaque reasoning preservation behavior being reconsidered.

Owner confidence: medium

Options:

- **Scoped Structural Preservation (recommended):** Preserve valid opaque signatures only when route, block type, field name, and token shape prove the value is provider-owned replay metadata, then add focused repair coverage for corrupted persisted blocks.
- **Pattern-Only Hardening:** Make vendor-prefix detectors stricter and case-sensitive while keeping the current rule that credential-looking provider signatures are redacted.
- **Replay Recovery Only:** Leave transcript redaction unchanged and add send-side or repair stripping for ellipsis-corrupted Bedrock/Anthropic thinking blocks.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 still preserve provider signature fields only after `isOpaqueReplayToken` passes, and that predicate fails when `redactSensitiveText` changes the value. I did not run live Bedrock traffic in this read-only review.

## Solution Assessment

Unclear as an implementation until the security boundary is chosen; the strongest direction is scoped structural preservation for provider-owned replay signatures plus a replay/repair guard for already-corrupted blocks.
