## Review Findings

Overall confidence: 0.88

Full review comments:

- **[P1] Delay marking event ids until the message resolves:** `extensions/clickclack/src/gateway.ts:131`
  - body: `processEvent` records `params.event.id` before `resolveEventMessage` runs. If the message lookup temporarily returns `null` because ClickClack has not made the message visible in the narrow fetch window yet, this returns without dispatching but leaves the event id suppressed, so a later websocket replay of the same live event is dropped for the rest of the process. Keep the early duplicate check, but only add the event id after the event has reached an intentional terminal state, and cover the null-then-replay case.
  - confidence: 0.9
