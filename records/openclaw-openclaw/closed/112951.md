## Summary

This PR remains necessary: current main has the earlier non-blocking PASSIVE checkpoint behavior, while this branch adds the missing bounded-retention behavior for a WAL file that was temporarily forced to grow. The central implementation, real SQLite before/after measurements in the PR body, focused regression coverage, and green exact-head CI support the 64 MiB fixed ceiling; the remaining maintainer-visible choice is accepting its intentional retention/performance trade-off across managed SQLite databases.

## What This Changes

The PR configures a 64 MiB SQLite WAL retained-file limit in shared database maintenance, adds regression and durable-pragma coverage, and documents when reclaimed file space becomes visible.

## System Context

OpenClaw opens several local SQLite databases for shared state, per-agent state, tasks, plugins, memory, and related services. Their common WAL-maintenance helper configures each database's journaling behavior; this change bounds retained WAL file size after checkpoint/reset activity without restoring the blocking periodic checkpoint policy.

## Best Possible Solution

Keep the fixed, non-configurable 64 MiB limit in the shared WAL-maintenance helper, retain the documented PASSIVE periodic-checkpoint policy, and merge once maintainers accept the bounded-retention versus file-reuse trade-off.
