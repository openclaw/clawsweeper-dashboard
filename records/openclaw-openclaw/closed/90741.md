## Summary

Current main still uses mtime-based models-config freshness, so the central optimization is not obsolete and this PR remains useful. It should stay open, but the exact head retains a blocking synchronous SQLite contention path and its runtime proof predates the latest conflict-resolution merge.

## What This Changes

The PR replaces mtime-based models-config freshness with canonical SQLite/content fingerprints, adds provider/model-scoped structural short-circuits, validates generated plugin catalogs, and disables persisted catalog caching when source state is uncacheable.

## Best Possible Solution

Keep the canonical SQLite/content fingerprint and structural-validation design, but make lock contention fail fast to an uncacheable cache miss or move the read off the event loop, then provide exact-head runtime proof for warm reuse, restart/upgrade, corrupt state, and contended state.
