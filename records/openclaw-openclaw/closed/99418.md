## What This Changes

The PR adds a NaN fallback to `loadSessionLogs` when top-level transcript timestamps fail `Date` parsing.

## Best Possible Solution

Land one canonical linked PR that adds a braced guard or reuses `parseTimestamp`, includes focused `loadSessionLogs` regression proof, and then close the duplicate candidate PR.

## Reproduction Assessment

Yes at source level: current main directly assigns `new Date(parsed.timestamp).getTime()` in `loadSessionLogs`, so an invalid string can produce `NaN` before the gateway sends logs. I did not run a full session-file gateway repro in this read-only review.

## Solution Assessment
