## Summary

Keep open: current main has doctor stale-lock cleanup and gateway health primitives, but the one-click installer wrappers still run non-fixing doctor checks, treat gateway probes mostly as best-effort, and do not surface a stale-lock recovery path from the wrapper flow.

## What This Changes

Requests follow-up hardening of one-click install/update wrappers so stale gateway/session locks and half-started gateways produce recovery guidance and a documented post-install health check.

## Best Possible Solution

Define a default-safe installer health/recovery policy that reuses existing doctor and status seams, surfaces stale-lock repair guidance, and documents the post-install verification path without hiding security or state-repair decisions.

## Reproduction Assessment

No high-confidence live stale-lock installer reproduction was established in this read-only review. Source inspection does show the current wrappers use best-effort/non-fixing checks and do not route stale-lock recovery clearly through the one-click flow.

## Solution Assessment

Unclear until maintainers choose the installer default posture. The maintainable direction is to reuse existing `doctor --fix` and gateway status paths, but current wrappers do not yet make that recovery path obvious.
