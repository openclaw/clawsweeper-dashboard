## Label Justifications

- `P1`: The issue affects real multi-account gateway/channel deployments by disconnecting unaffected channel accounts during account-scoped config writes.
- `impact:message-loss`: Whole-channel restarts can suppress or disrupt message delivery for accounts whose config did not change, and the canonical related report includes failed final replies on this path.
- `maturity:stable`: The issue affects Gateway runtime / config reload behavior, and the maturity helper reports `gateway-runtime` as M4 Stable.

## Summary

Keep open: current main still collapses account-scoped channel config writes into whole-channel restarts, and the same-author implementation PR is open rather than merged.

## What This Changes

The issue asks for config hot reload to restart only changed channel accounts for `channels.{kind}.accounts.{accountId}.*` paths while preserving whole-channel restarts for channel-global changes.

## Best Possible Solution

Land one canonical generic reload-planner fix that carries `(channel, accountId)` restart targets through the gateway handler, while keeping whole-channel restarts for default-account, channel-global, mixed, removed, or non-canonical account changes.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: an account-scoped Mattermost path matches the broad channel reload prefix, becomes a `restartChannels` entry, and the handler restarts the whole channel.

## Solution Assessment

Is this the best way to solve the issue? Yes; carrying account-scoped restart targets through the generic gateway planner and handler is the narrow maintainable fix because channel lifecycle already accepts account ids.
