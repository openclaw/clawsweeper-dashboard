- `impact:message-loss`: Premature prepare readiness can allow host suspension before the requested cron continuation wake is durably recovered.

- `maturity:stable`: The affected Gateway Lifecycle surface belongs to the M4 Stable `gateway-runtime` feature.

## Summary

Current main still launches cron-continuation settlement recovery as detached work after the admitted agent run settles, so Gateway prepare can miss the pending retry. The issue is a focused, valid lifecycle regression, but its protected `maintainer` label and active assignment require maintainer handling rather than automated cleanup.

## What This Changes

Fix delayed cron-continuation settlement recovery so it remains admitted as independent Gateway work during lifecycle prepare.

## Best Possible Solution

Run the complete delayed settlement-recovery lifecycle under the existing independent Gateway root-continuation primitive, retain the generation-rotation stop rule, and add a deterministic test proving prepare stays busy until recovery succeeds, exhausts, or releases.
