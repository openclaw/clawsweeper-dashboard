## Label Justifications

- `P1`: A deterministic regression prevents operators from cancelling active cron scripts and can allow stale side effects after a gateway restart.
- `impact:message-loss`: A retired script result can still enqueue notify or wake effects into a newer scheduler generation.
- `impact:other`: The same lifecycle gap leaves hung detached cron work running beyond operator cancellation and restart boundaries.

## Summary

Keep this regression open. Current `main` is the reported failing baseline, and two open pull requests explicitly propose fixes; the protected `maintainer` label requires explicit maintainer handling rather than automated cleanup. The broader linked PR appears to cover both cancellation and scheduler-generation stale-result ownership, while the narrower PR addresses only part of that boundary.

## What This Changes

Fix main-target cron script jobs so task cancellation and scheduler restart retire detached script executions and prevent stale notify or wake side effects.

## Best Possible Solution

Adopt one canonical cron repair that classifies script payloads as detached execution across cancellation, restart, and completion paths, then add focused regression coverage for abort-ignoring late results and scheduler-generation retirement.
