## Summary

Keep this PR open for maintainer handling. The gateway-owned layout is a coherent direction, but the new required native protocol fields can make a newly updated Swift client fail against an older gateway; the submitted mock-harness screenshots also do not prove real gateway persistence or reconnection behavior.

## What This Changes

The PR stores the Control UI sidebar’s built-in and custom section order in the gateway, exposes it through the sessions-group protocol, and makes every section header draggable with hover- or focus-only drag grips.

## System Context

The Control UI reads the gateway’s session-group catalog to render sidebar sections, then sends user reordering back through the same gateway RPC. The gateway persists that layout in the shared state database and broadcasts a session-change event so other connected Control UI clients can refresh.

## Architecture Diagram

  B --> C[Gateway sessions-group request]
  C --> D[Shared state database]
  D --> E[Gateway response and change event]
  E --> F[Connected Control UI clients]
  F --> G[Reordered sidebar sections]

## Best Possible Solution

Keep the gateway-owned persistence design, but make response decoding backward-compatible for older gateways and add focused upgrade coverage plus redacted live evidence that reordering survives a real gateway refresh or reconnect.
