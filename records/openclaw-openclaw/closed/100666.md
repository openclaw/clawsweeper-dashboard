## Summary

Keep open: the PR targets the right ACP ledger hot path and includes useful proof, but the in-memory byte cache is updated inside SQLite write transactions and can drift from the rolled-back database after a failed write.

## What This Changes

The PR changes the ACP SQLite event ledger to initialize replay byte totals once and maintain them with row-level deltas, plus tests for serialized-byte retention and repeated-scan avoidance.

## Best Possible Solution

Keep the ledger-scoped cached accounting approach, but make the byte-cache update commit-scoped or force a recompute after any write failure before merge.
