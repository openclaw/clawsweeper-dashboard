## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.93

Full review comments:

- **[P1] Target active SQLite credential storage:** `src/agents/auth-profiles/paths.ts:32`
  - body: Current main persists auth profile secrets through `auth_profile_store` in the per-agent SQLite DB, but this patch only seals the legacy `auth-profiles.json` path. Rebasing this shape would leave the active credential store unprotected or create a parallel legacy path, so the encryption design needs to move to the SQLite/doctor migration boundary.
  - confidence: 0.91
- **[P1] Block plaintext downgrade without the passphrase:** `src/infra/sealed-json-file.ts:113`
  - body: `saveSealedJsonFile` writes plaintext whenever `OPENCLAW_PASSPHRASE` is absent, even if the existing destination is sealed. A missing env var plus an oauth/CLI/legacy merge write can replace encrypted credentials with plaintext and partial data, contradicting the intended fail-closed behavior.
  - confidence: 0.94
- **[P1] Write sealed credential files atomically and privately:** `src/infra/sealed-json-file.ts:113-114`
  - body: This direct `writeFileSync` truncates the credential file in place and only applies `0600` after the write. A crash, ENOSPC, or link/clobber edge can corrupt or expose secret-bearing files; use the existing atomic replace pattern with a private temp file and guarded destination semantics.
  - confidence: 0.88
- **[P2] Preserve long-running final-response requests:** `src/gateway/client.ts:520-524`
  - body: This default timeout applies even when `expectFinal` is true, so an accepted long-running agent request can be rejected after 30s before the final response arrives. Current main's gateway-client package keeps `expectFinal` requests untimed unless the caller supplies a timeout, and that behavior should be preserved.
  - confidence: 0.9
- **[P2] Persist KDF parameters in the sealed envelope:** `src/infra/sealed-json-file.ts:39`
  - body: The envelope records the algorithm but not the scrypt parameters used to derive the key. Without explicit stored KDF metadata, future tuning or compatibility checks cannot reliably decrypt older stores or audit the cost used for credential-at-rest protection.
  - confidence: 0.82
- **[P2] Read sealed main stores during subagent inheritance:** `src/agents/auth-profiles/store.ts:412`
  - body: The subagent inheritance fallback still calls `loadJsonFile` on the main store, so a sealed main `auth-profiles.json` will parse as invalid JSON and subagents will silently stop inheriting credentials. Use the same sealed-aware reader or redesign this path with the current persisted-store abstraction.
  - confidence: 0.9
