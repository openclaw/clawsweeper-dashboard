## Summary

Close as cannot reproduce: the reported omitted-agent spec is not produced by current supported ACP binding paths, and the suggested fallback uses the wrong default agent id for OpenClaw.

## What This Changes

The issue asks for ACP configured-binding session matching to treat an omitted ACP agent id as the default agent instead of repeatedly recreating the session.

## Best Possible Solution

Keep the current contract: resolve or require `agentId` before ACP lifecycle code, and only revisit lifecycle fallback behavior if a supported caller can produce an omitted-agent spec.

## Maintainer Decision

Required: false

## Reproduction Assessment

No. Current schema, compiler, record resolution, and SDK paths require or resolve `agentId` before `ensureConfiguredAcpBindingSession`, so the omitted-agent spec described here is not reachable through supported current-main behavior.

## Solution Assessment

No. Hard-coding a fallback to `default` is not the best fix because OpenClaw's default agent id is `main`, and the supported path already resolves the agent before lifecycle matching.
