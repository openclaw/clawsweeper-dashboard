## Summary

Keep open: current main still shows the Telegram durable/final send fallback gaps reported here, and the protected `maintainer` label independently prevents conservative cleanup closure.

## What This Changes

The issue reports that Telegram durable/final send paths miss streaming-path fallbacks for rich entity errors, media caption parse errors, quote-parameter errors, and longer flood waits.

## Best Possible Solution

Implement Telegram-owned durable send fallback parity in the plugin, with regression coverage for rich entity fallback, media caption parse fallback, native quote fallback, and Telegram-appropriate flood-wait retry handling.

## Reproduction Assessment

Yes, source-level: current main still routes durable final/message-tool sends through `sendMessageTelegram`, where rich validation, media caption parsing, native quotes, and retry-after caps do not have the same sibling fallbacks. I did not run a live Telegram repro in this read-only pass.

## Solution Assessment

Yes, with one boundary constraint: the best fix is Telegram-plugin fallback parity around the durable send helpers, not a broad core channel rewrite. The retry-after piece should be implemented as Telegram-specific policy unless maintainers choose to change shared channel retry defaults.
