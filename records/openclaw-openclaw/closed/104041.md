## Summary

The request remains necessary: current main still uses a dismissible top-of-content update banner, the signed macOS updater is not bridged into the embedded Control UI, managed gateway repair remains prompt-gated, and appcast generation has no beta channel tagging. The feature is in scope but carries a protected maintainer label and requires explicit product, upgrade, and release-policy decisions.

## What This Changes

Add a persistent Control UI sidebar update card, make signed macOS updates run app-first with automatic repair limited to app-managed gateways, and publish Sparkle beta items selected from the canonical gateway update channel.

## Best Possible Solution

Implement one coordinated flow using existing owners: render update availability persistently in the sidebar, keep ordinary web updates on `update.run`, expose a constrained signed-app-only native update bridge, auto-repair only the app-managed gateway after relaunch, and use one appcast with untagged stable items plus beta-tagged items selected from canonical `update.channel`.
