## Summary

Keep this PR open: it addresses a real unbounded-read availability problem, but the proposed shared 1 MiB limit changes the documented `--file` contract and rejects previously accepted approvals files without evidence that 1 MiB is a safe compatibility boundary.

## What This Changes

The PR replaces the unbounded `openclaw approvals set --file` read with a bounded descriptor-based reader and adds tests for ordinary, oversized, directory, and FIFO inputs.

## Best Possible Solution

Retain bounded descriptor-based reading, but define a separately justified and documented disk-file limit that preserves realistic existing approvals exports, then add an end-to-end regression for a valid file larger than 1 MiB.
