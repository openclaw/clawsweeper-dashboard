- **[P1] Remove the legacy runtime writer before activating SQLite:** `src/agents/tools/transcripts-tool.ts:114`
  - body: Returning a file-backed store whenever unimported metadata exists keeps the retired store writable during normal runtime.   - confidence: 0.96

  - body: The `.sqlite-migrated` marker is independent of the rows it claims are complete. Losing the marker after a committed import switches runtime back to legacy files, while retaining it after replacing or restoring the database hides the legacy source behind an empty or older SQLite store. Store and verify a migration receipt in SQLite as part of the migration transaction rather than using a sidecar marker.
  - confidence: 0.97
- **[P1] Fail closed when the legacy store cannot be inspected:** `src/agents/tools/transcripts-tool.ts:105`
  - body: The catch block treats permission and I/O failures as proof that no legacy transcripts exist. That activates SQLite despite an unknown legacy state, and fixing the filesystem later can flip the process back to the file backend and split new and old sessions. Propagate the error or report migration-pending until Doctor can inspect the directory successfully.
  - confidence: 0.98
