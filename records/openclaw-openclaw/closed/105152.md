## Summary

Current `main` already resolves the observable failure: agent-initiated Skill Workshop lifecycle calls now use a 70-second approval deadline inside the tool watchdog budget and return a structured pending result instead of hanging until the client kills the call. The report’s strongest signals—no workshop file lock, no writes, proposal remaining pending, and immediate CLI success—match a pre-execution approval timeout rather than a poisoned store lock; this fix merged after the reporter’s `2026.6.9` build and remains main-only.

## What This Changes

Prevent `skill_workshop apply` from hanging in a long-lived gateway while the same proposal succeeds through the fresh-process CLI.

## Best Possible Solution

Keep the current bounded approval behavior and ask for a new current-main report only if an approved lifecycle call demonstrably enters `applySkillProposal` and then hangs, including approval timing and gateway logs that identify the first non-settling await.

## Reproduction Assessment

No on current `main`: the previously overlong approval wait is now bounded to return before the tool watchdog, with regression coverage for the pending timeout outcome. The report reproduces released `2026.6.9` behavior, not the current implementation.

## Solution Assessment

Yes. Bounding the approval at its owner boundary is safer and more maintainable than evicting a possibly active store lock, which could permit overlapping writes; a separate store fix should require evidence that execution passed approval and entered `applySkillProposal`.
