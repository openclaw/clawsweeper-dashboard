## Summary

The corrected minimal reproduction now loads with `activation.onStartup: true`, and both current `main` and the shipped `v2026.7.1` loader normalize the default module export before checking `register`/`activate`. The original failure was traced to a manifest/export id mismatch in the first reproduction rather than the reported validation behavior.

## What This Changes

The issue requests that startup validation accept `defineChannelPluginEntry` default exports with registration functions, matching the runtime loader.

## Best Possible Solution

Keep the existing normalized loader behavior shipped in `v2026.7.1`; reopen only with a current-version package whose manifest id, exported entry id, and loaded artifact path are captured together.
