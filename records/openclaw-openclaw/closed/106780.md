## Label Justifications

- `P1`: Localized sandbox environments can turn an ordinary missing-file stat into a thrown runtime error, breaking an active agent filesystem workflow.

## Summary

Current main still performs English-only ENOENT matching. The current PR head addresses that bug without the earlier temporary-file and broad-pattern defects, so the contribution remains necessary and should proceed through normal landing rather than cleanup closure.

## What This Changes

Changes sandbox `stat` handling to translate missing parent or target paths into an `ENOENT` sentinel with exit code 2 under `LC_ALL=C`, while preserving other failures and adding bridge and generated-plan coverage.

## Best Possible Solution

Keep missing-path classification at the sandbox command boundary under a deterministic locale, expose it to the bridge through a narrow exit-code contract, and preserve diagnostic failures for every non-ENOENT condition.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Run current-main sandbox stat handling with GNU `stat` under a non-English locale such as zh_CN.UTF-8 against a missing path; the localized stderr does not match the bridge's English-only check, as demonstrated by the submitted terminal transcript.

## Solution Assessment

Yes. Translating the external utility's locale-normalized diagnostic into a narrow internal exit-code contract is more maintainable than continuing to parse host-localized stderr in the TypeScript bridge, while still distinguishing permission and I/O failures.
