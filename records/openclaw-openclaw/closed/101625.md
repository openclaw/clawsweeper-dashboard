## Summary

Keep this PR open, but it is not merge-ready: the patch changes the low-level send cap while the production caller can already hand it a 2000-code-unit chunk with a dangling surrogate, so the central outbound-message corruption remains.

## What This Changes

The PR imports `truncateUtf16Safe` and uses it instead of two raw 2000-code-unit slices in Zalouser media and plain text send paths.

## Best Possible Solution

Make Zalouser's chunk range calculation UTF-16-safe before slicing and keep the low-level `truncateUtf16Safe` calls as a guard, with regression coverage for text and media/caption sends.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source inspection: a production send through `sendMessageZalouser` can chunk 1999 BMP characters plus an emoji with raw `text.slice`, creating the dangling surrogate before `sendZaloTextMessage` runs.

## Solution Assessment

No; as submitted this is too low in the send stack. The boundary must be made safe in `splitTextRanges` or `splitStyledText` before chunk text and style ranges are sliced.
