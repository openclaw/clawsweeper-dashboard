## Summary

Codex review finds this feature still necessary: current main has the underlying activity and notification primitives, but every macOS client independently derives connection alerts from broadcast presence, and no gateway-owned active-computer router or canonical related item exists. The maintainer label and cross-surface behavior require an explicit product decision before implementation.

## What This Changes

Route node connection alerts through the gateway to the most recently active eligible computer using authenticated node activity telemetry.

## Best Possible Solution

Implement an alert-specific gateway router: accept additive authenticated node activity updates, derive recency from gateway receipt time, select the most recently active connected Mac that advertises system.notify, use a bounded idempotent fallback, expose detailed activity only through node inventory/tools, and project only the stable active-node identity into normal model context.
