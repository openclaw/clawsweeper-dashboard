## Summary

Keep this PR open, but the current patch is not merge-ready: it targets a real installer bug, yet the one-line boolean change does not fix the Debian-with-pacman case because `is_arch_linux` itself falls back to `command -v pacman`.

## What This Changes

This PR changes `scripts/install.sh` so the Linux Node.js pacman branch requires both `command -v pacman` and `is_arch_linux`.

## Best Possible Solution

Make the Arch distro predicate independent of the `pacman` binary for `install_node`, then cover Debian-with-fake-pacman and real Arch/pacman routing before merge.

## Reproduction Assessment

Yes. Source inspection shows that on current main, a non-Arch Linux system with `pacman` on PATH makes `is_arch_linux` return success and sends `install_node` through the pacman branch before apt/NodeSource.

## Solution Assessment

No. The proposed `&&` is only a plausible fix; the best fix is to remove the shared `pacman` fallback from this distro decision or introduce an os-release-only Arch helper, then add focused route tests.
