## Summary

Keep open: the patch addresses the right provider/auth mismatch in the direct Google image provider, but the readiness hook is not added to the Google provider facade that OpenClaw actually registers for image-generation discovery and auto-fallback.

## What This Changes

The PR makes the direct Google image-generation provider treat a usable `models.providers.google.apiKey` as configured and adds direct-provider tests for literal, missing, empty, and whitespace-only config keys.

## Best Possible Solution

Share one Google image readiness helper between the registered lazy provider and the loaded provider, then add a registered/runtime-path regression for config `apiKey` plus custom `baseUrl` with no env/profile and guard missing or blank keys.

## Solution Assessment
