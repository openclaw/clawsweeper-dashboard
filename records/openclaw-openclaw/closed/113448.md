## Summary

Keep this PR open for maintainer review. It addresses the concrete routed-reply hook bypass tracked by https://github.com/openclaw/openclaw/issues/92374, but it also introduces a documented provider-owned delivery mode in the channel plugin SDK and changes the security-sensitive order of hook execution, suppression, and native delivery. The PR body reports extensive testing, yet it does not include inspectable live logs, screenshots, recordings, or artifact links that independently show the claimed after-fix behavior.

## What This Changes

This PR routes normal channel agent replies through ordered outbound hooks before delivery, while adding an explicit provider-owned exception for Telegram and Discord delivery funnels that must settle messages themselves.

## System Context

Inbound channel turns accept an event, generate agent reply payloads, and deliver each payload through either shared core delivery or a channel-specific adapter. This change places outbound rewrite and cancellation hooks at that handoff so plugins can affect replies before Telegram, Discord, WhatsApp, or another channel makes them visible.
