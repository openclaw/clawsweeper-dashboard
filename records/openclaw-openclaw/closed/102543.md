## Summary

Keep open: current main still decodes the bounded browser stderr tail with `Buffer.toString("utf8")`, which can emit a replacement character for a retained trailing partial UTF-8 code point. The PR is a narrow, code-correct fix with focused regression coverage, but it needs real behavior proof before merge because the submitted evidence is test-only.

## What This Changes

The PR changes the browser bounded UTF-8 stderr-tail helper to decode with Node `StringDecoder` and adds tests for trailing partial and split multibyte code points.

## Best Possible Solution

Land the shared helper fix after the PR body includes current-head real behavior proof showing a real browser stderr diagnostic path remains valid UTF-8 after truncation or split chunks.
