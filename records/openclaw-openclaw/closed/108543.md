## Summary

Keep open: the SQLite design is consistent with repository policy, but the branch makes existing APNs registrations unavailable until an operator explicitly runs Doctor, and the supplied evidence is test-only rather than a real upgrade-and-push demonstration.

## What This Changes

Moves APNs registration reads, writes, invalidations, and legacy import from a JSON sidecar to shared SQLite with Doctor migration receipts and deletion tombstones.

## Best Possible Solution

Keep SQLite as the sole steady-state authority, but ensure the supported upgrade path runs or visibly blocks on the Doctor migration before APNs reads switch over, then prove a v2026.7.1 upgrade preserves live direct and relay delivery, invalidation, and restart behavior.
