## Summary

Keep open: current main still writes generated Windows gateway launchers as UTF-8 while embedding user-profile paths, so the reported CJK first-run failure remains source-reproducible and neither related pull request supplies the missing encoding fix.

## What This Changes

Make generated Windows `gateway.vbs` and `gateway.cmd` files safely preserve CJK user-profile paths.

## Best Possible Solution

Centralize byte-safe launcher writing, emit VBS as UTF-16 LE with BOM, use a verified locale-safe CMD strategy, repair existing generated launchers during refresh, and prove the full first-run path on Windows with a CJK profile.

Yes at source level: both launchers embed the CJK profile path and current writers use an incompatible UTF-8 contract; the reporter also supplied a concrete v2026.7.1 Windows failure path. A live VM reproduction was not run during this read-only review.

## Solution Assessment

The UTF-16 LE BOM direction for VBS is appropriate, but the CMD strategy should follow verified Windows locale behavior rather than hard-coded GBK; the best fix belongs in the shared launcher-writing boundary and must cover both Scheduled Task and startup-fallback paths.
