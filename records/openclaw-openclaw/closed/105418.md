## What This Changes

Updates the cron session reaper’s per-store throttle after persistence failures and adds a regression test intended to verify the cooldown.

## Best Possible Solution

Keep the failure-path throttle update, but replace the test with a deterministic failure at the actual `updateSessionStore` boundary and assert that the second call does not invoke persistence or emit another warning, then provide redacted runtime output demonstrating the cooldown.
