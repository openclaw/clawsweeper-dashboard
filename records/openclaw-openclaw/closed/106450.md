## Summary

Keep this PR open: current main still has the reported pending-restart budget bypass, but this patch silently permits an additional unrecorded restart beyond the configured maximum and lacks real Gateway/channel-adapter proof. The related open PRs are competing candidates rather than safe merged replacements.

## What This Changes

The branch counts pending channel-recovery attempts against the hourly restart budget, permits one unrecorded completion attempt at a full budget, resets that allowance after rolling-window capacity returns, and adds timer-driven regression tests.

## Best Possible Solution

Define one canonical recovery-cycle contract: charge a clearly specified budget slot, allow only the bounded continuation required to finish that same cycle, align configuration documentation and tests with that meaning, and prove normal completion, permanent-pending capping, and rollover using a real Gateway and channel adapter.
