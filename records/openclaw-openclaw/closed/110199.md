- `impact:ux-release-blocker`: Recovering the reported production state otherwise requires manual database or state-file intervention outside the product flow.

## Summary

Current `main` already resolves the reported deadlock by separating reviewed non-blocking migration residue into notices while preserving real warnings as readiness blockers; the checkpoint is recorded for notice-only migrations.

## What This Changes

The issue requests that startup migration warnings cannot indefinitely prevent checkpoint recording and gateway readiness.

## Best Possible Solution

Keep the notice-versus-warning convergence model on current `main`; retain fail-closed behavior only for genuine migration, archive, ownership, or canonical-state conflicts.
