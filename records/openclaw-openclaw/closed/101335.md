## Label Justifications

- `P2`: The issue reports a real Telegram queue semantics mismatch with limited channel scope and no confirmed outage, data loss, crash loop, or security impact.
- `impact:session-state`: Same-chat Telegram messages are treated as separate idle-session turns instead of being admitted into the active reply operation's queued state.
- `impact:ux-friction`: Users configuring Telegram `collect` get surprising separate turns for same-chat bursts instead of the documented coalesced follow-up behavior.

## Summary

Keep open: current main still drains Telegram spooled updates one full same-lane handler at a time before later updates can reach the reply dispatcher, while queue docs describe collect-mode batching for active-run messages. No merged fix or direct duplicate was found, and the repair needs maintainer design because it changes Telegram spool/drain ordering semantics.

## What This Changes

The issue requests that Telegram same-chat bursts arriving during an active reply coalesce through `messages.queue.collect` instead of being serialized as separate idle-session turns by isolated ingress.

## Best Possible Solution

Define a maintainer-approved Telegram ingress-to-follow-up admission contract for busy same-lane updates, then implement it with isolated-ingress, webhook/spool, collect-queue, crash/replay, and live Telegram proof; if maintainers reject that behavior, document Telegram same-chat `collect` as unsupported.
