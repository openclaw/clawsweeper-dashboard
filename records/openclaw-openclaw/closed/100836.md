## Summary

Keep open. The patch is a narrow and likely correct replacement of current-main cron edit's paginated `cron.list` lookup with the existing `cron.get` single-job read path, but this external PR still needs real CLI/Gateway behavior proof beyond mocked Vitest output before merge.

## What This Changes

This PR changes `openclaw cron edit` schedule and timeout-only payload lookups to call `cron.get` directly and updates cron CLI tests that expected paginated `cron.list` lookups.

## Best Possible Solution

Land the direct `cron.get` lookup after the contributor adds redacted real CLI/Gateway proof showing cron edit succeeds without paginated list calls.

## Reproduction Assessment

Yes, source inspection on current main shows `cron edit --exact` and timeout-only edit lookups call `loadCronJobForEditSchedulePatch`, which pages `cron.list`. I did not run a live large-gateway timing repro.

## Solution Assessment

Yes, this is the narrowest maintainable fix because `cron.get` already exists for id-addressed single-job reads. Keeping pagination or adding another list filter would duplicate the existing Gateway contract, while `cron show` can remain list-backed because it also accepts names.
