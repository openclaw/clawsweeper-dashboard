## Label Justifications

- `impact:auth-provider`: The affected boundary is provider/model request compatibility: the provider rejects the tool schema before model execution.

## Summary

This is a duplicate of the broader active llama.cpp tool-schema compatibility report, which records the same unanchored `declarationKey` pattern and the additional schema constraints exposed after that first failure. Current `main` no longer emits that pattern from the cron tool schema, while the remaining compatibility investigation is already tracked in the canonical issue.

## What This Changes

Report that llama.cpp rejects the cron tool’s JSON Schema because a regex pattern is not fully anchored, causing local-provider agent turns to fail before replying.

## System Context

OpenClaw builds JSON Schema definitions for agent tools, including the cron scheduler, and sends them with provider requests. A llama.cpp-compatible endpoint converts those schemas into a constrained grammar; a rejected schema prevents the entire agent turn from reaching the model.
