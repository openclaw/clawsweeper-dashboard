## Summary

Keep open: current `main` and shipped v2026.6.11 still allow heartbeat context to become the implicit recipient of a no-recipient general `message` send. The source path is distinct from the related heartbeat final-text, duplicate-fallback, and cross-provider reports, and no open PR currently owns this exact repair.

## What This Changes

Prevent no-recipient heartbeat `message` tool sends from resolving to the heartbeat sentinel or unintentionally delivering to the source conversation.

## Best Possible Solution

Carry an explicit synthetic-heartbeat or implicit-route eligibility fact into message-tool normalization, reject or privately absorb missing-recipient heartbeat sends, preserve explicit-target heartbeat notifications and ordinary source replies, and add routed plus routeless regression tests.
