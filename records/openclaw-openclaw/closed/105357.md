## Label Justifications

## Summary

Keep this issue open. Current main still activates every direct-CDP screenshot target, and the official protocol defines that operation as foregrounding the tab. The adjacent tab-creation PR explicitly leaves screenshots unchanged, while revising this intentionally landed reliability policy requires maintainer direction and headed/headless runtime proof.

## What This Changes

Prevent direct-CDP screenshots from implicitly activating background tabs in headed browsers while retaining recovery for headless background-capture stalls.

## Best Possible Solution

Make capture non-activating by default, then reconnect, activate, and retry once only for a specifically recognized screenshot-command timeout; avoid adding configuration unless live proof shows remote unknown-mode sessions require an explicit policy knob.
