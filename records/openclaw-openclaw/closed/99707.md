## Summary

Keep open: this PR is the active implementation candidate for unified live QA hosting, but the current branch is not ready because it makes existing live scorecard profile runs select the live adapter driver without an explicit adapter channel.

## What This Changes

The PR adds an optional QA runner adapterFactory surface and live transport adapters for Telegram, Slack, WhatsApp, and Matrix so shared QA scenarios can run through QA Lab's hosted suite path.

## Best Possible Solution

Keep the additive adapterFactory seam, but select the live factory only for explicit adapter-channel runs and add regression coverage for the profile-driven live metadata path.

## Reproduction Assessment

Yes. Source inspection shows profile runs pass channelDriver live without an adapter channel, while the PR now maps any channelDriver live to the live transport driver and therefore has no default factory for the existing profile path.

## Solution Assessment

No. The shared adapter direction is plausible, but the implementation should gate live factory selection on an explicit adapter channel/factory so scorecard metadata continues to work as before.
