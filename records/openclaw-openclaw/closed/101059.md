## Summary

Keep this issue open. Current main still only accumulates OpenAI Responses refusal deltas while the active output item is a message, while function-call argument finalization can still produce a tool call with empty arguments instead of a structured provider refusal.

## What This Changes

The issue asks OpenClaw to handle OpenAI Responses streaming refusal chunks during tool-call output as a structured model refusal instead of falling through to tool-call argument parsing.

## Best Possible Solution

Normalize OpenAI Responses refusal events before tool-call finalization, using the existing structured provider-refusal/error path and covering both `packages/ai` and any sibling transport parser that shares the invariant.

## Solution Assessment

Yes for the central bug, but not necessarily via the exact named error in the issue. The maintainable fix is to map OpenAI refusal events into OpenClaw's existing structured provider-refusal/error path before tool execution.
