## Summary

The PR should stay open because it replaces a working provider login and refresh path with an importer that cannot read credentials from current official Gemini CLI installations: upstream now uses keychain-backed HybridTokenStorage and treats `oauth_creds.json` only as a legacy migration file. The migration direction also needs maintainer confirmation after that blocking contract mismatch is resolved.

## What This Changes

The PR replaces OpenClaw-managed Gemini CLI OAuth login and refresh with importing and re-importing credentials from the official Gemini CLI credential files.

## Best Possible Solution

Keep the current provider-owned OAuth path until a supported official Gemini CLI credential handoff or delegated runtime boundary exists, then add an explicit migration that preserves existing profiles and proves fresh setup, upgrade, refresh, and authenticated model use.
