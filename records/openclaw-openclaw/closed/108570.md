## Label Justifications

- `P1`: The deterministic reconnect race can break an active channel workflow by silently skipping inbound events for real ClickClack users.

## Summary

This issue remains necessary because the cursor-ordering race is present on the current-main base and the linked closing PR is still open rather than merged.

## What This Changes

Ensure ClickClack websocket events are processed serially, commit reconnect cursors only after successful processing, and wait for queued work before reconnecting.

## Best Possible Solution

Keep websocket-cycle ownership in the ClickClack plugin: serialize inbound events, commit each cursor only after success, settle the queue before reconnect, and retain focused close, failure, abort, malformed-frame, and backlog regression coverage.
