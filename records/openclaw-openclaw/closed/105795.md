## What This Changes

The PR adds a shared three-second deadline to Control UI stale-chunk document probes so concurrent automatic and manual recovery can reach fallback revalidation after a hung probe aborts.

## Best Possible Solution

Land the shared bounded probe after refreshing against current main, retaining the existing successful-reload, cooldown, build-guard, and offline fallback semantics.

## Maintainer Decision

## Reproduction Assessment

Yes. Returning a stale lazy chunk while holding the document HEAD probe open deterministically blocks current-main recovery; the focused regression tests and after-fix Chromium run exercise that path.

## Solution Assessment

Yes. Bounding and sharing the probe inside its existing recovery owner is narrower and more maintainable than adding another caller-level timeout or fallback path.
