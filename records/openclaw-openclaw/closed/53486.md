## Label Justifications

- `impact:message-loss`: Interactive-card semantics are lost when valid Feishu card payloads are delivered as raw text instead of native interactive cards.

## Summary

Keep open: current main and the latest release still send plain Feishu `message`/`text` strings through the text branch, while the direct fix PRs for this behavior are closed unmerged and the merged native-card work only covers structured payloads.

## What This Changes

Restore Feishu proactive `message(action=send)` so valid interactive-card JSON in the plain `message` or `text` parameter is sent as a native interactive card instead of raw text.

## Best Possible Solution

Keep this as the canonical issue and either sponsor a narrow Feishu-plugin parser fix with live Feishu proof, or explicitly document that raw interactive-card JSON in plain `message` is unsupported and steer users to structured card/presentation payloads.
