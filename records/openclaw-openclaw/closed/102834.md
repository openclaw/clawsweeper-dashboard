## Summary

Keep open. Current main still passes HTTP browser Origin policy into gateway auth but accepts `gateway.auth.mode="none"` before consulting that policy, while the WebSocket path rejects disallowed browser Origins; the same source shape is present in the latest release tag.

## What This Changes

The issue asks OpenClaw to reject browser-origin HTTP requests with a disallowed `Origin` under `gateway.auth.mode="none"` instead of letting them reach operator HTTP routes.

## Best Possible Solution

Apply a shared HTTP browser-Origin gate whenever an `Origin` header is present before accepting `auth.mode="none"`, preserving origin-less private-ingress clients and adding focused regression tests for none, trusted-proxy, token/password, and WebSocket parity.
