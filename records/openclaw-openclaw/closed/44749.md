## Summary

Keep open: current main and the latest release still mutate a caller-supplied exec approvals snapshot and save the whole approvals file, so concurrent allow-always approvals can still overwrite earlier persisted allowlist entries. The open broader fix candidate is not merged yet and changes security-state locking behavior, so this should stay with maintainer/security review.

## What This Changes

The issue reports that concurrent allow-always exec approvals can silently lose entries in `exec-approvals.json` because later whole-file writes are based on stale in-memory snapshots.

## Best Possible Solution

Land or revise a maintainer-approved serialized exec-approvals mutation path that re-reads current policy inside the same lock or transaction for gateway, node, and macOS writers, with regression proof for concurrent allow-always additions and stale revocation races.
