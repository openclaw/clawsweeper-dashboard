## Summary

Current main already enforces bounded cron execution across scheduled, manual, and startup-catch-up paths, so the reported missing-timeout condition is not present; the issue targets gateway wiring files rather than the cron service that owns execution limits. ([formatika.de](https://www.formatika.de/mobile.jsp?content=source&detail=products%2FSources%2Fformale+Sprachen%2FJAVA%2Fopenclaw%2Fsrc%2Fcron%2Fservice%2Ftimer.ts&utm_source=openai))

## What This Changes

Add an upper execution-time boundary to cron jobs so hung work cannot indefinitely occupy scheduler concurrency.

## Best Possible Solution

Keep the existing cron-service timeout and abort contract; if a current release still stalls, require a new report with the job JSON, run history, timeout value, last execution phase, and logs so the remaining defect can be isolated without adding another config surface.
