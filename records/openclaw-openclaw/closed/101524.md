## Summary

Keep open: the PR targets a real async child-process error path, but the current one-line no-op listener would turn a failed managed-service update helper spawn into a false `started` handoff instead of the documented failed-handoff response.

## What This Changes

The PR adds a no-op `error` listener to the detached managed-service update handoff child process and updates the Vitest spawn mock to expose `on`.

## Best Possible Solution

Handle async helper spawn failure before reporting `started`, route it through the existing `managed-service-handoff-failed` path, and add focused regression coverage plus redacted OpenClaw terminal or log proof.

## Solution Assessment

No. A no-op listener prevents the parent crash but is not the best fix because this handoff has a documented failed-spawn response path; the implementation should surface async spawn failure before reporting success.
