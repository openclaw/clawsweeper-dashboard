Keep open: current main and v2026.6.11 cover several full tool-call XML leak shapes, but they do not cover the reported standalone `<parameter name="...">...</parameter>` wrapper, and the Telegram rich-message path can still render unsupported XML-like text visibly.

## What This Changes

The issue requests sanitizing Telegram rich-message output so standalone `<parameter name="...">` wrappers are not shown to users inside rich details content.

## Best Possible Solution

Extend the shared visible-text or rich-delivery sanitization path so standalone `<parameter name="...">...</parameter>` wrappers are removed before Telegram rich rendering, preserving safe inner text and literal code/prose examples.

Yes, at source level. The current sanitizer and repair parser do not recognize the reported standalone `<parameter name="...">` wrapper, and the Telegram rich path forwards rendered rich text when `richMessages` is enabled; I did not run a live Telegram reproduction.

## Solution Assessment

Yes on direction. The maintainable fix belongs in the shared visible-text/tool-call sanitization boundary before Telegram rich rendering, not in a new config option or Telegram-only fallback.
