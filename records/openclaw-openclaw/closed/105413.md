## Summary

Current main and v2026.6.11 both route wake-now main-session cron events through heartbeat active-hours before inspecting the queued cron payload, so the overnight `quiet-hours` failure is a real core regression and the issue remains necessary. The existing tagged-event path should render cron text when reached, so the reported inside-hours generic heartbeat prompt needs integrated regression coverage rather than being dismissed or split prematurely.

## What This Changes

Fix main-session `systemEvent` cron jobs so every scheduled payload executes independently of heartbeat active hours and is not replaced by a generic heartbeat poll.

## Best Possible Solution

Treat explicit cron wakes as scheduler-owned events that bypass heartbeat cadence, enablement, active-hours, and empty-file gates, while reusing the existing tagged cron prompt and consumption path and recording a non-ok result whenever no cron turn actually runs.
