## Summary

Keep open: the UTF-16 truncation problem is real, but this patch is not merge-ready because it removes existing browser-side payload caps and only provides test/CI proof rather than after-fix real browser behavior.

## What This Changes

The branch removes browser-context `.slice(0, 101/121)` pre-truncation from CDP, Playwright URL, and Chrome MCP snapshot helpers so Node-side `truncateUtf16Safe` performs final truncation.

## Best Possible Solution

Preserve the 100/120-character browser-side payload caps with surrogate-safe truncation in each evaluated script, then keep Node-side `truncateUtf16Safe` as the final guard.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source inspection: current main uses raw `.slice(0, 101/121)` inside evaluated browser scripts before Node-side `truncateUtf16Safe`, so an emoji high surrogate at the boundary can be returned malformed. I did not run a live browser repro in this read-only review.

## Solution Assessment

No. Removing pre-truncation fixes the dangling-surrogate symptom but drops the existing payload caps; the better fix is a browser-context surrogate-safe cap like the prior same-surface approach in https://github.com/openclaw/openclaw/pull/98155.
