## Summary

This focused PR remains necessary because current main still leaves identified unlisted Telegram API methods without an OpenClaw request timer; the branch closes that recurring allowlist gap, has convincing controlled runtime proof, and the latest head includes direct area-owner test work. The patch is correct, but merging intentionally changes the timeout for custom or slow unlisted operations from grammY's 500-second default to 60 seconds unless the existing higher timeout setting is configured.

## What This Changes

The PR makes identified Telegram Bot API methods absent from the explicit timeout table use a 60-second default guard while preserving fixed method limits, the 45-second getUpdates guard, and higher configured timeouts.

## Best Possible Solution

Keep explicit method-specific limits as overrides over the general 60-second guard, retain the fixed getUpdates behavior, and preserve the existing configurable higher timeout for slow custom Bot API deployments.
