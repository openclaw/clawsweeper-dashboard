## Summary

Current main still has the reported unbounded Android history-image path, and the protected issue is paired with an open exact fix candidate at https://github.com/openclaw/openclaw/pull/105065, so it should remain open until that PR is reviewed and merged or rejected.

## What This Changes

Apply Android’s existing 300 KiB encoded-image ceiling to structured chat-history images before base64 and bitmap decoding.

## Best Possible Solution

Land the linked focused fix after exact-head Play and third-party parser/decoder tests, Android build, and ktlint prove oversized structured images return before base64 decoding while normal images, audio, Markdown images, and managed media references remain unchanged.

## Solution Assessment

Yes. A canonical encoded-image limit enforced at structured parsing and again as the decoder’s first instruction is the narrow defense-in-depth fix, with no new configuration or product policy.
