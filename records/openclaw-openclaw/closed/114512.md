## Summary

Keep this PR open for explicit maintainer review. The focused watchdog change appears correct and its supplied scheduler proof is strong, but it intentionally removes the only pre-run timeout while a job waits for lane admission; maintainers should confirm that an unbounded lane wait is the intended availability policy and refresh proof on the current merge head.

## What This Changes

The PR pauses the isolated-cron setup watchdog while a job waits for the shared nested execution lane, then starts a fresh full setup timeout when the lane admits the job.

## System Context

Scheduled isolated cron jobs enter a shared nested execution lane before their runner begins setup. The watchdog decides whether a pre-run failure is reported, and the scheduler then persists the job result and triggers downstream retry or notification handling.
