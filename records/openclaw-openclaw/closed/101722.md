## Label Justifications

- `P2`: This is a focused agent-harness parsing bug with plausible user-facing answer corruption but no evidence of a broad outage or blocked onboarding path.
- `impact:ux-friction`: A user replying to an agent input prompt can get confusing or wrong answer mapping when answer text is mistaken for keyed syntax.

## Summary

Keep open. Current main still has a permissive shared parser that treats delimiter-bearing answer lines as keyed entries; the common URL/time fallback path is less broken than the issue claims, but the Codex/Copilot answer bridge lacks coverage for this edge and should be hardened before cleanup.

## What This Changes

The issue asks OpenClaw to stop `parseKeyedAnswers()` from treating delimiter characters inside user answer text as keyed-answer separators.

## Best Possible Solution

Keep the shared helper, but make keyed parsing question-aware or delimiter-aware so unkeyed answer text with URLs, times, Windows paths, or config snippets remains intact while supported keyed and numeric replies still map to question ids.
