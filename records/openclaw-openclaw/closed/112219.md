## Summary

This is a current, narrowly described privacy-contract bug: the Voice Wake UI promises fully on-device recognition while both identified Speech-request paths reportedly leave Apple’s on-device requirement unset. The item also carries the protected `maintainer` label, so it requires explicit maintainer handling rather than automated cleanup.

## What This Changes

Require macOS Voice Wake and its built-in trigger test to set `requiresOnDeviceRecognition = true` so their Speech requests match the displayed on-device-recognition promise.

## Best Possible Solution

Centralize Voice Wake request configuration in the macOS app, set `requiresOnDeviceRecognition = true` alongside its existing partial-results and dictation settings, use that helper for both runtime wake detection and the trigger test, and add focused regression coverage for the privacy invariant.
