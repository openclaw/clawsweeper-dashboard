## Summary

Keep open: current main and the latest release compute and return usage for plugin `api.runtime.llm.complete` calls, but that path does not emit the trusted `model.usage` diagnostic event consumed by OTel and Prometheus exporters.

## What This Changes

Request to emit trusted `model.usage` diagnostics, with plugin attribution, for LLM completions initiated through `api.runtime.llm.complete`.

## Best Possible Solution

Add one diagnostics-gated emitter in the plugin LLM runtime, plus exporter/test updates for bounded plugin attribution, while preserving the existing SDK result shape.

## Reproduction Assessment

Yes, at source level. `runtime.llm.complete` computes and returns usage while diagnostics exporters only observe `model.usage`, and the plugin runtime currently emits no such event.

## Solution Assessment

Yes, the requested direction is the narrow maintainable solution. Emitting from `src/plugins/runtime/runtime-llm.runtime.ts` reuses the existing diagnostics contract instead of making every plugin instrument its own usage.
