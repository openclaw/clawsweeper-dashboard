## Label Justifications

- `P1`: A poisoned long-running Anthropic session rejects every later turn until history is repaired or reset, disrupting a real agent workflow.
- `impact:session-state`: The failure is caused by persisted assistant history becoming unsafe to replay after pruning changes the retained window.
- `impact:message-loss`: Subsequent user turns fail instead of receiving agent responses while the session remains poisoned.
- `impact:auth-provider`: The observable failure is a provider-side Anthropic/Bedrock validation rejection of replayed thinking metadata.

## Summary

Close as implemented on main and shipped: the replay sanitizer now removes Anthropic/Bedrock thinking or redacted-thinking blocks without a usable signature before provider conversion, while preserving a valid non-empty assistant turn. That directly prevents the reported pruning path from promoting an unsigned empty block into the latest replayed assistant message.

## What This Changes

Prevent unsigned empty Anthropic thinking blocks from poisoning replayed session history after pruning and causing permanent provider 400 errors.

## System Context

OpenClaw stores agent conversations as session history, then assembles and sanitizes a replay view before sending it to a selected model provider. The affected boundary is the replay sanitizer between persisted assistant messages and the Anthropic/Bedrock request converter; it determines whether a malformed historical thinking block can reach the provider.

  C --> D{Thinking block has usable signature?}
  D -- No --> E[Drop block and preserve assistant turn shape]
  D -- Yes --> F[Provider request conversion]
  E --> F
  F --> G[Anthropic or Bedrock response]

## Best Possible Solution

Keep the shipped replay sanitization as the canonical protection; any separate work on pruning older valid signed thinking blocks should remain scoped to its own provider-contract and context-cost decision.
