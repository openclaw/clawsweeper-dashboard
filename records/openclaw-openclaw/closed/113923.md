## Label Justifications

- `P2`: The bug makes long rendered file previews inaccessible in a bounded Control UI surface, but raw-text viewing remains an available workaround.
- `impact:ux-friction`: Affected users must leave the rendered reader or switch to raw text to access content below the clipped viewport.

## Summary

This issue is a duplicate of the already-open canonical sidebar-scroll report. The workspace file browser opens files through the same Control UI sidebar path, and current main still has the shared flex/overflow layout identified by the earlier report.

## What This Changes

The issue requests that long rendered Markdown files in the Control UI workspace sidebar remain vertically scrollable instead of being clipped.

## System Context

The Control UI workspace browser fetches a selected session file and passes it to the shared detail sidebar. That sidebar renders Markdown inside a flex layout, whose content container must shrink and scroll when a document exceeds the available height.

## Architecture Diagram

  C --> D[Rendered Markdown content]
  D --> E{Flex layout shrinks content}
  E -->|Yes| F[Scrollable document]
  E -->|No| G[Clipped document]

Keep https://github.com/openclaw/openclaw/issues/107571 as the single canonical fix: repair the shared sidebar flex sizing, verify scrollHeight/clientHeight and scrollTop behavior with long Markdown, and cover the workspace file-preview entry point alongside the existing sidebar and modal surfaces.
