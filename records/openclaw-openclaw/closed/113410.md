## Summary

Keep this issue open. The reported failure is a compatibility-sensitive latent regression in the Claude CLI session catalog: the current default still matches existing seeded routes, but a future default-model change can make those routes disappear from session creation. The issue is maintainer-labeled and authored by a repository member, so it requires explicit maintainer handling rather than automated cleanup; the recent Opus 5 work by fuller-stack-dev is useful provenance but deliberately did not change this default-routing behavior.

## What This Changes

Replace the Claude CLI session-creation check’s single hardcoded model probe with deterministic discovery of an Anthropic model that is actually routed to `claude-cli` for the requested agent.

## System Context

The Anthropic extension turns configured model and agent-runtime policy into a session-creation capability for the Claude CLI backend. Setup and documented model-scoped routes feed that decision; the resulting model/runtime pair is then offered to the session catalog.

## Architecture Diagram

## Best Possible Solution

Define and implement deterministic, agent-scoped Claude CLI route discovery in the Anthropic extension, preserve existing configured model routes across a default-model bump, and add regression coverage for older-only, newer-only, no-route, and multiple-route configurations before changing the default.

## Reproduction Assessment

No live current-main failure is present while the canonical default remains `claude-opus-4-8`, but the report gives a high-specificity source reproduction: move that probe to a newer model while retaining an existing model-scoped `claude-cli` route and session creation becomes unavailable.

## Solution Assessment

Unclear until maintainers choose the deterministic precedence for multiple eligible routes. A route-aware resolver is safer than rewriting every existing configuration for each future default-model bump, provided selection follows a documented agent-scoped order.
