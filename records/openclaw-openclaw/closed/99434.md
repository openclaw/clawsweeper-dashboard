## Summary

Current main and shipped releases already fix the reported custom-OPENCLAW_HOME managed-skill path bug: managed skill prompt locations are preserved as readable state-root paths when `~` would resolve to the wrong OS home.

## What This Changes

The issue reports managed skill `<location>` entries compacting to `~/.openclaw/skills/...` under custom `OPENCLAW_HOME`, causing read-tool ENOENT against the OS home.

## Best Possible Solution

Keep the shipped managed-skill prompt path preservation and ask reporters on older versions such as 2026.6.3 to upgrade to a release containing the fix.

## Reproduction Assessment

No current-main failure is reproducible from source: the path formatter now preserves explicit state-root managed skill paths and regression coverage checks the exact stale `~/.openclaw/skills/...` shape. The original failure is well explained for older versions because the read tool expands `~` through the OS home.

## Solution Assessment

Yes. The shipped fix is the narrow maintainable solution: keep token-saving `~` compaction when it resolves correctly, but preserve absolute managed/plugin skill paths when `~` would point at the wrong home.
