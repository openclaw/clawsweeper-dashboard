## Summary

Keep open. Current main and the latest release still make voice-call speak only after the completed embedded-agent result, and this PR uses the right existing block-reply seam, but the latest head can still queue multiple early TTS attempts before the first delivery resolves and it lacks live voice-call proof.

## What This Changes

The PR wires voice-call response generation to start TTS from embedded-agent block replies, returns an `earlyTextSpoken` fallback gate, and expands response-generator regression tests.

## Best Possible Solution

Keep the `onBlockReply` seam, but gate early TTS with a separate attempted/in-flight state so only one early speak can start, preserve fallback after failed delivery, and require redacted live voice-call proof before merge.

## Reproduction Assessment

Yes, at source level: current main waits for `runEmbeddedAgent()` before speaking, and PR head can start multiple early `onEarlyText` calls before the first TTS promise resolves. I did not run a live Twilio/VoIP roundtrip in this read-only review.

## Solution Assessment

No as currently written: reusing `onBlockReply` is the right narrow seam, but the early delivery gate must block additional attempts while the first TTS call is pending and real transport proof is still required.
