## Summary

Keep open for normal PR handling: the patch is a narrow, likely correct hardening change with no blocking findings, but it intentionally fail-closes Google Meet API JSON bodies over the shared 16 MiB cap, so maintainers should accept that compatibility tradeoff before merge.

## What This Changes

This PR replaces three successful Google Meet API `response.json()` reads in `extensions/google-meet/src/meet.ts` with the shared `readProviderJsonResponse` SDK helper.

## Best Possible Solution

Use the shared bounded provider JSON helper for the Meet API success-response path, and track broader Google Calendar/OAuth response hardening separately if maintainers want plugin-wide coverage.

## Reproduction Assessment

Yes from source: current `main` uses `response.json()` for the three targeted success-response paths, and the shared helper has tested overflow behavior. I did not run a fresh local repro in this read-only review.

## Solution Assessment

Yes for the stated Meet API surface: the PR reuses the existing plugin SDK helper rather than adding a plugin-local reader. The only open judgment is whether maintainers accept the standard 16 MiB fail-closed cap for this plugin path.
