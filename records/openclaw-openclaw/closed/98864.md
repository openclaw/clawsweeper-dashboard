## Summary

Keep open: current main still ignores `timeoutSeconds` in the Codex dynamic-tool per-call timeout reader, so the requested bug fix remains necessary and narrow.

## What This Changes

Dynamic tool hard-call timeout resolution should treat positive finite `timeoutSeconds` as the seconds-form fallback when `timeoutMs` is absent.

## Best Possible Solution

Implement one narrow Codex app-server timeout-reader fix that preserves `timeoutMs`, falls back to positive finite `timeoutSeconds * 1000`, ignores invalid values, and keeps main-thread plus side-question behavior aligned with focused tests.

## Reproduction Assessment

Yes, from source inspection: a call argument object with only `timeoutSeconds` reaches the current `timeoutMs`-only reader and falls back to configured/default timeouts. I did not run a live or unit reproduction in this read-only review.

## Solution Assessment

Yes: the narrowest maintainable fix is to update the existing timeout-reader boundary and regression tests, rather than adding a new config option or changing broader timeout policy.
