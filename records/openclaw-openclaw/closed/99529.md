## Summary

Keep open: the fix shape is useful and the contributor added real cold-cache proof, but the patch can make unrescanned usage-cost entries computed under old pricing look fresh after a checkpointed or bounded refresh.

## What This Changes

The branch moves usage-cost cache `pricingFingerprint` to the cache file level, strips it from serialized entries, sets the active fingerprint before refresh writes, and adds a cold round-trip test.

## Best Possible Solution

Use one canonical cache schema that rebuilds or clears all old-fingerprint entries before stripping per-entry fingerprints, with tests for cold cache, pricing-change invalidation, and checkpoint or bounded refresh reloads.

## Reproduction Assessment

Yes, source-level: current main writes `pricingFingerprint` on every cache entry, and the PR diff shows a mixed-cache path where old entries can inherit the new file-level fingerprint after reload. I did not run tests because this review was constrained to read-only inspection.

## Solution Assessment

No. Moving the fingerprint to the cache level is the right direction, but the implementation must preserve pricing invalidation for partially refreshed or checkpointed caches before it is the best fix.
