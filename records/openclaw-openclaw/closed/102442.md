The PR changes Android notification text sanitization to truncate at a UTF-16-safe boundary and adds a regression test for an emoji straddling the 512-code-unit cap.

## Best Possible Solution

Land the narrow Android Kotlin sanitizer and regression test after the contributor adds redacted real Android notification-forwarding proof that the boundary case stays well-formed.

## Reproduction Assessment

Yes. Source inspection shows current main uses `normalized.take(512)`, so a string with 511 BMP code units followed by an emoji can retain only the emoji's high surrogate; I did not run Android tests in this read-only review.

## Solution Assessment

Yes. A local Kotlin helper at the Android notification sanitizer is the narrowest maintainable fix because Android cannot reuse the TypeScript helper, and the PR preserves the existing trim/null/512-code-unit behavior except when the cut would leave a high surrogate.
