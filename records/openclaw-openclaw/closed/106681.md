## Summary

The reported implementation flaw is not present: OpenClaw already launches the exec tool through `child_process.spawn`, while accepting shell syntax is an intentional tool contract rather than accidental argument interpolation. The meaningful remaining concern—preventing prompt-injected or content-derived commands from reaching privileged execution—is already tracked by the broader canonical security issue.

## What This Changes

Prevent prompt injection or malformed model output from turning shell-tool input into destructive command execution, preferably by replacing shell parsing with argument-array execution.

## Best Possible Solution

Keep the intentional shell-command runner and its argv-safe process launch, then resolve provenance-aware blocking, risk classification, and approval UX in https://github.com/openclaw/openclaw/issues/54508 with focused bypass tests covering untrusted content and destructive commands.
