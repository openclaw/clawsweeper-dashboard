## Summary

Current main still concentrates the full WebSocket connection lifecycle in one handler, and this newly opened, assigned, maintainer-labeled cleanup remains necessary. The requested boundary follows existing helper seams and fits current security and stability priorities, but it needs deliberate owner review because every Gateway client traverses this path.

## What This Changes

Split the Gateway WebSocket message handler into focused pre-auth, authentication, authenticated-dispatch, and shared response/error modules without changing protocol or runtime behavior.

## Best Possible Solution

Extract the pre-auth, connect/auth, authenticated-dispatch, and response/error phases around one explicit connection-state owner, preserving invariant comments and proving equivalent ordering with focused and broad Gateway tests.
