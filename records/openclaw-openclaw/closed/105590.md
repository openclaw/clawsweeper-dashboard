## Summary

Current main and the latest release do not provide HealthKit access. The focused architecture remains necessary and fits established iOS permission, node-capability, and gateway command-policy seams, but this protected sensitive-data feature needs maintainers to approve the health-purpose, disclosure, retention, revocation, and dual-consent contract before implementation.

## What This Changes

Add an opt-in iOS node command that returns fixed, on-device HealthKit aggregates after both iOS and gateway authorization.

## Best Possible Solution

Approve and implement only a fixed-schema, read-only, on-device aggregate command with user-initiated HealthKit consent, explicit provider/history disclosure and revocation, conditional capability advertisement, gateway dangerous-command opt-in, and conservative unavailable or no-data responses.
