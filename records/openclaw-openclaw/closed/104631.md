## Summary

Current main and v2026.6.11 both retain fixed 1 GiB warning and 2 GiB critical heap-used thresholds, so the false-positive diagnostic remains. The report is actionable and corroborated, although source inspection proves event emission, logging, and optional bundle capture—not an OpenClaw-owned automatic restart listener—so the repair should stay focused on adaptive threshold classification.

## What This Changes

Replace fixed gateway heap-pressure thresholds that misclassify larger V8 heaps as critically pressured despite substantial remaining heap headroom.

## Best Possible Solution

Derive default heap warning and critical thresholds from V8’s effective heap limit with conservative bounds, leave RSS threshold and RSS growth detection unchanged, and add focused coverage for default, constrained, and enlarged heaps without adding configuration.

## Repair Work Prompt

Fix the gateway diagnostic-memory bug reported at https://github.com/openclaw/openclaw/issues/104631: fixed 1 GiB warning and 2 GiB critical heap-used defaults misclassify processes configured with larger V8 heaps. Use Node’s supported V8 heap statistics to derive default heap warning and critical thresholds from the effective heap size limit, with conservative bounds that preserve meaningful behavior for default and constrained heaps. Keep RSS threshold and RSS growth behavior unchanged. Add focused regression tests for a default or constrained heap and an approximately 8 GiB heap, proving that about 2 GiB heap use is not critical when substantial V8 headroom remains and that near-limit usage is still classified appropriately. Do not add an openclaw.json key, environment variable, compatibility fallback, new restart listener, or CHANGELOG.md edit. Treat the reported manager/supervisor restart behavior as validation context unless current source proves it belongs to this module.
