## Label Justifications

- `P1`: The shipped-release bug can make long-running OpenAI-compatible agent sessions lose model-visible tool output and break active user workflows.
- `impact:session-state`: The failure corrupts the model-visible session context by replacing real tool-result text with a placeholder.
- `impact:message-loss`: Plain-text tool-result messages can be suppressed from the model-visible conversation, causing retries or missing replies.
- `maturity:stable`: The affected gateway/agent runtime prompt-history path maps to the M4 Stable gateway-runtime feature in the maturity shortlist.

## Summary

Close: current main implements the reported fix path. Aggregate prompt-history truncation now protects fresh trailing tool results and uses a bounded elision marker instead of silently emptying text, while OpenAI-compatible replay uses media-aware placeholders instead of treating empty non-media output as an image.

## What This Changes

Report that aggregate tool-result truncation empties text and makes OpenAI-compatible providers send image placeholders for plain-text tool outputs.

## Best Possible Solution

Keep the current-main prompt projection and media-aware provider replay behavior, then ship it in the next stable release.

## Reproduction Assessment

Yes, source-level against v2026.6.11: clearToolResultText wrote empty text and OpenAI-compatible replay used the image placeholder for empty tool output. Current main no longer has that failure shape, and focused regression tests cover the saturated-history fresh-output case.

## Solution Assessment

Yes. The current-main fix addresses both required layers: aggregate truncation preserves or marks text instead of silently emptying it, and provider replay reserves image placeholders for actual media.
