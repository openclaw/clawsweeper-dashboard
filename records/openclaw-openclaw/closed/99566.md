The PR updates exec approval command-display truncation to use `truncateUtf16Safe` and adds a regression test for an emoji surrogate pair crossing the 16 KiB display cap.

## Best Possible Solution

Merge the narrow sanitizer change after normal maintainer review and CI; keep channel-specific preview fixes such as https://github.com/openclaw/openclaw/pull/99539 separate.

## Reproduction Assessment

## Solution Assessment

Yes. Reusing the existing UTF-16-safe helper at `truncateForDisplay` fixes every caller of that sanitizer without changing caps, redaction ordering, marker text, or approval payload contracts.
