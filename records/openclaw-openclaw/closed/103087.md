## Summary

Keep open. Current main still returns wiki-corpus pages from the shared bridge vault without applying agent/session visibility, and the companion memory-core supplement path drops agent identity before reaching the same lookup; this is a security-sensitive scoping bug, not cleanup.

## What This Changes

Scope memory-wiki bridge vault reads by caller agent and session so sandboxed agents cannot read another agent's bridged memory through wiki or memory fallback tools.

## Best Possible Solution

Add one canonical agent/session visibility gate for bridged memory-wiki pages and corpus supplements, using bridge ownership metadata, and cover direct `wiki_get`/`wiki_search` plus `memory_get`/`memory_search` `corpus=all` with multi-agent sandbox regression tests.
