## Label Justifications

- `P1`: A deterministic foreground reconnect breaks the native iOS multi-chat workflow and hides the active conversation from users.
- `impact:session-state`: The selected chat session is replaced by the main-session selection during reconnect even though the gateway conversation remains present.
- `impact:ux-friction`: Users must avoid backgrounding the app or recover hidden conversations through Control Activity or another client surface.

## Summary

Keep this issue open: current main still clears the focused iOS chat during a forced reconnect, and the linked fix remains an open PR rather than merged current behavior. The discussion correctly narrowed the confirmed defect to client-side focus loss; repeated creation of orphan sessions remains a separate unverified claim.

## What This Changes

Preserve the selected non-main iOS chat across same-gateway foreground reconnects without carrying session state across gateway switches.

## Best Possible Solution

Preserve focusedChatSessionKey only when reconnecting to the same stable gateway, clear it on gateway replacement, prove both paths on an iPhone or simulator, and separately use gateway session telemetry to confirm or reject the orphan-session claim.

## Reproduction Assessment

Yes at source level: foreground stale-connection recovery reaches connection preparation that clears the focused chat key and falls back to main. Two reports provide consistent device observations, although this review did not independently run an iOS device reproduction.

## Solution Assessment

Yes for the confirmed focus-reset defect: preserving focus only for the same stable gateway is narrower and safer than unconditional persistence or a new gateway resume protocol. Orphan-session cleanup should not be bundled without a separate confirmed reproduction.
