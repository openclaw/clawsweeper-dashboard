## Summary

Keep open: current main has restart deferral, stale-process cleanup, `/readyz`, and startup-unavailable pieces, but it still does not define one shared partial-reload/degraded-state contract for Control UI and `sessions.resolve`. The related WebChat issue and open PR address a narrower missing-notice subset, not the broader macOS launchd partial-reload recovery problem.

## What This Changes

The issue requests more deterministic macOS launchd Gateway reload recovery so live plugin/config maintenance does not expose a partially alive Control UI with misleading session errors or doctor-dependent recovery.

## Best Possible Solution

Define one Gateway reload/degraded readiness state that `sessions.resolve` and Control UI consume, keep launchd restart recovery deterministic, and validate it with a live macOS managed-Gateway replay.
