## Label Justifications

- `impact:message-loss`: The report concerns a claimed silent no-reply stall after a user message during context overflow recovery.
- `impact:session-state`: The reported surface is session context compaction and retry state after preflight overflow detection.

## Summary

Current main and shipped releases already recover these compact preflight routes without adding `handled:true`; the missing flag is part of the contract that lets the outer run loop perform compaction/truncation and retry.

## What This Changes

The issue asks to add `handled:true` and `source` fields to `compact_only` and `compact_then_truncate` preflight recovery results to prevent silent session stalls.

## Best Possible Solution

Keep the existing contract: `handled:true` means recovery already happened, while compact routes should continue through the outer overflow-compaction path before retrying.

## Reproduction Assessment

No, not against current main. Source and regression tests show the compact routes without `handled:true` are routed into overflow compaction and retried, which contradicts the claimed stall path.

## Solution Assessment

No, adding `handled:true` to these compact routes is not the best fix. It would mark compaction as already complete and bypass the outer recovery branch that currently performs the needed compaction/truncation work.
