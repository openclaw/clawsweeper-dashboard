## Summary

Keep open, but this patch is not merge-ready: it targets a real restart-continuation delivery class, yet removes the deliberate session-id mismatch guard that prevents stale queued continuations from running after a session key rebounds.

## What This Changes

The branch narrows restart-continuation fallback from any expected-session mismatch to only missing session entries, and updates restart-sentinel tests to dispatch after a queued session id changes.

## Best Possible Solution

Preserve the session-id mismatch guard unless a proven stable identity can distinguish same-session reload rotation from true session-key rebinding, then add current-head real gateway proof and focused tests for both cases.

## Reproduction Assessment

Partially. Source inspection shows current main demotes queued continuations when `entry.sessionId` differs from `expectedSessionId`, and the PR's new test exercises that path, but no live after-fix proof demonstrates the reported reload-only rotation.

## Solution Assessment

No. Narrowing the guard to only missing entries is too broad because the current implementation intentionally treats a changed session id as a stale/rebound-session guard, and this PR does not prove a safe same-session rotation discriminator.
