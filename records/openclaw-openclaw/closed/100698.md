## Summary

Keep open: the iOS slice is now merged on current main, but the Android app still lacks custom-header storage/UI/injection on main and the linked Android implementation remains open for owner/security review. The protected `maintainer` label also rules out conservative cleanup closure.

## What This Changes

Allow iOS and Android mobile apps to store and attach per-gateway custom HTTP headers for gateways behind authenticating reverse proxies.

## Best Possible Solution

Review and land the Android implementation only after owner/security approval confirms the arbitrary-header credential lifecycle, then close this issue when both mobile platform slices are on main and release notes can describe the supported deployment shape.
