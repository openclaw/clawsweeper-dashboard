## Summary

Keep open. The report describes a concrete compaction-path plumbing defect: safeguard-generated summaries can lose both the session thinking level and the wrapped provider stream transport, so provider-specific request shaping is skipped. The supplied evidence distinguishes this from the related Ollama catalog-resolution and split-turn-summary reports, but current-main source confirmation is still needed before dispatching a repair. Likely related people: jasonvassallo is the detailed runtime reporter (low-confidence routing; feature-history ownership was not established from the available read-only evidence).

## What This Changes

Preserve the session thinking level and provider-wrapped stream function when the compaction safeguard generates staged LLM summaries, so compaction uses the same reasoning and provider request handling as normal turns.

## System Context

OpenClaw’s compaction safeguard condenses long agent-session history before the next turn can run. It passes session messages and model settings into a staged summarization path, which calls the agent-core summarizer and then the selected provider transport to produce the replacement session summary.

## Architecture Diagram

flowchart LR
  A[Session messages and thinking level] --> B[Compaction safeguard]
  B --> C[Staged summary pipeline]
  C --> D[Agent-core summarizer]
  D --> E[Provider stream wrapper]
  E --> F[Compaction summary]
  F --> G[Updated session context]

## Best Possible Solution

Thread the already-resolved session `thinkingLevel` and wrapped `streamFn` through the safeguard’s staged-summary interfaces into the agent-core summarizer, remove or update obsolete arity compatibility logic, and add a focused regression test that proves compaction invokes the wrapped transport with the resolved reasoning setting.
