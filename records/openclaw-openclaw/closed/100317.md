- **[P2] Validate Serve proxy targets before advertising fallbacks:** `src/shared/tailscale-status.ts:100`
  - body: This helper still accepts a Serve route when the proxy only matches the loopback port. A stale `http://127.0.0.1:18789` proxy can be advertised as a `wss://` fallback for a TLS-enabled Gateway, and a proxy target with a backend path can route the WebSocket handshake away from the Gateway root. Compare the expected backend scheme and require a root-only target before adding the URL.
  - confidence: 0.91
- **[P2] Verify setup endpoints before dropping fallbacks:** `apps/ios/Sources/Gateway/GatewayConnectionController.swift:229-235`
  - body: This probe only checks that TCP opens before `selectingEndpoint` drops every other route. On a network with any host listening at the same RFC1918 address and port as the LAN URL, the app can persist the wrong endpoint and never try the advertised Tailnet fallback; verify the Gateway/WebSocket path or keep fallbacks through connection failure. This concern was visible in the prior reviewed head, so it is a late finding.
  - late: true
  - confidence: 0.86
- **[P2] Document gatewayUrls in the protocol docs:** `packages/gateway-protocol/src/schema/devices.ts:115-117`
  - body: The schema now returns optional `gatewayUrls`, but `docs/gateway/protocol.md` still documents `device.pair.setupCode` as returning only `gatewayUrl`. Protocol clients rely on that public page, so add the new field and its ordering/compatibility semantics there.
