## Summary

Keep open: current main has the client-side optimistic-tail preservation, but `chat.send` still ACKs before the normal user-turn recorder/persistence path, and the open gateway-side candidate PR remains unresolved.

## What This Changes

The issue reports silent WebChat user-message loss when `chat.send` returns before the durable transcript catches up and `chat.history` reconciles from an older snapshot.

## Best Possible Solution

Make the Gateway/WebChat contract explicit: after `chat.send` ACK, a user turn should either be durably visible/progressing or visibly fail without duplicate transcript entries, while keeping the current UI optimistic-tail preservation.
