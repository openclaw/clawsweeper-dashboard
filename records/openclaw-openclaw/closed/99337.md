## Summary

Keep this PR open: it targets a real MCP tool-filter regex risk, but the proposed cap still allows the 32-wildcard boundary and a same-shape Node probe took seconds to fail, so the ReDoS class remains reachable.

## What This Changes

The PR adds a wildcard-count guard to MCP glob matching in the agent bundle runtime and materialization paths.

## Best Possible Solution

Replace the duplicated regex conversion with a shared linear `*` matcher for MCP filters, preserve the documented exact-name/simple-glob semantics, and add regression coverage for both normal filters and repeated-wildcard adversarial inputs.

## Reproduction Assessment

Yes. Source inspection shows both MCP filter paths compile configured `*` patterns into regexes, and a read-only Node probe reproduced multi-second failure time for an accepted 32-wildcard pattern.

## Solution Assessment

No. The cap is a plausible mitigation, but it leaves the regex backtracking mechanism reachable at the allowed boundary; a linear segment matcher is the safer maintainable fix.
