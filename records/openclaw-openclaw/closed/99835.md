## Summary

Keep open: current main and the latest release still use the loaded-plugin-only fast guard, so a Telegram topic child key can miss the thread rejection before Telegram is loaded; two open closing PRs now own the fix path.

## What This Changes

The issue asks for `sessions_send` to reject Telegram forum-topic child session keys before inter-agent dispatch even when the Telegram plugin has not been loaded.

## Best Possible Solution

Land one plugin-boundary-respecting fix that makes the `sessions_send` guard use Telegram's lightweight session-key resolver before dispatch, with focused regression coverage, then close the overlapping candidate PR.

## Reproduction Assessment

Yes, at source level: current `sessions_send` calls `parseSessionThreadInfoFast`, the fast resolver returns no thread metadata when Telegram is not loaded, and the generic fallback only recognizes `:thread:`. I did not run tests because this review is read-only and the source path is already clear.

## Solution Assessment

Yes, the best fix is to reuse the plugin-aware lightweight session-key resolver for this guard and add a focused `sessions_send` regression test. Adding Telegram `:topic:` semantics to the generic parser would be a weaker owner-boundary fit because other channels can use `:topic:` differently.
