## Summary

The cited module does not load plugins or contain an asynchronous initialization lock: it synchronously registers connected node sessions and replaces capability/tool snapshots, while plugin runtime loading is owned by a separate synchronous loader. The report is therefore not currently reproducible or actionable, but it is new and salvageable if the reporter supplies the exact API call, plugin, logs, and concurrent sequence linking these surfaces.

## What This Changes

Prevent duplicate gateway node capability registrations and memory growth allegedly caused by concurrent loads of the same plugin.

## Best Possible Solution

Capture a minimal current-main reproduction naming the gateway request, plugin, node connection, and duplicate observable; if it proves a race, enforce single-flight behavior at the plugin runtime registry owner and add a deterministic concurrent-call regression test without adding request-time discovery to `NodeRegistry`.
