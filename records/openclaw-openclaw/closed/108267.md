## Summary

Keep open: current main still has the reported SSRF-policy gap, but this patch is not merge-ready because its optional guarded path leaves the normal default-deny case unguarded and discards guarded-response cleanup ownership.

## What This Changes

Propagates provider SSRF request policy into BytePlus, Runway, Together, and xAI video polling and download sub-requests.

## Best Possible Solution

Always use the guarded request primitive for provider follow-up URLs, including when no policy override is configured, and preserve cleanup ownership until the response body is consumed; add provider-level tests for default deny, explicit private-network allowance, dispatcher forwarding, retries, and release-on-success/error.
