## Summary

Keep open: the report identifies a concrete Windows-specific archive durability failure that can repeatedly stall the gateway, and no merged fix or canonical issue was found for this exact writable-descriptor path.

## What This Changes

Fix Windows SQLite transcript archiving so fsync uses a writable temporary-file descriptor and cannot repeatedly block session maintenance after an EPERM failure.

## Best Possible Solution

Update the archive writer to write and fsync through one writable exclusive-create descriptor, add a real Windows filesystem regression test, and track any worker/off-main-thread archive materialization separately from this narrow correctness fix.
