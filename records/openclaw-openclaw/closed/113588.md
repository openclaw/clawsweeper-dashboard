## Summary

Keep this PR open for repair. Its central binding fix is ineffective: every changed call passes a configured default agent as a second argument to a resolver that accepts only the session key and falls back to `main` for opaque keys, so JavaScript ignores the new argument and affected bindings still record `main` rather than the configured agent.

## What This Changes

The PR tries to restore configured default-agent metadata for opaque Discord, Feishu, Matrix, and account-scoped conversation bindings, while making macOS fixture-path and session-store cleanup tests more stable.

## System Context

Channel adapters create or update conversation bindings that associate a channel conversation with an agent session key. The shared binding service then uses the stored agent metadata to route later interactions to the intended configured agent.

## Best Possible Solution

Replace the four calls with the existing configuration-aware session-agent resolver, passing each adapter’s config, then add focused regressions for opaque keys with a non-`main` configured default and attach redacted after-fix runtime evidence from one supported channel flow.
