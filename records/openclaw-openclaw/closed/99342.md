## Summary

Current main and v2026.6.11 already address the reported Telegram `/models` callback stall class: model browsing now uses bounded read-only catalog loading, and the repeated setup-registry scans behind provider/model selection are cached rather than rebuilt for each picker step.

## What This Changes

The issue reports Telegram `/models` inline provider browse/list callbacks blocking for 120s+ with unstable provider-list behavior on OpenClaw 2026.6.6.

## Best Possible Solution

Keep the shipped v2026.6.11 implementation; ask for a new report only if `/models` inline callbacks still stall on v2026.6.11 or newer with fresh timing logs.

## Reproduction Assessment

No current-main repro remains from source review: the old v2026.6.6 hot path matches the merged `/models` setup-registry and bounded browse fixes, and those fixes are present on current main. I did not run a live Windows Telegram timing repro.

## Solution Assessment

Yes. The shipped fix addresses the maintainable hot path by bounding read-only catalog browsing and caching repeated setup-registry scans instead of adding a new config knob or Telegram-only workaround.
