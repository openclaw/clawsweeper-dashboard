## Summary

Keep this PR open for revision: trimming at the shared gateway RPC boundary changes valid exact-path behavior, so a workspace file or directory whose name intentionally begins or ends with whitespace can resolve to a different target or become inaccessible.

## What This Changes

The PR trims leading and trailing whitespace from relative paths used by `agents.workspace.list` and `agents.workspace.get`, with regression coverage for padded paths.

## Best Possible Solution

Preserve exact filesystem path semantics in the gateway protocol and, if paste-friendly trimming is wanted, perform it only in an explicitly user-entry-oriented client surface that cannot represent whitespace-bearing names ambiguously.
