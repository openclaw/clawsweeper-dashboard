## Label Justifications

- `P2`: The report concerns a bounded authentication integrity race, but the affected legacy runtime path has already been removed and shipped.
- `impact:security`: The alleged race would allow credential contents to change between validation and use.
- `impact:auth-provider`: The reported symptom concerns provider credential discovery and authentication handshakes.

## Summary

The reported file-validation race is no longer present in the supported auth path: OpenClaw moved runtime auth profiles to the per-agent SQLite database and removed the legacy JSON read path before this issue was filed; that architecture shipped in v2026.6.5.

## What This Changes

Eliminate a reported check-then-read race when discovering authentication credentials from a token file.

## Best Possible Solution

Keep runtime auth discovery on the canonical SQLite store and continue handling any legacy JSON credential files exclusively through the existing `openclaw doctor --fix` migration path.

## Maintainer Decision

Required: false

## Reproduction Assessment

No. Current main does not perform the reported token-file check followed by a second payload read in these modules; discovery consumes the SQLite-backed auth store and credential conversion is in-memory.

## Solution Assessment

Yes. Removing runtime credential-file reads in favor of one canonical transactional SQLite store is narrower and safer than adding descriptor locking to a retired JSON path.
