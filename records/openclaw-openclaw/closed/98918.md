## Summary

Keep open: current main partially protects normal Telegram spawns by keeping Telegram top-level placement as `current` and hiding thread fields, but the child-topic binding primitive still exists and the default/opt-in behavior needs a focused regression decision before this can be considered solved.

## What This Changes

Request to keep internal Telegram sub-agent runs hidden or grouped under the parent conversation by default instead of creating fresh user-visible threads.

## Best Possible Solution

Define the intended Telegram default, then add a focused fix or regression guard that keeps internal subagent fan-out hidden or parent-grouped by default while preserving any explicit opt-in topic-per-subagent workflow.

## Reproduction Assessment

Yes at source level for the explicit child-placement path, but not as a live default-flow repro: current source has a Telegram child-topic creation path for bound child placement, while normal Telegram tool exposure currently prefers `current` placement and hides thread fields.

## Solution Assessment

No complete fix is proven on main; the safest path needs maintainer direction on default Telegram subagent visibility versus explicit topic-per-subagent workflows, plus regression and live Telegram proof.
