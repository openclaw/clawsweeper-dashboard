## Summary

Keep open for explicit product and security-boundary design: current main can short-circuit individual messages before model execution, but it still integrates agent-harness and session runtime code, while the linked dummy-model PR deliberately addresses only a narrower operational fallback.

## What This Changes

Request a supported deterministic gateway deployment profile that excludes the AI harness while retaining channels, authenticated webhooks, cron, media delivery, and explicitly enabled plugins.

## Best Possible Solution

Define one maintainer-approved control-plane architecture—preferably coordinated with the runtime-split RFC—with an artifact-level no-harness guarantee, explicit deterministic plugin and cron APIs, no AI credential/session initialization, and status or diagnostics that attest to the active capability boundary; treat the dummy-model PR only as optional compatibility UX.

Question: Should OpenClaw support a first-class no-harness control-plane deployment, and if so should it be delivered through the broader gateway/runtime process split or a separately packaged gateway profile?

Rationale: Plugins can short-circuit model turns, but they cannot prove that agent runtime code and credentials are absent; selecting the permanent process, packaging, security, and compatibility boundary requires maintainer intent.

Likely owner: jalehman

Owner reason: They merged the central deterministic interception seam and have adjacent provider-runtime boundary history.

Owner confidence: medium

Options:

- **Unify with runtime split (recommended):** Make the lightweight gateway/control plane from https://github.com/openclaw/openclaw/issues/42026 the canonical architecture and add deterministic plugin execution as an explicit control-plane capability.
- **Create a gateway profile:** Keep the embedded architecture but publish a separately built and validated profile that excludes agent-harness modules and AI credential paths.
- **Limit scope to plugin interception:** Decline an artifact-level boundary and document before_agent_reply plus direct tool invocation as the supported deterministic pattern, acknowledging that harness code remains installed.
