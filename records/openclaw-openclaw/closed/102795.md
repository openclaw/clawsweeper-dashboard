## Summary

Keep open: the local downloaded-image half is a good narrow fix, but the remote URL fallback is still incomplete because QQBot computes remote media types and then drops them before final `MediaTypes` reaches core. The protected `maintainer` label also makes this unsuitable for cleanup closure.

## What This Changes

The branch replaces QQBot attachment MIME lowercasing with `normalizeMimeType` and propagates canonical image MIME values from `processAttachments`, updating the attachment unit expectations.

## Best Possible Solution

Carry `remoteMediaTypes` through QQBot `InboundContext` and `buildCtxPayload` as aligned `MediaTypes` for remote `MediaUrls`, while keeping the existing canonicalization for downloaded images.
