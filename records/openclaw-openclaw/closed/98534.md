## Summary

Keep open: current main still lets plugin node.invoke policy approvals store whitespace-only title/description, and the Control UI parser drops blank-title plugin approvals. The linked fix PR is open and draft, so this issue should remain open until https://github.com/openclaw/openclaw/pull/98535 lands or is replaced.

## What This Changes

Normalize plugin-supplied node.invoke policy approval title and description so pending approvals always have non-empty UI-renderable copy.

## Best Possible Solution

Land or replace the linked fix PR with a narrow change that normalizes policy approval copy before manager registration and keeps regression coverage for whitespace-only title/description.

## Reproduction Assessment

Yes from source inspection: policy approvals store sliced whitespace-only copy, the manager registers it as pending, and the UI parser normalizes the title to empty and drops it. I did not run a live gateway/UI repro because this cleanup review is read-only.

## Solution Assessment

Yes: normalizing and falling back in the node.invoke policy approval runtime is the narrow owner-boundary fix because that path writes directly to the shared manager instead of passing through plugin.approval.request validation.
