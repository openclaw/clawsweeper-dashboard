## Summary

The one-shot recovery is well proven and no discrete correctness defect remains, but this PR invalidates Feishu authentication caches process-wide rather than for the affected account; an owner should confirm that scope and select the canonical implementation before merge.

## What This Changes

The PR detects Feishu token-invalid responses, clears SDK and CardKit token caches, resolves fresh clients, retries once, and adds recovery regression coverage.

## Best Possible Solution

Use account/app-scoped invalidation at the Feishu cache owner, retry exactly once with a freshly resolved client or token, preserve the original Feishu error when invalidity persists, and consolidate the regression and live proof in one canonical PR.
