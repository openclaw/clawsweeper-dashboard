## Label Justifications

- `P2`: The issue is a normal-priority Telegram delivery reliability bug limited to long chunked outbound replies.
- `impact:message-loss`: A rejected middle Telegram chunk can drop the remaining chunks of an outbound reply.

## Summary

Keep open: current main and the latest release still abort Telegram chunk delivery when an unhandled per-chunk send rejects, so the tail-loss problem is real and not already implemented. The issue is actionable, but the fix needs a maintainer decision on which Telegram errors are recoverable before changing partial-delivery semantics.

## What This Changes

The issue requests resilient Telegram chunked text delivery so one failed chunk does not silently drop all remaining chunks.

## Best Possible Solution

Add Telegram-owned per-chunk failure handling for recoverable validation/send failures while preserving loud failures for fatal routing, auth, topic, and non-recoverable transport errors.

## Reproduction Assessment

Yes from source: both durable Telegram chunk loops and the streaming reply helper await each chunk send without a per-chunk recovery path. I did not run a live Telegram Bot API repro in this read-only review.

## Solution Assessment

Unclear as requested: continuing after every Telegram error is not the best fix because it can hide fatal routing, auth, topic, or transport failures. The maintainable path is a narrow recoverable-error policy inside the Telegram send funnel.
