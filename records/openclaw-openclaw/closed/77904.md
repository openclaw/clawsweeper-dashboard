## Summary

Keep open: the PR fixes the right CLI model-inspection hang in the right layer, but the current helper still has a blocking stream-flush bug because it can call `process.exit` without waiting for stdout/stderr callbacks when buffers report zero queued bytes.

## What This Changes

The PR adds a one-shot default-runtime exit helper, wires it into `models list` and `models status`, and flushes the requested exit from `runCli` teardown with regression coverage.

## Best Possible Solution

Land the teardown-level one-shot exit fix only after stdout and stderr use callback-backed flush barriers before `defaultRuntime.exit`, preserving the custom-runtime and Vitest-worker exclusions and keeping changelog ownership out of the PR.

## Solution Assessment

No, not yet. Deferring the forced exit until `runCli` teardown is the right boundary, but the implementation needs an unconditional callback-backed stdout/stderr barrier instead of using `writableLength` as a flush-completion signal.
