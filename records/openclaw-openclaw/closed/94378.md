## Summary

Keep this PR open: current main and the latest release still fail fast on the first invalid strict-mode image entry, and the PR is a focused candidate for preserving valid entries from mixed batches. The remaining blocker is maintainer acceptance of a compatibility-sensitive SDK-exported strict-mode behavior change, not a concrete line-level defect in the patch.

## What This Changes

The PR changes OpenAI-compatible image response parsing so strict mode skips invalid per-entry `b64_json` values and returns valid images unless every returned entry is invalid.

## Best Possible Solution

Land the focused parser change after maintainers explicitly accept partial-success strict parsing as SDK behavior, while keeping URL/object/base64url proxy response work on separate review paths.

## Reproduction Assessment

Yes at source level: current main and `v2026.6.11` throw inside the strict parser loop on the first invalid entry before later valid entries can be returned. I did not execute tests in this read-only review, but the PR body supplies before/after terminal proof for the mixed batch.

## Solution Assessment

Yes for the mixed `b64_json` batch behavior if maintainers accept the SDK compatibility shift: deferring the strict error until after the loop is the narrow shared-helper fix. The safer alternative is preserving fail-fast as the default and adding an explicit opt-in for partial success.
