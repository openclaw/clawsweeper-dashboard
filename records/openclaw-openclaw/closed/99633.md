## What This Changes

The issue reports that CLI session reuse still invalidates in multi-sender Telegram groups because prompt tool-name hashing varies with sender ownership.

## Best Possible Solution

Keep this open as the precise tracker for making CLI session binding prompt-tool hashes derive from session-stable tool topology while preserving per-turn owner-only tool enforcement at the actual MCP listing/call layer.

## Reproduction Assessment

Yes at source level: current main still hashes prompt tools from a loopback scope that includes `senderIsOwner`, and `resolveCliSessionReuse` invalidates the CLI session when that hash changes. I did not run a live Telegram group reproduction in this read-only review.

## Solution Assessment

Yes directionally: the best fix is not to loosen session invalidation globally, but to feed session-stable tool-topology facts into the binding hash while leaving per-turn security scoping in Gateway/MCP tool resolution.
