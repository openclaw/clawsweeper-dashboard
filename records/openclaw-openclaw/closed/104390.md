## Label Justifications

- `P2`: The historical cache instability could substantially increase provider usage cost, but it did not block core runtime availability.
- `impact:auth-provider`: The report concerns provider prompt-cache input stability and cache read/write token accounting.

## Summary

Current main and v2026.6.11 already address both reported cache-instability classes: tool-result history uses a byte-stable per-attempt projection, and ordinary heartbeat runs preserve the bound channel as the prompt-routing origin instead of using the synthetic heartbeat provider. The report was captured on older v2026.6.6 behavior and does not describe the latest shipped implementation.

## What This Changes

Ensure tool-result truncation and heartbeat prompt assembly remain byte-stable across turns so provider prompt caches can reuse the existing prefix.

## Best Possible Solution

Keep the shipped stable tool-result projection and real-channel heartbeat routing; if the behavior recurs on v2026.6.11 or newer, open a new report with redacted consecutive provider payloads proving identical model, context-window, session, channel, and tool-result inputs still produce different bytes.
