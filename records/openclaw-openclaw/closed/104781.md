## Summary

Current main contains the reported producer/consumer mismatch: node-hosted skills advertise a synthetic `node://` location, the prompt requires reading that exact location, and the read tool interprets it as a gateway-local filesystem path. No canonical replacement or fix PR was found, and the protected `maintainer` label requires explicit maintainer handling.

## What This Changes

Make node-hosted skill instructions and relative resources usable from the publishing node’s actual skill directory, including custom state directories.

## Best Possible Solution

Keep this issue as the canonical regression and amend the node-owned publication/snapshot contract so the agent can consume the bounded instructions without a gateway-local read and receives the exact node-local base directory for relative `exec host=node` operations, with focused and live-shaped coverage for a custom `OPENCLAW_STATE_DIR`.
