## Summary

Keep this PR open: the central retry approach is useful and current main still permits a conflict to escape after the fast retry, but cancellation can occur during backoff and still allow another session-init attempt. The linked issue should remain the canonical tracker while the patch and real-behavior evidence are tightened. ## What This Changes

Adds typed reply-session CAS conflict errors and retries the unlocked session-initialization attempt with jittered exponential backoff, plus focused helper tests.

## Best Possible Solution

Keep the retry at the common unlocked session-init boundary, make both the delay and next iteration abort-aware, add regression coverage for aborting during sleep, and obtain maintainer confirmation that bounded retry rather than durable re-enqueue is the intended residual-delivery policy.
