  - body: Installing SIGTERM/SIGINT listeners inside shared gateway RPC changes interruption behavior for every gateway caller. Current main already has the `signal` and `onSignalAbort` seam, so `message send` should own process signals and pass an AbortSignal through that path.
  - confidence: 0.9
- **[P2] Preserve the existing timeout contract:** `src/commands/message.ts:79`
  - body: Current outbound message gateway calls default to 10,000 ms when no timeout is provided, but this line always sends 30,000 ms for `message send`.   - confidence: 0.88
- **[P2] Reject malformed timeout values visibly:** `src/cli/program/message/helpers.ts:38-40`
  - body: `parseInt` accepts partial values such as `5s`, and invalid values like `abc`, `0`, or negatives silently fall back to the default. A safety timeout flag should use the existing strict positive-integer parser and fail visibly so operators know which timeout is actually running.
  - confidence: 0.86

  - body: Root policy says `CHANGELOG.md` is release-owned and normal PRs should not edit it. Keep the release-note context in the PR body or squash message instead of adding an Unreleased entry here.
