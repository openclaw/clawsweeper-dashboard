## Summary

Keep open: current main still keys provider usage and auth-status enrichment by provider rather than by serving credential, and the linked PR explicitly split this out as a session/usage data-contract follow-up.

## What This Changes

Request credential-keyed usage/cost attribution so mixed API-key/subscription and multi-account setups show the correct billing mode and quota per session or auth profile.

## Best Possible Solution

Add a credential-aware session and provider-usage contract, migrate the affected gateway/UI/CLI surfaces to consume it, and cover mixed API-key/subscription plus multi-account scenarios with focused regression tests.

## Solution Assessment

No current provider-level attribution is not the best long-term fix. The maintainable solution is to carry credential identity or billing mode through the session and usage contracts before the UI decides whether to show subscription quota or API cost.
