## Summary

Close as a duplicate of the open canonical gateway-liveness report. This issue’s requested watchdog and automatic recovery are already tracked together with the same “process remains alive but cannot serve requests” failure mode; the reported heap pressure is useful diagnostic context to add there, but does not establish a distinct fix boundary.

## What This Changes

Add automatic recovery for a gateway that remains alive but becomes unresponsive under critical memory pressure, with optional heap-limit and diagnostic controls.

## System Context

The Gateway is OpenClaw’s long-running Node.js service: channels, CLI clients, and agent runs send work to it over HTTP/WebSocket, and it coordinates provider calls and session execution. When its event loop stalls, the process can remain present to systemd while user requests and message delivery stop progressing.
