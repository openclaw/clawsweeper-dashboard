## Summary

This remains necessary: current `main` rejects empty string attachment placeholders before the Mattermost send call, while the PR narrowly normalizes blank values as absent and preserves rejection of non-empty binary payloads. The patch looks correct and focused, but the external-contributor merge gate still needs concrete after-fix Mattermost behavior proof rather than an unsupported statement that a production-equivalent hotfix worked. ([github.com](https://github.com/openclaw/openclaw/blob/main/extensions/mattermost/src/channel.ts))

## What This Changes

The PR makes Mattermost send actions ignore blank top-level or nested `buffer` and `base64` attachment fields while continuing to reject non-empty binary payloads, with regression tests.

## Best Possible Solution

Keep the local normalization and focused tests, then merge after a redacted real Mattermost send demonstrates that text is delivered with blank placeholders and a non-empty binary payload still fails clearly.
