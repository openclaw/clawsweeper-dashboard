## Label Justifications

- `P1`: The latest stable release reportedly causes a previously working class of Anthropic-backed scheduled jobs to fail on every run.
- `impact:auth-provider`: The failure occurs when Anthropic models resolve through the claude-cli backend.
- `impact:ux-friction`: Affected operators must move jobs to another runtime or external scheduler because the cron API cannot remove the stamped policy.

## Summary

The older open report already tracks the same claude-cli/toolsAllow incompatibility, including scheduled-run failures and the inability to clear inherited policy. This report adds valuable evidence that v2026.7.1 broadened the failure to freshly created and edited jobs, but it does not establish a distinct remaining fix.

## What This Changes

Report that v2026.7.1 automatically stamps default toolsAllow policy onto cron agentTurn jobs, causing claude-cli-backed runs to fail preflight.

## Best Possible Solution

Consolidate the regression evidence into https://github.com/openclaw/openclaw/issues/103677 and preserve the shipped distinction between inherited default policy and explicit per-job restrictions: claude-cli jobs should ignore non-enforceable default metadata, while explicit restrictions continue to fail closed.

Yes at source level: defining effective toolsAllow reaches a CLI preflight that rejects runtime restrictions, and the report provides a concrete fresh-job path on v2026.7.1. A live current-main run was not performed during this read-only review.

## Solution Assessment

Yes, consolidating this report into the older canonical issue is the best tracking path. The eventual implementation should distinguish automatically inherited defaults from explicit restrictions rather than silently dropping every policy or breaking all claude-cli cron jobs.
