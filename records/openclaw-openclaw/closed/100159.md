## Summary

Keep this PR open for normal merge review: current main still stacks refreshed WhatsApp terminal QR frames, and this maintainer-labeled patch fixes that in the WhatsApp login display path with no blocking findings.

## What This Changes

The branch updates `extensions/whatsapp/src/login.ts` and its coverage test to version QR renders, clear interactive terminals before refreshed QR frames, and suppress stale async QR render results.

## Best Possible Solution

Land the narrow WhatsApp terminal login display fix once the protected maintainer and final CI gates are satisfied, keeping QR refresh ownership local to `loginWeb`.

## Reproduction Assessment

Yes, at source level: current main logs every QR event as a new terminal frame, and Baileys 7.0.0-rc13 emits refreshed QR events after the first 60 seconds and then every 20 seconds. I did not run a live WhatsApp session during this read-only review.

## Solution Assessment

Yes. Handling refresh replacement in `loginWeb` is the narrow owner-boundary fix because Baileys delegates QR display to `connection.update`, while changing `createWaSocket` or the QR renderer would affect sibling consumers that do not own this terminal frame behavior.
