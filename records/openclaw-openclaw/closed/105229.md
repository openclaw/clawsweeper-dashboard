## Summary

Current main already prevents the reported indefinite LLM request stall: it bounds the first response by provider class, honors the existing provider timeout override, and routes safe prompt timeouts into model fallback. The issue’s linked source path is outdated, but its observable blackhole-endpoint problem is addressed.

Ensure unresponsive LLM provider requests time out within a configurable deadline and trigger fallback instead of indefinitely blocking an agent queue.

## Best Possible Solution

Keep the current provider-class first-event watchdog and existing `models.providers.<id>.timeoutSeconds` override, which bound blackhole requests without imposing an unsafe universal 60-second limit on slow local generation.
