## Summary

The exact current head still has the previously reported compatibility defect: it fixes the indefinite auth wait for modern runtimes, but can synchronously stop the bootstrap on older Telegram WebViews before the existing recovery handler is installed. The added hanging-socket evidence is useful, yet it mirrors the fetch in Node rather than executing the served page in the target WebView, so the PR remains blocked on both the narrow code repair and real Telegram proof.

## What This Changes

The PR adds a 15-second deadline to the generated Telegram Mini App auth fetch and regression tests for recovery from a hanging same-origin auth request.

## Best Possible Solution

Keep the deadline at the Mini App-owned auth boundary, implement it with an `AbortController` and a cleared 15-second timer, then prove both healthy authentication and stalled-auth recovery by executing the served page in a supported Telegram WebView.
