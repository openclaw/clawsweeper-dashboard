## What This Changes

The PR changes Android link-preview image caching from a 32-entry `LruCache` to an 8 MiB byte budget while preserving a 32-result ceiling for tiny and failed results, with focused regression tests.

## Best Possible Solution

Land the narrow `LinkPreviewImageStore` byte-accounting fix after proof expectations are satisfied, keeping the existing remote-fetch and decode policy unchanged.

## Reproduction Assessment

Yes from source inspection: current main uses Android `LruCache` entry accounting for `LinkPreviewImageResult`, and AOSP documents that default sizing counts entries unless `sizeOf` is overridden. I did not run a device memory repro.

## Solution Assessment

Yes: overriding `sizeOf` inside `LinkPreviewImageStore` is the narrow owner-boundary fix for this cache-accounting bug, and the tests cover both bitmap-byte eviction and the retained entry-count invariant.
