## Summary

Keep this PR open for maintainer review. The narrowly scoped same-process exception appears coherent and retains the fail-closed behavior for foreign locks, missing files, and malformed data, but this protected exec-policy change still needs after-fix real gateway evidence before merge.

## What This Changes

The PR makes synchronous exec-approval reads preserve a valid committed policy when an asynchronous holder in the same process owns the approval-file lock, instead of returning a temporary deny policy.

## System Context

OpenClaw stores host exec-approval policy in a local file that is read while agent runs assemble their effective tool permissions. The Codex app-server integration consumes that effective policy before allowing local command execution, so a transient deny fallback can terminate an otherwise permissive agent turn.

## Architecture Diagram

  C -->|Foreign or unsafe state| F[Fail-closed deny policy]
  D --> G[Resolve effective exec policy]

  G --> H[Codex app-server execution gate]

## Best Possible Solution

Keep the exception limited to verified same-process ownership, retain deny for every uncertain state, and attach a redacted live gateway reproduction showing that concurrent approval activity no longer aborts a permissive Codex run while foreign-lock denial remains intact.
