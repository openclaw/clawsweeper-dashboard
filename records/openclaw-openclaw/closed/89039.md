## Summary

This PR remains necessary because current main only contains the narrower preserved-prompt-error fallback fix, but the branch is not merge-ready: configured provider retries still run inside the released prompt-lock interval and can preserve the takeover race for configured users.

The branch changes embedded-session transcript ownership and fencing, OpenAI retry propagation and orchestration, takeover failure handling, diagnostics, and regression coverage.

## Best Possible Solution

Force `maxRetries: 0` for every SDK request made while the embedded prompt lock is released, then honor configured provider retry counts only by rerunning full attempts after the session lock is reacquired.
