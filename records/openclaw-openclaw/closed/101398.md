## What This Changes

The branch adds an optional maxBytes bound to Feishu image/file upload helpers, forwards the existing media limit from sendMediaFeishu, and adds regression tests for string-path reads.

## Best Possible Solution

Merge the focused helper hardening after redacted real-behavior proof, or an explicit maintainer proof override, confirms oversized string-path rejection before Feishu SDK upload.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: current main calls readRegularFile without maxBytes when the upload helpers receive direct string paths, but I did not run an oversized-file repro in a real Feishu setup.

## Solution Assessment

Is this the best way to solve the issue? Yes for the helper-level hardening: passing maxBytes into fs-safe's bounded reader is the narrow maintainable fix, while the normal sendMedia local-path flow was already bounded through loadWebMedia.
