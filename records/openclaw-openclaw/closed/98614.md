## Summary

Keep open: current main still has the token-auth `sessions_spawn` path that can dispatch the `agent` method in process without forcing a synthetic `operator.write` client, and the direct candidate fix at https://github.com/openclaw/openclaw/pull/99199 remains open.

## What This Changes

The issue reports a regression where token-auth, channel-triggered `sessions_spawn` fails with `missing scope: operator.write` after upgrading from v2026.6.1 to v2026.6.11.

## Best Possible Solution

Keep this issue open until https://github.com/openclaw/openclaw/pull/99199 or an equivalent narrow `callSubagentGateway` token-auth fix lands with auth-boundary review and focused proof.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: the report gives concrete token-auth Google Chat steps, and current main shows the in-process `agent` dispatch can inherit a caller client without `operator.write`; I did not run the live channel deployment.

## Solution Assessment

Is this the best way to solve the issue? Yes, the best path is a narrow fix at the `callSubagentGateway` in-process dispatch boundary, such as the open candidate PR, with proof that it preserves the intended auth boundary.
