## Label Justifications

- `P1`: A completed subagent can fail to resume a cron orchestration workflow, leaving real multi-agent pipelines unable to continue through their supported completion path.
- `impact:message-loss`: The child completion signal is discarded after announce retries, so the requester never receives the event needed to continue.
- `impact:session-state`: The yielded requester remains out of sync with completed child state and may wait indefinitely despite all subagents having finished.

## Summary

The cron-specific evidence is useful, but the same remaining failure is already tracked by the open canonical report: terminal announce give-up leaves a `sessions_yield` requester unwoken. The canonical report explicitly includes a scheduled workflow and requests the same synthetic completion-or-failure wake behavior, so maintaining a second tracker would split diagnosis and implementation discussion.

## What This Changes

Ensure subagent completion or an explicit delivery-failure signal reaches cron-isolated requester sessions waiting through `sessions_yield`.

## Best Possible Solution

Keep one canonical implementation discussion at https://github.com/openclaw/openclaw/issues/90178 and make terminal announce failure produce a typed completion-failure event that wakes the yielded requester, while external delivery recovery remains independently retryable and idempotent.
