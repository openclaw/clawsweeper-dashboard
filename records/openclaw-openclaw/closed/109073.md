## Label Justifications

- `P0`: The v2026.7.1 upgrade can leave the entire gateway unavailable in a permanent supervised restart loop until an operator rolls back or manually moves runtime-managed state.
- `impact:crash-loop`: The startup preflight exits on every attempt and launchd immediately restarts the gateway without reaching readiness.
- `impact:ux-release-blocker`: Recovery requires rollback or manually identifying and archiving internal legacy state files, with no in-product recovery path.

## Summary

The reported v2026.7.1 crash loop is valid, but its exact Memory Core and Codex retained-source warning paths were already tracked in the canonical migration issue and associated fix PR; the additional field evidence is useful but does not establish a distinct remaining root cause.

## What This Changes

Prevent warning-only retained legacy migration sources from blocking gateway readiness and causing a supervised restart loop after upgrade.

## Best Possible Solution

Keep the canonical repair that classifies authoritative-SQLite retained sources as non-blocking notices while preserving fail-closed readiness for genuine migration blockers, with regression coverage for each migration producer.
