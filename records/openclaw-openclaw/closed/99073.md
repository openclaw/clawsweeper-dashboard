## Summary

Keep open: this is a valid Discord delivery bug fix candidate, but the patch is too broad because it drops trailing chunk reply references for explicit reply tags and non-single-use reply modes, not only implicit `first` replies.

## What This Changes

The branch gates Discord `replyTo` to the first text chunk, removes it from media-caption follow-up chunks, and updates Discord send tests to expect trailing chunks without `message_reference`.

## Best Possible Solution

Carry reply source or mode through Discord's physical chunk sender so only implicit single-use replies suppress trailing physical chunks, while explicit and `all` replies keep their current references, with focused tests for each case.

## Reproduction Assessment

Yes. Current main source and existing tests show `replyTo` becomes `message_reference` on every physical Discord chunk, and the linked issue includes shipped-version instrumentation for the same path.

## Solution Assessment

No. The patch is in the right owner module, but the unconditional low-level gate is too broad because it cannot distinguish implicit single-use replies from explicit or `all` reply references.
