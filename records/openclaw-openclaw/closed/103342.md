## Label Justifications

- `P2`: The reported login-gate flash is a limited-blast-radius Control UI usability regression, not a loss of access or data.
- `impact:ux-friction`: A refresh briefly shows an incorrect login state before the stored-token session reconnects, creating avoidable operator confusion.
- `maturity:stable`: The supplied maturity context classifies the affected Control UI surface as stable.

## Summary

The reported refresh-time login flash is already addressed by the merged Control UI connecting-splash work and is present in the current release line. The current app shell recognizes stored gateway credentials, keeps the login gate for actual failures or credential-less starts, and shows a connecting state during the initial authenticated connection instead.

## What This Changes

Fix the Control UI refresh flow so a browser with stored token credentials does not briefly show the login screen while its initial Gateway WebSocket connection is starting.

## System Context

The Control UI is the browser application that reconnects to the Gateway after a page load. Stored browser credentials feed the initial WebSocket handshake; the app shell chooses either a connecting splash, the authenticated dashboard, or the login gate based on connection and failure state.

## Architecture Diagram

flowchart LR
  A[Browser refresh] --> B[Stored token or device credential]
  B --> C[Control UI app shell]
  C --> D{Initial Gateway connection}
  D -->|Connecting with credentials| E[Connecting splash]
  D -->|Connected| F[Dashboard]
  D -->|Missing or rejected credentials| G[Login gate]

## Best Possible Solution

Keep the stored-credential connecting splash as the canonical Control UI refresh behavior and direct affected users to upgrade from 2026.6.11 to v2026.7.1 or later.
