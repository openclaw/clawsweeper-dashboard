## Summary

Current main and the latest shipped release do not match the reported failure mode: the LSP parser uses a local per-read `messages` array, resets the session buffer to the unparsed remainder, and logs only notification method names rather than retaining full JSON-RPC payloads for lifecycle debugging.

## What This Changes

The issue requests bounding or truncating LSP JSON-RPC message storage to prevent long-session heap exhaustion.

## Best Possible Solution

Close this report as not matching current or shipped behavior; a new issue should include heap snapshots, logs, or a reproducible LSP server transcript if there is a distinct oversized-frame or burst-parsing memory problem.

No. Adding a circular buffer or truncation for a non-existent retained lifecycle log is not the right fix; any future memory-hardening work needs evidence for a different failure mode such as oversized partial frames or unusually large single read batches.
