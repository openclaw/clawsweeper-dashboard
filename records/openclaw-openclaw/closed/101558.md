## Summary

Close as not reproducible: current main and the latest release do not retain all LSP JSON-RPC payloads in a session-long array; the reported `messages` array is local to one parse pass, processed immediately, and then dropped.

## What This Changes

The issue asks OpenClaw to bound or truncate LSP JSON-RPC message retention because it claims `messages.push(JSON.parse(body))` grows across long sessions until OOM.

## Best Possible Solution

Keep the existing local parse-and-dispatch design; a new report should identify a real retaining object such as `session.buffer`, pending requests, or another heap owner before adding bounds.

## Maintainer Decision

Required: false

## Reproduction Assessment

No. Source inspection on current main and `v2026.6.11` shows the reported `messages` array is local to one parse pass, complete messages are processed and dropped, and only incomplete bytes remain in `session.buffer`.

## Solution Assessment

No. Adding a circular buffer for `messages` would target data that is not retained; if heap growth is observed, the maintainable fix is to capture proof of the actual retained object and bound that path.
