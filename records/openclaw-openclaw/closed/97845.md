## Summary

The exact reviewed head still has the previously reported merge blocker: its new persistence-only scrub deliberately uses the strict, code-blind stripper, so legitimate fenced or inline tool-call examples can be deleted from the durable assistant message even though display and outbound paths preserve them. The original leak remains worth fixing and current main does not make this PR obsolete, but this mismatch must be repaired before merge.

## What This Changes

The branch adds bare, `antml:`, and `mm:` attribute-style XML tool-call parsing, streaming promotion and scrubbing, persisted-message cleanup, code-aware internal delivery sanitization, and an opt-in code-preservation mode for the Plugin SDK stripper.

Use the shared Markdown code-region scanner to pass a predicate into the persistence line-strip, prove that fenced and inline examples survive in the durable `done.message`, keep unfenced standalone degraded invokes scrubbed, and retain the Plugin SDK helper's strict default and closed namespace allow-list.
