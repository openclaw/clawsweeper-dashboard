## Summary

Keep this PR open: the foreground metadata gap raised earlier is fixed and the live proof is strong, but the prior P1 availability finding remains because all completed nonzero exec output is discarded even when changing output represents real progress.

## What This Changes

The PR changes exec loop-detection hashing and foreground failure metadata so repeated nonzero outcomes with volatile output can accumulate a no-progress streak and trigger loop blocking.

## Best Possible Solution

Preserve structured failure identity while retaining a bounded progress signal for completed nonzero results, such as hashing normalized output with known volatile identifiers removed, and add coverage for both volatile-only retries and genuinely progressing nonzero retries.
