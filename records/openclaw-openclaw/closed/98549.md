## Summary

Keep open: current main has SecretRef resolution, manifest-declared plugin tools, sender/group tool policy, and guarded fetch/SSRF primitives, but it does not have the requested conversation-scoped credential broker or opaque request handle. The `maintainer` label also makes this a protected human-handled item.

## What This Changes

Add a core credential broker for explicitly granted plugin operations so SecretRef-backed credentials can be used without exposing plaintext to plugin code.

## Best Possible Solution

Land a maintainer-approved broker seam after the scoped capability profile is accepted, reusing manifest tool contracts, tool policy, SecretRef resolution, and guarded fetch with one bundled consumer and security proof.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature/security design request. Source inspection gives high confidence that current main has SecretRef, tool-policy, manifest, and SSRF primitives but not the requested conversation-scoped credential broker.

## Solution Assessment

The requested direction is plausible and aligned, but it is not an autonomous fix; the safest solution is a narrow core-owned broker API with maintainer/security review rather than exposing more plaintext SecretRef resolution to plugin code.
