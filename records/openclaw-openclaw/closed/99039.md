The PR changes the macOS config file reader to keep config-health observation state in memory instead of reading or writing `logs/config-health.json`, with Swift regression tests for ignoring a legacy sidecar and not recreating it during suspicious-read auditing.

## Best Possible Solution

Keep this PR as the candidate fix, require redacted real macOS app proof before merge, and land the sidecar-removal shape only if maintainers accept SQLite as the durable config-health owner.

## Solution Assessment

Yes, pending proof: removing the macOS steady-state sidecar read/write is the narrow storage-boundary fix because durable config health is already in `config_health_entries` and legacy JSON belongs to doctor migration only.
