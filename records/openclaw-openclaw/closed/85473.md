## Summary

Keep open: current main still has memory-core-owned dreaming plus a sidecar path for selected memory plugins, not a public memory-plugin dreaming protocol. The ClawHub LanceDB dreaming plugin linked in the discussion is a useful workaround, and the open memory role-slot PR is related, but neither settles the requested OpenClaw-managed plugin-SDK/config/scheduler contract.

## What This Changes

Request to expose Dreaming as a memory-plugin protocol so non-memory-core memory plugins can participate in Light, REM, and Deep consolidation.

## Best Possible Solution

Decide the public dreaming ownership model first: either add a narrow plugin-SDK/config contract coordinated with memory role-slot work, or document that dreaming orchestration remains plugin-owned through ClawHub packages.
