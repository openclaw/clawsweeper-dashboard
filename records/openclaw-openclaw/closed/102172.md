## Summary

Keep open: current main and v2026.6.11 still have the reported Claude live-session cleanup path into managed-run cancellation and process-tree SIGTERM/SIGKILL, and the open sibling reports do not supersede this lifecycle/no-opt-out decision.

## What This Changes

This issue requests a Claude CLI lifecycle escape hatch or telemetry so turn-end live-session cleanup does not silently kill Workflow or other CLI-owned background child work.

## Best Possible Solution

Define an owner-approved Claude CLI lifecycle contract that preserves default orphan prevention while making in-flight CLI-owned background work observable and, if preserved, bounded by an explicit drain policy.

## Maintainer Decision

Question: Should Claude CLI turn-end cleanup remain unconditional, or should OpenClaw add a bounded drain and telemetry contract for in-flight CLI-owned background grandchildren such as Workflow runtimes?

Rationale: The source confirms the current cleanup path, but changing it affects orphan prevention, user-visible task completion, config/default surface, and the boundary with Claude Code's own tool lifecycle.

Options:

- **Adopt bounded drain plus telemetry (recommended):** Detect or accept only explicit in-flight CLI-owned background work, defer cleanup within a ceiling, and surface forced cleanup as parent-visible failure telemetry.
- **Telemetry first:** Keep cleanup unconditional for now, but snapshot/log/surface killed grandchildren so the silent failure class becomes observable before process lifetime changes.
- **Declare post-turn CLI work unsupported:** Document or enforce that Claude CLI Workflow/background grandchildren cannot survive OpenClaw turn cleanup and route users to ACP, exec/process, or detached task surfaces.
