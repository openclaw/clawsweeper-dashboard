## Label Justifications

- `P2`: The bug breaks screenshot image results for MCP clients but leaves text and DOM browser actions available as a workaround.
- `impact:data-loss`: The reported failure drops required image payload fields (`data` and `mimeType`) from a tool result before the MCP client receives it.
- `maturity:stable`: The affected MCP loopback gateway path belongs to `gateway-runtime`, which the maturity shortlist reports as M4 Stable.

## Summary

Current main already fixes the reported browser screenshot MCP validation failure: the loopback MCP handler now preserves valid SDK image content blocks instead of rewriting them to `{type,text}`, and regression coverage includes image blocks with `data` and `mimeType`. The fix is main-only relative to the latest tagged release, so users on v2026.6.11 or 2026.6.10 can still see the old behavior until the next release.

## What This Changes

The issue asks OpenClaw to stop returning malformed MCP image content for `browser(action="screenshot")` under Claude CLI v2.1.201 by preserving or safely downgrading screenshot image blocks.

## Best Possible Solution

Keep the merged gateway MCP loopback content-preservation fix on main and let the next release carry it to users affected on 2026.6.10 or v2026.6.11.

## Solution Assessment

Yes. The merged fix is at the gateway MCP loopback normalization boundary that dropped the fields, and it preserves valid SDK content while downgrading malformed or unsupported blocks to text.
