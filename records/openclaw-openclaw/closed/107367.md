## What This Changes

The PR changes LINE group-history consumption so a mention turn clears only the ambient entries it actually read, retaining messages recorded concurrently for the next turn.

## Best Possible Solution

Keep the plugin-local atomic snapshot and selective consumed-entry cleanup, preserving successful-turn-only deletion and focused tests for loss, duplication, window limits, and failed-turn retries.

## Reproduction Assessment

Yes. The deterministic path records ambient history, parks a mention turn in `processMessage`, records another ambient message, and releases the turn; focused red/green tests and a live LINE run both demonstrate the failure and fix.

## Solution Assessment

Yes. Defining the consumed window and identities in one synchronous operation, then removing only that set after a successful turn, is the narrowest maintainable fix and avoids both whole-key message loss and a second live-map read that could duplicate context.
