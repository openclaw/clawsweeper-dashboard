## Label Justifications

- `P0`: Currently supported and installer-provided runtimes may expose all canonical SQLite-backed state to a documented corruption race.
- `impact:data-loss`: The upstream WAL-reset defect can corrupt persisted state and session databases.
- `maturity:stable`: The affected gateway-runtime and cli-install-update-onboard-doctor features are both scored M4 Stable.

## Summary

Current `main` still accepts and installs Node builds whose embedded SQLite is in SQLite’s documented WAL-reset corruption range, and the recently merged application-level hardening explicitly leaves this upstream runtime risk unresolved. This protected, maintainer-authored issue is still necessary, but the enforcement timing is a compatibility decision that needs explicit owner approval.

## What This Changes

Require supported OpenClaw Node runtimes to embed a SQLite release containing the upstream WAL-reset corruption fix, with coordinated enforcement, diagnostics, and upgrade guidance.

## Best Possible Solution

Create one authoritative Node/embedded-SQLite safety policy, reject affected runtimes before any SQLite-backed state opens, and reuse it across engines, startup, doctor, installers, daemon and native resolution, CI, package acceptance, documentation, and release proof.

Yes at the dependency-contract level: accepted and pinned Node versions can be directly checked against official embedded SQLite versions and SQLite’s affected range. ## Solution Assessment

Yes in principle: requiring a fixed embedded SQLite release is the only complete mitigation identified by SQLite; application locking, transaction, snapshot, and checkpoint hardening remain defense in depth rather than substitutes.
