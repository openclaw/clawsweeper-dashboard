## Summary

Current main no longer loads the full Codex runtime entry during CLI metadata capture: the merged Codex supervision work added a dedicated metadata entry and focused coverage, so the reported runtime-state dereference is obsolete on main. Shipped-release provenance remains unconfirmed, but this close reason permits a current-main-only fix.

## What This Changes

Prevent Codex CLI metadata registration from opening runtime state so `openclaw codex --help` can render without full plugin activation.

## Best Possible Solution

Keep the dedicated Codex metadata entry and regression test on main, then include that implementation in the next published core and `@openclaw/codex` release with an aligned package smoke check.

## Reproduction Assessment

Yes for the affected package: enabling its Codex plugin and running `openclaw codex --help` deterministically produced the `openSyncKeyedStore` TypeError. Current main no longer reproduces because metadata capture uses the dedicated lightweight entry.

## Solution Assessment

Yes. Splitting static CLI metadata into its own entry is narrower and more maintainable than guarding individual runtime-state calls, and it directly follows the documented registration-mode boundary.
