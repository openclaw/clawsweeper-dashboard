## Summary

Keep this PR open: the prior blocking finding still applies. The branch makes Slack lifecycle reactions opt-in, but current Slack source and docs show common default channel mentions can have no native assistant status thread, so existing users can lose queued/thinking/tool/done reaction progress and see only a static ack.

## What This Changes

The PR makes Slack lifecycle status reactions require `messages.statusReactions.enabled: true`, keeps acknowledgement reactions static by default, updates Slack/config docs and help text, and adds focused Slack tests for that new default.

## Best Possible Solution

Prefer Slack native assistant status only when a usable native status thread target exists, and preserve lifecycle reaction progress by default whenever the native status call would no-op.
