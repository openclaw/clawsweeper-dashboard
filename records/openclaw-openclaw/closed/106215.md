## Summary

Keep this issue open for explicit maintainer sponsorship. Current OpenClaw supports provider-based CLI migration and workspace Markdown memory, but not importing Codex or Claude durable memory through Control UI; the protected `maintainer` label and private host-filesystem boundary rule out automated cleanup or implementation.

## What This Changes

Add a metadata-only Control UI workflow that imports selected Codex CLI and Claude Code durable memory through the existing provider migration framework into an OpenClaw agent workspace.

## Best Possible Solution

Extend each provider with allowlisted memory items, reuse the existing migration planner, conflict and backup machinery, and expose a generic Gateway plan/apply RPC whose Control UI displays only source labels, sanitized paths, counts, conflicts, and outcomes after explicit confirmation.
