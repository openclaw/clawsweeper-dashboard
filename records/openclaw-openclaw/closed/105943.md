## What This Changes

The PR makes bundle LSP framing require one case-insensitive, decimal-only Content-Length header, propagates framing errors through startup, and adds valid, malformed, and duplicate-header regression cases.

## Best Possible Solution

Keep the framing validation at the bundle LSP runtime boundary, preserve valid case-insensitive headers, fail startup before exposing tools for duplicate or non-decimal lengths, and land only after rebasing onto current main with the focused test and real-subprocess proof repeated.
