## Summary

Keep open: the merged reply-session fixes address the released conflict family, but the supplied current-main breadcrumbs still leave the distinct post-restart WebChat boot-session route-ownership behavior unproven and without a canonical replacement issue.

## What This Changes

The issue requests that WebChat direct conversations remain on the normal main session after restart recovery instead of failing on initialization and later accepting turns through a boot session.

## Best Possible Solution

Define boot-session ownership as a recovery invariant—fresh WebChat direct inbound turns must resolve to the active user session rather than a recovery boot key—then add a restart regression test that proves the main session remains usable and correctly targeted.
