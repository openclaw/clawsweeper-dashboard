## Label Justifications

- `P1`: The report describes a gateway crash during concurrent agent runs, which would break an active agent workflow if it reproduced.
- `impact:crash-loop`: The reported failure mode is an unhandled SQLite lock exception crashing the gateway process.
- `impact:session-state`: The affected surface is the ACP event ledger that persists and replays session updates.
- `maturity:stable`: The issue maps to `gateway-runtime | Gateway runtime | M4 Stable` from the maturity shortlist.

## Summary

Current main and the latest release already cover the reported ACP ledger lock-contension path: ledger writes go through the shared OpenClaw SQLite state database, which sets a 30s busy timeout and uses synchronous immediate transactions before ledger mutation.

## What This Changes

The issue reports that concurrent `node:sqlite` `DatabaseSync` writes in the ACP event ledger can raise `SQLITE_BUSY` and crash the gateway during concurrent agent runs.

## Best Possible Solution

Keep the shipped shared-state SQLite implementation with the 30s busy timeout and immediate transaction helper; reopen only if a fresh trace shows `SQLITE_BUSY` still escaping on the latest release.

Yes, the current implementation is the best existing solution for the reported symptom. It centralizes the timeout and WAL setup in the shared state DB instead of adding a one-off ACP ledger opener.
