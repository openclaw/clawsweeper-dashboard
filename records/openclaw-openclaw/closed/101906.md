## What This Changes

The branch persists plugin conversation-binding “allow always” approvals to SQLite before publishing them to the in-memory approval cache, with regression coverage for failed and overlapping approval writes.

## Best Possible Solution

Land the narrow persist-before-cache ordering with its failure and concurrency regression coverage once the exact PR head remains clean through required integration checks.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source and supplied after-fix evidence: force `runOpenClawStateWriteTransaction` to fail while resolving an allow-always request, then request the same plugin/channel/account scope again. Current behavior before this patch publishes the cache entry before awaiting persistence, whereas the proposed path keeps that second request pending.

## Solution Assessment

Yes. Persisting before cache publication is the narrowest maintainable fix because the cache is the auto-approval decision source; rebuilding the cache after the await also avoids discarding a concurrent successful grant.
