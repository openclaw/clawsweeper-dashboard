## Summary

Keep this issue open: current main still contains the duplicate-delivery path, and the open linked PR is the concrete implementation candidate that should be reviewed and landed before the issue closes.

## What This Changes

Prevent LINE long replies from re-sending chunks already delivered through the reply token when a later push fails.

## Best Possible Solution

Keep reply-token fallback limited to genuine reply failures; after any successful visible delivery, push only the remaining chunks and propagate a consistently tagged partial-delivery error with focused regression coverage.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: a reply containing more than five chunks, followed by failure of the first remaining push, deterministically enters the catch and push-all fallback on current main. The supplied failing regression transcript corroborates that path, although this review did not run it independently.

## Solution Assessment

Yes. Separating genuine reply-token failure from post-reply push failure and reusing the existing visible-partial-delivery marker is narrower and more consistent than adding another fallback or deduplication layer.
