- `merge-risk: 🚨 session-state`: The patch changes retention decisions for persisted primary and admitted session records in both file-backed and SQLite maintenance paths.

## Summary

This PR remains necessary: current `main` still protects durable thread/channel sessions but does not protect `agent:<id>:main`, so entry-cap maintenance can evict the active primary conversation under the reported pressure. The patch is a focused repair and has received several follow-up commits from `steipete`; it should stay open for normal maintainer review and real runtime proof rather than being closed or replaced.

## What This Changes

This PR marks agent primary sessions, including the global primary session, as maintenance-protected and carries the SQLite store path into maintenance so admitted sessions are not reclaimed by another write.

## System Context

Session maintenance runs after persisted session writes and enforces age, entry-count, and disk policies across file-backed and SQLite session stores. Its protection decisions determine which interactive, channel, and admitted in-flight agent sessions survive a maintenance pass.

## Architecture Diagram

  F --> G[Interactive and channel runs]

## Best Possible Solution

Keep the primary and admitted-session protections, land them only after a redacted real maintenance scenario confirms that a concurrent write cannot evict the active primary session, and review the separate durable-conversation cap policy in https://github.com/openclaw/openclaw/pull/112641 independently.
