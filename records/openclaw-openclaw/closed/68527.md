## Summary

Keep open. Current main has materially improved MCP cleanup, idle eviction, setup diagnostics, add-time probing, and short request-failure pauses, but it does not clearly provide process-wide failed-start circuiting or default Linux service resource ceilings; the host-isolation policy also needs explicit security and product ownership.

## What This Changes

Prevent misconfigured MCP servers from causing repeated child-process creation and host exhaustion through bounded retries, lifecycle cleanup, setup validation, diagnostics, and Linux service guardrails.

## Best Possible Solution

Add process-wide per-server failed-start single-flight and bounded cooldown keyed to canonical MCP configuration, always tear down failed process trees, expose degraded and cooldown state in MCP status, and separately adopt approved systemd ceilings or clear installer/doctor guidance without automatically provisioning swap.
