## Summary

Close as implemented on current main: the reported daily-reset loop is prevented because a stale session rollover now persists a fresh sessionStartedAt before later session-store writes can reuse the entry.

## What This Changes

The issue reports that daily-reset session rotation for direct HTTP-chat sessions keeps the old sessionStartedAt, causing every later turn to start a new empty session.

## Best Possible Solution

Keep the current-main rollover persistence behavior and include it in the next release so users on v2026.6.11 or v2026.7.1-beta.2 receive the fix.

## Solution Assessment

Yes. Updating the rotated session row at the rollover persistence boundary is the narrow maintainable fix because it preserves the existing daily reset policy without adding config or a parallel reset path.
