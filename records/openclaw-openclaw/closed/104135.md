## Summary

Keep this issue open for explicit maintainer direction. The split lifecycle/dedupe ownership exists in both current main and v2026.6.11, no canonical replacement was found, and an agent-run-only consolidation is a credible bounded cleanup; however, the protected `maintainer` label and ownership choice make this human-sponsored architecture work rather than automatic repair intake.

## What This Changes

Consolidate Gateway `agent.wait` terminal state, projection, waiter, and timeout ownership under the agent job registry.

## Best Possible Solution

Use the agent job registry as the sole owner of agent-run terminal observations and waiter resolution, retain the active-chat dedupe-only branch, reuse the canonical terminal-outcome merge contract, and migrate the full conflict-order and cleanup test matrix before deleting the duplicate agent waiter.
