## Summary

Keep open: current main still combines a strict Control UI `script-src` policy with browser-side Zod 4.4.3 and no early jitless initialization, so the reported CSP violation remains actionable. The config-fetch behavior is substantially improved by credential retries and post-connect refresh, with current main also avoiding the unauthenticated startup request when no credential exists, but the safer CSP repair still needs owner confirmation and real-browser proof.

## What This Changes

Prevent Control UI Zod validation from triggering strict-CSP violations and avoid an unauthenticated initial runtime-config request under token auth.

## Best Possible Solution

Import a dedicated early Control UI bootstrap module that calls `z.config({ jitless: true })` before the application module graph can construct Zod schemas, retain the current authenticated config retry/post-connect refresh behavior, and add strict-CSP browser regression proof for both Chrome and Firefox.
