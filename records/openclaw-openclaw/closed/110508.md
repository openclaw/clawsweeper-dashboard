## Summary

Keep this PR open: the cleanup split addresses the reported races, but the current gateway-stop gate can still skip Telegram credential release after the child has reached terminal state and `stop()` later reports cleanup failure. Likely related people: steipete is the recent QA teardown contributor (medium confidence).

## What This Changes

The branch splits QA transport cleanup into pre- and post-gateway phases, waits for MCP agent completion before a second turn, and adjusts live-shard signal setup ordering.

## Best Possible Solution

Drive post-gateway credential release from the gateway process boundary’s verified terminal/quiesced outcome rather than from whether `stop()` resolved, and add coverage for an exited child whose stop path subsequently rejects.

## Reproduction Assessment

Yes in source: arrange for the isolated gateway to mark itself terminal, then make its later stop path reject. The PR’s new `gatewayErrors.length === 0` gate skips the only post-stop Telegram lease-release hook in that case.

## Solution Assessment

No. Splitting cleanup phases is the right direction, but treating a rejected stop call as proof that the gateway is non-terminal conflates cleanup outcome with process state; use the existing terminal boundary as the decision source.
