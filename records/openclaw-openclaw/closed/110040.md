## Label Justifications

- `P0`: On the affected stable release, a routine update can disable multiple healthy plugins and leave a first-time or community user without a non-technical recovery path.
- `impact:data-loss`: The failure path mutates persisted plugin enablement and allowlist state even though the installed plugin remains healthy.
- `impact:auth-provider`: Affected packages include provider plugins, so disabling them can remove an existing authentication or model-provider path.
- `impact:ux-release-blocker`: Recovery requires plugin IDs, terminal commands, and potentially manual configuration repair after a normal update operation.

## Summary

## What This Changes

Prevent valid array-shaped `npm view --json` metadata from causing installed plugins to be treated as failed and disabled during updates.

## Best Possible Solution

Keep the canonical array-normalization and state-preserving update behavior, ship both together in stable releases, and avoid tracking another identical report.

Yes for OpenClaw v2026.7.1: the supplied npm command and prior reports establish the exact array-shaped response and destructive update path. A failing current-main path is not expected because current code includes metadata normalization and state preservation.

## Solution Assessment

Yes. Normalizing the dependency output at the install-source boundary and preserving existing state on non-authoritative update failures is narrower and safer than adding a new fallback, configuration option, or plugin-specific exception.
