## What This Changes

The issue reports that Telegram isolated ingress treats transient getUpdates 429/5xx and non-JSON 502 responses as fatal, eventually exhausting gateway restarts.

## Best Possible Solution

Review and land the linked Telegram worker fix, or a split equivalent, that retries 429/5xx getUpdates failures, honors retry_after, handles non-JSON 5xx bodies, and preserves fatal 401/404 plus parent-owned 409 recovery.

## Reproduction Assessment

Yes. From source inspection, mocked getUpdates 429, 500, 502, or non-JSON 502 responses reach the current worker parser/retry gate and can terminate the worker instead of retrying.

## Solution Assessment

Yes. The narrow maintainable fix belongs in the Telegram isolated-ingress worker retry policy, reusing shared Telegram API error classification while preserving the existing 409 parent recovery boundary.
