## Summary

This PR does not fix the reported gateway behavior: it changes a helper used by MCP write commands, while normal runtime config loading still copies server entries unchanged and filters only on `enabled === false`. It also introduces an undocumented second enablement field without establishing a shipped compatibility contract.

## What This Changes

The PR adds a `disabled` MCP server schema field, maps `disabled: true` to `enabled: false` in the MCP write-path canonicalizer, and adds direct helper tests.

## Best Possible Solution

Keep `enabled` as the sole runtime field; if a shipped legacy source for `disabled` can be proven, migrate it to `enabled` in `openclaw doctor --fix` and erase the alias, otherwise reject it with actionable guidance to use `enabled: false`.
