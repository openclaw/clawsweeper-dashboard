## Summary

Current main already fixes the reported shell snapshot stdout crash path: the canonical merged fix removes the unused stdout pipe entirely and adds regression coverage, so adding a stdout error listener is no longer needed.

## What This Changes

The issue reports that shell snapshot `runShell` attached a stdout `data` listener without a stdout `error` listener and requests stream-error handling to avoid process crashes.

## Best Possible Solution

Keep the merged no-stdout-pipe implementation from https://github.com/openclaw/openclaw/pull/100744; no further core change is needed unless new evidence shows another shell snapshot stream path still crashes.

## Maintainer Decision

Required: false

## Reproduction Assessment

No current-main failure path remains: `runShell` now uses ignored stdio, so the reported `child.stdout` stream no longer exists. The historical release path is source-backed in `v2026.6.11`, where stdout was still piped and read without a stdout error listener.

## Solution Assessment

Yes. Removing the unused stdout pipe is the narrowest maintainable fix because both `runShell` callers consume only exit status; adding a no-op stdout error listener would preserve an unnecessary stream surface.
