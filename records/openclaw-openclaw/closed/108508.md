## Summary

Keep this PR open, but do not merge its current head: the existing review finding identifies a concrete lifecycle bug where an unused runtime candidate can populate the process-wide memo before the artifact is actually selected, causing a later activating load to ignore its built-artifact preference. The reported duplicate-registration bug is valid and the approach is close, but the memoization boundary and after-fix runtime proof still need correction.

## What This Changes

The PR adds process-lifecycle memoization for plugin runtime and setup entry paths so separate registry assemblies resolve a plugin to one evaluated module instance.

## Best Possible Solution

Commit the canonical entry identity only when the registration plan selects or opens that runtime/setup artifact, then cover setup-only lookup followed by built-preferred activation and demonstrate one real gateway process sharing plugin state across its hook and tool.
