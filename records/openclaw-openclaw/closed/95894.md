## Summary

Keep open: current main and the latest release still propagate the host `path-to-regexp` 8.4.0 override into managed npm plugin roots, while Express 4.x still requires `path-to-regexp` 0.1.x, so the reported plugin crash path remains plausible and needs a maintainer dependency-policy decision.

## What This Changes

The issue asks OpenClaw to stop managed plugin installs from forcing Express 4.x plugins onto an incompatible `path-to-regexp` version or to surface a clear validator error.

## Best Possible Solution

Define a scoped managed-npm-root policy or validation path that preserves plugin-owned Express 4 dependency graphs without downgrading OpenClaw's Express 5/router stack, with install/update regression coverage and docs.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw stop propagating incompatible host dependency overrides into third-party managed plugin roots, or keep plugin packages fully responsible and only validate/report the mismatch?

Rationale: The code path is compatibility and supply-chain sensitive: root overrides are used as OpenClaw security policy, but applying them into plugin-owned dependency graphs can break valid third-party packages.

Likely owner: steipete

Owner reason: History ties this person to the isolated plugin install architecture and dependency ownership docs that frame the policy choice.

Owner confidence: high

Options:

- **Scope Managed-Root Overrides (recommended):** Exclude or scope host overrides that conflict with plugin-owned dependency ranges, then prove Express 4 plugins keep `path-to-regexp` 0.1.x while OpenClaw core keeps 8.x.
- **Add Validator-Only Failure:** Keep current override propagation but detect Express 4 plus incompatible `path-to-regexp` at install/update time and fail with an actionable package/shrinkwrap fix.
- **Document Plugin-Owned Pins:** Keep the current behavior and document that affected plugins must publish their own shrinkwrap or override for Express 4 compatibility.

## Reproduction Assessment

Yes. Source inspection shows current main still writes the host `path-to-regexp` 8.4.0 override into managed npm plugin roots, and dependency metadata confirms Express 4.21.2 requires `path-to-regexp` 0.1.12; I did not run a live plugin install because this review is read-only.

## Solution Assessment

No, the issue's preferred blanket top-level override is not the best fix because OpenClaw's Express 5/router stack needs `path-to-regexp` 8.x. The best direction is a maintainer-approved scoped managed-root policy or validator that preserves plugin dependency ownership without breaking core.
