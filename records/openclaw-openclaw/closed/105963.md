## Summary

Keep open: current main still has separate Node and Control UI gateway lifecycle implementations, and the narrower internal consolidation remains useful independently of the broader public SDK request. The protected `maintainer` label also requires explicit maintainer handling.

## What This Changes

Consolidate the Node and Control UI TypeScript gateway WebSocket lifecycle implementations behind one transport-injected internal client while preserving host-specific security and UX behavior.

## Best Possible Solution

Create one internal protocol-lifecycle engine in `packages/gateway-client` with an injected WebSocket/clock transport, retain Node security and persistence in its host adapter, retain browser URL/reconnect/error policy in the UI adapter, migrate both callers with parity tests and live Control UI connect/reconnect proof, and avoid a protocol bump or public-package commitment.
