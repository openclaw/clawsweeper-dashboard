## Label Justifications

- `P1`: Authenticated Control UI operators are kicked out of the dashboard on routine Gateway WebSocket drops, breaking an active user workflow in the latest release and current main.
- `impact:ux-friction`: The UI presents a transient transport failure as a login/connect gate, causing avoidable confusion and context loss without data loss.
- `impact:session-state`: The app shell drops established dashboard context even though the underlying client and chat page have reconnect/session-resume paths.
- `maturity:stable`: The affected Control UI WebSocket lifecycle maps to the M4 Stable `gateway-runtime` feature, including Hosted Web Surface and WebSocket Connection.

## Summary

Keep open: current main still routes recoverable authenticated WebSocket drops through the login gate, the issue has the protected `maintainer` label, and the open linked fix PR is the right place to resolve it before this issue closes.

## What This Changes

The issue asks for authenticated Control UI sessions to stay mounted with an in-place reconnect state on transient Gateway WebSocket drops instead of returning to the login/connect gate.

## Best Possible Solution

Review and land or revise https://github.com/openclaw/openclaw/pull/100479 so recoverable post-auth drops keep the Control UI shell mounted, while first-connect and credential failures still use the login gate; keep the macOS stale-tunnel issues separate.
