## Label Justifications

- `P2`: This is a bounded but real approval lifecycle bug affecting stale sensitive-action approvals on current main.
- `impact:security`: Plugin approvals are a sensitive-action authorization boundary, and stale approval ids can remain clickable after the originating run aborts.
- `impact:session-state`: The gateway pending approval state can outlive the agent run state and leave UI/channel approval cards stale until timeout.
- `maturity:stable`: The issue affects the M4 Stable `gateway-runtime` approval/plugin approval area in the maturity scorecard.

## Summary

Keep open: current main still has no `plugin.approval.cancel`, and the agent abort path cancels locally while the gateway approval record can remain pending. The linked draft fix PR is a candidate, so this issue should stay open until that PR or an equivalent fix lands.

## What This Changes

The issue asks for aborted plugin tool approvals to cancel the pending gateway approval and clear stale approval cards/events.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/98577, or replace it with an equivalent gateway-owned cancellation path that unblocks waiters and broadcasts terminal cleanup for all approval surfaces.

## Reproduction Assessment

Yes, by source inspection: an accepted two-phase plugin approval can enter `waitDecision`, the agent abort path returns local cancellation, and current gateway state is only cleared by resolve or timeout expiry. I did not run a live end-to-end repro in this read-only sweep.

## Solution Assessment

Yes, a requester-side gateway cancellation path with a terminal cleanup event is the maintainable boundary for this bug. The open linked PR is the candidate implementation and still needs normal PR review before this issue can close.
