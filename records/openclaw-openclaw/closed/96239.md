## Summary

Keep open: current main has a Feishu streaming mitigation that preserves an answer when a later error final arrives, but the underlying mutating-tool warning policy still intentionally appends warnings after success-looking replies, and the exact `configuration file` stdout trigger has not been proven fixed in a live Feishu run.

## What This Changes

The issue asks OpenClaw to stop surfacing a misleading Feishu warning card before or above the real final reply when a successful agent turn leaves a stale or false `lastToolError` from an exec-like tool.

## Best Possible Solution

Define one shared recovered-tool-warning policy for successful visible replies, then prove the chosen behavior with a reduced payload test plus Feishu live or fixture evidence for the original `replies=2` shape.
