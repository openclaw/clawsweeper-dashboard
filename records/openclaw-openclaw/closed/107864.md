## Summary

Keep this PR open, but do not merge the current patch: its fallback detects an internally inconsistent persisted registry, while the linked report says the persisted SQLite plugin and install-record metadata were already self-consistent and startup recovered only after stale sibling generation directories were removed. The focused tests therefore validate a different state, and no real upgrade/restart proof shows that the reported gateway lockout is fixed. ([github.com](https://github.com/openclaw/openclaw/pull/107864))

## What This Changes

The PR makes plugin registry snapshot loading discard persisted global npm plugin metadata when its plugin root differs from the recorded install path, and adds managed-generation fixtures and regression tests.

## Best Possible Solution

At the managed npm discovery/index derivation boundary, constrain each plugin ID to the generation referenced by its authoritative install record, ignore or safely clean stale sibling generations, and prove first and repeated gateway startups using the exact self-consistent persisted state from the report.
