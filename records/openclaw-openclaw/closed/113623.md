## What This Changes

The PR makes Control UI multi-select session actions defer each row’s expensive canonical session-list refresh, then refresh once per affected agent after the batch completes.

## System Context

The Control UI sidebar sends session mutations to the Gateway through its session capability. Each mutation normally refreshes the canonical session list so the sidebar reflects the saved state; this PR changes batch callers to postpone that refresh until the full selection has been processed.

## Architecture Diagram

flowchart LR

  B --> C[Session patch per selected row]
  C --> D[Gateway commits and change events]
  D --> E[One final list refresh per agent]
  E --> F[Settled sidebar state]

## Best Possible Solution

Land the one-refresh-per-agent design only after a redacted real Control UI/Gateway run demonstrates that a multi-select action settles correctly without per-row list refreshes, while preserving failure and stale-scope behavior for each affected agent.
