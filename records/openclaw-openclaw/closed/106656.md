## Summary

Current gateway bootstrap already enables strict plugin loading, so registration or import failures abort initialization instead of returning a silently degraded plugin registry; the report describes behavior fixed before it was filed.

## What This Changes

Require gateway initialization to fail clearly when a required plugin throws during bootstrap rather than continuing with missing capabilities.

## Best Possible Solution

Keep the existing strict gateway bootstrap contract; if an independently reproducible plugin service-start failure still permits an unusable gateway, track that narrower service lifecycle case with the affected plugin and its required-startup contract.

No. A new dependency-resolution graph is broader than necessary for the reported failure because the existing strict bootstrap boundary already makes loader failures fatal; service-start failures should be assessed separately if a concrete required service reproduces the problem.
