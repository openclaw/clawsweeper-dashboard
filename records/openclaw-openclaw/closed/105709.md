## Summary

The current head still has the prior P1 compatibility regression: it makes the shipped `ReplyRuntimeConfigSchemaShape` nested-only even though external plugins have no repository-owned doctor migration and the PR retains flat-key resolver compatibility for them. The bundled-channel migration is otherwise coherent and heavily tested, but this public SDK contract break plus missing real external-plugin upgrade proof blocks merge.

The PR migrates Signal, IRC, Nextcloud Talk, WhatsApp, Google Chat, and Mattermost from flat streaming configuration to nested `streaming` objects, adds doctor migrations and resolver deprecation warnings, removes bespoke flat-key reads, and updates tests, docs, generated metadata, and Plugin SDK baselines.

## Best Possible Solution

Use a dedicated nested-only delivery schema for the six bundled channels while keeping `ReplyRuntimeConfigSchemaShape` flat-key-compatible for external plugins through the announced deprecation window, with focused strict-schema tests and a real upgrade transcript.
