## Summary

Keep open: current main and the latest release still apply WHAM `subscription_limit` blocks profile-wide, and https://github.com/openclaw/openclaw/pull/99810 is the active open fix candidate. This issue should close only after that PR or an equivalent replacement lands.

## What This Changes

The issue reports that Codex/OpenAI WHAM `subscription_limit` blocks are applied to an entire shared auth profile instead of only the model that exhausted its quota.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99810, or an equivalent replacement, with coverage for WHAM writes, read-side gating, and old unscoped or conflicting blocked-state behavior.

## Reproduction Assessment

Yes. Source inspection gives a deterministic current-main repro by triggering or seeding a WHAM `subscription_limit` block and checking `isProfileInCooldown` for a different `forModel`; I did not run tests because this review is read-only and must keep the checkout clean.

## Solution Assessment

Yes. Reusing the existing `blockedModel` field and mirroring the established `cooldownModel` gate is the narrowest maintainable fix; adding config or provider-specific fallback policy would be broader than needed.
