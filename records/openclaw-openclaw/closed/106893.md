## Summary

This v2026.6.11 report matches the reply-session stale-snapshot conflict already fixed by the merged serialization work in https://github.com/openclaw/openclaw/pull/96847; current main additionally retries conflicts and fences stale rollover ownership, so this issue should close unless the behavior reproduces on v2026.7.1 or newer.

## What This Changes

Prevent gateway restarts from leaving webchat and Telegram sessions in initialization conflicts that block messages and repeatedly replay spooled Telegram updates.

## Best Possible Solution

Keep the serialized, retrying, ownership-fenced initializer now on main; request a new current-version report with restart timing and redacted logs only if v2026.7.1 or newer still enters the conflict loop.
