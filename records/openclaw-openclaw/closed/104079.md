## Summary

Current main has a concrete lifecycle gap: backgrounded exec sessions remain live in the bash registry after their originating run settles, but the shared Gateway active-work snapshot has no corresponding count or blocker, so suspension preparation can report ready while that process is still running. This is a narrow, current-main bug in an unreleased core suspension API, not the broader plugin telemetry proposal.

## What This Changes

Ensure every live background exec session contributes a sanitized blocker to Gateway suspension readiness until it exits or is killed.

## Best Possible Solution

Add a count-only `background-exec` category to the shared active-work snapshot using a narrow registry count helper, return no command, PID, output, scope, or session identifiers, and add exit, kill, restart, prepare, rollback, and resume race coverage around the existing admission ordering.
