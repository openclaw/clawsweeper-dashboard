## Summary

Keep open: the report provides a current-main live reproduction, identifies a concrete 10-second scheduler delay, and shows a bounded first-turn latency penalty. The protected `maintainer` label requires explicit lifecycle judgment because starting this work immediately must be balanced against earlier post-ready pre-warm saturation reports.

## What This Changes

Start the Gateway’s agent runtime plugin registry pre-warm immediately after readiness instead of intentionally waiting 10 seconds.

## Best Possible Solution

Schedule the canonical runtime-plugin registry load on the first post-ready event-loop opportunity, deduplicate immediate requests onto that in-flight load, and add timing coverage proving both unchanged readiness latency and reduced first-turn preparation cost.
