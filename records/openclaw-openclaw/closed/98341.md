## Summary

Keep open: the Feishu OOM hardening target is real, but this patch is not merge-ready because it duplicates lower-level JSON parsing, leaves the streaming card-create read unbounded, can skip guarded-fetch cleanup on token overflow, lacks real Feishu/Lark proof, and overlaps with other open Feishu bounded-reader PRs.

## What This Changes

The branch caps Feishu app-registration and streaming-card token JSON reads with `readResponseWithLimit`, updates Feishu tests to real `Response` bodies, adds a local Feishu proof script, and deletes a Twilio proof script.

## Best Possible Solution

Land one canonical Feishu bounded-JSON implementation using the shared provider JSON helper, covering all credentialed JSON reads with a maintainer-approved cap, guaranteed release cleanup, no unrelated proof-script churn, and real Feishu/Lark proof or override.

## Reproduction Assessment

Yes for source-level reproduction: current main has unbounded native `response.json()` reads in Feishu app-registration, streaming-token, and card-create success paths. I did not establish a live OOM failure or run a real Feishu/Lark tenant flow in this read-only review.

## Solution Assessment

No; this is a plausible partial mitigation, but the maintainable fix should use the shared JSON helper, cover the sibling card-create read, and guarantee guarded-fetch cleanup on overflow. It also needs real Feishu/Lark proof or a maintainer proof override before merge.
