## What This Changes

The issue reports that agent-initiated `skill_workshop` lifecycle actions ignore the existing `skills.workshop.approvalPolicy: "auto"` setting when the before-tool-call context lacks `config`.

## Best Possible Solution

Land the linked narrow fix after review, keeping explicit hook config authoritative and using runtime config only as a safe fallback when hook config is absent.

## Reproduction Assessment

Yes, at source level: current main resolves missing Skill Workshop approval config as default pending policy, while docs say `approvalPolicy: "auto"` should skip lifecycle approval. I did not run a live TUI or webchat session in this read-only review.

## Solution Assessment

Yes: the best fix is the narrow fallback used by the linked PR, preserving explicit hook config precedence and failing closed when runtime config is unreadable. Passing config through every caller would be broader and easier to miss on future hook contexts.
