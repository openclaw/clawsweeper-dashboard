## Summary

Keep open: current main still has a source-level path where an unresolved `agents.defaults.models` entry without `agentRuntime` gets the generic `models.providers[...]` registration hint, while `openai-codex` is legacy and the validator still rejects the exact overlay shape reported here without `baseUrl`.

## What This Changes

The issue reports contradictory provider-model recovery guidance that can lead operators from an `Unknown model` error into an invalid `models.providers.openai-codex` config and a gateway startup crash-loop.

## Best Possible Solution

Keep `openai-codex` as legacy-only input, and update the unknown-model recovery path to detect legacy/auth-gated provider misses and point operators to `openclaw doctor --fix`, `openclaw models status`, and the OpenAI auth flow instead of suggesting a `models.providers.openai-codex` overlay.

## Solution Assessment
