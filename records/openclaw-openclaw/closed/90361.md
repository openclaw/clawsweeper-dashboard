## What This Changes

The issue reports intermittent first-class memory_search failures where valid builtin memory indexes are reported as missing metadata during overlapping search/reindex activity.

## Best Possible Solution

Review, land, or explicitly replace https://github.com/openclaw/openclaw/pull/90453 with one manager-level read barrier that keeps real provider/model mismatches fail-closed and coordinates adjacent metadata durability work.

## Reproduction Assessment

Yes, at source level: current main still points the manager at a shadow reindex database during full reindex and the tool still fail-closes on a post-search status result with missing identity. I did not run a live concurrent gateway reproduction in this read-only review.

## Solution Assessment

Yes for the current direction: a manager-level read barrier and stable status snapshot address the lifecycle race more directly than a tool-wrapper mitigation. The remaining decision is maintainer acceptance of wait semantics and adjacent PR coordination.
