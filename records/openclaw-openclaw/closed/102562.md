- `merge-risk: 🚨 compatibility`: The PR changes shared image sanitization for all providers, so existing non-Anthropic image workflows could be transcoded or fall back differently after upgrade.

## Summary

Keep open: the linked Anthropic HEIC/TIFF bug is real, but this PR is not the best fix because it applies Anthropic-only MIME policy inside the provider-neutral image sanitizer and still falls through to the original unsupported MIME when conversion fails.

## What This Changes

The PR adds Anthropic MIME allowlist checks to `resizeImageBase64IfNeeded` so within-limit images with unsupported MIME values are transcoded to JPEG before returning from the shared image sanitizer.

## Best Possible Solution

Normalize unsupported image bytes at a shared Anthropic inline-image helper used by both the packaged provider and custom transport, keep `tool-images.ts` provider-neutral, and add focused HEIC/TIFF fallback regressions plus real loopback or live Anthropic proof.
