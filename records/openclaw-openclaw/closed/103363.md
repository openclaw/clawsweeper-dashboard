## Summary

The shipped and current implementations both silently omit selected content and then show generic success, while the gateway contract confirms non-image delivery is intentionally unsupported on this route; this remains a valid, bounded bug rather than an already-fixed or duplicate item.

## What This Changes

Report that the iOS Share Extension accepts only three images, omits video/file attachments, and still reports success without warning.

## Best Possible Solution

Keep the current supported-media boundary unless separately expanded, but show selected-versus-accepted attachment facts before sending, let users avoid unintended partial delivery, and report partial completion instead of generic success.
