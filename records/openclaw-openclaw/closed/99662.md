## Summary

Keep open: current main still has a source-backed Discord partial/progress preview path that creates a draft message and later finalizes through edits, which matches the reported missed unread/highlight behavior; no merged fix owns this specific notification symptom yet.

## What This Changes

The issue asks for Discord partial/progress-streamed turns to produce a fresh completion signal instead of only editing an existing preview message when the final answer is ready.

## Best Possible Solution

Choose one Discord-owned finalization policy that preserves current preview value while making turn completion visible after users navigate away, likely coordinated with https://github.com/openclaw/openclaw/issues/94285 if a new finalBehavior option is needed.

## Reproduction Assessment

Yes. The reporter supplied concrete Discord message metadata from v2026.6.11, and current source shows partial preview updates and eligible final replies can reuse/edit an existing preview message rather than creating a fresh completion message.

## Solution Assessment

Unclear. A fresh final message or default-off finalization mode is plausible, but maintainers should first choose the Discord streaming policy because changing partial finalization affects existing preview semantics and message volume.
