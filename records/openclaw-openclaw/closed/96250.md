## Summary

Keep this PR open: the OOM mitigation is valuable and now has clear maintainer sponsorship, but the current head has a blocking regeneration bug that can preserve an obsolete automatically generated heap cap after host or cgroup memory shrinks; the live proof also predates the adaptive rewrite.

## What This Changes

Adds an adaptive host-memory-derived heap-only `NODE_OPTIONS` setting for managed Gateway services, preserves an installed heap flag, and reports the applied value through status and doctor with regression tests.

## Best Possible Solution

Recompute the generated adaptive cap on every service installation or regeneration; preserve an override only when its operator-owned provenance is explicit, then demonstrate fresh install and constrained-memory regeneration with the generated service plus `gateway status` and doctor output.
