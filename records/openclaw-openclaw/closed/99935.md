Full review comments:

- **[P1] Route explicit setup flags through a supported path:** `src/commands/onboard.ts:32-39`
  - body: Interactive commands like `openclaw onboard --gateway-port 19000` or `--no-install-daemon` now fall into conversational onboarding, but that path only forwards the workspace and then uses quickstart defaults. Existing public setup flags must either keep routing to the classic wizard or be fully threaded through this flow so upgrades do not silently replace gateway/auth/daemon choices.
  - confidence: 0.9
- **[P2] Require full setup before calling onboarding ready:** `src/crestodian/onboarding-welcome.ts:18-19`
  - body: A valid config with only a default model now gets the ready welcome instead of the setup proposal, so first-run onboarding can skip workspace creation, gateway defaults, and the security acknowledgement that setup-apply records. The ready check needs a completed-setup signal, not just a model.
  - confidence: 0.86
- **[P2] Run channel post-write hooks from chat setup:** `src/crestodian/chat-engine.ts:94-103`
  - body: The chat setup path writes the config immediately after `setupChannels` but does not collect and drain channel `afterConfigWritten` hooks like `channels add` does. Adapters such as Matrix encrypted setup rely on that hook for required bootstrap, so this can report a channel configured while leaving it incomplete.
  - confidence: 0.9
- **[P2] Respect paused local gateways before starting chat:** `apps/macos/Sources/OpenClaw/OnboardingView+CrestodianSetup.swift:35`
  - body: Opening the Crestodian setup page in local mode only checks whether the CLI is installed before sending the RPC. Because local request recovery can call `GatewayProcessManager.setActive(true)`, the page can restart a gateway the user intentionally paused instead of respecting the existing onboarding guard.
  - confidence: 0.84
- **[P2] Keep the app timeout above the server turn:** `apps/macos/Sources/OpenClaw/OnboardingCrestodianChat.swift:72-75`
  - body: The macOS request times out at 120 seconds, while the server-side Crestodian path can wait 180 seconds and the embedded run can consume the full 120 seconds. A cold or slow local model turn can therefore show an app error while the server continues processing.
  - confidence: 0.88
