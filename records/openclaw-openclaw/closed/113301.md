## Summary

Close as a duplicate of the still-open canonical resolver report: this issue supplies a concrete third-party package example, but its central failure mode—an uncaught missing plugin entry during loading—is already tracked by https://github.com/openclaw/openclaw/issues/106628. Current main also validates missing declared extension files into diagnostics and catches module-load failures at the plugin loader boundary rather than treating them as an unhandled Gateway startup exception.

## What This Changes

Report that a plugin whose declared package entry is absent can crash Gateway startup instead of being skipped with an actionable plugin diagnostic.

## System Context

OpenClaw discovers installed plugins, resolves their declared runtime files, and imports each plugin into the Gateway registry. A missing or invalid entry must become a per-plugin diagnostic so the Gateway can continue starting and report which package needs repair.

  C --> D{Entry exists and imports?}
  D -->|Yes| E[Register plugin with Gateway]

  F --> G[Gateway continues startup]

Keep https://github.com/openclaw/openclaw/issues/106628 as the single report for malformed plugin entries, validate its release behavior with the affected package, and keep the recovery path diagnostic-first rather than silently importing an undeclared root file.
