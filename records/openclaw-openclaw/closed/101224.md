## Summary

Keep open. Current main and the latest release still route ClawHub skill install/update temporary work through `os.tmpdir()` into `@openclaw/fs-safe` temp workspaces, whose current implementation chmods the selected root directory to `0700`; the reporter's auditd logs match a real source-level availability bug.

## What This Changes

The issue reports that `openclaw skills install` and ClawHub skill updates can change `/tmp` permissions from `1777` to `0700`.

## Best Possible Solution

Route skill install/update archive staging and ClawHub download staging through a private OpenClaw-owned temp root, or fix the temp workspace wrapper so it never chmods a shared parent like `/tmp`; add regression coverage proving the parent temp directory mode is preserved.
