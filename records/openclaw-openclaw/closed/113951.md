## Summary

This is a focused, plausible repair for Control UI notification-click routing, and the supplied Chromium run plus CI evidence support the intended scoped behavior. Keep it open for maintainer review because it deliberately narrows the previously broad notification URL behavior and carries the `maintainer` label; the remaining question is whether any supported sender relies on same-origin targets outside the registered application scope.

## What This Changes

The PR changes Control UI service-worker notification clicks to resolve and focus only windows inside the registered OpenClaw application scope, adding regressions for nested deployments, multiple tabs, malformed URLs, and worker upgrades.

## System Context

The Control UI service worker receives web-push payloads and turns notification clicks into a focused or newly opened browser window. It must map notification URLs to the registered OpenClaw application path so reverse-proxy deployments preserve the intended session without navigating to unrelated same-origin pages.

## Best Possible Solution

Retain the registration-scope boundary, then confirm the supported notification payload contract and add a focused producer-side assertion or documentation note if out-of-scope same-origin URLs were ever supported.
