Overall confidence: 0.93

Full review comments:

- **[P1] Return an authenticated CDP WebSocket URL:** `extensions/browser/src/browser/extension-relay/relay-server.ts:132`
  - body: `/json/version` is fetched through an authenticated profile URL, but the returned `webSocketDebuggerUrl` drops the relay token. The Playwright path then derives auth headers from that returned WS URL, so discovery can succeed while the `/cdp` upgrade is rejected as unauthorized.
  - confidence: 0.94
- **[P1] Add browserContextId to page target info:** `extensions/browser/src/browser/extension-relay/relay-bridge.ts:342-349`
  - body: Playwright 1.61.1 asserts `targetInfo.browserContextId` for every non-browser target. The relay announces shared and created tabs as page targets without that field, so `connectOverCDP` can throw before listing or controlling the tab.
  - confidence: 0.92
- **[P2] Use the assigned relay port when pairing:** `extensions/browser/src/cli/browser-cli-extension.ts:32`
  - body: For unpinned extension profiles, config resolution assigns deterministic ports in `resolved.extensionRelayPorts`, but the pairing CLI falls back to the default port. A custom `driver: "extension"` profile can receive a pairing string for the wrong relay.
  - confidence: 0.9
- **[P2] Reattach existing shared tabs after reconnect:** `extensions/browser/src/browser/extension-relay/relay-bridge.ts:284-285`
  - body: After an extension reconnect, `handleExtensionGone()` clears each tab's attached state but keeps the tab entries. The next `hello`/`tabs` sync for those existing entries only updates metadata, so auto-attach clients never get the tabs back until the user removes and re-shares them or reconnects the CDP client.
  - confidence: 0.87
- **[P2] Detach debugger sessions when unpairing:** `extensions/browser/chrome-extension/background.js:380-382`
  - body: Unpairing removes the stored relay credentials and closes the WebSocket, but it does not detach any tab in `attachedTabs` or clear the shared group. Chrome can keep showing the debugging infobar after the user explicitly revoked pairing.
  - confidence: 0.89
- **[P2] Track extension-owned tab groups:** `extensions/browser/chrome-extension/background.js:58`
  - body: The extension treats every Chrome tab group titled `OpenClaw` as shared. A pre-existing or manually renamed group with that title is reported to the relay before the user clicks share, so unrelated signed-in tabs can become agent-visible.
  - confidence: 0.86
- **[P2] Return CDP-shaped targets from /json/list:** `extensions/browser/src/browser/extension-relay/relay-server.ts:139`
  - body: Existing fallback code expects Chrome-style `/json/list` entries with `id`, `url`, and sometimes `webSocketDebuggerUrl`, but this endpoint returns `RelayTabInfo` with `tabId`. Target-id fallback and JSON tab consumers cannot resolve shared tabs through the relay.
  - confidence: 0.9
- **[P2] Detach tabs before stopping the relay:** `extensions/browser/src/browser/extension-relay/relay-bridge.ts:770`
  - body: Relay shutdown closes the extension socket and clears bridge state without sending detach commands. The extension's close handler only schedules reconnect, so debugger attachments can remain active after OpenClaw stops or rebinds the relay.
  - confidence: 0.86
