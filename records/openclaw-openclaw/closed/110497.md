## Summary

Keep this active, maintainer-labeled PR open, but do not merge it yet: separating start from restart drops two established recovery/cleanup behaviors on existing managed gateways. Likely related people: steipete (high confidence) introduced and recently maintained the lifecycle-audit path in the preceding merged work.

## What This Changes

The branch adds a dedicated `GatewayService.start()` path and immediate lifecycle auditing for successful launchd, systemd, and Windows managed-service starts.

## Best Possible Solution

Keep dedicated audited start APIs, but make them preserve the restart path’s platform-specific recovery semantics: reset failed systemd units before starting and remove a stale Windows Startup fallback after the Scheduled Task is proven running.
