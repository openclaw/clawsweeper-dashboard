## Summary

Current `main` appears to have already fixed the reported CLI-backend node-execution gap through the merged node-only bundled-MCP `exec` path. This issue reports the stable `2026.7.1-2` behavior; the matching repair merged on July 10, 2026, so no additional core change is needed.

## What This Changes

Expose a policy-scoped, node-forced `exec` tool to CLI-backed agent sessions so their bundled MCP surface can execute approved commands on a connected node without enabling a second gateway-local shell.

## System Context

CLI-backed agents receive OpenClaw tools through a bundled loopback MCP server while their native shell runs on the gateway host. The gateway resolves that tool surface and, for eligible sessions, now grants a node-forced `exec` path into the existing approval and node-command runtime.

  D -->|Yes| E[Node-forced exec tool]
  D -->|No| F[Control tools only]
  E --> G[Approval and execution policy]
  G --> H[Connected node command]

## Best Possible Solution

Keep the node-only bundled-MCP `exec` implementation as the canonical CLI-backend path and retain the generic `nodes.invoke system.run` denial as a fail-closed boundary.
