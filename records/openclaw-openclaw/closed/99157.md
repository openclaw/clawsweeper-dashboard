## Summary

Current main and the latest release already remove the recurring background Feishu probe path that drives the reported monthly Lark quota exhaustion; the remaining startup and explicit diagnostic probes are one-shot/operator-requested behavior rather than the automatic health-loop problem described here.

## What This Changes

The issue requests a way to disable or throttle Feishu/Lark bot health probes so metered tenants are not forced over Lark API quotas.

## Best Possible Solution

Keep the current shipped behavior that avoids automatic Feishu probes; handle any desired full no-probe startup or explicit-diagnostics mode as a separate maintainer-sponsored config/product request.

## Reproduction Assessment

No for the high-volume current-main bug: periodic gateway health refresh and the channel health monitor do not call Feishu probes. Source still shows startup and explicit diagnostic probes, but those are not the monthly 60-second background loop described here.

## Solution Assessment

Yes for the central outage driver: keeping background health refresh non-probing is narrower than adding another config surface. A full Feishu no-probe switch would be a separate product/config decision rather than required to fix this issue.
