## Summary

This PR remains necessary because current main still derives outbound conversation references from the raw prefixed target when an adapter returns no conversation ID. The patch correctly normalizes routing-only provider and kind prefixes at the outbound projection boundary, preserves adapter identifiers as authoritative, and leaves the raw target available for its separate target reference; no blocking correctness or security finding was found.

## What This Changes

The PR normalizes provider- and kind-prefixed outbound targets before using them as fallback message-audit conversation identifiers and adds focused regression coverage.

## Best Possible Solution

Keep the fallback normalization in the outbound audit projection so it shares the destination-routing grammar, while preserving adapter-returned conversation IDs as authoritative and the original routed target as a separate pseudonymous target reference.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. On the PR base, a message-ID-only adapter result supplies no conversation ID, causing the audit store to hash the raw prefixed target and produce a different reference from an inbound record keyed by the platform conversation ID.

## Solution Assessment

Yes. Reusing the canonical provider and target-kind normalization at the owning outbound projection is narrower and more maintainable than changing the generic audit store or adding channel-specific fallback rules.
