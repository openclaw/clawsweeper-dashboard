## Summary

Current main and v2026.6.11 still contain the onboarding retry lockout, and the linked closing PR remains open, so this issue is still necessary. The report identifies a concrete core onboarding bug rather than a new feature request.

## What This Changes

Make a failed onboarding migration import retryable without requiring users to wipe config, credentials, sessions, or workspace state.

## Best Possible Solution

Keep one canonical retry-safe migration boundary that preserves successful provider mutations, records partial application durably, and offers an in-product retry or recovery path, with a regression covering failed apply followed by an immediate second onboarding attempt.
