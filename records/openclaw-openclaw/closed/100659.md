## Summary

Close as superseded: current main and the merged keyless Firecrawl implementation intentionally support keyless `web_fetch` through explicit provider selection or configured credentials, not empty-config keyless auto-detection.

## What This Changes

The issue asks OpenClaw to auto-detect keyless `web_fetch` providers without requiring any configured credential.

## Best Possible Solution

Keep the merged explicit-selection keyless `web_fetch` behavior from https://github.com/openclaw/openclaw/pull/94551; discuss any new auto-selection policy in a maintainer-sponsored follow-up, likely alongside https://github.com/openclaw/openclaw/issues/96743.

## Solution Assessment

No, changing the branch exactly as proposed is not the best cleanup path because it would silently change provider auto-detection semantics. The safer outcome is to keep explicit selection unless maintainers choose a new provider-routing policy.
