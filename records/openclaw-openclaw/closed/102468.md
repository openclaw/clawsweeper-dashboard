## Label Justifications

- `P1`: Default Telegram long turns can make a group unresponsive and then abort otherwise healthy reply work after the spooled handler timeout.
- `impact:message-loss`: Same-lane Telegram messages are held upstream of session admission, and timeout recovery can fail the active spooled update rather than deliver a normal reply path.
- `impact:session-state`: The transport lane prevents mid-turn Telegram messages from entering the active session queue or steering admission while a reply operation is running.

## Summary

Keep open: current main still holds the Telegram isolated-ingress lane while the full downstream turn runs, and the protected maintainer label plus Telegram replay/ordering blast radius make this a maintainer design item rather than cleanup closure.

## What This Changes

The issue requests a Telegram ingress ownership redesign so per-chat/topic spool lanes complete after durable handoff to session admission instead of staying held for the entire agent turn.

## Best Possible Solution

Define and land a Telegram ingress handoff design that completes the spooled lane claim after durable session-admission handoff while preserving replay safety, reply-fence cleanup, crash/restart behavior, and live Telegram proof.

Options:

- **Detach After Durable Handoff (recommended):** Move Telegram spool lane lifetime to ingestion/classification plus durable session handoff, then let session admission own active-run ordering and steering.
- **Keep Lane Ownership And Tune Recovery:** Preserve one-handler-per-lane transport ownership and improve timeout or user-visible recovery, accepting that same-lane messages still cannot reach steering during long turns.
- **Split Narrow Follow-Ups:** Track handler-timeout visibility and collect starvation separately while leaving this issue as the umbrella design decision for lane ownership.

## Reproduction Assessment

Yes, at source level: current main awaits the full Telegram update handler while marking the lane active, blocks later same-lane spooled updates, and keeps timeout tests for that behavior. I did not run a live Telegram long-turn reproduction in this read-only review.

## Solution Assessment

Unclear until maintainer design review: detaching after durable handoff appears to be the right ownership direction, but it must preserve Telegram replay, tombstone, ordering, and reply-fence contracts.
