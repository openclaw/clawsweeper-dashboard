## Summary

Keep open: current main still lets `sessions.create` resolve, parent-link, and fork a source session without checking the parent entry's `pluginOwnerId` against the plugin-runtime caller, while the sibling delete path enforces that boundary.

Report that `sessions.create` can fork or parent-link another plugin-owned session without checking ownership of the source session.

## Best Possible Solution

Add a narrow gateway security fix that checks the resolved parent session owner before `sessions.create` parent-linking or forking, with regression coverage for foreign-owner denial and same-owner success.
