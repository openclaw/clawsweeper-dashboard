## Summary

This is a focused SMS replay-cache bug fix with useful runtime proof, but it should stay open for maintainer review because the new saturated-cache path intentionally returns HTTP 429 and that can affect SMS delivery unless Twilio retry/fallback behavior is accepted or documented.

## What This Changes

The PR changes the SMS Twilio webhook replay cache to prune expired entries before capacity checks, preserve live replay keys, and return 429 when every tracked SID is still unexpired, with regression tests for saturation.

## Best Possible Solution

Preserve the replay-protection fix, but make the rare saturation delivery tradeoff explicit before merge and avoid implying Twilio will retry 429 unless the configured webhook URL or fallback path actually provides that behavior.
