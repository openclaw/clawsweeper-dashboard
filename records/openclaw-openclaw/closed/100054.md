## What This Changes

The PR changes `sessions.usage` to group visible and hidden sessions by agent and call `loadSessionCostSummariesFromCache` once per agent instead of calling the single-session cache loader for each visible entry.

## Best Possible Solution

Land the narrow batched-loader fix after real gateway/dashboard proof confirms the false `rss_growth` warning is reduced, while leaving broader usage-cache isolation work to https://github.com/openclaw/openclaw/issues/86718.

## Reproduction Assessment

Yes at source level: current main builds one visible-session cache-summary task per returned visible session, and each task reads the durable usage-cost cache. I did not rerun the live RSS replay, but the linked issue provides v2026.6.11 limit=50 versus limit=1 measurements that match this path.

## Solution Assessment

Yes, this looks like the best narrow fix: it reuses the existing batched cache loader already used for hidden sessions instead of adding a new cache or changing diagnostics thresholds. The broader worker/isolation problem should stay separate.
