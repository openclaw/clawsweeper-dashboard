## Summary

Keep this issue open: current main tracks per-agent auth-profile identity for claude-cli compatibility and status reporting, but the turn subprocess still follows Claude Code’s gateway-wide native login unless credentials are explicitly forwarded. The remaining choice concerns credential ownership and safe child-process delivery, so implementation needs an Anthropic runtime owner’s decision rather than automated repair.

## What This Changes

Allow claude-cli turns to use the selected agent’s Anthropic auth profile, with native shared login as the fallback when no compatible profile exists.

## Best Possible Solution

Make an explicitly selected or ordered compatible per-agent profile take precedence for that Claude child only, deliver it through a supported narrowly scoped secret mechanism with defined refresh behavior, retain native Claude login only when no compatible profile exists, and have `models status` call the same effective-auth decision path.
