## Summary

Keep open: this is a focused candidate fix for the linked cron catch-up bug, but it is not merge-ready because the new persisted marker can leak through full cron list/get responses while the public cron state schema still forbids that field, and the contributor proof is unit-test-only.

## What This Changes

The branch moves startup catch-up deferral tracking from a process-local CronServiceState Set into CronJobState.pendingCatchupDeferral and updates maintenance, timer, rollback, and cron tests around that marker.

## Best Possible Solution

Persist the marker in cron runtime state, keep it out of public cron API responses unless maintainers intentionally add it to the protocol, add focused schema/read-view regression coverage, and include real restart proof before merge.
