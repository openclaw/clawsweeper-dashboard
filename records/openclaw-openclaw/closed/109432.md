## Summary

The prior P1 remains on the latest head: the timeout reduces ordinary stalls but does not establish the claimed hard startup deadline, because the synchronous child-process call still blocks until the child closes. Keep this PR open for an owner-level startup-boundary decision and supported-host proof.

## What This Changes

Adds a one-second timeout to fallback SQLite mount classification, selects rollback journaling on timeout, and expands WAL-policy tests.

## Best Possible Solution

Prepare and process-cache filesystem classification asynchronously outside database opening, reuse that snapshot for every SQLite store, conservatively select rollback journaling when classification is unavailable, and prove aggregate startup plus journal selection on a supported macOS/BSD host.
