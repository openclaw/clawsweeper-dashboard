## Summary

Keep open: this is a focused, well-supported bug fix for the linked OpenAI OAuth false-cooldown path, with no blocking code findings. It still changes auth-provider cooldown semantics, so it should stay on the protected maintainer review path before merge.

## What This Changes

The PR adds an access-token expiry check before OpenAI OAuth WHAM cooldown probes and adds a regression test for expired access tokens using normal transient cooldown instead of a 12-hour WHAM cooldown.

## Best Possible Solution

Land the narrow expiry-gated WHAM probe after auth-owner review, preserving the 12-hour WHAM 401 cooldown for locally valid tokens that WHAM rejects.

## Maintainer Decision

## Reproduction Assessment

Yes, at source level. Current main probes WHAM with any stored OpenAI OAuth access token and maps a 401 to a 12-hour cooldown, while the PR body also includes live before/after output for the expired-token case.

## Solution Assessment

Yes. The central decision point is `shouldProbeWhamForFailure`, and gating that probe on local token expiry avoids the false 401 path while preserving the existing 12-hour cooldown for locally valid tokens rejected by WHAM.
