## Summary

Current main still sends both Quick Config controls to keys rejected by the strict schema, so the reported silent save failure remains real. The thinking repair is mechanical, but fast mode needs a maintainer scope decision because runtime supports per-agent and per-model defaults—not the proposed global defaults key.

## What This Changes

Fix Control UI Quick Config so the Model & Thinking card persists changes through canonical configuration contracts.

## Best Possible Solution

Change thinking to `agents.defaults.thinkingDefault`; after choosing fast-mode scope, bind that control to an existing per-agent or selected-model setting, or deliberately add a fully typed, documented, runtime-tested global precedence contract—not a schema-only key.
