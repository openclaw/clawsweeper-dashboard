## Summary

Keep open: current main and the latest release still contain the matched-allowlist plan-miss gate that produces the reported warning, while the docs still promise `on-miss` prompts only when the allowlist does not match.

## What This Changes

The issue asks OpenClaw to restore documented macOS gateway exec behavior so allowlisted `ask: "on-miss"` commands do not require human approval when they can be safely enforced.

## Best Possible Solution

Restore documented `on-miss` behavior only for Darwin command shapes that OpenClaw can render into an enforced command, keep explicit approval for truly unenforceable plans, and document the remaining command-shape limitations.
