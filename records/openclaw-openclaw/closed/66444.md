Full review comments:

- **[P1] Preserve the activation retry:** `src/daemon/systemd.ts:735`
  - body: Current main retries `daemon-reload` plus the failed `enable`/`restart` when systemd says the freshly written unit does not exist. This branch goes back to a single reload followed by direct `enable`, so the migrated/root systemd race fixed by `e4e69c5bc6` can fail again after install/update.
  - confidence: 0.93
- **[P1] Honor custom systemd units during uninstall:** `src/daemon/systemd.ts:794`
  - body: The PR head resolves the uninstall target with `resolveGatewaySystemdServiceName(env.OPENCLAW_PROFILE)`, ignoring `OPENCLAW_SYSTEMD_UNIT`. That reopens the node-only/custom-unit bug fixed on current main, where uninstall disables `openclaw-gateway.service` instead of the actual custom unit.
  - confidence: 0.94
- **[P1] Carry current env-file preservation into migration:** `src/daemon/systemd.ts:527-533`
  - body: `writeSystemdUnit` no longer receives `environmentValueSources`, so the new migration cannot distinguish inline-only, file-only, and inline-and-file values. Current main uses that contract to keep SecretRef/file-backed values out of inline unit env and to preserve operator env files; dropping it can reintroduce token and missing-secret regressions during restage.
  - confidence: 0.9
- **[P1] Reject option-like unit names:** `src/daemon/systemd.ts:55-63`
  - body: The new validator rejects paths but still accepts names beginning with `-`, and the `systemctl` calls pass unit names without a `--` terminator. A custom `OPENCLAW_SYSTEMD_UNIT` such as `--user` or `-Hhost` can still be parsed as a `systemctl` option instead of a service operand.
  - confidence: 0.88
- **[P1] Preserve kept Environment assignment values:** `src/daemon/systemd-unit.ts:270-272`
  - body: When stripping one assignment from a mixed `Environment=` line, this re-renders the kept values through `renderEnvLines`, which filters out empty values and trims whitespace. Valid operator settings like `Environment=LD_PRELOAD=` or whitespace-significant values can be silently changed during migration.
  - confidence: 0.89
- **[P1] Avoid direct writes for token-bearing drop-ins:** `src/daemon/systemd.ts:637-638`
  - body: The managed drop-in can contain gateway tokens, but the branch writes and backs up predictable HOME-derived systemd paths with direct `copyFile`/`writeFile`. Before this changes the secret storage path, the branch needs a safe write/backup strategy or an explicit owner-approved threat model for symlink and permission behavior.
  - confidence: 0.82
- **[P2] Remove the release-owned changelog edit:** `CHANGELOG.md:20`
  - body: `CHANGELOG.md` is release-owned in this repo, and this branch edits it directly. Keep the release-note context in the PR body or squash message and let release generation update the changelog.
  - confidence: 0.96
