## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Do not treat wildcard-configured groups as unknown:** `extensions/telegram/src/unknown-group.ts:12`
  - body: `group-policy-allowlist-empty` also occurs for configured wildcard `groups: {"*": ...}` when no sender allowlist is configured, because wildcard matches do not set `groupConfig` in the group-policy result. Marking that reason as unknown makes `unknownGroupAction: "leave"` eject the bot from groups intentionally covered by wildcard config.
  - confidence: 0.9
- **[P2] Build warning thread params with the Telegram helper:** `extensions/telegram/src/bot-handlers.runtime.ts:1660`
  - body: `resolvedThreadId` can be `1` for a forum General topic, and existing `buildTelegramThreadParams()` intentionally omits `message_thread_id=1` because Telegram rejects that value for sends. Passing the raw thread id here makes warn/leave fail to send the configured warning in General-topic forums.
  - confidence: 0.91
- **[P2] Apply unknown-group actions before native commands return:** `extensions/telegram/src/bot-handlers.runtime.ts:1645`
  - body: The new action only runs in the regular message handler. Native and plugin slash commands are registered earlier and return from their own auth path on `group-chat-not-allowed`, so `/help` in an unknown group still sends the old auth reply and never warns or leaves as configured.
  - confidence: 0.86
