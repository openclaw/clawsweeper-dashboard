## Summary

The defect is present in both the latest release and current main: repeated sequential `nack()` calls repeat the callback. The report should stay open, but its proposed pending-only guard is too broad because current tests intentionally allow an acknowledged context to transition to nacked.

## What This Changes

Make repeated message receive `nack()` calls invoke `onNack` only once.

## Best Possible Solution

Add an already-nacked guard that preserves the tested ack-to-nack transition, then cover duplicate sequential calls and rejected-callback retry semantics in the lifecycle tests.
