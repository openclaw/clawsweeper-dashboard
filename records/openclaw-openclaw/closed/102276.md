## What This Changes

The PR adds a pre-execute abort guard for prepared agent-core tool calls, propagates `executionStarted: false` for skipped calls, skips `afterToolCall` for work that never started, and adds a focused regression test.

## Best Possible Solution

Merge this small agent-core guard after the contributor adds redacted real setup proof that a canceled parallel batch no longer starts the paid-style prepared tool.

## Solution Assessment

Yes. Rechecking abort state immediately before `tool.execute` is the narrow core boundary; requiring every paid or async tool to self-police a signal that was already aborted before execution would be weaker and easier to drift.
