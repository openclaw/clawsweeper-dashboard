## Summary

Keep this PR open: the patch appears mechanically correct and useful, with no blocking review findings; the main merge consideration is maintainer acceptance of a new 16 MiB inbound frame cap across all realtime transcription providers.

## What This Changes

The PR adds a 16 MiB `ws` `maxPayload` limit to the shared realtime transcription websocket session and adds boundary tests for below-cap and over-cap inbound frames.

## Best Possible Solution

Land the shared `maxPayload` guard with its boundary tests once maintainers accept the 16 MiB all-provider cap; only change the cap if provider contract evidence shows legitimate realtime transcript frames need more headroom.
