## Summary

Keep open. Current main and v2026.6.11 already provide implicit Linux no-display headless fallback and an actionable explicit-headed error, but the browser route/client boundary still collapses that case to a string-only error instead of the requested machine-readable reason/details contract.

## What This Changes

The issue asks managed browser launch to either safely fall back or return a structured, actionable no-display result when headed launch is requested without a display server.

## Best Possible Solution

Define an additive BrowserProfileUnavailableError reason/details contract serialized by browser routes and preserved by BrowserServiceError, while keeping explicit headed no-display fail-closed unless maintainers approve an opt-in fallback policy.

Yes, at source level. Explicit headed local managed launches on Linux without DISPLAY/WAYLAND_DISPLAY reach BrowserProfileUnavailableError, and the route/client helpers expose only a string error instead of a stable reason/details object.

## Solution Assessment

Unclear until the maintainer chooses the contract shape. The narrowest maintainable path appears to be an additive structured error envelope, not broader automatic fallback for explicitly headed launches.
