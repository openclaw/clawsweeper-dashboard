## Summary

The report identifies a plausible current connection-lifecycle gap: the backend OpenAI Realtime client bounds message size but does not independently bound the WebSocket upgrade. The upstream `ws` client explicitly supports `handshakeTimeout`, and no related item or current-main implementation was found that already owns this fix.

## What This Changes

Bound OpenAI realtime-voice WebSocket upgrade attempts so a peer that accepts TCP but never completes the upgrade cannot stall session startup indefinitely.

## Best Possible Solution

Add a named provider-owned handshake deadline to every equivalent backend OpenAI/Azure realtime WebSocket constructor that lacks one, preserve the existing startup error path, and cover a server that accepts TCP without returning an upgrade response.
