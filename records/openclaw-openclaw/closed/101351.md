- `impact:auth-provider`: The broken behavior is selection and reuse of gateway-issued device credentials during Control UI authentication.

- `impact:security`: The issue concerns bearer device credentials being reused against the wrong same-origin gateway endpoint.

## Summary

Keep open: current main still has the unscoped Control UI device-auth storage behavior, and the linked fixing PR is open rather than merged. The issue is also maintainer-labeled and authored by a member, so cleanup should not close it ahead of the fix review.

The issue asks Control UI to scope gateway-issued browser device credentials by exact gateway endpoint so same-origin path or query routed gateways do not overwrite each other.
