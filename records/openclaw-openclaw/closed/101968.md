## Summary

Keep this PR open: the bounded-read and cache-cap hardening is useful, and the PR body provides credible real behavior proof, but the patch is not merge-ready because oversized or malformed 409 conflict bodies now fall through the outer fail-open path and can allow a Slack thread send that should remain cancelled.

## What This Changes

The branch routes Thread Ownership 409 conflict JSON through the plugin SDK bounded reader, caps the Slack mention bypass map at 2000 entries, re-exports the needed SDK helpers from the extension API barrel, and adds focused regression tests.

## Best Possible Solution

Land a narrow version that bounds the 409 body and caps the mention cache while preserving 409-as-cancel semantics, then reconcile or close the overlapping hardening PRs once one branch is chosen.

No as submitted: the cache cap and shared bounded reader are the right shape, but the 409 branch must preserve cancellation when the owner body is oversized or malformed. A safer version catches parse/overflow inside the 409 branch and returns `{ cancel: true }` with an unknown owner.
