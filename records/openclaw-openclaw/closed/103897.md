## Summary

Keep open: the shipped release and current main both contain a contradictory tool contract that leaves CLI-backed agents unable to use the advertised remote-node shell path. The report is source-reproducible, affects a stable security-sensitive runtime surface, and has neither a merged fix nor a viable canonical replacement.

## What This Changes

Expose a policy-scoped remote-node execution path to CLI-backed agents so they can follow `exec host=node` guidance without using the Gateway host shell.

## Best Possible Solution

Expose a node-only projection of the existing `exec` contract to CLI loopback MCP, constrained by effective tool policy and the existing node approval pipeline, with composed tests and live proof showing remote `system.run` succeeds while Gateway-host shell access remains unavailable.
