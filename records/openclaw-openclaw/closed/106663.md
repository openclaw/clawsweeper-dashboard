## Label Justifications

- `impact:security`: The report concerns whether manipulated configuration paths can expose sensitive host files.

## Summary

Current main already confines configuration includes to the config directory or explicit operator-approved roots, revalidates canonical paths and symlinks, and performs guarded open-time boundary checks; the report’s named `config-paths.ts` file only handles dotted object keys and is not the config-import reader.

## What This Changes

Prevent configuration imports from traversing outside the designated configuration root and reading arbitrary host files.

## Best Possible Solution

Keep the shipped config-include boundary: default to the directory containing `openclaw.json`, permit additional trees only through explicit `OPENCLAW_INCLUDE_ROOTS`, and retain lexical, canonical, symlink, and guarded-open checks.

## Maintainer Decision

Required: false

## Reproduction Assessment

No. On current main, a `../../../etc/shadow` include resolves outside the permitted config roots and is rejected before the guarded read; regression tests also cover off-root and symlink escapes.

## Solution Assessment

Yes. The existing layered design is stronger than a string `startsWith` assertion because it checks lexical containment, canonical targets, symlinks, realpath failures, and the opened file against the matched root.
