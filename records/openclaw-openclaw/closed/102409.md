## Summary

Keep open: this fixes a real UTF-8 boundary bug in `persistEventPayload`, but it is not merge-ready because the new implementation decodes/re-encodes the full payload for an 8 KiB preview and the standalone `openclaw proxy start/run` preview path still has the same mid-character truncation bug.

## What This Changes

The PR changes proxy-capture `persistEventPayload` to use `truncateUtf8Prefix` for inline previews and adds focused tests for multibyte UTF-8 boundaries.

## Best Possible Solution

Use a Buffer-aware UTF-8 preview helper that keeps work capped at the preview byte budget and route both `persistEventPayload` and `finishBodyPreviewCapture` through it with tests and real capture proof.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P2] Keep preview truncation byte-bounded:** `src/proxy-capture/store.sqlite.ts:935`
  - body: `buffer.toString("utf8")` decodes the entire captured payload, and `truncateUtf8Prefix` then turns that whole string back into a Buffer before trimming to 8192 bytes. The old path only decoded the preview prefix; for large request/response/WS payloads this makes preview generation proportional to full body size and can reintroduce capture-side memory/CPU pressure. Please truncate on a Buffer prefix boundary instead of decoding the full payload.
  - confidence: 0.88
- **[P2] Cover the standalone proxy preview path:** `src/proxy-capture/store.sqlite.test.ts:368-371`
  - body: The new regression tests exercise only `persistEventPayload`, but `openclaw proxy start/run` records request and response previews through `finishBodyPreviewCapture` in `src/proxy-capture/proxy-server.ts`, which still decodes an arbitrary 8192-byte prefix with `Buffer.concat(...).toString("utf8")`. A real standalone proxy capture can still store a trailing `U+FFFD`, so the sibling path needs the same boundary-safe fix and proof.
  - confidence: 0.9
