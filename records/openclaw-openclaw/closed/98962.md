## Summary

Current main and the latest release still silently keep the last duplicate model alias, and the linked candidate PRs are both open/unmerged with unresolved compatibility and coverage concerns. This issue should stay open as the canonical report until one coherent fix lands.

## What This Changes

The issue requests duplicate configured model aliases to stop resolving silently by last-match overwrite and instead receive an operator warning with deterministic model selection.

## Best Possible Solution

Land one coherent fix that warns on duplicate aliases in both direct configured-model resolution and alias-index resolution while preserving shipped selection semantics unless maintainers explicitly approve a precedence break.
