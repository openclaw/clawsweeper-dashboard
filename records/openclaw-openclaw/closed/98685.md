## Repair Work Prompt

Fix https://github.com/openclaw/openclaw/issues/98685. Current main records logMessageQueued after queueEmbeddedAgentMessageWithOutcomeAsync accepts delivery into an active embedded run, while clearActiveEmbeddedRun emits one idle state transition; multiple steered messages can therefore leave diagnostic queueDepth positive after embedded_run:ended even when no active/waiting work remains. Keep the repair inside embedded-run/diagnostic accounting, distinguish accepted active-run steering from real queued backlog or reconcile it on normal run end, and avoid new config, fallback policy, or broad stuck-session recovery changes. Add focused regression coverage for multiple active-run steered messages completing with no active/waiting work and queueDepth 0; follow src/agents/embedded-agent-runner/run/AGENTS.md by preferring helper-level tests over full expensive runner coverage unless needed. Do not edit CHANGELOG.md.
