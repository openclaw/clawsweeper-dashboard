## Summary

Keep open: current main and the latest release still use `.jsonl.deleted.*` and `.jsonl.reset.*` as first-class archive names, and retention plus disk-budget paths can still physically remove those retained transcript artifacts. The role-ordering reset hard-delete path was fixed by a merged PR, but the broader naming, migration, and no-delete policy requested here remains unresolved.

## What This Changes

The issue requests replacing destructive-looking session archive suffixes such as `.deleted.*` and `.reset.*` with non-destructive archive semantics and preventing OpenClaw from physically deleting retained session transcripts.

## Best Possible Solution

Define one durable transcript lifecycle contract: retained transcripts should use archive-oriented names or storage, old suffixes should migrate through doctor/backfill rather than runtime aliases, and any physical purge should be explicit, documented, and upgrade-tested.

- **Split naming from purge policy:** Use the open semantics issue for suffix/config clarity while tracking no-physical-delete as a separate data durability decision.
