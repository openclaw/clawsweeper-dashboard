## Summary

Keep open: current main still makes quarantined Skill Workshop proposals terminal for normal CLI/tool lifecycle actions, while docs tell users to revise or quarantine after a scan failure and quarantined proposals still count against the active proposal limit.

## What This Changes

The issue requests a supported path to recover or dismiss Skill Workshop proposals after they enter `quarantined` status.

## Best Possible Solution

Add a bounded recovery path that lets quarantined proposals be revised back to pending after validation and rejected/dismissed without touching live skills, while keeping direct apply protected by the existing clean-scan and workspace-write checks.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level. Current main routes apply, revise, reject, and quarantine through a pending-only gate, and docs plus tests show quarantined proposals remain active but cannot be recovered through those actions.

## Solution Assessment

Yes, the best fix is a narrow lifecycle repair rather than a broad new workflow: allow revise or reject from quarantined with tests, and keep apply gated on a clean scan instead of directly applying quarantined content.
