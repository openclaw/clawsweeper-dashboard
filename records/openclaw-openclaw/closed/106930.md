## Summary

Keep this PR open for feature-history owner review. It is a focused, proof-backed repair for premature context compaction, but it deliberately changes the prepared catalog’s cross-provider precedence rule and needs an updated review against current `main`.

## What This Changes

The branch preserves provider-discovered model context limits through the prepared catalog lifecycle, using final and static catalog metadata only to fill missing context-cache keys.

## System Context

OpenClaw builds a prepared model catalog when configuration and auth state are published, then agent context resolution reads its cached limits to decide when to compact sessions. This PR keeps the live provider-discovery values distinct from manifest, configured, and bundled fallback metadata before that cache is populated.

## Best Possible Solution

Adopt one explicit prepared-catalog rule—live discovery is authoritative for its route and static/final rows only fill absent keys—then rebase and rerun the focused provider-context proof against current `main`.
