## Label Justifications

- `P1`: The reported state blocks an active WebChat workflow by preventing normal session navigation until the user refreshes or resets.
- `impact:session-state`: The symptom is an incorrect derived active-session state after a completed agent run.
- `impact:ux-friction`: Users can recover by refreshing or resetting, but the normal in-product session workflow becomes confusing and interrupted.

## Summary

Close as implemented: current WebChat lifecycle reconciliation explicitly clears stale active-session rows when live events or polling no longer identify the run, which matches the reported indefinitely spinning session indicator. The behavior was added by the merged WebChat fix and is covered by focused regression tests.

## What This Changes

The issue reports that WebChat leaves a completed agent session in a loading state, preventing session switching or creation until the page is refreshed or the session is reset.

## System Context

WebChat combines gateway run events with polled session state to decide whether a chat session is still active. That derived state drives the session-list loading indicator and whether navigation remains available after a response completes.

## Architecture Diagram

  C --> D{Run still active?}
  D -->|Yes| E[Keep session loading state]
  D -->|No or stale| F[Clear active session row]
  F --> G[Stop spinner and allow navigation]
