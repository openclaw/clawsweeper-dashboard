## Summary

Keep open: the report gives a deterministic current-main source-level reproduction, no merged fix or viable linked PR is identified, and the maintainer label plus assignment require explicit maintainer handling rather than automated cleanup.

## What This Changes

Allow Control UI session creation to proceed while an unrelated session-list refresh is loading.

## Best Possible Solution

Remove list-loading state from the session-create eligibility gate, retain connection and scope validation, queue the post-create authoritative refresh through the existing refresh serializer, and add a deferred-list regression test proving `sessions.create` is sent exactly once.

## Reproduction Assessment

Yes at source level: holding `sessions.list` pending sets shared loading state, after which creation returns `null` before issuing `sessions.create`; the issue also reports a deterministic 1/1 Testbox reproduction. I could not rerun it because local read-only commands were unavailable.

## Solution Assessment

Yes—the narrow maintainable fix is to decouple the write request from read-only list loading and reuse the existing refresh queue afterward, rather than adding another lock or parallel refresh path.
