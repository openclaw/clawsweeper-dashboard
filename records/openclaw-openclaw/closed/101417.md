## Summary

Keep open: the PR targets a valid Windows process-cleanup bug, but the patch only swallows async `taskkill.exe` spawn errors and still does not run the direct child-kill fallback that would prevent the orphaned process leak.

## What This Changes

This PR adds no-op `error` listeners to the three Windows `taskkill.exe` spawn calls in `src/process/exec.ts` and adds a standalone proof script under `test/`.

## Best Possible Solution

Route every Windows taskkill child `error` through a shared fallback that directly kills the original child when appropriate, preserve trusted System32 lookup, and add focused regression tests plus redacted Windows/OpenClaw proof.

Yes for source-level reproduction: current main returns after `taskkill.exe` spawns that lack async fallback handling, and Node documents failed spawns as `error` events. I did not run a live Windows end-to-end reproduction in this read-only review.

## Solution Assessment

No: this branch is not the best fix because it swallows taskkill child errors instead of routing them to the existing direct `SIGKILL` fallback. The maintainable fix is a small helper or equivalent shared logic that handles all taskkill spawn failures consistently.
