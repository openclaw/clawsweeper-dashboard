## Summary

This PR is still necessary: current `main` retains separate active-transcript selection logic in the bounded reader and pagination index, so branched histories can disagree about the preceding compaction boundary. The proposed shared selector removes that drift, carries forward the prior review’s requested consolidation, and has focused JSONL regression coverage; it is ready for ordinary maintainer merge review once required checks finish.

## What This Changes

The branch introduces one active-transcript entry selector and uses it in both filesystem history readers so pagination includes the preceding compaction marker with matching totals and sequence metadata.

## Best Possible Solution

Keep one canonical selector for active transcript entries, use it for every filesystem reader that assigns paginated history identity, and merge this focused correction without folding in the broader WebChat cursor/UI proposal.
