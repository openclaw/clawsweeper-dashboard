## Summary

Keep open: current main protects the main Control UI list/picker path with label-backed display names, but label precedence is still inconsistent in derived-title consumers and related Control UI naming/title work remains unsettled.

## What This Changes

The issue asks OpenClaw to consistently render a persisted user session label across Control UI/WebChat headers, pickers, reloads, reconnects, restarts, and session-family rotations.

## Best Possible Solution

Define one shared session display precedence contract, likely label before generated derived title for user-visible names, and cover label-only sessions in the derived-title/client paths before closing this issue.

## Reproduction Assessment

Yes at source level: deriveSessionTitle ignores entry.label, and the TUI session picker requests derived titles and renders them before displayName. The exact Control UI browser symptom still lacks live reproduction against current main.

## Solution Assessment

Unclear: the narrow code fix is likely to add label precedence to derived-title/client title resolution, but maintainers should first align it with the open Control UI rename and browser-title work so there is one session-name contract.
