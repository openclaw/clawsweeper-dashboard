- `P2`: The PR addresses silent CLI agent-session history loss under a bounded filesystem race, but the remaining case has limited scope.

## Summary

The reported history-loss bug is real and the shared reader improves short-read handling, but the prior blocker remains: the positional offset is still calculated from a path size captured before opening the transcript, so a replacement with a sufficiently smaller file can still return an incomplete or empty history.

## What This Changes

The PR changes oversized CLI session-tail loading to use the shared full-window reader, decode only returned bytes, and add shrink-race regression coverage.

## Best Possible Solution

Calculate the bounded tail length and offset from `handle.stat()` after opening the transcript, retain decode-by-`bytesRead` and partial-first-line trimming, and cover a replacement whose old offset would fall beyond the new file’s intended tail.
