## Summary

Current main does not implement local human accounts or exact-tab member RBAC, and no published PR currently owns the work. The request is legitimate but crosses the newly established plugin-owned Workspaces boundary into stable gateway identity, authorization, SDK, CLI, and hosted-UI contracts, so it should remain open for an explicit maintainer product and security decision before the unpublished branch is reviewed.

## What This Changes

Add an opt-in gateway-local Teams mode with local human identities, exact workspace-tab grants, owner-mediated change requests, invitations, and a restricted member portal.

## Best Possible Solution

Approve a staged design first: add only a minimal reusable identity and exact-resource authorization kernel to core where genuinely required, while keeping invitations, workspace-tab policy, change requests, sharing administration, and the restricted portal in the Workspaces owner surface unless maintainers explicitly sponsor a first-party core Teams product.
