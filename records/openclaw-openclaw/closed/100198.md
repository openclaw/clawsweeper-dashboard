## Summary

Keep open: current main still has gateway event inventories and mobile handlers without the requested CI parity check, and the protected maintainer label requires explicit maintainer handling rather than cleanup closure.

## What This Changes

Request a CI-runnable gateway protocol event/method coverage check that compares the advertised protocol inventory to iOS and Android client handlers with explicit allowlists for intentionally ignored events.

## Best Possible Solution

Add a focused protocol/mobile parity guard under gateway-protocol or scripts that compares GATEWAY_EVENTS and relevant schema/catalog exports with iOS and Android dispatch tables, uses reviewed allowlists for intentional ignores, and runs in the relevant Node/native CI scope.

## Reproduction Assessment

Not applicable as a CI coverage request rather than a runtime bug. Source inspection confirms current main has an advertised event catalog and separate mobile handlers, but no parity check tying them together.

## Solution Assessment

Yes, deriving an inventory from the gateway protocol/catalog and comparing it to mobile handlers is the right layer for this guard. The allowlist policy should be maintainer-owned because some events are intentionally operator-only, node-only, or ignored by a specific client.
