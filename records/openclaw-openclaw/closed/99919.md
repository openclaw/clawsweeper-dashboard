## Summary

Keep open: current main still routes generated-media completion into a requester-agent handoff that carries the media-ready event but not the originating cron task prompt, bootstrap kind, or explicit thinking/fallback context; the stored cron provider/model is only a partial mitigation.

## What This Changes

Issue #99919 reports that async image generation completion in isolated cron sessions resumes without the originating cron task context and can silently abandon the remaining job steps.

## Best Possible Solution

Add a bounded cron-aware generated-media continuation path that re-enters the originating cron run context, preserving resolved prompt/task, provider/model/fallbacks, thinking, bootstrap kind, and delivery semantics.

## Reproduction Assessment

Yes, source-level: current main's generated-media wake enters the requester-agent handoff with only the media completion event, while the normal cron path is the path that carries the original prompt, model/fallbacks, thinking, and bootstrap context.

## Solution Assessment

Yes for the narrow bug: cron-aware continuation or persisted run-context handoff is the maintainable fix; background:false and broader async routing work are mitigations rather than replacements.
