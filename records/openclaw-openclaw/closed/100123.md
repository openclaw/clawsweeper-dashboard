## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P2] Check queued turns before cached chat.send results:** `src/gateway/server-methods/chat.ts:3893`
  - body: This queued-turn check still runs after the `chat:<runId>` dedupe cache. If a queued `chat.send` ACK is lost and the client retries, the cached terminal `ok` branch above returns before this check, so the TUI can clear its pending row while the queued prompt has not run. Move the queued-turn check ahead of the cached terminal result, or avoid caching terminal `ok` until the queued content completes.
  - confidence: 0.93
- **[P2] Preserve queued BTW turns during session stops:** `src/gateway/chat-queued-turns.ts:11-20`
  - body: Queued entries still have no `turnKind`, and the session-scoped queued abort path does not receive `preserveSideRuns`. Active and pre-registered runs skip BTW turns, but queued `/btw` work will still match the session and be aborted by Esc or `/stop`, cancelling an unrelated side question. Carry `turnKind` into queued entries and apply the same preserve-side-runs filter before aborting them.
  - confidence: 0.92
- **[P2] Clear pre-ACK pending submits after session abort:** `src/tui/tui-session-actions.ts:628`
  - body: `abortsPendingRun` only looks at `pendingChatRunId`, but a user can press Esc after `addPendingUser()` and before `sendChat()` returns, when `pendingOptimisticUserMessage` and `pendingSubmitDraft` are set and `pendingChatRunId` is still null. If the session abort cancels that pre-registered queued send, the row may be dropped while the TUI remains in a pending/busy state until an ACK that may never arrive. Treat the current pending draft or returned run ids as an abort target too.
  - confidence: 0.9
