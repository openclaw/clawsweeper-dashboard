## Summary

The PR remains necessary because current main still permits `NaN`, but the current head is not merge-ready: the same blocking correctness finding from the prior review remains unresolved, and the submitted proof describes validation behavior absent from the branch.

## What This Changes

The PR replaces Signal setup’s direct `Number()` port coercion with shared TCP-port parsing, exports the patch builder for tests, and adds helper-level port regression tests.

## Best Possible Solution

Reject every non-empty malformed Signal `httpPort` through `signalSetupAdapter.validateInput` before configuration mutation, while retaining `parseTcpPort` in the patch builder as defensive enforcement and proving both invalid and valid cases through the real setup path.
