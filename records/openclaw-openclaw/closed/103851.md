## Summary

Current main still has the deterministic first-publication failure: immutable preflight evidence can select token bootstrap, but the protected publisher does not consume that evidence and instead forces trusted-publisher authentication. This protected beta blocker remains necessary, and no canonical follow-up PR currently owns the npm fix.

## What This Changes

Make first publication of an absent official npm plugin consume the immutable preflight token-bootstrap route instead of forcing trusted-publisher authentication.

## Best Possible Solution

Trusted-main workflow code should validate and consume the exact immutable preflight artifact and approval tuple, publish only the approved absent-package tarball with registry-scoped token auth, configure and verify its trusted publisher, and retain the existing OIDC path for established packages.

## Reproduction Assessment

Yes. Current-main source gives a high-confidence deterministic reproduction: preflight emits token bootstrap, protected publication forces trusted-publisher mode, and the wrapper clears the token. A live npm mutation was not needed to establish the contradictory control flow.

## Solution Assessment

Yes. Consuming the immutable evidence in trusted-main publication code is the narrowest maintainable solution because it avoids re-inferring authorization from mutable registry state and preserves the release-target credential boundary.
