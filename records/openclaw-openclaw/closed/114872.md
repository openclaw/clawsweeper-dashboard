## Summary

Close as a duplicate of the broader open configuration-validation report. That report already covers both halves of this failure: `config set` accepting an out-of-range value and the resulting inability to use `config set` for recovery; current documentation also defines `openclaw doctor --fix` as the supported repair path for invalid configuration.

## What This Changes

Allow users to recover an invalid `openclaw.json` without being blocked by full-config validation in `openclaw config set`.

## System Context

The configuration CLI and Control UI write the shared `openclaw.json` settings file, while the Gateway validates that file before startup and reload. Invalid values stop the Gateway, so recovery flows must repair the canonical file without weakening normal write-time validation.

## Architecture Diagram

  B --> C[Schema validation]
  C -->|valid| D[Gateway startup and reload]
  C -->|invalid| E[Diagnostic commands]
  E --> F[Doctor repair]
  F --> B

## Best Possible Solution

Keep the canonical report focused on preventing `config set` or the wizard from writing invalid values, while retaining `openclaw doctor --fix` as the explicit recovery path for already-invalid files.
