## Summary

Keep this issue open. Current `main` still has conflicting Anthropic capability sources: the resolver recognizes these models as GA 1M models, while the bundled Anthropic catalog constrains them to 200k, producing premature compaction and truncation in a documented provider workflow.

## What This Changes

Align direct Anthropic Opus 4.6/4.7 and Sonnet 4.6 context metadata, override precedence, and existing-session context refresh with their GA 1M capability.

## Best Possible Solution

Make the Anthropic plugin catalog and resolver share one authoritative capability definition, honor documented explicit model overrides, and re-resolve or invalidate stale persisted context limits when the active model or known window increases, with separate fresh-session and existing-session regression coverage.
