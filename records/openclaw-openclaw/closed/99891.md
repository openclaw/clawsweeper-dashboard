## Summary

Keep open for maintainer review: this maintainer draft is protected from cleanup, and the patch has a concrete security-boundary blocker because CLI-origin embedded fallbacks forward image attachments without checking the fallback provider or a media-trust policy.

## What This Changes

The branch shares a fallback runtime marker across model fallback attempts so embedded retries can receive image attachments when the first attempt used a CLI runtime, with focused CLI attempt tests for that decision.

## Best Possible Solution

Preserve CLI-origin images only for same-provider or explicitly trusted media fallback, with regression tests for both same-provider preservation and cross-provider stripping or consent.

## Reproduction Assessment

Yes at source level: current main passes undefined images on all fallback retries, so a CLI-origin fallback to embedded loses attachments. I did not run a live CLI/provider fallback in this read-only review.

## Solution Assessment

No as submitted: preserving CLI-origin images is the right class of fix, but forwarding them across provider fallback without a trust boundary is not the narrowest safe solution.
