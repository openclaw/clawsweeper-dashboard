## Summary

This PR does not yet fix the lease leak it describes: the lease is acquired inside `resolveTelegramApiContext` before the new thunk guard is reached, so a synchronous failure while finishing API-context construction still skips release. It also has only test output, not after-fix runtime proof.

## What This Changes

The branch changes the Telegram send lease helper to invoke 13 outbound send/action operations through deferred thunks and release the client-options lease if the thunk throws synchronously.

## Best Possible Solution

Make `resolveTelegramApiContext` release its lease if any work after `client.lease?.()` fails, retain a single owner for successful send/action cleanup, and add a focused regression test that forces that exact path.
