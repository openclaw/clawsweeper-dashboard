## Summary

This remains necessary: current main suppresses synthetic Codex usage when the effective harness falls back to the default runtime, and its isolated fallback probe can fail without the live session’s ChatGPT authentication even though the Codex plugin already holds recent rate-limit snapshots.

## What This Changes

Preserve the Codex quota line in chat `/status` for Codex app-server sessions when runtime resolution falls back to OpenClaw Default and the live rate-limit probe cannot authenticate.

## Best Possible Solution

Expose the active Codex client’s recent valid rate-limit snapshot through the plugin-owned usage path, use it when the isolated live read fails, and recognize authoritative `codex` session/provider state even when the displayed runtime is OpenClaw Default.
