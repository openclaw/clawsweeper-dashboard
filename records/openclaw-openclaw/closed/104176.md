## Summary

Current OpenClaw remains intentionally limited to curated Codex plugins, while current Codex provides the filtered workspace catalog contract needed by this request. The feature is still necessary, but its protected label and expansion of the organization-plugin trust boundary require explicit maintainer sponsorship.

## What This Changes

Allow explicitly configured, already-active Codex `workspace-directory` plugins to use the existing native inventory, ownership, readiness, approval, and binding pipeline without OpenClaw installing them.

## Best Possible Solution

After maintainer approval, add a Codex-plugin-local, opt-in workspace marketplace mode that queries only when an enabled explicit policy requires it, exact-matches the marketplace-qualified summary ID, uses the returned remote ID for reads, preserves existing default-deny controls, and excludes install, authentication, migration, bundled, and primary-runtime behavior.
