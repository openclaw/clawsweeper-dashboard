## Summary

Keep this PR open. The updated patch still assigns lexical order to opaque or mixed-format message IDs without evidence that those strings encode a channel-provided ordering, so an equal-timestamp watermark can advance over entries using an arbitrary boundary; it also lacks inspectable after-fix runtime evidence beyond automated checks.

## What This Changes

The PR changes ambient transcript watermark persistence and Telegram history filtering to compare canonical decimal message IDs as `bigint` values and other IDs lexically.

## Best Possible Solution

Define a source-proven monotonic tie-breaker for every supported ambient transcript ID family; when an opaque ID has no ordering contract, preserve a source cursor or treat equal-timestamp opaque IDs as non-orderable rather than lexically sortable.
