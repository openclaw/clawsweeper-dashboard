## Summary

Keep this issue open because current main still permits continuous same-key input to postpone dispatch indefinitely while growing the pending batch. The implementation is narrow once maintainers define whether the existing quiet-period debounce contract should gain a fixed maximum latency; no related issue or PR currently owns that specific change.

Likely related people: @juanpablodlc introduced rapid-message batching (high confidence); Vincent Koc later maintained its same-key ordering behavior (high confidence); @steipete has the most commits on this module (medium confidence).

## What This Changes

Add a bounded maximum wait to shared inbound debounce so continuous same-key input periodically dispatches complete ordered batches.

## Best Possible Solution

Define one shared bounded-latency invariant that tracks the first buffered enqueue and force-flushes the complete ordered batch at a documented fixed ceiling or debounceMs ratio, without adding configuration unless a fixed rule proves inadequate.
