Full review comments:

- **[P2] Reset AI setup when the gateway target changes:** `apps/macos/Sources/OpenClaw/Onboarding.swift:230-233`
  - body: `isAISetupBlocking` trusts one unkeyed `aiSetup.connected` flag, and `startIfNeeded()` will not run detection again after the first success. Because the local/unconfigured/remote selection handlers change the target without clearing that model, a user can verify one gateway, go Back, choose another gateway, and continue to first chat without live-testing the new backend, which breaks the central guarantee of this PR.
  - confidence: 0.9
- **[P2] Roll back manual keys on persistence failures:** `src/crestodian/setup-inference.ts:364-372`
  - body: Manual API keys are staged before the live test, but rollback only happens when the test returns `ok: false`. If the following `updateConfig` or `applySetup` call throws after a successful test, the RPC fails while the newly staged `${provider}:manual` auth profile remains and may overwrite a previously working profile; wrap the whole post-test persistence phase so staged credentials are restored on any failure before success is returned.
  - confidence: 0.88
- **[P2] Mark setup activation as a control-plane write:** `src/gateway/methods/core-descriptors.ts:71`
  - body: `crestodian.setup.activate` can run a long live model check and then mutate auth/config state, but the descriptor is not marked `controlPlaneWrite`. Since the gateway only applies the shared write budget to methods with that flag, an admin client can fire repeated activation attempts instead of being limited like other gateway-wide writes.
  - confidence: 0.9
