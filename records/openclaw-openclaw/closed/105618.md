## Label Justifications

- `P2`: The race deterministically misreports successful skill configuration writes but has limited blast radius within overlapping Control UI skill operations.
- `impact:ux-friction`: The page can appear settled with the opposite of persisted state, prompting users to repeat or unintentionally reverse a successful change.

## Summary

Keep this issue open. Current main still permits the deterministic stale-report race, no canonical issue or fix PR owns it, and the protected `maintainer` label requires explicit human handling rather than automated cleanup or repair intake.

## What This Changes

Prevent overlapping Control UI skill mutations and status refreshes from leaving the page with stale enabled, configured, or installed state.

## Best Possible Solution

Add one page-owned mutation lane or queued final-refresh generation in `ui/src/lib/skills/index.ts` so every accepted skill write is followed by authoritative state that an older response cannot overwrite, and cover the exact two-write ordering with a deterministic regression test.
