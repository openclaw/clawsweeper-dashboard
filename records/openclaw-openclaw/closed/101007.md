## Summary

Keep open. The PR fixes the core resource issue by replacing current `main`'s unbounded stderr chunk array with the existing bounded tail helper, but it should tighten one low-risk diagnostic edge before merge: the child-exit message still slices from the start of the retained tail, so very large stderr can hide the newest error text.

## What This Changes

The PR bounds accumulated stderr for the `tool_search_code` child process and adds a regression test for the bounded tail helper.

## Best Possible Solution

Land the bounded stderr storage after the child-exit diagnostic reports the newest retained stderr snippet and after the adjacent stderr stream-error change is rebased as needed.

Yes from source: current `main` appends every child stderr chunk to an array and joins the full stderr stream on child exit. I did not run a live noisy subprocess because this review is read-only, but the source path is clear.

## Solution Assessment

Mostly yes: reusing the existing session stderr tail helper is the narrowest maintainable fix. The remaining tweak is to take the displayed 500-character child-exit detail from the end of that retained tail, not from its beginning.
