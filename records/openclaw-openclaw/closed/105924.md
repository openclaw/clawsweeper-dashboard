## Summary

Keep this fresh, maintainer-labeled issue open for explicit product and security ownership. Current main appears to expose the plugin tool, approval, CLI, and SQLite seams needed for an external implementation, but bundling a commercial secrets integration is a deliberate exception to the normal ClawHub path and should not be decided automatically.

## What This Changes

Add an optional bundled 1Password code plugin that gives agents slug-scoped, approval-gated secret retrieval with durable auditing, TTL grants, rate-limit caching, and an audit CLI.

## Best Possible Solution

Prototype this as an externally distributed ClawHub code plugin using the existing tool, approval, plugin-owned CLI, and SQLite seams; compare the official 1Password JavaScript SDK with `op`, prove secret non-persistence and approval binding, then bundle or grant official publisher status only if maintainers explicitly accept long-term security ownership.
