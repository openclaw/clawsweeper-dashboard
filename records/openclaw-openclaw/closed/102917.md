## Summary

Keep open; the production Matrix msgtype normalization is well-scoped, but the new test leaves the shared Matrix runtime slot as `undefined` and also imports a private media package from an extension test, so a small test-boundary repair is needed before merge.

## What This Changes

The PR lowercases Matrix outbound media `contentType` before resolving the Matrix media `msgtype` and adds formatting tests for mixed-case image, audio, and video MIME values.

## Best Possible Solution

Land the Matrix msgtype normalization with tests that use the public SDK media facade and reset the shared runtime slot using the store's null/clear semantics.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at the helper boundary: current main passes raw `contentType` into a case-sensitive `mediaKindFromMime`, so mixed-case image/audio/video values resolve to `MsgType.File`. I did not run a live Matrix homeserver send in this read-only review.

## Solution Assessment

Mostly yes: lowercasing at the Matrix msgtype boundary is the narrow production fix and avoids changing the plugin runtime contract. The test harness should still clean the runtime slot correctly and stay on public plugin SDK imports.
