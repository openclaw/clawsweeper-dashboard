## Summary

Close: current main and released OpenClaw already rotate an auto-selected Codex/OpenAI auth profile to another compatible profile after a prompt-level subscription usage-limit error, while user-locked profiles stay single-candidate and exhausted profiles are skipped by cooldown/block state.

## What This Changes

The issue requests automatic fallback from a Codex-backed OpenAI auth profile that hits a subscription usage limit to another compatible OpenAI auth profile, without moving user-locked sessions.

## Best Possible Solution

Keep the shipped runtime fallback path; use https://github.com/openclaw/openclaw/issues/79604 only for the broader policy question of how many same-provider profiles should be exhausted before cross-provider fallback.

## Reproduction Assessment

Yes, at source level. Current main and the shipped release contain a regression test that simulates a prompt-level Codex subscription usage-limit error on an auto-selected profile and verifies a second attempt with a compatible backup profile.

## Solution Assessment

Yes. The existing implementation is the right owner-boundary fix because profile rotation stays in the agent auth/failover runtime and Codex harness path, while user-locked sessions remain a single-candidate path.
