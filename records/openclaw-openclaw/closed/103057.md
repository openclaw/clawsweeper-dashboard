## Summary

Keep open: current main still has the Workboard write-scope sourcePath acceptance path and later admin-dispatch materialization chain, with no merged or open PR found for this exact authorization gap.

## What This Changes

The issue reports that Workboard lets a write-scoped caller persist an arbitrary worktree sourcePath that a later admin dispatch materializes as a managed worktree.

## Best Possible Solution

Patch Workboard so explicit host repo roots for managed worktree cards are accepted only through an operator.admin-authorized mutation, or are constrained to a configured workspace-anchored contract, with regression coverage for a write-only author followed by admin dispatch.

- **Downgrade to hardening:** Treat this as non-security hardening under the trusted-operator model, accepting that Workboard would remain inconsistent with the documented operator.write/operator.admin split.

## Reproduction Assessment

Yes at source level. Current main shows write-scoped Workboard card creation can persist an absolute sourcePath, and later dispatch passes that stored path to ManagedWorktreeService when the dispatcher has admin scope; I did not rerun the live Gateway PoC.

## Solution Assessment

Yes for direction. The maintainable fix is to enforce the existing admin-required explicit-host-path contract before Workboard persists the source path, with tests covering the lower-privilege author and later admin dispatcher split.
