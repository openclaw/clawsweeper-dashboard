## Label Justifications

- `merge-risk: 🚨 compatibility`: The PR changes the meaning of the shell `-c` payload for existing PTY commands.

## Summary

Keep open with a blocking finding: the patch breaks normal PTY shell execution and does not prove the current argv boundary is injectable.

## What This Changes

The PR wraps `ptyCommand` in POSIX single quotes before passing it as the final shell `-c` argument and updates the mocked supervisor test to expect that escaped payload.

## Best Possible Solution

Keep the PTY command as the shell `-c` program, rely on the argv-safe wrapper boundary, and only add hardening if a real exploitable wrapper path is demonstrated with end-to-end PTY proof.
