## Summary

## Best Possible Solution

Full review comments:

- **[P1] Preserve trusted-proxy password bootstrap:** `src/commands/dashboard.ts:56-59`
  - body: The handoff emits `gatewayPassword` only for `password` mode. A same-host Gateway using supported `trusted-proxy` plus password fallback therefore gives a fresh Linux app neither a bootstrap credential nor a device token, so it cannot pair or connect. Include the non-SecretRef trusted-proxy password fallback and cover that configuration.
  - confidence: 0.97
- **[P2] Map Linux client IDs to current-session aliases:** `packages/gateway-protocol/src/client-info.ts:25`
  - body: Adding `openclaw-linux` as a first-party native client id without adding it to the sibling current-session alias set lets a Linux-originated current-session reference fall through as a literal session id. That breaks tools that should target the requester’s active session; add the matching alias and regression coverage.
  - confidence: 0.94
- **[P2] Report bootstrap-auth failures separately from pairing:** `apps/linux/src-tauri/src/gateway_ws.rs:1`
  - body: The new client maps pre-pairing `AUTH_*` failures without shared credentials to the pairing-required state, even though the Gateway rejects the connection before a pairing request exists. Show a bootstrap-auth-unavailable state instead, so SecretRef-managed first-run users are not sent to approve a nonexistent request.
  - confidence: 0.9
