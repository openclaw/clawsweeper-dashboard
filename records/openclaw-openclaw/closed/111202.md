## Label Justifications

- `P1`: A timed-out sandboxed subagent can leave a host Docker CLI process running indefinitely, creating an urgent reliability failure in an active agent workflow.
- `impact:crash-loop`: The report concerns a hung external process that survives run termination and can accumulate into host-level availability pressure.

## Summary

This remains a distinct, actionable sandbox-lifecycle bug: current main creates the embedded run abort controller but resolves sandbox context before exposing that signal to the tool runtime, while the cited Docker deadline PR addresses elapsed-time bounding rather than run-abort propagation. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/agents/pi-embedded-runner/run/attempt.ts?utm_source=openai))

## What This Changes

Thread run cancellation through sandbox-context and backend startup so hung Docker CLI setup work is terminated when an embedded sandboxed run times out, aborts, or is killed.

## Best Possible Solution

Add one optional abort signal to sandbox-context/backend creation, link it to the terminal embedded-run signal before startup begins, propagate it through Docker and SSH startup commands, and add focused abort regression coverage for the shared contract.

- **Limit the repair to Docker:** Pass cancellation only through the Docker startup path, accepting that SSH and future backend factories retain separate lifecycle semantics.
