## Summary

Close as already implemented: merged work predating this report removed per-call watched-file freshness, reused lifecycle-owned plugin metadata snapshots, and threaded discovery through Gateway hot paths; current architecture and release documentation confirm that model.

## What This Changes

Avoid repeated synchronous filesystem freshness checks during plugin metadata discovery by reusing a lifecycle-owned Gateway snapshot.

## Best Possible Solution

Keep the current explicit snapshot/discovery threading and lifecycle replacement model; investigate any remaining slow-disk startup cost with the existing Gateway startup trace rather than removing cold-read manifest freshness globally.
