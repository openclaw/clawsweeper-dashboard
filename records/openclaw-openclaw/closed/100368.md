## Summary

Keep open: current main still warns and suppresses substantive `message_tool_only` finals, but source inspection shows those assistant messages are persisted and replayed as normal context without an undelivered marker, so the reported memory/user-visible desynchronization remains unresolved.

## What This Changes

The issue asks OpenClaw to represent withheld `message_tool_only` finals honestly in later agent context so the agent cannot treat private, undelivered text as something the user saw.

## Best Possible Solution

Make delivery reality part of the core replay contract: a withheld `message_tool_only` final should either be replayed with an explicit undelivered marker or replaced by a concise system notice, coordinated with stranded-final recovery work.
