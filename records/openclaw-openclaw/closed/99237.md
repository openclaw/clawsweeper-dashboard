## Summary

Keep open: current main still has the reported failure path, because doctor auto-approves shell-completion install under `--fix`, the doctor contribution does not catch installer failures, and the installer rethrows profile write errors as fatal. Targeted duplicate searches found adjacent doctor/completion work, but no merged or open canonical fix for the read-only shell profile case.

## What This Changes

The issue reports that `openclaw doctor --fix` exits 1 when optional shell-completion installation cannot write an unwritable shell rc file.

## Best Possible Solution

Keep the explicit `openclaw completion install` command fatal, but make the doctor-owned optional shell-completion repair catch profile write failures and emit a Shell completion note while allowing the rest of `doctor --fix` to exit successfully.

## Reproduction Assessment

Yes from source inspection: with `--fix`, `shouldAutoApproveDoctorFix` makes the completion prompt true, `doctorShellCompletion` calls `installCompletion`, and an EACCES profile write is rethrown without a doctor catch. I did not run a live command repro during this read-only pass.

## Solution Assessment

Yes: the best fix is at the doctor shell-completion boundary, where the install is optional and update already downgrades refresh errors, while preserving fatal behavior for the explicit completion installer.
