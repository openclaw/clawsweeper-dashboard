## Summary

Keep open: current main still treats `agents.list` changes as hot-reloadable, but the session model resolver can keep using persisted runtime model fields before consulting the current agent config, and child sessions can inherit those stale fields after `/new`. The issue is distinct from nearby hot-reload/model reports because the central remaining problem is agent model-primary reload interacting with session runtime model metadata.

## What This Changes

The issue asks for hot-reloaded `agents.<id>.model.primary` changes to affect subsequent turns and fresh threads, or for the gateway to stop logging a misleading successful reload when restart is required.

## Best Possible Solution

Refresh or clear affected unpinned session runtime model metadata when `agents.<id>.model.primary` hot-reloads, and add regression coverage for both next-turn resolution and `/new` child-session inheritance.
