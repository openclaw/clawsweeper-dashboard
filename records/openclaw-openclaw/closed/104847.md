## Summary

Keep open: current main still treats chat abort as AbortSignal cancellation, intentionally lets registered background exec sessions survive that signal, and has no durable ownership contract for an autonomous descendant that daemonizes beyond the managed process group. The report describes a concrete P0 security and data-loss incident, no open PR owns this exact explicit-abort gap, and the adjacent turn-end issue addresses the opposite policy question of preserving desired background work.

## What This Changes

Make explicit user abort reliably stop turn-owned autonomous child agents, or visibly report any registered processes intentionally allowed to survive.

## Best Possible Solution

Define a typed lifecycle boundary for autonomous executors: launch them inside a turn-owned OS/process scope or durable task registration, terminate that scope on explicit user abort, preserve ordinary registered background-job behavior, and include any intentionally surviving tasks in the abort response and process UI.
