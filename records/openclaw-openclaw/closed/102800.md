## Repair Work Prompt

Fix the Slack message tool delete/react casing bug reported in https://github.com/openclaw/openclaw/issues/102800. Current main lowercases Slack normalized route targets for matching/session keys, then the generic message-action mutation path can pass the lower-cased channel id into Slack chat.delete/reactions.*. Keep lower-case normalized keys for comparisons/session routing, but ensure Slack API calls for delete, react, reaction removal, reactions reads, edit, pin/unpin, and similar channelId-based actions receive the provider channel id with original Slack casing when the input was a Slack id such as channel:C0XXXXXXXXX. Prefer a Slack-owned or narrow shared resolver change; do not add config, do not change send behavior, and do not globally stop normalizing lookup keys unless tests prove no session/cross-context regression. Add regression coverage that exercises runMessageAction or Slack message-action dispatch for delete/react with target channel:C0ABCDEF and asserts the invoked Slack action receives C0ABCDEF, plus a guard that normalized matching still treats channel:C0ABCDEF and channel:c0abcdef as equivalent.
