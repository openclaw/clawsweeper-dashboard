## Summary

Keep open: this is a concrete Telegram message-loss report, and current main does not provide enough proof for an implemented-on-main close. Adjacent fixes now preserve unsent finals and Telegram retained-preview gaps, but the shared coalescer still has a buffered-tail hazard: sub-min idle flushes reschedule, `stop()` only clears the timer, and abort-time flush resets buffered text.

## What This Changes

The issue reports that Telegram DM block streaming can silently drop the final buffered tail of long assistant replies when coalescing is still below `minChars` at turn finalization.

## Best Possible Solution

Fix the shared block-reply coalescer or pipeline finish path so any buffered final tail is delivered or explicitly preserved before stop/abort, with Telegram DM proof and without adding a new `flushOnEnqueue` config knob in this issue.
