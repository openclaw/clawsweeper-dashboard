## Summary

Keep open as a feature/design request: current main already auto-downloads inbound Telegram media through `getFile` into the shared media store, but the requested opt-in file-id archive/download action, workspace storage workflow, and memory integration are not implemented.

## What This Changes

Request an opt-in Telegram media download/archive mode with a file-id-based agent action, workspace-scoped storage, and basic-memory integration.

## Best Possible Solution

Define a shared on-demand attachment archive/download contract, then implement Telegram through the plugin/media-store boundary with explicit privacy and storage behavior rather than adding a one-off steady-state config path by default.

## Reproduction Assessment

Not applicable as a bug reproduction. Source inspection confirms current main downloads inbound Telegram media already, but does not expose the requested on-demand file-id archive action or `mediaDownloads` option.

## Solution Assessment

Unclear: the requested Telegram-specific config/action is one possible solution, but a shared attachment metadata/download contract or plugin-owned memory workflow is likely more maintainable and less likely to drift.
