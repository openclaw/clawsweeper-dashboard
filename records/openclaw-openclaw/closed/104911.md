## Summary

The request is broader than existing no-prompt execution support and directly challenges deliberate scope-escalation protections, so it should remain open for a security-boundary product decision.

## What This Changes

Requests an opt-in local-owner deployment mode that treats a dedicated non-admin OS account as the primary trust boundary and reduces repeated internal approvals.

## Best Possible Solution

Keep execution policy separate, then design a proof-bound stable local service identity with a fixed maximum scope baseline, explicit enrollment and revocation, audit/status visibility, and an unattended-readiness Doctor check.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should a configured local service identity retain a pre-approved broad operator scope baseline across repairs and reconnects without interactive scope-upgrade approval, and what proof must bind it to the dedicated OS account?

Rationale: Current main deliberately prevents silent scope widening, while the requested unattended model needs durable authority; acceptable identity proof, maximum scopes, and recovery semantics are security policy choices.

Likely owner: steipete

Owner reason: Recent merged history places pairing, verified auto-approval, and gateway authorization design with this feature owner and merger.

Owner confidence: high

Options:

- **Bounded Verified Identity (recommended):** Add explicit enrollment backed by OS-account or host-key proof, fixed maximum scopes, audit output, revocation, and a readiness diagnostic.
- **Diagnostics Only:** Keep scope upgrades interactive, document the existing no-prompt execution profile, and add preflight checks for token and pairing drift.
- **Broad Owner Mode:** Add one aggregate switch that suppresses local execution and scope approvals inside the account boundary, accepting a substantially larger trust contract.

## Reproduction Assessment

Yes at the current-main contract level: execution prompts can be disabled, but a paired identity requesting broader scopes is intentionally blocked and converted into a pending approval. The reporter’s exact deployment and identity-drift sequence was not run live.

## Solution Assessment

No. A single blanket owner-mode flag crosses an intentional anti-escalation invariant; a bounded verified-identity contract and readiness diagnostics are the safer maintainable direction.
