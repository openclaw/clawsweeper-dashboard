## Label Justifications

- `P1`: Normal heartbeat or interactive turns can intermittently lose a shared session-initialization race and be skipped.
- `impact:message-loss`: The report says heartbeat turns are skipped when the initialization conflict occurs.
- `impact:session-state`: Heartbeat and interactive work contend while initializing the same `agent:main:main` session state.
- `impact:ux-friction`: Users receive a raw intermittent conflict and may pursue unsupported config-write workarounds even though subsequent retries often succeed.

## Summary

The reported heartbeat failure is another trigger for the same transient reply-session initialization race already tracked by the older open canonical issue; the protected config-write concern is separate and already has dedicated reports.

## What This Changes

The issue requests that heartbeat turns stop conflicting with the main session and that users have a supported way to adjust heartbeat behavior despite protected agent-driven config paths.

## Best Possible Solution

Consolidate the Windows heartbeat reproduction into https://github.com/openclaw/openclaw/issues/102400 and fix transient same-session initialization contention in the shared reply-session path, while leaving agent config-write policy to its dedicated security/product discussions.
