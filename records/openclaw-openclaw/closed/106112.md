## Label Justifications

- `P1`: A functioning Slack connection repeatedly becomes silent for six to seven minutes while user messages accumulate behind stale processing state.
- `impact:message-loss`: Inbound Slack messages are suppressed from timely processing and receive no reply or status indication while the lane is wedged.
- `impact:session-state`: The session remains marked as processing with active embedded work after terminal `run:completed` progress.

## Summary

Keep open. The repeated current-release trace supports a real Slack availability bug, and the existing merged recovery work is explicitly limited to Telegram’s durable ingress spool rather than this in-memory session-lane path. The older Slack report may share the underlying stale active-work condition, but there is not yet enough evidence to designate either report as the canonical root cause or identify a current-main fix.

## What This Changes

Fix Slack Socket Mode thread sessions whose lane remains processing after an embedded run completes, causing subsequent messages to stall until forced recovery or gateway restart.

## Best Possible Solution

Make terminal embedded-run completion atomically clear the matching active-work and session-lane ownership before queued channel work drains, then add a regression that completes and delivers a Slack-thread run, enqueues another message, and proves the next run starts without watchdog intervention.
