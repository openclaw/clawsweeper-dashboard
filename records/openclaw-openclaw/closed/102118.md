## What This Changes

The branch adds quickselect-based partial sorting in `src/gateway/server-methods/tasks.ts` so `tasks.list` sorts only the requested page window after filtering.

## Best Possible Solution

Implement a bounded task-registry or gateway listing path that filters and selects the requested `tasks.list` page without calling a helper that pre-sorts every task, while preserving the current response shape and cursor/order semantics.

No, this is only a partial mitigation: it avoids the second full sort but leaves the registry helper's full sort in the polling path. The better fix is to expose or use an unsorted/bounded registry traversal for this listing path, then apply top-K selection before paging.
