## Summary

The patch correctly fixes the normal build profiles, but it does not fix the separate Docker build command even though the PR claims Docker coverage. That command still snapshots `dist-runtime` before the browser plugin copies its Chrome extension, so one focused follow-up is required before merge.

## What This Changes

Reorders generated plugin asset copying before runtime postbuild and raw-copies unpacked Chrome extension directories into the bundled runtime overlay.

## Best Possible Solution

Use the same phase invariant for every production build entry point: build plugin assets before `tsdown`, copy generated assets after `tsdown`, then snapshot and stamp `dist-runtime`; add focused Docker ordering coverage and artifact proof.
