## Summary

Keep open: current main still awaits parent-fork token resolution on the session creation and reply fork paths, and the adjacent open accessor refactor leaves the token decision as a caller-supplied async callback rather than adding a timeout.

## What This Changes

The issue reports that parent-session fork creation can block indefinitely while resolving the parent transcript token count because the async token-count path has no timeout or abort bound.

## Best Possible Solution

Add a small bounded wait around parent-fork token resolution, preserving the fast fresh-token path and oversized-parent skip behavior, without adding a config option or weakening automatic fork sizing.

Yes: a bounded parent-token probe is the narrow fix, because the docs make sizing automatic and the existing fresh-token path can remain unchanged. The adjacent accessor refactor is useful cleanup but does not itself solve the timeout-specific behavior.
