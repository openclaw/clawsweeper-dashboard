## Summary

Keep this PR open: the reported current-main crash is real and the proof is useful, but the patch changes corrupt rows into `null` payloads while the shared queue API and existing consumers still assume `payload: TPayload`. That can move the crash from `JSON.parse` into channel/plugin code rather than safely quarantining malformed rows.

## What This Changes

The PR changes the channel ingress queue parser to return `null` for malformed persisted JSON and adds regression tests for corrupt pending payload and metadata rows.

## Best Possible Solution

Keep the corrupt-row resilience, but handle malformed persisted JSON through an explicit invalid/quarantine path or by skipping invalid rows before they become normal typed payload records.

## Reproduction Assessment

Yes, source-reproducible: current main directly calls JSON.parse on persisted queue JSON in the shared row parser, and the PR body includes a negative-control SyntaxError for malformed payload_json. I did not run tests because this review is read-only, but the failing path is clear from source and the submitted terminal proof.

## Solution Assessment

No. Catching in the shared parser is a plausible layer, but returning null as TPayload is not the best fix because existing list and claim consumers dereference typed payloads; malformed rows should be quarantined, skipped, or represented with an explicit invalid-record contract.
