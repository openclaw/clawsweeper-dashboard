## Summary

Keep open: the PR is focused, but the proposed single in-call refresh flag is too broad and can skip current main's forced Codex app readiness repair after a non-forced initial inventory warmup. The external PR also has no real behavior proof.

## What This Changes

The branch adds an in-call boolean in the Codex plugin thread-config builder to skip later app inventory refreshes after an earlier refresh in the same request.

## Best Possible Solution

Preserve forced post-install, deferred-missing, and not-ready app inventory repairs; de-duplicate only truly equivalent refreshes, then add focused regression coverage and redacted real behavior proof.

## Reproduction Assessment

Yes, source-reproducible: current main intentionally follows a non-forced initial app inventory refresh with a forced not-ready repair when plugin apps remain unavailable. The PR's new flag suppresses that second branch after the first refresh; I did not run a live Codex app-server scenario in this read-only review.

## Solution Assessment

No, this is not the best fix as written because it treats a non-forced cache warm and a forced readiness repair as interchangeable. A safer fix would de-duplicate only equivalent refreshes or track refresh reason/snapshot state while preserving forced repairs.
