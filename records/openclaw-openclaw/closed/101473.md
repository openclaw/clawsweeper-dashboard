## Summary

Keep open: this is a focused bug-fix PR with useful terminal proof, but it is not merge-ready because the new AbortSignal is not reachable from production staging callers and the abort path can settle before the child has closed. The fixed 10 second SCP connect timeout is also a compatibility-sensitive runtime default that needs maintainer acceptance.

## What This Changes

The PR adds an optional AbortSignal parameter and a fixed SSH ConnectTimeout option to the auto-reply scpFile helper, with focused spawn-option regression tests.

## Best Possible Solution

Thread the existing chat/getReply abort signals through stageSandboxMedia to scpFile, make aborted scpFile calls wait for child close before settling, and have a maintainer accept or adjust the ConnectTimeout policy with regression coverage.

Full review comments:

- **[P2] Thread aborts into the staging entry points:** `src/auto-reply/reply/stage-sandbox-media.ts:366`
  - body: The new `signal` parameter is only usable through the private `testing.scpFile` export. Production still calls `stageRemoteFileIntoRoot` and `scpFile` without the active run signal, even though `chat.send` and `getReply` already have abort signals before media staging, so aborting a run while SCP is connecting still leaves the child alive until the new SSH timeout. Please thread the existing signal through `stageSandboxMedia` -> `stageRemoteFileIntoRoot` -> `scpFile` and cover that production path.
  - confidence: 0.9
- **[P2] Wait for scp close after abort:** `src/auto-reply/reply/stage-sandbox-media.ts:390`
  - body: Passing `signal` to `spawn` makes Node emit an `AbortError` before the child has necessarily emitted `close` or `exit` (a Node 24 probe showed `AbortError` before `SIGTERM` exit). Because `scpFile` settles on `child.once("error", finish)`, an aborted transfer can return to `stageRemoteFileIntoRoot` and remove the temp directory while the SCP child is still shutting down, violating the close-authoritative invariant below. Record the abort error, but reject only from the `close` handler after the child is gone.
  - confidence: 0.86
