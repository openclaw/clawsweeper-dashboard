## Label Justifications

- `P1`: A deterministic WhatsApp group-channel workflow silently drops messages explicitly addressing the agent through a supported configured pattern.
- `impact:message-loss`: Matching group messages are suppressed before agent dispatch whenever they also natively mention another participant.
- `impact:ux-friction`: The rejection occurs before the normal inbound log, leaving operators with little evidence for diagnosing the ignored message.

## Summary

Keep open: current main still suppresses configured WhatsApp text mention patterns whenever native mentions target only other participants, contradicting the documented pattern-based mention mode and deterministically dropping addressed messages.

## What This Changes

Allow configured WhatsApp text mention patterns to satisfy group mention gating even when the message also natively mentions other participants.

## Best Possible Solution

Evaluate operator-configured mention regexes after native mentions fail to match the bot, keep the numeric self fallback suppressed in that branch, and emit a bounded diagnostic when all mention checks reject the message.
