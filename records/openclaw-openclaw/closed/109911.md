## Label Justifications

- `P1`: The report describes acknowledged inbound messages becoming permanently unavailable and invisible to operators across shared-ingress consumers.
- `impact:message-loss`: Failed inbound events can be acknowledged upstream, then dead-lettered without a replayable payload or an operator-facing warning.

## Summary

This appears to be a distinct, current shared-ingress reliability gap rather than a duplicate of the LINE retry-bound or upgrade reports. The reported loss and invisibility are serious, but the remedy combines data-retention, replay semantics, and a new operator surface, so it needs maintainer direction before a safe implementation can be scoped.

Likely related people: `steipete` is the recent contributor on the merged LINE ingress-drain adoption; confidence is low because the local history pass could not be completed in this read-only environment.

## What This Changes

Add recoverable and operator-visible handling for shared inbound ingress events that reach a failed/dead-letter state, including their payload and same-ID resubmission behavior.

## Best Possible Solution

Choose and document one shared ingress dead-letter policy: retain diagnostically useful payload data under a bounded privacy-aware retention rule, expose failed-row counts through an operator-facing health or doctor surface, and define a guarded replay/supersede path that cannot duplicate adopted work.
