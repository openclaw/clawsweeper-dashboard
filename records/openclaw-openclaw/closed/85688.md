## Summary

Keep open: current main and v2026.6.11 only partially expose attribution through Gateway `sessions.usage`; the requested stable status/usage JSON contract for session kind, cron job identity, channel target kind, runtime, and privacy handling is still missing and needs maintainer API/product direction.

## What This Changes

The issue requests stable agent, session-kind, cron, channel, model, and runtime attribution fields in official usage/status JSON surfaces for external dashboards.

## Best Possible Solution

Define the stable attribution contract on the narrowest official usage surface, likely `sessions.usage`, with optional low-cardinality fields, docs/tests, and a clear privacy rule for channel target identifiers; keep #51184 focused on CLI/TUI display labels.
