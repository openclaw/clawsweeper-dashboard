## Summary

Keep open: current main and v2026.6.11 still store the same pricing fingerprint on every usage-cost cache file entry, and the report gives concrete large-cache measurements that match the source shape.

## What This Changes

Request to reduce `.usage-cost-cache.json` bloat by moving the identical `pricingFingerprint` out of each per-file cache entry or replacing it with a compact per-entry hash.

## Best Possible Solution

Compact the generated usage-cost cache schema with a versioned rebuild while preserving pricing invalidation and append-only reuse, then leave broader size caps or SQLite/off-process storage to the broader memory-pressure tracker.

## Reproduction Assessment

Yes, at source level: current main writes `pricingFingerprint` into every cache entry and the issue reports one distinct value across 31,433 entries. I did not run a large-cache replay in this read-only review.

## Solution Assessment

Yes for the narrow bloat: storing the fingerprint once at cache level, or storing only a compact per-entry hash, is the smallest maintainable fix as long as versioned rebuild and freshness checks remain covered.
