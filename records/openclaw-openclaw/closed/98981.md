## Summary

Current main already prevents the reported cron/session state from persisting: cron runs get a plain UUID transcript path, and a cron entry whose transcript never materialized is stored without resumable sessionId/sessionFile fields. The fix is current-main-only; no release tag contains the proof commit yet.

## What This Changes

The issue asks OpenClaw to stop an idle cron/session rotator from polling forever when a topic-scoped session lacks sessionFile and filename fallback looks for a non-existent topic-suffixed transcript.

## Best Possible Solution

Keep the current main behavior: cron sessions should only persist resumable session metadata after a transcript exists, and missing-transcript legacy state should not be treated as a live session to rotate.

## Reproduction Assessment

No current-main failing reproduction remains. Source and test evidence show current main prevents the sessionId-without-sessionFile resumable cron state that made the reported polling loop possible.

## Solution Assessment

Yes. Fixing cron session persistence at the OpenClaw session-state boundary is narrower than adding a workspace-specific idle-rotator orphan marker, and it keeps topic filename logic out of cron’s missing-sessionFile path.
