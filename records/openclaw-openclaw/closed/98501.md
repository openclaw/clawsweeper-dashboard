## Summary

Keep open: the rename itself is coherent, but the PR broadens Codex approval reviewer routing from app scope to thread/turn scope even though pinned Codex 0.142.4 supports app-level reviewers. That creates a concrete approval-boundary regression before merge.

## What This Changes

The PR renames the Codex plugin destructive approval policy string from `"always"` to `"ask"` across schema, docs, runtime policy, persisted bindings, migration contracts, and focused tests.

## Best Possible Solution

Keep the rename to `"ask"`, but preserve app-scoped reviewer routing by setting `apps.<id>.approvals_reviewer = "user"` only for affected plugin apps and not adding thread/turn-level reviewer overrides for the whole session.

## Reproduction Assessment

Yes, by source inspection: the PR moves the reviewer from app config to thread/turn-level params, while pinned Codex 0.142.4 supports and resolves app-level reviewers before the global reviewer. I did not run tests in this read-only review.

## Solution Assessment

No, the rename is useful but the reviewer routing is broader than necessary. The safer fix is to keep `"ask"` app-scoped using Codex's supported `apps.<id>.approvals_reviewer` contract.
