## Summary

Keep open: current `main` and the latest release still leave `sessions.patch` without the plugin-runtime ownership check that `sessions.delete` enforces, so this remains a concrete gateway security/session-state bug.

## What This Changes

The issue asks for `sessions.patch` to reject plugin-runtime mutations against sessions owned by a different plugin, matching the existing `sessions.delete` ownership fence.

## Best Possible Solution

Add the existing plugin-runtime ownership fence to `sessions.patch`, recheck it inside the lifecycle mutation window for existing entries, and cover foreign archive/unarchive/metadata denial plus owned-session success.
