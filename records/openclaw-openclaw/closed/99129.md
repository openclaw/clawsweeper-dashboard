## What This Changes

The branch changes `parseFrontmatterBlock` to use `Object.hasOwn` when merging line-parsed frontmatter entries and adds a regression test for prototype-named YAML null keys.

## Best Possible Solution

Land the narrow `Object.hasOwn` guard and regression test after the normal current-head required checks; broader null-prototype frontmatter hardening can be tracked separately if maintainers want it.

## Reproduction Assessment

Yes. Source inspection shows current main drops YAML null values, line-parses the same keys, and then suppresses Object.prototype-named fallback keys via `key in merged`; the PR body also includes before/after terminal output for that exact parser path.

## Solution Assessment

Yes. `Object.hasOwn` is the narrowest maintainable fix for this merge fallback because the decision is whether `merged` owns the key; changing the parser map shape would be broader hardening outside the reported path.
