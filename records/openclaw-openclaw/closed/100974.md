## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: an actively retrying repair request preserves its original `ts`, TTL pruning deletes it after five minutes, the next retry mints a new requestId, and macOS queues stale request objects. I did not run the several-hour macOS scenario in this read-only review.

## Solution Assessment

Yes, the best fix boundary is to address both gateway request lifetime/resolution broadcasts and macOS queue coalescing because either side alone can leave stale alerts or stale approvals. The linked PR is the direct implementation candidate, so the issue should remain open until that PR is reviewed and merged or replaced.
