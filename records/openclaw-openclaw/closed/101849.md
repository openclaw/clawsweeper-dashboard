## Summary

Keep open: the PR targets a real Control UI stored-auth flicker, but the new gate still misses tokenized URLs that require gateway URL confirmation because it snapshots auth before the pending credentials are applied.

## What This Changes

The branch adds a stored-auth initial-connect splash in Control UI, a synchronous device-token presence probe, E2E coverage, CSS, and docs for avoiding login-gate flashes.

## Best Possible Solution

Keep the stored-auth splash approach, but make the predicate use the credentials actually being connected with, including pending gateway URL confirmation, and cover that path in E2E.

Yes. Source inspection shows a tokenized URL with a changed gatewayUrl is kept in pendingGatewayConnection, then confirmation starts a credentialed connect while the PR's initialAuthPresent flag remains false.

## Solution Assessment

No. The PR is a targeted fix for the right surface, but it is not the best complete solution until auth gating is derived from the current or pending connection rather than a page-load snapshot.
