## What This Changes

Requests a configuration option to suppress user-visible notifications for expected non-zero foreground exec exits.

## Best Possible Solution

Keep the existing `messages.suppressToolErrors` configuration as the canonical suppression surface; users can retain `tools.exec.notifyOnExit` for background completion notifications without adding another overlapping config option.

## Maintainer Decision

## Reproduction Assessment

Yes, at source level: foreground exec failures produce the concise warning by default, while `messages.suppressToolErrors` disables the warning and progress-dispatch paths.

## Solution Assessment

Yes. Reusing the existing messages-level suppression setting solves the observable problem without expanding OpenClaw's already-large configuration surface; an exec-only setting would be overlapping granularity rather than a missing capability.
