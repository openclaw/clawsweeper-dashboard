## Summary

Current main validates and conflict-checks configuration writes, protects conversational writes with owner/admin policy, redacts secrets, supports model/auth failover, and provides operator repair through doctor, but it does not live-test a candidate provider before persisting it or retain a rollback capability usable after the active model path fails. This remains a legitimate security-sensitive feature discussion, not an already-implemented bug fix or safe autonomous repair.

## What This Changes

Add a secure, transactional workflow for agents to validate, activate, and roll back LLM provider/model and credential-reference changes without exposing secrets or losing recovery access.

## Best Possible Solution

If maintainers sponsor the capability, add one explicit operator-approved provider-change transaction to the canonical gateway config owner: accept only provider/model and SecretRef references, probe the candidate out-of-band, atomically activate it, audit the actor and changed paths, retain one doctor-recoverable rollback point, and never expose resolved credentials or create a parallel runtime config path.
