## Summary

Current main addresses the central failure: lean local-model sessions no longer hide policy-permitted shell execution behind structured Tool Search, so a model can select `exec` instead of concluding that no live-data capability exists. The remaining question of whether a particular local model generates a correct curl command is model behavior, not a missing OpenClaw execution route.

## What This Changes

The issue requests a usable, discoverable shell-execution path for local embedded Ollama/Qwen sessions handling live-data requests when compact Tool Search is active.

## System Context

Local-model lean mode reduces the prompt-visible tool catalog by routing most tools through Tool Search. The embedded-agent and shared harness paths construct that compact surface before the model selects and invokes OpenClaw tools, including policy-controlled shell execution.

## Architecture Diagram

flowchart LR
  A[Local Ollama or Qwen request] --> B[Embedded agent run]
  B --> C[Lean tool-surface selection]
  C --> D[Tool Search controls]
  C --> E[Direct policy-permitted exec]
  D --> F[Cataloged tools]
  E --> G[Shell command execution]
  F --> H[OpenClaw tool runtime]
  G --> H

## Best Possible Solution

Keep the current narrow behavior: expose `exec` only when normal policy permits it, retain Tool Search compaction for other tools, and treat model-specific command quality as separate from tool-surface routing.
