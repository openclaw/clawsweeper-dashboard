## Summary

This PR should remain open: the macOS short-swap change is well-scoped, but the Gateway audit still has two definite correctness gaps that violate its stated required invariant. A bounded log tail can silently omit an early restart error, and a failed first health probe can leave that restart permanently unaudited; the protected `maintainer` label also requires explicit maintainer handling.

## What This Changes

The PR audits Gateway logs after managed restarts and keeps the current managed macOS app running until its signed replacement is ready for a short final process swap.

## Best Possible Solution

Persist a pending restart audit boundary before every managed Gateway restart, retry it across later heartbeats, use the existing cursor/truncation/reset metadata to prove complete coverage, and clear the pending state only after health and log verification both pass; retain the macOS short-swap improvement.

Yes at source level. More than 1000 post-restart log lines with an early error exercise the ignored truncation path, while throwing during the first post-restart status or health probe and rerunning with a current build demonstrates the lost audit boundary.

## Solution Assessment

No. Auditing a bounded tail only after health proof does not satisfy the required restart-window invariant; durable pending state plus complete-coverage checks is the narrowest reliable design.
