- **[P2] Use offset mapping instead of substring recovery:** `src/agents/sessions/tools/edit-diff.ts:140-141`
  - body: `recoverOriginalSpan` only succeeds when an original substring normalizes exactly to the fuzzy target. If `oldText` matches part of an NFKC-expanded character, such as `ff` against original `ﬃ`, normalized content contains a match but no original substring normalizes to that exact prefix, so this returns no span and rejects a fuzzy edit that the matcher located. The canonical branch handles this by mapping normalized offsets back to original segment boundaries and adds regressions for these cases.
