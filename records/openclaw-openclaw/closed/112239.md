## Label Justifications

## Summary

Keep this PR open for human review. It is a valuable core-boundary cleanup and fixes packaged external-plugin flag discovery, but the proposed move creates a concrete upgrade break for packaged Nextcloud Talk users with an already-installed older plugin: legacy alias handling disappears from core before that plugin release provides the replacement hook.

## What This Changes

The branch moves channel-specific `channels add` flags and input coercion into plugin manifest/setup metadata, registers options from bundled, catalog, and installed plugin data, and relocates Nextcloud Talk legacy aliases into its setup adapter.

## Best Possible Solution

Keep plugin ownership, but make the host/plugin upgrade path safe: publish and require the compatible Nextcloud Talk plugin in the same release train, or preserve the aliases through a version-aware compatibility boundary until the installed plugin contract is guaranteed; then show redacted terminal proof for both a fresh packaged external-plugin install and an upgrade starting with the older Nextcloud Talk plugin.
