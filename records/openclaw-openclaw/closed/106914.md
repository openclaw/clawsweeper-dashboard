## Label Justifications

- `P2`: This is a deterministic CLI regression in the latest release with a limited model-list blast radius and a provider-filter workaround; gateway execution remains healthy.
- `impact:auth-provider`: The failure occurs in Anthropic provider model normalization and is triggered by configured provider and model references.
- `impact:ux-friction`: Affected users cannot use the normal unfiltered model-list command and must know to apply a provider filter or move to a build containing the fix.

## Summary

Current `main` contains the exact missing-cost-safe Sonnet 5 normalization fix from merged https://github.com/openclaw/openclaw/pull/102186, with provider and CLI regression coverage. v2026.7.1 was cut from a different release commit and does not contain it, so the bug is fixed on `main` but remains observable in that release.

## What This Changes

Prevent unfiltered `openclaw models list` from crashing when a configured Anthropic Sonnet 5 row reaches provider normalization without cost metadata.

## Best Possible Solution

Keep the provider-owned missing-cost-safe comparator and sibling regression coverage on `main`, then ensure the next stable 2026.7.x artifact contains `740e7687e84068548152cf52c7ac9c1d788f8a57` and package-smoke `openclaw models list` against a configured costless Sonnet 5 reference.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Multiple users reproduced the same v2026.7.1 stack trace on macOS and WSL2 with unfiltered `openclaw models list`, while source inspection shows the configured-row path can omit `cost` before provider normalization.

## Solution Assessment

Yes. The merged fix handles partial configured and display projections at the provider normalization boundary and covers the Anthropic, Anthropic Vertex, and Bedrock Mantle siblings instead of inventing cost fields in CLI rows or hiding normalization errors.
