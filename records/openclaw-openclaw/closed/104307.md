## Summary

The Kova regression is real and exact-head workflow proof shows the branch fixes it, but the patch adds a second, externally settable command signal even though npm already exposes whether prepack is running under `pack` or `publish`. That duplicate control can bypass the stable-release changelog guard outside the intended wrapper, so the PR needs a narrow correction before merge.

## What This Changes

The PR makes the OCM npm wrapper set an internal environment opt-in for root `npm pack`, forwards that opt-in to changelog preparation during prepack, and adds resolver tests.

## Best Possible Solution

Have prepack derive `allowUnreleased` from npm's native top-level command (`npm_command === "pack"`), preserve strict behavior for `publish` and absent or unknown command contexts, and cover both direct pack and publish cases with focused tests.
