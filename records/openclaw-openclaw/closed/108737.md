## Summary

Keep this PR open: the client-owned, reversible layout-command design is promising, but two previously reported delivery defects remain visible at the current head, live Control UI proof is absent, and the intended multi-client targeting behavior needs explicit confirmation.

## What This Changes

The branch adds a typed `ui.command` gateway method/event, an owner-only capability-gated `screen` agent tool, and Control UI handlers for chat splits, focus, navigation, sidebar visibility, and terminal/browser panels.

## Best Possible Solution

Keep layout state ephemeral and client-owned, but advertise the capability only where an active handler exists, route panel commands through the existing lazy-load delivery path, define a trusted initiating/session-relevant client-targeting contract, and prove the complete flow in a real Control UI before merge.
