## Label Justifications

- `P1`: The report describes a common group-chat pattern that can repeatedly break CLI session reuse for active users.
- `impact:session-state`: The failure mode invalidates CLI session bindings and loses resumed-session continuity.

## Summary

Keep open: current `main` still lets per-message explicit mention state change the CLI session-reuse static prompt hash, and the issue has the protected `maintainer` label so it needs explicit maintainer handling rather than cleanup closure or unattended repair.

## What This Changes

The issue reports CLI session reuse invalidation when group messages toggle explicit bot mention state because per-turn mention context enters the session-stable system prompt hash.

## Best Possible Solution

Move explicit mention notice out of session-stable group context into per-turn inbound context, keep `extraSystemPromptStatic` stable across mention toggles, and resolve the groupIntro hash drift through the existing canonical tracker or the same bounded fix if maintainers want one patch.

## Reproduction Assessment

Yes from source inspection: a current group turn with `ExplicitlyMentionedBot: true` builds a different `groupChatContext` than one without it, and that context is part of `extraSystemPromptStatic` used for the CLI binding hash. I did not run a live Telegram/CLI repro in this read-only sweep.

## Solution Assessment

Yes, the proposed direction is the right owner-boundary fix: keep per-message mention facts in per-turn inbound context and make the static CLI binding facts session-stable. The groupIntro subproblem should either be fixed at the same prompt-identity boundary or handled through the existing canonical groupIntro tracker.
