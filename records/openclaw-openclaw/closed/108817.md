## Summary

This focused fix remains useful, but the prior ordering blocker is still present: creation time does not reliably identify the newest visible Discord widget when parallel sends finish out of order. The PR also lacks after-fix real Discord proof, so it is not ready to merge.

## What This Changes

The PR changes missing-custom-ID Discord Activity launches from unique-widget-only fallback to selecting the channel widget with the greatest creation timestamp, with corresponding HTTP tests and troubleshooting documentation.

## Best Possible Solution

Track or serialize successful Discord widget delivery order, use that authoritative ordering only for missing-ID fallback, retain exact-ID lookup, add an overlapping-send regression test, and demonstrate the result in a redacted real Discord launch.
