## Summary

Close: current main and release v2026.6.11 already cover the central rejected-`thinking` problem for Azure/Microsoft Foundry-style DeepSeek V4 routing through the existing non-DeepSeek `thinkingFormat` path, while this PR adds a duplicate config value from a conflicting stale branch.

## What This Changes

The PR adds `thinkingFormat: "none"` as a model compat value and tries to skip OpenAI-compatible thinking/reasoning parameter injection for proxy-hosted reasoning models.

## Best Possible Solution

Keep the shipped compatibility path and use existing model compat flags such as `thinkingFormat: "openai"` and, when needed, `supportsReasoningEffort: false` instead of adding a duplicate `thinkingFormat: "none"` enum.

## Reproduction Assessment

Yes from source for the original rejected-field class: DeepSeek-native routing can emit top-level `thinking`, and current main has tests proving the Foundry/non-native paths suppress it. I did not live-test Azure AI Foundry credentials for this PR.

## Solution Assessment

No: adding `thinkingFormat: "none"` is not the best solution now that current main already has an explicit non-native compat route and a separate `supportsReasoningEffort` flag for proxies that reject reasoning-effort fields.
