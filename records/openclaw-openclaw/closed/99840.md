## What This Changes

The PR changes Android NodeRuntime so app backgrounding stops any active voice capture through the existing Off stop path instead of only stopping ManualMic.

## Best Possible Solution

## Solution Assessment

Yes, source-wise: stopping through setVoiceCaptureMode(Off) at the NodeRuntime foreground boundary reuses the existing TalkMode and foreground-service cleanup path while preserving setVoiceScreenActive's ManualMic-only behavior. Merge still needs real Android proof.
