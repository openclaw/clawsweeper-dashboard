## Summary

Keep this PR open for a narrow repair: the writable-descriptor approach addresses the reported Windows EPERM, but the new single `fs.writeSync` call can publish an incomplete archive before transcript rows are deleted.

## What This Changes

The PR replaces write-then-read-only-fsync with one exclusive writable descriptor for SQLite transcript archive writing and adds Windows-focused regression coverage.

## Best Possible Solution

Preserve the single writable descriptor for the Windows fsync fix, but use a write-all operation or an explicit short-write loop before fsync, rename, and archive-backed row deletion.
