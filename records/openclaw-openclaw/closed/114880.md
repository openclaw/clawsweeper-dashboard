## Label Justifications

- `P1`: A guarded Telegram DM lane can make later user messages appear unresponsive until recovery, but the reported root cause is already fixed in the current release.
- `impact:message-loss`: The report describes later same-lane Telegram updates being held behind a guarded handler and therefore not processed promptly.
- `impact:session-state`: The failure is a mismatch between spool-lane ownership and the active agent-turn lifecycle.

## Summary

The reported guarded-DM failure is already addressed by the released Telegram durable-turn-adoption work: a spooled update now completes when the agent run is durably adopted rather than waiting for a non-settling tool subprocess, and the Telegram reply fence no longer owns cancellation after adoption.

## What This Changes

Fix Telegram direct-message lane recovery so a reply abort cannot leave a spooled lane guarded when an active agent tool subprocess does not settle.

## System Context

Telegram polling writes inbound updates to an isolated spool and serializes each chat/topic lane while it hands the update to the channel turn system. The turn system then owns agent execution, cancellation, queueing, and delivery; the spool lane must not remain coupled to the full agent-tool lifetime.

## Architecture Diagram

flowchart LR
  A[Telegram DM update] --> B[Isolated ingress spool]
  B --> C[Per-lane claim and dispatch]
  C --> D[Durable agent turn adoption]
  D --> E[Session turn lifecycle]
  E --> F[Tool subprocess and reply]
  D --> G[Spool completion and lane release]

## Best Possible Solution

Keep the shipped durable-adoption ownership model; if the same diagnostic appears on v2026.7.1 or later, reopen with the exact build SHA and a redacted trace showing whether the turn crossed adoption before the lane remained guarded.
