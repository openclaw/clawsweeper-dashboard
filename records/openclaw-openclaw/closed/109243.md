## Label Justifications

- `P2`: An indefinitely blocked doctor run is a real availability bug, but it requires the narrow condition that the locally executed `ps` process ignores its timeout signal.

## Summary

Keep this PR open for merge. Current main still lets `spawnSync` use its default `SIGTERM`, and Node documents that a synchronous child call can remain blocked when the child handles that signal without exiting; the focused `SIGKILL` change matches the dependency contract and has convincing before/after runtime proof. ([nodejs.org](https://nodejs.org/api/child_process.html))

## What This Changes

This PR makes the WhatsApp doctor process probe force-stop `ps` with `SIGKILL` at its existing one-second timeout and adds a regression assertion for the spawn options.

## Best Possible Solution

Land the bounded `SIGKILL` timeout change with its focused regression test after the remaining exact-head checks complete.
