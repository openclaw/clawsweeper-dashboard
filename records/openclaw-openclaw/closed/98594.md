## Summary

Keep open: current `main` and `v2026.6.11` still generate the macOS app launch-at-login plist with only `PATH`, and an open fix candidate with closing syntax now owns the implementation path.

## What This Changes

The issue requests preserving `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` in the macOS app launch-at-login plist so login-launched app instances keep the profile active when autostart was enabled.

## Best Possible Solution

Review and land one narrow macOS LaunchAgent fix with focused plist tests and macOS proof, then close this issue after the merged commit reaches `main`.

## Reproduction Assessment

Yes, source-level reproduction is high-confidence: the current plist generator emits only `PATH`, while the macOS app profile resolver depends on `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR`. I did not run a live macOS login-cycle reproduction in this read-only review.

## Solution Assessment

Yes, preserving the existing profile env override keys in the app LaunchAgent is the narrowest maintainable fix. Reusing the separate gateway service LaunchAgent machinery would be broader than needed for `ai.openclaw.mac.plist`.
