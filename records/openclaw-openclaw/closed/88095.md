## Summary

Keep open: current main and the latest release still lack an enrolled-speaker gate for Voice Wake, push-to-talk, or Talk mode. This is a real feature request, but it needs product and security design before implementation because it touches speaker enrollment, sensitive voiceprint storage, fallback policy, native app UX, and plugin/provider ownership.

## What This Changes

Request speaker enrollment and speaker-identification filtering for Voice Wake, push-to-talk, and Talk mode so non-primary voices do not trigger or contaminate voice sessions.

## Best Possible Solution

Define a privacy-preserving speaker-gate design for live Voice Wake/PTT/Talk, including canonical storage, doctor migration behavior if config is added, provider/plugin API boundaries, default-off fallback policy, and native app enrollment UX before implementation.
