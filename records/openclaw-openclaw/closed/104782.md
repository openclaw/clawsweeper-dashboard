## Summary

Current main still has the reported cross-client gap: the initiating Control UI keeps the human-readable follow-up locally, while the validated send request and `chat.side_result` carry only the synthetic context question, so another client cannot recover the intended display text. No canonical fix PR owns the remaining work, and the protected `maintainer` label requires explicit maintainer handling.

Likely related people:
- `steipete` — high confidence; introduced the side-chat follow-up behavior and documented this deferred gap.
- `xingzhou` — medium confidence; recent contributor to the current gateway/UI event-path structure.

## What This Changes

Add an optional human-readable side-chat question to the send/event path so non-initiating clients display and reuse the user’s typed follow-up instead of the synthetic context prompt.

## Best Possible Solution

Thread one optional display-question value through `ChatSendParamsSchema`, gateway and embedded side-result producers, and client parsing; retain the existing `question` field for compatibility and add a two-client regression test.
