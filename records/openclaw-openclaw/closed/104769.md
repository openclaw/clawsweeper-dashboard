## Label Justifications

- `P1`: A normal automatic compaction path can switch a canonical SQLite-backed session into a stray legacy file transcript when truncation is enabled.
- `impact:session-state`: The defect can mis-associate the active transcript locator, session identity, and post-compaction lineage.

## Summary

Keep open: current `main` still contains the reported mismatch, and the protected `maintainer` label requires explicit maintainer handling.

**Likely related people**
- `@steipete` — high confidence; introduced the current helper and both compaction call paths.
- `@jalehman` — medium confidence; carried the SQLite session/transcript storage flip that established this boundary.

## What This Changes

Prevent automatic post-compaction transcript rotation from treating a SQLite session marker as a filesystem path.

## Best Possible Solution

Make `rotateTranscriptAfterCompaction` return without side effects for SQLite markers before inspecting entries or resolving paths, then add focused helper and automatic-attempt coverage proving the SQLite locator and session ID remain unchanged and no JSONL artifact is written.

Yes—source inspection gives a high-confidence path: complete automatic compaction for a SQLite-backed session with `truncateAfterCompaction` enabled, and the attempt path invokes the file-only rotation helper with the SQLite marker.

## Solution Assessment

Yes—the proposed helper-level gate is the narrowest durable fix because it enforces the file-versus-SQLite boundary for every caller; retaining caller-side guards can still avoid unnecessary work.
