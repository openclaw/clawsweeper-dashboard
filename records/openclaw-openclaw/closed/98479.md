## Summary

Keep this PR open, but do not merge the current head: the earlier diagnostics concern is fixed and the live proof is credible, yet the new readiness logic breaks the documented tailnet loopback-only fallback when Tailscale becomes available after Gateway startup.

## What This Changes

## Best Possible Solution

Determine readiness from the running Gateway's inspected listener topology: use loopback for a loopback-only fallback, probe the configured interface when that listener is present, and retain same-PID ownership verification before delivering an authenticated loopback URL.
