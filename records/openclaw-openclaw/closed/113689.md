## Summary

Keep this PR open for maintainer review. The browser adapter currently forwards the shared protocol’s 1008 close code directly, while the browser WebSocket contract rejects client-initiated 1008 closes; the proposed one-code translation is narrow and no patch defect is evident. It still needs redacted, after-fix native-browser evidence showing the Control UI reaches its close-and-reconnect path.

## What This Changes

Maps the browser Control UI’s outgoing Gateway policy-violation close from 1008 to browser-safe application code 4008 and adds focused socket-adapter regressions.

## System Context

The Control UI opens a browser WebSocket through a small adapter, which passes Gateway protocol events into the browser client and then its reconnect handling. The adapter must translate only browser-incompatible outgoing close requests without changing close events received from the Gateway.
