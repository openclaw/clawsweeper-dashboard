## Summary

Keep open: the patch is well-proven and no correctness defect is evident, but the new 16 MiB success-response ceiling could make existing Reef relay operations fail, and the available Reef protocol/docs do not establish that ceiling as a supported contract. A Reef owner should confirm the limit before merge.

## What This Changes

Routes Reef relay success and error JSON bodies through the shared bounded provider HTTP reader and adds overflow-cancellation, malformed-body, and fallback regression coverage.

## Best Possible Solution

Establish one owner-approved Reef relay response ceiling—preferably backed by relay pagination or a matching server-side limit—and then retain the shared streaming reader and focused cancellation coverage.
