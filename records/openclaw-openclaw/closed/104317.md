## Summary

The memory cap is useful, but the patch does not bound the full hostile-response lifetime: `fetchVault` clears its five-second abort timer when headers arrive, while the new reader can then wait indefinitely for a slow or stalled body. This availability gap should be fixed before merge.

## What This Changes

The PR bounds successful Vault authentication and KV JSON response reads to 1 MiB and adds an oversized-response regression test.

## Best Possible Solution

Use one request-lifetime abort deadline that remains active through bounded JSON consumption, and cover both oversized and headers-first stalled streams with spawned-resolver tests.
