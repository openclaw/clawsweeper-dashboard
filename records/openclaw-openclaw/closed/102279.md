## Summary

Keep open: current main still turns timed-out Telegram isolated-ingress spooled updates into terminal failed tombstones while suppressing the normal user-facing failure fallback, and no merged or viable related item owns the failed-tombstone visibility/notice policy yet.

## What This Changes

The issue requests a fix for Telegram isolated-ingress handler-timeout dead letters that silently consume a user message without replay, user notice, or durable operator surfacing.

## Best Possible Solution

Keep single-processing safety for terminal failed tombstones, but make dead-lettered Telegram ingress entries actionable through retained failed-row status/doctor surfacing and a maintainer-approved duplicate-safe user notice or guarded replay policy.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For Telegram isolated-ingress failed tombstones, should OpenClaw preserve terminal dead-letter semantics and add visibility, or should handler-timeout rows be replayed automatically?

Rationale: The current terminal tombstone behavior avoids duplicate side effects, but the user-visible and operator-visible recovery contract is a product reliability choice that affects retry policy, status/doctor surfaces, and Telegram user messaging.

Likely owner: joshavant

Owner reason: Josh authored the major timeout and spooled replay lifecycle fixes that best frame the single-processing versus replay tradeoff.

Owner confidence: high

Options:

- **Surface And Notify Failed Tombstones (recommended):** Preserve terminal failed rows for unsafe timeout and retry-limit cases, add failed-ingress counts/details to operator surfaces, and send one duplicate-safe failure notice when a user message is dead-lettered.
- **Replay Handler-Timeout Tombstones Once:** Allow a guarded one-time replay for handler-timeout rows with zero attempts, but require proof that late original handlers cannot duplicate replies or session effects.
- **Operator Visibility Only:** Expose failed tombstones in status or doctor without user notices, accepting that senders may still see silence while operators get a repair path.

## Reproduction Assessment

Yes, at source level: current main marks handler-timeout spooled updates failed, suppresses spooled replay fallback replies, and has regression tests expecting failed tombstones instead of replay. I did not run live Telegram fault injection in this read-only review.

## Solution Assessment

Unclear until maintainers choose the dead-letter policy. The report identifies a real gap, but the safest likely fix should preserve single-processing semantics while adding operator surfacing and a duplicate-safe user notice unless maintainers explicitly approve replay.
