## Summary

Current main still rebuilds the computer tool for each gateway invocation, so the closure-local held-button guard cannot observe a prior `tools.invoke` mouse-down. This is a valid, narrowly scoped security-hardening follow-up with no duplicate or open fix PR, but shared state must be bounded to a caller or connection lifecycle to avoid cross-client contamination.

## What This Changes

Preserve held-button target protection across successive privileged `tools.invoke` computer calls instead of resetting it with each request-scoped tool instance.

## Best Possible Solution

Add an explicit, bounded computer invocation-state owner keyed to the authenticated gateway caller or connection and session as appropriate, inject it into request-created computer tools, and prove retarget rejection plus release, disconnect, eviction, and cross-client isolation without globally caching the full tool set.
