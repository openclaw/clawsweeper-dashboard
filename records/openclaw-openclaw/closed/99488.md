## Summary

Keep open: current main still trims `params.sessionKey` directly, and the PR is a narrow defensive hardening that turns an undefined runtime value into the existing required-session-key error. The central uncertainty is not patch correctness, but whether maintainers want to widen this internal boundary without a focused regression test, since the normal `attach.grant` caller falls back to a string session key.

## What This Changes

The PR changes `mintAttachGrant` to use optional chaining before trimming `sessionKey`, so an undefined runtime value reaches the existing validation guard instead of throwing a TypeError.

## Best Possible Solution

If maintainers accept this defensive boundary, land the guard with a focused grant-store regression test; otherwise keep `mintAttachGrant` as a strict string-only internal API.

## Reproduction Assessment

Partly. Source inspection and the contributor's terminal screenshot show a direct `mintAttachGrant` call with undefined crashes on current main, but no high-confidence current-main `attach.grant` user path was shown because the caller falls back to a string session key.

## Solution Assessment

Unclear. The one-line guard is an acceptable defensive mitigation, but the best fix should either prove undefined is a real runtime boundary with regression coverage or preserve the stricter internal string contract.
