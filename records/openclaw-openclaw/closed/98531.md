## Summary

Keep open: the branch is a focused compatibility attempt, but it is not merge-ready because it leaves the linked dashboard startup `.toSorted()` path and many sibling production ES2023 Array call sites untouched, and the direct `.sort()`/`.reverse()` replacements fail lint.

## What This Changes

The PR replaces eight Control UI `Array.prototype.toSorted`/`toReversed` uses with `slice().sort()` or `slice().reverse()` equivalents across app render, chat, workboard, dreaming, and usage views.

## Best Possible Solution

Use the existing compatibility-helper pattern or a maintainer-approved startup polyfill to remove ES2023 Array dependencies from the dashboard path and affected production UI call sites, then prove the dashboard in a no-ES2023 browser/runtime.

## Reproduction Assessment

Yes, at source level: current main calls `.toSorted()` in the dashboard sidebar recent-sessions render path, and the linked report shows the same Chrome 109 dashboard error. I did not run a live Chrome 109 browser in this read-only review.

## Solution Assessment

No. This branch is narrower than the reported failure and uses direct `sort`/`reverse` replacements that fail lint; a compatibility helper or approved polyfill should cover the actual dashboard startup path and sibling production call sites.
