## Summary

Keep open. Current main and the latest release still create Discord forum-parent `message action=send` threads with only `name` and `message`, so the reported archive-duration gap remains real and is not owned by another open canonical item.

## What This Changes

The issue asks Discord forum-parent message sends to honor the forum thread archive window, either by carrying the channel default or by accepting the existing `autoArchiveMin` override on `send`.

## Best Possible Solution

Keep the fix inside the Discord plugin send path: when forum/media parent sends create a thread, pass a valid explicit archive duration from `autoArchiveMin` if provided, otherwise copy the parent channel's `default_auto_archive_duration` when available, with focused regression tests and live Discord proof.
