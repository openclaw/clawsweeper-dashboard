## Summary

The patch does not fix the reported indefinite block: when the timer wins, the unchanged credential-mutation promise is immediately awaited again by the surrounding infinite loop. The barrier is deliberate security hardening against post-revocation RPCs, so the safe repair is a bounded fail-closed connection outcome, not continuing later requests.

## What This Changes

The PR adds a 30-second Promise.race to each credential-mutation barrier wait and a standalone test suite that copies the wait-loop logic.

## Best Possible Solution

Make one bounded barrier wait return settlement versus timeout; on timeout, close the affected WebSocket through an established gateway close-cause path and require fresh authentication, then prove the actual handler behavior with focused integration coverage and redacted live output.
