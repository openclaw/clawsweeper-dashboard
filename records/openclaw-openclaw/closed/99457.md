## Summary

Keep open: current main still has the plugin-bound fallback early return keyed only on `WasMentioned === false`, while the documented group policy says always-on unmentioned group traffic should still enter the agent path unless mention gating or ambient-room mode suppresses it. No duplicate or open fix PR showed up in targeted GitHub searches.

## What This Changes

The issue asks for plugin-bound fallback to suppress unmentioned group/channel traffic only when the effective route policy requires mention gating or classifies the inbound as ambient, not for always-on group routes.

## Best Possible Solution

Update the plugin-bound fallback path to use the effective group mention or ambient-room policy before suppressing, while preserving current suppression for mention-required rooms and explicit command bypass behavior.

## Reproduction Assessment

Yes, source-level reproduction is high-confidence: create a plugin-owned group binding whose targeted claim returns `missing_plugin` or `no_handler`, set `WasMentioned: false` with an always-on `requireMention: false` route, and current main returns before `replyResolver`/agent dispatch. I did not run the live iMessage setup.

## Solution Assessment

Yes, the issue's suggested direction is the narrow maintainable fix: gate this fallback on effective mention or ambient policy instead of raw `WasMentioned`. The fix should reuse existing group policy helpers rather than add a parallel config interpretation.
