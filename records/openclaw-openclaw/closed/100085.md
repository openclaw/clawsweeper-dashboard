## Summary

Keep open: current main still kills operator terminal PTYs on WebSocket disconnect and exposes no attach/list/text or replay-buffer protocol, while the maintainer label and proposed admin-PTY lifetime/config changes require explicit maintainer review rather than conservative cleanup close.

## What This Changes

Request detach/reattach support for operator terminal sessions, including bounded output replay, a plain-text buffer read, new terminal protocol methods, UI reattach behavior, and a configurable detached-session timeout.

## Best Possible Solution

Define a maintainer-approved terminal detachment contract in the gateway/protocol/UI: bounded replay buffers, attach/list/text methods, UI reconnect reattachment, explicit caps/reaper behavior, security review for plaintext output reads, and focused tests for disconnect, reattach, shutdown, and disabled-terminal paths.

## Reproduction Assessment

Yes for the current limitation: source inspection shows `closeForConn()` finalizes and kills sessions on WebSocket disconnect, and the active protocol has no attach/list/text methods or detached-session timeout.

## Solution Assessment

Unclear as a final product design: detach/reattach is the right owner boundary for this terminal surface, but maintainers still need to settle timeout defaults, security/cap limits, and the plaintext buffer contract before implementation.
