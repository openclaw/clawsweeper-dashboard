## Summary

Keep open: current main and v2026.6.11 still route memory-wiki through one global plugin config and one vault path, while the issue discussion shows real multi-agent memory isolation and sensitive-data boundary impact that no merged PR now owns.

## What This Changes

Request per-agent memory-wiki vault configuration so agents on one gateway can keep separate wiki roots, indexes, searches, writes, and prompt/corpus context.

## Best Possible Solution

Define a maintainer-approved memory-wiki isolation contract covering schema precedence, vault routing for all read/write/context surfaces, no-context fail-closed behavior, upgrade/docs guidance, and two-agent regression proof.
