## Summary

The report is valid and still necessary: current main and the latest release retain misleading node-identity documentation, while the runtime separates the client instance identifier, signed device identity, and pairing-auth token. The protected maintainer label requires explicit maintainer handling, so this issue should remain open.

## What This Changes

Correct headless-node documentation that misstates the effect of `--node-id` and the contents of `node.json`, `identity/device.json`, and `identity/device-auth.json`.

## Best Possible Solution

Update both pages to call `--node-id` a client instance-ID override, remove the false pairing-reset claim, and document `node.json`, `identity/device.json`, and `identity/device-auth.json` separately with version-aware wording where shipped behavior is discussed.
