- `merge-risk: 🚨 security-boundary`: The diff changes which pending prompt receives an authorization request when concurrent metadata conflicts.

## Summary

This remains necessary: the branch adds the missing correlation path for concurrent ACP exec approvals, but its new selector still gives a supplied `runId` precedence over a supplied `toolCallId`. That contradicts the stated fail-closed rule and can relay an approval to the run selected by `runId` without verifying that it owns the requested execute call.

## What This Changes

The PR parses Gateway approval `toolCallId`s, uses them to correlate concurrent ACP permission prompts, derives approval titles from matched execute calls, and forwards the id through node-host approvals.

## Best Possible Solution

Make a present `toolCallId` authoritative in every selection path: when `runId` is also present, require the selected pending prompt to contain that exact execute call and otherwise drop the approval; add conflicting run-id/tool-call-id regression coverage.
