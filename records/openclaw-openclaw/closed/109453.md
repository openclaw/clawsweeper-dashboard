## Summary

Keep this PR open: the change is narrow and directionally useful, but Node’s synchronous timeout contract does not establish the claimed bound for the Windows kernel-wait failure mode, so the QA runner may still hang.

## What This Changes

Adds a five-second timeout to the Windows QA CLI process-tree `taskkill.exe` call and updates its unit expectation.

## Best Possible Solution

Use one asynchronous Windows process-tree termination helper with a parent-side settle deadline for both this path and https://github.com/openclaw/openclaw/pull/109454, then prove the stalled cleanup path on Windows.
