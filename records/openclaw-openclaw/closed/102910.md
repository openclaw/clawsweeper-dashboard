## Summary

Keep open: current main still has a source-reproducible throw in `splitTelegramHtmlChunks`. The normal `sendMessageTelegram` helper catches this and falls back to plain text, but the Telegram outbound adapter and shared payload sender can still call the throw-capable HTML chunker without a fallback, so a narrow delivery fix remains useful.

## What This Changes

The issue asks for Telegram HTML chunking to avoid uncaught tag-overhead errors so outgoing messages still deliver.

## Best Possible Solution

Keep the issue open and make Telegram HTML chunk planning degrade to readable sendable text, with sibling coverage for the splitter, outbound adapter, and payload delivery path.
