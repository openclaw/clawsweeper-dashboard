## Summary

This is a valid released regression that remains present on current main: the command path discovers installed Exa credentials, but gateway target validation only derives web-provider SecretRef targets from bundled-origin plugin records. No other open issue or PR currently owns the installed-plugin registry gap.

## What This Changes

Fix gateway command SecretRef validation so installed web-search plugins such as Exa have their declared credential targets recognized.

## Best Possible Solution

Build the gateway's process-stable known-target registry from active installed-plugin manifest metadata, while preserving plugin enablement, manifest-first laziness, strict allowed-path scoping, and provider-specific ownership in each plugin manifest.
