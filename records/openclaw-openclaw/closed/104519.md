## Summary

The issue remains necessary: current main and the latest release deliberately allow `askFallback` to re-authorize exec after a prompt timeout, and no merged change removes that path. Keep it open for an explicit security/compatibility decision because the protected item would intentionally change a shipped operator workflow.

## What This Changes

Make expiration terminal for a created exec approval so `askFallback` cannot authorize execution after the pending request times out.

## Best Possible Solution

After owner approval, remove post-timeout fallback authority at the shared decision and Gateway replay boundaries, retain any `askFallback` role only before pending creation, and align tests and public docs around one terminal expiration outcome.
