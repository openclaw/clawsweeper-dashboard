## What This Changes

The PR moves startup cron catch-up deferral tracking into cron service state so maintenance recompute callers preserve staggered missed-run slots until they fire.

## Best Possible Solution

## Reproduction Assessment

Yes. Current main is source-reproducible because read/status, finalization, reservation release, and empty-due timer maintenance recompute paths can call recomputeNextRunsForMaintenance without the startup-local deferral skip set before the deferred slot fires.

## Solution Assessment

Yes. Moving pending deferral ids into CronServiceState is the cleanest owner-boundary fix because all affected maintenance recompute callers share the same future-slot repair invariant; continuing to thread one-off skip sets through selected callers would keep the policy duplicated.
