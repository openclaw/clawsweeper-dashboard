## Summary

Issue #87996 should stay open because current main still leaves the reported LiteLLM/Vertex beta generic `INVALID_ARGUMENT` shape outside the existing provider-error, context-overflow, and provider-hook recovery classifiers, while related merged work only covers more specific overflow wording.

## What This Changes

The issue asks OpenClaw to turn generic LiteLLM/Vertex beta `INVALID_ARGUMENT` failures in long sessions into actionable, recoverable provider/session errors instead of leaving users with a generic failed turn.

## Best Possible Solution

Add a narrow provider-owned LiteLLM/Vertex recovery rule for the proven error shape, preserve redacted provider detail, and prove the failed turn clears its lane without broadly reclassifying every `INVALID_ARGUMENT`.
