## Label Justifications

- `P2`: This is a concrete Slack session-state bug with a bounded affected workflow, not a core outage or release blocker.
- `impact:session-state`: The issue splits one Slack MPIM into separate per-agent session histories and leaves stale context in the channel-keyed twin.

## Summary

Keep open: current main and the latest release still allow a C-prefixed Slack MPIM with missing `channel_type` and unresolved channel info to fall back to `channel`, while explicit or resolved MPIMs route as `group`; this is a valid Slack session-state bug with a narrow plugin-owned fix path.

## What This Changes

Fix Slack MPIM ingress so bot-authored messages without `channel_type` do not create a parallel `slack:channel:<channelId>` session for the same room that human-authored MPIM messages key as `slack:group:<channelId>`.

## Best Possible Solution

Keep the fix inside the Slack plugin by carrying or caching authoritative MPIM channel type into bot-authored ingress, then add regression coverage proving human and bot-authored events in the same MPIM share the `slack:group:<channelId>` session without changing core session-key semantics.
