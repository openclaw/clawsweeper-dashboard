## Summary

This PR remains necessary: the base implementation’s `127.` prefix rule treats a DNS hostname such as `127.evil.com` as loopback, while the proposed `isIP(...) === 4` guard preserves literal `127/8` endpoints and routes DNS names through the existing private-network opt-in. No discrete patch defect was found; normal maintainer review can decide on the intentional compatibility restriction.

## What This Changes

The branch restricts LiteLLM image-generation loopback auto-allowance to literal IPv4 `127/8` addresses and adds regression coverage for literal loopback, IPv6 loopback, DNS lookalikes, and the existing private-network opt-in.

## Best Possible Solution

Land the narrow provider-local guard with its regression coverage, retaining the existing explicit private-network opt-in for exceptional non-literal endpoint hosts.
