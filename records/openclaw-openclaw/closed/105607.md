## Summary

The current head is a focused fix, but it still leaves a reachable narration-clear path that can render raw tool progress before the five-second gate and recreate the flash it intends to remove.

## What This Changes

The PR delays narrated Discord progress drafts behind the existing activity gate and omits the implicit default title for narration unless label configuration is explicit.

## Best Possible Solution

Make narration set and clear events obey the same progress-gate invariant, then add a regression test proving a pre-gate clear stays silent until the gate opens and renders the raw fallback afterward.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. On the current head, start tool progress, receive non-empty narration while the gate is pending, then receive the narrator's empty clear update before five seconds; the compositor renders raw tool rows immediately.

## Solution Assessment

No. Delaying only non-empty narration is incomplete because the established empty-clear lifecycle can bypass the same gate; the narrowest fix is to defer that fallback render until the gate has started.
