## Summary

Keep open: current main and the latest release still have the empty-response to reused-session-clear path, and the linked fix PR is open rather than merged, so this issue still owns the remaining user problem.

## What This Changes

A reused Claude CLI session can emit a synthetic empty result before the real answer, causing OpenClaw to classify the turn as `empty_response`, clear the session, and lose later output.

## Best Possible Solution

Review and either land or close the linked fix PR, while keeping this issue open until maintainers settle whether preserving the session is enough or the runtime must wait for or deliver the later real answer.

## Reproduction Assessment

Yes at source level: current main still routes empty CLI output to `FailoverError(reason="empty_response")`, and reused Claude CLI FailoverErrors clear the stored session binding. I did not reproduce the live queued task-notification timing path against Claude CLI in this read-only review.

## Solution Assessment

Unclear as a final fix. The linked PR is a plausible narrow mitigation for preserving the binding, but the issue also asks for delivering or waiting for the later real answer, which needs maintainer judgment and real provider proof.
