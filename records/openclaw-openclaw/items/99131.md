## Summary

Keep open. Current main and v2026.6.11 still let an empty Claude CLI result become `empty_response` and clear the reused Claude CLI binding, while the open closing PR is only a candidate mitigation and has not merged.

## What This Changes

The issue reports a Claude CLI reused-session failure where a synthetic empty result is treated as final, causing OpenClaw to discard the session before the later real answer is delivered.

## Best Possible Solution

Keep this issue as the canonical tracker until maintainers land a focused Claude CLI recovery path that detects the synthetic notification-consuming resume result before destructive clearing and proves delivery or safe retry behavior.

## Reproduction Assessment

Yes, at source level with strong issue logs: current main converts empty Claude CLI output into `empty_response`, then clears a reused Claude CLI session binding on any `FailoverError`. I did not run a live Claude Code task-notification reproduction in this read-only review.

## Solution Assessment

Unclear as a complete fix. Preserving the binding is a useful mitigation, but maintainers still need to decide whether the best recovery is to keep reading the same process, retry on the same session, or route through parser/classifier fallback handling.
