## Summary

Keep open. Current main and the latest release still convert empty Claude CLI output into `FailoverError(empty_response)`, and a reused Claude CLI `FailoverError` still clears the stored session binding; the linked closing PR is open but not merged.

## What This Changes

Prevent reused Claude CLI sessions with synthetic empty task-notification results from being discarded before the later real answer is delivered.

## Best Possible Solution

Review and land a focused fix, likely through https://github.com/openclaw/openclaw/pull/99139 or an adjusted version, that classifies the Claude synthetic notification-consuming resume separately and preserves/delivers session state with live Claude CLI task-notification proof.

## Reproduction Assessment

Yes, source-reproducible with strong report evidence. The issue logs match current main: empty Claude CLI output becomes `empty_response`, and any reused-session `FailoverError` clears the stored Claude CLI binding; I did not run a live Claude Code task-notification repro.

## Solution Assessment

Unclear. Preserving the session on `empty_response` is a plausible narrow mitigation, but maintainers still need to choose whether the best fix is to keep reading the same process, retry the same session, or preserve the binding while routing through fallback/status handling.
