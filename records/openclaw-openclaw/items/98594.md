## Summary

Keep open: current main and the latest release still generate the macOS app LaunchAgent plist with only `PATH`, so the profile env loss remains. The active fix path is to review and consolidate the open candidate PRs at https://github.com/openclaw/openclaw/pull/99739 and https://github.com/openclaw/openclaw/pull/99752, then close this issue after one lands.

## What This Changes

The issue requests preserving non-empty `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` in the macOS app LaunchAgent so Launch at Login uses the same OpenClaw profile.

## Best Possible Solution

Land one narrow macOS app LaunchAgent fix that carries the two existing profile env vars once when non-empty, escapes plist values, adds focused Swift plist coverage, and includes redacted macOS launchd proof.

## Reproduction Assessment

Yes, source-reproducible with high confidence: current `plistContents` emits only `PATH`, while `OpenClawPaths` uses `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` to select the active profile. I did not run a live macOS login cycle in this read-only review.

## Solution Assessment

Yes, the best fix direction is preserving the already-supported env override keys in the app LaunchAgent rather than adding new config or changing gateway service policy. The current open PRs still need maintainer review, consolidation, and real macOS proof before this issue can close.
