## Summary

Keep open: current main and v2026.6.11 still generate the macOS app Launch at Login plist with only PATH, so the profile-env loss remains; the issue should stay canonical while the open candidate fix PRs are reviewed.

## What This Changes

The issue asks the macOS Launch at Login plist to preserve OPENCLAW_CONFIG_PATH and OPENCLAW_STATE_DIR so custom app profiles survive login relaunches.

## Best Possible Solution

Land one narrow macOS LaunchAgent fix that preserves the two existing profile env vars once when non-empty, escapes plist values, adds focused Swift plist coverage, and includes redacted macOS launchd or login proof.

## Reproduction Assessment

Yes, source-reproducible: current main writes only PATH into the macOS app LaunchAgent plist while OpenClawPaths uses OPENCLAW_CONFIG_PATH and OPENCLAW_STATE_DIR for the active profile. I did not run a live macOS login cycle in this read-only review.

## Solution Assessment

Yes, the right fix is to preserve the already-supported profile env keys in the app LaunchAgent. The best path now is to review, repair, and land one of the open candidate PRs instead of creating another duplicate repair.
