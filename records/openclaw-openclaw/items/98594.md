## Summary

Keep open: current main still writes the macOS app launch-at-login plist with only `PATH`, while the macOS app profile resolver already uses `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR`. The issue now has open fix candidates, including https://github.com/openclaw/openclaw/pull/99739 with closing syntax, so the right cleanup path is to review and land or reject one of those PRs rather than close this issue early.

## What This Changes

The issue requests preserving non-empty `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` in the macOS app launch-at-login LaunchAgent so login-launched OpenClaw keeps the profile active when autostart was enabled.

## Best Possible Solution

Review and land one narrow macOS LaunchAgent fix that preserves the existing profile env vars when non-empty, escapes plist values through a safe plist path, and adds focused Swift coverage without changing the separate gateway service environment policy.

## Reproduction Assessment

Yes, from source inspection rather than a live login cycle: the LaunchAgent plist generator emits only `PATH`, while `OpenClawPaths` uses `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` to select the macOS app profile.

## Solution Assessment

Yes: carrying the already-supported profile env vars into the app LaunchAgent is the narrowest maintainable fix, with focused plist parsing tests; adding a new config knob or reusing the separate gateway-service env machinery would be broader than needed.
