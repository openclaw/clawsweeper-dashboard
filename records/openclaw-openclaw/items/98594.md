## Summary

Keep open: current `origin/main` and latest release still generate the macOS app LaunchAgent plist with only `PATH`, so login launch can still drop the profile env and fall back to the default state/config. The open candidate PR at https://github.com/openclaw/openclaw/pull/99739 uses closing syntax for this issue, so the issue should stay open until a proof-positive fix PR lands.

## What This Changes

The issue reports that macOS Launch at Login does not preserve `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` for custom OpenClaw profiles.

## Best Possible Solution

Land one narrow macOS LaunchAgent fix that preserves non-empty `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` exactly once, keeps existing `PATH` behavior, adds focused Swift plist tests, and includes redacted macOS launchd proof.

## Reproduction Assessment

Yes, source-reproducible: current `origin/main` writes only `PATH` into the macOS app LaunchAgent plist while `OpenClawPaths` uses `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` for profile selection. I did not run a live macOS login cycle in this read-only review.

## Solution Assessment

Yes, the best fix is the narrow LaunchAgent plist propagation of the existing env contract, not a new setting or compatibility layer. The issue should stay open until one linked fix PR lands with tests and macOS proof.
