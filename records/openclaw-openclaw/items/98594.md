## Summary

Keep open: current main and v2026.6.11 still generate the macOS app LaunchAgent plist with only `PATH`, while the macOS app resolves custom profiles from `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR`. Open PRs at https://github.com/openclaw/openclaw/pull/99739 and https://github.com/openclaw/openclaw/pull/99752 are candidate fixes, so this issue should close only after a fix lands.

## What This Changes

The issue reports that macOS Launch at Login does not preserve custom OpenClaw profile environment variables in its LaunchAgent plist.

## Best Possible Solution

Land one narrow macOS app LaunchAgent fix that preserves the existing non-empty profile env vars exactly once, keeps `PATH` behavior, escapes plist values safely, and proves the generated plist on macOS.

## Reproduction Assessment

Yes from source inspection: current `main` writes only `PATH` into the app LaunchAgent environment while the macOS app uses `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` to resolve the active profile. I did not run a live macOS login cycle in this read-only review.

## Solution Assessment

Yes: preserving the already-supported env override keys in the app LaunchAgent plist is the narrow owner-boundary fix. The existing open PRs need review/proof before this issue can close.
