- `impact:session-state`: The reported failure can restart the app under the wrong OpenClaw config/state directory after login, causing profile and session-state drift.

## Summary

Keep open: current main still writes the macOS app LaunchAgent `EnvironmentVariables` dictionary with only `PATH`, while the macOS app resolves `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` for profile selection. The open PRs at https://github.com/openclaw/openclaw/pull/99739 and https://github.com/openclaw/openclaw/pull/99752 are candidate fixes, but neither is merged, so this issue should remain the canonical tracking item.

## What This Changes

The issue asks macOS launch-at-login to preserve `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` in the generated LaunchAgent plist so autostart keeps the profile active when Launch at Login was enabled.

## Best Possible Solution

Land one narrow macOS fix that adds non-empty `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` to the generated app LaunchAgent environment, keeps `PATH`, escapes plist values safely, and adds focused Swift regression coverage.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: enable Launch at Login while the app process has custom profile env vars, and the generated plist currently includes only `PATH`, so a login-launched process cannot inherit those profile variables from the plist.

## Solution Assessment

Yes. The best fix is the narrow LaunchAgent generation change already described by the issue: preserve only the supported non-empty profile env vars alongside `PATH` and verify the plist output with Swift tests.
