- `P2`: This is a normal-priority macOS startup/profile bug with clear source evidence and limited blast radius to Launch at Login users using custom profile env vars.
- `impact:session-state`: A login-launched app can bind to the default config/state instead of the profile the user enabled autostart from, causing profile and session-state drift.
- `maturity:stable`: The issue affects the M4 Stable `macos-gateway-host` surface, specifically LaunchAgent/profile state and config handling.

## Summary

Keep open: current main and v2026.6.11 still generate the macOS app LaunchAgent with only `PATH`, and open candidate PRs now own the repair path. The issue should close only after one narrow LaunchAgent fix lands with Swift coverage and macOS launchd proof.

## What This Changes

Preserve `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` in the macOS app launch-at-login plist so login launches keep the selected OpenClaw profile.

## Best Possible Solution

Land one narrow macOS LaunchAgent fix that preserves the two existing non-empty profile env vars alongside `PATH`, escapes plist values, adds raw plist regression coverage, and includes redacted macOS launchd or Launch at Login proof.

## Reproduction Assessment

Yes, source-reproducible: current main writes only `PATH` into the macOS app LaunchAgent plist while `OpenClawPaths` reads `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` for profile selection. I did not run a live macOS login cycle in this read-only review.

## Solution Assessment

Yes, preserving the already-supported env override keys in the app LaunchAgent is the narrow owner-boundary fix. The open candidate PRs still need review, consolidation, and real macOS proof before this issue can close.
