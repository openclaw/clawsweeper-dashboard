## Summary

Keep open: current main and the latest release still generate the macOS app Launch at Login plist with only `PATH`, while the app profile resolver depends on `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR`; active PRs are candidate fixes, not merged fixes.

## What This Changes

The issue asks the macOS app Launch at Login plist to preserve non-empty `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` so login-launched app instances keep the selected profile.

## Best Possible Solution

Land one narrow macOS LaunchAgent fix that preserves the two existing profile env keys once, keeps `PATH` behavior, adds isolated Swift plist coverage, and includes redacted macOS launchd or Launch at Login proof.

## Reproduction Assessment

Yes, source-reproducible: current main writes only `PATH` into the macOS app LaunchAgent plist while `OpenClawPaths` uses `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` for profile selection. I did not run a live macOS login cycle in this read-only review.

## Solution Assessment

Yes, the requested shape is the narrow maintainable fix: preserve the existing profile env contract in the app LaunchAgent rather than adding new config or reusing the separate gateway service env machinery.
