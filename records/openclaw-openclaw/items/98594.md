## Summary

Keep open: current main and v2026.6.11 still generate the macOS app LaunchAgent environment with only PATH, and the active linked fix PR is open rather than merged. This issue should stay canonical until that PR lands or is replaced.

## What This Changes

The issue reports that macOS launch-at-login loses the custom OpenClaw profile environment and falls back to the default profile after login.

## Best Possible Solution

Land a narrow macOS app LaunchAgent fix, or a clean replacement for the open candidate PR, that preserves non-empty OPENCLAW_CONFIG_PATH and OPENCLAW_STATE_DIR, escapes plist values, and proves the plist output with focused Swift tests plus macOS proof.

## Reproduction Assessment

Yes, source-reproducible: current main emits only PATH in the macOS app LaunchAgent plist while OpenClawPaths reads OPENCLAW_CONFIG_PATH and OPENCLAW_STATE_DIR for the active profile. I did not run a live macOS login cycle in this read-only review.

## Solution Assessment

Yes, preserving the existing profile env keys in the app LaunchAgent is the narrow maintainable fix; adding a new config surface or reusing unrelated gateway service machinery would be broader than necessary. The active PR is the right direction but remains open and still needs repair/proof before the issue can close.
