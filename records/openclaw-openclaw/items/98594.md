## Summary

Keep open: current main and the latest release still generate the macOS app launch-at-login plist with only `PATH`, so the profile env loss remains. The open fix PRs are useful candidates, but they are unmerged and still need review/proof, so this issue should remain the tracking anchor.

## What This Changes

The issue requests preserving non-empty `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` in the macOS app launch-at-login LaunchAgent plist.

## Best Possible Solution

Land one narrow macOS LaunchAgent fix that preserves the two existing profile env keys when non-empty, keeps `PATH`, escapes plist output, and includes Swift regression coverage plus redacted macOS launchd proof.

## Reproduction Assessment

Yes, source-reproducible: current main writes only `PATH` into the macOS app LaunchAgent plist while `OpenClawPaths` uses `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` for the active profile. I did not run a live macOS login cycle.

## Solution Assessment

Yes: preserving the existing profile env keys in the app LaunchAgent is the narrowest maintainable fix. The best path now is to review and land one proof-positive open PR rather than queue another duplicate branch.
