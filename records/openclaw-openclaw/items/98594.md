## Summary

Keep open: current main and the latest release still generate the macOS app Launch at Login plist with only `PATH`, while an open linked fix PR and another open candidate PR are still awaiting PR-level repair/proof before this issue can close.

## What This Changes

The issue asks macOS Launch at Login to preserve non-empty `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` in the app plist so login-launched instances keep the selected profile.

## Best Possible Solution

Land one narrow macOS LaunchAgent fix that preserves the two existing profile env keys once, keeps plist escaping and `PATH`, adds focused Swift coverage, and includes redacted macOS launchd proof before closing this issue.

## Reproduction Assessment

Yes, source-reproducible on current main: the app LaunchAgent plist emits only `PATH`, while `OpenClawPaths` uses `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` for profile selection. I did not run a live macOS logout/login cycle in this read-only review.

## Solution Assessment
