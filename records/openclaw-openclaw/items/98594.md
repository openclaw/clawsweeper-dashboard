## Summary

Keep open: current main and the latest release still generate the macOS app autostart plist with only `PATH`, so a login-launched app can lose the selected profile env and fall back to the default profile. The linked fix PR at https://github.com/openclaw/openclaw/pull/98596 attempted the right narrow area but is closed unmerged, so it is useful context rather than a closure reason.

## What This Changes

The issue asks the macOS app Launch at login plist to preserve non-empty `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` alongside `PATH`.

## Best Possible Solution

Land a narrow macOS app LaunchAgent fix that carries the two existing profile env vars when non-empty, escapes plist values, and adds focused Swift plist tests without changing gateway service env policy.

## Reproduction Assessment

Yes from source inspection, though not from a live login cycle: `LaunchAgentManager.plistContents` emits only `PATH`, while `OpenClawPaths` uses `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` to select the macOS app profile.

## Solution Assessment

Yes: preserving the already-supported env override keys in the app LaunchAgent is narrower than adding new config or reusing the separate gateway durable-env machinery for `ai.openclaw.mac.plist`.
