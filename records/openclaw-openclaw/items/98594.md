## Summary

Keep open: current main and the latest release still generate the macOS app launch-at-login plist with only `PATH`, so the reported profile-env drop remains real. An open linked PR now owns the candidate fix, so this issue should stay open until that PR is reviewed and merged.

## What This Changes

The issue reports that macOS Launch at Login drops `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR`, causing login-launched OpenClaw to fall back to the default profile.

## Best Possible Solution

Review and land a narrow fix such as https://github.com/openclaw/openclaw/pull/99739 that preserves the existing profile env vars in the app LaunchAgent plist, then close this issue after merge evidence exists.

## Reproduction Assessment

Yes, from source: current `LaunchAgentManager.plistContents` emits only `PATH` in `EnvironmentVariables`, while `OpenClawPaths` reads the profile from `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR`. I did not run a live macOS login cycle in this read-only review.

## Solution Assessment

Yes at the issue level: preserving the already-supported env override keys in the app LaunchAgent is the narrowest maintainable fix. The active PR still needs review and macOS validation before this issue closes.
