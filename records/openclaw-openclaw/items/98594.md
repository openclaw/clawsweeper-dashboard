- `maturity:stable`: The issue affects the `macos-gateway-host` Profiles and Isolation surface, which is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and the latest release still generate the macOS app LaunchAgent plist with only `PATH`, while two open PRs are candidate fixes. The issue should remain the canonical tracker until one proof-positive PR lands.

## What This Changes

The issue asks macOS Launch at Login to preserve non-empty `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` so login-launched app instances keep the profile that enabled autostart.

## Best Possible Solution

Land one narrow macOS LaunchAgent fix that carries the two existing profile env vars once when non-empty, preserves `PATH`, escapes plist values, adds focused Swift plist coverage, and then close duplicate candidate PRs after the fix lands.

## Reproduction Assessment

Yes, source-reproducible: current `main` writes only `PATH` into the macOS app LaunchAgent plist while `OpenClawPaths` uses `OPENCLAW_CONFIG_PATH` and `OPENCLAW_STATE_DIR` for profile selection. I did not run a live macOS login cycle in this read-only review.

## Solution Assessment

Yes, preserving the existing env override keys in the app LaunchAgent is the narrow maintainable fix. The best path is to review and land one linked candidate PR with macOS launchd proof rather than queueing another duplicate fix.
