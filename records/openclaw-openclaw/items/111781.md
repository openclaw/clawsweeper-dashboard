## Summary

Keep this PR open for revision: it adds a MIME heuristic that conflicts with the registered `audio/aac` container contract and can turn an ISOBMFF video into audio solely from a misleading header or `.aac` suffix.

## What This Changes

The PR adds `audio/aac` to the ambiguous-ISOBMFF audio-hint map and changes MIME detection cases to return `audio/aac` for `isom`-brand bytes.

## Best Possible Solution

Keep `audio/aac` out of the ISOBMFF override map; use `audio/mp4` for correctly labelled audio-only MP4, or add actual container-track inspection before supporting malformed AAC hints.

## Solution Assessment

No. Extending the existing hint map is not a safe fix because an ISOBMFF brand alone does not prove an audio-only container; correctly labelled audio-only MP4 already has the `audio/mp4` family of hints.
