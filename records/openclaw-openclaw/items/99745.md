## Summary

Keep open: the Telegram rich-send direction matches the linked issue and scoped send-funnel parity rule, but the patch currently fails type checking because the new fallback helper is scoped inside the plain chunk sender while the rich chunk sender calls it from outside that scope. ## What This Changes

This PR raises the shared typing failure breaker default and adds Telegram rich-message empty-content/plain-text fallbacks in durable and delivery send funnels with regression tests.

## Best Possible Solution

Move the fallback helper to a scope visible to the rich chunk sender or define it inside that sender, keep both Telegram send funnels aligned, then add real Telegram proof plus focused type/test validation before merge.

## Reproduction Assessment

Yes. Current-main source shows the two-failure typing default and the rich send paths without an empty-content/content-required fallback; the PR's own merge commit also has a reproducible type-check failure in CI.

## Solution Assessment
