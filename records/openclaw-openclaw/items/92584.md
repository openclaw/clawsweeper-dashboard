## Summary

The PR is a narrow, well-proven security hardening change, but it intentionally removes a shipped Control UI media compatibility path, so it should stay open for maintainer acceptance of that break before merge.

## What This Changes

The PR removes Control UI assistant-media query-token authentication, updates media tests to use bearer headers, and adds an e2e regression that rejects a correct `?token=` while preserving bearer and mediaTicket access.

## Best Possible Solution

Land the narrow fallback removal after maintainer acceptance, with release-note or PR-body context naming bearer auth and scoped mediaTicket URLs as the supported assistant-media paths.
