## What This Changes

The issue asks to make the TUI PTY `/reset` test deterministic by ensuring it emits the expected session-reset RPC rather than intermittently timing out under CI timing.

## System Context

The TUI PTY harness types commands into an interactive terminal backed by an in-process fixture Gateway. `/reset` passes through the TUI command lifecycle guard before it can reset the active session and emit the fixture RPC that the harness asserts.

## Architecture Diagram

flowchart LR

  B --> C[TUI command handler]
  C --> D[Run lifecycle guard]
  D -->|idle| E[Session reset RPC]
  D -->|active or finishing| F[Abort-first terminal message]
  E --> G[Fixture RPC log assertion]
  F --> G

## Best Possible Solution

Preserve the active-run data-loss protection, establish the intended boundary for a just-finished run, then make the PTY test wait for the corresponding settled state and add failure diagnostics that include recent PTY output alongside fixture RPC entries.
