## What This Changes

The PR wraps gateway lock payload writing after `fs.open("wx")` in an inner cleanup block that closes the handle and removes the partial lock file before rethrowing.

## Best Possible Solution

Land the narrow cleanup after adding real failure-injection proof, ideally with focused regression coverage, while preserving existing `GatewayLockError` wrapping.

## Reproduction Assessment

Yes, there is a high-confidence source reproduction path: make `fs.open` succeed and make the returned handle's `writeFile` reject, then current main throws before any close path runs. I did not execute a live disk-full or injected-handle reproduction in this read-only review.

## Solution Assessment

Yes, the inner cleanup block is the narrowest maintainable fix because it owns the acquired handle before any caller can receive a `release` function. Moving cleanup to callers would not help when acquisition fails before returning.
