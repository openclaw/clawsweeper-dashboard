## Summary

Keep open: the patch is the right narrow code fix for the source-proven gateway-lock file-descriptor leak, but this external PR still needs convincing real behavior proof before merge.

## What This Changes

The PR wraps gateway-lock payload writing after `fs.open("wx")` so write failures close the handle, remove the partial lock file, and rethrow.

## Best Possible Solution

Land this narrow `acquireGatewayLock` cleanup after acceptable redacted failure-injection proof, preferably with a focused regression test for the opened-handle write-failure path.

## Reproduction Assessment

Yes. Source-level reproduction is high confidence: make `fs.open(lockPath, "wx")` succeed and the returned `FileHandle.writeFile` reject, and current main has no cleanup before throwing `GatewayLockError`.

## Solution Assessment

Yes for the code shape: `acquireGatewayLock` owns the unreturned handle, so closing it and removing the partial lock in an inner catch is the narrow maintainable fix. Merge readiness still needs stronger real behavior proof, and preferably regression coverage.
