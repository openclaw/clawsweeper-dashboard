## Summary

Keep this PR open for a focused repair. The reported data-loss bug is real and the cleanup boundary is appropriate, but protection currently depends on the source checkout’s present `.worktreeinclude`; changing or removing that manifest after provisioning can leave the same unique ignored state eligible for permanent deletion.

## What This Changes

The PR adds a guard to run-end and automatic managed-worktree cleanup that compares `.worktreeinclude`-matched ignored files against the source checkout and preserves worktrees when content, type, permissions, or readability diverge.

## Best Possible Solution

Retain or derive the provisioned-file set independently of the source manifest’s current contents, compare that set with the exact state restore can recreate, and cover manifest removal and pattern changes with real-service regressions.
