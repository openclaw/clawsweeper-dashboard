## Summary

Keep open: current main and the latest release still provide static Discord presence, auto-presence, and the gated `set-presence` message action, but not the requested plugin-runtime Discord presence API. This remains a public plugin/channel API and bot-credential security-boundary product decision, not conservative cleanup.

## What This Changes

Add an `api.runtime.channel.discord.updatePresence(...)` method so plugins can change Discord bot activity/status at runtime without restarting.

## Best Possible Solution

Approve a Discord-owned, default-off, account-scoped plugin runtime presence contract that reuses the existing gateway update path without exposing provider internals, then add focused docs and tests for authorization and precedence.

## Reproduction Assessment

Not applicable: this is a feature/API request, not a reported broken existing behavior. Source and release inspection give a high-confidence current-main and v2026.6.11 gap for the requested plugin-runtime Discord presence API.

## Solution Assessment

Unclear as proposed: dynamic presence control is plausible, but a direct `api.runtime.channel.discord` slot conflicts with the current generic runtime boundary unless maintainers intentionally add a Discord-owned seam.
