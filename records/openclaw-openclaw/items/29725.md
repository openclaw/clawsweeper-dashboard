## Summary

Keep open: current main and v2026.6.11 still do not expose the requested plugin-runtime `api.runtime.channel.discord.updatePresence` API. The remaining work is a public Discord plugin API and bot-credential mutation boundary decision, not a narrow stale cleanup item.

## What This Changes

Request a new plugin-runtime Discord presence method so plugins can dynamically update the bot status and activity without restarting.

## Best Possible Solution

Approve or reject a Discord-owned plugin runtime presence contract that reuses the existing gateway presence path through a narrow, gated, account-scoped seam with documented precedence against static config, auto-presence, and `setPresence`.

## Maintainer Decision

Rationale: The source already has internal presence mutation paths, but promoting one to `api.runtime.channel.discord` changes the public plugin contract and exposes a bot-token-backed mutation boundary to plugin code.

Likely owner: steipete

Owner confidence: medium

Options:

- **Approve a gated runtime API (recommended):** Add a narrow Discord-owned `updatePresence` runtime seam with explicit gating, account selection, docs, tests, and precedence rules.
- **Keep presence as message action only:** Keep dynamic presence limited to the existing default-off `setPresence` message action and document that plugins should not mutate Discord presence directly.
- **Fold into self-profile direction:** Defer this presence-only API behind the broader Discord self-profile decision if maintainers want one identity/profile contract instead of a separate runtime method.
