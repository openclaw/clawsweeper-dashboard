## Summary

Keep open: current main still lacks the requested `api.runtime.channel.discord.updatePresence` plugin-runtime API. The repository now has static Discord presence config, optional auto-presence, and a gated `setPresence` message action, but promoting presence mutation to plugin code remains a public API and Discord bot-credential security-boundary decision.

## What This Changes

Expose a Discord plugin-runtime method so plugins can dynamically update the bot's activity and status without restarting the Discord channel.

## Best Possible Solution

Approve or reject a narrow Discord-owned plugin-runtime presence contract; if approved, reuse the existing gateway presence path with explicit gating, account scoping, docs, tests, live Discord proof, and precedence rules.

- **Design gated runtime API (recommended):** Add a narrow Discord-owned `updatePresence`-style runtime seam with explicit gating, account selection, docs, tests, live Discord proof, and precedence rules.

- **Fold into self-profile direction:** Defer this request behind https://github.com/openclaw/openclaw/issues/34004 if maintainers want one Discord identity/profile API instead of a separate presence-only runtime API.
