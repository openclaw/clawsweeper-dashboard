## Summary

Keep open: current main and v2026.6.11 still do not expose the requested `api.runtime.channel.discord.updatePresence` plugin API. Existing static config, auto-presence, and the gated `setPresence` message action cover related Discord presence behavior, but the remaining request is a public plugin API and bot-credential security-boundary decision.

## What This Changes

The issue requests a plugin-runtime Discord `updatePresence()` API so plugins can update bot status and activity without a restart.

## Best Possible Solution

Approve or reject a Discord-owned, default-off, account-scoped plugin runtime presence contract that reuses the existing gateway presence path and defines precedence against static config, auto-presence, and `setPresence`.

Rationale: The source already has internal presence mutation paths, but promoting one to `api.runtime.channel.discord` changes both the public plugin contract and the stored Discord bot-credential mutation boundary.

Likely owner: steipete

Owner confidence: high

Options:

- **Design a gated Discord runtime API (recommended):** Add a narrow Discord-owned `updatePresence`-style runtime seam with explicit gating, account selection, docs, tests, and precedence rules.
- **Keep presence as message action only:** Keep dynamic presence limited to the existing default-off `setPresence` action and document that plugins should not mutate Discord presence directly.
- **Fold into self-profile direction:** Defer this issue behind https://github.com/openclaw/openclaw/issues/34004 if maintainers want one Discord identity/profile API instead of a presence-only plugin API.
