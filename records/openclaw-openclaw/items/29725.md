## Summary

Keep open: current main and the latest release still do not expose the requested `api.runtime.channel.discord.updatePresence` plugin runtime API. Existing Discord support covers static config, auto-presence, and a default-off `setPresence` message action, but promoting presence mutation to plugin runtime remains a public API and bot-credential security-boundary decision.

## What This Changes

Expose a Discord plugin runtime `updatePresence()` API so plugins can change the bot's status/activity without restarting or using unsupported client access.

## Best Possible Solution

Approve or reject a narrow Discord-owned plugin-runtime presence contract that reuses the existing gateway presence path through an explicit gate, account scope, docs, tests, live proof, and precedence rules.

Options:

- **Design a gated Discord runtime API (recommended):** Add a narrow Discord-owned `updatePresence`-style runtime seam with explicit gating, account selection, docs, tests, and precedence rules.
- **Keep presence as message action only:** Keep dynamic presence limited to the existing default-off `setPresence` message action and document that plugins should not mutate Discord presence directly.
- **Fold into self-profile direction:** Defer this issue behind the broader self-profile decision if maintainers want one Discord identity/profile API instead of a separate presence-only plugin API.
