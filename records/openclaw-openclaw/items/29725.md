## Summary

Keep open: current main still has static Discord presence config, auto-presence, and a gated `setPresence` message action, but it does not expose the requested plugin-runtime `api.runtime.channel.discord.updatePresence` API. The remaining work is a public plugin API and Discord credential-boundary decision.

## What This Changes

The issue requests a Discord plugin-runtime API for dynamically updating bot presence without restarting the gateway.

## Best Possible Solution

Approve or reject a Discord-owned, default-off, account-scoped presence mutation contract; if approved, implement it through a narrow plugin-owned SDK/runtime seam with documented precedence against static config, auto-presence, and `setPresence`.

- **Fold into self-profile direction:** Defer this request behind the broader Discord self-profile/status discussion if maintainers want one identity/profile API instead of a presence-only runtime API.
