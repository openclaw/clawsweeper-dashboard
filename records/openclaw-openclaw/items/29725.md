## Summary

Keep open: current main and v2026.6.11 still do not provide the requested plugin-runtime `api.runtime.channel.discord.updatePresence` API. The existing Discord implementation has static config, auto-presence, and a default-off `setPresence` message action, but promoting presence mutation to plugin runtime remains a public API and security-boundary decision.

## What This Changes

The issue requests a Discord plugin-runtime API that lets plugins update bot activity/status dynamically without direct Discord client access or restarts.

## Best Possible Solution

Approve or reject a narrow Discord-owned plugin-runtime presence contract that reuses the existing gateway path with explicit gating, account scoping, precedence rules, docs, tests, and live Discord proof.

- **Fold into self-profile direction:** Defer this request behind https://github.com/openclaw/openclaw/issues/34004 if maintainers want one Discord identity/profile API instead of a separate presence-only runtime API.
