## Summary

Keep open: current main still has static Discord presence config, auto-presence, and a default-off `setPresence` message action, but it does not expose the requested `api.runtime.channel.discord.updatePresence` plugin runtime API. The remaining work is a public plugin contract and Discord bot-credential mutation boundary that needs maintainer product and security approval.

## What This Changes

Request to add a Discord plugin runtime method so plugins can update bot status/activity dynamically without restarting OpenClaw.

## Best Possible Solution

Approve or reject a narrow Discord-owned plugin-runtime presence contract that reuses the existing gateway presence path through an explicit gate, account scope, docs, tests, live proof, and clear precedence rules.

Question: Should OpenClaw expose Discord bot presence mutation to plugins as a public runtime API, and what gate, account scoping, audit/error, and precedence model should it use?

Rationale: The internal gateway path exists, but promoting it to plugin runtime changes the public plugin contract and exposes a Discord bot-credential-backed mutation boundary to plugin code.

Likely owner: thewilloftheshadow

Owner confidence: high

Options:

- **Design a gated runtime API (recommended):** Add a narrow Discord-owned `updatePresence`-style runtime seam with explicit gating, account selection, docs, tests, live proof, and precedence rules.
- **Keep presence as message action only:** Leave dynamic presence mutation on the existing default-off `setPresence` message action and document that plugins should not mutate Discord presence directly.
- **Fold into self-profile direction:** Defer this request behind https://github.com/openclaw/openclaw/issues/34004 if maintainers want one Discord identity/profile API instead of a separate presence-only runtime API.
