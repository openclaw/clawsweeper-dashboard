## Summary

Keep open: current main still lacks the requested plugin-runtime `api.runtime.channel.discord.updatePresence` API. Existing Discord presence support covers static config, auto-presence, and a gated `set-presence` message action, but exposing presence mutation to plugin code remains a public API and security-boundary decision.

## What This Changes

The issue requests a plugin-accessible Discord runtime API for dynamically updating bot presence without restarting OpenClaw.

## Best Possible Solution

Approve or reject a Discord-owned plugin runtime presence contract that reuses the existing gateway presence path through a narrow, gated, account-scoped seam with documented precedence against static config, auto-presence, and `setPresence`.

- **Fold into self-profile direction:** Defer this issue behind https://github.com/openclaw/openclaw/issues/34004 if maintainers want one Discord identity/profile API instead of a presence-only runtime API.
