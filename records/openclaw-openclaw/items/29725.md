## Summary

Keep open: current main and the latest release still provide static Discord presence, auto-presence, and the gated `setPresence` message action, but not the requested plugin-runtime Discord `updatePresence` API. This remains a Discord/plugin API and bot-credential security-boundary decision, and the related self-profile issue only partially overlaps it.

## What This Changes

Add a plugin-facing Discord runtime method so plugins can dynamically update the bot's Discord activity and status without restarting.

## Best Possible Solution

Approve a Discord-owned, default-off, account-scoped plugin runtime presence contract that reuses the existing gateway update path without exposing provider internals, then add focused SDK/docs/tests for authorization and precedence.

## Reproduction Assessment

Not applicable: this is a feature/API request, not a reported broken existing behavior. Current-main and v2026.6.11 source inspection give a high-confidence gap for the requested plugin-runtime Discord presence API.

## Solution Assessment

Unclear as proposed: dynamic presence control is plausible, but a direct `api.runtime.channel.discord` slot conflicts with the current generic runtime boundary unless maintainers intentionally add a Discord-owned seam. A safer shape would reuse the existing gateway path behind explicit account scoping, gating, docs, and precedence rules.
