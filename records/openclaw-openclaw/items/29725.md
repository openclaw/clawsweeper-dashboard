## Summary

Keep open: current main and v2026.6.11 still have static Discord presence, auto-presence, and the gated `setPresence` message action, but not the requested plugin-runtime `api.runtime.channel.discord.updatePresence` API. This remains a public Discord/plugin API and bot-credential security-boundary decision, not conservative cleanup.

## What This Changes

The issue requests a new Discord plugin-runtime API, `api.runtime.channel.discord.updatePresence(...)`, so plugins can update the bot's Discord activity/status without restarting.

## Best Possible Solution

Approve a Discord-owned, account-scoped, default-off plugin runtime presence contract that reuses the existing gateway update path without exposing provider internals, then add focused docs and tests for authorization, account selection, and precedence.

## Reproduction Assessment

Not applicable: this is a feature/API request, not a reported broken existing behavior. Source and release inspection give a high-confidence current-main and v2026.6.11 gap for the requested plugin-runtime Discord presence API.

## Solution Assessment

Unclear as proposed: dynamic presence control is plausible, but a direct `api.runtime.channel.discord` slot conflicts with the current generic runtime boundary unless maintainers intentionally add a Discord-owned seam and security model.
