## Summary

Keep open: current main and v2026.6.11 still lack the requested plugin-runtime `api.runtime.channel.discord.updatePresence` API. Existing static config, auto-presence, and the gated Discord `setPresence` message action cover adjacent presence paths, but promoting presence mutation into the plugin runtime remains a public API and security-boundary decision.

## What This Changes

The issue requests a plugin runtime API for updating Discord bot presence dynamically without restarting.

## Best Possible Solution

Approve or reject a Discord-owned plugin runtime presence contract that reuses the existing gateway presence path through a narrow, gated, account-scoped seam with documented precedence against static config, auto-presence, and `setPresence`.

## Maintainer Decision

Rationale: The implementation path exists internally, but promoting it to plugin runtime changes the public plugin contract and the Discord bot-credential mutation boundary.

Likely owner: Peter Steinberger

Owner reason: The unresolved choice is primarily a public plugin-runtime boundary decision with Discord security implications.

Owner confidence: medium

Options:

- **Design a gated runtime API (recommended):** Add a narrow Discord-owned `updatePresence`-style runtime seam with explicit gating, account selection, docs, tests, and precedence rules.
- **Keep presence as message action only:** Keep dynamic presence limited to the existing default-off `setPresence` message action and document that plugins should not mutate Discord presence directly.
- **Fold into self-profile direction:** Defer this request behind https://github.com/openclaw/openclaw/issues/34004 if maintainers want one Discord identity/profile API instead of a separate presence-only runtime API.
