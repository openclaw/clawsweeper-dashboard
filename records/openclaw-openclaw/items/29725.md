## Summary

Keep open: current main and v2026.6.11 still do not expose the requested `api.runtime.channel.discord.updatePresence` plugin-runtime API. Existing Discord support covers static config, auto-presence, and a gated `setPresence` message action, but promoting presence mutation to plugins remains a public API and Discord bot-credential security-boundary decision.

## What This Changes

Expose a plugin runtime method so plugins can dynamically update Discord bot presence/status without restarting OpenClaw.

## Best Possible Solution

Approve or reject a narrow Discord-owned plugin-runtime presence contract that reuses the existing gateway presence path through an explicit gate, account scope, precedence rules, docs, tests, and live Discord proof.

Rationale: The internal gateway capability exists, but promoting it to plugin runtime changes the public plugin contract and exposes a Discord bot-credential-backed mutation boundary to plugin code.

Likely owner: steipete

Owner confidence: medium

Options:

- **Design a gated runtime API (recommended):** Add a narrow Discord-owned `updatePresence` runtime seam with explicit authorization, account selection, docs, tests, and precedence with static and auto presence.
- **Keep current surfaces only:** Leave dynamic presence mutation on static config, auto-presence, and the default-off `setPresence` message action instead of giving plugins direct runtime control.
- **Fold into self-profile direction:** Defer this request behind https://github.com/openclaw/openclaw/issues/34004 if maintainers want one Discord identity/profile API instead of a presence-only plugin API.
