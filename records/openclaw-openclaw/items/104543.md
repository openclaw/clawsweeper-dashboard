## Label Justifications

- `P2`: Current main deterministically limits long Control UI transcripts to one backend page, but the failure is confined to transcript visibility and does not lose stored data.
- `impact:session-state`: The selected session view omits older persisted conversation messages even though the Gateway can return them.
- `impact:ux-friction`: The shallow transcript and loaded-only hidden count can mislead users who are verifying continuity after reconnects or updates.

## Summary

Current main still stops the Control UI transcript at one backend page: the history loader requests 100 messages without an offset, drops the returned cursor metadata, and top scrolling only expands the locally loaded render window. The adjacent session-search issue does not cover this behavior, and no matching fix PR or canonical issue was found, so this remains a valid bounded Control UI bug.

## What This Changes

Add real older-message pagination to the selected Control UI transcript using the existing `chat.history` offset metadata while preserving the viewport and live-message reconciliation.

## Best Possible Solution

Extend the current `ui/src/pages/chat` history/state owner with per-session pagination metadata and a deduplicated older-page loader, wire it to top-scroll or a clear load-older affordance, restore the pre-prepend viewport anchor, and render separate states for locally hidden versus server-unfetched history.
