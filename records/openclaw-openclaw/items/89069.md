## Summary

Current main still keeps childless Codex-native subagent mirrors alive for the documented 30-minute grace, while the issue reports that this window is long enough for a stuck initializing native subagent to exhaust bounded Codex execution capacity; the existing merged fixes are related but do not implement earlier recovery or diagnostics for this failure mode.

## What This Changes

The issue asks for earlier recovery or diagnostics when a childless Codex-native subagent remains stuck initializing and consumes app-server or unified execution capacity before the 30-minute stale-task fallback fires.

## Best Possible Solution

Add maintainer-approved early detection or recovery for quiet childless Codex-native initialization stalls, preferably with status-query or task-audit diagnostics before changing the automatic lost threshold.

Rationale: The current 30-minute policy is intentional and documented, but changing it can prematurely terminalize valid slow native subagents; the source supports the bug impact but does not determine the product-safe cutoff or recovery mechanism.

Options:

- **Add health-based early recovery (recommended):** Use Codex-native status or transcript health signals to warn, audit, or mark only clearly stalled childless mirrors before the 30-minute fallback.
- **Shorten the fixed grace:** Reduce the childless Codex-native grace for all mirrors, accepting the risk that slow-but-valid native subagents may be marked lost earlier.
- **Diagnostics only first:** Keep the 30-minute fallback and add status, audit, and version diagnostics so maintainers can gather live evidence before changing terminalization policy.
