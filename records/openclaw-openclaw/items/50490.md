- `impact:session-state`: The persisted `groupActivation` session state is accepted by the command path but not honored by Feishu admission.
- `impact:message-loss`: The activation gate makes the wrong delivery decision for Feishu group messages, allowing non-mentioned messages through when the session should be mention-only.

## Summary

Keep open. Current main and the latest release still have the Feishu-specific gap: `/activation mention` persists session activation state, but Feishu group admission still gates non-mentioned group messages from config-derived `requireMention`; the linked fixing PR is open and unmerged.

## What This Changes

The issue asks Feishu group chat `/activation mention` to stop admitting non-@ messages after the session activation mode is changed.

## Best Possible Solution

Make Feishu's group admission gate derive `requireMention` from persisted `groupActivation` before the activation ingress check, with config fallback and regression coverage matching sibling channels.
