## Label Justifications

- `P1`: A timing-dependent regression rejects a supported reasoning setting during an ordinary active-chat model-switch workflow.
- `impact:session-state`: Concurrent model and reasoning session mutations can observe inconsistent persisted state.
- `impact:auth-provider`: Reasoning capability validation is performed against the wrong provider/model selection.
- `impact:ux-friction`: Users can see the new model selected yet receive an error naming the previous model, forcing retries or slower interaction.

## Summary

Keep open: the report provides a concrete current-main race, and the source model keeps model and thinking updates as separate session mutations, allowing thinking validation to observe stale model state. The protected `maintainer` label also requires explicit maintainer handling.

## What This Changes

Fix a race where a reasoning-level selection can be validated against the previously selected session model.

## Best Possible Solution

Serialize each session’s model and reasoning mutations through one Gateway-owned ordering boundary, validate reasoning against the post-model state, and make immediate sends wait for all earlier setting mutations.
