## Summary

Keep open: current main and v2026.6.11 still do not implement external-workspace agent config discovery, and the request adds trusted-root, precedence, live-registration, and session/security semantics that need maintainer direction before code work.

## What This Changes

Request to add opt-in automatic discovery of agent configuration files from configured external workspace directories instead of requiring every agent in central `agents.list`.

## Best Possible Solution

Define the zero-restart agent-management and trusted-discovery contract first; if accepted, make discovery opt-in, trusted-root scoped, subordinate to explicit `agents.list`, and routed through canonical config/RPC validation.

## Reproduction Assessment

Yes for the source-level gap: current main and v2026.6.11 only expose explicit `agents.defaults`/`agents.list` config and explicit agent-management RPCs. This is a feature request, not a failing runtime bug.

## Solution Assessment

Unclear pending maintainer direction: a glob scanner is plausible, but it is not yet proven to be the best boundary. The safer path is to decide the zero-restart agent-management, trusted-root, and precedence contract before implementing scanning.
