## Summary

Keep open: current main still only supports explicit agent registration through `agents.list` and `agents.create/update/delete`; trusted external workspace config discovery remains missing and needs product/security direction before implementation.

## What This Changes

Request automatic discovery and loading of agent config files from trusted external workspace directories instead of requiring explicit central `agents.list` registration.

## Best Possible Solution

First choose the product/security boundary; if accepted, specify trusted roots, glob limits, schema validation, explicit-over-discovered precedence, reload behavior, audit/doctor handling, and upgrade tests before implementation.

Options:

- **Keep Explicit Registration (recommended):** Continue using central config, `$include`, and `agents.create/update/delete`, and treat workspace auto-discovery as operator tooling unless a smaller missing API is identified.
- **Design Trusted Discovery:** Approve a core discovery contract only after maintainers define trusted roots, precedence, validation, reload behavior, and security proof.
- **Prioritize Zero-Restart Management:** Defer glob discovery and first design hot-load/hot-remove semantics for explicit agent registration, matching the main pain called out in discussion.
