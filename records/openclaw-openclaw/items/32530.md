## Summary

Keep open: current main and v2026.6.11 still lack external-workspace agent configuration discovery, and the requested scanner would add trusted-root, config, live-registry, session, and security semantics that need maintainer direction.

## What This Changes

Request adds opt-in discovery of agent configuration files from configured external workspace directory globs instead of manually listing each agent in central config.

## Best Possible Solution

Define the opt-in trusted-discovery contract first; if accepted, route discovered records through canonical schema/RPC validation, keep explicit `agents.list` precedence, and require clear security and session-state tests.

Yes for the source-level gap: current main and v2026.6.11 only expose explicit `agents.defaults`/`agents.list` plus explicit agent-management RPCs. This is a feature request, not a failing runtime bug.
