## Summary

Keep open: current main supports explicit `agents.list`, `$include`, and manual `agents.create`/`openclaw agents add`, but it does not implement trusted workspace glob discovery for agent config files. The requested `agents.autoDiscover` shape is a real product/config/security decision, not a cleanup-close candidate.

## What This Changes

The issue requests opt-in auto-discovery and loading of agent configurations from configured external workspace directories.

## Best Possible Solution

First decide the product and trust boundary; if accepted, design an opt-in trusted-directory discovery flow that feeds the canonical agent registry with validation, deterministic precedence, docs, and focused gateway/session tests.
