## Summary

Keep open: current main and v2026.6.11 still only expose explicit agent configuration and registration paths, while external workspace agent-config discovery remains a product/security design question.

## What This Changes

The issue requests automatic discovery and loading of agent configurations from external workspace directories instead of manual central registration.

## Best Possible Solution

Define a trusted agent registration/discovery contract, including security boundary and reload behavior, before implementing any scanner; keep explicit `agents.list`, `agents add`, and agent RPC registration canonical until then.

## Reproduction Assessment

Not applicable as a bug reproduction; source inspection gives high confidence current main supports explicit `agents.list`, `agents add`, agent RPC registration, and bounded include-style config composition, not external workspace agent-config auto-discovery.

## Solution Assessment

Unclear pending maintainer direction; adding a glob scanner is plausible, but the issue has not settled trusted roots, precedence, deletion, reload, and session/auth ownership semantics needed for a best fix.
