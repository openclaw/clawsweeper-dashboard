## Summary

Keep open: current main still has no core `agents.autoDiscover` or workspace agent-config file discovery path, and the request adds config, filesystem trust, routing, and reload semantics that need maintainer product/security direction.

## What This Changes

Request adding `agents.autoDiscover` so OpenClaw can scan trusted workspace directories for agent config files and register agents without manually editing central `agents.list` entries.

## Best Possible Solution

Keep explicit registration as the default unless maintainers design a trusted discovery contract with roots, precedence, validation, reload behavior, and security proof.

Options:

- **Keep Explicit Registration (recommended):** Continue using central config and explicit agent RPCs, and leave workspace scanning to external operator tooling unless a narrower missing API is identified.
- **Design Trusted Discovery:** Define a core `agents.autoDiscover` contract with trusted roots, config schema, precedence, validation, reload semantics, and security tests before implementation.
- **Extend Runtime Registration First:** Prioritize zero-restart `agents.create/update/delete` and binding reload behavior before adding glob-based config discovery.

## Reproduction Assessment

Yes for source-level feature absence: current main derives agents from `agents.list` and explicit `agents.create/update/delete`, and no `agents.autoDiscover` or config-pattern surface exists. This is a feature request rather than a broken existing behavior contract.

## Solution Assessment

No for direct implementation as proposed without product design: glob-based auto-loading is plausible but not clearly the safest boundary. A better path is to decide trusted roots, precedence, validation, and whether explicit runtime registration should be extended first.
