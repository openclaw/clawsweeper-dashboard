## Summary

Keep open: current main and v2026.6.11 still do not implement `agents.autoDiscover` or equivalent workspace-owned agent config loading. The related workspace capability docs issue/PR only covers a narrower docs convention, while this request still needs maintainer product and security design before code work.

## What This Changes

Request to add automatic discovery and loading of agent configurations from trusted external workspace directories instead of requiring every agent in central `agents.list` config.

## Best Possible Solution

Define a maintainer-approved, operator-controlled discovery or import design with trusted roots, deterministic conflict handling, validation failure behavior, and session lifecycle semantics before adding any core config source.

## Reproduction Assessment

Not applicable: this is a new discovery/configuration capability request, not a broken existing behavior report. Source inspection gives high confidence that current main and v2026.6.11 do not implement `agents.autoDiscover` or equivalent external workspace agent config loading.

## Solution Assessment

No: the proposed glob-based merge is not yet the best solution because trust, conflict, validation, persistence, and session lifecycle rules are undefined. The safer current path is explicit agent registration plus hot `agents.list` reload while maintainers decide whether workspace discovery belongs in core.
