## Summary

Keep open: current main supports explicit agent registration and Gateway agent mutation APIs, but it still lacks trusted workspace agent-config auto-discovery; the requested change crosses config authority, security, and session-routing boundaries, so it needs maintainer product and security review rather than cleanup closure.

## What This Changes

Request to add workspace directory scanning so OpenClaw can load agent configurations from external workspaces instead of requiring manual `agents.list` registration.

## Best Possible Solution

Define an operator-controlled discovery or registration model that reuses the existing agent config mutation and reload contracts, or explicitly document manual `agents.create`/`openclaw agents add` as the supported path.

## Reproduction Assessment

Not applicable: this is a feature request, not a broken existing behavior report. Source inspection confirms current main has explicit `agents.list` and manual Gateway agent mutation paths, but no workspace config auto-discovery path.

## Solution Assessment

Unclear: glob-based external config loading might solve the workflow, but it is not clearly the best design until maintainers choose the trust, reload, and ownership model. Any implementation should reuse existing agent config mutation and hot-reload contracts instead of adding request-time directory scanning.
