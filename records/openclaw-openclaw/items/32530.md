## Summary

Keep open: current main still requires explicit configured agents or `agents.create`/CLI writes, and `agents.autoDiscover` would add config, security, and runtime-registration behavior that needs maintainer direction.

## What This Changes

Request automatic discovery and loading of agent configurations from trusted external workspace directories instead of manually adding every agent to `agents.list`.

## Best Possible Solution

Define a maintainer-approved zero-restart agent-management design first, then add any opt-in discovery through the existing config/RPC path with trusted-root validation and explicit-agent precedence.

## Reproduction Assessment

Yes for source-level behavior: current schema only accepts `agents.defaults` and `agents.list`, and current Gateway listing ignores disk-only agents when explicit config exists.

## Solution Assessment

Unclear pending product/security direction; a custom scanner is not automatically the best fix, and the safer path is a maintainer-approved design that reuses `agents.create`/config patch semantics with trusted roots and explicit precedence.
