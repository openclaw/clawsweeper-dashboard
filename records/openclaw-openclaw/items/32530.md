## Summary

Keep open: current main still uses explicit `agents.list`, `openclaw agents add`, and `agents.create/update/delete`; trusted external workspace agent-config discovery is not implemented and needs product/security direction before a fix is queued.

## What This Changes

Request automatic discovery and loading of agent configs from trusted external workspace directories instead of manually registering each agent in central config.

## Best Possible Solution

Keep explicit registration as the default unless maintainers define a trusted discovery contract with allowed roots, file names, precedence, validation, reload behavior, and security proof.

Options:

- **Keep Explicit Registration (recommended):** Continue using `agents.list`, `agents.create/update/delete`, `openclaw agents add`, `$include`, and operator tooling unless a smaller missing API is identified.
- **Design Trusted Discovery:** Approve a bounded core discovery contract that specifies roots, config file names, merge precedence, validation, reload semantics, and security proof before implementation.
- **Narrow To Zero-Restart Management:** Focus on making explicit agent registration hot-load safely before considering automatic glob-based discovery.
