## Summary

Keep open: current main and v2026.6.11 still support explicit `agents.list`, `$include`, Gateway `agents.create/update/delete`, and hot-applied `agents.list` changes, but they do not implement trusted external workspace agent-config discovery. The remaining work is a product and security design decision, not conservative cleanup.

## What This Changes

Request auto-discovery and loading of agent configurations from specified external workspace directories instead of requiring each agent to be manually registered in central config.

## Best Possible Solution

Define an operator-controlled discovery or registration model that reuses schema validation, trusted-root policy, explicit agent mutations, and hot reload semantics; otherwise keep `$include` and `openclaw agents add` as the supported path.
