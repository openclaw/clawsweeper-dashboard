## Summary

Keep open: current main and the latest release still use explicit `agents.list`/`agents.create` registration, while workspace agent auto-discovery would add new config, trust, precedence, and live-registration semantics that need maintainer product and security direction.

## What This Changes

Request to add opt-in discovery of agent configuration files from external workspace directories instead of requiring every agent to be manually registered in central config.

## Best Possible Solution

Define a maintainer-approved zero-restart agent-management design first; if accepted, make discovery opt-in, trusted-root scoped, routed through the canonical config/RPC path, and subordinate to explicit `agents.list` entries.

## Reproduction Assessment

Yes for the source-level gap: current schema only accepts `agents.defaults` and `agents.list`, and current Gateway listing preserves explicit configured scope over disk-only agent directories. This is a feature request rather than a failing runtime bug.

## Solution Assessment

Unclear pending maintainer direction: a glob-based scanner is plausible, but not proven to be the best fix. The safer design is to decide the zero-restart agent-management contract first and then reuse canonical config/RPC mutation with trusted-root validation.
