## Summary

Keep open: current main and the latest release still rely on explicit configured agent entries plus admin mutation APIs, while trusted external workspace agent-config discovery remains missing and needs product/security direction before implementation.

## What This Changes

The issue requests automatic discovery and loading of agent configuration files from configured external workspace directories so multi-project deployments do not need to manually register every agent in central config.

## Best Possible Solution

Decide the trust and product boundary first; if accepted, design a scoped discovery contract with validated roots, precedence, audit/doctor behavior, and live registry semantics before implementation.

Yes, at source level: current main and v2026.6.11 use strict agents.defaults/list config plus explicit agent RPCs, with no agents.autoDiscover, workspace-dir glob, or agent config-pattern scanner. This is a missing feature rather than a failing existing behavior.

## Solution Assessment

Unclear until maintainer direction is confirmed. Direct glob discovery may help multi-project operators, but explicit zero-restart agent registration could solve much of the reported pain with a smaller trust boundary.
