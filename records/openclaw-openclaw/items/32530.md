## Summary

Keep open: current main still lacks external workspace agent-config discovery. Explicit `agents.list`, `agents.create/update/delete`, `$include`, and hot reload cover parts of the management pain, but the requested glob/config-file authority remains a product and security design decision.

## What This Changes

The issue requests automatic discovery and loading of agent configurations from external workspace directories instead of requiring every agent in central config.

## Best Possible Solution

Define a maintainer-approved trust model and runtime lifecycle for external agent config authority, likely extending explicit agent registration/hot-load paths before adding any glob-based scanner.

## Reproduction Assessment

Not applicable; this is a feature request, not a bug report. Source inspection confirms the proposed `agents.autoDiscover`/workspace config-file loading path does not exist on current main.

## Solution Assessment

No; the proposed direct glob scanner is not yet proven to be the best core solution. A safer path is to first settle the authority, trust, migration, and zero-restart lifecycle model around explicit agent registration or a plugin/API seam.
