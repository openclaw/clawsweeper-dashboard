## Summary

Keep open: current main and the latest release still support explicit agent registration through `agents.list`, `openclaw agents add`, and Gateway `agents.create/update/delete`, but they do not define a trusted external-workspace agent-config discovery contract. The remaining work is a product and security decision, not conservative cleanup.

## What This Changes

Request to add `agents.autoDiscover` so OpenClaw can scan trusted workspace directories and load agent config files without manually editing the central config.

## Best Possible Solution

Define a trusted agent registration/discovery contract with explicit security, precedence, deletion, reload, session, auth, and migration semantics; keep explicit `agents.list` and `agents.create` as the canonical path until that direction is accepted.

## Reproduction Assessment

Not applicable as a bug reproduction. Source and release inspection show current main and v2026.6.11 support explicit agent registration and hot config reload, not automatic external workspace agent-config discovery.

## Solution Assessment

Unclear pending maintainer direction. A glob scanner is plausible ergonomically, but the best fix needs a settled trust, precedence, deletion, reload, session, and auth ownership model first.
