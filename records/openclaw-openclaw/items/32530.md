## Summary

Keep open: current main still lacks external workspace agent-config discovery. Existing `agents.list`, `agents.create/update/delete`, `$include`, and hot reload cover pieces of the workflow, but glob-based external config authority remains a product and security decision.

## What This Changes

Add an `agents.autoDiscover` configuration surface that scans trusted workspace directories for agent config files and merges discovered agents without central manual registration.

## Best Possible Solution

Define a maintainer-approved authority, trust, precedence, and lifecycle model first, then implement either explicit hot-load agent registration or a tightly bounded discovery seam with security review.

## Reproduction Assessment

Not applicable; this is a feature request, not a bug report. Source inspection confirms the proposed `agents.autoDiscover` and workspace config-file loading path does not exist on current main.

## Solution Assessment

No; the proposed direct glob scanner is not yet proven to be the best core solution. A safer path is to settle explicit agent hot-load, config authority, trust, and precedence before adding any scanner.
