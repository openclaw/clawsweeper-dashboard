## Summary

Keep open: current main and v2026.6.11 still have explicit agent registration through `agents.list`, CLI, and Gateway RPCs, but no trusted external-workspace agent-config discovery. The remaining blocker is product and security design, not stale cleanup.

## What This Changes

Request to add an `agents.autoDiscover`-style configuration surface that scans workspace directories for agent config files and registers agents without manual central `agents.list` edits.

## Best Possible Solution

Define a trusted agent registration/discovery contract with explicit security, precedence, reload, deletion, session, and auth semantics; keep explicit `agents.list` and `agents.create` canonical until then.

## Reproduction Assessment

Not applicable as a bug reproduction. Source and docs inspection show current main and v2026.6.11 support explicit `agents.list`, explicit agent creation, and config hot reload, not automatic external workspace agent-config discovery.

## Solution Assessment

Unclear pending maintainer direction. A glob scanner is plausible ergonomically, but the best fix needs a settled trust, precedence, deletion, reload, session, and auth ownership model first.
