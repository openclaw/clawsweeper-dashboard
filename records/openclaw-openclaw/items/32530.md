## Summary

Keep open: current main and the latest release still do not implement trusted external workspace agent-config discovery, and the remaining work is a product/security decision rather than a safe cleanup close.

## What This Changes

Request automatic discovery and loading of agent configuration files from configured external workspace directories instead of requiring every agent in central config.

## Best Possible Solution

Maintainers should choose the product/security boundary first; if discovery is accepted, specify trusted roots, glob limits, schema validation, explicit-over-discovered precedence, reload behavior, audit/doctor handling, docs, and upgrade tests.

## Solution Assessment

Unclear until maintainer direction: direct glob discovery may be useful, but explicit zero-restart agent registration could solve the main operational pain with a smaller security boundary.
