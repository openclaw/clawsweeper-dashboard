## Summary

Keep open: current main still lacks trusted workspace agent-config auto-discovery. Existing explicit agent registration, Gateway agent mutation, and hot config reload paths solve part of the operational pain, but making external workspace files a source of agent config crosses config authority, security, and session-routing boundaries.

## What This Changes

Request auto-discovery of agent configuration files from configured external workspace directories instead of manually adding every agent to `agents.list`.

## Best Possible Solution

Define an operator-controlled discovery or registration model that reuses existing config validation and agent mutation/reload contracts, or document explicit agent registration as the supported path.

## Reproduction Assessment

Not applicable: this is a feature request, not broken existing behavior; source inspection confirms current main has explicit `agents.list` and Gateway agent mutation paths but no workspace agent-config auto-discovery.

## Solution Assessment

Unclear: glob-based discovery may solve the workflow, but it is not clearly the best design until maintainers choose trust roots, config authority, precedence, and reload semantics.
