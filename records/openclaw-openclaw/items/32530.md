## Summary

Keep open: current main and v2026.6.11 still accept only explicit `agents.defaults`/`agents.list` agent configuration and have no `agents.autoDiscover` or workspace-owned agent config import path. The related workspace-capability PR is docs-only, and the hot-reload discussion only partially overlaps the requested external workspace agent discovery.

## What This Changes

Request adding `agents.autoDiscover` workspace directory scanning so external workspace agent config files can be loaded without manually registering every agent in central `agents.list`.

## Best Possible Solution

Design an operator-controlled discovery or import path with trusted roots, deterministic validation and conflict precedence, and live agent lifecycle semantics before adding schema, CLI/Gateway behavior, docs, and tests.

## Reproduction Assessment

Not applicable as a bug reproduction, but source inspection gives high confidence the requested capability is absent: current schema, docs, CLI, and Gateway paths consume explicit `agents.list` entries only.

## Solution Assessment

No. The proposed glob-based merge is a plausible direction, but the maintainable solution needs a maintainer-approved trust, precedence, validation, and lifecycle model; existing `agents.list`, `$include`, and `openclaw agents add` cover manual registration only.
