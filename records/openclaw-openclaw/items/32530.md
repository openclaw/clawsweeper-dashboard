## Summary

Keep open: current main and v2026.6.11 still support explicit agent registration through `agents.list`, `openclaw agents add`, and Gateway `agents.create/update/delete`, but there is no trusted external-workspace agent-config discovery contract. This remains a product and security design item, not conservative cleanup.

## What This Changes

The issue requests a new `agents.autoDiscover` configuration surface that scans external workspace directories for agent config files and loads discovered agents with explicit-agent precedence.

## Best Possible Solution

Define a trusted agent registration/discovery contract with explicit security, precedence, reload, deletion, session, and auth semantics; keep explicit `agents.list` and Gateway `agents.create/update/delete` canonical until that design is accepted.

## Reproduction Assessment

Not applicable as a bug reproduction. Source inspection shows current main and v2026.6.11 support explicit `agents.list`, explicit agent creation, and hot application for `agents.list`, not automatic external workspace agent-config discovery.

## Solution Assessment

Unclear pending maintainer direction. A glob scanner is plausible ergonomically, but the best solution must settle trust, precedence, reload, deletion, session, and auth ownership first.
