## Summary

Keep open. Current main has several partial naming and session-lifecycle mechanisms, but not a single settled contract for ACP/native subagent titles, lifetime, and cross-channel persistence; that remaining work needs maintainer product direction rather than conservative cleanup closure.

## What This Changes

The issue requests centralized chat-session naming plus a defined ACP/native subagent lifetime and cross-channel persistence model.

## Best Possible Solution

Define one gateway-owned session metadata and lifecycle contract, then make dashboard, ACP, native subagents, docs, and companion app consumers read the same title, lifetime, and persistence semantics.

- **Policy Doc First:** Write the session naming/lifetime/persistence policy before implementation so later code changes have an explicit owner-approved target.

No live ACP/Copilot reproduction was run, but source inspection shows the current behavior is split across dashboard-only generated titles, derived session-row titles, ACP presentation fallback, and separate lifecycle rules. That is enough to validate the product gap at source level, not enough for a strict bug repro.

## Solution Assessment

No automatic fix is the best path yet. The maintainable solution is to choose a canonical session metadata/lifetime contract first, then implement the aligned code and docs changes against that contract.
