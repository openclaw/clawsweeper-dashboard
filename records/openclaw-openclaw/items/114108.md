## Summary

This remains a plausible P1 auth-routing bug: the documented OpenAI agent route should use Codex subscription authentication for Dashboard embedded turns rather than require an API key. The report is detailed, but the current Dashboard session’s selected runtime, auth profile/order, and relevant configuration are still needed to isolate whether the failure is a route-selection regression or a stale per-session setting.

## What This Changes

Make Dashboard embedded-agent chats use the same authenticated Codex/OpenAI route as successful CLI runs instead of failing with an OpenAI API-key error.

## System Context

Dashboard chat starts an embedded agent run through the Gateway, which resolves a model, runtime, and credentials before invoking the Codex app-server or another agent runtime. A wrong runtime or auth-profile resolution causes the run to fail before a reply is delivered to the chat session.

## Architecture Diagram

  D --> E[Codex auth resolution]

  F --> G[Assistant reply]

## Best Possible Solution

Trace the Dashboard run’s resolved runtime and auth profile, then make new and existing Dashboard sessions select the documented Codex account/profile path before any API-key fallback; add a regression test proving a Codex-authenticated Dashboard chat replies without OPENAI_API_KEY.
