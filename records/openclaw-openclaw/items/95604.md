## Summary

Keep this PR open for repair and owner review. The feature is coherent and well tested in isolation, but the current head introduces a P1 source-message reaction collision: configurable progress cleanup can remove an active acknowledgement or status reaction while the canonical controller still believes that reaction is present. The live evidence is also from an older combined stack rather than the exact reviewed head.

## What This Changes

The PR adds opt-in Discord source-message subagent count and failure reactions, typing keepalive, requester message-id propagation, configurable per-account settings, and persisted terminal cleanup handling.

## Best Possible Solution

Make one serialized Discord source-message lifecycle own acknowledgement, queued/thinking/tool, subagent count, failure, done, and typing states; if maintainers intentionally keep separate trackers, reject every overlapping progress/failure and acknowledgement/status emoji before merge, then prove the exact head in live Discord.
