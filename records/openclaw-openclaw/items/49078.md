## Summary

Keep open. Current main and the latest release still expose cron completion routing as `none`, `announce`, or `webhook` with one primary target plus webhook/failure side paths; deterministic file targets, multi-channel output targets, session injection, and a first-class discard/output contract remain unimplemented and need maintainer API/security direction.

## What This Changes

The issue requests a new cron job output-routing contract so scheduled job results can be deterministically written to files, delivered to channels, injected into sessions, or discarded without relying on prompt compliance.

## Best Possible Solution

Maintainers should design one cron output-routing contract that covers schema/protocol, safe file-write boundaries, channel fan-out, session insertion, partial-failure status, docs, tests, and upgrade behavior before implementation.

## Reproduction Assessment

Not applicable as a strict bug reproduction because this is a feature/config request. The missing contract is source-reproducible: current main and v2026.6.11 expose only `none`, `announce`, and `webhook` delivery with no `output.targets` schema.

## Solution Assessment

No, not as a one-off fix yet. The requested direction is useful, but the best implementation needs a maintainer-approved API and security model rather than adding ad hoc file, channel, and session branches independently.
