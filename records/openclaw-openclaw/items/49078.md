## Summary

Keep open. Current main and v2026.6.11 still only support cron delivery as announce, webhook, or none, while this issue asks for a broader file/channel/session/silent output-target contract that needs maintainer product and security design.

## What This Changes

The issue requests first-class cron output routing targets for files, channels, sessions, and silent/discard behavior instead of relying on prompt-directed routing.

## Best Possible Solution

Define one maintainer-approved cron output-routing contract covering schema/protocol, safe file writes, channel fan-out, session delivery, silent/discard behavior, fallback/status semantics, docs, and focused regression proof.
