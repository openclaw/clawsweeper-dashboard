## Summary

Keep open. Current main and the latest release still expose cron completion delivery as `none`, `announce`, or `webhook`, so the requested file/channel/session/silent output-target contract remains unimplemented and needs maintainer product and security design.

## What This Changes

Request to add a first-class cron `output` config that deterministically routes completed job output to file, channel, session, or silent targets instead of relying on prompt compliance.

## Best Possible Solution

Define one maintainer-approved cron output-routing contract covering schema/protocol, safe file writes, channel fan-out, session delivery, silent/discard behavior, fallback/status semantics, docs, and focused regression proof.
