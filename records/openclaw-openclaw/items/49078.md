## Summary

Keep open. Current main and v2026.6.11 still only expose cron completion delivery as `none`, `announce`, or `webhook`, while this issue asks for a broader first-class output contract covering file writes, channel targets, session injection, silent discard, fallback/status semantics, and safety policy.

## What This Changes

The issue requests deterministic cron job output targets so completed job responses can be routed to files, channels, sessions, or discarded without relying on prompt instructions.

## Best Possible Solution

Design one maintainer-approved cron output-routing contract covering schema/protocol, safe workspace file writes, channel fan-out, session or dispatch delivery, fallback/status semantics, docs, and focused tests.
