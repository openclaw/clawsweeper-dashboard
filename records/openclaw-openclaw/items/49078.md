## Summary

Keep open. Current main and v2026.6.11 still expose the existing single cron `delivery` contract (`none`, `announce`, `webhook`) with webhook/failure extras, but not the requested deterministic `output.targets` contract for file, channel fan-out, session injection, or silent discard routing.

## What This Changes

The issue requests a first-class cron `output.targets` contract for deterministic file, channel, session, and silent routing of completed job output.

## Best Possible Solution

Maintainers should design one cron output-routing contract that covers schema/protocol, safe workspace file writes, channel fan-out, session insertion, partial failure/fallback/status behavior, docs, tests, and upgrade behavior.

Not applicable as a strict bug reproduction. This is a feature/config request, and source, protocol schema, docs, and release inspection show the requested output-routing contract is absent.

## Solution Assessment

Unclear until maintainers choose the API. The requested direction solves a real reliability gap, but a one-off implementation would be risky without explicit security, status, fallback, and ownership semantics.
