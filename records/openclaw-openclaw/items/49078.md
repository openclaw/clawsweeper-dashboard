## Summary

Keep open. Current main and latest release still expose cron completion delivery as `none`, `announce`, or `webhook`; the related merged work improves target-session awareness after existing delivery but does not add the requested deterministic file/channel/session output-target contract.

## What This Changes

Request to add a first-class cron `output.targets` configuration that can route finished job text to files, channels, sessions, or discard it independently of prompt compliance.

## Best Possible Solution

Design one maintainer-approved cron output-routing contract that covers schema/protocol, safe file writes, channel fan-out, internal session delivery, fallback/status semantics, docs, and focused tests before implementation.

## Reproduction Assessment

Not applicable as a strict bug reproduction; this is a feature/config request. Source, protocol, docs, and latest-release inspection give high confidence that the requested output-routing contract is absent.

## Solution Assessment

Unclear until maintainers choose the API and safety boundary. A framework-owned output target layer is plausible, but a one-off implementation would be too risky without path, channel, session, fallback, and status semantics.
