## Summary

Keep open. Current main and the latest release still expose cron output routing through the existing `none`, `announce`, and `webhook` delivery contract; the requested deterministic file/channel/session output target layer is still a product, API, and security design decision.

## What This Changes

The issue requests deterministic cron output targets for files, channels, sessions, and silent runs instead of relying on prompt instructions or the current delivery modes.

## Best Possible Solution

Design one maintainer-approved cron output-routing contract covering schema/protocol, safe file writes, channel fan-out, internal session delivery, fallback/status semantics, docs, and focused tests before implementation.
