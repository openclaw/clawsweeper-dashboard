## Summary

Keep open. Current main and the latest release still only support the existing cron completion delivery contract, while the requested deterministic file/channel/session output target list remains a new public cron API that needs maintainer product and security design.

## What This Changes

The issue requests a new cron job output-routing config that can deterministically route final job results to files, messaging channels, sessions, or discard them without relying on prompt compliance.

## Best Possible Solution

Maintainers should design one cron output-routing contract that covers schema/protocol, safe file writes, channel fan-out, session insertion, silent/discard behavior, partial failure status, docs, and regression proof before implementation.

## Solution Assessment

Unclear as an implementation direction until maintainers choose the permanent API and safety semantics. A broad output target contract is plausible, but it should not be implemented as a narrow automated patch.
