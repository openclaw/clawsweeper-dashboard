## Summary

Keep open. Current main and v2026.6.11 still expose cron completion delivery as `none`, `announce`, or `webhook`; the requested file/channel/session/silent output-target contract remains a product and security design item rather than a cleanup close.

## What This Changes

The issue requests a first-class cron job `output` configuration that can route final job results to files, messaging channels, sessions, or silent discard independently of prompt compliance.

## Best Possible Solution

Design one maintainer-approved cron output-routing contract covering schema/protocol, safe workspace file writes, channel fan-out, session delivery, silent/discard behavior, fallback/status semantics, docs, and focused tests.
