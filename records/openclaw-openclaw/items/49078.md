## Summary

Keep open. Current main and the latest release still expose cron completion delivery as `none`, `announce`, or `webhook`; related merged work improves target-session awareness after delivery but does not add the requested deterministic file/channel/session output-target contract.

## What This Changes

Request to add deterministic cron output targets for files, channels, and sessions so scheduled job results do not depend only on prompt compliance.

## Best Possible Solution

Design one maintainer-approved cron output-routing contract covering schema/protocol, safe file writes, channel fan-out, internal session delivery, fallback/status semantics, docs, and focused tests before implementation.

## Reproduction Assessment

Yes for the missing-feature claim: current main source, protocol schema, docs, and the latest release expose only `none`, `announce`, and `webhook` completion delivery. A live cron run is not needed to prove the requested output-target schema is absent.

## Solution Assessment

Unclear until maintainers choose the API and safety boundary. A framework-owned output target layer is plausible, but the durable solution needs file, channel, session, fallback, and status semantics designed together.
