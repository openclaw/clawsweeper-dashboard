## Summary

Keep open. Current main and v2026.6.11 still expose cron completion delivery as `none`, `announce`, or `webhook`; this issue asks for a broader first-class output contract covering file writes, channel targets, session injection, silent discard, fallback, and status semantics.

## What This Changes

The issue requests a new cron job `output.targets` configuration so scheduled agent results can be deterministically routed to files, channels, sessions, or discarded without relying on prompt compliance.

## Best Possible Solution

Design one maintainer-approved cron output-routing contract covering schema/protocol, safe workspace file writes, channel fan-out, session delivery, fallback/status semantics, docs, and focused regression proof.
