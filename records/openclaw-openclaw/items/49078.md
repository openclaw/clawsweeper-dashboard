## Summary

Keep open. Current main and the latest release still expose cron completion delivery as `none`, `announce`, or `webhook`; the requested file/channel/session/silent output-target contract remains a broader product and security design item rather than a cleanup close.

## What This Changes

The issue requests first-class cron job output targets so completed job results can be deterministically routed to files, channels, sessions, or discarded without relying on prompt instructions.

## Best Possible Solution

Design one maintainer-approved cron output-routing contract covering schema/protocol, safe workspace file writes, channel fan-out, session delivery, silent/discard behavior, fallback/status semantics, docs, and focused tests.
