## Summary

Keep this PR open for human maintainer review. The final patch has a concrete compatibility regression: a legacy Matrix-local `--profile` argument is no longer rejected or handled locally, so the root CLI parser consumes it as a global state profile and the Matrix runner proceeds with the new implicit full selection; a prior focused Matrix command can therefore become a much broader run without a clear migration error.

## What This Changes

This PR removes QA scenario `execution.profiles` metadata and Matrix named profiles, deriving Matrix and smoke scenario sets from catalog and taxonomy eligibility before internally sharding CI execution.

## System Context

QA Lab converts scenario catalog facts and taxonomy coverage into local transport runs and CI smoke checks. Matrix and smoke runners select eligible scenarios first, then workflows split the selected set into deterministic execution shards and publish QA evidence.

## Architecture Diagram

flowchart LR
  A[Scenario catalog] --> B[Taxonomy coverage]
  B --> C[QA scenario selection]
  C --> D[Matrix and smoke runners]
  D --> E[Internal CI shards]
  E --> F[QA reports and release checks]

## Best Possible Solution

Keep taxonomy and catalog ownership for selection, but make legacy Matrix-local profile usage fail clearly with a migration message to plain `qa matrix` or repeated `--scenario`; preserve documented global root-profile behavior without allowing the ambiguous trailing legacy form to trigger a broad Matrix run.
