## Summary

Keep open: current main and v2026.6.11 still force `dirty_watched_tree` before the mtime freshness path, and neither the closed same-repo PR nor the open conflicting fork PR has landed a fix.

## What This Changes

The issue requests that dirty watched source trees fall through to build-stamp mtime freshness instead of forcing a full gateway watch rebuild on every startup.

## Best Possible Solution

Keep a canonical issue open until the run-node build requirement uses mtime freshness for dirty-but-already-built watched trees while preserving rebuilds for newer sources, changed HEAD, missing dist, and missing bundled plugin outputs.

Yes. Source inspection shows a dirty watched tree returns `dirty_watched_tree` before source mtime freshness can be evaluated; I did not run the mutable `pnpm gateway:watch` repro because this review must keep the checkout read-only.
