## Summary

The hardening remains necessary because current main and v2026.6.11 retain the unbounded read, but this patch creates an undocumented 1 MiB whole-file compatibility limit that needs an explicit hook-format decision before merge.

## What This Changes

The PR replaces an unbounded HOOK.md read during hook installation with the shared bounded regular-file reader and adds an oversized-file regression test.

## Best Possible Solution

Define one shared hook-metadata policy: preferably parse a race-safe bounded leading frontmatter block while preserving the documentation body, or explicitly document and consistently enforce a maintainer-approved whole-file limit across install and workspace discovery.
