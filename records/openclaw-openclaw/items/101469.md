It should remain open for a hook-area owner to confirm the compatibility-sensitive metadata contract because the helper also rejects symlinked and multiply linked files, not only files over 1 MiB.

The PR replaces install-time `HOOK.md` reads with a 1 MiB bounded fs-safe regular-file read and adds oversized-file regression coverage.

## Best Possible Solution

Adopt one explicit bounded hook-metadata contract across installation and workspace discovery, using fs-safe if hook metadata must be a stable single-linked regular file and adding focused coverage for every intentionally rejected shape.
