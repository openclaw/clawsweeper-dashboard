## Summary

Keep open. Current `origin/main` and the latest release still expose only `daily` and `idle` reset modes, the same-mode implementation PRs are closed unmerged, and this issue remains the clearest canonical tracker for a manual-only session reset mode.

## What This Changes

Request an explicit manual-only session reset mode, proposed as `mode: "never"`, for base, type, and channel reset policies.

## Best Possible Solution

Choose one canonical manual-only reset mode, then update schema, exported types, generated config metadata/help, runtime policy, docs, and focused reset-policy tests while preserving existing daily, idle, `/new`, and `/reset` behavior.
