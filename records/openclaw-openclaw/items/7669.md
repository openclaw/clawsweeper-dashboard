## Summary

Keep open: current main still documents an optional npm `dev` channel, but the public release workflows, publish helper, and release-plan contract only implement alpha/beta/latest publishing, and the live npm registry still has no `dev` dist-tag.

## What This Changes

The issue requests re-enabling an npm `dev` dist-tag for moving main-branch OpenClaw builds and adding release verification and docs alignment for that channel.

## Best Possible Solution

Maintainers should either approve and design a secured first-class npm `dev` snapshot channel, or deliberately retire npm `dev` from public release-channel docs and keep dev installs git-based.

## Reproduction Assessment

Yes. Current source lacks a `dev` workflow choice or publish plan, the latest release has the same gap, and live npm returns E404 for `openclaw@dev`.

## Solution Assessment

Unclear. Re-enabling npm `dev` snapshots may solve the reported workflow, but the best path depends on release/security policy; retiring the npm `dev` doc claim is the safer alternative if moving-main publishing is not desired.
