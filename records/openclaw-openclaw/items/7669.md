## Summary

Keep open: current main, the latest shipped release, and the live npm registry still do not provide an npm `dev` dist-tag publish path, and the remaining decision is release/security policy rather than conservative cleanup.

## What This Changes

The issue asks to re-enable an npm `dev` dist-tag for moving main-branch OpenClaw builds and align CI verification and docs with that channel.

## Best Possible Solution

Maintainers should either design a first-class, provenance-safe npm `dev` snapshot channel for moving `main`, or explicitly retire the npm `dev` wording and document dev as git-only.

## Reproduction Assessment

Yes: current source lacks a `dev` dist-tag workflow/publish boundary, and the live npm registry has no `openclaw@dev` selector. This is source-reproducible rather than a broken existing code path with a local failing test.

## Solution Assessment

No autonomous fix is best yet; re-enabling npm `dev` snapshots is plausible, but maintainers must first choose the secure release policy. The safer alternative may be to document dev as git-only and remove the optional npm wording.
