## Summary

Keep open for a release-manager decision. Current main and the live npm registry still do not provide the documented npm `dev` tag, but OpenClaw now has a first-class npm `alpha` release path and directs persistent moving-main development installs through git, so restoring `dev` is a compatibility and release-security choice rather than a mechanical CI repair.

## What This Changes

Restore and verify an npm `dev` snapshot channel for moving `main`, or align the documented development-channel contract with the supported npm-alpha and git-dev paths.

## Best Possible Solution

Adopt one explicit development-distribution contract—preferably moving-main `dev` through git and npm prereleases through `alpha`—then align release workflows, version rules, updater behavior, registry verification, FAQ, installation docs, CI docs, and release guidance; add a `dev` alias only if release managers intentionally approve and document its compatibility lifecycle.
