## Summary

Keep open: current main still lacks a first-class npm `dev` dist-tag publish path, the latest shipped release lacks it too, and the live npm registry exposes `alpha`, `beta`, and `latest` but no `dev`.

## What This Changes

The issue requests restoring a first-class npm `dev` dist-tag publication path for moving `main` builds and verifying that docs match the release pipeline.

## Best Possible Solution

Maintain the current git-based dev channel and either design a security-reviewed npm dev snapshot pipeline with workflow support, versioning rules, tests, registry readback, and docs, or explicitly retire the npm dev tag from public docs.

## Reproduction Assessment

Yes. Current source lacks a `dev` publish choice or publish-plan contract, and the live npm registry has no `openclaw@dev` dist-tag.

## Solution Assessment

No, not as a simple re-enable. The maintainable path needs a release/security decision first, then either a complete npm dev snapshot pipeline or docs that clearly retire npm dev snapshots.
