## Summary

Keep open: current main and the latest shipped release still lack a first-class npm `dev` dist-tag publish path, while the public release-channel docs still mention optional npm `dev` snapshots and the live npm registry has no `dev` tag.

## What This Changes

The issue requests re-enabling an npm `dev` dist-tag for moving main-branch OpenClaw releases and adding release verification and docs alignment.

## Best Possible Solution

Maintainers should either approve and design a secure first-class npm `dev` snapshot channel, or deliberately retire npm `dev` from release-channel docs and keep dev installs git-only.

## Reproduction Assessment

Yes. Source inspection shows no `dev` workflow choice or publish plan, the latest release has the same gap, and the live npm registry returns E404 for `openclaw@dev`.

## Solution Assessment

Unclear. Re-enabling npm `dev` snapshots may solve the reported workflow, but the best implementation depends on maintainer release/security policy; explicitly retiring npm `dev` from docs is the safer alternative if maintainers do not want moving-main package publishing.
