## Summary

Keep open for a maintainer product decision. The supplied current-main review evidence still shows transcript-level scrolling rather than a bounded, independently scrollable body for native large/tall bubbles; making every such bubble scrollable is a distinct mobile interaction contract, not an established regression fix.

## What This Changes

The issue requests that all native chat bubbles treated as large use a scrollable body, rather than enabling inner scrolling only when a truncation threshold is reached.

## Best Possible Solution

Choose one native long-content policy, then implement a bounded message-body reader consistently in the SwiftUI and Android chat surfaces while preserving transcript scrolling and validating tall-but-untruncated, truncated, streaming, and accessibility cases on real mobile devices.

- **Decline nested scrolling:** Retain the existing transcript-level interaction model and close the request only after documenting why a per-bubble reader is not desired.
