## Summary

Keep open. Current main and the latest release still provide transcript-level native chat scrolling, but completed and streaming bubble bodies are plain SwiftUI/Compose stacks without a bounded inner body scroll; the merged native reader-scroll PR is adjacent transcript behavior, not this per-bubble request.

## What This Changes

The issue requests that all large native chat bubbles wrap their body content in a scroll view regardless of whether truncation is triggered.

## Best Possible Solution

Define the current native tall-bubble rule, then implement one bounded body-reading behavior for completed and streaming bubbles across SwiftUI and Android while preserving transcript scrolling, text selection, accessibility, and streaming layout.

## Reproduction Assessment

No high-confidence live reproduction was established. Source inspection on current main shows native completed and streaming bubble bodies lack bounded inner scroll containers, but the old `.large` rule and mobile gesture behavior still need device-level confirmation.

## Solution Assessment

Unclear as specified. Always-on inner scrolling is plausible, but maintainers should choose the current iOS/Android interaction model first because nested scrolling can affect transcript scroll, selection, accessibility, and streaming layout.
