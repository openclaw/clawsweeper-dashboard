## Summary

Keep open. Current main still has transcript-level scrolling in native chat, but completed and streaming bubble bodies are plain SwiftUI/Compose stacks without a bounded per-bubble body scroll area, and the merged native reader-managed scrolling PR did not implement this specific behavior.

## What This Changes

Requests native `.large` chat bubbles to always wrap body content in a scrollable body area rather than only when truncation triggers.

## Best Possible Solution

Define a cross-native tall-bubble body-reader rule, then implement bounded body reading for completed and streaming bubbles across SwiftUI and Android with device/emulator proof for transcript scrolling, selection, accessibility, and streaming layout.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should native chat adopt always-on bounded inner body scrolling for large/tall bubbles, or should long content use a different reader affordance?

Rationale: Source inspection shows the requested behavior is still missing, but the permanent UX affects nested gestures, transcript scrolling, selection, accessibility, and streaming layout, so automation should not choose the interaction model alone.

Likely owner: steipete

Owner reason: steipete already reviewed this issue and handled the adjacent native reader-managed scrolling merge, making him the best available routing owner for the product choice.

Owner confidence: high

Options:

- **Adopt Bounded Inner Body Scroll (recommended):** Define the current tall-bubble rule and implement bounded body scrolling consistently in iOS and Android native chat, with live proof for nested gestures and accessibility.
- **Use A Reader Affordance Instead:** Avoid always-on nested scrolling and provide a separate full-message reader or expansion surface for tall native content.
- **Defer Native Body Reader:** Keep transcript-level scrolling only until maintainers decide the nested-scroll complexity is worth the UX change.

## Reproduction Assessment

No high-confidence live reproduction was established. Source inspection on current main shows native bubble bodies lack bounded inner scroll containers, but the old `.large` terminology and mobile gesture behavior still need device-level confirmation.

## Solution Assessment

Unclear as specified. Always-on inner scrolling is plausible, but maintainers should choose the current iOS/Android interaction model first because nested scrolling can affect transcript scroll, selection, accessibility, and streaming layout.
