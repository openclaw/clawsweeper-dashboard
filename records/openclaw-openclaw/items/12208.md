## Summary

Keep open. Current main still provides native transcript/list scrolling, but completed and streaming bubble bodies remain plain SwiftUI/Compose stacks without a bounded per-bubble body scroll area; the merged reader-managed scrolling PR is adjacent rather than a fix for this request.

## What This Changes

The issue asks for every large or tall native chat bubble body to be scrollable, even when it does not cross the truncation threshold.

## Best Possible Solution

Define a cross-native tall-bubble body-reader rule, then implement bounded body reading for completed and streaming bubbles across SwiftUI and Android with live device or emulator proof for transcript scrolling, selection, accessibility, and streaming layout.

- **Adopt Bounded Inner Body Scroll (recommended):** Define the current tall-bubble rule and implement bounded body scrolling consistently in iOS and Android native chat, with live proof for nested gestures and accessibility.
- **Use A Reader Affordance:** Avoid always-on nested scrolling and provide a separate full-message reader or expansion surface for tall native content.
- **Defer Native Body Reader:** Keep transcript-level scrolling only until maintainers decide the nested-scroll complexity is worth the UX change.
