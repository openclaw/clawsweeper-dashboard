## Summary

Keep open. Current main still lacks a bounded per-bubble body scroll container in native chat; the merged reader-managed scrolling work controls transcript position rather than the individual large-bubble body behavior requested.

## What This Changes

The issue requests that every large native chat bubble wrap its body content in a scrollable area even when content has not crossed the truncation threshold.

## Best Possible Solution

Define a cross-platform large/tall-bubble body-reader rule, then implement bounded body reading for completed and streaming native bubbles across SwiftUI and Android with live mobile proof for nested gestures, selection, accessibility, and streaming layout.

Rationale: Source inspection shows the requested behavior is still missing, but the permanent UX affects nested gestures, transcript scrolling, selection, accessibility, and streaming layout, so automation should not choose the interaction model alone.

Options:

- **Adopt Bounded Inner Body Scroll (recommended):** Define the current tall-bubble rule and implement bounded body scrolling consistently in iOS and Android native chat, with live proof for nested gestures and accessibility.
- **Use A Reader Affordance:** Avoid always-on nested scrolling and provide a separate full-message reader or expansion surface for tall native content.
- **Defer Native Body Reader:** Keep transcript-level scrolling only until maintainers decide the nested-scroll complexity is worth the UX change.
