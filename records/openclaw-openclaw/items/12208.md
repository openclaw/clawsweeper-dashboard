## Summary

Keep open for a maintainer product decision. The latest supplied current-main review evidence still shows transcript-level scrolling rather than a bounded, independently scrollable body for native iOS and Android chat bubbles; making every large/tall bubble scrollable changes the mobile reading and gesture contract rather than repairing an established regression.

## What This Changes

The issue requests that all large native chat bubbles provide an independently scrollable body even when their content has not crossed a truncation threshold.

## System Context

OpenClaw’s native iOS and Android chat views render live and historical assistant, tool, attachment, and markdown content inside message bubbles. Those bubbles are then placed in a scrollable conversation transcript, so a per-bubble scroll container would add a second scrolling surface within the mobile chat experience.

## Architecture Diagram

flowchart TD
  A[Assistant and tool content] --> B[Native message body]
  B --> C[Chat bubble]
  C --> D{Large or tall content rule}
  D --> E[Bounded bubble body scroll]
  C --> F[Conversation transcript list]
  E --> F
  F --> G[iOS and Android chat interaction]

## Best Possible Solution

Define one native long-content interaction policy for iOS and Android, including the bounded height, accessibility behavior, and when nested scrolling is enabled; implement it in both message-body renderers while retaining transcript-level scrolling, then validate tall-but-untruncated content on real mobile devices.

- **Use truncation-driven scrolling:** Keep inner scrolling only after a clearly documented truncation or height threshold, rather than applying it to every large bubble.
