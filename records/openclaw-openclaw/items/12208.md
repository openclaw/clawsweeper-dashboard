## Summary

Keep open. Current main still has transcript-level native chat scrolling, but completed and streaming bubble bodies are rendered as plain SwiftUI or Compose stacks without a bounded inner body scroll; the merged native reader-managed scrolling PR is adjacent list-position behavior, not this per-bubble body request.

## What This Changes

The issue asks native large/tall chat bubbles to make their body area scrollable even when content does not cross the old truncation threshold.

## Best Possible Solution

Define the current native tall-bubble rule, then implement one bounded body-reading behavior for completed and streaming bubbles across SwiftUI and Android while preserving transcript scrolling, selection, accessibility, and streaming layout.

## Reproduction Assessment

No high-confidence live device reproduction was established. Source inspection on current main shows native completed and streaming bubble bodies lack bounded inner scroll containers, but the old `.large` terminology and mobile gesture behavior still need device-level confirmation.

## Solution Assessment

Unclear as specified. Always-on inner scrolling is plausible, but maintainers should first choose the current iOS/Android tall-bubble interaction model because nested scrolling can affect transcript scroll, selection, accessibility, and streaming layout.
