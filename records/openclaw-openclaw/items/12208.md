## Summary

Keep open for product direction. The latest shipped work improves transcript-reader scroll stability, but it does not establish the requested per-message body scrolling policy, and the related WebChat reader implementation explicitly left inline bubble sizing unchanged.

## What This Changes

Request that every native chat bubble classified as large use a bounded, independently scrollable message-body area even when truncation has not triggered.

## Best Possible Solution

Define one shared native long-message interaction—preferably an explicit full-message reader with a bounded viewport over always-nested scrolling—then implement consistent iOS and Android behavior with device proof for tall, truncated, streaming, attachment, and tool-result messages.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should tall native messages open an explicit full-message reader, use an independently scrollable body inside every large bubble, or retain transcript-only scrolling?

Rationale: Each option changes touch gestures, accessibility, selection, and scroll anchoring across iOS and Android; source inspection cannot determine the intended interaction model.

Likely owner: steipete

Owner reason: They already provided product-level review on this exact issue and are the strongest available routing candidate for the cross-platform interaction choice.

Owner confidence: medium

Options:

- **Use Explicit Reader (recommended):** Open tall messages in a dedicated bounded reader while keeping the transcript's gesture and anchoring model simple.
- **Use Nested Body Scroll:** Make every large bubble body independently scrollable and accept the additional nested-gesture and accessibility complexity.
- **Keep Transcript Scrolling:** Retain current transcript-only scrolling and close this request as not planned.

## Reproduction Assessment

No high-confidence live reproduction is available. Static and release evidence distinguishes transcript-reader scrolling from the requested per-bubble body behavior, but current iOS and Android device proof is still needed.

## Solution Assessment

No, always enabling nested body scrolling is not yet proven to be the best solution. An explicit reader modeled on the WebChat approach likely avoids gesture and accessibility conflicts, but maintainers must choose the native interaction first.
