## Summary

Keep open. Current main still lacks a bounded per-bubble body scroll path for native mobile chat, and the closed WebChat full-message reader is adjacent browser/Gateway work rather than an iPhone/Android bubble interaction fix.

## What This Changes

The issue requests that every native `.large` chat bubble body use an inner scroll container, even when content has not crossed the existing truncation threshold.

## Best Possible Solution

Define the current native tall-bubble rule, then implement one bounded body-reader behavior for completed and streaming iOS/Android bubbles while preserving transcript scrolling, text selection, accessibility, and streaming layout.

## Reproduction Assessment

No high-confidence live reproduction was established. Source inspection on current main shows native bubble bodies are plain SwiftUI/Compose containers with transcript-level scrolling only, but device gesture behavior and the current tall-bubble rule still need confirmation.

## Solution Assessment

Unclear as specified. Always-on inner scrolling is plausible, but maintainers should choose the current iOS/Android nested-scroll, selection, accessibility, and streaming behavior before implementation.
