## Summary

Keep open. Current main and the latest release still render native mobile chat bubble bodies as ordinary SwiftUI/Compose content inside transcript-level scroll containers; the merged WebChat reader and native transcript reader-managed scroll work are adjacent, but they do not implement an always-scrollable bounded body area for large native bubbles.

## What This Changes

The issue requests always-scrollable body content for large native chat bubbles instead of only enabling body scrolling when truncation is detected.

## Best Possible Solution

Define the native tall-bubble reader interaction, then implement one bounded body-reading behavior for completed and streaming bubbles across SwiftUI and Android while preserving transcript scrolling, selection, accessibility, and streaming layout.

## Reproduction Assessment

No high-confidence live reproduction was established. Source inspection on current main shows native completed and streaming bubble bodies lack bounded inner scroll containers, but the mobile gesture behavior needs device-level confirmation.

## Solution Assessment

Unclear as specified. Always-on inner body scrolling is plausible, but maintainers should first choose the current iOS/Android tall-bubble interaction because nested scrolling can affect transcript scroll, selection, accessibility, and streaming layout.
