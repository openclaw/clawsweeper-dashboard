## Summary

Keep open. Current main and v2026.6.11 still render native completed and streaming chat bubble bodies as plain SwiftUI/Compose stacks with only transcript-level scrolling; the merged WebChat reader and native reader-managed transcript scrolling work are adjacent, not implementations of per-bubble body scrolling.

## What This Changes

Request that every large/tall native chat bubble wrap its body content in an inner scroll container, even when the message has not crossed a truncation threshold.

## Best Possible Solution

Define the current native tall-bubble rule, then implement one bounded body-reading behavior for completed and streaming bubbles across SwiftUI and Android while preserving transcript scrolling, text selection, accessibility, and streaming layout.

## Reproduction Assessment

No high-confidence live device reproduction was established. Source inspection on current main shows native bubble bodies lack bounded inner scroll containers, but the old .large terminology and mobile gesture behavior still need device-level confirmation.

## Solution Assessment

Unclear as specified. Always-on inner scrolling is plausible, but maintainers should choose the current iOS/Android interaction model before implementation because nested scrolling can affect transcript scroll, selection, accessibility, and streaming layout.
