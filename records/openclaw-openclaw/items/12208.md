## Summary

Keep open for a maintainer product decision. Current native work preserves the reader’s transcript position and provides a return-to-latest control, but it does not define or implement nested scrolling for every large message body; the latest release describes the same transcript-level behavior. ([docs.openclaw.ai](https://docs.openclaw.ai/releases/2026.7.1?utm_source=openai))

## What This Changes

Make every native chat bubble classified as large use a bounded scrollable body even when its content does not cross the truncation threshold.

## Best Possible Solution

Preserve one shared iOS/Android interaction contract: prefer the reader-managed transcript plus an explicit bounded full-message reader for tall content, unless live device comparison shows nested bubble scrolling is clearly more usable and accessible.

## Maintainer Decision

Required: true

Kind: product_direction

Question: After the reader-managed transcript scrolling work, should large native message bodies gain nested bounded scrolling, or should tall content open through a separate full-message reader?

Rationale: Both choices are implementable but define different gesture, accessibility, streaming, and cross-platform UX contracts that cannot be selected from static source evidence alone.

Likely owner: steipete

Owner reason: This account previously reviewed the issue and is the strongest available owner for choosing the intended native interaction.

Owner confidence: medium

Options:

- **Use Explicit Reader (recommended):** Keep transcript scrolling reader-managed and provide a bounded full-message reader for tall content, avoiding nested-scroll gesture competition.
- **Scroll Large Bodies:** Give every large bubble a bounded inner scroller and require matching device proof for gestures, accessibility, and streaming on iOS and Android.

## Reproduction Assessment

No, there is not yet a high-confidence current-device reproduction. Source and prior current-main review establish that the requested always-scrollable body policy is absent, but they do not demonstrate the present interaction problem after the latest transcript-scrolling changes.

## Solution Assessment

No, unconditional nested scrolling is not yet proven to be the best solution. A separate bounded reader better preserves the recently shipped reader-managed transcript model unless cross-platform device proof favors nested scrolling.
