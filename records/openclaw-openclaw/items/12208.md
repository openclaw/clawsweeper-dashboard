## Summary

Keep open. Current main and the latest release still provide native transcript/list scrolling, but completed and streaming bubble bodies render as unbounded SwiftUI/Compose stacks rather than a bounded per-bubble body scroll; the merged native reader-scroll PR is adjacent transcript behavior, not this inner bubble request.

## What This Changes

Request that native large chat bubbles always use a scrollable body area, even when content has not crossed a truncation threshold.

## Best Possible Solution

Define the current native tall-bubble rule, then implement one bounded body-reading behavior for completed and streaming bubbles across SwiftUI and Android while preserving transcript scrolling, selection, accessibility, and streaming layout.

## Reproduction Assessment

No high-confidence live reproduction was established. Source inspection on current main shows native bubble bodies lack bounded inner scroll containers, but the old `.large` terminology and mobile gesture behavior still need device-level confirmation.

## Solution Assessment

Unclear as specified. Always-on inner scrolling is plausible, but maintainers should choose the current iOS/Android interaction model first because nested scrolling can affect transcript scroll, selection, accessibility, and streaming layout.
