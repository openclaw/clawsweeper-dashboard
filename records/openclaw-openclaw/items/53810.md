## Summary

Keep open: current main has adjacent text-tool-call repair, but the reported Qwen/ModelStudio/Kimi-style markers are still non-executable when they live only in thinking/reasoning content, and a fix needs live provider proof plus maintainer security/product direction before reasoning text is promoted into tool calls.

## What This Changes

The issue asks OpenClaw to normalize provider/model-specific tagged tool-call text emitted inside thinking blocks so subagent runs do not announce success before intended tools execute.

## Best Possible Solution

Add provider-owned Qwen/ModelStudio normalization, or a narrow shared helper if maintainers approve the boundary, that promotes only validated standalone tagged tool-call sections for allowed tools before stop-reason and announce logic, with live provider proof.

## Reproduction Assessment

No high-confidence live reproduction is available. Source inspection shows current main still leaves thinking-only tagged marker text non-executable; replay against affected ModelStudio models is still missing.

## Solution Assessment

Unclear until maintainers choose the security boundary. Delaying announce alone is not the best fix; narrowly canonicalizing validated provider-owned markers before announce/tool dispatch is the maintainable path if live proof confirms the behavior.
