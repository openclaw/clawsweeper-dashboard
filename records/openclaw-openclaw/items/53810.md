## Summary

Keep open: current main still leaves the reported Qwen/ModelStudio-style tagged tool calls non-executable when the markers live entirely inside thinking content, and the linked PRs are adjacent rather than a fix for this provider/runtime boundary.

## What This Changes

The issue asks OpenClaw to prevent premature subagent completion announces by normalizing model-specific tagged tool-call markers emitted inside thinking/reasoning content for affected OpenAI-compatible providers.

## Best Possible Solution

Add provider-owned Qwen/ModelStudio normalization, or a narrow shared OpenAI-compatible helper, that promotes only validated standalone tagged tool-call sections before stop-reason and announce logic, with live provider proof and allowed-tool gating.

## Reproduction Assessment

No high-confidence live reproduction is available. Source inspection shows current Qwen/ModelStudio and generic promotion paths still leave tagged tool-call markers inside thinking blocks non-executable.

## Solution Assessment

Unclear until maintainers choose the security boundary. Delaying announce alone is not the best fix; narrowly canonicalizing validated provider-owned markers before announce is the maintainable path if live proof confirms the behavior.
