## Summary

Keep open: current main still does not promote tagged tool-call markers that live only inside thinking/reasoning content, and the remaining fix needs live provider proof plus a maintainer-approved security boundary before reasoning text can become executable tool calls.

## What This Changes

The issue asks OpenClaw to avoid prematurely announcing subagent completion when Qwen/ModelStudio/Kimi-style providers emit tool-call markers only inside thinking content instead of structured tool-call blocks.

## Best Possible Solution

Add provider-owned Qwen/ModelStudio normalization, or a narrowly gated shared OpenAI-compatible helper, that promotes only validated standalone tagged tool-call sections for allowed tools before stop-reason and announce logic, with live provider proof.

## Reproduction Assessment

No high-confidence live reproduction is available. Source inspection shows current main leaves marker text inside thinking blocks non-executable, but the reported provider/model behavior has not been replayed against current main.

## Solution Assessment

Unclear until maintainers choose the security boundary. Delaying announce alone is not the best fix; narrowly canonicalizing validated provider-owned markers before announce is the maintainable path if live proof confirms the behavior.
