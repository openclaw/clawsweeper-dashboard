## Summary

Keep open: current main partially handles Kimi tagged tool calls in text blocks and has generic text promotion, but the reported marker-inside-thinking path for Qwen/ModelStudio-style providers remains unnormalized and still needs live provider proof plus a security/product decision before reasoning text can become executable tool calls.

## What This Changes

The issue asks OpenClaw to avoid premature successful subagent announcements by handling provider/model-specific tagged tool calls emitted inside thinking content for Alibaba/Qwen/Kimi/MiniMax-style endpoints.

## Best Possible Solution

Add provider-owned Qwen/ModelStudio normalization, or a narrow shared helper, that promotes only validated standalone tagged tool-call sections from thinking/reasoning content for allowed tools, with focused tests and live provider proof.

## Reproduction Assessment

No high-confidence live reproduction is available. Source inspection shows current main leaves tagged tool calls inside thinking content non-executable on the Qwen/OpenAI-compatible path, but the affected provider/model behavior has not been replayed live.

## Solution Assessment

Unclear until maintainers choose the security boundary. Delaying announce alone is not the best fix; if live proof confirms the behavior, the maintainable path is narrow provider-owned or shared normalization before terminal-state and announce logic.
