## Summary

Keep open: current main and the latest release still only promote tagged Kimi tool-call markers from text content, while the report is about provider/model output where executable-looking markers live inside thinking content and the assistant turn finishes as `stop`. A fix still needs live provider reproduction plus an explicit security/product decision before OpenClaw promotes reasoning text into executable tool calls.

## What This Changes

The issue reports provider-specific subagent failures where Kimi/MiniMax/ModelStudio-style tool-call markers inside thinking blocks are not normalized into structured tool calls, causing premature completion delivery and missing work.

## Best Possible Solution

Keep the issue open for a provider-owned normalization design that is backed by live endpoint proof, allowed-tool validation, and security review before any thinking-block content is promoted into executable tool calls.

## Reproduction Assessment

No high-confidence live reproduction is present for current main; source inspection does show that thinking-only tagged markers are not promoted because both the Kimi wrapper and shared repair path operate on text candidates.

## Solution Assessment

Unclear: parsing these markers is plausible, but the best fix needs maintainer product/security direction because turning thinking content into executable tool calls is more sensitive than normal text-block repair.
