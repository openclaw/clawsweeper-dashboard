## Summary

Keep open: current main still has adjacent parser support for tagged Kimi tool-call text, but the reported Qwen/ModelStudio-style markers inside thinking content are not normalized into executable tool calls, and a fix needs live provider proof plus maintainer product/security direction before executing tool calls parsed from reasoning text.

## What This Changes

The issue asks OpenClaw to stop announcing subagents as complete when affected models emit non-standard tagged tool-call markers inside thinking content instead of structured tool-call blocks.

## Best Possible Solution

Add a provider-owned, security-reviewed normalization path only after live Qwen/ModelStudio/Kimi/MiniMax repro proves the exact marker formats and the implementation can reject unsafe reasoning text while preserving current structured tool-call behavior.

## Reproduction Assessment

Yes from source inspection, but not from a fresh live run: current main has reachable Qwen/ModelStudio model paths and does not normalize the reported thinking-contained marker format into structured tool calls. The missing piece is live provider proof for the affected endpoint/model combinations.

## Solution Assessment

Unclear: parsing provider-specific markers is plausible, but the best fix must be provider-owned and security-reviewed before OpenClaw executes tool calls recovered from reasoning/thinking text.
