## Summary

Keep open: current main and v2026.6.11 still do not promote Qwen/ModelStudio-style tagged tool-call markers when they live only inside thinking content, and a fix needs live provider proof plus a maintainer security/product decision before reasoning text becomes executable tool calls.

## What This Changes

The issue reports subagents announcing completion before affected provider models' tagged tool-call markers inside thinking content are normalized and executed.

## Best Possible Solution

Add provider-owned Qwen/ModelStudio normalization, or a narrow shared OpenAI-compatible helper, that promotes only validated standalone tagged tool-call sections before stop-reason and announce logic after live provider proof and allowed-tool gating.

## Reproduction Assessment

No high-confidence live reproduction is available from this review. Source inspection shows the current Qwen/ModelStudio path still leaves tagged tool-call markers in thinking content non-executable, matching the reported failure shape.

## Solution Assessment

Unclear until maintainers choose the security boundary. Delaying announce alone is not the best fix; validated provider-owned marker normalization before stop-reason handling is the maintainable path if live proof confirms the behavior.
