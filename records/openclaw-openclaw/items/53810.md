## Summary

Keep open: current main still supports some standalone text tool-call repair and Kimi text-block marker parsing, but the reported Qwen/ModelStudio-style markers inside thinking/reasoning content are still not promoted to executable tool calls. The remaining decision is security-sensitive because it would make provider-emitted reasoning text executable.

## What This Changes

This issue asks OpenClaw to handle provider/model-specific tagged tool-call markup inside thinking content so subagent tool use does not finish early or lose results.

## Best Possible Solution

Approve a narrowly gated provider-owned Qwen/ModelStudio normalization path, or an explicitly approved shared helper, that promotes only validated standalone tagged thinking sections for allowed tools after live provider proof.
