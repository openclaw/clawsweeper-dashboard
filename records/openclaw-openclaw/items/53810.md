## Summary

Keep open: current main still has the reported gap for Qwen/ModelStudio-style tagged tool calls when the markers are carried only in thinking/reasoning content, and the remaining fix needs live provider proof plus a security/product decision before reasoning text is promoted into executable tool calls.

## What This Changes

The issue asks OpenClaw to prevent premature subagent completion announcements when affected provider/model pairs emit nonstandard tagged tool-call markers inside thinking content instead of structured toolCall blocks.

## Best Possible Solution

Add conservative provider-owned Qwen/ModelStudio normalization, or a narrow shared helper, that promotes only validated standalone tagged sections for allowed tools before stop-reason and announce logic.

## Reproduction Assessment

No high-confidence live reproduction is available. Source inspection shows current main still leaves tagged markers inside thinking blocks non-executable on the implicated provider path.

## Solution Assessment

Unclear until maintainers choose the security boundary. Delaying announce alone is not the best fix; validated provider-owned marker normalization before announce is the maintainable path if live proof confirms the behavior.
