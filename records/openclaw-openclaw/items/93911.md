## Summary

Keep this PR open: the patch is a focused and apparently correct logging fix with sufficient real behavior proof, but it intentionally changes upgrade semantics for blank or whitespace-only `logging.file` values and needs maintainer acceptance before merge.

## What This Changes

The PR changes logger runtime resolution so blank `logging.file` values fall back to the default rolling log path, warns once on file append failures, and adds regression tests while keeping schema validation permissive.

## Best Possible Solution

Land the runtime fallback and append-warning behavior once maintainers accept blank or whitespace-only `logging.file` as equivalent to unset while preserving every nonblank configured path exactly.

## Reproduction Assessment

Yes. Source inspection of current main shows `cfg?.file` is passed through directly and false `appendLogLine` returns are ignored; I did not run local tests in this read-only review.

## Solution Assessment

Yes, subject to maintainer acceptance of the config semantics. Runtime resolution is the right layer for blank-value compatibility, schema rejection would break existing startup, and trimming nonblank paths would silently rewrite configured paths.
