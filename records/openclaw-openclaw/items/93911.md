## Summary

Keep open for maintainer review: the patch is a focused logging fix with sufficient runtime proof and no blocking correctness finding, but it intentionally changes upgrade behavior for existing blank or whitespace-only `logging.file` values.

## What This Changes

The PR changes logger resolution so blank or whitespace-only `logging.file` falls back to the default rolling log path, emits a one-time stderr warning on append failures, and adds regression tests while leaving the config schema permissive.

## Best Possible Solution

Land the runtime fallback and append-warning behavior once maintainers accept blank or whitespace-only `logging.file` as equivalent to unset while preserving every nonblank configured path exactly.

## Reproduction Assessment

Yes, source-level. Current main passes `cfg?.file` through directly and ignores false `appendLogLine` returns; I did not run tests in this read-only review.

## Solution Assessment

Yes, subject to maintainer acceptance of the config semantics. Runtime resolution is the right compatibility layer, schema rejection would break existing startup, and trimming nonblank paths would silently rewrite configured paths.
