## Summary

Needs changes before merge: the final validation still diverges from the decoder’s charset-resolution contract, so valid BOM-sniffed UTF-16 responses containing a legitimate replacement character can be returned as an empty body. The prior two blockers are addressed, but this remaining compatibility regression is a narrow mechanical repair.

## What This Changes

The PR validates `arrayBuffer()` response bytes with fatal decoding using the declared charset, restores the `text()` fallback after byte-read failure, and adds response-decoding regression tests.

## Best Possible Solution

Use one shared resolved-charset helper for forgiving decoding and fatal validation, including header, BOM, and document sniffing behavior, then add BOM-only UTF-16 regression coverage.
