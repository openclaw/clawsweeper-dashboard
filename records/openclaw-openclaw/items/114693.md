## Summary

Keep this issue open as the direction and measurement tracker. The linked open PR addresses the reported primary Gateway metadata-rediscovery stall, but it has not merged, and the proposed client startup coalescing, metadata ownership, transcript-first rendering, and any remaining event-loop work are distinct follow-up decisions.

## What This Changes

Request staged Control UI chat-startup improvements that eliminate duplicated metadata work and let available transcript history render before optional model and agent metadata.

## System Context

Control UI chat panes call Gateway startup and metadata RPCs to load a session transcript together with agent/model controls. The Gateway reads session history and projects model visibility before returning data, and the UI then commits the result into the active pane.

## Architecture Diagram

flowchart LR
  A[Control UI chat pane] --> B[Startup and metadata requests]
  B --> C[Gateway chat startup handler]
  C --> D[Session transcript read]
  C --> E[Agent and model metadata projection]
  D --> F[Transcript first paint]
  E --> G[Model controls and commands]
  F --> H[Interactive chat pane]
  G --> H

## Best Possible Solution

Land or decline the narrow prepared-metadata candidate first, remeasure one-pane and split-pane startup on its merged result, then split any confirmed UI fast-path and request-coalescing work into bounded follow-up issues with explicit session-ownership semantics.
