## Summary

This is a useful, focused hardening change, but the current patch does not guarantee redaction: `redactSensitiveText()` inherits `logging.redactSensitive` and custom-pattern settings, so supported configurations can still expose the upstream credential. The submitted loopback test is strong supplemental coverage, while the standalone transcript exercises the helper rather than the changed Copilot error paths.

## What This Changes

The PR applies sensitive-text redaction to GitHub Copilot model-discovery and embedding HTTP error bodies and adds loopback transport regression tests.

## Best Possible Solution

Make provider error sanitization unconditionally apply the built-in credential patterns regardless of logging preferences, preserve the existing Copilot fallback prefixes, and prove both failed request paths with redacted runtime output.
