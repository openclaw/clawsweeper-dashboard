## Summary

Keep open: current main has hook timeouts, plugin-local active-memory timeout protection, Telegram transport cooldowns, and channel crash-loop suppression, but it still lacks the requested framework-level plugin/hook circuit breaker with attribution, persisted breaker lifecycle, half-open or forced-open state, operator status/reset controls, and per-plugin degradation policy.

## What This Changes

The issue requests a core plugin circuit-breaker framework that times and attributes plugin hook failures, skips unhealthy plugin hooks, persists breaker state, supports recovery/reset, and exposes operator status.

## Best Possible Solution

Define a generic plugin-host breaker contract first, including hook attribution, SQLite-backed state, status/reset surfaces, fail-mode semantics, and a passive telemetry phase before active hook skipping.
