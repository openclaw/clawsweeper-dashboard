## Summary

Keep open: current main has partial protections, including hook timeouts, plugin health/status reporting, invalid-config quarantine, channel crash-loop suppression, and an Active Memory-local breaker, but it still does not provide the requested framework-level plugin circuit breaker with persisted plugin/hook state, open/half-open/forced-open lifecycle, operator reset, lock attribution, and per-plugin degradation policy.

## What This Changes

Request a gateway/plugin-runtime circuit breaker that tracks plugin hook timeouts, errors, and lock overruns, persists breaker state, skips degraded plugin hooks, and exposes status/reset/fail-mode controls.

## Best Possible Solution

Design a generic core plugin-runtime breaker first, then implement SQLite-backed per-plugin/hook state, lock attribution, operator-visible status/reset, and a default-compatible log-only rollout before enabling active degradation.
