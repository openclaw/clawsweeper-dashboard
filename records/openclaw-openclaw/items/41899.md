## Summary

Keep open: current main has partial hook timeouts, lock watchdogs, runtime health storage, and an Active Memory local breaker, but it still lacks the requested framework-level plugin circuit breaker with attribution, persisted lifecycle state, operator controls, and per-plugin degradation policy.

## What This Changes

The issue requests a framework-level plugin circuit breaker for graceful degradation when plugin hooks or tools repeatedly time out, error, or hold locks too long.

## Best Possible Solution

Keep this as a maintainer-owned design item and define a SQLite-backed breaker contract for plugin hooks/tools, including attribution, lifecycle state, degradation modes, status visibility, reset controls, and upgrade-safe defaults.

## Reproduction Assessment

Yes from source at the capability level: current main has partial timeout and health mechanisms but no generic plugin breaker lifecycle. I did not reproduce a live gateway incident.

## Solution Assessment

Unclear as a final design: a framework breaker is directionally appropriate, but the proposed JSON registry should become SQLite-backed and the plugin API, fail modes, defaults, and operator controls need maintainer decisions first.
