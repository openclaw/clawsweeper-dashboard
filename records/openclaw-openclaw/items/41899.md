## Summary

Keep open: current main has hook timeouts, gateway/channel-specific breakers, and a narrow Active Memory timeout breaker, but it still lacks the requested framework-level plugin circuit breaker with durable plugin-scoped lifecycle state, hook/session attribution, operator status/reset, half-open/forced-open recovery, and per-plugin degradation policy.

## What This Changes

The issue requests a gateway/plugin-runtime circuit breaker that gracefully quarantines misbehaving plugins while preserving the rest of the gateway.

## Best Possible Solution

Define a core plugin-runtime breaker API backed by the canonical SQLite/plugin-state store, with hook timing/failure attribution, operator status/reset surfaces, passive rollout, and plugin-declared safe degradation modes before active enforcement.
