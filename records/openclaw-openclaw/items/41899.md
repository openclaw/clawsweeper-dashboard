## Summary

Keep open: current main has per-hook timeouts/error policy and a narrow Active Memory timeout breaker, but it does not implement the requested framework-level plugin circuit breaker with persisted lifecycle state, plugin-scoped quarantine, operator reset/status, and per-plugin degradation policy.

## What This Changes

Request to add a framework-level plugin circuit breaker that can quarantine misbehaving plugin hooks while preserving the rest of the gateway.

## Best Possible Solution

Design a generic plugin-runtime breaker around the existing hook runner and plugin status/doctor surfaces, store durable breaker state in the canonical SQLite-backed runtime store, and require maintainer-approved defaults before enabling automatic plugin quarantine.

## Maintainer Decision

Question: Should OpenClaw add a core framework-level plugin circuit breaker, and if so what default fail modes and storage/operator surfaces are acceptable for existing plugins?

Rationale: Current code only has hook timeouts and a plugin-local Active Memory breaker; the requested shared breaker would change plugin API expectations, config/default behavior, runtime storage, status output, and operator controls.

Likely owner: Vincent Koc

Owner reason: The current hook runner, plugin registry, and gateway runtime surfaces all point to this recent area contributor in local history.

Owner confidence: medium

Options:

- **Design core breaker first (recommended):** Keep this issue open for a maintainer-led design that defines generic hook attribution, SQLite-backed state, status/reset commands, and compatibility-safe default behavior before implementation.
- **Keep plugin-owned only:** Defer a framework breaker and ask each high-risk plugin to implement its own degradation policy through existing hook/config surfaces.
- **Start passive telemetry only:** Implement non-quarantining hook timing and failure counters first, then decide active open/half-open behavior after real deployment data.

## Reproduction Assessment

No live incident was reproduced in this read-only pass, but source inspection confirms current main lacks the requested framework-level open/half-open/forced-open plugin breaker and operator reset path. The existing Active Memory breaker is plugin-local and narrower than the reported gateway-level failure model.

## Solution Assessment

Unclear until maintainers choose the product boundary: a core hook-runner breaker is plausible, but the issue's JSON-file registry and per-plugin defaults conflict with current SQLite/storage and high-bar config guidance. A safer first implementation would likely be passive hook telemetry plus a maintainer-approved SQLite-backed breaker API before active quarantine defaults.
