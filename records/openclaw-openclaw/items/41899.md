## Summary

Keep open: current main has bounded hook timeouts, cleanup bounds, channel crash-loop suppression, session-lock watchdogs, and an Active Memory-local timeout breaker, but it still lacks the requested framework-level plugin circuit breaker with plugin/hook attribution, persisted lifecycle state, operator reset/status controls, and per-plugin degradation policy.

## What This Changes

The issue requests a framework-level plugin circuit breaker that can quarantine or degrade unhealthy plugin hooks while keeping the rest of the gateway available.

## Best Possible Solution

Design one canonical plugin-runtime breaker contract with passive telemetry first, plugin/hook lock attribution, SQLite-backed state if persistence is required, operator-visible status/reset controls, and tested defaults that avoid surprising existing plugin authors.
