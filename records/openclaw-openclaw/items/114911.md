## Label Justifications

- `P0`: The PR addresses a path where an agent can replace an existing user file while reporting a successful create or normal modification.

## Summary

Keep this PR open, but do not merge it yet: the proposed check is a time-of-check/time-of-use guard, so another writer can still create the target after `exists` returns and before the later write overwrites it. The change also deliberately turns a previously successful patch form into an error, so an agents-runtime owner should confirm the intended Add File compatibility contract before landing.

## What This Changes

The PR makes `apply_patch` reject Add File hunks and Move to destinations that already exist, preserving the existing target instead of overwriting it.

## System Context

OpenClaw’s agent file-editing tool accepts a structured patch from an agent, resolves its paths through either the workspace, raw filesystem, or sandbox backend, then reports a summary of created, changed, and deleted files. This PR changes the create-destination decision before those backend writes occur.

## Best Possible Solution

Confirm that Add File and non-self Move to are intended to be create-only, then provide an atomic no-clobber create operation through every patch backend and cover both the concurrent-create boundary and the delete-then-add replacement idiom.
