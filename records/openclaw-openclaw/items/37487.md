## Risks / Open Questions

- A first-class per-profile proxy setting could expose proxy credentials through Chrome argv, logs, status payloads, config snapshots, or process listings unless SecretRef and redaction rules are designed end to end.
- Proxy-routed browser traffic changes the SSRF trust boundary because the final DNS resolution and connect target may be controlled by the proxy rather than OpenClaw's process.
- Agent and subagent browser-profile binding affects access to cookie-bearing browser state, so inheritance, overrides, profile authorization, and user visibility need an explicit maintainer policy.
- Concurrent local Chromium instances need launch serialization, resource limits, ownership cleanup, and diagnostics; the linked browser-lock comment reports multi-browser memory and launch-race constraints.
