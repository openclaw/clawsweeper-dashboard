## Summary

This is a credible fix for the linked mixed-JSON logging bug, with real process-level evidence and no concrete patch defect found. It should remain open for the existing protected maintainer review because it deliberately expands the observable scope of the opt-in `logging.consoleStyle: "json"` contract across early CLI diagnostics and routes.

## What This Changes

The branch centralizes JSON console-line formatting, installs console capture before CLI routes diverge, and routes several direct diagnostics through that formatter while preserving explicit command `--json` output.

## System Context

The CLI reads profile and logging settings before it selects gateway fast paths, routed commands, or Commander execution. Those paths emit console diagnostics and subsystem logs that operators may ingest as JSONL, while command-result JSON must remain a separate raw-machine-output contract.

## Architecture Diagram

flowchart LR

  B --> C[Console capture setup]
  C --> D[Route-first or Commander command]
  D --> E[Diagnostics and subsystem logs]
  E --> F[JSONL console stream]
  D --> G[Explicit command JSON result]

## Best Possible Solution

Land a single shared formatter and early capture boundary only after confirming that JSON console style intentionally covers the repaired CLI diagnostics while explicit command `--json` stays raw and independently parseable.
