## Label Justifications

- `P2`: The request affects plugin guardrail and session correlation correctness, but it is an additive public API/product improvement rather than an active runtime outage.
- `impact:session-state`: The requested hook data is needed to correlate outbound messages with the correct run/session state under concurrent or multi-path delivery.
- `impact:security`: The requested verification evidence is used for pre-send policy enforcement and could expose sensitive transcript or tool-result data if designed incorrectly.

## Summary

Keep open: current main and v2026.6.11 still only partially cover the request. `message_sending` has cancel/rewrite support and can receive `sessionKey`, but outbound delivery still does not provide outbound `runId` or bounded same-turn transcript/tool-call/result evidence for deterministic pre-send verification.

## What This Changes

Request an outbound pre-send plugin hook/context that exposes outbound text, destination, session/run identity, and verification evidence so plugins can annotate or block unsupported agent claims before delivery.

## Best Possible Solution

Define a maintainer-approved additive Plugin SDK contract for outbound run identity plus redacted, bounded same-turn verification evidence, then wire shared outbound and direct-reply paths with docs and focused regression tests.

- **Land identity only first:** Add outbound runId/message identity now while leaving deterministic evidence for a later Plugin SDK design.
- **Treat existing hooks as sufficient:** Close the request as covered by `reply_payload_sending` and sessionKey correlation, accepting that plugins still lack first-class tool/result evidence.

## Reproduction Assessment

Yes, at source level: current main's `message_sending` hook has sessionKey but no outbound runId or bounded same-turn verification evidence, while `reply_payload_sending` has runId but only exposes payload and usage state.

## Solution Assessment

Unclear pending maintainer security/API design. Adding run identity is plausible, but the best fix for transcript/tool-call evidence needs a bounded, redacted, permission-aware Plugin SDK contract rather than an ad hoc metadata dump.
