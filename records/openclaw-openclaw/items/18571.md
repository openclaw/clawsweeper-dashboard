## Label Justifications

- `P2`: The issue is a bounded but security-sensitive plugin API improvement for hook correlation and guardrails, not an urgent outage or blocked first-run path.
- `impact:session-state`: The missing run/evidence context prevents plugins from correlating outbound messages to the correct same-turn session state under concurrent or multi-path delivery.
- `impact:security`: The requested pre-send evidence surface is intended for policy enforcement and could expose sensitive transcript or tool-result data if designed incorrectly.

## Summary

Keep open. Current main and the latest release still leave outbound `message_sending` without `runId` or bounded verification evidence, while the merged sessionKey work only covers the correlation subset.

## What This Changes

Request to expose outbound text, channel/recipient, session/run identity, and bounded tool-call/result context to pre-send message hooks so plugins can deterministically annotate or block delivery.

## Best Possible Solution

Define a maintainer-approved additive plugin API for outbound run identity plus redacted, bounded same-turn evidence across shared and direct delivery paths, leaving claim-verification policy implementation to plugins or ClawHub.

## Reproduction Assessment

Yes. Source inspection on current main shows outbound `message_sending` still receives no runId or bounded same-turn verification evidence, and the latest release has the same gap.

## Solution Assessment

Unclear. Adding identity and evidence is directionally aligned, but the exact redaction, permission, and cross-hook semantics need maintainer product/security review before becoming a public plugin contract.
