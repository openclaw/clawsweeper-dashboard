## Summary

Keep open. Current main and v2026.6.11 have the pre-send `message_sending` hook and the sessionKey slice from https://github.com/openclaw/openclaw/pull/73706, but the central deterministic verification contract is still missing: outbound delivery still provides no runId and no bounded transcript/tool-call/result evidence for the hook.

## What This Changes

The issue requests a pre-send outbound message hook/context that exposes session and run identity plus bounded verification evidence so plugins can deterministically inspect, annotate, or block outbound agent claims.

## Best Possible Solution

Define a maintainer-approved additive hook contract for outbound run identity plus redacted, bounded same-turn verification evidence, then wire shared outbound and direct-reply paths with docs and focused tests.

## Reproduction Assessment

Yes, at source level: current main's outbound `message_sending` hook has sessionKey but no outbound runId or bounded same-turn verification evidence. The latest release v2026.6.11 has the same central gap.

## Solution Assessment

No, not yet. The current sessionKey-only implementation is useful but not the best complete solution; the remaining fix needs a bounded redacted plugin SDK contract rather than an ad hoc metadata dump.
