## Summary

Keep open: current main has the sessionKey subset and an adjacent reply_payload_sending hook, but outbound message_sending still lacks runId and any bounded transcript/tool-call/result evidence needed for deterministic pre-send verification.

## What This Changes

The issue requests an outbound pre-send message hook that can inspect outbound text plus session/run tool evidence and annotate, cancel, or retry delivery deterministically.

## Best Possible Solution

Define one additive plugin-hook contract for pre-send verification, with explicit run/session identity and bounded recent evidence fields across shared outbound delivery and reply paths.
