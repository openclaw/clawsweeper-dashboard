## Summary

Keep open: current main and the latest release only partially cover this request. `message_sending` can rewrite/cancel and now gets `sessionKey`, while `reply_payload_sending` has `runId` plus usage state, but no outbound pre-send hook exposes outbound `runId` together with bounded same-turn transcript/tool-call/result evidence for deterministic verification.

## What This Changes

The issue requests a pre-send outbound message hook API with message text, session/run identity, tool-call history, and cancel/retry capability for deterministic verification before delivery.

## Best Possible Solution

Define a maintainer-approved additive hook contract for outbound run identity plus redacted, bounded same-turn verification evidence, then wire shared outbound and direct-reply paths with docs and focused regression tests.

Unclear until product/security review. Adding run identity is plausible, but the best fix for transcript/tool-call evidence needs a bounded, redacted, permission-aware plugin SDK contract rather than an ad hoc metadata dump.
