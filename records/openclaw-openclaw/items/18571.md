## Summary

Keep open: current main has the pre-send `message_sending` hook and the sessionKey slice from https://github.com/openclaw/openclaw/pull/73706, but outbound `message_sending` still lacks runId and bounded same-turn transcript/tool-call/result evidence for deterministic verification.

## What This Changes

The issue requests a plugin-visible outbound pre-send hook context with message text, session/run identity, tool/result history, and cancel/annotate capability for deterministic verification before delivery.

## Best Possible Solution

Define a maintainer-approved additive plugin hook contract for outbound run identity plus redacted, bounded same-turn verification evidence, then wire shared outbound and direct-reply paths with docs and focused tests.

## Reproduction Assessment

Yes, at source level: current main’s outbound `message_sending` hook has sessionKey but no outbound runId or bounded same-turn verification evidence. No live runtime repro was run in this read-only review.

## Solution Assessment

Unclear until product/security review. Adding runId is plausible, but exposing transcript/tool-call evidence should be a bounded redacted plugin SDK contract rather than an ad hoc metadata dump.
