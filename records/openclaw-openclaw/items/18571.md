## Summary

Keep open: current main implements the sessionKey subset, but not the requested outbound runId or bounded tool-call/result evidence needed for deterministic pre-send verification.

## What This Changes

Expose a pre-send outbound hook context with sessionKey/runId plus bounded verification evidence so plugins can annotate, block, or retry unsafe outbound messages.

## Best Possible Solution

Define one additive, permissioned plugin-hook contract that forwards outbound runId plus a bounded recent evidence view across shared delivery and direct reply paths, with docs and regression coverage.

Options:

- **Define bounded evidence contract (recommended):** Add runId and a redacted, size-limited recent evidence view to the pre-send hook with explicit docs, permissions, and tests across shared and direct reply paths.
- **Limit to runId only:** Thread outbound runId now but leave tool/transcript evidence for a separate security design, which improves correlation but does not satisfy deterministic verification.
- **Route to another seam:** Keep message_sending text-only and require verification plugins to use reply_payload_sending, diagnostics, or a future dedicated verification hook.

## Reproduction Assessment

Yes, source inspection is enough: current main's message_sending path forwards ctx.sessionKey but has no outbound runId or bounded tool/result evidence. I did not run a live plugin repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the security boundary; the current sessionKey-only implementation is useful but not the complete requested solution. The maintainable fix should be one additive, documented hook contract rather than more one-off identity plumbing.
