## Summary

Keep open: current main and the latest release still lack outbound `runId` plus bounded transcript/tool-call/result evidence for deterministic pre-send verification; only the `sessionKey` subset and an adjacent reply-payload hook exist, and the remaining API needs a maintainer security-boundary decision.

## What This Changes

The issue requests a pre-send outbound hook context that can read outbound text, correlate the run/session, inspect recent tool-call evidence, and annotate or block delivery before users see unsupported claims.

## Best Possible Solution

Define one additive plugin-hook contract for deterministic pre-send verification, with explicit run/session identity, bounded recent evidence fields, redaction/permission rules, docs, and regression coverage across shared outbound delivery and direct reply paths.
