## Summary

Keep open. Current main has the pre-send `message_sending` hook and the sessionKey slice from merged PR #73706, but the requested deterministic verification contract still lacks outbound runId plus bounded same-turn transcript/tool-call/result evidence.

## What This Changes

Expose session/run identity and verification evidence to the outbound pre-send message hook so plugins can annotate or block unverified claims before delivery.

## Best Possible Solution

Define a maintainer-approved additive hook contract for outbound run identity plus redacted, bounded same-turn verification evidence, then wire shared outbound and direct-reply paths with docs and focused tests.

## Reproduction Assessment

Yes, at source level: current main's outbound `message_sending` hook has sessionKey but no runId or bounded same-turn verification evidence; no live runtime repro was run in this read-only review.

## Solution Assessment

Unclear until product/security review; adding runId is plausible, but exposing transcript/tool-call evidence needs a bounded redacted plugin SDK contract rather than an ad hoc metadata dump.
