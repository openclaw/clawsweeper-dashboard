- `impact:session-state`: The requested hook data is needed to correlate outbound messages with the correct same-turn run/session state under concurrent or multi-path delivery.

## Summary

Keep open: current main has partial coverage through `message_sending` sessionKey plumbing and `reply_payload_sending` runId/usageState, but the requested outbound runId plus bounded transcript/tool-call/result evidence contract is still missing and is a public plugin/security decision.

## What This Changes

The issue requests a pre-send outbound hook context with message text, session/run identity, and tool-call/result evidence so plugins can deterministically annotate or block unsupported agent claims before delivery.

## Best Possible Solution

Define a maintainer-approved additive hook contract for outbound run identity plus redacted, bounded same-turn verification evidence, then wire shared outbound and direct-reply paths with docs and focused regression tests.

Unclear until maintainer review. Adding identity is plausible, but the best fix for transcript/tool-call evidence needs a bounded, redacted, permission-aware plugin SDK contract rather than an ad hoc metadata dump.
