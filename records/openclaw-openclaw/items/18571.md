## Summary

Keep open: current main and the latest release have the sessionKey subset plus an adjacent reply-payload hook, but they still do not provide outbound runId or bounded transcript/tool-call/result evidence for deterministic pre-send verification.

## What This Changes

The issue requests outbound pre-send hook context that exposes session/run identity and bounded verification evidence so plugins can inspect, annotate, or block messages before delivery.

## Best Possible Solution

Define one additive plugin-hook contract for deterministic pre-send verification, with explicit run/session identity, bounded recent evidence fields, redaction/permission rules, docs, and regression coverage across shared outbound delivery and reply paths.
