- `impact:session-state`: The requested hook data is needed to correlate outbound messages with the correct same-turn run/session state.

## Summary

Keep open: current main and the latest release only partially cover this request. `message_sending` now gets `sessionKey`, and `reply_payload_sending` has `runId` plus usage state, but no outbound pre-send hook exposes outbound `runId` together with bounded transcript/tool-call/result evidence for deterministic verification.

## What This Changes

The issue asks for an outbound pre-send hook context that exposes session/run identity and bounded verification evidence so plugins can inspect, annotate, or block messages before delivery.

## Best Possible Solution

Define a maintainer-approved additive hook contract for outbound run identity plus redacted, bounded same-turn verification evidence, then wire shared outbound and direct-reply paths with docs and focused regression tests.

Question: Should OpenClaw expose same-turn transcript/tool-call/result evidence to outbound pre-send plugin hooks, and what bounded, permissioned public SDK shape should own it?

Rationale: The remaining work changes public plugin API semantics and can expose sensitive session/tool data before delivery, so automation cannot safely choose field shape, redaction, permissions, or hook ownership without maintainer intent.

Likely owner: steipete

Owner confidence: high

Options:

- **Add bounded evidence contract (recommended):** Expose run identity plus capped, redacted same-turn verification evidence on the chosen pre-send hook and document the permission/security model.
- **Land identity only first:** Add outbound runId/message identity now but leave deterministic evidence for a later plugin API design.
- **Treat payload hook as sufficient:** Close the request as covered by `reply_payload_sending`, accepting that plugins still lack first-class tool/result evidence.

## Reproduction Assessment

Yes, at source level: current main's `message_sending` hook has `sessionKey` but no outbound `runId` or bounded same-turn verification evidence, while `reply_payload_sending` has `runId` but only exposes payload and usage state. No live channel run was performed in this read-only review.

## Solution Assessment

Unclear until product/security review. Adding run identity is plausible, but the best fix for transcript/tool-call evidence needs a bounded, redacted, permission-aware plugin SDK contract rather than an ad hoc metadata dump.
