## Summary

Keep open: current main and v2026.6.11 only partially cover this request. `message_sending` can rewrite/cancel and now gets `sessionKey`, while `reply_payload_sending` has `runId` plus usage state, but no outbound pre-send hook exposes outbound `runId` together with bounded transcript/tool-call/result evidence for deterministic verification.

## What This Changes

The issue asks OpenClaw to expose outbound pre-send hook context with session/run identity and bounded evidence so plugins can deterministically verify or block agent claims before delivery.

## Best Possible Solution

Define a maintainer-approved additive plugin hook contract for outbound run identity plus redacted, bounded same-turn verification evidence, then wire shared outbound and direct-reply paths with docs and focused regression tests.
