## Summary

Keep open: current main and v2026.6.11 cover the sessionKey subset, but they still do not expose outbound runId or a bounded transcript/tool-call/result evidence contract for deterministic pre-send verification.

## What This Changes

The issue requests outbound pre-send hook context that includes session/run identity and enough bounded evidence for plugins to verify, annotate, or block messages before delivery.

## Best Possible Solution

Define one additive, permissioned plugin-hook contract for pre-send verification, including explicit run/session identity and bounded recent evidence fields across shared outbound delivery and direct reply paths.
