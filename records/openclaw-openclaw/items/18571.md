## Summary

Keep open. Current main has the pre-send message hook and the merged sessionKey correlation slice, but the central request remains missing: outbound `message_sending` still lacks runId plus bounded tool-call/result evidence for deterministic pre-send verification.

## What This Changes

Request an outbound pre-send message hook/context that exposes session/run identity plus bounded tool-call evidence so plugins can deterministically verify, rewrite, or block outbound claims before delivery.

## Best Possible Solution

Define a maintainer-approved additive plugin hook contract for outbound run identity plus redacted, bounded same-turn evidence, then wire shared outbound delivery and direct-reply paths with docs and focused regression tests.

## Reproduction Assessment

Yes. Source inspection shows outbound `message_sending` still receives only content/routing/sessionKey context, while the hook types and docs do not provide bounded tool-call/result evidence for deterministic verification.

## Solution Assessment

Unclear as a direct implementation request. The direction fits the plugin API, but the best fix needs maintainer-approved field names, data bounds, redaction rules, and cross-path behavior before code is queued.
