## Summary

Keep open. Current main and v2026.6.11 have partial pre-send hook coverage, including outbound `sessionKey` and the newer `reply_payload_sending` hook, but `message_sending` still lacks outbound `runId` and bounded transcript/tool-call/result evidence for deterministic verification.

## What This Changes

The issue requests a pre-send outbound plugin hook/context with outbound text, sessionKey/runId, and bounded tool-call/result evidence so deterministic verifier plugins can annotate or block delivery.

## Best Possible Solution

Define one additive, permissioned plugin-hook contract for outbound verification evidence, keeping domain-specific verifier logic in plugins while core owns session/run correlation, bounded tool-result access, docs, and contract tests.

Owner confidence: high

Options:

- **Design bounded evidence contract (recommended):** Define a versioned additive hook context or evidence object with explicit permissions, redaction, limits, and tests before implementation.
- **Route evidence through turn-end API:** Keep outbound hooks payload-only and satisfy tool-call/result access through the broader typed turn outcome contract instead.
- **Keep hooks advisory:** Document that current pre-send hooks can rewrite/cancel text but are not a deterministic verification boundary for tool claims.

## Reproduction Assessment

Yes. Source inspection shows the current outbound `message_sending` event/context lacks `runId` and bounded tool-call/result evidence, while the adjacent `reply_payload_sending` hook only adds payload/run/usage context.

## Solution Assessment

Unclear pending maintainer design. The requested direction is valid, but the safest solution is a bounded, permissioned evidence contract rather than exposing raw session history directly to every pre-send hook.
