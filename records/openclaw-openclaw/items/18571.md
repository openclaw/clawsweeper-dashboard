## Label Justifications

- `P2`: The missing hook context affects plugin-based verification and trust but is an additive API design item rather than an outage or first-run blocker.
- `impact:session-state`: Without run/session evidence on outbound hooks, plugins can mis-associate claims with the wrong turn or lack the state needed to verify them.
- `impact:security`: The request is for a pre-send guardrail that can block fabricated or policy-violating outbound messages before users see them.

## Summary

Keep open: current main and v2026.6.11 have the `message_sending` hook and the merged sessionKey subset, but the central outbound `runId` plus bounded tool-call/result evidence contract is still missing and needs maintainer API/security design.

## What This Changes

The issue requests a pre-send outbound message hook context that exposes session/run identity and bounded tool-call evidence so plugins can deterministically verify or block outbound claims before delivery.

## Best Possible Solution

Define a bounded, permissioned Plugin SDK contract for outbound pre-send verification, then thread `runId` and a size-capped recent evidence view through shared outbound delivery with docs, API baseline updates, and regression tests.
