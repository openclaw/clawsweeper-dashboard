## Summary

Keep this PR open: it addresses the right unhandled stream-error gap, but the new handler rejects immediately without terminating or waiting for the live `codex exec resume` child, which can leave the dangerous resume process running after OpenClaw reports failure and clears the active-session guard.

## What This Changes

The branch adds stdout/stderr `error` listeners to `runCodexExecResume` and two real-spawn Vitest regressions for synthetic parent-side stream errors.

## Best Possible Solution

Make the stream-error path lifecycle-complete: record the first stream error, terminate and wait for the `codex exec resume` child before settling, and add proof that no real-spawn child survives the stdout/stderr error path.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source inspection: the patched stream-error handler rejects without any child kill/wait path, and the existing `finally` clears only timers/temp files. I did not run tests because this was a read-only review.

## Solution Assessment

No: adding stream `error` listeners is the right direction, but immediate rejection is not the best fix because it can orphan the child and clear `activeResumeSessions` too early. The safer fix is to terminate and settle through child exit/close, or explicitly document and test diagnostic-only suppression if maintainers choose that contract.
