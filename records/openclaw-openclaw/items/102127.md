## Summary

Keep open: the previous ClawSweeper blocker is still present at the same PR head. The patch catches stdout/stderr stream errors, but it can reject and clear the active resume-session guard while the spawned `codex exec resume` process continues running.

## What This Changes

The PR adds stdout and stderr stream error listeners to the Codex node CLI resume subprocess path and adds focused regression tests for synthetic stream errors.

## Best Possible Solution

Make the stream-error path lifecycle-complete: record the first stream error, terminate the Codex resume child, wait for exit or close, then reject with the stream error.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source inspection: the patched stream-error handler rejects immediately, while cleanup only clears timers and removes the temp directory. The real-spawn tests also create a long-lived child but do not assert that it exits or is killed.

## Solution Assessment

No: adding stream error listeners is the right direction, but immediate rejection is not lifecycle-safe. The best fix is to record the stream error, terminate the child, and settle only after child exit or close.
