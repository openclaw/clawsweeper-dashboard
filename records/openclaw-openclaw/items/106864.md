## Summary

This is a credible, narrowly scoped fix for a serious Android chat regression. The proposed ownership split is sound: the gateway should own run expiry, while the Android watchdog should not fail a run that refreshed history still confirms as active. No discrete patch defect is established, but the PR needs after-fix Android proof before merge.

## What This Changes

The PR removes Android’s hardcoded 30-second `chat.send` timeout override and re-arms the 120-second pending-run watchdog whenever refreshed gateway history still reports the same run in flight.

## Best Possible Solution

Keep gateway configuration authoritative for run expiry, retain the Android timeout only as an orphaned-run detector, add focused coverage for in-flight re-arming and the not-in-flight timeout path, and prove the complete flow with a redacted Android run lasting more than 120 seconds.
