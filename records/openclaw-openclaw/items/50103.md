## Summary

Keep open. Current main and the latest release still do not provide the requested agent-level `agents.defaults.systemPrompt` / `rules` or per-agent prompt-rule config contract, and the remaining work needs maintainer product and security direction rather than cleanup.

## What This Changes

The issue asks for config-level agent system prompt or rules fields under agent defaults and per-agent config so reusable behavioral rules can be injected into every agent session.

## Best Possible Solution

Define one canonical, maintainer-approved agent-level prompt/rules contract with explicit precedence, defaults-plus-per-agent merge behavior, session-creation coverage, docs, schema/help metadata, and security limits; keep raw includes and hard enforcement in their narrower tracks.

## Reproduction Assessment

Yes for the source-level feature gap, not as a bug reproduction: strict current-main schemas reject the requested fields and the prompt builders do not resolve config prompt/rules text. No runtime failure path is needed to show the requested capability is missing.

## Solution Assessment

Unclear until maintainers decide the product and security boundary. The narrow maintainable path is likely an append-style agent prompt/rules contract first, with raw includes and hard enforcement handled by their canonical related items.
