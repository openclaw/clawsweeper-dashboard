## What This Changes

Clear Control UI question cards, answers, unmatched resolutions, and pending composer state when the active Gateway changes, without clearing them for a reconnect to the same Gateway.

## System Context

The Control UI keeps Gateway-backed question records in browser state and renders them into the active chat session. Switching the WebSocket client to a different Gateway must change the ownership boundary before those records reach the chat thread and question composer.

## Architecture Diagram

flowchart LR
  A[Gateway A WebSocket] --> B[Control UI Gateway store]
  C[Gateway switch controls] --> B
  B --> D{Same Gateway client?}
  D -->|Reconnect| E[Retain authoritative question records]
  D -->|Replacement Gateway| F[Clear prior Gateway question state]
  E --> G[Chat thread and question composer]
  F --> G
  H[Gateway B WebSocket] --> B

## Best Possible Solution

Make Gateway identity an explicit question-state ownership key: reset all prior-Gateway question state only when the client identity changes, preserve it on same-client reconnect, and add focused regressions for pending, answered, cancelled, and expired records.
