## Summary

This PR addresses a real concurrent-loss report, but it changes the established legacy `sessions.groups.put` contract from replacement to merge. That leaves older clients unable to remove groups through their existing successful mutation call, so the patch needs a narrow compatibility repair and after-fix two-tab behavior proof before merge.

## What This Changes

The PR adds atomic gateway operations for adding and reordering session groups, updates Control UI callers to use them, and changes the legacy group-catalog mutation to merge rather than replace rows.

## System Context

Control UI session grouping reads a catalog from the Gateway and sends mutations back through Gateway RPC methods. The Gateway persists that catalog in the shared SQLite state database and broadcasts catalog changes to other connected clients.

## Best Possible Solution

Keep `sessions.groups.put` as the documented full-replacement operation for existing clients, use the new atomic add and reorder operations for current Control UI mutations, and add a focused regression test plus redacted live two-tab proof showing both created groups persist.
