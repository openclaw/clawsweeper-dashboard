## Label Justifications

- `P1`: A normal multi-client Control UI workflow can lose an existing persisted sidebar ordering behavior after merge.
- `merge-risk: 🚨 compatibility`: The new Gateway mutation surface omits the established section-order persistence input used by existing sidebar moves.
- `merge-risk: 🚨 session-state`: Cross-client sidebar state is Gateway-persisted session presentation state, and the new reorder path can leave it stale after a drag.

## Summary

Keep this PR open: its atomic add path addresses the reported two-tab loss, but the new reorder request carries only group names and no longer persists the existing cross-section sidebar order. That makes dragging non-group sections appear to work locally while the Gateway retains the old saved order for subsequent loads or other clients.

## What This Changes

The branch adds atomic Gateway methods for adding and reordering custom session groups, updates Control UI and Android protocol callers to use them, and retains the legacy full-catalog write for older clients.

## System Context

Control UI sends session-group mutations to the Gateway, which persists the custom-group catalog and the sidebar’s section order in shared state before broadcasting session changes to other connected clients. The new semantic mutation methods are intended to avoid stale full-catalog writes while preserving the existing sidebar behavior.

## Architecture Diagram

flowchart LR

  E --> F
  F --> G[Other open clients]

## Best Possible Solution

Make the semantic reorder operation atomically persist both the ordered custom-group names and the existing sidebar section order, or introduce an equally atomic dedicated section-order operation; prove a Gateway-backed reload and a second client observe a non-group section move as well as concurrent group adds.

Yes, from source: move a non-group sidebar section, reload the Control UI or connect a second client, and compare the Gateway-provided section order. The changed path sends only group names—often an empty list—so it cannot persist the dragged non-group section ordering.

## Solution Assessment

No. Atomic add/reorder is the right direction for concurrent group creation, but the current reorder payload drops the established cross-section ordering input; the final semantic mutation must retain that persisted behavior atomically.
