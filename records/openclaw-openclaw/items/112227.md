## Summary

This PR targets the currently open concurrent custom-group-loss report and has credible terminal proof for the atomic-add path, so it should remain open for review rather than be closed. The remaining concern is scope: it adds a second public Gateway operation for reordering even though the PR says production sidebar reordering continues to use the existing full-catalog operation; that API should be removed or explicitly sponsored before merge.

## What This Changes

The branch adds atomic Gateway methods to add and reorder custom session groups, changes Control UI creation flows to use atomic add, and retains a legacy full-catalog fallback for older Gateways.

## System Context

Control UI reads and mutates the Gateway’s shared custom session-group catalog, which is persisted in SQLite and broadcast to connected clients. The PR moves single-group creation from a stale client-side catalog replacement to a server-side add operation so independently open tabs do not delete one another’s new groups.
