## Summary

The PR is still necessary for the concurrent custom-group loss reported in https://github.com/openclaw/openclaw/issues/106362, but the current head breaks the legacy `sessions.groups.put` contract in two ways: it no longer removes omitted groups and it ignores the accepted `sectionOrder` parameter. The new atomic add/reorder path can solve the race without changing those existing-client semantics; refreshed real Gateway or Control UI proof is also required for the final force-pushed head.

## What This Changes

The branch adds narrower Gateway operations for adding and reordering custom session groups, updates Control UI and Android protocol enumeration to use them, and changes the older full-catalog group mutation path.

## System Context

Control UI session-group actions go through the Gateway, which persists the shared group catalog in OpenClaw state and broadcasts a session-change event to connected clients. This PR changes both the mutation API and the UI paths that create or reorder sidebar groups.

## Best Possible Solution

Keep `sessions.groups.put` fully backward-compatible—replacement semantics plus `sectionOrder` request/response behavior—while routing newer Control UI creation and reorder flows through the new atomic methods; then publish redacted final-head proof showing two concurrent tabs retain both groups and legacy put behavior still works.
