## Summary

This PR addresses a real Workboard duplicate-proof report, but its latest-entry heuristic cannot distinguish the completing run from a later retry with identical evidence. The PR should remain open for a correlation-safe repair and after-fix runtime proof. Likely related people: steipete is the low-confidence routing candidate from the linked report and recent Workboard changes.

## What This Changes

The PR replaces the immediately preceding identical `unknown` Workboard proof with a terminal result during completion and documents proof statuses as worker self-attestation.

## Best Possible Solution

Use an explicit completion/run correlation mechanism so only the pending proof created by that run can be resolved; otherwise preserve append-only proof history, add retry regression coverage, and provide redacted after-fix runtime output.
