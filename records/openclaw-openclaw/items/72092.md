## Summary

Keep this PR open for maintainer review, not cleanup close: the patch is a focused fix for the open Bedrock `aws-sdk` media-auth bug, no blocking code finding surfaced, and the remaining question is accepting the auth-provider behavior change plus deciding whether PDF scope must be handled with or after this PR.

## What This Changes

This PR lets media-understanding image, MiniMax fallback, audio, and video paths treat empty `aws-sdk` provider auth as keyless execution and adds image/audio/video regression tests.

## Best Possible Solution

Land the focused image/audio/video keyless `aws-sdk` fix after maintainer acceptance, and either track PDF separately or require a small PDF follow-up before closing the canonical issue.

## Reproduction Assessment

Yes. Source inspection on current main shows `aws-sdk` auth can resolve without a literal API key, then image/audio/video media paths reach `requireApiKey` and throw before AWS SDK credentials can be used.

## Solution Assessment

Yes for the image/audio/video scope. The PR reuses the existing keyless `kind: "none"` runner path and limits the image carve-out to `aws-sdk`, rather than broadening `requireApiKey` globally; PDF remains a separate scope decision.
