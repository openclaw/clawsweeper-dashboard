## Summary

The focused retry matches the existing Gateway idempotency architecture and has no concrete correctness finding, but merge should wait for after-fix real delivery proof and maintainer confirmation that process-lifetime reconciliation is the intended guarantee.

## What This Changes

The PR retries a timed-out Gateway-backed message action once with the unchanged request and idempotency key, forwarding cancellation and using a minimum 60-second reconciliation timeout.

## Best Possible Solution

Keep reconciliation at the shared Gateway action boundary, add a real client/server timeout-reattachment test and redacted exactly-one-delivery proof, then explicitly accept or extend the process-lifetime guarantee before merge.
