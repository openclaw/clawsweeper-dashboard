## Summary

This PR targets a plausible Wear request-routing bug and follows the phone-proxy security boundary established by the merged companion work, but it needs real paired-device after-fix proof before merge because the new fail-closed route selection can change delivery behavior for existing multi-phone or disconnected-node states.

## What This Changes

The branch replaces the Wear client's cached-phone handling with generation-scoped registrations, targeted invalidation after failed or timed-out requests, unambiguous nearby-node selection, reachable-node fallback, and focused routing regressions.

## Best Possible Solution

Keep the phone-only Gateway and credential boundary, then demonstrate on a paired phone and Wear device that a failed stale route rediscovers one reachable phone while ambiguous states do not send to an unintended node.
