## Best Possible Solution

Choose one canonical, security-reviewed filesystem/media root contract and wire Telegram outbound through that schema, resolver, docs, and tests instead of adding an ad hoc Telegram-only key.

## Reproduction Assessment

Yes, source-level: current strict Telegram and agent-default schemas omit mediaLocalRoots, while outbound runtime only consumes roots when they are already supplied through mediaAccess or function parameters.

## Solution Assessment

No, not as a direct Telegram-only key yet; the maintainable solution is one shared local-root authorization contract aligned with tools.fs/media access policy.
