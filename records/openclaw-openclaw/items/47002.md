Question: Which public host-local media root policy should OpenClaw support for Telegram outbound media: shared `tools.fs.roots`, a narrower media-only `mediaLocalRoots` surface, or no persistent root expansion?

Rationale: The requested fix changes what host-local files can be read and uploaded by message delivery, and repository policy treats new config/default surfaces plus filesystem boundaries as maintainer/security decisions.

Likely owner: jacobtomlinson

Owner confidence: high

Options:

- **Use shared filesystem roots (recommended):** Adopt a single security-reviewed `tools.fs.roots`-style contract for filesystem tools and outbound media so OpenClaw does not grow competing allowlists.
- **Add media-only roots:** Add a narrower media-root config if maintainers want outbound media reads separated from read/write/edit filesystem policy, with explicit docs and tests for the split boundary.
- **Keep current boundary:** Do not add persistent host-root expansion and continue relying on managed roots, concrete-source widening, copies, symlinks, or staged media.
