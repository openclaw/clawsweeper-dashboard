## Summary

Keep open: current main and v2026.6.11 still do not expose a public Telegram or agent-defaults `mediaLocalRoots` config key, while fixing that would define a host-local file-read/upload boundary that needs maintainer product and security direction.

## What This Changes

The issue requests a public configuration path for outbound Telegram media local roots that the validator currently rejects.

## Best Possible Solution

Choose one canonical security-reviewed host media-root policy, then align schema, exported types, docs, Telegram/outbound delivery, and focused tests around that contract.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose host-local outbound media roots through a Telegram-specific config key, through a shared filesystem/media-root policy such as `tools.fs.roots`, or keep the current managed-root model and document it?

Rationale: The requested key changes a public config surface and file-read/upload security boundary, and it overlaps active broader root-policy work, so automation should not choose the permanent contract.

Likely owner: Peter Steinberger

Owner reason: Recent outbound media policy and root-plumbing history makes this the best available owner for the contract direction.

Owner confidence: high

Options:

- **Use shared root policy (recommended):** Make the canonical fix part of a shared, security-reviewed root policy that Telegram outbound media consumes without adding a one-off channel setting.
- **Add Telegram-scoped roots:** Expose `channels.telegram.mediaLocalRoots` with docs and tests if maintainers want channel-specific operator control.
- **Document managed roots only:** Decline new root configuration for now and document the built-in allowlist plus supported staging directories and CLI workaround.

## Solution Assessment

No for a validator-only patch: the best fix must define the public security contract and then update schema, types, docs, runtime root propagation, and tests together.
