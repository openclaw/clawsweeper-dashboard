## Summary

Keep open: current main covers many explicit host-readable outbound media sends through the shared filesystem-read media access path, but the requested security-scoped root config surface is still not present and should be decided as one canonical root policy rather than a Telegram-only `mediaLocalRoots` key.

## What This Changes

Requests accepting a configurable local media root surface for Telegram outbound media so local file paths outside managed roots can be sent without symlink or copy workarounds.

## Best Possible Solution

Adopt one shared, documented host-local filesystem/media root policy, then wire outbound media, schema/help, doctor behavior, and Telegram tests through that surface without adding per-channel one-off root keys.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw solve remaining local outbound media root needs through a canonical `tools.fs.roots`-style filesystem policy, keep the current fs-read trust model only, or add a narrower `mediaLocalRoots` config surface?

Rationale: The remaining work changes which host paths an agent can read and transmit as media, so automation cannot safely choose the permanent config/security boundary from source inspection alone.

Likely owner: Peter Steinberger

Owner reason: Peter introduced the current media access path and docs that this decision would extend or intentionally leave as-is.

Owner confidence: high

Options:

- **Canonical filesystem roots (recommended):** Use a shared `tools.fs.roots`-style policy for host path access and make outbound media consume that one root model after security review.
- **Keep current fs-read model:** Close this class of requests as covered by `tools.fs.workspaceOnly=false` plus read policy, accepting that there is no narrower root allowlist today.
- **Add mediaLocalRoots:** Expose a media-specific root allowlist under channel or agent config, accepting a second policy surface that must be documented, tested, and migrated carefully.

## Reproduction Assessment

Yes for the remaining exact config-surface gap: current source shows strict Telegram and agent-default schemas still do not accept `mediaLocalRoots`. The broader local-send failure is partly addressed by the shipped fs-read media path, so the remaining reproduction is the missing config surface rather than a total inability to send host-readable media.

## Solution Assessment

No: adding `mediaLocalRoots` only under Telegram or agent defaults is not clearly the best fix because it would duplicate the current filesystem-read policy. The maintainable path is a single shared root policy with security review, schema/help alignment, and focused media delivery tests.
