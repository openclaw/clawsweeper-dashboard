## Summary

Holding this open: current main and the latest checked release still do not expose a public `mediaLocalRoots` config key for Telegram outbound media, and the requested fix changes a host-local file-read/upload boundary that needs maintainer product and security direction before implementation.

## What This Changes

The issue asks OpenClaw to accept configured local media roots for Telegram outbound media instead of rejecting paths outside the built-in media allowlist.

## Best Possible Solution

Choose one canonical security-reviewed host media-root policy, then align schema, exported types, docs, Telegram/outbound delivery, and focused upgrade tests around that contract.

Options:

- **Use shared root policy (recommended):** Make the canonical fix part of a shared, security-reviewed root policy that Telegram outbound media consumes without adding a one-off channel setting.
- **Add Telegram-scoped roots:** Expose a narrow `channels.telegram.mediaLocalRoots` contract with docs and tests if maintainers want channel-specific operator control.
- **Document managed roots only:** Decline new root configuration for now and document the built-in allowlist plus the supported staging directories and CLI workaround.
