## Summary

The report remains necessary: current architecture treats `agent_databases` as runtime discovery state, while Doctor does not cover stale registry rows, allowing an orphaned entry to remain authoritative and recreate its missing database. The literal `agent` writer remains unidentified, and persistent-agent lifecycle semantics need an explicit maintainer choice before cleanup code deletes or suppresses durable state. citeturn10view3turn4view2

## What This Changes

Prevent stale or phantom `agent_databases` entries from causing the gateway to initialize databases for nonexistent agents, and add safe Doctor detection and repair.

## Best Possible Solution

Define `agent_databases` as durable discovery metadata but stop startup from creating or eagerly opening missing databases for unconfigured agents; have Doctor report metadata, path, and configuration mismatches and remove only provably empty or missing phantom rows automatically, with explicit confirmation for data-bearing historical databases.
