## Summary

Current main still leaves QA-bus POST and relay-poll requests without a total deadline. This focused PR addresses that remaining hang path, follows the recently merged state-request timeout pattern, and has no concrete correctness or security finding.

## What This Changes

Adds a 10-second default deadline to QA-bus POST requests, extends long-poll deadlines by the server wait window, composes caller cancellation, and adds focused loopback coverage.

## Best Possible Solution

Land the owner-level deadline and long-poll grace after required checks finish, keeping timeout policy internal and avoiding any new config or public API surface.

## Maintainer Decision

## Reproduction Assessment

Yes at source level: on current main, a loopback QA-bus peer can accept a POST and never return headers or complete the body, while `postJson` has no owner-supplied deadline. The PR's focused loopback scenario directly exercises that path.

## Solution Assessment

Yes. Applying one composed total deadline in the shared POST owner is narrower and more maintainable than adding separate timers to sends, actions, and polling, and the longer poll deadline preserves the server wait contract.
