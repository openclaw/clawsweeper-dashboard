## Summary

Keep open. Current main and the latest release still parse fetched Feishu quoted/thread message content without modeling or normalizing fetched-message mention metadata; the reporter and commenters correctly identified the `normalizeMentions()` gap, and the only same-repo fix attempt is closed unmerged while the remaining cross-repo candidate is open but conflicting.

## What This Changes

The issue requests resolving Feishu mention placeholders inside replied or quoted message context instead of passing raw `@_user_N` tokens to the agent.

## Best Possible Solution

Normalize fetched Feishu message mention metadata at the `parseFeishuMessageItem()` boundary so `getMessageFeishu()` and `listFeishuThreadMessages()` produce the same readable mention form as inbound events, with focused regression coverage for quoted text/post content and thread history.
