## Summary

Keep open. Current main and the latest release still parse fetched Feishu quoted/thread message content without carrying or normalizing fetched-message mention metadata, while the same issue is already claimed by an open but conflicting cross-repo fix PR.

## What This Changes

The issue reports that Feishu replied/quoted message context shows raw `@_user_N` placeholders because fetched quoted content is parsed without mention normalization.

## Best Possible Solution

Normalize fetched Feishu message mentions at the `parseFeishuMessageItem()` boundary so `getMessageFeishu()` and `listFeishuThreadMessages()` share one readable parsed shape, with focused quote/thread regression coverage.
