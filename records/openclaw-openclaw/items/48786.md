## Summary

Keep open. Current main and the latest release still parse fetched Feishu quoted/thread message content without modeling or normalizing fetched-message mention metadata, while the live inbound path already resolves Feishu mention placeholders; the same-repo fix PR was closed unmerged, and the remaining open fork PR still needs maintainer handling before ClawSweeper should queue a duplicate repair.

## What This Changes

The issue asks OpenClaw to resolve Feishu mention placeholders in quoted/replied message context instead of passing raw `@_user_N` tokens into agent-visible content.

## Best Possible Solution

Land a narrow Feishu-plugin fix in the shared fetched-message parser path that normalizes fetched `im.message.get/list` mentions for quoted, root, and thread context with focused regression tests and real Feishu proof.

## Reproduction Assessment

Yes, at source level. A mocked Feishu `im.message.get` or `im.message.list` response with body text containing `@_user_1` and fetched-message `mentions` metadata would currently return the placeholder unchanged because `parseFeishuMessageItem()` ignores `mentions`.

## Solution Assessment

Yes. The best fix is a narrow Feishu plugin repair in `parseFeishuMessageItem()` or a nearby adapter that normalizes fetched message mentions once for both quoted messages and thread history, rather than reviving the broad closed PR branch.
