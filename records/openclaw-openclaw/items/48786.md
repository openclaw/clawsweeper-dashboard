## Summary

Keep open. Current main still parses fetched Feishu quoted/root/thread message content without modeling or normalizing fetched-message mention metadata, while live inbound messages already resolve mention placeholders; the target-repo fix PR is closed unmerged and the remaining fork copy is open but conflicting, so no landed implementation solves this yet.

## What This Changes

The issue asks for Feishu quoted/replied message content to resolve raw `@_user_N` mention placeholders before the content is inserted into agent quote or thread context.

## Best Possible Solution

Land or replace the Feishu plugin fix in the shared fetched-message parser path: model fetched `mentions`, adapt that shape into the existing mention-normalization helper, apply it to quoted/root/thread content, and cover it with focused `extensions/feishu/src/send.test.ts` regression tests plus real Feishu proof.

## Reproduction Assessment

Yes, at source level. A fetched Feishu message whose `body.content` contains `@_user_N` will be parsed by `parseFeishuMessageItem()` without any fetched-message mention metadata normalization, while the live inbound path normalizes event mentions.

## Solution Assessment

Yes, the reported fix direction is the right boundary if it is kept narrow. The durable solution should normalize once in the fetched-message parser shared by quoted/root/thread reads, not patch downstream prompt rendering.
