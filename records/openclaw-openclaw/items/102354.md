## Summary

Keep open: the PR is focused, but it is not merge-ready because it relabels unsupported image bytes as `image/png` without converting or validating the payload, and it has no real behavior proof for the changed provider paths.

## What This Changes

The branch adds provider-local MIME helpers that pass JPEG/PNG/GIF/WebP through and replace every other image MIME string with `image/png` in Mistral, OpenAI Chat Completions, and OpenAI Responses data URLs.

## Best Possible Solution

Normalize or transcode unsupported image bytes at a shared inline-image boundary before provider payload construction, then prove Mistral, OpenAI Chat Completions, and OpenAI Responses send provider-accepted payloads.

## Reproduction Assessment

Yes for the patch defect by source inspection: the PR changes only the MIME string interpolated into data URLs while leaving the original base64 bytes unchanged. I did not run a live provider call in this read-only review.

## Solution Assessment

No. This is not the best fix because it changes the declared MIME without normalizing the encoded image bytes; the safer solution is byte conversion or byte-sniffed rejection before provider payload construction.
