Yes, at source level. Current main appends image `MediaPath` values as raw URLs and does not classify `media://inbound/<id>` as assistant-media proxyable, so a history message with that media ref cannot render inline after reload.

## Solution Assessment

Yes. Reusing the existing authenticated, ticketed assistant-media route with a raw one-segment inbound predicate is narrower and safer than adding a new public `/media/inbound` route.
