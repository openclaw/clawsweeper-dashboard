## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.87

Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:190-194`
  - body: `resolveExcludePatterns()` reads `${stateDir}/.backupignore` on every backup create, even when the user did not pass an exclude flag. That means an existing or injected file can change plain `openclaw backup create` output and silently omit restore data, contradicting the PR's backward-compatibility claim; make this explicit opt-in or get maintainer approval for the new default.
  - confidence: 0.88
- **[P1] Apply excludes to external backup assets:** `src/infra/backup-create.ts:364-368`
  - body: The PR builds one exclude filter rooted at `canonicalStateDir`, while workspaces and custom config/credential paths can live outside that root. Those assets are then archived in full despite explicit patterns, so users can still back up bulky or sensitive external files they asked to exclude; use per-asset filter bases or fail clearly before creating the archive.
  - confidence: 0.9
- **[P2] Do not rescan every archive during create:** `src/infra/backup-create.ts:528-529`
  - body: `listArchiveEntries(tempArchivePath)` reads the finished compressed archive and stores every entry during normal create, adding a second full pass over the same large backup path this PR is trying to make reliable. Gate this behind `--verify`, stream the check without retaining all entries, or provide realistic large-backup proof that it does not reintroduce the stall/OOM class.
  - confidence: 0.82
