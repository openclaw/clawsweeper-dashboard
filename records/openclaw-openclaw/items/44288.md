## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.93

Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:187-194`
  - body: This auto-loads `${stateDir}/.backupignore` on every backup unless `--include-all` is set, so an existing or injected state file can silently change backup contents even when the user did not pass any exclude flag. That breaks the PR's no-behavior-change promise and is risky for credential/restorable-state backups; make this explicit opt-in or get a maintainer-approved documented default.
  - confidence: 0.93
- **[P1] Apply excludes to every backup asset:** `src/infra/backup-create.ts:364-368`
  - body: The filter is rooted at `canonicalStateDir`, and assets outside that root are only warned about instead of filtered. Custom workspaces/config paths can still archive large or sensitive files despite explicit exclude patterns, so the implementation needs per-asset filter bases or a narrower documented scope before merge.
  - confidence: 0.94
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:528-535`
  - body: `listArchiveEntries(tempArchivePath)` decompresses the just-written archive and stores every entry path before publishing. For the multi-GB backups this PR is meant to unblock, that adds a second full archive pass and O(entry count) memory pressure; use streaming/accounted verification or leave the full scan to explicit verify.
  - confidence: 0.88
- **[P2] Preserve duplicate gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating patterns before passing them to `ignore` changes gitignore semantics because later duplicate rules can intentionally override an intervening negation, such as `*.log`, `!important.log`, `*.log`. Preserve the user's declared order and duplicates so the filter matches the dependency contract.
  - confidence: 0.9
