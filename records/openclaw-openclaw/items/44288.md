## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:187-194`
  - body: `resolveExcludePatterns()` reads `stateDir/.backupignore` even when the user passed no exclude flag. That means an existing file can silently change a normal backup and omit restore-critical data, which contradicts the PR's compatibility claim; make this file explicit opt-in or gated behind an exclude option.
  - confidence: 0.93
- **[P1] Apply excludes to every backup asset:** `src/infra/backup-create.ts:363-368`
  - body: The filter is rooted only at `canonicalStateDir`, and the later warning confirms external workspaces/custom config assets bypass patterns and are archived in full. Users who pass `--exclude '*.pem'` or `--smart-exclude` reasonably expect the rule to apply to all included backup assets, so this can include sensitive or huge external trees despite explicit excludes; use per-asset roots or an equivalent consistent matching model.
  - confidence: 0.92
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:528-529`
  - body: `listArchiveEntries()` reads the just-written `.tar.gz` and stores every entry before publish, adding a second full archive pass plus O(entry count) memory to the multi-GB backup path this feature is meant to help. Validate asset presence during the write or use a bounded streaming check instead.
  - confidence: 0.88
- **[P2] Preserve duplicate gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: Dropping later duplicate patterns changes order-sensitive gitignore semantics when a negation appears between duplicates, such as `*.log`, `!important.log`, `*.log`. Pass the ordered rule list through to `ignore` and track stats by rule identity instead of deduplicating by pattern text.
  - confidence: 0.9
