## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Require opt-in before loading .backupignore:** `src/infra/backup-exclude.ts:190-194`
  - body: This branch loads `${stateDir}/.backupignore` even when the user did not pass an exclude flag for this run. Backup contents are recovery- and security-sensitive, so an existing or tampered state file should not silently change default `openclaw backup create` output without an explicit opt-in mode.
  - confidence: 0.91
- **[P1] Apply excludes to every backup asset root:** `src/infra/backup-create.ts:378-382`
  - body: The PR now warns that external assets bypass excludes, but it still archives valid config, credentials, or workspace assets outside `stateDir` in full. Users and scripts passing `--exclude` or `--smart-exclude` need those patterns applied to each included root, not a warning after the archive plan has already widened.
  - confidence: 0.9
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:528-535`
  - body: The create path always reads the finished `.tar.gz` and stores every entry in memory to cross-check asset presence. That adds a second full archive pass and O(entry count) memory to the large-backup workflow this PR is trying to make reliable, so the check should be opt-in, streaming, or otherwise bounded.
  - confidence: 0.86
- **[P2] Preserve duplicate gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating first occurrences changes gitignore's ordered rule semantics: a later duplicate can intentionally re-ignore after a negation. Keep the rule list order intact unless a narrower normalization is proven equivalent for all negation cases.
  - confidence: 0.88
