Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:187-194`
  - body: `stateDir/.backupignore` is loaded for every backup unless `--include-all` is set, so an existing file can change the contents of a plain `backup create` after upgrade. Backup scope is a compatibility and restoreability contract, so this should be explicit or maintainer-approved rather than an implicit default.
  - confidence: 0.9
- **[P1] Apply excludes to every backup asset root:** `src/infra/backup-exclude.ts:358-364`
  - body: Paths outside the single `stateDir` base are always included, so explicit exclude rules do not affect external workspaces or custom config/credential assets. Warning after the fact still archives those assets in full, which can leave bulky or sensitive files in the backup despite the user's patterns.
  - confidence: 0.92
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:528-535`
  - body: The create path now lists the full archive and stores all entry names before publishing. On large backups this adds a second archive pass plus O(number of entries) memory, which undermines the availability problem the PR is trying to reduce.
  - confidence: 0.86
- **[P2] Preserve duplicate gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: Gitignore rule order is meaningful, including duplicate rules around negations. Deduplicating by first occurrence before passing rules to `ignore` can flip the final ignored/unignored result compared with the user's declared order.
  - confidence: 0.88
