Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:190-194`
  - body: This still loads `${stateDir}/.backupignore` for every backup when the file exists, even if the user runs a plain `openclaw backup create`. For backup/restore, that lets local state silently change archive contents without command-line opt-in; keep ignore-file loading behind explicit `--exclude-file` or a maintainer-approved default policy before merge.
  - confidence: 0.88
- **[P1] Apply excludes to external backup assets:** `src/infra/backup-exclude.ts:358-364`
  - body: The filter still returns `true` for every path outside the single `stateDir` base, while `resolveBackupPlanFromDisk` can include external workspaces and custom config/credential locations. A warning does not make explicit exclude rules apply, so users can still archive large or sensitive external assets in full despite `--exclude` or `.backupignore`.
  - confidence: 0.91
- **[P2] Avoid the mandatory full archive rescan:** `src/infra/backup-create.ts:528-535`
  - body: Every non-dry backup now calls `listArchiveEntries` and stores all archive paths before publish, even when the user did not request `--verify`. On multi-GB backups this adds a second full traversal plus O(entry count) memory, which can worsen the stall and memory-pressure class this PR is trying to fix.
  - confidence: 0.86
