## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Require opt-in before loading .backupignore:** `src/infra/backup-exclude.ts:189-194`
  - body: This reads `${stateDir}/.backupignore` even when no exclude flag is passed. That makes plain `openclaw backup create` start omitting files based solely on a pre-existing state-dir file, so existing users can get incomplete backups without explicitly opting into excludes.
  - confidence: 0.9
- **[P1] Apply excludes to external backup assets:** `src/infra/backup-exclude.ts:362-363`
  - body: Returning `true` for any path outside `baseDir` means excludes do not apply to custom config, credentials, or workspaces that `resolveBackupPlanFromPaths` can include outside `stateDir`. A warning still writes an archive containing files the user asked to exclude; filter per asset root or fail/narrow the feature instead.
  - confidence: 0.88
- **[P2] Preserve ordered duplicate gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating rules before passing them to `ignore` changes order-sensitive gitignore semantics. A sequence like `*.log`, `!important.log`, `*.log` intentionally re-overrides the negation, but this code drops the final rule and can include/exclude different files than the user declared.
  - confidence: 0.78
- **[P2] Do not rescan every backup during create:** `src/infra/backup-create.ts:528-529`
  - body: This reads the entire `.tar.gz` back into an in-memory array and then scans it for each asset after writing. For the large installations this PR is meant to help, that adds a second full archive pass plus O(entry count) memory pressure unless replaced with a streaming check or proven at realistic size.
  - confidence: 0.82
