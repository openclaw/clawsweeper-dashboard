## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve duplicate gitignore rules:** `src/infra/backup-exclude.ts:225-231`
  - body: `--exclude-file` promises gitignore syntax, but this first-occurrence dedupe changes order-sensitive negation behavior. For example, `*.log`, `!important.log`, `*.log` should end with `important.log` excluded, but the final rule is dropped here, so backups can include or omit files contrary to the user's declared rule order. Keep the ordered rule list intact and track source metadata without collapsing duplicates.
  - confidence: 0.88
- **[P2] Avoid rescanning every backup into memory:** `src/infra/backup-create.ts:528-529`
  - body: After writing the archive, this calls `listArchiveEntries()`, whose helper stores every tar entry path in an array. That adds a full second gzip read plus O(entry count) memory to every backup, including the large installations this PR is meant to unblock, and can reintroduce stalls or OOM before publish. Track required roots during write or stream the verification instead.
  - confidence: 0.84
- **[P3] Document the new backup contract:** `src/cli/program/register.backup.ts:31-41`
  - body: These new public backup flags and the auto-loaded `.backupignore` behavior are not reflected in `docs/cli/backup.md`. Users would still see only the coarse backup controls and no protected-path, smart-exclude, or manifest semantics, so the behavior/API change needs matching user docs before merge.
  - confidence: 0.78
