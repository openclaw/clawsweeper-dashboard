## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Require opt-in before auto-loading `.backupignore`:** `src/infra/backup-exclude.ts:187-194`
  - body: This always reads `${stateDir}/.backupignore` unless `--include-all` is set, so an existing or restored state file can change `openclaw backup create` even when the user passes no exclude flags. That contradicts the no-flag compatibility claim and makes backup scope depend on an implicit file; make this opt-in or require an explicit maintainer-approved default.
  - confidence: 0.9
- **[P1] Apply excludes to external backup assets:** `src/infra/backup-exclude.ts:358-364`
  - body: `createBackupArchive()` builds the filter with `stateDir` as its only base, and this branch includes every `../` or cross-drive path without applying the user's patterns. External workspaces or custom config paths will still be archived in full despite `--exclude` or `.backupignore`; the warning added later does not prevent the oversized or sensitive archive.
  - confidence: 0.91
- **[P2] Do not rescan every archive during create:** `src/infra/backup-create.ts:525-529`
  - body: This unconditional `listArchiveEntries()` decompresses the completed archive and stores every entry path after every backup, including the multi-GB backups this PR is intended to unblock. Keep the deep payload scan behind `--verify` or stream the check without retaining the full entry list.
  - confidence: 0.88
