## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:190-194`
  - body: The PR says existing backups are unchanged when no exclude flags are passed, but this code always reads `stateDir/.backupignore`. An existing file with that name turns plain `openclaw backup create` into a filtered backup during upgrade, so this needs an explicit opt-in or maintainer-approved default behavior before merge.
  - confidence: 0.92
- **[P1] Apply excludes to external backup assets:** `src/infra/backup-exclude.ts:362-363`
  - body: Returning true here makes every asset outside `stateDir` immune to `--exclude` and `.backupignore` rules. The backup planner can include external workspaces, config, or credentials, so patterns intended to remove large or sensitive files can silently leave those files in the archive.
  - confidence: 0.9
- **[P2] Avoid rescanning every archive during create:** `src/infra/backup-create.ts:528-529`
  - body: The exclude path already writes an uncompressed tar and gzips it; this extra `listArchiveEntries` call then reads every archive entry into memory before publish. On the large backups this PR targets, that adds another full pass and O(entry count) memory pressure, so validate expected assets without a full in-memory rescan.
  - confidence: 0.83
