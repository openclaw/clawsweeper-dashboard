## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:190-194`
  - body: This runs even when the user did not pass an exclude flag, so a pre-existing state-dir `.backupignore` silently changes default backup contents. That contradicts the branch's no-flags compatibility claim and can omit restore-critical data from normal backups; load this file only behind an explicit option or exclude mode.
  - confidence: 0.92
- **[P1] Apply excludes to external backup assets:** `src/infra/backup-create.ts:364-368`
  - body: The filter is rooted only at `stateDir`, and the later warning still archives external workspaces or custom config paths in full. Users who pass `--exclude '*.pem'` or `--smart-exclude` can still back up matching sensitive or huge files outside the state directory, so the implementation needs per-asset bases or another real filtering strategy before merge.
  - confidence: 0.91
- **[P2] Avoid rescanning the full archive during create:** `src/infra/backup-create.ts:528-529`
  - body: This integrity check reads the completed `.tar.gz` back and keeps every entry path in memory before publish. On the multi-GB backups this feature is meant to make usable, that adds another full I/O pass and O(entry count) memory pressure; switch to a bounded check or collect the necessary facts while writing.
  - confidence: 0.88
- **[P2] Preserve duplicate pattern order:** `src/infra/backup-exclude.ts:225-233`
  - body: Late discovery: this code was visible in earlier review cycles. Gitignore rules are order-sensitive, and duplicate patterns can intentionally re-override a negation, but this deduplication drops the later rule and changes the user's requested include/exclude result.
  - late: true
  - confidence: 0.82
