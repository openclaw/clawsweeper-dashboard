## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Require explicit opt-in for `.backupignore`:** `src/infra/backup-exclude.ts:190`
  - body: This loads `stateDir/.backupignore` even when the user did not pass `--exclude-file`, so an existing state file can start omitting backup contents after upgrade. Backup scope is a recovery and security boundary; make this explicit or get maintainer approval for the default behavior.
  - confidence: 0.9
- **[P1] Apply excludes to each backup asset root:** `src/infra/backup-create.ts:383-386`
  - body: The PR warns but still archives every external asset in full when patterns are active. Valid backup assets can include external workspaces or custom config paths, so `--exclude '*.log'` can leave large or sensitive files in the archive despite the user's rule.
  - confidence: 0.88
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:528-529`
  - body: `listArchiveEntries()` reads and stores every archive entry after writing the tarball. For the large backups this PR is trying to make practical, that mandatory second pass adds O(entries) memory and can reintroduce stalls or memory pressure before publication.
  - confidence: 0.84
- **[P2] Preserve ordered duplicate gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: Gitignore semantics are order-sensitive, and repeated patterns can intentionally override a negation later in the file. Deduplicating first occurrence wins can flip results such as `*.log`, `!important.log`, `*.log`, so pass the ordered rule list through to `ignore`.
  - confidence: 0.87
