## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:190-194`
  - body: This loads `${stateDir}/.backupignore` for every backup unless `--include-all` is set, even when the user did not request excludes. On upgrade, a leftover or locally written file can change the default catastrophic-loss backup scope and omit recovery-critical files. Keep default `backup create` behavior unchanged and load this file only behind an explicit flag/path or a maintainer-approved default.
  - confidence: 0.88
- **[P1] Apply excludes to each backup asset root:** `src/infra/backup-exclude.ts:358-364`
  - body: The filter returns `true` for every path outside `baseDir`, while the backup plan can include external workspaces and custom config/credential paths. The new warning still archives those trees in full, so `--exclude logs/` can fail exactly where large or sensitive workspace files live. Use per-asset filter bases or reject unsupported combinations instead of shipping a flag that knowingly does not apply to part of the archive.
  - confidence: 0.9
- **[P2] Avoid rescanning full archives during create:** `src/infra/backup-create.ts:525-529`
  - body: After writing, `createBackupArchive` calls `listArchiveEntries`, which decompresses and stores every archive entry before publish. Large backups are the problem this PR is trying to solve; adding a second full archive pass with O(entry count) memory can reintroduce stalls or memory pressure. Validate specific roots while streaming or keep this behind explicit verification.
  - confidence: 0.84
