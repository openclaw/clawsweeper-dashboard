## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:190-194`
  - body: This loads `${stateDir}/.backupignore` on every backup unless `--include-all` is passed, even when the user did not ask for excludes. An existing or injected file in the state dir can silently remove files from a normal backup, so this needs an explicit flag or another maintainer-approved opt-in path before merge.
  - confidence: 0.9
- **[P1] Apply excludes to every backup asset root:** `src/infra/backup-exclude.ts:362-364`
  - body: Returning `true` for paths outside `baseDir` means external workspaces, config, or credentials are archived in full whenever they sit outside `stateDir`. A warning does not make `--exclude '*.pem'` or `--smart-exclude` true for those assets, so the filter needs per-asset roots or equivalent behavior before this can be trusted.
  - confidence: 0.91
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:528-529`
  - body: The create path reads the completed `.tar.gz` back into an array of every entry before publishing. On the multi-GB backups this feature targets, that adds a second full archive pass and O(entry count) memory pressure; validate during streaming or keep this behind explicit verify instead.
  - confidence: 0.86
- **[P2] Preserve ordered gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating patterns before `ignore().add()` changes gitignore semantics because later duplicate rules can intentionally override an earlier negation. Keep the ordered rule list intact for matching, and only aggregate stats separately if needed.
  - confidence: 0.88
