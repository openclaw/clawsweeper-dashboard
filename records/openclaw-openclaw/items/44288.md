- **[P1] Rebase excludes onto the current backup writer:** `src/infra/backup-create.ts:469-475`
  - body: This exclude path builds a separate tar with only `excludeFilter`, but current main's writer now snapshots SQLite databases, skips live/transient state, disables tar hardlink reuse, and retries tar EOF races. Rebase the feature so excludes compose with that existing `tarFilter` path instead of replacing it, or backups can regress restore safety and large-state reliability.
  - confidence: 0.92
- **[P1] Gate implicit `.backupignore` loading:** `src/infra/backup-exclude.ts:187-194`
  - body: `resolveExcludePatterns(makeSpec(), stateDir)` loads `.backupignore` even when the user passes no exclude flag, so an existing state-dir file can silently change default backup contents. That is a compatibility and restore-safety decision; make it explicit opt-in or get maintainer-approved upgrade behavior before enabling it by default.
  - confidence: 0.9
- **[P1] Preserve verifier hardlink and manifest hardening:** `src/commands/backup-verify.ts:289-296`
  - body: Switching verification to a string-only entry list drops tar entry type/linkpath metadata, so the current main hardlink-target validation cannot run; this file also no longer has the current manifest-size limit while reading manifest data. Keep those verifier protections when adding `excludedStats` support.
  - confidence: 0.88
- **[P2] Avoid a full archive rescan during create:** `src/infra/backup-create.ts:528-535`
  - body: After writing the archive, this block reads every tar entry into an array and a set even when the user did not ask for `--verify`. Large archives are the motivating failure mode for this PR, so adding an unconditional second full pass can worsen runtime and memory pressure; validate during write or keep the expensive scan behind explicit verification.
  - confidence: 0.82
- **[P2] Keep duplicate rules in declared order:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating patterns changes gitignore semantics because later duplicate rules can intentionally re-override a negation, such as `*.log`, `!important.log`, `*.log`. Pass the declared rule order through to `ignore` and track source metadata separately so backup contents match the user's exclude file.
  - confidence: 0.78
