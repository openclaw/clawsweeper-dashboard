## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:187-194`
  - body: This still reads `stateDir/.backupignore` on every backup create, even when the user did not pass any exclude flag. An existing or injected file can therefore change normal backup contents without opt-in, contradicting the PR's compatibility claim and risking incomplete restore archives.
  - confidence: 0.91
- **[P1] Apply excludes to external backup assets:** `src/infra/backup-exclude.ts:358-364`
  - body: The filter still returns `true` for paths outside `stateDir`, while backup planning can include external workspaces or custom config paths. A warning does not make `--exclude` correct: those assets are archived in full despite explicit patterns, which can include the large or sensitive files users meant to omit.
  - confidence: 0.88
- **[P2] Avoid rescanning the full archive during create:** `src/infra/backup-create.ts:525-528`
  - body: After writing the archive, create now lists and stores every tar entry before publishing. On the multi-GB backups this PR is meant to help, that adds a second full archive read and O(entry count) memory; use streaming/bounded validation or keep the expensive scan behind explicit verify behavior.
  - confidence: 0.84
