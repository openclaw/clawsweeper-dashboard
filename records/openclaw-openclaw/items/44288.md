## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:190`
  - body: This runs on every `backup create`, even when no exclude flag was passed. A state-dir `.backupignore` can silently remove files from a recovery archive, so the no-flags path is not backward compatible and should not trust a local file unless the operator opted in.
  - confidence: 0.91
- **[P1] Apply excludes to external backup assets:** `src/infra/backup-exclude.ts:362-363`
  - body: Returning `true` for paths outside `stateDir` means external workspaces, custom config, or external credential assets are archived in full even when a user’s pattern should match them. The later warning does not make the archive obey the requested exclusion, so this still risks surprising size and sensitive-file inclusion.
  - confidence: 0.9
- **[P2] Avoid rescanning the full archive during create:** `src/infra/backup-create.ts:528`
  - body: `listArchiveEntries` reads the whole `.tar.gz` and stores every entry path after every backup with this PR’s create path. On the multi-GB/high-entry backups this feature targets, that adds a second full pass and O(entry count) memory before publish; keep this as explicit verify behavior or stream only the targeted validation.
  - confidence: 0.86
