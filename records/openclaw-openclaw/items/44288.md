Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:190-194`
  - body: This prior blocker is still present: every backup resolves `stateDir/.backupignore` even when the user did not request excludes. That can silently change the contents of an existing backup command after upgrade; make this explicit, for example by loading the file only with `--exclude-file` or another maintainer-approved opt-in.
  - confidence: 0.89
- **[P1] Apply excludes to external backup assets:** `src/infra/backup-create.ts:364-368`
  - body: The branch now warns about external assets, but it still archives those assets in full while exclude patterns are active. A user excluding large or sensitive workspace/config content would get a successful backup that ignores their rules for those paths, so the filter needs per-asset roots or the feature must stop promising that scope.
  - confidence: 0.87
- **[P2] Avoid rescanning every archive during create:** `src/infra/backup-create.ts:528-529`
  - body: This prior P2 is still present: `createBackupArchive` reads the full finished `.tar.gz` and stores every entry just to confirm asset roots. On the large backups this PR targets, that adds a second archive pass plus O(entry count) memory pressure; use streaming verification or keep this behind explicit verify instead.
  - confidence: 0.76
