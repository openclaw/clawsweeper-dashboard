## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Require explicit opt-in for `.backupignore`:** `src/infra/backup-exclude.ts:187-194`
  - body: This auto-loads `stateDir/.backupignore` even when the user passed no exclude flag, so an existing state file can silently change backup contents and break the PR's backward-compatibility claim. Load ignore-file rules only from an explicit flag/mode, or otherwise make the behavior a documented maintainer-approved compatibility change.
  - confidence: 0.92
- **[P1] Apply excludes to every backup asset:** `src/infra/backup-create.ts:363-368`
  - body: The filter is rooted at `canonicalStateDir`, while `resolveBackupPlanFromDisk` can include external workspaces, custom config, and external credentials assets; the later warning confirms those assets are archived in full. `--exclude` should either apply with per-asset bases or fail/limit the request instead of producing an archive with partial exclude semantics.
  - confidence: 0.9
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:525-529`
  - body: This cross-check reads the completed `.tar.gz` and stores every entry after every create, even without `--verify`. For the multi-GB backup cases this PR targets, that adds a second full pass and O(entry count) memory; keep this behind verify or stream a bounded check instead.
  - confidence: 0.88
- **[P2] Preserve gitignore rule order:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating later patterns changes order-sensitive gitignore semantics around negations, for example `*.log`, `!important.log`, `*.log` no longer has the final rule. Pass the ordered rule list through intact while tracking source metadata separately.
  - confidence: 0.86
