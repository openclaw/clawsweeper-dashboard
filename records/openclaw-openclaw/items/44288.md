Full review comments:

- **[P1] Rebase exclude creation onto the current backup writer:** `src/infra/backup-create.ts:469-476`
  - body: The exclude-enabled path calls `tar.c` directly over the planned assets. Current main now wraps tar creation with EOF retries, volatile-file filtering, SQLite snapshots/remaps, and temp-root safeguards; bypassing that path can restore torn SQLite state or reintroduce large-backup stalls when excludes are active.
  - confidence: 0.91
- **[P1] Gate implicit `.backupignore` loading:** `src/infra/backup-exclude.ts:190-194`
  - body: Pattern resolution always reads `.backupignore` from the state directory, even when the user did not pass an exclude flag. That makes an existing file silently change backup contents on upgrade, so this needs an explicit opt-in or maintainer-approved compatibility plan.
  - confidence: 0.9
- **[P1] Restore the manifest extraction size limit:** `src/commands/backup-verify.ts:202-209`
  - body: This manifest reader accumulates chunks without the current main 1 MiB cap. A malformed or hostile archive can force unbounded memory growth during `backup verify`, which is a regression from the current verifier.
  - confidence: 0.87
- **[P1] Keep archive entry metadata for hardlink checks:** `src/commands/backup-shared.ts:49-56`
  - body: The shared entry lister returns only normalized path strings, so `backupVerifyCommand` no longer sees `type` and `linkpath` metadata. Current main uses that metadata to reject hardlinks whose targets are missing or outside the archive root.
  - confidence: 0.86
- **[P2] Keep duplicate rules in declared order:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating patterns before passing them to `ignore` changes gitignore precedence when a later duplicate intentionally overrides an intervening negation, such as `*.log`, `!important.log`, `*.log`. Backup filters should preserve the user's rule order exactly.
  - confidence: 0.84
- **[P2] Avoid a full archive rescan during create:** `src/infra/backup-create.ts:528-529`
  - body: After writing the archive, this code reads every tar entry into memory just to check asset roots. For the multi-GB backups this feature targets, that adds a second full pass and O(entry count) memory pressure before the archive can publish.
  - confidence: 0.8
