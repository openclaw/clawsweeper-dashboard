## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.87

Full review comments:

- **[P1] Require explicit opt-in for `.backupignore`:** `src/infra/backup-exclude.ts:187-194`
  - body: This still auto-loads a state `.backupignore` during ordinary `openclaw backup create`, even when the user passed no exclude flag. That breaks the PR's no-behavior-change claim and can make existing recovery archives omit files after upgrade based only on a pre-existing state file; load it only under an explicit exclude mode or a dedicated flag.
  - confidence: 0.9
- **[P1] Apply excludes to every backup asset:** `src/infra/backup-create.ts:363-368`
  - body: The filter is rooted at `stateDir`, and assets outside that root are included in full. A warning does not make `--exclude '*.pem'` or `--smart-exclude` correct for external workspaces/config paths because the command still succeeds while archiving files the user asked to omit; use per-asset filter bases or fail the run when patterns cannot be honored.
  - confidence: 0.88
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:528-529`
  - body: This reads the finished `.tar.gz` and materializes every entry path for every backup, not only `--verify`. On the multi-GB backup path this PR is meant to improve, that adds a second full archive pass and O(entry count) memory pressure; keep full scans behind verify or replace this with a bounded streaming/presence check.
  - confidence: 0.87
- **[P2] Preserve duplicate gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: The deduplication step removes later duplicate patterns before passing rules to `ignore`, but gitignore rules are order-sensitive. A sequence like `*.log`, `!important.log`, `*.log` should end with `important.log` excluded, and dropping the final duplicate changes the user's declared policy.
  - confidence: 0.82
