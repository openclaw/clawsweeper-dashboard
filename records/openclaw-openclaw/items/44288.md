## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Require explicit opt-in for .backupignore:** `src/infra/backup-exclude.ts:187-194`
  - body: This auto-loads `.backupignore` from the state directory even when the user runs ordinary `openclaw backup create` with no exclude flags. That contradicts the PR's compatibility claim and lets an existing local file silently change backup contents on upgrade; only read this file when the user opts into exclude behavior.
  - confidence: 0.92
- **[P1] Apply excludes to every backup asset:** `src/infra/backup-create.ts:378-388`
  - body: The filter is rooted at `stateDir`, so external workspaces and custom config assets bypass all exclude patterns; the new warning still proceeds with a backup that includes those assets in full. Users can therefore request excludes for large or sensitive workspace files and still archive them, so the implementation needs per-asset filter bases or an explicit fail/opt-out path.
  - confidence: 0.9
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:528-529`
  - body: After writing the archive, this reads every tar entry into memory to verify asset presence. On the multi-GB backups this feature targets, that adds another full gzip/tar pass plus an O(entry count) set, increasing the chance of the same stalls or memory pressure the PR is trying to reduce.
  - confidence: 0.86
- **[P2] Preserve gitignore rule order:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating patterns before passing them to `ignore` changes gitignore semantics because later duplicate rules can intentionally override an earlier negation. Preserve the original ordered rule list and track stats without collapsing meaningful duplicates.
  - confidence: 0.84
