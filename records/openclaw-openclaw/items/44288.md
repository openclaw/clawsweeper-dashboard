Overall correctness: patch is incorrect

Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:190-193`
  - body: `resolveExcludePatterns` reads `stateDir/.backupignore` for every backup create call, so an existing file from local experiments or tooling changes plain `openclaw backup create` after upgrade and can omit files without the user passing an exclude flag. Make this opt-in or land it behind an explicit maintainer-approved default with upgrade docs/tests.
  - confidence: 0.92
- **[P1] Apply excludes to external backup assets:** `src/infra/backup-exclude.ts:362-363`
  - body: The filter returns `true` for paths outside `baseDir`, while backup planning can include external workspace/config/credential assets. That means `--exclude '*.pem'` or `--exclude logs/` is ignored for those assets, so sensitive or bulky external content can still be archived despite the explicit exclude.
  - confidence: 0.9
- **[P2] Avoid rescanning every archive during create:** `src/infra/backup-create.ts:528`
  - body: After writing the archive, the create path calls `listArchiveEntries`, which reads the full `.tar.gz` and stores every entry path before publish. For multi-GB installs this adds a second full pass plus O(entry count) memory to the flow that is trying to avoid backup stalls; make this streaming/optional or prove it at realistic size.
  - confidence: 0.84
