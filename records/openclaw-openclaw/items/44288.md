Full review comments:

- **[P1] Require explicit opt-in for `.backupignore`:** `src/infra/backup-exclude.ts:190-194`
  - body: This branch still auto-loads `stateDir/.backupignore` even when the user passes no exclude flag. That violates the PR's backward-compatibility claim and can silently change catastrophic-loss backup contents for an existing setup; make `.backupignore` loading opt-in through an explicit flag/path or only activate it when maintainers choose that product contract.
  - confidence: 0.88
- **[P1] Apply excludes to every backup asset root:** `src/infra/backup-create.ts:364-367`
  - body: The filter is rooted only at `stateDir`, and the create path now warns while still archiving external workspaces or custom config paths in full. That leaves explicit patterns ineffective for a central workspace use case and can still include large or sensitive external files; build per-asset filters or otherwise apply the rules to each included asset root before landing.
  - confidence: 0.9
- **[P2] Avoid rescanning the whole archive on create:** `src/infra/backup-create.ts:528`
  - body: This integrity check reads the finished `.tar.gz` and stores every entry path before publishing. For multi-GB backups with many files, that adds a second full pass and O(entry count) memory to the same path this PR is trying to make viable; replace it with streaming validation or a narrower check.
  - confidence: 0.82
