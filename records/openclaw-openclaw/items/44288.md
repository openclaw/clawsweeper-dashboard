## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:187-194`
  - body: `createBackupArchive()` resolves exclude patterns for every backup, and this block auto-loads `stateDir/.backupignore` even when no exclude flag was passed. A pre-existing or locally tampered file can silently change default backup contents on upgrade, so persistent exclude files need an explicit opt-in path before merge.
  - confidence: 0.93
- **[P1] Apply excludes to each backup asset root:** `src/infra/backup-exclude.ts:358-364`
  - body: This branch treats every path outside the state-directory base as included, while backup plans can also include external workspaces, config, or credentials paths. A warning later in `createBackupArchive()` still archives those assets in full despite explicit user patterns, so the filter needs per-asset bases or an equivalent design.
  - confidence: 0.91
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:528-529`
  - body: The create path now reads the entire `.tar.gz` back into an in-memory entry list before publishing it. On the multi-GB backups this feature targets, that adds a second full archive pass plus O(entry count) memory pressure; keep the integrity check streaming, optional, or in `backup verify` instead.
  - confidence: 0.88
- **[P2] Preserve duplicate gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: This de-duplicates patterns before handing them to `ignore`, but gitignore rules are order-sensitive and a duplicate after a negation can intentionally override that negation. Dropping later duplicates can flip include/exclude behavior compared with the user's declared file order.
  - confidence: 0.86
