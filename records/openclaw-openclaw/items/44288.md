## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.8

Full review comments:

- **[P1] Keep .backupignore from changing plain backups:** `src/infra/backup-exclude.ts:189-194`
  - body: `resolveExcludePatterns` reads `stateDir/.backupignore` on every `backup create` unless `--include-all` is set, even when the user did not pass any exclude flag. That makes a plain backup omit files solely because a newly recognized file happens to exist, contradicting the no-flags compatibility claim and changing the restorable backup contract. Gate auto-loading behind an explicit exclude mode or make the default change a documented maintainer decision with upgrade proof.
  - confidence: 0.86
- **[P2] Preserve duplicate gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: The code removes later duplicates before calling `ignore().add()`, but gitignore rules are order-sensitive: a later duplicate can intentionally override a negation in between. Dropping that rule can include or exclude different files than the user requested, which is especially risky for backups. Keep the ordered rule list intact and track provenance by rule occurrence rather than by pattern string.
  - confidence: 0.82
