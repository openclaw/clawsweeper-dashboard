## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Require opt-in before loading .backupignore:** `src/infra/backup-exclude.ts:187-194`
  - body: `resolveExcludePatterns()` reads `${stateDir}/.backupignore` for every backup unless `--include-all` is set, so normal `openclaw backup create` output can change without the user opting into excludes. Backup scope is recovery-critical; keep default backups unchanged and only load this file from an explicit flag/path or explicit smart-exclude mode.
  - confidence: 0.91
- **[P1] Apply excludes to every backup asset:** `src/infra/backup-create.ts:363-388`
  - body: The filter is rooted at `canonicalStateDir`, and assets outside it are only warned and archived in full. `--exclude '*.pem'`, `.env*`, or `--smart-exclude` will not filter external workspaces or custom config, so sensitive or large files remain despite requested excludes; use per-asset roots or a fail/skip policy before merge.
  - confidence: 0.93
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:528-535`
  - body: After writing the archive, this code reads every tar entry into memory and does nested scans for every asset. That adds a second full archive pass and O(entries) memory in the large-backup path this PR is meant to improve; use targeted streaming validation or leave full listing to `backup verify`.
  - confidence: 0.87
- **[P2] Preserve duplicate gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating patterns drops later duplicate rules, but gitignore order makes duplicates meaningful around negations such as `*.log`, `!important.log`, `*.log`. Preserve the full rule order and track source metadata separately so user rules do not flip behavior.
  - confidence: 0.9
