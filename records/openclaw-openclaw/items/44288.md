  - body: The exclude-enabled path creates a separate tar from `result.assets` and bypasses current main's live SQLite snapshots, volatile-file filter, tar EOF retry wrapper, and link-cache handling.   - confidence: 0.9
- **[P1] Gate implicit `.backupignore` loading:** `src/infra/backup-exclude.ts:187-194`
  - body: This always loads `stateDir/.backupignore` unless `--include-all` is set, so `openclaw backup create` can omit files for users who did not pass any exclude flag. That contradicts the backward-compatibility claim and is risky for restore-critical backup contents.
  - confidence: 0.88
- **[P1] Preserve verifier entry metadata:** `src/commands/backup-shared.ts:49-58`
  - body: Moving archive listing to a shared helper that returns only path strings drops `type` and `linkpath`, so the verifier cannot keep current main's hardlink target validation. Keep entry metadata in the shared listing or leave the verifier's metadata-aware path intact.
  - confidence: 0.86
- **[P2] Keep duplicate rules in declared order:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating patterns before passing them to `ignore` changes gitignore semantics because later duplicate rules can intentionally override an intervening negation. Preserve the full ordered rule list and track stats separately so user-declared precedence is not changed.
  - confidence: 0.78
- **[P2] Avoid a full archive rescan during create:** `src/infra/backup-create.ts:525-542`
  - body: The create path reads the finished archive and stores every entry path to validate asset roots, adding a second full pass and O(entry count) memory to the same large-backup scenarios this PR is trying to improve. Reuse writer-side facts or stream validation without materializing all entries.
  - confidence: 0.74
