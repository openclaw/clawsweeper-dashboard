## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:187-194`
  - body: `resolveExcludePatterns` reads `${stateDir}/.backupignore` on every backup create even when the user passed no exclude option. That creates a hidden backup-content control file: an existing or planted state-dir file can silently omit data from normal backups, which contradicts the PR's no-behavior-change claim and needs an explicit opt-in flag, documented migration, or maintainer-approved default.
  - confidence: 0.9
- **[P1] Apply excludes to external backup assets:** `src/infra/backup-exclude.ts:358-364`
  - body: The filter returns `true` for any path outside the state-dir base, while `createBackupArchive` can also include external workspaces, custom config paths, or credentials directories. A warning still archives those assets in full despite explicit exclude rules, so sensitive or large external content can remain in the backup; use per-asset filter bases or fail/disable excludes for unsupported assets instead.
  - confidence: 0.9
- **[P2] Avoid rescanning the full archive during create:** `src/infra/backup-create.ts:525-535`
  - body: The create path now calls `listArchiveEntries` after every archive write and stores the full entry list in memory before publish. On the multi-GB backups this feature targets, that adds a second full `.tar.gz` pass and O(entry count) memory pressure even for no-exclude backups; keep that work behind verify or stream a bounded check instead.
  - confidence: 0.86
