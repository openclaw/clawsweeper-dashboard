## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Require opt-in before loading .backupignore:** `src/infra/backup-exclude.ts:187-194`
  - body: `openclaw backup create` currently means archive the resolved backup plan unless the user passes an existing size reducer. This PR always reads `stateDir/.backupignore`, so an already-present file can change normal backup contents on upgrade without an explicit backup flag and omit restorable user data. Make this explicit, gate it behind the chosen exclude mode, or get a maintainer-approved default with upgrade proof.
  - confidence: 0.87
- **[P2] Apply excludes to external backup assets:** `src/infra/backup-exclude.ts:358-363`
  - body: The filter is rooted at the state directory and returns `true` for `../` paths, so external workspaces and custom config assets bypass every exclude pattern. Workspaces are the documented main size driver, so commands like `--exclude node_modules/` will not affect a common backup payload; warning about the bypass is not enough for the advertised feature.
  - confidence: 0.89
- **[P2] Preserve duplicate gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: `ignore` applies rules in order, and later duplicate positive rules can intentionally override an intervening negation such as `*.log`, `!important.log`, `*.log`. Deduplicating before calling `ignore` changes the user-declared rule order and can include or omit different backup files than requested.
  - confidence: 0.9
