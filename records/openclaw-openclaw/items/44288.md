Full review comments:

- **[P1] Gate automatic .backupignore loading:** `src/infra/backup-exclude.ts:187-194`
  - body: This reads `.backupignore` from the state directory on every backup unless `--include-all` is set, so an existing file can change archive contents even when the user passes no exclude flag. Current main has no exclude semantics and the PR promises no behavior change without exclude flags, so auto-loading needs to be explicit or maintainer-approved before merge.
  - confidence: 0.9
- **[P1] Preserve archive entry metadata for verify:** `src/commands/backup-shared.ts:49-56`
  - body: The shared listing now returns only path strings. `backup verify` no longer sees tar entry `type` or `linkpath`, which drops current main's hardlink target validation and lets broken or unsafe hardlink entries pass verification.
  - confidence: 0.91
- **[P1] Restore the manifest size limit:** `src/commands/backup-verify.ts:202-210`
  - body: This manifest extractor accumulates chunks without the current `MAX_MANIFEST_BYTES` cap. A crafted or corrupt backup can force unbounded memory use during `backup verify`, so keep the bounded reader from current main when adding `excludedStats`.
  - confidence: 0.88
- **[P1] Rebase excludes onto the hardened backup writer:** `src/infra/backup-create.ts:469-476`
  - body: The exclude path calls `tar.c` directly on source assets and then gzips the tar, but current main's writer now wraps archive creation with retry handling, SQLite snapshot/remap, volatile-path filtering, and link-cache behavior. The exclude implementation needs to compose with that writer instead of forking an older path.
  - confidence: 0.86
- **[P2] Avoid the unconditional full archive rescan:** `src/infra/backup-create.ts:528-529`
  - body: Every create now reads the completed `.tar.gz` back into an in-memory entry list before publishing. For the multi-GB backups this feature is meant to unblock, that adds a second full pass and O(entry count) memory even when the user did not ask for `--verify`.
  - confidence: 0.84
- **[P2] Keep ordered duplicate ignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating patterns changes gitignore order semantics when duplicate rules are separated by negation, for example `*.log`, `!important.log`, `*.log`. Since the PR promises gitignore syntax, preserve the ordered rule list and track source metadata without removing later duplicates.
  - confidence: 0.79
