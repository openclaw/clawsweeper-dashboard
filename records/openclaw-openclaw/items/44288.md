Overall confidence: 0.9

Full review comments:

- **[P1] Rebase exclude archives onto the hardened writer:** `src/infra/backup-create.ts:469-475`
  - body: The exclude path writes a separate tar directly from `result.assets`, so it bypasses current main's retry wrapper, SQLite snapshot/remap handling, and volatile-file filter. That can reintroduce live-write failures or unsafe SQLite/archive contents when excludes are active.
  - confidence: 0.9
- **[P1] Gate automatic .backupignore loading:** `src/infra/backup-exclude.ts:187-194`
  - body: Loading `stateDir/.backupignore` automatically changes backup contents even when the user did not pass an exclude flag. Backup contents are restore- and security-sensitive, so this needs an explicit opt-in or maintainer-approved compatibility plan before merge.
  - confidence: 0.88
- **[P1] Restore the manifest size limit:** `src/commands/backup-verify.ts:202-210`
  - body: `extractManifest` now buffers the manifest entry without the `MAX_MANIFEST_BYTES` cap present on main. A malformed or hostile archive can force unbounded memory use during `backup verify`.
  - confidence: 0.88
- **[P1] Preserve archive entry metadata for hardlink checks:** `src/commands/backup-shared.ts:49-56`
  - body: The shared entry lister returns only path strings, but current verification needs `type` and `linkpath` to reject hardlinks that target missing entries or escape the archive root. This drops verifier hardening while moving the helper.
  - confidence: 0.86
- **[P2] Avoid the unconditional full archive rescan:** `src/infra/backup-create.ts:528-535`
  - body: After every exclude backup, the code reads the entire `.tar.gz` back into an in-memory path list. For multi-GB backups, that extra full pass can materially increase runtime and memory pressure.
  - confidence: 0.8
