## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:190-194`
  - body: `resolveExcludePatterns` always reads `stateDir/.backupignore`, even when the user did not pass any exclude-related flag. That changes the default backup contract and lets a state-dir file silently omit backup contents during an ordinary `openclaw backup create`; make file-based excludes explicit, or only load this file behind a deliberate flag/contract.
  - confidence: 0.91
- **[P1] Apply excludes to external backup assets:** `src/infra/backup-exclude.ts:358-364`
  - body: The filter treats every path outside `baseDir` as included, and `createBackupArchive` builds that base from only the state directory. A warning is not enough for `--exclude`/`.backupignore`: external workspaces or custom config paths are still archived in full despite matching patterns, so sensitive or multi-GB content can remain in the archive.
  - confidence: 0.9
- **[P2] Avoid rescanning the full archive during create:** `src/infra/backup-create.ts:528-535`
  - body: The create path always lists the whole `.tar.gz` into memory before publish. For the same large backups this feature is meant to unblock, that adds a second full archive pass plus O(number of entries) memory; keep this behind `--verify` or replace it with a bounded/streaming integrity check.
  - confidence: 0.86
- **[P2] Preserve gitignore rule order:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating patterns before passing them to `ignore` changes ordered gitignore semantics, especially when duplicate rules appear around negations. Preserve the user's rule sequence so patterns like `*.log`, `!important.log`, `*.log` keep their declared final result.
  - confidence: 0.84
