## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Require explicit opt-in for `.backupignore`:** `src/infra/backup-exclude.ts:187-194`
  - body: This is still present from the previous review cycle. `resolveExcludePatterns` reads `${stateDir}/.backupignore` for every backup unless `--include-all` is set, even when the user did not pass an exclude flag. That makes an existing or newly created file an ambient backup policy surface and can silently omit restore data on upgrade; require an explicit flag or a maintainer-approved migration/default contract before loading it.
  - confidence: 0.92
- **[P1] Apply excludes to every backup asset:** `src/infra/backup-exclude.ts:358-364`
  - body: This remains unresolved as code behavior; the new warning does not make the exclude semantics correct. `createBackupArchive` builds one filter rooted at `stateDir`, and this guard returns `true` for external workspaces or custom config paths, so explicit `--exclude` and `.backupignore` patterns silently do not filter those assets. Use per-asset filter bases or fail the unsupported combination instead of archiving sensitive or bulky external trees in full.
  - confidence: 0.9
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:525-529`
  - body: This cross-check reads the full `.tar.gz` and keeps every entry path in memory before publishing every backup. For the multi-GB installations this PR targets, that adds another full archive pass and O(entry count) memory pressure after compression; keep full archive enumeration behind `--verify` or replace it with a streaming/bounded check.
  - confidence: 0.87
- **[P2] Preserve gitignore rule order:** `src/infra/backup-exclude.ts:225-233`
  - body: This is still present from the previous review cycle. Deduplicating pattern strings changes gitignore semantics because later matching rules can intentionally override a negation, for example `*.log`, `!important.log`, `*.log`. The `ignore` dependency evaluates rules in insertion order, so pass the ordered list through intact and track source metadata without collapsing duplicates.
  - confidence: 0.89
