Overall correctness: patch is incorrect

Full review comments:

- **[P1] Apply exclude rules to external assets:** `src/infra/backup-exclude.ts:362-364`
  - body: `buildExcludeFilter` returns `true` for every path outside `stateDir`, but the backup plan can include external workspaces and custom config/credential assets. That means `--exclude ".env*"`, `--exclude "node_modules/"`, or `--smart-exclude` still archives those external assets in full; a warning does not make the requested filter behavior true or safe for non-interactive backups.
  - confidence: 0.91
- **[P2] Preserve ordered gitignore rules:** `src/infra/backup-exclude.ts:229-231`
  - body: This deduplication removes later duplicate patterns before passing rules to `ignore`, but gitignore semantics are order-sensitive with negation. For example `*.log`, `!important.log`, `*.log` should leave `important.log` excluded, while this PR drops the final rule and includes it instead.
  - confidence: 0.88
- **[P2] Avoid loading the entire archive listing:** `src/infra/backup-create.ts:528-529`
  - body: Every exclude-enabled backup now rereads the freshly written tarball and stores all entry paths in an array before publishing. On the large state trees this feature is meant to help, that second full archive pass plus O(entry count) memory can turn backup creation into another stall or memory-pressure path; validate required roots with a streaming check instead.
  - confidence: 0.78
