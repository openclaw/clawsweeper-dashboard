## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Require explicit opt-in for `.backupignore`:** `src/infra/backup-exclude.ts:187-194`
  - body: This reads `${stateDir}/.backupignore` for every backup unless `--include-all` is set, so an existing or injected state-local file can silently change backup contents even when the user passed no exclude option. Backup completeness is recovery-critical; make ignore-file loading an explicit flag or a maintainer-approved default with upgrade proof.
  - confidence: 0.91
- **[P1] Apply excludes to every backup asset:** `src/infra/backup-create.ts:363-368`
  - body: The filter is rooted at `canonicalStateDir`, and the new warning leaves external workspaces or custom config assets archived in full. That means `--exclude` can still fail to filter the largest or most sensitive backed-up content; the implementation should apply patterns per asset root or clearly avoid promising global backup excludes.
  - confidence: 0.9
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:525-529`
  - body: The create path now reads the completed `.tar.gz` and stores every entry path before publishing. On multi-GB backups this adds a second full archive pass and O(entry count) memory, which can worsen the same large-backup stall or pressure scenario the feature is meant to address.
  - confidence: 0.86
- **[P2] Preserve duplicate gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating patterns changes gitignore semantics because repeated rules can intentionally override an intervening negation, such as `*.log`, `!important.log`, `*.log`. Preserve the ordered rule list for matching, and track stats by rule or by pattern separately if aggregation still needs de-duping.
  - confidence: 0.88
