## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Require explicit opt-in for .backupignore:** `src/infra/backup-exclude.ts:189-194`
  - body: This auto-loads `${stateDir}/.backupignore` for ordinary backups, so a file in the state directory can silently change what gets archived even when the user did not request exclude behavior. Backup contents are a restore/security boundary; load an exclude file only through an explicit flag or maintainer-approved opt-in path.
  - confidence: 0.9
- **[P1] Apply excludes to each backup asset root:** `src/infra/backup-create.ts:364-368`
  - body: The filter is built against `canonicalStateDir`, while `resolveBackupPlanFromDisk()` can include external workspaces and custom config/credential paths. The current warning still archives those assets in full, so `--exclude` can fail to remove large or sensitive files exactly where users asked it to apply.
  - confidence: 0.88
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:528-529`
  - body: `listArchiveEntries()` reads the just-written `.tar.gz` and stores every path before publish. On multi-GB backups this adds a full second archive pass plus O(entry count) memory pressure in the same path meant to prevent large backup stalls; make the create-time check streaming or bounded to the required asset roots.
  - confidence: 0.86
- **[P2] Preserve ordered gitignore rules:** `src/infra/backup-exclude.ts:229-231`
  - body: Dropping later duplicate patterns changes gitignore semantics because later matches can intentionally override earlier negations. For example, `*.log`, `!important.log`, `*.log` should end with `important.log` excluded, but this dedupe removes the final rule and flips the result.
  - confidence: 0.84
