  - body: `resolveExcludePatterns()` reads `${stateDir}/.backupignore` on every backup unless `--include-all` is passed, even when the user did not ask for file-based excludes. An existing or injected state-dir file can silently change backup scope, so this needs an explicit flag or another maintainer-approved opt-in path before merge; this prior blocker remains unresolved at the current head.
  - confidence: 0.9
- **[P1] Apply excludes to each backup asset root:** `src/infra/backup-exclude.ts:358-364`
  - body: The filter returns `true` for paths outside `baseDir`, and `createBackupArchive()` builds it with only the state directory. External workspaces, config, or credentials are archived in full even when they contain files matching `--exclude` or `.backupignore`; warning users about the bypass does not make the exclude behavior true. This prior blocker remains unresolved at the current head.
  - confidence: 0.92
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:528-529`
  - body: `createBackupArchive()` calls `listArchiveEntries()` before the final rename, and that helper runs `tar.t` while pushing every entry path into an array. For multi-GB backups with many files, this adds a second full archive pass and O(entry count) memory use to the workflow this PR is meant to relieve. This prior blocker remains unresolved at the current head.
  - confidence: 0.88
- **[P2] Preserve duplicate gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: The dedupe pass removes later repeated patterns before `ignore` sees them, but ordered gitignore rules can intentionally repeat a pattern after a negation, such as `*.log`, `!important.log`, `*.log`. Dropping the later duplicate changes the final include/exclude decision from the user's rule order. This prior blocker remains unresolved at the current head.
  - confidence: 0.88
