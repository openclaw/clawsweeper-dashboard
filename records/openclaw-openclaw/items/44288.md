## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Require opt-in before loading .backupignore:** `src/infra/backup-exclude.ts:187-194`
  - body: `resolveExcludePatterns()` auto-loads `stateDir/.backupignore` for every backup unless `--include-all` is passed. That contradicts the PR's no-behavior-change claim: an existing or newly created file in the state directory can silently remove backup contents from a plain `openclaw backup create`, including recovery-critical state. Make this explicit behind a flag or only load the file when exclude mode is requested.
  - confidence: 0.93
- **[P2] Apply excludes to external backup assets:** `src/infra/backup-exclude.ts:358-364`
  - body: The filter is rooted at `stateDir` and returns `true` for `../` or cross-drive paths, while the backup plan can include external workspaces, configs, and credentials. A user-supplied `--exclude '*.pem'` or `--exclude node_modules/` therefore does not filter those assets; warning after choosing to archive them in full is not enough for the advertised exclude behavior.
  - confidence: 0.9
- **[P2] Preserve duplicate gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating patterns changes gitignore semantics because later duplicate rules can intentionally re-override a negation, for example `*.log`, `!important.log`, `*.log`. Keep the ordered rule list intact for matching and track stats with a separate id/source structure instead of removing duplicates before passing rules to `ignore`.
  - confidence: 0.95
- **[P2] Do not rescan every backup during create:** `src/infra/backup-create.ts:525-529`
  - body: The post-tar check calls `listArchiveEntries()` unconditionally, which decompresses the whole archive and stores every entry path in memory even when the user did not request `--verify`. That adds a second full pass to the large-backup path this PR is meant to help, so gate this behind verify or stream-check only the expected roots.
  - confidence: 0.86
- **[P3] Document the new backup exclude flags:** `src/cli/program/register.backup.ts:30-52`
  - body: The PR registers six new `backup create` flags and changes manifest output, but the user-facing backup docs still only describe the existing coarse controls. Add docs for the exclude contract, protected paths, .backupignore behavior, manifest field, and external-asset limitation before exposing the new CLI surface.
  - confidence: 0.84
