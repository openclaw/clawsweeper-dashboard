- **[P1] Rebuild on the current backup safety path:** `src/infra/backup-create.ts:469-475`
  - body: At this head the exclude path writes `result.assets` directly and predates current main's SQLite snapshotting, volatile-file filter, tar retry, and temp-root placement.   - confidence: 0.84
- **[P1] Apply excludes to external backup assets:** `src/infra/backup-exclude.ts:358-363`
  - body: The filter returns `true` for every path outside `stateDir`, but backup plans can include external workspaces, config, and credentials. A user-supplied pattern like `*.pem` or `logs/` will not apply there, so sensitive or bulky external files can still be archived despite the explicit exclude.
  - confidence: 0.92
- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:187-194`
  - body: `resolveExcludePatterns()` always reads `stateDir/.backupignore`, even when the user runs plain `openclaw backup create` with no exclude flags. That changes existing backup scope based on a newly meaningful local file and can silently omit restore-critical state despite the PR's compatibility claim.
  - confidence: 0.9
- **[P2] Preserve ordered duplicate patterns:** `src/infra/backup-exclude.ts:225-233`
  - body: Gitignore rules are order-sensitive, but this deduplication keeps only the first occurrence. A sequence like `*.log`, `!important.log`, `*.log` should end with `important.log` excluded; dropping the final duplicate flips the user's declared precedence.
  - confidence: 0.82
- **[P2] Avoid rescanning every archive during create:** `src/infra/backup-create.ts:525-535`
  - body: The post-create check calls `listArchiveEntries()` and stores every tar entry before publish. For the multi-GB backups this PR is meant to help, that adds a second full archive pass plus O(entry count) memory before the user gets a result.
  - confidence: 0.78
