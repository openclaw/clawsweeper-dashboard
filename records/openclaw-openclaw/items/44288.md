## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:190-194`
  - body: `resolveExcludePatterns()` reads `stateDir/.backupignore` on every backup unless `--include-all` is passed, even when the user did not request excludes. That makes an existing or injected state file silently change recovery archive contents; auto-loading should be removed or gated behind an explicit opt-in/default decision.
  - confidence: 0.93
- **[P1] Apply excludes to external backup assets:** `src/infra/backup-exclude.ts:362-364`
  - body: The filter returns `true` for any path outside the single `stateDir` base, so custom config, credentials, or external workspace assets are archived in full even when they match `--exclude` or `.backupignore`. The warning added later is not enough because the requested exclusion contract still does not hold for valid backup assets.
  - confidence: 0.92
- **[P2] Avoid rescanning the full archive during create:** `src/infra/backup-create.ts:528-535`
  - body: After writing the archive, this path calls `listArchiveEntries()` and stores every tar entry before publish. For multi-GB backups, that adds a second full gzip/tar pass and O(entry count) memory pressure in the same workflow users report stalling, so the integrity check needs a streaming or narrower design.
  - confidence: 0.88
- **[P2] Preserve gitignore rule order:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating patterns before passing them to `ignore` changes gitignore precedence for repeated rules around negations, such as `*.log`, `!important.log`, `*.log`. Since this feature promises gitignore syntax, rules should be evaluated in authored order instead of first-occurrence deduped.
  - confidence: 0.86
