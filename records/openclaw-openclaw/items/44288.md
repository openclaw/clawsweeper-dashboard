## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Require opt-in before loading `.backupignore`:** `src/infra/backup-exclude.ts:190-194`
  - body: This auto-loads `${stateDir}/.backupignore` for every backup unless `--include-all` is passed, so a pre-existing or injected state-dir file can silently change backup contents even when the user did not request excludes. That violates the stated no-flags compatibility claim; make this explicit opt-in or require a maintainer-approved config contract and upgrade proof.
  - confidence: 0.9
- **[P1] Apply excludes to every backup asset root:** `src/infra/backup-create.ts:363-368`
  - body: The filter is rooted only at `canonicalStateDir`, while backup planning can include external workspaces, config, and credentials. The new warning still archives those assets in full, so `--exclude '*.pem'` or `--smart-exclude` can fail to affect the exact files users expect to control; build filters per asset root or otherwise make the command reject unsupported asset scopes.
  - confidence: 0.91
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:528-529`
  - body: The create path now reads the completed `.tar.gz` into an array of every entry before publishing. On the multi-GB backups this feature targets, that adds a second full archive pass and O(entry count) memory pressure; validate during streaming or keep the expensive listing behind explicit verify.
  - confidence: 0.86
- **[P2] Preserve ordered gitignore rules:** `src/infra/backup-exclude.ts:225-233`
  - body: Deduplicating patterns before `ignore().add()` changes gitignore semantics because later duplicate rules can intentionally override an earlier negation, such as `*.log`, `!important.log`, `*.log`. Keep the ordered rule list intact for matching, and aggregate stats separately if needed.
  - confidence: 0.88
