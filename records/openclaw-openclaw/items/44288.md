Full review comments:

- **[P1] Require explicit opt-in for `.backupignore`:** `src/infra/backup-exclude.ts:171-185`
  - body: This PR auto-loads `${stateDir}/.backupignore` whenever `backup create` runs without `--include-all`, so an existing file in state can start removing content from backups even when the user did not ask this run to use an exclude file. Because backups are a restore/safety boundary, implicit state-file policy needs maintainer approval or an explicit flag before merge.
  - confidence: 0.89
- **[P1] Apply excludes to each backup asset root:** `src/infra/backup-create.ts:458-473`
  - body: `buildExcludeFilter` is still rooted at the canonical state directory, and the PR now only warns when external workspaces or custom config files bypass that filter. That means `--exclude` can archive those assets in full despite matching patterns, which is not the contract users expect from backup excludes and can keep large or sensitive content in the archive.
  - confidence: 0.9
- **[P2] Avoid rescanning large archives during create:** `src/infra/backup-create.ts:352-357`
  - body: The integrity check calls `listArchiveEntries`, which reads every entry in the newly-created `.tar.gz` into memory before the rename. On multi-GB installations with many files, this adds a second full archive pass and O(entry count) memory on the path this PR is meant to make reliable.
  - confidence: 0.82
