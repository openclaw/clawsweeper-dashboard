## What This Changes

Report that running `openclaw doctor --fix` while a gateway is live replaces prepared model-catalog configuration and causes subsequent inbound messages to retry without reaching agents.

## System Context

The doctor command repairs OpenClaw configuration, while the live gateway consumes that configuration to route inbound channel messages into agent runs. A configuration replacement during repair can therefore affect the gateway’s prepared routing state and its ingress retry queue.

## Best Possible Solution

Make concurrent `doctor --fix` safe by first choosing and documenting one supported lifecycle contract; unless a proven atomic reload boundary already exists, refuse repair while a live gateway owns the affected configuration and provide a clear stop–repair–start recovery path.
