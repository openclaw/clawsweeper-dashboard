## Summary

Keep open: current main still does not provide a startup-loaded immutable operator policy layer, and the issue is maintainer-owned, protected, and security-sensitive. The current Policy plugin covers conformance/audit checks, while the agent-facing config guard is a narrow write allowlist rather than a general locked operator-defaults policy.

## What This Changes

The issue requests an immutable operator defaults/policy source that is loaded on startup, takes deterministic precedence, is visible read-only in status/doctor, and cannot be weakened by agent/runtime writes.

## Best Possible Solution

Have maintainers define the security boundary, then implement one canonical immutable operator overlay across config loading, config writes, status/doctor, docs, and upgrade handling, or explicitly document current Policy as conformance-only.

Not applicable: this is a feature request, not a current-main bug. Source inspection shows current main has conformance-only Policy surfaces and a narrow agent config-write guard, but no general immutable operator-policy lock to reproduce as broken existing behavior.
