## Summary

Keep open: this is a maintainer-authored, protected security/product feature request, and current main still lacks the requested startup-loaded immutable operator policy layer. The current Policy plugin provides conformance/audit checks, and the agent-facing Gateway tool has a narrow config-write allowlist, but neither implements a general non-editable operator defaults overlay with precedence, status/doctor visibility, and locked write enforcement.

## What This Changes

Request support for an immutable operator-owned defaults/policy source that is loaded on startup, takes precedence over mutable user config where applicable, is visible read-only in diagnostics, and cannot be weakened by agent/runtime writes.

## Best Possible Solution

Have maintainers define one canonical security boundary, then implement the immutable operator overlay across config loading, config writes, status/doctor, docs, and upgrade handling, or explicitly document Policy as conformance-only.

## Reproduction Assessment

Not applicable: this is a feature request, not a broken current-main behavior. Source inspection shows current main has conformance-only Policy surfaces and a narrow agent config-write guard, but no general immutable operator-policy lock to reproduce as a bug.

## Solution Assessment

Unclear pending maintainer decision: a runtime-enforced overlay is plausible for enterprise policy, but the permanent boundary between core config, Policy conformance, doctor repair, and runtime enforcement needs security/product approval first.
