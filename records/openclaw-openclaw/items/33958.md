Current Policy features, Nix immutable-config mode, and gateway write guards are adjacent, but none provides a startup-loaded immutable operator policy layer with locked precedence over mutable config.

## What This Changes

The issue requests an immutable operator-owned defaults/policy source loaded at startup, reflected in status/doctor, and enforced against runtime or agent writes that would weaken locked policy.

## Best Possible Solution

Define one maintainer-approved security boundary for immutable operator policy, then implement it consistently across startup config loading, write validation, status/doctor visibility, docs, and upgrade handling, or explicitly keep Policy/Nix as conformance-only.
