Keep open: current main still does not implement the requested immutable startup-loaded operator policy layer, and the issue is maintainer-authored, protected, security-sensitive product work. ## What This Changes

Requested support for an immutable operator-owned defaults/policy source that loads at startup, has deterministic precedence over mutable config where applicable, is visible in status/doctor, and cannot be weakened by agent/runtime writes.

## Best Possible Solution

Have maintainers choose the security boundary, then implement one canonical immutable operator overlay across config loading, config writes, status/doctor, docs, and upgrade handling, or explicitly document that current Policy remains conformance-only.

## Solution Assessment

Unclear pending maintainer decision: a runtime-enforced overlay is plausible for enterprise policy, but the permanent boundary between core config loading, Policy conformance, doctor/status reporting, and write enforcement needs a security/product call.
