## Summary

This is a fresh, concrete availability bug report with a narrowly described write-amplification path and correlated production measurements. The related issues cover broader Dreaming pressure and all-row plugin-state reads, but neither replaces this unchanged-row persistence diagnosis, so this issue should remain open for current-main confirmation and a bounded owner-plugin fix.

## What This Changes

Avoid unconditional `memory-core` Dreaming workspace-state rewrites by registering only new or changed entries and deleting only entries no longer desired.

## Best Possible Solution

Confirm the current `memory-core` workspace writer on `main`, then add a narrow owner-plugin diff that compares canonical desired values against the target workspace’s existing rows, preserves delete semantics, and adds regression coverage for first-write, unchanged, changed, and removed-entry cases.
