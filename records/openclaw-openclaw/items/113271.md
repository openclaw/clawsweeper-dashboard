The remaining merge question is product direction: whether a manual composer height should be one browser-local layout preference across every chat session; the contributor’s rationale supports that scope, but it still needs an explicit owner decision before merge.

## What This Changes

The PR adds an accessible drag handle to the primary Control UI chat composer so users can set, persist, nudge, and reset its textarea height while preserving automatic sizing by default.

## System Context

The Control UI chat composer renders the textarea where users draft messages. This change adds a resize control beside the primary composer, stores an opt-in browser-local height preference, and supplies that value to the shared textarea sizing path without affecting suggestion composers.
