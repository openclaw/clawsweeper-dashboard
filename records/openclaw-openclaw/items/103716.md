## Summary

This draft remains useful as a design discussion, but not as a mergeable patch: it adds a fail-closed yet unused validator while current main still uses a bundled Gemini-specific credential bridge through the backend-owned `prepareExecution` hook. The prior blocker remains because the branch neither migrates that live path nor establishes why a second provider-owned contract is the best permanent boundary.

## What This Changes

The PR adds an internal identity-bound validator and focused unit tests for a proposed provider-owned CLI credential-to-environment forwarding envelope.

## Best Possible Solution

Keep one canonical backend execution bridge: either narrow the bundled Gemini preparation path so it receives only immutable selection metadata and returns a closed environment envelope, or introduce a generic contract only in an atomic migration that replaces the private credential branch, updates the SDK/docs/tests, and proves the live flow.
