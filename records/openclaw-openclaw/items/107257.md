## Summary

This PR addresses a valid startup-loop regression, but its recovery remains owned by a nested installer invocation while the outer invocation retains the poisoned rollback snapshot. It needs a state-aware rollback repair and real npm behavior proof before merge; the overlapping alternative PR is still open, so it is not yet a safe superseding target.

## What This Changes

The branch classifies absent installed npm integrity separately from conflicting integrity, quarantines managed-project rebuild artifacts, retries installation once, and adds regression coverage for successful recovery.

## Best Possible Solution

Keep quarantine, retry state, peer snapshots, and rollback selection under one owning install attempt so every post-quarantine failure cleans the rebuilt attempt without restoring the poisoned project; prove clean recovery, persistent incomplete metadata, real conflicts, and downstream security-validation failure, then land one canonical implementation.
