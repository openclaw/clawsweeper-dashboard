## Summary

Keep open: current main and the latest release still emit raw `reason: "target-none"` for disabled-by-default heartbeat delivery without an explanatory event field or status/CLI hint, and the two direct fix PRs are closed unmerged. The remaining blocker is a maintainer decision on the diagnostic contract, not missing reproduction data.

## What This Changes

The issue asks for the default disabled heartbeat delivery path to present a clearer diagnostic than `target-none`.

## Best Possible Solution

Preserve `target-none` as the stable machine reason unless maintainers explicitly approve a rename, and add an additive human-readable disabled-delivery explanation to heartbeat event/status/CLI surfaces with focused regression coverage.

## Reproduction Assessment

Yes. Source inspection on current main shows unset or explicit `target: "none"` resolves to `reason: "target-none"`, and the heartbeat runner exposes that raw reason through last-heartbeat/status surfaces.

## Solution Assessment

Unclear until maintainers choose the diagnostic contract. The safest observed path is an additive hint/status rendering change because it preserves `target-none` for machines while clarifying disabled delivery for humans.
