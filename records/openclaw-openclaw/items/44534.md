## Summary

Keep open: current main and the latest release still expose `target-none` for the default disabled-delivery heartbeat path, and both direct repair PRs were closed unmerged. The remaining work is small, but maintainers should choose the diagnostic contract before another fix lands.

## What This Changes

The issue asks OpenClaw to make the default disabled heartbeat delivery path read as configuration-disabled instead of looking like a missing recipient or routing failure.

## Best Possible Solution

Keep `target-none` stable as the machine reason unless maintainers explicitly choose a breaking rename, and add a human-facing disabled-delivery hint plus status/CLI presentation coverage.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw preserve `reason: "target-none"` as the machine-readable heartbeat skip reason and add a human-facing disabled-delivery hint, or rename the reason string itself?

Rationale: The implementation is small, but the exposed reason string may already be consumed by scripts or log parsers, and the safer alternative adds a new optional diagnostic field.

Likely owner: steipete

Owner reason: They introduced the default-none heartbeat behavior and have the strongest history on the affected heartbeat/status contract.

Owner confidence: high

Options:

- **Add hint, keep reason (recommended):** Keep `target-none` as the stable machine reason and render an optional disabled-delivery hint in heartbeat status output.
- **Rename reason:** Change the machine reason to `delivery-disabled` and accept the compatibility risk for consumers that parse the old value.
- **Leave current output:** Keep the raw diagnostic unchanged and accept the operator confusion as low-priority friction.

## Reproduction Assessment

Yes. Source inspection shows the default and explicit `target: "none"` path emits `reason: "target-none"`, and current tests assert that raw reason.

## Solution Assessment

Unclear until maintainers choose the contract. The additive hint/status rendering path is the safest narrow solution because it improves human diagnostics without renaming an exposed reason string.
