## Summary

Keep open: current main and v2026.6.11 still expose the disabled-delivery heartbeat skip as raw `reason: "target-none"` without a human-readable explanation, and both direct fix PRs are closed unmerged.

## What This Changes

Request clarifying the default disabled heartbeat delivery diagnostic so users do not read `target-none` as a routing failure.

## Best Possible Solution

Keep `target-none` as the stable machine reason unless maintainers explicitly approve a rename, and add an optional human-readable disabled-delivery explanation to heartbeat event/status/CLI surfaces with focused regression coverage.

## Reproduction Assessment

Yes. Source inspection on current main shows unset or explicit `target: "none"` resolves to `reason: "target-none"`, and the heartbeat runner forwards that reason into the last-heartbeat event without a companion explanation.

## Solution Assessment

Unclear until maintainers choose the diagnostic contract. A blind reason rename is riskier than an additive hint/status rendering change because `reason` is machine-readable and may already be parsed.
