## Summary

Keep open: current main and the latest release still emit the raw `target-none` heartbeat skip reason without a disabled-delivery hint, while both direct repair PRs are closed unmerged. The remaining work is small, but maintainers need to choose the diagnostic contract before automation changes a machine-readable reason.

## What This Changes

The issue requests clearer heartbeat diagnostics when the default `target: "none"` intentionally disables outbound delivery but the last heartbeat event reports `reason: "target-none"`.

## Best Possible Solution

Keep `target-none` as the stable machine code unless maintainers explicitly approve a rename, and add an additive disabled-delivery explanation in the heartbeat event/status/CLI path with focused resolver and formatter tests.
