## Summary

Keep open: current `origin/main` and v2026.6.11 still emit the raw `target-none` diagnostic for disabled heartbeat delivery, and the two direct repair PRs are closed unmerged, so the remaining work is a small maintainer diagnostic-contract decision.

## What This Changes

Clarify heartbeat skipped diagnostics when the default `target: "none"` intentionally disables delivery so operators do not misread it as a routing failure.

## Best Possible Solution

Keep `target-none` as the stable machine reason unless maintainers explicitly approve a rename, and add an operator-facing disabled-delivery explanation in the heartbeat event/status/CLI path with focused tests.
