## Summary

Keep open: current main and the latest release still expose the disabled-delivery heartbeat path as raw `target-none` without a human-readable explanation, and the direct fix PRs are closed unmerged.

## What This Changes

The issue requests clearer heartbeat diagnostics when the default `target: "none"` disables delivery, so users do not mistake `target-none` for a routing failure.

## Best Possible Solution

Keep `target-none` as the stable machine code unless maintainers explicitly approve a rename, and add a human-readable disabled-delivery explanation in the heartbeat event/status/CLI path with focused tests.
