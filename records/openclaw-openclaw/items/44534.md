## Summary

Keep open: current main and v2026.6.11 still expose disabled heartbeat delivery as `reason: "target-none"` without a human-readable disabled-delivery explanation, and the direct repair PRs are closed unmerged.

## What This Changes

The issue asks for heartbeat diagnostics to make the default `target: "none"` disabled-delivery path clear instead of showing only `target-none`.

## Best Possible Solution

Keep `reason: "target-none"` stable unless maintainers explicitly approve a rename, and add an additive disabled-delivery explanation that reaches heartbeat-last and deep status output with focused tests.
