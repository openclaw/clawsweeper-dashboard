## Summary

Keep open: current main and v2026.6.11 still emit the raw `target-none` skip reason without a disabled-delivery hint, and the direct repair PRs are closed unmerged, so the remaining work is a small diagnostic contract decision.

## What This Changes

Request to make the heartbeat skipped-delivery output less misleading when the default `target: "none"` configuration intentionally disables outbound delivery.

## Best Possible Solution

Preserve the stable machine `reason` unless maintainers explicitly approve a rename, and add a human-facing disabled-delivery explanation that reaches both `system heartbeat last` and deep status output with focused tests.

I did not run a live gateway because this review is read-only and the source/test path is sufficient to prove the current behavior.

## Solution Assessment

Unclear until maintainers choose the diagnostic contract; the additive-hint shape is the best current candidate because it fixes the operator wording without breaking the existing machine reason. A direct rename should wait for explicit approval because `reason` is already exposed through gateway and CLI output.
