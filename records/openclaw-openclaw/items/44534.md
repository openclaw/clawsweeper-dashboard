## Summary

Keep open: current main and v2026.6.11 still expose the disabled heartbeat delivery path as `reason: "target-none"` without a human-readable disabled-delivery explanation, and both direct repair PRs are closed unmerged.

## What This Changes

The issue asks OpenClaw to make heartbeat disabled-delivery skips clearer when the default heartbeat target is `none`.

## Best Possible Solution

Keep `reason: "target-none"` stable unless maintainers explicitly approve a rename, and add an additive disabled-delivery explanation that reaches heartbeat-last and deep status output with focused tests.
