## Summary

Keep open: current main and the latest release still expose `target-none` for the disabled-delivery heartbeat path, while the direct repair PRs were closed unmerged. The remaining work is a small diagnostic-contract decision, not stale cleanup.

## What This Changes

The issue asks OpenClaw to make heartbeat skipped diagnostics clearer when delivery is intentionally disabled by the default `target: "none"` configuration.

## Best Possible Solution

Keep `reason: "target-none"` stable as the machine reason, add a human-facing disabled-delivery hint to heartbeat events, and render that hint in status/CLI output with focused regression coverage.
