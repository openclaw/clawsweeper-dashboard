## Summary

Keep open: current main and v2026.6.11 still emit raw `target-none` without a disabled-delivery hint, and the direct repair PRs are closed unmerged, so the remaining work is a small diagnostic contract decision.

## What This Changes

Request clearer heartbeat skip diagnostics when delivery is intentionally disabled by the default `target: "none"` configuration.

## Best Possible Solution

Keep `target-none` as the stable machine code unless maintainers explicitly approve a rename, and add a human-readable disabled-delivery explanation in the heartbeat event/status/CLI path with focused tests.

## Reproduction Assessment

Yes. Current source shows unset or explicit `target: "none"` resolves to `reason: "target-none"`, and the skipped heartbeat path emits that reason; I did not run a live gateway, but the source path is direct.

## Solution Assessment

Unclear until maintainers choose the diagnostic contract. A blind reason rename is riskier than an additive hint/status rendering change because `reason` is machine-readable and may already be parsed.
