## Summary

Keep open: current main still exposes the config-disabled heartbeat path as the machine reason `target-none` without an additive operator-facing hint in the stored event, and both direct repair PRs for this issue are closed unmerged. The issue is valid, but the durable fix needs maintainer choice because renaming the reason would change a machine-readable diagnostic contract while adding a hint/status wording is additive.

## What This Changes

The issue asks for clearer heartbeat skipped output when the default `target: none` disables delivery, so users do not mistake the `target-none` reason for a routing failure.

## Best Possible Solution

Preserve `target-none` as the stable machine reason and add an additive human-readable hint or CLI/status wording that explains `delivery disabled by configuration` for the default `target: none` path.
