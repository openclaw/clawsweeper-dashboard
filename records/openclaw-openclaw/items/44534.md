## Summary

Keep open: current `main` and the latest release still expose the confusing disabled-delivery heartbeat diagnostic, and both direct repair PRs are closed unmerged, so the remaining work is a small but compatibility-sensitive output-contract decision.

## What This Changes

The issue asks for clearer heartbeat skip diagnostics when default heartbeat delivery is intentionally disabled by `target: "none"`.

## Best Possible Solution

Keep `reason: "target-none"` as the machine-readable value unless maintainers explicitly approve a contract rename, and add an optional human-facing disabled-delivery hint that CLI/status output can surface.
