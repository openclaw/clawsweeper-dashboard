## Summary

Keep open: current main and v2026.6.11 still expose the raw `target-none` heartbeat skip reason without a disabled-delivery explanation, while the two direct repair PRs are closed unmerged. The remaining choice is a small but real diagnostic-contract decision.

## What This Changes

The issue requests clearer heartbeat diagnostics when the default `target: "none"` disables external delivery but reports `reason: "target-none"`.

## Best Possible Solution

Preserve `reason: "target-none"` unless maintainers explicitly approve a rename, and add a human-facing disabled-delivery explanation that reaches both `system heartbeat last` and deep status output with focused tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw preserve `reason: "target-none"` as the machine-readable heartbeat skip reason and add a disabled-delivery hint/display field, or rename the reason itself?

Rationale: The value is exposed through Gateway/CLI output and asserted in tests, so the clearer rename and the compatibility-safe additive hint are both plausible but encode different product/API-contract choices.

Likely owner: steipete

Owner reason: They introduced the default-none heartbeat behavior and have the strongest history on the heartbeat delivery/status boundary.

Owner confidence: high

Options:

- **Add an additive hint (recommended):** Keep `reason: "target-none"`, add a disabled-delivery hint or equivalent display field, and update the CLI/status formatting plus regression tests.
- **Rename the reason:** Change the machine-readable reason to a clearer value such as `delivery-disabled`, accepting the compatibility risk for users or scripts parsing the old value.
- **Leave current output:** Keep `target-none` unchanged and rely on docs, accepting the existing operator confusion as low-priority UX friction.

## Reproduction Assessment

Yes. Source inspection shows unset or explicit `target: "none"` resolves to `reason: "target-none"`, and the CLI/Gateway path returns that stored event without a hint or translation.

## Solution Assessment

Unclear until maintainers choose the diagnostic contract. The additive-hint shape is the safest current candidate because it improves operator wording without breaking the existing machine-readable reason.
