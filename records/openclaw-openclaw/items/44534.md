## Summary

Keep open: current main and v2026.6.11 still emit `target-none` for the disabled-by-default heartbeat delivery path, and the direct repair PRs were closed unmerged, so the remaining work is a small diagnostic contract decision.

## What This Changes

Clarify the default disabled-heartbeat-delivery diagnostic so `target-none` does not look like a chat/session routing failure.

## Best Possible Solution

Keep `target-none` as the stable machine reason, add a human-facing disabled-delivery hint, and render that hint in heartbeat CLI/status output.
