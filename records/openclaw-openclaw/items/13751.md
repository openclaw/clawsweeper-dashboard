## Summary

Keep open: current `main` and the latest release still use contact-backed Feishu sender-name lookup by default and still expose live contact-directory peer listing, so the reported security and UX concern remains. The next step is maintainer-owned because changing Feishu permission defaults and directory lookup semantics is a security/product decision and overlaps an open Feishu display-name PR.

## What This Changes

Requests making basic Feishu inbound messaging work without contact-directory read permission by default, including sender-name resolution and live directory lookup behavior.

## Best Possible Solution

Make basic inbound Feishu messages contact-free by default: use verified event or chat-member metadata when available, fall back quietly to the stable sender id, and require explicit opt-in for contact-backed profile lookup and live user-directory listing with docs and regression tests.
