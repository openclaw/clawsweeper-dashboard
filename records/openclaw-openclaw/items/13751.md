## Summary

Keep open: current main and v2026.6.11 still keep Feishu sender-name lookup contact-backed and default-on, so the reported broad contact-directory permission dependency remains unresolved and needs security/product follow-up rather than cleanup closure.

## What This Changes

The issue requests making basic Feishu sender-name resolution work without requiring broad contact-directory read permission, with live directory lookup made explicit or optional.

## Best Possible Solution

Make basic inbound Feishu messages contact-free by default, use verified event or chat-member metadata when available, fall back quietly to stable sender ids, and require explicit opt-in for contact-backed profile lookup and live user-directory listing with docs and regression coverage.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 still default Feishu sender-name lookup on and call the Feishu contact user API; I did not run a live Feishu tenant in this read-only review.

## Solution Assessment

Unclear as an exact implementation path. The contact-free default is the right end state, but maintainers need to decide whether event metadata, chat-member lookup, static aliases, or an explicit contact-lookup opt-in should be the permanent product contract.
