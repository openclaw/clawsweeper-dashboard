## Label Justifications

- `P1`: Multiple Feishu users report normal bot operation pushing them toward broad organization contact permissions or noisy authorization prompts.
- `impact:security`: The issue concerns organization contact-directory access being used by default for basic Feishu sender display-name behavior.
- `impact:auth-provider`: The failure mode is tied to Feishu permission scopes, authorization prompts, and credentialed contact API access.
- `impact:ux-friction`: Users can proceed only by granting sensitive permissions, disabling sender-name lookup, or tolerating degraded sender labels and permission noise.

## Summary

Keep open: current main and v2026.6.11 still keep Feishu sender-name resolution contact-backed and default-on, and live peer listing still enumerates contact users. The remaining change is security/defaults-sensitive and overlaps an open human-review Feishu display-name PR, so this is not safe cleanup closure or an automated competing fix.

## What This Changes

The issue asks to make Feishu sender-name resolution and directory listing avoid broad contact-directory permissions by default.

## Best Possible Solution

Make basic inbound Feishu messages contact-free by default, use verified lower-scope metadata or stable sender ids, and require explicit opt-in for contact-backed sender lookup and live user-directory listing with docs and regression coverage.

## Solution Assessment

No, current main is not the best end state because it only partially suppresses stale-scope noise while leaving contact-backed lookup default-on. The safer path is a maintainer-approved contact-free default with explicit opt-in for contact-backed profile and live-directory lookup.
