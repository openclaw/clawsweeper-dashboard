## Label Justifications

- `impact:security`: The issue concerns organization contact-directory access being used by default for basic Feishu sender display-name behavior.

## Summary

Keep open: current main and the latest release still keep Feishu sender-name resolution contact-backed and default-on, while the merged fixes only suppress stale-scope noise or add an opt-out. The remaining work changes Feishu permission/security defaults and overlaps an open human-review PR, so it needs maintainer direction rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to stop requiring broad Feishu contact-directory permissions for basic sender display-name resolution and live directory lookup.

## Best Possible Solution

Make basic inbound Feishu messages contact-free by default, use verified lower-scope metadata or stable sender ids, and require explicit opt-in for contact-backed sender lookup and live user-directory listing with docs and regression coverage.
