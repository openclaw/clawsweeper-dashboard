## Label Justifications

- `P1`: Multiple organizations report that a bundled Feishu workflow depends on a broad scope their security policies will not permit, although basic messaging can continue with degraded identities.
- `impact:security`: The central request is to minimize organization-wide contact-directory access for basic inbound message handling.

- `impact:ux-friction`: Users can proceed by opting out or accepting opaque IDs, but the default produces noisy permission guidance and avoidable setup and support burden.

## Summary

Current main still performs default-on, contact-backed sender lookup and live contact-directory enumeration. The open maintainer-authored Feishu display-name PR only partially overlaps, retains contact fallback, and has unresolved security concerns, so this issue remains necessary for an explicit permission-boundary decision. ([github.com](https://github.com/openclaw/openclaw/blob/main/extensions/feishu/src/bot-sender-name.ts))

## What This Changes

Make basic Feishu sender-name handling and directory behavior avoid organization-wide contact-directory permission by default.

## Best Possible Solution

Revise the active Feishu work so ordinary inbound messages use verified event or exact chat-member metadata first, quietly fall back to the stable sender ID, and use contact-backed profile or live-directory access only through explicit documented opt-in with bounded caches, trusted permission URLs, and fresh-install plus upgrade tests.
