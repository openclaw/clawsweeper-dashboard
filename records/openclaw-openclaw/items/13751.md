## Summary

Keep open: current main and v2026.6.11 still default Feishu sender-name resolution to contact-backed lookup, docs/tests still preserve manual opt-out, and live peer listing still calls the contact directory. The report remains security/auth-sensitive and overlaps an assigned maintainer path plus an open maintainer-labeled Feishu PR, so cleanup closure or a competing automated fix would be premature.

## What This Changes

The issue requests making Feishu sender-name resolution and live user listing stop depending on broad contact-directory permissions for basic bot use.

## Best Possible Solution

Make basic inbound Feishu sender attribution contact-free by default, fall back quietly to a stable sender id, and gate contact-backed profile lookup plus live user-directory listing behind explicit operator opt-in with docs and regression tests.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: with `resolveSenderNames` unset or true, inbound Feishu messages call `resolveFeishuSenderName`, which calls `client.contact.user.get`; live peer listing also calls `client.contact.user.list`.

## Solution Assessment

Unclear. A contact-free default is the right end state for safer basic messaging, but maintainers still need to choose the trusted Feishu metadata source and opt-in semantics before changing defaults.
