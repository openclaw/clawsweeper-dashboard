## Label Justifications

- `P1`: Multiple Feishu users report normal bot operation pushing them toward broad organization contact permissions, degraded sender labels, or noisy authorization prompts.
- `impact:security`: The issue concerns organization contact-directory access being used by default for basic Feishu sender display-name behavior.
- `impact:auth-provider`: The failure mode is tied to Feishu permission scopes, authorization prompts, and credentialed contact API access.
- `impact:ux-friction`: Users can proceed only by granting sensitive permissions, disabling sender-name lookup, or tolerating degraded sender labels and permission noise.

## Summary

Keep open: current main and v2026.6.11 still keep Feishu sender-name resolution contact-backed and default-on, and live peer listing still enumerates contact users. The remaining fix is security/defaults-sensitive, needs maintainer choice, and overlaps an open Feishu display-name PR rather than being safe cleanup closure.

## What This Changes

The issue asks the Feishu plugin to stop depending on broad contact-directory permission for basic sender-name resolution and to avoid default live directory contact lookups.

## Best Possible Solution

Make basic inbound Feishu messages contact-free by default, use verified lower-scope metadata or stable sender ids, and require explicit opt-in for contact-backed sender lookup and live user-directory listing with docs and regression coverage.
