## Summary

Keep open: current main and v2026.6.11 still perform Feishu sender-name lookup through the contact API by default, and live peer listing still enumerates contact users. The remaining change is security and compatibility sensitive because it changes Feishu permission defaults and overlaps the paused maintainer PR at https://github.com/openclaw/openclaw/pull/73399.

## What This Changes

The issue requests making Feishu basic sender-name resolution and live directory behavior avoid broad contact-directory permissions by default.

## Best Possible Solution

Make basic inbound Feishu messages contact-free by default, use verified lower-scope metadata or stable sender ids, and require explicit opt-in for contact-backed sender lookup and live user-directory listing with docs and regression coverage.

- **Land Display-Name PR First:** Resolve https://github.com/openclaw/openclaw/pull/73399 first for DM fallback behavior, then keep this issue open for the broader contact-free default and live-directory decision.

No, current main is not the best end state because it only partially suppresses stale-scope noise while leaving contact-backed lookup default-on. The safer path is a maintainer-approved contact-free default with explicit opt-in for contact-backed profile and live-directory lookup.
