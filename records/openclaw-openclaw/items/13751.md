## Summary

Keep open: current main and v2026.6.11 still default Feishu sender-name resolution to a contact-backed lookup, live peer listing still uses the Feishu contact directory, and the open overlapping PR only partially covers this while it remains conflicting and paused for human review.

## What This Changes

The issue asks the Feishu plugin to stop requiring broad contact-directory permission for basic sender-name attribution and related live directory behavior by default.

## Best Possible Solution

Make Feishu inbound sender attribution contact-free by default, fall back quietly to a stable sender id, and gate contact-backed profile and live user-directory lookup behind explicit operator opt-in with docs and regression tests.

## Reproduction Assessment

Yes, source-level: current main defaults sender-name resolution on and still calls Feishu contact user APIs for sender names and live peer listing. I did not run a live Feishu tenant in this read-only review.

## Solution Assessment

Yes on direction, but the exact patch still needs maintainer choice. The Feishu plugin is the right owner boundary, but maintainers should choose the low-scope sender metadata path and opt-in semantics before changing defaults.
