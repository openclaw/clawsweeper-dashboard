## Summary

Keep open: current main and v2026.6.11 still make Feishu sender-name resolution contact-backed by default, live peer listing still uses the contact directory, and the active overlapping PR only partially covers the problem while it remains paused for maintainer/security review.

## What This Changes

Request to make basic Feishu sender attribution and directory behavior avoid requiring broad organization contact-directory permission by default.

## Best Possible Solution

Make Feishu inbound sender attribution contact-free by default, fall back quietly to a stable sender id, and gate contact-backed profile plus live user-directory lookup behind explicit operator opt-in with docs and regression tests.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 still default sender-name resolution on and still call Feishu contact user APIs for sender names and live peer listing. I did not run a live Feishu tenant in this read-only review.

## Solution Assessment

Yes on direction, but the exact patch still needs maintainer choice. The Feishu plugin is the right owner boundary, but maintainers should choose the low-scope sender metadata path and opt-in semantics before changing defaults.
