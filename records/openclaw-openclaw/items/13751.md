## Summary

Keep open: current main and the latest release still use contact-backed Feishu sender-name lookup by default, and live peer listing still calls the contact directory. The overlapping open PR only partially reduces the sender-name path and is paused for human/security review, so this issue remains the canonical maintainer follow-up.

## What This Changes

The issue asks for Feishu inbound sender-name resolution and directory listing to stop requiring broad contact-directory permissions by default.

## Best Possible Solution

Make Feishu inbound sender attribution contact-free by default, fall back quietly to a stable sender id, and gate contact-backed profile and live user-directory lookup behind explicit operator opt-in with docs and regression tests.

## Reproduction Assessment

Yes. Source inspection on current main shows `resolveSenderNames` defaults on and still calls Feishu contact user APIs for sender names and live peer listing; I did not run a live Feishu tenant in this read-only review.

## Solution Assessment

Yes on direction, but the exact patch still needs maintainer choice. The Feishu plugin is the right owner boundary, but maintainers should choose the low-scope sender metadata path and opt-in semantics before changing defaults.
