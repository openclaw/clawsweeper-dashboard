## Summary

Keep open: current main and latest release still perform contact-backed Feishu sender-name lookup by default, with only partial stale-scope noise suppression already merged. The remaining change is security and compatibility sensitive because it changes Feishu permission defaults and overlaps an open Feishu display-name PR.

## What This Changes

The issue requests making Feishu inbound sender-name handling work without requiring the broad `contact:contact.base:readonly` contact-directory scope.

## Best Possible Solution

Make basic inbound Feishu messages contact-free by default, use verified lower-scope metadata or stable sender ids, and require explicit opt-in for contact-backed sender lookup and live user-directory listing with docs and regression coverage.

- **Land Narrow Display-Name PR First:** Resolve https://github.com/openclaw/openclaw/pull/73399 first for DM fallback behavior, then keep this issue open for the broader contact-free default and live-directory decision.

No, current main is not the best end state because it only partially suppresses stale-scope noise while leaving contact-backed lookup default-on. The safer path is a maintainer-approved contact-free default with explicit opt-in for contact-backed profile and live-directory lookup.
