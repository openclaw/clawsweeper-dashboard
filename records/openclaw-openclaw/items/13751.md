## Summary

Keep open: current main and the latest release still perform contact-backed Feishu sender-name lookup by default, and the related live peer listing still calls the contact directory. The issue remains valid, but the fix changes Feishu security/default semantics and overlaps an open maintainer-owned Feishu display-name PR, so it should stay maintainer-owned rather than queued as a competing repair.

## What This Changes

Remove the Feishu sender-name dependency on broad contact-directory read permission for basic inbound bot behavior.

## Best Possible Solution

Make basic inbound Feishu messages contact-free by default, fall back quietly to stable sender ids when no verified name is available, and require explicit documented opt-in for contact-backed profile lookup or live user-directory listing.
