- `impact:auth-provider`: The affected behavior is Feishu permission/scope authorization and generated permission guidance.

## Summary

Keep open: current main still uses contact-backed Feishu sender-name lookup by default, docs/tests preserve the opt-out model, and the open Feishu replacement PR only partially overlaps while paused for human/security review.

## What This Changes

The issue requests making ordinary Feishu sender-name handling work without broad contact-directory permission.

## Best Possible Solution

Make Feishu inbound messages contact-free by default, fall back quietly to stable sender ids, and make any contact-backed profile or live directory lookup an explicit documented operator choice.

## Reproduction Assessment

Yes. Source inspection on current main shows unset `resolveSenderNames` still defaults to contact-backed sender lookup, and tests/docs preserve that opt-out model.

## Solution Assessment

No, the current implementation is not the best end state for this issue. The safer end state is a contact-free default with any contact-backed profile lookup made explicit and documented.
