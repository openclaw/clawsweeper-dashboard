## Label Justifications

- `P1`: Multiple Feishu users report normal bot operation pushing them toward broad organization contact permissions or noisy authorization prompts.
- `impact:security`: The issue concerns organization-wide contact-directory access being used for basic Feishu sender display-name behavior.
- `impact:auth-provider`: The failure mode is tied to Feishu permission scopes, authorization prompts, and credentialed contact API access.
- `impact:ux-friction`: Users can proceed only by granting sensitive permissions, disabling sender-name lookup, or tolerating degraded sender labels and permission noise.

## Summary

Keep open: current main and the latest release still perform contact-backed Feishu sender-name lookup by default and still expose live contact-directory peer listing, so the reported security and UX concern remains valid. The repair should stay maintainer-owned because it changes Feishu permission defaults and overlaps an open Feishu display-name PR.

## What This Changes

Request to stop Feishu basic sender-name resolution from requiring broad contact-directory permissions and make live directory lookup explicitly opt-in.

## Best Possible Solution

Make basic inbound Feishu messages contact-free by default, use verified lower-scope metadata or stable sender ids, and require explicit opt-in for contact-backed sender lookup and live user-directory listing with docs and regression coverage.
