## Summary

Keep open: current main and the latest release still default Feishu sender-name resolution to contact-backed lookup, and live peer listing still uses the contact directory, so the central permission-scope problem remains unresolved.

## What This Changes

The issue asks OpenClaw to stop requiring broad Feishu contact-directory permission for basic sender-name attribution and live peer discovery.

## Best Possible Solution

Make Feishu inbound sender attribution contact-free by default, fall back quietly to a stable sender id, and gate contact-backed profile and live user-directory lookup behind explicit operator opt-in with docs and regression tests.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: current main defaults resolveSenderNames on and still calls Feishu contact user APIs for sender names and live peer listing. I did not run a live Feishu tenant in this read-only review.

## Solution Assessment

Yes on direction, but the exact patch still needs maintainer choice. The Feishu plugin is the right owner boundary, but maintainers should choose the low-scope sender metadata path and opt-in semantics before changing defaults.
