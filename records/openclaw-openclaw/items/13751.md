- `impact:auth-provider`: The failure mode is tied to Feishu permission scopes, authorization prompts, and credentialed API access.

## Summary

Keep open: current main and the latest release still use contact-backed Feishu sender-name lookup by default and still expose live contact-directory peer listing, so the permission concern remains real and needs maintainer-owned security/defaults direction.

## What This Changes

The issue requests making basic Feishu sender-name resolution work without requiring broad contact-directory permission.

## Best Possible Solution

Make basic inbound Feishu messages contact-free by default, use verified lower-scope metadata only when safe, fall back quietly to the stable sender id, and require explicit opt-in for contact-backed profile lookup and live user-directory listing with docs and regression coverage.
