- `P1`: A deterministic Control UI auth regression blocks affected same-origin multi-gateway users from reconnecting without re-entering the gateway token.
- `impact:auth-provider`: The bug is specifically about gateway-issued device credentials being reused against the wrong Control UI gateway endpoint.
- `impact:security`: A bearer device token can be sent to a different same-origin gateway path than the endpoint that issued it.
- `impact:ux-friction`: Affected users can recover by re-entering the shared token, but routine tab or gateway use presents an avoidable login gate.

## Summary

This issue should stay open: it is maintainer-authored/protected, has an open closing pull request at https://github.com/openclaw/openclaw/pull/101352, and current main still stores Control UI device auth under one origin-wide browser key.

## What This Changes

The issue reports that Control UI device credentials collide when multiple gateways share one HTTPS origin but use different path or query routes.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/101352, or an equivalent fix that scopes device-bound credentials by normalized gateway endpoint while preserving ephemeral shared-token handling.
