## What This Changes

The issue reports that Control UI device tokens stored under one origin-wide browser key collide for multiple same-origin gateway paths or query routes.

## Best Possible Solution

Review and land or replace the linked PR that scopes browser device-auth records by normalized gateway endpoint while keeping shared gateway tokens ephemeral.

Question: Should the legacy origin-wide browser device-auth record be migrated to the first gateway opened after upgrade, or should upgrade force fresh scoped device credentials for each endpoint?

Rationale: The old record stores a bearer device credential without endpoint provenance, so the migration choice affects both upgrade continuity and cross-gateway credential isolation.

Likely owner: Peter Steinberger

Owner confidence: high

Options:

- **Accept first-open migration (recommended):** Proceed with the linked PR's endpoint-scoped storage and claim the ambiguous legacy record once before deleting the old key.
- **Force fresh scoped credentials:** Discard the ambiguous legacy record on upgrade and require each gateway endpoint to issue a new scoped device token.
