## Label Justifications

- `P2`: This is a bounded but real routing bug affecting multi-agent Slack thread workflows rather than a core outage.
- `impact:session-state`: The report concerns persisted session metadata resolving an intended Slack thread route as webchat.
- `impact:message-loss`: Wrong route resolution can misroute or hide A2A replies and announce messages from the intended Slack thread.

## Summary

Keep open: current main still parses group session providers from the first `From` segment, so an `agent:<id>:slack:channel:...` key can still fall back to a `webchat` provider hint; the paired fix PR is open but conflicting, so the issue is not implemented yet.

## What This Changes

The issue asks OpenClaw to preserve A2A Slack thread routing when session keys are agent-prefixed and restart/announce fallback has incomplete delivery context.

## Best Possible Solution

Refresh and review https://github.com/openclaw/openclaw/pull/49750, or land an equivalent narrow current-main fix that parses agent-prefixed Slack thread keys and preserves explicit delivery route precedence.

## Reproduction Assessment

Yes, at source level: current `resolveGroupSessionKey()` reads `parts[0]` from `ctx.From`, so `agent:builder:slack:channel:...` can miss the encoded Slack provider and use a webchat provider hint instead. I did not run a live Slack A2A scenario.

## Solution Assessment

Yes on direction, but the best path is to refresh the existing paired PR or land an equivalent narrow fix against current main instead of opening a second repair lane.
