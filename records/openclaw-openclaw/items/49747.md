## Summary

Close: current main no longer matches the reported repro path. Slack inbound code keeps agent-prefixed thread session keys in the route/session-key fields, not in `MsgContext.From`, and the restart fallback half now uses routable-context gating plus field-level merging that has shipped.

## What This Changes

The issue asks OpenClaw to prevent A2A Slack thread sessions from being normalized as webchat and to stop restart/announce fallback from routing through the base session when explicit target routing is available.

## Best Possible Solution

Keep the current prepared-route/session-key separation and restart field-merge behavior; reopen or file a new issue only with runtime evidence that Slack now places an `agent:<id>:...` value in `MsgContext.From`.

## Reproduction Assessment

No. Current Slack source constructs `MsgContext.From` as a Slack user/channel/group route while keeping the agent-prefixed session key in `SessionKey`, and the restart fallback half is already covered by source and tests.

## Solution Assessment

Yes. The best current direction is to preserve prepared Slack route facts and field-merge only missing restart-route data, rather than decoding internal agent session keys from `From`.
