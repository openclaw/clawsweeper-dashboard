## Summary

Keep open: current main still has the sender-blind compaction bug, but this PR is only a partial mitigation because it keys on owner status rather than durable participant identity, so two non-owner participants can still collide. The PR also still needs redacted real behavior proof from a real multi-user compaction or transcript path.

## What This Changes

The PR changes duplicate-user-message compaction deduplication to include `__openclaw.senderIsOwner` in the dedup key and adds focused owner/non-owner unit coverage.

## Best Possible Solution

Land or revise a maintainer-approved sender-metadata boundary, then make both compaction dedup consumers use a durable per-participant discriminator; if identity is unavailable, avoid pruning rather than collapsing distinct participants.

## Reproduction Assessment

Yes. Source inspection shows current main keys duplicate compaction only by normalized text, and this PR's owner-status key still collides for two distinct non-owner participants; I did not run a live group-channel compaction E2E.

## Solution Assessment

No. A sender-aware key is the right direction, but this branch uses owner status instead of a per-participant identity and therefore remains too narrow.
