## Summary

Keep open: current main still lacks a single capability-aware contract for configured model inputs. The code accepts and preserves audio/video metadata in some paths, rejects it in the session registry, and still trusts configured `image` declarations for media routing, so a schema-only guardrail would conflict with existing behavior and needs maintainer product/API direction first.

## What This Changes

The issue requests schema validation, tests, CI failure, and docs for unsupported `models.providers.*.models[*].input` modality declarations.

## Best Possible Solution

Define one canonical configured-model capability authority, keep valid multimodal metadata where supported, and align schema, exported types, registry validation, media routing, diagnostics, tests, and docs around that contract.
