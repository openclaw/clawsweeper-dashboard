## Summary

Keep open: current main still does not provide a consistent capability-aware guardrail for configured model inputs, and the remaining behavior requires a maintainer contract decision before a safe fix can land.

## What This Changes

Add guardrails so unsupported values in configured model input modalities fail before deployment and are covered by tests and docs.

## Best Possible Solution

Define one canonical configured-model input contract and enforce it consistently across schema, exported types, generated schema, catalog normalization, runtime selection, tests, docs, and any needed doctor migration.

## Reproduction Assessment

Yes, at source level: current main accepts audio/video configured inputs and still has runtime paths that trust configured image metadata. I did not run a live invalid deployment in this read-only review.

## Solution Assessment

No, not as a schema-only rejection. The best fix needs a maintainer decision on whether audio/video are valid model metadata, unsupported runtime capabilities, or should require an explicit capability-override contract.
