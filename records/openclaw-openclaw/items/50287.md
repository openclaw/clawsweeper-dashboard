## Summary

Keep open: current main still has an unresolved contract split where configured model inputs accept `audio`/`video`, generated plugin model catalogs reject them in the session registry, and docs/runtime behavior still describe narrower text/image semantics. This needs maintainer product/API direction before a safe fix PR can choose rejection, preservation, or an override-gated guardrail.

## What This Changes

The issue requests schema, test, CI, and documentation guardrails for unsupported `models.providers.*.models[*].input` modalities.

## Best Possible Solution

Define one canonical configured-model input contract, then align schema, exported types, generated/catalog validation, media/model routing, docs, tests, and any needed doctor migration around that contract.

Rationale: Current main accepts audio/video in the public config schema/type and preservation tests, while the session registry and docs still behave as if model input is text/image-only, so an automated fix would be choosing product/API direction.

Owner confidence: medium

Options:

- **Keep metadata, add semantic guards (recommended):** Accept audio/video in catalog metadata, but prevent runtime routing from trusting unsupported user-declared capabilities unless provider-owned catalog proof or an explicit override contract exists.
- **Reject to text/image contract:** Tighten configured model input to text/image only and add tests, docs, and a doctor migration or warning for any shipped configs that already contain audio/video.
- **Land catalog acceptance first:** Allow the generated-catalog PR to proceed separately while leaving user-declared capability validation in this issue until maintainers settle the permanent contract.
