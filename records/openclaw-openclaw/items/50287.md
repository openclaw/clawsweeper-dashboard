## Summary

Keep open: current main and v2026.6.11 still have an unresolved model-input capability contract. Config accepts and preserves audio/video metadata, runtime and docs still mostly operate on text/image, and related open PRs address generated-catalog acceptance rather than the requested unsupported-capability guardrail.

## What This Changes

The issue requests schema, test, CI, and docs guardrails that reject unsupported `models.providers.*.models[*].input` modality declarations before deployment.

## Best Possible Solution

Define one canonical model capability authority, then align config schema, exported types, registry validation, media-understanding selection, tests, docs, and any needed doctor migration around that contract.

## Reproduction Assessment

Yes, at source level. Current main accepts and preserves configured audio/video input metadata while runtime registry/types/docs remain text/image-oriented and media selection trusts configured image declarations without a capability authority check.

## Solution Assessment

No, not as a blanket schema-only rejection. The best fix needs maintainer direction on whether audio/video are valid model metadata, should be clamped for specific runtime paths, or require an explicit capability-override contract.
