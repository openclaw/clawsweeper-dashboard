## Summary

Keep open: current main still has an unresolved model-input contract. The config schema and public type accept audio/video, the session registry still validates text/image only, docs describe text/image behavior, and a current test preserves audio/video metadata, so this needs maintainer product/API direction rather than cleanup closure.

## What This Changes

The issue requests guardrails that reject unsupported `models.providers.*.models[*].input` modalities before deployment, with tests, CI failure, and docs.

## Best Possible Solution

Define one canonical model-input capability authority, then align schema, exported types, registry validation, media-understanding selection, tests, docs, and any needed doctor migration around that contract.

## Reproduction Assessment

Yes, at source level. Current main accepts audio/video configured inputs, preserves them in provider catalog tests, and still has text/image-only runtime validators plus image-routing paths that trust configured capability metadata.

## Solution Assessment

No, not as a blanket schema rejection yet. The maintainable fix first needs a maintainer decision on whether audio/video are valid model metadata, should be clamped per runtime path, or require an explicit capability-override contract.
