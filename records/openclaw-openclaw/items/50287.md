## Summary

Keep open. Current main and the latest release still have split model-input behavior: config accepts `audio`/`video`, while the session registry and runtime model type remain `text`/`image`, and media-understanding still trusts configured image declarations. The remaining work is still necessary, but it needs maintainer product/API direction before an automated fix because related open work argues that some `audio`/`video` catalog metadata is valid.

## What This Changes

Request to add validation guardrails for configured model input modalities so unsupported combinations fail before deployment, with tests and fallback/model-tier documentation.

## Best Possible Solution

Define one model-input capability contract, then enforce it consistently across schema, exported types, registry validation, provider/catalog normalization, media-understanding selection, tests, docs, and any needed doctor migration or explicit override path.

## Reproduction Assessment

Yes, at source level. Current main accepts `audio`/`video` in configured model inputs while registry/runtime surfaces still only admit `text`/`image`, and media-understanding selection trusts user-declared image capability without catalog cross-checking.

## Solution Assessment

Unclear as an implementation path. The guardrail is directionally aligned with safer validation, but blanket schema tightening is not the best fix until maintainers decide capability authority, compatibility behavior, migration, and override policy.
