## Summary

Keep open: current main and v2026.6.11 still leave the configured-model input contract unsettled, with config accepting audio/video metadata while registry, list, docs, and media-selection paths remain text/image-oriented. This needs maintainer product/API direction before a safe validation hardening PR.

## What This Changes

Add schema validation, tests, CI guardrails, and docs so unsupported `models.providers.*.models[].input` modalities are caught before deployment.

## Best Possible Solution

Define one canonical configured-model input capability contract, then align schema, exported types, registry validation, catalog normalization, model-list rendering, media selection, docs, tests, and any needed doctor migration around that contract.

- **Accept Metadata With Guardrails:** Keep audio/video as valid metadata but add runtime-specific selection checks, clearer diagnostics, and docs separating chat input support from media-understanding or future metadata.
