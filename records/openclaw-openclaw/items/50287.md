## Summary

Keep open. Current main and the latest release still have an unresolved configured-model input contract: top-level config accepts `audio` and `video`, registry/runtime paths still only accept or expose `text` and `image`, and docs describe only text/image model inputs. That makes the requested guardrail still necessary, but not safe for an autonomous fix until maintainers decide whether `audio`/`video` are valid model metadata or should be rejected before deployment.

## What This Changes

Request to add pre-deployment validation, tests, CI failure behavior, and docs for unsupported `models.providers.*.models[*].input` modalities.

## Best Possible Solution

Define one canonical configured-model input contract and enforce it consistently across config schema, registry loading, catalog normalization, model-list display, tests, and docs, with a compatibility path if shipped configs using `audio` or `video` need migration or explicit preservation.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: a configured model input containing `audio` passes the top-level config schema, while registry/runtime/docs remain text/image-oriented. I did not run tests because this review is read-only.

## Solution Assessment

No, a simple schema-tightening patch is not yet the best fix. The safer path is a maintainer decision on whether `audio`/`video` are supported metadata, then an aligned schema/runtime/docs/test change with upgrade handling.
