## Summary

Keep open. Current main and v2026.6.11 still have conflicting model-input contracts: config accepts audio/video, the session registry still rejects those modalities in generated catalogs, media-understanding still trusts user-declared image support, and related open PRs do not settle the semantic guardrail decision.

## What This Changes

The issue requests schema, test, CI, and docs guardrails for unsupported `models.providers.*.models[*].input` modality declarations.

## Best Possible Solution

Define one configured-model capability authority and enforce it consistently across config schema/types, session registry, provider catalog normalization, media-understanding routing, docs, tests, and any needed doctor migration or explicit override path.

## Reproduction Assessment

Yes, at source level. Current main accepts audio/video in config metadata, rejects them in the session registry, and trusts user-declared image metadata in media-understanding without a capability cross-check.

## Solution Assessment

Unclear as a concrete implementation. The guardrail direction is useful, but blanket schema tightening is not the best fix until maintainers decide the capability authority, compatibility behavior, and migration or override path.
