## Summary

Keep open: current main and v2026.6.11 still do not implement the requested capability-aware model-input guardrail. The config schema accepts audio/video model input metadata and media-understanding still trusts configured image declarations, so the remaining work is a provider/model capability contract decision rather than stale cleanup.

## What This Changes

Add validation guardrails for configured model input modalities so invalid provider/model input combinations fail before deployment, with targeted tests and fallback/model-tier docs.

## Best Possible Solution

Define one canonical model-input capability authority, then align schema, exported types, registry validation, media-understanding selection, tests, docs, and any required doctor migration around that contract.

## Reproduction Assessment

Yes, source-level. Current schema/type/tests accept and preserve audio/video configured model inputs, while media-understanding still routes from user-declared image capability without a catalog-capability cross-check.

## Solution Assessment

No, not as a blanket schema rejection yet. The maintainable fix needs a maintainer decision on whether audio/video are valid metadata, should be clamped per runtime path, or require an explicit capability-override contract.
