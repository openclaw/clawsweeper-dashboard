## Summary

Keep open: current main and the latest release still have an unresolved model-input contract split, with configured model inputs accepting audio/video while registry/runtime paths and docs remain narrower. The open related PRs address generated-catalog audio/video acceptance, not the product decision for rejecting or gating unsupported user-declared capabilities.

## What This Changes

Issue requests schema, CI, tests, and docs guardrails for unsupported `models.providers.*.models[*].input` modality declarations.

## Best Possible Solution

Define one canonical configured-model input contract, then align schema, exported types, registry validation, catalog normalization, media-routing checks, docs, and tests around that maintainer-approved rule.

## Reproduction Assessment

Yes, at source level: current main accepts configured audio/video inputs in the config/schema path while the session registry and user docs remain narrower, and configured image metadata is trusted for media routing. I did not run a live invalid-provider deployment in this read-only review.

## Solution Assessment

Unclear: a blanket schema-only rejection is not the best proven fix because current main intentionally preserves audio/video metadata in some paths. The best solution needs a maintainer decision on accept, clamp, reject, or override-gate behavior before implementation.
