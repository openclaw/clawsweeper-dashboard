## Summary

Keep open. Current main and v2026.6.11 still have a split model-input contract: the canonical config schema accepts `audio`/`video`, the session registry still rejects those modalities from generated plugin catalogs, and media-understanding still trusts user-declared `image` capability; the requested guardrail therefore needs maintainer product/API direction rather than cleanup closure.

## What This Changes

The issue requests CI-visible guardrails for `models.providers.*.models[*].input` so unsupported model input modalities are rejected and documented.

## Best Possible Solution

Define one capability-authority contract for configured model input metadata, then align schema, registry, catalog normalization, media routing, docs, tests, and any needed doctor migration or explicit override around that contract.

## Reproduction Assessment

Yes, at source level. Current main accepts `audio`/`video` in configured model input metadata, rejects those values in the generated-catalog registry path, and trusts configured `image` declarations for media-understanding routing; I did not run a live deployment repro in this read-only review.

## Solution Assessment

Unclear as a concrete implementation. The guardrail is useful, but blanket schema tightening is not the best fix until maintainers decide capability authority, compatibility behavior, and any migration or override path.
