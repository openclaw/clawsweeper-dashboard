## Summary

Keep open. Current main and v2026.6.11 still have conflicting model-input contracts: config accepts `audio`/`video`, the session registry and runtime model/list types remain `text`/`image`-only, and media-understanding still trusts user-declared `image` capability without a catalog-capability cross-check; related open PRs address generated-catalog acceptance, not the semantic unsupported-capability guardrail.

## What This Changes

Request to add validation guardrails for `models.providers.*.models[*].input`, targeted invalid/valid modality tests, CI failure before deployment, and fallback/model-tier docs.

## Best Possible Solution

Define an authoritative capability contract for configured model inputs, including precedence between user config, generated catalogs, bundled provider catalogs, diagnostics, docs, and any migration or override behavior, then enforce it consistently.

## Reproduction Assessment

Yes, at source level. Current main accepts `audio`/`video` in configured model input metadata, preserves those values in configured catalogs, still has `text`/`image`-only registry/runtime surfaces, and media-understanding trusts user-declared `image` without a catalog-capability cross-check; I did not run a live deployment failure repro.

## Solution Assessment

Unclear as a concrete implementation. The guardrail direction is useful, but blanket schema rejection is not the best fix until maintainers decide capability authority, compatibility behavior, and any migration or override path.
