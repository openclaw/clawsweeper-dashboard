## Summary

Keep open: current main still lacks a capability-aware guardrail for configured model inputs. The config schema and public type accept audio/video metadata, docs and runtime media routing still describe/use text/image behavior, and the related open PR handles generated catalog acceptance rather than unsupported user-declared capability validation.

## What This Changes

Request to add validation guardrails so unsupported `models.providers.*.models[*].input` modality declarations fail before deployment.

## Best Possible Solution

Define one canonical configured-model input capability contract, then align schema, exported types, registry validation, catalog normalization, media-understanding routing, docs, and tests around that contract.
