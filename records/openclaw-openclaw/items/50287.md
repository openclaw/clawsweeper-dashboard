## Summary

Keep open: current main and v2026.6.11 still do not implement a settled, capability-aware guardrail for configured model input metadata. The remaining work is a product/API contract decision because current schema and tests accept audio/video metadata while media-understanding still trusts configured image capability before catalog validation.

## What This Changes

The issue requests schema, test, CI, and docs guardrails so unsupported `models.providers.*.models[*].input` modality declarations fail before deployment.

## Best Possible Solution

Define one canonical model-input capability authority, then align schema, exported types, generated/registry validation, media-understanding selection, tests, docs, and any needed doctor migration around that contract.

## Reproduction Assessment

Yes, at source level: current main accepts audio/video configured model inputs and media-understanding trusts configured `image` capability before catalog validation. I did not run a live invalid-provider deployment in this read-only review.

## Solution Assessment

No, a blanket schema rejection is not the best fix yet. The maintainable path needs a maintainer decision on whether audio/video are valid metadata, should be clamped by runtime path, or require an explicit capability-override contract.
