## Summary

Keep open: current main still has an unresolved configured-model input capability contract, with wide config/types, narrower registry validation, and docs/runtime behavior that do not settle whether audio/video or falsely declared image support should be rejected, accepted, or override-gated.

## What This Changes

The issue requests schema, test, CI, and docs guardrails for unsupported `models.providers.*.models[*].input` modality configurations.

## Best Possible Solution

Define one canonical configured-model input capability contract, then align schema, exported types, generated/runtime registry validation, catalog normalization, media-understanding selection, tests, docs, and any needed doctor migration around that contract.

## Reproduction Assessment

Yes, at source level. Current `main` accepts audio/video in the canonical config schema/type, the session registry still has narrower validation, and image routing can trust configured `image` metadata without a catalog-capability cross-check; I did not run a live invalid-provider deployment in this read-only review.

## Solution Assessment

No, not as a blanket schema-only rejection. The best fix needs a maintainer decision on whether audio/video are valid model metadata, should be clamped for specific runtime paths, or require an explicit capability-override contract.
