## Summary

Keep open: current main and the latest release still do not implement a capability-aware guardrail for configured model inputs, and a direct schema-only rejection would conflict with current public config/types plus tests that preserve audio/video metadata.

## What This Changes

The issue requests validation guardrails for `models.providers.*.models[*].input`, targeted modality tests, early CI failure for invalid config, and model-input validation docs.

## Best Possible Solution

Define one canonical model-input capability authority, then align schema, exported types, registry validation, media-understanding selection, tests, docs, and any needed doctor migration or explicit override around that contract.

## Reproduction Assessment

Yes. Source inspection shows current main accepts `audio`/`video` configured model inputs and trusts configured `image` metadata without a catalog-capability cross-check; I did not run a live invalid-provider deployment in this read-only review.

## Solution Assessment

No, a blanket schema rejection is not yet the best fix. Maintainers first need to decide whether audio/video are valid model metadata, unsupported runtime inputs to clamp/reject, or values requiring an explicit capability override and migration path.
