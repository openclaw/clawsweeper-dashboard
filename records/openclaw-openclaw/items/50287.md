## Summary

Keep open: current main still does not implement the requested capability-aware guardrail for configured model inputs. The code accepts and preserves audio/video model input metadata in public config paths, still has a narrower generated-catalog registry validator, and media-understanding can still trust user-declared image capability, so this remains a maintainer product/API contract decision rather than a cleanup close.

## What This Changes

The issue requests schema, test, CI, and docs guardrails so unsupported `models.providers.*.models[*].input` modality declarations fail before deployment.

## Best Possible Solution

Define one canonical model-input capability authority, then align schema, exported types, generated-catalog registry validation, media-understanding selection, tests, docs, and any needed doctor migration or explicit override path around that contract.

## Reproduction Assessment

Yes. Source inspection shows current validation accepts audio/video configured model inputs and tests preserve them, while media-understanding still trusts configured image metadata without a semantic capability cross-check.

## Solution Assessment

No, not as a blanket schema rejection yet. The best fix needs a maintainer decision on whether audio/video are valid model metadata, should be clamped in specific runtime paths, or require an explicit capability-override contract.
