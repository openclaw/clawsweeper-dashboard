## Summary

## What This Changes

The issue requests validation guardrails, tests, CI failure, and docs for unsupported `models.providers.*.models[*].input` modality declarations.

## Best Possible Solution

Define one canonical model-input capability authority, then align schema, exported types, registry validation, media-understanding selection, tests, docs, and any needed doctor migration or override policy around that contract.

## Reproduction Assessment

Yes, at source level. Current main accepts audio/video configured model inputs, preserves those values in provider-catalog tests, and can trust configured image metadata before any catalog-capability cross-check.

## Solution Assessment

No, not as a blanket schema-only rejection. The best fix needs a maintainer decision on whether audio/video are valid model metadata, should be clamped for specific runtime paths, or require an explicit capability-override contract.
