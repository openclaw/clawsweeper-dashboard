## Summary

Keep this PR open: its central cancellation fix is incomplete across node-host execution and nonstandard abort constructors, and its new lifecycle events can be emitted after an abort terminal event.

## What This Changes

The branch binds exec approvals to agent runs, cancels run-bound approvals on abort, adds approval-park lifecycle events, and extends the approval protocol with run, session, and tool-call identifiers.

## Best Possible Solution

Make run-bound approval settlement a complete abort invariant across every host and ChatAbortOps constructor, suppress post-terminal lifecycle clears, and prove both inline and detached approval paths with an aborted run.

Yes, from source: aborting a run while an approval is pending exercises the uncovered node-host and auxiliary abort-construction paths, while an inline approval resolution after abort exercises the post-terminal lifecycle path. No independent live reproduction artifact was provided.

## Solution Assessment

No. Centralizing cancellation under the run-abort owner is the right design, but the implementation must cover all execution hosts and abort constructors and must not emit a parked-run clear after terminal abort processing.
