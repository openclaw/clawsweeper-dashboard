## Summary

Keep open. Current guidance requires behavior-focused regression coverage and test-value review, but it does not settle the requested failing-first enforcement mechanism; a maintainer should choose the scope before process or CI changes are made.

## What This Changes

The issue proposes a non-blocking failing-first test methodology for fix-bearing pull requests through contribution guidance, a review checklist, or CI.

## Best Possible Solution

Adopt a short non-blocking failing-first prompt in the PR template or reviewer checklist, accompanied by one verified before/after example; defer automated pre-patch CI enforcement unless maintainers explicitly sponsor its design and maintenance cost.
