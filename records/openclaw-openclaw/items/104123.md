## Label Justifications

- `P2`: The PR fixes a real but bounded transcript live-capture race that can continue capture or persist content after an agent run is canceled.

## Summary

This PR remains necessary: current main drops the agent-run cancellation signal before transcript provider startup, while the patch fixes that gap through the existing provider contract without changing post-start capture or ordinary stop behavior. No actionable correctness or security finding was identified.

## What This Changes

The PR forwards agent-run cancellation into pending transcript startup, suppresses canceled-start utterances, and retains failed provider cleanup as a retryable active session.

## Best Possible Solution

Transcript startup should honor the run signal only until provider startup settles, suppress writes from canceled startup, and retain failed provider cleanup as explicit retryable state while preserving ordinary active-session stop finalization.

## Solution Assessment

Yes. Forwarding the existing signal at the transcript tool boundary is the narrowest maintainable fix, and the cleanup-pending mode preserves retryability without changing the public provider API or ordinary stop semantics.
