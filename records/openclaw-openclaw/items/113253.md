## Summary

This is a credible ClawSweeper review-worker failure, but its lease, heartbeat, placeholder, and recovery ownership sits in the separate ClawSweeper service rather than the OpenClaw source repository. The target repository only receives the comment-triggered dispatch; no OpenClaw runtime, plugin, or documentation change can repair a worker that expires after accepting that dispatch.

## What This Changes

Repair ClawSweeper review runs that post a placeholder comment and then expire without replacing it with a verdict or failure status.

## System Context

An OpenClaw pull-request comment can trigger the repository-side dispatch endpoint, which forwards a review request to the separate ClawSweeper service. ClawSweeper owns the lease, heartbeat, worker execution, durable review-comment state, and recovery workflow that ultimately publishes review results back to GitHub.

## Best Possible Solution

Move the report to the ClawSweeper repository, preserving the three run timestamps and placeholder-comment links; fix the worker’s durable lease-expiry/recovery path there so every terminal failure updates the reserved review comment or is reconciled by scheduled recovery.
