## Summary

The patch is a focused, plausible repair that uses the plugin SDK’s shared base64 canonicalizer before screenshot decoding and adds a regression test. It should remain open: the supplied evidence exercises the production command boundary but replaces the desktop driver and image processor with fixtures, so it does not yet demonstrate after-fix behavior from a real CUA desktop-driver capture.

## What This Changes

This PR makes the CUA computer plugin reject malformed base64 PNG data returned by the desktop driver before it reaches screenshot decoding or image processing.

## System Context

The CUA computer plugin receives screenshot data from a desktop-driver process and exposes it through the `screen.snapshot` command. That command either forwards a valid image into the image-processing path or returns a driver-facing capture error to the computer-use client.

## Architecture Diagram

flowchart LR
  Driver[Desktop driver process] --> Payload[Desktop screenshot payload]
  Payload --> Snapshot[screen.snapshot command]
  Snapshot --> Validate[Validate PNG base64]
  Validate -->|valid| Process[Decode and process image]
  Validate -->|invalid| DriverError[Actionable driver error]
  Process --> Client[Computer-use client]

## Best Possible Solution

Keep the shared validator at the plugin’s driver-output boundary, retain the focused regression test, and add a redacted real desktop-driver capture transcript or log covering one malformed and one valid screenshot.
