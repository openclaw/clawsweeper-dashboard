## Summary

Keep open: current main still lacks the requested status cost display and this PR is the active fix candidate, but the current head adds full-transcript reads to default status paths, which needs maintainer design review before merge.

## What This Changes

The PR surfaces cumulative transcript-backed session cost in `/status` and `openclaw status`, adds a conditional `Cost` column, and updates focused status/cost docs and tests.

## Best Possible Solution

Surface cumulative session cost through a persisted, incremental, cached, or bounded status source that preserves the fast default status path; exact deep aggregation should be explicit if it remains expensive.

## Reproduction Assessment

Source-reproducible: the PR head adds full-transcript cost reads in both `/status` and recent `openclaw status` session rows, and current docs/source show the default status path is expected to stay fast and bounded. I did not run a large-transcript latency benchmark in this read-only review.

## Solution Assessment

No: the visible output implementation is plausible and the proof is strong, but full transcript scans in default status paths are not the narrowest maintainable solution. A persisted, incremental, cached, bounded, or explicit deep-path cost source would solve the user problem with less availability risk.
