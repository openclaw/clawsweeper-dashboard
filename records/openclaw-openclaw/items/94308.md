Keep open: the PR addresses the linked session-cost status request and has credible after-fix proof, but current head still introduces full-transcript cost reads on default status paths, which is a maintainer-visible availability risk for large sessions.

## What This Changes

The PR adds transcript-backed cumulative session cost display to `/status` and `openclaw status`, updates the Sessions table, and adds focused docs and tests.

## Best Possible Solution

Preserve the cumulative cost display, but feed it from persisted, incremental, cached, bounded, or explicitly deep-path data so normal status commands remain lightweight.

## Reproduction Assessment

Yes from source inspection: the PR head adds two full-transcript cost reads on default status paths, and current main shows both the existing bounded fallback pattern and the plain-status fast-path docs. I did not run a large-transcript latency benchmark in this read-only review.

## Solution Assessment

No for the current head: surfacing transcript-backed cumulative cost is the right direction, but default status should not depend on unbounded transcript scans when bounded, cached, persisted, or explicit deep-path alternatives exist.
