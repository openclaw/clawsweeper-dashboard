- **[P1] Keep `/status` off full transcript scans:** `src/status/status-text.ts:333-339`
  - body: This helper runs the full-transcript aggregate reader before rendering the normal `/status` response. That reader walks every transcript line and accumulates them before aggregating, while current status uses a bounded tail, so long sessions can make a basic status request slow or memory-heavy. Please keep the default status path bounded or use a maintained aggregate/cache instead.
  - confidence: 0.89
- **[P1] Avoid full scans for recent session rows:** `src/commands/status.summary.ts:422-432`
  - body: `getStatusSummary` builds the default `openclaw status` session rows with `Promise.all`, and this new block full-scans each recent session transcript to decide the Cost column. Plain status is documented as the fast read-only path, so users with several large recent sessions can pay multiple full transcript reads just to print status. Please use bounded or precomputed cost data for this table.
  - confidence: 0.88
