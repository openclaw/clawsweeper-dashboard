## Summary

Keep open: this is a useful implementation candidate with sufficient real-output proof, but the current head still puts unbounded full-transcript cost reads on routine status paths, so it should not merge until maintainers choose a bounded, cached, persisted, or explicitly deep cost source.

## What This Changes

The branch adds transcript-backed session cost rendering to `/status` and `openclaw status`, adds a conditional `Cost` column, and updates focused docs and tests.

## Best Possible Solution

Compute cumulative cost through a persisted, incremental, cached, or bounded session-cost source for default status, and reserve exact full transcript aggregation for an explicit deep or repair path if needed.

## Reproduction Assessment

Source-reproducible: the PR head adds full transcript usage reads in `src/status/status-text.ts` and `src/commands/status.summary.ts`, and the underlying reader walks all transcript lines before aggregating. I did not run a large-transcript latency benchmark in this read-only review.

## Solution Assessment

No for the current head: showing cumulative cost is the right user-facing direction, but placing full transcript scans on default status paths is not the best maintainable solution for a fast status command.
