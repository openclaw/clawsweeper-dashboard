## Summary

Keep open for ordinary maintainer landing: current main still has the five-minute unbounded retention path, while the refreshed head is narrow, contract-compatible, and has no actionable review finding.

## What This Changes

The PR limits the reply usage handoff to the 1,024 newest snapshots after expiry pruning and adds oldest-entry eviction coverage.

## Best Possible Solution

Keep the handoff lifecycle-owned and bounded with expiry-first, oldest-entry eviction while preserving exact run correlation and the documented optional hook contract.

## Maintainer Decision

## Reproduction Assessment

Yes at source level: recording more than 1,024 distinct run snapshots inside the five-minute window leaves all entries retained on current main, and the PR reports confirming this with 5,000 IDs against a recent main SHA.

## Solution Assessment

Yes. Expiry-first capacity eviction is the narrowest maintainable fix because the metadata is explicitly best-effort, while deleting on first consumption could incorrectly prevent reuse across multiple deliveries from one run.
