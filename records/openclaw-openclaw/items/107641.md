## Summary

Keep this issue open: v2026.7.1 already includes a five-second native-hook relay lifetime bound, yet the report observes live `openclaw-hooks` processes surviving for tens of minutes and causing a real Telegram delivery failure. The open PreToolUse fan-out work is relevant but does not yet explain why the shipped timeout, exit path, or process-group cleanup fails under contention.

## What This Changes

Investigate and bound long-running `openclaw-hooks` subprocesses that accumulate under Codex-backed load and eventually starve message delivery.

## Best Possible Solution

Add bounded, low-volume lifecycle diagnostics that correlate each relay event with PID, PPID/PGID, start, timeout, signal, and exit outcome; then enforce event-appropriate concurrency and process-group termination in the Codex plugin/shared relay owner without adding a user-facing timeout option unless operational evidence proves one is necessary.
