## Summary

Current main already fixes the reported Windows node approvals crash: the CLI and gateway now accept host-native Windows approval snapshots, validate them as a node-specific union, and reject incompatible allowlist helper mutations with an actionable message instead of assuming `file`/`socket` fields.

## What This Changes

The issue reports `openclaw approvals get --node` and `openclaw approvals allowlist add --node` crashing against a paired Windows node with undefined `socket` and `file` property errors.

## Best Possible Solution

Keep the current main implementation and ship it in the next release; users on `v2026.6.11` need a build that includes https://github.com/openclaw/openclaw/pull/101669.

## Maintainer Decision

## Reproduction Assessment

Yes. The source comparison shows `v2026.6.11` assumed node approval responses were file-backed while Windows `0.6.12` returns a host-native shape; current main has regression tests for that exact native shape.

## Solution Assessment

Yes. The main-branch fix is the narrow maintainable solution: model node approvals as a file/native union at the protocol boundary, validate payloads at the gateway, and make incompatible helper commands fail with a clear message.
