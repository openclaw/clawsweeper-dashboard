## Summary

Keep this PR open for normal review. The change follows LanceDB’s documented idempotent-create contract and preserves the plugin’s post-open schema validation, but the supplied evidence is limited to a focused test claim and the current type-check failures need resolution before merge.

## What This Changes

This PR changes the LanceDB memory plugin to open the existing memory table first or atomically create an empty one when absent, then adds a regression test that initializes two connections against one fresh database path.

## System Context

The optional LanceDB memory plugin creates or opens its shared `memories` table before it can store or retrieve agent memory. Gateway and worker processes can independently reach that initialization path, after which the table schema determines whether memory operations may proceed.

## Best Possible Solution

Keep the open-first and atomic empty-table creation design, retain the existing legacy-schema rejection, and land it only after a real two-process or equivalent concurrent run plus green type checks confirms both fresh and existing-store behavior.
