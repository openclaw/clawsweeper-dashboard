## Summary

Keep open: current main has fixed several adjacent subagent announce, delivery, and Codex-native premature-success cases, but the generic subagent path can still finalize from the child agent-run outcome while child-owned background exec/process work is tracked separately and may outlive that turn.

## What This Changes

The issue reports that parent/session status can show a subagent complete before delegated background work or result delivery is actually complete.

## Best Possible Solution

Define the lifecycle contract explicitly, then either surface child-owned background processes as separate active work in task/status views or add a generic owned-process liveness gate before subagent finalization.

## Reproduction Assessment

No, not with high confidence from a controlled current-main run. The discussion has two user reports and current source shows a credible path where background exec/process work can outlive the subagent run outcome.

## Solution Assessment

Unclear. Current main handles nested subagent gating and several delivery cases, but the remaining generic background-process semantics need a maintainer decision on whether those processes block subagent completion or remain separate visible active work.
