- `impact:session-state`: The reported failure is a mismatch between visible subagent/session completion state and actual delegated work state.

## Summary

Keep this open: current main has descendant-subagent announce gating and later embedded-run lifecycle fixes, but the reported gap remains for child-owned background process work that can outlive the child agent turn and make completion semantics misleading.

## What This Changes

The issue asks OpenClaw to keep subagent/session completion state running until delegated user-relevant work, including long-running background side effects, is actually finished.

## Best Possible Solution

Define the lifecycle contract first, then implement one coherent path: either keep agent-run completion authoritative while surfacing child-owned background processes as active work, or defer subagent finalization through a generic owned-process liveness seam with timeouts, cancellation, cleanup, and regression coverage.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should child-owned background exec/process sessions block subagent completion, or should they remain separate active work surfaced through task/session status?

Rationale: Current code has two valid boundaries: subagent completion follows the child agent-run result, while long-running exec/process sessions are separately registered and pollable; choosing which state owns user-visible completion affects timeout, cancellation, and detached-job semantics.

Likely owner: tyler6204

Owner reason: The strongest related history is in subagent announce and descendant-gating code that defines when parent completion is emitted.

Owner confidence: medium

Options:

- **Keep completion agent-run authoritative (recommended):** Subagent completion stays tied to the child agent turn, but any child-owned running process must remain visible in `/tasks`, `session_status`, or final handoff text so users do not see a false all-done state.
- **Block completion on owned processes:** Subagent finalization waits for child-owned process sessions to finish, with explicit timeout, cancel, cleanup, and tests to avoid indefinite completion hangs.
- **Require live repro first:** Hold implementation until a focused live reproduction captures the exact UI/status path and process ownership state that appears completed too early.

## Reproduction Assessment

No live high-confidence reproduction was established in this review. Source inspection does show a plausible current path: subagent completion follows the child agent-run result while background exec/process liveness is tracked separately.

## Solution Assessment

Unclear until maintainers choose the lifecycle contract. The safest direction is not a one-line delay, but a deliberate state model for whether child-owned background processes block completion or remain separately surfaced active work.
