## Summary

Keep this open: current main has fixed adjacent announce and descendant-delivery races, but the issue's central lifecycle contract remains unresolved because subagent task completion is still finalized from the child agent-run result while background exec/process sessions can remain active separately.

## What This Changes

The issue asks OpenClaw to keep subagent/task state in progress until delegated background work is actually complete instead of signaling completion early.

## Best Possible Solution

Define one lifecycle contract, then align subagent task finalization, owned process visibility, docs, and regression coverage to either surface child-owned process work separately or defer completion through a bounded process-liveness gate.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should subagent completion remain tied to child agent-run terminal state while child-owned background exec/process sessions are surfaced separately, or should those process sessions block subagent task completion?

Rationale: Both behaviors are plausible product contracts, and the current docs/code separate authoritative agent-run task completion from process registry liveness while the issue expects delegated background work to affect completion state.

Likely owner: steipete

Owner reason: Recent subagent lifecycle and cleanup stabilization commits make this the closest available owner for the runtime contract decision.

Owner confidence: medium

Options:

- **Surface background work separately (recommended):** Keep child agent-run completion authoritative, but make child-owned process sessions visible in tasks/session status and parent handoff so users are not told all delegated work is done.
- **Block on child process liveness:** Treat scoped child-owned background process sessions as part of subagent completion with timeout, cancellation, and explicit detached-work escape rules.
- **Document current semantics:** Clarify that subagent completion means the child agent turn ended and that background processes must be tracked through process/task status, accepting the current behavior as intentional.

## Reproduction Assessment

Yes at source level, but not from a live run here: current main can finalize subagent task state from agent-run outcome while background exec/process sessions remain separately tracked.

## Solution Assessment

Unclear until maintainers choose the contract; current main improves descendant announce delivery, but the remaining fix depends on whether child-owned process liveness is part of subagent completion or separate active-work status.
