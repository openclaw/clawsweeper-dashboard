## Summary

Keep this open: current main has several adjacent subagent announce and descendant-gating fixes, but generic child-owned background process work is still outside the subagent completion gate, so closing this as implemented would overstate current behavior.

## What This Changes

The issue asks OpenClaw to keep subagents visibly running until delegated background or long-running work is actually complete, instead of letting parent/session state show completion too early.

## Best Possible Solution

Define a narrow runtime contract for completion-required child work, then make subagent/task state and parent wake behavior follow that contract without treating every detached process as a subagent blocker by default.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should subagent completion remain tied to the child agent-run terminal lifecycle, or should it also wait on explicitly completion-required background exec/process and async task state before marking the subagent done?

Rationale: Current source intentionally separates background exec/process sessions from subagent run liveness, so fixing this broadly changes product semantics for detached work rather than applying a small mechanical bug fix.

Likely owner: vincentkoc

Owner reason: Recent history ties this area to subagent delivery/session state and exec completion behavior, and the issue timeline already mentioned this account for routing.

Owner confidence: medium

Options:

- **Add an explicit completion-required child-work contract (recommended):** Introduce a narrow runtime signal for background work that must block subagent completion, and keep ordinary fire-and-forget process sessions separate.
- **Keep terminal-run semantics and improve visibility:** Leave subagent completion tied to agent-run terminal state, but make UI/docs/task views clearly show detached child process state separately.
- **Treat all child background processes as blockers:** Hold subagent completion while any child-owned process session is active, accepting longer waits and compatibility risk for existing workflows.

## Reproduction Assessment

No, not with a high-confidence live current-main repro. Source inspection does show the likely remaining failure shape: background exec/process sessions can outlive the agent turn, while subagent liveness and cleanup only gate on registry terminal state and descendant subagent runs.

## Solution Assessment

Unclear as an automatic fix. The best repair depends on a maintainer choosing whether background process state should become part of subagent completion semantics or remain a separately visible task/process surface.
