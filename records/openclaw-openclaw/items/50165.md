## Summary

Keep this open: current main has fixed adjacent announce, descendant-delivery, and active-process visibility paths, but the central lifecycle contract is still unresolved because subagent task completion is finalized from the child agent-run result while child-owned background exec/process sessions can remain active separately.

## What This Changes

The issue reports that subagents can be shown as completed before delegated user-relevant work or background side effects have actually finished.

## Best Possible Solution

Define one lifecycle contract, then align subagent task finalization, owned-process visibility, docs, and regression coverage to either surface child-owned processes as separate active work or gate completion through bounded process liveness.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should subagent task completion remain tied to child agent-run terminal state while child-owned background exec/process sessions are surfaced separately, or should child-owned process liveness gate subagent completion?

Rationale: Both behaviors are plausible product contracts: blocking on every process can strand intentional detached work, while the current separation can still make parent sessions believe delegated work is done too early.

Likely owner: steipete

Owner reason: This person is the best available routing owner because the decision spans recent subprocess hardening and subagent lifecycle behavior, and the current alternatives require maintainer product judgment.

Owner confidence: medium

Options:

- **Surface Background Work Separately (recommended):** Keep child agent-run completion authoritative, but make child-owned process sessions visible in tasks/session status and parent handoff so users are not told all delegated work is done.
- **Gate Completion On Process Liveness:** Treat scoped child-owned background process sessions as part of subagent completion with bounded timeout, cancellation, cleanup, and explicit detached-work escape rules.
- **Document Current Semantics:** Clarify that subagent completion means the child agent turn ended and that background processes must be tracked through process/task status, accepting the current behavior as intentional.

## Reproduction Assessment

Yes at source level, but not from a fresh live run here: current main can finalize subagent task state from agent-run outcome while background exec/process sessions remain separately tracked.

## Solution Assessment

Unclear until maintainers choose the lifecycle contract; current main improves descendant announce delivery and active-process visibility, but the remaining fix depends on whether child-owned process liveness is part of subagent completion or separate active-work status.
