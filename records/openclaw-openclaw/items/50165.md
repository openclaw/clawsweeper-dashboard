## Label Justifications

- `P2`: The issue describes a credible subagent lifecycle/status reliability gap with limited blast radius and a product-contract blocker rather than an urgent outage.
- `impact:session-state`: Parent-visible subagent and task state can become terminal while child-owned background work may still be active.
- `impact:message-loss`: False completion can make users or parent agents stop monitoring before the actual delegated result or artifact is ready.

## Summary

Keep open: current main has improved subagent task reconciliation and delivery suspension, but the central lifecycle question remains unresolved because subagent task completion still follows the child agent-run terminal state while background exec/process work is tracked separately and can outlive that turn.

## What This Changes

The issue asks OpenClaw to keep subagent-visible completion state running until the delegated user-relevant work, including long-running child work, is actually complete.

## Best Possible Solution

Define the lifecycle contract, then implement one coherent path: either make owned completion-required process liveness block subagent finalization, or keep agent-run completion authoritative while showing child-owned background processes as separate active work in task and session status surfaces.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should child-owned background exec/process work block subagent completion, or should it remain a separate active-work signal after the subagent agent-run completes?

Rationale: Both behaviors are plausible from current code: blocking fixes false completion but can hang intentionally detached work, while separate surfacing preserves non-blocking semantics but requires clearer status and UX contracts.

Likely owner: masatohoshino

Owner reason: The recent subagent task-owner reconciliation work is closest to the remaining completion-vs-task-state decision surface.

Owner confidence: medium

Options:

- **Separate Active Work (recommended):** Keep subagent completion tied to the child agent-run outcome and surface background exec/process liveness explicitly in task and session status views.
- **Block Completion On Owned Processes:** Treat owned background processes as completion-required work with bounded timeout, cancellation, cleanup, and regression tests before subagent finalization.
- **Narrow To Delivery Fixes:** Close this lifecycle direction in favor of narrower delivery and task-ledger issues, accepting that background processes are intentionally detached from subagent completion.

## Reproduction Assessment

No, not with a high-confidence controlled current-main run. The issue is source-reproducible at medium confidence because the current lifecycle path finalizes subagent tasks from agent-run outcome while background exec/process sessions are a separate registry path.

## Solution Assessment

Unclear until maintainers choose the lifecycle contract. A narrow code fix is not yet safest because blocking on background processes and surfacing them separately have different timeout, cancellation, cleanup, and UX implications.
