## Summary

Keep open: current main still has plugin approval request/wait/resolve but no terminal requester-side cancel path, and the linked draft PR is the active fix candidate rather than a reason to close this issue before merge.

## What This Changes

Request cancellation of accepted plugin tool approvals when an agent run aborts so gateway, UI, and channel approval state is cleaned up immediately.

## Best Possible Solution

Land a narrow fix that terminally cancels the pending gateway approval on agent abort, unblocks waiters with `decision: null`, broadcasts cleanup, and updates approval consumers to handle that cleanup safely.

## Reproduction Assessment

Yes, by source inspection: an accepted two-phase plugin approval registers a pending gateway record, the agent abort path returns a local cancellation while `waitDecision` is pending, and current main has no `plugin.approval.cancel` RPC to expire that record. I did not run a live repro in this read-only review.

## Solution Assessment

Yes, the linked PR's general shape is the right owner boundary: requester-side cancellation should reuse gateway approval state, publish the same cleanup event family, and update consumers that render resolved plugin approval state. The issue should stay open until that PR or an equivalent fix lands.
