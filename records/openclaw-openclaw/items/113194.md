## What This Changes

Prevent a steered second webchat `chat.send` from persisting a competing user turn that aborts the active agent run with a session-file takeover error.

## System Context

Gateway `chat.send` admits a user turn, dispatches it to the active agent runtime, then finalizes replies and transcript state. A steered or queued follow-up must remain owned by the active runtime so gateway post-dispatch fallback persistence does not become a second transcript writer.

## Architecture Diagram

flowchart LR
  A[Webchat follow-up] --> B[Gateway chat.send]
  B --> C[Active-run admission]
  C --> D[Agent runtime owns transcript]
  D --> E[Model call completes]
  E --> F[Gateway finalization]
  F --> G[Single session transcript]
  C --> H[Steer or follow-up decision]
  H --> D

## Best Possible Solution

Land a narrowly scoped gateway ownership fix with a regression test and redacted live proof that a steered follow-up leaves the original run intact, commits through the runtime-owned transcript path, and is handled after that run completes.
