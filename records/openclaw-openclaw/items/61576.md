## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Advertise the current gateway protocol:** `apps/linux-gtk/crates/gateway-client/src/protocol.rs:218`
  - body: Current main requires protocol version 4, but this client advertises version 3 for both `minProtocol` and `maxProtocol`. A current gateway rejects that handshake as a protocol mismatch, so the app cannot connect until this uses the shared current version contract.
  - confidence: 0.96
- **[P1] Send raw config text to config.set:** `apps/linux-gtk/crates/app/src/views/config.rs:222-225`
  - body: `config.set` validates a `{ raw, baseHash? }` payload, but this sends `{ path, value }`. The Save button therefore returns an invalid-request error instead of persisting the edited config.
  - confidence: 0.95
- **[P1] Use supported skills RPC payloads:** `apps/linux-gtk/crates/app/src/views/skills.rs:123-127`
  - body: The gateway schema does not accept `skillId` for `skills.update`, and `skills.install` also requires one of the supported install shapes. Skill toggles and install buttons will fail validation instead of changing backend skill state.
  - confidence: 0.93
- **[P1] Wrap cron enablement in patch:** `apps/linux-gtk/crates/app/src/views/cron.rs:327-331`
  - body: `cron.update` requires mutable fields inside `patch`, but this sends `enabled` at the top level while optimistically flipping the UI chip. The gateway rejects the request, so users can believe a job is disabled while it remains active.
  - confidence: 0.94
- **[P2] Call channels.status with supported params:** `apps/linux-gtk/crates/app/src/views/channels.rs:126-128`
  - body: `channels.status` accepts `probe`, `timeoutMs`, and `channel`; it rejects the added `channelId` property. The Probe button therefore errors instead of returning channel health for the selected channel.
  - confidence: 0.9
- **[P2] Read pending pair requests from pending:** `apps/linux-gtk/crates/app/src/views/instances.rs:96-100`
  - body: `node.pair.list` returns `{ pending, paired }`, but this reads `requests`. Real pending approvals are rendered as empty, hiding the operator action needed to pair nodes.
  - confidence: 0.88
- **[P2] Use the registered restart RPC:** `apps/linux-gtk/crates/app/src/views/control_room.rs:66`
  - body: The gateway exposes `gateway.restart.request` and `gateway.restart.preflight`, not `gateway.restart`. The Control Room restart button will always fail with an unknown-method error.
  - confidence: 0.9
- **[P1] Persist connection settings outside process env:** `apps/linux-gtk/crates/app/src/views/settings.rs:221-226`
  - body: Save & Reconnect only mutates this process’s environment, so the displayed “settings saved” state is lost after restart and the already-created client is not actually reconfigured. Store the connection settings through the canonical config path or rebuild the client explicitly.
  - confidence: 0.86
- **[P2] Use the local ws default in settings:** `apps/linux-gtk/crates/app/src/views/settings.rs:56-58`
  - body: This settings field still defaults to `wss://127.0.0.1:18789` while the local gateway default is plain `ws://127.0.0.1:18789`. Fresh local users who leave the default unchanged will attempt TLS against a non-TLS listener.
  - confidence: 0.84
- **[P2] Add a bounded challenge wait:** `apps/linux-gtk/crates/gateway-client/src/client.rs:258-278`
  - body: The handshake waits indefinitely for `connect.challenge` and ignores other frames without a timeout. A misrouted or stalled WebSocket endpoint can hang a connection attempt forever instead of returning to the reconnect/backoff loop.
  - confidence: 0.78
