Full review comments:

- **[P1] Use the current config RPC contract:** `apps/linux-gtk/crates/app/src/views/config.rs:222-225`
  - body: `config.get` accepts `{}` and `config.set` expects `{ raw, baseHash }`; this view sends `{ path }`/`{ path, value }` and reads `payload.config`, so the editor will fail or show empty data against the current gateway. Serialize the raw config and carry the returned hash through save.
  - confidence: 0.94
- **[P1] Send supported skills mutation parameters:** `apps/linux-gtk/crates/app/src/views/skills.rs:123-126`
  - body: The current gateway accepts `skills.update` with `skillKey` and `skills.install` with an install name/id or source-specific shape, not `skillId`. As written, enabling or installing skills from the Linux UI will fail request validation.
  - confidence: 0.93
- **[P1] Build cron mutations from the current schema:** `apps/linux-gtk/crates/app/src/views/cron.rs:327-330`
  - body: `cron.add` now requires a named job with `sessionTarget`, `wakeMode`, and `payload`, and `cron.update` requires a `patch` object. The flat `{ schedule, agentId, message }` and `{ jobId, enabled }` payloads will not persist create/toggle actions.
  - confidence: 0.92
- **[P2] Probe channels with supported status params:** `apps/linux-gtk/crates/app/src/views/channels.rs:126-127`
  - body: `channels.status` only allows `probe`, `timeoutMs`, and `channel`; sending `channelId` trips the schema's `additionalProperties: false`, so the probe button will fail instead of refreshing channel state.
  - confidence: 0.9
- **[P2] Read node pair requests from pending:** `apps/linux-gtk/crates/app/src/views/instances.rs:96-100`
  - body: `node.pair.list` returns the pairing list with `pending` and `paired`; this view reads `requests`, so real pending pair requests will be hidden as "No pending requests".
  - confidence: 0.88
- **[P2] Call gateway.restart.request for restarts:** `apps/linux-gtk/crates/app/src/views/control_room.rs:66`
  - body: The gateway exposes `gateway.restart.request` and `gateway.restart.preflight`, not `gateway.restart`. The Control Room restart button will hit an unknown method until it uses the current restart RPC.
  - confidence: 0.89
