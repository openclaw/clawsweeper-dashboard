## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Use a first-class Linux client identity:** `apps/linux-gtk/crates/gateway-client/src/protocol.rs:219-222`
  - body: This native desktop app currently sends `client.id` and `mode` as `cli`. That lets the connection pass today's closed client-id schema, but it prevents the gateway from applying native-app policy, diagnostics, allowlists, or future Linux-specific controls. Add an explicit Linux app client ID and policy path, or keep this out of core until that contract is approved.
  - confidence: 0.93
- **[P1] Send raw config text to config.set:** `apps/linux-gtk/crates/app/src/views/config.rs:222-225`
  - body: `config.set` validates `{ raw, baseHash? }`, but this sends `{ path, value }`. The Save button therefore fails validation instead of persisting the edited config, making the Config view's write path nonfunctional.
  - confidence: 0.95
- **[P1] Use skillKey for skills.update:** `apps/linux-gtk/crates/app/src/views/skills.rs:123-127`
  - body: `skills.update` requires `skillKey`, but this toggle sends `skillId`. Installed skill enable/disable changes will be rejected by the gateway and the UI can show a state that did not persist.
  - confidence: 0.94
- **[P1] Send a valid skills.install request:** `apps/linux-gtk/crates/app/src/views/skills.rs:160-163`
  - body: `skills.install` does not accept a bare `skillId`; it requires a legacy `{ name, installId }`, ClawHub slug, or upload payload. The Install button will fail for available skills until it uses one of the supported request shapes.
  - confidence: 0.92
- **[P1] Wrap cron enablement in patch:** `apps/linux-gtk/crates/app/src/views/cron.rs:327-330`
  - body: `cron.update` requires mutable fields under `patch`, but this sends `enabled` at the top level. The toggle request is rejected while the status chip is updated optimistically, leaving the displayed cron state out of sync with the gateway.
  - confidence: 0.95
- **[P2] Pass supported channel status parameters:** `apps/linux-gtk/crates/app/src/views/channels.rs:126-128`
  - body: `channels.status` accepts `probe`, `timeoutMs`, and `channel`, not `channelId`. The Probe action currently sends an invalid request, so users cannot verify channel health from this view.
  - confidence: 0.9
- **[P2] Read pair requests from pending:** `apps/linux-gtk/crates/app/src/views/instances.rs:96-99`
  - body: The node-pair list payload exposes pending pair requests under `pending`, but this code reads `requests`. Real pending approvals will be treated as empty, hiding pair requests that operators need to approve or reject.
  - confidence: 0.86
- **[P2] Call the supported restart RPC:** `apps/linux-gtk/crates/app/src/views/control_room.rs:66`
  - body: The gateway registers `gateway.restart.request` and `gateway.restart.preflight`, not `gateway.restart`. The Control Room restart button will always hit an unknown method instead of requesting a safe restart.
  - confidence: 0.88
- **[P2] Use the plain local gateway URL default:** `apps/linux-gtk/crates/app/src/views/onboarding.rs:99-102`
  - body: The onboarding form still pre-fills `wss://127.0.0.1:18789`, while the local gateway default is plain `ws://127.0.0.1:18789`. Fresh local users who accept the default will attempt TLS against a non-TLS listener and fail before connecting.
  - confidence: 0.86
