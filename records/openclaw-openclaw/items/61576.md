## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Send raw config text to config.set:** `apps/linux-gtk/crates/app/src/views/config.rs:222-225`
  - body: `config.set` is validated by `ConfigSetParamsSchema`, which only accepts `{ raw, baseHash? }` with additional properties rejected. This button sends `{ path, value }`, so Save will be rejected by the current gateway instead of updating config.
  - confidence: 0.93
- **[P1] Use skillKey for skills.update:** `apps/linux-gtk/crates/app/src/views/skills.rs:123-127`
  - body: Installed skill updates require `skillKey`; the current schema does not accept `skillId`. Toggling a skill from this view will fail validation before the gateway can apply the enabled state.
  - confidence: 0.94
- **[P1] Send a supported skills.install payload:** `apps/linux-gtk/crates/app/src/views/skills.rs:160-163`
  - body: `skills.install` accepts the legacy `{ name, installId }`, ClawHub, or upload payload shapes, not `{ skillId }`. The Install button therefore cannot install the listed skill against the current gateway contract.
  - confidence: 0.94
- **[P1] Wrap cron enablement changes in patch:** `apps/linux-gtk/crates/app/src/views/cron.rs:327-331`
  - body: `cron.update` requires an id or jobId plus a `patch` object. Sending `enabled` at the top level will be rejected, so the enable/disable control cannot update cron jobs.
  - confidence: 0.92
- **[P1] Use supported channel status parameters:** `apps/linux-gtk/crates/app/src/views/channels.rs:126-128`
  - body: `channels.status` accepts `channel`, `probe`, and `timeoutMs`; it does not accept `channelId`. The probe action will not target the selected channel under the current schema.
  - confidence: 0.9
- **[P1] Read pending pair requests from pending:** `apps/linux-gtk/crates/app/src/views/instances.rs:96-100`
  - body: `node.pair.list` returns `{ pending, paired }`, but this view reads `requests`. Pending pair requests will be displayed as empty even when the gateway returns them.
  - confidence: 0.89
- **[P1] Call the registered gateway restart method:** `apps/linux-gtk/crates/app/src/views/control_room.rs:65-67`
  - body: The gateway registers `gateway.restart.preflight` and `gateway.restart.request`, not `gateway.restart`. The restart button will call an unknown method and report a failure.
  - confidence: 0.94
- **[P2] Default local gateway UI to ws:** `apps/linux-gtk/crates/app/src/views/settings.rs:56-57`
  - body: The app's connection form still defaults to `wss://127.0.0.1:18789`, while the gateway-client default and local gateway path use plain `ws://127.0.0.1:18789`. Fresh users following the UI default can fail to connect before any config is loaded.
  - confidence: 0.84
