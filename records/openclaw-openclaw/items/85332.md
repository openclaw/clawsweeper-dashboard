## Summary

Keep open: current main and the latest release only support extra APT packages during local image builds, while this issue asks for a pulled-image startup or production-safe derived-image workflow that still needs product and security direction.

## What This Changes

The issue requests a slim Docker image workflow that installs deployer-selected APT packages without requiring manual container edits after each image refresh.

## Best Possible Solution

Maintainers should choose an explicit derived-image or prebuild/restart contract, document the supported Docker and Podman flow, and keep the default runtime image non-root and slim.
