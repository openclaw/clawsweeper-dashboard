## Summary

Keep open: current main and v2026.6.11 still support extra APT packages only during image builds, while this issue asks for a remote-image startup or production-safe prebuild workflow. The linked iproute2 request was already closed in favor of this broader Docker package-customization decision.

## What This Changes

Request to add a slim Docker image mode or bootstrap path that lets remote-image deployments install explicit APT packages without maintaining a custom local image manually.

## Best Possible Solution

Maintainers should choose an explicit derived-image or prebuild-and-restart contract, with docs, tests, and security review, while preserving the slim non-root default image and avoiding package installation during gateway downtime.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature request. Source inspection gives high confidence that current main and v2026.6.11 support APT packages only during image build, not pulled-image startup or prebuild automation.

## Solution Assessment

Unclear for implementation shape. The deployment gap is real, but entrypoint-time APT installation is not obviously the safest production path; a derived-image prebuild command or documented Dockerfile pattern needs maintainer approval.
