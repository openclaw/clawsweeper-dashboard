## Summary

Keep open: current main and v2026.6.11 still only support extra APT packages during image builds, while the requested pulled-image or production-safe prebuild path remains a Docker packaging and security-boundary decision.

## What This Changes

The issue requests an opt-in slim Docker image flow for installing deployer-selected APT packages when using or preparing official remote images.

## Best Possible Solution

Define an explicit derived-image or prebuild/restart workflow with docs, tests, and package-trust guidance, while keeping startup-time APT installation out of the default gateway downtime path unless maintainers deliberately approve it.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw support deployer-configured APT packages for pulled official Docker images, and should that be a derived-image prebuild flow rather than a startup-time installer?

Rationale: The implementation choice affects official image hardening, root package-manager execution, package source trust, startup downtime, and the documented env/CLI contract, so code inspection alone cannot choose the boundary.

Likely owner: steipete

Owner reason: The remaining choice is a Docker packaging and security-contract decision, and this person has recent adjacent commits hardening and documenting the current APT package build behavior.

Owner confidence: medium

Options:

- **Design a derived-image prebuild flow (recommended):** Keep this issue open and specify a prebuild command or documented `Dockerfile.extend` pattern that builds from the official image before restarting the gateway.
- **Allow a startup-time installer:** Accept the downtime and root package-manager risk by adding an explicit first-boot or entrypoint installer with caching, logging, failure semantics, and clear security docs.
- **Keep build-time customization only:** Close or defer this direction and continue steering operators to source/local Docker builds or custom Dockerfiles for extra packages.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature request. Source inspection gives high confidence that current main and v2026.6.11 support extra APT packages only during image builds, while remote images are pulled as-is.

## Solution Assessment

Unclear for implementation shape. The deployment gap is real, but entrypoint-time APT installation is probably not the safest production default; a derived-image prebuild path needs maintainer approval.
