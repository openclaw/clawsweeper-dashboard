## Summary

Keep open: current main and the latest release still only support extra APT packages during image builds, while the requested pulled-image or production-safe prebuild path remains a product and security decision.

## What This Changes

Requests an opt-in Docker image mode, startup path, or prebuild flow to install deployer-selected APT packages while keeping the official image slim.

## Best Possible Solution

Define an explicit derived-image or prebuild/restart workflow with docs, tests, and package-trust guidance, while keeping startup-time APT installation out of the default gateway downtime path unless maintainers deliberately approve it.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support deployer-configured APT packages for pulled official Docker images, and should that be a derived-image prebuild flow rather than a startup-time installer?

Rationale: The implementation choice affects official image hardening, package-manager trust, runtime privileges, downtime, and the documented env/CLI contract, so source inspection cannot choose the product and security boundary.

Likely owner: steipete

Owner reason: steipete is the best available routing candidate from the Docker APT docs and verification history for deciding whether the env/CLI and security contract should expand beyond build-time customization.

Owner confidence: medium

Options:

- **Design a derived-image prebuild flow (recommended):** Keep the issue open and specify a prebuild command or documented Dockerfile.extend pattern that builds from the official image before restarting the gateway.
- **Allow startup-time installation:** Accept the downtime and root package-manager risk by adding an explicit first-boot or entrypoint installer with caching, logging, and failure semantics.
- **Keep build-time customization only:** Defer this direction and continue steering operators to local image builds or custom Dockerfiles for extra packages.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature request. Source inspection gives high confidence that current main and v2026.6.11 support extra APT packages only during image builds, while remote images are pulled as-is.

## Solution Assessment

Unclear for implementation shape. The deployment gap is real, but entrypoint-time APT installation is not the safest production default; a derived-image prebuild path needs maintainer approval.
