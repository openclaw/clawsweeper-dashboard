## Summary

Keep open: current main and the latest release support extra APT packages only as image-build customization, while the requested pulled-image, startup, or production-safe prebuild workflow still needs a product and security decision.

## What This Changes

Request a slim Docker image workflow that lets operators configure extra Debian APT packages without manually entering or rebuilding containers after pulling/updating the official image.

## Best Possible Solution

Define an explicit derived-image prebuild/restart workflow or documented Dockerfile.extend pattern with package-trust guidance, failure semantics, docs, and tests before considering startup-time APT installation.

## Maintainer Decision

Question: Should OpenClaw support deployer-configured APT packages for pulled official Docker images, and if so should the supported path be a derived-image prebuild flow instead of a startup-time installer?

Rationale: The choice affects official image hardening, root package-manager execution, gateway downtime, env/CLI contract semantics, and constrained-host behavior, so code inspection cannot safely pick the product/security boundary.

Likely owner: steipete

Owner confidence: medium

Options:

- **Design derived-image prebuild flow (recommended):** Keep this issue open and specify a prebuild command or documented Dockerfile.extend pattern that builds from the current official image before restarting the gateway.
- **Allow startup-time installer:** Accept the downtime and package-manager risk by adding an explicit first-boot or entrypoint installer with caching, logging, and fail-loud semantics.
- **Keep build-time customization only:** Close or defer this direction and continue steering operators to local/source image builds or custom Dockerfiles for extra packages.
