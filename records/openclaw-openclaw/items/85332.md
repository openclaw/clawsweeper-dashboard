## Summary

Keep open: current main and v2026.6.11 support extra APT packages only as build-time Docker customization, while the requested pulled-image or production-safe prebuild/startup path remains an unresolved Docker packaging and security decision.

## What This Changes

The issue requests an opt-in slim Docker image or bootstrap path that can install deployer-selected APT packages for deployments using pulled OpenClaw images.

## Best Possible Solution

Define an explicit derived-image prebuild/restart workflow, or a documented Dockerfile.extend pattern, with package-trust guidance and focused Docker setup tests before expanding beyond the existing build-time ARG contract.
