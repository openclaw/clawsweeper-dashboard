## Summary

Keep open: current main and the latest release support extra APT packages only as build-time Docker/Podman image customization, while this issue asks for a pulled-image startup path or production-safe prebuild workflow that still needs product and security direction.

## What This Changes

Request to add a slim Docker image mode or bootstrap path that installs deployer-specified APT packages while keeping the official image small.

## Best Possible Solution

Maintainers should choose an explicit derived-image or prebuild/restart workflow that reuses the existing package variable where possible, documents the Dockerfile.extend fallback, and keeps package installation out of default gateway startup.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature request. Source inspection gives high confidence that current main and v2026.6.11 support APT packages only during image build, not pulled-image startup or production-safe prebuild automation.

## Solution Assessment

Unclear for implementation shape. The deployment gap is real, but entrypoint-time APT installation is not clearly the safest production default; a derived-image prebuild command or documented Dockerfile pattern needs maintainer approval.
