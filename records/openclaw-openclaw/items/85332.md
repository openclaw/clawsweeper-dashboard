## Summary

Keep open: current main and the latest release already support extra APT packages only as a local image-build customization, while this issue still asks for a pulled-image startup or production-safe prebuild workflow that needs maintainer product and security direction.

## What This Changes

Request to add an opt-in Docker image path that installs deployer-specified APT packages while keeping the official image slim.

## Best Possible Solution

Maintainers should choose an explicit derived-image or prebuild/restart contract, with docs and tests, while preserving the slim non-root default image and avoiding package installation during gateway downtime.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature request. Source inspection gives high confidence that current main and v2026.6.9 support APT packages only during image build, not pulled-image startup or prebuild automation.

## Solution Assessment

No for entrypoint-time APT as the default production answer; the safer end state is a maintainer-approved derived-image/prebuild contract or documented extension Dockerfile pattern with clear security and downtime semantics.
