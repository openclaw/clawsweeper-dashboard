## Summary

Keep open: current main and the latest release still support extra APT packages only during local image builds, while this issue asks for a pulled-image startup path or production-safe derived-image workflow that still needs maintainer product and security direction.

## What This Changes

Request to add an opt-in slim Docker image workflow that installs deployer-selected APT packages without bloating the default image or requiring repeated manual container edits.

## Best Possible Solution

Maintainers should choose a production-safe derived-image or explicit prebuild/restart contract, with docs, tests, doctor visibility, and clear root/network/cache failure semantics before changing the official image startup path.

## Solution Assessment
