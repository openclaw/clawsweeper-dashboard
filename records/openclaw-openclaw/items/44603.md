## Summary

Keep open: current main and the latest release still expose PTY only as a per-call exec parameter, while the requested global `tools.exec.pty` default is absent from schema, default resolution, runtime wiring, and docs. The remaining decision is whether maintainers want a new security-sensitive exec config surface, not conservative cleanup closure.

## What This Changes

Request adding `tools.exec.pty` to `openclaw.json` as a global default so exec commands can use PTY output without the model passing `pty: true` on every call.

## Best Possible Solution

If maintainers approve the config surface, add a default-off `tools.exec.pty` contract across schema, types, resolved defaults, direct exec, gateway approval exec, docs, and focused tests while preserving per-call override precedence and coordinating sandbox behavior.
