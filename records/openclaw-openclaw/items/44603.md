## Summary

Keep open: current main and the latest release still expose PTY only as a per-call exec parameter, while the requested global `tools.exec.pty` default is absent from config schema, types, docs, and default wiring. The request is valid source-reproducible work, but it adds a new shell-exec config surface and needs maintainer product/security approval before implementation.

## What This Changes

Request to add an opt-in global `tools.exec.pty` configuration default so long-running exec commands can use PTY streaming without relying on every model call to pass `pty: true`.

## Best Possible Solution

If maintainers approve the surface, add opt-in `tools.exec.pty` across schema, types, help, docs, resolver/default wiring, direct and gateway exec paths, with per-call precedence, sandbox-warning coordination, and focused tests.
