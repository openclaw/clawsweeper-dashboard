- `P2`: This is a bounded exec ergonomics/config request with real long-running-command UX impact, but it is not an outage, crash loop, or data-loss emergency.

## Summary

Keep open: current `main` and latest release still expose PTY only as a per-call exec parameter, while the requested global `tools.exec.pty` config default is absent from schema, types, docs, and runtime default wiring. The prior implementation PRs are closed unmerged, and the open sandbox PTY warning issue is related but does not cover this config-default request.

## What This Changes

The issue requests a global `tools.exec.pty` setting so exec calls can default to PTY mode and stream long-running command output without the model passing `pty: true` each time.

## Best Possible Solution

If maintainers approve the config surface, add canonical `tools.exec.pty` schema, types, help, docs, and focused tests; thread the default through direct and gateway exec with per-call precedence; and coordinate sandbox suppression messaging with the related warning issue.
