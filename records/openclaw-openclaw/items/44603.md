## Summary

Keep open: current main and v2026.6.11 still expose PTY only as a per-call exec parameter, while the requested global `tools.exec.pty` default is absent from schema, resolved defaults, runtime wiring, and docs. Because this would add a security-sensitive global shell-exec default, it needs maintainer product/security direction rather than cleanup closure.

## What This Changes

The issue requests a default-off `tools.exec.pty` config option so long-running exec commands can use PTY streaming by default without relying on every model tool call to pass `pty: true`.

## Best Possible Solution

If maintainers approve the config surface, add a default-off `tools.exec.pty` contract across schema, types, direct exec, gateway approval exec, docs, and focused tests while preserving per-call override precedence and sandbox suppression behavior.
