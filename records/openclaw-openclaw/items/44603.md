## Summary

Keep open: current main and the latest release still expose PTY only as a per-call exec parameter, while the requested global `tools.exec.pty` config default is absent from schema, types, docs, and default wiring. The exact implementation PRs are closed unmerged, and the open sandbox PTY warning issue is related but does not cover this config-default request.

## What This Changes

Request adding a global `tools.exec.pty` boolean in `openclaw.json` so exec calls can default to PTY mode and stream long-running command output without relying on each model call to pass `pty: true`.

## Best Possible Solution

If maintainers approve the config surface, add canonical `tools.exec.pty` schema, types, help, docs, and tests; thread the default through direct and gateway exec paths with per-call precedence; and coordinate sandbox suppression messaging with the related warning issue.

## Reproduction Assessment

Yes. Source inspection shows current main accepts per-call `pty` but has no `tools.exec.pty` schema/type/docs/default path, and both direct and gateway exec still read only `params.pty`.

## Solution Assessment

Unclear until maintainers approve the product/security direction. The proposed technical shape is plausible, but the best fix must include the full config contract, direct/gateway coverage, and sandbox-warning coordination.
