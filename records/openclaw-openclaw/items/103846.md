## Repair Work Prompt

Fix the Anthropic OAuth pre-expiry refresh no-op reported in https://github.com/openclaw/openclaw/issues/103846. In the auth-profile lifecycle, once `createOAuthManager` classifies an OAuth credential as needing refresh and acquires the global refresh lock, ensure the built-in provider path invokes the resolved provider's `refreshToken` operation instead of delegating to `getOAuthApiKey`, whose independent raw-expiry check can return unchanged credentials. Preserve plugin-owned refresh, the Chutes special path, timeout and locking behavior, identity checks, refresh-token rotation handling, and persistence semantics. Do not change `getOAuthApiKey` behavior for `src/agents/sessions/auth-storage.ts`, alter refresh margins, add config, or broaden provider policy. Add regression coverage showing an Anthropic credential expiring in four minutes triggers exactly one refresh and returns/persists rotated credentials, while a credential outside the manager margin still avoids refresh. Do not edit `CHANGELOG.md`.
