## Summary

Keep this PR open for a small correctness repair. The cleanup migration follows the repository’s preferred helper, but the combined hook can skip directory cleanup if either SQLite-close helper throws; use a `finally` so test-owned state is always removed. The related WAL-verifier fix is already merged, while this PR is a distinct follow-up cleanup.

## What This Changes

The PR moves database-verifier test temporary directories from file-wide cleanup to per-test cleanup after the test SQLite handles are closed.

## System Context

The database verifier tests create temporary OpenClaw state directories and open process-held SQLite databases inside them. Their Vitest teardown must release those database handles before deleting the corresponding directory so each test starts from isolated filesystem state.

## Architecture Diagram

flowchart LR
  A[Verifier test case] --> B[Temporary state directory]
  B --> C[SQLite state and agent handles]
  C --> D[Per-test teardown]
  D --> E[Close database handles]
  E --> F[Remove temporary directory]
  F --> G[Next isolated test]

## Best Possible Solution

Keep the close-before-delete ordering, but wrap the two database-close calls and tracker cleanup in a `try`/`finally` so every test-owned directory is removed even when a teardown close fails.
