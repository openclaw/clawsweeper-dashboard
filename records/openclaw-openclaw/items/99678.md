Keep open: this PR remains the active fix for a shipped runtime-alias bug, and the refreshed head removes the prior lint blocker. I found no blocking correctness or security findings in the focused source review.

## What This Changes

The PR updates runtime-postbuild alias generation so stable and legacy runtime aliases explicitly forward a target chunk's default export when one exists, with a regression test for default-only chunks.

## Best Possible Solution

Land this focused generator fix after remaining CI and maintainer review, keeping the separate bundled-plugin runtime wrapper path unchanged.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: current main emits only export-star aliases, the compaction path imports default through such an alias, and a Node ESM probe confirms export-star omits default. I did not run a packaged compaction flow in this read-only review.

## Solution Assessment

Yes, this is the best fix boundary: the alias generator is the layer that drops the default export, while callers legitimately import the default runtime helper. Changing the compaction caller would leave the other generated aliases as latent traps.
