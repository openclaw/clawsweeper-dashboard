## What This Changes

This PR makes cron completion webhooks treat non-2xx responses as failures, retries proven-unsent direct notifications, and repairs Workboard board targeting, claim-capacity accounting, archived-card handling, outage fallback, and duplicate change-service starts.

## System Context

Cron completion handling sends webhook and announcement notifications after scheduled jobs finish, while the Workboard plugin dispatches ready cards into subagent runs and the Control UI selects the intended board. These paths affect whether operators receive failure signals and whether queued work is started on the correct board without duplicate services or stale capacity blocks.
