## Summary

Keep open: current main still routes added `acp` config through the restart fallback, and the open linked PR is a candidate fix rather than a merged implementation.

## What This Changes

The issue reports that adding ACP config to a running gateway auto-enables `acpx`, triggers a gateway restart, then leaves `acpx` unloaded and repeats the restart cycle.

## Best Possible Solution

Land exactly one focused ACP reload fix, preferably through the open linked PR after maintainer review, then close this issue with the merged commit and release provenance.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source-reproducible: current main still auto-enables `acpx` from ACP config, lacks an `acp` reload rule, and sends unmatched config paths to the restart path. I did not run the live systemd loop in this read-only cleanup pass.

## Solution Assessment

Yes, the narrow maintainable fix is to classify ACP config changes as plugin hot reloads so the ACPX lifecycle can re-register without a gateway process restart. The issue should remain open until the linked candidate PR lands or is rejected.
