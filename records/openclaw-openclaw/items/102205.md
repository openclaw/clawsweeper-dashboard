## Summary

Keep open: current main still lacks an ACP reload rule, so `acp` config changes fall through to gateway restart, and the live closing PR has not merged yet.

## What This Changes

The issue reports that adding ACP config while the gateway is running auto-enables acpx, classifies the config change as a restart, then loses the acpx runtime after the self-triggered restart and loops.

## Best Possible Solution

Land exactly one ACP reload fix on current main so `acp` config changes hot-reload plugin services instead of scheduling a gateway restart, then let the linked closing PR resolve this issue.
