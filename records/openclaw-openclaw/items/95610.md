## Summary

Keep open: current main appears to have reduced the system-prompt part by placing channel/session guidance below the internal cache boundary, but the central `message_tool_only` tool-schema churn is still present and explicitly tested. This is not implemented, obsolete, or safely closeable without a maintainer decision on where visible-reply steering should live for OpenAI-style prefix caching.

## What This Changes

The issue asks OpenClaw to keep OpenAI prompt-cache prefixes stable by moving per-turn `message_tool_only` guidance out of cached system/tool-prefix content.

## Best Possible Solution

Keep the issue open and have maintainers choose a boundary-safe design that keeps `message` tool schemas byte-stable across delivery-mode flips while still delivering visible reply guidance late enough for OpenAI automatic prefix caching.
