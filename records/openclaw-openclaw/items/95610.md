## Summary

Keep open. Current main still derives the system-prompt messaging guidance from the per-turn `message_tool_only` delivery state, while the embedded runner resolves channel message hints on each run; that leaves a source-supported path for the reported OpenAI prefix churn. The related draft PR is a promising broader repair candidate, but it is not merged and the safety boundary between prompt-stable guidance and actual reply delivery needs maintainer confirmation.

## What This Changes

Fix OpenAI prompt-cache churn by keeping message-tool guidance and other delivery-dependent prompt content byte-stable across turns while preserving correct visible-reply delivery.

## System Context

The embedded-agent runner assembles the system prompt and the visible tool catalogue before it sends an agent turn to a provider. Per-channel delivery state and message-tool hints feed that assembly, so changes in those facts can change the prefix OpenAI attempts to reuse from its automatic cache.

## Architecture Diagram

flowchart LR
  A[Incoming channel turn] --> B[Resolve delivery policy]
  B --> C[Resolve message-tool hints]
  C --> D[Build system prompt]
  D --> E[Send tools and messages to OpenAI]
  E --> F[Automatic prefix-cache lookup]
  B --> G[Actual reply delivery]

## Best Possible Solution

Adopt one session-stable prompt-facing delivery/tool shape, enforce the actual per-turn delivery requirement outside that reusable prefix, and validate consecutive OpenAI turns for both warm cache reads and correct no-duplicate visible replies.

## Solution Assessment
