## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Derive callbacks from trusted session identity:** `extensions/gateway-restart/index.ts:36-39`
  - body: The tool asks the model for `sessionKey` and later treats it as the owner-trusted continuation target. The current gateway restart path derives the session from trusted runtime context in `src/agents/tools/gateway-tool.ts`, so a plugin restart API should not let model parameters choose another session.
  - confidence: 0.91
- **[P1] Use the canonical gateway restart path:** `extensions/gateway-restart/index.ts:160-164`
  - body: Writing a plugin-owned marker and calling `process.exit(0)` bypasses the current restart scheduler, coalescing/deferral guards, SQLite restart sentinel, durable continuation queue, and authorization behavior. This creates a second restart mechanism with different safety properties.
  - confidence: 0.88
- **[P2] Preserve complete follow-up run context:** `src/auto-reply/reply/queue/build-followup-run.ts:107-119`
  - body: The cold-session builder restores only a subset of `FollowupRun.run` and hardcodes `blockReplyBreak`, omitting current context fields for workspace/cwd variants, account/group, sender/provenance, elevation, and delivery mode. Replayed turns can run with the wrong context or policy.
  - confidence: 0.84
- **[P2] Keep restart markers until continuation delivery is durable:** `extensions/gateway-restart/index.ts:221-223`
  - body: `enqueueFollowupTurn()` only confirms an in-memory queue enqueue, but the plugin deletes the marker immediately afterward. If the process exits or crashes before drain/delivery, the restart continuation is lost; the current sentinel path clears state only after durable continuation handling.
  - confidence: 0.86
- **[P2] Honor follow-up dedupe semantics:** `src/plugins/runtime/runtime-followup.ts:30-37`
  - body: The API documentation says the call returns false when a turn is deduped, but this implementation passes dedupe mode `"none"` into `enqueueFollowupRun`, so retries or duplicate plugin events will enqueue duplicate follow-up turns instead of reporting a dedupe.
  - confidence: 0.78
