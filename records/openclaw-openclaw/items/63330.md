  - body: The tool asks the model for `sessionKey` and later uses that value for an owner-trusted follow-up turn. Current gateway restart derives the target from trusted runtime session context first, so this path should not let a tool argument choose another session's callback target.
  - confidence: 0.92

  - body: This writes its own marker file and exits the process directly, bypassing the gateway restart scheduler, session-key coalescing guard, SQLite sentinel, and durable restart continuation queue. That creates a second restart authority with weaker policy and durability than the existing path.
  - confidence: 0.9
- **[P1] Preserve complete follow-up run context:** `src/auto-reply/reply/queue/build-followup-run.ts:107-119`
  - body: The cold-session builder reconstructs only a subset of `FollowupRun.run` and hardcodes reply behavior, omitting account/group/sender/provenance/cwd/elevation fields used by routing and authorization paths. Post-restart turns can resume with the wrong context or tool policy.
  - confidence: 0.86
- **[P2] Keep markers until continuation delivery is durable:** `extensions/gateway-restart/index.ts:215-223`
  - body: `enqueueFollowupTurn()` only confirms an in-memory follow-up queue item, but the watcher deletes the marker immediately. A crash or second restart before drain/delivery can lose the continuation; current restart continuations are cleared only after durable session-delivery enqueue.
  - confidence: 0.82
