Full review comments:

- **[P1] Derive the callback session from runtime context:** `extensions/gateway-restart/index.ts:37-39`
  - body: The tool asks the model for `sessionKey`, then writes that value into the marker and the watcher later enqueues an owner-trusted followup for it. Current `gateway` restart derives the session from trusted runtime context first, so this PR lets a tool call target another guessed session for a trusted continuation.
  - confidence: 0.94
- **[P1] Use the canonical gateway restart path:** `extensions/gateway-restart/index.ts:164`
  - body: Calling `process.exit(0)` directly bypasses the existing restart-disable check, SIGUSR1 scheduling, restart sentinel write/cleanup hooks, and drain lifecycle used by `createGatewayTool`. Route this through the host-owned gateway restart/sentinel path instead of adding a second restart implementation.
  - confidence: 0.92
- **[P1] Preserve the full followup run context:** `src/auto-reply/reply/queue/build-followup-run.ts:107-119`
  - body: This rebuilt cold-session run omits account, group, sender, spawned cwd/workspace, bash elevation defaults, configured block streaming break, owner numbers, and input provenance that current followup execution and compaction/tool policy consume. Cold plugin followups can therefore resume under the wrong routing or security context.
  - confidence: 0.9
- **[P2] Import the declared TypeBox package:** `extensions/gateway-restart/index.ts:4-5`
  - body: The plugin imports `@sinclair/typebox`, but its package manifest declares no dependency and the repo's plugin packages use the declared `typebox` package. An installed plugin package can fail to load before registration with `ERR_MODULE_NOT_FOUND`.
  - confidence: 0.88

  - body: The branch's `createQaMultipassPlan` shape no longer includes `concurrency` or forwards `--concurrency` to the guest QA command, while current main still supports that option. Rebasing this as-is would make Multipass runs ignore the requested worker count.
  - confidence: 0.86
