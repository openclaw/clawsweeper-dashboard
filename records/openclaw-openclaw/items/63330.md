## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Derive the restart session from trusted context:** `extensions/gateway-restart/index.ts:36-39`
  - body: sessionKey is model-supplied tool input, but the marker later uses it to enqueue an owner-trusted follow-up turn. This needs to come from the trusted current session/tool context, not arbitrary tool parameters, or one session can target another session's continuation.
  - confidence: 0.93
- **[P1] Use the canonical gateway restart path:** `extensions/gateway-restart/index.ts:160-164`
  - body: This writes a plugin-owned marker and exits the process directly, bypassing commands.restart, the SIGUSR1 restart scheduler, the SQLite restart sentinel, and durable session-delivery continuation. That creates a second restart contract that can ignore operator policy and lose the callback after another crash.
  - confidence: 0.91
- **[P1] Preserve the full follow-up run context:** `src/auto-reply/reply/queue/build-followup-run.ts:107-119`
  - body: The cold-run builder restores only a subset of FollowupRun.run and hardcodes blockReplyBreak, while current runs carry account, group, cwd, skills, elevation, and delivery-policy fields. Cold plugin follow-ups can therefore run in the wrong workspace or with the wrong policy/session context.
  - confidence: 0.88
- **[P2] Import the declared TypeBox package:** `extensions/gateway-restart/index.ts:4-5`
  - body: The new plugin imports @sinclair/typebox, but this repo and existing plugin packages use typebox, and the new package manifest declares no runtime dependency. External or package-isolated plugin loading can fail before registration.
  - confidence: 0.9
- **[P2] Keep Multipass concurrency forwarding:** `extensions/qa-lab/src/multipass.runtime.ts:365-368`
  - body: The PR removes concurrency from the Multipass plan and no longer passes --concurrency to the guest QA command, while the CLI still parses and forwards that option. Users selecting a Multipass concurrency will silently get the default worker count instead.
  - confidence: 0.86
- **[P2] Document the new runtime namespace before exposing it:** `src/plugins/runtime/types-core.ts:182-203`
  - body: This adds api.runtime.followup as a public plugin runtime contract, but there is no matching SDK documentation or contract-surface update. Plugin authors would get an undocumented privileged API with unclear trust, dedupe, and upgrade semantics.
  - confidence: 0.82
