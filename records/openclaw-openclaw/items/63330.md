Full review comments:

- **[P1] Derive callbacks from trusted session identity:** `extensions/gateway-restart/index.ts:36-39`
  - body: The tool asks the model for `sessionKey` and later uses that value for an owner-trusted follow-up turn. Current gateway restart prefers the runtime `agentSessionKey` so model-supplied params cannot queue work into another session; this path should derive the callback target from trusted tool/session context or a maintainer-approved capability boundary.
  - confidence: 0.92
- **[P1] Use the canonical gateway restart path:** `extensions/gateway-restart/index.ts:160-164`
  - body: This writes its own JSON marker and exits the process, bypassing `commands.restart`, SIGUSR1 scheduling/coalescing, SQLite restart sentinel state, and durable restart continuation recovery. That creates a second restart authority with weaker policy and durability than the current gateway restart path.
  - confidence: 0.9
- **[P1] Preserve complete follow-up run context:** `src/auto-reply/reply/queue/build-followup-run.ts:107-119`
  - body: The cold run reconstruction restores only a subset of run context and hardcodes `blockReplyBreak`, omitting workspace/cwd, group/account/sender/provenance/elevation defaults that current queue grouping and runtime authorization paths use. Post-restart turns can run with wrong workspace, routing/account context, or tool policy.
  - confidence: 0.84
- **[P2] Keep markers until continuation delivery is durable:** `extensions/gateway-restart/index.ts:221-223`
  - body: `enqueueFollowupTurn()` only confirms an in-memory queue item; deleting the marker here means a crash or second restart before drain/delivery can lose the continuation. Current restart sentinel continuations go through durable session delivery recovery before clearing sentinel state.
  - confidence: 0.8
- **[P2] Declare the plugin runtime dependencies:** `extensions/gateway-restart/package.json:1-15`
  - body: `index.ts` imports `@sinclair/typebox`, but this plugin package declares no dependencies. A standalone/plugin install can fail module resolution unless the dependency is owned by `extensions/gateway-restart/package.json` or the import is replaced with an SDK-provided schema helper.
  - confidence: 0.78
- **[P2] Honor the follow-up dedupe contract:** `src/plugins/runtime/runtime-followup.ts:30-36`
  - body: The public type says the method can return false when a request is deduped, but the implementation passes dedupe mode `none`, so plugin retries can enqueue duplicate owner-trusted turns. Either implement explicit idempotency/dedupe semantics or change the API contract before exposing it.
  - confidence: 0.76
