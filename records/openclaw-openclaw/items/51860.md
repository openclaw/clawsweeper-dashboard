## Summary

Keep open. Current main and the latest release still manage macOS gateway install/status as a user LaunchAgent in the GUI launchd domain; the remaining system LaunchDaemon path is a real setup reliability gap that needs product and security direction, not cleanup closure.

## What This Changes

Request managed macOS system LaunchDaemon install/status support so the gateway can start before user login and report system-domain service state accurately.

## Best Possible Solution

Define one audited macOS launchd user/system scope model across install, status, lifecycle, doctor, docs, and tests, keeping the user LaunchAgent default while making any system LaunchDaemon path explicit and security-reviewed.

## Reproduction Assessment

Yes, at source level. Current main still resolves Darwin gateway install/status through the LaunchAgent registry, user LaunchAgents plist path, and gui-domain launchctl calls; no live macOS reboot scenario was run in this read-only review.

## Solution Assessment

No, the raw --system flag sketch is only a plausible direction. The best fix is a shared launchd scope and privilege contract that also covers status, lifecycle, doctor repair, docs, and regression proof.
