## Summary

Keep open. Current main and v2026.6.11 still install and manage the macOS gateway as a user LaunchAgent, while system LaunchDaemon discovery is diagnostic only and docs still say headless LaunchDaemon support is custom/not shipped. The durable macOS TMPDIR part has been addressed, and open duplicate-manager PRs may mitigate one failure mode, but the requested boot-without-login install/status support remains a product and security decision.

## What This Changes

Request to add macOS system LaunchDaemon support for gateway install/status so the gateway can start before user login and report system-domain state accurately.

## Best Possible Solution

Define one explicit macOS user/system launchd scope contract across install, status, stop, uninstall, doctor, docs, and tests, keeping user LaunchAgent as the safe default and adding only an audited explicit LaunchDaemon path or guidance flow.

## Reproduction Assessment

Yes, at source level. Current main still has no system install flag, resolves Darwin service management through the LaunchAgent registry, writes under Library/LaunchAgents, and probes gui/<uid>; I did not run a live macOS reboot scenario in this read-only review.

## Solution Assessment

No, not as a one-off flag only. The maintainable solution is a shared launchd user/system scope model covering privilege, execution user, coexistence, install, status, lifecycle, doctor, docs, and tests.
