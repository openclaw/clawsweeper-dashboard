## Summary

Keep open. Current main still treats macOS gateway install, stop, restart, uninstall, and primary status as a user LaunchAgent in the gui domain, while system LaunchDaemon discovery is diagnostic only; the requested pre-login LaunchDaemon lifecycle remains a product and security-sensitive gap.

## What This Changes

The issue requests macOS Gateway install/status support for `/Library/LaunchDaemons` so the Gateway can start before user login and status can report system-domain services accurately.

## Best Possible Solution

Define one explicit macOS LaunchAgent/LaunchDaemon scope contract across install, status, doctor, docs, and tests, keeping user LaunchAgent as the default and adding an audited explicit LaunchDaemon mode or documented external-supervisor guidance.

## Reproduction Assessment

Yes, at source level: current main resolves macOS service management to a user LaunchAgent path and gui-domain launchctl checks, while system services are only surfaced by deep diagnostics.

## Solution Assessment

No, not as a one-off flag; the best fix needs a shared launchd scope model covering sudo, UserName, environment, install/status/doctor behavior, and upgrade safety.
