## Summary

Keep open. Current main and the latest release still manage macOS Gateway installs as user LaunchAgents; `gateway status --deep` can discover system LaunchDaemons, but there is no managed boot-before-login LaunchDaemon install/status contract yet.

## What This Changes

The issue requests macOS system LaunchDaemon support for gateway install/status so the gateway can start at boot before user login.

## Best Possible Solution

Define one explicit macOS launchd user/system scope contract across install, status, stop, uninstall, doctor, docs, and tests, keeping the user LaunchAgent default while making privileged LaunchDaemon behavior explicit and audited.

## Reproduction Assessment

Yes, at source level. Current main still installs and checks the macOS gateway as a user LaunchAgent in `gui/<uid>`, while `/Library/LaunchDaemons` is only an extra deep-scan discovery target.

## Solution Assessment

No. The bare `--system` flag sketch is only a plausible direction; the best solution needs a shared launchd scope contract across install, status, lifecycle, doctor, docs, and security review.
