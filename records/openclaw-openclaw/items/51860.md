## Summary

Keep open. Current main and the latest release still install and report the macOS gateway as a user LaunchAgent; `gateway status --deep` can now discover system LaunchDaemons as extra diagnostics, but the requested boot-without-login LaunchDaemon install/status mode remains unresolved and security-sensitive.

## What This Changes

Request first-class macOS system LaunchDaemon install/status support so the gateway can start at boot without a logged-in user and status reflects system-domain services.

## Best Possible Solution

Define one audited macOS launchd user/system scope model across install, status, doctor, lifecycle, docs, and tests, keeping LaunchAgent as the safe default and adding either explicit LaunchDaemon support or clear diagnostic-only guidance.

- **Diagnostic guidance only:** Do not manage LaunchDaemons from OpenClaw yet; improve status/doctor guidance so headless operators can safely own custom launchd setup themselves.
- **Full managed LaunchDaemon mode:** Add first-class LaunchDaemon install/status/start/stop/uninstall support, accepting the larger privileged-service surface after owner review.

## Solution Assessment

No, not as a one-off `--system` flag patch. The maintainable solution is a shared launchd scope contract covering privilege, execution user, coexistence, lifecycle, status, doctor, docs, and regression tests.
