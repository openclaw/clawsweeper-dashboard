## Summary

Keep open. Current main and v2026.6.11 still treat the macOS managed gateway service as a user LaunchAgent; `status --deep` can discover extra system services, but first-class system LaunchDaemon install/status remains unresolved and needs maintainer product/security direction.

## What This Changes

The issue requests macOS system LaunchDaemon support for gateway install/status so the gateway can start at boot before user login.

## Best Possible Solution

Define an explicit macOS system LaunchDaemon lifecycle contract, or explicitly document it as unsupported, covering install/status/stop/uninstall/doctor, sudo/user scoping, stable TMPDIR and env/secrets handling, upgrade behavior, and operator-facing docs.

## Reproduction Assessment

Yes from source and discussion: the Darwin service adapter still installs and inspects a user LaunchAgent, the install command has no system-mode flag, and runtime hints call custom LaunchDaemons not shipped. I did not perform a live macOS reboot reproduction in this read-only review.

## Solution Assessment

No, the suggested `--system` flag is a useful starting point but is not by itself the best complete fix. The maintainable solution needs a full privileged launchd lifecycle and upgrade/security contract across CLI, status, doctor, docs, and tests.
