## Summary

Keep open. Current main and the latest release still manage macOS gateway install/status as a user LaunchAgent path; durable TMPDIR handling has improved, but the requested boot-without-login LaunchDaemon install/status mode remains unresolved and security-sensitive.

## What This Changes

The issue requests macOS system LaunchDaemon support for `openclaw gateway install` and status reporting so the gateway can start after reboot without a user login.

## Best Possible Solution

Define one explicit macOS launchd user/system scope contract across install, status, doctor, stop, uninstall, docs, and tests, keeping the user LaunchAgent as the safe default and adding an audited LaunchDaemon path only through clear privileged-operator UX.

## Reproduction Assessment

Yes, at source level: current main still registers no system install flag and resolves Darwin gateway install/status through the LaunchAgent registry, user LaunchAgents plist path, and `gui/<uid>` launchctl calls. The issue and related comments also provide live macOS evidence, but I did not run a reboot scenario in this read-only review.

## Solution Assessment

No, not as a one-off `--system` flag alone. The maintainable solution is a shared launchd scope model covering privilege, execution user, coexistence, install/status/lifecycle behavior, doctor repair, docs, and regression tests.
