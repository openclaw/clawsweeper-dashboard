## Summary

Keep open. Current main and the latest v2026.6.11 release still manage macOS gateway installs as user LaunchAgents, while system LaunchDaemon discovery is diagnostic-only; the requested boot-without-login install/status mode remains a product and security decision.

## What This Changes

The issue asks for macOS gateway install/status support for system-level LaunchDaemons so the gateway can start at boot without user login.

## Best Possible Solution

Define one explicit macOS user/system launchd contract across install, status, doctor, lifecycle, docs, and tests, keeping the user LaunchAgent as the safe default and adding an audited LaunchDaemon path only after owner approval.

- **Diagnostic guidance only:** Do not manage LaunchDaemons yet; improve status and doctor to identify system services and provide copy-paste manual launchctl guidance.
- **Full LaunchDaemon lifecycle:** Add install/status/start/stop/restart/uninstall support for LaunchDaemons as a larger privileged-service feature after owner review.

## Reproduction Assessment

Yes, at source level. Current main still resolves Darwin gateway install/status through the LaunchAgent registry, user LaunchAgents plist path, and gui/<uid> launchctl checks; I did not run a live macOS LaunchDaemon scenario in this read-only review.

## Solution Assessment

Unclear as a one-off --system flag. The maintainable solution is a shared launchd user/system scope model that covers install, status, doctor, lifecycle commands, privilege handling, docs, and tests together.
