## Summary

Keep open. Current main and the latest release still install and report the macOS gateway as a per-user LaunchAgent, while LaunchDaemon support is limited to diagnostic discovery and related duplicate-manager mitigation work; the requested boot-without-login install/status mode remains a product and security decision.

## What This Changes

The issue requests macOS gateway install/status support for system-level LaunchDaemons so the gateway can start at boot before user login and status can report that mode accurately.

## Best Possible Solution

Define one explicit macOS launchd user/system scope contract across install, status, doctor, stop, uninstall, docs, and tests, keeping the user LaunchAgent as the safe default and adding an audited LaunchDaemon path only with clear privileged-operator UX.

## Reproduction Assessment

Yes, at source level. Current main still resolves Darwin gateway install/status through the LaunchAgent registry, user LaunchAgents plist path, and `gui/<uid>` launchctl calls; I did not run a live macOS reboot scenario in this read-only review.

## Solution Assessment

No, not as a one-off `--system` flag alone. The maintainable solution is a shared launchd scope model covering privilege, execution user, coexistence, install/status/lifecycle behavior, doctor repair, docs, and regression tests.
