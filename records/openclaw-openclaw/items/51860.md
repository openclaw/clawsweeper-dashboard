## Summary

Keep open. Current main and v2026.6.11 still manage the macOS gateway as a user LaunchAgent; system LaunchDaemon discovery is diagnostic, and first-class boot-without-login support remains a privileged service-mode product/security decision.

## What This Changes

The issue requests macOS system LaunchDaemon support for gateway install/status so the gateway can start at boot before user login.

## Best Possible Solution

Define one explicit macOS launchd scope contract across install, status, doctor, stop, uninstall, docs, and tests, keeping user LaunchAgent as the safe default and adding LaunchDaemon support only through clear privileged-operator UX.

## Solution Assessment

No, not as a one-off `--system` flag alone. The maintainable fix is a shared launchd scope model that covers privilege, execution user, coexistence, install/status/lifecycle behavior, doctor repair, docs, and regression tests.
