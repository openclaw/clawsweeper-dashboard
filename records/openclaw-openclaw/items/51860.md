## Summary

Keep open. Current main and the latest release still expose macOS gateway install/status as a user LaunchAgent path; durable TMPDIR handling improved, but first-class boot-without-login LaunchDaemon install/status support remains unresolved and security-sensitive.

## What This Changes

Request macOS gateway install/status support for a system LaunchDaemon so the gateway can start at boot without a user login and report system-domain service state correctly.

## Best Possible Solution

Define one explicit macOS launchd user/system scope contract across install, status, doctor, stop, uninstall, docs, and tests, keeping the user LaunchAgent as the safe default and adding an audited LaunchDaemon path only through clear privileged-operator UX.
