## Summary

Keep open. Current main and v2026.6.11 still manage the macOS gateway as a per-user LaunchAgent; system LaunchDaemon discovery is diagnostic only, so the boot-without-login install/status request remains unresolved and needs maintainer product/security direction.

## What This Changes

The issue requests a macOS system LaunchDaemon install/status mode for the gateway so it can start before user login and report system-domain services accurately.

## Best Possible Solution

Define one explicit macOS user/system launchd scope model across install, status, doctor, stop, uninstall, docs, and tests, keeping the user LaunchAgent as the safe default and adding an audited explicit LaunchDaemon path only with clear privileged-operator UX.

## Reproduction Assessment

Yes, at source level. Current main still resolves Darwin gateway install/status through the LaunchAgent registry, user LaunchAgents plist path, and gui/<uid> launchctl calls; I did not run a live macOS reboot scenario in this read-only review.

## Solution Assessment

No, not as a one-off --system flag alone. The maintainable solution is a shared launchd scope model covering privilege, execution user, coexistence, install/status/lifecycle behavior, doctor repair, docs, and tests.
