## Summary

Keep open. Current main and v2026.6.11 still manage the macOS Gateway service as a user LaunchAgent in the GUI launchd domain; system LaunchDaemon support remains a product and security decision, while `gateway status --deep` is only extra discovery.

## What This Changes

Request first-class macOS system LaunchDaemon install/status support so the Gateway can start before GUI login and report system-domain services accurately.

## Best Possible Solution

Define one explicit macOS launchd user/system scope contract across install, status, stop, uninstall, doctor, docs, and tests, keeping user LaunchAgent as the safe default and adding only an audited explicit LaunchDaemon path or guidance flow.

## Reproduction Assessment

Yes, at source level. Current main still resolves Darwin Gateway install/status through the LaunchAgent registry, user LaunchAgents plist path, and gui/<uid> launchctl calls; I did not run a live boot-without-login macOS scenario.

## Solution Assessment

No, the bare --system flag sketch is only a plausible direction. The maintainable solution is a shared launchd scope model covering privilege, execution user, coexistence, lifecycle, status, doctor, docs, and tests.
