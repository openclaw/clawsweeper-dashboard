## Summary

Keep open. Current main and the latest release still install and manage macOS Gateway as a user LaunchAgent, while system LaunchDaemon handling remains only diagnostic and needs a product/security decision.

## What This Changes

Request macOS Gateway support for installing and status-checking a system LaunchDaemon so the Gateway can start before user login.

## Best Possible Solution

Define one explicit macOS launchd user/system scope model across install, status, stop, uninstall, doctor, docs, and tests, with user LaunchAgent as the safe default and any LaunchDaemon path explicit and security-reviewed.

## Reproduction Assessment

Yes, at source level. Current main still resolves managed macOS Gateway install/status through the LaunchAgent registry, a user LaunchAgents plist path, and gui/<uid> launchctl calls; I did not run a live boot-without-login macOS scenario.

## Solution Assessment

No, the bare --system flag sketch is only a plausible direction. The best fix is a shared launchd scope contract covering privilege, execution user, coexistence, lifecycle, status, doctor, docs, and regression proof.
