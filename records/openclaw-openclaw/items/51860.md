## Summary

Keep open. Current main and the latest release still expose macOS gateway install/status as a user LaunchAgent path; durable TMPDIR handling has improved, but the requested boot-without-login LaunchDaemon install/status mode remains unresolved and security-sensitive.

## What This Changes

Request to add macOS system LaunchDaemon install/status support so the gateway can start before user login.

## Best Possible Solution

Define one explicit macOS launchd user/system scope contract across install, status, doctor, stop, uninstall, docs, and tests, keeping the user LaunchAgent as the safe default and adding an audited LaunchDaemon path only through clear privileged-operator UX.

## Reproduction Assessment

Yes, at source level. Current main still registers no system install flag and resolves Darwin gateway install/status through the LaunchAgent registry, user LaunchAgents plist path, and `gui/<uid>` launchctl calls; I did not run a live macOS reboot scenario in this read-only review.

## Solution Assessment

No, not as a one-off `--system` flag alone. The maintainable solution is a shared launchd scope model covering privilege, execution user, coexistence, install/status/lifecycle behavior, doctor repair, docs, and regression tests.
