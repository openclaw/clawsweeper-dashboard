## Summary

Keep open. Current main and the latest release still manage macOS gateway install/status as a user LaunchAgent; `status --deep` can discover system services, but the requested boot-without-login LaunchDaemon install/status contract remains unresolved and security-sensitive.

## What This Changes

The issue requests macOS gateway LaunchDaemon install/status support so the gateway can start before user login and report system-domain launchd state correctly.

## Best Possible Solution

Define one explicit macOS launchd user/system scope contract across install, status, doctor, stop, uninstall, docs, and tests, keeping user LaunchAgent as the safe default and adding only an audited explicit LaunchDaemon path or guidance flow.
