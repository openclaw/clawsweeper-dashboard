## Summary

Keep open. Current main and the latest release still manage the macOS gateway as a user LaunchAgent, while system LaunchDaemon discovery is diagnostic and the full boot-without-login install/status contract remains a security-sensitive product decision.

## What This Changes

Issue requests macOS gateway LaunchDaemon install/status support so the gateway can start before user login and report system-domain launchd state accurately.

## Best Possible Solution

Define one explicit macOS launchd user/system scope contract across install, status, doctor, stop, uninstall, docs, and tests, keeping user LaunchAgent as the safe default and adding LaunchDaemon support only through clear privileged-operator UX.

## Reproduction Assessment

Yes, at source level. Current main still registers no system install flag and resolves Darwin install/status through the user LaunchAgents path plus `gui/<uid>` launchctl calls; I did not run a live macOS reboot scenario in this read-only review.

## Solution Assessment

No, not as a one-off `--system` flag alone. The maintainable fix is a shared launchd scope model that covers privilege, execution user, coexistence, install/status/lifecycle behavior, doctor repair, docs, and regression tests.
