## Summary

This PR remains necessary because current main still has the reported unbounded teardown path, but the current head does not invoke its new timeout helper and its force-release primitive does not revoke already-running retained writes. The branch therefore does not yet fix the outage safely, and the screenshots demonstrate only the before-fix failure.

## What This Changes

The PR adds a 30-second retained-session-lock release helper, a controller force-dispose operation, and focused unit tests for those additions.

## Best Possible Solution

Use one controller-owned bounded-release operation that marks the current attempt as having lost ownership before releasing the file lock, invoke it from the actual teardown or abort path, and verify both prompt recovery and rejection of late retained writes in a real gateway session.
