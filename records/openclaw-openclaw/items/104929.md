## Summary

The submitted head is knowingly incomplete: it only kills the executor’s POSIX process group, while the PR’s own macOS evidence shows `setsid` and double-fork descendants survive. The newer ACPX candidate moves cleanup to the correct plugin/runtime ownership boundary and adds meaningful lease, PID-reuse, TERM/KILL, and persistent-session coverage, but it is not the PR head and still needs explicit maintainer approval for fail-closed startup/cancel behavior plus exact-head real service proof.

## What This Changes

This PR adds executor/background process roles, gives CLI executors isolated POSIX process groups, and routes abort cancellation through that group while preserving generic background process lifetimes.

## Best Possible Solution

Replace the obsolete process-group patch with the ACPX-owned lease-drain design: close the cached runtime handle first, identify survivors with an unforgeable per-turn lease plus gateway epoch, revalidate ownership before signaling, escalate TERM to KILL, fail visibly if verified survivors remain, and leave generic persistent `exec/process` sessions unchanged.
