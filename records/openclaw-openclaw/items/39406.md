## Summary

Keep open: current main has an all-off `messages.suppressToolErrors` escape hatch and some channel-side suppression for non-terminal warnings, but it does not implement the requested success-aware normal-chat `all | final | off` delivery policy; choosing that policy needs maintainer product and safety direction.

## What This Changes

The issue requests a configurable policy for suppressing transient tool-error warning bubbles after an agent has recovered and produced a useful final reply.

## Best Possible Solution

Keep default-visible safety behavior, retain `messages.suppressToolErrors` as the explicit all-off operator escape hatch, and add any final-outcome-gated mode only as a maintainer-approved opt-in with schema, docs, upgrade notes, and runtime/channel tests.
