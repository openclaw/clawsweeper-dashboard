## Summary

Keep open: current main and the latest release support the existing boolean `messages.suppressToolErrors` opt-out, but they still do not implement the requested normal-chat `all | final | off` delivery policy for recovered or transient tool failures.

## What This Changes

Request a normal-chat config policy to suppress, defer, or disable automatic tool-error warnings after transient or recovered tool failures.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep current safety behavior as the default, and add `final` or `off` only with aligned schema, docs, payload/progress handling, and representative channel regression coverage.
