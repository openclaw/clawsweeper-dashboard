## Summary

Keep open: current main and v2026.6.11 still preserve success-looking final replies followed by visible mutating-tool warnings unless operators use the existing all-off `messages.suppressToolErrors` boolean, so the requested final-only delivery policy remains a product/config decision.

## What This Changes

The issue requests a normal-chat config policy to suppress or delay transient tool-error warnings when the agent later recovers or returns a useful final answer.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep the current safety-preserving behavior as the default, and add any `final` or `off` mode only with schema/help/docs plus payload, progress, and channel regression coverage.
