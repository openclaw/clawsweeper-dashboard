## Summary

Keep open: current main and v2026.6.11 still expose only the all-off `messages.suppressToolErrors` boolean plus safety-preserving warning behavior, not the requested normal-chat `all | final | off` delivery policy for recovered tool errors.

## What This Changes

The issue requests a config option to suppress or defer transient tool-error warnings on user-facing chat surfaces when the agent later succeeds.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep current safety behavior as the default, and add `final` or `off` only with schema, docs, payload/progress, and representative channel regression coverage.
