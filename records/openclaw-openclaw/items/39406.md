## Summary

Keep open: current main has targeted warning-leak fixes and the all-off `messages.suppressToolErrors` boolean, but it still lacks the requested normal-chat `all | final | off` delivery policy, so the remaining work is a maintainer product/config decision.

## What This Changes

The issue requests configurable normal-chat suppression or delaying of transient tool-error warnings after a successful final reply.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep visible warnings as the default, and add final/off semantics only with schema, docs, payload, progress, and representative channel regression coverage.
