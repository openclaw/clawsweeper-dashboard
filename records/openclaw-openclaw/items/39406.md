## Summary

Keep open: current main and the latest release still provide only full `messages.suppressToolErrors` suppression and intentionally preserve mutating-tool warnings after success-looking replies, so the requested final-only normal-chat policy remains unresolved.

## What This Changes

Request a normal-chat config policy to suppress or delay transient tool-error warnings when the agent recovers and sends a useful final reply.

## Best Possible Solution

Define one default-compatible tool-error delivery contract: keep safety-preserving `all` behavior by default, document the existing all-off boolean or replace it deliberately, and add any `final` mode only with schema, docs, payload, progress, and channel coverage.
