## Label Justifications

- `P2`: The issue affects user-visible channel warning delivery for hosted/team deployments, but it is bounded to message-delivery policy rather than core availability.
- `impact:message-loss`: The issue is about whether automatic tool-error warning messages are delivered, suppressed, or delayed on user chat surfaces.
- `impact:ux-friction`: The reported behavior confuses non-technical hosted or group-chat users after otherwise successful agent turns without fully blocking progress.

## Summary

Keep open: current main has useful partial suppression through `messages.suppressToolErrors`, but it still preserves success-looking final replies followed by visible mutating-tool warning payloads and does not implement the requested shared `all | final | off` normal-chat policy.

## What This Changes

The issue requests a configurable normal-chat policy to suppress or delay transient tool error warnings when the agent recovers or succeeds.

## Best Possible Solution

Maintainers should choose one default-compatible warning-delivery contract, then align config schema/help, runner payload policy, progress delivery, docs, and channel regression tests around that contract.

## Reproduction Assessment

Yes, at source level: current main still has a regression test where `Done.` is followed by a visible failed-write warning, and source search shows no final-only delivery enum.

## Solution Assessment

Unclear; `all | final | off` is plausible, but the best solution depends on a maintainer safety decision because current behavior intentionally keeps unacknowledged failed mutations visible.
