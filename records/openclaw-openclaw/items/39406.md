## Summary

Keep open: current main and the latest release support the existing all-off `messages.suppressToolErrors` boolean, but the requested success-aware normal-chat `all | final | off` delivery policy is still a product/config decision and is explicitly not covered by the narrower fixes already merged.

## What This Changes

The issue requests a public config policy for normal chat tool-error warning delivery, such as `all | final | off`, so recovered or transient tool failures do not confuse hosted or group-chat users.

## Best Possible Solution

Keep the existing `messages.suppressToolErrors` all-off escape hatch, and have a maintainer decide whether OpenClaw should add a narrower success-aware delivery mode with tests for mutating, exec-like, progress, cron, heartbeat, and channel delivery paths.
