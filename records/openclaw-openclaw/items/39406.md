## Summary

Keep open: current main and v2026.6.11 have the all-off `messages.suppressToolErrors` boolean and narrower acknowledged-failure handling, but they still preserve visible success-looking mutating tool warnings by default and do not implement the requested `all | final | off` normal-chat delivery policy.

## What This Changes

Request a normal-chat configuration policy to suppress or defer transient tool-error warnings, especially when the agent later succeeds.

## Best Possible Solution

Define one default-compatible tool-error delivery policy for normal chat, preserving current visibility by default while allowing explicitly configured hosted deployments to suppress or defer recovered transient warnings with tests for true failures and recovered successes.

Rationale: Source inspection proves the capability gap, but choosing the default, final-only semantics, and side-effect safety boundary changes public config and user-visible failure behavior.

Owner confidence: high

Options:

- **Approve default-compatible policy (recommended):** Add an opt-in delivery enum that keeps current `all` behavior by default and defines conservative `final` and `off` semantics with schema, docs, and regression coverage.
- **Keep boolean suppression only:** Treat `messages.suppressToolErrors` as the supported operator escape hatch and handle confusing warnings through docs or narrower issue-specific fixes.
- **Defer to recovery/status design:** Leave this open until the warning reason, retry-confirmation, and internal-warning routing issues converge on a shared status model.
