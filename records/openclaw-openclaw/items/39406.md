## Summary

Keep open: current main and latest release still do not provide the requested final-only normal-chat delivery policy; they only provide a full `messages.suppressToolErrors` opt-out plus safety-preserving warnings for success-looking mutating or exec failures.

## What This Changes

Request adding or extending configuration so normal chat surfaces can suppress or delay transient tool-error warning bubbles after successful or useful final replies.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep safety-preserving visibility as the default, and add any `final` or `off` mode only with aligned schema, docs, payload, progress, and representative channel coverage.
