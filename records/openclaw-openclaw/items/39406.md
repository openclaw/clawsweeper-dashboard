## Summary

Keep open: current main still has only the boolean `messages.suppressToolErrors` opt-out plus safety-preserving visible warnings for success-looking mutating-tool failures, so the requested normal-chat `all | final | off` delivery policy remains a product decision.

## What This Changes

Request a normal-chat tool-error delivery policy or global suppression option so recovered transient tool failures do not appear as confusing user-facing channel warnings after successful turns.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep current safety behavior as the default, and add `final` or `off` only with schema, docs, payload/progress, and representative channel regression coverage.
