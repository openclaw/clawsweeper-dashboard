## Summary

Keep open: current main and v2026.6.11 provide a full `messages.suppressToolErrors` escape hatch, but they still intentionally show mutating-tool warnings after success-looking assistant replies, so the requested final-only/internal-only delivery policy remains unresolved and needs maintainer product direction.

## What This Changes

The issue requests a normal-chat configuration option to suppress or defer transient tool-error warning bubbles after the agent recovers successfully.

## Best Possible Solution

Define one maintainer-approved, default-compatible tool-error delivery policy, then align config schema/help/docs and focused payload/progress tests around that contract.

## Maintainer Decision

Question: Should normal chat support a final-only or internal-only tool-error delivery mode beyond the existing `messages.suppressToolErrors` full suppression flag?

Rationale: Current code intentionally preserves visible warnings for success-looking mutating failures, while the issue asks to suppress that class for hosted and group-chat UX; code inspection cannot choose the safety versus cleanliness policy safely.

Likely owner: vincentkoc

Owner reason: The related warning-leak fix and discussion make vincentkoc the strongest available routing candidate for the remaining product-policy choice.

Owner confidence: medium

Options:

- **Add final-only policy (recommended):** Introduce a typed message delivery policy that suppresses post-success transient warnings while still surfacing unresolved or explicitly failed final turns.
- **Document full suppression only:** Treat `messages.suppressToolErrors` as the supported operator contract and state that final-only suppression is not currently planned.
- **Keep current safety default:** Leave success-looking mutating failures visible by default and require operators to opt into any broader suppression mode explicitly.

## Reproduction Assessment

Yes, at source level. Current tests explicitly expect a visible warning after success-looking mutating tool failures, while the requested final-only mode would suppress that case.

## Solution Assessment

Unclear until maintainers choose the product contract. The existing full suppression knob solves the `off` case, but the requested final-only policy changes safety semantics for success-looking failed mutations.
