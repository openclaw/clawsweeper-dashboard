## Summary

Keep open: current main has an all-off `messages.suppressToolErrors` escape hatch and some post-final/verbose suppression, but it still deliberately shows mutating-tool warnings when the assistant merely looks successful; the requested `all | final | off` normal-chat policy remains a maintainer product decision.

## What This Changes

Requested a normal-chat configuration policy to suppress, defer, or disable transient tool-error warning bubbles after the agent recovers successfully.

## Best Possible Solution

Define a maintainer-approved opt-in delivery policy that keeps the current fail-visible default, preserves errors in agent context/logs, and adds focused regression coverage across embedded payload building and channel dispatch before exposing it as public config.
