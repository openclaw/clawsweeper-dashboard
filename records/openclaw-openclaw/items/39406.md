## Summary

Keep open: current main has the existing all-off `messages.suppressToolErrors` escape hatch and narrower progress/channel fixes, but the requested success-aware normal-chat `all | final | off` delivery policy is still absent and remains a product/config decision.

## What This Changes

Request a normal-chat configuration policy to suppress transient tool-error warning bubbles after successful agent recovery, either as `toolErrorDelivery: all | final | off` or by extending `suppressToolErrorWarnings` beyond heartbeat runs.

## Best Possible Solution

Keep the current default-visible safety behavior and all-off boolean, then add a maintainer-approved opt-in delivery policy only if schema, docs, upgrade notes, and tests cover mutating, non-mutating, progress, heartbeat, cron, Telegram, and Discord paths.
