## Summary

Keep open: current main and v2026.6.11 still only provide the all-off `messages.suppressToolErrors` boolean, while default behavior still shows failed mutating-tool warnings after success-looking replies, so the requested final-only policy remains a product/config decision.

## What This Changes

Request a normal-chat config policy such as `all | final | off` to suppress transient tool-error warning bubbles after successful or useful final replies.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep current visible warnings as the default, and add final/off semantics only with schema, docs, payload, progress, and representative channel regression coverage.
