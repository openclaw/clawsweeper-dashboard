- `impact:ux-friction`: Hosted and team-chat operators report post-success warning bubbles that confuse non-technical users and create avoidable support burden.

## Summary

Keep open: current main now supports an all-off operator path through `messages.suppressToolErrors`, but it still intentionally shows mutating or exec-like tool warnings after success-looking replies, so the requested final-only delivery policy remains unresolved and needs product direction.

## What This Changes

Requests normal-chat configuration to suppress, delay, or disable transient tool-error warning bubbles after recovered or successful agent turns.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract: keep safety-preserving visible warnings as the default, keep or deliberately migrate the existing all-off boolean, and add any final-only mode only with schema, docs, payload, progress, and channel coverage for failed mutations.
