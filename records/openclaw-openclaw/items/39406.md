## Summary

Keep open: current main and the latest release still provide only the boolean `messages.suppressToolErrors` opt-out plus safety-preserving mutating-tool warnings, not the requested normal-chat `all | final | off` delivery policy.

## What This Changes

Request a user-facing configuration policy that can suppress or delay transient tool-error warning bubbles after an agent recovers and returns a useful final reply.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep current safety behavior as the default, and add `final` or `off` only with schema, docs, payload/progress, and representative channel regression coverage.
