## Summary

Keep open: current main and the latest release still lack the requested final-only normal-chat tool-error delivery policy; the existing implementation provides an all-off `messages.suppressToolErrors` boolean plus safety-preserving warnings for success-looking failed mutations, so the remaining work is a maintainer product/config decision.

## What This Changes

Request a config-controlled normal-chat policy for tool-error warning delivery so hosted and team-chat deployments can hide or defer recovered transient tool failure bubbles.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep current visible warnings as the default, and add final/off semantics only with schema, docs, payload, progress, and representative channel regression coverage.
