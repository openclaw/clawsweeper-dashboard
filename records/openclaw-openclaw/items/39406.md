## Summary

Keep open: current main and the latest release still keep success-looking mutating tool failures visible unless the broad all-off `messages.suppressToolErrors` knob is set or the assistant explicitly acknowledges the failed action. A merged narrow fix explicitly left this issue open for the broader normal-chat delivery policy/config decision.

## What This Changes

The issue requests a configurable normal-chat policy for suppressing transient tool error warnings after a successful or useful final assistant response.

## Best Possible Solution

Add a maintainer-approved, documented warning-delivery policy that defaults to current safety behavior while giving hosted chat operators an explicit normal-chat suppression mode with tests for mutating safety fallbacks.
