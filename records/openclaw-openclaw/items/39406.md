## Summary

Keep open: current main and v2026.6.11 support the existing boolean all-off `messages.suppressToolErrors` path, but they still do not implement the requested normal-chat `all | final | off` delivery policy for recovered or transient tool failures.

## What This Changes

Request a config surface that can suppress or defer transient tool-error warning bubbles on normal chat surfaces after recovered or successful turns.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep current safety behavior as the default, and add `final` or `off` only with aligned schema, docs, payload/progress handling, and representative channel regression coverage.
