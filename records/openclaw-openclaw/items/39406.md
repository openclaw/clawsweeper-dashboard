## Summary

Keep open: current main and the latest release still have only the all-off `messages.suppressToolErrors` boolean plus warning/progress suppression paths, not the requested success-aware `all | final | off` normal-chat delivery policy; choosing that policy is a product and safety decision.

## What This Changes

The issue requests a user-facing config policy that can suppress transient tool-error warning bubbles after a successful final agent reply.

## Best Possible Solution

Define a default-compatible normal-chat warning-delivery contract that keeps current safety behavior by default and adds any final-only/off behavior as an explicit, documented operator opt-in with schema and runtime/channel coverage.
