## Summary

Keep open: current main and the latest release still provide a boolean all-off suppression path, but not the requested success-aware normal-chat `all | final | off` delivery policy. The remaining work is a product/config decision because the default warning protects users from silent failed mutations.

## What This Changes

The issue requests a config option that can suppress or defer transient tool-error warnings when the agent later produces a successful final reply.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep visible warnings as the default, and add any `final` or `off` behavior only after maintainers choose the failed-mutation safety rules and align schema, docs, payload, progress, and channel coverage.

Options:

- **Add explicit opt-in delivery policy (recommended):** Define a default-compatible enum such as `all | final | off` that preserves current warnings by default while allowing hosted or group-chat operators to opt into final-only or off behavior with focused tests.
- **Keep boolean-only policy:** Treat `messages.suppressToolErrors` as the supported all-off escape hatch and document that OpenClaw will not add a success-aware enum for now.
- **Move policy to channels:** Let team-chat plugins own warning visibility where channel UX differs, avoiding another global message config key.
