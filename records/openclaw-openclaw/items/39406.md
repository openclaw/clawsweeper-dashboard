## Summary

Keep open: current main and v2026.6.11 still provide only the all-off `messages.suppressToolErrors` boolean, while default behavior still shows success-looking replies followed by failed mutating-tool warnings; the requested final-only policy remains a product/config decision.

## What This Changes

Request a normal-chat configuration policy to suppress or delay transient tool-error warnings when an agent ultimately recovers and succeeds.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep current visible warnings as the default, and add final/off semantics only with schema, docs, payload, progress, and representative channel regression coverage.
