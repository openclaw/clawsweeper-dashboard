## Summary

Keep open: current main and the latest release still support only full opt-out via `messages.suppressToolErrors`, while success-looking mutating-tool failures are intentionally still shown by default; the requested final-only or off delivery policy remains a product/config decision.

## What This Changes

Request a normal-chat configuration policy to suppress or delay transient tool-error warning bubbles after successful or useful final replies.

## Best Possible Solution

Define one default-compatible tool-error delivery contract, keep `all` as the default, and align schema, docs, payload/progress delivery, and representative channel tests around maintainer-approved `final` or `off` semantics.
