## Summary

Keep open: current main and the latest release have an all-off `messages.suppressToolErrors` boolean plus safety fallback warnings for success-looking mutating-tool failures, but not the requested normal-chat `all | final | off` delivery policy.

## What This Changes

Request a normal-chat configuration policy to suppress transient tool-error warning bubbles after the agent recovers and provides useful final output.

## Best Possible Solution

Define one default-compatible warning-delivery contract that preserves current visibility by default, keeps or consolidates the existing all-off suppression knob, and adds a final-only mode only with maintainer-approved safety semantics and regression coverage across payload, progress, and channel delivery.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a normal-chat tool-error delivery policy such as `all | final | off`, or should the supported operator contract remain the existing boolean `messages.suppressToolErrors` plus targeted safety fallbacks?

Rationale: The source-proven gap is real, but the remaining fix changes public config and decides when user-visible failed mutations may be hidden after a success-looking final answer; code inspection cannot safely choose that product/safety contract.

Likely owner: vincentkoc

Owner reason: They authored the merged narrow warning-policy fixes and explicitly kept this issue as the broader follow-up.

Owner confidence: high

Options:

- **Approve default-compatible policy (recommended):** Add a documented opt-in policy that keeps current `all` behavior by default, treats the existing boolean as the `off`/internal-only path, and adds `final` only with strict acknowledgement/success tests.
- **Constrain to existing boolean:** Do not add `final`; document `messages.suppressToolErrors` as the supported hosted/team-chat suppression knob and keep safety warnings visible by default.
- **Fold into warning router design:** Defer this specific knob and design it together with https://github.com/openclaw/openclaw/issues/45565 so tool, lifecycle, and system notices share one category/destination policy.

## Reproduction Assessment

Yes, at source level. Current tests still expect success-looking mutating-tool failures to emit a warning, while config/schema exposes only `messages.suppressToolErrors` and heartbeat-scoped `suppressToolErrorWarnings`; I did not run a live chat replay.

## Solution Assessment

Unclear. A three-mode delivery policy is plausible, but the safest maintainable solution depends on maintainer-approved semantics for hiding failed mutations after final output and how that relates to the existing boolean suppression knob.
