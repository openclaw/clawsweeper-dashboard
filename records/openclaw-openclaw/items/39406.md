## Summary

Keep open: current main and v2026.6.11 still preserve visible mutating-tool warnings after success-looking replies unless the operator opts into full `messages.suppressToolErrors` suppression, so the requested final-only delivery policy remains a maintainer product/config decision.

## What This Changes

Request a normal-chat config policy such as `all | final | off` so hosted chat deployments can suppress transient tool-error warning bubbles after a successful or useful final reply.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, preserve `all` as the safety default, and add any `final` or `off` semantics only with schema, docs, payload/progress, and representative channel coverage.
