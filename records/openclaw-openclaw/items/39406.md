## Summary

Keep open: current main and v2026.6.11 still only provide the all-off `messages.suppressToolErrors` boolean, while success-looking mutating and exec failures still produce visible warnings by default. The remaining `all | final | off` normal-chat policy is a real hosted/team-chat UX request, but it needs maintainer product direction because it adds public config surface and changes when failed side effects are visible.

## What This Changes

The issue requests a normal-chat tool-error delivery policy or global suppression option so transient recovered tool failures do not appear as confusing user-facing warning bubbles after useful final replies.

## Best Possible Solution

Keep default-visible safety behavior, retain the existing all-off escape hatch, and add any final-outcome-gated mode only as a maintainer-approved opt-in with schema, docs, upgrade notes, and channel/runtime tests.
