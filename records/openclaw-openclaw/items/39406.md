## Summary

Keep open: current main and v2026.6.11 still have only an all-off `messages.suppressToolErrors` boolean plus acknowledgement-based warning suppression, while success-looking final replies can still be followed by visible mutating-tool warnings. The remaining `all | final | off` policy is a real hosted/team-chat UX request, but it changes failed-mutation safety semantics and needs maintainer product direction before a fix PR.

## What This Changes

Request a normal-chat configuration policy for tool-error warnings so hosted and team-chat deployments can hide or delay transient warning bubbles after successful agent replies.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep the current safety-preserving behavior as the default, and add any `final` or `off` mode only with maintainer-approved failed-mutation semantics plus schema, docs, payload, progress, and channel regression coverage.
