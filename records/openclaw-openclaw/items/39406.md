## Summary

Keep open: current main partially addresses the noisy-warning class with `messages.suppressToolErrors`, but it still has no success-aware normal-chat `all | final | off` policy, and current tests preserve visible warnings when a mutating tool fails but the assistant sounds successful. Adding that policy is a product/config-surface decision, not a conservative cleanup close.

## What This Changes

Request a normal-chat configuration policy to suppress transient tool-error warnings after successful final replies, while preserving tool errors in agent context and logs.

## Best Possible Solution

Keep default-visible safety behavior, retain `messages.suppressToolErrors` as the explicit all-off escape hatch, and add any final-outcome-gated mode only as a maintainer-approved opt-in with schema, docs, upgrade notes, and focused runtime/channel tests.
