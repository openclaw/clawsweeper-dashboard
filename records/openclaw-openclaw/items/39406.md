## Summary

Keep open: current main and v2026.6.11 have an all-off `messages.suppressToolErrors` opt-out, but default behavior still intentionally shows failed mutating-tool warnings after success-looking replies, so final-only delivery remains an unresolved config/product decision.

## What This Changes

Request a normal-chat config policy to suppress or defer transient tool-error warning bubbles after an agent recovers, potentially replacing or extending `messages.suppressToolErrors`.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, preferably by evolving the existing boolean into a documented small policy with schema, docs, payload/progress handling, and representative channel tests.
