## Summary

Keep open: current main has the existing boolean `messages.suppressToolErrors` opt-out and related narrow suppressions, but it still does not implement the requested normal-chat `all | final | off` policy for recovered or transient tool failures.

## What This Changes

The issue requests a public config option to control when transient tool-error warnings are delivered to user-facing chat surfaces.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep current safety behavior as the default, and add final/off modes only with aligned schema, docs, payload/progress handling, and representative channel regression coverage.
