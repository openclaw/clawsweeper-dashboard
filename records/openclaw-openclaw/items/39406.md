## Summary

Keep open: current main and the latest release have the boolean all-off `messages.suppressToolErrors` opt-in, but they still do not implement the requested normal-chat `all | final | off` delivery policy for recovered or transient tool-error warnings.

## What This Changes

Requested a normal-chat configuration policy to suppress transient tool-error warning bubbles after agent recovery while preserving internal tool context and logs.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep current safety behavior as the default, and add `final` or `off` only with schema, docs, payload/progress, and representative channel regression coverage.
