## Summary

Keep open: current main still lacks the requested normal-chat `all | final | off` delivery policy; it has an all-off `messages.suppressToolErrors` boolean plus targeted safety fixes that deliberately keep failed mutating-tool warnings visible after success-looking replies.

## What This Changes

Request a config policy to suppress, defer, or disable transient tool-error warning bubbles for hosted/team chat deployments after the agent recovers or gives a useful final reply.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, keep visible warnings as the default, and add final/off semantics only with schema, docs, payload, progress, and representative channel regression coverage.
