- `impact:ux-friction`: Hosted/team-chat operators report confusing post-success warning bubbles that create avoidable user confusion and support burden.

## Summary

Keep open: current main and the latest release still do not implement the requested shared normal-chat `all | final | off` tool-error delivery policy. Current main has useful suppression pieces, including `messages.suppressToolErrors` and a main-only progress-payload gate, but success-looking replies are still intentionally followed by visible mutating-tool warnings unless an operator opts into full suppression.

## What This Changes

Request a normal-chat config policy to suppress, delay, or disable transient tool-error warning bubbles after recovered agent tool failures.

## Best Possible Solution

Define one default-compatible normal-chat tool-error delivery contract, then align config schema/help/docs, embedded-runner payload policy, progress delivery, and representative channel tests around that contract.

## Reproduction Assessment

Yes, at source level: current main still has a test where `Done.` is followed by a visible failed-write warning, and the config surface has no final-only delivery enum. I did not run a live Telegram or Discord replay in this read-only cleanup pass.

## Solution Assessment

Unclear. The requested `all | final | off` shape is plausible, but the best implementation depends on a maintainer safety decision because failed mutations currently remain visible to avoid silent false success.
