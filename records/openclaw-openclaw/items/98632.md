## Summary

Keep open: the requested loopback-range fix is valid, but this patch still prefix-matches hostnames and lacks real behavior proof, so it is not merge-ready.

## What This Changes

The PR changes the model list/status local URL classifier to treat any hostname beginning with `127.` as local instead of only `127.0.0.1`.

## Best Possible Solution

Use a parsed loopback-IP helper for canonical 127/8 IP literals, keep explicit wildcard and mDNS exceptions, add focused tests for `127.0.0.2` and a `127.*` hostname, and provide redacted real command proof.

## Maintainer Decision

## Reproduction Assessment

Yes by source inspection: current main only matches exact `127.0.0.1` in `list.local-url.ts`, so `http://127.0.0.2:11434` is not local. A Node URL check also shows `http://127.example.com` remains a hostname the PR would prefix-match.

## Solution Assessment

No. The direction is right, but prefix matching is not the best fix; `isLoopbackIpAddress` or equivalent IP parsing avoids classifying DNS hostnames like `127.example.com` as local.
