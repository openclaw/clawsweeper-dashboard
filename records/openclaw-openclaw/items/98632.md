## Summary

## What This Changes

The branch changes the model local URL classifier to recognize any hostname beginning with `127.` as local instead of only exact `127.0.0.1`.

## Best Possible Solution

Use canonical IP loopback parsing for `127.0.0.0/8`, keep existing wildcard and mDNS exceptions explicit, then add regression tests and contributor-owned real command proof before merge.

## Reproduction Assessment

Yes by source inspection and a URL parser probe: current main only matches exact `127.0.0.1`, while `new URL('http://127.0.0.2:11434').hostname` is `127.0.0.2`. I did not run a full CLI scenario in this read-only review.

## Solution Assessment

No. The requested loopback widening is correct, but the PR's string-prefix implementation is not the safest fix; it should reuse parsed loopback detection and add coverage for both the accepted IP case and rejected hostname case.
