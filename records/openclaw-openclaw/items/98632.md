## Summary

Keep this PR open, but it is not merge-ready: the reported current-main bug is real by source inspection, while the proposed prefix match would also classify non-IP hostnames like `127.example.com` as local.

## What This Changes

The PR changes the model status/list local URL classifier to treat hostnames beginning with `127.` as local instead of only exact `127.0.0.1`.

## Best Possible Solution

Use the existing net-policy loopback parser for `127.0.0.0/8` and keep the wildcard and mDNS display exceptions explicit in the model-list classifier.

## Reproduction Assessment

Yes by source inspection: current main returns false for `http://127.0.0.2:11434` because it only matches exact `127.0.0.1`. I did not execute tests or commands because this review is read-only.

## Solution Assessment

No. The direction is right, but the safest fix is canonical IP loopback parsing plus explicit existing wildcard and mDNS exceptions, not a hostname prefix check.
