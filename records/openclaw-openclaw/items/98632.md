## Summary

Keep this PR open, but not merge-ready: the requested 127/8 status-command behavior is still missing on current main, while this branch still uses a hostname prefix check that can misclassify non-IP DNS names and still lacks real command-output proof.

## What This Changes

The PR changes the model status/list local URL classifier from exact `127.0.0.1` matching to `host.startsWith("127.")`.

## Best Possible Solution

Use canonical IP-literal loopback parsing for 127/8, keep wildcard and `.local` exceptions explicit, add regression coverage for `127.0.0.2` and a non-IP `127.*` hostname, then provide redacted real command output.

## Reproduction Assessment

Yes. Current main only matches exact `127.0.0.1`, and source plus a Node URL probe show the PR's `127.` prefix check would also match a non-IP hostname such as `127.example.com`.

## Solution Assessment

No. The target behavior is valid, but prefix-matching hostnames is not the best fix; the maintainable shape is to parse IP literals with the existing loopback helper and test both the desired 127/8 case and the false-positive hostname case.
