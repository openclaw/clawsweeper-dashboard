## Summary

Keep open: the underlying 127/8 loopback display bug is still present on current main, but this PR still uses a hostname prefix match that can misclassify non-IP DNS names as local, and the contributor has not provided real command-behavior proof.

## What This Changes

The PR changes the model-list/status local URL classifier from exact `127.0.0.1` matching to any hostname starting with `127.`.

## Best Possible Solution

Use the existing canonical loopback IP parser for `127.0.0.0/8`, keep the wildcard and mDNS display exceptions explicit, and add regression coverage for both `127.0.0.2` and a non-IP `127.*` hostname.

## Reproduction Assessment

Yes. Source inspection shows current main only treats exact `127.0.0.1` as IPv4 loopback in this classifier, and the PR head can be checked by the same path for the `127.*` hostname false positive.

## Solution Assessment

No. Widening to the full 127/8 range is the right direction, but prefix-matching hostnames is not the narrowest maintainable fix when `isLoopbackIpAddress` already provides parsed IP-literal behavior.
