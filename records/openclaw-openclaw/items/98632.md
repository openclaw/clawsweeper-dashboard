## Summary

Keep open: the reported 127.0.0.0/8 display bug is valid by source inspection, but this PR still fixes it with a hostname prefix match that can misclassify non-loopback DNS names and it still lacks real command-output proof.

## What This Changes

The PR changes the model list/status local URL classifier to treat any parsed hostname starting with `127.` as local.

## Best Possible Solution

Use parsed IP-loopback detection via the existing net-policy helper for `127.0.0.0/8`, keep the existing wildcard and mDNS display exceptions explicit, and add focused regression coverage for both `127.0.0.2` and a non-IP `127.*` hostname.

Yes by source inspection: current `main` returns false for `http://127.0.0.2:11434` because the classifier only matches exact `127.0.0.1`. I did not run the command path because this review is read-only.

## Solution Assessment

No. The requested direction is right, but prefix-matching hostnames is not the best fix; parsed loopback IP detection plus explicit existing exceptions is narrower and safer.
