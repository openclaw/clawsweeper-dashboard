## Summary

Keep this PR open: the asynchronous clipboard read can complete after a submission has already consumed attachments, leaving the copied image queued for a later unrelated message. The feature is useful, but it needs safe paste-to-submit association and real terminal proof before merge.

## What This Changes

This PR adds Ctrl+V clipboard-image handling in the TUI and forwards a pending base64 image attachment with the next chat submission.

## Best Possible Solution

Associate each clipboard-image read with the same submit that initiated it—await or explicitly resolve the in-flight paste before sending, discard stale results safely, and prove the corrected behavior with a redacted real TUI run.
