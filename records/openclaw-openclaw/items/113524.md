## What This Changes

Repair isolated `agentTurn` cron jobs whose persisted, operator-unset plugin-only `toolsAllow` list removes core filesystem and shell tools despite an unrestricted global tool policy.

## System Context

Isolated cron jobs persist an agent-turn payload, then start an embedded agent runtime with the job’s tool policy. That policy shapes the tool inventory exposed to the model and therefore whether scheduled work can access host capabilities such as file reads and command execution.

## Architecture Diagram

flowchart LR

  B --> C[Isolated agent run]
  C --> D[Embedded tool construction]
  D --> E[Tool policy filtering]
  E --> F[Model-visible tool inventory]
  F --> G[Scheduled task result]

## Best Possible Solution

Define and preserve provenance for intentional job-local tool restrictions, then provide a narrowly scoped migration or Doctor repair for only demonstrably implicit/stamped plugin-only snapshots; runtime should surface a clear diagnostic instead of silently succeeding with an unexpectedly reduced tool surface.

Question: Should a persisted job-local `toolsAllow` that appears to be a creator-derived default be automatically repaired to inherit the global tool policy, or remain an authoritative per-job restriction unless the operator explicitly clears it?

Rationale: Both choices affect an authorization boundary: automatic repair can broaden existing jobs, while preserving the value leaves affected scheduled work silently unable to use expected core tools. The current report does not establish a safe universal provenance test.

Options:

- **Add provenance-aware repair (recommended):** Recommended: retain explicit job restrictions, but identify and repair only values recorded as implicit/default-derived, with a visible Doctor or cron-editor recovery path.
- **Treat all persisted lists as intentional:** Keep current restrictions authoritative and add diagnostics plus a manual clear action, accepting that previously stamped jobs require operator intervention.
- **Reset all plugin-only lists:** Migrate matching lists to inherited policy, but accept a compatibility and permission-expansion risk for jobs that intentionally used them.

## Solution Assessment
