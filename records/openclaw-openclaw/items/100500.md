## Summary

Keep open: the PR targets a real missing-target delivery bug, but the current patch is not merge-ready because it can pair a `deliveryContext.to` value with a different legacy `channel`, bypassing the existing route-owner guard and risking wrong-channel delivery.

## What This Changes

The PR adds `deliveryContext.to` and `origin.to` fallbacks for `deliveryContextFromSession`, extends the session-source origin type, and adds helper regression tests.

## Best Possible Solution

Preserve channel/target ownership atomically: recover `to` only when the same channel wins, or let the complete `deliveryContext`/`origin` route win as a pair, with a regression that rejects mixed-channel target carryover and real delivery proof for the reported WhatsApp case.
