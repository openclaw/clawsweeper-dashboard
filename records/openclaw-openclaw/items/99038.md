## Summary

Keep this PR open, but the patch is not merge-ready: it adds a one-year cap only to bare-minute input while the same duration with an `m` suffix still follows the existing Gateway cron horizon.

## What This Changes

The PR bounds QQBot plain-number relative reminder inputs to one year and adds parseRelativeTime regression tests.

## Best Possible Solution

Keep bare-minute input validation aligned with the same positive safe-integer and Gateway cron horizon used by equivalent relative-duration syntax, with focused boundary tests.

## Reproduction Assessment

Yes from source inspection: current `parseRelativeTime` accepts bare digits as minutes and `prepareRemindCronAction` sends the duration into cron scheduling. The PR's exact overflow examples are partly incorrect, but the validation gap and proposed behavioral change are source-reproducible.

## Solution Assessment

No; bounding only bare numbers at one year is not the best fix because Gateway cron already validates far-future one-shot jobs and equivalent `525601m` inputs remain accepted. The safer fix is shared validation that rejects non-positive or unsafe math while preserving the scheduler's existing horizon consistently.
