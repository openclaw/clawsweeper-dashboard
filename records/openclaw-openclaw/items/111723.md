## Summary

The reported omission is real in the Claude ACP adapter, but it is not implemented by OpenClaw: the ACPX extension is explicitly a thin wrapper and current main consumes the external adapter package. This issue should move upstream to the adapter project rather than add a duplicate OpenClaw-side patch.

## What This Changes

Pass environment values from Claude Code settings into the Claude Agent SDK environment when an ACP session is created.

## Best Possible Solution

File the narrowly scoped fix with agentclientprotocol/claude-agent-acp: merge resolved settings env after process environment and before explicit ACP caller options, add precedence coverage, then let OpenClaw update its dependency after an upstream release.
