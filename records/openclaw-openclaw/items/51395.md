## Summary

Keep open: current main and v2026.6.11 still expose standard file chooser, direct file-input, and Chrome MCP upload paths only. The ByteUploader-style drop, paste, or native-drag request remains a security-sensitive Browser plugin API/product decision, and the linked FSB implementation supports an explicit drop-file tool rather than a silent upload fallback.

## What This Changes

Request a browser upload path for custom non-file-input uploaders such as ByteUploader using DataTransfer, clipboard paste, or native drag simulation.

## Best Possible Solution

Add an explicit Browser plugin drop-file, paste-file, or native-drag upload mode only after maintainers settle the API and security contract; keep standard file-input upload unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.

## Reproduction Assessment

## Solution Assessment

No for a silent fallback. The maintainable path is an explicit Browser plugin upload mode with approved security semantics, managed-path validation, docs, tests, and live custom-uploader proof.
