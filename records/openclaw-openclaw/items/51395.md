## Summary

Keep open: current main and v2026.6.11 still only support standard file chooser, direct file-input, and Chrome MCP upload paths. The requested ByteUploader-style drop, paste, or native-drag behavior remains a security-sensitive Browser plugin API/product decision rather than a cleanup-close candidate.

## What This Changes

The issue requests browser upload support for custom non-file-input uploaders such as ByteUploader, with proposed drop, paste, or native drag fallback behavior.

## Best Possible Solution

Add an explicit Browser plugin upload mode only after maintainers approve the security/API contract; keep standard file-input upload unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.
