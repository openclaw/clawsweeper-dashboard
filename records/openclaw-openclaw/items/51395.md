## Summary

Keep open: current main still exposes Browser upload as standard file chooser arming, direct file-input setting, or Chrome MCP `upload_file` only. The requested ByteUploader-style drop, paste, or native-drag behavior remains a new Browser plugin capability that needs explicit API and security direction, and the FSB comment usefully supports making that path explicit rather than a silent fallback.

## What This Changes

The issue requests a Browser upload capability for custom uploader widgets that do not expose a standard file input, especially ByteUploader-style drag, paste, or native drag paths.

## Best Possible Solution

Add an explicit Browser plugin drop-file, paste-file, or native-drag upload mode only after maintainers settle the API and security contract; keep standard file-input upload unchanged and require live custom-uploader proof.

## Reproduction Assessment

No high-confidence live reproduction was run. Source inspection shows current upload support is limited to file chooser, direct file input, and Chrome MCP upload paths, which makes the ByteUploader failure plausible but not live-proven.

## Solution Assessment

No for a silent fallback. The maintainable path is an explicit Browser plugin upload mode with approved security semantics, managed-path validation, docs, tests, and live custom-uploader proof.
