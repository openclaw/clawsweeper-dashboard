## Summary

Keep open: current main and the latest release still expose standard file chooser arming, direct file-input setting, and Chrome MCP upload_file only. The linked FSB reference supports an explicit drop_file-style tool rather than a silent upload fallback, so this remains a security-sensitive Browser plugin API/product decision.

## What This Changes

The issue requests a browser upload fallback or explicit file-injection mode for non-standard custom uploaders such as ByteUploader, where CDP file-input upload reports success but leaves no selected files.

## Best Possible Solution

Add an explicit Browser plugin drop-file, paste-file, or native-drag upload mode only after maintainers settle the API and security contract; keep standard file-input upload unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.

## Reproduction Assessment

No high-confidence live current-main reproduction was run. Source inspection confirms current upload support is limited to file chooser, direct file input, and Chrome MCP upload paths, but no ByteUploader page was exercised.

## Solution Assessment

No for a silent fallback. The maintainable path is an explicit Browser plugin upload mode with approved security semantics, managed-path validation, docs, tests, and live custom-uploader proof.
