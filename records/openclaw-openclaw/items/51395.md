## Summary

Keep open: current main and the latest release still implement standard file chooser, direct file-input, and Chrome MCP upload paths only. The requested ByteUploader-style drop, paste, or native-drag upload remains a new security-sensitive Browser plugin capability, with FSB providing a useful explicit drop_file reference rather than proof that OpenClaw core already supports it.

## What This Changes

Request an upload fallback or explicit mode for custom ByteUploader-style components that do not populate standard file inputs through the current browser upload tool.

## Best Possible Solution

Design an explicit Browser plugin file-drop, paste-file, or native-drag upload mode with managed path validation, target selection, docs, tests, and live custom-uploader proof while leaving existing file-input upload unchanged.

## Reproduction Assessment

No live high-confidence ByteUploader reproduction was run. Source inspection does confirm current main lacks the requested drop, paste, or native-drag upload path, so the missing capability is source-reproducible while the exact site behavior is not live-proven.

## Solution Assessment

No for a silent fallback. The maintainable solution is an explicit Browser upload mode with approved security semantics, managed-path validation, documentation, focused tests, and live custom-uploader proof.
