## Summary

Keep open: current main and v2026.6.11 still expose standard file chooser, direct file-input, and Chrome MCP upload_file paths only. The requested ByteUploader-style drop, paste, or native-drag upload behavior remains a security-sensitive Browser plugin feature that needs maintainer API direction and live custom-uploader proof.

## What This Changes

Request an explicit fallback or upload mode for custom browser uploader components that do not use standard file inputs.

## Best Possible Solution

Add an explicit Browser plugin drop-file, paste-file, or native-drag upload mode only after maintainers settle the API and security contract; keep standard file-input upload unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.

No high-confidence live reproduction was run against a ByteUploader page. Source inspection confirms current upload support is limited to file chooser, direct file input, and Chrome MCP upload_file paths, which makes the feature gap reproducible from source but not live-proven.

## Solution Assessment

No for a silent fallback. The maintainable path is an explicit Browser plugin upload mode with approved security semantics, managed-path validation, docs, tests, and live custom-uploader proof.
