## Summary

Keep open: current main and the latest release still expose standard file chooser, direct file-input, and Chrome MCP upload paths only. The requested ByteUploader-style drop, paste, or native-drag capability remains a security-sensitive Browser plugin API/product decision, and the linked FSB discussion supports making that path explicit rather than a silent upload fallback.

## What This Changes

The issue requests a browser upload fallback for custom ByteUploader-style upload surfaces that do not expose a standard file input.

## Best Possible Solution

Add an explicit Browser plugin drop-file, paste-file, or native-drag upload mode only after maintainers settle the API and security contract; keep standard file-input upload unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.
