## Summary

Keep open: current main and v2026.6.11 still only implement standard file chooser, direct file-input, and Chrome MCP file-input upload paths. ByteUploader-style drop, paste, or native-drag upload remains a security-sensitive Browser plugin API/product decision, and the FSB reference supports an explicit drop-file style tool rather than a silent upload fallback.

## What This Changes

Request an upload fallback or explicit mode for custom uploader components such as ByteUploader using DataTransfer drop, clipboard paste, or native drag simulation when standard file inputs do not accept files.

## Best Possible Solution

Add an explicit Browser plugin drop-file, paste-file, or native-drag upload mode only after maintainers settle the API and security contract; keep standard file-input upload unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.

## Reproduction Assessment

No high-confidence live reproduction was run against a ByteUploader page. Source inspection does show current upload support is limited to file chooser, direct file-input, and Chrome MCP upload paths, so the missing custom-uploader mode is source-plausible.

## Solution Assessment

No for a silent fallback. The maintainable solution is an explicit Browser plugin upload mode with approved security semantics, managed-path validation, docs, focused tests, and live custom-uploader proof.
