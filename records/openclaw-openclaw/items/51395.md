## Summary

Keep open: current main and v2026.6.11 still expose standard file-chooser, direct file-input, and Chrome MCP upload paths only. The requested ByteUploader-style drop, paste, or native-drag upload behavior remains a new security-sensitive Browser plugin capability, and LakshmanTurlapati's FSB reference supports making that path explicit instead of a silent fallback.

## What This Changes

Request an explicit Browser upload fallback or mode for ByteUploader-style custom uploaders using DataTransfer/drop, clipboard paste, or native drag when standard file-input upload leaves files.length at 0.

## Best Possible Solution

Add an explicit Browser plugin drop-file, paste-file, or native-drag upload mode only after maintainers settle the API and security contract; keep standard file-input upload unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.

## Reproduction Assessment

No high-confidence live reproduction was run. Source inspection confirms current upload support is limited to file chooser, direct file input, and Chrome MCP upload paths, but no ByteUploader page was exercised.

## Solution Assessment

No for a silent fallback. The maintainable path is an explicit Browser plugin upload mode with approved security semantics, managed-path validation, docs, tests, and live custom-uploader proof.
