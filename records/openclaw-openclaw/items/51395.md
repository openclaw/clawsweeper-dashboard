## Summary

Keep open: current main and the latest release still only support standard file chooser, direct file-input, and Chrome MCP upload paths. The ByteUploader-style drop, paste, or native-drag path remains a Browser plugin API and security-boundary product decision, and the FSB reference comment supports making that mode explicit instead of a silent fallback.

## What This Changes

The issue requests a Browser upload capability for custom ByteUploader-style components that do not use standard file inputs.

## Best Possible Solution

Add an explicit Browser plugin drop-file, paste-file, or native-drag upload mode only after maintainers settle the API and security contract; keep standard file-input upload unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.
