## Summary

Keep open: current main and the latest release still only support standard file chooser arming, direct file-input setting, and Chrome MCP file-input upload. The ByteUploader/drop/paste/native-drag request remains a security-sensitive Browser plugin feature and API decision, with the linked FSB reference supporting an explicit drop-file tool rather than a silent upload fallback.

## What This Changes

Request an additional Browser upload mode for non-standard custom uploaders such as ByteUploader using DataTransfer drop, clipboard paste, or native drag simulation.

## Best Possible Solution

Add an explicit Browser plugin custom-upload mode only after maintainers settle the API and security contract; keep standard file-input upload unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.

## Reproduction Assessment

## Solution Assessment

No for a silent fallback. The maintainable path is an explicit Browser plugin upload mode with approved security semantics, managed-path validation, docs, tests, and live custom-uploader proof.
