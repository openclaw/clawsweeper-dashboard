## Summary

Keep open: current main and v2026.6.11 still expose standard file chooser, direct file-input, and Chrome MCP file-input upload paths only. The requested ByteUploader-style drop, paste, or native-drag behavior remains a security-sensitive Browser plugin API/product decision, and the FSB reference in the discussion supports making this an explicit tool mode rather than a silent upload fallback.

## What This Changes

The issue requests an explicit fallback or alternate Browser upload path for custom ByteUploader-style components that do not use standard file inputs.

## Best Possible Solution

Add an explicit Browser file-drop, paste-file, or native-drag upload mode only after maintainers settle the API and security contract; keep standard file-input upload unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.

## Reproduction Assessment

No high-confidence live current-main reproduction was run. Source inspection confirms current upload support is limited to file chooser, direct file input, and Chrome MCP upload paths, so the reported gap is source-plausible rather than live-proven.

## Solution Assessment

No for a silent fallback. The maintainable path is an explicit Browser plugin upload mode with approved security semantics, managed-path validation, docs, tests, and live custom-uploader proof.
