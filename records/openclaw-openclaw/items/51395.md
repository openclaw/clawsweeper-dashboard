## Summary

Keep open: current main and v2026.6.11 still expose standard file chooser, direct file-input, and Chrome MCP upload paths only. The requested custom-uploader drop, paste, or native-drag behavior remains useful but security-sensitive, and the FSB reference in the discussion supports an explicit upload mode rather than a silent fallback.

## What This Changes

The request is to add Browser upload support for custom uploader components that bypass standard file inputs, such as ByteUploader-style drop, paste, or native-drag flows.

## Best Possible Solution

Add an explicit Browser plugin drop-file, paste-file, or native-drag upload mode only after maintainers approve the security contract; keep standard file-input upload unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.

## Reproduction Assessment

No high-confidence live reproduction was run against ByteUploader or an equivalent custom uploader. Source inspection confirms current upload support is limited to file chooser, direct file input, and Chrome MCP upload paths.

## Solution Assessment

No for a silent upload fallback. The maintainable path is an explicit Browser plugin upload mode with approved security semantics, managed-path validation, docs, tests, and live custom-uploader proof.
