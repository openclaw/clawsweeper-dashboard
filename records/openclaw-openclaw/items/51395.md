## Summary

Keep open: current main and v2026.6.11 still expose standard file chooser, direct file-input, and Chrome MCP upload paths only. The requested ByteUploader-style drop, paste, or native-drag behavior remains a security-sensitive Browser plugin API/product decision, and the linked FSB implementation supports making that path explicit rather than a silent upload fallback.

## What This Changes

The issue requests a Browser upload capability for custom ByteUploader-style controls that do not accept CDP/file-input uploads.

## Best Possible Solution

Add an explicit Browser plugin drop-file, paste-file, or native-drag upload mode only after maintainers settle the API and security contract; keep standard file-input upload unchanged.

## Reproduction Assessment

No high-confidence live reproduction has been run. Source inspection shows only standard file chooser/input paths, but no ByteUploader page was exercised.

## Solution Assessment

No for a silent fallback. The maintainable path is an explicit Browser plugin upload mode with approved security semantics, managed-path validation, docs, focused tests, and live custom-uploader proof.
