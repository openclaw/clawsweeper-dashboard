## Summary

Keep open: current main and the latest release still only support standard file chooser, direct file-input, and Chrome MCP upload paths. The ByteUploader-style drop, paste, or native-drag behavior remains a security-sensitive Browser plugin API/product decision rather than an implemented or duplicate item.

## What This Changes

Request an explicit browser upload fallback or mode for custom uploader components such as ByteUploader using DataTransfer, clipboard paste, or native drag simulation.

## Best Possible Solution

Add an explicit Browser plugin drop-file, paste-file, or native-drag upload mode only after maintainers settle the API and security contract; keep standard file-input upload unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.
