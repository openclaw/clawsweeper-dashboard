## Summary

Keep open: current main and latest release still expose standard file chooser arming, direct file-input setting, and Chrome MCP `upload_file` paths only. The requested ByteUploader-style drop, paste, or native-drag upload behavior remains a new Browser plugin capability that needs explicit API and security direction; the linked FSB comment is useful because it argues for a separate drop-file style tool instead of a silent fallback.

## What This Changes

Request a Browser upload fallback or explicit mode for ByteUploader-style custom file upload components that do not use standard file inputs.

## Best Possible Solution

Add an explicit Browser plugin drop-file, paste-file, or native-drag upload mode only after maintainers settle the API and security contract; keep standard file-input upload unchanged and require managed-path validation, docs, tests, and live custom-uploader proof.

## Reproduction Assessment

No high-confidence live reproduction was run. Source inspection of current main confirms no DataTransfer, clipboard, or native-drag upload mode, but the ByteUploader `files.length` behavior still needs a live or minimal custom-uploader proof.

## Solution Assessment

No for a silent fallback. The maintainable path is an explicit Browser upload mode with approved security semantics, managed-path validation, docs, tests, and live custom-uploader proof.
