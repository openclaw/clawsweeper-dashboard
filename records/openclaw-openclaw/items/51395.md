## Summary

Keep open: current main and the latest release still only support standard file chooser, direct file-input, and Chrome MCP file-input upload paths. The requested ByteUploader-style drop, paste, or native-drag path remains a new Browser plugin capability that needs maintainer API and security direction; LakshmanTurlapati's FSB reference supports making this an explicit tool mode rather than a silent fallback.

## What This Changes

Request an upload path for ByteUploader-style custom uploaders that do not accept standard file input population.

## Best Possible Solution

Add an explicit Browser plugin drop-file, paste-file, or native-drag upload mode only after maintainer-approved security semantics and live custom-uploader proof; keep standard file-input upload unchanged.

## Reproduction Assessment

No high-confidence live reproduction was run. Source inspection shows current upload support is limited to file chooser, file input, and Chrome MCP file-input paths, but no ByteUploader page was exercised.

## Solution Assessment

No for a silent fallback. The maintainable path is an explicit Browser plugin upload mode with approved security semantics, managed-path validation, docs, tests, and live custom-uploader proof.
