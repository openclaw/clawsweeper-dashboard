## Summary

Keep open: current main still exposes standard file chooser, direct file-input, and Chrome MCP upload paths, but no ByteUploader-style DataTransfer, clipboard, or native-drag upload mode. The FSB reference in the discussion usefully points toward an explicit drop-file tool shape, which fits the security-sensitive nature of this request better than a silent fallback.

## What This Changes

Request an explicit Browser upload capability for custom non-file-input uploaders such as ByteUploader, using DataTransfer drop, clipboard paste, or native drag simulation.

## Best Possible Solution

Add an explicit Browser plugin drop-file, paste-file, or native-drag upload mode only after maintainers settle the API and security contract; keep standard file-input upload unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.
