## Summary

Keep open: current main and v2026.6.11 still support standard file chooser arming, direct file-input setting, and Chrome MCP `upload_file`, but not a ByteUploader-style DataTransfer, clipboard, or native-drag upload mode. The FSB reference in the discussion is useful support for an explicit drop-file API shape, but this remains a Browser security/product decision rather than a cleanup close.

## What This Changes

The issue requests a browser upload capability for custom uploader widgets that do not use standard file inputs, such as ByteUploader-style drag, paste, or drop paths.

## Best Possible Solution

Add a named Browser plugin file-injection mode only if maintainers approve the security contract; keep existing upload behavior unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.
