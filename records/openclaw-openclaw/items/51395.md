## Summary

Keep open: current main and the latest release still support standard file chooser arming, direct file-input setting, and Chrome MCP upload_file, but not a ByteUploader-style DataTransfer, clipboard, or native-drag upload mode. The FSB reference in the discussion is useful evidence for an explicit drop-file API shape, but this remains a security/product decision rather than an automatic fallback fix.

## What This Changes

Request browser upload support for custom ByteUploader-style uploaders via a DataTransfer drop, clipboard paste, or native drag simulation path.

## Best Possible Solution

Add a named Browser plugin file-injection mode only if maintainers approve the security contract; keep existing upload behavior unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.
