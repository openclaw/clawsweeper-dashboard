## Summary

Keep open: current main and v2026.6.11 still expose standard file chooser, direct file-input, and Chrome MCP upload_file paths only. The ByteUploader-style drop, paste, or native-drag request remains a security-sensitive Browser plugin API/product decision, and the linked FSB implementation is useful evidence for making this an explicit drop-file style tool rather than a silent upload fallback.

## What This Changes

Request adding a browser upload fallback or explicit mode for custom uploaders such as ByteUploader using drop, paste, or native drag simulation.

## Best Possible Solution

Add an explicit Browser plugin drop-file, paste-file, or native-drag upload mode only after maintainers settle the API and security contract; keep standard file-input upload unchanged and require managed-path validation, docs, focused tests, and live custom-uploader proof.
