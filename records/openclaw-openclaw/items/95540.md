## Summary

Keep open for maintainer merge review: the patch is a narrow, source-backed fix for a released upgrade/config corruption path, with no blocking code findings; the remaining decision is accepting the intentional fail-closed behavior for schemaless external channel migrations.

## What This Changes

The PR changes the doctor `groupAllowFrom` fallback migration to skip writes when OpenClaw has no generated bundled schema for the channel, and adds a regression test for an external `email` channel.

## Best Possible Solution

Land the focused fail-closed doctor guard with the regression test, while keeping plugin-specific config migrations owned by plugin schemas or plugin doctor contracts rather than core guesses.

## Reproduction Assessment

Yes, from source and reported live evidence: current main allows missing generated schemas, then the doctor migration can write `groupAllowFrom` into external channel config that plugin schema validation rejects. I did not rerun a local test command in this read-only review.

## Solution Assessment

Yes, this is the best narrow fix: it gates only the write path on schema visibility while leaving bundled schemas and capability warnings intact. Loading external plugin schemas earlier or adding post-write validation are broader follow-ups, not required for this root-cause fix.
