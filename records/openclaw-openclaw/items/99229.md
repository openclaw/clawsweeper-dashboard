Keep open: current main still exposes an iOS Location Always setting and background-location runtime paths without the explicit user-facing permission contract/effective OS status requested here, and the linked background-mode posture decision remains open.

## What This Changes

The issue requests an explicit iOS Location Always permission flow and use-case contract that distinguishes desired app setting from effective OS authorization and aligns background location runtime, docs, and bundle configuration.

## Best Possible Solution

Have iOS/privacy owners decide whether background location is intended, then either implement a deliberate Always flow with effective OS-status UI and bundle validation or remove/soften the Always/background surfaces together.

## Reproduction Assessment

Yes, source-level: current main exposes Always in Settings and has Always-gated background runtime paths, while the UI/docs do not present an effective OS authorization/use-case contract. I did not run a live device permission-flow reproduction.

## Solution Assessment

Unclear until maintainers decide product intent. If background location stays, the narrow maintainable path is an explicit Always flow plus status model and bundle guard; if it does not, the safer path is to remove or soften the Always/background claims together.
