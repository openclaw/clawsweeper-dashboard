## Summary

Keep open: current main still has the reported no-fallback gap. The embedded runner can throw a live-switch control error during a clean active attempt, but `runWithModelFallback` converts that switch into a failed candidate when the target is not a later configured fallback, matching the reporter's `fallbackConfigured=false` log and bypassing the existing outer retry loop.

## What This Changes

The issue asks OpenClaw to retry an in-flight turn against a newly selected live model instead of ending the run when the switch occurs mid-attempt.

## Best Possible Solution

Keep the existing bounded outer live-switch retry, but let a real user-requested switch escape or redirect out of `runWithModelFallback` when it is not a configured fallback candidate; preserve the stale-switch loop guard for same or earlier fallback targets.

## Repair Work Prompt

Fix the live model switch mid-attempt bug reported in https://github.com/openclaw/openclaw/issues/101676. Current main throws `LiveSessionModelSwitchError` from `src/agents/embedded-agent-runner/run.ts` when a persisted user model switch is detected during a clean active attempt, but `src/agents/model-fallback.ts` converts that error into a failed fallback candidate when the switched model is not a later configured fallback candidate; with no configured fallback this produces `model_fallback_decision decision=candidate_failed fallbackConfigured=false` and the outer `src/agents/agent-command.ts` or cron live-switch retry loop never runs. Make the boundary distinguish a real user-requested live switch from stale same/earlier fallback conflicts: retry the same turn on the requested provider/model through the existing bounded outer retry path, while preserving the existing loop guard for stale fallback switch errors. Add focused regression coverage for the no-fallback explicit switch path and keep existing fallback-loop tests passing by updating only the semantics that are now intentionally different. Do not add config, defaults, provider-specific literals, or broad fallback behavior.
