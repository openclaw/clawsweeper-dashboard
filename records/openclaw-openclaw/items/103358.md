## Summary

Keep open: current main still knowingly permits a rebased local head to become a tree-equivalent GraphQL commit with the old remote parent, so the reported ancestry-sensitive PR diff pollution remains possible. The protected `maintainer` label also requires explicit maintainer handling rather than cleanup closure.

## What This Changes

Fix `scripts/pr prepare-sync-head` so same-repository rebases cannot publish stale commit ancestry through GitHub GraphQL.

## Best Possible Solution

Detect whether the prepared commit changes branch ancestry; permit GraphQL only when it can preserve that ancestry, otherwise fail closed or use the existing explicit lease-protected git override, then verify the remote parent or merge base as well as its tree and add a regression test for equal trees with different parents.

## Solution Assessment

Yes in direction: ancestry-aware push selection and verification inside the existing PR wrapper is the narrowest maintainable fix. The safe default should fail closed when the verified GraphQL path cannot represent the rebased parent rather than treating tree equality as sufficient.
