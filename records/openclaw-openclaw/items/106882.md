## Summary

Keep this issue open: current Discord voice support tracks voice-state events and supplies routed voice turns, but the inspected implementation does not proactively enqueue initial-roster or membership-change context. The issue is newly filed, assigned, and protected by the `maintainer` label, so conservative cleanup must leave it for explicit handling.

## What This Changes

Add silent session-scoped Discord voice events that seed the current participant roster and report subsequent joins, leaves, and moves.

## Best Possible Solution

Keep roster tracking inside the Discord voice-session owner: seed a bounded member map from the cached guild voice states when a session activates, diff only user/channel transitions from subsequent voice-state updates, exclude the bot, and enqueue non-waking untrusted system context to the resolved supervisor session with focused join, leave, move, duplicate-update, reconnect, and silence tests.
