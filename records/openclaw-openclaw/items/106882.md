## Summary

Keep this issue open. Current Discord voice support creates a routed session and consumes voice-state updates for the bot and configured follow users, but it does not seed the active agent with the channel roster or emit general participant join/leave context. The request is newly filed, assigned, concretely bounded, aligned with channel improvements, and protected by the `maintainer` label. ([github.com](https://github.com/openclaw/openclaw/blob/main/extensions/discord/src/voice/manager.ts))

## What This Changes

Notify an active Discord voice agent of the initial participant roster and subsequent participant joins, leaves, or moves through silent session-scoped context events.

## Best Possible Solution

Implement roster ownership in the Discord voice manager: seed a bounded self-excluding snapshot when a session becomes active, track user channel transitions, and enqueue silent untrusted membership events to the resolved supervisor session with focused deduplication and no-spoken-reply tests.
