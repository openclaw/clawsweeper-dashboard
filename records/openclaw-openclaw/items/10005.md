## Summary

## What This Changes

The issue requests a configuration option to hide the rendered chat `/status` and `session_status` card while preserving current behavior by default.

## Best Possible Solution

Define a maintainer-approved status-card visibility contract that preserves current rendering by default, covers the security-sensitive privacy scope, and updates schema, help/docs, and focused chat/tool tests together.

Rationale: Source inspection proves the gap, but the permanent config key and privacy boundary affect public configuration and security-sensitive status disclosure, so automation should not choose it alone.

Options:

- **Per-agent or per-section visibility (recommended):** Add a scoped visibility model that can suppress usage/cost or other sensitive sections while preserving the existing card by default.
- **Whole-card boolean or JSON-only mode:** Add the smallest requested toggle, accepting that it may not fully solve the multi-agent privacy case from the related closed issue.
- **Reject new config surface:** Keep `/status` and `session_status` as explicit diagnostic surfaces and close the product direction as not planned.

## Solution Assessment

Unclear as proposed; a whole-card boolean is plausible, but the best fix needs maintainer choice on privacy scope, output shape, and config ownership. A per-agent or per-section visibility model may solve the security case better than only JSON output.
