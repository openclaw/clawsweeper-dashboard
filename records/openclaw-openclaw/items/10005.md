Keep open: current main still has no supported way to hide, reduce, or return JSON-only output for the rendered chat `/status` and `session_status` status card, and the related privacy-focused request was already closed into this issue as the canonical tracker.

## What This Changes

Request to add a supported option to hide or reduce the rendered `/status` and `session_status` status card, likely through `session.statusCard` or `agents.defaults.statusCard`.

## Best Possible Solution

Define a maintainer-approved status-card visibility contract that preserves current rendering by default, covers the multi-agent usage/billing privacy case, and updates schema, docs, and focused chat/tool tests together.

## Reproduction Assessment

Yes for the current-behavior gap via source inspection: current main funnels both `/status` and `session_status` through rendered status-card text with no supported hide or JSON-only setting. This is a feature request rather than a failing bug reproduction.

## Solution Assessment

Unclear as proposed; a config key is plausible, but the best fix needs maintainer choice on privacy scope, output shape, and config ownership. A narrower section-visibility model may solve the security use case better than only whole-card JSON output.
