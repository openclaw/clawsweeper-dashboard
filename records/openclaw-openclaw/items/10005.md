## Summary

Current main and release v2026.6.11 still render the shared status card for both chat `/status` and `session_status`, with no supported hide, JSON-only, or section-visibility setting. This remains the canonical tracker and needs maintainer product/privacy direction before implementation.

## What This Changes

Add a configuration option to suppress the rendered session status card while preserving current behavior by default.

## Best Possible Solution

Define one shared status-presentation policy under `src/status/`, preserve current rendering by default, apply it consistently to chat and tool callers, and document whether sensitive sections can be suppressed per agent or trust boundary.
