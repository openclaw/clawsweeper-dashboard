## Summary

Keep open: current main still has no supported way to hide or reduce the rendered chat `/status` and `session_status` card, and the related CLI JSON and status-cost work are adjacent surfaces rather than replacements.

## What This Changes

The issue requests a configurable way to hide the rendered session status card for chat `/status` and `session_status`, preserving current behavior by default.

## Best Possible Solution

Define a maintainer-approved status-card visibility contract that keeps current rendering on by default, covers the multi-agent usage/billing privacy case, and updates schema, docs, chat-command tests, and `session_status` tests together.

## Reproduction Assessment

Yes for the current-behavior gap via source inspection: current main funnels both `/status` and `session_status` through rendered status-card text with no supported hide or JSON-only setting. This is a feature request rather than a failing bug reproduction.

## Solution Assessment

Unclear as proposed; a boolean config key is plausible, but the best fix needs maintainer choice on privacy scope, output shape, and config ownership. A section-visibility model may solve the security use case better than only whole-card JSON output.
