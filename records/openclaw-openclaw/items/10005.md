## Summary

Current main and v2026.6.11 still render chat `/status` and `session_status` through the shared status-card text path with no supported hide, JSON-only, or section-visibility setting, so this remains a valid product/privacy request.

## What This Changes

The issue requests a configuration option to hide or suppress the rendered session status card for chat `/status` and the `session_status` tool while preserving current behavior by default.

## Best Possible Solution

Define a maintainer-approved status-card visibility contract that preserves current rendering by default, covers privacy-sensitive status fields, and updates schema, docs, and focused chat/tool tests together.

- **Reject new config surface:** Keep `/status` and `session_status` as explicit diagnostics surfaces and close the product direction as not planned.

## Solution Assessment

Unclear as proposed; a whole-card boolean is plausible, but the best fix needs maintainer choice on privacy scope, output shape, and config ownership. A per-agent or per-section visibility model may solve the security case better than only JSON output.
