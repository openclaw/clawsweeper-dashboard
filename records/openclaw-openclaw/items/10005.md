## What This Changes

Add a documented configuration setting to suppress the rendered status card returned by chat `/status` and the `session_status` tool.

## System Context

Chat `/status` and the agent-facing `session_status` tool both feed runtime and session facts into OpenClaw’s shared status renderer. That renderer produces the human-readable card sent back through chat or tool output, so a visibility choice must be defined consistently across both entry points.

## Architecture Diagram

flowchart LR
  A[Runtime and session facts] --> B[Shared status renderer]
  C[Chat /status command] --> B
  D[session_status tool] --> B
  B --> E[Rendered status card]
  E --> F[Chat reply]
  E --> G[Tool response]
  H[Chosen visibility setting] --> B

## Best Possible Solution

Define one documented status-visibility contract for both `/status` and `session_status`, preserve today’s rendered card by default, and add focused schema, help, docs, and regression coverage for the selected disabled behavior.
