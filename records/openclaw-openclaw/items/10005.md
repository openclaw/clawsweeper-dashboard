## Summary

## What This Changes

Add a documented setting that lets users suppress the rendered status card returned by chat `/status` and the `session_status` tool.

## System Context

Chat `/status` and the agent-facing `session_status` tool both assemble runtime, model, token, session, and task information into a shared human-readable status response. The response is sent back through the active conversation or tool result, so a visibility policy must define what callers receive instead.

## Architecture Diagram

flowchart LR

  B[session_status tool] --> C
  D[Runtime and session facts] --> C
  C --> E[Rendered status card]
  E --> F[Chat reply]
  E --> G[Tool result]
  H[Chosen visibility policy] --> C

## Best Possible Solution

Choose one documented visibility policy for the shared status presentation, preserve today’s rendered output by default, then thread that policy through both chat and tool paths with focused contract tests and upgrade-safe schema/help/docs.
