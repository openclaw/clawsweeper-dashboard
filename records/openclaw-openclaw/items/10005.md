## Summary

Keep open: current main and the latest release still render chat `/status` and `session_status` through the shared status-card text path with no supported hide, JSON-only, or section-visibility setting. The remaining work is a product/security configuration decision, not an already-implemented cleanup item.

## What This Changes

The issue requests a config option such as `session.statusCard` or `agents.defaults.statusCard` to suppress the rendered `/status` and `session_status` status card while preserving current behavior by default.

## Best Possible Solution

Add a maintainer-approved, documented status-card visibility contract for chat `/status` and `session_status`, preserving current rendering by default and covering privacy-sensitive usage/cost suppression with schema, docs, and focused tests.
