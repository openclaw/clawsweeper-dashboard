## What This Changes

The issue requests a configuration option to hide the rendered chat and session-tool status card while preserving current behavior by default.

## Best Possible Solution

Define a maintainer-approved status-card visibility contract that preserves current rendering by default, covers the shared-user privacy case, and updates config schema, docs, and focused chat/tool tests together.

## Reproduction Assessment

Yes for the current-behavior gap via source inspection: both chat `/status` and `session_status` still flow through rendered status-card text with no supported hide or JSON-only setting. This is a feature request rather than a failing bug reproduction.

## Solution Assessment

Unclear as proposed; a config key is plausible, but the best fix needs maintainer choice on privacy scope, output shape, and config ownership. A narrower section-visibility model may solve the security use case better than only whole-card JSON output.
