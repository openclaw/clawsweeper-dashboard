## Summary

Keep open: current main and the latest release still render chat `/status` and `session_status` through the shared status-card text path, with no supported hide, JSON-only, or section-visibility setting. The remaining work is a maintainer product/security decision because it adds a new configuration surface around potentially sensitive status output.

## What This Changes

Request to add a default-on configuration option that can hide the rendered `/status` and `session_status` card and return less chat-visible output.

## Best Possible Solution

Add one documented default-on status-card visibility contract for chat `/status` and `session_status`, preserving current output for existing users while explicitly covering sensitive usage/cost suppression with schema, docs, and focused tests.
