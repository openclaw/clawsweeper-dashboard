## Summary

Keep open: current main and the latest release still render chat `/status` and `session_status` through the shared status-card text path with no supported hide, JSON-only, or section-visibility setting. The remaining work is a product/security configuration decision, not an already-implemented cleanup item.

## What This Changes

The issue requests a configuration option to hide or suppress the rendered status card returned by chat `/status` and the `session_status` tool.

## Best Possible Solution

Add a documented default-on status-card visibility contract for chat `/status` and `session_status`, preserving current output for existing users while allowing operators to suppress either the whole card or sensitive sections with schema, docs, and focused tests.
