## Summary

Keep open: current main and v2026.6.11 still return the shared rendered status card with no supported visibility control. The remaining work needs a maintainer security/product decision because cosmetic hiding, structured-only output, and per-agent sensitive-field filtering have different compatibility and disclosure semantics.

## What This Changes

Add a configuration-controlled way to hide or filter the human-readable session status card returned by chat `/status` and the `session_status` tool.

## Best Possible Solution

Preserve the current default card and authorization checks, then add an explicitly approved per-agent status-section policy that applies consistently to rendered text and structured details, with schema, help, docs, and focused coverage for both callers.
