## Summary

Current main still renders both chat `/status` and `session_status` through the shared human-readable status-card path, and the documented tool contract provides no suppression or structured-only mode. This remains a valid low-priority product/config request: the privacy-focused related issue was folded into this canonical tracker, while CLI JSON output does not solve chat or tool presentation. Maintainers must choose the supported visibility scope and output semantics before implementation.

## What This Changes

Add an opt-in configuration control that hides the rendered session status card for chat `/status` and `session_status`, retaining current rendering by default.

## Best Possible Solution

Define one canonical least-disclosure policy at the agent/status presentation boundary, preserve the current operator-facing card by default, allow per-agent section or visibility control where less-trusted recipients are possible, and retain structured `session_status` details for agent workflows with focused documentation and tests for both chat and tool paths.

## Solution Assessment

No, the proposed undifferentiated boolean is not yet the best solution because it does not define global versus per-agent scope or whether structured tool details remain available. A canonical per-agent presentation policy that can suppress sensitive sections while preserving operational fields is safer and more flexible.
