## Summary

Keep open: current main and the latest release still always render chat `/status` and `session_status` through the status-card text path, with no supported hide, JSON-only, or section-suppression setting. This remains the canonical tracker for the related usage/billing privacy request.

## What This Changes

Request a configuration-controlled way to hide or replace the rendered status card for chat `/status` and the `session_status` tool while preserving current behavior by default.

## Best Possible Solution

Define a maintainer-approved status-card visibility contract that preserves current rendering by default, covers the multi-agent usage/billing privacy case, and updates schema, docs, and focused chat/tool tests together.

## Reproduction Assessment

Yes for the current-behavior gap via source inspection: current main funnels both `/status` and `session_status` through rendered status-card text with no supported hide or JSON-only setting. This is a feature request rather than a failing bug reproduction.

## Solution Assessment

Unclear as proposed; a whole-card boolean config is plausible, but the best fix needs maintainer choice on privacy scope, output shape, and config ownership. A narrower per-agent or per-section visibility model may solve the security case better than only JSON output.
