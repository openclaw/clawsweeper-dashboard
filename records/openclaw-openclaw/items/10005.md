## Summary

Keep open: current main and the latest release still route chat `/status` and `session_status` through the rendered status-card text path with no supported hide, JSON-only, or section-visibility setting. This remains a product/security configuration decision rather than an implemented cleanup item.

## What This Changes

The issue requests a new configuration option to hide or suppress the rendered `/status` and `session_status` card while preserving current rendering by default.

## Best Possible Solution

Add a documented default-on visibility contract for chat `/status` and `session_status`, preserving current output for existing users while covering privacy-sensitive usage/cost suppression with schema, docs, and focused tests.
