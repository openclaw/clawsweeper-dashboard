Request adding a documented configuration option to suppress the rendered `/status` and `session_status` status card, preserving current rendering by default.

## Best Possible Solution

Define a maintainer-approved status-card visibility contract that preserves current rendering by default, covers the multi-agent usage/billing privacy case, and updates schema, docs, chat-command tests, and `session_status` tests together.

## Reproduction Assessment

Yes, at source level: current main funnels both chat `/status` and `session_status` through rendered status-card text with no supported hide, section filter, or JSON-only setting. This is a feature/config request rather than a failing bug reproduction.

## Solution Assessment

Unclear as proposed; a boolean config key is plausible, but the best fix needs maintainer choice on privacy scope, output shape, and config ownership. A section-visibility model may solve the security use case better than only whole-card JSON output.
