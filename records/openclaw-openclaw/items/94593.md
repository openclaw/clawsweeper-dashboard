## Summary

Keep open: the reset-preservation direction is still useful, but the PR head introduces a cleanup regression when `OPENCLAW_TRAJECTORY_DIR` is also a normal cleanup directory. Ordinary transcript archives in that directory would stop pruning because the new header gate only accepts trajectory runtime headers.

## What This Changes

The PR archives reset-time trajectory runtime and pointer artifacts, excludes archived trajectory filenames from transcript classification, and scans `OPENCLAW_TRAJECTORY_DIR` for header-proven trajectory archives during retention cleanup.

## Best Possible Solution

Keep the shared reset-archive fix, but narrow the override-directory cleanup gate so trajectory override archives are protected without changing existing transcript archive retention in overlapping cleanup directories.

## Reproduction Assessment

Yes. Source inspection shows current main archives only transcript candidates on reset, and the PR body supplies terminal red/green proof for production archive and cleanup functions against on-disk session directories; this read-only review did not rerun tests.

## Solution Assessment

No, not yet. The shared reset helper is the right owner boundary, but the override cleanup gate should be scoped to trajectory override archives instead of changing transcript archive retention in overlap cases.
