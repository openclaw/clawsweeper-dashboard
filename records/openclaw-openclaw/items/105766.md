## Summary

This PR addresses a valid requester-stop gap, but the new path cancels the ACP runtime directly instead of using the canonical task cancellation lifecycle. That can leave durable task or mirrored-flow state stale or report a user cancellation as another terminal outcome, and the PR supplies mocked tests rather than live ACP process-cleanup proof.

## What This Changes

The PR extends requester-stop handling to cancel active owner-keyed ACP detached tasks and adds tests for terminal-task filtering and child-session deduplication.

## Best Possible Solution

Enumerate active ACP tasks owned by the requester, but route each through the canonical task cancellation API—or add one owner-scoped task cancellation helper—so runtime termination, cancelled status, flow synchronization, and delivery semantics remain one lifecycle; then prove the child process exits in a real ACP run.
