## Summary

Keep open. Current main and the latest release provide global transient cron retry/backoff, but the requested per-job `openclaw cron add` / `openclaw cron edit` retry controls and stored job policy are still absent; the linked fork PR is open but conflicting, so it is not a merged solution.

## What This Changes

Add per-cron-job retry count, retry delay, and optional backoff controls so failed recurring jobs retry before their next natural schedule.

## Best Possible Solution

Keep this as the canonical request and land an additive, maintainer-approved per-job retry design that preserves the global default behavior, documents CLI/Gateway/storage semantics, and either refreshes or replaces the conflicting fork implementation.
