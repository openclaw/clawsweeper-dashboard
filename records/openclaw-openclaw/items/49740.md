## Summary

Keep open. Current main has global transient retry/backoff for recurring cron errors and tests it, but the requested per-job CLI, Gateway, and persisted retry controls are still absent; an open cross-repo PR references this issue, so the safe path is maintainer product/API review rather than closing.

## What This Changes

Add per-job cron retry options such as `--retry-count`, `--retry-delay`, and optional backoff so failed recurring jobs can rerun before their next scheduled slot.

## Best Possible Solution

Keep this issue as the canonical per-job cron retry contract discussion, then land an additive design that preserves the current global retry behavior and documents CLI, Gateway, storage, list/status, and failure-alert semantics.
