## Summary

Keep open. Current main and v2026.6.11 already retry recurring cron jobs globally after transient failures, but the requested per-job `cron add` / `cron edit` retry-count, retry-delay, and retry-backoff contract is still absent and needs maintainer product review.

## What This Changes

Request adds per-job cron retry controls for count, delay, and optional backoff so failed scheduled jobs retry before the next natural run.

## Best Possible Solution

Keep this as the canonical request and land an additive maintainer-approved per-job retry design that preserves existing global retry/backoff safeguards, Gateway compatibility, persisted job shape, docs, and regression proof.
