## Summary

Keep open. Current main and the latest release handle transient recurring cron failures through global `cron.retry`, but the requested per-job `openclaw cron add` / `openclaw cron edit` retry controls are still absent and need a maintainer-approved public cron contract.

## What This Changes

Request per-job cron retry options for failed scheduled jobs, including retry count, delay, and optional backoff controls.

## Best Possible Solution

Keep the global retry behavior, then land an additive per-job retry design with explicit CLI, Gateway, persisted job, docs, and regression-test coverage after maintainer approval.

## Reproduction Assessment

Yes, at source level. Current main has global transient retry behavior, but the requested per-job CLI flags, persisted retry policy, and Gateway-visible job fields are absent.

## Solution Assessment

Unclear. Per-job retry controls are plausible, but the best solution needs maintainer approval because global retry already solves the broad outage case while per-job settings add public API and storage semantics.
