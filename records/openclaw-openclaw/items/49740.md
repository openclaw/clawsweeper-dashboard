## Summary

Keep open. Current main and v2026.6.11 solve the global recurring retry gap, but the requested per-job retry count, retry delay, and backoff controls for `openclaw cron add` / `openclaw cron edit` are still absent and need a maintainer-approved public cron contract.

## What This Changes

Add per-job retry controls to cron add/edit so failed recurring jobs can retry after configurable delays before the next natural schedule.

## Best Possible Solution

Keep the shipped global retry behavior and decide an additive per-job retry contract that preserves current schedule-cadence safeguards before implementing new cron CLI/API/storage fields.
