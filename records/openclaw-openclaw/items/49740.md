## Summary

Keep open: current main and the latest release already retry recurring cron jobs after transient failures, but this issue still requests a per-job `cron add`/`cron edit` retry-count, retry-delay, and backoff contract that is absent and compatibility-sensitive.

## What This Changes

The issue requests configurable per-job cron retry controls for failed scheduled runs, including retry count, delay, and optional backoff behavior.

## Best Possible Solution

Keep this issue as the canonical per-job cron retry request until maintainers either approve an additive job-level retry policy with explicit global fallback and clear/disable semantics, or decide shipped global retry is the intended product boundary.
