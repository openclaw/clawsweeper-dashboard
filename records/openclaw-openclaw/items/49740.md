## Summary

Keep open. Current main and v2026.6.11 have global transient cron retry/backoff for recurring jobs, but the requested per-job `openclaw cron add` / `openclaw cron edit` retry-count, retry-delay, and retry-backoff contract is still absent and needs maintainer product approval.

## What This Changes

The issue requests configurable per-job cron retries after scheduled job failures, including retry count, delay, and optional backoff flags on `openclaw cron add` and `openclaw cron edit`.

## Best Possible Solution

Keep this issue as the canonical request and land an additive maintainer-approved per-job retry design that preserves the existing global retry/backoff safeguards, Gateway protocol compatibility, persisted job shape, docs, and regression proof.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose global cron retry behavior, but the requested per-job CLI flags, Gateway schema fields, and persisted job retry policy are absent.

## Solution Assessment

Unclear. Per-job retry controls are plausible and aligned with the reliability need, but the best solution needs maintainer approval because it adds a public CLI/API/storage contract on top of existing global retry behavior.
