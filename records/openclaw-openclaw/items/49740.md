## Summary

Keep open: current main and v2026.6.11 already mitigate transient recurring cron failures with global retry/backoff, but the requested per-job `cron add`/`cron edit` retry-count, retry-delay, and backoff contract is still absent and needs maintainer product/API direction.

## What This Changes

Request to add configurable per-job cron retry controls to `openclaw cron add` and `openclaw cron edit`, including retry count, delay, and backoff behavior after failed scheduled runs.

## Best Possible Solution

Keep this as the canonical per-job cron retry request until maintainers either approve an additive job-level retry policy or explicitly declare the shipped global retry policy sufficient.
