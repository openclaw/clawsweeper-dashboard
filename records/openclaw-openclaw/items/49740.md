## Summary

Keep open. Current main and v2026.6.11 already have global cron retry/backoff for transient recurring failures, but the requested per-job `openclaw cron add` / `openclaw cron edit` retry count, delay, and backoff controls are still absent and need maintainer-approved public cron job semantics.

## What This Changes

Requested configurable per-job retry options for cron jobs so failed scheduled runs can retry before the next natural schedule.

## Best Possible Solution

Define a maintainer-approved job-level retry policy that extends the cron CLI, Gateway API job schema, SQLite persistence, docs, and regression tests without disturbing the existing global default retry behavior.

## Reproduction Assessment

Yes for the remaining gap: source inspection shows global retry exists, while per-job retry fields and CLI flags are absent from the current CronJob schema and add/edit command surfaces.

## Solution Assessment

No final implementation shape is confirmed yet; the likely best shape is a job-level override layered over the existing global retry policy, but the public API and migration semantics need maintainer confirmation.
