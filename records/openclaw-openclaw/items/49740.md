## Summary

Keep open: current main and v2026.6.11 cover global transient recurring-cron retry, but the requested per-job `cron add`/`cron edit` retry-count, retry-delay, and backoff contract is still absent and needs maintainer API/product direction.

## What This Changes

Request per-job cron retry controls so failed recurring jobs can retry before the next natural schedule instead of waiting hours or days.

## Best Possible Solution

Define an additive job-level retry policy with explicit zero/clear semantics, protocol/schema/docs/tests, and fallback to global defaults when unset, or explicitly decide that shipped global retry is the intended boundary.
