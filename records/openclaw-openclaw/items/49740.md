## Summary

Keep open. Current main and v2026.6.11 have global transient retry/backoff for recurring cron failures, but the requested per-job `openclaw cron add` / `openclaw cron edit` retry count, delay, and backoff controls are still absent and require a maintainer-approved public cron contract.

## What This Changes

The issue requests per-cron retry controls for failed scheduled jobs, including retry count, retry delay, and optional backoff flags on `openclaw cron add` and `openclaw cron edit`.

## Best Possible Solution

Keep this issue as the canonical product/API decision and land an additive per-job retry design only after maintainers settle CLI, Gateway, storage, default, and alert semantics.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 have global cron retry behavior, but the requested per-job CLI flags, Gateway schema fields, and persisted job retry policy are absent.

## Solution Assessment

Unclear. Per-job retry controls are plausible, but the best solution requires maintainer approval because it expands public CLI/API/storage semantics and must preserve the shipped global retry/backoff behavior.
