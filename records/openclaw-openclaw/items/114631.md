## Summary

Keep this PR open for maintainer review. The additive protocol path is coherent and preserves the current question payload, but it newly serializes a full wizard step—including a demonstrated sensitive initial value—into custodian chat results without an established confidentiality or retention contract for that transport.

## What This Changes

The PR adds an optional `step` field containing the full awaited wizard step to custodian chat replies and updates the gateway schema, generated Swift client, and protocol/engine tests.

## System Context

Custodian chat runs setup wizards through the system-agent chat engine, then the gateway returns each reply to connected clients. Today clients receive a lossy card-shaped question; this change additionally sends the complete wizard step so a later client renderer can support text inputs, large selections, links, and other wizard controls.

## Architecture Diagram

flowchart LR
  A[Setup wizard] --> B[Chat engine]
  B --> C[Awaited wizard step]
  C --> D[Question-card projection]
  C --> E[Full step payload]
  D --> F[Gateway chat reply]
  E --> F
  F --> G[Custodian client]
  G --> H[Future wizard renderer]

## Best Possible Solution

Define the custodian chat confidentiality contract before landing: either redact sensitive prefilled values from this transport while retaining the safe rendering metadata, or document and prove an end-to-end protected handling path for every chat-result consumer.
