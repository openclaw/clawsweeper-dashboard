## Summary

Keep open: the leak concern is real, but the patch is not mergeable because it removes the last Discord gateway `error` listener after dispose and reopens the late-error crash path that current cleanup tests and history intentionally guarded.

## What This Changes

The PR makes the Discord gateway supervisor call `emitter.off("error", onGatewayError)` during dispose and rewrites Discord monitor tests to assert zero retained error listeners after cleanup.

## Best Possible Solution

Prevent stale supervisor closure retention without leaving the shared Discord gateway emitter unguarded, and keep regression coverage for both repeated restarts and late `error` emission after disposal.

## Solution Assessment

No. Removing the exact listener is a plausible leak fix, but the best fix must also preserve late gateway error protection with a non-retaining/shared guard or clearer gateway-owned listener boundary.
