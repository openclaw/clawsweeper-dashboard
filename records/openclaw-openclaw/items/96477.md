## Summary

Keep open. The June 24, 2026 abort-cleanup repair addressed a related retained-lock leak, but the July 10, 2026 report describes a separate post-generation failure: a completed reply was not delivered and the session continued blocking queued inbound messages. The proposed readers-writer lock, sharding, batching, and pooling alternatives are product architecture choices, so this needs maintainer scoping plus current-release production evidence rather than an automated fix attempt.

## What This Changes

The issue requests a production-safe concurrency model for shared agent sessions so multi-user Slack and Telegram deployments do not serialize unrelated work or strand completed replies behind a session lock.

## System Context

Channel messages are mapped to an agent session, where an agent run reads and writes ordered transcript state before its completed reply is delivered back through the originating channel. Session locking protects that state, so changing its granularity affects run ordering, queue release, and message delivery correctness.
