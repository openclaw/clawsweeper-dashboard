## Summary

Keep this PR open for human review. The feature direction is coherent and extends the two merged question-runtime slices, but the new `operator.questions` permission is only added to fresh pairing profiles; an upgraded app can retain an existing paired token without that scope and lose access to gateway-backed question cards until there is a deliberate upgrade or recovery path. Real behavior proof also remains incomplete for the changed channel and native-app surfaces.

## What This Changes

This PR converges `ask_user`, Codex, and Copilot questions on the gateway runtime; adds channel terminal cleanup and reaction answering; adds native app cards; and moves web questions into a docked composer panel.

## Best Possible Solution

Preserve a safe upgrade experience for already-paired operator clients through an explicit scope-upgrade or visible re-pair recovery path, then add redacted after-fix evidence for native cards and representative channel finalization/reaction flows before merging.
