## Reproduction Assessment

Yes. Current main and `v2026.6.11` show `parseByteSize` rounding and checking only `Number.isFinite`, while `parseNonNegativeByteSize` floors finite numbers, so unsafe values remain finite but precision-corrupted.

## Solution Assessment

Yes, with a compatibility caveat. Centralizing the safe-integer check in `parseByteSize` and mirroring it in numeric config parsing matches `parseDurationMs` and covers the documented compaction byte-size callers; the extra Zod refine is redundant but harmless.
