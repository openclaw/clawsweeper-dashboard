## Summary

Keep this PR open: it addresses a confirmed destructive Windows restart bug with the right ownership boundary and no concrete code defect found, but the external contribution still needs real Windows behavior proof before merge.

## What This Changes

The PR derives trusted gateway entrypoints from the installed Windows launcher and checks each gateway-port listener’s process command line before force-killing it during update restart.

## Best Possible Solution

Keep the launcher-derived ownership gate, then prove on Windows that a competing unrelated listener survives while a genuine stale OpenClaw gateway listener is still cleared before the scheduled task restarts.
