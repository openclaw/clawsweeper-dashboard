The PR rewrites Slack `fetchWithSlackAuth` redirect handling to manually revalidate HTTPS Slack hosts on every hop, strip auth on cross-origin Slack redirects, and add SSRF regression tests.

## Best Possible Solution

Land the Slack helper redirect hardening after maintainer security review and required CI completion, while keeping the active Slack media download path on the shared guarded-fetch flow.

## Reproduction Assessment

Yes, by source inspection rather than a failing live run: current main validates the first Slack URL, then hands the redirected HTTPS URL to automatic fetch following without Slack-host checks on later hops.

## Solution Assessment

Yes. The patch is the narrow owner-local fix for this helper; the active production path already uses shared guarded media fetch, and this helper needs its own manual loop if it remains exported for tests or future internal use.
