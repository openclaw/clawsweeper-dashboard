Keep open for normal maintainer review: current main still has the Slack helper redirect gap, the PR is a focused security hardening of that helper, real behavior proof is sufficient, and I found no blocking patch defect.

## What This Changes

The PR rewrites Slack `fetchWithSlackAuth` redirect handling as a bounded manual loop that revalidates every redirect target as HTTPS on a Slack hostname and adds SSRF regression tests.

## Best Possible Solution

Land the narrow Slack helper hardening after ordinary maintainer merge review, while keeping production Slack media downloads on the shared guarded `saveRemoteMedia` path.

## Reproduction Assessment

Yes. Current-main source plus undici source show that after the first manual Slack redirect response, later hops are delegated to automatic `redirect: "follow"` behavior without another Slack hostname check.

## Solution Assessment

Yes. The PR fixes the implicated owner-local helper by applying the same per-hop manual redirect invariant used by the guarded media path; routing this response-returning helper through the full media-save path would be broader than needed.
