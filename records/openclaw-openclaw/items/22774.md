## Summary

Keep open. Current main and v2026.6.11 still provide trace provenance, `senderLabel` display hints, and forwarded-label projection, but not the requested durable human/main-agent/sub-agent sender identity contract across protocol input, transcripts, subagent delivery, history/live events, and Control UI avatars.

## What This Changes

Requests durable multi-role sender identity in Chat UI for multi-agent workflows so human, main-agent, and sub-agent messages render with distinct attribution.

## Best Possible Solution

Define one additive trusted per-message sender metadata contract, persist it where appropriate, expose it through chat/session history and live events, and render stable names, avatars, and colors without changing provider-facing roles.

## Reproduction Assessment

Yes, at source level. Current schemas, provenance types, subagent announce delivery, history projection, and Control UI rendering provide trace fields or derived labels rather than a durable human/main-agent/sub-agent sender identity contract.

## Solution Assessment

Yes in direction, but not as a UI-only avatar patch or a new provider message role. The maintainable solution is additive trusted sender metadata that preserves canonical transcript roles while giving history and UI consumers durable renderable identity.
