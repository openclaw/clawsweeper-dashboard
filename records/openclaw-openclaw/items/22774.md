## Summary

Keep open: current main has useful provenance and sender-label projection for `sessions_send`, but it still lacks the requested durable per-message human/main-agent/sub-agent identity contract across protocol schemas, persisted transcripts, live/history events, subagent announcements, and Control UI avatars.

## What This Changes

The issue requests multi-role Chat UI attribution so human, main-agent, and sub-agent messages have distinct durable identity, labels, avatars, and colors in multi-agent workflows.

## Best Possible Solution

Define one additive, durable sender identity contract for chat/session messages, persist it with transcripts, expose it through `chat.history` and live session events, carry it through `chat.send`, `sessions.send`/steer paths, and render per-message labels/avatars/colors in Control UI while coordinating narrower open attribution bugs.
