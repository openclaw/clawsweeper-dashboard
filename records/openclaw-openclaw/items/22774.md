## Summary

Keep open: current main and v2026.6.11 still provide trace provenance, spawnedBy metadata, and derived senderLabel hints, but not the requested durable human/main-agent/sub-agent sender identity contract across protocol input, transcripts/history/live events, subagent delivery, and Control UI avatars.

## What This Changes

The issue requests durable multi-role sender identity in the Chat UI so human, main-agent, and sub-agent messages render with distinct, auditable identities.

## Best Possible Solution

Define one additive trusted per-message sender metadata contract and carry it through protocol input, transcript persistence/history/live events, subagent/session-send delivery, and Control UI rendering while preserving provider-facing message roles.

## Reproduction Assessment

Yes, by source inspection: the current schemas, provenance model, display projection, and UI normalizer expose only trace metadata or senderLabel hints, not the requested durable sender identity contract.

## Solution Assessment

No; current main has useful derived labels and spawnedBy/provenance metadata, but the maintainable solution is a single additive sender identity contract across message ingestion, persistence, live/history payloads, and rendering.
