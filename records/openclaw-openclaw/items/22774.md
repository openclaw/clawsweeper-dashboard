## Summary

Keep open: current main and v2026.6.11 still have provenance, `senderLabel`, `spawnedBy`, and partial forwarded-display logic, but not the requested durable per-message sender identity contract across Gateway schemas, sessions, transcripts, live/history payloads, subagent delivery, and Control UI rendering.

## What This Changes

The issue requests multi-role Chat UI attribution so human users, main agents, and subagents render with distinct sender identity in multi-agent workflows.

## Best Possible Solution

Define one additive sender identity object with stable id, kind, display name, source agent/session, render metadata, and trust/provenance semantics, then thread it through chat.send, sessions.send/steer, subagent announcements, persistence, history/live events, and Control UI rendering.
