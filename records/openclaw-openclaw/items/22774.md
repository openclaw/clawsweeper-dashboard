## Label Justifications

## Summary

Keep open. Current main and v2026.6.11 still provide only trace provenance plus derived senderLabel display for some sessions_send cases, not the requested durable human/main-agent/sub-agent sender identity contract across protocol inputs, transcripts, subagent announcements, live/history payloads, and per-message Control UI avatars.

## What This Changes

Request durable multi-agent sender attribution in Chat UI so human, main-agent, and sub-agent messages render with distinct identity instead of sharing role-based user/agent avatars.

## Best Possible Solution

Define an additive trusted per-message sender metadata contract, persist and propagate it through chat/session/subagent/history/live paths, and update Control UI rendering while preserving provider-facing roles.

## Reproduction Assessment

Yes, at source level. Current schemas, provenance types, subagent delivery, display projection, and Control UI rendering show trace fields or derived labels rather than a durable per-message sender identity contract.

## Solution Assessment

Yes in direction, but not as a UI-only avatar patch or new provider message roles. The maintainable solution is additive trusted sender metadata that preserves canonical transcript roles while giving history and UI consumers durable renderable identity.
