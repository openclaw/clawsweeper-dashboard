## Summary

Keep open: current main and v2026.6.11 still provide provenance and senderLabel display hints, but not the requested durable per-message human/main-agent/sub-agent identity contract across protocol input, transcripts, live/history events, and Control UI avatars.

## What This Changes

The issue requests durable multi-role sender identity in the Chat UI so human, main-agent, and sub-agent messages can be distinguished in multi-agent workflows.

## Best Possible Solution

Define an additive trusted per-message sender metadata contract, persist it with transcript/history events, carry it through inter-session and subagent delivery, and render it in Control UI without replacing provider-compatible message roles.
