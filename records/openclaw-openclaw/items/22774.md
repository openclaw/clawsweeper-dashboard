## Summary

Keep open: current main has inter-session provenance and senderLabel display hints, but it still lacks a durable per-message sender identity contract across Gateway schemas, transcripts/history/live events, subagent delivery, and Control UI rendering. Related issues either close into this broader tracker or cover narrower prompt/UI fallback slices.

## What This Changes

The issue requests durable Chat UI sender identity for human, main-agent, and sub-agent messages in multi-agent workflows.

## Best Possible Solution

Define one additive per-message sender identity object with stable id, kind, display name, source agent/session, render metadata, and trust/provenance semantics, then thread it through chat.send, sessions.send/steer, subagent announcements, persistence, history/live events, and Control UI grouping/avatar rendering.
