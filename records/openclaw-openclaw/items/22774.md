## Summary

Keep open: current main has partial sender-label and transcript metadata handling, but the issue’s durable multi-role sender identity contract is still missing across public gateway schemas, sessions_send routing, persisted/live message state, and Control UI rendering.

## What This Changes

Request durable multi-role chat identity so human, main-agent, and sub-agent messages can be attributed and rendered distinctly in multi-agent workflows.

## Best Possible Solution

Define an additive canonical sender identity contract first, then thread it through sessions/chat protocol, transcript persistence, live/history projections, and Control UI rendering with compatibility tests for existing label-only messages.
