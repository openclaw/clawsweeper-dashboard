## Summary

Keep open: current main and v2026.6.11 still provide inter-session provenance and senderLabel display hints, but not the requested durable per-message human/main-agent/sub-agent sender identity contract across protocol input, transcripts, live/history payloads, and Control UI avatars.

## What This Changes

Request durable multi-role sender attribution in Chat UI for human, main-agent, and sub-agent messages in multi-agent workflows.

## Best Possible Solution

Define an additive per-message sender identity contract and carry it through protocol input, persisted transcripts, history/live events, and Control UI rendering without relying on UI-only senderLabel inference.

Rationale: The issue is not a narrow bug fix: it changes stored message semantics and public gateway/UI contracts, and the current code has several partial attribution mechanisms that need one maintainer-approved source of truth.

- **Keep narrow partial fixes only:** Continue landing scoped senderLabel and sessions_send prompt fixes while leaving the broader durable identity contract unimplemented for now.
- **Defer multi-agent UI identity:** Leave this open as a roadmap item until a larger multi-agent/session model design is prioritized.

## Reproduction Assessment

Yes, at source level: current main has no durable sender identity fields in chat.send or sessions.send, InputProvenance only carries source trace metadata, and Control UI rendering consumes only role plus senderLabel. I did not run the reported live five-agent workflow in this read-only review.

## Solution Assessment

Unclear until maintainers define the product/API contract. The current UI senderLabel projection is a useful partial mitigation, but the maintainable fix is an additive per-message sender metadata contract rather than more role-only avatar inference.
