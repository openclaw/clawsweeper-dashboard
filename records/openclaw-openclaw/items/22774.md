## Summary

Keep open: current main and v2026.6.11 have useful inter-session provenance, `senderLabel`, and `sessions_send` forwarded-display projection, but they still do not provide the requested durable per-message human/main-agent/sub-agent identity contract across protocol, transcripts, history/live events, and Control UI avatars.

## What This Changes

Request durable multi-role sender identity in Chat UI so multi-agent messages can distinguish human, main-agent, and sub-agent origins.

## Best Possible Solution

Define one additive per-message sender identity contract and carry it through protocol input, persisted transcripts, history/live events, and Control UI rendering without relying on role-only avatar inference or UI-only senderLabel recovery.

- **Keep Narrow Partial Fixes:** Continue landing scoped senderLabel, requester-name, and WebChat fallback repairs while leaving the broader durable identity contract unimplemented for now.
- **Defer Multi-Agent UI Identity:** Leave this as a roadmap item until a broader multi-agent/session model design is prioritized.

## Reproduction Assessment

Yes, at source level: current main has no durable sender identity fields in chat.send or sessions.send, InputProvenance only carries trace metadata, and Control UI rendering consumes only role plus senderLabel. I did not run the reported live five-agent workflow in this read-only review.

## Solution Assessment

Unclear until maintainers define the product/API contract. The current senderLabel and forwarded-display projections are useful partial mitigations, but the maintainable fix is an additive per-message sender identity contract rather than more role-only avatar inference.
