## Summary

Keep open: current main has provenance traces, forwarded `senderLabel` projection, and browser-local identity, but it still lacks the durable per-message human/main-agent/subagent sender identity contract requested across Gateway schemas, transcripts, live/history payloads, and Control UI avatars.

## What This Changes

The issue requests durable multi-role Chat UI sender attribution so human, main-agent, and subagent messages remain distinguishable in multi-agent workflows.

## Best Possible Solution

Define one additive per-message sender identity contract, persist it with transcript entries, expose it through history/live events, and render it in Control UI without replacing existing source provenance or narrow sessions_send fixes.
