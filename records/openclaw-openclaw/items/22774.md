## Summary

Keep open: current main and v2026.6.11 still provide trace provenance and a simple `senderLabel` display hint, but not the requested durable per-message human/main-agent/sub-agent sender identity contract across protocol inputs, transcripts, history/live payloads, and Control UI avatars.

## What This Changes

Request multi-role sender identity in the Chat UI so human, main-agent, and sub-agent messages are visually and durably distinguishable in multi-agent workflows.

## Best Possible Solution

Define an additive per-message sender metadata contract with sender id, sender kind, display name, source session/agent, and renderable avatar/color metadata, persist it in transcripts, expose it through history/live events, and render it in Control UI without turning this into a broader agent-hierarchy framework.

## Reproduction Assessment

Yes, source inspection gives a high-confidence source-level reproduction of the missing contract: protocol schemas, `InputProvenance`, subagent announce delivery, and Control UI rendering carry role plus optional label/provenance, not durable per-message sender identity. I did not run a live multi-agent UI scenario in this read-only review.

## Solution Assessment

No, the proposed avatar-only framing is not the best complete fix by itself; the maintainable solution is first to define and persist sender metadata, then render avatars/colors/names from that contract. The current `senderLabel` projection remains a useful partial fallback but does not solve auditability across all requested paths.
