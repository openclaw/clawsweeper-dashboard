## Summary

Keep open: current main and v2026.6.11 still have provenance and senderLabel display hints, but not the requested durable per-message human/main-agent/sub-agent identity contract across protocol, transcripts, live/history payloads, and Control UI rendering.

## What This Changes

The issue requests multi-role Chat UI support so human, main-agent, and sub-agent messages carry distinct durable sender identity and visual attribution in multi-agent workflows.

## Best Possible Solution

Define one additive per-message sender identity contract and carry it through protocol input, persisted transcripts, history/live events, subagent announce delivery, and Control UI rendering without relying on UI-only senderLabel inference.

Rationale: The current code has several partial attribution mechanisms, but the requested fix changes public gateway and persisted session semantics, so automation should not choose the canonical identity shape.

Options:

- **Design additive sender metadata (recommended):** Add a durable sender identity object with sender id, kind, display name, source session/agent, and renderable avatar/color metadata, then migrate UI and session surfaces to consume it.
- **Keep narrow partial fixes:** Continue landing scoped senderLabel and sessions_send prompt fixes while leaving the broader durable identity contract unimplemented for now.
- **Defer multi-agent identity:** Leave this open as a roadmap item until a larger multi-agent/session model design is prioritized.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 have no durable sender identity fields in chat.send or sessions.send, InputProvenance only carries trace metadata, and Control UI rendering consumes role plus senderLabel. I did not run the reported live five-agent workflow in this read-only review.

## Solution Assessment

Unclear until maintainers define the product/API contract. The current senderLabel projection is a useful partial mitigation, but the maintainable fix is an additive per-message sender metadata contract rather than more role-only avatar inference.
