## Summary

Keep open: current main and v2026.6.11 still provide role-based chat rendering plus provenance and `senderLabel` hints, but not the requested durable human/main-agent/sub-agent sender identity contract across protocol, transcripts, live/history payloads, subagent announcements, and Control UI rendering.

## What This Changes

Request durable multi-role Chat UI attribution for human, main-agent, and sub-agent messages in multi-agent workflows.

## Best Possible Solution

Define one additive durable sender identity object for chat/session messages, persist it with transcripts, expose it through history/live events, carry it through `chat.send`, `sessions.send`/steer and subagent announce paths, and render per-message labels/avatars/colors in Control UI.
