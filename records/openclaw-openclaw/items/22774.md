## Summary

Keep open: current main and the latest release have inter-session provenance, forwarded `senderLabel` display, browser-local identities, and subagent lineage hints, but they still do not provide the requested durable per-message human/main-agent/subagent sender identity contract across protocol, transcript/history, live events, and Control UI rendering.

## What This Changes

The issue requests multi-role Chat UI sender attribution so human users, main agents, and subagents are visually and persistently distinguishable in multi-agent workflows.

## Best Possible Solution

Define one additive sender identity object with stable id, kind, display name, source agent/session, render metadata, and trust semantics, then thread it through chat.send, sessions.send/steer, subagent announcements, persistence, history/live events, and Control UI grouping/avatar rendering.
