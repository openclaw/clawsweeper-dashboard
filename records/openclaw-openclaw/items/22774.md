## Summary

Keep open. Current main and v2026.6.11 still provide trace provenance, derived `senderLabel` display hints, and forwarded-message projection, but not the requested durable per-message human/main-agent/sub-agent sender identity contract across chat/session protocol, transcripts, subagent delivery, history/live payloads, and Control UI avatars.

## What This Changes

Request durable multi-role sender attribution in Chat UI and session history so human, main-agent, and sub-agent messages render with distinct identities instead of being shown as the human user.

## Best Possible Solution

Define one additive trusted per-message sender metadata contract, persist it where appropriate, propagate it through chat/session/subagent delivery and history/live events, and render stable names, avatars, and colors without changing provider-facing roles.

## Reproduction Assessment

Yes, at source level. Current schemas, provenance types, sessions.send forwarding, docs, and Control UI rendering show trace fields and derived labels rather than a durable human/main-agent/sub-agent sender identity contract; I did not run a live five-agent workflow in this read-only review.

## Solution Assessment

Yes in direction, but not as a UI-only avatar patch or new provider message roles. The maintainable solution is additive trusted sender metadata that preserves canonical transcript roles while giving history and UI consumers durable renderable identity.
