## Summary

Keep open: current main has provenance traces and sender-label display hints, but it still lacks a durable per-message sender identity contract that can distinguish human users, main agents, and subagents across Gateway schemas, session history, live events, and Control UI rendering.

## What This Changes

The issue requests durable multi-role/per-message sender identity in the Chat UI for multi-agent workflows.

## Best Possible Solution

Define one additive sender identity object with stable id, kind, display name, source agent/session, render metadata, and trust/provenance semantics, then thread it through chat.send, sessions.send/steer, subagent announcements, persistence, history/live events, and Control UI grouping/avatar rendering.
