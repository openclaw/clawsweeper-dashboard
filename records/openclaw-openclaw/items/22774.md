## Summary

Keep open: current main has partial `sessions_send` forwarded-label projection and `senderLabel` display hints, but it still lacks the durable per-message sender identity contract needed to distinguish humans, main agents, and subagents across protocol, transcripts, live/history events, and Control UI rendering.

## What This Changes

The issue requests durable multi-role sender identity in the Chat UI so human, main-agent, and sub-agent messages are visually and auditably distinct in multi-agent workflows.

## Best Possible Solution

Define one additive sender identity object with stable id, kind, display name, source agent/session, render metadata, and trust/provenance semantics, then thread it through chat.send, sessions.send/steer, subagent announcements, persistence, history/live events, and Control UI grouping/avatar rendering.
