## Summary

Keep this issue open because the linked pull request, https://github.com/openclaw/openclaw/pull/113188, explicitly targets this remaining A2A prompt-cache problem and has not merged. The earlier merged work in https://github.com/openclaw/openclaw/pull/90173 intentionally stabilized only session identifiers while leaving volatile announce reply text out of scope, so it does not supersede this report.

## What This Changes

Move volatile A2A announce text, reply turn counters, and inbound context out of the early system-prompt region so inter-agent handoffs retain provider prompt-prefix cache reuse.

## System Context

The agent runtime turns `sessions_send` requests into A2A handoffs, combining routing and step context with the target agent prompt. Context placed in the early system prompt changes the cached prefix before tool schemas and conversation history; tail runtime context can carry per-turn facts without destabilizing that prefix.

Review and, if complete, land https://github.com/openclaw/openclaw/pull/113188 with regression coverage that compares full system-prompt bytes across announce, reply, heartbeat, and ordinary inbound A2A paths while preserving the volatile facts in tail runtime context.
