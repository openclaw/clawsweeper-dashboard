## Label Justifications

- `P1`: A stalled Discord or proxy connection can indefinitely block an active outbound webhook delivery workflow.
- `merge-risk: 🚨 message-delivery`: Aborting after Discord may have accepted the POST can create an ambiguous failure and duplicate a message if an upper layer retries.

## Summary

The patch appears narrowly correct, but this external PR should remain open because its evidence is focused Vitest/loopback output rather than after-fix proof from a real Discord or proxy setup. The 15-second abort also creates an ambiguous-delivery edge if Discord accepts a webhook but stalls its response body, so the surrounding delivery path must not blindly retry and duplicate the message.

## What This Changes

The PR applies Discord’s 15-second REST timeout budget to webhook requests and response-body reads, preserves deadline errors, and adds stalled-server regression coverage.

## Best Possible Solution

Keep one Discord-owned 15-second deadline across connection and body consumption, classify post-dispatch timeouts as an unknown delivery outcome that cannot be blindly retried, and prove the behavior through a redacted real Discord or proxy run.
