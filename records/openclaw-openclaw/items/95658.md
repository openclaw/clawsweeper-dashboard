## Label Justifications

- `P1`: The issue reported a latest-release upgrade regression that broke a real Telegram/Groq voice transcription workflow until users discovered external plugin recovery steps.
- `impact:message-loss`: Failed STT meant voice-note content was not transcribed into the channel/agent message path.
- `impact:auth-provider`: The failure was caused by provider/plugin resolution after Groq moved to the external @openclaw/groq-provider package.

## Summary

Current main implements the actionable Groq media-provider recovery path with a catalog-gated install, registry refresh, gateway stop/start, and doctor hint, which resolves the central dead-end upgrade failure without re-bundling or runtime auto-installing the provider.

## What This Changes

The issue reports that upgrading to 2026.6.9 externalized Groq STT into an external provider plugin, leaving configured Groq audio users with failed Telegram transcription and a generic missing-provider error unless they install, refresh, and fully restart the gateway.

## Best Possible Solution

Keep Groq as an official external provider plugin and rely on the current main catalog-gated recovery diagnostic; file a narrower follow-up only if a fresh report still shows incorrect agent-turn behavior after install, registry refresh, and full gateway stop/start.
