## Summary

Keep open: the PR targets a real CLI hang, but the current helper can still force-exit without a callback-backed stdout/stderr barrier and may truncate the same model inspection output it is trying to protect.

## What This Changes

The branch adds a deferred default-runtime one-shot exit helper and wires `models list` and `models status` to request a top-level forced exit after output and teardown.

## Best Possible Solution

Make the exit helper always wait on callback-backed stdout and stderr barrier writes before `runtime.exit`, preserve the default-runtime/custom-runtime split, and refresh current-head terminal proof for `models list --json`, `models status --json`, and `models status --check`.

Overall correctness: patch is incorrect

Full review comments:

- **[P2] Always wait on stream callbacks before exiting:** `src/cli/one-shot-exit.ts:60-62`
  - body: This branch treats `writableLength <= 0` as already flushed and jumps to `setImmediate(exit)`, but `process.exit()` terminates immediately and there is no callback-backed stdout/stderr barrier in that path. Under pipe-backed stdout or log collectors, the final small JSON/table write can be accepted below the high-water mark and still be at risk when the forced exit runs, so the fix can replace a hang with truncated model inspection output. Queue a callback-backed barrier write for stdout and stderr before calling `runtime.exit`, even when `writableLength` is zero.
  - confidence: 0.86
