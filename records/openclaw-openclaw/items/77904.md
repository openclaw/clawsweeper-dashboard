## Summary

Keep this PR open because the current head still has a concrete output-safety defect: the forced exit can skip the stream barrier exactly when a small pipe-backed write was accepted below the high-water mark, so the final model output can still be truncated.

## What This Changes

The PR adds a default-runtime one-shot exit helper, requests it from successful `models list` and `models status` output paths, and flushes it from top-level CLI teardown.

## Best Possible Solution

Keep the top-level teardown flush, but make it wait on callback-backed stdout/stderr barrier writes regardless of `writableLength` and cover the zero-buffer pending-output case with a regression test.
