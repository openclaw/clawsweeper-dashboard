## Summary

Current main has useful cron inspection, including delivery-route previews and manual-run waiting, but still lacks side-effect-free cron execution testing, an input-driven skill test runner, and a supported mock/read-only tool-interception contract. The related open items cover narrower slices and do not supersede this broader design issue.

## What This Changes

Add CI-friendly cron and skill test/validation commands that preview execution and delivery while preventing or explicitly controlling external side effects.

## Best Possible Solution

Define an additive request-scoped testing contract with validation-only cron preview, an explicit-input skill runner, structured redacted call traces, and capability-aware side-effect policies coordinated with the narrower global-interception issue.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What public guarantee should cron and skill testing provide: static validation only, execution up to the model boundary, or a full agent turn with universally intercepted tools and deliveries?

Rationale: Those modes have materially different fidelity, security, concurrency, plugin compatibility, and CI semantics, so implementation cannot safely choose the boundary from the issue sketch alone.

Likely owner: steipete

Owner reason: They provided the existing design review and have the broadest recent history across the affected cron, skills, and runtime boundaries.

Owner confidence: high

Options:

- **Phased scoped contract (recommended):** Ship request-scoped static cron validation and an explicit-input skill harness first, then add capability-aware execution interception after the shared tool contract is approved.
- **Full universal dry-run:** Design one core run context that intercepts every tool, plugin hook, delivery, command job, and client tool, accepting the larger compatibility and security program.
- **Retain inspection only:** Treat existing cron inspection and normal skill invocation as sufficient and decline a stronger no-side-effect execution guarantee.

## Reproduction Assessment

Yes at source level: current main exposes real cron runs and inspection commands but no side-effect-free cron execution test, no skill test RPC or CLI, and no supported universal mock/read-only run context. A live failure is unnecessary because the missing capability is observable from the public command and method surfaces.

## Solution Assessment

No for the literal global configuration and blanket mock-wrapper sketch. The safer maintainable direction is request-scoped, phased, explicit about model and tool boundaries, and coordinated with https://github.com/openclaw/openclaw/issues/41418.
