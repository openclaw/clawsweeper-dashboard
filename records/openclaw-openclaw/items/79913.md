## Summary

Keep open: current main and the latest release still do not read `SPAWN_ALLOWLIST`, so the PR is useful, but the submitted patch is not merge-ready because host env can override explicit default `sessions_spawn` authorization config.

## What This Changes

The PR applies `OPENCLAW_SPAWN_ALLOWLIST` or `SPAWN_ALLOWLIST` to `agents.defaults.subagents.allowAgents` during config load and adds parser/overlay tests.

## Best Possible Solution

Land a fallback-only env bridge that fills a missing default allowlist for env-only Docker deployments, preserves explicit JSON and per-agent allowlists, keeps configured-agent wildcard limits, and documents precedence.

## Reproduction Assessment

Yes. Source inspection shows current main and `v2026.6.11` have no `SPAWN_ALLOWLIST` reader, while native, ACP, and `agents_list` spawn surfaces consume only configured `subagents.allowAgents`; I did not run the Docker Compose scenario.

## Solution Assessment

No as written. A config-load fallback is the right narrow layer for env-only Docker deployments, but it should not override explicit default allowlists without maintainer-approved security semantics and docs.
