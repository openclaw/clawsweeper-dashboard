## What This Changes

The PR mirrors official external provider `providerEndpoints` into the bundled external provider catalog, appends those catalog manifests to provider endpoint attribution, and adds docs plus regression tests for dist builds without installed provider plugins.

## Best Possible Solution

Land the catalog mirror after maintainer acceptance of the endpoint-policy compatibility change and exact-head CI, while keeping hosted marketplace feeds out of classification.

## Reproduction Assessment

Yes at source level. Current main only collects endpoint metadata from installed/bundled manifests, and package excludes remove the affected official provider manifests from dist, so those URLs fall through to `custom` when the plugin is not installed.

## Solution Assessment

Yes, with maintainer sign-off on the compatibility surface. Mirroring manifest endpoint metadata into the shipped official catalog is narrower than loading source `extensions/` in built checkouts and preserves installed-manifest precedence.
