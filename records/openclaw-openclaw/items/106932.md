## Label Justifications

- `P0`: The underlying current-user failure leaves an active Codex-backed channel session permanently unusable and recovery requires manual SQLite repair.
- `merge-risk: 🚨 compatibility`: The patch removes an established `session_start` plugin notification from Control UI child creation and successful fork paths.
- `merge-risk: 🚨 session-state`: Plugin consumers may fail to initialize or associate state for the newly created child when its lifecycle start event is suppressed.

## Summary

Keep this PR open but do not merge it as written: suppressing the parent’s terminal event addresses the reported binding retirement, but the same guard also suppresses the newly created child’s established `session_start` lifecycle event, and the submitted proof is mock-based rather than a real dashboard-to-parent round trip.

## What This Changes

The PR skips paired parent `session_end` and child `session_start` hooks for detached dashboard children and forks, with gateway tests updated to expect neither lifecycle event.

## Best Possible Solution

Decouple the events: suppress only the parent `session_end` for parallel child/fork creation, continue emitting `session_start` for the created child, preserve `before_reset` and `command:new`, and prove a real parent turn succeeds after dashboard-child creation.
