## Summary

This PR addresses a valid P0 session-corruption path, but the unchanged head still has the prior P1 lifecycle-classification defect: it suppresses the parent terminal event for every dashboard-keyed child, including Control UI `/new` when one dashboard session actually replaces another. Focused tests support the reported mechanism, but no live after-fix parent-turn proof is provided.

## What This Changes

The PR changes gateway child-session lifecycle emission so detached dashboard children and forks do not end the parent session while still starting the created child.

## Best Possible Solution

Classify succession from both operation intent and parent/target roles: forks and dashboard children created from non-dashboard channel parents remain parallel, while dashboard-to-dashboard `/new` and non-dashboard successors retain the parent `session_end`; cover each case and provide a redacted live parent-turn transcript.
