## Summary

This PR should stay open: the previous P1 blocker remains on the same reviewed head because the target-key heuristic treats every dashboard-keyed child as parallel, including a dashboard-to-dashboard Control UI `/new` successor that must still end its replaced parent, and the external PR still lacks after-fix live Codex-backed proof.

## What This Changes

The PR changes gateway session creation to suppress the parent `session_end` hook for forks and dashboard-keyed children while retaining the new child's `session_start`, with focused gateway lifecycle tests.

## Best Possible Solution

Classify succession from both parent and child semantics: forks and channel-to-dashboard detached children remain parallel, while dashboard-to-dashboard Control UI `/new` remains a rollover; cover both paths and provide redacted live Codex-backed before/after proof.
