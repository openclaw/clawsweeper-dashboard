## Summary

Keep this PR open: it targets a severe, source-supported session-state bug, but the dashboard-key heuristic also suppresses the established parent lifecycle event for every dashboard child without proving that all such children are parallel. The lifecycle contract needs maintainer confirmation and real Codex-backed behavior proof before merge.

Likely related people: @BunsDev is the strongest routing candidate because the behavior appears to date to the merged Control UI `/new` lifecycle work, with medium confidence.

## What This Changes

Gates the parent `session_end(reason:"new")` hook for forks and dashboard-keyed children while continuing to emit the created child's `session_start`, with focused gateway lifecycle tests.

## Best Possible Solution

Represent parent disposition explicitly at the `sessions.create` caller boundary—parallel child, fork, or replacement—then emit parent `session_end` only for replacement while testing channel-to-dashboard parallel creation and dashboard/TUI successor creation separately.
