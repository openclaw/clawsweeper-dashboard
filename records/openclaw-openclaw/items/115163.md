## Summary

Keep this maintainer-labeled Slack fix open. The shared resolver approach correctly targets the reported silent table loss across live input, thread context, and read actions, but the new table-presence predicate also treats table blocks inside Slack app/message unfurls as qualifying content; this changes debounce behavior despite the PR’s stated ordinary-attachment-only boundary. The PR body provides extensive fixture, test, and CI evidence, but no after-fix live Slack run or redacted runtime output, so real behavior proof remains mock-only.

## What This Changes

This PR renders native Slack pasted table blocks as escaped TSV and uses a shared message resolver so tables reach live agent input, thread history, and Slack channel/thread read results.

## System Context

The Slack plugin turns Slack message text, blocks, and selected attachment content into text supplied to agents and returned by Slack read actions. The shared resolver is used by live message preparation, thread-history reconstruction, and channel/thread reads, so its attachment provenance rules affect multiple inbound paths.

## Best Possible Solution
