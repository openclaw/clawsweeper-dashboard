## Summary

Current main has partial model/fallback observability, but the central request is still missing: durable resolved-backend provider/model fields are not stored on sessions, `session_status` does not expose them, and the OpenAI-compatible stream path still does not capture `chunk.model` as a resolved runtime model.

## What This Changes

Request to expose requested versus resolved backend provider/model and fallback state through session persistence, `session_status`, and agent runtime/status surfaces.

## Best Possible Solution

Define an additive generic resolved-backend telemetry contract, capture provider response model data where available, persist requested versus actual/fallback state, and expose it consistently in `session_status`, status text, and runtime usage surfaces with live proxy proof.
