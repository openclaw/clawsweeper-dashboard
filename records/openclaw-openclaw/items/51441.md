## Summary

Keep open: current main has partial response-model and fallback trace concepts, but it still does not expose a stable resolved backend model/provider and fallback-used contract through `session_status`, agent metadata, persisted session state, or Gateway session rows.

## What This Changes

Expose requested-vs-resolved backend model/provider and fallback-used metadata in session status, agent runtime context, and persisted/Gateway session surfaces.

## Best Possible Solution

Define one requested-vs-resolved model/provider contract, capture successful provider response identity, persist/display it without overwriting selected model state, and prove it with a live routing-proxy scenario.

## Reproduction Assessment

No live current-main LiteLLM/OpenRouter repro was run here; source inspection shows the requested public fields are absent, and issue comments provide live examples of resolved runtime/status divergence.

## Solution Assessment

Unclear until maintainers choose the product contract; capturing `response.model` is necessary but not sufficient unless persistence, Gateway rows, status output, and agent-facing metadata agree.
