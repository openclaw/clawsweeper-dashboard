## Summary

Keep open. Current main has partial internal fallback telemetry, but it still lacks the requested stable public contract for resolved backend provider/model and fallback-used metadata in `session_status`, persisted session usage, and `GatewaySessionRow`.

## What This Changes

Request to expose requested versus resolved backend model/provider and fallback-used metadata in agent runtime, session persistence, `session_status`, and status output.

## Best Possible Solution

Define one core telemetry contract that carries requested and resolved provider/model plus fallback-used state from OpenAI-compatible transport and execution trace through session persistence, Gateway rows, `session_status`, and agent runtime text, with focused proxy/fallback tests.

## Reproduction Assessment

No high-confidence live reproduction was run in this read-only review. Source inspection does show the requested public fields are absent while related internal telemetry exists, so the missing-contract part is source-reproducible.

## Solution Assessment

Yes, the requested direction is broadly the right layer, but the best implementation should reuse the existing `executionTrace`/reply-usage substrate instead of adding a competing model identity path. Maintainers still need to decide the exact public field names, lifetime, and persistence semantics.
