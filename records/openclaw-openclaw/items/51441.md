Keep open. Current main has partial resolved-model plumbing for provider output and embedded-runner attribution, but the requested explicit resolved backend/fallback contract is still missing from Gateway session rows, `session_status` details/output, and the broader runtime-context surfaces.

## What This Changes

Expose actual backend model/provider and fallback status from proxy/provider execution through agent metadata, session persistence, Gateway session rows, `session_status`, and runtime context.

## Best Possible Solution

Define one additive resolved-runtime metadata contract, derive it from the existing `responseModel` and execution-trace paths, then surface it consistently in session rows, status output, and runtime context with focused proxy/fallback tests.
