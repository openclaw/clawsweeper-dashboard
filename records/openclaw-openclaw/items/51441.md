## Summary

Keep open. Current main has partial model/fallback tracing, but it still does not expose an explicit resolved backend/fallback contract through durable session rows, `session_status`, or OpenAI-compatible successful-response metadata.

## What This Changes

The issue requests resolved backend provider/model and fallback status in session status, persisted session metadata, and agent runtime context.

## Best Possible Solution

Define an additive core runtime/session contract that keeps requested selection separate from resolved provider/model/fallback status, persists it without overwriting user intent, and exposes it in `session_status` plus status surfaces with live routing-proxy proof.

Rationale: This changes provider/session API semantics across persistence, Gateway rows, agent runtime metadata, and user-visible status output, so automation should not pick the permanent contract shape alone.

Likely owner: steipete

Owner confidence: high

Options:

- **Add additive resolved metadata (recommended):** Add optional resolved provider/model/fallback fields alongside existing selected model fields and validate them against at least one routing proxy before exposing them broadly.
- **Only reconcile existing model fields:** Keep the current `model`/`modelProvider` shape and improve status display, accepting that requested-vs-resolved history remains ambiguous.
- **Defer to transport-only work:** Route only the HTTP/header side through https://github.com/openclaw/openclaw/issues/22021 and leave agent/session introspection for a later design.

We have a medium-confidence source reproduction, not a high-confidence live reproduction: current main lacks the requested fields in the session row, session store, usage persistence, and `session_status` output. The live LiteLLM/OpenRouter path was not run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the contract shape. The best maintainable direction appears to be additive resolved-runtime metadata rather than reusing `model`/`modelProvider` for both requested and resolved identity.
