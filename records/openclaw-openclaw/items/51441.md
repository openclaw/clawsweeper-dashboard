## Summary

Current main does not yet provide the requested resolved backend model/provider/fallback-used contract: it has partial internal concepts such as responseModel, executionTrace fallback metadata, and fallback notices, but the public session_status, Gateway session rows, persisted session usage, and agent runtime metadata still expose only selected/reported model identity. The issue should remain open as the canonical product/API contract for effective backend model attribution across routed/fallback model calls.

## What This Changes

Expose the actual resolved backend provider/model and fallback-used state in session_status, agent runtime metadata, and persisted Gateway session rows for routed model calls.

## Best Possible Solution

Keep this issue open as the canonical core contract, then implement additive resolved backend identity fields consistently from transport response metadata through agent metadata, persistence, Gateway/session_status, visible status, and tests/live proxy proof.

## Reproduction Assessment

Yes at source level: current main still lacks the requested resolved backend fields and propagation path, but I did not run a live LiteLLM/OpenRouter-style proxy reproduction.

## Solution Assessment

Unclear until maintainers choose the public contract shape; the best direction is an additive end-to-end resolved identity contract rather than a UI-only or trace-only patch.
