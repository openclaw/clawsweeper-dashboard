## Summary

Keep open: current main still exposes only the requested/runtime `modelProvider`/`model` identity and does not provide durable `resolvedModel`, `resolvedProvider`, or `fallbackUsed` fields through the session row, `session_status`, or OpenAI-compatible transport metadata. Related OpenRouter, HTTP-header, subagent, and UI issues overlap, but none replaces this broader session/runtime observability request.

## What This Changes

The issue requests first-class resolved backend model/provider and fallback metadata in OpenAI-compatible transport results, session persistence, `session_status`, CLI/status output, and agent runtime context.

## Best Possible Solution

Add additive core telemetry that keeps requested and resolved model/provider identities separate, persists the resolved backend/fallback result from the provider/fallback layer, and renders both clearly in `session_status` and runtime context.
