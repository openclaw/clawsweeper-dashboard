## Summary

Keep open. Current main has some selected/active model and fallback telemetry, but it still does not expose the requested resolved backend model/provider/fallback contract in `GatewaySessionRow`, `session_status`, or the OpenAI-compatible HTTP response surface.

## What This Changes

The issue requests resolved backend model/provider and fallback metadata in session status, persisted session usage, and agent runtime context for routing proxies such as LiteLLM/OpenRouter.

## Best Possible Solution

Define one additive resolved-runtime metadata contract that distinguishes requested, selected, active, and provider-reported model refs, then thread it through usage persistence, `GatewaySessionRow`, `session_status`, and relevant HTTP/provider paths with live proxy proof.

## Reproduction Assessment

Yes at source level: current session-row and session_status contracts lack the requested resolved backend fields, and the OpenAI-compatible HTTP route returns the requested `model` value in its response payload. I did not run a live routing-proxy repro.

## Solution Assessment

Unclear as a final design: capturing provider-reported model metadata is directionally right, but maintainers still need to choose the canonical API across status output, session rows, runtime context, and HTTP responses.
