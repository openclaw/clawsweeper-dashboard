## Summary

Keep this PR open but do not merge the current head: the reported false overflow is credible and proof-positive, yet the previously identified fallback-safety defect remains, and the latest refresh introduces a large unrelated replacement of the central attempt runtime.

## What This Changes

The PR skips the tool-loop guard’s aggregate character-based overflow check when the configured context engine declares ownership of compaction, while retaining individual tool-result truncation.

## Best Possible Solution

Keep individual tool-result truncation, suppress the aggregate heuristic only while a successfully assembled engine-owned view is active for the current iteration, immediately restore native guard behavior on engine fallback, and carry that narrow change on current main without replacing the modular attempt runtime.
