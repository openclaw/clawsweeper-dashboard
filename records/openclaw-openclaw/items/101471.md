## Summary

Keep open: the PR addresses a real ownsCompaction false-positive path, but the current head still disables the aggregate fallback guard even when the context-engine loop falls back to raw provider messages after `afterTurn` or `assemble` failure.

## What This Changes

The PR adds an `ownsCompaction` option to the embedded tool-result context guard, passes it from the engine-owned attempt path, and adds a regression test for skipping the aggregate overflow throw under pressure.

## Best Possible Solution

Skip the rough aggregate heuristic only when the context engine successfully owns the current transformed view; keep the aggregate guard active on engine-loop fallback unless maintainers explicitly accept provider-overflow fallback.

## Solution Assessment

No: the requested direction is valid, but the implementation remains too broad because it does not distinguish successful engine-owned assembly from engine fallback. The narrower fix is to mirror the pre-prompt `contextEngineAssemblySucceeded` shape for this mid-turn guard.
