## Summary

Keep open: the false-positive ownsCompaction fix is useful and has real log proof, but the branch still removes the existing local aggregate overflow fallback when the context-engine loop falls back to raw messages after an engine failure.

## What This Changes

The PR passes an `ownsCompaction` flag into the embedded tool-result guard, skips its aggregate char-based overflow throw for engine-owned compaction, and adds focused unit coverage for that skip.

## Best Possible Solution

Skip the rough aggregate heuristic only when the context engine successfully owns the current transformed view, or get explicit maintainer acceptance that provider overflow recovery is the intended fallback after engine-loop failure.

## Solution Assessment

No: the requested direction is valid, but the implementation is still too broad because it does not distinguish successful engine-owned assembly from engine fallback. The narrower fix is to make the skip depend on successful engine ownership for that transform.
