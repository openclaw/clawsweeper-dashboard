## Summary

Keep open: current main and v2026.6.11 preserve raw Telegram `<tg-emoji>` HTML, but still do not expose first-class `entities` or `caption_entities` through the shared message tool, Telegram send/edit/caption delivery, or a shared custom-emoji representation.

## What This Changes

Request Telegram custom emoji support in messages, captions, and replies, including identifiers and a supported way for OpenClaw message delivery to send them.

## Best Possible Solution

Choose one canonical product/API representation for Telegram custom emoji, then implement validated entity support through the shared message tool and Telegram send/edit/caption/reply paths while preserving existing HTML fallback behavior.

## Reproduction Assessment

Yes. Source inspection of current main and v2026.6.11 shows the message tool and Telegram send surfaces still lack first-class `entities` or `caption_entities`, and reporter comments describe production entity arrays being dropped through plugin slash-command/message-tool sends.

## Solution Assessment

Unclear until maintainers choose the public API shape. Raw `<tg-emoji>` preservation is useful, but it is not the full shared message/caption/reply entity solution requested.
