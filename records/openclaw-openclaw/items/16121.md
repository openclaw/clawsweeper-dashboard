## Summary

Keep open: current main has partial raw HTML `<tg-emoji>` passthrough and the newer `richMessages` option, but it still does not provide first-class outgoing Telegram custom emoji entity support through the shared message tool, send/edit paths, captions, or delivery adapters.

## What This Changes

The issue requests Telegram custom emoji support for messages, captions, and replies, including recognizing identifiers and preserving custom emoji formatting instead of escaping or dropping it.

## Best Possible Solution

Choose the public API representation first, then implement validated Telegram custom emoji support through message-tool, channelData, send, caption, edit, streaming/delivery paths, docs, and focused regression tests while preserving current HTML fallback behavior.
