## Label Justifications

- `P2`: The issue affects Telegram message fidelity and shared message-tool delivery for a major channel, but it has limited blast radius and does not make the core runtime unusable.

## Summary

Keep open: current main and v2026.6.11 preserve raw `<tg-emoji>` HTML, but they still lack a first-class `entities`/`caption_entities` path through the shared message tool and Telegram send/delivery surfaces; the closed related PR and issues do not supersede the remaining message, caption, edit, and reply work.

## What This Changes

Request to add first-class Telegram custom emoji support for outgoing messages, captions, replies, and shared message-tool entity handling.

## Best Possible Solution

Choose one canonical product/API representation for Telegram custom emoji, then implement it through the shared message tool and Telegram send/edit/caption/reply delivery paths while preserving the existing raw HTML fallback and chunking safeguards.

## Reproduction Assessment

Yes, from source inspection rather than a live Telegram run: the shared message tool and Telegram outbound adapter do not expose or forward a supported `entities`/`caption_entities` path, while comments provide a production path where custom emoji entities are dropped.

## Solution Assessment

No final implementation shape is confirmed yet; raw `<tg-emoji>` preservation is useful partial coverage, but the maintainable fix needs a maintainer-chosen API shape spanning the shared message tool and Telegram delivery paths.
