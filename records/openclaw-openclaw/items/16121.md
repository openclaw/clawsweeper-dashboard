## Summary

Keep open. Current main now preserves raw Telegram `<tg-emoji emoji-id="...">` HTML tags and has rich-message text support, but the canonical message-tool/entity surface still lacks `entities` and `caption_entities`, so the reported plugin slash-command custom emoji arrays still have no supported path.

## What This Changes

Request support for Telegram custom emoji in messages, captions, and replies, including identifier handling and message-tool delivery.

## Best Possible Solution

Keep this issue as the canonical tracker, choose one Telegram custom emoji representation, then wire it through the shared message tool and Telegram send/edit/caption/reply/streaming paths with fallback-preserving tests and live Telegram proof.
