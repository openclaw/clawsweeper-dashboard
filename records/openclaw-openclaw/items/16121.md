## Summary

Keep open: current main partially supports raw Telegram `<tg-emoji>` HTML and opt-in rich messages, but the first-class custom emoji entity path through the shared message tool, Telegram sends, captions, edits, and replies is still missing.

## What This Changes

Request first-class Telegram custom emoji support for outgoing messages, captions, and replies, including Telegram entity identifiers and a usable message-tool/API representation.

## Best Possible Solution

Choose one canonical product/API representation for Telegram custom emoji entities, then implement it through the shared message tool and Telegram send/edit/caption/reply paths while preserving existing raw HTML and rich-message fallback behavior.

## Reproduction Assessment

Yes. Source inspection shows the shared send schema, outbound adapter, and Telegram send options have no first-class entity/caption-entity input, and issue comments provide a production path where custom emoji entities are dropped through the message tool.

## Solution Assessment

Unclear until maintainers choose the API shape. Raw `<tg-emoji>` preservation and opt-in rich messages are useful partial support, but they do not solve the requested shared message/caption/reply entity path.
