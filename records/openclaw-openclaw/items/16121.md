## Summary

Keep open: current main and v2026.6.11 preserve raw Telegram `<tg-emoji>` HTML, but first-class `entities`/`caption_entities` still do not flow through the shared message tool, Telegram send/edit/caption delivery, or a canonical custom-emoji representation.

## What This Changes

Request support for Telegram custom emoji in messages, captions, and replies, including custom emoji identifiers and entity-based delivery.

## Best Possible Solution

Choose one canonical custom-emoji representation, then implement validated Telegram entity support through the shared message tool and Telegram send/edit/caption/reply/streaming paths while preserving current HTML fallback behavior.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 lack `entities`/`caption_entities` inputs through the message tool and Telegram send/edit paths, and the issue comments describe the matching production drop through plugin slash-command/message-tool sends.

## Solution Assessment

Unclear until maintainers choose the public API shape. Raw `<tg-emoji>` preservation is useful but does not solve the shared message/caption/reply entity support requested here.
