## Summary

Keep open: current main and v2026.6.11 only partially preserve raw Telegram `<tg-emoji>` HTML, but still do not expose Telegram `entities` or `caption_entities` through the shared message tool, send/edit/caption delivery, or a shared custom-emoji representation. This remains valid work, but the public API shape needs maintainer judgment before implementation.

## What This Changes

Request first-class Telegram custom emoji support in messages, captions, replies, and message-tool delivery using Telegram custom emoji identifiers/entities.

## Best Possible Solution

Choose one canonical public representation, then implement validated Telegram custom emoji entity support through the shared message tool and Telegram send/edit/caption/reply paths while preserving existing HTML, rich-message, and plain fallback behavior.

## Reproduction Assessment

Yes. Source inspection of current main and v2026.6.11 shows no message-tool or Telegram send/edit/caption `entities` path, and the issue comments include a production path where entity arrays are dropped through plugin slash-command/message-tool delivery.

## Solution Assessment

Unclear until maintainers choose the API shape. Raw `<tg-emoji>` preservation and richMessages help some cases, but they are not the full entity/caption-entity path requested.
