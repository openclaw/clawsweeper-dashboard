## Summary

Keep open: current main and v2026.6.11 only provide partial raw Telegram HTML/rich-message handling for custom emoji, while the shared message tool and Telegram send/edit/caption delivery paths still lack first-class `entities` and `caption_entities` support for `custom_emoji` metadata.

## What This Changes

Request support for Telegram custom emoji identifiers and rendering in messages, captions, and replies.

## Best Possible Solution

Choose one canonical API representation for Telegram custom emoji entities, then wire validated `entities` and `caption_entities` through the shared message tool and Telegram delivery paths while preserving existing HTML and rich-message fallback behavior.

## Reproduction Assessment

Yes. Source inspection shows the shared message schema, Telegram action payload builder, and low-level send options have no `entities` or `caption_entities` path, matching the reporter's production note that direct Bot API entity sends work but the OpenClaw message-tool path drops them.

## Solution Assessment

No final solution has been selected yet. Raw `<tg-emoji>` HTML preservation is a useful partial path, but the durable fix needs a maintainer-approved entity representation across message-tool, send, edit, caption, reply, and rich-message surfaces.
