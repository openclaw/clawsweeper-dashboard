## Summary

Keep open: current main and v2026.6.11 preserve raw Telegram `<tg-emoji>` HTML, but first-class Telegram custom emoji entities still cannot flow through the shared message tool, Telegram send/edit/caption paths, or a shared Markdown/custom-emoji representation.

## What This Changes

The issue requests first-class Telegram custom emoji support for messages, captions, and replies, including custom emoji identifiers and outgoing rendering.

## Best Possible Solution

Choose one canonical product/API representation for Telegram custom emoji, then implement validated entity support through the shared message tool and Telegram send/edit/caption/reply delivery paths while preserving the existing raw HTML fallback behavior.

## Reproduction Assessment

Yes. Source inspection shows the message tool and Telegram send surfaces still lack first-class `entities` or `caption_entities`, while reporter comments describe production entity arrays being dropped through plugin slash-command/message-tool sends.

## Solution Assessment

Unclear until maintainers choose the API shape. Raw `<tg-emoji>` preservation is useful, but it is not the full shared message/caption/reply entity solution requested.
