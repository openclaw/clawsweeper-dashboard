## Summary

Keep open: current main partially addresses raw Telegram custom emoji HTML by allowing `<tg-emoji emoji-id="...">`, but the shared message tool and Telegram send/edit/caption paths still do not expose first-class `entities` or `caption_entities` for the entity-based workflow users reported.

## What This Changes

The issue requests Telegram custom emoji support for messages, captions, and replies, including custom emoji identifiers and a usable send path from OpenClaw tooling.

## Best Possible Solution

Choose one canonical custom emoji representation, then implement validated Telegram delivery across the shared message tool and Telegram send, edit, caption, reply, and streaming paths while preserving current raw HTML and rich-message fallbacks.
