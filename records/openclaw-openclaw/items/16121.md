## Summary

Keep open: current main partially preserves raw Telegram `<tg-emoji>` HTML, but it still does not provide first-class custom emoji entity support through the shared message tool or Telegram send/caption/edit/reply delivery paths.

## What This Changes

The issue requests Telegram custom emoji support for messages, captions, and replies, including parsing/rendering custom emoji IDs and sending them where normal emoji are supported.

## Best Possible Solution

Choose the product/API representation first, then implement validated Telegram custom emoji support through the shared message tool and Telegram plugin delivery paths while preserving current HTML fallback behavior.

## Reproduction Assessment

Yes from source inspection: current main has no message-tool or Telegram send option that can carry `entities`/`caption_entities`, while Telegram's API supports those fields; no live Telegram send was run in this read-only review.

## Solution Assessment

The request is valid, but the best fix is not an ad hoc raw-HTML allowlist only; maintainers should first choose the durable entity or rich-message representation and then wire it consistently through Telegram delivery.
