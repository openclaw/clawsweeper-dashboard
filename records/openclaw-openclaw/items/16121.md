## Summary

Keep open: current main only partially handles raw Telegram `<tg-emoji>` HTML preservation, while first-class outgoing custom emoji entities for the shared message tool, Telegram send/edit paths, captions, and replies are still missing and need maintainer API-shape direction.

## What This Changes

Request support for Telegram custom emoji in messages, captions, and replies, including identifiers/entities and a user-facing way to send them.

## Best Possible Solution

Choose one canonical representation, then wire validated entities/caption_entities through the message tool, Telegram send/edit/caption/delivery paths, docs, and regression tests without regressing existing HTML fallback behavior.
