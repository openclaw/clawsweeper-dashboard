Request support for Telegram custom emojis in messages, captions, and replies, including custom emoji identifiers and first-class rendering/sending semantics.

## Best Possible Solution

Choose one canonical product/API representation for Telegram custom emoji entities, then implement it through the shared message tool and Telegram send/edit/caption delivery paths while preserving existing raw HTML and rich-message fallback behavior.

## Reproduction Assessment

Yes from source inspection, not live execution: the shared send schema and Telegram outbound adapter have no first-class entity-list input, while issue comments provide a production path where custom emoji entities are dropped through the message tool.

## Solution Assessment

Unclear until maintainers choose the API shape; raw `<tg-emoji>` preservation and rich-message helpers are useful partial support, but they are not the full shared message/caption/reply entity solution requested.
