## What This Changes

The issue requests Telegram custom emoji support in messages, captions, and replies, including custom emoji identifiers and send/display parity with standard emoji.

## Best Possible Solution

Choose one canonical product/API representation, then implement validated Telegram custom emoji entity support through the shared message tool and Telegram send/edit/caption/reply paths while preserving existing fallback behavior.

## Reproduction Assessment

Yes. Source inspection of current main and v2026.6.11 shows `entities` and `caption_entities` are absent from the shared message tool and Telegram send/edit/caption surfaces, matching the production report that custom emoji entity arrays do not survive message-tool sends.

## Solution Assessment

Unclear until maintainers choose the public API shape. Raw `<tg-emoji>` preservation helps some cases, but it is not the full shared message/caption/reply entity solution requested.
