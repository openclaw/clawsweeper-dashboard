## Summary

Keep open: current main and the latest release have partial raw `tg-emoji` HTML preservation, but they still lack the requested first-class Telegram custom emoji entity path through the shared message tool, Telegram sends, captions, edits, and replies.

## What This Changes

The issue requests first-class Telegram custom emoji support for messages, captions, and replies, including preserving Telegram custom emoji identifiers through OpenClaw delivery paths.

## Best Possible Solution

Choose one canonical custom-emoji representation, then wire it through the shared message tool and Telegram send/edit/caption/reply paths with offset, fallback, and chunking tests.

## Reproduction Assessment

Yes. Source inspection shows the shared send schema, outbound adapter, and Telegram send options have no first-class entity or caption-entity input, and issue comments provide a production path where custom emoji entities are dropped through the message tool.

## Solution Assessment

Unclear until maintainers choose the API shape. Raw `tg-emoji` preservation and opt-in rich messages are useful partial support, but they do not solve the requested shared message/caption/reply entity path.
