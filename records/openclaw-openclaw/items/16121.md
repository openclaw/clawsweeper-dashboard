## Summary

Keep open: current main only partially preserves raw Telegram <tg-emoji> HTML, while first-class custom emoji entities still cannot flow through the shared message tool, Telegram send/edit/caption delivery paths, or a shared Markdown/custom-emoji representation.

## What This Changes

Request first-class Telegram custom emoji support for OpenClaw Telegram messages, captions, and replies, including custom emoji identifiers and rendering.

## Best Possible Solution

Choose one canonical Telegram custom emoji representation, then add validated entity support through the Telegram plugin message-tool schema/channelData and send/edit/caption/reply paths while preserving existing raw HTML fallback behavior.

## Reproduction Assessment

Yes, source-reproducible: current schemas and send paths omit entities/caption_entities, and issue comments describe production entity arrays being dropped through plugin slash-command/message-tool sends.

## Solution Assessment

Unclear until maintainers choose the public API shape; raw <tg-emoji> preservation is useful but does not satisfy the shared message/caption/reply entity request.
