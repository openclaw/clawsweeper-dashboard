## Summary

Keep open: current main partially allows raw `<tg-emoji emoji-id="...">` HTML, but it still lacks first-class Telegram custom emoji entity support through the shared message tool and Telegram send/edit/caption delivery paths.

## What This Changes

Request first-class Telegram custom emoji support for messages, captions, and replies, including custom emoji identifiers and outgoing entity handling.

## Best Possible Solution

Choose the API representation first, then implement validated Telegram custom emoji entity support through the message tool and Telegram send/edit/caption/durable/streaming paths while preserving current HTML fallback behavior.

- **HTML-Only Scope:** Declare `<tg-emoji>` HTML passthrough the supported path and keep raw entity-array requests out of scope for now.

## Solution Assessment

Unclear until maintainers choose the API shape; a shared typed rich-text/custom-emoji representation appears cleaner than raw HTML only, but it must cover Telegram-owned delivery semantics.
