## What This Changes

The issue requests Telegram custom emoji support for outgoing messages, captions, and replies, including custom emoji identifiers and rendering behavior.

## Best Possible Solution

Choose one canonical API representation for Telegram custom emoji entities, then wire validated `entities` and `caption_entities` through the shared message tool and Telegram delivery paths while preserving existing HTML fallback behavior.

## Reproduction Assessment

Yes. Source inspection shows the shared message schema and Telegram send options have no entity fields, matching the reporter's production path where direct Bot API `entities` works but the plugin slash-command/message-tool path drops it.

## Solution Assessment
