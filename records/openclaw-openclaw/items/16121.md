## Summary

Keep open: current main has partial raw Telegram rich HTML support, including `<tg-emoji>`, but the first-class custom emoji entity path requested here is still missing from the shared message tool, Telegram send/edit/caption surfaces, and Telegram outbound payload data.

## What This Changes

Request support for Telegram custom emoji in messages, captions, replies, and shared message-tool delivery.

## Best Possible Solution

Choose one canonical product/API representation for Telegram custom emoji, then implement it through the shared message tool and Telegram send/edit/caption delivery paths while preserving the existing raw HTML fallback behavior.

## Reproduction Assessment

Yes, from source inspection rather than live execution: the current send/tool/payload surfaces have no first-class `entities` or `caption_entities` path while issue comments describe entity arrays being dropped through the shared message tool.

## Solution Assessment

No, the existing raw `<tg-emoji>` and opt-in rich message support is only a partial workaround; the maintainable fix needs a chosen API representation and regression coverage across message, caption, edit, and reply paths.
