## Summary

Keep open: current main and the latest release only partially address the request by preserving raw `<tg-emoji>` HTML, while the shared message tool and Telegram send/edit/caption paths still do not expose first-class `entities` or `caption_entities` for custom emoji metadata.

## What This Changes

The issue requests first-class Telegram custom emoji support for outgoing messages, captions, and replies, including custom emoji identifiers and rendering behavior.

## Best Possible Solution

Choose one canonical entity representation, then implement validated Telegram custom emoji delivery across the shared message tool and Telegram send, edit, caption, reply, and streaming paths while preserving current raw HTML and rich-message fallbacks.

Yes for source-level reproduction, but not via a live Telegram run in this read-only review. The issue discussion gives a concrete shared message-tool entity path, and current main still has no entity-bearing send schema or Telegram send/edit/caption option.

## Solution Assessment

Unclear until maintainers choose the public API shape. Raw `<tg-emoji>` preservation and opt-in rich messages cover part of the request, but they are not the full entity-based message/caption/reply solution reported by users.
