## Summary

Keep open: current main partially preserves raw Telegram `<tg-emoji>` HTML and supports opt-in rich messages, but first-class outgoing custom emoji entities through the shared message tool, Telegram sends, captions, edits, and replies are still missing.

## What This Changes

The issue requests Telegram custom emoji support for messages, captions, and replies, including custom emoji identifiers and entity-based delivery.

## Best Possible Solution

Choose one canonical custom-emoji entity representation, then implement it through the Telegram plugin message-tool schema, send/edit/caption/reply paths, and fallback tests while preserving existing raw HTML behavior.

## Reproduction Assessment

Yes. Source inspection shows the shared message-tool schema, Telegram schema contribution, outbound adapter, and send options have no first-class entity or caption-entity input, and issue comments provide a production path where custom emoji entities are dropped.

## Solution Assessment

Unclear until maintainers choose the API shape. Raw `<tg-emoji>` preservation and rich messages are useful partial support, but the durable solution needs one canonical entity representation with send/edit/caption/reply fallback parity.
