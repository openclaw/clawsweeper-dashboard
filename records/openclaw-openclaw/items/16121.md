## Summary

Keep open: current main and v2026.6.11 only partially cover the request through raw `<tg-emoji>`/rich-message HTML paths; the shared message tool and Telegram send/edit/caption delivery surfaces still do not expose first-class `entities` or `caption_entities` for custom emoji.

## What This Changes

The issue requests Telegram custom emoji support for outgoing messages, captions, replies, identifiers, and shared message-tool delivery.

## Best Possible Solution

Choose one canonical entity representation, then implement validated Telegram custom emoji delivery across the shared message tool and Telegram send, edit, caption, reply, and streaming paths while preserving current raw HTML and rich-message fallbacks.
