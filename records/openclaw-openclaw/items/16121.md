## Summary

Keep open: current main has partial raw `<tg-emoji>` and rich-message support, but the first-class `entities` / `caption_entities` path through the shared message tool and Telegram send/edit/caption/reply surfaces is still missing.

## What This Changes

The issue requests Telegram custom emoji support for messages, captions, and replies, including custom emoji identifiers and entity-aware rendering/delivery.

## Best Possible Solution

Choose one canonical representation, then implement validated Telegram custom emoji entity support through the shared message tool and Telegram send/edit/caption/reply paths while preserving the current raw HTML and rich-message fallbacks.
