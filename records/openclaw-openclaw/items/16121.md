## Summary

Keep open: current main and the latest release preserve raw Telegram `<tg-emoji>` HTML, but first-class custom emoji entities still cannot flow through the shared message tool or Telegram send/edit/caption delivery paths.

## What This Changes

The issue requests Telegram custom emoji support for messages, captions, replies, identifiers, rendering, and shared message-tool delivery.

## Best Possible Solution

Choose one canonical product/API representation, then implement validated Telegram custom emoji entity support through the shared message tool and Telegram send/edit/caption/reply paths while preserving raw HTML fallback behavior.

## Reproduction Assessment

Yes. Source inspection of current main and v2026.6.11 shows no first-class `entities` or `caption_entities` surface in the shared message tool or Telegram send paths, and reporter comments describe entity arrays being dropped through plugin slash-command/message-tool sends.

## Solution Assessment

Unclear until maintainers choose the public API shape. Raw `<tg-emoji>` preservation is useful partial progress, but it is not the full shared message/caption/reply entity solution requested.
