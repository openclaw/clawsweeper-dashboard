## Summary

Keep open: current main and the latest release still lack a first-class Telegram custom emoji entity path through the shared message tool, Telegram send options, captions, edits, and outbound adapter, even though raw `<tg-emoji>` HTML and opt-in rich messages now cover part of the original request.

## What This Changes

The issue requests first-class Telegram custom emoji support for messages, captions, and replies, including custom emoji identifiers and entity-preserving delivery.

## Best Possible Solution

Choose one canonical Telegram custom-emoji entity contract, then implement it through the shared message tool and Telegram plugin send/edit/caption/reply paths while preserving existing raw HTML and rich-message compatibility behavior.

## Reproduction Assessment

Yes. Source inspection shows no first-class `entities` or `caption_entities` input in the shared message tool, Telegram outbound adapter, or Telegram send options, and the issue comments provide a production path where custom emoji entities are dropped through that route.

## Solution Assessment

Unclear until maintainers choose the API shape. Raw `<tg-emoji>` preservation and opt-in rich messages are useful partial support, but they do not solve the requested message/caption/reply entity round-trip.
