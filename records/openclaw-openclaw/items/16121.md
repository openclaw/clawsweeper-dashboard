## Summary

Keep open: current main and v2026.6.11 only partially cover the request by preserving raw `<tg-emoji>` HTML, while the shared message tool and Telegram send/edit/caption paths still lack first-class `entities` or `caption_entities` support for custom emoji metadata.

## What This Changes

The issue requests Telegram custom emoji support for messages, captions, replies, and shared message-tool delivery.

## Best Possible Solution

Choose one canonical entity representation, then implement validated Telegram custom emoji delivery across the shared message tool and Telegram send, edit, caption, reply, and streaming paths while preserving current raw HTML and rich-message fallbacks.
