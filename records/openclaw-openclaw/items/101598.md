## Summary

The PR remains necessary and the latest head resolves the prior Windows child-only termination blocker by reusing the shared process-tree owner. The runtime fix is otherwise well-shaped, but the new public SDK functions are undocumented and need explicit maintainer approval; native Windows execution of the committed descendant-shutdown test is also still needed before merge.

## What This Changes

The PR adds first-error-wins stdout/stderr failure handling and process-tree shutdown to Microsoft Foundry device-code login, exposes three process-tree helpers through the existing plugin SDK process-runtime subpath, and adds mocked plus real-process regressions.

## Best Possible Solution

Keep the shared process-tree implementation and existing `process-runtime` subpath, explicitly approve and document the three-function plugin contract, then run the committed native Windows test to prove the Azure CLI descendant is gone before rejection or strengthen the shared shutdown contract if it fails.
