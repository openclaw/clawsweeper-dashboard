## Summary

Keep this PR open for maintainer review. The earlier merged prerequisite fixed the diagnosis, while this branch intentionally changes the Gateway readiness contract from fail-closed to degraded-ready for a verified, plugin-owned payload failure; that product and availability choice remains the central merge decision.

## What This Changes

The branch quarantines an enabled plugin whose installed payload fails static verification during startup, allows the Gateway to become ready, and exposes the configured-unavailable state through loader diagnostics, doctor, status, health, and documentation.

## Best Possible Solution

Adopt the bounded degrade-and-boot policy only if maintainers explicitly want Gateway readiness to represent availability of the core service rather than every configured plugin; retain the typed degraded status, pre-import quarantine, recovery-on-restart behavior, and existing fail-closed boundaries for ambiguous or non-plugin-owned failures.
