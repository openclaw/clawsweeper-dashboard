## Summary

This PR is still necessary: current `main` contains the earlier diagnostic-classification fix, while this branch adds the separate Gateway readiness policy that quarantines a known broken configured plugin and keeps other Gateway functions ready. The implementation has strong real-run evidence and no confirmed patch defect, but it intentionally changes the established fail-closed startup contract; the assigned feature owner should confirm that compatibility decision before merge.

## What This Changes

The branch introduces boot-local quarantine for configured plugins whose installed payload fails static verification, keeps the Gateway ready when ownership is known, and exposes the configured-unavailable state through loader, doctor, status, health, tests, and plugin documentation.

## Best Possible Solution

Land the bounded exact-root quarantine only after the assigned owner confirms that a known, owned plugin payload failure should make that plugin unavailable without making the Gateway unready; retain fail-closed handling for ownerless, pathless, ambiguous, structural-config, and state-migration failures.
