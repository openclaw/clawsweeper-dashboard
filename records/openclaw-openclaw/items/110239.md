## Summary

Keep this PR open for maintainer review: its real-run evidence and focused coverage strongly support the implementation, but changing gateway readiness from fail-closed to partial readiness for a configured unavailable plugin remains a product and operations contract decision.

## What This Changes

The branch quarantines enabled plugins with verified broken payloads before import, allows the gateway to boot, and reports the configured-unavailable state through health, status, and doctor.

## Best Possible Solution

Adopt and document one gateway-readiness contract: permit degraded boot only for a known configured-plugin verification failure, retain fail-closed behavior for unknown owners, invalid config, and state migrations, and make configured-unavailable state visible to operators; otherwise preserve the existing fail-closed contract and leave the canonical issue open for a different solution.
