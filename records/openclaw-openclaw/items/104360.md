## Summary

Keep open: the revised head fixes the earlier AgentSession clamp behavior, but a positive `maxRetryDelayMs` can still be bypassed when embedded failover independently authorizes a silent same-model retry for structured cooldowns up to 60 seconds. The submitted loopback test also does not prove this session-to-failover handoff in a real run.

## What This Changes

The PR preserves Anthropic HTTP status and Retry-After metadata on assistant errors, applies it to AgentSession retry delays and embedded same-model failover, and adds focused regression coverage.

## Best Possible Solution

Pass the existing provider `maxRetryDelayMs` into embedded failover and reject structured cooldowns above a positive cap, keeping zero unlimited; alternatively, centralize structured Retry-After retry ownership in AgentSession so one budget governs attempts and delay.
