## Summary

The transport-side metadata preservation is well targeted, but the new AgentSession delay helper reverses the existing `maxRetryDelayMs` contract: it shortens over-cap provider cooldowns and treats `0` as a zero-second cap instead of disabling the cap. This can retry Anthropic before the server permits, so the PR needs a narrow correctness repair and real post-fix retry proof before merge.

## What This Changes

Preserve Anthropic HTTP status and Retry-After metadata through transport errors so AgentSession and embedded-runner retry logic can honor provider cooldowns.

## Best Possible Solution

Keep the structured status and Retry-After transport plumbing, but make AgentSession decline auto-retry when a valid cooldown exceeds a positive cap, treat a zero cap as unlimited, and preserve the metadata for visible failover or terminal handling.
