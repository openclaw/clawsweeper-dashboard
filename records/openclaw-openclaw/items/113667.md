## What This Changes

This PR scopes Telegram’s persistent inbound-message dispatch dedupe key by numeric bot identity, leaves legacy unscoped claims unused, and documents the resulting V2 cutover behavior.

## System Context

Telegram inbound updates pass through the Telegram handler before agent dispatch. A persistent replay guard decides whether a message is new, a duplicate, or missing sufficient identity; that decision determines whether the user receives a reply.

## Architecture Diagram

  C --> D[Persistent replay guard]
  D --> E{Claim outcome}
  E -->|New bot-scoped claim| F[Agent dispatch and settlement]
  E -->|Duplicate claim| G[Suppress replay]
  E -->|Invalid identity| H[Process without persistent claim]

## Best Possible Solution

Adopt bot-scoped V2 replay claims as the sole runtime format only after the Telegram owner explicitly accepts the bounded V1-to-V2 duplicate-delivery trade-off and the branch is refreshed against current `main`.
