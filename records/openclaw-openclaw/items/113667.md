## Summary

This PR has a coherent fix and convincing real Telegram evidence, but it intentionally abandons still-valid unscoped persisted V1 dedupe claims on upgrade. That trades a bounded one-time duplicate at the V1/V2 boundary for preventing silent cross-bot message suppression, so it should remain open for an explicit Telegram owner decision rather than be auto-merged or closed.

## What This Changes

The PR changes Telegram’s persisted inbound-message replay key from account/chat/message coordinates to account/bot/chat/message coordinates, while bypassing persistent dedupe when the bot identity is unavailable.

## System Context

Telegram inbound updates enter the Telegram channel handler, which obtains the current bot identity and asks a persistent replay guard whether the message was already dispatched. A successful claim permits agent dispatch and records settlement; a duplicate suppresses the replay.

## Architecture Diagram

flowchart LR
  A[Telegram update] --> B[Telegram message handler]
  B --> C[Resolve numeric bot identity]
  C --> D[Persistent dispatch replay guard]
  D --> E{Claim outcome}
  E -->|New claim| F[Agent dispatch and settlement]
  E -->|Duplicate| G[Suppress replay]
  E -->|Identity invalid| H[Fail open without persistence]

## Best Possible Solution

Keep V2 as the sole runtime format and land only after the Telegram owner explicitly accepts the documented upgrade behavior: legacy unscoped replay entries may no longer suppress a redelivery, while bot-scoped V2 entries preserve normal same-bot replay protection.
