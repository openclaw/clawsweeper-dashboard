## Summary

## What This Changes

This PR changes Telegram’s persistent dispatch dedupe from account/chat/message identity to account/bot/chat/message identity, while leaving legacy rows quarantined so they cannot suppress runtime V2 dispatches.

## System Context

Telegram inbound handlers consult a persistent replay-dedupe guard before dispatching a received message, then settle the claim after the dispatch outcome. This PR supplies the bot identity to that guard so persisted state reused by another bot cannot cause a fresh inbound message to be discarded.
