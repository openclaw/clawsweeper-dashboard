- `impact:session-state`: The requested task/no-stickiness modes and pool state would change how auth profile choices are pinned or rotated across sessions and worker tasks.
- `impact:auth-provider`: The request directly affects provider auth profile selection, OAuth/API-key routing, cooldowns, quota-aware provider choice, and fallback behavior.

## Summary

Keep open: current main and v2026.6.11 still provide auth profile ordering, cooldown/last-used rotation, bounded same-provider retries, and session pinning, but not the requested opt-in provider-profile pool routing contract with explicit strategies, in-flight/concurrency limits, quota/bucket state, weights, or task/no-stickiness modes.

## What This Changes

Requests an opt-in provider-profile pool routing layer for multi-account OAuth/API-key workloads, starting with google-gemini-cli and generalizing to other providers.

## Best Possible Solution

Define an additive generic provider/auth-profile pool-routing contract that preserves current session-sticky defaults, reuses existing cooldown state where appropriate, and exposes observable status/probe state before adding quota, bucket, concurrency, and weighting strategies.
