## Summary

Keep open: current main supports auth profile ordering, cooldown state, session pinning, and bounded same-provider rotation, but it does not provide the requested opt-in pool-routing contract with explicit strategies, in-flight limits, quota or bucket state, and pool observability.

## What This Changes

The issue requests a provider-profile routing layer for multi-account OAuth/API pools with configurable strategies, task-oriented stickiness, concurrency caps, quota/cooldown behavior, and status visibility.

## Best Possible Solution

Define a maintainer-approved, additive provider/auth-profile routing contract that preserves session-sticky defaults, reuses current auth profile/cooldown state, and reconciles the narrower key-pool and same-provider rotation issues before adding new config or status fields.
