## Summary

Keep open: current main still has auth profile order, round-robin-by-last-used selection, cooldown/disabled state, bounded same-provider rotation, cooldown probes, and provider usage status, but not the requested opt-in provider-profile pool routing contract with explicit strategies, task/no-stickiness modes, in-flight/concurrency caps, weights, quota/bucket metadata, or pool-state CLI/status output.

## What This Changes

Request an opt-in provider-profile pool routing layer for multi-account OAuth/API-key/provider endpoint workloads, starting with google-gemini-cli.

## Best Possible Solution

Define a minimal additive pool-routing contract that preserves current session-sticky defaults and reuses existing auth profiles/cooldowns while adding observable strategy and state semantics only after maintainers choose the first supported scope.
