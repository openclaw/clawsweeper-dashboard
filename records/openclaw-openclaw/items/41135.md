## Summary

Keep open: current main and the latest release still provide auth ordering, last-used/cooldown rotation, session pinning, and bounded same-provider retries, but not the requested opt-in provider-profile pool routing layer with explicit strategies, per-profile concurrency/in-flight state, quota/bucket signals, or task/no-stickiness modes.

## What This Changes

The issue requests an opt-in core provider-profile pool routing layer for multi-account OAuth/API-key and endpoint pools, starting with google-gemini-cli.

## Best Possible Solution

Define an additive generic provider/auth-profile routing contract that preserves session-sticky defaults while integrating provider-owned quota signals, persisted state, status JSON, docs, and upgrade-safe config handling.
