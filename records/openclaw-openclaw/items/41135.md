## Summary

Keep open: current main has auth ordering, cooldown-aware profile rotation, same-provider retry caps, and session pinning, but it still does not provide the requested opt-in provider-profile pool routing contract with explicit strategies, task/no-stickiness modes, in-flight/concurrency limits, weights, quota/bucket state, or routing status inspection.

## What This Changes

Request an opt-in provider-profile routing layer for multi-account OAuth/API-key and endpoint pools, starting with google-gemini-cli batch workloads.

## Best Possible Solution

Define a minimal additive provider/auth-profile pool routing contract that preserves session-sticky defaults, exposes observable state, and phases quota, bucket, weight, and concurrency semantics behind explicit maintainer-approved config.
