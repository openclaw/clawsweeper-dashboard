## Summary

Keep open: current main and the latest stable release still have auth ordering, session stickiness, cooldowns, and bounded same-provider retry, but not the requested opt-in provider-profile pool routing layer for batch/worker workloads.

## What This Changes

Request adds configurable provider-profile pool routing policies for multi-account OAuth/API-key or endpoint pools, including batch-oriented stickiness, per-profile concurrency, in-flight state, cooldown-aware selection, and status/CLI visibility.

## Best Possible Solution

Define an additive generic provider/auth-profile routing contract that preserves session-sticky defaults while integrating provider-owned quota signals, persisted pool state, status JSON, docs, and upgrade-safe config handling.
