## Summary

Keep open: current main and the latest stable release still provide auth profile ordering, cooldown/failure state, session pinning, and bounded same-provider rotation, but not the requested opt-in provider-profile pool routing contract with explicit strategies, concurrency/in-flight limits, task/no-stickiness modes, quota/bucket state, or pool observability. This is a product/API design item across provider routing, auth config, fallback behavior, and session state, so it should stay in maintainer review rather than become an automatic fix job.

## What This Changes

The issue requests an opt-in provider-profile routing layer that can distribute provider calls across multiple OAuth/API profiles or endpoints with explicit pool strategies, concurrency limits, cooldown/quota awareness, and observability.

## Best Possible Solution

Define an additive maintainer-approved provider/auth-profile routing contract that preserves session-sticky defaults, reuses current auth profile/cooldown state, and reconciles narrower follow-ups such as https://github.com/openclaw/openclaw/issues/28847 and https://github.com/openclaw/openclaw/issues/79604 before adding new config or status fields.
