## Summary

Keep open: current main and v2026.6.11 still provide auth order, cooldowns, API-key rotation, bounded same-provider profile rotations, and session profile pinning, but not the requested opt-in provider-profile pool routing layer with explicit strategies, in-flight/concurrency limits, quota/bucket state, weights, or task/no-stickiness modes.

## What This Changes

The issue requests an opt-in provider-profile routing policy layer for multi-account OAuth/API-key pools, starting with Gemini CLI batch workloads.

## Best Possible Solution

Define an additive generic provider/auth-profile routing contract that preserves session-sticky defaults while integrating provider-owned quota signals, observable state, status JSON, docs, and upgrade-safe config handling.
