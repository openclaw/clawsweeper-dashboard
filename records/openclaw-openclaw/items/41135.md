## Summary

Keep open: current main and the latest stable release still provide auth profile order, cooldown/failure state, session pinning, bounded same-provider rotation, and status/probe surfaces, but not the requested opt-in provider-profile pool routing contract with explicit strategies, task/no-stickiness modes, in-flight/concurrency limits, quota/bucket state, weights, or pool observability.

## What This Changes

The issue requests an opt-in provider-profile routing layer for multi-account OAuth/API pools, starting with google-gemini-cli, with configurable pool strategies and routing observability.

## Best Possible Solution

Define a minimal additive core provider/auth-profile pool-routing contract that preserves session-sticky defaults, reuses current cooldown state, and reconciles #28847 and #79604 before adding config, status, or doctor behavior.
