## Summary

Keep open: current main and v2026.6.11 support provider auth order, cooldowns, last-used ordering, flat API-key rotation, and bounded same-provider retries, but they do not provide the requested opt-in provider-profile pool routing contract with explicit strategies, task/no-stickiness modes, in-flight/concurrency limits, weights, or quota/bucket state.

## What This Changes

Add an opt-in provider-profile routing layer for distributing batch or worker requests across multiple OAuth/API profiles for the same provider, starting with google-gemini-cli.

## Best Possible Solution

Define an additive generic provider/auth-profile pool routing contract that preserves session-sticky defaults, starts with one observable opt-in strategy, and aligns provider-owned quota signals, status JSON, docs, tests, and upgrade-safe config handling.
