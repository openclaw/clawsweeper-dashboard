## Summary

Keep open: current main and v2026.6.11 still provide auth profile order, round-robin-by-last-used selection, cooldown/disabled state, bounded same-provider rotation, and cooldown probes, but not the requested opt-in provider-profile pool routing layer with explicit strategies, task/no-stickiness modes, in-flight/concurrency caps, weights, quota/bucket state, or pool-state CLI/status output.

## What This Changes

The issue requests an opt-in provider-profile pool routing layer with explicit strategies, profile state, concurrency limits, and observability for multi-account provider workloads.

## Best Possible Solution

Define an additive generic provider/auth-profile pool-routing contract that preserves session-sticky defaults while integrating provider-owned quota signals, persisted state, status JSON, docs, and upgrade-safe config handling.
