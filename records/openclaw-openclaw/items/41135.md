## Summary

Keep open: current main and v2026.6.11 still provide auth profile ordering, cooldown-aware selection, session pinning, and bounded same-provider retries, but not the requested opt-in provider-profile pool routing layer with explicit strategies, task/no stickiness, per-profile concurrency/in-flight state, weights, quota/bucket state, or pool-status visibility.

## What This Changes

The issue requests explicit provider-profile routing policies for multi-account OAuth/API-key pools, starting with Gemini CLI and generalizing to other providers/endpoints.

## Best Possible Solution

Define an additive generic provider/auth-profile routing contract that preserves session-sticky defaults while integrating provider-owned quota signals, persisted state, status JSON, docs, and upgrade-safe config handling.
