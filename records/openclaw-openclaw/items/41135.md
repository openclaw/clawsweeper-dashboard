## Summary

Keep open: current main and v2026.6.11 still provide auth profile order, cooldown/last-used rotation, bounded same-provider retries, and session pinning, but not the requested opt-in provider-profile pool routing layer with explicit strategies, in-flight/concurrency limits, quota/bucket state, weights, or task/no-stickiness modes.

## What This Changes

Request an opt-in provider-profile pool routing policy layer for distributing provider requests across multiple OAuth/API profiles with strategies, concurrency, quota/failure state, and observability.

## Best Possible Solution

Define an additive generic provider/auth-profile routing contract that preserves session-sticky defaults while integrating provider-owned quota signals, persisted state, status JSON, docs, and upgrade-safe config handling.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 expose order/cooldown/lastUsed/session-pinning behavior but not pool routing config or pool state. I did not run a live Gemini OAuth pool workload.

## Solution Assessment

Unclear until maintainers choose the contract; the capability gap is real, but the illustrative config shape and strategy list are not yet proven to be the best implementation. The safer path is an additive generic routing policy that keeps current defaults unchanged.
