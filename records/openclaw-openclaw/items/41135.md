## Summary

Keep open: current main has auth profile ordering, cooldown-aware rotation, session pinning, and bounded same-provider retry behavior, but it still lacks the requested opt-in provider-profile pool routing layer with explicit strategies, worker/task stickiness controls, in-flight/concurrency caps, weights, quota/bucket state, and status/probe observability.

## What This Changes

The issue requests first-class provider-profile pool routing so worker and batch runs can choose auth profiles by policy instead of relying on provider-wide auth order and reactive cooldowns.

## Best Possible Solution

Keep this as the canonical product/design tracker and ship an additive, opt-in pool-routing contract that preserves current auth.order/session defaults while unifying narrower bucket, rotation, and alias-profile routing work.
