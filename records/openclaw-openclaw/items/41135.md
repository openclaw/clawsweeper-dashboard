## Summary

Keep open: current main and v2026.6.11 still provide auth order, per-profile cooldown state, API-key rotation, bounded same-provider profile rotations, and probe/status visibility, but not the requested opt-in provider-profile pool routing contract with strategies, task/no-stickiness modes, per-profile in-flight/concurrency caps, weights, quota/bucket state, or pool-state CLI/status output.

## What This Changes

The issue requests an OpenClaw-native provider-profile routing layer for multi-account OAuth/API-key pools, starting with google-gemini-cli batch workloads.

## Best Possible Solution

Define a minimal additive provider/auth-profile pool-routing contract that preserves session-sticky defaults while integrating provider-owned quota signals, observable pool state, status JSON, docs, and upgrade-safe config handling.
