## Summary

Keep open: current main and latest release have auth ordering, cooldowns, last-used rotation, bounded same-provider retries, and session pinning, but not the requested opt-in provider-profile pool routing contract with explicit strategies, in-flight/concurrency limits, quota/bucket state, weights, or task/no-stickiness modes.

## What This Changes

Issue 41135 requests an OpenClaw-native provider-profile pool routing layer for multi-account OAuth/API-key and endpoint pools.

## Best Possible Solution

Define an additive generic provider/auth-profile routing contract that preserves session-sticky defaults while integrating provider-owned quota signals, persisted state, status JSON, docs, and upgrade-safe config handling.
