## Summary

Keep open: current main and v2026.6.11 still provide auth ordering, cooldowns, same-provider rotation caps, and generic API-key rotation, but not the requested opt-in provider-profile pool routing contract with explicit strategies, in-flight/concurrency limits, quota/bucket state, weights, or task/no-stickiness modes.

## What This Changes

Add an opt-in provider-profile routing layer for multi-account OAuth/API-key pools with configurable strategies, concurrency limits, cooldown behavior, and observable routing state.

## Best Possible Solution

Define an additive generic provider/auth-profile routing contract that preserves current session-sticky defaults while integrating provider-owned quota signals, persisted state, status JSON, docs, and upgrade-safe config handling.
