## Summary

Keep open: current main and the latest stable release still provide auth ordering, cooldowns, session stickiness, and bounded same-provider retry, but not the requested opt-in provider-profile pool routing layer for batch/worker workloads.

## What This Changes

The issue requests native provider-profile pool routing policies for multi-account OAuth/API pools, starting with google-gemini-cli, including strategies, per-profile concurrency state, quota/failure awareness, observability, and CLI/status inspection.

## Best Possible Solution

Define an additive generic provider/auth-profile routing contract that preserves session-sticky defaults while integrating provider-owned quota signals, persisted pool state, status JSON, docs, and upgrade-safe config handling.
