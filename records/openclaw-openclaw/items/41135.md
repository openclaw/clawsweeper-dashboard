## Summary

Keep open: current main and the latest release still only provide auth profile order, cooldown/last-used rotation, bounded same-provider retries, and session/profile overrides, not the requested opt-in provider-profile pool routing layer with explicit strategies, in-flight/concurrency limits, quota/bucket state, weights, or task/no-stickiness modes.

## What This Changes

The issue requests an opt-in provider-profile routing layer for multi-account provider pools with explicit strategies, concurrency limits, cooldown/failure awareness, and observability.

## Best Possible Solution

Define an additive generic provider/auth-profile routing contract that preserves session-sticky defaults while integrating provider-owned quota signals, persisted state, status JSON, docs, and upgrade-safe config handling.
