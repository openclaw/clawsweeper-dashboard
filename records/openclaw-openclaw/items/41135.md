## Label Justifications

- `P2`: This is a meaningful provider/auth routing improvement for batch and multi-account users, but it is not a core outage, data-loss event, or security emergency.
- `impact:auth-provider`: The request directly affects provider auth profile selection, OAuth/API-key routing, cooldowns, quota-aware provider choice, and fallback behavior.
- `impact:session-state`: The requested task/no-stickiness modes and pool selection state would change how auth profile choices are pinned or rotated across sessions and worker tasks.

## Summary

Keep open: current main and latest stable release still provide auth ordering, cooldown/last-used rotation, bounded same-provider retries, and session pinning, but not the requested opt-in provider-profile pool routing layer with explicit strategies, in-flight/concurrency limits, quota/bucket state, weights, or task/no-stickiness modes.

## What This Changes

Requested an OpenClaw-native provider-profile pool routing layer for multi-account OAuth/API providers, starting with google-gemini-cli, with explicit strategy, config, status, and stickiness semantics.

## Best Possible Solution

Define an additive generic provider/auth-profile routing contract that preserves session-sticky defaults while integrating provider-owned quota signals, persisted state, status JSON, docs, and upgrade-safe config handling.
