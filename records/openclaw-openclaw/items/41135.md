## Summary

Keep open: current main and v2026.6.11 have auth profile order, cooldown, session pinning, and bounded same-provider rotation, but not the requested opt-in provider-profile pool routing contract with strategies, per-profile concurrency, in-flight state, quota/bucket state, weights, or task/no-stickiness modes.

## What This Changes

Add an opt-in provider-profile pool routing layer for multi-account OAuth/API-key workloads, starting with google-gemini-cli, with explicit routing policy, state, and observability controls.

## Best Possible Solution

Define an additive generic provider/auth-profile pool routing contract that preserves session-sticky defaults while integrating provider-owned quota signals, persisted state, status JSON, docs, and upgrade-safe config handling.
