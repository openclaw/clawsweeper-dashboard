## Summary

Keep open: current main and v2026.6.11 still provide auth ordering, cooldown demotion, last-used round-robin, and bounded same-provider retries, but not the requested opt-in provider-profile pool routing layer with explicit strategies, per-profile in-flight/concurrency, weights, quota/bucket state, or task/no-stickiness modes.

## What This Changes

Request an opt-in provider-profile pool routing layer for multi-account OAuth/API profiles with configurable strategies, concurrency/quota state, and status/CLI observability.

## Best Possible Solution

Define an additive generic provider/auth-profile routing contract that preserves current session-sticky defaults, starts with minimal observable pool state, and leaves advanced quota, bucket, and weighting semantics phased behind explicit maintainer direction.
