## Summary

Keep this PR open for maintainer security review. The patch has focused durable SQLite coverage and no discrete correctness defect found, but it changes the security contract by allowing previously accepted monotonic metadata to continue rejecting lower-sequence feeds after the signing key is no longer trusted; that revocation and recovery policy needs an explicit maintainer decision before merge.

## What This Changes

The PR compares newly verified signed feeds with persisted accepted monotonic metadata across signing-key rotation and restores that metadata when SQLite snapshots are read.

## Best Possible Solution

Define and document the retained-monotonic-authority and emergency key-revocation recovery contract, then keep the narrow SQLite-backed rotation fix if that contract explicitly permits prior authenticated metadata to reject rollback candidates.
