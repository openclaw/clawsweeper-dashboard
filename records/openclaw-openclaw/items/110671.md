## Summary

This PR demonstrates the unbounded `brew --prefix` hang, but the current patch applies its 15-second limit to every DNS CLI subprocess and still relies on the default termination signal. The focused follow-up PR is related but remains open and proof-incomplete, so this PR should stay open for a bounded repair rather than be superseded now.

## What This Changes

The branch adds a 15-second timeout to the DNS CLI synchronous subprocess helper and `sudo tee` fallback, plus a regression test asserting the timeout option is supplied.

## Best Possible Solution

Keep the shared helper unbounded by default, opt in to a 15-second `SIGKILL`-backed deadline only for probe operations such as `brew --prefix`, and test both the bounded probe and an intentionally unbounded setup operation.

## Solution Assessment

No. A deadline is the right fix for the demonstrated probe, but placing it in the shared helper also bounds legitimate long-running setup operations; an opt-in probe timeout is the narrower maintainable solution.
