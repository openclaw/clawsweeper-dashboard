## Summary

Keep this PR open, but do not merge it as written: Node's synchronous timeout sends SIGTERM and still waits for the child to exit, so a process that ignores SIGTERM can continue to block the CLI—the failure mode this PR says it eliminates.

## What This Changes

Adds a 15-second `spawnSync` timeout to DNS CLI subprocess calls and a new unit test that asserts the timeout option is passed.

## Best Possible Solution

Use a bounded asynchronous subprocess path that terminates on timeout, escalates after a short grace period, and proves the CLI returns for a child that ignores SIGTERM while preserving valid slow DNS operations.
