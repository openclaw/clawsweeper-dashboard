## What This Changes

Classifies authenticated Telegram 400/403 unreachable-recipient errors as terminal ingress failures and rethrows failed pairing replies so queued inbound updates are dead-lettered instead of retried.

## System Context

Telegram polling places inbound updates into an ingress queue, whose drain dispatches the update and either retries or dead-letters failures. Pairing-mode DMs send a reply during dispatch; this PR makes a permanent Telegram reply rejection reach the drain's terminal-failure decision.

## Best Possible Solution

Keep the narrow error-code-gated classifier and pairing-error propagation, then rebase cleanly, rotate and redact the credential, and publish redacted live gateway output showing a blocked-recipient update reaches the failed ingress queue state; include a restart/replay check for the durable queue path.
