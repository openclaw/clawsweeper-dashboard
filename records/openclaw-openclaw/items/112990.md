## Summary

The remaining merge blocker is real after-fix behavior proof: the PR body shows injected-test output, not a redacted run through an actual Telegram ingress failure and durable queue.

## What This Changes

The PR adds a `recipient-unreachable` Telegram ingress failure reason for matching Bot API 400/403 errors and tests that affected spooled updates are dead-lettered instead of retried.

## System Context

Telegram's plugin persists inbound updates in a durable ingress queue before dispatching them into agent and pairing flows. The ingress monitor consults the plugin's terminal-failure classifier to decide whether a failed update should be retried or recorded as a dead letter.
