## Summary

Keep this PR open for normal merge review: it remains necessary because current main retries and logs pairing-reply delivery failures rather than surfacing confirmed unreachable-recipient errors to the ingress dead-letter path, while this narrowed branch adds that missing propagation with focused regression coverage and credible real gateway proof.

## What This Changes

The PR marks confirmed Telegram 400/403 blocked, kicked, or missing-recipient failures as terminal ingress errors and rethrows failed pairing replies so the queue dead-letters the affected update instead of retrying it.

## System Context

Telegram polling stores inbound updates in the shared ingress queue before dispatching them through the Telegram plugin. A direct-message pairing reply can fail during that dispatch; the plugin must distinguish a permanent recipient rejection from a retryable failure so the generic queue can dead-letter only the former.
