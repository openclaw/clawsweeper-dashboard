## Summary

Keep this PR open as the candidate fix for the linked Telegram retry bug. The terminal classification is directionally correct, but matching broad message text without confirming a Telegram API failure can dead-letter unrelated dispatch errors, and the PR body lacks inspectable after-fix live proof.

## What This Changes

The PR adds a Telegram ingress failure category intended to dead-letter spooled updates immediately when a bot cannot reach a blocked, removed, or nonexistent recipient.

## System Context

Telegram updates enter OpenClaw through the channel ingress spool and are drained into the agent/pairing flow. Failures are either returned to the retry queue or marked terminal and dead-lettered, so the classification determines whether an incoming user event is retried or discarded.

## Best Possible Solution

Recognize recipient-unreachable failures only when the matching message is tied to a confirmed Telegram API permanent response, add negative coverage for lookalike non-Telegram errors, and attach redacted live ingress-drain evidence showing immediate dead-lettering.
