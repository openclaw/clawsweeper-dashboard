## Label Justifications

- `P0`: First-time macOS users with supported providers outside Anthropic/OpenAI/Google cannot complete guided provider setup in-product and must leave onboarding for technical setup paths.
- `impact:auth-provider`: The issue concerns provider auth choice discovery, API-key activation, starter model selection, and credential/config persistence.
- `impact:ux-release-blocker`: The affected flow is first-run macOS onboarding for otherwise supported providers, and recovery currently requires leaving the app-guided setup path.
- `maturity:stable`: The issue touches M4 Stable Gateway runtime/setup APIs and macOS Gateway host surfaces, plus CLI onboarding/auth choices tracked in the stable taxonomy.

## Summary

Keep open: current main still limits the macOS manual API-key picker and Gateway manual activation to Anthropic, OpenAI, and Google, and the live issue has a protected `maintainer` label for a new Gateway/macOS onboarding product surface.

## What This Changes

Request to load the macOS Connect your AI manual API-key provider picker from the Gateway text-inference provider auth catalog instead of a hardcoded Anthropic/OpenAI/Google list.

## Best Possible Solution

Add an additive Gateway setup catalog contract that returns text-inference API-key choices with provider-owned labels, hints, auth method identifiers, starter-model activation, and dynamic macOS rendering without duplicating provider defaults in Swift.

- **Implement catalog-backed macOS setup (recommended):** Extend the Gateway setup RPCs additively and render provider-owned text-inference API-key choices in the macOS app.
- **Keep the three-provider picker:** Leave app onboarding limited to Anthropic, OpenAI, and Google while other providers use CLI or plugin setup paths.
- **Split protocol design first:** Keep this issue open for product direction and open a narrower Gateway setup-contract design task before implementation.

## Solution Assessment

Yes directionally, but the final API shape needs maintainer approval. Reusing provider-owned catalog/auth metadata through additive Crestodian setup RPCs is the maintainable solution; expanding the Swift enum would preserve the duplicate source of truth.
