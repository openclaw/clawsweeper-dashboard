- `P0`: First-time macOS users with supported providers outside the hardcoded three cannot complete guided in-product provider setup and must leave onboarding for technical setup paths.

- `maturity:stable`: The affected setup path overlaps the M4 Stable `macos-gateway-host` surface and the M4 CLI onboarding/auth setup taxonomy surface.

## Summary

Keep open: current main still hardcodes the macOS manual API-key picker and Gateway manual activation to Anthropic, OpenAI, and Google, while this protected maintainer-labeled issue asks for a new catalog-backed Gateway/macOS onboarding surface.

## What This Changes

Load the macOS Connect your AI manual API-key provider picker from Gateway/provider setup catalog choices instead of a fixed three-provider app enum.

## Best Possible Solution

Add an additive catalog-backed setup choice contract to `crestodian.setup.detect` and `crestodian.setup.activate`, render provider-owned text-inference API-key choices dynamically in macOS, and keep provider-specific auth/default-model behavior in provider plugins.
