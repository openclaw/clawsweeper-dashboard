## Summary

Keep open: current main still hardcodes the macOS manual API-key picker to Anthropic, OpenAI, and Google, while the existing provider setup flow already has plugin/catalog-backed text-inference auth choices. The protected maintainer label and new Gateway/macOS product surface mean this should not be auto-closed or queued as an unsponsored repair.

## What This Changes

Load the macOS Connect your AI manual API-key provider picker from Gateway/provider setup catalog data instead of a three-provider Swift/backend constant.

## Best Possible Solution

Add an additive Gateway setup-provider catalog built from provider-owned text-inference API-key auth choices, render that in macOS, and route activation through provider-owned auth/default-model behavior with live verification before persisting config.
