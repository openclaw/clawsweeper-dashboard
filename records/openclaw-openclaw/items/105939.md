## Summary

The exact head still has a blocking output-capture race: the inherited-pipe helper attaches consuming `data` listeners before the real readers, so fast commands can silently lose initial output. The earlier stream-error concern appears addressed, but this protected PR still needs the race fixed, real cross-platform execution proof, and owner approval of the dependency tradeoff.

## What This Changes

The PR pins Execa 9.6.1 as a root runtime dependency, rebuilds the canonical process wrapper around it, moves inherited-pipe cleanup into `src/process/child-process.ts`, migrates agent session exec plus bash/find/grep callers, narrows the plugin SDK process barrel, and rewrites focused tests.

## Best Possible Solution

Keep the Execa-backed canonical wrapper, but make inherited-pipe cleanup non-consuming until real output readers are attached, add fast-output regressions for the migrated caller shapes, and require redacted Linux and Windows live proof before accepting the new root dependency and lifecycle semantics.
