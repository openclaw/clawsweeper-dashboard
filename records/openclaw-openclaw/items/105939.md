## Summary

Keep this PR open for repair: the latest head appears to address the earlier output-ordering and core execution findings, but the replacement child-process lifecycle helper still drops the old stdout/stderr error guards, leaving local bash execution vulnerable to an uncaught stream error that can terminate the agent runtime.

## What This Changes

The PR adds Execa 9.6.1 as the core execution dependency, rebuilds the canonical process wrapper around it, centralizes inherited-pipe cleanup, and migrates selected agent exec, bash, find, and grep paths.

## Best Possible Solution

Restore the old stream-error safety contract in the shared child-process lifecycle layer, retain caller-specific error reporting where needed, and add a focused regression test that emits stdout and stderr errors after launch before merging the Execa migration.

No, not at the current head. Adopting one canonical Execa-backed wrapper is a maintainable direction, but the shared replacement should preserve the previous stream-error contract rather than leaving each migrated caller vulnerable or requiring scattered guards.
