## Label Justifications

- `P1`: The shared process refactor can lose agent command output or crash the core runtime on real stream failures.
- `merge-risk: 🚨 compatibility`: Merging changes shared subprocess output, exit, timeout, abort, Windows, and plugin-facing behavior that existing callers rely on.
- `merge-risk: 🚨 availability`: The missing bash stream error guards can turn a subprocess pipe failure into a process-terminating uncaught error.

## Summary

The Execa refactor belongs at the canonical process boundary, but the current head still installs the descendant-pipe watcher before real readers and lacks bash stream error guards. It can therefore lose fast command output or crash the runtime, so this PR and its linked issue should remain open until those blockers are fixed.

## What This Changes

The PR pins Execa 9.6.1, rebuilds the canonical process wrapper around it, adds bounded descendant-pipe release handling, narrows the plugin SDK process exports, and migrates agent exec, bash, find, and grep callers.

## Best Possible Solution

Keep the Execa-based canonical owner boundary, but register descendant-pipe cleanup only after each caller's output consumers and error guards, preserve every existing exit, timeout, abort, output, and Windows contract, and rerun exact-head focused and CI validation.
