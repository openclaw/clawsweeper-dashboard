## Summary

The latest head still has the previously reported P1 stream-order defect: the descendant-pipe watcher starts consuming output before the real readers are attached. The PR also still lacks final-head real Linux and Windows lifecycle proof, so it is not ready to merge despite substantial automated coverage.

## What This Changes

The PR adds Execa 9.6.1 as the root process runtime, rebuilds the canonical execution wrapper around it, centralizes descendant-pipe cleanup, migrates several agent command callers, and narrows the plugin SDK process exports.

## Best Possible Solution

Make descendant-pipe observation non-consuming or attach it only after every real output consumer, add an immediate-output regression covering all migrated caller shapes, and provide redacted final-head Linux and Windows lifecycle transcripts before merge.
