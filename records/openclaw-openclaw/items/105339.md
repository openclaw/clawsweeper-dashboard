## Summary

This PR should remain open because it bounds retained session-history state only after the complete transcript has already been loaded and projected, leaving reconnect and refresh peak memory proportional to transcript size. The proposed mitigation is useful, but it does not yet establish the claimed prevention of constrained-host OOM failures.

## What This Changes

## Best Possible Solution

Bound default session-history reads end-to-end for file and SQLite storage before projection, preserve inexpensive total and sequence metadata with exact cursor semantics, and reserve full materialization for explicit historical pages.
