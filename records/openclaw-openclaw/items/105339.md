## Summary

Keep open for one explicit product-contract decision: the implementation and exact-head Gateway proof support bounding memory, but changing no-limit HTTP/SSE history from all projected messages to a 500-message recent window is client-visible compatibility policy rather than a purely internal fix.

Likely related people: Gustavo Madeira Santana appears connected to the session-history endpoint’s introduction with high confidence; Tak Hoffman is a medium-confidence routing candidate from subsequent session-management work.

## What This Changes

Caps unpaginated Gateway session-history initialization, refresh, and incremental SSE state to the newest 500 projected messages while retaining explicit cursor pagination and adding regression coverage.

## Best Possible Solution

Adopt a maintainer-approved bounded default for unpaginated history, preserve complete retrieval through explicit cursor pagination, and make the bounded-window contract discoverable to Gateway clients before release.
