## Summary

The implementation appears correct for steady-state retained-history growth and prior review defects are fixed, but merge should wait for inspectable real Gateway proof and an owner decision on whether full-read peak memory must be addressed in the same change.

## What This Changes

The PR caps unpaginated live Gateway session-history state at the newest 500 projected messages during initialization, inline appends, and refresh while preserving explicit limit/cursor pages and adding regression tests.

## Best Possible Solution

Keep the single bounded live-state path, provide inspectable authenticated Gateway proof, and either bound unpaginated transcript reads before projection or explicitly track peak full-read memory as separate owner-approved work.
