## Label Justifications

- `P2`: This is a real Gateway memory and availability bug with a focused surface, but it requires long-running or unusually large sessions.
- `merge-risk: 🚨 compatibility`: The PR changes existing unpaginated history behavior from full retained history to a fixed 500-message window.

## Summary

Keep this PR open, but do not merge the latest head yet: it bounds the retained projected array, while initialization and refresh still fully read and materialize the transcript before trimming, leaving the reported peak-memory/OOM path unresolved. The supplied retained-count output does not prove that source-read boundary on an exact-head Gateway run.

## What This Changes

The PR limits unpaginated Gateway session-history snapshots to the newest 500 projected messages and adds tests for construction, append, refresh, and explicit pagination behavior.

## Best Possible Solution

Move the recent-window limit into the transcript-reader/storage boundary, preserve absolute sequence and cursor semantics, then feed only that bounded raw window into projection while leaving explicit limit/cursor pages exact; prove initialization, append, refresh, and older-page retrieval through an authenticated exact-head Gateway run with peak-memory measurements.
