## Summary

Keep open, but the patch should not merge as written: it treats permanent quota/billing exhaustion as temporary throttling, so the linked failure can still fail while making `openclaw memory index` wait roughly 90 seconds first.

Likely related people
- `@mushuiyu886` — high-confidence adjacent owner from recent embedding-batch splitting work.
- `@TurboTheTurtle` — medium-confidence recent contributor across memory/provider reliability work.

## What This Changes

The PR gives memory-index embedding batches a 30-second exponential backoff and 120-second cap when error text resembles a rate-limit response.

## Best Possible Solution

Carry structured retry semantics or a bounded retry-after hint from the provider adapter into memory-core, retry only confirmed transient throttling, fail permanent quota/billing errors promptly, keep waits cancellable, and prove the behavior with both focused tests and a redacted live indexing run.
