## Summary

Keep this PR open, but do not merge the current patch: `structuredClone` cannot copy the function-valued handlers stored throughout the plugin registry, so transaction creation can throw before later plugins register. ([raw.githubusercontent.com](https://raw.githubusercontent.com/openclaw/openclaw/main/src/plugins/registry-types.ts))

## What This Changes

The PR replaces the plugin registry’s shallow transaction snapshot with `structuredClone` and adds a rollback test that mutates a hosted-media resolver record.

## Best Possible Solution

Keep runtime callbacks and provider objects by identity, make registration operations append-only or immutable where possible, and clone only the specific mutable plain-data fields proven to cross the rollback boundary.

Yes. Create a transaction over a registry containing any function-valued resolver or handler; the proposed `structuredClone(registry)` throws before returning the transaction. ([raw.githubusercontent.com](https://raw.githubusercontent.com/openclaw/openclaw/main/src/plugins/registry-types.ts))

## Solution Assessment

No. The rollback concern deserves investigation, but cloning the callback-heavy runtime registry wholesale is incompatible with its data model; the narrow fix is targeted immutable or field-level snapshotting.
