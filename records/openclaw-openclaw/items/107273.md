## Summary

The prior blocking finding remains unchanged at the reviewed head: the proposed clone mechanism cannot snapshot the callback-bearing plugin registry, so the transaction can fail before rollback begins. The PR also still lacks after-fix proof from a real plugin-loading setup.

## What This Changes

The PR replaces the plugin registry transaction’s shallow snapshot with `structuredClone` and adds a rollback regression test for an in-place hosted-media resolver record mutation.

## Best Possible Solution

Keep callback-bearing registration objects by reference while independently copying the mutable registry structures and deeply copying the specific mutable data records, especially `PluginRecord` and its nested arrays; add coverage using an already-populated mixed registry and prove both successful registration and failed-registration rollback in a real plugin load.

No. Deep isolation is needed, but cloning the entire heterogeneous registry is the wrong shape because runtime registrations intentionally contain functions; a targeted function-preserving snapshot is narrower and compatible.
