- `impact:auth-provider`: The affected surface is provider request shaping and model route usability for custom `api: "openai-responses"` configurations.

## Summary

Keep open: current main and the latest release still synthesize `status: "completed"` on replayed OpenAI Responses assistant message items, and this report provides concrete strict-endpoint 400 logs plus a local after-sanitization success signal.

## What This Changes

The issue asks OpenClaw to stop sending replayed `input[].status` fields, or otherwise provide a compatibility path, for strict custom `api: "openai-responses"` providers.

## Best Possible Solution

Add a narrow Responses input compatibility sanitizer at the custom/proxy or store-disabled payload boundary that removes output-only replay fields such as `status` without adding a new config option, with regression coverage for the managed and shared Responses builders.
