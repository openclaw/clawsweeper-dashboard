This PR should remain open: it fixes a real loose-string validation bug, but the proposed integer parser also rejects fractional coordinates allowed by the current Browser schema, CLI, and execution backends. A blocking compatibility finding and missing real-browser proof prevent merge.

The PR changes browser `clickCoords` x/y normalization from loose non-negative finite-number coercion to strict non-negative integer parsing, adds loose-token regression tests, and removes the unused coercion helper.

## Best Possible Solution

Add the narrowest browser-owned decimal-only finite-number route parser that accepts finite numeric values and ordinary decimal strings, rejects hexadecimal and scientific-notation strings, and then applies the existing non-negative coordinate validation.
