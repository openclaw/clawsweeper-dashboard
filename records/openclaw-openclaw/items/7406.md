## Summary

Keep open. Current main still learns Telegram forum topic names as `TopicName` but does not propagate them into the generic `ThreadLabel`/display-name path, and the open closing PR is the active candidate fix.

## What This Changes

Show human-readable Telegram forum topic names in the session dropdown instead of raw topic-qualified session keys.

## Best Possible Solution

Review and either land or close https://github.com/openclaw/openclaw/pull/96793; the desired end state is Telegram populating generic `ThreadLabel`/session display metadata from known forum topic names while preserving the parent group label.

## Reproduction Assessment

Yes. Source inspection shows current main learns Telegram forum `TopicName` but does not set `ThreadLabel`, while the shared session display path consumes `ThreadLabel`/`displayName`; I did not run a live Telegram forum setup.

## Solution Assessment

Yes. The linked PR’s direction is the narrow maintainable path because it reuses the existing Telegram topic-name cache and generic `ThreadLabel` metadata instead of adding Telegram-specific UI formatting or a new config field.
