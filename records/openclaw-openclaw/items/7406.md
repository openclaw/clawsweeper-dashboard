## Summary

Keep open. Current main and the latest release still learn Telegram forum topic names as `TopicName` but do not expose them as the generic `ThreadLabel` consumed by session display, and https://github.com/openclaw/openclaw/pull/96793 is the open closing candidate that should land or be closed first.

## What This Changes

Show learned Telegram forum topic names as human-readable session dropdown labels instead of raw topic IDs or internal session keys.

## Best Possible Solution

Review and land or close https://github.com/openclaw/openclaw/pull/96793; the desired end state is existing Telegram topic-name metadata flowing through the generic `ThreadLabel`/session display path while preserving the parent group label.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: Telegram forum messages can populate `TopicName`, but current main does not set `ThreadLabel`, while session display uses `ThreadLabel`/`displayName`; I did not run a live Telegram forum setup in this read-only review.

## Solution Assessment

Yes. The best fix is the narrow linked PR direction: reuse the existing Telegram topic-name cache and generic `ThreadLabel` metadata instead of adding Telegram-specific UI formatting or a new config field.
