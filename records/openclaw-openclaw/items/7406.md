## Summary

Keep open. Current main and the latest release still learn Telegram forum topic names as `TopicName` but do not expose them as generic `ThreadLabel` session-display metadata, and https://github.com/openclaw/openclaw/pull/96793 is the open closing candidate that should land or be closed first.

## What This Changes

The issue requests human-readable Telegram forum topic names in the session dropdown instead of raw topic-id session keys.

## Best Possible Solution

Land or close https://github.com/openclaw/openclaw/pull/96793; the desired end state is a generic `ThreadLabel`/session-display path populated from known Telegram forum topic names while preserving the parent group label.

## Reproduction Assessment

Yes. Source inspection shows current main learns `TopicName` for Telegram forum topics but does not map it to `ThreadLabel`, while the session display path consumes label/displayName fields before falling back to parsed session keys.

## Solution Assessment

Yes. The linked PR's direction is the narrow maintainable fix because it reuses the existing Telegram topic-name cache and generic `ThreadLabel` seam rather than adding Telegram-specific UI formatting or a new config field.
