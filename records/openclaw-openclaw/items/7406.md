## Summary

Current main and the latest shipped release still learn Telegram forum topic names only as `TopicName`; they do not bridge that value into the generic `ThreadLabel` path that produces stored session display names and selector labels. The issue remains necessary, and the open closing pull request https://github.com/openclaw/openclaw/pull/96793 is the focused candidate fix, so this canonical issue should stay open until that PR lands or is replaced.

## What This Changes

Requests human-readable Telegram forum topic names in session selectors instead of raw or indistinguishable topic session identifiers.

## Best Possible Solution

Land the existing generic `ThreadLabel` mapping after redacted live Telegram forum or gateway `sessions.list` proof confirms the topic title becomes the session display name while the parent group remains the conversation label and routing IDs remain unchanged.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level. Current main learns and emits a Telegram forum title as `TopicName`, but both inbound paths omit `ThreadLabel`, while the downstream session display path consumes `ThreadLabel`.

## Solution Assessment

Yes. Reusing the generic thread-label metadata seam is the narrowest maintainable solution because it preserves separate group and topic identities and avoids Telegram-specific UI parsing or a new configuration surface.
