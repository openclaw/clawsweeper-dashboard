## Summary

Keep open. Current main and the latest release still learn Telegram forum topic names as `TopicName` but do not expose them as generic `ThreadLabel` for session labels; https://github.com/openclaw/openclaw/pull/96793 remains the open closing candidate.

## What This Changes

The issue requests human-readable Telegram forum topic names in the session dropdown instead of raw Telegram topic session keys.

## Best Possible Solution

Land the linked PR if it passes review and real Telegram proof, leaving Telegram to populate generic `ThreadLabel` from cached topic names while preserving parent group labels.

## Reproduction Assessment

Yes, source-reproducible: current main learns cached Telegram forum `TopicName` but does not set `ThreadLabel`, while session rows and the Control UI depend on label/display metadata before falling back to keys. I did not run a live Telegram forum setup in this read-only review.

## Solution Assessment

Yes, the linked PR’s direction is the narrow maintainable fix: reuse the existing topic-name cache and generic `ThreadLabel` metadata instead of adding Telegram-specific UI formatting or a new config field.
