## Summary

Current main and the latest release still expose Telegram forum names only as `TopicName`, while the generic `ThreadLabel` needed by session display metadata is absent in both inbound paths. The issue remains necessary and canonical because the focused closing pull request is still open and unmerged, and its live Telegram proof remains outstanding.

## What This Changes

Show known Telegram forum topic names as human-readable session-selector labels instead of raw or indistinguishable topic identifiers.

## Best Possible Solution

Populate the existing generic `ThreadLabel` from the cached Telegram topic name in both ordinary inbound and native-command metadata while preserving the parent group in `ConversationLabel`, then verify the resulting selector label in a real forum-topic session.

## Reproduction Assessment

Yes at source level: current main learns the human topic name but omits `ThreadLabel` in both Telegram forum message and native-command session metadata paths. A live selector reproduction was not run during this read-only issue review.

## Solution Assessment

Yes. Reusing the existing generic `ThreadLabel` contract is narrower and more maintainable than adding Telegram-specific parsing or formatting to the Control UI.
