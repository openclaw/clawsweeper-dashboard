## Summary

Keep open: current main still lacks the requested user-visible behavior, and the open closing pull request https://github.com/openclaw/openclaw/pull/96793 owns the focused implementation.

## What This Changes

Show learned Telegram forum topic names as human-readable labels for topic sessions instead of raw numeric identifiers.

## Best Possible Solution

Land the narrow Telegram-owned change that maps a known forum `TopicName` to the generic `ThreadLabel` for both ordinary inbound messages and native commands, preserves the parent conversation label and routing identifiers, and includes redacted live Telegram session-selector proof.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from current source: Telegram obtains `TopicName` but omits `ThreadLabel`, while session persistence and the Control UI already consume `ThreadLabel` through `displayName`. No live Telegram run was performed for this read-only issue review.

## Solution Assessment

Yes. Reusing the existing generic `ThreadLabel` contract is the narrowest maintainable solution and avoids Telegram-specific UI parsing, a new configuration option, or a parallel persisted field.
