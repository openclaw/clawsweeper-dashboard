## Summary

Keep open. Current main and the latest release still learn Telegram forum topic names as `TopicName` but do not propagate them into the generic `ThreadLabel`/session display path, and https://github.com/openclaw/openclaw/pull/96793 is the open closing candidate that should land or be closed before this issue resolves.

## What This Changes

The issue requests human-readable Telegram forum topic names in the session dropdown instead of raw topic session keys.

## Best Possible Solution

Land or close https://github.com/openclaw/openclaw/pull/96793; the desired end state is a generic `ThreadLabel`/session-display path populated from known Telegram forum topic names while preserving the parent group label.

## Reproduction Assessment

Yes. Source inspection shows current main learns `TopicName` for Telegram forum topics but does not set `ThreadLabel`, while the shared session display path consumes `ThreadLabel` into `displayName`; I did not run a live Telegram forum setup in this read-only review.

## Solution Assessment

Yes for the linked repair direction, not for a Telegram-specific UI formatter. Reusing the existing generic `ThreadLabel` seam is narrower and more maintainable than adding a new per-topic config field or hard-coded Control UI formatting.
