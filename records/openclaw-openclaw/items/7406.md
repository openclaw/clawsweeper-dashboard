## Summary

Keep open. Current main and v2026.6.11 still expose Telegram forum topic names as `TopicName` without carrying them into the generic `ThreadLabel`/session display path, and the open closing PR is the current candidate fix rather than a reason to close this issue before merge.

## What This Changes

The issue requests human-readable Telegram forum topic names in the session dropdown instead of raw topic-session keys.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/96793 with the narrow `ThreadLabel` mapping for regular inbound messages and native commands, preserving parent group `ConversationLabel` and routing semantics.

## Reproduction Assessment

Yes. Source inspection is enough to reproduce the gap: Telegram forum context emits `TopicName`, but the session display path consumes `ThreadLabel`/`displayName`, and current main does not populate `ThreadLabel`.

## Solution Assessment

Yes. The best fix is to reuse the existing generic `ThreadLabel` seam from the known Telegram topic name; UI key parsing or a new config name field would create a second source of truth.
