## Summary

Keep open. Current main and the latest release still learn Telegram forum topic names as `TopicName` but do not propagate that value into `ThreadLabel`/stored `displayName`, and the open closing PR should resolve the remaining session-label gap before this issue closes.

## What This Changes

Request human-readable Telegram forum topic names in the session dropdown instead of raw topic IDs or group-only labels.

## Best Possible Solution

Land or close https://github.com/openclaw/openclaw/pull/96793; the desired end state is a generic `ThreadLabel`/session-display path populated from known Telegram forum topic names while preserving the parent group label.

## Reproduction Assessment

Yes. Source inspection shows current main learns `TopicName` for Telegram forum topics but does not set `ThreadLabel`, while the shared session display path consumes `ThreadLabel` into `displayName`; I did not run a live Telegram forum setup in this read-only review.

## Solution Assessment

Yes for the linked repair direction. Reusing the existing generic `ThreadLabel` seam is narrower and more maintainable than adding a Telegram-specific UI formatter or per-topic config field.
