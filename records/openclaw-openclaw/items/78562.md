## Summary

Keep open: the latest report reproduces the successful-but-insufficient recovery failure on v2026.7.1, while current related work addresses only distinct pressure sources and does not establish a complete post-compaction-fit recovery invariant.

## What This Changes

The issue requests that OpenClaw stop repeated context-overflow recovery cycles when a successful compaction still leaves the rebuilt tool-loop prompt over budget.

## Best Possible Solution

Define one recovery invariant for the embedded runner: after every compaction or truncation, measure the rebuilt provider-boundary prompt; submit it when it fits, otherwise perform one bounded stronger reduction or a clear successor-session recovery instead of accumulating successful-but-insufficient checkpoints.
