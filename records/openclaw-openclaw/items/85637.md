## Summary

Close: the supported current behavior is now documented and diagnosed. The 2026.5.x symptom matches the confirmed sandbox tool-policy gate: configured MCP servers can connect and list tools, while sandboxed turns still filter `bundle-mcp` tools unless the sandbox tool allowlist includes `bundle-mcp`, `group:plugins`, or a server glob; current main and shipped releases now surface that with docs and `openclaw doctor`.

## What This Changes

The issue reports remote `streamable-http` MCP tools connecting/authenticating but never appearing in a Pi agent's compiled tool surface.

## Best Possible Solution

Keep the shipped doctor/docs behavior and have users with sandboxed agents allow `bundle-mcp`, `group:plugins`, or a server glob in `tools.sandbox.tools.alsoAllow`; keep the separate namespaced `toolFilter` issue tracked in https://github.com/openclaw/openclaw/issues/98193.

## Reproduction Assessment

Yes for the confirmed root-cause shape: source and related live discussion show sandbox policy can hide otherwise materialized `bundle-mcp` tools unless the sandbox allowlist includes the MCP/plugin entry. I did not rerun the reporter's exact private bearer-authenticated remote server.

## Solution Assessment

Yes. The best shipped fix for this root cause is the narrow doctor warning and docs/recovery path, because changing sandbox defaults would broaden tool exposure for existing users.
