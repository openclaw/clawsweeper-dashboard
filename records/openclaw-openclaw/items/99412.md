- `P1`: Hidden model reasoning can leak into user-facing Matrix messages through a source-confirmed channel delivery gap.
- `impact:security`: The issue crosses a sensitive-information boundary by exposing internal reasoning text to chat recipients.

## Summary

Keep open: current main and the latest release still use the Matrix monitor regex that misses MiniMax `mm:` reasoning tags, while sibling shared, Slack, and iMessage paths already recognize that namespace. The bug is source-reproducible and security-sensitive because hidden reasoning can be delivered to Matrix rooms.

## What This Changes

The issue requests adding MiniMax `mm:` namespace recognition to the Matrix monitor's reasoning-only reply suppression regexes.

## Best Possible Solution

Align the Matrix monitor with the shared reasoning-tag contract, preferably by reusing a shared helper or adding the same namespace-aware pattern plus Matrix regression tests for MiniMax tags.

## Reproduction Assessment

Yes, at source level: current Matrix `THINKING_TAG_RE` and `THINKING_BLOCK_RE` do not match `<mm:think>...</mm:think>`, so a reasoning-only MiniMax reply is not suppressed by the fallback path. I did not run a live Matrix transport reproduction in this read-only review.

## Solution Assessment

Yes for the narrow bug: adding the same `mm:` namespace recognition used by shared, Slack, and iMessage paths is the minimal repair. The longer-term maintainable solution is to centralize this reasoning-tag grammar so monitor fallbacks do not drift again.
