## Summary

Keep this PR open, but do not merge it yet: its compatibility alias covers only `kimi` even though the plugin declares both `kimi` and `kimi-coding` provider IDs, leaving an existing `kimi-coding/k3[1m]` selection able to bypass the pre-catalog rewrite and fail after the old catalog entry is removed.

The PR removes `k3[1m]` from the Kimi model catalog, raises `k3` to a 1M context-window metadata value, and adds normalization intended to map legacy `k3[1m]` selections to `k3`.

## Best Possible Solution
