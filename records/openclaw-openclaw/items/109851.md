## Summary

Keep open: current main provides the authenticated Control UI MCP Apps host, but not the proposed least-privilege standalone/channel boundary. This fresh member-authored issue has a protected `maintainer` label, addresses a concrete credential-exposure gap, and needs explicit security-boundary review before implementation.

## What This Changes

Add a standalone read-only MCP App host using short-lived signed view tickets bound to a session, MCP runtime, and view lease instead of exposing the reusable Gateway bearer credential.

## Best Possible Solution

Implement a Gateway-owned, short-lived signed capability that reuses the existing view lease and separate-origin sandbox, permits only initialization, ping, teardown, and bounded view-data reads, rejects all privileged MCP methods, and ships with real-browser conformance covering expiry, replay, isolation, reload, and bearer non-disclosure before any channel launcher is added.
