## Summary

The issue remains necessary, but it combines two decisions: current main drops the execution signal before runtime and client `before_tool_call` dispatch, while a universal tool timeout and override configuration would introduce broader policy despite existing run-level, hook-level, and tool-owned limits. Keep it open for owner review and split the narrow lifecycle correction from timeout policy.

## What This Changes

Forward tool-execution cancellation into before-tool policy processing, standardize client-tool hook failures, and consider configurable bounded execution for tools.

## Best Possible Solution

Split the work: first forward the existing signal through both adapters and define tested abort versus ordinary-hook-error behavior; separately design any execution budget around existing run-level, hook-runner, and tool-owned timeout seams, avoiding a new global config knob unless those seams are insufficient.
