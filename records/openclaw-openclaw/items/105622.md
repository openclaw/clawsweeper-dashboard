## Summary

This remains necessary, but it combines separate concerns. Current main omits the execution signal at both adapter hook calls and deliberately rethrows client-hook failures, while existing hook budgets already bound Gateway admission without cancelling plugin work; a universal tool timeout remains a distinct product and configuration decision.

## What This Changes

Request abort propagation into before-tool hooks, consistent hook-error handling, and configurable per-tool execution timeouts.

## Best Possible Solution

Define and test cancellable `before_tool_call` semantics plus consistent runtime/client error outcomes first, then consider a separate timeout-policy proposal only if existing run, hook, approval, and tool-owned deadlines remain insufficient.
