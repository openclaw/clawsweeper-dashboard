## Summary

Keep open: current main and the latest release still have adjacent name/profile tool policies, HTTP tool deny lists, and per-call plugin approvals, but not the requested manifest-declared capability grants, default-deny pre-model filtering, execution-boundary authorization, or durable capability audit model.

## What This Changes

Request a capability-based permission model for skills/tools with manifest declarations, explicit grants/revocations, default-deny high-risk capabilities, and audit records.

## Best Possible Solution

Keep this open as a core/plugin-API security hardening design item and define a phased capability subsystem: schema/diagnostics first, then grants, pre-exposure filtering, execution checks, and durable audit storage.
