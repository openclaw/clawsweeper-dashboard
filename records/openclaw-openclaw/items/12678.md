## Summary

Keep open: current main and v2026.6.11 still have adjacent name/profile tool policies, HTTP deny lists, and per-call plugin approvals, but they do not implement the requested manifest-declared sensitive capabilities, explicit grants/revocations, pre-model default-deny filtering, execution-boundary checks, or durable capability audit records.

## What This Changes

The issue requests a capability-based permission model for skills and tool integrations with manifest-declared sensitive capabilities, explicit grants and revocations, default-deny enforcement, and durable audit records.

## Best Possible Solution

Define a phased core/plugin-API capability subsystem that starts with manifest schema and diagnostics, then adds maintainer-approved grants, pre-exposure filtering, execution checks, and durable audit storage.
