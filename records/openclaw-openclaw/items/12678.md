## Summary

Keep open: current main and v2026.6.11 still have adjacent name/profile tool policy, plugin approval hooks, HTTP tool deny lists, and metadata-only audit records, but not the requested manifest-declared capability grants, pre-model default-deny filtering, execution-boundary authorization, or durable capability-decision audit layer.

## What This Changes

The issue requests a capability-based permission model for OpenClaw skills/tools that declares sensitive capabilities, defaults high-risk actions to denied unless granted, supports grant/revoke UX, and audits high-risk invocations.

## Best Possible Solution

Define a phased core/plugin-API capability subsystem: schema and diagnostics first, then maintainer-approved grants/revocations, pre-exposure filtering, execution-boundary checks, and durable capability audit storage.
