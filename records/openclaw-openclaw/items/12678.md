## Summary

Keep open: current main and v2026.6.11 still have adjacent name/profile tool policies, before_tool_call/trusted-policy governance, plugin metadata, skill allowlists, and Gateway HTTP deny lists, but not manifest-declared capabilities, explicit grants/revocations, pre-model default-deny filtering, cross-surface execution checks, or durable high-risk capability audit records.

## What This Changes

The issue requests a capability-based permission model for skills and tools, with manifest declarations, default-deny grants, consent/revocation UX, and audit logging for high-risk actions.

Keep this as the canonical core/plugin-API security-hardening umbrella and split implementation into maintainer-approved phases for schema, grants, filtering, execution checks, and durable audit records coordinated with the narrower RFCs.
