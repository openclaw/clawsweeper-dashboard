## Summary

Keep open: current main and v2026.6.11 still have adjacent name/profile tool policies, plugin hooks, HTTP deny lists, and metadata-only audit records, but not the requested manifest-declared capability grants, pre-model default-deny filtering, execution-boundary authorization, or durable capability-decision audit layer.

## What This Changes

The issue requests capability-based permissions for skills/tools so high-risk actions are default-denied unless a trusted manifest/grant explicitly allows them.

## Best Possible Solution

Define a phased core/plugin-API capability subsystem: schema and diagnostics first, then maintainer-approved grants/revocations, pre-exposure filtering, execution-boundary checks, and durable capability audit storage.
