## Summary

Keep open: current main and the latest release still have adjacent name/profile tool policies, plugin approval hooks, HTTP tool deny lists, and audit records, but not the requested manifest-declared capability grants, pre-model default-deny filtering, execution-boundary authorization, or durable capability-decision audit layer. The linked @vainplex/openclaw-governance plugin is useful call-time prior art, but the issue discussion correctly distinguishes it from a core/plugin-API grant model.

## What This Changes

Request a capability-based permission model for skills/tools with declared capabilities, explicit grants, default-deny high-risk actions, grant/revoke UX, and high-risk audit records.

## Best Possible Solution

Define a phased core/plugin-API capability subsystem: schema and diagnostics first, then maintainer-approved grants/revocations, pre-exposure filtering, execution-boundary checks, and durable capability audit storage.
