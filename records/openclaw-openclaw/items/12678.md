## Summary

Keep open: current main and the latest release still have adjacent tool policies, hook-time governance, plugin activation metadata, and Gateway HTTP deny lists, but not the requested capability-manifest, explicit grant/revoke, pre-model default-deny, execution-boundary authorization, and durable high-risk audit layer.

## What This Changes

Request to add capability-based permissions for skills/tools with manifest declarations, default-deny grants, consent/revocation UX, and audit records.

## Best Possible Solution

Define a phased core/plugin-API capability subsystem: schema and diagnostics first, then maintainer-approved grant storage, pre-exposure filtering, execution checks across tool surfaces, and durable audit records.
