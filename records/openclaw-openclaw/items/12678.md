## Summary

Keep open: current main and the latest stable release still have adjacent name/profile tool policy, HTTP deny lists, and hook-time approvals, but not the requested manifest-declared capability grants, pre-model default-deny filtering, execution-boundary authorization, or durable capability audit model.

## What This Changes

The issue requests a capability-based permission layer for skills/tools with manifest declarations, explicit grants/revocations, default-deny high-risk actions, execution checks, and audit records.

## Best Possible Solution

Define a phased core/plugin-API capability subsystem that starts with schema and diagnostics, then adds maintainer-approved grants, pre-exposure filtering, execution checks, and audit storage.
