## Summary

Keep open: current main and v2026.6.11 still provide adjacent name/profile tool policy, before-tool hooks, HTTP tool deny lists, exec/plugin approvals, and metadata-only audit, but not the requested manifest-declared capability grants, pre-model default-deny filtering, execution-boundary authorization, or durable capability-decision audit layer.

## What This Changes

The issue requests capability-based default-deny permissions for skills and tools, including declarations, explicit grants, pre-model filtering, execution-boundary checks, and audit logging.

## Best Possible Solution

Define a phased core/plugin-API capability subsystem: schema and diagnostics first, then maintainer-approved grants/revocations, pre-exposure filtering, execution-boundary checks, and durable capability-decision audit storage.
