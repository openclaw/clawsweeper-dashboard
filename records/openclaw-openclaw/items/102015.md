## Summary

Keep open: current main still records normal model fallback transitions only as fallback-step observations, while the `model.failover` diagnostic/exporter contract is already present. The issue is also paired with an open PR that uses closing syntax, so it should remain open until that PR or another fix lands.

## What This Changes

The issue reports that model fallback retry chains are not visible in telemetry/diagnostic traces, making provider fallback storms hard to detect.

## Best Possible Solution

Land one narrow fix that emits the existing `model.failover` diagnostic event for each real failed-candidate to next-candidate transition without adding new trace attributes or changing fallback selection, backoff, or circuit-breaker policy.

## Reproduction Assessment

Yes. Source inspection shows a high-confidence path: configure multiple fallback candidates, make a candidate fail, and the normal failure path records a fallback step but does not emit `model.failover` unless the cooldown suspension branch is hit.

## Solution Assessment

Yes. The best fix shape is to emit the existing `model.failover` diagnostic event at the failed-candidate transition point, rather than adding undocumented `has_fallback` attributes or changing retry/backoff behavior.
