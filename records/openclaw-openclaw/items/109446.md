## Summary

Keep open. The POSIX fix remains necessary on current main, matches Codex’s direct-child timeout contract, and is a focused, well-tested correction for the reported host-OOM failure; Windows process-tree cancellation remains intentionally outside this PR’s scope.

## What This Changes

The PR prefixes POSIX Codex native-hook relay commands with `exec` and bypasses OpenClaw launcher, startup-environment, and compile-cache respawns so the timeout-owned PID remains the relay process.

## Best Possible Solution

Land the focused POSIX PID-ownership fix after normal merge gates, then track Windows process-tree termination or a parent-watchdog design separately without weakening the Linux repair.

## Maintainer Decision

## Reproduction Assessment

Yes. Shipped v2026.7.1 and current main have a deterministic POSIX process-tree path where Codex kills only its shell child while OpenClaw can leave a respawned relay descendant alive.

## Solution Assessment

Yes. Replacing the POSIX timeout-owned shell with the relay and removing every OpenClaw respawn layer on that internal command is the narrowest maintainable fix consistent with Codex’s current hook-runner contract.
