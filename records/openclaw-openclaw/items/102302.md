## Summary

Keep open: the PR targets a real source-reproducible Tailscale Serve Control UI HTTP auth gap, but the current head still expands a gateway security boundary without the WebSocket-equivalent origin gate, leaves docs inconsistent, and has only unit-test proof.

## What This Changes

The PR adds an `http-control-ui` auth surface, routes Control UI HTTP read requests through it, and adds gateway auth tests for tokenless Tailscale identity on bootstrap/media/avatar reads.

## Best Possible Solution

Allow tokenless Tailscale identity on Control UI HTTP reads only after the same origin policy is enforced, docs/tests are updated, and real Tailscale Serve proof is added; otherwise keep HTTP reads token-bound or design a narrower scoped media credential.
