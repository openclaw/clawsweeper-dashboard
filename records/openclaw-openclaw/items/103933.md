## Summary

Current main and the merged feature history define session-memory hits as following the same visibility rules as session history, including default `tree` denial for unrelated same-agent sessions. The PR instead makes unset `tree` broader than explicitly configured `tree`, so it remains blocked on a visibility-policy decision, real populated-index proof, and its current merge conflict.

## What This Changes

The PR lets authoritative same-agent session hits bypass memory-core’s history guard only when session visibility is unset, adds a public SDK helper for detecting explicit visibility configuration, updates SDK surface metadata, and adds focused regressions.

## Best Possible Solution

Preserve one canonical visibility contract across session history and memory recall; broader same-agent recall should use the existing explicit `agent` mode unless owners approve and document a coherent shared policy change.
