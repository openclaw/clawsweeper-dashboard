## Summary

Keep open. Current main and the latest release still classify only token-explicit `INVALID_ARGUMENT` overflows, while the reported LiteLLM/Vertex beta generic 400 shape remains outside the provider-error and session-recovery paths.

## What This Changes

The issue requests actionable provider/session recovery for long-session LiteLLM Vertex beta 400 `INVALID_ARGUMENT` failures that can leave later turns unreliable or silent.

## Best Possible Solution

Add a narrow maintainer-approved LiteLLM/Vertex provider-session recovery path, preferably via provider-owned hooks, with redacted structured details, actionable user copy, and proof that the failed turn releases or cleanly marks the session lane.
