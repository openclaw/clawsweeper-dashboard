Full review comments:

- **[P1] Merge legacy groups before clearing browser state:** `ui/src/lib/sessions/index.ts:839-848`
  - body: When the gateway already has any groups, this skips uploading browser-only legacy names but still deletes the local catalog. Merge the ordered legacy names into the server catalog before removing localStorage so existing empty groups and ordering are not lost during upgrade.
  - confidence: 0.99
- **[P1] Load the catalog before replace-all group writes:** `ui/src/lib/sessions/index.ts:869-876`
  - body: `groupsPut` replaces the complete gateway catalog even when `groupsLoad()` has not completed or previously failed. A create or reorder from a partial UI snapshot can therefore remove empty or off-window groups; merge against a fresh catalog before sending the replacement.
  - confidence: 0.98
- **[P2] Use the configured default agent for cached rows:** `ui/src/components/app-sidebar.ts:1506-1511`
  - body: Rows cached for another agent are filtered with the currently selected agent as `defaultAgentId`. Legacy or unprefixed sessions belonging to the real default agent are consequently dropped when another agent chat is active; pass `navigationState.defaultAgentId`.
  - confidence: 0.98
- **[P2] Keep dashboard sessions out of channel groups:** `ui/src/lib/session-display.ts:42-49`
  - body: A key such as `agent:ops-agent:dashboard:direct:...` matches the peer-kind expression and yields `dashboard` as the channel, putting an ordinary dashboard session under a bogus Dashboard transport section. Explicitly reject dashboard and other non-transport key namespaces.
  - confidence: 0.98
- **[P2] Hydrate unread state for collapsed agents:** `ui/src/components/app-sidebar.ts:1516-1518`
  - body: Unread counts only inspect `sessionRowsByAgent`, which is populated after an agent list is loaded. A never-expanded collapsed agent therefore shows no unread indicator despite unread sessions; hydrate a summary or populate the cache before rendering collapsed sections.
  - confidence: 0.96
- **[P2] Re-render when only the group catalog changes:** `ui/src/pages/sessions/sessions-page.ts:620-629`
  - body: The Sessions page now reads custom groups directly from shared `state.groups`, but its subscription schedules work only when `snapshot.result` changes. Creating or reordering an empty group updates the catalog without updating the page until an unrelated session refresh occurs.
  - confidence: 0.96
- **[P2] Disable draft submission during session refresh:** `ui/src/components/new-session-dialog.ts:219-233`
  - body: The dialog enables Start whenever it is connected, but `SessionCapability.create()` returns `null` while shared session state is loading. Submitting during a foreground refresh therefore shows a false create failure without sending the request; gate submission on loading or allow creation to queue.
  - late: true
  - confidence: 0.96
- **[P2] Navigate empty-agent fallback to that agent:** `ui/src/components/app-sidebar.ts:1488-1490`
  - body: The fallback rendered inside an expanded empty agent section has no target-agent argument and navigates to generic Chat, which reopens the currently active session rather than the empty agent's main session. This was visible on the earlier reviewed head and is raised late; pass the section agent's main-session key.
  - late: true
  - confidence: 0.95

  - body: When branch loading becomes invalid, the early return clears `branches` but neither increments the request token nor clears `baseRef` and loading state. An older request can later restore a base ref from the previous repository and submit it for a different folder; this is a late finding on unchanged code.
  - late: true
  - confidence: 0.97
