Full review comments:

- **[P1] Merge legacy groups before deleting browser state:** `ui/src/lib/sessions/index.ts:839-848`
  - body: When the gateway already has any groups, this skips uploading the browser-only catalog but still removes the localStorage entry. Existing empty groups and browser ordering are permanently lost; merge the two catalogs before deleting the legacy state.
  - confidence: 0.99
- **[P1] Load the catalog before replace-all writes:** `ui/src/components/app-sidebar.ts:705-708`
  - body: `groupsPut` replaces the whole gateway catalog, but callers can reach it while `groupsLoad()` is still in flight or after a list failure, using only an empty snapshot/current rows. Wait for or refetch the canonical catalog before adding or reordering names so unrelated groups are not dropped.
  - confidence: 0.98
- **[P1] Keep agent expansion out of global selection:** `ui/src/components/app-sidebar.ts:499-504`
  - body: Expanding an agent is documented as browse-only, but this updates `agentSelection`, which disambiguates global/main session keys throughout chat and session navigation. Merely opening another section can therefore make the active unqualified chat and later actions resolve against the wrong agent. This was visible on the previous head and is being raised late here.
  - late: true
  - confidence: 0.98
- **[P1] Do not combine node execution with gateway worktrees:** `ui/src/components/new-session-dialog.ts:54-64`
  - body: The builder submits `execNode` together with `worktree` and `cwd`, although the managed checkout is created on the gateway and node-host commands do not inherit the session default cwd. The sidebar then advertises a branch-backed Work session while commands run elsewhere; disable the combination or implement node-owned checkout routing.
  - confidence: 0.99
- **[P2] Use the configured default agent for cached rows:** `ui/src/components/app-sidebar.ts:1611-1616`
  - body: Filtering a non-active agent cache passes the currently selected/expanded agent as `defaultAgentId`. Legacy unprefixed rows belong to the configured default agent, so they can disappear or be attributed incorrectly after browsing another agent; pass the actual configured default id.
  - confidence: 0.96
- **[P2] Hydrate unread state for collapsed agents:** `ui/src/components/app-sidebar.ts:1621-1623`
  - body: The unread dot only counts `sessionRowsByAgent`, which is populated for the active or previously expanded agent. A collapsed agent that has not been browsed in this browser therefore shows no unread indicator until it is expanded; hydrate a summary for every agent or derive it from an unscoped result.
  - confidence: 0.97
- **[P2] Target the empty fallback at its agent:** `ui/src/components/app-sidebar.ts:1689-1695`
  - body: An expanded agent with no rows renders the generic Chat fallback, whose click navigates without an agent-specific session key. Under a non-default empty section this reopens the current chat instead of that agent’s main session; pass the section agent into the fallback navigation.
  - confidence: 0.98
- **[P2] Gate draft creation during session refreshes:** `ui/src/components/new-session-dialog.ts:219-233`
  - body: The dialog enables Start while `context.sessions.state.loading` is true, but `SessionCapability.create` returns null immediately in that state without sending `sessions.create`. This turns an ordinary foreground refresh into a misleading create failure; disable submission or queue creation until refresh completes.
  - confidence: 0.99
- **[P2] Cancel stale branch lookups on invalid targets:** `ui/src/components/new-session-dialog.ts:177-187`
  - body: Switching to a non-git or empty target returns here without incrementing the request token or clearing the prior base ref/loading state. A response for the old checkout can later populate the draft and be submitted for a different folder. This was equally visible on the previous reviewed head; invalidate pending requests whenever branch loading is abandoned.
  - late: true
  - confidence: 0.95
- **[P2] Exclude dashboard keys from channel grouping:** `ui/src/lib/session-display.ts:42-49`
  - body: The channel regex classifies keys such as `agent:<id>:dashboard:direct:<name>` as a Dashboard transport even though these are Control UI sessions. They appear in a bogus smart channel section; explicitly reject dashboard/main namespaces or parse only known transport key shapes.
  - confidence: 0.97
- **[P2] Handle every generated DM key shape:** `ui/src/lib/session-display.ts:114-121`
  - body: The fallback recognizes only `agent:<agent>:<channel>:direct:<id>`, while routing also generates `agent:<agent>:direct:<peer>` and account-qualified channel keys. Unlabeled sessions in those supported modes fall back to the complete raw key and peer id. This was already visible on the previous head; parse all routing shapes and shorten the peer portion consistently.
  - late: true
  - confidence: 0.99
- **[P2] Re-render when only the group catalog changes:** `ui/src/pages/sessions/sessions-page.ts:136-149`
  - body: Creating an empty group publishes a new `state.groups` array without changing `state.result`, but the Sessions page subscription schedules UI work only when the result object changes. The new empty group and move target remain invisible until an unrelated session refresh; request an update when the group snapshot changes.
  - confidence: 0.95
