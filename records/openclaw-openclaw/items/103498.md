## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.96

Full review comments:

- **[P1] Merge legacy groups before deleting browser state:** `ui/src/lib/sessions/index.ts:839-848`
  - body: When the gateway already contains any group, this skips importing the browser catalog but still removes it. Existing browser-only empty groups and ordering are therefore lost; merge the two catalogs before deleting the legacy key.
  - confidence: 0.99
- **[P1] Load the catalog before issuing replace-all writes:** `ui/src/components/app-sidebar.ts:656-660`
  - body: `groupsPut` replaces the entire gateway catalog, but this writer can run before `groupsLoad` succeeds and derives names only from empty state plus the current list window. Creating one group can consequently remove remote or empty groups; await a fresh catalog or use an additive server operation.
  - confidence: 0.98
- **[P2] Use the configured default agent for cached rows:** `ui/src/components/app-sidebar.ts:1507-1510`
  - body: Legacy or unprefixed session keys belong to the configured default agent, but this passes the currently selected agent instead. Expanding the real default agent while another agent is active can filter its legacy rows out of the sidebar.
  - confidence: 0.98
- **[P2] Exclude dashboard keys from channel grouping:** `ui/src/lib/session-display.ts:45-49`
  - body: A key such as `agent:ops-agent:dashboard:direct:...` matches this parser and becomes a `Dashboard` channel session, although dashboard sessions are meant to remain normal chats. Reject dashboard keys before transport classification.
  - confidence: 0.99
- **[P2] Hydrate unread state for collapsed agents:** `ui/src/components/app-sidebar.ts:1516-1518`
  - body: Unread counts only inspect the per-agent cache, which is populated when an agent is loaded or expanded. A never-opened collapsed agent therefore lacks the advertised unread indicator until after the user expands it.
  - confidence: 0.94
- **[P2] Re-render when the shared group catalog changes:** `ui/src/pages/sessions/sessions-page.ts:642-646`
  - body: Creating an empty group updates `state.groups` without changing the sessions result, while the Sessions page subscription schedules work only for result changes. The new group remains absent from sections and menus until an unrelated session refresh occurs.
  - confidence: 0.97
- **[P2] Disable draft submission while sessions are loading:** `ui/src/components/new-session-dialog.ts:219-221`
  - body: The dialog enables Start during a foreground session refresh, but `SessionCapability.create` returns `null` whenever `state.loading` is true. Submitting in that window reports a generic failure without sending `sessions.create`; gate the button or queue creation.
  - confidence: 0.99
- **[P2] Target the selected agent in the empty fallback:** `ui/src/components/app-sidebar.ts:1488-1490`
  - body: An expanded agent with no rows renders the generic chat fallback, which navigates without that agent's main-session search. Clicking it can reopen the previously active agent instead of the empty agent represented by the section.
  - confidence: 0.97
- **[P1] Invalidate branch requests when a target becomes invalid:** `ui/src/components/new-session-dialog.ts:177-183`
  - body: Returning here neither increments the request token nor clears `baseRef` and loading state. A response for the previous repository can later repopulate the draft and submit a base ref belonging to the wrong checkout.
  - confidence: 0.97
- **[P1] Disallow node execution with gateway-managed worktrees:** `ui/src/components/new-session-dialog.ts:46-61`
  - body: This builder can send both `execNode` and gateway worktree fields. The worktree is created on the gateway, while node execution intentionally does not inherit the gateway default cwd, so the sidebar advertises an isolated checkout that commands do not use; disable the combination or provision the checkout on the node.
  - confidence: 0.99
