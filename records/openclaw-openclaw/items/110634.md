## Summary

Keep this PR open: it fixes one active-cooldown eviction outcome by removing the only effective hard capacity limit, so it can retain more than 512 active entries for their full lifetime. The gateway owner needs to choose the capacity contract before a bounded fix can land. Likely related people: steipete (low-confidence gateway-area routing candidate).

## What This Changes

The branch changes `pruneCooldowns` so its size-enforcement loop stops when the oldest SSH-verification cooldown is still unexpired.

## Best Possible Solution

Keep a bounded cooldown cache and have the gateway owner select an explicit full-cache policy that preserves the intended cooldown priority without allowing unlimited active entries, then add regression coverage for both the active-entry case and the 512-entry limit.
