## Summary

Keep this PR open: it fixes premature eviction of active cooldowns, but the new early break leaves no defined admission policy once the map is full of active entries and can let the cache exceed its stated maximum. It also still needs real after-fix behavior proof before merge. Likely related people: the relevant current-main history could not be safely traced in this read-only environment, so routing confidence is low.

## What This Changes

The PR changes SSH verification cooldown pruning to stop deleting the oldest cooldown entry when that entry has not yet expired.

## Best Possible Solution

Keep active cooldowns intact while retaining a defined hard-cap admission rule—preferably reject or otherwise deliberately handle the newest cooldown when no expired entry can be pruned—then cover both branches with focused tests and redacted runtime proof.
