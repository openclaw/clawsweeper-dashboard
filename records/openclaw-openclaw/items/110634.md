## Summary

Keep this PR open, but do not merge it as written: the new early break preserves old active cooldowns by abandoning the intentional 512-entry bound, so high-cardinality active targets can grow the process-local map indefinitely. The repeated prior P1 blocker remains unfixed on the current head, and the PR still has only unit-test output rather than after-fix runtime proof.

## What This Changes

The branch changes SSH-verification cooldown pruning so the size-enforcement loop stops when the oldest cooldown entry is unexpired.

## Best Possible Solution

Retain a hard bounded cache and define saturation explicitly—prefer preserving existing active entries while declining the newly arriving cooldown when all 512 slots are active—then add focused regression coverage and redacted runtime evidence for that policy.
