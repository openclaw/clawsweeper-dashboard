## Summary

This PR should stay open: it prevents eviction of active cooldowns but now permits the cooldown map to exceed its explicit maximum whenever no entry has expired. It also still lacks contributor-supplied after-fix runtime evidence; tests asserted in the body are supplemental, not real behavior proof.

## What This Changes

The branch changes SSH verification cooldown pruning to stop deleting the oldest entry when that entry has not yet expired.

## Best Possible Solution

Keep active entries intact while preserving bounded admission: define the full-cache behavior before inserting a new cooldown, add a regression test for more than the maximum number of unexpired keys, and provide redacted runtime evidence for the resulting behavior.
