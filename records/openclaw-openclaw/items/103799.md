## Summary

The reported cross-agent memory leak is still present on current main and this PR is the viable candidate fix, but it should not merge yet: the security-sensitive gate duplicates an existing canonical SDK resolver, and the contributor supplied only mocked proof rather than a real two-agent runtime result.

## What This Changes

The PR makes memory-lancedb automatic recall and capture honor each agent’s effective memorySearch.enabled value, normalizes agent IDs, adds regression coverage, and documents the behavior.

## Best Possible Solution

Make memorySearch.enabled authoritative for memory-lancedb automatic recall and capture by resolving the agent through the supported plugin SDK helper, retaining defaults fallback exactly as core does, and proving both blocked hooks in a real two-agent Gateway and LanceDB run; broader explicit-tool or physical-store isolation should remain a separately approved design.
