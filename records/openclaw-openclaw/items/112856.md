## Summary

Keep this issue open. It is a distinct Control UI product-direction request rather than a duplicate of the completed start-screen unification work: the remaining choice is whether suggestions should become the primary returning-user start action and how much prominence recent chats retain.

## What This Changes

Make the Control UI start screen show suggestions even when recent chats exist, with recents reordered, collapsed, dismissed, or otherwise de-emphasized.

## System Context

The Control UI’s empty-chat and `/new` start surfaces introduce a session before the user sends a prompt. The welcome presentation combines the hero, composer, suggestions, and recent-session navigation, then hands the selected session or submitted prompt to the chat workflow.

## Architecture Diagram

flowchart TD
  A[Control UI start route] --> B[Welcome presentation]
  B --> C[Hero and composer]
  B --> D{Existing sessions?}
  D -->|Yes| E[Recent chat navigation]
  D -->|No| F[Starter suggestions]
  E --> G[Resume selected session]
  F --> H[Start a new prompt]

## Best Possible Solution

Adopt suggestions-first rendering for both empty-chat and `/new` when sessions exist, retain recents as a secondary section, and add focused UI coverage; add a persisted preference only if maintainers specifically want per-user control after reviewing the simplified layout.

Options:

- **Show suggestions first (recommended):** Always render the existing suggestions above recents and retain recents as a secondary quick-resume affordance without new settings.
- **Add per-user collapse:** Keep recents prominent by default but add a persisted collapse control for users who prefer a cleaner start screen.
- **Remove start-screen recents:** Use the sidebar as the sole session-navigation surface and keep the start screen focused on starting a new prompt.
