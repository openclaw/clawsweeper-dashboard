## Summary

Current main and the latest release bundle Novita with only a six-row static catalog, while Novita’s live `/v1/models` endpoint currently returns 139 chat routes including the reported model. The request remains useful as a provider-plugin enhancement, but the claim that the selector is completely empty needs version and configuration evidence because an active current provider should show the bundled rows.

## What This Changes

Add live Novita model catalog retrieval so current provider routes appear in model selection and resolve without manual registration.

## Best Possible Solution

Implement deterministic live discovery inside `extensions/novita` using existing provider-catalog helpers and retain the six-row manifest as the failure fallback; do not weaken generic unknown-model validation or add configuration surfaces.

## Solution Assessment

Yes, live discovery with deterministic filtering and static fallback is the narrowest maintainable solution because sibling provider plugins already use that pattern. The change should remain provider-owned rather than accepting arbitrary unknown aliases in core.
