## Summary

Keep open: current main and v2026.6.11 still route generic Telegram callback clicks as `callback_data` while using `callback.id` as the inbound `MessageSid`, so agents still lack a safe source-message id for editing the clicked inline-button message. The target-repo implementation PR is closed unmerged, and the remaining fix needs a deliberate callback metadata/current-message contract.

## What This Changes

The issue asks Telegram `callback_query` turns to expose the source message id so agents can edit the original inline-button message.

## Best Possible Solution

Add a Telegram-owned callback metadata/current-message path that preserves `callback.id` for answering and dedupe while exposing source chat/message ids to generic agent turns and message actions.

## Reproduction Assessment

Yes, source-level: a Telegram `callback_query` with distinct `callback.id` and `callback.message.message_id` reaches current callback paths that pass `callback.id` into `MessageSid`, while the generic agent payload only contains `callback_data`.

## Solution Assessment

No final solution has landed. The best fix is a deliberate source-message metadata/current-message contract, not a direct id swap that can break callback dedupe.
