## Summary

Keep open: current main still lacks a safe agent-visible source message id for generic Telegram callback turns, and the same-repo fix attempt is closed unmerged.

## What This Changes

The issue requests forwarding the source Telegram inline-button message ID to the agent when a callback query is received.

## Best Possible Solution

Add a Telegram-owned callback metadata/current-message path that preserves callback.id for answering and dedupe while exposing source chat/message ids to generic agent turns and message actions.

## Reproduction Assessment

Yes. Source inspection shows a Telegram callback_query with distinct callback.id and callback.message.message_id still reaches paths that pass callback.id into MessageSid while the generic agent payload only carries callback_data.

## Solution Assessment

No final solution has landed. The best fix is a deliberate callback source-message metadata/current-message contract, not a one-line id replacement that could break callback dedupe or callback answering.
