## Summary

Keep open: current main and v2026.6.11 still route generic Telegram callback clicks as `callback_data` while using the opaque `callback.id` as `MessageSid`, so agents still lack the source Telegram message id needed to edit the clicked inline-button message. The same-repo fix PR is closed unmerged, and the remaining open cross-repo PR is stale/conflicting rather than landed evidence.

## What This Changes

Expose the Telegram callback query source chat/message id to agent turns so inline-button callbacks can edit their originating message.

## Best Possible Solution

Define a Telegram-owned callback metadata/current-message contract that preserves `callback.id` for answering and dedupe while exposing the source chat/message ids to agent turns and message actions.

## Reproduction Assessment

Yes, source-level: a Telegram callback query with distinct `id` and `message.message_id` reaches current callback paths that pass `callback.id` into `MessageSid`, while the generic agent payload only contains `callback_data`. I did not run a live Telegram reproduction in this read-only cleanup review.

## Solution Assessment

Unclear as implemented so far: carrying source-message metadata is the right direction, but the best fix must preserve callback query identity for answering/dedupe and wire the source message id into the current-message/tool context deliberately.
