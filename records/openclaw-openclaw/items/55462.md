## Label Justifications

- `P2`: This is a bounded Telegram inline-button workflow gap that affects edit/session flows but does not make the core runtime unusable.
- `impact:session-state`: The missing source-message id prevents the agent from associating a callback turn with the original Telegram message state.

## Summary

Keep open: current main and the latest release still route generic Telegram callback clicks as `callback_data` text while using the opaque `callback.id` as the inbound message id. Plugin-owned callbacks already receive source chat/message metadata, but ordinary agent callback turns still lack the source message id needed for `editMessage`.

## What This Changes

Expose the originating Telegram callback message id to agent-visible callback-query turns so agents can edit the clicked inline-button message.

## Best Possible Solution

Add a Telegram-owned callback metadata/current-message contract that preserves `callback.id` for callback identity while exposing source chat/message ids to generic agent turns, with focused tests and live Telegram callback proof.

## Reproduction Assessment

Yes, source-level: a Telegram `callback_query` with distinct `callback.id` and `callback.message.message_id` reaches current paths that pass `callback.id` into the inbound message id while the agent-visible payload only contains `callback_data`. I did not run live Telegram proof in this read-only sweep.

## Solution Assessment

No final solution has landed. The best fix is an explicit callback source-message metadata contract, not a simple id replacement that could lose callback-query identity or dedupe semantics.
