## Summary

Keep open: current main and the latest release still route generic Telegram callback clicks as agent-visible callback text while using the opaque callback query id as the inbound message id, so agents still lack a safe source message id for editing the clicked inline-button message. The target-repo implementation attempt was closed unmerged, and the remaining fix needs a deliberate callback metadata/current-message contract.

## What This Changes

This issue asks OpenClaw to expose Telegram callback_query source message metadata to agent turns so editMessage can target the original inline-button message.

## Best Possible Solution

A Telegram-owned callback metadata contract should expose source chat/message ids to generic agent turns and message-tool current context while retaining callback.id for Telegram callback answering and callback-event dedupe.

Yes, source-level: current callback_query handling receives callback.message.message_id but routes the generic callback as callback_data text while using callback.id as messageIdOverride. Existing tests already model distinct callback query ids and source message ids.
