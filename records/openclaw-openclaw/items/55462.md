## Label Justifications

## Summary

Keep open: current main and the latest release still route generic Telegram inline-button callbacks as agent-visible `callback_data` text while preserving the opaque callback query id as the inbound message id, so agents still lack a safe source chat/message id for editing the clicked message. The target-repo implementation attempt is closed unmerged, and the remaining work needs a deliberate callback metadata contract rather than cleanup closure.

## What This Changes

The issue requests exposing the Telegram callback query source message id to agent turns so inline-button clicks can drive `editMessage` against the original message.

## Best Possible Solution

Add a Telegram-owned callback source-message metadata path that preserves `callback.id` for answering and dedupe while exposing source chat/message ids to generic agent turns, current-message tool context, prompt metadata, and focused Telegram tests plus live proof.
