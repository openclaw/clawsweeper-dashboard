## Summary

Keep open: current main and v2026.6.11 still route generic Telegram callback clicks as `callback_data` text while using the opaque callback query id as the inbound message id, so agents still do not get the source Telegram message id needed for `editMessage`. The same-repo implementation attempt is closed unmerged, and the remaining fix needs a deliberate callback metadata/current-message contract rather than cleanup closure.

## What This Changes

Expose the Telegram inline-button callback source message id to agent turns so agents can edit the original callback message.

## Best Possible Solution

Add a Telegram-owned callback metadata/current-message path that preserves `callback.id` for answering and dedupe while exposing source chat/message ids to generic agent turns and message actions across fallback and managed callback paths.

## Reproduction Assessment

Yes. Source inspection shows a callback update with distinct `callback.id` and `callback.message.message_id` reaches paths that expose only `callback_data` and use `callback.id` as `MessageSid`.

## Solution Assessment

No final solution has landed. The best path is not a literal id replacement, but a callback source-message metadata/current-message contract that also preserves callback query identity for dedupe and answering.
