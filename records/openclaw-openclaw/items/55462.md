## Label Justifications

- `P2`: This is a bounded Telegram channel workflow bug affecting inline-button edit/session flows without making the core runtime unusable.
- `impact:session-state`: The issue is about preserving the correct source-message context across a Telegram callback turn instead of exposing only an opaque callback query id.

## Summary

Keep open: current main and v2026.6.11 still route generic Telegram callback turns with `callback.id` as `MessageSid` and no separate callback source-message field. The same-repo fix PR is closed unmerged, and the remaining fork PR is conflicting, so this issue remains the canonical tracker.

## What This Changes

The issue requests forwarding the source Telegram callback message id to the agent so `editMessage` can update the clicked inline-button message.

## Best Possible Solution

Add a Telegram-owned callback metadata/current-message path that preserves `callback.id` for answering and dedupe while exposing source chat/message ids to generic agent turns and message actions, with focused regression tests and live Telegram proof.

## Reproduction Assessment

Yes, source-level. A Telegram `callback_query` with distinct `callback.id` and `callback.message.message_id` reaches current callback paths that pass `callback.id` into `MessageSid`, while the generic agent payload only contains `callback_data`.

## Solution Assessment

No final fix has landed. The best fix is a deliberate callback source-message metadata/current-message contract, not a simple id replacement that could break callback dedupe or callback answering.
