## Summary

Keep open: current main and v2026.6.11 still route generic Telegram callback clicks as `callback_data` text while using the opaque callback query id as the inbound message id, so generic agent turns still lack the source chat/message id needed for `editMessage`. The same-repository fix attempt is closed unmerged, and the remaining open fork PR is dirty/no-proof, so this issue remains the canonical tracker pending a maintainer-approved metadata contract.

## What This Changes

The issue asks OpenClaw to expose the Telegram callback query source message id to generic agent turns so inline-button handlers can edit the original message.

## Best Possible Solution

Add a Telegram-owned callback source-message metadata path that preserves `callback.id` for answering and dedupe while exposing source chat/message ids to generic agent turns, current-message tool context, focused tests, docs, and live Telegram proof.
