## Summary

Keep open: current main and v2026.6.11 still route generic Telegram inline-button callbacks as agent-visible `callback_data` text while using the opaque callback query id as the inbound message id, so the requested source-message id for editing the clicked message is not implemented. The same-repo fix PR is closed unmerged, and the remaining work needs a deliberate callback metadata/current-message contract rather than cleanup closure.

## What This Changes

The issue asks for generic Telegram inline-button callback turns to expose the originating Telegram `message_id` so agents can edit the clicked message.

## Best Possible Solution

Add a Telegram-owned callback metadata/current-message path that preserves callback query identity for answering and dedupe while exposing source chat/message ids to generic agent turns, templates/tool context, and edit-message workflows.

## Reproduction Assessment

Yes, source-level: a Telegram callback query with distinct `callback.id` and `callback.message.message_id` reaches the generic fallback path that only sends `callback_data` to the agent and overrides the inbound id with `callback.id`. No live Telegram click was run in this read-only review.

## Solution Assessment

No; no final solution is on main, and the literal raw-text field proposal is only a plausible shape. The best fix is a typed callback metadata/current-message contract that also accounts for dedupe, `answerCallbackQuery`, managed select callbacks, templates, and message-action current-message routing.
