## Summary

Keep open: current main and v2026.6.11 still route ordinary Telegram callback clicks as agent-visible `callback_data` text while using `callback.id` as the inbound message id, so agents still lack the source Telegram message id needed to edit the clicked inline-button message. The same-repo fix PR is closed unmerged, the open fork PR is conflicting and outside the target repo, and adjacent poll/callback cleanup work does not resolve this contract gap.

## What This Changes

The issue asks OpenClaw to expose the Telegram source message id from `callback_query.message.message_id` to agent turns so inline-button callbacks can edit their originating message.

## Best Possible Solution

Add a Telegram-owned callback metadata/current-message path that preserves `callback.id` for answering and dedupe while exposing the source chat/message ids to generic agent turns, templates/tool context, and message edit flows.

## Reproduction Assessment

Yes, source-level. A Telegram `callback_query` fixture with distinct `callback.id` and `callback.message.message_id` reaches current callback paths that pass `callback.id` into `MessageSid`, while the ordinary agent-visible payload only contains `callback_data`.

## Solution Assessment

No final fix has landed. The right direction is not a raw one-line id swap; the best fix should carry callback source-message metadata separately while preserving callback-query identity for answering and dedupe.
