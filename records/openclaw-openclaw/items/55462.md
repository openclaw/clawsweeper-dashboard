## Label Justifications

- `P2`: This is a bounded Telegram channel workflow bug affecting inline-button edit/session flows without making the core runtime unusable.
- `impact:session-state`: The issue is about preserving the correct source-message context across a Telegram callback turn instead of substituting the opaque callback query id.

## Summary

Keep open: current main and the latest release still expose generic Telegram inline-button clicks only as `callback_data` text while using the opaque callback query id as the inbound message id, so agents still lack a reliable source message id for editing the clicked message. The prior target-repo fix PR is closed unmerged, and the remaining work needs a deliberate callback metadata/current-message contract.

## What This Changes

Expose the Telegram `callback_query.message.message_id` and related chat context to agent turns so agents can edit the original inline-button message.

## Best Possible Solution

Add a Telegram-owned callback metadata/current-message contract that preserves `callback.id` for answer/dedupe while exposing the source chat and message ids to generic agent turns and edit actions.

## Reproduction Assessment

Yes, source-level: a Telegram `callback_query` with distinct `callback.id` and `callback.message.message_id` reaches current callback paths that pass `callback.id` into the inbound message id while the generic payload only contains `callback_data`. I did not run a live Telegram probe in this read-only cleanup review.

## Solution Assessment

No final solution has landed. The best fix is a deliberate callback source-message metadata/current-message contract, not a simple id replacement that could break callback dedupe or callback answering.
