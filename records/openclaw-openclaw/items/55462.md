## Summary

Keep open: current main and the latest release still route generic Telegram callback clicks as `callback_data` text while using the opaque callback query id as the inbound message id, so agents still do not get the source Telegram message id needed to edit the clicked inline-button message. The target-repo implementation attempt is closed unmerged, and the remaining fix needs a maintainer decision on the callback metadata/current-message contract.

## What This Changes

The issue asks OpenClaw to expose the originating Telegram `callback_query.message.message_id` to agent turns so inline-button callbacks can edit their source message.

## Best Possible Solution

Add a Telegram-owned callback metadata/current-message path that preserves callback query identity for Telegram callback handling while exposing source chat and message ids to generic agent turns and message actions.

## Reproduction Assessment

Yes, source-level: a Telegram `callback_query` with distinct `callback.id` and `callback.message.message_id` reaches current callback paths that pass `callback.id` into `MessageSid`, while the generic agent payload only contains `callback_data`. I did not run a live Telegram click in this read-only review.

## Solution Assessment

Unclear until maintainers choose the contract: carrying source chat/message ids is the right direction, but the fix should preserve callback query identity and update current-message/tool metadata consistently rather than only swapping one id field.
