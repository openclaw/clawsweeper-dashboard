## Label Justifications

- `P2`: This is a bounded Telegram channel workflow bug affecting inline-button edit flows without making the core runtime unusable.
- `impact:session-state`: The issue is about preserving the correct Telegram source-message context across callback turns instead of substituting the opaque callback query id.

## Summary

Keep open: current main and v2026.6.11 still route unclaimed Telegram inline-button callbacks as `callback_data` text and keep the opaque callback query id as the inbound message id, so agents still lack a safe source Telegram message id for editing the clicked message.

## What This Changes

Telegram inline-button callback turns should expose the source Telegram message id so agents can edit the clicked message.

## Best Possible Solution

Add a Telegram-owned callback metadata/current-message contract that preserves callback query identity for dedupe and answering while exposing source chat and message ids to ordinary agent turns and edit actions.

## Reproduction Assessment

Yes, source-level: a Telegram callback query with distinct `callback.id` and `callback.message.message_id` reaches fallback paths that pass `callback.id` into the inbound message id while only sending `callback_data` text to the agent.

## Solution Assessment

No final solution has landed. The safest fix needs a deliberate callback metadata/current-message contract, not a simple replacement that could collapse repeated clicks on one message into the same inbound id.
