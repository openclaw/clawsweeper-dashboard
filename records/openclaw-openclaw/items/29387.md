## Label Justifications

- `P1`: The issue affects a real multi-agent bootstrap workflow where users can run agents without the rules or identity context they believed were active.
- `impact:session-state`: The reported behavior is agent context drift: bootstrap files placed under the configured agent scope are absent from the session prompt while workspace files are injected.
- `impact:security`: An ignored agentDir/AGENTS.md can leave intended safety or access-control rules unenforced with no current warning.

## Summary

Keep open: current main and the latest release still load bootstrap files only from the resolved workspace directory, while three open closing PRs already cover the competing fix directions. The issue should stay open until maintainers choose and land either the warning-only path or the behavior-changing agentDir merge path.

## What This Changes

The issue asks OpenClaw to stop silently ignoring bootstrap-named files in per-agent agentDir, either by loading them with workspace files or warning and documenting the workspace-only contract.

## Best Possible Solution

Review and land one canonical linked PR after maintainers choose the policy: preferably the warning-only diagnostic if agentDir should remain runtime state, or a carefully gated agentDir merge if per-agent bootstrap from agentDir is accepted.

## Reproduction Assessment

Yes, source-level: with SOUL.md or AGENTS.md only under agentDir, current main only enumerates bootstrap files from workspaceDir, so the agentDir file cannot be injected. I did not run a live agent turn in this read-only review.

## Solution Assessment

Unclear until maintainers choose the policy. A warning-only fix is the lowest-risk repair for the silent failure, while loading/overriding from agentDir is a broader behavior change that needs security and upgrade review.
