## Summary

Keep open: current main and the latest release still load bootstrap files from the workspace path only, and three open closing PRs now represent competing fix policies that need maintainer choice before this issue can close.

## What This Changes

The issue requests a fix for per-agent agentDir bootstrap files being silently ignored, either by loading them into prompt context or warning users that only workspace bootstrap files apply.

## Best Possible Solution

Choose and land one maintainer-approved bootstrap authority policy: either explicit configured-agentDir loading with diagnostics/docs/tests/security proof, or warning-only diagnostics that document workspace as the sole bootstrap source.

## Maintainer Decision

Required: true

Rationale: Both choices are plausible but have different security and compatibility tradeoffs, and current open PRs implement different policies.

Likely owner: steipete

Options:

- **Choose warning-only diagnostics (recommended):** Keep workspace bootstrap files canonical, land a warning/docs path, and leave per-agent prompt customization to per-agent workspace configuration.
- **Choose explicit agentDir loading:** Allow configured agentDir files to merge or override workspace bootstrap files, but require precedence docs, doctor/diagnostic alignment, focused tests, and real-run proof.
- **Keep the issue open for design:** Pause all linked PRs until maintainers settle the prompt-authority and upgrade policy in one canonical design comment.

## Solution Assessment

Unclear as a product matter: warning-only is the lower-risk mitigation, while agentDir loading better satisfies per-agent customization but changes prompt authority and upgrade behavior.
