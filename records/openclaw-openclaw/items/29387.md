## Summary

Keep this issue open: current main and the latest release still resolve bootstrap prompt files from the configured workspace only, while three open linked PRs are candidate fixes with different policy tradeoffs. The issue should remain the canonical thread until maintainers choose and land either warning-only diagnostics or explicit agentDir prompt authority.

## What This Changes

The issue asks OpenClaw to stop silently ignoring bootstrap prompt files placed in an explicitly configured per-agent agentDir, either by loading/merging them or warning users that only workspace files are injected.

## Best Possible Solution

Choose one linked fix path and land it with matching docs, tests, and security review: warning-only if workspace remains canonical, or explicit agentDir bootstrap loading if maintainers approve that prompt-authority boundary.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 load bootstrap metadata from workspaceDir only, and the runtime caller passes sessionAgentId into that resolver. I did not run a live OpenClaw session in this read-only review.

## Solution Assessment

Unclear as a final product direction: warning-only diagnostics are a lower-risk fix for silent failure, while agentDir loading is a broader prompt-authority change that needs maintainer/security approval.
