## Summary

Keep open: current main and the latest release still resolve bootstrap prompt files from the agent workspace only, while open linked PRs propose different warning-only versus agentDir-loading policies that need maintainer/security choice.

## What This Changes

The issue asks OpenClaw to stop silently ignoring bootstrap prompt files placed in a configured per-agent agentDir, either by loading them or warning clearly.

## Best Possible Solution

Keep bootstrap prompt files workspace-owned unless maintainers explicitly accept an agentDir trust-boundary expansion; land either a warning/doctor/docs path or a reviewed loading policy with security and upgrade proof.

Rationale: The current source and docs support workspace-owned bootstrap files, but user reports and open PRs show real silent-misconfiguration risk; loading agentDir files would change a security-sensitive prompt source and needs maintainer intent.

Options:

- **Land warning-only diagnostic (recommended):** Preserve workspace as the only bootstrap prompt source, warn when bootstrap-named files are found in agentDir, and update docs/doctor guidance for the self-serve fix.
- **Adopt explicit agentDir loading:** Treat explicitly configured agentDir as a trusted per-agent bootstrap source, but require clear merge/override rules, tests across run paths, and security review before merge.
- **Defer pending design:** Keep the issue open and ask contributors to pause implementation until maintainers decide the permanent prompt-source boundary.
