## Summary

Keep open: current main and v2026.6.11 still resolve bootstrap prompt files from the workspace path only, while the open linked PRs represent competing warning-only versus agentDir-loading policies that need maintainer security-boundary choice.

## What This Changes

The issue asks OpenClaw to stop silently ignoring bootstrap-named files placed in a configured per-agent agentDir, either by loading/merging them or by warning and documenting the workspace-only behavior.

## Best Possible Solution

Keep agentDir state-only unless maintainers explicitly approve it as a prompt source; at minimum land a warning/doctor/docs path so misplaced bootstrap files are visible, with coverage for CLI and embedded runs.

## Maintainer Decision

Question: Should configured agentDir bootstrap-named files become an injected prompt source, or should agentDir remain state-only with warnings/docs when users put bootstrap files there?

Rationale: agentDir stores auth/session/model state, while workspace is the documented prompt/file context boundary; changing that boundary affects security expectations and upgrade behavior beyond a mechanical bug fix.

Likely owner: steipete

Owner reason: The bootstrap resolver history and current blamed implementation point to steipete as the best available owner for this prompt-context boundary decision.

Owner confidence: high

Options:

- **Warn and document state-only agentDir (recommended):** Land the warning/doctor/docs approach so users learn to move AGENTS.md/SOUL.md into the per-agent workspace without making agentDir a prompt source.
- **Load explicit agentDir bootstrap files:** Land an agentDir-loading PR only if maintainers want agentDir to become part of the prompt trust boundary and require upgrade/security tests for override and merge behavior.
- **Docs-only behavior clarification:** Clarify the current workspace-only contract without runtime diagnostics, accepting that misplaced safety rules may still fail silently until users read the docs.
