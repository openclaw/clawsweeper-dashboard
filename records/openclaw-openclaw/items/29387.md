## Summary

Keep open: current main and the latest release still load bootstrap context from the workspace path only and do not warn about bootstrap-named files under an explicitly configured agentDir. The issue is already paired with open closing PRs, but those PRs represent different policy choices, so maintainers should review one of them rather than closing this issue early.

## What This Changes

The issue asks OpenClaw to stop silently ignoring SOUL.md, AGENTS.md, TOOLS.md, and related bootstrap files placed in a configured per-agent agentDir.

## Best Possible Solution

Choose one bootstrap authority policy and land a linked PR: either explicit agentDir bootstrap precedence with docs, diagnostics, tests, and upgrade proof, or warning-only diagnostics that keep workspace as the canonical bootstrap source.

## Reproduction Assessment

Yes, source-level. Current main and v2026.6.11 resolve bootstrap metadata from workspaceDir only, while runtime callers already carry the session agent id; I did not run a live OpenClaw session in this read-only review.

## Solution Assessment

Unclear as a final product direction. Warning-only is the lower-risk mitigation if workspace remains canonical, while agentDir loading solves per-agent customization but needs maintainer/security approval for the prompt-authority boundary.
