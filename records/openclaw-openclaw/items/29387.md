- `impact:security`: The issue is about users believing safety or access-control instructions in agentDir/AGENTS.md are active when they are not injected.

## Summary

Keep open: current main and v2026.6.11 still load bootstrap context from the resolved workspace only, while three open closing PRs already cover the possible fix paths. The remaining decision is whether maintainers want warning-only behavior or agentDir bootstrap precedence, because that affects prompt authority and security expectations.

## What This Changes

The issue asks OpenClaw to stop silently ignoring bootstrap-named files placed in a configured per-agent agentDir, either by warning users or by loading/merging those files with workspace bootstrap context.

## Best Possible Solution

Review and land one chosen closing PR: warning-only plus docs if agentDir remains state-only, or a carefully scoped agentDir bootstrap implementation with explicit precedence, security proof, and upgrade tests.

## Reproduction Assessment

Yes, source-level. Current main resolves bootstrap metadata from workspaceDir only and does not inspect agentDir for either warning or merge behavior; I did not run a live agent setup in this read-only review.

## Solution Assessment

Unclear. Warning-only is the narrowest low-risk repair, while agentDir merge/override satisfies per-agent customization but needs maintainer approval for prompt-authority precedence.
