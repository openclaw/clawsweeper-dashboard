## Summary

Keep open: current main and the latest release still resolve bootstrap files from the workspace path only, while three open linked pull requests propose competing fix shapes that need maintainer review before this issue can close.

## What This Changes

The issue asks OpenClaw to stop silently ignoring bootstrap-named files placed in a configured per-agent agentDir, either by loading/merging them or warning users to move them into the workspace.

## Best Possible Solution

Maintainers should choose one contract, land or close the competing linked PRs, and ensure the selected path has focused resolver tests plus docs that make `workspace` versus `agentDir` behavior explicit.

## Reproduction Assessment

Yes, source-level: current main calls `loadWorkspaceBootstrapFiles(params.workspaceDir)` and never reads a configured `agentDir` in the bootstrap resolver. I did not run a live agent session in this read-only cleanup review.

## Solution Assessment

Unclear: the issue’s warning-only and agentDir-loading directions are both plausible, but they create different security and compatibility contracts. The best fix needs maintainer selection rather than a new unsponsored repair PR.
