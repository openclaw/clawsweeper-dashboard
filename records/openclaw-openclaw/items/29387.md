## Summary

Keep open: current main and the latest release still load bootstrap context from the resolved workspace, not from agentDir, and no warning exists for bootstrap-named files placed in agentDir. The issue is already paired with open closing PRs, so the right cleanup is maintainer review of those candidates rather than closing or queuing another fix.

## What This Changes

The issue asks OpenClaw to stop silently ignoring bootstrap files placed in per-agent agentDir, either by loading/merging them or by warning and documenting that workspace files are the supported prompt-injection source.

## Best Possible Solution

Maintainers should choose and land one canonical fix: either a low-compatibility-risk warning/docs path for misplaced agentDir bootstrap files or an explicitly accepted, tested agentDir bootstrap-loading contract that preserves per-agent workspace behavior and security diagnostics.

## Reproduction Assessment

Yes, source-level. Current main resolves bootstrap files from params.workspaceDir only, resolveAgentDir is separate, and there is no diagnostic for bootstrap-named files in agentDir.

## Solution Assessment

Unclear until maintainers choose the product boundary. Warning-only is the narrowest safe mitigation, while loading agentDir files may be acceptable only if maintainers explicitly want agentDir to become a bootstrap source.
