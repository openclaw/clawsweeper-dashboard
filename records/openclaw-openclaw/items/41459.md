## Summary

Keep open: current main and v2026.6.11 still do not expose a per-binding Discord visible-identity override, and the remaining work needs maintainer product/security direction before implementation.

## What This Changes

The issue requests an optional Discord binding-level nickname or identity override so one bot token can show different visible agent names per bound channel.

## Best Possible Solution

Have maintainers approve one Discord plugin-owned visible-identity model, likely webhook persona delivery if accepted, with explicit schema, credential handling, docs, tests, and live Discord proof.

Rationale: The current code lacks the requested surface, and any implementation creates a new public config/API plus bot-credential-backed identity behavior that automation should not choose without maintainer product and security intent.

- **Coordinate with self-profile work:** Treat this as part of the Discord self-profile decision and add nickname/avatar mutation only if maintainers accept the cross-channel identity semantics and security boundary.
- **Defer per-binding identity:** Keep current bot-account replies plus thread-bound webhook persona behavior and ask users to use multiple bot accounts or existing thread-bound flows for now.
