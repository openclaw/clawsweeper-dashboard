## Summary

Keep open: current main and v2026.6.11 still do not expose a per-binding Discord nickname or ordinary routed-reply identity override; the existing webhook username/avatar path is limited to thread-bound delivery and this remains a product/security decision.

## What This Changes

The issue requests an optional Discord binding identity override so one bot token can display different agent names per channel.

## Best Possible Solution

Have maintainers choose one Discord plugin-owned visible-identity model, likely webhook persona delivery if approved, with explicit schema, credential handling, docs, tests, and live Discord proof.
