## Summary

Keep open: current main still does not expose a Discord binding-level nickname or ordinary routed-reply visible identity override, and the remaining work needs maintainer product/security direction because the literal nickname proposal collides with Discord's guild-level profile semantics while webhook persona delivery is a separate public contract choice.

## What This Changes

The issue requests an optional Discord binding `nickname` field so one bot token can present different agent names in different Discord channels.

## Best Possible Solution

Have maintainers choose one Discord plugin-owned visible identity model, likely webhook persona delivery if approved, with explicit schema, credential handling, fallback behavior, docs, tests, and live Discord proof.
