## Summary

Keep open: current main and v2026.6.11 still lack a per-binding Discord nickname or ordinary routed-reply identity override; existing webhook username/avatar delivery is limited to thread-bound flows, so the remaining work needs maintainer product and security direction.

## What This Changes

Request adds an optional Discord binding-level nickname or identity override so one bot token can display different agent names per bound channel.

## Best Possible Solution

Have maintainers choose one Discord plugin-owned visible-identity model, likely webhook persona delivery if approved, with explicit schema, credential handling, docs, tests, and live Discord proof.
