## Summary

Keep open: current main and the latest release still lack a per-binding Discord nickname or ordinary routed-reply identity override, and the remaining work requires maintainer product/security direction before implementation.

## What This Changes

The issue requests an optional Discord binding identity override so one bot token can present different visible names per routed channel or agent.

## Best Possible Solution

Maintainers should choose one Discord plugin-owned visible identity model, then implement it with explicit config schema, credential handling, fallback behavior, docs, tests, and live Discord proof.
