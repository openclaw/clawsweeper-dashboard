## Summary

Keep open: current main and v2026.6.11 still lack a per-binding Discord nickname or ordinary routed-reply identity override; existing webhook username/avatar delivery is limited to thread-bound flows, so this needs maintainer product and security direction.

## What This Changes

The issue requests an optional Discord binding-level nickname/identity override so one Discord bot token can present different agent names in different channels.

## Best Possible Solution

Have maintainers choose one Discord plugin-owned visible-identity model, likely webhook persona delivery if approved, with explicit schema, credential handling, docs, tests, and live Discord proof.
