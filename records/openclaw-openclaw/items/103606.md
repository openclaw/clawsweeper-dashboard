## Label Justifications

- `P1`: The maintained Kubernetes workflow restarts the Gateway for every apply, while current source can also lose unapplied paths after ignored or failed reload revisions.
- `impact:session-state`: Restart-based reconciliation interrupts active Gateway connections and can discard process-local agent or session work.
- `impact:ux-friction`: GitOps operators must force deployment rollouts for ordinary config updates instead of receiving in-place reconciliation.
- `maturity:stable`: The issue affects the M4 Stable `gateway-runtime` and `linux-gateway-host` capabilities.

## Summary

Keep open: current main and the latest release still use copied PVC config plus forced Kubernetes rollouts, and the current reloader can baseline ignored or failed revisions; the requested ownership mode is not implemented and needs explicit maintainer product direction.

## What This Changes

Add an externally owned, hot-reloadable root configuration mode for Kubernetes-style projected config while separating mutable state and preserving the last successfully applied reload baseline.

## Best Possible Solution

Generalize the immutable-config guard into an explicit owner model, advance reload comparison state only after successful or committed application, and mount projected Kubernetes config separately from writable state.
