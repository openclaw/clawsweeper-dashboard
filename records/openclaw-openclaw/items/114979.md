## What This Changes

Update Control UI chat-transcript memoization so MCP app Pin controls refresh when a Gateway dashboard provider changes its `canPinMcpApps` capability without changing identity or revision.

## System Context

The Control UI renders Gateway-backed chat transcripts and derives MCP app actions from the current dashboard provider capabilities. Transcript memoization sits between provider updates and widget-card rendering, so omitted capability inputs can leave visible controls stale.

## Architecture Diagram

flowchart LR
  A[Gateway dashboard provider] --> B[Provider capability update]
  B --> C[Chat transcript memoization]
  C --> D[Rendered MCP app widget]
  D --> E[Visible Pin action]
  F[Provider identity and revision] --> C

## Best Possible Solution

Make the transcript’s memoization key/dependencies include the MCP pin capability used by widget rendering, then retain a regression test that toggles the capability with the same provider identity and revision in both directions.
