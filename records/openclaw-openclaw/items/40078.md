## Summary

Keep open: current main and the latest release still lack the requested default-off Discord silent transcription history mode for unmentioned audio in requireMention channels, and adding it requires maintainer product/security direction rather than conservative cleanup.

## What This Changes

The issue requests a per-guild or per-channel Discord option that silently transcribes unmentioned audio in requireMention channels, stores the transcript in history, and suppresses a bot reply until a later mention.

## Best Possible Solution

Define a Discord-owned, default-off silent transcription policy with consent, retention, cost bounds, inheritance semantics, schema/docs, and focused requireMention history tests before wiring it into preflight/history.

## Reproduction Assessment

Yes, at source level: current Discord preflight can transcribe audio for mention detection, but skipped requireMention messages record history from placeholder text and return before dispatch. I did not run a live Discord plus STT reproduction in this read-only review.

## Solution Assessment

No, not as a bare boolean alone. The maintainable solution needs a default-off Discord policy with consent, retention, cost, inheritance, schema, docs, and tests rather than only wiring transcription before the skip return.
