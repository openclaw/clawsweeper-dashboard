## Label Justifications

- `P2`: The issue blocks a bounded Discord voice-memo workflow, but the fix is an opt-in feature/config decision rather than a core outage.
- `impact:session-state`: The requested behavior changes what derived transcript state is retained in channel history and replayed into later turns.
- `impact:security`: Silent transcription would process speech from Discord messages that did not explicitly invoke OpenClaw.
- `impact:message-loss`: Later mentioned turns currently receive audio placeholders instead of usable spoken content for earlier voice messages.
- `maturity:stable`: The affected Discord channel surface is M4 Stable in the maturity docs, including conversation routing and media-rich channel behavior.

## Summary

Keep open: current main and v2026.6.11 still lack a Discord `preflightTranscribe` or equivalent silent no-mention transcript-retention mode, and the remaining work needs explicit product/security direction before implementation.

## What This Changes

Add an opt-in Discord guild/channel mode that transcribes unmentioned audio in `requireMention` channels, suppresses replies, and stores transcripts for later mentioned turns.

## Best Possible Solution

Define a Discord-owned, default-off silent transcription policy with consent, retention, cost, inheritance, schema, docs, and focused requireMention history tests before wiring it into preflight/history.

No, not as a bare boolean alone. The maintainable solution needs a default-off Discord policy with consent, retention, cost, inheritance, schema, docs, and tests rather than only wiring transcription before the skip return.
