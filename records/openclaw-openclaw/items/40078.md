## Summary

Keep open: current main and v2026.6.11 still lack the requested Discord silent transcript-history mode for unmentioned audio in requireMention channels, and adding it needs maintainer product/security direction rather than conservative cleanup.

## What This Changes

The issue requests a default-off guild or channel option that silently transcribes unmentioned Discord audio so later mentioned turns can use transcript history.

## Best Possible Solution

Define a Discord-owned, default-off silent transcription policy with consent, retention, provider-cost bounds, inheritance semantics, schema/docs, and focused requireMention history tests before wiring it into preflight history.

## Reproduction Assessment

Yes, from source inspection: current Discord preflight can transcribe authorized audio before mention checks, but if the message is still skipped by requireMention, pending history is recorded from the original placeholder text rather than the transcript. I did not run a live Discord plus STT scenario in this read-only review.

## Solution Assessment

No, the current implementation is not enough to close this issue: it helps mention detection and admitted-message dispatch, but not the requested default-off silent transcript history mode. The better solution needs an explicit Discord-owned policy with schema, docs, tests, and privacy/cost bounds.
