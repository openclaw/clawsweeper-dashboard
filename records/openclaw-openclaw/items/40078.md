## Label Justifications

- `P2`: The issue blocks a bounded Discord voice-memo workflow, but the fix is an opt-in feature/config decision rather than a core runtime outage.
- `impact:session-state`: The requested behavior changes what derived transcript state is retained in Discord channel history and replayed into a later turn.
- `impact:security`: Silent transcription would process speech from Discord messages that did not explicitly invoke OpenClaw.
- `impact:message-loss`: Later mentioned turns currently receive audio placeholders instead of usable spoken content for earlier voice messages.
- `maturity:stable`: The affected Discord channel surface is scored M4 Stable in `qa/maturity-scores.yaml`, including media-rich channel behavior.

## Summary

Keep open: current main and v2026.6.11 still lack a Discord `preflightTranscribe` or equivalent silent no-mention transcript-retention mode, and the remaining work needs maintainer product/security direction before implementation.

## What This Changes

Request adds silent Discord audio transcription for unmentioned messages in `requireMention` channels so later mentioned turns can use the transcript from history.

## Best Possible Solution

Define a Discord-owned, default-off silent transcription policy with consent, retention, cost, inheritance, schema, docs, and focused requireMention history tests before wiring it into the existing preflight/history paths.

## Reproduction Assessment

Yes, source-level: current Discord preflight can transcribe audio for mention detection, but if no mention is found it records pending history from placeholder text and returns. I did not run a live Discord plus STT reproduction in this read-only review.

## Solution Assessment

No, not as a bare boolean alone. The maintainable solution needs a default-off Discord policy with consent, retention, cost, inheritance, schema, docs, and tests rather than only wiring transcription before the skip return.
