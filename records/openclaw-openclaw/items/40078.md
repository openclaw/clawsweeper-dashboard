## Label Justifications

- `P2`: The issue blocks a bounded Discord voice-memo workflow, but the fix is an opt-in feature/config decision rather than a core outage.
- `impact:session-state`: The requested behavior changes whether derived audio transcripts are retained in channel history and replayed into later context.
- `impact:security`: Silent transcription would process speech from Discord messages that did not explicitly invoke OpenClaw.
- `impact:message-loss`: Later mentioned turns currently receive placeholder media history instead of usable spoken content for earlier voice messages.
- `maturity:stable`: The affected Discord channel surface is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and the latest release still lack a default-off silent Discord transcription mode for skipped `requireMention` messages, and the remaining work needs product/security approval before implementation.

## What This Changes

The issue requests a Discord guild/channel option that silently transcribes unmentioned audio while `requireMention` stays enabled, so later mentioned turns can use those transcripts from history.

## Best Possible Solution

Define a Discord-owned, default-off silent transcription policy with consent, retention, cost, inheritance, schema/docs, and focused `requireMention` history tests before implementation.

## Reproduction Assessment

Yes at source level: current Discord preflight can create a transcript for mention detection, but the no-mention skip path records pending history from the pre-built text entry and returns before transcript-backed context is built. I did not run live Discord plus STT proof in this read-only review.

## Solution Assessment

No, not as a bare boolean alone. The maintainable solution needs a default-off Discord policy covering consent, retention, cost, inheritance, schema, docs, and tests rather than only wiring transcription before the skip return.
