## Summary

Keep open. Current main and the latest release still synthesize visible Signal media placeholder text for blank audio/media sends, while the requested `messages` suppression option is absent; the iMessage-specific symptom was fixed separately, so the remaining work is a Signal/config product decision.

## What This Changes

The issue requests an opt-in messages configuration option to suppress visible media placeholder text such as `<media:audio>` for media-only messaging sends.

## Best Possible Solution

Keep this as the canonical product/config request; maintainers should choose a default-preserving policy, then implement Signal media-only suppression with schema/docs updates and focused regression proof without disturbing the iMessage fix.

## Reproduction Assessment

Yes, at source level: a blank Signal media send with an `audio/*` attachment flows from `deliverReplies` into `sendMessageSignal`, maps to `audio`, and sends `<media:audio>` as the RPC body. I did not run a live Signal client in this read-only review.

## Solution Assessment

Unclear. The requested global config option is plausible, but OpenClaw's config-surface bar is high and iMessage was fixed channel-locally, so maintainers should choose between a default-off `messages` option and a narrower Signal hidden-body policy before implementation.
