## Summary

Keep open. Current main and the latest release still synthesize visible Signal media-placeholder text for blank audio/media sends, while the requested strict `messages` suppression option is absent; iMessage was fixed separately, but the central Signal/config request remains a maintainer product decision.

## What This Changes

Request a default-off configuration option to suppress visible `<media:audio>` or related media placeholder text when sending audio/voice media through messaging channels.

## Best Possible Solution

Keep this as the canonical product/config request and choose either a documented default-off `messages` option or a narrower Signal hidden-body policy, preserving default fallback behavior and adding focused Signal media-only regression proof.

## Reproduction Assessment

Yes, at source level: a blank Signal media send with an `audio/*` attachment maps to `audio` and sends `<media:audio>` as the RPC body. No live Signal client was exercised in this read-only review.

## Solution Assessment

Unclear: the requested global config option is plausible, but maintainers should choose between a strict `messages` config surface and a narrower Signal transport policy because iMessage was fixed channel-locally.
