## Summary

Keep open. Current main still synthesizes visible Signal media-placeholder text for blank audio/media sends and the requested strict `messages` suppression option is absent, while the iMessage sibling fix only addresses one channel-specific branch.

## What This Changes

Request a default-off `messages` configuration option or equivalent channel policy to suppress visible `<media:audio>` placeholder text for media-only voice/audio sends.

## Best Possible Solution

Keep this as the canonical product/config tracker and have maintainers choose between a documented default-off `messages` option and a Signal-owned hidden-body policy while preserving the default fallback behavior.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes, at source level: a blank Signal media send with an `audio/*` attachment maps to `audio` and sends `<media:audio>` as the RPC body.

## Solution Assessment

Is this the best way to solve the issue? Unclear. The requested global config option is plausible, but current main fixed iMessage channel-locally, so maintainers should decide whether the remaining solution is Signal-specific delivery behavior or cross-channel messages policy.
