## Summary

Keep open. Current main and the latest release still synthesize visible Signal `<media:audio>` placeholder text for blank audio/media sends, and the strict `messages` config surface still has no suppression option; the iMessage half was fixed separately, but the central Signal/product-config request remains.

## What This Changes

The issue requests a default-preserving option to suppress automatic `<media:audio>` or other media placeholder text for media-only outbound messages.

## Best Possible Solution

Decide the product shape first, then either add a documented default-off `messages` or channel option with schema/help/docs coverage, or implement a narrower Signal hidden-body policy while preserving existing fallbacks and iMessage's internal echo-key behavior.

## Reproduction Assessment

Yes, from source inspection: a blank Signal media send maps audio MIME types to `audio` and then sends `<media:audio>` as the message body. I did not run a live Signal channel repro in this read-only review.

## Solution Assessment

Unclear. The requested config option is plausible, but maintainers should first choose whether the best fix is a default-off core/messages option or a narrower channel-owned hidden-body policy.
