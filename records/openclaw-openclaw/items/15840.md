## Summary

Keep open. Current main and the latest release still lack the requested suppression option, and Signal still fills blank audio/media sends with a visible media placeholder; the iMessage-only overlap was fixed separately, so the remaining work is a Signal/config product decision.

## What This Changes

Request a default-off way to suppress visible `<media:audio>` or `<media:...>` placeholder text for media-only audio/voice sends, especially Signal TTS voice messages.

## Best Possible Solution

Keep this as the canonical request; maintainers should choose a default-preserving global `messages` policy or Signal-specific hidden-body policy, then update schema/help/docs and focused Signal media-only tests without disturbing the iMessage fix.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: a blank Signal media send with an `audio/*` attachment flows into `sendMessageSignal`, maps to `audio`, and sends `<media:audio>` as the RPC body; no live Signal client was run.

## Solution Assessment

Is this the best way to solve the issue? Unclear: the requested global config option is plausible, but iMessage was solved channel-locally and Signal may need a hidden non-empty body, so maintainers should choose the product surface before implementation.
