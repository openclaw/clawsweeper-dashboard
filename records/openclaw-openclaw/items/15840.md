## Summary

Keep open. Current main and the latest release still synthesize visible Signal media-placeholder text for blank audio/media sends, the requested strict `messages` suppression option is absent, and the iMessage side is only a partial sibling fix rather than a full resolution of this Signal/config request.

## What This Changes

Request a default-preserving option or policy to suppress visible `<media:audio>` placeholder text for media-only voice/audio sends, especially Signal voice notes.

## Best Possible Solution

Have maintainers choose the Signal-local hidden-body policy or a default-off global `messages` option, then implement that default-preserving path with schema/help/docs only if needed, focused Signal tests, and live media-only proof while keeping the current iMessage attachment fix.

## Reproduction Assessment

Yes, at source level: a blank Signal media send with an `audio/*` attachment flows into `sendMessageSignal`, maps to `audio`, and sends `<media:audio>` as the RPC body. No live Signal client was run in this read-only review.

## Solution Assessment

Unclear: the requested global config option is plausible, but OpenClaw's config-surface bar is high and iMessage was solved channel-locally. Maintainers should choose between a Signal-local hidden-body policy and a default-off global suppression option before implementation.
