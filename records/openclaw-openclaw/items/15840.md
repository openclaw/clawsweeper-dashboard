## Summary

Keep open. Current main and the latest release still synthesize visible Signal media-placeholder text for blank audio/media sends, while the requested suppression setting is absent; the iMessage sibling has been fixed separately, so the remaining work is a Signal/config product decision.

## What This Changes

Request a default-off messages option or policy to suppress visible `<media:audio>` placeholder text for media-only audio/voice sends.

## Best Possible Solution

Keep this as the canonical product/config request; maintainers should choose a default-off global messages policy or a narrower Signal-specific hidden-body policy, then update schema/docs and Signal media-only tests while preserving the iMessage fix.

## Reproduction Assessment

Yes, at source level: a blank Signal media send with an `audio/*` attachment flows from `deliverReplies` into `sendMessageSignal`, maps to `audio`, and sends `<media:audio>` as the RPC body. I did not run a live Signal client in this read-only review.

## Solution Assessment

Unclear: the requested default-off config option is plausible, but AGENTS.md sets a high bar for new config surface and Signal may need a channel-specific hidden-body policy instead. Maintainers should choose the product surface before implementation.
