## Summary

Keep open. Current main and the latest release still synthesize visible Signal media-placeholder text for blank audio/media sends, while the requested strict messages suppression option is absent; iMessage was fixed separately, so the remaining work is a Signal/config product decision.

## What This Changes

Request a default-off messages configuration option, or similar policy, to suppress automatic media placeholder text such as `<media:audio>` for media-only outbound messages.

## Best Possible Solution

Keep this as the canonical product/config request; maintainers should choose a default-off `messages` policy or Signal-specific hidden-body policy, then update config/schema/docs and focused Signal media-only tests without disturbing the iMessage fix.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: a blank Signal media send with an `audio/*` attachment flows from `deliverReplies` into `sendMessageSignal`, maps to `audio`, and sends `<media:audio>` as the RPC body; no live Signal client was run.

## Solution Assessment

Is this the best way to solve the issue? Unclear: the requested global config option is plausible, but iMessage was solved channel-locally and Signal may need a hidden non-empty body, so maintainers should choose the product surface before implementation.
