## Summary

Keep open for a maintainer product decision. The visible Signal audio placeholder remains source-reproducible, but iMessage now suppresses its outbound placeholder without a global setting, so the remaining question is whether Signal should receive the same transport-owned fix or OpenClaw should add a new cross-channel configuration surface.

## What This Changes

Add an opt-in configuration option that suppresses synthetic `<media:audio>` and related placeholder text on outbound media-only messages.

## Best Possible Solution

Make attachment-only Signal sends use a transport-safe, non-visible fallback with focused delivery tests, and add a global setting only if maintainers identify multiple channels where users genuinely need selectable placeholder policy.
