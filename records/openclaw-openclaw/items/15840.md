## Summary

Keep open. Current main still has the remaining Signal media-only path synthesizing visible `<media:audio>` text, the requested `messages` suppression option is absent from strict config, and the iMessage sibling fix only partially reduces the original cross-channel problem.

## What This Changes

Add an opt-in messages setting or equivalent policy to suppress visible media-placeholder text such as `<media:audio>` for media-only outbound sends.

## Best Possible Solution

Resolve the remaining Signal media-only placeholder visibility with a transport-valid hidden-body or attachment-only path, and add a documented default-off global `messages` setting only if maintainers confirm cross-channel policy control is needed.

## Reproduction Assessment

Yes, at source level: a blank Signal media send with an `audio/*` attachment maps to `audio` and then sends `<media:audio>` as the RPC body. I did not run a live Signal client in this read-only review.

## Solution Assessment

Unclear. The requested global config option is plausible, but current main has already fixed iMessage channel-locally, so maintainers should choose between Signal-specific delivery behavior and a cross-channel messages policy.
