## Summary

Keep open. Current main and the latest release still synthesize visible Signal media-placeholder text for blank audio/media sends, while the requested strict `messages` suppression option is absent; the iMessage sibling was fixed separately, but the central Signal/config request remains unresolved.

## What This Changes

Request a default-off `messages` configuration option, or equivalent granular policy, to suppress visible `<media:audio>` fallback text for media-only outbound messages.

## Best Possible Solution

Keep this as the canonical maintainer product/config request; if accepted, implement a documented default-off media-placeholder suppression option or a narrower Signal hidden-body policy with focused Signal coverage while preserving default fallback behavior.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: a blank Signal media send with an `audio/*` attachment maps to `audio` and then sends `<media:audio>` as the RPC body; no live Signal client was run in this read-only review.

## Solution Assessment

Is this the best way to solve the issue? Unclear: the requested global config option is plausible, but current main has already fixed iMessage channel-locally, so maintainers should choose between a cross-channel `messages` policy and a narrower Signal transport fix.
