## Summary

Keep open. Current main and v2026.6.11 still synthesize visible Signal media-placeholder text for blank audio/media sends, while the requested strict `messages` suppression option is absent; the iMessage sibling was fixed separately, but the central Signal/config request remains.

## What This Changes

The issue requests a default-off configuration option to suppress generated media placeholder text such as `<media:audio>` for media-only messaging sends while preserving the existing fallback by default.

## Best Possible Solution

Keep this as the canonical maintainer product/config request and, if accepted, implement a documented default-off media-placeholder suppression option or narrower Signal hidden-body policy with focused Signal coverage while preserving default fallback behavior.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes, at source level: a blank Signal media send with an `audio/*` attachment maps to `audio` and then sends `<media:audio>` as the RPC body. I did not run a live Signal client in this read-only review.

## Solution Assessment

Is this the best way to solve the issue? Unclear. The requested global config option is plausible, but current main has already fixed iMessage channel-locally, so maintainers should decide whether the remaining solution is Signal-specific delivery behavior or cross-channel messages policy.
