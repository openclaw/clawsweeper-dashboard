## Summary

Keep open. Current `origin/main` and the latest release still synthesize visible Signal media placeholder text for blank media sends, while the requested strict `messages` suppression option is absent; the iMessage sibling behavior was fixed separately, so the remaining work is a Signal/config product decision.

## What This Changes

The issue requests an opt-in messages configuration option to suppress visible media placeholder text such as `<media:audio>` on outbound media-only channel sends.

## Best Possible Solution

Keep this as the canonical product/config request; maintainers should choose a default-off `messages` policy or a narrower Signal hidden-body policy, then update config/schema/docs and focused Signal media-only tests without disturbing the iMessage fix.

## Reproduction Assessment

Yes, at source level: a blank Signal media send with an `audio/*` attachment flows from reply delivery into `sendMessageSignal`, maps to `audio`, and sends `<media:audio>` as the RPC body. No live Signal client was run in this read-only review.

## Solution Assessment

Unclear: the requested global config option is plausible, but Signal may need a hidden non-empty transport body and the repository has a high bar for new config surface. Maintainers should choose the product surface before implementation.
