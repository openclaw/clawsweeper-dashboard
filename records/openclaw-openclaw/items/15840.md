## Summary

Keep open. Current main and latest release still synthesize visible Signal media-placeholder text for blank audio/media sends, while the requested strict `messages` suppression option is absent; the iMessage sibling was fixed separately, so the remaining request is a Signal/config product decision.

## What This Changes

The issue requests a default-preserving `messages` configuration option to suppress visible `<media:audio>` placeholder text for media-only outbound voice/audio messages.

## Best Possible Solution

Keep this as the canonical product/config request until maintainers choose a default-off global messages policy or a narrower Signal hidden-body policy, preserving iMessage's channel-local fix.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes, at source level: a blank Signal media send with an `audio/*` attachment flows from `deliverReplies` into `sendMessageSignal`, maps to `audio`, and sends `<media:audio>` as the RPC body. No live Signal client was run in this read-only review.

## Solution Assessment

Is this the best way to solve the issue? Unclear: the requested global config option is plausible, but iMessage was solved channel-locally and Signal may need a hidden non-empty body, so maintainers should choose the product surface before implementation.
