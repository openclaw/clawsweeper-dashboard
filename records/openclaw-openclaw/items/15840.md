## Summary

Keep open. Current main and the latest release still synthesize `<media:audio>` for captionless Signal audio/media sends, while the requested strict `messages` suppression option is absent; iMessage is now covered by a merged channel-local fix, leaving a Signal/global policy decision.

## What This Changes

Request adds a default-off `messages` configuration option to suppress media placeholder text for audio, voice, or media-only channel sends.

## Best Possible Solution

Resolve the remaining Signal media-only placeholder visibility with a transport-valid hidden body or attachment-only path, and add a documented default-off `messages` setting only if maintainers confirm cross-channel policy control is needed.

## Reproduction Assessment

Yes, at source level: a blank Signal media send with an `audio/*` attachment maps to `audio` and then sends `<media:audio>` as the RPC body. I did not run a live Signal client in this read-only review.

## Solution Assessment

Unclear. The requested global config option is plausible, but current main already fixed iMessage channel-locally, so maintainers should decide whether the remaining solution is Signal-specific delivery behavior or a cross-channel messages policy.
