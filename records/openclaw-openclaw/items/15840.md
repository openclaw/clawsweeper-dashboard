## Summary

Keep open. Current main and the latest release still synthesize visible Signal media-placeholder text for blank audio/media sends, while the requested strict `messages` suppression option is absent; the iMessage sibling was fixed separately, so the remaining work is a Signal/config product decision.

## What This Changes

The issue requests an opt-in configuration option or policy to suppress visible `<media:audio>` placeholder text for media-only channel sends.

## Best Possible Solution

Keep this as the canonical product/config request; maintainers should choose a default-off `messages` policy or Signal-specific hidden-body policy, then update config/schema/docs and focused Signal media-only tests without disturbing the iMessage fix.

## Reproduction Assessment

Yes, at source level: a blank Signal media send with an `audio/*` attachment flows from reply delivery into `sendMessageSignal`, maps to `audio`, and sends `<media:audio>` as the RPC body. No live Signal client was run in this read-only review.

## Solution Assessment

Unclear: the requested global config option is plausible, but iMessage was solved channel-locally and Signal may need a hidden non-empty body. Maintainers should choose the product surface before implementation.
