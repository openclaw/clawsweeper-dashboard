## Summary

Keep open because current main and the latest release still synthesize visible Signal media-placeholder text for blank media-only sends, while no documented strict `messages` suppression option exists. The merged iMessage sibling fix narrows the remaining work, but it does not solve the Signal/config request.

## What This Changes

The issue requests a default-off configuration option to suppress automatic `<media:audio>` fallback text for media-only messaging-channel sends.

## Best Possible Solution

Keep this as the canonical product/config request; maintainers should choose a default-off `messages` policy or Signal-specific hidden-body policy, then update config/schema/docs and focused Signal media-only tests without disturbing the iMessage fix.

## Reproduction Assessment

## Solution Assessment

Unclear: the requested global config option is plausible, but iMessage was solved channel-locally and Signal may need a hidden non-empty body, so maintainers should choose the product surface before implementation.
