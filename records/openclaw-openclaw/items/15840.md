## Summary

Keep open. Current main and the latest release still synthesize a visible Signal `<media:audio>` body for blank audio/media sends, while the requested `messages` suppression option is still absent; the related iMessage-only symptom was fixed separately but does not resolve the remaining Signal/config request.

## What This Changes

The issue requests a default-off configuration option to suppress automatic media placeholder text for audio or media-only outbound messages.

## Best Possible Solution

Keep this as the canonical maintainer product/config request and decide whether the remaining fix should be a documented default-off `messages` option or a narrower Signal transport policy that preserves the existing fallback by default.

## Reproduction Assessment

Yes, at source level: a blank Signal media send with an `audio/*` attachment maps to `audio` and then sends `<media:audio>` as the RPC body. I did not run a live Signal client in this read-only review.

## Solution Assessment

Unclear. The requested default-off global config option is plausible, but maintainers should choose between that cross-channel policy and a narrower Signal-specific hidden-body fix because OpenClaw's config surface bar is high.
