## Summary

Keep open. Current main and the latest release still synthesize visible Signal media-placeholder text for blank audio/media sends, while the requested strict `messages` suppression option is still absent and needs a maintainer product/config decision.

## What This Changes

The issue requests a default-off messages configuration option to suppress visible media placeholder text such as `<media:audio>` for voice/audio-only sends.

## Best Possible Solution

Resolve the remaining Signal media-only placeholder visibility with a transport-valid hidden-body or attachment-only path, and add a documented default-off `messages` setting only if maintainers confirm cross-channel policy control is needed.

## Reproduction Assessment

Yes, at source level: a blank Signal media send with an `audio/*` attachment maps to `audio` and then sends `<media:audio>` as the RPC body. I did not run a live Signal client in this read-only review.

## Solution Assessment

Unclear. The requested global config option is plausible, but current main has already fixed iMessage channel-locally, so maintainers should decide whether the remaining solution is Signal-specific delivery behavior or a cross-channel messages policy.
