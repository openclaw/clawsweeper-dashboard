## Summary

Keep open. ## What This Changes

The issue requests a default-off `messages` configuration option to suppress visible media placeholder text such as `<media:audio>` for audio or voice messages.

## Best Possible Solution

Keep this as the canonical product/config request and decide whether the durable fix is a documented default-off media-placeholder suppression option or a narrower Signal hidden-body policy that preserves default fallback behavior.

## Reproduction Assessment

Yes, at source level: a blank Signal media send with an `audio/*` attachment maps to `audio` and then sends `<media:audio>` as the RPC body. I did not run a live Signal client in this read-only review.

## Solution Assessment

Unclear. The requested global config option is plausible, but current main fixed iMessage channel-locally, so maintainers should decide whether the remaining solution is Signal-specific delivery behavior or cross-channel messages policy.
