## Summary

Keep open. Current main and the latest release still synthesize `<media:audio>` for blank Signal audio/media sends, the requested strict `messages` suppression option is absent, and the iMessage sibling behavior was fixed separately rather than closing the remaining Signal/config product decision.

## What This Changes

Request a default-off configuration or policy option to suppress visible `<media:audio>` fallback text for media-only outbound messages.

## Best Possible Solution

Choose a default-off global messages policy or a Signal-specific hidden-body policy, then update config/schema/docs and focused Signal media-only tests while preserving the existing iMessage fix.

## Reproduction Assessment

Yes, at source level: a blank Signal media send with an `audio/*` attachment flows from `deliverReplies` into `sendMessageSignal`, maps to `audio`, and sends `<media:audio>` as the RPC body. I did not run a live Signal client in this read-only review.

## Solution Assessment

Unclear: the requested global config option is plausible, but Signal may need a hidden non-empty body and iMessage was solved channel-locally, so maintainers should choose the product surface before implementation.
