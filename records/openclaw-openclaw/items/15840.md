## Summary

Keep open. Current main and v2026.6.11 still synthesize a visible Signal media placeholder for blank media-only sends, the requested strict `messages` suppression option is absent, and the iMessage sibling was only partially addressed by a separate merged fix, so this remains a product/config decision rather than closeable cleanup.

## What This Changes

Request a default-off configuration option to suppress automatically generated visible media placeholder text, especially `<media:audio>`, for media-only messaging sends.

## Best Possible Solution

Make a maintainer product call, then implement the chosen default-preserving behavior through the strict config/schema/docs surface or the Signal channel boundary, with focused media-only Signal tests and no regression to the existing iMessage empty-text behavior.

## Reproduction Assessment

Yes from source inspection: a Signal media-only send with empty text and an audio MIME type reaches `sendMessageSignal`, maps the MIME to `audio`, and assigns `<media:audio>` as the outgoing body. I did not run a live Signal client in this read-only review.

## Solution Assessment

No automatic fix is best yet. A default-off config option is plausible, but repository policy puts a high bar on new config surface and the iMessage sibling shows a channel-owned behavior fix may also be viable.
