## Reproduction Assessment

Yes at source level: current main catches a rich/media send failure in the quick-reply ordering path, continues to send text, and the monitor records outbound success after a normal return. I did not run a live LINE account reproduction in this read-only review.

## Solution Assessment

Yes: the fix stays in the LINE plugin, reuses the existing visibleReplySent partial-delivery contract, and returns the error so the monitor can adopt replyTokenUsed before surfacing it.
