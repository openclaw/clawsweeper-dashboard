- `P1`: The report describes an active agent workflow repeatedly rewriting useful context and ending without delivered output during long tool-result-heavy turns.
- `impact:data-loss`: False recovery can persistently replace prior tool outputs with tiny stubs, losing session content the agent still needed.

## Summary

This issue should stay open: current main still has a source-reproducible mid-turn estimator mismatch where the precheck can route on a tool-result-heavy transform-context view while the provider prompt path applies a separate aggregate projection, so the reported false recovery remains plausible in current code and the latest release.

## What This Changes

The issue reports that mid-turn context-overflow precheck overestimates tool-result-heavy prompts and triggers persistent transcript truncation far below the real provider context window.

## Best Possible Solution

Make mid-turn precheck estimate the same provider-boundary prompt projection that will be sent to the model, including aggregate tool-result caps, and avoid persistent recovery unless that projected prompt is actually over budget.
