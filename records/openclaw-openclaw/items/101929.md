## Label Justifications

- `P1`: The issue reports an active agent workflow that can repeatedly rewrite useful context and end with no assistant output during long tool-result-heavy turns.
- `impact:data-loss`: False recovery can persistently replace prior tool outputs with tiny stubs, losing retrievable session content the agent still needed.
- `impact:session-state`: The affected behavior is context/session-state drift between the real provider prompt, the precheck estimate, and the persisted transcript after recovery.

## Summary

Issue #101929 should stay open: current main still estimates mid-turn overflow against raw tool-result-heavy messages while the actual provider prompt later uses an aggregate-truncated projection, so the reported false positive recovery and persistent context rewriting remain plausible in current code and latest release.

## What This Changes

The issue asks OpenClaw to stop mid-turn overflow precheck from overestimating tool-result-heavy prompts and rewriting usable context when the real provider prompt remains well under the model window.

## Best Possible Solution

Estimate mid-turn precheck against the same provider-boundary prompt history sent to the model, including per-result and aggregate tool-result projection, then add focused regression coverage for the reported 250k-char/16k-cap shape.
