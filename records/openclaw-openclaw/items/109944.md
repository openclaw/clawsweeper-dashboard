## Summary

Keep open: current main still has the reported observability gap, neither related item owns the remaining work, and extending agent attribution into run and model-call events needs a maintainer semantics decision.

## What This Changes

Add an `agent` label to Prometheus model-call, tool-execution, and run metric families, including the diagnostic event context needed to populate it.

## Best Possible Solution

Use one canonical additive diagnostic contract: carry optional `agentId` through every run and model-call emitter, reuse the existing low-cardinality normalization in the Prometheus plugin, update all affected label tables, and prove both attributed and missing-agent behavior with focused exporter and emitter tests.

- **Keep fleet-wide semantics:** Leave these families unchanged and document that reliability and latency metrics intentionally aggregate across agents.
