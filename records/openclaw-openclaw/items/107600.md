## Summary

Keep open: the focused parsing fix addresses a real exception path, but the proposed `false` fallback violates the shipped `preserveFunnel` safety contract by treating an unknown status as confirmed route absence; the branch also lacks real Tailscale behavior proof.

## What This Changes

The PR catches malformed `tailscale funnel status --json` output, returns `false` instead of throwing, and changes the focused unit test to expect that fallback.

## Best Possible Solution

Represent Funnel inspection as covered, not covered, or unknown; preserve the existing route and skip Serve reconfiguration on unknown status, add caller-level regression coverage for that invariant, and provide redacted terminal or runtime proof from a real Tailscale setup.
