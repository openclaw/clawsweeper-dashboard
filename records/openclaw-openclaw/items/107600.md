## Summary

Keep this PR open, but do not merge its current head: the previous P1 blocker remains unchanged at the same SHA, because malformed status is an unknown state rather than proof that no Funnel route exists. The branch also lacks real-environment proof and is currently conflicted.

## What This Changes

The PR catches malformed `tailscale funnel status --json` output, returns `false`, and updates the focused unit test to expect that fallback.

## Best Possible Solution

Represent malformed or unavailable status as an explicit unknown/error outcome, log it, and make the Serve startup path preserve the existing Tailscale configuration unless route absence is positively established; cover true, false, and unknown outcomes and provide redacted live proof.
