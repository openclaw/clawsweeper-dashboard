## Summary

This PR should stay open: it avoids the parse exception by converting an unknown Funnel status into “no route,” which can make the `preserveFunnel` startup path overwrite an externally managed public Funnel with private Serve. The prior P1 finding remains unchanged on the current head, and the PR still supplies only unit-test output rather than real Tailscale behavior proof.

## What This Changes

The PR catches malformed `tailscale funnel status --json` output in `hasTailscaleFunnelRouteForPort` and returns `false` instead of propagating a parse error, with a matching unit-test expectation change.

## Best Possible Solution

Represent Funnel inspection as covered, not covered, or unknown; let the startup owner skip any Serve mutation on unknown status while logging a bounded diagnostic, and add caller-level coverage plus redacted live Tailscale proof that malformed output neither crashes startup nor changes an existing public Funnel.
