## Summary

This PR should remain open: it converts an unreadable Funnel status into “not covered,” so the preserve-Funnel startup path can proceed with Serve configuration despite not knowing whether an operator-managed Funnel route already exists. The unchanged head also still lacks real-host behavior proof.

## What This Changes

## Best Possible Solution

Represent Funnel inspection as covered, uncovered, or unknown, and make the preserve-Funnel caller skip configuration on unknown while surfacing a diagnostic; then prove both ordinary and malformed-status behavior on a redacted real host.
