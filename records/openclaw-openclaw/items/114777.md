## Summary

The cache is not safe to merge yet: it unconditionally wraps Node SQLite APIs that are absent from supported Node 22.22.3 and Node 24.15 runtimes, so opening the shared or file-backed agent state database can fail before the performance improvement is usable.

## What This Changes

This PR reuses a bounded cache of synchronous SQLite prepared statements for OpenClaw’s file-backed shared and per-agent state databases to reduce repeated SQL compilation during state-write bursts.

## System Context

OpenClaw’s shared and per-agent state owners open long-lived file-backed SQLite databases, then synchronous Kysely helpers compile and execute state queries against them. This PR inserts a database-owned statement cache into that execution path and requires every open, close, repair, and failure path to preserve native statement lifecycle safety.

## Best Possible Solution

Make cache installation capability-aware: preserve the existing uncached synchronous execution path when the required node:sqlite APIs are unavailable, wrap only methods that exist on that runtime, and add focused Node 22.22.3 and Node 24.15 coverage before merging.
