## Summary

The patch appears functionally correct and has credible after-fix terminal proof, but it adds a native-object retention invariant across OpenClaw’s long-lived SQLite owners: every enabled database must clear its cache before every close, replacement, repair, and eviction path. Keep this PR open for maintainer acceptance of that lifecycle tradeoff and completion of the running required checks. Likely related people: steipete is the current-head reviewer/coauthor and lifecycle-audit contact (medium confidence).

## What This Changes

This PR adds a bounded, second-use cache of synchronous SQLite prepared statements for OpenClaw’s file-backed shared and per-agent state databases, reducing repeated SQL compilation on hot query paths.

## System Context

OpenClaw’s shared state database and per-agent state databases execute synchronous Kysely-compiled SQL through the `node:sqlite` facade. This change sits between those database owners and SQLite execution, retaining selected prepared statements so repeated state reads and writes avoid recompilation while preserving the existing query results and close behavior.
