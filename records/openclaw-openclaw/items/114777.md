## Summary

This PR remains necessary because the synchronous Kysely path on current main still prepares equivalent SQLite SQL on each call. The branch’s bounded, database-owned cache is a plausible and well-tested improvement, but it is availability-sensitive because cached native statements retain their `DatabaseSync` owner; merge should wait for proof on the current merge result and an owner-level lifecycle check.

## What This Changes

The PR caches repeated synchronous SQLite prepared statements for OpenClaw’s shared and file-backed agent databases, while updating query-count tests so they measure executions rather than preparation calls.

## System Context

OpenClaw’s gateway, sessions, and agent state use shared and per-agent SQLite databases. Synchronous Kysely helpers compile query objects into SQLite statements; this PR retains a small set of repeated statements between executions and must clear them whenever a database owner closes, replaces, or repairs a handle.
