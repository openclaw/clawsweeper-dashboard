## Label Justifications

- `P1`: The PR addresses a real Teams session privacy regression, but its reset still permits old context-bearing state to reach the first post-reinstall turn.
- `merge-risk: 🚨 session-state`: The patch rotates persisted session identity while retaining all unlisted stored fields across the lifecycle boundary.

## Summary

The latest head fixes the prior preference-loss and package-compile defects, but the lifecycle reset still copies the complete old session entry and removes only a fixed field list. That leaves unlisted context-bearing state—most notably durable next-turn plugin injections—available after a Teams app removal/re-add, so the privacy boundary is not complete.

## What This Changes

The PR dispatches Microsoft Teams removal/reinstall lifecycle signals, removes stale conversation references, and rotates matching persisted sessions while preserving selected user preferences.

## Best Possible Solution

Keep the Teams lifecycle detection and conversation-reference cleanup, but route session rotation through a session-owner SDK seam that rebuilds from an explicit durable-settings allowlist and clears all prior-turn plugin, prompt, transcript, runtime, and delivery state.

No. The observable Teams boundary handling is well scoped, but the persisted reset should be implemented by the session subsystem with an explicit preservation contract rather than a plugin-local denylist.
