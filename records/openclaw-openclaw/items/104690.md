## Summary

This PR remains necessary because current main has no Microsoft Teams removal lifecycle reset, and the branch has strong live proof for the normal uninstall path. It is not merge-ready: the exact current head still skips matching entries whose `updatedAt` is already zero, even though provider-owned bindings make those entries fresh independently of the timestamp, so the prior session and metadata can survive the removal boundary.

## What This Changes

The PR adds Microsoft Teams lifecycle dispatch and handling that removes cached conversation references, rotates route-matched sessions on observable removal or reinstall boundaries, and detects changed personal-DM conversation IDs.

## Best Possible Solution

Remove both zero-timestamp exclusions, retain compare-and-swap checks against the observed session id and timestamp, fully replace every matching entry, and add a provider-bound `updatedAt: 0` regression test before landing the single canonical lifecycle implementation.
