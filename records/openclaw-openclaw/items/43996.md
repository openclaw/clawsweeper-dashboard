## Summary

Keep open: current main and the latest release still create Docker sandbox containers with mandatory `--security-opt no-new-privileges`, there is no supported opt-out or fallback, and the direct fix PR is closed unmerged. The remaining work is real, but it needs maintainer security/product direction before automation changes the sandbox boundary.

## What This Changes

The issue requests a recovery path for Docker sandbox containers that exit with EPERM when OpenClaw always passes Docker `no-new-privileges`.

## Best Possible Solution

Keep `no-new-privileges` enabled by default, then add a maintainer-approved dangerous opt-out with doctor/status diagnostics and real affected-host proof, or choose diagnostics-only if weakening the sandbox boundary is unacceptable.

## Solution Assessment

Unclear: an explicit dangerous opt-out is the narrowest practical mitigation if maintainers accept the security tradeoff, while a silent fallback would be a weaker security posture. Maintainers should choose between opt-out, diagnostics-only handling, or deeper image/runtime compatibility work.
