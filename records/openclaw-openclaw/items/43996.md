## Summary

Keep open: current main and the latest release still add Docker `--security-opt no-new-privileges` to sandbox containers unconditionally, while the direct fix PR is closed unmerged. The report is credible, but the remaining fix changes a sandbox security boundary and needs maintainer direction before repair work starts.

## What This Changes

The issue reports Docker sandbox containers exiting before command execution on a Linux host where Docker `no-new-privileges` makes even `/usr/bin/sleep` fail with EPERM.

## Best Possible Solution

Keep the secure default, then have maintainers choose an explicit audited mitigation: either a dangerous opt-out with diagnostics/docs/doctor reporting, or a fail-closed diagnostic that tells affected operators to change host/runtime/backend without silently weakening the sandbox.

Options:

- **Automatic fallback retry:** Retry container creation without the flag after the specific EPERM failure, accepting a less explicit security downgrade that must be carefully reported and tested.
