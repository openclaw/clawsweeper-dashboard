## Summary

Keep open: current main and the latest release still unconditionally pass Docker `--security-opt no-new-privileges` when creating sandbox containers, the strict config schema has no supported opt-out, and the direct fix PR is closed unmerged. The report remains actionable, but the recovery path changes a sandbox security boundary and needs maintainer direction before implementation.

## What This Changes

The issue reports Docker-backed sandbox containers exiting immediately with `exec /usr/bin/sleep: operation not permitted` on hosts where Docker rejects `--security-opt no-new-privileges`, and asks for a config opt-out, fallback retry, or clearer diagnostic.

## Best Possible Solution

Keep `no-new-privileges` enabled by default, then add a maintainer-approved recovery path such as an explicitly dangerous opt-out plus clear diagnostics, dangerous-config reporting, docs, tests, and real Docker proof on an affected host.
