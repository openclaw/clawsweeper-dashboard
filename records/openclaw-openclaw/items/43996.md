## Label Justifications

- `P1`: A real user reports Docker sandbox sessions failing immediately after upgrade, breaking an agent execution workflow with a security-sensitive runtime default.
- `impact:security`: The issue centers on Docker sandbox hardening with `no-new-privileges`, and any functional fix may change the sandbox security boundary.
- `impact:crash-loop`: The sandbox container exits immediately with code 255, leaving session commands unable to run.

## Summary

Keep open: current main and the latest release still unconditionally create Docker sandbox containers with `--security-opt no-new-privileges`, the config schema has no supported opt-out or fallback, and the direct fix PR is closed unmerged. The issue remains actionable but needs maintainer security/product judgment before a repair PR.

## What This Changes

The issue requests a safe way to handle Docker sandbox startup failures on hosts where `no-new-privileges` makes even `/usr/bin/sleep` fail, such as an opt-out, fallback retry, or clearer diagnostics.

## Best Possible Solution

Keep the secure default, then add a maintainer-approved explicit dangerous opt-out and clear doctor/status diagnostics for incompatible Docker hosts, avoiding any silent fallback that weakens isolation without operator consent.
