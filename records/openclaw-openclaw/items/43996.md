## Summary

Keep open: current main and the latest release still unconditionally add Docker `--security-opt no-new-privileges` to sandbox containers, the strict config schema has no supported opt-out, and the direct fix PR was closed unmerged. The report is actionable, but the recovery path changes a sandbox security boundary and needs maintainer direction.

## What This Changes

This issue requests a supported recovery path for Docker sandbox containers that fail to exec when OpenClaw applies `--security-opt no-new-privileges`.

## Best Possible Solution

Keep `no-new-privileges` enabled by default, then add a maintainer-approved explicit dangerous opt-out or diagnostic-only path with clear operator warnings and real Docker proof on an affected host.

- **Declare host unsupported:** Treat Docker hosts that reject `no-new-privileges` as unsupported for Docker sandbox mode and direct users to another backend or host configuration.

Unclear until the security decision is made. The best narrow mitigation appears to be an explicit dangerous opt-out with secure default and reporting; a silent automatic fallback would be riskier because it weakens sandbox hardening without operator intent.
