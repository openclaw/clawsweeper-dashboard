## Summary

Keep open: current main and the latest release still add Docker `--security-opt no-new-privileges` to sandbox containers unconditionally, and the only direct fix PR is closed unmerged. The remaining fix is real but security-sensitive because any opt-out or fallback changes the sandbox hardening boundary.

## What This Changes

Request a safe recovery path for Docker sandbox hosts where `no-new-privileges` makes even `/usr/bin/sleep` fail with EPERM.

## Best Possible Solution

Keep `no-new-privileges` enabled by default, then add a maintainer-approved explicit dangerous opt-out and clear diagnostic path with focused tests and affected-host Docker proof.
