## What This Changes

The issue reports Docker-backed sandbox containers exiting immediately on a host where `--security-opt no-new-privileges` makes `/usr/bin/sleep` fail with EPERM, requesting an opt-out, fallback retry, or clearer diagnostics.

## Best Possible Solution

Keep the secure default, then add a maintainer-approved compatibility path such as an explicit dangerous opt-out or tightly diagnosed fallback, with status/doctor messaging, docs, and real Docker proof on an affected host.

Yes, source-reproducible: current main always injects Docker `no-new-privileges`, and the reporter supplied a host-level Docker matrix where only that flag makes `/usr/bin/sleep` fail. I did not reproduce the host-specific EPERM locally.

## Solution Assessment

No single fix is selected yet. The best likely shape is a secure default plus explicit, audited compatibility/diagnostic behavior; a silent fallback would be riskier without maintainer approval.
