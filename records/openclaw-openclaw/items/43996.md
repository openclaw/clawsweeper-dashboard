## Summary

Keep open: current main and the latest release still create Docker sandbox containers with `--security-opt no-new-privileges` unconditionally, the direct fix PR is closed unmerged, and the remaining recovery path changes a sandbox security boundary.

## What This Changes

The issue reports Docker-backed sandbox containers exiting immediately on an affected host when OpenClaw applies `no-new-privileges`, and asks for a config opt-out, fallback, or clearer diagnostic.

## Best Possible Solution

Keep `no-new-privileges` enabled by default, then add a maintainer-approved explicit dangerous opt-out and diagnostic path with real Docker proof on an affected host.

## Solution Assessment

Unclear until the security boundary decision is made. The best narrow mitigation appears to be an explicit dangerous opt-out with secure default and reporting; silent automatic fallback would be riskier.
