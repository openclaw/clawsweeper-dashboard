## Summary

Keep open: current main and the latest release still unconditionally create Docker sandbox containers with `--security-opt no-new-privileges`, the reported host-level Docker matrix isolates that flag as the failing trigger, and the direct fix PR is closed unmerged. The remaining work is actionable, but it needs maintainer security/product judgment because the likely recovery paths change sandbox hardening or add a dangerous config surface.

## What This Changes

The issue requests a supported recovery path for Docker sandbox containers that exit with `exec /usr/bin/sleep: operation not permitted` when `no-new-privileges` is applied.

## Best Possible Solution

Keep the secure default, then add a maintainer-approved audited recovery path for incompatible Docker hosts, such as an explicit dangerous opt-out with reporting, an image/runtime compatibility fix, or diagnostics that explain the host failure without silently weakening isolation.
