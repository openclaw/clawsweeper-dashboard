## Summary

Keep open: current main and the latest release still add Docker `--security-opt no-new-privileges` to sandbox containers unconditionally, and the direct fix PR was closed unmerged. The report remains actionable, but the recovery path changes a sandbox hardening boundary and needs maintainer direction before repair automation chooses a policy.

## What This Changes

The issue reports Docker sandbox startup failures when OpenClaw unconditionally applies `--security-opt no-new-privileges`, and asks for a config opt-out, fallback retry, or clearer diagnostic.

## Best Possible Solution

Keep `no-new-privileges` enabled by default, then add a maintainer-approved explicit dangerous opt-out or diagnostic-only path with focused tests and affected-host Docker proof.

## Solution Assessment

Unclear until maintainers choose the security boundary. The best narrow mitigation appears to be an explicit dangerous opt-out with secure default and reporting; silent automatic fallback would be riskier.
