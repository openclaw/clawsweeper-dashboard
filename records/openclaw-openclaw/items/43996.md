## Summary

Keep open: current main and the latest stable release still always pass Docker `--security-opt no-new-privileges` to sandbox containers, there is still no supported opt-out or fallback, and the direct fix PR was closed unmerged. The report is well supported, but the recovery path changes a sandbox security boundary and needs maintainer direction.

## What This Changes

The issue requests recovery for Docker sandbox startup failures on hosts where `--security-opt no-new-privileges` makes even `/usr/bin/sleep` fail with `operation not permitted`.

## Best Possible Solution

Keep `no-new-privileges` enabled by default, then either add a maintainer-approved dangerous opt-out with doctor/status diagnostics and affected-host proof, or choose diagnostics-only handling if weakening the sandbox boundary is unacceptable.
