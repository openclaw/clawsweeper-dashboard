## Summary

Keep open: current main and the latest release still unconditionally add Docker `--security-opt no-new-privileges` to sandbox containers, there is no supported opt-out or targeted fallback, and the direct fix PR was closed unmerged. The report is actionable, but the recovery shape changes sandbox hardening and needs maintainer security-boundary direction before an automated repair should write code.

## What This Changes

The issue reports Docker sandbox startup failures when OpenClaw applies `no-new-privileges` on a host where Docker rejects that flag for even `/usr/bin/sleep`.

## Best Possible Solution

Keep `no-new-privileges` enabled by default, then add a maintainer-approved explicit dangerous opt-out or diagnostic-only path with clear operator messaging and real Docker proof on an affected host.
