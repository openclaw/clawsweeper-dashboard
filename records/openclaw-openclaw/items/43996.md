## Summary

Keep open: current main and the latest release still add Docker `--security-opt no-new-privileges` to sandbox containers unconditionally, while the direct fix PR is closed unmerged. The report remains actionable, but the repair changes a sandbox hardening boundary and needs maintainer direction first.

## What This Changes

The issue requests a recovery path for Docker sandbox containers that exit immediately when `--security-opt no-new-privileges` makes even `/usr/bin/sleep` fail with `operation not permitted`.

## Best Possible Solution

Keep `no-new-privileges` enabled by default, then add a maintainer-approved explicit dangerous opt-out and clear diagnostic path with focused tests and affected-host Docker proof.
