## What This Changes

The issue requests recovery or diagnostics for Docker sandbox sessions that fail when OpenClaw applies `no-new-privileges`.

## Best Possible Solution

Keep `no-new-privileges` as the secure default, then add a maintainer-approved explicit recovery path with clear status/doctor diagnostics, security-audit reporting, focused tests, and Docker proof on an affected host.

Options:

- **Explicit Dangerous Override (recommended):** Add a documented dangerous config key, default it to the current secure behavior, and surface the weakened runtime in status/doctor/security audit output.
- **Diagnostic Only:** Keep the flag mandatory and improve startup/status errors so operators can identify the host-level Docker incompatibility without guessing from container logs.
- **Narrow EPERM Fallback:** Retry without the flag only for a tightly detected startup EPERM and record the runtime as weakened for audit/status visibility.
