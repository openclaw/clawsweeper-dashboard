## Summary

Keep open: current main and the latest release still unconditionally pass Docker `--security-opt no-new-privileges` when creating sandbox containers, while the only direct fix PR is closed unmerged. The report remains actionable, but the repair needs maintainer security/product judgment because the practical mitigations can weaken sandbox hardening or add a new dangerous config surface.

## What This Changes

The issue reports Docker-backed sandbox containers exiting with `exec /usr/bin/sleep: operation not permitted` on hosts where Docker `no-new-privileges` prevents even the sandbox keepalive command from starting.

## Best Possible Solution

Keep the secure default, then add a maintainer-approved explicit recovery path for incompatible Docker hosts, such as a dangerous opt-out with audit/status reporting or a targeted image/runtime compatibility fix plus clear diagnostics.
