## Summary

Keep open: current main and the latest stable release still always pass Docker `--security-opt no-new-privileges` to sandbox containers, there is no supported opt-out or fallback, and the direct fix PR is closed unmerged. The report is strong, but recovery changes a Docker sandbox security boundary and needs maintainer direction.

## What This Changes

The issue requests a supported recovery path when Docker `--security-opt no-new-privileges` makes OpenClaw sandbox containers fail to start with `exec /usr/bin/sleep: operation not permitted`.

## Best Possible Solution

Keep `no-new-privileges` enabled by default, then either add a maintainer-approved dangerous opt-out with doctor/status diagnostics and affected-host proof, or choose diagnostics-only handling if weakening the sandbox boundary is unacceptable.
