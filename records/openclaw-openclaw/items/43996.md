## Summary

Keep open: current main and the latest release still create Docker sandbox containers with `--security-opt no-new-privileges` unconditionally, while the only direct fix PR is closed unmerged. The report remains source-reproducible, but the recovery path needs maintainer security direction because an opt-out or fallback changes sandbox hardening.

## What This Changes

The issue asks for a config opt-out, automatic fallback, or clearer diagnostics for Docker sandbox startup failures when `no-new-privileges` causes `exec /usr/bin/sleep: operation not permitted`.

## Best Possible Solution

Keep `no-new-privileges` as the secure default, then add a maintainer-approved recovery path with explicit status/doctor/security-audit visibility, focused tests, and real Docker proof on an affected host.

- **Tightly detected fallback:** Retry without the flag only for a narrowly detected startup EPERM and record the runtime as weakened for audit and status visibility.
