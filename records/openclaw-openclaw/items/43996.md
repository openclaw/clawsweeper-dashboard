## Summary

Keep open: current main and the latest release still add Docker `--security-opt no-new-privileges` to sandbox containers unconditionally, no supported opt-out or fallback exists, and the direct fix PR is closed unmerged; resolving this now needs a maintainer security-boundary decision.

## What This Changes

The issue asks for a recovery path when Docker sandbox containers fail under `no-new-privileges`, such as an explicit opt-out, automatic fallback, or clearer diagnostic.

## Best Possible Solution

Keep `no-new-privileges` enabled by default, then add a maintainer-approved explicit dangerous opt-out and diagnostic path with tests, docs, dangerous-config reporting, and real Docker proof on an affected host.
