## Summary

This PR is still necessary only if it is rewritten around the canonical session-key contract: the current slice change passes the entire session-key tail as an agent ID, so it can regress default-model resolution rather than preserve a colon-containing agent ID.

## What This Changes

The branch replaces first-segment session-agent extraction with prefix slicing and adds an unrelated overflow guard for base64 image-size estimation.

## Best Possible Solution

Keep agent-ID extraction aligned with the canonical session-key parser or encoding; if colon-containing agent IDs are supported, introduce an unambiguous parser and cover both ordinary and colon-containing agent/session keys, then submit the image guard separately or prove its affected runtime path.
