## Summary

The patch does not solve the reported colon-containing agent-ID case: the shared parser still treats the first colon after `agent:` as the agent-ID boundary, so the proposed call returns `copilot` for `agent:copilot:agent:main` just like the removed inline split.

## What This Changes

The PR replaces inline `agent:` session-key splitting with `parseAgentSessionKey()` when resolving the configured default model shown for a session row.

## Best Possible Solution

Either retain the existing colon-delimited agent-ID grammar and close this ineffective substitution, or first approve a repository-wide session-key format and agent-ID contract that can represent embedded colons, then update all producers, parsers, validation, and regression coverage together.
