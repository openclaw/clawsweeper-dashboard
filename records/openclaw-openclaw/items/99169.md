## What This Changes

The PR caps QA channel bus client JSON success-response reads at 16 MiB for node:http POST calls and fetch-based state reads, with regression tests for oversized responses.

## Best Possible Solution

Land the bounded-reader patch after maintainers accept the shared 16 MiB QA bus cap, or adjust to a documented QA-specific cap with matching tests if larger payloads are valid.

## Reproduction Assessment

Yes, from source inspection and PR tests. Current main buffers node:http poll/action responses and calls response.json() for state without a byte cap, while the PR exercises oversized success bodies on the poll and state paths.

## Solution Assessment

Yes. Reusing the shared bounded response readers at the QA channel client boundary is the narrowest maintainable fix; a server-only guard would not protect exported facade users or misbehaving endpoints.
