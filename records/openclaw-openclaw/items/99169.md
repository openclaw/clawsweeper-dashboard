## Summary

Keep this PR open for maintainer review: the patch looks correct and well-scoped, with sufficient path-level proof, but the new 16 MiB fail-closed QA bus response contract is an intentional availability decision maintainers should accept before merge.

## What This Changes

The PR replaces unbounded QA channel bus JSON success-body reads with 16 MiB bounded readers and adds oversized-response regression tests.

## Best Possible Solution

Merge this shape if maintainers accept 16 MiB as the QA bus success-body contract; otherwise choose a named QA-bus-specific limit and update the same bounded-reader tests before merge.

## Reproduction Assessment

Yes. Current main clearly buffers node:http QA bus POST responses and uses unbounded response.json() for state, and the PR body gives a concrete streaming-server proof for oversized poll/state payloads; I did not run it locally because this review is read-only.

## Solution Assessment

Yes, this is the best narrow fix. It reuses existing plugin SDK bounded-response helpers for the fetch path and a small local node:http adapter for the only non-fetch path, while broader transport rewrites would be unnecessary churn.
