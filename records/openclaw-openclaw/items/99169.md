## Summary

Keep open for maintainer review. The patch looks correct and proven, but the new 16 MiB fail-closed QA bus response cap is an availability-affecting behavior change that maintainers should explicitly accept before merge.

## What This Changes

The branch caps QA channel bus client poll/state JSON success-body reads at 16 MiB using shared bounded readers and adds regression tests for oversized poll and state responses.

## Best Possible Solution

Land the bounded-reader patch after maintainers accept the shared 16 MiB QA bus cap; if larger QA payloads are valid, replace it with a documented QA-specific limit and matching tests.

## Reproduction Assessment

Yes from source inspection. Current main buffers node:http poll chunks and calls response.json() for state with no cap, while the PR tests exercise oversized success bodies on both paths.

## Solution Assessment

Yes. Reusing the existing bounded response helpers in the QA channel client is the narrowest maintainable fix; a server-only guard would not protect exported client/facade use or misbehaving endpoints.
