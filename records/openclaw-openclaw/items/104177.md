## Summary

The current head still contains two previously reported blockers: the launch-time status request can probe browser transports before explicit import consent, and a zero-cookie import can leave a newly created managed profile behind. The consent-first macOS workflow remains useful, but the PR is not merge-ready without real signed-app evidence.

## What This Changes

The PR adds a native macOS prompt and General Settings action that import Chrome-family cookies into an isolated managed browser profile, persist dismissal or completion state, and optionally make a successful import the browser default.

## Best Possible Solution

Use a non-probing source of configured profile names, make profile creation transactional so failed imports leave no profile or default changes, and retain the explicit local-only consent UI with redacted signed-app proof of the complete authenticated-browser result.
