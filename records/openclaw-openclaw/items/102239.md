## Best Possible Solution

Land the narrow reader/write-back fix after the contributor adds real isolated cron setup proof or an equivalent redacted runtime log, while keeping the failure handling limited to canonical setup-state metadata access denial.

Yes, this looks like the narrow maintainable fix: handle only canonical setup-state access denial as recoverable absence and avoid writing back to that path in the same setup pass.
