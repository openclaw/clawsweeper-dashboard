## Summary

Keep open: this focused bug-fix PR is not correct as written because it routes the no-stream fallback through `readResponsePrefix`, whose own fallback still calls `response.arrayBuffer()` before truncating to `maxBytes`.

## What This Changes

The PR exports `readResponsePrefix`, uses it in `readResponseBodySnippet` for no-stream responses, and updates the fallback tests to provide `arrayBuffer()`.

## Best Possible Solution

Revise the PR so capped no-reader fallbacks avoid whole-body `arrayBuffer()` and `text()` calls, preferably matching the fail-closed pattern already used by `src/agents/tools/web-shared.ts`, with tests that assert those fallbacks are not invoked.

Yes, source-reproducible: current main shows the no-reader fallback still calls a whole-body method before truncation, and the PR routes the changed code into that same helper. I did not run tests because this review is read-only.

## Solution Assessment

No. This is not the best fix because it moves the whole-body read from `text()` to `arrayBuffer()`; the maintainable fix is to avoid whole-body fallbacks when a byte cap is requested or explicitly fail closed.
