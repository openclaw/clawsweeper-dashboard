## Summary

This PR remains necessary because current main still returns Matrix-native payloads that the shared table renderer cannot display. The implementation and live proof are strong, but merging requires an explicit maintainer choice about changing `messages` from raw timeline events to a deduplicated current-message view for JSON and agent-tool consumers.

## What This Changes

The branch projects Matrix message fields into the shared CLI display shape, summarizes edits from `m.new_content`, and collapses replacement events to the latest valid edit.

## Best Possible Solution

Define the Matrix read payload as canonical current-message state, preserve an explicit raw-event view if maintainers consider it a supported need, and then land the plugin-owned field projection and standards-aligned replacement folding.
