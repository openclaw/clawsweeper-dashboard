## Summary

Keep this PR open: it fixes a real Matrix CLI formatting problem and has useful proof, but the current patch would expose edit event IDs as the actionable message IDs for deduped edited messages, which can break follow-up Matrix edit/delete/pin workflows.

## What This Changes

The PR normalizes Matrix message and pin payloads for the shared CLI formatter, prefers `m.new_content` for Matrix edits, and deduplicates Matrix `m.replace` events in message reads.

## Best Possible Solution

Keep the plugin-local normalization and dedupe approach, but make edited rows expose the original Matrix event id as the formatter/action id while preserving the raw replacement event id separately for JSON consumers.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: current main's formatter ignores the Matrix-native `eventId`/`sender`/`body`/numeric `timestamp` fields, which explains blank CLI rows. I did not run the live Matrix CLI in this read-only review.

## Solution Assessment

No, not yet: plugin-local normalization and Matrix edit dedupe are the right layer, but the current ID projection makes edited rows actionable by replacement event id rather than original event id. The safer fix is to keep raw Matrix fields while projecting the original target id for CLI/follow-up action use.
