## Summary

Keep open: current main now has a narrow read-only `agents.workspace.list/get` Gateway API, but the Mission Control file panel still uses the allowlisted `agents.files.*` API and the requested workspace CRUD plus system filesystem scope still need product and security decisions.

## What This Changes

The issue requests replacing the Mission Control bootstrap-file allowlist with scope levels for bootstrap files, all agent workspace files, and system filesystem browsing.

## Best Possible Solution

Keep `agents.files.*` as the bootstrap-file editor, use the current read-only `agents.workspace.*` API for bounded previews, settle workspace CRUD through the existing broad workspace-management thread, and require a separate explicit security design before any system filesystem scope exists.
