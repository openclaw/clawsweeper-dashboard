## Summary

Keep open: current main now has a read-only `agents.workspace.list/get` path and chat/mobile workspace previews, but the Agent Files panel is still allowlisted, workspace edits/deletes still belong to the broader open workspace-management thread, and the requested system filesystem scope remains a product/security decision.

## What This Changes

The issue asks to replace the Agent Files allowlist with selectable Mission Control scopes for bootstrap files, all workspace files, and host system files.

## Best Possible Solution

Keep `agents.files.*` as the bootstrap-file editor, use the current read-only workspace APIs for previews, and handle workspace mutations through the canonical workspace-management design while requiring a separate security-approved design for any host filesystem scope.
