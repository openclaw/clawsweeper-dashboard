- `merge-risk: 🚨 compatibility`: Existing contributors with relative or same-file global hooksPath values can have their local commit workflow broken by the new hook chain.

## Summary

Keep this PR open: the useful global-hook chaining idea is still blocked by the previously reported self-recursion bug, and the reviewed head has not changed since that finding.

## What This Changes

The branch adds a global `core.hooksPath` lookup to `git-hooks/pre-commit` and invokes the configured global `pre-commit` before the repo-local staged-file formatter flow.

## Best Possible Solution

Keep the global-hook chaining behavior only after resolving the candidate hook and skipping it when it is the same executable as the repo-local hook, with focused validation for the relative hooksPath case.

## Maintainer Decision

Required: false

Yes. Source inspection plus Git's `core.hooksPath` and hook working-directory contracts show that a global relative `core.hooksPath=git-hooks` can call this repository's `git-hooks/pre-commit` from inside itself.

## Solution Assessment

No. The hook is the right layer for this local hardening, but this implementation needs a same-file recursion guard before it is the narrow maintainable fix.
