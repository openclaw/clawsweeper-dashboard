- `merge-risk: 🚨 compatibility`: Existing contributors with relative or same-file global hooksPath values can have their local commit workflow broken by the new hook chain.

## Summary

Keep this PR open, but the prior blocker is still valid: the new global-hook chain can recurse into the same repo-local hook when a relative global `core.hooksPath` resolves to `git-hooks`. Current `main` has newer hook refactors but does not implement the requested global guard chaining, so the PR is not obsolete.

## What This Changes

The PR modifies `git-hooks/pre-commit` to invoke an executable globally configured pre-commit hook before the existing OpenClaw staged-file hook flow.

## Best Possible Solution

Keep the global-hook chaining idea only after resolving the candidate global hook and skipping it when it is the same executable as the repo-local hook, with focused validation for the relative-path case.

No. The hook is the right layer for this local hardening, but the implementation needs a same-file recursion guard before it is the narrow maintainable fix.
