## Summary

Keep this PR open, but it still needs changes before merge: the latest head is the same reviewed SHA and still invokes the configured global hook without guarding against calling this repo hook again.

## What This Changes

The PR adds a global `core.hooksPath` pre-commit chain to `git-hooks/pre-commit` before the existing staged-file formatting flow.

## Best Possible Solution

Keep the global-hook chaining only after resolving the candidate hook and the current hook path, skipping the global call when they point to the same executable.

Required: false

## Reproduction Assessment

Yes. Source inspection plus Git's hook-path contract shows that a relative global `core.hooksPath=git-hooks` resolves from the worktree root and can call this repository's `git-hooks/pre-commit` from inside itself.

## Solution Assessment

No. The hook is a plausible layer for this local hardening, but the implementation is not the best fix until it skips the global hook when it resolves to the same executable.
