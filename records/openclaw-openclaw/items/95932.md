## Label Justifications

- `P3`: This is a local developer hook hardening PR with limited blast radius and no runtime product impact.
- `merge-risk: 🚨 compatibility`: Existing contributors with relative or same-file global hooksPath values can have their local commit workflow broken by the new hook chain.
- `merge-risk: 🚨 availability`: The same-file hook case can recurse repeatedly and stall local pre-commit execution before the repo formatter flow runs.

## Summary

Keep open; the prior same-file recursion blocker is still present at the current PR head, and the virtual merge result would still execute a globally configured hook before the local hook without checking whether it is the same file.

## What This Changes

The branch updates `git-hooks/pre-commit` to invoke an executable globally configured pre-commit hook before the existing OpenClaw staged-file formatting flow.

## Best Possible Solution

Keep the global-hook chaining behavior only after resolving the candidate hook and the current hook to canonical paths and skipping the global call when they are the same executable.

Required: false

Yes. Source inspection plus Git's hook-path contract shows that a global relative `core.hooksPath=git-hooks` resolves from the worktree root and can call this repository's `git-hooks/pre-commit` from inside itself.

## Solution Assessment

No. The hook is the right layer for this local hardening, but the implementation needs a same-file recursion guard before it is the narrow maintainable fix.
