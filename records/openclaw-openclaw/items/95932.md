## Label Justifications

- `P3`: This is local developer-hook hardening with limited blast radius and no OpenClaw runtime product impact.
- `merge-risk: 🚨 compatibility`: Existing contributors with relative or same-file global hooksPath values can have their local commit workflow broken by the new hook chain.
- `merge-risk: 🚨 availability`: The same-file hook case can recurse repeatedly and stall local pre-commit execution before the repo formatter flow runs.

## Summary

Keep open: the hardening idea is useful, but the current diff can call the repo hook recursively when the globally configured hook path resolves to this same `git-hooks/pre-commit` file.

## What This Changes

The branch reads global `core.hooksPath` in `git-hooks/pre-commit` and runs the configured global `pre-commit` before the existing staged-file formatting flow.

## Best Possible Solution

Keep the global-hook chaining only after resolving the candidate and current hook paths, skipping the global call when they are the same executable, and covering the relative global `core.hooksPath=git-hooks` case.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Source inspection plus Git's hook-path contract shows that a global relative `core.hooksPath=git-hooks` resolves from the worktree root and can call `git-hooks/pre-commit` from inside itself.

## Solution Assessment

No. The hook is the right layer for this local hardening, but this implementation needs a same-file recursion guard before it is the narrow maintainable fix.
