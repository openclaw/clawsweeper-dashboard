## Label Justifications

- `P3`: This is local developer hook hardening with limited blast radius and no OpenClaw runtime product impact.
- `merge-risk: 🚨 compatibility`: Existing contributors with relative or same-file global `hooksPath` values can have their local commit workflow broken by the new hook chain.
- `merge-risk: 🚨 availability`: The same-file hook case can recurse repeatedly and stall pre-commit execution before the repo formatter flow runs.

## Summary

Keep open: current main still does not chain the global hook, but this PR keeps the previously flagged self-recursion bug when the global hooks path resolves to this repository's hook, so it needs a narrow guard before merge.

## What This Changes

The PR adds a global `core.hooksPath` lookup to `git-hooks/pre-commit` and invokes an executable global `pre-commit` hook before the existing OpenClaw staged-file flow.

## Best Possible Solution

Keep the global-hook chaining idea only after resolving the candidate global hook and skipping it when it is the same executable as the repo-local hook, with focused validation for relative global hooksPath.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, this is source-reproducible. Git documents that relative `core.hooksPath` values resolve from the hook working directory and non-bare hooks run from the worktree root, so a global value of `git-hooks` makes the new block call this same hook.

## Solution Assessment

No. The hook is a plausible layer for the hardening, but the implementation is not the best fix until it resolves and skips same-file global hook candidates.
