## Label Justifications

- `P3`: This is local developer hook hardening with limited blast radius and no runtime product impact.
- `merge-risk: 🚨 compatibility`: Existing contributors with relative or same-file global hooksPath values can have their local commit workflow broken by the new hook chain.
- `merge-risk: 🚨 availability`: The same-file hook case can recurse repeatedly and stall local pre-commit execution before the repo formatter flow runs.

## Summary

Keep open; the previous same-file recursion blocker is still present at the current PR head, and the proposed hook chain can recurse before OpenClaw's staged-file flow runs.

## What This Changes

The PR adds a call from `git-hooks/pre-commit` to an executable globally configured `pre-commit` hook before the existing repo-local formatting flow.

## Best Possible Solution

Keep the global-hook chaining only after resolving the candidate hook and skipping it when it is the same executable as the repo-local hook, with focused coverage for that case.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Source inspection plus Git's documented hook-path contract shows that a global relative `core.hooksPath=git-hooks` resolves from the worktree root and can call `git-hooks/pre-commit` from inside itself.

## Solution Assessment

No. The hook is the right layer for this local hardening, but the implementation needs a same-file recursion guard before it is the narrow maintainable fix.
