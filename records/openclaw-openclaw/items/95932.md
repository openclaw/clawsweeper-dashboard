## Summary

Keep open: the prior blocker still applies because the added global hook call can recurse when global `core.hooksPath` resolves to the same repo-local `git-hooks/pre-commit`; a narrow guard is still needed before merge.

## What This Changes

The PR modifies `git-hooks/pre-commit` to invoke an executable globally configured pre-commit hook before the existing OpenClaw staged-file flow.

## Best Possible Solution

Keep the global-hook chaining idea only after resolving the candidate hook and the current hook to canonical paths and skipping the global call when they point to the same executable, with focused validation for the relative `git-hooks` case.
