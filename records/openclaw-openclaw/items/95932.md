## Summary

Keep open: the previous self-recursion blocker is still present at the unchanged PR head, and the current merge result still invokes the configured global pre-commit hook without checking whether it is the same repo hook.

## What This Changes

The PR adds a call in `git-hooks/pre-commit` to run an executable global `core.hooksPath` pre-commit hook before OpenClaw's existing staged-file formatting flow.

## Best Possible Solution

Keep the global-hook chaining idea only after resolving the candidate and current hook paths and skipping the global call when they point to the same executable, with focused coverage for a relative global hooksPath case.

## Solution Assessment

No. The hook is a plausible layer for this local hardening, but the implementation needs a same-file recursion guard before it is the narrow maintainable fix.
