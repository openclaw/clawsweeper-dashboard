## Summary

Keep this PR open: the global-hook chaining idea is focused, but the current patch still has the previously reported same-file recursion blocker and should not merge as-is.

## What This Changes

The branch makes `git-hooks/pre-commit` read global `core.hooksPath` and invoke that global `pre-commit` hook before the existing repo-local staged-file flow.

## Best Possible Solution

Keep the global-hook chaining behavior only after resolving the configured candidate and skipping it when it is the same executable as the repo-local hook, with focused coverage for a relative global hooksPath case.

## Solution Assessment

No. The hook is the right layer for this local hardening, but this implementation needs a same-file recursion guard before it is the narrow maintainable fix.
