## Summary

Keep open: the branch still has the same blocking recursion issue raised in the prior ClawSweeper review, because the current head invokes the configured global pre-commit hook without checking whether it resolves back to this repository's hook.

## What This Changes

The branch changes `git-hooks/pre-commit` to read global `core.hooksPath` and run an executable global `pre-commit` hook before the repo-local staged-file formatting flow.

## Best Possible Solution

Keep the global-hook chaining only after resolving the candidate global hook and skipping it when it is the same executable as `git-hooks/pre-commit`, with focused coverage for a relative global `core.hooksPath` case.

## Solution Assessment

No. The hook is the right layer for this local hardening, but the implementation needs a same-file recursion guard before it is the narrow maintainable fix.
