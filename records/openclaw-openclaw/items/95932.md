## Summary

Keep open: the current PR head still adds global hook chaining without guarding the same-file case, so a relative global `core.hooksPath=git-hooks` can recurse into this repository's hook before the existing staged-file flow runs.

## What This Changes

The branch modifies `git-hooks/pre-commit` to read global `core.hooksPath` and run an executable global `pre-commit` hook before the existing staged-file formatting flow.

## Best Possible Solution

Keep global-hook chaining only after resolving and comparing the candidate and current hook paths, with focused coverage for a relative global `core.hooksPath` same-file case.

## Solution Assessment

No. The hook is a plausible layer for this hardening, but the implementation is not the best fix until it skips the global hook when it resolves to the same executable.
