## Summary

Keep open: current main and v2026.6.11 still default detached cron output to implicit announce-to-last and hard-fail unresolved non-best-effort delivery, while https://github.com/openclaw/openclaw/pull/91399 remains the open closing implementation candidate.

## What This Changes

Cron jobs in local/no-channel setups should preserve generated output instead of failing completion delivery with “Channel is required” after successful execution.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/91399 or an equivalent narrow fix that downgrades only implicit no-channel delivery while preserving fail-closed behavior for explicit targets.

Yes, source-level: current main defaults detached cron output to announce/last, no-channel target resolution can return ok:false, and non-best-effort dispatch hard-fails that unresolved target. I did not run the live WSL2 Control UI scenario.
