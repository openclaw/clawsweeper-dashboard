## Summary

Keep this PR open: it fixes the fresh-create default, but existing persisted isolated recurring jobs that omitted `deleteAfterRun` can still load without cleanup, and https://github.com/openclaw/openclaw/pull/96045 proposes a conflicting one-shot-only lifecycle contract.

## What This Changes

This PR changes cron normalization and tests so newly created isolated recurring cron jobs default `deleteAfterRun` to `true` unless the user explicitly sets it to `false`.

## Best Possible Solution

Land one reconciled cron lifecycle contract: either make recurring isolated jobs cleanup-safe across fresh and already-persisted state, or reject recurring delete-after-run with a compatible doctor/operator recovery path.
