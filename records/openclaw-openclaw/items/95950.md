## Summary

Keep this PR open: it is a useful fresh-create fix for the linked isolated cron token/session leak, but the prior blocker remains because existing persisted recurring isolated jobs with omitted `deleteAfterRun` still skip cleanup after upgrade, and an open related PR proposes the opposite lifecycle contract.

## What This Changes

The PR changes cron normalization and tests so newly created recurring isolated cron jobs default `deleteAfterRun` to `true` while preserving explicit `false` and leaving recurring main jobs unchanged.

## Best Possible Solution

Merge one reconciled cron lifecycle contract: either make recurring isolated jobs cleanup-safe across fresh and upgraded persisted state, or reject recurring delete-after-run with a compatible recovery path and close this direction.
