## Summary

This focused credential-precedence fix has supplied live Gateway proof and passing checks, with no discrete correctness or security defect evident in the reviewed PR material; it should remain open for ordinary maintainer merge review rather than cleanup.

## What This Changes

The branch makes configure-wizard gateway health and reachability probes treat blank or whitespace `OPENCLAW_GATEWAY_TOKEN` and `OPENCLAW_GATEWAY_PASSWORD` values as unset, preserving configured credentials while retaining nonblank environment overrides.

## Best Possible Solution

Land the shared-normalizer approach if the configure-wizard owner accepts that blank environment values should match runtime gateway-auth semantics, with configured credentials used only when the environment value is blank or whitespace.

## Reproduction Assessment

Yes. The supplied before/after live-Gateway scenario uses production reachability functions with blank and whitespace credential variables; the legacy nullish-coalescing path sends the blank value while the proposed resolver uses configured credentials.

## Solution Assessment

Yes. Reusing the existing optional-string normalizer at each wizard probe override site is the narrowest maintainable fix and preserves the existing nonblank environment-first contract.
