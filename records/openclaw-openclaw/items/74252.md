## Summary

Keep this PR open: current main and the latest release still conflate fast log growth with rotation, and the branch fixes that path with focused coverage. The remaining blocker is not a code defect; maintainers should explicitly accept the additive `logs.tail.skippedBytes` response contract or ask the contributor to narrow the PR.

## What This Changes

The PR narrows log-tail reset semantics, adds optional `logs.tail.skippedBytes` metadata, re-anchors the Control UI on skipped windows, refreshes the generated Swift protocol model, and adds CLI/log-tail/UI regression tests.

## Best Possible Solution

Land the reset/truncation fix with `skippedBytes` if maintainers approve the additive `logs.tail` response contract; otherwise narrow this PR to the reset-only CLI/log-tail fix and track UI skipped-window metadata separately.

## Reproduction Assessment

Yes, from source inspection. Current main and `v2026.6.11` set `reset = true` when a valid cursor is only too far behind `maxBytes`, and the CLI maps that field directly to the false rotation notice.

## Solution Assessment

Yes, conditionally. Fixing the boolean conflation in `readLogSlice` is the right layer, and `skippedBytes` is a narrow additive contract for UI re-anchoring if maintainers accept the response change.
