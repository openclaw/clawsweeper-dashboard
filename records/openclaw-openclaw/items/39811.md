## Summary

Keep open: current main improves runtime unknown-model diagnostics and fallback notices, but `config validate` still only rejects configured refs that match manifest suppressions and does not generally flag arbitrary unknown configured model IDs. The downstream `openclaw-extensions doctor` workaround is useful evidence, but it confirms the core validation gap rather than closing it.

## What This Changes

The issue asks OpenClaw to validate unknown configured model refs before runtime and make fallback from a failed primary model visible to users.

## Best Possible Solution

Adopt a maintainer-approved advisory catalog validation path in `config validate` and doctor using runtime-equivalent model resolution, with explicit handling for custom or forward-compatible refs and fallback notices as the runtime backstop.

Kind: product_direction

Question: Should configured model-ref validation be advisory, strict fail-closed, or limited to known-retired/suppressed catalog entries?

Rationale: Provider routing, config validation, and fallback behavior are compatibility-sensitive, and source inspection cannot safely choose how authoritative the catalog should be for custom or future model refs.

Likely owner: vincentkoc

Owner reason: The decision is closest to recent config validation and model-routing helper history.

Owner confidence: high

Options:

- **Advisory trusted-catalog validation (recommended):** Warn in `config validate` and doctor when a configured ref is absent from trusted runtime/catalog evidence, while allowing custom and future refs with clear wording.
- **Strict fail-closed validation:** Reject configured refs not present in the trusted catalog, reducing runtime surprises but risking breakage for custom providers and newly released models.
- **Keep suppression-only validation:** Continue only blocking known-retired or explicitly suppressed refs, preserving maximum compatibility but leaving the reported class mostly unresolved.

## Reproduction Assessment

Yes at source level: current main collects configured model refs but only rejects refs found in static suppression metadata, so arbitrary unknown refs are not generally caught before runtime.

## Solution Assessment

Unclear until maintainers choose catalog authority semantics; advisory doctor/config validation is likely safer than unconditional fail-closed validation for every catalog miss.
