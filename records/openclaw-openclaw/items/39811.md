## Summary

Keep open: current main still rejects only manifest-suppressed configured model refs and has catalog-backed doctor validation only for `hooks.gmail.model`, so the broader invalid primary/fallback/per-agent model validation request remains unresolved.

## What This Changes

The issue asks OpenClaw to warn or validate when configured primary/fallback agent model refs cannot be verified, instead of allowing silent runtime fallback or failure.

## Best Possible Solution

Define warning-first catalog authority for configured model refs, then add doctor/config validate coverage for default, per-agent, fallback, channel, and hook refs while preserving an explicit path for custom or forward-compatible models.

Question: Should unknown configured model refs be warning-only in doctor/config validate, hard validation errors, or runtime/startup warnings when catalog authority is incomplete?

Rationale: The code can enumerate configured refs, but choosing how to treat unknown refs affects custom providers, forward-compatible model names, fail-closed config validation, and upgrade safety.

Likely owner: steipete

Owner confidence: high

Options:

- **Warning-first validation (recommended):** Add catalog-backed doctor/config warnings for unknown configured refs, with wording that distinguishes trusted catalog misses from custom or forward-compatible setups.
- **Strict validation:** Reject unknown configured refs at validation time, accepting a compatibility break unless maintainers also define an explicit escape contract.
- **Runtime-only diagnostics:** Keep config validation permissive and rely on startup warmup, runtime errors, and fallback notices rather than adding a new config/doctor analyzer.

## Reproduction Assessment

Yes, at source level: current validation enumerates configured refs but only rejects manifest-suppressed models, while doctor catalog validation is scoped to `hooks.gmail.model`. I did not run a live CLI repro in this read-only review.

## Solution Assessment

Unclear until maintainer policy is set: advisory doctor/config validation looks like the safest fix shape, while hard errors need a compatibility decision for custom and forward-compatible models.
