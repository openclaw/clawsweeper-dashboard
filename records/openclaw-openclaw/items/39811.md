## Summary

Keep open: current main has better runtime unknown-model diagnostics and fallback logs, but it still does not generally validate configured model refs against provider/catalog availability in `config validate` or doctor, and related closed reports continue to route this class back to this issue.

## What This Changes

The issue requests early validation and clearer fallback notification for configured model refs that are invalid or unverifiable before they fail at runtime.

## Best Possible Solution

Add a maintainer-approved, runtime-equivalent model-ref analyzer for `config validate` and doctor that emits advisory warnings for trusted catalog misses while preserving explicit custom-provider and forward-compatible model paths.

Kind: product_direction

Question: Should OpenClaw treat configured model refs missing from trusted runtime/catalog evidence as advisory warnings, hard validation failures, or only known-retired/suppressed-model warnings?

Rationale: Provider routing, config validation, doctor behavior, and fallback semantics are compatibility-sensitive, and current source shows the remaining fix depends on how much catalog authority maintainers want over custom or newly released model refs.

Likely owner: steipete

Owner reason: The decision spans model catalog core, fallback observability, and config/doctor policy, and steipete has recent history across the most central surfaces plus timeline activity on this issue.

Owner confidence: medium

Options:

- **Advisory trusted-catalog validation (recommended):** Warn in `config validate` and doctor when configured refs are absent from trusted runtime/catalog evidence, while using clear wording for custom and future refs.
- **Strict fail-closed validation:** Reject configured refs not present in trusted catalog evidence, reducing runtime surprises but risking upgrade breaks for custom providers and newly released models.
- **Keep suppression-only validation:** Continue only blocking known-retired or explicitly suppressed refs, preserving compatibility but leaving the reported silent-misconfiguration class mostly unresolved.

## Reproduction Assessment

Yes at source level: current main accepts arbitrary model strings structurally and only rejects manifest-suppressed refs, while runtime still has a `model_not_found` failure path for unresolved configured refs.

## Solution Assessment

Unclear until maintainers choose validation semantics; the safest direction appears to be advisory doctor/config validation rather than unconditional fail-closed catalog enforcement.
