## Summary

Keep open: current main and the latest release still do not validate arbitrary configured agent/default/fallback model refs against a trusted or runtime-equivalent catalog. The implemented coverage is narrow, the same-repo fix PR was closed unmerged, and the open fork PR is still only a candidate path rather than a merged fix.

## What This Changes

The issue asks OpenClaw to warn on invalid configured model refs before runtime and to make fallback behavior legible when the selected model fails.

## Best Possible Solution

Define trusted-catalog and warning/error semantics, then add runtime-equivalent advisory validation in `config validate` and doctor for default, per-agent, fallback, and related configured model refs while keeping broader fallback-notification behavior on its existing path.

Required: true

Kind: product_direction

Question: Should OpenClaw validate arbitrary configured agent model refs against a trusted/runtime-equivalent catalog as warnings or errors, and should that validation live in `config validate`, doctor, config write/reload, or some combination?

Rationale: The source gap is clear, but the durable product choice is whether unknown refs are invalid, warning-only, or allowed for custom and forward-compatible provider setups; automation cannot safely choose that compatibility boundary.

Likely owner: steipete

Owner reason: The decision crosses model selection, config validation, doctor UX, and provider catalog semantics, and steipete has the strongest inspected ownership signal across those paths.

Owner confidence: high

Options:

- **Add advisory trusted-catalog validation (recommended):** Warn in `config validate` and doctor using runtime-equivalent resolution, alias handling, fallback coverage, and catalog-origin awareness without blocking custom/forward-compatible refs by default.
- **Hard-fail invalid configured refs:** Reject unresolvable active model refs at config write or startup, preventing runtime surprises but intentionally making previously accepted configs fail earlier.
- **Defer to broader model reconciliation:** Keep this issue as a specific repro but only solve it as part of the broader model reconcile/session reset design in https://github.com/openclaw/openclaw/issues/28965.

## Reproduction Assessment

Yes, source-reproducible for the remaining validation gap: current main only checks manifest-suppressed refs in config validation and `hooks.gmail.model` in doctor, while arbitrary default/per-agent/fallback model refs are not catalog-validated. I did not run a live gateway reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose semantics: advisory validation is the likely narrow path, but hard errors versus warnings and user-declared versus trusted catalog rows are compatibility-sensitive. The earlier same-repo PR was not the best final fix because it was closed unmerged and reviewed as too narrow.
