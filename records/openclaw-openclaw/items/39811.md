Keep open: current main and the latest release still only reject manifest-suppressed configured model refs, while doctor catalog validation is scoped to `hooks.gmail.model`; arbitrary invalid default/per-agent model refs remain a real unresolved model-routing reliability gap. The same-repo attempted fix was closed unmerged, and the remaining open fork PR is conflicting, so this issue still needs maintainer policy and repair direction.

## What This Changes

The issue requests validation and user-visible warning paths for invalid configured model references so model routing does not fail or fall back silently.

## Best Possible Solution

Maintainers should choose the warning/error policy, then either sponsor/repair the open fork PR or replace it with a focused runtime-equivalent `config validate` and doctor analyzer that distinguishes trusted catalog evidence from custom or forward-compatible refs.
