## Summary

Keep open: current main and the latest release still only reject statically suppressed model refs, while arbitrary configured model names can remain accepted until runtime. The fallback-notification half is now covered, but the remaining catalog/doctor/config-validation behavior needs maintainer product direction because warning versus hard-fail affects custom and forward-compatible providers.

## What This Changes

The issue requests validation and user-visible warnings for invalid configured model references so misconfigured primary or fallback models do not fail silently at runtime.

## Best Possible Solution

Define warning-first catalog authority, then add shared runtime-equivalent doctor and config-validate coverage for configured model refs while preserving an explicit path for custom and forward-compatible provider models.
