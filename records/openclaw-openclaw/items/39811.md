The discussion adds useful real-world evidence from `openclaw-extensions`, but the remaining choice is product policy around advisory warnings versus strict rejection for custom or forward-compatible models.

## What This Changes

Request that OpenClaw warn or reject unverifiable configured model names before they silently reach runtime fallback or unknown-model failures.

## Best Possible Solution

Add a maintainer-approved advisory validation and doctor path for configured model refs that are absent from trusted runtime/catalog evidence, while preserving custom and forward-compatible provider setups unless maintainers explicitly choose strict rejection.
