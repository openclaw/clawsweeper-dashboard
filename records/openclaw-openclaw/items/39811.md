## Summary

Keep open: current main has improved runtime unknown-model messaging and documented fallback notices, but the central request remains unresolved because general configured agent model refs are still not checked against the model catalog by `config validate` or doctor.

## What This Changes

The issue asks OpenClaw to warn or fail earlier when configured primary/fallback/agent model refs do not resolve to known provider catalog entries, and to make fallback behavior visible to users.

## Best Possible Solution

Add a core-owned advisory validation/doctor path for configured model refs that are absent from trusted runtime/catalog evidence, while preserving forward-compatible custom provider setups and the current visible fallback notices.

Options:

- **Advisory catalog warnings (recommended):** Add warnings in `config validate` and doctor for catalog-missing configured model refs, keeping custom and forward-compatible refs non-fatal.
- **Strict validation:** Reject catalog-missing configured refs during validation or config writes, accepting the compatibility risk for custom and future provider ids.
- **Runtime-only handling:** Keep accepting arbitrary configured refs and rely on improved runtime errors plus fallback notices instead of adding preflight validation.
