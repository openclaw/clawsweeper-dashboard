## What This Changes

The issue requests catalog-backed validation or warning for invalid configured model names before runtime fallback or failure.

## Best Possible Solution

Define warning-first catalog authority, then add doctor/config validate coverage for configured model refs while preserving an explicit path for custom and forward-compatible models.

Question: Should unknown configured model refs be warning-only in doctor/config validate, hard validation errors, or startup/runtime warnings, and which catalog source is authoritative for custom and forward-compatible providers?

Rationale: The source can identify configured refs and catalog status, but warning versus hard-fail behavior affects existing custom providers, upgrade safety, and forward-compatible model names.

Likely owner: steipete

Owner reason: He has the strongest observed current-main history across config validation, configured model refs, and doctor checks, and the remaining blocker is a product/compatibility policy choice.

Owner confidence: high

Options:

- **Warning-first validation (recommended):** Add catalog-backed doctor/config warnings for unknown configured refs with wording that distinguishes trusted catalog absence from custom or forward-compatible refs.
- **Strict validation:** Reject unknown configured refs at config validation or write time, accepting a compatibility break unless an explicit escape contract is added.
- **Runtime-only handling:** Keep config validation permissive and rely on startup warnings, runtime errors, fallback notices, and status/doctor diagnostics instead.

Yes, at source level: current validation enumerates configured refs but only rejects manifest-suppressed refs, and doctor catalog validation is limited to `hooks.gmail.model`. I did not run a live CLI repro in this read-only cleanup review.

## Solution Assessment

Unclear until maintainer policy is set: warning-oriented doctor/config validate coverage looks safest, while hard errors need an explicit compatibility decision for custom and forward-compatible models.
