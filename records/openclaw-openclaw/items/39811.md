## Summary

Keep open: current main still only rejects manifest-suppressed model refs and has catalog-backed doctor checks for `hooks.gmail.model`, so the broader request to warn on arbitrary invalid configured agent model names remains unresolved. The downstream `openclaw-extensions doctor` workaround in the issue comments is useful evidence that this remains a real model-routing reliability gap.

## What This Changes

The issue requests config validation, doctor coverage, and user-visible fallback warnings for invalid configured model references.

## Best Possible Solution

Define warning-first catalog authority for configured model refs, then add doctor/config validate coverage for default, per-agent, fallback, channel, and hook refs while preserving an explicit path for custom or forward-compatible models.
