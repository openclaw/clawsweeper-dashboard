## Summary

Keep open: current main still only rejects manifest-suppressed configured model refs and has hook-specific doctor catalog warnings, while the broader request to warn on arbitrary invalid default, per-agent, and fallback model refs remains unresolved.

## What This Changes

The issue requests validation and user-facing warnings when configured model references cannot be verified against provider/catalog availability and would otherwise fail or fall back at runtime.

## Best Possible Solution

Define warning-first catalog authority for configured model refs, then add config validate and doctor coverage for default, per-agent, fallback, channel, and hook refs while preserving an explicit custom/forward-compatible path.

Options:

- **Warning-first validation (recommended):** Add catalog-backed doctor/config warnings for unknown configured refs, with clear wording for custom or untrusted catalogs and no hard failure by default.
- **Strict validation:** Reject unknown configured refs at config validation time, accepting a compatibility break unless an explicit escape contract is added.
- **Runtime-only handling:** Keep config validation permissive and rely on startup warmup, runtime errors, and fallback notices.

## Solution Assessment

Unclear until maintainer policy is set: a warning-oriented doctor/config validate analyzer appears safest, while hard errors need an explicit compatibility decision for custom and forward-compatible models.
