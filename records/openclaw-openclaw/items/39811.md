## Summary

Keep open: current main has fallback notices and suppression-specific model-ref validation, but it still does not catalog-check arbitrary configured default/per-agent model refs in config validation or doctor; the downstream openclaw-extensions doctor workaround reinforces that this remains a real model-routing reliability gap.

## What This Changes

Warn or reject invalid configured model names before runtime, especially through openclaw config validate and doctor for default, fallback, and per-agent model settings.

## Best Possible Solution

Add warning-first catalog validation through the existing configured-ref collector in config validate and doctor, with explicit wording for custom or forward-compatible refs and focused tests for default, fallback, and per-agent settings.

Rationale: The code can identify configured refs, but the permanent behavior affects custom providers, local proxies, future model names, fail-closed config validation, and upgrade safety.

Options:

- **Warning-first validation (recommended):** Add catalog-backed config validate and doctor warnings for unknown configured refs, while keeping existing configs loadable by default and distinguishing custom or untrusted catalog cases.
- **Strict validation:** Reject unknown configured refs at validation time, accepting a compatibility break unless maintainers also define an escape or migration contract.
- **Runtime-only handling:** Keep config validation permissive and rely on startup checks, runtime errors, and fallback notices instead of adding a new config/doctor analyzer.
