## Summary

Keep open: current main and v2026.6.11 still only reject manifest-suppressed model refs and validate `hooks.gmail.model` in doctor, so the broader request to warn on arbitrary invalid configured agent model names remains unresolved. The May 7 downstream `openclaw-extensions doctor` workaround is useful supporting evidence that this is a real model-routing reliability gap, not just config hygiene.

## What This Changes

The issue requests catalog-backed validation and doctor/config warnings for invalid configured model references, plus visible fallback feedback when a bad primary silently falls back.

## Best Possible Solution

Define warning-first catalog authority for configured model refs, then add doctor/config validate coverage for default, per-agent, fallback, channel, and hook refs while preserving an explicit path for custom or forward-compatible models.
