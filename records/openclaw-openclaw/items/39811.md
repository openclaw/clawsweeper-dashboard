## Summary

Keep open: current main has better runtime unknown-model guidance and documented fallback notices, but the central config/doctor validation request remains unresolved for ordinary configured model refs that are absent from the model catalog.

## What This Changes

The issue requests config/doctor validation and user-facing warning paths for configured model refs that do not resolve to an available provider model before runtime fallback.

## Best Possible Solution

Add a maintainer-approved advisory validation path in `config validate` and `doctor` that checks configured default, fallback, per-agent, channel, hook, and message model refs against trusted catalog/runtime-equivalent resolution, with explicit exceptions for custom and forward-compatible providers.

- **Runtime-only diagnostics:** Keep config permissive and rely on runtime unknown-model and fallback notices, accepting that bad refs remain discoverable only after use.
