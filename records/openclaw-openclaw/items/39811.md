## Summary

Keep open: current main and v2026.6.11 still only reject manifest-suppressed configured model refs, while arbitrary unknown agent/default/fallback refs can pass config validation and fail later at runtime. The May 7 downstream `openclaw-extensions doctor` workaround and the closed duplicate reports add concrete user evidence, but the remaining warning/error semantics need maintainer product direction before repair.

## What This Changes

The issue asks OpenClaw to validate or warn on invalid configured model refs and make fallback from a failed primary model visible to users.

## Best Possible Solution

Define warning-first, runtime-equivalent diagnostics for configured model refs in `openclaw config validate` and doctor, with clear handling for custom or forward-compatible providers and separate tracking for fallback notification behavior.

Options:

- **Warning-first validation (recommended):** Add catalog-backed warnings for unknown configured refs while preserving a documented path for custom and forward-compatible models.
- **Strict validation:** Reject unknown configured refs at config validation time and accept the compatibility cost only with an explicit escape or migration contract.
- **Runtime-only handling:** Keep config validation permissive and rely on startup checks, runtime errors, and fallback notices instead of a new config/doctor analyzer.
