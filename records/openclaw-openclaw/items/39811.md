- `impact:auth-provider`: The issue concerns model choice, provider catalog resolution, and fallback routing for configured model refs.

## Summary

Keep open: current main has implemented visible fallback notices, but it still does not warn or fail during `config validate`/doctor for arbitrary bad configured primary, fallback, or per-agent model refs; only manifest-suppressed refs and `hooks.gmail.model` get catalog-style checks.

## What This Changes

Request early validation or doctor warnings for configured model refs that cannot be verified against provider/catalog availability, plus visible fallback notification when a primary model fails.

## Best Possible Solution

Add a maintainer-approved advisory validation and doctor analyzer for configured model refs using runtime-equivalent resolution, trusted catalog/source metadata, aliases, and fallbacks while preserving custom and forward-compatible setups.
