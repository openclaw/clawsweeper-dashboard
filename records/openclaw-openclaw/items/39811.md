## Summary

Keep open: current main only rejects configured model refs that match manifest suppressions and warns for `hooks.gmail.model`; it still does not broadly warn on arbitrary invalid default, fallback, or per-agent model refs. The May downstream workaround and the open closing PR candidate are useful evidence that this remains a real model-routing reliability gap.

## What This Changes

The issue asks OpenClaw to detect invalid configured model references before they fail at runtime and to make model fallback/failure visible to users.

## Best Possible Solution

Keep this issue as the canonical model-config validation gap and land a warning-oriented doctor/config validation path that checks configured primary, fallback, and per-agent refs against trusted runtime-equivalent catalog evidence without blocking intentional custom models.

Rationale: The source gap is clear, but AGENTS.md and VISION.md make config strictness, forward-compatible custom models, and fallback behavior compatibility-sensitive enough that automation should not choose the permanent policy alone.

Owner confidence: high

Options:

- **Warn in doctor/config validate (recommended):** Surface catalog-missing configured refs as warnings with clear paths and hints while preserving forward-compatible custom model setups.
- **Fail config validation:** Reject unknown configured refs early, reducing runtime failures but risking breakage for custom or not-yet-catalogued models.
- **Limit to doctor only:** Keep runtime/config writes permissive and use doctor as the advisory repair surface, accepting that misconfiguration may still reach runtime until users run doctor.

## Solution Assessment

Unclear as a final policy: a warning-oriented doctor/config validation fix looks like the safest narrow path, but maintainers need to choose catalog authority and whether absence should warn or fail.
