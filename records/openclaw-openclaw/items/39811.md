## Summary

Keep open: current main only catches statically suppressed configured model refs and hooks.gmail.model catalog mismatches, so the broader request to warn on arbitrary unknown configured agent model names remains unresolved.

## What This Changes

The issue requests validation and warning paths for configured model names that are not known or resolvable, so users do not silently run with invalid model routing or fallbacks.

## Best Possible Solution

Add a catalog-backed doctor/config warning path for all configured agent model refs, with explicit policy for trusted-catalog absence versus custom or forward-compatible refs.
