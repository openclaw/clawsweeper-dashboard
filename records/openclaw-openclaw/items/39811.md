## Summary

Keep open: current main now covers the user-visible fallback-status half via #101337, but generic configured-model validation remains missing because config validation only rejects manifest-suppressed refs and doctor catalog validation is still scoped to `hooks.gmail.model`. The linked downstream `openclaw-extensions doctor` workaround and closed duplicates are useful evidence, but the open fork PR is conflicting and does not make the core issue obsolete.

## What This Changes

The issue requests early validation or warnings for configured model names that cannot resolve, plus explicit user notification when automatic model fallback is used.

## Best Possible Solution

Adopt warning-first catalog-backed config validate and doctor checks across configured model refs, with explicit semantics for custom or forward-compatible refs and the current fallback notices left intact.

Rationale: The code can enumerate the refs, but the behavior affects custom providers, forward-compatible model names, fail-closed validation, and upgrade safety, so automation should not choose the warning/error contract alone.

Owner confidence: medium

Options:

- **Warning-first validation (recommended):** Add catalog-backed doctor/config warnings for unknown configured refs while distinguishing trusted catalog absence from likely invalid refs without hard-failing existing setups by default.
- **Strict validation:** Reject unknown configured refs at config validation time, accepting a compatibility break unless maintainers also define an explicit escape or migration contract.
- **Runtime-only handling:** Keep config validation permissive and rely on startup warmup, runtime errors, and fallback notices instead of adding a configured-ref analyzer.
