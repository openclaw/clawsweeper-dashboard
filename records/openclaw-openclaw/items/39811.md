## Summary

Keep open: current main and v2026.6.11 only reject manifest-suppressed retired model refs, while doctor catalog validation is still scoped to `hooks.gmail.model`; fallback visibility improved, but generic configured-model validation remains unresolved and the linked fork PR is currently conflicting.

## What This Changes

The issue requests upfront warnings or validation for invalid configured model references, plus visible notification when a primary model fails over to a fallback.

## Best Possible Solution

Add an advisory catalog-aware `config validate` and doctor check for configured primary, fallback, and per-agent model refs, with explicit policy for custom or forward-compatible refs, while keeping the existing fallback status and notice improvements.
