## Summary

Keep open: current main still lacks general catalog-backed `config validate` or doctor coverage for arbitrary configured agent model refs, and the only open closing PR is a conflicting fork PR rather than a merged fix. The May 7 downstream `openclaw-extensions doctor` workaround is useful evidence that this remains user-visible.

## What This Changes

The issue requests catalog-backed validation or warnings for unknown configured model names and user-visible notice when model fallback hides a primary-model failure.

## Best Possible Solution

Define warning-first catalog authority, then add `config validate` and doctor coverage for configured model refs while preserving an explicit path for custom and forward-compatible models.

Options:

- **Warning-first validation (recommended):** Add catalog-backed doctor/config warnings for unknown configured refs with wording that distinguishes trusted catalog absence from custom or forward-compatible refs.
- **Strict validation:** Reject unknown configured refs at config validation or write time, accepting a compatibility break unless an explicit escape contract is added.
- **Runtime-only handling:** Keep config validation permissive and rely on startup warnings, runtime errors, fallback notices, and status/doctor diagnostics instead.

## Reproduction Assessment

Yes at source level: current validation enumerates configured refs but only rejects manifest-suppressed refs, and current doctor catalog validation is limited to `hooks.gmail.model`. I did not run a live CLI repro in this read-only cleanup review.

## Solution Assessment

Unclear until maintainer policy is set: warning-oriented doctor/config validate coverage looks safest, while hard errors need an explicit compatibility decision for custom and forward-compatible models.
