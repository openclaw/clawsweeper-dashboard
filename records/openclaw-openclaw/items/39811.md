## Summary

Keep open: current main only rejects statically suppressed model refs and hook-specific catalog misses, while the reported arbitrary configured-model misconfiguration class remains possible and is already tied to an open linked fix candidate plus maintainer policy questions.

## What This Changes

The issue asks OpenClaw to validate or warn on unrecognized configured model names so invalid primary or fallback models are not silently accepted and discovered only at runtime.

## Best Possible Solution

Land or replace the linked validation work with a shared analyzer used by `openclaw config validate`, `openclaw doctor`, and config-write paths that resolves refs like runtime does, distinguishes trusted catalog absence from custom model setups, and covers primaries, fallbacks, per-agent refs, model-map keys, aliases, and legacy `default`-style entries.

## Reproduction Assessment

Yes. Source inspection shows configured model strings are accepted structurally and current validation only rejects manifest-suppressed refs or the hook-specific doctor path, so an arbitrary unsuppressed bogus model can still pass upfront validation.

## Solution Assessment

No complete solution is on main yet. The best fix is not a simple hard rejection of every unknown string; it needs maintainer-approved warning/error semantics and trusted-catalog handling for custom and forward-compatible provider setups.
