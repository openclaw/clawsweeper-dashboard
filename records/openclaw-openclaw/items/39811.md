## Summary

Keep open: current main still only rejects manifest-suppressed configured model refs, while doctor catalog validation is scoped to `hooks.gmail.model`; the generic default/per-agent/fallback validation requested here remains unresolved. The related same-repo PR was closed unmerged, and the downstream `openclaw-extensions doctor` workaround is useful supporting evidence rather than an upstream fix.

## What This Changes

The issue requests config/doctor validation and user-facing warnings for invalid configured model references before they silently fail or fall back at runtime.

## Best Possible Solution

Adopt warning-first, catalog-aware validation in `openclaw config validate` and doctor that uses runtime-equivalent ref resolution, distinguishes trusted catalog evidence from user-declared rows, covers defaults/per-agent/fallbacks, and leaves broader fallback-notification behavior separate.
