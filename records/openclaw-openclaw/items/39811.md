## Summary

Keep open: current main has improved fallback visibility, but configured model references are still not validated generically against a trusted catalog in `config validate` or doctor. The remaining work needs maintainer policy on catalog authority and warning-versus-error behavior because custom, proxy, local, and forward-compatible model refs are plausible supported inputs.

## What This Changes

The issue asks OpenClaw to warn or reject configured primary, fallback, and per-agent model refs that are unknown before they fail or silently fall back at runtime.

## Best Possible Solution

Add warning-first `config validate` and doctor coverage for all configured model refs using runtime-equivalent parsing, trusted catalog/source semantics, sanitized output, and tests for custom and forward-compatible refs.

Rationale: Automation can identify the missing validation path, but only maintainers can choose the permanent compatibility policy for custom provider catalogs and future model refs.

Options:

- **Warning-first validation (recommended):** Surface advisory warnings in `config validate` and doctor while preserving runtime compatibility for custom and forward-compatible refs.
- **Strict validation:** Reject unknown configured refs before runtime, accepting that some custom or future refs need an explicit escape hatch or migration path.
- **Runtime/status only:** Keep validation permissive and rely on improved runtime errors, fallback visibility, and status output instead of preflight catalog checks.
