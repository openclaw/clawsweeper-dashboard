## Summary

Keep open: current main has fallback notice/status support, but broad catalog-backed validation for arbitrary configured model refs still is not implemented; the open closing fork PR is conflicting and unmerged, so it cannot close the issue yet.

## What This Changes

The issue asks OpenClaw to warn or fail early when configured primary, fallback, or per-agent model refs cannot be resolved against trusted provider catalog evidence.

## Best Possible Solution

Land a narrow catalog-backed doctor/config validation path that warns on unknown configured model refs, preserves intentional custom or forward-compatible setups, and keeps the existing fallback notices/status behavior.

Rationale: The issue is valid, but OpenClaw policy treats config/default changes and fail-closed validation as compatibility-sensitive because strict catalog checks can break custom or future model refs.

Options:

- **Doctor warning first (recommended):** Add advisory doctor/config validate warnings for refs absent from trusted catalogs while keeping runtime forward-compatible behavior.
- **Strict config error:** Reject unknown configured refs during config validation and explicitly accept the upgrade risk for custom and future model IDs.
- **Suppressed refs only:** Keep the current behavior and only reject model refs that provider manifests explicitly suppress as retired or unsafe.
