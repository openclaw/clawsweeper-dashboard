## Summary

Keep open: current main and v2026.6.11 still only reject manifest-suppressed configured model refs and validate `hooks.gmail.model`; arbitrary invalid configured agent model refs remain unresolved. The open fork PR is conflicting and should be reviewed, sponsored, or replaced rather than treated as a landed fix.

## What This Changes

The issue requests early validation or warning for invalid configured model names and user-visible notice when model fallback hides a failed primary model.

## Best Possible Solution

Define warning-first catalog authority for configured model refs, then add `config validate` and doctor coverage for default, per-agent, fallback, channel, and hook refs while preserving an explicit custom or forward-compatible model path.
