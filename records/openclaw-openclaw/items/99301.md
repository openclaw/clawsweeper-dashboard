Keep open for ordinary maintainer review: current main and the latest release still have the unhandled scheduled Feishu streaming-card flush path, while the branch fixes that timer-owned promise boundary with focused regression coverage and no blocking review finding.

## What This Changes

The branch wraps the Feishu streaming-card scheduled flush update promise in a catch that logs failures and adds a fake-timer regression test for the rejected timer path.

## Best Possible Solution

Land the focused Feishu timer rejection handler with its regression test, keeping broader Feishu media retry or API-behavior questions separate from this narrow reliability fix.

## Reproduction Assessment

Yes at source level: current main schedules `this.update(pending)` from a timer without awaiting or catching the returned promise, so a rejected scheduled update can become an unhandled rejection. I did not run tests because this review is read-only.

## Solution Assessment

Yes: catching at the timer-owned fire-and-forget boundary is the narrowest maintainable fix. Changing `update()` itself would blur the normal awaited caller path, and the dispatcher already awaits ordinary streaming updates through `partialUpdateQueue`.
