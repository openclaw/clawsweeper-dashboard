## What This Changes

The issue reports that same-PID session `.jsonl.lock` files can survive gateway restart or recovery and block later session writes because the PID still appears alive.

## Best Possible Solution

Define and land one focused startup/recovery lock policy for same-PID transcript locks, with tests for legacy no-starttime, matching-starttime, active HELD_LOCKS, and too-old/hold-exceeded cases; keep broader live heartbeat or delivery races in their narrower trackers.
