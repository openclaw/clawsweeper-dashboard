## Summary

Keep open: current main and v2026.6.11 include partial self-owned session-lock recovery, but the startup sweep still preserves some current-PID/no-starttime or live OpenClaw-owned locks, and newer field reports show same-PID live-gateway lock contention remains unresolved.

## What This Changes

The issue asks OpenClaw to clear orphaned session `.jsonl.lock` files whose PID matches the starting gateway after in-memory lock ownership has been lost.

## Best Possible Solution

Keep the partial shipped reclaim behavior, resolve the stale fork PR, and have maintainers decide the remaining same-PID live-lock policy alongside the focused session-lock delivery and maxHold tracks.

## Reproduction Assessment

Yes at source and field-report level, but not as a fresh live current-main reproduction. Current source shows only partial startup/acquisition reclaim, and issue comments include same-PID live-gateway lock timeouts on recent shipped builds.

## Solution Assessment
