## Summary

Keep open: current main and v2026.6.11 partially reclaim same-PID orphan locks, but source and field evidence still leave live/recovery same-PID session-lock contention unresolved, and the linked cleanup PR is open and conflicting rather than a terminal fix.

## What This Changes

The issue asks OpenClaw to clear or reclaim orphaned session `.jsonl.lock` files owned by the current gateway PID so later session writes do not time out after restart or recovery.

## Best Possible Solution

Keep this as the canonical same-PID session-lock recovery thread until maintainers land or reject a focused lock-lifecycle policy with regression tests and live restart/recovery proof.

## Reproduction Assessment

Yes, source-level: current main still preserves some live/self-held session locks and reports `hold-exceeded` only, while the issue includes field logs of same-PID lock timeouts on shipped builds. I did not run a fresh live packaged gateway reproduction.

## Solution Assessment

Unclear as a single boot sweep. Current source shows boot cleanup is only a partial fix, so the best path is maintainer-approved live/restart lock-lifecycle policy plus focused tests and live proof.
