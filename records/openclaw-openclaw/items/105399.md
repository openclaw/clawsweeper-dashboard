## Summary

The PR fixes the raw rejection object, but not the complete operator diagnostic: the nested Baileys Boom is an `Error`, and the canonical formatter returns only its message before reading `output.statusCode`. Keep this PR open for a focused formatter/test repair; current main does not contain the change, and the protected `maintainer` label prevents cleanup closure.

## What This Changes

The PR changes WhatsApp connection-close rejection to use `lastDisconnect.error` when available and adds a regression test asserting the original Error, message, and status metadata survive.

## Best Possible Solution

Keep the direct nested Error rejection, but make the canonical formatter inspect Boom status and payload details before the generic Error fallback, with regression coverage for both the raw rejection and visible login-result message.
