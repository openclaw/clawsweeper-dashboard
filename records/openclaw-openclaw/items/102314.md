## Summary

This issue should stay open: current source and the latest release both show Workboard dispatch tells worker agents to report completion through Workboard lifecycle tools while starting the worker sub-agent without an explicit optional-tool allowlist, so the reported stuck-running card state is a valid shipped bug with a narrow repair path.

## What This Changes

The issue reports that Workboard automated card dispatch starts sub-agent worker sessions without the optional Workboard lifecycle tools needed to heartbeat, complete, or block dispatched cards.

## Best Possible Solution

Add a narrow explicit allowlist for the Workboard worker lifecycle tools on dispatched sub-agent runs while preserving optional tool gating for ordinary sessions.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source inspection: Workboard prompts dispatched workers to call lifecycle tools, but starts light-context sub-agent runs without toolsAllow while optional plugin tools require an explicit allowlist. No live run was executed in this read-only review.

## Solution Assessment

Yes, an explicit Workboard lifecycle tool allowlist is the narrowest maintainable fix. Removing optional: true would expose Workboard tools more broadly, and auto-completing cards on sub-agent end would be a separate product fallback that still would not give workers heartbeat or block tools.
