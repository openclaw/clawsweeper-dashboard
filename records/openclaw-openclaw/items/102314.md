## Label Justifications

- `P2`: This is a valid Workboard automation bug with limited blast radius: dispatched cards can remain running indefinitely, but core runtime availability is not blocked.
- `impact:session-state`: The issue leaves Workboard card execution and run state out of sync with the worker’s actual completion state.

## Summary

Keep open: current main and the latest release still show the Workboard dispatch path starting lightweight sub-agents without any way to grant the optional Workboard protocol tools, and no merged or open canonical fix now owns the remaining work.

## What This Changes

Workboard dispatch should give automated sub-agent workers access to the Workboard protocol tools so dispatched cards can complete, block, or heartbeat instead of remaining running.

## Best Possible Solution

Add a narrow plugin subagent/Gateway toolsAllow path and have Workboard pass only the worker protocol tools, with regression coverage and live dispatch proof.

Options:

- **Add subagent toolsAllow (recommended):** Extend the plugin subagent/Gateway path to forward an explicit allowlist, then have Workboard grant only its heartbeat, completion, block, proof, log, attachment, and release tools to dispatched workers.
- **Make Workboard tools default:** Remove optional gating for some or all Workboard tools, accepting a broader default tool surface for normal sessions.
- **Use lifecycle fallback only:** Block or recover cards when a worker exits without protocol tools, which reduces stuck cards but does not give workers the documented completion path.

## Reproduction Assessment

Yes by source inspection: dispatch prompts workers to use Workboard tools, but optional Workboard tools are filtered unless allowlisted and the plugin subagent path has no allowlist field. I did not run a live Gateway/provider worker in this read-only review.

## Solution Assessment

Unclear until maintainers choose the API seam. A narrow toolsAllow path for plugin subagents appears to be the best owner-boundary fix; broadening default Workboard tools is riskier, and lifecycle fallback alone only recovers after failure.
