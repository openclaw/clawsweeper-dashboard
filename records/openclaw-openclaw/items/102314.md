## What This Changes

The issue asks for automated Workboard dispatch workers to receive Workboard lifecycle tools so claimed cards do not remain running after worker completion.

## Best Possible Solution

Add a narrow plugin subagent/Gateway tool-allowlist path and have Workboard pass only the worker protocol tools, with regression coverage and live dispatch proof.

- **Make Workboard tools default:** Remove optional gating for some or all Workboard tools, accepting a broader default tool surface for normal sessions.
- **Use lifecycle fallback only:** Block or recover cards when a worker exits without protocol tools, reducing stuck cards without giving workers the documented completion path.

## Reproduction Assessment

Yes, by source inspection: dispatch prompts workers to use Workboard tools, but those tools are optional and the plugin subagent/Gateway path has no allowlist field to expose them. I did not run a live Gateway/provider worker in this read-only review.

## Solution Assessment

Unclear until maintainers choose the API seam. A narrow `toolsAllow` path for plugin subagents appears to be the best owner-boundary fix; broadening default Workboard tools is riskier, and lifecycle fallback alone only recovers after failure.
