## Summary

This is a fresh, concrete regression report against the current release line, and its central symptom—manual transcript truncation leaving session context accounting stale—needs a focused current-version reproduction before it can be closed. Current main has moved the active session store toward SQLite and documents that legacy `sessions.json` is not the runtime authority, so the report should be narrowed to the Gateway compaction result and live session state rather than manual edits to the legacy store.

## What This Changes

The issue requests reliable session-compaction accounting and recovery when manual truncation or safeguard auto-compaction leaves a session unable to continue.

## System Context

Session compaction is a Gateway-owned path that either summarizes older conversation or truncates a transcript through `sessions.compact`, then updates the session state used for subsequent model runs and status reporting. Transcript/session storage and token freshness signals feed compaction thresholds, overflow recovery, and the user-visible session status.

Reproduce the manual `--max-lines` path and one safeguard-overflow path on the current release, capture the Gateway session state before and after each, then make the Gateway invalidate or replace only context-size metadata that no longer represents the compacted active transcript; track any independent summarization fallback or configuration request separately.
