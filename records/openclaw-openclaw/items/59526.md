## Summary

Keep open: current main still supports typed auth-profile pinning and auth-order commands, but `/models` channel pickers remain provider/model/runtime selectors with no first-class account/profile choice or active-account display. The linked PR is useful partial overlap for preserving existing profile overrides during model-only selection, but it does not implement the requested picker UX and is still open/conflicting.

## What This Changes

Request account/profile selection and active-account display directly in the `/models` buttons/menu for GPT/OpenAI and Claude/Anthropic-backed models.

## Best Possible Solution

Define one shared `/models` account/profile picker contract that enumerates compatible auth profiles for the selected provider/model, shows the active profile, and persists through existing session/auth helpers across supported channels.
