## Summary

Keep open: current main and latest release still expose `/models` as provider/model picker state only, while account/profile selection remains available through typed `/model ...@profile` and status/order flows. The related open PR is useful partial overlap for preserving existing auth-profile state during model selection, but it does not add the requested account picker UX.

## What This Changes

Request to let the `/models` picker buttons/menu choose both a provider model and the backing provider account/auth profile for GPT/OpenAI and Claude/Anthropic models.

## Best Possible Solution

Define a shared `/models` account/profile picker contract that enumerates compatible auth profiles for the selected provider/model, shows the active profile, and persists through the existing session/auth helpers across supported channels.

## Solution Assessment

Unclear until maintainers choose product semantics. The maintainable direction is a shared auth-profile picker contract rather than raw model-string editing or separate channel-specific account encodings.
