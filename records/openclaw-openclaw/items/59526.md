## Summary

Keep open: current main and v2026.6.11 still provide typed profile pinning and status, but `/models` picker payloads and Discord/Telegram callbacks remain provider/model/runtime oriented rather than first-class account/profile selection. The related open PR is useful partial overlap for preserving existing auth-profile state, but it does not add the requested account picker UX.

## What This Changes

Request first-class account/profile selection and active account display in `/models` buttons for GPT/OpenAI and Claude/Anthropic models.

## Best Possible Solution

Define a shared `/models` account/profile picker contract that enumerates compatible auth profiles for the selected provider/model, shows the active profile, and persists through the existing model/auth session helpers across supported channels.
