- `maturity:stable`: The issue affects Discord native model picker behavior, and the Discord taxonomy feature is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main supports typed per-session auth profile overrides with `/model ...@<profileId>` and status/auth listing, but the `/models` picker surfaces still expose provider/model selection rather than account/profile choices or active account display. The open related PR is useful partial overlap for preserving existing auth-profile state during picker selections, but it does not implement the requested account-switching UX.

## What This Changes

Add account/profile switching and active-account visibility directly to `/models` picker controls for providers such as OpenAI/GPT and Claude/Anthropic.

## Best Possible Solution

Define one account/profile picker contract on top of the existing session `authProfileOverride` state, then wire Discord, Telegram, text/status docs, and focused tests to the same behavior.
