## Summary

Keep open: current main still supports typed `/model ...@profile` profile pinning, but the `/models` picker paths remain provider/model/runtime oriented and do not expose first-class account/profile selection or active account display.

## What This Changes

The issue requests account selection directly inside the `/models` picker for GPT/OpenAI and Claude-backed models.

## Best Possible Solution

Define a shared `/models` account/profile picker contract that enumerates compatible auth profiles for the selected provider/model, shows the active profile, and persists through existing model/auth session helpers across supported channels.
