## Summary

Keep open: current main and v2026.6.11 still expose `/models` as provider/model/runtime selection, while account/profile choice remains available through typed `/model ...@profile` and auth-order/status flows. The related open PR is useful partial overlap for preserving an existing auth profile during model-only picker selections, but it does not add account selection or active-account display in the picker.

## What This Changes

Request to let `/models` buttons show and switch provider account/auth profiles for GPT/OpenAI and Claude/Anthropic models.

## Best Possible Solution

Define a shared account/profile picker contract that enumerates compatible profiles, shows the active profile, and applies selections through existing session/auth-profile helpers across supported channel pickers.

- **Pilot one channel first:** Approve a narrower channel experiment while documenting that other channel pickers stay unchanged until the shared contract is accepted.

## Solution Assessment

Unclear until maintainers choose the UX and compatibility semantics. The maintainable path is a shared picker/profile contract, not raw model-string editing or separate channel-specific account hacks.
