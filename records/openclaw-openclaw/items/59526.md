## Summary

Keep open: current main and v2026.6.11 still support account/profile pinning through typed `/model ...@<profileId>` and auth-order/status flows, but the `/models` interactive payloads and Telegram/Discord picker state still only carry provider/model/runtime choices. The linked preservation PR is useful adjacent work, but it does not add account selection or active-account display in the picker.

## What This Changes

Add first-class account/profile switching and active-account display to the `/models` button/menu flow for GPT/OpenAI and Claude/Anthropic-style provider accounts.

## Best Possible Solution

Define one shared `/models` account/profile picker contract that lists compatible auth profiles for the selected provider/model, shows the active profile, and persists through existing session/auth helpers across supported channel pickers.
