## Summary

Keep open: current main and the latest release still expose `/models` picker state as provider/model/runtime selection, while account/profile pinning remains available through typed `/model ...@profile` and auth-order/status flows. The related open PR is useful partial overlap for preserving existing auth-profile state, but it does not add the requested account picker UX.

## What This Changes

Allow the `/models` picker/buttons to select and display the active provider auth account/profile for account-backed GPT/OpenAI and Claude/Anthropic models.

## Best Possible Solution

Define a shared `/models` account/profile picker contract that enumerates compatible auth profiles for the selected provider/model, shows the active profile, and persists through the existing session/auth helpers across supported channels.
