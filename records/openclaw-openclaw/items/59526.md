## Summary

Keep open: current main and v2026.6.11 still expose account/profile pinning through typed `/model <model>@<profileId>`, status, and auth-order flows, while the `/models` picker data and channel callbacks remain provider/model/runtime-only. The related open PR is useful partial overlap for preserving existing auth-profile state during model selection, but it does not add first-class account selection or active-account display in the picker.

## What This Changes

Request account switching from the chat `/models` picker so users can choose both provider model and configured account/profile for GPT/OpenAI and Claude/Anthropic-style providers.

## Best Possible Solution

Define a shared model-picker auth-profile contract that enumerates compatible profiles for the selected provider/model, displays the active account, and applies changes through existing session/auth helpers across supported channel pickers.
