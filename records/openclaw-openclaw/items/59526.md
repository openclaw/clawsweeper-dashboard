## Summary

Keep open: current main still does not let `/models` buttons choose or display provider accounts/auth profiles. The related open PR is useful adjacent work for preserving an existing auth-profile override during model selection, but it does not implement the requested account-switching picker UX.

## What This Changes

Request to let `/models` picker buttons choose and show provider accounts for GPT/OpenAI and Claude/Anthropic models.

## Best Possible Solution

Define a shared picker/profile contract that enumerates compatible auth profiles for each provider/model, shows the active profile, and reuses existing session/auth helpers across supported channels.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should `/models` become a first-class model-and-account picker for provider-backed models, and should that contract be shared across Discord, Telegram, and future channel pickers?

Rationale: Current code deliberately separates model selection from auth-profile state, and changing that affects cross-channel UX, provider routing, session persistence, and upgrade compatibility.

Likely owner: steipete

Owner reason: The history points to steipete for adjacent model/auth override behavior and auth-profile documentation, and the decision is primarily about product semantics for that state.

Owner confidence: high

Options:

- **Define shared picker support (recommended):** Add a shared account/profile selection contract to the model picker and implement it in supported channels with compatibility tests.
- **Keep typed profile pinning:** Keep `/model ...@profile`, `/model status`, and auth-order commands as the supported account-switching path and document that `/models` remains model-only.
- **Pilot one channel first:** Approve a narrower Discord or Telegram experiment before promoting the account-picker state to the shared contract.

## Reproduction Assessment

Yes, source-level: the shared channel adapter and Telegram/Discord picker state carry provider/model/runtime data but no account/profile choices. A live channel repro was not needed because this is a missing feature rather than a broken existing contract.

## Solution Assessment

Unclear until maintainers choose the product semantics; the maintainable solution is a shared picker/profile contract rather than raw model-string editing or separate channel-local account hacks.
