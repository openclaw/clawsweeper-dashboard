## Summary

Keep open: current main still treats `/models` picker actions as provider/model/runtime selection only, while account/profile selection remains available through typed `/model ...@profile` and auth-order commands. The related open PR is useful partial overlap for preserving an existing auth profile during model changes, but it does not add the requested account picker or active-account display.

## What This Changes

Request first-class account/profile switching directly from `/models` picker buttons for GPT/OpenAI and Claude/Anthropic models, including visible active-account state.

## Best Possible Solution

Define a shared `/models` account/profile picker contract that enumerates compatible profiles for each provider/model, shows the active profile, and persists through existing session/auth helpers across supported channels.
