## Summary

Keep open: current main and v2026.6.11 still expose `/models` as a provider/model/runtime picker, while account/profile selection remains available through typed `/model ...@profile` and auth-order flows. The open related PR is useful partial overlap for preserving an existing profile during picker changes, but it does not add first-class account switching or active-account display in the picker.

## What This Changes

Request to let `/models` buttons show and switch the active provider account/profile for GPT/OpenAI and Claude/Anthropic models.

## Best Possible Solution

Define a shared `/models` account/profile picker contract that enumerates compatible auth profiles for the selected provider/model, shows the active profile, and persists through existing session/auth helpers across supported channels.
