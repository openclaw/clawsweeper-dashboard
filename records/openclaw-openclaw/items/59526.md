## Summary

Keep open: current main and v2026.6.11 still expose `/models` as a provider/model picker, while account/profile selection remains available only through typed `/model ...@profile` and auth-order/status flows. The related open PR is useful partial overlap for preserving existing auth-profile state during model changes, but it does not add the requested account picker UX.

## What This Changes

The issue requests first-class account/profile switching and active-account visibility inside the `/models` picker for OpenAI/GPT and Anthropic/Claude models.

## Best Possible Solution

Define a shared `/models` account/profile picker contract that enumerates compatible auth profiles for the selected provider/model, shows the active profile, and persists through existing session/auth helpers across supported channel pickers.
