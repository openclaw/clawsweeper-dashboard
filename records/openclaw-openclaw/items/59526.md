## Summary

Keep open: current main and v2026.6.11 still expose `/models` picker state as provider/model/runtime selection, while account/profile switching remains available through typed `/model ...@profile` and CLI auth-order flows. The related open PR at https://github.com/openclaw/openclaw/pull/92254 is useful partial overlap for preserving existing auth-profile state, but it does not add account selection or active-account display to the picker.

## What This Changes

The issue requests account/profile selection directly inside the `/models` picker UI for GPT/OpenAI and Claude/Anthropic-backed models.

## Best Possible Solution

Define one shared `/models` account/profile picker contract that enumerates compatible auth profiles for the selected provider/model, shows the active profile, and persists through the existing session/auth helpers across supported channel pickers.
