## Summary

Keep open: current main and v2026.6.11 still expose `/models` as model/provider/runtime selection, while account/auth-profile selection remains available only through typed `/model ...@profile` and provider auth-order flows. The related open PR is useful partial overlap for preserving existing auth-profile state during picker changes, but it does not add the requested account picker UX.

## What This Changes

Request `/models` buttons/menus to let users choose both a provider model and the backing account/auth profile, with the active account visible for GPT/OpenAI and Claude/Anthropic-style models.

## Best Possible Solution

Define a shared `/models` account/profile picker contract that enumerates compatible auth profiles for the selected provider/model, shows the active profile, and persists through the existing session/auth helpers across supported channel pickers.
