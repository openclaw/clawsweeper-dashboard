## Summary

Keep open: current main and v2026.6.11 still expose `/models` picker state as provider/model/runtime only; typed `/model ...@profile` exists, but the requested account/profile picker UX remains a product decision.

## What This Changes

Request to let users choose and view the backing auth account/profile directly from `/models` buttons for GPT/OpenAI and Claude/Anthropic models.

## Best Possible Solution

Define a shared `/models` account/profile picker contract that enumerates compatible auth profiles for the selected provider/model, shows the active profile, and persists through the existing session/auth helpers across supported channels.

Rationale: The lower-level auth-profile machinery exists, but picker UX, persistence semantics, compatibility with typed `/model ...@profile`, and channel callback shape need maintainer product direction before implementation.

- **Pilot one channel first:** Approve a narrower Discord or Telegram experiment while explicitly leaving other channel pickers unchanged until the shared contract is accepted.

## Solution Assessment

Unclear until maintainers choose the UX and compatibility semantics. The maintainable path is a shared picker/profile contract, not raw model-string editing or separate channel-specific account hacks.
