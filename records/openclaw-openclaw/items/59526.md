## Summary

Keep open: current main still exposes `/models` as provider/model/runtime selection, while account/profile switching remains a typed `/model ...@profile` and auth-order/status flow. The related open PR is useful partial overlap for preserving compatible auth-profile state, but it does not add the requested account picker UX.

## What This Changes

Request `/models` buttons/menus to let users choose both a GPT/OpenAI or Claude/Anthropic model and the backing provider account/auth profile.

## Best Possible Solution

Define a shared `/models` account/profile picker contract that enumerates compatible auth profiles for the selected provider/model, shows the active profile, and persists through existing session/auth helpers across supported channels.
