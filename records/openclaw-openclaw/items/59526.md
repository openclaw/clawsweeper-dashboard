## Summary

Keep open: current main still has typed `/model ...@<profileId>` profile pinning, but the `/models` picker payloads and Telegram/Discord picker callbacks remain provider/model/runtime oriented and do not offer first-class account selection or active-account display. The related open preservation PR is useful adjacent work, but it preserves an existing compatible auth profile rather than adding the requested account/profile picker UX.

## What This Changes

The issue requests first-class provider account/auth-profile selection and active-account display from the `/models` picker for OpenAI/GPT and Anthropic/Claude models.

## Best Possible Solution

Define a shared `/models` auth-profile picker contract that lists compatible profiles per provider/model, marks the active profile, and persists through the existing session model/auth helpers across supported channels.
