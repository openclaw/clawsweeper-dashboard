## Summary

Keep open: current main and the latest release still expose model/provider/runtime picker state but not first-class account/profile selection from `/models`. Existing typed `/model ...@profile` support and the related open preservation PR are useful partial coverage, but they do not satisfy the requested account picker UX.

## What This Changes

Requested adding account/profile selection and active-account display directly to the `/models` button UI for GPT/OpenAI and Claude/Anthropic-backed models.

## Best Possible Solution

Define a shared `/models` account/profile picker contract that enumerates compatible auth profiles for the selected provider/model, shows the active profile, and persists through the existing model/auth session helpers across supported channels.
