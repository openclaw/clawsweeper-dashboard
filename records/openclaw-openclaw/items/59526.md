## Summary

Keep open: current main and v2026.6.11 still expose `/models` picker state as provider/model/runtime selection, while account/profile selection remains a typed `/model ...@profile` workflow; the related open PR only preserves existing profile overrides during model changes and does not add the requested picker account selector.

## What This Changes

The issue requests first-class account/profile switching and active account display from the `/models` button/menu UI for GPT/OpenAI and Claude/Anthropic-backed models.

## Best Possible Solution

Define one shared `/models` account/profile picker contract that enumerates compatible provider auth profiles, shows the active profile, and persists through existing session/auth override helpers across supported channel pickers.
