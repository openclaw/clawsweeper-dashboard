## Summary

Keep open: current main and the latest release still expose model/provider picker state, while account/profile selection is available through typed `/model ...@profile` and auth-order flows rather than the requested `/models` button UX. The linked preservation PR is useful partial overlap, but it does not add account selection or active-account display in the picker.

## What This Changes

Request to let `/models` buttons/menu choose and display the backing auth account/profile for GPT/OpenAI and Claude/Anthropic models.

## Best Possible Solution

Define a shared account/profile picker contract for `/models` that lists compatible auth profiles for the selected provider/model, shows the active profile, and reuses existing session/auth helpers across supported channels.

- **Pilot One Channel First:** Approve a narrower experiment in one channel while documenting that other channel pickers stay unchanged until the shared contract is accepted.

## Solution Assessment

Unclear until maintainers choose the UX shape. The maintainable direction is to extend the shared picker/profile contract rather than add raw model-string editing or channel-specific account hacks.
