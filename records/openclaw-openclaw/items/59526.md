## Summary

Keep open: current main and v2026.6.11 still model `/models` buttons as provider/model selection only. Typed `/model ...@profile` account pinning exists, and #92254 is useful partial overlap for preserving existing profile state, but neither adds first-class account/profile choice or active account rows to the picker.

## What This Changes

Request to let `/models` button/menu flows choose and show provider auth profiles/accounts for GPT/OpenAI and Claude/Anthropic models.

## Best Possible Solution

Define one shared typed model-picker account/profile contract that enumerates compatible profiles for the chosen provider/model, shows the active profile, and persists through existing session auth helpers across Telegram and Discord.
