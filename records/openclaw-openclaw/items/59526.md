## Summary

Keep open: current main and v2026.6.11 still expose `/models` picker state as provider/model/runtime selection, while account/profile switching remains a typed `/model ...@profile` path. The related open pull request is useful partial overlap for preserving an existing auth profile during model-only selection, but it does not add the requested account picker or active-account display.

## What This Changes

The issue requests adding account/profile selection and visible active account state directly to the `/models` picker for GPT/OpenAI and Claude-style providers.

## Best Possible Solution

Define a shared `/models` account/profile picker contract that enumerates compatible auth profiles for the selected provider/model, shows the active profile, and persists through the existing session/auth helpers across supported channels.
