## Summary

Keep open: current main and v2026.6.11 still expose `/models` picker state as provider/model/runtime selection only. Typed `/model ...@<profileId>` account pinning exists, and the related preservation PR is useful partial overlap, but neither adds account/profile choices or active-account display to the picker UX.

## What This Changes

Requests `/models` buttons/menu to let users select both a provider model and configured provider account/profile, with the active account visible for GPT/OpenAI and Claude/Anthropic models.

## Best Possible Solution

Define a shared `/models` account/profile picker contract that enumerates compatible auth profiles for the selected provider/model, shows the active profile, and persists through the existing session/auth helpers across supported channels.
