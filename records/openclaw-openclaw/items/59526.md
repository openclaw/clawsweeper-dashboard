## Label Justifications

- `P2`: This is a normal-priority provider/account UX improvement with a clear source gap but no evidence of a blocked core runtime path.
- `impact:auth-provider`: The request is specifically about selecting which configured provider account/auth profile backs a chosen GPT/OpenAI or Claude/Anthropic model.
- `impact:ux-friction`: Users can proceed through typed model/profile refs and auth-order configuration, but the picker flow remains awkward for frequent account switching.

## Summary

Keep open: current main still separates model selection from account/profile selection in the `/models` picker, and the related open model-picker PR only preserves an existing compatible auth-profile override rather than adding the requested account-switching UI.

## What This Changes

Request `/models` buttons and menus to show and switch provider accounts for GPT/OpenAI and Claude/Anthropic models without manually editing raw model/profile strings.

## Best Possible Solution

Define one shared account/profile picker contract that lists compatible profiles for the selected provider/model, shows the active profile, and persists through existing session auth-profile helpers across Discord, Telegram, and Gateway flows.

Options:

- **Define shared picker contract (recommended):** Add account/profile metadata and actions to the shared `/models` surface, then implement channel renderers against that contract.
- **Keep typed account controls:** Keep `/model ...@profile`, `/model status`, and CLI auth order as the supported account-switching path and close this feature as not planned.
- **Pilot one channel behind shared data:** Start with one channel only if maintainers first define the shared model/profile data shape so the pilot does not become a divergent contract.

## Reproduction Assessment

Yes, at source level: current `/models` picker data and Discord/Telegram callbacks carry provider/model/runtime choices but no selectable account/profile choice. The supported current account path is documented typed profile pinning and auth-order configuration.

## Solution Assessment

Unclear until maintainers choose the product direction; a shared picker contract is the safest implementation shape if this feature is accepted. Channel-specific string inference or independent account menus would be a poorer fit because auth/profile state is shared session behavior.
