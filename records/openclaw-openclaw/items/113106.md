## Label Justifications

- `P2`: Malformed Xiaomi TTS responses can produce unusable audio for affected provider users, but the change has a limited optional-provider blast radius.

## Summary

This PR remains necessary: the Xiaomi TTS decode boundary currently accepts any non-empty string and relies on Node’s permissive Base64 decoding, so malformed provider payloads can become corrupt audio. The proposed shared-helper validation is a narrow, consistent fix with focused regression coverage and credible live before/after proof; it should proceed through normal current-base review rather than close cleanup.

## What This Changes

This PR validates Xiaomi text-to-speech audio data with the shared Base64 canonicalizer and adds a regression test that malformed provider responses fail instead of producing corrupted audio bytes.

## System Context

The Xiaomi plugin calls Xiaomi’s text-to-speech API and converts its returned Base64 audio field into a buffer for audio files or voice-note transcoding. This change guards the network-response decoding boundary so invalid provider data fails before it can reach downstream audio output.
