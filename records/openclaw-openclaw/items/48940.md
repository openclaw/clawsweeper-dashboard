Full review comments:

- **[P1] Move durable ACP state out of JSON sidecar storage:** `src/acp/store/store.ts:112`
  - body: This adds `state/acp/gateway-node-runtime-store.json` for sessions, runs, worker events, leases, checkpoints, delivery targets, and idempotency. OpenClaw-owned runtime state under state dirs is required to use SQLite/shared state DB or an explicitly designed DB schema, so this bypasses migration/doctor handling and creates recovery/upgrade debt for the core durability path.
  - confidence: 0.93
- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke.ts:426`
  - body: The new ACP invoke path sends worker events through `sendNodeEvent`, but that helper catches and ignores `client.request("node.event", ...)` failures. A node can therefore report an ACP turn as accepted or completed locally while the gateway never records the event or terminal, leaving the durable run stuck in recovery and replay state inconsistent.
  - confidence: 0.9
- **[P1] Do not restart an active projection runner:** `src/auto-reply/reply/dispatch-acp-replay.ts:456`
  - body: When a target already has an active runner, `ensureProjection` calls `existing.start()`, and `start()` always launches another `run()` loop. A second ensure for the same target can race the first loop on the same events/checkpoints and duplicate outward delivery instead of deduplicating projection work.
