  - body: `handleAcpInvokeCommand` receives `sendNodeEvent`, but the helper underneath swallows `client.request("node.event", ...)` failures. An ACP worker can therefore settle locally while the gateway never records the event or terminal, leaving the durable run stuck in recovery.
  - confidence: 0.92
- **[P1] Reuse the active projection runner:** `src/auto-reply/reply/dispatch-acp-replay.ts:456`
  - body: When a target already has an active runner, calling `existing.start()` starts another `run()` loop because `start()` is not idempotent. A second ensure for the same target can race checkpoints or duplicate outbound delivery instead of joining the existing projection.
  - confidence: 0.91
- **[P2] Stop projections when turn start creates no run:** `src/auto-reply/reply/dispatch-acp.ts:396`
  - body: The durable dispatch path starts a wait-for-run projection before `runTurn`, then rethrows `turnError` when no durable run was created. That branch never stops the projection, so it can keep polling forever for a run that cannot appear.
  - confidence: 0.9
- **[P1] Serialize reconnect reconciliation before worker events:** `src/gateway/server/ws-connection/message-handler.ts:1024`
  - body: `handleNodeConnected` is launched fire-and-forget, so worker traffic can be accepted before suspect lease reconciliation finishes. In that window valid same-node progress can be rejected as missing an active lease and strand a run in recovery.
  - confidence: 0.88
- **[P1] Validate run reuse by session and request:** `src/acp/store/store.ts:534`
  - body: `startRun` returns any existing `store.runs[runId]` without checking that it belongs to the same session and request. A cross-session run ID collision can alias durable state and corrupt later event, terminal, and delivery bookkeeping.
