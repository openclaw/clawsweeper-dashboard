## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Move ACP durable state out of the JSON sidecar:** `src/acp/store/store.ts:111-112`
  - body: This store makes sessions, runs, worker events, leases, delivery targets, checkpoints, and idempotency authoritative in `state/acp/gateway-node-runtime-store.json`. OpenClaw runtime state is supposed to live in the canonical SQLite stores, so landing this would create a parallel migration/upgrade path for exactly the state that restart replay depends on.
  - confidence: 0.91
- **[P1] Reject run IDs that belong to another session:** `src/acp/store/store.ts:532-535`
  - body: `startRun` returns any existing `store.runs[runId]` before checking `sessionKey` or `requestId`. If two ACP sessions produce the same request/run id, the second session will alias the first run and later worker events will fail validation or corrupt delivery bookkeeping; require the existing run to match the same session and request before treating it as idempotent.
  - confidence: 0.95
- **[P1] Return the active projection instead of starting it again:** `src/auto-reply/reply/dispatch-acp-replay.ts:454-457`
  - body: When a target already has an active projection runner, `ensureProjection` calls `existing.start()`, but `start()` launches another `run()` loop on the same runner. A second ensure for the same target can therefore create competing delivery loops and race checkpoint updates instead of deduplicating projection work.
  - confidence: 0.93
- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke-acp.ts:865-874`
  - body: The ACP worker bridge advances `deliveredSeq` after awaiting `sendNodeEvent`, but the node-host `sendNodeEvent` implementation swallows `node.event` request failures. A dropped worker event or terminal is then treated as delivered locally, leaving the gateway without the durable terminal and the node session incorrectly settled.
  - confidence: 0.9
- **[P1] Await reconnect reconcile before accepting ACP worker events:** `src/gateway/server/ws-connection/message-handler.ts:1024-1038`
  - body: The node connect handler starts `handleNodeConnected` as fire-and-forget. During that window, incoming `acp.worker.event` or `acp.worker.terminal` traffic can hit the store while the lease is still `suspect`, be rejected as missing an active lease, and leave a live node-backed run stuck in recovery.
  - confidence: 0.88
- **[P2] Stop the pending projection when turn creation fails:** `src/auto-reply/reply/dispatch-acp.ts:394-397`
  - body: If `acpManager.runTurn` fails before a durable run record exists, this branch rethrows without stopping the projection runner that was started with `waitForRunStart: true`. That runner keeps polling for a run that will never appear, leaking a background loop per early failed dispatch.
  - confidence: 0.86
