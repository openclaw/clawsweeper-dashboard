## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke.ts:426`
  - body: The ACP command path awaits `sendNodeEvent`, but that helper catches and drops `client.request("node.event")` failures. For ACP worker events and terminals, treating a dropped gateway write as success lets the node settle locally while the gateway never records the terminal, so durable recovery and replay state can diverge. Use a non-best-effort ACP event sender or otherwise surface the transport failure to the ACP command handler.
  - confidence: 0.9
- **[P1] Reuse the active projection instead of restarting it:** `src/auto-reply/reply/dispatch-acp-replay.ts:456`
  - body: When a target is already active, `ensureProjection` calls `existing.start()`, and `start()` launches `run()` every time. A second ensure for the same `targetKey` can therefore create another polling/delivery loop over the same run, duplicating outbound effects and racing checkpoint writes. Return the existing settled promise without starting another runner.
  - confidence: 0.88
- **[P1] Stop the projection runner on early turn-start failure:** `src/auto-reply/reply/dispatch-acp.ts:395-396`
  - body: The durable ACP path starts a wait-for-run projection before `runTurn`; if `runTurn` fails before a durable run exists, this branch rethrows without stopping the runner. Because the runner keeps returning false while the run is missing, each early failure can leak a background polling loop for a run that will never appear. Stop the projection service or runner before rethrowing.
  - confidence: 0.86
- **[P1] Await ACP reconnect reconcile before worker events:** `src/gateway/server/ws-connection/message-handler.ts:1024-1034`
  - body: Node registration starts `handleNodeConnected` in the background and then continues accepting node traffic. A reconnecting ACP worker can send an event or terminal before suspect lease reconciliation finishes, causing the store to reject valid progress as missing an active lease. Gate ACP worker traffic until reconcile settles, or make the ACP event path perform the needed reconciliation before validation.
  - confidence: 0.84
- **[P1] Reject run ID reuse across sessions:** `src/acp/store/store.ts:532-534`
  - body: `startRun` returns any existing `store.runs[runId]` as idempotent without checking that it belongs to the same session and request. Since dispatch uses inbound message identifiers as run IDs when available, two sessions can collide and the second session will reuse the first run record, corrupting lease validation and delivery bookkeeping. Require matching `sessionKey` and `requestId`, or namespace run IDs by session.
  - confidence: 0.9
