## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Move ACP runtime state into SQLite:** `src/acp/store/store.ts:112`
  - body: This store writes durable runtime state to `state/acp/gateway-node-runtime-store.json`. ACP sessions, runs, events, leases, checkpoints, delivery targets, and idempotency are product state, so keeping them in a JSON sidecar bypasses the shared SQLite state model, doctor migration ownership, and normal backup/recovery expectations.
  - confidence: 0.9
- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke.ts:424-427`
  - body: The ACP path now passes the shared `sendNodeEvent` helper into `handleAcpInvokeCommand`, but that helper catches and ignores `node.event` request failures. A node can therefore finish a turn locally while the gateway never records the worker event or terminal, leaving the durable run stuck or inconsistent.
  - confidence: 0.88
- **[P1] Do not restart active projection runners:** `src/auto-reply/reply/dispatch-acp-replay.ts:454-456`
  - body: When a projection already exists for a target, this calls `existing.start()`. `start()` launches `this.run()` every call, so a second ensure for the same target starts another polling/delivery loop against the same checkpoint and can duplicate sends or race checkpoint updates.
  - confidence: 0.9
- **[P1] Stop the projection runner on pre-run failures:** `src/auto-reply/reply/dispatch-acp.ts:394-396`
  - body: If `runTurn` fails before a durable run record exists, this branch rethrows `turnError` after a projection was started with `waitForRunStart: true`. Nothing stops that runner, so it keeps polling forever for a run that will never be created.
  - confidence: 0.84
- **[P1] Await reconnect reconciliation before worker frames:** `src/gateway/server/ws-connection/message-handler.ts:1024-1034`
  - body: `handleNodeConnected` is launched fire-and-forget after registration. During reconnect, worker events can arrive before the suspect lease is reactivated, causing `validateActiveLeaseBinding` to reject valid progress and leaving a completed node turn stranded in recovery.
  - confidence: 0.86
- **[P1] Reject cross-session run id reuse:** `src/acp/store/store.ts:532-535`
  - body: `startRun` returns any existing `store.runs[runId]` without checking that the existing record belongs to the same session and request. If two sessions produce the same request/run id, the second session aliases the first run and later lease/session validation rejects its worker traffic.
  - confidence: 0.82
- **[P1] Gate ACP node commands explicitly:** `src/gateway/node-command-policy.ts:54-57`
  - body: Adding ACP commands to `SYSTEM_COMMANDS` makes session/turn control default-authorized for desktop node platforms. These commands execute ACP worker control over the gateway/node trust boundary and need an explicit ACP-specific policy gate or opt-in before becoming defaults.
  - confidence: 0.83
- **[P3] Reject array ACP envelopes at the object check:** `src/acp/store/gateway-events.ts:50-52`
  - body: `isRecord` accepts arrays here, so a JSON array reaches field validators and reports misleading field errors instead of the intended object-envelope error. The sibling helper in `src/acp/runtime/acp-node.ts` already excludes arrays.
  - confidence: 0.76
