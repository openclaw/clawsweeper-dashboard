## Review Findings

Overall confidence: 0.88

Full review comments:

- **[P1] Use SQLite for durable ACP gateway state:** `src/acp/store/store.ts:111-112`
  - body: This store persists OpenClaw-owned runtime sessions, runs, events, leases, checkpoints, and idempotency as a JSON sidecar under the state dir. Repository policy makes SQLite the default for runtime state, so landing this path would create upgrade and recovery debt instead of using the canonical store.
  - confidence: 0.94
- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke.ts:425-426`
  - body: The ACP node-host path wires worker events through `sendNodeEvent`, but that helper catches and ignores `node.event` request failures. A dropped non-terminal event or terminal can therefore be treated as delivered locally while the gateway store never records it, leaving recovery and replay state inconsistent.
  - confidence: 0.91
- **[P1] Return the active projection instead of starting it again:** `src/auto-reply/reply/dispatch-acp-replay.ts:454-456`
  - body: When a projection for the same target is already active, `ensureProjection` calls `existing.start()`, and `start()` launches a fresh `run()` loop every call. Duplicate loops can race outbound delivery and checkpoint updates for the same ACP run.
  - confidence: 0.9
- **[P2] Stop the projection runner when turn start creates no run:** `src/auto-reply/reply/dispatch-acp.ts:395-396`
  - body: If `acpManager.runTurn` fails before a durable run exists, the code rethrows after checking `getRun`, but the projection started with `waitForRunStart: true` is not stopped. That leaves a background poller waiting for a run that will never appear.
  - confidence: 0.86
- **[P1] Await ACP reconnect reconciliation before worker events:** `src/gateway/server/ws-connection/message-handler.ts:1024`
  - body: Node connect starts ACP lease reconciliation as fire-and-forget work, so incoming `acp.worker.*` traffic can be handled while the store still has a suspect lease. A valid reconnecting worker can then have progress rejected before reconciliation completes.
  - confidence: 0.88
- **[P1] Scope run idempotency by session and request:** `src/acp/store/store.ts:532-535`
  - body: `startRun` returns any existing record for the same `runId` without checking that it belongs to the same `sessionKey` and `requestId`. A run-id collision across sessions can alias one session to another run and corrupt recovery bookkeeping.
  - confidence: 0.9
