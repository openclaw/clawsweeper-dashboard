## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Move ACP durable state out of the JSON sidecar:** `src/acp/store/store.ts:111-113`
  - body: This adds long-lived ACP sessions, runs, events, leases, delivery targets, checkpoints, and idempotency under `state/acp/gateway-node-runtime-store.json`. OpenClaw's runtime state is supposed to live in SQLite so migrations, doctor repair, backup, permissions, and upgrade behavior have one owner; this needs to use the shared state DB or an explicitly approved dedicated SQLite schema before merge.
  - confidence: 0.93
- **[P1] Reject run IDs owned by another session:** `src/acp/store/store.ts:532-534`
  - body: `startRun` returns any existing `store.runs[runId]` before checking that it belongs to the same `sessionKey` and `requestId`. If two sessions produce the same run ID, the second session aliases the first run and later worker events fail or corrupt delivery bookkeeping; require matching ownership before treating it as idempotent.
  - confidence: 0.9
- **[P1] Return the active projection instead of starting it again:** `src/auto-reply/reply/dispatch-acp-replay.ts:454-456`
  - body: When a target already has an active projection, `ensureProjection` calls `existing.start()`, but `start()` launches `this.run()` every time. A second ensure for the same target can therefore create another polling/delivery loop racing the same checkpoints and outbound sends.
  - confidence: 0.88
- **[P1] Do not send ACP worker events through best-effort transport:** `src/node-host/invoke.ts:425-426`
  - body: The ACP command path wires worker events through `sendNodeEvent`, whose `node.event` request catches and ignores failures. ACP events and terminals are the durable authority for gateway state, so transport failures must propagate to the worker/session error path instead of being treated like best-effort telemetry.
  - confidence: 0.86
- **[P1] Await reconnect reconcile before accepting ACP worker events:** `src/gateway/server/ws-connection/message-handler.ts:1024-1038`
  - body: `handleNodeConnected` runs fire-and-forget on reconnect, so a worker event can arrive while the lease is still `suspect` and be rejected before the status reconcile reactivates it. Reconnect handling needs to gate ACP worker ingress or otherwise buffer/retry until reconciliation finishes.
  - confidence: 0.84
- **[P2] Stop the pending projection when turn creation fails:** `src/auto-reply/reply/dispatch-acp.ts:394-396`
  - body: The durable path starts a projection with `waitForRunStart: true` and then rethrows when `runTurn` fails before any durable run exists. That leaves the projection runner polling for a run that will never appear; stop or settle the runner on this early failure path.
  - confidence: 0.78
- **[P3] Exclude arrays from worker payload objects:** `src/acp/store/gateway-events.ts:50-52`
  - body: This `isRecord` helper accepts arrays, unlike the sibling runtime helper, so malformed ACP worker payload arrays proceed to field-level errors instead of failing the object-envelope contract. Add the `!Array.isArray(value)` guard here as well.
