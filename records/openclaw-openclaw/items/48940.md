Full review comments:

- **[P1] Move ACP runtime state into SQLite:** `src/acp/store/store.ts:112`
  - body: This PR persists gateway-owned ACP sessions, runs, events, leases, targets, checkpoints, and idempotency in `state/acp/gateway-node-runtime-store.json`. That is OpenClaw runtime state, so it needs to live in the shared/per-agent SQLite state model with a migration/doctor owner rather than adding a new JSON sidecar that backups and upgrades do not understand.
  - confidence: 0.96
- **[P1] Gate ACP node commands explicitly:** `src/gateway/node-command-policy.ts:56`
  - body: Adding all ACP session and turn commands to `SYSTEM_COMMANDS` makes macOS, Linux, and Windows nodes advertise them by default. These commands start, cancel, close, and status-check runtime work over the node trust boundary, so they need an ACP-specific capability/authorization policy instead of inheriting the broad system command default.
  - confidence: 0.92
- **[P1] Use a non-best-effort ACP event sender:** `src/node-host/invoke.ts:426`
  - body: `handleAcpInvokeCommand` awaits `sendNodeEvent`, but that helper catches and ignores `client.request("node.event")` failures. ACP worker events and terminals are the durable source of gateway replay state; if this request drops, the node can believe a turn settled while the gateway never records it, leaving recovery and replay inconsistent.
  - confidence: 0.94
- **[P1] Return the active projection instead of restarting it:** `src/auto-reply/reply/dispatch-acp-replay.ts:456`
  - body: When a target already has a projection runner, `ensureProjection` calls `existing.start()`, and `start()` launches `this.run()` again. A second ensure for the same target can therefore run a second polling/delivery loop against the same checkpoint and duplicate outbound effects.
  - confidence: 0.93
- **[P2] Stop the projection runner when turn start fails early:** `src/auto-reply/reply/dispatch-acp.ts:396`
  - body: The durable ACP path starts a projection runner with `waitForRunStart: true`, then rethrows `turnError` when no durable run exists. That path never stops the runner, so it can keep polling forever for a run that will never be created after an early `runTurn` failure.
  - confidence: 0.88
- **[P1] Await ACP reconnect reconciliation before worker frames:** `src/gateway/server/ws-connection/message-handler.ts:1024`
  - body: Node connect launches `handleNodeConnected` in the background. During that window, incoming `acp.worker.*` frames can still see the lease as `suspect` and be rejected before reconciliation reactivates it, which can strand an otherwise completed node turn in recovery.
  - confidence: 0.9
- **[P1] Reject cross-session run ID reuse:** `src/acp/store/store.ts:534`
  - body: `startRun` treats any existing `store.runs[runId]` as an idempotent hit without checking that the stored session and request match the current call. If two sessions reuse the same provider-derived request id, the second session aliases the first run and subsequent worker events can fail or corrupt delivery bookkeeping.
