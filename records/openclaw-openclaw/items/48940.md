Full review comments:

- **[P1] Store ACP runtime state in SQLite:** `src/acp/store/store.ts:112`
  - body: This adds durable runtime state under `state/acp/gateway-node-runtime-store.json`, including sessions, runs, events, leases, checkpoints, delivery targets, and idempotency. OpenClaw runtime state belongs in the shared or agent SQLite stores so upgrade, backup, doctor, and migration behavior has one owner; move this store to SQLite or get an explicit storage design approved before merge.
  - confidence: 0.95
- **[P1] Gate ACP node commands explicitly:** `src/gateway/node-command-policy.ts:56`
  - body: Adding `NODE_ACP_COMMANDS` to `SYSTEM_COMMANDS` grants session ensure/load, turn start/cancel, close, and status through the same desktop defaults as generic system commands. These commands control a remote ACP execution worker and need a narrow ACP-specific policy/capability/approval gate with tests, not inherited system-command authorization.
  - confidence: 0.92
- **[P1] Use a non-best-effort ACP event sender:** `src/node-host/invoke.ts:426`
  - body: The ACP command handler forwards worker events through `sendNodeEvent`, but that sender catches and ignores `client.request("node.event", ...)` failures. A dropped worker event or terminal can therefore look accepted to the node while the gateway never persists it, leaving replay and cancel state inconsistent; ACP worker events need a sender that returns transport failure to the command path.
  - confidence: 0.9
- **[P1] Return the active projection instead of restarting it:** `src/auto-reply/reply/dispatch-acp-replay.ts:456`
  - body: When a projection for the target is already active, `ensureProjection` calls `existing.start()`, and `start()` launches `run()` again. Re-entering the same runner can create parallel polling/delivery loops for one target, racing checkpoints and duplicating outward sends; return the existing settled promise or make `start()` idempotent.
  - confidence: 0.88
- **[P2] Stop the projection runner when turn start fails early:** `src/auto-reply/reply/dispatch-acp.ts:396`
  - body: If `acpManager.runTurn` fails before a durable run exists, this branch rethrows `turnError` while the `waitForRunStart` projection loop remains alive and keeps polling for a run that will never appear. Stop the runner before rethrowing so failed dispatches do not leak background loops.
  - confidence: 0.84
- **[P1] Await ACP reconnect reconciliation before worker frames:** `src/gateway/server/ws-connection/message-handler.ts:1024`
  - body: `handleNodeConnected` runs fire-and-forget during node connect, so an `acp.worker.event` or terminal can arrive before suspect-lease reconciliation completes and be rejected as missing an active lease. Gate worker frame handling on the reconciliation result, or otherwise queue/drop with an explicit retry path, so reconnects do not strand active runs.
