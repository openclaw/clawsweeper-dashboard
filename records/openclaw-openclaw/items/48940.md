## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.94

Full review comments:

- **[P1] Move durable ACP state into SQLite:** `src/acp/store/store.ts:111-113`
  - body: This new store persists ACP sessions, runs, events, leases, checkpoints, delivery targets, and idempotency to a JSON sidecar under the state directory. Repository policy requires OpenClaw-owned runtime state, queues, cursors, and checkpoints to use SQLite/shared state DB ownership, so this would land a second persistent state model without the expected migration and doctor semantics.
  - confidence: 0.96
- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke.ts:425-426`
  - body: The ACP command path passes worker events through the existing best-effort node.event helper, which catches and ignores request failures. `runWorkerTurn` then advances `deliveredSeq` and can settle locally even if the gateway never records the event or terminal, leaving the durable run stuck or inconsistent after transport failure.
  - confidence: 0.94
- **[P1] Return the active projection instead of restarting it:** `src/auto-reply/reply/dispatch-acp-replay.ts:455-456`
  - body: When a target already has an active runner, `ensureProjection` calls `existing.start()`, but `start()` launches `run()` every time. A second ensure for the same target can therefore create concurrent polling/delivery loops over one checkpoint and duplicate outbound effects.
  - confidence: 0.95
- **[P2] Stop the runner when turn creation fails:** `src/auto-reply/reply/dispatch-acp.ts:394-396`
  - body: If `runTurn` throws before a durable run exists, this branch rethrows `turnError` while the projection runner that was started with `waitForRunStart` keeps polling for a run that will never appear. Stop or settle the projection service on this error path.
  - confidence: 0.9
- **[P1] Await reconnect reconcile before worker events can arrive:** `src/gateway/server/ws-connection/message-handler.ts:1024-1034`
  - body: `handleNodeConnected` is launched fire-and-forget, leaving a reconnect window where incoming ACP worker events are processed while the lease is still `suspect`. The store rejects worker progress unless the lease is active, so a reconnecting node can lose its terminal/event before reconcile completes.
  - confidence: 0.92
- **[P1] Check session and request before reusing a run id:** `src/acp/store/store.ts:532-534`
  - body: `startRun` treats any existing `store.runs[runId]` as an idempotent hit without checking `sessionKey` or `requestId`. If two sessions collide on a request-derived run id, the second session aliases the first run and later worker events fail session/lease validation.
  - confidence: 0.95
