Full review comments:

- **[P1] Move ACP runtime state into SQLite:** `src/acp/store/store.ts:111-113`
  - body: This persists gateway-owned sessions, runs, events, leases, checkpoints, delivery targets, and idempotency in `state/acp/gateway-node-runtime-store.json`. Root policy makes OpenClaw-owned runtime state SQLite-only; a JSON sidecar bypasses the migration, doctor, backup, and runtime-store expectations this feature depends on after restart.
  - confidence: 0.94
- **[P1] Gate ACP node commands explicitly:** `src/gateway/node-command-policy.ts:56`
  - body: Adding `NODE_ACP_COMMANDS` to `SYSTEM_COMMANDS` puts `acp.session.ensure/load/close/status` and `acp.turn.start/cancel` into the default macOS/Linux/Windows node allowlists. That expands paired-node session control and execution authority by default; this needs an explicit ACP worker capability or opt-in policy gate before merge.
  - confidence: 0.9
- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke.ts:426`
  - body: The ACP handler awaits `sendNodeEvent`, but `sendNodeEvent` catches and ignores `client.request("node.event")` failures. A node can settle a turn locally while the gateway never persists the worker event or terminal, leaving durable runs stuck or replay-inconsistent.
  - confidence: 0.93
- **[P1] Do not restart active projection runners:** `src/auto-reply/reply/dispatch-acp-replay.ts:456`
  - body: When a target already has an active projection, `ensureProjection` calls `existing.start()`, and `start()` launches another `run()` loop. A second ensure for the same target can therefore create parallel polling/delivery loops that duplicate outbound replies and race checkpoint updates.
  - confidence: 0.91
- **[P2] Stop the projection runner on pre-run failures:** `src/auto-reply/reply/dispatch-acp.ts:395-396`
