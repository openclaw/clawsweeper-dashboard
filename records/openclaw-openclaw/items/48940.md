Full review comments:

- **[P1] Move ACP runtime state into SQLite:** `src/acp/store/store.ts:111-113`
  - body: The new gateway ACP store writes sessions, runs, events, leases, checkpoints, delivery targets, and idempotency to `acp/gateway-node-runtime-store.json`. That is durable OpenClaw runtime state, and the repository policy requires these stores to use SQLite with migration/doctor ownership, not a steady-state JSON sidecar.
  - confidence: 0.9
- **[P1] Gate ACP node commands explicitly:** `src/gateway/node-command-policy.ts:54-58`
  - body: Adding all ACP worker commands to the desktop system command defaults lets any paired desktop node advertise and receive ACP session/start/cancel/close control without an ACP-specific authorization or explicit opt-in policy. This expands the gateway/node trust boundary and should be gated or documented as an intentional product/security decision before merge.
  - confidence: 0.86
- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke.ts:424-427`
  - body: ACP turn processing now sends worker events through `sendNodeEvent`, but that helper catches and ignores failed `node.event` requests. A node can finish locally while the gateway never records the event or terminal, leaving the durable run stuck or replay semantics wrong; ACP needs a non-best-effort sender or an explicit terminal-delivery failure path.
  - confidence: 0.87
- **[P1] Do not restart active projection runners:** `src/auto-reply/reply/dispatch-acp-replay.ts:454-456`
  - body: When a target already has an active projection runner, `ensureProjection` calls `existing.start()`, and `start()` launches another `run()` loop. A second ensure for the same target can therefore duplicate outbound sends and race checkpoint updates instead of deduplicating the in-flight projection.
  - confidence: 0.84
- **[P1] Stop early-failed projection runners:** `src/auto-reply/reply/dispatch-acp.ts:394-397`
  - body: The durable ACP path starts a projection runner before `runTurn`; if `runTurn` fails before creating a durable run, the catch branch rethrows without stopping that runner. The runner then polls forever for a run that will never exist, leaking background work for each early dispatch failure.
  - confidence: 0.82
- **[P1] Await reconnect reconciliation before worker frames:** `src/gateway/server/ws-connection/message-handler.ts:1024-1038`
  - body: Node reconnect reconciliation is launched fire-and-forget, so worker events can be processed while the store still treats the lease as suspect. In that window valid completion traffic can be rejected and the run can remain stuck in recovery even though the node completed it.
