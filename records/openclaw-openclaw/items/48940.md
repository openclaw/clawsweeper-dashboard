## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Surface ACP worker event send failures:** `src/node-host/invoke.ts:426`
  - body: `handleAcpInvokeCommand` gets a sender that delegates to `sendNodeEvent`, but that helper catches and ignores `client.request("node.event")` failures. For ACP worker events and terminals, a failed gateway RPC must put the worker/session into an explicit error path; otherwise the node can settle locally while the gateway never records the terminal.
  - confidence: 0.92
- **[P1] Reject run collisions across sessions:** `src/acp/store/store.ts:533-534`
  - body: `startRun` returns any existing `store.runs[runId]` as idempotent without checking that it belongs to the same `sessionKey` and `requestId`. Because the caller derives run IDs from message IDs, two sessions can alias onto the first run and corrupt later lease, event, and delivery bookkeeping.
  - confidence: 0.9
- **[P1] Reuse the active projection promise:** `src/auto-reply/reply/dispatch-acp-replay.ts:456`
  - body: When a target is already active, `ensureProjection` calls `existing.start()`, and `start()` launches `run()` again on the same runner. A second ensure for the same target can therefore create a competing polling/delivery loop that races checkpoint updates and can duplicate outward sends.
  - confidence: 0.88
- **[P1] Stop the wait-for-start projection on early turn failure:** `src/auto-reply/reply/dispatch-acp.ts:375-381`
  - body: The durable path starts a `waitForRunStart` projection in `Promise.all`, but if `runTurn` rejects before creating a durable run, the code rethrows without stopping the projection runner. That runner keeps polling for a run that will never appear, leaking background work for every early ACP dispatch failure.
  - confidence: 0.84
- **[P2] Store ACP durability in the canonical state DB:** `src/acp/store/store.ts:111-112`
  - body: The PR introduces `state/acp/gateway-node-runtime-store.json` for OpenClaw-owned runtime state. Repository policy requires runtime state, caches, queues, registries, cursors, and checkpoints to use SQLite unless an explicit product artifact exception applies, so this should move to the shared state DB or get an owner-approved migration design before merge.
  - confidence: 0.9
- **[P1] Gate worker events behind reconnect reconcile:** `src/gateway/server/ws-connection/message-handler.ts:1024-1038`
  - body: Node connect starts `handleNodeConnected` fire-and-forget, so a reconnecting node can send `acp.worker.event` or `acp.worker.terminal` while the lease is still suspect and before status reconcile has reactivated it. That race rejects valid progress and can strand the run in recovery even though the worker completed.
  - confidence: 0.8
