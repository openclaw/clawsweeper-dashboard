Full review comments:

- **[P1] Move ACP durable state into SQLite:** `src/acp/store/store.ts:111-112`
  - body: This PR writes sessions, runs, events, leases, checkpoints, delivery targets, and idempotency into `state/acp/gateway-node-runtime-store.json`. Root policy requires OpenClaw-owned runtime state to live in SQLite-backed stores, with legacy file stores handled by doctor/migration code, so merging this creates a new unsupported state surface with upgrade and recovery risk.
  - confidence: 0.95
- **[P1] Surface ACP node event delivery failures:** `src/node-host/invoke.ts:426`
  - body: `handleInvoke` passes ACP worker events through `sendNodeEvent`, but that helper catches and ignores `client.request("node.event", ...)` failures. `runWorkerTurn` therefore advances sequence/terminal handling as if the gateway durably accepted events that may have been dropped, which can leave the gateway store stuck in recovery while the node thinks the run completed.
  - confidence: 0.93
- **[P1] Reuse the active projection runner instead of restarting it:** `src/auto-reply/reply/dispatch-acp-replay.ts:456`
  - body: When a target is already active, `ensureProjection` calls `existing.start()`, and `start()` always launches another `run()` loop. Re-entering projection for the same target can create duplicate polling/delivery loops racing on the same checkpoint and outward replies.
  - confidence: 0.92
- **[P2] Stop the projection runner when turn start never creates a run:** `src/auto-reply/reply/dispatch-acp.ts:395-396`
  - body: The durable ACP path starts a `waitForRunStart` projection runner before `runTurn`; if `runTurn` fails before any durable run exists, this branch rethrows `turnError` without stopping the runner. The runner then keeps polling for a run that will never appear, leaking background work after failed dispatches.
