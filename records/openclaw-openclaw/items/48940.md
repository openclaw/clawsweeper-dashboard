## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Move ACP durable state into SQLite:** `src/acp/store/store.ts:112`
  - body: This adds `gateway-node-runtime-store.json` for persistent ACP sessions, runs, events, leases, checkpoints, delivery targets, and idempotency. OpenClaw-owned runtime state is supposed to live in SQLite, and current ACP metadata already uses the shared SQLite state DB, so this sidecar would create upgrade/doctor/runtime drift before users ever exercise the new backend.
  - confidence: 0.93
- **[P1] Reject cross-session run-id reuse:** `src/acp/store/store.ts:533-534`
  - body: `startRun` returns any existing `store.runs[runId]` without verifying that it belongs to the same `sessionKey` and `requestId`. If two sessions produce the same run id, the second session aliases the first durable run and later worker events fail or corrupt delivery bookkeeping; require the existing run to match the session/request or namespace run ids by session.
  - confidence: 0.92
- **[P1] Return the active projection instead of starting it again:** `src/auto-reply/reply/dispatch-acp-replay.ts:455-456`
  - body: When a projection already exists, `ensureProjection` calls `existing.start()`, but `start()` launches `this.run()` again before returning the same settled promise. A second ensure for the same target can therefore run another polling/delivery loop and race or duplicate outbound sends; return the existing settled promise or make `start()` idempotent.
  - confidence: 0.91
- **[P1] Use reliable transport for ACP worker events:** `src/node-host/invoke.ts:424-427`
  - body: The new ACP path passes worker events through the existing best-effort `sendNodeEvent` wrapper, which catches failed `client.request("node.event")` calls. For durable ACP, a swallowed terminal or event send means the node can think the gateway accepted progress while the store never recorded it; use a non-best-effort sender for ACP or make failures visible to the worker state machine.
  - confidence: 0.9
- **[P1] Await ACP reconnect reconcile before accepting worker events:** `src/gateway/server/ws-connection/message-handler.ts:1024-1038`
  - body: `handleNodeConnected` is launched fire-and-forget, so a reconnecting node can send `acp.worker.event` or `acp.worker.terminal` while the gateway still has its lease marked suspect. That can reject real worker progress and leave the run stuck in recovery; gate ACP worker ingress on completed reconcile or queue events until the lease state is authoritative.
  - confidence: 0.86
- **[P2] Stop the pending projection when turn creation fails:** `src/auto-reply/reply/dispatch-acp.ts:394-396`
  - body: If `acpManager.runTurn` fails before a durable run exists, the projection runner started with `waitForRunStart: true` keeps polling for a run that will never appear, and the branch rethrows without stopping it. Stop the runner or delay starting projection until the run record exists on this early-failure path.
  - confidence: 0.82
