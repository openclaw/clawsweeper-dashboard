## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Store ACP runtime state in SQLite:** `src/acp/store/store.ts:112`
  - body: This creates the durable ACP store at `state/acp/gateway-node-runtime-store.json` and writes sessions, runs, events, checkpoints, leases, and idempotency with `writeJsonAtomic`. OpenClaw-owned runtime state is required to live in SQLite/shared state DB or an approved SQLite schema, so merging this sidecar would create an unversioned data model outside migrations and doctor repair.
  - confidence: 0.92
- **[P1] Check ownership before reusing runs:** `src/acp/store/store.ts:533-534`
  - body: `startRun` treats any existing `store.runs[runId]` as an idempotent hit without checking that it belongs to the same session and request. Since `resolveAcpRequestId` can use channel/provider message IDs, two sessions can collide on a run id, alias to the wrong durable run, and then reject or corrupt later worker delivery for the second session.
  - confidence: 0.9
- **[P1] Propagate ACP node-event failures:** `src/node-host/invoke.ts:426`
  - body: The ACP worker bridge awaits `sendNodeEvent`, but that helper still catches and ignores `client.request("node.event")` failures. A dropped `acp.worker.event` or `acp.worker.terminal` is therefore reported as accepted to the worker while the gateway store never records it, leaving durable recovery and outward replay with missing terminal state.
  - confidence: 0.88
- **[P1] Do not restart active projection runners:** `src/auto-reply/reply/dispatch-acp-replay.ts:456`
  - body: When a projection for the same target is already active, this calls `existing.start()`, and `start()` unconditionally launches another `run()` loop on the same runner. Repeated recovery/dispatch calls for one target can therefore race checkpoint updates and duplicate outward sends instead of deduplicating to the existing settled promise.
  - confidence: 0.87
- **[P1] Await ACP reconnect reconciliation before events:** `src/gateway/server/ws-connection/message-handler.ts:1024`
  - body: Node reconnect reconciliation is fired in the background, so the socket can begin handling `acp.worker.event` or `acp.worker.terminal` before the suspect lease is reactivated. In that window `validateActiveLeaseBinding` rejects progress, and the node-host path does not replay those dropped events, so an otherwise healthy reconnect can wedge the run in recovery.
  - confidence: 0.84
- **[P2] Stop polling when turn start fails early:** `src/auto-reply/reply/dispatch-acp.ts:396`
  - body: The durable path starts a projection runner with `waitForRunStart: true`; if `runTurn` fails before creating a durable run, this branch throws the turn error without stopping that runner. The runner then keeps polling for a run that will never exist, leaking a background loop for each early dispatch failure.
  - confidence: 0.82
