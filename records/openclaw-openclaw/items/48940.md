Full review comments:

- **[P1] Store ACP runtime state in SQLite:** `src/acp/store/store.ts:111-112`
  - body: This adds durable OpenClaw runtime state as `state/acp/gateway-node-runtime-store.json`. Repository policy requires runtime state, queues, checkpoints, and indexes to use SQLite-owned storage, so this needs to move into an approved SQLite owner with upgrade/doctor proof before merge.
  - confidence: 0.95
- **[P1] Gate ACP node commands explicitly:** `src/gateway/node-command-policy.ts:56`
  - body: Adding `NODE_ACP_COMMANDS` to `SYSTEM_COMMANDS` makes ACP session and turn control part of the default desktop node command surface once declared. That expands the gateway/node trust boundary; ACP worker control should be separately authorized or explicitly opted in.
  - confidence: 0.92
- **[P1] Propagate ACP worker event delivery failures:** `src/node-host/invoke-acp.ts:865`
  - body: The ACP worker bridge awaits `sendNodeEvent`, but the provided sender catches and ignores `node.event` request failures. A worker can therefore settle locally while the gateway never records the event or terminal, leaving runs stuck in recovery or missing delivery.
  - confidence: 0.94
- **[P1] Return the active projection promise:** `src/auto-reply/reply/dispatch-acp-replay.ts:455-456`
  - body: When a projection already exists, `ensureProjection` calls `existing.start()`, and `start()` launches another `run()` loop. A second ensure for the same target can duplicate outbound sends and race checkpoint writes instead of joining the active runner.
  - confidence: 0.93
- **[P1] Stop the projection runner on early turn-start failure:** `src/auto-reply/reply/dispatch-acp.ts:394-396`
  - body: If `runTurn` fails before the durable run exists, this branch rethrows after starting a projection with `waitForRunStart: true`. The runner is never stopped, so it can keep polling forever for a run that will never appear.
  - confidence: 0.9
- **[P1] Await ACP reconnect reconciliation before worker frames:** `src/gateway/server/ws-connection/message-handler.ts:1024-1034`
  - body: `handleNodeConnected` runs fire-and-forget during node registration, so incoming ACP worker frames can be processed before suspect lease reconciliation completes. In that window the store can reject progress and strand an otherwise completed run in recovery.
  - confidence: 0.88
- **[P1] Reject cross-session run ID reuse:** `src/acp/store/store.ts:532-534`
  - body: `startRun` returns any existing `store.runs[runId]` without confirming the same session and request. If two sessions produce the same run id, the second session aliases the first run and later worker events can fail validation or corrupt delivery bookkeeping.
  - confidence: 0.93
