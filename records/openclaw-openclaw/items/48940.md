## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Move ACP durable state into SQLite:** `src/acp/store/store.ts:111-113`
  - body: This PR persists ACP sessions, runs, accepted events, leases, checkpoints, delivery targets, and idempotency to `state/acp/gateway-node-runtime-store.json`. OpenClaw runtime state and checkpoints belong in SQLite with an owned migration/doctor path; a new JSON sidecar can strand durable ACP state across upgrades and bypass the repository's storage contract.
  - confidence: 0.95
- **[P1] Use a reliable ACP worker event sender:** `src/node-host/invoke.ts:424-427`
  - body: The ACP command handler passes the existing `sendNodeEvent` helper into `handleAcpInvokeCommand`, but that helper intentionally swallows `node.event` request failures. ACP worker events and terminals are durable protocol handoffs, so treating a failed gateway RPC as success can settle the node locally while the gateway never records the terminal.
  - confidence: 0.92
- **[P1] Validate existing runs before idempotent reuse:** `src/acp/store/store.ts:532-535`
  - body: `startRun` returns any existing record for the same `runId` before checking that it belongs to the same `sessionKey` and `requestId`. A cross-session run id collision would alias the second session onto the first run, after which lease/session validation and delivery bookkeeping no longer describe the requested turn.
  - confidence: 0.9
- **[P1] Return existing projections without restarting them:** `src/auto-reply/reply/dispatch-acp-replay.ts:454-456`
  - body: When a target already has an active projection runner, `ensureProjection` calls `existing.start()`, and `start()` always launches another `run()` loop. A duplicate ensure for the same target can therefore create competing projection loops that duplicate outbound delivery and race checkpoint updates.
  - confidence: 0.91
- **[P1] Serialize reconnect reconcile before ACP events:** `src/gateway/server/ws-connection/message-handler.ts:1024-1038`
  - body: The node handshake fires `handleNodeConnected` in the background, so worker events can arrive while the store still marks the lease suspect and rejects progress as `ACP_NODE_ACTIVE_LEASE_MISSING`. A reconnecting node that completes a turn in that window can leave the gateway run stuck in recovery despite valid worker output.
  - confidence: 0.87
- **[P2] Stop pending projections when turn creation fails:** `src/auto-reply/reply/dispatch-acp.ts:372-397`
  - body: The durable dispatch path starts a projection with `waitForRunStart: true` in parallel with `runTurn`, but if `runTurn` fails before a durable run is created the code rethrows without stopping the runner. That leaves a background projection polling for a run that will never appear for each early turn-start failure.
  - confidence: 0.82
