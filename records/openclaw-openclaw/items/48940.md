Keep open: current main still has no ACP node-backed runtime, so the PR is not obsolete, but this head is not merge-ready. The safer path is a smaller maintainer-reviewed slice with SQLite durability and real paired-node validation.

Full review comments:

- **[P1] Move durable ACP state into SQLite:** `src/acp/store/store.ts:112`
  - body: This adds persistent OpenClaw-owned runtime state under `state/acp/gateway-node-runtime-store.json`. The repository policy requires runtime state, caches, checkpoints, and registries to live in SQLite-backed stores, so this should move to the shared/agent/dedicated SQLite owner before merge instead of adding a steady-state JSON sidecar.
  - confidence: 0.96
- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke.ts:425-427`
  - body: The ACP bridge passes terminal and worker events through `sendNodeEvent`, but that helper swallows `node.event` request failures. A node can therefore complete locally while the gateway never durably records the terminal, leaving the run stuck in recovery and replay/cancel state inconsistent.
  - confidence: 0.95
- **[P1] Do not restart active projection runners:** `src/auto-reply/reply/dispatch-acp-replay.ts:456`
  - body: When a target already has an active runner, `ensureProjection` calls `existing.start()`, and `start()` launches another `run()` loop. Re-entering this path can create duplicate polling/delivery loops for the same target and race checkpoint updates or outbound sends.
