## Review Findings

Full review comments:

- **[P1] Move ACP state into the shared SQLite store:** `src/acp/store/store.ts:112`
  - body: This adds durable ACP sessions, runs, events, leases, checkpoints, delivery targets, and idempotency under `state/acp/gateway-node-runtime-store.json`. OpenClaw runtime state is database-first and should live in the shared state DB with schema/migration/doctor coverage, otherwise upgrades and recovery have a second unmigrated source of truth.
  - confidence: 0.92
- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke.ts:426`
  - body: The ACP node worker awaits `sendNodeEvent`, but the helper catches and ignores `client.request("node.event", ...)` failures. A dropped terminal can therefore be treated as successful locally and call `settleCompletedTurn`, while the gateway never records the canonical terminal and leaves the run recovering.
  - confidence: 0.91
- **[P1] Return the active projection instead of restarting it:** `src/auto-reply/reply/dispatch-acp-replay.ts:456`
  - body: When a projection already exists for the target, this calls `existing.start()`, and `start()` launches `run()` again every time. A second `ensureProjection` for the same target can start another polling/delivery loop, racing checkpoint writes and duplicating outward sends.
  - confidence: 0.89
- **[P2] Stop the projection runner when startup fails early:** `src/auto-reply/reply/dispatch-acp.ts:396`
  - body: The durable path starts a projection with `waitForRunStart: true`; if `runTurn` throws before a durable run exists, this branch rethrows without stopping the runner. The runner then keeps polling for a run that will never appear, leaking background work for every early start failure.
  - confidence: 0.86
- **[P1] Reject run-id collisions across sessions:** `src/acp/store/store.ts:534`
  - body: `startRun` returns any existing `store.runs[runId]` without checking that the run belongs to the same `sessionKey` and `requestId`. If two sessions produce the same run id, the second session aliases the first run and later worker events fail session/lease validation or corrupt delivery bookkeeping.
  - confidence: 0.9
- **[P1] Await reconnect reconciliation before worker traffic:** `src/gateway/server/ws-connection/message-handler.ts:1024`
  - body: `handleNodeConnected` is launched fire-and-forget, so ACP worker events can arrive while the lease is still `suspect`. The store rejects worker progress in that state, and the node-host path does not emit a heartbeat to recover the dropped terminal/event, leaving the run stuck in recovery after a reconnect.
  - confidence: 0.84

## Risks / Open Questions

- Merging this as-is would create a new JSON sidecar for persistent ACP runtime state instead of using the shared SQLite state DB and migration/doctor path.
- Dropped node.event RPCs can be treated as successful ACP worker event or terminal delivery, leaving gateway state stuck while the node considers the run complete.
- Repeated projection starts for the same target can create competing delivery loops and duplicate outward messages or race checkpoint writes.
- Reconnect handling can accept ACP worker traffic before same-node suspect-lease reconcile finishes, causing valid terminal or event payloads to be rejected and the run to remain recovering.
