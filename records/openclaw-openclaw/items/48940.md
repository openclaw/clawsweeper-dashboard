## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.94

Full review comments:

- **[P1] Move ACP runtime state into SQLite:** `src/acp/store/store.ts:111-113`
  - body: The new durable ACP store writes runtime sessions, runs, events, leases, and checkpoints to `gateway-node-runtime-store.json`. OpenClaw-owned runtime state belongs in the shared SQLite/migration/doctor path, so this sidecar would create unowned upgrade, backup, and recovery behavior.
  - confidence: 0.96
- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke.ts:425-426`
  - body: ACP terminal/event delivery depends on `sendNodeEvent` throwing when the gateway RPC fails, but the provided sender uses the existing best-effort helper that swallows `node.event` errors. A node can settle locally while the gateway never records the terminal, leaving recovery and replay state stuck.
  - confidence: 0.94
- **[P1] Do not restart active projection runners:** `src/auto-reply/reply/dispatch-acp-replay.ts:455-456`
  - body: `ensureProjection` calls `existing.start()` for an already-active target, and `start()` always launches another `run()` loop. A second ensure for the same target can duplicate outbound delivery and race checkpoint updates.
  - confidence: 0.95
- **[P1] Stop the projection runner on pre-run failures:** `src/auto-reply/reply/dispatch-acp.ts:394-396`
  - body: When `runTurn` fails before a durable run exists, this branch throws while the wait-for-run-start projection loop remains active and polling forever. Stop or settle that runner before rethrowing the early failure.
  - confidence: 0.91
- **[P1] Await ACP reconnect reconciliation before worker frames:** `src/gateway/server/ws-connection/message-handler.ts:1024-1034`
  - body: Reconnect reconciliation is launched fire-and-forget after node registration, so incoming ACP worker frames can be processed while the lease is still suspect and be rejected. Await or gate worker event handling until lease reconciliation finishes.
  - confidence: 0.92
- **[P1] Reject cross-session run id reuse:** `src/acp/store/store.ts:532-535`
  - body: `startRun` returns any existing global `runId` without confirming the same session and request. A run-id collision across sessions aliases durable state and can corrupt or strand delivery bookkeeping.
  - confidence: 0.95
- **[P1] Gate ACP node commands explicitly:** `src/gateway/node-command-policy.ts:54-57`
  - body: Adding ACP start/cancel/close/session commands to desktop default system commands expands paired-node execution authority by default. This needs an explicit trust-boundary and authorization policy instead of silently joining the broad system command set.
  - confidence: 0.9
- **[P3] Reject array ACP envelopes at the object check:** `src/acp/store/gateway-events.ts:50-52`
  - body: The gateway ACP envelope guard accepts arrays as records, unlike the sibling ACP node runtime guard. Reject arrays at the object check so malformed worker payloads fail at the right boundary with consistent errors.
  - confidence: 0.86

## Security Review

  - body: ACP session/load/start/cancel/close/status commands are added to the desktop system command default set, changing what a paired node can execute without a clearly reviewed authorization boundary.
