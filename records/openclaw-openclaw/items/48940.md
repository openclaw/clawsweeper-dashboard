## Review Findings

Full review comments:

- **[P1] Move durable ACP state out of JSON sidecar storage:** `src/acp/store/store.ts:111-112`
  - body: This adds `state/acp/gateway-node-runtime-store.json` for sessions, runs, events, leases, checkpoints, delivery targets, and idempotency. OpenClaw-owned runtime state under state dirs is required to use SQLite/shared state DB or an explicitly designed DB schema, so this creates upgrade and recovery debt for the durability path.
  - confidence: 0.93
- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke.ts:426`
  - body: The ACP invoke path reports worker events through `sendNodeEvent`, but that helper catches and ignores failed `node.event` requests. A node can therefore finish a run locally while the gateway never records the event or terminal, leaving durable recovery and replay state inconsistent.
  - confidence: 0.9
- **[P1] Do not restart an active projection runner:** `src/auto-reply/reply/dispatch-acp-replay.ts:456`
  - body: When a target already has an active projection runner, `ensureProjection` calls `existing.start()`, and `start()` always launches another polling loop. A repeated ensure for the same target can race checkpoints and duplicate outward delivery instead of deduplicating work.
  - confidence: 0.91
- **[P2] Stop the runner when turn start never creates a run:** `src/auto-reply/reply/dispatch-acp.ts:395-396`
  - body: The durable dispatch path starts a projection runner with `waitForRunStart`, then rethrows `turnError` when no durable run exists. That branch never stops the runner, so the background loop keeps polling for a run that will never appear after each early `runTurn` failure.
  - confidence: 0.88
- **[P1] Await ACP reconnect reconcile before worker traffic:** `src/gateway/server/ws-connection/message-handler.ts:1024`
  - body: Node connect launches `handleNodeConnected` as fire-and-forget while the same connection can immediately send ACP worker events. During that window the store can still treat the lease as suspect and reject progress, stranding a run even though the node completed it.
  - confidence: 0.86
- **[P1] Validate run idempotency by session and request:** `src/acp/store/store.ts:532-534`
  - body: `startRun` returns any existing `store.runs[runId]` before checking that it belongs to the same session and request. If two sessions reuse a provider/request-derived run id, the second aliases the first run record and later worker traffic fails session/lease validation.
  - confidence: 0.9
