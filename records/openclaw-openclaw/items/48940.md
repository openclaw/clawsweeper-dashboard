## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Store ACP runtime state in SQLite:** `src/acp/store/store.ts:111-112`
  - body: This store writes durable sessions, runs, events, leases, delivery targets, checkpoints, and idempotency to `state/acp/gateway-node-runtime-store.json`. OpenClaw runtime state now belongs in SQLite, and current ACP metadata/replay state already follows that direction, so this sidecar would bypass shared backup, doctor, migration, and transaction boundaries.
  - confidence: 0.95
- **[P1] Reject cross-session run ID reuse:** `src/acp/store/store.ts:532-535`
  - body: `startRun` returns any existing run keyed by raw `runId` without checking `sessionKey` or `requestId`. If two ACP sessions reuse a provider/request id, the second session aliases the first run and later worker events fail the lease/session checks, leaving delivery and recovery state corrupt.
  - confidence: 0.93
- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke.ts:424-427`
  - body: The ACP command handler sends worker events and terminals through the shared `sendNodeEvent` helper, which catches and ignores `client.request("node.event", ...)` failures. A node can finish a run locally while the gateway never persists the terminal, leaving the run stuck in recovery and replay/cancel state inconsistent.
  - confidence: 0.9
- **[P1] Return the active projection instead of starting another loop:** `src/auto-reply/reply/dispatch-acp-replay.ts:454-457`
  - body: When a projection already exists for a target, `ensureProjection` calls `existing.start()`, and `start()` launches `run()` again. Retrying the same target can therefore create multiple projector loops over the same checkpoint, duplicating outbound sends or racing checkpoint updates instead of joining the active projection.
  - confidence: 0.92
- **[P1] Await ACP reconnect reconciliation before worker frames:** `src/gateway/server/ws-connection/message-handler.ts:1024-1038`
  - body: Node connect reconciliation is launched fire-and-forget, so the same websocket can deliver ACP worker frames before a suspect lease is reactivated. Those frames are rejected as missing an active lease, and the node worker path does not guarantee replay of the dropped terminal/event, so a completed reconnecting run can strand in recovery.
  - confidence: 0.88
- **[P1] Do not default-allow ACP node runtime commands:** `src/gateway/node-command-policy.ts:54-58`
  - body: Adding ACP commands to `SYSTEM_COMMANDS` makes them default-allowed for macOS, Linux, and Windows nodes whenever a node declares them. This expands the gateway-to-node session and turn control surface without an ACP-specific opt-in or policy decision.
  - confidence: 0.87
