Full review comments:

- **[P1] Store ACP runtime state in SQLite:** `src/acp/store/store.ts:111-112`
  - body: This adds durable sessions, runs, events, leases, checkpoints, delivery targets, and idempotency as `gateway-node-runtime-store.json`. OpenClaw-owned runtime state belongs in SQLite, so this would create backup, migration, doctor, and recovery drift for real users.
  - confidence: 0.95
- **[P1] Gate ACP node commands explicitly:** `src/gateway/node-command-policy.ts:54-57`
  - body: Adding all ACP session and turn commands to `SYSTEM_COMMANDS` makes them default desktop/system node capabilities once advertised. These commands can start, cancel, close, and inspect ACP work on paired nodes, so they need an ACP-specific authorization or opt-in policy instead of inheriting broad system-command defaults.
  - confidence: 0.9
- **[P1] Use a non-best-effort ACP event sender:** `src/node-host/invoke.ts:425-426`
  - body: The ACP worker path depends on `node.event` to persist events and terminals on the gateway, but this call goes through the shared best-effort sender that swallows request failures. A node can finish locally while the gateway never records the terminal, leaving the durable run stuck in recovery and making replay/cancel state inconsistent.
  - confidence: 0.95
- **[P1] Return the active projection instead of restarting it:** `src/auto-reply/reply/dispatch-acp-replay.ts:454-456`
  - body: When a target is already active, `ensureProjection` calls `existing.start()`, but `start()` launches `run()` again. A second ensure for the same target can create concurrent polling/delivery loops that race checkpoints and duplicate outbound sends.
  - confidence: 0.93
- **[P1] Stop the projection runner when turn start fails early:** `src/auto-reply/reply/dispatch-acp.ts:395-396`
  - body: If `runTurn()` throws before creating a durable run, the projection runner started with `waitForRunStart: true` is left polling for a run that will never appear. Stop or avoid starting the runner on this branch so failed dispatches do not leak background loops.
  - confidence: 0.88
- **[P1] Await ACP reconnect reconciliation before worker frames:** `src/gateway/server/ws-connection/message-handler.ts:1024-1034`
  - body: Reconnect reconciliation is launched fire-and-forget, so a reconnecting node can send worker events before the suspect lease is reactivated. Those events are rejected as missing an active lease, which can strand a completed run in recovery even though the node is healthy.
  - confidence: 0.86
- **[P1] Reject cross-session run ID reuse:** `src/acp/store/store.ts:532-535`
  - body: `startRun` returns any existing `store.runs[runId]` without checking the session or request. If two sessions produce the same run id, the second session aliases the first run record and later worker events fail validation or corrupt delivery bookkeeping.
  - confidence: 0.92
- **[P3] Reject array ACP envelopes at the object check:** `src/acp/store/gateway-events.ts:50-51`
  - body: This helper accepts arrays as records, so malformed top-level ACP payload arrays fall through to field-level errors instead of the intended object-envelope rejection. Match the sibling helper and exclude arrays here.
  - confidence: 0.82
- **[P3] Remove the unreachable handled branch:** `src/gateway/server-node-events.ts:268-270`
  - body: After throwing when `handled` is false, execution can only reach this branch when `handled` is true. Replace the conditional with a plain `return` to remove the dead check from a hot event path.
  - confidence: 0.9
