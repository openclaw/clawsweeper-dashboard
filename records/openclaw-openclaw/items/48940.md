Full review comments:

- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke.ts:426`
  - body: This wires ACP worker delivery through `sendNodeEvent`, but that helper catches and ignores `node.event` request failures. If a worker event or terminal frame is dropped, the node can continue as if the gateway accepted it, leaving the durable run stuck or inconsistent instead of surfacing an explicit handoff failure.
  - confidence: 0.94
- **[P1] Move ACP runtime state into SQLite:** `src/acp/store/store.ts:112`
  - body: The new store persists gateway-owned sessions, runs, events, leases, checkpoints, delivery targets, and idempotency in a JSON sidecar under the state directory. Runtime state of this shape needs the shared SQLite migration/doctor path so upgrades, backups, corruption handling, and concurrent access use the repository's canonical state model.
  - confidence: 0.96
- **[P1] Gate ACP node commands explicitly:** `src/gateway/node-command-policy.ts:57`
  - body: Adding all ACP commands to `SYSTEM_COMMANDS` makes them desktop defaults alongside existing system commands. These commands start/cancel/close node-hosted ACP work and expand the paired-node trust boundary, so they need an ACP-specific authorization policy instead of becoming default allowed commands.
  - confidence: 0.9
- **[P1] Do not restart active projection runners:** `src/auto-reply/reply/dispatch-acp-replay.ts:456`
  - body: When a target is already active, `ensureProjection` calls `existing.start()`, and `start()` launches `run()` again. A repeated ensure for the same target can therefore create multiple polling/delivery loops that race checkpoints or duplicate outbound sends.
  - confidence: 0.91
- **[P2] Stop the projection runner on pre-run failures:** `src/auto-reply/reply/dispatch-acp.ts:396`
  - body: The durable path starts a projection runner with `waitForRunStart` before `runTurn` creates the durable run. If `runTurn` fails before the run exists, this branch rethrows without stopping the runner, so it can keep polling forever for a run that will never appear.
  - confidence: 0.86
- **[P1] Await reconnect reconciliation before worker frames:** `src/gateway/server/ws-connection/message-handler.ts:1024`
  - body: Node reconnect starts ACP lease reconciliation as fire-and-forget work. Worker events can arrive before the suspect lease is reactivated, causing valid same-node progress to be rejected as missing an active lease and leaving the run in recovery.
  - confidence: 0.9
- **[P1] Reject cross-session run id reuse:** `src/acp/store/store.ts:533-534`
  - body: `startRun` returns an existing run by `runId` alone. If another session reuses the same provider/request-derived id, the second session aliases the first run and later worker events fail session/lease validation or corrupt delivery bookkeeping.
  - confidence: 0.93
- **[P3] Reject array ACP envelopes at the object check:** `src/acp/store/gateway-events.ts:51`
  - body: This `isRecord` helper accepts arrays, unlike the sibling ACP node runtime parser. Arrays are rejected later with field-level errors, but the gateway worker envelope boundary should reject non-object payloads at the envelope check for consistent validation.
  - confidence: 0.82
