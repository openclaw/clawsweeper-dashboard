Full review comments:

- **[P1] Move durable ACP state out of JSON sidecar storage:** `src/acp/store/store.ts:112`
  - body: This adds `state/acp/gateway-node-runtime-store.json` for sessions, runs, worker events, leases, checkpoints, delivery targets, and idempotency. OpenClaw-owned runtime state under state dirs belongs in SQLite/shared state DB or an explicitly designed DB schema, so this creates migration and recovery debt for the durability path.
  - confidence: 0.93
- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke.ts:426`
  - body: The new ACP invoke path sends worker events through `sendNodeEvent`, but that helper catches and ignores `client.request("node.event", ...)` failures. A node can therefore settle a turn locally while the gateway never records the event or terminal, leaving durable recovery and replay state inconsistent.
  - confidence: 0.9
- **[P1] Do not restart an active projection runner:** `src/auto-reply/reply/dispatch-acp-replay.ts:456`
  - body: When a target already has an active runner, `ensureProjection` calls `existing.start()`, and `start()` always launches another polling loop. A second ensure for the same target can race the first loop on the same checkpoint and duplicate outward delivery.
  - confidence: 0.91
- **[P2] Stop the runner when turn start never creates a run:** `src/auto-reply/reply/dispatch-acp.ts:396`
  - body: The durable dispatch path starts a projection runner with `waitForRunStart`, then rethrows `turnError` when no durable run exists. That branch never stops the runner, so it keeps polling for a run that will never appear after each early `runTurn` failure.
  - confidence: 0.88
- **[P1] Serialize reconnect reconcile before accepting worker traffic:** `src/gateway/server/ws-connection/message-handler.ts:1024`
