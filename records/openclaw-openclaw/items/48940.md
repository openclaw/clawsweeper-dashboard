- **[P1] Move durable ACP state into SQLite:** `src/acp/store/store.ts:111-113`
  - body: This adds durable ACP runtime sessions, runs, events, checkpoints, leases, idempotency, and delivery state as a JSON sidecar under the state dir. Root policy requires OpenClaw-owned runtime state and checkpoints to use SQLite/shared state storage, so merging this creates a parallel persistent store without an approved schema or doctor migration path.
  - confidence: 0.91
- **[P1] Propagate ACP worker event send failures:** `src/node-host/invoke.ts:665-673`
  - body: ACP worker events and terminals are sent through this helper, but errors from client.request("node.event") are swallowed. The node-host ACP code awaits this sender and can then mark turns as advanced or completed even when the gateway never accepted the event, leaving durable recovery state divergent.
  - confidence: 0.9
- **[P1] Reuse the active projection runner:** `src/auto-reply/reply/dispatch-acp-replay.ts:454-457`
  - body: ensureProjection calls existing.start() for an already active target, but start() always launches another run() loop. A duplicate projection loop can re-deliver outbound messages and race checkpoint updates instead of deduplicating the active target.
  - confidence: 0.88
- **[P2] Stop projections when turn start creates no run:** `src/auto-reply/reply/dispatch-acp.ts:394-397`
  - body: When acpManager.runTurn fails before a durable run record exists, this branch rethrows turnError without stopping the waitForRunStart projection runner. That runner keeps polling for a run that will never appear, leaking background work after each early dispatch failure.
  - confidence: 0.86
- **[P1] Serialize reconnect reconciliation before worker events:** `src/gateway/server/ws-connection/message-handler.ts:1024-1038`
  - body: handleNodeConnected is launched fire-and-forget during node session setup, so acp.worker events can be processed while the previous lease is still suspect. Store lease validation can reject that progress before reconciliation reactivates the lease, which can strand a completed node run in recovery.
  - confidence: 0.87
- **[P1] Validate run reuse by session and request:** `src/acp/store/store.ts:532-535`
  - body: startRun treats any existing runId as an idempotent hit without checking the sessionKey or requestId. If two sessions collide on a runId, the second session aliases the first run and subsequent worker events or delivery bookkeeping can fail validation against the wrong session.
  - confidence: 0.9
