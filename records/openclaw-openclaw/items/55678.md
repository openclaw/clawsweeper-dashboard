## Summary

Keep open: current main and v2026.6.11 still omit Qwen/DashScope from the provider-usage ID/resolver path, and the bundled Qwen plugin owns those aliases without provider-usage auth or snapshot hooks. The related Token Plan PR is useful but adjacent; its own discussion calls Alibaba usage accounting a separate follow-up.

## What This Changes

The issue requests DashScope/Qwen provider usage accounting so the UI does not show zero usage while Alibaba/Qwen tokens or credits are being consumed.

## Best Possible Solution

Add Qwen-owned usage auth and usage snapshot hooks, map Qwen/DashScope aliases into the provider-usage resolver, and cover the UI/status paths with focused tests plus redacted live endpoint proof.

## Reproduction Assessment

Yes, source-level: current main cannot resolve Qwen/DashScope IDs into usage providers, and the UI/status usage paths filter through that resolver before polling. I did not run a live DashScope credential scenario in this read-only review.

## Solution Assessment

No as proposed: adding only DashScope to usageProviders is not the best complete fix because provider-owned auth extraction and response normalization are also missing. The cleaner fix is Qwen plugin usage hooks plus alias resolver wiring and endpoint-contract proof.
