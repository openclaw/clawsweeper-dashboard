## Summary

Keep open: current main and the latest release still omit DashScope/Qwen from provider-usage resolution, and the Qwen plugin owns the aliases without usage auth or snapshot hooks. The linked Token Plan PR is adjacent and explicitly leaves Alibaba usage accounting as a separate follow-up.

## What This Changes

The issue requests DashScope/Qwen usage accounting because the UI shows zero usage while tokens are actually consumed.

## Best Possible Solution

Keep this as the canonical usage-accounting tracker until Qwen-owned usage auth and usage snapshot hooks land, DashScope/Qwen aliases map into the provider-usage resolver, and focused tests plus redacted live endpoint proof verify the UI result.

## Reproduction Assessment

Yes, at source level: `resolveUsageProviderId` cannot return a DashScope/Qwen usage provider, and the Qwen plugin currently has no usage-auth or usage-snapshot hooks. I did not run a live DashScope credential scenario in this read-only review.

## Solution Assessment

No, the proposed allowlist-only shape is not the best complete fix because it would make DashScope eligible for polling without provider-owned auth extraction or quota response normalization. The maintainable path is Qwen plugin usage hooks plus alias wiring and endpoint-contract proof.
