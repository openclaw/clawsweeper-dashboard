## Summary

Keep open: current main supports Anthropic API-key, setup-token, and Claude CLI auth paths, but it still does not expose the requested one-click Anthropic browser OAuth flow. This remains a provider-auth UX request that needs maintainer product and security direction before implementation.

## What This Changes

The issue requests a one-click Anthropic OAuth onboarding flow that opens a browser, detects account type, and configures Anthropic auth without manual token or API-key setup.

## Best Possible Solution

Add an explicit provider-owned Anthropic browser OAuth auth method only after maintainers approve scopes, callback behavior, token storage/refresh, billing/account detection, docs, and fallback behavior, while keeping existing API-key, setup-token, and Claude CLI paths explicit.
