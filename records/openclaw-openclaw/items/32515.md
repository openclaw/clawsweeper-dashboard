## Summary

Keep open: current main and v2026.6.11 still expose Anthropic CLI reuse, setup-token, and API-key setup paths, but not a one-click Anthropic browser OAuth onboarding choice wired through provider auth. The request remains a product/security decision because official Anthropic Claude Code guidance now treats Claude.ai OAuth credentials as native-app/subscription auth rather than a general third-party product auth surface.

## What This Changes

The issue requests replacing manual Anthropic API-key/setup-token/CLI auth setup with a browser OAuth flow that detects account type and configures OpenClaw automatically.

## Best Possible Solution

Decide the permitted Anthropic auth strategy first; if approved, implement a provider-owned OAuth auth method with explicit scopes, loopback/paste fallback, account/billing detection, docs, and security tests, otherwise keep improving the supported Claude CLI/setup-token/API-key paths.
