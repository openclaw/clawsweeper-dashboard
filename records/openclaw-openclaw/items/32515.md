## Summary

Keep open: current main still exposes Anthropic setup through Claude CLI, setup-token, and API-key choices, while the internal Anthropic OAuth helper is not registered as a one-click provider auth or onboarding method. The remaining work crosses security, billing/account detection, token storage, refresh, and first-run UX policy, so it needs maintainer direction rather than cleanup closure.

## What This Changes

Request one-click Anthropic browser OAuth during onboarding with automatic account or token-path detection instead of manual key/token setup.

## Best Possible Solution

Add an additive Anthropic provider-owned OAuth auth method only after security and product approval, keeping API-key, setup-token, and Claude CLI paths available until migration and fallback behavior are proven.
