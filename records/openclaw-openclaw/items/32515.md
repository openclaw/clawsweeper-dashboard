## Summary

Keep open: current main and v2026.6.11 still do not expose Anthropic browser OAuth as an onboarding or provider-auth choice; the existing OAuth helper and merged callback hardening are internal pieces, not the requested one-click auth flow.

## What This Changes

The issue requests one-click Anthropic browser OAuth in onboarding, with automatic account/token-type detection and no manual key, token, or env-file setup.

## Best Possible Solution

Add an additive Anthropic-provider-owned OAuth auth method only after maintainers approve the security, billing, docs, and fallback contract, while keeping API-key, setup-token, and Claude CLI routes explicit.
