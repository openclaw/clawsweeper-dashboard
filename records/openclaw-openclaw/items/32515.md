## Summary

Keep open: current main and v2026.6.11 still expose Anthropic Claude CLI, setup-token, and API-key choices, but not the requested one-click browser OAuth onboarding flow. The remaining work is a security-sensitive auth-provider product decision rather than a cleanup close.

## What This Changes

The issue asks OpenClaw to replace manual Anthropic credential setup with a browser-based one-click OAuth onboarding flow that can distinguish API-key and OAuth-style Anthropic tokens.

## Best Possible Solution

Add an explicit Anthropic plugin-owned browser OAuth auth method only after maintainers approve the consent, scope, billing, callback, token storage, refresh, docs, and fallback contract; keep API-key and Claude CLI choices explicit.

## Reproduction Assessment

Not applicable: this is a feature request for a new Anthropic authentication/onboarding flow, not a failing current behavior report. Source inspection shows the requested one-click onboarding choice is not registered in current main or v2026.6.11.

## Solution Assessment

No, not as a blanket replacement for every Anthropic auth setup path. The safer solution is an additive provider-owned OAuth option after security, consent, billing, storage, and upgrade behavior are approved.
