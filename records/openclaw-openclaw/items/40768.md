Keep open: current main and the latest release still recognize Feishu group @mentions by the receiving bot's app-scoped open_id, so the reported multi-bot mismatch can still suppress an explicitly mentioned bot. The same-author closing PR remains open, conflicting, and under human review, so the issue should stay open until that path lands or is replaced.

## What This Changes

This issue asks OpenClaw to recognize Feishu group @mentions correctly when multiple Feishu bot apps share a group and Feishu delivers app-scoped mention open_id values.

## Best Possible Solution

Land one current-main Feishu identity fix that proves a stable bot identity across text mentions, post mentions, command stripping, mention-forward, debounce batching, focused tests, and redacted live multi-bot proof, then close this issue.

## Reproduction Assessment

Yes, at source level: a Feishu event whose mention open_id differs from botOpenId makes checkBotMentioned return false, and the group requireMention gate can drop the message. I did not run a live multi-bot Feishu tenant.

No landed solution exists yet. The open linked PR is a plausible candidate, but the best fix needs a current-main rewrite around a proven stable Feishu bot identity source before merge.
