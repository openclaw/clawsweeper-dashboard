## Label Justifications

- `P1`: The issue can invalidate every live Claude CLI session at once and disrupt real active agent workflows.
- `impact:session-state`: The reported failure drops reusable CLI session bindings and starts fresh execs without the previous live conversation context.
- `impact:auth-provider`: The root cause is the auth-epoch policy that combines local Claude credential storage state with OpenClaw auth-profile state.

## Summary

Keep open: current main and the latest release still compose Claude CLI auth epochs from the local credential fingerprint plus the selected auth-profile credential, so a same-identity local credential source-presence flip can still rotate the epoch and invalidate live sessions. Related fix PRs are either closed unmerged or overlapping/conflicting, so the remaining blocker is the maintainer auth-identity policy decision rather than lack of source evidence.

## What This Changes

The issue asks OpenClaw to keep live Claude CLI sessions reusable when the local credential storage source appears or disappears but the authenticated identity is unchanged.

## Best Possible Solution

Settle the Claude CLI auth ownership policy, then land a narrow provider-owned epoch rule that keeps same-identity storage flips stable while still invalidating on real identity changes, with regression coverage for file-missing/file-present and bootstrap cases.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For Claude CLI sessions with an OpenClaw auth profile, should the auth epoch treat unchanged credential identity as stable when the local credentials file appears or disappears, and where should that policy live?

Rationale: The source-repro is clear, but changing auth-epoch inputs defines the session/auth boundary and can affect when existing sessions survive or reset.

Likely owner: steipete

Owner reason: The strongest history signal for the auth-epoch invalidation policy is the original auth-epoch commit plus later related merge activity.

Owner confidence: high

Options:

- **Profile credential owns identity when present (recommended):** Exclude or suppress the local Claude file fingerprint once the selected auth-profile credential exists, keep a bootstrap fallback, and test real identity changes separately.
- **Host credential owns Claude CLI:** Adopt a host-owned mode for Claude CLI and separately make local credential presence identity-stable, otherwise the exact file absent/present flip can remain unresolved.
- **Keep storage-sensitive invalidation:** Treat any local credential source-presence change as a reset boundary and accept the reported session-continuity cost.

## Solution Assessment

Unclear until maintainers choose the auth identity policy; the narrowest maintainable fix appears to be a provider-owned epoch policy, not transcript reseed or a broad session reset feature.
