## Summary

Keep open: current main and v2026.6.11 still compose Claude CLI auth epochs from both the local credential fingerprint, when present, and the selected auth profile, so the reported same-identity storage-source flip can still invalidate live CLI sessions.

## What This Changes

The issue reports that `resolveCliAuthEpoch` invalidates live CLI sessions when Claude CLI credential storage presence changes even though the auth identity is unchanged.

## Best Possible Solution

Land or sponsor a focused Claude CLI auth/session policy fix that keeps unchanged identity from resetting live sessions across local source-presence flips while preserving resets for logout, real account changes, and unprovable identity changes.

Options:

- **Adopt Host-Only Direction:** Accept the broader host-owned auth model from the open PR after resolving conflicts and security concerns.
- **Keep Current Fail-Closed Behavior:** Leave current behavior in place and document that users should avoid mixed auth-profile/local Claude CLI churn until stronger identity proof exists.

I did not run a live Anthropic Max credential-flow reproduction in this read-only pass.

## Solution Assessment

Unclear. The requested direction is plausible and narrow, but maintainers still need to choose the Claude CLI identity boundary so unchanged storage presence does not reset sessions while real or unprovable auth changes still do.
