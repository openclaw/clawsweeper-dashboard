## Label Justifications

- `P1`: The report describes a real CLI session continuity break where all live bindings can be invalidated during normal credential storage churn.
- `impact:session-state`: The failure drops reusable CLI session bindings and makes the next turn start without the prior live session context.
- `impact:auth-provider`: The bug is caused by auth-profile and local Claude CLI credential epoch composition.

## Summary

Keep open: current main and v2026.6.11 still compose Claude CLI auth epochs from the local credential fingerprint when it is readable plus the selected auth-profile credential, so a same-identity file/keychain source-presence flip can still produce a different epoch and invalidate live CLI sessions.

## What This Changes

The issue asks OpenClaw to keep live CLI sessions reusable when Claude CLI credential storage presence changes but the authenticated identity is unchanged.

## Best Possible Solution

Settle the Claude CLI auth-epoch ownership rule, then land a focused fix and tests that keep same-identity storage-shape changes stable while preserving invalidation for real account or logout changes.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For Claude CLI sessions with an auth-profile credential present, should the auth epoch treat local credential file/keychain source presence as identity-changing, or should the auth-profile identity be canonical for session continuity?

Rationale: Current code deliberately treats local credential absence as meaningful auth-state loss, but the report shows that same rule also invalidates live sessions when only the local source of storage appears or disappears.

Likely owner: steipete

Owner reason: The relevant auth invalidation behavior and follow-up CLI continuity work trace most strongly through this history.

Owner confidence: high

Options:

- **Prefer auth-profile identity (recommended):** Skip the local Claude CLI fingerprint whenever a selected auth-profile credential is present, and rely on auth-profile identity changes to invalidate sessions.
- **Keep storage-sensitive epochs:** Leave local credential presence in the epoch and accept same-identity session resets when the non-prompting local read flips between null and readable.
- **Add explicit backend ownership mode:** Define a narrower CLI backend auth-owner contract before changing Claude CLI so profile-owned, host-owned, and mixed modes each have upgrade tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: What Claude CLI identity signal should reusable-session auth epochs trust when OpenClaw has both an auth-profile credential and a local Claude credential source whose storage presence can appear or disappear?

Rationale: Current code can reset live sessions for storage-shape churn, but relaxing the epoch without an accepted identity boundary could preserve a session across a real or unprovable account change.

Likely owner: joshavant

Owner reason: Josh already gave item-specific guidance on the overlapping PR about avoiding a public host-only mode and preserving resets for changed or unproven auth identity.

Owner confidence: medium

Options:

- **Narrow Identity-Stable Fix (recommended):** Use a Claude CLI-specific internal fix that ignores storage-presence churn only when the unchanged identity boundary is proven, and fail closed for logout or unproven account changes.
- **Accept Host Credential Ownership:** Allow the local Claude credential to own the epoch for Claude CLI sessions and document the security tradeoff around the available host identity signal.
- **Keep Fail-Closed Behavior:** Leave the current invalidation behavior in place and document user-side mitigation for setups with credential source churn.

## Reproduction Assessment

Yes, from source inspection rather than a live run. Current main can produce one epoch from the auth profile alone when the local read is null and a different epoch from local-plus-profile when it is readable, and the session reuse code invalidates that mismatch as `auth-epoch`.

## Solution Assessment

Unclear until maintainers decide the auth identity policy. The proposed profile-precedence shape is the narrowest fit for the reported source-storage flip, but it must not weaken invalidation for real credential loss or account change.
