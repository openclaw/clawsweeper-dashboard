## Label Justifications

- `P1`: The report describes active Claude CLI sessions being invalidated across all live bindings when unchanged auth identity is represented by a different local credential source shape.

## Summary

Keep open: current main and v2026.6.11 still compute Claude CLI auth epochs from both local credential presence and the selected auth profile, so the reported same-identity source-of-storage flip can still invalidate live CLI sessions.

## What This Changes

The issue requests a fix so `resolveCliAuthEpoch` does not invalidate every live Claude CLI session when local credential storage presence changes but the auth identity is unchanged.

## Best Possible Solution

Settle the Claude CLI auth identity contract, then land a narrow fix that keeps unchanged identity from resetting live sessions across local source-presence flips while still failing closed on logout, real account changes, or unprovable identity changes.

Question: What should define the Claude CLI auth identity boundary for reusable sessions when an OpenClaw auth profile exists but local Claude credential storage presence changes?

Rationale: The source-level bug is clear, but the fix changes credential-boundary session reuse; automation cannot safely choose whether profile credential, host credential, or a stricter fail-closed rule owns identity without maintainer/security intent.

Likely owner: vincentkoc

Owner reason: Vincent has the strongest recent history on the auth-profile/CLI epoch seams and release state, while the decision should also include security-owner review.

Owner confidence: medium

Options:

- **Identity-Stable Epoch With Fail-Closed Guardrails (recommended):** Ignore local storage-source presence only when the same Claude CLI/OpenClaw auth identity is provable, and keep resetting when identity is absent, changed, or unprovable.
- **Profile Credential Owns The Boundary:** Treat the selected OpenClaw auth profile as canonical when present and use local CLI fingerprints only for bootstrap/no-profile cases, accepting that profile identity must be sufficient for Claude CLI reuse.
- **Keep Storage Presence Fail-Closed:** Accept the current reset behavior for ambiguous Claude CLI identity-less credentials and document the limitation rather than changing session reuse semantics now.

## Solution Assessment

Unclear: the requested direction is plausible, but the best fix depends on the maintainer-approved Claude CLI auth identity boundary so unchanged storage presence does not reset sessions while real or unprovable auth changes still do.
