## Summary

Keep open: current main and v2026.6.11 still let Claude CLI local credential file presence change the auth-epoch part set while an auth profile is selected, so the reported same-identity storage-source flip can still invalidate live CLI sessions.

## What This Changes

The issue asks OpenClaw to keep CLI session auth epochs stable when Claude CLI local credential storage appears or disappears but the credential identity is unchanged.

## Best Possible Solution

Adopt a maintainer-approved CLI auth-epoch policy that keeps unchanged Claude CLI identity stable across local credential storage-source flips while still invalidating logout, account switches, and unprovable identity changes.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What should Claude CLI auth epochs treat as the session identity when both an OpenClaw auth profile and local Claude CLI storage are present?

Rationale: Current main still invalidates sessions on local file presence even when the profile identity is unchanged, but suppressing that signal changes the auth/session safety boundary and should be an explicit maintainer decision.

Likely owner: steipete

Owner reason: The key invalidation behavior and central auth-epoch/session files trace to `steipete`, making him the strongest available owner for the policy decision.

Owner confidence: high

Options:

- **Make profile identity canonical (recommended):** When a selected auth-profile credential exists, use it as the epoch identity and fall back to local storage only for bootstrap/local-only cases, with tests for logout and account-switch invalidation.
- **Use a host-owned mode:** Land a narrowed host-owned Claude CLI policy only if it also prevents source-presence churn and proves upgrade behavior for existing session bindings.
- **Keep storage-presence invalidation:** Close or reject the request if maintainers want any local credential storage-source change to force session reset despite the reported continuity cost.

## Reproduction Assessment

Yes. Current-main source still changes the auth-epoch part set when the Claude CLI local reader flips between null and a credential while an auth profile is selected, and `resolveCliSessionReuse` invalidates same-version epoch mismatches.

## Solution Assessment

Unclear. The reporter's profile-canonical fix is a plausible narrow repair, but the best final shape depends on maintainer intent for the Claude CLI auth identity boundary and must preserve real auth-change invalidation.
