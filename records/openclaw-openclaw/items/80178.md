- `impact:session-state`: The reported failure drops stored CLI session bindings and replaces the live session handle even though the user identity is unchanged.

## Summary

Keep open: current main and v2026.6.11 still build Claude CLI auth epochs from a local credential part plus the selected auth-profile part, so local credential presence can still flip the epoch and trigger `invalidatedReason: "auth-epoch"` for live sessions.

## What This Changes

The issue asks OpenClaw to keep Claude CLI auth epochs stable when the local credential storage source appears or disappears but the resolved identity is unchanged.

## Best Possible Solution

Land a narrow Claude CLI auth-epoch policy fix that treats local storage-source presence as non-identity only when the same host/profile identity is proven, while preserving resets for logout, real account switch, and unprovable identity changes.

## Maintainer Decision

Kind: security_boundary

Question: What should define the Claude CLI auth epoch when an OpenClaw auth profile exists and the local Claude credential source appears or disappears without proven identity change?

Rationale: Current source makes storage presence part of the auth boundary, but removing it naively can keep sessions alive across a real or unprovable account change for identity-less Claude CLI OAuth profiles.

Likely owner: joshavant

Owner reason: Josh provided the most explicit maintainer-facing auth-boundary guidance on the overlapping Claude CLI auth-epoch PR.

Owner confidence: medium

Options:

- **Require Proven Same Identity (recommended):** Implement a Claude-specific fix that ignores local storage-source churn only when the auth/profile identity is provably unchanged, and otherwise keeps fail-closed invalidation.
- **Use Profile Credential As Canonical:** Treat the selected auth profile as the epoch source whenever present, accepting that identity-less Claude CLI OAuth profiles may not detect some real local account switches.
- **Keep Fail-Closed Storage Sensitivity:** Leave the current invalidation behavior in place and document/work around the credential file/keychain churn for affected users.

## Reproduction Assessment

Yes, source-reproducible: current main still changes the auth-epoch part set when a Claude CLI local credential read flips between absent and present while an auth profile is selected, and session reuse invalidates same-version epoch mismatches.

## Solution Assessment

Unclear as a final implementation: the issue is valid, but maintainers still need to choose the Claude CLI identity boundary before code should suppress storage-presence churn.
