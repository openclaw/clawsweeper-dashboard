## Summary

Keep open: current main and v2026.6.11 still let Claude CLI local credential presence change the auth epoch part set while an auth profile is selected, so the reported same-identity storage-source flip can still invalidate live CLI sessions.

## What This Changes

The issue asks OpenClaw to keep Claude CLI session auth epochs stable when local credential storage flips between absent and present but the resolved auth identity is unchanged.

## Best Possible Solution

Settle one Claude CLI auth epoch owner policy, then implement it so unchanged identity and storage-source churn do not reset live sessions while real account changes, logout, bootstrap local-only cases, and unprovable auth loss still invalidate with regression coverage.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For Claude CLI sessions with a selected OpenClaw auth profile, should the auth epoch track stable credential identity rather than whether local credential storage is currently readable or present?

Rationale: The code fix is small, but the intended security/session boundary is not purely mechanical: one choice avoids spurious context loss, while another keeps fail-closed invalidation for absent or unreadable local auth state.

Likely owner: steipete

Owner reason: The central auth-epoch invalidation behavior appears to originate in Peter Steinberger's `e5023cc141e2` commit, and this decision needs the same session/auth boundary ownership.

Owner confidence: high

Options:

- **Use profile identity when present (recommended):** When a selected auth-profile credential exists, make it the canonical epoch identity and use the local Claude CLI fingerprint only for bootstrap/no-profile cases, preserving real profile identity changes.
- **Keep host credential as owner:** Continue treating local Claude CLI credential presence as authoritative, accepting same-identity resets as the cost of fail-closed logout or unreadable-state detection.
- **Adopt host-only plus explicit absence policy:** Use the host-only backend direction only if it also defines how file absence versus keychain/file source flips are distinguished from real logout.

## Reproduction Assessment

Yes. Current source still changes the auth epoch part set when a Claude CLI local credential read flips between absent and present while an auth profile is selected, and `resolveCliSessionReuse` invalidates same-version epoch mismatches.

## Solution Assessment

Unclear until maintainers choose the auth identity boundary. The reporter's profile-canonical direction is a narrow plausible fix for this issue, while the open host-only PR addresses an adjacent auth-profile rotation problem but does not by itself solve local storage-source flips.
