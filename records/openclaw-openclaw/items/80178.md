## Summary

Keep open: current main and v2026.6.11 still build Claude CLI auth epochs from a local credential part when present plus the selected auth-profile part, so the reported source-of-storage presence flip can still invalidate live sessions. The overlapping open PR is not a safe canonical fix because it is conflicting and still under auth-boundary review.

## What This Changes

The issue reports that Claude CLI session auth epochs change when the local credential file appears or disappears even though the user identity is unchanged.

## Best Possible Solution

Land or sponsor a focused Claude CLI auth/session policy fix that keeps unchanged identity from resetting live sessions across local source-presence flips while preserving resets for logout, real account changes, and unprovable identity changes.

## Reproduction Assessment

Yes. Current-main source still changes the auth-epoch part set when a Claude CLI local credential read flips between absent and present while an auth profile is selected, and session reuse invalidates same-version epoch mismatches.

## Solution Assessment

Unclear. The requested direction is plausible, but maintainers still need to choose the Claude CLI identity boundary so storage-presence churn does not reset sessions while real or unprovable auth changes still do.
