## Summary

Keep open: current main and v2026.6.11 still include the local CLI credential fingerprint whenever the reader returns one, so a same-identity source-of-storage flip can still move the auth epoch and invalidate live CLI sessions.

## What This Changes

The issue reports that `resolveCliAuthEpoch` invalidates live CLI sessions when Claude CLI credential storage presence changes even though the authenticated identity is unchanged.

## Best Possible Solution

Land a focused auth-epoch policy fix that keeps unchanged identity from resetting Claude CLI sessions across local source-presence flips while preserving invalidation for real credential loss or account changes.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For Claude CLI reusable sessions, should an auth epoch track stable credential identity only, or also change when the readable local credential storage source appears or disappears while identity is unchanged?

Rationale: Current code intentionally keeps true local credential absence visible, while this issue shows storage-source churn can destroy live session continuity; choosing the boundary changes auth/session policy.

Likely owner: steipete

Owner reason: The earliest and most central CLI OAuth session-continuity commit in the inspected history is by steipete, and the remaining question is the auth/session policy boundary.

Owner confidence: high

Options:

- **Prefer stable identity (recommended):** Ignore local credential source-presence changes when a selected auth profile already supplies the same identity, while still invalidating on real identity changes and bootstrap credential loss.
- **Keep storage-sensitive epochs:** Retain the current conservative invalidation behavior and document that local credential storage changes can reset CLI sessions.
- **Adopt backend-owned mode:** Route Claude CLI through a backend ownership mode such as the open host-only proposal if maintainers decide the host credential is the sole auth owner for that runtime.

## Reproduction Assessment

Yes from source inspection, though not from a live credential churn run in this read-only review. Current main still changes the auth-epoch part set when a Claude CLI local credential read flips between absent and present while an auth profile is selected, and session reuse invalidates same-version epoch mismatches.

## Solution Assessment

Unclear until maintainers choose the auth identity policy. The reporter's identity-first fix is narrow, but current code explicitly preserves credential absence as a meaningful auth-state loss, so the best permanent shape needs owner intent before automation changes it.
