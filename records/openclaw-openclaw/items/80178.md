## Summary

Keep open: current main and v2026.6.11 still compose the Claude CLI auth epoch from a local credential part when the file read is present plus the selected auth-profile part, so a same-identity source-of-storage flip can still rotate the epoch and invalidate live CLI sessions.

## What This Changes

Keep CLI auth epochs stable when a Claude CLI credential file/keychain source-presence flip does not change the underlying identity.

## Best Possible Solution

Settle and implement one Claude CLI auth epoch owner policy that keeps unchanged identity stable across local storage-source flips while still invalidating on logout, real account changes, and unprovable auth changes.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For Claude CLI sessions with a selected OpenClaw auth profile, should the auth epoch treat the profile credential as canonical identity when present, or should the ambient host/local credential remain part of the session identity?

Rationale: Both choices affect auth/session safety: excluding local file presence prevents destructive same-identity resets, but over-broad reuse could cross a real or unprovable credential change.

Likely owner: steipete

Owner reason: Peter has the clearest feature-history signal for the CLI session auth invalidation behavior and can arbitrate the session/auth boundary with the adjacent owners.

Owner confidence: high

Options:

- **Profile credential canonical when present (recommended):** Ignore the local Claude CLI fingerprint once a selected auth-profile credential exists, with regression tests for file absent/present, logout, and identity change behavior.
- **Host-only Claude CLI policy:** Adopt a backend-level host-only policy like the overlapping PR, after proving it covers this storage-source flip and preserves real host re-login invalidation.
- **Keep fail-closed epoch composition:** Keep current local-plus-profile hashing and document that source-presence churn can reset live sessions as an intentional auth safety tradeoff.

## Reproduction Assessment

Yes. Current-main source still changes the auth-epoch part set when the Claude CLI file credential read flips between absent and present while an auth profile is selected, and `resolveCliSessionReuse` invalidates same-version epoch mismatches.

## Solution Assessment

Unclear. The reported profile-canonical fix is narrow and plausible, but maintainers need to choose the Claude CLI auth identity boundary before automation should change session reuse semantics.
