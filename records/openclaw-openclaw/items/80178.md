## Summary

Keep open: current main and the latest release still include Claude CLI local credential presence in the auth epoch while also adding the selected auth-profile part, so the reported storage-source flip can still invalidate live CLI sessions even when identity is unchanged.

## What This Changes

The issue reports that `resolveCliAuthEpoch` invalidates live Claude CLI sessions when local credential storage presence changes despite unchanged auth identity.

## Best Possible Solution

Land a focused Claude CLI auth-epoch policy fix that keeps unchanged identity from resetting live sessions across local credential source-presence flips while preserving invalidation for logout, real account switches, and unprovable identity changes.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For Claude CLI sessions with an auth-profile credential, should the reusable-session auth epoch treat the auth profile as the canonical identity and ignore local credential storage presence, or should local file/keychain presence remain part of the epoch?

Rationale: The narrow code fix is clear, but the choice changes the auth/session identity contract and must be owned by maintainers before automation writes it.

Likely owner: steipete

Owner reason: The clearest history signal for CLI OAuth session continuity and session invalidation policy is Peter Steinberger's prior work on this exact surface.

Owner confidence: high

Options:

- **Profile identity owns epoch (recommended):** Ignore the local Claude CLI fingerprint when an auth-profile credential is present, preserving sessions across file/keychain storage churn while still rotating on profile identity changes.
- **Keep combined storage epoch:** Keep the current local-plus-profile epoch and accept that local storage presence changes intentionally reset live CLI sessions.
- **Backend-specific host policy:** Adopt a backend policy that declares whether the host CLI credential or OpenClaw profile owns the epoch, then apply it to claude-cli with upgrade proof.

## Reproduction Assessment

Yes from source inspection: a mocked Claude local credential reader that returns null and then a credential would make `resolveCliAuthEpoch` switch between profile-only and local-plus-profile inputs, and `resolveCliSessionReuse` invalidates same-version epoch mismatches. I did not run tests because this is a read-only cleanup review.

## Solution Assessment

Unclear until maintainers settle the auth identity policy; the reporter's proposed shape is narrow and plausible, but it changes the auth-boundary contract for profile-plus-local CLI sessions.
