## Summary

Keep open: current main and v2026.6.11 still build Claude CLI auth epochs from both the file-only local credential fingerprint and the selected auth profile, so a local credential source-presence flip can still produce an auth-epoch mismatch and reset live CLI sessions. The recent reporter update says the same failure is still reproducible on v2026.6.11, and the related fix PRs are either closed unmerged or still under auth-boundary review.

## What This Changes

The issue asks OpenClaw to keep live Claude CLI sessions reusable when local credential storage presence changes but the resolved auth identity is unchanged.

## Best Possible Solution

Land a maintainer-approved Claude CLI auth-epoch policy that ignores unchanged storage-presence churn while still invalidating logout, true account changes, and unprovable identity changes.
