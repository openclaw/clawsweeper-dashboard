## Label Justifications

- `P1`: The reported auth-epoch reset can break active Claude CLI agent workflows by dropping live session continuity mid-conversation.
- `impact:session-state`: The failure mode invalidates stored CLI session bindings and replaces a live session handle despite unchanged effective identity.
- `impact:auth-provider`: The trigger is the auth epoch calculation across local Claude CLI credentials and OpenClaw auth-profile state.

## Summary

Keep open: current main and v2026.6.11 still compose the CLI auth epoch from an optional local credential fingerprint plus the selected auth-profile credential, so a local storage-presence flip can still rotate the epoch and reset live sessions; the related PRs are unmerged candidate/auth-boundary discussions, not landed fixes.

## What This Changes

The issue asks OpenClaw to stop invalidating live Claude CLI sessions when local credential storage presence changes but the effective auth identity is unchanged.

## Best Possible Solution

Land or sponsor a narrow Claude CLI auth-epoch policy that ignores storage-source churn only when auth identity is proven unchanged, preserves bootstrap/logout/account-change invalidation, and adds focused regression plus real credential-flow proof.

Question: What should define the Claude CLI reusable-session auth identity when an OpenClaw auth profile exists but the local Claude credential source appears or disappears?

Rationale: The source-level bug is clear, but the safe fix requires maintainer intent on whether to trust profile identity, host credential identity, or fail closed when identity cannot be proven.

Likely owner: steipete

Owner confidence: high

Options:

- **Proven identity only (recommended):** Keep sessions reusable across storage-source churn only when the unchanged Claude CLI identity is proven; otherwise fail closed and reset.
- **Profile credential is canonical:** Use the selected auth profile as the session identity when present, accepting that identity-less profiles may not detect all host account changes.
- **Keep current fail-closed behavior:** Leave storage-presence flips as auth-epoch changes until Claude CLI exposes a stronger stable identity signal.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: current main conditionally adds a local claude-cli fingerprint and then invalidates same-version stored bindings when that epoch differs. I did not run a live Anthropic Max credential-source flip in this read-only review.

Unclear as an implementation. The requested direction is plausible, but the best fix needs maintainer agreement on the Claude CLI identity boundary so unchanged storage shape does not reset sessions while real or unproven auth changes still do.
