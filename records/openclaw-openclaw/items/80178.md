## Summary

Keep open: current main and v2026.6.11 still compose the Claude CLI auth epoch from both the local credential fingerprint and the selected auth-profile part, so a same-identity local credential source-presence flip can still invalidate live CLI sessions.

## What This Changes

The issue asks OpenClaw to stop same-identity Claude CLI local credential storage-presence changes from rotating CLI auth epochs and invalidating live session bindings.

## Best Possible Solution

Adopt a narrow Claude CLI auth-epoch contract that preserves live session continuity across same-identity storage-source flips while failing closed on changed or unproven identity, then resolve or replace the overlapping open PR under that policy.

- **Approve Host-Only Contract:** Make Claude CLI local host credentials the session auth owner and intentionally ignore cosmetic OpenClaw profile changes after security review.
- **Keep Fail-Closed Behavior:** Leave current invalidation semantics in place and document user-side mitigation for setups that share Claude CLI credentials across storage sources.
