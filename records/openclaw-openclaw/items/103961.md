## Summary

This PR remains necessary because current `main` still trusts any live-PID usage-cost lock indefinitely, but the unchanged head is not merge-ready: it can break single-writer serialization, invalidates the queued-retry fixture, and does not show that its unregistered-token state arises from the reported in-process restart. The linked issue should remain open while the branch is repaired and proven against a live gateway.

## What This Changes

The PR adds process-local usage-cost lock-token tracking, reclaims same-PID locks without a registered token, and adds a regression test for that fabricated leaked-lock state.

## Best Possible Solution

Use one lifecycle-owned lock registry that registers ownership before publication, rolls it back on every failed acquisition, explicitly retires or transfers refresh ownership at the in-process restart boundary, and proves both live-lock serialization and abandoned-lock recovery in focused tests plus a redacted live gateway run.
