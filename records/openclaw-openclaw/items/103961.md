## Summary

The new head resolves the prior publish-race and foreign-lock coverage findings, but it still resets only half of the restart ownership state: an abandoned queue entry remains unschedulable, while a still-running old refresh can lose its lock protection. Real gateway proof is also still absent.

## What This Changes

Adds process-local usage-cost lock-token tracking, reclaims unregistered same-PID locks, clears token registrations during in-process gateway restart, and adds lock and restart regression tests.

## Best Possible Solution

Give usage-cost refreshes a lifecycle generation or explicit abort-and-drain contract so queue admission and lock ownership retire together at restart, then prove recovery and overlap exclusion in one lifecycle test.
