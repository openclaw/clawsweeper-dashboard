## Summary

The central idea is useful, but the current head clears refresh-lock ownership without retiring the independently owned queue lifecycle, so pre-restart work can overlap or mutate post-restart state. The linked issue remains valid, and the promised live gateway proof is not yet attached.

## What This Changes

The PR tracks same-process usage-cost refresh lock tokens, reclaims unowned self-PID locks, clears holder registrations during in-process gateway restart, and adds lock-behavior regression tests.

## Best Possible Solution

Generation-scope or retire the complete usage-cost refresh lifecycle at restart—lock holders, queued timers, active promises, and completion ownership—then prove stale completions cannot mutate current state and attach redacted live gateway recovery evidence.
