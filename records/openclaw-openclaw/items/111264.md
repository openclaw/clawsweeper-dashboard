## Summary

The patch appears narrowly correct and includes production-path proof, but it intentionally changes which previously accepted opaque-cursor aliases can resume a visible-message page. No line-level defect is evident; a maintainer should confirm that rejecting byte-distinct rewritten cursors is the intended Plugin SDK compatibility boundary before merge.

## What This Changes

The PR makes visible-message transcript pagination reject altered base64url cursor encodings or cursor envelopes with extra fields, while preserving canonical OpenClaw-issued cursor continuation.

## System Context

The Plugin SDK exposes paginated visible transcript messages backed by the session SQLite store. Callers return the emitted continuation cursor to the next read, which either produces the next page or returns a reset when the cursor is invalid.

## Best Possible Solution

Keep the canonical encoder/decoder round-trip rule if maintainers confirm that SDK continuation cursors are opaque values that callers must return unchanged, then merge alongside the separate raw-transcript cursor hardening where appropriate.
