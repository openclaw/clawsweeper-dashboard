## Summary

This PR is still necessary, but the prior P1 parser finding remains on the unchanged head: rejecting an unequal match after the global regex consumes it can hide a later valid equal-delimiter code span. The linked self-closing-tag work identifies the shared Markdown/parser boundary as the appropriate owner, so this branch needs that broader parser-safe repair before merge.

## What This Changes

The PR rejects inline-code candidates whose opening and closing backtick runs differ in length, with regression tests intended to prevent reasoning tags inside malformed Markdown from being preserved.

## System Context

Shared text utilities first identify Markdown code regions, then assistant-visible-text sanitization avoids modifying content inside those regions while stripping reasoning tags elsewhere. Incorrect region boundaries therefore affect what model output is treated as literal code versus sanitizable assistant text.
