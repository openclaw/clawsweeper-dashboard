## Summary

Keep open. Current main and the latest release already cover the safe implicit Linux no-display headless fallback plus actionable explicit-headed errors, but browser route/client boundaries still collapse the failure to a message-only error, so the requested machine-readable no-display contract remains unresolved.

## What This Changes

Request structured missing-display handling for managed browser launches configured for headed mode in no-display service environments, with either policy-gated headless fallback or a machine-readable error.

## Best Possible Solution

Keep the existing implicit no-display fallback, keep explicit headed mode fail-closed, and add an additive closed-code browser error envelope plus client fields for the no-display case after maintainers approve the contract.
