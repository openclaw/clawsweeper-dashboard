## Summary

The useful access-request workflow remains necessary, but this PR is not merge-ready because it introduces a second sender-group authorization model alongside current main’s canonical access-group contract and changes the pre-admission privacy and activation boundaries without maintainer-approved product direction.

## What This Changes

This PR adds blocked-DM pre-auth hooks, grouped Telegram and WhatsApp allowlist entries, sender-group metadata, allowlist command support, trusted-hook activation behavior, documentation, and regression coverage.

## Best Possible Solution

Keep a generic, explicitly enabled pre-auth observation API with minimal metadata by default, make content exposure an intentional opt-in, and derive matched sender groups through the canonical accessGroups resolver rather than fixed objects inside channel allowlists.
