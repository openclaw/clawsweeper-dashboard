## Summary

This PR appears to resolve the three earlier functional findings on its current head, but it adds a permanent plugin-runtime API that reaches profile-scoped provider authorization and usage data without maintainer-confirmed API direction. It also still lacks inspectable after-fix proof from a real provider profile, so it should remain open for maintainer API review and redacted live evidence rather than be closed or auto-repaired.

## What This Changes

Adds `runtime.providerUsage.read(...)`, a trusted plugin API that reads a sanitized provider-usage snapshot for one exact authentication profile without credential output, refresh, or fallback.

## System Context

OpenClaw plugins receive selected runtime capabilities from core. This path resolves one stored auth profile, applies the owning provider's usage-authorization policy, calls the provider usage fetch hook, and returns a token-free snapshot to the requesting plugin.
