## Summary

Keep open. The patch appears to fix a source-proven trace metadata bug without changing the public field shape, but the external PR still needs real after-fix behavior proof before merge.

## What This Changes

The PR carries per-tool `isError` metadata through embedded agent attempt results and uses it to count `toolSummary.failures` as the number of failed tool calls.

## Best Possible Solution

Preserve the shipped numeric trace field and land a narrow count fix that uses the existing per-tool error classification, with after-fix proof from a real multi-failure embedded-agent run.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: current main types `toolSummary.failures` as a number but produces it from `Boolean(attempt.lastToolError)`, so multi-failure turns are capped at one. I did not run a live 12-call agent repro in this read-only review.

## Solution Assessment

Yes, the proposed shape is the best narrow fix: it preserves the existing numeric field and counts the same per-tool error classification already used by the tool handler. The mocked full-runner regression is acceptable for this result metadata path, while renaming the field to a boolean would be a breaking trace/API change.
