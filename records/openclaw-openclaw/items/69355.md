## Review Findings

Overall confidence: 0.91

Full review comments:

- **[P2] Skip source checkouts before warning about install metadata:** `src/commands/doctor-rebuild-guard.ts:79-80`
  - body: `doctorCommand` can pass a source checkout root into this helper, and source checkouts legitimately may not have packaged `dist/build-info.json`. This branch would turn that into a corrupt install warning, so prove the root is a packaged install before emitting the note.
  - confidence: 0.91
- **[P2] Bound the npm registry lookup in doctor:** `src/commands/doctor-rebuild-guard.ts:162`
  - body: This check runs in normal `openclaw doctor`, but the registry request has no timeout or abort signal. On blackholed or very slow HTTPS paths, a nonessential warning check can stall doctor instead of becoming inconclusive.
  - confidence: 0.93
- **[P2] Do not warn from expired registry cache data:** `src/commands/doctor-rebuild-guard.ts:212`
  - body: After the fresh-cache check rejects an expired entry, the fallback still loads the same cache file unconditionally when fetch is unavailable or offline. That can turn stale registry data into `version-unreleased` or rebuild warnings, which conflicts with the stated silent-on-inconclusive behavior.
  - confidence: 0.92
- **[P2] Reject package/build-info version mismatches:** `src/commands/doctor-rebuild-guard.ts:90-91`
  - body: `package.json.version` is read but not compared with `dist/build-info.json.version`, so a partial update can evaluate the wrong version and report `pristine` or `unreleased` instead of corrupt local metadata. Treat mismatched versions as corrupt before looking up npm publish time.
  - confidence: 0.9
- **[P2] Avoid a sidecar JSON cache for doctor registry state:** `src/commands/doctor-rebuild-guard.ts:50-51`
  - body: Normal doctor would create `~/.openclaw/rebuild-guard-cache.json`, but OpenClaw-owned caches should not add another sidecar JSON file. Either avoid persistent caching here or route it through the current state-store owner.
  - confidence: 0.84
