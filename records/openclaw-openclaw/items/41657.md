## Summary

Keep open: current main and v2026.6.11 still deliver Slack files as placeholders plus media path/type context, but not as structured per-file id/name/MIME/size metadata. The useful remaining work is a shared inbound attachment metadata contract and privacy decision, not stale Slack cleanup.

## What This Changes

The issue requests structured Slack file attachment metadata in inbound messages delivered to agents.

## Best Possible Solution

Define a shared inbound attachment metadata contract, map Slack file id/name/MIME/size into it, and preserve existing placeholders, MediaPath/MediaPaths, and download-file behavior for compatibility.
