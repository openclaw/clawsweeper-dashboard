## Label Justifications

## Summary

Keep open: current main handles Slack files as placeholders plus media path/type fields, but it still lacks the requested per-file metadata surface for file name, MIME type, size, and provider file ID as structured agent context.

## What This Changes

Request structured Slack inbound file attachment metadata in agent-delivered messages instead of relying only on text placeholders or downloaded media paths.

## Best Possible Solution

Define one shared inbound attachment metadata contract that preserves existing MediaPath/MediaPaths behavior while adding provider file id, file name, MIME type, size, download/local reference, and downloaded status for Slack and sibling channels.
