## Summary

Keep open: current main and v2026.6.11 still deliver Slack attachments through placeholders, media paths, media types, and `download-file`, but they do not expose the requested structured per-file metadata fields to agents.

## What This Changes

The issue requests agent-visible Slack file attachment metadata such as file id, filename, MIME type, and size for inbound Slack messages.

## Best Possible Solution

Define one shared inbound attachment metadata contract in the channel/plugin context path, populate it from Slack files first, and preserve current placeholders plus MediaPath/MediaPaths behavior.
