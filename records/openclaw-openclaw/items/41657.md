## Summary

Keep open: current main and the latest release still expose Slack file attachments through placeholders plus legacy media path/type fields, but the requested structured per-file metadata is still missing and needs a shared channel/plugin SDK decision.

## What This Changes

The issue requests structured Slack file attachment metadata in inbound messages delivered to agents.

## Best Possible Solution

Define a shared InboundAttachments-style channel/plugin SDK contract that preserves existing placeholder and Media* fields while mapping provider file ids, filenames, MIME types, sizes, local paths, and download status across Slack and sibling channels.
