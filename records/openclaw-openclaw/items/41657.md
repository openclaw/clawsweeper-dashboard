## Summary

Keep open: current main and latest release expose Slack file attachments through downloaded media paths/types plus fileId-bearing placeholders, but they still do not provide the requested structured per-file metadata for filename, MIME type, size, and provider file ID; the Slack-only PR attempts were closed unmerged, leaving this issue as the canonical shared contract discussion.

## What This Changes

Slack inbound file messages should expose structured attachment metadata such as provider file ID, filename, MIME type, and size to agents.

## Best Possible Solution

Define one shared InboundAttachments-style metadata contract that preserves existing media path/type and placeholder behavior while mapping Slack, Discord, Telegram, and future channels consistently.
