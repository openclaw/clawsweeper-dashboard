## Label Justifications

- `P2`: The issue is a real Slack attachment metadata gap with limited blast radius and existing partial behavior through placeholders and media paths.
- `impact:message-loss`: Provider file metadata from inbound Slack attachments is not delivered as structured agent context, so part of the channel message payload is lost to agents.

## Summary

Keep open: current main handles Slack files as downloaded media plus agent-visible placeholders, but it still does not expose the requested structured file metadata surface for provider file ID, file name, MIME type, and size.

## What This Changes

The issue requests Slack file attachment metadata to be delivered to agents with inbound messages, rather than only text placeholders and media path/type fields.

## Best Possible Solution

Define one shared inbound attachment metadata contract that preserves existing MediaPath/MediaPaths and placeholder behavior while adding provider file ID, file name, MIME type, size, local/download reference, and downloaded status for Slack and sibling channels.
