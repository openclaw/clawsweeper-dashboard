## Summary

Keep open: current main and the latest release expose Slack files through placeholders, `MediaPath`/`MediaPaths`, content types, and `download-file`, but not as structured per-file metadata. The remaining work needs a shared channel attachment contract and privacy decision rather than a Slack-only field.

## What This Changes

Request to expose inbound Slack file attachment metadata such as file id, filename, MIME type, and size to agents.

## Best Possible Solution

Define a shared inbound attachment metadata contract, then map Slack file id/name/MIME/size into it while preserving current placeholders, media paths, and download-file.
