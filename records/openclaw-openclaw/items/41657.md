## Summary

Keep open: current main and v2026.6.11 still expose Slack files through placeholders plus legacy Media* fields, but no structured per-file metadata carries filename, MIME type, size, or provider file id; this needs a shared channel/plugin context decision rather than a Slack-only patch.

## What This Changes

The issue requests Slack inbound file attachment metadata, at least file id, filename, MIME type, and size, in the agent-delivered message context.

## Best Possible Solution

Define a shared InboundAttachments-style channel/plugin SDK contract that preserves existing placeholder and Media* fields while mapping provider file IDs, filenames, MIME types, sizes, local paths, and download status across Slack and sibling channels.
