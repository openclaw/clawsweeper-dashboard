## Summary

Keep open: current main and v2026.6.11 already expose Slack file IDs through placeholders, media paths, and download-file guidance, but they still do not deliver structured per-file id/name/MIME/size metadata to agents. The remaining work is a shared inbound attachment metadata contract and privacy decision, not a stale Slack-only cleanup.

## What This Changes

Request to deliver Slack file attachment metadata such as file id, filename, MIME type, and size to agents instead of only text placeholders and media path fields.

## Best Possible Solution

Define a shared inbound attachment metadata contract, map Slack file id/name/MIME/size into it, and preserve the existing placeholders, MediaPath/MediaPaths, and download-file workflow for compatibility.
