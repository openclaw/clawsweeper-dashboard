## Label Justifications

- `P2`: This is a normal-priority Slack/channel capability gap: file messages still reach agents, but structured attachment metadata is missing.
- `impact:message-loss`: Slack-provided attachment facts such as MIME type and size are omitted from the structured inbound agent context.

## Summary

Keep open: current main and the latest release expose Slack file IDs through placeholders, media paths, and `download-file`, but they still do not deliver structured per-file id/name/MIME/size metadata to agents. The remaining work is a shared channel-to-agent attachment metadata contract and privacy decision, not a stale Slack-only cleanup.

## What This Changes

Request to expose Slack file attachment metadata such as file id, name, MIME type, and size during inbound Slack message delivery to agents.

## Best Possible Solution

Define a shared inbound attachment metadata contract with privacy rules, map Slack file id/name/MIME/size into it, and preserve existing placeholders, MediaPath/MediaPaths, and download-file behavior for compatibility.
