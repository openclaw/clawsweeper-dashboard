## Summary

Keep open: current main and the latest release still expose Slack files through placeholders, media paths/types, and `download-file`, but they do not deliver the requested structured per-file id/name/MIME/size metadata to agents. The remaining work is real, but it needs a shared channel/plugin context contract decision rather than a narrow Slack-only patch.

## What This Changes

The issue requests that inbound Slack file messages deliver structured file metadata to agents instead of only text/media placeholders.

## Best Possible Solution

Define a shared inbound attachment metadata context contract in the channel/plugin API, populate it from Slack first, and preserve existing placeholder/media/download-file behavior.
