## Summary

Keep open: current main and the latest release still expose Slack file facts only through placeholders, media path/type fields, and `download-file` guidance; the requested structured per-file metadata contract remains missing and needs maintainer product direction.

## What This Changes

Request to deliver Slack file attachment metadata such as file id, name, MIME type, and size to agents when inbound Slack messages include files.

## Best Possible Solution

Define one shared inbound attachment metadata contract in the channel/plugin context path, populate it from Slack first, and keep existing placeholder plus media-path behavior compatible.
