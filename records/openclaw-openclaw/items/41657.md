Keep open: current main gives Slack file placeholders plus media path/type context, but it still lacks the requested structured per-file metadata for filename, MIME type, size, and provider file ID; the related Slack PRs were closed unmerged and do not own the remaining shared API decision.

## What This Changes

Expose Slack inbound file attachment metadata to agents when Slack message events include files.

## Best Possible Solution

Define a shared, redacted inbound attachment metadata contract for channel/plugin SDK context, preserve existing placeholders and MediaPath(s), and have Slack populate file id, name, MIME type, size, download state, and local media references.
