## Summary

Keep open: current main and the latest release still expose Slack files through placeholders, media path/type fields, and `download-file`, but they do not deliver the requested structured per-file metadata to agents.

## What This Changes

The issue requests that Slack inbound messages deliver structured file attachment metadata such as file id, file name, MIME type, and size to agents.

## Best Possible Solution

Define one shared inbound attachment metadata contract in the channel/plugin context path, populate it from Slack first, and preserve the current placeholders plus MediaPath/MediaPaths behavior for compatibility.
