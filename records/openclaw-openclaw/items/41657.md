## Label Justifications

- `impact:message-loss`: Slack-provided attachment facts such as MIME type and size are omitted from the structured inbound agent context.

## Summary

Keep open: current main and v2026.6.11 download Slack files and expose file IDs through placeholders and download-file guidance, but the requested structured per-file id/name/MIME/size metadata is still absent from the shared agent context.

## What This Changes

Request structured inbound Slack attachment metadata, at least file id, name, MIME type, and size, to be delivered to agents instead of only text/media placeholders.

## Best Possible Solution

Define a shared inbound attachment metadata contract, map Slack file id/name/MIME/size into it, and preserve existing placeholders, MediaPath/MediaPaths, and download-file behavior for compatibility.
