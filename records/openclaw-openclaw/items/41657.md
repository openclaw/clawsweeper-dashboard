## Summary

Keep open: current main handles Slack files through placeholders plus legacy media path/type fields, but the requested structured per-file metadata is still missing and should be resolved as a shared channel/plugin context contract rather than a Slack-only patch.

## What This Changes

Requested Slack inbound delivery should expose file attachment metadata such as file id, filename, MIME type, and size to agents.

## Best Possible Solution

Define a shared InboundAttachments-style channel/plugin SDK contract that preserves existing placeholders and Media* fields while mapping provider file IDs, filenames, MIME types, sizes, local paths, and download status across Slack and sibling channels.
