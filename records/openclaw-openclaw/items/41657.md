## Label Justifications

- `P2`: This is a normal-priority Slack/channel capability gap: attachment delivery works through placeholders and media paths, but structured file metadata is unavailable.
- `impact:message-loss`: Slack-provided attachment facts such as file id, name, MIME type, and size are omitted from the structured inbound agent context.

## Summary

Keep open: current main and the latest release still deliver Slack attachments as placeholders, media paths, content types, and `download-file` access, but not as structured per-file metadata. The remaining work needs a shared channel attachment contract decision rather than another Slack-only patch.

## What This Changes

The issue requests structured inbound Slack file metadata for agents, including file ID, name, MIME type, and size.

## Best Possible Solution

Define a shared inbound attachment metadata contract, then map Slack id/name/MIME/size into it while preserving current placeholders, media paths, and `download-file`.
