## Summary

Keep open: current main and the latest release still expose Slack attachments through placeholders plus legacy media path/type fields, but the requested structured per-file metadata remains missing and needs a shared channel/plugin context decision.

## What This Changes

Issue requests agent-visible Slack file attachment metadata such as file ID, filename, MIME type, and size for inbound Slack messages.

## Best Possible Solution

Define a shared InboundAttachments-style channel/plugin SDK contract that preserves placeholders and Media* fields while mapping provider file IDs, filenames, MIME types, sizes, local paths, and download status across Slack and sibling channels.
