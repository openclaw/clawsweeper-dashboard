## Label Justifications

- `P2`: The issue reports a real Slack attachment metadata gap with limited blast radius and existing partial handling through placeholders and media paths.
- `impact:message-loss`: Provider file metadata from inbound Slack attachments is not delivered as structured agent context, so part of the channel message payload is lost to agents.

## Summary

Keep open: current main and the latest release already handle Slack files as downloaded media plus fileId-bearing placeholders, but they still do not provide the requested structured per-file metadata surface for agents.

## What This Changes

Request structured Slack inbound file metadata such as file ID, file name, MIME type, and file size in agent-delivered message context.

## Best Possible Solution

Define one shared inbound attachment metadata contract that preserves existing placeholders and MediaPath/MediaPaths behavior while adding provider file id, file name, MIME type, size, download/local reference, and downloaded status for Slack and sibling channels.
