## Summary

Keep open: current main and v2026.6.11 still deliver Slack files through placeholders, media paths, content types, and `download-file`, but not the requested structured per-file metadata fields.

## What This Changes

Requests that Slack inbound file attachments expose structured metadata such as file ID, file name, MIME type, and size to agents.

## Best Possible Solution

Define a shared inbound attachment metadata contract for channel/plugin delivery, then map Slack file id/name/MIME/size into it while preserving current placeholders, media paths, and `download-file` behavior.

## Solution Assessment

Unclear until maintainers choose the API shape. A shared inbound attachment metadata contract is safer than adding Slack-only fields because the same invariant applies to multiple channel plugins.
