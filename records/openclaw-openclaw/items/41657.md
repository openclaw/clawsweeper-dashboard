## Summary

Keep open: current main and v2026.6.11 still deliver Slack files through placeholders plus media path/type fields, but they do not expose the requested structured per-file id/name/MIME/size metadata to agents.

## What This Changes

The issue asks for Slack inbound file attachments to deliver structured metadata such as file ID, name, MIME type, and size to agents.

## Best Possible Solution

Define a shared inbound attachment metadata contract, map Slack id/name/MIME/size into it, and preserve the existing placeholders, MediaPath/MediaPaths, and download-file workflow for compatibility.
