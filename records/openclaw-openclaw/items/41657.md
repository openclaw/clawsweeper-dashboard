## Summary

Keep open: current main exposes Slack files as placeholders plus media path/type fields, but it still lacks the requested structured per-file metadata for filename, MIME type, size, and provider file ID; the related Slack-only PRs were closed unmerged and leave this issue as the canonical API discussion.

## What This Changes

Expose Slack inbound file attachment metadata to agents, at minimum provider file ID, filename, MIME type, and size.

## Best Possible Solution

Define one shared InboundAttachments-style metadata contract that preserves existing MediaPath/MediaPaths behavior while mapping Slack, Discord, and Telegram provider metadata consistently.
