## Summary

Keep open: current main and v2026.6.11 already expose Slack file IDs through placeholders plus downloaded media path/type fields, but they still do not provide the requested structured per-file metadata block with file name, MIME type, size, and provider IDs for agents.

## What This Changes

Request structured Slack inbound file attachment metadata in agent-delivered message context instead of relying only on text placeholders and media path/type fields.

## Best Possible Solution

Design a shared inbound attachment metadata contract that preserves existing `MediaPath`/`MediaPaths` and placeholder behavior while adding structured per-file facts for Slack, Discord, Telegram, and future channels.
