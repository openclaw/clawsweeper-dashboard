## Summary

Keep open: current main already delivers Slack file placeholders and legacy media path/type fields, but it still does not provide the requested structured per-file metadata contract for agents.

## What This Changes

The issue requests Slack file attachment metadata such as file ID, filename, MIME type, and size in inbound agent message delivery.

## Best Possible Solution

Define a shared InboundAttachments-style channel/plugin SDK contract that preserves existing placeholder and Media* fields while mapping provider file IDs, filenames, MIME types, sizes, local paths, and download status across Slack and sibling channels.
