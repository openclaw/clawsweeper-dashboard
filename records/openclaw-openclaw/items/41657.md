## Summary

Keep open: current main still exposes Slack files through placeholders, media paths, content types, and download-file, but it does not deliver the requested structured per-file metadata fields to agents.

## What This Changes

The issue requests that Slack inbound messages expose file attachment metadata such as file id, name, MIME type, and size to agents.

## Best Possible Solution

Define a shared inbound attachment metadata context contract in the channel/plugin API, populate it from Slack first, and preserve existing placeholder/media/download-file behavior.
