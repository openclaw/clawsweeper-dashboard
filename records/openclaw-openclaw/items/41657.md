## Summary

Keep open: current main and the latest release handle Slack files as placeholders plus media path/type fields, but the requested structured per-file metadata surface is still missing and needs a shared channel/plugin API decision.

## What This Changes

The issue requests that inbound Slack file attachments deliver agent-visible metadata such as file ID, name, MIME type, and size instead of only text/media references.

## Best Possible Solution

Define one shared inbound attachment metadata contract that preserves MediaPath/MediaPaths and placeholders while adding provider file id, file name, MIME type, size, local/download reference, and downloaded status for Slack and sibling channels.
