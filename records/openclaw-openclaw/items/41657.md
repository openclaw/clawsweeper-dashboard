## Summary

Keep open: current main and latest release still expose Slack file IDs through placeholders and legacy media fields, but they do not provide the requested structured per-file attachment metadata to agents; the remaining work is a shared channel/plugin context contract decision, not a stale Slack-only cleanup item.

## What This Changes

The issue asks OpenClaw to deliver Slack inbound file attachment metadata such as file ID, filename, MIME type, and size to agents.

## Best Possible Solution

Define a shared InboundAttachments-style channel/plugin SDK contract that preserves existing placeholders and Media* fields while mapping provider file IDs, filenames, MIME types, sizes, local paths, and download status across Slack and sibling channels.
