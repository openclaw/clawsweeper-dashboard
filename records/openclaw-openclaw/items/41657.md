## Summary

Keep open: current main and the latest release still expose Slack files through placeholders, media paths, content types, and `download-file`, but they do not deliver the requested structured per-file metadata fields to agents.

## What This Changes

Request structured Slack inbound file metadata, including file id, name, MIME type, and size, in agent-delivered message context.

## Best Possible Solution

Define a shared inbound attachment metadata context contract in the channel/plugin API, populate it from Slack first, and preserve existing placeholder, media, and `download-file` behavior.
