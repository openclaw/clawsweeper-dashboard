## Summary

Keep open: current main partially handles Slack attachments through downloads, placeholders with Slack file IDs, and legacy Media* fields, but it still lacks the requested structured per-file metadata contract for agents. The related Slack-only PRs are closed unmerged or only partially overlapping, so this needs a maintainer product/API decision rather than cleanup closure.

## What This Changes

The issue requests that inbound Slack file attachments deliver structured metadata such as file ID, name, MIME type, and size to agents.

## Best Possible Solution

Define a shared InboundAttachments-style channel/plugin SDK contract that preserves existing placeholder and Media* behavior while mapping provider file IDs, filenames, MIME types, sizes, local paths, and download status across Slack and sibling channels.
