## Label Justifications

- `P2`: This is a real Slack attachment metadata gap with limited blast radius and existing partial behavior through placeholders and media paths.
- `impact:message-loss`: Provider file metadata from inbound Slack attachments is not delivered as structured agent context, so part of the channel message payload is lost to agents.

## Summary

Keep open: current main and the latest release expose Slack attachments as text placeholders plus media path/type context, but they still do not provide the requested structured per-file metadata surface for file name, MIME type, size, and provider file ID.

## What This Changes

Request to deliver Slack inbound file attachment metadata to agents instead of only text/media path context.

## Best Possible Solution

Define one shared inbound attachment metadata contract that preserves MediaPath/MediaPaths and current placeholders while adding per-file provider id, file name, MIME type, size, local/source reference, and downloaded status for Slack and sibling channels.
