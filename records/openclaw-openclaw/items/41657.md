## Summary

Keep open: current main and the latest release still expose Slack files through placeholders plus media path/type fields, but they do not provide the requested structured per-file metadata block for agents; the durable fix needs maintainer agreement on the shared inbound attachment contract.

## What This Changes

Request Slack inbound file metadata such as file ID, filename, MIME type, and size be delivered to agents instead of relying only on text placeholders and media paths.

## Best Possible Solution

Define a shared inbound attachment metadata contract in the channel/plugin API, populate Slack file id, filename, MIME type, and size first, and keep existing placeholders, media fields, and download-file behavior intact.
