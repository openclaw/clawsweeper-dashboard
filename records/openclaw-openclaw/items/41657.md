## Summary

Keep open: current main and latest release still expose Slack attachment awareness through placeholders, media paths, content types, and the `download-file` action, but they do not deliver the requested structured per-file metadata fields such as original filename, provider file id, MIME type, and size to agents.

## What This Changes

Request to include Slack inbound file attachment metadata in agent-delivered message context.

## Best Possible Solution

Define one shared inbound attachment metadata contract in the channel/plugin context path, have Slack populate it from existing file payload fields, and preserve current placeholders plus `MediaPath`/`MediaPaths` behavior.

## Reproduction Assessment

Yes, at source level: Slack file payloads carry the requested facts, but the Slack media result and shared inbound media contract drop them before agent context. I did not run a live Slack workspace repro in this read-only review.

## Solution Assessment

Not as a Slack-only text append or one-off field; the maintainable fix is a shared channel attachment metadata contract populated by Slack. Current placeholders and media paths should remain for compatibility.
