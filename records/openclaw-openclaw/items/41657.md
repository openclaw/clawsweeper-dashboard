## Summary

Keep open: current main and the latest release still expose Slack files through placeholders, media paths, content types, and `download-file`, but they do not deliver the requested structured per-file metadata fields to agents.

## What This Changes

Request structured Slack file attachment metadata such as file id, name, MIME type, and size in inbound agent message delivery.

## Best Possible Solution

Define a shared inbound attachment metadata context contract in the channel/plugin API, populate it from Slack first, and preserve existing placeholder/media/download-file behavior.
