## Summary

Keep open: current main and the latest release still expose Slack file attachments to agents through placeholders and media path/type fields, but not through the requested structured id/name/MIME/size metadata. The remaining work is a shared channel-to-agent attachment metadata contract and privacy decision, so this is not safe to close as stale or already implemented.

## What This Changes

The issue requests Slack inbound file attachment metadata, at minimum file id, name, MIME type, and size, to be delivered to agents instead of only text/media placeholders.

## Best Possible Solution

Define a shared inbound attachment metadata contract, map Slack id/name/MIME/size into it, and preserve existing placeholders, MediaPath/MediaPaths, and download-file behavior for compatibility.
