## Summary

Keep open: current main and v2026.6.11 still expose Slack files through placeholders, media paths/types, and download-file, but not the requested structured per-file metadata fields.

## What This Changes

Request structured Slack inbound file metadata for agents, including file ID, name, MIME type, and size.

## Best Possible Solution

Define a shared inbound attachment metadata context contract in the channel/plugin API, populate it from Slack first, and preserve existing placeholder, media, and download-file behavior.
