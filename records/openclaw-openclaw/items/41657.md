## Summary

Keep open: current main and the latest release still expose Slack files through placeholders, media paths, content types, and `download-file`, but they do not deliver the requested structured per-file metadata fields to agents.

## What This Changes

Request Slack inbound file attachments to include agent-visible metadata such as file id, filename, MIME type, and size.

## Best Possible Solution

Define one shared inbound attachment metadata contract in the channel/plugin context path, have Slack populate it from existing file payload fields, and preserve current placeholders plus MediaPath/MediaPaths behavior.
