## Label Justifications

## Summary

Keep open: current main and the latest release still expose Slack files through placeholders plus legacy media path/type fields, but they do not provide the requested structured per-file metadata. The durable fix changes the shared channel/plugin context contract and needs maintainer product direction rather than a Slack-only cleanup close.

## What This Changes

The issue requests agent-visible Slack inbound file attachment metadata, including file ID, file name, MIME type, and size.

## Best Possible Solution

Define a shared InboundAttachments-style channel/plugin SDK contract that preserves existing placeholder and Media* fields while mapping provider file IDs, filenames, MIME types, sizes, local paths, and download status across Slack and sibling channels.
