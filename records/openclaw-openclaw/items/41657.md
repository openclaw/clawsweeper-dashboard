## Summary

Keep open: current main and the latest release expose Slack file IDs through placeholders and legacy media fields, but the requested structured per-file metadata is still missing from the shared inbound channel context and needs a maintainer product/API decision.

## What This Changes

The issue requests agent-visible Slack inbound file attachment metadata such as file ID, filename, MIME type, and size.

## Best Possible Solution

Define a shared InboundAttachments-style channel/plugin SDK contract that preserves existing placeholder and Media* fields while mapping provider file IDs, filenames, MIME types, sizes, local paths, and download status across Slack and sibling channels.
