## Summary

Keep open: current main and v2026.6.11 still do not deliver structured Slack file id/name/MIME/size metadata to agents. Slack now exposes file IDs through placeholders and download-file guidance, but the remaining useful work is a shared channel-to-agent attachment metadata contract decision, not cleanup that can be closed.

## What This Changes

The issue requests Slack inbound file attachment metadata, including file ID, filename, MIME type, and size, in agent-delivered message context.

## Best Possible Solution

Define a shared inbound attachment metadata contract, then map Slack file id/name/MIME/size into it while preserving current placeholders, media paths, and download-file guidance.
