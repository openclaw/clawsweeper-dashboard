## Summary

Keep open: current main and latest release still only provide Slack file placeholders plus generic media path/type fields, while the requested structured attachment metadata remains missing and needs a shared channel/plugin API decision.

## What This Changes

The issue asks for Slack inbound file attachments to expose file metadata such as id, name, MIME type, and size to agents.

## Best Possible Solution

Add a shared inbound attachment metadata contract through the channel/plugin SDK, preserve existing BodyForAgent placeholders and MediaPath/MediaPaths compatibility, and map Slack files into that shape first.
