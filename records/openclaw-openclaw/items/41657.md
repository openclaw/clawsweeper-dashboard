## Summary

Keep open: current main and v2026.6.11 still expose Slack files through media paths and fileId-bearing placeholders, but they do not deliver structured per-file id/name/MIME/size metadata to agents. The remaining work is a shared channel-to-agent attachment contract decision, not stale Slack-only cleanup.

## What This Changes

Request agents receive Slack inbound file attachment metadata such as file id, file name, MIME type, and size when Slack messages include files.

## Best Possible Solution

Define a shared inbound attachment metadata contract, map Slack file id/name/MIME/size into it, and preserve the existing placeholders, media paths, and download-file workflow for compatibility.
