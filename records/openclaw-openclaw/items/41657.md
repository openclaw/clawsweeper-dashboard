## Summary

Keep open: current main and the latest release still deliver Slack files through placeholders, media paths, content types, and on-demand download-file access, but not the requested structured per-file metadata fields to agents.

## What This Changes

The issue requests Slack inbound file attachment metadata such as file id, name, MIME type, and size to be delivered to agents.

## Best Possible Solution

Define one shared inbound attachment metadata contract in the channel/plugin context path, have Slack populate it from existing file payload fields, and preserve current placeholders plus MediaPaths behavior.
