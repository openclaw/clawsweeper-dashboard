## Summary

Keep open: current main and v2026.6.11 still deliver Slack files as placeholders plus media paths/content types, but they do not expose the requested structured id/name/MIME/size attachment metadata to agents. The discussion correctly narrows this into a shared inbound attachment contract decision rather than a Slack-only patch.

## What This Changes

Request structured Slack file attachment metadata in inbound agent delivery, including file id, name, MIME type, and size.

## Best Possible Solution

Define a shared inbound attachment metadata contract, map Slack id/name/MIME/size into it, and preserve existing placeholders, MediaPath(s), and download-file behavior for compatibility.
