## Summary

Keep open: current main exposes Slack files through placeholders plus legacy media path/type fields, but the requested structured per-file metadata remains missing and needs a shared channel/plugin context decision rather than a Slack-only patch.

## What This Changes

Request to deliver Slack inbound file attachment metadata such as file ID, name, MIME type, and size to agents instead of exposing only message text, placeholders, and downloaded media paths.

## Best Possible Solution

Define a shared InboundAttachments-style channel/plugin SDK contract that preserves existing placeholder and Media* fields while mapping provider file IDs, filenames, MIME types, sizes, local paths, and download status across Slack and sibling channels.
