## Label Justifications

- `P2`: This is a real Slack attachment metadata gap with a placeholder/download-file workaround, but it needs product direction and has limited blast radius.
- `impact:message-loss`: Structured file metadata from inbound Slack attachments is unavailable to agents even though the source Slack file payload contains it.

## Summary

Keep open: current main and the latest release still expose Slack files through placeholders plus legacy media path/type fields, while the requested structured name, MIME, size, and provider-ID metadata remains a shared channel/plugin context decision.

## What This Changes

Slack inbound messages should expose file attachment metadata to agents, at least file ID, filename, MIME type, and size.

## Best Possible Solution

Define a shared InboundAttachments-style channel/plugin SDK contract that preserves existing placeholder and Media* fields while mapping provider file IDs, filenames, MIME types, sizes, local paths, and download status across Slack and sibling channels.
