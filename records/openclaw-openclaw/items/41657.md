## Summary

Keep open: current main and v2026.6.11 expose Slack files through placeholders, fileId guidance, and media paths, but still do not deliver structured per-file id/name/MIME/size metadata to agents. The remaining work is a shared channel-to-agent attachment contract decision, not a stale Slack-only bug cleanup.

## What This Changes

Request that Slack inbound file messages deliver structured attachment metadata to agents, including file ID, file name, MIME type, and file size.

## Best Possible Solution

Define a shared inbound attachment metadata contract, map Slack file id/name/MIME/size into it, and preserve the existing placeholders, media paths, and download-file workflow for compatibility.
