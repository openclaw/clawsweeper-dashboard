## Summary

Keep open: current main and the latest release still expose Slack attachment data through placeholders plus legacy Media* path/type fields, but the requested structured per-file attachment metadata remains missing and needs a shared channel/plugin context decision rather than a Slack-only patch.

## What This Changes

The issue requests agent-visible metadata for inbound Slack file attachments, including file ID, filename, MIME type, and size.

## Best Possible Solution

Define a shared InboundAttachments-style channel/plugin SDK contract that preserves existing placeholder and Media* fields while mapping provider file IDs, filenames, MIME types, sizes, local paths, and download status across Slack and sibling channels.
