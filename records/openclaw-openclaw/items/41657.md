## Summary

Keep open: current main already delivers Slack file awareness through placeholders plus MediaPath/MediaTypes, but it still lacks the requested structured per-file metadata for filename, MIME type, size, and provider file ID; the closed related PRs leave this issue as the canonical API/product decision.

## What This Changes

The issue requests that Slack inbound messages expose file attachment metadata such as file ID, filename, MIME type, and size to agents.

## Best Possible Solution

Define one shared InboundAttachments-style metadata contract for channel plugins while preserving current Slack placeholders and legacy Media* fields.
