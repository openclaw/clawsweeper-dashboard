## Summary

Keep open: current main no longer fully strips Slack files, but it still does not deliver the requested structured per-file metadata fields to agents. The prior discussion correctly narrowed this from a Slack-only bug to a shared channel attachment-metadata API decision, and the fileId-only related PRs were closed unmerged.

## What This Changes

The issue asks for Slack inbound file attachment metadata such as file ID, name, MIME type, and size to be delivered to agents.

## Best Possible Solution

Define a shared inbound attachment metadata context contract, populate Slack id/name/MIME/size from it, and keep existing placeholders, media paths, and download-file behavior intact.
