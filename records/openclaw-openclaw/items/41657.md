## Summary

Keep open: current main and the latest release still expose Slack files through placeholders, media paths, content types, and `download-file`, but they do not deliver the requested structured per-file metadata fields to agents.

## What This Changes

The issue requests Slack inbound message delivery to include attachment metadata such as file ID, name, MIME type, and size.

## Best Possible Solution

Define one shared inbound attachment metadata contract in the channel/plugin context path, populate it from Slack first, and preserve current placeholders plus `MediaPath`/`MediaPaths` compatibility.
