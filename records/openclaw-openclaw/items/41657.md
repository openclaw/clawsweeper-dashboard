## Summary

Keep open: current main and the latest release still expose Slack attachments through placeholders, media paths, content types, and `download-file`, but they do not deliver the requested structured per-file metadata fields to agents.

## What This Changes

The issue requests agent-visible Slack file attachment metadata for inbound messages, including file id, file name, MIME type, and file size.

## Best Possible Solution

Define one shared inbound attachment metadata contract in the channel/plugin context path, have Slack populate it from existing `SlackFile` fields, and preserve current placeholders plus `MediaPath`/`MediaPaths` behavior.

## Solution Assessment

No for a Slack-only text append or one-off file-id field; the maintainable fix is a shared channel attachment metadata contract populated by Slack. Current placeholders and media paths should remain for compatibility.
