- `impact:message-loss`: Provider file metadata from inbound Slack attachments is not delivered as structured agent context, so part of the channel message payload is unavailable to agents.

## Summary

Keep open: current main already exposes Slack files through placeholders plus legacy media path/type fields, but it still does not provide the requested structured per-file metadata contract for agents.

## What This Changes

Request that Slack inbound file attachments expose metadata such as file ID, filename, MIME type, and size to agents instead of relying only on placeholders and media paths.

## Best Possible Solution

Define a shared InboundAttachments-style channel/plugin SDK contract that preserves existing placeholder and Media* fields while mapping provider file IDs, filenames, MIME types, sizes, local paths, and download status across Slack and sibling channels.
