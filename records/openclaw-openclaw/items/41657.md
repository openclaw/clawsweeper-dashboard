## Summary

Keep open: current main and the latest release still expose Slack files through placeholders, media paths, content types, and `download-file`, but not as structured per-file metadata. The remaining work needs a shared channel attachment contract decision rather than a Slack-only patch.

## What This Changes

Request to include Slack inbound file id, name, MIME type, and size metadata in the agent-delivered attachment context.

## Best Possible Solution

Define a shared inbound attachment metadata contract, then map Slack file id/name/MIME/size into it while preserving current placeholders, media paths, and `download-file`.
