## Summary

Keep open: current main and v2026.6.11 still expose Slack files through placeholders, media paths, content types, and `download-file`, but they do not deliver the requested structured per-file metadata fields to agents.

## What This Changes

Request Slack inbound file events deliver file ID, filename, MIME type, and size to agents as accessible attachment metadata.

## Best Possible Solution

Define one shared inbound attachment metadata contract in the channel/plugin context path, populate it from Slack first, and preserve current placeholders plus MediaPath/MediaPaths behavior.
