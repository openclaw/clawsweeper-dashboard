## Summary

Keep open: current main and v2026.6.11 expose Slack file IDs through placeholders plus downloaded media path/type fields, but they still do not provide the requested structured per-file metadata block for agents.

## What This Changes

Request to deliver Slack file attachment metadata, including id, name, MIME type, and size, to agents during inbound Slack message handling.

## Best Possible Solution

Define a shared inbound attachment metadata contract in the channel/plugin API, populate Slack file id, filename, MIME type, and size first, and keep existing placeholders and media fields intact.
