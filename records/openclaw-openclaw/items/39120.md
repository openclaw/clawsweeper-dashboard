## Summary

Keep open: current main and the latest release still reject explicitly configured extra bootstrap files when the basename is not one of the recognized workspace bootstrap names, and the open closing PR remains the active but unmerged implementation path.

## What This Changes

The issue requests support for injecting arbitrary workspace-relative files into bootstrap session context instead of limiting `bootstrap-extra-files` to recognized basenames.

## Best Possible Solution

Keep this as the canonical issue and resolve it by landing https://github.com/openclaw/openclaw/pull/74735 or a narrower maintainer-approved replacement that preserves workspace containment, size budgets, deterministic ordering, and session filtering.

Rationale: The implementation can be narrow, but it changes which workspace files may enter deterministic system-prompt context and therefore needs a maintainer decision on product scope and guardrails.

Likely owner: steipete

Owner confidence: high

Options:

- **Approve Guarded Custom Files (recommended):** Allow explicitly configured custom-basename files after the linked PR or a replacement preserves workspace guards, budgets, docs, ordering, and session filtering.
- **Keep Recognized Basenames Only:** Reject arbitrary file injection for this hook and route custom context needs to first-class filename or broader workspace convention proposals.
- **Defer To Broader Context API:** Pause this specific hook expansion until maintainers choose a broader workspace discovery or context-file API.
