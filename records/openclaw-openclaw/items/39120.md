## Summary

Keep open: current main and v2026.6.11 still reject configured extra bootstrap files whose basename is not recognized, and the open linked PR remains the active unmerged implementation path.

## What This Changes

The issue requests allowing configured workspace-relative files with custom basenames to be injected into bootstrap context under the existing workspace and size guards.

## Best Possible Solution

Keep this as the canonical issue and resolve it by landing https://github.com/openclaw/openclaw/pull/74735 or a narrower maintainer-approved replacement that preserves workspace guards, budgets, session filtering, and docs.
