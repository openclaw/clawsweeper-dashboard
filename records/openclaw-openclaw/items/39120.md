## Summary

Keep open: current main and the latest release still reject configured extra bootstrap files whose basename is not recognized, and the open closing PR remains the active but conflicting implementation path that needs product/API approval.

## What This Changes

Request to allow configured workspace-relative files with arbitrary basenames to be injected into agent bootstrap context under the existing workspace guards and bootstrap budgets.

## Best Possible Solution

Land or replace the linked implementation with maintainer-approved guarded custom-basename support through `bootstrap-extra-files`, preserving workspace containment, budgets, deterministic ordering, session filtering, and focused docs/tests.
