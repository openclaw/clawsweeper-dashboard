## Summary

Keep open: current main and v2026.6.11 still reject custom-basename extra bootstrap files, and https://github.com/openclaw/openclaw/pull/74735 remains open and conflicting as the active candidate fix.

## What This Changes

Request to let `bootstrap-extra-files` or a first-class config key inject explicitly configured arbitrary workspace files into bootstrap context under existing containment and budget guards.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/74735 or a narrow replacement that allows explicitly configured in-workspace files while preserving realpath containment, size budgets, session filtering, docs, and focused tests.

Question: Should OpenClaw core accept explicitly configured custom-basename workspace files as part of the `bootstrap-extra-files` startup-context contract?

Rationale: The change affects deterministic system-prompt context and hook configuration semantics, so automation cannot safely choose the trust and product boundary without maintainer intent.

Likely owner: steipete

Owner confidence: high

Options:

- **Approve explicit in-workspace extras (recommended):** Allow custom basenames only when explicitly configured and still protected by workspace containment, size budgets, session filtering, docs, and tests.
- **Keep recognized basenames only:** Reject arbitrary file injection and keep users on first-class workspace filenames or manual reads.
- **Defer to broader context API:** Keep this issue open until a larger context-loading contract covers discovery, trust, and session scoping.

## Reproduction Assessment

Yes. Source inspection shows that configuring `bootstrap-extra-files.paths` with a file like `hooks/REGISTRY.yaml` reaches `loadExtraBootstrapFilesWithDiagnostics` and is rejected as `invalid-bootstrap-filename` before loading.

## Solution Assessment

Unclear until maintainers choose the contract. The existing hook boundary is the narrow plausible location, but the active PR or replacement must preserve workspace guards, budgets, session filtering, docs, and focused tests.
