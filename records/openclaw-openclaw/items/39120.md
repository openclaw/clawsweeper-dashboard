## Summary

Keep open: current main and v2026.6.11 still reject extra bootstrap files with unrecognized basenames, and the open linked PR remains the active candidate rather than a merged fix.

## What This Changes

Request to let `bootstrap-extra-files` inject explicitly configured arbitrary workspace files into bootstrap Project Context instead of only recognized bootstrap basenames.

## Best Possible Solution

Land or reject the linked PR's guarded design explicitly; the accepted end state should keep broad global globs constrained while allowing intentional custom workspace context through a documented, budgeted, workspace-contained path.

Options:

- **Allow global arbitrary paths:** Accept the broader original request by making existing `paths` able to load any workspace-contained file, trading simplicity for higher accidental injection risk.
- **Reject core expansion:** Keep core bootstrap filenames fixed and direct custom context needs to workspace hooks, plugin hooks, or context-engine plugins instead.
