## Summary

Keep open: current main and the latest release still reject explicitly configured extra bootstrap files whose basename is not recognized, and the open closing PR remains the active but conflicting implementation path. This issue is still the canonical tracker for the custom workspace bootstrap-file contract and needs maintainer product direction before a fix lands.

## What This Changes

The issue requests a supported way to inject explicitly configured arbitrary workspace files into bootstrap context without renaming them to recognized bootstrap basenames.

## Best Possible Solution

Adopt a maintainer-approved core hook contract for explicit in-workspace custom bootstrap files while preserving existing path containment, size budgets, deterministic ordering, and session filtering.
