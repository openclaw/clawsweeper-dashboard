## Summary

Keep open: current main and v2026.6.11 still reject explicitly configured extra bootstrap files whose basename is not in the recognized workspace bootstrap list, and the only active implementation path is the open, conflicting linked PR that still needs maintainer product review.

## What This Changes

The issue asks OpenClaw to let configured bootstrap context injection include arbitrary workspace-relative files, or an equivalent first-class context-files config surface.

## Best Possible Solution

Keep this as the canonical issue and resolve it by landing a repaired, rebased https://github.com/openclaw/openclaw/pull/74735 or a narrower maintainer-approved replacement that preserves workspace guards, budgets, session filtering, and docs.
