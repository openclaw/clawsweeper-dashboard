## Summary

Keep open: current main and the latest release still reject explicitly configured extra bootstrap files whose basename is not recognized, and https://github.com/openclaw/openclaw/pull/74735 is still open as the active implementation candidate rather than merged.

## What This Changes

Request support for explicitly configured arbitrary workspace-relative files to be injected into bootstrap context instead of only recognized bootstrap basenames.

## Best Possible Solution

Keep this as the canonical issue and resolve it by rebasing, reviewing, and landing https://github.com/openclaw/openclaw/pull/74735 or a narrower maintainer-approved replacement that preserves workspace containment, size budgets, session filtering, docs, and focused tests.

Rationale: The code change is mechanically narrow, but it changes deterministic prompt context admission and the public hook contract, which is a maintainer product/security boundary decision.

Likely owner: steipete

Options:

- **Approve guarded custom basenames (recommended):** Allow explicitly configured workspace-relative custom basenames through the existing hook path after preserving boundary checks, budgets, diagnostics, docs, and session filtering.

- **Defer to broader context API:** Keep this issue open until a broader workspace context/discovery convention decides how custom context files should be surfaced.
