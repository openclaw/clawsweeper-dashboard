## Summary

Keep open: current main and latest release still reject configured extra bootstrap files whose basename is not recognized, and the open closing PR remains the active implementation candidate rather than a merged fix.

## What This Changes

The issue requests support for injecting arbitrary in-workspace files into bootstrap context instead of limiting `bootstrap-extra-files` to recognized bootstrap basenames.

## Best Possible Solution

Adopt a maintainer-approved core hook contract for explicit in-workspace custom bootstrap files while preserving containment checks, size budgets, deterministic ordering, and session filtering.
