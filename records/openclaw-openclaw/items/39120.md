## Summary

Keep open: current main and v2026.6.11 still reject configured extra bootstrap files whose basename is outside the recognized workspace bootstrap list, and the open closing PR remains the active but not-yet-landed implementation path.

## What This Changes

Request support for explicitly configured arbitrary workspace files to be injected into bootstrap context without renaming them to first-class bootstrap filenames.

## Best Possible Solution

Keep this as the canonical issue and resolve it through a rebased, repaired https://github.com/openclaw/openclaw/pull/74735 or a narrower maintainer-approved replacement that preserves workspace guards, budgets, session filtering, diagnostics, and docs.
