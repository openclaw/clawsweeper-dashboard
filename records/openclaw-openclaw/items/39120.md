## Summary

Keep open: current main and the latest release still reject explicitly configured extra bootstrap files whose basename is not recognized, and the open closing PR remains the active but conflicting implementation path.

## What This Changes

The issue requests support for injecting explicitly configured arbitrary workspace files into bootstrap context instead of limiting `bootstrap-extra-files` to recognized bootstrap basenames.

## Best Possible Solution

Adopt a maintainer-approved core hook contract for explicit in-workspace custom bootstrap files while preserving path containment, size budgets, deterministic ordering, diagnostics, and session filtering.
