Keep open: current main and v2026.6.11 still reject explicitly configured extra bootstrap files with custom basenames, and the open closing PR is unmerged and currently dirty. The issue remains the canonical product-decision thread for the bootstrap context contract.

## What This Changes

The issue requests support for injecting arbitrary workspace files into bootstrap/session context instead of limiting extra bootstrap files to recognized basenames.

## Best Possible Solution

Keep this as the canonical issue and resolve it by landing https://github.com/openclaw/openclaw/pull/74735 or a narrower replacement after it preserves workspace guards, size budgets, session filtering, docs, and maintainer-approved scope.
