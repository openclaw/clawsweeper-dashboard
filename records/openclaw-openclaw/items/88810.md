- **[P2] Consume single-use reply state on the first delivered chunk:** `extensions/telegram/src/bot/reply-threading.ts:88-90`
  - body: `sendChunkedTelegramReplyText` now skips accounting for `undefined` sends, but multi-chunk single-use reply modes still only consume `params.replyToId` when the delivered chunk is index 0. If chunk 0 renders empty and chunk 1 sends, `markReplyApplied` receives `undefined`, so `progress.hasReplied` remains false and a later reply in the batch can reuse the original Telegram reply target. This is the still-unfixed prior blocker; mark the single-use reply as consumed on the first delivered chunk instead.
  - confidence: 0.88

  - body: Late discovery: this was visible in the earlier review on the same head. The loop still passes `replyMarkup` only when `isFirstChunk`, so after this PR's new `continue` path, a skipped chunk 0 consumes the inline keyboard/control payload without delivering it and chunk 1 sends without controls. Track the first delivered chunk separately and attach first-only controls there.
  - late: true
