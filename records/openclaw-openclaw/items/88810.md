## Summary

Keep this PR open: the reply-funnel repair is directionally sound, but the newly added durable outbound recovery continues with the original chunk index after an empty rejection, so a later delivered chunk can lose first-only reply metadata. The supplied live proof is also for the July 9 head, not the current July 20 head or its direct-outbound path.

## What This Changes

The branch turns Telegram render-to-empty sends into no-ops and updates reply, hook, transcript, pin, prompt-context, and direct-send handling to count only delivered messages.

## Best Possible Solution

Make the direct outbound loop delivery-aware: retry first-only metadata on the first successfully delivered chunk after any empty-content skip, add a mixed skipped-then-delivered regression test, and provide a redacted live run on the current head.
