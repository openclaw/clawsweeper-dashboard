## Summary

The empty-send fix remains necessary on current main and has strong live proof, but the new skip path consumes first-chunk-only metadata before a message is delivered, so a later successful chunk can lose inline buttons and quote context.

## What This Changes

The PR makes render-to-empty Telegram text sends resolve as no-ops and updates reply, hook, transcript, pin, and voice-fallback accounting to distinguish skipped sends from delivered message IDs.

## Best Possible Solution

Keep reply markup and first-only quote metadata pending until the first chunk that returns a real Telegram message ID, with focused skipped-first-chunk regressions, while retaining the PR's no-op send and accounting behavior.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. With chunks `[empty-rendered, visible]`, the helper sends one-time buttons and first-only quote text only on the skipped first attempt, while the delivered second attempt receives neither.

## Solution Assessment

No, not yet. Handling render-to-empty content in the Telegram send wrapper is the narrowest maintainable approach, but all first-use metadata must be keyed to the first delivered chunk rather than chunk index zero.
