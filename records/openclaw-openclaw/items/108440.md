## Summary

Keep this PR open, but do not merge its current head. The explicit-barrel approach is well researched and heavily validated, yet it immediately removes shipped public Plugin SDK symbols based on observed corpus usage, conflicting with the repository’s documented compatibility and deprecation policy. A plugin outside the sampled corpus can therefore break on an ordinary upgrade.

**Likely related people**
- `@steipete` — high confidence; recent owner of the SDK contract-reduction work and the merged compatibility-window precursor.

## What This Changes

Replaces wildcard exports across permanent Plugin SDK entrypoints with observed-use export lists, updates internal imports and tests, and deletes modules made unreachable by the narrowed surface.

## Best Possible Solution

Keep explicit barrels, but preserve every shipped symbol on the current release line, deprecate unwanted exports through the registry and migration docs with compatibility tests, and remove them only at an explicitly approved compatibility boundary.
