## Summary

Keep open: current main and the latest release still mark an exact-limit streamed read as truncated, and `web_fetch` propagates that false positive into its warning and spill state.

## What This Changes

The issue requests that `readResponseText` and `web_fetch` treat stream-backed bodies exactly equal to `maxResponseBytes` as complete rather than source-truncated.

## Best Possible Solution

Fix the shared `readResponseText` boundary so exact-limit finite reads return `truncated: false`, while confirmed overflow and endless streams still truncate safely, then add focused helper and `web_fetch` regression coverage.
