## Summary

Keep open: current main still treats an exact-size bounded stream read as truncated, and `web_fetch` still turns that flag into a user-visible truncation warning/spill state.

## What This Changes

The issue requests fixing `readResponseText` so responses exactly equal to `maxBytes` are returned complete instead of marked truncated.

## Best Possible Solution

Fix the shared `readResponseText` boundary so exact-limit reads stay complete, and add regression coverage proving `web_fetch` only warns/spills as source-truncated after real overflow.
