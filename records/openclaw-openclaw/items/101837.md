## Summary

Keep open: current main still marks exact-limit streamed responses as truncated, `web_fetch` still surfaces that as a user-visible truncation warning/spill state, and I found no merged or open canonical fix for this exact boundary bug.

## What This Changes

This issue asks OpenClaw to stop `readResponseText` and `web_fetch` from treating a response whose body is exactly `maxResponseBytes` bytes as truncated.

## Best Possible Solution

Fix the boundary in the shared `readResponseText` helper so only a confirmed overflow sets `truncated`, then cover both the helper result and `web_fetch` warning/spill behavior with focused tests.
