## Summary

Keep this PR open: the availability bug is credible, but the patch introduces two competing timeout owners and its new test exercises a hung HTTP response rather than the claimed DNS/proxy preflight stall.

## What This Changes

The PR adds a top-level timeout AbortSignal to Feishu app-registration guarded fetches and adds timeout-oriented regression coverage.

## Best Possible Solution

Use one AbortSignal deadline for both guarded preflight and the request, preserve intentional error normalization, and add a regression that stalls lookup/preflight, asserts bounded rejection, and proves the HTTP fetch implementation was never called.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source: guarded-fetch preflight requires a top-level AbortSignal, while current Feishu registration supplies only the response-phase timeout. The submitted test does not reproduce that preflight stall because lookup completes and the request reaches a hung HTTP server.

## Solution Assessment

No. Forwarding a preflight signal addresses the right boundary, but the best fix uses a single deadline signal across preflight and request handling and verifies an actual stalled lookup without dispatching fetch.
