## Summary

Keep open: current main and v2026.6.11 still render TUI chat rows without per-message timestamps, and the same-repo implementation attempt was closed unmerged. The remaining work is valid, but it needs maintainer UX/config direction before another implementation path is useful.

## What This Changes

Request to add optional user-facing timestamps to user and assistant messages in the TUI chat log.

## Best Possible Solution

Define one opt-in TUI-owned timestamp display contract using real message timestamps for live, pending, streaming, and replayed rows, then land it with config/docs alignment and PTY-visible proof.
