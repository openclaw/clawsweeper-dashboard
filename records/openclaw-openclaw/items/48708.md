## Summary

Keep open: current main and v2026.6.11 still render TUI chat rows without per-message timestamps, while the remaining work is a TUI UX/config product decision rather than an already-fixed bug.

## What This Changes

The issue requests an optional TUI chat display mode that shows per-message timestamps for user and assistant messages.

## Best Possible Solution

Define one opt-in TUI-owned timestamp display contract using persisted message timestamps where available, then land or replace a reviewed implementation with focused TUI, config, docs, and PTY-visible coverage.

## Reproduction Assessment

Yes from source inspection: current main loads message timestamps from history for reconciliation but renders chat rows through text-only user and assistant components, with no timestamp display option in TUI config.

## Solution Assessment

Unclear until maintainers choose the product shape. The maintainable direction is an opt-in TUI-owned display contract that uses stored timestamps consistently across live, pending, streaming, system, tool, and replayed rows.
