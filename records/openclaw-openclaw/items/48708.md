## Summary

Keep open: current main and the latest release still render TUI chat rows without per-message timestamps, and the remaining work is a small but product-shaped TUI/config feature rather than conservative cleanup.

## What This Changes

The issue requests an optional TUI chat display setting or command that shows per-message timestamps for user and assistant messages.

## Best Possible Solution

Define one opt-in TUI-owned timestamp display contract that defaults off, reuses stored message timestamps where available, and lands with focused ChatLog, history replay, config validation, and TUI PTY coverage.

## Reproduction Assessment

Yes from source inspection, though this is a feature request rather than a bug reproduction: current main and v2026.6.11 render TUI user and assistant rows from text only, while timestamps are only used for pending/history reconciliation.

## Solution Assessment

Unclear until maintainers choose the public shape. The maintainable direction is a TUI-owned opt-in display contract using stored timestamps consistently across live and replayed rows, not another ad hoc local-clock prefix.
