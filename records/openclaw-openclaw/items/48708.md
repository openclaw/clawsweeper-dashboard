## Summary

Keep open: current main and the latest release still lack optional per-message timestamps in the TUI chat log, and the remaining work needs maintainer UX/config direction before another implementation path is useful.

## What This Changes

The issue requests an opt-in TUI feature to show timestamps beside user and assistant chat messages, via config or an in-session toggle.

## Best Possible Solution

Define one opt-in TUI-owned timestamp display contract using persisted message timestamps for live, pending, and replayed rows, then land a reviewed implementation with config/docs alignment and PTY-visible proof.
