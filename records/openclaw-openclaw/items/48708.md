## Summary

Keep open: current main and the latest release still lack optional per-message timestamps in the TUI chat log, and the same-repo implementation attempt was closed unmerged. The remaining work is valid, but it needs maintainer UX/config direction before another implementation path is safe.

## What This Changes

The issue requests an optional timestamp display for user and assistant messages in the TUI chat log.

## Best Possible Solution

Define one opt-in TUI-owned timestamp display contract using real message timestamps for live, pending, streaming, and replayed rows, then land it with config/docs alignment and PTY-visible proof.
