## Summary

Keep open: current main and the latest release still render TUI user and assistant chat rows without optional per-message timestamps. The feature shape is source-reproducible, but it changes user-facing TUI behavior and needs maintainer product direction before another implementation path is safe.

## What This Changes

Add an optional timestamp display for user and assistant messages in the TUI chat log, potentially controlled by config or a slash-command toggle.

## Best Possible Solution

Define one opt-in TUI-owned timestamp display contract using real message timestamps for live, pending, streaming, and replayed rows, then land it with config/docs alignment and PTY-visible proof.
