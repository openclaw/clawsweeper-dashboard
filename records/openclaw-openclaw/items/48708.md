## Summary

Keep open: current main and v2026.6.11 still lack an optional per-message timestamp display in the TUI, while open fork implementation candidates and the permanent UX/config shape still need maintainer review.

## What This Changes

Add an opt-in way to show timestamps beside user and assistant messages in the `openclaw tui` chat log.

## Best Possible Solution

Define one opt-in TUI-owned timestamp display contract, disabled by default, using real message timestamps for live and replayed rows, then land a reviewed implementation with focused config/docs and PTY-visible proof.
