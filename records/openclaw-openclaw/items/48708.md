## Summary

Keep open: current main and the latest release still do not show per-message timestamps in the TUI chat log, and the remaining work is a product/config-shape decision rather than a cleanup close candidate.

## What This Changes

Request to add optional user-facing timestamps to TUI chat messages, likely controlled by a TUI config setting or slash/settings toggle.

## Best Possible Solution

Define one opt-in TUI-owned timestamp display contract using persisted message timestamps where available, align it with existing time/timezone semantics, and land a reviewed implementation with focused TUI, config, docs, and PTY coverage.

## Reproduction Assessment

Not applicable as a bug reproduction, but yes for current behavior by source inspection: the TUI render path still constructs rows from text only and drops available timestamps before display.

## Solution Assessment

Unclear until maintainers choose the product shape. The safest implementation is a TUI-owned display contract that passes timestamp metadata through row components instead of prefixing transient local-clock strings in only one path.
