## Summary

Keep open: current main and v2026.6.11 still render TUI chat rows without optional per-message timestamps, while the same-repo implementation attempt was closed unmerged. The request is valid TUI ergonomics work, but it needs maintainer UX/config direction before another implementation path is safe.

## What This Changes

Request adds an optional user-facing timestamp display for user and assistant messages in the `openclaw tui` chat log.

## Best Possible Solution

Define one opt-in TUI-owned timestamp display contract using real message timestamps for live, pending, streaming, and replayed rows, then land it with config/docs alignment and PTY-visible proof.
