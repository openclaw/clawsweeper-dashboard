## Summary

Keep open: current main and the latest release still render TUI chat rows as text-only messages and accept only the existing footer TUI config, so the requested per-message timestamp display remains unimplemented and needs maintainer UX/config direction.

## What This Changes

Request to add an optional user-facing timestamp display for TUI chat messages, controlled by config, settings, or a slash-command toggle.

## Best Possible Solution

Define one opt-in TUI-owned timestamp display contract using stored message timestamps where available, then land or replace an implementation that covers live, pending, history, system, and assistant render paths.
