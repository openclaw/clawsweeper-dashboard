## Summary

Keep this PR open: it fixes the Gateway cleanup-reporting path, but it still removes valid ACP targets from subagent allowlists and leaves offline `--json` deletes without the promised cleanup outcomes. Real after-fix evidence is also not inspectable in the PR body. Likely related people: steipete is the current agent-lifecycle contributor (low-confidence routing signal).

## What This Changes

The branch adds per-path Trash cleanup outcomes to Gateway agent deletion, surfaces them in CLI output and protocol clients, documents manual cleanup, and prunes deleted agent IDs from subagent allowlists.

## Best Possible Solution

Use one shared cleanup-outcome contract for Gateway and offline deletion, and prune allowlist entries only when the ID is no longer a valid local or configured ACP target.
