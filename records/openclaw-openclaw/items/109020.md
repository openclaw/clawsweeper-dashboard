## Summary

This PR should remain open because its watchdog is cleared at WebSocket `open`, before Google Live reports protocol readiness, so the post-open stall demonstrated in the PR body can still leave Realtime Talk connecting indefinitely. The contributor’s live output also does not prove the patched timeout and resource cleanup after the fix.

## What This Changes

The PR adds a 30-second Google Live browser WebSocket startup deadline, terminal socket cleanup, and regression tests for timeout, error, and pre-open close paths.

## Best Possible Solution

Keep the startup watchdog armed until the current Google socket emits `setupComplete`, then clear it; retain stale-socket guards and prove both pre-open and post-open timeout cleanup.
