## What This Changes

The issue asks OpenClaw to resume or visibly fail an in-progress agent turn when auto-compaction interrupts execution before the final user-visible answer is delivered.

## Best Possible Solution

Define one compaction recovery contract: an active user turn either resumes from a safe transcript boundary with original delivery context intact or emits a visible failure, while runtime-only events remain hidden and mutating tool replay policy is explicit.

Options:

- **Adopt reply-obligation recovery (recommended):** Track pending user-facing turns through compaction and resume only from replay-safe boundaries while preserving the original delivery target or surfacing a visible failure.
- **Delay threshold compaction:** Allow overflow recovery to retry, but defer ordinary threshold compaction until the current turn reaches terminal delivery or a bounded timeout.
- **Visibility-only for now:** Keep automatic resume narrow and instead make compaction interruption visibly fail so users can retry without silent abandonment.
