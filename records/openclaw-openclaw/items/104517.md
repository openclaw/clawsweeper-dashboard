## Summary

The issue is valid on current main and remains necessary: `--print-config` deliberately prints a live, TTL-bound bearer token with no redacted mode or explicit secret warning. The broader attach tracker does not cover this narrower stdout-hygiene defect, and no fix PR exists.

## What This Changes

Add a log-safe secret-handling boundary for `openclaw attach --print-config`, which currently emits a live MCP bearer token.

## Best Possible Solution

Make normal printed output non-secret by writing bearer material only to a temporary `0600` handoff artifact, while offering raw token output only through an explicit, prominently warned opt-in if that workflow remains necessary.
