## Summary

Keep open. Current main and v2026.6.11 still have deterministic source precedence, alphabetical prompt ordering, prompt limits, per-skill enable/env/config entries, and no supported user-configurable skill priority contract or `openclaw skills priority` CLI surface; related open items overlap but do not supersede the product/API decision.

## What This Changes

Request to add user-configurable skill priority/ordering, including config, priority-aware selection, and CLI management commands.

## Best Possible Solution

Define one maintainer-approved skills ordering contract in the canonical skills config/schema/docs, apply it after eligibility and per-agent filters but before prompt limits, and keep snapshots, CLI inspection, docs, and truncation behavior aligned.

## Reproduction Assessment

Yes, as a source-level feature gap. Current main and v2026.6.11 still alphabetize prompt-visible skills, apply prompt limits, reject unknown per-skill top-level config fields, and expose no `openclaw skills priority` CLI command.

## Solution Assessment

Unclear. User-configurable priority is plausible, but the proposed sidecar `priority.json` shape is not clearly better than a canonical config/schema/docs contract with explicit snapshot, truncation, and upgrade semantics.
