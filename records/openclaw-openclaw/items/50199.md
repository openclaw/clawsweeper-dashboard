## Summary

Keep open. Current main and the latest release still use fixed skill-source precedence, alphabetical prompt ordering, prompt-budget prefix truncation, strict per-skill config fields, and no `openclaw skills priority` command, so the requested priority contract remains a real product/API decision.

## What This Changes

Request to add user-configurable skill priority/ordering, priority CLI commands, and priority-aware skill discovery or selection.

## Best Possible Solution

Define one maintainer-approved skills ordering contract in the canonical config/schema/docs, apply it after eligibility and per-agent filters but before prompt limits, keep deterministic fallback ordering, and update snapshots, CLI inspection, docs, and regression tests together.
