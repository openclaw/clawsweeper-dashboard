## Summary

Keep open. Current main and v2026.6.11 still do not provide a supported skill-priority config, separate priority file, or `openclaw skills priority` CLI surface; the remaining work is a product/API decision because it adds config and changes prompt-visible skill ordering.

## What This Changes

Request to add user-configurable skill priority rules so overlapping skills can be selected or ordered predictably.

## Best Possible Solution

Define a single maintainer-approved skill selection contract that covers exact matching, skillKey aliases, prompt ordering before truncation, session snapshot invalidation, docs, and CLI management, or explicitly defer priority selection to existing allowlists and skill specificity guidance.
