## Summary

Keep open. Current main and v2026.6.11 still use deterministic alphabetical skill ordering, prompt limits, existing per-skill enable/env/config entries, and no supported skill-priority config or `openclaw skills priority` CLI; related truncation and preference issues overlap but do not replace this maintainer product/API decision.

## What This Changes

Request to add user-configurable skill priority or ordering so overlapping eligible skills are selected and prompt-ordered predictably.

## Best Possible Solution

Define one maintainer-approved skills ordering contract in the existing skills config/schema/docs, apply it after eligibility and per-agent filters but before prompt limits, and keep snapshots, runtime materialization, CLI inspection, and docs aligned.

## Reproduction Assessment

Yes, as a source-level feature gap: current main and v2026.6.11 have alphabetical prompt ordering, strict skill config without priority or pinned fields, and no priority CLI subcommand. This is not a failing bug reproduction because the issue asks for new supported behavior.

## Solution Assessment

Unclear as proposed. User-configurable priority is plausible, but the sidecar priority file is not clearly the best OpenClaw API shape compared with a canonical config/schema/docs contract plus explicit snapshot and truncation semantics.
