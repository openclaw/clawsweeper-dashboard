## Summary

Keep open. Current main and the latest release still have deterministic source precedence, alphabetical prompt ordering, prompt limits, per-skill enable/env/config entries, and no supported user-configurable skill priority contract or `openclaw skills priority` CLI surface; the open truncation issue and the closed unmerged priority PR do not replace the remaining product/API decision.

## What This Changes

The issue requests user-configurable skill priority rules and CLI support so overlapping eligible skills can be selected predictably.

## Best Possible Solution

Define one first-class skills ordering contract in the existing config schema/docs, apply it after eligibility and per-agent filters but before prompt limits, keep non-priority ordering deterministic, and align snapshots, runtime materialization, CLI inspection, docs, and truncation behavior.

## Reproduction Assessment

Yes, as a source-level feature gap: current main and v2026.6.11 still sort prompt-facing skills alphabetically, limit the fitting prefix, and expose no `skills.priority` config or priority CLI command. This is not a failing bug reproduction because the issue asks for new supported behavior.

## Solution Assessment

Unclear as proposed. User-configurable priority is plausible, but the sidecar `priority.json` design is not clearly the best OpenClaw API shape compared with a canonical config/schema/docs contract plus explicit snapshot and truncation semantics.
