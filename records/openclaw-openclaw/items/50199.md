## Summary

Keep open. Current main and v2026.6.11 still use deterministic source precedence, alphabetical model-facing skill ordering, prompt prefix truncation, strict per-skill config fields, and no supported skill-priority CLI; the related open items overlap but do not replace this product/API decision.

## What This Changes

Requested user-configurable skill priority ordering and CLI management so overlapping skills can be selected predictably.

## Best Possible Solution

Define one maintainer-approved skills ordering contract in the canonical config/schema/docs, apply it after eligibility and per-agent filters but before prompt limits, preserve deterministic fallback ordering, and align snapshots, CLI inspection, docs, and truncation behavior.
