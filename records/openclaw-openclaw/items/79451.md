## Summary

Keep open. Current main and v2026.6.11 still generate the Claude CLI MCP handoff from enabled MCP servers without threading the agent's effective `tools.deny` policy into that generated config or Claude `--disallowedTools`, and the earlier direct fix PR closed unmerged after a permission-widening review finding.

## What This Changes

The issue asks OpenClaw to enforce per-agent `tools.deny` for MCP tools when agents run through the `claude-cli` backend.

## Best Possible Solution

Materialize or forward a per-agent effective MCP deny policy before Claude CLI sees the MCP surface, preserve deny-wins semantics without widening exact allow entries, fail closed when restrictions cannot be enforced, and cover the behavior with focused tests plus real Claude CLI config proof.
