## Summary

Keep open. Current main and the latest available release paths still generate Claude CLI MCP config from enabled bundled/configured servers without applying the agent's effective `tools.deny`; the direct fix PR is closed unmerged and the newer broad proxy PR is still open, so no close reason applies.

## What This Changes

The issue asks OpenClaw to enforce per-agent MCP `tools.deny` policy when invoking the `claude-cli` backend.

## Best Possible Solution

Materialize a per-agent effective MCP surface before invoking `claude-cli`, preserve deny-wins exact/wildcard/server/profile semantics without widening access, and fail closed or proxy calls when OpenClaw cannot prove the requested restriction is enforced.
