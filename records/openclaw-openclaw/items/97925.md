## Reproduction Assessment

Yes, at source level: construct an OpenAI.BadRequestError with status 400, no code, and the reported encrypted_content decrypt message, then pass it through the retry helper with encrypted_content in the request. Current main's predicate returns false, so the retry path throws instead of stripping and retrying.

## Solution Assessment

Yes, the narrowest maintainable fix is to extend isInvalidEncryptedContentError and cover the positive and negative message cases. Reworking the circuit breaker into a general provider-error classifier would be broader follow-up work, not the best first fix for this known recoverable stale-replay miss.
