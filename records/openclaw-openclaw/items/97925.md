## Summary

Keep this issue open: current main and v2026.6.11 still only classify `invalid_encrypted_content` and `thinking_signature_invalid`, while https://github.com/openclaw/openclaw/pull/97926 is the open closing PR for the xAI/Grok code-less decrypt wording.

## What This Changes

The issue asks OpenClaw to treat xAI/Grok's code-less encrypted_content decrypt 400 as a recoverable stale reasoning replay error so the existing strip-and-retry path runs before the per-model breaker opens.

## Best Possible Solution

Review and land the narrow matcher plus regression tests in https://github.com/openclaw/openclaw/pull/97926, then close this issue as implemented; broader provider-error classification can be tracked separately if maintainers want it.

## Reproduction Assessment

Yes, at source level: construct an OpenAI-style 400 error with no `code` and the reported encrypted_content decrypt message, then pass it through the retry helper with encrypted_content in the request. Current main's predicate returns false, so the helper throws instead of stripping and retrying.

## Solution Assessment

Yes, for this concrete bug the narrowest maintainable fix is to extend `isInvalidEncryptedContentError` for the xAI encrypted_content decrypt wording and add positive plus negative regression tests. A general provider-error classification contract is broader follow-up work, not the best first fix for this recovery miss.
