## Reproduction Assessment

Yes, at source level: construct an OpenAI.BadRequestError with status 400, no code, and the reported encrypted_content decrypt message, then pass it through the retry helper with encrypted_content in the request. Current main's predicate returns false, so the helper throws instead of stripping and retrying.

Yes, the narrowest maintainable fix is to extend isInvalidEncryptedContentError for the xAI encrypted_content decrypt wording and add positive plus negative regression tests. A general provider-error classification contract is broader follow-up work, not the best first fix for this concrete recovery miss.
