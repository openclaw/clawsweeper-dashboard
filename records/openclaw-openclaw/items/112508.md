## Summary

The patch flips a documented opt-in transcript-storage behavior for every existing configuration that leaves the setting unset, while the supplied evidence does not demonstrate that physical transcript rotation fixes the reported compaction-preparation timeout.

## What This Changes

This PR changes post-compaction successor-transcript rotation so it occurs by default unless `agents.defaults.compaction.truncateAfterCompaction` is explicitly set to `false`.

## System Context

Agent sessions retain conversation transcripts on disk and compact the context sent to subsequent model turns. After compaction, this policy decides whether to continue using the retained transcript or create a smaller successor transcript, which affects session persistence and later recovery behavior.
