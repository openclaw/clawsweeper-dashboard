## Summary

This remains a useful, bounded fix: requester-scoped MCP connections must consult registries that remain live through pinned runtime surfaces, not only the currently active registry. The patch follows the existing shared live-registry precedence rule and has no supported correctness finding; rebase it and refresh the focused proof against the actual merge result before landing.

## What This Changes

The PR changes requester-scoped MCP resolver discovery to scan all live plugin registries in active-first order, preserving the first resolver for each server name, and adds coverage for a pinned HTTP registry surviving an active-registry swap.

## System Context

OpenClaw’s plugin runtime keeps an active registry plus registries pinned by long-lived HTTP, channel, and session-extension surfaces. The MCP connection resolver partitions configured servers and asks those registries for requester-specific connection details before the agent opens the MCP transport.
