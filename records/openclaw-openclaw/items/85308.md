- `merge-risk: 🚨 message-delivery`: Fresh attempt keys can cause repeated or conflicting external delivery when visible evidence is missing or incomplete.

- `merge-risk: 🚨 compatibility`: The PR changes established retry, idempotency, cleanup, and SQLite hydration semantics for existing subagent completion workflows.

## Summary

Current main still conflates requester wake and visible-delivery success, so the fix remains necessary; however, this implementation retries missing visible delivery by re-running the entire requester completion turn under a fresh idempotency key, which can repeat orchestration side effects after the requester was already successfully awakened.

## What This Changes

The PR separates requester wake accounting from required visible subagent delivery, persists pending visible-delivery state across SQLite restore, and assigns distinct idempotency keys to delivery retries.

## Best Possible Solution

Separate requester wake execution from visible-delivery retry at the runtime boundary: once the requester turn has run, never invoke that full turn again; persist and retry an isolated visible-send operation, or record a terminal visible-delivery failure when no replay-safe operation exists.
