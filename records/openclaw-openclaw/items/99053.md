## What This Changes

The PR adds Discord HTTP 413 media fallback handling in `sendMessageDiscord`, classifies stripped-media receipts as text, adds regression coverage for normal and forum/media sends, and adds a local proof script.

## Best Possible Solution

Land one canonical Discord-owned fallback that preserves text on 413 across normal and forum/media sends, with real behavior proof, then close or supersede sibling candidate branches after merge.

## Reproduction Assessment

Yes. Current main sends media caption text and the file in one multipart request through `sendDiscordMedia`, and the local Discord REST error exposes 413 status fields; no current-main fallback catches that before the text can be lost.

## Solution Assessment

Mostly yes. The patch covers the normal and forum/media `sendMessageDiscord` branches without changing config defaults, but maintainers still need to choose whether this focused branch or the sibling delivery-accounting branch is canonical.
