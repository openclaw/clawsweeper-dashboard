## Summary

Needs changes before merge: the normal Discord media path gets a useful 413 text fallback, but the forum/media-channel media path still rethrows without fallback and the PR adds unwired partial-delivery helper exports beside the existing outbound delivery contract.

## What This Changes

The PR retries normal Discord media sends as text-only on HTTP 413, marks stripped-media receipts as text, adds partial-delivery helper exports, a regression test, and a shell proof script.

## Best Possible Solution

Land one canonical Discord-owned oversized-media fallback that covers every Discord media send path and reuses existing outbound delivery result/error accounting instead of adding unused parallel helper APIs.

## Reproduction Assessment

Yes. Current main accepts media up to the 100 MB OpenClaw default and sends the caption and file in one Discord media request, so a platform HTTP 413 can reject the whole message; the linked issue provides production logs and the PR body reports live before/after Discord proof.

## Solution Assessment

No. The normal-channel fallback is a useful mitigation, but this branch is not yet the best fix because it leaves the forum/media-channel media branch uncovered and adds unwired parallel partial-delivery helpers.
