## Label Justifications

- `P1`: The PR targets a real Discord channel workflow where an agent reply can be silently lost when an attachment exceeds the upload limit.
- `merge-risk: 🚨 compatibility`: The diff changes Discord's default media cap from 100 MB to 10 MB, which can alter existing deployment behavior on upgrade.
- `merge-risk: 🚨 message-delivery`: The fallback can still be bypassed by media loader rejection and can drop later text chunks, so merging as-is can leave Discord replies undelivered or partial.

## Summary

Keep open: this is the right Discord owner boundary and the PR includes useful live proof, but the current patch applies the 10 MB cap before the new fallback can run, so the reported default-config message-loss path remains broken.

## What This Changes

The PR lowers Discord outbound media's default load cap from 100 MB to 10 MB, adds a post-load oversized-attachment text fallback in `sendDiscordMedia`, and adds a focused Discord send test.

## Best Possible Solution

Keep the Discord-specific fallback, but separate the media loading cap from the Discord send cap or catch loader size failures, then prove default, configured-higher, and long-text fallback paths with focused tests and real Discord evidence.

## Reproduction Assessment

Yes. Source inspection shows current main accepts a 10.7 MB Discord media file under the 100 MB default and sends caption plus file in one request, while the PR's 10 MB loader cap prevents the new fallback from running for that same default path.

## Solution Assessment

No. The PR fixes in the right Discord layer, but the cap is applied too early; the best fix is to keep loading and send-limit decisions distinct or catch loader-size failures and send the fallback text.
