## Summary

Needs changes before merge: the fix targets the right Discord message-loss bug, but the current patch changes configured media cap behavior, reloads normal media sends, and leaves a lint-blocking helper block.

## What This Changes

The branch preloads Discord media in `sendMessageDiscord`, sends a text-only fallback above a 10 MiB preflight cap, marks stripped-media receipts as text, adds partial-delivery helper exports, and adds one regression test.

## Best Possible Solution

Land one Discord-owned fallback that preserves explicit `mediaMaxMb` semantics, avoids loading media twice, records receipts truthfully, and either wires or removes the new partial-delivery helpers.

Yes. Current main accepts over-10 MiB Discord media under the 100 MB default and sends caption plus file in one multipart request, so a Discord 413 can reject both together; the PR body also reports live before/after Discord proof.

- **[P1] Preserve explicit Discord media caps:** `extensions/discord/src/send.outbound.ts:338`
  - body: This clamps every Discord send to 10 MiB even when `channels.discord.mediaMaxMb` is explicitly higher. Current tests and docs expose higher configured caps, so users who configured 32/50/100 MB would now have attachments stripped before upload instead of using their configured limit.
  - confidence: 0.92
- **[P1] Preserve configured media load caps:** `extensions/discord/src/send.outbound.ts:327`
  - body: `loadMaxBytes` now raises lower configured caps to 100 MiB before the fallback check. A user who set a small `mediaMaxMb` to bound Discord media reads can now download much larger remote media before it is stripped, replacing the existing `loadWebMedia` cap contract.
  - confidence: 0.86
- **[P2] Reuse the loaded media for in-cap sends:** `extensions/discord/src/send.outbound.ts:357-366`
  - body: The PR loads the media for preflight and then calls `sendDiscordMedia` on the in-cap path, which loads the same URL again. Expiring or single-use media sources can fail on the second read, and normal media sends do double network/file work.
  - confidence: 0.88
- **[P2] Fix lint-breaking one-line conditionals:** `src/infra/outbound/deliver.ts:2060`
  - body: The added helper block in `deliver.ts` introduces unbraced one-line `if` statements, and CI `check-lint` fails with `eslint(curly)` on those lines. Brace the conditionals or remove the unused helpers so the required lint gate can pass.
