## Summary

Keep open: this is a real Discord message-loss fix candidate with useful live proof, but the current patch would break configured higher Discord media caps and now loads media twice on normal sends.

## What This Changes

The PR preloads Discord outbound media, sends a text-only fallback when the loaded attachment exceeds 10 MiB, marks stripped-media receipts as text, adds partial-delivery helper exports, and adds a regression test.

## Best Possible Solution

Land one Discord-owned fallback that uses the 10 MiB default safely, preserves explicit higher mediaMaxMb or catches real 413 responses, reuses loaded media, and keeps receipts/accounting truthful.

## Reproduction Assessment

Yes. At source level, current main accepts over-10 MiB Discord media under the 100 MB default and sends caption plus file in one multipart request, so a Discord 413 rejects both together; the PR body also reports live Discord before/after proof.

## Solution Assessment

No. The PR is in the right Discord send area, but the current implementation hard-caps explicit higher mediaMaxMb values and double-loads normal media instead of sharing the loaded send path.
