## Label Justifications

- `P1`: The PR targets a real Discord channel workflow where oversized reply media can silently drop user-visible text.
- `merge-risk: 🚨 compatibility`: The diff changes the shipped default outbound Discord media cap from 100 MB to 10 MB without matching docs/config alignment.

## Summary

Keep open: the PR targets the right Discord message-loss bug, but the current patch can still fail before its text fallback runs because the new 10 MB default is passed into `loadWebMedia` before the fallback size check.

## What This Changes

The PR changes Discord outbound media sends to strip oversized attachments before send, return text receipts for stripped media, lower the default media cap, and add regression tests.

## Best Possible Solution

Land one Discord-owned fallback that catches or avoids the loader-cap failure, degrades to text before Discord drops the reply, aligns the documented media cap/default, and keeps delivery receipts truthful.

## Reproduction Assessment

Yes, at source level: current main accepts over-10 MiB media under the default 100 MB cap and sends caption plus file in one multipart Discord request. The PR's default path is also source-reproducibly suspect because the media loader can reject the oversized file before the new fallback runs.

## Solution Assessment

No. The PR is in the right Discord send area, but the fallback is placed after a media-loader cap that can prevent it from running, and the default-cap change is not aligned with current docs or the checked Discord API contract.
