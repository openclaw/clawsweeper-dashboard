## Label Justifications

- `P1`: The PR targets a real Discord channel workflow where an agent reply can be silently lost when an attachment exceeds the upload limit.
- `merge-risk: 🚨 compatibility`: The diff changes Discord's default media cap from 100 MB to 10 MB, which can alter existing deployment behavior on upgrade.
- `merge-risk: 🚨 message-delivery`: The fallback can still be bypassed by loader rejection and can drop later text chunks, so merging as-is can leave Discord replies undelivered or partial.

## Summary

Keep open: this PR is the active candidate for the Discord oversized-attachment message-loss bug, but the current patch still applies the 10 MB cap before the new fallback can run and can drop later text chunks on the fallback path.

## What This Changes

The PR lowers Discord outbound media's default cap, adds an oversized-media text fallback in the Discord send path, and adds a focused send test.

## Best Possible Solution

Keep the Discord-specific fallback, but separate the media loading cap from the Discord upload-send cap or catch loader size failures, preserve all text chunks, and prove default, configured-higher, and long-text fallback paths.

## Reproduction Assessment

Yes. Source inspection shows current main accepts a 10.7 MB Discord media file under the default 100 MB OpenClaw cap and sends caption plus file in one multipart request, while the PR's 10 MB loader cap can reject that same default path before the fallback runs.

## Solution Assessment

No. The PR fixes in the right Discord layer, but the cap is applied too early and the fallback uses only the first chunk; the better fix keeps loading and send-limit decisions distinct or catches loader-size failures and sends all text.

  - body: Changing the default cap to 10 MB means the default path passes a 10 MB `maxBytes` into `loadWebMedia`.   - confidence: 0.93

Build the fallback from the full text or send the remaining chunks after the fallback notice.
