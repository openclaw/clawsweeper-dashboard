## Label Justifications

- `P1`: The PR targets a real Discord channel message-loss bug where an oversized reply attachment can discard the reply text and make the agent appear silent.
- `merge-risk: 🚨 message-delivery`: The new fallback can deliver text while still flowing through media-send receipt accounting, so message-delivery diagnostics can remain misleading after merge.

## Summary

Keep open: the latest PR head fixes the visible Discord text-loss path by stripping over-limit attachments before send, but it still returns through the existing media-send receipt wrapper, so delivery accounting can report a media part even when only fallback text was delivered.

## What This Changes

The PR adds a Discord send-path preflight size check that omits attachments over Discord's upload cap, sends fallback text, and adds focused regression tests.

## Best Possible Solution

Keep the Discord send-layer preflight fallback, but make the fallback result accurately represent text-only or partial delivery before treating this as the canonical fix.

## Reproduction Assessment

Yes. Current main accepts an 11 MB Discord media file under the 100 MB OpenClaw cap and sends caption plus file in one Discord multipart request, so a Discord 413 can drop both together; the linked issue also provides production logs for that path.

## Solution Assessment

No. The visible fallback is in the right Discord layer, but the current patch should also distinguish omitted-attachment text fallback from successful media delivery in the returned receipt/diagnostic metadata.
