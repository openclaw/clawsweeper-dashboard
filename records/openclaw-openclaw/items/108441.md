## Summary

Keep this issue open because current main has no owner-liveness or maximum-progress-age check, and an earlier report describes the same launchd contention pattern. However, the exact claim that each replacement process refreshes its predecessor’s lease is not yet established: lease ownership is a random UUID, and renewal requires that same UUID, so a deterministic two-process reproduction or timestamp/PID trace is needed before choosing takeover semantics. citeturn817213view0turn563510view0turn877904view0

## What This Changes

Prevent a crash-looping, version-skewed gateway from indefinitely starving a healthy gateway waiting for the shared startup-migrations lease.

## Best Possible Solution

First add a deterministic two-process regression that records owner UUID, PID, host/boot identity, expiry, and heartbeat changes across crashes; then implement atomic same-host dead-owner recovery plus a bounded non-renewable migration deadline or explicit progress rule, while retaining conservative cross-host exclusion and actionable diagnostics.
