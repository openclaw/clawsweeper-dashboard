## Summary

Keep open: current main and the latest release still emit MCP loopback schema-conflict warnings from the Gateway projection path, and the open candidate fix at https://github.com/openclaw/openclaw/pull/98821 is not merged yet.

## What This Changes

The issue asks OpenClaw to stop repeated MCP loopback schema-conflict warning floods by consolidating, deduping, or otherwise reducing warning emission without changing tool schema semantics.

## Best Possible Solution

Land a focused Gateway schema-projection/logging fix that preserves first-variant schema semantics, dedupes or summarizes repeated warnings, uses a parseable subsystem path, avoids structurally equal false positives, and includes real Gateway log proof.

## Reproduction Assessment

Yes for the source path: current main still calls logWarn for MCP loopback union-schema conflicts, and the cache can rebuild schemas on context misses or TTL expiry. I did not live-reproduce the exact production warning count.

## Solution Assessment

Yes, the Gateway MCP schema projection and logger prefix path are the right layers to fix. Renaming tool fields would be broader and compatibility-sensitive; diagnostic-preserving dedupe or summary is the narrower maintainable shape.
