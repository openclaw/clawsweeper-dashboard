## Summary

Keep open: current main and the latest release still emit MCP loopback schema-conflict warnings from the schema flattener, and the linked fix paths are still open rather than merged.

## What This Changes

The issue asks OpenClaw to stop emitting repeated MCP loopback schema-conflict warnings during loopback tool-schema initialization, preferably by consolidating or deduplicating warnings across the bundle lifecycle.

## Best Possible Solution

Land a focused Gateway MCP schema-projection fix, preferably the per-tool lifecycle dedupe approach from https://github.com/openclaw/openclaw/pull/98821 or an equivalent, with sink-level log-count proof and no schema field renaming or new config surface.

## Reproduction Assessment

Yes for the source path, not for the exact 4,384/day production count. Current main still logs conflict warnings in `flattenUnionSchema`, and the loopback cache rebuilds schemas on context cache misses.

## Solution Assessment

Yes, the Gateway MCP schema projection/cache lifecycle is the right layer to fix this. Broad field renaming is compatibility-sensitive, and pure debug demotion loses diagnostic signal compared with lifecycle-scoped aggregation or dedupe.
