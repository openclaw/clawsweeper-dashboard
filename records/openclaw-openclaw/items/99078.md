## Summary

Keep open: current main still forces the reported OpenRouter image-capability 404 through the generic HTTP 404 `model_not_found` path, and no duplicate or fixing PR was found.

## What This Changes

The issue reports that OpenRouter 404 responses for unsupported image input are classified as `model_not_found` instead of a format/capability mismatch.

## Best Possible Solution

Add a narrow failover-classifier guard so OpenRouter image-capability 404s classify as `format` while true `No endpoints found for <model>` responses still classify as `model_not_found`.

## Reproduction Assessment

Yes from source inspection: `resolveFailoverReasonFromError({ status: 404, message: "No endpoints found that support image input" })` reaches the HTTP 404 fallback that defaults to `model_not_found`. I did not run the assertion because this review is read-only.

## Solution Assessment

Yes: the best fix is a focused classifier and regression-test update in the failover error path, not changes to image attachment loading, model catalog detection, or fallback configuration.
