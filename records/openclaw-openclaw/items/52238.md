## Summary

Keep open: current main and v2026.6.11 still route the reported Feishu `oc_...` event with `chat_type: "p2p"` through the direct path, and the linked closing PR is still open and conflicting rather than merged.

## What This Changes

Feishu topic/OpenChat group messages delivered as `p2p` should be classified and routed as Feishu group/topic conversations instead of direct/main sessions.

## Best Possible Solution

Keep this as the canonical Feishu inbound classifier bug and land a Feishu-local shared discriminator, verified against real or official Feishu/Lark topic metadata, that preserves true p2p direct behavior.

## Reproduction Assessment

Yes. Source inspection shows a reported Feishu `chat_type: "p2p"` event reaches current main with `isGroup === false` and follows direct routing; I did not run a live Feishu/Lark replay in this read-only review.

## Solution Assessment

No, the broad `root_id`/`thread_id` or `oc_` prefix-only fixes are not the best solution. The best fix is a verified Feishu topic/OpenChat discriminator shared by dispatch and mention-forward logic, with regressions for true p2p cases.
