## Label Justifications

- `P1`: The issue reports a broken Feishu channel workflow where topic-group messages route to the wrong session and replies do not appear in the expected chat.
- `impact:message-loss`: The reported routing error causes bot replies to miss the Feishu topic group and appear in the wrong surface.
- `impact:session-state`: Misclassifying an `oc_...` topic group as direct changes the agent session key and can split or mis-associate conversation state.

## Summary

Keep open: current main still treats Feishu `chat_type: "p2p"` as a direct-message route even when the chat id is an `oc_...` OpenChat/topic group, so the reported message-loss/session split remains unresolved in the source tree. The issue is paired with open implementation work and overlapping Feishu routing PRs, so conservative cleanup should not close it before a maintainer-approved fix lands.

## What This Changes

The issue requests Feishu OpenChat/topic-group inbound events with `oc_...` chat ids to be routed as group/topic conversations instead of p2p direct messages.

## Best Possible Solution

Land a maintainer-approved Feishu routing fix that uses a single plugin-owned discriminator for OpenChat/topic-group events, preserves direct-message policy for real p2p chats, and includes regression coverage for inbound dispatch plus any affected mention/outbound session paths.
