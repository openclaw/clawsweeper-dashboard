- `P1`: The issue reports a broken Feishu channel workflow where topic/group messages can route as direct messages and fail to reply in the user’s Feishu topic.
- `impact:message-loss`: Misclassifying a Feishu topic-group message can send or suppress the visible reply outside the intended channel conversation.
- `impact:session-state`: The group/direct mismatch can attach conversation state to the wrong agent session.

## Summary

Keep open: current main and v2026.6.11 still route a Feishu event preserved as `chat_type: "p2p"` through the direct-message path, and an open closing PR plus overlapping Feishu routing PRs still need maintainer judgment.

## What This Changes

The issue reports that Feishu topic-group messages with `oc_...` chat ids are classified as p2p/direct, causing replies and sessions to route away from the Feishu group topic.

## Best Possible Solution

Land one Feishu plugin classifier and routing fix that uses maintainer-verified topic-group evidence, preserves true P2P thread semantics, updates mention-forward parity, and proves both inbound topic-group routing and direct-thread compatibility.

## Reproduction Assessment

Yes, at source level: `parseFeishuMessageEvent` preserves `event.message.chat_type`, `isFeishuGroupChatType` only treats `group` and `topic_group` as group, and `handleFeishuMessage` routes `p2p` as direct. I did not run a live Feishu tenant repro in this read-only review.

## Solution Assessment

Unclear as proposed: the issue’s `thread_id`/`root_id` fallback is plausible, but current tests intentionally keep P2P thread messages direct. The best fix needs a verified Feishu topic-group discriminator and compatibility tests for true direct threads.
