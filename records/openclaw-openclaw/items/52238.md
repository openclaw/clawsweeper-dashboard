## Label Justifications

- `P1`: The issue reports a broken Feishu channel workflow where group/topic messages can be routed as direct messages and replies do not return to the user’s Feishu topic.
- `impact:message-loss`: Misrouting a Feishu topic-group message to a direct/main session can suppress or misdeliver the visible channel reply.
- `impact:session-state`: The wrong group/direct classification can attach conversation state to the wrong agent session.

## Summary

Keep open: current main and v2026.6.11 still classify a Feishu event with `chat_type: "p2p"` as non-group, so the reported `oc_...` topic-group path can still take direct-message routing. This remains the canonical tracker because the same-repo implementation attempt was closed as unsafe and the open related PRs are partial or still need maintainer judgment.

## What This Changes

The issue asks OpenClaw to route Feishu topic-group/OpenChat messages reported as `p2p` back through the Feishu group/topic path instead of the direct-message path.

## Best Possible Solution

Land one Feishu-plugin classifier and routing fix that uses a verified topic-group discriminator, preserves true direct-message thread behavior, updates mention-forward parity, and proves both inbound topic-group routing and direct-thread compatibility.

## Solution Assessment

No, the issue’s suggested `thread_id`/`root_id` fallback is not yet proven as the best fix because current tests intentionally keep `p2p` thread messages on the direct path. The best fix needs a verified Feishu topic-group discriminator and compatibility tests for true direct threads.
