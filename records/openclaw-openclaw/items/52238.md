## Summary

Keep open: current main and the latest release still classify the reported Feishu `oc_...` event with `chat_type: "p2p"` as non-group, so it follows direct-session routing instead of the Feishu group/topic route. This remains the canonical same-repository tracker because newer duplicate logs were closed into it, while related open PRs are either external/conflicting or scoped to adjacent outbound/topic-anchor behavior.

## What This Changes

The issue reports that Feishu topic-group messages with `oc_...` chat IDs are treated as direct `p2p` messages, causing replies and session routing to leave the topic group.

## Best Possible Solution

Keep this as the canonical Feishu inbound group/direct classification bug and land a Feishu-local shared classifier based on verified topic/OpenChat metadata, with regressions that preserve true p2p direct, p2p thread, and root-only quote behavior.

## Reproduction Assessment

Yes, source-reproducible: a reported Feishu event with `chat_type: "p2p"` reaches current main with `isGroup === false` and follows direct-session routing. I did not run a live Feishu/Lark replay in this read-only review.

## Solution Assessment

No, the originally suggested broad `root_id`/`thread_id` or `oc_` prefix-only classifier is not the best fix. The safer solution needs a verified Feishu topic/OpenChat discriminator shared by dispatch and mention-forward logic, with tests proving true p2p cases remain direct.
