## Label Justifications

- `P1`: The issue reports real Feishu group/topic messages being routed as direct messages, breaking a live channel workflow for affected users.
- `impact:message-loss`: Misclassification can send or surface the response away from the intended Feishu topic group instead of replying in the channel.

## Summary

Keep open: current main and the latest release still treat the reported Feishu `oc_...` event with `chat_type: "p2p"` as non-group, so the central wrong-session routing problem remains. This issue is still the canonical same-repository tracker because the same-repo fix PR was closed, the external closing PR is open but conflicting, and adjacent same-repo PRs do not merge this inbound classifier fix.

## What This Changes

The issue asks OpenClaw to classify Feishu topic-group/OpenChat messages delivered as `p2p` so they route to the Feishu group/topic session instead of a direct or web/main session.

## Best Possible Solution

Keep this as the canonical Feishu inbound classifier bug and land a Feishu-local shared discriminator based on verified topic/OpenChat metadata, with regressions that preserve true p2p direct, p2p thread, root-only quote, reaction, and card-action behavior.

## Reproduction Assessment

Yes, source-reproducible: the reported Feishu event with `chat_type: "p2p"` reaches current main with `isGroup === false` and follows direct-session routing. I did not run a live Feishu/Lark replay in this read-only review.

## Solution Assessment

No for the broad proposed `root_id`/`thread_id` or `oc_` prefix-only classifier; those conflict with current p2p/thread tests and prior p2p reaction routing evidence. The best fix is a verified Feishu topic/OpenChat discriminator shared by dispatch and mention-forward logic, with explicit negative tests for true p2p behavior.
