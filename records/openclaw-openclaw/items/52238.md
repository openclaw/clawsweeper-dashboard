## Summary

Keep open: current main and v2026.6.11 still classify Feishu `chat_type: "p2p"` events as direct even when the reported chat id is `oc_...`, so the Topic Group routing bug remains. The same-repo fix PR is closed unmerged, and the open related PRs cover adjacent topic-anchor or outbound route paths rather than a merged fix for this inbound classifier.

## What This Changes

The issue reports that Feishu Topic Group/OpenChat messages with `oc_...` chat ids are classified as `p2p`, causing replies and session routing to use a direct/web session instead of the Feishu group/topic route.

## Best Possible Solution

Keep this as the canonical Feishu inbound group/direct classification bug and land a Feishu-local shared classifier based on verified Topic Group/OpenChat metadata, with regressions that preserve true p2p direct, p2p thread, and root-only quote behavior.

## Reproduction Assessment

Yes. Source reproduction is high-confidence: a Feishu event with `chat_type: "p2p"` reaches current main with `isGroup === false` and follows direct-session routing; I did not run a live Feishu/Lark account replay in this read-only review.

## Solution Assessment

Unclear. The desired outcome is correct, but the implementation should not use a broad `oc_...` or root/thread-only heuristic without maintainer approval because current code and tests preserve several p2p cases that would be easy to regress.
