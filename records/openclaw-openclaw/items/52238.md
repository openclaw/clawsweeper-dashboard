## Summary

Keep open: current main and v2026.6.11 still treat the reported Feishu `oc_...` event with `chat_type: "p2p"` as non-group, which sends it through direct-message routing instead of the Feishu group/topic route. The issue is still the canonical same-repository tracker because the linked closing PR is open and conflicting, and the open same-repo Feishu PRs cover adjacent outbound/topic-anchor paths rather than a merged inbound classifier fix.

## What This Changes

Feishu topic-group messages delivered as `chat_type: "p2p"` are reported as being routed to direct/web sessions instead of the originating Feishu group or topic.

## Best Possible Solution

Keep this as the canonical Feishu inbound classifier bug and land a Feishu-local shared discriminator based on verified topic/OpenChat metadata, with regressions that preserve true p2p direct, p2p thread, root-only quote, mention-forward, and card-action behavior.
