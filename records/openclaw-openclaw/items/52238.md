## Summary

Keep open: current main and the latest release still classify the reported Feishu `chat_type: "p2p"` event as non-group, so the message can follow direct-session routing instead of the Feishu topic/group route. The issue remains the canonical same-repo tracker because the same-repo fix PR is closed unmerged, adjacent PRs cover outbound or topic-anchor behavior, and the open external closing PR has not merged.

## What This Changes

The issue asks OpenClaw to route Feishu/Lark topic-group messages delivered as `chat_type: "p2p"` with `oc_...` chat IDs as group/topic messages instead of direct messages.

## Best Possible Solution

Keep this as the canonical Feishu inbound group/direct classification bug and land a Feishu-local shared classifier based on verified topic/OpenChat metadata, with regressions that preserve true p2p direct, p2p thread, and root-only quote behavior.

## Reproduction Assessment

Yes, source-reproducible: a reported Feishu event with `chat_type: "p2p"` reaches current main with `isGroup === false` and follows direct-session routing. I did not run a live Feishu/Lark replay in this read-only review.

## Solution Assessment

No, the originally suggested broad `root_id`/`thread_id` or `oc_` prefix-only classifier is not clearly the best fix. The safer solution needs a verified Feishu topic/OpenChat discriminator shared by dispatch and mention-forward logic, with tests proving true p2p cases remain direct.
