## Summary

Keep open: current main and v2026.6.11 still treat the reported Feishu `oc_...` event with `chat_type: "p2p"` as non-group, so it can route through direct-message/session handling instead of the intended Feishu topic/group route. The issue remains the canonical tracker because the open closing PR is still conflicting and same-repo related PRs cover adjacent routing/topic-anchor paths rather than a merged inbound classifier fix.

## What This Changes

Feishu topic-group messages reported by Feishu as `p2p` are requested to route as group/topic conversations instead of direct messages.

## Best Possible Solution

Keep this as the canonical Feishu inbound classifier bug and land a Feishu-local shared discriminator, backed by live or official-contract proof, that is reused by dispatch and mention-forward logic while preserving true p2p direct/card-action/thread behavior.

## Solution Assessment

No for the originally suggested broad heuristic. The safer fix is a verified Feishu topic/OpenChat discriminator shared by dispatch and mention-forward handling, with regressions proving true p2p cases remain direct.
