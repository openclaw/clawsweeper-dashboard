## Summary

Keep open: current main and v2026.6.11 still classify the reported Feishu `chat_type: "p2p"` event as non-group, so it follows direct-session routing. The open cross-repo closing PR is not merged, and the same-repo Feishu PRs are closed, conflicting, or scoped to adjacent outbound/topic-anchor work.

## What This Changes

The issue reports Feishu topic-group messages with `oc_...` chat IDs and `chat_type: "p2p"` being routed as direct messages instead of Feishu group/topic sessions.

## Best Possible Solution

Keep this as the canonical Feishu inbound group/direct classification bug and land a Feishu-local shared classifier based on verified topic/OpenChat metadata, with regressions that preserve true p2p direct, p2p thread, root-only quote, card-action, and mention-forward behavior.

## Reproduction Assessment

Yes, at source level: a reported Feishu event with `chat_type: "p2p"` reaches current main with `isGroup === false` and follows direct-session routing. I did not run a live Feishu/Lark replay in this read-only review.

## Solution Assessment

No, the broad `root_id`/`thread_id` or `oc_` prefix-only fixes proposed in the discussion are not the best solution. The safer fix needs a verified Feishu topic/OpenChat discriminator shared by dispatch and mention-forward logic while preserving existing p2p direct/thread behavior.
