## Summary

Keep open: current main and v2026.6.11 still classify the reported Feishu `oc_...` event with `chat_type: "p2p"` as non-group, so it follows direct-message routing instead of the intended Feishu group/topic route. The issue remains the canonical same-repository tracker because the same-repo implementation PR was closed as unsafe, the open same-repo PRs are adjacent, and the open cross-repo closing PR has not merged.

## What This Changes

The issue reports Feishu topic-group messages whose `chat_type` arrives as `p2p` being routed as direct messages instead of group/topic messages.

## Best Possible Solution

Keep this as the canonical Feishu inbound classifier bug and land a Feishu-local shared discriminator based on verified topic/OpenChat metadata, with regressions that preserve true p2p direct, p2p thread, root-only quote, and card-action behavior.

## Reproduction Assessment

Yes, source-reproducible: a reported Feishu event with `chat_type: "p2p"` reaches current main with `isGroup === false` and follows direct-session routing. I did not run a live Feishu/Lark replay in this read-only review.

## Solution Assessment

No, the originally suggested broad `root_id`/`thread_id` or `oc_` prefix-only classifier is not the best fix. The safer solution needs a verified Feishu topic/OpenChat discriminator shared by dispatch and mention-forward logic, with tests proving true p2p cases remain direct.
