## Summary

Keep open: current main and v2026.6.11 still classify the reported Feishu `oc_...` event with `chat_type: "p2p"` as non-group, so the message follows direct-session routing instead of the Feishu group/topic route. This remains the canonical tracker because the same-repo fix attempt is closed, the cross-repo closing PR is still open and conflicting, and adjacent Feishu PRs do not merge the inbound classifier fix.

## What This Changes

Fix Feishu/Lark topic-group messages delivered as `p2p` so they route to the intended group/topic session instead of the direct/main session.

## Best Possible Solution

Keep this as the canonical Feishu inbound group/direct classification bug and land a Feishu-local shared classifier based on verified topic/OpenChat metadata, with regressions that preserve true p2p direct, p2p thread, and root-only quote behavior.

## Reproduction Assessment

Yes, source-reproducible: a reported Feishu event with `chat_type: "p2p"` reaches current main with `isGroup === false` and follows direct-session routing. I did not run a live Feishu/Lark replay in this read-only review.

## Solution Assessment

No, not as originally proposed: root/thread metadata or an `oc_` prefix alone conflicts with existing p2p/direct coverage. The best fix is a verified Feishu topic/OpenChat discriminator shared by dispatch and mention-forward logic, with tests for true direct cases.
