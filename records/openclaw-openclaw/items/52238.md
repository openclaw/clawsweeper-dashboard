## Summary

Keep open: current `main` and the latest release still classify the reported Feishu `oc_...` event with `chat_type: "p2p"` as non-group, and related PRs are either unmerged or only partially overlap the inbound classifier problem.

## What This Changes

The issue reports Feishu Topic Group messages with `oc_...` chat ids being classified as direct `p2p` messages, causing replies and session routing to leave the group topic.

## Best Possible Solution

Keep this as the canonical Feishu inbound classifier bug and land a Feishu-local shared classifier based on verified Topic Group/OpenChat metadata, with regressions proving true p2p direct and p2p thread cases remain direct.

## Reproduction Assessment

## Solution Assessment

No for the broad proposed heuristics. Current tests preserve true `p2p` direct-thread behavior with `root_id` and `thread_id`, so the best fix needs a verified Feishu topic/OpenChat discriminator and regression coverage for both sides.
