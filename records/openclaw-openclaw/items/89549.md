## Summary

Keep open: current main still does not provide high-confidence proof that native `sessions_spawn` carries the requester session's effective model/runtime/auth profile into child runs, while the docs say native sub-agents inherit the caller and the reporter showed accepted child runs failing later on the OpenAI route.

## What This Changes

The issue requests a fix for native `sessions_spawn(..., mode:"run")` child runs that are accepted but later fail with OpenAI OAuth missing-scope errors instead of inheriting a working requester context or failing at spawn time.

## Best Possible Solution

Make native `sessions_spawn` either inherit the requester session's effective model/runtime/auth-profile context when using caller defaults, or fail before acceptance when the child route cannot execute; keep the broader OpenAI OAuth scope problem tracked separately.
