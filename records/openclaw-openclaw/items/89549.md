## Summary

Keep open: current main and the latest release still do not prove that native `sessions_spawn` child runs inherit the requester session's effective runtime/auth context or fail before acceptance when that context cannot execute. An open requester-model inheritance PR overlaps with part of the problem, but it is unmerged, currently conflicting, and does not settle the auth-profile/runtime handoff described by this issue.

## What This Changes

The issue reports accepted `sessions_spawn(..., mode:"run")` child runs later failing on an OpenAI auth route with missing scopes instead of completing or failing synchronously.

## Best Possible Solution

Define the native subagent runtime/auth inheritance contract, then land or replace the open model-inheritance work with a focused fix that includes regression coverage and live OpenAI/Codex proof that child runs either use the intended route or fail before acceptance.

- **Require explicit child route selection:** Maintainers could require configured subagent model/auth policy before spawn instead of implicit inheritance, trading compatibility for explicit control.
