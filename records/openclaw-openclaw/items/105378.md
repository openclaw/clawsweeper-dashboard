## Summary

This is a valid, source-reproducible P1 agent workflow bug, but it must remain open because the direct closing implementation PR is still open. Current main creates adopted Claude Code sessions with a plugin-owned locked CLI model, while generic command and reply selection paths can treat that non-HTTP-catalog model as invalid and attempt a forbidden reset; the right outcome is to review and land or reject the linked fix rather than create parallel work.

## What This Changes

Preserve the plugin-owned locked `claude-cli` model when sending messages in an adopted Claude Code session.

## Best Possible Solution

Use one generic durable-session invariant: a valid owner-created locked session executes its stored backend and model unchanged in both command and reply selection, while every model-mutation path remains fail-closed; keep CLI-entrypoint discovery in its separate canonical PR and add real adopted-session plus Codex-harness regression proof.
