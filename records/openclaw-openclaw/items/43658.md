## Summary

Keep open: current main and the latest release still return a usable shared GitHub Copilot API-token cache entry before the requesting GitHub token is used, and the same-repository closing PR is still open and conflicting rather than merged.

## What This Changes

The issue reports that GitHub Copilot profile rotation reuses one cached Copilot API token across different GitHub auth profiles.

## Best Possible Solution

Refresh, land, or replace https://github.com/openclaw/openclaw/pull/43659 so the canonical Copilot token helper binds cached API tokens to the requesting GitHub credential, with regression coverage for same-profile hits, profile switches, and legacy cache entries.

## Reproduction Assessment

Yes from source inspection: current main returns a usable shared Copilot token cache before comparing or deriving anything from the incoming `githubToken`. I did not perform a live two-account Copilot quota run in this read-only review.

## Solution Assessment

Yes, credential-aware cache validation in the canonical provider-auth helper is the narrowest maintainable fix for the reported failure; the active repair candidate needs to be refreshed against current main before landing.
