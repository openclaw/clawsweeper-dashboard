## Summary

Keep open: current main and v2026.6.11 still return a usable shared GitHub Copilot API-token cache before the selected rotated GitHub credential affects token exchange, and the same-repository closing PR remains open and conflicting.

## What This Changes

The issue asks OpenClaw to make GitHub Copilot API-token caching respect the rotated auth profile instead of reusing one shared cached token across profiles.

## Best Possible Solution

Land a rebased version of https://github.com/openclaw/openclaw/pull/43659 or an equivalent narrow provider-auth fix that binds the Copilot API-token cache to the selected GitHub credential/profile and covers legacy cache entries.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: current main can return a valid shared Copilot cache entry before using the newly selected GitHub token, so a rotated profile can inherit the previous profile's API token. I did not run a live two-account Copilot rotation because that needs real credentials.

## Solution Assessment

Yes in direction: cache ownership should be scoped or validated against the selected GitHub credential in the provider-auth helper. The open linked PR is the direct candidate, but it needs rebase/merge-conflict handling before it can close the issue.
