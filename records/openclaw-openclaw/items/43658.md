- `impact:auth-provider`: The failure is in GitHub Copilot credential-to-token routing, where profile rotation can reuse the wrong provider token.

## Summary

Keep open: current main and the latest release still reuse the shared GitHub Copilot API-token cache before the selected GitHub credential affects token exchange, and the linked same-repository fix PR remains open rather than merged.

## What This Changes

The issue asks for GitHub Copilot token exchange caching to distinguish auth profiles so profile rotation after rate limiting uses the selected account's Copilot token.

## Best Possible Solution

Land or replace the linked same-repository fix after it proves fresh-install and legacy-cache behavior, binding the cached Copilot API token to the requesting GitHub credential in the provider-owned helper.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level. A focused harness can preload a valid shared Copilot token cache entry, call resolveCopilotApiToken with a different githubToken, and observe that current main returns the cached token without using the new credential.

## Solution Assessment

Yes in direction. The narrow maintainable fix belongs in the provider-owned token helper, with regression coverage for cross-profile cache misses and legacy cache refresh; the open linked PR or an equivalent replacement should be reviewed rather than queueing a second fix lane.
