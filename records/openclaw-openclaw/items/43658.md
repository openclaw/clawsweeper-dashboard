## Summary

Keep open: current main and latest release still accept the shared GitHub Copilot API-token cache before checking the requesting GitHub token, while the same-repository repair PR that closes this issue is still open and conflicting.

## What This Changes

The issue reports that GitHub Copilot auth profile rotation is ineffective because a shared cached Copilot API token is reused across distinct GitHub PAT profiles.

## Best Possible Solution

Land an account-bound cache fix in the canonical Copilot token helper with mismatch and legacy-cache regression coverage, then close this issue after the linked repair PR is merged or replaced.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction seam: load a valid cached Copilot token, call resolveCopilotApiToken with a different GitHub token, and the helper returns the cached token before using the new GitHub token; this review did not run a live multi-account Copilot scenario.

## Solution Assessment

Yes. The best fix is to bind cache hits in src/plugin-sdk/provider-auth.ts to the requesting GitHub token/profile and add focused mismatch plus legacy-cache tests, rather than adding another profile-rotation layer elsewhere.
