## Summary

Keep open: current main and the latest release still return a usable shared GitHub Copilot API-token cache before the selected GitHub credential affects token exchange, and the same-repository closing PR is still open rather than merged.

## What This Changes

The issue asks OpenClaw to make GitHub Copilot API-token caching respect the active auth profile so profile rotation after rate limits uses the newly selected account.

## Best Possible Solution

Keep this issue open until the linked PR lands or is replaced by an equivalent focused fix that binds the Copilot API-token cache to the requesting GitHub credential and covers legacy cache refresh.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current main can return a usable shared Copilot token cache entry before using the newly selected `githubToken`, so a rotated profile can receive the previous profile's Copilot API token; I did not run a live two-account Copilot quota scenario.

## Solution Assessment

Yes in direction. The narrow maintainable fix belongs in the provider-owned token helper, not in the auth-profile rotation layer; a new repair lane is not the best next step while the linked same-repository PR remains open.
