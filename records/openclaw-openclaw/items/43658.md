## Summary

Keep open: current main and the latest release still return a usable shared GitHub Copilot API-token cache before the rotated GitHub credential affects token exchange, and the same-repository closing PR is still open rather than merged.

## What This Changes

The issue asks for GitHub Copilot API-token caching to be profile-aware so profile rotation after a rate limit exchanges the newly selected profile's GitHub token instead of reusing one shared cached Copilot token.

## Best Possible Solution

Update the active provider-owned Copilot token helper in src/plugin-sdk/provider-auth.ts so cache reuse is bound to the GitHub credential/profile that produced the Copilot token, with focused regression tests for same-profile hit, cross-profile miss, and legacy cache miss; resolve the open linked PR before queuing any separate fix.

## Reproduction Assessment

Yes at source level: current main returns a valid shared Copilot token cache entry before using the newly selected params.githubToken, so a rotated profile can receive the previous profile's Copilot API token. I did not run a live two-account Copilot quota repro.

## Solution Assessment

Yes, the maintainable fix belongs at the provider-owned Copilot token exchange cache boundary, not in higher-level rotation logic. The linked PR points in the right direction but needs to be reconciled with the current active src/plugin-sdk/provider-auth.ts path before it can close this issue.
