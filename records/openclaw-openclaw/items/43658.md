## Summary

Keep open: current main and the latest release still reuse one shared GitHub Copilot API-token cache before the rotated GitHub credential can affect token exchange, and the same-repository closing PR is still open rather than merged.

## What This Changes

The issue requests that GitHub Copilot API-token caching respect the active auth profile so rate-limit rotation uses the newly selected GitHub credential.

## Best Possible Solution

Land a rebased version of https://github.com/openclaw/openclaw/pull/43659 or an equivalent narrow fix in src/plugin-sdk/provider-auth.ts, with regression coverage for same-credential cache hits, cross-credential cache misses, and legacy cache entries.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: a valid cached Copilot API token is returned from the shared cache path before the selected GitHub PAT is used, so a profile switch cannot affect token exchange until the cache misses. I did not perform a live two-account Copilot run because that needs real account credentials.

## Solution Assessment

Yes in direction: scoping or validating the provider-owned Copilot token cache by the selected GitHub credential is the narrow maintainable fix. The current linked PR should be rebased or replaced against the current SDK helper path before merge.
