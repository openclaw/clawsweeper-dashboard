## Summary

Keep open: current main and the latest release still reuse a valid shared GitHub Copilot API-token cache entry before the selected GitHub credential affects token exchange, and the same-repository closing PR remains open rather than merged.

## What This Changes

The issue requests that GitHub Copilot API-token cache entries be scoped to the selected auth profile or GitHub token so rate-limit profile rotation uses a distinct Copilot API token.

## Best Possible Solution

Bind the cached Copilot API token to the source GitHub credential or profile in the shared provider-auth helper, add regression coverage for cache bypass on profile switch, and close this issue only after the linked or replacement fix merges.

## Solution Assessment

Yes: the narrow maintainable fix belongs in the shared Copilot token helper because all runtime callers already pass the selected GitHub token. The open same-repository PR targets that class of fix, but it is not merged and must be refreshed or replaced before the issue closes.
