## Summary

Keep open: current main and the latest release still return a usable shared GitHub Copilot API-token cache before the selected GitHub credential affects token exchange, and the same-repository closing PR is still open rather than merged.

## What This Changes

The issue reports that GitHub Copilot auth-profile rotation is ineffective because all profiles reuse one cached Copilot API token.

## Best Possible Solution

The active provider-auth helper should reject a usable Copilot API-token cache unless it can prove the cache was produced by the selected GitHub credential; maintainers should land a refreshed version of the linked fix or close and replace that PR.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: seed a usable cached Copilot token, then call `resolveCopilotApiToken` with a different GitHub token and the helper returns the cache before using the selected credential. I did not run a live Copilot multi-account scenario in this read-only review.

## Solution Assessment

Yes, binding or keying the cache to the source GitHub credential in the active `src/plugin-sdk/provider-auth.ts` helper is the narrow maintainable fix. The open PR has the right direction but needs to be refreshed from stale paths to the current helper and tests.
