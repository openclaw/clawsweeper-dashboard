## Summary

Keep open: current main and the latest release still reuse one shared GitHub Copilot API-token cache before the rotated GitHub credential can affect token exchange, and the same-repository closing PR is still open rather than merged.

## What This Changes

The issue reports that GitHub Copilot profile rotation is ineffective because all profiles share one cached Copilot API token.

## Best Possible Solution

Make the provider-owned Copilot API-token cache belong to the selected GitHub credential, with regression coverage for same-credential cache hits, cross-credential cache misses, and legacy cache entries.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source inspection: a valid cached Copilot API token is returned from the shared cache path before the selected GitHub PAT is used, so a profile switch cannot affect token exchange until the cache misses.

## Solution Assessment

Yes in direction: the narrow maintainable fix is to scope or validate the cache by the selected GitHub credential in the provider-owned token helper, with focused regression tests around cache ownership.
