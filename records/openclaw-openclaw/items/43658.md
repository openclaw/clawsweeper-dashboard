## Label Justifications

- `P2`: This is a normal-priority auth-provider bug that breaks multi-profile Copilot failover for affected users without making the whole runtime unusable.
- `impact:auth-provider`: The failure is in GitHub Copilot credential/profile token routing, where profile rotation can reuse the wrong provider token.

## Summary

Keep open: current main and the latest release still reuse the shared GitHub Copilot API-token cache before the selected GitHub credential affects token exchange, and the linked same-repository fix PR is still open rather than merged.

## What This Changes

Make GitHub Copilot API-token caching distinguish the requesting GitHub credential/profile so profile rotation after rate limits exchanges and uses the newly selected account's token.

## Best Possible Solution

Keep this issue open until https://github.com/openclaw/openclaw/pull/43659 lands, is adopted, or is replaced by an equivalent focused fix that binds the Copilot API-token cache to the requesting GitHub credential and covers legacy cache refresh.
