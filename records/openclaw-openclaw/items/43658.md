## Summary

Keep open: current main and latest release still return a usable shared GitHub Copilot API-token cache entry before the selected GitHub credential affects token exchange, and the same-repository closing PR remains open rather than merged.

## What This Changes

The issue requests that GitHub Copilot API-token caching respect the selected auth profile so rotation after rate limits uses the next profile's GitHub credential.

## Best Possible Solution

Bind the cached Copilot API token to the source GitHub credential or profile in the shared provider-auth helper, add regression coverage for profile-switch cache misses, and close this issue only after the linked or replacement fix merges.

## Solution Assessment

Yes: the narrow maintainable fix belongs in the shared Copilot token helper because the active plugin and core callers already pass the selected GitHub token. The linked same-repository PR targets that class of fix, but it is not merged and needs refresh/review or replacement.
