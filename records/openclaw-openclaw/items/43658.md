## Summary

Keep open: current main and the latest release still use a single GitHub Copilot API-token cache that can be returned before the rotated GitHub credential is exchanged, and the same-repository closing PR is still open rather than merged.

## What This Changes

The issue reports that GitHub Copilot profile rotation reuses one shared cached Copilot API token instead of exchanging a token for the newly selected GitHub credential.

## Best Possible Solution

Land a rebased version of https://github.com/openclaw/openclaw/pull/43659 or an equivalent narrow provider-auth fix that binds the Copilot API-token cache to the selected GitHub credential and covers legacy unowned cache entries.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: current main can return a valid shared Copilot cache entry before using the newly selected GitHub token, so a rotated profile can inherit the previous profile's API token. I did not run a live two-account Copilot rotation because that needs real account credentials.

## Solution Assessment

Yes in direction: cache ownership should be scoped or validated against the selected GitHub credential in the provider-auth helper. The open linked PR is the direct candidate, but it needs rebase/merge-conflict handling before it can close the issue.
