## Summary

Keep open: current main and v2026.6.11 still reuse one GitHub Copilot API-token cache without tying it to the requesting GitHub credential, and the same-repository linked PR remains the active fix candidate.

## What This Changes

The issue asks for GitHub Copilot API-token caching to be scoped to the active auth profile so rate-limit rotation uses the next account's token.

## Best Possible Solution

Keep this issue open until the linked PR lands or is replaced by a focused fix that records credential ownership for the Copilot API-token cache and covers legacy cache refresh with regression tests.

## Maintainer Decision

## Reproduction Assessment

Yes. Source inspection shows current main can return a valid shared Copilot API-token cache before using the incoming GitHub credential, which reproduces the reported profile-rotation failure path without a live two-account quota run.

## Solution Assessment

Yes in direction. The narrow maintainable fix is to keep one provider-owned token helper while adding credential ownership to cache lookup/write and regression coverage; a new fix lane should wait while the linked PR remains open.
