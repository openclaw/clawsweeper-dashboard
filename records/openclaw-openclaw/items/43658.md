## Label Justifications

- `impact:auth-provider`: The failure is in GitHub Copilot credential/profile token routing, where profile rotation can reuse the wrong provider token.

## Summary

Keep open: current main and the latest release still return a valid shared GitHub Copilot API-token cache before the requesting GitHub credential affects the exchange, and the open linked repair PR should remain the implementation path until it lands, is adopted, or is replaced.

## What This Changes

The issue reports that GitHub Copilot auth-profile rotation can reuse one cached Copilot API token across distinct GitHub credentials, making rate-limit failover ineffective.

## Best Possible Solution

Keep this issue open until https://github.com/openclaw/openclaw/pull/43659 lands, is adopted, or is replaced by an equivalent focused fix that scopes the Copilot API-token cache to the requesting GitHub credential and covers legacy cache refresh.
