## Summary

Keep open: current `main` and the latest release still accept a usable shared GitHub Copilot API-token cache before the selected GitHub credential affects token exchange, and the same-repository closing PR remains open rather than merged.

## What This Changes

The issue reports that GitHub Copilot profile rotation reuses one cached Copilot API token across profiles, so rotating after a rate limit still uses the rate-limited account token.

## Best Possible Solution

Land or replace the linked fix with a provider-owned cache boundary that either records the source credential/profile or isolates the cache per profile, with regression coverage for same-token cache hits, different-token cache misses, and legacy cache entries.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source inspection: a valid Copilot API-token cache entry is returned before `params.githubToken` is used for token exchange, so a profile switch cannot invalidate the shared cache. I did not run a live two-account Copilot quota test.

## Solution Assessment

Yes: the maintainable fix belongs at the Copilot token-cache boundary, not in rate-limit rotation policy, because the cache helper currently erases which credential produced the token. The linked PR is the right class of fix but still needs normal PR review, proof, and conflict resolution before it can close this issue.
