## Summary

Keep open: current main still reuses a valid shared GitHub Copilot API-token cache entry before the selected GitHub credential affects token exchange, and the same-repository fix candidate remains open rather than merged.

## What This Changes

The issue asks OpenClaw to make GitHub Copilot API-token caching profile-aware so auth profile rotation uses the newly selected account instead of a previously cached Copilot token.

## Best Possible Solution

Bind the cached Copilot API token to the source GitHub credential or profile in the shared provider-auth helper, add regression coverage for profile-switch cache misses, and close this issue only after the linked or replacement fix merges.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: seed a usable shared Copilot cache entry, call resolveCopilotApiToken with a different githubToken, and current main returns the cache before using the new credential. I did not run a live multi-account Copilot repro in this read-only pass.

## Solution Assessment

Yes: the narrow maintainable fix belongs in the shared Copilot token helper because all active runtime callers already pass the selected GitHub token. The open same-repository PR targets that class of fix, but it is not merged and must be refreshed or replaced before this issue closes.
