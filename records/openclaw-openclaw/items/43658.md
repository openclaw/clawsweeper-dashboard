## Summary

Keep open: current main and v2026.6.11 still use one shared GitHub Copilot API-token cache before the selected rotated GitHub credential affects token exchange, and the direct same-repository fix PR remains open and conflicting rather than merged.

## What This Changes

The issue requests making GitHub Copilot profile rotation effective by preventing one profile from reusing another profile's cached Copilot API token.

## Best Possible Solution

Land a rebased version of https://github.com/openclaw/openclaw/pull/43659, or an equivalent narrow provider-auth fix, that binds Copilot API-token cache reuse to the selected GitHub credential and covers legacy cache entries.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: current main can return a valid shared Copilot cache entry before using the newly selected GitHub token, so a rotated profile can inherit the previous profile's API token. I did not run a live two-account Copilot rotation because that needs real account credentials.

## Solution Assessment

Yes in direction: cache ownership should be scoped or validated against the selected GitHub credential in the provider-auth helper. The open linked PR is the direct candidate, but it needs rebase/merge-conflict handling and proof before it can close the issue.
