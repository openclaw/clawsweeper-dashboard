## Summary

Keep open: current main and latest release still return a usable shared GitHub Copilot API-token cache before the requesting GitHub credential affects the exchange, and the open linked repair PR should own the fix path until it lands or is replaced.

## What This Changes

The issue reports that GitHub Copilot profile rotation reuses one cached Copilot API token across multiple GitHub PAT-backed profiles.

## Best Possible Solution

Keep this issue open until https://github.com/openclaw/openclaw/pull/43659 lands, is adopted, or is replaced by an equivalent focused fix that scopes the Copilot API-token cache to the requesting GitHub credential and covers legacy cache refresh.

## Reproduction Assessment

Yes from source inspection: current main returns a usable shared Copilot token cache before comparing or deriving anything from the incoming `githubToken`. I did not perform a live two-account Copilot quota run in this read-only review.

## Solution Assessment

Yes in direction: the maintainable fix is to keep one provider-owned token helper while adding credential ownership to cache lookup/write and focused regression coverage. A new repair lane is not the best next step while the linked same-repository PR is still open.
