## Summary

Keep open: current main and the latest release still return a usable shared GitHub Copilot API-token cache entry before the selected GitHub credential affects token exchange, and the same-repository fix PR remains open rather than merged.

## What This Changes

Bind GitHub Copilot API-token cache entries to the requesting GitHub credential so profile rotation after rate limits exchanges a distinct Copilot token.

## Best Possible Solution

Keep this issue open until the linked PR lands or is replaced by an equivalent focused fix that binds the Copilot API-token cache to the requesting GitHub credential and covers legacy cache refresh.

## Reproduction Assessment

Yes at source level. Current main can return a usable shared Copilot token cache entry before using the newly selected `githubToken`, so a rotated profile can receive the previous profile's Copilot API token.

## Solution Assessment

Yes in direction. The narrow maintainable fix belongs in the provider-owned token helper by binding the cache to the requesting GitHub credential; a new repair lane is not the best next step while the linked same-repository PR remains open.
