## Label Justifications

- `impact:auth-provider`: The failure concerns ChatGPT OAuth refresh-token ownership and credential routing between OpenClaw and Codex CLI.

## Summary

Keep open: current main still tells the bundled coding-agent to launch Codex with the ambient credential home, while OpenClaw's OAuth guidance documents that parallel OpenClaw and Codex CLI logins can invalidate one another. The earlier merged auth work removed external credential syncing and isolated the native harness, but did not fix this external skill launch path. ([github.com](https://github.com/openclaw/openclaw/raw/refs/heads/main/skills/coding-agent/SKILL.md))

## What This Changes

Prevent the bundled coding-agent's external Codex worker from using an ambient Codex credential home that can invalidate OpenClaw's ChatGPT OAuth session.

## Best Possible Solution

Make the bundled Codex worker path require a dedicated per-worker `CODEX_HOME`, document the one-time separate `codex login`, preflight `codex login status`, and scope the variable only to Codex worker commands so OpenClaw remains the canonical owner of its own OAuth profile.
