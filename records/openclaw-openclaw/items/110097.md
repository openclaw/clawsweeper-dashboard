## Summary

Keep this PR open for repair: the intended no-tools behavior is well-motivated, but the current head forwards `disableTools` as an unknown `agent` request parameter, so the actual in-process gateway path rejects it before the embedded runner can use it. The added unit test stops at the dispatched object, and the live capture exercises the pre-existing `modelRun` path rather than this new propagation path.

## What This Changes

The PR adds an internal `disableTools` option to plugin subagent runs and uses it to omit tool construction for memory-core Dream Diary narrative generation.

## Best Possible Solution

Keep the no-tools plugin capability, but carry the trusted flag through authenticated in-process client metadata or another explicitly internal request channel, then prove that a real plugin subagent run reaches `constructTools: false` while ordinary external `agent` requests still reject the field.
