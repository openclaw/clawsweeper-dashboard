## Summary

This PR remains necessary: current `main` gives the Mattermost probe only a request-init abort signal, while the shared guarded-fetch implementation applies its top-level timeout signal to DNS/proxy preflight. The proposed change aligns the probe with the established guard-owned deadline contract, has no supported correctness finding, and the contributor’s exact-head terminal run demonstrates the intended timeout before HTTP dispatch.

## What This Changes

The branch passes the resolved Mattermost probe deadline to `fetchWithSsrFGuard`, removes the local request-signal timer, and adds regression coverage for a stalled SSRF preflight lookup.

## Best Possible Solution

Land one guard-owned deadline by forwarding the resolved probe timeout as top-level `timeoutMs`, retain the focused preflight regression, and rebase the branch onto current `main` before merge.
