## Summary

Keep open with one blocking finding: the exporter-side zero-preservation fix is in the right layer, but the Codex completed-call path hard-codes `contextOverflowDetected: false`, so the zero-output near-budget Codex case can still be reported as explicitly not overflow.

## What This Changes

The PR preserves zero-valued model-call usage, adds terminal/context-pressure diagnostic fields, projects Codex app-server terminal facts, exports OTEL attributes, and documents/tests the new telemetry.

## Best Possible Solution

Derive Codex completed-call overflow from `attemptUsage` plus the effective context budget, or omit the field when Codex cannot classify it, then land a maintainer-approved telemetry contract for the new diagnostic and OTEL names.

## Reproduction Assessment

Yes. Source inspection of current main shows explicit zero usage can be normalized, but model-call OTEL assignment filters those zero values through the positive-only helper; I did not run a live OTLP replay in this read-only review.

## Solution Assessment

No, not yet. The exporter and diagnostic projection layers are the right owner boundary, but the current Codex completed-call implementation hard-codes a false overflow result instead of deriving or omitting it.
