## Summary

Keep open: current main still skips heartbeat active-hours time validation when `heartbeat.every` is omitted, and the live issue is already paired with an open closing PR rather than a merged fix.

## What This Changes

The issue asks OpenClaw to reject malformed heartbeat `activeHours.start`/`end` values even when `heartbeat.every` is omitted and the default cadence is used.

## Best Possible Solution

Land or replace the linked schema-focused PR so `activeHours` time validation runs whenever `activeHours` is present, with regression coverage for defaults and per-agent heartbeat configs.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction: current `HeartbeatSchema` returns before active-hours validation whenever `every` is omitted. The issue also includes a real-schema `safeParse` transcript showing malformed no-cadence windows are accepted.

## Solution Assessment

Yes, the best fix is the narrow schema repair already proposed by the linked PR: guard only duration parsing on `every`, and always validate active-hours strings when `activeHours` is present.
