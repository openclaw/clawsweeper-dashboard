## Summary

Keep open: current main still exits HeartbeatSchema validation before checking activeHours when heartbeat.every is omitted, and the latest release has the same shape. This is a narrow config-validation bug with a clear source path and no canonical duplicate or merged fix.

## What This Changes

The issue asks OpenClaw to validate heartbeat activeHours start/end strings even when heartbeat.every is omitted and the default cadence is used.

## Best Possible Solution

Validate activeHours.start and activeHours.end independently of heartbeat.every in HeartbeatSchema, add regression coverage for both defaults and per-agent heartbeat config, and leave the default cadence plus runtime active-hours semantics unchanged.

Yes, we have a high-confidence source-level reproduction: with heartbeat.every absent, current HeartbeatSchema returns before activeHours.start/end validation. The issue also provides a current-main safeParse transcript showing the bad no-every cases succeed.

## Solution Assessment

Yes, the narrowest maintainable fix is to guard only the duration parse with val.every and always run activeHours validation when activeHours is present. A runtime behavior change or new config option would be broader than needed.
