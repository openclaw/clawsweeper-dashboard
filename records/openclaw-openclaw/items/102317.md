## Summary

Keep open: current main still exits `HeartbeatSchema` validation before checking `activeHours.start` and `activeHours.end` when `heartbeat.every` is omitted, and the latest release has the same shape. This is a narrow config-validation bug with clear source evidence and no merged duplicate fix.

## What This Changes

The issue requests validation of heartbeat `activeHours` start/end time strings even when `every` is omitted and the default cadence is used.

## Best Possible Solution

Validate `activeHours.start` and `activeHours.end` whenever `activeHours` is present, while keeping duration parsing conditional on an explicit `every` value and adding focused schema regression coverage.
