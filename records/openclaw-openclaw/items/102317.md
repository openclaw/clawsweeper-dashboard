## Summary

Keep open: current main and the latest release still skip heartbeat active-hours time validation when `every` is omitted, and an open linked PR already owns the narrow fix path.

## What This Changes

The issue reports that malformed heartbeat `activeHours.start` and `activeHours.end` strings are accepted when `heartbeat.every` is omitted, causing the window to behave as always active.

## Best Possible Solution

Review and land the linked narrow schema/test PR, or replace it with an equivalent fix, then close this issue once main rejects malformed heartbeat active-hours values without an explicit cadence.
