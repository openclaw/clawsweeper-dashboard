## Summary

Keep open: current main still returns from `HeartbeatSchema.superRefine` before validating `activeHours.start` and `activeHours.end` when `heartbeat.every` is omitted. The issue is already paired with open closing PR https://github.com/openclaw/openclaw/pull/102319, so the conservative cleanup path is to keep this issue open until that PR lands or is replaced.

## What This Changes

The issue asks OpenClaw to reject malformed heartbeat active-hours time strings even when `heartbeat.every` is omitted.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/102319 or an equivalent narrow schema fix that validates active-hours start/end independently of the optional cadence, with regression coverage for defaults and per-agent heartbeat config.

## Solution Assessment

Yes. The narrowest maintainable fix is to gate only duration parsing on `every` while still validating `activeHours.start` and `activeHours.end` whenever activeHours is configured.
