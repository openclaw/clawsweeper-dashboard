## What This Changes

This PR forwards authorized agent-roster removals through the public config writer so `openclaw agents delete <id>` can persist an intentional deletion without weakening the guard against unapproved roster loss.

## System Context

OpenClaw's agent-management commands update the canonical `openclaw.json` configuration through a public writer. That writer delegates to the IO layer that preserves the agent roster and rejects accidental removals, while explicit deletion callers supply the IDs they are allowed to remove.

## Best Possible Solution
