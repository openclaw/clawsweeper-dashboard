## Label Justifications

- `P1`: A newly introduced supported continuation workflow silently mutates real external session history and can conflict with another active Claude client.
- `impact:data-loss`: The issue concerns unintended persistent modification of user-owned Claude transcript data.
- `impact:session-state`: The adopted native session incorrectly continues under the external source session identity instead of switching to a forked successor.

## Summary

Current `main` contains the intended fork-on-first-resume mechanism, but the live reproduction shows an adopted, model-locked Claude session reaches `claude --resume` without the fork flag and modifies the external transcript. No fix PR or current-main implementation resolves the regression, and the protected `maintainer` label requires the issue to remain open for explicit maintainer handling.

## What This Changes

Ensure the first turn after adopting a local Claude CLI catalog session forks the external session instead of appending to its source transcript.

## Best Possible Solution

Keep the existing one-shot fork design, preserve `forkNextResume` through the full model-locked first-turn path, and add integration coverage that observes `--fork-session`, a distinct successor session id, and a byte-unchanged source JSONL.
