## Label Justifications

- `P0`: A normal self-update can leave a previously working installation unable to launch, with recovery requiring the user to upgrade Node outside OpenClaw.
- `impact:crash-loop`: After the swap, the CLI exits at its runtime guard and the installed OpenClaw process is unavailable on the existing Node runtime.
- `impact:ux-release-blocker`: A community user can be blocked during update with no in-product recovery path because the replacement CLI cannot start to guide or repair the installation.

## Summary

This remains a concrete update-safety regression: current main can parse the newer multi-clause Node engine range for future updater runs, but that cannot protect users executing the already-shipped 2026.6.11 updater, which can swap in an unusable release. The protected `maintainer` label also requires explicit maintainer handling.

## What This Changes

Prevent older OpenClaw self-updaters from replacing a runnable global npm installation with a release that cannot start on the installed Node runtime.

## Best Possible Solution

Ship a candidate-owned preinstall Node guard that rejects unsupported runtimes before the staged npm swap, emits a clear upgrade instruction, and is proven on affected Windows/macOS versions plus supported Node floors without changing the updater transaction.

## Reproduction Assessment

Yes. The exact released-version path reproduced in repository Parallels npm update smoke on Windows Node 24.14.0 and macOS Node 25.2.1, with the same stage-swap-runtime-guard sequence in both attempts.

## Solution Assessment

Yes. Candidate-package preinstall enforcement is the narrowest fix that can protect already-shipped older updater code; changing only current updater parsing cannot repair those installed binaries.
