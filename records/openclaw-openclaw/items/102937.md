## Summary

Keep open: current main still has a source-reproducible config precedence bug where `messagePrefix` does not receive channel/account context, while adjacent `responsePrefix` and `ackReaction` paths do. The remaining work is narrow and belongs in the existing agents/WhatsApp inbound prefix path rather than a cleanup close.

## What This Changes

The issue requests that message prefix resolution honor existing channel-level and account-level `messagePrefix` configuration overrides instead of only the global value or caller-supplied override.

## Best Possible Solution

Add account-to-channel-to-global `messagePrefix` resolution for the existing inbound prefix path, pass the needed channel/account context, and cover empty-string, account, channel, and legacy global behavior without adding a new config option.
