## Label Justifications

- `P1`: The issue affects real user-facing channel workflows and has recent production-style reports of internal assistant text reaching external chats.
- `impact:security`: Leaked reasoning, tool traces, and internal planning can expose sensitive operational details to unintended channel recipients.
- `impact:message-loss`: The reported failure is incorrect channel message delivery: extra internal messages are delivered as if they were intentional replies.
- `impact:session-state`: Several reports and current code paths involve assistant text being stored or accumulated in session/delivery state before becoming visible.

## Summary

Keep open: current main has useful partial guards for commentary-phase and message-tool-only delivery, but the central channel-leak problem is still source-reproducible through automatic visible-reply paths, pre-tool block-reply flushing, and cron delivery payload selection; two open fork PRs still use closing syntax and need maintainer review rather than issue cleanup.

## What This Changes

The issue asks OpenClaw to keep assistant text produced before or between tool calls internal instead of delivering it as visible messages in Slack, Telegram, iMessage, Discord, WhatsApp, Feishu, webchat, or similar channels.

## Best Possible Solution

Keep this as the canonical product bug until maintainers choose a compatibility-safe delivery policy, review or close the linked implementation PRs, and add regression coverage for unphased pre-tool/inter-tool text plus cron/isolated delivery reasoning payloads.

## Reproduction Assessment

Yes, there is a high-confidence source-level reproduction path: automatic visible delivery plus text_end block replies can flush pre-tool assistant text when tool execution starts. I did not run a live Slack/Telegram/Discord reproduction in this read-only review.

## Solution Assessment

No, closing this issue is not the best solution yet. Current main has partial commentary-phase and message-tool-only safeguards, but the remaining default-delivery and cron paths need a maintainer-approved policy and targeted regression coverage.
