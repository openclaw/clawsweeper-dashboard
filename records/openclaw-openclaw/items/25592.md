## Label Justifications

- `P1`: Multiple reporters show live channel workflows receiving internal assistant text, including production Discord, Telegram, Slack, and WhatsApp-style delivery.
- `impact:message-loss`: The failure produces extra or wrongly routed channel-visible messages during tool-heavy turns.
- `impact:session-state`: Several comments show the leaked text can already be persisted in assistant/session history before delivery.
- `impact:security`: The leaked content can expose internal planning, raw tool payloads, operational traces, and private workflow context in external channels.
- `maturity:stable`: The issue affects Discord and Gateway delivery behavior, and the maturity scorecard lists Discord and Gateway runtime as M4 Stable.

## Summary

Keep open: current `main` still has source-level paths where non-final assistant text can become visible in channel delivery, and linked PRs remain partial, open, conflicting, or proof-gated rather than a merged canonical fix.

## What This Changes

The issue asks OpenClaw to stop routing intermediate assistant text between tool calls to Slack, Telegram, iMessage, Discord, WhatsApp, and similar messaging channels.

## Best Possible Solution

Keep this as the canonical bug and land a generic delivery-boundary policy that preserves final/commentary phase safeguards, explicit message-tool delivery, and compatibility for existing automatic replies with clear tests for direct chats, room events, cron announce delivery, and multi-tool turns.

## Reproduction Assessment

Yes at source level: current `main` still allows automatic visible delivery for direct/source chats and has tests that deliberately flush buffered pre-tool assistant text before tool execution. I did not run a live channel repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the compatibility policy. The best fix is not a channel-specific filter; it should be a generic terminal-delivery rule with regression coverage for unphased pre-tool text, message-tool-only turns, cron announce payloads, and explicit final replies.
