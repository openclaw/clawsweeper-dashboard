## Summary

Keep open: current main has partial commentary/reasoning suppression, but source inspection and the issue discussion still show automatic channel delivery paths for ordinary or unphased assistant text, plus unmerged closing PRs that have not resolved the canonical issue.

## What This Changes

The issue asks OpenClaw to stop sending assistant text produced between tool calls to messaging channels unless it is final, intentional, or explicitly sent.

## Best Possible Solution

Keep #25592 as the canonical tracker and land an upgrade-aware delivery-boundary fix that covers automatic direct chats, message_tool_only turns, cron announce, explicit message-tool sends, and phased plus unphased provider output.

- **Ship opt-in mitigation only:** Expose a config or final-tag opt-in as an immediate mitigation while leaving #25592 open for the default policy decision.
