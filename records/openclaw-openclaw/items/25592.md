## Summary

Keep open: current main has useful phase/commentary and message-tool-only safeguards, but the broad leak class is still source-reproducible. Automatic source replies remain the default outside opted-in message-tool-only modes, the subscriber still has a tested path that flushes ordinary unphased pre-tool text as a block reply, and cron announce selection can preserve multiple text payloads without reasoning/commentary metadata.

## What This Changes

The issue requests that intermediate assistant text between tool calls stay private and only final or explicit message-tool output reach messaging channels.

## Best Possible Solution

Keep the issue open until maintainers choose the durable source-reply policy and land tested guards for unphased pre/inter-tool text, message-tool-only delivery, cron announce delivery, and transient progress/commentary boundaries.

## Reproduction Assessment

Yes for source-level reproduction: current tests still assert buffered unphased assistant text is flushed to onBlockReply before tool execution, while docs and source keep automatic source replies as a default path.

## Solution Assessment

No current-main solution is complete: phase/commentary guards and message-tool-only suppression are useful partial fixes, but the remaining source-reply and cron paths need a policy-backed fix with upgrade proof.
