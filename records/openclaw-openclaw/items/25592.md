## Summary

Keep open: current main has partial safeguards for commentary/final-answer phases, but source, docs, tests, and fresh field reports show the central cross-channel leak remains unresolved and compatibility-sensitive.

## What This Changes

The issue reports that intermediate assistant text between tool calls is delivered to user-facing messaging channels instead of remaining internal.

## Best Possible Solution

Keep this as the canonical product bug and choose a cross-channel final-only/message-tool policy that preserves a deliberate compatibility path, then add regression coverage for phased and unphased pre-tool/inter-tool text across streaming and final assembly.

## Reproduction Assessment

Yes, at source level: direct chats still default to automatic delivery, and unphased assistant chunks can still be appended to the block-reply path when automatic delivery is active. I did not run a live channel repro in this read-only cleanup review.

## Solution Assessment

No current main is not a complete solution; it contains useful final-answer/commentary safeguards, but the remaining fix needs a maintainer decision on default visible-reply semantics and compatibility for existing bare-text DM workflows.
