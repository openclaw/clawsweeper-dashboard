## Summary

Keep open: current main has important phase-aware suppression, but source chats still default to automatic visible replies and some block/cron delivery paths can still expose intermediate assistant text before a final/silent outcome; this remains the canonical cross-channel leak bug.

## What This Changes

The issue asks OpenClaw to prevent assistant text produced before or between tool calls from being delivered as visible messages in external channels.

## Best Possible Solution

Keep this issue as the canonical channel-leak bug, make a maintainer decision on automatic versus explicit source-reply delivery, then land a unified fix with regression coverage for streaming, final assembly, cron announce delivery, and message-tool-only turns.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should external source chats keep automatic bare-text visible replies by default, or should OpenClaw require explicit message-tool/final-only delivery for user-visible output on channel sessions?

Rationale: The code choice trades a security-sensitive internal-text leak against compatibility for existing users and models that rely on automatic final text replies, so automation should not choose the permanent policy alone.

Likely owner: Peter Steinberger

Owner reason: Peter has the strongest sampled history across the reply dispatcher and commentary suppression paths that define this product boundary.

Owner confidence: medium

Options:

- **Adopt explicit delivery with migration (recommended):** Make external channel/session output explicit or final-only by default, preserve a documented opt-out or migration path for deployments that need legacy automatic bare-text replies, and cover cron plus streaming paths.
- **Keep automatic default with stronger guards:** Preserve compatibility by default while adding narrower suppression for known commentary, reasoning, NO_REPLY, and pre-tool block shapes, accepting that some malformed bare text may still require follow-up fixes.
- **Opt-in only for now:** Leave the existing automatic default, improve docs and diagnostics, and unblock only users who configure message-tool-only or final-tag enforcement.

## Reproduction Assessment

Yes at source level, but not with a live current-main channel run. Current main still has automatic visible reply defaults, immediate block dispatch before later silent finals, and cron payload selection that preserves multiple successful text payloads.

## Solution Assessment

No single proposed path is proven best yet. The maintainable solution needs a maintainer-owned delivery policy plus shared suppression across subscriber, dispatcher, cron, and channel delivery paths rather than another one-channel workaround.
