## Summary

Keep open: current main and the latest release still have source-provable automatic delivery paths for ordinary assistant text, while the landed mitigations only cover narrower commentary/Anthropic/phase-aware cases and related PRs remain partial or unmerged.

## What This Changes

Requests that assistant text produced before or between tool calls stay internal instead of being delivered to messaging channels unless it is an intentional final reply or explicit message-tool send.

## Best Possible Solution

Choose a generic channel-delivery policy for tool-using turns, then add focused regression coverage across source replies, message-tool-only mode, cron announce delivery, NO_REPLY turns, and phase-aware provider output without relying on provider-specific filters alone.

## Reproduction Assessment

Yes at source level: current main still defaults ordinary source replies to automatic delivery and tests preserve buffered pre-tool text flushing, with cron payload selection also lacking reasoning filtering. I did not run a live Slack, Telegram, Discord, or Feishu reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the compatibility policy: explicit message-tool-only delivery is the clean boundary, but unconditional default changes can break existing bare-text reply setups. The best fix is a generic delivery-boundary decision plus regression tests, not a channel-specific sanitizer.
