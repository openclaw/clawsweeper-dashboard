## Summary

Keep open: current main has useful commentary-phase and message-tool-only mitigations, but ordinary automatic delivery and cron announce paths can still surface intermediate assistant text, and linked implementation PRs remain open or unmerged.

## What This Changes

The issue requests that internal or intermediate assistant text between tool calls stay out of messaging channels unless it is an intentional final or message-tool send.

## Best Possible Solution

Keep #25592 as the canonical issue, decide the automatic-versus-explicit channel-delivery policy, and land a focused generic fix with regression tests plus real affected-channel proof.

## Reproduction Assessment

Yes at source level: current main still defaults ordinary direct source delivery to automatic, flushes unphased text before tool execution, and preserves multiple cron delivery payloads; no live channel repro was run in this read-only review.

## Solution Assessment

The best fix is a generic delivery-boundary decision across embedded-agent and cron paths, not a one-channel filter or a partial NO_REPLY-only repair.
