## Summary

Keep open: current main and the latest release include useful partial safeguards, but source and tests still preserve automatic source-reply delivery and a visible buffered pre-tool text flush path, and open linked implementation PRs still claim this issue.

## What This Changes

Reports that intermediate assistant text produced before or between tool calls is being automatically delivered to messaging channels instead of staying internal until the final intentional reply.

## Best Possible Solution

Keep this as the canonical cross-channel leak bug while maintainers choose the source-reply policy and land, replace, or close the linked implementation PRs with regression coverage for unphased pre/inter-tool text, phase separation, NO_REPLY, cron, and direct/chat channel paths.

## Reproduction Assessment

Yes at source level: current code and tests show automatic source-reply delivery and a buffered pre-tool text chunk being flushed visibly before tool execution. I did not run a live channel repro in this read-only review.

## Solution Assessment

Unclear as a final product decision: current commentary-phase suppression is necessary but not sufficient. The best fix needs maintainer approval for automatic direct replies versus message-tool-only or final-only delivery, with compatibility proof.
