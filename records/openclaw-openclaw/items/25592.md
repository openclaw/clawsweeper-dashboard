## Summary

Keep open. Current main has important commentary/final-answer guards, but source and tests still preserve no-phase/automatic multi-segment assistant text delivery across tool boundaries, and the live related PRs are partial or adjacent rather than merged replacements.

## What This Changes

The issue requests suppressing intermediate assistant text between tool calls from being delivered to messaging channels while preserving intentional final or message-tool output.

## Best Possible Solution

Resolve the remaining delivery-policy gap at the shared embedded payload or source-reply boundary, with tests proving both phase-tagged and phase-less tool-using turns across interactive and cron delivery.

Options:

- **Add Opt-In Final-Only Trim (recommended):** Introduce a narrow final-only or last-segment delivery policy at embedded payload construction so operators can suppress interim no-phase segments without globally disabling automatic replies.
- **Change Defaults To Explicit Sends:** Move affected messaging-channel turns toward message-tool-only delivery by default, accepting a larger compatibility change for stronger leakage prevention.
- **Keep Automatic Default And Patch Cases:** Preserve automatic bare-text delivery and continue landing targeted leak fixes for commentary, silent final, and cron announce variants as they are proven.

No final fix is on main yet. Partial commentary/final-answer guards are useful, but the remaining no-phase fallback and automatic delivery policy need a shared solution rather than another channel-specific filter.
