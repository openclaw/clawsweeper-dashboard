## Summary

Keep open: current main contains useful partial safeguards for commentary/phased output, but the central channel delivery-boundary bug remains source-reproducible and needs a maintainer policy/security decision before a safe fix can land.

## What This Changes

The issue asks OpenClaw to prevent assistant text produced before or between tool calls from being delivered to messaging channels unless it is intentional final or message-tool output.

## Best Possible Solution

Keep this as the canonical product/security bug, choose a channel-delivery policy that handles compatibility explicitly, and add regression coverage for unphased pre/inter-tool text, message-tool-only turns, cron announce delivery, and reasoning/commentary leak paths.

Yes, at source level. Current main still has automatic visible-reply paths, tests that flush buffered pre-tool text, and cron helpers that preserve multiple successful deliverable payloads; I did not run a live channel repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the compatibility policy. The best fix is not a one-off sanitizer; it should define when channel text is final or private and then prove upgrade-safe behavior across sibling delivery paths.
