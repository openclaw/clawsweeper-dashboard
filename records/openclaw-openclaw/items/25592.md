## Summary

Keep open: current main has important partial guards, but the source still allows automatic visible replies and still has source-reproducible paths where unphased pre-tool/inter-tool assistant text can become block replies; two linked closing PRs are open but conflicting and need maintainer review rather than issue cleanup.

## What This Changes

The issue asks OpenClaw to prevent intermediate assistant text between tool calls from being routed as visible messages to Slack, Telegram, Discord, iMessage, Feishu, WebChat, and similar channels.

## Best Possible Solution

Keep this as the canonical bug while maintainers choose a compatibility-safe delivery policy, preserve the existing commentary/final-answer guards, and land or replace focused fixes with regression coverage for unphased pre-tool/inter-tool text and cron reasoning payloads.

## Reproduction Assessment

Yes, source-reproducible: current tests and source show unphased assistant text can be flushed as block replies before or around tool execution when automatic delivery is active. I did not run a live channel repro in this read-only review.

## Solution Assessment

Unclear: the issue is real, but the best fix requires a maintainer decision on automatic reply compatibility versus message-tool/final-only delivery. A narrow patch should preserve existing commentary-phase suppression and add coverage for unphased text and cron payload metadata.
