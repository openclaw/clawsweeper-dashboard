## Summary

Keep open: current main has several partial leak guards, but ordinary automatic source replies, unphased assistant text, pre-tool block flushing, and cron payload selection still leave the reported channel-leak class source-reproducible. The issue also has recent production reports and compatibility-sensitive policy choices around direct-chat delivery, so it is not safe maintainer cleanup.

## What This Changes

The issue asks OpenClaw to stop routing intermediate assistant text produced before or between tool calls to user-visible messaging channels.

## Best Possible Solution

Keep this issue as the canonical bug, choose a compatibility-aware source-reply policy for channel sessions, and land focused regression coverage across direct chats, group/channel delivery, cron announce delivery, streaming-off behavior, and reasoning/commentary metadata.

## Reproduction Assessment

Yes, there is a high-confidence source-level reproduction path: automatic source replies plus unphased block-reply chunks or cron deliverable payload selection can still emit intermediate assistant text. I did not run a live channel repro in this read-only review.

## Solution Assessment

No, closing or queueing another autonomous fix is not the best next step. The best path is a maintainer policy decision for source-reply delivery semantics, followed by one focused implementation that preserves existing explicit message-tool and progress/commentary safeguards.
