## Summary

Keep open: current main has important commentary/reasoning guards, but automatic source-reply delivery and buffered pre-tool block delivery remain current behavior, cron/direct-channel variants still have source-level risk, and linked implementation PRs are open/conflicting rather than merged fixes.

## What This Changes

The issue asks OpenClaw to stop sending assistant narration, reasoning, or commentary text produced before or between tool calls to external messaging channels.

## Best Possible Solution

Keep this issue as the canonical product/security bug until maintainers choose the external-channel delivery policy and land regression-tested coverage across automatic source replies, block streaming, message-tool-only turns, and cron announce delivery.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should external channel sessions keep automatic bare-text replies by default, or should they move to an explicit message-tool or final-only delivery policy to prevent inter-tool text leaks?

Rationale: Current code and docs preserve automatic visible replies for normal direct/group/channel turns, while the safest leak fix likely changes compatibility-sensitive channel delivery behavior.

Likely owner: Peter Steinberger

Owner reason: Current-file blame and recent commentary leak fixes make this the clearest routing owner for the delivery-policy decision.

Owner confidence: high

Options:

- **Change external channels to explicit delivery (recommended):** Move external source replies toward message-tool-only or final-only semantics with migration, doctor, docs, and proof coverage so internal text does not reach chats by default.
- **Keep compatibility and add opt-in guards:** Keep automatic replies as the default, but land targeted guards such as enforce-final or stricter verbose-off/message-tool-only handling for users who opt in.
- **Split by surface:** Apply explicit delivery to shared rooms and cron first while preserving direct-chat automatic replies until a separate migration is ready.

## Reproduction Assessment

Yes. Current source and tests show automatic delivery remains valid for normal source replies, and a block-reply regression test still flushes buffered pre-tool assistant text as a visible block reply before tool execution.

## Solution Assessment

Unclear as a product choice. The safest technical fix is explicit or final-only delivery for external channels, but maintainers need to decide how much automatic bare-text compatibility to preserve and how to migrate affected users.
