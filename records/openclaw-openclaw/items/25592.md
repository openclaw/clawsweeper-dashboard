## Summary

Keep open: current main has important partial safeguards for commentary-phase, Anthropic pre-tool, and silent-reply subsets, but automatic source-reply defaults, unphased pre-tool text flushing, and cron delivery payload selection still leave the reported cross-channel leak class unresolved.

## What This Changes

The issue asks OpenClaw to stop routing assistant text produced between tool calls to user-facing messaging channels unless it is an intentional final or explicit message-tool send.

## Best Possible Solution

Keep this as the canonical delivery-boundary bug and choose an upgrade-safe external-channel policy, then land a generic final-only/message-tool-only guard with regression coverage for unphased inter-tool text, message-tool-plus-private-final turns, NO_REPLY suppression, reasoning payloads, and cron delivery.
