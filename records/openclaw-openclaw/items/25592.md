- `P1`: The issue reports recurring production leaks into user-facing messaging workflows across multiple channels, but it is not a crash loop or complete runtime outage.

## Summary

Keep open: current main has useful phase/final-answer guards, but automatic source delivery and cron announce payload selection can still expose unphased or internal assistant text to user-facing channels, and the open closing candidates are unmerged/conflicting rather than proven replacements.

## What This Changes

Requests suppressing intermediate assistant text between tool calls so messaging channels receive only intentional final or message-tool output.

## Best Possible Solution

Keep this issue as the canonical bug until maintainers choose a compatibility-safe source-reply policy and land regression-covered guards across embedded streaming, final payload assembly, cron announce delivery, and message-tool-only paths.

Rationale: Current docs and tests intentionally preserve automatic final text for compatibility, while the issue asks for stronger explicit-send semantics that would change existing channel behavior.

Likely owner: steipete

Owner confidence: high

Options:

- **Preserve defaults with stronger guards (recommended):** Keep automatic final replies compatible, but suppress unphased inter-tool/internal text and harden cron/message-tool delivery with focused tests.
- **Move defaults to explicit send:** Make source-channel visible output message-tool-only or final-tag-only by default, accepting upgrade risk and migration/docs work.
- **Ship opt-in escape hatches only:** Land configurable final-tag or verbose-off mitigations without changing the default leak-prone automatic paths.
