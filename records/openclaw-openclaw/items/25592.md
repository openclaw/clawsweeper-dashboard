## Summary

Keep open. Current main and the latest release still have a source-backed path where phase-less or no-canonical-final assistant text falls back to every accumulated assistant segment, so the central cross-channel leak is not fixed; the next step is a maintainer delivery-policy decision, not another cleanup close.

## What This Changes

The issue reports that assistant text produced between tool calls can be delivered as visible messaging-channel output instead of staying internal until the final intentional reply.

## Best Possible Solution

Define a payload-level delivery policy that prevents no-canonical-final interim prose from becoming external messages across interactive and cron paths, while preserving or explicitly migrating the documented automatic final-reply contract.
