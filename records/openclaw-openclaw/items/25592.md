## Label Justifications

- `P1`: Multiple real channel reports show internal assistant text leaking into active user-facing messaging workflows across Slack, Telegram, Discord, WhatsApp, and Feishu.
- `impact:security`: Leaked intermediate text can expose internal planning, tool syntax, reasoning, private context, and operational details to channel recipients.
- `impact:message-loss`: The defect creates unintended duplicate or misrouted channel messages and can mix private intermediate text with intended final replies.
- `maturity:stable`: The affected channel delivery behavior includes Discord, which is scored M4 Stable in qa/maturity-scores.yaml and taxonomy.yaml.

## Summary

Keep open: current main and v2026.6.11 have partial mitigations, but automatic source delivery, unphased assistant text buffering, and cron/direct payload selection can still route intermediate/plain assistant text to channels; the remaining fix needs maintainer security and compatibility direction.

## What This Changes

The issue asks OpenClaw to stop routing intermediate assistant text between tool calls to Slack, iMessage, Telegram, Discord, WhatsApp, Feishu, and similar messaging channels.

## Best Possible Solution

Keep #25592 canonical while maintainers choose the source/direct delivery policy and land a generic channel-agnostic suppression rule with regression coverage for automatic, message_tool_only, cron announce, reasoning/commentary, message-tool sends, abort, and yield paths.

## Reproduction Assessment

Yes at source level: current default delivery tests, embedded subscription logic, payload assembly, cron payload selection, and field reports provide a high-confidence reproduction model, but no live channel run was performed in this read-only review.

## Solution Assessment

No complete best fix is landed; the safest direction is a generic delivery-boundary policy that suppresses reasoning/commentary/inter-tool text while preserving intentional final or message-tool sends under a maintainer-approved compatibility plan.
