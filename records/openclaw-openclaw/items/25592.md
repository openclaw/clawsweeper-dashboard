## Summary

Keep open: current main has useful commentary-phase and message-tool-only safeguards, but it still preserves automatic visible replies and a tested pre-tool block flush path for unphased assistant text, so the central channel leak is not fully fixed.

## What This Changes

The issue asks OpenClaw to keep assistant text produced before or between tool calls out of user-facing messaging channels unless it is an intentional final or explicit message-tool reply.

## Best Possible Solution

Keep this as the canonical cross-channel delivery bug, review the linked narrow PRs, and choose a compatibility-safe final-only or message-tool-only policy for automatic source replies with regression coverage across direct, group/channel, streaming, final assembly, and cron delivery paths.

## Reproduction Assessment

Yes. Current-main source and tests show automatic visible replies remain the default for ordinary source chats and that unphased buffered text is flushed before tool execution on text_end block-reply channels.

## Solution Assessment

No single current fix is clearly the best final solution yet. Main has important partial guards, but the remaining direct/source reply default and unphased pre-tool text behavior need a maintainer compatibility decision before a broad fix lands.
