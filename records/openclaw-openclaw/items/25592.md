## Summary

Keep open: current main has partial commentary and reasoning guards, but it still defaults source replies to automatic delivery and still allows unphased block text onto the visible reply path unless message-tool-only delivery has already been used. Recent field reports and open partial PRs show the cross-channel leak class is not fully resolved.

## What This Changes

The issue asks OpenClaw to prevent assistant text produced before or between tool calls from being delivered as visible messaging-channel replies unless it is an intentional final reply or explicit message-tool send.

## Best Possible Solution

Keep this as the canonical product bug until maintainers choose and verify a direct-chat/final-only delivery policy across auto-reply, embedded subscriber, cron, WebChat/history, and channel adapters while preserving the existing opt-in message-tool-only escape hatch.

## Reproduction Assessment

Yes, source-reproducible: current main still resolves ordinary source replies to automatic delivery and routes unphased block text to assistantTexts/onBlockReply when not already in message-tool-only delivery. I did not run a live Slack/Telegram/Discord repro in this read-only review.

## Solution Assessment

No, current main is not the full solution: it has useful commentary-phase and provider-specific guards, but the automatic-delivery policy and unphased block path remain. The safest fix needs a maintainer policy choice plus regression coverage across the visible reply, cron, WebChat/history, and channel delivery surfaces.
