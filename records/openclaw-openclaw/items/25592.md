## Summary

Keep open: current main and v2026.6.11 still default channel/direct source replies to automatic and preserve block/cron delivery paths that can surface unphased inter-tool text; current commentary suppression is partial and the candidate PRs are open/unmerged.

## What This Changes

Prevent assistant text produced between tool calls or internal reasoning/commentary from being delivered as user-visible messages on external messaging channels.

## Best Possible Solution

Adopt one maintainer-approved external-source delivery policy, preferably explicit message-tool/final-only channel output with an upgrade path for existing automatic replies, and cover direct/group/channel/cron plus unphased provider cases before closing.

## Maintainer Decision

Kind: product_direction

Question: Should external source chats keep automatic bare-text replies by default, or should channel-visible turns require explicit message-tool/final-only delivery?

Rationale: Automatic bare-text delivery is shipped and compatibility-sensitive, but it is also the path that lets internal reasoning or inter-tool narration escape to real channels.

Likely owner: Josh Lehman

Owner reason: Josh carried the current source-reply and agent delivery surfaces most directly in recent main history.

Owner confidence: medium

Options:

- **Make explicit delivery the channel default (recommended):** Treat bare assistant text as internal for external channels and require message-tool or final-only output, with migration/docs for users who relied on automatic replies.
- **Keep automatic default with narrower guards:** Preserve compatibility and keep adding provider/phase-specific leak suppression, accepting a larger ongoing edge-case surface.
- **Add an opt-in strict mode first:** Ship strict delivery as an existing-config or documented opt-in mode while maintainers collect upgrade proof before changing defaults.
