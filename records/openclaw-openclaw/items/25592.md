## Summary

Keep open: current main still has source-reproducible automatic delivery paths for non-final assistant text, cron announce delivery does not carry/filter reasoning metadata, and two live unmerged PRs still claim to fix this issue.

## What This Changes

The issue asks OpenClaw to stop assistant text produced before or between tool calls from being routed as visible channel messages unless it is an intentional final reply or explicit message-tool send.

## Best Possible Solution

Keep this as the canonical product bug, review or reject the two open implementation PRs, then land a maintainer-approved delivery policy with regression coverage for automatic source replies, unphased inter-tool text, and cron announce payloads.
