## Label Justifications

- `P1`: The issue reports recurring real-user channel leaks across production messaging workflows, including current Discord, Telegram, Feishu/WebChat, and cron variants.
- `impact:security`: Internal reasoning, tool-like payloads, and operational text can be exposed to external messaging channels and customer-facing conversations.

## Summary

Keep open: current main has important partial safeguards for phased/commentary text and final-answer payload assembly, but the broader channel-delivery leak remains a live canonical bug with recent Discord, Telegram, Feishu/WebChat, and cron evidence plus compatibility-sensitive policy questions around automatic visible replies.

## What This Changes

The issue asks OpenClaw to prevent assistant text emitted before or between tool calls from being delivered as visible messages to Slack, iMessage, Telegram, Discord, Feishu, WebChat, and similar messaging channels.

## Best Possible Solution

Keep this issue open as the canonical channel-delivery bug and have maintainers choose a direct-chat-safe final-only or explicit-send policy, then land focused fixes with regression coverage across streaming, final payload assembly, cron announce delivery, and message-tool-only runs.

## Reproduction Assessment

Yes at source level: current main still has automatic source-reply paths and tests that pin automatic defaults, while the issue thread contains recent channel-specific reports. I did not run a live messaging-channel repro in this read-only review.

## Solution Assessment

Unclear as a single code change: current main has partial, well-targeted fixes, but the best complete solution still depends on a maintainer decision about automatic visible replies versus explicit/message-tool-only delivery for direct chats and autonomous delivery paths.
