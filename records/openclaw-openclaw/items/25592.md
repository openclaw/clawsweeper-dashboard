## Label Justifications

- `P1`: The issue describes a live cross-channel workflow where internal assistant text reaches real messaging users across Slack, Telegram, Discord, WhatsApp, Feishu, and similar channels.
- `impact:security`: Leaked tool payloads, internal planning, and operational text can expose sensitive implementation details or private workflow context to unintended channel audiences.
- `impact:message-loss`: The bug causes extra unintended channel messages and confusing duplicate/final-looking replies during tool-heavy turns.
- `impact:session-state`: Several reports trace the leak to assistant transcript content and phase metadata being stored or replayed into visible delivery paths.

## Summary

Keep open: current main and the latest release have important commentary/reasoning mitigations, but source inspection still shows automatic source delivery and cron payload-selection paths that can expose unphased/intermediate assistant text; open linked PRs also still claim partial fixes for this issue.

## What This Changes

The issue asks OpenClaw to stop routing intermediate assistant text between tool calls to user-visible messaging channels.

## Best Possible Solution

Keep this as the canonical bug and land a maintainer-approved delivery policy that suppresses internal/unphased text across automatic source replies and cron announce delivery while preserving explicit message-tool sends and tested compatibility behavior.

## Reproduction Assessment

Yes, at source level: current main still defaults ordinary source replies to automatic delivery and preserves unphased assistant text, while cron delivery selection does not carry reasoning/commentary flags. I did not run a live Slack, Telegram, or Discord repro in this read-only pass.

## Solution Assessment

No, the current main implementation is only a partial mitigation because commentary-phase and reasoning guards do not cover unphased text or the cron announce selection path. The best fix needs a maintainer-approved policy for default source delivery, explicit message-tool behavior, or safe opt-in final-only enforcement with regression coverage.
