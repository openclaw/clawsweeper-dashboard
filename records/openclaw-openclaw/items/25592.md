## Summary

Keep open: current main has important commentary-phase and message-tool-only guards, but source, tests, docs, and recent field reports still show automatic/block/cron delivery paths where intermediate or reasoning text can become external channel output. The remaining fix is also policy-sensitive because changing source-chat delivery defaults could break deployments that rely on bare assistant replies.

## What This Changes

The issue asks OpenClaw to prevent intermediate assistant text between tool calls from being routed as visible messages to messaging channels.

## Best Possible Solution

Keep this as the canonical product/security bug until maintainers choose the source-chat delivery policy, land or close the linked implementation candidates, and add regression coverage for unphased pre-tool text, post-message-tool text, and cron reasoning payloads.
