## Summary

Keep open: current main has useful partial guards for commentary/final-answer text, but it has not solved the central cross-channel leak. Source, tests, docs, and issue discussion still preserve automatic visible replies in normal direct/group/channel paths and leave cron/message delivery variants that need a maintainer policy decision and broader proof.

## What This Changes

The issue asks OpenClaw to prevent intermediate assistant text between tool calls from being delivered to messaging channels unless it is an intentional final reply or explicit message-tool send.

## Best Possible Solution

Keep this issue as the canonical bug, choose a safe external-channel visible-reply policy, then land one generic delivery-boundary fix with regression coverage for direct, group/channel, cron announce, message-tool, and reasoning/commentary variants.
