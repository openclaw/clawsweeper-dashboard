## Summary

Keep open: current main and v2026.6.11 still leave source-provable leak paths through automatic source replies, unphased block reply emission, and cron delivery payload selection; this issue remains the canonical tracker for the broader channel-delivery boundary bug.

## What This Changes

The issue reports intermediate assistant text between tool calls being delivered visibly to messaging channels instead of remaining internal.

## Best Possible Solution

Keep this as the canonical product bug, review or close the linked partial PRs, choose a generic delivery-boundary policy for direct/source and cron paths, and add regressions for unphased inter-tool text, message-tool-only turns, reasoning placeholders, and cron announce delivery.

## Reproduction Assessment

Yes from source inspection: automatic source delivery still exists by default, unphased assistant text can be emitted as block replies, and cron announce delivery drops isReasoning before selecting deliverable payloads. I did not run a live channel repro in this read-only review.

## Solution Assessment

No to closing or to a narrow channel-specific filter: the best solution is a maintainer-approved generic delivery-boundary policy with upgrade-safe handling for existing automatic reply setups and focused regression coverage across interactive and cron paths.
