## Label Justifications

- `P1`: The issue reports recurring leakage of internal assistant/tool narration into real messaging channels, affecting active channel workflows without making the whole runtime unusable.
- `impact:security`: Internal planning text, command-like payloads, and operational details can be exposed to external chat recipients.
- `impact:message-loss`: The affected delivery path sends unintended extra channel messages and can obscure the single intentional final reply.
- `impact:session-state`: Several reproductions show leaked commentary or duplicated text persisted in session history before later channel delivery.

## Summary

Keep open: current main has important partial leak guards, but the central cross-channel problem is not fully solved because automatic visible replies remain the documented default, unphased block text can still be flushed before tool execution, and cron announce delivery still lacks reasoning/commentary metadata in its deliverable payload contract.

## What This Changes

The issue asks OpenClaw to stop routing assistant text produced before or between tool calls to external messaging channels unless that text is intentionally sent.

## Best Possible Solution

Keep this as the canonical product bug until maintainers choose a source-reply delivery policy and land regression coverage for unphased pre-tool/inter-tool text across streaming, final assembly, and cron announce delivery.
