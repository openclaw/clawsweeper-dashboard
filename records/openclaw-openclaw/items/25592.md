## Label Justifications

- `P1`: The report describes recurring production-visible leaks of internal assistant text into real messaging channels, but fixing it requires compatibility-sensitive policy work rather than an emergency one-line repair.
- `impact:security`: Internal planning text, raw tool payloads, and reasoning can expose sensitive operational details to external channel users.
- `impact:message-loss`: The bug is about channel delivery routing the wrong assistant messages, producing unintended visible messages alongside the intended reply.
- `impact:session-state`: Several reproductions show commentary or duplicate text entering stored assistant/session content before later delivery exposes it.
- `maturity:stable`: The issue includes Discord channel leakage, and `qa/maturity-scores.yaml` marks the Discord channel surface as M4 Stable.

## Summary

Keep open: current main and the latest release still preserve automatic direct source replies, and cron announce delivery still lacks reasoning/commentary filtering at the deliverable-payload boundary; the linked fork PRs are open but unmerged candidates, not a resolved fix.

## What This Changes

The issue requests that intermediate assistant text between tool calls stay internal instead of being delivered as visible Slack, Telegram, iMessage, Discord, WhatsApp, webchat, or Feishu channel messages.

## Best Possible Solution

Choose and implement a channel delivery policy that prevents internal or non-final assistant text from reaching external channels, with an upgrade path for existing bare-text DM users and regression coverage across direct chats, groups, streaming, final assembly, message-tool replies, and cron announce delivery.
