## Summary

Keep open: current main and the latest release still have automatic source-reply delivery paths and still preserve a visible block-reply flush path for unphased assistant text before tool execution. Existing commentary-phase suppression is useful partial mitigation, but it does not close the broader cross-channel leak described by the February report and the July field update.

## What This Changes

The issue reports that intermediate assistant text produced before or between tool calls is delivered as visible channel messages instead of staying internal.

## Best Possible Solution

Keep this issue as the canonical delivery-policy bug until maintainers choose and validate a safe final-only or explicit-send behavior across direct, group/channel, streaming, cron, and message-tool paths.

## Reproduction Assessment

Yes, from source inspection: default source delivery remains automatic for direct/group/channel paths, and unphased assistant chunks can still be buffered for visible block replies when suppression is not active. I did not run a live Slack or Telegram repro in this read-only review.

## Solution Assessment

No, current main is not the complete solution: commentary-phase suppression is useful but incomplete for ordinary unphased assistant text and default automatic delivery. The best fix still needs maintainer policy for compatibility-sensitive final-only or message-tool-only behavior.
