## Summary

Keep open: current main has important commentary/final-answer mitigations, but automatic source delivery, unphased assistant text buffering, and cron deliverable payload selection still leave the reported cross-channel leak source-reproducible.

## What This Changes

The issue asks OpenClaw to prevent assistant text produced before or between tool calls from being sent as visible messaging-channel replies, leaving only intentional final or message-tool output visible.

## Best Possible Solution

Keep this as the canonical tracker, choose the generic delivery-boundary policy, review or close the linked implementation PRs, and add regression coverage across automatic, message-tool-only, unphased inter-tool text, message-tool sent turns, and cron announce paths.

## Reproduction Assessment

Yes at source level: current main defaults source replies to automatic, unphased assistant text can enter block-reply delivery, and cron payload selection lacks reasoning/commentary filtering; no live channel repro was run in this read-only review.

## Solution Assessment

No: current main is only a partial mitigation; the best fix is a generic delivery-boundary policy with upgrade-safe defaults and tests, not a channel-specific sanitizer or broad text heuristic.
