## Summary

Keep open. Current main and the latest release include useful phase/commentary safeguards, but the generic delivery path still preserves automatic visible replies and a source-level pre-tool buffered text flush path; recent cron/reasoning reports also show remaining non-final text can still reach channels.

## What This Changes

Request to prevent non-final assistant text produced before or between tool calls from being delivered as visible messaging-channel replies.

## Best Possible Solution

Keep this as the canonical bug and have maintainers choose a channel-visible delivery policy that suppresses non-final/inter-tool text while preserving or migrating existing automatic-reply users, then add regression coverage for unphased pre-tool text, message-tool turns, and cron reasoning payloads.

## Reproduction Assessment

Yes at source level. Current main and v2026.6.11 still default ordinary source replies to automatic delivery, and the current pre-tool flush test asserts an unphased chunk is delivered before tool execution; no live channel repro was run.

## Solution Assessment

No final fix is selected yet. Existing partial fixes are useful, but the remaining solution needs a maintainer decision on automatic versus message-tool/final-only delivery and must cover cron/reasoning payload paths generically.
