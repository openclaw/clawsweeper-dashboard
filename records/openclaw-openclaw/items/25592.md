## Summary

Keep open. Current main and the latest release still preserve every non-empty assistant text segment when no canonical final answer is resolved, so the central channel leak remains source-reproducible despite partial commentary-phase and message-tool-only safeguards.

## What This Changes

The issue asks OpenClaw to prevent assistant text emitted between tool calls from being routed as visible messages in Slack, Telegram, Discord, iMessage, WhatsApp, Feishu, and similar channels.

## Best Possible Solution

Keep this issue as the canonical tracker and implement one coherent source-reply delivery policy at the payload assembly and cron delivery boundary, with upgrade-safe defaults or an explicit maintainer-approved opt-in path plus regression coverage for phased and phase-less providers.
