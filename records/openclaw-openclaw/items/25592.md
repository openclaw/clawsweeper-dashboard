## Summary

Keep open: current main and the latest release still preserve automatic visible-reply paths and buffered pre-tool text delivery, while the discussion has recent cross-channel production reproductions and open partial fix PRs.

## What This Changes

The issue asks OpenClaw to stop routing intermediate assistant text between tool calls to messaging channels.

## Best Possible Solution

Keep this as the canonical bug while maintainers choose the source-reply policy, then land focused fixes that cover automatic direct/source replies, pre-tool buffered text, cron reasoning payloads, and message-tool-only delivery with regression proof.

Yes for a source-level reproduction: current main still has automatic visible-reply paths and tests that flush buffered pre-tool assistant text. I did not run a live transport repro in this read-only review.

## Solution Assessment

No single proposed path is proven best yet. The durable fix should be a maintainer-approved delivery policy plus regression coverage across automatic source replies, message-tool-only mode, cron announce delivery, and channel history/projection.
