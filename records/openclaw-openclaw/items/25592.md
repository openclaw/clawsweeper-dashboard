## Label Justifications

- `P1`: The issue affects real Slack, Telegram, WhatsApp, Discord, and other channel workflows by exposing intermediate assistant text during normal agent operation.
- `impact:security`: The reported leaks can expose internal reasoning, tool arguments, error traces, and operational context to unintended channel audiences.
- `impact:message-loss`: The failure mode is channel-message misdelivery and duplication: non-final assistant text is routed as visible user messages.

## Summary

Keep open: current main has meaningful partial safeguards, but source inspection and recent field reports still show automatic channel-delivery paths for ordinary or unphased assistant text, plus an open same-repository implementation candidate that has not resolved the canonical bug.

## What This Changes

The report asks OpenClaw to stop routing intermediate assistant text between tool calls to messaging channels as visible user messages.

## Best Possible Solution

Keep this as the canonical bug while maintainers choose a compatible final-only or message-tool-only delivery policy, then land regression coverage across direct chats, group/channel chats, cron announce delivery, streaming, and final reply assembly.
