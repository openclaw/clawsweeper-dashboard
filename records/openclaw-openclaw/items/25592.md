## Summary

Keep open: current main has useful commentary/final-answer safeguards, but source-reply delivery still has automatic visible paths and cron delivery still selects non-error payloads without preserving reasoning metadata, so the central channel leak is not fully solved.

## What This Changes

The issue requests that intermediate assistant text between tool calls stay internal instead of being delivered as visible messages to Slack, iMessage, Telegram, Discord, and other channels.

## Best Possible Solution

Keep this as the canonical product bug and choose a direct-chat-safe delivery policy that suppresses non-final/unphased/cron reasoning text without breaking deliberate automatic final replies or documented plugin-owned delivery.

## Reproduction Assessment

Yes at source level: current main still has automatic visible-reply paths, unphased text buffering, and cron payload selection that does not carry isReasoning. I did not run a live Slack, Telegram, Discord, or iMessage reproduction in this read-only review.

## Solution Assessment

No, the issue is not solved yet; current main is a partial mitigation, not the durable fix. The best fix needs a maintainer-approved delivery boundary plus regression coverage for unphased text, message-tool-only turns, cron announce delivery, and final_answer/commentary phase handling.
