## Label Justifications

- `P1`: The issue is a recurring production-facing channel workflow failure where internal assistant text can be delivered to real users across multiple messaging integrations.
- `impact:security`: The reported leaks include reasoning, raw tool-call syntax, operational details, and customer context that should remain private/internal.
- `impact:message-loss`: The channel delivery pipeline can misroute unintended assistant text as standalone user-visible messages in Slack, Telegram, Discord, WhatsApp, WebChat, Feishu, and cron announce paths.

## Summary

Keep open. Current main has important partial guards for commentary-phase and Anthropic pre-tool narration, but source replies still default to automatic delivery for normal channel turns and the code/tests still preserve buffered pre-tool block delivery paths, so the central cross-channel leak is not proven fixed.

## What This Changes

The issue reports that assistant text emitted before or between tool calls is delivered as visible Slack, Telegram, iMessage, Discord, WhatsApp, WebChat, Feishu, and cron/channel messages instead of staying internal until a final or explicit message-tool send.

## Best Possible Solution

Keep this as the canonical bug until maintainers choose a source-reply delivery policy and land one tested path that prevents internal/pre-tool text from reaching external channels while preserving intentional final or message-tool replies.
