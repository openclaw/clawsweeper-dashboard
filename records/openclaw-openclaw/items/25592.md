## Summary

Keep open: current main has partial commentary/reasoning guards, but source, docs, tests, and recent issue discussion still show external-channel delivery paths where automatic final replies or cron payload selection can expose internal assistant text; linked closing PRs are open and conflicting rather than merged fixes.

## What This Changes

The issue asks OpenClaw to stop assistant text produced between tool calls from being delivered as visible messages to external messaging channels.

## Best Possible Solution

Define one external-channel delivery boundary that never publishes commentary, reasoning, or tool-adjacent unphased text, then land source-reply, embedded-stream, and cron coverage with an explicit maintainer decision on automatic-default compatibility.

- **Treat current main as sufficient:** Close only if maintainers intentionally accept remaining automatic delivery and cron metadata behavior as product-supported rather than a leak.
