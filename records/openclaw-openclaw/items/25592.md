## Summary

Keep open: current main still defaults ordinary source replies to automatic delivery, has a test that flushes buffered pre-tool text before tool execution, and cron delivery still selects payloads without reasoning metadata; the related PRs are partial or unmerged.

## What This Changes

The issue asks OpenClaw to stop routing intermediate assistant text, reasoning, or commentary between tool calls as visible messages in messaging channels.

## Best Possible Solution

Keep #25592 as canonical and have maintainers choose a generic delivery-boundary policy that suppresses internal/inter-tool text while preserving intentional final replies, message-tool sends, and upgrade expectations.

## Reproduction Assessment

Yes at source level: current main defaults ordinary source replies to automatic, preserves pre-tool buffered block delivery in tests, and cron payload selection lacks reasoning filtering; no live channel run was done in this read-only review.

## Solution Assessment

No close or single partial PR is the best end state yet; the best fix needs a maintainer-approved delivery policy plus regressions for automatic, message-tool-only, cron, reasoning, commentary, and failure-fallback paths.
