## Label Justifications

- `P1`: The issue describes a recurring user-facing channel workflow failure where internal assistant text is delivered to real Slack, Telegram, WhatsApp, Discord, and other channel recipients.
- `impact:security`: Intermediate reasoning, raw tool-call-like text, and internal processing context can be exposed to external channel recipients.
- `impact:message-loss`: The defect causes channel delivery to emit extra unintended messages in addition to or instead of the intended final/message-tool reply.
- `impact:session-state`: Several reports and source paths show commentary/intermediate assistant text entering assistantTexts or session history before later delivery or quote-context exposure.
- `maturity:stable`: The issue affects Discord conversation routing and delivery, and qa/maturity-scores.yaml marks Discord as M4 Stable with Conversation Routing and Delivery supported.

## Summary

Keep open: current main contains partial protections for commentary-phased output and Anthropic pre-tool narration, but automatic visible-reply defaults, unphased text buffering before tool execution, and cron deliverable selection still leave the central channel-leak problem unresolved; linked PRs are open, closed-unmerged, or partial candidates rather than merged fixes.

## What This Changes

The issue requests that assistant text produced between tool calls stay internal instead of being routed to messaging channels, leaving only final intentional output or explicit message-tool sends visible.

## Best Possible Solution

Keep #25592 as the canonical tracker until maintainers choose a generic delivery-boundary policy, land a focused fix with upgrade-safe defaults, and add regression coverage for automatic replies, message-tool sends, unphased provider text, commentary/reasoning payloads, and cron announce delivery.

Options:

- **Staged guarded delivery (recommended):** Keep existing automatic final-reply compatibility for now, but suppress phase-tagged commentary, structured reasoning, obvious non-final tool-turn buffers, and cron reasoning payloads with tests and a later default-policy follow-up.
- **Explicit-send default:** Make source/channel replies visible only through message(action=send) by default and provide a migration or opt-out for deployments that rely on bare final text.
- **Opt-in escape hatches only:** Land only opt-in controls such as final-tag enforcement or message-tool-only config, leaving the current automatic default unchanged for compatibility.
