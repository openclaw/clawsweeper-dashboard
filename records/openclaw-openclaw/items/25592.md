## Label Justifications

- `P1`: The issue reports real channel messages exposing internal assistant narration across Slack, Telegram, WhatsApp, Discord, and cron announce paths.
- `impact:security`: Internal processing text, tool-like payloads, and error traces can become visible in external professional channels.

- `maturity:stable`: The affected gateway/source-delivery path maps to `gateway-runtime`, which is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open. Current main has phase-aware commentary/final-answer mitigations, but the shared payload builder still falls back to every accumulated assistant text when no canonical final answer is available, and source replies still default to automatic channel delivery for normal turns.

## What This Changes

The issue asks OpenClaw to stop routing assistant text produced between tool calls as visible messages in messaging channels.

## Best Possible Solution

Define a shared final-only/source-delivery invariant at payload construction or lower, with maintainer-approved compatibility behavior, and cover both interactive channel and cron announce delivery paths.

Options:

- **Adopt final-only payload construction (recommended):** Trim the no-canonical-final fallback at payload construction so interactive and cron delivery share one safer default, with any compatibility escape hatch documented and tested.

- **Keep automatic fallback with opt-in suppression:** Accept the current default risk and add a configuration knob for operators who know their provider or channel leaks interim text.
