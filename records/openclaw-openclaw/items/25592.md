## Summary

Keep open: current main has several useful partial safeguards, but the central cross-channel leak class is still source-reproducible. Automatic source delivery remains the default for ordinary chats, unphased assistant text can still enter visible delivery paths, cron announce delivery still selects deliverable text without reasoning metadata, and there are still active partial PRs rather than a merged canonical fix.

## What This Changes

The issue reports that assistant text emitted before or between tool calls is delivered as visible messages in messaging channels instead of staying internal until the final intentional reply.

## Best Possible Solution

Keep this as the canonical bug until maintainers choose and land a direct-chat-safe final-only or message-tool-only delivery policy with regression coverage across streaming, final assembly, and cron/announce paths.

## Reproduction Assessment

Yes. Source inspection shows automatic source replies remain default for ordinary chats, commentary-only guards are partial, tool execution start still flushes block-reply buffers, and cron announce delivery lacks reasoning metadata.

## Solution Assessment

Unclear. Suppression is needed, but the best fix requires a maintainer delivery-policy decision because unconditional message-tool-only or final-only defaults can break deployments that rely on automatic bare-text replies.
