## Label Justifications

- `P1`: The report describes recurring real-channel leakage of internal assistant text in production messaging workflows.
- `impact:security`: Internal reasoning, raw tool payloads, and error traces can be exposed to external channel recipients.
- `impact:message-loss`: The same delivery boundary decides whether the intended final reply is suppressed, duplicated, or mixed with intermediate channel messages.

- `maturity:stable`: The issue affects Discord conversation routing and delivery, and Discord is scored M4 Stable in qa/maturity-scores.yaml.

## Summary

Keep open: current main has important phased-commentary and reasoning-payload mitigations, but source delivery still allows automatic visible replies and unphased assistant text paths that match the reported cross-channel leak class.

## What This Changes

The issue requests that assistant text produced before or between tool calls stay internal and not be delivered as visible messages to Slack, Telegram, iMessage, Discord, WhatsApp, Feishu, or other messaging channels.

## Best Possible Solution

Keep this as the canonical bug and land a compatibility-aware final-only or explicit-send policy with regression coverage for unphased pre-tool/inter-tool text across automatic, message-tool-only, and cron delivery paths.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: with automatic source delivery active, unphased assistant text can be buffered or collected as reply text, and cron payload selection still treats successful textual payloads as deliverable. I did not run a live channel repro in this read-only cleanup pass.

## Solution Assessment

Unclear as a final product decision. The safest implementation needs to suppress pre-tool/inter-tool text without breaking existing direct-chat automatic final replies or weaker model fallback behavior, so a narrow fix should cover automatic delivery, message-tool-only suppression, and cron/announce selection rather than only one channel adapter.
