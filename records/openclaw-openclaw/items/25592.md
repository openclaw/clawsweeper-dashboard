## Summary

Keep open: current main has important phased-commentary mitigations, but automatic source delivery, unphased assistant text buffering, and cron delivery selection still leave the reported channel leak source-provable.

## What This Changes

The issue asks OpenClaw to stop routing assistant text emitted before or between tool calls as visible channel messages, allowing only final or explicit message-tool output to reach users.

## Best Possible Solution

Keep #25592 as the canonical bug until maintainers choose the delivery policy and land one focused fix covering automatic direct replies, unphased inter-tool text, message-tool-only/NO_REPLY, cron announce delivery, and regression proof.

## Reproduction Assessment

Yes, at source level: current main defaults source replies to automatic delivery, can buffer unphased assistant text before tool execution, flushes that buffer at tool start, and the cron helper still lacks reasoning-payload filtering.

## Solution Assessment

Unclear as an implementation choice: the desired final-or-explicit visible-output boundary fits the bug, but the default behavior and upgrade path need maintainer product/security judgment before a fix lands.
