## Summary

Keep open: current main has partial safeguards for commentary-tagged text and message-tool-only modes, but automatic source-reply paths and cron multi-payload delivery still leave the central inter-tool leak class source-reproducible; the linked fix PRs are open and conflicting.

## What This Changes

The issue asks OpenClaw to prevent assistant text produced between tool calls from being delivered visibly to messaging channels.

## Best Possible Solution

Adopt one maintainer-approved source-channel delivery policy that keeps internal/inter-tool text private by default, preserves intentional final or message-tool replies, covers direct/group/cron/streaming/history paths, and includes regression plus live channel proof.
