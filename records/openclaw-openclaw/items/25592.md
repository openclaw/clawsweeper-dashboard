## Label Justifications

- `P1`: User-visible internal reasoning and tool text can leak into real messaging channels across multiple reported deployments.
- `impact:security`: The leaked text can expose internal planning, tool payloads, operational context, or customer-facing private details to external chats.

- `maturity:stable`: The issue includes Discord channel delivery, and qa/maturity-scores.yaml lists Discord as M4 Stable with Conversation Routing and Delivery stable completeness.

## Summary

Keep open: current main and the latest release still have source-provable paths where unphased assistant text can be buffered and delivered around tool execution, and the linked implementation PRs are candidates rather than merged fixes.

## What This Changes

Suppress internal assistant text produced before or between tool calls so messaging channels only receive intentional final replies or explicit message-tool output.

## Best Possible Solution

Keep this as the canonical channel-leak bug, choose a maintainer-approved delivery policy for automatic replies versus message-tool/final-only delivery, and land focused regression coverage for unphased inter-tool text plus cron reasoning/commentary payload filtering.

## Reproduction Assessment

Yes, source-reproducible: current main buffers unphased assistant text and flushes it before tool_execution_start, and current tests assert that delivery behavior. I did not run a live Slack, Telegram, Discord, or iMessage reproduction in this read-only pass.

## Solution Assessment

No, current main is not the complete fix; commentary-phase and NO_REPLY safeguards are partial while unphased text and cron payload paths remain. The best solution needs a maintainer policy decision that preserves or migrates legitimate automatic replies while suppressing internal inter-tool output.
