## What This Changes

Prevent Slack Socket Mode from waiting forever after a zombie WebSocket stops delivering transport activity without emitting a disconnect or error event.

## System Context

The Slack plugin receives Socket Mode traffic and reports connection status to the gateway health monitor. Its reconnect supervisor must distinguish a quiet but live WebSocket from a dead transport so inbound Slack messages can recover without restarting the OpenClaw process.

## Best Possible Solution

Land a Slack-owned recovery path that records only real Socket Mode transport activity, treats prolonged transport silence as stale, and bounds the reconnect waiter without treating ordinary application-event quiet as a failure.
