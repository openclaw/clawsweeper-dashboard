## Summary

Current main already reschedules filesystem events received during an active reload, rereads authoritative disk state for watcher notifications, and supports native-to-polling recovery. This issue should remain open because the single pending in-process slot may still discard a committed write’s stronger follow-up intent, while the valid watcher recreation gap is already owned by narrower issue and PR work.

## What This Changes

Harden gateway configuration hot reload against rapid writes, queued filesystem events, stale events, and watcher recreation gaps.

## Best Possible Solution

Keep latest-state coalescing, preserve the strongest required follow-up intent across pending committed writes, and leave watcher recreation reconciliation to the focused canonical issue and viable candidate PR rather than duplicating it here.
