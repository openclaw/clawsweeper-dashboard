## Summary

Keep this PR open for normal review. The proposed guard appears to align the thrown-error fallback path with the existing channel-delivery result-classification guard, and the paired open issue remains the canonical report; however, the supplied evidence is unit-test/mock-only and does not yet demonstrate an after-fix delivered-reply-then-provider-error scenario in a real runtime.

## What This Changes

The PR makes model fallback stop after a thrown channel-delivery attempt when that attempt already sent a reply, preventing the next model candidate from rerunning and duplicating the visible answer.

## System Context

Embedded agent runs can try configured model candidates in sequence. Channel delivery records whether a reply was sent; that evidence determines whether a failure may safely advance to a fallback candidate or must stop to avoid a duplicate user-facing reply.

## Best Possible Solution

Retain one consistent delivery-evidence rule across returned-result and thrown-error fallback exits, preserve the no-delivery fallback path, and add redacted real-runtime proof before merge.
