## Summary

Keep this PR open for normal maintainer review: current main still buffers Convex broker responses with raw `response.text()`, while the PR uses the existing bounded SDK reader, preserves the chunk payload path, adds focused regression coverage, and now includes real terminal proof plus clean live status checks.

## What This Changes

The PR caps ordinary qa-lab Convex credential broker responses at 1 MiB, keeps chunk payload hydration on the configured payload limit, and adds buffered plus streaming oversized-response tests.

## Best Possible Solution

Land this narrow bounded-read fix through normal maintainer review, keeping official chunked credential payload hydration on its configured payload cap.

## Reproduction Assessment

Yes. Current main reads `postConvexBroker()` responses with raw `response.text()` before error handling, and the PR body plus added tests exercise an oversized loopback broker response; I did not execute tests because this review is read-only.

## Solution Assessment

Yes. This is the best fix shape: it applies the cap at the shared credential lease boundary, reuses the existing SDK bounded reader, and avoids duplicating per-transport or local stream-reading logic.
