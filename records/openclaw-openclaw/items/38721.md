## Summary

Keep open: current main still has the dirty-shutdown watchdog and intentionally does not drain or abort active chat runs on normal shutdown, so the child-process-handle shutdown blocker is not solved by the merged websocket close fix.

## What This Changes

The issue asks OpenClaw to prevent gateway stop/restart from timing out dirty when active child-process handles remain alive, and to clarify whether shutdown should cancel or detach managed exec children.

## Best Possible Solution

Define one owner-approved gateway stop contract that rejects new work, bounds active run/session drains, cancels managed exec/process scopes before the watchdog, and documents any background-process exception maintainers choose to preserve.

## Maintainer Decision

Kind: product_direction

Question: Should normal SIGTERM/SIGINT gateway shutdown cancel active runs and their managed exec child processes, or preserve yielded/backgrounded exec sessions unless an explicit restart or process-kill path is used?

Rationale: Current source and tests intentionally preserve active/background work on normal shutdown, so changing that behavior is an operator-safety and product-policy choice before it is a mechanical patch.

Likely owner: vincentkoc

Owner reason: Vincent has the strongest recent process/lane surface history among the likely owners and was already pulled into the issue timeline.

Owner confidence: high

Options:

- **Define bounded managed-process shutdown (recommended):** On normal stop, reject new work and cancel managed active run/exec scopes through the supervisor before the watchdog, with documented exceptions for any background process class maintainers choose to preserve.
- **Preserve current normal-stop behavior:** Keep normal shutdown from aborting active/background exec work and treat this as a diagnostics or documentation issue instead of runtime cancellation behavior.
- **Defer to session exec-control design:** Keep this open until https://github.com/openclaw/openclaw/issues/12554 defines the process-control contract, then reuse that contract for gateway shutdown.

## Reproduction Assessment

No high-confidence live reproduction was run for the Ubuntu/systemd timeout. Source inspection does show current main and v2026.6.11 preserve active/background exec work during normal shutdown, matching the unresolved shutdown-policy gap.

## Solution Assessment

Unclear until maintainers choose the shutdown policy. The websocket-close fix is not sufficient; the maintainable solution is a single owner-approved normal-stop contract for active runs, managed child processes, and any background-process exception.
