## Summary

Keep open: current main and latest v2026.6.11 still preserve active/background exec work during normal SIGTERM shutdown, while the merged websocket-close fix addressed only an adjacent shutdown hang. The child-process shutdown policy remains unresolved and should not be auto-closed.

## What This Changes

The issue reports gateway shutdown timeouts on systemd stops when referenced child-process handles remain active, leaving dirty shutdown and later lane waits.

## Best Possible Solution

Define a normal gateway stop contract that rejects new work, bounds active run and session drains, cancels managed exec/process scopes before the watchdog, and documents any preserved background-process exception.

Question: Should normal SIGTERM/SIGINT gateway shutdown abort active runs and their managed exec child processes, or preserve background/yielded exec sessions unless an explicit restart or kill path is used?

Rationale: Current source and tests intentionally preserve active/background work on normal shutdown, so changing that behavior is an operator-safety and product policy decision rather than a mechanical bug patch.

Likely owner: vincentkoc

Owner reason: This handle has the strongest recent history across the process supervisor, process tool, and session/process-control boundary.

Owner confidence: high

Options:

- **Define bounded managed-process shutdown (recommended):** On normal stop, reject new work and cancel managed active run/exec scopes through the supervisor before the watchdog, with an explicit documented exception for any background process class maintainers choose to preserve.
- **Preserve current normal-stop behavior:** Keep normal shutdown from aborting active/background exec work and treat this as a diagnostics or documentation problem rather than a runtime cancellation change.
- **Defer to session exec-control design:** Keep this open until https://github.com/openclaw/openclaw/issues/12554 defines the process-control contract, then reuse that contract for gateway shutdown.

No, not with high-confidence live proof: this read-only review did not reproduce the Ubuntu/systemd child-process handle timeout. Source inspection does show current main and v2026.6.11 preserve active/background exec work on normal shutdown, matching the reported unresolved policy gap.
