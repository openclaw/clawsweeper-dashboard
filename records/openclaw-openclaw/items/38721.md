## Summary

Keep open: current main and the latest release still preserve active/background exec work during normal gateway shutdown, so the child-process shutdown timeout report is not implemented or superseded. The remaining work is a maintainer policy choice about normal-stop semantics and operator safety, not a stale cleanup item.

## What This Changes

Investigate dirty gateway shutdowns where referenced child-process handles appear to keep normal stop/restart from completing under systemd.

## Best Possible Solution

Define one normal gateway stop contract that rejects new work, bounds active run/session drain, cancels chosen managed exec/process scopes before the watchdog, and documents any background-process class that should survive normal stop.

Options:

- **Define bounded managed-process shutdown (recommended):** On normal stop, reject new work and cancel owner-approved managed active run/exec scopes through supervisor cancellation before the watchdog, with documented exceptions for preserved background work.
- **Preserve current normal-stop behavior:** Keep normal shutdown from aborting active/background exec work and treat child-process shutdown timeouts as diagnostics, docs, or operator-runbook work rather than runtime cancellation.
- **Defer to session exec-control design:** Keep this issue open until https://github.com/openclaw/openclaw/issues/12554 defines the process-control contract, then reuse that design for shutdown semantics.
