## Summary

## What This Changes

The issue reports gateway shutdown timeouts on OpenClaw 2026.3.2 when referenced child-process and pipe handles remain active during systemd shutdown.

## Best Possible Solution

Define one normal gateway stop policy that rejects new work, bounds or cancels active run and child-process owners through canonical process scopes, and explicitly preserves any intended background-process exception.

## Reproduction Assessment

No high-confidence live reproduction was run in this review. Source inspection does show the relevant policy gap: normal SIGTERM shutdown does not abort active runs, and the latest release preserves that behavior, but the exact child command from the reporter's Node report is not identified.

## Solution Assessment

Unclear until maintainers choose the shutdown policy. The websocket-close fix is not the complete solution; the safer path is an owner-approved normal-stop contract for active exec/process children and any preserved background-process exception.
