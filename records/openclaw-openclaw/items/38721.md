- `impact:crash-loop`: The reported failure is a shutdown timeout followed by forced non-zero gateway exit and restart behavior.

## Summary

Keep open: current main and v2026.6.11 still preserve active runs on normal gateway shutdown, so the reported child-process shutdown timeout remains a real lifecycle/policy gap rather than something fixed by adjacent websocket or systemd work.

## What This Changes

The issue asks OpenClaw to handle gateway shutdowns blocked by active child-process handles so normal stop/restart does not exit dirty or leave lane waits.

## Best Possible Solution

Define a normal gateway stop contract that rejects new work, bounds active run/session drains, cancels or explicitly preserves managed exec/process scopes before the watchdog, and documents the chosen exception policy.

- **Defer to session kill/control design:** Leave this issue blocked on the broader sessions_kill or process ownership design so operators can list and terminate child work explicitly.
