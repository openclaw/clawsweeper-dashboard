## Summary

Keep open: current main and v2026.6.11 still keep normal gateway shutdown separate from the restart-only active-run drain/abort path, so the reported child-process shutdown timeout remains unresolved and is not covered by the adjacent websocket shutdown fix.

## What This Changes

The issue reports gateway shutdown timeouts where active referenced child-process and pipe handles appear to block clean stop/restart and leave later lane waits.

## Best Possible Solution

Define and document a normal gateway stop contract that rejects new work, bounds active run and session drains, then either cancels or explicitly preserves managed process scopes before the watchdog with live Ubuntu systemd proof.

Options:

- **Define bounded managed-process shutdown (recommended):** Normal stop would reject new work, drain briefly, then cancel managed exec/process scopes before the watchdog while documenting explicit preservation exceptions.

- **Defer to session kill design:** This issue would wait for the broader session/process list-and-kill surface tracked in https://github.com/openclaw/openclaw/issues/12554.
