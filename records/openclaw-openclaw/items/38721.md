## Summary

Keep open: current main and latest v2026.6.11 still preserve active/background exec work during normal SIGTERM shutdown, and the gateway shutdown path does not cancel managed exec child processes before the watchdog. The merged websocket-close fix addressed an adjacent shutdown hang, but not the reported child-process and pipe handles.

## What This Changes

The issue asks OpenClaw to handle child process handles during gateway shutdown so systemd stop/restart does not leave a dirty shutdown and follow-on lane waits.

## Best Possible Solution

Define a bounded gateway stop contract that rejects new work, drains or aborts active runs, cancels managed exec/process-supervisor children before the watchdog, and explicitly documents any background/yielded exception.

Rationale: Current source intentionally preserves active runs on normal shutdown and preserves yielded/background exec sessions on abort; changing that can prevent dirty shutdowns but may terminate user work.

Owner confidence: medium

Options:

- **Define bounded managed-process shutdown (recommended):** Make normal gateway stop reject new work, cancel foreground active managed exec runs before the watchdog, and document or separately handle any background/yielded exception.
- **Preserve background work and add visibility:** Keep active/background exec preservation as the default and add diagnostics or operator visibility so shutdown blockers can be identified without killing work automatically.
- **Defer to session exec-control design:** Keep this open behind #12554 until maintainers choose the broader session kill/list/process-group model.

## Solution Assessment

Unclear until maintainers choose the shutdown policy. The websocket close fix is not enough; the maintainable fix should be an owner-approved gateway/process lifecycle contract rather than an ad hoc child kill in one path.
