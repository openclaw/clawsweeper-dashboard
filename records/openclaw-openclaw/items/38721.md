## What This Changes

This issue reports gateway stop/restart timeouts where active child-process and pipe handles appear to keep shutdown dirty and leave lane waits afterward.

## Best Possible Solution

Define a normal gateway stop contract that rejects new work, bounds active run/session drains, cancels managed exec/process scopes before the watchdog, and documents any background-process class maintainers choose to preserve.

Rationale: Current code intentionally preserves background exec sessions on tool-call abort and normal shutdown does not abort active runs, so a correct fix changes operator-visible lifecycle policy rather than just a local timeout.

- **Define bounded managed-process shutdown (recommended):** Normal gateway stop rejects new work, bounds drains, cancels tracked managed exec/process scopes before the watchdog, and documents any explicitly preserved background class.
- **Preserve background jobs by default:** Keep normal stop from killing yielded/background exec sessions and instead improve diagnostics plus operator-facing process kill guidance for dirty shutdowns.
- **Split by explicit mode:** Keep compatibility as the default and add an owner-approved strict shutdown mode only after upgrade and documentation decisions are made.

No live Ubuntu/systemd reproduction was run in this read-only review; source inspection and existing tests show normal shutdown leaves active run abort controllers intact while background exec sessions are intentionally preserved.

## Solution Assessment

Unclear until maintainers choose the shutdown policy; the best fix is a single owner-approved contract for normal stop, managed child processes, and background exec preservation rather than another one-off socket or service timeout.
