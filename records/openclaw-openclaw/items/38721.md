## Summary

Keep open: current main and the latest release still have the gateway dirty-shutdown watchdog and still preserve active/background exec work on normal SIGTERM, so the child-process shutdown policy reported here is not implemented by the merged websocket-close or systemd cleanup work.

## What This Changes

The issue asks OpenClaw to prevent gateway shutdown timeouts caused by active child-process handles that leave dirty shutdowns and lane waits on Ubuntu/systemd.

## Best Possible Solution

Define a normal gateway stop contract that rejects new work, bounds active run/session drains, cancels managed exec/process scopes before the watchdog, and documents any background-process class that should be preserved.

Options:
