## Summary

Keep open: current main and the latest release still preserve active/background exec work during normal gateway shutdown, so the reported child-process shutdown timeout is not fixed by the adjacent websocket or systemd hardening work.

## What This Changes

The issue reports dirty gateway shutdowns on systemd when an active child-process handle appears to block cleanup until the watchdog exits.

## Best Possible Solution

Define a normal gateway stop contract that rejects new work, bounds active run/session drains, cancels managed exec/process scopes before the watchdog, and documents any background-process class that should be preserved.

Rationale: Current source and tests intentionally preserve active/background work on normal shutdown, so changing that behavior is an operator-safety and product-policy decision rather than a mechanical cleanup.

Owner confidence: high

Options:

- **Define bounded managed-process shutdown (recommended):** On normal stop, reject new work and cancel managed active run/exec scopes through the supervisor before the watchdog, with a documented exception for any background process class maintainers choose to preserve.
- **Preserve current normal-stop behavior:** Keep normal shutdown from aborting active/background exec work and treat this as a diagnostics or documentation gap instead of a runtime cancellation change.
- **Defer to session exec-control design:** Keep this issue open until https://github.com/openclaw/openclaw/issues/12554 defines the process-control contract, then reuse that contract for gateway shutdown.
