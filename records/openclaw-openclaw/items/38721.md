## Summary

Keep open: current main still has the shutdown watchdog and still preserves active chat/agent runs on normal SIGTERM/SIGINT shutdown, so the reported child-process handle timeout is not proven fixed by the websocket shutdown fix or the newer session-end hook drain.

## What This Changes

The issue reports dirty gateway shutdown timeouts on Ubuntu systemd where Node diagnostic reports show referenced child-process and pipe handles, followed by lane wait delays.

## Best Possible Solution

Define a normal gateway stop contract that rejects new work, bounds active run/session drains, and either cancels or explicitly preserves managed process scopes before the shutdown watchdog, then prove it with Ubuntu systemd stop/restart evidence.
