## Summary

Keep open: current main and v2026.6.11 still preserve active/background exec work on normal shutdown while the dirty-shutdown watchdog remains, so the child-process shutdown policy reported here is not implemented by the adjacent websocket or supervisor cancellation fixes.

## What This Changes

The issue reports dirty gateway shutdowns on systemd when active referenced child-process and pipe handles remain during stop/restart.

## Best Possible Solution

Define a normal gateway stop contract that rejects new work, bounds active run/session drains, cancels managed exec/process scopes before the watchdog, and documents any background-process class that should be preserved.
