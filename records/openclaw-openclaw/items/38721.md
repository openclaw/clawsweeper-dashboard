## Summary

Keep open: current main and the latest release still preserve active/background exec work on normal SIGTERM shutdown, so the child-process shutdown timeout reported here remains unresolved and needs maintainer policy.

## What This Changes

The issue reports dirty gateway shutdowns on Linux/systemd where active child-process handles appear to keep shutdown from completing and are followed by lane waits.

## Best Possible Solution

Define a normal gateway stop contract that rejects new work, bounds active run/session drains, cancels managed exec/process scopes before the watchdog, and documents any background-process class that should be preserved.
