## Summary

Keep open: current main and the latest release still preserve active/background exec work during normal Gateway SIGTERM shutdown, so the child-process shutdown policy reported here is not implemented by the adjacent websocket-close and service-managed child hardening fixes.

## What This Changes

The issue reports Ubuntu systemd Gateway shutdowns timing out with active child-process handles and asks whether exec subprocesses should be cancelled or detached during shutdown.

## Best Possible Solution

Define a normal Gateway stop contract that rejects new work, bounds active run/session drains, cancels managed exec/process scopes before the watchdog, and documents any background-process class that should be preserved.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should normal SIGTERM/SIGINT Gateway shutdown abort active runs and their managed exec child processes, or preserve background/yielded exec sessions unless an explicit restart or kill path is used?

Rationale: Current source and tests intentionally preserve active/background work on normal shutdown, so changing this is an operator-safety and product policy choice rather than a mechanical cleanup.

Likely owner: steipete

Owner reason: Peter has the strongest combined history on service-managed child hardening, exec abort behavior, and the run-loop watchdog split.

Owner confidence: medium

Options:

- **Define bounded managed-process shutdown (recommended):** On normal stop, reject new work and cancel managed active run/exec scopes through the supervisor before the watchdog, with documented exceptions for any preserved background process class.
- **Preserve current normal-stop behavior:** Keep normal shutdown from aborting active/background exec work and treat this as a diagnostics or documentation gap rather than a runtime cancellation change.
- **Defer to session exec-control design:** Keep this issue open until the session-wide exec-control contract in https://github.com/openclaw/openclaw/issues/12554 defines the reusable process ownership model.

No high-confidence live reproduction was established for the exact Ubuntu/systemd timeout. Source inspection does reproduce the unresolved policy gap: current main preserves active/background exec work on normal SIGTERM shutdown.

## Solution Assessment

Unclear until maintainers choose the shutdown policy. The websocket-close fix and service-managed child hardening are useful adjacent fixes, but the durable solution is one owner-approved contract for normal stop, managed child processes, and background-process preservation.
