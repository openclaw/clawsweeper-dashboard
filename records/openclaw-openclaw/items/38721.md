## Summary

Keep open: current main still has the dirty-shutdown watchdog and still preserves active/background exec work on normal SIGTERM shutdown, while the merged websocket-close fix addressed only an adjacent shutdown hang.

## What This Changes

Investigate and fix gateway normal-shutdown timeouts where referenced child-process handles keep cleanup from completing and leave lane waits after restart.

## Best Possible Solution

Define a normal gateway stop contract that rejects new work, bounds active run and session drains, cancels managed exec/process scopes before the watchdog, and documents any preserved background-process exception.

Options:

- **Define bounded managed-process shutdown (recommended):** On normal stop, reject new work and cancel managed active run/exec scopes before the watchdog, with a documented exception for any background process class maintainers choose to preserve.

- **Defer to session exec-control design:** Keep this open until https://github.com/openclaw/openclaw/issues/12554 defines the process-control contract, then reuse that contract for gateway shutdown.
