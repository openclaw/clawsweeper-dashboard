## Summary

Keep open: current main still has the dirty-shutdown watchdog and intentionally avoids aborting active runs or yielded/backgrounded exec sessions during normal SIGTERM shutdown. The merged websocket-close fix addressed an adjacent shutdown hang, not the child-process handle policy reported here.

## What This Changes

The issue asks whether gateway shutdown should cancel or detach child processes that can keep normal stop/restart cleanup dirty and leave lane waits behind.

## Best Possible Solution

Define a normal gateway stop contract that rejects new work, bounds active run and session drains, cancels managed exec/process scopes before the watchdog, and documents any preserved background-process exception.
