## Summary

This should stay open: current main still preserves active/background exec work during normal shutdown, and the merged websocket shutdown fix addresses a different blocker than the child-process handles reported here.

## What This Changes

The issue asks for gateway shutdown to avoid dirty timeout exits when active child-process or pipe handles from exec/tool work keep the Node process alive.

## Best Possible Solution

Define one gateway stop contract that rejects new work, bounds active run/session drains, cancels managed exec/process scopes before the watchdog, and documents any background-process exception maintainers choose to preserve.
