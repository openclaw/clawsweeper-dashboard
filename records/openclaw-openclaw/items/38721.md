## Summary

Keep open: current main still preserves active/background exec work during normal Gateway stop, and the merged websocket-close fix only addressed an adjacent shutdown hang. This still needs maintainer policy on normal shutdown cancellation before it is safe to route as a fix PR.

## What This Changes

The issue reports Gateway shutdown timeouts on Linux systemd when referenced child-process and pipe handles remain active during stop/restart cycles.

## Best Possible Solution

Define a normal Gateway stop contract that rejects new work, bounds active run and session drains, cancels managed exec/process scopes before the watchdog, and documents any preserved background-process exception.
