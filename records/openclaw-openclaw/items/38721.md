## Summary

Keep open: current main still has the dirty shutdown watchdog and normal gateway stop still skips the restart-only active-run abort/drain path, so the child-process/pipe-handle shutdown problem is not implemented on main and is distinct from the merged websocket-close fix.

## What This Changes

The issue asks OpenClaw to avoid dirty gateway shutdown when active child-process handles and pipes outlive normal gateway stop/restart.

## Best Possible Solution

Define one gateway stop policy that rejects new work, drains or aborts active runs through their canonical owners, cancels supervisor-owned child-process scopes with bounded grace, and documents any preserved background-process exception.

## Reproduction Assessment

No high-confidence live reproduction is available from this read-only review. The reporter provided strong diagnostics and current source shows normal shutdown leaves active runs un-aborted, but the exact child process behind the Node report was not identified on current main.

## Solution Assessment

Unclear. The websocket-close fix is not the complete solution; the best path needs an owner-approved normal-stop policy for active exec/process children before code changes are safe.
