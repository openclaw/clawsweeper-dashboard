## Summary

Source, tests, latest release-tag checks, and the issue discussion all point to the same outcome: the websocket hang was fixed, but normal gateway shutdown still intentionally preserves active/background exec work. This remains open because the unresolved part is a shutdown policy and operator-safety choice, not a stale or implemented report.

## What This Changes

The issue requests a fix or policy for gateway SIGTERM/SIGINT shutdowns that time out when active child-process handles keep the process alive, plus guidance for debugging the responsible child command.

## Best Possible Solution

Define a normal gateway stop contract that rejects new work, bounds active run and session drains, cancels managed exec/process scopes before the watchdog, and documents any preserved background-process exception.
