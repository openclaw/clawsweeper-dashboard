## Summary

Keep open: current main still has the shutdown watchdog and still preserves active/background exec work on normal SIGTERM shutdown, so the child-process shutdown blocker reported here is not resolved by the merged websocket-close fix or the adjacent systemd subprocess hardening.

## What This Changes

The issue reports gateway shutdown timeouts on OpenClaw 2026.3.2 where Node diagnostic reports show active child-process and pipe handles during shutdown.

## Best Possible Solution

Define a normal gateway stop contract that rejects new work, bounds active run/session drains, cancels managed exec/process scopes before the watchdog, and documents any background-process class that should be preserved.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should normal SIGTERM/SIGINT gateway shutdown cancel managed active run and exec child-process scopes before the shutdown watchdog, or preserve yielded/background exec sessions unless an explicit restart or kill path is used?

Rationale: Current source and release tests preserve active/background work on normal shutdown, so changing this is an operator-safety and product-policy choice rather than a mechanical cleanup.

Likely owner: vincentkoc

Owner reason: This handle has the strongest current history signal across exec/process behavior and would likely own the shutdown policy tradeoff with adjacent gateway owners.

Owner confidence: high

Options:

- **Define bounded managed-process shutdown (recommended):** On normal stop, reject new work and cancel managed active run/exec scopes through the supervisor before the watchdog, with documented exceptions for any background class maintainers choose to preserve.
- **Preserve current normal-stop behavior:** Keep normal shutdown from aborting active/background exec work and treat this as a diagnostics or documentation gap unless a restart/kill path is explicitly requested.
- **Defer to session exec-control design:** Keep this issue open until the public session exec-control contract in https://github.com/openclaw/openclaw/issues/12554 defines process ownership and termination semantics.

## Reproduction Assessment

No high-confidence live reproduction was established in this read-only review. Source inspection shows current main and v2026.6.11 still preserve active/background exec work on normal SIGTERM shutdown, matching the unresolved shutdown-policy gap reported here.

## Solution Assessment

Unclear until maintainers choose the shutdown policy. The websocket-close and systemd hardening fixes are useful adjacent work, but the maintainable fix is one owner-approved contract for normal stop, managed child processes, and background-process preservation.
