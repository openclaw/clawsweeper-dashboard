## Summary

Keep open: current main still has the dirty-shutdown watchdog, still skips active-run abort/drain for normal SIGTERM/SIGINT shutdown, and still preserves yielded/backgrounded exec processes on tool-call abort. The websocket shutdown fix and MCP stdio child cleanup fixes are adjacent but do not settle the normal gateway-stop child-process policy.

## What This Changes

The issue requests fixing gateway shutdown timeouts where referenced child-process and pipe handles can leave supervised stop/restart dirty and followed by lane waits.

## Best Possible Solution

Define one normal gateway stop contract that rejects new work, bounds active run/session drains, cancels managed exec/process scopes before the watchdog, and documents any preserved background-process exception.
