## Summary

Keep open: current main and v2026.6.11 still preserve active runs on normal gateway shutdown, and the related websocket shutdown fix does not cover referenced child-process handles that can keep the process alive.

## What This Changes

The issue asks OpenClaw to diagnose and fix gateway stop timeouts caused by active child-process handles so systemd shutdown cleans up without lane-wait fallout.

## Best Possible Solution

Define a maintainer-approved normal-stop policy that cancels the right supervised child work within the shutdown budget, preserves intentional background semantics where required, emits diagnostics for remaining handles, and covers Ubuntu systemd plus process-supervisor tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: On normal gateway stop or SIGTERM, should OpenClaw terminate active supervised exec child processes, preserve background exec work, or add a narrower opt-in/diagnostic shutdown policy?

Rationale: Current source makes both sides real: dirty shutdowns are a production reliability bug, but existing tests and comments intentionally preserve active/background work on normal stop, so automation should not choose cancellation semantics without maintainer intent.

Likely owner: steipete

Owner reason: This handle has the strongest combined signal across recent gateway close, exec behavior, and prior review routing for the shutdown-policy decision.

Owner confidence: medium

Options:

- **Bound foreground cancellation (recommended):** Cancel non-background supervised exec work during normal shutdown, preserve explicit background sessions unless separately killed, and emit diagnostics for any remaining child handles.
- **Kill all supervised exec:** Treat gateway stop as an operator-owned hard boundary and terminate all supervised child process trees before the watchdog fires, accepting the upgrade behavior change.
- **Preserve current default:** Keep normal stop non-destructive and improve diagnostics or operator commands, accepting that long-running children may still force dirty shutdown until manually handled.

## Reproduction Assessment

No live current-main reproduction was run in this read-only pass. The reporter's Node diagnostics plus current source make the path source-reproducible: normal SIGTERM does not abort active runs, background exec can intentionally survive tool abort, and gateway close does not cancel supervised child scopes.

## Solution Assessment

Unclear until maintainers choose the shutdown policy. A bounded cancellation path for non-background supervised work plus diagnostics looks safer than either killing every child process or preserving the dirty-shutdown failure mode unchanged.
