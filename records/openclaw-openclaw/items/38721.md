## Summary

Keep open: current main still has the shutdown watchdog and still preserves active/background exec work on normal SIGTERM shutdown, so the child-process shutdown policy reported here is not implemented by the merged websocket-close or systemd-cgroup fixes.

## What This Changes

The issue asks OpenClaw to resolve dirty gateway shutdowns where active child-process handles can keep the process alive until the shutdown watchdog exits and later lane waits appear.

## Best Possible Solution

Define a normal gateway stop contract that rejects new work, bounds active run/session drains, cancels managed exec/process scopes before the watchdog, and documents any background-process class that should be preserved.
