## Summary

Keep open: current main still has the dirty-shutdown watchdog and still preserves active/background exec work during normal gateway stop, while the merged websocket shutdown fix addressed only an adjacent close hang. The remaining child-process shutdown policy needs maintainer direction and live Ubuntu/systemd proof before a fix PR is safe.

## What This Changes

The issue reports gateway shutdown timeouts on SIGTERM where Node diagnostic reports show active child-process and pipe handles, followed by dirty shutdown and lane waits.

## Best Possible Solution

Define one normal gateway stop contract that rejects new work, bounds active run/session drains, cancels selected managed child-process scopes before the watchdog, and documents any preserved background-process exception.

Rationale: Current source and tests intentionally preserve active/background exec work on normal shutdown, so changing that behavior is an operator-safety and product contract decision rather than a mechanical patch.

Options:

- **Define bounded managed-process shutdown (recommended):** On normal stop, reject new work and cancel maintainer-approved managed run/exec scopes before the watchdog, with an explicit documented exception for any background process class that should survive.

- **Defer to session exec-control design:** Keep this open until https://github.com/openclaw/openclaw/issues/12554 defines the process-control contract, then reuse that contract for gateway shutdown.
