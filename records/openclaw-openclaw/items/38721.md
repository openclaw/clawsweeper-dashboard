## Summary

Keep open: current main and v2026.6.11 still preserve active or background exec work during normal gateway shutdown, so the child-process shutdown timeout reported here remains unresolved and is distinct from the merged websocket-close fix.

## What This Changes

The issue asks for gateway shutdown to handle active child/subprocess handles cleanly, avoid dirty stop/restart and lane waits, and expose enough diagnostics to identify the stuck child command.

## Best Possible Solution

Define a normal gateway stop contract that rejects new work, bounds active run/session drains, cancels managed exec/process scopes before the watchdog, and documents any background-process class that should be preserved.

## Maintainer Decision

Question: Should normal SIGTERM/SIGINT gateway shutdown abort active runs and their managed exec child processes, or preserve background/yielded exec sessions unless an explicit restart or kill path is used?

Rationale: Current source and tests intentionally preserve active/background work on normal shutdown, so changing it is an operator-safety and product-policy choice rather than a mechanical cleanup.

Likely owner: vincentkoc

Owner reason: Vincent is the strongest current routing signal across the exec/background completion and current gateway behavior surfaces.

Owner confidence: high

Options:

- **Define bounded managed-process shutdown (recommended):** On normal stop, reject new work and cancel managed active run/exec scopes through the supervisor before the watchdog, with documented exceptions for any preserved background class.
- **Preserve current normal-stop behavior:** Keep normal shutdown from aborting active/background exec work and handle this as diagnostics or documentation rather than runtime cancellation.
- **Defer to session exec-control design:** Keep this open until https://github.com/openclaw/openclaw/issues/12554 defines the process-control contract, then reuse that contract for gateway shutdown.

No live high-confidence reproduction was established in this read-only review. The reporter supplied Node reports and current source shows normal shutdown preserves active/background exec work, but the exact child command still needs live Ubuntu/systemd proof.
