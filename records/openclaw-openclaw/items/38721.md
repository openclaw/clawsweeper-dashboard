## Summary

Keep open: current main still has the reported dirty-shutdown path by source inspection. Normal gateway stop does not abort active runs or call the process supervisor, while explicit background exec preservation is intentional; related websocket and launcher fixes do not cover this child-process handle blocker.

## What This Changes

The issue asks OpenClaw to diagnose and fix gateway shutdown timeouts caused by active child-process handles that survive normal stop or restart.

## Best Possible Solution

Define and test a normal-stop policy that bounds supervised child cleanup without silently destroying intentional background work, with diagnostics for any remaining handles.

## Maintainer Decision

Required: true

Kind: product_direction

Question: On normal gateway stop or SIGTERM, should OpenClaw terminate active supervised exec child processes, preserve background and active exec work, or add a narrower opt-in and diagnostic shutdown policy?

Rationale: Current tests intentionally preserve active runs on normal shutdown, while the report shows referenced child-process handles can force dirty shutdown; automation should not choose the product boundary between cleanup and preserving user-started background work.

Likely owner: mbelinky

Owner reason: They own the closest merged shutdown fix and already separated this issue from the websocket shutdown blocker in the issue discussion.

Owner confidence: medium

Options:

- **Bound foreground cancellation (recommended):** Cancel non-background active supervised exec work during normal shutdown, preserve explicit background sessions unless separately killed, and emit diagnostics for remaining handles.
- **Kill all supervised exec:** Make gateway stop a hard lifecycle boundary that terminates all supervised exec children before exit.
- **Preserve current default:** Keep background and active exec preservation as the default and add diagnostics or operator commands while accepting that long children can still cause dirty shutdown.

## Reproduction Assessment

Yes by source inspection, not live proof: current main preserves active runs on normal SIGTERM and has no gateway-close supervisor cancellation path, while the reporter supplied Node diagnostic evidence of referenced child-process handles.

## Solution Assessment

Unclear until maintainers choose the policy; bounded non-background supervised cancellation plus diagnostics looks safer than blanket process killing or preserving dirty shutdown behavior.
