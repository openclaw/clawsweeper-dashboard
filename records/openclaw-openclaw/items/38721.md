## Summary

## What This Changes

The issue reports gateway shutdown timeouts on OpenClaw 2026.3.2 where Node diagnostic reports show active child-process and pipe handles during systemd gateway stop.

## Best Possible Solution

Define a maintainer-approved normal-stop policy that cancels only the right supervised child work within the shutdown budget, preserves intentional background semantics where required, records diagnostics for remaining handles, and covers Ubuntu systemd plus process-supervisor tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: On normal gateway stop or SIGTERM, should OpenClaw terminate active exec child processes, preserve all background exec work, or add a narrower opt-in/diagnostic shutdown policy?

Rationale: Current source makes both sides real: dirty shutdowns are bad, but existing tests and comments intentionally preserve active/background work on normal stop, so automation should not choose cancellation semantics without maintainer intent.

Likely owner: steipete

Owner reason: This handle has the strongest current gateway/exec path and prior-review signal for the shutdown policy decision.

Owner confidence: medium

Options:

- **Bound foreground cancellation (recommended):** Cancel non-background active supervised exec work during normal shutdown, preserve explicit background sessions unless separately killed, and emit stability diagnostics for any remaining child handles.
- **Kill all supervised exec:** Treat gateway stop as an operator-owned hard boundary and terminate all supervised child process trees before the watchdog fires, accepting the upgrade behavior change.
- **Preserve current default:** Keep normal stop non-destructive and improve diagnostics or operator commands, accepting that long-running children may still force dirty shutdown until manually handled.

## Reproduction Assessment

No live high-confidence reproduction was run in this read-only pass. The report's Node diagnostics plus current source make the path source-reproducible: normal SIGTERM does not abort active runs, background exec is intentionally preserved, and no process-supervisor shutdown hook is wired into gateway close.

## Solution Assessment

Unclear until maintainers choose the shutdown policy. A bounded, tested cancellation path for non-background supervised work plus diagnostics looks safer than either killing every child process or preserving the current dirty-shutdown failure mode.
