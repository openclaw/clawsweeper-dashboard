## Summary

Keep open: current main and latest v2026.6.11 still preserve active/background exec work during normal SIGTERM shutdown, while the merged websocket-close fix only addressed an adjacent shutdown hang. The child-process shutdown policy remains unresolved and needs maintainer direction.

## What This Changes

The issue reports gateway shutdown timeouts on SIGTERM where active child-process and pipe handles appear to block cleanup and leave dirty shutdown plus lane-wait behavior.

## Best Possible Solution

Define a normal gateway stop contract that rejects new work, bounds active run and session drains, cancels managed exec/process scopes before the watchdog, and documents any preserved background-process exception.
