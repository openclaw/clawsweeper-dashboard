## Summary

Keep open: current main and v2026.6.11 still intentionally block ACP spawns from sandboxed requesters, and the open execution-backend work is adjacent rather than an implemented sandbox-to-ACP bridge.

## What This Changes

Request an opt-in, auditable way for sandboxed OpenClaw sessions to spawn or control ACP sessions without dropping the sandbox security boundary.

## Best Possible Solution

Keep the fail-closed guard until maintainers define an explicit opt-in sandbox-to-ACP bridge or execution-placement contract with allowlisting, audit controls, docs, tests, and live Docker/acpx proof.
