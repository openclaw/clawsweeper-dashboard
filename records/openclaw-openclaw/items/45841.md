## Summary

Keep open: current main and v2026.6.11 still intentionally block ACP spawns from sandboxed requester sessions, and the open execution-backend PR is adjacent contract work rather than a sandbox-to-ACP bridge. The remaining work needs maintainer product and security agreement before implementation.

## What This Changes

The issue requests an opt-in way for sandboxed OpenClaw sessions to spawn or control ACP harness sessions without dropping the sandbox boundary entirely.

## Best Possible Solution

Keep the fail-closed guard until maintainers define an explicit opt-in sandbox-to-ACP bridge or execution-placement contract with allowlisting, audit controls, docs, tests, and live Docker/acpx proof.
