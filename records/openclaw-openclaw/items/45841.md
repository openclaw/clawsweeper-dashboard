## Summary

Keep open: current main and v2026.6.11 still intentionally block ACP spawns from sandboxed requester sessions, and the remaining work is a security-boundary/product decision rather than conservative cleanup.

## What This Changes

Request to let sandboxed OpenClaw sessions spawn ACP sessions through sandboxed execution or a narrow host bridge/proxy.

## Best Possible Solution

Define one sandbox-aware ACP execution model with narrow spawn, steer, cancel, authorization, audit, workspace, secret, rate-limit, and cleanup semantics, then implement docs and tests for sandboxed requesters, `sandbox="require"`, slash ACP spawns, and upgrade-safe config behavior.

## Maintainer Decision

Question: Should OpenClaw support sandboxed requester sessions spawning ACP by running ACP inside a sandbox, by adding a narrow host-side bridge/proxy, or by folding this into the execution-backend placement contract?

Rationale: Changing the current block defines a sandbox-to-host trust boundary plus public config and model-facing tool semantics, so automation cannot safely choose the permanent security design.

Likely owner: steipete

Owner confidence: high

Options:

- **Design Sandbox-Aware ACP Boundary (recommended):** Define a narrow bridge or placement contract for ACP spawn, steer, and cancel with explicit auth, audit, workspace, secret, rate-limit, and cleanup rules before implementation.
- **Require Harnesses Inside Sandbox:** Keep the host-side ACP block and document installing Claude Code, Codex, or Gemini inside the OpenClaw sandbox container as the supported workflow for now.
- **Defer To Execution Backends:** Keep this issue as an acceptance case while the broader execution-backend placement design settles remote-worker and sandbox semantics.

## Reproduction Assessment

Yes, at source level: current main returns a forbidden runtime-policy error for sandboxed ACP spawns and for `sandbox="require"` with `runtime="acp"`. I did not run a live Docker ACP scenario because the source, tests, and docs describe the behavior explicitly.

## Solution Assessment

Unclear as a final implementation: the requested direction is valid, but a bare allow flag is not the safest fix. Maintainers should first choose whether this belongs in an ACP proxy, sandboxed harness execution, or the broader execution-backend placement contract.
