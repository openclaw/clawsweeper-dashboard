## Summary

Keep open: current main and the latest release still intentionally block ACP spawning from sandboxed requester sessions, and the remaining work is a security-sensitive product decision about how ACP should cross or share the sandbox boundary.

## What This Changes

Requested feature: allow sandboxed OpenClaw sessions to spawn and control ACP sessions through a safe sandbox/host boundary.

## Best Possible Solution

Choose a core sandbox-aware ACP execution design that keeps spawn/steer/cancel narrowly authorized and auditable, then implement docs and tests for sandboxed requester behavior, `sandbox="require"`, slash-command ACP spawns, and upgrade-safe config semantics.

Rationale: The next step defines a sandbox/host trust boundary plus public config and model-facing tool semantics, so automation cannot safely choose the permanent security design.

Likely owner: steipete

Owner confidence: high

Options:

- **Design Sandbox-Aware ACP Boundary (recommended):** Define a narrow bridge or placement contract for ACP spawn/steer/cancel with explicit auth, audit, workspace, secret, rate-limit, and cleanup rules before implementation.
- **Require Harnesses Inside Sandbox:** Keep the host-side ACP block and document running Claude Code, Codex, or Gemini inside the OpenClaw sandbox container as the supported workflow for now.
- **Defer To Execution Backends:** Keep this issue open as an acceptance case while the broader execution-backend placement design settles remote-worker and sandbox semantics.

## Reproduction Assessment

Yes, at source level: current main returns a forbidden runtime-policy error for sandboxed ACP spawns and for `sandbox="require"` with `runtime="acp"`. I did not run a live Docker ACP scenario because the source, tests, and docs describe the behavior explicitly.

## Solution Assessment

Unclear as a final implementation: the requested direction is valid, but the safest fix is not a bare allow flag. Maintainers should first choose whether this belongs in an ACP proxy, sandboxed harness execution, or the broader execution-backend placement contract.
