## Summary

Keep open: current main and v2026.6.11 still intentionally block ACP spawns from sandboxed requester sessions, and the remaining work is a security-sensitive product decision about the sandbox-to-ACP trust boundary.

## What This Changes

The issue asks OpenClaw to let sandboxed requester sessions spawn or control ACP harness sessions through a safe sandbox/host boundary.

## Best Possible Solution

Choose a core sandbox-aware ACP execution design that keeps spawn, steer, cancel, workspace, secrets, rate limits, and audit behavior narrowly authorized, then implement it with docs and tests for sandboxed requester behavior and sandbox="require" semantics.

Rationale: The next step defines a sandbox-to-host execution boundary plus public config and model-facing tool semantics, so automation cannot safely choose the permanent security design.

Options:

- **Design Sandbox-Aware ACP Boundary (recommended):** Define a narrow bridge or placement contract for ACP spawn, steer, and cancel with explicit auth, audit, workspace, secret, rate-limit, and cleanup rules before implementation.
- **Require Harnesses Inside Sandbox:** Keep the current host-side ACP block and document running Claude Code, Codex, Gemini, or other harnesses inside the OpenClaw sandbox container as the supported workflow.
- **Defer To Execution Backends:** Keep this issue open as an acceptance case while the broader backend/profile placement design settles remote-worker security and lifecycle semantics.

## Reproduction Assessment

Yes, at source level: current main returns a forbidden runtime-policy error for sandboxed ACP spawns and for sandbox="require" with runtime="acp". I did not run a live Docker ACP scenario because the documented/source behavior is explicit and the requested work is a feature/security design change.

## Solution Assessment

Unclear as an implementation: bridge, sidecar, nested sandbox, and broader execution-placement designs are all plausible. The best next step is maintainer product and security design before an autonomous patch.
