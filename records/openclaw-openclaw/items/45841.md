## Summary

Keep open: current main and v2026.6.11 still intentionally block ACP spawns from sandboxed requesters, and enabling this crosses a sandbox-to-host execution boundary that needs maintainer product and security design.

## What This Changes

Request to let sandboxed OpenClaw sessions spawn and control ACP harness sessions through sandboxed execution, a sidecar, or a controlled host bridge.

## Best Possible Solution

Keep the fail-closed guard until maintainers define an explicit opt-in sandbox-to-ACP bridge or execution-placement contract with requester allowlisting, spawn/steer/cancel scope, audit logs, rate limits, docs, tests, and live Docker/acpx proof.
