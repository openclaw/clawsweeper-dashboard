## Summary

Keep open. Current main and the latest release still lack a shared source-message edit/delete/recall lifecycle contract or native-message-id to active-run cancellation map; the active related work is channel-specific, open, closed-unmerged, or adjacent rather than a merged fix for the cross-channel request.

## What This Changes

The issue requests cross-channel support for message recall/delete and edit events so OpenClaw can cancel or supersede running agent tasks when the source message changes.

## Best Possible Solution

Define a minimal maintainer-approved source-message lifecycle contract, then implement channel-specific edit/delete/recall adapters and tests while keeping outbound message actions separate.

## Reproduction Assessment

Yes, at source level. Current main exposes source message ids and run/session abort primitives, but the inspected channel ingress, abort registry, Discord, and Telegram paths do not provide lifecycle events or source-message-to-active-run cancellation.

## Solution Assessment

No current implementation fully solves it. The maintainable path is a shared lifecycle contract where needed plus channel-specific handlers and tests; the open Discord PR is a useful slice but not a merged replacement for this cross-channel issue.
