## Summary

Keep open. Current main and the latest release still expose run/session abort primitives, but they do not provide a shared source-message edit/delete/recall lifecycle event or native-message-id to active-run cancellation map; the active related work is still channel-specific, open, proof-blocked, or adjacent.

## What This Changes

The issue requests support for native message recall/delete/edit events so channel users can cancel or update running agent tasks tied to the original message.

## Best Possible Solution

Define a minimal maintainer-approved source-message lifecycle contract, then implement channel-specific edit/delete/recall adapters and tests while keeping outbound message actions separate.

Question: Should OpenClaw add a shared source-message lifecycle contract for channel edit/delete/recall events, or keep these behaviors as channel-specific plugin features for now?

Rationale: Source inspection shows the gap is real, but the durable behavior changes session cancellation, transcript/context semantics, and plugin SDK boundaries across multiple messaging channels.

Likely owner: steipete

Owner confidence: high

Options:

- **Define shared lifecycle contract (recommended):** Add the smallest plugin/core contract needed for source message edit/delete/recall events, then let channels implement adapters against that contract.
- **Keep channel-specific slices:** Allow Discord, Signal, Telegram, Feishu, and WhatsApp to solve their own event behavior without a shared OpenClaw lifecycle API yet.
- **Defer until one channel lands:** Wait for a narrow, proven channel implementation before deciding whether the abstraction should be promoted into shared contracts.

## Reproduction Assessment

Yes, at source level. Current main exposes source message ids and run/session abort primitives, but the inspected contracts do not expose source-message edit/delete/recall lifecycle events or a native-message-id to active-run cancellation map.

## Solution Assessment

No current implementation fully solves it. The maintainable path is a shared lifecycle contract where needed plus channel-specific handlers and tests; the open Discord PR is a useful slice but not a merged replacement for the cross-channel issue.
