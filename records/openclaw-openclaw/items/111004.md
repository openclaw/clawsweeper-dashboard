## Summary

The current main branch still has an unbounded auth-profile JSON read, so this PR remains necessary. The latest branch addresses the earlier descriptor-race and symlink-compatibility concerns, includes focused coverage, and supplies a redacted live terminal probe; a human auth-store owner should still confirm that silently treating any existing store above 10 MiB as unavailable is the intended persisted-profile compatibility contract before merge.

## What This Changes

The PR caps auth-profile JSON reads at 10 MiB through the regular-file policy wrapper and adds oversized-file and symlinked-store coverage for both current and legacy auth stores.

## Best Possible Solution

Keep the descriptor-bounded read and symlink-preserving path, but land only after the auth-store owner confirms that a 10 MiB existing-store cap with the current null/no-credentials outcome is the desired compatibility contract.
