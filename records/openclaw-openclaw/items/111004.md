## Summary

Keep open: the security-hardening intent is sound, but the pathname-based `statSync` check is not bound to the subsequent read, so it does not reliably prevent the stated hostile/corrupt-store availability failure.

Likely related people: `steipete` and `vincentkoc` are medium-confidence routing candidates from recent auth-profile and auth-runtime history.

## What This Changes

Adds a 10 MiB pre-read size check and regular-file check for auth-profile JSON stores, with tests for oversized current and legacy files.

## Best Possible Solution

Open the file once, inspect that file descriptor, and perform a bounded descriptor read that detects more than 10 MiB before parsing; preserve the current null-on-read-failure behavior.
