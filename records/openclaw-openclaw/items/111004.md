## Summary

The updated branch still checks a pathname with `statSync` and then rereads that pathname, so a replace-or-grow race can bypass the 10 MiB cap; focused tests also remain mock-only proof for merge purposes.

## What This Changes

The PR adds a 10 MiB pre-read limit and regular-file check for current and legacy auth-profile JSON stores, plus tests for already-oversized files.

## Best Possible Solution

Read through one opened descriptor with a hard byte-bounded read, reject data beyond the cap before parsing, add deterministic race/growth coverage, and attach redacted terminal or runtime proof from a real temporary agent profile store.
