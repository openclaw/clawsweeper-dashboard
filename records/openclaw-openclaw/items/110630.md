## Summary

Keep this PR open for maintainer handling. The durable-ingress direction is appropriate for preventing Zalo crash-window message loss, but the current head still has two concrete lifecycle regressions identified in the PR review: ignored valid webhook events can be retried indefinitely, and shutdown can permit duplicate concurrent redelivery. It also lacks after-fix proof from a real Zalo webhook environment.

## What This Changes

This PR replaces Zalo’s in-memory webhook replay guard with durable raw-envelope admission and a shared ingress drain for retry, restart recovery, and tombstones.

## Best Possible Solution

Preserve durable-before-ack admission, but explicitly acknowledge valid unsupported/no-message events and retain the drain owner until all active deliveries and deferred claims settle; then demonstrate a redacted real Zalo delivery and restart-redelivery sequence before merge.
