## Summary

Keep this PR open: the current UI branch treats every generic `open-agent` handoff as a fresh-install hatch and omits the required chat session when adding the hatch draft, so the stated web onboarding outcome is not reliably delivered. The `maintainer` label also requires explicit maintainer handling rather than cleanup closure.

## What This Changes

The PR makes a successful fresh `setup` operation hand users from the system-agent flow into the newly created agent and adds a bootstrap-greeting draft for the web custodian handoff.

## Best Possible Solution

Use an explicit additive hatch discriminator from the system-agent/gateway handoff, consume it only for the fresh-setup path, and navigate with the active agent-chat session plus draft; cover both ordinary handoffs and the full fresh web setup path.
