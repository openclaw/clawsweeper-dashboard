## Summary

Keep open: the PR targets a valid backup reliability gap, but the current diff broadens state-wide `.lock` and `.partial` skips enough to silently omit durable installed-plugin files from backups, and the contributor proof is test-only rather than a real archive run.

## What This Changes

The branch extends the backup volatile-path filter, summary/docs text, and tests to skip agent runtime caches, browser cache paths, retired archives, and additional transient sidecars.

## Best Possible Solution

Merge a narrow centralized backup filter that excludes disposable runtime/cache/archive paths while preserving durable browser profile and installed plugin source files, backed by a real backup archive proof.

## Reproduction Assessment

Yes, at source level: current main's `isVolatileBackupPath` lacks the requested agent runtime cache, browser cache, retired archive, and wider sidecar rules, while `createBackupArchive` relies on that predicate during tar creation. I did not run a live disappearing-file race repro.

## Solution Assessment

No. Extending the centralized filter is the right layer, but this implementation makes `.lock` and `.partial` whole-state rules; the safer fix scopes sidecars to transient roots and proves durable plugin/browser state remains included.
