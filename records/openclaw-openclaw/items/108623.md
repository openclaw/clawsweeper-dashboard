## Label Justifications

- `P0`: As written, deleting an agent with a custom state directory can trash unrelated user files in the configured directory's parent.
- `merge-risk: 🚨 compatibility`: Existing custom `agentDir` configurations can change from deleting explicit agent state to deleting the entire containing directory.
- `merge-risk: 🚨 security-boundary`: The patch broadens a destructive filesystem operation to a derived parent path without ownership, containment, or emptiness checks.

## Summary

Keep this PR open for repair: the cleanup intent is valid, but deriving a recursive trash target from configurable `agentDir` can remove unrelated parent-directory contents in custom layouts.

## What This Changes

The PR adds best-effort cleanup of the per-agent parent state directory after deleting its agent and session subdirectories through both CLI and Gateway paths.

## Best Possible Solution

Resolve the canonical OpenClaw-owned `state/agents/<agentId>` root independently of configurable `agentDir`, and remove it only when containment and emptiness checks both succeed; custom paths and unexpected sibling contents must remain untouched.
