## Label Justifications

- `P1`: The current revision can race with same-id agent creation and move newly created session state to Trash.
- `merge-risk: 🚨 session-state`: Merging the check-then-trash sequence can remove a newly recreated agent's sessions directory after it has been created.
- `merge-risk: 🚨 security-boundary`: The patch expands filesystem deletion to a parent directory, and the emptiness boundary is not enforced atomically at removal time.

## Summary

The follow-up correctly stops custom agent-directory parents from being trashed, but the new emptiness check is separated from the recursive trash operation. A concurrent recreation of the same agent can add `sessions/` after the check and have the newly created state moved to Trash, so this PR still needs a narrow safety repair before merge.

## What This Changes

The PR adds canonical-path and emptiness-guarded cleanup of the per-agent parent state directory after CLI and Gateway agent deletion, with regression tests for default and custom agent directories.

## Best Possible Solution

Replace the check-then-trash sequence with one shared best-effort helper that verifies the canonical path and uses an atomic empty-directory removal operation that fails with `ENOTEMPTY`; keep custom paths and any repopulated directory untouched, and exercise the real helper in focused filesystem tests.
