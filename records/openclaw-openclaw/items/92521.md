## Summary

This PR remains necessary because current main captures a restrictive child inheritance cap before asynchronous MCP/LSP tools materialize. The revised concrete post-filter refresh is safer than the related selector-preservation or inheritance-removal approaches, and this review found no blocking correctness defect.

## What This Changes

The PR updates spawned-subagent inheritance so authorized MCP/LSP tools materialized at runtime are added to the child cap only after the parent’s final policy and schema filters.

## Best Possible Solution

Keep parent-to-child least privilege by deriving the mutable child cap from concrete final effective tools after every deny, normalization, compatibility, and quarantine layer, without preserving broad runtime selectors or removing inheritance.
