## Summary

Keep open: current main and v2026.6.11 still expose a single preselected ack reaction value, while array/random/contextual selection would add a new cross-channel config or SDK contract that needs maintainer product direction.

## What This Changes

Add configurable or contextual ack reaction emoji selection instead of using one fixed `ackReaction` value for every acknowledged inbound message.

## Best Possible Solution

Preserve the shipped `ackReaction` string contract and add one maintainer-approved shared array or selector strategy across config types, strict schemas, docs, SDK/channel seams if needed, and bundled-channel tests.
