## Summary

Keep open: current main and v2026.6.11 still support one preselected ack reaction string, while arrays or contextual selection would add a cross-channel config/API contract that needs maintainer product direction.

## What This Changes

The issue requests configurable or dynamic acknowledgement reaction emojis, either from a configured emoji list or from per-message contextual selection.

## Best Possible Solution

Preserve the shipped ackReaction string contract and add one maintainer-approved shared array or selector strategy across config types, strict schemas, public docs, SDK/channel seams if needed, and bundled-channel tests.
