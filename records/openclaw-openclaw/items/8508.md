## Summary

Keep open: current main and v2026.6.11 still resolve one preselected acknowledgment reaction, while list-based or contextual selection would add a shipped cross-channel configuration and behavior contract. ## What This Changes

Allow acknowledgment reactions to vary from a configured set or be selected contextually per inbound message.

## Best Possible Solution

Keep the existing string contract as the default; if sponsored, add an opt-in deterministic configured-list strategy with explicit account/channel precedence, transport validation and fallback, focused bundled-channel tests, and docs before considering model-driven selection.
