## Summary

Current main and v2026.6.11 still support only one preselected acknowledgment reaction string. The direct randomization PR closed unmerged, and the remaining cross-channel selection semantics require explicit maintainer product direction.

## What This Changes

Allow acknowledgment reactions to use configured alternatives or per-message contextual selection instead of one fixed emoji.

## Best Possible Solution

Preserve existing string and explicit-disable behavior, then add an additive configured selector only after maintainers define deterministic selection semantics and require each channel owner to validate or fall back from the selected reaction.

- **Model-Selected Reaction:** Add a pre-processing model decision hook and accept extra latency, nondeterminism, and a broader runtime contract.
- **Keep Singular Values:** Retain predictable per-account, per-channel, and global acknowledgment strings without dynamic selection.
