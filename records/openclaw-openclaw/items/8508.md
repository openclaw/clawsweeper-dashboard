## Summary

Keep open: current main and the latest release still expose a single preselected ack reaction value, while array-based or contextual selection would add a cross-channel config/API contract that needs maintainer product direction.

## What This Changes

The issue requests native support for configurable or dynamic acknowledgement reaction emoji selection instead of one fixed `ackReaction` value.

## Best Possible Solution

Preserve the shipped `ackReaction` string contract and add one maintainer-approved shared array or selector strategy across config types, schemas, docs, SDK/channel seams if needed, and bundled-channel tests.
