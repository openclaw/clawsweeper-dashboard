## Summary

Current main and v2026.6.11 still resolve one deterministic initial acknowledgment emoji; lifecycle status reactions add varied queued/thinking/tool/done feedback, but they do not implement configured-list or content-aware initial selection, so the requested product choice remains open.

## What This Changes

Allow automatic acknowledgment reaction emojis to be selected from configured alternatives or dynamically from message context.

## Best Possible Solution

Keep the deterministic initial ack plus lifecycle status reactions unless maintainers approve one additive, predictable cross-channel selection contract; if approved, preserve the existing string form and precedence while specifying selection and fallback behavior before implementation.
