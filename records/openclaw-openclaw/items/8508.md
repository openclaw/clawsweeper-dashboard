## Summary

Keep open: current main and v2026.6.11 still expose one preselected ack reaction string, while array-based or contextual selection would add a cross-channel config/API contract that needs maintainer product direction.

## What This Changes

Request to let acknowledgment reactions vary through a configured emoji array or contextual per-message selection instead of one static `ackReaction` string.

## Best Possible Solution

Preserve the shipped single-string `ackReaction` contract and add one maintainer-approved, backward-compatible shared array or selector strategy across config, schema, docs, SDK/channel seams if needed, and bundled-channel tests.

- **Design a plugin/channel hook first:** Extend a typed plugin/channel seam before growing core config if maintainers want extension-owned pre-ack selection behavior.
