## Summary

Keep open: current main and v2026.6.11 still support only one preselected acknowledgment reaction, while list-based or contextual selection would add a public cross-channel configuration contract requiring maintainer product direction.

## What This Changes

Allow acknowledgment reactions to vary from a configured emoji set or be selected contextually for each inbound message.

## Best Possible Solution

If approved, extend the existing resolver with backward-compatible string-or-nonempty-list values, select one validated reaction locally before processing, preserve current precedence and cleanup behavior, and defer model-driven contextual choice to a separate future design.
