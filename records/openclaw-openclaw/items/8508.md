## Summary

Keep open for maintainer direction: current main still accepts only one preselected initial acknowledgment reaction. Lifecycle status reactions provide adjacent queued/thinking/tool/done feedback, but they do not choose the initial ack from a configured set or from inbound message context.

## What This Changes

Allow acknowledgment reactions to vary per inbound message through a configured emoji set or contextual selection instead of always using one fixed value.

## Best Possible Solution

Preserve `ackReaction` as the fast deterministic default; if maintainers approve this direction, add an opt-in bounded emoji-choice strategy with selection performed before channel encoding, explicit per-channel fallback rules, and no extra model call on the acknowledgment path.
