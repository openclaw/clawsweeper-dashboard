## Summary

Keep open for a maintainer product decision. The supplied July 18 current-main review and issue discussion show that acknowledgements still use one pre-processing reaction value; a pool or contextual chooser would add a compatibility-sensitive configuration and channel-fallback contract rather than repair broken existing behavior.

## What This Changes

Add configurable or contextual acknowledgement reaction emojis so OpenClaw can vary the reaction sent before processing an inbound message.

## System Context

Inbound channel messages resolve an acknowledgement reaction before normal agent processing begins. The shared reaction helper sends that value through each channel adapter and later removes or updates it according to the configured lifecycle.

## Architecture Diagram

  A --> G[Agent processing]

## Best Possible Solution

Choose a backward-compatible, deterministic configured-pool contract first—preserving `ackReaction`—or explicitly decline the feature; avoid model-driven selection unless maintainers intentionally redefine pre-processing acknowledgement timing and failure behavior.
