## Summary

Keep open for an explicit product decision: current main and the latest release retain a single preconfigured acknowledgment reaction, while contextual or multi-emoji selection remains a distinct, engaged feature request with no canonical implementation PR.

## What This Changes

Allow acknowledgment reactions to be selected from multiple configured emojis or chosen contextually for each inbound message.

## Best Possible Solution

Preserve ackReaction as the backward-compatible fixed default and, if maintainers sponsor the feature, add one additive channel-aware emoji-list contract with an explicit local selection strategy and tested fallback behavior; defer model-driven pre-ack selection unless a latency-safe generic hook is intentionally approved.

## Maintainer Decision

Question: Should OpenClaw add an additive multi-emoji acknowledgment contract, and if so should initial selection be deterministic, random, rule-based, or model-driven?

Rationale: The current config and channel APIs do not establish selection semantics, while each option changes latency, predictability, compatibility, and configuration complexity.

Likely owner: steipete

Owner confidence: high

Options:

- **Add local strategy (recommended):** Keep ackReaction compatible and add an optional emoji list with a deterministic, round-robin, or random local selector that performs no model call.
- **Add model-driven selection:** Introduce a pre-ack model or agent hook, accepting additional latency, cost, and failure behavior before acknowledgment appears.
- **Keep fixed reactions:** Retain static global, channel, and account-level configuration and close the contextual-selection direction as unnecessary complexity.

## Reproduction Assessment

Yes at the source-contract level: current main accepts and resolves only one acknowledgment reaction string, so the requested list or contextual selector is demonstrably absent. This is a missing feature rather than a failing existing behavior reproduction.

## Solution Assessment

No, unrestricted model-driven selection is not yet the best default because acknowledgment happens before normal processing and channel emoji formats differ. An additive local strategy over a configured list is the narrower, more predictable starting point if maintainers approve the feature.
