## Summary

Keep this PR open: its string-equality check still misses repeated Content-Length values with the same decimal value but different leading-zero spelling, so the claimed early rejection remains incomplete for valid repeated values such as `17, 017`.

## What This Changes

The PR updates the TypeScript and JavaScript bounded-response helpers to use repeated matching comma-combined Content-Length values for early size rejection and adds matching/conflicting-header tests.

## Best Possible Solution

Normalize each syntactically valid decimal list member to a canonical numeric spelling before comparing them, retain streaming enforcement for conflicting or malformed values, and cover both TypeScript and MJS helpers with `17, 017` pre-read rejection evidence.
