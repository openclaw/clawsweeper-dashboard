## Summary

The PR addresses a reproduced current-main Anthropic retry defect at the correct transport/session boundary, but the prior blocking finding remains on the unchanged head: overflowed Retry-After values are intentionally parsed as positive infinity and then discarded by the new finite-only error extractor, causing the session to fall back to a short exponential retry. The ordinary finite-wait proof is strong, CI is green, and the remaining repair is narrow; this PR should stay open for that fix rather than be closed or superseded.

## What This Changes

The PR adds Anthropic HTTP status and Retry-After metadata to transport errors and assistant messages, then uses the existing provider retry maximum to bound in-turn auto-retry delays.

## Best Possible Solution

Use a closed, transport-neutral representation for server retry guidance that can distinguish absent, finite, and over-limit values through AssistantMessage; enforce retry.provider.maxRetryDelayMs once in retry resolution and add a real parser-to-transport-to-session regression for overflowed numeric headers.
