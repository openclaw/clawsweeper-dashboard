- `P1`: The PR addresses and currently risks a broken ACP turn workflow where prolonged disconnects can silently lose or indefinitely stall an in-flight prompt.
- `merge-risk: 🚨 session-state`: The changed deadline settlement controls whether an active run is cleared and whether its terminal notice is durably associated with the correct ACP session and run.

## Summary

The core fix is directionally right, but the new grace-expiry path awaits ACP client delivery before rejecting the prompt, so an unresponsive client can turn the five-second disconnect deadline into an unbounded hang; real ACP runtime proof is also still missing.

## What This Changes

The PR emits and records an outcome-unknown ACP interruption before rejecting prompts that remain pending when the Gateway disconnect grace expires, with focused live-update and ledger-replay tests.

## Best Possible Solution

Record the interruption durably without making deadline rejection wait on ACP transport delivery, preserve run-scoped exactly-once settlement, add a blocked-delivery regression test, and show a redacted real ACP disconnect plus `session/load` replay transcript before merge.
