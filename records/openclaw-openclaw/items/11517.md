## What This Changes

Request a staged refactor that reduces direct import coupling in the embedded agent-attempt runner and Discord message-monitor code.

## System Context

OpenClaw’s embedded runner prepares and executes agent turns, then projects results back to routing and channel delivery. Discord’s monitor turns inbound Discord events into the same agent-run and reply pipeline, so both areas depend on shared runtime policy but have separate ownership boundaries.

## Architecture Diagram

flowchart TD
  Inbound[Inbound user event] --> Discord[Discord monitor]
  Discord --> Routing[Routing and session preparation]
  Routing --> Runner[Embedded agent runner]
  Runner --> Phases[Attempt preparation and execution phases]
  Phases --> Outcome[Terminal outcome and reply delivery]
  RuntimePlan[Shared runtime policy] --> Runner

## Best Possible Solution

Retain the issue only as a narrowly scoped Discord-monitor cleanup, with the embedded-runner work linked to the RuntimePlan roadmap and pursued through small behavior-preserving phase extractions rather than a new global RunContext.
