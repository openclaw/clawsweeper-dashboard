## What This Changes

The issue reports that a built-in OpenClaw runtime agent with an empty local auth store cannot use inherited main-agent OpenAI OAuth on `openai-chatgpt-responses`, while `main` succeeds with the same forced profile.

## Best Possible Solution

Keep main-agent OAuth read-through as the supported behavior and fix the built-in OpenClaw ChatGPT responses auth handoff so an inherited profile behaves like the owning main profile without adding config or copying refresh tokens.
