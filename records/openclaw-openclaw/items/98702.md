## Summary

Keep open: current main has adjacent ChatGPT Responses session-affinity and auth-bootstrap work, but the latest reporter evidence shows a fresh local per-agent OAuth grant plus full gateway restart still fast-fails for non-main built-in `openclaw` runtime agents, so the central provider-auth problem is not proven fixed.

## What This Changes

A non-main built-in OpenClaw runtime agent using `openai-chatgpt-responses` should authenticate with OpenAI OAuth consistently with the `main` agent.

## Best Possible Solution

Fix the native OpenClaw ChatGPT Responses runtime so non-main forced and auto-selected OAuth profiles carry the same provider-required auth, account, session, and request context as `main`, with focused regression tests and live OAuth `models status --probe` proof.
