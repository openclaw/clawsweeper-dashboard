## Summary

Keep open: current main still has the node-host stream-error crash gap, and the PR adds useful handling plus proof, but it still completes `system.run` as soon as stdout/stderr emits an error instead of waiting for the child lifecycle to finish.

## What This Changes

The PR adds stdout/stderr `error` handlers to node-host `runCommand`, exposes `runCommand` through a `testing` export, and adds a focused regression test plus proof script.

## Best Possible Solution

Keep the stream-error guard, but record the pipe failure and make child exit or close the authoritative completion path, killing the child if output capture is no longer trustworthy and adding regression proof for long-lived children.

## Solution Assessment

No. The PR addresses the crash path, but resolving `runCommand` from the stream error is too early; the best fix keeps child exit/close authoritative and reports the stream failure after the child is stopped or observed exiting.
