Full review comments:

- **[P2] Thread Android global controls through the owner agent:** `apps/android/app/src/main/java/ai/openclaw/app/chat/ChatController.kt:299-313`
  - body: For a displayed selected-global row, this payload sends only `key: "global"`; the gateway resolves unscoped global mutations to the default agent, so Android rename/group/pin/archive/unread/delete can update the wrong global row. Carry the row's owner agent into `ChatSessionEntry` or scope the list, then include `agentId` in these RPCs.
  - confidence: 0.9
- **[P2] Hide Android delete for agent main rows:** `apps/android/app/src/main/java/ai/openclaw/app/ui/SessionsScreen.kt:491-493`
  - body: The new menu exposes Delete for every non-archived row, including `agent:work:main`. The gateway only blocks the default main key, so deleting a non-default agent main removes the anchor session and leaves Android falling back to a missing main alias; gate Delete with the same main/global/unknown protection used for archive.
  - confidence: 0.89
- **[P2] Pass the parent agent when forking from Sessions:** `ui/src/pages/sessions/sessions-page.ts:598-602`
  - body: `sessionAgentId(key)` only returns a scoped agent for global/main aliases, so forking a normal non-default row such as `agent:work:dashboard:123` omits `agentId`. The gateway then creates the fork under the default agent instead of the parent agent, unlike the intended transcript fork semantics.
  - confidence: 0.85
- **[P2] Scope Sessions-page unread toggles to row ownership:** `ui/src/pages/sessions/view.ts:1323`
  - body: This unread toggle passes only `row.key`; for combined-list global rows, row ownership is not preserved, and `SessionsPage.patchSession` falls back to the selected/default agent. Mark read/unread can therefore mutate a different global session than the row the user clicked.
  - confidence: 0.87
