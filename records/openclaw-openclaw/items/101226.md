## Summary

Keep this PR open: the latest head fixed the two prior blockers around missing target-run abort and over-broad explicit-run cleanup, but the session-scoped cleanup is still key-only and the contributor has not supplied real Gateway proof for the subprocess-stop behavior.

## What This Changes

The PR adds target-run abort, queue clearing, and requester subagent stopping after successful session-scoped `chat.abort`, while leaving explicit `runId` abort scoped to the matched run.

## Best Possible Solution

Reuse the `/stop` identity resolution for `chat.abort`: pass the stored session id into matching, target-run abort, and queue cleanup, keep explicit `runId` abort scoped to one run, and require redacted live stop proof before merge.
