## Summary

Keep this PR open, but it is not merge-ready: it adds some cleanup after `chat.abort`, yet it skips the target embedded-run abort that stops the primary tool subprocess and broadens explicit `runId` aborts into whole-session cleanup. The branch also only provides test output, not after-fix real behavior proof from a live gateway/subprocess scenario.

## What This Changes

The PR adds queue clearing and subagent stopping after successful `chat.abort` session and run-id aborts in `src/gateway/server-methods/chat.ts`.

## Best Possible Solution

Share the `/stop` target-abort semantics with `chat.abort`: resolve the stored session id, abort the matched reply/embedded run, clear only intended queues, preserve explicit `runId` scope, and prove it with a live long-running subprocess abort.
