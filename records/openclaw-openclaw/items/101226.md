## Summary

Keep this PR open but not merge-ready: the current head still re-raises the existing P1 blocker because session-scoped cleanup only uses the canonical session key, while the established `/stop` cleanup carries the stored session id as well. The PR adds existing auto-reply abort, queue-clear, and subagent-stop helpers to the session-scoped `chat.abort` handler after a successful abort.

## Best Possible Solution

Reuse the `/stop` identity resolution for `chat.abort`: pass the stored session id into target-run abort and queue cleanup, keep explicit `runId` abort scoped to one run, and require redacted live stop proof before merge.
