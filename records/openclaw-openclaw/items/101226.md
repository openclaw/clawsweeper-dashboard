## Summary

Keep this PR open, but it is not merge-ready: the branch adds queue/subagent cleanup after `chat.abort`, yet still misses the target embedded-run abort step that gives `/stop` its subprocess-stop behavior, and the explicit `runId` path broadens a one-run abort into whole-session cleanup. The only contributor proof is unit test output, so real Gateway behavior proof is still needed before merge.

## What This Changes

The branch adds `clearSessionQueues` and `stopSubagentsForRequester` calls after successful session-key and explicit-run `chat.abort` paths in `src/gateway/server-methods/chat.ts`.

## Best Possible Solution

Share the `/stop` target-abort semantics with `chat.abort`: resolve the stored session id, abort the matched reply/embedded run, clear only intended queues, preserve explicit `runId` scope, and prove the live subprocess-stop behavior.
