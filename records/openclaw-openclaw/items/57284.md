## Summary

Keep open: current main still treats `openclaw agent --deliver` as agent-reply delivery rather than direct notification sending, while direct session injection remains a separate product/security decision. The same-repo direct-delivery PRs were closed unmerged, and an open cross-repo candidate still references this issue but is not a merged fix path.

## What This Changes

Request that `openclaw agent --deliver` send the original message directly like `message send`, plus a direct session-injection path for waking sessions without an LLM turn.

## Best Possible Solution

Keep `message send` as the deterministic outbound notification path unless maintainers explicitly add a separate direct mode, and design session injection as a distinct security-reviewed API.

## Reproduction Assessment

Yes at source level: current main routes `--deliver` through an agent turn and delivers only agent-produced payloads, with tests proving `NO_REPLY` becomes suppressed no-visible-payload status. I did not run a live Signal delivery test in this read-only review.

## Solution Assessment

No for the requested direct rewrite as-is: current docs and maintainer discussion point to `message send` for literal channel sends, while direct session injection needs a separate authorized API design.
