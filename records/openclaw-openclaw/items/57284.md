## What This Changes

## Best Possible Solution

Keep `message send` as the direct notification path unless maintainers approve a separate explicit direct mode, and design session injection as its own authorized API with clear delivery/status semantics.

No, not as originally requested: redefining `agent --deliver` as literal send duplicates `message send` and conflicts with the current documented command boundary. A separate direct mode or session-injection API needs maintainer product and security approval first.
