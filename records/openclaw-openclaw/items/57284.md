## Summary

Keep open: current main and the latest available release still define `openclaw agent --deliver` as delivery of an agent-produced reply, while the linked direct-delivery PRs were closed unmerged and the remaining session-injection portion needs product and security design.

## What This Changes

The issue asks for `openclaw agent --deliver` to reliably deliver original notification text or wake/inject into an agent session instead of depending on a model-generated reply.

## Best Possible Solution

Keep `agent --deliver` as agent-reply delivery, use `message send` for direct channel notifications, and design any session injection as a separate authorized API if maintainers approve it.

## Reproduction Assessment

Yes, at source level: current main routes `--deliver` through an agent run and delivers only produced payloads, but I did not run a live Signal or Telegram delivery command in this read-only review.

## Solution Assessment
