## Summary

Keep this open: current main and the latest release still accept and store channel-id-looking values in cron channel-type fields, and the linked closing PR is still open and waiting on author changes.

## What This Changes

The issue requests early cron add/edit feedback when a channel id is passed to `--channel` or `--failure-alert-channel`, plus clearer flag help that distinguishes channel type from destination id.

## Best Possible Solution

Land or revise the linked PR so cron add/edit warn about likely channel-id misuse while preserving valid bundled, loaded, and configured external channel types.
