## Summary

This issue should remain open: current main and v2026.6.11 still store cron channel-type flag values without validating them, and the linked open PR is the right implementation candidate but has not merged.

## What This Changes

The issue asks OpenClaw to reject channel IDs passed to cron channel-type flags and update help text to distinguish channel type from destination ID.

## Best Possible Solution

Land or revise the linked PR so cron add/edit validate channel-type flags against known bundled and loaded channel types and give `--to` / `--failure-alert-to` guidance before writing jobs.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source inspection: current main accepts and stores the channel flag values without known-channel-type validation, while the help can render `last|<channel-id>`. I did not run a live CLI repro in this read-only cleanup review.

## Solution Assessment

Yes, the best fix belongs at cron CLI add/edit parsing before `cron.create` or `cron.update` writes the job. The fix should reject unknown channel types, preserve valid built-in/loaded plugin types, and regression-test that invalid values make no gateway call.
