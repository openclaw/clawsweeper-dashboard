## Summary

Keep open. Current main and v2026.6.11 still preserve or materialize Telegram single newlines instead of collapsing model hard-wraps, and the remaining work is a Telegram formatting policy choice.

## What This Changes

Request to collapse single mid-paragraph Telegram newlines before outbound delivery while preserving intentional breaks.

## Best Possible Solution

Define a Telegram-owned, Markdown-aware soft-wrap policy, preferably opt-in, that collapses prose hard-wraps while preserving blank lines, code/pre blocks, blockquotes, list semantics, rich messages, and plain fallback behavior.

- **Make Collapse Default:** Change Telegram output globally to collapse detected soft wraps, accepting compatibility risk for users who rely on single-newline preservation.
- **Keep Preservation Behavior:** Confirm preserving model newlines is the intended Telegram behavior and close this direction in favor of prompts or formatting guidance.

## Reproduction Assessment

Yes at source level: current main preserves Markdown softbreaks as literal newlines and the Telegram rich path materializes them as <br>, so the requested collapse policy is absent. I did not run a live Telegram client reproduction in this read-only review.

## Solution Assessment

Unclear as a product choice. The Telegram plugin is the right owner, but unconditional collapse conflicts with newline-preservation behavior while the safer opt-in path adds compatibility-sensitive config surface.
