## Summary

Keep open. Current main and v2026.6.11 still preserve or materialize Telegram single newlines rather than collapsing soft wraps, and related rich-message fixes intentionally protect line-break preservation, so this remains a Telegram product/config decision rather than conservative cleanup.

## What This Changes

The issue requests Telegram-specific normalization that collapses single mid-paragraph/list soft newlines before sending while preserving intentional double-newline breaks.

## Best Possible Solution

Define a Telegram-owned newline policy that distinguishes model soft wraps from intentional hard line breaks, with maintainer-approved default/config behavior and coverage for rich, legacy HTML, lists, blockquotes, and code/pre content.

## Reproduction Assessment

Yes, at source level: current Telegram send paths preserve or materialize single newlines and there is no collapse-newlines config surface. I did not run live Telegram visual proof in this read-only cleanup review.

## Solution Assessment

Unclear as product policy: the Telegram formatter/send boundary is the right owner, but a default-on collapse can regress users who depend on preserved line breaks, while a setting adds compatibility-sensitive config surface.
