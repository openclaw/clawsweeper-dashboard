## Summary

Keep open. Current main and the latest release still do not provide Telegram soft-newline collapse behavior; current rich-message work intentionally preserves line breaks, so the remaining work is a maintainer product/config decision rather than cleanup-closeable stale work.

## What This Changes

The issue requests Telegram-specific normalization that collapses soft single newlines inside prose while preserving intentional paragraph breaks.

## Best Possible Solution

Define a Telegram-owned, Markdown-aware soft-line-break normalization policy with a maintainer-approved default or opt-in setting, preserving blank lines, code/pre blocks, blockquotes, lists, rich messages, and plain fallback behavior.

## Reproduction Assessment

Yes, at source level: current Telegram delivery preserves Markdown softbreaks, and the rich path materializes them as `<br>` rather than collapsing them. I did not run a live Telegram client reproduction in this read-only review.

## Solution Assessment

Unclear as a product choice: the Telegram plugin is the right owner, but unconditional collapse conflicts with existing newline-preservation behavior while a new option adds config surface.
