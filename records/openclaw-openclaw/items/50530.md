## Summary

Keep open. Current main still has no Telegram policy or config that collapses model hard-wrap newlines inside prose/list items, and recent rich-message work intentionally preserves line breaks, so this remains a maintainer product/config decision rather than cleanup-closeable.

## What This Changes

The issue requests Telegram-specific normalization that collapses single soft newlines inside paragraphs or list items while preserving intentional double-newline breaks.

## Best Possible Solution

Define a Telegram-owned, Markdown-aware soft-line-break policy with an explicit maintainer decision on default versus opt-in behavior, preserving blank lines, code/pre blocks, blockquotes, rich messages, and the plain fallback path.

## Reproduction Assessment

Yes, at source level. Current main preserves Markdown softbreaks as literal newlines and the Telegram rich path now materializes them as `<br>`; I did not run a live Telegram client reproduction in this read-only review.

## Solution Assessment

Unclear as a product choice. The Telegram plugin is the right owner, but unconditional collapse conflicts with newline-preservation behavior while an opt-in setting adds compatibility-sensitive config surface.
