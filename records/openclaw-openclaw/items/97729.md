## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Keep exec-approval relays behind pairing approval:** `src/gateway/server-methods/exec-approvals.ts:145-166`
  - body: This branch falls through to `nodeRegistry.invoke` whenever the node raw-declared `system.execApprovals.*` and the gateway did not explicitly deny it. For a first-connect node, `reconcileNodePairingOnConnect` leaves `nodeSession.commands` empty until pairing approval, and the public pairing docs say pending node commands do not execute before approval; forwarding based on raw `declaredCommands` bypasses that boundary. The preflight should reject unless the effective approved `nodeSession.commands` contains the requested exec-approval command.
  - confidence: 0.93
- **[P1] Pair exec-approval defaults with admin pairing scope:** `src/gateway/node-command-policy.ts:120-122`
  - body: Adding `system.execApprovals.get/set` to the platform defaults makes these sensitive commands part of the pairing command surface, but current `resolveNodePairApprovalScopes` only escalates `NODE_SYSTEM_RUN_COMMANDS` to `operator.admin`; other commands still need only `operator.write`. Either leave this advertisement change to the maintainer draft or include the matching admin-scope pairing authz and focused tests in the same security-boundary change.
  - confidence: 0.86
