## Summary

Keep open: this is a plausible fix for the unsupported exec-approvals node TypeError, but the latest patch can still block capable node hosts whose normal pairing/effective command surface omits `system.execApprovals.get/set`.

## What This Changes

The PR adds a gateway preflight for `exec.approvals.node.get/set`, adds exec-approval IDs to the desktop host command set, expands gateway tests, and widens the RPC test helper error type.

## Best Possible Solution

Keep the structured unsupported-node error, but preserve existing capable-node approvals workflows by proving normal connect/pair/reconnect behavior or by gating the scoped RPC on raw declared capability plus explicit deny policy.

## Reproduction Assessment

Yes. Source inspection shows current main relays node exec-approval calls without a capability guard, and the PR's latest guard can reject capable nodes when normal reconciliation filters exec-approval IDs out of the effective command surface.

## Solution Assessment

No. Gateway-boundary validation is the right layer for the raw TypeError, but this implementation still relies on an effective command surface that the normal pairing path may not populate for exec-approval-capable node hosts.
