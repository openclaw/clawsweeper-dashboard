## Summary

Keep this issue open for a focused current-version trace. Current documentation says `auth.order` selects among provider profiles, while the Claude CLI backend is selected separately by runtime policy; the report does not include the effective model/runtime configuration or diagnostic output needed to distinguish a regression from an intentionally forced `claude-cli` runtime. A previously closed report documents a similar persisted-order failure, but it does not establish that this current SQLite-backed case is already resolved or duplicate.

## What This Changes

The issue reports that Anthropic runtime selection continues using an expired Claude CLI OAuth profile after the configured auth order prefers valid API-key profiles, and that CLI logout leaves the cached profile available.

## System Context

OpenClaw resolves an agent's canonical Anthropic model through its runtime policy, then selects credentials from the agent auth-profile store. Auth ordering governs eligible provider profiles, while a selected Claude CLI runtime delegates authentication to the local Claude CLI path.

## Best Possible Solution

Make runtime selection and auth-profile selection agree: when the OpenClaw provider runtime is active, honor the configured Anthropic profile order and skip expired credentials; when Claude CLI is intentionally selected, report that runtime choice and provide a visible recovery path to switch or re-authenticate.
