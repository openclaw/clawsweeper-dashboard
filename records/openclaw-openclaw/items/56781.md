## Label Justifications

- `P2`: This is a normal-priority resilience feature for long-session compaction and summary outages with bounded but real provider-routing impact.
- `impact:session-state`: The request is about preserving usable session/context summaries when compaction or Lossless summary generation cannot use the primary model.
- `impact:auth-provider`: The requested fallback chain would route summarization across provider/model references and potentially different auth profiles.

## Summary

Keep open. Current main and the latest release still lack a public `agents.defaults.compaction.fallbacks` field, explicit `compaction.model` still bypasses the fallback wrapper, and the Lossless/context-engine `summaryModel` surface remains single-model; related PRs are closed unmerged or only partial history.

## What This Changes

Request an ordered fallback model chain for embedded compaction and Lossless/LCM summary generation so summarization can retry another model when the primary is rate-limited, unavailable, or times out.

## Best Possible Solution

Define the public fallback contract first, then implement embedded compaction in core if approved while routing Lossless `summaryModel` fallback support through the Lossless plugin or a generic context-engine SDK seam.
