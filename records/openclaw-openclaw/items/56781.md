## Summary

Keep open. Current main and v2026.6.11 still lack a public compaction fallback-chain field and keep the Lossless/context-engine `summaryModel` surface as a single-model/plugin-owned concern, while the related implementation PRs are closed unmerged partial attempts.

## What This Changes

Request to add ordered fallback model chains for embedded compaction and Lossless/LCM `summaryModel` so summarization can fail over on provider errors, rate limits, or timeouts.

## Best Possible Solution

Keep this as the canonical design tracker, choose the public fallback contract first, then implement embedded compaction in core only if approved while routing Lossless `summaryModel` fallback to the Lossless plugin or a generic context-engine SDK seam.
