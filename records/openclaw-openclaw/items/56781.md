## Summary

Keep open. Current main and v2026.6.11 still lack the requested public `agents.defaults.compaction.fallbacks` and Lossless summary-model fallback surfaces; explicit `agents.defaults.compaction.model` remains exact, and the related implementation PRs are closed unmerged partial attempts rather than a current landing path.

## What This Changes

The issue requests ordered fallback model chains for core compaction and Lossless/LCM `summaryModel` compaction.

## Best Possible Solution

Define the fallback contract first, then implement embedded compaction in core if approved while routing Lossless summary-model fallback to the Lossless plugin or a generic context-engine SDK seam.

## Maintainer Decision

Rationale: The remaining work adds provider/auth routing behavior and crosses the core compaction plus plugin-owned Lossless/context-engine boundary, so automation cannot safely choose the public contract or owner boundary.

Options:

- **Approve Core Embedded Fallback Plus Plugin-Owned Lossless (recommended):** Add an explicit core fallback chain for embedded compaction and keep Lossless `summaryModel` fallback in the Lossless plugin unless a missing SDK seam is proven.
- **Design One Context-Engine Fallback Contract:** Pause implementation until maintainers choose a generic API that can cover embedded compaction, Lossless, and other context-engine summaries consistently.
- **Keep Summarizer Fallbacks Outside Core:** Decline a new core config key and ask operators to use provider plugins, compaction providers, or external routing for summarizer fallback behavior.

## Solution Assessment

Unclear. An explicit fallback list is a plausible embedded-compaction shape, but the Lossless half crosses plugin/context-engine ownership and needs maintainer API direction before implementation.
