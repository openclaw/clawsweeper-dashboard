## Summary

Keep open. Current main and the latest release still lack the requested explicit public fallback surfaces: embedded compaction accepts one `compaction.model`, explicit compaction models bypass the fallback wrapper, and Lossless remains a plugin/context-engine `summaryModel` surface with no fallback chain in OpenClaw core.

## What This Changes

Request adds ordered fallback model chains for embedded compaction and Lossless/LCM `summaryModel` so summarization can recover from rate limits, provider errors, or timeouts.

## Best Possible Solution

Have maintainers decide the public fallback contract, implement embedded compaction in core only if approved, and keep Lossless `summaryModel` fallback in the Lossless plugin or a generic context-engine SDK seam if one is missing.

## Reproduction Assessment

Yes for the source-level gap: current main lacks the requested fallback fields, and explicit compaction models bypass the fallback wrapper. A live 429/timeout repro is not required to show the requested capability is missing.

## Solution Assessment

Unclear. An explicit fallback list is plausible for embedded compaction, but the Lossless half crosses plugin/context-engine ownership and needs maintainer API direction before a repair PR chooses the contract.
