## Summary

Keep open. Current main and the latest release still lack the requested public fallback surfaces: explicit embedded compaction has only one `compaction.model`, the fallback wrapper is bypassed when that model is set, and Lossless is still documented/migrated through a single plugin-owned `summaryModel`.

## What This Changes

The issue requests ordered fallback model chains for embedded compaction and Lossless/LCM summary-model configuration so summarization can recover from rate limits, provider errors, or unavailable primary models.

## Best Possible Solution

Have maintainers define the public contract first: embedded compaction can get an explicit fallback chain only if its replacement/inheritance semantics are accepted, while Lossless `summaryModel` fallback should live in the Lossless/context-engine owner path or a generic plugin SDK seam if that seam is missing.
