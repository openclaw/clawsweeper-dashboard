## Summary

Keep open. Current main and v2026.6.11 still do not provide the requested public fallback list for explicit compaction models, and Lossless/LCM `summaryModel` fallback support remains a plugin/context-engine ownership question rather than implemented core behavior.

## What This Changes

The issue requests ordered fallback model chains for embedded compaction and Lossless/LCM summary model selection so summary work can retry another model after rate limits, provider errors, or timeouts.

## Best Possible Solution

Settle a split ownership contract: core owns embedded `agents.defaults.compaction` fallback semantics, while Lossless/LCM summary fallbacks are exposed through the context-engine plugin contract or that plugin's documented config.
