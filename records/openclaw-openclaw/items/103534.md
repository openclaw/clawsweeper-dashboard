## Summary

The core fix is source-correct: plugin ownership is checked on the projected session snapshot, and SQLite rejects the write if that exact row changes before commit. Merge should remain human-gated because strict denial of legacy ownerless rows changes persisted-session compatibility and the external PR still lacks after-fix proof from a deployed Gateway.

## What This Changes

The PR adds plugin-runtime ownership authorization and owner stamping to `sessions.patch`, adds foreign-owner, ownerless-row, creation, and race regression coverage, and includes a shallow-context guard in the local-audio doctor contribution.

## Best Possible Solution

Keep the authorization plus SQLite compare-before-upsert design, remove the unrelated doctor change, explicitly approve and document the legacy ownerless-row recovery policy, and demonstrate both fresh-store and upgraded-store behavior on a deployed Gateway before merge.
