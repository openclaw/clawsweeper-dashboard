## Summary

This PR addresses a valid cross-plugin session mutation bug, but the current authorization still checks a detached snapshot before the authoritative SQLite lifecycle write, leaving a TOCTOU gap. The branch also retains an unrelated doctor-health behavior change and lacks deployed after-fix proof.

## What This Changes

The PR adds plugin-owner authorization and owner stamping to `sessions.patch`, regression coverage for foreign and ownerless rows, and a separate doctor-health guard.

## Best Possible Solution

Reread and authorize the exact candidate row inside the synchronous SQLite lifecycle transaction immediately before removals or upsert, preserve owner stamping only for genuinely new rows, remove the doctor-health change, and prove fresh and legacy behavior on a deployed Gateway.
