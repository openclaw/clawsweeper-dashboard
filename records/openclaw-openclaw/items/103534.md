## Summary

This PR addresses a valid cross-plugin session-mutation bug, but the unchanged head retains the prior P1 concurrent-create bypass: authorization occurs before the store transaction selects the actual entry. It also lacks real deployed-gateway proof, conflicts with current main, and requires an explicit decision on legacy ownerless sessions.

## What This Changes

The PR adds plugin-runtime ownership checks to `sessions.patch`, stamps ownership on sessions created through patching, and adds regression coverage for owned, foreign-owned, ownerless, and newly created sessions.

## Best Possible Solution

Perform the ownership comparison inside the same store transaction against the selected entry, stamp ownership only when that transaction truly creates the row, add deterministic concurrent-create coverage, and use an explicitly approved operator recovery policy for legacy ownerless rows.
