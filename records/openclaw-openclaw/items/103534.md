## Summary

Current main still has the reported cross-plugin `sessions.patch` gap, so this PR remains necessary; however, the latest head is not merge-ready because ownership is authorized before a separate storage write, an unrelated doctor-health change remains, and real deployed behavior proof is missing.

## What This Changes

The PR adds plugin-runtime ownership checks and owner stamping to `sessions.patch`, with regression coverage for owned, foreign, ownerless, concurrent, and creation cases, plus a doctor-health guard.

## Best Possible Solution

Enforce ownership through `applySessionEntryReplacements` or an equivalent storage-owned operation so authorization and replacement use the same authoritative row version, retain new-row owner stamping, remove the doctor-health change, define recovery for legacy ownerless rows, and prove the result in a real Gateway/plugin-runtime setup.
