- `merge-risk: 🚨 compatibility`: Legacy ownerless sessions become inaccessible to plugin-runtime patch callers without migration or recovery tooling.

## Summary

This PR remains necessary, but it is not merge-ready: the ownership denial runs after a storage phase that intentionally migrates and prunes session keys even when projection fails, so an unauthorized request can still mutate persisted state. The contributor must also provide deployed behavior proof, and a Gateway owner must approve the permanent policy for legacy ownerless rows.

## What This Changes

The PR adds plugin-runtime ownership enforcement to `sessions.patch`, stamps plugin ownership on patch-created rows, and adds lifecycle, race, ownerless-row, and projection regression coverage.

## Best Possible Solution

Add an authorization seam at the session-store projection boundary that checks the transaction-selected immutable entry before migration or pruning, preserve creator stamping only for genuinely new rows, and prove rejected calls leave every canonical and alias entry unchanged.
