## Summary

This PR remains necessary: it is the active candidate fix for the open cross-plugin `sessions.patch` authorization gap. The branch has focused regression coverage and credible deployed-gateway proof, but merging deliberately makes plugin-runtime callers fail closed on legacy ownerless persisted rows, so a maintainer must confirm that upgrade contract before merge.

## What This Changes

The PR makes gateway `sessions.patch` restrict plugin-runtime callers to session rows owned by the calling plugin, rechecks that authorization against the projection snapshot, and stamps ownership on newly created plugin session rows.

## System Context

The gateway accepts session mutation requests from operator and in-process plugin-runtime clients, then projects and persists the resulting session row. Plugin ownership is carried with a session row so a plugin cannot archive, restore, or rewrite session state belonging to another plugin.
