## Summary

This PR addresses a real cross-plugin session-mutation bug, but the authoritative check still runs after candidate-key migration, allowing a rejected request to persistently rename session state. The branch also needs maintainer approval for its fail-closed treatment of legacy ownerless rows and contributor-supplied real behavior proof.

## What This Changes

The PR adds plugin-runtime ownership checks to `sessions.patch`, stamps ownership on patch-created sessions, and adds regression coverage for foreign-owned, ownerless, newly created, and concurrently appearing rows.

## Best Possible Solution

Add a locked pre-migration authorization hook—or otherwise authorize the selected source entry before candidate-key promotion, deletion, or persistence—then add a regression proving rejected legacy-key requests leave all keys and values unchanged, document an approved recovery path for ownerless rows, and provide live plugin-runtime Gateway proof.
