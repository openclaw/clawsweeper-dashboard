## Summary

This PR remains necessary because current `main` lacks the `sessions.patch` ownership fence, but the current head does not close the race: `applySessionPatchProjection` declares `authorize` without invoking or forwarding it, so authorization never runs on the authoritative persisted entry. The branch also retains an unrelated doctor-health change. Likely related people: `jalehman` (high confidence, session storage/accessor boundary), `steipete` (high confidence, recent gateway/session behavior), and `vincentkoc` (medium confidence, recent SQLite session-accessor work).

## What This Changes

The branch attempts to restrict plugin-runtime `sessions.patch` mutations to owned sessions, stamp plugin ownership on newly created rows, and add gateway regression coverage.

## Best Possible Solution

Make the canonical session patch mutation authorize the writer-selected persisted entry before migration and save, add a regression that changes ownership after the initial snapshot, preserve ownership stamping only for new rows, and remove the unrelated doctor-health diff.
