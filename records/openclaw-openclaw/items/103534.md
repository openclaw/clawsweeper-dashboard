## Summary

This PR remains necessary because current `main` still lacks a `sessions.patch` plugin-ownership fence, but the latest head is not merge-ready: authorization still occurs before a separate authoritative write, the previously flagged unrelated doctor change remains, and real Gateway proof is absent.

## What This Changes

The PR adds plugin-owner checks and owner stamping to `sessions.patch`, introduces an authorization hook in session projection types, adds regression tests, and includes an unrelated doctor-health guard.

## Best Possible Solution

Authorize plugin ownership inside the canonical session-store mutation or transaction against the authoritative row before migration or persistence, keep any handler check only as a fast fail, remove the doctor change, and prove foreign rejection, same-owner success, ownerless handling, and unchanged rejected storage on a real Gateway.
