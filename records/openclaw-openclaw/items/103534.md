## Summary

The security fix is still necessary, but the latest head remains incorrect: ownership rejection occurs after the storage accessor has migrated the selected row and pruned aliases, and that mutated store is saved even when authorization fails. The branch also lacks required deployed Gateway proof and needs an explicit maintainer decision on legacy ownerless-row access.

## What This Changes

The PR adds plugin-runtime ownership checks to `sessions.patch`, stamps ownership on rows created by plugin callers, and adds regression tests for foreign, ownerless, new, and concurrently selected rows.

## Best Possible Solution

Add a storage-neutral authorization hook that evaluates the transaction-selected entry before canonical-key migration, alias pruning, or persistence; retain owner stamping for genuinely new rows, add unchanged-store regression coverage, and prove the behavior through a deployed Gateway run.
