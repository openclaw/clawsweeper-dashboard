## Label Justifications

- `P1`: An installed plugin can otherwise alter another plugin’s active session state through the gateway patch method.
- `merge-risk: 🚨 compatibility`: Legacy ownerless rows that a plugin could previously patch will now be rejected for plugin-runtime callers.

## Summary

Keep this PR open for maintainer review. Current `main` still lacks the `sessions.patch` plugin-owner fence, while the branch adds an authoritative snapshot-time check, preserves ownership for plugin-created rows, and has strong deployed-gateway proof; the remaining blocker is an explicit decision to fail closed for legacy ownerless sessions and coordination with the related creation-path work.

## What This Changes

The PR adds plugin-runtime ownership checks to `sessions.patch`, stamps `pluginOwnerId` on newly created session rows, and adds race, persistence, and gateway regression coverage.

## Best Possible Solution

Accept the fail-closed rule for plugin-runtime access to legacy ownerless rows, land this narrow patch after the exact head’s required checks complete, then rebase or consolidate the separate `sessions.create` ownership work around the resulting shared invariant.
