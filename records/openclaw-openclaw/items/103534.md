## Summary

The patch correctly closes the cross-plugin `sessions.patch` authorization gap using transaction-selected state and preserves creator ownership on new rows. It should remain open until a maintainer confirms the fail-closed policy for legacy ownerless rows and the contributor supplies after-fix proof from a deployed plugin-runtime Gateway setup.

## What This Changes

The PR adds transaction-time plugin-runtime ownership authorization to `sessions.patch`, stamps creator ownership on newly materialized session rows, adds ownership regression coverage, and guards a local-audio doctor contribution in shallow contexts.

## Best Possible Solution

Keep the transaction-time authorization before migration, preserve creator ownership only when materializing new rows, document an operator recovery path for legacy ownerless rows, and merge after deployed same-owner, foreign-owner, and ownerless-row proof.
