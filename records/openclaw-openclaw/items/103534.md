## Summary

The PR targets the correct cross-plugin authorization boundary, but the current head still performs canonical-key migration and alias deletion before its ownership check, so an unauthorized request can mutate persisted session state despite returning an error. The branch also needs deployed Gateway proof and explicit acceptance of its fail-closed behavior for legacy ownerless rows.

## What This Changes

The PR adds plugin-runtime ownership enforcement to `sessions.patch`, stamps ownership on newly created session rows, and adds foreign-owner, ownerless-row, creation, and race regression tests.

## Best Possible Solution

Authorize the transaction-selected raw session entry before canonical-key migration, alias pruning, or persistence; preserve owner stamping for newly created plugin rows; and explicitly approve fail-closed ownerless handling or provide a trusted migration.
