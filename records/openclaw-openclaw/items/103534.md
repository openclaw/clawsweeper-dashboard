## Summary

The patch appears technically sound and fixes the transaction race, but it remains blocked on deployed real-behavior proof and an explicit maintainer decision about making legacy ownerless sessions unpatchable by plugin runtimes.

## What This Changes

The PR adds pre-migration transaction authorization for plugin-runtime `sessions.patch`, stamps plugin ownership on newly created rows, and adds regression coverage for foreign, ownerless, concurrent, and self-owned mutations.

## Best Possible Solution

Keep the transaction-time pre-migration authorization and strict foreign-owner isolation, choose this branch as the canonical fix if maintainers accept its broader correctness coverage, and either explicitly support operator-only recovery for ownerless rows or add a one-time doctor migration before merge.
