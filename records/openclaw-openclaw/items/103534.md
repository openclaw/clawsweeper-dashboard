## Summary

This fix remains necessary because current `main` and the latest release still lack a `sessions.patch` ownership fence. The current head is not merge-ready: authorization occurs after the accessor can migrate persisted keys, real deployed proof is missing, and the legacy ownerless-row policy needs maintainer confirmation.

## What This Changes

The PR adds plugin-runtime ownership enforcement to `sessions.patch`, stamps `pluginOwnerId` on patch-created sessions, rejects ownerless rows, and adds lifecycle and projection regression coverage.

## Best Possible Solution

Add a transaction-selected pre-mutation authorization stage to the session accessor, reject before any key migration or write, then prove storage invariance in regression coverage and a real deployed Gateway before landing.
