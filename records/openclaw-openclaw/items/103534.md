## Summary

This PR remains blocked: the proposed ownership check returns the intended error, but it executes after the accessor has already migrated session aliases and will persist those changes even on failure. The linked issue remains valid, and neither competing PR is currently a safe canonical replacement.

## What This Changes

The PR adds plugin-runtime ownership enforcement and ownership stamping to `sessions.patch`, with regression coverage for foreign-owned, ownerless, newly created, and transaction-race cases.

## Best Possible Solution

Authorize the transaction-selected entry before alias migration—preferably through a pre-mutation accessor callback—then assert rejected storage is unchanged, preserve new-row owner stamping, and document the approved ownerless-row recovery policy.
