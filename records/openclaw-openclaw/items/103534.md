## Label Justifications

- `P1`: The PR targets an active cross-plugin session mutation boundary, but the current implementation still leaves a transaction-time authorization race.
- `merge-risk: 🚨 compatibility`: Plugin-runtime patches that previously worked on persistent ownerless rows will fail after upgrade without a proven migration or recovery path.
- `merge-risk: 🚨 session-state`: The patch changes authorization and ownership stamping for persisted session rows, and the current ordering can commit over a different row version.
- `merge-risk: 🚨 security-boundary`: The ownership check is detached from the exact row committed by SQLite, so the intended cross-plugin isolation can still be bypassed by a concurrent replacement.

## Summary

The current head still authorizes a cloned session snapshot before the SQLite lifecycle mutation acquires its writer lock, so a concurrent replacement can bypass the intended cross-plugin fence. The branch also retains an unrelated doctor-health behavior change, and the deliberate fail-closed treatment of legacy ownerless rows needs explicit upgrade handling before merge.

## What This Changes

The PR adds plugin-runtime ownership checks and owner stamping to `sessions.patch`, regression tests for foreign and ownerless rows, and an unrelated doctor health guard.

## Best Possible Solution

Implement the ownership predicate inside the storage writer transaction against the exact existing row being replaced, stamp ownership only for genuinely new plugin-created rows, define the upgrade path for shipped ownerless rows, and remove the doctor-health hunk.
