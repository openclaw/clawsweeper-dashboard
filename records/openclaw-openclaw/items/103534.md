## Summary

The current head still has the previously reported P1 ordering defect: the authoritative owner check occurs only after the storage accessor has migrated and pruned session keys. The focused harness coverage is useful, but real plugin-runtime behavior proof is also still required. Likely related people: @jalehman for the session projection/accessor seam and @steipete for recent gateway session lifecycle and delete behavior.

## What This Changes

The PR adds plugin-owner authorization to `sessions.patch`, stamps ownership on plugin-created session entries, and adds gateway regression coverage.

## Best Possible Solution

Make the transaction select the target entry, authorize that selected entry, and only then perform canonical-key migration and patch projection; add regression coverage proving rejected requests leave every persisted key and entry unchanged.
