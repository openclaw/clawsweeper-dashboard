## Summary

Keep this PR open for revision: the repeated P1 blocker remains on the exact current head because ownership is checked only after the accessor has already migrated persisted session aliases. ## What This Changes

The PR adds plugin-owner authorization and owner stamping to Gateway `sessions.patch`, with regression coverage for foreign, ownerless, creation, and race cases.

## Best Possible Solution

Add an accessor-level pre-mutation authorization hook over the transaction-selected entry, prove failed authorization performs no migration or write, and resolve legacy ownerless rows through an explicit maintainer-approved migration or operator-only policy.
