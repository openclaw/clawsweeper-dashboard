## Summary

The current head has no supported line-level correctness defect and appears to close the reported authorization race safely, but this PR should remain open because deployed plugin-runtime proof is absent and maintainers must explicitly accept the compatibility boundary for legacy ownerless rows.

## What This Changes

The PR adds exact plugin-owner authorization to `sessions.patch`, stamps plugin ownership on newly created session rows, and adds focused lifecycle, race, and projection tests.

## Best Possible Solution

Keep the transaction-selected exact-owner check and new-row ownership stamping, then land only after maintainers approve the ownerless-row upgrade policy and redacted deployed Gateway evidence shows foreign rejection, same-owner success, and successful plugin-created row reuse.
