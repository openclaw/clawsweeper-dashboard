## Label Justifications

- `P1`: The PR addresses a real cross-plugin authorization defect, but the proposed fence still permits unauthorized persisted session-key mutation.
- `merge-risk: 🚨 compatibility`: Legacy ownerless rows become fail-closed for plugin-runtime patch calls, and rejected alias requests can still change persisted key layout.
- `merge-risk: 🚨 session-state`: The current transaction order can canonicalize or prune persisted session entries before returning the ownership error.
- `merge-risk: 🚨 security-boundary`: The cross-plugin ownership decision currently occurs after a storage mutation rather than before all unauthorized effects.

## Summary

The PR is still necessary because current main lacks a `sessions.patch` ownership fence, but the latest head retains the prior merge-blocking transaction-order defect: the session accessor migrates and prunes candidate keys before the ownership callback runs, then persists those changes even when authorization rejects. Green CI does not settle this persisted-state and security-boundary failure, and the PR also lacks required real plugin-runtime Gateway proof.

## What This Changes

The branch adds plugin-owner authorization to `sessions.patch`, stamps the authenticated plugin owner on newly materialized session rows, and adds gateway lifecycle and projection regression tests.

## Best Possible Solution

Add a transaction-level pre-migration authorization hook or equivalent accessor contract so ownership is checked against the selected freshest entry before canonicalization, alias pruning, or any save; then cover unchanged rejected storage and prove all ownership states through a real plugin-runtime Gateway run.
