## Summary

The core ownership repair is still necessary and the transaction-selected authorization design is directionally correct, but this head is not merge-ready: it retains an unrelated doctor runtime change, intentionally breaks plugin-runtime access to legacy ownerless rows without explicit owner acceptance or migration proof, and provides only harness/CI evidence rather than after-fix proof from a real plugin-runtime Gateway setup.

## What This Changes

The branch adds pre-migration authorization to session patch persistence, enforces exact plugin ownership for `sessions.patch`, stamps ownership on plugin-created session rows, adds ownership/race regressions, and changes local-audio doctor health execution.

## Best Possible Solution

Keep the authorization inside the exclusive writer against the freshest selected row, remove the doctor change, explicitly approve exact-owner fail-closed semantics or add an operator-owned legacy migration path, and demonstrate the complete ownership matrix through a real plugin-runtime Gateway before merge.
