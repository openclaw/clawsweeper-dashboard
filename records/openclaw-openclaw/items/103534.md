## Label Justifications

- `P1`: The current Gateway permits an in-process plugin runtime to archive, unarchive, rename, or otherwise mutate another plugin's session.
- `merge-risk: 🚨 compatibility`: Failing closed on legacy ownerless rows can stop existing plugin-runtime patch workflows immediately after upgrade.
- `merge-risk: 🚨 session-state`: An incorrect authorization or ownership-stamping boundary could deny valid session updates or permit mutation of another plugin's persisted session state.
- `merge-risk: 🚨 security-boundary`: The patch changes the authorization boundary between trusted in-process plugins and plugin-owned session records.

## Summary

Keep this PR open: the underlying cross-plugin mutation bug remains on current `main`, and the patch appears technically sound, but merge still requires deployed plugin-runtime proof and explicit maintainer acceptance of the fail-closed behavior for legacy ownerless rows.

## What This Changes

Adds plugin-owner authorization to `sessions.patch`, records the authenticated plugin owner on newly created session rows, extracts shared ownership helpers, and adds ownership, race, and persistence regression tests.

## Best Possible Solution

Keep authorization against the transaction-selected session row, stamp ownership only when a plugin creates a new row, and land the fail-closed ownerless policy only after maintainers confirm that upgrade boundary and a deployed plugin-runtime run proves it.
