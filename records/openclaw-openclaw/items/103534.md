## Summary

The exact PR head still authorizes too late: the session-store accessor migrates and prunes candidate keys before invoking the new ownership check, so a rejected foreign-plugin patch can alter persisted key state. The canonical issue remains valid, and this PR needs the narrow ordering repair plus real Gateway proof.

## What This Changes

The PR adds plugin-owner authorization and owner stamping to Gateway `sessions.patch`, with lifecycle and projection regression coverage.

## Best Possible Solution

Add a generic pre-migration validation hook to the session patch accessor, authorize the transaction-selected entry through that hook, and cover a foreign-owned canonical-plus-legacy target proving rejection preserves every persisted key and value.
