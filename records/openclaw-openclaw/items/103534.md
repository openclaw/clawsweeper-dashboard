## Summary

Keep this PR open for maintainer review: the patch now appears race-safe and has no supported line-level correctness finding, but deployed behavior proof is still missing and the fail-closed policy for legacy ownerless sessions needs an explicit security and upgrade decision.

## What This Changes

The PR adds atomic plugin-runtime ownership checks to `sessions.patch`, stamps ownership on newly created session rows, and adds focused gateway regression coverage.

## Best Possible Solution

Keep authorization inside the locked session projection, preserve ownership on creation, and land only after maintainers confirm the ownerless-row policy and obtain redacted deployed-Gateway proof for same-owner success, foreign-owner rejection, ownerless rejection, and ownership persistence.

## Solution Assessment

Unclear pending one policy choice. Authorizing the transaction-selected row before persistence is the narrowest maintainable fix, but maintainers must confirm whether permanent fail-closed handling or an explicit migration is correct for legacy ownerless rows.
