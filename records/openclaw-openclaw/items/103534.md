## Summary

This remains a necessary security fix, but the current head still rejects plugin-runtime callers only after the accessor has migrated or pruned candidate keys, so an unauthorized request can alter persisted session state. The branch also needs deployed Gateway proof and maintainer confirmation of the legacy ownerless-row policy before merge.

## What This Changes

The PR adds plugin-runtime ownership enforcement and owner stamping to `sessions.patch`, with regression coverage for foreign, ownerless, creation, and race cases.

## Best Possible Solution

Authorize the transaction-selected entry before candidate-key migration or persistence, prove rejected requests leave storage unchanged, and provide an operator-visible recovery path for legacy ownerless rows.
