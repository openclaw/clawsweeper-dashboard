## Summary

Keep open: the central security fix appears directionally correct and the previously reported atomic-authorization issue is addressed, but this external PR still lacks deployed real-behavior proof, changes the policy for legacy ownerless sessions, and retains an unrelated doctor-health change.

## What This Changes

The PR restricts plugin-runtime `sessions.patch` mutations to sessions owned by the calling plugin, stamps ownership on newly created sessions, adds transaction-local authorization and regression tests, and also changes a doctor-health guard.

## Best Possible Solution

Land a narrow session-only patch that authorizes the exact row selected under the mutation lock, stamps new rows with the authenticated plugin owner, retains fail-closed ownerless handling only after explicit approval, removes the doctor-health change, and includes redacted deployed-Gateway proof for foreign rejection and same-owner success.
