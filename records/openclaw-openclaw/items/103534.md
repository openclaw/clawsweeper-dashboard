## Summary

The PR addresses a real cross-plugin session mutation gap, but the latest head still authorizes and projects from a snapshot before the authoritative SQLite write, leaving a concurrent owner-change bypass. It also changes unrelated doctor behavior, lacks deployed-Gateway proof, and needs an explicit upgrade policy for legacy ownerless rows.

## What This Changes

The branch adds plugin-owner checks to `sessions.patch`, stamps ownership on plugin-created sessions, adds an accessor authorization callback and regression tests, and includes a separate doctor-health guard.

## Best Possible Solution

Run ownership validation and patch projection inside the same writer-queued SQLite mutation against the authoritative row, remove the doctor hunk, define a doctor/operator recovery path for legacy ownerless rows, and attach redacted deployed-Gateway proof.
