## Summary

This PR addresses a valid cross-plugin session-mutation bug, but the final head retains the prior P1 blocker: ownership is checked only after the projection accessor has intentionally migrated the selected key set, and that migration is saved even when authorization fails. Real deployed plugin-runtime Gateway proof is also still missing, and the fail-closed policy for legacy ownerless rows needs explicit maintainer approval.

## What This Changes

The PR adds plugin-runtime ownership checks to `sessions.patch`, rejects legacy ownerless rows, stamps `pluginOwnerId` on patch-created sessions, and adds regression coverage.

## Best Possible Solution

Add a pre-migration authorization phase to the projection accessor so the transaction-selected entry is checked before key promotion or pruning and no storage changes persist on rejection; separately provide a tested doctor or operator recovery path for legitimate legacy ownerless rows.
