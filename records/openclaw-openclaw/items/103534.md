## Summary

Keep open: current main still has the reported ownership gap, but this PR performs its authoritative check after the accessor has migrated the selected entry, allowing a denied request to change persisted key layout; deployed behavior proof is also still missing.

## What This Changes

The PR adds plugin-runtime ownership enforcement and creation-time owner stamping to `sessions.patch`, with regression coverage for foreign-owned, ownerless, newly created, and concurrently selected rows.

## Best Possible Solution

Add an accessor-level pre-projection authorization hook, or an equivalent transaction selection contract, so ownership is checked against the freshest selected entry before migration, pruning, or persistence; retain owner stamping only for genuinely new rows and prove rejected storage remains unchanged.
