## Summary

The original cross-plugin mutation bug remains valid, but this head is not merge-ready: the ownership error is produced only after the session-store accessor has migrated candidate keys, and that accessor saves the migrated store even when projection fails. The previous P1 therefore remains unresolved despite green CI.

## What This Changes

The PR adds plugin-runtime ownership checks and owner stamping for `sessions.patch`, with coverage for foreign-owned, ownerless, creation, and race scenarios.

## Best Possible Solution

Make patch-projection failures atomic by authorizing the transaction-selected entry before committing migration, or by staging migration on a cloned store and persisting only on success; then prove rejected storage is unchanged and settle the legacy ownerless-row upgrade policy.
