## Summary

Keep open: the session-ownership repair is directionally sound and well tested, but the current head still includes the previously reported unrelated Doctor behavior change and provides only harness-based proof for a security- and upgrade-sensitive runtime boundary.

## What This Changes

The PR restricts plugin-runtime `sessions.patch` mutations to plugin-owned rows, stamps ownership on newly created rows, adds an authorization callback to the session projection writer, and adds regression coverage.

## Best Possible Solution

Land a focused gateway/session patch that authorizes the writer-selected row, stamps ownership on creation, removes unrelated Doctor changes, and includes an explicit ownerless-row upgrade policy plus redacted live Gateway proof.
