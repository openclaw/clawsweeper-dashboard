## Summary

This PR remains necessary because current `main` still lacks the `sessions.patch` ownership fence, but it is not merge-ready: authorization still uses a cloned pre-writer snapshot rather than the row committed by storage, the unrelated doctor-health change remains, and external real-behavior proof is absent.

## What This Changes

The PR adds plugin-runtime ownership authorization to `sessions.patch`, stamps `pluginOwnerId` on newly created session rows, adds ownership regression tests, and changes local-audio doctor-health execution.

## Best Possible Solution

Authorize the exact current session row inside the same storage writer or SQLite transaction that commits the patch, remove the doctor-health change, retain focused ownership and race coverage, explicitly settle legacy ownerless-row handling, and provide a redacted deployed-Gateway plugin-runtime trace.
