## Summary

Keep open: the current head still authorizes a snapshot before a separate storage write, leaving the cross-plugin TOCTOU path incompletely fixed; it also retains the previously flagged unrelated doctor change and lacks deployed runtime proof.

## What This Changes

The PR adds plugin-runtime ownership checks and owner stamping to `sessions.patch`, with gateway regression tests, and also changes a doctor health contribution.

## Best Possible Solution

Perform plugin ownership authorization inside the storage-owned compare-and-write operation against the exact current row, stamp ownership only when creating a new plugin row, remove the doctor hunk, and explicitly approve or migrate the ownerless-row upgrade boundary.
