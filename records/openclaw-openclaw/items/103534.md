## Summary

The sessions fix now checks the transaction-selected row before migration, preserves existing ownership, stamps new plugin-created rows, and covers the reported race and ownership cases. Current main still has the bug, and the competing PR is conflicted, so this PR remains useful; merge should wait for contributor-supplied deployed proof and maintainer confirmation that legacy ownerless rows must fail closed after upgrade.

## What This Changes

The PR adds transaction-time plugin-runtime authorization to `sessions.patch`, stamps `pluginOwnerId` on newly materialized session rows, adds ownership regression coverage, and adds a guard for shallow local-audio doctor contribution contexts.

## Best Possible Solution

Keep the authorization immediately before persistence under the store writer lock, retain owner identity on existing rows, stamp authenticated ownership on new rows, and pair the fail-closed legacy policy with a documented operator or doctor recovery path if maintainers confirm it.
