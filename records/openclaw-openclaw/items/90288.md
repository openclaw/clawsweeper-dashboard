## Summary

Keep open: current main and release v2026.6.11 still only promote serialized tool-call text that carries executable arguments, while the reported bare `[tool: exec]` marker remains an unsupported provider/model failure mode that needs a maintainer recovery policy.

## What This Changes

The issue asks OpenClaw to detect or recover when non-Anthropic provider routes emit bare text tool markers such as `[tool: exec]` instead of structured tool calls.

## Best Possible Solution

Choose an explicit provider-recovery policy that treats bare markers as failed tool intent without inventing arguments, then prove it against the MiniMax/OpenRouter/DeepSeek paths and keep the parseable-payload promotion tests intact.
