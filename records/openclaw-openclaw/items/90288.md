## Label Justifications

- `P1`: Affected provider/model routes can leave tool-enabled agent turns stuck with visible marker text and no executed tool result.
- `impact:message-loss`: The intended tool-backed assistant response can be replaced by a visible marker with no corresponding tool output.

- `impact:auth-provider`: The failure is tied to provider/model tool-call compatibility across Anthropic Messages and OpenAI-compatible routes.

## Summary

Keep open: current main and latest stable still only recover parseable, payload-bearing plain-text tool calls, while the reported bare `[tool: exec]` marker is neither safely promotable nor diagnosed. Related XML/invoke PRs overlap the degraded-tool-intent pipeline but do not close this no-argument bracket-marker policy gap.

## What This Changes

The issue requests recovery, fallback, or diagnostics when non-Anthropic/provider-compatible models emit bare tool-call markers such as `[tool: exec]` as visible text instead of structured tool calls.

## Best Possible Solution

Keep this issue open until maintainers choose a recovery policy for bare leaked tool markers and back it with live provider proof plus focused parser, stream, diagnostic, and fallback coverage.
