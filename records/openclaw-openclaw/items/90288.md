## Summary

Keep open: current `main` still only promotes serialized plain-text tool calls when a parseable payload is present, while the reported bare marker shape has no executable arguments and remains a provider/runtime policy gap. The related fallback and namespaced-XML reports overlap, but none owns this exact non-native bare-marker recovery decision.

## What This Changes

The issue reports non-Anthropic or compatibility-layer models emitting plain-text tool-call markers like `[tool: exec]` instead of structured tool-use blocks, leaving tool-enabled sessions stuck without an executed tool call.

## Best Possible Solution

Choose an explicit non-native tool-call recovery policy for bare leaked markers, then implement it with live provider proof and focused regression coverage while keeping argument-bearing serialized promotion bounded.
