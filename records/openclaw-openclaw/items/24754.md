## Summary

Keep open: current main and the latest release still provide authenticated Gateway WebSocket WebChat, device pairing, Talk/WebRTC voice, and configurable DM session isolation, but not the requested native browser-held E2EE chat transport with encrypted browser chat envelopes and per-device/per-agent keys.

## What This Changes

The issue requests a native no-third-party browser-held E2EE chat transport with QR browser pairing and per-device/per-agent isolation.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement the protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
