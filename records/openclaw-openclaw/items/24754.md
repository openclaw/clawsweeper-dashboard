## Summary

Keep open: current main and v2026.6.11 still provide authenticated Gateway WebSocket WebChat, device pairing, Matrix E2EE as a third-party channel option, and provider-backed browser Talk/WebRTC, but not the requested native no-third-party browser-held E2EE chat transport with encrypted message envelopes and per-device/per-agent browser keys.

## What This Changes

The issue requests a native no-third-party browser chat transport with browser-held E2EE, QR/device pairing, and per-device/per-agent encrypted channel isolation.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
