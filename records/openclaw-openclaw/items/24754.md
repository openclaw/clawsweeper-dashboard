## Summary

Keep open: current main and v2026.6.11 still provide Gateway/WebChat chat, device pairing, dmScope isolation, Matrix/Nostr encrypted channel alternatives, Signal, and browser Talk/WebRTC voice, but not the requested native no-third-party browser-held E2EE chat transport.

## What This Changes

The issue requests a native browser-based, no-third-party, end-to-end encrypted chat transport for OpenClaw with per-device and per-agent isolation.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model and capability first, then implement the chosen core or plugin-seam path with key lifecycle, encrypted envelopes, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests.

- **Defer native transport:** Keep WebChat, Tailscale, Matrix E2EE, Nostr, Signal, and dmScope isolation as supported paths unless maintainers later sponsor this direction.

  - body: Current security docs treat dmScope as messaging-context isolation, not a hostile multi-tenant or host-admin boundary; native E2EE needs an explicit design for where plaintext may exist and how keys, recovery, transcripts, relays, tools, and compromised in-process code are handled.
  - confidence: 0.92
