## Summary

Keep open: current main and the latest release still provide Gateway/WebSocket WebChat, device pairing, dmScope isolation, Matrix/Nostr encrypted channel alternatives, and browser Talk/WebRTC voice, but not the requested native no-third-party browser-held E2EE chat transport.

## What This Changes

Request a native browser-based E2EE chat layer with browser-held keys, QR/device pairing, no third-party chat account, and per-agent/per-device isolated encrypted channels.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model and capability first, then implement the chosen core or plugin-seam path with key lifecycle, encrypted envelopes, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests.
