## Summary

Keep open: current main and the latest release still provide Gateway WebSocket WebChat, Control UI chat, device pairing, and browser Talk/WebRTC voice, but not the requested no-third-party browser-held E2EE chat transport with encrypted browser message envelopes and per-device/per-agent keys.

## What This Changes

Request to add a native browser-based end-to-end encrypted chat layer for OpenClaw instances without requiring third-party chat apps, accounts, or public internet exposure.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
