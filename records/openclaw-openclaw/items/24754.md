## Summary

Keep open: current main and v2026.6.11 still provide authenticated Gateway WebSocket WebChat, existing channel plugins, dmScope isolation, and provider-backed Talk/WebRTC voice, but not the requested browser-held E2EE chat transport with per-device/per-agent encrypted browser channels.

## What This Changes

The issue requests a native no-third-party browser E2EE chat layer for OpenClaw with browser-held keys, QR pairing, and per-agent channel isolation.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement the protocol, key lifecycle, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
