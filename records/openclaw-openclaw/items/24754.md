## Summary

Keep open: current main and the latest release still provide Gateway-visible WebChat/Control UI chat, device pairing, dmScope isolation, and encrypted third-party channel options, but not the requested native no-third-party browser-held E2EE browser chat transport.

## What This Changes

The issue requests native browser-held E2EE browser chat with per-device and per-agent encrypted channels and no third-party chat app.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model and capability first, then implement the chosen core or plugin-seam path with key lifecycle, encrypted envelopes, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests.
