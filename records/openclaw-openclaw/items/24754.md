## Summary

Keep this issue open. Current main has Gateway WebSocket WebChat, browser device pairing, WebCrypto-backed device identity, provider-backed Talk/WebRTC voice, and configurable DM session isolation, but it still does not implement browser-held E2EE chat envelopes, browser key negotiation, or per-device/per-agent encrypted browser chat channels.

## What This Changes

The issue requests a native browser-based E2EE chat transport for OpenClaw instances with browser-held keys, per-agent/per-device isolation, no third-party chat app, and minimal setup.

## Best Possible Solution

Keep this as a maintainer-led product/security design item, defining either a core Gateway/WebChat E2EE transport or the missing plugin seams before implementation.
