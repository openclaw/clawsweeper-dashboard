## Summary

Keep open: current main and the latest release still provide authenticated Gateway WebSocket WebChat, Control UI chat, device pairing, configurable DM session isolation, and browser Talk/WebRTC voice, but not the requested native no-third-party browser-held E2EE chat transport with encrypted browser message envelopes and per-device/per-agent keys.

## What This Changes

The issue requests a native browser-based end-to-end encrypted chat transport for OpenClaw, avoiding third-party chat accounts and adding per-agent/per-device isolation.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
