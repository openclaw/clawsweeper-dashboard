## Summary

Keep open: current main still has authenticated Gateway WebSocket WebChat, browser Talk/WebRTC, and third-party channel plugins, but not browser-held E2EE chat with encrypted per-device/per-agent channels.

## What This Changes

The issue proposes a native browser-based E2EE chat layer with QR/device pairing and isolated per-agent channels that do not require third-party chat apps.

## Best Possible Solution

Define a maintainer-approved encrypted-browser-channel capability and threat model first, then implement the protocol, browser key lifecycle, routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
