## Summary

Keep open: current main and the latest release still provide authenticated Gateway/WebChat chat with Gateway-visible plaintext message content, not the requested browser-held E2EE transport with encrypted envelopes, browser key negotiation, or per-device/per-agent encrypted browser channels.

## What This Changes

The issue requests a native no-third-party browser chat layer with QR pairing, browser-held E2EE keys, and isolated per-agent/per-device channels.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement the selected core or plugin-seam design with protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests.

Options:

- **Defer Native Transport:** Keep WebChat, Tailscale, Matrix E2EE, Signal, and dmScope isolation as supported paths until maintainers sponsor a native encrypted browser transport.
