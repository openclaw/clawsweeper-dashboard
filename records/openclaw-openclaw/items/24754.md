## Summary

Keep open: current main still has authenticated Gateway/WebChat chat, device pairing, dmScope isolation, Matrix/Nostr encrypted channel options, and browser Talk/WebRTC voice, but not the requested no-third-party browser-held E2EE chat transport with encrypted browser message envelopes and per-device/per-agent key lifecycle.

## What This Changes

Request a native browser-based E2EE chat layer for OpenClaw instances that avoids third-party chat apps and provides per-agent isolated encrypted browser channels.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model and capability first, then implement the chosen core or plugin-seam path with key lifecycle, encrypted envelopes, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests.
