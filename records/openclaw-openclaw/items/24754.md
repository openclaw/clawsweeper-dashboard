## Summary

Keep open: current main and v2026.6.11 still provide authenticated Gateway/WebChat chat, device pairing, dmScope isolation, and browser Talk/WebRTC voice, but not the requested no-third-party browser-held E2EE chat transport with encrypted envelopes and browser/device key lifecycle.

## What This Changes

The issue requests a built-in browser-based E2EE chat transport for OpenClaw instances, with per-device/per-agent isolation and no third-party chat service.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model and capability first, then implement the chosen core or plugin-seam path with key lifecycle, encrypted envelopes, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests.
