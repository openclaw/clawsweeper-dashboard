## Summary

Keep open: current main and the latest release still provide authenticated Gateway/WebChat chat, device pairing, dmScope isolation, and encrypted third-party/plugin channel options, but they do not implement the requested browser-held native E2EE browser chat transport or key lifecycle.

## What This Changes

The issue requests a native no-third-party browser chat layer with browser-held E2EE, QR/device pairing, and per-agent/per-device isolated encrypted channels.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model first, then implement the chosen core or plugin-seam path with key lifecycle, encrypted envelopes, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests.
