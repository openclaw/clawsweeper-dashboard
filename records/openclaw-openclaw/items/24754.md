## Summary

Keep open: current main and v2026.6.11 still provide authenticated Gateway/WebChat chat, device pairing, dmScope isolation, Matrix/Nostr encrypted channel alternatives, and browser Talk/WebRTC voice, but not a native no-third-party browser-held E2EE chat transport with encrypted envelopes and browser key negotiation.

## What This Changes

Add a native no-third-party browser-based E2EE chat transport with QR pairing, browser-held keys, and per-agent/per-device encrypted channel isolation.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model and capability first, then implement the chosen core or plugin-seam path with key lifecycle, encrypted envelopes, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests.

- **Defer native transport:** Keep WebChat, Tailscale, Matrix E2EE, Nostr, Signal, and dmScope isolation as supported paths unless maintainers later sponsor this direction.
