## Summary

Keep open: current main and the latest release still provide authenticated Gateway WebSocket WebChat, browser Talk/WebRTC, device pairing, and third-party channel plugins, but not the requested native no-third-party browser-held E2EE chat transport with per-device/per-agent encrypted browser channels.

## What This Changes

The issue proposes a native browser-based E2EE chat layer with QR pairing and per-device/per-agent keys so OpenClaw users can chat without third-party transports.

## Best Possible Solution

Define a maintainer-approved encrypted-browser-channel capability and threat model first, then implement the chosen core or plugin boundary with protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests.
