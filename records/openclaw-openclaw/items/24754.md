## Summary

Keep open: current main and v2026.6.11 still provide authenticated Gateway WebSocket WebChat, device pairing, and browser Talk/WebRTC voice, but not the requested no-third-party browser-held E2EE chat transport with encrypted browser envelopes and per-device/per-agent keys.

## What This Changes

The issue proposes a native browser-based E2EE chat layer for OpenClaw instances with no third-party chat app, per-device/per-agent keys, and isolated encrypted channels.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
