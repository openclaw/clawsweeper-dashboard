## Summary

Keep open: current main and the latest release still expose WebChat as authenticated Gateway WebSocket chat, while this issue asks for a new no-third-party browser-held E2EE chat transport with encrypted envelopes, browser/device keys, and per-agent/per-device isolation.

## What This Changes

Request a native browser-based E2EE chat layer for OpenClaw so users can pair a browser and chat without a third-party chat app or public internet exposure.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
