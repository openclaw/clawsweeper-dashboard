## Summary

Keep open: current main still provides authenticated Gateway WebSocket WebChat, Control UI chat, browser Talk/WebRTC voice, and configurable DM session isolation, but not the requested native no-third-party browser-held E2EE chat transport with per-device/per-agent keys and encrypted browser chat envelopes.

## What This Changes

Request native browser-based E2EE chat built into OpenClaw, with no third-party chat app and isolated encrypted channels per agent/device.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.

- **Defer native transport:** Keep WebChat, Tailscale, Matrix/Nostr/Signal, and dmScope isolation as the supported paths and close the direction only after explicit maintainer product decision.
