## Summary

Keep open: current main and v2026.6.11 still provide authenticated Gateway WebSocket WebChat, Control UI device pairing, PWA/Web Push, DM-session isolation knobs, and browser Talk/WebRTC, but not the requested browser-held E2EE chat transport with encrypted per-device/per-agent browser channels.

## What This Changes

The issue requests a native browser-based E2EE chat transport for OpenClaw that avoids third-party chat apps and gives each agent/device isolated encrypted channels.

## Best Possible Solution

Define a maintainer-approved encrypted-browser-channel capability and threat model first, then implement protocol, UI, key lifecycle, routing, transcript, relay/recovery, docs, and contract tests under the chosen core or plugin boundary.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a new transport and security architecture proposal. Source and release inspection confirm current main and v2026.6.11 lack encrypted browser chat fields and still route chat.send plaintext through the Gateway.

## Solution Assessment

No, not yet: the WebRTC/WebCrypto sketch is plausible, but the best solution needs an explicit threat model, key lifecycle, relay fallback, transcript semantics, and core/plugin ownership decision before implementation.
