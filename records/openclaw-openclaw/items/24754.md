## Summary

Keep open: current main and the latest release still provide authenticated Gateway WebSocket WebChat and browser Talk, but not native browser-held E2EE chat with per-device/per-agent encrypted browser channels. This remains a product and security architecture decision.

## What This Changes

Request a native browser-based E2EE chat layer for OpenClaw instances with no third-party chat app and per-agent/per-device isolation.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.

- **Defer native transport:** Keep WebChat, Tailscale, Matrix/Nostr/Signal, and dmScope isolation as the supported paths unless maintainers later sponsor this direction.
