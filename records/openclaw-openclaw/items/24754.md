## Summary

Keep open: current main still provides authenticated Gateway WebSocket WebChat, browser Talk/WebRTC, DM session isolation, and third-party encrypted channel plugins, but not the requested browser-held E2EE chat transport with per-device/per-agent keys and encrypted browser channel envelopes.

## What This Changes

Request to add a native no-third-party browser chat layer with E2EE, QR/device pairing, and per-agent isolated encrypted channels.

## Best Possible Solution

Define a maintainer-approved encrypted-browser-channel capability and threat model first, then implement protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
