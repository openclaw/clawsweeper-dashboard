## Summary

Keep open: current main and the latest release still provide authenticated Gateway/WebChat chat, Matrix/Nostr-style external encrypted channel options, and session dmScope isolation, but they do not implement the requested native no-third-party browser-held E2EE browser chat transport with encrypted envelopes, browser/device keys, and per-agent/per-device encrypted browser channels.

## What This Changes

The issue proposes a native browser-based E2EE chat transport for OpenClaw with per-device and per-agent isolation, no third-party chat account, and QR/browser onboarding.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model and capability first, then implement the chosen core or plugin-seam path with key lifecycle, encrypted envelopes, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests.
