## Summary

Keep open: current main and v2026.6.11 still provide WebChat over authenticated Gateway WebSocket, device/session routing, Matrix/Nostr encrypted third-party channel options, and provider-backed Talk/WebRTC, but not the requested native no-third-party browser-held E2EE chat transport with encrypted envelopes and per-device/per-agent browser keys.

## What This Changes

The issue proposes a native no-third-party browser E2EE chat layer with per-device and per-agent isolation for OpenClaw instances.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
