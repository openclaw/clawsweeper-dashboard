## Summary

Keep open: current main and the latest release still implement browser chat as authenticated Gateway WebSocket chat with Gateway-visible message text, so the requested browser-held E2EE transport remains missing and needs maintainer security/product design.

## What This Changes

The issue requests a native no-third-party browser E2EE chat transport with per-device and per-agent encrypted channels instead of external chat providers or Tailscale/WebChat setup.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement protocol/key lifecycle, per-device and per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
