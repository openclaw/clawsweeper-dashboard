## Summary

Keep this issue open. Current main has authenticated Gateway WebChat, browser device pairing, browser-local identity, Web Push, and provider-backed Talk/WebRTC, but it still does not provide the requested browser-held end-to-end encrypted chat transport, encrypted message envelope contract, or per-device/per-agent chat key lifecycle.

## What This Changes

Add a native browser-based, no-third-party, end-to-end encrypted chat layer with per-device and per-agent encrypted channels for OpenClaw instances.

## Best Possible Solution

Keep this as a maintainer-led product/security architecture item: define encrypted envelopes, browser-held key negotiation, key lifecycle, transcript/storage semantics, relay fallback, and the core-vs-plugin boundary before implementation.
