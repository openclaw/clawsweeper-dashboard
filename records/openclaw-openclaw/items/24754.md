## Summary

Keep open: current main and v2026.6.11 still have authenticated Gateway WebSocket WebChat, device pairing, Matrix E2EE as a third-party channel option, and browser Talk/WebRTC, but not native no-third-party browser-held E2EE chat with encrypted message envelopes and per-device/per-agent browser keys.

## What This Changes

Request native browser-based end-to-end encrypted chat for OpenClaw instances without requiring third-party chat providers, installs, accounts, or public exposure.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model and capability first, then implement protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
