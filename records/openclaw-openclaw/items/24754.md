## Summary

Keep open: current main and the latest release still provide authenticated Gateway WebSocket WebChat, device pairing, browser-local Control UI preferences, and provider-backed Talk/WebRTC voice, but not the requested browser-held E2EE chat transport with encrypted browser message envelopes and per-device/per-agent browser keys.

## What This Changes

The issue requests a native browser-based end-to-end encrypted chat transport for OpenClaw, avoiding third-party chat apps and adding per-device/per-agent encrypted isolation.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.

- **Defer native transport:** Keep WebChat, Tailscale, Matrix, Nostr, Signal, and dmScope isolation as supported paths unless maintainers later sponsor this direction.
