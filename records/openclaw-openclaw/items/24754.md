## Summary

Keep open: current main has authenticated Gateway/WebChat chat, device pairing, dmScope isolation, and provider-backed browser Talk/WebRTC, but it still lacks the requested browser-held E2EE browser chat transport and key lifecycle.

## What This Changes

Requests a native no-third-party browser E2EE chat layer with QR pairing, browser-held keys, per-device/per-agent channels, and no separate chat app signup or install.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model and capability first, then implement the chosen core or plugin-seam path with key lifecycle, encrypted envelopes, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests.
