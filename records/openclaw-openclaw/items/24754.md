## Summary

Keep open: current main and the latest release still implement WebChat as authenticated Gateway WebSocket chat with Gateway-visible `chat.send` message text, so the requested native no-third-party browser-held E2EE chat transport is still missing and needs maintainer security/product design.

## What This Changes

The issue proposes a native browser-based E2EE chat layer with QR pairing, no third-party chat app, and per-agent/per-device encrypted channels.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
