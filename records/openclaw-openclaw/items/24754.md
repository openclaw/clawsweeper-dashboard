## Summary

Keep open: current main and v2026.6.11 still provide authenticated Gateway/WebChat chat, device pairing, dmScope isolation, Matrix/Nostr encrypted channel alternatives, and browser Talk/WebRTC voice, but not the requested native no-third-party browser-held E2EE chat transport.

## What This Changes

The issue requests native browser-based end-to-end encrypted chat for OpenClaw without third-party chat apps, including per-agent and per-device isolation.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model and capability first, then implement the chosen core or plugin-seam path with key lifecycle, encrypted envelopes, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests.
