## Summary

Keep open: current main and the latest release still provide Gateway/WebChat chat, device pairing, dmScope isolation, Matrix/Nostr encrypted channel alternatives, and browser Talk/WebRTC voice, but not the requested native no-third-party browser-held E2EE chat transport.

## What This Changes

The issue requests a native browser chat layer with browser-held E2EE, QR/device setup, no third-party chat provider, and per-device/per-agent encrypted channel isolation.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model and capability first, then implement the chosen core or plugin-seam path with key lifecycle, encrypted envelopes, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests.
