## Summary

Keep open: current main and v2026.6.11 still provide Gateway/WebChat chat, existing encrypted channel plugins, device/auth controls, and browser Talk/WebRTC voice, but not native no-third-party browser-held E2EE chat with encrypted envelopes and per-device/per-agent key lifecycle.

## What This Changes

The issue requests a native browser-based E2EE chat transport for OpenClaw instances that avoids third-party chat apps and isolates conversations per device and agent.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model first, then implement the chosen core or plugin-seam path with key lifecycle, encrypted envelopes, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests.
