## Summary

Keep open: current main still has authenticated Gateway WebSocket WebChat, device pairing, Matrix E2EE as a third-party channel, and provider-backed Talk/WebRTC, but not the requested native no-third-party browser-held E2EE browser chat transport with encrypted envelopes and per-device/per-agent browser keys.

## What This Changes

The issue requests a native browser chat layer with E2EE, QR/device pairing, no third-party chat service, and per-agent/per-device isolation.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
