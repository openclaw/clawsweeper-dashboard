## Summary

Keep open: current main and the latest release still provide Gateway WebSocket WebChat, device pairing, Matrix E2EE as a third-party channel option, and provider-backed Talk/WebRTC, but not the requested native no-third-party browser-held E2EE browser chat transport.

## What This Changes

The issue requests a native no-third-party browser E2EE chat layer with QR/device pairing and per-agent/per-device isolated encrypted channels.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
