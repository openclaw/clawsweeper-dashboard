## Summary

Keep open: current main and the latest release still provide authenticated Gateway WebSocket WebChat, Control UI chat, browser Talk/WebRTC voice, device pairing, and existing encrypted third-party/plugin channels, but not the requested no-third-party browser-held E2EE chat transport with encrypted browser message envelopes and per-device/per-agent keys.

## What This Changes

The issue proposes a native browser-based E2EE chat layer for OpenClaw instances with QR pairing, no third-party chat provider, and per-agent isolated encrypted channels.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel capability and threat model first, then implement protocol/key lifecycle, per-device/per-agent routing isolation, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
