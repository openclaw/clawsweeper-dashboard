## Summary

Keep open: current main and v2026.6.11 still provide Gateway/WebChat chat, device pairing, dmScope isolation, Matrix/Nostr encrypted channel alternatives, and browser Talk/WebRTC voice, but not the requested native no-third-party browser-held E2EE chat transport.

## What This Changes

The issue proposes a built-in browser-based E2EE chat layer with QR pairing, browser-held keys, per-agent/per-device isolation, and no third-party chat app.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model and capability first, then implement the chosen core or plugin-seam path with key lifecycle, encrypted envelopes, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests.
