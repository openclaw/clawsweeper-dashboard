## Summary

Keep open: current main and the latest release still provide authenticated Gateway/WebChat chat, dmScope isolation, and encrypted third-party/plugin channel options, but they do not implement native browser-held E2EE browser chat with browser key lifecycle or encrypted chat envelopes.

## What This Changes

The issue proposes a native browser-based E2EE chat layer with QR pairing, browser-held keys, no third-party chat provider, and per-agent/per-device isolated channels.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model first, then implement the chosen core or plugin-seam path with key lifecycle, encrypted envelopes, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests.
