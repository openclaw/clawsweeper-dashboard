## Summary

Keep open: current main and v2026.6.11 still provide authenticated Gateway WebSocket WebChat and provider-backed browser Talk, but not native no-third-party browser-held E2EE chat. The remaining work is a maintainer/security architecture decision, not conservative cleanup.

## What This Changes

Request a built-in browser-based E2EE chat transport with QR/device setup, no third-party account, and per-agent/per-device encrypted channel isolation.

## Best Possible Solution

Define a maintainer-approved encrypted browser-channel threat model and contract first, then implement protocol/key lifecycle, per-device/per-agent routing, transcript/relay semantics, UI/docs, and tests under the chosen core or plugin boundary.
