## Summary

Keep this issue open. Current main has authenticated Gateway WebChat, browser device pairing, browser-local identity, Web Push, and provider-backed Talk/WebRTC, but it still does not implement the requested browser-held E2EE chat transport, encrypted envelope contract, or per-device/per-agent browser key lifecycle.

## What This Changes

The issue requests native browser-held E2EE chat with no third-party chat app or account and per-agent/per-device encrypted channels.

## Best Possible Solution

Keep this as a maintainer-led product/security architecture item: define encrypted envelopes, browser-held key negotiation, key lifecycle, transcript/storage semantics, relay fallback, and the core-vs-plugin boundary before implementation.
