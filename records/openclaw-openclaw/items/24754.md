## Summary

Keep open: current main still provides authenticated Gateway WebSocket WebChat, device pairing, Talk/WebRTC voice, and configurable DM session isolation, but not the requested browser-held E2EE browser chat transport with encrypted per-device/per-agent channels.

## What This Changes

The issue requests a native no-third-party browser chat layer with browser-held E2EE keys and isolated per-agent/per-device channels.

## Best Possible Solution

Define a maintainer-approved encrypted-browser-channel capability and threat model first, then implement protocol fields, browser key lifecycle, per-device/per-agent routing, transcript semantics, relay/recovery behavior, docs, and contract tests under the chosen core or plugin boundary.
