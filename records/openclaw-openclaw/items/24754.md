## Summary

Keep this issue open: current main and the latest release still provide authenticated Gateway WebSocket WebChat, device pairing, Web Push, and provider-backed Talk/WebRTC, but not the requested browser-held E2EE chat transport or encrypted per-device/per-agent chat key lifecycle.

## What This Changes

Requests a native browser-based end-to-end encrypted chat layer for OpenClaw that avoids third-party chat apps and isolates browser chat channels per agent/device.

## Best Possible Solution

Keep this as a maintainer-led architecture item: define encrypted envelopes, browser-held key negotiation, key lifecycle, transcript/storage semantics, relay fallback, and the core-vs-plugin boundary before implementation.
