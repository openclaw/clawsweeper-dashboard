## Summary

Keep open: this maintainer-authored, protected security/compatibility PR is useful but still needs human boundary-design and rollout work before merge because the proposed loader-time policy has concrete bypasses and can fail existing plugins closed on upgrade.

## What This Changes

The PR adds loader-time plugin import-policy validation that rejects private OpenClaw imports, undeclared bare packages, and plugin-root escapes while allowing SDK subpaths, declared dependencies, Node builtins, and local imports.

## Best Possible Solution

Keep the import-boundary work open, rebase it on the current loader, harden enforcement with runtime or AST-backed resolution checks, and add an explicit compatibility rollout plan before merging.

Overall confidence: 0.92

Full review comments:

- **[P1] Reject private OpenClaw imports before allowlists:** `src/plugins/import-policy.ts:371-372`
  - body: `validateBareSpecifier` allows declared packages before checking the private `openclaw/*` guard. A plugin can add `openclaw` to dependencies and then import `openclaw/runtime`, defeating the boundary this PR is adding.
  - confidence: 0.96
- **[P1] Reject computed specifiers or enforce the boundary at runtime:** `src/plugins/import-policy.ts:256-279`
  - body: The policy only collects literal specifiers matched by regexes, so `require("openclaw/" + "runtime")` or `import(getSpecifier())` is never validated before Jiti executes it. That leaves a direct bypass for the security property claimed by the PR.
  - confidence: 0.92
- **[P1] Scan plugin-local dependency entrypoints:** `src/plugins/import-policy.ts:455`
  - body: After an allowed bare specifier passes the manifest allowlist, validation immediately continues without resolving or scanning the dependency's actual code. A plugin can ship a declared local dependency whose entrypoint imports private OpenClaw internals or escapes the plugin root.
  - confidence: 0.9
- **[P1] Resolve runtime overlay imports before allowlisting them:** `src/plugins/import-policy.ts:75`
  - body: `isRuntimeOverlayForwardImport` trusts a raw `../../../dist/` prefix before resolving the full path. A specifier with traversal after that prefix can skip the normal boundary checks instead of being constrained to the canonical dist root.
  - confidence: 0.86
- **[P1] Add an upgrade-safe enforcement path:** `src/plugins/loader.ts:1150-1160`
  - body: This turns policy violations into plugin load errors before module evaluation, but the PR body already notes existing plugins may rely on private imports or undeclared dependencies. Without a staged rollout, doctor/migration path, or maintainer-confirmed breaking change, upgrades can silently become plugin startup failures.
  - confidence: 0.88
- **[P3] Remove the release-owned changelog edit:** `CHANGELOG.md:55`
  - body: Normal PRs should not edit `CHANGELOG.md`; release generation owns that file. Keep the release-note context in the PR body or squash message instead.
  - confidence: 0.93
