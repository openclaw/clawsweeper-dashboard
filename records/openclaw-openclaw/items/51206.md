## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Reject private OpenClaw imports before dependency allowlists:** `src/plugins/import-policy.ts:371-375`
  - body: `allowedPackages.has(barePackage)` returns before the private `openclaw/*` guard, so a plugin can declare `openclaw` and still import `openclaw/runtime`. That defeats the boundary the PR is adding.
  - confidence: 0.94
- **[P1] Reject computed module specifiers or enforce them at runtime:** `src/plugins/import-policy.ts:256-280`
  - body: The scanner only records literal regex matches, so `require("openclaw/" + "runtime")` or a variable-fed dynamic import reaches module evaluation without policy validation. This leaves the new security boundary bypassable.
  - confidence: 0.9
- **[P1] Scan plugin-local dependency entrypoints before loading:** `src/plugins/import-policy.ts:439-455`
  - body: Declared bare imports are allowed and then skipped, so a dependency shipped under the plugin root can import private OpenClaw internals and execute when the plugin loads. Either traverse plugin-local dependencies or enforce the denylist at runtime.
  - confidence: 0.86
- **[P1] Add an upgrade-safe enforcement path:** `src/plugins/loader.ts:1150-1160`
  - body: This new check fails plugins before module evaluation, and the PR body acknowledges existing plugins may rely on undeclared packages or private imports. Without a staged rollout, migration, docs, or compatibility proof, existing setups can stop loading on upgrade.
  - confidence: 0.88
