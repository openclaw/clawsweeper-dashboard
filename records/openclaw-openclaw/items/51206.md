## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Reject private OpenClaw imports before allowlists:** `src/plugins/import-policy.ts:371-372`
  - body: `validateBareSpecifier` returns success for self-package and declared dependency matches before it checks `openclaw/*`. A plugin can declare `openclaw` and still import `openclaw/runtime`, bypassing the private import boundary this PR is adding.
  - confidence: 0.96
- **[P1] Reject computed specifiers or enforce at runtime:** `src/plugins/import-policy.ts:256-279`
  - body: The policy only records literal specifiers matched by these regexes, while plugin code can build the same blocked module name with computed `require()` or `import()` at runtime. That lets a plugin pass validation and then load the private module during evaluation.
  - confidence: 0.9
- **[P1] Validate plugin-local dependency entrypoints:** `src/plugins/import-policy.ts:439-455`
  - body: After a bare specifier is allowed by the manifest dependency list, validation immediately continues and never inspects the resolved dependency code under the plugin root. A plugin can hide forbidden private imports or root escapes inside a declared local dependency.
  - confidence: 0.88
- **[P1] Add an upgrade-safe enforcement path:** `src/plugins/loader.ts:1154-1160`
  - body: This branch turns any policy violation into a plugin load error before module evaluation. Because external plugins are a documented runtime surface, fail-closed startup behavior needs a staged rollout, explicit maintainer acceptance, or upgrade proof for existing plugins before merge.
  - confidence: 0.86
- **[P2] Resolve overlay imports before allowing them:** `src/plugins/import-policy.ts:75`
  - body: `isRuntimeOverlayForwardImport` allows every specifier with the raw `../../../dist/` prefix before the resolved path is checked. A path such as `../../../dist/../../outside.js` can satisfy the prefix test while escaping the intended canonical dist root.
  - confidence: 0.83
- **[P2] Support package.json directory entry resolution:** `src/plugins/import-policy.ts:318-324`
  - body: Local resolution only tries direct files and `index.*`, but Node also resolves `require("./dir")` through that directory's package entrypoints. Valid in-package imports using the standard directory entry pattern would be rejected as unresolved by the new policy.
  - confidence: 0.78
