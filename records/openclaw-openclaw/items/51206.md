## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Reject private OpenClaw imports before allowlists:** `src/plugins/import-policy.ts:366-375`
  - body: `validateBareSpecifier` returns success for the plugin package name or a declared dependency before it checks `openclaw/*`. A plugin can declare `openclaw` and then import `openclaw/runtime`, bypassing the private import boundary this PR is meant to enforce.
  - confidence: 0.96
- **[P1] Reject computed module specifiers or enforce at runtime:** `src/plugins/import-policy.ts:256-279`
  - body: The policy only records literal specifiers matched by these regexes, while Node accepts computed `require()` and `import()` specifiers at runtime. A plugin can build `openclaw/runtime` from a variable and pass validation before the loader evaluates it.
  - confidence: 0.9
- **[P1] Scan plugin-local dependency entrypoints:** `src/plugins/import-policy.ts:439-455`
  - body: After allowing a declared bare dependency, validation immediately continues and never inspects the resolved dependency code under the plugin root. That lets a plugin hide forbidden private imports or root escapes inside a declared local dependency.
  - confidence: 0.88
- **[P2] Support Node directory package resolution for local imports:** `src/plugins/import-policy.ts:318-324`
  - body: Local path resolution only tries direct files and `index.*` fallbacks, but Node also resolves `require("./dir")` through that directory's package metadata. Valid in-plugin imports using a package entrypoint can be rejected before runtime even though the actual loader would resolve them.
  - confidence: 0.82
- **[P1] Add an upgrade-safe enforcement path:** `src/plugins/loader.ts:1154-1160`
  - body: This converts any policy violation into a plugin load error before module evaluation. Existing external plugins are a compatibility baseline, so fail-closed startup behavior needs a staged rollout, migration/doctor path, or explicit maintainer acceptance with upgrade proof.
  - confidence: 0.86
- **[P3] Remove the normal PR changelog edit:** `CHANGELOG.md:55`
  - body: `CHANGELOG.md` is release-owned in this repo, and normal PRs should keep release-note context in the PR body or commit message. This line should be dropped before merge.
  - confidence: 0.94
