## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Reject private OpenClaw imports before dependency allowlists:** `src/plugins/import-policy.ts:371-372`
  - body: `allowedPackages.has(barePackage)` returns before the private `openclaw`/`openclaw/*` guard. A plugin can declare `openclaw` in its package metadata and then import `openclaw/runtime`, defeating the boundary this PR is meant to enforce.
  - confidence: 0.96
- **[P1] Block nonliteral module specifiers before execution:** `src/plugins/import-policy.ts:256-279`
  - body: The policy only collects literal specifiers matched by regex. Computed calls such as `require("openclaw/" + "runtime")` or `import(getSpecifier())` are not violations and still execute through the loader, so the new security boundary is bypassable.
  - confidence: 0.9
- **[P1] Validate plugin-local dependency entrypoints before execution:** `src/plugins/import-policy.ts:439-455`
  - body: Allowed bare imports are not resolved or traversed after validation. A plugin can declare a dependency and place code under its local dependency tree that imports private OpenClaw modules, and that code will run without being checked by this policy.
  - confidence: 0.88
- **[P2] Normalize runtime-overlay forwards before allowing them:** `src/plugins/import-policy.ts:389-396`
  - body: The runtime-overlay exception returns success based only on the raw `../../../dist/` prefix. A specifier with traversal after that prefix can skip the later root and canonical-dist checks, widening the allowed filesystem boundary.
  - confidence: 0.84
- **[P2] Resolve local package directories like the runtime loader:** `src/plugins/import-policy.ts:318-324`
  - body: Local resolution tries direct files and `index.*` files, but it does not honor a directory package's `package.json` entrypoint. Valid in-plugin imports such as `require("./dir")` can be rejected even though Node/Jiti would load them.
  - confidence: 0.82
- **[P1] Add upgrade proof before hard-failing plugin loads:** `src/plugins/loader.ts:1150-1160`
  - body: This inserts an unconditional load-time failure for policy violations, but the PR body says real third-party plugins were not verified and migration may be needed. That can turn existing installed plugins into upgrade-time failures without maintainer-approved rollout proof.
  - confidence: 0.86
- **[P3] Remove the release-owned changelog entry:** `CHANGELOG.md:53`
  - body: Normal OpenClaw PRs should not edit `CHANGELOG.md`; release generation owns that file. Keep the release-note context in the PR body or squash message instead of landing this changelog line.
  - confidence: 0.91
