## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Reject private OpenClaw imports before dependency allowlists:** `src/plugins/import-policy.ts:371-372`
  - body: `allowedPackages.has(barePackage)` returns before the `openclaw`/`openclaw/*` rejection, so a plugin can declare `openclaw` and import private host paths while still passing the new policy. Move the private OpenClaw guard ahead of package/self allowlists and add a regression test for that bypass.
  - confidence: 0.96
- **[P1] Block nonliteral module specifiers before execution:** `src/plugins/import-policy.ts:256-279`
  - body: The policy only sees literal specifiers matched by regex, so computed calls such as `require("openclaw/" + "runtime")` or `import(getSpecifier())` are not reported and still reach module execution. A security boundary here needs AST/runtime enforcement or a conservative violation for nonliteral require/import calls.
  - confidence: 0.9
- **[P1] Validate plugin-local dependency entrypoints before execution:** `src/plugins/import-policy.ts:439-455`
  - body: Allowed bare imports are not resolved or traversed after validation, so a declared package under the plugin root can import private OpenClaw modules or escape paths without this policy checking that code. Resolve local dependency entrypoints and scan the plugin-owned dependency graph, or enforce the boundary during resolution.
  - confidence: 0.88
- **[P2] Normalize runtime-overlay forwards before allowing them:** `src/plugins/import-policy.ts:389-396`
  - body: The runtime-overlay exception returns success based only on the raw `../../../dist/` prefix, before the resolved path is checked against the canonical dist root. Resolve and normalize first so traversal after the prefix cannot widen the allowed filesystem boundary.
  - confidence: 0.84
- **[P2] Resolve local package directories like the runtime loader:** `src/plugins/import-policy.ts:318-324`
  - body: Local resolution only tries files and `index.*`, so a valid in-plugin `require("./dir")` that relies on that directory's `package.json` entrypoint can be rejected even though Node/Jiti would load it. Use Node-compatible resolution for local paths or add the missing package-directory support.
  - confidence: 0.82
- **[P1] Add upgrade proof before hard-failing plugin loads:** `src/plugins/loader.ts:1150-1160`
  - body: This turns import-policy violations into unconditional plugin load failures, but the PR body says real third-party plugins were not verified and migration may be needed. Before merge, maintainers need rollout or migration proof for existing bundled and external plugins that may rely on the old behavior.
  - confidence: 0.86
- **[P3] Remove the release-owned changelog entry:** `CHANGELOG.md:53`
  - body: Normal OpenClaw PRs should not edit `CHANGELOG.md`; release generation owns that file. Keep the release-note context in the PR body or squash message instead of landing this changelog line.
  - confidence: 0.91
