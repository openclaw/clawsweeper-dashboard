## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.95

Full review comments:

- **[P1] Reject private OpenClaw imports before allowlists:** `src/plugins/import-policy.ts:371-372`
  - body: `resolveBarePackageName("openclaw/runtime")` returns `openclaw`, so a plugin that declares `openclaw` in dependencies hits `allowedPackages.has(...)` and returns `null` before the private OpenClaw rejection below. That defeats the central boundary this PR is adding; reject `openclaw` and `openclaw/*` before package/self allowlists and add coverage for that bypass.
  - confidence: 0.97
- **[P1] Block computed module specifiers before loading:** `src/plugins/import-policy.ts:274`
  - body: The scanner only records literal `require("...")`, `import("...")`, and similar calls. A plugin can build the same forbidden path in a variable, pass validation, and then the loader still executes the module through jiti, so nonliteral specifiers must be denied or enforced at resolution time before this can be a boundary.
  - confidence: 0.95
- **[P1] Validate plugin-local dependency entrypoints:** `src/plugins/import-policy.ts:455`
  - body: After a declared bare package is allowed, validation immediately continues without resolving or scanning the dependency entrypoint. A plugin-local package under `node_modules` can therefore import private OpenClaw internals and still execute when the plugin is loaded; resolve declared package entrypoints and traverse plugin-root code or enforce the boundary at runtime.
  - confidence: 0.94
- **[P1] Reject traversal inside bare specifiers before allowlists:** `src/plugins/import-policy.ts:357-359`
  - body: The SDK allowlist accepts any raw specifier starting with `openclaw/plugin-sdk/`, and declared packages are allowed by package name before subpath normalization. Requests like `openclaw/plugin-sdk/../../runtime` or a declared package subpath with `..` can escape the intended allowlist, so reject traversal segments or resolve the target before allowing the bare import.
  - confidence: 0.93
- **[P1] Normalize overlay forwards before allowing them:** `src/plugins/import-policy.ts:75`
  - body: The runtime-overlay exception returns true for any raw `../../../dist/` prefix and then `classifyLocalSpecifierViolation` skips the normal root checks. A suffix containing `..` can leave the canonical dist root while still passing this prefix check; resolve the specifier and prove it stays inside `canonicalDistRoot` before allowing it.
  - confidence: 0.93
- **[P2] Preserve package.json directory resolution:** `src/plugins/import-policy.ts:318-324`
  - body: Local path resolution only tries direct files, extensions, and `index.*`, but Node's CommonJS resolver calls `tryPackage` for directory requests and honors package entry metadata. Valid plugin imports such as `require("./dir")` with a `dir/package.json` entry would be rejected before runtime, so mirror Node-compatible directory resolution or use Node's resolver for policy checks.
  - confidence: 0.88
