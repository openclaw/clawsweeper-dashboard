Full review comments:

- **[P1] Reject private OpenClaw imports before package allowlists:** `src/plugins/import-policy.ts:371-372`
  - body: `allowedPackages.has(barePackage)` returns before the private `openclaw` and `openclaw/*` rejection, so a plugin can declare `openclaw` and import private host paths while still passing the new policy. Move the private OpenClaw guard ahead of package/self allowlists and add a regression test for that bypass.
  - confidence: 0.96
- **[P1] Block nonliteral module specifiers before execution:** `src/plugins/import-policy.ts:256-279`
  - body: The policy only sees literal specifiers matched by regex, so computed calls such as `require("openclaw/" + "runtime")` or `import(getSpecifier())` are not reported and still reach module execution. A security boundary here needs AST/runtime enforcement or a conservative violation for nonliteral require/import calls.
  - confidence: 0.9
- **[P1] Validate plugin-local dependency entrypoints before execution:** `src/plugins/import-policy.ts:439-455`
  - body: Allowed bare imports are not resolved or traversed after validation, so a declared package under the plugin root can import private OpenClaw modules or escape paths without this policy checking that code. Resolve plugin-owned dependency entrypoints and scan them, or enforce the boundary during module resolution.
  - confidence: 0.88
- **[P1] Reject traversal inside bare specifiers before allowlists:** `src/plugins/import-policy.ts:355-359`
  - body: This was visible in the earlier reviewed head, but it is a separate bypass: any `openclaw/plugin-sdk/...` string is allowed before normalizing subpath segments, so a request such as `openclaw/plugin-sdk/../runtime` can pass the policy while resolving outside the allowed SDK subpath. Reject `.` and `..` path segments before applying SDK or package allowlists.
  - late: true
  - confidence: 0.86
- **[P1] Normalize overlay forwards before allowing them:** `src/plugins/import-policy.ts:389-396`
  - body: This was visible in the earlier reviewed head: the runtime-overlay special case returns success for any raw `../../../dist/` prefix before resolving the remainder, so `../../../dist/../../...` skips the normal root checks. Resolve the path first and only allow it when the result stays under the canonical dist root.
  - late: true
  - confidence: 0.84
- **[P2] Preserve Node-compatible local directory resolution:** `src/plugins/import-policy.ts:318-324`
  - body: Local path resolution only tries direct files plus `index.*`, but Node also resolves `require("./dir")` through `dir/package.json` `main` or `exports`. This can reject valid in-package imports before runtime even though the current loader would resolve them.
  - confidence: 0.84
- **[P1] Add upgrade proof before hard-failing plugin loads:** `src/plugins/loader.ts:1150-1160`
  - body: This turns import-policy violations into unconditional plugin load failures, but the PR body says real third-party plugins were not verified and migration may be needed.   - confidence: 0.86
