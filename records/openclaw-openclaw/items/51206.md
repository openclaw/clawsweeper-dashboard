- **[P1] Reject private OpenClaw imports before dependency allowlists:** `src/plugins/import-policy.ts:371-372`
  - body: `allowedPackages.has(barePackage)` returns before the private `openclaw`/`openclaw/*` rejection, so a plugin can declare `openclaw` and import private host paths while still passing the new policy. Move the private OpenClaw guard ahead of package/self allowlists and add a regression test for that bypass.
  - confidence: 0.96
- **[P1] Block nonliteral module specifiers before execution:** `src/plugins/import-policy.ts:256-279`
  - body: The policy only sees literal specifiers matched by regex, so computed calls such as `require("openclaw/" + "runtime")` or `import(getSpecifier())` are not reported and still reach module execution. A security boundary here needs AST/runtime enforcement or a conservative violation for nonliteral require/import calls.
  - confidence: 0.9
- **[P1] Validate plugin-local dependency entrypoints before execution:** `src/plugins/import-policy.ts:439-455`
  - body: Allowed bare imports are not resolved or traversed after validation, so a declared package under the plugin root can import private OpenClaw modules or escape paths without this policy checking that code. Resolve plugin-owned dependency entrypoints and scan them, or enforce the boundary during module resolution.
  - confidence: 0.88
- **[P1] Add upgrade proof before hard-failing plugin loads:** `src/plugins/loader.ts:1150-1160`
  - body: This turns import-policy violations into unconditional plugin load failures, but the PR body says real third-party plugins were not verified and migration may be needed.
