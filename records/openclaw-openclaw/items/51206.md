## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.95

Full review comments:

- **[P1] Reject private OpenClaw imports before package allowlists:** `src/plugins/import-policy.ts:371-375`
  - body: The dependency allowlist returns before the private `openclaw/*` guard, so a plugin can declare `openclaw` in `dependencies` and still import `openclaw/runtime`. That defeats the boundary this PR is adding; check the private OpenClaw path before package-name allowlists and add a regression fixture.
  - confidence: 0.98
- **[P1] Block nonliteral module specifiers before execution:** `src/plugins/import-policy.ts:256-279`
  - body: The scanner only collects quoted literal `import`, `require`, and `require.resolve` specifiers, then the loader executes the plugin module. A plugin can compute the same forbidden specifier at runtime and bypass the policy, so nonliteral module calls need to be rejected or the restriction needs runtime resolver enforcement.
  - confidence: 0.95
- **[P1] Validate plugin-local dependency entrypoints before execution:** `src/plugins/import-policy.ts:439-455`
  - body: Declared bare packages are accepted and skipped with `continue`, but the dependency code itself is never resolved or scanned before Jiti evaluates the module graph. A plugin can place forbidden imports inside `node_modules/<declared-dep>/index.js`, so plugin-local dependency entrypoints need the same boundary enforcement or a runtime deny path.
  - confidence: 0.94
- **[P1] Reject traversal inside bare specifiers before allowlists:** `src/plugins/import-policy.ts:355-359`
  - body: The SDK prefix check accepts any `openclaw/plugin-sdk/` subpath before normalizing path segments, and declared package checks similarly trust the package prefix. Requests like `openclaw/plugin-sdk/../../runtime` or `left-pad/../other-package` can normalize outside the intended package, so reject `.` and `..` segments before any allowlist success.
  - confidence: 0.91
- **[P1] Normalize overlay forwards before allowing them:** `src/plugins/import-policy.ts:63-75`
  - body: The runtime-overlay exception allows any raw specifier starting with `../../../dist/` and returns before the normal inside-root checks. A suffix with additional `..` segments can escape the intended dist root, so resolve and realpath the target against the canonical dist root before allowing the overlay import.
  - confidence: 0.9
- **[P1] Use fileURLToPath for file specifier checks:** `src/plugins/import-policy.ts:329-334`
  - body: Late discovery: this code was unchanged at the prior reviewed head, but it is still a concrete boundary bug. `new URL(specifier).pathname` leaves percent-encoded path segments for policy checks while Node file URL loading decodes them, so use `fileURLToPath()` before normalization and containment checks.
  - late: true
  - confidence: 0.87
- **[P2] Preserve Node-compatible local directory resolution:** `src/plugins/import-policy.ts:318-324`
  - body: The local resolver tries direct files and `index.*`, but Node also resolves `require("./dir")` through `dir/package.json` `main` or exports. Valid in-package imports using that standard pattern will now fail as unresolved inside the plugin root, so mirror Node-compatible package-directory resolution or do not fail closed on it.
  - confidence: 0.9
