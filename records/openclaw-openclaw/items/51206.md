Full review comments:

- **[P1] Reject private OpenClaw imports before package allowlists:** `src/plugins/import-policy.ts:371-372`
  - body: The allowed-package check returns before the private `openclaw` and `openclaw/*` rejection, so a plugin can declare `openclaw` and import private host paths while still passing the new policy. Move the private OpenClaw guard ahead of package and self allowlists and add a regression test for that bypass.
  - confidence: 0.96
- **[P1] Block nonliteral module specifiers before execution:** `src/plugins/import-policy.ts:256-279`
  - body: The policy only sees literal specifiers matched by regex, so computed calls such as concatenated `require()` or dynamic `import()` arguments are not reported and still reach module execution. A security boundary here needs AST/runtime enforcement or a conservative violation for nonliteral require/import calls.
  - confidence: 0.9
- **[P1] Validate plugin-local dependency entrypoints before execution:** `src/plugins/import-policy.ts:439-455`
  - body: Allowed bare imports are not resolved or traversed after validation, so a declared package under the plugin root can import private OpenClaw modules or escaping paths without this policy checking that code. Resolve plugin-owned dependency entrypoints and scan them, or enforce the boundary during module resolution.
  - confidence: 0.88
- **[P1] Reject traversal inside bare specifiers before allowlists:** `src/plugins/import-policy.ts:355-359`
  - body: Any `openclaw/plugin-sdk/...` string is allowed before subpath normalization, and the same first-segment allowlist is used for declared packages. Reject `.` and `..` path segments before applying SDK or package allowlists so a request cannot resolve outside the intended package subpath.
  - confidence: 0.86
- **[P1] Normalize overlay forwards before allowing them:** `src/plugins/import-policy.ts:389-396`
  - body: The runtime-overlay special case returns success for any raw `../../../dist/` prefix before resolving the remainder, so traversal after `dist/` skips the normal root checks. Resolve the path first and only allow it when the result stays under the canonical dist root.
  - confidence: 0.84
- **[P2] Preserve Node-compatible local directory resolution:** `src/plugins/import-policy.ts:318-324`
  - body: Local path resolution only tries direct files plus `index.*`, but Node-compatible `require("./dir")` can resolve through `dir/package.json` entry metadata. This can reject valid in-package imports before runtime even though the current loader would resolve them.
  - confidence: 0.84
