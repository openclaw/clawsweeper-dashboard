## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.94

Full review comments:

- **[P1] Reject private OpenClaw imports before dependency allowlists:** `src/plugins/import-policy.ts:371-375`
  - body: `openclaw/runtime` is rejected only after same-package and dependency allowlists. A plugin can declare `openclaw` in package.json and the policy returns early, defeating the private-import boundary this PR is trying to enforce.
  - confidence: 0.98
- **[P1] Enforce computed imports instead of regex-only literals:** `src/plugins/import-policy.ts:256-279`
  - body: The scanner only matches literal `import`, `require`, and `require.resolve` strings. A plugin can compute the same forbidden specifier at runtime and still reach private OpenClaw modules or outside-root files once the module executes.
  - confidence: 0.93
- **[P1] Validate plugin-local dependency entrypoints before execution:** `src/plugins/import-policy.ts:439-455`
  - body: Allowed bare dependencies are not resolved or scanned; validation continues immediately after the allowlist check. A plugin can hide a forbidden private import inside its local node_modules dependency and the loader will execute it.
  - confidence: 0.9
- **[P2] Normalize runtime-overlay forwards before allowing them:** `src/plugins/import-policy.ts:75`
  - body: The runtime-overlay exception allows any raw specifier starting with `../../../dist/` before boundary checks. A path with later `..` segments can escape the intended canonical dist root while still passing this early allowlist.
  - confidence: 0.88
- **[P2] Resolve local package directories the way Node does:** `src/plugins/import-policy.ts:318-322`
  - body: Local path resolution only tries direct files and `index.*` fallbacks, but Node also supports directory package.json entrypoints. Valid in-package imports such as `require("./dir")` can be rejected even though runtime resolution would load them.
  - confidence: 0.82
- **[P3] Remove the release-owned changelog entry:** `CHANGELOG.md:55`
  - body: OpenClaw's changelog is release-generated, and normal PRs should put release-note context in the PR body or squash message instead of editing CHANGELOG.md directly.
  - confidence: 0.96
