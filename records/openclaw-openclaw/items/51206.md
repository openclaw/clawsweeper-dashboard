## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.94

Full review comments:

- **[P1] Reject private OpenClaw imports before package allowlists:** `src/plugins/import-policy.ts:371-376`
  - body: The private `openclaw/*` rejection runs after the package-name and dependency allowlists, so a plugin can declare `openclaw` and still import `openclaw/runtime`. That defeats the boundary this PR is meant to enforce; move the private OpenClaw guard before any package allowlist and cover the bypass in a test.
  - confidence: 0.96
- **[P1] Block nonliteral module specifiers before execution:** `src/plugins/import-policy.ts:273-274`
  - body: The scanner only collects string-literal `import`/`require` calls, but the loader executes the plugin afterward. Computed specifiers such as `require("openclaw/" + "runtime")` are invisible to the policy and still run, so this needs AST rejection of nonliteral specifiers or runtime resolver enforcement.
  - confidence: 0.92
- **[P1] Validate plugin-local dependency entrypoints before execution:** `src/plugins/import-policy.ts:455`
  - body: Declared bare packages are allowed and then skipped, so a plugin can ship a dependency under its root whose entrypoint imports private OpenClaw internals or escapes the package. If declared dependencies are allowed, plugin-local dependency entrypoints need to be resolved and checked before `getJiti` executes them.
  - confidence: 0.9
- **[P1] Reject traversal inside bare specifiers before allowlists:** `src/plugins/import-policy.ts:355-359`
  - body: The raw `openclaw/plugin-sdk/` prefix is accepted without normalizing or rejecting `.`/`..` segments, and declared package subpaths get the same first-segment allowlist treatment. A normalized subpath can leave the intended SDK or package boundary while the policy still treats it as allowed.
  - confidence: 0.86
- **[P1] Normalize overlay forwards before allowing them:** `src/plugins/import-policy.ts:75`
  - body: The runtime overlay exception allows any specifier that starts with `../../../dist/` and returns before the resolved path is checked. A suffix containing additional `..` segments can escape the canonical dist root, so the exception should be based on the normalized real resolved path instead of a raw string prefix.
  - confidence: 0.88
- **[P2] Preserve Node-compatible local directory resolution:** `src/plugins/import-policy.ts:318-324`
  - body: Local resolution only tries direct files and `index.*`, but Node also resolves `require("./dir")` through `dir/package.json` `main`/`exports`. Valid plugin-local imports using that standard package-directory shape will now fail policy validation before runtime would load them.
  - confidence: 0.88
