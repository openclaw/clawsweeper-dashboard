## Summary

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Reject private OpenClaw imports before allowlists:** `src/plugins/import-policy.ts:371-372`
  - body: `allowedPackages.has(barePackage)` returns before the private `openclaw/*` rejection, so a plugin can declare `openclaw` and then import `openclaw/runtime` while passing the new policy. Move the private OpenClaw guard ahead of package/self allowlists and add a regression test for this bypass.
  - confidence: 0.96
- **[P1] Block non-literal specifiers or enforce runtime resolution:** `src/plugins/import-policy.ts:270-274`
  - body: The policy only matches literal `import(...)` and `require(...)` strings. A plugin can compute the same forbidden specifier and still reach module evaluation, so this does not enforce the claimed boundary unless non-literal specifiers are rejected or runtime resolution is also gated.
  - confidence: 0.9
- **[P1] Validate plugin-local dependency code before execution:** `src/plugins/import-policy.ts:455`
  - body: After a declared bare package passes validation, this branch immediately `continue`s instead of resolving and scanning the dependency entrypoint. A plugin can hide a forbidden private import inside its own `node_modules` dependency and the loader will execute it.
  - confidence: 0.88
- **[P1] Add an upgrade-safe rollout for hard load failures:** `src/plugins/loader.ts:1159-1160`
  - body: This turns policy violations into hard loader errors before plugin execution, but the PR does not include a maintainer-approved rollout, warning/doctor path, docs, or representative plugin proof. Existing plugins using private internals or undeclared packages can stop loading on upgrade.
  - confidence: 0.86
