## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Move private OpenClaw checks before dependency allowlists:** `src/plugins/import-policy.ts:371-372`
  - body: A plugin can declare `openclaw` in its package metadata and then `require("openclaw/runtime")`; `allowedPackages.has(barePackage)` returns before the private OpenClaw guard runs. Move the private `openclaw`/`openclaw/*` rejection ahead of package-name and dependency allowlists, and add a regression test for a declared `openclaw` dependency.
  - confidence: 0.96
- **[P1] Block computed specifiers or enforce at runtime:** `src/plugins/import-policy.ts:256-280`
  - body: The new policy only finds literal string specifiers with regexes, so `require("openclaw/" + "runtime")` or `import(getSpecifier())` can pass validation and still load private internals at runtime. Either reject non-literal import/require calls with an AST parser or enforce the boundary in module resolution.
  - confidence: 0.9
- **[P1] Validate plugin-local dependency entrypoints:** `src/plugins/import-policy.ts:439-455`
  - body: Allowed bare imports stop at the package allowlist and are never resolved or traversed, so a declared plugin-local dependency can import `openclaw/runtime` before the plugin module graph is executed. Resolve allowed dependencies from the importer and validate plugin-root dependency entrypoints, or make runtime resolution deny the forbidden imports.
  - confidence: 0.88
- **[P1] Add an upgrade-safe enforcement path:** `src/plugins/loader.ts:1154-1160`
  - body: This turns policy violations into hard plugin load failures for all plugin origins before module evaluation. Without a maintainer-approved rollout, docs/doctor guidance, and upgrade proof for existing bundled and third-party plugins, a security hardening change can break working installs at upgrade time.
  - confidence: 0.88
- **[P2] Resolve overlay imports before allowing them:** `src/plugins/import-policy.ts:389-396`
  - body: The runtime-overlay exception returns success based only on the raw `../../../dist/` prefix, before checking where the specifier resolves. A path like `../../../dist/../../outside.js` can skip containment checks; resolve and require the result to stay inside the canonical dist root instead.
  - confidence: 0.86
- **[P2] Support package.json directory entry resolution:** `src/plugins/import-policy.ts:318-324`
  - body: Local module resolution only tries direct files and `index.*` fallbacks, but Node also supports directory entrypoints through `package.json` fields. A valid in-plugin `require("./dir")` can be rejected even though runtime resolution would load it, so the policy should use Node-compatible resolution for local imports.
  - confidence: 0.78
