## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Reject private OpenClaw imports before dependency allowlists:** `src/plugins/import-policy.ts:371-372`
  - body: `allowedPackages.has(barePackage)` returns before the private `openclaw/*` guard, so a plugin can declare `openclaw` and still import `openclaw/runtime`. Move the private-path rejection ahead of package allowlists and add a regression test for this bypass.
  - confidence: 0.98
- **[P1] Block nonliteral module specifiers before execution:** `src/plugins/import-policy.ts:256-279`
  - body: The policy only collects literal `import`/`require` strings with regexes, but the loader runs the plugin through Jiti afterward. Computed specifiers such as string concatenation can evade validation and still load private modules, so nonliteral resolution needs to be rejected or enforced at runtime.
  - confidence: 0.94
- **[P1] Validate plugin-local dependency entrypoints before execution:** `src/plugins/import-policy.ts:440-455`
  - body: Declared bare packages are allowed and then skipped, so a plugin can put forbidden imports inside its own `node_modules` dependency and execute them after validation. Resolve and traverse plugin-local dependency entrypoints, or enforce the same block during runtime resolution.
  - confidence: 0.92
- **[P1] Use fileURLToPath for file imports:** `src/plugins/import-policy.ts:329-334`
  - body: `new URL(specifier).pathname` keeps percent escapes, while Node converts file URLs to filesystem paths before loading. That mismatch can let encoded traversal pass the policy but resolve outside the plugin root at runtime; use `fileURLToPath()` and validate the decoded path.
  - confidence: 0.87
- **[P1] Constrain runtime-overlay forwards after resolution:** `src/plugins/import-policy.ts:389-396`
  - body: The overlay exception returns success for any raw specifier starting with `../../../dist/` before resolving the final path. A suffix with additional traversal can escape the intended canonical dist root, so resolve and verify the target stays inside the canonical dist root before allowing it.
  - confidence: 0.86
- **[P3] Remove the release-owned changelog entry:** `CHANGELOG.md:55`
  - body: Normal PRs should not edit `CHANGELOG.md`; release generation owns that file. Keep the release-note context in the PR body or squash message instead and remove this entry from the branch.
  - confidence: 0.96
