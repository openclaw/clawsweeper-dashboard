## Label Justifications

- `P2`: This is a consistently reproducible released regression with limited blast radius: unknown CLI commands emit misleading plugin crashes, but normal Gateway and Codex agent operation remains healthy.
- `impact:ux-friction`: A routine CLI typo misleadingly appears to indicate a broken Codex installation before the correct unknown-command diagnostic is shown.

## Summary

Keep open: current main still performs Codex runtime-state setup during lightweight CLI metadata discovery, while both linked closing PRs remain open. The issue should remain canonical until the explicit registration-mode fix or an equivalent repair lands.

## What This Changes

Prevent unknown CLI-command discovery from running Codex runtime-only setup when plugin runtime state is unavailable.

## Best Possible Solution

Register Codex CLI metadata first, return early for every non-full registration mode, retain strict runtime-state requirements for full activation, and prove unknown-command, Codex help, and full Gateway paths before landing.
