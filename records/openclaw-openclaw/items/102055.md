## Summary

Keep open: current main still lets malformed QA JSON bodies escape through raw `SyntaxError` text, and no duplicate or open/merged fix PR was found. The attached patch comment points in the same narrow direction, but there is no canonical landed fix yet.

## What This Changes

The issue asks for QA Lab and QA Bus JSON POST endpoints to return stable malformed-body diagnostics instead of raw JavaScript parser text.

## Best Possible Solution

Normalize invalid JSON at the shared QA body-reader boundary so QA Bus and QA Lab return one stable malformed-body diagnostic while preserving empty-body `{}` behavior and existing size/time limit responses.

## Solution Assessment

Yes: the narrow maintainable fix is to normalize `INVALID_JSON` inside `readQaJsonBody` or by reusing the existing bounded JSON helper, then add QA Bus/Lab regressions. A broader server refactor or new config surface is unnecessary.
