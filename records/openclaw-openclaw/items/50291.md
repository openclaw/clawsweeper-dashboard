## Summary

Keep open: current main has partially addressed lifecycle run correlation, but the broad plugin-hook trace context request still has real source-level gaps in outbound message_sending identity, first-class agent/message span aliases, and subagent requester-run hierarchy.

## What This Changes

Request to add trace correlation fields such as runId, messageId, senderId, parentSpanId, and subagent parent/child run IDs across plugin hook contexts and events.

## Best Possible Solution

Define one backward-compatible plugin-hook correlation contract, then land focused slices for agent inbound identity, outbound delivery correlation, subagent child/requester run IDs, and trace/span aliases with SDK docs and contract tests aligned.

## Reproduction Assessment

Yes, at source level: current main still lacks outbound run/message identity in message_sending and requesterRunId in subagent hook contracts, while only part of lifecycle runId is implemented.

## Solution Assessment

No, not as a one-shot mechanical patch; the direction is valid, but the best fix needs maintainer-approved public SDK semantics across several hook families before implementation.
