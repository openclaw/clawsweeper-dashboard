## Summary

Keep open: current main has implemented part of the requested lifecycle correlation, but outbound message hooks and subagent parent-run correlation still have clear source-level gaps that need maintainer API direction.

## What This Changes

Request to add richer plugin-hook trace context such as run, message, sender, and parent-span identifiers so observability plugins can correlate concurrent messages, agent lifecycle hooks, message hooks, and subagent traces.

## Best Possible Solution

Adopt a maintainer-approved additive plugin-hook tracing contract that reuses diagnostic trace context where appropriate, covers outbound message correlation, and carries subagent child/requester run identity without reviving deprecated hooks as the primary API.

## Reproduction Assessment

Yes at source level: current hook types and dispatch code prove lifecycle runId is partly implemented while outbound message and requester-run subagent correlation remain missing. I did not run a live observability plugin scenario because this review is read-only and the source contract is sufficient to verify the remaining gaps.

## Solution Assessment

Unclear as a single field-by-field patch: adding fields is plausible, but the maintainable solution should define the supported public tracing contract first and then align lifecycle, message, and subagent hooks to it.
