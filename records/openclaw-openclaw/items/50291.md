## Label Justifications

- `P2`: The issue blocks reliable observability correlation for plugin authors in multi-run and subagent workflows, but it is not an emergency user blocker or data-loss report.
- `impact:session-state`: The missing correlation fields cause tracing plugins to mis-associate or fail to stitch session, run, message, and subagent state.

## Summary

Current main has shipped part of the requested correlation surface, notably `runId` propagation for selected agent lifecycle hooks and a diagnostic trace carrier, but the issue's central ask remains open because outbound message hooks, agent hook span aliases, and subagent requester-run hierarchy still do not expose a unified public plugin correlation contract.

## What This Changes

Add consistent trace and run correlation context such as message id, run id, span hierarchy, and parent span fields across OpenClaw plugin hooks for observability integrations.

## Best Possible Solution

Define one additive, backward-compatible plugin hook correlation contract across agent, message, subagent, and diagnostics paths, then document and test fresh and concurrent-run behavior against that contract.
