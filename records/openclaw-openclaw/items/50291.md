## Label Justifications

- `P2`: The issue affects observability plugin correlation for agent/session state with limited blast radius, but it is not a core runtime outage.
- `impact:session-state`: Missing correlation fields can cause plugins to mis-associate runs, messages, sessions, and subagent hierarchy in concurrent or nested workflows.

## Summary

Keep open: current main has implemented the lifecycle `runId` part, but the central observability request remains partially unsolved because outbound `message_sending` still lacks run/message identity and subagent hooks still lack requester run identity for run-based trace trees.

## What This Changes

The issue requests richer plugin hook trace context so observability plugins can correlate agent runs, messages, outbound delivery, and nested subagent spans.

## Best Possible Solution

Define one backward-compatible plugin-hook correlation contract, then land focused slices for outbound delivery run/message identity and subagent child/requester run identity with SDK docs and contract tests aligned.

## Reproduction Assessment

Yes, at source level. Current main explicitly documents that outbound delivery does not yet plumb `runId`, `message_sending` lacks run/session/message event fields, and subagent lifecycle hooks emit child run identity without requester run identity.

## Solution Assessment

No, not as the broad all-hooks mechanical patch originally proposed. The direction is valid, but the best fix is a maintainer-approved public SDK contract that uses current typed hooks and diagnostic trace context rather than expanding legacy hooks indiscriminately.
