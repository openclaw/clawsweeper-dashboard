## Summary

Keep open: current main has added useful correlation slices, including runId backfill for legacy agent lifecycle hooks and message-hook context fields, but the broad trace-context request is still not implemented across outbound message hooks, agent contexts, and subagent parent-run relationships.

## What This Changes

Request to add message, sender, run, and span/parent trace identifiers across plugin hook events and contexts so observability plugins can build accurate trace trees.

## Best Possible Solution

Define a minimized additive Plugin SDK trace-correlation contract, then wire agent, message, and subagent hook families consistently with docs, API baseline updates, and focused hook-order/correlation tests.

## Reproduction Assessment

Yes. Source inspection shows current main still lacks outbound runId in message_sending, requesterRunId in subagent hook payloads, and message/span fields across all agent hook contexts.

## Solution Assessment

Unclear pending maintainer API design. Additive trace fields are plausible, but the best fix should avoid expanding legacy before_agent_start semantics and should define one coherent Plugin SDK contract across hook families.
