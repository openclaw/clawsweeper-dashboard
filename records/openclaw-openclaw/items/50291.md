## Summary

Keep open: current main has addressed part of the runId gap for legacy agent lifecycle hooks and added a diagnostic trace carrier, but the requested public hook trace context remains incomplete for outbound message runId, agent message/span aliases, and subagent requester/child run hierarchy.

## What This Changes

Request adds richer trace-correlation metadata across plugin hook contexts and message/subagent hook payloads so observability plugins can build accurate per-turn trace trees.

## Best Possible Solution

Define a maintainer-approved trace-correlation contract for plugin hooks, likely using the existing diagnostic trace carrier plus typed lifecycle hooks, then fill the outbound message and subagent run-relationship gaps with focused tests and docs.

## Maintainer Decision

Rationale: Both paths affect the public plugin SDK, identifier exposure, deprecated before_agent_start semantics, outbound delivery hooks, and subagent lifecycle contracts; automation cannot safely choose the permanent API shape.

Owner confidence: high

Options:

- **Design narrow trace contract (recommended):** Use the existing DiagnosticTraceContext and typed lifecycle hooks as the canonical observability surface, then add only the missing run/message/subagent fields required to make that contract complete.
- **Add broad fields everywhere:** Treat the issue literally by adding runId/messageId/senderId/span fields across all applicable hook payloads and contexts, accepting a larger public SDK expansion.
- **Defer to narrower issues:** Leave this umbrella open only as context and handle outbound runId, agent_start, and sender metadata through the existing narrower issues.

## Reproduction Assessment

Yes, by source inspection rather than a live run: current main still omits requested correlation fields from agent context, outbound message_sending, and subagent requester-run hook data. The existing tests only prove the partial runId injection for before_agent_start and agent_end.

## Solution Assessment

Unclear as written: adding every requested field broadly is plausible, but the better long-term fix is a maintainer-approved trace context contract that avoids making deprecated hooks and ad hoc span aliases the permanent API.
