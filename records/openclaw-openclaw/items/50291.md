## Summary

Keep open: current main and v2026.6.11 cover part of the request with lifecycle runId backfill and message-hook trace context, but outbound message_sending still lacks run/message identity and public subagent hooks still lack requesterRunId for run-based trace hierarchy.

## What This Changes

The issue requests richer plugin hook trace context such as runId, messageId, senderId, trace/span fields, and requesterRunId across agent, message, and subagent hook families.

## Best Possible Solution

Define one additive, backward-compatible plugin-hook correlation contract, then land focused slices for agent inbound identity, outbound delivery run/message correlation, subagent child/requester run IDs, and trace/span aliases with SDK docs and tests aligned.

## Reproduction Assessment

Yes, at source level. Current main still shows missing outbound run/message identity and no requesterRunId in public subagent hook contracts, although lifecycle runId backfill is now covered.

## Solution Assessment

No, not as a one-shot mechanical field addition. The direction is valid, but the best fix is a maintainer-approved public SDK contract across agent, message, diagnostics, and subagent hooks before implementation.
