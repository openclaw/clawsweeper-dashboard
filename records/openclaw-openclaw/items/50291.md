## Label Justifications

- `P2`: The issue affects plugin observability and trace correlation for concurrent or nested runs, but it is a bounded API/product improvement rather than an active core outage.
- `impact:session-state`: Missing run, message, and requester identifiers can cause plugins to mis-associate events across sessions, turns, and subagent hierarchy.

## Summary

Keep open: current main partially implements agent lifecycle runId correlation, but outbound message hooks still lack per-turn run/message identity and subagent hooks still lack requester run identity for run-based trace trees.

## What This Changes

The issue requests plugin hook trace and correlation fields such as runId, messageId, senderId, span context, and subagent parent/child run identity across agent, message, and subagent hooks.

## Best Possible Solution

Define one additive plugin-hook correlation contract, then land focused slices for outbound run/message identity, subagent child/requester run IDs, and trace/span context with docs and contract tests aligned.

## Reproduction Assessment

Yes, at source level: current main still documents outbound runId as not plumbed, message_sending lacks requested identity fields, and subagent hooks lack requesterRunId; no live Feishu/group-chat repro was run in this read-only review.

## Solution Assessment

No as a mechanical one-shot patch; the direction is valid, but the best fix needs a maintainer-approved public Plugin SDK contract across several hook families.
