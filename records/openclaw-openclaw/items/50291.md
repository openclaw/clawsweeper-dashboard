## Summary

Keep open: current main has added some run and diagnostic trace context to agent lifecycle hooks, but the central observability gap remains for outbound message hooks and run-based subagent parent correlation, so this is still meaningful plugin API work rather than conservative cleanup.

## What This Changes

Expose complete trace correlation data across plugin hooks, including run/message/sender identity and parent-child span or run relationships for observability plugins.

## Best Possible Solution

Define an additive plugin trace-correlation contract that preserves existing hook compatibility, then land it in narrow slices for typed agent start/subagent parent identity and outbound message run correlation with SDK docs and API-baseline coverage.

## Reproduction Assessment

Yes. Source inspection on current main shows the remaining API gap: outbound `message_sending` lacks run/message correlation fields, and subagent plugin events lack requester run identity for run-based trace trees.

## Solution Assessment

Unclear. The broad requested direction is reasonable, but the best maintainable fix is an additive maintainer-approved plugin API design rather than mechanically adding every proposed field to every hook.
