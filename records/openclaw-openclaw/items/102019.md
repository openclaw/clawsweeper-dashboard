## Summary

Keep open. Current main still emits trajectory `session.ended` with only coarse status and terminal flags, and the documented OTel surface exposes `openclaw.run` outcome/error fields rather than a public `openclaw.end_reason` contract; this needs a maintainer telemetry-contract decision, not cleanup closure.

## What This Changes

The issue requests a populated semantic `openclaw.end_reason` attribute on `session.ended` telemetry so operators can distinguish completion, timeout, interruption, and failure modes.

## Best Possible Solution

Define one additive low-cardinality session termination reason contract, derive it from the canonical terminal outcome path, and emit it on the maintainer-approved trajectory and/or OTel surfaces with docs and focused regression coverage.
