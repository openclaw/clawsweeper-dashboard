## Summary

Keep this PR open for maintainer review/merge: current `main` and `v2026.6.11` still apply the fixed 15s wrapper to `memory_search`, while this head appears to implement the scoped QMD timeout fix correctly with strong real-behavior proof. ## What This Changes

The PR scopes `memory_search` deadlines so QMD search commands use `memory.qmd.limits.timeoutMs` while setup, fallback, wiki/supplement, sync, visibility filtering, and cleanup remain bounded by the default 15s deadline, with docs and regression tests updated.

## Best Possible Solution

Land this focused branch if maintainers accept using the existing QMD timeout only for live QMD search commands, then redirect broader timeout proposals through the canonical timeout issue.
