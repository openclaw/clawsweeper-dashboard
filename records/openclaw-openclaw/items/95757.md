## Summary

Keep open: this PR is a live candidate fix for the linked QMD timeout bug, and the current patch appears correct and well-proven, but it still needs maintainer acceptance of the longer QMD command wait plus conflict resolution before merge.

## What This Changes

The PR scopes `memory_search` deadlines so only actual QMD search commands can use `memory.qmd.limits.timeoutMs`, while setup, fallback, wiki/supplement work, sync waits, filtering, and cleanup keep the default 15-second budget.

## Best Possible Solution

Make this PR mergeable, land the scoped QMD command-timeout policy if maintainers accept the availability tradeoff, and use the merged result as the canonical fix for the linked QMD timeout issue while closing or retargeting broader overlapping timeout proposals.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 still apply a fixed 15-second `memory_search` wrapper while QMD already has a configurable command timeout, matching the linked issue's failure mode.

## Solution Assessment

Yes, with maintainer acceptance. This is the narrowest maintainable shape I found because it reuses the existing QMD timeout only at the QMD command owner boundary instead of adding a new global config/env knob or broad whole-manager exemption.
