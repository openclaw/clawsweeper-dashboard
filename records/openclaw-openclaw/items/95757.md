## Summary

This PR remains necessary because neither current main nor v2026.6.11 solves the reported configured-QMD-timeout mismatch. The real before/after evidence, focused coverage, maintained repair history, and repeated zero-finding reviews support landing the exact head after required checks complete.

## What This Changes

The PR scopes the existing memory-search deadline so configured QMD command timeouts can exceed 15 seconds while setup, fallback, supplements, filtering, cancellation, and cleanup remain separately bounded.

## Best Possible Solution

Land the phase-owned implementation: apply memory.qmd.limits.timeoutMs only to actual QMD search commands, retain the established default deadline for every surrounding phase, preserve caller cancellation, and give builtin fallback a fresh bounded budget.
