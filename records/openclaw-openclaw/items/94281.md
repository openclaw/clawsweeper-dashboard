## Summary

Keep open: the PR still carries a plausible fix for the linked screenshot truncation report, but it is not merge-ready because it changes an explicitly preserved raw media invoke contract, conflates `screen.record` with snapshot handling, and still lacks after-fix real behavior proof.

## What This Changes

The PR routes generic `nodes` invoke results through a sanitizer that writes large top-level `payload.base64` values to temp files and returns `FILE:` output instead of raw JSON.

## Best Possible Solution

Resolve the raw-invoke compatibility decision first, then either land a tested command-specific file-backed sanitizer with real proof or close this branch as superseded by the dedicated `screen_snapshot` action.

## Reproduction Assessment

Yes at source level: current main preserves explicitly enabled raw media invoke while the live tool-result default cap remains 16,000 chars, so a larger inline screenshot payload can still be truncated. I did not run a live Windows node in this read-only review.

## Solution Assessment

No as submitted. File-backed output is plausible, but this patch changes the raw invoke contract and should either preserve that contract or make the compatibility decision explicit with command-specific helpers, tests, and real proof.
