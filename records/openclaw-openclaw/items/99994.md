## Summary

Keep open. Current main and the latest release still have the reported non-Windows session-store retry gap and the workspace profile read still rethrows non-ENOENT read errors, so the central heartbeat-adjacent reliability problem remains actionable even though the issue overstates that `loadSessionStore` always propagates the final read error.

## What This Changes

The issue requests bounded retry handling for transient EAGAIN-style filesystem reads in heartbeat-adjacent session-store and workspace profile reads on macOS/Linux.

## Best Possible Solution

Add a narrow bounded transient-read retry for the affected session-store and workspace template reads, with focused regression tests and PR-body release-note context, while preserving ENOENT and permanent-error behavior.

## Reproduction Assessment

Yes for a focused source-level reproduction: current main rethrows non-ENOENT workspace template read errors and does not retry session-store reads on non-Windows. I did not live-reproduce the macOS/Linux race in this read-only review.

## Solution Assessment

Yes, a bounded retry at the read seams is the best narrow fix; it should align with the existing transient read predicate pattern and avoid a dist-only patch, config knob, or broad filesystem fallback.
