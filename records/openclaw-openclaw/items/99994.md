## Summary

Keep open. Current main and v2026.6.11 still have the non-Windows session-store read retry gap and the workspace template read still rethrows non-ENOENT read errors, so the reported heartbeat-adjacent reliability bug remains actionable.

## What This Changes

The issue requests bounded retry handling for transient EAGAIN/errno -11 reads in `loadSessionStore()` and `fileContentDiffersFromTemplate()` so heartbeat ticks do not fail during filesystem write races.

## Best Possible Solution

Add a narrow bounded transient-read retry at the session-store and workspace template read seams, reusing or aligning with the existing transient read predicate, and cover both paths with focused regression tests.

## Reproduction Assessment

Yes for a source-level reproduction: current main does not retry session-store reads on non-Windows and rethrows non-ENOENT workspace template read errors. I did not run a live macOS/Linux race reproduction in this read-only review.

## Solution Assessment

Yes, a bounded retry at the read seams is the narrow maintainable fix. A dist-only patch, config knob, or broad filesystem fallback would be the wrong layer.
