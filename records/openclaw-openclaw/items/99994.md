## Summary

Keep open. Current main and the latest release still lack non-Windows retry coverage for the heartbeat-adjacent session-store read and still rethrow transient workspace template read failures, so the central reliability bug remains actionable even though the report overstates `loadSessionStore()` as a direct throw path.

## What This Changes

The issue reports transient EAGAIN or errno -11 file-read failures during heartbeat ticks because `loadSessionStore()` and workspace template comparison reads lack cross-platform retry handling.

## Best Possible Solution

Add a bounded core transient-read retry path for the session-store and workspace template reads, preserving `ENOENT` and non-transient error semantics, and cover it with injected EAGAIN/errno -11 regression tests plus focused heartbeat/cron validation.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: inject a transient EAGAIN/errno -11 into the workspace `fs.readFile()` and the heartbeat path will fail, while injecting it into `loadSessionStore()` shows the non-Windows no-retry empty-store behavior.

## Solution Assessment

Is this the best way to solve the issue? Yes, a narrow source-level retry helper or core-local equivalent of the existing memory read retry pattern is the maintainable fix; a dist-only local patch is only a workaround.
