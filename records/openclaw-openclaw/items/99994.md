## Summary

Keep open. Current main and the latest release still have the non-Windows session-store retry gap and the workspace template read still rethrows non-ENOENT read errors; two open PRs use closing syntax for this issue, so the issue should remain canonical until one implementation lands.

## What This Changes

The issue asks to retry transient EAGAIN/EINTR read failures in `loadSessionStore()` and `fileContentDiffersFromTemplate()` so macOS/Linux heartbeat ticks do not abort.

## Best Possible Solution

Land one focused PR that adds bounded transient-read retry to both read seams, preserves the existing Windows empty/unparseable-read mitigation, includes focused regression tests plus real gateway proof, then close this issue as fixed.

## Reproduction Assessment

Yes, source-level. Current main still uses one session-store read attempt on non-Windows and rethrows non-ENOENT workspace template read errors, and the reporter supplied macOS logs and local before/after proof; I did not run a live race reproduction.

## Solution Assessment

Partly. Retrying at the two implicated read seams is the right fix shape, but the final implementation should also preserve the existing bounded retry for transient unparseable session-store reads and avoid retrying permanent errors unnecessarily.
