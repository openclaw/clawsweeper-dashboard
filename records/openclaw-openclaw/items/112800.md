## Summary

This remains a useful, narrow P1 repair: the branch changes Twilio verification to bind to the configured public webhook path rather than a proxy-rewritten local path. The updated PR body now provides before/after terminal output using the production verifier with correctly computed Twilio signatures, so the real-behavior proof is sufficient; no discrete patch defect was identified from the supplied diff and related-provider history.

## What This Changes

The PR changes Twilio voice-call webhook verification to retain the configured `publicUrl` path, preserves the inbound query string, adds proxy-rewrite regression coverage, and aligns the voice-call documentation with that behavior.

## System Context

The voice-call plugin receives provider webhooks through the Gateway, which may sit behind a reverse proxy. It reconstructs the external URL used for provider signature verification from `publicUrl` and request details, then accepts or rejects the inbound voice-call event.
