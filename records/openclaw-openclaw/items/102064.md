## Summary

Keep open: current main still has a cron reaper path that selects expired cron run-session entries and archives their transcripts without consulting active session-work admissions, while isolated cron runs do hold a lifecycle admission through execution and delivery. The newer active-memory report was closed as superseded to this issue, so this remains the canonical tracker for the cron/session-GC failure.

## What This Changes

The issue reports intermittent `EmbeddedAttemptSessionTakeoverError` when isolated cron agent runs have their `.jsonl` transcript renamed to `.deleted.*` while the run is still active.

## Best Possible Solution

Make cron run-session cleanup lifecycle-aware so it skips or drains active admitted work before archiving/removing transcripts, with focused coverage for an isolated cron run through final delivery.
