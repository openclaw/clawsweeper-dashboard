## Summary

Keep open: current main still has a cron run-session reaper path that archives expired `:run:` transcripts from `updatedAt` without consulting active session-work admissions, while the issue reports an active isolated cron run losing its transcript during final delivery. Recent main adds admission tracking around isolated cron execution, but the cleanup path has not been made lifecycle-aware yet.

## What This Changes

The issue requests preventing session cleanup from deleting or archiving an active isolated cron agent run transcript while the embedded agent still holds or will reacquire its prompt lock.

## Best Possible Solution

Make cron/session cleanup lifecycle-aware so active admitted cron work is skipped or drained before transcript archival, with regression coverage for an isolated cron run through final delivery.
