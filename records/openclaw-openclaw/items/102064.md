## Summary

Keep open: current main still has a cron reaper path that can archive removed cron-run transcripts by age without consulting the active session-work admission that isolated cron runs hold through execution and delivery. The related active-memory report was closed back to this issue as the canonical remaining cron/session-lifecycle tracker, so cleanup closure would be premature.

## What This Changes

The issue reports intermittent cron-spawned isolated agent session `.jsonl` files being renamed to `.deleted.*` while an embedded agent run is still active, causing `EmbeddedAttemptSessionTakeoverError` during final message delivery.

## Best Possible Solution

Make cron/session cleanup lifecycle-aware so active admitted isolated cron work cannot have its transcript archived mid-run, while coordinating the retention and SQLite-storage follow-ups instead of forking cleanup semantics.
