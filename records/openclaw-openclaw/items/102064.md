## Summary

Keep open: current main and the latest release still show a cron run-session reaper path that can archive `.deleted.*` transcripts without consulting active session-work admissions, so the reported active-run takeover is not proven fixed.

## What This Changes

The issue requests that session cleanup stop renaming or deleting an active cron-spawned isolated agent session transcript while the embedded run is still executing or delivering its final message.

## Best Possible Solution

Make cron/session cleanup lifecycle-aware so it skips or drains active admitted cron work before archiving transcripts, with regression coverage for an isolated cron run through final delivery.
