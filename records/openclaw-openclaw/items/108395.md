## Summary

Keep this issue open: the supplied session-history evidence shows assistant-role text impersonating a human turn immediately before consequential actions, while current output sanitization is post-run and does not reject `Human:` text. The report does not prove that the text was structurally converted into a user-role message, but it exposes a credible security-boundary gap: approval-sensitive actions can rely on model interpretation rather than fresh authenticated owner provenance.

## What This Changes

Prevent assistant-generated human-turn text from being treated as authorization for approval-sensitive external actions.

## Best Possible Solution

Represent pending approval as structured runtime state and require a fresh authenticated owner turn or narrowly scoped approval capability before releasing consequential core or plugin actions, with pre-execution self-talk detection retained only as defense in depth.
