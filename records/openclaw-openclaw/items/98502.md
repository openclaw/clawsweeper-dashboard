## Summary

Keep open: the image-generation fallback change is small, but the OAuth fix still applies the bounded read after `postTokenForm` has already drained the token endpoint response with `arrayBuffer()`, so the claimed auth-provider OOM boundary remains incomplete.

## What This Changes

The PR replaces three OpenAI error-path `response.text()` reads with `readResponseTextLimited` and adds a loopback OAuth error-body boundary test.

## Best Possible Solution

Move the OAuth byte cap into the guarded token fetch/read lifecycle before `arrayBuffer()`, preserve SSRF guard release behavior, and prove oversized plus normal exchange/refresh errors on the real token response path.

## Reproduction Assessment

Yes. Source inspection on the PR head shows exchange and refresh both call `postTokenForm`, which awaits `response.arrayBuffer()` before the changed bounded reads execute.

## Solution Assessment

No. `readResponseTextLimited` is the right primitive, but the OAuth fix needs to apply it before or inside the token fetch helper rather than after the helper has copied the full response body.
