## Summary

Keep open. Current main and the latest release still use one global session visibility gate for list/history/send/status, so the reported Telegram group cross-agent list/send asymmetry is not fixed and still needs maintainer security/product direction.

## What This Changes

The issue reports asymmetric Telegram group cross-agent session visibility where one agent cannot see or send to the peer's `agent:*:telegram:group:<id>` session key.

## Best Possible Solution

Choose and implement a maintainer-approved A2A/session visibility contract that preserves list/history/status privacy while allowing only explicitly authorized cross-agent delivery, then prove it with a redacted live Telegram A/B scenario.

## Reproduction Assessment

Yes from source for the shared gate shape, but not as a live Telegram repro. Current code rejects cross-agent targets before A2A policy unless visibility is `all`; the exact one-way Telegram A/B case still needs redacted live proof.

## Solution Assessment

Unclear. A send-only exception is plausible, but the best fix needs maintainer-approved semantics that separate delivery permission from list/history/status visibility without widening transcript access.
