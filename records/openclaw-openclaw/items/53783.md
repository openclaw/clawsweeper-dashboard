## Summary

Keep open. Current main still uses one global session visibility gate for list/history/send/status, so the reported cross-agent Telegram group-session visibility and send asymmetry is not fixed; related issues and PRs cover broader policy directions, but no merged current-main change resolves this exact behavior.

## What This Changes

The issue requests that Telegram cross-agent group sessions become visible/actionable through session tools when Agent A and Agent B are authorized to interact, without overexposing unrelated session history.

## Best Possible Solution

Choose a coherent A2A/session visibility contract, prove it with a live Telegram A/B scenario, and preserve list/history/status isolation while allowing only maintainer-approved send behavior.

## Reproduction Assessment

Yes, partially: source inspection shows the current visibility guard can hide/block cross-agent sessions before A2A policy helps, but the exact Telegram one-way A/B case still needs live proof.

## Solution Assessment

Unclear: simply bypassing visibility for send may solve part of the bug, but the best fix must be a maintainer-approved contract that separates message delivery from list/history/status access.
