## Summary

Keep open. Current main and the latest release still couple cross-agent list/send visibility to the single `tools.sessions.visibility` gate, and the exact Telegram A/B asymmetry has not been fixed or superseded by a merged related PR.

## What This Changes

The issue asks for consistent cross-agent Telegram group session visibility so two agents in the same group can discover each other's `agent:*:telegram:group:<id>` session keys and send both directions.

## Best Possible Solution

Define a maintainer-approved A2A/session visibility contract, then prove it with focused list/send/status/history tests plus a redacted live Telegram A/B group scenario that preserves read/list isolation while allowing only approved message delivery.

## Reproduction Assessment

Yes, partially. Source inspection shows current main can hide and block cross-agent session targets before A2A policy helps, but the exact Telegram one-way A/B mismatch still needs live proof with each agent's effective visibility and A2A policy.

## Solution Assessment

Unclear. A narrow send-only bypass might solve part of the report, but the maintainable fix needs an explicit security contract that separates message delivery from list/history/status access.
