## Summary

The latest head still has the previously reported slow-hook ownership race: a delivery claim can expire while the asynchronous hook is running, allowing another replay pass to execute the same side effect and either claimant to write the terminal result. The PR should remain open for that narrow repair, followed by an explicit maintainer decision on the broader durable-runtime stack and release inclusion.

## What This Changes

Adds durable wake-target resolution, persisted wake obligations, lease-claimed delivery replay, shared-state schema support, documentation, and focused wake/replay tests on top of the durable runtime foundation.

## Best Possible Solution

Use a claimant token or renewable lease that remains valid for the full asynchronous hook, condition every terminal write on that ownership, add a competing replay regression with the first hook held beyond `claimTtlMs`, and land the stack in order only after explicit durable-runtime sponsorship.
