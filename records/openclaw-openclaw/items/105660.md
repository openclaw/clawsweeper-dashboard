- `P1`: An ordinary restart can permanently suppress a pending wake in the proposed recovery subsystem, defeating its central notification guarantee.

## Summary

The PR remains necessary because current `main` has no durable wake/replay layer, but it is not merge-ready: a process interruption after a pending attempt is persisted permanently suppresses later delivery, and the broader persistent contract still needs maintainer sponsorship.

## What This Changes

Adds durable wake-target resolution, wake-obligation producers, persisted delivery-attempt replay, shared-state schema updates, documentation, and focused tests on top of the open durable runtime foundation.

## Best Possible Solution

Use a crash-safe attempt state machine with a bounded lease or reclaim deadline, an idempotent downstream delivery key, and distinct handling for pre-side-effect retry versus post-side-effect unknown outcome; then prove real restart behavior and PR2-to-PR3 database upgrade before adopting the layer.
