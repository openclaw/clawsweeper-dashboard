- `impact:security`: The bug sits at the boundary between an explicit administrator trust gesture and the restrictive plugin execution allowlist.
- `impact:ux-friction`: Affected administrators must manually edit configuration despite holding the required in-product admin scope.

## Summary

Keep open: the documented administrator RPC promises plugin enablement, while the reported restrictive-allowlist path rejects the request before applying the repository’s canonical enable mutation; the protected `maintainer` label and active assignee also require owner-led handling.

## What This Changes

Make the Control UI administrator Enable action preserve existing `plugins.allow` entries, add the selected installed plugin, and enable it atomically.

## Best Possible Solution

Route `plugins.setEnabled` through the canonical enable-config mutation before validation and persistence, preserving unrelated allowlist entries and denylist enforcement, with focused Gateway tests for restrictive allowlists and atomic failure behavior.
