## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Do not classify empty wildcard allowlists as unknown groups:** `extensions/telegram/src/unknown-group.ts:12`
  - body: `group-policy-allowlist-empty` also occurs when `groups` contains `"*"` and no sender allowlist is configured, because wildcard matches deliberately do not set `chatExplicitlyAllowed`. Treating that reason as unknown means `unknownGroupAction: "leave"` can eject the bot from groups intentionally covered by wildcard config instead of only truly unregistered chats.
  - confidence: 0.9
- **[P2] Reuse thread params for unknown-group warning sends:** `extensions/telegram/src/bot-handlers.runtime.ts:1660`
  - body: The warning path sends `resolvedThreadId` directly, but current Telegram helpers omit `message_thread_id=1` because Telegram rejects General-topic sends with that id. In a General forum topic, `warn` can 400 and `leave` can leave without sending the configured warning.
  - confidence: 0.88
- **[P2] Apply unknown-group actions before native commands:** `extensions/telegram/src/bot-handlers.runtime.ts:1647`
  - body: Native slash commands are registered before the normal message handlers and answer `group-chat-not-allowed` inside `resolveTelegramCommandAuth`. A first `/help` or plugin command in an unknown group bypasses the new warn/leave path, so the bot stays in the unknown group despite the configured action.
  - confidence: 0.86
- **[P2] Evict expired unknown-group cooldown entries:** `extensions/telegram/src/unknown-group.ts:25`
  - body: `isOnCooldown` returns false for expired entries but leaves them in `lastActionAt`, so a long-running bot exposed to many unknown group ids accumulates stale cooldown state even after the cooldown expires or the bot leaves. Prune expired entries or bound the tracker.
  - confidence: 0.78
