## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Do not leave wildcard-configured groups as unknown:** `extensions/telegram/src/unknown-group.ts:12`
  - body: `group-policy-allowlist-empty` can mean the chat matched a wildcard `groups` entry but has no sender allowlist. Treating it as unknown makes `unknownGroupAction: "leave"` leave configured groups instead of only unregistered chats.
  - confidence: 0.88
- **[P2] Reuse thread params for warning sends:** `extensions/telegram/src/bot-handlers.runtime.ts:1660`
  - body: This path sends `{ message_thread_id: resolvedThreadId }` directly. For a forum's General topic, current Telegram helper code omits thread id 1 because Telegram rejects it, so `warn` can fail and `leave` can happen without the configured warning.
  - confidence: 0.9
- **[P1] Route native commands through unknown-group policy:** `extensions/telegram/src/bot-handlers.runtime.ts:1644-1646`
  - body: The new action only runs from the normal message handler. Native slash commands are registered on a separate path before that handler and return from their own auth flow, so `/help` or plugin commands in an unknown group can bypass warn/leave.
  - confidence: 0.84
- **[P3] Document the new Telegram config keys:** `src/config/types.telegram.ts:213-220`
  - body: The PR adds public Telegram config fields but does not update the channel docs or config-help surface, leaving operators without the documented upgrade and safety guidance required for new config behavior.
  - confidence: 0.78
- **[P3] Prune expired cooldown entries:** `extensions/telegram/src/unknown-group.ts:17-27`
  - body: `lastActionAt` only grows. A bot repeatedly added to many unknown groups can retain one map entry per chat even after cooldown expiry or leaving, so the tracker should evict expired entries or otherwise bound the cache.
  - confidence: 0.73
