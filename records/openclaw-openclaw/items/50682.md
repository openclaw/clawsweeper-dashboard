## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Restrict unknown-group actions to chat allowlist misses:** `extensions/telegram/src/unknown-group.ts:11`
  - body: `group-policy-allowlist-empty` is not necessarily an unregistered chat: current tests cover wildcard-matched groups with no sender entries returning that reason. With `unknownGroupAction: "leave"`, this would eject the bot from an intentionally configured wildcard group after a sender-allowlist miss instead of only acting on a true chat allowlist miss.
  - confidence: 0.91
- **[P2] Build warning thread params through the helper:** `extensions/telegram/src/bot-handlers.runtime.ts:1665`
  - body: This sends `resolvedThreadId` directly, but the existing `buildTelegramThreadParams` helper deliberately omits forum General topic id `1` because Telegram rejects that value for message sends. In a General topic, `warn` will fail and `leave` can leave without posting the configured warning.
  - confidence: 0.89
- **[P2] Apply unknown-group handling before native commands return:** `extensions/telegram/src/bot-handlers.runtime.ts:1647-1648`
  - body: The new action only runs in the generic message handler. Native Telegram commands are registered before that handler and their callbacks return without calling downstream middleware, so an unknown group’s `/help` or plugin command still gets the old static denial and never warns or leaves as configured.
  - confidence: 0.87
- **[P3] Prune expired cooldown entries:** `extensions/telegram/src/unknown-group.ts:23-25`
  - body: `lastActionAt` only ever grows. A bot exposed to many unknown groups can retain one entry per chat indefinitely, including after successful `leaveChat`; evict expired entries when checking the cooldown or bound the map.
  - confidence: 0.78
