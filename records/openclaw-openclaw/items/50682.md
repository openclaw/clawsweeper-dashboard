## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Classify only real unknown chats:** `extensions/telegram/src/unknown-group.ts:12`
  - body: `group-policy-allowlist-empty` is not the same as an unregistered chat. For example, `groups: { "*": ... }` makes `resolveChannelGroupPolicy` allow the chat while leaving `groupConfig` undefined, so this branch can warn or eject the bot from wildcard-configured groups instead of only unknown groups. Limit unknown-group actions to the concrete chat-not-allowed case or carry a more precise policy result.
  - confidence: 0.93
- **[P1] Apply unknown-group actions to slash commands:** `extensions/telegram/src/bot-handlers.runtime.ts:1644-1645`
  - body: This action is only wired into the normal message handler. Native commands are registered before that handler, and `resolveTelegramCommandAuth()` handles `group-chat-not-allowed` by sending the static auth message, so an unknown group whose first activity is `/help` or a plugin command will not warn or leave as configured.
  - confidence: 0.92
- **[P2] Use thread params for warning sends:** `extensions/telegram/src/bot-handlers.runtime.ts:1660`
  - body: Passing `resolvedThreadId` directly reintroduces the General-topic case that `buildTelegramThreadParams()` intentionally filters out: Telegram rejects `message_thread_id=1` for `sendMessage`. This means warning in a forum General topic can 400, and `leave` may happen without the configured warning.
  - confidence: 0.9
- **[P3] Prune expired cooldown entries:** `extensions/telegram/src/unknown-group.ts:27-31`
  - body: `lastActionAt` only grows. A long-running bot exposed to many unique unknown groups can retain every old chat id forever even after cooldown expiry or successful leave; delete expired entries during cooldown checks or otherwise bound the tracker.
  - confidence: 0.78
