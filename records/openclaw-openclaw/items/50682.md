## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Do not treat sender-filter misses as unknown groups:** `extensions/telegram/src/unknown-group.ts:12`
  - body: `group-policy-allowlist-empty` is also returned for wildcard-configured groups when no sender allowlist is present; treating it as an unknown chat means `unknownGroupAction: "leave"` can eject the bot from groups covered by `groups: {"*": ...}` instead of only truly unregistered groups. Please classify unknown groups from the chat allowlist result/context, or limit this helper to the actual `group-chat-not-allowed` case.
  - confidence: 0.91
- **[P2] Reuse the thread helper for warning sends:** `extensions/telegram/src/bot-handlers.runtime.ts:1660`
  - body: This warning path sends `{ message_thread_id: resolvedThreadId }` directly. For forum General topics `resolvedThreadId` can be `1`, but `buildTelegramThreadParams()` intentionally omits that id because Telegram rejects it, so `warn` will fail and `leave` can leave without the configured warning.
  - confidence: 0.88
- **[P2] Apply unknown-group actions to native commands:** `extensions/telegram/src/bot-handlers.runtime.ts:1644-1645`
  - body: The new policy runs only inside the generic message handler. Native Telegram commands are registered before those handlers and authorize in `bot-native-commands.ts`, so `/help` or plugin slash commands in an unknown group still get the old fixed denial path and never warn or leave as configured.
  - confidence: 0.87
