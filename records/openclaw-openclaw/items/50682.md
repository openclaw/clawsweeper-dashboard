## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Classify only real chat-allowlist misses as unknown groups:** `extensions/telegram/src/unknown-group.ts:12`
  - body: `group-policy-allowlist-empty` is also returned for configured wildcard groups when no sender allowlist entries exist. Treating it as unknown means `unknownGroupAction: "warn"` or `"leave"` can warn or eject the bot from groups intentionally covered by `groups: {"*": ...}` instead of only truly unregistered chats.
  - confidence: 0.92
- **[P2] Reuse thread params for unknown-group warnings:** `extensions/telegram/src/bot-handlers.runtime.ts:1660`
  - body: This sends `message_thread_id` directly from `resolvedThreadId`. For a forum's General topic that value can be `1`, and the existing Telegram helper omits that ID because sendMessage rejects it, so `warn` can fail and `leave` can leave without the configured warning.
  - confidence: 0.9
- **[P2] Run unknown-group actions for native slash commands:** `extensions/telegram/src/bot-handlers.runtime.ts:1645-1647`
  - body: The new action path is only in the normal message handler. Native slash commands are registered through a separate command handler that answers `group-chat-not-allowed` itself, so `/help` or plugin commands in an unknown group bypass the configured warn/leave behavior.
  - confidence: 0.88
- **[P2] Evict expired unknown-group cooldown entries:** `extensions/telegram/src/unknown-group.ts:27`
  - body: `lastActionAt` only grows as new unknown chat IDs are observed. Long-running bots exposed to many unknown groups will retain expired cooldown entries indefinitely; prune expired entries or bound the map when checking cooldown state.
  - confidence: 0.83
