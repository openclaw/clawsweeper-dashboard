## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Classify only true unknown chats as unknown groups:** `extensions/telegram/src/unknown-group.ts:12`
  - body: `group-policy-allowlist-empty` is also returned for a wildcard-enabled group with no sender allowlist entries, and current tests assert that as a sender-policy block rather than an unconfigured chat. Including it here means `unknownGroupAction: "leave"` can eject the bot from groups that are intentionally covered by `groups: {"*": ...}` instead of only from unknown group IDs.
  - confidence: 0.9
- **[P2] Use the Telegram thread helper for warning sends:** `extensions/telegram/src/bot-handlers.runtime.ts:1660`
  - body: This new send path passes `resolvedThreadId` directly, but `resolvedThreadId` can be `1` for a forum General topic and the existing helper deliberately omits that value because Telegram rejects it for message sends. Route the warning through the same thread-param helper used by the rest of the Telegram send path.
  - confidence: 0.9
- **[P2] Apply unknown-group actions to native commands:** `extensions/telegram/src/bot-handlers.runtime.ts:1647`
  - body: The new warn/leave behavior only runs inside the normal message handler, while native Telegram commands are registered first and complete authorization inside `resolveTelegramCommandAuth`. A `/help` or plugin command in an unknown group still gets the fixed denial response and never triggers the configured warn/leave action.
  - confidence: 0.87
- **[P3] Prune expired cooldown entries:** `extensions/telegram/src/unknown-group.ts:26`
  - body: `lastActionAt` is never evicted, so a long-running bot that encounters many unique unknown groups retains every chat id forever even after the cooldown has expired or after a leave succeeds. Delete expired entries when checking cooldown, or otherwise bound this map.
  - confidence: 0.78
