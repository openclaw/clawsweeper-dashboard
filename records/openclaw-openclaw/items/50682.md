## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.87

Full review comments:

- **[P1] Classify only truly unknown chats as unknown groups:** `extensions/telegram/src/unknown-group.ts:12`
  - body: `group-policy-allowlist-empty` is a sender-authorization state, not an unregistered chat: current `evaluateTelegramGroupPolicyAccess` returns it after the chat allowlist check, and existing tests cover wildcard-matched groups with no sender allowlist. With this line, `unknownGroupAction: "leave"` can make the bot leave configured wildcard groups instead of only chats that fail `group-chat-not-allowed`.
  - confidence: 0.89
- **[P2] Route unknown-group policy through native commands:** `extensions/telegram/src/bot-handlers.runtime.ts:1644-1645`
  - body: This new action runs only after `shouldSkipGroupMessage` in the regular message handler. Native slash commands are handled by `resolveTelegramCommandAuth`, which returns `This group is not allowed.` for `group-chat-not-allowed` and never calls the new warn/leave path, so `/help` in an unknown group bypasses the configured leave/warn behavior.
  - confidence: 0.84
- **[P2] Use the Telegram thread helper for warning sends:** `extensions/telegram/src/bot-handlers.runtime.ts:1660`
  - body: Passing `resolvedThreadId` directly sends `message_thread_id: 1` for a forum General topic, but the current Telegram helper intentionally omits id 1 for message sends because Telegram rejects it. In that case the configured warning is swallowed and `leave` proceeds without the warning.
  - confidence: 0.86
- **[P3] Bound or prune the unknown-group cooldown map:** `extensions/telegram/src/unknown-group.ts:27-31`
  - body: `lastActionAt` only grows: each unique unknown chat id is retained for the process lifetime, even after the cooldown expires or a leave succeeds. A long-running bot added to many unknown groups can accumulate stale entries, so prune expired entries or otherwise bound the tracker.
  - confidence: 0.78
