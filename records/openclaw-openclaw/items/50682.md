## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Do not classify allowlist-empty as unknown:** `extensions/telegram/src/unknown-group.ts:12`
  - body: `group-policy-allowlist-empty` is not the same as an unregistered chat. Current main can reach it after wildcard/group policy allowed the chat but sender allowlist setup failed, so `unknownGroupAction: "leave"` can warn or leave a configured group instead of only a truly unknown group. Restrict the action to a precise chat-allowlist miss or carry a richer policy result.
  - confidence: 0.88
- **[P2] Use the Telegram thread helper for warning sends:** `extensions/telegram/src/bot-handlers.runtime.ts:1660`
  - body: This sends `{ message_thread_id: resolvedThreadId }` directly. For forum General topic, `resolvedThreadId` is `1`, and the existing helper intentionally omits that value because Telegram rejects message sends with `message_thread_id=1`; the catch then leaves the group without the configured warning. Build a thread spec and call `buildTelegramThreadParams` here.
  - confidence: 0.91
- **[P2] Apply unknown-group actions to native commands:** `src/config/zod-schema.providers-core.ts:283`
  - body: The new config is channel-level, but only the normal message handler consumes it. Telegram native slash-command handlers run before that handler and authorize inside `bot-native-commands`, so an unknown group whose first activity is `/help` or a plugin command still gets static denial text and no configured warn/leave action. Share the policy with command auth or document and encode the narrower scope.
  - confidence: 0.84
