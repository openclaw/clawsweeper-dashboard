## Label Justifications

- `P1`: Silent final fallback delivery loss can break real agent/channel workflows by making a completed turn look like no response.

## Summary

Keep open. Current main has implemented important pieces of durable delivery accounting, but the protected maintainer-owned umbrella is still necessary because current and latest-release code still contain source-backed final-delivery gaps and open related PRs cover only narrower slices.

## What This Changes

Define and enforce cross-channel semantics so sanitized final fallback messages are either delivered with proof or recorded as failed, suppressed, partial, or platform-outcome-unknown.

## Best Possible Solution

Keep this as the canonical maintainer-owned delivery contract, then land or replace narrow channel slices under it with SDK/core conformance tests and live transport proof where required.

## Reproduction Assessment

Yes. Source inspection shows current main still has channel paths where visible final fallback semantics can collapse into empty identity or queuedFinal success without proven platform delivery; I did not run live channel credentials in this read-only review.

## Solution Assessment

Yes as a tracking shape. A shared core/channel contract is the maintainable path because channel-specific patches do not settle SDK semantics, recovery visibility, and conformance coverage together.
