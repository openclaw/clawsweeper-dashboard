## Summary

Keep open. This protected MEMBER-authored maintainer issue is still necessary: current main has partial durable delivery accounting, but Telegram and dispatcher paths can still treat queued or attempted final delivery as a visible response without confirmed platform delivery, and open PR #96095 covers only a Telegram slice.

## What This Changes

Define a core/channel contract so sanitized final fallback text on durable text-capable channels ends as sent, failed, partial_failed, or intentionally suppressed instead of silently disappearing.

## Best Possible Solution

Keep #87561 as the canonical maintainer-owned delivery contract, land reviewed channel-specific slices under it, then add shared SDK/core conformance and diagnostics coverage across durable text-capable channels.
