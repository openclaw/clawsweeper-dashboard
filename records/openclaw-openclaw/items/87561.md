## Summary

Keep open. Current main implements part of the durable outcome model and empty-identity suppression, but the broader contract is still not complete: Telegram can still treat queued final dispatch as a visible response without confirmed delivery, the latest release has the same path, and the open Telegram PR is only a candidate slice.

## What This Changes

Requested a durable cross-channel contract so sanitized final fallback text is either delivered with proof or reported as failed/suppressed instead of disappearing.

## Best Possible Solution

Keep this as the canonical maintainer-owned delivery contract, review or revise the Telegram candidate PR as a slice, and finish shared delivered-vs-queued semantics plus conformance tests for durable text-capable channels.

Yes. Source inspection shows current Telegram still treats queued final dispatch as visible response proof, and the latest release has the same path; the new comment adds a production timeout scenario matching that source path.
