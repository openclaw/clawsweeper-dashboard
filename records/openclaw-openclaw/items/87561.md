## Summary

Keep open. This is a MEMBER-authored issue with the protected maintainer label, and current main plus v2026.6.11 still show source-backed final-fallback delivery gaps while open and closed related PRs cover only narrower channel slices.

## What This Changes

The issue asks OpenClaw to define and enforce a cross-channel durable final fallback contract so sanitized final fallback messages are delivered or explicitly reported as failed/suppressed instead of disappearing.

## Best Possible Solution

Keep this as the canonical maintainer-owned delivery contract, land or replace the channel-specific slices when proven, then add SDK/core semantics and conformance coverage across durable text-capable channels.

## Reproduction Assessment

Yes at source level. Current main still has a WhatsApp durable-final text path that routes final isError payloads to sendPayload and returns an empty messageId without sending, and the latest comment adds a production Telegram false-success delivery path.

## Solution Assessment

Yes. Keeping this as the broad core/channel contract is the best current path; channel-specific fixes can prove slices, but they do not by themselves settle SDK semantics, explicit outcomes, recovery diagnostics, and cross-channel conformance.
