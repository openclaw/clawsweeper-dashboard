## Label Justifications

- `P1`: The report and follow-up comment describe real CLI-backed agent requests being killed mid-flight after 180 seconds of silence.
- `impact:session-state`: The watchdog termination can destroy an in-flight resumed agent session before it can consume later results and continue.

## Summary

Keep open: current main and the latest release still preserve the 180-second no-output cap for ordinary inherited resumed CLI-backed runs, while the merged related work only lifts the cap for cron or explicit/configured run timeouts. The remaining choice is a maintainer policy decision about the default guard versus operator configuration, not a cleanup-close candidate.

## What This Changes

The issue requests raising, removing, or making configurable the CLI no-output watchdog cap so long-running CLI-backed agent requests are not killed after 180 seconds of silence.

## Best Possible Solution

Keep this issue open until maintainers choose the CLI resume watchdog policy, preferably as a focused default/override decision that does not bundle unrelated TUI streaming behavior unless that broader direction is explicitly accepted.
