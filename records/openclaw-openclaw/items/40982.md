## Label Justifications

- `P1`: The issue affects real CLI-backed agent turns by terminating long silent work mid-run and surfacing failed model/session workflows.
- `impact:session-state`: The watchdog kill can end an in-flight CLI session before the agent completes or preserves the turn state.

## Summary

Keep open: current main and the latest release still keep ordinary inherited resumed CLI user runs on the 180-second no-output cap; the merged timeout-provenance fix only covers configured, explicit, and cron timeout intent, while the open candidate PR is broader and still needs maintainer policy review.

## What This Changes

The issue requests raising, disabling, or making configurable the hard CLI no-output watchdog ceiling that can terminate long-silent resumed CLI-backed agent runs around 180 seconds.

## Best Possible Solution

Keep this as the canonical CLI no-output watchdog policy issue until maintainers land a narrow, proof-backed change through the existing watchdog default/config surface, with explicit approval for any disable semantics.

- **Add explicit disable or tuning semantics:** Accept 0 or null style disable behavior only with schema, docs, config metadata, and upgrade proof for existing configs.
- **Keep the 180-second inherited guard:** Leave current behavior intact and document per-backend watchdog overrides for operators with known long silent CLI workloads.

Yes, at source level. An ordinary resumed user run with a 600,000 ms overall timeout still resolves to a 180,000 ms no-output watchdog, and the runner uses that value in the termination path; I did not run a live 180-second stall in this read-only review.

## Solution Assessment

No complete fix is on main yet. A bounded default change through the existing watchdog surface is the narrow likely implementation path, while disabling or changing public config semantics needs maintainer approval and upgrade proof.
