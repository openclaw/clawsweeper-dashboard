## Summary

Keep open: current main and v2026.6.11 still keep ordinary inherited resumed CLI-backed user runs on the 180-second no-output ceiling, while merged work only fixed configured or explicit timeout intent and the remaining raise/disable behavior is a maintainer timeout-policy choice.

## What This Changes

The issue requests raising, removing, or making configurable the hard 3-minute no-output watchdog cap for CLI-backed resumed sessions.

## Best Possible Solution

Land a narrow maintainer-approved CLI watchdog policy change through the existing defaults/config surface, with resolver coverage and real long-silent CLI proof; keep adjacent TUI streaming-watchdog configuration on its own tracker.
