## Summary

Keep open: current main and v2026.6.11 still preserve the 180-second no-output cap for ordinary inherited resumed CLI-backed user runs; merged work only lifts configured or explicit timeout intent, so the remaining raise/disable behavior is a maintainer timeout-policy decision.

## What This Changes

The issue asks to raise, remove, or make configurable the 3-minute no-output watchdog cap for resumed CLI-backed requests.

## Best Possible Solution

Land a narrow maintainer-approved CLI watchdog policy change through the existing watchdog defaults/config surface, with resolver coverage and real long-silent CLI proof; keep adjacent TUI streaming-watchdog configuration on its own tracker.
