## Summary

Keep open: current main and the latest release still keep ordinary inherited resumed CLI user runs on the 180-second no-output cap, while the remaining bounded-default or disable behavior is a maintainer policy decision with an open but broader candidate PR.

## What This Changes

The issue requests raising, disabling, or configuring the CLI no-output watchdog so long-running CLI-backed agent requests are not killed at the 180-second resume cap.

## Best Possible Solution

Keep this as the canonical CLI no-output watchdog policy issue until maintainers land a narrow, proof-backed change through the existing watchdog default/config surface, with explicit approval for any disable semantics.
