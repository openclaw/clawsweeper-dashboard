## Summary

Keep open: current main and v2026.6.11 still leave ordinary inherited resumed CLI-backed user runs on the 180-second no-output watchdog cap. The merged timeout work only fixes configured or explicit timeout intent, and the open candidate PR is still broader, conflicting, proof-blocked, and policy-sensitive.

## What This Changes

The issue requests raising, disabling, or making configurable the hard 3-minute no-output watchdog cap for CLI-backed resumed requests.

## Best Possible Solution

Keep this as the canonical CLI no-output watchdog policy issue until maintainers land a narrow, proof-backed change through the existing watchdog default/config surface, with explicit approval for any disable semantics.
