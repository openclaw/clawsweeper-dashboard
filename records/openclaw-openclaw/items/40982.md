## Label Justifications

- `P1`: The issue affects real CLI-backed agent turns by terminating long silent work mid-run and surfacing failed model/session workflows.
- `impact:session-state`: The watchdog kill can end an in-flight CLI session before the agent completes or preserves the turn state.

## Summary

Keep open: current main and latest release v2026.6.11 still leave ordinary inherited resumed CLI-backed runs on the 180-second no-output watchdog cap, and the only open implementation candidate is still review-blocked and broader than this issue.

## What This Changes

Requests raising, removing, or making configurable the CLI no-output watchdog cap that can terminate long silent resumed CLI-backed agent runs.

## Best Possible Solution

Keep this as the canonical CLI no-output watchdog policy issue until maintainers land a narrow, proof-backed change through the existing watchdog config/default surface, with explicit approval for any disable semantics.

## Reproduction Assessment

Yes, from source inspection. An ordinary resumed user run with a 600,000 ms overall timeout still resolves to a 180,000 ms no-output watchdog, and the runner uses that value in the termination path; I did not run a live 180-second stall in this read-only review.

## Solution Assessment

No complete fix is on main yet. Raising bounded defaults through the existing watchdog surface is the narrow likely code path, while disabling the watchdog or changing default policy needs maintainer approval and upgrade proof.
