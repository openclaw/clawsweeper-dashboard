- **[P1] Store dashboard state in SQLite:** `extensions/dashboard/src/store.ts:69-73`
  - body: This creates OpenClaw-owned runtime state as `workspace.json` plus undo JSON files under the state directory. Root policy and the existing plugin keyed-store seam put runtime/plugin state in SQLite, so landing this would create a parallel persistent data model without a migration or DB owner; move the workspace document and undo ring into plugin-state/shared SQLite or a justified SQLite schema.
  - confidence: 0.93
- **[P2] Keep undo workspace versions monotonic:** `extensions/dashboard/src/store.ts:133-147`
  - body: `undo()` restores the old snapshot verbatim, including its older `workspaceVersion`, and then broadcasts that restored document. Clients that cache by version or skip refetches unless the version advances can miss an undo; restore the content while assigning a fresh version or route undo through the normal mutation path.
  - confidence: 0.87
- **[P2] Derive gateway actor from request context:** `extensions/dashboard/src/gateway.ts:83-89`
  - body: Dashboard write RPCs accept an `actor` param and stamp it into `createdBy`/`approvedBy` and broadcasts, so any `operator.write` caller can claim `system` or another agent. Gateway handlers already receive trusted client/context, and core chat treats system provenance as privileged; derive the dashboard actor from trusted context or restrict caller-supplied provenance to an admin/internal path.
  - confidence: 0.89
