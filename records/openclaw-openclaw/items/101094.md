## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Store dashboard state in SQLite:** `extensions/dashboard/src/store.ts:47-50`
  - body: The new store makes stateDir/dashboard/workspace.json plus undo JSON snapshots the steady-state source of truth. Root policy requires OpenClaw runtime/plugin state to use SQLite or plugin state, with file storage reserved for named artifacts; sibling Workboard already uses plugins/workboard/workboard.sqlite. Move workspace, undo, and registry state to a SQLite/plugin-state schema before merge.
  - confidence: 0.92
- **[P2] Keep undo workspace versions monotonic:** `extensions/dashboard/src/store.ts:93-106`
  - body: undo() writes the previous snapshot back unchanged, so workspaceVersion can move backward after later writes. The PR uses this value in responses and broadcasts, so decreasing it can make clients ignore an undo or process updates out of order. Restore the snapshot content but assign a new version greater than the current document before writing and broadcasting.
  - confidence: 0.9
- **[P2] Derive the actor instead of accepting it from RPC params:** `extensions/dashboard/src/gateway.ts:83-88`
  - body: Every write RPC allows callers to pass actor and then uses that value for createdBy, approvedBy, and broadcasts. A client with operator.write can stamp a human edit as agent:* or system, which breaks the provenance and approval audit this feature relies on. Keep gateway-originated writes as user or derive the actor from authenticated request context, and reserve agent provenance for the tool-context path.
  - confidence: 0.87
