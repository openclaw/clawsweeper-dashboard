## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Move dashboard runtime state to SQLite:** `extensions/dashboard/src/store.ts:72-73`
  - body: The store writes `workspace.json` and the undo ring under `stateDir/dashboard`. OpenClaw policy requires runtime state and plugin scratch data to use SQLite unless this is a named artifact, so merging this as-is creates a second persistent state model without an approved migration or ownership boundary.
  - confidence: 0.91
- **[P2] Keep undo workspace versions monotonic:** `extensions/dashboard/src/store.ts:144`
  - body: `undo()` writes the old snapshot unchanged, so a rollback can publish a lower `workspaceVersion` than clients have already seen. The PR presents workspaceVersion as monotonic and later UI subscribers can ignore or misorder that rollback if they gate refreshes on increasing versions.
  - confidence: 0.87
- **[P2] Derive dashboard actors from trusted request context:** `extensions/dashboard/src/gateway.ts:83-88`
  - body: Gateway RPCs accept `actor` from params and then use it for `createdBy`, `approvedBy`, and broadcast provenance. Any operator.write client can forge user/system/agent metadata; the tool path already derives actor from trusted context, so the gateway path needs the same treatment from authenticated request/client scope.
  - confidence: 0.9
