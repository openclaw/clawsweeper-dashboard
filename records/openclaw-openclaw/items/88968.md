## Summary

Keep open for maintainer review before merge. Current main still turns memory-flush visible error payloads into a terminal `run_failed` reply, while this PR moves that failure to log-and-continue with targeted reset-state cleanup and sufficient live Gateway/WebSocket proof; the remaining blocker is explicit maintainer acceptance of the session-state, message-delivery, and existing-option semantics tradeoffs.

## What This Changes

The PR changes memory-flush failure handling so failed flush maintenance no longer aborts the main reply, rotates exhausted sessions while preserving old transcripts, clears stale flush state on reset, and documents the expanded `notifyUser` behavior.

## Best Possible Solution

Land or revise a maintainer-approved fail-open recovery that keeps failed memory maintenance from blocking normal replies while preserving old transcripts and documenting the accepted notice/session semantics.
