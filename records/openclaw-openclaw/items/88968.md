## Summary

Keep open for maintainer review: current main and the latest release still abort the user reply when memory-flush visible error payloads are produced, while this PR appears mechanically sound and well-proven but needs explicit acceptance of the fail-open recovery semantics.

## What This Changes

The PR changes reply memory-flush failure handling to log visible flush errors, rotate exhausted sessions while preserving old transcripts, clear stale flush state on reset, and update tests/docs for the expanded notice behavior.

## Best Possible Solution

Land or revise one owner-approved fail-open recovery that keeps user replies moving, preserves the prior transcript for recovery, and documents the accepted `notifyUser` notice expansion.
