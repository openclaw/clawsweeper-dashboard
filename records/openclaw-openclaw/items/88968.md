## Summary

Keep open: current main still terminates the reply when memoryFlush emits visible error payloads, while this PR is the active candidate for changing that behavior. It should stay in maintainer review because the branch changes reply-delivery, session-rotation, persisted session-state, and `notifyUser` semantics, and it overlaps an open same-pipeline PR.

## What This Changes

The PR changes memoryFlush failure handling to log and continue the main reply, rotate and clear session state on exhaustion, reuse `compaction.notifyUser` for a degraded notice, and update docs plus regression tests.

## Best Possible Solution

Settle one maintainer-approved pre-run maintenance policy across this PR and https://github.com/openclaw/openclaw/pull/84792, then land the recovery only with intended fail-open, rotation, notice, and upgrade semantics documented and tested.
