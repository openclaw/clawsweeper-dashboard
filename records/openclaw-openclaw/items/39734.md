## Summary

Keep open: current main and v2026.6.11 still do not expose a Bedrock config path for custom `anthropic_beta` or generic `additionalModelRequestFields`, and the remaining question is the public Bedrock provider config contract.

## What This Changes

The issue requests a configurable Bedrock Anthropic beta-field passthrough so Claude models on Amazon Bedrock can send beta flags such as `context-1m-2025-08-07` without patching installed provider code.

## Best Possible Solution

Add a Bedrock-plugin-owned, schema-backed request-field or beta merge contract with docs, focused merge/de-duplication tests, and redacted live Bedrock proof before landing.

Options:

- **Add Bedrock-owned request fields (recommended):** Expose a schema-backed Bedrock plugin or per-model params contract that validates and merges request fields, covering `anthropic_beta` without making core own generic Bedrock payload policy.
- **Add only typed beta support:** Support a narrow `anthropicBeta` or Bedrock `context1m` path for Claude long-context usage while avoiding a general Converse body passthrough.
- **Decline custom betas:** Keep Bedrock request shaping internal and require first-class provider support for each beta feature before OpenClaw sends it.

Unclear. A configurable Bedrock request-field path is plausible, but maintainers should choose the public config contract before implementation because it expands provider-owned request surface.
