## Summary

Keep open: current main and v2026.6.11 still do not expose a Bedrock config path for custom `anthropic_beta` or generic `additionalModelRequestFields`, and the remaining decision is the public provider config contract.

## What This Changes

Request to let Amazon Bedrock model config pass custom Anthropic beta flags or provider request fields into Bedrock Converse `additionalModelRequestFields`.

## Best Possible Solution

Add a Bedrock-plugin-owned, schema-backed request-field or beta merge contract with docs, focused merge/de-duplication tests, and redacted live Bedrock proof before landing.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Bedrock expose a broad `additionalModelRequestFields`/`providerFields` passthrough, a narrower typed `anthropicBeta`/`context1m` option, or no user-configurable beta flags?

Rationale: The source gap is clear, but adding any of these paths creates a user-facing provider config contract and repository policy treats provider routing and config/default surfaces as compatibility-sensitive.

Likely owner: steipete

Owner reason: The decision spans Bedrock provider behavior, provider config surface policy, and adjacent Anthropic long-context lifecycle work where this owner appears in recent history.

Owner confidence: medium

Options:

- **Add Bedrock-owned request fields (recommended):** Expose a Bedrock plugin or per-model params contract that validates and merges request fields, covering `anthropic_beta` without making core own generic Bedrock payload policy.
- **Add only a typed beta option:** Support a narrow `anthropicBeta` or Bedrock `context1m` path for Claude long context while avoiding a general Converse body passthrough.
- **Decline custom betas:** Keep Bedrock request shaping internal and require first-class provider support for each beta feature before OpenClaw sends it.

## Reproduction Assessment

Yes for a source-level reproduction: current main has no Bedrock config merge point for custom `anthropic_beta` or `additionalModelRequestFields`, and the issue includes a live Bedrock command transcript for the same failure mode.

## Solution Assessment

Unclear. A configurable Bedrock request-field path is plausible, but maintainers should choose the public config contract before implementation because this expands provider-owned request surface.
