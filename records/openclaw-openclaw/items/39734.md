## Summary

Keep open: current main and the latest release still lack a Bedrock config path for custom `anthropic_beta` or generic `additionalModelRequestFields`, and the remaining decision is which provider-owned public config contract maintainers want.

## What This Changes

Request to let Amazon Bedrock model configuration supply custom Anthropic beta flags, such as `context-1m-2025-08-07`, into Bedrock Converse `additionalModelRequestFields` instead of patching provider code after upgrades.

## Best Possible Solution

Add a Bedrock-plugin-owned, schema-validated request-field or beta merge contract with docs, focused tests for `anthropic_beta` merge/de-duplication, and redacted live Bedrock proof before landing.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should the Bedrock plugin expose a broad `additionalModelRequestFields` or `providerFields` merge contract, a narrower typed `anthropicBeta` or `context1m` option, or keep Anthropic beta flags internal?

Rationale: The missing path is source-proven, but adding provider request-body config expands a public provider contract and OpenClaw policy sets a high bar for new config surfaces.

Likely owner: vincentkoc

Owner reason: vincentkoc has the strongest available history on the recent Bedrock provider and provider-contract surfaces that would need to own this decision.

Owner confidence: high

Options:

- **Add Bedrock request-field merge contract (recommended):** Expose a Bedrock-owned, schema-validated merge point for vendor request fields and document merge/de-dup semantics for `anthropic_beta`.
- **Add only a narrow beta option:** Support a typed `anthropicBeta` or 1M-context option while avoiding a broad arbitrary request-field passthrough.
- **Decline custom beta config:** Keep beta flags internal and require first-class provider support for each Bedrock beta field instead of allowing user config to send arbitrary vendor fields.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path for the missing configuration surface: the current Bedrock plugin has no config or option that can merge custom `anthropic_beta` into `additionalModelRequestFields`. I did not run a live AWS Bedrock request.

## Solution Assessment

Unclear. The proposed per-model `providerFields` path is plausible, but maintainers should choose the permanent Bedrock public config contract before implementation because broad request-body passthrough changes provider ownership and upgrade semantics.
