## Summary

Keep open: current main still has no Bedrock model-config path for custom `anthropic_beta` or generic `additionalModelRequestFields`, and the remaining fix is a provider config contract decision rather than conservative cleanup.

## What This Changes

Request to let Amazon Bedrock model config supply custom Anthropic beta flags that OpenClaw merges into Bedrock Converse `additionalModelRequestFields`.

## Best Possible Solution

Add a Bedrock-plugin-owned request-field contract with schema, docs, tests for `anthropic_beta` merging and de-duplication, and redacted live Bedrock proof before landing.

Rationale: The source gap is clear, but the fix adds a user-facing provider config contract and repository policy treats config/default/provider surfaces as compatibility-sensitive product decisions.

Owner confidence: medium

Options:

- **Add Bedrock-owned request fields (recommended):** Expose a Bedrock plugin or per-model params contract that safely merges request fields, validates shape, documents upgrade behavior, and covers `anthropic_beta` without making core generic config own the vendor field.
- **Add only a narrow beta flag:** Support a typed Bedrock `anthropicBeta` or `context1m` path for Claude long context while avoiding a general Converse body passthrough.
- **Decline custom betas:** Keep Bedrock request shaping internal and handle each beta feature through first-class provider support when maintainers intentionally add it.

Yes, at source level. Current main has no Bedrock config merge point for custom `anthropic_beta` or `additionalModelRequestFields`, and the issue includes a live Bedrock command transcript for the same failure mode.

## Solution Assessment

Unclear. A configurable Bedrock request-field path is plausible, but maintainers should choose the public config contract before implementation because this expands provider-owned request surface.
