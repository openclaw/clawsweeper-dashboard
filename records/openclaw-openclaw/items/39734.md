## Summary

Keep open: current main and v2026.6.11 still do not expose a Bedrock config path to merge custom `anthropic_beta` or generic `additionalModelRequestFields`, and the remaining choice is the public provider config contract rather than a cleanup close.

## What This Changes

Request is to let Amazon Bedrock model config supply custom `anthropic_beta` flags that OpenClaw merges into Bedrock Converse `additionalModelRequestFields`.

## Best Possible Solution

Add a Bedrock-plugin-owned, schema-validated request-field merge contract, or a deliberately narrower typed beta option, with docs, merge/dedup tests, and redacted live Bedrock proof.

Rationale: The source gap is clear, but adding provider request-body config expands a public provider contract and can affect upgrades, vendor behavior, and support burden.

Options:

- **Add Bedrock request-field merge contract (recommended):** Expose a Bedrock-owned, schema-validated merge point for vendor request fields and document merge/dedup semantics.
- **Add only a narrow beta option:** Support a typed `anthropicBeta` or 1M-context option while avoiding broad passthrough of arbitrary request fields.
- **Decline custom beta config:** Keep beta flags internal and require users to wait for first-class provider features instead of sending custom vendor fields.

## Reproduction Assessment

Yes for a source-level reproduction: current Bedrock code only builds `additionalModelRequestFields` from internal reasoning logic and has no config merge path for `context-1m-2025-08-07`. I did not run live Bedrock credentials, so the runtime API acceptance evidence comes from the issue discussion and SDK contract inspection.

## Solution Assessment

Unclear until maintainers choose the config contract. A Bedrock-owned merge path is the most flexible fix, while a narrow typed beta option is safer if broad passthrough is not desired.
