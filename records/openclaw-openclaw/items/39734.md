## Summary

Keep open: current main and v2026.6.11 still lack a Bedrock-owned config path for custom `anthropic_beta` or generic `additionalModelRequestFields`, and the remaining blocker is choosing the public provider config contract.

## What This Changes

Allow Bedrock model configuration to pass custom Anthropic beta flags into Converse `additionalModelRequestFields`.

## Best Possible Solution

Add a Bedrock-plugin-owned, schema-validated request-field merge contract, or deliberately choose a narrower typed `anthropicBeta`/`context1m` option, with docs, merge/dedup tests, and redacted live Bedrock Converse proof.

Yes, source-reproducible. Current Bedrock source builds `additionalModelRequestFields` internally and exposes no configured `anthropic_beta` or `providerFields` merge path; the issue discussion adds live Bedrock CLI evidence, but I did not rerun AWS credentials in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public config contract. A Bedrock-owned validated merge path is the flexible fix, while a narrower typed option is safer if broad passthrough is not desired.
