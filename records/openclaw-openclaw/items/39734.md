## Summary

Keep open: current main and v2026.6.11 still lack a Bedrock config path for custom `anthropic_beta` or generic `additionalModelRequestFields`, and the closed related PRs leave this issue as the canonical product-contract decision.

## What This Changes

The issue requests a per-model Bedrock configuration path to merge custom `anthropic_beta` flags into Converse `additionalModelRequestFields`.

## Best Possible Solution

Define a Bedrock-owned request-field merge contract, document it, test `anthropic_beta` merging and de-duplication with internally generated fields, and require redacted live Bedrock proof before landing.

## Reproduction Assessment

Yes. Source-level reproduction is high confidence: current main only builds Bedrock `additionalModelRequestFields` from internal reasoning options, and neither `BedrockOptions` nor the plugin config schema exposes the requested custom beta/request-field path.

## Solution Assessment

Unclear. A configurable Bedrock request-field path is likely the right direction, but maintainers should choose the narrow public contract before implementation because this adds user-facing provider config surface.
