## Summary

Keep open: current main and v2026.6.11 still do not expose a Bedrock config path for custom `anthropic_beta` or generic `additionalModelRequestFields`; the source gap is clear, but the fix is a public provider config decision.

## What This Changes

The issue requests a Bedrock provider configuration path for custom Anthropic beta flags so users can pass `anthropic_beta` values through `additionalModelRequestFields`.

## Best Possible Solution

Add a Bedrock-plugin-owned, schema-backed request-field or beta merge contract with docs, focused merge/de-duplication tests, and redacted live Bedrock proof before landing.

Rationale: The source gap is clear, but adding any path creates a user-facing provider config contract, and repository policy treats provider routing plus config/default surfaces as compatibility-sensitive.

Owner confidence: medium

Options:

- **Add Bedrock-owned request fields (recommended):** Expose a schema-backed Bedrock plugin or per-model params contract that validates and merges request fields, covering `anthropic_beta` without moving Bedrock payload policy into core.
- **Add only typed beta support:** Support a narrow `anthropicBeta` or Bedrock `context1m` path for Claude long-context usage while avoiding a general Converse body passthrough.
- **Decline custom betas:** Keep Bedrock request shaping internal and require first-class provider support for each beta feature before OpenClaw sends it.

## Reproduction Assessment

Yes, source-level: current main constructs Bedrock `additionalModelRequestFields` internally and exposes no config schema or stream option for custom `anthropic_beta`; the issue also includes a live Bedrock CLI transcript for the same failure mode.

## Solution Assessment

Unclear. A configurable Bedrock request-field path is plausible and matches the AWS Converse API shape, but maintainers should choose between broad passthrough and typed beta support before implementation.
