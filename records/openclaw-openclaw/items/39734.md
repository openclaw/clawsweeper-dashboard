## Summary

Keep open: current main and the latest release still lack a Bedrock config path for custom `anthropic_beta` or generic `additionalModelRequestFields`, and the remaining blocker is the public provider config contract.

## What This Changes

Request to let Amazon Bedrock model config supply custom `anthropic_beta` flags that are merged into Bedrock Converse `additionalModelRequestFields`.

## Best Possible Solution

Add a Bedrock-plugin-owned request-field merge contract with schema, docs, tests for `anthropic_beta` merging and de-duplication, and redacted live Bedrock proof before landing.

- **Add Bedrock-owned request fields (recommended):** Expose a Bedrock plugin or per-model params contract that validates and safely merges request fields, documents upgrade behavior, and covers `anthropic_beta` without creating a core-wide generic passthrough.

- **Decline custom beta config:** Keep Bedrock request shaping internal and ask users to wait for first-class provider support for each beta feature.

Unclear. A configurable Bedrock request-field path is plausible, but maintainers should choose the public config contract before implementation because this expands provider-owned request surface.
