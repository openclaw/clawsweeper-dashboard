## Summary

Keep open: current main and the latest release still lack a Bedrock config path for custom `anthropic_beta` or generic `additionalModelRequestFields`, while the issue discussion and source inspection show the provider gap remains real. The remaining blocker is maintainer product direction for the public Bedrock request-field contract.

## What This Changes

Request adding a Bedrock model-config path so users can send custom Anthropic beta flags such as `context-1m-2025-08-07` through `additionalModelRequestFields`.

## Best Possible Solution

Add a Bedrock-plugin-owned request-field merge contract, preferably through documented per-model params, with schema validation and tests proving configured `anthropic_beta` values merge safely with existing Bedrock reasoning betas.

Options:

- **Add only a narrow beta option:** Support a typed Bedrock `anthropicBeta` or `context1m` path for Claude long context while avoiding arbitrary Converse body fields.
- **Decline custom betas:** Keep Bedrock request shaping internal and require first-class provider updates for each supported beta feature.

## Solution Assessment

Unclear until maintainer direction is set. A Bedrock-owned request-field merge path is plausible and likely the best end state, but maintainers should choose the public config contract before implementation because this expands provider-owned request surface.
