## Summary

Keep open: current main and v2026.6.11 still lack a Bedrock-owned config path to merge custom `anthropic_beta` or generic `additionalModelRequestFields`, and the remaining choice is the public provider config contract.

## What This Changes

The issue asks for a Bedrock provider configuration path that can pass custom Anthropic beta flags into Converse `additionalModelRequestFields`.

## Best Possible Solution

Add a Bedrock-plugin-owned, schema-validated beta/request-field merge contract, or a deliberately narrower typed `anthropicBeta` option, with docs, merge/dedup tests, and redacted live Bedrock proof.

Options:

- **Add broad request-field merge contract:** Expose schema-validated `additionalModelRequestFields` or `providerFields` for Bedrock and document merge precedence, safety boundaries, and unsupported prompt-management interactions.
- **Keep beta flags internal:** Decline custom beta config and require first-class provider support for each Bedrock beta feature as it becomes needed.

Yes. Current source shows no Bedrock config merge path for `anthropic_beta`, and the issue discussion plus AWS docs provide a concrete live Bedrock proof path; I did not run AWS credentials in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public config contract. A typed `anthropicBeta` option is the safer narrow fix, while a broad Bedrock request-field passthrough is more flexible but needs explicit product approval.
