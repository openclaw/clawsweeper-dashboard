## Summary

Keep open: current main and the latest release still lack a Bedrock config path for custom `anthropic_beta` or generic `additionalModelRequestFields`, and the remaining work is a provider config-contract decision rather than a cleanup-close candidate.

## What This Changes

Request support for per-model Bedrock `anthropic_beta` or `additionalModelRequestFields` configuration so users can opt into Claude beta features without patching provider code.

## Best Possible Solution

Add a Bedrock-plugin-owned request-field merge contract with schema validation, docs, focused tests for `anthropic_beta` merging and de-duplication, and redacted live Bedrock proof before landing.

## Maintainer Decision

Kind: product_direction

Question: Should Bedrock expose a broad `additionalModelRequestFields` or `providerFields` passthrough, a narrower typed `anthropicBeta` or `context1m` option, or no user-configurable beta flags?

Rationale: This would create a user-facing provider config contract, and repository policy treats new config/default surfaces and provider routing behavior as compatibility-sensitive product decisions.

Owner confidence: high

Options:

- **Add Bedrock-owned request fields (recommended):** Expose a Bedrock plugin or per-model params contract that safely merges request fields, validates shape, documents upgrade behavior, and covers `anthropic_beta` without creating a core-wide generic passthrough.
- **Add only a narrow beta option:** Support a typed Bedrock `anthropicBeta` or `context1m` path for Claude long context while avoiding a general Converse body passthrough.
- **Decline custom betas:** Keep Bedrock request shaping internal and require first-class provider support for each beta feature before users can opt in.

## Reproduction Assessment

Yes at source level. Current Bedrock request construction never reads or merges a configured `providerFields` or `additionalModelRequestFields` value, and the issue includes live Bedrock evidence for the same missing `anthropic_beta` path.

## Solution Assessment

Unclear until maintainer direction is set. A Bedrock-owned request-field merge path is plausible, but maintainers should choose the public config contract before implementation because this expands provider-owned request surface.
