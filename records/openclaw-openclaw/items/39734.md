## Summary

Keep open: current main and v2026.6.11 still lack a Bedrock config path for custom `anthropic_beta` or generic `additionalModelRequestFields`, and the remaining blocker is choosing the public Bedrock provider config contract.

## What This Changes

The issue requests a config-driven way for Amazon Bedrock Claude model definitions to pass `anthropic_beta` flags into Bedrock Converse `additionalModelRequestFields`.

## Best Possible Solution

Add a Bedrock-plugin-owned, schema-backed request-field or beta merge contract with docs, focused merge/de-duplication tests, and redacted live Bedrock proof before landing.

Question: Should Bedrock expose a broad `additionalModelRequestFields` or `providerFields` passthrough, a narrower typed `anthropicBeta`/`context1m` option, or no user-configurable beta flags?

Rationale: The source gap is clear, but any fix adds a user-facing Bedrock provider config contract and repository policy treats provider routing and config surfaces as compatibility-sensitive.

Likely owner: steipete

Owner reason: This choice spans provider config policy, Bedrock plugin boundaries, and adjacent Claude long-context support where this owner has recent merged history.

Owner confidence: medium

Options:

- **Add Bedrock-owned request fields (recommended):** Expose a Bedrock plugin or per-model params contract that validates and merges request fields, covering `anthropic_beta` without making core own generic Bedrock payload policy.
- **Add only typed beta support:** Support a narrow `anthropicBeta` or Bedrock `context1m` path for Claude long-context usage while avoiding a general Converse body passthrough.
- **Decline custom betas:** Keep Bedrock request shaping internal and require first-class provider support for each beta feature before OpenClaw sends it.

## Reproduction Assessment

Yes, source-level: current main constructs Bedrock `additionalModelRequestFields` only internally and exposes no config/schema path for custom betas. The issue also includes a live Bedrock CLI transcript for the same failure mode, though I did not rerun it with AWS credentials.

## Solution Assessment

Unclear. A configurable Bedrock request-field path is plausible, but maintainers should choose the public config contract before implementation because it expands provider-owned request surface.
