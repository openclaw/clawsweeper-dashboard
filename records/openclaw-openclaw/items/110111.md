## Summary

This PR should remain open for a focused test correction: the increased PID-file polls do not tolerate startup slower than the test command’s existing 500 ms timeout, so they can turn the same failure into a much longer wait. The `maintainer` label also requires explicit maintainer handling rather than cleanup closure.

## What This Changes

The branch changes three cross-OS release-check tests to wait up to 10 seconds rather than 2 seconds for child PID files.

## Best Possible Solution

Make startup readiness and the command-timeout assertion independent: record the child PID before starting the short timeout window, or redesign the fixture so a deliberately slow startup can be observed while the signal-forwarding deadline remains meaningfully tested.
