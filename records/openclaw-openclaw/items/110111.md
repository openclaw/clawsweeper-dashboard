## Summary

This PR should stay open: the three 10-second PID polls do not correct the timeout ordering in the 500 ms timeout test, so a delayed child can still be terminated before it writes the PID file. The current evidence shows focused test/CI runs, but not the claimed delayed-start condition succeeding after the fix.

## What This Changes

The PR changes three cross-OS release-check test child-PID readiness waits from 2 seconds to 10 seconds.

## Best Possible Solution

Restructure the timeout fixture so the child PID is established before the 500 ms timeout begins, then retain a bounded readiness wait and add a deterministic delayed-start regression case.
