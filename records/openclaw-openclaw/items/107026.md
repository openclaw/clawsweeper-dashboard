## Summary

This is a substantial, well-proven opt-in feature, but it still needs explicit maintainer sponsorship for the managed-configuration contract and the previously reported path-ownership defect remains on the unchanged head. The process-global write block can freeze configuration writes for unrelated profiles while one layered Gateway is running, so the PR is not merge-ready.

## What This Changes

Adds a repeatable `gateway run --config-layer <id=path>` flag that validates and composes ordered JSON5 configuration documents into a read-only startup snapshot, blocks mutations and reloads, and documents the workflow.

## Best Possible Solution

If maintainers sponsor the RFC direction, represent layered immutability as ownership of the specific effective config path or server context, preserve normal writes for unrelated profiles, and add coexistence coverage alongside the existing startup and mutation tests.
