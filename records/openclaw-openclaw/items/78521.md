## Summary

Keep open. The PR is a useful security-hardening direction, but the current diff trusts raw external-content marker substrings in attacker-controlled tool-result text, so it can bypass the wrapper and marker sanitization it is meant to add.

## What This Changes

The branch wraps text `toolResult` blocks at the generic transport-message boundary with existing external-content markers and updates adjacent regression tests.

## Best Possible Solution

Keep the shared transport-boundary hardening direction, but sanitize attacker-supplied marker text inside one fresh wrapper or use a non-attacker-controlled trusted-boundary signal, then refresh the branch and add redacted provider-payload or log proof.

## Reproduction Assessment

Yes. At source level, the PR head returns `toolResult` text unchanged when it contains external-content marker substrings, and the discussion includes a provider-payload reproduction of that bypass.

## Solution Assessment

No. The shared transform is a plausible boundary for this hardening, but this implementation must not treat marker substrings inside untrusted tool output as proof that the content is already safe.
