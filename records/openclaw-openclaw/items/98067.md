## Best Possible Solution

Land the per-connection pending-RPC cleanup after maintainer review and redacted real Android/gateway proof shows pending calls settle promptly on disconnect/reconnect without canceling replacement-connection waiters.

## Reproduction Assessment

Yes, from source inspection: current main registers pending RPC waiters in a session-wide map and intentional `closeQuietly()` does not drain them, while the PR adds focused tests for disconnect and reconnect behavior.

## Solution Assessment

Yes. Per-connection waiter ownership is the maintainable fix because a session-wide drain on close could cancel RPCs owned by a replacement WebSocket connection.
