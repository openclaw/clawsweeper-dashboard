## What This Changes

The PR moves Android `GatewaySession` RPC waiters from a session-wide map into each WebSocket `Connection`, cancels that connection's waiters on close, adds disconnect/reconnect regression tests, and updates native i18n line inventory.

## Best Possible Solution

Land the per-connection pending-RPC cleanup after maintainer review and redacted real Android/gateway proof shows pending calls settle promptly on disconnect/reconnect without canceling replacement-connection waiters.

## Reproduction Assessment

Yes from source inspection, but not from a locally executed run in this read-only review. Current main registers RPC waiters in a session-wide map and intentional `closeQuietly()` does not drain them, while the PR adds focused tests for disconnect and reconnect behavior.

## Solution Assessment

Yes. Per-connection waiter ownership with synchronized register/drain is the maintainable fix because a session-wide drain could cancel RPCs owned by a replacement WebSocket connection.
