## Summary

Keep this PR open: the proposed fingerprint relies on V8 serialization bytes being stable for equal values, but Node explicitly disclaims that property, so unchanged configuration can produce false cache misses and the optimization rests on an unsupported contract.

## What This Changes

The PR changes web-fetch provider-cache config fingerprinting from JSON text to `node:v8` serialization bytes and adds a large deep-mutation regression test.

## Best Possible Solution

Use a deterministic fingerprint of the minimal provider-discovery inputs, or a lifecycle-owned version carried into the cache key, while preserving same-object mutation invalidation and avoiding repeated full-config string allocation.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, from source and the upstream dependency contract: every cache hit requires a repeatable fingerprint, while the selected serializer does not guarantee equal-value byte equality. A particular false miss is V8-implementation-dependent rather than deterministic on every invocation.

## Solution Assessment

No. The benchmark shows the approach can be faster, but a cache fingerprint should not rely on a serializer property that Node explicitly does not guarantee; a deterministic minimal projection or lifecycle version is safer.
