## Summary

Keep open: current main and v2026.6.11 still lack a Discord role-mention trigger config and preflight path, and this issue remains the narrow canonical tracker while broader Discord routing/access-control issues only partially overlap.

## What This Changes

The issue requests Discord role-mention triggers so configured role mentions can wake mention-gated agents instead of requiring direct bot mentions.

## Best Possible Solution

Add a distinct Discord-owned selected-role trigger contract and wire it through config types, strict schema, generated metadata/help, docs, preflight, and focused tests without reusing the existing sender `roles` allowlist.

## Reproduction Assessment

Yes. At source level, with `requireMention` true and only `mentionedRoles` present, `explicitlyMentioned` is false, role IDs are not passed into `resolveDiscordMentionState`, and the no-mention or `ignoreOtherMentions` drop paths can run; no live Discord replay was run in this read-only pass.

## Solution Assessment

Unclear as a finalized product path. A selected role-ID trigger surface appears safer than auto-triggering on every bot-held role, but maintainers still need to approve the config name, inheritance, default, and multi-agent fan-out behavior.
