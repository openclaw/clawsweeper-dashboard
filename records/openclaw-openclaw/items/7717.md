## Summary

Keep open: current main and v2026.6.11 still lack a Discord role-mention trigger config or preflight path, so role-addressed wake behavior remains an unresolved Discord product/config decision.

## What This Changes

Request to add Discord role-mention triggers so configured role mentions can wake bots in mention-gated guild channels.

## Best Possible Solution

Approve a narrow Discord-owned trigger-role contract, then wire it through config types, strict schema, metadata/docs, preflight, source tests, and live Discord proof while preserving sender role allowlists and current @everyone/@here behavior.

Options:

- **Add Explicit Trigger Roles (recommended):** Add a narrow guild/channel trigger-role list that turns matching mentioned role IDs into a wake mention while keeping sender roles as access control.
- **Fold Into Access Redesign:** Keep this blocked until the broader Discord bypass/mention/deny model in https://github.com/openclaw/openclaw/issues/69748 defines role semantics.
- **Decline Role Wake Triggers:** Keep direct user mentions and @everyone/@here only, and document role mentions as non-wake metadata.

## Reproduction Assessment

Yes, at source level: with requireMention true and only mentionedRoles present, current preflight has no path that compares mentioned role IDs with configured trigger roles. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear as a final product contract: configured role IDs look safer than treating every bot-held role as a wake signal, and regex mentionPatterns are only a workaround rather than a Discord role metadata contract.
