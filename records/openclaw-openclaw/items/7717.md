## Summary

Keep open: current main and v2026.6.11 still lack a Discord role-mention trigger config or preflight path, and the live related-item history keeps this issue as the narrow canonical tracker for that remaining behavior.

## What This Changes

Request support for configured Discord role mentions, such as an `@AI` role, to wake agents in mention-gated guild channels.

## Best Possible Solution

Approve a narrow Discord-owned trigger-role contract, then wire it through config types, strict schema, metadata/docs, preflight, and focused tests while preserving sender role allowlists and current @everyone/@here behavior.

## Reproduction Assessment

Yes, at source level: with `requireMention` true and only `mentionedRoles` present, current preflight never compares mentioned role IDs to configured trigger IDs and can reach the no-mention or other-mention drop path. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear as a final product contract: selected configured role IDs look safer than treating every bot-held role as a wake signal, but maintainers still need to choose the config name, inheritance, and fan-out behavior.
