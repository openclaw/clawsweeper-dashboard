## Summary

Keep open: current `main` and `v2026.6.11` still lack a selected Discord role-mention trigger config and preflight path, and this issue remains the narrow canonical tracker while broader Discord access-control and routing reports only partially overlap.

## What This Changes

The issue requests Discord role mentions to become configurable wake triggers for bots, instead of only direct bot mentions.

## Best Possible Solution

Approve a narrow Discord-owned selected-role trigger contract, then wire it through config types, strict schema, generated metadata/help, docs, preflight, and focused tests without reusing the existing sender `roles` allowlist.

## Reproduction Assessment

Yes, at source level: with `requireMention` true and only `mentionedRoles` present, explicit mention remains false and role IDs are not passed into `resolveDiscordMentionState`, so the `no-mention` or `ignoreOtherMentions` drop paths can run. No live Discord replay was run in this read-only review.

## Solution Assessment

Unclear as a final product contract: configured selected role IDs appear safer than auto-triggering on every bot-held role, but maintainers still need to decide the exact config name, inheritance, managed-role behavior, and fan-out semantics.
