## Summary

Keep open: current main and v2026.6.11 still do not expose a Discord role-mention trigger config or treat configured role mentions as explicit wake mentions. Related role-mention reports were closed in favor of this issue, while the broader Discord access-control and mention-gating issues only partially overlap.

## What This Changes

The issue requests Discord role-mention triggers so selected role mentions can wake Discord agents instead of requiring direct bot mentions.

## Best Possible Solution

Keep this as the canonical role-mention trigger tracker and implement an additive Discord plugin config/activation path only after maintainers decide the role matching semantics.

## Reproduction Assessment

Yes, at source level: a role-only Discord mention leaves explicitlyMentioned false, passes mentionedRoles only as generic hasAnyMention metadata, and reaches the no-mention path when requireMention is true unless another mention signal matches. I did not run a live Discord replay in this read-only pass.

## Solution Assessment

Unclear until maintainers choose the product contract. The narrow maintainable direction is an additive Discord plugin config and preflight comparison against mentioned role IDs, preserving existing sender roles allowlists and @everyone/@here behavior.
