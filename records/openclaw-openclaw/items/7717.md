## Summary

Keep open: current main and v2026.6.11 still lack a Discord role-mention trigger config or mention-state path, and the related open issues are broader or adjacent rather than a safer canonical replacement.

## What This Changes

The issue requests a Discord guild/channel option that lets configured role mentions wake agents, so users can ping a shared bot role instead of each bot directly.

## Best Possible Solution

Approve a narrow Discord-owned trigger-role contract, then wire it through config types, strict schema, docs, preflight, and focused tests while preserving sender role allowlists and existing @everyone/@here behavior.

## Reproduction Assessment

Yes, at source level: with requireMention true and only mentionedRoles present, current preflight never compares role IDs to configured trigger IDs and can drop the message as no-mention or other-mention. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear as a final product contract: an explicit configured role-ID trigger list looks safer than treating every bot-held role as a wake signal, but maintainers still need to choose the config name, inheritance, and fan-out behavior.
