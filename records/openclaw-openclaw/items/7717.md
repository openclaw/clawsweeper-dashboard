## Summary

Keep open: current main and v2026.6.11 still lack a Discord role-mention trigger config and preflight path, while related broader Discord routing/access-control items only partially overlap.

## What This Changes

Request adding Discord role-mention triggers so selected role IDs can wake agents in mention-gated guild channels.

## Best Possible Solution

Approve a narrow Discord-owned selected-role trigger contract, then wire it through config types, strict schema, generated metadata/help, docs, preflight, and focused tests without reusing the existing sender roles allowlist.

## Reproduction Assessment

Yes at source level: with requireMention true and only mentionedRoles present, explicitlyMentioned is false, role IDs are not passed into resolveDiscordMentionState, and the no-mention or ignoreOtherMentions drop paths can run. I did not run a live Discord replay in this read-only pass.

## Solution Assessment

Unclear as a finalized product path. A selected role-ID trigger surface appears safer than auto-triggering on every bot-held role, but maintainers still need to approve the config name, inheritance, default, and multi-agent fan-out behavior.
