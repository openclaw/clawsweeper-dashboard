## Summary

Keep open: current main and v2026.6.11 still do not provide a Discord role-mention wake trigger, so this remains a valid Discord feature/product-decision issue rather than conservative cleanup.

## What This Changes

Add opt-in Discord role-mention triggers so configured role mentions can wake agents, instead of requiring direct bot mentions.

## Best Possible Solution

Approve a narrow Discord-owned trigger-role contract, then wire it through config types, strict schema, docs, preflight, and focused source/live proof while preserving sender role allowlists and existing @everyone/@here behavior.

## Maintainer Decision

Question: Should Discord role mentions wake agents via an explicit opt-in trigger-role config, automatic bot role membership, or the broader Discord access-control redesign?

Rationale: The source gap is clear, but the fix adds a new Discord config surface and determines how multi-agent fan-out behaves when a shared role is mentioned.

Likely owner: steipete

Owner confidence: high

Options:

- **Use explicit trigger role IDs (recommended):** Add a narrow guild/channel trigger-role list and treat only configured mentioned roles as wake signals while keeping sender roles as access control.
- **Fold into access-control redesign:** Defer this issue to the broader bypass/mention/deny Discord access model so sender authorization and role-trigger semantics are decided together.
- **Decline role fan-out:** Keep direct mentions and @everyone/@here as the only wake signals and document role mentions as non-triggering metadata.

## Reproduction Assessment

Yes, at source level: with requireMention true and only mentionedRoles present, current preflight has no path that compares mentioned role IDs with configured trigger role IDs, so role-only messages can still drop as no-mention or other-mention. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear as a final product contract: configured role IDs look safer than automatic bot-held role activation, but maintainers still need to choose the config name, inheritance, and fan-out behavior.
