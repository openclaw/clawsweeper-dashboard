## Summary

Keep open: current main and v2026.6.11 still lack a Discord role-mention trigger config or preflight path, so the requested role-addressed wake behavior remains a valid Discord delivery/product decision.

## What This Changes

Request to let Discord role mentions such as @AI wake bots, preferably through a configured role-ID trigger list.

## Best Possible Solution

Approve a narrow Discord-owned trigger-role contract, then wire it through config types, strict schema, generated metadata/docs, preflight, focused tests, and live Discord proof while preserving sender role allowlists and current @everyone/@here behavior.

Options:

- **Fold into access redesign:** Keep this blocked until the broader Discord bypass/mention/deny model in https://github.com/openclaw/openclaw/issues/69748 defines role semantics.
- **Decline role wake triggers:** Keep direct user mentions and @everyone/@here only, and document role mentions as non-wake metadata.

## Reproduction Assessment

Yes, at source level: with requireMention true and only mentionedRoles present, current preflight has no path that compares mentioned role IDs with configured trigger roles. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear as a final product contract: configured role IDs look safer than treating every bot-held role as a wake signal, but maintainers still need to choose the config name, inheritance, and fan-out behavior.
