## Summary

Keep open: current main and the latest release still treat Discord role mentions as generic mention metadata, not as configured wake triggers, and the related closed reports point back to this issue as the canonical tracker. The remaining work needs maintainer product review because it adds Discord activation/config semantics where `roles` already means sender allowlist.

## What This Changes

Add Discord role-mention activation so configured role IDs can wake mention-gated Discord agents.

## Best Possible Solution

Keep this as the narrow canonical role-mention trigger tracker and design an additive Discord guild/channel trigger-role surface, or an approved equivalent, that preserves current sender `roles`, `requireMention`, `ignoreOtherMentions`, @everyone/@here, reply-to-bot, and routing semantics.

## Reproduction Assessment

Yes, at source level. A role-only Discord mention populates `mentionedRoles`, but current preflight only compares `mentionedUsers` to the bot id and `resolveDiscordMentionState` has no role-trigger input, so `requireMention` can still drop the message.

## Solution Assessment

Unclear. The requested Discord-plugin scope is right, but the exact config shape needs maintainer approval because role IDs already have sender-allowlist semantics and related access-control proposals overlap this surface.
