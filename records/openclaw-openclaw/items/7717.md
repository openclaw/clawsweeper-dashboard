## Summary

Keep open: current main and v2026.6.11 still lack a Discord role-mention trigger config and preflight path, while related Discord issues only cover adjacent mass-mention, access-control, or broader active-target semantics.

## What This Changes

Request to let Discord role mentions, such as a configured `@AI` role, wake matching OpenClaw bots instead of requiring direct bot mentions.

## Best Possible Solution

Approve a narrow Discord-owned selected-role trigger contract, then wire it through config types, strict schema, generated metadata/docs, preflight, and focused tests while preserving existing sender `roles` allowlist behavior.

## Reproduction Assessment

Yes, at source level: with `requireMention` true and only `mentionedRoles` present, `explicitlyMentioned` remains false and role IDs are not passed into `resolveDiscordMentionState`, so the no-mention or `ignoreOtherMentions` drop paths can run. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear as a final product contract: configured selected role IDs appear safer than automatically waking on every bot-held role, but maintainers still need to choose the config name, inheritance behavior, default, and fan-out semantics.
