## Summary

Keep open: current main and v2026.6.11 still lack a Discord role-mention trigger config and preflight path, and the linked broader Discord routing/access-control items only partially overlap this narrower request.

## What This Changes

The issue requests Discord role-mention triggers so selected role mentions can wake Discord-connected agents like direct bot mentions.

## Best Possible Solution

Add a distinct Discord-owned selected-role trigger contract and wire it through config types, strict schema, generated metadata/help, docs, preflight, and focused tests without reusing the existing sender `roles` allowlist.

## Reproduction Assessment

Yes at source level. With `requireMention` true and only `mentionedRoles` present, current preflight records the role mention as generic mention metadata but does not pass role IDs into the mention resolver, so `wasMentioned` remains false and no-mention or other-mention drops can run.

## Solution Assessment

Unclear as a finalized product path. A selected role-ID trigger surface appears safer than auto-triggering on every bot-held role, but maintainers still need to approve the config name, inheritance, default, and multi-agent fan-out behavior.
