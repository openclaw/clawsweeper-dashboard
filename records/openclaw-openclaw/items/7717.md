## Summary

Keep open: current main and v2026.6.11 still lack a Discord role-mention trigger config or preflight path, and this issue remains the narrow canonical tracker rather than a duplicate of broader Discord routing/access-control proposals.

## What This Changes

The issue requests Discord role mention triggers so configured Discord role IDs can wake agents without directly mentioning each bot.

## Best Possible Solution

Approve a narrow Discord-owned trigger-role contract, then wire it through config types, strict schema, generated metadata/help, docs, preflight, and focused tests while preserving sender role allowlists and current mass-mention behavior.

## Reproduction Assessment

Yes, at source level: with `requireMention` true and only `mentionedRoles` present, current preflight never compares the mentioned role IDs to configured trigger IDs and can reach the no-mention or other-mention drop path. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear as a final product contract: selected configured role IDs look safer than treating every bot-held role as a wake signal, but maintainers still need to choose the config name, inheritance, and fan-out behavior.
