## Summary

Keep open: current main and the latest release still lack a Discord role-ID trigger config and preflight path, and related closed reports point back to this as the canonical narrow tracker rather than proving it fixed.

## What This Changes

Request to let configured Discord role mentions wake agents, instead of requiring users to mention each bot directly.

## Best Possible Solution

Approve a narrow Discord plugin selected-role trigger contract, then wire it through config types, strict schema, metadata/docs, preflight, and focused tests while preserving sender roles allowlists and @everyone/@here behavior.

## Reproduction Assessment

Yes, at source level: with requireMention true and only mentionedRoles present, current preflight has no configured role-ID comparison before mention gating. I did not run a live Discord replay.

## Solution Assessment

Unclear as a finalized product contract: configured role IDs appear safer than treating every bot-held role as a wake signal, but maintainers still need to choose the config name, inheritance, and fan-out behavior.
