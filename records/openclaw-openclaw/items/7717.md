## Summary

Keep open: current main and the latest release still lack a configured Discord role-mention trigger path; role mentions are recorded as generic mention metadata, while existing `roles` config remains sender access control rather than activation.

## What This Changes

Request to let selected Discord role mentions wake agents in mention-gated guild channels, likely through a new role ID config surface.

## Best Possible Solution

Approve a narrow Discord-owned selected-role trigger contract, then wire it through config types, strict schema, generated metadata/help, docs, preflight, and focused tests while preserving existing sender `roles`, @everyone/@here, `ignoreOtherMentions`, and routing behavior.

## Reproduction Assessment

Yes, at source level: with `requireMention` true and only `mentionedRoles` present, current preflight has no configured role-ID comparison and can reach the no-mention or other-mention drop path. I did not run a live Discord replay.

## Solution Assessment

Unclear as a final product contract: configured role IDs appear safer than treating every bot-held role as a wake signal, but maintainers still need to choose the config name, inheritance, and fan-out behavior.
