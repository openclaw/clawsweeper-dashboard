## Summary

Keep open: current main and v2026.6.11 still do not have a Discord role-mention trigger config or preflight path, and the remaining work needs maintainer product direction because it adds a shipped Discord config surface and role fan-out semantics.

## What This Changes

Add Discord role-mention triggers so configured role mentions can wake bots, instead of only direct bot mentions and existing mention patterns.

## Best Possible Solution

Approve a narrow Discord-owned trigger-role contract, then wire it through config types, strict schema, metadata/docs, preflight, and focused source plus live Discord proof while preserving sender role allowlists and current @everyone/@here behavior.

Owner confidence: high

Options:

- **Add explicit trigger roles (recommended):** Add a narrow guild/channel trigger-role list that turns matching mentioned role IDs into a wake mention while keeping sender roles as access control.
- **Fold into access redesign:** Keep this blocked until the broader Discord bypass, mention, and deny access-list proposal defines role membership and trigger semantics together.
- **Decline role wake triggers:** Keep direct bot mentions and @everyone/@here only, and document role mentions as non-wake metadata.

## Reproduction Assessment

Yes, at source level: with requireMention true and only mentionedRoles present, current preflight has no path that compares mentioned role IDs with configured trigger roles. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear as a final product contract: configured role IDs look safer than treating every bot-held role as a wake signal, but maintainers still need to choose the config name, inheritance, and fan-out behavior.
