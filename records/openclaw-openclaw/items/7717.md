## Summary

Keep open: current main and v2026.6.11 still lack a Discord role-mention trigger config and preflight path, while this issue remains the narrow canonical tracker for role-addressed Discord wake behavior.

## What This Changes

The issue requests Discord role-mention trigger support so configured role IDs can wake Discord-bound agents instead of requiring direct bot mentions.

## Best Possible Solution

Add a distinct Discord-owned selected-role trigger contract in the bundled Discord plugin, preserving sender roles allowlists and covering config types, strict schema, generated metadata/help, docs, preflight, and focused role-only tests after maintainer product approval.

## Reproduction Assessment

Yes at source level: with requireMention true and only mentionedRoles present, explicitlyMentioned stays false, role IDs are not passed into resolveDiscordMentionState, and no-mention or ignoreOtherMentions drop paths can run. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear as a finalized product path: a selected role-ID trigger surface appears safer than auto-triggering on every bot-held role, but maintainers still need to approve the config name, inheritance, default, and fan-out semantics.
