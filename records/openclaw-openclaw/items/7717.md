## Summary

Keep open: current `main` and the latest release still lack a Discord role-mention trigger config or preflight path; role mentions are captured as generic mention metadata, while existing `roles` config is sender access control, not activation.

## What This Changes

Request support for configuring Discord role mentions so role pings can wake mention-gated agents instead of requiring direct bot mentions.

## Best Possible Solution

Approve a narrow Discord-owned selected-role trigger contract, then wire it through config types, strict schema, metadata/docs, preflight, and focused tests while preserving existing sender `roles` allowlists and @everyone/@here behavior.

## Reproduction Assessment

Yes. At source level, with `requireMention` true and only `mentionedRoles` present, current preflight does not compare role IDs to configured trigger IDs and can reach the no-mention or other-mention drop path.

## Solution Assessment

Unclear as a final product contract. Configured role IDs appear safer than treating every bot-held role as a wake signal, but maintainers still need to choose the config name, inheritance, and fan-out behavior.
