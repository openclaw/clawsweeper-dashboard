## Summary

Keep open: current main and v2026.6.11 still lack a Discord role-mention trigger config or preflight path, and the related closed reports point back to this issue as the narrow canonical tracker.

## What This Changes

Request support for configured Discord role IDs whose mentions wake the bot, so messages like `@AI` can trigger responses without pinging each bot directly.

## Best Possible Solution

Approve a narrow Discord-owned role-trigger contract, then implement it in the bundled Discord plugin without reusing sender `roles` semantics.

## Reproduction Assessment

Yes, at source level: with `requireMention` true and only `mentionedRoles` present, current preflight has no path that compares mentioned role IDs with configured trigger role IDs. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear as a final product contract: selected configured role IDs look safer than treating every bot-held role as a wake signal, but maintainers still need to choose the config name, inheritance, and fan-out behavior.
