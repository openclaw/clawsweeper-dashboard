## Summary

Current source, v2026.6.11, related issues, and history all point the same way: this remains a valid open Discord feature/product decision, not conservative cleanup, because role mentions are still metadata for mention filtering rather than configurable wake triggers.

## What This Changes

Request to let configured Discord role mentions, such as a shared agent role, wake agents under mention gating instead of requiring each bot to be mentioned directly.

## Best Possible Solution

Approve a narrow Discord-owned trigger-role contract, then wire it through config types, strict schema, docs, preflight, and focused source/live proof while preserving sender role allowlists and existing @everyone/@here behavior.

## Reproduction Assessment

Yes, at source level: with `requireMention` true and only `mentionedRoles` present, current preflight has no path that compares mentioned role IDs with configured trigger roles, so it can drop as no-mention or other-mention. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear as a final product contract: configured role IDs look safer than automatic bot-held role activation, but maintainers still need to choose the config name, inheritance, and fan-out behavior.
