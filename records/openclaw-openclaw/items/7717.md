## Summary

Keep open: current main and v2026.6.11 still lack configured Discord role-mention wake triggers. The request is valid and canonical, but direct bot mentions were previously confirmed as intentional, so an opt-in multi-agent fan-out policy needs maintainer approval before implementation.

## What This Changes

Add Discord guild/channel configuration that lets selected mentioned role IDs wake mention-gated agents.

## Best Possible Solution

Preserve direct bot mention as the default and, if approved, add a separately named opt-in guild/channel role-ID wake list that matches only observed configured roles, with schema, docs, focused regression coverage, and redacted live Discord proof.

Options:

- **Add opt-in wake roles (recommended):** Add a separate role-ID list that activates only on configured matching role mentions and leaves existing defaults unchanged.
- **Defer to access redesign:** Define mentioned-role wake semantics as part of the broader Discord access-policy redesign at https://github.com/openclaw/openclaw/issues/69748.
- **Keep direct mentions only:** Decline role-based fan-out and retain direct bot mention as the only role-specific wake mechanism.

## Reproduction Assessment

Yes, at source level. A role-only guild message sets generic mention facts but cannot set `wasMentioned` because neither observed role IDs nor configured trigger roles reach the mention-state helper.

## Solution Assessment

Not fully settled. An additive opt-in role-ID trigger is substantially safer than accepting every role mention, but its inheritance, bot-message policy, and interaction with other mention controls require maintainer approval.
