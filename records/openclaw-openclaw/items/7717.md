## Summary

Keep open: current main and the latest release still lack a selected Discord role-mention trigger config and preflight path; role mentions are recorded as generic mention metadata and existing `roles` config is sender access control, not activation.

## What This Changes

Request to let configured Discord role mentions, such as a shared `@AI` role, wake Discord-connected agents instead of requiring direct bot mentions.

## Best Possible Solution

Approve a narrow Discord-owned selected-role trigger contract, then wire it through config types, strict schema, metadata/docs, preflight, and focused tests while preserving existing sender `roles` allowlist and @everyone/@here behavior.

## Reproduction Assessment

Yes, at source level: with `requireMention` true and only `mentionedRoles` present, current preflight does not compare role IDs to configured trigger IDs and can reach the no-mention or other-mention drop path. I did not run a live Discord replay.

## Solution Assessment

Unclear as a final product contract: configured role IDs appear safer than treating every bot-held role as a wake signal, but maintainers still need to choose the config name, inheritance, and fan-out behavior.
