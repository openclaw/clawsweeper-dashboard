## Summary

The central request is already supported through configured mention patterns: Discord preserves raw role tokens such as `<@&ROLE_ID>` in inbound text, and matching configured patterns satisfy the wake gate. A dedicated `triggerOnRoles` key would duplicate the existing configuration path.

## What This Changes

Enable Discord role mentions to wake agents, ideally scoped by configured role IDs.

## Best Possible Solution

Keep mention patterns as the canonical role-trigger solution, document a Discord role-token example such as `<@&ROLE_ID>`, and address stricter `ignoreOtherMentions` interactions in the narrower routing tracker.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes for the reported default behavior: without a matching configured pattern, a role-only mention is not a native direct-bot mention. Current source also provides a high-confidence supported path by matching the preserved `<@&ROLE_ID>` token with `mentionPatterns`.

## Solution Assessment

No, adding a parallel `triggerOnRoles` field is not the best solution because the existing mention-pattern contract handles exact role tokens and can be scoped for Discord; documentation avoids another config source of truth.
