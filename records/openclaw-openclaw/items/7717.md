## Summary

Keep open: current main and v2026.6.11 still lack a Discord role-mention trigger surface; role mentions are only generic mention metadata today, while existing `roles` config remains sender access control.

## What This Changes

Requests Discord role mentions, such as a shared agent role, to wake agents instead of requiring each bot to be mentioned directly.

## Best Possible Solution

Approve a narrow Discord-owned selected-role trigger contract, then wire it through config types, strict schema, generated metadata/help, docs, preflight, and focused tests while preserving sender `roles` allowlists and current @everyone/@here behavior.

## Reproduction Assessment

Yes, at source level: with `requireMention` true and only `mentionedRoles` present, current preflight does not compare role IDs to configured trigger IDs and can reach the no-mention or other-mention drop path. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear as a final product contract: configured role IDs appear safer than treating every bot-held role as a wake signal, but maintainers still need to choose the config name, inheritance, and fan-out behavior.
