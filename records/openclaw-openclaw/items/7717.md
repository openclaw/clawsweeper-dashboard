## Summary

Keep this issue open. It requests a new Discord activation policy rather than repairing an established contract, and role-trigger semantics—especially intentional multi-bot fan-out, configuration scope, and interaction with existing mention and sender-access rules—need a maintainer product decision before implementation.

## What This Changes

Add an opt-in Discord guild or channel configuration that treats selected role mentions as wake-up mentions for bots when mention gating is enabled.

## System Context

Discord inbound preflight receives guild messages and decides whether a configured bot should respond before routing the message into an agent run. It combines sender access policy and mention state, so a role-based wake signal would affect which bots receive a shared guild message.

## Architecture Diagram

flowchart LR
  A[Discord guild message] --> B[Discord plugin preflight]
  B --> C[Sender access rules]
  B --> D[Mention detection]
  E[Guild or channel configuration] --> D
  C --> F[Eligibility decision]
  D --> F
  F --> G[Agent routing]
  G --> H[Bot response]

## Best Possible Solution

Define a distinct, opt-in role-trigger contract in the bundled Discord plugin, including whether matching roles wake every eligible bot, guild-versus-channel precedence, and the interaction with `requireMention`, `ignoreOtherMentions`, replies, sender allowlists, and bot-loop protections; then add schema, docs, and focused preflight coverage.
