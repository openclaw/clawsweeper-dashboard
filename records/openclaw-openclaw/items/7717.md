## Summary

Keep open: current main and v2026.6.11 still lack a Discord role-mention trigger config and the mention gate has no configured-role input. The gap is source-reproducible, but the fix changes Discord activation/config semantics and needs maintainer product direction.

## What This Changes

The issue requests Discord role-mention triggers so configured role mentions can wake eligible bots instead of requiring direct bot mentions.

## Best Possible Solution

Approve and document a Discord-owned additive role-trigger contract, then wire it through config types, strict schema, metadata/docs, preflight, and focused tests while preserving existing sender role allowlists and @everyone/@here behavior.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: a guild message with only a role mention can set generic mention flags but cannot set `wasMentioned` because role IDs are not passed into the mention-state helper. The current schema also has no role-trigger key to configure the desired behavior.

## Solution Assessment

Unclear: an additive role-ID trigger option is plausible, but maintainers need to choose the config name, default, inheritance scope, and coexistence with existing sender `roles` and broader access-list proposals.
