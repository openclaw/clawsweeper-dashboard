## Summary

Keep open: current main and v2026.6.11 still do not implement Discord role-mention wake triggers, and the related closed reports explicitly defer the remaining role-trigger behavior to this issue rather than replacing it.

## What This Changes

The issue requests Discord role-mention triggers so configured role IDs can wake bots in mention-gated guild channels.

## Best Possible Solution

Keep this as the narrow canonical tracker and implement an additive Discord-plugin role-trigger config with schema, docs, and preflight tests while preserving sender role allowlists and existing @everyone/@here behavior.

## Reproduction Assessment

Yes, at source level: a role-only Discord payload sets mentionedRoles but not mentionedUsers, and current preflight never compares those role IDs with configured trigger roles before the requireMention drop path. I did not run a live Discord replay in this read-only pass.

## Solution Assessment

Unclear until maintainers choose the product contract. The requested explicit role-ID trigger config is plausible, but the best final shape must avoid colliding with sender roles allowlists and define managed-role and fan-out semantics.
