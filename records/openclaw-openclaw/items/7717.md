## Summary

Keep open: current main and the latest release still lack a Discord role-mention trigger config or preflight path, and this remains the narrow canonical tracker rather than a duplicate of broader Discord routing/access-control work.

## What This Changes

Request to add Discord role-mention triggers so messages mentioning configured roles can wake mention-gated bots.

## Best Possible Solution

Approve a narrow Discord-owned trigger-role contract, then wire it through config, schema, docs, preflight, and regression tests without overloading sender role allowlists.

## Reproduction Assessment

Yes, at source level: with `requireMention` true and only `mentionedRoles` present, current preflight never compares the mentioned role IDs to configured trigger IDs and can reach the no-mention or other-mention drop path. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear as final product contract: selected configured role IDs look safer than treating every bot-held role as a wake signal, but maintainers still need to choose the config name, inheritance, and fan-out behavior.
