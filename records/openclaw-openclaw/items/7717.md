## Summary

Keep open: current main and v2026.6.11 still lack a Discord role-mention trigger config and preflight path, while related closed reports point back to this narrow tracker and broader open reports only partially overlap.

## What This Changes

Requests Discord role mentions for configured role IDs to wake mention-gated bots, likely through an additive guild/channel triggerOnRoles-style config.

## Best Possible Solution

Add a distinct Discord-owned selected-role trigger contract after maintainer approval, preserving sender roles allowlists and covering config types, strict schema, generated metadata/help, docs, preflight, and focused role-only tests.

## Reproduction Assessment

Yes, at source level: with requireMention true and only mentionedRoles present, explicitlyMentioned remains false, role IDs are not passed into resolveDiscordMentionState, and the no-mention or ignoreOtherMentions drop paths can run. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear as a finalized product path: a selected role-ID trigger surface appears safer than auto-triggering on every bot-held role, but maintainers still need to approve the config name, inheritance, default, and fan-out semantics.
