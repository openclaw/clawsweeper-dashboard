## Label Justifications

- `P1`: A normal active channel workflow silently omits user-supplied media and can produce an ungrounded model response.
- `impact:message-loss`: The attachment is downloaded and persisted but absent from the model-visible steered input.

## Summary

The source trace supports a real shared active-run bug: OpenClaw accepts and persists an attachment-bearing inbound turn but sends only its text through the steering boundary. Current Codex and Pi contracts can carry images in streaming steer requests, so the issue remains necessary and has a bounded cross-runtime repair.

## What This Changes

Preserve media attachments when an inbound message is delivered into an active steer-mode agent run.

## Best Possible Solution

Extend the internal steering request to carry ordered typed image inputs for capable runtimes, retaining the existing full follow-up fallback when a runtime rejects or cannot represent the attachment payload.

Yes at source level: the active steering branch accepts only the prompt text and bypasses the image-bearing follow-up path, matching the supplied runtime trace. This read-only review did not execute a live current-main Telegram run.

## Solution Assessment

No for the proposed unconditional media-to-follow-up guard: it prevents loss but is narrower than the dependency contracts permit. The best fix is multimodal steering through the shared runtime boundary with tested fallback to the existing follow-up path.
