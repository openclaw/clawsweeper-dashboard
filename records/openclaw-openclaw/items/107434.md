## Label Justifications

- `P1`: A current shared channel workflow silently omits user-supplied images while accepting their captions, producing ungrounded replies for active runs.
- `impact:message-loss`: Inbound attachment content is staged and persisted but does not reach the model when the turn takes the active steering path.

## Summary

Keep this issue open: the supplied live trace and source analysis support a real shared-queue attachment-loss bug, while current queue documentation promises that unsteerable input waits for a later turn rather than being dropped. The exact repair should remain pending direct inspection of the bundled Codex `turn/steer` contract. ([docs.openclaw.ai](https://docs.openclaw.ai/tools/steer?utm_source=openai))

## What This Changes

Preserve attachments when media-bearing inbound turns arrive during an active run configured for steering.

## Best Possible Solution

Make attachment-bearing active turns follow-up eligible and non-steerable unless the active runtime contract can carry ordered attachment bytes, then cover one- and multi-image ordering through queue admission and model-input compilation.
