## Label Justifications

- `P1`: Every embedding or memory request against a stopped on-demand local provider fails until an operator manually starts the service, breaking an established provider workflow.
- `impact:auth-provider`: The issue affects exact provider-alias routing and lifecycle acquisition for configured local embedding endpoints.

## Summary

Current main does not apply configured provider `localService` lifecycle management to embedding HTTP requests, while model requests already use the canonical host-owned manager. The issue is valid, aligned with repository direction, newly filed and assigned, and protected by maintainer authorship and labeling, so it should remain open for its owner-led implementation.

## What This Changes

Apply configured provider-owned local-service startup and lease management to embedding HTTP requests as well as chat/model requests.

## Best Possible Solution

Add a minimal host-injected acquisition function to embedding creation, resolve lifecycle configuration from the exact configured provider alias, and wrap each remote embedding operation with the canonical manager’s independent lease while preserving shared startup serialization and cleanup semantics.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: model transports recognize and acquire configured `localService`, while the embedding creation contract and caller expose no equivalent acquisition path. This read-only review did not run a live stopped-server scenario.

## Solution Assessment

Yes. A narrow host-injected acquisition hook is the best maintainable shape because it reuses the single lifecycle owner, preserves exact configured aliases, and avoids exposing core process management or duplicating it inside provider plugins.
