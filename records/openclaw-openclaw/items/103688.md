## Summary

The explicit restart boundary and live proof are convincing, but the exact head still attaches eviction tracking to a generic module loader that also loads shared OpenClaw runtime code. This can clear a non-plugin module graph while secondary plugin entrypoints remain tracked without their full package root, so the PR needs one focused ownership repair before merge.

## What This Changes

The PR clears plugin loader, manifest, activated runtime, and tracked native module caches during in-process gateway restarts and adds regression coverage for workspace-plugin entrypoint and nested-dependency reloads.

## Best Possible Solution

Move restart tracking out of the generic loader and record only plugin-owned main, setup, runtime, and CLI entrypoints at owner-aware call sites with each discovered plugin root; exclude the shared OpenClaw runtime module and add a split-entry dependency regression.
