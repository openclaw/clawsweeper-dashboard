## Summary

Keep open: this PR is not merge-ready because it changes the synthetic merge message `timestamp` field, but the final compaction merge prompt serializes only message content, so the LLM still cannot see chunk chronology. The linked issue remains valid, and the stronger path is to make chunk order/source range model-visible before merge.

## What This Changes

The PR changes staged compaction merge messages to copy each chunk's first numeric timestamp and adds a regression test around the merge-call inputs.

## Best Possible Solution

Put deterministic chunk order and source time-range metadata into the merge message content or serialization path, then test the final prompt text and provide real after-fix compaction proof.

No. Preserving `AgentMessage.timestamp` alone is not the best fix because the merge LLM sees serialized text, so chunk order/source range must become model-visible.
