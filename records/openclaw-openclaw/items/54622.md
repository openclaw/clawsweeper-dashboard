## Summary

Keep open: current main still only logs lane-wait facts internally and does not surface a structured session-lane busy result to the Gateway-backed CLI. The linked candidate fix is still open and draft, so this issue remains the canonical tracker until that PR lands or is replaced.

## What This Changes

The issue requests that `openclaw agent --agent <id> --message ...` print an actionable session-lane busy or timeout error instead of exiting silently when the session lane is blocked.

## Best Possible Solution

Resolve this through https://github.com/openclaw/openclaw/pull/90933 or a narrow replacement that propagates existing queue wait facts through Gateway to CLI text/JSON output, preserves non-CLI behavior, and tests ordinary plus admin-authority CLI paths.

## Reproduction Assessment

Yes, at source level: current main logs lane-wait facts in the command queue while the Gateway-backed CLI response type and renderer have no structured lane-busy result. I did not run the live two-terminal CLI timing scenario in this read-only review.

## Solution Assessment

Yes on the owner boundary, but the exact terminal busy contract needs maintainer judgment. The maintainable fix is to carry existing queue wait facts through Gateway to CLI output while preserving non-CLI delivery semantics.
