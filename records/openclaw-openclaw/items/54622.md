Rationale: The bug fix is clear, but the user-visible behavior affects operator scripts: stderr text, JSON error shape, and whether lane-busy uses exit code 1 or a distinct temporary-failure code need maintainer intent before the linked PR lands.

Owner confidence: high

Options:

- **Distinct busy result (recommended):** Return a structured `LANE_WAIT_EXCEEDED` result with actionable stderr/JSON and a stable distinct non-1 exit code for automation.
- **Message-only compatibility:** Surface an actionable stderr/JSON error but keep exit code 1 to minimize shell-script compatibility risk.
- **No terminal busy result:** Reject fail-fast busy behavior and limit the fix to better diagnostics/timeouts, leaving same-session dispatch semantics unchanged.
