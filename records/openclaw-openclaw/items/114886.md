## Summary

Keep open. This is a narrowly described Tlon shutdown bug: an abort that lands during asynchronous monitor startup can leave the monitor waiting for an abort event that has already occurred, bypassing its cleanup path. The related SSE reconnect PR addresses a different shutdown wait and is not a replacement for this work.

## What This Changes

Ensure the Tlon channel monitor settles and runs cleanup when the gateway abort signal fires before monitor startup has registered its abort listener.

## System Context

The gateway starts configured channel accounts and passes its lifecycle abort signal into each channel monitor. Tlon performs connection and subscription startup before it waits for that signal; once the monitor settles, its cleanup closes the Urbit API client and ingress processing.

## Architecture Diagram

flowchart TD
  A[Gateway account startup] --> B[Tlon monitor startup]
  B --> C[Invite, subscription, and API connection]
  A --> D[Gateway abort signal]
  D --> E{Abort observed by monitor?}
  C --> E
  E -->|Yes| F[Monitor settles]
  F --> G[Stop ingress and close API]
  E -->|Late listener without guard| H[Monitor remains pending]

## Best Possible Solution

Use the existing abort-aware lifecycle primitive, or an equivalent single guarded wait, at the Tlon monitor boundary; add a deterministic regression test that verifies the startup-race abort reaches the existing finally cleanup without changing reconnect policy.
