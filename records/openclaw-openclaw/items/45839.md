## Summary

Keep open: current main and the latest release still render pairing approvals as text commands, while Telegram callback handling covers exec/plugin/generic callbacks but not pairing approve/deny; the remaining work needs a security/product decision.

## What This Changes

The issue requests Telegram inline Approve and Deny buttons for pairing notifications so operators do not have to paste pairing approval commands manually.

## Best Possible Solution

Add a typed, replay-safe pairing/device approval action that renders as Telegram buttons while keeping the durable pairing store and existing approval-time scope checks authoritative.
