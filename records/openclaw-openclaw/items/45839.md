## Summary

Keep open: current main and v2026.6.11 still use command-text pairing approval paths, while Telegram native callbacks cover exec/plugin/generic interactions but not pairing approve/deny; the remaining work needs explicit security/product direction.

## What This Changes

Add Telegram inline Approve/Deny buttons for pairing and device-pair notifications so operators do not have to copy command text or use the CLI.

## Best Possible Solution

Add typed, single-use pairing/device approval actions that render as Telegram buttons while preserving the durable pairing store and existing approval-time scope checks as the source of truth.
