## Summary

Keep open: current main and v2026.6.11 still expose pairing approvals through command text, while Telegram inline callbacks cover generic/plugin/exec paths but not a typed pairing approve/deny action. The remaining work is security-sensitive and needs maintainer direction before an implementation PR is safe.

## What This Changes

The issue asks for Telegram inline approve/deny buttons for pairing notifications instead of requiring operators to paste pairing CLI commands.

## Best Possible Solution

Define typed, replay-safe pairing and device-approval actions rendered by Telegram buttons while keeping existing pairing stores and Gateway approval-time scope checks authoritative.
