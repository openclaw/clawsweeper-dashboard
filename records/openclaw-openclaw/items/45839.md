## Summary

Keep open: current main and the latest release still render pairing approvals as text commands, while Telegram inline callback handling covers exec/plugin/generic callbacks but not pairing approve/deny; the remaining work needs an explicit security/product decision.

## What This Changes

The issue requests Telegram inline Approve/Deny buttons on pairing approval notifications so operators do not have to copy and run CLI approval commands.

## Best Possible Solution

Add a typed, replay-safe pairing/device approval action that renders as Telegram buttons while keeping the durable pairing store and existing approval-time scope checks authoritative.
