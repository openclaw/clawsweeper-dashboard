## Summary

Keep open: current main and latest release still rely on command-text pairing approval, while Telegram callbacks support exec/plugin/native interactions but not pairing approve/deny. The remaining work is useful, but it changes an access-approval boundary and needs maintainer security/product direction before a fix PR.

## What This Changes

The issue requests Telegram Approve/Deny inline buttons for pairing approval instead of requiring operators to copy CLI or slash commands.

## Best Possible Solution

Add typed, single-use pairing/device approval actions that render as Telegram buttons while preserving the durable pairing store and existing approval-time scope checks as the source of truth.
