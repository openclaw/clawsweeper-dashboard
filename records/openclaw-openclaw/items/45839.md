## Summary

Keep open: current main still renders Telegram chat/device pairing approvals as text commands, while existing Telegram inline-button handling covers exec/plugin/generic callbacks but not pairing; the remaining click-to-approve path needs a security and product decision.

## What This Changes

Request Telegram inline Approve/Deny buttons for pairing notifications so operators can approve or reject pairing requests without pasting CLI or /pair commands.

## Best Possible Solution

Define a typed, replay-safe pairing/device-approval action rendered as Telegram inline buttons while keeping the existing pairing stores and Gateway approval-time scope checks authoritative.

## Reproduction Assessment

Yes, source-level: current main sends Telegram pairing and device-pair approval instructions as command text, and the Telegram callback handler has no pairing approve/deny branch; no live Telegram scenario was run.

## Solution Assessment

Unclear: inline buttons are the desired UX, but the best fix needs typed callback/action semantics with explicit owner authorization, approval scopes, expiry, replay/idempotency, denial, and first-owner bootstrap behavior.
