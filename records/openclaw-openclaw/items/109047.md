## Summary

The PR remains necessary: current main still clears the request timer when fetch resolves at headers, while this branch extends the deadline through response-body consumption. The implementation follows the affected production path, prior review found no correctness defects, and the added live HTTP-server proof directly exercises stalled, slow-drip, and successful bodies; it should remain open for normal exact-head checks and Signal-area maintainer review.

## What This Changes

Keeps Signal container REST request deadlines active through JSON, error, and attachment response-body consumption and adds unit plus live HTTP-server regression coverage.

## Best Possible Solution

Use one request-owned deadline across fetch and every response-body read, retain the idle chunk timeout as a secondary stall guard, cancel the body on deadline expiry, and land with the focused unit and live-server coverage green.

## Reproduction Assessment

Yes. A live HTTP server can return headers and drip bytes every 50 ms—faster than the idle guard—so current main remains active beyond the total request deadline; the added production-path test reproduces that condition with real sockets and timers.

## Solution Assessment

Yes. Keeping one AbortController owned by the complete request and racing all body consumption against it is narrower and more consistent than adding another timer or changing the existing idle-stall semantics.
