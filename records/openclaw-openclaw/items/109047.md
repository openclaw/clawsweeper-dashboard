## Summary

Keep this PR open: current main still releases the Signal REST timer when fetch returns headers, and the proposed request-wide deadline appears to address that gap cleanly, but the external PR provides only focused mocked Vitest output rather than after-fix proof through a real streaming HTTP/undici or signal-cli-rest-api path.

## What This Changes

The PR keeps the Signal container REST deadline active through response-body consumption, cancels timed-out bodies, races body reads against abort, and adds slow-drip timeout tests.

## Best Possible Solution

Keep the request-wide deadline design, then demonstrate through the production Signal container path or a real chunked HTTP/undici stream that an over-deadline drip fails near timeoutMs while an in-budget drip and attachment download still complete normally.

## Reproduction Assessment

Yes at source level: a response that returns headers and continuously drips chunks can outlive the current timer because it is cleared when fetch resolves. The PR adds a deterministic mocked reproduction, but this review did not establish the failure through a live container or real network stream.

## Solution Assessment

Yes in design: one deadline spanning fetch and body consumption is narrower and more maintainable than relying only on a resettable idle-chunk timeout. Merge readiness still requires real-stream proof of the production abort behavior.
