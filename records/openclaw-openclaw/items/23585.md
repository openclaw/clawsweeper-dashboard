## Summary

Keep open. Current main still has no trusted-proxy default/fallback identity for real proxied requests with a missing identity header, and adding one would change a security-sensitive auth boundary that needs maintainer approval.

## What This Changes

The issue requests a trusted-proxy fallback/default user identity when the configured identity header is absent on WebSocket connections.

## Best Possible Solution

Keep trusted-proxy identity validation fail-closed by default unless maintainers approve a narrow explicit single-principal fallback mode with config, schema, docs, audit guidance, loopback/source/header rules, allowlist semantics, and regression coverage.

Rationale: The code change is mechanically bounded, but it changes the trusted-proxy auth boundary from requiring per-request identity evidence to allowing a configured principal based on proxy-source trust.

Likely owner: vincentkoc

Owner confidence: high

Options:

- **Approve narrow fallback mode (recommended):** Add a default-off single-principal fallback with config/schema/docs/audit/test coverage for source, loopback, required-header, origin, and allowlist semantics.
- **Keep fail-closed identity headers:** Reject headerless trusted-proxy identity and document Cloudflare Zero Trust IP-whitelist/no-identity WebSocket setups as unsupported for this auth mode.
- **Require live Cloudflare proof first:** Ask for a reproducible Cloudflare Tunnel/WebSocket proof before accepting new OpenClaw auth surface.

## Reproduction Assessment

Yes for the OpenClaw source path: current main deterministically rejects trusted-proxy requests without the configured identity header, and a focused test asserts `trusted_proxy_user_missing`. I did not live-reproduce Cloudflare's WebSocket header stripping.

## Solution Assessment

Unclear pending maintainer/security approval. The requested `defaultUser`/`fallbackUser` option is mechanically plausible, but it changes the trusted-proxy trust model; the safer baseline is fail-closed identity headers unless a narrow single-principal mode is explicitly accepted.
