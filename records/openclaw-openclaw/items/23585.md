## Summary

Keep open. Current main and the latest release still reject trusted-proxy requests when the configured identity header is absent, and adding a fallback identity would change a security-sensitive auth boundary that needs maintainer/security approval.

## What This Changes

The issue requests an explicit trusted-proxy fallback/default identity config for headerless requests from configured trusted proxy sources.

## Best Possible Solution

Keep trusted-proxy identity validation fail-closed by default unless maintainers approve a narrow explicit single-principal fallback mode with schema, docs, audit guidance, loopback/source/header rules, allowlist semantics, and regression coverage.

Rationale: The code change is mechanically clear, but it changes the trusted-proxy auth boundary from per-request identity evidence to proxy-source plus configured principal, which automation should not decide.

Options:

- **Approve narrow fallback mode (recommended):** Add an explicit single-principal fallback config with fail-closed defaults, audit/docs/schema updates, and tests for proxy source, loopback, required headers, and allowlist semantics.
- **Keep fail-closed:** Reject headerless trusted-proxy identity and document Cloudflare Zero Trust IP-whitelist or no-identity WebSocket setups as unsupported for trusted-proxy auth.
- **Require live proxy proof first:** Ask for a reproducible Cloudflare Tunnel proof before deciding whether OpenClaw should add a fallback identity surface.

## Reproduction Assessment

Yes for the OpenClaw source path: current main deterministically rejects trusted-proxy requests without the configured identity header, and a focused test asserts `trusted_proxy_user_missing`. I did not live-reproduce Cloudflare's WebSocket header stripping.

## Solution Assessment

Unclear pending maintainer/security approval. The requested `defaultUser` or `fallbackUser` option is plausible, but it changes the trusted-proxy trust model; the safer baseline is fail-closed identity headers unless a narrow single-principal mode is explicitly accepted.
