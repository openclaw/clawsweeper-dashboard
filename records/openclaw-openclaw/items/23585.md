## Summary

Keep open. Current main and the latest release still fail closed when a real trusted-proxy request lacks the configured identity header, and adding a fallback identity is a new security-sensitive auth/config surface that needs maintainer approval.

## What This Changes

The issue requests a trusted-proxy `defaultUser` or `fallbackUser` config option so requests from trusted proxy sources can authenticate when the identity header is absent.

## Best Possible Solution

Keep trusted-proxy identity validation fail-closed by default unless maintainers approve a narrow explicit single-principal fallback mode with config, schema, docs, audit guidance, loopback/source/header rules, allowlist semantics, and regression coverage.

- **Require Live Cloudflare Proof First:** Ask for a reproducible Cloudflare Tunnel proof before deciding whether OpenClaw should add a fallback identity surface.
