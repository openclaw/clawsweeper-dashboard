## Summary

Keep open. Current main still rejects trusted-proxy requests when the configured identity header is absent, and adding a fallback/default identity would change a security-sensitive auth boundary that needs maintainer/security approval.

## What This Changes

Requests a trusted-proxy default or fallback user option for real proxy requests whose identity header is missing, especially Cloudflare WebSocket upgrade paths.

## Best Possible Solution

Keep trusted-proxy identity validation fail-closed by default unless maintainers approve a narrow explicit single-principal fallback mode with config, schema, docs, audit guidance, source/loopback/header rules, allowlist semantics, and regression coverage.

## Reproduction Assessment

Yes for the OpenClaw source path: current main deterministically rejects a trusted-proxy request without the configured identity header, and a focused test asserts trusted_proxy_user_missing. I did not live-reproduce Cloudflare's WebSocket header stripping.

## Solution Assessment

Unclear pending maintainer/security approval. The requested defaultUser/fallbackUser is mechanically plausible, but it changes the trusted-proxy trust model; safer defaults are fail-closed identity headers, a documented alternate auth path, or a maintainer-approved single-principal mode.
