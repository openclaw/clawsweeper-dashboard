## Summary

Keep open: current main and v2026.6.11 still require bundled or trusted official install provenance for keyed state, and there is no supported immutable-container path that keeps an official plugin package plus install record visible when the active OpenClaw home is mounted. The related open PR only covers the narrower ClawHub npmSpec trust mismatch, not this self-hosted/load-path provisioning contract.

## What This Changes

The issue requests a supported immutable/container deployment path for official external channel plugins such as Microsoft Teams to retain trusted keyed-store provenance outside a mutable mounted OpenClaw home.

## Best Possible Solution

Keep the fail-closed trust gate and add a maintainer-approved immutable official-plugin provenance path that stores or verifies package plus install record outside the mutable runtime mount, with Docker docs and targeted upgrade proof.

Question: What provenance and storage contract should official external plugins use in immutable/container deployments where the active OpenClaw home is mounted over image-baked state?

Rationale: The source confirms the runtime can only safely grant keyed-store access from trusted install provenance, but current Docker/state layout gives no supported way to preserve that provenance for image-baked official plugins.

Likely owner: hxy91819

Owner confidence: high

Options:

- **Add immutable official plugin provenance (recommended):** Support a build-time official install root or importable signed install record that runtime verifies against the official catalog while keeping raw load paths untrusted.
- **Document mounted-state installs only:** Keep the current security boundary unchanged and document that self-hosted operators must install official plugins into the mounted OpenClaw state before runtime starts.
- **Accept explicit operator trust:** Add an operator allowlist or trusted flag that bypasses provenance for configured plugin paths, accepting a broader security tradeoff.

## Reproduction Assessment

Yes at source level: a config/load-path official plugin without matching install-record provenance remains untrusted, and Microsoft Teams opens keyed stores during startup; live ECS/Fargate reproduction was not run in this read-only review.

## Solution Assessment

No current implementation is sufficient; the best fix is a provenance-preserving immutable official plugin install path, not raw path trust or a hard-coded channel-specific bypass.
