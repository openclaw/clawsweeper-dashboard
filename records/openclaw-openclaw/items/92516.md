## Summary

Keep open: current main and the latest release still enforce the trusted-plugin keyed-store gate, and this issue has narrowed to a security/product decision about a provenance-preserving immutable-container install path rather than raw load-path trust.

## What This Changes

The issue asks OpenClaw to support containerized/self-hosted official external channel plugins whose package and install provenance can survive a mounted mutable state directory.

## Best Possible Solution

Define a provenance-preserving container install contract: official plugin package plus install record can live in an immutable runtime plugin root separate from mutable state, while unproven load paths continue to fail closed.

Yes. Source inspection shows a load-path/configured external plugin without a matching trusted official install record fails the `openKeyedStore` gate, and the latest release carries the same condition.
