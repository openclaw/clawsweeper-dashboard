## Summary

Keep open: current main still has no supported provenance-preserving path for image-baked external channel plugins when the active state directory is mounted over the build-time install record, and the recent discussion narrowed this to a security/product decision rather than raw load-path trust.

## What This Changes

The issue requests a supported self-hosted container deployment path for official external channel plugins that need trusted keyed state while preserving plugin provenance.

## Best Possible Solution

Add a provenance-preserving immutable official plugin install/runtime-root contract, with doctor/docs/CLI coverage, while keeping arbitrary load-path and spoofed package installs denied.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw support an immutable self-hosted official-plugin install root, or equivalent package-plus-install-record contract, so mounted state directories can use trusted official channel plugins without trusting arbitrary load paths?

Rationale: The fix decides where trusted install provenance may live and which external channel packages receive host-managed persistent state access, so automation should not choose this security boundary or product shape.

Likely owner: hxy91819

Owner reason: They are assigned, already stated the intended fail-closed trust model on this issue, and have recent adjacent plugin trust-boundary history.

Owner confidence: high

Options:

- **Approve Immutable Provenance Path (recommended):** Add a narrow official-install contract that preserves package identity, install record, resolved path, and official catalog checks outside the mounted state-dir conflict.
- **Document Unsupported For Now:** Keep the fail-closed model and explicitly document that image-baked load-path official channel plugins cannot use trusted keyed state when their install record is hidden.
- **Fold Into Broader Plugin State Design:** Defer this until the community keyed-state and official external-plugin trust model are designed together.

## Reproduction Assessment

Yes at source level: current main rejects keyed state for non-bundled plugins without trusted official-install provenance, install records live under the active state directory, and Microsoft Teams opens keyed state during startup. I did not run the full ECS/EFS container reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the trust model. The issue's narrowed immutable provenance path is more maintainable than raw trust config or implicit load-path trust, but it still needs a security-boundary decision.
