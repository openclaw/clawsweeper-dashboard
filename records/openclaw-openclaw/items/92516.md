## Label Justifications

- `P1`: The issue blocks official externalized channel use in self-hosted containers with a channel crash loop while touching the trusted-plugin state boundary.
- `impact:security`: The requested fix changes how OpenClaw proves an external plugin may access host-managed keyed state and channel ingress APIs.
- `impact:crash-loop`: The reported Microsoft Teams channel exits after the trusted-state gate denies access and then auto-restarts repeatedly.

## Summary

Keep open: current main still gates keyed state and channel ingress to bundled or trusted-official installs, while the reported immutable-container path masks the install record needed to grant trust. This is not solved by the narrower ClawHub npmSpec work and still needs a maintainer security/product decision.

## What This Changes

Request a supported self-hosted container path for official externalized channel plugins to retain trusted provenance and run keyed-state-backed channels without crash loops.

## Best Possible Solution

Keep the fail-closed trust gate and design a supported immutable-container official plugin install/provenance path where package identity and install records remain verifiable while mutable config/state can still be mounted.

## Maintainer Decision

Required: true

Question: Should OpenClaw support a provenance-preserving immutable-container official plugin root/install-record contract for external channel plugins, and where should that record live relative to mounted runtime state?

Rationale: The source path is clear, but the repair decides which external plugin code receives trusted host-managed keyed state and ingress capabilities, so automation should not choose the trust boundary or storage contract.

Options:

- **Approve Immutable Official Plugin Root (recommended):** Keep raw load paths untrusted, but add a documented build-time install/provenance root that survives mounted runtime config/state and is checked against official package identity.
- **Document Mounted-Home Requirement Only:** Keep the current model and document that trusted official plugins must be installed into the same mounted OpenClaw home used by the runtime container.
- **Defer To Broader Trust Policy:** Hold this issue until maintainers decide the combined policy for ClawHub, self-hosted/load-path, workspace-origin, and community keyed-state access.

## Reproduction Assessment

Yes, at source level: a non-bundled load-path channel without trustedOfficialInstall still hits the runtime state gate, and Microsoft Teams opens keyed stores during startup. I did not run the ECS/Fargate container reproduction in this read-only review.

## Solution Assessment

No to raw trust allowlists or implicit load-path trust; those collapse source provenance into operator intent. The best fix is a provenance-preserving official install/deployment contract that keeps arbitrary copied packages untrusted.
