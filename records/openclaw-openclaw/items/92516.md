## Summary

Keep open: current main and v2026.6.11 still require bundled origin or trusted official install provenance for keyed state, while the live thread has narrowed the ask to a provenance-preserving immutable-container deployment path rather than raw load-path trust.

## What This Changes

The issue requests a supported self-hosted/container deployment path for externalized official channel plugins that need trusted keyed state without losing install provenance behind mounted runtime state.

## Best Possible Solution

Keep the fail-closed gate and design a provenance-preserving official plugin package/install-record root or equivalent deployment contract that survives mounted runtime state/config.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw add a provenance-preserving immutable official plugin package/install-record root or equivalent self-hosted container deployment contract while continuing to deny raw load-path/config trust?

Rationale: The choice decides which external channel plugins receive trusted host-managed state and ingress capabilities and likely changes install, config, state, and container provisioning contracts.

Likely owner: hxy91819

Owner confidence: high

Options:

- **Approve Immutable Official Provenance Root (recommended):** Define a supported build-time official install/provenance path outside mutable runtime state and require tests plus container proof that raw load-path packages remain denied.
- **Document Build-Time State Coupling:** Document that self-hosted images must ship and mount the same OpenClaw state containing the package and install record, then close this as not planned.
- **Defer To Broader Keyed-State Model:** Hold this issue behind the broader community/plugin keyed-state capability decision, accepting that official self-hosted channel deployments remain blocked meanwhile.

## Reproduction Assessment

Yes, at source level: a non-bundled external channel without trusted official-install metadata still throws when it opens keyed state, and Teams opens keyed state during startup.

## Solution Assessment

No to the raw trust shortcuts in the original option list; the best path is a maintainer-approved provenance-preserving deployment contract that keeps arbitrary load paths denied.
