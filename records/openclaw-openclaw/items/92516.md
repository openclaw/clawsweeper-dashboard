## Summary

Keep open: current main and latest release still fail closed for image-baked or load-path official channel plugins without trusted install-record provenance, and the remaining ask is a security/product decision rather than a duplicate of the narrower ClawHub npmSpec fix.

## What This Changes

Request a supported self-hosted/container deployment path for official external channel plugins that need trusted keyed state and headless provisioning.

## Best Possible Solution

Keep the fail-closed trust gate and design a supported immutable official-plugin package/provenance path that survives mounted mutable state, with doctor/docs and container proof.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw add a provenance-preserving immutable official plugin install root or record path for self-hosted containers whose mutable state directory is mounted?

Rationale: Automation cannot choose which externally supplied plugin roots should receive trusted keyed-state and ingress APIs without maintainer security intent.

Likely owner: hxy91819

Owner reason: hxy91819 is the current assignee and has already framed the issue in terms of the intended plugin trust model.

Owner confidence: high

Options:

- **Design immutable official provenance (recommended):** Add a supported official package plus install-record path outside the mutable state mount while keeping raw load paths and config trust flags untrusted.
- **Document current limitation:** Keep the current fail-closed model and document that runtime containers must use the same state directory snapshot created by the installer.
- **Ship official bundled images:** Avoid a general trust-root change by publishing image variants that bundle common official channel plugins under maintainer-controlled provenance.

## Reproduction Assessment

Yes at source level: a non-bundled external channel without trusted official-install metadata will throw when it opens keyed state, and Microsoft Teams opens keyed stores during runtime.

## Solution Assessment

No to raw trust allowlists or implicit load-path trust; the maintainable path is a provenance-preserving official plugin deployment contract chosen by maintainers.
