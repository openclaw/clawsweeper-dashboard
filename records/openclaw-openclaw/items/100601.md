## Summary

Keep open: the follow-up is still useful because current main does not protect the shared PortGuardian record store from cross-instance clobbering, but this PR is not merge-ready while the new locked write path can proceed after a failed `flock`.

## What This Changes

The PR refactors macOS PortGuardian tunnel record persistence into a shared locked read-merge-write path, switches to per-process owned records, unifies tunnel teardown/termination, and updates focused tests plus native string inventory.

## Best Possible Solution

Require the exclusive file lock before any `port-guard.json` mutation, keep the existing record schema and narrow process-kill gates, and add real or focused concurrency proof that sibling app records survive.

No. A single locked write path is the right owner-boundary fix, but the implementation must enforce lock acquisition before it can reliably solve cross-instance record loss.
