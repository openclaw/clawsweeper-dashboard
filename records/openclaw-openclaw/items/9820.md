## Summary

Keep open. Current main and the latest release still do not support arbitrary JSONL files through builtin memorySearch.extraPaths; the remaining blocker is a maintainer product/security decision about whether raw message logs belong in builtin memory indexing or in QMD/session-memory/converter/plugin workflows.

## What This Changes

This issue requests native JSONL support for memorySearch.extraPaths so raw message-hook logs can be indexed for semantic search without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
