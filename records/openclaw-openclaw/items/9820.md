- `impact:session-state`: The request changes what message/session-like JSONL history can become searchable long-term memory.

## Summary

Keep open. Current main and v2026.6.11 still keep builtin memory extra-path ingestion Markdown/multimodal-oriented, while JSONL parsing is limited to opt-in session transcript memory; maintainers still need to decide whether arbitrary raw JSONL logs belong in builtin memorySearch.extraPaths.

## What This Changes

The issue requests native JSONL support for memorySearch.extraPaths discovery, indexing, watching, and memory_get.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
