## Summary

Keep open. Current main still excludes arbitrary JSONL files from builtin memory extra-path discovery, memory_get, and watcher handling; the existing session-transcript JSONL path is separate, so this remains a product and security decision rather than implemented behavior.

## What This Changes

The issue asks for builtin memory extra-path indexing to support JSONL raw message logs without converting them to Markdown first.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow.
