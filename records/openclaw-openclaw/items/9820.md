## Summary

Keep open. Current main and v2026.6.11 still scope builtin memory extra paths to Markdown plus enabled multimodal files, while the existing JSONL support is limited to session transcript indexing; the remaining blocker is a product/security decision about whether arbitrary raw logs belong in builtin memory ingestion.

## What This Changes

Request native JSONL ingestion for builtin memorySearch.extraPaths so raw message logs can be indexed for semantic memory search.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
