## Label Justifications

- `P2`: This is a bounded memory-search capability request with meaningful but non-emergency impact and an unresolved design boundary.
- `impact:session-state`: The requested path would make raw conversation-log records available to memory search and therefore changes what session-derived state can be recalled.
- `impact:security`: The requested canonical raw-message-log workflow could index sensitive message content or metadata unless searchable fields and privacy controls are explicitly defined.

## Summary

Keep open: current main still excludes arbitrary JSONL files from builtin memory extra paths, while the requested raw-message-log ingestion needs a maintainer decision on the supported data, privacy, and ownership boundary before a safe implementation can be scoped.

## What This Changes

Add native JSONL discovery, indexing, and retrieval support for builtin `memorySearch.extraPaths` so line-delimited message logs can be searched without conversion to Markdown.

## Best Possible Solution

Choose whether raw JSONL ingestion belongs in an external memory plugin or the builtin memory contract; if builtin, implement one explicit JSONL record-to-search-text policy consistently across admission, watching, indexing, retrieval, docs, and focused tests.
