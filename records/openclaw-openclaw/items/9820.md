## Summary

Keep open. Current main and v2026.6.11 still keep builtin memory extra-path ingestion Markdown/multimodal-oriented; JSONL support exists only for the separate session-transcript source path, and maintainers still need to decide whether arbitrary raw log ingestion belongs in builtin memorySearch.extraPaths.

## What This Changes

Request native JSONL ingestion for builtin memorySearch.extraPaths so raw message-log files can be indexed without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
