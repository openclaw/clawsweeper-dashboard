## Summary

Keep open. Current main and v2026.6.11 still restrict builtin memory extra paths to Markdown plus enabled multimodal files; arbitrary JSONL ingestion remains a product/security decision, not an already-implemented cleanup.

## What This Changes

The issue requests native JSONL ingestion for builtin memorySearch.extraPaths so raw message logs can be indexed without a converter.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow.
