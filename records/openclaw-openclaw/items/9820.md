## Label Justifications

- `P2`: This is a useful but non-blocking memory capability request with an available JSONL-to-Markdown conversion workaround.
- `impact:session-state`: The feature would make raw conversation-derived records part of searchable agent memory.
- `impact:security`: Raw message logs may contain private messages, tool output, credentials, and cross-session data requiring explicit indexing and retrieval boundaries.

## Summary

Current main and v2026.6.11 still limit builtin memory extra paths to Markdown; JSONL transcript indexing remains a separate opt-in path with dedicated sanitization and visibility controls. The request is still necessary, but maintainers must decide whether arbitrary structured logs belong in builtin memory and define the security contract before implementation.

## What This Changes

Add native JSONL ingestion for files configured through builtin memory extra paths.

## Best Possible Solution

Keep builtin durable memory Markdown-focused unless maintainers approve a typed structured-log source that parses an explicit schema, sanitizes content, preserves line and source identity, enforces retrieval visibility, and works consistently across discovery, indexing, watching, retrieval, configuration help, documentation, and tests.

Rationale: The existing product separates curated Markdown memory from opt-in, sanitized, visibility-filtered session transcripts; accepting arbitrary JSONL requires a schema and privacy contract that source inspection cannot choose.

Owner confidence: high

Options:

- **Keep builtin Markdown-focused (recommended):** Document the converter and session-memory paths, and direct custom structured-log schemas to a plugin.
- **Approve typed JSONL ingestion:** Define one supported record schema and privacy model, then add complete ingestion and retrieval support without accepting arbitrary unknown JSONL records.

## Reproduction Assessment

Yes at the source and documented-contract level: a .jsonl file under memorySearch.extraPaths falls outside the documented .md scan set, while transcript JSONL requires the separate session-memory source. A live runtime run was not needed to establish this intentional capability gap.

## Solution Assessment

No. Adding .jsonl to an extension allowlist and chunking each raw line is insufficient because it bypasses schema validation, sanitization, source identity, visibility rules, retrieval support, and watcher/index consistency.
