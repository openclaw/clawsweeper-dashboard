## Summary

Keep open. Current main and v2026.6.11 still exclude ordinary JSONL files from builtin memory extra paths; session-transcript JSONL is a separate specialized path, and no canonical issue or viable PR owns arbitrary structured-log ingestion. The request remains useful but needs a maintainer product and security decision before implementation.

## What This Changes

Add native JSONL ingestion to builtin memory search extra paths so structured message-hook logs can be indexed and semantically searched without Markdown conversion.

## Best Possible Solution

Choose one explicit ownership model: either add a bounded, schema-aware JSONL importer across discovery, parsing, line mapping, watching, retrieval, tests, and privacy documentation, or keep builtin extra paths Markdown-only and document a converter, QMD, or plugin workflow for raw structured logs.
