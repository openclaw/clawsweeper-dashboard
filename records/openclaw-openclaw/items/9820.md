## Summary

Keep open. Current main and v2026.6.11 still do not implement arbitrary JSONL ingestion for builtin memorySearch.extraPaths; this remains a feature request with a product and security boundary decision rather than an implemented behavior.

## What This Changes

Request native JSONL support in builtin memorySearch.extraPaths so raw message logs can be discovered, line-chunked, indexed, watched, searched, and read without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow.
