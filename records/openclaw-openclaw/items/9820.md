## Summary

Keep open. Current main and v2026.6.11 still exclude arbitrary JSONL files from builtin memorySearch.extraPaths discovery, memory_get, and watcher filtering; the gap is source-reproducible, but widening raw-log ingestion needs a product and security decision.

## What This Changes

Request native JSONL support in the builtin memory indexer so raw message logs in memorySearch.extraPaths can be indexed without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow.

## Solution Assessment
