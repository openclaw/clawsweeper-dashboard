## Summary

Keep open. Current main still does not support native JSONL ingestion for builtin `memorySearch.extraPaths`, and the remaining choice is whether raw log recall belongs in builtin memory or in QMD/session-memory/plugin surfaces.

## What This Changes

Request native JSONL support in the memory indexer so raw message logs under `memorySearch.extraPaths` can be semantically searched without converting them to Markdown.

## Best Possible Solution

Maintainers should decide the memory product boundary first; if accepted, implement JSONL admission, line-aware parsing/chunking, watcher support, memory_get behavior, docs, and security-focused tests together, otherwise document the QMD/session-memory or ClawHub plugin path.
