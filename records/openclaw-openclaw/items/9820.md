## Summary

Keep open. Current main and v2026.6.11 still do not support arbitrary JSONL files in builtin memorySearch.extraPaths; the gap is source-reproducible, but broadening raw-log ingestion needs product and security direction before a fix PR.

## What This Changes

The issue requests native JSONL support for the builtin memory indexer so raw message-log files in memorySearch.extraPaths can be indexed without converting them to Markdown.

## Best Possible Solution

Keep builtin extraPaths Markdown/multimodal-only unless maintainers sponsor JSONL; either document the supported QMD/session-memory/converter/plugin workflow or implement first-class line-aware JSONL with read/watch/search tests, docs, and privacy guardrails.
