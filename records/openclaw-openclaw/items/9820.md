## Label Justifications

- `P2`: This is a normal-priority memory indexing feature gap with a workaround and no evidence of urgent runtime outage.
- `impact:session-state`: The request affects whether raw conversation logs can become searchable durable memory and later influence recalled context.
- `impact:security`: Indexing arbitrary JSONL logs can expose private message, tool, or operational fields to embedding storage and providers without a defined redaction contract.

## Summary

Keep open: current main and the latest release still exclude ordinary `.jsonl` files from builtin `memorySearch.extraPaths`, while the existing JSONL handling is limited to the separate sanitized session-transcript path. The request remains valid, but it needs maintainer product and security direction before implementation.

## What This Changes

Requested native JSONL support for memory indexing of `extraPaths` so raw message logs can be semantically searched without conversion.

## Best Possible Solution

Define one supported JSONL ingestion contract for extra paths, including parsing, line mapping, `memory_get`, watcher behavior, docs, tests, and redaction semantics, or document the QMD/session-memory/converter/plugin alternative as the intended path.

## Reproduction Assessment

Yes, at source level: current main still rejects ordinary `.jsonl` files from builtin extra-path discovery and `memory_get`, while watcher/indexing paths remain Markdown or enabled multimodal only. I did not run a live indexing command because this is a read-only review and the source path is sufficient.

## Solution Assessment

Unclear. The proposed extension-list change is not sufficient by itself; a maintainable fix needs a single contract for admission, JSONL parsing/chunking, line mapping, `memory_get`, watcher behavior, docs, tests, and redaction/security semantics.
