## Summary

Current main and v2026.6.11 still exclude ordinary JSONL from builtin memory extra paths. The existing JSONL implementation is intentionally limited to opt-in OpenClaw session transcripts, and no canonical replacement issue or viable PR owns arbitrary raw-log ingestion, so this issue remains necessary for a maintainer product and security decision.

## What This Changes

Requests native JSONL ingestion for builtin memory indexing of configured extra paths.

## Best Possible Solution

Choose one documented contract: either implement schema-aware, privacy-controlled JSONL ingestion across discovery, parsing, watching, retrieval, citations, docs, and tests, or explicitly keep arbitrary logs in a converter/plugin or QMD workflow while preserving builtin JSONL support for sanitized session transcripts.
