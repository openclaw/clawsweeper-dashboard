## Summary

Keep open. Current main still does not implement native JSONL support for builtin `memorySearch.extraPaths`; JSONL parsing exists for opt-in session transcript indexing, but arbitrary JSONL extra files remain outside the memory admission, read, watcher, and docs contract.

## What This Changes

The issue requests native JSONL ingestion for `memorySearch.extraPaths` so raw message hook logs can be indexed without a Markdown conversion step.

## Best Possible Solution

Keep this open until maintainers choose the product/security boundary: either implement native JSONL extraPath support across discovery, parsing, watcher, `memory_get`, docs, and tests, or document the supported session-memory/QMD/converter-plugin workflow and close by decision.
