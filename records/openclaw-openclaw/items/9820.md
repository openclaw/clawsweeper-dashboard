## Summary

Keep open. Current main and v2026.6.11 still limit builtin memory extra paths to Markdown plus enabled multimodal files, while JSONL handling is limited to session transcript indexing and needs a maintainer product/security decision before builtin raw-log ingestion expands.

## What This Changes

Request native JSONL support for memory indexer extra paths so raw message logs can be semantically indexed without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
