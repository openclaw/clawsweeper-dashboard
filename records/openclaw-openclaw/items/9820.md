## Summary

Keep open. Current main and the latest release still skip arbitrary `.jsonl` files in builtin `memorySearch.extraPaths` and `memory_get`; the existing session-transcript JSONL support is a separate opt-in session-memory path, so the remaining blocker is product/security scope rather than proof of the gap.

## What This Changes

Request native JSONL support in the memory indexer so raw message logs listed through `memorySearch.extraPaths` can be chunked and searched without a Markdown conversion step.

## Best Possible Solution

Have maintainers pick and document the product boundary: either add bounded JSONL ingestion for builtin `memorySearch.extraPaths` with redaction/scope tests, or document the QMD/session-memory/converter-plugin path.
