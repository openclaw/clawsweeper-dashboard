## Label Justifications

- `P2`: This is a normal-priority memory indexing feature gap with a workaround and no evidence of an urgent runtime outage.
- `impact:session-state`: The request affects whether raw conversation logs can become searchable durable memory and later retrieved context.
- `impact:security`: Indexing arbitrary raw JSONL logs can expose private message, tool, or operational fields to embedding storage and providers without a defined redaction contract.

## Summary

Current main still excludes arbitrary JSONL files from builtin memorySearch.extraPaths and memory_get, while session transcript JSONL indexing is a separate sanitized sessions-source path. This should stay open for maintainer product/security review rather than becoming an automated fix, because accepting raw JSONL logs changes what private log fields may be embedded, stored, or sent to a provider.

## What This Changes

Request native JSONL ingestion for builtin memory indexing so raw message log files in memorySearch.extraPaths can be searched without converting them to Markdown.

## Best Possible Solution

Define a safe JSONL extra-path ingestion contract, or document the supported QMD, session-memory, converter, or plugin alternative if arbitrary raw JSONL is out of builtin scope.

## Reproduction Assessment

Yes, at source level: configure memorySearch.extraPaths to a plain .jsonl file or a directory containing one, and current main excludes it from discovery, memory_get, and watcher-triggered indexing. I did not run a live indexing command because this is a read-only review and the source path is direct.

## Solution Assessment

Unclear. The proposed extension-list change is not enough; the maintainable fix needs one contract for admission, JSONL parsing/chunking, line mapping, memory_get, watcher behavior, docs, tests, and redaction/security semantics.
