## Summary

Keep open. Current main and the latest release still keep builtin memory extraPaths to Markdown plus enabled multimodal files, while arbitrary JSONL support remains limited to the separate opt-in session-transcript path and needs an explicit product/security decision.

## What This Changes

The issue requests native JSONL ingestion for builtin memorySearch.extraPaths so raw message logs can be indexed and searched without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement first-class line-aware JSONL support across builtin discovery, parsing, indexing, watching, `memory_get`, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
