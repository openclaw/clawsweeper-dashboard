## Summary

Keep open: current main and the latest release still do not support arbitrary JSONL files through builtin memorySearch.extraPaths, while the existing JSONL path is limited to sanitized session transcript indexing. This remains a valid feature request that needs maintainer product and security direction before implementation.

## What This Changes

Request native JSONL ingestion for memorySearch.extraPaths so raw message-log files can be indexed and searched without converting them to Markdown first.

## Best Possible Solution

Define one supported JSONL ingestion contract for extraPaths, including admission, parsing, chunking, line mapping, memory_get, watcher behavior, docs, tests, and redaction; otherwise document the supported QMD, session-memory, converter, or plugin alternative.

## Reproduction Assessment

Yes, at source level: current main rejects ordinary .jsonl files from builtin extra-path discovery and memory_get, while watcher and indexing paths remain Markdown or enabled multimodal only. I did not run a live indexing command because this is a read-only review and the source path is sufficient.

## Solution Assessment

Unclear. The proposed extension-list change is not enough by itself; the maintainable solution needs one contract for JSONL admission, parsing/chunking, line mapping, retrieval, watcher behavior, docs, tests, and sensitive-field handling.
