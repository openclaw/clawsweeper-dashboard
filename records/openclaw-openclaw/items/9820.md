## Summary

Keep open. Current main and v2026.6.11 still scope builtin memory extra paths to Markdown plus enabled multimodal files; the remaining blocker is a product/security decision about whether arbitrary raw JSONL logs belong in builtin memory ingestion.

## What This Changes

The issue requests native JSONL ingestion for memory indexing from memorySearch.extraPaths so raw message-log files can be searched without a converter.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
