## Summary

Keep open: current main and the latest release still do not support arbitrary JSONL files through builtin `memorySearch.extraPaths`; the remaining gap is real but needs maintainer product and security direction before implementation.

## What This Changes

The issue requests native JSONL ingestion for memory indexing extra paths so raw message logs can be searched without converting them to Markdown.

## Best Possible Solution

Maintain this as a product/security decision until maintainers either define a complete JSONL extra-path ingestion contract or document the supported converter, QMD, session-memory, or ClawHub plugin alternative.

## Reproduction Assessment

Yes, at source level: current discovery, read, indexing, and watch paths still reject or treat ordinary non-`.md` extra-path files as unsupported. I did not run a live index command because this review is read-only and tests would write artifacts.

## Solution Assessment

Unclear. The proposed extension-list change is not enough by itself because admission, parsing/chunking, line mapping, watcher behavior, `memory_get`, docs, and redaction semantics need one coherent contract.
