## Summary

Keep open: current main and v2026.6.11 still exclude arbitrary JSONL files from builtin `memorySearch.extraPaths`; the remaining work is useful but needs maintainer product and security direction before implementation.

## What This Changes

Request native JSONL support for builtin `memorySearch.extraPaths` so raw message logs can be indexed and searched without converting them to Markdown.

## Best Possible Solution

Define a safe JSONL extra-path ingestion contract, or document the supported QMD, session-memory, converter, or plugin alternative if arbitrary raw JSONL is out of builtin scope.
