## Summary

Keep open. Current main and the latest release still exclude plain JSONL from builtin memory extra-path indexing and memory_get, while session transcript JSONL and QMD/session exports are separate paths; the remaining work is a maintainer product/security decision, not a stale or already-implemented request.

## What This Changes

The issue requests native JSONL support for memorySearch.extraPaths so raw message logs can be indexed for semantic memory search without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement first-class line-aware JSONL ingestion across discovery, parsing, indexing, watching, memory_get, docs, and tests with privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
