## Summary

Keep open: current main and the latest release still do not support arbitrary JSONL files through builtin memorySearch.extraPaths, and adding that path needs an explicit product and security contract rather than a simple extension-list change.

## What This Changes

The issue requests native JSONL support for memorySearch.extraPaths so raw message logs can be indexed and searched without converting them to Markdown.

## Best Possible Solution

Define a complete JSONL extra-path ingestion contract with admission, parsing, line mapping, watcher behavior, memory_get, docs, tests, and redaction rules, or document the supported QMD/session-memory/converter/plugin alternative if arbitrary raw JSONL is out of builtin scope.

## Reproduction Assessment

Yes, at source level: current main still rejects ordinary .jsonl files from builtin extra-path discovery and memory_get, while watcher/indexing paths remain Markdown or enabled multimodal only. I did not run a live indexing command because this is a read-only review and the source path is sufficient.

## Solution Assessment

No, the proposed extension-list change alone is not the best fix. A maintainable solution needs one contract across file admission, JSONL parsing/chunking, line mapping, memory_get, watcher behavior, docs, tests, and security/redaction semantics.
