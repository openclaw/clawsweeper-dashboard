## Summary

Keep open: current main and the latest release still do not support arbitrary JSONL files through builtin `memorySearch.extraPaths`; existing JSONL support is limited to the dedicated session-transcript path with filtering, redaction, and line mapping. The request is valid but needs product and security direction before implementation.

## What This Changes

Add native JSONL ingestion for builtin `memorySearch.extraPaths` so raw hook logs can be indexed and searched without converting them to Markdown.

## Best Possible Solution

Define a safe JSONL extra-path ingestion contract, or document the supported QMD, session-memory, converter, or plugin alternative if arbitrary raw JSONL is out of builtin scope.
