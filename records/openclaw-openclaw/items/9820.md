## Summary

Keep open: current main and v2026.6.11 still do not support arbitrary `.jsonl` files through builtin `memorySearch.extraPaths`, while the existing session-transcript JSONL and QMD paths are separate alternatives that do not settle the requested product boundary.

## What This Changes

Request native JSONL ingestion for builtin memory extra paths so raw message-log JSONL can be indexed without converting it to Markdown.

## Best Possible Solution

Make a maintainer decision first, then either add security-aware JSONL support across admission, parsing, line mapping, read/watch behavior, docs, and tests, or document the QMD/session-transcript/converter-plugin route as the supported path.

## Reproduction Assessment

Yes. Source inspection on current main shows builtin `memorySearch.extraPaths` only admits `.md` plus enabled multimodal files, and arbitrary `.jsonl` is excluded from both `listMemoryFiles` and `memory_get`.

## Solution Assessment

Unclear. Native JSONL support is plausible, but the best fix is not an extension-list change; maintainers need to choose between builtin parsing, QMD/session transcript indexing, or a converter/plugin boundary.
