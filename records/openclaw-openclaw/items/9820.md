## Summary

Keep open: current main has dedicated session-transcript JSONL handling but still does not admit arbitrary `.jsonl` files from `memorySearch.extraPaths`. The requested behavior is a new, privacy-sensitive ingestion mode, so maintainers need to choose the intended text-extraction and ownership boundary before a safe implementation can be scoped.

## What This Changes

Add native JSONL parsing and indexing for arbitrary files and directories configured through the builtin memory indexer’s extra paths.

## System Context

The bundled Memory Core plugin discovers workspace and configured extra-path files, converts them into searchable chunks, and stores those chunks in the per-agent memory index. Its separate session-memory source already flattens OpenClaw session JSONL into safe text with original-line mapping; arbitrary extra paths currently follow the Markdown or enabled-multimodal path instead.

## Architecture Diagram

  C -->|Arbitrary JSONL| E[Currently skipped]
  D --> F[Embedding and search index]

  H --> F

## Best Possible Solution

Define a Memory Core-owned JSONL ingestion contract that extracts only approved text fields, preserves original line mapping, handles malformed lines deterministically, and updates discovery, watching, retrieval, documentation, and focused privacy/regression tests together; otherwise document the supported session-memory or converter/plugin workflow as the intended path.
