## Summary

Keep open. Current main and the latest release still exclude arbitrary JSONL files from builtin memory extra-path discovery, memory_get, watcher filtering, and documented builtin behavior; this remains a product/security boundary rather than a cleanup-close candidate.

## What This Changes

The issue requests native JSONL support for builtin memory extra-path indexing so raw message logs can be embedded without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow.
