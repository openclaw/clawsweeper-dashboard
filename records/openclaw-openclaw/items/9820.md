## Summary

Keep open: current main and the latest release still do not support arbitrary JSONL files through builtin `memorySearch.extraPaths`, while the existing session-transcript JSONL path is a separate sanitized ingestion path. This remains a useful feature request, but it needs maintainer product and security review before implementation.

## What This Changes

Add native JSONL admission, parsing, indexing, watching, and retrieval support for `memorySearch.extraPaths`.

## Best Possible Solution

Define a safe JSONL extra-path ingestion contract, or document the supported QMD, session-memory, converter, or plugin alternative if arbitrary raw JSONL is out of builtin scope.

## Reproduction Assessment

Yes, at source level: configure `memorySearch.extraPaths` to a plain `.jsonl` file or a directory containing one, and current main excludes it from discovery, `memory_get`, and watcher-triggered indexing. I did not run a live indexing command because this is a read-only review and the source path is direct.

## Solution Assessment

Unclear. The proposed extension-list change is not enough; the maintainable fix needs one contract for admission, JSONL parsing and chunking, line mapping, `memory_get`, watcher behavior, docs, tests, and redaction/security semantics.
