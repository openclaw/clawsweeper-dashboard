## Summary

Keep open. Current main and v2026.6.11 still scope builtin memory extra paths to Markdown plus enabled multimodal files, while JSONL support is limited to the separate session-transcript memory path and the remaining choice is product/security direction.

## What This Changes

The issue requests native JSONL ingestion for builtin memorySearch extra paths so raw message-log JSONL files can be indexed without conversion.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
