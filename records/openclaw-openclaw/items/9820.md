## Summary

Keep open: current main and the latest release still do not support arbitrary JSONL files through builtin `memorySearch.extraPaths`; session-transcript JSONL indexing is a separate sanitized path, not raw extra-path ingestion.

## What This Changes

The issue requests native JSONL ingestion for builtin `memorySearch.extraPaths` so raw message-log JSONL files can be semantically indexed without conversion.

## Best Possible Solution

Define a safe JSONL extra-path ingestion contract, or document the supported QMD, session-memory, converter, or plugin alternative if arbitrary raw JSONL is out of builtin scope.

## Reproduction Assessment

Yes, at source level: configure `memorySearch.extraPaths` to a plain `.jsonl` file or a directory containing one, and current main excludes it from discovery, `memory_get`, and watcher-triggered indexing.

## Solution Assessment

Unclear. The proposed extension-list change is too narrow because a maintainable fix needs one contract for admission, JSONL parsing/chunking, line mapping, `memory_get`, watcher behavior, docs, tests, and redaction/security semantics.
