## Label Justifications

- `P2`: This is a normal-priority memory indexing enhancement with a documented converter workaround and no evidence of urgent runtime breakage.
- `impact:session-state`: The request affects whether raw conversation logs can become searchable durable memory and retrieved context.
- `impact:security`: Indexing arbitrary raw JSONL logs can expose private message, tool, or operational fields to local embedding storage and remote providers without a defined redaction contract.

## Summary

Keep open: current main and the latest release still exclude arbitrary JSONL files from builtin memory `extraPaths`, and the remaining work needs maintainer product and security direction before implementation.

## What This Changes

The issue requests native JSONL support in the builtin memory indexer so raw message logs listed through `memorySearch.extraPaths` can be chunked and embedded without a Markdown conversion step.

## Best Possible Solution

Define a safe JSONL extra-path ingestion contract with record/field selection, redaction, line mapping, watcher/read behavior, docs, and tests, or document the supported QMD, session-memory, converter, or plugin alternative if arbitrary raw JSONL stays out of builtin scope.
