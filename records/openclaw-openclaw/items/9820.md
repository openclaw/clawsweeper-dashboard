## Summary

Keep open. Current main and the latest release still keep builtin memory extra path indexing Markdown/multimodal-oriented, while existing JSONL handling is scoped to session-memory paths; the remaining blocker is maintainer product/security direction, not lack of source evidence.

## What This Changes

Request to add native JSONL support to builtin memorySearch.extraPaths so raw message logs can be semantically searched without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across builtin discovery, chunking, watching, memory_get, docs, and tests with privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
