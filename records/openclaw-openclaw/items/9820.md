## Summary

Keep open. Current main and the latest release still keep builtin memory extra path ingestion Markdown/multimodal-oriented, while the existing JSONL support is limited to the opt-in session transcript path; the remaining decision is whether arbitrary raw JSONL logs belong in builtin memory or in a documented plugin/QMD/converter workflow.

## What This Changes

The issue requests native JSONL ingestion for builtin `memorySearch.extraPaths` so raw message logs can be indexed for semantic memory search without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across builtin discovery, chunking, watching, `memory_get`, docs, and tests with privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
