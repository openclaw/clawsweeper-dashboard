## Summary

Keep open. Current main and the latest release still keep builtin memory extra paths Markdown/multimodal-only, while JSONL support is limited to the separate session-transcript ingestion path; maintainers still need to decide whether arbitrary raw log ingestion belongs in builtin memory, QMD/session memory, a converter/plugin workflow, or docs.

## What This Changes

The issue requests native JSONL support for `memorySearch.extraPaths` so raw message-hook logs can be indexed without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement first-class line-aware JSONL support across builtin discovery, parsing, indexing, watching, `memory_get`, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
