## Summary

Keep open. Current main and v2026.6.11 still keep builtin memory extra-path ingestion Markdown/multimodal-oriented, while the existing JSONL support is limited to the separate session-transcript path; the remaining decision is whether arbitrary raw JSONL logs belong in builtin memorySearch.extraPaths at all.

## What This Changes

Request to add native JSONL ingestion for memorySearch.extraPaths so raw message logs can be indexed without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
