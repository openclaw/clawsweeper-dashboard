## Summary

Keep open: current main still does not support arbitrary JSONL files through builtin `memorySearch.extraPaths`, and the remaining decision is product/security scope rather than stale cleanup.

## What This Changes

Request native `.jsonl` support for builtin memory indexing of `memorySearch.extraPaths` so raw message-log lines can be embedded and searched without converting them to Markdown.

## Best Possible Solution

Maintain this as a product/security decision until maintainers either define a complete JSONL extra-path ingestion contract or document the supported converter, QMD, session-memory, or ClawHub plugin alternative.

## Reproduction Assessment

Yes at source level: current discovery, watcher, indexing, and read paths still exclude ordinary `.jsonl` extra-path files or treat only session-source JSONL specially. I did not run a live indexing command because this read-only review cannot create test artifacts in the checkout.

## Solution Assessment

Unclear; the proposed extension-list change is not the best complete solution by itself because admission, parsing/chunking, line mapping, watcher behavior, `memory_get`, docs, and redaction semantics all need one coherent contract.
