## Summary

Keep open. Current main and v2026.6.11 still keep builtin memory extra-path ingestion Markdown/multimodal-oriented, while JSONL handling remains limited to the separate session-transcript path; the remaining blocker is a maintainer product/security decision about raw-log ingestion.

## What This Changes

Request native JSONL support in builtin memory indexing for `memorySearch.extraPaths` so raw message logs can be searched without conversion to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, `memory_get`, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
