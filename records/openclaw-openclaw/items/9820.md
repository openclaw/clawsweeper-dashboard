## Label Justifications

- `P2`: This is a normal-priority memory indexing feature gap with a workaround and no evidence of an urgent runtime outage.
- `impact:session-state`: The request affects whether raw conversation logs can become searchable durable memory and later retrieved context.

## Summary

Keep open: current main and the latest release still do not support arbitrary JSONL files through builtin `memorySearch.extraPaths`, while the existing session-transcript JSONL path is a separate sanitized ingestion flow.

## What This Changes

Request native JSONL support for builtin `memorySearch.extraPaths` so raw message-hook logs can be indexed for memory search without a converter.

## Best Possible Solution

Define a complete JSONL extra-path ingestion contract, or document the supported QMD, session-memory, converter, or plugin alternative if arbitrary raw JSONL is out of builtin scope.

## Reproduction Assessment

Yes, at source level: current main rejects ordinary `.jsonl` files from builtin extra-path discovery and `memory_get`, while watcher/indexing paths remain Markdown or enabled multimodal only. I did not run a live indexing command because this is a read-only review and the source path is sufficient.

## Solution Assessment

Unclear. The proposed extension-list change is not sufficient by itself; the maintainable fix needs one contract for admission, JSONL parsing/chunking, line mapping, `memory_get`, watcher behavior, docs, tests, and redaction/security semantics.
