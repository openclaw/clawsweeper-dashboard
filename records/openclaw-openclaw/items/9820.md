## Summary

Keep open. Current main and the latest release still do not support arbitrary JSONL files through builtin memorySearch.extraPaths; the existing JSONL support is a separate sanitized session-transcript path, and the requested raw-log ingestion needs maintainer product/security direction before implementation.

## What This Changes

The issue requests native JSONL ingestion for builtin memorySearch.extraPaths so raw message log files can be indexed without converting them to Markdown.

## Best Possible Solution

Document and implement one approved ingestion boundary: either native JSONL extraPaths with schema validation, sanitization, line mapping, watcher, memory_get, docs, and tests, or an explicit supported QMD/plugin/converter workflow for raw hook logs.

## Reproduction Assessment
