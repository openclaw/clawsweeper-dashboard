## Summary

Keep open. Current main and the latest release still exclude arbitrary JSONL files from builtin memory extra-path discovery, memory_get, and watcher filtering; the remaining question is a product/security choice, not an implemented cleanup target.

## What This Changes

The issue requests native JSONL support for memorySearch.extraPaths so raw message-log files can be indexed without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow.
