Keep open for an explicit maintainer decision. Current main still excludes ordinary JSONL from builtin memory extra paths, while the existing JSONL path is specifically designed for sanitized OpenClaw session transcripts; no newer canonical issue or viable PR owns the requested arbitrary-log behavior.

## What This Changes

Add native JSONL ingestion and semantic-search support for files configured through builtin memory extra paths.

## Best Possible Solution

Keep builtin extra-path memory Markdown-focused unless maintainers sponsor a typed structured-log source; otherwise document a self-managed converter or memory plugin that renders a reviewed, redacted Markdown corpus before indexing.
