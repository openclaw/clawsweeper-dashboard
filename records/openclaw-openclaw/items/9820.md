## Label Justifications

- `impact:session-state`: The request affects whether raw conversation logs can become searchable durable memory and later retrieved context.

## Summary

Keep open: current main and the latest release still exclude arbitrary JSONL files from builtin memorySearch.extraPaths, while the existing session JSONL path is a separate sanitized transcript-ingestion flow. This remains useful, but it needs a maintainer product and security decision before implementation.

## What This Changes

The issue requests native JSONL ingestion for builtin memorySearch.extraPaths so raw message-log files can be indexed without conversion.

## Best Possible Solution

Define a safe JSONL extra-path ingestion contract across admission, parsing, redaction, chunking, watcher updates, memory_get, docs, and tests, or document the supported QMD, session-memory, converter, or plugin alternative if arbitrary raw JSONL is out of builtin scope.

## Reproduction Assessment

Yes, at source level: configure memorySearch.extraPaths to a plain .jsonl file or a directory containing one, and current main excludes it from discovery, memory_get, and watcher-triggered indexing. I did not run a live indexing command because this is a read-only review and the source path is direct.

## Solution Assessment

Unclear. The proposed extension-list change is not enough; the maintainable fix needs one contract for admission, JSONL parsing/chunking, line mapping, memory_get, watcher behavior, docs, tests, and redaction/security semantics.
