## Summary

Keep open. Current main and v2026.6.11 still exclude arbitrary JSONL files from builtin memory extra-path discovery, memory_get, and watcher filtering; this remains a product/security decision, not implemented behavior.

## What This Changes

The issue requests native JSONL ingestion for memorySearch.extraPaths so raw message-hook logs can be indexed for semantic memory search.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow.
