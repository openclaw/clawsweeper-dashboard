## Summary

Keep open: current main still does not support arbitrary JSONL files through builtin `memorySearch.extraPaths`, and the issue remains a real memory feature gap with unresolved product and security boundaries.

## What This Changes

Request native JSONL ingestion for builtin memory indexing so raw message-log files in `memorySearch.extraPaths` can be searched without converting them to Markdown.

## Best Possible Solution

Define a complete JSONL extra-path ingestion contract or document the supported converter, QMD, or session-memory alternative before closing this issue.

## Reproduction Assessment

Yes, at source level: current discovery, read, indexing, watcher, and docs paths still treat builtin extra-path memory as Markdown or enabled multimodal files, not arbitrary JSONL. I did not run tests because this review is read-only and tests would write artifacts.

Unclear; the proposed extension-list change is not the best complete fix by itself because admission, parsing/chunking, line mapping, watcher behavior, `memory_get`, docs, and redaction semantics need one coherent contract.
