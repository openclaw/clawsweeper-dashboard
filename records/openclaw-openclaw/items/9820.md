## Summary

Keep open: current main and the latest release still do not support arbitrary JSONL files through builtin memorySearch.extraPaths, while session-transcript JSONL remains a separate opt-in path with its own visibility and corpus rules.

## What This Changes

Issue requests native JSONL ingestion for memorySearch.extraPaths so raw message logs can be indexed without converting them to Markdown.

## Best Possible Solution

Keep this open for a maintainer product/security decision: either add native JSONL support across admission, parsing/chunking, watcher, memory_get, docs, and tests with clear sensitive-data handling, or document the supported QMD/session-memory/converter/ClawHub-plugin workflow instead.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: configure builtin memorySearch.extraPaths with a .jsonl file and current file admission, memory_get, and watcher logic will skip or reject it unless it is Markdown or enabled multimodal media.

## Solution Assessment

Unclear. Native JSONL support is plausible, but the best solution depends on whether maintainers want raw hook logs in builtin memory or prefer QMD/session-memory/converter/plugin ownership for that data.
