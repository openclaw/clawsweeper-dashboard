## Summary

Keep open. Current main and v2026.6.11 still keep builtin memory extra-path indexing Markdown/multimodal-oriented, while session JSONL handling is a separate session-transcript path; the remaining question is a maintainer product/security choice about arbitrary raw-log ingestion.

## What This Changes

Request to add native JSONL support to builtin memorySearch.extraPaths so raw message-log files can be indexed and searched without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
