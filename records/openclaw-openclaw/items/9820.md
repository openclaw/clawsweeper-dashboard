## What This Changes

Add native JSONL parsing and indexing for user-configured `memorySearch.extraPaths`, so raw message-log files can be searched without a Markdown conversion step.

## System Context

The memory-core plugin discovers configured memory sources, turns their content into searchable chunks, and stores those chunks for `memory_search` and `memory_get`. Session-transcript JSONL has a separate opt-in ingestion path; this request would extend arbitrary additional-file ingestion into that trust boundary.

## Architecture Diagram

flowchart LR
  A[Configured extra paths] --> B[Memory file discovery]
  C[Session transcript JSONL] --> D[Session-memory parser]
  B --> E[Chunking and embeddings]
  D --> E
  E --> F[Search index]
  F --> G[memory_search results]
  B --> H[memory_get access]

## Best Possible Solution

Choose and document one supported boundary: either a plugin-owned converter/memory integration for raw logs, or a deliberately scoped builtin JSONL document contract that defines parsing, privacy, search scope, and read behavior end to end.
