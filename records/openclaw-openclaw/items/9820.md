## Summary

Keep open. Current main and the latest release still do not support arbitrary JSONL files in builtin memorySearch.extraPaths; native raw-log ingestion remains a maintainer product/security decision rather than completed cleanup.

## What This Changes

The issue requests native JSONL support in the memory indexer so raw message logs listed in memorySearch.extraPaths can be semantically indexed without conversion to Markdown.

## Best Possible Solution

Keep the issue open until maintainers choose and document the supported raw-log recall path; if builtin JSONL is accepted, implement it across file admission, line-aware parsing/chunking, watcher filtering, memory_get, docs, and focused tests with privacy guardrails.
