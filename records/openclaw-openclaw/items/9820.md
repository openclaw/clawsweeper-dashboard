## Label Justifications

- `P2`: This is a normal-priority memory indexing feature gap with a workaround and no evidence of an urgent runtime outage.
- `impact:session-state`: The request affects whether raw conversation logs can become searchable durable memory and later retrieved context.
- `impact:security`: Indexing arbitrary raw JSONL logs can expose private message, tool, or operational fields to embedding storage and providers without a defined redaction contract.

## Summary

Keep open: current main and the latest release still do not support arbitrary JSONL files through builtin `memorySearch.extraPaths`, and the existing session-transcript JSONL path is a separate sanitized ingestion path. This remains a useful feature request, but it needs maintainer product and security direction before implementation.

## What This Changes

Request native JSONL ingestion for `memorySearch.extraPaths` so raw message logs can be indexed without converting them to Markdown.

## Best Possible Solution

Define a complete JSONL extra-path ingestion contract, or document the supported QMD, session-memory, converter, or plugin alternative if arbitrary raw JSONL is out of builtin scope.

## Reproduction Assessment

Yes, at source level: current main still rejects ordinary `.jsonl` files from builtin extra-path discovery and `memory_get`, while watcher and indexing paths remain Markdown or enabled multimodal only.

## Solution Assessment

Unclear. The proposed extension-list change is not sufficient by itself; the durable fix needs one contract for admission, JSONL parsing/chunking, line mapping, `memory_get`, watcher behavior, docs, tests, and redaction/security semantics.
