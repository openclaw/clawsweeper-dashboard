## Summary

Keep open: current main still excludes arbitrary JSONL files from builtin memorySearch.extraPaths, while the existing session-transcript JSONL support is a separate opt-in path and the requested raw-log ingestion needs maintainer product and security direction.

## What This Changes

Request native JSONL ingestion for builtin memorySearch.extraPaths so raw message-hook logs can be semantically searched without converting them to Markdown.

## Best Possible Solution

Keep this open until maintainers either approve a native JSONL contract for builtin extraPaths with security-reviewed discovery, parsing, watch, read, docs, and tests, or explicitly document the supported QMD/sessionMemory/converter-plugin workflow.
