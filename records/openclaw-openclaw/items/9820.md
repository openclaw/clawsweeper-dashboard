## Summary

Keep open. Current main and v2026.6.11 still do not provide native JSONL support for builtin memorySearch.extraPaths, and the remaining question is a product/security decision rather than a stale implementation gap.

## What This Changes

The issue requests native JSONL ingestion for memory search extra paths so raw message logs can be indexed without conversion.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow.
