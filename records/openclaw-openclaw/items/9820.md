## Summary

Keep open. Current main and the latest release still keep builtin memory extra-path ingestion Markdown/multimodal-oriented, while existing JSONL support is limited to opt-in session transcript indexing; the remaining blocker is a maintainer product/security decision about arbitrary raw JSONL logs.

## What This Changes

Requested native JSONL support for memorySearch.extraPaths so raw message-log files can be indexed and searched without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, `memory_get`, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
