## Label Justifications

- `P2`: This is a clear memory capability request with source-reproducible current behavior, but it is not a user-blocking regression.
- `impact:session-state`: The request changes what message/session-like JSONL history can be indexed and recalled through memory search.

## Summary

Keep open. Current main and the latest release still keep builtin memory extra path indexing Markdown/multimodal-oriented, while session JSONL indexing is a separate opt-in path; the remaining blocker is a maintainer product/security decision.

## What This Changes

Request native JSONL support in builtin `memorySearch.extraPaths` so raw message logs can be indexed and searched without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across builtin discovery, chunking, watching, `memory_get`, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.

Options:

- **Document the supported alternative (recommended):** Keep builtin extraPaths Markdown/multimodal-only and document the QMD, session-memory, converter, or plugin-owned workflow for raw JSONL recall.
- **Add native builtin JSONL:** Implement JSONL as a first-class builtin memory format with line-aware parsing, watcher and `memory_get` support, tests, docs, and privacy guardrails.
- **Defer to plugin/API design:** Keep this open until maintainers decide whether a plugin or memory API extension should own arbitrary raw-log ingestion.

Yes. Source inspection gives a high-confidence path: builtin `listMemoryFiles` and `readMemoryFile` reject plain `.jsonl` extra paths, and docs still describe extra path directory scanning as `.md` only.

## Solution Assessment
