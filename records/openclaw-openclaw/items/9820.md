## Summary

Keep open. Current main and the latest release still scope builtin memory extraPaths to Markdown plus enabled multimodal files, while JSONL support is limited to session-transcript paths; the remaining choice is a maintainer product/security decision about whether arbitrary raw JSONL logs belong in builtin memory ingestion.

## What This Changes

The issue requests native JSONL ingestion for builtin memory indexing extra paths so raw message logs can be semantically searched without converting them to Markdown.

## Best Possible Solution

Decide the product/security boundary first, then either implement first-class line-aware JSONL ingestion across discovery, watcher, indexing, memory_get, docs, and tests, or document the supported QMD/session-memory/converter/plugin workflow.
