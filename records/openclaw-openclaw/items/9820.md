## Summary

Keep open. Current main and the latest release still exclude plain JSONL from builtin memory extra-path discovery and memory_get; session transcript JSONL support is a separate opt-in session-memory path, so this needs maintainer product/security direction rather than cleanup closure.

## What This Changes

The issue asks for builtin memory indexing of `.jsonl` files from `memorySearch.extraPaths`, treating JSONL lines as indexable chunks instead of requiring a Markdown conversion step.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
