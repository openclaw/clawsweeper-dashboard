## Summary

Keep open. Current main and the latest release still scope builtin memory extraPaths to Markdown plus enabled multimodal files, while JSONL support remains limited to session transcript paths; the remaining question is whether arbitrary raw log ingestion belongs in builtin memory or should be documented as a QMD/session-memory/converter/plugin workflow.

## What This Changes

Add native JSONL ingestion and line-aware chunking for memorySearch.extraPaths so raw message logs can be semantically indexed without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, parsing, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported QMD/session-memory/converter/plugin workflow instead.
