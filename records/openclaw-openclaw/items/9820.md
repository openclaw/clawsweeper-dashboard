## Summary

Keep open. Current main and v2026.6.11 still keep builtin memory extra-path ingestion Markdown/multimodal-oriented; the remaining decision is product/security scope for arbitrary raw JSONL log ingestion, not source ambiguity.

## What This Changes

The issue requests native JSONL support in builtin memorySearch.extraPaths so raw message logs can be indexed and searched without converting them to Markdown.

## Best Possible Solution

Make an explicit product/security choice: either implement line-aware JSONL support across discovery, chunking, watching, memory_get, docs, tests, and privacy guardrails, or document the supported session-memory/QMD/converter/plugin workflow instead.
