## Summary

Keep open: current main and the latest release still do not support arbitrary JSONL files through builtin `memorySearch.extraPaths`; the existing JSONL path is the separate, sanitized session-transcript source, so this still needs maintainer product and security review.

## What This Changes

The issue requests native JSONL ingestion for the builtin memory indexer so raw message logs in `memorySearch.extraPaths` can be searched without converting them to Markdown.

## Best Possible Solution

Define a safe JSONL extra-path ingestion contract, or document the supported QMD, session-memory, converter, or plugin alternative if arbitrary raw JSONL is out of builtin scope.

## Reproduction Assessment

Yes, at source level: configure `memorySearch.extraPaths` to a plain `.jsonl` file or a directory containing one, and current main excludes it from discovery, `memory_get`, and watcher-triggered indexing.

## Solution Assessment

Unclear. The proposed extension-list change is not enough; the maintainable fix needs one contract for admission, JSONL parsing/chunking, line mapping, `memory_get`, watcher behavior, docs, tests, and redaction/security semantics.
