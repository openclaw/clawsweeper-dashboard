## Summary

This PR addresses real ClickClack media-loss and model-reply truncation problems, but it is not merge-ready because attachment failure after message creation can turn a retry into duplicate visible messages, and the new token-budget configuration/default still needs maintainer direction and after-fix live proof.

## What This Changes

The PR adds ClickClack media upload and attachment delivery, introduces a per-account model-reply token budget with a 512-token default, logs empty completions, and updates tests, docs, and generated config metadata.

## Best Possible Solution

Make ClickClack media delivery atomic or safely idempotent across upload, message creation, and attachment association; keep one plugin-owned token default unless maintainers sponsor the new setting, and then prove both omitted-default and configured live model replies.
