## Summary

Keep open: current main and the latest release still have a source-level Telegram path where unmentioned requireMention group media is skipped before download, while later history replay can only attach images when `InboundHistory.media` already exists. The remaining blocker is the privacy/security policy for retaining and replaying unmentioned group media, not whether the symptom is real.

## What This Changes

The issue asks OpenClaw to preserve Telegram group media from unmentioned history entries so a later mentioned turn can inspect those images instead of seeing only `<media:image>` placeholders.

## Best Possible Solution

Approve a bounded Telegram history-media policy, then reuse `HistoryEntry.media` and the existing recent-history image pipeline with focused source tests plus live Telegram proof.
