## Summary

Keep open: current main and v2026.6.11 still skip unmentioned Telegram requireMention group media before download, so the later mentioned turn cannot receive historical image media even though the shared history-media pipeline now exists. The remaining blocker is the security/product policy for retaining and replaying unmentioned group media, not a missing generic HistoryEntry type.

## What This Changes

The issue requests preserving Telegram group media from unmentioned messages so a later @mention can inspect the recent image instead of seeing only a placeholder.

## Best Possible Solution

Approve a bounded Telegram history-media policy, then reuse the existing HistoryEntry.media, recordWithMedia, and recent-history-image pipeline so safe local image metadata can be replayed without leaking paths or widening passive group replies.

Yes, but only after a maintainer policy decision: the narrow implementation should reuse the shared HistoryEntry.media and recordWithMedia path rather than reintroducing ad hoc mediaPaths/mediaTypes arrays. A direct fix without retention and path-exposure bounds would not be the best solution.
