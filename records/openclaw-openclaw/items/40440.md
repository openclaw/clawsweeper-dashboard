## Summary

Keep open: current main and v2026.6.11 still do not make unmentioned Telegram `requireMention` group media available to a later addressed turn; the source gap is clear, but retaining bystander attachments is a security/product boundary rather than a safe cleanup close.

## What This Changes

Preserve Telegram group media from unmentioned history entries so later @mentioned turns can inspect the attachments.

## Best Possible Solution

Define an explicit Telegram history-media policy, likely bounded and opt-in, that preserves authorized recent images through `HistoryEntry.media` without downloading or retaining unauthorized bystander media by default, then validate it with live Telegram proof.

- **Not planned:** Close the request and keep unmentioned group media text-only or skipped in `requireMention` groups to avoid retaining bystander attachments.

Yes, there is a high-confidence source reproduction path: unmentioned non-audio media in a `requireMention` Telegram group is skipped before `getFile`, and processed group history entries are recorded without media metadata. I did not run a live Telegram repro in this read-only pass.

## Solution Assessment

Unclear as a direct fix: simply preserving all unmentioned group media would solve the attachment gap but may be the wrong security boundary. The best maintainable solution needs an explicit bounded retention policy before code repair.
