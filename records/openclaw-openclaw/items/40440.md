## Summary

Keep open: current main still records Telegram group-history entries as text-only while the shared history-media pipeline can only replay media that was already stored on `HistoryEntry.media`. The remaining fix is security/product-sensitive because it would retain and later expose unmentioned group media to model context.

## What This Changes

The issue asks OpenClaw to preserve Telegram media from unmentioned group-history messages so a later mentioned turn can inspect the image data, not only placeholder text.

## Best Possible Solution

Approve a bounded Telegram history-media policy, then reuse `HistoryEntry.media`/`recordWithMedia` and the recent-history image pipeline with focused tests and live Telegram proof.
