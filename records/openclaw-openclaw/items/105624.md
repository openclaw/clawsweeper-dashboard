## Summary

This issue remains necessary: current main masks registered secret values but does not generally redact sensitive JSON, form, or query keys before proxy-capture persistence. Shared database sidecar hardening already exists and should be verified rather than duplicated.

## What This Changes

Harden proxy capture by applying content-aware secret redaction to captured bodies, URLs, and headers and ensuring private SQLite file modes.

## Best Possible Solution

Use the shared structured and text redaction primitives at the proxy-capture serialization boundary, add focused JSON, form, query, and header regressions, and modify shared SQLite handling only if a filesystem-stat test proves WAL or SHM files are not private while open.

## Solution Assessment

Partly. Content-aware redaction through existing shared helpers is the narrow maintainable fix, but a proxy-local umask or duplicate sidecar-hardening path is unjustified unless the shared database's current permission contract fails a focused real-filesystem test.
