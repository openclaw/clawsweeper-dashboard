## Summary

The vulnerability is valid and the guard sits at the correct mutation boundary, but the implementation breaks a documented explicit-owner case: channel-qualified global owners are reinterpreted under the target provider and denied. The mocked resolver strips prefixes without provider filtering, so its “global owner passes” test masks production behavior.

## What This Changes

The PR adds a target-channel owner re-check for cross-channel `/allowlist` writes, extracts a reusable non-owner denial helper, and adds regression tests for origin-only and global owners.

## Best Possible Solution

Preserve a successful explicit `commands.ownerAllowFrom` match from the origin authorization, and require target-channel ownership only when owner authority came from the origin channel’s fallback `allowFrom`; cover both with the real resolver and production-path proof.
