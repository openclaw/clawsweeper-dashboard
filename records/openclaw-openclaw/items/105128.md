## Summary

The current head correctly stops treating context-derived owners as globally authorized, but the cross-channel target check still passes the origin `OwnerAllowFrom` into `resolveCommandAuthorization`. That lets a context-only origin owner resolve as an owner again on the synthetic target, so the security boundary remains incomplete and the PR is not merge-ready.

## What This Changes

The PR adds explicit global-owner provenance, target-channel authorization for cross-channel `/allowlist` mutations, and regression coverage for owner-source classification and handler behavior.

## Best Possible Solution

Build target authorization from target-relevant sender, channel, and account facts while explicitly excluding origin-derived `OwnerAllowFrom`; add non-mocked full-handler regressions for context-only, target-local, and configured-global owners, then provide redacted persisted-config output for the denied and allowed cases.
