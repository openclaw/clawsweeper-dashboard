## Summary

Keep this issue open while the linked fixes are reviewed: the rejection is safety-correct for ordinary SQLite 3.46.1, but shared-library builds with independently verified distro backports need an explicit maintainer-approved policy, and the current error wording is misleading.

## What This Changes

Support verified distribution-backported shared SQLite runtimes that report otherwise-unsafe version numbers, while clearly explaining the accepted patch branches.

## Best Possible Solution

Keep the strict version check as the default, clarify that the backports are branch-specific, and permit an explicitly warned shared-system-SQLite override only when maintainers accept trusted operators owning backport verification and tests prove embedded builds cannot bypass the guard.
