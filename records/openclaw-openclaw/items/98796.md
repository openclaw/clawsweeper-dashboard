## Summary

Keep open; current main does not already provide these Android command controls, but the PR is not merge-ready because the new local reset path calls an admin-only Gateway method from Android's normally bounded operator connection, and the fallback command catalog duplicates `commands.list`. A member has already asked for visual Mantis proof, but no usable proof output is present yet.

## What This Changes

The PR adds Android chat command metadata, command-list refresh plumbing, new-chat controls, slash-command picker UI, local `/new` and `/reset` handling, and Android unit tests.

## Best Possible Solution

Keep command discovery driven by `commands.list`, make Android new/reset actions use a write-scoped Gateway path that preserves `/reset` semantics, and merge only after maintainer product acceptance plus visible Android proof.

## Reproduction Assessment

Yes from source for the PR defect: normal Android operator connections request only `operator.approvals`, `operator.read`, and `operator.write`, while the proposed new-chat path calls admin-only `sessions.reset`. I did not run an emulator in this read-only review.

## Solution Assessment

No; exposing Android command controls is plausible, but direct `sessions.reset` is the wrong contract for Android's bounded operator token and the fallback catalog duplicates `commands.list`. A safer solution keeps Gateway command discovery authoritative and uses a scope-correct command/reset path.
