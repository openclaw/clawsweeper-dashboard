## Summary

Keep open: current main still has a source-supported Discord path that commits or logs non-retryable handler failures after `reply session initialization conflicted`, and the proof-sufficient shared self-heal PR is still open rather than merged. That PR may be the right root fix, but it does not yet settle whether Discord also needs channel-level retry/requeue or visible-failure parity for delivered thread replies.

## What This Changes

Discord thread replies can be silently lost when reply-session initialization conflicts during a finished session’s finalize window, and the issue asks for retry or visible failure handling comparable to sibling channels.

## Best Possible Solution

Review and land the shared reply-session conflict self-heal if maintainers accept it, then retest Discord thread follow-ups and add Discord retry/requeue or visible failure handling only if delivered Discord replies can still drop retryable init conflicts.
