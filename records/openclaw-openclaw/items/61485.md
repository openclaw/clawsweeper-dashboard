Full review comments:

- **[P1] Re-detect images after prompt overrides:** `src/agents/embedded-agent-runner/run/attempt.ts:4145`
  - body: `imageResult` is computed from the original prompt before this assignment, and the later provider call still sends `imageResult.images`. If an `llm_input` hook adds or removes image refs, the model receives mismatched attachments; recompute or roll back image state after accepting a prompt override.
  - confidence: 0.9
- **[P1] Apply system-prompt overrides to the active session:** `src/agents/embedded-agent-runner/run/attempt.ts:4148`
  - body: This only updates `systemPromptForHook`, while the active session prompt and Google prompt-cache wrapper were already built from the old `systemPromptText`. A plugin's advertised `systemPrompt` override can be logged/prechecked without reaching the provider.
  - confidence: 0.88
- **[P1] Rewrite output before downstream observers see it:** `src/agents/embedded-agent-runner/run/attempt.ts:5141`
  - body: The override is applied only in the returned attempt result, after `agent_end` and trajectory recording already consumed the original `messagesSnapshot` and `assistantTexts`. Redaction plugins would still leak the original output to those observers.
  - confidence: 0.9
- **[P1] Bound awaited LLM hook handlers:** `src/plugins/hooks.ts:967`
  - body: This converts formerly fire-and-forget hooks to awaited modifying hooks, but `DEFAULT_MODIFYING_HOOK_TIMEOUT_MS_BY_HOOK` has no `llm_input` or `llm_output` budget. A plugin handler that never settles can now stall the agent hot path unless defaults or caller-level timeouts are added.
  - confidence: 0.86
