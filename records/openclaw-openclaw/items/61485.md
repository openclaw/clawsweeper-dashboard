## Summary

Keep open for maintainer review: the feature direction is useful, but this PR is not merge-ready because the system-prompt override does not reach the actual model path, output redaction runs after downstream observers have already seen the original answer, awaited hook handlers are unbudgeted by default, and current-head real behavior proof is insufficient.

## What This Changes

The PR changes `llm_input` and `llm_output` from observe-only plugin hooks into awaited modifying hooks that can block LLM calls, rewrite prompt fields, and replace assistant texts.

## Best Possible Solution

Land only a maintainer-approved, hardened LLM hook API that applies prompt/system changes to the real provider path, redacts before every downstream observer, has default hook budgets, includes docs/tests, resolves conflicts, and carries current-head real gateway proof.
