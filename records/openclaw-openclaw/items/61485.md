Full review comments:

- **[P1] Apply system-prompt overrides to the model call:** `src/agents/embedded-agent-runner/run/attempt.ts:4148`
  - body: Assigning the hook result only to `systemPromptForHook` updates diagnostics/precheck inputs, but the later `promptActiveSession` path still uses the active session system prompt and the Google prompt-cache wrapper was prepared from the old `systemPromptText`. A plugin returning `{ systemPrompt }` therefore does not reliably change the provider-visible system prompt.
  - confidence: 0.91
- **[P1] Re-detect prompt images after hook rewrites:** `src/agents/embedded-agent-runner/run/attempt.ts:4145`
  - body: `imageResult` is computed before `llm_input` can replace `promptForModel`, then the old `imageResult.images` are sent to the model. A hook that adds an image reference will not load it, and a hook that removes a reference can still send the original image.
  - confidence: 0.9
- **[P1] Give awaited LLM hooks default timeouts:** `src/plugins/hooks.ts:967`
  - body: This turns `llm_input` and `llm_output` into awaited sequential modifying hooks, but the default modifying-hook timeout map still omits them. A never-settling LLM hook can now stall the model-call or response path, repeating the hook-hang class fixed for `before_agent_start`.
  - confidence: 0.88
- **[P1] Keep redacted output out of run state:** `src/agents/embedded-agent-runner/run/attempt.ts:5141`
  - body: The output hook override is only substituted in the returned `assistantTexts`; `messagesSnapshot`, `lastAssistant`, trajectory events, and the stored session state still carry the original assistant message. That means a redaction plugin can change the immediate payload while the unredacted response remains available to later context and metadata paths.
  - confidence: 0.86
- **[P1] Do not expose a modifying contract that harnesses ignore:** `src/plugins/hook-types.ts:1045-1052`
  - body: The shared handler map advertises result-returning `llm_input`/`llm_output` hooks, but OpenClaw's harness helper still dispatches these hooks best-effort and ignores returned values for Codex/Copilot-style runtimes. Either implement the result contract consistently or scope the public API so plugin authors do not get conflicting behavior by runtime.
  - confidence: 0.84
- **[P2] Document and test the new hook result contract:** `src/plugins/hook-types.ts:1045-1052`
  - body: Changing these hook signatures creates a public plugin API, but the current docs still describe them as observation hooks and the PR diff does not add focused contract coverage for the new block/rewrite/redact semantics. Plugin authors need the documented contract and regression tests before relying on it.
  - confidence: 0.82
