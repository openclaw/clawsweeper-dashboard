## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Add default timeouts for awaited LLM hooks:** `src/plugins/hooks.ts:967`
  - body: This converts `llm_input` to `runModifyingHook`, but the default modifying-hook timeout map still has no `llm_input` or `llm_output` entry. Because `runModifyingHook` awaits the raw promise when no timeout is configured, one hung plugin can stall every model call or output path.
  - confidence: 0.93
- **[P1] Apply systemPrompt overrides to the model call:** `src/agents/embedded-agent-runner/run/attempt.ts:4147-4148`
  - body: The returned `systemPrompt` is assigned only to `systemPromptForHook`; the active session and Google prompt-cache wrapper were already configured from `systemPromptText`. That makes traces and prechecks see the override while the provider can still receive the old system prompt.
  - confidence: 0.89
- **[P1] Re-detect prompt images after hook rewrites:** `src/agents/embedded-agent-runner/run/attempt.ts:4144-4145`
  - body: Prompt images are detected from `promptSubmission.prompt` before this assignment, and the later model call still sends `imageResult.images`. If a plugin rewrite adds image refs they are missed; if it removes refs the old images can still be sent.
  - confidence: 0.91
- **[P1] Keep redacted output out of assistant state:** `src/agents/embedded-agent-runner/run/attempt.ts:5141-5144`
  - body: `assistantTexts` can be replaced here, but the result still returns the original `lastAssistant`. Payload generation falls back to `lastAssistant` when replacements are empty or multi-part, so a redaction or suppression hook can leak original assistant text or drive retry/live-switch decisions from stale state.
  - confidence: 0.84
