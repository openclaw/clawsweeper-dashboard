## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Bound the awaited LLM hooks:** `src/plugins/hooks.ts:967`
  - body: This changes `llm_input` from a fire-and-forget observer into an awaited modifying hook, but the default modifying-hook timeout map still does not include `llm_input` or `llm_output`. Existing plugins that previously observed asynchronously can now hang agent turns indefinitely unless the PR adds bounded defaults and coverage for both hooks.
  - confidence: 0.91
- **[P1] Apply systemPrompt overrides to the active model path:** `src/agents/embedded-agent-runner/run/attempt.ts:4147-4148`
  - body: Assigning `llmInputResult.systemPrompt` only to `systemPromptForHook` does not update the active session system prompt or the Google prompt-cache wrapper, which was already built from the old `systemPromptText`. A plugin returning a system-prompt rewrite will therefore see diagnostics/precheck reflect the new value while the provider can still use the original prompt.
  - confidence: 0.9
- **[P1] Rewrite assistant output before downstream observers:** `src/agents/embedded-agent-runner/run/attempt.ts:4948-4949`
  - body: The `llm_output` override is captured only after context-engine afterTurn and `agent_end` have already received `messagesSnapshot` containing the original assistant text. That breaks the advertised redaction use case because internal observers and artifacts can see the unredacted response before the replacement `assistantTexts` is returned.
  - confidence: 0.92
