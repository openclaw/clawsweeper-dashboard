- **[P1] Bound the awaited LLM hooks:** `src/plugins/hooks.ts:967`
  - body: This changes existing observe-only hooks to awaited modifying hooks, but `DEFAULT_MODIFYING_HOOK_TIMEOUT_MS_BY_HOOK` has no defaults for `llm_input` or `llm_output`; an existing plugin that returns a never-settling promise can now hold the model turn indefinitely. Add finite fail-open defaults and regression coverage for both hooks.
  - confidence: 0.91
- **[P1] Apply systemPrompt overrides to the active session:** `src/agents/embedded-agent-runner/run/attempt.ts:4149`
  - body: The PR stores `llmInputResult.systemPrompt` in `systemPromptForHook`, which is used for precheck/trace, but the active session system prompt and Google prompt-cache wrapper were already prepared from `systemPromptText`. A plugin returning `systemPrompt` can therefore be ignored by the model; apply it through the same session system-prompt/cache boundary as `before_prompt_build`.
  - confidence: 0.86
- **[P1] Rewrite assistant output before downstream observers:** `src/agents/embedded-agent-runner/run/attempt.ts:5138`
  - body: The override is only substituted in the returned `assistantTexts`; by this point `before_agent_finalize`, context-engine afterTurn, and `agent_end` have already consumed `messagesSnapshot` and the original assistant text. A redaction plugin would not prevent downstream observers or state from seeing the unredacted response.
  - confidence: 0.88
- **[P2] Document and test the new hook contract:** `src/plugins/hook-types.ts:277-286`
  - body: These result types change public plugin semantics, but current docs still describe `llm_input` and `llm_output` as observation hooks and the PR adds no contract tests. Update `docs/plugins/hooks.md` and focused wired/registry tests so plugin authors know the new contract and compatibility stays guarded.
  - confidence: 0.82
