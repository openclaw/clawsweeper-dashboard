- **[P1] Apply system prompt overrides to the active session:** `src/agents/embedded-agent-runner/run/attempt.ts:4148`
  - body: `llm_input` can return `systemPrompt`, but this assignment only changes `systemPromptForHook` for later checks/telemetry. The active session system prompt and prompt-cache observation were already built from `systemPromptText`, so a plugin can believe it enforced policy while the model still receives the old system prompt.
  - confidence: 0.93
- **[P1] Re-detect prompt images after prompt rewrites:** `src/agents/embedded-agent-runner/run/attempt.ts:4145`
  - body: `imageResult` is computed from the original prompt before this hook runs, then reused for the model call. If a plugin removes an image reference, stale images can still be sent; if it adds one, the new image is never loaded, which breaks the prompt mutation contract and can cross the intended security boundary.
  - confidence: 0.92
- **[P1] Redact downstream state before firing observers:** `src/agents/embedded-agent-runner/run/attempt.ts:4948-4949`
  - body: `llm_output` runs after `messagesSnapshot`, `lastAssistant`, and `agent_end` have already captured the raw assistant response, and this only swaps the returned `assistantTexts`. A redaction plugin would not redact what downstream observers and state consumers already saw, so the advertised response-redaction behavior is leaky.
  - confidence: 0.9
- **[P1] Bound awaited LLM hooks by default:** `src/plugins/hooks.ts:967`
  - body: This converts `llm_input` into an awaited sequential modifying hook, but the default modifying-hook timeout table still has no entry for `llm_input` or `llm_output`. A plugin handler that used to run fire-and-forget can now hang the agent turn unless every operator manually configures a timeout.
  - confidence: 0.88
- **[P2] Document the new prompt-injection policy behavior:** `src/plugins/hook-types.ts:204`
  - body: Adding `llm_input` to `PROMPT_INJECTION_HOOK_NAMES` changes what `plugins.entries.<id>.hooks.allowPromptInjection=false` does, but the existing config/docs still describe only `before_prompt_build` and legacy `before_agent_start` prompt fields. Please update docs/help/tests so operators know `llm_input` prompt/systemPrompt results are also filtered.
  - confidence: 0.86
