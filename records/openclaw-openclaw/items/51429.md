## Summary

Keep this issue open: current main and the latest release still persist resolved default workspace paths into config, and the open linked pull request is the active fix candidate rather than a merged implementation.

## What This Changes

The issue reports that setup/onboarding can persist a machine-specific absolute default workspace path, making OpenClaw appear to use a hardcoded foreign home directory.

## Best Possible Solution

Land a rebased, proof-backed fix that serializes recognized default workspaces as portable ~/.openclaw/workspace values or omits the default, while preserving explicit custom absolute workspaces and covering setup/onboard/configure writes.
