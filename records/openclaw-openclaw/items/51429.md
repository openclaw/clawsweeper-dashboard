## Summary

Current `main` still writes resolved default workspace values into persisted config, so this issue remains necessary; the linked open pull request is the active fix candidate, not a merged implementation.

## What This Changes

The issue asks OpenClaw to stop persisting machine-specific absolute default workspace paths during setup/onboarding/configure and keep the default workspace portable.

## Best Possible Solution

Land a focused fix that canonicalizes only recognized default workspace values before config persistence across setup, onboarding, and configure, with regression tests for default, profile-specific default, and explicit custom workspace cases.
