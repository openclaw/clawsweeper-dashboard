## Summary

Keep open: current main and v2026.6.11 still leave several Chrome MCP existing-session paths without a route-level abort or default call timeout, so a target-browser crash or never-settling upstream call can still strand browser automation work.

## What This Changes

The issue asks Chrome MCP existing-session browser calls to reject and clean up when the target Chrome instance crashes instead of leaving pending promises and halted agent automation.

## Best Possible Solution

Add one Chrome MCP failure boundary that gives every existing-session tool call a bounded timeout/abort path, clears the cached session on timeout/abort/transport loss, and covers target-crash or never-settling raw calls with focused regression tests.

## Reproduction Assessment

Yes from source, but not from a live crash run. Current main has Chrome MCP paths that await raw MCP calls without a default timeout or propagated abort signal, which is enough to reproduce the dangling-promise shape if the upstream call never settles.

## Solution Assessment

Yes, the narrow fix belongs in the Chrome MCP adapter and existing-session route cancellation path. A new config option or agent-level workaround would be worse than making the transport fail boundedly and reset its cached session.

## Repair Work Prompt

Fix https://github.com/openclaw/openclaw/issues/101070 by making Chrome MCP existing-session calls fail boundedly when the target browser or upstream MCP call disappears. In `extensions/browser/src/browser/chrome-mcp.ts`, ensure every `callTool` path has a conservative adapter-level timeout or receives a route-provided timeout/signal, and on timeout/abort/transport loss clear the matching cached session and close the Chrome MCP handle. Thread `req.signal` and appropriate action/snapshot timeouts through the existing-session branches in `extensions/browser/src/browser/routes/agent.act.ts`, `extensions/browser/src/browser/routes/agent.snapshot.ts`, and hooks/basic routes where they call Chrome MCP wrappers without cancellation. Add focused tests that simulate `client.callTool` never resolving for no-explicit-timeout actions like hover/fill/evaluate and verify the promise rejects, the session is reset, and the next call reconnects. Do not add a new public config/env option, do not broaden Browser capabilities, and do not change stable tab-id policy. Treat https://github.com/openclaw/openclaw/issues/80036 and https://github.com/openclaw/openclaw/issues/78602 as context only unless the same bounded cleanup fix directly covers a tested subset.
