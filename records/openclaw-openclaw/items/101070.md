Keep open: current main has partial Chrome MCP timeout/session cleanup, but the reported target-crash path is not covered end to end and several existing-session actions still call Chrome MCP without route abort or explicit timeout wiring.

## Best Possible Solution

Centralize Chrome MCP existing-session cancellation so every route-backed action, including evaluate, wait, coordinate clicks, and navigation-guard probes, rejects and evicts the session on route abort, timeout, transport close, or simulated target crash, with focused regression coverage.
