- `impact:session-state`: Dangling Chrome MCP promises can leave an agent browser automation turn stuck with stale session/tool state.

## Summary

Keep open: current main still has a source-supported Chrome MCP hang path where a never-settling MCP tool call can leave browser automation pending, and the related Chrome MCP timeout/attach issues do not fully own this target-crash cleanup case.

## What This Changes

Report asks Chrome MCP to reject and clean up pending tool calls or sleeps when the target browser crashes instead of leaving agent browser automation hung.

## Best Possible Solution

Chrome MCP should fail and reconnect within bounded time when a tool call never settles after target loss, without adding config surface or changing non-Chrome-MCP browser paths.

## Reproduction Assessment

Yes at source level, but not as a live crash reproduction: current `callTool` can await a never-settling MCP promise indefinitely when no timeout or signal is supplied, and several existing-session routes omit those bounds.

## Solution Assessment

Yes, a narrow browser-plugin repair is the best direction: add bounded default rejection/cleanup for never-settling Chrome MCP tool calls and focused regression tests, while preserving explicit timeout behavior.
