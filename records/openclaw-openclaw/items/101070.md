## Summary

Keep open: current main has useful Chrome MCP timeout/session cleanup, but it still lacks consistent crash/abort wiring for existing-session wait, coordinate click, and evaluate paths, and no merged PR owns the reported target-browser-crash cleanup end to end.

## What This Changes

The issue asks for Chrome MCP in-flight CDP calls and sleep/wait paths to reject and clean up when the target Chrome instance crashes.

## Best Possible Solution

Centralize Chrome MCP existing-session cancellation so route-backed actions reject, evict the session, and unblock the agent on request abort, action timeout, transport close, or target-browser crash, with regression coverage for wait/evaluate/coordinate-click paths.
