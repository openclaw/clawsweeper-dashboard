## Summary

Keep open: current main and the latest release still only bound Chrome MCP calls when a timeout or AbortSignal reaches the shared wrapper, and several existing-session actions plus the wait loop still call Chrome MCP without that wiring. Related Chrome MCP fixes landed, but none clearly owns this target-browser-crash dangling-promise gap.

## What This Changes

Report that Chrome MCP can leave unresolved tool and wait promises when the target browser crashes during a paused breakpoint, wedging browser automation and leaking memory.

## Best Possible Solution

Centralize Chrome MCP existing-session cancellation so every route-backed action and wait path rejects, evicts the cached session, and cleans up on route abort, explicit timeout, transport close, or simulated target-browser crash.
