## Summary

Keep open: current main has partial Chrome MCP timeout and session cleanup, but the target-crash dangling-promise risk is not proven fixed because several existing-session Chrome MCP paths still call the shared tool wrapper without timeout or route-abort wiring and there is no crash-specific regression coverage.

## What This Changes

The issue reports that Chrome MCP can leave CDP/tool correlation and sleep-related awaits pending when the target browser crashes during automation.

## Best Possible Solution

Centralize Chrome MCP existing-session cancellation so every route-backed action rejects, evicts the session, and cleans up on route abort, explicit timeout, transport close, or simulated target-browser crash, with regression coverage for the crash/hang path.
