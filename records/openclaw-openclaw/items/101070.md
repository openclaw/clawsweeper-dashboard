## Summary

Keep open. The exact Chrome-crash breakpoint scenario is not yet proven, but the current Chrome MCP wrapper still has timeout-sensitive paths worth fixing or disproving with a focused regression test rather than closing from source inspection alone.

## What This Changes

The issue reports that Chrome MCP CDP correlation and sleep-timeout waits can remain pending after a target Chrome crash, leaving browser automation halted.

## Best Possible Solution

Bound Chrome MCP readiness and tool-call waits with explicit OpenClaw timeouts/cancellation, reset only the affected session, and add a fake-session regression that proves a hung or crashed target rejects and reconnects.
