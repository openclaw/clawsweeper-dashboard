## Label Justifications

- `P1`: The underlying bug silently loses ambient LINE group context during ordinary concurrent group activity, and the proposed fix still leaves a user-visible history race.
- `merge-risk: 🚨 session-state`: The mismatched snapshot and read boundaries can replay already-consumed group context into a later turn.

## Summary

Keep this PR open: it addresses a valid LINE group-history loss race, but the consumed-key snapshot occurs before the history is actually copied into the inbound context, leaving a narrower race that can replay an already-consumed ambient message on the next turn.

## What This Changes

The PR adds identity-based LINE group-history cleanup so a completed mention turn removes only the ambient entries it consumed rather than deleting the entire group window.

## Best Possible Solution

Capture the history entries and their identity keys atomically at the exact point used to build `InboundHistory`, clear those same identities only after successful processing, and cover arrivals both before and after that capture boundary.

## Solution Assessment

No. Identity-based cleanup is the right direction, but the identity snapshot must be taken at the same boundary as the actual history copy; otherwise the patch substitutes possible duplication for the original loss race.
