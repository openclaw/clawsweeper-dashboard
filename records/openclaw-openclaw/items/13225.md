- `P2`: This is a valid plugin/runtime API enhancement with meaningful routing and security implications, but it is not an urgent broken workflow.

- `impact:auth-provider`: The requested redirect contract directly affects provider and model choice, auth profile selection, and fallback behavior.

## Summary

Keep open: current main still exposes `before_tool_call` as a params/block/approval hook and does not provide the requested pre-tool model/session redirect contract. The closest split-routing PR is closed unmerged, while a later per-tool-routing duplicate was closed back to this issue as the canonical design tracker.

## What This Changes

Request a pre-tool-call hook that can inspect preceding model output and route a pending tool call to another model or session.

## Best Possible Solution

Keep this as the canonical design issue for an additive pre-tool or continuation-routing API with explicit security, audit, provider/auth, fallback, and session-state semantics.

Existing `before_model_resolve` remains useful for prompt-time routing but does not solve pending tool-call delegation.
