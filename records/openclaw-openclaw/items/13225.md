## Label Justifications

- `P2`: This is a meaningful plugin/runtime API enhancement with security and routing implications, but it is not an urgent broken workflow.
- `impact:session-state`: Routing a pending tool call across models or sessions can affect transcript continuity, tool-call IDs, tool-result ownership, cancellation, and compaction state.
- `impact:security`: The requested hook would expose pre-execution context and grant routing authority at a sensitive plugin policy boundary.
- `impact:auth-provider`: The requested redirect contract directly affects provider and model choice, auth profile selection, and fallback behavior.

## Summary

Keep open: current main and v2026.6.11 still expose `before_tool_call` as params/block/approval only, without the requested pre-tool model/session redirect contract. Related implementation attempts are closed unmerged, and the remaining work is a security-sensitive plugin/runtime API decision.

## What This Changes

The issue requests a pre-tool-call hook contract that can inspect preceding assistant output and redirect a pending tool call to another model or session.

## Best Possible Solution

Keep this as the canonical design issue for an additive pre-tool or continuation-routing API with explicit security, audit, provider/auth, fallback, and session-state semantics.

- **Keep hooks params-only:** Leave `before_tool_call` limited to params, block, and approval while using prompt-time model hooks, capability-specific model config, or explicit subagents for routing.
- **Split context from routing:** First add narrowly gated assistant/tool context visibility, then revisit model or session redirection after security review.

Yes, at source-contract level: current `before_tool_call` event/result/runtime code has no redirect, provider, model, session target, or preceding-output contract. This is a feature gap rather than a runtime bug reproduction.

## Solution Assessment

No for the literal event sketch alone; the maintainable solution needs a typed routing phase or hook result that preserves provider/auth, fallback, audit, and session-state contracts. Existing `before_model_resolve` remains useful for prompt-time routing but does not solve pending tool-call delegation.
