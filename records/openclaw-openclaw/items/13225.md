## Label Justifications

- `P2`: This is a valid plugin/runtime API enhancement with meaningful routing and security implications, but it is not an urgent broken workflow.
- `impact:session-state`: Routing a pending tool call across models or sessions can affect transcript continuity, tool-call IDs, tool-result ownership, and compaction state.
- `impact:security`: The requested hook would expose pre-execution context and grant routing authority at a sensitive plugin policy boundary.
- `impact:auth-provider`: The requested redirect contract directly affects provider and model choice, auth profile selection, and fallback behavior.

## Summary

Keep open: current main and v2026.6.11 still expose `before_tool_call` as a params/block/approval hook, not the requested pre-tool model/session routing contract. Related items either overlap only context/approval/subagent mechanics or are closed unmerged, so this remains the canonical product and security design item.

## What This Changes

Request an additive pre-tool-call hook or hook result that can inspect pending tool-call context and redirect execution to another model or session.

## Best Possible Solution

Keep this as the canonical maintainer design item for an additive pre-tool or continuation-routing plugin/runtime API with explicit security, audit, provider/auth, fallback, and session-state semantics.

## Reproduction Assessment

Yes, at the source-contract level: current `before_tool_call` event/result/runtime code has no redirect, model, provider, session target, or preceding-output contract. This is a feature gap rather than a broken-behavior runtime reproduction.

## Solution Assessment

No for the literal event sketch alone; the maintainable solution needs a typed routing phase or hook result that preserves provider/auth, fallback, audit, and session-state contracts. Existing `before_model_resolve` remains useful for prompt-time routing but does not solve pending tool-call delegation.
