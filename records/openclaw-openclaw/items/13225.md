## Summary

Keep open: current main and v2026.6.11 still expose `before_tool_call` as a params/block/approval hook, not the requested pre-tool model/session routing contract. The nearest implementation attempt was closed unmerged and routed back to this issue, while prompt-time model selection through `before_model_resolve` does not cover pending tool-call redirection.

## What This Changes

Requested a pre-tool-call hook that can inspect preceding model output and redirect a pending tool call to another model or session.

## Best Possible Solution

Keep this as the canonical maintainer design item for an additive pre-tool or continuation-routing plugin/runtime API with explicit security, audit, provider/auth, fallback, and session-state semantics while preserving existing params rewrite, block, and approval behavior.

## Reproduction Assessment

Yes for the source-level feature gap: current `before_tool_call` event/result/runtime code has no redirect, provider, model, session target, or preceding-output contract. This is not a broken-behavior runtime reproduction because the item is a feature request.

## Solution Assessment

No for the literal event sketch alone; the maintainable solution is a typed routing phase or hook result that preserves provider/auth, fallback, audit, permission, and session-state contracts. Existing `before_model_resolve` is useful for prompt-time model selection but is not the right layer for pending tool-call redirection.
