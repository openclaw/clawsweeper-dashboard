## Summary

Keep open: current main and the latest release still expose `before_tool_call` as params/block/approval, not a pre-tool model/session routing contract. Related routing/context items are closed unmerged, duplicate back to this issue, or only partially overlap.

## What This Changes

The issue requests a pre-tool-call hook that can inspect preceding assistant output and route a pending tool call to another model or session.

## Best Possible Solution

Keep this as the canonical maintainer design item for an additive pre-tool or continuation-routing plugin/runtime API with explicit security, audit, provider/auth, fallback, and session-state semantics.

## Reproduction Assessment

Yes, at the source-contract level: current `before_tool_call` event/result/runtime code has no redirect, provider, model, session target, or preceding-output contract. This is a feature gap rather than a broken-behavior runtime reproduction.

## Solution Assessment

No for the literal event sketch alone; the maintainable solution needs a typed routing phase or hook result that preserves provider/auth, fallback, audit, and session-state contracts. Existing `before_model_resolve` remains useful for prompt-time routing but does not solve pending tool-call delegation.
