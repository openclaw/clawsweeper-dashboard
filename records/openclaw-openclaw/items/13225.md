## Label Justifications

- `P2`: This is a valid plugin/runtime API enhancement with meaningful routing and security implications, but it is not an urgent broken workflow.
- `impact:session-state`: Routing a pending tool call across models or sessions can affect transcript continuity, tool-call IDs, tool-result ownership, cancellation, and compaction state.

## Summary

Keep open: current main and v2026.6.11 still expose `before_tool_call` as params/block/approval, while prompt-time `before_model_resolve` cannot redirect a pending tool call to another model or session. The related split-routing PRs are closed unmerged or only cover adjacent context fields, so this remains the canonical design item.

## What This Changes

Requests a pre-tool-call hook/API that can inspect preceding model output and route a pending tool call to another model or session.

## Best Possible Solution

Keep this as the canonical design item for an additive pre-tool or continuation-routing plugin/runtime API with explicit security, audit, provider/auth, fallback, and session-state semantics.
