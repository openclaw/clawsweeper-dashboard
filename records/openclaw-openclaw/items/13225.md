## Summary

Keep open: current main and v2026.6.11 still expose `before_tool_call` as a params/block/approval hook, while `before_model_resolve` is prompt-time model selection only. Related routing/context items are closed unmerged, partial, or adjacent, so this remains the canonical pre-tool model/session routing design item.

## What This Changes

Request a pre-tool-call hook/API that can inspect pending assistant context and redirect a tool call to another model or session for delegation.

## Best Possible Solution

Keep this as the canonical maintainer design item for an additive typed pre-tool or continuation-routing API with explicit security, audit, provider/auth, fallback, and session-state semantics while preserving existing rewrite/block/approval behavior.

## Reproduction Assessment

Yes for the source-level feature gap: current `before_tool_call` event/result/runtime code has no redirect, model, provider, session target, or preceding-output contract. This is a feature request, not a failing runtime bug reproduction.

## Solution Assessment

No for the literal event sketch alone; the maintainable solution is a typed routing phase or hook result that preserves provider/auth, fallback, audit, and session-state contracts. The issue should remain open for that product/security design.
