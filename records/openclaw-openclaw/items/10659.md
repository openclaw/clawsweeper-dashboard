## Summary

Current main substantially improves SecretRef storage, runtime resolution, and redaction, but it explicitly still leaves plaintext credentials agent-readable and does not provide the requested agent-blind boundary for arbitrary tool execution. The broader security roadmap remains open, the prior core PR closed unmerged, and the discussion’s user-isolation guide and credential-vault plugin are useful mitigations rather than evidence that the native requirement is complete.

## What This Changes

Requests a native credential boundary that lets agents use selected secrets without reading their raw values, with substitution, output redaction, and command-access controls.

## Best Possible Solution

Adopt a capability-scoped credential-provider design that injects secrets only at the final trusted dispatch boundary, keeps raw values out of agent-readable files, environment, prompts, and tool arguments, and applies exact redaction before streaming, persistence, logging, and delivery; use plugins for vault backends behind a narrow core security contract.

- **Plugin mitigation only:** Keep current generic hooks and document credential-vault plugins as best-effort mitigations without promising agent-blind credentials.
- **OS isolation contract:** State that strong separation requires a separate user, sandbox, or proxy and provide supported deployment guidance rather than an in-process masking feature.

## Reproduction Assessment

Yes, at source level: current documentation confirms that credentials in agent-readable files remain readable, and the exec path returns command output to the agent. No live test with real credentials was appropriate or necessary for this read-only security review.

## Solution Assessment

No, the exact command blocklist and literal-redaction proposal is not the best complete security solution because it is bypassable and cannot enforce same-user isolation. The best direction is a scoped trusted-dispatch credential broker with an explicit threat model and comprehensive output and persistence controls.
