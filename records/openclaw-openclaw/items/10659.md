## Summary

Keep open: current main and v2026.6.11 have substantial SecretRef, audit, redaction, and plugin-hook mitigations, but they still do not implement the native masked-secret boundary requested here for arbitrary agent-executed commands and otherwise-readable plaintext credentials.

## What This Changes

Request to add masked secrets so agents can use API keys without seeing raw values, including placeholder substitution, output redaction, command blocking, and mask-list configuration.

## Best Possible Solution

Ship or explicitly supersede a native credential-isolation design that keeps raw values out of agent-readable files, env, context, and transcripts, with approved redaction, migration/doctor, and plugin or credential-provider boundaries.

## Reproduction Assessment

Yes, at source level: current docs explicitly say readable plaintext credentials remain agent-readable, and current source lacks the requested placeholder or mask-list contract.

## Solution Assessment

Unclear as a final design: the direction is valid, but placeholder substitution, command blocking, redaction, config, migration, and plugin/API shape need maintainer/security design rather than an autonomous patch.
