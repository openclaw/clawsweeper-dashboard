## Summary

Keep open: current main has strong SecretRef, audit, redaction, and plugin-hook mitigations, but it still does not implement the native masked-secret/process-isolation boundary requested here, and the direct masked-secrets PR was closed unmerged.

## What This Changes

The issue requests a native masked-secrets system that lets agents use API keys without seeing raw credential values.

## Best Possible Solution

Keep this as the focused native masked-secrets tracker until maintainers choose and land a security-approved design for dispatch-time credential use, agent-inaccessible raw values, exact output redaction for configured secrets, and plugin/SDK seams for external credential providers.

No autonomous patch is clearly the best fix yet. The best path needs maintainer security/product direction around process isolation, credential injection, redaction semantics, migration, and plugin/SDK extension points.
