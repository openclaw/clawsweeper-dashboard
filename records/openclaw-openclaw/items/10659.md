## Summary

Keep open: current main has substantial SecretRef, audit, redaction, command-scoped resolution, and plugin-hook mitigation work, but it still does not provide the native masked-secret or process-isolation boundary requested here.

## What This Changes

The issue requests a native masked-secrets system that lets agents use credentials without reading raw values, including placeholder substitution, output redaction, command/file blocking, and a mask-list config.

## Best Possible Solution

Keep this issue open until secops/product choose and ship, or explicitly reject, a native credential boundary that keeps raw values out of agent-readable files/env/context while supporting dispatch-time use and auditable redaction.

- **Narrow placeholder safety net:** Implement a limited `{{secret}}` substitution and redaction layer while clearly documenting that it is not a security boundary.

## Solution Assessment

No, the exact placeholder/blocklist proposal is not obviously the best final boundary. The safer path is a maintainer-approved credential-boundary design that decides what belongs in core, SDK hooks, and external plugins before implementation.
