## Summary

Keep open: current main and v2026.6.11 have substantial SecretRef, audit, redaction, host-env sanitization, and plugin-hook mitigations, but they still do not implement the native agent-inaccessible masked-secret boundary requested here.

## What This Changes

Issue requests native masked-secret handling so agent-executed commands can use API keys without exposing raw values to the agent, tool output, or chat history.

## Best Possible Solution

Ship or explicitly supersede a native credential-isolation design that keeps raw values out of agent-readable files, env, model context, tool output, and transcripts, with approved redaction, migration/doctor, and plugin or credential-provider boundaries.

## Reproduction Assessment

Yes, at source level: current docs explicitly say readable plaintext credentials remain agent-readable, and current source lacks the requested placeholder or mask-list contract.

## Solution Assessment

Unclear as a final design: the direction is valid, but placeholder substitution, command blocking, redaction, config, migration, and plugin/API shape need maintainer/security design rather than an autonomous patch.
