## Summary

Keep open: current main has SecretRef, audit, redaction, and plugin-hook mitigations, but the requested native masked-secret boundary is still not implemented; docs explicitly say plaintext paths remain agent-readable and SecretRefs are not a process-isolation boundary.

## What This Changes

The issue requests a masked secret facility that lets users reference credentials without exposing raw API keys to agents, shell commands, transcripts, or ordinary config reads.

## Best Possible Solution

Define the security boundary first, then implement one canonical masked-secret path with migration, audit/doctor support, exec/tool-output rules, and plugin/provider contract coverage.

## Reproduction Assessment

Yes at source level: current docs and schemas show SecretRefs/redaction exist, while plaintext remains readable and no native masked-secret placeholder or mask-list contract exists.

## Solution Assessment

No final implementation shape is proven yet; this needs maintainer security/product design before code because the right boundary spans config, exec, redaction, provider/plugin APIs, and migration behavior.
