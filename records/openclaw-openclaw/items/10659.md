## Summary

Keep this issue open. Current main and v2026.6.11 ship substantial SecretRef storage, scrubbing, command-scoped resolution, exact-value redaction, and provider-egress hardening, but the supported contract explicitly does not isolate credentials from a shell-capable agent. The remaining work is a security-owned product decision about whether OpenClaw should promise agent-blind credential use beyond its trusted-local-agent model.

## What This Changes

Add a native credential boundary so agents can invoke authenticated tools or commands without receiving raw secret values.

## Best Possible Solution

Extend the canonical SecretRef architecture with a capability-scoped credential broker that injects values only at authorized dispatch boundaries, keeps raw values out of agent-readable files and environments, and redacts exact values before model, transcript, log, and channel persistence.

- **Add capability broker (recommended):** Build on SecretRefs with least-privilege dispatch-time injection, a narrow credential-provider plugin API, and end-to-end secret-egress proof.
- **Keep current trust model:** Document SecretRefs as storage and egress hardening only, and support OS isolation, external proxies, or credential-vault plugins for agent-blind use.

## Reproduction Assessment

Yes. Current main and the latest release explicitly document that readable plaintext files and environment credentials remain accessible to shell/file tools and that SecretRefs are not process isolation.

## Solution Assessment

No. The proposed placeholder substitution, broad output scanning, and command blocklists are bypass-prone; a capability-scoped broker integrated with the existing SecretRef and egress-guard architecture is the narrower durable solution.
