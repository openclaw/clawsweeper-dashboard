## Summary

Keep open: current main and the latest release have substantial SecretRef, redaction, audit, and plugin-hook mitigations, but they still do not provide the native masked-secret or process-isolation boundary requested here.

## What This Changes

Request a native masked-secrets system that lets agents use configured credentials without seeing raw API keys, with substitution, output redaction, command policy, and config support.

## Best Possible Solution

Keep this issue open until secops/product choose and ship, or explicitly reject, a native credential boundary that keeps raw values out of agent-readable files, env, context, transcripts, and command output while preserving controlled dispatch-time use.

- **Limited Redaction Safety Net:** Implement a constrained placeholder and redaction layer while documenting that it is not a complete security boundary.

## Reproduction Assessment

Yes, at source level. Current docs say plaintext credentials in agent-readable files remain readable via file or shell tools, and current source lacks the requested placeholder, mask-list config, and native command/output boundary.

## Solution Assessment

No, the exact placeholder-plus-blocklist proposal is not clearly the best final design. The safer path is a maintainer-approved credential-boundary design that decides what belongs in core, SDK hooks, external plugins, and operator isolation.
