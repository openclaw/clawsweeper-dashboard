## Summary

The issue makes a plausible case that message-level optimisation belongs in the context-engine plugin boundary rather than in another prompt hook, but a close or implementation verdict needs direct confirmation of the current context-engine lifecycle, plugin documentation, and VISION.md scope. The related system-prompt hook request is distinct, so it should not be collapsed into this issue.

## What This Changes

The issue recommends using context-engine plugins to optimise model-visible conversation history while preserving OpenClaw’s canonical transcript, instead of extending `before_prompt_build` with message mutations.

## System Context

OpenClaw prepares a model context from an agent transcript, prompt inputs, and token constraints before a provider receives the request. A context engine is the intended boundary for selecting or transforming the model-visible message representation without necessarily changing stored conversation history.
