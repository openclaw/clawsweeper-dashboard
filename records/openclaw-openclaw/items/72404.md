## Summary

Keep open: the Bedrock image-capability bug is valid and the supplied real behavior proof is strong, but this PR is still not merge-ready because the provider-key gate can infer image support for custom/proxy endpoints, one dynamic merge caller still lacks provider identity, the branch is conflicting, and the focused CI shard fails on stale tests.

## What This Changes

The PR adds model-config merge logic and tests to infer `input: ["text", "image"]` for explicit-only known vision model IDs when the provider key is in a built-in allowlist.

## Best Possible Solution

Land a refreshed fix that defaults image input only for provider-owned bundled catalog rows, threads provider identity through every merge path, leaves custom/proxy endpoints explicit, and passes the focused model-config validation.

## Reproduction Assessment

Yes. Current main's merge helper returns explicit-only model rows unchanged when discovery has no matching model, and the media-understanding runtime rejects resolved models whose `input` does not include `image`.

## Solution Assessment

No. The bug fix direction is valid, but the current implementation is partial and unsafe; the safer fix is to gate inference on provider-owned endpoint/transport facts and thread provider identity through all merge paths.
