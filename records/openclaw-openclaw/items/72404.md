- **[P1] Guard inferred image input against custom endpoints:** `src/agents/models-config.merge.ts:164-167`
  - body: `builtInProvider` is derived only from the provider key, so `models.providers.anthropic` or another built-in key with a user-configured `baseUrl`/custom request transport will still get image support inferred from the model ID.   - confidence: 0.87

  - body: The new `providerKey` option defaults to not built-in when omitted, but `mergeImplicitProviderConfig` still calls `mergeProviderModels(implicit, existing)` for dynamic provider-model catalogs. That means one of the stale-catalog repair paths this PR is meant to cover will keep returning Bedrock explicit-only rows without the image input default; pass the provider id through that caller and cover it with a focused test.
  - confidence: 0.86
- **[P2] Update direct tests to pass provider identity:** `src/agents/models-config.merge.explicit-input-default.test.ts:33`
  - body: These tests still call `mergeProviderModels(implicit, explicit)` after the implementation made provider identity required for inference, so the PR's own focused CI fails with `input` remaining undefined.
