## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Guard inferred image input against custom endpoints:** `src/agents/models-config.merge.ts:164-167`
  - body: The new built-in check only looks at `providerKey`, but OpenClaw supports `models.providers.<id>.baseUrl` and request overrides on provider entries. A user can keep a built-in key like `anthropic` or `openai` while pointing at a proxy that never declared image support, and this branch will still inject `input: ["text", "image"]` from the model name, causing image attachments to be sent to that endpoint. Please gate the default on the bundled endpoint/transport contract or require explicit `input` whenever endpoint/request transport is overridden.
  - confidence: 0.92
- **[P1] Thread provider identity into implicit catalog merges:** `src/agents/models-config.merge.ts:164-167`
  - body: `builtInProvider` becomes false whenever `opts.providerKey` is absent, but `mergeImplicitProviderConfig` still calls `mergeProviderModels(implicit, existing)` in the dynamic provider path. That means built-in providers merged during discovery/wildcard visibility can still preserve stale explicit-only rows with `input: undefined`, which is one of the paths this PR is meant to repair. Pass `providerId` through that caller and add coverage for it.
  - confidence: 0.9
- **[P2] Update direct tests for the provider-key gate:** `src/agents/models-config.merge.explicit-input-default.test.ts:33`
  - body: After adding the provider-key gate, the new positive tests still call `mergeProviderModels` without a `providerKey`, so they assert a default the implementation now refuses; CI shows six failures from these assertions. Update the helper-level tests to pass a built-in provider key or change the expected contract so the suite covers the supported path.
  - confidence: 0.96
