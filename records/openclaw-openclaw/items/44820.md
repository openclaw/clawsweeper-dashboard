## Summary

Keep open: current main and v2026.6.11 only partially address the session artifact disk-bloat report. Deleted/reset archive retention and unreferenced-artifact cleanup exist, but normal maintenance still preserves old `.bak.*` archives, startup reads do not run full cleanup, and the open cleanup PR only covers a narrower deleted/reset reporting path.

## What This Changes

The issue requests automatic cleanup of stale session artifact files such as `.reset.*`, `.deleted.*`, `.tmp`, and `.bak.*` under agent session directories.

## Best Possible Solution

Land or replace the targeted deleted/reset cleanup reporting PR, then make a maintainer decision on the durable session artifact lifecycle for `.bak.*`, orphan/unindexed transcript archive/prune, and any proactive startup/timer sweeps.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level, but not through a live multi-day filesystem run: current code and tests show `.bak.*` archives are preserved in normal retention, CLI cleanup does not yet report deleted/reset archive cleanup on main, and startup reads do not run full pruning.

## Solution Assessment

Is this the best way to solve the issue? Unclear for the full issue: reusing existing archive-retention helpers is the best narrow path for deleted/reset cleanup, but `.bak.*` deletion and proactive sweeps need a maintainer-approved lifecycle policy.
