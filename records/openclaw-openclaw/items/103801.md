## Summary

This PR remains necessary because current `main` still has the reported gateway hot-reload divergence, but the exact-head patch does not fully serialize runtime snapshot activation with subsystem publication. The previously reported P1 remains: another secrets activation can interleave after `activatePreparedSnapshot` releases its queue and before `setState` publishes hooks, cron, and heartbeat state. The automated checks are green, but they do not exercise that concurrency window, and the PR contains no after-fix real managed-gateway proof.

## What This Changes

Delays runtime-config snapshot activation until gateway subsystem publication and moves shared auth-session generation changes until after a successful hot reload.

## Best Possible Solution

Provide one canonical runtime-secrets transaction API that keeps prepared-snapshot activation, gateway subsystem `setState`, and generation-dependent auth-client transition inside the same serialized critical section, with concurrent-activation, rollback, and live managed-gateway proof.
