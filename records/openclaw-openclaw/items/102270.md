## Summary

Keep open. Current main still runs managed npm plugin installs with lifecycle scripts disabled, so native addon build scripts such as better-sqlite3's install step are intentionally skipped; the remaining question is the secure product shape for diagnostics or opt-in rebuild support, not cleanup closure.

## What This Changes

The issue asks OpenClaw plugin installs to handle or clearly diagnose native addon dependencies such as better-sqlite3 so installed plugin tools do not fail later with missing .node bindings.

## Best Possible Solution

Keep lifecycle scripts disabled by default, add a generic native-addon diagnostic or install-time warning with an actionable rebuild/plugin-publisher path, and only add trusted opt-in rebuild support if maintainers explicitly accept that security tradeoff.

- **Add trusted opt-in rebuild:** Introduce a manifest or policy-gated native rebuild path for trusted packages only, with explicit security docs and focused upgrade tests.
- **Leave plugin-owned:** Reaffirm that native addon rebuilds are plugin-owned and close or document this as unsupported, accepting that users may still see late generic runtime failures.

## Reproduction Assessment

Yes, from source inspection: OpenClaw's managed npm plugin install path passes --ignore-scripts, while the reported dependency chain includes better-sqlite3 with a native install script. I did not run the live Node 24 Camofox tool call scenario.

## Solution Assessment

No, automatically running npm rebuild as the default is not clearly the best fix because it weakens the current script-disabled security model. The safer maintainable path is diagnostics by default, with a separately approved trusted opt-in rebuild contract if maintainers want native-addon install support.
