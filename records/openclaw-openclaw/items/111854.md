## Summary

The issue remains necessary: current main intentionally constructs the internal oversized-transcript placeholder with `__openclaw.truncated`, while the report identifies that the Control UI presents that transport marker as an ordinary user turn. The core transcript safeguard should remain; the display projection/UI needs a bounded rendering rule for the metadata.

## What This Changes

Hide or distinctly render oversized transcript placeholders in the Control UI instead of showing `[chat.history omitted: message too large]` as a normal user message.

## Best Possible Solution

Keep the Gateway placeholder for safe transcript recovery, but have the Control UI recognize `__openclaw.truncated.reason === "oversized"` and render a non-user warning/omission state (or omit it), with focused coverage for an oversized user turn.
