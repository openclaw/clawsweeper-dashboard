## Summary

Keep open: current main and the latest release still resolve `${XDG_CONFIG_HOME}` as a literal path segment in the shared workspace/skill-install path flow, while the only linked fix candidate is an open fork PR that has not landed upstream.

## What This Changes

The issue requests that skill installation expand `${XDG_CONFIG_HOME}` from the environment instead of installing under a literal `${XDG_CONFIG_HOME}` directory.

## Best Possible Solution

Keep this issue as the canonical tracker until maintainers approve and land one focused path-resolution or dotenv-expansion fix with regression coverage for skill installs and the shared resolver semantics.

## Reproduction Assessment

Yes, at source level. Current main sends placeholder-containing workspace paths through resolvers that expand only `~`, then skill install appends `skills/<slug>` under that unresolved path.

## Solution Assessment

Unclear. Shared env-placeholder expansion is a plausible boundary, but maintainers should decide the cross-surface semantics for unknown, empty, and sensitive variables before landing it broadly.
