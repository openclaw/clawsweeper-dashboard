## Summary

Keep open: current main and the latest release still resolve configured user/workspace paths without expanding `$VAR` or `${VAR}`, so the reported skill install path can still become a literal placeholder directory. A linked fork PR proposes the expected resolver-level fix, but no target-repo fix has merged.

## What This Changes

The issue asks OpenClaw to expand `${XDG_CONFIG_HOME}` from the environment when resolving skill install/workspace paths instead of creating a literal placeholder directory.

## Best Possible Solution

Land one target-repo fix that expands documented env placeholders in shared user-path resolution with focused skill-install coverage, while leaving broader dotenv value interpolation to https://github.com/openclaw/openclaw/issues/38259.
