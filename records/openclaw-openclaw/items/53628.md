## Summary

Keep open: current main and v2026.6.11 still leave `${VAR}` path placeholders literal in the workspace path flow used by ClawHub skill installs, and the linked fork PR is open but not a landed or clearly complete fix.

## What This Changes

The issue requests that skill installation expand `${XDG_CONFIG_HOME}` from the Docker environment instead of writing into a literal `${XDG_CONFIG_HOME}` directory.

## Best Possible Solution

Land one focused, maintainer-approved path-resolution fix that covers configured workspaces and direct workspace env overrides, preserves safe behavior for unresolved placeholders, adds regression coverage for ClawHub skill install targets, and then close this issue.

## Reproduction Assessment

Yes, at source level. Current main sends placeholder-containing workspace paths through resolver branches that only expand `~`, then ClawHub skill install appends `skills/<slug>` under that unresolved path.

## Solution Assessment

Unclear. Shared resolver expansion is a plausible boundary, but the current linked PR is not clearly the best fix because maintainers still need approved semantics for unknown, empty, and sensitive variables and likely need to cover the direct `OPENCLAW_WORKSPACE_DIR` branch too.
