## Summary

Keep open: current main and the latest release still leave `$VAR` and `${VAR}` placeholders literal in the shared user/workspace path resolver that feeds ClawHub skill install targets, and the direct linked fix PR is still open and unmerged.

## What This Changes

The issue requests that `${XDG_CONFIG_HOME}` be expanded when resolving the workspace path used for ClawHub skill installation, instead of creating a literal `${XDG_CONFIG_HOME}` directory.

## Best Possible Solution

Land or replace the linked path-resolution fix with maintainer-approved env-placeholder semantics and focused coverage for configured agent workspaces, ClawHub skill installs, unknown variables, and the boundary with https://github.com/openclaw/openclaw/issues/38259.

## Reproduction Assessment

Yes. Source inspection shows a configured workspace such as `${XDG_CONFIG_HOME}/workspace` is passed through `resolveUserPath` and then into the ClawHub install target without `$VAR` or `${VAR}` expansion; I did not perform a live Docker write in this read-only review.

## Solution Assessment

Unclear. Expanding env placeholders in the shared resolver is a plausible narrow fix, but maintainers should first confirm missing-variable behavior and whether dotenv or `OPENCLAW_WORKSPACE_DIR` expansion is part of the intended contract.
