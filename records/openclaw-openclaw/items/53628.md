## Summary

Keep open: current main and v2026.6.11 still leave `$VAR` and `${VAR}` placeholders literal in the shared path flow used before ClawHub skill install targets are built, and all same-repository fix PRs are closed unmerged. The issue remains the canonical OpenClaw tracker while maintainers choose the shared resolver semantics.

## What This Changes

Ensure skill installs that resolve paths containing `${XDG_CONFIG_HOME}` or similar env placeholders use the environment value instead of creating literal placeholder directories.

## Best Possible Solution

Land one maintainer-approved shared path resolver update that expands env placeholders for configured user paths while preserving safe unresolved-variable behavior and adding resolver plus ClawHub install coverage.

## Reproduction Assessment

Yes. Source inspection shows `${XDG_CONFIG_HOME}/workspace` follows resolver branches that only expand `~`, then ClawHub skill install appends `skills/<slug>` under that unresolved path.

## Solution Assessment

Unclear. Fixing the shared resolver is likely the right boundary, but maintainers should choose cross-surface semantics for unknown, empty, and sensitive env variables before landing it broadly.
