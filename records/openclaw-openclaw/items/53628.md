## Summary

Keep open: current main and v2026.6.11 still leave `$VAR` and `${VAR}` placeholders literal in the shared user/workspace path flow used by skill install targets, while a linked open fix candidate still needs maintainer review for shared env-expansion semantics.

## What This Changes

The issue reports that skill installation treats `${XDG_CONFIG_HOME}` as a literal directory segment instead of expanding it from the Docker environment.

## Best Possible Solution

Keep this issue as the canonical tracker and review the linked fix PR or an equivalent maintainer-approved resolver change with regression coverage and upgrade-safety notes.

## Reproduction Assessment

Yes, at source level: current main sends non-tilde placeholder paths through `path.resolve` and then appends `skills/<slug>` under that unresolved workspace target. I did not run a live Docker install in this read-only review.

## Solution Assessment

Unclear. Shared resolver expansion is the likely narrow boundary, but maintainers still need to approve cross-surface semantics for unknown, empty, and sensitive env variables before landing it broadly.
