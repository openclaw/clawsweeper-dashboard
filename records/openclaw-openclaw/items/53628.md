## Summary

Keep open: current main and v2026.6.11 still leave `$VAR`/`${VAR}` placeholders literal in the shared user/workspace path flow used before ClawHub skill install targets are built, and the linked fix PR is still open and unmerged.

## What This Changes

The issue reports that ClawHub skill installation treats `${XDG_CONFIG_HOME}` as a literal path segment instead of expanding it to the configured environment value.

## Best Possible Solution

Land one maintainer-selected shared user-path resolver fix that expands explicit env placeholders safely, preserves or diagnoses unresolved placeholders, covers ClawHub skill install with regression proof, and then close this issue.

## Reproduction Assessment

Yes, from source inspection. Current main sends `${XDG_CONFIG_HOME}/workspace` through resolver paths that only expand leading `~`, then skill install appends `skills/<slug>` under that unresolved path.

## Solution Assessment

Unclear. Shared env-placeholder expansion is likely the right boundary, but maintainers should choose the cross-surface semantics for unknown, empty, and sensitive variables before landing it broadly.
