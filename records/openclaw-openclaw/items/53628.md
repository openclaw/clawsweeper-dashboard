## Summary

Keep open: current main still sends configured workspace paths through a resolver that expands only `~`, so `${XDG_CONFIG_HOME}` can still be preserved literally before ClawHub skill install writes under `<workspace>/skills/<slug>`. The remaining fix is real but compatibility-sensitive because it changes shared path/env semantics beyond this one install path.

## What This Changes

The issue reports that skill installation treats `${XDG_CONFIG_HOME}` from Docker `.env` configuration as a literal directory name instead of expanding it before resolving the skill path.

## Best Possible Solution

Land or replace one focused shared path resolver update with workspace and ClawHub skill-install coverage, while documenting the boundary between config substitution, dotenv expansion, and path resolution.
