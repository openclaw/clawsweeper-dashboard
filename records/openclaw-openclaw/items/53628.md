## Label Justifications

- `P2`: The bug misroutes skill installs for users with env-placeholder workspace paths, with real but bounded Docker/ClawHub impact.
- `impact:data-loss`: Installed skill files can be written under a literal placeholder directory instead of the intended workspace, making user-installed skill data appear missing from the configured location.
- `maturity:stable`: The affected CLI/Gateway skill install path maps to M4 Stable surfaces in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and v2026.6.11 still only expand `~` in the shared user-path resolver, so a configured skill workspace containing `${XDG_CONFIG_HOME}` can still resolve to a literal placeholder path. The linked open fork PR is a fix candidate, but this issue should stay open until maintainers choose the shared path/env expansion semantics and land a reviewed fix.

## What This Changes

The issue reports that ClawHub skill installation in Docker writes under a literal `${XDG_CONFIG_HOME}` workspace path instead of the expanded config-home path.

## Best Possible Solution

Choose the shared path placeholder semantics, then land a focused resolver fix with tests for skill install paths, known env vars, unknown or empty vars, escaped literals, and tilde interaction.
