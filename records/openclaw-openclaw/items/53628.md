## Summary

Keep open: current main and the latest release still leave `$VAR` and `${VAR}` placeholders literal in the shared user-path resolver used before ClawHub skill install targets are built, and the linked fix PR is still open and unmerged.

## What This Changes

The issue asks skill installation to expand `${XDG_CONFIG_HOME}` in the target workspace path instead of creating a literal `${XDG_CONFIG_HOME}` directory.

## Best Possible Solution

Land one maintainer-approved shared path resolver update that expands supported `$VAR` and `${VAR}` workspace paths, preserves safe behavior for unresolved placeholders, adds focused regression coverage, and then close this issue once the behavior is on main.

## Reproduction Assessment

Yes, from source inspection. Current main sends `${XDG_CONFIG_HOME}/workspace` through resolver paths that only expand `~`, then skill installation appends `skills/<slug>` under that unresolved path.

## Solution Assessment

Unclear. Shared resolver expansion is likely the right boundary, but maintainers should choose the cross-surface semantics for unknown, empty, and sensitive env variables before landing it broadly.
