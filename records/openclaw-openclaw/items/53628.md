## Summary

Keep open: the reported skill-install path problem is still source-reproducible when an unresolved workspace path containing `${XDG_CONFIG_HOME}` reaches the skill installer. Current Docker Compose pins container-side paths for fresh installs, but the shared workspace/path interpolation boundary still needs a maintainer decision before this should be treated as fixed.

## What This Changes

The issue asks OpenClaw/ClawHub skill installation to expand `${XDG_CONFIG_HOME}` from the environment instead of installing under a literal `${XDG_CONFIG_HOME}` directory.

## Best Possible Solution

Settle one env-interpolation contract for workspace/config paths, then land or replace the resolver/config-dotenv fix with focused regression coverage for Docker workspace paths and ClawHub skill install targets.
