## Label Justifications

## Summary

Keep open: current main and the latest release still leave `$VAR` and `${VAR}` placeholders literal in the shared user/workspace path flow used before ClawHub skill install targets are built, and an open linked fork PR still proposes the unresolved fix path.

## What This Changes

The issue reports ClawHub skill installs treating `${XDG_CONFIG_HOME}` as a literal path segment instead of expanding it from the Docker environment.

## Best Possible Solution

Land or explicitly reject a shared resolver/env-loading fix that covers approved user/workspace path placeholders with focused tests and clear compatibility/security semantics.

## Reproduction Assessment

Yes from source inspection: current `resolveHomeRelativePath` does not expand `$VAR` or `${VAR}`, and skill install target resolution preserves a literal workspace path. I did not run the Docker install flow, so this is source-reproducible rather than a live reproduction.

## Solution Assessment

Unclear: expanding shared user-path placeholders is likely the right layer if maintainers want config/env interpolation, but AGENTS.md makes those semantics compatibility-sensitive and the broader dotenv issue may be part of the right boundary.
