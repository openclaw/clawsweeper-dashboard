## Summary

Keep open: current main and v2026.6.11 still pass `$VAR` and `${VAR}` placeholders through the shared user/workspace path resolver, and an open linked fork PR still proposes the unresolved fix path.

## What This Changes

The issue reports that ClawHub skill installation treats `${XDG_CONFIG_HOME}` from Docker `.env` as a literal directory segment instead of expanding it before resolving the skill install path.

## Best Possible Solution

Land one focused shared path resolver update that expands approved env placeholders before filesystem resolution, preserves or clearly rejects unresolved placeholders, covers ClawHub skill install tests, then close this issue and retire unchosen overlapping PRs.
