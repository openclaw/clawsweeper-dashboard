- `impact:data-loss`: Installed skill files can be written into an unintended literal `${XDG_CONFIG_HOME}` directory and be absent from the configured active workspace.

## Summary

Keep open: current main and v2026.6.11 still leave `$VAR` and `${VAR}` placeholders literal in the shared user/workspace path flow used before ClawHub skill install targets are built, and the linked fix candidate is still open and unmerged.

## What This Changes

The issue asks OpenClaw to expand `${XDG_CONFIG_HOME}` and similar env placeholders in skill-install workspace paths so ClawHub installs land under the resolved active workspace.

## Best Possible Solution

Land or replace the linked fix with a maintainer-approved shared user-path env expansion policy, regression coverage for workspace and skill installs, and Docker-style proof; otherwise document that env placeholders are unsupported in these paths.

## Reproduction Assessment

Yes, at source level. Current main sends configured workspace paths through `resolveUserPath`, which only expands `~`, then skill install appends `skills/<slug>` under the unresolved path.

## Solution Assessment

Unclear. Shared resolver expansion is the likely right boundary, but maintainers need to choose the cross-surface semantics for unknown, empty, and sensitive env variables before landing it broadly.
