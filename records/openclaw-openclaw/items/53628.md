## Summary

Keep open: the reported Docker skill-install path bug still has a source-level path where `${XDG_CONFIG_HOME}` can remain literal, and the linked open fork PR needs maintainer review rather than issue cleanup.

## What This Changes

The issue asks OpenClaw to expand `${XDG_CONFIG_HOME}` when resolving ClawHub skill install targets so Docker installs do not create a literal `${XDG_CONFIG_HOME}` directory.

## Best Possible Solution

Settle the canonical env-expansion boundary, then land a narrow tested fix for skill/workspace paths or add doctor/docs guidance that prevents literal placeholder paths from being used as install targets.
