## Summary

Keep open: current main and the latest release still leave visible Control UI Settings text and schema-derived field labels in English for Chinese locales, while the linked implementation PRs are open partial candidates rather than merged fixes.

## What This Changes

Translate the Control UI Settings/configuration surface into Chinese, including Settings chrome, Quick Settings copy, section/category labels, and schema-derived field labels.

## Best Possible Solution

Adopt one Settings i18n contract that covers toolbar chrome, Quick Settings, section metadata, and schema/uiHint-derived field labels with English fallback, then rebase or replace the open partial PRs against that contract.

## Maintainer Decision

Question: What Settings localization contract should OpenClaw support for schema/uiHint-derived config labels, and how should the two open partial Settings localization PRs be sequenced?

Rationale: UI chrome can follow the existing t() and generated-locale pipeline, but schema-derived labels require a maintainer-owned key shape and fallback behavior across config schema metadata and Control UI rendering.

Likely owner: steipete

Owner reason: steipete has adjacent Settings/config history and is the best available owner for the UX/API tradeoff between config schema metadata and Control UI localization.

Owner confidence: medium

Options:

- **Define one Settings i18n contract (recommended):** Choose a single key/fallback design for Settings chrome, section metadata, Quick Settings, and schema labels, then ask the open PRs to rebase or be replaced against it.
- **Land low-risk chrome slices first:** Accept narrow toolbar or Quick Settings localization PRs after proof, while keeping schema-derived labels explicitly open on this issue.
- **Defer schema-label localization:** Limit current work to non-schema UI chrome and document that schema/uiHint labels remain English until a later config metadata design.

## Reproduction Assessment

Yes. Source inspection on current main shows the Settings page still renders English toolbar, Appearance, Quick Settings, section/category, and schema-derived labels when zh-CN is selected; I did not run a live browser session in this read-only review.

## Solution Assessment

Unclear for the final implementation shape. Existing t() and generated locale infrastructure is the right boundary for UI chrome, but schema-derived field labels need a maintainer-approved lookup and fallback contract before automation should attempt the full fix.
