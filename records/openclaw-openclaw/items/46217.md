Define one Settings i18n contract that routes toolbar, quick-settings, section metadata, and schema/uiHint field labels through generated locale keys with English fallback, then land focused PRs against that contract.

Unclear for the final implementation shape. Existing `t()`/generated locale infrastructure is the right boundary for UI chrome, but schema-derived field labels need a maintainer-approved lookup and fallback contract before a full fix should be automated.
