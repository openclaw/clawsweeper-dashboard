## Summary

Keep open: current main still has English Settings chrome, Appearance/Quick Settings copy, and schema-derived config labels for Chinese locales, while the linked PRs are open partial fixes rather than merged coverage.

## What This Changes

The issue requests fuller Chinese localization for the Control UI Settings section and its configuration labels.

## Best Possible Solution

Define one Settings i18n contract covering toolbar chrome, Quick Settings/Appearance copy, section metadata, and schema/uiHint-derived labels, then sequence or replace the partial PRs against that contract.

Likely owner: steipete

Options:

- **Define One Settings I18n Contract (recommended):** Sponsor a single key/fallback design for Settings chrome, Quick Settings, section metadata, and schema labels, then ask contributors or ClawSweeper to rebase or replace the partial PRs against it.
- **Land Chrome Slices First:** Review and land toolbar or Quick Settings localization as narrow PRs while keeping schema-derived labels tracked here as explicit follow-up work.
- **Defer Schema-Label Localization:** Limit near-term work to fixed Settings UI chrome and keep schema-derived config labels English until maintainers want a broader config metadata translation API.

## Solution Assessment

Unclear for the final implementation shape. Existing t() and generated locale infrastructure is the right boundary for fixed UI chrome, but schema-derived field labels need a maintainer-approved lookup and fallback contract before a full fix should be automated.
