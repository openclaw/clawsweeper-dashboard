## Summary

Keep open: current main and the latest release still lack a shared Android/iOS transport-auth contract, setup-code metadata, and native WebSocket upgrade-header support for authenticated reverse proxies; the Android attempt is closed unmerged and the open iOS PR covers only a Basic-auth subset with unresolved proof/security blockers.

## What This Changes

The issue requests transport-level reverse-proxy authentication metadata and mobile client support so Android and iOS can send Basic, bearer, fixed-header, cookie, or OIDC proxy credentials before the gateway WebSocket upgrade.

## Best Possible Solution

Define a staged shared mobile transport-auth contract for setup-code and manual Gateway connections, land TLS-only static header support first if approved, and split OIDC into a separate security-reviewed browser-return design with real proxy proof.
