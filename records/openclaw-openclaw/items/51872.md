## Summary

Keep open: current main still does not carry proxy-auth metadata through QR/setup-code or manual mobile connect flows, Android and iOS still open WebSocket upgrades without proxy credentials, and the only active PR covers a narrower iOS/macOS Basic-auth slice with unresolved review blockers.

## What This Changes

The issue requests transport-level proxy authentication for non-web mobile clients so Android and iOS can pass Basic, bearer, fixed-header, cookie, or OIDC proxy credentials before the Gateway WebSocket upgrade.

## Best Possible Solution

Define a shared mobile transport-auth contract covering static proxy headers, credential storage/clearing/redaction, TLS requirements, setup-code/manual-entry behavior, and whether OIDC is a separate follow-up, then land proof-backed Android and iOS slices against that contract.

## Reproduction Assessment

Not applicable as a bug: this is a missing feature request, not broken documented behavior. Source inspection confirms current setup-code, Android, and iOS WebSocket paths do not carry proxy-layer auth fields before the HTTP upgrade.

## Solution Assessment

Unclear as proposed: static bearer/basic support is a plausible first slice, but the best maintainable fix needs shared mobile credential and security direction for Android, iOS, fixed headers, cookies, and OIDC before broad implementation proceeds.
