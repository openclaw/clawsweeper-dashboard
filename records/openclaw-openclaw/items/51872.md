## Summary

Keep open: current main and v2026.6.11 still lack a shared Android/iOS transport-auth contract for reverse-proxy credentials, and the open iOS PR covers only a Basic-auth subset while Android, bearer/custom-header/cookie, and OIDC behavior remain unresolved.

## What This Changes

Request support for passing reverse-proxy authentication metadata from setup/QR bootstrap or manual connection into Android and iOS transport requests before the gateway WebSocket upgrade.

## Best Possible Solution

Define a small shared mobile reverse-proxy transport-auth contract for setup/manual connection, credential lifecycle, and WebSocket upgrade headers, then land platform-specific Basic-first support with security review and live proxy proof before expanding to bearer/custom/OIDC modes.
