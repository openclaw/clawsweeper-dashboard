## Summary

Keep open: current main and the latest release still lack a mobile pre-upgrade proxy-auth path for Android/iOS WebSocket connects or setup-code metadata, while the related Android PR is closed unmerged and the narrower iOS Basic-auth PR remains open with proof/security blockers.

## What This Changes

Request transport-level proxy auth metadata and mobile-client support so Android/iOS can connect through authenticating reverse proxies before the Gateway protocol handshake.

## Best Possible Solution

Define a maintainer-approved mobile transport-auth contract, including setup-code fields, supported auth schemes, secure credential storage/reset rules, and live proxy proof, then land focused platform implementations against that contract.

## Reproduction Assessment

Yes for the missing support path: current main builds native mobile WebSocket upgrade requests without proxy headers and setup codes cannot carry proxy-auth metadata. I did not run a live Caddy/nginx mobile reproduction in this read-only review.

## Solution Assessment

No current implementation is the best complete fix yet. The likely solution needs a shared mobile transport-auth contract first, because the linked PRs cover only partial Android/iOS slices and raise credential lifecycle/security questions.
