## Summary

Keep open: current main still does not provide proxy-auth metadata in mobile setup/manual connect payloads or attach pre-upgrade proxy headers from Android/iOS clients, and the related implementation work is either closed unmerged or only a blocked iOS Basic-auth slice.

## What This Changes

The issue requests mobile/client support for transport-level reverse-proxy authentication such as bearer tokens, Basic auth, fixed headers, cookies, and OIDC handoff so Android/iOS clients can reach a protected Gateway before the WebSocket upgrade.

## Best Possible Solution

Define a shared Android/iOS mobile Gateway transport-auth contract, split static header support from OIDC if needed, and land proof-backed implementation slices only after credential storage, clearing, TLS, redaction, and setup-code behavior are settled.

## Reproduction Assessment

Yes by source inspection for the missing capability: current setup-code, Android, and iOS WebSocket paths do not carry proxy-auth metadata or pre-upgrade headers. I did not run a live authenticated reverse proxy because this is a read-only cleanup review.

## Solution Assessment

Unclear as proposed: static Basic/Bearer support is a plausible first slice, but the best maintainable solution needs shared mobile credential and security direction for Android, iOS, fixed headers, cookies, and OIDC.
