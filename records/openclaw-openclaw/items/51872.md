## Summary

Keep open: current main and latest stable release still lack mobile WebSocket upgrade-header/auth metadata support for authenticated reverse proxies; the Android bearer/basic PR closed unmerged, and the open iOS Basic-auth PR is only a partial candidate with proof and security blockers.

## What This Changes

Request support for native mobile clients to carry reverse-proxy transport authentication, including Bearer, Basic, fixed headers/cookies, and possible OIDC, through setup-code or manual gateway connections before WebSocket upgrade.

## Best Possible Solution

Define a shared secure mobile transport-auth contract for setup-code/manual gateway connections, then land reviewed per-platform slices with credential lifecycle, cleartext safeguards, docs, and real reverse-proxy proof.
