## Summary

Keep open: current main still lacks a shared mobile transport-auth contract and does not carry reverse-proxy auth metadata through setup-code/manual Android or iOS WebSocket upgrade paths; the linked PRs are partial candidates, with the Android one closed unmerged and the iOS Basic-auth one still open with blockers.

## What This Changes

Request support for mobile clients to send reverse-proxy authentication material, including bearer/basic/static headers/cookies and possible OIDC, before the Gateway WebSocket upgrade.

## Best Possible Solution

Define a shared mobile transport-auth contract, split static proxy headers from OIDC if needed, specify credential storage/clearing/redaction/TLS rules, then land proof-backed Android and iOS slices against that contract.

## Reproduction Assessment

Not applicable as a bug: this is a missing feature request. Source inspection gives high-confidence current-main proof that setup-code, Android, and iOS WebSocket paths do not carry pre-upgrade proxy-auth headers.

## Solution Assessment

Unclear as proposed: static bearer/basic support is a plausible first slice, but the broader cookie/fixed-header/OIDC and credential-lifecycle design needs product and security direction. The existing open iOS PR should be reviewed as a partial candidate, not treated as the full fix.
