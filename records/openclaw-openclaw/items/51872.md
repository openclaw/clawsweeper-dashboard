## Summary

Keep open: current main and v2026.6.11 still lack a shared Android/iOS transport-auth contract for authenticated reverse proxies, and the related Android/iOS PRs do not cover or land the full requested behavior.

## What This Changes

The issue requests transport-level proxy authentication support for native clients, including setup-code metadata and mobile handling for bearer, Basic, fixed headers, cookies, and OIDC before the Gateway WebSocket upgrade.

## Best Possible Solution

Define a shared mobile transport-auth contract for setup-code and manual Gateway connections, stage static header support separately from OIDC, and require secure storage, clearing, redaction, TLS, endpoint-change handling, and real proxy proof before landing platform slices.

- **Decline native proxy credentials:** Document authenticated reverse proxies as unsupported for native mobile clients and recommend VPN, tunnel, WebChat, or proxy configuration alternatives.
