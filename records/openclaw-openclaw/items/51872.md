## Summary

Keep open: current main still lacks mobile setup-code metadata and native Android/iOS WebSocket header support for reverse-proxy transport auth, while the related iOS PR is only a narrower Basic-auth candidate and the Android candidate is closed unmerged.

## What This Changes

The issue requests support for mobile clients to carry reverse-proxy transport authentication such as bearer/basic/fixed headers/cookies and possible OIDC before the Gateway WebSocket upgrade.

## Best Possible Solution

Keep this broad issue open for a maintainer-approved mobile transport-auth contract, split the implementation into safe static-header and OIDC slices if needed, and use the narrower iOS PR only after its blockers are resolved.

Yes, at source level for the missing capability: current main has no setup-code field or native mobile WebSocket header path for reverse-proxy credentials. I did not run a live Android/iOS plus proxy reproduction in this read-only cleanup review.

## Solution Assessment
