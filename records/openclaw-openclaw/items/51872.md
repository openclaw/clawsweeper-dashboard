## Summary

Keep open: current main and v2026.6.11 still lack a shared Android/iOS transport-auth contract for proxy credentials; the Android attempt closed unmerged and the open iOS PR covers only a Basic-auth subset.

## What This Changes

Request adds transport-level proxy authentication metadata and mobile client handling so iOS/Android can connect to gateways behind Basic, Bearer, fixed-header, cookie, or OIDC authenticating reverse proxies.

## Best Possible Solution

Define a shared, security-reviewed mobile transport-auth contract for setup codes/manual config, then land narrow app implementations with secure storage, redaction, reset semantics, docs, and live proxy proof.

## Reproduction Assessment

Yes. Source inspection shows the native Android and shared iOS/macOS WebSocket paths construct upgrade requests with URL-only inputs and no proxy-auth metadata/settings; I did not run a live proxy environment in this read-only review.

## Solution Assessment

Unclear. Setup-code metadata plus mobile WebSocket header support is plausible for Basic/Bearer, but OIDC and generic fixed headers/cookies need maintainer security/product direction before that becomes the best complete shape.
