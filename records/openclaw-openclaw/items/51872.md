## Summary

Keep open: current main still lacks proxy-auth metadata in mobile setup/manual connection paths and does not attach proxy auth headers to Android or iOS WebSocket upgrades; the old Android PR is closed unmerged, and the newer iOS Basic-auth PR is only a partial, still-open slice.

## What This Changes

Request support for Android and iOS clients to send reverse-proxy authentication material, including bearer/basic/static headers/cookies and possibly OIDC, before the Gateway WebSocket upgrade.

## Best Possible Solution

Define a shared mobile transport-auth contract first, split static pre-upgrade headers from OIDC if needed, then land proof-backed Android/iOS slices with setup-code/manual-connect metadata, secure storage, redaction, TLS rules, and reverse-proxy validation.

## Reproduction Assessment

Not applicable as a bug: this is a missing feature request, not broken documented behavior. Source inspection confirms current setup-code, Android, and iOS WebSocket paths do not carry proxy-layer auth fields before the HTTP upgrade.

## Solution Assessment

Unclear as proposed: static bearer/basic support is a plausible first slice, but the best maintainable solution needs shared mobile credential, secure-transport, QR/manual metadata, and OIDC direction before implementation proceeds.
