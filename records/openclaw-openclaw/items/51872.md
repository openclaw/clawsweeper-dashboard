## Label Justifications

- `P2`: The issue blocks mobile use for authenticated reverse-proxy deployments, but it is a bounded feature/security gap rather than a general runtime outage.
- `impact:security`: The requested mobile transport headers can contain bearer tokens, Basic credentials, cookies, or OIDC-derived credentials before normal Gateway auth runs.
- `impact:auth-provider`: The failure is an authentication-layer mismatch where proxy credentials must be sent on the HTTP/WebSocket upgrade before OpenClaw Gateway authentication can run.
- `maturity:stable`: The affected Android app and iOS app surfaces are both scored M4 Stable in qa/maturity-scores.yaml.

## Summary

Keep open: current main has useful iOS/shared and Android runtime support for sanitized per-gateway custom headers, but the original cross-platform request is not complete because setup-code/QR payloads still carry no proxy-auth metadata, current Android settings/onboarding expose only token/bootstrap/password fields, and the OIDC browser-return path remains a product/security decision.

## What This Changes

Request mobile transport-level proxy authentication for Android and iOS clients before the Gateway WebSocket upgrade, covering static headers such as Bearer/Basic/cookies and a possible OIDC handoff.

## Best Possible Solution

Complete the maintainer-approved static proxy-header path across setup-code/manual mobile setup and both native clients, then track OIDC browser handoff as a separate security design unless maintainers explicitly include it here.
