## Summary

Keep open: current main still lacks shared mobile transport-auth metadata and WebSocket upgrade header plumbing; the related Android PR closed unmerged, and the open iOS Basic-auth PR is only a partial candidate with blockers.

## What This Changes

Request adds HTTP transport-level authentication for Android/iOS Gateway connections behind authenticated reverse proxies, including setup-code metadata and mobile client upgrade credentials.

## Best Possible Solution

Define a shared secure transport-auth contract for mobile Gateway setup/manual connections, split static header support from OIDC if needed, and land Android/iOS slices only after credential lifecycle and real proxy proof requirements are approved.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path for the gap: setup-code, Android, and iOS native WebSocket paths have no proxy-auth/header fields before upgrade, though no live mobile proxy run was executed.

## Solution Assessment

Unclear as one implementation. Static bearer/basic header support is a plausible first slice, but the full request needs maintainer-approved credential lifecycle, Android/iOS parity, and OIDC browser-return boundaries.
