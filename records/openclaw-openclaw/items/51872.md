- `impact:security`: The requested behavior would store and replay proxy credentials before OpenClaw's normal Gateway authentication boundary.

## Summary

Keep open: current main and v2026.6.11 still lack a shared Android/iOS transport-auth contract, setup-code metadata, and WebSocket upgrade-header support for authenticated reverse proxies; the related Android PR closed unmerged and the open iOS PR covers only a Basic-auth subset with blockers.

## What This Changes

Request support for mobile clients to carry reverse-proxy authentication material through setup/manual Gateway connections before the WebSocket upgrade.

## Best Possible Solution

Define a shared Android/iOS transport-auth contract for setup-code and manual Gateway connections, split static header support from OIDC if needed, and land platform slices only after credential storage, clearing, redaction, TLS, endpoint-change, and real proxy proof requirements are approved.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path for the gap: current setup-code, Android, and iOS native WebSocket paths have no proxy-auth/header fields before upgrade. I did not run a live mobile client through an authenticating reverse proxy in this read-only review.

## Solution Assessment

Unclear as one implementation: bearer/basic headers are a plausible first slice, but the full request needs maintainer-approved credential lifecycle, static-header versus cookie behavior, Android/iOS parity, and OIDC browser-return boundaries.
