## Summary

Keep open: current main still lacks the mobile setup-code/manual-connect contract and pre-upgrade WebSocket header injection needed for authenticated reverse proxies, and the active iOS slice is only a partial, blocked candidate rather than a merged fix.

## What This Changes

Request support for Android/iOS clients to carry reverse-proxy transport credentials such as bearer, Basic, fixed headers, cookies, or OIDC through setup and the initial Gateway connection.

## Best Possible Solution

Define a shared mobile transport-auth contract for setup-code and manual-connect flows, split static headers from OIDC if needed, and land proof-backed Android/iOS implementations with credential lifecycle and secure-transport rules.

## Reproduction Assessment

Not applicable as a bug: this is a missing feature request, not broken documented behavior. Source inspection verifies current setup-code, Android, and iOS WebSocket paths do not carry pre-upgrade proxy authentication metadata or headers.

## Solution Assessment

Unclear as proposed: static bearer/basic support is a plausible first slice, but the best maintainable path needs a shared Android/iOS credential lifecycle and security design before implementation.
