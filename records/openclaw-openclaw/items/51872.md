## Summary

Keep open: current main and the latest release still lack a shared Android/iOS transport-auth contract, setup-code metadata, and WebSocket upgrade-header support for authenticated reverse proxies. The closed Android PR did not land, and the open iOS PR covers only a Basic-auth subset with unresolved proof/security blockers.

## What This Changes

Request transport-level reverse-proxy authentication metadata for non-web clients so iOS and Android can reach gateways behind Basic, bearer, fixed-header, cookie, or OIDC-authenticated proxies.

## Best Possible Solution

Define a shared mobile transport-auth contract first, then land platform slices only after credential storage, clearing, redaction, TLS, endpoint-change, setup-code metadata, and OIDC redirect boundaries are maintainer-approved and proven against real proxy setups.

## Reproduction Assessment

Yes: source inspection gives a high-confidence reproduction path for the gap because setup-code, Android, and iOS native WebSocket paths have no proxy-auth/header fields before upgrade. I did not run a live mobile client through an authenticating reverse proxy in this read-only review.

## Solution Assessment

Unclear as one implementation: bearer/basic headers are a plausible first slice, but the full request needs maintainer-approved credential lifecycle, static-header versus cookie behavior, Android/iOS parity, and OIDC browser-return boundaries.
