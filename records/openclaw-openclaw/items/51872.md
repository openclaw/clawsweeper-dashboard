## Summary

Keep open: current main partially implements the static custom-header direction for native gateway upgrades, but the broader request is not fully settled or exposed because setup-code/QR still has no proxy-auth payload, Android currently has no caller for its custom-header setter, and OIDC remains a separate product/security design.

## What This Changes

Request to let iOS and Android native clients send reverse-proxy authentication credentials, including bearer/basic/custom headers and possible OIDC, before the Gateway WebSocket upgrade.

## Best Possible Solution

Finish the agreed static per-gateway header path with explicit user-entry and bootstrap scope, keep the secure credential lifecycle intact, and split OIDC into a separate design unless maintainers choose to include it now.
