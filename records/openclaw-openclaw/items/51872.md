## Summary

Keep open: current main and the latest release still lack a shared mobile transport-auth contract, Android/iOS setup-code metadata, and pre-upgrade proxy headers; the closed Android PR is not a fix, and the open iOS PR only covers a Basic-auth subset with review blockers.

## What This Changes

Request to let Android and iOS clients carry reverse-proxy transport authentication, including bearer/basic/fixed headers/cookies and possible OIDC, before the Gateway WebSocket upgrade.

## Best Possible Solution

Define a shared Android/iOS transport-auth contract for setup-code and manual Gateway connections, split static header support from OIDC if needed, and land proof-backed platform slices only after credential storage, clearing, redaction, TLS, and endpoint-change rules are approved.

## Reproduction Assessment

Yes for the source-level gap: current Android and iOS clients cannot attach proxy Authorization/custom headers before the WebSocket upgrade. I did not run a live mobile client through an authenticating reverse proxy in this read-only review.

## Solution Assessment

Unclear as a single implementation: static bearer/basic headers are a plausible first slice, but the full request needs maintainer product/security decisions for credential lifecycle, arbitrary headers/cookies, Android+iOS parity, and OIDC browser-return handling.
