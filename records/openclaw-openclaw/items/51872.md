## Summary

Keep open: current main and the latest release still do not carry proxy-auth metadata through setup/manual mobile bootstrap or attach pre-upgrade proxy credentials from Android/iOS. The open iOS work at https://github.com/openclaw/openclaw/pull/98677 covers only a Basic-auth subset and still has proof/security blockers, while the Android attempt at https://github.com/openclaw/openclaw/pull/73168 is closed unmerged.

## What This Changes

Request mobile setup/manual connection support for reverse-proxy transport authentication before the Gateway WebSocket upgrade.

## Best Possible Solution

Define a shared Android/iOS transport-auth contract with credential storage, clearing, redaction, endpoint-change, TLS, setup-code, and OIDC rules, then land reviewed slices with real reverse-proxy proof.

## Reproduction Assessment

Not applicable as a bug: this is a missing feature request, not broken documented behavior. Source inspection confirms current setup-code, Android, and iOS WebSocket paths do not carry proxy-layer auth fields before the HTTP upgrade.

## Solution Assessment

Unclear as proposed: static bearer/basic support is a plausible first slice, but the broad request needs maintainer product and security direction for storage, TLS, fixed headers, cookies, and OIDC before implementation proceeds.
