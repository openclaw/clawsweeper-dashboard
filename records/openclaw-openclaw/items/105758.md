Decompose `createPluginRegistry` into typed domain registrar modules composed over one canonical registry state object without changing plugin SDK contracts or runtime behavior.

## Best Possible Solution

Introduce one internal typed registry state, extract cohesive registrars in reviewable stages, and leave `createPluginRegistry` as a thin deterministic composition root while preserving registration order, diagnostics, modes, lazy boundaries, and the existing `PluginRegistry` and plugin API contracts.
