## Summary

Keep this issue open: current main and the latest stable release still use growing full-content Feishu CardKit updates, a fresh live comment says the latency still reproduces, and the linked open pull request is only a candidate path that now needs maintainer/product review.

## What This Changes

The issue reports severe Feishu/Lark streaming-card latency on long replies after switching CardKit updates from append-only suffixes to full accumulated content.

## Best Possible Solution

Keep full-content updates as the default until Feishu maintainers decide whether a proven opt-in append/transport mode, a stronger coalescing strategy, or another CardKit-compatible mitigation can reduce long-reply latency without reintroducing truncation.
