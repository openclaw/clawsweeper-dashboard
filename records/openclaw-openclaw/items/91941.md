## Summary

Keep open: current main and v2026.6.11 still send growing full-content Feishu CardKit payloads, and a July 6 live repro says the linked cadence-only PR did not materially fix the multi-minute tail.

## What This Changes

The issue requests a fix for Feishu streaming-card long-reply latency caused by repeated full accumulated CardKit content updates, without regressing prior full-content truncation fixes.

## Best Possible Solution

Keep full-content updates as the default, then add a narrowly documented opt-in append/content mode or another Feishu-backed transport mitigation only after live proof shows lower latency and complete final content.

## Maintainer Decision

Required: true

Rationale: The requested fix affects Feishu's transport contract and likely adds config surface; the latest live repro says cadence coalescing may not be enough, while earlier issues show suffix payloads can truncate content.

Owner confidence: high

Options:

- **Add Opt-In Append Mode (recommended):** Keep full-content updates as the default, add a documented per-account opt-in append/content mode with truncation warnings, and require live proof for both final content and latency.
- **Stay Full-Content Only:** Reject append mode for contract safety and continue iterating on coalescing/backpressure, accepting that the latest live repro says this may not solve affected deployments.
- **Document Streaming-Off Workaround:** Treat slow Feishu tenants as an operational limitation and document `streaming: false` or raw replies as the supported workaround without adding new payload modes.

## Reproduction Assessment

Yes, through source inspection plus live reporter evidence: a Feishu DM/card-streaming run with a few-thousand-character reply on 2026.7.1-beta.2 reportedly took about 340s from `Started streaming` to `Closed streaming` after about 25s of model generation. I did not independently run a live Feishu tenant reproduction in this read-only review.

## Solution Assessment

Unclear as currently proposed: coalescing full-content updates is the narrower contract-preserving candidate, but the July 6 live repro says it did not materially improve the tail. The best fix now needs maintainer direction on whether an opt-in append/content mode is acceptable.
