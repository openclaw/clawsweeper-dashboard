## Summary

Keep this issue open: current main and the latest stable release still send growing full-content Feishu CardKit updates, and the latest live repro says the linked cadence-only PR did not fix the multi-minute tail.

## What This Changes

The issue requests a Feishu streaming-card fix for long replies where repeated full accumulated CardKit updates cause severe latency, possibly via an opt-in append/content mode while preserving the default full-content behavior.

## Best Possible Solution

Keep full-content CardKit updates as the default, then make a maintainer decision on an explicitly opt-in append or alternate transport mode with docs, tests, and live Feishu proof for both the slow-full-content and truncation-sensitive setups.
