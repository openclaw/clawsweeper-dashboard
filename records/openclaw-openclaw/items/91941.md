## What This Changes

The issue asks for Feishu streaming-card long replies to stay responsive when full accumulated CardKit content updates become slow, potentially through a safe opt-in transport mode.

## Best Possible Solution

Keep this issue as the canonical Feishu long-reply streaming-card latency tracker until maintainers choose a compatibility-safe Feishu delivery contract, likely preserving full-content updates by default while proving an opt-in append, segment, or other non-growing-payload mode for affected tenants.
