## Summary

Keep this issue open: current main and v2026.6.11 still send growing full-content Feishu CardKit update payloads, the linked open fix candidate is not merged and now has live feedback saying cadence coalescing did not fix the multi-minute tail, so the remaining work needs maintainer product direction rather than cleanup closure.

## What This Changes

The issue requests a way to avoid severe Feishu/Lark streaming-card latency on long replies caused by repeated full accumulated CardKit content updates while preserving the default full-content behavior that prevents truncation.

## Best Possible Solution

Keep full-content as the default CardKit contract, then either land a proven full-content mitigation or add a documented per-account opt-in append mode only with live Feishu/Lark proof for latency and no truncation.
