## Summary

Close as implemented: custom providers can already select the standard OpenAI Responses adapter with `api: "openai-responses"`. The requested `openai-codex-responses` name is no longer the correct generic custom-provider route; the current configuration contract uses the standard Responses adapter for `/v1/responses` backends.

## What This Changes

Add an OpenAI Responses API format to custom model configuration so third-party providers that expose `/v1/responses` can be used.

## System Context

Custom providers are declared under `models.providers`, where the selected API adapter and base URL determine the outbound model request format. The resolved provider model then feeds the agent runtime, which chooses the appropriate HTTP or native transport before streaming the model response back to sessions and channels.

## Best Possible Solution

Keep the current `openai-responses` custom-provider route as the canonical solution and direct any remaining client-specific selector problem to the client that is not exposing the schema-supported adapter.
