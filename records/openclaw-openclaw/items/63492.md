## Summary

Keep open: current main and the latest release still use path-based `sessions.json` storage with no external backend selector or adapter API, and this issue is the canonical session-storage tracker rather than cleanup-ready duplicate work.

## What This Changes

The issue requests a pluggable external session storage backend so multiple OpenClaw instances can share session state without sticky routing.

## Best Possible Solution

Keep this as the session-storage design tracker until maintainers choose a core or SDK backend contract, default local behavior, credential handling, migration path, and consistency model.
