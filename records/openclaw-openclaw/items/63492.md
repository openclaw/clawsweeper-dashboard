## Summary

Keep open: current main and v2026.6.11 still expose session storage as local path-backed `sessions.json` plus transcript files, while the requested external shared backend remains a product/architecture decision not replaced by the broader database or horizontal-scaling trackers.

## What This Changes

Request support for a pluggable external session storage backend so multiple OpenClaw instances can share session state without sticky routing.

## Best Possible Solution

Keep this as the canonical session-specific external storage tracker and design the backend boundary only after the session accessor/SQLite migration and broader database-abstraction direction settle.

Rationale: The source gap is clear, but backend ownership, credentials, consistency semantics, transcript lifecycle, migration behavior, and config shape are product and architecture decisions.

Owner confidence: medium

Options:

- **Design a storage contract after the SQLite seam (recommended):** Define a backend-neutral contract covering session metadata, transcript events, migrations, pruning, credentials, consistency, tests, and docs before selecting Redis, Mongo, Postgres, or plugin ownership.
- **Keep this external/plugin-only:** Document sticky sessions or external orchestration as deployment guidance and pursue plugin/API gaps only if current plugin surfaces cannot express the storage backend safely.
- **Fold into broader database abstraction:** Treat external session storage as a subset of the broader networked database backend effort and keep this issue as a linked session-specific requirements source.

## Reproduction Assessment

Yes, source confirmation is high-confidence: current main only accepts a string `session.store` and resolves it to local `sessions.json` plus local transcript files. This is not a bug reproduction, but the missing external shared backend is directly visible in code and docs.

## Solution Assessment

No, not as the literal Redis/Mongo key-value factory described. The maintainable path needs a maintainer-approved storage boundary covering session metadata, transcripts, migrations, pruning, credentials, consistency, and upgrade behavior.
