## Summary

Keep open: current main and v2026.6.11 still use local path-backed `sessions.json` plus JSONL transcript storage, while the open/closed related work covers adjacent SQLite migration, broad database abstraction, or horizontal scaling rather than the requested shared external session backend.

## What This Changes

The issue requests a pluggable external session storage backend so multiple OpenClaw instances can share session state without local filesystem affinity.

## Best Possible Solution

Keep this open as the canonical session-specific shared-storage tracker until maintainers choose the storage boundary and coordinate it with SQLite/accessor and broader database-abstraction work.
