## Label Justifications

- `P2`: The request targets meaningful production scalability and reliability impact, but it is a broad feature/design item rather than an urgent confirmed regression.
- `impact:session-state`: The reported failure mode is losing or splitting conversation context when requests for the same session land on different OpenClaw instances.
- `impact:data-loss`: The issue describes session state disappearing from the user's perspective when an instance-local store is unavailable or lost.

## Summary

Keep open: current main and v2026.6.11 still expose session storage as a local `sessions.json` path-backed store, while this request asks for a new external shared session backend and remains a product/architecture decision.

## What This Changes

The issue requests a pluggable external session-storage backend such as Redis or MongoDB so multiple OpenClaw instances can share session state without sticky routing.

## Best Possible Solution

Keep this as the session-specific external storage tracker, then design the storage contract after the session accessor/SQLite migration and broader database-backend direction are settled.
