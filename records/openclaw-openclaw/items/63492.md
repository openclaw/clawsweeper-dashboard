## Summary

Keep open: current main still exposes session storage as local `sessions.json` plus JSONL transcript files, and the active SQLite migration/broader database-backend issues are prerequisite or overlapping architecture work rather than an external shared session backend.

## What This Changes

Request a pluggable external session-storage backend so multiple OpenClaw instances can share session state without sticky routing.

## Best Possible Solution

Keep this as the canonical session-specific external shared-storage tracker and design the backend boundary with the SQLite/session-accessor and broader database-abstraction decisions.
