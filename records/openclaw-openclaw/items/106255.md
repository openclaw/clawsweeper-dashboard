## Summary

The latest head still has a concrete lifecycle gap: an inline browser opened before onboarding remains armed, but normal onboarding completion does not invoke the controller retry path, so the first eligible banner can remain absent until another dashboard update or browser action. The PR also lacks after-fix native behavior proof and carries the protected `maintainer` label.

## What This Changes

Defers the macOS browser-cookie import offer from app launch and Gateway connection to the first inline-browser open, with retry and one-shot state handling, regression tests, documentation, and localization inventory updates.

## Best Possible Solution

Connect the armed offer to the actual onboarding-eligibility transition through one lifecycle-owned retry path, add a regression that completes onboarding with the sidebar already open, then provide a redacted signed-app recording or runtime trace—or obtain an explicit proof override.
