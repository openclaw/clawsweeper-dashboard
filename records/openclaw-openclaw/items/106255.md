## Summary

The timing change correctly removes premature launch and connection offers, but the current head consumes its one-shot trigger before import eligibility is known. A first sidebar open in remote mode or before onboarding can therefore suppress the later eligible local offer, and the external PR still lacks after-fix live macOS proof.

## What This Changes

The PR moves the macOS cookie-import offer from app launch and Gateway connection to the first inline-browser sidebar open, adds smoke coverage and documentation, and refreshes generated native localization resources.

## Best Possible Solution

Make the trigger outcome-aware: retain a pending first-eligible-open state until the import model confirms an eligible local and onboarded check, consume it after that check regardless of whether profiles are found, and add transition coverage plus redacted signed-app proof.
