Full review comments:

- **[P1] Fail closed when plan state cannot be read:** `src/agents/plan-mode/gate-hook.ts:37-40`
  - body: This catch turns any session-store read failure into inactive plan mode, so a session that is actually planning can run mutating tools if the store read fails. Because plan mode is the PR's read-only safety boundary, the gate needs to block or return an explicit failure when it cannot prove the session is inactive.
  - confidence: 0.9
- **[P1] Make Slack question buttons resolve questions:** `src/infra/question-forwarder.ts:68-70`
  - body: For Slack, this only stores `/answer <n>` as a callback value. The existing Slack block-action path renders that as an `openclaw:reply_button` action and, after approval/plugin checks, enqueues a generic Slack interaction event instead of running the text-command `/answer` handler, so clicking the button does not resolve the QuestionManager promise and the asking tool can remain parked. Route the click through a typed question action or direct `question.resolve` handling.
  - confidence: 0.88
- **[P2] Update public docs for the new tool defaults:** `src/agents/openclaw-tools.registration.ts:40`
  - body: This makes `update_plan` default-on for all models and the PR also adds `tools.experimental.goalDriver`, but the public config docs still describe `tools.experimental.planTool` as opt-in/default-off and do not document `goalDriver`. Users upgrading or configuring these features will follow stale docs, so update the gateway config and experimental-features docs with the code change.
  - confidence: 0.84
