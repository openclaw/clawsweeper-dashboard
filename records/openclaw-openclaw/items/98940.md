## Summary

Keep open. The PR is a useful partial mitigation, but it is not merge-ready because missing or chunked `content-length` responses still call Playwright `Response.body()`, which returns the full buffer before the PR slices it, and the contributor has not provided real large-response behavior proof.

## What This Changes

The PR changes browser Playwright response-body capture to pre-check `content-length`, prefer `resp.body()`, and decode only a byte-capped prefix before final character truncation.

## Best Possible Solution

Use a truly pre-read bounded browser response strategy, or narrow this PR to a partial known-content-length mitigation with explicit tests, real proof, and accepted empty-body semantics.

## Reproduction Assessment

Yes by source and dependency inspection: current main reads the whole Playwright response body before final truncation, and Playwright 1.60 `Response.body()` returns one full binary payload. I did not run a live large-response browser repro in this read-only review.

## Solution Assessment

No. The `content-length` pre-check is a useful partial mitigation, but this is not the best OOM fix because the no-`content-length` path still awaits Playwright's full buffer before slicing.
