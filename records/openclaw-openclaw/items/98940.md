## Summary

Keep open: current main and the latest release still use the unbounded Playwright text path, and this PR is a plausible lower-risk decode-only mitigation after removing the CDP interception design. It still needs contributor real browser proof before merge, and maintainers should notice that it does not eliminate Playwright's full Buffer allocation for extremely large responses.

## What This Changes

The PR changes the browser plugin responsebody helper from `response.text()` to `response.body()` plus bounded `subarray` decoding, with mocked regression tests for small and oversized responses.

## Best Possible Solution

Land this only as an explicitly scoped decode-only browser bug fix after redacted real browser proof shows bounded tool output and unchanged page response delivery.

## Reproduction Assessment

Yes, source-reproducible: current main and v2026.6.11 call Playwright `resp.text()` before applying `maxChars`, and Playwright v1.60.0 implements `text()` by awaiting the full body Buffer then decoding it. I did not run a live large-response browser OOM reproduction in this read-only review.

## Solution Assessment

Acceptable as a lower-risk decode-only mitigation, not as complete OOM prevention. Removing the CDP fulfill path avoids the earlier page-delivery regression, but maintainers should explicitly accept that full Buffer allocation remains.
