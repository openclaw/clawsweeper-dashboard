- `P1`: The PR targets a browser `responsebody` OOM/availability risk in a user-facing browser tool path.

## Summary

Keep open for normal maintainer merge handling: current main and the latest release still decode the browser response body through Playwright `text()` before trimming, while this PR has no blocking line-level findings and now includes copied real Playwright Chromium proof for the bounded decode path.

## What This Changes

The PR changes the browser plugin `responsebody` helper from full `response.text()` decoding to `response.body()` plus bounded `Buffer.subarray()` decoding, with focused regression tests.

## Best Possible Solution

Land the scoped decode-only mitigation if maintainers accept that boundary, and track true page-preserving streaming capture separately only if a safe Playwright/CDP approach is found.

## Reproduction Assessment

Yes, source-reproducible: current main and v2026.6.11 call Playwright `resp.text()` before applying `maxChars`, and Playwright v1.60.0 implements `text()` by awaiting the full body Buffer then decoding it. I did not run a live large-response OOM reproduction in this read-only review.

## Solution Assessment

Yes for a low-risk decode-only mitigation: the PR avoids full-string decoding and preserves page delivery by staying on passive Playwright response observation. It is not a complete zero-copy OOM fix because `resp.body()` still buffers the response.
