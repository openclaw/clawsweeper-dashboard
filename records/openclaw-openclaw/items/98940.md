## Label Justifications

- `P1`: The PR targets an OOM/availability issue and the current CDP path can alter or break matched browser responses.
- `merge-risk: 🚨 availability`: Merging the CDP interception path could make page fetches or navigations receive truncated or stale-header responses during responsebody capture.

## Summary

Keep open: latest head fixes the earlier empty-body CDP fulfill bug, but the CDP path still fulfills matched oversized page responses with only the captured prefix, so responsebody capture can mutate or break the page network response it observes.

## What This Changes

The PR changes the browser plugin response-body helper to prefer Chromium CDP Fetch streaming, fall back to Playwright `body()` decoding, and adds response-body tests.

## Best Possible Solution

Use a browser-owner-approved approach that bounds OpenClaw responsebody capture without changing the matched page response, or narrow the PR to a documented decode-only mitigation if CDP cannot preserve delivery.

## Reproduction Assessment

Yes, source-reproducible: current main calls Playwright `resp.text()` before applying `maxChars` on the responsebody route. I did not run a live large-response browser OOM reproduction in this read-only review.

## Solution Assessment

No. CDP streaming is a plausible layer for true bounded capture, but this implementation is not the best fix because the oversized path fulfills the page with the captured prefix rather than preserving the original response.
