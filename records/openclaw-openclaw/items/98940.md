## Summary

This PR should stay open: the latest head fixes the missing `truncated` flag, but the new known-large `content-length` path still makes default `openclaw browser responsebody` output blank, and the posted real behavior proof does not show the current-head pre-reject behavior.

## What This Changes

The PR changes the browser plugin's Playwright response-body reader from full `resp.text()` decoding to a content-length pre-reject plus `resp.body().subarray()` bounded decode path, with adjacent regression tests.

## Best Possible Solution

Keep the bounded decode mitigation, but make oversized known-length omissions visible in the default CLI/API contract and back the current head with real browser or terminal proof for known-large, unknown-length, and small responses.

## Reproduction Assessment

Yes. Source inspection of PR head shows a response with `content-length > maxChars * 4` skips `resp.body()`, returns `body: ""` with `truncated: true`, and the current default CLI prints only that empty body.

## Solution Assessment

No. The `body()+subarray()` fallback is an acceptable mitigation, but the known-large pre-reject path needs a visible CLI/API contract and current-head proof before this is the best fix.
