## Summary

Keep open: current main has a real unbounded browser response-body read, but this PR is not merge-ready because it slices only after Playwright has already buffered the full body, proof remains mock-only, and added test lines fail lint.

## What This Changes

The PR replaces the Playwright response capture `resp.text()` path with `resp.body()` plus a capped decode slice and adds mocked regression/diagnostic tests for oversized bodies.

## Best Possible Solution

Use a CDP or other capture path that limits bytes before response materialization, or explicitly land this only as a decode-memory mitigation with maintainer-accepted risk and real proof.

## Reproduction Assessment

Yes by source and dependency inspection: current main reads the full Playwright response text before final truncation, and Playwright 1.60 `Response.text()` delegates to `Response.body()`. I did not run a live large-response browser repro in this read-only review.

## Solution Assessment

No. The patch reduces string decode memory but is not the best OOM fix because it still waits for Playwright to buffer the full response body before slicing.
