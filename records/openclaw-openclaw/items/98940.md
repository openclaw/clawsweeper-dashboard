## Summary

Keep open: the current head is a useful decode-allocation mitigation, but it is not merge-ready because it still awaits Playwright's full response Buffer before truncation and the PR body/proof still claims content-length pre-reject and CLI notice behavior that the diff does not implement.

## What This Changes

The PR changes the browser plugin's Playwright response-body reader from `Response.text()` to `Response.body()` plus prefix decoding/truncated flagging, and adds a unit test for large-body prefix decoding.

## Best Possible Solution

Add a declared `content-length` pre-reject before `resp.body()`, implement any claimed CLI notice, prove the oversized path does not call `body()`, and explicitly document or redesign the remaining unknown-length full-buffer limitation.
