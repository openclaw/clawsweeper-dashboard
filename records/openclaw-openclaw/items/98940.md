## Summary

Keep open; the PR has a useful mitigation direction, but the latest content-length pre-check silently returns an empty, unflagged response for known-oversized bodies and the real behavior proof still describes an older body()+subarray result.

## What This Changes

The PR changes `responseBodyViaPlaywright` from `resp.text()` to a Playwright `body()`/bounded decode path, skips `body()` when `content-length` exceeds the byte cap, and adds adjacent Vitest coverage.

## Best Possible Solution

Preserve the pre-read guard only if oversized known-length responses return an explicit truncation signal and the PR body includes current-head proof for both the known-length reject path and the unknown-length fallback.

## Reproduction Assessment

Yes. Source inspection shows current main reads the full Playwright response before trimming, and PR-head source plus its new test show the known-large content-length path returning empty with no truncation marker; I did not run tests in this read-only review.

## Solution Assessment

No. A pre-read content-length guard is a reasonable mitigation, but this implementation silently drops the body without signaling truncation and the current proof no longer matches the latest code path.
