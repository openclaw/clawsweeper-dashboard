## Summary

Keep open: the OOM risk is real on current main and the latest release, but this PR still makes the matched browser response receive the captured prefix instead of preserving the original response body.

## What This Changes

The branch rewrites the browser plugin responsebody helper to use Chromium CDP Fetch streaming with a Playwright body()+subarray fallback and adds response-body tests.

## Best Possible Solution

Use a browser-owner-approved bounded capture path that preserves matched page delivery, or narrow the PR to a documented decode-only mitigation if CDP cannot safely do both.

## Reproduction Assessment

Yes, source-reproducible: current main and v2026.6.11 call Playwright resp.text() before applying maxChars on the responsebody route. I did not run a live large-response browser OOM reproduction in this read-only review.

## Solution Assessment

No. CDP streaming is a plausible layer for true bounded capture, but this implementation is not the best fix because the oversized path fulfills the page with the captured prefix rather than preserving the original response.
