## Summary

Keep open. The actual merge result is the browser response-body patch, but it is not merge-ready because it still awaits Playwright's full response Buffer before truncation and the PR proof describes content-length pre-reject/CLI behavior that is not present on the current head.

## What This Changes

The branch changes the browser plugin's Playwright response-body reader to call `Response.body()`, decode only a `maxChars * 4` byte prefix, mark byte/char truncation, and adds a responsebody prefix test.

## Best Possible Solution

Make the current-head browser response-body path either avoid reading declared oversized responses before `resp.body()` and clearly prove the remaining unknown-length tradeoff, or replace it with a safe streaming design that preserves page delivery.
