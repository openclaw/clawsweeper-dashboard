## Summary

Keep this PR open for maintainer review. Its stated goal addresses the linked native-iOS media regression, but the proposed HTTP fetch has no approved device-authenticated authorization contract for setup-code-paired clients, and transcript reconciliation can still conflate distinct image attachments.

## What This Changes

The branch teaches native iOS chat to preserve gateway assistant-image metadata, load managed image bytes through the active gateway connection, and render bounded inline image previews after history reloads and reconnects.

## System Context

Gateway chat history and events become OpenClawKit transcript messages, which native iOS reconciles and renders. For protected assistant media, the iOS chat transport must obtain bytes from the gateway without bypassing the connection’s authorization and TLS guarantees.

## Best Possible Solution

Approve a generic device-scoped native-media authorization contract, implement the loader against that contract without shared privileged credentials, include attachment identity in reconciliation fingerprints with regressions, then capture a redacted live gateway-to-iOS reconnect/history proof.
