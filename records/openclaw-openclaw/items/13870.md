## Summary

Keep open: current main still lacks a durable paired-device rename/label workflow, and https://github.com/openclaw/openclaw/pull/94517 is the open closing candidate rather than a reason to close this issue before merge.

## What This Changes

Request a human-friendly paired-device name or label shown in the web UI and `openclaw devices list` so operators do not have to identify devices by opaque hash IDs.

## Best Possible Solution

Land or replace the linked narrow implementation with a durable operator-owned paired-device label across Gateway protocol, CLI, Control UI, docs, and authorization coverage, while keeping broader metadata display in the adjacent issue separate.

## Reproduction Assessment

Yes. Source inspection of current main shows the missing operator label field, missing `device.pair.rename` RPC/schema, missing CLI rename command, and missing Control UI label/rename support.

## Solution Assessment

Yes for the direction. A durable operator-owned label separate from reconnect-owned `displayName` is the narrow maintainable solution, but the open linked PR or a replacement still needs to satisfy the full CLI/UI/Gateway/docs contract before this issue can close.
