## Summary

Keep open: current main and v2026.6.11 still lack an operator-owned paired-device label/rename workflow, and the open linked PR is the active implementation candidate rather than a reason to close this issue before merge.

## What This Changes

The issue requests human-friendly labels for paired devices in the CLI and web UI instead of relying on opaque device IDs.

## Best Possible Solution

Review and land or replace https://github.com/openclaw/openclaw/pull/94517 with a durable operator-owned paired-device label across storage, protocol, Gateway authorization, CLI, Control UI, docs, and tests while keeping broader metadata display in https://github.com/openclaw/openclaw/issues/23916 separate.

## Reproduction Assessment

Yes. Source inspection of current main and v2026.6.11 shows paired devices use displayName/deviceId only and lack device.pair.rename, a CLI rename command, and a Control UI rename action.

## Solution Assessment

Yes for the issue direction. A separate operator-owned label with precedence over client displayName is the narrow maintainable solution; reusing displayName would conflict with reconnect metadata, and the active PR still needs review/repair before merge.
