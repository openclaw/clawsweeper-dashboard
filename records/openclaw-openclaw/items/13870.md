## Summary

Keep open: current main and v2026.6.11 still lack an operator-owned paired-device rename workflow, and the open linked PR is the active implementation candidate rather than a reason to close this issue early.

## What This Changes

Request adding human-friendly, user-settable names for paired devices in the CLI and Control UI instead of relying on opaque device IDs.

## Best Possible Solution

Review and land or replace https://github.com/openclaw/openclaw/pull/94517 with a durable operator-owned paired-device label across protocol, storage, CLI, Control UI, docs, and authorization coverage while keeping https://github.com/openclaw/openclaw/issues/23916 separate for broader metadata display.

## Reproduction Assessment

Yes. Source inspection of current main shows paired devices use displayName/deviceId only and lack device.pair.rename, a CLI rename command, and a Control UI rename action.

## Solution Assessment

Yes. A separate operator-owned label with precedence over client displayName is the narrow maintainable solution; reusing displayName would create a competing writer with reconnect metadata.
