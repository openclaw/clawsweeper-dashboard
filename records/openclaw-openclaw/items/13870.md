## What This Changes

The issue requests human-friendly names for paired devices in the CLI and Control UI, including a rename workflow instead of opaque hash-only identifiers.

## Best Possible Solution

Land or replace the linked implementation with a durable operator-owned paired-device label, Gateway RPC, CLI/UI display and rename actions, docs, and authorization/lifecycle coverage.

## Reproduction Assessment

Yes. Source inspection of current main shows the missing operator label field, missing device.pair.rename schema/method, missing CLI rename command, and missing Control UI label/rename support.

## Solution Assessment

Yes. A separate operator-owned label with explicit precedence over client displayName is the narrow maintainable solution; reusing displayName would let reconnect metadata overwrite the user label.
