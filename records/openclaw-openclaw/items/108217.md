## Summary

The PR’s helper implementation is tidy, but the new production signal fires at the same one-second deadline that the drain wait already enforces; it does not connect to a real superseding restart or lifecycle cancellation. The prior P1 remains unresolved, so this needs a maintainer decision on restart-coalescing semantics before it can be treated as a bug fix.

## What This Changes

The branch adds an optional `AbortSignal` to cron task-drain polling, tests abort behavior, and passes `AbortSignal.timeout(1_000)` from the gateway restart drain path.

## Best Possible Solution

First define whether a superseding gateway restart may interrupt cron task draining and the state guarantees required before the next restart proceeds; then either wire that real lifecycle signal through the helper with an end-to-end regression test or retain the existing bounded deadline without the new API.
