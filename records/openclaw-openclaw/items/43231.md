## Summary

Keep open: current main and the latest release still expose known Telegram forum topic names only after a numeric topic/thread id is already known, and they do not provide the requested name-to-topic_id resolver, topic list action, or catalog surface for agent routing.

## What This Changes

The issue requests first-class Telegram forum topic-name to topic_id resolution so agents can route messages to named topics without manual numeric mappings.

## Best Possible Solution

Expose a Telegram-owned observed-topic catalog or list/resolve action backed by the topic-name cache, returning topic ids, names, closed state, and freshness with structured ambiguity instead of silently routing by guessed names.

Rationale: The current cache provides observed id-to-name data, but reversing it affects stale data handling, duplicate titles, closed topics, permissions, prompt size, and whether the contract belongs in message actions or context metadata.

Options:

- **Expose Observed Topic Catalog (recommended):** Add a Telegram-owned list/catalog action returning known topic ids, names, closed state, and freshness so agents can choose or ask when ambiguous.
- **Add Resolver-Only Helper:** Add a direct name-to-id helper that returns structured ambiguity or stale/unknown results instead of silently picking a topic.
- **Keep Numeric IDs For Now:** Leave numeric topic ids as the supported routing contract and document the manual mapping workaround until maintainers want a stronger Telegram product surface.

## Reproduction Assessment

Yes, at source level: current main still routes Telegram forum sends through numeric messageThreadId or chatId:topic:id, while the existing cache only returns a name after the numeric id is known. I did not run a live Telegram forum group.

## Solution Assessment

Unclear which proposed surface is best. The existing topic-name cache is the likely data source, but the maintainable fix needs a maintainer-selected catalog, list, or resolver contract rather than relying on current-topic metadata.
