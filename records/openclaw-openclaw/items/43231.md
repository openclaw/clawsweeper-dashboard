## Summary

Keep open: current main and v2026.6.11 still support Telegram forum routing by numeric topic/thread id and expose learned names only after an id is already known; the requested name-to-id resolver, topic list action, or catalog surface remains a product/API decision.

## What This Changes

Request first-class Telegram forum topic-name to topic_id resolution for agent routing, either through context injection, a list/topics action, or channel metadata/catalog.

## Best Possible Solution

Keep this as the canonical tracker and design a Telegram-owned observed-topic catalog, list action, or resolver that returns known topic ids, names, closed state, freshness, and structured ambiguity.
