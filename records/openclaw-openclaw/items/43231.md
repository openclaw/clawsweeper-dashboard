## Summary

Keep open: current main and `v2026.6.11` still expose Telegram topic names only after a numeric topic/thread id is known, but they do not provide the requested topic-name-to-topic_id resolver, topic list action, or catalog surface for agent routing.

## What This Changes

The issue requests first-class Telegram forum topic-name to topic_id resolution or a topic catalog/list surface so agents can route by human-readable topic names.

## Best Possible Solution

Add a Telegram-owned topic catalog or resolver backed by the persisted topic-name cache and service-message learning, with explicit ambiguity/staleness rules and an approved agent-facing seam.

## Reproduction Assessment

Yes, at source level: current main learns and exposes topic names only after a numeric forum thread id is known, while routing actions still require positive integer `messageThreadId`/`threadId` or numeric `:topic:` targets. I did not run a live Telegram forum group in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product surface. The existing persisted topic-name cache is the right data source, but the remaining fix needs a deliberate resolver/list/catalog contract rather than treating reverse current-topic metadata as complete.
