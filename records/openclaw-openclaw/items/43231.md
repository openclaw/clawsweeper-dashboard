## Summary

Keep open: current main and the latest release still expose Telegram forum topic names only after a numeric thread/topic id is already known; they do not provide the requested name-to-topic_id resolver, topic-list action, or channel metadata catalog for agent routing. The merged topic-name cache work is useful partial progress, and the open ThreadLabel PR is adjacent display work rather than the routing resolver requested here.

## What This Changes

The issue requests first-class Telegram forum topic-name to topic_id resolution or a topic catalog/list surface so agents can route messages by human-readable topic names.

## Best Possible Solution

Add a Telegram-owned, best-effort topic catalog/resolver based on observed/create/edit topic-name cache entries with explicit ambiguity and staleness behavior, or document numeric-topic-only routing if maintainers reject that surface.
