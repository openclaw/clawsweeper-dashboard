## Summary

Keep open: current main still has only numeric Telegram topic routing plus topic-id-to-name metadata; it does not expose a reliable topic-name-to-topic_id resolver, list action, or catalog endpoint for agent routing.

## What This Changes

The issue requests first-class Telegram forum topic-name to topic_id resolution or a topic catalog surface for outbound agent routing.

## Best Possible Solution

Add a Telegram plugin-owned topic catalog or lookup surface backed by observed/create/edit topic metadata, expose clear ambiguity and staleness results to agent tools, and keep numeric threadId as the actual send primitive.
