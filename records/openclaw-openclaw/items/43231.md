Keep open: current main and v2026.6.11 still expose Telegram forum topic names only after a numeric topic/thread id is already known, so name-to-topic_id routing remains a Telegram product/API-surface decision.

## What This Changes

The issue requests reliable Telegram forum topic-name to topic_id resolution so agents can route messages to another forum topic by human-readable name.

## Best Possible Solution

Add a Telegram-owned observed-topic catalog, list action, or resolver backed by the existing cache, returning structured ambiguity/freshness so routing never guesses the wrong topic.
