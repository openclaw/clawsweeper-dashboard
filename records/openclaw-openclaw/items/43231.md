## Summary

Keep open: current main and latest release still expose Telegram forum topic names only after a numeric topic/thread id is known; they do not provide the requested name-to-topic_id resolver, topic list action, or catalog surface for agent routing.

## What This Changes

Request durable Telegram forum topic-name to topic_id resolution for routing agent messages into named forum topics.

## Best Possible Solution

Keep this as the canonical tracker and design a Telegram-owned observed-topic catalog, list action, or resolver that maps known names to IDs with explicit stale, duplicate, renamed, and closed-topic behavior.

## Reproduction Assessment

Yes, at source level: current main still routes Telegram forum sends through numeric `messageThreadId`/`chatId:topic:id`, while the existing cache is keyed by `chatId:threadId` and only returns the name for that known id.

## Solution Assessment

No current implementation fully solves this issue. The existing topic-name cache is the likely data source, but the best fix needs a deliberate resolver/list/catalog contract rather than relying on current-topic metadata.
