## Summary

Keep open: current main and v2026.6.11 still require numeric Telegram forum topic IDs for routing, while the merged topic-name work only exposes names after a numeric thread ID is already known. Related PRs cover reverse metadata and session labels, not a reliable name-to-topic_id resolver or topic catalog.

## What This Changes

The issue requests first-class Telegram forum topic name to topic_id resolution or a topic catalog/list surface so agents can route by human-readable topic names.

## Best Possible Solution

Keep this as the canonical tracker and design a Telegram-owned observed-topic catalog or resolver that returns topic ids, names, closed state, freshness, and ambiguity instead of silently guessing a destination.
