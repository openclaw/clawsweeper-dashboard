## Summary

Keep open: current main and v2026.6.11 still provide Telegram forum topic names only after a numeric topic/thread id is already known; they do not provide the requested name-to-topic_id resolver, topic-list action, or catalog surface for agent routing. The related display-label work is adjacent and does not resolve routing by topic name.

## What This Changes

Request first-class Telegram forum topic-name to topic_id resolution, topic listing, or a topic catalog for agent routing.

## Best Possible Solution

Add a Telegram-owned topic catalog or resolver backed by the persisted topic-name cache and service-message learning, with explicit ambiguity/staleness rules and an approved agent-facing seam while preserving numeric topic ids as the routing source of truth.

## Reproduction Assessment

Yes, at source level: current main still routes Telegram forum sends through numeric `messageThreadId`/`chatId:topic:id`, while the existing cache is keyed by `chatId:threadId` and only returns the name for that known id.

## Solution Assessment

No current implementation fully solves this issue. The existing topic-name cache is the likely data source, but the best fix needs a deliberate resolver/list/catalog contract rather than relying on current-topic metadata.
