## Summary

Keep open: current main and v2026.6.11 expose numeric Telegram topic routing plus observed topic ID-to-name metadata, but they still do not provide the requested topic-name to topic_id resolver or catalog for routing.

## What This Changes

The issue requests first-class Telegram forum support for resolving human-readable topic names to numeric topic IDs for agent message routing.

## Best Possible Solution

Keep this as the canonical tracker and design a Telegram-owned observed-topic catalog, list action, or resolver that returns topic IDs with explicit stale, duplicate, renamed, and closed-topic behavior.

Options:

- **Expose Observed Topic Catalog (recommended):** Add a Telegram-owned list/catalog action or metadata endpoint that returns known topic IDs, names, closed state, and freshness so agents can choose or ask when ambiguous.

- **Keep Numeric-Only Routing:** Leave topic names as display/context metadata and document numeric topic IDs or chatId:topic:threadId as the only supported routing contract.

Unclear which proposed surface is best. The existing topic-name cache is the likely data source, but the maintainable fix needs a maintainer-selected resolver, list, or catalog contract rather than relying on current-topic metadata.
