## Summary

Keep open: current main and the latest release still expose Telegram forum topic names only after the numeric chat/topic context is known; they do not provide a reliable name-to-topic-id resolver, topic list, or catalog for agent routing.

## What This Changes

The issue requests first-class Telegram forum topic-name to topic_id resolution so agents can route messages by human-readable topic names instead of requiring manual numeric IDs.

## Best Possible Solution

Keep this issue as the canonical tracker and design a Telegram-owned observed-topic catalog, list action, or resolver that returns topic IDs with explicit stale, duplicate, closed, and unknown-topic behavior.

Options:

- **Expose Observed Topic Catalog (recommended):** Add a Telegram-owned list/catalog action returning known topic IDs, names, closed state, and freshness so agents can resolve or ask when ambiguous.
- **Add Direct Resolver:** Add a name-to-ID helper that returns structured ambiguity or not-found results instead of silently routing on stale data.
- **Keep Numeric IDs Only:** Leave numeric topic IDs as the routing contract and document that name-based routing remains unsupported.

## Reproduction Assessment

Yes, source-reproducible: current main still routes Telegram forum sends through numeric thread IDs while the topic-name cache only returns names after chatId and threadId are known. I did not run a live Telegram forum group.

## Solution Assessment

Unclear which proposed surface is best. The existing cache is the likely data source, but the maintainable fix needs a maintainer-selected resolver, list, or catalog contract rather than relying on current-topic metadata.
