## Summary

Keep open: current main and v2026.6.11 still expose only numeric Telegram topic routing plus reverse/current-topic name metadata, not the requested forward topic-name to topic_id catalog or resolver.

## What This Changes

Request first-class Telegram forum topic-name to topic_id resolution for agent routing, via context map, list action, or channel metadata endpoint.

## Best Possible Solution

Keep this as the canonical tracker and design a Telegram-owned observed-topic catalog, list action, or resolver with explicit duplicate, stale, renamed, and closed-topic behavior before routing by name.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw expose a Telegram forum topic title-to-topic_id routing surface, and should it be prompt context, a message action, or a channel metadata/plugin SDK endpoint?

Rationale: Current code intentionally exposes names only after a numeric topic id is known; choosing forward routing needs maintainer intent for ambiguity, freshness, Bot API limits, and the agent/plugin contract.

Likely owner: obviyus

Owner reason: The likely design owner is tied to the persisted topic-name cache that any catalog or resolver would build on.

Owner confidence: high

Options:

- **Expose Observed Topic Catalog (recommended):** Add a Telegram-owned list/catalog action or metadata endpoint returning known topic ids, names, closed state, and freshness so agents can ask when ambiguous.
- **Add Resolver-Only Helper:** Add a direct name-to-id helper that returns structured ambiguity or stale-data errors instead of silently choosing among duplicates.
- **Keep Numeric-Only Routing:** Leave topic names as display/context metadata and document numeric topic ids or chatId:topic:<threadId> as the only supported routing contract.

## Reproduction Assessment

Yes, at source level. Current main still routes Telegram forum sends through numeric messageThreadId or chatId:topic:id, while the existing cache only returns a name after the numeric id is known; I did not run a live Telegram forum group.

## Solution Assessment

Unclear which proposed surface is best. The existing topic-name cache is the likely data source, but the maintainable fix needs a maintainer-selected resolver, list, or catalog contract rather than relying on current-topic metadata.
