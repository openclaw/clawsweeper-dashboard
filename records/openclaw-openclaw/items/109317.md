## Label Justifications

- `P1`: The reported one-strike watchdog can disrupt the active Control UI chat, terminal, and event workflow during real transient gateway stalls.

## Summary

Keep open for maintainer review: current main still reconnects the whole Control UI socket after one silent failed terminal probe, while this focused patch changes that to two consecutive failures with strong regression coverage and no concrete correctness defect found.

## What This Changes

The PR makes the Control UI terminal liveness watchdog require two consecutive silent probe failures before reconnecting the shared gateway WebSocket, with counter-reset logic and expanded tests.

## Best Possible Solution

Keep the bounded two-strike policy, but verify in a real browser session that an induced transient gateway stall preserves chat and terminal state while a genuinely dead socket still reconnects within the expected maximum delay.

## Solution Assessment

Yes. Requiring consecutive silent failures is a narrow client-side fix that distinguishes a transient busy gateway from a persistently dead socket without adding configuration or changing the gateway protocol.
