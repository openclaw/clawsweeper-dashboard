## What This Changes

The PR adds generation-bound recovery receipts and a Gateway session-identity precondition so concurrent orphan-recovery scans do not dispatch duplicate subagent resumes.

## System Context

After a gateway restart, orphan recovery reads active subagent runs and their interrupted session-store entries, then dispatches a synthetic resume through the Gateway. This PR inserts a receipt/identity gate between that scan and Gateway admission, affecting whether a subagent session is resumed, skipped, or retried.

## Architecture Diagram

flowchart LR

  B --> C[Orphan recovery scan]
  C --> D[Session-store marker check]
  D --> E[Generation-bound recovery receipt]
  E --> F[Gateway admission]
  F --> G[Registry and session marker update]
  G --> H[Recovered or safely skipped session]

## Best Possible Solution

Keep the generation- and marker-bound receipt design if a real gateway restart scenario demonstrates one resume per interrupted generation while confirming that a later genuinely newer interruption still recovers.
