## Summary

This PR remains necessary because current main still uses one process-global MCPorter daemon-start promise and does not implement the proposed per-agent generated configuration boundary. The patch has strong focused coverage and prior real runtime proof, but one user-facing discovery-order error should be corrected and the compatibility-sensitive generated-versus-external routing contract still needs explicit owner review before merge.

## What This Changes

The PR separates QMD and MCPorter process environments, creates per-agent generated MCPorter configuration and daemon identities for bare QMD servers, preserves user-owned configurations externally, updates documentation, and adds an extensive behavior matrix.

## Best Possible Solution

Correct the documented precedence, rebase onto current main, prove a fresh and upgraded installation through a live MCPorter-backed search—including at least one non-default external configuration—and obtain owner approval for the generated-versus-external classification and per-agent daemon lifecycle before merging.
