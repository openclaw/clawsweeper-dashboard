## What This Changes

The PR catches malformed JSON while restoring WhatsApp web credentials from backup, treats malformed test-helper session stores as empty, and adds a regression test for multi-byte malformed creds.

## Best Possible Solution

Land the narrow plugin-local recovery fix with the new regression test once maintainers accept backup restore as the intended behavior for unparseable WhatsApp creds.

## Reproduction Assessment

Yes. Source inspection shows a malformed creds.json longer than one byte reaches JSON.parse(raw) on current main and exits to return false before backup restoration; I did not execute it because this sweep is read-only.

## Solution Assessment

Yes. Catching the primary parse failure locally inside restoreCredsFromBackupIfNeeded is the narrow owner-boundary fix because the existing backup path already owns corrupted WhatsApp creds recovery and sibling save logic already preserves good backups when parsing fails.
