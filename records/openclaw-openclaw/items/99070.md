## What This Changes

The PR adds local `try/catch` handling around WhatsApp auth backup JSON parsing and the plugin test-helper session-store mock when malformed JSON is read.

## Best Possible Solution

Land the focused WhatsApp auth-store fix after the contributor adds real after-fix proof for corrupted credential restoration and ideally a regression test for the multi-byte malformed JSON case.

## Reproduction Assessment

Yes. From source, a WhatsApp auth directory with malformed `creds.json` longer than one byte and a valid `creds.json.bak` will hit `JSON.parse(raw)` inside the outer catch on current main and return false before backup restore; I did not run it because this review is read-only.

## Solution Assessment

Yes, this is the right narrow owner-boundary fix: catch the primary parse failure locally and continue to the existing backup path. The remaining gap is proof and regression coverage, not a different implementation layer.
