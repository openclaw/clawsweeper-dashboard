## Summary

## What This Changes

The PR wraps WhatsApp auth-store and test-helper `JSON.parse` calls in local `try/catch` blocks so malformed credential or mocked session JSON falls back to backup restore or an empty mock store.

## Best Possible Solution

Land the focused WhatsApp auth-store recovery fix with redacted after-fix proof and a regression test for malformed multi-byte `creds.json` restoring from a valid backup.

## Reproduction Assessment

Yes. Source inspection shows a malformed `creds.json` longer than one byte reaches `JSON.parse(raw)` on current main and returns false from the outer catch before backup restore; I did not execute it because this review is read-only.

## Solution Assessment

Yes. Catching the primary parse failure locally and continuing to the existing backup path is the narrow owner-boundary fix; the remaining blocker is proof and targeted coverage, not a different implementation layer.
