## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P2] Separate RPC rejections from transport drops:** `apps/android/app/src/main/java/ai/openclaw/app/chat/ChatController.kt:937-938`
  - body: `GatewaySession.request` throws for structured `ok:false` chat.send responses, including deleted or archived session rejections, and this catch records every throw as `TransportFailure`. That leaves invalid queued rows retrying as if the socket dropped instead of burning attempts and surfacing a failed/deletable command.
  - confidence: 0.92
- **[P2] Rotate failed-row retry idempotency keys:** `apps/android/app/src/main/java/ai/openclaw/app/chat/ChatCommandOutbox.kt:168-170`
  - body: User Retry requeues the same row id, but that id is the `chat.send` idempotency key and the gateway caches terminal results by `chat:<runId>`. Retrying after a terminal failure can replay the cached failure instead of starting a fresh turn; keep stable keys for ambiguous redelivery, not explicit failed-row retry.
  - confidence: 0.88
- **[P2] Rotate keys between terminal retry attempts:** `apps/android/app/src/main/java/ai/openclaw/app/chat/ChatController.kt:923-925`
  - body: The automatic retry loop calls `attemptOutboxSend(item)` repeatedly, and each attempt still sends `item.id` as the idempotency key. A transient terminal `error` or `timeout` ACK can be cached by the gateway and replayed for attempts 2 and 3, burning retries without re-running the turn.
  - confidence: 0.9
- **[P2] Purge main-alias outbox rows on canonical delete:** `apps/android/app/src/main/java/ai/openclaw/app/chat/ChatController.kt:1253-1254`
  - body: Rows queued before gateway hello can have `sessionKey == "main"`, while the UI and flush path map them to the canonical main session. When that canonical main session is deleted, this exact-key purge misses the alias rows, so they can remain visible and later flush into a deleted session.
  - confidence: 0.9
- **[P2] Use non-destructive storage for durable outbox rows:** `apps/android/app/src/main/java/ai/openclaw/app/chat/ChatTranscriptCache.kt:175-178`
  - body: Adding `OutboxCommandEntity` to this destructively migrated database makes queued user commands disposable on a future schema bump. The outbox needs a non-destructive migration path, separate durable owner, or explicit maintainer acceptance before shipping.
  - confidence: 0.9
- **[P2] Move queued sends out of composition scope:** `apps/android/app/src/main/java/ai/openclaw/app/ui/chat/ChatComposer.kt:275-276`
  - body: The composer clears the draft before launching `onSend` in a composition-bound coroutine; if the sheet or screen is dismissed, navigated away, or recreated right after tapping Send, cancellation can prevent runtime send/queue and the restore path may never run. Hand the send to ViewModel/runtime scope before clearing local UI state.
  - confidence: 0.86
- **[P2] Route live sends behind queued outbox rows:** `apps/android/app/src/main/java/ai/openclaw/app/chat/ChatController.kt:336-346`
  - body: Once health is true, `sendMessageAwaitAcceptance` immediately starts a fresh live `chat.send` without checking queued or sending durable rows, so a newer command can execute before the offline backlog it should follow after cold open or reconnect. Preserve per-session order by queueing the live send behind pending outbox rows.
  - confidence: 0.83
