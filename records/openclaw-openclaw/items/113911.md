## Summary

Keep this issue open for maintainer review. Current main still builds plugin hook conversation data from session history, while the documented hook-facing message shape does not establish a stable persisted transcript-entry identifier; the requested identifier is a small but compatibility-sensitive plugin-hook API addition rather than a confirmed regression fix. Likely related people: solstead (medium confidence) for the hook-history lifecycle work, with current ownership otherwise requiring a fuller local history pass.

## What This Changes

Expose a stable persisted transcript-entry identifier to plugin conversation hooks so plugins can deduplicate and persist individual transcript messages safely.

## System Context

Agent lifecycle hooks give plugins a reconstructed view of an agent session’s conversation. Session-history loading supplies the message objects, which are then passed to hooks such as agent completion, compaction, and reset; without an entry identifier, plugins cannot reliably associate a hook message with its persisted transcript record.

## Architecture Diagram

flowchart LR
  A[Persisted session transcript] --> B[Session-history loader]
  B --> C[Conversation message list]
  C --> D[Agent lifecycle hooks]
  D --> E[Plugin persistence or deduplication]
  B -. entry id currently not exposed .-> E

## Best Possible Solution

Add one documented, namespaced transcript-entry identifier at the shared session-history-to-hook boundary, preserve existing message fields, and add regression coverage for agent-end, compaction, and reset hook payloads.
