## Summary

Keep open: current main and the latest release still expose session context-usage data, but native diagnostics only classify processing or queued stale session work and do not define a context-pressure alert for saturated terminal `done` sessions. The remaining work needs maintainer product direction plus live proof of the restart-to-done and silent message failure path before implementation.

## What This Changes

The issue requests native monitoring or recovery for sessions that are terminal `done` but still saturated at the context limit, because those sessions can appear inactive while agents stop responding.

## Best Possible Solution

Define one native context-pressure/session-liveness contract for saturated terminal sessions, expose it through the chosen diagnostics or health surface, and add regression coverage plus a live proof path for restart recovery.
