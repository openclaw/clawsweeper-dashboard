## Label Justifications

- `P2`: A normal Control UI edit can silently persist the wrong retained configuration value, but the report is narrowly scoped to redacted array round trips.
- `impact:data-loss`: Deleting or reordering a row can overwrite a retained row's durable value with a different row's prior value, losing the intended mapping.

## Summary

Keep open. Current `main` restores redacted array elements by their array index, so removing or reordering an id-keyed row can bind a retained row to another row’s original value. The linked, open candidate fix at https://github.com/openclaw/openclaw/pull/110659 directly owns the repair and should be reviewed/landed rather than competing with it.

Likely related people: `steipete` is the highest-confidence routing candidate from the repeated redaction/array-restore history; `joshavant` is also relevant from the earlier Control UI SecretRef round-trip work.

## What This Changes

Fix the Control UI redacted-config round trip so object-array values follow stable item identity rather than their prior array position.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/110659 if its identity matching remains limited to unique client-visible ids and its regression coverage proves both safe failure and positional fallback behavior.
