## Summary

Keep open: current main still lacks shell-path `openclaw cron add` counting, and the only matching fix path is an open, conflicting PR rather than merged code.

## What This Changes

The issue reports that successful assistant-created cron reminders via `openclaw cron add --at` can still receive the contradictory unscheduled-reminder note in Telegram replies.

## Best Possible Solution

Land or replace the linked fix with a narrow producer-side change that counts successful shell-driven `openclaw cron add` before the reply guard runs, with focused regression coverage and real Telegram or agent-run proof.

## Reproduction Assessment

Yes, at source level: current main increments `successfulCronAdds` only for structured cron tool adds, while the reply guard appends the note when reminder text has zero successful cron adds. I did not run a live Telegram or cron scenario in this read-only review.

## Solution Assessment

Yes, the best fix shape is to count successful shell-driven cron adds at the telemetry producer before the reply guard runs, rather than hiding the note only in Telegram delivery. The current linked PR is in the right ownership area but still needs review, repair, or replacement before merge.
