## Summary

Keep open: current main and the latest release still only count structured cron-tool adds, while the shell-driven `openclaw cron add` path is owned by an open, unmerged fix PR that currently needs repair before it can close this issue.

## What This Changes

The issue reports that Telegram replies can append a false unscheduled-reminder note after a reminder was successfully created with `openclaw cron add --at`.

## Best Possible Solution

Land or replace the linked fix with a narrow agent tool-result telemetry change that counts successful shell-driven `openclaw cron add` results before the reply guard runs, with focused regression coverage and real behavior proof.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. At source level, current main increments `successfulCronAdds` only for structured cron tool adds, while the reply guard appends the note when reminder text has zero successful cron adds.

## Solution Assessment

Yes. The best fix is to count successful shell-driven cron adds at the agent tool-result telemetry producer before the reply guard runs, rather than hiding the note only in Telegram delivery.
