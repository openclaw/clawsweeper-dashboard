## Summary

Keep open: current main and the latest release still only count structured `cron` tool adds, while this issue's shell-driven `openclaw cron add` path is owned by an open, unmerged fix PR.

## What This Changes

The issue asks OpenClaw to stop appending the false unscheduled-reminder note after a reminder was successfully created through cron scheduling.

## Best Possible Solution

Review, repair, and land or replace the linked fix so successful shell-driven `openclaw cron add` results update the same per-turn counter before the reply guard runs, with focused regression coverage and redacted real behavior proof.

## Reproduction Assessment

Yes, at source level: current main counts only structured `cron` add tool calls, while the reply guard appends the note when reminder text has zero successful cron adds. I did not run a live Telegram or cron scenario in this read-only review.

## Solution Assessment

Yes, the best fix shape is to count successful shell-driven cron adds at the agent tool-result telemetry producer before the reply guard runs, rather than hiding the note only in Telegram delivery. The current linked PR is in the right ownership area but still needs review, repair, or replacement before merge.
