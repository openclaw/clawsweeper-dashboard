## Summary

Keep open: current main and the latest release still count only structured cron-tool adds, and the linked open PR that targets shell-driven `openclaw cron add` is unmerged and conflicting.

## What This Changes

The issue reports that a contradictory unscheduled-reminder note is appended after a reminder is successfully created through `openclaw cron add`, especially from Telegram-visible flows.

## Best Possible Solution

Land or replace the linked PR with a narrow producer-side fix that counts verified shell-driven `openclaw cron add` successes before the reply guard runs, with regression coverage and real cron or Telegram proof.

## Reproduction Assessment

Yes. At source level, current main increments `successfulCronAdds` only for structured cron tool adds, while the reply guard appends the note when reminder text has zero successful cron adds.

## Solution Assessment

Yes. The best fix shape is to count successful shell-driven cron adds at the telemetry producer before the reply guard runs; Telegram-only sanitization would leave the shared reply/session state wrong.
