## Summary

Keep open: current main and the latest release still count only structured cron-tool additions as successful reminder scheduling, so a shell-driven `openclaw cron add --at ...` can leave the reply guard with `successfulCronAdds === 0` and append the contradictory note.

## What This Changes

The report asks OpenClaw to stop appending the unscheduled-reminder note after a reminder was successfully created through cron scheduling.

## Best Possible Solution

Land a narrow producer-side fix that counts successful exec/bash `openclaw cron add` results before the reply guard runs, without adding a Telegram-only sanitizer or new config surface.

Yes at source level: current main counts structured `cron` add results but not exec/bash `openclaw cron add`, while the reply guard appends the note whenever reminder text has zero successful cron adds. I did not run a live Telegram or cron scenario in this read-only review.

## Solution Assessment

Yes: the maintainable fix belongs at the telemetry producer that sets `successfulCronAdds`, not in a downstream channel sanitizer. The patch should narrowly parse the shell command and success result, then add regression coverage for successful, failed, and unrelated exec commands.

## Repair Work Prompt

Fix the shell-driven cron scheduling false-note bug reported at https://github.com/openclaw/openclaw/issues/52972. On current main, `handleToolExecutionEnd` increments `successfulCronAdds` only for structured `cron` tool add calls, so an agent that runs `openclaw cron add --at ...` through `exec` or `bash` can successfully create the job while the reply guard still sees zero cron adds and appends the unscheduled-reminder note. Add a narrow producer-side counter path in `src/agents/embedded-agent-subscribe.handlers.tools.ts` that recognizes successful exec/bash `openclaw cron add` results using the start args command plus the real CLI/tool success shape; avoid broad substring/prose-only matching, failed command overcounting, Telegram-only sanitizing, new config, or unrelated reminder-guard regex changes. Add focused regression tests in `src/agents/embedded-agent-subscribe.handlers.tools.test.ts` for valid success, failed result, missing success receipt, unrelated commands, and bypass-like substring cases. Run the focused agent handler tests and the reply-guard tests, then provide real behavior proof of an agent turn that runs `openclaw cron add --at ...` through exec/bash and delivers a confirmation without the false note, with private details redacted.
