## Summary

Keep open: current main and the latest release still count only structured cron-tool adds, and the shell-driven `openclaw cron add` fix is owned by an open, unmerged PR with conflicts and a pending real-proof ask.

## What This Changes

The issue reports that Telegram replies can append the unscheduled-reminder note after a cron reminder was successfully scheduled through `openclaw cron add`.

## Best Possible Solution

Land or replace the linked fix with a narrow counter-path change that counts successful shell-driven `openclaw cron add` results before the reply guard runs, with focused regression coverage and real behavior proof.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. At source level, current main increments `successfulCronAdds` only for structured cron tool adds, while the reply guard appends the note when reminder text has zero successful cron adds.

## Solution Assessment

Yes. The best fix shape is to count successful shell-driven cron adds at the telemetry producer before the reply guard runs, rather than hiding the note only in Telegram delivery.
