## Summary

Keep this PR open: its objective is useful, but the `statSync` pre-check does not bound the subsequent `readFile`, so a file can grow between the check and read and still cause the doctor migration to allocate an unbounded buffer. The hard caps also need an explicit migration-policy decision because valid persisted Reef history above those limits would no longer import. Likely related people: cxbAsDev is the low-confidence routing contact as the author of both proposed commits; current-main feature ownership could not be established from the available read-only inspection path.

## What This Changes

The branch adds size pre-checks before four legacy Reef doctor-migration readers load audit, replay, review, and delivery files.

## Best Possible Solution

Implement a lossless, bounded-memory Reef legacy-state import—using descriptor/stream-based parsing and incremental SQLite migration where needed—then prove both oversized-history handling and normal legacy migration with redacted doctor output.
