## Summary

Keep this PR open: it addresses a credible doctor-migration memory risk, but the `statSync` pre-check does not actually bound the subsequent path-based `readFile` when an append-only legacy log grows between those operations. The patch also needs real after-fix migration evidence and a documented recovery path for already-large user state files before merge.

## What This Changes

The PR adds per-file size checks before Reef doctor migration reads four legacy state files, rejecting files above 50 MiB for JSONL logs or 10 MiB for JSON files.

## Best Possible Solution

Use a reader that enforces the byte limit during the actual read, add regression coverage for oversized and concurrently growing legacy logs, and define a supported doctor recovery or bounded migration path for legitimate existing state above the caps.

## Solution Assessment

No: a pre-read stat alone is not the narrowest reliable bound for a concurrently growing append-only file. A byte-bounded reader plus an explicit oversized-state recovery behavior is safer and matches the intended doctor hardening.
