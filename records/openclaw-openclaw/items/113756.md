## Summary

This remains an actionable WebChat delivery-ordering report: it names a fresh reproduction on 2026.7.1-2 and describes asynchronous image completion replies interleaving with ordinary session replies. Earlier reports establish a related race family, but they cover Slack message-tool sends and Telegram subagent timing rather than proving the same WebChat path; they should inform diagnosis, not close this issue as a duplicate.

## What This Changes

The issue requests that ordinary WebChat replies and asynchronous background image-task completion replies appear in one consistent chronological order within a direct session.

## System Context

WebChat sends user turns through the Gateway and displays the resulting session transcript and visible reply events. Background image work can complete after later conversational turns, so its completion delivery must preserve the same ordering contract as normal reply delivery before the chat UI renders it.

## Best Possible Solution

Capture a focused current-version reproduction, trace the normal and background-completion visible-reply paths to their shared session boundary, and make both use one ordered delivery contract with regression coverage for later user turns arriving before completion.
