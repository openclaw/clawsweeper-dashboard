## Summary

Keep open: current main and v2026.6.11 still enforce the exact single-target memory-flush write guard, while user comments report recurrence after the direct fix PR closed unmerged. The remaining decision is not cleanup-closeable because relaxing the guard changes a silent housekeeping run's workspace write authority.

## What This Changes

The issue requests relaxing the pre-compaction memory-flush write guard so unrelated workspace writes are not rejected during flush runs.

## Best Possible Solution

Define and land a maintainer-approved memory-flush write-authority contract that either keeps the single-target append guard or allows narrowly validated non-memory workspace writes with tests, docs, and explicit security reasoning.

Options:

- **Approve a narrow exception contract (recommended):** Allow non-memory workspace writes to pass through the existing write tool's workspace and sandbox checks while keeping memory-path writes restricted to the configured append-only target, with focused regression tests and docs.

- **Add an explicit operator opt-in:** Introduce a config-gated broader write mode with upgrade docs, but accept the added configuration surface and compatibility burden.
