## Summary

Keep open: current main and latest release still enforce the exact one-file memory-flush write guard, user comments report recurrence after the closed unmerged passthrough PR, and relaxing the guard needs maintainer product/security direction rather than conservative cleanup closure.

## What This Changes

The issue reports that memory-flush compaction restricts the write tool to the daily memory file and blocks unrelated file edits during active sessions.

## Best Possible Solution

Define and land a maintainer-approved memory-flush write-authority contract that either preserves the single-target append guard with better recovery UX or allows narrowly validated non-memory exceptions with tests, docs, and explicit security reasoning.
