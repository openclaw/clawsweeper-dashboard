## Summary

Keep open: current main still supports the split paths-only upload arm plus later click workflow, and the file chooser client still wraps `/hooks/file-chooser` with a fixed 20s request timeout. Current dispatcher-path error handling has improved, but the reported atomic-upload/API-contract question and live dynamic-page proof gap remain.

## What This Changes

The issue requests a more robust browser upload/file chooser flow that avoids stale trigger refs and does not misreport action-path failures as browser-control outages.

## Best Possible Solution

Make the Browser upload contract explicit: keep paths-only arming with correct timeout/error semantics or steer uploads to the existing atomic upload-with-trigger path, then cover the choice with focused Browser plugin tests and live dynamic-page proof.

- **Document current workaround only:** Leave runtime behavior unchanged and document stale-ref recovery plus selector/batch mitigations, accepting that the underlying flake remains possible.
