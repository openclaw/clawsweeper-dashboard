## Summary

Keep open: current main partially improves the timeout-reporting side, but the central browser upload/file chooser problem is not fully solved because upload arming still has a fixed 20s client timeout and the model-facing atomic-upload preference remains a maintainer behavior decision.

## What This Changes

The issue reports flaky browser upload/file chooser handling when upload arming and chooser-trigger clicks are split across requests, plus misleading timeout errors after stale ref failures.

## Best Possible Solution

Keep the split API compatible, but make the model-facing path prefer atomic `upload` with `ref` when a chooser trigger is known, align the upload hook client timeout with the route timeout budget if maintainers confirm that behavior, and add focused browser contract plus live repro proof.
