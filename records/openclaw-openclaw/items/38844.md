## Summary

Keep open: current main and the latest release still preserve the paths-only upload arming path and fixed 20s file-chooser client wrapper, while the merged selector/batch work only mitigates adjacent stale-ref workflows and does not settle the reported upload contract or live dynamic-page failure.

## What This Changes

The issue asks for browser file chooser uploads to avoid stale-ref split flows and to keep browser action failures from being reported as browser-control outages.

## Best Possible Solution

Make the Browser upload contract explicit: preserve paths-only arming with clearer timeout/error semantics or steer agent/tool flows to upload-with-trigger/direct input behavior, then validate on a dynamic-page upload trace.
