## Summary

Keep open: current main and the latest release still preserve the paths-only upload-arming workflow and the agent helper still wraps `/hooks/file-chooser` with a fixed 20s client timeout. Main has adjacent mitigations for selector/batch actions and dispatcher-path error wording, but the upload atomicity/stale-ref contract still needs maintainer direction and live dynamic-page proof.

## What This Changes

The issue asks OpenClaw to make browser file chooser uploads robust on dynamic pages and keep stale-click/action timeouts specific instead of reporting browser-control outages.

## Best Possible Solution

Make the Browser upload contract explicit, then either preserve paths-only arming with better timeout/error semantics or steer agent/tool flows to the existing atomic upload-with-trigger path with focused tests and live dynamic-page proof.
