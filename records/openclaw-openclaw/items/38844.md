## Summary

Keep open: current main and the latest release still accept paths-only browser upload arming and still use a fixed 20s outer `/hooks/file-chooser` client timeout. The existing atomic upload-with-ref path and merged selector/batch work are useful partial mitigations, but they do not settle the Browser upload contract or prove the stale-ref timeout report is fixed.

## What This Changes

The issue reports flaky browser upload/file chooser flows where split upload arming and later stale trigger clicks can be misreported as browser control service timeouts.

## Best Possible Solution

Make the Browser upload contract explicit: either preserve paths-only arming with clearer timeout/error behavior or steer agent uploads to atomic upload-with-trigger, then add focused Browser plugin tests plus live dynamic-page proof.

## Reproduction Assessment

No high-confidence live current-main reproduction was run. Source inspection still shows the split paths-only arming path and fixed hook request timeout that make the reported failure plausible.

## Solution Assessment

Unclear: the existing upload-with-ref route is the right atomic boundary, but maintainers still need to decide whether paths-only arming remains supported API or should be retired/migrated.
