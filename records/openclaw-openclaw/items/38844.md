## Summary

Keep open: current main and the latest release still support paths-only browser upload arming and the Browser agent client still uses a fixed 20s outer `/hooks/file-chooser` timeout. Merged selector/batch work helps adjacent stale-ref workflows, but it does not settle the upload contract or prove the reported dynamic-page timeout/stale-ref behavior is fixed.

## What This Changes

The issue asks OpenClaw to make browser file chooser uploads on dynamic pages favor an atomic upload-and-trigger flow and keep stale-click/action timeout errors specific instead of reporting a browser-control outage.

## Best Possible Solution

Make the Browser upload contract explicit: preserve paths-only arming with correct timeout/error semantics or steer uploads to an atomic upload-with-trigger path, then cover it with Browser plugin tests and live dynamic-page proof.

Rationale: Both behaviors are currently supported, and changing the default could improve reliability while also affecting callers that intentionally arm a chooser before a later trigger.

- **Document current workaround only:** Leave runtime behavior unchanged and document stale-ref recovery plus selector/batch mitigations, accepting that the underlying flake remains possible.
