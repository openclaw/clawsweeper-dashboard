## Summary

Keep open: current main has partial fixes and mitigations, but the central upload-flow reliability request is not implemented. The Browser tool still leaves upload-trigger atomicity to caller-supplied `ref`/`inputRef`/`element`, the model-facing upload path can still arm without a trigger, and the file-chooser client path still has a fixed 20s outer timeout.

## What This Changes

The issue requests more robust browser file chooser uploads, especially atomic upload-plus-trigger handling on dynamic pages and accurate timeout/error reporting for stale browser actions.

## Best Possible Solution

Define the Browser upload contract first, then either document and guide the existing explicit `ref`/`inputRef`/`element` flow or implement a narrow atomic upload-trigger path with timeout slack, stale-ref diagnostics, focused tests, and live dynamic-page proof.
