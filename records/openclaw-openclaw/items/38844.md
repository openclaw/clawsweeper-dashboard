## Summary

Keep open: current main still supports paths-only file-chooser arming and still wraps `browserArmFileChooser()` with a fixed 20s client timeout, while merged selector/batch work only mitigates adjacent stale-ref cases.

## What This Changes

The issue requests a more robust browser upload/file chooser flow on dynamic pages and clearer error reporting when stale-click or browser action failures occur.

## Best Possible Solution

Make the Browser upload contract explicit, preserve compatibility for paths-only arming unless maintainers choose otherwise, and steer agent/tool flows toward same-request trigger upload with focused tests and live dynamic-page proof.
