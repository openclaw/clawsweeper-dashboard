## Summary

Keep open: current main still supports paths-only Browser upload arming, still has a fixed 20s outer `/hooks/file-chooser` client timeout, and still treats upload-with-trigger as optional rather than the preferred atomic dynamic-page path. Related selector/batch and dispatcher-error work partially mitigates adjacent stale-ref behavior, but it does not settle the upload contract or provide live current-main proof that this report is fixed.

## What This Changes

The issue reports flaky Browser file chooser uploads where paths-only upload arming followed by a separate stale ref click can later surface as a misleading browser-control timeout.

## Best Possible Solution

Make the Browser upload contract explicit, then either preserve paths-only arming with clearer timeout/error semantics or steer agent/tool flows to atomic upload-with-trigger behavior with focused Browser tests and live dynamic-page proof.

- **Document current workaround only:** Leave runtime behavior unchanged and document stale-ref recovery plus selector/batch mitigations, accepting that dynamic-page flakes can remain.
