## Summary

Keep open: current main still supports paths-only browser upload arming, optional same-request trigger handling, and a fixed 20s file-chooser client wrapper, so the reported upload contract and dynamic-page timeout behavior are not settled by the merged selector/batch mitigation.

## What This Changes

The issue asks for browser upload/file chooser flows to avoid stale-ref split failures and keep browser-action timeouts distinguishable from browser-control reachability failures.

## Best Possible Solution

Make the Browser upload contract explicit, preserve compatible paths-only arming or intentionally migrate callers to atomic trigger/direct-input behavior, and validate the chosen path on a dynamic-page upload trace.
