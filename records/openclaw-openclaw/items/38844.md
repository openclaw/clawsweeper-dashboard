## Summary

Keep open: current main still preserves the split upload-then-click Browser upload API and the Browser agent client still wraps `/hooks/file-chooser` with a fixed 20s request timeout. Merged selector/batch work reduces adjacent stale-ref workflows, but it does not prove the dynamic-page upload contract or reported timeout/stale-ref behavior is fixed.

## What This Changes

The issue requests a more robust Browser upload/file chooser flow that avoids stale refs and keeps browser action timeout errors specific.

## Best Possible Solution

Make the Browser upload contract explicit: keep paths-only arming with better timeout/error semantics and atomic guidance, or intentionally steer agent/tool flows to upload-with-trigger with tests and live proof.
