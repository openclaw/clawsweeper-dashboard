## Summary

Keep open: current main and v2026.6.11 partially mitigate the report, but they do not prove the central dynamic-page upload flow is resolved. The Browser tool still exposes upload as an arming call, the direct client still uses a fixed 20s file-chooser request timeout, and the remaining atomic-upload behavior needs maintainer product/API direction plus live proof.

## What This Changes

The issue asks to make managed browser file-upload chooser flows robust by preferring atomic upload-plus-trigger handling and preserving stale-ref/action-timeout diagnostics instead of transport-outage wording.

## Best Possible Solution

Keep this as Browser plugin/API work: decide the intended managed-profile upload contract, then implement the chosen atomic/direct-input/default guidance path with a live dynamic-page proof and focused regression coverage.
