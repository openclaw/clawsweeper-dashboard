## Summary

Keep open: current main and v2026.6.11 still support paths-only browser upload arming with a fixed 20s client request timeout, while atomic upload-with-ref only happens when the trigger ref is supplied in the same upload request. Merged selector and batch work helps adjacent stale-ref workflows, but it does not settle the upload contract or prove the reported dynamic-page timeout path is fixed.

## What This Changes

The issue asks for browser file chooser uploads to avoid stale split upload/click flows and to preserve action-specific errors instead of surfacing misleading browser-control timeouts.

## Best Possible Solution

Make the Browser upload contract explicit: keep documented paths-only arming with action-specific timeout/error semantics, or steer agents to atomic upload-with-trigger behavior, then validate with Browser plugin tests and live dynamic-page proof.
