## Summary

Keep open: current main fixes part of the timeout wording for local dispatcher failures and shipped selector/batch mitigations reduce some stale-ref workflows, but the Browser upload contract still allows paths-only arming plus a later stale-ref click and the latest release still has the fixed 20s upload-hook client wrapper.

## What This Changes

The issue asks for browser file-upload flows to avoid stale-ref split upload/click failures and to preserve action-specific timeout errors instead of reporting healthy browser-control paths as service outages.

## Best Possible Solution

Make the Browser upload contract explicit: preserve paths-only arming with correct timeout/error semantics, or steer agent uploads to the existing atomic upload-with-trigger path with focused Browser plugin tests and live dynamic-page proof.
