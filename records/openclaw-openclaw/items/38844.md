## Summary

Keep open: current main and the latest release still support paths-only file-chooser arming and the Browser tool helper still wraps `/hooks/file-chooser` with a fixed 20s client timeout. Main has adjacent improvements for selector/batch actions and dispatcher-path error context, but the atomic upload-with-trigger contract and live dynamic-page proof are still unresolved.

## What This Changes

The issue asks for managed Browser upload/file-chooser flows to avoid split upload-then-stale-click failures and to keep browser action timeouts distinguishable from browser-control service outages.

## Best Possible Solution

Make the Browser upload contract explicit, keep paths-only arming compatible unless maintainers choose otherwise, steer known-trigger flows toward the existing atomic upload-with-trigger path, and prove the timeout/error behavior with focused tests plus a live dynamic-page upload trace.
