## Summary

Keep open: current main and the latest release still leave the Browser upload contract unsettled for paths-only arming, and the agent Browser client still uses a fixed 20s `/hooks/file-chooser` outer timeout even though the route already supports atomic upload-plus-click when `ref` is provided.

## What This Changes

The issue reports flaky managed-browser file chooser uploads when upload arming and trigger clicks are split, plus misleading timeout wording when stale-click or action failures look like browser-control outages.

## Best Possible Solution

Define the Browser upload contract explicitly: keep upload-with-ref as the preferred atomic path, decide whether paths-only arming remains supported, align the agent-client hook timeout with that decision, and add focused Browser plugin tests plus live dynamic-page proof.

## Reproduction Assessment

No high-confidence live reproduction was run. Source inspection still shows the relevant paths-only upload arming path and fixed 20s agent-client file-chooser timeout, so the remaining issue is source-reproducible but needs a live dynamic-page trace.

## Solution Assessment

Unclear: upload-with-ref is the right atomic boundary already, but maintainers need to decide whether paths-only arming is a supported Browser API mode and what timeout budget the agent client should guarantee.
