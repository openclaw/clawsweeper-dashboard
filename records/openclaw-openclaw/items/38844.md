## Summary

Keep open: current main and v2026.6.11 still preserve paths-only browser upload arming and a fixed 20s file-chooser client wrapper, while merged selector/batch work only mitigates adjacent stale-ref flows rather than settling the reported upload contract or proving the dynamic-page failure fixed.

## What This Changes

Browser upload/file chooser flows can split upload arming from trigger clicking, letting dynamic-page refs go stale and obscuring failures as browser control timeouts.

## Best Possible Solution

Make the Browser upload contract explicit: preserve paths-only arming with clearer timeout/error semantics or steer agent/tool flows to upload-with-trigger/direct input behavior, then validate on a dynamic-page upload trace.
