## Summary

Keep open. Current main has shipped partial improvements for dispatcher-timeout wording and selector/batch browser actions, but the specific upload/file-chooser problem still has unresolved product and implementation questions around making upload+trigger the preferred atomic flow, handling stale refs on dynamic pages, and proving the live browser behavior.

## What This Changes

The issue asks OpenClaw to make browser upload/file-chooser flows robust against stale trigger refs and to avoid reporting browser action failures as browser-control transport outages.

## Best Possible Solution

Define a focused browser upload contract: agents should use one upload request with the current trigger ref/inputRef/element when possible, the client timeout should allow the route-level action result to surface, and any stale-trigger failure should tell the agent to re-snapshot rather than restart the gateway.
