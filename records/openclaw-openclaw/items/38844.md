Keep open: current main still supports paths-only browser upload arming, retains a fixed 20s outer `/hooks/file-chooser` client timeout, and has no live dynamic-page proof that the stale-ref-to-timeout report is fixed. Merged selector/batch work helps nearby workflows, but it does not settle the Browser upload contract.

## What This Changes

The issue asks for a more robust Browser upload/file-chooser flow that avoids stale refs and keeps browser action timeout errors specific.

## Best Possible Solution

Make the Browser upload contract explicit, then cover the chosen atomic or compatibility-preserving path with Browser plugin tests and live dynamic-page proof.
