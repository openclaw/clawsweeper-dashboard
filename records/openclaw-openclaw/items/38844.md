## Label Justifications

- `P2`: The bug can falsely report upload success and affect a later browser interaction, but its blast radius is limited to managed-browser file chooser uploads.
- `impact:session-state`: A detached chooser waiter can outlive the originating request and consume a later unrelated chooser event.

## Summary

Keep open: current main still returns success from the managed `paths + ref` route before chooser capture and file assignment complete, while the detached waiter suppresses failures and can affect a later chooser. The merged related PR improved guidance and timeout slack but did not fix this lifecycle defect.

## What This Changes

Fix managed-browser `paths + ref` uploads so the request owns and awaits the entire chooser lifecycle while preserving paths-only delayed arming and specific action errors.

## Best Possible Solution

Keep paths-only delayed arming as its own explicit path, and add one awaited managed-Playwright operation for `paths + ref` that arms before clicking, awaits chooser capture, strict revalidation, and `setFiles`, propagates every failure, and revokes listener, timer, and ownership state in `finally` under one request deadline and abort signal.
