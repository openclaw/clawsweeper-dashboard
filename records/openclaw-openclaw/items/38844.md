## Summary

Keep open: current main still supports paths-only browser upload arming and only optionally clicks the trigger in the same request, so the central stale-ref upload contract question remains unresolved. Related selector/batch and timeout work helps adjacent flows, but it does not prove this dynamic file chooser flow fixed.

## What This Changes

The issue reports flaky Browser file chooser uploads where paths-only arming followed by a separate stale-ref click can become a misleading browser control timeout.

## Best Possible Solution

Make the Browser upload contract explicit, preserve compatibility unless maintainers choose otherwise, and add focused tests plus live proof for the chosen atomic upload path and timeout/error behavior.
