## Summary

Keep this PR open for repair: the durable-ingress direction is appropriate and the earlier tombstone-pruning concern appears addressed, but the current head moves an existing account-validation failure behind HTTP acknowledgment and leaves the documented webhook behavior inconsistent with the implementation.

## What This Changes

The PR replaces detached in-memory Twilio webhook dispatch and replay guarding with SQLite enqueue-before-ack, sender-serialized draining, restart recovery, completed tombstones, and dead-letter handling.

## Best Possible Solution

Keep signature, payload, and AccountSid rejection before acknowledgment; durably enqueue the validated raw form before HTTP 200, drain through the core lifecycle seam, and align SMS documentation and focused tests with the new retention and backpressure contract.
