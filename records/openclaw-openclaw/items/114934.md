## Summary

Keep this PR open for normal review: it addresses a credible silent data-corruption path with a focused fail-closed repair, but it still needs contributor-provided after-fix behavior proof before merge.

## What This Changes

The branch makes the built-in `edit` and `apply_patch` tools reject files that are not valid UTF-8 so targeted edits cannot rewrite unrelated invalid bytes.

## System Context

OpenClaw agent file tools read workspace or host files, transform text requested by an agent, and write the result back to disk. This change sits at the byte-to-text boundary and prevents lossy decoding from turning a small text edit into persistent file corruption.

## Architecture Diagram

flowchart LR
  A[Agent edit request] --> B[Edit or patch tool]
  C[Host, workspace, or sandbox file] --> D[Read file bytes]
  D --> E{Valid UTF-8?}
  E -->|Yes| F[Apply text change]
  F --> G[Write updated file]
  E -->|No| H[Reject without writing]

## Best Possible Solution

Retain strict byte validation at every write-capable text-decoding boundary, document the explicit unsupported-encoding error through real behavior proof, and merge only after confirming invalid bytes remain unchanged across the affected paths.
