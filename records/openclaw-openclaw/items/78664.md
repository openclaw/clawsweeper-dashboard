## Summary

Keep open: current main still performs provider tool-schema normalization on every call, while this PR adds a conservative process-local parameter cache limited to known bundled compatibility normalizers and custom provider hooks bypass it. I found no blocking patch defect; the remaining merge work is normal maintainer review, a green required-check state, and coordination with adjacent open hook-hardening PRs.

## What This Changes

The branch adds a process-local LRU cache for provider-normalized tool parameters in embedded agent runs, resolves cache eligibility for bundled DeepSeek/Gemini/OpenAI normalizers, and updates focused tests, provider-hook docs, and the generated SDK baseline hash.

## Best Possible Solution

Keep the conservative bundled-normalizer-only cache shape, merge only after required checks are green, and refresh against whichever adjacent provider hook-hardening PR lands first.

## Solution Assessment

Yes, subject to green checks: limiting cache eligibility to known bundled normalizer identities and caching only cloned parameters is the narrowest maintainable fix I found. Custom provider hooks bypass the cache, which avoids turning third-party hook context into a stale cache contract.
