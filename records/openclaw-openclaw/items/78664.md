## What This Changes

Adds an internal LRU cache for provider-normalized tool schema parameters on repeated embedded-agent turns, scoped to bundled DeepSeek, Gemini, and OpenAI compatibility normalizers with custom provider hooks bypassing the cache.

## Best Possible Solution

Rebase onto current main, preserve the bundled-only cache scope and custom-provider bypass, rerun the focused tests/API baseline plus QA Smoke, then land after provider-runtime owner review.

## Reproduction Assessment

Yes at source level: current main calls provider tool-schema normalization on each wrapper invocation, and the PR proof/tests show repeated bundled normalization hitting the cache while custom provider hooks bypass it. I did not reproduce the live latency, OOM, or anti-abuse symptoms.

## Solution Assessment

Yes, after rebase this is the narrow maintainable fix shape: cache cloned parameters only for known bundled normalizers and rebuild tool objects, closures, approval state, and policy per turn. Caching full tool objects or custom provider hooks would be a riskier boundary.
