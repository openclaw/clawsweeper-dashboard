## What This Changes

Adds an internal LRU cache for provider-normalized tool schema parameters keyed by bundled compatibility family, model/API/base URL, and tool schema signature, with tests, provider-runtime glue, docs, and API-baseline hash refresh.

## Best Possible Solution

Land the internal cache after provider/runtime owner review and a clean or triaged QA smoke gate, keeping custom provider hooks uncached and avoiding new config or public plugin API surface.

## Reproduction Assessment

Yes at source level: current main normalizes through the provider hook on every call, and the PR proof/tests show repeated bundled normalization hitting the cache while custom provider hooks bypass it. I did not reproduce live provider latency, OOM, or anti-abuse behavior.

## Solution Assessment

Yes, this appears to be the narrowest maintainable shape: cache only cloned parameters for known bundled normalizer identities and rebuild tool objects, closures, approval state, and policy per turn. Caching full tools or custom provider hooks would be riskier and less aligned with the existing provider boundary.
