## Summary

Keep this open: current main still has a positive embedded-runner idle watchdog for cloud provider streams, and the OpenAI-compatible OpenRouter path only resets that watchdog when upstream chunks arrive. Main has mitigations, including per-provider timeoutSeconds and direct Anthropic fine-grained tool streaming, but I did not find a merged fix or live proof that the reported OpenRouter Anthropic large-tool-argument path now succeeds by default.

## What This Changes

The issue requests reliable embedded-runner handling for slow generation of large tool-call parameters so model turns do not fail with a generic network-loss error and lose work.

## Best Possible Solution

Keep this as the canonical issue until maintainers choose and prove a provider-safe fix, likely by combining documented timeout policy with provider-specific streamed tool arguments where supported and a live OpenRouter Anthropic regression proof.

## Reproduction Assessment

Yes at source level, but not as a fresh live current-main repro: the embedded runner still aborts provider silence between chunks, and the OpenAI-compatible path only advances when OpenRouter emits tool-call argument deltas. A high-confidence live repro still needs OpenRouter Anthropic credentials and the large Write-tool scenario from the report.

## Solution Assessment

Unclear: the request is valid, but the best permanent fix is a maintainer policy choice between timeout behavior, provider-specific tool streaming, or both. The current timeoutSeconds knob is a mitigation, not enough evidence to close this issue as solved.
