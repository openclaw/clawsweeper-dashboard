## Summary

Keep this open: current main has useful adjacent mitigations, but it does not yet prove the OpenRouter to Anthropic large tool-argument path can complete without losing the embedded run.

## What This Changes

The issue reports embedded runner network failures when slow OpenRouter-routed Anthropic models generate large tool-call parameters before usable stream activity reaches OpenClaw.

## Best Possible Solution

Verify the OpenRouter Anthropic large-tool-argument path live, then make the embedded runner either receive provider-side tool-argument deltas or use an explicitly compatible timeout/retry policy that preserves existing stall detection.

## Reproduction Assessment

Yes, source-backed but not live reproduced: the issue gives concrete OpenRouter Anthropic steps, and current source still has a 120s cloud first-event boundary with no OpenRouter-specific large-argument streaming wrapper. The exact provider behavior still needs live proof with an OpenRouter key and the slow model path.

## Solution Assessment

Unclear: current main's first-event timeout and explicit provider timeout support are useful mitigations, but they are not clearly the best final fix. Maintainers still need to choose between provider-specific tool-argument streaming, timeout policy changes, retry behavior, or a combination.
