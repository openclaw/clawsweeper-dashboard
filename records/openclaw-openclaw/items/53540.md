## Label Justifications

- `impact:message-loss`: The failed model turn produces no tool call, output file, or final assistant response.

## Summary

Keep this open: current main still has a chunk-based cloud LLM idle watchdog, and OpenRouter-routed Anthropic models still use the OpenAI-compatible stream path. Existing timeout knobs and native Anthropic tool-argument streaming are useful mitigations, but I did not find source, tests, or live proof that the reported default OpenRouter large-tool-argument path now succeeds.

## What This Changes

The issue asks OpenClaw to avoid `Network connection lost` failures when slow providers generate large tool-call parameters before emitting stream chunks.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose and prove a provider-safe fix, likely combining focused OpenAI-compatible streaming regressions with supported tool-argument streaming or an explicit timeout policy.
