## Summary

Keep this issue open: current main has useful mitigations for provider request timeouts and direct Anthropic fine-grained tool streaming, but I did not find a merged default fix or live current-main proof that the reported OpenRouter plus Anthropic large tool-argument path now succeeds.

## What This Changes

This issue reports embedded-runner LLM failures when a slow hosted model generates large tool-call parameters, especially large `Write` content through OpenRouter to Anthropic.

## Best Possible Solution

Prove the reported OpenRouter path live on current main, then prefer provider-specific tool-argument streaming where the transport supports it; otherwise use explicit provider timeout/retry/error handling without weakening cloud-stream hang detection globally.

## Reproduction Assessment

No high-confidence live reproduction was performed against current main. The issue has concrete reporter steps and the current source still contains the relevant OpenRouter transport plus positive idle watchdog path, so it is source-reproducible rather than fully reproduced.
