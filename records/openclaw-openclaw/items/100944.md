## Label Justifications

- `P1`: The issue reports silently dropped Signal DMs in a real channel workflow, which is an urgent user-facing message delivery regression.
- `impact:message-loss`: The failed debounce flush can drop an inbound Signal DM without a reply, retry, or visible user feedback.
- `impact:session-state`: The drop is triggered by reply-session initialization conflicts at the shared session-state boundary.

## Summary

Keep open: current main still has a Signal-specific debounce flush path that logs reply-session initialization conflicts and lets the debouncer drop the buffered DM, while Slack and Telegram now preserve the inbound through bounded retry/backoff paths.

## What This Changes

The issue asks for Signal inbound DM handling to retry or visibly preserve messages that hit reply-session initialization conflicts instead of silently dropping them.

## Best Possible Solution

Add a narrow Signal inbound retry/requeue path for reply-session initialization conflicts, matching the bounded Slack/Telegram behavior while leaving the shared session writer fixes intact.
