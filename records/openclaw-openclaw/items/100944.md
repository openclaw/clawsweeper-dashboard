## Summary

Keep open: current main still lacks Signal-specific retry or preservation when the inbound debounce flush hits a reply-session initialization conflict, and two open fixing PRs are already linked as candidates.

## What This Changes

Signal DM follow-up messages should not be silently dropped when the debounce flush hits a reply-session initialization conflict.

## Best Possible Solution

Land one narrow Signal plugin fix that preserves failed debounced inbound entries through bounded retry/backoff for this conflict class, with focused regression coverage and real Signal proof if practical.
