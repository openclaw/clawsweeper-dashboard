## Summary

This PR remains necessary because current `main` has not yet incorporated the restart-intent preservation path. The supplied production-path proof and focused regression coverage are strong, but this race-sensitive gateway change should stay open for gateway-owner review and completion of the fresh exact-head checks.

## What This Changes

The branch preserves a restart requirement from an unapplied coalesced gateway config write while still applying the newest configuration, including when a filesystem watcher echo claims the pending write.

## System Context

Gateway configuration writes reach the config reloader through the in-process write bus and filesystem watcher. The reloader coalesces competing updates, then either hot-reloads the latest configuration or restarts the gateway when the accumulated write intent requires it.

## Architecture Diagram

flowchart LR

  B[Pending write B: restart required] --> R
  W[Filesystem watcher echo] --> R
  C[Newest write C] --> R
  R --> D{Coalesce payload and intent}
  D --> E[Apply newest configuration]
  D --> F[Restart gateway when required]

## Best Possible Solution

Keep the narrow pending-origin provenance model, obtain a gateway-area review of its clear/retry lifecycle on the latest head, and merge only after the exact-head required checks complete successfully.
