## Summary

This PR remains necessary: current main still replaces a pending write’s full `afterWrite` intent and moves watcher candidates without recording whether they came from pending state, which leaves the reported restart-loss interleaving unaddressed. The proposed narrow provenance state and regression coverage appear consistent with the gateway’s existing latest-config coalescing model; it needs normal gateway-owner review of the final force-pushed head and its still-running checks, not a cleanup close.

## What This Changes

The PR preserves a restart-required intent from an unapplied coalesced gateway config write while continuing to apply the newest config payload, including when a watcher echo claims the pending write.

## Best Possible Solution

Land a focused gateway-state-machine fix only after an owner confirms that pending-origin restart intent is retained through watcher and missing-file retries, while active-origin intent never leaks into a newer write, with the newest configuration still winning.
