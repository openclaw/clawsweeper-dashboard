## What This Changes

The PR changes gateway configuration reload coalescing so that a restart required by an unapplied committed write survives a later non-restart write while the newest configuration remains the one applied.

## System Context

Gateway configuration changes arrive through in-process writes and filesystem watcher events, which the reloader coalesces while an earlier reload is active. The reloader chooses the newest configuration payload but must preserve any still-unapplied restart requirement before it either hot-reloads or restarts the running gateway.

## Best Possible Solution

Keep the narrow pending-origin invariant, land it only after gateway ownership review and exact-merge-head focused validation confirm that pending restart intent survives coalescing without allowing obsolete active intent to leak.
