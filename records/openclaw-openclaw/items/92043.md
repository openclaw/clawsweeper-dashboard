## Summary

Keep open: current main and v2026.6.11 still show the aggregate compaction timeout, timeout-shaped chunk progress discard, and hidden timeout guidance, while the open linked PR is the active fix path.

## What This Changes

The issue asks OpenClaw to prevent long compactions from failing in the same timeout loop by reusing partial chunk progress or otherwise avoiding one aggregate wall-clock failure, and to surface timeout/config guidance.

## Best Possible Solution

Review and either land a rebased https://github.com/openclaw/openclaw/pull/92899 or choose an equivalent bounded checkpoint design, then close this issue after the fix merges.

Yes at source level: current main uses the 180s aggregate compaction timeout and still rethrows timeout-shaped chunk failures before preserving completed chunk summaries. The issue and comments also include production confirmations, but I did not run a live slow-provider compaction in this read-only review.

## Solution Assessment

Yes with a maintainer policy decision: fixing the summary owner and shared timeout wrapper is a better direction than only telling users to raise a config knob. The open linked PR appears to target the right boundaries but needs conflict resolution and maintainer acceptance of the session-state semantics.
