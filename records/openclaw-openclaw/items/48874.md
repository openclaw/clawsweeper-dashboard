## Summary

Keep open: current main and v2026.6.11 have useful session lifecycle and routing primitives, but the RFC's full cross-session architecture, public shared-memory boundary, all-channel binding model, and topic/family state model are still product/security design work rather than implemented behavior.

## What This Changes

The issue proposes a broad multi-session architecture with shared LLM inference, isolated session contexts, shared public knowledge/RAG, and Web UI session lifecycle controls.

## Best Possible Solution

Keep this as maintainer-scoped architecture work and split accepted pieces into focused trackers for session-family state, channel binding/routing, UI lifecycle, and shared-memory privacy rules.
