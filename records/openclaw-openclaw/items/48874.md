## Summary

Keep open: current main now covers important lifecycle slices such as session create/list/patch, archive/restore/pin metadata, Control UI session actions, and the Google Chat group/direct classification slice, but the RFC’s all-channel binding model, session-family/shared-memory contract, and privacy/security boundary remain unresolved maintainer design work.

## What This Changes

Request a multi-session architecture with shared model inference, isolated per-channel/task sessions, public/shared knowledge, session lifecycle UI, and routing/key cleanup.

## Best Possible Solution

Keep this as a broad maintainer-scoped architecture RFC, route focused implementation to the narrower session-family, UI lifecycle, and selective shared-channel trackers, and close only after maintainers choose the shared-memory, routing, storage, and security contract.

## Reproduction Assessment

## Solution Assessment
