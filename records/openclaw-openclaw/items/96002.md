Full review comments:

- **[P1] Restrict CLI scope preservation to clean local Hosts:** `src/gateway/server/ws-connection/handshake-auth-helpers.ts:299-301`
  - body: `resolvePairingLocality` returns `direct_local` for any clean loopback socket before Host classification, and the handler only logs when that request carries a public/non-local Host. With this new `direct_local` allowance, a reverse proxy that connects over loopback without forwarded headers lets a CLI-shaped shared-secret client keep self-declared `operator.admin` scopes without a device. Gate the carve-out on the same local/private Host proof used by the container-local path, or pass an equivalent clean-local signal into this helper.
  - confidence: 0.9
- **[P2] Honor active password auth when omitting identity:** `src/gateway/call.ts:496-498`
  - body: The omission predicate keys password activity only off `authMode === "password"`, but supported password callers can arrive through explicit `url` + `password` config-bypass or through `gateway.auth.mode: "trusted-proxy"` local password fallback. Those paths still attach the durable CLI device identity and can hit the stale read-scoped pairing baseline the PR is meant to remove. Derive the active shared-secret kind from resolved credentials or add equivalent password-aware coverage here.
  - confidence: 0.88
