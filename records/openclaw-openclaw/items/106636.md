Keep open: the linked bug remains relevant and current main still writes sandbox command buffers without a demonstrated bounded-memory path, but this head is not merge-ready because its evidence is test-only and current main has since changed the SSH execution owner path.

## What This Changes

The PR adds a shared helper that converts large binary command input into 64 KiB readable-stream chunks and uses it for Docker and SSH sandbox commands.

## Best Possible Solution

Use one process-layer binary-input primitive that preserves the small-input fast path, streams large buffers with backpressure through both Execa-backed Docker and current-main direct SSH stdin, preserves abort and stream-error semantics, and is proven with real large writes plus exact-byte and memory measurements.
