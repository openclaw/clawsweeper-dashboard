## Summary

Keep open: current main still returns from ACP reset cleanup when cancellation times out, before the manager close path can evict the runtime handle and reap the process. The reporter’s second persisted-reset claim is not supported by current source because the reset-aware session-store wrapper intentionally hides a marked-fresh record on its next load, with focused coverage for that behavior.

## What This Changes

Fix ACP-backed session reset cleanup so timeout paths cannot leave a stale runtime or poisoned session available for reuse.

## Best Possible Solution

Add a manager-owned forced-discard cleanup path that evicts the runtime record and terminates the backend process after a bounded cancel or close failure, then keep the existing reset-aware fresh-session mechanism unless a regression test proves it insufficient.
