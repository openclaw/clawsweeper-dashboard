## What This Changes

Fix the Windows Desktop Tray reconnect flow so a successful pairing role upgrade delivers and persists the new node credential before the client retries the gateway connection.

## System Context

The Desktop Tray connects to the local Gateway over WebSocket using a paired-device credential. When the Gateway upgrades a device from operator to node access, it must issue the new token in the same handshake path so the Tray can persist it and reconnect without falling back into pairing.

## Architecture Diagram

flowchart LR
  A[Desktop Tray restart] --> B[Gateway WebSocket handshake]
  B --> C[Device pairing and role upgrade]
  C --> D[Issue node credential]
  D --> E[Send gateway hello]
  E --> F[Tray persists credential]
  F --> G[Connected Tray session]

## Best Possible Solution

Reproduce the reboot and role-upgrade path with supported matching Tray and Gateway versions, then ensure an already-approved connection receives and persists its newly issued node token before any reconnect attempt; add regression coverage for the successful upgrade-to-hello path and duplicate-device behavior.
