## Summary

Keep open. Current main still implements bundled session-memory as command-only persistence, while idle/daily rollover, shutdown drain, message-count checkpoints, and summary-output behavior remain separate lifecycle/product surfaces rather than a merged fix.

## What This Changes

Request automatic session-memory checkpoints on idle, shutdown, message count, and summary-output triggers instead of relying on manual `/new` or `/reset`.

## Best Possible Solution

Keep this as the broad session-memory automation tracker, consolidate the daily/idle candidate first, then explicitly scope shutdown checkpointing, periodic checkpoints, and opt-in summary output with privacy and dedupe rules.
