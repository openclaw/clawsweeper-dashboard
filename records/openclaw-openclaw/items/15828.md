## Summary

Keep open. Current main and the latest release still keep the bundled session-memory hook on explicit command triggers only; the requested idle, shutdown, message-count checkpoint, and summary-output behavior remains unimplemented and needs maintainer product/security scoping.

## What This Changes

Request adds configurable automatic session-memory checkpoint triggers for idle, shutdown, message count, and optional LLM summaries beyond `/new` and `/reset`.

## Best Possible Solution

Use this as the broad tracker: resolve the daily/idle reset hook path first, then design bounded shutdown and periodic checkpoint semantics plus opt-in summary/privacy config with docs and targeted tests.

## Reproduction Assessment

Yes for the current behavior gap: source inspection shows the bundled handler only accepts `command:new` and `command:reset`, while docs and metadata expose no idle, shutdown, periodic, or summary trigger configuration. I did not run a live gateway scenario because this review is read-only.

## Solution Assessment

No single automated fix is the best solution yet. The daily/idle, shutdown, periodic, and summary pieces cross lifecycle, config, storage, and privacy boundaries, so maintainers should split and approve the behavior shape before implementation.
