## Summary

Keep open. Current main and v2026.6.11 still leave bundled session-memory command-only; related shutdown and typed session lifecycle infrastructure exists, but it does not implement idle, shutdown, periodic, or summary checkpoints for this bundled hook.

## What This Changes

The issue requests automatic session-memory checkpoints for idle, shutdown, periodic message counts, and optional summarized memory output.

## Best Possible Solution

Keep this as the broad session-memory automation tracker: decide or land the daily/idle reset-hook path first, then scope shutdown, message-count, and summary-output behavior with bounded lifecycle guarantees, privacy defaults, docs, and focused tests.

## Reproduction Assessment

Yes. Source inspection is enough: enabling bundled session-memory and firing anything other than command:new or command:reset returns before memory capture, while current docs and metadata expose no requested trigger or summary configuration.

## Solution Assessment

No single automated fix is the best solution yet. The daily/idle, shutdown, periodic checkpoint, and LLM-summary pieces cross lifecycle, config, storage, and privacy boundaries, so maintainers should choose the behavior shape before implementation.
