## Label Justifications

- `P2`: The issue describes real session-memory preservation gaps with limited blast radius, but the remaining work needs product/security scoping rather than emergency handling.
- `impact:session-state`: The requested behavior is about preserving session context across idle, shutdown, command, and long-running conversation boundaries.
- `impact:data-loss`: Without automatic checkpoints, useful transcript context can be lost or require manual recovery when sessions rotate or the gateway stops.
- `impact:security`: Automatic transcript persistence and optional LLM-generated summaries would process private conversation data beyond the current explicit command boundary.

## Summary

Keep open. Current main and the latest release still keep bundled session-memory persistence scoped to explicit command hooks, while idle, shutdown, periodic checkpoint, and summary-output behavior remains unimplemented and needs maintainer product/security direction.

## What This Changes

The issue requests automatic session-memory persistence on idle, shutdown, periodic message checkpoints, and command resets, plus optional LLM summarization instead of raw transcript dumps.

## Best Possible Solution

Keep this as the broad session-memory automation tracker while maintainers choose one lifecycle contract: land or replace the daily/idle path, then separately scope bounded shutdown capture, periodic checkpoints, and opt-in summary output with privacy docs and regression coverage.

## Maintainer Decision

Rationale: The source-level gap is clear, but the permanent shape affects internal hooks, plugin-visible lifecycle events, shutdown deadlines, new config keys, and sensitive transcript retention, so automation should not choose the product/security boundary alone.

Likely owner: vincentkoc

Owner reason: Vincent Koc has the strongest current-line ownership signal on the bundled hook and docs, with recent adjacent fixes to session-memory responsiveness and filename behavior.

Owner confidence: high

Options:

- **Stage Lifecycle Contract (recommended):** Use or replace the daily/idle PR path first, then design shutdown, periodic checkpoint, and summary-output behavior as explicit opt-in surfaces with privacy and dedupe rules.
- **Narrow To Automatic Reset:** Split shutdown, message-count, and LLM summary output into separate follow-ups and keep this tracker focused on idle/daily reset persistence.
- **Move To Plugin-Owned Memory:** Define any missing generic plugin lifecycle API and let a memory plugin or ClawHub package own optional checkpointing behavior instead of expanding the bundled hook.

## Reproduction Assessment

Yes. Source inspection on current main shows bundled session-memory only handles command:new and command:reset, while idle/daily rollover and shutdown use separate lifecycle paths and the requested trigger/summary config is absent.

## Solution Assessment

Unclear as a single implementation. The direction is valid, but the best fix needs maintainer selection of the hook/API contract, privacy defaults, shutdown deadline, checkpoint dedupe, and summary semantics before an autonomous patch is safe.
