## Summary

Keep open. Current main and the latest release still keep bundled session-memory persistence scoped to explicit command hooks, while the requested idle, shutdown, periodic checkpoint, and summary-output behavior remains a broader product/security design item with only a partial open daily/idle candidate PR.

## What This Changes

The issue requests automatic session-memory checkpoints for idle, shutdown, message-count, and command triggers, plus an optional LLM summary output mode.

## Best Possible Solution

Keep this as the broad session-memory automation tracker while maintainers choose a lifecycle contract: land or replace the daily/idle PR path, then separately scope bounded shutdown capture, periodic checkpoints, and opt-in summary output with privacy docs and regression coverage.

## Reproduction Assessment

Yes. Source inspection on current main shows bundled session-memory only handles command:new and command:reset while daily/idle rollover and shutdown use separate lifecycle paths, and the requested trigger/summary config is absent.

## Solution Assessment

Unclear as a single implementation. The direction is valid, but the best fix needs maintainer selection of the hook/API contract, privacy defaults, shutdown deadline, and checkpoint dedupe semantics before an autonomous patch is safe.
