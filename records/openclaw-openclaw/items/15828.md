## Summary

Keep open: current main still leaves bundled session-memory on the manual `command:new` / `command:reset` path, while idle, shutdown, message-count checkpointing, and summary-output behavior remain missing; https://github.com/openclaw/openclaw/pull/61675 covers only the daily/idle slice and is still open.

## What This Changes

Requests automatic session-memory checkpoint triggers for idle, shutdown, and periodic message counts, plus optional concise summaries instead of relying only on `/new` or `/reset`.

## Best Possible Solution

Keep this as the broad tracker, consolidate the daily/idle slice through https://github.com/openclaw/openclaw/pull/61675 or a replacement, then define one maintainer-approved session-memory finalization contract for idle, shutdown, message-count checkpoints, summaries, dedupe, docs, tests, and privacy behavior.

Yes, source-level. Current main keeps bundled session-memory registered and implemented for `command:new` / `command:reset`, while idle rollover and shutdown use adjacent lifecycle paths that do not invoke that hook.
