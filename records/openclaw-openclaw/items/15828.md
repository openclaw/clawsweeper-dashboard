## Summary

Keep open: current main and the latest release still keep bundled session-memory on explicit `/new` and `/reset` only, while the requested idle, shutdown, periodic checkpoint, and summary-output behavior remains a product/security-sensitive lifecycle design task. The open daily/idle candidate pull request only covers part of this request and is not a merged fix.

## What This Changes

Request automatic session-memory preservation on idle, shutdown, periodic message checkpoints, and optionally model-generated summaries instead of only manual command-triggered capture.

## Best Possible Solution

Define a maintainer-approved session-memory finalization contract covering daily/idle rollover, shutdown/restart, periodic checkpoints, dedupe, privacy/retention, docs, and regression proof; then land https://github.com/openclaw/openclaw/pull/61675 only if it fits that broader contract or replace it with a narrower approved implementation.

## Reproduction Assessment

Yes at source level: current main registers and runs bundled session-memory only for command new/reset, while shutdown and session-end lifecycle paths exist separately. I did not run a live gateway because this review is read-only.

## Solution Assessment

Unclear as a final design: the missing behavior is real, but the best fix should be a maintainer-approved lifecycle/API and privacy contract rather than simply adding trigger config to the bundled handler.
