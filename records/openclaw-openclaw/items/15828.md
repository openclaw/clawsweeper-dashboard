## Summary

Keep open: current main and the latest release still keep bundled session-memory on manual `command:new`/`command:reset`, while this issue asks for idle, shutdown, periodic checkpoint, and summary-output behavior that remains product- and security-sensitive.

## What This Changes

Request automatic session-memory checkpoints on idle, shutdown, message-count intervals, and manual commands, plus optional LLM summary output and trigger configuration.

## Best Possible Solution

Keep this as the broad tracker, land or replace the daily/idle slice through the active related work, then define one maintainer-approved memory finalization contract for shutdown, periodic checkpoints, summaries, dedupe, docs, tests, and privacy behavior.

## Reproduction Assessment

Yes, at source level. Current main keeps bundled session-memory registered and implemented for `command:new`/`command:reset`, while idle rollover and shutdown use adjacent lifecycle paths that do not invoke that handler.

## Solution Assessment

Unclear pending maintainer product/API choice. The requested behavior is useful, but the best fix needs decisions on trigger contract, summary/provider privacy, shutdown deadlines, dedupe, and overlap with the open daily/idle implementation candidate.
