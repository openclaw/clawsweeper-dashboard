## Summary

Keep open. Current main and v2026.6.11 still keep bundled session-memory on explicit `/new` and `/reset` command events only; adjacent idle/daily and shutdown lifecycle hooks exist, but they do not implement the requested bundled memory checkpoints, periodic trigger, or summary-output mode.

## What This Changes

The issue requests automatic session-memory checkpoints on idle, shutdown, periodic message counts, and command events, plus optional LLM-generated summary output and trigger configuration.

## Best Possible Solution

Use this issue as the broad session-memory automation tracker, with a maintainer-approved opt-in design that consolidates daily/idle work first and then scopes shutdown, periodic, and summary-output behavior with privacy-safe defaults.

## Reproduction Assessment

Yes. Source inspection is enough to reproduce the current behavior gap: session-memory is still registered and guarded for command:new/command:reset only, while idle, shutdown, message-count, and summarize configuration are absent.

## Solution Assessment

No single automated fix is the best path yet. The request crosses lifecycle, config, storage, and privacy boundaries, and maintainers should split or approve the behavior shape before implementation.
