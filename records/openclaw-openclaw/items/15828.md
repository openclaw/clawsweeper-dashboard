## Summary

Keep open. Current main and the latest release still keep bundled session-memory on explicit command hooks, while the requested idle, shutdown, periodic checkpoint, and summary-output behavior needs a maintainer-owned lifecycle and privacy decision.

## What This Changes

Request to add automatic session-memory checkpoints for idle, shutdown, message-count, and command resets, plus optional LLM summaries and related config.

## Best Possible Solution

Keep this as the broad tracker, choose the lifecycle/privacy contract first, then land daily/idle persistence and separately scope shutdown, message-count, and opt-in summary behavior with docs and targeted tests.
