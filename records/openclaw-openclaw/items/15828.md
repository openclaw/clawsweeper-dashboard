## Label Justifications

- `P2`: The issue describes real session-memory preservation gaps with limited blast radius, but the remaining work needs product/security scoping rather than emergency handling.
- `impact:session-state`: The request is about preserving session context across idle, shutdown, command, and long-running conversation boundaries.

- `impact:security`: Automatic transcript persistence and optional LLM summaries would process private conversation data beyond the current explicit command boundary.

## Summary

Keep open. Current main still implements bundled session-memory as command-scoped persistence for `/new` and `/reset`; idle/daily rollover, shutdown drain, message-count checkpoints, and summary-output behavior remain separate lifecycle/product surfaces rather than a merged fix.

## What This Changes

Request automatic session-memory checkpoints on idle, shutdown, periodic message counts, and command reset, plus an optional LLM summary output mode.

## Best Possible Solution

Keep this as the broad session-memory automation tracker, consolidate the daily/idle candidate first, then explicitly scope shutdown checkpointing, periodic checkpoints, and opt-in summary output with privacy and dedupe rules.
