## Summary

Keep open. Current main still leaves the bundled session-memory hook command-only; shutdown and typed session lifecycle infrastructure now exist, but they do not make session-memory capture idle, shutdown, periodic, or summary checkpoints.

## What This Changes

Request automatic session-memory persistence on idle, shutdown, and message-count checkpoints, plus an optional LLM summary mode and trigger configuration.

## Best Possible Solution

Keep this as the broad session-memory automation tracker: land or reject the daily/idle hook path first, then scope shutdown, message-count, and summary-output behavior with bounded lifecycle guarantees, privacy defaults, docs, and targeted tests.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: enabling the bundled session-memory hook and firing anything other than command:new or command:reset returns before memory capture. The missing trigger/config behavior is visible in the handler, HOOK metadata, and public docs on current main and v2026.6.11.

## Solution Assessment

No single automated fix is the best solution yet. The daily/idle, shutdown, periodic checkpoint, and LLM-summary pieces cross lifecycle, config, storage, and privacy boundaries, so maintainers should split and approve the behavior shape before implementation.
