## Summary

Keep open. Current main and the latest release still implement the bundled session-memory hook for explicit command:new/command:reset only; the requested idle, shutdown, message-count, and summary-output triggers remain missing, and related PRs/issues only cover parts of the broader request.

## What This Changes

The issue requests automatic session-memory checkpoints on idle, shutdown, periodic message-count thresholds, and optional LLM-generated summaries instead of only manual /new or /reset commands.

## Best Possible Solution

Define one maintainer-approved session-memory automation design that preserves existing command behavior, sets explicit opt-in/default semantics, and stages daily/idle, shutdown, periodic, and LLM-summary behavior with docs and focused tests.

Yes, at source level. Current main keeps bundled session-memory registered and implemented for command:new/command:reset while idle rollover and shutdown use adjacent lifecycle paths that do not invoke that hook.

Unclear pending maintainer product/API choice. The requested behavior is useful, but the best fix needs decisions on trigger contract, summary/provider privacy, shutdown deadlines, dedupe, and overlap with the open daily/idle implementation candidate.
