## Summary

Keep open. Current main and the latest release still leave bundled session-memory capture tied to explicit reset/new command events; the open daily/idle PR covers only one slice and does not settle shutdown, periodic checkpoint, or summary-output behavior.

## What This Changes

Request automatic session-memory checkpoints for idle, shutdown, message-count intervals, and optional LLM summaries instead of relying only on `/new` and `/reset`.

## Best Possible Solution

Keep this as the broad automation tracker, land or reject the daily/idle hook path first, then scope shutdown, periodic checkpoint, and summary-output behavior with explicit privacy defaults, bounded lifecycle guarantees, docs, and targeted tests.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: bundled session-memory only handles `command:new` and `command:reset`, while idle/daily rollover and shutdown use separate lifecycle paths.

## Solution Assessment

No single automated fix is clearly best yet. The daily/idle slice has an open candidate PR, while shutdown, periodic checkpointing, and LLM summaries need maintainer-approved lifecycle, config, and privacy semantics.
