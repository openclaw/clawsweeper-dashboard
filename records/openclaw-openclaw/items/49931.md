## Summary

Keep this issue open: current main and the latest release still do not provide a supported `tools.exec.shell` config contract, and the open Windows PowerShell PATH PR only addresses a narrower shell-discovery problem.

## What This Changes

The issue requests a persisted `tools.exec.shell` configuration option for overriding the exec tool shell, especially for Windows/WSL and complex Bash-style command workflows.

## Best Possible Solution

Define a maintainer-approved exec shell-selection contract covering config precedence, shell arguments, startup validation, WSL cwd/PATH semantics, gateway/node/sandbox/PTY behavior, and approval/safe-bin policy before implementation.
