Keep this issue open: current main still lacks a supported `tools.exec.shell` config contract, and the remaining work is a security-sensitive product/config decision rather than stale cleanup.

## What This Changes

The issue requests a global or per-agent exec shell override, mainly so Windows users can run exec commands through WSL/bash or another preferred shell instead of the built-in PowerShell default.

## Best Possible Solution

Define one maintainer-approved exec shell-selection contract, then update config types/schema/help/docs and thread it consistently through gateway, PTY, sandbox, node, approval, PATH, WSL, and safe-bin behavior with focused tests.

## Reproduction Assessment

Yes for the missing capability: source inspection shows current main has no `tools.exec.shell` type, strict schema key, docs entry, or runtime config threading. This is a feature gap rather than a broken existing contract.

## Solution Assessment

Unclear. A config-backed shell override is plausible, but the best design needs maintainer decisions on shell arguments, WSL cwd/PATH semantics, validation timing, and approval/safe-bin policy.
