## Summary

Keep this PR open: the prior P1 blocker remains because `terminateChild()` treats `child.killed` as proof of exit, although Node defines it only as successful signal delivery, so cleanup can resolve while the Codex child is still running and the SIGKILL escalation has already been canceled. ([nodejs.org](https://nodejs.org/api/child_process.html))

## What This Changes

Adds guarded stdout/stderr error handling to Codex exec-resume, terminates the spawned child on failure, and adds injected-child regression tests.

## Best Possible Solution

Keep the helper, but resolve only after an observed `exit` or `close` event, preserve the two-second SIGKILL escalation until then, and test a child that ignores SIGTERM by asserting its actual exit or terminal signal rather than `child.killed`.
