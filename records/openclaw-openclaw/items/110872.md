## Summary

Keep open for an owner-backed product/security design decision. Current public docs confirm that outbound delivery still accepts transport-level targets and resolves some directory names, but they do not establish a verified, consent-linked recipient identity contract; the linked outbound-gate and delivery-receipt issues are complementary rather than replacements.

## What This Changes

Add a recipient-addressed mode to the shared message tool that resolves verified consent-linked routes, refuses ambiguity, previews the resolved route, and returns idempotent delivery receipts while preserving raw-target sends.

## Best Possible Solution

Define one narrow generic recipient-route contract for the shared outbound layer—identity reference, verification provenance, ambiguity/refusal rules, and revocation ownership—then land it in focused stages that preserve raw-target compatibility and reuse existing delivery receipts rather than creating a parallel ledger.
