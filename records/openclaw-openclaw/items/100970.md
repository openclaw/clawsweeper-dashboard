## What This Changes

This PR adds optional `debounceMs` overrides to WhatsApp direct-chat and group configuration entries so each conversation can use a different inbound batching window.

## System Context

WhatsApp's inbound listener admits messages, derives a conversation-specific batching window from channel configuration, and passes the message into OpenClaw's shared keyed inbound debouncer. The resulting batch controls when the agent turn begins and which messages are processed together.

## Architecture Diagram

  Inbound[Admitted inbound message] --> Resolver
  Resolver --> Debouncer[Shared inbound debouncer]
  Debouncer --> Batch[Stable conversation batch]
  Batch --> Agent[Agent turn]

## Best Possible Solution

Sponsor one permanent contract for per-conversation inbound batching, preferably the WhatsApp-owned configuration path if a generic plugin API is not needed by another channel, then land only that selected implementation with its documented precedence and upgrade behavior.
