## Summary

This is a bounded, apparently correct implementation of conversation-scoped WhatsApp batching, but it adds two user-visible configuration surfaces and is explicitly competing with an open generic plugin-policy design. Keep it open for a maintainer product-direction choice rather than closing or auto-repairing it.

## What This Changes

Adds optional `debounceMs` settings to WhatsApp direct-chat and group entries, resolves the setting per admitted conversation, and keeps each active message batch on its initial debounce window.

## System Context

WhatsApp messages are admitted, grouped by a shared inbound debouncer, then delivered as an agent turn. The WhatsApp monitor supplies the conversation-specific delay while the shared debouncer retains ownership of keyed batching, ordering, and flush timing.
