Keep open for normal PR review: current main still clones the message history before checking for context handlers, and the proposed guard is a focused hot-path improvement that matches the existing payload/response hook pattern without changing context-handler behavior.

## What This Changes

The branch skips no-handler context-hook cloning in `ExtensionRunner.emitContext` and `createAgentSession`, then adds focused runner coverage for no-handler, mutation-isolation, and replacement-message behavior.

## Best Possible Solution

Land the small hot-path guard if exact-head CI remains green, keeping no-handler turns clone-free while preserving isolated cloned messages for registered context handlers.

## Reproduction Assessment

Yes. Current main source shows `createAgentSession` reaches `emitContext` whenever a runner exists, and `emitContext` clones before checking handlers; the PR body also includes a before/after terminal harness for the no-handler path.

## Solution Assessment

Yes. The best fix is the narrow guard at the caller plus callee: caller gating mirrors sibling hooks, and callee gating protects future direct callers without adding a new API or config switch.
