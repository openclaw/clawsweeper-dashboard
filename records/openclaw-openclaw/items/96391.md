## Summary

Keep open: this PR targets a real WebChat session-continuation bug, but the current implementation still lets any later stale WebChat send with the same session id bypass idle/daily rollover instead of limiting the exception to a one-shot restore path.

## What This Changes

The branch adds a transient `CallerSessionId` to WebChat send context, populates it from the backing session id, and reuses matching stale sessions in `initSessionState` with regression coverage.

## Best Possible Solution

Preserve the page-load continuation while keeping the stale-session exception explicitly one-shot and leaving ordinary idle/daily rollover intact.

## Solution Assessment

No. The current shape fixes the immediate restart case, but it is not the best fix because it duplicates the private one-shot resume boundary and can bypass reset policy on later stale sends.
