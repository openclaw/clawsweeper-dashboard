## Summary

Keep this PR open, but it is not merge-ready: the current branch fixes the old proof mismatch, yet the new gateway-level guard broadens WebChat session freshness bypass from a one-shot resume path to ordinary matching `chat.send` calls.

## Best Possible Solution

Keep the WebChat continuity fix, but scope freshness suppression to a one-shot, caller-verified resume path tied to loaded history/reconnect, and preserve ordinary idle/daily rollover for normal stale sends.
