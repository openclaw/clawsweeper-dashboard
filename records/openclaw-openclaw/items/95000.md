## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Avoid provider readiness hooks in the read RPC:** `src/gateway/server-methods/image.ts:89-90`
  - body: This still invokes `provider.isConfigured` before the read-only helper. Several image providers implement that hook through `isProviderApiKeyConfigured`, which calls `ensureAuthProfileStore` without `readOnly: true`, so an `operator.read` inventory RPC can reach write-capable auth-profile code. Derive readiness directly from read-only env/profile/config checks instead.
  - confidence: 0.93
- **[P2] Require non-empty config before reporting configured:** `src/gateway/server-methods/image.ts:44-48`
  - body: The fallback readiness check treats provider key presence, and truthy plugin `config`, as configured, so empty objects such as `models.providers.openai = {}` can produce `configured: true`. The existing CLI helper uses non-empty object checks for this inventory state; the RPC should do the same so settings UIs do not show empty config as ready.
  - confidence: 0.86
- **[P2] Preserve explicit selection when credentials are missing:** `src/gateway/server-methods/image.ts:109-111`
  - body: After resolving `agents.defaults.imageGenerationModel`, the handler only returns `active` when that provider is also `configured`. A settings UI needs to show the explicit selected provider even when credentials are missing, while readiness remains false; otherwise a configured-but-broken selection is indistinguishable from no selection.
  - confidence: 0.82
