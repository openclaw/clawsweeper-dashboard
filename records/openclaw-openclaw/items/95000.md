## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Avoid provider-owned readiness hooks in the read RPC:** `src/gateway/server-methods/image.ts:90`
  - body: `image.providers` still calls `provider.isConfigured` before the read-only fallback. Current OpenAI-compatible image providers implement that hook through `isProviderApiKeyConfigured`, which calls `ensureAuthProfileStore` without `readOnly`, so an `operator.read` inventory refresh can touch auth profile state.
  - confidence: 0.91
- **[P2] Require non-empty config before reporting configured:** `src/gateway/server-methods/image.ts:44`
  - body: The model-config branch checks only that a matching provider key exists, so `{ models: { providers: { openai: {} } } }` reports OpenAI as configured. The existing CLI helper requires non-empty config values, and this RPC should not tell Console that an empty stub is ready.
  - confidence: 0.86
- **[P2] Return active selection separately from readiness:** `src/gateway/server-methods/image.ts:110-111`
  - body: When `agents.defaults.imageGenerationModel` names a provider that is not currently configured, the handler returns `active: null`. That hides an existing user preference from the settings surface; the image CLI keeps `selected` distinct from readiness so UIs can show the selected provider and the missing configuration separately.
  - confidence: 0.8
- **[P2] Include all geometry capability fields in the schema:** `packages/gateway-protocol/src/schema/image-generation.ts:18-23`
  - body: The schema allows `sizesByModel` but omits `aspectRatiosByModel` and `resolutionsByModel`, both of which are part of the current image-generation capability type and normalization path. A provider returning those valid fields can make the new RPC reject its own inventory response or ship an incomplete client contract.
  - confidence: 0.88
