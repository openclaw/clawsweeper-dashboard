## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.87

Full review comments:

- **[P1] Avoid provider-owned writes in the read RPC:** `src/gateway/server-methods/image.ts:90`
  - body: `provider.isConfigured` is still tried before the read-only fallback. Current image providers route that hook through `isProviderApiKeyConfigured`, which uses `ensureAuthProfileStore`, so a supposedly read-only `operator.read` metadata refresh can touch auth profile state. Use a local read-only projection only, or add a provider contract that is explicitly side-effect-free.
  - confidence: 0.91
- **[P2] Require non-empty config before reporting configured:** `src/gateway/server-methods/image.ts:44-50`
  - body: This fallback marks a provider configured when the provider key exists, even if the config object is empty. The existing CLI path uses `hasOwnKeys` for model/plugin config, so this would make the new RPC report empty stubs as ready and mislead the Console provider settings UI.
  - confidence: 0.84
- **[P2] Keep active selection separate from readiness:** `src/gateway/server-methods/image.ts:109-111`
  - body: The handler drops an explicit `agents.defaults.imageGenerationModel` selection unless the provider is also configured. That hides an existing user preference from the settings surface; sibling `tts.providers` reports the active selection independently, and the image CLI keeps `selected` distinct from readiness.
  - confidence: 0.79
- **[P2] Expose all geometry capability fields:** `packages/gateway-protocol/src/schema/image-generation.ts:18-23`
  - body: The schema omits `aspectRatiosByModel` and `resolutionsByModel`, which are part of the current image-generation capability type and are read by normalization. If a provider returns those valid fields, the new RPC validator rejects its own inventory response and native/generated clients start from an incomplete contract.
  - confidence: 0.88
