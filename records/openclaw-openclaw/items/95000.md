## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Avoid provider-owned writes in the read RPC:** `src/gateway/server-methods/image.ts:89-90`
  - body: `image.providers` is an `operator.read` metadata call, but this still invokes each provider's `isConfigured` hook before the local read-only fallback. Current image providers route that hook through `isProviderApiKeyConfigured`, which calls `ensureAuthProfileStore` without forcing `readOnly`, so a Console inventory refresh can touch auth profile state instead of remaining read-only.
  - confidence: 0.93
- **[P2] Require non-empty config before reporting configured:** `src/gateway/server-methods/image.ts:44-47`
  - body: This fallback marks any matching provider key as configured, including `models.providers.<id>: {}` and an empty plugin config object. The existing CLI inventory helper requires non-empty config objects via `hasOwnKeys`, so this can report a provider as configured when no credential or usable config exists.
  - confidence: 0.88
- **[P2] Include all geometry fields in the protocol schema:** `packages/gateway-protocol/src/schema/image-generation.ts:18-23`
  - body: The handler returns provider `capabilities.geometry` directly, but the new protocol schema omits `aspectRatiosByModel` and `resolutionsByModel`, which are part of the current image-provider SDK contract. Valid provider payloads using those fields can fail validation or be unavailable to generated clients.
  - confidence: 0.84
- **[P3] Sync the native i18n inventory:** `apps/shared/OpenClawKit/Sources/OpenClawProtocol/GatewayModels.swift:448-450`
  - body: Adding the generated Swift `ImageProvidersResult` model changes the native source inventory, and CI now fails `native-i18n` with the instruction to run `pnpm native:i18n:sync` and commit `apps/.i18n/native-source.json`. Please include that generated inventory update with this Swift model change.
  - confidence: 0.86
