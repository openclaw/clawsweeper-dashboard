## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Avoid provider-owned readiness hooks in the read RPC:** `src/gateway/server-methods/image.ts:90`
  - body: `image.providers` still calls `provider.isConfigured` before the read-only fallback. Current image providers implement that hook through `isProviderApiKeyConfigured`, which calls `ensureAuthProfileStore` without `readOnly`, so an `operator.read` inventory refresh can touch auth profile state.
  - confidence: 0.92
- **[P2] Require non-empty config before reporting configured:** `src/gateway/server-methods/image.ts:44-50`
  - body: The fallback readiness check treats the presence of a matching `models.providers` key as configured even when the value is `{}`. That can tell Console a provider is ready when there are no usable credentials or provider settings.
  - confidence: 0.86
- **[P2] Preserve explicit active selection when auth is missing:** `src/gateway/server-methods/image.ts:110-111`
  - body: When `agents.defaults.imageGenerationModel` names a provider that is not currently configured, the handler returns `active: null`. That hides the user's selected provider from a settings surface instead of letting the UI show the selection and missing configuration separately.
  - confidence: 0.8
- **[P2] Include model-specific edit limits in the protocol contract:** `packages/gateway-protocol/src/schema/image-generation.ts:7-14`
  - body: The schema/type for edit support includes `maxInputImages` but omits `maxInputImagesByModel` and `maxInputImagesByModelPrefix`, which are current image provider capability fields used by Fal and runtime limit resolution. Typed clients would receive an incomplete first-shipped contract.
  - confidence: 0.86
