## Summary

Keep open. Current OpenClaw tool policy can remove schemas before a model call, but the documented plugin hooks only inject prompt context, observe LLM input, or intervene after the model has selected a tool; no supported plugin return contract for a per-request final tool allowlist was found. This remains a useful plugin-SDK gap rather than a completed feature.

Likely related people: Kaspre (medium confidence, recent plugin-hook maintenance) and jgavinray (medium confidence, recent contributor on plugin tool-policy propagation).

## What This Changes

Request a documented plugin API that can deterministically filter the model-visible tool candidates before their schemas are serialized into an LLM prompt.

## System Context

An agent turn resolves its configured tool policy and materializes the callable tool set before sending the provider a prompt. Plugins can currently add prompt context or observe the resulting provider input, but they cannot return a supported per-request replacement for that tool set.

## Architecture Diagram

flowchart LR
  A[Inbound agent turn] --> B[Configured tool policy]
  B --> C[Candidate callable tools]
  C --> D[Plugin pre-prompt selection]
  D --> E[Provider prompt builder]
  E --> F[Model-visible tool schemas]
  F --> G[Model tool calls]

## Best Possible Solution

Add one typed, documented plugin-SDK selector at the canonical post-policy/pre-serialization boundary: provide stable candidate descriptors and request metadata, accept only a validated subset by stable ID, preserve host denials, and fall back to the unchanged candidate set on plugin failure.
