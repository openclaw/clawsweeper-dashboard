## Summary

The ACP startup bug is real, but the current head is not merge-ready: its capability guard runs after explicit and derived thinking values have been collapsed, so it silently discards an explicit `sessions_spawn(thinking: ...)` request despite the PR claiming that request still fails visibly. The branch also lacks inspectable exact-head real behavior proof.

## What This Changes

The PR makes ACP thinking option emission conditional on advertised thinking aliases and adds focused unit tests for omission and alias selection.

## Best Possible Solution

Retain thinking-origin information at ACP spawn normalization, omit an unadvertised thinking control only when it was automatically model-derived, and keep explicit spawn or runtime-option requests strict; prove both paths against the exact head on a real limited-capability ACP backend.
