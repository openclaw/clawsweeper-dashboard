## Summary

The linked ACP startup bug remains valid, but the current patch is not mergeable: its capability override drops the session handle, preventing ACPX from returning the handle-specific `reasoning_effort` option that the alias logic requires. The earlier P1 findings are fixed, but this blocker remains and real first-turn proof is missing.

## What This Changes

The PR adds synthetic `thinking` and `thought_level` aliases to acpx capabilities when `reasoning_effort` is reported, while retaining inherited model-level thinking defaults for ACP spawns.

## Best Possible Solution

Forward the `getCapabilities` input into the ACPX delegate, return a copied capability result rather than mutating delegate-owned arrays, rely on the existing generic `thinking`-to-`reasoning_effort` resolver, add a resolved-handle regression test, and then prove an actual acpx first turn succeeds.
