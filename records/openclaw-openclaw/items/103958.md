## Summary

This PR addresses a confirmed ACP startup failure and remains necessary because current `main` and v2026.7.1 still inject unsupported thinking configuration. The ACPX capability forwarding and Codex-only aliasing are sound, but removing inherited thinking for every ACP backend introduces a blocking compatibility regression for capable backends.

## What This Changes

The branch stops injecting model-derived thinking into ACP spawns and makes ACPX expose Codex thinking aliases from session-scoped capabilities without mutating delegate data.

## Best Possible Solution

Keep the handle forwarding and Codex-only alias normalization, but preserve inherited thinking and make only auto-derived typed thinking best-effort when a backend does not advertise a compatible option; explicit user config writes should remain strict.
