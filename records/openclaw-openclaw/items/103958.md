## Summary

This PR should remain open because it breaks the established, tested inheritance of configured or model-profile thinking into ACP sessions; that value is also consumed by acpx to configure Codex reasoning at launch.

## What This Changes

The PR stops deriving and including a thinking value in ACP spawn runtime options unless the caller supplies an explicit thinking override.

## Best Possible Solution

Preserve inherited thinking through the acpx backend-specific launch path, then prevent it from being redundantly reapplied as an unsupported generic ACP config option; explicit unsupported controls should remain visible errors.
