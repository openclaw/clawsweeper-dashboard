## Summary

This PR targets a real Slack Socket Mode recovery gap that current `main` still has: the supervisor waits only for disconnect-style events, while a wedged transport can remain connected without delivering inbound events. The branch adds a bounded transport-idle escape path without using application-message silence as the liveness signal, which is the right direction; however, its stated proof is unit/CI coverage plus a pre-fix production observation, not inspectable after-fix behavior from a real Slack setup, so it should remain open pending that evidence and focused dependency-contract verification.

## What This Changes

The PR records Slack Socket Mode transport activity separately from application events and reconnects when the socket stays transport-idle for a bounded interval.

## System Context

Slack Socket Mode supplies a long-lived WebSocket to the Slack channel monitor, which reports account health to the gateway and waits for socket lifecycle events before reconnecting. This change inserts transport-liveness signals into that path so a silent-but-still-connected socket can return the reconnect loop to recovery.
