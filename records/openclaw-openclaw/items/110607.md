## Summary

Keep this PR open for explicit maintainer handling: it is linked to the concrete browser retry bug and carries the protected `maintainer` label, so it should not be auto-closed or routed through automated cleanup. The proposed classifier is narrowly aimed at transient browser-control failures, but the publicly visible evidence is a summary rather than inspectable after-fix runtime output.

## What This Changes

The branch classifies browser-control failures so transient transport errors and HTTP 408/504 errors tell the model to retry once, while disabled, refused, authentication, and rate-limit failures retain no-retry guidance.

## Best Possible Solution

Keep the browser failure classification in the browser plugin, validate that retry-once guidance is limited to request paths that are safe after an ambiguous transport failure, and attach redacted after-fix Testbox output before a maintainer lands the PR.
