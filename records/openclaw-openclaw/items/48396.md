## Summary

Keep open: the feature is useful and still tracked by the linked canonical issue, but this PR is not merge-ready because it renders `subject` metadata instead of the gateway's `lastMessagePreview`, never asks `sessions.list` to hydrate that preview, includes a root planning document, and lacks real UI proof.

## What This Changes

The PR adds a root planning note and changes the Control UI Sessions table to show a dual-line Updated cell with a truncated preview sourced from session subject metadata plus new CSS.

## Best Possible Solution

Repair this PR or replace it with a narrow implementation that requests `includeLastMessage`, carries `lastMessagePreview` through the UI row type, renders that field in the Sessions table, removes the planning document, adds focused UI coverage, and includes real browser proof.

## Reproduction Assessment

Yes for the patch defect by source inspection: the diff renders `row.subject`, while current main's gateway/TUI preview contract uses `includeLastMessage` and `lastMessagePreview`. I did not run a live browser reproduction in this read-only review.

## Solution Assessment

No, this is not the best fix as proposed: a view-only subject preview will show blank or unrelated metadata. The maintainable fix is to reuse the existing `sessions.list` preview contract end to end.
