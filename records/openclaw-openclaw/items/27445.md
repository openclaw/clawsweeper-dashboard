## Summary

Keep open. Current main and v2026.6.11 still lack the requested public native `announceTarget` tool/config contract, and the remaining choice is a compatibility-sensitive product decision rather than an obsolete or already-implemented cleanup item.

## What This Changes

The issue requests a native `announceTarget: "channel" | "parent"` option for sub-agent completion announces, with both a config default and a per-`sessions_spawn` override.

## Best Possible Solution

Define the minimal public completion-routing contract first, then implement native parent-targeted completion routing with backward-compatible channel default, ACP `streamTo` kept separate, and focused tests for native run-mode, thread-bound session-mode, config parsing, and docs.

Options:

- **Approve per-spawn plus config default (recommended):** Add `announceTarget` to `sessions_spawn` and `agents.defaults.subagents`, default it to current channel behavior, and route `parent` completions into the requester session without direct channel delivery.
- **Approve per-spawn only:** Add only a per-call override to avoid expanding global config while still enabling explicit orchestrator-controlled handoffs.
- **Decline native routing for now:** Keep current depth-based completion delivery and leave users on explicit callback patterns or narrower follow-up issues.
