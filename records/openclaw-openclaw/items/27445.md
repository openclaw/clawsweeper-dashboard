## Summary

Keep open. Current main has improved sub-agent completion handoff, but it still lacks the requested public `sessions_spawn.announceTarget` and `agents.defaults.subagents.announceTarget` contract, and thread-bound native session spawns still disable completion announce registration entirely.

## What This Changes

The issue requests a new `announceTarget` setting on `sessions_spawn` and `agents.defaults.subagents` to route sub-agent completion announces into the parent session instead of directly to the channel.

## Best Possible Solution

Keep this as a maintainer-sponsored sub-agent routing design that preserves current default behavior, decides whether explicit `announceTarget` or the existing completion-event policy is canonical, and covers thread-bound session completion wakeups.

## Reproduction Assessment

Yes. Source inspection is a high-confidence path: current main has no native `sessions_spawn.announceTarget` or `agents.defaults.subagents.announceTarget`, and thread-bound session spawns can still register without a completion announce wake.

## Solution Assessment

Unclear as a final product choice. The requested option is plausible, but current main already moved toward requester-session completion events, so maintainers should choose the durable public contract before implementation.
