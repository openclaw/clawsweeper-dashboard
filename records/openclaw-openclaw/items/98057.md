## Summary

Keep open for maintainer review: the patch appears correct and well-proven, but it deliberately changes account-sensitive Feishu chat routing and fail-closed behavior for multi-account setups, which needs human acceptance before merge.

## What This Changes

The PR changes `feishu_chat` registration and execution to use the shared Feishu tool-account resolver with contextual account routing, plus regression tests for contextual selection, explicit account override, later-account registration, and disabled contextual-account fail-closed behavior.

## Best Possible Solution

Land the chat-only resolver alignment if maintainers accept contextual/explicit account precedence and disabled-account fail-closed behavior, while leaving the broader Feishu non-inbound binding work to its separate PR.

## Reproduction Assessment

Yes, at source level: current main and `v2026.6.11` use `accounts[0]` for `feishu_chat` registration and client creation, so contextual account state cannot affect chat execution. I did not run live Feishu credentials during this read-only review, but the PR body supplies redacted live/staged proof.

## Solution Assessment

Yes, with maintainer acceptance: reusing the existing Feishu tool-account resolver is the narrow maintainable fix for the chat subset and matches sibling tools. The remaining question is whether maintainers accept the deliberate multi-account fail-closed compatibility behavior before merge.
