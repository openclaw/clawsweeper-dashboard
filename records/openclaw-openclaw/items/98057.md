## Summary

Keep open for maintainer review: the patch appears correct and the proof is sufficient, but it intentionally changes Feishu chat credential selection and fail-closed behavior for multi-account setups; it should not be treated as closing the broader Feishu non-inbound routing issue.

## What This Changes

The PR changes `feishu_chat` registration and execution to use the shared Feishu tool-account resolver with contextual account routing, plus focused regression coverage.

## Best Possible Solution

Land this as the narrow chat-account resolver alignment if maintainers accept the credential-boundary change, or deliberately fold it into the broader Feishu routing PR while keeping the broader issue open.

## Solution Assessment

Yes for the chat subset: reusing the existing Feishu tool-account resolver is the narrowest maintainable fix and matches sibling Feishu tools. It is not the full solution for the broader non-inbound binding-precedence issue tracked at https://github.com/openclaw/openclaw/issues/96657.
