## Summary

Keep open: current main still lacks managed SSH transport for `openclaw node run`, while the reverse-proxy pairing/auth symptom is only partially addressed by source-level credential changes and overlaps a broader remote-node approval issue.

## What This Changes

The issue asks OpenClaw to add first-class SSH transport support for node-host connections and to make remote `wss://` node pairing create an approvable request behind a reverse proxy.

## Best Possible Solution

Define one supported remote node-host contract, then either keep external SSH documented with better recovery guidance or add managed SSH with explicit host-key/lifecycle handling plus live-tested reverse-proxy device pairing.
