## Summary

Keep open: current main and v2026.6.11 still do not provide managed SSH transport for `openclaw node run`, while the direct `wss://` pairing/auth half is only partly addressed by current credential code and overlaps a separate open remote-node approval issue.

## What This Changes

Request first-class SSH transport for `openclaw node run` and a fix or clarified support path for remote reverse-proxy node pairing/auth challenge behavior.

## Best Possible Solution

Define one supported remote node-host contract, then implement or document it with explicit SSH lifecycle, credential precedence, pairing approval, and reverse-proxy trust boundaries proven in a real remote setup.
