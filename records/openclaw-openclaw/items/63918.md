## Summary

Current main preserves explicit cron `payload.thinking` through the isolated-agent path and the OpenAI reasoning resolver now avoids sending unsupported disabled `none`; the reporter also confirmed the original failing cron jobs completed after upgrading to `v2026.4.9`, which contains the provider-side fix.

## What This Changes

Cron `agentTurn` jobs with explicit `payload.thinking` should not be reshaped into an unsupported OpenAI `thinking=none` request for GPT-5 nano-class models.

## Best Possible Solution

Close this issue as fixed in `v2026.4.9`; open a new issue only if a current-release cron payload and OpenAI request log show `minimal` still being reshaped to `none`.
