## Summary

Current main preserves explicit cron `payload.thinking` through the cron execution path and the OpenAI provider payload now resolves model-supported reasoning efforts instead of sending unsupported `none`; the fix first shipped in `v2026.4.9`, which the reporter also verified resolved the failing cron runs.

## What This Changes

Cron `agentTurn` jobs should preserve explicit `payload.thinking: "minimal"` and avoid sending unsupported OpenAI `reasoning.effort: "none"` to `openai/gpt-5-nano`.

## Best Possible Solution

Keep the shipped provider behavior: cron should preserve explicit per-job thinking, and OpenAI payload builders should normalize or omit unsupported reasoning values instead of sending `none` to models that reject it.
