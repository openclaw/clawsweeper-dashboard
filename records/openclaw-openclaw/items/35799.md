## Summary

Keep open. Current main and the latest release already cover stable heartbeat phase spreading, but cron `every` still has no prime, phase, or jitter contract; the remaining request changes public scheduling/config semantics and needs maintainer product direction.

## What This Changes

The issue requests prime-derived heartbeat and cron `every` cadence plus deterministic per-agent phase jitter to reduce synchronized scheduling spikes.

## Best Possible Solution

Keep the shipped heartbeat phase spreading and cron-expression stagger, then either design one explicit cron `every` phase/stagger/prime contract with schema, CLI, persistence, docs, and upgrade tests, or explicitly keep `every` as fixed anchored cadence.
