## Summary

Keep open. Current main already spreads heartbeat interval runs by stable per-agent phase and staggers recurring top-of-hour cron expressions, but cron `every` remains a fixed `everyMs`/`anchorMs` schedule with no public prime, phase, or jitter contract, so the remaining request needs maintainer product/API direction.

## What This Changes

Request to add prime-derived cadence and deterministic phase jitter to heartbeat and cron `every` schedules to reduce synchronized bursts and provider rate-limit pressure.

## Best Possible Solution

Keep the existing heartbeat phase spreading, then design one explicit cron `every` phase/stagger contract with schema, CLI, persistence, status display, docs, and upgrade tests before considering prime transforms.
