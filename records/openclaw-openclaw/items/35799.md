## Summary

Keep open. Current main and v2026.6.11 already spread heartbeat interval runs and stagger cron-expression top-of-hour schedules, but cron `every` still has no public phase/jitter or prime-cadence contract, and adding one is a scheduling API/product decision.

## What This Changes

Requests prime-derived cadence and deterministic phase jitter for heartbeat and cron `every` schedules to reduce synchronized scheduler load spikes.

## Best Possible Solution

Keep the shipped heartbeat phase spreading, then design one explicit cron `every` phase/stagger contract with schema, CLI, persistence, status/docs, and upgrade tests before considering prime transforms.
