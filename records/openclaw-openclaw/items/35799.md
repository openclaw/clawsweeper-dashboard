## Summary

Keep open. Current main and v2026.6.11 already spread heartbeat interval runs and stagger cron-expression top-of-hour schedules, but public prime/phase controls and cron `every` jitter remain absent, so the remaining work is a maintainer-owned scheduling/API decision.

## What This Changes

Request to add prime-derived cadence and deterministic phase jitter controls for heartbeat and cron `every` schedules to reduce synchronized provider load spikes.

## Best Possible Solution

Keep the shipped heartbeat phase spreading, then design one explicit cron `every` phase/stagger contract with schema, CLI, persistence, status/docs, and upgrade tests before considering prime transforms.
