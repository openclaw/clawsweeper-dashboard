## Summary

Keep open. Current main already spreads heartbeat interval runs across stable per-agent phases and staggers cron-expression top-of-hour jobs, but cron `every` remains a fixed anchored interval with no prime, phase, or jitter contract, and the remaining request changes public scheduling/config semantics.

## What This Changes

Request prime-derived cadence and deterministic phase jitter controls for heartbeat and cron `every` schedules to reduce synchronized load spikes.

## Best Possible Solution

Keep the shipped heartbeat phase spreading and cron-expression stagger, then choose one canonical cron `every` phase/stagger/prime contract with schema, CLI, persistence, docs, and upgrade tests before implementation.
