## Summary

Keep open. Current main already spreads heartbeat interval runs by stable per-agent phase and staggers top-of-hour cron expressions, but cron `every` still has only fixed `everyMs`/`anchorMs` semantics and no prime, phase, or jitter contract, so the remaining work is a maintainer-owned scheduling/API decision.

## What This Changes

The issue requests prime-derived cadence and deterministic phase jitter controls for heartbeat and cron `every` schedules to reduce synchronized load spikes.

## Best Possible Solution

Keep the existing heartbeat phase spreading and cron-expression stagger, then design one explicit opt-in cron `every` phase/stagger contract with schema, CLI, persistence, docs, status output, and upgrade tests before considering prime transforms.
