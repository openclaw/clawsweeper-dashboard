## Summary

Keep open. Current main implements and ships stable heartbeat phase spreading, but cron `every` remains an anchored fixed-interval schedule with no phase, stagger, or prime cadence contract, so the remaining work still needs maintainer product/API direction.

## What This Changes

Request to add prime-derived scheduling and deterministic phase jitter for heartbeat and cron `every` schedules to reduce synchronized provider load spikes.

## Best Possible Solution

Keep the shipped heartbeat phase spreading, then have maintainers choose one canonical cron `every` phase/stagger/prime contract with schema, CLI, persistence, docs, and upgrade tests before implementation.

## Reproduction Assessment

Yes, source-level. Current main shows heartbeat phase spreading exists, while cron `every` only supports `everyMs`/`anchorMs`, the CLI rejects stagger/exact with `--every`, and deterministic stagger applies only to cron-expression schedules.

## Solution Assessment

Unclear until maintainers choose the product contract. Prime cadence and new phase knobs are plausible, but a smaller cron `every` stagger/phase contract, docs-supported anchor pattern, or no new public surface may be the more maintainable solution.
