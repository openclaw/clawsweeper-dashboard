## Summary

Keep open. Current main and v2026.6.11 already spread heartbeat interval runs and cron-expression top-of-hour jobs, but cron `every` and the public heartbeat config still lack prime cadence, phase-jitter, or `every` stagger controls, so the remaining work is a product/API decision rather than cleanup closure.

## What This Changes

The issue requests prime-derived heartbeat and cron `every` cadence plus deterministic per-agent phase jitter to reduce synchronized scheduling spikes.

## Best Possible Solution

Keep the shipped heartbeat phase spreading and cron-expression stagger, then choose one canonical cron `every` phase/stagger or prime-cadence contract with schema, CLI, persistence, docs, upgrade tests, and observability before implementation.
