## Summary

Keep open. Current main and the latest release already spread heartbeat interval runs by stable per-agent phase and stagger top-of-hour cron expressions, but cron `every` remains a fixed `everyMs`/`anchorMs` contract and the requested prime/phase controls still need a maintainer scheduling/API decision.

## What This Changes

Request optional or default prime cadence and deterministic phase/jitter scheduling controls for heartbeat and cron `every` jobs to reduce synchronized load spikes.

## Best Possible Solution

Keep the existing heartbeat phase spreading, then design one explicit cron `every` phase/stagger contract covering schema, CLI, persistence, docs, status output, and upgrade tests before considering prime transforms.
