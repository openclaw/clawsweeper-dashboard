## Summary

Keep open. Current main already has stable per-agent heartbeat phase spreading and cron-expression top-of-hour staggering, but cron `every` remains a fixed `everyMs`/`anchorMs` schedule with no prime, phase, or jitter public contract, so the remaining work needs maintainer product/API direction.

## What This Changes

Request to add prime-derived cadence and deterministic per-agent phase jitter for heartbeat and cron `every` schedules to reduce synchronized traffic spikes.

## Best Possible Solution

Keep the shipped heartbeat phase spreading, then choose one explicit cron `every` phase/stagger/prime contract that covers schema, CLI, persistence, docs, and upgrade tests before implementation.

Yes, source-level. Current main shows stable heartbeat phases exist, while cron `every` only supports `everyMs`/`anchorMs` and normalization prunes stagger-style fields from `every` schedules.

## Solution Assessment

Unclear until maintainers choose the product contract. Prime cadence and phase knobs are plausible, but a smaller cron `every` phase/stagger contract or preserving fixed `every` semantics may be more maintainable.
