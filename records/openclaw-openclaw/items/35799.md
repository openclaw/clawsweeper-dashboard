## Summary

Keep open. Current main and the latest release already cover the heartbeat anti-herd part with stable per-agent phases, but cron `every` still has no prime, phase, or jitter public contract, so the remaining work is a maintainer product/API decision rather than cleanup closure.

## What This Changes

The issue requests prime-derived heartbeat and cron `every` scheduling plus deterministic per-agent phase jitter to reduce synchronized load spikes.

## Best Possible Solution

Keep the shipped heartbeat phase spreading and cron-expression stagger, then choose one canonical cron `every` phase/stagger/prime contract with schema, CLI, persistence, docs, and upgrade tests before implementation.

## Solution Assessment

Unclear until maintainers choose the product contract. Prime cadence and phase knobs are plausible, but the smallest maintainable path may be a narrower cron `every` phase/stagger contract or preserving fixed semantics.
