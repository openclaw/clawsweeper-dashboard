## Summary

Keep open. Current main already has deterministic heartbeat phase spreading and cron-expression staggering, but cron `every` still has no public prime, phase, or jitter contract, so the remaining request needs maintainer product/API direction rather than cleanup closure.

## What This Changes

Request to add prime-derived cadence and deterministic phase jitter controls for heartbeat and cron `every` schedules to reduce synchronized request spikes.

## Best Possible Solution

Keep the shipped heartbeat phase spreading and cron-expression stagger, then choose one canonical cron `every` phase/stagger/prime contract with schema, protocol, CLI, persistence, docs, and upgrade tests before implementation.
