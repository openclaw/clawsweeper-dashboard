## Summary

Keep open. Current main already spreads heartbeat interval runs by stable per-agent phase and staggers cron-expression top-of-hour jobs, but the requested prime cadence and cron `every` phase/jitter controls remain a public scheduling API decision rather than completed cleanup.

## What This Changes

The issue requests optional prime-derived heartbeat and cron `every` cadence plus deterministic phase jitter to reduce synchronized multi-agent load spikes.

## Best Possible Solution

Keep stable heartbeat phase scheduling, then design one explicit cron `every` phase/stagger contract with schema, CLI/tool/protocol, persistence, status/docs, and upgrade tests before considering prime transforms.
