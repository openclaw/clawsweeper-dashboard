## Summary

Keep open. Current main covers the heartbeat phase-spreading part, but cron `every` is still a fixed anchored interval and the requested prime/phase/jitter controls would add public config, CLI, persistence, and docs surface that needs maintainer product direction.

## What This Changes

Request adding prime-derived cadence and deterministic phase jitter controls for heartbeat and cron `every` schedules to reduce synchronized load spikes.

## Best Possible Solution

Keep the shipped heartbeat phase spreading and cron-expression stagger, then design one canonical opt-in contract for cron `every` phase/stagger or explicitly decide to keep `every` fixed.
