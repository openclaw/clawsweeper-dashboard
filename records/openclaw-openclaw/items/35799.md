## Summary

Keep open. Current main covers the heartbeat half with stable per-agent phase spreading and cron-expression top-of-hour staggering, but cron `every` and public heartbeat config still lack prime/every-mode/phase-jitter controls, so the remaining work is a product/API decision rather than conservative cleanup.

## What This Changes

Request to add optional prime cadence and deterministic phase/jitter controls for heartbeat and cron `every` schedules to reduce synchronized load spikes.

## Best Possible Solution

Keep the shipped heartbeat phase spreading and cron-expression stagger, then design one canonical anti-herd scheduling contract for cron `every` and heartbeat with schema, CLI, persistence, docs, and upgrade tests.
