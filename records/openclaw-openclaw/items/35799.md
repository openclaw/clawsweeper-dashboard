## Summary

Keep open. Current main already spreads heartbeat interval runs and staggers cron-expression top-of-hour schedules, but cron `every` still has no phase/jitter or prime-cadence contract, and exposing those controls is a maintainer-owned scheduling/API decision.

## What This Changes

Request to add prime-derived cadence and deterministic phase jitter controls for heartbeat and cron `every` schedules to reduce synchronized provider/request spikes.

## Best Possible Solution

Keep the shipped heartbeat phase spreading, then design one explicit cron `every` phase/stagger contract with schema, CLI, persistence, status/docs, and upgrade tests before considering prime transforms.
