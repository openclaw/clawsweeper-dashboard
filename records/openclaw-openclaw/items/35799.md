## Summary

Keep open. Current main and the latest release cover part of the request with deterministic heartbeat phase spreading and cron-expression staggering, but cron `every` still has only fixed `everyMs`/`anchorMs` semantics and no public prime, phase, or jitter contract, so the remaining work needs maintainer product/API direction.

## What This Changes

The issue requests prime-derived heartbeat/cron interval scheduling and deterministic per-agent phase jitter to reduce synchronized scheduling spikes.

## Best Possible Solution

Keep the shipped heartbeat phase spreading and cron-expression stagger, then decide on one canonical cron `every` phase/stagger/prime contract with schema, CLI, persistence, docs, and upgrade tests before implementation.
