## Summary

Keep open. Current main and the latest release already include stable per-agent heartbeat phase spreading and cron-expression top-of-hour staggering, but the requested public prime/phase controls for heartbeat and cron `every` schedules are still missing and require maintainer product/API direction.

## What This Changes

The issue requests prime-derived scheduling defaults plus deterministic per-agent phase jitter for heartbeat and cron `every` schedules to reduce synchronized load spikes.

## Best Possible Solution

Keep the existing heartbeat phase spreading and cron-expression staggering, then choose one explicit public contract for cron `every` and any heartbeat knobs before implementation.
