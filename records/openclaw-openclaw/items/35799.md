## Summary

Keep open. Current main covers stable heartbeat phase spreading and cron-expression staggering, but cron `every` still has no prime, phase, or jitter contract; the remaining work is a compatibility-sensitive product/API decision rather than cleanup closure.

## What This Changes

The issue requests prime-derived cadence and deterministic phase jitter controls for heartbeat and cron `every` schedules to reduce synchronized load spikes.

## Best Possible Solution

Keep the shipped heartbeat phase spreading and cron-expression stagger, then choose one canonical cron `every` phase/stagger/prime contract with schema, protocol, CLI, persistence, docs, and upgrade tests before implementation.

- **Keep every fixed:** Preserve `every` as an anchored fixed interval and rely on heartbeat phase plus cron-expression staggering for anti-herd behavior.
- **Accept broader prime mode:** Add prime cadence transforms plus deterministic phase controls for heartbeat and cron, with explicit migration and observability requirements.

Yes, at source level: current main shows heartbeat phase spreading exists, while cron `every` only supports `everyMs`/`anchorMs` and prunes stagger fields from `every` schedules. No runtime bug repro is applicable because this is a feature/API request.

## Solution Assessment

Unclear until maintainers choose the product contract. Prime cadence and new phase knobs are plausible, but a smaller cron `every` phase/stagger contract or preserving fixed `every` semantics may be more maintainable.
