## Summary

Keep open. Current main and the latest release have shipped stable heartbeat phase spreading and cron-expression top-of-hour staggering, but they still do not add prime cadence or public phase-jitter controls for heartbeat and cron every schedules, so the remaining work is a product/API decision rather than conservative cleanup closure.

## What This Changes

Request to add prime-derived scheduling and deterministic per-agent phase jitter controls for heartbeat defaults and cron every schedules to reduce synchronized provider traffic.

## Best Possible Solution

Define one compatibility-preserving scheduler contract that reuses the existing deterministic phase/stagger machinery where possible, then add schema, CLI/status readback, docs, and focused scheduler tests only after that direction is approved.

- **Decline new timing knobs:** Keep fixed-interval semantics plus existing heartbeat phase and cron-expression staggering, and close this only after maintainers state prime/phase controls are out of scope.
