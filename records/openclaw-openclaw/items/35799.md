## Summary

Keep open. Current main and the latest release already cover stable per-agent heartbeat phase spreading and cron-expression top-of-hour staggering, but the requested prime cadence and public anti-herd controls for heartbeat and cron every schedules are still missing and require a maintainer product/API decision.

## What This Changes

Request prime-derived heartbeat and cron every cadence plus deterministic phase jitter to reduce synchronized scheduling spikes.

## Best Possible Solution

Define one compatibility-preserving scheduler contract for heartbeat and cron every schedules, preferably reusing the existing deterministic phase/stagger machinery rather than adding prime-only behavior unless maintainers explicitly choose that model.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a public anti-herd scheduling contract for heartbeat and cron every schedules, and should it be deterministic phase/stagger, prime cadence, explicit fixed-time phase, or no new timing knob?

Rationale: Current source already implements stable heartbeat phasing and cron-expression staggering, but the missing request requires public config, CLI, protocol, persisted schedule semantics, defaults, docs, and upgrade behavior that automation should not choose alone.

Likely owner: vincentkoc

Owner confidence: high

Options:

- **Design One Scheduler Contract (recommended):** Add one documented, compatibility-preserving anti-herd model across heartbeat and cron every with schema/protocol, CLI/docs, readback, and focused upgrade tests.
- **Limit To Cron Every Stagger:** Extend the existing cron stagger model to every schedules and leave heartbeat's implicit stable phase as the heartbeat behavior for now.
- **Decline New Timing Knobs:** Keep current fixed-interval semantics plus existing heartbeat phase and cron-expression staggering, and close this only after maintainers state prime or public phase controls are out of scope.

## Reproduction Assessment

Yes for the source-level feature gap, not as a failing bug: current main still types and documents cron every as fixed interval state and heartbeat config as one every duration while the requested prime/jitter public controls are absent.

## Solution Assessment

Unclear as a final implementation shape: extending the existing deterministic phase/stagger machinery appears more maintainable than separate prime-only fields, but maintainers need to choose the public contract and defaults first.
