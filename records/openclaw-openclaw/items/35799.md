## Summary

Keep open. Current main and v2026.6.11 already spread heartbeat interval runs by stable per-agent phase and stagger recurring top-of-hour cron expressions, but cron `every` is still a fixed `everyMs`/`anchorMs` contract with no prime, phase, or jitter surface, so the remaining work needs maintainer product/API review.

## What This Changes

The issue requests opt-in or default prime-derived heartbeat/cron interval scheduling plus deterministic per-agent phase jitter to reduce synchronized provider load spikes.

## Best Possible Solution

Keep the existing heartbeat phase spreading, then design one explicit cron `every` phase/stagger contract with schema, CLI, persistence, docs, status display, and upgrade tests before considering prime transforms.
