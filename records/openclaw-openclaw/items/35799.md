## Summary

Keep open. Current main already spreads heartbeat interval runs by stable per-agent phase and staggers top-of-hour cron expressions, but cron `every` remains a fixed `everyMs`/`anchorMs` contract with no prime, phase, or jitter surface, so the remaining work is a maintainer-owned scheduling/API decision.

## What This Changes

Request prime-derived heartbeat and cron `every` cadences plus deterministic per-agent phase jitter to reduce synchronized load spikes.

## Best Possible Solution

Keep the existing heartbeat phase spreading, then design one explicit cron `every` phase/stagger contract that covers schema, CLI, persistence, docs, status output, and upgrade tests before considering prime transforms.
