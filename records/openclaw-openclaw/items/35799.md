## Summary

Keep open. Current main and the latest release already cover stable heartbeat phase spreading and cron-expression top-of-hour staggering, but cron `every` remains a fixed anchored interval with no public phase, jitter, or prime-cadence contract, so the remaining request still needs maintainer product/API direction.

## What This Changes

Request adds prime-derived cadence and deterministic phase jitter controls for heartbeat and cron `every` schedules to reduce synchronized agent/provider load spikes.

## Best Possible Solution

Keep the shipped heartbeat stable phase and cron-expression stagger, then design one backward-compatible cron `every` phase/stagger/prime contract with schema, CLI, persistence, docs, and upgrade tests before implementation.
