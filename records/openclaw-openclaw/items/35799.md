## Summary

Keep open. Current main and v2026.6.11 already spread heartbeat intervals with a stable per-agent phase, but cron `every` remains a fixed anchored interval with no jitter/prime public contract, and the proposed heartbeat/cron config/API defaults need product direction before implementation.

## What This Changes

Request prime-derived heartbeat and cron interval scheduling plus deterministic per-agent phase jitter to reduce synchronized heartbeat and cron traffic spikes.

## Best Possible Solution

Keep the shipped heartbeat phase spreading, then choose one narrow default-compatible scheduler contract for any cron `every` jitter/prime behavior, with schema/protocol/CLI/docs/tests and upgrade behavior handled together.
