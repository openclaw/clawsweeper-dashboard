## Summary

Keep open. Current main has deterministic heartbeat phase spreading and documented cron-expression staggering, but the requested prime/phase-jitter API for cron `every` and optional/default scheduling policy remains a product decision rather than an already-implemented cleanup item.

## What This Changes

The issue requests prime-derived intervals and deterministic per-agent phase jitter for heartbeat and cron `every` schedules to reduce synchronized load spikes.

## Best Possible Solution

Maintain heartbeat's existing stable phase behavior, then have maintainers decide whether cron `every` should gain an explicit jitter/prime scheduling contract, default policy, CLI/docs surface, and upgrade-safe observability.
