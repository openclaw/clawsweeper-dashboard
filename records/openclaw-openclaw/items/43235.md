## Summary

Keep open: current main and v2026.6.11 still route ordinary foreground agent turns through a per-session lane and then the shared `main` lane, so the reported multi-agent starvation remains a real scheduler/config product gap. The closed broad PR is not a viable fix, and the newer hook-lane PR only covers a narrow adjacent hook surface.

## What This Changes

The issue requests per-agent command lane isolation so one busy agent in a multi-agent gateway does not starve unrelated agents sharing the global main lane.

## Best Possible Solution

Define a maintainer-owned foreground scheduler contract with default `main` behavior, bounded server-owned per-agent or agent-group lane routing, aggregate caps, schema/help/docs alignment, and regression coverage for fresh config plus unchanged upgrades.
