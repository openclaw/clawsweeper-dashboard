## Summary

Keep open: current `main` and `v2026.6.11` still route ordinary foreground agent turns through a per-session lane and then the shared `main` lane, and the only linked broad implementation PR was closed unmerged after security, compatibility, proof, and mergeability blockers.

## What This Changes

The issue requests per-agent command lane isolation so one busy foreground agent cannot monopolize the shared `main` queue in multi-agent deployments.

## Best Possible Solution

Keep this as the canonical foreground per-agent lane tracker, then design a server-owned lane/concurrency model that preserves global caps, updates schema/docs, and covers all foreground embedded-run entry points.

## Reproduction Assessment

Yes, at source level: current foreground runs still compose a `session:<key>` lane plus the shared `main` lane, and the Feishu logs show `lane=main` waits consistent with that path. I did not run a live multi-agent Feishu deployment in this read-only review.

## Solution Assessment

Unclear as proposed: per-agent isolation is the right capability, but maintainers still need to choose the server-owned config shape, global-cap semantics, and security boundary.
