## Summary

Keep open: current main and the latest release still route ordinary inbound agent turns through the shared process-wide main lane, and the only open related PR is a narrow hook-mapping lane slice rather than per-agent foreground isolation.

## What This Changes

Request per-agent or per-group foreground command lanes so one long-running agent does not consume the shared main-lane capacity for other agents.

## Best Possible Solution

Define an opt-in core lane policy that keeps shared main as the default, supports per-agent or per-group foreground isolation with per-lane caps, preserves an aggregate safety cap, and ships with schema, docs, and queue/security tests.

- **Document separate gateways:** Keep foreground replies on the shared main lane and recommend separate gateway deployments for heavy agent groups.

## Solution Assessment
