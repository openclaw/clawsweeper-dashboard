## Summary

Keep open: current main and v2026.6.11 still route ordinary foreground turns through the shared `main` lane, and the remaining fix needs a maintainer-owned scheduler/config decision.

## What This Changes

Request to add per-agent or per-agent-group foreground command lanes so long-running work from one agent does not starve other agents on a shared gateway.

## Best Possible Solution

Design a server-owned foreground lane model that derives lanes from trusted agent config, preserves an aggregate resource cap, updates schema/docs/doctor expectations, and covers all embedded-run entry points.
