## Summary

Keep open: current main and the latest release still route ordinary foreground agent turns through a per-session lane and then the shared main lane, while the previous broad implementation PR was closed unmerged after security, compatibility, proof, and mergeability blockers.

## What This Changes

The issue requests per-agent command lane isolation so one busy agent on a shared gateway does not starve unrelated agents' inbound turns.

## Best Possible Solution

Design a server-owned foreground lane model that derives lanes from trusted agent config, preserves aggregate resource caps, updates schema/docs/doctor expectations as needed, and covers all embedded-run entry points.
