## Summary

Keep open: current main and v2026.6.11 still route ordinary foreground agent turns through a per-session lane and then the shared global `main` lane. The prior broad implementation PR was closed unmerged, and the remaining fix needs maintainer-approved scheduler/config semantics.

## What This Changes

Request to support per-agent foreground command lanes so one busy agent cannot starve other agents on a shared multi-agent gateway.

## Best Possible Solution

Design a server-owned foreground lane model that derives lanes from trusted agent config, preserves aggregate resource caps, updates schema/docs/doctor expectations as needed, and covers all embedded-run entry points.
