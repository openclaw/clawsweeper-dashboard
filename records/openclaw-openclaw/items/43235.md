## Summary

Keep open: current main and v2026.6.11 still route ordinary foreground agent turns through the shared process-wide `main` lane, so the requested per-agent foreground lane isolation remains unmet and needs maintainer product direction.

## What This Changes

The issue requests per-agent or grouped command lanes so one slow agent in a multi-agent deployment cannot starve unrelated agents on the shared foreground lane.

## Best Possible Solution

Keep this as the canonical foreground scheduler design item and implement a default-preserving, server-controlled per-agent or grouped lane contract with aggregate safety caps, docs, and upgrade tests after maintainers settle the public config shape.
