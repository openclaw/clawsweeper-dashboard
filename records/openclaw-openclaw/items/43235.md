## Summary

Keep open: current main and v2026.6.11 still route ordinary foreground agent work through a per-session lane and the shared `main` lane, while the broad implementation attempt at https://github.com/openclaw/openclaw/pull/73991 was closed unmerged and the newer hook-lane PR only covers hook mappings.

## What This Changes

The issue requests per-agent or per-agent-group command lanes so one agent's long foreground turn cannot consume shared `main` lane capacity for unrelated agents.

## Best Possible Solution

Keep this as the canonical foreground per-agent lane tracker and design a server-owned lane/concurrency model that preserves global resource caps, validates lane names, updates schema/docs, and covers all foreground embedded-run entry points.

## Reproduction Assessment

Yes, at source level: current main still composes a per-session lane with the shared `main` global lane, and the issue/comment logs match that bottleneck. I did not run a live multi-agent Feishu deployment in this read-only review.

## Solution Assessment

Unclear as proposed: per-agent isolation is the needed capability, but maintainers still need to choose the server-owned config shape, global-cap semantics, and security boundary before implementation.
