## Summary

Keep open: current main and v2026.6.11 still route ordinary foreground agent turns through a per-session lane and then the shared main lane, and the remaining work is a compatibility-sensitive scheduler/config product decision rather than cleanup-close material.

## What This Changes

Support per-agent command lanes so multi-agent deployments can isolate heavy agents from the shared main queue.

## Best Possible Solution

Define a server-owned foreground lane model that derives lanes from trusted agent config, keeps per-session ordering, preserves a global resource cap, and updates schema, docs, doctor/upgrade expectations, and regression tests together.
