## Label Justifications

- `impact:other`: One busy agent can degrade unrelated agents on a shared gateway, which is meaningful operator impact outside the narrower owned impact labels.

## Summary

Keep open: current main and v2026.6.11 still route ordinary foreground agent turns through a per-session lane and then the shared `main` lane, while the only broad implementation candidate was closed unmerged and the newer hook-lane PR covers only a narrow adjacent slice.

## What This Changes

The issue requests per-agent or per-agent-group command lanes so heavy agents in shared gateways do not starve unrelated agents on the global foreground lane.

## Best Possible Solution

Design a server-owned foreground lane model derived from trusted agent config, preserve an aggregate resource cap, update schema/help/docs and upgrade expectations, and cover all embedded-run entry points.
