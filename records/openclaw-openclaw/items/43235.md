## Summary

Keep open: current main and the latest release still route ordinary foreground turns through the shared `main` lane, and the remaining work needs a maintainer-owned scheduler/config decision rather than cleanup closure.

## What This Changes

The issue requests per-agent or per-agent-group command lanes so one long-running agent turn cannot starve unrelated agents on a shared gateway.

## Best Possible Solution

Design a server-owned foreground lane model that derives lanes from trusted agent config, preserves an aggregate resource cap, updates schema/docs/doctor expectations, and covers all embedded-run entry points.

## Reproduction Assessment

Yes, at source level: current main composes a per-session lane with the shared `main` global lane for ordinary foreground turns, and the Feishu logs match that lane-wait path. I did not run a live multi-agent Feishu deployment in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public scheduler/config contract. Per-agent isolation is plausible, but the best fix should use trusted server-owned config and preserve aggregate caps rather than accepting arbitrary request-supplied lane ids.
