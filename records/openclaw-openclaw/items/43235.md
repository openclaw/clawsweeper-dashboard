## Summary

Keep open: current main and v2026.6.11 still route ordinary foreground agent turns through the shared process-wide `main` lane, while per-agent or grouped foreground lane isolation remains a core scheduler/config product decision.

## What This Changes

Request to add per-agent or grouped foreground command lanes so one busy agent cannot starve other agents on a shared gateway.

## Best Possible Solution

Design a server-owned foreground lane model that derives lanes from trusted agent config, preserves aggregate resource caps, updates schema/docs/doctor expectations as needed, and covers all embedded-run entry points.
