## Summary

Keep open: current main and the latest release still route ordinary foreground agent turns through a per-session lane and then the shared process-wide main lane, so per-agent foreground lane isolation remains unimplemented and needs maintainer product direction.

## What This Changes

Request per-agent or per-agent-group command lanes so long-running work from one agent does not consume the shared foreground main-lane capacity for all agents.

## Best Possible Solution

Design a server-owned foreground lane model that derives lanes from trusted agent config, preserves an aggregate resource cap, updates schema/docs/doctor expectations as needed, and covers all embedded-run entry points.
