## Summary

Keep open: current main and v2026.6.11 still route ordinary foreground agent turns through the shared main lane, while the issue has concrete multi-agent lane-wait field logs and needs a maintainer-owned scheduler/config decision.

## What This Changes

Request support for per-agent or grouped command lanes so long-running work for one agent does not consume the shared foreground main lane for other agents.

## Best Possible Solution

Design a default-preserving core scheduler config that routes foreground agent turns by server-owned agent or group lane with per-lane and aggregate caps, then update schema, docs, and upgrade tests in coordination with hook/subagent/channel lane work.
