## Summary

Keep open: current main and v2026.6.11 still route ordinary foreground agent turns through a per-session lane and then the shared process-wide main lane, while the requested per-agent foreground lane contract remains a maintainer product/config decision.

## What This Changes

The issue requests per-agent command-lane isolation so heavy work in one agent does not starve other agents on a shared gateway.

## Best Possible Solution

Design a server-owned foreground lane model that derives trusted lanes from agent or group config, preserves an aggregate resource cap, validates lane names, and updates schema, docs, and focused queue coverage without changing existing defaults unexpectedly.
