## Summary

Keep open: current main and v2026.6.11 still route ordinary foreground agent turns through a per-session lane and then the shared main lane, while the prior broad implementation PR was closed unmerged after security, compatibility, proof, and mergeability blockers.

## What This Changes

The issue requests configurable per-agent command lanes so heavy work for one agent does not starve other agents on the shared main lane.

## Best Possible Solution

Design a server-owned foreground lane model that derives lanes from trusted agent config, preserves aggregate resource caps, updates schema/docs/doctor expectations as needed, and covers all embedded-run entry points.
