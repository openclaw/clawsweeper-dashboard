## Summary

Keep open: current main and the latest release still route normal foreground agent turns through a per-session lane plus the shared process-wide main lane, and the requested per-agent or grouped foreground command-lane policy remains a real core scheduler/config product decision.

## What This Changes

The issue requests per-agent command lanes or per-agent concurrency limits so one slow agent in a shared gateway cannot starve other agents' foreground replies.

## Best Possible Solution

Design a default-preserving core scheduler config that routes foreground agent turns by server-owned agent or group lane with per-lane and aggregate caps, then update schema, docs, and regression tests in coordination with hook, subagent, browser, and channel lane work.
