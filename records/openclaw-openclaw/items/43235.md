## Summary

Keep open: current main still sends ordinary foreground agent turns through a per-session lane and then the shared `main` global lane, while the prior broad implementation PR is closed unmerged and the newer open lane PR only covers hook mappings.

## What This Changes

Request support for per-agent or per-agent-group foreground command lanes so one heavy agent cannot exhaust the shared `main` lane on multi-agent gateways.

## Best Possible Solution

Design a server-owned foreground lane model that derives lanes from trusted agent config, preserves aggregate resource caps, updates schema/docs/doctor expectations as needed, and covers all embedded-run entry points.
