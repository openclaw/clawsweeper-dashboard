## Summary

Keep open: current `origin/main` and the latest release still route normal foreground agent turns through the shared process-wide `main` lane, while per-agent or grouped foreground lane isolation remains a core scheduler/config product decision.

## What This Changes

Requested support for per-agent or grouped command lanes so multi-agent foreground runs can avoid shared `main` lane starvation.

## Best Possible Solution

Keep this as the canonical foreground scheduler design item and implement a default-preserving, server-controlled per-agent or grouped lane contract with aggregate safety caps, docs, and upgrade tests after maintainers settle the public config shape.
