## Summary

Keep open: current main and the latest release still route ordinary foreground agent turns through a per-session lane and then the shared `main` lane; the remaining fix is a public scheduler/config decision rather than a cleanup close.

## What This Changes

The issue requests per-agent or per-agent-group command lanes/concurrency so one long-running agent cannot starve other agents on a shared gateway.

## Best Possible Solution

Design a server-owned foreground lane model that derives lanes from trusted agent config, preserves an aggregate resource cap, documents default/upgrade behavior, and coordinates with subagent, hook, and workload-specific lane proposals.

- **Document separate gateways:** Keep the current shared main lane and document separate gateway processes as the supported isolation pattern for heavy agents.
