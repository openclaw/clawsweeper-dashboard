## Summary

Keep open: current main and the latest release still run ordinary foreground agent turns through a per-session lane and then the shared main lane, so the reported multi-agent starvation problem remains. The request should not be auto-implemented yet because the fix adds public scheduler and config semantics that need maintainer direction.

## What This Changes

Request per-agent or per-agent-group command lanes so one long-running agent does not consume the shared main-lane concurrency budget for unrelated agents.

## Best Possible Solution

Design a server-owned foreground lane model that derives lanes from trusted agent config, preserves an aggregate resource cap, updates schema/docs/doctor expectations as needed, and covers all embedded-run entry points.
