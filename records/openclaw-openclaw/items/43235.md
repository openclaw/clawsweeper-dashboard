## Summary

Keep open: current main and the latest release still route ordinary foreground agent turns through the shared process-wide `main` lane, while the requested per-agent or grouped foreground lane isolation remains a product/config decision.

## What This Changes

The issue requests per-agent command lanes or lane groups so heavy agents in multi-agent deployments cannot starve unrelated agents sharing the global `main` lane.

## Best Possible Solution

Keep this as the canonical foreground scheduler design item and implement a default-preserving, server-controlled per-agent or grouped lane contract with aggregate safety caps, docs, and upgrade tests after maintainers settle the public config shape.
