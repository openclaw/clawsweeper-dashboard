## Summary

Keep open: current main and the latest release still route ordinary foreground agent turns through a per-session lane and then the shared main lane, while the requested per-agent foreground lane isolation remains a compatibility-sensitive scheduler/config feature needing maintainer direction.

## What This Changes

The issue requests per-agent command lanes so long-running work by one agent does not monopolize the shared main command lane in multi-agent deployments.

## Best Possible Solution

Define a server-owned foreground lane model from trusted agent/default config, preserve per-session serialization plus an aggregate cap, and update schema, docs, and regression coverage together.

- **Document process isolation:** Keep the current shared main lane and document separate gateway processes as the supported isolation pattern for heavy agents.
