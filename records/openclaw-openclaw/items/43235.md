## Summary

Keep open: current main still routes foreground agent turns through per-session lanes plus the shared main lane, while the field reports show multi-agent main-lane starvation and the fix needs maintainer-owned scheduler/config direction.

## What This Changes

Request support for per-agent or grouped foreground command lanes so multi-agent gateways do not force every inbound agent turn through one shared main lane.

## Best Possible Solution

Design a default-preserving core scheduler config that routes foreground agent turns by server-owned agent or group lane with per-lane and aggregate caps, then update schema, docs, and upgrade tests in coordination with hook, subagent, and channel lane work.
