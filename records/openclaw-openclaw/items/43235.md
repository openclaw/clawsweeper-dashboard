## Summary

Keep open: current main and the latest release still route ordinary foreground agent turns through a per-session lane and then the shared `main` lane, so the reported shared-gateway starvation remains a real unmet feature/config gap that needs maintainer product direction.

## What This Changes

Add per-agent or dedicated foreground command lanes so one busy agent on a shared gateway cannot starve unrelated agents.

## Best Possible Solution

Define a server-owned foreground lane model derived from trusted agent/defaults config, preserve per-session serialization plus an aggregate resource cap, and update schema, docs, and tests together.
