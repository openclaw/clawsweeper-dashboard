## Summary

Keep open: current main and v2026.6.11 still route ordinary foreground agent turns through the shared `main` lane, while per-agent or grouped foreground lane isolation remains a scheduler/config product decision.

## What This Changes

The issue requests per-agent or grouped command lanes so long-running agents do not monopolize the shared foreground `main` lane in multi-agent deployments.

## Best Possible Solution

Keep this as the canonical foreground scheduler design item and implement a default-preserving, server-controlled per-agent or grouped lane contract with aggregate safety caps, docs, and upgrade tests after maintainers settle the public config shape.
