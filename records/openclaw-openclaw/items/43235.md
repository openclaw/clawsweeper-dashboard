## Summary

Keep open: current main and the latest release still route ordinary foreground agent turns through the shared process-wide `main` lane, while the requested per-agent foreground lane isolation remains a new scheduler/config feature that needs maintainer product direction.

## What This Changes

The issue requests configurable per-agent command lane isolation so one agent's long-running foreground work does not consume the shared main lane for every agent.

## Best Possible Solution

Keep this as the canonical foreground scheduler design item and implement a default-preserving per-agent or grouped lane contract only after maintainers settle the config shape, aggregate cap, upgrade behavior, and safety semantics.
