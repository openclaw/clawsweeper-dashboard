## Summary

Keep open: current main and the latest release still route ordinary foreground agent turns through the shared process-wide `main` lane, and the requested per-agent foreground lane isolation remains a new scheduler/config feature that needs maintainer product direction.

## What This Changes

The issue requests configurable per-agent command lanes so long-running work from one agent does not occupy the shared foreground `main` lane for all agents on a multi-agent gateway.

## Best Possible Solution

Keep this as the canonical foreground scheduler design item and implement a default-preserving, server-controlled per-agent or grouped lane contract only after maintainers settle the config shape, aggregate cap, upgrade behavior, and safety semantics.
