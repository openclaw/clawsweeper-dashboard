## Summary

Keep open: current main and v2026.6.11 still route ordinary foreground agent turns through the shared `main` lane, while the remaining fix needs a maintainer-owned public scheduler/config decision.

## What This Changes

The issue requests per-agent command lanes so one busy agent cannot consume the shared foreground main lane for every other agent.

## Best Possible Solution

Design a server-owned foreground lane model that derives lanes from trusted agent config, preserves aggregate resource caps, validates lane names, updates schema/docs/doctor expectations as needed, and covers all embedded-run entry points.

Yes, at source level: current main composes a per-session lane with the shared main global lane for ordinary foreground turns, and the Feishu logs match that lane-wait path. I did not run a live multi-agent Feishu deployment in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public scheduler/config contract. Per-agent isolation is plausible, but the final design must coordinate aggregate caps, trusted lane derivation, and adjacent lane proposals.
