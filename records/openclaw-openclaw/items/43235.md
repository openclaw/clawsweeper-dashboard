## Summary

Keep open: current main and the latest release still route ordinary foreground agent turns through a per-session lane and then the shared `main` lane, while the remaining fix adds public scheduler/config semantics that need maintainer product direction.

## What This Changes

Request to add per-agent or per-agent-group foreground command lanes so one busy agent cannot starve unrelated agents on a shared gateway.

## Best Possible Solution

Design a server-owned foreground lane model that derives lanes from trusted agent config, preserves an aggregate resource cap, documents upgrade/default behavior, and covers every embedded-agent entry point.
