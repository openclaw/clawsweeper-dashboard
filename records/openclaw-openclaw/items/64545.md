## Label Justifications

- `P1`: The report is a source-reproducible channel security bug that can let a party with the Mattermost bot token forge button interaction callbacks.
- `impact:security`: The issue concerns credential-derived HMAC signing and the authorization boundary for Mattermost interaction callbacks.

## Summary

Keep open: current main and the latest release still derive Mattermost interaction signing from the bot token with a public HMAC key, and the same-repository candidate fix is open rather than merged.

## What This Changes

The issue asks OpenClaw to replace Mattermost button interaction signing that derives HMAC secrets from the bot token and a public constant with a non-forgeable per-account secret.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/64546 or a narrow replacement after maintainer security review, with a durable per-account interaction secret, upgrade/doctor guidance where needed, docs updates, and old-forgery rejection coverage.

Options:

- **Use a per-account stored secret (recommended):** Generate or require a durable per-account interaction secret, persist it through the plugin-owned credential/config path, update docs, and prove old bot-token-derived forgeries fail while valid buttons still work.
- **Require explicit configured secret only:** Avoid automatic generation and make operators configure the interaction secret, trading less migration logic for more setup friction and possible button-delivery regressions.
- **Keep bot-token derivation:** Accept the current coupling between Mattermost API credentials and interaction signing, which leaves this reported security boundary unchanged.

## Reproduction Assessment

Yes. Source inspection of current main shows the interaction secret is deterministically derived from the Mattermost bot token with a public HMAC key and then used for `_token` verification; I did not run a live Mattermost POST in this read-only review.

## Solution Assessment

Yes on direction, but not yet as a completed repository state. The maintainable fix is to stop using the bot token as the signing root and provide a durable per-account interaction secret with explicit setup, docs, and upgrade behavior.
