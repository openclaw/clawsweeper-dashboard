## Label Justifications

- `P1`: The issue reports a security-sensitive Mattermost interaction integrity weakness affecting real button-click workflows, but exploitation is bounded by bot-token access and Mattermost callback context.
- `impact:security`: The affected behavior is the HMAC verification boundary for Mattermost interaction callbacks and approval-style button events.

## Summary

Keep open: current main and the latest release still derive the Mattermost interaction signing secret from the bot token with a public HMAC key, and the same-repository candidate fix remains open and conflicting.

## What This Changes

The issue asks OpenClaw to stop using a public hardcoded HMAC derivation key for Mattermost interaction tokens and move to a non-forgeable interaction signing secret.

## Best Possible Solution

Land or replace the linked fix with a migration-backed per-account interaction secret, update the public Mattermost HMAC docs, and prove old bot-token-derived forged tokens fail while normal button clicks still work.

## Solution Assessment

Unclear until maintainer/security direction is set. A generated or persisted per-account secret is the right class of fix, but the current derivation is documented and shipped, so the landing path needs migration and compatibility proof.
