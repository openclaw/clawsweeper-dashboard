## Summary

Keep open: current main and the latest release still use the reported bot-token-derived Mattermost interaction signing secret, and the linked same-repository fix remains open, conflicting, and security/upgrade-sensitive.

## What This Changes

The issue reports that Mattermost interaction callback tokens can be forged because the signing secret is deterministically derived from the bot token using a public HMAC key.

## Best Possible Solution

Land a security-reviewed Mattermost fix that stops bot-token-derived signing and provisions or explicitly requires a durable per-account signing secret through supported setup, SecretRef/config, docs, tests, and restart or split-process proof.

## Reproduction Assessment

Yes. Source inspection shows the signing secret is still derived from the Mattermost bot token with a public HMAC key and then used to verify callback `_token` values; I did not run a live Mattermost server in this read-only review.

## Solution Assessment

No shipped fix exists yet. Replacing the derivation is the right direction, but the open candidate still needs maintainer security/product choice around durable secret provisioning versus an explicit fail-closed upgrade path.
