## Label Justifications

- `P1`: The issue affects Mattermost interaction authorization and can let bot-token exposure become forged button callbacks into agent action flows.
- `impact:security`: The report concerns credential-derived HMAC signing and the authorization boundary for Mattermost interaction callbacks.

## Summary

Keep open: current main and the latest release still derive the Mattermost interaction signing secret from the bot token with a public HMAC key, and the linked same-repository fix is open, conflicting, and still needs security/product direction.

## What This Changes

The issue requests replacing Mattermost button interaction signing that is derived from the bot token with a non-forgeable per-account signing secret.

## Best Possible Solution

Land a refreshed version of https://github.com/openclaw/openclaw/pull/64546, or a narrow replacement, that removes bot-token-derived signing and provisions a durable per-account interaction secret through supported setup, SecretRef/docs, upgrade behavior, and restart/split-process proof.
