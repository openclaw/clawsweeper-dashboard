## Label Justifications

- `P1`: The report shows a source-reproducible Mattermost callback signing weakness that can affect channel interaction authorization.
- `impact:security`: The issue concerns credential-derived HMAC signing and the authorization boundary for Mattermost interaction callbacks.

## Summary

Keep open: current main and v2026.6.11 still derive the Mattermost interaction signing secret from the bot token with a public HMAC key, and the same-repository candidate fix is open, dirty, and waiting on maintainer security/product direction.

## What This Changes

The issue reports that Mattermost interaction callback tokens are forgeable because the signing secret is deterministically derived from the bot token with a public HMAC key.

## Best Possible Solution

Land a refreshed version of https://github.com/openclaw/openclaw/pull/64546, or a narrow replacement, that removes bot-token-derived signing and provides durable per-account secret provisioning, SecretRef/setup/docs coverage, upgrade behavior, and old-forgery rejection tests.

## Reproduction Assessment

Yes. Source inspection on current main shows the interaction secret is derived from the bot token with a public HMAC key, and the tests/docs still encode that deterministic behavior; I did not run a live Mattermost server in this read-only review.

## Solution Assessment

Yes on remediation direction, but not as a completed repository state. The durable fix should stop using the bot token as the signing root while making the replacement secret explicit, persistent, documented, and tested across restart or split-process paths.
