## Summary

Keep open: current `main` and the latest stable release still use the Mattermost bot-token-derived interaction signing secret, and the same-repository fix candidate at https://github.com/openclaw/openclaw/pull/64546 is open, conflicting, and awaiting maintainer security/product direction.

## What This Changes

The issue asks OpenClaw to stop deriving Mattermost interaction signing tokens from the bot token with a public HMAC key.

## Best Possible Solution

Land a refreshed security fix, or a narrow replacement, that removes bot-token-derived Mattermost interaction signing and provides durable per-account secret provisioning or explicit fail-closed setup with SecretRef, docs, tests, and restart/split-process proof.

- **Narrow to hardening-only:** If maintainers decide bot-token possession is already inside the Mattermost/OpenClaw trust boundary, narrow the report rather than treating it as a release-blocking vulnerability.

## Reproduction Assessment

Yes. Source inspection shows current main derives the Mattermost interaction signing secret from the bot token with a public HMAC key and uses it for `_token` verification; I did not run a live Mattermost server in this read-only review.

## Solution Assessment

No completed fix is on main. The right direction is to stop using the bot token as the signing root, but the linked PR still needs maintainer-approved durable provisioning or explicit fail-closed behavior before it is the best fix.
