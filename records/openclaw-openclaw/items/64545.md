## Label Justifications

- `P1`: The issue concerns a high-impact Mattermost callback signing weakness that can let a bot-token holder forge interaction callbacks and trigger agent action flows.
- `impact:security`: The report is about credential-derived HMAC signing and the authorization boundary for Mattermost interaction callbacks.

## Summary

Keep open: current main and the latest stable release still derive Mattermost interaction signing from the bot token with a public HMAC key, and the linked same-repository fix remains open, conflicting, and security/upgrade-sensitive.

## What This Changes

The issue reports Mattermost interaction tokens are forgeable because button signing secrets are deterministically derived from the bot token with a public HMAC key.

## Best Possible Solution

Land a refreshed version of https://github.com/openclaw/openclaw/pull/64546, or a narrow replacement, that removes bot-token-derived signing and provides durable per-account secret provisioning with setup, SecretRef/docs, regression tests, and restart or split-process proof.

Yes. Source inspection of current main and v2026.6.11 shows the deterministic bot-token-derived HMAC secret used for Mattermost `_token` verification; I did not run a live Mattermost server in this read-only review.

## Solution Assessment

Yes on direction, but not yet as a completed repository state. The maintainable solution is to stop using the bot token as the signing root and provide a durable per-account interaction secret with explicit setup, docs, and upgrade behavior.
