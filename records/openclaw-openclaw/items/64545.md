## Summary

Keep open: current main and the latest release still derive Mattermost interaction signing from the bot token with a public HMAC key, and the same-repository candidate fix remains open/conflicting with security-sensitive upgrade decisions unresolved.

## What This Changes

The issue reports that Mattermost interaction tokens are forgeable because the signing secret is deterministically derived from the bot token using a public HMAC derivation key.

## Best Possible Solution

Land a refreshed version of https://github.com/openclaw/openclaw/pull/64546, or a narrow replacement, that removes bot-token-derived signing and provisions a durable per-account interaction secret through supported setup, SecretRef/docs/doctor coverage, old-forgery rejection tests, and restart or split-process proof.

Yes. Source inspection of current main and v2026.6.11 shows the interaction signing secret is deterministically derived from the bot token with a public HMAC key, then used to verify Mattermost callback _token values; I did not run a live Mattermost server in this read-only review.

## Solution Assessment

Yes on direction, but not as a completed repository state. The maintainable fix is to stop using the bot token as the signing root and provide a durable per-account interaction secret with explicit setup, docs, upgrade behavior, and proof.
