## Summary

Keep open: current main and v2026.6.11 still derive the Mattermost interaction signing secret from the bot token with a public HMAC key, and the same-repository candidate fix remains open and unmerged.

## What This Changes

The issue reports that Mattermost button interaction tokens are forgeable because the signing secret is deterministically derived from the bot token with a public HMAC key.

## Best Possible Solution

Land a refreshed security fix, or a narrow replacement, that removes bot-token-derived Mattermost interaction signing and provisions a durable per-account signing secret through supported setup, SecretRef or doctor coverage, docs, tests, and restart/split-process proof.

## Reproduction Assessment

Yes. Source inspection of current main and v2026.6.11 shows the Mattermost interaction secret is deterministically derived from the bot token with a public HMAC key and then used for _token verification; I did not run a live Mattermost server in this read-only review.

## Solution Assessment

Unclear as a final implementation until maintainers choose the credential model. The right direction is to stop using the bot token as the signing root, but the durable secret, setup, docs, and upgrade behavior must be settled before this is fixed.
