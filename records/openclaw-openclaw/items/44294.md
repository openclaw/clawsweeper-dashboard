## Summary

Keep open: current main and v2026.6.11 still map non-refusal ACP error kinds to `end_turn`, and the open linked PR is the active candidate fix rather than a merged implementation.

## What This Changes

The issue asks OpenClaw to preserve structured ACP backend error classes so clients can distinguish refusals, timeouts, rate limits, context limits, and server failures from normal `end_turn` completion.

## Best Possible Solution

Keep this issue open behind https://github.com/openclaw/openclaw/pull/91603 or a replacement that chooses the ACP client-visible error contract, preserves structured backend failure data, avoids SDK code conflicts, and adds focused tests plus real ACP proof.
