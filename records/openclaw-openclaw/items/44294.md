## Summary

Keep open: current main and the latest release still collapse non-refusal ACP backend error kinds into normal `end_turn`, and the open linked PR is only a candidate fix that still needs ACP client-contract review and proof before this issue can close.

## What This Changes

The issue requests structured ACP backend error-kind preservation so ACP clients can distinguish refusals, timeouts, rate limits, context limits, and backend failures instead of receiving normal end-of-turn completion for all error states.

## Best Possible Solution

Keep this issue open behind https://github.com/openclaw/openclaw/pull/91603 or a refreshed replacement that settles the ACP client-visible error contract, preserves backend error classification, and updates focused tests plus real ACP proof.

## Reproduction Assessment

Yes. Source inspection shows current main maps non-refusal ACP error kinds such as `timeout` and `unknown` to `end_turn`, and focused tests assert that behavior; I did not run tests because this is a read-only review.

## Solution Assessment

Unclear as an implementation choice. Preserving structured error classification is the right end state, but the exact ACP client-visible representation needs maintainer-approved contract work because the current SDK stop-reason union has no transient-failure variants.
