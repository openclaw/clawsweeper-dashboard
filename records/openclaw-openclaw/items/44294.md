## Summary

Keep open: current main and the latest release still collapse non-refusal ACP backend error kinds into normal `end_turn`, and the open linked PR remains the active implementation candidate rather than a merged fix.

## What This Changes

The issue asks for ACP backend error events to retain structured error kinds so clients can distinguish refusals, timeouts, rate limits, context-length failures, and server errors instead of treating them as normal end-of-turn completion.

## Best Possible Solution

Keep this issue open until the linked PR or a replacement lands an approved ACP error contract that preserves structured backend failure data with focused tests and real ACP proof.
