## Summary

Keep open: current main and the latest release still collapse non-refusal ACP backend error kinds such as `timeout` and `unknown` into normal `end_turn`, while the linked closing PR remains open and still needs ACP client-contract review.

## What This Changes

The issue asks OpenClaw ACP translation to preserve structured backend error classifications instead of collapsing backend error states into a normal `end_turn` stop reason.

## Best Possible Solution

Keep this issue open behind https://github.com/openclaw/openclaw/pull/91603 or a refreshed replacement that chooses the ACP client-visible error contract, preserves structured backend failure data, and updates focused tests and proof.

## Reproduction Assessment

Yes. Source inspection shows current main maps non-refusal ACP error kinds such as `timeout` and `unknown` to `end_turn`, and focused tests assert that behavior; no tests were run because this is a read-only review.

## Solution Assessment

Unclear as an implementation. Preserving structured failure data is the right endpoint, but the ACP SDK stop-reason contract does not include the requested transient classes, so maintainers must choose the client-visible representation before accepting a fix.
