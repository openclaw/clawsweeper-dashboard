## Label Justifications

- `P2`: This affects ACP client-visible failure semantics and retry/UX behavior, but it is bounded to ACP translation and already has an open implementation candidate.
- `impact:session-state`: Collapsing failed backend turns into normal `end_turn` can make ACP clients record a failed prompt as successful turn completion.
- `impact:auth-provider`: Provider/backend failure classes such as rate limits, timeouts, and context-length errors are currently hidden from ACP clients behind `end_turn`.

## Summary

Keep open: current main and `v2026.6.11` still collapse non-refusal ACP error kinds such as `timeout`, `rate_limit`, `context_length`, and `unknown` into normal `end_turn`; the linked open PR remains the active implementation candidate but needs maintainer ACP contract review.

## What This Changes

The issue requests preserving structured ACP backend error classifications so ACP clients can distinguish backend failures from normal turn completion.

## Best Possible Solution

Resolve https://github.com/openclaw/openclaw/pull/91603 or a refreshed replacement after maintainers choose the ACP client-visible error contract, with focused translator tests for refusal, timeout, rate_limit, context_length, and unknown failures.

- **Defer for ACP protocol support:** Leave current behavior in place until upstream ACP adds explicit structured backend failure semantics.
