## Summary

Keep open: current main and the latest release still collapse non-refusal ACP backend error kinds into normal `end_turn`, while the open linked PR remains the active but unmerged implementation candidate that needs maintainer contract review.

## What This Changes

The issue requests preserving structured Gateway ACP backend error kinds so clients can distinguish refusals, timeouts, rate limits, context-length failures, and other backend failures instead of receiving `end_turn` for all non-refusal errors.

## Best Possible Solution

Keep this issue open behind https://github.com/openclaw/openclaw/pull/91603 or a replacement that chooses the ACP client-visible error contract, preserves structured backend failure data, updates focused tests, and includes real ACP proof.
