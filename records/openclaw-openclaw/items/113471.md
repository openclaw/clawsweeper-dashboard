## Summary

Keep this PR open. Current main still replaces a provider without a manager-owned retirement barrier and returns from local-worker close after sending shutdown rather than waiting for process exit; this branch addresses that real lifecycle gap. The patch has no definite code-level finding from this review, but merge remains blocked on inspectable final-head real-environment proof because the Raspberry Pi comment shows copied before-state output and only asserts the after-state.

## What This Changes

This PR centralizes embedding-provider retirement in Memory Core, waits for local embedding workers to terminate before replacement, and closes request-scoped embedding providers in gateway and CLI flows.

## System Context

Memory Core creates embedding providers for indexing and semantic search, while gateway and CLI commands create short-lived providers for embedding requests. Those paths feed local llama.cpp worker processes, so retirement must finish before a replacement can be admitted or shutdown can complete.
