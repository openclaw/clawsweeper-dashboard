## Summary

Keep this PR open. The cleanup intent is valid, but both new calls start an asynchronous provider shutdown and immediately continue replacement or retry; that does not guarantee the old local worker has exited before a new provider can be used. The PR also needs observable after-fix runtime evidence, not only a statement that it was tested on an RPi.

## What This Changes

This PR starts closing the prior Memory Core embedding provider when the manager installs a replacement provider or resets initialization for a retry.

## System Context

Memory Core creates an embedding provider for indexing and memory search; local providers can own a child worker process. Provider initialization, fallback, and retry paths replace that provider and therefore must hand off worker ownership without leaving overlapping or orphaned processes.

## Architecture Diagram

flowchart LR

  B --> C[Embedding provider]
  C --> D[Local worker process]
  C --> E[Failure or retry]
  E --> F[Provider handoff]
  F --> B
  D --> G[Worker shutdown]

## Best Possible Solution

Serialize provider disposal with replacement or retry, keep the manager from initializing a new local provider until the prior provider’s close promise has settled, and add a focused lifecycle regression test plus redacted real-host process evidence.
