## Summary

## What This Changes

The PR makes gateway channel shutdown catch a failing account plugin’s `stopAccount` hook, record that account’s error, and continue cleanup for all accounts.

## System Context

The gateway channel manager starts, stops, and reports runtime state for each configured account of a channel plugin. A plugin stop hook runs during teardown; the manager then waits for the task, clears abort/task tracking, and publishes the stopped runtime snapshot used by restarts and status views.

## Architecture Diagram

flowchart TD
  A[Channel stop request] --> B[Gateway channel manager]
  B --> C[Per-account plugin stop hook]
  C --> D{Hook succeeds?}
  D -->|Yes| E[Wait for task and clear tracking]
  D -->|No| F[Record account-local error]
  F --> E
  E --> G[Publish stopped runtime state]
  G --> H[Restart and status consumers]

## Best Possible Solution

Retain the account-local cleanup design, land it after final exact-head review, and keep the regression test as the contract that a failed plugin teardown hook cannot strand sibling accounts or stale lifecycle tracking.
