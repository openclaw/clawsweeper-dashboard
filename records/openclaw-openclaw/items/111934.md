## Summary

Keep this PR open for normal review: current `main` still lets a thrown `stopAccount` reject that account’s shutdown callback before its task/runtime cleanup runs, while the proposed per-account catch preserves cleanup and records the failure. The focused regression test and copied production-path output support the patch; no discrete correctness or security blocker was identified.

## What This Changes

The PR catches individual channel-plugin `stopAccount` failures in `stopChannel`, records `lastError`, and adds multi-account cleanup regression coverage.

## Best Possible Solution

Land a narrow per-account error-isolation path that logs and preserves the failing account’s diagnostic while always completing the existing abort/task/runtime cleanup for every account.
