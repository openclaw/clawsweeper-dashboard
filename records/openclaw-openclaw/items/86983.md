## Summary

Keep open: current main and v2026.6.11 still lack a Slack outbound DM recipient allowlist; the remaining work is security-sensitive product/config design, not an implemented fix or a `dmPolicy` bug to close as duplicate.

## What This Changes

The issue requests a Slack outbound DM recipient allowlist, tentatively named `allowTo` or `dmAllowTo`, to block `openclaw message send` DMs to non-approved users.

## Best Possible Solution

Define a maintainer-approved outbound target policy, preferably shared where possible, then wire Slack explicit DM sends through that policy with schema/docs/tests instead of reusing inbound `allowFrom` semantics.

## Reproduction Assessment

Yes, as a source-level feature gap. Current main exposes Slack inbound `dmPolicy`/`allowFrom` and message-tool action/cross-context policy, but no outbound recipient allowlist surface or Slack send-path gate for `allowTo`/`dmAllowTo`.

## Solution Assessment

Unclear until maintainers choose the API owner. A shared outbound target policy looks more maintainable than reusing inbound `allowFrom`, while a Slack-only field may be a narrower first step if maintainers want provider-local semantics.
