## Summary

Keep open. Current main and v2026.6.11 still do not expose enforceable before/after tool-call interception through managed HOOK.md/internal hooks; typed plugin hooks are the supported policy surface, and the remaining choice is a security-sensitive API/product decision.

## What This Changes

The issue requests a managed HOOK.md/internal hook surface for before and after tool calls that can block or rewrite tool execution and observe results.

## Best Possible Solution

Keep this as the canonical design tracker until maintainers either add a typed managed HOOK.md tool-call contract with block/rewrite/observe semantics, docs, and tests, or explicitly keep tool-call policy plugin-only with loader/info validation for unsupported event names.

Rationale: The source gap is clear, but exposing pre-tool execution to managed hooks changes OpenClaw's security boundary and permanent hook API semantics; automation cannot choose trust, ordering, timeout, failure, and compatibility behavior safely.

Likely owner: steipete

Options:

- **Design managed tool-call hooks (recommended):** Add typed managed before and after tool-call events that compose with plugin hooks, trusted policies, and all tool execution surfaces, with focused tests and public docs.
- **Keep policy plugin-only:** Reject or warn on before_tool_call and after_tool_call in HOOK.md metadata and point users to typed plugin hooks or ClawHub-packaged code plugins for enforceable tool policy.
- **Expose observation only:** Expose non-blocking after-call telemetry to managed hooks while keeping pre-tool blocking and parameter rewrites in the typed plugin contract.

## Reproduction Assessment

Yes, at source level. A managed HOOK.md handler can register an arbitrary event string, but current internal hooks return void and current before/after tool paths consult plugin hooks rather than managed internal hooks.

## Solution Assessment

Unclear as an implementation shape. The capability is valid, but the best fix depends on whether maintainers want managed hooks to gain policy semantics or want unsupported tool-call event names rejected with plugin-hook guidance.
