## Summary

Keep open. Current main and v2026.6.11 still keep enforceable before/after tool-call policy in typed plugin hooks, while managed HOOK.md internal hooks remain a void-returning event system with no tool-call dispatch or block/rewrite contract.

## What This Changes

Expose before_tool_call and after_tool_call behavior through managed/internal HOOK.md hooks so local hook handlers can observe, block, or rewrite tool calls.

## Best Possible Solution

Keep this as the canonical design tracker until maintainers either add typed managed HOOK.md tool-call events with block/rewrite/observe semantics, validation, docs, and tests, or explicitly keep tool-call policy plugin-only and reject or warn on unsupported HOOK.md event names.

Rationale: The source gap is clear, but exposing pre-tool execution to managed hooks changes OpenClaw's security and plugin API boundary; automation cannot choose trust, ordering, timeout, failure, and compatibility semantics safely.

Likely owner: steipete

Options:

- **Design managed tool-call hooks (recommended):** Add a typed managed/internal before and after tool-call API that composes with plugin hooks, trusted policies, and all tool execution surfaces, with focused tests and public docs.
- **Keep plugin-only policy:** Reject or warn on before_tool_call and after_tool_call in HOOK.md metadata, and point users to typed plugin hooks or ClawHub-packaged code plugins for enforceable tool policy.
- **Expose telemetry only:** Expose non-blocking after-call or observation-only events to managed hooks while keeping pre-tool blocking and parameter rewrites in the typed plugin contract.

## Reproduction Assessment

Yes, at source level. Managed HOOK.md handlers can register event strings, but internal hooks return void and current before/after tool paths consult typed plugin hooks rather than managed internal hooks.

## Solution Assessment

Unclear until maintainers decide the API boundary. The capability is valid, but the best fix depends on whether managed hooks should gain policy semantics or unsupported tool-call event names should be rejected with plugin-hook guidance.
