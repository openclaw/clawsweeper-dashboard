## Summary

Keep open. Current main and v2026.6.11 still keep enforceable before/after tool-call behavior in typed plugin hooks, while managed HOOK.md internal hooks have no tool-call event type, no blocking or parameter-rewrite return contract, and no bridge from tool execution.

## What This Changes

Expose enforceable before_tool_call and after_tool_call behavior through managed internal HOOK.md hooks rather than requiring a full plugin.

## Best Possible Solution

Add a maintained typed managed/internal tool-call hook contract or explicitly decide tool-call interception stays plugin-only; if implemented, bridge through the existing plugin hook semantics with focused source tests and docs for blocking, parameter rewrites, failure policy, and supported event names.

## Reproduction Assessment

Yes from source, not from a live run: current main has no internal tool-call event type or return contract, and the managed HOOK.md loader only registers internal hook events.

## Solution Assessment

Unclear until maintainers choose the API. Bridging to the existing plugin hook runner is likely the clean owner boundary, but the issue should stay open until blocking, parameter rewrite, and failure semantics are decided and implemented.
