## Summary

Keep open. Current main and v2026.6.11 still keep enforceable tool-call policy in typed plugin hooks; managed HOOK.md hooks remain void-returning internal events, so this needs maintainer API/security direction rather than cleanup closure.

## What This Changes

The issue requests managed/internal HOOK.md support for before and after tool-call hooks with blocking, parameter rewrite, and audit semantics.

## Best Possible Solution

Keep this as the canonical design tracker until maintainers either add a typed managed HOOK.md tool-call contract with block/rewrite/observe semantics, validation, docs, and tests, or explicitly keep tool-call policy plugin-only and surface unsupported managed hook event names.
