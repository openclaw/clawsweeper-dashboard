## Summary

Keep open. Current main and v2026.6.11 still keep enforceable before/after tool-call behavior in typed plugin hooks, while managed HOOK.md internal hooks have no tool-call event type, no blocking or parameter-rewrite return contract, and no bridge from tool execution.

## What This Changes

Request to expose before_tool_call and after_tool_call tool lifecycle interception through managed/internal HOOK.md hooks, including pre-execution block/parameter rewrite and post-execution audit events.

## Best Possible Solution

Keep this as the canonical design tracker for either a typed managed/internal tool-call hook contract with block, parameter rewrite, after-call observation, unsupported-event validation, docs, and focused tests, or an explicit maintainer decision that tool-call policy remains plugin-only.

## Reproduction Assessment

Yes, at source level. A managed HOOK.md handler can register an event string, but the current internal dispatcher returns void and the before/after tool paths consult typed plugin hooks rather than managed internal hooks.

## Solution Assessment

Unclear as an implementation shape. The issue should stay open until maintainers choose the managed-hook API, trust model, event names, return semantics, timeout/failure behavior, and unsupported-event diagnostics.
