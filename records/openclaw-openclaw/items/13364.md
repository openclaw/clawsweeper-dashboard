## Summary

Keep open. Current main still keeps enforceable tool-call interception in typed plugin hooks, while managed internal HOOK.md hooks remain a void-returning command/session/agent/gateway/message event system with no synchronous before/after tool-call contract; related reports and partial PRs do not supersede this canonical security-sensitive API decision.

## What This Changes

The issue requests exposing before_tool_call and after_tool_call through managed internal HOOK.md hooks so handlers can block, rewrite, or observe tool operations without a full plugin.

## Best Possible Solution

Decide the managed-hook contract first: either add typed before/after tool-call internal events with explicit block/rewrite semantics, validation, docs, and focused coverage across tool paths, or explicitly keep enforcement plugin-only and document that boundary.
