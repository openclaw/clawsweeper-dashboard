## Summary

Keep this PR open. The proposed source/generated split has a concrete generated-PR isolation failure: the post-merge refresh can rewrite Android `values/strings.xml`, while the new changed-scope rule treats that path as source and rejects the resulting generated PR as mixed. That can leave locale parity stale and block release preflight; the protected `maintainer` label also requires explicit human handling.

## What This Changes

The branch makes native locale generation a serialized post-merge workflow, changes PR CI to validate source-level i18n invariants, and retains strict generated-locale parity for generated PRs and release checks.

## Best Possible Solution

Define one explicit ownership boundary for Android base strings, then cover both a normal source PR and the serialized generated-locale PR so the publisher can pass isolation, validate parity, and auto-merge its exact head.
