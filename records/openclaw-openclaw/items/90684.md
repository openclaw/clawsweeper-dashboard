## Summary

Keep open: Feishu is now fixed on current main, but the broader non-Discord sanitizer umbrella is not complete because current main still has uncovered channel adapters and several open slice PRs.

## What This Changes

The issue asks OpenClaw to apply `sanitizeAssistantVisibleText()` to Feishu and other non-Discord outbound channel text before user-visible delivery.

## Best Possible Solution

Keep this umbrella open until maintainers either land the remaining per-channel sanitizer hooks or choose a shared outbound sanitizer boundary, with focused regression coverage for each affected channel and live proof where practical.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should this umbrella finish as audited per-channel `sanitizeText` hooks, or should OpenClaw move `sanitizeAssistantVisibleText()` to a shared outbound delivery boundary for all channels by default?

Rationale: Both shapes can fix the leak, but the shared-boundary option changes the stripping contract for every channel while per-channel hooks leave ongoing audit burden and uneven coverage.

Owner confidence: high

Options:

- **Finish per-channel hooks (recommended):** Land or close the existing channel-slice PRs and keep sanitization explicit in each adapter, minimizing global behavior change at the cost of continued audit work.
- **Move to shared boundary:** Apply the delivery sanitizer centrally, then add opt-out or skip semantics only where a channel proves legitimate content would be over-stripped.
- **Pause for security policy:** Hold the remaining PRs until maintainers define the exact user-visible internal-scaffolding policy for channels and failure banners.

## Reproduction Assessment

Yes, source-reproducible: current main still has channel outbound adapters without `sanitizeText`, and the shared delivery path only calls `handler.sanitizeText` when the channel provides it. I did not perform a live credentialed channel repro.

## Solution Assessment

No single current implementation is the full best solution yet: the Feishu hook is a good accepted slice, but the umbrella needs either complete per-channel coverage or a maintainer-approved shared boundary to avoid more missed adapters.
