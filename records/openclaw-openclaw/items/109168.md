## Summary

Keep open. The leading-boundary repair is directionally sound, but the new one-shot `StringDecoder.write()` silently discards an incomplete UTF-8 sequence at the end of captured output, and the PR supplies only focused unit-test evidence rather than after-fix behavior from a subprocess harness.

## What This Changes

The PR makes the bounded child-output test helper skip leading UTF-8 continuation bytes before decoding retained output and adds two overflow regressions.

## Best Possible Solution

After removing leading continuation bytes, finalize the one-shot decoder with `StringDecoder.end(buffer)` rather than `write(buffer)`, add coverage for an incomplete trailing sequence, and show a redacted subprocess/E2E failure transcript proving readable overflow diagnostics.
