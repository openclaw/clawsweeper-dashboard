## Summary

The patch addresses a real bounded-tail decoding defect, but the new one-shot `StringDecoder.write()` path can silently suppress an incomplete UTF-8 sequence at the end of captured diagnostics. The PR also provides unit-test evidence only, not real child-process behavior proof.

## What This Changes

The PR changes the shared bounded child-output helper to skip leading UTF-8 continuation bytes before decoding and adds two overflow regression tests.

## Best Possible Solution

Align only the truncated front boundary, preserve normal replacement behavior for genuinely incomplete trailing output, add a trailing-sequence regression, and provide a redacted real child-process diagnostic transcript.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source: when the byte cap retains only continuation bytes from the beginning of a multibyte character, current-main `Buffer.toString("utf8")` renders U+FFFD. The added cases encode that path, although no independent runtime execution was available.

## Solution Assessment

No. Skipping leading continuation bytes is the correct owner-boundary fix, but one-shot `StringDecoder.write()` is broader than needed because it also discards incomplete trailing bytes; aligned `Buffer.toString("utf8")` or `StringDecoder.end()` is safer.
