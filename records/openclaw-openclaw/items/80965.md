- **[P1] Preserve iMessage configured-chat group classification:** `src/config/group-policy.ts:389`
  - body: `extensions/imessage/src/monitor/inbound-processing.ts` treats an explicitly configured `channels.imessage.groups.<chat_id>` entry as group traffic only when `groupListPolicy.allowlistEnabled && groupConfig`. After this resolver returns `allowlistEnabled=false` for explicit `groupPolicy: "open"`, configured iMessage chats that arrive with `is_group=false` are handled as DMs, losing group gating, group session isolation, and per-group prompt behavior. Decouple the classification signal from allowlist enforcement and add an iMessage regression test.
  - confidence: 0.87
- **[P2] Align every group-allowlist doc with explicit-open semantics:** `docs/channels/groups.md:285`
  - body: The new Groups note is useful, but current Groups, Telegram, WhatsApp, and WhatsApp group-message docs still say configured `groups` acts as an allowlist without qualifying explicit `groupPolicy: "open"`. After this runtime change those pages would mislead operators into thinking unlisted groups stay blocked.
  - confidence: 0.88
