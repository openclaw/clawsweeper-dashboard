## Summary

Keep open: current main now captures durable user corrections even from failed or timed-out turns, but it still does not implement hard-failure or performance-driven skill optimization, nor usage-based skill archive/retirement. The Hermes and SkillClaw examples are useful product context, but this remains a broad core/plugin/config decision rather than a cleanup close.

## What This Changes

Add skill lifecycle management that creates Skill Workshop proposals from failure or underperformance signals and archives or retires inactive skills from usage metrics.

## Best Possible Solution

Split the proposal into maintainer-sponsored failure-repair and retirement-metrics designs, favor plugin or ClawHub extension seams where possible, and persist any accepted lifecycle state in canonical SQLite-backed state with explicit user approval before archive or delete behavior.
