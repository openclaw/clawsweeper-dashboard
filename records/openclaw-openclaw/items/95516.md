## Summary

Keep open: current main now covers part of the request by capturing durable user corrections even on failed turns, but it still lacks hard-failure/performance-driven skill repair, persisted usage metrics, and usage-based archive/retirement policy.

## What This Changes

Request skill lifecycle management that generates Skill Workshop repair proposals from failure or underperformance signals and archives or retires inactive skills based on usage metrics.

## Best Possible Solution

Split the idea into a maintainer-sponsored lifecycle design: define failure-signal capture, usage metrics storage, archive/delete recovery, and the core versus plugin/ClawHub API boundary before implementation.

Options:

- **Design a core/plugin API split (recommended):** Specify minimal core state and hooks for failure and usage signals while pushing optional policy and UI behavior to plugin or ClawHub surfaces where possible.

- **Defer lifecycle automation:** Leave current correction-based proposal capture in place and revisit retirement/optimization only after stronger maintainer demand or plugin API gaps are documented.
