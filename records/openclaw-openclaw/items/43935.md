## Summary

Keep open: current main and the latest release still collapse account-scoped channel config changes into whole-channel restarts, while the direct implementation paths remain open and unmerged.

## What This Changes

The issue asks the gateway reload planner and handler to restart only changed channel accounts for strict `channels.<channel>.accounts.<accountId>.*` config changes.

## Best Possible Solution

Land one canonical generic reload-planner fix, preferably the current-base implementation at https://github.com/openclaw/openclaw/pull/99312 if gateway owners accept the contract, then close the superseded older PR and duplicate report.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: a strict account path matches a broad channel reload prefix, becomes a channel-only restart plan, and the executor restarts the whole channel.

## Solution Assessment

Is this the best way to solve the issue? Yes; carrying account-scoped restart targets through the generic gateway planner and handler uses the existing channel manager account-id seam and keeps whole-channel restarts for global or mixed changes.
