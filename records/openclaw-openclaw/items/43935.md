## Summary

Keep open: current main and v2026.6.11 still model channel hot reload as whole-channel restarts, while the open fix candidates have not landed.

## What This Changes

The issue asks the gateway reload planner to restart only the affected account for `channels.<channel>.accounts.<accountId>.*` changes instead of restarting the whole channel.

## Best Possible Solution

Land the current-base implementation in https://github.com/openclaw/openclaw/pull/99312 if gateway owners accept the generic account-scoped reload contract, then close or supersede https://github.com/openclaw/openclaw/pull/43938 and duplicate https://github.com/openclaw/openclaw/issues/99311.

## Reproduction Assessment

Yes at source level. A strict account path under `channels.telegram.accounts.*` matches Telegram's broad reload prefix, the planner records only `restartChannels`, and the handler performs whole-channel stop/start.

## Solution Assessment

Yes. Carrying account-scoped restart targets through the generic reload plan and existing channel manager account-id arguments is the narrow maintainable fix, with whole-channel fallback for channel-global or mixed changes.
