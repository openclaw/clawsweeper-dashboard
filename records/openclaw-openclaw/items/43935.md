## Summary

Keep open: current main and the latest release still collapse account-scoped channel config changes into whole-channel restarts, while the implementation path is owned by open fix PRs rather than a merged change.

## What This Changes

The issue requests gateway reload planning that restarts only affected channel accounts for `channels.<channel>.accounts.<accountId>.*` changes while preserving full-channel restarts for global or mixed changes.

## Best Possible Solution

Land one canonical generic account-scoped reload fix, likely https://github.com/openclaw/openclaw/pull/99312 or a repaired https://github.com/openclaw/openclaw/pull/43938, then close the duplicate same-root reports after the fix merges.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: an account-scoped channel config path matches a broad channel reload prefix, the plan records only the channel, and the executor restarts the whole channel with no account id.

## Solution Assessment

Is this the best way to solve the issue? Yes; carrying account-scoped restart targets through the generic gateway planner and handler is the narrow maintainable fix because the channel lifecycle already accepts account ids.
