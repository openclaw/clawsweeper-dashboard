## Summary

Keep open: current main and the latest release still represent channel reloads as whole-channel restarts, and this issue is paired with open candidate PRs that maintainers still need to review or replace.

## What This Changes

The issue requests account-scoped channel hot-reload planning so changes under `channels.<channel>.accounts.<accountId>.*` restart only that account instead of the whole channel.

## Best Possible Solution

Land or replace the account-scoped reload planner/executor change, with tests proving account-only, channel-global, mixed/default-account, plugin-reload, and secrets-reload behavior.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: a Telegram account path matches the broad channel reload prefix, the plan can only store a channel id, and the handler calls stop/start without an account id; reporter logs add real-world Telegram message-loss evidence.

## Solution Assessment

Is this the best way to solve the issue? Yes: carrying account-scoped restart targets through the generic gateway planner and handler is the narrow maintainable fix because `ChannelManager` already accepts optional account ids.
