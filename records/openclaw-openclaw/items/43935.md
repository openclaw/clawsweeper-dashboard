## Summary

Keep open: current main and the latest release still collapse account-scoped channel config changes into whole-channel restarts, and the fix is still represented by open implementation PRs rather than merged code.

## What This Changes

The issue requests gateway hot reload to restart only the changed channel account for strictly account-scoped channel config paths.

## Best Possible Solution

Land one canonical generic reload-planner fix that carries (channel, accountId) restart targets through the gateway handler while preserving whole-channel restarts for channel-global, mixed, default-account, removed-account, and unsafe fallback cases.

## Reproduction Assessment

Yes. At source level, a strict account-scoped channel path matches the channel reload prefix, the plan records only the channel, and the handler stops/starts the whole channel; the issue comments add timestamped Telegram delivery-loss logs.

## Solution Assessment

Yes. The narrow maintainable fix is to carry account-scoped restart targets through the generic gateway reload planner and handler, because the lower channel manager already accepts account ids.
