## Summary

Keep open: current main and v2026.6.11 still collapse account-scoped channel config edits into whole-channel restarts, and the implementation work is still open rather than merged.

## What This Changes

The issue reports that `channels.<channel>.accounts.<accountId>.*` config edits restart the entire channel instead of only the affected account, widening the disruption window for active traffic.

## Best Possible Solution

Land one canonical generic reload-planner fix that carries `(channel, accountId)` restart targets through the gateway handler while preserving whole-channel restarts for channel-global, default-account, mixed, removed-account, or non-canonical account changes.

## Reproduction Assessment

Yes at source level: a Telegram account path matches the broad channel reload prefix, becomes a channel-only restart plan, and the handler performs whole-channel stop/start. I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Yes; carrying account-scoped restart targets through the generic gateway planner and handler is the narrow maintainable fix because the lower channel manager already accepts optional account ids.
