## Summary

Keep open: current main and v2026.6.11 still represent channel reloads only as whole-channel restarts, the discussion includes message-loss logs on that path, and the linked PRs are implementation candidates rather than merged fixes.

## What This Changes

The issue asks the gateway reload planner to restart only the affected channel account for `channels.<channel>.accounts.<accountId>.*` config changes instead of restarting every account on that channel.

## Best Possible Solution

Land one generic account-scoped reload fix that carries `(channel, accountId)` restart targets through the gateway handler, then close the same-root duplicate reports after the fix merges.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: an account-scoped channel config path matches a broad channel reload prefix, the plan records only the channel, and the executor restarts that whole channel with no account id.

## Solution Assessment

Is this the best way to solve the issue? Yes; carrying account-scoped restart targets through the generic gateway planner and handler is the narrow maintainable fix because the channel lifecycle already accepts account ids.
