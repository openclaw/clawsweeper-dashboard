## What This Changes

The issue requests account-scoped gateway reloads for `channels.<channel>.accounts.<accountId>.*` changes instead of restarting the entire channel.

## Best Possible Solution

Land one canonical generic reload-planner fix that carries `(channel, accountId)` restart targets through the gateway handler while preserving whole-channel restarts for channel-global, mixed, default-account, secrets reload, and unlisted-account cases.

## Reproduction Assessment

Yes at source level: a strict account path matches a channel reload prefix, the plan records only the channel id, and the handler restarts that channel without an account id. I did not run a live Telegram or Mattermost repro in this read-only review.

## Solution Assessment

Yes, if maintainers accept the generic channel contract: the existing channel manager already accepts optional account ids, so the maintainable fix is to preserve that scope through reload planning and execution. The current-base PR is the best candidate to review before keeping the older conflicting branch alive.
