## Summary

Keep open: current main and v2026.6.11 still collapse account-scoped channel config edits into whole-channel restarts, and the remaining work is covered by open fix PRs rather than a merged implementation.

## What This Changes

This issue asks the gateway reload planner to restart only changed channel accounts for strict `channels.<channel>.accounts.<accountId>.*` config edits while preserving whole-channel restarts for global or mixed changes.

## Best Possible Solution

Land one canonical generic reload-planner fix, likely through https://github.com/openclaw/openclaw/pull/99312 or a repaired https://github.com/openclaw/openclaw/pull/43938, that carries `(channel, accountId)` restart targets while preserving whole-channel restarts for global, mixed, default, removed, or unsafe account changes.

## Reproduction Assessment

Yes, at source level: an account-scoped Telegram path matches the broad `channels.telegram` reload prefix, the plan stores only a channel id, and the hot reload handler restarts that whole channel with no account id.

## Solution Assessment

Yes. Carrying account-scoped restart targets through the generic gateway reload planner and executor is the narrow maintainable fix because the lower channel manager already supports account-scoped start and stop.
