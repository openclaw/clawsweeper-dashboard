## Summary

Keep open: current main and v2026.6.11 still represent account-scoped channel config changes as whole-channel restarts, and the remaining work is already covered by open implementation PRs rather than a merged fix.

## What This Changes

The issue requests account-scoped gateway hot reloads for `channels.<channel>.accounts.<accountId>.*` changes instead of restarting the entire channel.

## Best Possible Solution

Land one canonical generic gateway reload fix that carries `(channel, accountId)` restart targets through the planner and handler while preserving whole-channel restarts for channel-global, mixed, default-account, removed-account, and non-canonical account changes.

## Reproduction Assessment

Yes at source level: a strict account path such as `channels.telegram.accounts.engineer.dmPolicy` matches the broad channel reload prefix, becomes a channel-only restart plan, and the handler performs whole-channel stop/start. I did not run a live Telegram or Mattermost repro in this read-only review.

## Solution Assessment

Yes: carrying account-scoped restart targets through the generic gateway planner and handler is the narrow maintainable fix because the channel manager already accepts optional account ids. The current best path is to review and land one canonical implementation PR rather than queue a separate fix job.
