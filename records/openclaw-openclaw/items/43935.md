## Summary

Keep open: current main and v2026.6.11 still represent account-scoped channel config changes as whole-channel restarts, and the remaining work is already covered by open fix PRs rather than a merged implementation.

## What This Changes

Account-scoped channel config edits should restart only the affected channel account instead of bouncing every account on that channel.

## Best Possible Solution

Land the generic account-scoped reload fix, likely through https://github.com/openclaw/openclaw/pull/99312 or a repaired https://github.com/openclaw/openclaw/pull/43938, so the planner carries channel/account restart targets while channel-global and mixed changes still restart the whole channel.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: an account-scoped Telegram path matches the broad channels.telegram reload prefix, becomes a channel restart plan, and the hot reload handler restarts the whole channel with no account id.

## Solution Assessment

Is this the best way to solve the issue? Yes; carrying account-scoped restart targets through the generic gateway reload planner and executor is the narrow maintainable fix because the lower channel manager already supports account-scoped start and stop.
