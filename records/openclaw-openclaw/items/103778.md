## Summary

Current main still publishes attempted plugin metadata before the fallible plugin rebuild, so the reported persistent metadata/runtime divergence remains valid. The open pull request https://github.com/openclaw/openclaw/pull/103795 directly owns the fix and should be strengthened and reviewed rather than creating competing work.

## What This Changes

Ensure a failed gateway plugin reload preserves metadata describing the previously active plugin runtime.

## Best Possible Solution

Place metadata publication immediately beside the synchronous attached-runtime replacement after fallible preparation and previous-service shutdown, then add focused regression coverage showing that a thrown preparation leaves both previous states unchanged.

## Maintainer Decision

## Reproduction Assessment

Yes at source level. Current main commits the next snapshot before a fallible loader call, and the outer reload path contains the exception without reaching attached-runtime replacement.

## Solution Assessment

Mostly yes. Deferring publication past preparation fixes the reported permanent divergence, but publishing immediately beside runtime replacement after service shutdown gives the narrowest consistent commit boundary.
