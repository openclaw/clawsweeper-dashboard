## Summary

Keep this issue open: current MiniMax provider code still selects Bearer authentication for the API-key provider, while the reported endpoint explicitly rejects requests without `X-Api-Key`; this is a credible beta regression with a bounded repair path.

## What This Changes

The issue reports that upgrading from v2026.7.1 to v2026.7.2-beta.2 causes MiniMax Anthropic requests to omit the API-key header and fail with HTTP 401.

## Best Possible Solution

Make the built-in API-key MiniMax provider use the upstream `x-api-key` path, preserve Bearer auth for the Portal/OAuth provider, add regression coverage for both, and migrate any beta-created incompatible API-key setting through `openclaw doctor --fix`.
