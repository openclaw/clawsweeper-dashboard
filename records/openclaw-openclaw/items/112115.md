The issue requests that control-plane HTTP URL construction stop trusting the incoming Host header and instead use trusted configured hosts.

## Best Possible Solution

Have a security owner trace every Gateway HTTP route that emits absolute URLs, prove whether Host or forwarded-host values can influence one, and—only if confirmed—derive origins from the existing trusted deployment configuration with regression coverage for direct and reverse-proxy modes.
