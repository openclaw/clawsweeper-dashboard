## Summary

Keep open for maintainer product review. Current main and the latest release still intentionally split QQBot Markdown into independently sent chunks, a QQBot owner has now said that behavior is by design to avoid truncation, and an open linked PR proposes a bounded safe-size merge that should not close the issue before the delivery policy is decided.

## What This Changes

The issue requests changing QQBot long Markdown delivery so one logical reply does not appear as several independent QQ message bubbles.

## Best Possible Solution

Have QQBot maintainers explicitly choose the delivery policy: either keep chunk splitting as intentional and close this issue plus candidate PRs, or land the bounded safe-size merge path with clear live proof and fallback expectations.
