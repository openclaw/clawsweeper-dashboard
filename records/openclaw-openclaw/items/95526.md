## Summary

Keep open for maintainer direction, not a cleanup close. Current main and the latest stable release still split QQBot markdown into independently sent chunks; a member has now said that behavior is intentional, while https://github.com/openclaw/openclaw/pull/99032 proposes the opposite policy and remains open, conflicting, and unmerged.

## What This Changes

Requests QQBot to deliver long markdown replies as one visible message bubble instead of multiple independent per-chunk QQ messages.

## Best Possible Solution

QQBot should have one documented long-markdown delivery policy: keep safe split chunks by default, or adopt a maintainer-approved bounded merge policy with live QQ proof and regression coverage.
