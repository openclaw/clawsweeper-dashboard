## Summary

Keep open. Current main still sends each QQBot Markdown chunk through a per-chunk outbound send loop, and the open linked repair PR has not merged; a member comment also says the split behavior is intentional, so this needs a maintainer product decision rather than cleanup closure.

## What This Changes

The issue asks QQBot to preserve one logical long Markdown reply as one QQ message bubble or collapsed reply chain instead of emitting each chunk as an independent bubble.

## Best Possible Solution

Maintainers should choose the QQBot delivery contract, then either land one bounded safe-merge path with live safe-size and overflow proof or document that multi-bubble self-contained chunking is intended and close the competing repair PRs.
