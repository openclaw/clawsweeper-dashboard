## Summary

Keep this draft PR open: it is a substantive candidate implementation for the open OpenCode catalog-drift tracker, but its year-long models.dev metadata cache can still hide models that become available after gateway startup. It also needs maintainer direction on introducing the shared hybrid catalog layer and after-fix real runtime proof before merge.

## What This Changes

This draft PR adds a hybrid OpenCode Zen/Go provider catalog that combines fresh gateway model IDs, models.dev metadata, and plugin-owned static transport policy, with a gateway-start prewarm.

## System Context

The OpenCode Zen and Go plugins build provider model catalogs consumed by OpenClaw’s model selection and dynamic-model resolution paths. This change inserts a shared hybrid catalog layer between live gateway discovery and the plugin catalogs so model availability, metadata, and OpenClaw-specific transport rules can be combined.

## Best Possible Solution

Keep static plugin policy as the authoritative offline fallback, but refresh models.dev metadata when a newly discovered gateway ID is absent from the cached slice (or use a bounded metadata TTL) and obtain explicit approval for the shared private-local hybrid catalog design before landing.
