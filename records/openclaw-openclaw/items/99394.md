## Summary

Keep open: this is a plausible fix for the linked Feishu newline bug, but the branch currently rewrites text in the adapter chunker before Feishu decides whether the message will be post-md or card-rendered, so existing card-mode sends can get unintended doubled spacing.

## What This Changes

The PR adds a Feishu post markdown newline normalizer, applies it in send payload construction, outbound chunking, and reply dispatch, and adds focused unit tests around send payload behavior.

## Best Possible Solution

Keep the newline upgrade inside Feishu post-md delivery after the card/post decision, with chunking that accounts for the expanded post text without feeding doubled newlines into card renderers.

## Reproduction Assessment

Yes at source level: current main serializes plain Feishu post-md text unchanged, and the PR diff shows the new adapter chunker rewrites text before Feishu chooses card versus post. I did not run a live Feishu client round trip.

## Solution Assessment

No: send.ts payload normalization is a good owner boundary for post-md sends, but normalizing in the adapter chunker is too early because that path also feeds card-mode delivery.
