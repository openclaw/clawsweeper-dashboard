## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Preserve raw text before Feishu auto-card routing:** `extensions/feishu/src/outbound.ts:452-458`
  - body: `sendOutboundText` now builds `normalizedText` before checking `shouldUseCard` and then sends that normalized value to `sendMarkdownCardFeishu`. Text that reaches this helper with code fences or tables can get extra blank lines in a card even though the bug is scoped to post-md messages; decide card routing on raw text and normalize only after the post path is selected.
  - confidence: 0.9
- **[P2] Rechunk post text after newline expansion:** `extensions/feishu/src/outbound.ts:477`
  - body: The generic outbound payload sender calls `feishuOutbound.chunker` before `sendText`, and this branch's chunker still measures raw text while `sendOutboundText` later expands single newlines. A raw chunk within 4000 characters can therefore become an over-limit Feishu post, so add post-only expanded-length chunking or rejection before `sendMessageFeishu`.
  - confidence: 0.88
- **[P2] Guard expanded text edits before patching post content:** `extensions/feishu/src/send.ts:755-756`
  - body: The edit path now expands newlines before building the post patch payload, but it still sends the result directly to `client.im.message.patch`. A near-limit edit that previously fit the channel's post text boundary can grow past it after normalization, so reject or otherwise handle expanded over-limit edits locally with a focused regression.
  - confidence: 0.78
