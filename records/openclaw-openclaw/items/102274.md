Keep this open: current main still has the stale Teams stream cursor path after `finalize()`, and the issue is now paired with an open closing PR that should be reviewed rather than closing the issue early.

## What This Changes

The issue reports Microsoft Teams partial streaming corrupting post-tool text by slicing a new segment with a stale preamble offset.

## Best Possible Solution

Review and land or close https://github.com/openclaw/openclaw/pull/102277; the durable fix is to retire or reset Teams native stream state after a streamed segment is finalized so post-tool text uses intact block delivery.

## Reproduction Assessment

Yes at source level: a preamble partial advances `emittedTextLength`, `finalize()` clears pending state without resetting or retiring that cursor, and a later longer post-tool partial can be emitted as a stale slice. I did not run a live Teams DM repro in this read-only pass.

## Solution Assessment

Yes, the best fix belongs in the Microsoft Teams stream controller boundary: retire or reset the native stream after close and cover post-finalize partial text. The already-open PR targets that narrow boundary, so the issue should wait for that PR to be proven and resolved.
