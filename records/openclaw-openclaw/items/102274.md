## Label Justifications

- `P1`: Default Microsoft Teams DM partial streaming can corrupt tool-using replies, which is a broken channel delivery workflow for affected users.
- `impact:message-loss`: The issue is about user-visible assistant text being sliced and merged into the wrong Teams bubble after a tool call.

## Summary

The current Teams controller still tracks one emitted-text offset across the stream lifetime, and neither `preparePayload` nor `finalize` resets that offset for a new post-tool text segment. The report should stay open as a focused Microsoft Teams DM streaming regression, with the related long-reply duplicate issue kept separate.

## What This Changes

The issue requests that Microsoft Teams partial streaming reset or rotate reply-stream state at tool/segment boundaries so post-tool text is not sliced against a pre-tool preamble.

## Best Possible Solution

Restore a segment-boundary contract in the Teams stream controller: after the first streamed segment is finalized or a tool boundary starts, later post-tool text should either start a fresh stream with a reset cursor or bypass native streaming and use block delivery without slicing.

Yes, a narrow controller-level fix is the best path: reset or retire the partial-stream delta state at the same segment/tool boundary that the older `#56071` fix protected, then add regression coverage for post-finalize `onPartialReply`.

## Repair Work Prompt

Fix https://github.com/openclaw/openclaw/issues/102274 in the Microsoft Teams plugin. The observable bug is that in personal/DM partial streaming, a text preamble streamed before a tool call leaves `emittedTextLength` scoped to the old segment; a later post-tool text segment can be sliced at that stale offset and appended to the preamble bubble. Keep the fix inside the msteams reply stream controller/dispatcher boundary, do not add a config option, and do not conflate this with the >4000-character double-post fallback tracked by https://github.com/openclaw/openclaw/issues/91723 and https://github.com/openclaw/openclaw/pull/91729. Add or update tests that cover `onPartialReply` after a first streamed segment has been prepared and finalized, where the next segment is longer than the preamble, and assert the second segment is not emitted as `payload.text.slice(previousLength)`. Also preserve the existing cumulative-delta behavior for a single active segment and the existing fallback behavior for media and stream failures. Validation should run the focused msteams stream controller tests and, if available to the maintainer, a real Teams DM tool-using turn with streaming.mode `partial`.
