## Summary

This should stay open: current main still keeps one Teams partial-stream delta cursor for the controller lifetime, finalization does not reset that cursor, and the existing tests cover the pending-finalization path but not a later post-finalize text segment after a tool boundary.

## What This Changes

The issue reports that Microsoft Teams DM partial streaming can corrupt a post-tool text segment by slicing it at a stale preamble-length offset and appending the remainder into the preamble bubble.

## Best Possible Solution

Restore a segment-boundary contract in the Teams stream controller so post-tool text either starts with a reset delta cursor or bypasses native streaming for block delivery without slicing against the pre-tool preamble.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: a preamble partial advances `emittedTextLength`, `finalize()` does not reset it, and a later longer post-tool segment can be sliced at that stale offset. I did not establish a live Teams DM reproduction in this read-only review.

## Solution Assessment

Yes, the narrow maintainable fix belongs in the Microsoft Teams stream controller boundary: reset or retire partial-stream delta state at the segment/tool boundary and add regression coverage for post-finalize partial text. A broader core streaming rewrite is not necessary for this focused issue.
