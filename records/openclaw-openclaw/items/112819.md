## Summary

Keep this PR open. The seconds-to-milliseconds normalization is the right boundary for export and initial add planning, but the patch appears to leave the MCP update write path able to emit retired portable timeout keys when another server property changes; that can make a valid timeout-bearing update fail config validation. The contributor should repair that narrow path and add redacted real export/add/update behavior proof before merge.

## What This Changes

This PR preserves managed MCP-server request and connection timeouts by converting between portable Claw manifest seconds and OpenClaw configuration milliseconds during export, add planning, and digest comparison.

## System Context

Claws package one new agent together with its managed resources, including MCP servers. Export serializes an installed managed agent into a portable manifest; add and update plans compare that manifest with live configuration and then write canonical MCP-server configuration plus ownership records.

## Architecture Diagram

  F --> G[Managed MCP server]

## Best Possible Solution

Use one portable-manifest-to-canonical-config projection for every MCP configuration write, including update-plan action details, then prove a live export → add/reinstall → update sequence preserves request and connection timeouts while changing another server field.
