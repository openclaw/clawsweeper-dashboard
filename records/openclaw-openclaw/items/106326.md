## Summary

Keep this issue open for maintainer product direction. Current main still contains the reported parallel settings vocabularies, and existing design-system guidance has not standardized these runtime surfaces; the maintainer label also prevents automated cleanup. The proposal fits the web-frontend ergonomics roadmap, but its mandatory anatomy, exceptions, and migration sequence should be approved before implementation.

## What This Changes

Define a unified design language and shared primitives for Control UI settings-related pages, replacing divergent card, row, toggle, badge, animation, and spacing patterns.

## Best Possible Solution

Use the existing shared design-system tokens as the foundation, approve a small Control UI settings anatomy with explicit accessibility and page-specific exceptions, then migrate related page groups through focused PRs with Playwright interaction and visual-regression proof while deleting superseded CSS in each batch.
