## Summary

Keep open: the patch fixes part of the media-redaction bug, but supported history readers still call the shared projector without the new redaction option, and the proof only exercises the sanitizer directly rather than the real history endpoints.

## What This Changes

The PR adds an opt-in inline media redaction mode to gateway chat-display projection, threads it through main gateway history/session-history calls, and adds sanitizer tests plus a proof script.

## Best Possible Solution

Keep live broadcasts unredacted by default, but make every history/full-message reader opt into inline media redaction or invert the default for history-owned projection, with focused proof for main gateway, `chat.message.get`, embedded gateway, and embedded TUI.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: store a message with an `input_image.image_url`, nested `image_url.url`, or `source.data` data URL, then request `chat.message.get`, embedded gateway history, or embedded TUI history and those readers still project without the redaction option.

## Solution Assessment

No. The sanitizer opt-in and live-broadcast exception are reasonable, but the best fix must cover every history reader or move the default to a history-owned redaction mode with explicit live-broadcast exceptions.
