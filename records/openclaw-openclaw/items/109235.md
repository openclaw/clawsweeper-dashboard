## Summary

Keep open. The report describes a narrow shipped regression: iMessage can transcribe a native voice memo while losing its audio classification before the inbound-only TTS gate, so the configured voice reply is silently reduced to text. No merged fix or canonical open PR currently owns this iMessage-specific gap.

## What This Changes

Fix iMessage native voice memos with blank attachment MIME values so `messages.tts.auto: "inbound"` recognizes them as inbound audio.

## Best Possible Solution

Normalize a blank iMessage attachment MIME from the already-resolved attachment path before media-kind, placeholder, and inbound-context construction, then cover empty-MIME CAF and non-audio attachments with focused regression tests.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: a blank attachment MIME prevents the prepared context from identifying a CAF voice memo as audio, and the inbound-only TTS gate then skips synthesis. The reporter also provides a concrete stable-release reproduction and database query, though this review did not independently run macOS Messages.

## Solution Assessment

The owner-local MIME normalization is the best fix direction, but not with the proposed nullish-coalescing expression because an empty string is not nullish. Treat blank MIME as absent, use the shared filename-based MIME helper, and leave shared TTS policy unchanged.
