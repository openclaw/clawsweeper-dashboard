## Summary

Keep open: current `main` still leaves the `text_end` partial-delivery path unable to turn a trailing standalone `MEDIA:` line into `mediaUrls`, while the linked candidate PR is still open, conflicting, and targets removed `pi-embedded-subscribe*` files.

## What This Changes

The issue reports that standalone final `MEDIA:` directives can reach the Weixin channel as text without `mediaUrl` or `mediaUrls`, causing the image send to be skipped.

## Best Possible Solution

Keep this as the canonical bug and resolve it by porting the useful final-media text_end behavior into the current `embedded-agent-subscribe*` path while preserving message_end and structured tool-media delivery coverage.

## Reproduction Assessment

Yes at source level: the text_end path still resolves media from an accumulator result that withholds trailing MEDIA lines but does not parse them into `mediaUrls`. I did not run a live Weixin reproduction in this read-only review.

## Solution Assessment

Yes for the issue direction: the maintainable fix belongs at the shared embedded-agent final-reply media boundary, not as a Weixin-only fallback. The current paired PR is not the best landable patch as submitted because it targets obsolete files.
