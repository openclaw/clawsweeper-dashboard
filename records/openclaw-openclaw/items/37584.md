## Summary

Keep open: current main and v2026.6.11 still keep web-search credentials/settings in global `tools.web` or plugin-scoped config, while the requested per-agent override remains a security-sensitive config design decision.

## What This Changes

The issue requests per-agent overrides for web-search and tool settings such as `tools.web.search.apiKey`, provider, and timeouts.

## Best Possible Solution

Define a maintainer-approved agent-scoped web-tool credential/settings contract that coordinates global `tools.web`, plugin-owned web provider config, SecretRefs/redaction, precedence, docs, doctor/upgrade behavior, and two-agent regression coverage.

## Reproduction Assessment

Yes, source-level: `AgentToolsSchema` is strict and has no `web`, while global schema and runtime web-search/SecretRef paths read only `tools.web` or plugin-scoped web provider config.

## Solution Assessment

Unclear as an immediate implementation path: the proposed `agents.list[].tools.web` shape is plausible, but the best fix needs maintainer decisions on credential ownership and precedence across top-level tools, plugin config, env, and SecretRefs.
