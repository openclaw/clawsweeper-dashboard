## Summary

Keep open: current main still lacks an accepted per-agent web-search/tool credential surface, and the remaining work is a security-sensitive config/product contract rather than a narrow bug fix.

## What This Changes

The issue requests per-agent overrides for global tool settings such as `tools.web.search.apiKey`, provider, and related web-search options under `agents.list[].tools`.

## Best Possible Solution

Define one SecretRef-aware agent-scoped credential/config precedence contract for tool and plugin-owned web-search settings, then document and test fresh-install and upgrade behavior instead of adding a one-off `agents.list[].tools.web` shape.

Options:

- **Generic plugin/tool config override (recommended):** Create a single per-agent override contract that can cover plugin-owned web-search credentials and future tool settings without special-casing one provider family.
- **Narrow web-search-only override:** Add only `agents.list[].tools.web.search` support, which is smaller but risks another parallel credential path beside plugin config.
- **Defer to per-agent env/credential isolation:** Keep tool config global and solve agent-specific credentials through a broader env or SecretRef scoping design.
