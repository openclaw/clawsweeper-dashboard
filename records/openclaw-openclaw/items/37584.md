## Summary

## What This Changes

## Best Possible Solution

Define one maintainer-approved agent-scoped credential/config contract for web tools and plugin-owned webSearch settings, then implement schema, runtime merge, SecretRef/redaction, docs, and focused two-agent tests.

Question: Should OpenClaw add a first-class agent-scoped web/tool credential contract here, and should it live under `agents.list[].tools.web` or a generic per-agent plugin/tool configuration surface?

Rationale: The missing capability is real, but choosing the config location and precedence affects credential isolation, SecretRef resolution, plugin-owned config, docs, validation, and upgrade behavior.

Likely owner: Peter Steinberger

Owner confidence: medium

Options:

- **Design generic per-agent plugin/tool config (recommended):** Define one precedence and SecretRef contract covering plugin-owned webSearch configs and global `tools.web` before implementation.
- **Add only `agents.list[].tools.web`:** This addresses the narrow issue fastest but risks a second credential source competing with plugin-owned webSearch config.
- **Keep credentials global:** This keeps the config surface lean but leaves shared credential, billing, and rate-limit isolation unsolved for multi-agent installs.

## Reproduction Assessment

Yes. Source inspection shows `AgentToolsSchema` is strict and has no `web` field, while web-search runtime and SecretRef targets still use global `tools.web.search` or plugin-owned webSearch config without an agent-scoped merge.

## Solution Assessment

Unclear. `agents.list[].tools.web` is plausible, but the best fix needs maintainer decisions on precedence, SecretRef/redaction, validation, plugin-owned config, and upgrade behavior before implementation.
