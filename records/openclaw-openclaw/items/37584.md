## What This Changes

The issue asks for agent-scoped overrides for web/tool settings such as `tools.web.search.apiKey` so different agents can use different web-search credentials or providers.

## Best Possible Solution

Define one maintainer-approved agent-scoped web/tool credential contract covering precedence, SecretRef/redaction, plugin-owned `webSearch`, schema validation, docs, and two-agent regression coverage.

Rationale: The config location and precedence define a credential isolation boundary across SecretRefs, plugin-owned `webSearch`, provider auto-detection, config.apply, docs, reload, and upgrade behavior, so automation cannot safely choose the permanent contract.

Options:

- **Add only per-agent web settings:** Solve the immediate web-search credential use case faster under `agents.list[].tools.web`, accepting a narrower surface that may later conflict with plugin-owned web provider configuration.
- **Keep web credentials global:** Leave web-search provider credentials global or plugin-scoped and document separate gateways or provider-specific workarounds for billing isolation.
