Rationale: The config location and precedence define a credential isolation boundary across SecretRefs, plugin-owned `webSearch`, provider auto-detection, config.apply, docs, and upgrade behavior, so automation cannot safely choose the permanent contract.

Likely owner: steipete

Owner confidence: high

Options:

- **Design generic agent-scoped tool/plugin config (recommended):** Add a shared contract for agent-scoped tool/provider/plugin settings with explicit precedence, SecretRef handling, validation, reload, docs, and upgrade tests.
- **Add only `agents.list[].tools.web`:** Solve the immediate web-search credential use case faster, but accept a narrower surface that may later conflict with plugin-owned web provider configuration.
- **Keep web credentials global:** Leave web-search provider credentials as global/plugin-scoped settings and document separate gateways or provider-specific workarounds for users who need billing isolation.

Unclear until maintainers choose the contract. `agents.list[].tools.web` is plausible, but a single agent-scoped credential/config design is safer than adding a second source that competes with plugin-owned webSearch settings.
