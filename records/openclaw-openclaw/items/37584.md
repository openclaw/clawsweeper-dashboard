Options:

- **Design Generic Agent-Scoped Tool/Plugin Config (recommended):** Define one precedence and SecretRef contract for web tools plus plugin-owned webSearch settings before implementation.
- **Add Only `agents.list[].tools.web`:** This is narrower and faster, but risks creating a second credential source that competes with plugin-owned webSearch config.
- **Keep Web Credentials Global:** This keeps config lean but leaves billing, rate-limit, and credential isolation unsolved for multi-agent installs.

## Reproduction Assessment

Yes, at source level. Current main has a strict per-agent tools schema with no `web` field, while web-search runtime and SecretRef resolution still read global or plugin-owned webSearch config.

## Solution Assessment

Unclear until maintainers choose the contract. `agents.list[].tools.web` is plausible, but the safer durable fix is a single agent-scoped credential/config design that does not conflict with plugin-owned webSearch settings.
