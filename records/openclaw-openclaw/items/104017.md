## Summary

Keep this PR open for maintainer review. The exact-head controlled-server evidence now supports the timeout behavior, but applying a fixed 30-second deadline to every ordinary Zalo API operation is an intentional availability and compatibility policy change that needs an owner decision before merge.

## What This Changes

The PR changes the Zalo Bot API client so ordinary calls receive a 30-second abort deadline while explicit per-call and long-poll deadlines remain in effect, with regression coverage for a response body that stalls after headers.

## Best Possible Solution

Confirm whether a 30-second default is the intended contract for all ordinary Zalo API methods; if it is, merge this bounded implementation and retain focused coverage for both ordinary calls and long polling.
