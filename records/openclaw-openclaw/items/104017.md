## Summary

The PR is still necessary because current main leaves ordinary Zalo Bot API calls without a deadline; the proposed shared-client fix is narrow, preserves existing probe and long-poll overrides, has focused regression coverage, and includes convincing current-head runtime proof. No actionable correctness or security defect was found, so it should remain open for normal maintainer merge handling.

## What This Changes

The PR adds a 30-second default abort deadline to ordinary Zalo Bot API requests and regression coverage for stalled response bodies while preserving explicit per-call and long-poll timeouts.

## Best Possible Solution

Land the shared plugin-owned 30-second deadline with the existing explicit 5-second probe and poll-timeout-plus-5-seconds overrides, keeping timeout policy centralized rather than duplicating timers in each Zalo caller.
