## Label Justifications

- `P1`: The patch can cause user-visible channel replies to be dropped during a gateway restart initiated from an active turn.
- `merge-risk: 🚨 compatibility`: It changes the existing `--safe --skip-deferral` behavior from a pre-restart bypass into a destructive close-stage delivery bypass.

## Summary

Keep open, but the patch is not safe to merge as written: it turns the close-stage reply drain into an immediate timeout for `--safe --skip-deferral`, a behavior already observed to discard queued channel replies. The underlying delay report remains valid on current main, but this branch needs a delivery-preserving design and conflict refresh rather than acceptance of the zero-drain tradeoff. ([raw.githubusercontent.com](https://raw.githubusercontent.com/openclaw/openclaw/main/src/infra/restart.ts))

## What This Changes

The PR carries `skipDeferral` through both scheduled gateway-restart paths and makes that intent set the restart close-stage pending-reply drain timeout to zero.

## Best Possible Solution

Retain a delivery-preserving close-stage drain for `--safe --skip-deferral` and, if prompt self-restart is required, implement a bounded/deferred handoff after the initiating reply is delivered; then rebase and prove both the quick-restart and pending-reply cases.
