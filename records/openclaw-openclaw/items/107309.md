## Summary

Keep this PR open, but do not merge it in its current form. It fixes the earlier app-only projection and name-reservation concerns, yet the remaining test constructs a catalog state that the pinned MCP SDK rejects before OpenClaw materialization, so the claimed external-server crash and the proposed recovery boundary remain unproven.

## What This Changes

The PR catches MCP parameter-schema normalization exceptions in executable and app-only tool projections, logs a warning, and skips the affected catalog entry.

## Best Possible Solution

Prove the smallest MCP-valid schema that reaches OpenClaw and fails normalization, then either make `normalizeToolParameterSchema` accept that valid schema or reject it at catalog construction with a tool-scoped diagnostic and consistent catalog accounting.
