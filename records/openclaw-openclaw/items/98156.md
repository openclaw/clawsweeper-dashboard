## Summary

Keep open: current main and v2026.6.11 still have the abort-settle/takeover mechanics visible in source, while the existing replay helper is tied to reset lifecycle and the open related PR only partially covers the context-loss recovery policy.

## What This Changes

The issue reports that provider-error abort settlement can trigger embedded session takeover, rotate the transcript, and leave WebChat with a blank replacement session instead of prior context.

## Best Possible Solution

Define one bounded recovery path for provider-error abort/takeover that preserves context only within the same authorized session boundary and covers that path with source-level and live-style regression proof.

Question: What context, if any, may OpenClaw carry from a reset/taken-over embedded session into its replacement after provider-error abort settlement?

Rationale: The useful fix is not just mechanical: replaying prior transcript or trajectory data can solve user-visible amnesia, but it can also cross auth, channel, thread, clean-reset, or session-isolation boundaries if the policy is wrong.

Likely owner: steipete

Owner reason: Recent adjacent session-lock recovery work plus security-sensitive product-boundary judgment makes this the best available routing candidate from the history inspected.

Owner confidence: medium

Options:

- **Bounded same-session recovery (recommended):** Allow a small user/assistant context bridge only when the previous and replacement sessions share the same sessionKey, channel/thread/auth scope, and reset reason is internal recovery.
- **Takeover recovery only:** Land or revise the related takeover PR for resend/message-loss behavior, but do not automatically replay context until a separate security design is approved.
- **No automatic carry-forward:** Keep reset as a hard boundary and rely on user-visible diagnostics/exported trajectory for recovery, accepting that this issue remains a product limitation.
