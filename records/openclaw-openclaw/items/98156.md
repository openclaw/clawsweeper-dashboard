## Summary

Keep open: current main still has the advisory abort-settle/takeover mechanics and only a narrow reset-lifecycle replay helper, while the directly related takeover fix remains open and the context-replay boundary needs maintainer/security direction.

## What This Changes

The issue requests that an abort-settle/takeover reset after provider errors preserve enough prior session context instead of starting the replacement session blank.

## Best Possible Solution

Define a maintainer-approved provider-failure abort/takeover recovery path that either keeps the original session mapping or seeds bounded replacement-session context with auth, channel, thread, and clean-reset safeguards, then land the related takeover PR or a narrower follow-up.
