- `P2`: This is a concrete availability flaw in a supported trusted-plugin API, but the report provides source characterization rather than an observed current-user crash and requires a heavily populated namespace.
- `impact:crash-loop`: The affected problem class is process availability because a single complete scan can create severe memory pressure or heap exhaustion.

## Summary

Current `main` still exposes the shipped complete-array `entries()` contract and eagerly selects and parses every live namespace row, with no bounded enumeration API or canonical fix PR; the issue should remain open for Plugin SDK compatibility direction.

## What This Changes

Add a bounded plugin-state enumeration path so legitimate large namespaces cannot force one `entries()` call to load and parse every row at once.

## Best Possible Solution

Add a deterministic bounded page API, migrate high-volume bundled and migration callers, and retain then deprecate legacy `entries()` under an explicit Plugin SDK compatibility policy.

Options:

- **Add pagination and deprecate (recommended):** Add a bounded page API, migrate bundled callers, and temporarily retain `entries()` with explicit deprecation and oversized-read guidance.
- **Reject oversized reads:** Preserve complete-array semantics only below an aggregate threshold and return a typed limit error for larger namespaces.
- **Version the contract:** Introduce bounded enumeration only through a new versioned SDK contract and leave the current method unchanged.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: populate a namespace through the supported API and call `entries()`, which unconditionally selects and parses every live row. A destructive multi-gigabyte run is not needed to establish the unbounded behavior.

## Solution Assessment

Yes, bounded keyset pagination at the plugin-state owner boundary is the best general fix; silently limiting the existing method or merely lowering row limits would either break its shipped semantics or leave aggregate-byte risk unresolved.
