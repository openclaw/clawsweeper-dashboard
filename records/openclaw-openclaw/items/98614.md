## Summary

Keep this open: current main still has the token-auth in-process subagent path that can inherit the channel plugin client instead of forcing a write-scoped synthetic operator client, and the closing fix PR is still open rather than merged.

## What This Changes

The issue reports a v2026.6.11 regression where channel-triggered `sessions_spawn` fails with `missing scope: operator.write` in a token-auth loopback deployment.

## Best Possible Solution

Land or replace the narrow fix that forces a write-scoped synthetic operator client for in-process subagent `agent` dispatch while preserving explicit admin scopes for cleanup calls.

## Reproduction Assessment

No live high-confidence reproduction was run, but the current-main source path is source-reproducible: `agent` requires `operator.write`, while in-process `callSubagentGateway` does not force the synthetic write-scoped client for non-admin `agent` calls.

## Solution Assessment

Yes, the linked fix direction is the narrowest maintainable path: force the synthetic client at the `callSubagentGateway` in-process chokepoint instead of changing broad token-auth or device-identity behavior.
