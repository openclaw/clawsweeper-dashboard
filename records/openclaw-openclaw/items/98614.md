## What This Changes

The issue reports a v2026.6.11 regression where token-auth channel-triggered `sessions_spawn` fails with `missing scope: operator.write`.

## Best Possible Solution

Land or replace the narrow linked PR that forces the correct synthetic operator client for in-process subagent `agent` dispatch, with redacted token-auth channel proof and maintainer confirmation of the auth boundary.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: the issue gives concrete token-auth Google Chat steps, and current main shows the non-admin in-process `agent` dispatch can avoid the synthetic `operator.write` client; I did not run a live deployment repro.

## Solution Assessment
