## What This Changes

The issue reports a regression where channel-triggered `sessions_spawn` fails with `missing scope: operator.write` on token-auth deployments after upgrading to v2026.6.11.

## Best Possible Solution

Land or close the focused linked fix PR after review; once it merges, close this issue against the merge commit and shipped release provenance.

## Reproduction Assessment

Yes from source: the current `agent` spawn call enters `callSubagentGateway` without explicit scopes, so in-process dispatch can inherit the channel/plugin client instead of forcing the default synthetic `operator.write` client. I did not run the live Google Chat deployment, but the failing path is source-reproducible.

## Solution Assessment

Yes, the best fix direction is at the `callSubagentGateway` chokepoint so spawned `agent` calls use a write-scoped synthetic client while admin cleanup keeps explicit admin scopes. The open linked PR is the active candidate for that narrow path.
