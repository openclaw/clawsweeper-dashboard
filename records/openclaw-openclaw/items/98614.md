## Summary

Keep open: current main and the latest release still have the token-auth `sessions_spawn` path where in-process `agent` dispatch can inherit a caller client without `operator.write`, and the direct candidate fix is open but unmerged.

## What This Changes

The issue reports a regression where Google Chat-triggered token-auth `sessions_spawn` fails with `missing scope: operator.write` after upgrading to v2026.6.11.

## Best Possible Solution

Keep this issue open until https://github.com/openclaw/openclaw/pull/99199 or an equivalent narrow `callSubagentGateway` in-process dispatch fix lands with focused proof, and do not close it through the auth-none-only path.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: the report gives concrete token-auth Google Chat steps, and current main shows the in-process `agent` dispatch can inherit a caller client without `operator.write`; I did not run the live channel deployment.

## Solution Assessment

Is this the best way to solve the issue? Yes: the narrowest maintainable path is to fix the `callSubagentGateway` in-process dispatch boundary, while preserving admin-only cleanup scopes and proving the intended auth boundary.
