## Summary

Keep this open: current `main` does not have a merged, clearly applicable fix for the reported token-auth `sessions_spawn` regression, and the overlapping open PRs split between auth-none cleanup and a broader token-auth subagent fix path.

## What This Changes

The issue reports that Google Chat-triggered `sessions_spawn` fails with `missing scope: operator.write` on token-auth loopback deployments after upgrading from v2026.6.1 to v2026.6.11.

## Best Possible Solution

Keep this issue open until maintainers land or reject a narrow token-auth subagent fix with regression coverage for the `callSubagentGateway` to `agent` path and proof that Google Chat-style loopback delegation works after upgrade.

## Reproduction Assessment

Yes at source level, but not by a live Google Chat run in this review. The issue provides a version bisection and error output, and the source path shows `sessions_spawn` reaches a Gateway `agent` call that requires `operator.write`.

## Solution Assessment

No, the auth-none-only PR is not the best complete fix for this token-auth report. The best path is maintainer review of the token-auth subagent identity/scope boundary, likely using the narrower `callSubagentGateway` opt-in shape from the open candidate PR or a replacement that proves both security and upgrade behavior.
