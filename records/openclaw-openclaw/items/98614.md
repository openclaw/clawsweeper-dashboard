## Summary

Keep open: current main still sends the normal in-process `agent` spawn without an unconditional synthetic write-scoped client, and https://github.com/openclaw/openclaw/pull/99199 is the direct open candidate fix rather than a merged implementation.

## What This Changes

The issue reports a regression where token-auth, channel-triggered `sessions_spawn` fails with `missing scope: operator.write` after upgrading to v2026.6.11.

## Best Possible Solution

Land or supersede https://github.com/openclaw/openclaw/pull/99199 with focused proof that token-auth channel-triggered `sessions_spawn` succeeds and that admin-only cleanup remains admin-scoped.

## Reproduction Assessment

Yes at source level: the current `sessions_spawn` path calls `agent` without explicit scopes, and in-process dispatch inherits the scoped caller client unless `forceSyntheticClient` is true. I did not run a live Google Chat token-auth deployment in this read-only review.

## Solution Assessment

Yes, the best fix is a narrow change at the `callSubagentGateway` in-process dispatch boundary rather than broad Gateway auth-none or device-identity churn; the open candidate PR uses that shape but still needs maintainer proof review.
