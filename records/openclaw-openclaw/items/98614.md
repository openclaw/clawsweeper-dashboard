## Summary

Keep open: current main still has the reported token-auth `sessions_spawn` source path where in-process `agent` dispatch can inherit the caller client without `operator.write`, and the direct candidate fix at https://github.com/openclaw/openclaw/pull/99199 remains open and unmerged.

## What This Changes

The issue reports a regression where channel-triggered `sessions_spawn` on token-auth Gateway deployments fails with `missing scope: operator.write` after upgrading to v2026.6.11.

## Best Possible Solution

Keep this issue open until https://github.com/openclaw/openclaw/pull/99199 or an equivalent token-auth `callSubagentGateway` fix lands with focused regression proof and auth-boundary review.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: current main still routes `sessions_spawn` to an in-process `agent` Gateway call without forcing the synthetic write-scoped client; I did not run the live Google Chat deployment.

## Solution Assessment

Is this the best way to solve the issue? Yes, the best path is a narrow fix at the `callSubagentGateway` in-process dispatch boundary, with proof that it preserves the intended auth boundary for token-auth channel spawns.
