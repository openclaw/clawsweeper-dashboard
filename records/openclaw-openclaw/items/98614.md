## What This Changes

The issue reports that token-auth channel-triggered `sessions_spawn` regressed by letting the subagent `agent` call miss `operator.write`.

## Best Possible Solution

Review, prove, and land https://github.com/openclaw/openclaw/pull/99199 or an equivalent narrow `callSubagentGateway` fix, then close this issue from the merged commit.

Yes from source inspection and the reporter's bisected deployment evidence, although I did not run the live Google Chat setup. Current main still leaves the non-admin in-process `agent` dispatch able to inherit a narrower channel/plugin scoped client.

## Solution Assessment

Yes, the best path is a narrow fix at the `callSubagentGateway` in-process dispatch seam so `agent` uses the synthetic `operator.write` client without adding config or channel-specific behavior.
