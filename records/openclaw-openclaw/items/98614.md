## Summary

Keep open: current main still lets non-admin in-process subagent `agent` dispatch inherit the caller client when no explicit scopes are supplied, and the direct candidate fix is still an open conflicting PR rather than merged code.

## What This Changes

The issue reports a released regression where token-auth channel-triggered `sessions_spawn` fails with `missing scope: operator.write` after upgrading from `v2026.6.1` to `v2026.6.11`.

## Best Possible Solution

Land a reviewed fix at the `callSubagentGateway` in-process dispatch chokepoint that gives non-admin `agent` dispatch a synthetic write-scoped client after `sessions_spawn` policy authorizes the spawn, while keeping admin cleanup explicitly admin-scoped.
