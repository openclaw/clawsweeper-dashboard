## What This Changes

Fix the token-auth Google Chat `sessions_spawn` regression that fails with `missing scope: operator.write` after upgrading from v2026.6.1 to v2026.6.11.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/99199 or an equivalent narrow `callSubagentGateway` fix with focused auth-boundary proof, then close this issue as implemented after merge.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: current main still lets the in-process `agent` dispatch inherit a channel caller client unless forced synthetic, and the reporter supplied a concrete v2026.6.1 versus v2026.6.11 release comparison.

## Solution Assessment

Is this the best way to solve the issue? Yes: the narrow maintainable fix is at the `callSubagentGateway` in-process dispatch boundary, where https://github.com/openclaw/openclaw/pull/99199 forces the synthetic operator client without changing channel plugins or Gateway method scopes.
