## Summary

Keep open: current main still only forces the synthetic Gateway client when explicit scopes are present, while the token-auth `agent` spawn path sends no scopes; https://github.com/openclaw/openclaw/pull/99199 is the open candidate fix and has not merged.

## What This Changes

The issue reports a regression where `sessions_spawn` from a token-auth channel-triggered session fails with `missing scope: operator.write` after upgrading from v2026.6.1 to v2026.6.11.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99199, or an equivalent token-auth in-process dispatch fix, then close this issue with release or main-commit provenance.

## Reproduction Assessment

Yes at source level, but not by running a live Google Chat deployment in this read-only review. Current main routes the `agent` spawn call through in-process dispatch without explicit scopes, and the dispatcher inherits the channel-scoped client unless `forceSyntheticClient` is true.

## Solution Assessment

No for closing this issue now. The auth-none PR is adjacent but not the token-auth fix; the best current solution is to review and land PR 99199 or an equivalent in-process synthetic-client repair.
