## Summary

Keep this PR open for normal maintainer review. The current Signal attachment path still decodes untrusted daemon data with Node’s lenient base64 decoder before persisting it, while this focused patch uses the existing shared validator and includes credible after-fix runtime evidence; it needs a rebase/review refresh because its base is behind current `main`.

## What This Changes

The branch rejects malformed base64 returned by Signal’s attachment RPC before decoding and saving the attachment, with a focused regression test for that failure path.

## System Context

The Signal plugin’s monitor receives inbound events and fetches referenced attachments from signal-cli over its RPC interface. It decodes and saves the media, then the event handler passes the resulting local media path into OpenClaw’s inbound agent pipeline.
