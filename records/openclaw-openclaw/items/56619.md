## Summary

Keep open: current main and the latest release expose a generic `--notify` pairing approval path, but WhatsApp still registers only pairing normalization and has no approval notifier, so the reported sender-feedback gap remains.

## What This Changes

The issue asks for WhatsApp senders approved through DM pairing to receive an approval confirmation instead of having to guess when to retry.

## Best Possible Solution

Implement WhatsApp support for the existing `openclaw pairing approve ... --notify` path through the plugin-owned outbound send adapter, with focused tests and no new default/config surface unless maintainers explicitly choose that later.

Yes, source-level reproduction is high-confidence: `--notify` dispatches through `notifyPairingApproved`, but the WhatsApp pairing adapter has no `notifyApproval`, so the notification path returns without sending. I did not run a live WhatsApp session.

## Solution Assessment

Yes for the narrow path: wiring WhatsApp into the existing text pairing notifier is the smallest maintainable fix. Default-on notification, configurable copy, or replaying the blocked message should stay out of this repair unless maintainers make that product decision.
