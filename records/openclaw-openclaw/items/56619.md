## Label Justifications

- `P2`: This is a bounded WhatsApp pairing UX and delivery bug with a clear source-level gap, but it does not make the whole runtime unusable.
- `impact:message-loss`: The approval confirmation message requested by the WhatsApp sender flow is not delivered after approval.
- `impact:ux-friction`: The approved sender must guess when to try again because the product gives no same-channel confirmation.

## Summary

Keep open: current main and the latest release still expose `pairing approve --notify`, but WhatsApp does not register a pairing approval notifier, so the requester still gets no approval confirmation.

## What This Changes

The issue requests a WhatsApp confirmation message after a sender's DM pairing request is approved, with optional broader behavior such as default notification or replaying the blocked message.

## Best Possible Solution

Implement the existing `--notify` behavior for WhatsApp through a maintainer-approved gateway-backed notification seam, with focused regression coverage and redacted live or gateway proof before merge; defer default-on notification, config, and message replay unless separately sponsored.
