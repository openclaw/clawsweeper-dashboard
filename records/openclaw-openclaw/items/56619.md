## Summary

Keep open: current main and v2026.6.11 still expose the generic pairing `--notify` path, but WhatsApp's pairing adapter has no approval notifier, and the two exact fix PRs were closed unmerged. The open pairing-request hook PR is adjacent owner/plugin notification work, not sender approval confirmation.

## What This Changes

The issue requests notifying a WhatsApp sender after their pairing code is approved so they know they can start messaging the bot.

## Best Possible Solution

Implement WhatsApp approval confirmation on the existing `openclaw pairing approve --notify` path, using a channel-owned notifier or narrow generic outbound seam, while leaving default notification and original-message replay for separate product direction.

## Maintainer Decision

## Reproduction Assessment

Yes, at source level. The docs and CLI expose `pairing approve --notify`, `notifyPairingApproved` no-ops without a channel `notifyApproval` hook, and the WhatsApp adapter does not provide that hook.

## Solution Assessment

Yes for the narrow repair: wire WhatsApp into the existing approval-notification seam. The default-send and original-message replay ideas should remain out of scope unless maintainers explicitly choose them.
