## Summary

Keep open: current main and the latest release still document and wire `pairing approve --notify`, but WhatsApp has no `notifyApproval` adapter, so approval notification dispatch is a no-op for the reported channel. The two linked fix PRs were closed unmerged, and the open pairing-request hook PR is adjacent rather than a fix for post-approval sender feedback.

## What This Changes

The issue requests notifying a WhatsApp sender after their pairing code is approved so they know they can start interacting.

## Best Possible Solution

Add a WhatsApp-owned `notifyApproval` adapter through the existing channel/plugin pairing seam, with focused tests proving `openclaw pairing approve whatsapp <code> --notify` sends the shared approval message to the approved sender.

## Reproduction Assessment

Yes. Source inspection shows `--notify` is documented and wired through the CLI, but the current WhatsApp pairing adapter has no `notifyApproval`, so notification dispatch is a no-op for WhatsApp.

## Solution Assessment

Yes. The existing shared pairing notifier and plugin-owned WhatsApp channel adapter are the narrowest maintainable boundary; adding config/default policy should wait for explicit maintainer direction.
