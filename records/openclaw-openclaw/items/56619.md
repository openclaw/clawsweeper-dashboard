## Label Justifications

- `P2`: The missing WhatsApp approval notification is a normal-priority channel pairing gap with limited blast radius and a clear focused repair path.
- `impact:message-loss`: The same-channel approval confirmation promised by the pairing notification flow is suppressed for WhatsApp because no notifier exists.
- `impact:ux-friction`: Approved WhatsApp senders receive no feedback and have to guess when to retry, creating avoidable pairing UX friction.

## Summary

Keep open: current main and latest release still expose the pairing approval notification path, but WhatsApp does not implement the channel notifier, and the only exact fix PRs are closed unmerged. The currently open pairing hook PR is adjacent operator/plugin notification work, not sender notification after approval.

## What This Changes

The issue asks for WhatsApp senders approved through DM pairing to receive an approval confirmation instead of having to guess when to retry.

## Best Possible Solution

Implement a WhatsApp-owned `notifyApproval` adapter on the existing `openclaw pairing approve --notify` path, with focused tests; leave default notifications and original-message replay for separate product decisions.
