## Label Justifications

- `P2`: The missing WhatsApp approval notification is a normal-priority channel pairing gap with limited blast radius.
- `impact:message-loss`: The approved sender does not receive the same-channel confirmation message promised by the pairing notification flow.
- `impact:ux-friction`: The sender has to guess when approval is complete and send another message to proceed.

## Summary

Keep open: current main and the latest release still expose the generic pairing `--notify` path, but WhatsApp still has no approval-notification adapter, and the prior direct fix PRs are closed unmerged.

## What This Changes

Request that approved WhatsApp DM-pairing senders receive an in-channel confirmation after the owner approves their pairing code.

## Best Possible Solution

Add a WhatsApp-owned `notifyApproval` implementation on the existing pairing adapter so `openclaw pairing approve whatsapp <CODE> --notify` sends the shared approval text through the supported WhatsApp outbound path.
