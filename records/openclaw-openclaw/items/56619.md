## Label Justifications

- `P2`: The missing WhatsApp pairing approval notification is a normal-priority channel pairing bug with limited blast radius.
- `impact:message-loss`: The approved sender does not receive the same-channel confirmation message promised by the existing pairing notification flow.
- `impact:ux-friction`: The sender has to guess when approval happened and retry manually, which adds avoidable pairing-flow confusion without fully blocking progress.

## Summary

Keep open: current main and the latest release still leave the documented pairing approval `--notify` path as a no-op for WhatsApp because the WhatsApp pairing adapter lacks a notification hook, and both linked fix PRs are closed unmerged.

## What This Changes

The issue asks for WhatsApp pairing approval to notify the newly approved sender so they know when to retry.

## Best Possible Solution

Add a WhatsApp-owned approval notification hook to the existing `openclaw pairing approve --notify` path using the channel's existing send/outbound machinery, without adding default-on behavior, new config, or blocked-message replay unless maintainers explicitly choose that broader product direction.

## Reproduction Assessment

Yes, at source level. Current main exposes `openclaw pairing approve --notify`, but `notifyPairingApproved` returns when the adapter lacks `notifyApproval`, and the WhatsApp adapter lacks that hook.

## Solution Assessment

Yes for the narrow repair. The maintainable fix is to wire WhatsApp into the existing pairing notification seam; default notification and original-message replay should remain separate product choices.
