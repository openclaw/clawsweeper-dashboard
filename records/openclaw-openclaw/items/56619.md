## Summary

Keep open: current main still no-ops for WhatsApp pairing approval notification because the WhatsApp adapter lacks `notifyApproval`; the two direct fix PRs are closed unmerged, and the open pairing-request hook PR covers pre-approval notifications rather than post-approval sender delivery.

## What This Changes

Request that approving a WhatsApp DM pairing code notify the approved sender, with optional broader ideas for default delivery, configurable copy, or replaying the blocked message.

## Best Possible Solution

Add a WhatsApp-owned notifier to the existing `pairing approve --notify` seam using the established outbound send path, with focused tests and redacted real delivery proof; leave default/config/replay behavior to a separate product discussion.

## Reproduction Assessment

Yes, at source level. The docs and CLI expose `pairing approve --notify`, the shared dispatcher returns when no adapter notifier exists, and the WhatsApp adapter currently lacks that hook.

## Solution Assessment

Yes for the narrow repair: use the existing `--notify` pairing notification seam and add WhatsApp delivery. Default-on notification, configurable copy, and replaying the original blocked message are broader choices that should stay separate.
