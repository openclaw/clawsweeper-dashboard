## Summary

Keep open: current main and the latest release still expose the pairing `--notify` path, but WhatsApp has no approval-notification adapter, and the linked implementation attempts were closed unmerged.

## What This Changes

Requests that WhatsApp pairing approval notify the newly approved sender so they know when to retry.

## Best Possible Solution

Wire WhatsApp into the existing pairing `--notify` approval path through the gateway-backed outbound delivery seam, using the shared approval message and leaving default notification, custom copy, and replay behavior out of scope.

## Reproduction Assessment

Yes, at source level: `pairing approve --notify` calls the shared notifier, the shared notifier returns when `notifyApproval` is missing, and the WhatsApp pairing adapter currently lacks that hook. I did not run a live WhatsApp session in this read-only review.

## Solution Assessment

Yes for the narrow repair: implementing WhatsApp delivery on the existing `--notify` seam is the maintainable fix. Default notification, configurable copy, and original-message replay should stay separate product choices.
