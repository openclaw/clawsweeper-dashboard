## Summary

Keep open: current main and the latest release still expose `openclaw pairing approve --notify`, but WhatsApp still has no approval-notification hook; the two linked implementation PRs are closed unmerged, and the open pre-auth/access-request PRs do not solve sender approval confirmation.

## What This Changes

The issue requests notifying a WhatsApp sender after their pairing request is approved, with optional broader behavior such as replaying the blocked message.

## Best Possible Solution

Add a WhatsApp approval notifier to the existing `openclaw pairing approve --notify` path, with focused coverage for CLI approval, shared pairing dispatch, WhatsApp target normalization, and outbound delivery arguments.

Yes, at source level. The CLI exposes `--notify`, but the shared helper returns when the adapter lacks `notifyApproval`, and the current WhatsApp adapter does not provide that hook.

## Solution Assessment
