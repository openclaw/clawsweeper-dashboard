## Summary

Keep open: current main still does not deliver a WhatsApp approval confirmation to the requester, even though the shared pairing CLI has an opt-in `--notify` path. The prior WhatsApp fix PRs were closed unmerged, and the merged pairing-request hook only notifies/audits when a request is created, not when the sender is approved.

## What This Changes

The issue requests that WhatsApp senders receive a same-channel confirmation after their DM pairing request is approved.

## Best Possible Solution

Add a WhatsApp-owned `notifyApproval` implementation on the existing pairing notification seam, using the existing outbound send path and focused account/target coverage, without adding new config or replay behavior by default.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: approve a WhatsApp pairing with `--notify`, and the shared notifier returns because the WhatsApp adapter has no `notifyApproval` hook. I did not run a live WhatsApp session in this read-only review.

## Solution Assessment

Yes for the narrow fix: the maintainable path is to wire WhatsApp into the existing `--notify` pairing notification seam. Making notification default-on or replaying the blocked message should remain separate maintainer decisions.
