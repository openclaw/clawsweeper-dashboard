## Label Justifications

- `impact:message-loss`: The expected approval confirmation message is never delivered to the approved WhatsApp sender.

## Summary

Keep open: current main and the latest release still expose `openclaw pairing approve --notify`, but WhatsApp has no pairing approval notifier, so the sender notification path remains a no-op for this channel. The direct fix PRs are closed unmerged, and the currently open pairing-request hook PR is adjacent rather than a fix for approval notification.

## What This Changes

The issue requests notifying a WhatsApp sender after their DM pairing request is approved, preferably through an approval confirmation message or replay of the blocked message.

## Best Possible Solution

Wire WhatsApp into the existing `openclaw pairing approve ... --notify` notifier through gateway-owned outbound delivery, with focused tests, and leave automatic/default notification policy for a separate maintainer decision.

## Maintainer Decision

## Reproduction Assessment

Yes, at source level. Current main exposes `openclaw pairing approve --notify`, but the dispatcher returns when `notifyApproval` is absent and the WhatsApp pairing adapter does not define that hook.

## Solution Assessment

Yes for the narrow repair: use the existing `--notify` approval path and add a WhatsApp notifier through the shared outbound delivery layer. Making approval notifications automatic by default would be a separate product/config decision.
