## Summary

Keep open: current main and v2026.6.11 still have the WhatsApp gap. The pairing CLI documents and exposes `--notify`, but WhatsApp's pairing adapter still has no approval notifier, and both linked fix PRs are closed unmerged.

## What This Changes

The issue requests a WhatsApp approval confirmation so a newly paired sender knows they can message the bot after the owner approves their pairing code.

## Best Possible Solution

Wire WhatsApp into the existing `openclaw pairing approve ... --notify` path with a focused notifier and tests, then provide redacted live WhatsApp or gateway proof; leave default-on notification and replay as separate product decisions.

## Reproduction Assessment

## Solution Assessment

Yes for the narrow repair: implement the existing `--notify` behavior for WhatsApp. Default notification, configurable copy, and original-message replay should stay out of this fix unless maintainers explicitly choose that broader product direction.
