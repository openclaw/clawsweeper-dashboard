## Label Justifications

- `P2`: The missing WhatsApp approval confirmation is a bounded channel pairing defect with limited blast radius.
- `impact:message-loss`: The documented same-channel approval confirmation is silently not delivered for WhatsApp because the adapter lacks a notifier hook.
- `impact:ux-friction`: Approved WhatsApp senders must guess when to send another message because they get no in-channel confirmation after approval.

## Summary

Keep open: current main and the latest release still expose the approval notification path but WhatsApp does not implement the notifier, and the prior same-issue fix PRs were closed unmerged. The open related hook PR is adjacent operator-notification work, not sender-after-approval delivery.

## What This Changes

This issue asks OpenClaw to notify a WhatsApp sender after their DM pairing code is approved.

## Best Possible Solution

Wire WhatsApp into the existing `pairing approve --notify` path with SDK-safe, gateway-backed outbound delivery, focused regression tests, and redacted live proof; leave default notification, message customization, and original-message replay to separate product decisions.

## Maintainer Decision

## Reproduction Assessment

Yes, at source level. Current main documents and exposes `pairing approve --notify`, but the shared notifier no-ops when the adapter lacks `notifyApproval`, and the WhatsApp adapter lacks that hook.

## Solution Assessment

Yes for the narrow repair. The best fix is to make WhatsApp support the existing `--notify` notification seam without adding a default/config/replay behavior in the same change.
