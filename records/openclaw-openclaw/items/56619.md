## Label Justifications

- `P2`: The missing WhatsApp approval notification is a bounded channel pairing gap with limited blast radius.
- `impact:message-loss`: The approved sender does not receive the same-channel confirmation message promised by the pairing notification flow.
- `impact:ux-friction`: The sender has to guess when approval happened and retry manually, which adds avoidable pairing-flow confusion.

## Summary

Keep open: current main and v2026.6.11 still expose the pairing notification path but WhatsApp has no approval notifier, and both linked implementation PRs are closed unmerged.

## What This Changes

Request that WhatsApp senders approved through DM pairing receive a same-channel approval confirmation instead of having to guess when to message again.

## Best Possible Solution

Wire WhatsApp into the existing opt-in `pairing approve --notify` path through the shared gateway/outbound delivery layer, without adding new config, changing the default approval flow, or replaying blocked messages in this fix.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: current main exposes `pairing approve --notify`, but the dispatcher returns without delivery when the adapter lacks `notifyApproval`, and the WhatsApp adapter lacks that hook.

## Solution Assessment

Yes for the narrow fix: use the existing pairing notification seam and WhatsApp/gateway outbound delivery, while leaving default notification, custom messages, and blocked-message replay out of scope.
