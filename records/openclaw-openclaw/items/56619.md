## Label Justifications

- `P2`: The missing WhatsApp approval confirmation is a normal-priority channel pairing gap with limited blast radius and a clear bounded repair.
- `impact:message-loss`: The approved sender does not receive the same-channel confirmation message that the existing pairing notification path is documented to send.
- `impact:ux-friction`: The sender has to guess when approval happened or send another message, creating avoidable pairing UX confusion without fully blocking progress.

## Summary

Keep open: current main and the latest release still expose the documented pairing approval `--notify` path, but WhatsApp does not implement the channel `notifyApproval` hook, and the two direct fix PRs were closed unmerged. The currently open related hook PR is adjacent operator/request-notification work, not a sender-after-approval fix.

## What This Changes

Request that WhatsApp send a confirmation to a newly approved pairing sender, preferably through the existing pairing approval notification flow.

## Best Possible Solution

Add a WhatsApp-owned `notifyApproval` implementation for the existing `--notify` pairing approval path, without adding new config, default notification behavior, or original-message replay unless maintainers explicitly choose that broader UX.
