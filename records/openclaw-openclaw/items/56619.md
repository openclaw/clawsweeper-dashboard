## Repair Work Prompt

Fix the WhatsApp pairing approval notification gap for https://github.com/openclaw/openclaw/issues/56619. On current main, `openclaw pairing approve --notify` calls the shared pairing notifier, but `extensions/whatsapp/src/channel.ts` declares a pairing adapter with only `idLabel` and `normalizeAllowEntry`, so `src/channels/plugins/pairing.ts` returns without delivery. Add WhatsApp support for the existing opt-in `--notify` path only: send the shared approved message to the approved direct sender through the existing WhatsApp outbound/send path, preserve accountId behavior, keep core plugin-agnostic, do not add a config/env/default-notify surface, and do not replay the original blocked message. Add focused tests for the WhatsApp pairing adapter and keep shared CLI/pairing tests green. Do not edit CHANGELOG.md.
