- `P2`: The missing WhatsApp approval confirmation is a normal-priority channel pairing gap with limited blast radius.
- `impact:message-loss`: The approved sender does not receive the same-channel confirmation message promised by the pairing notification flow.

## Summary

Keep open: current main and v2026.6.11 expose the pairing `--notify` path, but WhatsApp still does not implement the adapter hook that would send the same-channel approval confirmation. The two exact fix PRs are closed unmerged, and the open pairing-request-hook PR is adjacent rather than a sender approval notification fix.

## What This Changes

The issue requests a WhatsApp same-channel confirmation after pairing approval, with possible extensions for default notification or blocked-message replay.

## Best Possible Solution

Add a WhatsApp-owned `notifyApproval` implementation on the existing pairing notification seam, with focused tests, and leave default auto-notify or message replay for a separate product choice.

Yes, at source level. `openclaw pairing approve --notify` routes through `notifyPairingApproved`, but the WhatsApp pairing adapter lacks `notifyApproval`, so the confirmation is silently not sent.

## Solution Assessment

Yes for the narrow repair. The best fix is to wire WhatsApp into the existing pairing notifier path, not add a new config surface or replay blocked messages in the same change.
