## What This Changes

Request to notify a WhatsApp sender after the owner approves their pairing request, with optional original-message replay as a broader follow-up.

## Best Possible Solution

Add a WhatsApp-owned notifier on the existing pairing `--notify` adapter/outbound path, with focused tests, and leave default-on notification or original-message replay for an explicit later product decision.

## Reproduction Assessment

Yes, at source level. WhatsApp creates a pairing request and sends the pairing code, but approval with `--notify` reaches a no-op because the WhatsApp pairing adapter lacks `notifyApproval`.

## Solution Assessment

Yes for the narrow repair. The maintainable fix is to wire WhatsApp into the existing pairing notification seam, not add a new config/default surface or replay blocked messages in the same change.
