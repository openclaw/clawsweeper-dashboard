## Summary

Keep open: the proposed strict UTF-8 decoder changes link understanding from tolerant processing to silently skipping an entire fetched link, without considering the response-declared charset or an approved strict-decoding policy.

## What This Changes

The PR changes `fetchLinkContent` to decode fetched link bytes with a fatal UTF-8 `TextDecoder`, causing malformed UTF-8 to throw instead of producing replacement characters.

## Best Possible Solution

Adopt an explicit response-charset policy, decode declared encodings correctly, and reject only content that cannot be decoded under that policy with focused coverage for valid legacy charset and malformed declared-UTF-8 responses.
