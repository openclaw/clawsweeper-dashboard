## Summary

Keep this PR open, but do not merge it as written: fatal UTF-8 decoding converts any non-UTF-8 response into a whole-link skip before configured link-model entries run, while the fetcher accepts broad text media types without consulting their declared charset. ([raw.githubusercontent.com](https://raw.githubusercontent.com/openclaw/openclaw/main/src/link-understanding/runner.ts))

## What This Changes

The branch changes `fetchLinkContent` to use a fatal UTF-8 `TextDecoder`, rejecting malformed byte sequences instead of inserting replacement characters.

## Best Possible Solution

Preserve link-understanding coverage by decoding a declared supported response charset with fatal validation, with an explicit owner-approved policy for absent, unsupported, or malformed charset declarations.
