## Summary

Keep open. The PR targets the right shared parser, but it is not merge-ready because the new numeric guard still lets common time-like fallback values such as `14:30:00` or `14:30 tomorrow` become keyed answers, and the contributor evidence is tests/CI only rather than real behavior proof.

## What This Changes

The PR changes the agent harness keyed-answer parser and adds focused tests so URL, Windows path, and numeric time-like text are less likely to be misread as keyed multi-question answers.

## Best Possible Solution

Keep the shared-helper repair, but reject time-like fallback text before keyed lookup for common variants while preserving explicit keyed replies such as `14: answer`, `q1: answer`, `q1 = answer`, and `q1 - answer`.

## Solution Assessment

No. The shared helper is the right layer, but the numeric-only guard is too narrow for the time-string class the PR claims to fix.
