Fix the Mattermost streaming-reply regression reported at https://github.com/openclaw/openclaw/issues/109471. In the Mattermost plugin, ensure that once a preview post has been successfully finalized into the assistant answer, a later isError tool-warning payload from the same turn is delivered separately without clearing or deleting that finalized post. Preserve existing behavior for previews that have not finalized, media/reply fallbacks, failed final edits, threading, and streaming-off mode. Prefer a Mattermost-owned lifecycle adjustment unless inspection proves the shared adapter contract itself is wrong for sibling channels; do not change agent payload ordering, suppress tool warnings globally, add config, or add runtime compatibility branches. Add regression coverage for ordered payloads [successful assistant final, trailing isError warning], asserting the answer remains and the warning sends normally. No CHANGELOG.md edit is expected.
