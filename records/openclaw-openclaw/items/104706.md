- `P1`: The PR addresses a wrong-account authentication regression in an active Telegram and channel login workflow.
- `merge-risk: 🚨 auth-provider`: The patch changes which canonical profile key owns newly obtained OpenAI OAuth credentials and validates the provider result at a shared runtime boundary.

## Summary

The canonical-identity fix remains necessary and the prior shared-path blocker is addressed, but the current patch can still report a successful login without adopting the returned profile when the target session row does not exist. Exact-head CI is green, yet the external PR also lacks required after-fix live Telegram proof.

## What This Changes

The PR stops reusing the current session profile id during Codex authentication, validates the returned login result, and updates Telegram and shared channel sessions to the returned canonical OpenAI profile.

## Best Possible Solution

Keep model-auth as the sole owner of canonical profile derivation, then use one race-safe session mutation that creates or updates the target row so every full-success response means the returned profile was actually adopted; preserve partial-success messaging when persistence fails.
