## Summary

Keep open: current main still has the exact discovered-gateway fail-closed path, and the reporter's follow-up reframes the practical failure as misleading Tailscale Serve reachability diagnostics rather than an implemented fix.

## What This Changes

The issue requests supported iOS discovered-gateway first-use behavior or clearer diagnostics when a Bonjour/Tailscale gateway lacks advertised TLS and no trusted fingerprint exists.

## Best Possible Solution

Preserve secure defaults, then make iOS discovery/onboarding either diagnose unreachable Tailscale Serve clearly or mark non-TLS/no-pin discovered gateways unavailable unless maintainers explicitly approve a plaintext exception.

## Reproduction Assessment

Yes, source-level. A discovered gateway with gateway.tlsEnabled false and no stored GatewayTLSStore fingerprint reaches the exact guard that returns the reported error; I did not run a live iOS device repro.

## Solution Assessment

Unclear until maintainers pick the security UX. The safest direction is to keep the TLS-only trust boundary and improve iOS diagnostics/availability instead of silently allowing plaintext discovered connects.
