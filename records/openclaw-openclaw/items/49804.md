## Summary

Keep open: current main has several targeted lifecycle guards and cleanup helpers, but it does not provide the shared cross-boundary ResourceManager-style shutdown protocol requested here. This remains a maintainer design/API decision rather than an implemented cleanup or a narrow safe fix lane.

## What This Changes

The issue requests a standard ResourceManager-like shutdown protocol so async work can be registered, cancelled, or drained before cleanup across retry, session, and channel paths.

## Best Possible Solution

Keep this as the canonical design tracker and choose a narrow lifecycle/drain protocol only if targeted fixes and open concrete bugs prove the existing opt-in helpers are insufficient.
