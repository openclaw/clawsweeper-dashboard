## Summary

Keep this PR open: the central duplicate-send bug is real and strongly proven, but the patch leaves a delivered lost-ACK command as a persistent failed Retry row because the new unconfirmed path neither deletes it nor participates in authoritative-history cleanup.

## What This Changes

The PR changes Android outbox recovery and gateway outcome handling so post-dispatch uncertainty becomes a visible failed row requiring explicit Retry, while pre-dispatch failures and definitive rejections retain automatic retry behavior.

## Best Possible Solution

Keep explicit Retry and Delete for genuinely ambiguous sends, but delete the matching delivery-unconfirmed outbox row when authoritative history proves delivery by idempotency key, with regression coverage for both confirmed and still-ambiguous cases.
