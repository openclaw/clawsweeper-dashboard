## Summary

Keep open: current main and v2026.6.11 still preserve the reported ACP pending-identity and stored-metadata-ready behavior, and the overlapping warm-restore PR is open but not a safe merged fix.

## What This Changes

The issue reports that ACP-bound channel sessions can remain in pending identity state after gateway restart storms, causing follow-up messages to miss the intended ACP agent.

## Best Possible Solution

Implement status- or liveness-backed ACP recovery for persistent bound sessions after gateway restart, keep ensure-sourced IDs provisional until confirmed, and prove configured channel dispatch after restart.
