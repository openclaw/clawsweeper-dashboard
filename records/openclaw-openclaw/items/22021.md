## Summary

Keep open: current main still lacks actual-runtime-model response metadata for the Gateway OpenAI-compatible HTTP endpoints, and this issue remains the canonical item for that transport contract rather than being superseded by related session/runtime observability work.

## What This Changes

Request to expose the actual runtime model used by Gateway OpenAI-compatible HTTP responses, proposed as an `X-Actual-Model` response header.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including SSE semantics, then wire it from the selected-model signal or agent metadata with focused Gateway tests and docs.

## Solution Assessment

No for the literal header-only proposal. The maintainable fix needs a unified body/header/SSE metadata contract so fallback attribution remains accurate after streaming headers have flushed.
