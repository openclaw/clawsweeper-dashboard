## Summary

Keep open: current main and the latest release still lack an actual-runtime-model response surface for the OpenAI-compatible Gateway HTTP endpoints, and the remaining work needs a public HTTP/SSE API contract decision.

## What This Changes

Request to expose the actual runtime model used by Gateway OpenAI-compatible HTTP responses, proposed as an `X-Actual-Model` response header.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including SSE semantics, then wire it from the selected-model signal with focused Gateway tests and docs.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What actual-runtime-model metadata contract should Gateway expose for non-streaming and streaming OpenAI-compatible HTTP responses?

Rationale: The source gap is clear, but the requested response header is a public API contract and ordinary headers cannot cover late fallback selection after SSE headers flush.

Likely owner: steipete

Owner reason: steipete already reviewed this exact Gateway HTTP contract gap and has the strongest Gateway HTTP/docs history signal among likely owners.

Owner confidence: high

Options:

- **Define unified HTTP/SSE metadata (recommended):** Document and implement one actual-model contract for Chat Completions and Responses across non-streaming body/header metadata and streaming SSE-compatible metadata.
- **Limit first pass to non-streaming:** Add actual-model response metadata only where it is known before headers are sent and leave streaming attribution as an explicit follow-up limitation.
- **Defer to runtime metadata work:** Keep transport response attribution deferred until the broader resolved-model and session-status metadata contract is decided.

## Reproduction Assessment

Yes, from source inspection: current Gateway handlers return the request-side `model` and do not wire the existing selected-model signal into HTTP responses. No live fallback run was executed in this read-only cleanup review.

## Solution Assessment

No for the literal header-only proposal. The maintainable fix needs a unified body/header/SSE metadata contract so fallback attribution remains accurate after streaming headers have flushed.
