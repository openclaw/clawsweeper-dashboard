## Summary

Keep open: current main and the latest release still lack an actual-runtime-model response metadata contract for the OpenAI-compatible Gateway HTTP endpoints, and the remaining work is API/SSE product-contract design rather than conservative cleanup.

## What This Changes

Request to expose the actual runtime provider/model used by OpenAI-compatible Gateway HTTP requests, proposed as `X-Actual-Model` response metadata.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including non-streaming and SSE behavior, then wire it from the existing selected-model signal with focused Gateway tests and live proxy proof.

## Reproduction Assessment

Yes at source level. Current main has no actual-model Gateway response header or documented equivalent, and both OpenAI-compatible handlers return request-side model values while actual selected-model plumbing remains below the HTTP layer.

## Solution Assessment

No for the header-only proposal. The useful end state needs a unified body/header/SSE metadata contract so fallback attribution remains accurate after streaming headers have flushed.
