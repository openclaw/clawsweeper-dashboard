## Summary

Keep open: current main and the latest release still lack an actual-runtime-model response metadata contract for the Gateway OpenAI-compatible HTTP endpoints, and the remaining work needs maintainer API/SSE direction.

## What This Changes

Add an `X-Actual-Model` or equivalent response metadata surface so HTTP clients can see which runtime model actually handled each Gateway OpenAI-compatible request.

## Best Possible Solution

Define one documented Gateway actual-model metadata contract for `/v1/chat/completions` and `/v1/responses`, including streaming semantics, then wire actual selection from `onModelSelected` or agent metadata with focused endpoint tests.

## Reproduction Assessment

Yes. Source inspection reproduces the missing behavior: current main has no `X-Actual-Model` or equivalent response metadata, and both Gateway HTTP endpoints emit the request-side model while actual model selection remains below the HTTP layer.

## Solution Assessment

Unclear until maintainers choose the public contract. A plain response header is not sufficient for streaming fallback cases because headers are flushed before the actual selected model may be known.
