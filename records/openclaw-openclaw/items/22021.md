## Summary

Keep open: current main and the latest release still lack an actual-runtime-model response surface for the OpenAI-compatible Gateway HTTP endpoints, and the remaining work needs a public HTTP/SSE API-contract decision rather than conservative cleanup.

## What This Changes

The issue requests an `X-Actual-Model` or equivalent Gateway HTTP response surface showing the provider/model that actually processed each request.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including non-streaming and SSE behavior, then wire it from the existing selected-model signal with focused Gateway tests and live routing-proxy proof.

## Reproduction Assessment

Yes, from source inspection: current handlers return request-side `model` and do not wire the existing selected-model signal into HTTP responses; no live fallback run was executed in this read-only cleanup review.

## Solution Assessment

No for the header-only proposal. The maintainable solution needs a unified body/header/SSE metadata contract so fallback attribution remains accurate after streaming headers have flushed.
