## Summary

Keep open: current main and the latest release still lack actual-runtime-model response metadata for the OpenAI-compatible Gateway HTTP endpoints, while the existing selected-model callback remains below the HTTP layer. The remaining work is a public Gateway HTTP/SSE API contract decision, not conservative cleanup.

## What This Changes

Request to expose the runtime-selected model in Gateway OpenAI-compatible HTTP responses, proposed as an `X-Actual-Model` response header.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including non-streaming and SSE behavior, then wire it from the existing selected-model signal with focused Gateway tests and live proxy proof.

Options:

- **Define unified metadata contract (recommended):** Document and implement a single contract for non-streaming body/header metadata plus streaming SSE-compatible metadata across Chat Completions and Responses.
- **Limit to non-streaming headers:** Add a header only where the selected model is known before response headers are sent, accepting that streaming clients remain unresolved or get a separate later follow-up.
- **Defer HTTP response metadata:** Keep this issue open behind the broader session/runtime metadata work and avoid adding HTTP response fields until the selected-versus-resolved model contract is settled elsewhere.

## Solution Assessment

No for the header-only proposal. The useful end state needs a unified body/header/SSE metadata contract so fallback attribution remains accurate after streaming headers have flushed.
