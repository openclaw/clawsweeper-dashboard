## Summary

Keep open: current main and the latest release still lack a Gateway actual-runtime-model response surface, and the remaining work needs a maintainer API-contract decision for non-streaming and streaming OpenAI-compatible responses.

## What This Changes

The issue requests an `X-Actual-Model`-style HTTP response metadata surface so clients can see which model actually handled each Gateway request.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including non-streaming and SSE behavior, then wire it from the existing selected-model signal with focused Gateway tests and live routing-proxy proof.
