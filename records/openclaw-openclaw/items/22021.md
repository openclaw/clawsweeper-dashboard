## Summary

Keep open: current main and the latest release still lack actual-runtime-model metadata on the Gateway OpenAI-compatible HTTP responses, and the remaining work is a public API/SSE contract decision rather than conservative cleanup.

## What This Changes

Add a Gateway HTTP response surface, such as `X-Actual-Model`, that exposes the actual runtime model used for each OpenAI-compatible response.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including non-streaming and SSE behavior, then wire it from the existing selected-model signal with focused Gateway tests and live routing-proxy proof.

Question: What actual-runtime-model contract should Gateway expose for non-streaming and streaming OpenAI-compatible HTTP responses?

Rationale: Current code has actual selected-model metadata below the HTTP layer, but ordinary response headers are flushed too early for streaming fallback cases; maintainers need to choose the public API shape before implementation.

Likely owner: steipete

Owner reason: steipete already reviewed this exact Gateway API-contract gap and has the strongest recent history signal for the affected endpoint/docs surface.

Owner confidence: high

Options:

- **Define unified metadata contract (recommended):** Document and implement one contract for non-streaming body/header metadata plus streaming SSE-compatible metadata across Chat Completions and Responses.
- **Limit to non-streaming headers:** Add an ordinary header only where the selected model is known before response headers are sent, leaving streaming clients for a later contract.
- **Fold into broader resolved-model work:** Keep this blocked until the broader session/runtime resolved-model contract explicitly covers HTTP response attribution.

## Reproduction Assessment

Yes. Source inspection on current main and `v2026.6.11` shows no actual-model response header or documented equivalent, and both OpenAI-compatible handlers return request-side model values while actual selected-model plumbing remains below the HTTP layer.

## Solution Assessment

No for the header-only proposal. The maintainable solution is a unified body/header/SSE metadata contract so fallback attribution remains accurate after streaming headers have flushed.
