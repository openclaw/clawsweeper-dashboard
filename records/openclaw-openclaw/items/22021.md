## Summary

Keep open: current main and the latest release still lack a Gateway HTTP actual-runtime-model response metadata contract, and the remaining work needs maintainer API/SSE direction rather than conservative cleanup closure.

## What This Changes

The issue requests a Gateway HTTP response metadata surface, proposed as `X-Actual-Model`, that reports the model that actually processed each OpenAI-compatible request.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including non-streaming and SSE behavior, then wire it from the existing selected-model signal with focused Gateway tests and live proxy proof.

## Reproduction Assessment

Yes at source level. Current main has no actual-model Gateway response header or documented equivalent, and both OpenAI-compatible handlers return request-side model values while actual selected-model plumbing remains below the HTTP layer.

## Solution Assessment

No for the header-only proposal. The maintainable fix needs a unified body/header/SSE metadata contract so fallback attribution remains accurate after streaming headers have flushed.
