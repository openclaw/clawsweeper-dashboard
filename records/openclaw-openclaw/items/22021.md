## Summary

Keep open: current main and the latest release still lack an actual-runtime-model response surface for the OpenAI-compatible Gateway HTTP endpoints, and a header-only fix needs maintainer API-contract direction for streaming behavior.

## What This Changes

The issue requests an HTTP response header that exposes the actual runtime model used by Gateway responses.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including non-streaming and SSE behavior, then wire it from the existing selected-model signal with focused Gateway tests.

Question: What actual-runtime-model metadata contract should Gateway expose for non-streaming and streaming OpenAI-compatible HTTP responses?

Rationale: The source gap is clear, but ordinary response headers cannot represent model selection that happens after SSE headers are flushed, so implementation needs maintainer intent on the public API shape.

Likely owner: steipete

Owner confidence: high

Options:

- **Define unified HTTP/SSE metadata (recommended):** Document and implement one actual-model contract for Chat Completions and Responses across non-streaming response metadata and streaming SSE-compatible metadata.
- **Limit the first pass to non-streaming:** Expose actual-model metadata only where it is known before response headers are sent and leave streaming attribution as an explicit follow-up limitation.
- **Defer to broader runtime metadata:** Keep transport response attribution deferred until the broader resolved-model and session-status metadata contract is decided.

## Reproduction Assessment

Yes, from source inspection: current main returns the request-side `model` in Gateway HTTP responses and does not wire the existing actual selected-model signal into HTTP response metadata. No live fallback run was executed in this read-only cleanup review.

## Solution Assessment

No for the literal header-only proposal. The maintainable fix needs a unified response metadata contract that covers body/header/SSE behavior so fallback attribution stays accurate after streaming headers have flushed.
