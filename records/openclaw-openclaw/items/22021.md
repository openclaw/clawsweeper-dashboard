## Summary

Keep open: current main still lacks actual-runtime-model response metadata for the OpenAI-compatible Gateway HTTP endpoints. The handlers still echo the request-side agent model, while the actual selected-model signal remains below the HTTP layer, so the remaining work needs a public HTTP/SSE contract decision.

## What This Changes

Request to add a Gateway HTTP response surface, proposed as `X-Actual-Model`, that exposes the provider/model actually used for each OpenAI-compatible HTTP response.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including SSE semantics, then wire it from the selected-model signal or agent metadata with focused Gateway tests and docs.
