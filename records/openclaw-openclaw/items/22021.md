## Summary

Keep open: current main and the latest release still lack an actual-runtime-model response metadata surface for the Gateway OpenAI-compatible HTTP endpoints, and the remaining work needs a public HTTP/SSE API-contract decision rather than conservative cleanup.

## What This Changes

Request to expose the actual runtime model used by Gateway OpenAI-compatible HTTP requests, proposed as an `X-Actual-Model` response header.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including non-streaming and SSE behavior, then wire it from the existing selected-model signal with focused Gateway tests and live routing-proxy proof.

## Solution Assessment
