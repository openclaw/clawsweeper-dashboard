## Summary

Keep open: current main and v2026.6.11 still lack an actual-runtime-model metadata surface for Gateway OpenAI-compatible HTTP responses. The remaining work is a public Gateway HTTP/SSE API contract decision, because a simple response header cannot cover streaming fallback after SSE headers are flushed.

## What This Changes

Request to add an `X-Actual-Model` HTTP response header so Gateway clients can see which runtime model actually handled each OpenAI-compatible request.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including non-streaming and SSE behavior, then wire it from the existing selected-model signal with focused Gateway tests and live routed-provider proof.
