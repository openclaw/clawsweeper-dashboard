## Summary

Keep open: current main and the latest release still lack actual-runtime-model response metadata for the OpenAI-compatible Gateway HTTP endpoints, and this issue remains the canonical item for choosing the public HTTP/SSE contract.

## What This Changes

Request to expose the actual runtime model used for each OpenAI-compatible Gateway HTTP request, proposed as an `X-Actual-Model` response header.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including non-streaming and SSE behavior, then wire it from the existing selected-model signal with focused Gateway tests and live proxy proof.

## Reproduction Assessment

Yes at source level: current Gateway handlers still emit request-side model values and lack an actual-selected-model response metadata contract. I did not run a live routing-proxy request in this read-only review.

## Solution Assessment

No for the header-only proposal: a plain response header cannot cover late fallback selection after streaming headers flush. The best path is a unified body/header/SSE metadata contract chosen by maintainers.
