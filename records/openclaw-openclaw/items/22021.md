## Summary

Keep open: current main and the latest release still lack an actual-runtime-model response surface for the OpenAI-compatible Gateway HTTP endpoints. The gap is source-reproducible, but the API shape needs maintainer direction because a header-only design cannot cover streaming fallback cases after SSE headers flush.

## What This Changes

Request to expose the model that actually processed each OpenAI-compatible Gateway HTTP request, proposed as an `X-Actual-Model` response header.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including non-streaming and SSE behavior, then wire it from the existing selected-model signal with focused Gateway tests and live routing-proxy proof.

Rationale: The missing behavior is real, but normal response headers cannot reliably represent late fallback selection after SSE headers flush, so implementation needs maintainer intent on the public API shape.

Likely owner: steipete

Owner confidence: high

Options:

- **Define unified HTTP/SSE metadata (recommended):** Document and implement one actual-model contract for Chat Completions and Responses across non-streaming body/header metadata and streaming SSE-compatible metadata.
- **Limit first pass to non-streaming:** Add actual-model response metadata only where it is known before headers are sent, and leave streaming attribution as an explicit follow-up limitation.
- **Defer to broader runtime metadata:** Keep the transport response surface deferred until the overlapping resolved-model/session-status contract is decided.

## Reproduction Assessment

Yes. Source inspection on current main shows no actual-model Gateway response header or documented equivalent, and both OpenAI-compatible handlers still return request-side model values while actual selected-model plumbing remains below the HTTP layer.

## Solution Assessment

No for the header-only proposal. The maintainable solution needs a unified body/header/SSE metadata contract so fallback attribution remains accurate after streaming headers have flushed.
