## Summary

Keep open: current main and the latest release still lack an actual-runtime-model response surface for the OpenAI-compatible Gateway HTTP endpoints, and the remaining work needs a public HTTP/SSE API contract decision rather than conservative cleanup.

## What This Changes

Add a Gateway HTTP response metadata surface that exposes the model that actually served each OpenAI-compatible request.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including non-streaming and SSE behavior, then wire it from the existing selected-model signal with focused Gateway tests and live routing-proxy proof.
