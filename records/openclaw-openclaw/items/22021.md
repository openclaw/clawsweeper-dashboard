## Summary

Keep open: current main and the latest release still lack an actual-runtime-model response surface for Gateway OpenAI-compatible HTTP responses; existing model attribution is internal and the remaining work is a public HTTP/SSE contract decision.

## What This Changes

Request adding `X-Actual-Model` or an equivalent Gateway HTTP response metadata surface that exposes the model that actually processed each request.

## Best Possible Solution

Define one documented actual-selected-model metadata contract across `/v1/chat/completions` and `/v1/responses`, including non-streaming and SSE behavior, then wire it from the existing model-attribution signals with focused Gateway tests.

Rationale: The source gap is clear, but the public API shape is not: normal response headers cannot cover late fallback selection after SSE headers flush, and the choice overlaps existing session/status resolved-model work.

Likely owner: steipete

Owner confidence: high

Options:

- **Define unified HTTP/SSE metadata (recommended):** Document and implement one actual-model contract for Chat Completions and Responses across non-streaming body/header metadata and streaming SSE-compatible metadata.
- **Limit first pass to non-streaming:** Expose actual-model response metadata only when it is known before headers are sent and explicitly leave streaming attribution as a documented follow-up.
- **Defer to resolved-model status work:** Keep HTTP response attribution deferred until the broader resolved backend model and session-status contract in the linked runtime metadata issue is decided.

## Reproduction Assessment

Yes, from source inspection: current Gateway HTTP handlers return the request-side `model` and do not wire existing selected-model or execution-trace signals into HTTP response metadata. I did not run a live fallback/proxy scenario in this read-only review.

## Solution Assessment

No for the literal header-only proposal. The maintainable fix needs a unified body/header/SSE metadata contract so fallback attribution remains accurate after streaming headers have flushed.
