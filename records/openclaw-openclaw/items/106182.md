## Summary

Keep this issue open: current main supports current-turn autonomous review and `/learn` over the active conversation or named sources, but it has no incremental older-session scan. The protected `maintainer` label and assignment also require explicit maintainer handling.

## What This Changes

Add an incremental, cursor-based Skill Workshop flow that scans older eligible sessions and creates pending reusable-skill proposals.

## Best Possible Solution

Add an explicit bounded history-scan service that enumerates eligible foreground sessions in stable reverse order, stores a per-agent cursor in the shared SQLite state database, feeds redacted batches through the existing reviewer and pending-proposal lifecycle, and exposes progress, cost/privacy context, reset behavior, and scan-new/scan-earlier actions in the Workshop UI.

## Risks / Open Questions

- Historical session scanning introduces privacy and provider-cost exposure beyond the current-turn reviewer, so eligibility, explicit consent, batch limits, and visible coverage must be settled before implementation.
- A cursor based only on time may skip or rescan sessions after deletion, import, or timestamp ties; the persisted boundary needs stable ordering and documented reset semantics.
- The issue requires filtering foreground sessions from review, background, and subagent runs; using inconsistent session classification would expose unintended transcripts or generate duplicate proposals.
- The new scan cursor is durable application state and should use the appropriate shared SQLite owner rather than adding another JSON or sidecar state path.
