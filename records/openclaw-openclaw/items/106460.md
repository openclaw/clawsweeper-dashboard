## Summary

Keep this issue open. At the reviewed main SHA, Context Profile presets still feed the complete editable configuration into the shared `config.set` or `config.apply` submission path, so an unrelated redacted SecretRef can reject an otherwise valid three-field profile update; the documented `config.patch` API already provides the correct partial-write boundary.

## What This Changes

Make Control UI Context Profile Apply and Save operations succeed when unrelated configuration fields contain redacted SecretRefs, with clear nearby success or failure feedback.

## Best Possible Solution

Submit Context Profile changes as a `config.patch` containing only the three owned `agents.defaults` fields and the current base hash, then show success or the returned error beside the profile controls; keep generic full-config Save/Apply behavior separate and add a regression fixture containing a redacted structured SecretRef.
