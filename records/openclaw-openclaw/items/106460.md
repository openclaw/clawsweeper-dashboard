## Summary

Current main still stages a Context Profile preset into the complete editable configuration and submits that whole document through `config.set` or `config.apply`. The supported API already provides `config.patch` for partial writes, so this remains a concrete, bounded bug with no viable canonical fix identified.

## What This Changes

Update Context Profiles without resubmitting unrelated concealed SecretRefs, and show clear success or failure beside the profile controls.

## Best Possible Solution

Have Context Profile Apply/Save issue a `config.patch` containing only `agents.defaults.bootstrapMaxChars`, `bootstrapTotalMaxChars`, and `contextInjection` with the current base hash, then reload the snapshot and render an inline success or gateway-error state beside the controls.

## Reproduction Assessment

Yes: configure an unrelated valid SecretRef, select a Context Profile, and invoke Apply or Save. The reported INVALID_REQUEST logs align with the current-main full-document submission path, although this review did not execute a fresh live main run.

## Solution Assessment

No—the current full-document `config.set`/`config.apply` path is not the best solution for a three-field preset. The existing `config.patch` contract is narrower, safer for concealed secrets, and easier to regression-test.
