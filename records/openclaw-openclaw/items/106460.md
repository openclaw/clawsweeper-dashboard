## Summary

Keep this issue open: current main still stages the Context Profile preset into the complete loaded configuration and submits that full document, allowing an unrelated redacted SecretRef to reject the three-field profile update; no merged fix or viable canonical PR currently owns the regression.

## What This Changes

Make Control UI Context Profile updates succeed without resubmitting concealed SecretRef values and show profile-specific save failures inline.

## Best Possible Solution

Have the Context Profile controls send a base-hash-guarded config.patch containing only the three profile fields, preserve all unrelated SecretRefs server-side, display the returned error beside the controls, and add regression coverage using a config snapshot with a redacted SecretRef.
