## Summary

Keep this issue open: the report maps to a current Control UI path that submits the complete redacted config for a three-field Context Profile change, so unrelated SecretRefs can reject the operation before any profile value is saved. No merged fix or canonical open PR currently owns this focused regression.

## What This Changes

Make Control UI Context Profile actions update their three agent-default fields without resubmitting unrelated redacted SecretRefs, and show clear inline success or failure feedback.

## Best Possible Solution

Give Context Profile a dedicated hash-aware `config.patch` operation for its three fields, preserve strict SecretRef validation for genuine credential edits, and render the RPC result beside the profile controls.

## Solution Assessment

Yes—the narrowest maintainable solution is a dedicated partial patch for the profile fields plus local result feedback, rather than weakening SecretRef validation or teaching every credential path to tolerate unrelated whole-config submissions.
