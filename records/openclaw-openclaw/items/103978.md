## Summary

Keep this issue open: current main still exposes and copies plugin-supplied approval caller IDs, while verified Gateway connection identity remains a separate internal seam. The linked draft fix is not a safe replacement because maintainer review rejects routing derived from raw node invocation input, and the protected, assigned issue requires an explicit security and compatibility decision.

## What This Changes

Replace plugin-supplied approval caller IDs with a documented, read-only authenticated Gateway caller-context contract.

## Best Possible Solution

Add one immutable discriminated caller-context value populated only from verified Gateway connection and turn provenance, represent absent or unverified context explicitly, migrate bundled consumers, document the external SDK transition, and remove request-supplied routing identity after a bounded deprecation window without retaining a runtime fallback.
