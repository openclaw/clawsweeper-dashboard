## Summary

Keep this PR open: the force-pushed head resolves the prior provider-policy blocker and the narrow replay-seam placement appears correct, but the supplied helper-only transcript does not prove that a real interrupted session successfully resumes through the Gateway/provider path.

## What This Changes

The PR conditionally repairs orphaned tool-call/result pairs before assigning rebuilt session context to provider-bound agent state at two replay points.

## Best Possible Solution

Keep repair at the provider-bound replay seam, add focused coverage proving enabled, disabled, orphaned, and already-paired behavior at the actual assignment path, and land it only after a real Gateway interruption/resume demonstrates a successful provider request.
