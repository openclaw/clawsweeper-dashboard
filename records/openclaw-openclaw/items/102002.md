## Summary

This PR remains necessary: current `main` still reads media-understanding images at the final provider byte cap and normalizes them without the image tool’s model-aware compression policy. The branch appears to address that gap across provider-entry, explicit runtime, and CLI fallback paths, and the prior local source-cap finding appears addressed, but it is currently dirty against `main` and still lacks after-fix real-provider behavior proof.

## What This Changes

The PR reuses the image tool’s model-aware compression policy so configured attachment descriptions, explicit image descriptions, and CLI image-description fallbacks can downscale oversized images before provider execution.

## System Context

Media-understanding receives image attachments from channel workflows and file/CLI calls, obtains their bytes, normalizes formats, then sends them to the selected vision provider. This change inserts model-aware compression before that provider request while retaining the final provider byte limit and skipped-attachment behavior.
