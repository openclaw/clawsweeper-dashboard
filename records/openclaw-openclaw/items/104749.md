## Summary

Keep this PR open for a focused repair: the floating multi-turn panel is a strong solution direction, but the current head has two reproducible paths that lose side-chat state. The protected `maintainer` label also requires explicit maintainer handling rather than cleanup closure.

## What This Changes

This PR replaces the Control UI’s inline `/btw` result card with a floating multi-turn side-chat panel supporting accumulated turns, follow-up questions, hide/clear actions, responsive layout, and updated documentation and tests.

## Best Possible Solution

Use one explicit acceptance contract for side-chat follow-ups: retain input until every pre-send gate accepts it, and disable submission while a side turn is pending unless the product deliberately implements visible queue or abort-and-replace semantics.

## Maintainer Decision

## Reproduction Assessment

Yes at source level. A pending side turn still exposes the follow-up input, and the next submission retires the first run; separately, failed picker gating returns before the panel draft-restoration callback runs.

## Solution Assessment

No, not in the current form. The floating multi-turn panel is the narrowest appropriate UI owner, but its follow-up path must preserve drafts across all rejections and respect the existing single-pending-run model.
