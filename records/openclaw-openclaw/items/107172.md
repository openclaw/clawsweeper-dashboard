## Label Justifications

- `P1`: A reproducible Codex/Feishu regression can delay or suppress the expected channel reply for several minutes during an ordinary agent turn.
- `impact:message-loss`: The originating Feishu response can finalize with zero replies while the actual answer is delivered separately or generated only after channel finalization.
- `impact:session-state`: A nested run can resolve to the same active session and become queued behind its own parent turn, mis-associating completion and delivery state.

## Summary

Keep this issue open: current `main` still allows synchronous `sessions_send` to resolve to the originating session and wait for a nested run, while the linked PR addresses only that self-wait guard and explicitly leaves Codex reply accounting, Feishu finalization, and late native-hook handling unresolved. citeturn1view3turn11view0

## What This Changes

Prevent Codex tool-only turns from synchronously self-targeting their active Feishu session, delaying or losing the visible final reply and triggering the `Done.` fallback.

## Best Possible Solution

Land a focused resolved-session self-target guard, then preserve Codex turn and native-hook state through final assistant-output accounting so Feishu emits exactly one timely visible answer and never substitutes `Done.` for a still-pending or already tool-delivered result.
