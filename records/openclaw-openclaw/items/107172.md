## Label Justifications

- `P1`: A released optional runtime can stall an active channel turn for minutes and fail to place the generated answer in the originating Feishu reply.
- `impact:message-loss`: The expected answer is omitted from the originating Feishu response and replaced by fallback text, while the nested result arrives too late or through a separate delivery path.
- `impact:session-state`: A nested synchronous request can resolve to and wait behind the same active session that initiated it, creating a self-dependency in the session lane.

## Summary

Keep this issue open. Current `main` still allows a synchronous `sessions_send` target to resolve to the originating active session and then starts and waits for the nested run, so the reported self-wait remains possible. The linked open PR addresses that guard but explicitly leaves Codex tool-delivery accounting, Feishu finalization, and late native-hook lifecycle handling unresolved.

## What This Changes

Prevent Codex tool-only turns from synchronously sending to their own active Feishu session, stalling the session lane and producing an empty-reply fallback instead of the expected answer.

## Best Possible Solution

Land or supersede the linked post-resolution self-target guard, then keep this issue as the canonical integration track until Codex tool-delivered output is reflected in parent reply accounting, Feishu finalizes deliberate tool-delivered completions without an unrelated fallback, and relay teardown waits for all turn-related native-hook activity; validate the complete behavior with a fresh real Feishu session.
