## What This Changes

The PR makes snapshot config materialization inject the same compaction and context-pruning defaults as normal config loading, preventing prepared runtime lookup from comparing unequal runtime configs.

## System Context

OpenClaw materializes user configuration for both gateway-startup snapshots and reply-time loading. Those materialized configs feed prepared model-runtime ownership lookup, which requires the startup and reply paths to agree exactly before an agent can answer a message.

## Best Possible Solution

Preserve one shared full materialization profile for startup and reply-time configs, retain raw user configuration for writes, and add redacted after-fix gateway evidence showing an omitted-mode configuration can answer after a restart.
