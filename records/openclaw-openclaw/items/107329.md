## Summary

Keep this PR open, but do not merge it yet: the reported QMD path bug is credible, while the prior blocking finding remains because unresolved search results still trigger synchronous filesystem discovery in the request hot path; the indexed-read authorization change also needs explicit owner approval and native-QMD proof.

## What This Changes

The PR checks QMD result paths, recovers a unique slug-equivalent file by searching the collection filesystem, permits that recovered file in indexed reads, and adds recovery, missing-file, and ambiguity tests.

## Best Possible Solution

Resolve slug aliases from authoritative QMD records during indexing or collection refresh into a bounded prepared mapping, keep request-time reads exact against that mapping, and validate the complete native-QMD search-to-read roundtrip plus collision, symlink, and large-collection behavior.
