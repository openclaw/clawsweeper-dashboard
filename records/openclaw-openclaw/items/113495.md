## Summary

Keep this PR open, but do not merge it as written. It fixes a real policy-propagation gap for the configured endpoint, yet it also lets that endpoint’s private-network permission apply when a separate runtime remote endpoint overrides the base URL; that widens an SSRF exception beyond the host the configuration describes. The branch also still needs inspectable after-fix runtime proof rather than claimed trace text alone.

## What This Changes

The PR passes the existing `models.providers["openai-compatible"].request.allowPrivateNetwork` opt-in into OpenAI-compatible embedding requests and adds SSRF-policy propagation and localhost-redirect tests.

## System Context

The OpenAI-compatible embedding adapter builds an outbound client from provider configuration and optional runtime remote overrides. That client passes requests through the shared SSRF guard, which decides whether redirect targets may reach private-network addresses.

## Architecture Diagram

flowchart LR

  C --> D[Client and SSRF policy]

## Best Possible Solution

Scope `allowPrivateNetwork` to the effective endpoint: do not inherit the configured provider’s private-network exception when a runtime remote base URL replaces that provider endpoint, unless the remote override has its own explicit documented policy source; add focused override coverage and real after-fix proof.
