## Summary

Keep this PR open for a focused maintainer security-boundary decision. The implementation follows the shared request/transport SSRF policy path and has credible after-fix container proof, but it deliberately lets a provider-level private-network grant remain effective when a caller supplies a different remote base URL; that authorization scope needs explicit approval before merge.

## What This Changes

The branch routes OpenAI-compatible embedding requests through the shared provider request and transport SSRF policy resolvers so the existing `request.allowPrivateNetwork` setting is honored.

## System Context

OpenClaw’s memory index asks an embedding provider to turn workspace and session text into vectors. The OpenAI-compatible adapter builds the outbound HTTP client, where provider request settings become SSRF restrictions before traffic reaches an embedding endpoint.

## Best Possible Solution

Explicitly define whether provider-level `request.allowPrivateNetwork` is a broad transport permission for remote overrides; merge this canonical-resolver implementation if it is, otherwise scope the permission to the effective endpoint through a named remote-level contract.
