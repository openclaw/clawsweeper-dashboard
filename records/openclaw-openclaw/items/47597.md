- `impact:security`: The requested live child progress stream could expose sensitive child tool arguments, outputs, paths, or reasoning across session/channel boundaries.

## Summary

Keep open: current main and the latest release still treat `streamTo` as ACP-only, while native subagent runs only register completion delivery. The remaining request is real, but it needs maintainer/security design for what child progress may cross session and channel boundaries.

## What This Changes

The issue asks for `sessions_spawn` to support `streamTo: "parent"` with `runtime: "subagent"` so parent sessions receive live child progress instead of only the final result.

## Best Possible Solution

Define a maintainer-approved native subagent progress contract, likely as opt-in `streamTo: "parent"`, with bounded redacted system-event delivery and completion-only behavior preserved by default.

Rationale: Current code and docs intentionally keep native subagents completion-only, and exposing live child progress crosses session, channel, and potentially sensitive tool-output boundaries.

Likely owner: dutifulbob

Owner confidence: medium

Options:

- **Design opt-in native relay (recommended):** Add native `streamTo: "parent"` only after defining redaction, truncation, verbosity inheritance, routing, cleanup, and tests for both quiet and verbose paths.
- **Keep ACP-only streaming:** Leave native subagents completion-only and document ACP as the supported live-progress runtime for now.
- **Split minimal wait indicator:** Implement only a safe parent waiting/progress heartbeat first, and track full child tool/output streaming as a separate security-reviewed feature.

Not applicable as a strict bug repro, but source inspection gives high confidence in the current behavior: native subagent spawns ignore `streamTo` and rely on completion delivery only.

## Solution Assessment

Unclear until maintainers choose the visibility contract. A direct heartbeat or event relay is plausible, but the best fix must first define redaction, verbosity, routing, and cleanup behavior.
