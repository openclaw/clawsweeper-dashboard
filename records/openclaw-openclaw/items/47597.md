## Summary

Keep open: current main still treats `streamTo="parent"` as ACP-only and does not implement live native subagent parent progress streaming; the remaining work needs maintainer security/product direction before an implementation PR is safe.

## What This Changes

Request support for `streamTo="parent"` or equivalent real-time parent progress updates when `sessions_spawn` uses native `runtime="subagent"`.

## Best Possible Solution

Define a bounded native subagent parent-progress relay with explicit visibility, redaction, requester routing, cleanup, timeout behavior, tests, and docs before exposing it through `streamTo="parent"`.

Rationale: Current code safely ignores the ACP-only field, but live native progress changes what isolated child-session data becomes visible to parent users and channel surfaces.

Owner confidence: medium

Options:

- **Design Redacted Native Progress (recommended):** Expose bounded lifecycle/progress summaries first, with requester routing, cleanup, timeout, and redaction tests before any tool-result or thinking visibility.
- **Keep ACP-Only StreamTo:** Document `streamTo` as permanently ACP-only and leave native subagents on completion events plus `subagents` inspection.
- **Build Structured Child Event Stream:** Create a broader native child event subscription surface, accepting a larger design covering tool output, thinking visibility, and channel limits.

## Solution Assessment

Unclear until maintainers choose the visibility contract; simply removing the ACP-only gate or adding a heartbeat is not the best safe fix without redaction, routing, and cleanup rules.
