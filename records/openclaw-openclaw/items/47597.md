## Label Justifications

- `P2`: The issue requests a normal-priority core runtime capability improvement with real UX impact but no current unusable-runtime or data-loss emergency.
- `impact:security`: Relaying native child progress to a parent can expose sensitive tool arguments, results, command output, paths, approvals, or reasoning-like content across boundaries.
- `impact:ux-friction`: Native subagent waits can leave parent surfaces silent until completion, creating avoidable confusion for long-running delegation workflows.

## Summary

Keep open: current `main` and `v2026.6.11` only ignore ACP-only `streamTo` on native/default subagent calls; they still do not provide native parent progress streaming. The remaining work needs maintainer/security design for what child progress can cross session and channel boundaries.

## What This Changes

Request support for `streamTo="parent"` on native `runtime="subagent"` spawns so parent sessions can receive live progress instead of only final completion delivery.

## Best Possible Solution

Keep this as the canonical native subagent parent-stream design tracker, then implement a bounded, redacted progress relay only after maintainers choose the visibility, routing, and security contract.
