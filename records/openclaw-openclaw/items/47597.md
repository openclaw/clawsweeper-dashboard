## Label Justifications

- `P2`: This is a normal-priority core runtime UX/security design request with source-confirmed missing behavior but no current hard failure on main.
- `impact:security`: The requested parent stream could expose child tool calls, command output, paths, approvals, patches, or reasoning unless a redaction policy is defined.
- `impact:ux-friction`: Long native subagent runs can leave the parent surface silent until final completion, which adds avoidable confusion without fully blocking progress.

## Summary

Keep open: current main no longer errors on `streamTo="parent"` for native subagent spawns, but it still strips/ignores the field and does not implement live native child progress streaming; the remaining work needs a maintainer-approved security and product contract before implementation.

## What This Changes

The issue requests live parent-session progress streaming for `sessions_spawn({ runtime: "subagent", streamTo: "parent" })`.

## Best Possible Solution

Define a native subagent progress contract that reuses existing delivery/progress rendering, redacts and truncates sensitive child output, honors parent visibility settings, and only then wire `streamTo="parent"` or a clearer option into `spawnSubagentDirect`.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should native subagent runs expose parent-session progress streaming, and what child-output visibility/redaction contract should that stream use?

Rationale: The code path is clear enough to implement, but choosing raw streaming, heartbeat-only status, or no native stream changes security boundaries and user-visible agent behavior.

Likely owner: vincentkoc

Owner reason: This person authored the current tolerant sessions_spawn behavior that any product/security direction would need to preserve or replace.

Owner confidence: medium

Options:

- **Design redacted native progress first (recommended):** Add an explicit bounded progress contract for native subagents before exposing any child tool output, then implement `streamTo="parent"` against that contract.
- **Keep completion-only native subagents:** Leave native subagents as final-completion only and document ACP as the runtime for live parent streaming.
- **Mirror ACP streaming broadly:** Expose child assistant/progress output to the parent with ACP-like behavior, accepting the higher leakage and routing-review burden.

## Reproduction Assessment

Yes, at source level: current main only materializes `streamTo` for ACP, strips it before native `spawnSubagentDirect`, and tests assert native subagent spawns ignore it. I did not run a live gateway scenario in this read-only pass.

## Solution Assessment

No, not as a direct ACP parity port. The maintainable solution is an explicit native progress/redaction contract first, then a bounded implementation in the sessions_spawn and subagent runtime paths.
