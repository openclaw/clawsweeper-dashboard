- `P2`: This has clear user value for long native subagent runs, but it is a normal-priority feature/design item rather than an outage, data-loss issue, or crash-loop emergency.
- `impact:security`: Parent-visible native child progress can expose sensitive tool arguments, outputs, file paths, command data, or reasoning-like content across session and channel boundaries.
- `impact:ux-friction`: Long native subagent runs can leave the parent session looking idle until completion, which creates avoidable confusion even when final delivery eventually works.

## Summary

Keep open: current main fixes the old hard-failure facet by ignoring ACP-only `streamTo` on native/default subagent calls, but it still does not implement native `runtime="subagent"` parent progress streaming. This remains a product and security-sensitive core agent/runtime design item, not a closeable stale report.

## What This Changes

Request to add `sessions_spawn` `streamTo="parent"` support for `runtime="subagent"` so parent sessions receive real-time child progress instead of completion-only updates.

## Best Possible Solution

Keep this as the canonical native subagent parent-stream design tracker, then implement only after maintainers approve the visibility, redaction, routing, cleanup, and test contract.

## Reproduction Assessment

Yes, at source level: current main only materializes `streamTo` for ACP, tests assert native/default subagent calls drop it, and docs tell users to omit it for native spawns. I did not run a live long-running subagent session in this read-only review.

## Solution Assessment

No implementation path is approved yet. The best fix is not simply passing `streamTo` into `spawnSubagentDirect`; it needs a native progress event contract with conservative visibility, routing, cleanup, and security boundaries.
