- `P2`: This is a valid but bounded feature request for long-running subagent UX, with no evidence of a current core runtime outage.
- `impact:security`: The request changes what a parent session can observe from an isolated child run, including potentially sensitive progress, tool, or reasoning content.

## Summary

Keep open: current main and v2026.6.11 still treat `streamTo="parent"` as ACP-only and deliberately ignore it for native `runtime="subagent"`; the hard-error path was fixed separately, but the requested live parent progress stream remains a product/security design decision.

## What This Changes

Request to add live `streamTo="parent"` progress streaming for `sessions_spawn` when using native `runtime="subagent"`.

## Best Possible Solution

Define a parent-only native subagent progress contract with redacted lifecycle or assistant progress, routing tests, and docs, while keeping the current ACP-only `streamTo` behavior until that policy is approved.

Rationale: The implementation is not a mechanical guard removal: it changes child-session visibility and channel delivery semantics, and current docs/tests intentionally keep `streamTo` ACP-only for native subagents.

Options:

- **Approve bounded native stream (recommended):** Add a parent-only native subagent relay for sanitized lifecycle or assistant-progress updates, with tests proving redaction, routing, cleanup, and no raw tool/thinking leakage by default.
- **Keep ACP-only streamTo:** Leave native subagents on final announce plus `sessions_history` and document ACP or thread-bound sessions as the live-progress path.
- **Defer to parent-send design:** Treat this as blocked on the broader parent-scoped send/progress contract in https://github.com/openclaw/openclaw/issues/18967.

## Reproduction Assessment

Yes at source level: current main strips `streamTo` for native subagent spawns and tests assert that ignore behavior. I did not run a live subagent session, so this is source-reproducible rather than runtime-reproduced.

## Solution Assessment

Unclear: enabling live parent progress is useful, but simply removing the ACP-only gate is not the best fix without a native parent-only routing, redaction, and cleanup contract. The safer direction is a bounded native relay or a parent-scoped progress/send design approved by maintainers.
