- `impact:security`: The requested stream would decide what child-session progress, tool data, and potentially sensitive output may cross into parent-visible surfaces.

## Summary

Keep open: current main and v2026.6.11 still treat `streamTo="parent"` as ACP-only and native subagents only return completion handoffs, so the requested live parent progress stream remains unimplemented and needs a maintainer-approved security/routing contract.

## What This Changes

Request support for `streamTo="parent"` on native `sessions_spawn` calls with `runtime="subagent"` so long-running child work can surface progress to the parent session.

## Best Possible Solution

Design a bounded native subagent parent-progress relay with explicit redaction, visibility levels, requester-session routing, cleanup, timeout handling, tests, and docs before exposing it through `streamTo="parent"`.

Rationale: Current code can safely ignore the ACP-only field, but implementing live native progress changes what isolated child-session data becomes visible to parent users and channels, which is a product and security boundary choice.

Owner confidence: medium

Options:

- **Design redacted native progress relay (recommended):** Add native parent progress only for bounded lifecycle/progress summaries first, with requester routing, cleanup, and redaction tests before any tool-result or thinking visibility.
- **Keep ACP-only streamTo:** Document `streamTo` as permanently ACP-only and leave native subagents on completion events plus `/subagents` inspection.
- **Expose structured child event stream:** Build a broader child-event subscription surface for native subagents, but require a larger design covering tool output, thinking visibility, and channel delivery limits.

## Solution Assessment

Unclear until maintainers choose the security boundary. The issue's heartbeat idea is plausible, but the durable fix should be a reviewed native progress contract rather than only removing the ACP-only restriction.
