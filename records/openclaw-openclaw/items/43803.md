## What This Changes

The issue asks for `config.patch` to skip SIGUSR1 gateway restarts when all changed paths are hot-reloadable browser profile config paths.

## Best Possible Solution

Review and either land or explicitly reject https://github.com/openclaw/openclaw/pull/93827, keeping `browser.profiles.*` hot-reloadable while preserving restart behavior for service-level browser settings such as `browser.enabled` and `browser.defaultProfile`.

## Reproduction Assessment

Yes, at source level: current `main` maps `browser.profiles.*` through the broad `browser` restart prefix, and the hot-mode config write path schedules SIGUSR1 when that reload plan requires a gateway restart. I did not run a live foreground gateway crash repro in this read-only review.

## Solution Assessment

Yes. The narrow maintainable solution is plugin-owned browser profile reload metadata plus planner/config.patch regression coverage while preserving broader browser restart behavior; the active closing PR already owns that path.
