## What This Changes

The issue requests that `config.patch` skip SIGUSR1 restarts when changed paths such as `browser.profiles.*` are hot-reloadable.

## Best Possible Solution

Review and either land or explicitly reject https://github.com/openclaw/openclaw/pull/93827, preserving service-level browser restarts while making `browser.profiles.*` hot-reloadable with config.patch coverage.

## Reproduction Assessment

Yes, at source level: current main maps `browser.profiles.*` through the broad `browser` restart prefix, and the hot-mode config write path schedules SIGUSR1 when that plan requires a gateway restart. I did not run a live foreground gateway crash repro in this read-only pass.

## Solution Assessment

Yes, the narrow maintainable direction is to classify `browser.profiles.*` as hot while preserving restart classification for service-level browser settings. The open closing PR already attempts that path, so this issue should stay open until that PR merges or maintainers reject it.
