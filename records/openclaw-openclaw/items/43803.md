## Summary

Keep open: current main still restart-scopes browser plugin config through the broad `browser` prefix, so browser profile config paths can still drive the restart path; the open closing PR is the active implementation candidate and should be reviewed before this issue closes.

## What This Changes

The issue reports that `config.patch` changes to hot-reloadable browser profile paths still schedule a gateway SIGUSR1 restart and disrupt gateway/session state.

## Best Possible Solution

Review and either land or close the open browser hot-reload PR; the desired end state is for `browser.profiles.<name>.*` changes to hot-reload without a SIGUSR1 while service-level browser config remains restart-scoped.

## Reproduction Assessment

Yes. Source inspection shows current main still maps the browser plugin's broad `browser` restart prefix into `restartGateway: true`, and the config write flow can schedule SIGUSR1 from that plan in hot mode; I did not run a live gateway repro in this read-only review.

## Solution Assessment

Yes. The best fix is a narrow reload-classification change that makes `browser.profiles.<name>.*` hot reloadable while preserving restart behavior for broader browser service settings; the open closing PR is the right implementation path to review.
