## What This Changes

The issue reports that `config.patch` still schedules a SIGUSR1 restart for hot-reloadable browser profile paths such as `browser.profiles.*`, disrupting gateway/session state.

## Best Possible Solution

Review and land or replace https://github.com/openclaw/openclaw/pull/93827 so `browser.profiles.*` changes classify as hot while service-level browser settings that require restart remain restart-scoped.

## Solution Assessment
