## What This Changes

This PR gives unnamed managed worktrees readable session-derived or crustacean-themed names, adds collision allocation, and documents the resulting branch and checkout naming behavior.

## System Context

Managed worktrees create an isolated Git checkout and `openclaw/&lt;name>` branch for a session or API caller. The gateway supplies the creation request, the worktree service allocates a name and checkout, and the resulting path is persisted back onto the session.

## Architecture Diagram

flowchart LR
  A[Session or API request] --> B[Gateway session creation]
  B --> C[Choose explicit or inferred name]
  C --> D[Managed worktree allocation]
  D --> E[Git branch and checkout]
  E --> F[Session worktree record]

## Best Possible Solution

Keep arbitrary session-message content out of Git branch and filesystem names by using an explicit user-provided worktree label for semantic names and the readable crustacean fallback otherwise; then provide a redacted end-to-end creation and collision proof before merge.
