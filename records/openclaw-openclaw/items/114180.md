## Label Justifications

- `P1`: Under the default tree-visibility workflow, one session tool returns a parent-owned child key while another deterministically denies retrieving that child’s history.
- `impact:session-state`: The issue affects durable child-session lineage and retrieval of an agent’s historical session transcript.

## Summary

This is a concrete default-tree-visibility bug, and an open pull request explicitly targets it with reported real Gateway proof. Keep this issue open until that pull request is reviewed and merged; its sibling direct-action scope should not block the narrow history repair.

## What This Changes

Make `sessions_history` honor durable child-session lineage when `sessions_list` already exposes that child under tree visibility, regardless of display-recency expiry.

## System Context

OpenClaw session tools read durable Gateway session rows and transcripts on an agent’s behalf. Session listing evaluates row lineage for visibility, while direct history access currently uses a child-session lookup that can be filtered by display recency before it authorizes transcript retrieval.
