## Summary

Keep this issue open: the selected-text mouse-copy regression remains necessary to fix and is distinct from the completed right-click Reply capability. Current source evidence shows the custom message-bubble interaction owns the context-menu path without a selection-aware native-menu escape, while the merged Reply work and its proof cover reply behavior rather than native Copy/Search access.

## What This Changes

Restore mouse access to native browser selection actions in Control UI chat without removing the message Reply context menu.

## Best Possible Solution

When a non-collapsed browser selection intersects a rendered chat message, leave the context-menu event untouched so the native menu opens; otherwise preserve the existing custom Reply menu, with focused coverage for both paths and no new setting or config surface.

## Reproduction Assessment

Yes from source, but not as a live browser run: highlight text in a reply-enabled message and right-click; the custom bubble handler owns the event without a selection-aware native-menu path. The report provides concrete Chrome steps, and current source explains the deterministic result.

## Solution Assessment

Yes—the narrowest maintainable fix is to defer to the browser only for an active selection inside a chat message while retaining the custom Reply menu elsewhere. Adding a setting would create unnecessary configuration surface, and a custom Copy-only item would still omit native Search and accessibility integrations.
