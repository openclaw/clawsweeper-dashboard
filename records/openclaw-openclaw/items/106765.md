## Summary

Keep this issue open: current main still suppresses the browser menu for every reply-enabled chat bubble, so the reported mouse-copy accessibility regression remains and is distinct from the completed right-click Reply feature. citeturn538300view0turn833058view0

## What This Changes

Restore mouse-accessible copy, search, and related native context-menu actions when text is selected in Control UI chat messages.

## Best Possible Solution

Before suppressing `contextmenu`, detect a non-collapsed selection within the clicked chat bubble and preserve the native browser menu; retain the custom Reply menu only when no message-text selection is active, with regression coverage for both paths.

## Solution Assessment

Yes—the narrowest maintainable fix is to preserve the native browser menu only for a real selection inside the clicked message, rather than adding another setting or duplicating browser copy/search functionality in the custom menu.
