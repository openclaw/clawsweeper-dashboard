## Summary

Keep open: current main and the latest release still short-circuit non-template literal `session.store` paths, so this PR remains the live fix candidate for https://github.com/openclaw/openclaw/issues/54435. The blocker is that the proposed fix changes explicit literal agent-layout paths from single-file scope to sibling-agent discovery, which needs a maintainer compatibility decision before merge.

## What This Changes

The PR changes Gateway combined session-store loading and target discovery so literal `agents/<id>/sessions/sessions.json` store paths can enumerate sibling agent stores while true shared literal stores remain single-store.

## Best Possible Solution

Land a refreshed fix only after maintainers choose and document the literal agent-layout upgrade policy, preserving single-file isolation by default unless widened discovery is explicitly accepted and covered by regression tests.

## Reproduction Assessment

Yes, at source/proof level: current main returns from the single-store branch for any non-template literal `session.store`, and the linked comparison artifact shows `sessions.list` count 1 before and 2 after for a literal `agents/main` path. I did not run a fresh local live Gateway repro in this read-only review.

## Solution Assessment

No, not as-is. The branch fixes the under-count, but it reinterprets an explicit config path and needs a maintainer-approved upgrade policy or isolation-preserving default before it is the best fix.
