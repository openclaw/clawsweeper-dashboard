## Summary

Keep this PR open: the stateful decoding approach fixes the reported split-byte corruption at the correct ownership boundary, but the app-server client decoder lifecycle is incomplete and the external contribution still lacks real Codex sandbox behavior proof.

## What This Changes

The PR replaces per-chunk UTF-8 conversion with stateful decoding in the Codex sandbox HTTP output and app-server stderr paths, adding split-byte lifecycle regression tests.

## Best Possible Solution

Use one `StringDecoder` per byte stream, finalize every decoder exactly once when its stream ends before constructing final diagnostics, add focused client coverage for terminal flushing, and demonstrate the result through a real Codex sandbox/app-server run.

Yes from source inspection: converting each Buffer independently necessarily corrupts a multibyte code point divided between data events, and the added focused tests exercise that exact boundary. A real current-main Codex sandbox reproduction was not provided.

## Solution Assessment

No, not yet: incremental decoding is the narrow root-cause solution, but the client-side decoder must also be finalized at stream termination so buffered terminal bytes are not silently discarded.
