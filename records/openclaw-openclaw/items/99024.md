## Summary

Keep open: the CSP hardening goal is useful, but this patch removes the WebSocket allowance that current documented/configurable `gatewayUrl` flows still rely on, and the PR still has no after-fix browser CSP proof.

## What This Changes

This PR replaces the Control UI CSP `connect-src` bare `ws:`/`wss:` sources with an explicit Google Live WebSocket host and updates the CSP unit test.

## Best Possible Solution

Land CSP tightening only after preserving or explicitly deprecating configurable Gateway WebSocket targets, updating docs/tests for that decision, and adding real browser CSP/network proof.

## Reproduction Assessment

Yes from source: the PR's CSP no longer allows configured `ws://` or `wss://` Gateway URLs, while current docs/tests and settings code still support those targets. I did not run a browser session, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

No as-is: explicit provider endpoints are a good direction, but the patch assumes only same-origin Gateway sockets and leaves the documented configurable `gatewayUrl` contract broken. The safer path is to preserve or deliberately retire that contract with maintainer approval and browser proof.
