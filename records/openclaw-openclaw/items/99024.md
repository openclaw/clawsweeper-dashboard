## Summary

Keep open: the hardening direction is useful, but the PR still misses existing localStorage-only remote Gateway upgrades and makes connect-src depend on request/cookie state. The latest head also has concrete lint failures.

## What This Changes

The PR tightens the Gateway-served Control UI CSP connect-src policy by replacing bare WebSocket schemes with explicit endpoints and request/cookie-derived remote Gateway origins.

## Best Possible Solution

Land the CSP hardening only with a maintainer-approved remote-Gateway source contract that preserves or deliberately migrates existing saved settings, avoids unintended route/query/cookie state, and includes browser CSP/network proof.

## Reproduction Assessment

Yes, source-reproducible: current docs and UI code store gatewayUrl in localStorage and strip it from the URL, while the PR only gives the server query/cookie visibility for new loads. Existing saved remote Gateway users can therefore reload with no CSP source for their WebSocket origin.

## Solution Assessment

No as-is: tightening connect-src is the right direction, but the proposed query/cookie source contract misses existing saved settings and trusts caller-controlled state. A maintainer-approved server-visible allowlist or migration model is the safer fix.
