## Summary

## What This Changes

The PR removes bare `ws:`/`wss:` from Control UI CSP `connect-src`, adds Google Live and query-derived Gateway origins, and updates Gateway CSP tests.

## Best Possible Solution

Land the hardening only with a durable, tested remote-Gateway CSP model that preserves saved `gatewayUrl` reloads, or with an explicit maintainer-approved contract change plus docs, tests, and browser proof.

## Reproduction Assessment

Yes, source-reproducible: current UI code stores `gatewayUrl` in localStorage and removes it from the URL, while the PR only adds CSP sources from the request query. I did not run a live browser session, so this is source proof rather than live reproduction.

## Solution Assessment

No as-is: query-derived CSP sources are a reasonable first-load mitigation, but they are not durable for saved remote Gateway reloads. The safer fix needs a maintainer-approved allowlist or compatibility plan plus browser diagnostics.
