## What This Changes

The PR tightens the Control UI CSP connect-src directive by removing bare ws:/wss:, adding explicit provider endpoints, and allowing request/cookie-derived remote Gateway origins.

## Best Possible Solution

Land the CSP hardening only with a server-owned remote-Gateway source contract that preserves or deliberately migrates existing saved gatewayUrl users, does not trust arbitrary route/query/cookie state, and includes real browser CSP/network proof.

## Reproduction Assessment

Yes, source-reproducible: current docs and UI code store gatewayUrl in localStorage and remove it from the URL, while the PR can only add a saved remote origin from the request query or the new cookie. Existing localStorage-only users therefore have no server-visible source to add to CSP after upgrade.

## Solution Assessment

No as-is: tightening connect-src is the right direction, but the current implementation relies on caller-controlled request/cookie state and misses existing saved settings. A maintainer-approved server-visible remote-Gateway contract is the safer fix.
