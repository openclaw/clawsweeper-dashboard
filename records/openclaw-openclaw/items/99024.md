## Summary

Keep this PR open, but it is not merge-ready: removing bare `ws:`/`wss:` is the right security direction, while the current query/cookie-derived dynamic origin model still needs maintainer security approval and stronger proof of an actual cross-origin Gateway WebSocket path.

## What This Changes

The PR tightens Control UI CSP `connect-src` and adds dynamic remote Gateway origin persistence through query parameters, a `gateway-url` cookie, and UI reload handoffs.

## Best Possible Solution

Land a hardened CSP that removes blanket WebSocket schemes while preserving remote Gateway support through a maintainer-approved, server-owned origin authority and tested upgrade path.

## Reproduction Assessment

Yes by source inspection: current main emits bare `ws:` and `wss:` in Control UI `connect-src`. I did not run a live browser exploit path, so this is source-reproducible rather than locally reproduced.

## Solution Assessment

No. Removing blanket WebSocket scheme sources is the right direction, but this implementation makes client-controlled state the authority for additional CSP origins; a server-owned or explicitly approved origin model is safer.
