## Summary

Keep open: the CSP hardening direction is valid, but the branch still lets browser-controlled query/cookie state expand `connect-src`, so maintainer security review and stronger final-scenario proof are needed before merge.

## What This Changes

The branch removes bare `ws:`/`wss:` from Control UI CSP `connect-src`, adds explicit provider endpoints, and adds query/cookie/reload handling plus tests for remote `gatewayUrl` origins.

## Best Possible Solution

Land a server-owned or explicitly maintainer-approved dynamic `connect-src` contract that preserves documented remote `gatewayUrl` usage without letting arbitrary browser URL/cookie state become CSP origin authority.

## Reproduction Assessment

Yes. Current `main` and `v2026.6.11` both show bare `ws:`/`wss:` in Control UI `connect-src`; I did not run a live browser exploit path in this read-only review.

## Solution Assessment

No, not as currently proposed. Removing blanket WebSocket schemes is the right direction, but making CSP origin authority depend on query params and a script-writable cookie is not the narrowest maintainable security fix.
