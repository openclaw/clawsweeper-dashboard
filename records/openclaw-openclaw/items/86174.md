## Summary

Keep open: the latest report still describes a deterministic WebChat routing mismatch on OpenClaw 2026.7.1-2, and the merged child-session work intentionally retained parent runtime-selection inheritance. The remaining question is the product contract for a child whose picker says Default: preserve inheritance and display it, make new sessions independent, or add an explicit child-level default state.

## What This Changes

Fix WebChat child sessions so the displayed model selection agrees with the model actually chosen when a parent session has a persistent model override.

## System Context

Control UI WebChat creates dashboard child sessions through the Gateway and then sends messages against their persisted session state. The model picker projects that state for the user, while reply-time resolution may inherit a parent selection before routing to a provider.

## Best Possible Solution

Define one child-session model contract shared by creation, patching, stored resolution, and the picker: preserve intentional parent inheritance only when the UI identifies it, and provide a deliberate, tested way to select the configured default without it being shadowed by the parent.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For a WebChat child session created from a parent with a user model override, should the product preserve inherited routing and show it, start independently at the configured default, or support an explicit child-level Default that blocks inheritance?

Rationale: Merged work establishes that child sessions intentionally inherit runtime selection, but the current picker semantics make that inheritance invisible and prevent a displayed Default selection from reliably selecting the configured default.

Likely owner: steipete

Owner reason: The available history ties the original inheritance behavior to this contributor's feature work, making them the best evidence-backed routing candidate for the contract decision.

Owner confidence: medium

Options:

- **Show inherited selection and add explicit default (recommended):** Keep the existing child-session inheritance contract, label the effective inherited model in WebChat, and store a distinct child-level default choice when the user explicitly selects Default.
- **Make new dashboard sessions independent:** Stop carrying parent model selection into ordinary New Session creation so a newly displayed Default always resolves from the configured agent default.
- **Keep hidden inheritance unchanged:** Retain current behavior and document that a Default-looking child may route through its parent, accepting the mismatch and user-cost risk.

## Solution Assessment

Unclear: correcting the mismatch is necessary, but the best fix depends on the maintainer decision about whether dashboard child sessions should retain inherited model intent or make Default an explicit non-inheriting choice.
