## Summary

Keep open. The report has a concrete, recent confirmation that an explicit WebChat Default selection can still lose to a parent session’s override; the merged adjacent fixes deliberately did not change that inheritance contract. The remaining work needs a maintainer decision on child-session semantics before a safe compatibility-preserving fix can be selected.

## What This Changes

Fix Control UI WebChat child sessions so the model shown as Default and the provider/model used for the first run cannot diverge because of an inherited parent override.

## System Context

Control UI WebChat creates dashboard child sessions through the gateway and later sends messages through stored-model resolution. The child’s direct model state and parent-session fallback determine the provider/model passed into the agent run.

## Architecture Diagram

## Best Possible Solution

Define one canonical child-session model contract, then align session creation, an explicit Default selection, the picker label, and reply-time stored-model resolution with focused regressions for inherited and non-inherited paths.

## Maintainer Decision

Required: true

Kind: product_direction

Question: When a dashboard child session visibly shows or receives an explicit Default selection, should that selection break parent model-override inheritance, or should the inherited effective model remain visible and controllable in the UI?

Rationale: Either choice changes compatibility-sensitive persisted session behavior; the source-level repair needs a durable user-facing contract rather than another one-sided resolver adjustment.

Likely owner: steipete

Owner reason: Available feature provenance connects this person to the original inheritance behavior.

Owner confidence: medium

Options:

- **Make explicit Default authoritative (recommended):** Persist a child-level default/no-inherit selection so a child displaying Default always routes through the configured effective default.
- **Expose inherited selection:** Keep parent inheritance but show the effective inherited model and provide a separate action to reset the child to its configured default.
- **Make New Session independent:** Do not attach a parent session for the explicit New Session action, reserving parent linkage for rollover-only flows.

## Reproduction Assessment

Yes, at source level: the issue supplies a deterministic parent-override/new-child/Default-send sequence, and a July 24, 2026 report confirms it on 2026.7.1-2. This review did not independently execute the current-main WebChat flow.

## Solution Assessment

Unclear until maintainers choose the child-session contract. Making an explicit Default selection authoritative is the most internally consistent repair, but retaining inheritance with an accurate visible effective selection is also a valid product choice.
