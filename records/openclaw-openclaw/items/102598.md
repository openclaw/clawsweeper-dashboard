## Summary

Keep open: current main and v2026.6.11 still classify periodic usage-limit text as typed `FailoverError.reason = rate_limit`, but the group-visible failure paths rederive rate-limitedness from weaker message patterns, and the protected `maintainer` label prevents cleanup close or automatic repair routing.

## What This Changes

The issue asks OpenClaw to surface periodic weekly/monthly provider usage-limit failures in group chats by honoring typed `FailoverError` reasons in the user-copy failure paths.

## Best Possible Solution

Use typed `FailoverError.reason` for `rate_limit`/`overloaded` classification in both user-copy paths, keep generic group silence only for truly generic failures, and add focused non-direct regression coverage for raw periodic `FailoverError` copy.
