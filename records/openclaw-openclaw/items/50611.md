## Summary

Current main still has the reported non-positive memory-flush threshold path, and the exact same-repository fix attempts are closed unmerged. Keep this open for a maintainer decision on the permanent clamp, warning, validation, or doctor-migration policy.

## What This Changes

The issue reports that `reserveTokensFloor` can equal the active context window, leaving no positive memory-flush threshold so memory flush never triggers.

## Best Possible Solution

Centralize a context-window-aware effective reserve or positive threshold for memory flush and token-based preflight compaction, with focused regression coverage for `reserveTokensFloor >= contextWindowTokens` and documented upgrade behavior for oversized configs.
