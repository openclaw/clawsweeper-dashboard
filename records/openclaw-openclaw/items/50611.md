## Summary

Keep open. Current `main` and latest release still allow `reserveTokensFloor + softThresholdTokens` to make the token-based memory-flush/preflight threshold non-positive, so the reported configuration can still skip the intended flush path.

## What This Changes

The issue reports that token-based memory flush never triggers when `reserveTokensFloor` is equal to the model context window.

## Best Possible Solution

Land a focused maintainer-approved fix that centralizes a context-window-aware positive threshold for memory flush and token-based preflight compaction, with regression coverage for `reserveTokensFloor >= contextWindowTokens` and explicit compatibility behavior.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: with positive token usage and `reserveTokensFloor + softThresholdTokens >= contextWindowTokens`, the shared gate returns `null`, so `shouldRunMemoryFlush` returns false before flushing.

## Solution Assessment

Unclear as final policy. A shared context-window-aware effective threshold is the narrow technical layer, but maintainers still need to choose clamp, warning, validation, and doctor behavior for existing oversized reserve configs.
