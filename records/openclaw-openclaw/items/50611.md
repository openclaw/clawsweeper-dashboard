## Summary

Keep open. Current main and the latest release still let an oversized `reserveTokensFloor` make the token-based memory-flush gate non-positive, and the exact compatibility policy for clamping or warning on existing configs still needs maintainer direction.

## What This Changes

The issue asks OpenClaw to prevent `reserveTokensFloor` values equal to the model context window from disabling memory flush.

## Best Possible Solution

Adopt one context-window-aware effective reserve or positive threshold policy for memory flush and token-based preflight compaction, with regression coverage for equal and greater-than-window reserve values and docs/help kept in sync.
