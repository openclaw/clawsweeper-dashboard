## Summary

Keep open. Current main and the latest release still skip token-based memory flush when the computed threshold is non-positive, and no same-repository fix for this exact reserve-floor edge case has merged.

## What This Changes

The issue reports that `reserveTokensFloor` equal to the context window makes memory-flush thresholding non-positive so pre-compaction memory flush never triggers.

## Best Possible Solution

Keep this issue as the canonical reserve-floor bug until maintainers approve one shared effective reserve or positive-threshold policy for memory flush and preflight compaction, with regression coverage for equal and greater-than-context reserve values.
