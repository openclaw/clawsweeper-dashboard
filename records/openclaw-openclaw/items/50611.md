## Summary

Keep open: current main still has the non-positive memory-flush threshold path, and the remaining fix needs a maintainer choice about clamping versus config validation or doctor migration.

## What This Changes

The issue reports that `reserveTokensFloor` equal to the active context window can make the memory-flush threshold non-positive so token-based flush/preflight never runs.

## Best Possible Solution

Centralize a context-window-aware effective reserve or positive threshold for memory flush and token-based preflight compaction, with focused regression coverage and documented upgrade behavior for oversized configs.
