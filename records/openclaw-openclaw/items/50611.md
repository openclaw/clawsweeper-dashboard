## Summary

Keep open: current main and v2026.6.11 still disable token-based memory flush/preflight when `reserveTokensFloor + softThresholdTokens` makes the computed threshold non-positive, so the reported session-memory bug remains unresolved.

## What This Changes

The issue asks OpenClaw to prevent memory flush from being skipped when `reserveTokensFloor` is equal to or greater than the model context window.

## Best Possible Solution

Land a maintainer-approved centralized positive-threshold policy for memory flush and preflight compaction, with regression coverage for `reserveTokensFloor + softThresholdTokens >= contextWindowTokens` and documented compatibility behavior.

## Reproduction Assessment

Yes. Source inspection shows that with positive token usage and `reserveTokensFloor + softThresholdTokens >= contextWindowTokens`, the shared gate returns `null`, so token-based flush and preflight compaction do not run.

## Solution Assessment

Unclear as final policy. The technical fix belongs in the shared effective threshold/reserve calculation, but maintainers still need to choose clamp, warning, validation, or doctor behavior for existing configs.
