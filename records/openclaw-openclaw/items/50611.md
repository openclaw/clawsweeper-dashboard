## Summary

Keep open. Current main and latest release still allow `reserveTokensFloor + softThresholdTokens` to make the memory-flush gate non-positive, so token-based memory flush/preflight can still skip under the reported configuration.

## What This Changes

The issue reports that `reserveTokensFloor` equal to `contextWindow` prevents memory flush/compaction from triggering because the effective threshold becomes non-positive.

## Best Possible Solution

Land a focused maintainer-approved fix that centralizes a context-window-aware positive threshold for memory flush and token-based preflight compaction, with regression coverage for `reserveTokensFloor >= contextWindowTokens` and documented compatibility behavior.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: with positive token usage and `reserveTokensFloor + softThresholdTokens >= contextWindowTokens`, the shared gate returns `null`, so `shouldRunMemoryFlush` returns false before flushing.

## Solution Assessment

Unclear as final policy. A shared context-window-aware effective threshold is the narrow technical layer, but maintainers still need to choose clamp, warning, validation, or doctor behavior for existing oversized reserve configs.
