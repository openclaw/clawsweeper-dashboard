## Summary

Keep open. Current main and the latest release still allow a configured memory-flush reserve floor plus the soft threshold to make the token gate non-positive, which disables token-triggered memory flush/preflight; related same-repo fixes are closed unmerged, and the open adjacent memory-flush PR targets a different 0/0 counter bug.

## What This Changes

The issue reports that memory flush does not trigger when `reserveTokensFloor` is equal to the model context window, leaving agents to fill the context without trimming.

## Best Possible Solution

Land a focused current-main fix that centralizes a context-window-aware positive token threshold for memory flush and preflight compaction, with regression coverage for `reserveTokensFloor >= contextWindowTokens` and explicit maintainer-approved compatibility behavior.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: with positive token usage and `reserveTokensFloor + softThresholdTokens >= contextWindowTokens`, the shared gate returns `null`, causing memory flush and token-based preflight compaction to skip.

## Solution Assessment

Unclear as final policy. A shared context-window-aware threshold helper is the narrow technical layer, but maintainers still need to choose clamp, warning, validation, or doctor behavior for existing oversized reserve configs.
