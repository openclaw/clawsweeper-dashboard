## What This Changes

Fix divergent runtime-config default materialization between startup snapshots and reply-time loads so prepared model-runtime resolution does not reject equivalent agent configuration.

## System Context

OpenClaw materializes user configuration for both gateway startup and inbound-message handling. Startup publishes a prepared model catalog from a snapshot, while reply handling resolves against a load-materialized configuration; those representations must agree for exact prepared-runtime lookup to succeed.
