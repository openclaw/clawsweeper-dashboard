## Summary

Keep open: the reported session-warning rollover is real on current main, but this branch is not merge-ready because the new formatter promotes any half-unit value to the next unit, so valid values like 30s, 30m, and 12h would be shown as 1 minute, 1 hour, and 1 day.

## What This Changes

The PR changes the session maintenance warning duration formatter to round days, hours, and minutes before choosing the display unit, and adds regression cases for boundary rollover examples.

## Best Possible Solution

Keep the fix local to the session warning formatter, but round the smaller unit first and carry only when seconds or minutes reach 60 or hours reach 24, with tests for both rollover and non-rollover midpoint values.

## Reproduction Assessment

Yes. Current main source shows the raw-threshold formatter can emit 60 minutes at 3,570,000ms, and the PR defect is source-reproducible because Math.round(ms / unit) >= 1 promotes half-unit values.

## Solution Assessment

No. The requested bug is worth fixing, but this implementation is too broad; it should carry rounded lower units only at true 60/24 overflows instead of selecting the next unit at half its size.
