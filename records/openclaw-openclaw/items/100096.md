## Summary

Keep open: the rollover bug is plausible, but this PR still has the prior correctness blocker because it promotes half-unit values directly into larger units, and the attached proof is a standalone copied formatter rather than the changed OpenClaw warning path.

## What This Changes

The PR changes the session maintenance warning duration formatter to branch on rounded day/hour/minute values and adds regression tests for 59.5s, 59m30s, and 23h59m30s rollover text.

## Best Possible Solution

Use progressive lower-unit rollover: round seconds first, promote to minutes only at 60 rounded seconds, to hours only at 60 rounded minutes, and to days only at 24 rounded hours, with guard tests below each threshold.

## Reproduction Assessment

Yes. Source inspection of the PR diff gives a high-confidence reproduction for the review finding: `Math.round(ms / unit) >= 1` promotes 30s, 30m, and 12h before lower units are considered.

## Solution Assessment

No. The requested rollover behavior is valid, but this implementation promotes directly from raw milliseconds to larger rounded units too early; the safer fix is progressive lower-unit rollover.
