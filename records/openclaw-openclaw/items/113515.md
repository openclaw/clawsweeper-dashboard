## Summary

This PR remains necessary, but it still has a bounded correctness problem: a location derived only from a QMD file hint is cached under the document ID after the authoritative local index misses. If indexing later recovers or maps that ID differently, later searches keep using the fallback until cache clearing. The session-scope addition also lacks current-head real behavior proof.

## What This Changes

The PR makes QMD memory search retain a returned file URI when local document-ID lookup misses and permits the shared `global` session transcript through session-memory visibility filtering.

## System Context

Memory Core converts QMD search output into OpenClaw memory-search hits and filters session-backed hits for the requesting agent. QMD document IDs normally resolve through OpenClaw’s local index, while file hints provide a fallback location when that index is stale or incomplete.

## Architecture Diagram

flowchart LR
  A[QMD search result] --> B[Document resolver]
  B --> C[Local document index]
  B --> D[QMD file hint fallback]
  C --> E[Cached document location]
  D --> E
  E --> F[Memory search hit]
  G[Session transcript hit] --> H[Visibility filter]
  H --> F

## Best Possible Solution

Use QMD file hints for the immediate stale-index lookup but cache only authoritative index resolutions, then add an index-recovery regression test and provide redacted current-head evidence for the shared-global-session path.

## Reproduction Assessment

Yes, source-reproducible: resolve a QMD result while its document-ID row is missing, restore an authoritative row for that ID, and repeat the lookup in the same resolver instance. The fallback is cached by ID, so the recovered row is not consulted until cache clearing.

## Solution Assessment

No. The hint fallback is the right recovery mechanism, but caching it as a document-ID resolution conflates provisional QMD data with the authoritative local index; cache only index-backed locations or give fallback entries an explicit invalidation contract.
