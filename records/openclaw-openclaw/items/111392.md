## Summary

Keep this PR open: it is a focused candidate fix for the linked P1 Dreaming stall, but its snapshot comparison changes last-write-wins behavior when `params.entries` repeats a key, and the submitted after-fix evidence is limited to an instrumented Vitest runtime rather than a real Dreaming run.

## What This Changes

The PR reads existing memory-core Dreaming workspace rows once, skips `register()` calls for deeply equal values, retains deletion of removed rows, and adds contract tests for state-write counts.

## Best Possible Solution

Keep the one-read comparison design, but update the comparison state after every accepted value (or coalesce duplicate desired keys with explicit last-write-wins semantics), add a duplicate-key regression test, and attach redacted proof from a real Dreaming run showing the unchanged pass avoids writes.

## Solution Assessment

No, not quite: reading once and skipping equal values is the right bounded fix, but the implementation must preserve the existing sequential last-write-wins behavior for duplicate entry keys before it is safe.
