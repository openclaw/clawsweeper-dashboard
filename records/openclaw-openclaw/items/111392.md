## Summary

The performance fix is well-scoped and has credible real SQLite-backed proof, but it changes the keyed-store retention behavior at namespace capacity by no longer refreshing `created_at` for unchanged rows. Keep this PR open for an explicit Memory Core/plugin-state owner decision before merge.

## What This Changes

The PR reads existing Dreaming workspace-state rows and registers only new or changed canonical values while retaining deletion of absent keys and sequential duplicate-key behavior.

## Best Possible Solution

Make the Memory Core retention policy at keyed-store capacity explicit, add focused capacity coverage for the selected policy, and merge only after the state owner accepts the resulting upgrade behavior.
