## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Move Activity config under the Canvas plugin owner:** `src/config/zod-schema.ts:660-664`
  - body: Current main intentionally treats root `canvasHost` as legacy-only and migrates it into `plugins.entries.canvas.config.host`. Adding new `canvasHost.activity` fields reopens the old core config surface instead of extending the Canvas plugin contract, so existing upgrade and generated-config behavior would drift.
  - confidence: 0.91
- **[P1] Require a credential before granting Activity access:** `src/gateway/a2ui-activity.ts:150-154`
  - body: When `activity.token` is unset, this returns `true` after checking only launch-context markers that come from query/cookie/referer state. An external request can spoof those markers and reach Canvas/A2UI before normal Gateway bearer or capability auth runs.
  - confidence: 0.94
- **[P1] Bundle the Discord SDK instead of importing mutable CDNs:** `src/canvas-host/a2ui.ts:172-175`
  - body: The injected Canvas helper executes SDK code from jsDelivr or esm.sh at runtime inside the Canvas origin. That adds a third-party supply-chain execution path without a pinned local dependency or CSP/SRI-style control.
  - confidence: 0.9
- **[P1] Stop putting Activity tokens in WebSocket URLs:** `src/canvas-host/a2ui/index.html:325-329`
  - body: The bridge reads the Activity token from the page URL and appends it to the WebSocket query string, and it falls back to `ws://` on HTTP pages. Tokens in URLs leak through logs/history/intermediaries and can be sent in cleartext on misconfigured HTTP deployments.
  - confidence: 0.92
- **[P2] Bound Activity broadcasts before retaining and sending them:** `src/gateway/a2ui-activity.ts:240-243`
  - body: `broadcastPush` stores arbitrary JSONL and sends it to every connected client without a size cap or `bufferedAmount`/slow-client guard. A large A2UI payload or slow clients can turn a node command into gateway memory or event-loop pressure.
  - confidence: 0.87

## Security Review

Status: needs_attention

Summary: The diff introduces concrete auth, token-transport, third-party script execution, and Activity broadcast resource risks that need attention before merge.

Concerns:

- **[high] Activity access can bypass Gateway auth without a token:** `src/gateway/a2ui-activity.ts:151`
  - body: The PR allows Activity Canvas/A2UI routes before normal auth when no Activity token is configured and launch markers are present, but those markers are not cryptographic credentials.
  - confidence: 0.94
- **[high] Injected helper imports executable SDK code from CDNs:** `src/canvas-host/a2ui.ts:173`
  - body: Canvas pages would execute Discord SDK code fetched from mutable third-party CDN URLs at runtime in the Canvas origin.
  - confidence: 0.9
- **[medium] Activity token travels in URL and WebSocket query strings:** `src/canvas-host/a2ui/index.html:328`
  - body: The A2UI bridge reads the token from query parameters and sends it in the WebSocket URL, which can leak via logs, history, intermediaries, and cleartext HTTP deployments.
  - confidence: 0.92
- **[medium] A2UI Activity broadcast lacks resource limits:** `src/gateway/a2ui-activity.ts:240`
  - body: The hub retains and broadcasts arbitrary JSONL without payload caps or slow-client backpressure, creating a resource-exhaustion path.
  - confidence: 0.87
