Overall confidence: 0.93

Full review comments:

- **[P1] Move Activity config under Canvas plugin ownership:** `src/config/types.gateway.ts:41-59`
  - body: Current main migrates root `canvasHost` into `plugins.entries.canvas.config.host` and serves Canvas/A2UI from the Canvas plugin. Adding `canvasHost.activity` creates a competing config surface and does not fit the current upgrade path.
  - confidence: 0.94
- **[P1] Require a credential before allowing Activity access:** `src/gateway/a2ui-activity.ts:150-154`
  - body: With Activity mode enabled and no token, this returns allowed after spoofable launch-context markers or cookies, and Canvas authorization accepts that before normal Gateway bearer or node-capability auth. Activity access needs a real token or verifiable Discord assertion before public Canvas/A2UI is exposed.
  - confidence: 0.96
- **[P1] Bundle or pin the Discord SDK before injecting it:** `src/canvas-host/a2ui.ts:172-175`
  - body: The injected Canvas helper executes `@discord/embedded-app-sdk` from jsDelivr or esm.sh at runtime. That makes every Activity page trust mutable third-party CDN code; use a pinned local dependency or an owner-approved integrity/CSP model before exposing this in production.
  - confidence: 0.92
- **[P1] Stop carrying Activity tokens in WebSocket URLs:** `src/canvas-host/a2ui/index.html:325-329`
  - body: The A2UI bridge reads `activityToken` from the page URL, forwards it in the WebSocket query string, and falls back to cleartext `ws://` on HTTP pages. Use a safer cookie/exchange/protocol path and fail closed for insecure transport so tokens do not leak through logs, intermediaries, or browser history.
  - confidence: 0.9
- **[P2] Bound Activity broadcasts and slow clients:** `src/gateway/a2ui-activity.ts:240-243`
  - body: `broadcastPush` stores arbitrary JSONL and sends it to every Activity WebSocket without byte limits or `bufferedAmount` handling. Add payload caps and slow-client behavior before exposing this public fanout path.
  - confidence: 0.91
