Full review comments:

- **[P1] Move Activity config under the Canvas plugin owner:** `src/config/types.gateway.ts:41-59`
  - body: Current main moved Canvas host configuration to the Canvas plugin and hides root `canvasHost` from public config schema. Adding `canvasHost.activity` here reopens a retired root config surface and splits Activity behavior from the plugin that owns Canvas routing, docs, and migration.
  - confidence: 0.93
- **[P1] Require a real credential before bypassing Canvas auth:** `src/gateway/a2ui-activity.ts:150-154`
  - body: When Activity mode is enabled without a configured token, this path returns true after only seeing launch-context markers that any caller can spoof in the query string, cookie, or referer. Because `authorizeCanvasRequest` accepts that before bearer or node-capability auth, public callers can reach Canvas/A2UI routes unauthenticated.
  - confidence: 0.96
- **[P1] Bundle or pin the Discord SDK before injecting it:** `src/canvas-host/a2ui.ts:171-176`
  - body: The injected Canvas helper executes `@discord/embedded-app-sdk` from jsDelivr and then esm.sh at runtime. That gives a public Canvas page third-party executable code that is not pinned, bundled, or covered by repo dependency review, so a compromised CDN response can run in the Activity page origin.
  - confidence: 0.91
- **[P1] Stop carrying Activity tokens in WebSocket URLs:** `src/canvas-host/a2ui/index.html:325-329`
  - body: The A2UI bridge reads `activityToken` from the page query string and appends it to the WebSocket URL, falling back to `ws://` on HTTP. Tokens in URLs leak through logs/history/intermediaries and are sent in cleartext on HTTP, so the bridge needs a cookie/header/token-exchange path that fails closed without HTTPS.
  - confidence: 0.9
- **[P2] Bound Activity broadcasts and slow clients:** `src/gateway/a2ui-activity.ts:240-243`
  - body: `broadcastPush` stores arbitrary JSONL as `lastJsonl` and sends it to every connected Activity WebSocket without size checks or `bufferedAmount` backpressure. A large A2UI payload or slow clients can grow memory and stall the gateway event loop.
  - confidence: 0.88
- **[P2] Reset failed SDK loads so the helper can retry:** `src/canvas-host/a2ui.ts:202-208`
  - body: If the SDK import or `ready()` call fails once, the rejected `_loadPromise` remains cached and later `OpenClaw.discord.load()` calls reawait the same failure. A transient CDN/network/ready timeout therefore bricks the helper until a full page reload.
  - confidence: 0.86
