Full review comments:

- **[P1] Move Activity config under the Canvas plugin contract:** `src/config/zod-schema.ts:660-665`
  - body: This branch adds `canvasHost.activity` to core config and reads it from Gateway, but current main owns Canvas through the bundled Canvas plugin (`extensions/canvas/openclaw.plugin.json` keeps `canvasHost` only as a compatibility migration path). Landing a new root Canvas config owner would split upgrade/doctor/docs ownership and conflict with the current plugin boundary, so the Activity host config and route behavior need to move under the Canvas plugin contract before merge.
  - confidence: 0.91
- **[P1] Require credentialed Activity auth before bypassing Gateway auth:** `src/gateway/a2ui-activity.ts:151-154`
  - body: `isCanvasActivityAccessAllowed` returns true when no Activity token is configured after accepting any non-empty `instance_id`, `frame_id`, or `platform` marker from the URL, cookie, or referer. Because `authorizeCanvasRequest` calls this before bearer/capability auth, a public Activity-enabled gateway can be opened by spoofing a launch marker; require a real shared secret or signed Discord assertion for the bypass.
  - confidence: 0.95
- **[P1] Stop loading the Discord SDK from public CDNs:** `src/canvas-host/a2ui.ts:173-175`
  - body: The injected Canvas helper executes `@discord/embedded-app-sdk` from jsDelivr and then esm.sh at runtime. That gives public CDN responses script execution in the Canvas origin without a repo-pinned dependency or integrity boundary; bundle/pin the SDK through the owned package path or provide a maintainer-approved local loader.
  - confidence: 0.92
- **[P1] Bound Activity broadcasts before fanning out:** `src/gateway/a2ui-activity.ts:240-243`
  - body: `broadcastPush` stores the full JSONL payload and sends it to every Activity socket without byte limits or bufferedAmount checks, while `node.invoke` can stringify an arbitrary object into this path. This bypasses the normal Gateway broadcast backpressure pattern and can turn one large A2UI update or slow client set into memory/event-loop pressure.
  - confidence: 0.9
- **[P1] Stop carrying Activity tokens in URLs:** `src/canvas-host/a2ui/index.html:325-329`
  - body: The Activity bridge reads `activityToken` from the page URL and appends it to the WebSocket query string, which exposes the token to browser history, logs, referers, intermediaries, and cleartext `ws://` if the page is served over HTTP. Use a secure cookie or other non-URL credential transport and fail closed for authenticated Activity traffic on non-TLS origins.
  - confidence: 0.91
- **[P2] Clear the failed Discord SDK load promise:** `src/canvas-host/a2ui.ts:202-207`
  - body: When SDK loading or `ready()` times out, the catch block records the error but leaves `state._loadPromise` set to the rejected promise. Later calls re-await the same failure and cannot recover after a transient CDN/network issue without a full page reload; clear the promise before rethrowing.
  - confidence: 0.86
