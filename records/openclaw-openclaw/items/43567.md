## Summary

Keep open: the specific pre-compaction memory-flush leak is fixed, but current main still lacks a first-class system/diagnostic presentation path and audience policy for visible runtime-originated messages.

## What This Changes

Request to render internal/runtime system-originated messages in Control UI/TUI as a distinct diagnostic block rather than ordinary user or assistant chat bubbles.

## Best Possible Solution

Define one shared audience/provenance contract: agent-only internals stay hidden, while deliberately visible runtime notices render through a dedicated diagnostic/system treatment across Control UI/WebChat and TUI.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should visible runtime/system-originated messages be hidden by default, rendered as a dedicated diagnostic block, or continue through ordinary chat grouping?

Rationale: The current source supports multiple implementation shapes, but the choice affects transcript projection, Control UI/WebChat rendering, TUI parity, and restart-continuation behavior, so automation should not pick the product policy by itself.

Likely owner: steipete

Owner reason: The strongest recent history is on Gateway display projection and Control UI chat rendering, which are central to the policy decision.

Owner confidence: medium

Options:

- **Define shared audience contract (recommended):** Choose a core hidden-vs-diagnostic audience model first, then implement Gateway projection and surface rendering from that contract.
- **Hide runtime internals:** Treat system/runtime-originated prompts as agent-only unless a source explicitly opts into user-visible diagnostics.
- **Style current system rows only:** Add a distinct system block for role system rows without changing visibility semantics, accepting that some agent-only text may still be exposed.

## Reproduction Assessment

Yes, at source level: current Control UI can create and normalize system-role rows, but renders them through the generic other chat group instead of a dedicated system block. I did not run a live Control UI/TUI reproduction in this read-only review.

## Solution Assessment

No, a display-only colored block is not the best standalone fix. The maintainable path is to decide the runtime audience/provenance contract first, then wire Gateway projection and surface-specific rendering to that contract.
