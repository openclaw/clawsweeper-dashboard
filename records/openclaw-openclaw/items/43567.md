## Summary

Keep open: current main fixes the concrete pre-compaction memory-flush leak, but the broader product request is still unresolved because generic visible system/runtime rows still flow through normal chat grouping rather than a first-class diagnostic/system block.

## What This Changes

The issue requests a distinct UI treatment for internal/runtime system messages so they are not confused with user or assistant chat bubbles.

## Best Possible Solution

Define a shared audience/provenance contract first: hide agent-only internals, and render deliberately visible runtime notices through a dedicated diagnostic/system block across Control UI/WebChat and TUI.

## Reproduction Assessment

Yes, at source level for the remaining gap: generic system-role rows can still be built as normal message items and rendered through the generic other chat group path. I did not run a live Control UI/TUI reproduction in this read-only review.

## Solution Assessment

No, a display-only colored block is not the best standalone fix. The maintainable solution is to choose the runtime audience/provenance contract first, then wire projection and surface-specific rendering to that contract.
