## Summary

Keep open: the concrete pre-compaction memory-flush leak has been fixed and release-noted, but current main still lacks a shared runtime/system audience contract and a dedicated Control UI/WebChat/TUI diagnostic presentation for intentionally visible system-originated messages.

## What This Changes

The issue requests that internal runtime/system messages render with clearly distinct system-originated treatment instead of appearing as normal user or assistant chat bubbles.

## Best Possible Solution

Define one shared audience/provenance contract: agent-only internals stay hidden, while deliberately visible runtime notices render through a dedicated diagnostic/system treatment across Gateway projection, Control UI/WebChat, and TUI.

## Maintainer Decision

Question: Should visible runtime/system-originated messages be hidden by default, rendered as dedicated diagnostic/system blocks, or continue through ordinary chat grouping for some system rows?

Rationale: The source supports multiple implementation shapes, but the choice affects transcript projection, Control UI/WebChat rendering, TUI parity, restart continuations, and session-state provenance, so automation should not choose the product policy by itself.

Likely owner: steipete

Owner reason: The strongest recent history signal is around Gateway display projection and system-event handling, which are central to the policy decision.

Owner confidence: medium

Options:

- **Define shared audience contract (recommended):** Choose a core hidden-vs-diagnostic audience model first, then implement Gateway projection and UI/TUI rendering from that contract.
- **Hide runtime internals by default:** Treat system/runtime-originated prompts as agent-only unless a source explicitly opts into user-visible diagnostics.
- **Style current system rows only:** Add a distinct system block for role `system` rows without changing visibility semantics, accepting that some agent-only text may still be exposed elsewhere.

## Reproduction Assessment

Yes, at source level: current main normalizes `system` rows but renders non-user/non-assistant/non-tool roles through the generic `other` chat group, while Gateway projection only hides selected internals. I did not run a live Control UI/TUI reproduction in this read-only review.

## Solution Assessment

No, a display-only colored block is not the best standalone fix. The maintainable path is to decide the runtime audience/provenance contract first, then wire Gateway projection and surface-specific rendering to that contract.
