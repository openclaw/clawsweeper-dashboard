## Best Possible Solution

Define one shared audience/provenance contract: agent-only internals stay hidden, while deliberately visible runtime notices render through dedicated diagnostic/system treatment across Control UI/WebChat and TUI.

Rationale: The source supports multiple implementation shapes, but the choice affects transcript projection, Control UI/WebChat rendering, TUI parity, and continuation/runtime message policy, so automation should not choose the product semantics.

Options:

- **Define shared audience contract (recommended):** Choose a core hidden-vs-diagnostic audience model first, then implement Gateway projection plus UI/TUI rendering from that contract.
- **Hide runtime internals:** Treat system/runtime-originated prompts as agent-only unless a source explicitly opts into user-visible diagnostics.
- **Style current system rows only:** Add a distinct system block for role system rows without changing visibility semantics, accepting that some agent-only text may still be exposed.

## Reproduction Assessment

Yes at source level: Control UI normalizes system-role rows, but system roles fall through the generic other chat group rather than a dedicated system block. I did not run a live Control UI/TUI reproduction in this read-only review.

## Solution Assessment

No, a display-only colored block is not the best standalone fix. The maintainable path is to decide the runtime audience/provenance contract first, then wire Gateway projection and surface-specific rendering to that contract.
