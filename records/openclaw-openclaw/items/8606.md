## Summary

Keep open: current main and the latest release still prune context without emitting a pruning lifecycle hook, and the direct implementation candidate remains open and conflicting rather than merged.

## What This Changes

Request a lifecycle hook/event when context pruning trims tool outputs so handlers can react to or index the pruned material.

## Best Possible Solution

Keep this as the canonical request and resolve it through https://github.com/openclaw/openclaw/pull/12581 or a replacement that emits bounded, sanitized pruning metadata after successful pruning with focused tests and public docs.

## Reproduction Assessment

Yes, at source level. Current main prunes through the active context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only session:prune lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction; raw pruned-content access needs explicit privacy, trust, timeout, and size-limit decisions.
