## Summary

Keep open: current main and v2026.6.11 still prune context without emitting a pruning lifecycle hook, and https://github.com/openclaw/openclaw/pull/12581 remains the open candidate rather than a merged fix.

## What This Changes

The issue requests a context-pruning lifecycle hook so external memory or indexing handlers can react when old tool output is trimmed from active context.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/12581 with an implementation on the active `src/agents/agent-hooks/context-pruning/*` path that emits bounded sanitized pruning metadata after successful pruning, adds focused tests, and documents the hook contract.

## Reproduction Assessment

Yes. Source inspection shows current main's context-pruning extension calls the pruner and returns rewritten messages without emitting an internal or plugin hook, while the hook catalog and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the contract. A metadata-only `session:prune` lifecycle event in the active agent-hooks path looks like the narrow maintainable direction, while raw pruned-content access needs explicit privacy, trust, timeout, and size-limit decisions.
