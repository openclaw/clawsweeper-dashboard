## Summary

Keep open: current main and v2026.6.11 still prune context without emitting a pruning lifecycle hook, and the direct linked implementation PR remains open, conflicting, and blocked on hook-contract and security review.

## What This Changes

The issue requests a new context/session pruning hook event with metadata so external handlers can index content after it is pruned from active context.

## Best Possible Solution

Keep this as the canonical request and resolve it through the linked PR or a replacement that emits bounded, sanitized pruning metadata from the active agent-hooks pruning path after successful pruning, with tests and docs.

## Reproduction Assessment

Yes, at source level. Current main prunes through the context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only session:prune lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction, while raw pruned-content indexing needs explicit privacy, timeout, and size-limit decisions.
