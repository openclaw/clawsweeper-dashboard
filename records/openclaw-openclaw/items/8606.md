## Summary

Keep open: current main and the latest release still lack a context-pruning lifecycle hook, and the direct linked implementation remains open, conflicting, and blocked on the safe hook contract.

## What This Changes

The issue requests a lifecycle hook that fires after context pruning so downstream handlers can index or otherwise preserve pruned session content.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/12581 or a maintainer-approved replacement that emits bounded, sanitized pruning metadata from the active agent-hooks pruning path after successful pruning, with focused tests and public hook docs.

## Reproduction Assessment

Yes, at source level. Current main prunes through the active context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only `session:prune` lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction, while raw pruned-content access needs explicit privacy, trust, timeout, and size-limit decisions.
