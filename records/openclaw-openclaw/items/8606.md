## Summary

Keep open: current main and the latest release still lack a context/session pruning lifecycle hook, and the linked implementation PR remains open, conflicting, and blocked on a safe hook contract.

## What This Changes

Request adding a context/session pruning lifecycle hook that fires after pruning with metadata about trimmed content for follow-up indexing.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/12581 or a replacement that emits bounded sanitized metadata from the active agent-hooks pruning path after successful pruning, with bounded hook delivery and public docs.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose a pruning lifecycle hook now, and should the contract be metadata-only by default rather than exposing raw pruned content?

Rationale: The implementation direction is clear enough, but the payload and delivery semantics affect session privacy, installed hook trust, and agent availability.

Likely owner: steipete

Owner reason: Peter Steinberger is the strongest routing owner from cache-TTL pruning history, active-path refactors, and prior maintainer review on this issue.

Owner confidence: high

Options:

- **Metadata-only session:prune (recommended):** Expose a bounded event from the active pruning path with counts, timing, and sanitized optional tool identifiers, while keeping raw pruned content out of the default payload.
- **Raw-content opt-in design:** Allow richer pruned-content access only behind an explicit security-reviewed opt-in contract with size, timeout, and logging guidance.
- **Defer the hook:** Keep scheduled indexing or memory plugins as the supported workaround until maintainers are ready to define a pruning hook boundary.

## Reproduction Assessment

Yes, at source level. Current main prunes through the active context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook docs/catalog omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the security contract. A metadata-only session:prune event in the active agent-hooks path looks like the narrowest maintainable solution; raw pruned-content access should not be the default.
