## Summary

Keep open: current main and the latest release still prune context without a pruning lifecycle hook, and the linked implementation PR is open and unmerged. The request remains valid, but the hook payload needs maintainer product and security review before this issue can close.

## What This Changes

Request to emit a context/session pruning lifecycle hook with metadata when tool-output pruning trims active context so external indexers can preserve search access.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/12581 or a maintainer-approved replacement that emits bounded, sanitized pruning metadata from the active agent-hooks path after successful pruning, with focused tests and docs.

## Reproduction Assessment

Yes, at source level. Current main prunes through the active context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only session:prune lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction, while raw pruned-content access needs explicit privacy, trust, timeout, and size-limit decisions.
