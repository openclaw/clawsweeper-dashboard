## Summary

Keep open: current main and the latest release still lack a context/session pruning lifecycle event, while the direct implementation candidate remains open, conflicting, and not merged.

## What This Changes

The issue requests a context/session pruning lifecycle hook that fires after pruning with metadata suitable for external indexing or memory workflows.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/12581 or a maintainer-approved replacement that emits bounded, sanitized pruning metadata from the active agent-hooks path after successful pruning, with focused tests and public docs.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: What pruning-hook contract should OpenClaw support for this issue: metadata-only by default, raw pruned content behind an explicit trusted opt-in, or no core hook yet?

Rationale: The source gap is clear, but the permanent API decides what session/tool metadata or content can leave the context-building path and what latency/security boundaries hook handlers must obey.

Likely owner: vincentkoc

Owner reason: Vincent owns the open implementation attempt and has adjacent hook-surface history, so he is the best current routing candidate for the contract choice.

Owner confidence: medium

Options:

- **Metadata-only session prune hook (recommended):** Add a session:prune lifecycle event in the active agent-hooks path with counts, timestamp, session identity when available, and sanitized bounded tool metadata only.
- **Trusted raw-content opt-in:** Allow raw pruned content only behind an explicit trusted hook/plugin permission after documenting privacy, size, timeout, and logging expectations.
- **Defer core hook surface:** Keep scheduled indexing as the workaround until a broader memory or hook API design can cover pruning, reset, and compaction together.

## Reproduction Assessment

Yes, at source level. Current main prunes through the active context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A bounded metadata-only session:prune event in the active agent-hooks path appears to be the narrowest maintainable direction; raw pruned-content access needs explicit privacy, trust, timeout, and size-limit decisions.
