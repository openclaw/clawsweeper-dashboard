## Summary

Keep open: current main and v2026.6.11 still prune context without emitting a pruning lifecycle hook, and the direct implementation PR is still open, conflicting, and blocked on the safe hook contract.

## What This Changes

The issue requests a `context:prune` or `session:prune` hook that fires after context pruning with metadata about trimmed content so external memory/indexing workflows can react.

## Best Possible Solution

Resolve this through a maintainer-approved, metadata-only pruning lifecycle hook in `src/agents/agent-hooks/context-pruning/*`, with timeout-safe delivery, focused tests, and docs for the supported payload.

## Reproduction Assessment

Yes, at source level. Current main prunes through the context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs/docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A bounded metadata-only `session:prune` event in the active agent-hooks path looks like the narrowest maintainable direction; raw pruned-content access needs explicit privacy, size, trust, and timeout decisions.
