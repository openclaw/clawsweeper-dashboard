## Summary

Keep open: current main and v2026.6.11 still lack a context-pruning lifecycle hook, and https://github.com/openclaw/openclaw/pull/12581 is the explicit but unmerged implementation candidate.

## What This Changes

Request to add a context-pruning lifecycle hook that exposes safe metadata about pruned tool output for downstream indexing.

## Best Possible Solution

Resolve this through the linked PR or a replacement against the active agent-hooks path with bounded sanitized metadata, focused tests, and public docs.

## Reproduction Assessment

Yes, at source level. Current main prunes through the context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only session:prune lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction, while raw pruned-content indexing needs explicit privacy, timeout, size-limit, and trust-boundary decisions.
