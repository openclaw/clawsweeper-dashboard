## Summary

Keep open: current main and latest release still prune context without a pruning lifecycle hook, and the direct implementation candidate remains open and unmerged. The request is valid, but the hook payload and dispatch semantics need maintainer product/security review before a fix lands.

## What This Changes

Request to add a context-pruning lifecycle hook that fires after pruning with metadata about what was trimmed.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/12581 or a maintainer-approved replacement that emits bounded, sanitized pruning metadata from the active agent-hooks path after successful pruning.

## Reproduction Assessment

Yes, at source level. Current main and the latest release prune through the active context extension and pruner without returning hook metadata or emitting a pruning hook, and hook catalogs/docs do not define a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only `session:prune` lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction, while raw pruned-content access needs explicit privacy, trust, timeout, and size-limit decisions.
