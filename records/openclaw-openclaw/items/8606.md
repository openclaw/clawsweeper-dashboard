## Summary

Keep open: current main and the latest release still lack a context/session pruning lifecycle hook, and the open linked implementation PR remains conflicting and unmerged.

## What This Changes

The issue requests a context-pruning lifecycle hook that emits metadata after pruning so downstream handlers can index pruned content.

## Best Possible Solution

Review and land the linked PR or a maintainer-approved replacement that emits bounded, sanitized pruning metadata from the active pruning path after successful pruning, with focused tests and public docs.

## Maintainer Decision

Kind: product_direction

Question: What pruning-hook contract should OpenClaw support for this issue: metadata-only by default, raw pruned content behind an explicit trusted opt-in, or no core hook yet?

Rationale: The source gap is clear, but the permanent API decides what session/tool metadata or content may leave the context-building path and how hook latency/security boundaries are enforced.

Likely owner: vincentkoc

Owner reason: Vincent owns the open implementation candidate and has adjacent hook-surface history.

Owner confidence: high

Options:

- **Metadata-only session prune hook (recommended):** Add a session:prune lifecycle event in the active agent-hooks path with bounded counts, timestamp, session identity when available, and sanitized tool metadata only.
- **Trusted raw-content opt-in:** Expose pruned content only behind explicit trusted plugin or hook permission with privacy, size, timeout, and logging rules.
- **Defer core hook surface:** Keep scheduled indexing as the workaround until a broader memory or hook API design covers pruning, reset, and compaction together.

## Reproduction Assessment

Yes, at source level. Current main prunes through the active context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A bounded metadata-only session:prune event in the active pruning path appears to be the narrowest maintainable direction; raw pruned-content access needs explicit privacy, trust, timeout, and size-limit decisions.
