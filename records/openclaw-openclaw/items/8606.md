## Summary

Keep open: current main and v2026.6.11 still prune context without emitting a pruning lifecycle hook, and the direct linked implementation PR remains open, conflicting, and unmerged.

## What This Changes

The issue requests a `session:prune` or `context:prune` lifecycle hook with metadata so handlers can react when old tool output is trimmed from active context.

## Best Possible Solution

Keep this as the canonical request and resolve it through a current-path PR that emits bounded, sanitized pruning metadata after successful pruning with focused tests and public docs.

## Reproduction Assessment

Yes, at source level. Current main prunes through the active context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only `session:prune` lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction; raw pruned-content access needs explicit privacy, trust, timeout, and size-limit decisions.
