## Summary

Keep open: current main and the latest release still prune context without emitting a pruning lifecycle hook, and the linked implementation PR is open but conflicting and needs maintainer review for the safe hook contract.

## What This Changes

The issue requests a context-pruning lifecycle hook that fires after pruning and exposes safe metadata for external indexing or memory workflows.

## Best Possible Solution

Land a maintainer-approved pruning lifecycle hook as a narrow core/plugin API extension with metadata-only payload, bounded hook execution, focused pruning tests, and docs for the supported event contract.

## Reproduction Assessment

Yes. Source inspection on current main shows pruning runs through `contextPruningExtension` and `pruneContextMessages(...)`, but no pruning lifecycle hook or metadata payload is emitted or documented.

## Solution Assessment

Unclear until maintainer review. A hook/API extension is the right product shape if external indexing needs event-driven pruning metadata, but the final answer must choose a safe internal-vs-plugin contract and payload scope.
