## Summary

Keep open: current main and v2026.6.11 still prune context without emitting a pruning lifecycle hook, and the direct implementation candidate remains open and conflicting rather than merged.

## What This Changes

Request to add a context/session pruning lifecycle hook that fires after tool-output pruning and exposes metadata for external indexing.

## Best Possible Solution

Resolve this through https://github.com/openclaw/openclaw/pull/12581 or a replacement that emits bounded, sanitized pruning metadata after successful pruning in the active agent-hooks path, with focused tests and public hook docs.

## Reproduction Assessment

Yes, at source level. Current main prunes through the active context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only session:prune lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction, while raw pruned-content access needs explicit privacy, trust, timeout, and size-limit decisions.
