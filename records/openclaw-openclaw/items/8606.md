## Summary

Keep open: current main and v2026.6.11 still prune context without a pruning lifecycle hook, and the open closing PR remains unmerged, conflicting, and blocked on hook-contract/security decisions.

## What This Changes

Requests a hook event fired after context pruning with metadata so external handlers can index or otherwise act on content removed from active context.

## Best Possible Solution

Keep this as the canonical request and resolve it through the linked PR or a replacement in the active `agent-hooks` pruning path with bounded, sanitized metadata, focused tests, and public docs.

## Reproduction Assessment

Yes, at source level. Current main prunes through the context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only `session:prune` event in the active pruning path looks like the narrowest direction, while raw pruned-content indexing needs explicit privacy, trust, timeout, and size-limit decisions.
