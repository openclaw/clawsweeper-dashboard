## Summary

Keep open: current main still lacks a context/session pruning lifecycle hook, and the direct linked implementation PR remains open, unmerged, and not yet ported to the active pruning path.

## What This Changes

The issue requests a lifecycle hook that fires after context pruning trims tool outputs so handlers can preserve or index what was removed from active context.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/12581 or a maintainer-approved replacement that emits bounded, sanitized pruning metadata from the active agent-hooks path after successful pruning, with focused tests and public hook docs.

## Reproduction Assessment

Yes, at source level. Current main prunes through the active context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only session:prune lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction, while raw pruned-content access needs explicit privacy, trust, timeout, and size-limit decisions.
