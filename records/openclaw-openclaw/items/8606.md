## Summary

Keep open: current main and the latest release still prune context without emitting a pruning lifecycle hook, and the direct implementation PR remains open, conflicting, and security/product-contract sensitive.

## What This Changes

The issue requests a context-pruning lifecycle hook that fires after pruning and exposes enough metadata for external memory or indexing handlers to react without polling.

## Best Possible Solution

Resolve this through a maintainer-approved, metadata-only pruning lifecycle hook in `src/agents/agent-hooks/context-pruning/*`, with timeout-safe delivery, focused tests, and docs for the supported payload.

## Reproduction Assessment

Yes, at source level. Current main prunes through the context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs/docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only session:prune lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction, while raw pruned-content indexing needs explicit privacy, trust, timeout, and size-limit decisions.
