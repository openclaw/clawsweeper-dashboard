## Summary

Keep open: current main and v2026.6.11 still prune context without emitting a pruning lifecycle hook, and the direct linked PR is open but blocked on current-path porting and the safe hook contract.

## What This Changes

The issue requests a lifecycle event that fires after context pruning trims tool output so downstream handlers can index or preserve pruned context.

## Best Possible Solution

Keep this as the canonical request and resolve it with the linked PR or a replacement that emits bounded, sanitized pruning metadata from the active agent-hooks path after successful pruning, with focused tests and docs.

## Reproduction Assessment

Yes, at source level. Current main prunes through the active context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Partly. A metadata-only pruning lifecycle event is the right narrow direction, but raw pruned-content indexing needs explicit privacy, trust-boundary, timeout, and size-limit decisions before it becomes a contract.
