## Summary

Keep open: current main and the latest release still prune context without emitting a pruning lifecycle hook, and the linked implementation PR remains open, conflicting, and review-blocked.

## What This Changes

Request to emit a context-pruning lifecycle hook with metadata about what was trimmed so downstream handlers can preserve or index pruned content.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/12581 or a maintainer-approved replacement that emits bounded, sanitized pruning metadata from the active agent-hooks path after successful pruning.

## Reproduction Assessment

Yes, at source level. Current main prunes through the active context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only session prune lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction, while raw pruned-content access needs explicit privacy, trust, timeout, and size-limit decisions.
