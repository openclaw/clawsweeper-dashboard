## Summary

Keep open: current main and the latest release still lack a context-pruning lifecycle hook, and the direct linked implementation candidate is open, unmerged, and dirty. The remaining decision is the safe hook contract, especially whether payloads stay bounded metadata-only.

## What This Changes

The issue requests a hook event when context pruning trims old tool output so follow-up handlers can index or observe what left active model context.

## Best Possible Solution

Keep this as the canonical request and resolve it through https://github.com/openclaw/openclaw/pull/12581 or a replacement that emits bounded, sanitized pruning metadata after successful pruning in the current agent-hooks path, with focused tests and docs.

## Reproduction Assessment

Yes, at source level. Current main prunes through the active context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only session:prune lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction, while raw pruned-content access needs explicit privacy, trust, timeout, and size-limit decisions.
