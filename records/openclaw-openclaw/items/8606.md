## Summary

Keep open: current main still lacks a pruning lifecycle hook or payload metadata, and the linked implementation PR explicitly closes this issue but remains open, conflicting, and security-sensitive.

## What This Changes

The issue requests a context-pruning lifecycle hook that fires after pruning and exposes pruning details for event-driven indexing.

## Best Possible Solution

Keep this issue open and land or replace the linked PR with a current-path implementation that emits a bounded `session:prune` event after successful pruning, uses sanitized summary metadata by default, avoids blocking prompt assembly on hook handlers, and updates focused tests plus hook docs.

## Reproduction Assessment

Yes at source level: current main's pruning extension returns rewritten messages and the pruner returns only `AgentMessage[]`, with no prune hook or metadata contract. I did not run runtime tests because this review is read-only and source inspection is sufficient for this feature gap.

## Solution Assessment

Yes, a bounded post-prune lifecycle hook is the right surface, but the best implementation should emit only safe summary metadata by default and avoid blocking context assembly. The linked PR or a replacement should be reviewed for that contract before merge.
