## Summary

Keep open: current main and the latest release still prune context without emitting a pruning lifecycle hook, and the open implementation candidate is still unmerged and conflicting.

## What This Changes

The issue requests a context-pruning lifecycle hook that fires after pruning with metadata usable by external indexing or memory handlers.

## Best Possible Solution

Keep this as the canonical request and resolve it through https://github.com/openclaw/openclaw/pull/12581 or a replacement that emits bounded, sanitized pruning metadata after successful pruning in the active agent-hooks path with focused tests and docs.

## Reproduction Assessment

Yes, at source level. Current main prunes through the active context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only session:prune lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction, while raw pruned-content access needs explicit privacy, trust, timeout, and size-limit decisions.
