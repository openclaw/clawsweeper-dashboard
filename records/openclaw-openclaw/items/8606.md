## Summary

Keep open: current main and v2026.6.11 still prune context without a pruning lifecycle hook, and the linked open PR is the candidate implementation but remains conflicting and blocked on the safe hook contract.

## What This Changes

Request a context-pruning lifecycle hook that fires after pruning with metadata suitable for event-driven indexing or memory workflows.

## Best Possible Solution

Keep this issue as the canonical request and resolve it through the linked PR or a replacement that emits bounded, sanitized pruning metadata after successful pruning in the active agent-hooks path, with focused tests and public docs.

## Reproduction Assessment

Yes, at source level. Current main prunes through the context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only session:prune lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction, while raw pruned-content indexing needs explicit privacy, trust, timeout, and size-limit decisions.
