## Summary

Keep open: current main and v2026.6.11 still prune context without emitting a pruning lifecycle hook, and the linked implementation candidate remains open rather than merged.

## What This Changes

The issue requests a context-pruning lifecycle hook that fires after pruning with enough metadata for handlers to index or preserve pruned content.

## Best Possible Solution

Resolve this through https://github.com/openclaw/openclaw/pull/12581 or a replacement that emits bounded, sanitized pruning metadata after successful pruning in the active agent-hooks path, with focused tests and docs.

## Reproduction Assessment

Yes, at source level. Current main prunes through the active context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only session:prune lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction, while raw pruned-content access needs explicit privacy, trust, timeout, and size-limit decisions.
