## Summary

Keep open. Current main and the latest release still lack a context-pruning lifecycle hook, and the open implementation candidate that closes this issue remains unmerged, conflicting, and security-sensitive.

## What This Changes

The issue requests a hook such as `session:prune` or `context:prune` that fires after context pruning with metadata about trimmed content so external memory/indexing handlers can react without polling.

## Best Possible Solution

Keep this issue open and resolve it through https://github.com/openclaw/openclaw/pull/12581 or a replacement that ports to the current `agent-hooks` path, emits a bounded safe prune event, documents the payload, and proves hook failures cannot stall pruning.

## Reproduction Assessment

Yes, at source level. Current main and `v2026.6.11` both prune by returning rewritten messages only, while hook catalogs and docs contain no `session:prune` or `context:prune` event.

## Solution Assessment

Unclear until maintainers settle the payload and delivery contract. A narrow prune lifecycle event is the right shape, but the best implementation should avoid raw sensitive payloads and keep hook execution from blocking prompt assembly.
