## Summary

Keep open: current main and the latest release still lack a context/session pruning lifecycle hook, and the direct linked implementation is still open and unmerged.

## What This Changes

The issue requests a hook event after context pruning so external indexing or memory workflows can react to trimmed context without polling.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/12581 or a replacement that emits a bounded, sanitized `session:prune` event from the active agent-hooks path after successful pruning, with focused tests and docs.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: What pruning-hook contract should OpenClaw support for this issue: metadata-only by default, raw pruned content behind explicit trusted opt-in, or no core hook yet?

Rationale: The source gap is clear, but maintainers must choose what session/tool metadata or content may leave the context-building path and whether hook delivery is bounded or asynchronous.

Likely owner: vincentkoc

Owner reason: vincentkoc owns the open implementation attempt and has adjacent hook-surface history, so he is the best current routing candidate for the contract choice.

Owner confidence: high

Options:

- **Metadata-Only Prune Event (recommended):** Add `session:prune` in the active agent-hooks path with counts, timestamp, session identity when available, and sanitized bounded tool metadata only.
- **Trusted Raw-Content Opt-In:** Allow raw pruned content only behind an explicit trusted hook or plugin permission with documented privacy, size, timeout, and logging expectations.
- **Defer Core Hook Surface:** Keep scheduled indexing as the workaround until a broader memory or hook API design covers pruning, reset, and compaction together.

## Reproduction Assessment

Yes, at source level. Current main prunes through the active context extension and pruner without emitting a pruning hook or returning hook metadata, and hook catalogs/docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only `session:prune` event in the active agent-hooks path appears to be the narrowest maintainable direction; raw content needs explicit privacy, trust, timeout, and size-limit decisions.
