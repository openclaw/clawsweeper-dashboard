## Summary

Keep open: current main and v2026.6.11 still prune context without any pruning lifecycle hook, and https://github.com/openclaw/openclaw/pull/12581 is an open but conflicting direct implementation candidate.

## What This Changes

Request a context-pruning lifecycle hook that fires after tool-output pruning with metadata suitable for event-driven indexing.

## Best Possible Solution

Resolve this through the linked PR or a replacement in the active agent-hooks pruning path that emits bounded, sanitized metadata after successful pruning, with focused tests and public hook docs; raw pruned content should not be exposed by default.

## Reproduction Assessment

Yes, at source level. Current main prunes through the context extension and pruner without emitting a pruning hook or returning hook metadata, and the hook catalogs and docs omit a pruning event.

## Solution Assessment

Unclear until maintainers choose the hook contract. A metadata-only session:prune lifecycle event in the active agent-hooks path looks like the narrowest maintainable direction, while raw pruned-content indexing needs explicit privacy, trust, timeout, and size-limit decisions.
