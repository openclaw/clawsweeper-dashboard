## Label Justifications

- `P2`: The reported failure would affect scheduled Slack delivery in a bounded conflicting multi-account configuration.
- `impact:message-loss`: The reported symptom is suppression of scheduled Slack messages after selecting an account without a valid token.

## Summary

Current main already makes the cron job’s explicit account authoritative over session and binding fallbacks, preserves it through target and route resolution, and passes it to Slack delivery. Full history shows this behavior was merged in March 2026 and shipped months before the reported June 2026 failure.

## What This Changes

Ensure Slack delivery uses an explicitly supplied account ID before any channel-name or channel-ID fallback matching.

## Best Possible Solution

Keep the shipped explicit-account precedence and request a new current-release report only if evidence shows the account changing after delivery-target resolution, including the stored cron delivery object and pre-send resolved account.
