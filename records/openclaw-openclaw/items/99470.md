## Summary

Keep open. Current main filters intact `provider=openclaw` / `model=delivery-mirror` transcript artifacts, but this report describes a degraded replay shape where that identity is absent and current `normalizeAssistantReplayContent` has no adjacent duplicate assistant fallback.

## What This Changes

The issue requests a fix for delivery-mirror transcript artifacts leaking into model prompts as duplicate assistant turns after rebuild or merge paths lose mirror identity.

## Best Possible Solution

Preserve delivery-mirror identity through rebuild/merge where possible and add a narrow replay-boundary fallback that removes only adjacent byte-identical no-tool assistant duplicates from model prompts while keeping transcript receipts persisted.

## Reproduction Assessment

Yes, at source level. Current main filters delivery mirrors only when `provider/model` identity is present, so a stripped-metadata adjacent duplicate assistant pair remains model-visible; I did not run a live Telegram reproduction.

## Solution Assessment

Yes, with care. The maintainable fix is at the prompt replay boundary plus preserving mirror identity, not suppressing delivery-mirror persistence because those rows are still delivery receipts.
