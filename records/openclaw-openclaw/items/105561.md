## Summary

This is a valid shipped catalog-contract bug: `v2026.6.11` and current main publish Codex-discovered models as `codex/*`, while doctor and successful execution establish `openai/*` plus the Codex runtime as canonical. The issue should stay open because no merged fix or safe canonical successor exists, and the permanent machine-readable provider/runtime representation needs maintainer confirmation.

Likely related people: `steipete` (medium confidence, broad provider/migration/catalog history), Vincent Koc (medium confidence, introduced the current snapshot), and Eva H (low confidence, adjacent catalog/migration history).

## What This Changes

Align Codex model-catalog identifiers with the canonical OpenAI provider references and Codex runtime used by configuration migration and execution.

## Best Possible Solution

Define one typed catalog representation for canonical `openai/<model>` plus explicit Codex runtime identity, then update the Codex plugin, CLI/gateway projections, doctor migration, and fresh-install/upgrade tests together while keeping legacy provider names migration-only.
