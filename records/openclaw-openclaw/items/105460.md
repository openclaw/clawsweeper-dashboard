## Summary

The reported framing bug remains on current main and this branch uses the right immediate-failure owner boundary, but it is not merge-ready because the new strict parser still accepts colonless malformed header lines. The fixed size limits also intentionally terminate previously tolerated sessions and need explicit maintainer acceptance before landing.

## What This Changes

The PR replaces permissive bundled-LSP stdout parsing with strict Content-Length validation, 8 KiB header and 64 MiB body bounds, fatal session cleanup, and focused framing regression tests.

## Best Possible Solution

Keep a single strict bounded parser at the bundled-LSP stdout trust boundary, reject every malformed header line and invalid or oversized frame, preserve valid Content-Type framing, and fail pending requests before terminating only the affected server session.
