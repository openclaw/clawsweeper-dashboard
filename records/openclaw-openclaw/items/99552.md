## Summary

Keep open: current main and v2026.6.11 still drop non-tab/newline/carriage-return C0 control bytes in exec output paths, and the remaining fix needs a maintainer decision on the display-safe sanitizer contract.

## What This Changes

The issue reports that exec output sanitization strips ASCII control characters below 32, making legitimate SSH/ANSI-heavy command output effectively unreadable or placeholder-rendered.

## Best Possible Solution

Define the display-safe exec output contract, then add focused regression coverage through sanitizer, exec runtime, and session rendering so legitimate terminal output remains inspectable without allowing raw control-sequence injection.

## Reproduction Assessment

Yes for the core sanitizer behavior: current main source shows ESC, BEL, backspace, and other non-tab/newline/carriage-return C0 controls are dropped before exec output is stored/rendered. The full blank/image-placeholder rendering symptom still needs a live SSH or agent-flow repro.

## Solution Assessment

Unclear as an implementation direction: raw control preservation would be unsafe, while escaping residual controls or stripping full ANSI sequences before display are plausible safer repairs. A maintainer should settle the display contract before implementation.
