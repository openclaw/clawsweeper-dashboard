## Summary

Keep open: current main and v2026.6.11 still lack a general operator-configurable local media root for the image tool. Current code covers narrower managed-inbound media and channel-scoped iMessage attachment roots, while the broader configurable-root policy remains an open security/product decision with https://github.com/openclaw/openclaw/pull/52951 as a candidate implementation path.

## What This Changes

Request adding an operator-configurable local media root allowlist for the image tool so external iMessage attachment paths can be read without copying them into the workspace.

## Best Possible Solution

Choose one canonical operator-controlled local-root policy, likely tools.fs.roots or a deliberately scoped media-only policy, then wire it through shared media roots, schema/types, docs, and regression tests while preserving managed-inbound and channel-scoped boundaries.

## Reproduction Assessment

Yes, source-level: current main rejects arbitrary outside-root image paths and exposes no mediaLocalRoots/localRoots-style image-tool config field. I did not run a live iMessage reproduction in this read-only review.

## Solution Assessment

No for a one-off tools.image.mediaLocalRoots patch as-is. The safer solution is a single filesystem/media root policy so image tools, outbound media, webchat preview, and workspaceOnly semantics do not grow conflicting allowlists.
