## Summary

Keep open: current `origin/main` and v2026.6.11 still lack a general configurable image/media local-root allowlist. The narrower iMessage attachment-root path is now handled as scoped inbound media, but the requested operator-controlled host-root policy remains a security-sensitive product/config decision, with https://github.com/openclaw/openclaw/pull/52951 still open rather than merged.

## What This Changes

Request to add an operator-configurable local media root allowlist for the image tool so trusted attachment directories outside OpenClaw-managed roots can be read without copying.

## Best Possible Solution

Choose one canonical operator-controlled filesystem/media-root policy, wire it through shared media loading plus schema/docs/tests, and keep scoped channel inbound roots distinct from broad host-local reads.

## Reproduction Assessment

Yes, source-level: current main exposes no configurable media-root field and the image tool resolver still restricts host-local reads to default/workspace roots plus separate scoped inbound roots. I did not run a live iMessage reproduction in this read-only review.

## Solution Assessment

No, not as a narrow per-tool field yet. The safer maintainable path is a single reviewed filesystem/media-root policy so image tools, outbound media, webchat previews, and `workspaceOnly` behavior do not grow conflicting allowlists.
