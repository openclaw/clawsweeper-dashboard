## Summary

Keep open: current main and v2026.6.11 still do not expose a configurable image/media local-root allowlist. Current code has narrower channel-scoped iMessage inbound-root support, but the requested operator-controlled host-root policy remains a security-sensitive product/config decision with an open broader implementation candidate.

## What This Changes

Request a configurable local media root allowlist for the image tool so trusted attachment directories can be read without copying files into the workspace.

## Best Possible Solution

Choose one canonical operator-controlled local-root policy, likely tools.fs.roots or a deliberately scoped media-only policy, then wire it through shared media roots, schema/types, docs, and tests while preserving current managed-inbound and channel-scoped boundaries.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 expose no mediaLocalRoots/localRoots-style config field for the image tool, and current tests still reject outside-root image paths except for scoped channel inbound roots. I did not run a live iMessage reproduction in this read-only review.

## Solution Assessment

No, not as a direct tools.image.mediaLocalRoots patch yet. The safer path is for maintainers to pick a single filesystem/media-root policy so image tools, outbound media, webchat preview, and workspaceOnly semantics do not grow conflicting allowlists.
