## Summary

Keep open: current main and v2026.6.11 still do not expose a configurable image/media local-root allowlist. The narrow iMessage attachment-root path is handled through scoped inbound roots, but the requested operator-controlled host-root policy remains a security-sensitive product/config decision with an open broader candidate PR.

## What This Changes

Request to add a configurable local media root allowlist for the image/media tools so attachments outside default roots can be read without manual copying.

## Best Possible Solution

Choose one canonical, security-reviewed filesystem/media-root policy, wire it through schema, docs, shared media loaders, image/PDF and outbound/webchat paths, and preserve scoped channel inbound roots as a separate boundary.

## Reproduction Assessment

Yes, source-level. Current main routes image-tool local files through fixed/default roots plus scoped inbound roots, and strict config schemas expose no tools.image.mediaLocalRoots or equivalent field.

## Solution Assessment

No for an isolated per-tool config patch. The safer fix is a single reviewed filesystem/media-root policy so image tools, outbound media, webchat previews, and workspaceOnly behavior do not grow conflicting allowlists.
