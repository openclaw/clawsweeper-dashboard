## Summary

Keep open: current main and v2026.6.11 still do not expose a public configurable local-media-root allowlist for image/media tools. The iMessage attachment path has a narrower scoped inbound-root fix, but the broader operator-controlled host-root policy remains a security-sensitive config/product decision.

## What This Changes

The issue requests a configurable allowlist for additional local media roots so image/media tools can read operator-approved attachment directories outside OpenClaw-managed roots.

## Best Possible Solution

Choose one canonical security-reviewed filesystem/media-root policy, keep scoped channel inbound roots separate from broad host-local reads, and wire the accepted policy through schema, docs, shared media loaders, and focused tests.

Rationale: The requested config changes what model-facing media tools may read from the host, and repository policy treats filesystem boundaries plus config/default surfaces as maintainer/security decisions rather than safe autonomous fixes.

Owner confidence: high

Options:

- **Use shared filesystem roots (recommended):** Adopt a single security-reviewed tools.fs.roots-style contract for filesystem tools and media paths so OpenClaw does not grow competing allowlists.
- **Add media-only roots:** Add a narrower media-root config if maintainers want image/PDF/media reads decoupled from read/write/edit filesystem policy, with explicit docs and tests for the split boundary.
- **Keep current boundary:** Continue requiring copies, symlinks, managed inbound media, or scoped channel attachment roots instead of persistent host-root expansion.

## Reproduction Assessment

Yes, source-level. Current main routes image local paths through fixed/default roots plus scoped inbound roots, and strict public schemas expose no mediaLocalRoots-style field.

## Solution Assessment

No for an ad hoc per-tool config patch. The safer maintainable solution is a single reviewed filesystem/media-root policy so image tools, outbound media, webchat previews, and workspaceOnly behavior do not grow conflicting allowlists.
