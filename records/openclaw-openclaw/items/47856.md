## Summary

Keep open: current main and v2026.6.11 still lack a public configurable image/media local-root setting. The scoped iMessage attachment-root path is now handled, but the requested operator-controlled local-root policy remains a security-sensitive product/config decision with an open broader implementation candidate.

## What This Changes

The issue requests a `tools.image.mediaLocalRoots`-style config option so the image tool can read additional operator-approved local directories such as iMessage attachment folders.

## Best Possible Solution

Choose one canonical operator-controlled local-root policy, likely `tools.fs.roots` or a deliberately scoped media-only policy, then wire it through shared media roots, schema/types, docs, and regression tests while preserving managed-inbound and channel-scoped boundaries.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 reject outside-root image paths and expose no `mediaLocalRoots` or equivalent config field. I did not run a live iMessage reproduction in this read-only review.

## Solution Assessment

No for a direct `tools.image.mediaLocalRoots` patch yet. The safer solution is for maintainers to pick one filesystem/media root policy so image tools, outbound media, webchat preview, and `workspaceOnly` semantics do not grow conflicting allowlists.
