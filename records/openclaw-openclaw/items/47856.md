## Summary

Keep open: current main still has no public `mediaLocalRoots` or equivalent image-tool config surface. Current code partially addresses the iMessage case through channel-scoped inbound roots and managed inbound media, but the broader operator-controlled local-root policy remains a security-sensitive product decision with an open broader implementation candidate.

## What This Changes

Request to add a configurable local media root allowlist so the image tool can read trusted attachment directories, especially iMessage attachment folders, without copying files into the workspace.

## Best Possible Solution

Choose one canonical operator-controlled local-root policy, likely `tools.fs.roots` or a deliberately scoped media-only policy, then wire it through shared media roots, schema/types, docs, and tests while preserving current managed-inbound and channel-scoped boundaries.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 reject arbitrary outside-root image paths and expose no public `mediaLocalRoots` or local-root config field. I did not run a live iMessage reproduction in this read-only review.

## Solution Assessment

No, not as a direct `tools.image.mediaLocalRoots` patch yet. The safer maintainable path is for maintainers to choose a single filesystem/media root policy so image tools, outbound media, webchat, and `workspaceOnly` semantics do not grow conflicting allowlists.
