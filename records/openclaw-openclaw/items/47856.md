## Summary

Keep open: current main and v2026.6.11 still lack a general configurable image/media local-root allowlist. A narrower iMessage attachment-root path is now implemented, but the requested operator-controlled host-root policy remains a security-sensitive product/config decision with an open broader candidate PR.

## What This Changes

Request to add a configurable local media root allowlist so the image tool can read trusted attachment directories outside the default workspace/media roots.

## Best Possible Solution

Choose one canonical operator-controlled filesystem/media-root policy, wire it through shared media loaders and config schema/docs/tests, and keep scoped channel inbound roots separate from broad host-local reads.

## Reproduction Assessment

Yes, source-level. Current main and v2026.6.11 reject untrusted outside-root image paths and expose no general mediaLocalRoots/localRoots-style config field, though scoped iMessage attachment roots now work when the image tool has channel/account context.

## Solution Assessment

No for a direct per-tool config patch yet. The maintainable fix is a single reviewed filesystem/media-root policy so image tools, outbound media, webchat previews, and workspaceOnly behavior do not grow conflicting allowlists.
