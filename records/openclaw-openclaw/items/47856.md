## Summary

Keep open: current main and v2026.6.11 still do not provide a configurable image/media local-root allowlist. The original iMessage attachment-root symptom is partly addressed through channel-scoped inbound roots, but the broader request remains a security-sensitive config/product decision and is only covered by an open, conflicting broader filesystem-roots PR.

## What This Changes

Request to add a `tools.image.mediaLocalRoots` or similar `openclaw.json` field so image/media tools can read operator-approved local directories outside the default roots.

## Best Possible Solution

Choose one canonical operator-controlled filesystem/media-root policy, keep channel inbound attachment roots separate from broad host-local reads, and wire the accepted policy through schema, docs, shared media loaders, and focused security tests.

## Reproduction Assessment

Yes. Source inspection shows current main rejects external local media paths unless they are under fixed/default roots or scoped inbound roots, and current schemas expose no configurable image/media local-root field.

## Solution Assessment

No for an ad hoc per-tool config patch. The safer maintainable solution is a single reviewed filesystem/media-root policy so image tools, outbound media, webchat previews, and `workspaceOnly` behavior do not grow conflicting allowlists.
