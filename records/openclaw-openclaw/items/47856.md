## Summary

Keep open: current main and v2026.6.11 still lack a general configurable image/media local-root allowlist. The narrower iMessage attachment-root path is now handled through scoped inbound roots, but the requested operator-controlled host-root policy remains an unresolved security-sensitive product/config decision with an open broader candidate PR at https://github.com/openclaw/openclaw/pull/52951.

## What This Changes

The issue requests a configurable allowlist for image/media local roots so attachment-heavy workflows can read trusted host media paths without manual copies.

## Best Possible Solution

Choose one canonical operator-controlled filesystem/media-root policy, wire it through shared media loaders and config schema/docs/tests, and keep scoped channel inbound roots separate from broad host-local reads.

## Reproduction Assessment

Yes, from source inspection. Current main and v2026.6.11 expose no general configurable local-root field, and the image tool still feeds fixed local roots into the shared media loader while outside-root paths are rejected.

## Solution Assessment

No for a narrow per-tool config patch by itself. The maintainable direction is one reviewed filesystem/media-root policy so image tools, outbound media, webchat previews, and workspace-only behavior do not grow conflicting allowlists.
