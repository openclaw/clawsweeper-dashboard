## Summary

Keep open: current main and v2026.6.11 still do not expose a configurable image/media local-root allowlist. The remaining work is valid, but it is a security-sensitive product/config decision because it would expand host-local file access and overlaps the still-open `tools.fs.roots` PR.

## What This Changes

The issue requests an OpenClaw config option that extends the image tool local-media allowlist for iMessage attachment paths and similar local media directories.

## Best Possible Solution

Choose one canonical operator-controlled root policy, likely through `tools.fs.roots` or an explicitly scoped media policy, then land schema/types/docs/tests for image/PDF local media, iMessage inbound attachments, workspaceOnly behavior, and security expectations.

## Reproduction Assessment

Yes, source-level: current tests and implementation show outside-workspace local images are rejected and channel attachment roots stay separate from broad local roots. I did not run a live iMessage flow in this read-only cleanup pass.

## Solution Assessment

No, not as a direct `tools.image.mediaLocalRoots` patch yet. The safer fix is a maintainer-approved canonical filesystem/media root policy because this affects security boundaries and overlaps the open filesystem-roots PR.
