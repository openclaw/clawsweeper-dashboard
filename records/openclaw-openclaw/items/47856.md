## Summary

Keep open: current main and v2026.6.11 still lack a public configurable media local-root allowlist. The narrow iMessage attachment-root bug is fixed through scoped inbound roots, but the broader requested host-root policy remains a security/product decision with an open broader PR candidate.

## What This Changes

Request to add a configurable local-root allowlist for image/media tools so operators can allow selected host attachment directories without copying files into the workspace.

## Best Possible Solution

Choose one canonical operator-controlled filesystem/media-root policy, keep channel inbound roots scoped, and wire the accepted policy through schema, docs, shared media loaders, and focused security tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw accept a broad operator-controlled host-local media/filesystem root policy for model-facing media reads, and if so should it be the shared tools.fs.roots design rather than a per-tool mediaLocalRoots field?

Rationale: The requested behavior changes a host filesystem read boundary and overlaps an open broad PR; automation cannot choose the permanent security/config contract safely.

Likely owner: jacobtomlinson

Owner reason: Recent merged work on the central local-root policy makes this the strongest code-history owner for the design choice.

Owner confidence: medium

Options:

- **Adopt one shared root policy (recommended):** Use tools.fs.roots or an equivalent shared schema across image/PDF/media/webchat/outbound paths, with explicit validation, docs, and upgrade/security tests.
- **Add a narrow media-only knob:** Implement a smaller mediaLocalRoots field, but accept the maintenance risk of a separate trust boundary from other host-file policy paths.
- **Keep current scoped behavior:** Do not add arbitrary host roots; users keep copying/symlinking files or rely only on channel-scoped inbound roots such as iMessage attachmentRoots.

## Reproduction Assessment

Yes. Source inspection shows the image tool validates local paths through fixed/default roots plus scoped inbound roots, while current schemas expose no tools.image.mediaLocalRoots or equivalent config field.

## Solution Assessment

No for an ad hoc per-tool config patch. The safer maintainable solution is one reviewed filesystem/media-root policy so image tools, outbound media, webchat previews, and workspaceOnly behavior do not grow conflicting allowlists.
