## Summary

Keep open: current main and v2026.6.11 still do not expose a general configurable local media root for the image tool. Current code has narrower support for managed inbound media and channel-scoped iMessage attachment roots, but the requested operator-controlled local-root policy remains a security-sensitive product/config decision with https://github.com/openclaw/openclaw/pull/52951 as an open, conflicting broader candidate.

## What This Changes

The issue requests an operator-configurable allowlist for image-tool local media roots so paths such as iMessage attachments can be read without copying files into the workspace.

## Best Possible Solution

Choose one canonical operator-controlled local-root policy, likely tools.fs.roots or a deliberately scoped media-only policy, then wire it through shared media roots, schema/types, docs, and tests while preserving current managed-inbound and channel-scoped boundaries.

## Reproduction Assessment

Yes, source-level: current main rejects arbitrary outside-root image paths and exposes no mediaLocalRoots/localRoots-style config field. I did not run a live iMessage reproduction in this read-only review.

## Solution Assessment

No, not as a direct tools.image.mediaLocalRoots patch yet. The safer path is for maintainers to pick a single filesystem/media-root policy so image tools, outbound media, webchat preview, and workspaceOnly semantics do not grow conflicting allowlists.
