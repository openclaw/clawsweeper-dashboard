## Summary

Keep open: current main and v2026.6.11 still do not expose a general configurable local media root for the image/media tools. Current code has narrower scoped iMessage inbound-root support and managed inbound-media handling, but the requested operator-controlled local-root policy remains an unresolved security-sensitive product/config decision with an open, conflicting broader implementation candidate.

## What This Changes

Request to add a configurable image/media local-root allowlist so trusted attachment-heavy workflows can read host-local media paths without copying them into an OpenClaw workspace.

## Best Possible Solution

Choose one canonical operator-controlled local-root policy, likely tools.fs.roots or a deliberately scoped media-only policy, then wire it through shared media roots, schema/types, docs, and tests while preserving current managed-inbound and channel-scoped boundaries.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 reject arbitrary outside-root image paths and expose no configurable local-root field. I did not run a live iMessage reproduction in this read-only review.

## Solution Assessment

No for a direct one-off tools.image.mediaLocalRoots patch. The safer maintainable path is for maintainers to pick one filesystem/media root policy so image tools, outbound media, webchat preview, and workspaceOnly semantics do not grow conflicting allowlists.
