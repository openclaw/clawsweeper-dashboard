## Summary

Keep open: current main and v2026.6.11 still do not expose a public configurable local-media-root allowlist for image/media tools. The narrow iMessage attachment-root path is partly handled through scoped inbound roots, but the broader host-root policy remains a security-sensitive product/config decision.

## What This Changes

Request to add a configurable media local-root allowlist so the image tool can read trusted attachment directories outside OpenClaw-managed roots.

## Best Possible Solution

Choose one canonical security-reviewed filesystem/media-root policy, keep scoped channel inbound roots separate from broad host-local reads, and wire the accepted policy through schema, docs, shared media loaders, and focused tests.

Rationale: The request changes what model-facing media tools may read from the host, and repository policy treats filesystem boundaries plus config/default surfaces as security-sensitive product decisions rather than safe autonomous fixes.

Owner confidence: high

Options:

- **Use shared filesystem roots (recommended):** Adopt a single security-reviewed tools.fs.roots-style contract for filesystem tools and media paths so OpenClaw does not grow competing allowlists.
- **Add media-only roots:** Add a narrower media-root config only if maintainers want image/PDF/media reads decoupled from read/write/edit filesystem policy, with explicit docs and split-boundary tests.
- **Keep current boundary:** Continue requiring managed inbound media, scoped channel attachment roots, copies, or symlinks instead of persistent host-root expansion.

## Reproduction Assessment

Yes, at source level. Current main routes image local paths through fixed/default roots plus scoped inbound roots, and strict public schemas expose no mediaLocalRoots-style field.

## Solution Assessment

No for an ad hoc per-tool config patch. The safer maintainable solution is a single reviewed filesystem/media-root policy so image tools, outbound media, webchat previews, and workspaceOnly behavior do not grow conflicting allowlists.
