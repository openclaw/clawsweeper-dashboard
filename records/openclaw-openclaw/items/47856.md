## Summary

Keep open: current main and the latest release still lack a general operator-configurable local media root for the image tool. Narrower iMessage attachment-root handling and managed inbound-media exceptions exist, but the requested host-local allowlist remains a security-sensitive product/config decision with an open broader implementation candidate.

## What This Changes

The issue requests a `tools.image.mediaLocalRoots`-style config option so the image tool can read operator-approved attachment directories outside the fixed OpenClaw-managed roots.

## Best Possible Solution

Choose one canonical operator-controlled local-root policy, likely the broader `tools.fs.roots` direction or a deliberately scoped media-only policy, then wire it through shared media roots, config schema/types, docs, and image/PDF/local-media tests while preserving channel-scoped inbound boundaries.

## Reproduction Assessment

Yes. Source inspection shows local image paths outside the current managed/config/media/workspace/sandbox roots are rejected by the image tool path, and the requested config key is absent; I did not run a live iMessage account flow in this read-only review.

## Solution Assessment

No, not as a direct one-off image-tool field yet. The safer maintainable path is for maintainers to pick one filesystem/media root policy so image tools, outbound media, prompt-image loading, and `workspaceOnly` semantics do not grow competing allowlists.
