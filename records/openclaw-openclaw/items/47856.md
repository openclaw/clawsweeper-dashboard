## Summary

Close as implemented: current main and v2026.6.11 solve the reported iMessage and managed inbound-media image-tool path problem through scoped channel inbound roots, without adding a broad host-root allowlist.

## What This Changes

The issue requests a configurable image/media local-root allowlist so iMessage and other local attachment paths outside default OpenClaw roots can be analyzed without copying them into the workspace.

## Best Possible Solution

Keep the shipped scoped inbound-root implementation for iMessage and managed inbound media; broader arbitrary host-root access should continue through the separate filesystem-root product/security review.

## Reproduction Assessment

No current-main failure remains for the iMessage and managed inbound-media paths. The merged PR has before/after proof for the historical iMessage rejection, and current regression tests cover configured and wildcard attachment roots plus managed inbound media.

## Solution Assessment

Yes for this issue's central workflow. The shipped solution reuses channel-owned attachment-root contracts and keeps them separate from broad `localRoots`, which is safer than adding an unconstrained `tools.image.mediaLocalRoots` knob here.
