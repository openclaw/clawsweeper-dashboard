## Summary

Keep open: current main and v2026.6.11 still lack a public configurable local media root for the image tool, and the remaining work is a security-sensitive product/config decision rather than a narrow bug fix.

## What This Changes

Request to add an operator-configurable allowlist for image-tool local media roots so iMessage and similar attachment paths can be read without copying files into the workspace.

## Best Possible Solution

Pick one canonical operator-controlled local-root policy, likely tools.fs.roots or a deliberately scoped media-only policy, then wire it through shared media roots, schema/types, docs, and tests while preserving managed-inbound and channel-scoped boundaries.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 reject outside-root image paths and expose no mediaLocalRoots/localRoots-style config field. I did not run a live iMessage reproduction in this read-only review.

## Solution Assessment

No for a direct tools.image.mediaLocalRoots patch yet. The safer solution is a single filesystem/media root policy so image tools, outbound media, webchat preview, and workspaceOnly semantics do not grow competing allowlists.
