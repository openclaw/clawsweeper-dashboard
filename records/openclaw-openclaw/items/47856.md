## Summary

Keep open: current main and v2026.6.11 still do not expose a configurable image/media local-root allowlist. Current code has scoped iMessage inbound-root support and managed inbound-media handling, but the broader operator-controlled host-root policy remains a security-sensitive product decision with an open broader implementation candidate.

## What This Changes

Request a configurable `tools.image.mediaLocalRoots`-style setting so image/media tools can read trusted local attachment directories outside OpenClaw-managed roots.

## Best Possible Solution

Choose one canonical, security-reviewed operator-controlled root contract, likely `tools.fs.roots` or a deliberately scoped media-only policy, then wire schema, docs, shared media roots, image/PDF loading, and regression tests through that single contract.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 reject outside-root image paths and expose no `mediaLocalRoots` or `localRoots` config field. I did not run a live iMessage reproduction in this read-only review.

## Solution Assessment

No, not as a standalone `tools.image.mediaLocalRoots` patch yet. The safer fix is a single local-media/filesystem root policy so image tools, outbound media, webchat preview, and `workspaceOnly` semantics do not grow conflicting allowlists.
