## Summary

Keep open: current main and v2026.6.11 still lack a configurable image/media local-root allowlist. The original iMessage attachment case is partly handled through scoped inbound roots, but the requested operator-controlled host-root policy remains a security-sensitive config/product decision with an open broader candidate implementation.

## What This Changes

Request a `tools.image.mediaLocalRoots` or similar config field so image/media tools can read additional operator-approved local directories such as iMessage attachment roots.

## Best Possible Solution

Adopt one security-reviewed root policy for media and filesystem access, keep scoped channel inbound roots separate, and wire the accepted contract through schema, docs, shared media loaders, and focused tests.

## Reproduction Assessment

Yes, source-level. Current main resolves image-tool local roots from fixed defaults/workspace and strict config schemas expose no `tools.image.mediaLocalRoots`, `tools.media.localRoots`, or `tools.fs.roots` equivalent.

## Solution Assessment

No for an ad hoc per-tool config field. The safer solution is a single reviewed filesystem/media-root contract so image tools, outbound media, webchat previews, and `workspaceOnly` behavior do not grow conflicting allowlists.
