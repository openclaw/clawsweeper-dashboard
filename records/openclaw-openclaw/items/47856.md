## Summary

Keep open: current main and latest release still lack a public configurable image/media local-root allowlist. The narrower iMessage attachment-root regression is fixed through scoped inbound roots, but the requested operator-controlled host-root policy remains a security-sensitive config/product decision with an open broader candidate PR.

## What This Changes

Request to add an opt-in config surface for image/media tools to allow additional host-local media roots, especially iMessage attachment directories.

## Best Possible Solution

Adopt one canonical operator-controlled filesystem/media-root policy, keep scoped channel inbound roots separate from broad host-local reads, and wire the accepted policy through schema, docs, shared media loaders, and focused tests.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 route image-tool local media through fixed/default roots plus scoped inbound roots, and the strict public schemas expose no tools.image.mediaLocalRoots or equivalent persistent extra-root field.

## Solution Assessment

No for an ad hoc per-tool config patch. The safer maintainable solution is a single reviewed filesystem/media-root policy so image tools, outbound media, webchat previews, and workspaceOnly behavior do not grow conflicting allowlists.
