## Summary

Keep open: current main and the latest release still do not expose a configurable image/media local-root allowlist. The narrow iMessage attachment-root case is now handled through scoped inbound roots, but the broader host-root config remains a security-sensitive product decision that overlaps an open, conflicting filesystem-roots PR.

## What This Changes

The issue requests a configurable media local-root allowlist for the image tool so local attachment paths can be read without copying them into the workspace.

## Best Possible Solution

Choose one central operator-controlled filesystem/media-root policy, keep scoped channel inbound roots separate from broad host-local reads, and wire the accepted policy through schema, docs, shared media loaders, and focused tests.

Question: Should OpenClaw accept an operator-configured host local-root policy for media/image reads, and should that policy be the broader tools.fs.roots design or a narrower media-only config?

Rationale: This changes what model-facing tools may read from the host and the repository policy sets a high bar for new config and filesystem access surfaces, so automation cannot choose the trust boundary on its own.

Owner confidence: medium

Options:

- **Adopt central tools.fs.roots policy (recommended):** Use the broader filesystem-root design, require security review and upgrade proof, and have media/image/PDF/webchat consume that single policy.
- **Add narrow media-only roots:** Introduce a smaller media-local-root field with explicit validation, but accept the risk of a separate trust boundary from filesystem tools.
- **Keep current scoped roots only:** Decline broad host roots for now and keep using workspace/default roots plus channel-owned inbound attachment roots.

## Reproduction Assessment

Yes, source-level. Current main routes image paths through fixed/default roots plus scoped inbound roots, while strict config schemas expose no tools.image.mediaLocalRoots or equivalent field.

## Solution Assessment

No for the proposed per-tool config shape. The safer solution is a single reviewed filesystem/media-root policy so image tools, outbound media, webchat previews, and workspaceOnly behavior do not grow conflicting allowlists.
