## Summary

Keep open: current main and v2026.6.11 still lack a public image-tool mediaLocalRoots-style config field. Main now has narrower iMessage inbound-root and managed-inbound-media support, but the remaining request is an operator-controlled host filesystem read policy that needs maintainer product and security direction.

## What This Changes

Request to add a configurable local media root allowlist for the image tool so iMessage and other attachment paths outside OpenClaw-managed roots can be read without copying.

## Best Possible Solution

Choose one canonical operator-controlled local-root policy, likely tools.fs.roots or a deliberately scoped media-only policy, and wire it through shared media roots, schema/types, docs, and tests while preserving managed-inbound and channel-scoped boundaries.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 reject outside-root image paths unless they are managed inbound media or channel-scoped inbound roots, and no mediaLocalRoots/localRoots-style config field is accepted. I did not run a live iMessage reproduction in this read-only review.

## Solution Assessment

No, not as a direct tools.image.mediaLocalRoots patch yet. The safer path is for maintainers to pick a single filesystem/media-root policy so image tools, outbound media, webchat preview, and workspaceOnly semantics do not grow conflicting allowlists.
