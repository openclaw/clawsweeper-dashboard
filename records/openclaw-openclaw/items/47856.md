## Label Justifications

- `P2`: This is a bounded configurability improvement with real attachment-workflow friction, but it is not a core outage, data-loss emergency, or release-blocking first-run failure.
- `impact:security`: The requested allowlist would intentionally expand trusted host-local filesystem roots that media tools may read.
- `impact:ux-friction`: Affected users can proceed by copying or symlinking media into allowed roots, but that creates repeated manual steps for attachment-heavy workflows.

## Summary

Keep open: current main still lacks a public configurable local-root allowlist for the image/media tools; the iMessage-specific attachment-root path is now partly handled through scoped inbound roots, but the requested operator-controlled host-root policy remains a security-sensitive product decision.

## What This Changes

Request to add a config option such as `tools.image.mediaLocalRoots` so image/media tools can read operator-approved local attachment directories outside the default roots.

## Best Possible Solution

Choose one canonical operator-controlled filesystem/media-root policy, keep scoped channel inbound roots separate from broad host-local reads, and wire the accepted policy through schema, docs, shared media loaders, and focused security tests.

## Solution Assessment
