## Summary

Keep open: current main and v2026.6.11 still do not expose a general configurable media local-root allowlist for the image tool. Current code has narrower iMessage inbound-root and managed-media handling, but the requested operator-controlled host-root policy remains a security-sensitive config/product decision, with https://github.com/openclaw/openclaw/pull/52951 as the broad open implementation candidate.

## What This Changes

The issue requests an operator-configurable media local roots allowlist for the image tool so iMessage and other attachment paths can be read without copying into an OpenClaw-managed directory.

## Best Possible Solution

Choose one shared, security-reviewed root-policy contract, likely by landing or narrowing tools.fs.roots, then wire image/PDF media reads, schemas, docs, and tests through that contract instead of adding an image-only config key.

## Reproduction Assessment

Yes, at source level: the image tool still passes a fixed localRoots list to loadWebMedia, and the strict tools.fs schema exposes only workspaceOnly. I did not run a live iMessage flow for this read-only review.

## Solution Assessment

No for a standalone tools.image.mediaLocalRoots knob: the safer maintainable path is one shared filesystem/media-root policy with schema, docs, and security tests. The current open tools.fs.roots PR is the closest candidate but still needs maintainer review or narrowing before this issue can close.
