## Summary

Keep open: current main and v2026.6.11 have the narrower iMessage inbound-root fix, but they still do not expose an operator-configurable local media root policy for the image tool. The remaining work is a security-sensitive config/product decision, and the broader candidate PR is still open rather than merged.

## What This Changes

The issue requests an operator-configurable local media root allowlist for image-tool access to attachment paths outside the default OpenClaw-managed directories.

## Best Possible Solution

Choose one canonical security-reviewed root policy, likely the open tools.fs.roots direction or a deliberately scoped media-only contract, then wire it through shared media roots, schema/types, docs, and tests while preserving current managed-inbound and channel-scoped boundaries.

## Reproduction Assessment

Yes, source-level for the general requested config surface: current media roots are fixed to OpenClaw-managed directories plus workspace/channel inbound roots, and the strict filesystem config schema still accepts only workspaceOnly. I did not run a live iMessage or Docker reproduction in this read-only review.

## Solution Assessment

No for a direct tools.image.mediaLocalRoots patch yet. The safer solution is one canonical filesystem/media-root policy so image tools, outbound media, webchat preview, and workspaceOnly semantics do not grow conflicting allowlists.
