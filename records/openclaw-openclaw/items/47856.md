## Summary

Keep open: current main fixes the narrower iMessage attachment-root path through scoped inbound roots, but it still lacks any public configurable host-local media-root allowlist for the image tool. The remaining request is a security-sensitive product/config decision, and the broader candidate implementation is still open and conflicting.

## What This Changes

The issue requests a configurable media local-root allowlist so the image tool can read operator-approved local attachment directories outside the default OpenClaw roots.

## Best Possible Solution

Choose one canonical operator-controlled filesystem/media-root policy, keep scoped channel inbound roots separate from broad host-local reads, and wire the accepted policy through schema, docs, shared media loaders, and focused tests.

## Reproduction Assessment

Yes, source-level. Current main has fixed/default media roots plus scoped inbound roots, and the strict config schemas expose no tools.image.mediaLocalRoots or equivalent persistent extra-root field.

## Solution Assessment

No for an ad hoc per-image-tool config field. The safer maintainable solution is a single reviewed filesystem/media-root policy so image tools, outbound media, webchat previews, and workspaceOnly behavior do not grow conflicting allowlists.
