## Summary

Keep open: current main and v2026.6.11 still lack a general configurable image-tool local media root, while the narrower iMessage inbound attachment-root path is handled separately. The remaining request is a security-sensitive config/product decision, with https://github.com/openclaw/openclaw/pull/52951 as the broader open implementation candidate.

## What This Changes

The issue requests an operator-configurable local media root allowlist for the image tool so iMessage and similar attachment paths outside OpenClaw-managed roots can be read without manual copying.

## Best Possible Solution

Choose the canonical host-local media/filesystem root policy, likely by narrowing or landing the tools.fs.roots direction, then align schema, docs, image/PDF/local-media tests, and security review around that single boundary.

## Reproduction Assessment

Yes, source-level: current main passes image-tool local paths through resolveMediaToolLocalRoots, and that resolver has no general configurable root input. I did not run a live iMessage image-tool turn in this read-only review.

## Solution Assessment

Unclear as a final product choice: a media-only config could solve the reported workflow, but the broader tools.fs.roots candidate may be the cleaner owner boundary if maintainers accept it.
