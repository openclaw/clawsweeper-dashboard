## Summary

Keep open: current main still lacks a general operator-configurable image/media local-root allowlist. The narrower iMessage attachment-root symptom is fixed through scoped inbound roots, but the requested broad host-root policy remains a security-sensitive config/product decision and the overlapping implementation PR is still open and conflicting.

## What This Changes

Request to add a configurable image/media local-root allowlist so trusted external attachment directories can be read without copying files into the workspace.

## Best Possible Solution

Choose one canonical, security-reviewed local filesystem/media-root policy with narrow root validation, safe defaults, shared resolver/schema/docs/tests, and clear interaction with channel inbound roots and `workspaceOnly`.

## Reproduction Assessment

Yes, source-level. Current main and v2026.6.11 expose no general media-local-root config field and tests still reject arbitrary outside-root image paths, while scoped iMessage attachment roots now work only with channel/account context.

## Solution Assessment

No for an ad hoc per-tool config patch. The best fix is a single reviewed filesystem/media-root policy so image tools, outbound media, webchat preview, and workspace-only behavior do not grow competing allowlists.
