## Summary

Keep open: current main and v2026.6.11 have narrower iMessage attachment-root and managed-inbound media support, but they still do not expose a general configurable local-root policy for the image tool. The remaining work is a security-sensitive product/config decision, with https://github.com/openclaw/openclaw/pull/52951 as the broader open implementation candidate.

## What This Changes

Request to add an operator-configurable local media root allowlist for the image tool so attachment paths outside OpenClaw-managed directories can be read without manual copies.

## Best Possible Solution

Choose one canonical operator-controlled local-root policy, likely the shared tools.fs.roots design or a deliberately scoped media-only policy, then wire it through shared media roots, schema/types, docs, and regression tests while preserving current managed-inbound and channel-scoped boundaries.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 reject outside-root image paths and expose no mediaLocalRoots/localRoots-style config field. I did not run a live iMessage reproduction in this read-only review.

## Solution Assessment

No for a direct tools.image.mediaLocalRoots patch yet. The safer path is for maintainers to pick one filesystem/media root policy so image tools, outbound media, webchat preview, and workspaceOnly semantics do not grow competing allowlists.
