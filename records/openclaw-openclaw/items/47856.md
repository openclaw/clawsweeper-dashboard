## Summary

Keep open: current main and v2026.6.11 still do not expose a general configurable local-media root for the image tool. Main has narrower iMessage inbound attachment-root support, but the requested operator-controlled local-root policy remains a security-sensitive config/product decision, and the broader open implementation candidate is still unmerged and conflicting.

## What This Changes

Request to add an operator-configurable local-media allowlist for the image tool so iMessage and other attachment paths outside default roots can be analyzed without manual copying.

## Best Possible Solution

Choose one canonical operator-controlled local-root policy, likely tools.fs.roots or a deliberately scoped media-only contract, then wire image/PDF/outbound media through it with schema, docs, and regression tests that preserve safe defaults.

## Reproduction Assessment

Yes at source level: current main rejects outside-root image paths and exposes no general mediaLocalRoots/localRoots config field. I did not run a live iMessage flow in this read-only review.

## Solution Assessment

No as a direct tools.image.mediaLocalRoots patch without maintainer direction. The safer solution is a single root-policy contract so image tools, PDF tools, outbound media, webchat preview, and workspaceOnly semantics do not grow conflicting allowlists.
