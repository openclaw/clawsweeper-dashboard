## Summary

Keep open: current main and v2026.6.11 still do not expose a general configurable local media root for the image tool. The iMessage attachment-root subset is fixed through scoped inbound roots, but the requested operator-controlled local-root policy remains a security-sensitive product/config decision with an open broader implementation candidate.

## What This Changes

The issue requests an operator-configurable local media root allowlist for the image tool so external attachment paths such as iMessage media can be read without manual copying.

## Best Possible Solution

Define a maintainer-approved local-root policy, either by repairing/narrowing https://github.com/openclaw/openclaw/pull/52951 or by designing a smaller media-only config with schema, docs, and tests for `workspaceOnly`, managed inbound media, iMessage inbound roots, and upgrade behavior.

## Reproduction Assessment

Yes, source-level: current main still has no configurable image/media local-root field and tests assert rejection for arbitrary non-workspace local image paths. I did not run a live iMessage reproduction in this read-only review.

## Solution Assessment

Unclear: the requested `tools.image.mediaLocalRoots` shape is plausible, but it may duplicate or conflict with the broader `tools.fs.roots` policy now under review. The best fix needs maintainer choice on the filesystem/media security boundary first.
