## Summary

Keep open: current main and v2026.6.11 still lack a general configurable media-local-root allowlist for the image/media tools. The narrower iMessage attachment-root path is implemented, but the requested operator-controlled host-root policy remains a security-sensitive product/config decision, with https://github.com/openclaw/openclaw/pull/52951 still open and conflicting.

## What This Changes

The issue requests a configurable image/media local-root allowlist so trusted attachment directories outside OpenClaw-managed roots can be used without manually copying files into the workspace.

## Best Possible Solution

Choose one canonical operator-controlled filesystem/media-root policy, validate and document its security boundary, then wire that policy through shared media loaders, image/PDF tools, outbound media, and preview paths without duplicating per-tool allowlists.

## Reproduction Assessment

Yes, source-level. Current main’s resolver and tests show outside-root image paths are still rejected, while the strict config schemas expose no `mediaLocalRoots`, `localRoots`, or `tools.fs.roots` field on main.

## Solution Assessment

No for a direct per-tool config patch yet. The maintainable solution is one reviewed filesystem/media-root policy so image tools, outbound media, webchat previews, and `workspaceOnly` semantics do not grow conflicting allowlists.
