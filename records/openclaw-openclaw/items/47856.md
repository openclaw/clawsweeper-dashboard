## Summary

Keep open: current main and v2026.6.11 still lack a configurable local media-root allowlist for the image tool. The narrower iMessage attachment-root path has related closed work, but this issue’s broader operator-controlled host-root policy remains a security-sensitive product/config decision with https://github.com/openclaw/openclaw/pull/52951 as the active candidate implementation path.

## What This Changes

The issue requests a configurable media local-root allowlist so the image tool can read operator-approved paths such as iMessage attachment directories outside the default workspace/media roots.

## Best Possible Solution

Land, revise, or reject one canonical security-reviewed root policy that covers image, PDF, outbound media, and prompt-image access consistently, rather than adding an image-only allowlist that creates a second source of truth.

## Reproduction Assessment

Yes for the source-level limitation: current main still resolves image-tool local roots from default/workspace roots and has no accepted `tools.image.mediaLocalRoots`, `tools.mediaLocalRoots`, or `tools.fs.roots` config surface. I did not run a live iMessage attachment flow for this read-only review.

## Solution Assessment

No for the originally proposed image-only key as the best final shape. The safer maintainable solution is a single maintainer-approved filesystem/media-root policy that preserves safe defaults and applies consistently across local media consumers.
