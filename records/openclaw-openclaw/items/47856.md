## Summary

Keep open: current main and v2026.6.11 still lack an operator-configurable media local-root allowlist for the image tool. The scoped iMessage attachment-root bug is fixed through inbound roots, but the broader request remains a security-sensitive config/product decision and overlaps the open broader filesystem-roots candidate.

## What This Changes

Request to add an operator-configurable media local-root allowlist for the image tool so attachment directories outside OpenClaw-managed roots can be read without manual copying.

## Best Possible Solution

Adopt one centrally reviewed opt-in filesystem/media-root policy, keep channel inbound roots scoped, and wire the accepted policy through schema, docs, shared media loaders, and focused security tests.

## Reproduction Assessment

Yes. Source inspection shows the image tool validates through fixed/default roots plus scoped inbound roots, while current schemas expose no `mediaLocalRoots`-style config field.

## Solution Assessment

No for an ad hoc per-tool config patch. The more maintainable solution is a single reviewed filesystem/media-root policy so image tools, outbound media, webchat previews, and `workspaceOnly` behavior do not grow conflicting allowlists.
