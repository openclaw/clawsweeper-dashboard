## Summary

Keep open: current main and v2026.6.11 still do not expose a configurable image/media local-root allowlist. The narrower iMessage attachment-root bug is now handled through scoped inbound roots, but the requested operator-controlled host-root policy remains a security-sensitive product/config decision with an open broader implementation candidate.

## What This Changes

Request to add an opt-in configurable local media root allowlist so the image tool can read trusted attachment directories outside the default OpenClaw roots.

## Best Possible Solution

Choose one canonical operator-controlled root policy, likely tools.fs.roots or a deliberately scoped media-only variant, then wire it through shared media roots, schema/types, docs, and regression tests while preserving scoped inbound-root and workspaceOnly boundaries.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 reject outside-root image paths and expose no mediaLocalRoots/localRoots-style config field. I did not run a live iMessage reproduction in this read-only review.

## Solution Assessment

No for a direct per-tool tools.image.mediaLocalRoots patch as the default answer. The safer path is a single maintainer-approved filesystem/media root policy so image tools, outbound media, webchat preview, and workspaceOnly semantics do not grow conflicting allowlists.
