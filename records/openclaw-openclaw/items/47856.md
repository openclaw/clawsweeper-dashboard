## Summary

Keep open: current main and v2026.6.11 still lack a configurable image/media local-root allowlist. The narrower iMessage attachment-root path is now handled through scoped inbound roots, but the requested operator-controlled host-root policy remains a security-sensitive product/config decision with an open broader candidate PR.

## What This Changes

The issue requests an operator-configurable allowlist such as `tools.image.mediaLocalRoots` so the image tool can read local attachment directories outside the built-in allowed roots.

## Best Possible Solution

Choose one canonical operator-controlled filesystem/media-root policy, keep scoped channel inbound roots separate from broad host-local reads, and wire the accepted policy through schema, docs, shared media loaders, and focused tests.

## Reproduction Assessment

Yes. Source inspection shows the image tool validates local paths through fixed/default roots plus scoped inbound roots, while current schemas expose no `tools.image.mediaLocalRoots` or equivalent config field.

## Solution Assessment

No for an ad hoc per-tool config patch. The safer maintainable solution is a single reviewed filesystem/media-root policy so image tools, outbound media, webchat previews, and `workspaceOnly` behavior do not grow conflicting allowlists.
