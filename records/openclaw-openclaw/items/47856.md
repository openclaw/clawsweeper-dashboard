## Summary

Keep open: current main and v2026.6.11 still lack a general operator-configurable local media root policy for the image tool. Current code now covers narrower managed inbound media and scoped iMessage attachment roots, but the requested config surface remains a security-sensitive product decision with an open broader implementation candidate.

## What This Changes

Request to add an operator-configurable local media root allowlist so the image tool can read external attachment directories without manual copying.

## Best Possible Solution

Pick one canonical operator-controlled local-root policy, likely tools.fs.roots or a deliberately scoped media-only policy, then wire it through shared media roots, schemas/types, docs, and tests while preserving safe defaults.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 reject outside-root image paths and expose no mediaLocalRoots/localRoots-style config field. I did not run a live iMessage reproduction in this read-only review.

## Solution Assessment

No for a direct tools.image.mediaLocalRoots patch yet. The safer path is for maintainers to pick one filesystem/media root policy so image tools, outbound media, webchat preview, and workspaceOnly semantics do not grow conflicting allowlists.
