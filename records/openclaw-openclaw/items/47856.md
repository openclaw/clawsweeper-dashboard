## Summary

Keep open: current main and v2026.6.11 still do not expose a configurable media-local-root allowlist for the image/media tools. The narrower iMessage attachment-root path is now covered through channel-scoped inbound roots, but the broader operator-controlled host-root policy remains a security-sensitive product/config decision with an open but conflicting broader candidate PR.

## What This Changes

The issue requests a new `openclaw.json` configuration surface, such as `tools.image.mediaLocalRoots`, so the image tool can read operator-approved host directories outside OpenClaw-managed roots.

## Best Possible Solution

Choose one shared, security-reviewed filesystem/media-root policy, likely through a refreshed `tools.fs.roots` design or a narrower replacement, then wire image/PDF/media reads, schemas, docs, and regression tests to that contract while preserving safe defaults.
