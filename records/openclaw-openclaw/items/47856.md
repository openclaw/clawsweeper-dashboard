## Summary

Keep open: current main and v2026.6.11 still do not expose a general configurable local media root for the image tool. Current code has narrower support for scoped iMessage inbound attachment roots and managed inbound media, but the requested operator-controlled local-root policy remains a security-sensitive product/config decision with an open broader implementation candidate.

## What This Changes

Request configurable local media roots for the image tool so iMessage attachments and other trusted local media paths can be analyzed without manually copying files into the workspace.

## Best Possible Solution

Choose one canonical operator-controlled local-root policy, likely tools.fs.roots or a deliberately scoped media-only policy, then wire it through shared media roots, schema/types, docs, and tests while preserving current managed-inbound and channel-scoped boundaries.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 reject outside-root image paths and expose no mediaLocalRoots/localRoots-style config field. I did not run a live iMessage reproduction in this read-only review.

## Solution Assessment

No, not as a direct tools.image.mediaLocalRoots patch yet. The safer path is for maintainers to pick a single filesystem/media root policy so image tools, outbound media, webchat preview, and workspaceOnly semantics do not grow conflicting allowlists.
