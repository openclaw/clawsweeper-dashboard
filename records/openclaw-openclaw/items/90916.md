## Summary

Keep open for maintainer product and security scoping. Current main offers strong individual-session, thread/topic routing, labeling, lifecycle, and shared agent-memory primitives, but it does not provide the requested family-level state contract, governed memory boundary, or named-lane lifecycle; recent community comments also confirm that the use case remains active.

## What This Changes

Add named topic-session families that preserve per-topic transcript isolation while sharing assistant identity and explicitly governed durable memory.

## Best Possible Solution

Approve a staged RFC that first defines one canonical SQLite-backed family/topic metadata model, isolated-transcript invariants, explicit memory eligibility and handoff receipts, and routing identifiers that never confer authorization; then implement protocol/store, chat lifecycle, UI, and memory documentation as separately reviewed slices.
