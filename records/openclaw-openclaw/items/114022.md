## What This Changes

The PR changes gateway approval delivery so exec, plugin, and plugin-node approval requests proceed when the first configured forwarding or iOS route reports success, rather than waiting for every concurrent route to finish.

## System Context

Gateway approval requests fan out concurrently to configured external forwarding and iOS delivery routes, then report whether a user can be prompted. That result unblocks the exec or plugin approval manager, while the individual routes retain their own visibility filtering, failure logging, and cleanup behavior.

  D --> E
  E -->|yes| F[Unblock approval requester]
  E -->|all fail or decline| G[Report delivery failure]
  C --> H[Route cleanup and logging]
  D --> H

## Best Possible Solution

Merge the narrow first-success aggregation once a gateway owner confirms that started routes are intentionally allowed to finish independently after the requester is unblocked.
