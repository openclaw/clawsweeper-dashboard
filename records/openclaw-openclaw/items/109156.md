## Label Justifications

- `P1`: The proposed shared write deadline can break existing Slack file delivery and create ambiguous message-delivery outcomes for real users.
- `merge-risk: 🚨 compatibility`: Existing callers that omit `timeout` silently change from an unbounded SDK default to fixed 30-second or 60-second deadlines.
- `merge-risk: 🚨 message-delivery`: A timed-out write may abort a slow upload or be retried after Slack accepted the original request, risking failed or duplicate delivery.

## Summary

Keep this PR open, but do not merge it as written: the focused resolver tests pass, yet the new 60-second default also governs the shared upload-capable write client and can abort legitimate slow uploads. The submitted proof only inspects resolved option objects rather than demonstrating a stalled request, successful message send, or file upload through the real SDK transport.

## What This Changes

The PR adds 30-second and 60-second default timeouts to Slack web and write client option resolvers, exports those constants, and adds unit coverage for defaults and overrides.

## Best Possible Solution

Use operation-scoped timeout policies: retain the dedicated startup and lookup deadlines, bound short message/API operations where completion semantics are understood, and give uploads a separately justified transfer budget or preserve their existing timeout behavior; prove each path with the real Slack WebClient against controlled loopback stalls.
