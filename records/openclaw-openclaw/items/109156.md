## Summary

Keep open: bounding Slack calls is useful, but the blanket write-client deadline also covers file-upload transfers, so existing large or slow uploads could regress; contributor-provided real Slack behavior proof is also still required.

## What This Changes

Adds private 30-second one-shot Slack WebClient and 60-second write-client timeout defaults while leaving the shared Bolt client options timeout-free, with mocked-constructor and stalled-local-server tests.

## Best Possible Solution

Keep the Bolt resolver timeout-free, bound short-lived Slack API control and message operations at their owning call path, and preserve or separately configure the external file-upload transfer before proving normal sends, uploads, and Bolt continuity in a real Slack setup.

## Solution Assessment

No. Separating the one-shot web deadline from Bolt is sound, but applying one 60-second deadline to the entire write client is too broad because that client also performs file-upload transfers.
