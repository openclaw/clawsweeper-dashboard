## Summary

Keep this PR open for maintainer review: the implementation is focused, Bolt-safe, and convincingly proves that stalled one-shot requests terminate, but the new unconditional 30-second web and 60-second write defaults need explicit upgrade-safety acceptance because they can terminate slow, progressing requests that previously had no deadline.

## What This Changes

Adds private default timeouts of 30 seconds for one-shot Slack WebClient calls and 60 seconds for Slack write clients, preserves timeout-free shared Bolt options, and adds unit plus stalled-header network-path coverage.

## Best Possible Solution

Keep the private bounded defaults and explicit caller overrides, preserve the timeout-free shared Bolt seam, and land only after confirming that representative slow-success and file-upload paths remain safe or documenting why the chosen limits are acceptable.
