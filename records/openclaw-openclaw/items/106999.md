## Label Justifications

## Summary

The reported placeholder literals are real, but current main constructs `Image reply`/`Audio reply`/`Media reply` inside the WebChat transcript-media builder, while Telegram sends the original `ReplyPayload.text` through its own outbound adapter. No current-main source trace, normalized payload, or Bot API capture establishes the claimed cross-boundary leak, so the issue remains useful but should stay behind maintainer review rather than enter an automated repair lane.

## What This Changes

Prevent prompt or transcript media placeholders from replacing human-visible Telegram reply content.

## Best Possible Solution

Capture the normalized final `ReplyPayload` and redacted Telegram Bot API request for a media-only reply with an explicit reply directive; if the placeholder is already in `ReplyPayload.text`, fix the shared reply/media projection before channel dispatch, otherwise keep transcript-only labels internal and add a Telegram regression test proving media captions and reply text remain placeholder-free without adding configuration.
