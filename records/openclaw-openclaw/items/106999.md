## Summary

This issue should remain open, but the claimed cross-boundary Telegram leak is not yet established on current main. The named `Image reply`/`Audio reply`/`Media reply` strings are created by the WebChat transcript-media builder, while Telegram’s outbound adapter receives the original reply payload through a separate path; the report provides no normalized current-main payload or Bot API request showing where placeholder text enters Telegram delivery.

## What This Changes

Prevent prompt- or transcript-only media placeholder text from replacing human-visible Telegram replies.

## Best Possible Solution

Capture the normalized current-main `ReplyPayload` and redacted Telegram Bot API request for one failing turn, then fix the first boundary that substitutes internal placeholder text for the intended outbound text; preserve prompt-only placeholders and add focused regression coverage without adding a config option unless maintainers explicitly choose that product behavior.
