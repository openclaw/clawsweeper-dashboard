## Summary

Keep open: current main still runs aggregate ACP replay-table size estimation from the SQLite ledger write path, and no merged related item fixes it.

## What This Changes

The issue asks OpenClaw to remove per-write full-table ACP event-ledger size scans and use a cheaper SQLite or cached estimate instead.

## Best Possible Solution

Replace the SQLite ledger's per-write aggregate byte scan with ledger-local cheap accounting or cached stats that preserves retention semantics; avoid using a whole shared-database page count as the sole ledger-byte estimate unless that scope is proven safe.
