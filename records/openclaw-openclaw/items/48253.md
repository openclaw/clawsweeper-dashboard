## Summary

Keep open; current main still lacks a public host-delivered memory file scan/change/delete API for active memory plugins, and the requested SDK surface needs maintainer product and security review rather than cleanup closure.

## What This Changes

The issue requests a Memory Plugin API that lets third-party memory plugins consume OpenClaw's file scanning, watching, chunking/change detection, extraPaths, and stale-cleanup pipeline.

## Best Possible Solution

Design a narrow documented memory ingestion SDK seam with explicit file-scope consent, add/change/delete and batch semantics, chunking ownership, stale cleanup behavior, and contract tests covering memory-core plus an external-style memory plugin.
