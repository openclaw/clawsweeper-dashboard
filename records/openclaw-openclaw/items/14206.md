## Summary

Keep open. Current main and v2026.6.11 provide reactive retry for Feishu rate-limit responses but still do not expose proactive outbound pacing; the open linked pull request remains the canonical implementation candidate and needs a maintainer decision plus credible live Feishu proof before this issue can resolve. ([github.com](https://github.com/openclaw/openclaw/blob/main/docs/channels/feishu.md?utm_source=openai))

## What This Changes

Add configurable Feishu outbound message pacing, potentially coordinated with response chunking, to reduce send failures during high-frequency delivery.

## Best Possible Solution

Use one Feishu-owned per-account and per-target send queue at the shared SDK request boundary, preserve the current zero-delay default unless maintainers choose an automatic safe default, keep retry as a second line of defense, and avoid coupling transport pacing to LLM response segmentation.
