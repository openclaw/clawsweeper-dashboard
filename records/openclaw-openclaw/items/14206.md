## What This Changes

The issue requests configurable Feishu outbound message pacing so bursty chunked OpenClaw responses do not trigger Feishu API rate limits.

## Best Possible Solution

Review and land or replace https://github.com/openclaw/openclaw/pull/96513 with a plugin-local, default-off per-account/per-target Feishu pacing layer, then close this issue after equivalent code is on main.

Yes, at source level: current main has Feishu chunking and send paths plus reactive retry handling, but no proactive minimum-interval scheduler or config. I did not run a live Feishu burst test in this read-only review.

## Solution Assessment

Yes, keeping this issue open is the right path until the linked candidate lands or is replaced. A Feishu-plugin-local, default-off per-account/per-target limiter is the narrow maintainable shape and should compose with existing retry handling.
