## Summary

Keep open: current main and v2026.6.11 still record Feishu group messages that did not mention the current bot into pending group history, then replay that history into later mentioned turns. The request remains a valid Feishu context-isolation feature, but the fix needs maintainer product and compatibility direction because it changes public group-history behavior and likely adds config surface.

## What This Changes

The issue requests mention-scoped/per-bot Feishu group context so each bot only records context for messages addressed to it.

## Best Possible Solution

Add a maintainer-approved Feishu group context policy that preserves current defaults unless intentionally changed, with schema/docs/tests and live multi-bot proof.

## Solution Assessment

Unclear until maintainers choose the product contract. A Feishu-owned context policy with explicit compatibility defaults is safer than silently redefining requireMention.
