## Summary

Keep open: current main and v2026.6.11 still record unmentioned Feishu group messages into pending history and replay them into later handled turns, while the requested mention-only/per-bot context policy is absent and needs a maintainer compatibility choice.

## What This Changes

Request to add Feishu per-bot or mention-only group context isolation so messages addressed to other bots are not recorded into the current bot's context.

## Best Possible Solution

Add an explicit Feishu-owned mention-only context policy that preserves current defaults, updates strict schema/docs/tests, and proves the multi-bot behavior with redacted live Feishu evidence.

- **Redefine requireMention Semantics:** Make requireMention also suppress pending context recording, accepting a compatibility-sensitive behavior change that needs explicit maintainer approval and upgrade proof.
- **Defer To Existing Controls:** Keep only historyLimit, groupSessionScope, and current pending-history behavior, and document that strict per-bot context isolation is not currently supported.

## Reproduction Assessment

Yes, at source level: current Feishu code records unmentioned requireMention group messages and later injects that group history into handled turns. I did not establish a live multi-bot Feishu reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract. An explicit opt-in Feishu context policy is safer than silently redefining requireMention or adding ad hoc config keys.
