## Summary

This PR remains necessary: current `main` has the narrower blank-location repair from https://github.com/openclaw/openclaw/pull/112013, but not the populated Telegram location case. The updated branch restores the unscoped schema surface identified in review and has before/after Telegram Desktop evidence; the remaining merge gate is owner confirmation that only a trusted agent-runtime Gateway caller can select the model-origin behavior.

## What This Changes

The branch strips an incidental populated Telegram location from model-authored content sends, preserves strict rejection for direct mixed payloads and native location-only sends, and keeps legacy unscoped channel schema contributions available to cron and isolated agents.

## System Context

OpenClaw’s model message tool and Gateway route outbound actions through shared validation before dispatching to a channel plugin. The patch adds a Telegram-specific pre-dispatch normalization only for model-originated sends, then leaves normal validation and Telegram delivery to the existing paths.
