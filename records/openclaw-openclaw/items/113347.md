## What This Changes

This PR strips a populated Telegram location only from model-authored content sends so text or media can deliver, while preserving native location-only sends and strict rejection of direct/API mixed payloads.

## System Context

OpenClaw’s message tool and Gateway both dispatch channel actions through shared outbound validation. This change adds a private Telegram-only normalization step before that validation so model-schema overpopulation does not suppress an otherwise valid Telegram reply.

## Best Possible Solution

Keep a single private, host-owned Telegram normalizer at both dispatch boundaries, preserve strict direct/API validation and location-only sends, and land only after the origin boundary is explicitly approved and the refreshed head is green.
