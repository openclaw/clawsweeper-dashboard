## Summary

This PR remains necessary: current `main` handles only blank-string locations, while this narrowly preserves Telegram location-only sends and direct/API rejection but lets model-authored content sends recover from an incidental populated location. The patch follows the host-owned/private boundary rather than expanding the public plugin API; it needs final owner review and the remaining exact-head checks before merge.

## What This Changes

The PR removes a populated Telegram `location` only from model-authored `send` requests that also carry real content, preserving native location-only sends and strict direct/API mixed-payload rejection.

## System Context

OpenClaw’s message tool and Gateway both dispatch outbound channel actions through the shared message-action runner. This change inserts a Telegram-only normalization before shared validation so ordinary model replies reach Telegram without changing direct API contracts or other channels.
