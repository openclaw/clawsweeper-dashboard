## What This Changes

The issue reports duplicated Telegram direct-chat assistant context when a session transcript row retains a reply directive tag but the Telegram cache row contains only the delivered text.

## Best Possible Solution

Review and land one narrow Telegram-owned fix that normalizes delivered assistant text before session/cache prompt-context dedupe, then close the issue from the merged PR.

## Reproduction Assessment

Yes from source inspection, but not from a live Telegram run in this review. Current main still dedupes Telegram session transcript rows against cache rows by exact `timestamp_ms:body`, so directive-tagged transcript text and delivered cache text can remain as two prompt-context entries.

## Solution Assessment

Yes, a narrow Telegram prompt-context normalization step before the existing session/cache dedupe is the best fix shape. The linked PRs are implementation candidates; maintainers should choose the one that preserves timestamp alignment and provides adequate Telegram proof.
