## What This Changes

The issue reports Telegram direct-chat prompt context duplicating one delivered assistant reply as both a synthetic session transcript row and a Telegram cache row when directive tags or timestamps differ.

## Best Possible Solution

Review the open candidate PR, require or waive its live Telegram proof explicitly, and close this issue only after the chosen fix merges.

Yes, at source level: current main and v2026.6.11 dedupe by exact timestamp_ms plus body, while the reporter provided a live Telegram capture with both directive-tag text drift and timestamp drift. I did not run a fresh live Telegram scenario in this read-only pass.

## Solution Assessment

The open PR is the current candidate, so the issue should wait on that PR rather than spawning a second repair.
