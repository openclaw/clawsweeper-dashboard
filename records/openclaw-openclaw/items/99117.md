## Summary

Keep open. Current main still dedupes Telegram session-transcript rows against Telegram cache rows by exact timestamp plus exact trimmed body, so directive-tagged transcript text can still survive beside the delivered cache text; two open PRs now target the issue and should be reviewed rather than closing this before merge.

## What This Changes

The issue requests a Telegram prompt-context fix so one delivered assistant reply is not shown twice when the session transcript copy still contains inline reply directives and the Telegram cache copy contains the delivered visible text.

## Best Possible Solution

Land one narrow Telegram-owned fix that normalizes delivered assistant text for session/cache dedupe, preserves the timestamp-alignment behavior from https://github.com/openclaw/openclaw/pull/98769, and keeps cache-backed Telegram rows over synthetic session rows when both describe the same delivered reply.

## Reproduction Assessment

Yes, at source level: current main still dedupes session and cache prompt rows by exact timestamp_ms plus exact trimmed body, while session rows keep raw directive-tagged transcript text. I did not run a live Telegram scenario in this read-only review.

## Solution Assessment

Yes. The narrowest maintainable fix is to normalize Telegram prompt-context dedupe text at the session/cache merge boundary, using the existing directive-strip helper and preserving timestamp-based protection against unrelated rows.
