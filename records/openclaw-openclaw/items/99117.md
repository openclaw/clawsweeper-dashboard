## What This Changes

The issue reports duplicate Telegram prompt-context assistant rows when a session transcript reply includes an inline directive tag and the Telegram cache stores the delivered text without that tag.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99133, or replace it with an equivalent narrow Telegram-owned fix that normalizes directive-tagged assistant text without regressing the merged timestamp-alignment behavior.

## Reproduction Assessment

Yes, at source level. Current main still dedupes Telegram session/cache prompt rows by exact timestamp plus exact trimmed body while session transcript text can retain inline reply directives that delivered/cache text does not.

## Solution Assessment

Yes. The best fix is a narrow Telegram prompt-context normalization and dedupe repair that builds on the merged timestamp-alignment work, not a provider, transcript-storage, or configuration change.
