## Summary

Keep open. Current main still dedupes Telegram session-transcript and cache prompt rows by exact timestamp plus exact body, so the recently merged timestamp-drift fix does not cover this directive-tag mismatch variant.

## What This Changes

The issue asks OpenClaw to avoid duplicate Telegram prompt-context assistant entries when a session transcript copy and Telegram cache copy represent the same delivered reply.

## Best Possible Solution

Extend the Telegram prompt-context dedupe contract to compare normalized visible assistant text, keep timestamp alignment intact, and prefer cache-backed Telegram rows over synthetic session rows when both describe the same delivered reply.
