Keep open. Current main and the latest release still use exact timestamp/body matching for Telegram session/cache prompt-context dedupe, and the issue is already paired with an open closing PR that targets this directive-tag mismatch.

## What This Changes

The issue reports duplicate Telegram DM prompt-context assistant rows when a session transcript row includes directive tags and the Telegram cache row contains the delivered text.

## Best Possible Solution

Land a narrow Telegram-owned prompt-context dedupe fix that normalizes delivered assistant text for synthetic session rows, preserves timestamp-alignment behavior, and prefers cache-backed rows when equivalent.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still dedupe Telegram session/cache prompt rows by exact timestamp plus exact body, and the reporter supplied a live 2026.6.11 Telegram DM capture showing the directive-tag and timestamp-drift duplicate shape.
