## Summary

Keep open: current main and the latest release still expose `zh-CN` and `zh-TW` as public Control UI and CLI wizard locale IDs, and changing those shipped identifiers plus saved preferences needs maintainer product direction before implementation.

## What This Changes

The issue asks to rename Chinese locale identifiers from `zh-CN`/`zh-TW` to `zh-Hans`/`zh-Hant` across Control UI i18n, docs, detection, saved preferences, and picker labels.

## Best Possible Solution

Maintainers should choose the canonical Chinese locale-ID policy first; if switching to script IDs, land one coordinated migration across Control UI runtime/generator, CLI wizard, docs, tests, and saved preference repair, otherwise keep region IDs canonical and normalize script-tag inputs explicitly.
