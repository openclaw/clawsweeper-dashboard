## Summary

Keep open: current main and the latest release still expose `zh-CN` and `zh-TW` as public Control UI and CLI wizard locale IDs, and switching the canonical IDs needs maintainer direction on migration and alias policy.

## What This Changes

The issue asks to rename Chinese locale identifiers from `zh-CN`/`zh-TW` to script-based `zh-Hans`/`zh-Hant` across Control UI locale types, imports, detection, storage migration, and selectors.

## Best Possible Solution

Decide the canonical locale-ID policy first, then land one coordinated migration or alias update across Control UI, CLI wizard, docs publishing, generated i18n artifacts, tests, and saved-value handling.

## Maintainer Decision

Question: Should OpenClaw make `zh-Hans` and `zh-Hant` the canonical Chinese locale IDs across Control UI, CLI wizard, docs publishing, saved browser preferences, and app locale mappings?

Rationale: The rename is technically reasonable, but it changes shipped public locale identifiers, documented CLI environment values, and persisted browser preferences, so automation should not choose the migration and alias policy.

Likely owner: steipete

Owner reason: This is primarily a product and compatibility-policy choice spanning CLI setup, docs, and Control UI persistence.

Owner confidence: medium

Options:

- **Approve coordinated script-code migration (recommended):** Make `zh-Hans` and `zh-Hant` canonical and require one migration PR that updates runtime, docs, generated artifacts, tests, and old-value handling together.
- **Keep region-code public IDs:** Leave `zh-CN` and `zh-TW` as OpenClaw's public runtime and CLI IDs while accepting script-form input only as aliases that resolve to the existing IDs.
- **Split docs metadata from runtime IDs:** Keep runtime and CLI IDs unchanged while limiting script-based naming to docs publish metadata and navigation internals.

Yes for the current behavior, though this is not a bug failure: source and release inspection show current main and `v2026.6.11` still register, load, persist, test, and document `zh-CN`/`zh-TW`.
