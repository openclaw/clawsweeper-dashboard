## Summary

Keep open: current main and v2026.6.11 still expose `zh-CN` and `zh-TW` in the Control UI and CLI wizard, and changing those shipped public and saved locale IDs needs maintainer product direction.

## What This Changes

The issue requests renaming Chinese locale identifiers from `zh-CN`/`zh-TW` to script-based `zh-Hans`/`zh-Hant` across UI locale types, generated locale files, detection, saved preferences, selector labels, and related docs.

## Best Possible Solution

Maintainers should choose the canonical Chinese locale-ID policy first; if switching to script IDs, land one coordinated migration across Control UI runtime/generator, CLI wizard, docs, tests, and saved preference handling, otherwise keep region IDs canonical and normalize script-tag inputs explicitly.
