## What This Changes

The issue requests renaming Chinese locale identifiers from `zh-CN`/`zh-TW` to `zh-Hans`/`zh-Hant`, including locale files, detection logic, display values, and saved-preference migration.

## Best Possible Solution

Decide the canonical locale-ID policy first, then land one coordinated migration across Control UI, CLI wizard, docs publish metadata, generated i18n artifacts, tests, app mappings, and old saved-value handling.

Rationale: The rename is technically reasonable, but it changes shipped public locale identifiers, documented CLI environment values, and persisted browser preferences, so automation should not choose the migration and alias policy without maintainer intent.

Options:

- **Approve coordinated script-code migration (recommended):** Make `zh-Hans` and `zh-Hant` canonical and require one migration PR that updates runtime, docs, generated artifacts, tests, old saved-value handling, and any temporary public-input aliases together.
- **Keep region-code public IDs:** Leave `zh-CN` and `zh-TW` as OpenClaw's public runtime and CLI IDs while accepting script-form input only as normalization to the existing IDs.
- **Split docs metadata from runtime IDs:** Keep runtime and CLI IDs unchanged while limiting script-based naming to docs publish metadata and navigation internals.
