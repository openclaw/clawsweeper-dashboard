## Summary

Keep open: current main and v2026.6.11 still expose `zh-CN` and `zh-TW` as public Control UI and CLI wizard locale IDs. The requested script-code rename is coherent, but it crosses saved browser preferences, documented `OPENCLAW_LOCALE` values, generated i18n artifacts, docs publishing, and app locale resources, so maintainers need to decide the canonical contract before implementation.

## What This Changes

Requests renaming Chinese i18n locale identifiers from `zh-CN`/`zh-TW` to `zh-Hans`/`zh-Hant` with migration for existing saved preferences.

## Best Possible Solution

Decide the canonical locale-ID policy first, then land one coordinated migration across Control UI, CLI wizard, docs publish metadata, generated i18n files, tests, public docs, and any app locale mappings with explicit handling for existing saved and documented old values.
