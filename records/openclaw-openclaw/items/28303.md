## Summary

Keep open: current main and v2026.6.11 still expose `zh-CN` and `zh-TW` as public Control UI and CLI wizard locale IDs. The request is coherent, but changing shipped locale identifiers and saved preferences needs maintainer product direction before implementation.

## What This Changes

The issue requests replacing OpenClaw's public Chinese locale identifiers `zh-CN`/`zh-TW` with script-based `zh-Hans`/`zh-Hant` across UI, CLI, docs, locale files, detection, and saved preferences.

## Best Possible Solution

Decide the canonical locale-ID policy first, then land one coordinated migration across Control UI, CLI wizard, generated i18n artifacts, public docs, tests, and old saved-value handling.
