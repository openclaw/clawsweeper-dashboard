## Summary

Keep open: current main and the latest release still expose `zh-CN` and `zh-TW` as public Control UI and CLI wizard locale IDs, and changing shipped IDs plus saved preferences needs maintainer product direction before implementation.

## What This Changes

The issue requests renaming Simplified and Traditional Chinese locale identifiers from `zh-CN`/`zh-TW` to `zh-Hans`/`zh-Hant`, including generated locale files, language detection, language labels, and saved preference migration.

## Best Possible Solution

Decide the canonical locale-ID policy first, then land one coordinated migration across Control UI, CLI wizard, generated i18n artifacts, docs, tests, and old saved-value handling.

Rationale: The rename is technically reasonable, but it changes shipped public IDs, documented setup inputs, and persisted browser preferences, so automation should not choose the alias and migration policy without maintainer intent.

Likely owner: steipete

Owner confidence: medium

Options:

- **Approve coordinated script-code migration (recommended):** Make `zh-Hans` and `zh-Hant` canonical and require one migration PR that updates runtime, docs, generated artifacts, tests, and old-value handling together.
- **Keep region-code public IDs:** Leave `zh-CN` and `zh-TW` as public runtime and CLI IDs while accepting script-form input only as aliases that resolve to existing IDs.
- **Split docs metadata from runtime IDs:** Limit script-based naming to docs or platform metadata while keeping runtime and CLI locale IDs unchanged.
