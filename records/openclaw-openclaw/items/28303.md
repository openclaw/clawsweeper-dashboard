## Summary

Keep open: current main still uses `zh-CN` and `zh-TW` as shipped Control UI and CLI wizard locale identifiers, and renaming those persisted/user-facing locale codes needs maintainer product direction on migration or alias policy before implementation.

## What This Changes

The issue requests replacing region-based Chinese locale identifiers with script-based `zh-Hans` and `zh-Hant` across the i18n system, including persisted preference migration.

## Best Possible Solution

Maintainers should first choose the canonical Chinese locale ID policy, then implement a single compatibility-aware migration across Control UI localStorage, UI locale imports/tests, wizard locale resolution, docs i18n metadata, and any public examples.
