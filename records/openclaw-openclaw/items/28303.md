## Summary

Keep open: current main and v2026.6.11 still expose `zh-CN` and `zh-TW` as public Control UI and CLI wizard locale IDs, and changing those shipped identifiers needs maintainer direction on canonical IDs and migration policy.

## What This Changes

The issue asks to make `zh-Hans` and `zh-Hant` the canonical Chinese locale IDs instead of `zh-CN` and `zh-TW` across Control UI, CLI wizard, docs/runtime wiring, and saved locale handling.

## Best Possible Solution

Decide the canonical Chinese locale-ID policy first, then land one coordinated migration across Control UI, CLI wizard, docs publishing metadata, generated i18n artifacts, tests, and old saved-value handling.

Rationale: The rename is technically reasonable, but it changes shipped public locale identifiers, documented CLI environment values, and persisted browser preferences, so automation should not choose the migration and alias policy without maintainer intent.

Options:

- **Approve coordinated script-code migration (recommended):** Make `zh-Hans` and `zh-Hant` canonical and require one migration PR that updates runtime, docs, generated artifacts, tests, and old-value handling together.
- **Keep region-code public IDs:** Leave `zh-CN` and `zh-TW` as OpenClaw's public runtime and CLI IDs while accepting script-form inputs only as aliases that resolve to the existing IDs.
- **Split docs metadata from runtime IDs:** Keep runtime and CLI IDs unchanged while limiting script-based naming to docs publish metadata and navigation internals.
