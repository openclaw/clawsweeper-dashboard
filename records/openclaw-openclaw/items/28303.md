## Summary

Keep open: current main and the latest release still expose `zh-CN` and `zh-TW` as public locale IDs across Control UI, CLI wizard, docs, and generators. The request is valid cleanup, but it needs maintainer direction because changing canonical IDs affects saved browser preferences and documented setup environment values.

## What This Changes

Rename OpenClaw Chinese locale identifiers from `zh-CN`/`zh-TW` to script-based `zh-Hans`/`zh-Hant` across i18n runtime, generated locale files, detection, saved preferences, docs, and selectors.

## Best Possible Solution

Decide the canonical locale-ID policy first, then land one coordinated migration across Control UI, CLI wizard, docs publish, native locale mappings, generated metadata, tests, and public docs with explicit handling for existing saved and documented old values.

## Maintainer Decision

Question: Should OpenClaw make `zh-Hans` and `zh-Hant` the canonical Chinese locale IDs across Control UI, CLI wizard, docs publish, native locale tooling, and saved browser preferences?

Rationale: The rename is technically coherent, but current shipped behavior exposes `zh-CN` and `zh-TW` as public UI and CLI wizard values while docs publishing is already partly script-based; automation should not choose the permanent contract or legacy handling window on its own.

Likely owner: steipete

Owner reason: This person appears in the inspected history around CLI wizard i18n follow-up, public onboarding docs, and Control UI locale support, so they are the best available owner for the public-contract choice.

Owner confidence: medium

Options:

- **Approve coordinated script-code migration (recommended):** Make `zh-Hans`/`zh-Hant` canonical and require one migration PR that updates generated artifacts, docs, tests, native mappings, and legacy saved/doc values intentionally.
- **Keep region codes public for now:** Leave `zh-CN`/`zh-TW` as the public OpenClaw locale IDs and document that docs publishing may map them to script-based Mintlify language metadata.
- **Split docs metadata from runtime IDs:** Keep runtime and CLI IDs unchanged while limiting script-based naming to docs publishing and navigation metadata where Mintlify expects it.
