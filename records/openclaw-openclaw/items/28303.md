## Summary

Keep open: current main and the latest release still use `zh-CN` and `zh-TW` as the Control UI and CLI wizard locale contracts. The remaining work is a compatibility-sensitive product decision because stored browser preferences, wizard environment values, docs publish metadata, and generated locale assets need one coordinated migration policy.

## What This Changes

The issue requests renaming Chinese locale identifiers from `zh-CN`/`zh-TW` to `zh-Hans`/`zh-Hant` across UI i18n, docs/config references, language detection, and persisted locale handling.

## Best Possible Solution

Decide one canonical Chinese locale-ID policy for Control UI, CLI wizard, and docs publish output, then land a coordinated migration that preserves existing `zh-CN`/`zh-TW` users and documents any deprecation path.

## Reproduction Assessment

Yes. Source inspection on current main shows the Control UI type/registry, saved-preference path, CLI wizard resolver, tests, and docs still use `zh-CN` and `zh-TW`.

## Solution Assessment

No, not as a simple rename. The maintainable fix is a maintainer-approved locale-ID contract with explicit compatibility handling across UI storage, wizard environment input, docs publish metadata, tests, and generated i18n assets.
