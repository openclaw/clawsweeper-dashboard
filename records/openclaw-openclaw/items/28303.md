## Summary

Keep open: current main and the latest release still use `zh-CN`/`zh-TW` as canonical Chinese locale IDs in the Control UI and CLI wizard. The requested rename is valid cleanup, but it crosses saved browser preferences, documented `OPENCLAW_LOCALE` values, generated locale artifacts, and docs publish metadata, so it needs maintainer product direction before a repair PR should be queued.

## What This Changes

Rename OpenClaw's Chinese locale identifiers from `zh-CN`/`zh-TW` to `zh-Hans`/`zh-Hant` across i18n runtime, generated artifacts, docs, detection, and saved preferences.

## Best Possible Solution

Maintainers should choose the canonical Chinese locale-ID contract; if script IDs win, migrate Control UI, CLI wizard, docs publish metadata, generated i18n assets, tests, and saved browser preferences together, otherwise document `zh-CN`/`zh-TW` as the stable OpenClaw contract.
