## What This Changes

The issue requests renaming Chinese locale identifiers from `zh-CN` and `zh-TW` to script-based `zh-Hans` and `zh-Hant` across the i18n system, including saved preference migration.

## Best Possible Solution

Decide the canonical locale-ID policy first, then land one coordinated migration across Control UI, CLI wizard, docs publish metadata, generated i18n artifacts, tests, and old saved-value handling.

Rationale: The rename is technically reasonable, but it changes shipped public locale identifiers, documented CLI environment values, and persisted browser preferences, so automation should not choose the migration and alias policy without maintainer intent.

Likely owner: steipete

Owner confidence: medium

Options:

- **Approve coordinated script-code migration (recommended):** Make `zh-Hans` and `zh-Hant` canonical and require one migration PR that updates runtime, docs, generated artifacts, tests, and old-value handling together.
- **Keep region-code public IDs:** Leave `zh-CN` and `zh-TW` as OpenClaw's public runtime and CLI IDs while accepting script-form input only as aliases that resolve to the existing IDs.
- **Split docs metadata from runtime IDs:** Keep runtime and CLI IDs unchanged while limiting script-based naming to docs publish metadata and navigation internals.
