## Summary

Keep open: current main and v2026.6.11 still expose `zh-CN` and `zh-TW` as public Control UI and CLI wizard locale IDs, and changing those shipped IDs needs maintainer product and migration policy first.

## What This Changes

Rename OpenClaw Chinese locale identifiers from `zh-CN`/`zh-TW` to script-based `zh-Hans`/`zh-Hant` across runtime, generated i18n artifacts, docs, tests, and saved preferences.

## Best Possible Solution

Decide the canonical locale-ID policy first, then land one coordinated migration across Control UI, CLI wizard, generated i18n artifacts, docs, tests, and old saved-value handling.

Rationale: The rename is technically reasonable, but it changes shipped public IDs, documented setup inputs, and persisted browser preferences, so automation should not choose the alias and migration policy without maintainer intent.

Options:

- **Approve coordinated script-code migration (recommended):** Make `zh-Hans` and `zh-Hant` canonical and require one migration PR that updates runtime, docs, generated artifacts, tests, workflows, and old-value handling together.
- **Keep region-code public IDs:** Leave `zh-CN` and `zh-TW` as public runtime and CLI IDs while accepting script-form input only as aliases that resolve to the existing IDs.
- **Split docs metadata from runtime IDs:** Limit script-based naming to docs or publishing metadata while keeping runtime and CLI locale IDs unchanged.
