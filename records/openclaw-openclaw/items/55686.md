## Summary

Keep open: current main and v2026.6.11 still return no-argument `/reasoning` as a text-only `Options:` reply, while Feishu only renders buttons when a reply carries typed presentation/card data. The related native args-menu issue and open PR overlap, but they do not currently implement the Feishu command-status card-button path.

## What This Changes

Request that Feishu render selectable options for commands such as `/reasoning` as clickable card buttons instead of plain text choices.

## Best Possible Solution

Define selectable command-status replies as typed command-action presentation and let Feishu render them through its existing card renderer while preserving text fallback and coordinating with the native args-menu work.
