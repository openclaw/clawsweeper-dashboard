## Summary

Keep open: current main and v2026.6.11 still return no-argument `/reasoning` as a text-only `Options:` reply, and Feishu only renders clickable buttons when a reply carries typed presentation/card data. The related native args-menu issue and open PR overlap, but they do not cover the Feishu command-status card path.

## What This Changes

Request clickable Feishu card buttons for command option choices such as `/reasoning` on/off/stream instead of plain text `Options:` replies.

## Best Possible Solution

Define selectable command-status replies as typed command-action presentation and let Feishu render them through its existing card renderer while preserving text fallback and coordinating with native args-menu work.

## Reproduction Assessment

Yes. Source inspection shows no-argument `/reasoning` still returns a text-only `Options:` reply, while Feishu clickable controls require a typed presentation/card payload.

## Solution Assessment

Unclear as filed. Feishu card buttons are the right user outcome, but the maintainable fix should emit typed command-action presentation rather than parsing `Options:` text or adding a Feishu-only string workaround.
