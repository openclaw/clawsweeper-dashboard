## Summary

Keep open: current main and the latest release still return no-argument `/reasoning` as a text-only status reply, while Feishu can render buttons only when a reply carries typed presentation/card data. The related native args-menu issue and PR overlap, but they do not replace this Feishu command-status card-button work.

## What This Changes

Request Feishu to render command option choices such as `/reasoning` on/off/stream as clickable Feishu card buttons instead of plain `Options:` text.

## Best Possible Solution

Emit selectable command-status replies as typed command-action presentation and let Feishu render them through its existing card renderer while preserving readable text fallback.

## Reproduction Assessment

Yes. Source inspection shows no-argument `/reasoning` still returns a text-only `Options:` reply, while Feishu clickable controls require a typed presentation/card payload.

## Solution Assessment

Unclear as filed. Feishu card buttons are the right user outcome, but the maintainable fix should produce typed command-action presentation rather than adding a Feishu-only parser for `Options:` text.
