## Summary

Keep open: current main and the latest release still return the no-argument `/reasoning` status as text-only `Options:` output, while Feishu only renders clickable controls when the reply carries typed presentation/card data. The merged Feishu presentation and typed command-action work are useful building blocks, and the open shared args-menu issue overlaps, but they do not complete the Feishu command-status button path.

## What This Changes

Request Feishu to render command option choices such as `/reasoning` on/off/stream as clickable card buttons instead of plain text users must type.

## Best Possible Solution

Emit selectable command-status replies as typed command-action presentation and let Feishu render them through its existing card button/callback path while preserving text fallback.

- **Feishu-only card transform:** Teach Feishu to transform recognized command-status option text into cards, accepting a channel-specific parser and extra maintenance risk.
- **Native args-menu only:** Leave no-argument status replies text-only and rely only on channel-native args-menu surfaces where they already exist.

## Solution Assessment
