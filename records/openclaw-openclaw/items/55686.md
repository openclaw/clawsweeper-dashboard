## Summary

Keep open: current main and latest release still send no-argument `/reasoning` through the text-only directive-status path, while Feishu can only render clickable controls when a reply carries typed presentation/card data. The broader native-menu work in https://github.com/openclaw/openclaw/issues/85088 and https://github.com/openclaw/openclaw/pull/85159 overlaps, but it does not settle the Feishu command-status card path.

## What This Changes

Request that Feishu render selectable command options such as `/reasoning` on/off/stream as clickable card buttons instead of only an `Options:` text line.

## Best Possible Solution

Emit selectable command-status replies as typed command-action presentation, let Feishu render them through the existing card renderer, preserve the current-level text fallback, and coordinate the shared semantics with the related native-menu work.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: no-argument `/reasoning` returns only a text `Options:` reply, and current tests assert that text. I did not run a live Feishu tenant in this read-only review.

## Solution Assessment

Unclear as filed: Feishu card buttons are the right user outcome, but the maintainable fix should use shared typed command-action presentation rather than parsing `Options:` text or adding a Feishu-only shortcut.
