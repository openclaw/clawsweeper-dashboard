## Summary

Keep open: current main has generic plugin-tab plumbing and SQLite-backed plugin-state primitives, but it does not implement dashboard widget write-back; the linked roadmap and PR stack show active product work, with storage and sandbox/security decisions still needed.

## What This Changes

The issue requests `dashboard:setState`/`getState` bridge messages plus per-widget persisted state for dashboard widgets.

## Best Possible Solution

Implement the capability only after the dashboard substrate is accepted, using plugin-state SQLite or an approved dedicated schema, a manifest `state:persist` capability, per-widget namespacing, strict size limits, operator approval, rebroadcast behavior, and adversarial bridge/storage tests.
