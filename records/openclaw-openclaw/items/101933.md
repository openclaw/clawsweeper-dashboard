## Summary

Keep open: the PR guards the main Chrome launch child, but the bootstrap child is still spawned with piped stderr and no `error` listener, so the same unhandled stream-error crash can still happen on new-profile/bootstrap launches. The updated real-spawn proof is also insufficient because it installs a test-owned listener on a separate child process rather than exercising the production `launchOpenClawChrome` listener.

## What This Changes

The branch adds a Chrome launch stderr `error` listener in `launchOpenClawChrome` plus browser internal tests using a fake process and a real spawned Node child-pipe harness.

## Best Possible Solution

Handle stderr stream errors at the shared Chrome child ownership point, or attach the same guard to both bootstrap and runtime children, with proof that exercises `launchOpenClawChrome`.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level. The PR head still has the bootstrap branch calling the shared piped-stderr `spawnOnce()` without an `error` listener, and Node's EventEmitter contract makes an unhandled `error` event a process-exit path.

## Solution Assessment

No. The listener placement is a plausible mitigation for the main launch child, but the best fix is a shared guard for every Chrome child created by `spawnOnce()` plus production-path proof.
