## Summary

Keep open: current main still preserves pending final replies and has post-success, restart, and heartbeat-specific recovery paths, but I did not find a current-main steady-state drain for a terminal session whose final text remains in `pendingFinalDelivery` until later inbound activity. The open reaper PR targets this exact stranded-pending-final symptom but is not merged and still has durable delivery/idempotency review risk.

## What This Changes

The issue reports completed OpenClaw sessions whose final reply remains in `pendingFinalDelivery` and is not shown until another message flushes it.

## Best Possible Solution

Review, repair, or replace the open pending-final reaper approach so terminal sessions either deliver or explicitly fail saved final replies without later inbound activity, while preserving at-most-once delivery across restart windows.

## Reproduction Assessment

No high-confidence live reproduction was run for the Debian/Ollama multi-agent setup. Source inspection supports the reported failure shape because current main persists pending final text and has restart or post-success clear paths, but no merged steady-state terminal-session reaper.
