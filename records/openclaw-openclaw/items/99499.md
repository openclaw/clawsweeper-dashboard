## Summary

Keep open: the report describes a current v2026.6.11 gateway/session delivery failure, current main still has only partial pending-final cleanup paths, and the open repair PRs for terminal or stranded pending-final delivery are not merged and still need maintainer decisions around durable delivery, route safety, and duplicate-send semantics.

## What This Changes

The issue asks for completed sessions with saved `pendingFinalDeliveryText` to deliver their final reply to the UI without waiting for a later inbound message to flush it.

## Best Possible Solution

Define and land a shared durable final-delivery recovery contract that delivers or records explicit failure for terminal pending-final entries, with route-safe idempotency, no wrong-target fallback, and live proof for the reported gateway/session path.

## Reproduction Assessment

No high-confidence live reproduction was run for the Debian/Ollama multi-agent load setup. Source inspection gives a medium-confidence reproduction shape: current main can persist final text in `pendingFinalDelivery`, and the proven cleanup paths do not cover every terminal live session that never gets another inbound event.

## Solution Assessment

Unclear: the open reaper/restart-recovery PRs target the right symptom, but reviews show route-safety, idempotency, stale-replay, and proof gaps. The best fix should be a shared durable final-delivery outcome path rather than an isolated flush that can duplicate or misroute replies.
