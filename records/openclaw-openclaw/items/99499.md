## Summary

Keep open: current main still has durable pending-final persistence and restart/success cleanup paths, but no merged steady-state path that drains a completed live session's stranded `pendingFinalDeliveryText` without later inbound activity or restart. The closest open PR targets this exact symptom, but it still has message-delivery/session-state review blockers and cannot be treated as implemented.

## What This Changes

The issue reports completed Gateway sessions whose final reply remains in `pendingFinalDelivery` and is invisible in the UI until a later message flushes it.

## Best Possible Solution

Review and repair the durable final-delivery recovery design so terminal sessions deliver or explicitly fail saved final text without later inbound activity, while preserving at-most-once delivery across restart windows.

## Reproduction Assessment

No high-confidence live reproduction was run for the reported Ollama multi-agent/load setup. Source inspection does show a plausible current-main gap: pending-final text can remain persisted, success and restart paths are narrower than a live terminal-session drain, and the open repair PR targets the same stranded state.

## Solution Assessment

Unclear as a final implementation: the open reaper PR targets the right symptom, but its current review record flags durable idempotency and live-proof blockers. The best fix should establish a shared send/clear or claim contract rather than adding an unsafe best-effort flush.
