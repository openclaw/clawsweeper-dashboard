## Summary

Keep open: current main has durable pending-final persistence and some clear-after-success/restart recovery paths, but the reported live-session state where a completed reply remains pending until later inbound activity is not proven fixed. The reporter’s link to the older delivery-loop issue is useful context, and an open candidate PR now targets this exact stranded-pending-final behavior but still needs maintainer review before it can be treated as the canonical fix.

## What This Changes

The issue reports completed gateway sessions whose final reply remains in pendingFinalDelivery until another inbound message flushes delivery.

## Best Possible Solution

Review and either repair or replace the pending-final reaper/durable-delivery approach so terminal sessions deliver or explicitly fail their saved final reply without requiring a later inbound message, while preserving at-most-once semantics and restart recovery.

## Reproduction Assessment

No high-confidence live reproduction was run for the multi-agent Ollama/load scenario. Source inspection gives a medium-confidence reproduction shape: current main can preserve pendingFinalDelivery after failed/unfinished delivery, and the proven recovery paths do not cover a done live session that never restarts.

## Solution Assessment
