The branch changes `unsetConfigValueAtPath` to check the leaf key with `Object.hasOwn` and adds regression tests for prototype-named keys.

## Best Possible Solution

Land the narrow `Object.hasOwn` guard with regression tests after required CI and maintainer review; keep the fix in the config helper rather than widening unrelated path-blocking policy.

## Reproduction Assessment

## Solution Assessment

Yes. Replacing only the leaf existence check with `Object.hasOwn(cursor, leafKey)` is the narrowest maintainable fix; broader blocked-key parsing would not protect direct helper callers as cleanly.
