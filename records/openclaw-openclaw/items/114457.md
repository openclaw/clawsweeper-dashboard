## Summary

Keep this PR open for maintainer review. The patch has focused coverage and proof for the reported fallback gap, but it intentionally changes the shared cross-provider policy for generic `invalid_request_error` responses and also alters gateway retry behavior; the protected `maintainer` label requires an explicit owner decision before merge.

## What This Changes

This PR classifies raw and typed provider `invalid_request_error` responses as format failures so configured model fallbacks can advance, and returns retryable gateway errors while session transcript projections rebuild.

## System Context

Provider adapters and SDKs feed raw or structured errors into OpenClaw’s shared agent failover classifier, which decides whether the outer model-fallback loop should advance to another configured model. Separately, gateway session sends read transcript state before dispatching work, and the PR turns a temporary projection-rebuild failure into an explicit retryable response for clients.

Confirm the shared policy that generic provider request-format rejections may use configured fallbacks, then merge this bounded classifier and pre-dispatch retry handling with its precedence and idempotency coverage intact.
