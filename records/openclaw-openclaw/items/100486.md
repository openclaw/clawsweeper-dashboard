## Summary

Keep open: the patch is in the right hook/cron delivery boundary, but it currently bypasses strict target validation for explicit channel-only hook deliveries and has only mocked/unit proof, so it should not merge as-is.

## What This Changes

The PR changes hook agent dispatch so targetless hook runs create no cron fallback delivery while explicit channel-and-recipient hook targets still announce through cron delivery, with docs and focused tests updated.

## Best Possible Solution

Keep the no-implicit-last-target rule, but use delivery mode none only for truly targetless hook requests; preserve resolver errors for partial explicit targets and prove the hook flow in a real Telegram or logs-backed setup.
