## Summary

Keep this PR open. Its latest head has evolved from the original file-store failure proposal into a focused SQLite-session identity guard that prevents a reset or deleted session from receiving an old run’s pending final reply; the concrete test coverage is promising, but the current PR body’s real-environment proof predates that behavior and does not demonstrate the latest reset/deletion path.

## What This Changes

The branch records a pending final delivery only when the session still has the run’s original identity, then fails the reply run if the session was reset, deleted, or did not retain the committed delivery intent; it adds reply-runner coverage for that race.

## System Context

The auto-reply runner receives a completed agent result and records pending final-delivery metadata in the session store before returning a final reply. Restart and recovery logic later consume that metadata, so the write must stay associated with the same session rather than a replacement created during the model run.
