## Summary

Keep open for maintainer landing: current main and the latest release still have the uncapped omitted-`maxBytes` Google Chat media path, and the PR fixes that path with a docs-aligned 20 MiB bounded read. The patch looks correct; the remaining decision is accepting the exported-helper compatibility change and completing normal landing checks.

## What This Changes

The PR changes Google Chat media downloads so omitted `maxBytes` defaults to a 20 MiB bounded read and adds regression tests for content-length and streamed overflow behavior.

## Best Possible Solution

Land the bounded helper fallback after maintainers accept the compatibility change from unlimited omitted-cap downloads to the 20 MiB Google Chat media default.

## Reproduction Assessment

Yes. Current main leaves omitted `maxBytes` undefined in `fetchBuffer`, then calls `res.arrayBuffer()` for successful media responses, so the unbounded path is source-reproducible without running tests.

## Solution Assessment

Yes. The fix belongs at the Google Chat helper boundary because normal inbound attachment callers already pass `mediaMaxMb`, while direct helper callers need a default cap before reading external media.
