## Label Justifications

- `P2`: This is a normal-priority Google Chat resource-safety bugfix scoped to one bundled plugin helper and its tests.
- `merge-risk: 🚨 compatibility`: Direct helper callers that omitted `maxBytes` would now fail media responses above 20 MiB instead of buffering without a cap.

## Summary

Keep open: this focused bugfix is still necessary because current main and v2026.6.11 still let omitted-cap Google Chat media downloads reach an unbounded `arrayBuffer()` branch. The PR applies the existing 20 MiB Google Chat media default with strong helper-level regression proof; the remaining blocker is maintainer acceptance of the exported-helper compatibility change before landing.

## What This Changes

The PR changes Google Chat media downloads so omitted `maxBytes` uses a 20 MiB bounded read and adds regression tests for content-length overflow, chunked overflow, and stricter explicit caps.

## Best Possible Solution

Land the 20 MiB bounded helper fallback after maintainers accept the compatibility change, while preserving explicit `maxBytes` limits and existing inbound `mediaMaxMb` behavior.

## Reproduction Assessment

Yes. Source inspection on current main shows omitted `maxBytes` reaches the unbounded `res.arrayBuffer()` branch in `fetchBuffer`; the PR's loopback test demonstrates the intended bounded path at the helper boundary.

## Solution Assessment

Yes. The fix belongs at the Google Chat helper boundary because normal inbound attachment callers already pass `mediaMaxMb`, while direct helper callers need a default cap before reading external media.
