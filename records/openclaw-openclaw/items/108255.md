## Label Justifications

- `impact:auth-provider`: The missing parameter changes model/provider request behavior and can cause selected reasoning endpoints to reject or silently alter completions.

## Summary

Keep this issue open. The released plugin runtime completion API omits reasoning control while its downstream completion helper already accepts and forwards that option, leaving catalog-routed plugin calls unable to use some reasoning models reliably; no merged replacement or current-main implementation was found.

## What This Changes

Allow plugins calling `api.runtime.llm.complete` to specify reasoning effort and pass it through to the prepared completion runtime.

## Best Possible Solution

Add an optional canonically typed reasoning field to `LlmCompleteParams`, forward it unchanged into the existing prepared-completion options, and cover both reasoning-mandatory and omitted-field compatibility paths in runtime tests and SDK documentation.

## Reproduction Assessment

Yes at source level: call `api.runtime.llm.complete` for a reasoning-mandatory catalog model and observe that the public params and forwarding options cannot carry reasoning, although the immediate callee supports it. A fresh live provider run would strengthen the already detailed report.

## Solution Assessment

Yes, with one refinement: thread the repository's existing canonical reasoning type through the current API rather than adding a parallel effort representation or provider-specific workaround.
