## Summary

This PR still addresses a real current-main gap: invalid or out-of-range OpenAI Admin usage buckets can reach daily aggregation. The revised boundary check covers both Date overflow and timestamps outside the requested half-open range, and the supplied localhost runtime proof exercises the production fetch and aggregation path; no concrete patch defect is evident from the available PR material.

## What This Changes

The branch skips OpenAI costs and completions usage buckets whose `start_time` is not Date-valid or is outside the requested aggregation range, with regression coverage for negative and overflowing values.

## Best Possible Solution

Land the focused range-and-Date validation after the required CI gates confirm the exact current head; retain the single shared bucket resolver for costs and completions.

## Reproduction Assessment

Yes from source and the supplied live harness: a finite value such as `1e308` survives finite-number coercion but makes JavaScript Date formatting invalid, while a negative value is Date-valid yet outside the requested usage window.

## Solution Assessment

Yes. Filtering at the shared aggregation boundary is narrower and safer than clamping timestamps or adding separate costs/completions handling, because only buckets that cannot legitimately belong to the requested snapshot are discarded.
