## Summary

Keep open: the crash diagnosis and process-RPC handling are sound, but silently swallowing streaming HTTP stdout errors can leave a live request without a terminal body outcome or timely backend finalization.

## What This Changes

Adds stdout/stderr stream-error listeners to both Codex sandbox exec-server child-process owners and regression coverage for bridge survival.

## Best Possible Solution

Keep close-authoritative no-op handling for generic process output and diagnostic HTTP stderr, but terminate the streaming HTTP helper and route stdout protocol errors through the existing `fail()` and finalization path.
