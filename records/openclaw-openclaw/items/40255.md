## Summary

Keep open: current main and v2026.6.11 still violate the documented verbatim heartbeat prompt contract by passing configured prompts through generated heartbeat guidance, and the remaining work is already routed to maintainer review rather than a new cleanup close.

## What This Changes

The issue reports that user-configured heartbeat prompts are no longer respected because OpenClaw adds or substitutes generated heartbeat prompt text.

## Best Possible Solution

Keep this as the canonical tracker and land or replace a focused heartbeat-runtime fix that preserves configured heartbeat prompt text as the model-visible prompt while keeping generated heartbeat markers and guardrails internal or default-only.

## Reproduction Assessment

Yes for source-level reproduction: a configured heartbeat prompt is selected by resolveHeartbeatPromptRaw, then resolveHeartbeatRunPrompt unconditionally runs appendHeartbeatWorkspacePathHint when the prompt mentions HEARTBEAT.md. I did not run a live packaged heartbeat cycle in this read-only review.

## Solution Assessment

No, current main is not the solved state. The narrow maintainable fix should separate user-authored heartbeat prompt text from generated workspace guidance and prove the configured prompt, not the transcript marker, reaches the model-visible body.
