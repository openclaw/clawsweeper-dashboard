## Summary

Keep open: current main and the latest release still mutate configured heartbeat prompts that mention HEARTBEAT.md, and the related transcript-marker evidence remains unresolved while the only open closing-syntax fix is conflicting and not merge-ready.

## What This Changes

The issue reports a regression where configured heartbeat prompts are no longer honored verbatim and can be changed or replaced by generated heartbeat runtime text.

## Best Possible Solution

Land or replace a narrow heartbeat-runtime fix that preserves configured heartbeat prompt text as the model-visible prompt, keeps workspace-path guidance limited to default or internally generated prompts, and keeps [OpenClaw heartbeat poll] transcript-only.

## Reproduction Assessment

Yes. Source inspection shows a configured heartbeat prompt mentioning HEARTBEAT.md is resolved into the heartbeat runner and still passes through the unconditional workspace-hint helper; duplicate trajectory evidence also shows the transcript marker can replace the configured prompt at the model boundary.

## Solution Assessment

No, current main is not the solved state. The best fix is a narrow runtime change that separates user-authored heartbeat prompt text from generated heartbeat guidance and proves the transcript marker stays internal.
