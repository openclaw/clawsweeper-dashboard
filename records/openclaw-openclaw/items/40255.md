## Summary

Keep open: current main and the latest release still append the workspace HEARTBEAT.md path hint after resolving the configured heartbeat prompt, despite the docs saying custom heartbeat prompts are sent verbatim. A linked open fork PR uses closing syntax for this issue but is unmerged and conflicting, so this issue should remain the canonical tracker until that fix is updated, replaced, merged, or closed.

## What This Changes

The issue asks OpenClaw to stop mutating user-configured heartbeat prompts by appending the workspace HEARTBEAT.md path hint.

## Best Possible Solution

Keep this issue as the canonical tracker and land a narrow fix that skips the workspace-path hint for user-authored heartbeat prompts while preserving default/generated prompt guidance and the transcript-only heartbeat marker.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source-reproducible: set a custom heartbeat.prompt containing HEARTBEAT.md, and current resolveHeartbeatRunPrompt still sends the resolved prompt through appendHeartbeatWorkspacePathHint. I did not run a live heartbeat in this read-only review.

## Solution Assessment

Yes, the best fix is narrow: preserve the existing custom prompt contract by applying the workspace-path hint only to built-in or internally generated heartbeat prompts. The transcript marker path should remain transcript-only rather than becoming a model-visible replacement for the configured prompt.
