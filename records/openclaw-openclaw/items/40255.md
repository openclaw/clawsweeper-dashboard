## Summary

Keep open: current main still appends the workspace HEARTBEAT.md path hint to resolved heartbeat prompts that mention HEARTBEAT.md, despite the documented contract that configured heartbeat prompts are sent verbatim; the only open closing-syntax fix path is a conflicting fork PR and is not a merge-ready canonical fix.

## What This Changes

The issue reports a regression where user-configured heartbeat prompts are no longer respected because OpenClaw mutates or replaces the configured prompt during heartbeat runs.

## Best Possible Solution

Land or replace a narrow heartbeat-runtime fix that preserves configured heartbeat prompt text as model-visible input, limits workspace-path guidance to default or internally generated prompts, and keeps the heartbeat transcript placeholder internal to transcript filtering.
