## Summary

Keep open: current main still does not recognize leading `<session-recap>` / `<session_recap>` blocks in the shared inbound metadata stripper, so the Control UI and TUI callers can still render that internal recap text. The linked open fork PR at https://github.com/BingqingLyu/openclaw/pull/252 is the current fix candidate, but it is conflicting and not maintainer-modifiable.

## What This Changes

The issue requests stripping leading session-recap scaffolding from visible user-message rendering in Control UI and TUI while preserving legitimate mid-message user text.

## Best Possible Solution

Land a narrow shared-stripper fix that removes only leading standalone `<session-recap>` and `<session_recap>` blocks, with regression coverage for Control UI/TUI-visible text and mid-message preservation.

## Reproduction Assessment

Yes. Source inspection shows a leading `<session-recap>` block misses the shared fast-path regex, so both `stripInboundMetadata()` and `stripLeadingInboundMetadata()` return before parsing it; I did not run a live UI/TUI reproduction in this read-only review.

## Solution Assessment

Yes. The best fix belongs in the shared inbound metadata stripper because Control UI, TUI, gateway history, and other display paths already use that boundary; per-surface stripping would duplicate policy.
