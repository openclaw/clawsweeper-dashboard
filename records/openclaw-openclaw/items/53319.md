## What This Changes

The issue reports that two rapid `sessions_spawn` calls with `runtime: "acp"` can leave the first child ACP/Claude process accepted but never producing output while the later child eventually runs.

## Best Possible Solution

Run a current live ACPX/Claude rapid two-spawn smoke; if it reproduces, fix the confirmed launch-readiness boundary while preserving distinct-session parallelism unless maintainers deliberately choose a narrower concurrency gate.
