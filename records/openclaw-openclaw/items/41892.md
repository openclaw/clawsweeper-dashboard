Full review comments:

- **[P1] Preserve the current cron.status fields:** `src/cron/service/state.ts:179-185`
  - body: Current main’s status response includes `storage` and `sqlitePath`, but this branch still carries the older `CronStatusSummary` shape while adding `gatewayTimezone`.   - confidence: 0.9
- **[P1] Use the scheduler's deterministic stagger offset:** `ui/src/ui/helpers/cron-timeline.ts:384-388`
  - body: The runtime does not run staggered cron jobs at the midpoint of the window; it hashes `job.id` and uses `sha256(job.id) % staggerMs`. Adding `staggerMs / 2` here can plot jobs at the wrong minute, which makes the timeline and past/pending split disagree with the actual scheduler.
  - confidence: 0.94
- **[P1] Derive timeline status from real job state:** `ui/src/ui/helpers/cron-timeline.ts:542-543`
  - body: This marks every past marker as `ok` and every future marker as `pending`, then applies status CSS from that synthetic value. A job whose last run failed still renders as an OK past dot, so the timeline’s core status signal can contradict `job.state.lastStatus` and the linked issue’s status-color requirement.
  - confidence: 0.88
- **[P2] Regenerate locale output instead of marking English translated:** `ui/src/i18n/locales/de.ts:1239-1249`
  - body: Several non-English bundles add English strings such as `Today's Schedule` while the corresponding generated metadata reports no fallback keys and full translated counts. Per `ui/AGENTS.md`, these generated locale files should be regenerated from the current English source so fallback metadata remains truthful.
  - confidence: 0.86
