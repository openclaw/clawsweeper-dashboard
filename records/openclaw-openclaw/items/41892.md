Full review comments:

- **[P1] Preserve the current cron.status fields:** `src/cron/service/ops.ts:220-229`
  - body: This return object adds `gatewayTimezone` but omits current main's `storage` and `sqlitePath` fields from `cron.status`. Clients can already depend on the storage backend/path fields, so add the timezone field without removing the existing response fields.
  - confidence: 0.96
- **[P1] Use the scheduler's deterministic stagger offset:** `ui/src/ui/helpers/cron-timeline.ts:384-389`
  - body: The timeline applies `staggerMs / 2`, but runtime scheduling uses a stable per-job hash offset from `resolveStableCronOffsetMs(job.id, staggerMs)`. Jobs with stagger can therefore be plotted at the wrong minute and be classified past/pending incorrectly.
  - confidence: 0.94
- **[P1] Derive timeline colors from real job state:** `ui/src/ui/helpers/cron-timeline.ts:542-543`
  - body: Past markers are marked `ok` only because their hour is before the current time, and disabled jobs are skipped before rendering. The linked feature asks for status-colored markers, so failed or disabled jobs can be hidden or painted as healthy instead of reflecting real job state.
  - confidence: 0.9
- **[P2] Regenerate locale output instead of marking English translated:** `ui/src/i18n/locales/de.ts:1240-1251`
  - body: The generated German locale adds timeline keys with English text while its metadata reports no fallbacks. The UI guide treats non-English locale bundles as generated output, so this should come from the i18n sync pipeline or be marked as fallback output.
  - confidence: 0.88
