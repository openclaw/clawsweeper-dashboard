- **[P1] Preserve current cron.status storage fields:** `src/cron/service/ops.ts:221-228`
  - body: This return shape is based on an older status contract: adding `gatewayTimezone` drops current-main `storage` and `sqlitePath`, which are asserted by tests and used by clients. Rebase the branch so the new field is additive and the existing SQLite status fields remain present.
  - confidence: 0.9
- **[P1] Use runtime-equivalent stagger offsets:** `ui/src/ui/helpers/cron-timeline.ts:384-388`
  - body: The timeline adds `staggerMs / 2`, but runtime scheduling hashes the job id modulo the stagger window. Jobs with stagger can be plotted minutes away from the actual slot, flipping past/pending state and sending users to the wrong run history.
  - confidence: 0.88
- **[P1] Derive marker health from real job/run state:** `ui/src/ui/helpers/cron-timeline.ts:542`
  - body: Past markers become `ok` based only on wall-clock position, and disabled jobs are skipped entirely. The linked request asks for ok/fail/disabled coloring, so failed, skipped, unknown, or disabled jobs can look healthy or disappear from the new timeline.
  - confidence: 0.86
- **[P2] Regenerate locale output instead of marking English translated:** `ui/src/i18n/locales/fr.ts:1238-1248`
  - body: Several non-English locale files add English timeline strings while generated metadata reports them as translated rather than fallback text. Per `ui/AGENTS.md`, regenerate the i18n output from the source locale pipeline instead of hand-editing generated bundles into an inconsistent state.
  - confidence: 0.82
