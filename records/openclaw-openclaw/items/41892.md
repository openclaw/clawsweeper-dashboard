Full review comments:

- **[P1] Preserve the current cron.status fields:** `src/cron/service/ops.ts:228`
  - body: Current main's `status()` returns `storage: "sqlite"` and `sqlitePath` along with the legacy `storePath`, but this branch is based on the older return shape and only adds `gatewayTimezone`. Porting this as-is would remove current status metadata, so the rebase needs to keep all existing fields while adding the new one.
  - confidence: 0.92
- **[P1] Use the scheduler's deterministic stagger offset:** `ui/src/ui/helpers/cron-timeline.ts:386`
  - body: The runtime computes cron stagger as a stable hash of `job.id` modulo `staggerMs`, but the timeline adds `staggerMs / 2` and this helper only receives the schedule. Jobs with default or explicit stagger can be plotted at a minute the gateway will never use, which makes past/pending state and history navigation misleading.
  - confidence: 0.9
- **[P1] Derive marker state from real job state:** `ui/src/ui/helpers/cron-timeline.ts:542`
  - body: This classifies every past marker as `ok` and every future marker as `pending`, ignoring the job/run state already available elsewhere on the Cron page. A failed run earlier today will render as ok on the timeline, contradicting the feature's status-color contract.
  - confidence: 0.87
- **[P2] Regenerate translated locale output:** `ui/src/i18n/locales/de.ts:1241`
  - body: The German locale adds English timeline strings while its metadata says there are no fallback keys and all keys are translated. Per the UI i18n guide, non-English locale bundles are generated output; regenerate them or mark the new keys as fallbacks instead of committing English as translated copy.
  - confidence: 0.86
