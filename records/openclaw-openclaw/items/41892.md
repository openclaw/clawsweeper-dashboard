- **[P1] Preserve the current cron.status fields:** `src/cron/service/ops.ts:220-229`
  - body: This return object adds `gatewayTimezone` but omits the current `storage` and `sqlitePath` fields. Current main exposes those SQLite status fields, so merging this head would break clients that read the status storage backend/path; add the timezone field without removing existing response fields.
  - confidence: 0.96
- **[P1] Use the scheduler's deterministic stagger offset:** `ui/src/ui/helpers/cron-timeline.ts:384-389`
  - body: The timeline applies `staggerMs / 2` as an average offset, but the scheduler derives a stable per-job hash offset. Jobs with stagger can therefore be plotted at a different minute than they actually run, making marker position and past/pending classification wrong.
  - confidence: 0.94
- **[P1] Derive timeline colors from real job state:** `ui/src/ui/helpers/cron-timeline.ts:542-543`
  - body: Past markers are marked `ok` only because their hour is before the current time, and disabled jobs are skipped earlier. The linked feature asks for status-colored markers, and current Cron UI already reads persisted last-run status, so this timeline can paint failed past jobs as ok and hide disabled jobs instead of showing real state.
  - confidence: 0.9
- **[P2] Regenerate locale output instead of marking English translated:** `ui/src/i18n/locales/de.ts:1240-1251`
  - body: The German generated locale adds timeline keys whose values are still English while its metadata reports no fallback keys. The UI guide says non-English bundles are generated output, so these should come from the i18n sync pipeline or be marked as fallbacks rather than hand-maintained as translated strings.
  - confidence: 0.88
