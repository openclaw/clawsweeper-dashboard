Full review comments:

- **[P1] Preserve the current cron.status fields:** `src/cron/service/state.ts:182-184`
  - body: This branch adds `gatewayTimezone` to an older `CronStatusSummary` shape, but current main also returns `storage` and `sqlitePath`. Rebase the field onto the current status contract instead of dropping those fields, or existing Control UI/API consumers can lose the storage metadata they now receive.
  - confidence: 0.91
- **[P1] Use the scheduler's deterministic stagger offset:** `ui/src/ui/helpers/cron-timeline.ts:384-388`
  - body: The timeline shifts cron markers by `staggerMs / 2`, but runtime scheduling hashes `job.id` to a stable offset inside the stagger window. For staggered jobs this can plot the marker minutes away from the actual run slot; pass enough job data through to reuse the scheduler-equivalent offset instead of an average.
  - confidence: 0.93
- **[P1] Derive marker state from real job state:** `ui/src/ui/helpers/cron-timeline.ts:526-542`
  - body: The helper skips disabled jobs and marks every past marker as `ok` based only on wall-clock time. That contradicts the requested green/red/gray job-state visualization and can show failed runs as successful; use `job.enabled` plus `job.state.lastRunStatus`/`lastStatus` rather than time alone.
  - confidence: 0.9
- **[P2] Regenerate translated locale output:** `ui/src/i18n/locales/de.ts:1241-1251`
  - body: The generated German locale bundle still contains English timeline strings while its metadata marks the locale fully translated. Follow the UI i18n pipeline so translated bundles and `.i18n` metadata either contain real translations or accurately record fallback keys.
  - confidence: 0.88
