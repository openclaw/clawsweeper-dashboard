Full review comments:

- **[P1] Preserve the current cron.status response fields:** `src/cron/service/ops.ts:220-229`
  - body: This status response is based on an older shape: it adds `gatewayTimezone` but omits current main's `storage` and `sqlitePath` fields, which are part of the current cron.status contract and covered by tests. Rebase this so `gatewayTimezone` is additive rather than replacing the SQLite status fields.
  - confidence: 0.93
- **[P1] Use the scheduler's deterministic stagger offset:** `ui/src/ui/helpers/cron-timeline.ts:386`
  - body: The timeline approximates cron staggering as `staggerMs / 2`, but runtime scheduling uses a stable hash-derived offset from the job id. That can plot runs at different minutes than the scheduler, flipping past/pending markers and sending users to history for a slot that did not actually run.
  - confidence: 0.89
- **[P1] Derive timeline colors from real job state:** `ui/src/ui/helpers/cron-timeline.ts:526-542`
  - body: The linked request asks for ok/fail/disabled coloring, but this path hides disabled jobs and labels any past marker as `ok`. Failed jobs can therefore look healthy and disabled jobs disappear from the overview; use the same job state/status semantics as the job list instead.
  - confidence: 0.88
- **[P2] Regenerate locale output instead of marking English translated:** `ui/src/i18n/locales/de.ts:1241-1251`
  - body: Several generated locale bundles add English timeline strings while their metadata says there are no fallback keys and all keys are translated. That makes the i18n pipeline treat English copy as localized; regenerate/sync the locale output or leave these keys as fallbacks until translated.
  - confidence: 0.86
- **[P3] Remove the release-owned changelog entry:** `CHANGELOG.md:1988`
  - body: Normal PRs should not edit `CHANGELOG.md`; release generation owns this file. Keep the release-note context in the PR body or squash message instead.
  - confidence: 0.93
