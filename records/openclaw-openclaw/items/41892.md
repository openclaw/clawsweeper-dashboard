Full review comments:

- **[P1] Preserve current cron status metadata:** `src/cron/service/ops.ts:228`
  - body: The PR adds `gatewayTimezone` on top of an older `cron.status` return shape, but current main also returns `storage: "sqlite"` and `sqlitePath`. The rebase/conflict fix must keep those fields or status clients lose the current SQLite metadata while gaining the new timezone field.
  - confidence: 0.92
- **[P2] Use real run state for past markers:** `ui/src/ui/helpers/cron-timeline.ts:542`
  - body: Timeline markers become `ok` whenever their scheduled hour is in the past, regardless of whether the job actually ran, failed, was skipped, or has no history. Derive marker state from job/run status, or avoid claiming a past marker is healthy from time alone.
  - confidence: 0.88
- **[P2] Match the runtime's deterministic stagger offset:** `ui/src/ui/helpers/cron-timeline.ts:386`
  - body: The helper approximates cron staggering with `staggerMs / 2`, but the runtime uses a deterministic per-job hash offset. Staggered jobs can be plotted at the wrong minute and misclassified as past or pending unless the timeline uses runtime-equivalent offset logic.
  - confidence: 0.86
- **[P2] Regenerate translated locale output:** `ui/src/i18n/locales/de.ts:1241-1251`
  - body: The German and several other non-English bundles add English timeline strings while their metadata reports no fallback keys. Regenerate the Control UI locale output through the i18n pipeline so non-English users do not see stale English copy marked as translated.
  - confidence: 0.8
- **[P3] Remove the release-owned changelog edit:** `CHANGELOG.md:1988`
  - body: `CHANGELOG.md` is release-generated in this repo, so this feature PR should keep release-note context in the PR body or squash message rather than editing the release file directly.
  - confidence: 0.82
