Full review comments:

- **[P1] Preserve the current cron.status fields:** `src/cron/service/ops.ts:220-229`
  - body: This branch adds `gatewayTimezone` to an older `cron.status` response shape, but current main already returns `storage` and `sqlitePath` from the same RPC. When this is rebased or ported, dropping those fields would regress existing clients; add the timezone field on top of the current status contract instead of replacing it.
  - confidence: 0.95
- **[P1] Use the scheduler's deterministic stagger offset:** `ui/src/ui/helpers/cron-timeline.ts:384-388`
  - body: The timeline applies `schedule.staggerMs / 2`, but runtime scheduling uses a stable hash-based offset per job id and tests assert that exact behavior. For most staggered cron jobs this plots the marker at a time that the scheduler will not actually run; reuse or expose the scheduler projection rather than averaging the window.
  - confidence: 0.96
- **[P1] Derive marker state from real job state:** `ui/src/ui/helpers/cron-timeline.ts:520-543`
  - body: `hour <= nowH ? "ok" : "pending"` makes any earlier marker look successful even when the job's last run failed or was skipped, and disabled jobs are filtered out entirely. The linked feature asks for status colors, and the existing job list already derives real status from persisted job state; the timeline should use that same state instead of time-of-day.
  - confidence: 0.91
- **[P2] Regenerate translated locale output:** `ui/src/i18n/locales/de.ts:1240-1251`
  - body: The generated German metadata says there are no fallback keys and all keys are translated, but the new `cron.timeline.*` strings remain English. The UI guide says non-English locale bundles and `.i18n` metadata are generated output, so regenerate or correctly mark fallbacks instead of committing hand-maintained English strings as translated.
  - confidence: 0.93
