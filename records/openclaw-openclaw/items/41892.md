## Review Findings

Overall correctness: patch is incorrect

Full review comments:

- **[P2] Use scheduler-compatible stagger placement:** `ui/src/ui/helpers/cron-timeline.ts:384-388`
  - body: The timeline receives only `job.schedule` and then adds `staggerMs / 2`, but runtime cron uses a deterministic per-job offset derived from the job id. For top-of-hour jobs with the default 5-minute stagger, the dot can be minutes away from the actual scheduled slot and flip past/pending at the wrong time; pass enough job identity through and reuse the same stagger math or expose a scheduler projection instead of approximating.
  - confidence: 0.9
- **[P2] Use real run state for marker status:** `ui/src/ui/helpers/cron-timeline.ts:542`
  - body: This marks every earlier scheduled marker as `ok` purely from wall-clock time, ignoring failed, skipped, unknown, or missed runs already available on the job state and run history. The timeline then shows a green/success-looking dot for jobs that may have failed; derive marker status from the existing cron run state instead of time-of-day alone.
  - confidence: 0.88
- **[P3] Regenerate non-English timeline labels:** `ui/src/i18n/locales/de.ts:1241-1251`
  - body: The German locale metadata claims no fallback keys and all keys translated, but the newly added timeline strings remain English. Because these locale bundles are generated output, rerun the i18n pipeline or fix the generator input so non-English users do not see untranslated controls.
  - confidence: 0.84

  - confidence: 0.86
