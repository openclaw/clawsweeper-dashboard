Full review comments:

- **[P1] Preserve the current cron.status fields:** `src/cron/service/ops.ts:228`
  - body: Current main's status response includes storage and sqlitePath along with storePath, but this branch returns the older shape and only adds gatewayTimezone. A rebase must keep all current status fields while adding any optional timeline data, or current clients can lose response metadata.
  - confidence: 0.92
- **[P1] Use the scheduler's deterministic stagger offset:** `ui/src/ui/helpers/cron-timeline.ts:386`
  - body: The runtime computes a stable per-job stagger from job.id modulo staggerMs, but the timeline adds schedule.staggerMs / 2 and does not pass the job id into that calculation. Staggered jobs can be plotted at times the gateway will never schedule, which makes marker position and past/pending state unreliable.
  - confidence: 0.9
- **[P1] Derive marker state from real job state:** `ui/src/ui/helpers/cron-timeline.ts:542`
  - body: The timeline marks every past marker as ok and every future marker as pending, ignoring the job/run state already shown elsewhere on the Cron page. A failed or skipped run earlier today would appear green in the new timeline, contradicting the feature's status-color contract.
  - confidence: 0.87
- **[P2] Regenerate translated locale output:** `ui/src/i18n/locales/de.ts:1241`
  - body: The German locale adds English timeline strings while its metadata says there are no fallback keys and all keys are translated. Per the UI i18n guide, non-English locale bundles are generated output, so regenerate them or mark the new keys as fallbacks instead of committing English as translated copy.
  - confidence: 0.86
