- **[P1] Preserve current cron.status fields on rebase:** `src/cron/service/ops.ts:223-228`
  - body: The branch adds `gatewayTimezone` to an older `cron.status` response shape, while current main also returns `storage` and `sqlitePath`.   - confidence: 0.9
- **[P2] Use real run state for past markers:** `ui/src/ui/helpers/cron-timeline.ts:542`
  - body: `status: hour <= nowH ? "ok" : "pending"` marks every past scheduled slot as OK even when the job's stored state says the last run errored/skipped or when no run happened. That makes the timeline hide exactly the failures and missed runs users use the Cron page to spot.
  - confidence: 0.92
- **[P2] Match the scheduler's stable stagger offset:** `ui/src/ui/helpers/cron-timeline.ts:384-388`
  - body: The timeline adds `staggerMs / 2`, but runtime scheduling uses a stable per-job hash offset (`sha256(job.id) % staggerMs`). Default top-of-hour and explicitly staggered jobs can therefore be plotted minutes away from their actual execution slots.
  - confidence: 0.9
- **[P2] Regenerate locale output through the i18n pipeline:** `ui/src/i18n/locales/de.ts:1240-1250`
  - body: The German bundle claims no fallback keys and full translation metadata, but the new timeline strings are English. Since `ui/AGENTS.md` treats non-English locale bundles as generated output, these should be regenerated instead of landing stale or hand-filled locale files.
  - confidence: 0.86

  - body: Normal PRs should not edit `CHANGELOG.md`; release generation owns it. Keep the release-note context in the PR body or squash message and drop this direct changelog hunk.
