- **[P1] Preserve current cron status fields:** `src/cron/service/ops.ts:220-228`
  - body: This status hunk is stale against current main: current `status()` returns `storage` and `sqlitePath`, and tests assert them. When resolving the conflict, keep those fields while adding `gatewayTimezone`; otherwise clients that consume SQLite status metadata regress.
  - confidence: 0.9
- **[P2] Use run state for past markers:** `ui/src/ui/helpers/cron-timeline.ts:542`
  - body: Markers are marked `ok` whenever the scheduled hour is earlier than browser now, so failed, skipped, undelivered, or never-run jobs can show as successful. The timeline should reflect existing cron job/run state or avoid claiming success.
  - confidence: 0.92
- **[P2] Match the runtime's deterministic stagger:** `ui/src/ui/helpers/cron-timeline.ts:384-388`
  - body: `staggerMs / 2` is only an average; runtime scheduling hashes the job id modulo the stagger window. This can place timeline dots minutes away from actual execution and flip pending/past classification.
  - confidence: 0.88
- **[P2] Regenerate locale output:** `ui/src/i18n/locales/de.ts:1241-1251`
  - body: The generated German bundle marks all keys translated in metadata but displays English strings for the new timeline keys. Regenerate/update i18n output so generated bundles either contain real translations or explicit fallback metadata.
  - confidence: 0.86
- **[P3] Remove the release-owned changelog edit:** `CHANGELOG.md:9`
  - body: OpenClaw release generation owns `CHANGELOG.md` for normal PRs. Keep this release-note context in the PR body or squash message and drop the direct changelog entry.
