Full review comments:

- **[P1] Preserve current cron.status fields when adding gatewayTimezone:** `src/cron/service/ops.ts:222-228`
  - body: This hunk adds `gatewayTimezone` to the older status response shape, but current main also returns `storage` and `sqlitePath`. Because the live PR is dirty, taking this hunk as-is would regress existing status clients back to the deprecated path-only response.
  - confidence: 0.91
- **[P2] Stop marking past slots successful without run state:** `ui/src/ui/helpers/cron-timeline.ts:542`
  - body: Every marker before `now` is emitted as `ok`, so failed, skipped, not-delivered, or never-run slots can be shown as green success. Derive marker state from run history/job state, or use neutral past/future wording instead of success.
  - confidence: 0.92
- **[P2] Use the scheduler's stable stagger offset:** `ui/src/ui/helpers/cron-timeline.ts:384-388`
  - body: Runtime cron scheduling hashes the job id within `staggerMs`, but this helper shifts every marker by `staggerMs / 2`. Staggered jobs can be plotted minutes away from their actual run slot, which breaks the NOW and past/pending cue near schedule time.
  - confidence: 0.94
- **[P3] Regenerate generated locale output:** `ui/src/i18n/locales/de.ts:1241-1251`
  - body: The German generated bundle has English timeline strings while its metadata says all keys are translated. Update the English/source wiring and regenerate locale outputs instead of landing inconsistent generated strings.
  - confidence: 0.86

  - body: `CHANGELOG.md` is release-generated in this repo. Keep the release-note context in the PR body or squash message and drop this normal feature PR's direct changelog edit.
