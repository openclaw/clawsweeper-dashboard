## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve current cron.status fields:** `src/cron/service/ops.ts:220-228`
  - body: This branch edits `cron.status` from an older response shape and returns only `enabled`, `storePath`, `jobs`, `nextWakeAtMs`, and `gatewayTimezone`. Current main also returns `storage` and `sqlitePath` with regression assertions, so the rebase needs to keep those fields while adding `gatewayTimezone` or existing status consumers will lose the SQLite storage signal.
  - confidence: 0.9
- **[P1] Derive marker status from real run state:** `ui/src/ui/helpers/cron-timeline.ts:542`
  - body: The timeline marks every past enabled marker as `ok` based only on the current clock and skips disabled jobs. Failed, skipped, or disabled jobs can therefore be shown as healthy or disappear, even though the linked request asks for ok/fail/disabled status coloring.
  - confidence: 0.9
- **[P1] Use the runtime stagger offset for cron markers:** `ui/src/ui/helpers/cron-timeline.ts:384-388`
  - body: This adds `staggerMs / 2` to every cron marker, but runtime scheduling uses a deterministic hash-derived offset per job id. Staggered jobs can be plotted minutes away from their actual execution time and flip between pending and ok around the real run slot.
  - confidence: 0.88
- **[P2] Do not wildcard cron constraints the parser cannot handle:** `ui/src/ui/helpers/cron-timeline.ts:431-436`
  - body: For restricted fields the helper treats an empty parse result as a wildcard. Runtime delegates the expression to Croner instead, so a constraint the UI parser does not understand can produce timeline markers on days or months the scheduler would not actually run.
  - confidence: 0.82
- **[P2] Regenerate locale bundles instead of marking English as translated:** `ui/src/i18n/locales/fr.ts:1238-1248`
  - body: The French bundle adds English timeline copy while its metadata says there are no fallback keys and all keys are translated. Generated locale files should come from the i18n pipeline so non-English users do not get silent English strings marked complete.
  - confidence: 0.86
- **[P3] Keep changelog edits in the release flow:** `CHANGELOG.md:1988`
  - body: Normal feature PRs should not edit `CHANGELOG.md`; release generation owns that file. Please keep this release-note context in the PR body or eventual squash message and drop the direct changelog entry from the branch.
  - confidence: 0.8
