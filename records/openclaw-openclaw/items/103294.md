## Label Justifications

- `P1`: The current patch can make existing Web Push subscriptions disappear from the live runtime immediately after upgrade.
- `merge-risk: 🚨 compatibility`: The patch archives two shipped persisted-state files and changes startup behavior for corrupt legacy state.
- `merge-risk: 🚨 message-delivery`: If the runtime continues reading the archived JSON file, existing browser subscriptions are omitted from broadcasts.
- `merge-risk: 🚨 availability`: Unreadable legacy Web Push state now aborts the entire Gateway startup rather than isolating the optional notification feature.

## Summary

The SQLite migration is directionally aligned, but this head archives the legacy Web Push files without changing the live `push-web.ts` persistence path from those JSON files to SQLite, so an upgraded Gateway can lose its loaded subscriptions and regenerate VAPID identity. The direct SQLite transcript does not exercise that broken end-to-end path.

## What This Changes

The PR adds shared-SQLite storage and a Gateway-startup importer for Web Push subscriptions and VAPID keys, plus migration coverage and storage-location comments.

## Best Possible Solution

Keep the shared-SQLite direction, but route every public Web Push read, write, VAPID get-or-create, and cleanup through row-scoped transactional store operations before archiving JSON, then prove a real Gateway upgrade preserves VAPID identity and delivers to an existing subscription.
