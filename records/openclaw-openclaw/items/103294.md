## Summary

This PR remains necessary and follows the database-first storage direction, but the current migration still treats unreadable legacy files as absent, allowing gateway startup to continue with empty SQLite state; the supplied proof also covers only fresh CRUD rather than the upgrade path.

## What This Changes

Moves Web Push subscriptions and VAPID-key persistence from legacy JSON files to the shared SQLite state database with a gateway-startup importer.

## Best Possible Solution

Make migration distinguish an absent legacy file from unreadable or malformed state, prevent empty-store startup when recoverable legacy data cannot be imported, add focused migration coverage, and demonstrate a redacted legacy upgrade followed by successful Web Push delivery.
