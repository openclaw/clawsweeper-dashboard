## Summary

Keep open: the proposed guard fixes the reported false clamp, but it also disables the remaining-context protection whenever the completion cap is individually below the context window, including valid cases where prompt tokens plus completion tokens still exceed that window. The external PR also lacks after-fix real-provider proof.

## What This Changes

The PR restricts proxy-like OpenAI completion-budget clamping to configurations where the resolved completion cap meets or exceeds the effective context window and adds a large-prompt regression test.

## Best Possible Solution

Use one authoritative input-budget calculation across context precheck and outbound payload construction, clamp against the actual remaining context without collapsing valid requests to one token, and cover both the false-clamp case and the under-window-cap combined-overflow case.
