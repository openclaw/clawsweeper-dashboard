## Summary

The reported unauthenticated HTTP exposure does not match current OpenClaw: the named tool-server files are stdio MCP processes, while the separate loopback HTTP MCP endpoint already requires a bearer credential and rejects browser-origin requests before invoking tools. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/mcp/openclaw-tools-serve.ts))

## What This Changes

Investigate and secure an allegedly unauthenticated local HTTP endpoint that could invoke OpenClaw tools.

## Best Possible Solution

Keep the standalone tool bridges on process-owned stdio and retain bearer, loopback, Origin, and scoped-grant enforcement on the separate HTTP bridge; any future bypass report should identify the exact endpoint, request, version, and observed unauthorized tool result through the private security channel.
