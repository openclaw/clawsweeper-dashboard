## Summary

Keep open. Current main still exposes raw provider strings in Control UI Sessions/Usage display, filters, CSV, query matching, and aggregate keys, while the direct implementation PR is closed unmerged and the final alias-display contract still needs maintainer direction.

## What This Changes

The issue asks Control UI Sessions and Usage surfaces to show canonical provider ids instead of raw configured aliases such as `bailian` or `z-ai`.

## Best Possible Solution

Define the provider-display contract, then canonicalize only derived Sessions/Usage display, filter, query, CSV, and aggregate surfaces while preserving raw stored config/session values and avoiding new aliases unless approved.

## Solution Assessment

No, not exactly as proposed. Applying a minified helper everywhere is too blunt; the safer fix is a maintainer-approved derived-display and aggregate canonicalization contract that does not rewrite raw stored config/session fields.
