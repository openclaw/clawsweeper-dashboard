## Summary

Keep open. Current main still derives Control UI Sessions/Usage display, filters, CSV export, and usage aggregate keys from raw provider strings, while the z.ai plugin manifest has canonical aliases; the direct fix PR was closed unmerged, so there is no main implementation to close against.

## What This Changes

The issue requests consistent canonical provider display in the Control UI instead of showing raw configured provider aliases in Sessions and Usage views.

## Best Possible Solution

Define the provider-display canonicalization contract, then normalize derived Control UI Usage/Sessions display, filters, suggestions, CSV, and aggregate keys while preserving raw config and session storage.
