Keep open. Current main still uses raw provider strings across the affected Control UI Sessions/Usage display, filter, CSV, and aggregate paths, and the direct fix attempt is closed unmerged while the provider-display contract still needs maintainer direction.

## What This Changes

The issue asks Control UI provider displays to use canonical provider IDs instead of raw alias values from configuration.

## Best Possible Solution

Define one supported provider-display canonicalization contract, then implement it once across derived Sessions/Usage labels, filters, suggestions, CSV, and aggregate keys while preserving raw stored session/config fields.
