## Summary

Keep open. Current main still routes the affected Control UI Sessions/Usage display, filters, CSV export, and aggregate keys through raw provider strings, and the direct implementation attempt is closed unmerged while the exact canonical-display contract still needs maintainer confirmation.

## What This Changes

The issue asks Control UI Sessions and Usage views to display normalized provider identities consistently instead of raw configured aliases such as `bailian`.

## Best Possible Solution

Define the supported provider-display canonicalization contract, then normalize derived Usage/Sessions display, filters, query suggestions, CSV, and aggregate keys while preserving raw stored config and session fields.

- **Show alias with canonical context:** Display labels such as `zai (alias: bailian)` or tooltips where the raw alias matters, at the cost of a wider UI contract and more copy/tests.

## Reproduction Assessment

Yes, at source level. Current main still renders or groups `modelProvider`, `providerOverride`, and usage `entry.provider` directly in Sessions/Usage paths, so raw provider strings can remain visible without a browser repro.

## Solution Assessment

No, not exactly as proposed. Applying a minified `Jp()`-style helper everywhere is too blunt; the safer fix is a maintainer-approved derived-display and aggregate canonicalization contract that does not rewrite raw stored config/session fields.
