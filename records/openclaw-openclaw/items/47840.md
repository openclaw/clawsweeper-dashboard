Keep open. Current main still derives several Control UI Usage/Sessions display, query, CSV, and aggregate values from raw provider strings, while the direct implementation PR is closed unmerged and the exact alias/display contract still needs maintainer confirmation.

## What This Changes

The issue asks the Control UI to show canonical normalized provider IDs instead of raw configured aliases across Sessions and Usage views.

## Best Possible Solution

Define the supported provider-display contract, then normalize derived Sessions/Usage display, filters, suggestions, CSV, and aggregate grouping through the existing provider alias contract while preserving raw stored config/session fields.
