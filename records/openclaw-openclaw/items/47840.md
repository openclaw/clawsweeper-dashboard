## Summary

Keep open. Current main and v2026.6.11 still have raw provider values flowing through Control UI usage display, filters, CSV export, and aggregate keys, while the direct fix PR was closed unmerged and the canonical-vs-alias display contract still needs maintainer direction.

## What This Changes

The issue asks Control UI to display normalized provider ids instead of raw provider aliases across Sessions, Usage, model selection, and agent configuration surfaces.

## Best Possible Solution

Define one provider-display and usage-aggregation contract, then normalize alias-equivalent provider ids at the gateway/UI query, export, aggregate, and render boundaries while preserving raw alias context where maintainers want it visible.

- **Preserve raw display:** Leave raw aliases visible and only fix narrower matching/deduplication bugs, accepting the reported UI/internal inconsistency.
