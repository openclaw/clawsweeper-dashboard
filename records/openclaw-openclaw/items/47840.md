## Summary

Keep open. Current main still displays, filters, exports, and aggregates raw provider strings in the affected Control UI Sessions/Usage paths, and the direct implementation PR is closed unmerged; the remaining decision is the visible alias contract, not whether the source path exists.

## What This Changes

The issue requests consistent Control UI display of normalized model provider ids such as showing `zai` instead of raw alias values like `bailian`.

## Best Possible Solution

Define the provider-display contract, then canonicalize derived Sessions/Usage display, query, CSV, and aggregate surfaces with an approved provider-id normalizer while preserving raw config/session data.

## Solution Assessment

No, not exactly as proposed. Applying a minified helper everywhere is too blunt; the maintainable fix is an explicit derived-display and aggregate canonicalization contract that does not rewrite raw stored config/session fields.
