## Label Justifications

- `P2`: Signal edits can duplicate context or responses, but this is a bounded channel behavior requiring product semantics rather than emergency repair.
- `impact:message-loss`: Corrected content is still processed as a separate ordinary message while stale original content may remain actionable.
- `impact:session-state`: The original/edit relationship is not modeled as edit metadata or session supersession.

## Summary

Current main’s unreleased native Signal reply-quote work adds `targetSentTimestamp` typing and maps it to `ReplyToId`, but edited content still receives a new `MessageSid` and follows the ordinary inbound dispatch path. The requested edit marker, session supersession or dedupe, and reply-trigger policy therefore remain unresolved; broader cross-channel cancellation is separately tracked.

## What This Changes

Handle Signal `editMessage` envelopes as edits linked to the original message so corrected content does not become an unrelated duplicate turn.

## Best Possible Solution

Add explicit Signal edit metadata and a visible edited marker while preserving separate event and target identities; after maintainer direction, either keep edits as marked turns or add a shared lifecycle seam for supersession and mention-gated dispatch, with cross-channel cancellation remaining in the broader lifecycle issue.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Signal edits remain distinct inbound turns carrying edit metadata, or supersede the original turn and suppress a second reply unless the edit explicitly mentions the agent?

Rationale: signal-cli defines the transport relationship, but current OpenClaw contracts do not define how an edit mutates session history or triggers agent work, and the alternatives have materially different context and delivery semantics.

Likely owner: steipete

Owner reason: This decision spans Signal inbound dispatch and shared channel/session lifecycle seams where this person has the broadest recent history.

Owner confidence: high

Options:

- **Distinct marked edit (recommended):** Keep a unique edit event id, expose the original target id as structured metadata, and add an edited marker without rewriting prior history.
- **Supersede original turn:** Introduce a session-level edit operation that invalidates or replaces the original turn and avoids duplicate processing.
- **Mention-gated group edits:** Ingest non-mentioned group edits as context-only updates and dispatch only edits that explicitly mention the agent.

## Reproduction Assessment

Yes, at source level. The current handler and focused edit fixture show that edits use ordinary inbound dispatch identity while only native reply targeting references the original message.

## Solution Assessment

No. The current native-reply mapping is useful but does not solve edit visibility, duplicate context, transcript supersession, or response-trigger behavior; a distinct edit contract is the safer foundation.
