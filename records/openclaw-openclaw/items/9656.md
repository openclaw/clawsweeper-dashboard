## Label Justifications

- `P2`: Signal edits can duplicate context and responses for affected conversations, but the impact is bounded to an optional channel workflow rather than core availability.
- `impact:message-loss`: Edited Signal messages can be treated as independent messages, causing duplicated or incorrectly triggered channel responses.
- `impact:session-state`: The original and corrected message can both remain in agent context without a reliable supersession relationship.

## Summary

Keep this issue open. Current main still flattens Signal edit envelopes into the ordinary inbound-message path, while the only Signal-specific implementation PR closed unmerged and the broader cross-channel cancellation issue does not replace this Signal ingestion and transcript-state work.

## What This Changes

Handle Signal `editMessage` envelopes as edits linked to the original message rather than independent inbound messages that duplicate context or responses.

## Best Possible Solution

Add an explicit edit path inside the bundled Signal plugin that types and validates `targetSentTimestamp`, supersedes matching queued or pending Signal context with structured edited metadata, and retriggers group responses only for an explicit mention; leave cancellation of already-running turns to the cross-channel lifecycle work.

## Maintainer Decision

Question: When a Signal edit targets a message that has already entered session processing, should OpenClaw replace pending context without waking the agent, or also cancel and restart an active run?

Rationale: The parser and identity repair are clear, but transcript mutation and active-run cancellation affect session semantics beyond Signal transport normalization and require an intentional product contract.

Likely owner: steipete

Owner reason: The feature history and existing issue review connect this person most directly to Signal inbound routing and the pending product-policy choice.

Owner confidence: high

Options:

- **Bounded Signal supersession (recommended):** Replace matching pending context, preserve edited metadata, and wake only on explicit mention while leaving active-run cancellation to the cross-channel issue.
- **Cancel and restart active runs:** Treat an edit as superseding the active instruction and restart processing from corrected content, coupling this change to shared run-cancellation behavior.
- **Append an edit event:** Keep both transcript entries but mark the later one as an edit, accepting additional context and possible model ambiguity.

## Reproduction Assessment

Yes at the source level: an `editMessage.dataMessage` follows the normal Signal inbound path and receives the new envelope timestamp as its identity. No live Signal capture was required to establish that current-main behavior, though live proof should accompany a future PR.

## Solution Assessment

The requested direction is mostly correct, but its marker, replacement, and reply-suppression alternatives are not equivalent. The most maintainable solution is explicit Signal edit normalization plus a defined supersession policy, without folding cross-channel active-run cancellation into the transport patch.
