## Summary

Keep this issue open. The supplied July 18 current-main review shows Signal edits still enter the normal inbound-turn path under the new envelope identity, so OpenClaw lacks a settled edit-to-transcript and reply-suppression contract; the only focused Signal PR was closed unmerged.

## What This Changes

Add explicit Signal `editMessage` handling so corrected messages retain their relationship to the original message and do not create an unintended extra agent turn.

## System Context

The bundled Signal plugin receives signal-cli envelopes and normalizes their message content into queued inbound messages for session routing and agent dispatch. An edit envelope needs to preserve its original-message relationship before that queue and dispatch path decide transcript identity and whether to reply.

## Architecture Diagram

flowchart LR

  B --> C[Signal plugin]
  C --> D[Edit classification]
  D --> E[Session transcript and message identity]

  E --> G[Agent context]
  F --> H[Inbound dispatch]

## Best Possible Solution

Define one Signal-plugin edit contract: retain `targetSentTimestamp` as structured metadata, map it to the original inbound identity, update or explicitly annotate transcript state, and dispatch only when the edited content passes the chosen mention policy; add focused envelope, identity, history, and group-mention tests plus live Signal evidence.

- **Replace and mention-gate (recommended):** Use the target timestamp to update the original context entry and suppress a new turn unless the corrected group message explicitly mentions the agent.
- **Append explicit edit events:** Preserve both versions with structured edit metadata and make dispatch policy explicit, accepting more transcript complexity.
- **Broaden to cross-channel cancellation:** Design a generic recall/edit-to-active-run cancellation contract first, then implement Signal against that shared seam.
