## Summary

Keep open. Current main recognizes the upstream Signal edit target only for native reply quoting; it still treats edited content as a distinct ordinary inbound event, so correction metadata, context linkage or replacement, edit-aware dedupe, and an explicit reply policy remain unresolved. The closed unmerged implementation is useful prior art but is neither shipped nor a complete safe fix.

## What This Changes

Handle Signal `editMessage` envelopes as corrections linked to the original message instead of unrelated ordinary inbound messages.

## Best Possible Solution

Add a Signal-owned edit normalization path with separate event and correction-target IDs, structured edited metadata, and edit-aware group reply suppression; append a clear correction context initially, and pursue true transcript replacement only through an explicitly approved generic session-state API.
