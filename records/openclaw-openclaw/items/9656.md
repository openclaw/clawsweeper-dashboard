## Summary

Keep this issue open. The supplied current-main review shows Signal edit payloads are recognized and can target the original timestamp for replies, but they still travel through the ordinary inbound-turn path using the new envelope timestamp as message identity; that leaves no settled contract for transcript replacement, deduplication, or reply suppression. The only direct implementation attempt, https://github.com/openclaw/openclaw/pull/9701, closed unmerged. 

Likely related people: `steipete` is the strongest routing candidate from Signal monitor history (high confidence); `scoootscooob` and `zerone0x` are adjacent Signal-path contributors (medium confidence).

## What This Changes

Add explicit Signal `editMessage` handling so corrected inbound messages are tied to their originals instead of behaving as unrelated session turns.

## System Context

The Signal plugin converts signal-cli envelopes into normalized inbound messages, then hands them to OpenClaw’s shared dispatch and session pipeline. An edit event must be classified before message identity, transcript context, and automatic-reply routing are finalized.

## Architecture Diagram

flowchart LR
  A[Signal edit envelope] --> B[Signal plugin]
  B --> C[Edit classification]
  C --> D[Message identity]
  C --> E[Transcript context]
  D --> F[Inbound dispatch]
  E --> F
  F --> G[Agent reply decision]

## Best Possible Solution

Define a supported edit-event contract that preserves the original-message relationship, updates or supersedes context deterministically, and suppresses unsolicited edit-triggered turns by default; implement Signal as the first owner-plugin consumer with focused envelope, identity, transcript, and mention-gating coverage.

Rationale: The current inbound pipeline has no established edit-to-transcript or edit-to-active-run policy, so choosing one affects channel consistency and shared session semantics rather than only Signal parsing.

Likely owner: steipete

Owner confidence: high

Options:

- **Define a bounded edit contract (recommended):** Specify structured edit metadata, original-message matching, transcript supersession, and default no-reply behavior, with explicit mention handling as the only initial opt-in dispatch path.
- **Treat edits as informational only:** Keep normal inbound dispatch but attach an edited marker, accepting duplicate context and potential turn behavior as a documented limitation.
- **Fold edits into active-run cancellation:** Design a cross-channel recall/edit lifecycle with the broader work in https://github.com/openclaw/openclaw/issues/55691 before adding Signal behavior.
