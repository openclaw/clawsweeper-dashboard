## Label Justifications

- `P2`: Signal edits can create stale or duplicate conversational behavior, but the problem is limited to one channel and does not disable the core runtime.
- `impact:message-loss`: OpenClaw loses the semantic relationship that corrected Signal content supersedes a specific original message and can process both versions independently.
- `impact:session-state`: Original and edited content can become independent session messages, causing transcript and active-turn context drift.

## Summary

Keep this issue open. Current main still flattens Signal edit envelopes into the ordinary inbound path with a new message identity and no defined supersession, context-update, or response-trigger policy. The closed unmerged candidate PR is useful prior art, while the broader cross-channel cancellation issue does not replace this Signal-specific work.

## What This Changes

Add explicit Signal `editMessage` handling so corrected content retains its relationship to the original message and follows defined context and response-trigger semantics.

## Best Possible Solution

Implement a Signal-owned edit event path with typed target identity and structured edit metadata, then apply a maintainer-approved supersession and wake policy with focused fresh-edit, post-dispatch, group-mention, dedupe, and context-history coverage.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What should be authoritative when a Signal edit arrives after the original message may already be stored or running: append an explicit edit event, replace the prior context entry, or cancel and re-run from corrected content?

Rationale: signal-cli supplies the target identity, but OpenClaw has no established contract for mutating prior transcript context or deciding whether edits should wake an agent after dispatch.

Likely owner: steipete

Owner reason: The strongest available history and prior discussion both connect this person to Signal inbound routing and the unresolved behavior choice.

Owner confidence: high

Options:

- **Append structured edit event (recommended):** Keep the original history, add target-linked corrected content, and wake only under an explicit mention or active-turn policy.
- **Replace prior context:** Mutate the authoritative prior inbound entry and define behavior for persisted transcripts and already-running turns.
- **Cancel and re-run:** Cancel work triggered by the original and dispatch corrected content, aligning with broader recall/edit cancellation at substantially larger scope.

## Reproduction Assessment

No live reproduction was performed, but the issue is source-reproducible with high confidence: Signal edits enter the ordinary inbound path and use the edit envelope timestamp as their identity.

## Solution Assessment

No. Target-timestamp deduplication plus an `[edited]` prefix is incomplete because dedupe may discard the correction and does not define transcript or active-turn semantics; an explicit edit event path is safer.
