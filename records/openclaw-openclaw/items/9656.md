## What This Changes

Add Signal edit-envelope handling that retains the original-message relationship, avoids duplicate session context or replies, and defines how edits affect transcript state.

## Best Possible Solution

Define a narrow Signal edit contract first: normalize the target timestamp as structured edit metadata in the Signal plugin, then have the session owner explicitly decide transcript supersession and active-run behavior rather than treating an edit as a second ordinary message.
