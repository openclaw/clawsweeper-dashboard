## Label Justifications

- `P2`: Signal edits can duplicate context and responses for affected conversations, but they do not make the core runtime broadly unusable.
- `impact:session-state`: The issue concerns associating corrected content with the original turn and preventing stale or duplicated transcript context.

## Summary

Keep this issue open. Current main still treats Signal edit envelopes as ordinary inbound messages, while the closed unmerged candidate PR did not settle transcript supersession or edit-triggered response behavior. The transport gap is clear, but the authoritative context-update and wake policy requires maintainer direction.

## What This Changes

Handle Signal `editMessage` envelopes as edits associated with the original message instead of independent inbound messages.

## Best Possible Solution

Add a generic inbound supersession/edit contract at the plugin-to-session boundary, map Signal `targetSentTimestamp` into it, update or annotate authoritative context deterministically, and apply an explicitly chosen mention and active-run wake policy with focused Signal and session tests.

Options:

- **Structured correction event (recommended):** Map the edit to its original message, preserve an explicit edited marker or metadata, and suppress a new group response unless the corrected text mentions the agent.
- **Replace and restart:** Replace the original transcript content and cancel or restart any active turn that was based on the stale text.
- **Keep current semantics:** Continue treating edits as new messages and close the request as unsupported behavior.

## Reproduction Assessment

Yes at source level: feed the Signal monitor an envelope containing `editMessage.targetSentTimestamp` and `editMessage.dataMessage`; current routing treats it as an ordinary message with independent identity. A live Signal run was not established in this read-only review.

## Solution Assessment

No, not as a Signal-only transcript rewrite. The maintainable solution is for Signal to normalize native edit metadata into a generic supersession contract, with session code owning context mutation and wake semantics.
