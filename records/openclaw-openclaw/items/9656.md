## Label Justifications

- `P2`: Signal edits can duplicate processing and stale conversation context, but the impact is limited to one channel and does not make core runtime unusable.
- `impact:message-loss`: Corrected Signal content loses its semantic association with the outdated original and can lead to processing or responses based on the wrong version.
- `impact:session-state`: Treating an edit as an independent ordinary message can duplicate or drift the session transcript and context.

## Summary

Keep open. Current main recognizes Signal edit envelopes and now types their target timestamp, but still processes the edited body as an ordinary inbound message, assigns identity from the edit envelope’s timestamp, and lacks explicit correction, transcript supersession, deduplication, or edit-specific reply policy. The latest release has the same central gap, and the only candidate PR closed unmerged.

## What This Changes

Handle Signal `editMessage` envelopes as edits so corrected content retains its original-message relationship and does not create duplicate context or unintended responses.

## Best Possible Solution

Normalize Signal edits inside the Signal plugin with explicit target identity and structured edit metadata, then implement one maintainer-approved context and dispatch semantic with focused coverage for edit envelopes, message identity, history, and mention gating.
