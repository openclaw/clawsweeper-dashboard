## Summary

Keep open: current main still routes Apple Watch behavior through WatchConnectivity and the paired iPhone, while this asks for a new opt-in standalone watch Gateway node with its own credential and bounded capability surface. The protected `maintainer` label and credential/network exposure changes make this a maintainer product/security decision, not cleanup-close material.

## What This Changes

Request an opt-in Apple Watch mode that pairs directly with the Gateway over Wi-Fi or cellular while preserving the existing iPhone relay as default and fallback.

## Best Possible Solution

If maintainers approve the direction, implement a separate opt-in watch node with its own device-scoped credential, secure reachable Gateway URL, foreground-only session, bounded commands, and unchanged iPhone relay fallback.
