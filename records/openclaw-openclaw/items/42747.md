## Label Justifications

- `P2`: This is meaningful Slack security and operations work with limited channel scope, but it is not an active core outage or blocked first-run path.
- `impact:security`: The request would store and rotate Slack refresh tokens and client secrets, where bad persistence, logging, or recovery can compromise workspace access.
- `impact:auth-provider`: The issue changes Slack credential resolution, refresh, and active runtime auth behavior for bot/app access.

## Summary

Keep open: current main and v2026.6.11 still expose Slack as a static bot/app/user/signing-secret credential surface, while this asks OpenClaw to own a new rotating Slack OAuth lifecycle that needs maintainer product and security approval.

## What This Changes

Native Slack token rotation support would add OpenClaw-owned Slack OAuth refresh-token storage, refresh scheduling, runtime credential adoption, and setup/status UX.

## Best Possible Solution

Design this as a Slack-plugin-owned credential lifecycle with secure persistent storage, transactional refresh-token replacement, runtime token adoption, status/doctor recovery, docs, and live Slack rotation proof while preserving existing static-token setups.

## Maintainer Decision

Question: Should the bundled Slack plugin own native Slack token rotation now, and where should client secrets, refresh tokens, expiry metadata, and refreshed bot tokens be stored and adopted at runtime?

Rationale: This changes credential persistence and active Slack authorization behavior, so automation should not choose the permanent storage, refresh, and recovery model for rotating OAuth material.

Likely owner: steipete

Owner reason: steipete has the strongest sampled Slack setup/runtime and credential-surface history for this product/security choice.

Owner confidence: medium

Options:

- **Design Slack-plugin-owned rotation (recommended):** Implement a dedicated Slack plugin credential lifecycle with secure storage, transactional refresh, runtime adoption, status/doctor UX, docs, and live Slack proof.
- **Defer to external rotation:** Keep static Slack token support and document external/manual rotation until maintainers are ready to own rotating Slack secrets.
- **Wait for generic rotating credentials:** Defer Slack-specific work until OpenClaw has a shared plugin credential refresh and storage API that Slack can consume.
