## Summary

Keep open: current main and v2026.6.11 still treat Slack credentials as static bot/app/user/signing-secret inputs, while this asks OpenClaw to own a new rotating Slack OAuth credential lifecycle that needs security and product approval before implementation.

## What This Changes

Request native Slack token rotation support covering config/storage, oauth.v2.exchange bootstrap, oauth.v2.access refresh, runtime token adoption, retries, status, and docs.

## Best Possible Solution

Design this as a Slack-plugin-owned credential lifecycle with secure persistent storage, transactional refresh-token replacement, runtime token adoption, status/doctor recovery, docs, and live Slack rotation proof while preserving existing static-token setups.
