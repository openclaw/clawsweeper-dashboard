## Summary

Keep open: current main and the latest release still support Slack static bot/app/user/signing-secret credentials, while this asks for a new Slack OAuth token-rotation lifecycle that needs maintainer product and security direction before implementation.

## What This Changes

Add native Slack token rotation so OpenClaw can store refresh material, call Slack oauth.v2.access, refresh active bot tokens, and expose setup/status recovery without an external daemon.

## Best Possible Solution

Design this as a Slack-plugin-owned credential lifecycle with maintainer-approved secure storage, transactional refresh-token replacement, runtime token adoption, redacted status/doctor recovery, docs, and live Slack rotation proof while preserving static-token setups.
