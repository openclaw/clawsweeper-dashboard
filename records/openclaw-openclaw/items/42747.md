## Summary

Keep open: current main and v2026.6.11 still expose Slack as a static bot/app/user/signing-secret credential surface, while this asks OpenClaw to own a new rotating Slack OAuth lifecycle that needs maintainer product and security approval.

## What This Changes

Request native Slack OAuth token rotation for the Slack plugin, including refresh-token storage, oauth.v2.access refresh, runtime token adoption, and setup/status UX.

## Best Possible Solution

Design this as a Slack-plugin-owned credential lifecycle with secure persistent storage, transactional refresh-token replacement, runtime token adoption, status/doctor recovery, docs, and live Slack rotation proof while preserving existing static-token setups.

Options:

- **Wait for generic rotating credentials:** Defer Slack-specific work until OpenClaw has a shared plugin credential refresh and storage API that Slack can consume.
