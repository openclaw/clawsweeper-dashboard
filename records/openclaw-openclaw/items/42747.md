## Summary

Keep open: current main and the latest release still model Slack credentials as static SecretInput/SecretRef values, while this asks OpenClaw to own a new rotating OAuth credential lifecycle that needs maintainer product and security direction before implementation.

## What This Changes

The issue requests native Slack token rotation with refresh-token storage, proactive oauth.v2.access refreshes, runtime adoption of refreshed bot tokens, and setup/status UX.

## Best Possible Solution

Use this issue as the maintainer design tracker, then implement a Slack-plugin-owned rotation lifecycle only after deciding secure storage, transactional refresh-token replacement, status/doctor recovery, backwards compatibility, and live Slack proof requirements.
