- `impact:auth-provider`: The requested behavior changes Slack credential lifecycle, OAuth refresh handling, and provider/channel authentication state.

## Summary

Keep open: current main and the latest release still model Slack credentials as static bot/app/user/signing-secret values, while this asks OpenClaw to own a new Slack OAuth token-rotation lifecycle that needs product and security approval before implementation.

## What This Changes

The issue requests native Slack OAuth token rotation support, including refresh-token storage, oauth.v2.access refresh behavior, setup/status CLI support, runtime credential adoption, and documentation.

## Best Possible Solution

Approve a Slack-plugin design that stores rotation secrets through the intended OpenClaw secret/state contract, refreshes tokens before expiry for Socket Mode, HTTP mode, and relay paths, exposes status/doctor recovery, and preserves existing static-token deployments.
