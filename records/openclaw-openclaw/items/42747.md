## Summary

Keep open: current main and v2026.6.11 still model Slack credentials as static SecretInput values, while native Slack token rotation would add new OAuth secret storage, refresh scheduling, transactional persistence, and live runtime adoption that needs maintainer product and security direction.

## What This Changes

Request native Slack OAuth token rotation support using oauth.v2.access refresh-token flow, including new config/state, refresh scheduling, setup command, and runtime token adoption.

## Best Possible Solution

Design a Slack-plugin-owned rotation lifecycle with secure persisted state, transactional refresh/update, status and doctor recovery, docs, and Socket/HTTP adoption proof while preserving static-token setups.

Rationale: This changes credential persistence and live Slack auth behavior, so automation cannot safely choose the secret storage, redaction, migration, recovery, and operator UX model without maintainer security intent.

Options:

- **Design plugin-owned rotation (recommended):** Build Slack rotation behind the Slack plugin boundary with secure storage, transactional refresh, status/doctor recovery, docs, and live Socket Mode plus HTTP Mode proof.
- **Create a generic refresh seam first:** Define a reusable credential-refresh contract before implementing Slack as one consumer if maintainers want rotation to generalize beyond Slack.
- **Defer to external rotation:** Keep OpenClaw on static Slack token inputs and document external rotation or manual operational workarounds until maintainers want to own rotating Slack secrets.

## Risks / Open Questions

- Choosing managed openclaw.json fields before the storage decision could create the wrong source of truth for Slack client secrets, refresh tokens, expiry metadata, and replacement bot tokens.
- Refresh failure, concurrent refresh, or partial persistence could strand the gateway on an expired token or lose the usable refresh-token state without transactional or single-flight behavior.
- The design must account for existing static-token, env fallback, SecretRef, Socket Mode, HTTP mode, relay mode, and channel restart behavior, including the related manual-token reload issue at https://github.com/openclaw/openclaw/issues/80346.
- A Slack-only implementation may duplicate generic OAuth/credential refresh concepts unless maintainers explicitly choose plugin-local ownership for this channel-specific lifecycle.
