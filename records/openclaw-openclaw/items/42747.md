## Summary

Keep open: current main and v2026.6.11 still expose Slack as static credential inputs, while native token rotation would add a new Slack OAuth refresh lifecycle that needs maintainer product and security design.

## What This Changes

Add native Slack token rotation using Slack oauth.v2.access refresh flow, with stored refresh state and runtime adoption of refreshed bot tokens.

## Best Possible Solution

Design this as a Slack-plugin-owned credential rotation lifecycle with secure storage, transactional refresh/update, status/doctor recovery, docs, and Socket/HTTP/relay adoption proof while preserving static-token setups.

- **Create a generic refresh seam first:** Define a reusable plugin credential-refresh contract before implementing Slack as one consumer of that contract.
