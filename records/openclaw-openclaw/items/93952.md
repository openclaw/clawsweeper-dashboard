Full review comments:

- **[P1] Prevent timed-out OAuth work from writing after lock release:** `src/agents/auth-profiles/oauth-manager.ts:491-495`
  - body: The new in-lock timeout rejects the callback passed to `withFileLock`, so the lock is released, but `withRefreshCallTimeout` does not cancel the async body it started. If that body later resumes, it can still persist or mirror refreshed credentials outside the global OAuth lock while another process or queued refresh now owns the same key.
  - confidence: 0.94
- **[P1] Block timed-out refresh operations from mutating auth state:** `src/agents/embedded-agent-runner/run/auth-controller.ts:228-230`
  - body: `withAuthDeadline(refreshOperation, ...)` clears the single-flight handle on timeout, but the underlying refresh operation can still finish later and run the state writes guarded only by generation/profile/source checks. A retry using the same generation/profile/source can therefore be overwritten by the abandoned operation after the timeout path has let later model turns proceed.
  - confidence: 0.91
- **[P2] Give the outer auth deadline real contention headroom:** `src/agents/runtime-auth-refresh.ts:26`
  - body: The hard deadline is 300s, while the OAuth path can legitimately spend up to 150s waiting behind the old owner's in-lock work and then another 150s in its own in-lock section, before scheduling jitter or retries. That means normal serialized refresh contention can hit the outer hard deadline while each inner budget is still behaving as configured.
  - confidence: 0.84
