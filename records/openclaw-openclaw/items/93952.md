## Summary

Needs changes before merge: the new in-lock deadline releases OAuth refresh mutual exclusion while the timed-out refresh operation can continue in the background, recreating the concurrent refresh-token race that the file lock is intended to prevent.

## What This Changes

This PR adds hard deadlines around runtime and OAuth refresh work so hung provider authentication cannot leave an agent lane permanently waiting on an in-flight refresh.

## System Context

Embedded agent runs obtain runtime credentials through the auth controller, which may invoke OAuth refresh work protected by an in-process queue and a cross-agent file lock. The resulting credential is stored for the next model turn, so a stalled or racing refresh can stop agent replies or damage provider-auth continuity.

  F --> G[Next agent reply]

## Best Possible Solution

Keep the deadlock backstop, but retain refresh exclusion until the potentially token-rotating operation is actually aborted or known settled, or introduce a provider-safe fencing and recovery protocol; add a regression that proves an abandoned remote refresh cannot invalidate a successor.
