## Summary

Keep this PR open for maintainer review. The patch has focused regression coverage and credible terminal proof that a hung runtime-auth operation no longer leaves the embedded agent lane permanently blocked, but its timeout deliberately abandons an uncancellable provider/keychain operation while a retry may proceed; the repository needs an explicit decision that this provider-side concurrency tradeoff is acceptable.

## What This Changes

This PR puts hard deadlines around embedded runtime-auth refresh, cold-start credential preparation, and OAuth lock-held work, with local stale-write guards so hung authentication operations cannot indefinitely block agent runs.

## System Context

Before an embedded agent calls a model, the runtime auth controller resolves or refreshes provider credentials and stores the resulting runtime auth state. The OAuth manager serializes shared refreshes and persists refreshed credentials, so a stalled hook or lock-held operation can otherwise block later agent turns that depend on the same auth state.

## Best Possible Solution

Adopt one explicit auth-operation contract: either document and accept bounded abandoned-operation overlap for supported providers, or preserve exclusive ownership until the underlying operation settles; then rebase and prove the chosen behavior on the merge result without weakening the SQLite-only auth-store boundary.

- **Accept the local-only guard boundary:** Land the current design while explicitly accepting that it guarantees local state safety and lane recovery, not cancellation or provider-side serialization.
