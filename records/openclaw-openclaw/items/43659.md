## Summary

Keep open: the reported Copilot profile-rotation bug is valid, but this PR is stale and patches obsolete token-helper surfaces instead of the current `src/plugin-sdk/provider-auth.ts` resolver, so it is not merge-ready without a rebase and real behavior proof.

## What This Changes

The PR adds a GitHub-token fingerprint to Copilot token-cache entries and updates Copilot token tests so a profile switch bypasses a cache entry written by another GitHub token.

## Best Possible Solution

Rebase or replace this PR with a current-main patch in `src/plugin-sdk/provider-auth.ts`, add provider-auth regression coverage for same-profile hits, profile switches, and legacy cache misses, and attach redacted real behavior proof.

## Reproduction Assessment

Yes at source level: current main reads a shared Copilot token cache and returns it before using the newly selected `githubToken`, so a rotated profile can receive the previous profile's Copilot API token. I did not run a live two-account Copilot flow in this read-only review.

## Solution Assessment

No. The credential-fingerprint idea is a plausible narrow fix, but this branch applies it to obsolete helper paths instead of the current `src/plugin-sdk/provider-auth.ts` implementation owner.
