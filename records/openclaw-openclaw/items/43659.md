## Summary

Keep open: the linked Copilot profile-rotation bug is still real, but this branch is conflicting and still ports the fingerprint check to stale helper paths while current main routes Copilot token exchange through `src/plugin-sdk/provider-auth.ts`.

## What This Changes

The PR adds a GitHub-token fingerprint to Copilot token cache entries in extension and legacy helpers, then updates extension token tests so profile switches bypass a cached token from another profile.

## Best Possible Solution

Port the credential-aware cache validation and cache write to `src/plugin-sdk/provider-auth.ts`, keep `extensions/github-copilot/token.ts` as the SDK re-export, drop the obsolete `src/agents` change, and add provider-auth regression coverage plus real behavior proof.

## Reproduction Assessment

Yes at source level: current main reads a shared usable Copilot token cache entry before using the newly selected `githubToken`, so a rotated profile can receive the previous profile's Copilot API token. I did not run a live two-account Copilot flow in this read-only review.

## Solution Assessment

No. The fingerprint approach is plausible, but this patch is no longer the best implementation because current main's active owner is `src/plugin-sdk/provider-auth.ts`, not the extension-local or removed legacy helper paths.
