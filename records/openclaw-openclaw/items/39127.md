## Summary

Keep open: current main and v2026.6.11 still lack the requested gateway-owned `sessions.activity.get/list` RPCs, explicit attention state, child rollup, stale-run accounting, and `sessions.activity.statechange` event. The related open PRs are implementation candidates or partial overlaps, not merged replacements, so this remains the canonical product/API design item.

## What This Changes

Request to add a gateway-level per-session activity API and WebSocket state-change event model for busy/idle, explicit waiting states, stale runs, and child-session rollups.

## Best Possible Solution

Land a maintainer-approved Gateway v1 contract for `sessions.activity.get/list` and `sessions.activity.statechange`, with explicit attention states, monotonic versions, bounded child rollups, stale-run semantics, docs, and focused tests; keep UI/status consumers as follow-ups or adapters to that contract.
