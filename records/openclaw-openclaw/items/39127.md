Keep open: current main and v2026.6.11 still only expose coarse `sessions.list`/`sessions.changed` plus `hasActiveRun` signals. The requested dedicated `sessions.activity.*` RPCs, explicit attention states, stale-run accounting, child rollup, and activity `statechange` event remain missing, while related PRs are open/unmerged or narrower slices.

## What This Changes

The issue requests a gateway-owned per-session activity API with busy/idle runtime state, explicit attention states, children rollups, and WebSocket state-change events.

## Best Possible Solution

Settle one versioned gateway-owned activity and attention contract that clients, watchdogs, and UI status surfaces can consume without polling or message-text inference.
