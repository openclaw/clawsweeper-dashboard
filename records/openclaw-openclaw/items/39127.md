## Summary

Keep open: current main and the latest release still lack the requested gateway-owned `sessions.activity.get/list` RPCs, explicit attention state, children rollup, stale-run accounting, and `sessions.activity.statechange` event. Existing `sessions.list` live flags and related open PRs are partial overlaps, not merged replacements for this public Gateway/session activity contract.

## What This Changes

Request a gateway-owned per-session activity API and WebSocket statechange stream that exposes busy/idle, explicit waiting states, stale-run handling, and bounded child-session rollups.

## Best Possible Solution

Define one additive Gateway-owned activity contract with documented RPC schemas, WS resync/versioning, explicit attention transitions, bounded child rollups, and focused tests for fresh run, terminal, stale, reconnect, and cross-agent child cases.
