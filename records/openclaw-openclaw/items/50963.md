## Summary

Keep open: current main and v2026.6.11 still create native `sessions_spawn` child sessions with fresh UUID-backed keys, while the only resume support remains ACP-only and Teams lacks a thread-binding/session-binding implementation for native reuse. The source gap is clear, but the permanent fix changes session-state/API semantics and needs maintainer product direction.

## What This Changes

Request native subagent session reuse so repeated expert-agent spawns, especially from Teams, can continue prior child-session context instead of always starting a fresh session.

## Best Possible Solution

Define an explicit native subagent reuse contract with scoped isolation, liveness/TTL, locking, cleanup, docs, and regression tests before choosing core pooling, a new tool/API parameter, or a Teams binding implementation.
