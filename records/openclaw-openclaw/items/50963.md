## Summary

Keep open: current main and the latest release still create native `sessions_spawn` child sessions with fresh UUID-backed keys, while ACP resume and thread-bound channel binding do not provide a Teams-compatible native reuse contract. The issue remains necessary, but the fix needs maintainer product/API direction before implementation.

## What This Changes

The issue requests a way for expert subagents to reuse native `sessions_spawn(mode="run")` sessions instead of starting a fresh child session on every spawn.

## Best Possible Solution

Define an explicit native subagent reuse contract with scoped isolation, liveness/TTL, locking, cleanup, docs, and tests before choosing core pooling, channel session binding, or a new tool/API parameter.

No immediate implementation path is proven best yet. Adding a raw session key or Teams-only hook is plausible, but the safer solution is a maintainer-approved contract for isolation, TTL, locking, cleanup, and channel binding first.
