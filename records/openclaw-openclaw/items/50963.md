## Summary

Keep open: current main and the latest release still use fresh UUID-backed native subagent session keys, keep `resumeSessionId` ACP-only, and do not expose a Teams/native reuse contract. The remaining work is a real session-state API/product decision, not conservative cleanup.

## What This Changes

The issue requests subagent session reuse for expert agents so repeated Teams/native `sessions_spawn(mode="run")` calls can preserve context instead of always starting a fresh child session.

## Best Possible Solution

Define an explicit native subagent reuse contract with scoped isolation, liveness/TTL, locking, cleanup, docs, and tests; if the immediate goal is Teams thread persistence, add a Teams session-binding adapter through the current core binding seam instead of the deprecated hook.
