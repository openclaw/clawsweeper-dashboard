## Summary

Keep open: current main still has the native `sessions_spawn` session-reuse gap, and the remaining work is a maintainer product/API decision around native reuse semantics rather than a conservative cleanup close.

## What This Changes

Requested feature: allow expert/native subagents, especially from Teams workflows, to reuse an existing session instead of creating a fresh UUID-backed child session for every spawn.

## Best Possible Solution

Define an explicit native subagent reuse contract, or a Teams-compatible session-binding adapter path, with isolation, liveness/TTL, locking, cleanup, docs, and focused tests before implementation.

## Reproduction Assessment

Yes for a source-level reproduction: current main's native `sessions_spawn` path still chooses a fresh UUID child session key and has no native reuse or resume field. I did not run a live Teams/provider cost scenario in this read-only review.

## Solution Assessment

No as an immediate implementation direction: adding a raw session key parameter or a Teams-only hook is not the best permanent fix without maintainer decisions on isolation, TTL, locking, cleanup, and channel binding. The best path is design first, then a focused implementation against the chosen core/session-binding seam.
