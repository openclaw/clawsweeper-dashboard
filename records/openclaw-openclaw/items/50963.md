## Summary

Keep open: current main and the latest release still create native subagent child sessions with fresh UUID-backed keys, keep resume/reuse ACP-only, and do not give Teams a native reuse path. The remaining work is a product/API decision, not conservative cleanup.

## What This Changes

Request native `sessions_spawn` support for reusing or persisting expert subagent sessions, especially for Teams setups that cannot rely on thread-bound session mode.

## Best Possible Solution

Define a first-class native subagent reuse contract with scoped isolation, liveness/TTL, locking, cleanup, follow-up targeting, docs, and tests before choosing core pooling, explicit reuse keys, or channel-specific binding work.

## Solution Assessment

No immediate implementation path is proven best yet. Raw session keys, automatic pooling, and a Teams-only hook are all plausible, but the maintainable solution needs an explicit isolation, TTL, locking, cleanup, and routing contract first.
