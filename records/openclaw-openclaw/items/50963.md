## Summary

Keep open: current main and v2026.6.11 still lack a native `sessions_spawn` reuse contract, and Microsoft Teams still does not expose the core session-binding adapter needed for thread-bound spawned subagent sessions. The source gap is clear, but the permanent API and session-state semantics need maintainer product direction before implementation.

## What This Changes

Request native expert subagents to reuse prior session context across repeated `sessions_spawn` calls, especially for Microsoft Teams where thread-bound spawned sessions are not currently available.

## Best Possible Solution

Define an explicit native subagent reuse contract with scoped isolation, liveness/TTL, locking, cleanup, docs, and tests before choosing core pooling, Teams conversation binding, or a new tool/API parameter.

## Reproduction Assessment

Yes, source-level: current main still creates native `sessions_spawn` child sessions with a fresh UUID key, and native `mode="session"` still requires `thread=true`. I did not run a live Teams/provider scenario because the missing contract is directly visible in source and docs.

## Solution Assessment

Unclear. A raw session key, automatic pool, or Teams-only binding is plausible, but the best solution requires maintainer-approved isolation, TTL, locking, cleanup, and channel-binding semantics first.
