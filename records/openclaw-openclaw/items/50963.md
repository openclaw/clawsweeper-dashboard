## Summary

Keep open: current main and the latest release still create native `sessions_spawn` subagent runs with fresh UUID-backed child session keys, and native reuse/resume remains a product/API decision rather than cleanup-close material.

## What This Changes

Request native `sessions_spawn` subagents, especially expert agents on Teams, to reuse existing sessions instead of creating a fresh child session for every run spawn.

## Best Possible Solution

Define an explicit native subagent reuse contract, or a Teams-compatible session-binding adapter path, with isolation, liveness/TTL, locking, cleanup, docs, and tests before implementation.

## Reproduction Assessment

Yes. Current main has a source-level reproduction path: native `sessions_spawn` reaches `spawnSubagentDirect`, which still chooses a fresh UUID child session key and has no native reuse/resume field.

## Solution Assessment

No immediate implementation shape is clearly best yet. Adding a raw session key parameter or a Teams-only hook is plausible but needs maintainer decisions on isolation, TTL, locking, cleanup, and channel binding before code should land.
