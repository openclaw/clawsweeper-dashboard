## Summary

Keep open: current main still creates native subagent runs with fresh UUID-backed child session keys, keeps resume/reuse ACP-only, and has no Teams-compatible native reuse contract. The remaining work is a real product/API decision rather than a cleanup close.

## What This Changes

Request native expert subagents spawned by `sessions_spawn(mode="run")` to reuse an existing session instead of always starting a fresh child session.

## Best Possible Solution

Define an explicit native subagent reuse contract with scoped isolation, liveness/TTL, locking, cleanup, docs, and tests before choosing core reuse, channel binding, or a new tool/API surface.

## Reproduction Assessment

Yes for a source-level reproduction: current main still chooses a fresh UUID child session key for native `sessions_spawn` and drops ACP-only resume fields before native dispatch. I did not run a live Teams/provider cost scenario in this read-only review.

## Solution Assessment

No immediate implementation path is proven best yet: adding a raw session key or Teams-only hook is plausible but not the safest permanent answer without decisions on isolation, TTL, locking, cleanup, and channel binding. The best path is design first, then a focused implementation against the chosen seam.
