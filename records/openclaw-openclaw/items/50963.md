## Summary

Keep open: current main still has the reported native `sessions_spawn` gap. Native subagent spawns choose a fresh UUID-backed child session key, ACP resume remains explicitly ACP-only, and Teams exposes thread capability without a Teams-specific subagent binding hook, so the remaining work is a product/API decision rather than a cleanup close.

## What This Changes

The issue requests a native subagent session reuse path so repeated expert-agent `sessions_spawn` calls can preserve context instead of starting a fresh child session each time.

## Best Possible Solution

Define a native subagent reuse contract first, then implement the chosen core/session-binding path with scoped isolation, liveness/TTL, locking, cleanup, docs, and focused tests.

## Reproduction Assessment

Yes for a source-level reproduction: current main still chooses a fresh UUID child session key for native subagents and has no native reuse or resume field. I did not run a live Teams/provider cost scenario in this read-only review.

## Solution Assessment

No immediate implementation is clearly best yet: a raw session-key parameter or Teams-only hook would be plausible but could be the wrong boundary. The best path is a maintainer-approved native reuse/session-binding contract before code changes.
