## Summary

Keep open: current main and the latest release still create native `sessions_spawn` child sessions with fresh UUID-backed keys, while ACP resume and channel thread bindings do not provide the requested Teams-compatible native reuse contract.

## What This Changes

Request native `sessions_spawn(mode="run")` subagents, especially from Teams, to reuse prior child session context instead of always spawning a fresh session.

## Best Possible Solution

Define an explicit native subagent reuse contract with scoped isolation, liveness/TTL, locking, cleanup, docs, and tests before choosing core pooling, channel session binding, or a new tool/API parameter.

Options:

- **Design core opt-in native reuse (recommended):** Add an explicit, scoped native reuse contract only after deciding TTL/liveness, locking, cleanup, and history-isolation rules.
- **Add Teams session binding first:** Implement Teams through the channel session-binding adapter seam and leave ordinary native `mode="run"` isolated.
- **Keep native runs isolated:** Document ACP resume and thread-bound sessions as the supported reuse paths and close native run reuse as out of scope.

## Reproduction Assessment

Yes, for a source-level reproduction: current main still chooses a fresh UUID child session key for native `sessions_spawn` and drops ACP-only resume fields before native dispatch. I did not run a live Teams/provider scenario in this read-only review.

## Solution Assessment

No immediate implementation path is proven best yet. Adding a raw session key or Teams-only hook is plausible, but the safer solution is a maintainer-approved contract for isolation, TTL, locking, cleanup, and channel binding first.
