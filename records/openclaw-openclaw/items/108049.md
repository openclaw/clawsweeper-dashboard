## Summary

Keep this issue open: current main still uses the process TEMP value directly in the affected Windows installer paths, and the explicitly linked fix pull request remains open rather than merged. The report is narrow, source-reproducible, and describes a first-install blocker for affected Windows users.

## What This Changes

Make the Windows installer select and reuse an existing long-form temporary directory when TEMP or TMP contains an unresolved 8.3 short-path alias.

## Best Possible Solution

Normalize and validate the installer temporary root once at Windows installer startup, propagate that selected directory to TEMP and TMP, and reuse it consistently for portable Node, portable Git, extraction, and child-command working directories, with focused Windows proof covering an unresolved short alias and normal long paths.

## Maintainer Decision

Required: false

## Reproduction Assessment

No live failing Windows machine was independently reproduced in this review, but yes at the source level: current main routes all three affected bootstrap surfaces through raw `$env:TEMP` with no normalization or fallback.

## Solution Assessment

Yes in direction: selecting one validated long-form temp root at installer startup is narrower and more maintainable than adding separate fallbacks around each download, extraction, and command invocation; the linked implementation still needs ordinary review and real Windows proof.
