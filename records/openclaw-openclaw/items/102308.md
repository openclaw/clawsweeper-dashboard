## What This Changes

The issue requests that iOS chat keep showing assistant activity after returning to a long-running session when the latest user turn is unanswered and session history still reports active work.

## Best Possible Solution

Review and land or reject the linked iOS chat PR; the final fix should preserve the completed-run guard while showing a bounded fallback activity state for unanswered latest user turns with session-level active work.
