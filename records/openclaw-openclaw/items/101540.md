## Summary

Keep open. Current main has close/error cleanup for normal WebSocket shutdown, but connected gateway sockets only send periodic pings and do not track missed pong responses or force termination for a half-open connection, so the central leak concern remains plausible from source inspection.

## What This Changes

The issue reports that gateway WebSocket connections may leak ping timers and client objects when a silent TCP drop never emits a WebSocket close event.

## Best Possible Solution

Add a single gateway-owned heartbeat liveness path that marks connected sockets alive on `pong`, terminates unresponsive half-open sockets on the existing ping cadence, and keeps `close()` as the central timer/client cleanup owner.
