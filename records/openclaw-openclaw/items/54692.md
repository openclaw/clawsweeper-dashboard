## Summary

Keep open: current main still lacks the source-specific diagnostic improvement, but this PR is not merge-ready because the env override path would still receive CLI-specific `--url` recovery text and the external PR has only test/build proof.

## What This Changes

The PR updates gateway CLI/TUI URL override authentication error text and tests to provide different follow-up hints for CLI `--url` and `OPENCLAW_GATEWAY_URL` failures.

## Best Possible Solution

Keep the source-specific hint in the shared guard, make the generic hint source-aware so env override failures do not mention `--url`, then require redacted terminal/live output showing the final error text.

## Reproduction Assessment

Yes. Source inspection shows `OPENCLAW_GATEWAY_URL` sets `urlOverrideSource: "env"`, then the shared call-site `errorHint` is included in the thrown auth message; I did not run the CLI/TUI flow because this review is read-only and the missing proof is contributor-side.

## Solution Assessment

No as written. `ensureExplicitGatewayAuth` is the right layer for source-specific diagnostic text, but the shared call-site hint should not become CLI-specific for the env override path.
