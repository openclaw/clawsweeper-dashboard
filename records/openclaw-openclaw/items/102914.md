## Summary

Keep open: current main still registers queued chat turns without an abort-signal cleanup path, so an externally aborted controller can leave its queued-turn entry retained until a later explicit completion or queued-abort path runs.

## What This Changes

The issue requests abort-signal cleanup for queued Gateway chat turns registered by `registerQueuedChatTurn`.

## Best Possible Solution

Add a same-controller abort cleanup for queued chat turns, with regression coverage proving external signal abort removes the queued entry without deleting a replacement entry or weakening queued-turn authorization.

Yes, a narrow helper-level fix is the best path: keep the existing queued-turn owner boundary and add cleanup at registration/entry removal rather than changing Gateway queue semantics or adding a broader fallback.
