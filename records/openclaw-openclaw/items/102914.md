## Summary

Keep open: current main still stores queued chat turns without post-registration abort cleanup, and https://github.com/openclaw/openclaw/pull/102935 is an open linked candidate fix rather than a reason to close this issue before merge.

## What This Changes

The issue reports that `registerQueuedChatTurn` can retain aborted queued chat-turn controllers because it does not remove map entries when the controller's `AbortSignal` aborts after registration.

## Best Possible Solution

Keep this issue open until https://github.com/openclaw/openclaw/pull/102935 merges; the end state should be helper-level abort cleanup with focused regression coverage, or an equivalent replacement if that PR is closed.

## Solution Assessment

Yes. Adding cleanup at `registerQueuedChatTurn` is the narrowest owner-boundary fix because that helper owns admission into `chatQueuedTurns`, while existing lifecycle completion paths already handle drain-side cleanup.
