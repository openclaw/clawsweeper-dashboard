## Label Justifications

- `P1`: Substantive assistant output is silently omitted from durable channel replies during real multi-tool CLI turns.
- `impact:message-loss`: Completed mid-turn assistant text reaches transient previews but is absent from the durable message delivered to the operator.

## Summary

Keep open: current CLI handling preserves inter-tool commentary for transient progress, but the documented durable block-reply path still does not receive those completed CLI text segments, so operators can lose substantive mid-turn output when the final CLI result is only a short wrap-up. ([github.com](https://github.com/openclaw/openclaw/issues/110067))

## What This Changes

Make completed mid-turn text from CLI-backed runtimes reach durable block replies instead of only transient previews, without duplicating the final result.

## Best Possible Solution

Extend the generic CLI lifecycle with a completed-text/block callback that feeds the existing block-reply pipeline when enabled, preserve progress commentary as a separate transient projection, and deduplicate the terminal CLI result against blocks already delivered.

Yes at high confidence from source and field evidence: a Claude CLI turn with text before a tool call and a short final text block exercises the parser’s terminal-result selection while the earlier text remains progress-only. A fresh live run was not performed in this read-only review.

## Solution Assessment

Yes. Wiring classified completed CLI segments into the existing generic block-reply callback is narrower and more maintainable than a Mattermost- or Claude-specific workaround or a new configuration surface.
