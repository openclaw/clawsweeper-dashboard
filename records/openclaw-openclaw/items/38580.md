## Summary

Keep open: current main and the latest release still do not expose Telegram pinned-message reads, and the remaining work needs a maintainer product/security decision because it would expose persistent Telegram room context to agents.

## What This Changes

Request to let OpenClaw read Telegram pinned messages through the bot API for persistent chat context.

## Best Possible Solution

Add a Telegram-plugin-owned on-demand pinned-message read action behind an explicit gate, document getChat's one-current-pin semantics, and defer automatic session-start injection until maintainers approve the context policy.

Unclear until maintainers choose the product/security contract. The Telegram plugin is the right implementation boundary, but the default gate and whether pinned content enters prompt context automatically are maintainer decisions.
