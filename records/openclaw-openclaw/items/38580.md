## Summary

Keep open: current main and v2026.6.11 still do not expose Telegram pinned-message reads through discovery, runtime dispatch, config gates, docs, or tests. The nearest open issues cover broader Telegram history reads and pin/unpin mutations, but this remains a distinct security-sensitive pinned-context feature needing maintainer direction.

## What This Changes

The issue requests an on-demand or startup-time Telegram pinned-message read so agents can use pinned chat content as persistent context.

## Best Possible Solution

Approve a Telegram-plugin-owned on-demand pinned-message read first, backed by Bot API getChat, explicit action/config gating, chat/topic authorization, docs, focused tests, and live Telegram proof; defer automatic startup injection unless maintainers explicitly opt in.

## Reproduction Assessment

Yes. Source inspection is enough: shared read/list-pins action names and Telegram getChat support exist, but the Telegram plugin does not advertise, map, gate, dispatch, test, or document pinned-message reads.

## Solution Assessment

Unclear until maintainers choose the product contract. The likely right layer is a Telegram-plugin getChat action, but on-demand versus automatic context, default gating, and security boundaries need approval first.
