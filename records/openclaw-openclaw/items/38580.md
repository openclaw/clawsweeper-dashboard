## Summary

Keep open: current main and v2026.6.11 still do not expose Telegram pinned-message reads, and the remaining work is a security/product decision because it would expose persistent Telegram room context to agents.

## What This Changes

The issue requests Telegram pinned-message reads so agents can use pinned chat context on demand or at session start.

## Best Possible Solution

Add a Telegram-plugin-owned on-demand pinned-message read action behind an explicit gate, document getChat's one-current-pin semantics, and defer automatic session-start injection until maintainers approve the context policy.
