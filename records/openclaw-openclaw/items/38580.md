## Summary

Keep open: current main and the latest release still do not expose Telegram pinned-message reads, and the closed implementation attempts were not merged. The remaining choice is a product/security boundary because pinned messages are persistent chat context that agents could import into session state.

## What This Changes

Request to let Telegram agents fetch the current pinned chat message via the Telegram Bot API, either on demand or at session start.

## Best Possible Solution

Add a narrow Telegram-plugin pinned-message read surface only after maintainers choose the data-access gate, default behavior, and whether pinned content may enter prompt context automatically.

- **Opt-in session context:** Allow pinned content to be imported at session start only behind an explicit per-chat or per-account opt-in with clear docs and tests.
- **Do not add now:** Leave this out of OpenClaw until a broader Telegram read-policy design covers pinned messages and message history together.
