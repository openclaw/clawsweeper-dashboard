## Summary

Keep open: current main and v2026.6.11 still do not expose Telegram pinned-message reads, and the two linked implementation attempts are closed unmerged. The gap is source-reproducible, but the durable-context and access-default choices need maintainer product/security direction before implementation.

## What This Changes

Request to let OpenClaw fetch the current pinned Telegram chat message on demand or at session start via the Telegram bot API.

## Best Possible Solution

Approve a narrow Telegram-plugin pinned-message read surface only after maintainers choose the default gate and context-injection policy; the first implementation should favor explicit on-demand fetch with docs, focused tests, and live Telegram proof, while automatic session-start injection remains separately opt-in.
