## Summary

Keep open: current main and v2026.6.11 still do not expose Telegram pinned-message reads. The source gap is clear, but the default gate, data-access boundary, and whether pinned content becomes session context need maintainer product/security direction first.

## What This Changes

The issue requests a Telegram capability for agents to fetch the current pinned chat message on demand or at session start.

## Best Possible Solution

Decide the Telegram data-access policy first, then implement a narrow Telegram-plugin pinned-message read action or command behind an explicit gate, with docs, focused tests, and live Telegram proof; automatic session-start injection should remain separately approved opt-in behavior.
