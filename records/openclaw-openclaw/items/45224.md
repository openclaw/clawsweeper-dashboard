## Summary

Keep open: current main and the latest release still route raw/managed browser profiles through Playwright CDP, only suppress a narrow dialog-race rejection, and still exit on unclassified unhandled rejections. The linked FSB browser-split experiment is useful comparison context, but it does not implement the Gateway crash-isolation behavior here.

## What This Changes

The issue asks OpenClaw Gateway to survive Playwright CDP assertion failures from the browser subsystem without killing unrelated sessions.

## Best Possible Solution

Add a browser-owned failure boundary for Playwright CDP session assertions, backed by live CDP reproduction and regression coverage, so browser/CDP degradation cannot terminate unrelated Gateway sessions.

## Reproduction Assessment

Yes for source-level plausibility, but not for a high-confidence live repro: current main still routes raw CDP through Playwright and still exits on unclassified unhandled rejections, but I did not reproduce the exact Chrome/CDP assertion in a running Gateway.

## Solution Assessment

Unclear as an implementation shape: the goal is right, but maintainers should choose between an exact browser-owned Playwright assertion boundary, CDP reconnect/quarantine behavior, and longer-term browser subprocess isolation before queuing a fix.
