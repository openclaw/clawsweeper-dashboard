## Summary

Keep open: current main and the latest release still use Playwright CDP connections plus a fatal fallback for unclassified unhandled rejections, while the browser-specific suppression only covers a dialog race and not the reported CRSession assertion class.

## What This Changes

The issue reports that a Playwright CDP assertion from browser session handling can escape as an unhandled rejection and terminate the Gateway process.

## Best Possible Solution

Keep the fatal default for unknown process-level rejections, but make the browser plugin own a proven CDP assertion recovery path such as targeted classification plus connection teardown/reconnect, or an explicit isolated browser worker boundary.
