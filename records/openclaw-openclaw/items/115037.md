## What This Changes

The issue asks OpenClaw to avoid treating Claude CLI’s synthetic resumed-session placeholder as an empty-response failure that silently reroutes a real inbound turn to a fallback model.

## System Context

Claude CLI live-session handling receives a resumed process’s output and decides whether a turn is complete, should continue waiting, or should fail into the model-fallback pipeline. That decision determines both the model that answers the user and whether the reusable session remains usable for later turns.

## Architecture Diagram

flowchart LR
  A[Inbound user message] --> B[Claude CLI resumed process]
  B --> C[Synthetic placeholder or live output]
  C --> D[Claude live-session lifecycle]
  D -->|later output arrives| E[Deliver requested-model response]
  D -->|no continuation by deadline| F[Empty-response failure]
  F --> G[Model fallback decision]

## Best Possible Solution

Retain the merged owner-local lifecycle behavior: detect only the exact Claude synthetic placeholder, wait briefly for later output from a newly resumed process, deliver that output on the requested model, and fall back only after the continuation deadline expires.
