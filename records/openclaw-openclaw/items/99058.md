## What This Changes

The PR changes OpenAI Codex image-generation response handling to reject oversized or unknown-size no-readable-body responses before buffering, and adds unit plus loopback proof coverage.

## Best Possible Solution

Use the existing strict content-length parser or an equivalent digit-only safe-integer guard before any no-readable-body read, and make the fail-closed no-length policy an explicit maintainer-accepted behavior before merge.

## Reproduction Assessment

Yes. The PR head parses `Content-Length` with `Number(header)`, so malformed values such as `1e3` or `1.5` can pass as finite non-negative lengths before the no-body fallback reaches `arrayBuffer()`.

## Solution Assessment

No. The pre-read guard is the right layer for this bug, but the best fix needs strict digit-only safe-integer parsing before trusting the header; reusing the existing media-core parser keeps the repair narrow.
