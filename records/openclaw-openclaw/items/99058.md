## Summary

Keep open for maintainer review: current main still full-buffers the no-readable-body Codex image fallback, while the latest PR head fixes the prior ClawSweeper blocker with early Content-Length rejection and proof that the fallback buffer read is not called before the guard.

## What This Changes

The branch changes OpenAI Codex image-generation response reading to pre-check no-readable-body Content-Length, fail closed when length is missing or invalid, and add unit plus loopback proof coverage.

## Best Possible Solution

Land the bounded no-body guard if maintainers accept the intentional fail-closed behavior for unknown-size Codex image responses, without adding a runtime shim for unsafe fallback reads.

## Reproduction Assessment

Yes at source/proof level: current main awaits response.text() before the size check on the no-body branch, and the PR tests simulate response.body === null with oversized and missing Content-Length. I did not rerun tests in this read-only review, but the source path and posted loopback output are coherent.

## Solution Assessment

Yes, this is the best narrow fix for the no-stream edge if maintainers accept fail-closed behavior: it rejects unsafe unknown-size bodies before any full-buffer fallback. Broadly changing readResponseWithLimit would affect many callers and still cannot safely bound a missing stream without a trusted size signal.
