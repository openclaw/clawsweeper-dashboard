## Summary

Keep open: the latest head still routes the no-readable-body Codex image response through a helper that calls `arrayBuffer()` before enforcing the byte cap, so the central availability hardening remains incomplete despite the added loopback proof.

## What This Changes

The PR changes OpenAI Codex OAuth image generation to use `readResponseWithLimit` for `response.body === null` responses and adds unit, loopback, and script proof coverage.

## Best Possible Solution

Make the no-readable-body path fail before any full-buffer fallback, or update the shared helper to reject unknown no-stream bodies before `arrayBuffer()`, then add proof that oversized input is rejected without reading beyond the cap.

## Reproduction Assessment

## Solution Assessment

No. Reusing the shared helper is a good shape for readable streams, but it is not the best fix for this branch because the helper's missing-body fallback preserves the full-buffer behavior being fixed.
