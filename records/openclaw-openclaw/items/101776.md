## Summary

The current head is technically sound and the prior dangling-symlink finding is addressed, but an oversized existing `BOOT.md` is now silently treated as empty, so a maintainer should explicitly choose that compatibility outcome before merge.

## What This Changes

Bounds gateway `BOOT.md` reads at 16 MiB through the shared regular-file helper, preserves readable and dangling symlink behavior, and adds oversized-file and symlink regression coverage.

## Best Possible Solution

Keep the 16 MiB bounded read and symlink handling, but make size overflow an operator-visible failed boot check unless maintainers explicitly approve silent skipping and its upgrade behavior.
