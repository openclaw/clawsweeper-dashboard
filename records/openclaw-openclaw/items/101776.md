## Summary

Keep open: the oversized BOOT.md read cap is useful and the contributor proof covers that path, but the patch still turns readable symlinked BOOT.md files from runnable startup input into failed startup tasks.

## What This Changes

The branch replaces loadBootFile's unbounded fs.readFile with a 16 MiB capped readRegularFile call and adds gateway boot tests for oversized, directory, and symlinked BOOT.md paths.

## Best Possible Solution

Bound BOOT.md reads without changing existing readable symlink behavior; directories and other non-size read errors should remain visible failures unless maintainers explicitly choose a stricter policy.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source: current main uses an unbounded fs.readFile path for BOOT.md, and the contributor showed the branch skipping a 16 MiB + 1 byte file. The remaining symlink regression is also source-reproducible because readRegularFile rejects symlinks while current main uses fs.readFile.

## Solution Assessment

No. Bounding the BOOT.md read is the right fix direction, but using readRegularFile directly is too strict unless the implementation preserves current readable symlink behavior.
