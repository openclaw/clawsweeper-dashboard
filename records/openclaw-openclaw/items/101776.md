## Summary

This PR still needs changes before merge because the prior compatibility finding remains on the current head: a dangling `BOOT.md` symlink now produces a failed boot result instead of following the established missing-file path. The size-bound approach and supplied runtime proof are otherwise strong, and the remaining repair is narrow and mechanical.

## What This Changes

The branch caps gateway `BOOT.md` reads at 16 MiB, resolves readable symlinks before reading, and adds oversized-file, non-regular-file, and readable-symlink coverage.

## Best Possible Solution

Keep the bounded regular-file read and readable-symlink support, but classify `ENOENT` from resolving or reading `BOOT.md` as missing and add explicit dangling-symlink coverage while retaining hard failures for directories and permission errors.

## Reproduction Assessment

Yes at source level: a dangling symlink makes `realpath` return `ENOENT`, `lstat` then confirms the link exists, and the new branch rethrows instead of returning missing. The provided A/B and runtime evidence also reproduce the intended oversized and readable-symlink paths.

## Solution Assessment

No, not yet. Reusing `readRegularFile` with a size cap is the right boundary, but the extra `lstat` distinction unnecessarily changes the shipped `ENOENT` contract; returning missing for `ENOENT` is narrower and more compatible.
