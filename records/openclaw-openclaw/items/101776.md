## Summary

The oversized-read hardening is useful and has convincing runtime proof, but the current head still changes established ENOENT handling: a dangling BOOT.md symlink—and a file disappearing between realpath and the bounded read—becomes a failed boot check instead of skipped as missing. This narrow compatibility defect should be fixed before merge.

## What This Changes

The PR caps BOOT.md reads at 16 MiB, resolves readable symlinks before the bounded read, and adds gateway tests for oversized, directory, and readable-symlink paths.

## Best Possible Solution

Keep the 16 MiB bounded read and readable-symlink support, but map ENOENT from both path resolution and readRegularFile back to skipped/missing; retain failures for directories, permissions, path-mismatch races, and other non-ENOENT errors, with focused regression tests.
