## Summary

The previous dangling-symlink blocker is fixed: the current head preserves readable and dangling symlink behavior while bounding `BOOT.md` reads. No concrete correctness or security defect remains, but maintainers should explicitly accept the compatibility choice that an existing file over 16 MiB is classified as empty and not executed.

## What This Changes

Bounds gateway `BOOT.md` reads at 16 MiB through the shared regular-file helper and adds coverage for oversized files, regular-file symlinks, dangling symlinks, and non-regular targets.

## Best Possible Solution

Land the shared bounded-read implementation after confirming that oversized `BOOT.md` files should be reported as skipped/empty; if operator visibility is preferred, return a size-specific failed outcome instead while retaining the same cap and symlink semantics.
