## Label Justifications

- `P1`: Large Control UI attachments can fail in `chat.send`, blocking a real user-facing attachment delivery workflow across released builds and current main.
- `impact:message-loss`: The reported RangeError rejects attachment sends instead of delivering the file content to the agent.
- `impact:session-state`: The issue also reports failed queued items persisting and reappearing after the stack-overflow failure.
- `maturity:stable`: The affected Gateway `chat.send` attachment path belongs to `gateway-runtime`, which is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main has a partial large-base64 hardening fix, but the gateway and Control UI still contain full-string data URL capture regexes and the composer persistence path still restores failed queue items without dropping the old stack-overflow failures. The open linked fix PR is still unmerged and currently conflicting, so this issue remains the canonical tracker.

## What This Changes

Large Control UI attachments should be parsed and validated without stack-prone data URL/base64 regexes, and stale queue entries from the old RangeError should be dropped.

## Best Possible Solution

Keep this canonical issue open until https://github.com/openclaw/openclaw/pull/92223 is refreshed and landed, or until maintainers split and land an equivalent stack-safe parser plus stale queue cleanup fix.
