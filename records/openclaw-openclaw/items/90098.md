## Summary

Keep open: current main has the narrower base64-validation hardening from https://github.com/openclaw/openclaw/pull/99213, but it still has full-string data URL captures in the Control UI and gateway paths, still materializes large data URLs in the browser, and still restores failed queued sends instead of dropping RangeError-only stale entries. The linked closing PR at https://github.com/openclaw/openclaw/pull/92223 remains open and conflicting, so the issue is still necessary as the canonical tracker.

## What This Changes

The issue requests stack-safe Control UI and gateway attachment data URL/base64 handling, plus cleanup for persisted queue entries failed by the old stack overflow.

## Best Possible Solution

Land or split the linked fix so gateway and Control UI data URL parsing uses index/slice logic, base64 validation stays iterative, and RangeError-only stale queue entries are dropped without raising attachment limits.
