## Summary

Keep this PR open: it targets the reported Control UI cache collision and has focused regression coverage, but its raw-tail extraction drops empty colon-delimited segments and needs real after-fix behavior proof before merge.

## What This Changes

This PR changes the Control UI transcript-cache key so case-distinct Matrix room identifiers map to separate in-memory history snapshots.

## System Context

The Control UI saves a short transcript snapshot per selected session to keep route switches responsive. The cache key normalizer sits between an incoming session key and cache lookup, so it determines which conversation is restored into the chat view.

## Architecture Diagram

flowchart LR

  B --> C[Cache-key normalization]
  C --> D[Transcript snapshot cache]
  D --> E[Restored chat messages]
  F[Matrix room identifier] --> C

## Best Possible Solution

Extract the raw session rest losslessly after the validated agent prefix, retain the existing alias rules, add a delimiter-preservation regression, and provide a redacted before/after Control UI route-switch proof.

No. The case-preserving normalizer is the right shared contract, but extracting the opaque tail with filter(Boolean) is not lossless; raw-prefix slicing is the narrower maintainable fix.
