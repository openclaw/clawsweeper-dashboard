## Summary

This PR should remain open but is not merge-ready: its global replacement changes intentional literal `\n` file content, the same P1 concern raised in the prior review cycle. The linked regression has a concrete report, but the fix needs a boundary that distinguishes malformed transport encoding from content the agent intentionally asks to write.

## What This Changes

The branch replaces every literal backslash-n sequence in agent write-tool content with a newline before prechecks and disk writes.

## System Context

OpenClaw’s agent write tool receives a model-provided path and content string, checks the requested workspace mutation, queues it with other file changes, and writes the resulting file. The proposed normalization changes the content contract before both prechecks and the final disk operation.

## Best Possible Solution

Normalize malformed encoding only at a parser or provider boundary that can still distinguish transport escaping from literal requested content; otherwise preserve the write tool’s content string exactly and pursue the upstream producer defect.
