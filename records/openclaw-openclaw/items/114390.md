## Summary

Keep this PR open, but it is not ready to merge: the proposed write-stage replacement converts every literal `\n` sequence into a physical newline, so it changes valid file content and does not satisfy its stated preservation guarantee. The earlier P1 concern remains on the same head commit; the PR also needs redacted real after-fix evidence once the actual regression boundary is repaired.

## What This Changes

This PR changes the agent write tool so literal backslash-n sequences in supplied file content are converted to newline characters before prechecks and disk writes.

## System Context

The agent write tool receives a model-supplied path and content, validates the pending file mutation, then writes the content to the workspace. The changed step sits immediately before the mutation queue, so it affects every write-tool caller and every file type rather than only a particular provider or parser path.
