## What This Changes

Expose normalized receipts, queued-delivery identity and attempt count, and originating run correlation through the message_sent plugin hook while preserving messageId.

## Best Possible Solution

Add receipt and runId as optional additive fields, expose deliveryId and attemptNumber for queue-backed sends first, preserve messageId exactly, and document unavailable-value semantics with focused direct-send, multi-part, retry, and restart coverage; introduce universal dispatch identity only after explicit API approval.

- The permanent meaning of deliveryId is unsettled: exposing only durable-queue ids leaves direct sends uncorrelated, while minting ids for every dispatch creates a broader new runtime contract.
