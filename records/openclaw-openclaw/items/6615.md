## Summary

Current main still lacks native deny-over-allow exec approval rules, and the canonical issue is paired with two open implementation PRs. The broader direct candidate is currently conflicting and still has unresolved live macOS proof and persisted-policy ownership questions, so the issue remains necessary for maintainer security and product consolidation.

## What This Changes

Add native deny-over-allow exec approval rules that match dangerous command content and require a human decision despite permissive execution settings.

## Best Possible Solution

Consolidate the open candidates behind one additive policy with a single canonical persisted owner, human one-shot approval on matches, identical gateway, node, and macOS dispatch-time enforcement, strict schema and UI/docs coverage, and exact-head live companion proof.
