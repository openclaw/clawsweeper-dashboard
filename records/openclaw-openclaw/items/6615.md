## Summary

Keep this issue open. Current main still has no native exec-approval denylist or deny-over-allow evaluation, and the linked open pull request is the active implementation candidate. SafeClaw and the CRE plugin are useful prior art, but they do not provide the same built-in gateway/node enforcement; maintainers still need to approve the security semantics and upgrade-safe persisted configuration before landing native support.

## What This Changes

Add command- and argument-aware deny rules that override permissive exec approval settings and require approval or denial for matched commands.

## Best Possible Solution

Adopt one additive deny-over-allow rule model shared by gateway and node hosts, with deterministic matching, human-only approval on matches, fail-closed handling for unanalyzable commands, round-trip-safe configuration, Control UI/CLI support, and live prompt-to-allow-once cross-host proof before merge.

Options:

- **Adopt deny-over-allow overlay (recommended):** Keep existing security and ask modes, evaluate deny rules before permissive or durable allow decisions, and require explicit human approval for matches across both execution hosts.
- **Add a separate denylist mode:** Implement the originally proposed security=denylist and ask=on-match enums as a distinct operating mode, accepting a larger configuration and migration surface.
- **Keep policy external:** Decline native rules and rely on plugins such as CRE or external policy engines, accepting that core gateway/node approval parity may remain unavailable.

## Reproduction Assessment

Yes at source level: current main's policy enums, persisted approvals model, UI, and documentation expose allowlists but no denylist or deny-over-allow evaluation path. A runtime failure is not required to establish this feature gap.

## Solution Assessment

The exact security=denylist and ask=on-match proposal is not clearly the best shape. An additive deny-over-allow overlay preserves established modes and reduces migration churn, but its matching, prompting, and cross-host composition semantics require maintainer approval.
