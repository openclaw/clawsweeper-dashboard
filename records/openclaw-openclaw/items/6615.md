## Summary

Keep this issue open. Native deny-over-allow exec policy is not established on current main, and the linked open pull request is now the active implementation candidate; SafeClaw and CRE remain useful prior art but do not replace a merged cross-host policy. The remaining blocker is maintainer agreement on the security semantics and upgrade-safe persisted configuration.

## What This Changes

Add deny-over-allow exec approval rules that match command paths and arguments and require approval or denial when a rule matches.

## Best Possible Solution

Land one additive deny-over-allow approval overlay that reuses the existing parsed-command model, unions global and per-agent rules, forces human one-shot approval before broad allow decisions on both exec hosts, round-trips through protocol and management surfaces, and fails closed for unanalyzable commands.

Options:

- **Human approval overlay (recommended):** A deny match overrides automatic allow and durable trust, then requires an explicit one-shot human decision consistently on both hosts.
- **Unconditional hard denial:** A deny match always blocks execution, simplifying enforcement but removing any exceptional approval path.
- **No native policy:** Keep core allowlist-only and rely on external policy plugins, leaving native gateway/node exec behavior without deny-over-allow control.
