## Summary

This PR addresses the linked native-harness delegation bug with a sensible local-versus-inheritable policy split, but it is not merge-ready because the new default also applies to direct cron tool construction: an explicit cron `toolsAllow` restriction can disappear before `sessions_spawn` persists the child capability boundary. The submitted production-helper output is useful, but it still stubs the actual parent-child runtime and does not cover this sibling path.

## What This Changes

The PR makes runtime tool allowlists local by default, opts embedded agent runs into child inheritance, and adds focused capability-profile and tool-construction tests.

## Best Possible Solution

Keep native bridge allowlists local, but let direct tool-construction owners explicitly mark real runtime authority as inheritable; enable that for cron `toolsAllow`, audit equivalent callers, and cover both restored delegation and restricted-parent non-escalation.
