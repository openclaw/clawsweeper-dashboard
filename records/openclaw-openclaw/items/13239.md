## Summary

Current main and v2026.6.11 contain narrower provider setup, capability, migration, and live-probe documentation, but they still do not provide the requested cross-provider machine-readable lifecycle registry, deprecation guarantees, or lifecycle output in doctor/models commands. The latest substantive issue review explicitly retained this broader policy proposal, so conservative cleanup should not close it.

## What This Changes

Define a machine-readable provider/model-family/capability compatibility matrix, public deprecation policy, generated documentation, and CLI lifecycle reporting.

## Best Possible Solution

Adopt provider-owned lifecycle metadata aggregated into one generated registry for docs and concise doctor/models output, while keeping live auth and availability probes as a separate signal.

Options:

- **Scope official lifecycle guarantees (recommended):** Define guarantees for official and bundled provider paths first, require external plugins to publish owner-scoped lifecycle metadata, and generate shared docs and CLI output from those records.
- **Publish documentation guidance only:** Document non-binding support terminology and migration expectations without adding a machine-readable registry or CLI lifecycle surface.
- **Decline formal guarantees:** Keep provider-specific docs, release notes, migrations, and live probes as the support model without promising standard deprecation windows.

## Solution Assessment
