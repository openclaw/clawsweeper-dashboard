## Summary

Keep open: current main and the latest release still keep followup queue state process-local and still reject new command-lane work once gateway drain starts, while the durable replay work remains in open candidate PRs such as https://github.com/openclaw/openclaw/pull/82572, https://github.com/openclaw/openclaw/pull/51623, and https://github.com/openclaw/openclaw/pull/46303.

## What This Changes

The issue asks OpenClaw to preserve queued, draining, and downtime inbound messages across gateway restart so users do not have to resend dropped messages.

## Best Possible Solution

Adopt one SQLite-backed restart-recovery path that covers followup queues, drain-window rejections, and channel-specific redelivery or acknowledgment semantics, then close this after the chosen candidate merges.
