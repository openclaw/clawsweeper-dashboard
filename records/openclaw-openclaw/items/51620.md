## Summary

Keep open: current main and the latest release still keep followup queues in process memory and still reject new command-lane work during restart drain, while the durable replay work remains in open PRs rather than merged code.

## What This Changes

The issue asks OpenClaw to preserve queued, in-flight, and drain-window inbound messages across gateway restarts instead of silently dropping them.

## Best Possible Solution

Land a maintainer-selected SQLite and doctor-backed restart recovery implementation, likely https://github.com/openclaw/openclaw/pull/82572 or a successor, and split provider downtime catch-up or channel ACK semantics into narrower follow-ups if they remain.
