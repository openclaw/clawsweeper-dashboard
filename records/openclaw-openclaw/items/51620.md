- `P1`: Gateway restarts can silently drop accepted or in-flight channel work during active user conversations, making this an urgent reliability issue.
- `impact:message-loss`: The issue is specifically about inbound messages and queued followups disappearing across restart without user-visible recovery.

- `maturity:stable`: The affected Gateway runtime / Gateway Lifecycle surface maps to `gateway-runtime`, which is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and the latest release still keep followup queues process-local and reject new command-lane work during restart drain, while durable recovery remains in open PRs that need maintainer design review.

## What This Changes

Request durable gateway-restart handling so queued followup runs, drain-window arrivals, and channel acknowledgment behavior do not silently lose inbound messages.

## Best Possible Solution

Land or sponsor a SQLite-backed, untrusted-replay recovery design, likely through https://github.com/openclaw/openclaw/pull/82572 or a successor, and keep broader offline channel catch-up tracked separately.
