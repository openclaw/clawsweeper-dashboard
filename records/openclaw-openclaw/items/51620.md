## Summary

Keep open: current main has active-run restart recovery and a SQLite-backed restart sentinel, but followup queue items still live in process memory and drain-window command-lane enqueues still reject without durable inbound replay. The linked PRs are still open or partial, so the central user problem is not implemented on main.

## What This Changes

The issue asks OpenClaw to preserve and replay queued, in-flight, and restart-window inbound messages across gateway restarts.

## Best Possible Solution

Keep this as the canonical tracker until a rebased SQLite-backed restart recovery path lands, then split any remaining provider downtime catch-up or channel ACK semantics into narrower follow-ups.
