Yes for the code shape: handling unsupported hard-link errors inside `writeUsageCostCacheLockAtomically` preserves the existing owner boundary, `EEXIST` contention behavior, release path, and stale-lock handling. The unresolved blocker is proof acceptance, not a better implementation layer.
