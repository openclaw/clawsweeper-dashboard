## Summary

This PR is still necessary: current `main` sends Teams Graph requests without an SSRF policy and builds media policies without the RFC2544 opt-in. The proposed scope is plausibly safe because it remains hostname-limited, but it changes an SSRF boundary and still needs redacted after-fix proxy-DNS evidence before merge.

Likely related people: `steipete` is a low-confidence routing candidate from adjacent RFC2544 SSRF-policy work; current-main Teams ownership could not be established from the available read-only evidence.

## What This Changes

The PR permits RFC2544 fake-IP DNS results only for Microsoft Teams Graph hosts and existing allowed media-host suffixes, with focused regression assertions.

## System Context

The Microsoft Teams plugin uses guarded outbound fetches for Microsoft Graph operations and attachment downloads. The SSRF guard resolves hostnames before the request reaches Microsoft services or a host-side proxy, so the policy decides whether fake-IP proxy DNS results may proceed.

## Architecture Diagram

  Guard --> Policy[Hostname-scoped policy]

## Best Possible Solution

Keep the RFC2544 exception limited to explicit Graph and media hostname policies, then land it only after a redacted host-proxy/DNS fake-IP run proves Graph and media requests succeed while non-RFC2544 private targets remain blocked.
