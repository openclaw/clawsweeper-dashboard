## Summary

Keep open: current main still has pair-scoped `maxPingPongTurns` protection for `sessions_send`, but it does not carry a visited-agent chain across A2A turns. The linked implementation PR remains open, draft, and conflicting, so this issue still owns the graph-cycle policy decision.

## What This Changes

The issue requests graph-aware `sessions_send` loop detection so triangular or polygonal agent cascades are blocked instead of bypassing the existing pairwise ping-pong guard.

## Best Possible Solution

Land or reject a maintainer-approved graph-aware cycle guard for core `sessions_send` that propagates canonical visited-agent provenance through gateway and internal A2A turns, preserves direct `maxPingPongTurns`, and tests triangular cycles plus non-cyclic coordination.

Yes, source inspection gives a high-confidence reproduction path: a triangular A->B->C->A route can keep every pair below `maxPingPongTurns` because current main tracks only the current pair's ping-pong count and does not carry visited-agent provenance.
