## Summary

Keep open: current main and the latest release still lack propagated visited-agent provenance for graph-shaped `sessions_send` loops, and the linked implementation PR is open, draft, and conflicting, so this issue remains the canonical report until that PR lands or maintainers choose a different cycle policy.

## What This Changes

The issue requests graph-aware `sessions_send` loop detection so multi-agent cycles such as A to B to C to A cannot bypass the existing pairwise `maxPingPongTurns` guard.

## Best Possible Solution

Land a maintainer-approved provenance-chain guard across the runtime, gateway schema, and focused regression tests, likely via https://github.com/openclaw/openclaw/pull/94594 or a cleaned successor, with explicit policy acceptance for cyclic revisits.

## Solution Assessment

Yes, with maintainer policy acceptance: normalized visited-agent provenance plus a pre-delivery `sessions_send` guard is the right boundary because both gateway and in-process handoffs already consume `InputProvenance`.
