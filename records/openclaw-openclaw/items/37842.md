Keep open: current `main` and v2026.6.11 still lack graph-aware visited-agent provenance for `sessions_send`, while https://github.com/openclaw/openclaw/pull/94594 is open, draft, and conflicting as the linked implementation attempt.

## What This Changes

The issue requests graph-aware `sessions_send` cycle detection so multi-agent routes such as A -> B -> C -> A cannot bypass the existing pairwise ping-pong limit.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/94594 or a narrow replacement provenance-chain guard; if maintainers reject fail-closed cyclic revisits, close that PR and document the supported behavior.

## Reproduction Assessment

Yes at source level: current main has no propagated visited-agent chain and the A2A helper only alternates requester and target. I did not run a live 3+ agent deployment in this read-only review.

## Solution Assessment

Yes, with maintainer policy acceptance: normalized visited-agent provenance plus a pre-delivery `sessions_send` guard is the right boundary because gateway and in-process handoffs already consume `InputProvenance`. The issue should remain open until the linked PR lands or maintainers reject that fail-closed direction.
