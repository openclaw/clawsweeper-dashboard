## Summary

Keep open: current main and v2026.6.11 still lack a propagated visited-agent chain for `sessions_send`, and the linked fixing PR is open, draft, and conflicting, so this issue remains the canonical report until that PR lands or maintainers reject the fail-closed cycle policy.

## What This Changes

Add graph-aware `sessions_send` cycle detection so multi-agent routes such as A to B to C to A cannot bypass the existing pairwise `maxPingPongTurns` guard.

## Best Possible Solution

Review and either land one provenance-chain guard across the runtime, gateway schema, and regression tests, or close the linked PR if maintainers decide cyclic agent revisits should remain allowed.

## Reproduction Assessment

Yes at source level: current main carries no visited-agent chain, and the A2A helper only alternates a requester-target pair. I did not run a live three-agent deployment reproduction in this read-only review.

## Solution Assessment

Yes, with maintainer policy acceptance: normalized visited-agent provenance plus a pre-delivery `sessions_send` guard is the right boundary because both gateway and in-process handoffs already consume `InputProvenance`.
