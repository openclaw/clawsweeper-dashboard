## Summary

Keep open: current main and the latest release still lack a propagated visited-agent chain for `sessions_send`, while the open fixing PR is draft and conflicting, so this issue remains the canonical report until that PR lands or maintainers reject the fail-closed cycle policy.

## What This Changes

Request graph-aware loop detection for multi-agent `sessions_send` chains so A->B->C->A-style cascades do not bypass pairwise `maxPingPongTurns`.

## Best Possible Solution

Review and land one provenance-chain guard across runtime, gateway schema, and regression tests, or close the linked PR if maintainers decide cyclic agent revisits should remain allowed.

## Reproduction Assessment

Yes at source level: current main has no propagated visited-agent chain and the A2A helper only alternates requester and target. I did not run a live 3+ agent deployment in this read-only review.

## Solution Assessment

Yes, with maintainer policy acceptance: normalized visited-agent provenance plus a pre-delivery `sessions_send` guard is the right boundary because both gateway and in-process handoffs already consume `InputProvenance`. The open linked PR is the current candidate, but this issue should not close until it merges or is rejected.
