The issue requests graph-aware loop detection for multi-agent `sessions_send` cascades so cycles through three or more agents cannot bypass the existing pairwise ping-pong guard.

## Best Possible Solution

Review and land one provenance-chain guard across runtime, gateway schema, and regression tests, or close the linked PR if maintainers decide cyclic agent revisits should remain allowed.

## Reproduction Assessment

Yes, with maintainer policy acceptance: normalized visited-agent provenance plus a pre-delivery `sessions_send` guard is the right boundary because both gateway and in-process handoffs already consume `InputProvenance`.
