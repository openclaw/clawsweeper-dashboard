## Summary

## What This Changes

Request graph-aware `sessions_send` loop detection so multi-agent routes such as A -> B -> C -> A cannot bypass the pairwise `maxPingPongTurns` guard.

## Best Possible Solution

Review and land a single provenance-chain guard that updates runtime handoffs, the gateway protocol schema, and regression tests, or close the linked PR if maintainers decide cyclic revisits should remain allowed.

## Reproduction Assessment

## Solution Assessment

Yes, with maintainer policy acceptance: normalized visited-agent provenance plus a pre-delivery `sessions_send` guard is the right boundary because gateway and in-process handoffs already consume `InputProvenance`. The open linked PR is the current candidate, but this issue should not close until it merges or is rejected.
