## Summary

Keep open: current `main` and v2026.6.11 still lack graph-aware `sessions_send` route state, and the open closing PR is draft/conflicting, so this issue remains the canonical report until that PR lands or maintainers reject the fail-closed cycle policy.

## What This Changes

Request graph-aware cycle detection for multi-agent `sessions_send` chains so triangular or polygonal A2A cascades are blocked instead of bypassing pairwise `maxPingPongTurns`.

## Best Possible Solution

Review and land one provenance-chain guard across runtime, gateway schema, and regression tests, or close the linked PR if maintainers decide cyclic agent revisits should remain allowed.

## Reproduction Assessment

Yes at source level: current `main` carries no visited-agent chain, and the A2A helper only alternates a requester-target pair. I did not run a live 3+ agent deployment reproduction in this read-only review.

## Solution Assessment

Yes, with maintainer policy acceptance: normalized visited-agent provenance plus a pre-delivery `sessions_send` guard is the right boundary because gateway and in-process handoffs already consume `InputProvenance`. The open linked PR is the current candidate, but this issue should not close until it merges or is rejected.
