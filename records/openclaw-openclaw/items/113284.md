## Summary

## What This Changes

Prevent the macOS app from restarting or reinstalling a healthy LaunchAgent-managed local gateway when authentication, pairing, or attachment fails.

## System Context

The macOS app discovers a local gateway and attempts to attach using gateway endpoint and credential information derived from configuration and the user LaunchAgent. Its connection outcome must determine whether to show recovery guidance, while lifecycle repair commands can stop or replace the gateway that serves active agent and channel sessions.

## Architecture Diagram

flowchart LR
  App[macOS app launch] --> Discover[Discover local managed gateway]
  Discover --> Credentials[Resolve endpoint and credentials]
  Credentials --> Attach[Attempt WebSocket attach and pairing]
  Attach -->|Connected| Use[Use existing gateway]
  Attach -->|Rejected or pairing failure| Error[Show actionable attach error]
  Discover --> Health[Check managed service health]
  Health --> Guard[Protect healthy service from automatic repair]
  Guard --> Use
  Guard --> Explicit[Only explicit user-confirmed repair can change service]

## Best Possible Solution

Make the macOS gateway manager treat a healthy existing managed gateway as attach-only: pairing, authentication, or WebSocket failures should surface actionable recovery UI and must not invoke install, bootout, restart, or replacement unless the user explicitly confirms repair; cover both matching-version and mismatched-version cases with native macOS regression tests.
