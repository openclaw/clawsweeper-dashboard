## Summary

Keep open: current main still has token-only macOS remote Settings/onboarding UI and password-auth failures still tell users the auth mode is unsupported, while the linked draft PR is the active implementation candidate rather than a merged fix.

## What This Changes

The issue requests macOS Settings and onboarding support for entering, clearing, and preserving remote gateway password authentication via `gateway.remote.password`.

## Best Possible Solution

MacOS Settings and onboarding should expose `gateway.remote.password`, preserve non-plaintext password values unless explicitly edited, and guide password-auth failures to that field with focused AppState and onboarding coverage.

## Reproduction Assessment

Yes from source inspection: current main resolves `gateway.remote.password` in the connection stack, but macOS Settings/onboarding only expose `remoteToken` and password-auth failures still say the flow is unsupported. This was not live-reproduced in the macOS app, so the status is source-reproducible rather than reproduced.

## Solution Assessment

Yes: the narrow maintainable fix is to extend the existing macOS remote config state/UI and auth prompt handling for password auth, not to add a new config shape or alternate auth mode. The open linked PR is the right next object to review before starting another fix lane.
