## Label Justifications

- `P2`: This is a bounded user-facing Control UI feature defect: some generic links can fail to honor the new durable preference.
- `merge-risk: 🚨 compatibility`: Existing browser-local face state is intentionally discarded on upgrade while the new optional field changes session list and patch behavior across clients.

## Summary

Keep this PR open. Its durable preference design fits the existing session-row and gateway surfaces, but generic navigation can only recover the stored face when its target happens to be in the Control UI’s capped cached session list; Tasks and Workboard pass only a session key, so older targets can incorrectly fall back to Chat. The PR also needs redacted real browser evidence for the cross-device behavior before merge.

## What This Changes

The branch persists each thread’s preferred Chat or Dashboard face through the existing session patch/list protocol, changes generic navigation to use that preference, and adds a `/dashboards` index.

## System Context

The Control UI receives gateway session rows and builds links from them across the sidebar, task, workboard, and session pages. This change stores a face preference in the session entry, exposes it in list results, and uses it to select a Chat or Dashboard route while adding a server-filtered dashboard index.

Resolve the face at every generic-navigation boundary from an authoritative row or a targeted gateway lookup, add regression coverage for an uncached target, then provide redacted browser evidence showing one client changes the face and another client opens that thread through `/dashboards`.
