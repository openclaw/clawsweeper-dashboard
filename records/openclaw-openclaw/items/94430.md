## Summary

Keep open and do not merge as-is: the PR addresses a real failover gap, but routing moderation-policy blocks through `rate_limit` inherits throttling, profile rotation, model fallback, session suspension, and cross-provider retry semantics without maintainer-approved moderation behavior or real after-fix proof.

## What This Changes

The PR adds generic moderation-error string matching to embedded-agent failover classification, mapping `new_sensitive`, `content_filter`, `safety_block`, and `content_policy` messages to `rate_limit`, with matching tests and a changelog entry.

## Best Possible Solution

Define explicit maintainer-approved content-policy/moderation semantics, provider-owned where appropriate, and only opt into fallback/cooldown behavior when that security and product choice is intentional and proven.
