## Summary

This appears to be a valid Control UI bug: the documented release model distinguishes stable `latest` from beta prereleases, while the reported banner presents a beta candidate as though it were a stable update. Current-main inspection identified the Control UI update-overlay surface, but did not establish that the reported behavior has already been corrected or superseded, so this issue should remain open for a focused fix.

## What This Changes

Make the Dashboard update banner preserve beta/prerelease status so stable-channel users are not told that an unreleased stable version is available.

## System Context

The Gateway’s update check determines an available package version and the Control UI displays that result as an update notice. The notice influences whether an operator believes their installed stable release is behind and which update channel they may choose next.

## Best Possible Solution

Have the update-check contract retain the exact prerelease version and release channel, then render a clearly labeled beta notice in the Control UI while keeping stable-channel availability distinct; add focused coverage for stable, beta, and no-update results.
