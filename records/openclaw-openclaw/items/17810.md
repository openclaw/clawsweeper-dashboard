## Summary

Keep open: current main still lacks configurable per-file elevation/exclusion for SOUL.md, IDENTITY.md, USER.md, and MEMORY.md, while the direct implementation PR is closed unmerged. The remaining question is the accepted product/API boundary, not whether the source gap exists.

## What This Changes

The issue requests configurable mapping of selected bootstrap files into dedicated prompt sections, with optional exclusion from flat Project Context rendering.

## Best Possible Solution

Maintainers should choose one supported context-customization surface, then either add a narrow typed elevation/exclusion config with schema/docs/tests or document/extend the plugin/context-engine contract so external packages can implement this cleanly.
