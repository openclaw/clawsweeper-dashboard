## Summary

Keep open: current main and v2026.6.11 still render these bootstrap files as flat Project Context entries, the direct implementation PR is closed unmerged, and the remaining question is the accepted prompt/config API boundary.

## What This Changes

Add configurable per-file elevation for bootstrap context files so SOUL.md, IDENTITY.md, USER.md, and MEMORY.md can render as dedicated prompt sections and optionally be excluded from flat Project Context.

## Best Possible Solution

Maintainers should choose one supported context customization surface, then add either a narrow typed core config for deterministic per-file elevation/exclusion or a context-engine/plugin API that can express the same behavior without replacing the whole prompt.

Rationale: The source-level gap is clear, but the durable API changes prompt authority, prompt-cache stability, and the public config/plugin boundary, which needs maintainer product direction.

Owner confidence: high

Options:

- **Extend plugin/context-engine contract (recommended):** Document or add the minimal plugin/context-engine hook needed for external packages to elevate and exclude bootstrap files without adding another core config knob.
- **Add narrow core config:** Accept a typed core config for ordered pattern-to-section elevation with explicit exclusion behavior, plus schema, docs, and regression tests.
- **Keep Project Context flat:** Reject elevation as core behavior for now and direct users to context-engine plugins or manual prompt additions for persona-specific weighting.
