## Summary

Keep open. Current main and latest release still lack configurable per-file elevation/exclusion for SOUL.md, IDENTITY.md, USER.md, and MEMORY.md; the closed implementation PR is not merged, and the remaining blocker is the accepted prompt/config or context-engine API boundary.

## What This Changes

Request configurable elevation/exclusion of selected workspace bootstrap files such as SOUL.md, IDENTITY.md, USER.md, and MEMORY.md into named prompt sections instead of flat Project Context entries.

## Best Possible Solution

Maintainers should choose one prompt/context contract, then implement either documented typed elevation/exclusion config or a plugin/context-engine API that can place selected bootstrap files into named sections without replacing the whole system prompt.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 still render the relevant files as Project Context entries and expose no elevation/exclusion config. The reported long-session persona drift itself was not live-reproduced in this read-only review.

## Solution Assessment

Unclear as proposed. The requested `context.elevation` shape is plausible, but the best maintainable solution needs maintainer agreement on core config versus plugin/context-engine ownership.
