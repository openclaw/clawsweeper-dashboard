## Summary

Keep open. Current main and v2026.6.11 still lack configurable per-file elevation/exclusion for bootstrap context; non-Codex prompts continue to render files flat under Project Context, and the direct implementation PR is closed unmerged, so the remaining blocker is maintainer product/API direction.

## What This Changes

Requests configurable elevation of SOUL.md, IDENTITY.md, USER.md, and MEMORY.md into dedicated prompt sections ahead of Project Context, with optional exclusion from the flat context list.

## Best Possible Solution

Maintainers should choose the accepted context-extension boundary, then implement deterministic per-file section elevation as either a documented typed core config or a plugin/context-engine API that can prepend sections without replacing all prompt assembly.

## Reproduction Assessment

Yes. Source inspection shows that supplied bootstrap files still render as file headings under Project Context and that no context-elevation config/API exists.

## Solution Assessment

Unclear. The requested core config is plausible, but the best fix depends on whether maintainers want a typed core config surface or a plugin/context-engine extension point.
