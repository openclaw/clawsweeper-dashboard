## Summary

Keep open. Current main and v2026.6.11 still render the requested bootstrap files as flat Project Context entries with no elevation/exclusion config, and the direct implementation PR is closed unmerged; the remaining blocker is maintainer product/API direction.

## What This Changes

The issue requests configurable elevation of selected bootstrap context files into dedicated system-prompt sections instead of rendering them as ordinary Project Context files.

## Best Possible Solution

Maintainers should choose one prompt/context contract, then implement either documented typed elevation/exclusion config or a plugin/context-engine API that can place selected bootstrap files into named sections without replacing the whole system prompt.

## Reproduction Assessment

Yes at source level: current main still renders SOUL.md, IDENTITY.md, USER.md, and MEMORY.md-style inputs as Project Context entries and exposes no elevation/exclusion config. The model-quality drift claim itself was not live-reproduced in this read-only review.

## Solution Assessment

Unclear as proposed: context.elevation is plausible, but OpenClaw policy requires maintainer agreement on core config versus plugin/context-engine ownership before adding this public prompt surface.
