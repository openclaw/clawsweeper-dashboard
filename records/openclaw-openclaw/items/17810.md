## Summary

Keep open. Current main and v2026.6.11 still render SOUL.md, IDENTITY.md, USER.md, and MEMORY.md as ordered Project Context files without a configurable elevation/exclusion surface; the direct implementation PR is closed unmerged, so the remaining blocker is maintainer product/API direction.

## What This Changes

Request configurable per-file elevation so selected bootstrap files render as dedicated prompt sections above Project Context and can be excluded from the flat context listing.

## Best Possible Solution

Maintainers should choose one supported context customization surface, then implement deterministic per-file elevation and exclusion through either typed core config or a plugin/context-engine API with docs, schema metadata, and prompt-shape tests.

## Reproduction Assessment

Yes. Source inspection is enough to reproduce the gap: current main renders the target files as flat Project Context entries and exposes no elevation/exclusion config.

## Solution Assessment

Unclear. The requested behavior is plausible, but the best fix depends on maintainer choice between a typed core config contract and a plugin/context-engine extension surface.
