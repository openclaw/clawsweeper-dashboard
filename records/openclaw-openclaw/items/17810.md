## Summary

Keep open: current main and v2026.6.11 still lack the requested configurable per-file elevation/exclusion surface for SOUL.md, IDENTITY.md, USER.md, and MEMORY.md. Main has adjacent improvements, including fixed SOUL/MEMORY guidance and native Codex-specific routing for some workspace files, but the central non-Codex/core prompt contract remains a product/API decision rather than cleanup.

## What This Changes

The issue requests configurable elevation of selected context files into dedicated prompt sections, with optional exclusion from the flat Project Context renderer.

## Best Possible Solution

Maintainers should choose one supported context customization surface, then implement per-file elevation/exclusion through either a documented typed core config or a context-engine/plugin contract with schema, docs, and focused prompt-shape tests.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 still render the requested non-Codex files as flat Project Context entries and expose no elevation/exclusion parameter or config key. I did not live-reproduce the reported long-session persona drift.

## Solution Assessment

Unclear. The requested behavior is bounded and useful, but the best implementation still depends on maintainer direction on typed core config versus extending the context-engine/plugin contract.
