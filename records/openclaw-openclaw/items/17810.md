## Summary

Keep open: current main and v2026.6.11 still render the requested bootstrap files as flat Project Context entries and expose no per-file elevation/exclusion config, while the remaining decision is a prompt/config API product choice rather than conservative cleanup.

## What This Changes

The issue requests configurable elevation of selected bootstrap files such as SOUL.md, IDENTITY.md, USER.md, and MEMORY.md into dedicated system prompt sections instead of flat Project Context rendering.

## Best Possible Solution

Maintainers should choose one supported context customization surface, then either add a documented typed core config for deterministic per-file elevation/exclusion or extend the context-engine/plugin contract so external code can map bootstrap files into canonical prompt sections.

## Reproduction Assessment

Yes, at source level. Current main still renders these files as flat Project Context entries and exposes no elevation parameter or config key; I did not run a live model session to prove persona degradation over many turns.
