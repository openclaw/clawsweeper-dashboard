## Summary

Keep this PR open: the direct Gradium predicate fix is already on main through the merged sibling, but the branch contains useful gateway work that is not on main. That gateway fix is incomplete because `tts.status` evaluates fallback providers before the newly guarded provider-state map, so the same invalid Gradium configuration can still fail the RPC.

## What This Changes

The branch makes Gradium configuration checks fail closed and guards TTS provider-state enumeration against provider configuration errors.

## Best Possible Solution

Rebase onto main, drop the already-merged Gradium predicate changes, then guard every per-provider configuration check used by `tts.status` and add a gateway regression covering invalid Gradium configuration without weakening synthesis-time URL validation.
