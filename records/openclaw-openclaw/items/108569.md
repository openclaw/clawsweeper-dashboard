## Summary

Keep this PR open for revision: the direct Gradium predicate and `tts.status` changes are directionally correct, but `tts.providers` and the `/tts provider` inventory still resolve provider config outside a fail-closed boundary, so the same invalid `baseUrl` can still break supported enumeration paths.

## What This Changes

The PR makes Gradium `isConfigured` return false on invalid configuration, adds predicate regressions, and wraps `tts.status` provider-state enumeration with `configuredOrFalse`.

## Best Possible Solution

Make the shared configured-state path fail closed around both provider config resolution and the predicate, route `tts.status`, `tts.providers`, and `/tts provider` through it, and add caller-level regressions while keeping synthesis validation strict.
