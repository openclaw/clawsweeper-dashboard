## Summary

This remains a credible provider-streaming bug: the earlier DeepSeek recovery merged through https://github.com/openclaw/openclaw/pull/88946 addressed complete DSML blocks, while this report documents malformed opening markup and nested argument encodings that can still prevent declared tools from running. The remaining recovery grammar has a tool-execution safety tradeoff, so it needs an owner decision before implementation.

## What This Changes

Recover DeepSeek DSML tool intent from a custom OpenAI-compatible completions proxy when the wrapper opening tag is malformed or arguments are nested, so valid read and exec calls execute instead of reaching Feishu as text.

## System Context

The OpenAI-completions streaming transport converts provider response chunks into assistant text and tool-call blocks for the agent loop. Those blocks either run declared tools or are rendered by channels such as Feishu, so failed recovery exposes raw provider markup to users.

## Best Possible Solution

Add narrowly scoped DeepSeek recovery fixtures for the missing-`>` wrapper and nested JSON arguments, then recover only fully closed, unambiguous calls whose normalized arguments pass the existing declared-tool validation path.

- **Provider-specific opt-in:** Add recovery only behind an owner-approved DeepSeek-compatible transport rule if the proxy variant proves too ambiguous for the shared parser.
