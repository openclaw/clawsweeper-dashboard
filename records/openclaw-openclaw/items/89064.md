## Summary

Keep open. Current main still does not give a high-confidence implemented answer for live cron execution logs in the Web UI chat; the source path shows cron runs scoped to run-specific sessions while Web UI chat/tool rendering requires selected-session matches, and the remaining choice is the intended live-progress surface.

## What This Changes

The issue asks for OpenClaw cron job execution logs to appear live in the Web UI chat session instead of only after the cron task completes.

## Best Possible Solution

Define the intended live cron-progress destination, then align cron run session routing, Web UI event filtering, docs, focused tests, and live Control UI proof to that contract.

Options:

- **Define run follow mode (recommended):** Add or document a deliberate run-follow surface that subscribes to the run-specific session and shows live progress without changing parent-chat semantics.
- **Mirror into parent chat:** Treat cron progress as part of the parent selected chat and update routing/filtering so run-lane events appear there live.
- **Use Activity/tasks only:** Keep chat final-only and make Activity/tasks the supported live progress surface for cron runs.

Yes at source level: isolated cron runs use run-specific session keys while the Web UI chat and tool stream only accept matching selected-session events. No live Ubuntu/npm Control UI cron reproduction was run in this read-only review.

Unclear; showing live cron progress is useful, but maintainers should first choose the supported destination before changing event routing or chat filtering.
