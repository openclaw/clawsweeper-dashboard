## Summary

Keep open: the cleanup direction matches the shared temp-dir helper pattern, but the compaction test migration can clean up its temp directory before fire-and-forget session-store reconciliation has drained, undermining the leak fix it is trying to make.

## What This Changes

The PR migrates four agent test files from raw `fs.mkdtemp`/`fs.mkdtempSync` usage to the shared `withTempDir` test helper.

## Best Possible Solution

Keep the temp-dir migration, but hold compaction temp directories open until pending session-store reconciliation has drained, then refresh proof for the touched tests and cleanup path.

## Reproduction Assessment

Yes by source inspection: the patched compaction tests call `handleCompactionEnd` inside `withTempDir`, while `handleCompactionEnd` starts persisted count reconciliation asynchronously and returns before that write is guaranteed to drain. I did not run the tests because this review is read-only.

## Solution Assessment

No: `withTempDir` is the right helper for synchronous test-owned directories, but these compaction success cases also need to await or otherwise drain delayed session-store writes before the helper removes the directory.

- **[P2] Keep temp dirs alive until compaction writes drain:** `src/agents/embedded-agent-subscribe.handlers.compaction.test.ts:188`
  - body: These success-path compaction tests call `handleCompactionEnd` inside `withTempDir`, but `handleCompactionEnd` starts persisted count reconciliation as a fire-and-forget async write. Drain the session-store writer queue before leaving the temp-dir callback, or clean up only after the existing drain has completed.
