## What This Changes

The PR changes OpenAI-compatible image response parsing so strict mode skips invalid entries and returns valid images unless every returned entry is invalid.

## Best Possible Solution

Land this focused parser change if maintainers accept partial-success strict parsing as the SDK behavior, while keeping URL/object/base64url proxy response support on separate review paths.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 throw inside the strict parser loop before later valid entries can be processed. I did not run tests because this cleanup review is read-only, but the PR body supplies before/after terminal proof for the mixed batch.

## Solution Assessment

Yes if maintainers accept the compatibility shift: deferring the strict error until after the loop is the narrow shared-helper fix for mixed valid/invalid entries. The safer alternative is preserving fail-fast as the default and adding an explicit opt-in if fail-fast is considered part of the SDK contract.
