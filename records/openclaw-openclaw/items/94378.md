## Summary

Keep open for maintainer review: the patch is narrow and source-backed with sufficient terminal proof, but it changes SDK-exported strict-mode parser behavior from fail-fast to partial success and needs maintainer acceptance before merge.

## What This Changes

The PR changes the shared OpenAI-compatible image response parser and tests so strict mode skips invalid data entries when at least one valid b64_json image can be returned.

## Best Possible Solution

Land the focused parser change if maintainers accept partial-success strict parsing as SDK behavior, while keeping URL/object/base64url proxy response work on separate review paths.

## Reproduction Assessment

Yes at source level: current main throws inside the strict parser loop on the first invalid entry, before later valid entries can be returned. The PR body also supplies before/after terminal output for a mixed valid/invalid batch.

## Solution Assessment

Yes for the mixed b64_json batch behavior: deferring the strict error until after the loop is the narrow shared-helper fix. The remaining question is maintainer acceptance of the SDK-exported strict-mode compatibility change.
