## Label Justifications

- `P1`: The report describes a real user-facing QQ Bot reply workflow leaking internal metadata into normal chat replies.
- `impact:security`: The visible blocks include internal conversation and sender identifiers that should stay AI-facing metadata rather than user-visible reply text.
- `impact:ux-friction`: Users still receive replies, but the prefixed JSON metadata makes normal conversations confusing and support-heavy.

## Summary

Keep open: current main and v2026.6.11 still route QQ Bot outbound text through the shared assistant sanitizer without inbound-metadata stripping, while the direct candidate fix at https://github.com/openclaw/openclaw/pull/100791 remains open and waiting on author repair.

## What This Changes

The issue asks OpenClaw to stop rendering QQ Bot inbound metadata blocks such as Conversation info and Sender into user-visible replies.

## Best Possible Solution

Repair and land https://github.com/openclaw/openclaw/pull/100791, or an equivalent shared assistant-delivery sanitizer fix that strips inbound metadata before channel delivery while preserving user-role timestamp stripping.
