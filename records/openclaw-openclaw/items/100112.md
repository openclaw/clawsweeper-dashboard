## Summary

Keep open: current main still lacks a safe recovery path for aggregate-elided exec spill output and still truncates web_fetch content without spilling, and the live issue carries the protected maintainer label.

## What This Changes

Request to make destructive tool-result truncation recoverable by preserving safe exec spill-file recovery markers during history elision and adding bounded spill recovery for web_fetch output.

## Best Possible Solution

Define a core recovery contract that preserves details stripping, gates visible spill pointers by read capability and sandbox state, and adds bounded web_fetch spill recovery only after maintainers accept the lifecycle model.

## Reproduction Assessment

Yes from source: current main strips tool-result details on replay, replaces aggregate-elided text with a rerun-only marker, and truncates web_fetch content through in-memory slicing without a spill pointer. I did not run a live long-session reproduction.

## Solution Assessment

Unclear: reusing the private temp-file seam is plausible, but the best fix must first settle the safe model-visible marker, sandbox/read-capability gate, temp-file lifetime, and web_fetch spill cap.
