## Summary

Keep open. Current main intentionally tolerates unsupported chmod failures, but still rethrows EPERM when a target is not already private and the same-directory probe can chmod; this new report may be a narrower active SQLite sidecar-lock case rather than something already fixed by the earlier unsupported-filesystem work.

## What This Changes

The issue asks OpenClaw to avoid crashing when `applyPrivateModeSync` sees EPERM on SQLite database sidecar files during active locks.

## Best Possible Solution

If maintainers accept the boundary, add a narrow SQLite sidecar-lock handling path with regression tests proving active locked sidecars do not crash while ordinary broad-permission ownership failures still fail closed.
