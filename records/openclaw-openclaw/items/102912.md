## Summary

Keep open: current main and the latest release still rethrow unresolved `EPERM` from `applyPrivateModeSync`, and the merged chmod-less filesystem fix does not cover the reported live SQLite sidecar lock case. A fix is plausible, but it needs a narrow security-boundary decision before automation should change fail-closed permission hardening.

## What This Changes

The issue reports that `applyPrivateModeSync` can rethrow `EPERM` on live SQLite WAL/SHM sidecar files, crashing state database boot or write paths.

## Best Possible Solution

Define a narrow shared-state SQLite sidecar permission policy that avoids gateway crashes on lock-related chmod EPERM while preserving fail-closed behavior for ownership or privacy failures, then cover boot, repair, and write paths with regression tests.
