## Summary

Keep open: current main still has a credible source path where `applyPrivateModeSync` rethrows `EPERM` for a non-private SQLite sidecar, and the existing closed chmod-less filesystem fix does not cover the reported active-lock sidecar case.

## What This Changes

The issue reports that `applyPrivateModeSync` can crash the database boot/write sequence when `chmodSync` returns `EPERM` for SQLite database files under active locks.

## Best Possible Solution

Define a narrow shared-state SQLite sidecar permission policy that avoids gateway crashes on lock-related chmod EPERM while preserving fail-closed behavior for ownership or privacy failures, then cover boot, repair, and write paths with regression tests.
