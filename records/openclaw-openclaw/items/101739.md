## Summary

Keep open for normal maintainer review and merge handling. Current main still accepts inherited exec response keys, while this PR narrowly switches exec response lookup to own-property checks, adds focused regression coverage, and has sufficient real-behavior proof with no blocking findings.

## What This Changes

The PR changes exec SecretRef response parsing to require own entries in `values` and `errors`, and adds a POSIX regression test for a missing `toString` id.

## Best Possible Solution

Land the focused parser-boundary fix after the exact-head merge gate stays green, keeping the exec SecretRef protocol and config surface unchanged.

## Reproduction Assessment

Yes. Current main uses inherited `in` membership on JSON-parsed exec response `values` and `errors`, so an omitted id such as `toString` is source-reproducible without a new product mode.

## Solution Assessment

Yes. Checking own properties inside `parseExecValues` is the narrowest maintainable fix because the bug is at the exec response parser boundary; file/env SecretRef paths already use different lookup contracts.
