The PR changes exec SecretRef response parsing to require own `values`/`errors` entries for requested ids and adds a POSIX regression test for a missing `toString` id.

## Best Possible Solution

Land the narrow own-property parser check and regression test after normal secops/CODEOWNERS review and exact-head checks.

## Solution Assessment

Yes. Changing the membership check at the exec response parser boundary to `Object.hasOwn` is the narrow maintainable fix and preserves the existing protocol, missing-id, and per-id error behavior.
