## Summary

Keep open. The current head fixes the prior systemctl option-operand gap, but it still treats every `openclaw gateway call ...` invocation as read-only even though that CLI forwards arbitrary Gateway RPC methods and `update.run` schedules a restart, leaving a lifecycle mutation outside the new explicit-approval guard.

## What This Changes

The branch adds a shared exec approval lifecycle classifier and wires it into gateway-host, node-host, and system.run approval paths with focused tests for OpenClaw gateway/daemon lifecycle commands, wrappers, yolo mode, and read-only exceptions.

## Best Possible Solution

Keep the shared classifier, but make `gateway call` method-aware so lifecycle-affecting RPCs such as `update.run` require explicit approval while known read-only inspection methods stay cheap.

## Reproduction Assessment

Yes. By source inspection, PR head marks `gateway call` as read-only, while the CLI forwards arbitrary Gateway RPC methods and docs say `update.run` schedules a restart.

## Solution Assessment

No, not yet. The shared classifier is the right layer, but broadly treating `gateway call` as read-only is not the best fix because the low-level RPC helper can invoke lifecycle-affecting methods.
