## Summary

This PR remains necessary because current main still streams the OpenGrep installer without deadlines, but the proposed patch is not merge-ready: retries can feed partial or duplicated script bytes directly into bash, the installer's own downloads remain unbounded, and the submitted evidence is only a static workflow guard rather than real stalled-transfer proof.

## What This Changes

The PR adds curl connection, transfer, and retry limits to the installer-script fetch in both OpenGrep workflows and adds a static guard for those arguments.

## Best Possible Solution

Download the pinned installer into a temporary file with bounded curl, execute it only after a complete successful transfer, bound the entire installer subprocess so its internal downloads cannot hang, and prove the failure path with a redacted stalled-transfer run in both shared workflow shapes.

## Review Findings

Overall confidence: 0.99

Full review comments:

- **[P1] Download the installer fully before invoking bash:** `.github/workflows/opengrep-precise.yml:67-69`
  - body: Keep the retry output away from the interpreter until curl has completed successfully. A timed-out transfer can already have emitted and executed a script prefix, and a retry can restart content on the same stdout stream; download to a temporary file first, then invoke bash only after curl exits successfully. This prior P1 remains unresolved on the current head and applies to the full-scan sibling workflow too.
  - confidence: 0.98
- **[P2] Bound the installer subprocess and its downloads:** `.github/workflows/opengrep-precise.yml:69`
  - body: The pinned `install.sh` performs its own curl requests for the binary, certificate, and signature without deadlines, so limiting only the outer script fetch does not prevent the install step from stalling. Add a deadline around the complete installer execution or replace those downloads with a bounded repository-owned path, and cover the same invariant in both workflows.
  - confidence: 0.99
