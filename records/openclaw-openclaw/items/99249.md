## Summary

Keep open: the intended doctor-lint behavior matches the existing opt-in check pattern, but the current patch appears to fail TypeScript because it adds `defaultEnabled` to an object still returned as `HealthCheck`. The draft/protected-label state also means this should remain maintainer-controlled rather than closed as cleanup.

## What This Changes

The PR marks the core doctor workspace-suggestions health check default-disabled and adds coverage that default `doctor --lint` skips it while explicit `--only` still runs it.

## Best Possible Solution

Return the workspace suggestions check as `SplitHealthCheckInput` or an equivalent selection-aware type, keep the default-disabled behavior and tests, then add real doctor-lint terminal proof before maintainer-controlled merge.

## Reproduction Assessment

Yes, source-reproducible: current main's lint runner skips only checks marked `defaultEnabled: false`, and current main's workspace-suggestions check lacks that marker. The patch defect is also source-reproducible because `HealthCheck` does not include `defaultEnabled`.

## Solution Assessment

No: the requested behavior is narrow and consistent with the existing lint selection contract, but this patch is not the best shape until the helper return type matches the selection metadata contract. The smaller correct repair is to return `SplitHealthCheckInput` or equivalent rather than widening the public `HealthCheck` interface.
