## Summary

Keep open. The PR is a focused bug-fix attempt, but it introduces two merge-blocking regressions: it can bypass existing z.ai endpoint detection for a zhipu-labeled route, and it weakens the cron pre-model watchdog that was landed for the already-closed cron stall issue.

## What This Changes

The PR excludes zhipu GLM models from silent-overflow detection and moves `model_resolution`, `auth`, and `context_engine` cron watchdog phases from pre-execution to execution.

## Best Possible Solution

Revise the PR so `zai-native` endpoint detection remains authoritative, cron only clears the pre-model watchdog after a real execution milestone, and add focused regressions for both boundaries.

## Reproduction Assessment

Yes, at source level. Current main has a regression test where `context_engine` stalls trigger the pre-model watchdog, and the PR diff changes that phase to clear the watchdog before first model call.

## Solution Assessment

No. The zhipu carve-out should not outrank `zai-native` endpoint detection, and the cron fix needs a narrower phase boundary that preserves existing pre-model stall diagnostics.
