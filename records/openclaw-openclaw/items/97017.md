## Summary

Keep open, but the patch is not merge-ready. The Zhipu fix addresses a real missing exception, yet the cron phase reclassification regresses the merged pre-model watchdog behavior from https://github.com/openclaw/openclaw/pull/80130, and the provider early return bypasses explicit z.ai endpoint detection.

## What This Changes

The PR excludes provider `zhipu` from silent-overflow detection, changes three cron watchdog phases from `pre_execution` to `execution`, and updates related agent settings and cron regression tests.

## Best Possible Solution

Preserve explicit z.ai endpoint/model detection, add the Zhipu exception only for true first-party Zhipu routing, and fix cron false positives without removing the #74803 pre-model stall watchdog.

## Reproduction Assessment

Yes, source-level. Current main has a focused `context_engine` pre-model stall regression, and the PR diff shows that same phase being reclassified out of the short watchdog; the provider precedence issue is reproducible by inspecting the new `zhipu` early return before baseUrl/model-prefix checks.

## Solution Assessment

No. The Zhipu exception is plausible but ordered too broadly, and the cron change removes the existing pre-model protection instead of proving a narrower false-timeout fix.
