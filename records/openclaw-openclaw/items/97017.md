The PR adds a zhipu provider carve-out to the silent-overflow auto-compaction guard and reclassifies three cron startup phases from pre_execution to execution with regression-test updates.

## Best Possible Solution

## Solution Assessment

No. The zhipu carve-out is too broad because it masks existing endpoint/model detectors, and the cron phase change removes pre-model watchdog coverage that current main intentionally keeps.
