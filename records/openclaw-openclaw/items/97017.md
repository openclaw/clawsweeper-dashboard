## Label Justifications

- `P1`: The PR targets session-context wedging/loss and cron watchdog false timeouts in real agent workflows, and the current patch has a blocking session-state regression risk.

## Summary

Keep open. The PR is a focused bug-fix attempt, but it is not merge-ready because the new zhipu exception overrides existing explicit z.ai endpoint/model signals and the submitted proof is unit/CI-only rather than real after-fix behavior.

## What This Changes

The PR excludes provider `zhipu` from silent-overflow detection, moves three cron watchdog startup phases from pre-execution to execution, and updates related regression tests.

## Best Possible Solution

Keep the narrow bug-fix direction, but make the zhipu carveout apply only to the bare `glm-*` fallback after explicit z.ai endpoint and namespace checks, then add redacted real runtime proof for both affected behaviors.

## Reproduction Assessment

Yes, at source level. Current main flags provider `zhipu` with bare `glm-*` and maps the three cron phases as `pre_execution`; the PR finding is also source-reproducible because the new early return bypasses existing `api.z.ai` and `z-ai/...` checks.

## Solution Assessment

No. The zhipu bare-GLM carveout is plausible, but the current implementation is too broad because it overrides explicit z.ai route signals that current main deliberately treats as session-state protection.
