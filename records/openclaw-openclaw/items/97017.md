## Summary

Keep this PR open, but it is not merge-ready. The cron change regresses the current isolated cron pre-model watchdog behavior, and the zhipu change bypasses explicit z.ai endpoint/model evidence that current main treats as authoritative for the silent-overflow compaction guard.

## What This Changes

This PR exempts zhipu-labeled GLM models from silent-overflow detection and remaps cron watchdog model/auth/context phases from pre-execution to execution, with focused test updates.

## Best Possible Solution

Keep explicit z.ai endpoint and z-ai model-prefix detection authoritative, narrow any zhipu exemption to the bare glm-* fallback only, and preserve the current pre-model watchdog coverage for model_resolution/auth/context_engine unless an equivalent first-model-call guard replaces it.

## Reproduction Assessment

Yes, at source level. Current main's watchdog map and regression test show context_engine is intentionally covered by the pre-model timeout, while the PR diff moves that phase to execution and rewrites the regression away from context_engine.

## Solution Assessment

No. The PR is a plausible attempt, but the maintainable fix must preserve stronger existing signals: explicit z.ai endpoint/model evidence for compaction and the pre-model watchdog until a real execution milestone is reached.
