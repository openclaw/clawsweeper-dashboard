## Summary

Keep open, but the current patch is not mergeable: the zhipu exclusion is scoped, but the cron watchdog change removes the merged pre-model stall protection for isolated cron runs that reach model resolution, auth, or context-engine setup and then hang.

## What This Changes

The PR adds a zhipu exclusion to silent-overflow model detection and moves cron model/auth/context phases from pre-execution to execution, with focused regression tests.

## Best Possible Solution

Keep any validated zhipu provider exception narrow, but preserve the existing pre-model watchdog for model_resolution, auth, and context_engine unless a maintainer-approved redesign includes real runtime proof for the new timeout boundary.

## Solution Assessment

No. The zhipu exclusion may be a reasonable narrow fix, but the cron change is not the best fix because it removes the intentionally merged pre-model watchdog instead of isolating a specific spurious-timeout case.
