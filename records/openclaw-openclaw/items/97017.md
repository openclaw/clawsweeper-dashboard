## Label Justifications

- `P1`: The PR targets agent transcript wedging and isolated cron timeout behavior, and the current patch can reintroduce a broken cron workflow for real isolated jobs.
- `merge-risk: 🚨 compatibility`: A new provider-name exception changes behavior for existing configured `zhipu` model refs and can conflict with z.ai route detection.
- `merge-risk: 🚨 session-state`: The silent-overflow guard controls whether embedded auto-compaction can mutate transcript state before a provider request.
- `merge-risk: 🚨 availability`: The watchdog change can make isolated cron stalls consume the full job timeout instead of failing fast.

## Summary

Keep open. The PR is not merge-ready because the cron change drops the existing pre-model stall protection for model resolution, auth, and context-engine phases, while the provider change needs a narrower endpoint-aware exception and real runtime proof.

## What This Changes

The PR adds a `zhipu` exception to silent-overflow model detection and reclassifies three isolated cron watchdog phases from pre-execution to execution, with related regression-test updates.

## Best Possible Solution

Preserve the pre-model watchdog until first model call, make any Zhipu false-positive fix endpoint-aware instead of provider-name-only, and add redacted real runtime proof for both changed behaviors.

## Reproduction Assessment

Yes for the blocking cron regression by source inspection: current main has a regression test that stalls at `context_engine` and expects the watchdog to abort quickly, while this PR moves that phase to `execution` and rewrites the test to a different phase. The provider-risk path is also source-visible because the new `zhipu` return runs before baseUrl and `z-ai/` checks.

## Solution Assessment

No. The cron fix should avoid spurious timeouts without removing pre-model stall coverage, and the provider fix should distinguish first-party non-z.ai Zhipu routes from z.ai endpoints or prefixed models.
