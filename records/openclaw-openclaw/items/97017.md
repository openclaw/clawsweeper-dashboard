## Summary

Keep open. The zhipu compaction change is a plausible focused bug fix, but the cron half regresses the merged pre-model watchdog behavior by moving `model_resolution`, `auth`, and `context_engine` out of the short stall watchdog that was added for the historical isolated cron timeout failure.

## What This Changes

The PR excludes provider `zhipu` from silent-overflow-prone model detection and reclassifies cron `model_resolution`, `auth`, and `context_engine` phases as execution-stage watchdog milestones with test updates.

## Best Possible Solution

Split or rework the PR so the zhipu compaction exception is proven independently, while preserving the shipped cron pre-model watchdog contract for `model_resolution`, `auth`, and `context_engine`.

## Reproduction Assessment

Yes for the blocking cron regression at source level: current main's docs and regression test keep `context_engine` under the pre-model watchdog, while the PR remaps it to `execution`. The zhipu provider behavior still needs real runtime proof beyond unit tests.

## Solution Assessment

No. The zhipu exception may be a narrow fix, but the cron reclassification is not the best fix because it conflicts with the shipped pre-model watchdog contract; preserve that contract and prove the provider-specific change separately.
