## Label Justifications

- `P1`: The PR attempts to fix real agent/cron workflows but currently introduces a likely regression in isolated cron stall handling.
- `merge-risk: 🚨 availability`: The cron diff can make stalled isolated runs occupy the full job timeout instead of failing quickly at the pre-model boundary.
- `merge-risk: 🚨 session-state`: The zhipu diff changes when embedded auto-compaction is disabled for GLM sessions, which can affect transcript growth and recovery behavior.

## Summary

Keep open. The zhipu helper change is plausible, but the cron watchdog change reclassifies phases that current main intentionally keeps under the fast pre-model stall watchdog, so the PR would regress #74803-style isolated cron failures.

## What This Changes

The PR excludes zhipu GLM models from silent-overflow detection and reclassifies cron watchdog model-resolution/auth/context-engine phases as execution while adjusting regression tests.

## Best Possible Solution

Keep the zhipu helper fix only with real runtime proof, and leave cron model_resolution/auth/context_engine under the pre-model watchdog unless a narrower phase boundary is proven.

## Reproduction Assessment

Yes, at source level. Current main has a regression test where an isolated cron run stalls at context_engine and is aborted by the pre-model watchdog; the PR changes that phase to execution, which would clear the fast watchdog before a model call starts.

## Solution Assessment

No. The zhipu exclusion may be a valid narrow fix, but the cron watchdog half is not the best fix because it removes an intentional #74803 guard instead of proving a safer phase boundary.
