Full review comments:

- **[P1] Keep persistence out of the read tool:** `src/agents/sessions/tools/read.ts:205`
  - body: Released OpenClaw already routes canonical inbound references through the shared media loader for explicit image/PDF tools. Persisting a second workspace copy from `read` duplicates that supported path, makes a read-only tool mutate state, and only creates the alias after the agent happens to read the attachment. Remove this side effect and extend the shared loader or a specifically incompatible tool instead.
  - confidence: 0.98
- **[P1] Use the root-scoped safe-write helper:** `src/agents/sessions/tools/read.ts:269`
  - body: This raw destination copy can follow a symlink placed at `media`, `media/inbound`, or the destination filename and overwrite a process-writable file outside the workspace. OpenClaw already fixed this exact staging class by using `writeFileWithinRoot`; any retained staging path must use the same boundary-safe helper with regression coverage.
  - confidence: 0.99
- **[P1] Keep the canonical inbound ID as the filename:** `src/agents/sessions/tools/read.ts:250`
  - body: The staged destination still appends an inferred extension even though subsequent turns retain only the canonical inbound ID. That leaves the agent unable to deterministically map `media://inbound/<id>` to the promised workspace path; preserve the existing ID exactly or return a durable canonical path through the owning media API.
  - confidence: 0.97
- **[P1] Delete only artifacts owned by the disposing session:** `src/agents/sessions/agent-session.ts:863`
  - body: The cleanup call still passes no session identity, so disposing one `AgentSession` can remove directories tracked for other live sessions. Key staged artifacts by session and pass `this.sessionId` into cleanup, or move lifecycle ownership to the inbound-media component that can identify each artifact's owner.
  - confidence: 0.99
