## Summary

This PR is still necessary as a candidate response to the reported RHEL shared-SQLite startup rejection, but it is not safe to merge as written: a plain environment value disables a database-corruption guard without an auditable verification contract for the linked system library.

## What This Changes

The branch adds `OPENCLAW_ASSUME_SYSTEM_SQLITE_WAL_RESET_SAFE=1` as an opt-in bypass for the SQLite WAL-reset version guard on shared-system SQLite builds, with tests that retain rejection for embedded builds.

## Best Possible Solution

Keep the guard fail-closed unless maintainers first define a supported, auditable verification path for distribution backports; then implement that policy narrowly and prove it in the reported UBI/RHEL environment.
