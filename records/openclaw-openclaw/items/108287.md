## Summary

This PR remains necessary for the linked shared-SQLite regression, but its opt-in environment variable bypasses the WAL corruption guard without an auditable way to establish that a particular runtime really contains the distribution backport. The latest completed ClawSweeper review raised that same blocker on this unchanged head, and the PR still has only unit-test evidence rather than a real UBI/RHEL after-fix run.

## What This Changes

The branch adds `OPENCLAW_ASSUME_SYSTEM_SQLITE_WAL_RESET_SAFE=1` to permit a shared-system SQLite runtime below the accepted upstream version lines while retaining rejection for embedded SQLite builds.

## Best Possible Solution

Keep the existing fail-closed version guard unless maintainers choose and document a supportable verification contract for distribution backports; any accepted exception should be auditable, narrowly scoped, tested, and demonstrated on the affected shared-SQLite runtime.
