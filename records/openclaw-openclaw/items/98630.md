## Summary

Keep this PR open, but it is not merge-ready: the reported proxy-capture local-peer gap is real from source, yet the submitted raw `127.` prefix check can misclassify non-loopback hostnames and the external PR has no real behavior proof.

## What This Changes

The PR changes proxy-capture local-peer summary grouping from only `127.0.0.1`/`localhost` to any captured host string beginning with `127.`.

## Best Possible Solution

Parse captured hosts to a hostname/IP literal and reuse the existing loopback IP helper, with focused regression coverage for both `127.0.0.2` and a non-loopback `127.*` hostname.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 only add `127.0.0.1:*` and `localhost:*` to `localPeers`, so `127.0.0.2:11434` is missed; the PR's raw prefix can also be source-reproduced as a false positive for `127.example.com`.

## Solution Assessment

No. This is a plausible fix for the reported example but not the best fix because the codebase already has exact loopback IP parsing and captured hosts are not guaranteed to be IP literals.
