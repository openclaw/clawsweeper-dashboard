## What This Changes

The PR wraps self-hosted provider discovery JSON parsing in a labeled `Error` and adds a mocked malformed-JSON discovery test.

## Best Possible Solution

Merge the helper-level error-labeling patch only after real endpoint-style proof is added or explicitly waived, and make the regression assert the labeled warning or wrapped error so it fails on current main.

## Reproduction Assessment

Yes for the narrow source path: current main decodes bounded discovery bytes and calls a bare `JSON.parse`, so malformed JSON throws a raw parser error before the caller logs it. No high-confidence reproduction was shown for the stronger setup-wizard crash claim because the `/models` caller catches thrown discovery errors and returns `[]`.

## Solution Assessment

Yes, this is an acceptable narrow fix for error labeling: catching at the shared self-hosted discovery helper preserves existing fail-soft callers and improves diagnostics. The safer test shape is to assert the logged or thrown labeled error instead of only the already-existing empty result.
