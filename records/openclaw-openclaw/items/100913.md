Full review comments:

- **[P1] Block disconnect writes before closing the ledger:** `src/acp/server.ts:140-148`
  - body: During shutdown, `gateway.stop()` still reaches `onClose`, which calls `agent.handleGatewayDisconnect()`. With a pending prompt, that arms disconnect reconciliation; the timer path can later call `finishPrompt()` and record a final session snapshot, which goes back through `runOpenClawStateWriteTransaction()` and reopens the shared state DB after this close. This is a late finding on code that was already visible in the prior reviewed head; the fix needs a late-write gate/cancel path or a different owner boundary before closing the DB.
  - late: true
  - confidence: 0.86
- **[P2] Resolve shutdown only after ledger cleanup:** `src/acp/server.ts:147-148`
  - body: This prior shutdown-resolution blocker is still present: the existing `onClose` branch calls `onClosed()` whenever `stopped` is true. If the WebSocket closes before `agent.drain()` settles, `serveAcpGateway()` can resolve before `eventLedger.close()` runs, so callers can observe shutdown as complete while SQLite handles are still open. Route stopped close notification through the same cleanup promise instead of resolving from both places.
  - confidence: 0.89
