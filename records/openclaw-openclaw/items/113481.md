## Summary

This is a distinct, currently unsponsored feature request rather than an established regression. Its notification-only goal partially overlaps the open per-agent budget discussion, but threshold delivery in an agent’s next visible reply needs product direction on accounting accuracy, persistence, and the public configuration contract before implementation.

## What This Changes

Add opt-in per-agent daily text-model spend alerts that accumulate provider costs and append a threshold notification to the agent’s next visible reply.

## System Context

OpenClaw dispatches text-model requests for an agent and already exposes usage information to operators. This proposal would turn those per-call usage facts into durable per-agent daily accounting, evaluate configured thresholds, and surface a non-blocking alert in a later user-visible reply.

## Architecture Diagram

## Best Possible Solution

Choose a single cost-observability design that keeps alerts informational, defines authoritative versus estimated cost labeling, and shares any durable accounting primitive with future budget enforcement without coupling alerts to request blocking.
