## Summary

Keep this PR open, but do not merge it yet: a missing sandbox bridge silently selects the host-side fetch/extract fallback even when the caller supplied a sandbox key, contradicting the claimed fail-closed isolation boundary. The branch also publishes a new plugin SDK contract without visible maintainer direction. Likely related people: `steipete` (medium confidence) and `openclaw/openclaw-secops` (high confidence).

## What This Changes

The PR adds an opt-in `openclaw/plugin-sdk/sandboxed-fetch-runtime` helper and sandbox-exec bridge so plugin tools can fetch and extract untrusted web content inside a calling agent’s Docker sandbox.

## Best Possible Solution

Make a supplied `sandboxExecKey` authoritative: return a structured sandbox-unavailable error when its bridge is absent, retain host fallback only when no key was provided, add regression coverage, and obtain explicit approval for the permanent public SDK surface before merge.
