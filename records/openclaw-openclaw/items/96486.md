## Summary

Keep open for maintainer security/product review: current source and tests do not support the exact arbitrary attacker-origin POST described, but the shipped Host-header fallback is still an intentional dangerous-mode CSRF/DNS-rebinding hardening tradeoff that needs a human security-boundary decision.

## What This Changes

The issue asks OpenClaw to remove or further harden `gateway.controlUi.dangerouslyAllowHostHeaderOriginFallback` for network-exposed Gateway Control UI deployments.

## Best Possible Solution

Maintainers should explicitly choose the permanent security model for this dangerous mode: accept it as documented break-glass behavior, harden it with browser-side CSRF/fetch-metadata defenses, or remove it with compatibility handling.
