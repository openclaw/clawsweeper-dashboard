## Summary

Keep open for maintainer/security decision. Current main rejects the exact mismatched attacker-origin flow as written and already audits exposed Host-header fallback as critical, but the documented break-glass fallback remains a real origin-boundary downgrade that current main has not removed or otherwise fully resolved.

## What This Changes

The issue asks to remove or harden the dangerous Control UI Host-header origin fallback because network-exposed gateways may be exposed to CSRF or DNS-rebinding-style abuse.

## Best Possible Solution

Security owners should decide whether to retire the fallback or keep it only with additional defenses, then update origin tests, audit output, and public docs together.
