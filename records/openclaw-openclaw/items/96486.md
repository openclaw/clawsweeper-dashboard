## Summary

Keep open for maintainer security/product review. Current main and the latest release already reject the simple arbitrary-origin POST described and audit exposed Host-header fallback as critical, but the documented break-glass fallback remains a real origin-boundary policy decision rather than a safe cleanup close.

## What This Changes

The issue asks OpenClaw to remove or harden `gateway.controlUi.dangerouslyAllowHostHeaderOriginFallback` because it may weaken CSRF/origin protection on network-exposed gateways.

## Best Possible Solution

Maintainers should decide whether to explicitly accept the current dangerous-mode model or replace it with a narrower hardening plan such as explicit origins only, canonical public-origin configuration, `Sec-Fetch-Site` checks, or CSRF tokens with migration/docs coverage.
