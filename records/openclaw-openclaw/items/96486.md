## Summary

Keep open for maintainer/security review. Current main rejects the exact arbitrary attacker-origin POST as written because the dangerous fallback still requires the browser Origin host to match the request Host, but the documented Host-header fallback remains an intentional DNS-rebinding/CSRF boundary downgrade with no canonical replacement item.

## What This Changes

The issue asks OpenClaw to remove or further harden the Control UI Host-header origin fallback on network-exposed gateways.

## Best Possible Solution

Maintainers should decide whether to remove the fallback with a compatibility plan, preserve it only with additional defenses such as `Sec-Fetch-Site` or CSRF tokens, or explicitly accept the current audited dangerous-mode model.
