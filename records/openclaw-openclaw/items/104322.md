## Summary

This PR remains necessary because current main still performs single-attempt Feishu message sends. The implementation is focused, upstream-contract-backed, fully green on the reviewed head, and supported by convincing live exactly-once delivery proof; no actionable correctness defect was found.

## What This Changes

The PR adds opt-in transient retries with stable per-operation UUIDs to Feishu message create and reply paths for text, cards, media messages, and initial streaming-card delivery.

## Best Possible Solution

Land the Feishu-owned implementation as reviewed: reuse one UUID only for retries of the same message create or reply operation, keep uploads and Card Kit entity creation single-attempt, and use a fresh UUID for a distinct direct fallback send.
