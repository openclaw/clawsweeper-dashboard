## Summary

This PR remains necessary because current `main` only retries Feishu rate-limit failures, while the branch adds the missing transient transport and server-error recovery. The implementation is well-bounded and strongly proven, with no concrete correctness defect found; keep it open for a Feishu-area review and current-main refresh because it changes message-delivery retry semantics.

## What This Changes

The PR adds bounded transient retries with stable Feishu UUIDs for idempotent message create/reply operations while leaving uploads and Card Kit mutations single-attempt.

## Best Possible Solution

Keep one Feishu-owned helper that retries only UUID-deduplicated create/reply requests, generates a fresh UUID for each distinct logical fallback send, and leaves uploads and other non-idempotent mutations single-attempt.
