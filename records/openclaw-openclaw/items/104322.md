## Summary

Source, tests, the live Feishu proof, and Feishu’s documented UUID de-duplication contract support the patch, but current main still lacks transient create/reply retries and the branch is behind a fast-moving Feishu send path; keep it open for an exact-head refresh and Feishu-area approval of the retry classifier and idempotency boundary.

## What This Changes

Centralizes Feishu message create/reply calls behind a stable-UUID helper and adds opt-in bounded retries for transient transport, timeout, and server failures across text, card, media-message, and initial streaming-card sends.

## Best Possible Solution

Keep one Feishu-owned create/reply helper that generates a fresh UUID per logical send, reuses it across bounded transient retries, preserves distinct UUIDs for fallback sends, and leaves uploads and Card Kit mutations single-attempt, with exact-head regression and live de-duplication proof.
