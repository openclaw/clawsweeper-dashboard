## Summary

This PR remains necessary because current main and the latest release do not recover Feishu create/reply sends from transient transport or server failures. The patch appears correct and well-proven, but its deliberate message-delivery retry boundary needs explicit Feishu-area acceptance before merge.

## What This Changes

Centralizes Feishu message create/reply calls behind a stable-UUID helper, adds opt-in bounded retries for transient failures, and adds regression coverage across direct, reply, media, and streaming-card sends.

## Best Possible Solution

Keep one plugin-owned helper that generates a fresh UUID per logical create/reply, reuses it across bounded transient retries, and leaves uploads plus Card Kit create/update/replace/note/close operations single-attempt.
