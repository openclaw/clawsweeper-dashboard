## Summary

## What This Changes

The PR centralizes Feishu message create/reply calls behind a stable-UUID helper and adds bounded retries for transient transport, timeout, rate-limit, and server failures across text, card, media-message, and initial streaming-card sends.

## Best Possible Solution

Retain one plugin-owned helper that generates a stable UUID per logical create/reply, keep transient retries explicitly opt-in and bounded, leave uploads and Card Kit mutations single-attempt, then refresh onto current main and validate the resulting Feishu delivery paths before merge.
