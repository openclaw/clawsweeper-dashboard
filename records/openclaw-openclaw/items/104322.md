## Summary

This PR remains necessary: current `main` still sends Feishu create/reply operations through the shared request wrapper without transient-network or 5xx retry plus a stable per-send UUID. The submitted approach is narrowly scoped and has strong live duplicate-suppression evidence, but GitHub currently marks the head as conflicting with `main`, so it needs a refreshed exact-merge validation and normal Feishu-owner review before landing.

## What This Changes

Adds idempotent retries for transient Feishu message create and reply failures, reusing one UUID per logical send while leaving uploads and Card Kit mutations single-attempt.

## System Context

The bundled Feishu channel converts agent replies, cards, and uploaded-media references into Feishu message create or reply API calls. This change sits at that outbound delivery boundary, where retry classification and idempotency determine whether users receive one final message after a transient API failure.
