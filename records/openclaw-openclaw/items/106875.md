## Summary

Keep this issue open. Current main appears to have eliminated the released file-backed active-session eviction path by moving isolated cron persistence to guarded SQLite row updates, but the one-shot lifecycle-retry classification remains unsupported by the documented retry taxonomy, and the legacy `*.migrated` cleanup behavior still needs current-main proof or repair.

## What This Changes

Prevent session maintenance from disrupting active cron and hook runs, handle legacy migrated sidecars within cleanup, and retry lifecycle-claim failures instead of permanently disabling one-shot jobs.

## Best Possible Solution

Keep the guarded SQLite session update, classify lifecycle-claim failures through a structured bounded-retry path, and migrate or safely remove legacy `*.migrated` sidecars through the owning doctor/migration flow so steady-state disk budgeting only counts canonical removable artifacts.
