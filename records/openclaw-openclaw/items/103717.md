## Summary

The previous OSC-8 continuation finding was meaningfully addressed, but a cell that begins with a hyperlink can still reopen that link on every wrapped line after the original close, linking plain suffix text or table padding.

## What This Changes

The PR extends terminal table wrapping to tokenize C1 CSI and BEL-, ESC-ST-, or C1-ST-terminated OSC-8 sequences and preserve active hyperlink state across physical wraps.

## Best Possible Solution

Carry leading OSC-8 state into the wrapping state machine instead of unconditionally prepending the opener to every line, then cover a start-of-cell link followed by wrapped plain text for all supported terminators.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. A cell shaped as `${link} after` with enough content to wrap follows a clear current-head path where the opener becomes `prefixAnsi`, its close remains in the core tokens, and the opener is later reapplied to every output line.

## Solution Assessment

No. Closing and reopening active links at physical boundaries is the right approach, but the implementation must incorporate leading hyperlink state rather than treating leading ANSI as an unconditional per-line decoration.
