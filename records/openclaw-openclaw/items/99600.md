## Summary

Keep open: this PR fixes a real outbound recovery gap that is not fully superseded by the merged mid-batch recovery PR, and I found no blocking patch defect in this read-only review. The remaining concern is maintainer review of message-delivery semantics around marking a recovered send before ack and retaining post-send failures as failed diagnostics.

## What This Changes

The PR marks successful recovery sends as `unknown_after_send` before acking, returns commit-hook failures from the hook runner, records failed diagnostic rows for post-send failures, and adds recovery regression tests.

## Best Possible Solution

Land a focused recovery fix that preserves the existing live-send invariant: once recovery has platform-send evidence, keep the entry out of ordinary pending retries and retain only diagnostic state for post-send failures.

## Reproduction Assessment

Yes at source level: current recovery sends, acks, and then runs commit hooks without first persisting `unknown_after_send`, while the PR adds regression coverage for post-send hook and mark failures. I did not run tests because this review was read-only.

## Solution Assessment

Yes, this is the right layer for the fix: recovery should mirror the live-send invariant before acking and should keep sent deliveries out of pending replay without adding a new adapter API. The only maintainer choice is whether a failed diagnostic row is the desired operator-facing record for post-send failures.
