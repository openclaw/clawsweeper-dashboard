## Summary

This PR remains necessary because current `main` still lacks session-grouping export, and the contributor resolved the earlier fallback-span and generated-baseline findings. It is not merge-ready: the remaining P1 finding hashes the routing-stable `sessionKey`, which correlates separate conversations across `/new`, `/reset`, daily reset, and idle rollover, while the supplied terminal output still does not demonstrate a real OTLP exporter or collector receiving the attributes.

## What This Changes

The PR adds an opt-in `diagnostics.otel.sessionAttribute` setting that exports a session-derived SHA-256 digest under three grouping attributes on root run spans, with schema, tests, and documentation.

## Best Possible Solution

Export one opt-in, reset-scoped pseudonymous conversation identifier derived from the active `sessionId` through a shared helper, document its linkability and retention implications accurately, and demonstrate the resulting attributes at a real redacted OTLP collector or backend.
