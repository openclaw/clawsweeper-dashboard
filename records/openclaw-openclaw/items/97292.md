## Summary

Keeping this open: current main and v2026.6.11 can still construct the reported empty Anthropic error `tool_result` payload, and the linked open PR is the active fix candidate. The `maintainer` protected label and open closing PR both make cleanup closure inappropriate.

## What This Changes

Ensure GitHub Copilot Claude replay sends non-empty Anthropic `tool_result.content` when `is_error=true` so affected sessions can continue instead of failing with HTTP 400.

## Best Possible Solution

Review and land or reject https://github.com/openclaw/openclaw/pull/97293; if landing, keep the fix at the Anthropic-compatible provider boundary with regression coverage, then close this issue after merge.

## Reproduction Assessment

Yes. Source inspection shows current main can still pair empty `tool_result.content` with `is_error=true`, and the issue includes redacted provider 400 logs from v2026.6.11; I did not run a live Copilot replay because that requires private credentials and affected session state.

## Solution Assessment

Yes. Normalizing invalid empty error tool results at the Anthropic-compatible payload boundary is the narrowest maintainable fix; the fallback behavior for pinned sessions should be treated as a separate policy follow-up.
