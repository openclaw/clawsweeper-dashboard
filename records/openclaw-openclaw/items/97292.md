## Summary

Keep open: current main and v2026.6.11 still allow the legacy Anthropic provider payload builder to send empty content on an error `tool_result`, this issue has the protected `maintainer` label, and https://github.com/openclaw/openclaw/pull/97293 is the open linked fix path.

## What This Changes

The issue reports that GitHub Copilot Claude replay can send an Anthropic `tool_result` with `is_error=true` and empty content, causing HTTP 400 failures before an assistant reply.

## Best Possible Solution

Land or rework https://github.com/openclaw/openclaw/pull/97293 so Anthropic-bound error tool results are normalized to non-empty content before dispatch, with regression coverage for stored replay cases; handle pinned fallback policy separately if maintainers want that behavior changed.

## Reproduction Assessment

Yes. Source inspection of current main shows the legacy Anthropic provider can return an empty string from `convertContentBlocks` and send it with `is_error: true`; the issue and follow-up comments include matching provider 400 logs from real runs.

## Solution Assessment

Yes for the central bug. A provider-boundary normalization that preserves non-empty tool output and substitutes only empty error content is the narrowest maintainable fix; changing pinned-session fallback behavior is a separate policy decision.
