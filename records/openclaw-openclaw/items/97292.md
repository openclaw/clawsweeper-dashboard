## What This Changes

The issue reports GitHub Copilot Claude replay failures when OpenClaw sends an Anthropic error `tool_result` with empty content, causing provider-side HTTP 400 before the assistant replies.

## Best Possible Solution

Land or reject the linked provider-boundary fix PR, then close this issue only after the chosen non-empty Anthropic error tool-result invariant is merged and verified.

## Reproduction Assessment

Yes. Current-main source can build a `tool_result` with empty content and `is_error: true`, and the issue plus follow-up comments include matching redacted provider 400 logs from real GitHub Copilot Claude sessions.

## Solution Assessment

Yes. A provider-boundary normalization for empty error tool results is the narrowest maintainable fix because it protects replay regardless of which compaction or sanitization path produced the empty content.
