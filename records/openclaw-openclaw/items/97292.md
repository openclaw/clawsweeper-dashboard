## Summary

Keep open: the latest release has the reported Anthropic-compatible `tool_result` payload bug, current `main` still lacks an `is_error`-aware non-empty placeholder guard, and the issue is protected by the `maintainer` label with an open linked fix PR still unmerged.

## What This Changes

The issue asks OpenClaw to stop replaying Anthropic-compatible GitHub Copilot Claude error `tool_result` blocks with `is_error=true` and empty content because providers reject those requests before the assistant can reply.

## Best Possible Solution

Land a rebased provider-boundary guard, or an equivalent maintainer-owned patch, that never sends empty Anthropic error `tool_result` content; then close this issue and track any pinned-fallback policy change separately.

## Reproduction Assessment

Yes. Source inspection shows the Anthropic payload builder still lacks an `is_error`-aware non-empty fallback, and the issue comments include v2026.6.11 provider 400 logs from GitHub Copilot Claude replay.

## Solution Assessment

Yes for the central bug. The best fix is a narrow Anthropic-compatible provider-boundary guard that preserves non-empty output and substitutes a safe placeholder only for empty error results; the pinned-fallback question is a separate policy decision.
