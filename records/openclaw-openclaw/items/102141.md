## Summary

Keep this PR open for revision: the latest head still removes the shipped `after_receive_record` policy from LINE’s advertised adapter contract, and the maintainer discussion requires the acknowledgement boundary to be owned by a canonical reply-lane admission contract rather than a LINE-local callback. The HTTP transcript is useful real-behavior proof, but it does not resolve those compatibility and ownership blockers.

## What This Changes

Changes LINE webhook entrypoints to delay successful acknowledgement until per-event acceptance, adds retryable failure and sequencing behavior, exports callback types, expands tests, and documents webhook redelivery.

## Best Possible Solution

Expose a narrow generic Plugin SDK result that resolves only after the canonical inbound reply lane owns the turn, have every LINE webhook entrypoint aggregate that result per event, retain the shipped ACK policy through an explicit compatibility or deprecation path, and cover delayed failures, multi-event batches, empty verification requests, fresh installs, and upgrades.
