## What This Changes

Stop Memory Core from repeatedly warning when an empty legacy SQLite sidecar at the old memory path is detected after an agent turn.

## System Context

Memory Core indexes agent memory in the per-agent SQLite store while state-migration code scans older sidecar locations for importable legacy indexes. An agent turn and later CLI or gateway startup may therefore interact through the legacy-file detection and warning path.

## Architecture Diagram

flowchart LR
  A[Agent turn] --> B[Memory runtime]
  B --> C[Per-agent SQLite store]
  B --> D[Legacy sidecar path]
  D --> E[State migration scan]
  E --> F{Recognized legacy index?}
  F -->|No| G[Migration warning]
  F -->|Yes| H[Import or archive legacy data]

## Best Possible Solution

Trace the writer of the zero-byte legacy sidecar and the legacy-index detector, then keep runtime state solely in the per-agent store or explicitly treat a zero-byte non-index file as no migration candidate; add a regression test covering an agent turn followed by startup or CLI migration checks.
