## What This Changes

The PR treats blank or whitespace-only `location` values in loose outbound reply payloads as absent, while keeping non-blank malformed locations subject to the existing strict validator.

## System Context

Outbound reply producers provide loose reply payload objects that are normalized before OpenClaw delivers replies through inbound-reply and direct-DM paths. The normalizer turns supported fields into a portable outbound payload, and location validation protects downstream channel delivery from malformed location data.

## Best Possible Solution

Keep the blank-string exception at the loose reply-payload boundary, preserve the shared location normalizer’s strict contract, and land only after a rebased branch shows a redacted real reply delivery with `location: ""` or whitespace.
