## What This Changes

The PR makes blank or whitespace-only `location` values in loose outbound reply payloads behave as absent, while retaining the existing error for nonblank strings and other invalid location values.

## System Context

Loose reply payloads produced by agent and plugin paths are normalized before OpenClaw routes the reply to a direct message or inbound-reply delivery path. The normalizer converts supported fields into the outbound reply shape, where channel delivery consumes the validated location object or no location at all.
