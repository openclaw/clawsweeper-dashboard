## Summary

The latest head still has two merge blockers: pipe-backed inputs are rejected by the regular-file-only helper, and the existing CLI option gains an undisclosed 4 MiB ceiling. The bounded-memory objective is valid and the supplied real CLI proof is convincing for regular and symlinked files, but the patch is not yet compatibility-safe.

## What This Changes

The PR bounds `openclaw agent --message-file` reads at 4 MiB, preserves regular and symlinked files, and adds oversized-file, directory, and symlink regression tests.

## Best Possible Solution

Use a bounded incremental reader that retains regular-file, symlink, FIFO or named-pipe, missing-file, directory, UTF-8, BOM, and empty-input behavior, then state the 4 MiB ceiling in command help and `docs/cli/agent.md`.
