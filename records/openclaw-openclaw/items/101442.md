## Summary

The bounded-read approach addresses the memory-exhaustion problem, but the latest head introduces an undocumented 4 MiB ceiling and rejects previously readable FIFO/process-substitution inputs. The broader related PR is not a safe replacement because it adds separate stdin and validation policies while also changing symlink behavior.

## What This Changes

Caps `openclaw agent --message-file` reads at 4 MiB, preserves directory errors and symlink chains, adds regression tests, and refreshes the plugin SDK export budget.

## Best Possible Solution

Implement a bounded descriptor read that preserves established readable-path behavior, then document the approved size and input-type contract in CLI help and the public agent docs.
