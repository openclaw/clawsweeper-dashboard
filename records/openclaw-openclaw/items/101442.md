## Summary

Keep open: the reviewed head still breaks FIFO and process-substitution message inputs that current behavior accepts, and the new hard ceiling remains undocumented; both are bounded mechanical blockers rather than reasons to close the contribution.

## What This Changes

Bounds `openclaw agent --message-file` reads at 4 MiB, resolves symlink chains before reading, and adds oversized-file, directory, and symlink regression tests.

## Best Possible Solution

Use a byte-bounded streaming reader that preserves regular files, symlink chains, FIFOs, and process-substitution inputs, then document the 4 MiB ceiling in both agent CLI pages and cover each supported input type with focused tests.
