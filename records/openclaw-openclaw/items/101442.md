## Summary

The memory-exhaustion fix is necessary and well-proven, but the current patch still narrows the shipped file-source contract and adds an undocumented 4 MiB rejection threshold. The prior P1 and P2 findings remain unresolved on the current head, so this PR needs a maintainer compatibility decision and contributor follow-up before merge.

## What This Changes

Caps `openclaw agent --message-file` reads at 4 MiB, resolves symlink chains to regular files, preserves directory-specific errors, and adds oversized-file and symlink regression tests.

## Best Possible Solution

Implement one bounded input path that preserves the maintainer-approved shipped source types, stops reading once 4 MiB is exceeded, and documents the ceiling and accepted source contract in the public agent CLI docs.
