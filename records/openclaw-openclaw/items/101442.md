## Summary

Keep open: the unchanged head still introduces a compatibility regression for pipe-backed message paths and adds an undocumented user-visible ceiling; both blockers are narrow and repairable.

## What This Changes

Adds a 4 MiB limit to `openclaw agent --message-file` reads by resolving symlinks and using the regular-file reader, with oversized, directory, and symlink regression coverage.

## Best Possible Solution

Keep the 4 MiB allocation bound, but implement a bounded streaming reader that preserves regular files, symlinks, and existing readable pipe-backed paths where supported, then document the exact ceiling in CLI help and both agent documentation pages.
