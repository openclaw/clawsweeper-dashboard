## Summary

Keep open. The prior symlink blocker is fixed and the patch looks correct, but it changes a shipped CLI input by rejecting `--message-file` files over 4 MiB, so a maintainer should accept that compatibility boundary before merge.

## What This Changes

The PR changes `openclaw agent --message-file` to resolve symlinks, read the final regular file through `readRegularFile` with a 4 MiB cap, and adds oversized-file, directory, and symlink regression tests.

## Best Possible Solution

Land the bounded read with symlink compatibility once maintainers accept the 4 MiB cap and the release-note or docs context for the new limit.
