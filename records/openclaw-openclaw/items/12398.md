## Summary

Keep open. Current main and the latest release still have no cron postcondition contract or equivalent scheduler-owned verifier, and the remaining work is a broad cron runtime/protocol/security design rather than cleanup that can be closed or auto-fixed.

## What This Changes

Request to add deterministic scheduler-owned postcondition checks for isolated agent cron jobs, including retry context and escalation when an agent run ends cleanly but did not achieve its intended outcome.

## Best Possible Solution

Define a maintainer-approved additive cron post-run verification design, then wire typed config/state/protocol support, bounded verifier execution, retry context injection, run-log/UI/CLI/docs projection, and failure-alert integration with explicit security constraints.

## Reproduction Assessment

Yes, for the missing capability: current main has no postcondition fields in cron types/protocol/state and no verifier step after runIsolatedAgentJob. I did not reproduce the reporter's specific production early-termination incident in a live cron run.

## Solution Assessment

Unclear. Deterministic post-run verification is directionally appropriate, but the proposed shell-script CronJob field should not land until maintainers decide the core-contract versus plugin-hook shape and the security model.
