## Label Justifications

## Summary

Keep open: current main and v2026.6.11 still do not provide a cron postcondition contract or equivalent scheduler-owned verifier for successful-looking but incomplete isolated agent turns, and the remaining work is a product/security design item rather than cleanup-closeable stale work.

## What This Changes

The issue requests deterministic post-run postcondition checks for cron jobs so isolated agent outcomes can be verified, retried, and escalated when the intended result was not achieved.

## Best Possible Solution

Add a maintainer-approved additive cron verifier contract with typed persisted results, bounded execution, retry/escalation semantics, and either a safe scheduler-owned runner or a fail-capable plugin adapter for optional verifiers.

## Reproduction Assessment

Yes, at the source-contract level: current main has no postcondition fields, public schema support, or verifier branch between isolated agent completion and state application. The specific production 18-of-50 batch incident was not replayed in this read-only review.

## Solution Assessment

No, not as a raw shell-string field alone. Deterministic post-run verification is the right capability, but the maintainable solution needs a typed, bounded verifier or plugin seam with explicit retry, idempotency, and security semantics.
