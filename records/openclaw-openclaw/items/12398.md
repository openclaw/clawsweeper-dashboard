- `impact:session-state`: The request is about cron run state treating clean isolated session termination as success without verifying the intended task outcome.

## Summary

Keep open: current main and the latest release still lack a cron postcondition contract or equivalent scheduler-owned verifier for successful-but-incomplete isolated agent runs, and the remaining work needs product and security review rather than cleanup closure.

## What This Changes

Add optional cron postcondition checks that run deterministic verification after isolated agent jobs, persist verifier state, and drive retry or escalation from the result.

## Best Possible Solution

Define a maintainer-approved additive cron verifier contract with typed persisted results, bounded execution, retry/escalation semantics, and either a safe scheduler-owned runner or a fail-capable plugin adapter for optional verifiers.

## Reproduction Assessment

Yes, at the source-contract level: current main has no cron postcondition fields, public schema support, or verifier branch between isolated agent completion and state application. The specific production 18-of-50 incident was not replayed in this read-only review.

## Solution Assessment

Unclear as proposed. Deterministic post-run verification is the right capability, but a raw shell-string field is not enough; the maintainable path needs a typed, bounded verifier or plugin seam with explicit retry, idempotency, and security semantics.
