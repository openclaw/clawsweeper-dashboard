- `impact:session-state`: Cron can currently record a clean isolated session termination without a scheduler-owned check that the intended task outcome was achieved.

## Summary

Keep open: current main and the latest release still lack a cron postcondition contract or equivalent scheduler-owned verifier for successful-but-incomplete isolated agent turns. The remaining work is meaningful, but it needs maintainer product and security design before implementation.

## What This Changes

The issue requests an optional cron job postcondition contract that deterministically verifies isolated agent-turn outcomes after each scheduled run, with retry and escalation behavior on verifier failure.

## Best Possible Solution

Add a maintainer-approved additive cron verifier contract with typed persisted results, bounded execution, retry/escalation semantics, and either a safe scheduler-owned runner or a fail-capable plugin adapter for optional verifiers.

## Reproduction Assessment

Yes, at source-contract level: current main has no cron postcondition fields, public schema support, or verifier branch between isolated agent completion and state application. The specific production 18-of-50 incident was not replayed in this read-only review.

## Solution Assessment

No, not exactly as a raw shell-string field. Deterministic post-run verification is the right capability, but the maintainable path needs a typed, bounded verifier or plugin seam with explicit retry, idempotency, and security semantics.
