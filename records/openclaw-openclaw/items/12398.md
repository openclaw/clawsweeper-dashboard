- `P2`: This is a meaningful reliability improvement for scheduled agent workflows, but it is additive product/security design rather than an urgent shipped regression.
- `impact:session-state`: Cron can record a clean isolated session termination while lacking scheduler-owned proof that the intended session outcome was achieved.

## Summary

Keep open: current main and v2026.6.11 still lack a cron postcondition contract or equivalent scheduler-owned verifier for successful-but-incomplete isolated agent cron runs, and the remaining work needs product and security design rather than cleanup closure.

## What This Changes

Request an optional cron postcondition verifier that runs deterministic checks after isolated agent cron jobs, records outcomes, retries with failure context, and escalates on failed checks.

## Best Possible Solution

Define a maintainer-approved additive cron verifier contract with typed persisted results, bounded execution, retry/escalation semantics, and either a safe scheduler-owned runner or a fail-capable plugin seam.

- **Defer to broader verification API:** Keep this issue open but block implementation until maintainers define a shared verification model for cron, outbound messages, and agent-run claims.
