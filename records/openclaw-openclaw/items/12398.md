## Label Justifications

- `P2`: This is a meaningful reliability improvement for scheduled agent work, but it is an additive design item rather than an urgent shipped regression.
- `impact:session-state`: Cron can currently record a clean isolated session termination without a scheduler-owned check that the intended task outcome was achieved.

## Summary

Keep open: current main and v2026.6.11 still lack a cron postcondition contract or equivalent scheduler-owned verifier for successful-but-incomplete isolated agent cron runs, and the remaining work needs product and security design rather than cleanup closure.

## What This Changes

The issue requests an optional cron `postconditions` field that runs deterministic post-run checks, records verifier state, retries with failure context, and escalates after failed verification.

## Best Possible Solution

Add a maintainer-approved cron verifier contract with typed persisted results, bounded execution, retry/escalation semantics, and either a safe scheduler-owned runner or a fail-capable plugin seam for optional verifiers.

Rationale: The source gap is clear, but the proposed shell-based verifier changes command execution, retry, plugin API, persisted state, protocol, and security boundaries that automation should not choose by itself.

Options:

- **Approve bounded scheduler contract (recommended):** Define a typed post-run verifier owned by cron, with explicit command/plugin adapters, timeouts, output caps, redaction, persisted status, retry limits, and failure-alert integration.
- **Add plugin seam first:** Add a fail-capable cron post-run hook that can return pass/fail/retry/escalate decisions while keeping verifier implementation outside core.
- **Defer verification API:** Keep the issue open as a design tracker until maintainers settle a broader agent outcome-verification architecture across cron and outbound hooks.

## Reproduction Assessment

Yes, at source level: current main lacks cron postcondition fields, public schema support, and a verifier branch between isolated agent completion and state application. The specific production 18-of-50 incident was not replayed in this read-only review.

## Solution Assessment

Unclear until product and security review. Deterministic post-run verification is the right capability, but the proposed raw shell-string field should become a typed, bounded scheduler contract or fail-capable plugin seam rather than an ad hoc command hook.
