## Summary

Keep open: current main and v2026.6.11 still lack a cron postcondition contract or equivalent scheduler-owned verifier for successful-but-incomplete isolated agent cron runs, and the remaining work needs product and security design rather than cleanup closure.

## What This Changes

Request an optional cron postconditions contract that deterministically verifies agent-turn job outcomes after execution, then retries or escalates failures.

## Best Possible Solution

Add a maintainer-approved cron verifier contract with typed persisted results, bounded execution, retry/escalation semantics, and either a safe scheduler-owned runner or a fail-capable plugin seam for optional verifiers.

Options:

- **Add plugin seam first:** Add a fail-capable cron post-run hook that can return pass/fail/retry/escalate decisions while keeping verifier implementation outside core.
- **Defer verification API:** Keep the issue open as a design tracker until maintainers settle a broader agent outcome-verification architecture across cron and outbound hooks.

## Solution Assessment

Unclear until product and security review. Deterministic post-run verification is the right capability, but the proposed raw shell-string field should become a typed, bounded scheduler contract or fail-capable plugin seam rather than an ad hoc command hook.
