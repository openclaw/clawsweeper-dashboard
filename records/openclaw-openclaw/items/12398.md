## Label Justifications

- `P2`: This is a meaningful reliability and safety improvement for scheduled agent work, but it is an additive design item rather than an urgent shipped regression or first-run blocker.
- `impact:security`: The requested verifier would execute configured commands and expose cron run/session context to those commands.
- `impact:session-state`: Cron can currently persist a clean isolated session termination without scheduler-owned state proving the intended task outcome was achieved.

## Summary

Keep open: current main still lacks scheduler-owned cron postcondition verification, and existing command cron, failure alerts, and plugin hooks cover adjacent cases but not deterministic post-run verification of an `agentTurn` outcome.

## What This Changes

The issue requests optional cron `postconditions` that run deterministic checks after agent completion, persist verifier state, and convert failed checks into retry or escalation behavior.

## Best Possible Solution

Define a maintainer-approved additive cron verifier contract with typed persisted results, bounded execution, retry/escalation semantics, and either a safe scheduler-owned runner or a fail-capable plugin seam.

- **Defer Verifier API:** Keep this as the specific design tracker until maintainers settle a broader outcome-verification architecture across cron and outbound hooks.
