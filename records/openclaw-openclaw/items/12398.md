## Label Justifications

- `P2`: This is a meaningful reliability improvement for scheduled agent work, but it is an additive design item rather than an urgent shipped regression.
- `impact:session-state`: Cron can currently record a clean isolated session termination without a scheduler-owned check that the intended task outcome was achieved.

## Summary

Keep open: current main and the latest stable release still do not provide a cron postcondition contract or equivalent scheduler-owned verifier for successful-but-incomplete isolated agent turns. The remaining work is a product and security design item, not conservative cleanup.

## What This Changes

Request to add optional cron job postconditions that deterministically verify isolated agent-turn outcomes and trigger retry or escalation after each run.

## Best Possible Solution

Add a maintainer-approved additive cron verifier contract with typed persisted results, bounded execution, retry/escalation semantics, and either a safe scheduler-owned runner or a fail-capable plugin adapter.

## Reproduction Assessment

Yes, at the source-contract level: current main has no cron postcondition fields, public schema support, or verifier branch between isolated agent completion and state application. The specific production 18-of-50 incident was not replayed in this read-only review.

## Solution Assessment

No, not exactly as a raw shell-string field. Deterministic post-run verification is the right capability, but the maintainable path needs a typed, bounded verifier or plugin seam with explicit retry, idempotency, and security semantics.
