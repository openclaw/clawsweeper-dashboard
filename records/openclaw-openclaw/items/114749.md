## What This Changes

The PR centralizes plugin-install source planning and execution, makes Doctor discard pre-ledger managed-worktree rows for later fresh provisioning, and carries plugin metadata from loading into runtime consumers.

## System Context

Plugin installs enter through CLI and chat-command surfaces, are classified into a source plan, then execute through the plugin management service before configuration and install records are committed. Separately, Doctor inspects persisted state and removes obsolete worktree-registry rows so normal worktree use can provision only the current ledger format.
