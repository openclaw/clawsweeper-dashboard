## Summary

Keep open: the patch is directionally correct, but the engine account resolver still returns the original owned object, so inherited `appId` and other fields can influence account selection despite the new ownership invariant. The current-head proof is also limited to a mocked gateway harness and does not demonstrate an actual config-file cleanup path.

## What This Changes

Tightens QQBot account resolution and credential cleanup to ignore prototype-inherited account entries and credential fields, with new logout and credential regression tests.

## Best Possible Solution

Have every QQBot account lookup return an own-enumerable snapshot before any field access, cover inherited `appId` and credential fields across default selection, setup, bridge resolution, and logout, then demonstrate the current head against an installed plugin and a real temporary config file with redacted before/after output.
