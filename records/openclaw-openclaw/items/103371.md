## Summary

This PR remains useful because current main still permits prototype-inherited QQBot account data, but the current head retains the prior blocker: the engine resolver verifies that the account entry is owned, then returns the original object, so direct `appId` reads can still consume inherited fields. The logout-path proof is strong, but the ownership invariant is not yet enforced across the complete setup and resolution surface.

## What This Changes

The PR changes QQBot account resolution, setup mutation, bridge credential lookup, and logout cleanup to ignore prototype-inherited account entries and credential fields, with focused engine and gateway regression coverage.

## Best Possible Solution

Use one canonical QQBot account reader that verifies the entry is owned and returns a shallow own-property snapshot, then cover inherited `appId`, `clientSecret`, and `clientSecretFile` behavior across default selection, account resolution, setup mutation, and gateway logout while preserving normal owned-account writes.
