## Summary

The current PR head still has the prior blocking inconsistency: the engine verifies that the account-map key is owned but then reads fields from the original prototype-bearing account object, so inherited `appId` can still affect default and base account resolution while the bridge uses an own-property snapshot. The real-filesystem logout proof is strong for normal owned credentials, but this remaining P2 defect means the patch is not ready to merge.

## What This Changes

The PR changes QQBot account resolution, setup updates, credential resolution, and logout cleanup to ignore prototype-inherited account entries and credential fields, with focused regression coverage.

## Best Possible Solution

Normalize every owned named-account object to an own-enumerable snapshot at the engine boundary before any field read, retain the bridge snapshot, and add regressions proving standard owned JSON-style accounts still resolve while inherited `appId` and credential fields are ignored.
