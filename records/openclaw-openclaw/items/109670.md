## Summary

This PR addresses a real Parallels diagnostic-tail bug, but it is not ready to merge: it reimplements the UTF-8 boundary decoder already introduced by the merged sibling work, and it still lacks contributor-supplied after-fix runtime proof for the host-server failure path.

## What This Changes

The PR retains Parallels host-server stderr as a byte-bounded buffer and decodes it safely when reporting startup failures, with regression cases for truncated and chunk-split UTF-8 characters.

## Best Possible Solution

Keep the raw-byte accumulation needed for split stream chunks, but decode its retained buffer through the shared UTF-8-tail helper and add a redacted terminal or runtime-log proof from an after-fix host-server startup failure.

## Solution Assessment

No. Retaining raw bytes across stream chunks is the right boundary, but the final decode should reuse the existing shared `decodeUtf8Tail` behavior rather than add a parallel decoder with a second maintenance contract.
