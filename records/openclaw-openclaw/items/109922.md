## Summary

Keep this PR open, but do not merge the current head: the new `operator.questions` scope forces existing paired Control UI clients through a scope-upgrade flow, and the newly advertised question broadcasts still bypass the public SDK normalizer. The implementation otherwise shows substantial design, validation, and web behavior work.

## What This Changes

This PR adds a provider-neutral `ask_user` runtime with Gateway RPCs, a blocking agent tool, structured Control UI cards, native Telegram/Discord/Slack buttons, text-reply answering, documentation, and a public plugin SDK resolver.

## Best Possible Solution

Keep the provider-neutral question runtime, but gate it with an already-shipped operator scope such as `operator.write` unless maintainers deliberately design a paired-device scope migration; then normalize both broadcasts in the public SDK and add redacted live Telegram plus at least one Discord or Slack button-to-resume proof.
