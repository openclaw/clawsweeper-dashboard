## Summary

This remains a useful candidate for https://github.com/openclaw/openclaw/issues/29387, but it changes the documented bootstrap trust boundary: `workspace` currently owns agent instructions, while `agentDir` stores runtime state and credentials. The latest commit resolves session-derived agent identity but does not address the previously reported authority concern, so merge requires an explicit security/product decision and real runtime proof.

Likely related people: `tonywujiang` has high-confidence history on workspace bootstrap resolution; `steipete` has medium-confidence history on the agent-workspace contract and adjacent bootstrap behavior.

## What This Changes

The PR makes bootstrap files from an explicitly configured per-agent `agentDir` override same-named workspace files, including when the agent id must be derived from a session key.

## Best Possible Solution

Keep the configured per-agent workspace as the sole bootstrap authority and add an actionable warning or Doctor recovery when bootstrap-named files are found in `agentDir`; if maintainers intentionally want dual authority, first document the new precedence contract and add upgrade, security, and direct/heartbeat/cron proof.
