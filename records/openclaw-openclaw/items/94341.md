## Summary

This PR is not merge-ready: its new loading branch requires `params.agentId`, but the primary embedded-runner path resolves the session agent without passing it into bootstrap resolution, so the reported gateway flow remains broken. Separately, making `agentDir` a second prompt-authority root needs explicit product and security-boundary approval because current docs define the workspace as the bootstrap source, and the supplied proof is unit-test output rather than a real agent run.

## What This Changes

The PR loads bootstrap files from an explicitly configured `agentDir`, lets those files override same-named workspace files, and suppresses agent-directory `BOOTSTRAP.md` after workspace setup.

## Best Possible Solution

Keep the workspace as the canonical bootstrap authority and add a clear startup or Doctor warning for bootstrap-named files found in `agentDir`; if maintainers intentionally approve agentDir overrides, first resolve the effective session agent in every caller, document precedence and upgrade behavior, add caller-level regression coverage, and provide a redacted live gateway proof.
