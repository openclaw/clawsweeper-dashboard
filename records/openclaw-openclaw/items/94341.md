## Summary

The latest head still conflicts with the established workspace-only bootstrap contract: resolving the session agent ID makes the new path reachable for heartbeat and cron, but does not justify making the per-agent state directory a second, higher-precedence instruction source. The linked issue remains valid, yet this PR should not merge until maintainers choose the permanent authority boundary; the safer supported direction is a warning or Doctor path that directs users to each agent’s configured workspace.

## What This Changes

The PR loads explicitly configured per-agent `agentDir` bootstrap files alongside workspace files, gives `agentDir` copies precedence, and resolves the agent from a session key for background invocations.

## Best Possible Solution

Keep each agent’s configured workspace as the sole bootstrap authority, add a startup or `openclaw doctor` warning for bootstrap-named files found in `agentDir`, point users to `agents.list[].workspace`, and prove the warning with focused tests plus a redacted live multi-agent CLI or Gateway run.
