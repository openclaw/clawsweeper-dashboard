## Summary

Keep open for maintainer review: the patch is source-clean with no blocking code findings and sufficient apply-path proof, but it intentionally changes Skill Workshop update apply from permissive overwrite to fail-closed content-shape validation, so compatibility sign-off is still needed before merge.

## What This Changes

The PR adds an apply-time validator and regression tests so Skill Workshop update proposals reject empty, delta/proposal-note, and identity-swap replacement bodies before overwriting an existing `SKILL.md`.

## Best Possible Solution

Land this service-boundary guard only after maintainers accept the fail-closed compatibility tradeoff, and track revision-bound proposal certificates separately if that stronger invariant is desired.

## Reproduction Assessment

Yes. Source inspection shows current `main` strips proposal frontmatter and writes the update body without content-shape validation, and the PR body includes redacted apply-path proof of the bad draft being rejected after the fix.

## Solution Assessment

Yes, with a maintainer compatibility decision. Putting the guard in `applySkillProposal` is the right shared service boundary for chat, CLI, and Gateway, but the fail-closed heuristic needs owner sign-off because it can block valid-looking update drafts.
