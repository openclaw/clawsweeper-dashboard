## Summary

Keep open: current main and v2026.6.11 still leave the pathless inline `read` image-result case without outbound media, even though current main now preserves already-extracted tool media into final payloads. The linked open PRs are implementation candidates, not merged fixes.

## What This Changes

The issue reports that Feishu auto-replies can drop `read` tool image media between trusted tool-result extraction and the final outbound reply payload.

## Best Possible Solution

Land or sponsor one security-aware generic runtime fix that converts trusted `read` image content into a canonical media URL before channel dispatch, then verify Feishu delivery and keep Feishu fallback leakage tracked separately.
