## Summary

Keep open: the requester-derived delivery direction is useful, but current head still has a blocking session-state/message-delivery bug because it feeds the target its own first reply during ping-pong and then suppresses final announce delivery. It also leaves an unused local in a repo with unused-local checks enabled, and the copied bncr logs are not enough current-head real behavior proof.

## What This Changes

The PR changes `sessions_send` A2A announce target resolution, pre-delivers primary replies to a requester-derived target, skips requester ping-pong rounds, and updates focused A2A tests.

## Best Possible Solution

Keep the non-plugin/requester-target lookup direction, but stop ping-pong after requester direct delivery or use a proven non-deadlocking requester path, remove the unused local, and add current-head redacted Telegram/bncr proof showing exactly one requester-channel delivery with no target duplicate.
