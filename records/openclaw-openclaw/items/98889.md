## Summary

Keep open: the PR improves the syntax-error path, but the new archive guard still archives syntactically valid import-run files that the reader skips because they fail schema normalization, so the migration-safety fix is incomplete.

## What This Changes

The PR changes Memory Wiki legacy import-run reading and doctor archiving to skip malformed JSON files, leave skipped syntax-broken files in place with warnings, and adds reader and doctor regression tests.

## Best Possible Solution

Use the same import-run normalizer or migrated-record set for both read and archive, so only successfully normalized and migrated or already-known records are archived and every skipped file stays recoverable with a warning.

## Reproduction Assessment

Yes from source: current main has an unguarded JSON.parse that rejects the whole legacy read on syntax-broken JSON, and the PR residual is also source-reproducible because valid JSON that fails normalizeMemoryWikiImportRunRecord is filtered out by the reader but passes the new archive guard.

## Solution Assessment

No: guarding the reader and syntax-broken archive case is the right direction, but syntax-only archive validation is too narrow. The best fix is to make archive decisions from the same normalized records or normalizer used by the reader.
