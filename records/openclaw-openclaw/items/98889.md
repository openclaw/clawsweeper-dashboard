The PR changes Memory Wiki legacy import-run file reading to skip unreadable or malformed JSON files and adds a reader-level regression test.

## Best Possible Solution

Preserve or warn on malformed legacy import-run files during doctor migration, and archive only records that were actually parsed and migrated after a mixed valid/malformed vault test passes.

## Reproduction Assessment

Yes from source: current main reads legacy import-run files with an unguarded JSON.parse inside Promise.all, so malformed JSON rejects the whole read. I did not run a write-producing repro because this review is read-only.

## Solution Assessment

No: guarding the reader is the right layer, but the doctor migration also needs to avoid archiving skipped malformed files as migrated. A mixed valid/malformed doctor migration test is the safer proof path.
