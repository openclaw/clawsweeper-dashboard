## Summary

Keep open: this is a focused allowlist bug fix, but it is not merge-ready because Feishu message/reaction reads still fetch the message before the new allowlist check, and the PR has only mocked/unit proof for a security-sensitive channel behavior change.

## What This Changes

The branch adds allowlist checks and regression tests for Microsoft Teams, Feishu, Matrix, and Google Chat read-style channel actions.

## Best Possible Solution

Land a version that preauthorizes the explicit or current Feishu chat before any provider read, keeps a returned-chat mismatch guard as defense in depth, and includes real redacted behavior proof or a maintainer override.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: on current main, Feishu and sibling channel read actions reach provider read calls without target allowlist checks. I did not run live channel credentials, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

No, this is not yet the best fix because the Feishu guard runs after getMessageFeishu has already performed the sensitive provider read. The safer shape is preauthorization from the requested/current chat plus a post-fetch mismatch check.
