  - confidence: 0.92

  - body: When allowlist or disabled mode is enforced and a call supplies only `messageId`, this branch returns before the helper calls `getMessageFeishu`. That provider call is the read boundary this PR is trying to protect, so require an explicit/current chat target before fetching and keep the returned-chat check as defense in depth.
  - confidence: 0.91

  - body: The new allowed-target Teams tests pass `cfg` to `expectSuccessfulAction`, but that helper neither accepts nor forwards `cfg`, which makes check-test-types fail and means those tests would not exercise the configured allowlist. Add cfg to the helper shape and pass it into `runAction`.
