- **[P1] Honor Feishu groupAllowFrom in read authorization:** `extensions/feishu/src/channel.ts:648-649`
  - body: Feishu allowlist mode admits groups through `channels.feishu.groupAllowFrom` or explicit `groups.<chat_id>` entries, but this guard only accepts `hasExplicitFeishuGroupConfig`. Existing configs that use the documented `groupAllowFrom` allowlist will now reject allowed reads and reactions, so the guard needs to reuse the same admission inputs as the inbound path.
  - confidence: 0.91
- **[P1] Reject missing Feishu read context before fetching:** `extensions/feishu/src/channel.ts:665-666`
  - body: In allowlist mode, a `read` or `reactions` call with only an opaque Feishu `messageId` and no explicit/current chat target returns from this precheck and then calls `getMessageFeishu` to discover the chat. That still lets an agent trigger a provider message fetch before any target is authorized, so require an explicit or current chat target before the fetch and keep the returned-chat check as defense in depth.
  - confidence: 0.88
