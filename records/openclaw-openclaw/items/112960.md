## What This Changes

Make Memory Wiki page reads in bridge/shared-search mode resolve existing pages deterministically on the first call, rather than intermittently failing with a path-resolution error that succeeds on retry.

## System Context

The `memory-wiki` plugin exposes `wiki_get` and `wiki_search` to agents, including isolated cron sessions. A lookup is resolved through the bridge/shared-search vault path and filesystem-safe file access before the plugin returns page or search results to the calling agent.

## Architecture Diagram

flowchart LR
  A[Agent or cron session] --> B[wiki_get or wiki_search]
  B --> C[Memory Wiki bridge vault]
  C --> D[Shared search and page lookup]
  D --> E[Safe file-path resolution]
  E --> F[Page or search result]
  E --> G[Transient path-resolution error]

## Best Possible Solution

Trace the current `wiki_get` and `wiki_search` resolution path to the fs-safe result classification, then add a narrowly bounded retry only for verified transient replacement races while preserving hard failures for unsafe path validation; handle dotted lookup normalization as a separately tested contract if it is not already supported.
