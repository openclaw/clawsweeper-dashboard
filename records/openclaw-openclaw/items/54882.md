## What This Changes

The issue requests that verbose/block-streaming Read, Write, and Edit tool summaries show the file path when tool arguments use the `file` alias.

## Best Possible Solution

Settle whether legacy file-path aliases remain supported for display/diagnostics, then land a refreshed current-main PR that updates the active resolver, active embedded handler, metadata, and focused tests together.

## Reproduction Assessment

Yes, source-level. Current main still omits `record.file` from `resolvePathArg()` and from the active read-start path check, so a display/diagnostic path that receives `{ file: ... }` cannot show the requested path detail.

## Solution Assessment

Unclear as a direct fix path. Adding `file` to display is narrow, but current runtime validation now rejects legacy aliases, so maintainers should first decide the alias compatibility contract and then align code and tests.
