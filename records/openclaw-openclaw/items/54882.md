Keep this issue open: current main and the latest release still omit the `file` alias from the central Read/Write/Edit display resolver and the read-start diagnostic guard, and https://github.com/openclaw/openclaw/pull/77312 remains the open implementation candidate. ## What This Changes

Verbose/block-streaming Read/Write/Edit tool summaries should show the file path when raw tool args use the `file` parameter alias.

## Best Possible Solution

Keep this issue open, settle the alias contract, then land or replace https://github.com/openclaw/openclaw/pull/77312 with a current-main fix that aligns the resolver, active handler, OpenClawKit metadata, and focused tests.
