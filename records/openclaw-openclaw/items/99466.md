## Summary

Keep open: current main still has bounded built-in grep and existing exec control-command guardrails, but not the requested protected-root/broad recursive raw shell-search policy; the work is already paired with a live closing PR that should be reviewed or rejected before this issue closes.

## What This Changes

The issue requests runtime and prompt guardrails for raw Codex/OpenClaw shell searches so broad recursive `rg`, `grep`, and `find` over protected roots are blocked or require explicit audited bypass.

## Best Possible Solution

Land a maintainer-approved exec preflight guard that blocks high-confidence protected-root broad searches, updates the model-facing guidance, and makes any bypass/config semantics explicit before closing this issue.

## Reproduction Assessment

No high-confidence live repro was run; intentionally executing broad protected-root searches would repeat the risky behavior. Source inspection does show current main lacks the requested raw shell-search guard while Codex/OpenClaw shell paths can execute raw commands.

## Solution Assessment

Yes, the requested runtime guard plus prompt/tool-description guidance is the right layer because bounded grep alone cannot constrain raw shell exec. The exact default/bypass behavior remains a maintainer product and security decision, now represented by the linked PR.
