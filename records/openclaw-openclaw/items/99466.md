## Summary

Keep open: current main has bounded OpenClaw grep, Codex output caps, and some direct app-server bypass blocks, but it does not yet provide the requested protected-root or broad recursive shell-search policy for raw Codex/OpenClaw shell execution. The related issues are adjacent security/context/tool-policy work, not duplicates of this shell-search guardrail request.

## What This Changes

Request adds configurable protected-root and broad-search guardrails for Codex/OpenClaw raw shell searches, with explicit audited bypass for legitimate forensics.

## Best Possible Solution

Design a narrow Codex/OpenClaw shell preflight policy at the native pre_tool_use and sandbox exec seams that preserves repo-local searches, blocks broad protected-root recursive scans by default, and records explicit bypass reasons for trusted forensic lanes.

## Reproduction Assessment

No live broad-root scan was run in this read-only review, but source inspection shows bounded built-in grep and output caps coexist with shell execution paths that lack the requested protected-root or broad-search policy.

## Solution Assessment

The guardrail direction fits the existing native hook and sandbox exec policy seams, but the default root list, bypass audit shape, and config surface need maintainer product/security decisions before implementation.
