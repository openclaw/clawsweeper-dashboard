## Label Justifications

- `P2`: The feature addresses meaningful repeated latency for advanced large-catalog MCP deployments but does not block baseline OpenClaw use.
- `impact:ux-friction`: Ordinary turns can perform unnecessary MCP transport connections and tools/list calls, adding avoidable latency and operational load.

## Summary

Keep open: current main still catalogs every enabled MCP server whenever bundled MCP is active, so the requested server-subset capability remains missing. Recent work parallelized full-catalog loading and existing `toolsAllow` can skip MCP entirely, but neither provides intent-scoped activation; maintainers should first choose whether existing tool-policy planning or a new API owns that behavior.

## What This Changes

Add request-scoped MCP activation so embedded runs connect and catalog only the MCP servers required for the current task, including an explicit no-MCP mode.

## Best Possible Solution

Extend the existing tool-construction plan to emit a closed, normalized MCP activation mode applied before transport resolution, add targeted single-server cataloging for direct operations, and introduce an independent selector only if a concrete caller cannot express its need through canonical tool policy.
