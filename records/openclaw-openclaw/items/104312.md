## Label Justifications

- `P2`: The full-catalog path can add multi-second latency for MCP-heavy agents, but it affects a limited deployment class and explicit tool policy can already skip all MCP.
- `impact:other`: The concrete impact is avoidable MCP transport activation and catalog latency outside the more specific impact categories.

## Summary

Keep open: current main still supports only all-or-none bundle-MCP activation and catalogs every configured server whenever MCP is reachable. The requested subset capability remains missing, no separate canonical item owns it, and maintainers should choose the single policy owner before implementation.

## What This Changes

Add request-scoped MCP server selection so embedded runs catalog only the servers needed for the current task, including an explicit no-MCP mode.

## Best Possible Solution

Derive an authorized, normalized MCP server subset in the canonical attempt/run policy, pass it as a prepared fact into bundle-MCP materialization, filter configured entries before transport connection, and key catalog reuse by normalized selection while preserving the existing no-MCP fast path.
