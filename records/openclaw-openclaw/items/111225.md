## Summary

Keep this PR open for maintainer review: the feature is useful, but the current implementation can disclose raw watched-session identifiers outside the existing read boundary and has correctness gaps in how it infers active viewers and presence lifecycle.

## What This Changes

Adds optional watched-session keys to gateway presence and Control UI facepiles for identified online users and per-session viewers.

## Best Possible Solution

Project a recipient-authorized, redacted viewer-presence view instead of broadcasting raw subscription keys, define an explicit active-session lifecycle, preserve device connectivity aggregation, and add redacted shared-gateway proof for both authorized and restricted recipients.

- **[P1] Restrict watched session keys to read-authorized recipients:** `src/gateway/server.impl.ts:1249-1253`
  - body: Do not write raw subscription keys into the generic presence snapshot. Presence is delivered to recipients that need not have `operator.read`, so keys such as direct-channel session identifiers can disclose routing metadata outside the existing session-discovery boundary. Add a recipient-scoped or redacted projection before broadcasting.
  - confidence: 0.98
- **[P2] Preserve device connectivity when presence becomes per-connection:** `src/gateway/server/ws-connection/connect-session.ts:121-127`
  - body: Keying all non-node clients by `connId` leaves live and retained disconnect rows for one device. Existing device-oriented presence consumers must reduce those rows so a live connection wins; otherwise reconnects and multi-tab clients can suppress the connectivity transition that refreshes dependent UI.
  - confidence: 0.94
- **[P2] Broadcast identified presence when a client connects:** `src/gateway/server/ws-connection/connect-session.ts:329-333`
  - body: The new footer facepile consumes hello and `presence` events. A directly connected identified Control UI client that never enters chat does not cause peers to receive a connect-time presence snapshot, so it remains absent until another presence mutation occurs. Broadcast after inserting the connection row.
  - confidence: 0.91
- **[P2] Track an active session instead of accumulated subscriptions:** `src/gateway/server.impl.ts:1234-1239`
  - body: The viewer UI treats every retained message subscription as currently watched. Native active-session callers subscribe on navigation without removing the previous subscription, so a user can remain in facepiles for up to 32 sessions they only visited. Add an explicit active-session lifecycle or update clients to unsubscribe before using this data as presence.
  - confidence: 0.95
