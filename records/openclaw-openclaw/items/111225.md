  - body: The new helper writes raw subscribed session keys into the normal presence record, which is broadcast more broadly than session discovery. - **[P2] Preserve device connectivity across per-connection presence rows:** `src/gateway/server/ws-connection/connect-session.ts:121-129`
  - body: Using `connId` for every non-node presence row leaves multiple rows for one device, including retained disconnect rows. Existing device-oriented consumers must reduce those rows so any live connection wins; otherwise reconnect/session-catalog refresh state can become stale. This reiterates the outstanding prior P2 finding.
  - confidence: 0.9
- **[P2] Broadcast presence when an identified connection comes online:** `src/gateway/server/ws-connection/connect-session.ts:323-338`
  - body: The sidebar can render the global facepile from presence events, but a direct non-chat connection needs a connect-time presence broadcast after its row is inserted. Otherwise already-connected clients do not learn about that user until another presence-changing event occurs. This reiterates the outstanding prior P2 finding.
  - confidence: 0.84
- **[P2] Do not equate retained subscriptions with active viewing:** `src/gateway/server.impl.ts:1234-1280`
  - body: The registry projects every retained message subscription into viewer presence. Native clients can subscribe when selecting sessions without unsubscribing the prior key, so users remain shown as viewing prior sessions; introduce an active-view signal or update the relevant subscription lifecycle before presenting it as current viewer state. This reiterates the outstanding prior P2 finding.
