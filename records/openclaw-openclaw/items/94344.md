## Summary

Keep open for maintainer/security review: the patch is focused and has sufficient real behavior proof, but it intentionally expands an existing provider private-network trust flag into the memory embedding runtime path.

## What This Changes

The PR makes OpenAI-compatible memory embeddings derive SSRF policy from the configured provider's `request.allowPrivateNetwork`, adds omitted/false/true regression coverage, and documents the memory config behavior.

## Best Possible Solution

Land the provider-policy inheritance only after maintainers explicitly accept the SSRF boundary and explicit-false upgrade behavior, keeping the focused tests and memory docs aligned with that contract.

## Reproduction Assessment

Yes, by source inspection: current main reads configured provider base URL/API key/headers for OpenAI-compatible embeddings but builds SSRF policy only from `baseUrl`, so provider `request.allowPrivateNetwork` is not honored in this path. I did not run the live private-network repro locally because this review is read-only, but the PR body includes redacted live CLI proof.

## Solution Assessment

Yes as a candidate fix, but not as an autonomous merge: reusing the existing provider request policy is narrower than adding the closed memory-specific knob, yet the SSRF and explicit-false upgrade semantics need maintainer/security acceptance.
