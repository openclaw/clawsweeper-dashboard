## Summary

The patch is technically sound, well tested, and uses the existing provider request-policy boundary rather than adding a competing memory-only setting. It should remain open because inheriting the provider’s three-state private-network policy is an upgrade-sensitive SSRF contract that still needs explicit provider/security-owner approval.

## What This Changes

The PR makes configured OpenAI-compatible memory embeddings inherit provider private-network policy, suppresses local-service probes on explicit denial, adds SSRF regression coverage, and documents the three policy states.

## Best Possible Solution

Use the existing provider request-policy resolver as this PR does, then land the documented and tested three-state behavior only after a provider/security owner explicitly approves omitted exact-origin compatibility, explicit denial, and explicit broad opt-in.
