## Summary

Keep open for maintainer/security review: the patch appears technically coherent and well-proven, but it deliberately extends the existing provider private-network request policy into memory embedding fetches and changes explicit-false upgrade behavior.

## What This Changes

The branch makes OpenAI-compatible memory embeddings derive SSRF private-network policy from the selected configured provider's `request.allowPrivateNetwork`, adds omitted/false/true regression tests, and documents the behavior.

## Best Possible Solution

Land only after maintainers explicitly accept provider-policy inheritance and explicit-false fail-closed behavior as the intended memory embedding trust contract.

## Reproduction Assessment

Yes, at source level: current main routes configured OpenAI-compatible memory embeddings through the generic adapter, but that adapter only builds SSRF policy from the base URL hostname and does not consume provider `request.allowPrivateNetwork`. I did not run a live private endpoint in this read-only review.

## Solution Assessment

Yes for the implementation shape: reusing the existing provider request-policy surface is narrower than adding a memory-only knob and matches current model-provider transport semantics. The remaining question is maintainer/security acceptance of that trust boundary and upgrade behavior.
