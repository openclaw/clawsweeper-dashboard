## Summary

## What This Changes

The PR makes the OpenAI-compatible memory embedding client derive SSRF policy from configured provider `request.allowPrivateNetwork`, adds omitted/false/true regression tests, and documents the memory config behavior.

## Best Possible Solution

Land this provider-policy path only after maintainer/security acceptance of the SSRF boundary and explicit-false upgrade behavior; otherwise keep memory embeddings strict and replace it with a product-approved trust contract.

## Reproduction Assessment

Yes for the source-level path: current main routes configured OpenAI-compatible memory embeddings into the generic adapter, and that adapter only builds exact-host SSRF policy from `baseUrl`. I did not run a live private endpoint repro in this read-only pass.

## Solution Assessment

Yes as a code direction, pending maintainer/security acceptance: it reuses the existing provider request policy instead of adding memory-only config and covers omitted/false/true states. If maintainers reject inheritance, the safer alternative is to keep memory strict and define a separate approved trust contract.
