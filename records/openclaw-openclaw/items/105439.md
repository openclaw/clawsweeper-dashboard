## Summary

Keep open: the shared helper’s documented local-path behavior is reproducibly host-dependent on current main and the latest stable release, with a narrow repair and regression path available.

## What This Changes

Make `getFileExtension` interpret Windows and POSIX path separators consistently regardless of the host operating system.

## Best Possible Solution

Use a local-path extension parser that accepts both slash styles, likely `path.win32.extname`, while preserving the existing URL decoding branch and adding cases for dotted directories, extensionless basenames, normal Windows extensions, and POSIX paths.
