## Summary

Keep open: current main and v2026.6.11 still deny Feishu slash-command authorization when access groups are enabled and no command authorizer is configured, and the linked repair remains open/unmerged with shared authorization semantics needing maintainer choice.

## What This Changes

This issue asks for Feishu group-chat slash commands such as `/new`, `/status`, and `/model` to execute or at least reach the agent as normal text instead of disappearing as empty-content events.

## Best Possible Solution

Land or replace the linked command-authorization repair with an explicit approved contract for unconfigured command allowlists, plus Feishu group regression coverage for `/new`, `/status`, and `/model`.

Yes, at source level: current main denies access-groups-enabled command authorization when no authorizer is configured, and Feishu group handling forwards that result into inbound context. I did not run a live Feishu workspace reproduction.
