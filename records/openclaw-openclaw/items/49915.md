## Summary

Keep open: current main and v2026.6.11 still have a source-level Feishu slash-command gap. Group command authorization with no configured command allowlist remains denied, Feishu feeds that result into inbound command access, and the related open PRs are either unmerged or intentionally do not cover the stateful commands named here.

## What This Changes

The issue asks OpenClaw to make Feishu group slash commands such as `/new`, `/status`, and `/model` work, or at least deliver those messages to the agent as normal text.

## Best Possible Solution

Maintainers should choose the canonical Feishu text-command authorization and CommandTurn contract, then land or replace the linked repair with focused Feishu group coverage for `/new`, `/status`, and `/model`.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 still deny access-groups-enabled command authorization when no command authorizer is configured, and Feishu group handling forwards that result into inbound command access. I did not run a live Feishu workspace reproduction in this read-only review.

## Solution Assessment

No current main implementation fully solves this issue. The linked shared-gating repair is plausible but broad enough to require maintainer policy approval or a narrower Feishu command-turn/authorization repair.
