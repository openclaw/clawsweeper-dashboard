## Summary

Keep open: current main and v2026.6.11 still have a source-reproducible Feishu text-command failure path, and the visible related PR work is either closed unmerged or intentionally narrower than this issue's /new, /model, and group-bound routing problem.

## What This Changes

Feishu group slash commands such as /new, /status, and /model fail or disappear instead of executing or reaching the agent as text.

## Best Possible Solution

Maintainers should choose the canonical Feishu text-command contract, including explicit command-turn metadata and authorization semantics, then land focused coverage for Feishu group /new, /status, and /model with no per-group command allowlist configured.

## Reproduction Assessment

Yes from source, not live: current main still denies control commands when access groups are enabled and no command authorizer is configured, and Feishu feeds that authorization into inbound command context. I did not run a live Feishu group chat reproduction.

## Solution Assessment

Unclear: changing the shared default may fix the reported failure, but because command authorization is security-sensitive, maintainers need to confirm whether no command allowlist should mean allow or deny for Feishu/group text commands.
