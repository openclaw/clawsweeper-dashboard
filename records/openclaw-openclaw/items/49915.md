## Summary

## What This Changes

The issue reports that Feishu group slash commands such as `/new`, `/status`, and `/model` fail and may be dropped as empty-content events instead of executing or reaching the agent as text.

## Best Possible Solution

Maintainers should choose the Feishu slash-command authorization contract, then land a proof-backed fix that covers group and DM `/new`, `/status`, `/model`, and adjacent Feishu text command cases without broadening other channels unintentionally.

Question: Should Feishu slash commands with no explicit command allowlist inherit already-admitted Feishu sender access, or should the shared command-gating helper change for every channel?

Rationale: Both approaches can fix the user symptom, but the shared-helper approach changes the command authorization default for all channels using access groups, while the Feishu-scoped approach needs a clear owner contract for already-admitted Feishu senders.

Likely owner: steipete

Owner confidence: high

Options:

- **Prefer Feishu-scoped inheritance (recommended):** Authorize Feishu text commands for senders already admitted by Feishu DM/group policy when no Feishu command allowlist is configured, while preserving explicit allowlist denial.
- **Approve shared gate change:** Change `resolveCommandAuthorizedFromAuthorizers` globally so all-unconfigured access-group command authorizers are allowed, with cross-channel security and upgrade tests.
- **Keep fail-closed default:** Require explicit command allowlists for Feishu control commands and document the operator action instead of changing runtime defaults.
