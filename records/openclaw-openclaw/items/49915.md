## Summary

Keep open: current main and v2026.6.11 still have the Feishu slash-command path where an empty command allowlist resolves to unauthorized under default access-groups mode, and the open fixing PR has not landed.

## What This Changes

The issue reports that Feishu group slash commands such as /new, /status, and /model do not execute and may be dropped as empty-content events.

## Best Possible Solution

Land a proof-backed fix that either narrowly authorizes Feishu text commands for already-admitted senders with no Feishu command allowlist, or explicitly changes the shared command-gating contract with cross-channel security coverage.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should Feishu slash commands with no explicit command allowlist inherit already-admitted Feishu sender access, or should the shared command gate allow all-unconfigured authorizers under access groups?

Rationale: Both choices can fix the user symptom, but the shared-helper approach changes control-command authorization semantics across channels and should not be selected by cleanup automation.

Likely owner: steipete

Owner reason: The strongest history for the shared command gate and related security-boundary behavior points to this owner for the policy choice.

Owner confidence: high

Options:

- **Prefer Feishu-scoped inheritance (recommended):** Authorize Feishu text commands for senders already admitted by Feishu DM/group policy when no Feishu command allowlist is configured, while preserving explicit allowlist denial.
- **Approve shared helper change:** Change resolveCommandAuthorizedFromAuthorizers globally so an all-unconfigured command-authorizer set is allowed under access groups, with cross-channel security and upgrade tests.
- **Keep fail-closed default:** Require explicit command allowlists for Feishu control commands and document/configure the operator action instead of changing runtime defaults.

## Reproduction Assessment

Yes, at source level: current main still sends Feishu slash-command authorization through an empty command allowlist that resolves to CommandAuthorized=false under default access groups. I did not run a live Feishu workspace in this read-only review.

## Solution Assessment

Unclear until maintainer policy is chosen. A Feishu-scoped fix is the narrowest safer direction, while the open shared-helper PR fixes the symptom but broadens the command authorization boundary across channels.
