## Summary

Keep open: current main and v2026.6.11 still have a source-reproducible Feishu group slash-command path where unconfigured command authorizers resolve to unauthorized, and the linked fork PR remains open and unproven. The broader remaining command-boundary work is also tracked in https://github.com/openclaw/openclaw/issues/79409.

## What This Changes

Feishu group slash commands such as `/new`, `/status`, and `/model` should execute, or at least reach the agent as normal text instead of being swallowed as empty or metadata-only events.

## Best Possible Solution

Land or replace the linked repair with an explicit maintainer-approved command-authorization default and focused Feishu group coverage for `/new`, `/status`, and `/model`, coordinated with https://github.com/openclaw/openclaw/issues/79409.

## Reproduction Assessment

Yes. Source inspection shows `useAccessGroups=true` with no configured authorizer resolves unauthorized, Feishu group messages pass that into `CommandAuthorized`, and the reply runner drops unauthorized whole-message control commands; I did not run live Feishu.

## Solution Assessment

Unclear. The linked shared-gating change is a plausible fix for the symptom, but it could widen command access across channel callers, so the best fix needs maintainer-approved authorization semantics or a narrower Feishu contract.
