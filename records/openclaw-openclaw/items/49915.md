## Label Justifications

- `P1`: Feishu slash commands are a broken real-user channel control workflow with silent no-reply outcomes.
- `impact:message-loss`: The report and source path show command-only messages can produce no command action and no visible reply.

## Summary

Keep open: current main and the latest release still deny the unconfigured Feishu group command-authorization path, the same-repo fix PR was closed unmerged, and the remaining fix is an authorization-boundary decision rather than a cleanup close.

## What This Changes

The issue asks for Feishu group slash commands such as `/new`, `/status`, and `/model` to either execute as OpenClaw control commands or at least be delivered as normal text instead of being silently lost.

## Best Possible Solution

Land a proof-backed fix that either narrowly authorizes Feishu text commands for already-admitted senders with no Feishu command allowlist, or explicitly changes the shared command-gating contract with cross-channel security coverage.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should Feishu slash commands with no explicit command allowlist inherit already-admitted Feishu sender access, or should the shared command-gating helper change globally for every channel?

Rationale: Both approaches can fix the observed Feishu failure, but the shared-helper approach changes the control-command authorization boundary across channel runtimes and has already been treated as security-sensitive in related PR review.

Likely owner: steipete

Owner reason: This decision sits on the shared command-gating/security boundary where the strongest feature history points to steipete.

Owner confidence: high

Options:

- **Prefer Feishu-Scoped Inheritance (recommended):** Authorize Feishu text commands for senders already admitted by Feishu DM/group policy when no Feishu command allowlist is configured, while preserving explicit allowlist denial.
- **Approve Shared Helper Change:** Change `resolveCommandAuthorizedFromAuthorizers` globally so an all-unconfigured command-authorizer set is allowed under access groups, with cross-channel security and upgrade tests.
- **Keep Fail-Closed Default:** Require explicit command allowlists for Feishu control commands and document or repair the operator setup path instead of changing runtime defaults.

## Reproduction Assessment

Yes, at source level: current main routes Feishu group slash-command authorization through unconfigured command authorizers that deny under default access-groups mode. I did not run a live Feishu tenant in this read-only pass.

## Solution Assessment

Unclear until maintainer policy is chosen. A Feishu-scoped fix is the narrowest safer direction, while a shared-helper fix could be correct only with explicit approval and cross-channel security coverage.
