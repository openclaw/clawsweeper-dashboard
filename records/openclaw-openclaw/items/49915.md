## Summary

Keep open: current main and the latest shipped tag still carry a source-reproducible Feishu text-command authorization path where unconfigured command authorizers deny slash commands, and the nearby open PR work either is a fork candidate that still needs maintainer/proof review or explicitly excludes the stateful commands named here.

## What This Changes

Feishu group slash commands such as `/new`, `/status`, and `/model` should either execute as OpenClaw commands or be delivered as normal text instead of disappearing as metadata-only events.

## Best Possible Solution

Keep this issue open until maintainers choose the Feishu command-authorization contract and land or replace the linked repair with focused Feishu group coverage for `/new`, `/status`, and `/model`.

## Reproduction Assessment

Yes, at source level: current main denies access-groups-enabled command authorization when no command authorizer is configured, and Feishu group handling forwards that result into inbound context. I did not run a live Feishu workspace reproduction.

## Solution Assessment

Unclear: the linked shared-gating change is plausible for the symptom, but it changes authorization semantics beyond Feishu and needs maintainer policy approval or a narrower Feishu-scoped repair.
