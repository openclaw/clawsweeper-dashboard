## Summary

Keep open: current main and the latest release still format bundled session-memory hook filenames and `# Session` headers from the host or `TZ` timezone, while the memory-core auto-flush path already uses `agents.defaults.userTimezone`; switching the shipped session-memory artifact convention needs maintainer product approval.

## What This Changes

The issue asks OpenClaw to respect `agents.defaults.userTimezone` when naming memory files and rendering memory-file timestamps.

## Best Possible Solution

If maintainers approve the behavior, reuse the existing `userTimezone` resolver and timezone date helper in the bundled session-memory hook, keep memory-core auto-flush aligned, and update focused tests/docs without adding a new timezone config knob.

Options:

- **Use existing userTimezone (recommended):** Make the bundled session-memory hook use `agents.defaults.userTimezone` with host fallback, matching memory-core auto-flush behavior and avoiding a new config surface.
- **Keep host-local artifacts:** Document and preserve the current session-memory hook contract that artifacts follow the gateway host timezone.
- **Add dedicated memory timezone:** Introduce a separate memory artifact timezone only if independent control is worth the extra config, docs, and upgrade burden.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: configure `agents.defaults.userTimezone` differently from host `TZ`, trigger the bundled session-memory hook, and the handler still formats the filename/header from host/env timezone rather than config.

## Solution Assessment

Unclear until maintainers decide the product contract. Reusing the existing `userTimezone` helper is the narrowest maintainable implementation if the desired behavior is accepted; adding `memoryFlushTimezone` would need stronger justification because it expands config surface.
