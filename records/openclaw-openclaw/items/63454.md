## Summary

Keep open: current main and the latest release still leave the session-memory filename/header side of the request unresolved, while the pre-compaction memory-flush path is already aligned with `agents.defaults.userTimezone`. The remaining change is product-sensitive because it would change shipped memory artifact naming semantics from host-local time to configured user timezone.

## What This Changes

Request that generated memory file dates and `# Session` headers honor `agents.defaults.userTimezone` rather than UTC or host-local time.

## Best Possible Solution

Maintainers should decide the memory artifact timezone contract; if accepted, reuse the existing configured-timezone helpers for session-memory filename/header generation and update focused tests/docs without adding a new knob unless explicitly approved.
