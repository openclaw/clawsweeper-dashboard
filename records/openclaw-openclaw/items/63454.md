## Summary

Keep open: current main and the latest release still leave bundled session-memory filenames and `# Session` headers on host/TZ-local time, while memory-core auto-flush already uses `agents.defaults.userTimezone`; the remaining work is a product and compatibility decision, not an implemented cleanup close.

## What This Changes

Request memory artifact filenames and headers use configured `agents.defaults.userTimezone`, or a dedicated memory timezone setting, instead of UTC or host-local time.

## Best Possible Solution

Maintainers should decide whether session-memory artifacts join the `userTimezone` contract; if accepted, update the bundled hook, tests, and docs using existing timezone helpers without adding a new config knob unless explicitly approved.

- **Add a dedicated memory timezone contract:** Introduce a separate memory artifact timezone only if maintainers want memory timestamps to differ from prompt/envelope user timezone despite the extra config surface.

## Solution Assessment

Unclear until maintainers confirm the product contract. The narrow technical path is likely to reuse existing configured-timezone helpers in `session-memory`; adding a dedicated memory timezone would need stronger config-surface justification.
