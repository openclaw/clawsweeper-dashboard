## Summary

Keep open: current main and the latest release still only partly address the report. Memory-core auto-flush uses the configured user timezone, but the bundled session-memory hook still derives filenames and `# Session` headers from host or `TZ` local time, so the remaining behavior needs a maintainer product and compatibility decision.

## What This Changes

Request memory artifact filenames and header timestamps to respect `agents.defaults.userTimezone`, or a dedicated memory timezone setting, instead of UTC or host-local time.

## Best Possible Solution

Maintainers should choose one memory-artifact timezone contract: either make session-memory join the existing `userTimezone` behavior and update tests/docs, or intentionally document it as host-local; avoid adding a new memory timezone knob unless that broader config surface is explicitly approved.
