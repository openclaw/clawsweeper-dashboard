## Summary

Keep open: current main still leaves bundled session-memory filenames and headers on host/TZ local time while memory auto-flush uses configured `userTimezone`; docs currently define session-memory as host-local, so this remains a real but product-sensitive timezone contract decision.

## What This Changes

Request that generated memory file dates and `# Session` timestamps respect `agents.defaults.userTimezone` or an explicit memory timezone setting.

## Best Possible Solution

Maintainers should decide whether session-memory artifacts join the `userTimezone` contract; if accepted, reuse the existing configured-timezone helpers in session-memory and update focused tests/docs without adding a new timezone knob unless explicitly approved.
