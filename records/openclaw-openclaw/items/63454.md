## Summary

Keep open: current main still only partly matches the request. Pre-compaction memory flush uses the configured user timezone for canonical daily memory paths, but the bundled session-memory hook still derives dated filenames and `# Session` headers from host or `TZ` local time, so the remaining behavior needs maintainer product and compatibility approval.

## What This Changes

The issue requests memory file filenames and `# Session` headers to respect `agents.defaults.userTimezone`, or an explicitly approved memory-specific timezone setting, instead of UTC or host-local time.

## Best Possible Solution

Maintainers should explicitly decide whether bundled session-memory artifacts join the `userTimezone` contract; if accepted, update the handler, focused tests, and docs without adding a new timezone knob unless that config surface is approved.
