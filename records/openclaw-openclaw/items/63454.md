## Label Justifications

- `P2`: The issue affects memory artifact consistency for users in non-host timezones but does not block setup, first run, or core runtime availability.
- `impact:session-state`: The mismatch affects saved session-memory artifact names and headers, making session chronology drift from the configured user timezone.

## Summary

Keep open: current main and the latest release only partly satisfy the request. The memory-core compaction flush path now derives `memory/YYYY-MM-DD.md` from `agents.defaults.userTimezone`, but the bundled `session-memory` hook still formats its filename, fallback HHMM slug, and `# Session` header from host/TZ local time, so the remaining userTimezone behavior needs maintainer product approval.

## What This Changes

Request that memory artifact filenames and `# Session` timestamps respect `agents.defaults.userTimezone` instead of always using UTC or host-local time.

## Best Possible Solution

Have maintainers decide that session-memory artifacts join the existing `userTimezone` contract; if accepted, reuse current timezone helpers in the handler, update focused tests and docs, and avoid a new timezone knob unless explicitly approved.
