## Summary

Keep open: current main and v2026.6.11 only partially satisfy the request. Memory-core auto-flush now uses `agents.defaults.userTimezone`, but bundled `session-memory` filenames and `# Session` headers still come from host or `TZ` local time, and changing that shipped artifact behavior needs maintainer product approval.

## What This Changes

The issue asks for generated memory filenames and headers to use the configured user timezone instead of UTC or host-local time.

## Best Possible Solution

Maintainers should decide whether memory artifacts join the existing `userTimezone` contract; if accepted, reuse the configured-timezone helpers in `session-memory` and update focused tests/docs without adding a new timezone knob by default.
