## Summary

Keep open: current main and the latest release only partially satisfy the request. Pre-compaction memory flush now uses the configured user timezone, but the bundled session-memory hook still derives filenames and `# Session` headers from the host or `TZ` local timezone, and changing that shipped artifact convention needs maintainer product approval.

## What This Changes

Request that memory artifacts generated by auto-flush/compaction and bundled session-memory use `agents.defaults.userTimezone` for filenames and `# Session` timestamps rather than UTC or host-local time.

## Best Possible Solution

Maintainers should decide the memory-artifact timezone contract; if accepted, update bundled session-memory to reuse existing configured-timezone helpers and refresh focused tests/docs without adding a new timezone knob unless explicitly approved.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: set `agents.defaults.userTimezone` differently from the gateway host `TZ`, trigger bundled session-memory with `/new` or `/reset`, and the handler formats the filename/header from host/TZ rather than config.

## Solution Assessment

Unclear until maintainers confirm the product contract. The narrow technical solution is to reuse existing configured-timezone helpers in `session-memory`; a separate `memoryFlushTimezone` option would add config surface and needs stronger justification.
