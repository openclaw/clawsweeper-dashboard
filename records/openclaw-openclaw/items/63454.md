## Summary

Keep open: current main still only uses the host or `TZ` timezone for bundled session-memory filenames and `# Session` headers, while the auto-flush path already uses `agents.defaults.userTimezone`. The remaining request is valid but changes shipped memory artifact naming semantics, so it needs maintainer product approval rather than an automatic fix PR.

## What This Changes

The issue requests that memory artifact filenames and header timestamps use `agents.defaults.userTimezone` or an explicitly approved memory timezone setting instead of UTC or host-local time.

## Best Possible Solution

Maintainers should decide whether memory artifacts join the `userTimezone` contract; if accepted, update session-memory to reuse the existing configured-timezone helpers and add focused tests/docs without adding a new timezone option by default.
