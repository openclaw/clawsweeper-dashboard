## Summary

Keep open: current main and v2026.6.11 still only partially address the request. Pre-compaction memory flush uses `agents.defaults.userTimezone`, but the bundled `session-memory` hook still names files and writes `# Session` headers from host or `TZ` local time, and current docs describe that as host-local behavior.

## What This Changes

Request memory files written by auto-flush and the bundled session-memory hook to use the configured user timezone for filename dates and header timestamps, or to add a dedicated memory timezone setting.

## Best Possible Solution

Have maintainers define the memory artifact timezone contract; if accepted, reuse existing userTimezone/date-time helpers in bundled session-memory and update focused tests/docs without adding a new config key unless explicitly approved.
