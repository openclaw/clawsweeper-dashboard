## Summary

Keep open: current main and v2026.6.11 still leave bundled session-memory filenames and `# Session` headers on host/TZ-local time, while the memory-core auto-flush path already uses `agents.defaults.userTimezone`. The remaining work is a product decision about the session-memory artifact timezone contract, not a cleanup-safe close.

## What This Changes

Request that memory file filenames and headers use `agents.defaults.userTimezone`, or an explicit memory timezone, instead of UTC or host-local dates.

## Best Possible Solution

Maintainers should define the memory artifact timezone contract; if accepted, reuse the existing configured-timezone helpers in session-memory and update focused tests/docs without adding a new config key unless explicitly approved.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should bundled session-memory filenames and `# Session` headers join the existing `agents.defaults.userTimezone` contract, or should they remain host-local as currently documented?

Rationale: Both behaviors are plausible shipped contracts: host-local is documented and already shipped, while memory-core auto-flush and system prompt behavior already use configured user timezone.

Likely owner: vincentkoc

Owner reason: This person is the clearest current-main history owner for the implicated session-memory handler and docs path.

Owner confidence: high

Options:

- **Use `userTimezone` for session-memory (recommended):** Update session-memory filenames, fallback HHMM slugs, headers, tests, and docs to use the resolved `agents.defaults.userTimezone` with host fallback.
- **Keep host-local session-memory:** Leave runtime behavior unchanged and clarify that session-memory artifacts intentionally follow the gateway host timezone while auto-flush follows user timezone.
- **Add a separate memory timezone:** Introduce a dedicated config surface only if maintainers want memory artifacts decoupled from both host timezone and `userTimezone`.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: set `agents.defaults.userTimezone` differently from the host `TZ`, trigger bundled session-memory on `/new` or `/reset`, and the filename/header still come from host/env timezone.

## Solution Assessment

Unclear until maintainers confirm the product contract. The narrow technical path is to reuse the existing configured-timezone helpers in session-memory; a new `memoryFlushTimezone` config should not be added without explicit approval.
