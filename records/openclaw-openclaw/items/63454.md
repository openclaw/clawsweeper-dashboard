## Summary

Keep open: current main and v2026.6.11 still leave the bundled session-memory hook on host/TZ-local timestamps, while auto-flush memory planning already uses the configured user timezone. The remaining question is a product/compatibility decision about whether shipped session-memory artifact names should change from host-local to `agents.defaults.userTimezone`.

## What This Changes

The issue asks for memory file filenames and `# Session` header timestamps to respect `agents.defaults.userTimezone` instead of always using UTC or host-local time.

## Best Possible Solution

If maintainers accept the contract, update bundled session-memory to use the resolved `agents.defaults.userTimezone` and shared date-time helpers, align focused tests/docs, and avoid a new timezone config knob unless explicitly approved.
