## Summary

Keep open. Current main and the latest release still lack a bulk auth rotation/sync command or a repair path for env-backed API keys shadowed by per-agent auth profiles, and the fix choice changes credential propagation and auth precedence semantics.

## What This Changes

Request to add a bulk auth sync/rotation command, automatic credential sync, warning, or fallback for env-backed API key rotations shadowed by per-agent auth profiles.

## Best Possible Solution

Add an explicit, audited SQLite-backed auth rotation or doctor/status repair path that detects shadowed rotated keys and updates affected auth stores only with clear operator intent.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw solve env-backed API-key rotation shadowing with an explicit operator-controlled repair/warning path, automatic auth-store sync on config/env writes, or runtime fallback after credential failure?

Rationale: Each viable path changes credential copying, auth precedence, or failure recovery across agent stores, which is a security-sensitive auth-provider boundary rather than a mechanical cleanup.

Likely owner: steipete

Owner reason: The strongest current history for the auth resolver, auth CLI surface, SQLite auth persistence, and stale-shadow repair code points to steipete for this credential-boundary choice.

Owner confidence: high

Options:

- **Operator-controlled repair and warning (recommended):** Add doctor/status/models-auth detection plus a user-approved repair for shadowed rotated static keys, keeping credential movement explicit and auditable.
- **Automatic sync on config/env update:** Propagate supported static keys into affected agent auth stores automatically, accepting a larger silent secret-copying blast radius.
- **Runtime fallback after auth failure:** Try env/config credentials after a stored profile fails, accepting a more surprising provider-auth precedence model.

## Reproduction Assessment

Yes, source-level: current main still resolves stored profiles before env/config credentials by default, keeps `REF_SHADOWED` as an audit finding, and lacks a bulk auth sync or repair command. I did not run a live API-key rotation in this read-only review.

## Solution Assessment

Unclear: a sync command, warning, or doctor repair is plausible, but the best fix depends on maintainer/security intent for credential copying, SQLite auth-store updates, and fallback behavior.
