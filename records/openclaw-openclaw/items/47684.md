## Summary

Keep open. Current main still lacks a bulk auth rotation/sync command or inline config-set/models-status warning, while stored auth profiles can still shadow env-backed credentials; the remaining fix needs maintainer auth/security direction rather than an automatic cleanup close.

## What This Changes

Request an auth sync, auto-sync, warning, or fallback workflow for rotating provider API keys across multiple agent auth stores.

## Best Possible Solution

Design an explicit, audited SQLite-backed bulk auth rotation or status/doctor warning path, and avoid fallback-on-401 unless maintainers deliberately choose that security tradeoff.

Question: Which credential-rotation behavior should OpenClaw support for env/config key updates that are shadowed by stored auth profiles?

Rationale: The implementation choice changes credential propagation, auth precedence, stale-secret recovery, and operator visibility, which are security and product-policy decisions rather than a safe automatic fix.

Likely owner: steipete

Owner reason: The strongest history trail for auth precedence and main-store read-through points to this area contributor.

Owner confidence: high

Options:

- **Audited sync or doctor warning (recommended):** Add an explicit SQLite-backed rotation/sync command or `doctor`/status warning that reports affected agents and requires operator intent before changing stored credentials.
- **Auto-sync on config change:** Fan out credential changes automatically when config/env keys change, improving convenience but silently copying secrets across agent stores.
- **Fallback after 401:** Try env/config credentials after a stored profile fails auth, improving recovery but changing precedence and potentially masking stale stored credentials.
