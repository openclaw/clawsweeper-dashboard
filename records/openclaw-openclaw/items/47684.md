## Summary

Keep open: current main and v2026.6.11 still leave real stored auth profiles ahead of env/config-derived credentials and provide only audit/status diagnostics, so the requested rotation sync or warning workflow remains a security-sensitive product decision.

## What This Changes

The issue requests a user-facing way to synchronize rotated provider API keys across per-agent auth stores or warn when config/env credentials are shadowed.

## Best Possible Solution

Design an explicit, audited SQLite-backed auth rotation or doctor/status warning path for shadowed provider env/config credentials, with automatic sync or fallback only if maintainers approve that security boundary.
