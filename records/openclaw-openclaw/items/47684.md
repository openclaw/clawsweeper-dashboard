## Summary

Keep open. Current main and the latest release still do not provide a bulk auth sync/migrate command or an inline shadowing repair path, and the fix choice affects credential propagation, provider auth precedence, and per-agent auth state.

## What This Changes

Request a user-friendly way to rotate or sync provider API keys across agent auth stores when env/config credentials are shadowed by stored auth profiles.

## Best Possible Solution

Design an explicit, audited SQLite-backed auth rotation or doctor/status warning path, and avoid automatic fallback-on-401 unless maintainers intentionally choose that security tradeoff.

## Maintainer Decision

Kind: security_boundary

Question: Should OpenClaw handle env-backed API-key rotation shadowing with an explicit operator-controlled repair/warning path, automatic auth-store sync on config/env writes, or runtime fallback after credential failure?

Rationale: Each viable direction changes credential precedence, secret copying, or failure recovery across agent auth stores, which is auth-provider and security-boundary behavior rather than a purely mechanical bug fix.

Likely owner: steipete

Owner reason: The strongest current history for auth storage, CLI surface, and runtime auth precedence points to this owner for the credential-boundary choice.

Owner confidence: high

Options:

- **Operator-controlled repair and warning (recommended):** Add a doctor/status/models-auth repair path that detects shadowed rotated keys and updates canonical SQLite auth stores only after explicit user action.
- **Automatic sync on config/env update:** Propagate supported static keys into affected agent auth stores automatically, accepting a larger silent secret-copying blast radius.
- **Runtime fallback after auth failure:** Try env/config credentials after a stored profile fails, accepting a more surprising auth precedence model.

Unclear. A sync command or warning path is plausible, but the best fix depends on maintainer/security choice about credential copying, SQLite auth-store updates, shadowing diagnostics, and fallback behavior.
