Keep open. Current main still documents and implements stored auth profiles taking precedence over env-backed provider keys, and there is no bulk auth rotation/sync or audited repair path for shadowed static keys across agent stores.

## What This Changes

Issue requests a user-facing way to rotate env-backed Anthropic API keys across per-agent auth stores, such as sync, repair, warning, or fallback behavior.

## Best Possible Solution

Add an explicit, audited SQLite-backed auth rotation or doctor/status repair path that detects shadowed rotated static keys and updates affected auth stores only with clear operator intent.

- **Runtime fallback after auth failure:** Try env/config credentials after a stored profile fails, accepting a more surprising provider-auth precedence model.
