## Summary

Keep open. Current main and v2026.6.11 still expose credential shadowing only as an audit/status concern, while the requested user-facing auth rotation/sync or shadow-warning workflow remains a security-sensitive product decision rather than completed core behavior.

## What This Changes

Request a user-friendly auth rotation path, warning, or sync behavior so updated Anthropic/API-key env config is not silently shadowed by per-agent auth profiles.

## Best Possible Solution

Design an explicit audited SQLite-backed auth rotation or doctor/status warning path for shadowed provider env/config refs, with focused upgrade tests and no automatic fallback/copy unless maintainers approve that security tradeoff.

- **Operator-controlled repair and warnings (recommended):** Add an explicit CLI/doctor/status path that detects shadowed provider credentials and updates canonical SQLite auth stores only when the user asks for the repair.
- **Automatic sync on config change/reload:** Make config/env key updates propagate to matching agent auth stores automatically, accepting the wider implicit credential-copying behavior after security review.
- **Runtime fallback after auth failure:** Try env/config credentials after a stored profile fails, accepting a precedence change that could mask stale state and alter provider failover behavior.
