## Summary

Keep open. Current main and v2026.6.11 still do not provide a bulk auth sync/migrate command or an inline rotation warning for env-backed key changes, and the remaining fix requires maintainer auth/security direction rather than automatic cleanup closure.

## What This Changes

The issue requests a user-facing way to sync or warn about API key rotation across per-agent auth profile stores.

## Best Possible Solution

Design an explicit, audited SQLite-backed bulk auth rotation or doctor/status warning path, and avoid fallback-on-401 unless maintainers deliberately choose that precedence/security tradeoff.

Rationale: All viable fixes change credential precedence, secret propagation, or stale-auth recovery across agent stores, and repository policy treats auth/config/session state as compatibility- and security-sensitive.

Likely owner: steipete

Owner confidence: high

Options:

- **Operator-controlled repair and warning (recommended):** Add a doctor/status or `models auth` repair path that detects shadowed rotated keys and updates canonical SQLite auth stores only after explicit user action.
- **Automatic sync on write:** Update affected agent auth stores when config env/provider keys change, trading convenience for higher risk of silent secret propagation.
- **Runtime fallback after auth failure:** Try env/config credentials after a stored-profile failure, trading recovery convenience for a more complex and surprising auth precedence model.

Yes, source-level. Current main still lacks a bulk sync/migrate command, keeps paste-token and paste-api-key scoped to one selected agent store, and only exposes shadowing through secrets audit rather than the requested rotation workflow.

Unclear. A sync command or warning path is plausible, but the best implementation depends on maintainer/security choice about credential copying, SQLite store repair, and fallback semantics.
