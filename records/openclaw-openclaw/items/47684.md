## Summary

Keep open. Current main and v2026.6.11 still lack a bulk auth sync/migration or inline repair flow for env-backed API key rotation, and the viable fixes require a credential-precedence/security decision.

## What This Changes

The issue requests an operator-friendly way to rotate Anthropic/env API keys across per-agent auth stores, via sync, warning, or fallback behavior.

## Best Possible Solution

Design an explicit, audited SQLite-backed auth rotation or doctor/status repair path, and avoid automatic fallback-on-401 unless maintainers intentionally choose that security tradeoff.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw handle env-backed API-key rotation shadowing with an explicit operator-controlled repair/warning path, automatic auth-store sync on config/env writes, or runtime fallback after credential failure?

Rationale: Each viable direction changes credential copying, stored-auth precedence, or recovery behavior across agent auth stores, so automation should not choose the security boundary on its own.

Likely owner: steipete

Owner reason: steipete has the strongest recent history on SQLite auth storage and credential resolution semantics touched by this decision.

Owner confidence: high

Options:

- **Operator-controlled repair and warning (recommended):** Add doctor/status/models-auth detection plus an explicit fix path that updates canonical SQLite auth stores only after user confirmation.
- **Automatic sync on config/env update:** Propagate supported static keys into affected agent auth stores automatically, accepting a larger silent secret-copying blast radius.
- **Runtime fallback after auth failure:** Try env/config credentials after a stored profile fails, accepting a more surprising auth precedence model.

## Reproduction Assessment

Yes, source-level. Current main has no bulk auth sync/migrate command, manual auth writes are single-agent scoped, and stored real profiles still outrank env auth outside explicit env-first probe paths.

## Solution Assessment

Unclear. A sync command, doctor/status warning, or fallback path is plausible, but the best fix depends on maintainer/security choice about credential copying, SQLite auth-store updates, shadowing diagnostics, and fallback behavior.
