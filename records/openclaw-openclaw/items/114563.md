- `impact:message-loss`: Immediate submission can send a chat request without the attachment the user selected.

## Summary

This is a current, narrowly described Control UI attachment race with a linked open implementation PR. The issue also carries the protected `maintainer` label, so it requires explicit maintainer handling rather than automated cleanup; it should remain open until the linked fix is reviewed and merged or replaced.

## What This Changes

Prevent Control UI attachments from being omitted on immediate send or moving to a newly selected conversation while their browser read is still pending.

## System Context

The Control UI composer turns pasted, selected, and dropped browser files into attachment payloads before sending a chat request to the Gateway. The attachment-read lifecycle must remain tied to the originating chat pane so send requests contain complete files and late browser callbacks cannot modify another session.
