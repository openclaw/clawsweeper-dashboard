## Summary

This issue remains necessary: current ACPX supports loading a supplied backend session ID, while the generic `sessions_send` path does not distinguish completed resumable one-shots from active non-steerable runs. The documented ACP contract supports resumption, the reporter provides successful Claude and Codex live verification after a local repair, and no merged fix or canonical replacement was found.

## What This Changes

Make ACP follow-up sends resume completed run-mode backend sessions and reject follow-ups to active or non-resumable one-shots.

## Best Possible Solution

At the canonical ACP dispatch boundary, reuse a completed run-mode child's stable backend session ID for the next turn, reject active or metadata-incomplete one-shots with actionable guidance, and preserve persistent-session and non-ACP send behavior with focused regression and live two-provider proof.
