## Summary

Current main does not expose the reported XSS path: the named gateway modules serve Control UI assets rather than rendering plugin fields, while the actual metadata-facing form uses Lit child expressions without an unsafe HTML directive. Lit escapes text bindings, and OpenClaw’s documented trust model also treats installed plugins as trusted code rather than an untrusted content boundary. citeturn568352view1turn359154view0turn382621view0turn301308view0

## What This Changes

Investigate and prevent alleged script execution from plugin manifest metadata displayed in the Control UI.

## Best Possible Solution

Keep plugin metadata in escaped Lit text bindings, validate clickable URL schemes separately, and route any newly demonstrated execution sink through the private GitHub security-advisory process with an exact reproducer.
