## Summary

The PR should remain open but is not merge-ready: write-mode preparation can leave a partially updated candidate after a later step fails, and the standard landing wrapper adds an unguarded merge-commit path that conflicts with the repository’s current `main` history policy. The successful-path validation is substantial, but it does not exercise either blocker.

## What This Changes

Adds coordinated release version/preparation commands, bounded parallel metadata and shrinkwrap generation, cached changelog GraphQL discovery, tracked private-package shrinkwrap management, and an environment-selected merge-commit landing path.

## Best Possible Solution

Make release preparation transactional across every write step, add a real failure-path proof showing the pre-existing tracked worktree is preserved exactly, and remove the merge-commit option from this PR unless a separately approved non-main-only landing contract requires it.
