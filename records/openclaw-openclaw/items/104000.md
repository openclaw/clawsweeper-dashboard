## Summary

Keep this maintainer-owned PR open, but do not merge the current head: the centralized release-preparation direction is sound and well proven on the successful path, while two deterministic release-integrity defects remain in the proposed implementation.

## What This Changes

The PR adds a bounded release-preparation controller, parallelized metadata and shrinkwrap work, cached changelog discovery, version-alignment tooling, managed private-package shrinkwrap updates, and selectable PR merge methods.

## Best Possible Solution

Before landing, make the candidate identity cover every permitted worktree byte or reject untracked inputs, and make the version commit restore all original destinations after any replacement failure.

Full review comments:

- **[P1] Include untracked bytes in the candidate fingerprint:** `scripts/release-prepare.ts:303-316`
  - body: The fingerprint records untracked path names through porcelain status, but `git diff HEAD` contributes no untracked contents. Editing an existing untracked source or package input therefore preserves the same `candidateFingerprint` and default manifest path even though the prepared worktree changed. Reject untracked files or hash their bytes deterministically, and add a regression test for same-path content changes.
  - confidence: 0.98
- **[P1] Roll back version files when the commit phase fails:** `scripts/release-version.ts:129-130`
  - body: If a later `renameSync` fails, earlier destinations have already been replaced and cleanup only removes temporary files. That can leave root and native release metadata on different versions. Restore every destination already changed and add failure-injection coverage proving the original file set remains byte-identical.
  - confidence: 0.96
