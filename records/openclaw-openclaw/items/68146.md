## Summary

Keep open: current main and the latest release still return immediate retryable UNAVAILABLE for startup-gated RPCs, while this PR’s server-side hold is a meaningful but compatibility-sensitive fix that is currently conflicting and needs exact-head proof plus maintainer acceptance.

## What This Changes

This PR adds a Gateway startup barrier that holds startup-gated RPCs until post-attach sidecar readiness or a 20-second timeout, threads it through request context, and adds focused unit tests.

## Best Possible Solution

Refresh the branch, preserve the descriptor-derived gated method set and current live-registry dispatch semantics, then land the bounded server-side wait only if maintainers accept the startup timing tradeoff with exact-head real behavior proof.

## Reproduction Assessment

Yes. ## Solution Assessment

Conditionally yes. A Gateway-owned barrier is the right layer for cached pre-retry clients, but current releases already have client retries, so maintainers must decide whether the residual cached-client hardening is worth the server-side wait tradeoff.
