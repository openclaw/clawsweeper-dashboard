## Summary

Keep open: current main and the latest release still lack the requested WhatsApp pre-built link preview pass-through, the opt-in automatic high-quality preview config/socket option, and a batch send Gateway RPC. The narrow pass-through is dependency-supported, but the automatic fetch and batch RPC parts need maintainer security and protocol direction before implementation.

## What This Changes

The issue requests WhatsApp Web support for caller-supplied link preview payloads, opt-in high-quality preview fetching, and a batch send RPC for multi-message workflows.

## Best Possible Solution

Split the work: add a typed WhatsApp-owned pre-built linkPreview pass-through first, then design automatic preview fetching and batch Gateway sending separately with explicit security and protocol semantics.

## Reproduction Assessment

Yes, by source inspection: current main has no WhatsApp linkPreview input path, no automatic preview-fetching config/socket option, and no send.batch Gateway method while the Baileys contract supports text linkPreview pass-through.

## Solution Assessment

No as one combined implementation: the pre-built preview pass-through is a narrow dependency-supported increment, but automatic URL fetching and batch Gateway sending should be separate maintainer-approved designs.
