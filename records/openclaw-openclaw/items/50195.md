## Summary

Keep open: current main still lacks the WhatsApp pre-built `linkPreview` pass-through, an opt-in automatic Baileys preview-fetch setting, and any `send.batch` Gateway RPC. The narrow pass-through is technically supported by Baileys, but the automatic fetch and batch RPC pieces need maintainer security and protocol direction before implementation.

## What This Changes

The issue requests WhatsApp Web support for caller-supplied link previews, an opt-in automatic link-preview fetch setting, and a batch send RPC to reduce bulk-send overhead.

## Best Possible Solution

Split the request: add a typed WhatsApp-owned pre-built `linkPreview` pass-through first, then design automatic preview fetching and batch Gateway sending separately with explicit security and protocol semantics.

## Reproduction Assessment

Yes, by source inspection rather than live runtime reproduction. Current main lacks a WhatsApp `linkPreview` input path, lacks a preview-fetch config/socket option, and advertises `send` but not `send.batch`.

## Solution Assessment

No as one combined change. The pre-built preview pass-through is a narrow dependency-supported increment, but automatic URL fetching and batch Gateway sending should be separate maintainer-approved designs.
