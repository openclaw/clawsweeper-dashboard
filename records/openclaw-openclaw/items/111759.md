## Summary

Keep this PR open for one narrow correctness repair. The latest commit resolves the previously reported larger-replacement reset case and the supplied terminal runs demonstrate bounded follow reads and rotation handling, but decoding each fixed-size byte chunk independently can corrupt a UTF-8 character split at a 64 KiB boundary before the JSONL record is emitted.

## What This Changes

The PR bounds voice-call diagnostic JSONL tail reads, incrementally emits complete records during follow mode, discards oversized records, and resets follow state when a diagnostic file is truncated or replaced.

## System Context

The voice-call plugin exposes CLI diagnostics that read JSONL logs from disk and print complete records for operators. The tail command turns file bytes into JSON lines, then keeps polling as the log grows or rotates.

## Best Possible Solution

Decode follow-mode bytes with a stateful UTF-8 decoder (or retain incomplete trailing bytes) and add a regression that places a multibyte character across the 64 KiB boundary while preserving the existing bounded-memory and rotation guarantees.

## Reproduction Assessment

Yes, from source: arrange a UTF-8 character so its bytes cross the 64 KiB follow-read boundary, then append the remainder of its JSONL record. Independent per-chunk UTF-8 decoding will replace the split sequence instead of reproducing the original field value.

## Solution Assessment

No; bounded chunking is the right shape, but preserving only a string-level partial record is insufficient for arbitrary UTF-8 bytes. A stateful decoder or trailing-byte carry is the narrow maintainable repair.
