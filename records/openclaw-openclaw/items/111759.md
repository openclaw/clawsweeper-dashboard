## Summary

This PR addresses a real memory-safety problem and includes convincing live CLI proof, but the new reset condition detects only a smaller replacement file. A rotated replacement whose size is already at or beyond the prior offset can retain the old partial record and append it to new-file bytes, so the earlier rotation fix is incomplete.

## What This Changes

The PR changes the voice-call diagnostic tail command to read JSONL files in bounded chunks, retain unfinished records across polls, discard oversized records, and reset follow state after a detected file reset.

## System Context

The bundled voice-call plugin exposes a diagnostic JSONL tail command for operators. The command reads a growing local log file, separates complete JSON records for stdout, and must retain only bounded state while following later file updates.

## Best Possible Solution

Track the followed file’s identity alongside the byte offset and clear pending/discard state when the path resolves to a different file; add a regression where the replacement file is larger than the old offset and begins after an unfinished old-file record.
