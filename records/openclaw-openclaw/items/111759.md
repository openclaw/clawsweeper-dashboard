## Summary

This PR still addresses a real current-main diagnostic-memory problem, and its supplied live CLI proof is strong for the capped initial read. However, it leaves the tail command’s later polling read unbounded, so a large append between polls can still allocate an arbitrarily large buffer; fix that narrow gap, rebase onto current `main`, and rerun checks before merge.

Likely related people: `odrobnik` is a low-confidence routing candidate because the supplied voice-call history identifies the earlier `calls.jsonl` work; feature-history inspection was limited by the read-only terminal sandbox.

## What This Changes

The PR makes voice-call diagnostic commands read only the final 1 MB of a JSONL log at startup, drops a partial leading record, and adds boundary tests for `tail` and `latency`.

## System Context

The voice-call plugin persists diagnostic call records as JSONL and exposes CLI commands that either print recent records continuously or calculate latency summaries. These commands read an operator-selected file and emit parsed records or aggregate metrics to the terminal.

## Architecture Diagram

## Best Possible Solution

Keep the shared bounded initial reader, then make the tail follow loop consume appended bytes in bounded chunks while preserving an unfinished final JSONL record for the next poll; cover a post-start append larger than 1 MB.
