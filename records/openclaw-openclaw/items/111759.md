## Summary

Keep this PR open: the underlying current-main diagnostic commands still read custom JSONL files with `fs.readFileSync`, so the OOM fix remains necessary, but the capped-tail implementation can emit a truncated JSON fragment as a line and the posted direct-module proof does not match the patch’s non-exported helper.

## What This Changes

The PR replaces full-file reads in the voice-call `tail` and `latency` diagnostic commands with a shared synchronous helper that reads at most the final 1 MB of a custom JSONL file.

## Best Possible Solution

Keep the bounded read, discard the incomplete leading JSONL record whenever the read starts after byte zero, add regression coverage for a record crossing the cap boundary, and post redacted after-fix CLI proof from the actual PR head.
