## Summary

Keep this PR open: bounding the diagnostic read is the right direction, but the new helper begins at an arbitrary byte and makes `voicecall tail` emit a truncated JSONL fragment when the 1 MB cutoff lands inside a record. The submitted live-proof snippet also imports a helper that the shown patch does not export, so it does not establish the changed CLI behavior. Likely related people: Peter Steinberger is a low-confidence adjacent project-routing candidate; file-level voice-call history ownership could not be established from the accessible evidence.

## What This Changes

The PR replaces unbounded file reads in voice-call `tail` and `latency` diagnostics with a shared 1 MB JSONL-tail reader.

## Best Possible Solution

Keep the 1 MB bound, but make the helper retain only complete JSONL records at the cutoff, add focused `tail` and `latency` regression coverage for a mid-record boundary, and post redacted terminal proof from the actual CLI commands.

Yes, from source: use a JSONL file larger than 1 MB with the cutoff inside a record, then run the non-default-file `voicecall tail` path; the proposed direct split prints the suffix of that record as a line.

## Solution Assessment

No; the cap is appropriate, but the helper must follow the existing bounded-log reader’s prefix check and discard a partial first record rather than passing arbitrary tail bytes to JSONL consumers.
