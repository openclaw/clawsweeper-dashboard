## Summary

Keep open: current Control UI code intercepts every eligible chat-bubble context menu before checking whether the user has highlighted text, which matches the reported loss of the browser copy menu. The narrow repair is to preserve native context-menu behavior for a non-empty in-bubble selection while retaining Reply and user-message actions when no text is selected.

Likely related people: `vincentkoc` is a low-confidence routing candidate from recent Control UI work; exact ownership of this handler still needs local history confirmation.

## What This Changes

Fix the Control UI so right-clicking selected chat text keeps normal browser copy behavior instead of opening only the custom Reply menu.

## System Context

The Control UI renders Gateway-backed conversation history as chat bubbles. Bubble interactions currently send a right-click through a local message-action handler, which either opens Reply/Rewind/Fork controls or should leave the browser’s text-selection behavior intact.

## Architecture Diagram

flowchart LR
  A[Gateway chat history] --> B[Control UI chat bubble]
  B --> C[User selects text]

  D --> E{Non-empty selection?}
  E -->|Yes| F[Native browser copy menu]
  E -->|No| G[Reply and message actions]
  G --> H[Composer or session action]

## Best Possible Solution

Make the bubble context-menu handler selection-aware: leave a non-empty selection inside the message to the browser, and retain the existing custom message actions only when no selection is active.
