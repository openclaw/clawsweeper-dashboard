## Summary

Keep open: current main and v2026.6.11 still start `sessions_spawn` child tasks without `inputProvenance`, while https://github.com/openclaw/openclaw/pull/47087 is the open, unmerged direct fix candidate. The IdentyClaw plugin comment is useful adjacent signer-lineage context, but it complements rather than replaces the core session-provenance gap.

## What This Changes

Request that child tasks launched via `sessions_spawn` receive inter-session `inputProvenance` with requester lineage and `sourceTool: "sessions_spawn"`.

## Best Possible Solution

Keep this issue as the canonical tracker until https://github.com/openclaw/openclaw/pull/47087 is refreshed and landed, or replaced by the same narrow `spawnSubagentDirect()` provenance plumbing and regression coverage.
