## Summary

Keep this open: current main and v2026.6.11 still start spawned child tasks without `inputProvenance`, and the direct closing candidate at https://github.com/openclaw/openclaw/pull/47087 remains open, draft, and conflicting.

## What This Changes

Request that `sessions_spawn` child tasks receive inter-session `inputProvenance` with `sourceTool: "sessions_spawn"` and requester lineage.

## Best Possible Solution

Refresh and land, or replace, the narrow fix at the `spawnSubagentDirect` child `agent` call while keeping optional cryptographic lineage such as the linked IdentyClaw plugin as a complementary plugin-level layer.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: current main’s `spawnSubagentDirect()` child `agent` params omit `inputProvenance`, while sibling inter-session paths already pass provenance metadata. I did not run a live spawned-subagent scenario in this read-only review.

## Solution Assessment

Yes. The narrow maintainable solution is to reuse the existing `InputProvenance` envelope at the child `agent` boundary with `sourceTool: "sessions_spawn"`, not to add a broader trust or cryptographic lineage system in core.
