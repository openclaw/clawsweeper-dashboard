## Label Justifications

- `P2`: A documented compaction safeguard is disabled for all SQLite-backed sessions on current main, but token-based compaction remains available and the regression has not shipped in the latest release.
- `impact:session-state`: The defect changes transcript-size accounting, compaction timing, and memory-flush behavior for persisted sessions.

## Summary

Exact current main still drops transcript byte size for every SQLite-backed session, so the documented byte-based compaction policy is not enforced after the storage flip. Keep this issue open for an explicit maintainer-owned repair; the latest release predates the regression, but current main would carry it into the next release.

## What This Changes

Restore SQLite transcript byte totals to byte-based preflight compaction and memory-flush guards.

## Best Possible Solution

Make the SQLite branch of `readSessionLogSnapshot` return `readTranscriptStatsSync(marker).sizeBytes` when byte size is requested, retain the intentional lack of legacy usage scanning, and add SQLite-backed regression coverage for both byte-size consumers.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at high confidence from exact current-main source: any valid `sqlite:` session marker yields no byte size, so both downstream numeric byte guards evaluate false. This review did not execute a runtime test because the task is read-only.

## Solution Assessment

Yes, with a slightly broader boundary than the issue wording: using the existing SQL aggregate in the shared snapshot helper is the narrowest maintainable solution and repairs both current byte-size consumers without restoring file-backed runtime behavior.
