## Summary

Keep this PR open, but do not merge it yet: the linked duplicate-registration bug is well supported, while the proposed memo makes runtime artifact selection depend on whichever resolver caller runs first and the available after-fix evidence is test-only.

## What This Changes

The PR adds a process-lifetime memo for each plugin runtime or setup entry path so registry assemblies with different artifact preferences reuse one physical module, with reset hooks and focused tests.

## Best Possible Solution

Select the canonical artifact deterministically at the activating plugin-runtime owner boundary, keep fingerprint and identity lookups side-effect free, couple invalidation to the matching live-runtime lifecycle, and demonstrate the opposite-preference two-assembly path with redacted gateway output.
