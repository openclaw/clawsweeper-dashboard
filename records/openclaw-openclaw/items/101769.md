## Summary

Keep open. Current main and v2026.6.11 still use prefix-based frontmatter detection, so the reported delimiter edge case remains a valid narrow bug.

## What This Changes

The issue requests that Markdown frontmatter parsing treat only whole `---` delimiter lines as metadata fences.

## Best Possible Solution

Tighten the shared frontmatter delimiter check, keep BOM and CRLF handling, update bundle command body stripping to use the same whole-line rule, and add focused regression tests for `---not`, `----`, and valid `---` blocks.

## Repair Work Prompt

Fix the Markdown frontmatter delimiter bug reported in https://github.com/openclaw/openclaw/issues/101769. In `packages/markdown-core/src/frontmatter.ts`, require the opening and closing frontmatter fences to be whole delimiter lines after BOM and CRLF normalization; `---not`, `----`, and similar dash-prefixed text must not parse as metadata. Audit and update `src/plugins/bundle-commands.ts` so command body stripping uses the same delimiter rule instead of its local prefix check. Add focused regression coverage in `packages/markdown-core/src/frontmatter.test.ts` for `---not` and `----` prefixes returning no metadata while valid `---` blocks still parse; add or adjust `src/plugins/bundle-commands.test.ts` if body stripping would otherwise still remove command text. Do not add config options, compatibility shims, broad Markdown parser rewrites, or unrelated docs/changelog changes.
