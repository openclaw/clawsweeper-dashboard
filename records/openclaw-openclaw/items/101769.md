## Summary

Keep open: current main and latest release v2026.6.11 still accept `---` prefixes as frontmatter delimiters, and three open linked pull requests are candidate fixes but none has merged yet.

## What This Changes

The issue reports that Markdown beginning with dash-prefixed text such as `---not` is incorrectly parsed as frontmatter because the parser accepts a `---` prefix instead of a full delimiter line.

## Best Possible Solution

Land one canonical linked pull request that centralizes full-line delimiter recognition for parsing and body stripping, then close the duplicate candidates and this issue after merge.

## Maintainer Decision

## Reproduction Assessment

Yes at source level: current main checks `startsWith("---")` and `indexOf("\n---", 3)`, which accepts `---not` as a fence prefix. I did not run tests or harnesses to keep this review read-only.

## Solution Assessment

Yes, the best fix is a narrow parser and sibling-stripper repair that requires whole `---` delimiter lines plus regression coverage. The issue should stay open until one linked candidate pull request merges.
