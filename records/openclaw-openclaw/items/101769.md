## Label Justifications

- `P2`: This is a normal-priority shared parser bug with limited edge-case blast radius across plugin, hook, skill, and workshop Markdown metadata.
- `impact:data-loss`: The parser and body strippers can silently reinterpret metadata and drop or alter user-authored Markdown body text when the file starts with a non-delimiter dash prefix.

## Summary

Keep open: current main and v2026.6.11 still use prefix-based frontmatter fences, and live GitHub shows three open closing PRs covering the repair path, so this issue should remain canonical until one fix lands.

## What This Changes

Require Markdown frontmatter parsing and related body-stripping paths to treat only whole `---` lines as fences.

## Best Possible Solution

Land one canonical linked PR that makes delimiter detection exact in shared markdown-core and the duplicated stripping helpers, with focused regression coverage for invalid and valid fences.

## Solution Assessment

Yes: centralizing exact delimiter-line detection in markdown-core and reusing it from bundle command/workshop stripping paths is the narrow maintainable fix. Because linked fix PRs already exist, the issue should stay open until one canonical PR lands.
