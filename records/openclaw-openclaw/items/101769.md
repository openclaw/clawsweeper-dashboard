## Label Justifications

- `P2`: This is a normal-priority parser bug with limited edge-case blast radius across plugin command, hook, skill, and metadata Markdown.
- `impact:data-loss`: Prefix-based parsing can silently reinterpret metadata or strip user-authored Markdown body content that begins with non-delimiter dash text.

## Summary

Keep open: current main and the latest release still use prefix-based Markdown frontmatter fence checks, and three open closing PRs are candidates rather than merged fixes.

## What This Changes

The issue asks OpenClaw to treat only whole-line `---` delimiters as Markdown frontmatter fences so dash-prefixed body text like `---not` is preserved.

## Best Possible Solution

Land one canonical fix that uses an exact delimiter-line helper across the shared parser and all active body-stripping/frontmatter callers, including bundle commands, hooks, skills, workshop proposals, and the agent/session helper paths.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level. Current main checks only for a `---` prefix and searches for a `\n---` prefix close, so `---not\nname: nope\n---not\nbody` can enter frontmatter parsing without OS or provider dependencies.

## Solution Assessment

Yes, the requested direction is the best fix shape: tighten delimiter recognition in the shared parser and reuse that rule in sibling strip helpers instead of adding config or caller-specific policy.
