## Summary

Keep open: current main and the latest release still use prefix-based frontmatter fence detection, and the linked open PRs are implementation candidates rather than merged fixes.

## What This Changes

The issue reports that Markdown beginning with non-delimiter `---` prefixes such as `---not` is treated as YAML frontmatter instead of ordinary body text.

## Best Possible Solution

Land one canonical PR that requires whole-line `---` delimiters in the shared markdown-core parser and reuses the same delimiter helper for command, hook, skill, and workshop body-stripping paths.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Source inspection on current main shows the parser accepts `---not` because it checks only a `---` prefix and searches for any later `\n---` prefix.

## Solution Assessment

Yes. The best fix is a narrow shared delimiter contract for exact `---` lines, then replacing duplicated prefix-based stripping code with that shared behavior.
