## Summary

Keep open: current main and the latest release still accept non-delimiter `---` prefixes as frontmatter fences, and three open linked PRs are active candidate fixes rather than merged implementations.

## What This Changes

The issue requests that Markdown frontmatter parsing only treat a whole `---` delimiter line as a metadata fence.

## Best Possible Solution

Land one canonical PR that requires exact delimiter lines in the shared parser and affected strip helpers, then close the remaining duplicate candidate PRs after that merge.
