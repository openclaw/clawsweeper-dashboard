## Summary

Keep open: current main and v2026.6.11 still return and persist realpath-backed `sessionFile` values when the sessions directory is reached through a symlink. The doctor orphan comparison is now canonicalized, but the storage portability half of the report remains, and the open linked fork PR targets that remaining resolver/test work.

## What This Changes

The issue asks OpenClaw to stop persisting realpath-resolved session transcript paths for symlinked state directories so live transcripts are not misclassified as doctor orphans.

## Best Possible Solution

Review and land a narrow resolver change that keeps realpath containment checks but returns and persists caller-visible sessions-dir paths, with the existing doctor canonical comparison coverage retained.

Yes, source-level: with a symlinked sessions directory, current main resolves and persists `sessionFile` through `realBase`. I did not run a live symlinked-home CLI flow in this read-only review.
