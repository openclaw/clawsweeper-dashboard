## Summary

Keep open: current main and the latest release canonicalize doctor orphan comparisons, but the session resolver still returns and persists realpath-backed `sessionFile` values under a symlinked state directory. A live closing-reference PR, https://github.com/BingqingLyu/openclaw/pull/994, is the candidate fix, so this issue should stay open until that PR is reviewed and either merged or closed.

## What This Changes

The issue asks OpenClaw to preserve logical session transcript paths under symlinked state directories and avoid false-positive doctor orphan reports.

## Best Possible Solution

Review and land a narrow resolver fix that uses realpath only for containment checks but returns and persists caller-visible logical session paths, with regression tests for legacy realpath metadata and doctor orphan detection.

## Reproduction Assessment

Yes, source-level: current main computes `realBase` from the sessions directory, returns `path.resolve(realBase, normalized)`, and persists that value through `resolveAndPersistSessionFile()`. I did not run a live symlinked-home CLI flow.

## Solution Assessment

Yes. The best fix is the narrow resolver shape in the open candidate PR: keep realpath-based containment checks, return the logical sessions-dir path, and retain doctor regression coverage without adding configuration or product policy.
