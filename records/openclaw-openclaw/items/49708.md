## Summary

Keep open: current main and v2026.6.11 mitigate the doctor-side false-orphan comparison, but the session resolver still returns and persists realpath-backed `sessionFile` values under a symlinked state directory. A linked fork PR currently uses closing syntax for the remaining resolver/test work, so this issue should remain the canonical tracker until that fix is reviewed, adopted, landed, or explicitly closed.

## What This Changes

Fix symlinked state/session directories so stored `sessionFile` values preserve the logical path and doctor does not misclassify referenced transcripts as orphans.

## Best Possible Solution

Adopt, review, or replace the linked fork PR with an upstream fix that returns logical session paths while retaining realpath containment checks and doctor canonical-comparison coverage, then close this issue after merge.
