## Summary

Keep open: current main and the latest release now canonicalize doctor’s orphan-transcript comparison, but the session path resolver still returns realpath-backed `sessionFile` values for symlinked state directories, and that returned value is persisted. The open linked PR is the right candidate for the remaining resolver and regression-test work, so this issue should not be closed or queued for a duplicate repair branch yet.

## What This Changes

The issue asks OpenClaw to preserve logical symlinked session paths in persisted session metadata and prevent `openclaw doctor` from reporting tracked transcripts as orphans.

## Best Possible Solution

Land or explicitly close the open linked PR that preserves logical symlinked session paths while keeping doctor’s canonicalized orphan comparison as defense-in-depth.

## Reproduction Assessment

Yes. Source inspection shows a symlinked sessions directory is resolved through `realBase` and that result is persisted as `sessionFile`; I did not run the temp-dir repro because this review is read-only.

## Solution Assessment

Yes. The best fix is to preserve the caller-visible logical sessions directory in the resolver, map legacy real paths back to that namespace, and keep the doctor realpath comparison as a safety net.
