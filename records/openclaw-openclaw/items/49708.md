## Summary

Keep open: current main and the latest release mitigate the doctor orphan comparison, but the session resolver still returns and persists realpath-backed `sessionFile` values when the sessions directory is reached through a symlink. An open linked PR, https://github.com/BingqingLyu/openclaw/pull/994, targets the remaining logical-path resolver fix, so this issue should stay open until that candidate is reviewed and either merged or closed.

## What This Changes

The issue reports symlink-resolved session transcript paths causing persisted session paths to lose portability and doctor to report referenced transcripts as orphans.

## Best Possible Solution

Review and land https://github.com/BingqingLyu/openclaw/pull/994 or an equivalent narrow resolver fix that preserves caller-visible session paths while keeping realpath containment checks and the existing doctor orphan comparison coverage.

## Reproduction Assessment

Yes, source-level: with a symlinked sessions directory, current main resolves the transcript path through `realBase` and `resolveAndPersistSessionFile()` persists that value into `sessionFile`. I did not run a live symlinked-home CLI flow in this read-only review.

## Solution Assessment

Yes, the best fix is the narrow resolver change shown by the linked PR: keep realpath-based containment checks, return the logical sessions-dir path, and retain doctor regression coverage. A new config option or broader product decision is not needed.
