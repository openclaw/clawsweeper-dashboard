## What This Changes

The issue reports that `tools.exec.approvalRunningNoticeMs` is documented as a global exec config key but rejected by the strict runtime schema under `tools.exec`.

## Best Possible Solution

Land or replace with a narrow schema repair that moves `approvalRunningNoticeMs` into `ToolExecBaseShape`, updates generated schema artifacts if still required, and keeps strict rejection for unrelated unknown keys.

## Reproduction Assessment

Yes. Source inspection shows global `tools.exec` is parsed by strict `ToolExecSchema`, whose base shape omits the documented key; I did not run a live CLI repro in this read-only review.

## Solution Assessment

Yes. The narrow maintainable fix is to put the existing documented field in the shared exec base schema so global and per-agent config match, rather than changing docs or adding a parallel config path.
