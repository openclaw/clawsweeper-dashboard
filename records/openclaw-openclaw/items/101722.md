- `impact:ux-friction`: A user replying to an agent input prompt can get confusing or wrong answer mapping when answer text is mistaken for keyed syntax.

## Summary

Keep open. Current main still lets delimiter-bearing free-form lines create stray keyed answers, and the linked open fix PR is a candidate but has not merged and was already found too narrow for the full URL/path/time scope.

## What This Changes

The issue asks OpenClaw to harden shared agent user-input parsing so URL-like, path-like, time-like, and config-snippet answers are not corrupted as keyed replies.

## Best Possible Solution

Keep this issue as the canonical tracker until the shared parser fix in https://github.com/openclaw/openclaw/pull/101938 is broadened, tested, reviewed, and merged.

## Reproduction Assessment

Yes at source level: the current parser and a read-only probe show delimiter-bearing lines can create stray keys that override fallback answers when a question id/header/text matches. I did not verify a full live channel or TUI turn.

## Solution Assessment

Yes on repair boundary, but not yet on the active PR's patch shape. The shared helper should be made question-aware or otherwise guarded for all reported delimiter-bearing free-form answers while preserving supported keyed and numbered replies.
