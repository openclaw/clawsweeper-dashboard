- `impact:ux-friction`: A user replying to an agent input prompt can get confusing or wrong answer mapping when delimiter text is mistaken for keyed syntax.

## Summary

Keep open. Current main still runs a permissive delimiter parser over every multi-question reply line before fallback; ordinary bare URLs usually fall back intact, but first-answer time/range text such as `1:30` can be truncated through the numeric key path and the edge has no regression coverage.

## What This Changes

The issue asks to harden `parseKeyedAnswers()` so delimiter-bearing multi-question user-input answers are not mistaken for keyed replies.

## Best Possible Solution

Harden the shared helper so only recognized question keys consume keyed delimiters, then add focused regression tests for delimiter-bearing fallback answers while preserving supported keyed replies.

## Reproduction Assessment

Yes at source level: current main can map a first multi-question answer like `1:30` to `30` because `keyed.get("1")` wins before fallback. I did not establish a full live Codex/Copilot channel reproduction.

## Solution Assessment

Yes, the best fix is in the shared user-input helper. Patching Codex or Copilot separately would duplicate parsing policy and risk drift across harnesses.
