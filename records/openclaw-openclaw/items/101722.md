## Summary

Keep open. Current main still contains the shared parser that can treat delimiter-bearing fallback answer text as keyed syntax when the accidental key matches a question id/header/question or numeric index, and no merged or open follow-up appears to own this exact hardening yet.

## What This Changes

The issue reports that keyed answer parsing in the user input bridge can misclassify delimiter-bearing answer text such as URLs, Windows paths, time strings, and key/value snippets.

## Best Possible Solution

Keep the shared helper, but make keyed parsing question-aware so ordinary fallback answer text with URLs, times, Windows paths, or config snippets remains intact while supported keyed and numbered replies still work.

Required: false

## Reproduction Assessment

No high-confidence end-to-end reproduction yet. Source inspection and a read-only regex probe show a real corruption path when a delimiter-bearing line accidentally matches a question key or numeric selector, but several reported examples only fail in those matching cases.

## Solution Assessment

Yes, shared-helper hardening is the best repair path. Changing only the Codex or Copilot adapters would duplicate parser policy and risk drift across the plugin SDK surface.
