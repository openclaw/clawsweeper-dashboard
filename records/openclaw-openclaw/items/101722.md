## Summary

Keep open. Current main and v2026.6.11 still use the delimiter-first keyed-answer parser; the report overstates some common fallback cases, but there is still a bounded shared-parser hardening and coverage gap.

## What This Changes

The issue reports that the shared agent-harness keyed-answer parser can mistake delimiter-bearing freeform answers for keyed replies and corrupt multi-question user-input answers.

## Best Possible Solution

Keep the shared helper, but make keyed parsing question-aware or delimiter-aware so URL, time, Windows path, and config-snippet answer text stays intact while supported keyed and numeric multi-question replies still work.
