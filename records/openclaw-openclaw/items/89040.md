## Summary

This PR still carries a blocking compatibility bug: the new always-on bootstrap glob walker drops files under explicitly globbed symlinked directories that current main resolves through Node fs.glob. The event-loop-stall mitigation is focused and well evidenced, but the glob parity regression needs repair before maintainer merge review can treat the patch as safe.

## What This Changes

The PR makes embedded-run bootstrap file loading asynchronous, replaces extra-bootstrap glob resolution with a yielding walker, adds bootstrap hook scheduling/timing, and expands focused regression coverage.

## Best Possible Solution

Preserve Node fs.glob parity for symlinked directory patterns, keep the timing/scheduling helpers SDK-internal, then land after maintainers accept the bootstrap hook interleaving tradeoff.

## Reproduction Assessment

Yes for the PR-introduced compatibility bug: current main delegates to fs.glob, and a scratch Node probe shows explicit symlink-directory globs match today. The original event-loop stall is source-reproducible from sync bootstrap reads and blocking glob delegation, but I did not run a connected channel reproduction in this read-only pass.

## Solution Assessment

No, not yet: the async loader and yielding walker are the right direction, but the current patch is not the best fix until it preserves fs.glob symlink-directory parity for existing configs. After that repair, the remaining decision is maintainer acceptance of bootstrap hook interleaving and proof depth.
