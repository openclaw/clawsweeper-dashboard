## Risks / Open Questions

- Replacing Node fs.glob with a custom yielding walker is compatibility-sensitive because bootstrap-extra-files users may observe differences in glob parity, no-match handling, dot-directory traversal, symlink behavior, or traversal ordering despite the added parity tests.
- Returning every configured glob match without a cap preserves context but can still make total bootstrap scan wall time large on huge workspaces; the availability gain is event-loop yielding, not bounded total work.
- Yielding between bootstrap hook handlers changes event-loop interleaving while hooks can mutate bootstrapFiles, so maintainers should explicitly accept the session-context timing tradeoff before merge.
