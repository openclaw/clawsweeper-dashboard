## Risks / Open Questions

- Replacing `fs.glob` with a custom full-tree walker is compatibility-sensitive for existing broad `bootstrap-extra-files` configs; the PR has focused parity tests, but the implementation behind existing patterns changes on upgrade.
- Yielding between bootstrap hook handlers preserves handler order, but it allows other event-loop work to interleave where bootstrap hooks previously ran back-to-back, so hook chains that assumed uninterrupted timing need maintainer acceptance.
- The full walker avoids event-loop stalls but can still spend real I/O time traversing very broad globs on huge workspaces; that availability tradeoff is deliberate because the PR preserves configured matches instead of cutting traversal short.
