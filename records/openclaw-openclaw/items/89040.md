## Summary

Keep open; this is still a useful candidate fix for the linked bootstrap-context event-loop stall, but the current PR head still has a blocking compatibility regression in the custom glob walker. The previous ClawSweeper finding remains valid because the branch still treats symlinked directories as leaf paths, while current Node `fs.glob` descends explicit symlink-directory glob roots.

## What This Changes

The PR replaces synchronous bootstrap file reads and blocking extra-bootstrap glob scans with async/yielding paths, adds bootstrap-context timing, and routes agent bootstrap hooks through an internal yielding dispatcher.

## Best Possible Solution

Land the async/yielding bootstrap mitigation only after the custom walker preserves Node `fs.glob` parity for explicit symlink-directory traversal and keeps workspace-boundary protection covered by regression tests.

## Reproduction Assessment

Yes for the blocking PR defect: a Node v24.18.0 check shows `fs.glob` descends an explicit symlink-directory glob, while PR source inspection shows the walker yields symlinks as leaves. The broader event-loop stall is supported by the linked issue and PR proof but was not rerun end-to-end here.

## Solution Assessment

No: async/yielding bootstrap loading is the right layer, but the submitted walker is not yet the best fix because it changes existing glob semantics for symlinked directories. The safer repair is to preserve `fs.glob` parity while keeping the new yielding behavior and workspace escape checks.
