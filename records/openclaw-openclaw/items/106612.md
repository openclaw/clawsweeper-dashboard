## Summary

Keep this issue open: current main still terminates only the direct host-hook child on timeout, so descendant processes can survive, and no merged fix or canonical replacement owns this runtime path.

## What This Changes

Ensure timed-out, aborted, or gracefully stopped host hooks terminate their complete descendant process trees on Unix and Windows.

## Best Possible Solution

Use the shared platform-aware process-tree utility for host-hook timeout and abort cleanup, track active hook trees through graceful gateway shutdown, and add nested-child regression coverage without introducing a new config option or duplicating taskkill logic.
