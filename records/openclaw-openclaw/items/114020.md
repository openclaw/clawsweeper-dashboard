## Summary

This is a fresh, high-impact channel-dispatch regression report with a concrete failing error and a plausible shared gateway/channel contract boundary. It should remain open until current `main` is checked against the beta build and the lifecycle ownership is traced; bypassing the assertion would risk restoring dispatch without preserving the intended dispatch lifecycle contract.

## What This Changes

The issue requests a repair for Feishu and Telegram inbound dispatches that fail when their prepared turns do not declare the `runDispatchLifecycle` required by the gateway dispatch path.

## System Context

Channel adapters receive inbound platform updates, prepare a turn, and submit it to the gateway’s shared dispatch lifecycle. That lifecycle then runs the agent turn and returns replies for the adapter to deliver back to Feishu or Telegram.

## Architecture Diagram

flowchart LR
  A[Feishu or Telegram inbound update] --> B[Channel adapter]
  B --> C[Prepared inbound turn]
  C --> D[Gateway dispatch lifecycle check]
  D --> E[Agent run and replies]
  E --> F[Channel response delivery]

## Best Possible Solution

Reproduce the beta failure, identify the canonical prepared-turn constructor used by Feishu and Telegram, and make those adapters declare the required lifecycle through the supported shared contract; add regression coverage for both adapters without removing the gateway invariant.
