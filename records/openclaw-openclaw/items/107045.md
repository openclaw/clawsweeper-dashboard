## Summary

The empty scope list is the documented security behavior for a custom operator client that authenticates with a shared token but omits signed device identity; the request must be corrected in the external WebSocket client rather than OpenClaw core.

## What This Changes

Investigate why a WebSocket connect response returns an empty authenticated scopes array despite requested operator scopes.

## Best Possible Solution

Update the Spring Boot client to process `connect.challenge`, persist a stable Ed25519 device key, sign the challenge-bound connect payload, and send the required device identity fields; retain the server’s fail-closed scope clearing.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, from source: an operator connection using shared-token authentication without signed device identity deterministically has its requested scopes cleared. This reproduces the reported result but confirms expected behavior rather than a current-main bug.

## Solution Assessment

No, changing the gateway to trust this device-less custom client would weaken the authorization boundary. The maintainable solution is to implement the documented challenge and device-signature handshake in the external client.
