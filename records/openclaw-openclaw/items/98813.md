## Summary

The functional patch remains useful and current `main` still hardcodes mapped hook runs to the shared `cron` lane, but accepting a new public lane configuration that creates independent queue capacity is a maintainer product/scheduler decision rather than an implementation defect.

## What This Changes

Adds optional `hooks.mappings[].lane` configuration, documentation, and dispatch wiring so a mapped hook’s isolated agent run can use a configured command-queue lane instead of always using `cron`.

## Best Possible Solution

Have the hook/scheduler owner explicitly approve mapping-scoped lane selection and its documented capacity semantics; if approved, keep this narrow opt-in path with the existing `cron` default and direct-payload exclusion.
