## Summary

Keep this PR open for rework: it proposes a useful Workboard capability, but its read-time projection does not yet meet the advertised durable, replayable notification contract and it exposes incorrect scoping and discovery behavior.

## What This Changes

This PR adds an opt-in `status_changed` Workboard notification, derives it from card move history, extends the Workboard contract, and documents the new event for notification subscribers.

## System Context

Workboard records card lifecycle changes and exposes notification subscriptions to downstream consumers such as automation or channel integrations. This PR inserts a derived status-transition event between retained card history and subscription delivery, affecting replay, cursors, and run-scoped consumers.

## Best Possible Solution

Define the intended durability guarantee first, then emit an immutable transition record with transition-time scope and a stable sequence/identity that remains available for the subscription cursor; align the contract, tool schema, documentation, tests, and replay proof with that single model.

## Reproduction Assessment

Yes, from source inspection: move a reused or relinked card between runs, then request notifications scoped to the new run; the derived historical event uses the card's current scope. ## Solution Assessment

No. A read-time projection from a bounded, mutable recent-event ring cannot safely promise durable replay or stable deduplication; the feature needs an immutable, transition-time event source or a deliberately narrower best-effort contract.
