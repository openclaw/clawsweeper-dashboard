## Summary

Keep this PR open: current `main` does not provide the requested notification kind, but the branch does not yet meet its advertised durable/replay-safe contract. It derives delivery from a bounded, mutable card-event ring and reapplies the card’s current run/session scope to old transitions, so subscribers can miss events or receive them under the wrong scope.

## What This Changes

The PR adds an opt-in Workboard `status_changed` notification kind, projecting card status transitions from stored `moved` events and documenting the new subscriber payload.

## System Context

Workboard records card updates and lifecycle events in the Workboard plugin’s persisted store, then filters notifications for subscribed downstream consumers. The new event would let consumers react to ordinary card-status transitions rather than only terminal or stale states.

## Architecture Diagram

## Best Possible Solution

Define `status_changed` as a real immutable notification record written atomically with the status update, including transition-time card, session, and run scope; preserve an immutable event identifier/cursor, expose it through every subscription surface, and prove fresh plus replay behavior against the persisted store.
