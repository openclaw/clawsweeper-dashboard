## Summary

This PR remains necessary because current main still has the macOS alias failure it targets, but it should not merge at the current head: canonicalizing the target before migration-run creation removes non-root symlink components before the intentional topology guard can inspect them. The protected `maintainer` label also requires normal maintainer handling rather than cleanup closure.

## What This Changes

The PR canonicalizes session SQLite migration target inputs so macOS root aliases such as `/tmp` and `/private/tmp` compare consistently, and adds a regression test for importing through that alias.

## Best Possible Solution

Keep both lexical and canonical target representations: validate the original supplied paths for symlink topology first, then use canonical paths for trusted-target identity, containment checks, and manifest persistence, with regressions for both macOS root aliases and non-root symlink parents.
