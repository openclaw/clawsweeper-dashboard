## Summary

Keep this issue open with its paired fix PR, but treat the proposed direct-chat bypass as a security-boundary decision: current QQ Bot policy intentionally requires explicit approver authorization, so the report does not establish a button-mapping defect.

## What This Changes

Make QQ Bot C2C Allow-button callbacks resolve `skill_workshop` approvals instead of being rejected and timing out.

## Best Possible Solution

Preserve explicit approver authorization, but make unauthorized QQ approval cards actionable by suppressing unusable buttons or replying with `/bot-me` and exact `execApprovals.approvers` or non-wildcard `allowFrom` guidance; relax C2C authorization only after an explicit security decision and live QQ proof.
