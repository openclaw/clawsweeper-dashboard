## Summary

Keep this issue open with its linked candidate PR. Current QQ Bot documentation intentionally requires explicit, non-wildcard authorization for fallback approval clicks; allowing every direct C2C callback would change a security boundary and needs maintainer direction plus live QQ identity proof. ([docs.openclaw.ai](https://docs.openclaw.ai/channels/qqbot))

## What This Changes

Change QQ Bot direct-chat fallback approvals so clicking Allow can resolve plugin approval requests instead of being rejected and timing out.

## Best Possible Solution

Preserve explicit actor authorization, but return an actionable private-chat denial naming the required `allowFrom` or `execApprovals.approvers` setup; if implicit owner approval is desired, bind it to a stable configured owner or request-origin identity rather than every direct chat.
