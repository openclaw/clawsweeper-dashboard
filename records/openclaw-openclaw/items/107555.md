## Summary

Keep this issue open with its paired pull request. Current QQ Bot behavior intentionally requires explicit approval authorization, so the observed rejection is source-reproducible but is not an Allow/Deny decoding error; maintainers must decide whether verified direct-chat identity can safely authorize approvals or whether the existing boundary should remain and the misleading prompt/timeout UX should be fixed.

## What This Changes

Make QQ Bot approval buttons usable for skill_workshop operations in direct C2C conversations without weakening approval authorization.

## Best Possible Solution

Keep explicit actor authorization, route prompts only to configured approvers, and immediately explain how to add the sender OpenID to allowFrom or execApprovals.approvers; add a C2C exception only if QQ supplies a verified owner identity that can be tested as the authorization principal.
