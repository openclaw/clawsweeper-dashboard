## Summary

Keep this issue open with the linked candidate PR. Current behavior is source-reproducible, but the proposed C2C bypass changes a sensitive approval boundary: an open direct-message policy does not itself prove that the callback actor is the bot owner or an authorized approver.

Likely related people:

- `eleqtrizit` — high confidence; introduced the current fallback-button authorization gate.
- `cxyhhhhh` — medium confidence; recent contributor to the QQ interaction and gateway surface.

## What This Changes

Make QQ Bot approval buttons successfully resolve `skill_workshop` approvals in direct conversations instead of being rejected and timing out.

## Best Possible Solution

Keep sensitive approvals bound to a configured owner or explicit approver identity, only send actionable approval controls to that actor, and fail immediately with an in-chat authorization/setup message instead of waiting for the approval timeout.

Yes at source level: current main rejects implicit QQ approval callbacks when the actor lacks explicit command authorization, matching the reported logs and timeout path. ## Solution Assessment

No; unconditionally authorizing every C2C callback is not the safest fix because direct-message access and approval authority are distinct. The narrower solution is verified owner/approver authorization plus actionable targeting and fail-fast feedback.
