## Summary

Keep this issue open: current main retains the reported fail-closed authorization path, while the linked open PR is only a candidate fix and has not established a safe direct-message approval policy.

## What This Changes

Permit QQ Bot direct C2C approval buttons to resolve plugin approvals when the sender has no explicit non-wildcard command allowlist entry.

## Best Possible Solution

Bind direct-message approval callbacks to the canonical configured QQ Bot owner, command-authorized sender, access group, or explicit approval policy; acknowledge unauthorized clicks immediately instead of silently waiting for expiration.
