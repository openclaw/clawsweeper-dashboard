## Summary

Keep this issue open while the linked PR is reviewed. Current QQ Bot behavior intentionally requires explicit approval authority when `execApprovals` is absent; treating every direct-chat participant as implicitly authorized would change a security boundary rather than repair an established behavior contract. citeturn106409search0turn104465view0

## What This Changes

Allow QQ Bot users in direct C2C conversations to approve `skill_workshop` and other native approval requests without the current rejection and timeout.

## Best Possible Solution

Preserve explicit approval authorization, then make unauthorized button clicks immediately explain which existing `allowFrom` or `execApprovals.approvers` setting is required—or only deliver approval controls to configured approvers—rather than granting privileged approval authority to every direct-chat participant.
