## Summary

Keep this issue open with its paired fix PR: current QQ Bot behavior intentionally requires explicit actor authorization for fallback approval buttons, while the proposed direct-chat bypass changes a security boundary and needs owner review plus live QQ proof.

## What This Changes

Make QQ Bot Allow buttons approve Skill Workshop requests in direct conversations instead of being rejected and timing out.

## Best Possible Solution

Preserve explicit actor authorization, provide a narrow configured owner or approver path for QQ C2C plugin approvals, return a clear unauthorized-action response, and validate both authorized and unauthorized callbacks through live QQ plus focused regression tests.

Options:

- **Keep explicit authorization (recommended):** Retain the current identity gate, reject the unconditional C2C bypass, and improve configuration guidance and unauthorized-click feedback.
- **Add narrow C2C approvers:** Define a dedicated explicit approver resolution path for QQ plugin approvals while keeping ordinary DM admission separate.
- **Trust all C2C senders:** Accept the bypass only as an intentional documented security-policy change with live authorized and unauthorized callback proof.

## Reproduction Assessment

Yes at source level: a QQ C2C sender admitted by an open or wildcard DM policy but lacking an explicit non-wildcard authorization entry follows the rejection path and the pending approval then expires. No live QQ callback proof was provided.

## Solution Assessment

No; unconditionally authorizing every direct-chat callback is not the safest fix because DM admission is broader than privileged-action authorization. Explicit identity resolution with clear failure feedback is the narrower maintainable direction.
