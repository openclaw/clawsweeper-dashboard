## Summary

Keep this issue open while the linked pull request is reviewed. Current main intentionally requires explicit approval authority for QQ Bot fallback callbacks, so the observed rejection is reproducible, but changing C2C conversations to implicit approval authority requires a security-boundary decision rather than a competing automatic fix.

## What This Changes

Make QQ Bot Allow buttons successfully resolve skill-workshop approval requests in direct C2C conversations instead of being rejected and timing out.

## Best Possible Solution

Authorize C2C fallback approvals only through an explicit approver or separately established canonical owner identity, and immediately show actionable in-chat authorization guidance instead of presenting a button that waits to time out.

- **Trust every C2C sender:** Treat any permitted direct-message sender as authorized for approval callbacks.

## Reproduction Assessment

Yes, from source and shipped behavior: without an explicit approver or non-wildcard allowlist entry, fallback callback authorization rejects the actor and the approval wait expires. This review did not independently execute a live QQ callback.

## Solution Assessment

No. Trusting every C2C sender is broader than necessary; the safer fix preserves explicit or owner-bound approval authority and makes unauthorized prompts fail immediately with configuration guidance.
