## Summary

Keep this issue open while the linked pull request is reviewed. Current QQ Bot documentation says fallback approval buttons require an explicit non-wildcard command allowlist, so the observed rejection is consistent with the shipped security contract rather than an Allow/Deny mapping error; changing direct chats to implicit approval authority requires an explicit security decision.

## What This Changes

Allow QQ Bot direct-conversation users to resolve plugin approval buttons without a concrete non-wildcard approver allowlist.

## Best Possible Solution

Retain explicit actor authorization by default and provide immediate in-product recovery that identifies the sender with `/bot-me` and guides the operator through configuring approval-only access; permit a direct-chat shortcut only if QQ metadata reliably proves the callback actor is the configured bot owner.
