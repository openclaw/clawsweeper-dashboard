## Summary

The behavior still needs resolution, but it is not an established bug under the current QQ Bot contract: fallback approval clicks intentionally require a concrete command allowlist or dedicated approver, while the linked PR proposes relaxing that security boundary for C2C chats. Keep the issue paired with the open PR until maintainers choose the trust model and review live QQ callback identity evidence.

## What This Changes

Allow QQ Bot C2C recipients to resolve fallback plugin approvals without an explicit non-wildcard command or approval allowlist.

## Best Possible Solution

Preserve explicit approval authority by default and add a visible QQ recovery flow that identifies the sender OpenID and offers to add it as an approval-only approver; relax C2C authorization only if maintainers explicitly accept delivery as the trust boundary and live QQ proof shows the callback actor is securely bound to the intended recipient.
