## Summary

Keep this issue open with its paired pull request. The reported rejection is source-reproducible, but it comes from the intentional approval-authorization gate rather than incorrect Allow/Deny decoding; accepting direct-chat delivery as sufficient approval authority requires explicit security-boundary review.

## What This Changes

Correct QQ Bot direct-chat approval handling so authorized Allow clicks resolve plugin approvals instead of being rejected and timing out.

## Best Possible Solution

Keep approval authority fail-closed, accept direct callbacks only when bound to a verified trusted actor, and otherwise suppress unusable buttons or return immediate authorization guidance instead of timing out.

- **Keep gate, fix UX only:** Continue requiring explicit authorization but avoid presenting actionable buttons to unauthorized actors and return immediate setup guidance.

## Solution Assessment

No. A blanket non-group bypass conflates DM admission with privileged approval authority; verified actor binding or fail-fast authorization UX is the safer solution.
