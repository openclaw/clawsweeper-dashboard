## Summary

Current `main` still uses the post-run `sessions.patch` fallback and does not give the spawn-label schema the proposed task-title guidance, so the work remains necessary; the patch follows the existing run-start session-persistence path, but it needs real after-fix behavior proof before merge.

## What This Changes

This PR teaches subagents to use `label` as a short UI task title, removes the redundant completion-time session-label write, and tests that the agent request persists labels when a run starts.

## System Context

The `sessions_spawn` tool creates a child-agent request with a session label, and gateway session persistence records that label for the Control UI’s task ledger and session sidebar. The subagent completion announcer later delivers results to the parent and cleans up child sessions; this PR removes its second, post-run label write.
