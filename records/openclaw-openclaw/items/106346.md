## Summary

Keep this issue open for a maintainer product decision: current main documents fallback commands as defaults-only, but accepting inherited `--agent` context while mutating global defaults remains a hazardous multi-agent CLI behavior. Likely related people include steipete for the models CLI/status contract and vincentkoc for recent per-agent model and agent-scope work.

## What This Changes

Allow text-model fallback list/add/remove/clear commands to target per-agent fallback overrides with `--agent`, while explicitly rejecting agent scope for image fallbacks.

## Best Possible Solution

Define one explicit CLI contract: honor `--agent` for text fallback commands using existing per-agent model configuration with tested inheritance/materialization rules, and reject `--agent` with actionable output for image fallbacks.
