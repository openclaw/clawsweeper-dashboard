## Label Justifications

- `P2`: The bug can silently inspect or mutate the wrong fallback configuration in multi-agent deployments, but it is limited to an advanced CLI configuration workflow with a manual workaround.
- `impact:auth-provider`: The issue targets agent-specific model selection and fallback routing configuration.

## Summary

Keep this issue open: current main still accepts inherited `--agent` context without using it in fallback handlers, while the shared implementation reads and writes only global defaults. The text-model path already has per-agent runtime resolution, but current docs define these CLI commands as defaults-only and the image-model path has no matching per-agent contract, so maintainers should choose the permanent CLI semantics before implementation.

## What This Changes

Make model and image fallback list/add/remove/clear commands handle `--agent` safely instead of silently operating on global defaults.

## Best Possible Solution

Support explicit agent-scoped text fallback operations by creating or updating that agent's own fallback override, while rejecting `--agent` for image fallback commands unless a separate per-agent image-model contract is intentionally introduced; add focused CLI, mutation, inheritance, empty-override, and documentation coverage.
