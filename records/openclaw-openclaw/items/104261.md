## Summary

The requested capability is still necessary: OpenClaw intentionally keeps paired-node Codex sessions metadata-only, while Codex App Server supports multi-connection resume and approval routing but has no exclusive fenced ownership primitive. Keep this protected feature open for a maintainer and upstream Codex decision because safe takeover cannot be implemented until the shared lease authority and failure semantics are defined.

## What This Changes

Add a paired-node duplex runner and cross-process lease so OpenClaw can safely continue or archive remote native Codex threads without concurrent native-client ownership.

## Best Possible Solution

Define an authoritative fenced lease in the Codex App Server/runtime shared by Desktop, CLI, and OpenClaw, covering opaque store identity, owner generation, grant/renew/revoke, approval routing, idle proof, partition handling, and crash recovery; then add a paired-node duplex runner that refuses continue or archive without a current lease.
