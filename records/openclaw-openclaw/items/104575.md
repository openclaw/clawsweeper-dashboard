- `P2`: This is a focused channel reliability bug with limited blast radius: a stalled Mattermost file endpoint can block one inbound attachment-processing path indefinitely.

## Summary

Keep this PR open for normal merge consideration: current main still leaves Mattermost header waits unbounded, while the proposed patch uses the existing shared timeout contract at the plugin owner boundary, preserves graceful attachment failure, and has no actionable review finding.

## What This Changes

The PR adds 120-second response-header and 30-second body-idle deadlines to Mattermost inbound attachment downloads and covers stalled response headers with a loopback HTTP regression test.

## Best Possible Solution

Mattermost inbound media should use the shared fetch helper's bounded header and body-idle deadlines while continuing the message with explicit unavailable-attachment context when a download times out.
