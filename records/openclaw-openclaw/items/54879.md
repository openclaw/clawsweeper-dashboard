## Summary

Keep open: current main and the latest release still expose only the existing browser act text paths, while the issue and linked FSB data point describe a credible rich-editor IME capability gap that needs maintainer API and live-proof decisions.

## What This Changes

The issue requests a CDP-backed browser-tool text insertion action for IME/non-Latin text in contenteditable rich editors such as the X composer.

## Best Possible Solution

Add a focused browser-plugin act kind for native text insertion, with CDP Input.insertText support where available, explicit unsupported-driver behavior, schema/route/CLI/docs alignment, and live IME proof on a rich contenteditable editor.
