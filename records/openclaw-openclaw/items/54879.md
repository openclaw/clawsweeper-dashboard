## Summary

Keep open: current main and v2026.6.11 still expose only the existing browser `act` text paths, while the report and FSB comment describe a credible rich-editor IME gap that needs maintainer API and live-proof decisions.

## What This Changes

Request a browser `act` action that inserts text through CDP or IME-like native text insertion for contenteditable rich editors where paste, fill, type, and DOM insertion are unreliable.

## Best Possible Solution

Add a focused browser plugin `act` kind for native text insertion, with CDP `Input.insertText` support where available, explicit unsupported-driver behavior, schema/route/CLI/docs alignment, and live IME proof on a rich contenteditable editor.

## Reproduction Assessment

No high-confidence live reproduction of the X/Korean IME failure was established. Source inspection does reproduce the central gap: current main has no CDP/IME insert-text act kind and routes text insertion through type/fill paths.

## Solution Assessment

Unclear for the final API shape: the browser act layer is plausible and the FSB comment is useful corroboration, but maintainers still need to choose the public action contract, driver support, focus semantics, and unsupported behavior.
