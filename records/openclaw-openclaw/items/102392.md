## Summary

Keep open: current main still carries imported transcript text and speaker labels into `summary.md` and then writes that Markdown directly to stdout, and I found no merged or open canonical PR that fixes the terminal-control path. Because this is already-public but security-sensitive CLI output behavior, maintainer/security review should choose the handling route before repair automation owns it.

## What This Changes

Ensure imported transcript summaries printed by `openclaw transcripts show` cannot emit terminal control sequences from transcript text or speaker labels.

## Best Possible Solution

Sanitize externally supplied transcript text and speaker labels at the summary or terminal-display boundary with the existing terminal-core helper, then add regression coverage for CSI and OSC escapes through the import-to-`transcripts show` path.
