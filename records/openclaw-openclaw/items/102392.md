## Summary

Keep open: current main still lets imported transcript text and speaker labels flow into `summary.md` and then writes that markdown directly to terminal stdout, so the reported terminal-control exposure remains valid and security-sensitive.

## What This Changes

The issue asks OpenClaw to prevent imported transcript text or speaker labels with terminal escape sequences from being persisted to, or printed by, transcript summary output.

## Best Possible Solution

Sanitize externally supplied transcript text and speaker labels at the approved summary/display boundary with the existing terminal-core sanitizer, then add CSI and OSC regression coverage through the real `transcripts show` path.
