## Summary

Keep open: current main and the latest release still carry imported transcript text and speaker labels into `summary.md` without terminal-control sanitization, then `openclaw transcripts show` emits that markdown directly to stdout. The bug is narrow and source-reproducible, but the security handling route and exact sanitize-at-store versus sanitize-at-display boundary need maintainer review.

## What This Changes

The issue requests sanitizing imported transcript text and speaker labels before persisted `summary.md` output or terminal display so `openclaw transcripts show` cannot emit terminal escape bytes.

## Best Possible Solution

Sanitize externally supplied transcript text and speaker labels with the shared terminal-core sanitizer at the chosen summary/display boundary, then add regression coverage for CSI and OSC escapes through the real `transcripts show` path.
