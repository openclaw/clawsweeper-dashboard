## Summary

Keep open: current main and v2026.6.11 still carry imported transcript text and speaker labels into `summary.md`, then `openclaw transcripts show` writes that markdown directly to stdout. This is a valid security-hardening bug, but maintainers should choose the artifact-versus-display sanitization boundary before repair automation.

## What This Changes

The issue asks OpenClaw to prevent imported transcript text and speaker labels from preserving terminal escape sequences into `summary.md` and `openclaw transcripts show` output.

## Best Possible Solution

Sanitize untrusted transcript text and speaker labels at the chosen summary/display boundary with the terminal-core sanitizer, then add regression coverage for CSI and OSC controls through the real `transcripts show` path.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should transcript terminal-control sanitization happen when generating stored `summary.md`, when printing `transcripts show`, or in both places?

Rationale: All options can remove the stdout hazard, but they choose different semantics for persisted human-readable artifacts and security handling.

Likely owner: steipete

Owner reason: This person has the clearest current history on the transcript summary/store/CLI surface and is the best available owner for the boundary choice.

Owner confidence: high

Options:

- **Sanitize generated Markdown (recommended):** Strip terminal controls from externally supplied transcript text and speaker labels before rendering `summary.md`, making the stored artifact and CLI display safe by default.
- **Sanitize only CLI output:** Preserve stored artifact bytes and strip terminal controls only before stdout, but separately accept that opening `summary.md` directly can still affect a terminal.
- **Route through security first:** Pause repair work until security owners decide whether this already-public terminal-control issue needs advisory-style handling.

Yes. The issue body provides concrete CLI steps and captured output, and current-main source still shows imported transcript text entering `summary.md` without sanitization before `transcripts show` writes it to stdout; I did not run a live CLI repro in this read-only review.

## Solution Assessment

Yes for the expected end state: raw external terminal controls should not reach terminal stdout. The open design choice is the exact boundary, because sanitizing persisted Markdown and sanitizing display output have different artifact semantics.
