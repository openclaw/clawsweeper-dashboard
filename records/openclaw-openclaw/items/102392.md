## Summary

Keep open: current main still lets imported transcript text and speaker labels flow into stored transcript summaries without terminal-control sanitization, and non-JSON `openclaw transcripts show` writes the stored markdown directly to stdout. No linked or searched issue/PR currently supersedes this report.

## What This Changes

The issue reports that imported transcript text can persist terminal escape sequences into transcript summaries and `openclaw transcripts show` can write those bytes to stdout.

## Best Possible Solution

Sanitize externally supplied transcript text and speaker labels with the existing terminal-core sanitizer at the chosen summary/display boundary, then add regression coverage for CSI and OSC/control bytes through the real `transcripts show` path.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should transcript escape sanitization happen when summaries are persisted, only when `transcripts show` writes to a terminal, or at both boundaries?

Rationale: Sanitizing at persistence changes stored `summary.md` and `summary.json` semantics, while display-only sanitization leaves dangerous bytes in local artifacts; that storage/display boundary needs maintainer security intent.

Likely owner: steipete

Owner reason: This handle owns the strongest current implementation and merge-history signal for the transcript CLI and summary surface.

Owner confidence: high

Options:

- **Sanitize summary inputs before persistence (recommended):** Strip terminal escapes from imported utterance text and speaker labels before summary JSON/markdown are written, so stored summary artifacts are safe by default.
- **Sanitize only terminal display:** Leave stored artifacts byte-preserving but strip controls in non-JSON `transcripts show` output, preserving raw summaries at the cost of unsafe local files.
- **Sanitize both persistence and display:** Defend both stored artifacts and stdout, but document the intentionally non-byte-preserving summary behavior.

## Solution Assessment

Unclear until maintainer/security intent chooses the storage boundary; the narrow implementation should reuse the existing terminal-control sanitizer rather than introduce a new escaping grammar.
