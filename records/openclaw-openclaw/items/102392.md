## Summary

Keep open: current main still builds transcript summaries from imported utterance text and speaker labels without terminal-control sanitization, persists that rendered markdown, and `openclaw transcripts show` writes the stored `summary.md` directly to stdout. The adjacent exec-output sanitizer fix does not cover this transcript summary/display path, so this issue remains the canonical open work.

## What This Changes

The issue reports that imported transcript text with terminal escape sequences is persisted into transcript summaries and emitted by `openclaw transcripts show`.

## Best Possible Solution

Choose the transcript artifact safety boundary, then use one canonical terminal-control sanitizer for generated/displayed transcript summaries while preserving raw transcript JSONL as the audit/import source.

Options:

- **Sanitize generated summaries before persistence (recommended):** Remove terminal control sequences from summary fields before writing generated summary artifacts, while leaving raw `transcript.jsonl` as the source artifact.
- **Sanitize only terminal output:** Keep stored summary artifacts byte-preserving and sanitize the plain `transcripts show` stdout path only.
- **Sanitize both artifact and display paths:** Use persistence sanitization plus a defensive display sanitizer, accepting duplicate protection for this security-sensitive boundary.
