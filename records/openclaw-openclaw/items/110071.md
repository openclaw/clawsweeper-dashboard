## Label Justifications

- `P2`: The bug affects an optional Slack thread-ownership extension but can cause incorrect delivery in configured multi-agent workspaces.
- `merge-risk: 🚨 message-delivery`: The changed 409 error path can convert an ownership conflict into an allowed outgoing thread message.

## Summary

Keep this PR open for a narrow repair: it correctly introduces bounded parsing and cache eviction, but turns an HTTP 409 ownership conflict with an unreadable body into an allowed Slack send. The same status is the ownership signal, so parsing the optional owner field must not bypass cancellation.

## What This Changes

The branch caps thread-ownership forwarder conflict-body parsing at 64 KiB and limits the in-memory Slack mentioned-thread cache to 1,000 entries.

## Best Possible Solution

Catch bounded-read and JSON-parse failures inside the 409 branch, log the owner as unknown, and still return `{ cancel: true }`; keep the 64 KiB response cap and the bounded mention cache.

## Solution Assessment

No. Bounding the body is the right resource fix, but the status code—not optional JSON owner attribution—must remain authoritative for ownership cancellation; the approach in https://github.com/openclaw/openclaw/pull/101968 demonstrates that narrower repair.
