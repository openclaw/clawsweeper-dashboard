## Summary

The inbound-pipeline design uses the right owner and the identity plumbing is well covered, but the handler can confirm a persisted control even when downstream inbound authorization rejects the turn; live Slack proof is also still absent.

## What This Changes

The PR routes persisted Slack reply buttons and selects through normal inbound message handling while separating each action’s turn identity from the source-message native reply target.

## Best Possible Solution

Make inbound admission return an explicit accepted or rejected result, update persisted controls only after accepted dispatch, preserve private rejection feedback, and add redacted exact-head Slack proof before merge.
