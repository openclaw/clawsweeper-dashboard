## What This Changes

Investigate and repair Telegram polling ingress so a recovered stuck session cannot permanently drop later inbound messages for one forum topic while Telegram still acknowledges them.

## System Context

Telegram polling receives Bot API updates, derives a chat/topic lane, and hands the message to OpenClaw's session and agent-dispatch pipeline. This issue concerns the gap between acknowledging an update upstream and producing a durable inbound dispatch for the correct topic session.

## Architecture Diagram

flowchart TD
  A[Telegram Bot API update] --> B[Polling ingress]
  B --> C[Chat and forum-topic lane]
  C --> D[Spool and timeout recovery]
  D --> E[Session routing]
  E --> F[Agent dispatch]
  F --> G[Inbound log and reply]

## Best Possible Solution

Add a durable ingress/dispatch invariant for Telegram updates: either persist and route each acknowledged update to its topic session or emit a recoverable, visible failure, then prove both same-process and post-restart recovery with a real forum-topic scenario.
