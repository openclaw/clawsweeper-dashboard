## Summary

Keep open: this fresh v2026.7.1 report describes a still-plausible Codex runtime failure where an eventless app-server turn becomes a generic timeout, penalizes the selected auth profile, and cascades through fallbacks. Prior fixes addressed progress-aware timeouts, missing completion recovery, and account-update liveness, but they do not prove this new zero-model-event case is resolved.

## What This Changes

Prevent eventless Codex app-server timeouts from causing inappropriate auth-profile cooldowns and cascading model fallbacks.

## Best Possible Solution

Introduce a distinct Codex app-server liveness or transport failure classification: retire and restart the unhealthy app-server client, allow bounded model fallback, but do not cool down the auth profile unless an actual auth, quota, rate-limit, or provider response supports a profile-level failure; cover fresh-turn, accepted-but-eventless, lost-completion, and real provider-timeout cases with focused tests and a live redacted reproduction.
