## Summary

Current main confirms the reported timeout-to-cooldown chain, while earlier app-server watchdog and model-scoped cooldown fixes do not resolve a genuinely zero-event Codex turn or prevent that timeout from suppressing the same model across unrelated lanes. The issue remains useful for a correlated live reproduction and an explicit shared-health policy decision.

## What This Changes

Investigate intermittent zero-event Codex app-server turns and prevent one local idle timeout from cascading through shared OpenAI model/profile health across concurrent lanes.

## Best Possible Solution

Have the Codex plugin emit correlated turn, process, transport, and last-event diagnostics for silent attempts, classify OpenClaw-generated idle watchdog expiry separately from upstream provider errors, and update shared auth health only when the evidence demonstrates model or credential degradation rather than one failed attempt.
