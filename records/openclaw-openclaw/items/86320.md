## Summary

Keep open: current main has improved plugin and configured-channel startup diagnostics, but it still does not fully solve the central problem because the channel startup loop only audits channels that already registered successfully.

## What This Changes

The issue requests clearer Gateway startup handling when configured channels fail plugin loading, registration, compatibility checks, generated-module resolution, or health probes.

## Best Possible Solution

Keep the existing plugin diagnostics, then add an owner-approved Gateway channel initialization audit that compares configured channel signals and registry diagnostics against loaded channel plugins; split hot reload and broad startup performance work into separate decisions.
