## Summary

Keep open: current main has much better plugin, status, missing-owner, bundled-module, and Feishu timeout diagnostics than the reported 2026.5.12 build, but the broader startup contract is still not fully settled because Gateway channel startup only audits already-registered channel plugins and this issue also asks for fail-fast compatibility, hot reload, and performance policy decisions.

## What This Changes

The issue asks Gateway startup to surface channel plugin/runtime incompatibilities, missing generated channel modules, external API timeouts, and plugin-loading performance instead of silently skipping channel initialization.

## Best Possible Solution

Keep the existing plugin/status diagnostics, then add an owner-approved Gateway startup audit for configured channels that fail before registration while tracking hot reload and broad performance caching as separate product decisions.

Question: What startup contract should Gateway enforce when a configured channel plugin fails before channel registration?

Rationale: The source gap is real, but the right behavior is a policy choice: fail-fast can break existing setups, warn-and-continue preserves availability, and hot reload conflicts with the current process-stable plugin metadata contract.

Likely owner: steipete

Owner confidence: high

Options:

- **Warn and audit configured channels (recommended):** Add a non-fatal startup audit/status summary for configured channels that were expected but missing, blocked, or failed setup/runtime registration, while preserving restart-required plugin metadata.
- **Fail fast for configured channel failures:** Treat incompatible or unloadable configured channel plugins as startup-blocking errors, accepting the upgrade risk that one bad channel can stop Gateway readiness.
- **Split broader feature requests:** Keep this issue focused on startup diagnostics and move hot reload plus broad performance caching to separately sponsored roadmap work.
