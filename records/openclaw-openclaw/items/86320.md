## Summary

Keep open: current main has better plugin diagnostics and status visibility, but gateway startup still audits only loaded channel plugins, so configured channels that fail before registration can remain absent from the channel-start audit.

## What This Changes

The issue asks for clearer gateway/channel startup diagnostics and recovery behavior when configured channel plugins fail to load from version mismatch, missing generated modules, API timeouts, or large plugin sets.

## Best Possible Solution

Define an owner-approved configured-channel startup audit that reports attempted, loaded, and failed channels including pre-registration failures, while keeping hot reload, broad performance caching, and API-timeout severity as separate follow-up decisions.

Options:

- **Add A Configured-Channel Startup Audit (recommended):** Emit a startup summary for configured channel ids that were attempted, loaded, or failed before registration, without changing restart or hot-reload behavior in the same fix.
- **Fail Fast On Incompatible Plugins:** Treat selected plugin/core version mismatches as startup-blocking errors, accepting the upgrade-compatibility risk explicitly.
- **Split Reload And Performance Work:** Keep this issue focused on diagnostics and track hot reload, plugin metadata caching, and external API timeout severity as separate design items.
