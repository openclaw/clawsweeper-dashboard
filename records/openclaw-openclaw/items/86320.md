## Summary

Keep open: current main has better plugin diagnostics and missing-module hints than the reported 2026.5.12 build, but the gateway channel startup loop still only audits channel plugins that reached the loaded registry, so a configured external channel can fail before registration and remain absent from the channel startup path.

## What This Changes

The issue asks OpenClaw to surface gateway channel initialization failures caused by plugin/runtime version mismatch, missing generated modules, external API timeouts, and heavy startup plugin scanning.

## Best Possible Solution

Add an owner-approved gateway channel initialization audit that includes configured channels that failed before registration, while tracking bundled setup warnings, hot reload, Feishu API health severity, and broad startup caching as separate product or architecture work.

Options:

- **Add a narrow startup audit (recommended):** Record configured channel attempts and plugin-loader failures in a gateway startup summary without changing restart, hot-reload, or fail-fast policy.
- **Make mismatches fail fast:** Treat configured channel plugin/runtime incompatibility as a startup-blocking error, accepting a higher compatibility and upgrade impact for clearer failure semantics.
- **Keep diagnostics outside startup:** Rely on plugin status, doctor, and channel status diagnostics only, leaving gateway startup as warn-and-continue over loaded channel plugins.

Yes, at source level: current main records plugin registration failures as plugin diagnostics, but gateway channel startup only iterates already loaded channel plugins. I did not run the exact Windows Feishu/npm mismatch scenario in this read-only review.

## Solution Assessment

Unclear as a single bundled implementation: a narrow channel startup audit is the maintainable core fix, while fail-fast compatibility checks, hot reload, API timeout severity, and startup caching should be split or explicitly approved by maintainers.
