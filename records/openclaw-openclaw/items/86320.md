## Summary

Keep open: current main has better plugin and configured-channel startup diagnostics than the reported build, but it still does not fully provide a channel-level attempted/loaded/failed audit for configured channels that fail before registration.

## What This Changes

The issue asks for clearer Gateway diagnostics and recovery when configured channels are skipped during startup because of plugin/runtime mismatch, missing generated modules, external API timeouts, or heavy plugin loading.

## Best Possible Solution

Keep the current plugin diagnostics, then add an owner-approved configured-channel startup audit that maps each configured channel to activation, load, registration, start, and health-probe outcomes with repair guidance; split hot reload and broad performance caching into separate tracked work if maintainers want them.
