## Label Justifications

- `P1`: This is a shipped regression blocking remote browser control for managed-hosting and cross-machine users, but the fix requires product and security direction rather than emergency repair.
- `impact:security`: A restored or replacement relay would control authenticated browser sessions across extension, Gateway, node, and network boundaries.
- `impact:ux-friction`: The current alternatives require node-host setup, remote CDP, Chrome flags, or external tooling instead of the previous one-click extension workflow for non-technical managed-hosting users.

## Summary

Keep open: current main and v2026.6.11 still reject the legacy `driver: "extension"` path, migrate old relay config to `existing-session`, and do not provide the one-click cross-machine Chrome extension relay workflow described by the reporter and commenters.

## What This Changes

Restore or replace the removed Chrome extension browser relay so remote OpenClaw hosts can control a user's local Chrome across machines without requiring Node, CLI tools, or remote-CDP setup on the user's machine.

## Best Possible Solution

Keep this issue open until maintainers either land a vetted browser-backend or extension-bridge replacement with migration, docs, tests, and security review, or explicitly decide to keep the legacy relay retired and document the supported alternatives.
