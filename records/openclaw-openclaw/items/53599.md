## Label Justifications

- `P1`: This is a shipped regression blocking remote browser control for managed-hosting and cross-machine users, but the fix requires product and security direction rather than emergency repair.
- `impact:security`: A restored or replacement relay would control authenticated browser sessions across extension, Gateway, node, and network boundaries.
- `impact:ux-friction`: Current alternatives require node-host setup, remote CDP, Chrome flags, or external tooling instead of the previous one-click extension workflow for non-technical managed-hosting users.

## Summary

Keep open: current main and v2026.6.11 still reject the legacy Chrome extension relay driver and migrate old relay config to host-local existing-session, so the cross-machine one-click relay workflow remains missing and needs maintainer product/security direction.

## What This Changes

Restore or replace the removed Chrome extension browser relay so remote OpenClaw hosts can control a user's local Chrome across machines without requiring local CLI, Node.js, or remote-debugging setup.

## Best Possible Solution

Keep this open until maintainers either land a vetted browser-backend or extension-bridge replacement with migration, docs, tests, and security review, or explicitly decide to keep the legacy relay retired and document supported alternatives.
