## Summary

Keep open: current main and v2026.6.11 still reject the legacy `driver: "extension"` path, doctor migrates it to `existing-session`, and the documented replacement is not the same one-click cross-machine Chrome extension relay workflow. The open My Browser bridge PR and the browser-backend API issue are useful related work, but neither is a merged safe replacement for this concrete managed-hosting regression yet.

## What This Changes

The issue requests restoring or replacing the removed Chrome extension relay so remote OpenClaw hosts can control a user's local Chrome across machines without local Node or Chrome-flag setup.

## Best Possible Solution

Make a maintainer-approved browser-control strategy explicit: either land a vetted plugin/API-backed extension bridge with scoped auth, auditability, docs, tests, and migration behavior, or document that the legacy relay is retired and point managed hosts to supported node/remote-CDP paths.
