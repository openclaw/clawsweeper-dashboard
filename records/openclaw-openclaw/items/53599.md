## Summary

Keep open: current main and v2026.6.11 still reject the old `driver: "extension"` path and migrate it to `existing-session`, while the comments show real managed-hosting demand and no direct one-click cross-machine replacement.

## What This Changes

The issue asks OpenClaw to restore or replace the removed Chrome extension browser relay so remote/VPS OpenClaw instances can control a user's local Chrome without local CLI setup.

## Best Possible Solution

Choose a maintainer-approved browser-control direction: either define a secure browser backend/plugin API that lets third-party remote relays implement consent and auditing, or explicitly document that managed cross-machine extension relay is retired and unsupported in core.
