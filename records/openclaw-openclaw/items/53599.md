- `impact:security`: A restored relay would control authenticated browser sessions across extension, gateway, and network boundaries.

## Summary

Keep open: current main and the latest release still reject the legacy Chrome extension relay driver, migrate relay config to host-local Chrome MCP, and do not provide the one-click cross-machine replacement described by the reporter and follow-up users.

## What This Changes

The issue requests restoring or replacing the removed Chrome extension browser relay for cross-machine remote browser control.

## Best Possible Solution

Maintainers should explicitly choose the browser-control strategy: keep the legacy relay retired with clearer migration limits, or design a secure browser-backend/plugin API plus an optional relay implementation with migration, docs, tests, and security review.

## Reproduction Assessment

Yes, at source level: current main rejects driver="extension", migrates legacy relay config to existing-session, and has a contract test for the unsupported-driver response. I did not run a live cross-machine Chrome extension relay setup.

## Solution Assessment

No for an automatic direct restore. The issue is valid, but the maintainable fix needs maintainer-approved browser strategy and security design, likely involving the browser-backend/plugin API tracked at https://github.com/openclaw/openclaw/issues/19289.
