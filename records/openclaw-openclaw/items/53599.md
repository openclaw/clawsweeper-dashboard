## Label Justifications

- `P1`: This is a shipped regression that blocks remote browser control for managed-hosting and cross-machine users, but it needs product/security direction rather than emergency repair.
- `impact:security`: A restored or replacement relay would control authenticated browser sessions across extension, Gateway, and network boundaries.
- `impact:ux-friction`: The current alternatives require node-host setup, remote CDP, Chrome flags, or external tooling instead of the previous one-click extension workflow for non-technical managed-hosting users.

## Summary

Keep open: current main and v2026.6.11 still reject the legacy `driver: "extension"` path, migrate relay config to `existing-session`, and do not provide the one-click cross-machine Chrome extension relay workflow reported here. Related open browser-backend and My Browser work is useful context, but neither is a merged replacement for this regression yet.

## What This Changes

The issue asks OpenClaw to restore or replace the removed Chrome extension browser relay so remote Gateway deployments can control a user's local Chrome without local CLI or Chrome-flag setup.

## Best Possible Solution

Keep this issue open until maintainers either land a vetted browser-backend or extension-bridge replacement with migration, docs, tests, and security review, or explicitly decide to keep the legacy relay retired and document the supported alternatives.
