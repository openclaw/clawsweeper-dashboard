## Summary

Keep open: current main and v2026.6.11 still reject the legacy extension browser driver, migrate old relay config to Chrome MCP existing-session, and do not provide the one-click cross-machine extension relay workflow reported here. The issue remains a real regression, but the fix needs maintainer product and security direction rather than an autonomous restore.

## What This Changes

The issue asks OpenClaw to restore or replace the removed Chrome extension browser relay for cross-machine remote browser control, especially for managed-hosting users.

## Best Possible Solution

Maintainers should explicitly choose the browser-control strategy: keep the relay retired with clearer migration guidance, or design a secure browser-backend/plugin API plus an optional relay implementation with migration, docs, tests, and security review.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: current main rejects `driver: "extension"`, has a contract test for that rejection, and doctor migrates the old relay config to existing-session. I did not run a live cross-machine Chrome extension relay setup.

## Solution Assessment

No for a direct automated restore. The issue is valid, but the best fix needs maintainer-approved browser strategy and security design, likely involving the browser-backend/plugin API discussion rather than only restoring the old driver string.
