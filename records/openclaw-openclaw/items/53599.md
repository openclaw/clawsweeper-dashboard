## Label Justifications

- `P1`: This is a shipped regression blocking remote browser control for managed-hosting and cross-machine users, but the fix requires product and security direction rather than emergency repair.
- `impact:security`: A restored or replacement relay would control authenticated browser sessions across extension, Gateway, node, and network boundaries.
- `impact:ux-friction`: The current alternatives require node-host setup, remote CDP, Chrome flags, or external tooling instead of the previous one-click extension workflow for non-technical managed-hosting users.

## Summary

Keep open: current main and v2026.6.11 still reject the legacy `driver: "extension"` path, migrate old relay config to `existing-session`, and do not provide the one-click cross-machine Chrome extension relay workflow described by the reporter and commenters. The linked ClawHosters relay, FSB, and browser-relay projects are useful reference implementations, but they are not a merged OpenClaw replacement for this managed-hosting regression.

## What This Changes

Restore or replace the removed Chrome extension relay so remote OpenClaw instances can control a user's local Chrome across machines without local CLI, Node, or Chrome-flag setup.

## Best Possible Solution

Keep this issue open until maintainers either land a vetted browser-backend or extension-bridge replacement with migration, docs, tests, and security review, or explicitly decide to keep the legacy relay retired and document supported alternatives.
