## Label Justifications

- `P1`: This is a confirmed regression in a real cross-machine browser-control workflow affecting managed-hosting users, but the fix requires product/security direction rather than emergency runtime repair.
- `impact:security`: The requested browser relay would govern remote control of signed-in browser sessions, credentials, CDP/debugger access, and network reachability.
- `impact:ux-friction`: Non-technical managed-hosting users currently have no one-click relay replacement and are pushed toward Node, tunnels, or Chrome flag workflows.

## Summary

Keep open: current main and v2026.6.11 still reject the legacy extension driver and migrate relay config to Chrome MCP `existing-session`, while the related My Browser bridge PR and broader browser backend API issue are still open and not safe replacement close targets.

## What This Changes

Restore or replace the removed Chrome extension browser relay so remote hosted OpenClaw can control a user's local Chrome across machines without requiring local CLI tools or special Chrome flags.

## Best Possible Solution

Maintainers should choose a browser strategy, then either land a security-reviewed cross-machine browser bridge/plugin API with migration, docs, and tests, or explicitly retire the relay workflow with a supported managed-hosting alternative.
