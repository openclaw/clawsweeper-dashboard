## Label Justifications

- `P1`: The report describes a shipped regression that blocks remote browser control for managed-hosting and cross-machine users after the extension relay removal.
- `impact:security`: Restoring or replacing the relay would control signed-in browser sessions across extension, gateway, and network boundaries.
- `impact:ux-friction`: Affected users can proceed only through more technical alternatives such as a node host, remote CDP, browser flags, tunnels, or separate relay tooling.

## Summary

Keep open: current main and v2026.6.11 still reject the legacy `driver: "extension"` path, migrate relay config to `existing-session`, and do not provide the one-click cross-machine Chrome extension relay workflow reported here. The broader browser-backend API issue and external relay projects are useful context, but they are not a merged replacement for this regression.

## What This Changes

The issue asks OpenClaw to restore or replace the removed Chrome extension relay browser driver for cross-machine browser control.

## Best Possible Solution

Maintainers should explicitly choose the browser-control strategy: keep the relay retired with clearer migration guidance, or design a secure browser-backend/plugin API plus an optional relay implementation with migration, docs, tests, and security review.
