- `impact:security`: The requested relay would control authenticated browser sessions across extension, gateway, and network boundaries.

## Summary

Keep open: current main and v2026.6.11 still reject or migrate the legacy `driver: "extension"` path, and the documented replacements do not provide the reported one-click cross-machine Chrome extension relay workflow. The issue remains valid, but the fix needs a maintainer product and security-boundary decision rather than an automatic restore.

## What This Changes

The issue asks OpenClaw to restore or replace the removed Chrome extension browser relay so remote gateways can control a user's local Chrome across machines without local Node, CLI, or manual CDP setup.

## Best Possible Solution

Maintainers should choose an explicit browser-control strategy: either keep the relay retired with clearer migration guidance, or design a secure browser-backend/plugin API plus optional relay implementation with scoped tab ownership, auth, auditability, migration, docs, and tests.
