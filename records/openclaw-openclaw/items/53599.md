## Label Justifications

- `P1`: The issue describes a shipped regression that blocks remote browser control for managed-hosting and cross-machine users after the extension relay removal.
- `impact:security`: A restored relay would control authenticated browser sessions across extension, Gateway, and network boundaries, making credentials and browser authority central to the issue.

## Summary

Keep open: current main and v2026.6.11 still reject the legacy `driver: "extension"` path, migrate relay config to `existing-session`, and do not provide the one-click cross-machine Chrome extension relay workflow reported by multiple users.

## What This Changes

The issue asks OpenClaw to restore or replace the removed Chrome extension relay path for cross-machine browser control from managed or remote hosts.

## Best Possible Solution

Maintainers should explicitly choose the browser-control strategy: keep the relay retired with clearer migration guidance, or design a secure browser-backend/plugin API plus an optional relay implementation with migration, docs, tests, and security review.
