## Summary

This PR fixes retention of the failed-delete ID but not the full production failure: Discord has no later cleanup call after successful final delivery, and the asynchronous success path can clear ownership of a replacement preview. Both defects should be repaired before merge.

## What This Changes

The PR changes shared draft cleanup to retain a valid preview ID after deletion failure, clear it after successful deletion, and adds a helper-level retry regression test.

## Best Possible Solution

Preserve ownership after failed deletion, clear only the same successfully deleted ID, and retry cleanup once during Discord teardown when a fresh final succeeded but an unfinalized preview remains.
