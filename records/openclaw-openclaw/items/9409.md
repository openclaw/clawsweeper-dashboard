## Summary

Keep this issue open: current main has stronger overflow detection, observed-token extraction, compaction recovery, and internal diagnostics, but the user-facing failure path still provides recovery guidance rather than the requested safe session label, model/budget details, token count, and overage. Fresh June and July production reports confirm the diagnostic gap remains useful, while maintainers still need to decide what session identity may be disclosed and how estimated versus provider-observed counts should be labeled.

## What This Changes

Improve context-overflow failures with safe session identification, model and context-budget details, token counts, overage, and actionable recovery guidance.

## Best Possible Solution

Add one shared privacy-safe overflow diagnostic formatter that receives prepared provider/model, effective context budget, observed or clearly labeled estimated token count, computed overage, and a redacted human-readable session label; use it consistently across runner, precheck, sanitizer, and auto-reply paths without request-time transcript filesystem polling or a new config option.
