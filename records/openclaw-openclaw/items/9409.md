## Summary

Keep this issue open. Current main has stronger overflow detection, token extraction, transcript-size guards, compaction recovery, and structured debug logging, but no evidence shows that the user-facing failure paths now include safe session identity, model limits, observed size, or overage details. The closed-unmerged implementation attempt does not resolve the request, and fresh June and July production reports confirm that the generic guidance remains materially difficult to diagnose.

## What This Changes

Improve context-overflow failures with safe session and model identity, context-size and limit diagnostics, overage details, and actionable recovery guidance.

## Best Possible Solution

Define one redaction-aware overflow diagnostic object and formatter that receives already-prepared provider/model identity, effective context budget, the best available token observation with an explicit estimate label, computed overage, and a safe session display label; reuse it across runner, precheck, sanitizer, and auto-reply paths, while keeping raw identifiers and filesystem discovery out of the request hot path.
