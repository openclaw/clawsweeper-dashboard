## Summary

Keep this issue open: both the latest release and current main still convert context-overflow failures into generic recovery guidance, while richer session, model, budget, and overage data remains limited to internal logs or metadata. The request remains useful and canonical, but maintainers need to define a privacy-safe session label and distinguish estimated from observed token counts before implementation.

## What This Changes

Improve user-visible context-overflow errors with safe session identification, model and token-budget details, computed overage, and actionable recovery guidance.

## Best Possible Solution

Define one typed, privacy-safe overflow diagnostic payload with a channel-safe display label, provider/model identity, effective budget, and explicitly marked observed or estimated usage, then render it consistently through runner, formatter, sanitizer, and reply fallback paths.
