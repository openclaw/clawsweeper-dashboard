## Summary

Keep this issue open. Current main has stronger overflow detection, compaction recovery, and internal token diagnostics, but user-facing failure paths still omit the requested safe session label, model/budget details, token count, and overage; fresh June and July production reports confirm that this diagnostic gap continues to create substantial troubleshooting friction.

## What This Changes

Improve context-overflow failures with safe session identification, model and token-budget details, calculated overage, and actionable recovery guidance.

## Best Possible Solution

Add one shared privacy-safe overflow diagnostic formatter fed by already-prepared provider/model, safe display label, effective context budget, and explicitly labeled observed or estimated token counts; use it consistently across runner, precheck, sanitizer, and auto-reply paths without exposing raw keys or adding filesystem polling.
