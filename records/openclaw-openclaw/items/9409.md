## Summary

Current main still improves overflow recovery mainly through generic guidance, model-window hints, logs, and stored budget metadata; it does not surface the requested safe session label, current token size, model limit, and overage together. The direct implementation PR is closed unmerged, while related open work addresses model fallback rather than diagnostic content, so this issue remains necessary but needs a maintainer disclosure-policy decision before implementation.

## What This Changes

Improve context-overflow messages with session-safe, model-specific token diagnostics and actionable recovery guidance.

## Best Possible Solution

Extend the existing recovery helper into the canonical overflow diagnostic formatter, using a redacted display label and a typed observed/estimated/synthetic token-count source, then route every user-visible overflow exit through it.
