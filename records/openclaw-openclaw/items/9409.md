## Summary

Keep open: current main and the latest release still surface generic user-visible context-overflow text, while the detailed token/model/session facts are only logged or stored as metadata and related work does not implement the requested visible diagnostics.

## What This Changes

Request user-visible context-overflow errors that include safe session/channel identity, token size, model limit, overage, model identity, and clearer recovery actions.

## Best Possible Solution

Add one shared, redacted context-overflow diagnostic formatter and wire it through the runner, precheck, shared formatter/sanitizer, and auto-reply fallbacks after maintainers choose which session/model/token fields are safe to show.

- **Split Visibility From Recovery:** First standardize generic visible overflow guidance, then track richer diagnostics behind a separate maintainer-approved privacy policy item.
