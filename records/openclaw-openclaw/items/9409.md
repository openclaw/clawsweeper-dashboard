## Summary

Keep open: current main and v2026.6.11 still surface generic user-visible context-overflow copy in the runner, precheck, formatter/sanitizer, and auto-reply fallbacks, while the useful token/model/session facts remain in logs or metadata rather than the message users see.

The issue asks OpenClaw to include session/channel identity, token count, model limit, model identity, overage, and clearer recovery actions in context-overflow error messages.

## Best Possible Solution

Define one safe context-overflow diagnostic formatter with redacted session/channel display policy, then route it through the runner, precheck handling, shared formatter/sanitizer, and auto-reply fallbacks with focused regression coverage.
