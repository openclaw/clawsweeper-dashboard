## Summary

Keep this issue open. Current main has stronger overflow detection, compaction recovery, transcript-size controls, and internal diagnostics, but its user-facing overflow paths still omit safe session identification, model/budget details, token usage, and overage; fresh June and July production reports confirm the diagnostic gap remains materially confusing.

## What This Changes

Improve user-facing context-overflow errors with session, model, token-budget, overage, and actionable recovery details.

## Best Possible Solution

Add one shared privacy-safe overflow diagnostic formatter that consumes prepared provider/model identity, effective context budget, explicitly labeled observed or estimated token usage, computed overage when valid, and a redacted human display label; wire it through runner, precheck, sanitizer, and auto-reply terminal paths, retain concise /compact and /new recovery guidance, and cover missing-data, redaction, and divergent overflow-versus-compaction-failure cases without adding filesystem polling.
