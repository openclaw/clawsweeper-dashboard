## Summary

Current main and v2026.7.1 improve overflow recovery, token extraction, compaction guidance, and internal observability, but the user-visible paths are not shown to include a safe session label, model identity, effective limit, usage, and overage together. Fresh June and July production reports confirm that the remaining diagnostic gap still causes substantial troubleshooting friction.

## What This Changes

Improve context-overflow messages with safe session identification, model and context-limit details, observed usage or size diagnostics, computed overage, and concrete recovery actions.

## Best Possible Solution

Define one shared safe overflow-diagnostic formatter that receives prepared provider/model identity, effective context budget, authoritative or clearly labeled estimated usage, overage, and a redacted human session label; wire it through every terminal overflow path while keeping raw session keys, paths, and provider payloads out of channel-visible text.

- **Redacted diagnostics (recommended):** Show a redacted display label, provider/model, effective limit, and observed-or-estimated usage with explicit qualifiers while keeping raw identifiers, paths, and payloads in logs.
- **Actions-only message:** Keep visible text limited to recovery actions and expose detailed diagnostics through logs or a dedicated status/doctor surface.
- **Full identifiers:** Show raw session identifiers and exact-looking counts in channel messages while intentionally accepting the privacy and accuracy tradeoffs.

## Reproduction Assessment

Yes at source level. Current overflow handling has token extraction and internal diagnostics, while the documented visible recovery contract remains generic; recent production comments independently reproduce the resulting diagnostic friction.

## Solution Assessment

The direction is useful, but exposing the proposed raw session key and exact-looking counters is not the best safe implementation. A shared formatter with redacted identifiers, qualified token authority, and complete runner/precheck/sanitizer/auto-reply wiring is narrower and more maintainable.
