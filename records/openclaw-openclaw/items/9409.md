## Summary

Keep open: current main and the latest release still route context-overflow failures through generic user-visible copy, while newer diagnostics are only logged, stored in session metadata, or exposed in status paths rather than in the overflow reply itself.

## What This Changes

The issue requests a more specific context-overflow error message with session/channel identity, token counts, model limit, overage, and actionable recovery steps.

## Best Possible Solution

Add one shared privacy-safe context-overflow diagnostic formatter and wire it through the runner, precheck, formatter/sanitizer, and auto-reply fallback paths with regression coverage for every generic overflow surface.
