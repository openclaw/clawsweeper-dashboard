- `impact:session-state`: Unsupported audio can fail memory indexing and change which extraPath files become searchable memory context.

## Summary

Keep open. Current main and the latest release still advertise OGG/Opus as multimodal memory audio formats, preserve the detected audio MIME type, and pass it unchanged into Gemini embedding inlineData while the current Gemini embedding docs list audio support as MP3/WAV only.

## What This Changes

The issue asks OpenClaw to stop Gemini memory indexing from failing on OGG/Opus files under memorySearch.extraPaths, either by supporting conversion or by narrowing validation/docs.

## Best Possible Solution

Make Gemini multimodal memory audio provider-aware, with aligned docs, diagnostics, regression coverage, and live proof; only keep OGG/Opus advertised if OpenClaw owns a tested transcode path.

## Maintainer Decision

Kind: product_direction

Rationale: Both fixes are plausible, but they carry different product and dependency contracts: filtering/docs is smaller and safer, while transcode preserves advertised support but adds codec and operator behavior.

Owner confidence: high

Options:

- **Provider-aware validation first (recommended):** Skip or reject unsupported Gemini audio formats with clear diagnostics and docs, keeping transcode as a separately approved enhancement.
- **Owned transcode support:** Add a tested ffmpeg-backed OGG/Opus to WAV/MP3 normalization path, including dependency handling, diagnostics, and live Gemini proof.
- **Docs-only narrowing:** Remove unsupported audio formats from public docs and schema expectations, but this should be paired with runtime diagnostics to avoid raw provider 400s.

## Reproduction Assessment

Yes, source-level. Current main accepts .ogg and .opus, stores their detected audio MIME type, and passes it unchanged into Gemini inlineData; I did not run a live Gemini API repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the contract. Provider-aware filtering and diagnostics is the narrowest fix, while transcode is the only path that preserves the currently advertised OGG/Opus support.
