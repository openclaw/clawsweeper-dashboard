## Summary

Keep open. Current main and the latest release still advertise OGG/Opus as supported multimodal memory audio, preserve the detected audio MIME type, and pass it unchanged into Gemini inlineData, while the provider contract evidence limits Gemini embedding audio to MP3/WAV.

## What This Changes

The issue requests fixing Gemini multimodal memory indexing for OGG/Opus audio files discovered through memorySearch.extraPaths.

## Best Possible Solution

Define the Gemini-specific audio contract, then either narrow advertised support with a clear skip/error path or add an owned transcode path with provider-limit tests and docs.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Gemini multimodal memory treat OGG/Opus as unsupported input to skip/report, or should OpenClaw own an automatic transcode path to MP3/WAV before embedding?

Rationale: Both options are plausible, but they have different user-facing compatibility, dependency, and maintenance costs that automation should not choose without maintainer intent.

Likely owner: gumadeiras

Owner reason: The decision lands closest to the shipped multimodal memory extraPaths implementation and docs boundary introduced in the merged memory PR.

Owner confidence: high

Options:

- **Narrow Gemini support (recommended):** Document and enforce MP3/WAV-only audio for Gemini embeddings, with a clear non-fatal skip or diagnostic for OGG/Opus files.
- **Own transcoding:** Add an ffmpeg-backed conversion path for unsupported audio formats before Gemini embedding, including dependency detection, failure handling, and tests.
- **Defer behind broader multimodal design:** Keep this open under the broader multimodal memory direction until maintainers settle provider-specific media handling across formats.

## Reproduction Assessment

Yes. Source inspection shows OGG/Opus files are still accepted by extension, stored with their detected audio MIME type, and sent unchanged to the Gemini embedding request builder; I did not run a live Gemini request because this was a read-only review without provider credentials.

## Solution Assessment

Unclear. Provider-aware filtering is the narrowest safe repair, but satisfying the reported expectation that OGG/Opus embeds successfully would require a new transcode capability and maintainer approval.
