## Summary

Keep open: current main and v2026.6.11 still accept and document .ogg/.opus as Gemini multimodal memory audio, preserve the detected audio MIME type, and send it unchanged to Gemini inlineData while the Gemini Embeddings contract lists audio support as MP3/WAV.

## What This Changes

The issue reports that Gemini multimodal memory indexing rejects OGG/Opus audio files that OpenClaw currently treats as supported extraPaths audio.

## Best Possible Solution

Define the Gemini-specific audio contract, then either enforce MP3/WAV-only with a clear non-fatal diagnostic and docs or add an owned ffmpeg-backed transcode path with tests and live Gemini proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Gemini multimodal memory treat OGG/Opus as unsupported audio to skip/report, or should OpenClaw own automatic transcoding to MP3/WAV before embedding?

Rationale: Both choices are technically plausible but have different compatibility, dependency, and maintenance costs, so automation should not choose the public memory audio contract.

Likely owner: gumadeiras

Owner reason: The decision lands closest to the shipped multimodal memory extraPaths boundary and docs introduced through the merged multimodal memory work.

Owner confidence: high

Options:

- **Narrow Gemini Audio Support (recommended):** Document and enforce MP3/WAV-only audio for Gemini embeddings, with a clear non-fatal skip or diagnostic for OGG/Opus files.
- **Own Transcoding:** Add an ffmpeg-backed conversion path for unsupported audio formats before Gemini embedding, including dependency detection and failure handling.
- **Defer To Broader Multimodal Design:** Keep this open under the broader multimodal memory direction until provider-specific media handling is settled across formats.

## Reproduction Assessment

Yes, at source level. Current main accepts .ogg/.opus as multimodal audio, stores the detected MIME type, and passes it unchanged into the Gemini embedding request builder; no live Gemini request was run in this read-only review.

## Solution Assessment

Unclear without maintainer direction. Provider-aware MP3/WAV filtering is the narrowest safe repair, but satisfying the currently documented OGG/Opus expectation would require a maintained transcode capability.
