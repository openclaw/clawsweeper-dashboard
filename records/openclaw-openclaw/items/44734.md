## Label Justifications

- `impact:session-state`: Unsupported audio can fail memory indexing and affect which extraPath files become searchable memory context.

## Summary

Keep open. Current main and the latest release still advertise OGG/Opus for Gemini multimodal memory audio, preserve the detected audio MIME type, and pass it unchanged into Gemini inlineData, while the current Gemini embeddings documentation lists audio embedding support as MP3/WAV only.

## What This Changes

The issue requests fixing Gemini multimodal memory indexing for OGG/Opus audio files discovered through memorySearch.extraPaths.

## Best Possible Solution

Make the Gemini multimodal memory path provider-aware: either reject or skip unsupported audio with clear diagnostics and aligned docs, or approve and test an explicit transcode path if OGG/Opus should remain supported.

## Reproduction Assessment

Yes. Source inspection shows current main accepts .ogg and .opus, stores the detected audio MIME type, and passes it unchanged to Gemini inlineData; I did not run a live Gemini-keyed repro in this read-only review.

## Solution Assessment

Unclear. The source bug is clear, but the best fix requires maintainer direction between provider-aware filtering/diagnostics and an explicitly owned audio transcode path.
