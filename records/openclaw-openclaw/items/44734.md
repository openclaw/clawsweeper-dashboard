## Summary

Keep open: current main and v2026.6.11 still accept and advertise OGG/Opus for Gemini multimodal memory audio, then pass the detected MIME type unchanged into Gemini inlineData while the current Gemini Embeddings contract lists MP3/WAV audio support only.

## What This Changes

The issue reports that multimodal memory indexing sends OGG/Opus audio to Gemini embeddings and receives a provider 400 instead of embedding or documenting the unsupported format.

## Best Possible Solution

Define the Gemini-specific audio contract, then either enforce MP3/WAV-only with clear non-fatal diagnostics and docs or add an owned ffmpeg-backed transcode path with tests and live Gemini proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Gemini multimodal memory treat OGG/Opus as unsupported audio to skip/report, or should OpenClaw own automatic transcoding to MP3/WAV before embedding?

Rationale: Both choices are technically plausible but carry different public docs, dependency, provider-cost, and maintenance consequences, so automation should not choose the memory audio contract.

Likely owner: gumadeiras

Owner reason: The decision lands closest to the shipped multimodal memory extraPaths feature and public config/docs boundary introduced by PR 43460.

Owner confidence: high

Options:

- **Narrow Gemini Audio Support (recommended):** Document and enforce MP3/WAV-only audio for Gemini embeddings, with clear non-fatal skip or diagnostic behavior for OGG/Opus files.
- **Own Transcoding:** Add an ffmpeg-backed conversion path for unsupported audio formats before Gemini embedding, including dependency detection and failure handling.
- **Defer To Multimodal Design:** Keep this open under broader multimodal memory direction until provider-specific media handling is settled across formats.

## Reproduction Assessment

Yes, at source level: current main accepts OGG/Opus as multimodal audio, stores the detected MIME type, and passes it unchanged into Gemini inlineData. No live Gemini request was run in this read-only review.

## Solution Assessment

Unclear without maintainer direction. Provider-aware MP3/WAV filtering plus docs is the narrowest safe repair, but satisfying the currently documented OGG/Opus expectation would require a maintained transcode capability.
