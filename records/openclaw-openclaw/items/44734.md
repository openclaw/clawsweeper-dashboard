## Summary

Keep open: current main and v2026.6.11 still admit OGG/Opus as multimodal memory audio, preserve the detected MIME type, and pass it through to Gemini embeddings even though the current Gemini Embeddings contract only lists MP3/WAV audio support.

## What This Changes

The issue reports that Gemini multimodal memory indexing accepts OGG/Opus audio files and then fails when Gemini rejects those raw audio formats.

## Best Possible Solution

Keep the shipped multimodal memory feature, but make Gemini audio handling provider-contract safe: filter/skip unsupported raw audio with clear diagnostics and docs unless maintainers explicitly sponsor a managed transcoding path.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Gemini multimodal memory audio support be narrowed to raw MP3/WAV inputs, or should OpenClaw add a maintained transcoding path for OGG/Opus and other audio formats?

Rationale: Current code and docs promise OGG/Opus audio indexing, but satisfying that promise requires either narrowing the public contract or adding media transcoding, which is a product/dependency/security choice rather than a mechanical bug fix.

Likely owner: gumadeiras

Owner reason: The decision is closest to the multimodal memory feature and public config/docs boundary introduced by the merged image/audio indexing work.

Owner confidence: high

Options:

- **Narrow To Provider-Supported Audio (recommended):** Filter or skip non-MP3/WAV audio for Gemini embeddings with a diagnostic and update docs/tests to match the upstream contract.
- **Add Managed Transcoding:** Convert unsupported audio to WAV or MP3 before embedding, accepting the added dependency, platform, and security review burden.
- **Docs-Only Limitation:** Document that users must convert unsupported audio themselves, leaving current runtime behavior mostly unchanged except for clearer expectations.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 classify OGG/Opus as multimodal audio, preserve the detected MIME type, and send it unchanged to Gemini embeddings. I did not run a live Gemini-keyed CLI repro in this read-only cleanup pass.

## Solution Assessment

No, the submitted fix choices are not settled yet: provider-aware filtering is the narrowest safe repair, while automatic transcoding is broader and needs explicit maintainer approval. A docs-only update would reduce confusion but would not satisfy the originally advertised OGG/Opus indexing behavior.
