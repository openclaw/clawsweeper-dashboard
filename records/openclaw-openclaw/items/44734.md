## Summary

Keep open: current main and the latest stable release still accept and document OGG/Opus as Gemini multimodal memory audio, then pass the detected MIME type through to Gemini unchanged while the current Gemini Embeddings contract lists MP3/WAV audio support.

## What This Changes

The issue asks OpenClaw memory multimodal indexing to stop failing when Gemini receives OGG/Opus audio from `memorySearch.extraPaths`, either by transcoding or by narrowing validation/docs.

## Best Possible Solution

Define the Gemini-specific audio contract, then either enforce MP3/WAV-only with clear non-fatal diagnostics and docs or add an owned ffmpeg-backed transcode path with focused tests and live Gemini proof.

## Maintainer Decision

Rationale: Both fixes are technically plausible but choose different public docs, dependency, provider-cost, and maintenance contracts, so automation should not pick the memory audio policy.

Options:

- **Narrow Gemini audio support (recommended):** Document and enforce MP3/WAV-only audio for Gemini embeddings, with a clear non-fatal skip or diagnostic for OGG/Opus files.
- **Own transcoding:** Add an ffmpeg-backed conversion path for unsupported audio before Gemini embedding, including dependency detection and failure handling.
- **Defer to broader multimodal design:** Keep this issue under broader multimodal memory direction until provider-specific media handling is settled across formats.

Unclear without maintainer direction. Provider-aware MP3/WAV filtering plus docs is the narrowest safe repair, but satisfying the currently documented OGG/Opus expectation would require a maintained transcode capability.
