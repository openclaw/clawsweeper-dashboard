## Summary

Keep open: current main and the latest release still accept and document OGG/Opus as multimodal memory audio, preserve the detected MIME type, and pass it through to Gemini inlineData while Gemini's embedding docs list audio support as MP3/WAV only. The remaining decision is whether to preserve the documented support with provider-aware transcoding or narrow the Gemini audio contract and diagnostics.

## What This Changes

The issue requests fixing Gemini multimodal memory indexing so OGG/Opus files in memorySearch.extraPaths do not fail with Gemini 400 errors.

## Best Possible Solution

Keep this issue open and make Gemini memory audio provider-aware: preserve documented OGG/Opus support by transcoding to a Gemini-supported format when available, or deliberately narrow the supported list with skip diagnostics and docs if maintainers reject transcoding.

Question: Should Gemini multimodal memory preserve OpenClaw's documented OGG/Opus support by transcoding to MP3/WAV, or should OpenClaw narrow Gemini audio support to raw MP3/WAV with skip diagnostics and docs?

Rationale: Both outcomes fix the 400 error, but they set different user-facing contracts and operator dependencies for memory indexing.

Likely owner: gumadeiras

Owner confidence: high

Options:

- **Preserve support with transcode (recommended):** Keep OGG/Opus in the supported memory-audio contract, reuse the existing media-runtime/ffmpeg path to normalize unsupported Gemini audio to MP3 or WAV, and emit a clear skip diagnostic if transcoding is unavailable.
- **Narrow Gemini audio formats:** Remove or provider-filter unsupported Gemini audio formats so OGG/Opus are skipped before API calls, then update docs to say Gemini memory audio accepts only MP3/WAV raw inputs.
- **Design provider format metadata first:** Pause the fix until memory embedding providers expose per-modality supported formats, then make scanning/filtering/transcoding data-driven across providers.

## Solution Assessment

Unclear until maintainers choose the product contract. The narrow maintainable fix is provider-aware validation/transcoding in the Google memory embedding path plus docs/diagnostics, not letting unsupported raw MIME types reach Gemini.
