## Summary

Keep open: current main and v2026.6.11 still advertise OGG/Opus as Gemini multimodal memory audio, preserve the detected MIME type, and pass inline-data parts to Gemini unchanged, so the reported provider-format failure remains unresolved.

## What This Changes

The issue reports that Gemini multimodal memory indexing accepts OGG/Opus audio files under `memorySearch.extraPaths` but sends them to Gemini unchanged, where the embedding API rejects them.

## Best Possible Solution

Define the Gemini-specific audio contract, then either enforce supported audio formats with clear non-fatal diagnostics and docs or add an owned ffmpeg-backed transcode path with focused tests and live Gemini proof.
