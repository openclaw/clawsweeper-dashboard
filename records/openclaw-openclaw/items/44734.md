## Summary

Keep open: current main and v2026.6.11 still accept and document OGG/Opus as Gemini multimodal memory audio, preserve the detected MIME type, and pass it unchanged to Gemini even though the Gemini Embeddings contract only lists MP3/WAV audio support.

## What This Changes

The issue asks OpenClaw to handle or document Gemini multimodal memory indexing for OGG/Opus audio files that are accepted under memorySearch.extraPaths but rejected by Gemini.

## Best Possible Solution

Define the Gemini-specific audio contract, then either enforce MP3/WAV-only with a clear non-fatal diagnostic and docs or add an owned ffmpeg-backed transcode path with tests and live Gemini proof.

- **Defer To Multimodal Design:** Keep this open under broader multimodal memory direction until provider-specific media handling is settled across formats.
