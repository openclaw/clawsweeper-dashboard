## Summary

Keep open: current main and v2026.6.11 still advertise and accept OGG/Opus for Gemini multimodal memory, then pass the detected MIME type to Gemini unchanged while current Gemini Embeddings docs list audio support as MP3/WAV.

## What This Changes

The issue reports that Gemini multimodal memory indexing accepts .ogg/.opus files from memorySearch.extraPaths but Gemini rejects the raw audio MIME types.

## Best Possible Solution

Define the Gemini-specific memory audio contract, then either enforce MP3/WAV-only with clear non-fatal diagnostics and docs or add an owned transcode path with dependency handling, focused tests, and live Gemini proof.
