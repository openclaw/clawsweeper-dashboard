## Label Justifications

- `impact:session-state`: Unsupported audio can prevent extraPath files from being indexed into searchable memory context.

## Summary

Keep open. Current main and the latest release still advertise OGG/Opus for Gemini multimodal memory, preserve the detected audio MIME type, and send it unchanged to Gemini inline data; Google's current Gemini Embedding 2 docs list audio support as MP3/WAV only. ([ai.google.dev](https://ai.google.dev/gemini-api/docs/embeddings?utm_source=openai))

## What This Changes

Fix multimodal memory indexing so OGG/Opus audio in memorySearch.extraPaths does not fail against the Gemini embedding API.

## Best Possible Solution

Make the Gemini multimodal memory path provider-aware, with aligned docs and either clear unsupported-format handling or an explicitly approved and tested transcode path.

## Reproduction Assessment

Yes. Current main accepts .ogg and .opus as multimodal memory audio, stores the detected MIME type, and passes it unchanged to Gemini inlineData; I did not run a credentialed live Gemini request.

## Solution Assessment

Unclear. The code mismatch is clear, but the best fix needs maintainer direction between provider-aware filtering/diagnostics and an owned transcode path.
