## Summary

Keep open: current main still lacks catalog-derived model fallbacks, and this PR is the canonical implementation thread, but the patch is not merge-ready because it only updates candidate construction while existing embedded-run failover gates still read explicit fallback arrays.

## What This Changes

The PR adds an opt-in `agents.defaults.model.fallbacksFromModels` config flag, schema/docs updates, fallback candidate derivation, and focused tests for deriving text-model fallbacks from `agents.defaults.models`.

## Best Possible Solution

Unify catalog-derived fallback derivation into one effective fallback source shared by candidate construction, session override handling, embedded-run fallback availability, docs, and tests before the config flag lands.

## Reproduction Assessment

Yes. Source inspection shows the PR derives candidates in `src/agents/model-fallback.ts`, while `src/agents/embedded-agent-runner/run/fallbacks.ts` and `src/agents/agent-scope.ts` still compute fallback availability from explicit fallback arrays only.

## Solution Assessment

No. The helper-level derivation is a plausible piece, but the best fix is a single shared effective-fallback source used by both candidate construction and all failover gates.
