## Best Possible Solution

Make the effective fallback source shared or otherwise keep candidate construction and `fallbackConfigured` detection in sync, then validate the opt-in config with both focused tests and redacted real runtime proof.

## Reproduction Assessment

Yes. Source inspection shows the PR derives candidates in `src/agents/model-fallback.ts`, while embedded-run fallback availability is still computed from explicit fallback arrays in `src/agents/agent-scope.ts` and `src/agents/embedded-agent-runner/run/fallbacks.ts`.

## Solution Assessment

No, not as-is. The helper-level derivation is a plausible piece, but the best fix is one effective fallback contract used by both candidate construction and all failover gates.
