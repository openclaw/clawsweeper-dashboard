## Summary

Keep open: current main still lacks catalog-derived model fallbacks and this PR contains coherent unique work, but it is not merge-ready because the embedded-run fallback gate still ignores the derived candidates and real behavior proof is only test-based.

## What This Changes

The PR adds an opt-in `agents.defaults.model.fallbacksFromModels` config flag, schema/docs coverage, and tests so default model fallback candidates can be derived from `agents.defaults.models` when explicit fallbacks are omitted.

## Best Possible Solution

Use one shared fallback-availability and candidate contract so explicit fallbacks, explicit empty disables, and catalog-derived fallbacks drive both candidate construction and embedded-run failover decisions, then prove it with a redacted real run.

## Reproduction Assessment

Yes by source inspection. The PR derives catalog fallback candidates in `resolveFallbackCandidates`, but current embedded-run failover still computes availability from explicit fallback arrays before allowing `fallback_model`.

## Solution Assessment

No as submitted. Candidate derivation is a useful piece, but the best fix is to share the same effective fallback contract with embedded-run availability gates and then prove the opt-in path in a real run.
