## Summary

Keep open: this PR is the right canonical place for catalog-derived default model fallbacks, but it is not merge-ready because the production agent path can pass an empty fallback override before the new derivation branch runs, and the embedded-runner fallback gate still needs to understand the derived fallback source.

## What This Changes

Adds an opt-in `agents.defaults.model.fallbacksFromModels` config field with schema/docs/tests so default text-model fallbacks can be derived from `agents.defaults.models` when explicit fallbacks are omitted.

## Best Possible Solution

Make omitted explicit fallbacks distinguishable from `fallbacks: []` across the production agent caller, candidate resolver, and embedded-runner fallback availability gate, then require real fallback proof before merge.

## Reproduction Assessment

Yes. Source inspection of the PR head shows omitted explicit fallbacks can become an empty `fallbacksOverride` before `resolveFallbackCandidates` checks `fallbacksFromModels`.

## Solution Assessment

No. The current patch is a plausible helper-level implementation, but it misses the normal production caller and embedded-runner fallback-availability gate, so it is not the best complete fix yet.
