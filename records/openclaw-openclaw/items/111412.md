## Summary

This remains a valid WebChat product request. Current related work adds reply context, but it does not provide transcript editing, message-level branching, or a one-click rerun; the requested behavior needs an explicit maintainer decision on durable transcript and branch semantics before implementation.

## What This Changes

Add Control UI/WebChat controls to edit a sent user message, optionally reprocess it on a new branch, and regenerate an assistant response from the preceding prompt.

## Best Possible Solution

Define a message-level branch/replay contract first, then implement WebChat controls against that canonical gateway and session-history model rather than adding ad hoc flags to `chat.send`.

## Maintainer Decision

Question: Should WebChat edits be immutable branch-and-reprocess operations only, or should the product also permit save-only mutation of persisted conversation history?

Rationale: The two requested modes have materially different transcript integrity, history visibility, and agent-context consequences; current reply-context work does not establish this contract.

Options:

- **Branch-only edits (recommended):** Treat edits and regeneration as a new branch from the selected user turn, preserving the original transcript unchanged.
- **Allow save-only transcript mutation:** Permit typo-only edits in place, with explicit audit and UI semantics for changed historical content.
- **Defer until session-history policy is defined:** Keep the request open but do not add WebChat UI or gateway parameters until the durable history model is agreed.
