## Summary

This remains a valid WebChat product request: the recent reply-context work and existing session-fork concept do not provide message-level editing or a one-click alternative response. It needs maintainer direction on transcript mutation and branch semantics before implementation.

## What This Changes

Request WebChat controls to edit sent user messages and regenerate an assistant response, with history-only edits and branch-based reprocessing as separate modes.

## Best Possible Solution

Define a transcript-preserving branch workflow for edit-and-reprocess and a separate regenerate action, then expose the smallest explicit gateway/protocol operations needed by the Control UI rather than overloading ordinary message sending with ambiguous edit flags.

- **Support regenerate only:** Add a bounded alternative-response action first and defer history editing until transcript-mutation semantics are approved.
- **Keep session-level fork only:** Decline message-level controls for now and document the existing fork workflow as the supported alternative.
