## Summary

Keep open: the index-callback direction and Telegram Desktop proof address the visible silent-drop bug, but the current fingerprint still hashes model names without boundaries, so stale same-count model lists can pass the guard and select the wrong model.

## What This Changes

The branch replaces Telegram /model picker name-based selection callbacks with provider/page/index/count/fingerprint callbacks, preserves legacy callback parsing, and updates Telegram model-button tests.

## Best Possible Solution

Land one Telegram fix that uses length-safe index callbacks, preserves legacy callback parsing, and hashes an unambiguous full model-list representation with regression coverage.

## Reproduction Assessment

Yes. Current main and v2026.6.11 are source-reproducible: an over-limit compact model callback returns null and the keyboard skips that row while the header can still report the full model count; Mantis screenshots also show the before/after picker behavior.

## Solution Assessment

No. Index-based callback data is the right owner-boundary fix, but this implementation needs an unambiguous full-list fingerprint before stale index callbacks are safe to accept.
