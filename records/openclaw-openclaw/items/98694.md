## Summary

Keep open: this is a focused Telegram bug-fix PR with useful before/after Telegram proof and restored legacy callback parsing, but the new stale-button fingerprint only covers first model, last model, and count, so a same-count provider list change can still resolve an old index button to the wrong model before writing the session override.

## What This Changes

The PR replaces Telegram model-picker select callbacks with provider/page/index/count/fingerprint callback data, keeps legacy model-name callback parsing, and updates Telegram model-button tests.

## Best Possible Solution

Land one candidate that keeps callback_data under Telegram's limit, preserves legacy name-based callbacks, and binds index callbacks to a stable full model-list snapshot or selected model identity with regression coverage.

## Reproduction Assessment

Yes. Current main and v2026.6.11 are source-reproducible: an over-limit compact model callback returns null and the keyboard skips that row while the header can still report the full model count.

## Solution Assessment

No. Index-based callback data is the right direction, but this implementation's fingerprint is too weak for same-count same-boundary model list changes, so it needs a narrow repair before merge.
