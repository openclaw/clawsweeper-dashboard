## Label Justifications

- `P2`: This fixes a bounded Telegram model-picker bug that makes valid long-named models unavailable through the inline picker.
- `merge-risk: 🚨 compatibility`: The PR changes callback generation for every model button while old Telegram keyboards can remain clickable across an upgrade.
- `merge-risk: 🚨 session-state`: Selections become dependent on the current sorted catalog, count, and compact fingerprint rather than carrying the selected model directly.
- `merge-risk: 🚨 auth-provider`: A stale or colliding indexed callback could resolve to the wrong provider model and change the session's active model selection.

## Summary

Keep open for a maintainer choice: the bug remains on current main and this patch is well-proven, but it competes with a narrower fallback-only implementation and changes every newly generated model callback into list-dependent state.

## What This Changes

Replaces Telegram model-selection callback generation with provider/page/index/count/fingerprint payloads, retains legacy callback parsing, and updates model-picker tests.

## Best Possible Solution

Keep name-based callbacks when they fit, use a token-bound indexed fallback only for over-limit models, retain parsing for already-sent legacy keyboards, and land one canonical PR for https://github.com/openclaw/openclaw/issues/98221.
