## Summary

Keep open: this is a useful candidate fix with sufficient Telegram proof, but the latest full-list fingerprint still has a deterministic collision because model names are hashed back-to-back without separators, so stale callbacks can still resolve and write the wrong model.

## What This Changes

The branch replaces Telegram /model picker model-name callback_data with provider/page/index/count/fingerprint callbacks, preserves legacy callback parsing, and updates Telegram model-button tests.

## Best Possible Solution

Land one Telegram candidate that uses length-safe index callbacks, preserves legacy callback parsing, and hashes an unambiguous full model-list representation with regression coverage.

## Reproduction Assessment

Yes. Current main and v2026.6.11 are source-reproducible: an over-limit compact model callback returns null and the keyboard skips that row while the header can still report the full model count.

## Solution Assessment

No. Index-based callback data is the right owner-boundary fix, but this implementation needs an unambiguous full-list fingerprint before stale index callbacks are safe to accept.
