## Summary

Keep open: the central Telegram approval guidance fix is useful and source-reproducible, but the current head can still classify an accepted request as `approval-client` before any prompt is actually delivered, which can hide the setup guidance this PR is meant to add.

## What This Changes

The PR changes agent, gateway, plugin SDK, Telegram, docs, and approval tests so Telegram-originated plugin approval failures can append channel setup guidance using a plugin-specific setup hook and gateway delivery-route marker.

## Best Possible Solution

Land the Telegram setup-guidance fix after the delivery route marker distinguishes actually delivered approval clients from visible-but-skipped native runtimes, while preserving plain timeout text for real Web UI or delivered prompt timeouts.

## Solution Assessment

No for the current head. The setup-guidance hook is the right layer, but the route classifier is still too coarse because it treats visible approval clients as delivered before proving the request was handled.
