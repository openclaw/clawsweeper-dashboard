## Summary

Keep this PR open for revision. The recovery intent is valuable, but the new automatic continuation treats most failed tools as safe to resume even though a failed tool can have already performed an external action; it also still needs inspectable after-fix runtime proof.

## What This Changes

The branch changes embedded agent-run recovery so interrupted provider streams, unfinished finalization hooks, failed tool attempts, and a background-process race are handled as incomplete work rather than successful completed turns.

## System Context

The embedded agent runner turns model-stream output and tool activity into a final reply for a user session. It records terminal state, applies harness finalization decisions, and can retry an incomplete attempt from the persisted transcript before delivery.

## Architecture Diagram

flowchart LR

  B --> C[Terminal-state classification]
  C --> D{Completed delivery?}
  D -->|No| E[Persisted-transcript continuation]
  E --> B
  D -->|Yes| F[Final user reply]
  B --> G[Harness finalization hook]

## Best Possible Solution

Keep automatic continuation limited to attempts that carry a generic, trustworthy no-side-effect/idempotency signal; otherwise surface the tool failure without asking the model to continue, then add redacted runtime proof for the guarded recovery path.
