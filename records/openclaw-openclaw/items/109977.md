## Summary

Keep this PR open, but do not merge it yet. It extends the owner-isolation foundation from https://github.com/openclaw/openclaw/pull/101265 in the right direction, but the shared-default collection logic appears to associate an inherited SecretRef with only one agent owner, leaving other inheriting agents outside the degraded-owner guard; the PR also lacks after-fix proof from a real Gateway run.

## What This Changes

The PR scopes memory-search SecretRef degradation to individual agents and changes OpenAI-compatible and GitHub Copilot embedding adapters to consume prepared credential literals without runtime re-resolution or implicit fallback.

## Best Possible Solution

Represent each agent’s effective inherited memory credentials as an owner-scoped assignment, mark every affected inheriting agent unavailable, preserve literal-only adapter consumption, and prove that a real Gateway reaches readiness while healthy agents continue and each cold agent fails with the typed owner error.

## Reproduction Assessment

No live reproduction was executed, but the defect is source-reproducible with two enabled agents inheriting the same missing defaults API key or header: only one agent-specific owner can be attached by the once-only collection logic.

## Solution Assessment

No, not yet. Per-agent owner IDs and prepared literals are the correct boundaries, but deduplicating a shared defaults assignment by config path does not model every inheriting agent and needs a per-effective-agent representation.
