## Summary

Keep this PR open: the current patch still validates a pathname before reopening that pathname for an unbounded read, so the claimed memory cap can be bypassed by a file change; it also introduces new hard 100 MiB and 500 MiB CLI rejection limits without an established compatibility contract. The supplied Vitest result is useful supplemental validation, but no after-fix real capability-CLI run is shown.

## What This Changes

The PR changes capability-CLI `--file` handling from concurrent unbounded reads to sequential reads with a 100 MiB per-file limit and a 500 MiB invocation-wide budget.

## Best Possible Solution

Use a single opened file handle and bounded reads that never consume more than the validated byte count, then land only a size envelope that maintainers explicitly support and document for capability-CLI inputs.
