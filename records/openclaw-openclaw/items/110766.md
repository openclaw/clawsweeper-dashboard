## Summary

Keep this PR open for repair: the descriptor-sized reader changes supported Node input behavior for non-regular files, so it can silently supply an empty buffer where the existing `fs.readFile` path reads available data. The submitted terminal proof exercises a regular PNG through a mock provider but does not establish the claimed hardening outcome or this compatibility edge case.

## What This Changes

The branch replaces capability-CLI media reads with an explicit `open`/`stat`/manual-read helper and adds three focused tests for regular-file inputs.

## Best Possible Solution

Restore the established `fs.readFile` path unless maintainers can name a concrete descriptor-bound requirement that also preserves Node’s regular and non-regular input semantics with focused cross-platform proof.
