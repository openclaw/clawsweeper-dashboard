## Summary

Keep this PR open for maintainer review: it introduces a new hard capability-CLI file-size contract without an established compatibility decision, and its descriptor read can still exceed the size validated from the descriptor if that same file grows before `readFile()` completes.

## What This Changes

The branch replaces concurrent path-based capability-CLI media reads with sequential descriptor-bound reads and adds 100 MiB per-file plus 500 MiB aggregate input budgets.

## Best Possible Solution

First decide whether capability-CLI should enforce a documented file-input limit; if approved, read exactly the validated byte count from the opened descriptor with a partial-read loop and add regression coverage for same-inode growth, otherwise preserve the existing unlimited input contract and separate any policy proposal from this security hardening.
