## Summary

The patch adds a manual reader for a safety property already provided by the supported `fs.readFile` path, and its size-first loop changes behavior for non-regular or pseudo-files whose descriptor size is zero but whose readable content is not. The nominal image-edit transcript is useful smoke evidence, but it does not prove the claimed hardening outcome or justify replacing the existing reader.

## What This Changes

The PR replaces `fs.readFile` in capability-CLI media input handling with an explicit `open`/`stat`/buffered `read` loop while retaining `Promise.all` scheduling.

## Best Possible Solution

Retain the established `fs.readFile` implementation unless maintainers identify a concrete supported threat model that requires a descriptor-specific API; if that requirement exists, use the native file-handle whole-file read path and add focused compatibility coverage for regular and special inputs.
