## Label Justifications

- `P2`: The patch changes a bounded CLI media-input path and can silently produce invalid empty input for a supported Node file type, but it is not an urgent system-wide outage.
- `merge-risk: 🚨 compatibility`: The manual size-bound reader no longer preserves `fs.readFile` behavior for unknown-size readable descriptors.

## Summary

This PR is still necessary only if it preserves the established `fs.readFile` input contract. The current manual `stat.size` allocation makes unknown-size readable inputs return an empty buffer, so the patch should not merge as written.

## What This Changes

The PR replaces capability-CLI media `fs.readFile` calls with an explicitly opened descriptor reader and adds focused media-input tests.

## Best Possible Solution

Keep the explicit open/close boundary only if needed, but delegate the read to `FileHandle.readFile()` and add regression coverage for an unknown-size input so the CLI retains Node’s established reader behavior.

## Solution Assessment

No. `FileHandle.readFile()` on the explicitly opened handle is the narrower maintainable solution because it preserves the descriptor boundary while retaining Node’s regular-file and unknown-size-input behavior.
