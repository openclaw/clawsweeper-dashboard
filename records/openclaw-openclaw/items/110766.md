## Summary

Keep this PR open: descriptor-bound metadata checks remove the pathname swap, but the patch still allows an opened regular file to grow beyond its validated size during `FileHandle.readFile()`, and it introduces new hard limits that change an existing CLI input contract without maintainer approval.

## What This Changes

The PR changes capability-CLI media input loading to open each file once, validate it through that descriptor, and enforce 100 MiB per-file plus 500 MiB aggregate budgets.

## Best Possible Solution

First obtain maintainer approval for the intended capability-CLI size policy; then read exactly the descriptor-validated byte count with a bounded loop, preserve the approved aggregate semantics, and add focused behavior coverage and redacted runtime proof.
