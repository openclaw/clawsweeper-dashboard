## Summary

Keep this PR open: its memory-safety goal is useful, but the proposed fixed input caps change previously accepted CLI behavior without an established compatibility contract, and the stat-then-read path can still read an oversized replacement or grown file. It also still needs real after-fix CLI evidence rather than test output alone.

## What This Changes

The branch changes capability-CLI `--file` handling from concurrent unbounded reads to sequential reads with a 100 MiB per-file limit and a 500 MiB aggregate budget.

## Best Possible Solution

Use descriptor-bound, byte-limited reads that cannot allocate beyond the approved bound, then land only an explicitly approved and documented capability-CLI input-size contract with real command evidence for normal, per-file-limit, and aggregate-limit cases.
