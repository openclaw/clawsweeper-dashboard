## Summary

Keep this PR open: it addresses the reported digit-run examples, but the replacement regex still mistakes punctuation-delimited numbers for HTTP status codes, so the central false-positive class is only partially fixed.

## What This Changes

The branch restricts retryable status-number matches with word boundaries, adds daily and multi-hour quota exclusions, and adds focused classifier tests.

## Best Possible Solution

Recognize numeric retries only when the error contains actual HTTP status structure, reusing the existing parser where appropriate, while retaining explicit transient phrases and the new long-window quota exclusions; cover punctuation-delimited identifiers and prove permanent-versus-transient behavior in a redacted live run.
