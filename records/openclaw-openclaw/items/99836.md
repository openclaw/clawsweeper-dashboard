## What This Changes

The PR changes Slack interactive reply parsing to strip an optional style suffix before splitting choices on the last colon, and adds regression tests for colon-bearing button labels.

## Best Possible Solution

Make the multi-colon directive grammar explicit before merge: preserve existing colon-containing callback values while supporting time labels, or get maintainer approval plus docs/tests for intentionally moving legacy directives to last-colon semantics.

## Reproduction Assessment

Yes, from source inspection: current main uses the first colon as the delimiter, so a label containing a time like `9:00` is truncated and the value starts with the minutes. I did not execute tests because this review is read-only.

## Solution Assessment

No as written. The last-colon split fixes the reported time-label case, but it also changes existing colon-containing callback values, so the best fix needs compatibility coverage or an explicit maintainer-approved grammar change.
