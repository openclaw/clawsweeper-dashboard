## Summary

Keep open. Current main still has queue-level delivery recovery and adapter receipts, but it does not provide the requested durable transcript-entry to provider-message receipt ledger, per-entry client delivery status, or origin-delivery reconciler.

## What This Changes

The issue requests durable delivery receipts, per-entry delivery status, and origin-channel reconciliation for channel-scoped transcript entries.

## Best Possible Solution

Design one generic SQLite-backed delivery ledger keyed by transcript entry and expected channel target, feed it from outbound receipts and recovery outcomes, expose it through session/Gateway APIs and Control UI, and let adapters add reconciliation capability without duplicating queue state.
