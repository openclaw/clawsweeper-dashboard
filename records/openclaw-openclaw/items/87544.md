## Summary

Keep open. Current main has durable SQLite delivery queues, adapter message receipts, and queue recovery for ambiguous sends, but it still does not provide the requested transcript-entry to provider-message receipt ledger, per-entry delivery status, or origin-delivery reconciler.

## What This Changes

The issue asks OpenClaw to keep channel-scoped session transcripts and client-visible channel delivery consistent by recording durable delivery receipts, exposing per-entry delivery state, and reconciling missing origin deliveries.

## Best Possible Solution

Define one channel-generic SQLite-backed receipt ledger keyed by transcript entry and expected channel target, feed it from outbound send/recovery receipts, expose per-entry status through session/Gateway APIs and Control UI, and add adapter reconciliation without duplicating queue state.

## Reproduction Assessment

No live end-to-end reproduction was run in this read-only review. Source inspection gives a high-confidence way to verify the remaining product gap: queue rows lack transcript/provider receipt fields, successful rows are deleted on ack, and recovery is queue-state based rather than transcript-origin reconciliation.

## Solution Assessment

Unclear until maintainers choose the durable contract. The requested direction is right, but the best implementation should extend the existing SQLite/outbound recovery lifecycle rather than add a sidecar that can drift.
