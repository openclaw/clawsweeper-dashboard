## Summary

Keep open. Current main still has queue-local recovery and some delivery health visibility, but it does not provide the requested transcript-entry-to-provider-message receipt, per-entry delivery state, or transcript-keyed origin reconciler.

## What This Changes

The issue asks OpenClaw to track and reconcile delivery state for channel-scoped assistant outputs from durable transcript entries to the originating client/channel message.

## Best Possible Solution

Design one SQLite-backed delivery ledger keyed by transcript entry and expected channel target, feed it from the outbound send/recovery lifecycle, and expose per-entry delivery state through session/Gateway APIs and Control UI.
