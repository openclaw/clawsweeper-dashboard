## Summary

Keep open. Current main has queue-level recovery, channel message receipts, and transcript mirror markers, but it still does not provide the requested durable transcript-entry to provider-message receipt ledger, per-entry client-delivery status, or origin-delivery reconciler.

## What This Changes

The issue asks OpenClaw to make channel-scoped session transcripts and originating client/channel delivery state consistent by tracking delivery receipts, surfacing per-entry status, and supporting idempotent reconciliation.

## Best Possible Solution

Design one generic SQLite-backed delivery ledger keyed by transcript entry and expected channel target, feed it from outbound send/recovery receipts, expose it through session/Gateway APIs and Control UI, and let channel adapters add reconciliation capability without duplicating queue state.
