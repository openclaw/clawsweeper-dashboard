## Summary

Keep open. Current main still lacks the durable transcript-entry to provider-message receipt, per-entry delivery status, and origin-delivery reconciler requested here; the open related PR is only a queue-recovery mitigation and explicitly leaves this broader design open.

## What This Changes

The issue requests durable transcript-to-client delivery receipts, delivery-state surfacing, and reconciliation for channel-scoped sessions whose assistant transcript entries should appear in the originating channel.

## Best Possible Solution

Design one generic SQLite-backed delivery ledger keyed by transcript entry and expected channel target, feed it from outbound send/recovery receipts, expose it through session/Gateway APIs and Control UI, and let channel adapters add reconciliation capability without duplicating queue state.
