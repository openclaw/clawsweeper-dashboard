## Summary

Keep open. Current main still lacks the requested durable transcript-entry to provider-message receipt ledger, per-entry client-delivery status, and transcript-keyed origin-delivery reconciler; recent queue, health, and mirror work is useful but does not close the central gap.

## What This Changes

The issue asks for a durable channel-scoped delivery-state layer linking transcript entries to expected client/channel delivery and reconciliation outcomes.

## Best Possible Solution

Design one generic SQLite-backed delivery ledger keyed by transcript entry and expected channel target, feed it from outbound send/recovery receipts, expose it through session/Gateway APIs and Control UI, and let channel adapters add reconciliation capability without duplicating queue state.
