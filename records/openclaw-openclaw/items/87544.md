## Summary

Keep open. Current main has durable queue recovery, channel message receipt types, health dead-letter counts, and transcript mirror markers, but it still lacks the requested transcript-entry to provider-message receipt ledger, per-entry delivery state, and origin-delivery reconciler.

## What This Changes

Requests a channel-generic delivery receipt and reconciliation layer that links transcript assistant entries to the originating client/channel delivery result.

## Best Possible Solution

Design one SQLite-backed delivery ledger keyed by transcript entry and expected channel target, feed it from outbound send and recovery receipts, expose it through session/Gateway APIs and Control UI, and let channel adapters add reconciliation capability without duplicating queue state.

- **Split Runtime And UI Work:** Create separate maintainer-owned runtime-ledger and Control UI follow-up items if the complete design is too large for one implementation lane.

No live current-main reproduction of a missing Discord message was run. Source inspection gives high-confidence verification that the requested transcript-entry receipt ledger, per-entry delivery status, and origin reconciler are absent on current main.

## Solution Assessment

Unclear until maintainers choose the durable contract. The requested direction is appropriate, but the best implementation should extend the existing SQLite/outbound recovery lifecycle rather than add a sidecar that can drift.
