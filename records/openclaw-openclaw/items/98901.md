## What This Changes

The PR changes `config set --merge` so provider-object merges preserve and update `models.providers.<id>.models` rows by normalized model id, with regression coverage.

## Best Possible Solution

Land the focused config CLI fix after exact-head CI and maintainer acceptance of additive `--merge` semantics, keeping destructive model-list changes explicit through replacement paths.

## Reproduction Assessment

Yes from source inspection: current main only merges model arrays at the exact `models.providers.<id>.models` path, so a provider-object merge assigns the child array and can drop omitted rows. I did not run a local mutating repro because this review is read-only.

## Solution Assessment

Yes: `mergeConfigValue` owns `config set --merge` semantics, and the PR extends the existing protected model-array merge at the recursion boundary before write-time model-id normalization. A later write-preparation fix would be less precise because it would see only the already-clobbered array.
