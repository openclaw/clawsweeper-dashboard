- `P0`: The defect can silently and permanently delete cron history belonging to an unrelated configured store.

## Summary

The report identifies a concrete current-main retention defect that can silently delete cron history from an unrelated configured store. The open linked fix PR specifically addresses the same store-partition mismatch, so this issue should remain open until that PR is reviewed and merged.

## What This Changes

Scope the 2,000-run cron history retention cap by configured store and job ID instead of job ID alone.

## Best Possible Solution

Land the linked fix after confirming retention buckets use both canonical storeKey and sourceId, legacy rows without storeKey remain deterministic, and regression coverage proves same-store overflow still prunes while unrelated stores remain untouched.
