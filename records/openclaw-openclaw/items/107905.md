## Summary

This is a useful root-cause-oriented fix, but it is not merge-ready: the new shared regex also rejects negative decimal strings that `toNumber()` currently accepts, and the PR provides unit-test evidence rather than after-fix Control UI behavior proof.

## What This Changes

Changes the shared Control UI `toNumber()` helper to accept only unsigned plain-decimal strings and adds focused unit coverage for accepted and rejected syntax.

## Best Possible Solution

Use one explicitly named plain-decimal parser for the intended form fields, preserve signed decimal behavior where the generic helper promises number conversion, reconcile the overlap with https://github.com/openclaw/openclaw/pull/107480, and prove the resulting Control UI save and validation paths live.
