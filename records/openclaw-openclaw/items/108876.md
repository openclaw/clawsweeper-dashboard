## Summary

Keep this PR open: the timeout belongs at the proxy fetch boundary, but the current head still mishandles aborts that occur after downstream headers are sent and contains no contributor-supplied real behavior proof.

## What This Changes

Adds an `AbortSignal.timeout(...)` deadline to the Anthropic prompt-proxy upstream fetch.

## Best Possible Solution

Keep the single fetch deadline, but make timeout handling response-phase-aware: return a 502 only before headers are sent, otherwise terminate the partially written response or socket, then prove both pre-header and mid-body stalls with a redacted terminal transcript.
