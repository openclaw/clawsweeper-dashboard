## Summary

This PR should stay open: the timeout primitive is appropriate, but the new abort can occur after upstream headers have been forwarded, and the catch path then attempts to send a second status line instead of safely terminating the downstream response. Required after-fix real behavior proof is also absent. citeturn7view0turn20search0

## What This Changes

Adds an `AbortSignal.timeout(...)` boundary to the Anthropic prompt-proxy upstream fetch in `scripts/anthropic-prompt-probe.ts`.

## Best Possible Solution

Keep the fetch abort signal, but branch on `res.headersSent`: send a 502 only before headers, otherwise destroy or end the downstream response, then prove controlled stalls both before and after upstream headers in direct and gateway modes.
