## Summary

Keep this PR open for a focused follow-up: the reported real-machine evidence is strong, but the proposed path-based `statSync` check does not bind the checked file to the later `readFileSync` call, so a replacement between the two operations can bypass the intended allocation bound. The new 1 MiB hard limit also changes startup behavior for previously valid MXC configurations and needs explicit maintainer acceptance or upgrade guidance.

## What This Changes

This PR adds a 1 MiB pre-read size limit for MXC sandbox policy files and a regression test for oversized files.

## Best Possible Solution

Load the policy through one opened file descriptor, obtain its size from that descriptor before reading it, and land the cap only after maintainers confirm the intended upgrade behavior for already-valid large policy files.
