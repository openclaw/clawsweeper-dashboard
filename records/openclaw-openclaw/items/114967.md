## Summary

Keep this issue open. A release before the report already added macOS deep-status/doctor detection for leftover `ai.openclaw.update.*` jobs, but the reported ad-hoc label is `ai.openclaw.update-validator...` and the requested live-updater skill boundary remains unverified against current `main`; that is enough remaining scope to avoid an implemented-on-main close.

## What This Changes

Add safeguards to the agent-driven live-update flow so it cannot leave a persistent launchd keepalive job that repeatedly restarts the managed gateway, and make recovery visible to operators.

## System Context

The live-updater skill directs agents maintaining a source-checkout Gateway through a deterministic update script and managed LaunchAgent handoff. A separate persistent launchd job can sit outside that managed path, repeatedly invoke gateway restart, and make the Gateway unavailable until status or doctor surfaces the extra job.

## Architecture Diagram

flowchart LR
  A[Agent following live-update skill] --> B[Deterministic update flow]
  B --> C[Managed Gateway LaunchAgent]
  C --> D[Gateway health and deep status]
  A --> E[Ad-hoc persistent launchd job]
  E --> F[Repeated gateway restarts]
  D --> G[Doctor and operator recovery guidance]

## Best Possible Solution

Keep the deterministic update path as the sole restart mechanism, add an explicit live-updater prohibition on persistent ad-hoc launchd jobs and restart-then-verify watchdogs, and extend diagnostics only if current matching does not identify this noncanonical validator label with safe recovery guidance.
