## Summary

Current main exposes the reported unhandled ChildProcess error path, and the Node.js contract confirms that a failed spawn can terminate the parent when no error listener exists. The patch appears correct, but this external PR remains proof-blocked because its evidence is limited to unit-test output and does not demonstrate the failed-spawn behavior in a real CLI run.

## What This Changes

The PR attaches an error listener to the ACP debug client's spawned server process and logs process errors through its existing verbose logger.

## Best Possible Solution

Keep the listener at the process-owner boundary and demonstrate that a missing or non-executable `--server` produces a clear nonzero CLI failure without an uncaught exception or hang, with focused regression coverage if practical.
