## Summary

Keep this issue open for security-owner review. Current main still intentionally turns a detected stale lock into a fail-closed approvals fallback, so the reported post-crash exec outage remains source-reproducible; however, unconditional unlink-and-retry conflicts with the existing TOCTOU protection and needs an owner-approved recovery design.

## What This Changes

Recover or safely diagnose a definitely-stale `exec-approvals.json.lock` so a crashed container does not leave subsequent exec calls permanently denied.

## Best Possible Solution

Retain fail-closed behavior until the lock owner approves a race-safe stale-lock recovery protocol or an explicit operator-facing Doctor recovery that verifies and removes only the abandoned lock, with sync/async and shared-state tests.
