## Label Justifications

- `merge-risk: 🚨 message-delivery`: The patch deliberately changes outbound delivery behavior during a disconnected transport from silent apparent success to an explicit failure.

## Summary

This PR remains necessary: it changes IRC disconnect-window sends from a silent no-op with false delivery telemetry into an explicit delivery failure. The client-boundary guard plus the monitor null guard is the right layered fix, and no discrete correctness defect is evident in the final patch; it should remain open for normal maintainer merge review.

## What This Changes

The PR rejects IRC `sendPrivmsg` calls when the client is unready, closed, or has a destroyed socket, preserves monitor success telemetry only after a successful send call, and adds real loopback disconnect regression coverage.

## Best Possible Solution

Land the guarded client send boundary with the monitor null guard, retaining the loopback peer-disconnect and local-close regression coverage so IRC delivery is either sent or reported failed rather than falsely recorded as delivered.
