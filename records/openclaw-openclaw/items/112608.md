## Summary

Keep this feature request open. Current Skill Workshop guidance treats scan failures as a security decision point, while the requested visibility and recovery lifecycle remain a distinct product/security design problem; the related scanner-policy and proposal-restoration reports overlap but do not fully own this combined request.

## What This Changes

Add visible Skill Workshop scan findings before apply and a security-preserving recovery path for proposals quarantined by a later scan.

## System Context

Skill Workshop turns a proposed skill bundle into an applied local skill through a gateway-backed review and security-scan lifecycle. Proposal content and scanner findings feed the workshop UI and gateway actions, which either apply the bundle or quarantine it when the scan blocks it.

## Architecture Diagram

flowchart LR
  A[Proposed skill bundle] --> B[Security scan]
  B --> C[Proposal record and findings]
  C --> D[Skill Workshop UI]
  D --> E[Apply or revise decision]
  E --> F[Gateway lifecycle action]
  F --> G[Applied skill or quarantine state]

## Best Possible Solution

Add visible scan findings and a security-preserving revise/retry lifecycle that retains quarantine audit data, requires a fresh successful scan before apply, and exposes recovery only under an explicit maintainer-approved authorization model.

Options:

- **Approve guarded revise-and-retry (recommended):** Show findings and allow an authorized user to reopen the proposal for revision, but keep quarantine history and require a new clean scan before it becomes applicable again.
- **Allow an audited manual restore:** Permit an explicitly authorized restore to pending while preserving findings and forcing the normal apply-time scan, accepting a broader operator-controlled recovery path.
- **Keep quarantine terminal:** Expose detailed findings but retain the current terminal quarantine behavior, requiring users to create a new proposal after remediation.
