## Summary

Keep this PR open, but it is not a fix for the linked report as written: current main already maps `zai` to `ZAI_API_KEY`, and this branch preserves that lookup while only adding the separate legacy spelling `Z_AI_API_KEY`. The reported regular-agent failure occurs with `ZAI_API_KEY` and no stored auth profile, so the agent auth-resolution path still needs to be traced and proven.

## What This Changes

The branch changes Z.AI credential discovery so `zai` accepts `ZAI_API_KEY` first and `Z_AI_API_KEY` as an additional fallback.

## System Context

OpenClaw's shared AI package maps a provider ID to environment-variable candidates for API-key discovery. That result must reach the agent-specific authentication resolver so regular agent runs can authenticate a selected provider without an unnecessary stored profile.
