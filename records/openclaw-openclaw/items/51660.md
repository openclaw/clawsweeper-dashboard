## Summary

Keep open: current main and v2026.6.11 still lack a configurable permission policy for agent-created user-facing files, and the requested fix crosses a security-sensitive config boundary that needs maintainer product/security direction.

## What This Changes

Add an operator-configurable umask or file/directory mode policy for agent-created user-facing files without loosening private OpenClaw state.

## Best Possible Solution

Define an opt-in user-output filesystem permission policy at the tools/runtime boundary, keep restrictive defaults for private OpenClaw state, and test host Write/Edit, sandbox bridge, exec, and apply_patch behavior together.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 accept only tools.fs.workspaceOnly, host writes use fs.writeFile without a mode, and the sandbox write contract has no mode field. I did not run a live Docker/Unraid reproduction in this read-only review.

## Solution Assessment

Unclear as a final implementation. A configurable policy is plausible, but maintainers need to settle the exact config shape and the boundary between user-facing output and private OpenClaw state before a fix PR.
