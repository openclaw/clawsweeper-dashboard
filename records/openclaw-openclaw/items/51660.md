## Summary

Keep open: current main and the latest release still lack a configurable user-output file-permission policy, and the remaining work is a security-sensitive config/product decision rather than conservative cleanup.

## What This Changes

The issue requests configurable umask or file-mode handling for agent-created, user-facing files so shared Docker/NAS deployments can avoid post-write permission repair.

## Best Possible Solution

Define an opt-in user-output filesystem permission policy at the tools/runtime boundary, keep private OpenClaw state at restrictive modes, and cover host Write/Edit, apply_patch, sandbox bridge, exec-created output, media, docs, and regression proof together.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 have no tools permission policy key, and central host, apply_patch, and sandbox write paths do not carry a configurable mode option; no live Unraid/NAS run was performed in this read-only review.

## Solution Assessment

Unclear as a final implementation. A configurable user-output policy is plausible, but maintainers need to choose the exact boundary and avoid broad sensitive-state chmod changes before a safe fix can land.
