## Summary

Keep open: current main and v2026.6.11 still lack a configurable permission policy for agent-created user-facing output, and the remaining work needs maintainer product/security direction rather than conservative cleanup.

## What This Changes

The issue requests configurable umask or file/directory modes for user-facing files created by agent tools such as exec, write, and edit.

## Best Possible Solution

Define an opt-in, documented `tools.fs` permission policy for user-facing output only, with tests proving sensitive state/config/transcript paths stay at private modes and default upgrade behavior remains unchanged.
