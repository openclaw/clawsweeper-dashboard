## Summary

Keep open: current main and v2026.6.11 still lack a configurable user-output file-permission policy, and the remaining work is a security-sensitive product/config decision rather than conservative cleanup.

## What This Changes

The issue requests a configurable umask or explicit file/directory modes under `tools` for agent-created user-facing files such as Write/Edit, exec output, tool output, exports, and workspace documents.

## Best Possible Solution

Define an opt-in user-output filesystem permission policy at the tools/runtime boundary, keep private OpenClaw state at restrictive modes, and cover host Write/Edit, apply_patch, sandbox bridge, exec-created output, media, docs, and regression proof together.
