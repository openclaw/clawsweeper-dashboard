## Summary

Keep open: current main and the latest release still do not provide a configurable user-output umask/file-mode policy, and the remaining work is a product/security decision rather than conservative cleanup.

## What This Changes

The issue requests configurable umask or file and directory modes for agent-created, user-facing workspace files so shared Docker/NAS deployments can keep operator-visible outputs writable without external permission repair jobs.

## Best Possible Solution

Define an opt-in user-output permission policy at the tools/runtime boundary, preserve restrictive private-state handling by construction, and cover host Write/Edit, workspace-only, sandbox, apply_patch, and exec-created outputs with docs and regression proof.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 still have no tools-level permission policy, and current write paths either use process defaults or hardcoded helper modes. I did not run a live Docker/Unraid reproduction in this read-only review.

## Solution Assessment

Unclear as a final implementation: the requested config knob is plausible, but maintainers need to settle the exact user-output boundary and config shape before a safe implementation.
