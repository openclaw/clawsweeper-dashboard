## Summary

Keep open: current main and the latest release still lack a scoped permission policy for agent-created user-facing files, and the remaining work is a security-sensitive product/config decision rather than conservative cleanup.

## What This Changes

Request configurable umask/file and directory modes for agent-created user-facing files so shared Docker/NAS deployments can keep workspace artifacts group-writable without external chmod sweeps.

## Best Possible Solution

Define a narrow operator-configurable permission policy for user-facing workspace/media artifacts, keep internal state restrictive, and prove host, sandbox, apply_patch, and exec-created file behavior under permissive and restrictive umasks.

## Reproduction Assessment

Yes, at source level: current write/edit/apply_patch and sandbox bridge paths either omit mode handling or hardcode 0o600 for first-time sandbox writes, and the strict config schema has no requested permission key. I did not live-run an Unraid/NAS Docker setup in this read-only review.

## Solution Assessment

Unclear as a final implementation: a configurable user-output policy is plausible, but maintainers need to choose the security boundary and exec strategy before adding a new tools config surface.
