## Summary

Keep open: current main and v2026.6.11 still lack a configurable user-output permission policy, and the remaining work is a security-sensitive product/config decision rather than conservative cleanup.

## What This Changes

Request an opt-in umask or explicit file/directory mode policy for agent-created user-facing files so shared Docker/NAS deployments can make outputs writable without external repair jobs.

## Best Possible Solution

Define an opt-in user-output filesystem permission policy at the tools/runtime boundary, keep private OpenClaw state restrictive, and apply it consistently across host Write/Edit, apply_patch, sandbox bridge, exec-created output, media/docs/tests.

Options:

- **Add an opt-in user-output policy (recommended):** Define a narrow policy for user-created workspace/output artifacts, keep private state out of scope, and require schema, docs, and cross-path tests before implementation.
- **Document external host policy only:** Close as not planned and point Docker/NAS operators to host ACL, bind-mount ownership, or post-processing tools instead of adding OpenClaw config surface.
- **Fix only one write surface:** Narrow the work to Write/Edit or sandbox/media output and leave exec-created files to host process policy, accepting divergent behavior across tools.
