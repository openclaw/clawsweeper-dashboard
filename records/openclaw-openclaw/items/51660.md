## Summary

Keep open: current main and v2026.6.11 still lack a supported permission policy for agent-created user-facing output, and the remaining work is a product/security decision rather than conservative cleanup.

## What This Changes

Request a configurable umask or file-mode policy for agent-created user-facing files so Docker/NAS/shared-host deployments can avoid external permission repair jobs.

## Best Possible Solution

Define a narrow opt-in user-output filesystem permission policy at the tools/runtime boundary, with explicit exclusions for private state and tests across host writes, apply_patch, sandbox writes, and exec-related behavior.
