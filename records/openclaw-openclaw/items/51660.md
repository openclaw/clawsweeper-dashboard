## Summary

Keep open: current main and the latest release still lack an operator-controlled permission policy for agent-created user-facing files, and the remaining work is a security-sensitive config/product decision rather than conservative cleanup.

## What This Changes

Request a configurable tools-level umask or explicit file/directory mode policy for agent-created user-facing files across exec, write, and related workspace outputs.

## Best Possible Solution

Define an opt-in user-output filesystem permission policy at the tools/runtime boundary, keep private OpenClaw state restrictive, and document and test host, sandbox, exec, and apply_patch behavior together.

## Reproduction Assessment

Yes, at source level: current main has no tools.fs permission key beyond workspaceOnly and does not carry mode options through host, sandbox, apply_patch, or agent-core write paths. I did not run a live Docker/Unraid reproduction in this read-only review.

## Solution Assessment

Unclear as a final implementation. The requested direction is plausible, but maintainers need to settle the exact config shape and the boundary between user-facing output and private OpenClaw state before implementation.
