## Summary

Keep open: current main and v2026.6.11 still do not expose an operator-controlled file-mode or umask policy for agent-created user-facing files, and implementing one is a security-sensitive config/product decision across host, workspace, sandbox, exec, and apply_patch write surfaces.

## What This Changes

Request an opt-in tools/runtime permission policy so agent-created user-facing files can match shared Docker/NAS filesystem conventions without loosening private OpenClaw state.

## Best Possible Solution

Define an opt-in user-output filesystem permission policy at the tools/runtime boundary, preserve restrictive defaults for private OpenClaw state, and document and test host, sandbox, exec, and apply_patch behavior together.

## Reproduction Assessment

Yes, source-level. Current main has no tools.fs permission key and the host/sandbox write contracts do not carry mode options; I did not run a live Docker/Unraid reproduction in this read-only review.

## Solution Assessment

Unclear as a final implementation. The direction is plausible, but maintainers need to settle the config shape and the boundary between user-facing output and private OpenClaw state before implementation.
