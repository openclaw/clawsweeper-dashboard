## Summary

Keep open: current main and the latest release still lack a configurable permission policy for agent-created user-facing files, and the remaining decision is a security-sensitive config/product choice rather than cleanup.

## What This Changes

The issue requests a configurable umask or file/directory mode policy for user-facing files created by agent tools such as write/edit, exec, apply_patch, and sandbox-generated workspace output.

## Best Possible Solution

Define an opt-in user-output filesystem permission policy at the tools/runtime boundary, keep private OpenClaw state restrictive, and cover host write/edit, apply_patch, sandbox bridge, exec-created output, docs, and regression proof together.

- **Document host-level setup only:** Leave runtime permissions unchanged and document ACL, Docker user/group, umask, or NAS permission setup as the supported operator workaround.
