## Summary

Keep open: current main and the latest release still lack an operator-controlled permission policy for agent-created user-facing files, and the remaining work is a security-sensitive config/product decision rather than conservative cleanup.

## What This Changes

The issue requests configurable umask or explicit file and directory modes for agent-created user-facing files so shared Docker/NAS deployments can make those outputs writable by other host users or services.

## Best Possible Solution

Define an opt-in user-output filesystem permission policy at the tools/runtime boundary, preserve restrictive private-state defaults, and document/test host, sandbox, apply_patch, exec, and media behavior together.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 have no `tools` permission policy key and the central write paths do not carry mode options. I did not run a Docker/Unraid live repro in this read-only review.

## Solution Assessment

Unclear as a final implementation: the requested direction is plausible, but maintainers need to choose the permission-policy shape and exact user-output boundary first. A narrow Write/Edit-only default-mode change would not cover the broader request across exec, sandbox, apply_patch, and plugin/tool output.
