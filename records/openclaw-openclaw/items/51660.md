## Summary

Keep open: current main and the latest release still lack an operator-controlled permission policy for agent-created user-facing files, and the remaining work is a security-sensitive config/product decision rather than conservative cleanup.

## What This Changes

Request configurable umask or file/directory modes for agent-created user-facing files so shared Docker/NAS deployments can keep outputs writable by expected host users and services.

## Best Possible Solution

Define a narrow, explicit permission policy for operator-visible agent output only after maintainer product/security review, while preserving restrictive modes for private config, credentials, state, transcripts, and memory.

## Reproduction Assessment

Yes for source-level behavior: current main has no config-controlled file permission policy across the host, workspace, and sandbox agent write paths inspected. I did not run a live Unraid/NAS repro in this read-only review.

## Solution Assessment

No automatic fix path: a umask/mode knob is plausible, but the best solution needs maintainer agreement on scope, defaults, and sensitive-write exclusions before code changes.
