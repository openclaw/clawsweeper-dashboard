## Summary

Keep open: current main and the latest release still lack a configurable permission policy for agent-created user-facing output, and the remaining work is a security-sensitive product/config decision rather than conservative cleanup.

## What This Changes

The issue requests a configurable umask or explicit file and directory modes for user-facing files created by agent tools such as write, edit, apply_patch, sandbox writes, and exec-related output.

## Best Possible Solution

Define an opt-in user-output filesystem permission policy at the tools/runtime boundary, keep private OpenClaw state restrictive, and cover host write/edit, apply_patch, sandbox bridge, exec guidance, docs, and regression proof together.
