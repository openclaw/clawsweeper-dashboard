## Label Justifications

- `impact:message-loss`: The observable failure suppresses the sole completion or failure message promised by the bundled coding-agent workflow.

## Summary

The bundled coding-agent contract remains broken on current main: it mandates a worker-originated completion send, while strict Gateway calls intentionally fail closed when the sandbox cannot resolve the configured SecretRef. The linked work covers adjacent SecretRef and Codex isolation paths but does not solve this external-worker workflow.

## What This Changes

Make coding-agent completion notification work safely with SecretRef-backed Gateway auth, or detect that automatic notification is unavailable before useful worker execution proceeds.

## Best Possible Solution

Keep Gateway SecretRefs fail-closed and move completion delivery to a parent-owned relay that consumes the worker's terminal result and sends through the authenticated runtime; if that seam is infeasible, use a narrowly scoped single-notification capability rather than the main Gateway credential.

Options:

- **Parent-owned relay (recommended):** Have the parent monitor worker completion and deliver the captured result through its authenticated Gateway runtime without exposing credentials to the worker.
- **Scoped notification capability:** Mint a single-purpose or tightly limited credential that authorizes only the captured completion route and message operation.
- **Preflight and decline:** Detect unsupported secure automatic notification before useful worker work begins and require monitored completion without adding a credential bridge.

## Reproduction Assessment

Yes. The report gives a concrete 1/1 live reproduction on v2026.7.1, and current source preserves both halves of the failure: mandatory worker-originated message sending and fail-closed strict SecretRef authentication.

## Solution Assessment

No, direct long-lived credential injection is not the best fix. A parent-mediated completion relay is the narrowest maintainable direction because it preserves the existing SecretRef boundary and keeps notification ownership outside the coding subprocess.
