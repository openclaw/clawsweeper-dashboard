## Summary

Keep this PR open for maintainer review: the patch appears to close the request-policy gap and has credible exact-head proof, but intentionally forwarding provider authorization and configured headers to same-origin generated-media URLs is a security-boundary choice that should be explicitly accepted before merge.

## What This Changes

The PR propagates Vydra transport policy through image and video submission, polling, and generated-media downloads, preserves same-origin speech-download authorization, and normalizes download body-deadline aborts.

## Best Possible Solution

Adopt one documented Vydra request-policy object for each media operation, retain the strict same-origin-only header rule, and merge only after the responsible owner confirms that generated assets on the provider origin are an approved credential-forwarding boundary.
