## Summary

The request-policy lookup is at the correct Vydra owner boundary, but the previously reported blocker remains: proxy, TLS, and private-network policy reach only the initial submission request, while polling and generated-asset downloads continue through unguarded fetch paths. The controlled loopback tests improve confidence in header propagation but do not prove the external proxy/TLS behavior this change targets.

## What This Changes

Applies the configured Vydra provider request policy when resolving image and video generation HTTP context and adds mocked and loopback-server regression tests.

## Best Possible Solution

Carry one resolved guarded transport policy through submit, polling, and download, use origin-aware headers so provider credentials cannot leak to asset hosts, and prove the complete flow through a redacted external proxy or TLS route.
