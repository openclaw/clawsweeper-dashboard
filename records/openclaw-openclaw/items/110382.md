## Summary

This PR remains necessary: current `main` still passes the process-exiting `defaultRuntime` to Gateway wizard runners, while the branch isolates exits and preserves explicit daemon-install intent. The implementation and focused coverage look directionally sound, but the PR body still provides tests and downstream claims rather than redacted exact-head live evidence that a hosted Gateway survives a real RPC wizard; keep it open for that contributor-owned proof and a fresh base review.

## What This Changes

Runs Gateway-hosted setup and channel wizards with a non-exiting runtime, treats successful wizard exits as session completion, and adds optional `installDaemon` forwarding to the wizard RPC schema and Swift model.

## Best Possible Solution

Rebase onto current `main`, then attach redacted supported-path proof that invokes `wizard.start`, observes a successful and a non-zero wizard exit, and confirms the same Gateway remains reachable afterward while preserving the caller's explicit `installDaemon` value.
