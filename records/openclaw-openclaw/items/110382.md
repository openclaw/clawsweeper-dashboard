## Summary

Keep this PR open. Current `main` still passes `defaultRuntime` into both Gateway wizard runners, so the central shared-process exit bug is not already fixed. The branch’s boundary is focused and its zero/non-zero exit handling matches the existing `ExitError` contract, but the PR body supplies only summarized proof plus a log hash rather than an inspectable redacted transcript or artifact for the current head.

## What This Changes

The branch makes Gateway-hosted setup and channel wizards use a non-exiting runtime, maps zero exits to successful session completion, forwards optional `installDaemon`, regenerates the Swift protocol model, and adds handler and WebSocket regression coverage.

## Best Possible Solution

Retain a single Gateway-owned embedded-wizard path that catches only `ExitError(0)`, forwards `installDaemon` without coercion, and land it once an inspectable redacted exact-head transcript or artifact demonstrates both exits leave the Gateway serving health requests.
