## Summary

The lifecycle isolation is a focused fix for the open Gateway-wizard bug, but the optional public `installDaemon` RPC parameter gives remote clients control over daemon-installation policy and needs explicit owner acceptance; the supplied real-behavior proof also predates the current head’s final cancellation-cleanup commit.

## What This Changes

This PR runs Gateway-hosted setup and channel wizards with a non-exiting runtime, retains cancelled wizard ownership until the runner settles, skips headless catalog loading, and adds an optional `installDaemon` field to the Gateway wizard request.

## System Context

Gateway `wizard.start` embeds onboarding or channel setup inside a long-running shared Gateway process. It projects RPC parameters into the existing wizard runners, streams session state back to remote clients, and must prevent a CLI-style wizard exit or cancellation race from disrupting the host process or overlapping setup work.

## Best Possible Solution

Retain the embedded non-exiting Gateway wizard boundary, but land the protocol field only after its remote daemon-ownership contract is explicitly accepted and the final head demonstrates cancellation settlement, cleanup, and subsequent wizard start on a live Gateway connection.
