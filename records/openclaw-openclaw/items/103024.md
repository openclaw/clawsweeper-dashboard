## Label Justifications

- `P1`: The report describes a real Claude CLI workflow where turn-end cleanup can kill in-flight background work and lose the user-visible result path.
- `impact:session-state`: The parent session can believe background subagent work is still in flight while the live CLI process tree has already been canceled.
- `impact:message-loss`: Killing the Claude CLI background child can prevent task notifications or later assistant output from reaching the requester.
- `impact:data-loss`: In-flight background subagent work can be discarded when OpenClaw cancels the live CLI process tree at turn end.
- `maturity:stable`: The affected gateway runtime lifecycle surface matches the M4 Stable `gateway-runtime` maturity feature.

## Summary

Close as duplicate/superseded by the existing Claude CLI process-tree lifecycle tracker: current main still has the reported cleanup-to-cancel path, but https://github.com/openclaw/openclaw/issues/102172 already owns the same remaining decision about bounded drain, telemetry, or unsupported post-turn CLI-owned background work.

## What This Changes

The issue requests that Claude CLI live-session cleanup stop canceling in-flight background subagents at turn end by tracking live children and deferring idle/restart closes until they drain.

## Best Possible Solution

Keep the lifecycle decision centralized in https://github.com/openclaw/openclaw/issues/102172, carrying this subagent/task-notification evidence there while https://github.com/openclaw/openclaw/issues/99131 and https://github.com/openclaw/openclaw/pull/99139 continue to cover the separate synthetic-empty/session-binding side.
