## Summary

Keep open: current main and the latest release still show `sessions.patch` taking the session patch projection path without the plugin-runtime ownership guard that `sessions.delete` already enforces and tests, so this remains a real gateway security/session-state bug.

## What This Changes

The issue requests adding the same plugin-runtime ownership fence to `sessions.patch` that already exists for `sessions.delete`.

## Best Possible Solution

Add the existing plugin-runtime ownership fence to `sessions.patch`, recheck it inside the lifecycle mutation window when mutating an existing entry, and add regression coverage for foreign archive/unarchive/metadata mutation denial plus owned-session success.
