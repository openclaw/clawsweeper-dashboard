## Summary

Keep open: current main and v2026.6.11 still show `sessions.patch` mutating through the session patch projection without the plugin-runtime ownership guard that `sessions.delete` already enforces and tests, so this remains a real gateway security/session-state bug.

## What This Changes

The issue reports that gateway `sessions.patch` lets a plugin-runtime caller mutate another plugin's session because it lacks the plugin ownership guard used by `sessions.delete`.

## Best Possible Solution

Add the existing plugin-runtime ownership fence to `sessions.patch`, recheck it inside the lifecycle mutation window when mutating an existing entry, and add regression coverage for foreign archive/unarchive/metadata mutation denial plus owned-session success.
