## Summary

Keep open: current main and the latest release still leave `sessions.patch` without the plugin-runtime ownership check that `sessions.delete` enforces, so this remains a concrete gateway security/session-state bug.

## What This Changes

The issue reports that `sessions.patch` can archive, unarchive, or rewrite metadata for sessions owned by another plugin-runtime owner.

## Best Possible Solution

Add the existing plugin-runtime ownership fence to `sessions.patch`, rechecking inside the lifecycle mutation window, with regression coverage for foreign archive/unarchive/metadata denial and owned-session success.
