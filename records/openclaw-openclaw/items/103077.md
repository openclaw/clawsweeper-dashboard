## Summary

Keep open: current main still lets a plugin-runtime caller reach the `sessions.patch` projection path without comparing the caller's `pluginRuntimeOwnerId` to the target session's `pluginOwnerId`, while the sibling delete path enforces that ownership fence.

## What This Changes

The issue requests a plugin-ownership check for `sessions.patch` so plugin-runtime callers cannot archive, unarchive, or rewrite metadata on sessions owned by another plugin.

## Best Possible Solution

Add the existing plugin-runtime ownership fence to `sessions.patch`, recheck it inside the lifecycle mutation window before projection, and add focused regression coverage for foreign archive/unarchive/metadata denial plus owned-session success.
