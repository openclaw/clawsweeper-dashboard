## Summary

Keep open: current main and the latest release still leave `sessions.patch` without the plugin-runtime ownership check that `sessions.delete` enforces, so this remains a concrete gateway security/session-state bug.

## What This Changes

The issue reports that plugin-runtime callers can patch, archive, unarchive, or rewrite another plugin's session because `sessions.patch` lacks the ownership check used by `sessions.delete`.

## Best Possible Solution

Add a patch-specific plugin-runtime ownership fence, recheck it inside the lifecycle mutation window for existing entries, and cover foreign archive, unarchive, and metadata mutation denial plus owned-session success in gateway regression tests.
