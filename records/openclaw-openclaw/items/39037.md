## Summary

Keep open. Current main only partially exposes WhatsApp `externalAdReply` title/source/body as untrusted prompt context; the requested CTWA click id and field-shape, plugin-hook, prompt, and retention boundaries remain unresolved.

## What This Changes

Request to expose WhatsApp CTWA ad referral fields, especially `ctwaClid`, from inbound message context into agent/session-accessible metadata.

## Best Possible Solution

Add a narrow WhatsApp-owned CTWA referral metadata shape that exposes only maintainer-approved fields through untrusted channel context and/or opted-in plugin hooks, with explicit tests for prompt visibility, hook visibility, and retention behavior.

Options:

- **Expose narrow untrusted CTWA context (recommended):** Add a typed WhatsApp CTWA payload with approved fields such as `ctwaClid`, `sourceType`, `sourceId`, `sourceUrl`, and `headline/body` to untrusted channel context and opted-in hooks, without durable retention unless separately approved.
- **Plugin-hook only:** Expose CTWA fields only to WhatsApp plugin hooks or a conversion plugin surface, keeping them out of model preambles and session transcripts by default.
- **Defer CTWA exposure:** Leave current external-ad title/source/body behavior unchanged until a privacy/security policy for ad attribution identifiers is defined.
