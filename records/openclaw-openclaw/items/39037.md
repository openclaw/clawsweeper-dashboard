Keep open. Current main still exposes only partial WhatsApp ad-reply context and does not carry CTWA attribution fields into plugin hook metadata, agent context, or durable session metadata; the remaining work needs maintainer direction on privacy, prompt visibility, and retention.

## What This Changes

The issue requests exposing WhatsApp Click-to-WhatsApp ad referral fields, especially `ctwa_clid`, from inbound message context into session metadata or agent-visible context.

## Best Possible Solution

Define a WhatsApp-owned CTWA attribution payload, expose it through an approved plugin-hook or tightly scoped untrusted-context boundary, and persist it only if maintainers set explicit retention and redaction rules.

Options:

- **Plugin-hook attribution payload (recommended):** Expose selected CTWA fields to opted-in WhatsApp/plugin hook metadata so a Conversions API plugin can consume them without automatically putting the click id in every model prompt.
- **Per-turn untrusted context:** Expose selected CTWA/referral fields through the existing untrusted structured-context path and accept that the model can see them for that turn.
- **Persist session attribution:** Store the first CTWA payload on session state only after defining retention, redaction, and access rules.

## Solution Assessment

Is this the best way to solve the issue? Unclear as proposed: the WhatsApp plugin is the right extraction owner, but broad session metadata or preamble exposure is not automatically the safest contract.
