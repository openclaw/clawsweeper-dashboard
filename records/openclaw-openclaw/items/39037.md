## Summary

Keep open. Current main and the latest release still omit CTWA attribution fields from WhatsApp extraction, plugin-hook metadata, and session retention; the remaining blocker is the privacy/security boundary for exposing ad-click identifiers.

## What This Changes

The issue asks OpenClaw's WhatsApp channel to extract Click-to-WhatsApp referral fields such as ctwaClid and expose them through session metadata, prompt context, or a retrievable session attribute.

## Best Possible Solution

Define a WhatsApp-owned CTWA attribution payload, expose it first through an approved opted-in plugin-hook boundary, and add prompt visibility or session persistence only after maintainers approve retention and redaction rules.

- **Untrusted prompt context:** Expose selected CTWA fields as untrusted structured context for the current turn when maintainers accept model/transcript visibility.
- **Persist session attribution:** Store first-touch CTWA attribution on session state after defining retention, redaction, and access rules.

## Reproduction Assessment

Yes, source-level: a Baileys inbound message with contextInfo.externalAdReply.ctwaClid reaches an extractor that returns only title, sourceUrl, and body, and downstream hook/session metadata has no CTWA field. I did not run a live Click-to-WhatsApp webhook.

## Solution Assessment

Unclear as proposed: the WhatsApp plugin is the right extraction owner, but broad session metadata or preamble exposure is not automatically the safest contract. A typed opted-in plugin-hook attribution payload is the safest default unless maintainers approve prompt or session retention.
