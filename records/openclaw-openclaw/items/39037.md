## Summary

Keep open. Current main and the latest release expose only partial WhatsApp external-ad-reply metadata, while the requested CTWA click id/referral payload and its prompt, plugin, retention, and redaction contract remain unresolved.

## What This Changes

The issue requests exposing WhatsApp Click-to-WhatsApp referral fields, especially `ctwaClid`, through session or agent-visible metadata for attribution workflows.

## Best Possible Solution

Define a WhatsApp-owned CTWA attribution payload, expose selected fields through the existing untrusted structured-context or plugin-hook boundary, and persist it only after an explicit retention and redaction decision.

## Reproduction Assessment

Yes, source-level: a WhatsApp Baileys message carrying `externalAdReply.ctwaClid` would reach the current extractor path, which returns only `title`, `sourceUrl`, and `body`. I did not run a live Click-to-WhatsApp ad webhook reproduction.

## Solution Assessment

Unclear as proposed: extraction belongs in the WhatsApp plugin, but broad session metadata or preamble exposure is not automatically the safest contract. The safer likely direction is a typed untrusted structured-context or plugin-hook payload with explicit retention rules.
