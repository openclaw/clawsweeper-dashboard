## Summary

Keep open. Current main and latest release still expose only partial WhatsApp external-ad-reply metadata, while the requested CTWA click identifier, referral shape, prompt/plugin visibility, and retention boundary remain unresolved.

## What This Changes

Request to expose Click-to-WhatsApp referral metadata, especially `ctwa_clid`, from inbound WhatsApp messages to agent/session-accessible metadata.

## Best Possible Solution

Define a WhatsApp-owned CTWA attribution payload, expose it through the existing untrusted structured-context or plugin-hook boundary, and persist it only if maintainers approve a clear retention/security contract.

## Reproduction Assessment

Yes, source-level: a WhatsApp inbound message carrying CTWA data would pass through the current external-ad-reply extractor, which returns only title, sourceUrl, and body. I did not run a live Click-to-WhatsApp ad webhook reproduction.

## Solution Assessment

Unclear as proposed: extraction belongs in the WhatsApp plugin, but broad session metadata or preamble exposure is not automatically the safest contract. The safer likely direction is a typed untrusted structured-context or plugin-hook payload with explicit retention rules.
