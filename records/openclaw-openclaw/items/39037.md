## Summary

Keep open. Current main and the latest release still expose only partial WhatsApp external-ad metadata; the CTWA click identifier, plugin/prompt exposure shape, and any session-retention policy remain unresolved.

## What This Changes

The issue requests exposing Click-to-WhatsApp ad referral fields, especially `ctwaClid`, from inbound WhatsApp messages into agent-accessible metadata or session context.

## Best Possible Solution

Define a WhatsApp-owned CTWA attribution payload, expose it through an approved untrusted prompt or plugin-hook boundary, and persist it only if maintainers approve retention and redaction rules.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should WhatsApp CTWA attribution data be exposed only as per-turn untrusted structured context, also provided to plugin hooks, or persisted on session metadata for later Conversions API use?

Rationale: The extraction is bounded, but the requested value is an advertising click identifier and the issue explicitly asks for prompt/session visibility, so automation should not choose the privacy, retention, and plugin-access boundary.

Likely owner: steipete

Owner reason: The decision spans prompt metadata and session-retention boundaries where recent history points to steipete as the strongest routing candidate.

Owner confidence: high

Options:

- **Per-turn untrusted context only (recommended):** Extract CTWA fields in the WhatsApp plugin and expose them only through the existing fenced untrusted structured-context path without durable persistence.
- **Typed plugin-hook payload:** Define an opted-in WhatsApp attribution payload for plugin hooks so a Conversions API plugin can consume it without putting the identifier into every agent prompt.
- **Persist session attribution:** Store the first CTWA payload on session metadata only after defining explicit retention, redaction, and access rules.

## Reproduction Assessment

Yes. Source inspection shows current WhatsApp extraction and forwarding paths expose only title/sourceUrl/body from `externalAdReply`, while CTWA/referral fields are not projected; I did not run a live Click-to-WhatsApp webhook reproduction.

## Solution Assessment

Unclear as proposed. The WhatsApp plugin is the right owner for extraction, but broad prompt/session exposure is not automatically the safest contract; the safer path is a typed attribution payload behind an approved untrusted-context or plugin-hook boundary.
