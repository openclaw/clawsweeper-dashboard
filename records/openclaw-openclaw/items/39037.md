## Summary

Keep open. Current main and the latest release still expose only partial WhatsApp `externalAdReply` data, while CTWA click-id extraction and the prompt, plugin-hook, or session-retention boundary remain unresolved.

## What This Changes

The issue asks OpenClaw's WhatsApp plugin to expose Click-to-WhatsApp attribution fields such as `ctwaClid`/`ctwa_clid`, source URL/type/id, and headline through agent-visible or session metadata.

## Best Possible Solution

Define a WhatsApp-owned CTWA attribution payload, expose it through the chosen untrusted-context or plugin-hook boundary, and persist it only if maintainers set explicit retention and redaction rules.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should WhatsApp CTWA attribution data be exposed as per-turn untrusted context, plugin-hook metadata for an attribution plugin, or persisted session metadata for later conversion reporting?

Rationale: The extraction is bounded, but `ctwa_clid` is a per-click advertising identifier and the issue asks for prompt/session exposure, so automation should not choose visibility or retention policy.

Likely owner: steipete

Owner reason: Their adjacent session metadata and plugin-boundary history is the closest fit for deciding whether this belongs in prompt context, plugin hooks, or persisted session state.

Owner confidence: medium

Options:

- **Plugin-Hook Attribution Payload (recommended):** Expose typed CTWA data to an opted-in plugin hook so a Conversions API plugin can use it without putting the identifier in every agent prompt.
- **Per-Turn Untrusted Context:** Expose CTWA fields only as existing untrusted structured context for the current inbound turn, with no durable persistence.
- **Persist Session Attribution:** Store the first CTWA payload on session state after maintainers define retention, redaction, and access rules.

## Reproduction Assessment

Yes, source-level: current main extracts only partial `externalAdReply` data and does not project CTWA click/referral fields even though the pinned Baileys proto exposes them. I did not establish a live Click-to-WhatsApp webhook reproduction.

## Solution Assessment

Unclear as proposed: the WhatsApp plugin is the right extraction owner, but broad prompt/session exposure is not automatically the safest contract. The best likely direction is a typed CTWA attribution boundary, with persistence only after an explicit retention decision.
