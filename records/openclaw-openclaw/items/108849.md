## Summary

The JSON-path change is well targeted, but making the generic text reader fail closed is an unproven compatibility break for existing provider and proxy text bodies; retain the PR for a narrow correction rather than merge it as written.

## What This Changes

The branch makes provider text and JSON response decoding fatal on invalid UTF-8 and adds two regression tests for invalid-byte responses.

## Best Possible Solution

Use fatal decoding for JSON responses, where UTF-8 is the appropriate wire contract, while preserving compatible generic text-body handling unless maintainers deliberately adopt and document a UTF-8-only provider-text contract.
