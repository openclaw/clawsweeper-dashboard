## Summary

Keep open: the managed-directory hardening is still useful, but this PR still chmods caller-owned session/transcript parents through `SessionManager.open()` and Gateway transcript creation despite promising custom paths are unchanged.

## What This Changes

Adds `0o700` mkdir modes and best-effort chmod repair for session, settings, tool-bin, Gateway transcript, and plugin-skill directories while leaving session store/accessor mkdirs plain.

## Best Possible Solution

Land managed-directory hardening only after chmod repair is guarded to recognized OpenClaw-owned paths, caller-owned paths are preserved, and maintainers accept the upgrade permission tightening.

## Reproduction Assessment

Yes at source level. Current main still creates managed session directories without explicit private modes, and the PR body provides terminal proof under umask 0002, but I did not run the behavior locally in this read-only review.

## Solution Assessment

No. Managed-only hardening is the right direction, but this patch is not the best mergeable shape until it preserves caller-owned session and transcript parents in every runtime path.
