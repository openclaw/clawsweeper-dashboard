## Summary

Keep this maintainer-labeled feature open. Current main still couples exact external delivery to mutable session route metadata: MCP offers session-backed conversation listing and direct sends, while the agent-facing `sessions_send` tool starts another local agent turn. The requested durable multi-peer identity and correlated reply path remains missing and requires an explicit core product design.

## What This Changes

Add stable external conversation references plus owner-only discovery, direct-send, and correlated request/reply tools that remain distinct from local agent sessions.

## Best Possible Solution

Define one transport-generic core contract: store agent-owned opaque conversation identities and pending correlations in the per-agent SQLite database, resolve all sends through the existing normalized Gateway delivery path, atomically claim matched inbound replies before normal dispatch, and mirror outbound plus inbound messages once into the owning transcript while leaving existing session tools unchanged.
