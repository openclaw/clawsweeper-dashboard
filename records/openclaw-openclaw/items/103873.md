## Label Justifications

- `P1`: Every approval-analyzed agent execution routed to the current Mac node takes a degraded path that omits native policy facts.
- `impact:security`: The missing native preparation response prevents approval analysis from learning the Mac node's effective execution policy and reusable allow-always coverage.
- `impact:ux-friction`: Execution continues through a fallback, but users receive more conservative approvals and weaker reuse of previously approved commands.
- `maturity:stable`: The affected `gateway-runtime` and `macos-gateway-host` features are both scored M4 Stable.

## Summary

Keep this issue open: current `main` still lacks native Mac `system.run.prepare` support, and the existing Gateway fallback restores execution but not node-owned policy or allow-always facts. The protected `maintainer` label also requires explicit maintainer handling. Likely related people: NianJiu and steipete for recent native execution work, plus soloclz for the earlier compatibility fallback proposal.

## What This Changes

Add the `system` capability and node-owned `system.run.prepare` command to the macOS node so its core execution surface matches the headless CLI node.

## Best Possible Solution

Implement native Mac preparation using the post-refactor approval and validation primitives, advertise `system` and `system.run.prepare`, and add an explicit CLI-core-versus-Mac surface invariant plus native-handler and Gateway-path regressions while retaining the generic fallback for older nodes.
