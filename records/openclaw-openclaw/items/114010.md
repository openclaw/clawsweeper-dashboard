## Summary

The patch is a focused, plausible repair for a startup-order bug: the already computed dev ambient-channel policy now reaches the first plugin auto-enable pass. Keep this PR open for normal review, with one remaining merge gate: add inspectable after-fix real-startup evidence showing that a suppressed ambient Telegram token no longer triggers auto-enable, `getMe`, or restart scheduling.

## What This Changes

The PR forwards the dev ambient-channel suppression policy into the initial gateway configuration snapshot so environment-only credentials cannot auto-enable a channel plugin before gateway startup applies suppression.

## System Context

Gateway startup reads the initial configuration snapshot, may infer enabled plugins from environment credentials, and then starts configured channels. In development mode, the ambient-channel policy must reach that first inference step so suppressed credentials do not become persisted runtime plugin configuration or outbound channel activity.
