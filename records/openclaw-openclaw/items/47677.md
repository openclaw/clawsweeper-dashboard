## Summary

Keep open: current main and v2026.6.11 still treat accepted Telegram reactions as passive standard-emoji system events, while reaction-triggered wake behavior, custom-emoji normalization, and product-level reaction semantics remain unmerged product/API work with overlapping open candidates.

## What This Changes

Request first-class Telegram reactions that can wake an agent, normalize standard and custom emoji, express operator semantics, and expose debugging without downstream patches.

## Best Possible Solution

Land one maintainer-approved, queue-by-default Telegram reaction contract that normalizes unicode/custom emoji into stable keys, wakes only for explicit allowed policy after existing filters, documents upgrade behavior, and keeps high-level emoji meanings in preferences, prompt, or approval policy rather than transport hardcoding.
