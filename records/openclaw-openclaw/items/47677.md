## Summary

Keep open: current main and v2026.6.11 still treat Telegram reactions as passive standard-emoji system events, while reaction wake behavior, custom-emoji normalization, and product-level semantics remain unmerged product/API work with open implementation candidates.

## What This Changes

Request first-class Telegram reaction input support that can wake agents, normalize standard and custom emoji, define operator semantics, and expose observability.

## Best Possible Solution

Land or close a maintainer-approved opt-in Telegram reaction policy that preserves queue-only defaults, normalizes standard and custom reaction keys, defines the semantics boundary, documents upgrade behavior, and includes live Telegram proof.
