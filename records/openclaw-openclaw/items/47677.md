## Summary

Keep open: current main and v2026.6.11 still treat accepted Telegram reactions as passive system events, while reaction wake behavior, custom-emoji keys, and product-level reaction semantics remain unresolved with open implementation candidates needing maintainer direction.

## What This Changes

The issue requests first-class Telegram reaction input so configured reactions can wake the agent, normalize standard and custom emoji, express operator semantics, and provide observable routing/debug signals.

## Best Possible Solution

Choose one default-safe opt-in reaction wake contract, preferably the shared queue/wake/off policy, then keep per-emoji semantics, prompt guidance, custom-emoji detail, and durable feedback as explicitly scoped follow-ups or linked implementation work.
