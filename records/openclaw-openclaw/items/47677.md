## Summary

Keep open: current main and v2026.6.11 still treat accepted Telegram reactions as passive standard-emoji system events, while reaction wake behavior, custom-emoji normalization, product semantics, and observability remain unmerged product/API work with open but unresolved implementation candidates.

## What This Changes

The issue requests first-class Telegram reaction input so configured reactions can wake the agent, normalize standard and custom emoji, support operator semantics, and expose useful debugging signals.

## Best Possible Solution

Choose and land one maintainer-approved Telegram reaction contract that preserves queue-only defaults, adds explicit opt-in wake behavior, normalizes standard/custom reaction keys, documents the semantics boundary, and includes live Telegram proof.
