## Summary

Keep open: current main and v2026.6.11 still treat accepted Telegram reactions as passive standard-emoji system events, while reaction-triggered wake behavior, custom-emoji reaction keys, product-level reaction semantics, and stronger observability remain unmerged product/API work with open candidates.

## What This Changes

Request first-class Telegram reaction input so configured standard and custom emoji reactions can wake or drive agent workflows with semantics and observability.

## Best Possible Solution

Keep this issue open until maintainers choose and land one queue-by-default Telegram reaction wake/semantics contract with custom emoji keys, observability, docs, tests, and live Telegram proof.
