## Summary

Keep open: current main and v2026.6.11 still treat accepted Telegram reactions as passive standard-emoji system events, while reaction-only wake behavior, custom-emoji normalization, product semantics, and observability remain unmerged product/API work with open implementation candidates.

## What This Changes

Request first-class Telegram reaction input support: reaction-only agent wakes, standard/custom emoji normalization, configurable semantics, observability, and upgrade-safe behavior.

## Best Possible Solution

Adopt one maintainer-approved opt-in Telegram reaction policy that preserves queue-only defaults, normalizes standard/custom reaction keys, documents semantics and observability, and lands with live Telegram proof.
