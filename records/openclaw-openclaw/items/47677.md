## Summary

Keep open: current main and v2026.6.11 still enqueue Telegram reactions as passive system events, while reaction wake behavior, custom-emoji keys, and first-class operator semantics remain unresolved product/API work with open implementation candidates.

## What This Changes

Request first-class Telegram reaction handling so configured reaction-only inputs can wake or drive agent work, normalize standard and custom emoji, expose reaction semantics, and improve observability.

## Best Possible Solution

Adopt one default-safe opt-in reaction wake contract, preferably the shared queue/wake/off policy, then split per-emoji execution semantics, prompt guidance, custom-emoji detail, and durable feedback into explicit follow-ups or scoped implementation work.
