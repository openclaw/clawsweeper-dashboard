## What This Changes

The PR adds optional QA runner adapter factories and routes Telegram, Slack, WhatsApp, and Matrix live QA through QA Lab's shared suite host.

## Best Possible Solution

Gate live transport factory selection on an explicit adapter channel/factory, keep profile-only live metadata on the existing qa-channel transport path, and then let maintainers accept the additive SDK seam.

## Reproduction Assessment

Yes. Source inspection shows release/all profile runs pass channelDriver live without an adapter channel, while the PR maps channelDriver live to the live transport driver and therefore has no default factory for that existing profile path.

## Solution Assessment

No. The shared adapter direction is plausible, but the implementation must distinguish explicit live adapter selection from existing profile metadata before it is the best fix.
