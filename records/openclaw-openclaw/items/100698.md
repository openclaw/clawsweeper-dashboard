## Summary

Keep open: current main still lacks a mobile per-gateway custom-header path, and the protected maintainer label plus credential-bearing proxy-auth scope require owner/security product review rather than conservative cleanup closure.

## What This Changes

The issue requests iOS and Android support for secure, per-gateway custom HTTP headers on Gateway connections behind authenticating reverse proxies.

## Best Possible Solution

Define one shared, secret-safe mobile Gateway proxy-header contract, then review/land or revise the linked iOS and Android PRs with secure storage, gateway-only attachment, diagnostics redaction, reset behavior, TLS policy, and real authenticated-proxy proof.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw mobile apps support arbitrary per-gateway proxy headers, or should the mobile proxy-auth surface be narrowed to typed schemes such as Basic, Bearer, or fixed Cloudflare-style service-token fields first?

Rationale: The source gap is clear, but the permanent boundary controls credentials sent before Gateway auth, mobile secure storage, diagnostics redaction, reset/forget behavior, TLS expectations, and whether arbitrary operator-supplied headers are safe in native app settings.

Likely owner: steipete

Owner confidence: high

Options:

- **Approve broad custom headers with security review (recommended):** Land the platform PRs only after owner/security reviewers approve the sanitizer, secure-store lifecycle, gateway-only attachment, redaction, reset, TLS, and real-proxy proof contract.
- **Narrow to typed proxy auth:** Ask the platform PRs to replace arbitrary name/value headers with a smaller typed credential model that is easier to validate, redact, clear, and document.
- **Defer native proxy credentials:** Keep the mobile apps unsupported for authenticating-proxy deployments while maintainers settle the cross-platform transport-auth design.

## Reproduction Assessment

Yes, source-level: current main has no iOS or Android connection config field, secure-store setting, settings editor, or WebSocket request/header hook for per-gateway custom headers. I did not run a live Cloudflare Access or reverse-proxy repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the credential contract. Per-gateway headers are a plausible solution and the open platform PRs target the right surfaces, but the best fix must satisfy secure storage, redaction, reset, TLS, and non-gateway isolation requirements.
