## Summary

Keep open: current main and v2026.6.11 still lack a mobile per-gateway custom-header path, and the protected maintainer label plus credential-bearing proxy-auth scope require explicit owner/security review rather than cleanup closure.

## What This Changes

Request mobile apps support per-gateway custom HTTP headers, stored securely and attached only to gateway WebSocket and HTTP requests for authenticated reverse proxies.

## Best Possible Solution

Define a shared, secret-safe mobile Gateway proxy-header contract first, then land separate iOS and Android slices that store credentials securely, send them only to gateway endpoints over approved transports, redact diagnostics, and prove a real authenticated-proxy connection.

- **Defer native proxy credentials:** Keep mobile reverse-proxy header injection unsupported for now and document Tailscale, VPN, or proxy-bypass alternatives while the broader design remains unsettled.
