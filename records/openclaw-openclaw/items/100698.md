## Summary

Keep open: current main still lacks the requested mobile per-gateway custom-header transport path, and the protected maintainer label plus credential-bearing proxy-auth scope require owner/security review rather than cleanup closure.

## What This Changes

Request iOS and Android support for securely stored, per-gateway custom HTTP headers on gateway WebSocket connections behind authenticating reverse proxies.

## Best Possible Solution

Define a shared, secret-safe mobile gateway proxy-header contract, then review and land the iOS and Android platform PRs with gateway-only attachment, reserved-header sanitization, secure storage, redaction, TLS/pinning invariants, and real authenticated-proxy proof.

- **Defer native proxy credentials:** Keep mobile proxy-header injection unsupported for now and document VPN, Tailscale, or direct trusted-proxy alternatives while design remains unsettled.
