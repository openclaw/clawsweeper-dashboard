## Summary

Keep open: current main and v2026.6.11 still lack mobile per-gateway header support, and the linked iOS/Android implementation PRs are open under protected maintainer/security review rather than merged.

## What This Changes

The issue requests secure per-gateway custom HTTP headers in the iOS and Android apps so mobile clients can connect to gateways behind authenticating reverse proxies.

## Best Possible Solution

Review and land or revise the linked iOS and Android PRs under one shared secret-safe, gateway-only header contract, with macOS parity tracked separately if maintainers want it.

## Maintainer Decision

Question: Should OpenClaw mobile apps support arbitrary per-gateway custom headers for authenticating proxies, or should the first native proxy-auth contract be narrower and typed?

Rationale: The source gap is clear, but this feature stores and replays pre-Gateway credentials from native apps, so owner/security intent is needed before accepting arbitrary operator-supplied headers as the permanent product surface.

Likely owner: steipete

Owner reason: Peter authored the issue and linked PRs and has the strongest current signal across the mobile gateway and security/product boundary.

Owner confidence: high

Options:

- **Adopt shared custom-header contract (recommended):** Proceed with the iOS and Android PRs after owner/security review confirms secure storage, reserved-header filtering, redaction, gateway-only attachment, and real authenticated-proxy proof.
- **Narrow to typed proxy auth:** Ask the platform PRs to expose only approved Basic, Bearer, or fixed service-token fields first, reducing arbitrary-header risk at the cost of less operator flexibility.
- **Defer native proxy credentials:** Keep mobile proxy credential injection unsupported for now and document VPN, Tailscale, or proxy-bypass alternatives while the broader design remains unsettled.

Yes, source-level. Current main and v2026.6.11 have no iOS or Android connection config field, secure-store slot, settings path, or WebSocket request/header hook for per-gateway custom headers; I did not run a live reverse-proxy repro in this read-only review.

## Solution Assessment

Unclear until maintainers approve the credential contract. The linked platform PR split is the right owner boundary, but arbitrary per-gateway headers need owner/security review before it can be called the best permanent solution.
