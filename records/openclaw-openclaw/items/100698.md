## Summary

Keep open: current main still lacks mobile per-gateway custom-header support, and the issue is protected by maintainer/security/product-review labels with open Android and iOS implementation PRs that have not merged.

## What This Changes

The issue requests secure per-gateway custom HTTP headers in the iOS and Android apps so mobile Gateway WebSocket connections can pass authenticating reverse proxies.

## Best Possible Solution

Define a shared mobile proxy-header contract, then land platform PRs that securely store credentials, attach sanitized headers only to Gateway WebSocket requests, redact diagnostics, preserve TLS/pairing behavior, and include real authenticated-proxy proof.
