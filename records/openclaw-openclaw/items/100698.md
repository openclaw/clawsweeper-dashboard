## Summary

Keep open: current main and v2026.6.11 still lack mobile per-gateway custom-header support, and the linked iOS/Android implementation PRs are open candidates that need the existing maintainer/security review rather than cleanup closure.

## What This Changes

Add securely stored per-gateway custom HTTP headers to iOS and Android gateway connections so mobile apps can reach gateways behind authenticating reverse proxies.

## Best Possible Solution

Review the two linked platform PRs against one shared mobile proxy-header contract, then land only after owner/security approval covers secure storage, redaction, reserved-header sanitization, gateway-only attachment, and unchanged TLS/pairing behavior.

## Maintainer Decision

Rationale: This is not a routine source fix: the feature stores and replays credentials before Gateway authentication, changes mobile settings/storage surfaces, and must define what headers are allowed and where they may be sent.

Likely owner: steipete

Owner confidence: high

Options:

- **Review and land split platform PRs (recommended):** Proceed with the iOS and Android PRs only after owner/security review confirms the shared arbitrary-header contract and real behavior proof are sufficient.
- **Narrow to typed proxy auth first:** Ask the platform PRs to support a smaller Basic/Bearer/fixed-token contract before considering arbitrary header name/value pairs.
- **Defer mobile proxy headers:** Keep mobile reverse-proxy header injection unsupported for now and document VPN/Tailscale/proxy-bypass alternatives while the security model remains unsettled.

## Reproduction Assessment

Yes, source-level: current main has no iOS or Android connection config field, secure-store slot, settings path, or WebSocket request/header hook for per-gateway custom headers. I did not run a live Cloudflare Access or reverse-proxy reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers approve the credential contract. Per-gateway headers are a plausible mobile solution because a tunnel sidecar is not viable on phones, but arbitrary headers should land only if owner/security review approves the broader boundary.
