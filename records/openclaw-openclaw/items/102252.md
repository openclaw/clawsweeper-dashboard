## Best Possible Solution

Add a core agent-loop abort boundary before any prepared parallel tool starts execution, with regression coverage proving skipped prepared calls do not invoke `execute`.

## Repair Work Prompt

Fix the agent-core parallel tool execution cancellation race reported in https://github.com/openclaw/openclaw/issues/102252. In `packages/agent-core/src/agent-loop.ts`, add a core abort boundary so a prepared parallel tool call whose execution has not started yet is skipped if `signal.aborted` becomes true before `prepared.tool.execute` is invoked. Preserve result ordering and lifecycle events, mark skipped calls as `executionStarted: false`, and avoid pushing this responsibility into individual paid tools. Add focused regression coverage in `packages/agent-core/src/agent-loop.test.ts` that drives `runAgentLoop` with two parallel tool calls, aborts during an awaited `beforeToolCall` for the later call, and proves the earlier prepared tool's `execute` is not invoked. Do not add config flags, provider-specific behavior, or changelog edits.
