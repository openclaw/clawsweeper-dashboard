## Repair Work Prompt

Fix the agent-core parallel tool abort race reported in https://github.com/openclaw/openclaw/issues/102252. In `packages/agent-core/src/agent-loop.ts`, prevent any prepared-but-not-yet-started parallel tool call from invoking `tool.execute` once `signal.aborted` is true after preparation but before execution. Preserve parallel result ordering and lifecycle semantics: skipped calls should produce an aborted tool result with `executionStarted: false`, similar to the existing `prepareToolCall` aborted path. Add a focused regression test in `packages/agent-core/src/agent-loop.test.ts` using the real `runAgentLoop` parallel path with two tool calls: the first prepares successfully, the second awaits `beforeToolCall` and aborts the signal, then assert neither prepared paid-style tool `execute` runs after abort and the batch emits aborted/not-started results. Do not add config, change the `AgentTool` API, or move the responsibility into image/music/video tools. No changelog entry.
