## Summary

Keep open: current main and the latest stable release still have the parallel prepared-call abort gap, so this paid-tool cancellation bug remains actionable.

## What This Changes

The issue reports that a prepared tool in a parallel agent tool batch can still execute after the run is aborted while a later tool is still preparing.

## Best Possible Solution

Add a generic agent-core abort boundary before any prepared parallel tool starts execution, preserving ordered finalized results and keeping cancellation policy out of individual paid tools.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level. A prepared thunk can be queued before a later aborted preparation, and current main still invokes that thunk through Promise.all without a pre-execute abort check.

## Solution Assessment

Yes. The maintainable fix belongs at the agent-core execution boundary because the loop owns whether a prepared call is allowed to start after the run is already aborted.
