## Summary

The patch uses the native `ws` handshake timeout in the correct transport layer and adds convincing source-level regression coverage, with no discrete correctness or security defect found. It should remain open because the external-PR proof is still test-only and does not demonstrate the changed TCP and Unix behavior against a real Codex app-server setup.

## What This Changes

Adds a 30-second opening-handshake timeout to Codex app-server TCP and Unix WebSocket transports, adjusts error propagation, and adds stalled-handshake regression tests.

## Best Possible Solution

Keep the native `ws` timeout design, but prove the final head with redacted terminal output from real Codex app-server TCP and Unix sessions showing successful initialization, plus the stalled-peer timeout and resulting client rejection.
