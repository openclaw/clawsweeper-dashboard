## Summary

Keep this PR open for Codex-owner review. The stalled-handshake bug and dependency-level fix are well supported, but merge readiness depends on confirming the connection-timeout policy and clearing the current exact-head gates.

## What This Changes

The PR adds a 30-second WebSocket handshake timeout for Codex app-server TCP and Unix transports, guards optional error forwarding, and adds stalled-peer regression and real-socket proof coverage.

## Best Possible Solution

Bound stalled TCP and Unix upgrades with `ws` handshake timeout support, but have the Codex owner define whether the deadline derives from the existing app-server timeout policy or is intentionally fixed; retain focused real-socket regression coverage and land only with exact-head gates green.
