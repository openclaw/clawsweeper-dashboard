Keep open for Codex-owner confirmation. The reported indefinite handshake wait is credible and the patch is technically sound with strong real-socket proof, but imposing an unconditional 30-second deadline on both TCP and Unix transports changes an existing transport compatibility boundary.

## What This Changes

The PR adds a shared 30-second Codex app-server WebSocket handshake timeout, makes transport error forwarding conditional on listeners, and adds stalled-peer tests plus an executable real-socket proof.

## Best Possible Solution

Use the native `ws` handshake deadline through the shared transport-options builder, retain the focused TCP and Unix coverage, and merge the fixed 30-second value only after the Codex owner confirms that accepted-but-slow upgrades beyond that deadline are unsupported; avoid adding another user-facing config option unless that contract cannot be fixed.
