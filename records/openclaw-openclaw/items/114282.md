## Summary

This PR remains necessary: current OpenClaw still uses the retired Copilot token-exchange design that rejects fine-grained credentials, while the branch replaces that runtime path with account validation and direct source-credential use. The submitted live matrix and focused upgrade tests support the core fix, and no discrete patch defect was established; however, the provider-wide identity change and untested GitHub Enterprise policy behavior require explicit maintainer review before merge.

## What This Changes

The branch validates GitHub Copilot source credentials through the current account endpoint, uses the resolved Copilot endpoint for requests, and preserves legacy OAuth profiles without rewriting their durable GitHub credential.

## System Context

The bundled GitHub Copilot provider obtains a stored GitHub credential, prepares provider authentication and request headers, then feeds that material into model discovery, inference, embeddings, usage, and media requests. Core OAuth storage supplies the credential lifecycle while the plugin owns Copilot-specific endpoint validation and request identity.
