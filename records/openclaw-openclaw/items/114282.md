## Summary

Keep this PR open for maintainer review. The updated body now contains credible exact-head terminal proof of a fine-grained PAT authenticating, discovering models, and streaming a response, but the patch duplicates the provider runtime identity between core and the GitHub Copilot plugin, conflicting with the repository’s owner-boundary policy and creating a future split-brain request-header path.

## What This Changes

The PR replaces GitHub Copilot’s short-lived runtime token exchange with validation and direct use of the stored GitHub credential, while switching Copilot request identity to `copilot-developer-cli` across runtime surfaces.

## System Context

GitHub Copilot credentials enter through the provider’s OAuth or token configuration, then the provider resolves the account-specific API endpoint and supplies credentials and headers to model, embedding, media, and streaming requests. This change affects both plugin-owned Copilot requests and older core request paths that still construct Copilot headers directly.

## Best Possible Solution

Keep the runtime integration identity and Copilot-specific authentication policy in the GitHub Copilot provider, then expose any necessary request-header behavior to core through one generic provider seam so every Copilot surface consumes a single authoritative value.
