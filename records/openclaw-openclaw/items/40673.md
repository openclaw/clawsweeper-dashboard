## Summary

Keep open: current main still leaves a source-supported LaunchAgent/service-env path where sensitive raw-stream logging can remain enabled after an operator believes it was disabled, and no merged successor owns the remaining precedence contract.

## What This Changes

The issue reports that disabling `OPENCLAW_RAW_STREAM` for a macOS LaunchAgent can still leave `raw-stream.jsonl` receiving new events after gateway restart.

## Best Possible Solution

Define one raw-stream disable precedence contract where explicit managed-service disable cannot be overridden by stale generated service env, then add focused LaunchAgent/service-env tests, public docs, doctor/status guidance, and macOS proof.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should an explicit managed-service disable for `OPENCLAW_RAW_STREAM` override persisted state-dir `.env` or generated service-env values for macOS LaunchAgents?

Rationale: This decides a sensitive diagnostic logging boundary across multiple operator-controlled env sources, and automation should not encode that precedence without maintainer intent.

Likely owner: steipete

Owner reason: The recent raw-stream runtime and durable service-env helper history makes this the best available owner for the precedence decision.

Owner confidence: high

Options:

- **Explicit Disable Wins (recommended):** Treat unset, `0`, `off`, and `false` disable intent as authoritative for managed services, clear or override stale generated service-env entries, and document the precedence.
- **Persisted Env Remains Authoritative:** Keep state-dir `.env` and config env as the durable source and document that operators must remove or edit those values before a restart disables raw-stream logging.
- **Doctor-Guided Repair Only:** Leave runtime precedence mostly unchanged but add status/doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.

## Reproduction Assessment

Yes for a source-level path, but not as a live macOS run in this read-only review. Current source treats `0` and unset as disabled only when they are the final process value, while the LaunchAgent wrapper can source a persisted env file before gateway startup.

## Solution Assessment

Unclear: the source points to a valid bug, but the best fix depends on the maintainer-chosen precedence for explicit false launchd env versus persisted service-env sources. The safer end state is an explicit disable contract with tests and docs.
