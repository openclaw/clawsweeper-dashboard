## Summary

Keep open: current main still supports a source-level macOS LaunchAgent path where a generated service-env file can keep sensitive raw-stream logging enabled after an operator believes launchd has disabled it.

## What This Changes

The issue asks OpenClaw to make `OPENCLAW_RAW_STREAM` disabling reliable and documented for LaunchAgent-managed gateways.

## Best Possible Solution

Document and enforce one raw-stream disable contract across launchd inherited env, generated service env, state-dir `.env`, and config env, with LaunchAgent/service-env regression tests plus doctor or status guidance.

Rationale: This decides a sensitive diagnostic logging boundary across multiple operator-controlled env sources, and automation should not encode that precedence without maintainer intent.

Owner confidence: medium

Options:

- **Explicit Disable Wins (recommended):** Treat unset, `0`, `off`, and `false` as authoritative for managed services, clear or override stale generated service-env entries, and document the precedence.
- **Persisted Env Remains Authoritative:** Keep state-dir `.env` and config env as the durable source and document that operators must remove or edit those values before restart disables raw-stream logging.
- **Doctor-Guided Repair Only:** Leave runtime precedence mostly unchanged but add status or doctor checks that warn and repair stale raw-stream service-env values.

## Reproduction Assessment

Yes for a source-level path, but not as a live macOS run in this read-only review. Current source treats `0` and unset as disabled only after final env resolution, while the LaunchAgent wrapper can source a generated service-env file before gateway startup.

## Solution Assessment

Unclear: the source points to a valid bug boundary, but the best fix depends on the maintainer-chosen precedence for explicit false launchd env versus persisted service-env sources. The safest end state is an explicit disable contract with tests and docs.
