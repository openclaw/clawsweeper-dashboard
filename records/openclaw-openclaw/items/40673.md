## Summary

Keep open: current main still has a source-supported LaunchAgent/service-env path where raw-stream logging can remain enabled after an operator believes `OPENCLAW_RAW_STREAM` is unset or false, and no merged fix or canonical successor owns the remaining disable-precedence contract.

## What This Changes

Clarify and enforce raw-stream disable semantics for macOS LaunchAgent-managed gateways so unset, `0`, and documented false values stop appending raw stream logs after restart.

## Best Possible Solution

Define one raw-stream disable contract where explicit managed-service disable cannot be overridden by stale persisted service env, then add focused LaunchAgent/service-env tests, public docs, doctor or status guidance, and macOS proof.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should an explicit managed-service disable for `OPENCLAW_RAW_STREAM` override persisted state-dir `.env` or config service-env values, or should persisted sources remain authoritative until edited?

Rationale: This decides a sensitive diagnostic logging boundary across multiple operator-controlled environment sources; automation should not encode that precedence without maintainer intent.

Likely owner: steipete

Owner reason: steipete has the strongest recent history across both the raw-stream runtime and durable service-env helper paths involved in the decision.

Owner confidence: high

Options:

- **Explicit Disable Wins (recommended):** Treat unset, `0`, `off`, and `false` disable intent as authoritative for managed services, clear or override stale generated service-env entries, and document the precedence.
- **Persisted Sources Stay Authoritative:** Keep state-dir `.env` and config env as the durable source and document that operators must remove or edit those values before restart disables raw-stream logging.
- **Doctor-Guided Repair Only:** Leave runtime precedence mostly unchanged but add status or doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.

## Reproduction Assessment

Yes for a source-level path, but not as a live macOS run in this review. The raw-stream writer disables on final false env values, while the LaunchAgent wrapper can source persisted service env before gateway startup.

## Solution Assessment

No current close path is proven best. The maintainable fix needs an explicit sensitive-logging precedence contract across LaunchAgent wrapper env, state-dir `.env`, config env, CLI flags, docs, and doctor/status guidance.
