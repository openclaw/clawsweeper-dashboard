## Summary

Keep open: current main still has a source-supported LaunchAgent path where an existing generated service env file can keep raw-stream logging enabled after an operator unsets or sets the launchd value to 0, and no merged fix or canonical successor owns the sensitive logging precedence contract.

## What This Changes

The issue asks for LaunchAgent-managed raw-stream logging to stop appending after disable via unset or 0, with docs that define supported disable values and managed-service precedence.

## Best Possible Solution

Define a single raw-stream disable contract where explicit managed-service disable cannot be overridden by stale generated service env, then add focused LaunchAgent/service-env tests, docs for disable values and precedence, and doctor/status guidance for stale raw-stream env files.

Options:

- **Persisted Env Wins:** Keep state-dir .env and config env as the durable source and document that operators must edit those persisted values before restart disables raw-stream logging.
- **Doctor-Guided Repair Only:** Leave runtime precedence mostly unchanged but add status/doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.

## Solution Assessment

No close path is proven best. The maintainable fix needs an explicit sensitive-logging precedence contract across LaunchAgent wrapper env, generated service env, state-dir .env, config env, CLI flags, docs, and doctor/status guidance.
