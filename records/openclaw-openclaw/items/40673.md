## Summary

Keep open: current main proves `OPENCLAW_RAW_STREAM=0` is falsy once it reaches the Gateway process, but it does not settle the macOS LaunchAgent precedence contract when generated service-env/config sources still provide `OPENCLAW_RAW_STREAM=1`, and the log can contain sensitive prompts and tool output.

## What This Changes

The issue requests clear and reliable disable semantics for `OPENCLAW_RAW_STREAM` under macOS LaunchAgent service management, including docs for supported false values and service-env interaction.

## Best Possible Solution

Define one authoritative managed-service disable contract: explicit raw-stream false/unset should fail closed across LaunchAgent service-env sources, or status/Doctor must surface the active source and provide a clear cleanup path with docs for supported false values.
