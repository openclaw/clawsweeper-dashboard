## Summary

Keep open: current main still has a source-supported LaunchAgent generated env-file path that can feed `OPENCLAW_RAW_STREAM=1` into the gateway after `launchctl unsetenv` or `0`, and no merged fix or canonical successor owns the sensitive logging precedence contract.

## What This Changes

Requests clear and effective disable semantics for `OPENCLAW_RAW_STREAM` under macOS LaunchAgent so unset or `0` stops `raw-stream.jsonl` writes and docs define supported disable values.

## Best Possible Solution

Define one raw-stream disable precedence contract where an explicit managed-service disable cannot be hidden by stale generated env files, then cover LaunchAgent/service-env tests plus docs/status/doctor guidance.

Options:

- **Explicit Disable Wins (recommended):** Treat unset, `0`, `false`, and `off` as authoritative for managed-service disable, clear or override stale generated service-env entries, and document the precedence.
- **Persisted Env Wins:** Keep state-dir `.env` and config env as the durable source and document that operators must edit those persisted values before restart disables raw-stream logging.
- **Doctor-Guided Repair Only:** Leave runtime precedence mostly unchanged but add status/doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.
