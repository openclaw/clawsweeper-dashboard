## Summary

Keep open: current main still leaves a source-supported LaunchAgent/service-env path where persisted service environment can re-enable sensitive raw-stream logging after an operator disables the launchd value, and no merged fix or canonical successor owns the remaining precedence contract.

## What This Changes

The issue reports that disabling OPENCLAW_RAW_STREAM for a macOS LaunchAgent can still leave raw-stream.jsonl appending sensitive stream events after restart.

## Best Possible Solution

Define one raw-stream disable contract where explicit managed-service disable cannot be overridden by stale persisted service env, then add focused LaunchAgent/service-env tests, public disable-precedence docs, doctor/status guidance, and macOS proof.

- **Explicit Disable Wins (recommended):** Treat unset/0/off/false disable intent as authoritative for managed services, clear or override stale generated service-env entries, and document the precedence.
- **.env/config Remain Authoritative:** Keep persisted state-dir .env/config env as the durable source and document that operators must remove or edit those values before restart disables raw-stream logging.
- **Add Doctor-Guided Repair Only:** Leave runtime precedence mostly unchanged but add status/doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.

Yes for a source-level path, but not as a live macOS run in this review. The raw-stream writer disables on final false env values, while the LaunchAgent wrapper can source persisted service env before gateway startup.

## Solution Assessment

No current close path is proven best. The maintainable fix needs an explicit sensitive-logging precedence contract across LaunchAgent wrapper env, state-dir .env, config env, CLI flags, docs, and doctor/status guidance.
