## Summary

Keep open: current main and the latest release still have raw-stream logging controlled by the final process env, while the macOS LaunchAgent wrapper can source persisted service env after launchd inherited env. A stale `OPENCLAW_RAW_STREAM=1` can plausibly keep sensitive raw-stream logs appending, and no merged canonical fix owns the disable-precedence contract.

## What This Changes

Ensure disabling `OPENCLAW_RAW_STREAM` for a macOS LaunchAgent stops raw-stream JSONL writes after restart and document the supported false/unset values.

## Best Possible Solution

Define one raw-stream disable contract where explicit managed-service disable clears or overrides stale persisted service env, then cover it with LaunchAgent/service-env tests, docs, and doctor/status guidance.

Options:

- **Explicit Disable Wins (recommended):** Treat unset, `0`, `off`, and `false` as authoritative for managed services, clear or override stale generated service-env entries, and document the precedence.
- **Persisted Sources Stay Authoritative:** Keep state-dir `.env` and config env as the durable source and document that operators must remove or edit those values before restart disables raw-stream logging.
- **Doctor-Guided Repair Only:** Leave runtime precedence mostly unchanged but add status or doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.

Yes for a source-level path, but not as a live macOS run in this review. The raw-stream writer disables on final false env values, while the LaunchAgent wrapper can source persisted service env before gateway startup.

## Solution Assessment
