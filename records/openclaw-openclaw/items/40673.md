## Summary

Current main still has the same raw-stream gate and LaunchAgent service-env layering that can make a stale file-backed `OPENCLAW_RAW_STREAM=1` win before gateway startup, so this should stay open for a maintainer-owned disable-precedence/security decision.

## What This Changes

The issue asks OpenClaw to stop appending raw-stream diagnostics after `OPENCLAW_RAW_STREAM` is unset or set to a false value for a restarted macOS LaunchAgent gateway, and to document the supported disable values.

## Best Possible Solution

Define a single raw-stream disable precedence contract where explicit managed-service disable cannot be overridden by stale generated service env, then cover it with LaunchAgent/service-env tests, public docs, doctor or status guidance, and macOS proof.

- **Doctor-Guided Repair Only:** Leave runtime precedence mostly unchanged but add status or doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.

## Reproduction Assessment

Yes for a source-level path, but not as a live macOS run in this read-only review. Current source treats `0` and unset as disabled only after final env resolution, while the LaunchAgent wrapper can source generated service env before gateway startup.

## Solution Assessment

Unclear: the source points to a valid bug boundary, but the best fix depends on the maintainer-chosen precedence for explicit false launchd env versus persisted service-env sources. The safer end state is an explicit disable contract with tests and docs.
