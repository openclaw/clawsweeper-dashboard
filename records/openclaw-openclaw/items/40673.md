## Label Justifications

- `impact:security`: Raw-stream logs can contain prompts, tool output, and user data, and the issue reports new records being written after the operator believes logging is disabled.

## Summary

Keep open: current main still has a source-supported LaunchAgent path where a durable generated service env value can re-enable sensitive raw-stream logging after an operator disables the launchd inherited value, and the docs still do not define the disable precedence.

## What This Changes

The issue asks OpenClaw to make `OPENCLAW_RAW_STREAM` disable semantics clear and ensure LaunchAgent-managed gateways stop writing `raw-stream.jsonl` after the value is unset or set to `0`.

## Best Possible Solution

Maintainers should define the raw-stream disable precedence, then align the LaunchAgent wrapper/service-env handling, doctor diagnostics, docs, and regression tests so an operator has one reliable non-surprising way to stop sensitive raw-stream logging.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should an explicit LaunchAgent/inherited `OPENCLAW_RAW_STREAM=0` or unset value override OpenClaw-generated durable service env/config values that still contain `OPENCLAW_RAW_STREAM=1`, or should the durable source remain authoritative with a documented doctor/removal path?

Rationale: This controls a sensitive logging boundary and may alter service-env precedence for existing operators, so automation should not choose the policy silently.

Likely owner: steipete

Owner reason: Most connected to both the raw-stream helper migration and daemon/service-env planning history.

Owner confidence: high

Options:

- **Explicit disable wins (recommended):** Treat `0`, `false`, `off`, `no`, and unset as an operator disable that prevents generated LaunchAgent env-file raw-stream values from re-enabling logging, with docs and tests for the precedence.
- **Durable source wins:** Keep `.env`/config service env as authoritative and update docs/doctor to tell operators to remove or repair that durable source before restart.
- **Docs-only for now:** Clarify the current behavior without changing runtime precedence, accepting that launchctl `0` may not stop logging when a generated env file still enables it.

## Reproduction Assessment

Yes, source-reproducible: a LaunchAgent wrapper sources OpenClaw's generated env file before `exec`, so a durable `OPENCLAW_RAW_STREAM=1` can override launchd inherited `OPENCLAW_RAW_STREAM=0` before the raw-stream runtime gate runs. I did not run a live macOS LaunchAgent proof in this read-only review.

## Solution Assessment

Unclear until maintainer intent is set: the narrow maintainable fix is to define the disable precedence and update the LaunchAgent/service-env, doctor, docs, and tests together. A docs-only fix is safer mechanically but weaker for sensitive logging expectations.
