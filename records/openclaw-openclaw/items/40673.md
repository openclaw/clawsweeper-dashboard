## Summary

Keep open: current main and the latest release still have a source-level path where LaunchAgent-managed service environment values can leave sensitive raw-stream logging enabled after an operator believes OPENCLAW_RAW_STREAM is unset or 0, and no merged related item owns that disable-precedence contract.

## What This Changes

The issue asks OpenClaw to stop raw-stream writes after OPENCLAW_RAW_STREAM is unset or set to 0 under macOS LaunchAgent restarts, and to document supported disable values.

## Best Possible Solution

Define one raw-stream disable precedence contract where explicit managed-service disable cannot be overridden by stale generated service env, then add focused LaunchAgent/service-env tests, public docs, doctor/status guidance, and macOS proof.

Question: Should an explicit managed-service disable for OPENCLAW_RAW_STREAM override persisted state-dir .env or generated service-env values for macOS LaunchAgents?

Rationale: Raw-stream logs can contain sensitive prompts and tool output, so automation should not choose the permanent precedence rule between explicit false launchd env and durable service env sources.

Likely owner: Peter Steinberger

Owner reason: He has the strongest combined history on raw-stream logging and durable service-env helpers.

Owner confidence: high

Options:

- **Explicit Disable Wins (recommended):** Treat unset, 0, off, and false disable intent as authoritative for managed services, clear or override stale generated service-env entries, and document the precedence.
- **Persisted Env Remains Authoritative:** Keep state-dir .env and config env as the durable source and document that operators must edit those values before restart disables raw-stream logging.
- **Doctor-Guided Repair Only:** Leave runtime precedence mostly unchanged but add status or doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.

## Reproduction Assessment

Yes for a source-level path, but not as a live macOS run in this read-only review. Current source treats 0/unset as disabled only after final env resolution, while the LaunchAgent wrapper can source generated service env before gateway startup.

## Solution Assessment

Unclear: the source points to a valid bug boundary, but the best fix depends on the maintainer-chosen precedence for explicit false launchd env versus persisted service-env sources. The safer end state is an explicit disable contract with tests and docs.
