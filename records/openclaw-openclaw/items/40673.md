## Summary

Keep open: current main still has a source-level macOS LaunchAgent env path that can keep sensitive raw-stream logging enabled after an operator believes it is disabled, and no merged successor owns the disable-precedence contract.

## What This Changes

The issue asks OpenClaw to make OPENCLAW_RAW_STREAM disabling explicit and stop LaunchAgent-managed gateways from appending raw-stream logs after unset or false-valued disable attempts.

## Best Possible Solution

Define one raw-stream disable precedence contract where explicit managed-service disable cannot be overridden by stale generated service env, then add focused LaunchAgent/service-env tests, public docs, doctor or status guidance, and macOS proof.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should an explicit managed-service disable for OPENCLAW_RAW_STREAM override persisted state-dir .env, config env, and generated service-env values for macOS LaunchAgents?

Rationale: The repair chooses a security-sensitive precedence rule across multiple operator-controlled environment sources, and automation should not decide whether launchd false/unset, generated service env, or durable config/state should win.

Likely owner: Peter Steinberger

Owner reason: He has the strongest combined history on raw-stream logging and durable service-env design.

Owner confidence: high

Options:

- **Explicit Disable Wins (recommended):** Treat unset, 0, off, and false disable intent as authoritative for managed services, clear or override stale generated service-env entries, and document the precedence.
- **Persisted Env Remains Authoritative:** Keep state-dir .env and config env as the durable source and document that operators must remove or edit those values before restart disables raw-stream logging.
- **Doctor-Guided Repair Only:** Leave runtime precedence mostly unchanged but add status or doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.

## Reproduction Assessment

Yes, as a source-level reproduction path, but not as a live macOS run in this read-only review. Current source treats 0/unset as disabled only after final env resolution, while the LaunchAgent wrapper can source generated service env before gateway startup.

## Solution Assessment

Unclear: the source points to a valid bug boundary, but the best fix depends on the maintainer-chosen precedence for explicit false launchd env versus persisted service-env sources. The safer end state is an explicit disable contract with tests and docs.
