## Summary

Keep open: current main still has a source-supported LaunchAgent path where a generated service-env file can re-enable sensitive raw-stream logging after an operator disables the launchd-inherited value, and no merged successor owns the remaining disable-precedence contract.

## What This Changes

Fix and document raw-stream disable semantics so LaunchAgent-managed gateways stop appending raw-stream logs after `OPENCLAW_RAW_STREAM` is unset or set false.

## Best Possible Solution

Define one managed-service raw-stream disable contract, add focused LaunchAgent/service-env tests plus public docs and doctor/status guidance, and prove the macOS restart path no longer writes sensitive raw-stream logs after explicit disable.

Question: Should an explicit managed-service disable for `OPENCLAW_RAW_STREAM` override persisted state-dir `.env`, config env, or generated LaunchAgent service-env values?

Rationale: This decides a sensitive diagnostic logging boundary across multiple operator-controlled env sources, and automation should not encode that precedence without maintainer intent.

Likely owner: steipete

Owner confidence: medium

Options:

- **Explicit Disable Wins (recommended):** Treat unset, `0`, `off`, and `false` disable intent as authoritative for managed services, clear or override stale generated service-env entries, and document the precedence.
- **Persisted Env Remains Authoritative:** Keep state-dir `.env` and config env as the durable source and document that operators must remove or edit those values before restart disables raw-stream logging.
- **Doctor-Guided Repair Only:** Leave runtime precedence mostly unchanged but add status/doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.

## Reproduction Assessment

Yes for a source-level path, but not as a live macOS run in this read-only review. Current source treats `0` and unset as disabled, while the LaunchAgent wrapper can source a persisted env file before gateway startup.

## Solution Assessment

Unclear: the source points to a valid bug, but the best fix depends on the maintainer-chosen precedence for explicit false launchd env versus persisted service-env sources. The safer end state is an explicit disable contract with tests and docs.
