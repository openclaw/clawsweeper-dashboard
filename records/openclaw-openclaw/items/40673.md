## Summary

Keep open: current main still has a source-supported LaunchAgent service-env path where persisted raw-stream settings can re-enable sensitive logging after an operator disables the launchd value, and no merged fix or canonical successor owns that precedence contract.

## What This Changes

The issue asks OpenClaw to stop raw-stream JSONL writes after `OPENCLAW_RAW_STREAM` is unset or set to `0` under a restarted macOS LaunchAgent, and to document supported disable values.

## Best Possible Solution

Define one raw-stream disable contract where an explicit managed-service disable cannot be overridden by stale persisted service env, then add focused LaunchAgent/service-env tests, public disable-precedence docs, doctor/status guidance, and macOS proof.

Question: Should an explicit managed-service disable for `OPENCLAW_RAW_STREAM` override persisted state-dir `.env` and config service-env values, or should those persisted sources remain authoritative until edited?

Rationale: This decides a sensitive diagnostic-logging boundary across multiple operator-controlled env sources, and automation should not encode that precedence without maintainer intent.

Likely owner: steipete

Owner confidence: high

Options:

- **Explicit Disable Wins (recommended):** Treat unset, `0`, `off`, and `false` disable intent as authoritative for managed services, clear or override stale generated service-env entries, and document the precedence.
- **Persisted Env Remains Authoritative:** Keep state-dir `.env` and config env as the durable source and document that operators must remove or edit those persisted values before restart disables raw-stream logging.
- **Doctor-Guided Repair Only:** Leave runtime precedence mostly unchanged but add status/doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.

## Reproduction Assessment

Yes for a source-level path, but not as a live macOS run in this review. The raw-stream writer disables on final false env values, while the LaunchAgent wrapper can source persisted service env before gateway startup.

## Solution Assessment

No current close path is proven best. The maintainable fix needs an explicit sensitive-logging precedence contract across LaunchAgent wrapper env, state-dir `.env`, config env, CLI flags, docs, and doctor/status guidance.
