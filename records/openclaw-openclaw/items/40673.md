## Summary

Keep open: current main still leaves a source-level LaunchAgent/generated-env path where raw-stream logging can remain enabled after an operator believes `OPENCLAW_RAW_STREAM` was disabled, and no merged PR or canonical successor owns that sensitive logging precedence contract.

## What This Changes

The issue asks OpenClaw to stop appending raw-stream logs after `OPENCLAW_RAW_STREAM` is unset or set to `0` under a macOS LaunchAgent and to document disable semantics.

## Best Possible Solution

Define one raw-stream disable precedence contract so explicit managed-service disables cannot be hidden by stale generated env, then cover LaunchAgent tests, status or doctor guidance, and public docs.

Options:

- **Explicit Disable Wins (recommended):** Treat unset, `0`, `false`, and `off` as authoritative disable signals for managed services, clear or override stale generated service-env entries, and document the precedence.
- **Persisted Env Wins:** Keep state-dir `.env` and config env as the durable source, and document that operators must edit those persisted values before restart disables raw-stream logging.
- **Doctor-Guided Repair:** Leave runtime precedence mostly unchanged but add status or doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.

## Reproduction Assessment

Yes for a source-level path, but not as a live macOS run in this read-only review. The raw-stream writer disables on final false env values, while the LaunchAgent wrapper can source generated env values after launchd inherited env is set.

## Solution Assessment

Unclear. The maintainable fix needs an explicit sensitive-logging precedence contract across LaunchAgent wrapper env, generated service env, state-dir `.env`, config env, CLI flags, docs, and doctor/status guidance.
