## Summary

Keep open: current main proves `OPENCLAW_RAW_STREAM=0` is false at the final writer, but the macOS LaunchAgent wrapper can still source generated service-env values after launchd inheritance, and the sensitive logging precedence contract is not documented or settled.

## What This Changes

Fix and document `OPENCLAW_RAW_STREAM` disable semantics for macOS LaunchAgent-managed gateways so unset, `0`, or `off` reliably stops raw-stream JSONL writes after restart.

## Best Possible Solution

Define one managed-service raw-stream disable contract, implement it across LaunchAgent service-env planning and runtime docs, and add focused regression coverage plus doctor/status guidance for stale raw-stream env values.

Options:

- **Explicit Disable Wins (recommended):** Treat `unset`, `0`, `off`, `false`, and explicit service disable intent as authoritative, clear or override stale generated raw-stream service-env entries, and document that precedence.
- **Durable Env Wins:** Keep state-dir `.env` and config service env as the authoritative managed-service source, and document that operators must remove those values before restart disables raw-stream logging.
- **Doctor/Status Repair Only:** Leave runtime precedence unchanged but add doctor/status warnings and repair guidance when stale raw-stream service env can make logging appear disabled while still active.

## Reproduction Assessment

Yes for a source-level path, but not as a live macOS run in this review. The raw-stream writer disables on final false env values, while the LaunchAgent wrapper can source generated service env before gateway startup.

## Solution Assessment

No current close path is proven best. The maintainable fix needs an explicit sensitive-logging precedence contract across LaunchAgent wrapper env, durable service env, runtime behavior, docs, and doctor/status guidance.
