## Summary

Keep open: current main still has a source-supported LaunchAgent/service-env path where sensitive raw-stream logging can remain enabled after an operator disables the launchd-inherited value, and the intended disable precedence still needs maintainer intent.

## What This Changes

Clarify and fix raw-stream disable semantics so LaunchAgent-managed gateways stop appending raw-stream.jsonl after OPENCLAW_RAW_STREAM is unset or set to 0.

## Best Possible Solution

Define one raw-stream disable precedence contract across launchd inherited env, generated service-env, state-dir .env, and config env, then cover it with LaunchAgent tests, doctor/status guidance, docs, and macOS proof.

Question: Should an explicit managed-service disable for OPENCLAW_RAW_STREAM override persisted state-dir .env, config env, or generated service-env values for macOS LaunchAgents?

Rationale: Raw-stream logs can contain sensitive prompts and tool output, and automation should not choose this cross-source disable precedence without maintainer intent.

Owner confidence: high

Options:

- **Explicit Disable Wins (recommended):** Treat unset, 0, off, and false disable intent as authoritative for managed services, clear or override stale generated service-env entries, and document the precedence.
- **Persisted Env Remains Authoritative:** Keep state-dir .env and config env as the durable source and document that operators must remove or edit those values before restart disables raw-stream logging.
- **Doctor-Guided Repair Only:** Leave runtime precedence mostly unchanged but add status or doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.

## Reproduction Assessment

Yes for a source-level path, but not as a live macOS run in this read-only review. Current source treats 0/unset as disabled only after final env resolution, while the LaunchAgent wrapper can source a generated service-env file before gateway startup.

## Solution Assessment

Unclear: the source points to a valid bug boundary, but the best fix depends on the maintainer-chosen precedence for explicit false launchd env versus persisted service-env sources. The safer end state is an explicit disable contract with tests and docs.
