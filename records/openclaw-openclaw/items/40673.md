## Summary

Keep open: current main still has an unresolved raw-stream disable-precedence contract for LaunchAgent-managed gateways, and no merged related item owns the remaining security-sensitive behavior.

## What This Changes

The issue reports that `OPENCLAW_RAW_STREAM` can keep appending raw stream logs after a macOS LaunchAgent restart even when the operator unsets it or sets it to `0`.

## Best Possible Solution

Define one raw-stream disable precedence contract, cover it with LaunchAgent/service-env tests and docs, and require macOS proof that unset, `0`, `off`, and `false` stop appends after restart.

## Maintainer Decision

Required: true

Question: Should an explicit managed-service disable for `OPENCLAW_RAW_STREAM` override persisted state-dir `.env` or generated service-env values for macOS LaunchAgents?

Rationale: The repair chooses a sensitive logging precedence rule across multiple operator-controlled environment sources, and automation should not decide whether launchd false/unset, generated service env, or durable config/state should win.

Likely owner: Peter Steinberger

Owner reason: He has the strongest combined history across the original raw-stream feature and gateway daemon install planning.

Owner confidence: high

Options:

- **Explicit Disable Wins (recommended):** Treat unset, `0`, `off`, and `false` disable intent as authoritative for managed services, clear or override stale generated service-env entries, and document the precedence.
- **Persisted Env Remains Authoritative:** Keep state-dir `.env` and config env as the durable source and document that operators must remove or edit those values before restart disables raw-stream logging.
- **Doctor-Guided Repair Only:** Leave runtime precedence mostly unchanged but add status or doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.

## Reproduction Assessment

Yes for a source-level path, but not as a live macOS run in this read-only review. Current source treats `0` and unset as disabled only after final env resolution, while the LaunchAgent wrapper can source generated service env before gateway startup.

## Solution Assessment

Unclear: the source points to a valid bug boundary, but the best fix depends on the maintainer-chosen precedence for explicit false launchd env versus persisted service-env sources. The maintainable end state is an explicit disable contract with tests and docs.
