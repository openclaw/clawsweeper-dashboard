## Summary

Keep open: current main has a source-supported managed-service path where persisted service env can still enable sensitive raw-stream logging, while the intended precedence for an explicit operator disable remains unsettled and undocumented.

## What This Changes

This issue asks OpenClaw to make macOS LaunchAgent raw-stream disable behavior reliable for unset or false `OPENCLAW_RAW_STREAM` values and to document the supported disable semantics.

## Best Possible Solution

Define a single raw-stream disable contract for managed services, then add LaunchAgent/service-env regression coverage, public disable-precedence docs, doctor/status guidance, and macOS proof for the selected behavior.

Rationale: Raw-stream logs can contain prompts and tool output, so automation should not choose the operator-control boundary or migration behavior without maintainer intent.

Owner confidence: high

Options:

- **Explicit Disable Wins (recommended):** Treat `0`, `off`, `false`, and unset/removed launchd disable intent as authoritative for managed services, clear or override stale generated service-env entries, and document the precedence.
- **Persisted Env Wins:** Keep state-dir `.env` and config env as the durable source until the operator edits those files or config, and document that launchctl unset alone is not enough.
- **Doctor-Only Repair:** Leave runtime precedence mostly unchanged, but add doctor/status checks that warn about and repair raw-stream service-env drift before operators rely on disable state.

Yes for a source-level path, but not as a live macOS run in this review. The raw-stream writer disables on final false env values, while the LaunchAgent wrapper can source persisted service env before gateway startup.

No current close path is proven best. The maintainable fix needs an explicit sensitive-logging precedence contract across LaunchAgent wrapper env, state-dir `.env`, config env, CLI flags, docs, and doctor/status guidance.
