## Summary

Keep open: current main still has no merged fix or canonical successor for the LaunchAgent raw-stream disable contract. The raw writer rejects final `0`/unset values, but the managed LaunchAgent env-wrapper path can still export persisted `.env` or config-derived values after launchd inherited env, and the docs do not define disable precedence for this sensitive log.

## What This Changes

The issue requests clear and reliable disabling semantics for `OPENCLAW_RAW_STREAM` under macOS LaunchAgent-managed gateway restarts.

## Best Possible Solution

Define one raw-stream disable precedence contract for managed services, cover it with LaunchAgent/service-env tests, and document the supported disable path plus any doctor/status repair guidance.

Rationale: Raw-stream logs can include prompts, tool output, and user data, so automation should not choose the sensitive logging precedence contract without maintainer intent.

Owner confidence: high

Options:

- **Explicit Disable Wins (recommended):** Treat unset, `0`, `false`, and `off` as authoritative managed-service disable signals, clear or override stale generated service env entries, and document the precedence.
- **Persisted Env Wins:** Keep state-dir `.env` and config env as the durable source and document that operators must edit those persisted values before a restart disables raw-stream logging.
- **Doctor-Guided Repair:** Keep runtime precedence mostly unchanged but add status or doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.

## Reproduction Assessment

Yes for a source-level path, but not as a live macOS run in this read-only review. A LaunchAgent wrapper can source persisted env after launchd inherited env, while the raw writer only respects the final process env value.

## Solution Assessment

Unclear until maintainers choose the precedence contract. The maintainable fix should align LaunchAgent wrapper env, generated service env, state-dir `.env`, config env, docs, and doctor/status guidance instead of patching only the append call.
