## Summary

Keep open: current main still has a source-supported LaunchAgent path where a generated service env file can set `OPENCLAW_RAW_STREAM=1` after launchd inherited env is unset or `0`, while the public docs do not define a disable/precedence contract and no merged related PR owns the fix.

## What This Changes

The issue asks OpenClaw to stop writing raw-stream logs after LaunchAgent-managed raw-stream env is unset or set to `0`, and to document supported disable values.

## Best Possible Solution

Define one sensitive-logging disable contract where explicit managed-service disable cannot be overridden by stale generated service env, then add focused LaunchAgent/service-env tests, public docs, and doctor/status guidance.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should an explicit LaunchAgent-managed disable for `OPENCLAW_RAW_STREAM` override persisted state-dir `.env` or config service-env values, or should those persisted sources stay authoritative until edited?

Rationale: Raw-stream logs can contain prompts, tool output, and user data, so automation should not choose the precedence rule for disabling sensitive diagnostic logging without maintainer intent.

Likely owner: steipete

Owner confidence: high

Options:

- **Explicit Disable Wins (recommended):** Treat unset, `0`, `off`, and `false` disable intent as authoritative for managed services, clear or override stale generated service-env entries, and document the precedence.
- **Persisted Env Stays Authoritative:** Keep state-dir `.env` and config env as the durable source and document that operators must edit those persisted values before restart disables raw-stream logging.
- **Doctor-Guided Repair Only:** Leave runtime precedence mostly unchanged but add status/doctor checks that warn and repair stale raw-stream service-env values before operators believe logging is off.

## Reproduction Assessment

Yes for a source-level path, but not as a live macOS run in this review. The writer disables on final false env values, while the LaunchAgent wrapper can source persisted service env before gateway startup.

## Solution Assessment

No current close path is proven best. The maintainable fix needs an explicit precedence contract across launchd inherited env, generated service env, state-dir `.env`, config env, docs, and doctor/status guidance.
