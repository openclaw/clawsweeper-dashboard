## Summary

Keep open. Current main and v2026.6.11 still keep Active Memory on the reply-critical embedded-recall path, the fixed shared recall lane is only partly addressed by an open PR, and the remaining blocking/default/model/QMD startup choices require maintainer direction.

## What This Changes

The issue asks for safer Active Memory recall and QMD startup behavior so multi-agent gateways do not lose reply responsiveness to blocking embedded recall or boot/update bursts.

## Best Possible Solution

Keep this as the canonical reliability tracker, land or reject the per-agent lane candidate for that narrow slice, and make a maintainer-approved decision on blocking versus nonblocking or single-shot recall, recall-model defaults, and bounded/lazy QMD startup behavior.

## Reproduction Assessment

Yes, at source level. Current main still awaits Active Memory embedded recall inside before_prompt_build, and the shared-lane slice remains present until the open per-agent-lane PR lands.

## Solution Assessment

No complete solution is present yet. Current main has useful mitigations, but the best fix still needs maintainer choice around blocking versus nonblocking recall, model defaults, lane isolation, and QMD startup policy.
