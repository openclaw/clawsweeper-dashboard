## Label Justifications

- `impact:crash-loop`: The reported failure mode includes high CPU, event-loop/liveness warnings, gateway health timeouts, and timeout cascades that affect process availability.

## Summary

Keep open: current main still leaves Active Memory on a blocking pre-reply path with one process-wide recall lane, and the open per-agent lane PR only covers one subpart of the broader reliability/defaults issue.

## What This Changes

The issue asks OpenClaw to make Active Memory recall fail-open or nonblocking, avoid slow inherited recall models, enforce hard budgets and concurrency limits, and prevent QMD startup bursts on multi-agent gateways.

## Best Possible Solution

Review the per-agent recall-lane fix, then make the remaining Active Memory reply-path defaults explicitly fail-open or opportunistic while keeping QMD startup lazy or opt-in with clear docs and doctor/status diagnostics.

## Reproduction Assessment

Yes, at source level: current main still awaits Active Memory recall in `before_prompt_build`, routes every recall through the fixed `active-memory` lane, and new command lanes default to one active task. I did not run a live multi-agent gateway reproduction in this read-only review.

## Solution Assessment

Unclear as one single fix: per-agent recall lanes are a narrow best fix for the serialization sub-mechanism, but the broader issue needs a maintainer decision on fail-open defaults, model inheritance, and new config or diagnostics surfaces.
