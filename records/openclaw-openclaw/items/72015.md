## Label Justifications

- `P1`: The issue reports source-backed gateway availability and reply-latency failures affecting real interactive users when Active Memory is enabled.
- `impact:crash-loop`: The reported high CPU, event-loop stalls, health timeouts, and channel reconnect flaps are process-level availability failures.

## Summary

Keep open: current main and v2026.6.11 still leave Active Memory recall on a reply-critical before_prompt_build path and one fixed process-wide active-memory lane. The open pull request at https://github.com/openclaw/openclaw/pull/99105 targets the lane slice, but the broader nonblocking/default-model/QMD-startup policy remains unresolved.

## What This Changes

Request to make Active Memory and QMD startup safer for multi-agent gateways by avoiding blocking recall, slow inherited models, weak timeout enforcement, recall concurrency stacking, boot bursts, and hidden operational cost.

## Best Possible Solution

Keep this issue as the canonical reliability tracker while maintainers review the per-agent lane PR and choose the safe default policy for blocking recall, recall model selection, and QMD startup work.

## Reproduction Assessment

Yes. Source inspection on current main shows the Active Memory before_prompt_build hook awaits embedded recall, that recall uses one fixed active-memory lane, and unconfigured lanes default to one active task.

## Solution Assessment

Unclear as a complete solution. The open per-agent lane PR is a good narrow fix for cross-agent serialization, but maintainers still need to decide the broader blocking/default-model/QMD startup policy.
