## Summary

Keep open: current main and v2026.6.11 still leave Active Memory recall on the reply-critical hook with one fixed process-wide recall lane, and the open lane PR only covers one slice of the broader defaults/QMD startup decision.

## What This Changes

The issue requests safer Active Memory and QMD startup behavior so memory recall does not block replies or overload multi-agent gateways.

## Best Possible Solution

Keep this issue as the canonical reliability tracker while maintainers review the lane PR and choose the safe default policy for blocking recall, recall model selection, and QMD startup work.

## Reproduction Assessment

Yes. Source inspection on current main shows the Active Memory before_prompt_build hook awaits embedded recall, that recall uses one fixed active-memory lane, and unconfigured lanes default to one active task.

## Solution Assessment

Unclear as a complete solution. The open per-agent lane PR is a good narrow fix for cross-agent serialization, but maintainers still need to decide the broader blocking/default-model/QMD startup policy.
