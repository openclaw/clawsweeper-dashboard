## Label Justifications

- `P1`: Multiple live reports show Active Memory can make normal agent/channel replies slow, timed out, or gateway-unreliable for real users, but the affected feature is optional rather than an unavoidable core startup blocker.
- `impact:crash-loop`: The report and supporting comments describe gateway CPU spikes, health probe timeouts, event-loop stalls, and restart/boot overload symptoms.
- `impact:session-state`: The core failure is tied to memory recall and context injection on the reply-critical session path, including timeouts, empty recall, and shared memory-manager lifecycle issues.
- `maturity:stable`: The issue affects Gateway runtime health and reply-path reliability, and the `gateway-runtime` maturity surface is M4 Stable.

## Summary

Keep open: current main and v2026.6.11 still run Active Memory as a blocking pre-prompt embedded recall on the reply path, while QMD startup has only been partially reduced by opt-in/lazy startup behavior. The open per-agent recall-lane PR covers one useful slice, but the broader nonblocking default, model/default budget, cancellation, shared-manager cleanup, and operational-status decisions remain live maintainer work.

## What This Changes

The issue asks OpenClaw to make Active Memory recall fail open/nonblocking with safer model, timeout, and concurrency behavior, and to prevent QMD startup work from overloading multi-agent gateways.

## Best Possible Solution

Keep this issue as the canonical reliability umbrella until maintainers choose and land a fail-open Active Memory default plus narrow fixes for recall lane isolation, prompt sizing, cancellation/shared-manager cleanup, QMD startup behavior, and operator-facing diagnostics.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows eligible Active Memory turns still await embedded recall inside `before_prompt_build`, and the latest release still documents that path as blocking; I did not run a live gateway repro in this read-only sweep.

## Solution Assessment

No single current fix is the best complete solution yet. The QMD startup changes and the open per-agent recall-lane PR are useful partial fixes, but the maintainable end state needs a maintainer-approved fail-open/defaults and lifecycle design across Active Memory, QMD, and diagnostics.
