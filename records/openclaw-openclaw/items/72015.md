## Label Justifications

- `P1`: The issue reports source-backed gateway availability and reply-latency failures affecting real interactive users when Active Memory is enabled.
- `impact:crash-loop`: The reported high CPU, event-loop stalls, health timeouts, and channel reconnect flaps are process-level availability failures.

## Summary

Keep open: current main and v2026.6.11 still leave the reply-critical Active Memory embedded recall path and fixed process-wide recall lane in place; an open PR targets the lane slice, but the broader default, model, and QMD startup decisions remain unresolved.

## What This Changes

The issue requests safer Active Memory and QMD startup behavior so embedded memory recall does not block replies or overload multi-agent gateways.

## Best Possible Solution

Keep this issue as the canonical reliability tracker while maintainers review https://github.com/openclaw/openclaw/pull/99105 and choose a safe mix of per-agent recall isolation, hard or nonblocking recall budgets, explicit fast recall-model policy, and bounded or lazy QMD startup.

## Reproduction Assessment

Yes. Source inspection shows an eligible Active Memory before_prompt_build hook awaits embedded recall, that recall uses one fixed active-memory lane, and unconfigured lanes default to one active task.

## Solution Assessment

Unclear as a complete solution. The open per-agent lane PR is a narrow fix for cross-agent serialization, but maintainers still need to decide the broader blocking/default/model/QMD startup policy.
