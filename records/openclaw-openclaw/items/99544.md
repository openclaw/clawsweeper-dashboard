- `impact:message-loss`: The clicked Slack action value can be destructively consumed before the agent receives it.

## Summary

Keep open. Current main and the latest release still queue and wake Slack interactions, but heartbeat prompt rendering only materializes exec or cron events while the fallback consumption path can remove all pending events; two open PRs now target this issue and should be reviewed as fix candidates.

## What This Changes

Slack interactive action values can be queued and consumed by a hook heartbeat without being rendered into the agent prompt.

## Best Possible Solution

Review and land one narrow fix that renders the queued Slack interaction payload before heartbeat consumption, or leaves it queued until a rendering path consumes it, with regression coverage for the heartbeat prompt and consume symmetry.

## Reproduction Assessment

Yes. The source path shows a Slack block action queues `Slack interaction: ...`, requests a hook heartbeat, falls through the generic heartbeat prompt because no exec/cron bucket matches, and then selects all pending events for removal.

## Solution Assessment

Yes. The best fix is a narrow heartbeat prompt/consume symmetry repair, preferably through one of the open PRs, rather than a new Slack dispatch architecture or config option.
