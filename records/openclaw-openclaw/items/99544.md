## Summary

Keep open. Current main and the latest release still enqueue and wake Slack interactions, but the heartbeat prompt only renders exec or cron event bodies before the fallback consumption path can remove the Slack interaction; two open PRs now reference this issue as fix candidates, so the issue should stay canonical until one lands.

## What This Changes

Ensure Slack interaction system-event values are injected into or preserved through hook heartbeat turns instead of being consumed by the generic heartbeat path.

## Best Possible Solution

Land one narrow fix that keeps heartbeat prompt rendering and system-event consumption symmetric for Slack interaction events, with regression coverage proving every consumed interaction value reaches the model input or remains queued.

## Reproduction Assessment

Yes. Source inspection shows a Slack block action queues a slack:interaction event and requests a hook heartbeat, while current heartbeat prompt resolution does not render that event type before the fallback consumption path can remove it.

## Solution Assessment

Yes. The best fix is a narrow heartbeat prompt/consume symmetry repair, not a new config option or separate Slack-only dispatch path; the open PRs should be reviewed against that invariant.
