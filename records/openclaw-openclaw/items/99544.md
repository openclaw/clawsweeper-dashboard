## Summary

Keep open. Current main and the latest release still enqueue Slack interaction events and request a hook heartbeat, but the heartbeat prompt only renders exec or cron event text before the fallback selector can consume the Slack interaction payload; https://github.com/openclaw/openclaw/pull/99565 is the active open fix candidate and should be reviewed before this issue closes.

## What This Changes

The issue asks for Slack interaction system-event text to reach the heartbeat agent turn instead of being destructively consumed without the clicked action value.

## Best Possible Solution

Land or reject the open fix candidate, with heartbeat prompt rendering and heartbeat consumption kept symmetric so Slack interaction values either reach the model input or remain queued until a rendering path consumes them.

## Reproduction Assessment

Yes, source inspection gives a high-confidence path: Slack block actions enqueue a slack:interaction event and request a hook heartbeat, while current heartbeat prompt resolution only renders exec or cron events before fallback consumption can remove the interaction entry.

## Solution Assessment

Yes, the narrow maintainable fix is to repair heartbeat prompt/consume symmetry rather than add a Slack-only dispatch fork or new config surface; the issue should stay open while the linked PR is reviewed.
