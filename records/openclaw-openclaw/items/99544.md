## Summary

Keep open. Current main still queues and wakes for Slack interactions, but the heartbeat prompt only injects exec or cron event bodies; when neither bucket matches, the pending Slack interaction can be consumed without its value reaching the agent prompt.

## What This Changes

The issue requests that Slack button interaction payloads be injected into the heartbeat agent turn instead of only waking and then draining the queued system event.

## Best Possible Solution

Make heartbeat handling symmetric for Slack interaction system events: render the queued interaction payload into the heartbeat prompt or leave it queued until a path that renders it consumes it, without adding a new config surface.

## Reproduction Assessment

Yes, from source inspection rather than a live Slack run. A Slack block action queues a slack:interaction event and requests a hook heartbeat; current heartbeat prompt resolution does not render that event type before the fallback consumption path can remove it.

## Solution Assessment

Yes, the best fix is a narrow heartbeat prompt/consume symmetry repair, not a separate Slack-only dispatch path. The implementation should avoid duplicating inbound routing and should add regression coverage proving the interaction value reaches the model input or remains queued until it can.

## Repair Work Prompt

Fix the Slack interaction heartbeat consume-side bug tracked by https://github.com/openclaw/openclaw/issues/99544. Current main queues Slack block-action payloads and requests a hook heartbeat, but src/infra/heartbeat-runner.ts only renders exec and cron pending events before selecting all pending inspected events for consumption, so slack:interaction payloads can be spliced out without reaching the model. Implement a narrow symmetry fix: either add a typed/generic pending-system-event heartbeat prompt that includes the sanitized Slack interaction text when no exec/cron builder matched, or make the fallback consumption path leave unrendered generic events queued until a normal turn drains them. Prefer the smallest core-owned fix that preserves existing Slack enqueue/wake behavior and avoids a new config option or duplicate Slack-only dispatch pipeline. Add regression coverage for a hook wake with a queued slack:interaction event containing an action value, proving the value reaches the heartbeat Body or is not consumed when it is not rendered; keep existing exec and cron consumption behavior intact. Do not edit CHANGELOG.md for this normal fix; put release-note context in the PR body if a PR is opened.
