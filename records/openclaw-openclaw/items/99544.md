## Summary

Keep open. Current main and the latest release still route Slack interaction events into the heartbeat path without rendering that event text into the prompt, and two open PRs now explicitly claim this issue as their fix target.

## What This Changes

The issue reports that Slack interaction events wake the heartbeat runner but lose the clicked action value before it reaches the agent prompt.

## Best Possible Solution

Land one narrow fix that makes heartbeat prompt rendering and event consumption symmetric for Slack interaction system events, then close this issue from the merged PR.

## Reproduction Assessment

Yes. Source inspection shows a Slack block action queues a slack:interaction event and requests a hook heartbeat, while current heartbeat prompt resolution does not render that event type before the fallback consumption path can remove it.

## Solution Assessment

Yes for the requested direction. The maintainable fix should repair heartbeat prompt/consume symmetry without adding config, and the exact implementation should be selected through the open fixing PR review.
