## Summary

Keep open: current main and the latest release still contain the remaining cron/exec classification path, and a maintainer explicitly said this issue should stay open for typed exec failure-phase/process-started evidence rather than the closed text-inference fixes.

## What This Changes

The issue asks cron isolated `agentTurn` delivery not to be skipped when an earlier recovered tool error is incorrectly promoted to fatal, and asks cron state to distinguish delivery-not-attempted from delivery send failure.

## Best Possible Solution

Add typed exec failure-phase/process-started evidence and use it in cron outcome resolution so genuinely recovered process-started tool failures can deliver final output while unresolved mutating failures remain visible as degraded or warning outcomes.

## Reproduction Assessment

Yes at source level: current main and `v2026.6.11` still contain the fatal structured-payload pre-dispatch branch plus the completed nonzero-exit tool-error classifier. I did not run a live scheduled provider delivery repro in this read-only review.

## Solution Assessment

No, the closed simple fixes are not the best solution because they infer recovery from display text or final prose and can mask unresolved mutating actions. The better fix is typed exec/process-started evidence plus an explicit degraded cron outcome contract.
