## Summary

Keep open: current main and the latest release still have the source-level recovered-tool-warning gate that can keep a successful isolated cron run on the fatal pre-dispatch path, and multiple open PRs already reference this issue as candidate fixes.

## What This Changes

The issue reports that scheduled isolated cron agent runs can recover from an early tool error and produce final output, but the cron wrapper still treats the recovered warning as fatal and skips delivery dispatch.

## Best Possible Solution

Review and land one canonical narrow cron payload-outcome fix, such as https://github.com/openclaw/openclaw/pull/94849 or an equivalent replacement, that recovers known tool-warning trajectories while preserving true fatal structured-error suppression.

## Reproduction Assessment

Yes. The current main resolver still requires channel final-text preference for recovered cron tool warnings, and the fatal structured-payload branch returns before delivery dispatch when that escape hatch is missed.

## Solution Assessment

Yes for the direction: the narrow maintainable fix belongs in the cron payload outcome/finalization path, not a new config flag. The remaining maintainer choice is which open candidate PR should be the canonical implementation.
