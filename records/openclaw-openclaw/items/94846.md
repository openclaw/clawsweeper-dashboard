## Summary

Keep open: current main and v2026.6.11 still contain the source-level path where a completed nonzero exec result can become an error payload, the cron helper can classify that recovered output as fatal for non-preferred channels, and the finalizer then returns before normal delivery dispatch. A member rechecked current main in the issue discussion and explicitly kept this issue open because the safe fix needs typed exec failure-phase/process-started evidence plus a degraded cron outcome decision.

## What This Changes

Issue reports scheduled isolated cron agentTurn runs skipping direct delivery when an early recovered tool error is selected as fatal before dispatch despite final assistant output.

## Best Possible Solution

Add a typed exec failure-phase/process-started signal that cron can consume, then represent process-started recovered failures as a first-class degraded or warning cron outcome with separate delivery attempt, alert, retry, and diagnostics state.

## Reproduction Assessment

Yes. Source inspection plus sanitized issue evidence shows completed nonzero exec results still become tool-error state, non-preferred cron channels still miss the recovered-warning path, and fatal structured payloads still skip delivery before dispatch.

## Solution Assessment

No. The earlier narrow fixes that removed the final-text preference guard are not the best fix because maintainers found they can mask mutating failures; the safer solution needs typed exec phase evidence and an explicit degraded cron outcome contract.
