## Summary

Keep open: current main and v2026.6.11 still have the source-level path where Feishu-like channels fail the recovered-tool-warning escape hatch and return before cron delivery dispatch; the issue also has two open closing PRs, so it should stay open until one fix lands or is superseded.

## What This Changes

The issue asks cron isolated agentTurn finalization to deliver final assistant output after a recovered early tool error instead of treating that earlier warning as a fatal pre-dispatch failure.

## Best Possible Solution

Review and land one narrow cron payload-outcome fix that treats recovered tool warnings with final assistant output as non-fatal for delivery, while keeping true fatal structured errors, run-level errors, and structured/media delivery payloads protected.

## Reproduction Assessment

Yes. Current main and v2026.6.11 still show the source-level fatal-classification and pre-dispatch return path, and the issue includes reduced scheduled-run plus latest-release field evidence; I did not run a live Feishu/WSL2 scheduled job in this read-only review.

## Solution Assessment

Yes for the fix direction. The narrow maintainable solution is in cron payload outcome classification and focused regression coverage, not a new config flag or broad cron status rewrite.
