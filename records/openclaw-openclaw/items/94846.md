## Summary

Keep open: current main and v2026.6.11 still gate recovered cron tool-warning recovery on channel final-text preference, so Feishu-like announce delivery can still be skipped before dispatch; two open closing PRs already own the fix path.

## What This Changes

The issue requests that isolated scheduled agentTurn delivery still dispatch final assistant output after a recovered early tool error instead of treating the stale tool warning as fatal.

## Best Possible Solution

Land or consolidate a focused fix that treats recovered tool-warning classification independently from channel final-text preference, preserves structured/media payloads, and adds coverage for preferFinalAssistantVisibleText=false plus fatal controls.

## Reproduction Assessment

Yes at source level: the current helper still classifies recovered tool warnings as recovered only when the channel prefers final assistant text, and run finalization still returns before dispatch on fatal structured payloads. I did not run a live scheduled Feishu-like cron job in this read-only review.

## Solution Assessment

Yes: the best fix is the narrow helper-level recovery change represented by the focused open PR, with tests for non-preferred channels and fatal controls. Broader run-status/delivery decoupling work should stay separate unless maintainers intentionally combine it.
