## Summary

Keep open: current main still has the fatal pre-dispatch cron path and lacks the typed exec failure-phase/process-started evidence that the July 4 maintainer review identified as the safe remaining direction.

## What This Changes

The issue reports that scheduled isolated cron `agentTurn` runs can recover and produce final output, yet an earlier tool error is classified as fatal so delivery is skipped before dispatch.

## Best Possible Solution

Add typed exec failure-phase/process-started evidence and use it in cron classification so successful isolated runs with process-level warnings can be represented without hiding unresolved mutating actions or provider failures.

## Reproduction Assessment

Yes at source level, with recent field evidence: current main still has the fatal pre-dispatch branch and the issue comments include a v2026.6.11 scheduled-run reproduction. I did not run the live WSL2/Linux scheduled cron setup in this read-only review.

## Solution Assessment

No, the earlier helper-only recovery direction is no longer the best fix. The safer path is typed exec failure-phase/process-started metadata plus a maintainer-approved degraded/warning cron outcome when a process actually ran.
