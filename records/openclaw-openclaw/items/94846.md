## Summary

Keep open: current main and the latest release still classify the reported recovered isolated-cron tool-warning path as fatal before delivery dispatch, and there are open linked PRs that should be reviewed or consolidated before this issue closes.

## What This Changes

The issue asks cron isolated `agentTurn` delivery to continue when an early recoverable tool error is followed by successful final assistant output, or to record an explicit not-attempted delivery reason.

## Best Possible Solution

Review and land or consolidate one narrow `resolveCronPayloadOutcome` fix that treats recovered tool warnings with final assistant text as non-fatal across false-preference channels while preserving genuine fatal run-level errors and structured payload safety.

## Reproduction Assessment

Yes, at source level: current main still gates recovered `⚠️ 🛠️` tool-warning recovery on `preferFinalAssistantVisibleText` and then returns before dispatch when the structured warning remains fatal. I did not run the live WSL2/Feishu scheduled setup in this read-only review.

## Solution Assessment

Yes for the direction: the narrow maintainable fix is in cron payload-outcome classification and delivery payload selection, not a new config flag or broad cron status rewrite. The exact branch should be chosen by reviewing the open candidate PRs together.
