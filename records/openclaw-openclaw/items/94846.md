## Label Justifications

- `P2`: The bug affects real scheduled reporting and maintenance delivery, but the blast radius is bounded to isolated cron `agentTurn` outcome classification.
- `impact:session-state`: The parent cron run can record an error even when the isolated session ended successfully with a final assistant result.
- `impact:message-loss`: The reported successful final assistant output can be skipped before channel dispatch, leaving the user with `not-delivered` run history.

## Summary

Keep open. Current main still has the cron path that can treat recovered structured tool-error payloads as fatal before delivery dispatch, and maintainer discussion identifies unresolved product semantics for typed exec failure-phase evidence and degraded cron outcomes.

## What This Changes

The issue asks cron isolated `agentTurn` delivery to preserve successful final assistant output after recoverable tool failures and distinguish delivery-not-attempted from send failure.

## Best Possible Solution

Define typed exec failure-phase/process-started metadata and a first-class degraded/warning cron outcome so recovered non-terminal errors can still attempt delivery while real unresolved failures remain fail-closed.

Options:

- **Add typed degraded outcome (recommended):** Introduce typed process-started/failure-phase evidence and persist a degraded or warning cron outcome that allows delivery when the final assistant result is otherwise valid.
- **Keep fatal, improve diagnostics:** Keep the current fail-closed behavior and add explicit not-attempted/failure-phase diagnostics so users can see that delivery was skipped before dispatch.
- **Limit recovery to non-mutating tools:** Only recover read-only or explicitly non-mutating tool failures and leave mutating or ambiguous exec failures fatal.
