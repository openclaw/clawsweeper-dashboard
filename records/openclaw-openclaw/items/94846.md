## Summary

Keep open: current main and latest release still gate recovered cron tool-warning recovery on channel final-text preference, and the latest field evidence says the bug still reproduces on v2026.6.11. Open linked fix PRs remain the right path; this issue should close only after one lands.

## What This Changes

Fix scheduled isolated cron agentTurn delivery so recovered early tool errors do not suppress final assistant output dispatch or blur not-attempted delivery with send failure.

## Best Possible Solution

Land one canonical narrow cron payload-outcome fix, likely the https://github.com/openclaw/openclaw/pull/94849 shape, that treats recovered tool-warning final output as non-fatal without masking true fatal structured or run-level errors.

## Reproduction Assessment

Yes, at source level: current main still requires channel final-text preference before recovered tool warnings can clear fatality, and the finalizer returns before dispatch when that remains fatal. I did not run a live scheduled Feishu job in this read-only review.

## Solution Assessment

Yes for the narrow bug: the shared resolver/finalizer boundary is the maintainable place to fix recovered tool-warning classification and delivery payload selection. Broader final-assistant recovery needs separate maintainer judgment.
