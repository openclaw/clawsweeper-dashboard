## Summary

Keep open: current main still has the pre-dispatch fatal structured-error path, and release/user evidence on v2026.6.11 shows recovered isolated cron runs can still end session-success while outer cron records error and skips delivery.

## What This Changes

The issue asks cron isolated agentTurn delivery to preserve recovered successful session output instead of treating an earlier recoverable tool error as a fatal pre-dispatch delivery failure.

## Best Possible Solution

Add typed exec failure-phase/process-started metadata, then model recovered process-ran failures with a first-class degraded/warning cron outcome and separate delivery attempted/result state.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For recovered isolated cron runs where a process-ran exec/tool failure is followed by final assistant output, should cron record success, error, or a degraded/warning outcome, and should completion delivery proceed?

Rationale: Current code cannot distinguish all safe recovery cases, and the choice changes persisted cron status, delivery state, alerts, and retry/backoff behavior rather than being a mechanical bug fix.

Likely owner: vincentkoc

Owner reason: They are assigned and already gave the maintainer direction that this needs typed exec phase evidence and degraded cron outcome semantics.

Owner confidence: high

Options:

- **Add degraded cron outcome (recommended):** Introduce typed exec phase evidence and a degraded/warning cron state that can still dispatch completion delivery while preserving failure diagnostics and alert semantics.
- **Keep fail-closed behavior:** Continue treating process-ran nonzero failures as fatal until a later explicit same-action recovery contract proves the failure is resolved, accepting missed reports to avoid false success.
- **Treat final assistant output as success:** Prefer final assistant visible output after session success for delivery, but this risks hiding unresolved mutating failures without the typed phase and degraded-state work.

## Reproduction Assessment

Yes from source inspection and field evidence: current main still has the fatal structured-error pre-dispatch branch and reporters reproduced the same class on v2026.6.11, but I did not run a live scheduled cron in this read-only review.

## Solution Assessment

No for the earlier simple classifier/final-text approach; the best remaining fix needs maintainer-approved typed exec phase metadata plus explicit degraded cron state instead of inferring recovery from display text or prose.
