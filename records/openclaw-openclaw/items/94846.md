## Label Justifications

- `P2`: This is a normal-priority cron delivery bug with real scheduled-report impact but limited to recovered isolated `agentTurn` runs with delivery requested.
- `impact:session-state`: The outer cron run state can report fatal/error even though the isolated agent session completed successfully with final output.
- `impact:message-loss`: The final assistant output can be skipped before delivery dispatch, leaving the scheduled report undelivered.

## Summary

Keep open: current main and the latest release still require the channel to prefer final assistant text before a recovered cron tool warning is treated as non-fatal, and the fatal structured-error path returns before delivery dispatch. The issue is already paired with open fix candidates, so maintainer review should choose or consolidate that path rather than close it now.

## What This Changes

Reports that scheduled isolated `agentTurn` cron delivery is skipped when a recovered early tool warning is classified as fatal before `dispatchCronDelivery(...)`.

## Best Possible Solution

Land or consolidate a canonical cron-helper fix that treats recovered tool warnings with final assistant output as non-fatal regardless of channel final-text preference, while preserving structured/media payload behavior and adding regression coverage for Feishu-like channels.

## Reproduction Assessment

Yes, at source level: a recovered tool-warning payload plus final assistant text remains fatal when the delivery channel does not set `preferFinalAssistantVisibleText`. I did not rerun live Feishu delivery, but the issue includes reduced scheduled-run evidence and a latest-release field report matching the current code path.

## Solution Assessment

Yes, the narrow best fix is in cron payload outcome classification and delivery payload selection, not in Feishu delivery itself. The maintainer choice is which open candidate PR best implements that boundary without changing unrelated delivery/status semantics.
