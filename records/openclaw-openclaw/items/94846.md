## Summary

Keep open: maintainer discussion says the remaining July 2 failure shape is still valid, and current `main` still has the cron fatal-classification gates that can return before normal delivery dispatch. The original read-only `sed` subcase is partly covered elsewhere, but the remaining exec failure-phase/process-started ambiguity is not implemented on `main`.

## What This Changes

The issue reports scheduled isolated cron `agentTurn` runs skipping completion delivery when an earlier recovered tool error is still treated as fatal during cron finalization.

## Best Possible Solution

Add typed exec failure-phase/process-started evidence and use it in cron finalization so recovered non-terminal failures can deliver final output while real mutating/provider failures become an explicit degraded or warning outcome instead of false success or false non-delivery.

## Reproduction Assessment

Yes at source level: current `main` still has the fatal structured-payload and run-level-error gates that can suppress normal delivery dispatch. The remaining live July 2 case still needs sanitized `details.status`, `details.exitCode`, and compact error text to choose the exact process-phase fix safely.

## Solution Assessment

No for the closed broad recovery PR direction: maintainer review rejected inferring recovery from display text, failed-result shape, or final assistant prose alone. The best fix is narrower typed exec/process-started evidence feeding cron outcome classification.
