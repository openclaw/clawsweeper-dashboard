## Summary

Keep open: current main and v2026.6.11 still contain the source-level cron classifier/pre-dispatch skip path, and the latest maintainer comment explicitly keeps this issue open pending typed exec failure-phase/process-started evidence rather than display-text recovery heuristics.

## What This Changes

The issue reports scheduled isolated cron agent turns that recover and produce final output but are recorded as failed and not delivered before normal dispatch.

## Best Possible Solution

Add typed exec failure-phase/process-started evidence and have cron consume it to distinguish preflight rejection from launched subprocess failure; if the process ran, design a first-class degraded/warning cron outcome across persistence, delivery state, alerts, and retry/backoff.

## Reproduction Assessment

Yes at source level for the current classifier/pre-dispatch skip path: current main can still classify recovered tool-warning output as fatal and return before dispatch. The exact July 2 exec phase remains only partially reproducible until the reporter provides sanitized details.status, details.exitCode, and compact error text.

## Solution Assessment

Unclear as an implementation until the exec phase is known: display-text or assistant-prose recovery is not the best fix because it can mask failed side effects. The best path is typed producer evidence consumed by cron, with a deliberate degraded/warning outcome if a subprocess actually ran.
