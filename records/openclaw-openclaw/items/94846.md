## Label Justifications

- `P2`: This is a normal-priority cron delivery correctness bug with concrete field reports and limited blast radius to scheduled isolated agentTurn delivery.
- `impact:message-loss`: The final assistant output can be produced but not delivered because cron finalization returns before the delivery dispatcher.
- `impact:session-state`: The outer cron run state can record an error/not-delivered outcome even though the isolated session recovered and ended successfully.

## Summary

Keep open: current main and the latest release still gate recovered tool-warning recovery on channel final-text preference, so Feishu/Slack-like announce channels can still classify recovered runs as fatal and return before delivery dispatch. Two open closing PRs already own the fix path, so this issue should stay open until one lands or maintainers consolidate them.

## What This Changes

Reported scheduled isolated `agentTurn` cron delivery skip when a recovered early tool warning is classified as fatal before dispatch.

## Best Possible Solution

Land or consolidate a narrow fix that makes recovered tool-warning classification independent of channel final-text preference while delivering final assistant text for text-only recovered runs, with regression coverage for non-preference delivery channels.

## Reproduction Assessment

Yes. The source path on current main shows the reported failure condition: non-preference channels keep `hasRecoveredToolWarning` false, which can leave `hasFatalStructuredErrorPayload` true and hit the pre-dispatch return.

## Solution Assessment

Yes. The narrow best fix is to decouple recovery classification from channel output preference and ensure text-only recovered runs deliver final assistant text; https://github.com/openclaw/openclaw/pull/94849 is the clearest current candidate, while broader run-level-error handling may need separate maintainer choice.
