## What This Changes

Fix isolated scheduled `agentTurn` runs so recovered tool failures do not prevent delivery of successful final output, while separating typed exec failure phases, cron outcome, and delivery-attempt/result state.

## Best Possible Solution

Ratify a typed exec failure-phase/process-start contract, then implement one canonical cron degraded/warning outcome that preserves operator diagnostics, records delivery attempted separately from delivery result, and dispatches final output only under the approved recovery rules.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For an isolated cron session that ends successfully after a child process actually ran and exited nonzero, should OpenClaw use a persisted degraded/warning run outcome that may still dispatch final output, rather than infer success from final text or report a terminal error?

Rationale: The maintainer has rejected text-based recovery as unsafe, while the remaining proposal changes durable cron status, delivery-state semantics, alerting, and retry/backoff behavior; source-level implementation cannot safely choose that product contract unilaterally.

Likely owner: vincentkoc

Owner reason: The assigned member has already articulated the safety boundary and required design direction in the issue discussion.

Owner confidence: high

Options:

- **Approve typed degraded delivery (recommended):** Add typed process-start/failure-phase evidence and a degraded cron outcome that preserves warnings but can attempt delivery when the approved final-deliverable criteria hold.
- **Keep terminal-error semantics:** Continue treating process-ran nonzero exits as terminal for cron delivery, while improving records to distinguish not-attempted delivery from provider send failure.
- **Narrow the eligible recovery class:** Define a smaller typed subset of failures that may degrade and deliver, leaving all other process-exit failures terminal.
