## Label Justifications

- `P2`: The bug affects real scheduled reporting and maintenance delivery, but the blast radius is bounded to isolated cron agentTurn outcome classification.
- `impact:message-loss`: The final assistant output can be skipped before channel dispatch even though the isolated run produced it.
- `impact:session-state`: The outer cron run can record fatal error state while the isolated agent session completed successfully.

## Summary

Keep open: current main still has the reported pre-dispatch fatal-error path, and the latest maintainer discussion explicitly says the issue remains valid pending typed exec process-start/failure-phase evidence plus a first-class degraded cron outcome.

## What This Changes

The issue reports that scheduled isolated cron agentTurn runs can recover from an early tool error but still have final delivery skipped because cron finalization treats the earlier error as fatal.

## Best Possible Solution

Add typed exec failure-phase/process-started evidence that cron can trust, then represent process-ran recovered failures with a first-class degraded/warning cron outcome and separate delivery attempt/result state.

## Reproduction Assessment

Yes from source inspection and field evidence: current main still has the fatal structured-error pre-dispatch return and the recovery gates described by the issue. I did not run a live scheduled cron reproduction in this read-only review.

## Solution Assessment

No, the earlier simple classifier/final-text approach is not the best remaining fix because maintainers rejected inference from display text or final assistant prose as unsafe for mutating process-ran failures. The safer path is typed exec phase metadata plus explicit degraded cron state.
