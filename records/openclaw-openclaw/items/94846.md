## Summary

Keep open: current `main` and the latest release still have the recovered-tool-warning gate tied to channel final-text preference, and the fatal structured-payload branch still returns before cron delivery dispatch. The issue is already paired with open closing PRs, so the cleanup path is maintainer review/consolidation rather than closing or queueing a new fix PR.

## What This Changes

Cron isolated `agentTurn` should deliver final assistant output after a recovered early tool error instead of treating the recovered warning as fatal before dispatch.

## Best Possible Solution

Land one canonical narrow cron payload-outcome fix that recovers known tool-warning trajectories with final output while preserving true fatal structured-error suppression and genuine run-level failures.

## Solution Assessment

Yes for the narrow direction. The maintainable fix belongs in cron payload outcome classification/finalization, not in a new config flag or broad cron status rewrite; the linked open PRs should be reviewed as candidate implementations.
