## What This Changes

The issue reports isolated scheduled cron agentTurn delivery being skipped before dispatch when an earlier recovered tool error is classified as fatal despite final assistant output.

## Best Possible Solution

Add typed exec failure-phase/process-started evidence and a cron outcome model that distinguishes pre-exec rejection, completed nonzero subprocess warnings, recovered tool diagnostics, delivery attempted, and delivery not attempted while preserving fatal signals and mutating-action safeguards.

## Reproduction Assessment

Yes, source-reproducible with strong field evidence: current main still has the fatal structured-payload pre-dispatch branch, and July 4 sanitized logs show completed nonzero exec results followed by successful isolated output. I did not live-run the scheduled WSL2/Feishu scenario in this read-only review.

## Solution Assessment

Unclear as a product decision: simple recovery heuristics were closed as unsafe, and the best fix now needs typed process/failure-phase evidence plus a first-class degraded or warning cron outcome. A narrow code repair should wait for that maintainer-approved contract.
