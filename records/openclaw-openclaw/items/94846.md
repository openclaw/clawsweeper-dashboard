## Label Justifications

- `P2`: This is a bounded scheduled-cron delivery bug with real operator impact but limited blast radius.
- `impact:message-loss`: The reported runs produced final assistant output but did not dispatch that output to the configured delivery channel.
- `impact:session-state`: The parent cron run state diverges from the successful isolated session outcome and records the recovered tool warning as fatal.

## Summary

Keep open: current main and v2026.6.11 still gate recovered tool-warning recovery on channel final-text preference, so Feishu-like delivery can still return before dispatch after a successful isolated agent turn; open candidate PRs already own the fix path.

## What This Changes

The issue asks OpenClaw cron to deliver final output from a recovered isolated scheduled agentTurn instead of treating an earlier recovered tool warning as fatal.

## Best Possible Solution

Review and land one narrow cron payload-outcome fix, such as https://github.com/openclaw/openclaw/pull/94849 if maintainers accept that shape, that treats recovered tool warnings with final output as non-fatal and delivers the final assistant text on non-preference channels.

## Reproduction Assessment

Yes at source level: current main still gates recovered tool-warning recovery on `preferFinalAssistantVisibleText`, and v2026.6.11 still contains the same gate and pre-dispatch return. I did not run the live scheduled Feishu setup in this read-only review.

## Solution Assessment

Yes: the best fix is a narrow cron payload-outcome classification change that lets recovered tool warnings with final assistant output proceed to delivery. A new config option or broad cron status rewrite would be larger than this specific bug requires.
