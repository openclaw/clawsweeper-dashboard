## Summary

Keep open: current main and the latest release still contain source paths that can classify completed nonzero exec/tool results as errors and return before delivery, and a repository member explicitly kept this issue open pending typed exec failure-phase/process-started evidence and a degraded/warning cron outcome decision.

## What This Changes

This issue reports that scheduled isolated cron agent turns can finish successfully after an intermediate exec/tool error but still have cron classify the earlier error as fatal and skip delivery.

## Best Possible Solution

Keep this issue open until a maintainer-approved fix adds typed exec failure-phase/process-started evidence and a cron degraded/warning outcome that preserves delivery diagnostics, alerts, retry/backoff semantics, and true fatal failures.

## Reproduction Assessment

Yes, source-reproducible: current main still has the cron fatal structured-payload pre-dispatch branch, and completed nonzero exec results still become tool-error state. I did not execute the live scheduled channel setup in this read-only review.

## Solution Assessment

No, the earlier remove-the-channel-preference-guard fixes are no longer the best solution after the July 4 maintainer update. The safer path is typed exec process-started/failure-phase evidence plus a first-class degraded or warning cron outcome for process-ran recoveries.
