- `P2`: The issue affects scheduled cron delivery/status reliability for real workflows, but the blast radius is bounded to isolated agentTurn cron recovery cases.
- `impact:message-loss`: The reported successful final assistant output was not dispatched to the configured channel because delivery was skipped before dispatch.

## Summary

Keep open: current main and v2026.6.11 still have the recovered tool-warning classifier gate that can mark a successful isolated cron run fatal before delivery dispatch, and open linked PRs still own the candidate fixes.

## What This Changes

Treat recovered isolated scheduled agentTurn tool-warning runs with final assistant output as eligible for cron delivery instead of classifying the earlier tool error as fatal before dispatch.

## Best Possible Solution

Review and land one narrow cron payload-outcome fix that lets proven recovered tool-warning runs deliver final assistant output while preserving true fatal structured errors and run-level failures.

## Reproduction Assessment

Yes. The source path is high-confidence: current main still keeps recovered tool-warning recovery behind channel final-text preference and returns before dispatch when the warning remains fatal; the issue also includes a reduced scheduled run and a fresh v2026.6.11 field repro.

## Solution Assessment

Yes for the central bug. The shared helper classification is the right layer to repair before cron finalization dispatch; broader diagnostics such as deliveryAttempted can follow after the recovered-warning delivery semantics are fixed.
