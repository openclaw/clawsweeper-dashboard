## Label Justifications

- `P2`: The bug affects real scheduled reporting and maintenance delivery, but the blast radius is bounded to isolated cron agentTurn outcome classification.
- `impact:message-loss`: The final assistant output can be skipped before channel dispatch even though the isolated run produced it.

## Summary

Keep open: current main and v2026.6.11 still contain the pre-dispatch fatal structured-error path, and the latest maintainer discussion explicitly keeps this issue open for typed exec failure-phase evidence plus degraded cron outcome semantics.

## What This Changes

The issue reports that isolated scheduled agentTurn runs can recover, produce final assistant output, and still skip delivery before dispatch because an earlier tool error is classified as fatal.

## Best Possible Solution

Add typed exec failure-phase/process-started evidence that cron can trust, then represent process-ran recovered failures with a first-class degraded/warning cron outcome and separate delivery attempt/result state.

## Reproduction Assessment

Yes. Source inspection on current main still shows the fatal structured-error pre-dispatch return and the recovery gates described by the report; I did not run a live scheduled cron reproduction in this read-only review.

## Solution Assessment

No. The earlier simple classifier/final-text fixes are not the best remaining fix because maintainers rejected inference from display text or final assistant prose as unsafe; the durable path needs typed exec phase metadata plus explicit degraded cron state.
