## Summary

Keep open: current OpenClaw supports Telegram document download and shared text/PDF handling, but automatic Office-document extraction remains missing; the closed DOCX PR did not establish a safe replacement, and the remaining format, dependency, resource-limit, and trust-boundary choices require maintainer direction.

## What This Changes

Extract bounded text from Telegram document attachments and include it in the agent-visible message context.

## Best Possible Solution

Implement format support once behind the shared documentExtractors contract, beginning with explicitly approved MIME types and bounded extraction, then let Telegram and other channel/input_file paths consume the same sanitized, size-limited result without a new Telegram-specific config key.

## Solution Assessment

No, a Telegram-only parser or channel flag is not the best fix. The narrow maintainable solution is shared bounded extraction through the existing document-extractor contract, contingent on maintainer approval of formats and security limits.

## Security Review

Status: needs_attention

Summary: Any implementation will parse attacker-controlled document containers in a privileged agent process and needs an explicit bounded-extraction security design.

Concerns:

- **[high] Bound untrusted Office archive parsing:**
  - body: DOCX, PPTX, and XLSX are archive/XML containers that can trigger decompression, XML, CPU, or memory exhaustion unless entry counts, expanded bytes, parser time, nesting, and output size are capped before context insertion.
  - confidence: 0.94
- **[medium] Treat extracted document text as untrusted input:**
  - body: Automatic extraction can inject hostile instructions and oversized text into persistent conversation context, so results need clear untrusted-content wrapping, truncation, and provenance metadata.
  - confidence: 0.9
