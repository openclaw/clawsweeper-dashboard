## Summary

Keep open: current main and v2026.6.11 download Telegram documents and cover text/PDF extraction, but Office-style document attachments remain intentionally excluded from shared extraction. The related DOCX implementation PR is closed unmerged after proof and security blockers, so there is no landed or viable canonical fix to close this issue against.

## What This Changes

The issue requests extracting readable text from Telegram document attachments and including it in agent context instead of leaving only a media placeholder.

## Best Possible Solution

Finish Office-document support through the shared document extraction path, with maintainer-approved MIME scope, parser/dependency choice, archive/XML limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level. Telegram document paths and MIME types flow into shared media context, but Office MIME types are classified as binary and skipped before extraction.

## Solution Assessment

No to a Telegram-only parser or config toggle. The maintainable solution is a shared document extraction capability so Telegram, input_file, and adjacent attachment surfaces use one bounded implementation.
