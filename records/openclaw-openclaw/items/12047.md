## Summary

Keep open: current main and the latest release handle Telegram document download plus text/PDF extraction, but Office-style document text extraction remains intentionally excluded from the shared extraction path and the related DOCX PRs are closed unmerged.

## What This Changes

Request to extract readable text from Telegram document attachments and include it in agent context instead of leaving only a media placeholder.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extractor and media-understanding/input_file paths, preserving binary-safety checks, untrusted-content wrapping, focused Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level: Telegram saved media paths and MIME types flow into shared media context, but Office MIME types are classified as binary and skipped before extraction. I did not run a live Telegram bot reproduction in this read-only review.

## Solution Assessment

No to a Telegram-only parser or default config toggle. The maintainable solution is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
