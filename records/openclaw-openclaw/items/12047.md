## Summary

Keep open: current main and the latest release download and forward Telegram documents into shared media context, and recent work fixed runner-readable paths for non-image attachments, but Office-style document text extraction is still missing because Office MIME types are treated as binary and the bundled document extractor is PDF-only.

## What This Changes

Request to extract readable text from Telegram document attachments such as DOCX, PDF, TXT, and Markdown so the agent can process document contents instead of only seeing a media placeholder.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extract plugin and media-understanding/input_file paths, with bounded MIME scope, resource limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level: saved Telegram document paths and MIME types flow into shared media context, but Office MIME types are classified as binary and skipped before extraction. I did not run a live Telegram bot reproduction in this read-only review.

## Solution Assessment

No to a Telegram-only parser or default config toggle. The maintainable solution is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
