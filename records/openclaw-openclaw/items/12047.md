## Summary

Keep open: current main and the latest release handle Telegram document download plus text/PDF extraction, but Office-style document contents are still deliberately excluded before extraction, and the closed DOCX PR is not a safe canonical fix.

## What This Changes

The issue requests extracting text from Telegram document attachments so agents can read document contents instead of seeing only media placeholders or file references.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extractor, media-understanding, and input_file paths with bounded MIME scope, resource limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level: saved Telegram document paths and MIME types flow into shared media context, but Office MIME types are classified as binary and skipped before extraction. I did not run a live Telegram bot reproduction in this read-only cleanup pass.

## Solution Assessment

The requested outcome is valid, but a Telegram-only parser or new default config toggle would be the wrong layer. The maintainable solution is shared document extraction after maintainers settle parser, dependency, limit, and security boundaries.
