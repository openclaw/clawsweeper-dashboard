## Summary

Keep open: current main and v2026.6.11 handle Telegram document download plus text/PDF extraction, but Office-style document contents are still deliberately excluded from the shared extraction path.

## What This Changes

The issue requests extracting readable text from Telegram document attachments such as DOCX, PDF, TXT, and Markdown so the agent receives document contents instead of only a media placeholder.

## Best Possible Solution

Finish Office-document support through the shared document extraction path, with maintainer-approved MIME scope, parser/dependency choice, resource limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level. Current main passes saved Telegram document media into shared media context, but Office MIME types are classified as binary and skipped before extraction.

## Solution Assessment

No to a Telegram-only parser or default config toggle. The maintainable fix is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
