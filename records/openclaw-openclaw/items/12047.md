## Summary

Keep open: current main downloads Telegram documents and can extract text/PDF content through shared media paths, but Office-style document attachments are still intentionally excluded and the DOCX implementation attempts are closed unmerged.

## What This Changes

The issue requests extracting readable text from Telegram document attachments so agents can process documents instead of receiving only a document placeholder.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extract, media-understanding, and input_file paths, preserving binary-safety checks, untrusted-content wrapping, focused Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level: Telegram saved media paths and MIME types flow into shared media context, but Office MIME types are classified as binary and skipped before extraction. I did not run a live Telegram bot reproduction in this read-only review.

## Solution Assessment

No to a Telegram-only parser or default config toggle. The maintainable solution is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
