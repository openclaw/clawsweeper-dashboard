## Summary

Keep open: current main and v2026.6.11 still download Telegram documents and can extract text/PDF through shared paths, but Office-style document attachments remain intentionally excluded before extraction and no open merge-ready PR owns that remaining capability.

## What This Changes

Request text extraction for Telegram document attachments so agents can read document contents instead of only seeing media placeholders.

## Best Possible Solution

Finish the remaining Office-document capability through the shared document-extract/media-understanding path with maintainer-approved MIME scope, parser dependency ownership, archive/XML limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level. Telegram saved document paths and MIME types flow into shared media context, but Office MIME types are classified as binary and skipped before extraction on current main and v2026.6.11.

## Solution Assessment

No to a Telegram-only parser or a default config toggle. The maintainable solution is a shared document extraction capability so Telegram, input_file, and adjacent attachment surfaces use one bounded document path.
