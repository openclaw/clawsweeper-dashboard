## Summary

Keep open: current main handles Telegram document download plus text/PDF extraction, but Office-style document contents are still intentionally excluded before shared extraction, and the related DOCX PR was closed unmerged as unsafe/stalled rather than landing the missing capability.

## What This Changes

Request to extract readable text from Telegram document attachments and include that text in agent-visible message context.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extractor, media-understanding, and input_file paths with bounded MIME scope, resource limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level: Telegram document paths and MIME types flow into shared media context, but Office MIME types are classified as binary and skipped before extraction. I did not run a live Telegram bot reproduction in this read-only cleanup pass.

## Solution Assessment

No, a Telegram-only parser or new default config toggle would be the wrong layer. The maintainable solution is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
