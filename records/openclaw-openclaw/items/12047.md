## Summary

Keep open: current main solves Telegram download plus shared text/PDF extraction, but Office-style document contents are still intentionally skipped and no merged canonical PR owns that remaining capability.

## What This Changes

The issue requests extracting readable text from Telegram document attachments so agent context contains document contents instead of only a placeholder.

## Best Possible Solution

Implement the remaining Office-format support through the shared document-extractor/media-understanding path with approved MIME scope, parser dependency, archive/XML limits, and Telegram plus input_file coverage.

## Reproduction Assessment

Yes, at source level: Telegram documents flow into shared media context with MIME metadata, but Office MIME types are classified as binary and skipped before extraction. I did not establish a live Telegram reproduction in this read-only cleanup pass.

## Solution Assessment

No for a Telegram-only parser or config-only toggle; the maintainable fix belongs in the shared document-extractor/media-understanding path, or first in the plugin seam if maintainers want Office support outside bundled core.
