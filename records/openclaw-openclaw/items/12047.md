## Summary

Keep open: current main and the latest release cover Telegram document download plus text/PDF extraction, but Office-style document attachments are still deliberately excluded from the shared extraction path and both DOCX implementation PRs are closed unmerged.

## What This Changes

The issue requests Telegram document attachments to be text-extracted so agents receive readable document contents instead of only a media placeholder.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extractor and media-understanding/input_file paths, preserving binary-safety checks and untrusted-content wrapping instead of adding a Telegram-only parser.

## Reproduction Assessment

Yes, at source level: current main passes saved Telegram document paths and MIME types into shared media context, then Office-style MIME types are treated as binary and skipped before extraction. I did not run a live Telegram bot reproduction in this read-only review.

## Solution Assessment

No to a Telegram-only parser or default config toggle. The maintainable solution is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
