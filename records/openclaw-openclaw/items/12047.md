## Summary

Keep open: current main and v2026.6.11 support Telegram document download and text/PDF extraction paths, but Office-style attachments are still intentionally skipped before extraction and the DOCX implementation attempts are closed unmerged.

## What This Changes

Request to extract readable text from Telegram document attachments such as DOCX, PDF, TXT, and Markdown so agents can use document contents instead of only seeing a media placeholder.

## Best Possible Solution

Finish this through the shared document-extract/media-understanding path with maintainer-approved Office MIME scope, parser dependency ownership, resource limits, untrusted-content wrapping, Telegram coverage, and docs; avoid a Telegram-only parser or config toggle.

## Reproduction Assessment

Yes, at source level. Current main carries saved Telegram document metadata into media context, but Office MIME types are classified as binary and skipped before shared extraction.

## Solution Assessment

No to a Telegram-only extractor or default config switch. The maintainable solution is a shared document extraction capability with explicit security and resource limits so Telegram, input_file, and adjacent attachment surfaces do not drift.
