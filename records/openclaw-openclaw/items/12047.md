## Summary

Keep open: current main still downloads and forwards Telegram document media into the shared media context, but Office-style document contents remain excluded from extraction; the related DOCX implementation PRs are closed unmerged and the remaining work needs product and security decisions.

## What This Changes

Request to extract readable text from Telegram document attachments and include it in the agent-visible message context.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extractor and media-understanding/input_file paths, with bounded MIME scope, resource limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level: saved Telegram document paths and MIME types flow into shared media context, but Office MIME types are classified as binary and skipped before extraction. I did not run a live Telegram bot reproduction in this read-only review.

## Solution Assessment

No to a Telegram-only parser or default config toggle. The maintainable solution is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
