## Summary

Keep open: current main still downloads Telegram documents and can extract text/PDF content, but Office-style document attachments remain excluded from the shared extraction path and the related DOCX implementation PRs are closed unmerged.

## What This Changes

Request text extraction for Telegram document attachments so the agent sees readable document content instead of only a media placeholder.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extractor, media-understanding, and input_file paths, preserving binary-safety checks, untrusted-content wrapping, focused Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level: saved Telegram document paths and MIME types flow into shared media context, but Office MIME types are classified as binary and skipped before extraction. I did not run a live Telegram bot in this read-only pass.

## Solution Assessment

No to a Telegram-only parser or default config toggle. The maintainable path is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
