## Summary

Keep open: current main and v2026.6.11 handle Telegram document download plus text/PDF extraction, but Office-style document attachments are still intentionally excluded from the shared extraction path.

## What This Changes

The issue requests extracting readable text from Telegram document attachments so agents see file contents instead of only media placeholders.

## Best Possible Solution

Finish Office document support through the shared document-extract, input_file, and media-understanding path with maintainer-approved MIME scope, parser ownership, archive/XML limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, source-level. Saved Telegram document paths and MIME types flow into shared media context, but Office MIME types are classified as binary and skipped before extraction.

## Solution Assessment

No to a Telegram-only parser or default config toggle. The maintainable solution is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
