## Summary

Keep open: current main downloads Telegram documents and forwards saved media metadata, but Office-style document contents are still excluded by the shared MIME/extraction path, and the prior DOCX implementation candidate closed unmerged rather than landing.

## What This Changes

The issue requests extracting readable text from Telegram document attachments so agents receive document contents instead of only a document placeholder.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extractor and media-understanding/input_file paths, with bounded MIME scope, resource limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level: saved Telegram document paths and MIME types flow into shared media context, while Office MIME types are classified as binary and skipped before extraction. I did not run a live Telegram bot reproduction in this read-only cleanup pass.

## Solution Assessment

The requested outcome is valid, but a Telegram-only parser or new default config toggle would be the wrong layer. The maintainable solution is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
