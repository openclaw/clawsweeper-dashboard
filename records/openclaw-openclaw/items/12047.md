## Summary

Keep open: current main and the latest release handle Telegram document download plus text/PDF extraction, but Office-style document contents are still skipped and no merged or narrower canonical item owns that remaining Telegram/shared-extraction work.

## What This Changes

The issue requests extracting readable text from Telegram document attachments so agents can process files instead of seeing only media placeholders.

## Best Possible Solution

Extend the shared document-extractor/media-understanding path with maintainer-approved Office MIME scope, parser ownership, resource limits, untrusted-content wrapping, tests, docs, and live Telegram proof.

- **Extend external plugin seam first:** Keep core behavior unchanged until external document-extractor plugins can safely own Office formats through ClawHub or another approved plugin distribution path.
- **Defer Office extraction:** Keep current text/PDF behavior only and document Office files as unsupported until broader file/document input direction is settled.

## Reproduction Assessment

Yes, at source level: Telegram documents flow into shared media context with MIME metadata, but Office MIME types are classified as binary and skipped before extraction. I did not establish a live Telegram reproduction in this read-only cleanup pass.

## Solution Assessment

No, not as a Telegram-only parser or new channel toggle. The maintainable fix is a shared document-extractor/media-understanding change, or first extending the plugin seam if maintainers want Office support outside bundled core.
