## Summary

Keep open: current main and v2026.6.11 still handle Telegram document download plus text/PDF extraction, but Office MIME types remain filtered as binary and the only native DOCX implementation PR is closed unmerged, so the central document-content capability remains missing.

## What This Changes

Request to extract readable text from Telegram document attachments and include it in agent context instead of leaving only a media placeholder.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extractor, media-understanding, and input_file paths, with binary-safety checks, untrusted-content wrapping, focused Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level: saved Telegram document paths and MIME types flow into shared media context, but Office MIME types are classified as binary and skipped before extraction. I did not run a live Telegram bot reproduction in this read-only review.

## Solution Assessment

No to a Telegram-only parser or config toggle as the default answer. The maintainable solution is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
