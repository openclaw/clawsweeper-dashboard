## Summary

Keep open: current main and the latest release still download Telegram documents and extract text/PDF content, but Office-style document text remains excluded from shared extraction, and the prior DOCX implementation PRs closed unmerged.

## What This Changes

The issue requests extracting text from Telegram document attachments and including it in the agent-visible message context instead of only exposing a media placeholder.

## Best Possible Solution

Extend the shared document-extractor plus media-understanding/input_file paths for maintainer-approved Office formats, keep Telegram as a caller of the shared path, preserve MIME/binary safety and untrusted-content wrapping, and document the supported behavior.

## Reproduction Assessment

Yes, at source level: Telegram saved document media flows into shared media context, but Office MIME types are classified as binary and skipped before extraction. I did not run a live Telegram bot reproduction in this read-only cleanup pass.

## Solution Assessment

No to a Telegram-only parser or default config toggle. The maintainable solution is shared document extraction with maintainer-approved MIME scope, resource limits, and security handling so Telegram and adjacent attachment surfaces do not drift.
