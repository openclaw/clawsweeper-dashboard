## Summary

Keep open: current main and v2026.6.11 still download Telegram documents and can extract text/PDF, but Office-style document attachments remain intentionally excluded from the shared extraction path.

## What This Changes

The issue requests extracting readable text from Telegram document attachments so the agent receives document contents instead of only a media placeholder.

## Best Possible Solution

Finish the remaining Office-document capability through the shared document extraction path, with maintainer-approved MIME scope, parser/dependency choice, decompression/XML limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, source-level. Current main forwards saved Telegram document paths and MIME types into shared media context, but Office MIME types are classified as binary and skipped before extraction.

## Solution Assessment

No to a Telegram-only parser or default config toggle. The maintainable solution is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
