## Summary

Keep open: current main and v2026.6.11 handle Telegram document download plus text/PDF extraction, but Office-style document contents are still excluded before extraction, so the central remaining capability is not implemented.

## What This Changes

Requests text extraction from Telegram document attachments so the agent sees document contents instead of only a `<media:document>` placeholder.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extractor, media-understanding, and input_file paths, with bounded MIME scope, resource limits, untrusted-content wrapping, Telegram coverage, and docs.

- **Defer to native forwarding:** Treat this as part of the broader provider-native file/document forwarding design rather than adding local Office text extraction.

## Solution Assessment

No, not as a Telegram-only parser or new channel-specific config toggle. The maintainable solution is a shared document extraction boundary after maintainers settle parser, dependency, limit, and security policy.
