## Summary

Keep open: current `main` and the latest release still download and forward Telegram document media, but Office-style document contents remain excluded from shared extraction, and the closed DOCX PRs did not land a viable fix.

## What This Changes

Request to extract readable text from Telegram document attachments, especially Office-style files, and include it in agent-visible message context instead of only a placeholder.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extractor plus media-understanding/input_file paths, with bounded MIME scope, resource limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level: saved Telegram document paths and MIME types flow into shared media context, but Office MIME types are classified as binary and skipped before extraction. I did not run a live Telegram bot reproduction in this read-only cleanup pass.

## Solution Assessment

No to a Telegram-only parser or default config toggle. The maintainable solution is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
