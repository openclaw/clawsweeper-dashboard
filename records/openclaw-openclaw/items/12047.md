## Summary

Keep open: current main and the latest release still leave the Office-document part of this request unresolved. Telegram document metadata reaches the shared media context, but Office-style MIME types are excluded or classified as binary before extraction, and the related DOCX implementation PR is closed unmerged.

## What This Changes

Request to extract readable text from Telegram document attachments and include it in agent context instead of exposing only a media placeholder.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extractor and media-understanding/input_file paths, with bounded MIME scope, resource limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level: saved Telegram document paths and MIME types flow into shared media context, but Office MIME types are classified as binary or outside the allowlist before extraction. I did not run a live Telegram bot reproduction in this read-only review.

## Solution Assessment

No to a Telegram-only parser or default config toggle. The maintainable solution is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
