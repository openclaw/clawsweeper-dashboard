## Summary

Keep open: current main still downloads and forwards Telegram document attachments, but Office-style document contents remain excluded from shared extraction, and the related DOCX implementation PRs were closed unmerged rather than landing a safe fix.

## What This Changes

Request text extraction for Telegram document attachments so agents can read document contents instead of receiving only placeholders or attachment paths.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extractor plus media-understanding/input_file paths, with bounded MIME scope, resource limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level: Telegram forwards saved document media and content types into shared media context, but Office MIME families are classified as binary and skipped before extraction. I did not run a live Telegram bot reproduction in this read-only cleanup pass.

## Solution Assessment

No to a Telegram-only parser or default config toggle. The maintainable solution is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
