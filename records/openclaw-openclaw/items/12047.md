Keep open: current main and latest release already handle Telegram download plus shared text/PDF extraction, but Office-style document contents are still excluded before extraction, so the central requested capability remains missing.

## What This Changes

Request to extract text from Telegram document attachments so agents receive readable document contents instead of only a media placeholder.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extractor plus media-understanding/input_file paths, with bounded MIME scope, resource limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level: saved Telegram document paths and MIME types flow into shared media context, but Office MIME types are classified as binary and skipped before extraction. I did not run a live Telegram bot reproduction in this read-only cleanup pass.

## Solution Assessment

The requested outcome is valid, but a Telegram-only parser or new default config toggle would be the wrong layer. The maintainable solution is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
