## Summary

Keep open: current main and the latest release still handle Telegram document download and shared text/PDF extraction, but Office-style document contents remain excluded before extraction. The related DOCX implementation PRs are closed unmerged, and the remaining work needs maintainer product and security decisions.

## What This Changes

Request that Telegram document attachments such as DOCX, PDF, and TXT expose extracted text in the agent-visible message context instead of only a media placeholder.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extractor and media-understanding/input_file paths, with bounded MIME scope, resource limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level: saved Telegram document paths and MIME types flow into shared media context, but Office MIME types are classified as binary and skipped before extraction. I did not run a live Telegram bot reproduction in this read-only cleanup pass.

## Solution Assessment

No to a Telegram-only parser or default config toggle. The maintainable solution is shared document extraction so Telegram, input_file, and adjacent attachment surfaces use one bounded document capability.
