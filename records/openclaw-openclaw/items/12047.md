## Summary

Keep open: current main and v2026.6.11 handle Telegram document download plus text/PDF extraction, but Office-style document contents are still deliberately skipped before extraction and the related DOCX implementation PR was closed unmerged after proof and security blockers.

## What This Changes

Request to extract text from Telegram document attachments and include it in agent-visible context instead of only a media placeholder.

## Best Possible Solution

Implement maintainer-approved Office document support through the shared document-extractor, media-understanding, and input_file paths with bounded MIME scope, resource limits, untrusted-content wrapping, Telegram coverage, and docs.

## Reproduction Assessment

Yes, at source level: saved Telegram document paths and MIME types flow into shared media context, but Office MIME types are classified as binary and skipped before extraction. I did not run a live Telegram bot reproduction in this read-only cleanup pass.

## Solution Assessment

Unclear as an implementation until maintainers choose the parser, dependency, limits, and security boundary. A Telegram-only parser or new default config toggle would be the wrong layer; the maintainable direction is shared document extraction with explicit security limits.
