## Summary

Keep this PR open for maintainer review. It has credible after-fix proof and the previously reported abort-path defects were addressed, but it also changes polling from synchronous global backpressure to durable drain delivery with up to eight concurrent starts; a Zalo/channel owner should explicitly accept that cross-chat delivery-shape change before merge.

## What This Changes

Routes Zalo long-poll updates through the existing durable ingress queue before dispatch, adding restart recovery, deduplication, and polling-specific regression coverage.

## System Context

The Zalo plugin receives inbound messages either through webhooks or Bot API polling, then dispatches them into OpenClaw agent turns. This PR makes polling use the same SQLite-backed ingress queue already used by the webhook path so accepted updates can be recovered after an interruption.

## Best Possible Solution
