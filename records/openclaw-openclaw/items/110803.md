## Summary

Keep this PR open for maintainer review. The patch has credible real-behavior evidence for closing the polling crash/restart loss window and now accurately documents its best-effort shutdown behavior, but it also intentionally changes polling from one inline dispatch at a time to shared-ingress delivery with up to eight concurrent cross-chat deliveries; that delivery-policy change needs owner acceptance after rebasing on current main.

## What This Changes

Routes Zalo long-poll updates through the existing durable SQLite ingress queue before agent dispatch, adding restart recovery, deduplication, dead-letter handling, and abort-path journaling.

## System Context

Zalo polling receives Bot API updates that may be consumed by the upstream service as soon as the poll returns. This path now journals eligible updates into OpenClaw's shared channel-ingress queue before the queue drain dispatches them to the agent runtime.

  E --> F[Shared delivery drain]
  F --> G[Agent inbound dispatch]

## Best Possible Solution

Rebase onto current main, retain the single shared durable ingress path, and land only after the Zalo owner explicitly accepts the documented cross-chat concurrency change as the intended polling delivery policy.
