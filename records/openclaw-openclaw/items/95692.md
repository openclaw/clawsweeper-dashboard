## Summary

Keep this PR open, but it is not merge-ready: it adds a useful OpenRouter fallback idea, yet the patch introduces a parallel config path without proving the existing `extraBody.models` path is insufficient, reverses model-over-provider precedence, has a failing test assertion, and still lacks real OpenRouter behavior proof.

## What This Changes

The PR adds OpenRouter `models` fallback-array resolution and forwarding from request, provider, and model params into the OpenRouter transport patch, plus provider hook tests.

## Best Possible Solution

Keep the behavior provider-local only if maintainers want a dedicated convenience surface; otherwise document the existing `extraBody.models` path, and in either case preserve precedence and require redacted live OpenRouter proof before merge.

## Reproduction Assessment

Yes. The PR-head source shows provider params are read before model params while the new test and current merge pattern require model params to win, and the non-array test assertion also contradicts the patched runtime.

## Solution Assessment

No. The OpenRouter provider hook is a plausible layer, but current main already supports OpenRouter's documented OpenAI-compatible `extraBody.models` path; the best fix needs maintainer direction on whether to add a second surface, plus precedence, docs, and proof repairs.

  - confidence: 0.96
