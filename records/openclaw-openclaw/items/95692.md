## Summary

Current main already has the generic OpenRouter transport-param bridge, so the useful remaining value here is to make `models` an explicit, tested, documented provider-native fallback path without changing the existing override order. The latest PR head still has the same precedence bug and a failing test expectation, and there is still no real OpenRouter request/response proof.

## What This Changes

The PR adds OpenRouter `models` fallback-array resolution to the OpenRouter transport patch and adds hook tests for array forwarding, filtering, precedence, and invalid values.

## Best Possible Solution

Keep the hook provider-local, preserve current provider < model < request precedence for `models`, fix the assertion, document OpenRouter-native fallback versus OpenClaw failover, and require redacted live OpenRouter proof before merge.

## Reproduction Assessment

Yes. The branch is source-reproducible: PR head resolves provider params before model params for `models`, while its own new test expects model params to win, and the invalid-value assertion disagrees with the implementation.

## Solution Assessment

No. The provider hook is the right layer, but the current PR is only a plausible path until it preserves existing precedence, fixes the test, documents the new config surface, and supplies live OpenRouter proof.
