## Summary

This PR addresses a reproduced hang, but it should not merge as written because the existing 30-second header deadline becomes a hard lifetime limit for every ClawHub response body, including large archive downloads that currently may continue while making progress.

## What This Changes

The PR keeps ClawHub request deadlines active through response-body consumption and adds stalled and continuously dripping body regression coverage.

## Best Possible Solution

Use a total deadline for bounded JSON/control-plane responses while retaining an idle or progress-aware body policy for large artifact downloads, with regression coverage for a healthy download that remains active beyond the request timeout.
