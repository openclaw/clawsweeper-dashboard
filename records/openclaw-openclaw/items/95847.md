## Label Justifications

- `P1`: This PR changes subagent completion accounting in agent and cron workflows where incorrect state can suppress retries or misreport delivered work.
- `merge-risk: 🚨 compatibility`: The SQLite pending-final-delivery classifier changes how existing persisted delivery rows can rehydrate after an upgrade.

- `merge-risk: 🚨 session-state`: The patch changes durable descendant delivery, cleanup, wake, steer-replacement, and restoration state.

## Summary

Keep this PR open: the implementation appears focused and has no discrete correctness finding, but merge readiness still depends on real runtime proof and maintainer acceptance that exact requester consumption is terminal delivery evidence even when the requester’s outward send later fails.

## What This Changes

The branch adds durable requester-consumption credit for descendant subagent completions across announcement and isolated-cron fallback paths, persists the new state, adjusts SQLite restoration, and adds supporting tests and type/helper refactors.

## Best Possible Solution

Use one canonical delivery-state transition for exact consumed run IDs, preserve retryability for every unconsumed row, and land it only with a redacted cron/background restart proof covering both consumed and control rows.
