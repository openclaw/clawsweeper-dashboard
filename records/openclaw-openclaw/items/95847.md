## Summary

Keep this PR open, but do not merge the current head: the nested wake path treats successful wake-run creation as requester consumption, which can prematurely terminate descendant delivery accounting. The earlier generic typing finding is fixed, but this new P1 correctness blocker and missing real behavior proof remain.

## What This Changes

The PR adds durable requester-consumption delivery credit for explicit descendant completions used by nested subagent wake flows and cron fallback synthesis, including persisted registry metadata and SQLite restoration behavior.

## Best Possible Solution

Keep cron credit at the controller-owned fallback-adoption point, but move nested credit to a post-processing acknowledgement or settlement event that proves the replacement requester run incorporated the exact descendant findings.
