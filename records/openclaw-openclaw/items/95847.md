## Summary

The latest head still uses transcript commit as the delivered boundary for nested completion steering, then records that weaker signal as durable requester consumption. The accounting gap remains worth fixing, but this head can suppress a descendant completion when the requester terminates before processing the queued handoff.

## What This Changes

The PR adds durable delivery credit and persisted requester-consumption metadata for descendant subagent output adopted by cron and nested-subagent requester flows.

## Best Possible Solution

Require an explicit requester assistant-processing acknowledgement for completion steering, then apply durable credit only to the exact descendant run IDs included in that acknowledged output; retain transcript commit as durability evidence rather than consumption evidence.
