## Summary

Keep this PR open: the latest commit correctly delays nested descendant credit beyond wake creation, but it loses the original requester run window, so a successful wake continuation can still credit zero descendant rows.

## What This Changes

The PR adds durable requester-consumption delivery credit for descendant subagent results across nested wake, isolated cron fallback, and SQLite restoration paths.

## Best Possible Solution

Persist the original consuming requester run-start timestamp alongside the pending descendant IDs, use that preserved window after wake delivery, and prove the actual persisted rows become delivered across restart.
