## Summary

Keep open: current main does not implement the requested consumption accounting, and the exact-head review found the earlier correctness findings fixed with no remaining line-level defect, but this external PR still lacks the required real runtime and upgrade proof for its delivery and persistence changes.

## What This Changes

The PR durably marks explicitly identified descendant subagent completions as delivered when nested requester or isolated cron flows consume their output, carrying that state through wake replacement and SQLite restoration.

## Best Possible Solution

Keep the explicit-run, requester-matched accounting design, but merge only after exact-head runtime evidence demonstrates nested wake consumption, cron fallback credit through a failed outward send, and SQLite restart behavior for both fresh and upgraded state.
