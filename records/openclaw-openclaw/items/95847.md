## Summary

Keep this PR open: its stated delivery-accounting fix remains absent from current main, but the new credit function only accepts direct children even though cron fallback renders arbitrary descendants. That leaves rendered grandchildren pending and eligible for later failure/suspension handling; the PR also still needs redacted after-fix runtime proof.

## What This Changes

This PR adds durable delivered credit for subagent completions that a requester consumes through cron fallback or nested announcement handling, including persistence and lifecycle-query updates.

## System Context

Subagent completions enter the registry with delivery state, then cron and nested requester paths can synthesize their output into a parent result. The persisted delivery state determines whether cleanup, retry, and finalization regard that child work as settled or still awaiting delivery.

## Architecture Diagram

flowchart LR
  A[Child and grandchild completions] --> B[Subagent run registry]
  B --> C[Cron fallback or nested requester]
  C --> D[Selected output and run IDs]
  D --> E[Requester-consumption credit]
  E --> F[Persisted delivery state]
  F --> G[Cleanup retry and finalization]

## Best Possible Solution

Make consumption credit match the exact descendant runs whose output was rendered—by validating descendant ancestry from the requester session and run window, or by limiting fallback synthesis to direct children—then prove the direct and nested cases with a redacted runtime/persistence trace.
