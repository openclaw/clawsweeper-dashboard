## Summary

Keep this PR open: the latest head appears to resolve the prior steer-replacement accounting defect, but it still needs real cron/restart proof and an explicit maintainer decision on whether requester consumption should be equivalent to user-visible delivery.

## What This Changes

The branch durably credits explicitly consumed descendant completions across nested subagent announcements and isolated cron fallback, carries pending credit through steered replacement runs, persists the metadata, adjusts SQLite restoration, and adds regression coverage.

## Best Possible Solution

Represent requester consumption as an explicit terminal accounting state distinct from visible channel delivery unless maintainers affirm those concepts are equivalent, then prove the chosen state across a real cron run and restart while keeping the branch narrowly scoped.
