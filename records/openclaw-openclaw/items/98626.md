## Summary

Keep open: the bug-fix idea is focused, but the exact predicate broadens a private-network allow gate to any configured URL string beginning with `http://127.`, including non-loopback hostnames, and the PR still lacks after-fix real behavior proof.

## What This Changes

The PR changes the OpenAI image provider QA-only local endpoint predicate from matching only `http://127.0.0.1:` to matching any `http://127.` prefix.

## Best Possible Solution

Parse the configured URL and allow the QA escape hatch only for HTTP `localhost` or an actual 127/8 IP-literal hostname, with focused regression tests and redacted real behavior proof before merge.

## Reproduction Assessment

Yes. Source inspection is enough: current main rejects non-127.0.0.1 loopback URLs, and the PR-head `baseUrl.startsWith("http://127.")` predicate matches non-loopback hostnames such as `http://127.example.test/v1`.

## Solution Assessment

No. The best fix is parsed host validation for `localhost` or an actual 127/8 IP literal, not raw URL-string prefix matching.
