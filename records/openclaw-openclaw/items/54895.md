## Summary

Keep open. Current main has narrowed the misleading timeout behavior by returning accepted delivery for ordinary nonterminal waits, but it still does not provide caller-visible inter-session progress streaming, `sessions_subscribe`, `agent.events`, or another authorized buffered run-event API for long-running peer runs.

## What This Changes

The issue requests inter-session progress streaming or subscription support for long-running `sessions_send` runs, especially ACP/Codex-backed sessions.

## Best Possible Solution

Define a maintainer-approved run-event access model that keeps current `sessions_send` accepted semantics, adds authorized caller-visible progress or subscription behavior, and preserves redaction and channel-delivery boundaries.
