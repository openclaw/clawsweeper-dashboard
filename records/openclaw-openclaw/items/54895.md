## Summary

Keep open. Current main and v2026.6.11 partly fix the misleading wait-timeout slice by returning accepted for ordinary nonterminal waits, but they still lack caller-visible inter-session progress streaming, `sessions_subscribe`, `agent.events`, or an equivalent buffered run-event read API for long-running `sessions_send` runs.

## What This Changes

Request an inter-session progress streaming or subscription surface for long-running `sessions_send` runs, especially ACP/Codex delegated sessions.

## Best Possible Solution

Add an additive, permission-checked run-progress observation contract with bounded buffering/replay and redaction, then expose it through a maintainer-approved `sessions_subscribe` tool or `sessions_send` progress option.

## Reproduction Assessment

Yes, at source level. Current main lacks `sessions_subscribe`, `agent.events`, or another caller-readable buffered run-event API for a `sessions_send` caller; I did not run a live Telegram/ACP scenario in this read-only review.

## Solution Assessment

Unclear. A separate `sessions_subscribe` tool is plausible, but maintainers still need to choose the event API, authorization, redaction, buffering, retention, replay, and channel delivery semantics.
