## Summary

Keep open. Current main and v2026.6.11 still lack caller-visible progress streaming, `sessions_subscribe`, `agent.events`, or another buffered run-event read API for long-running peer `sessions_send` runs; related open issues overlap but do not supersede this focused session-tool gap.

## What This Changes

The issue requests caller-visible progress streaming or subscription support for long-running inter-session `sessions_send` runs.

## Best Possible Solution

Define an additive, permission-checked run-progress observation contract with bounded replay and redaction, then expose it through `sessions_subscribe` or a maintainer-approved `sessions_send` progress option.

## Reproduction Assessment

Yes, at source level: current main lacks `sessions_subscribe`, `agent.events`, or another caller-readable buffered run-event API for a `sessions_send` caller; live Telegram/ACP execution was not run in this read-only review.

## Solution Assessment

Unclear final API shape. A separate `sessions_subscribe` tool is plausible, but maintainers still need to decide the event API, authorization, redaction, retention, replay, and channel delivery semantics.
