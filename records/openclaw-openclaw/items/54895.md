## Summary

Keep open. Current main still lacks a caller-readable progress stream, `sessions_subscribe`, `agent.events`, or equivalent buffered run-event API for long-running peer `sessions_send` runs; adjacent ACP parent streaming covers parent-owned spawn/task flows, not this peer-send case.

## What This Changes

Requests caller-visible progress streaming or subscription support for long-running cross-session `sessions_send` runs.

## Best Possible Solution

Define a permission-checked, redacted, bounded run-event observation contract, then expose it through `sessions_subscribe` or a maintainer-approved `sessions_send` progress option.
