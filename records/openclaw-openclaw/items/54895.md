## Summary

Keep open. Current main still has fire-and-forget or wait/final-announce semantics for `sessions_send`; it does not expose `sessions_subscribe`, `agent.events`, or another permission-checked buffered run-event stream for caller sessions.

## What This Changes

Add caller-visible progress/event observation for long-running `sessions_send` runs, likely through a `sessions_subscribe` or `agent.events` style API.

## Best Possible Solution

Define an additive, permission-checked run-progress observation contract with bounded replay/redaction and expose it through a maintainer-approved `sessions_subscribe` or `sessions_send` progress surface.
