## Summary

Keep open. Current main and v2026.6.11 partly avoid treating ordinary nonterminal wait expiry as failed delivery, but they still do not provide caller-readable progress streaming, `sessions_subscribe`, `agent.events`, or another authorized buffered event API for peer `sessions_send` runs.

## What This Changes

Request inter-session progress streaming or subscription for long-running `sessions_send` runs, especially ACP/Codex sessions.

## Best Possible Solution

Add an additive, permission-checked run-progress observation contract with bounded replay and redaction, then expose it through `sessions_subscribe` or a maintainer-approved `sessions_send` progress option.

Options:

- **Design additive subscription API (recommended):** Define an authorized `agent.events` or `sessions_subscribe` contract with bounded replay/redaction before implementation.

- **Add `sessions_send` progress option directly:** Let `sessions_send` optionally forward progress, accepting tighter coupling between send behavior and visible channel delivery.
