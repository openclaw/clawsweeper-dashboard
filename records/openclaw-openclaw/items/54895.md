## Summary

Keep open. Current main and v2026.6.11 still lack caller-visible progress streaming for peer `sessions_send` runs, although ACP `sessions_spawn streamTo="parent"` now covers some initial spawn cases; the remaining cross-session event API needs maintainer product and security design.

## What This Changes

Request inter-session progress visibility for long-running `sessions_send` runs through event forwarding, a progress option, or a new `sessions_subscribe`/`agent.events` API.

## Best Possible Solution

Design an additive, permission-checked run-progress observation contract with bounded replay and redaction, reuse existing ACP parent-stream projection where appropriate, then expose it through a maintainer-approved `sessions_subscribe` or `sessions_send` progress surface.

- **Extend `sessions_send` with progress mode:** Keep one user-facing tool but make its result semantics more complex by optionally returning progress items or forwarding updates.
- **Defer to process events:** Fold this into the broader structured process-events work so session progress has one source of truth across clients and tools.
