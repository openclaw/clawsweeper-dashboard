## Summary

Keep open. Current main and v2026.6.11 still lack a caller-readable run-progress subscription or buffered event API for peer `sessions_send` runs; the timeout result is partly improved for nonterminal waits, but the central streaming/subscription request remains unresolved and security-sensitive.

## What This Changes

Add caller-visible progress streaming or subscription for long-running `sessions_send` runs, especially ACP/Codex peer sessions, instead of relying on synchronous wait plus final-only announce behavior.

## Best Possible Solution

Design an additive, permission-checked run-progress observation contract with bounded replay, redaction, retention, and channel delivery rules, then expose it through `sessions_subscribe` or a maintainer-approved `sessions_send` progress option.
