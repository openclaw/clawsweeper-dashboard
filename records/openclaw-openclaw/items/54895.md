## Summary

Keep open. Current main partially avoids treating every nonterminal wait expiry as failed delivery, but it still lacks caller-visible progress streaming, `sessions_subscribe`, `agent.events`, or another buffered run-event read API for long-running peer `sessions_send` runs.

## What This Changes

The issue requests inter-session progress visibility for long-running `sessions_send` calls, including a possible `sessions_subscribe` or event-streaming API.

## Best Possible Solution

Add an additive, permission-checked run-progress observation contract with bounded replay, redaction, retention, and ordering semantics, then expose it through a maintainer-approved `sessions_subscribe` tool or `sessions_send` progress option.
