## Summary

Keep open. Current main partially fixes the original delivery-status problem for nonterminal waits, but it still lacks caller-visible progress streaming, a `sessions_subscribe` tool, `agent.events`, or another permission-checked buffered run-event API for long-running peer `sessions_send` runs.

## What This Changes

Request an inter-session progress stream or subscription path so a `sessions_send` caller can observe long-running target-session tool, assistant, and lifecycle progress.

## Best Possible Solution

Design an additive, permission-checked run-progress observation contract with bounded replay and redaction, exposed through `sessions_subscribe` or a maintainer-approved `sessions_send` progress option.

## Reproduction Assessment

Yes, source-level: `sessions_send` has no progress parameter or subscription tool, Gateway exposes `agent.wait` but no `agent.events`, and the A2A path waits for a final reply before announcing.

## Solution Assessment

Unclear final API shape: `sessions_subscribe` or an additive `sessions_send` progress option is plausible, but maintainers need to choose the event contract, authorization, redaction, retention, replay, and delivery semantics.
