## Summary

Keep open. Current main still lacks a caller-readable progress or event subscription surface for long-running peer `sessions_send` runs; wait timeout reporting is partly improved, but streaming/subscription semantics remain unresolved and security-sensitive.

## What This Changes

Request inter-session progress streaming or a subscription API so callers of long-running `sessions_send` runs can observe tool, assistant, and lifecycle progress before final announce.

## Best Possible Solution

Design an additive, permission-checked run-progress observation contract with bounded replay and redaction, then expose it through `sessions_subscribe` or a maintainer-approved `sessions_send` progress option.
