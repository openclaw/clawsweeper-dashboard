## Summary

Keep open. Current main partly avoids treating ordinary wait-window expiry as failed delivery, but it still lacks caller-visible progress streaming, `sessions_subscribe`, `agent.events`, or another permission-checked buffered event read path for long-running peer `sessions_send` runs.

## What This Changes

Request to add caller-visible progress streaming or subscription support for long-running inter-session `sessions_send` runs, especially ACP/Codex-backed peer sessions.

## Best Possible Solution

Design one additive, permission-checked run-progress observation contract with bounded replay, redaction, retention, and channel delivery rules, then expose it through `sessions_subscribe` or a maintainer-approved `sessions_send` progress option.
