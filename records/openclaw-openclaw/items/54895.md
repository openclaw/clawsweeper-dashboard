## Summary

Keep open. Current main still lacks a caller-readable progress or event subscription surface for long-running peer `sessions_send` runs; the timeout result is partly improved for nonterminal waits, but the requested streaming/subscription behavior remains unresolved and security-sensitive.

## What This Changes

The issue requests inter-session progress visibility for `sessions_send`, especially for long-running ACP/Codex sessions that keep working after the caller's synchronous wait expires.

## Best Possible Solution

Design an additive, permission-checked run-progress observation contract with bounded replay/redaction, then expose it through `sessions_subscribe` or a maintainer-approved `sessions_send` progress option.
