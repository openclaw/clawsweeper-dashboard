## Summary

Keep open. Current main partly avoids treating ordinary nonterminal `sessions_send` waits as failed delivery, but it still lacks caller-visible inter-session progress streaming, `sessions_subscribe`, `agent.events`, or another permission-checked buffered run-event read API for long-running peer sessions.

## What This Changes

Request adding caller-visible progress observation for long-running `sessions_send` runs, especially ACP/Codex-backed sessions, through event forwarding, a progress option, or a new `sessions_subscribe` tool.

## Best Possible Solution

Define an additive, permission-checked run-progress observation contract with bounded replay, redaction, ordering, retention, and channel delivery rules, then expose it through `sessions_subscribe` or a maintainer-approved `sessions_send` progress option.
