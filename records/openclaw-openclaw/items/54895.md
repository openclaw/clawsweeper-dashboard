## Summary

Keep open. Current main and v2026.6.11 still lack caller-visible progress streaming, `sessions_subscribe`, `agent.events`, or another buffered run-event read API for long-running peer `sessions_send` runs, although main now partially avoids treating ordinary nonterminal wait expiry as failed delivery.

## What This Changes

Request an inter-session progress stream or subscription path so a `sessions_send` caller can observe tool, assistant, and lifecycle progress from a long-running target session.

## Best Possible Solution

Add an additive, permission-checked run-progress observation contract with bounded replay and redaction, then expose it through `sessions_subscribe` or a maintainer-approved `sessions_send` progress option.

## Reproduction Assessment

Yes, at source level: current main has no caller-readable buffered run-event API, `sessions_subscribe`, or `sessions_send` progress option for a long-running peer run; no live Telegram/ACP scenario was run in this read-only review.

## Solution Assessment

Unclear final API shape: a separate `sessions_subscribe` tool is plausible, but maintainers still need to decide authorization, event shape, redaction, retention, replay, and channel delivery semantics.
