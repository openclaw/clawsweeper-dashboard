## Summary

Keep open. Current main fixes part of the delivery-status problem by returning `accepted` for nonterminal wait expiry, but it still has no caller-readable progress stream, `sessions_subscribe`, `agent.events`, or equivalent buffered run-event API for long-running peer `sessions_send` runs.

## What This Changes

The issue requests progress/event streaming for long-running `sessions_send` inter-session runs so callers can observe target-session work before final completion.

## Best Possible Solution

Add an additive, permission-checked run-progress observation contract with bounded replay and redaction, then expose it through `sessions_subscribe` or a maintainer-approved `sessions_send` progress mode.
