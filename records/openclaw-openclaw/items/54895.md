## Summary

Keep open. Current main and v2026.6.11 still lack a caller-readable progress stream or subscription API for peer `sessions_send` runs; current code only partially improves wait-timeout delivery reporting, and the remaining API/security boundary needs maintainer design.

## What This Changes

The issue requests progress streaming or subscription support for long-running inter-session `sessions_send` runs, especially ACP/Codex-backed sessions.

## Best Possible Solution

Add an additive, permission-checked run-progress observation contract with bounded replay and redaction, then expose it through `sessions_subscribe` or a maintainer-approved `sessions_send` progress option.
