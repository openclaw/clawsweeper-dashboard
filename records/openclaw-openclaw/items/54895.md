## Summary

Keep open. Current main improved the misleading wait-timeout slice by returning accepted for nonterminal waits, but it still does not provide caller-visible inter-session progress streaming, a sessions_subscribe tool, an agent.events/read API, or a buffered/replayable run-event contract for long-running sessions_send work.

## What This Changes

The issue requests inter-session progress streaming for long-running sessions_send runs, especially ACP/Codex-backed sessions, so callers can observe tool, assistant, and lifecycle progress before the final announce.

## Best Possible Solution

Define one additive, permission-checked inter-session run-progress contract, ideally aligned with structured process/run events, with bounded buffering or replay, redaction, requester authorization, channel delivery rules, protocol/docs updates, and focused sessions_send plus ACP coverage.
