## Summary

Keep open. Current main and v2026.6.11 only partly improve the timeout status path; they still do not expose caller-visible progress streaming, `sessions_subscribe`, `agent.events`, or another buffered run-event read API for long-running peer `sessions_send` runs.

## What This Changes

Request inter-session progress visibility for long-running `sessions_send` runs, likely through `sessions_subscribe`, `agent.events`, or an explicit progress option.

## Best Possible Solution

Add an additive, permission-checked run-progress observation contract with bounded replay and redaction, then expose it through a maintainer-approved tool/API such as `sessions_subscribe` or a `sessions_send` progress option.
