## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Timestamp provider-result fallback states:** `extensions/memory-core/src/memory/manager-sync-ops.ts:2676-2677`
  - body: The new recovery probe returns immediately when `fallbackActivatedAtMs` is unset, but `applyProviderResult()` can put the manager into fallback-active from initial provider resolution without setting that timestamp. A manager created this way will never probe the recovered primary provider, so set recoverable timing/state on that path and add a regression test.
  - confidence: 0.91
- **[P2] Gate recovery on stale fallback identity:** `extensions/memory-core/src/memory/manager.ts:670-672`
  - body: `search()` now attempts primary recovery for every fallback-active manager before checking whether the current index is already valid for the fallback provider. If the outage path rebuilt or repaired the index against the fallback, this swaps to the primary and makes the stored index mismatched, so searches return empty until another reindex; gate recovery to the stale-primary-index case or mark/rebuild the index after restoring primary.
  - confidence: 0.82
