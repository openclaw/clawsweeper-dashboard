## Summary

Keep open: the PR still misses a fallback-active entry path, so a manager that starts up on the configured fallback can remain unable to probe the recovered primary provider. The linked issue is valid, but this branch needs a code fix and real Gateway outage/recovery proof before merge.

## What This Changes

The PR adds search-time recovery from memory-core fallback embedding providers by timestamping fallback activation, retrying the configured primary provider after a cooldown, and adding recovery-path unit tests.

## Best Possible Solution

Land one maintainer-chosen recovery implementation after it covers every fallback-active entry path, preserves index-identity safety, and includes redacted real Gateway outage/recovery proof.

## Reproduction Assessment

Yes at source level: current main can return fallbackFrom from createEmbeddingProvider, apply it to a long-lived manager, and then skip primary re-resolution after providerInitialized is true. I did not run a live Gateway/Ollama outage path in this read-only review.

## Solution Assessment

No, not yet. Search-time recovery is a reasonable layer, but this implementation only timestamps fallback states created by activateFallbackProvider and misses fallback-active states created by provider-result initialization.
