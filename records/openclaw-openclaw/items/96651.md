## Review Findings

Full review comments:

- **[P1] Timestamp every fallback-active provider-result path:** `extensions/memory-core/src/memory/manager-sync-ops.ts:2676-2677`
  - body: The new recovery probe returns immediately when `fallbackActivatedAtMs` is unset, but `applyProviderResult()` can still put a manager into fallback-active from initial provider resolution without setting that timestamp. A manager whose first provider load falls back will never probe the recovered primary; record recovery state on that path or use a throttle state that covers both entry paths, with a regression test.
  - confidence: 0.92
- **[P1] Gate recovery on identity mismatch:** `extensions/memory-core/src/memory/manager.ts:670-672`
  - body: This runs the recovery attempt for every fallback-active manager before checking whether the current fallback provider already matches the on-disk index. If an explicit identity repair rebuilt the index for the fallback provider, the cooldown can switch back to the primary and turn working fallback search into an identity mismatch; refresh the identity first and only recover when the active fallback index is invalid or mismatched.
  - confidence: 0.86
