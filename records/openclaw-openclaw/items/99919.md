## Label Justifications

- `P1`: The report describes a real scheduled workflow silently abandoning required post-media steps and final notification after async image completion.
- `impact:session-state`: The generated-media completion handoff resumes the cron run session without the original task context needed to continue the same workflow.

## Summary

Keep open: current main still resumes inactive isolated cron generated-media completions through the generic requester-agent handoff, and that handoff does not carry the cron job's original task prompt, bootstrap kind, thinking level, or explicit model selection.

## What This Changes

The issue reports that async `image_generate` completion for isolated cron agent turns resumes with the default chat model and generic prompt instead of the cron job's configured model and task instructions.

## Best Possible Solution

Add a cron-aware generated-media continuation path that re-enters the originating cron run with its resolved model, thinking level, bootstrap context, delivery context, and task prompt, with regression proof that it does not fall back to the account default model or generic prompt.

## Reproduction Assessment

Yes, source-reproducible: current main's media completion wake can target the cron run session but does not pass the cron model, thinking level, bootstrap kind, or original task prompt into the resumed agent turn. I did not run a live cron/image replay in this read-only review.

## Solution Assessment

Yes for the narrow direction: preserving or reconstructing the originating cron run context at the generated-media completion handoff is better than relying on `background: false` or a broad async-queue feature. The exact state ownership and replay safeguards still need maintainer review before implementation.
