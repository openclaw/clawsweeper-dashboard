## Summary

Keep open: current main has prior cron media wait and requester-agent routing fixes, but the yielded/generated-media completion path still resumes through a completion-only requester-agent handoff rather than the original cron run bootstrap with its configured provider/model, thinking level, and task prompt.

## What This Changes

Issue #99919 reports that isolated cron `image_generate` completions can resume under the default chat model and generic media-completion prompt instead of the cron job's configured model and original task context.

## Best Possible Solution

Define one canonical cron media continuation contract that restores the original cron run context for generated-media completions without bypassing the existing requester-agent delivery and direct-fallback safeguards.

## Reproduction Assessment

Yes, source-reproducible: current main's generated-media completion path carries only a media completion event into a requester-agent handoff, while the original cron executor path is the one that supplies the cron model, thinking level, bootstrap kind, and task prompt.

## Solution Assessment

No single code-only fix is proven best yet: maintainers need to decide whether the completion should persist/replay cron run context, force synchronous completion for this class, or add an explicit user-controlled synchronous media mode.
