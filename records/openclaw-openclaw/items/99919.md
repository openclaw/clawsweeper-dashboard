## Label Justifications

- `P1`: The issue reports a real scheduled workflow silently abandoning required post-media steps and final notification after async image completion.
- `impact:session-state`: The completion handoff resumes a cron run session without the original cron task context needed to continue the same workflow.
- `impact:message-loss`: The reporter observed `NO_REPLY` and `delivered: false` after partial work, so the expected final user message was lost.
- `impact:auth-provider`: The failure path can run the completion under the default chat model instead of the cron job's configured model.

## Summary

Keep open: current main still has a generated-media completion handoff that can call the requester agent on the cron run session with only the media completion event, not the originating cron model, thinking level, bootstrap kind, or original task prompt.

## What This Changes

The issue requests that async media completion for isolated cron agent turns preserve the originating cron task context and configured model instead of resuming under the default model with a generic prompt.

## Best Possible Solution

Add a cron-aware generated-media continuation path that re-enters or reconstructs the originating cron run with its resolved model, thinking setting, bootstrap context, delivery context, and original task prompt, with regression proof that the completion turn does not fall back to the account default model or generic prompt.

## Reproduction Assessment

Yes, source-reproducible: current main's media completion handoff can target the cron run session but does not pass the cron model, thinking level, bootstrap kind, or original task prompt into the requester-agent call. I did not run a live cron/media repro in this read-only review.

## Solution Assessment

Yes for the narrow direction: preserving or reconstructing the originating cron run context at the media-completion handoff is the maintainable fix. The `background:false` option and broader async routing proposals are useful adjacent workarounds, not replacements for this bug fix.
