## Label Justifications

- `P1`: The issue reports a real scheduled workflow silently abandoning required post-media steps and final notification after async image completion.
- `impact:session-state`: The async completion handoff resumes the cron run session without the original cron task context needed to continue the same workflow.
- `impact:message-loss`: The reporter observes NO_REPLY and delivered:false after partial work, so the expected final user message is lost.
- `impact:auth-provider`: The reported and source-supported failure path can run the completion under the default chat model instead of the cron job's configured model.

## Summary

Keep open: current main still routes async media-generation completions for inactive isolated cron runs through a requester-agent handoff that carries the session key and completion event but not the cron job's model, thinking level, bootstrap context, or original task prompt.

## What This Changes

The issue requests that async media-generation completions resume cron/isolated agentTurn sessions with the originating cron model and task instructions instead of default chat context.

## Best Possible Solution

Add a cron-aware generated-media continuation that re-enters the originating cron run with its resolved provider/model, thinking level, bootstrap context, delivery policy, and original task prompt, with regression coverage proving the completion turn does not fall back to defaults or a generic prompt.

## Reproduction Assessment

Yes, source-reproducible: current main's generated-media completion handoff targets the cron run session but only passes the media completion event and session key, not the cron run's model, thinking level, bootstrap kind, or original task prompt.

## Solution Assessment

Yes for the narrow bug: preserving or reconstructing the originating cron run context at the media-completion handoff is a better fix than relying on background:false or a broad async queue feature.
