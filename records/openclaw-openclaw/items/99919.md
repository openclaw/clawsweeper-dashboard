## Summary

Keep open: current main still has a source-reproducible cron/media continuation gap where inactive isolated cron generated-media completions re-enter through a generic requester-agent call, so the continuation loses the originating cron prompt and explicit provider/model/thinking context.

## What This Changes

The issue asks OpenClaw to resume generated-media completions for isolated cron runs with the original cron session context instead of a generic follow-up agent prompt.

## Best Possible Solution

Add a cron-aware generated-media continuation path that resumes the originating isolated cron run with its resolved provider/model, thinking level, bootstrap context, delivery context, and original task prompt, backed by focused regression and live cron/media proof.

## Reproduction Assessment

Yes at source level: the current completion handoff path can be traced from detached cron media generation to a requester-agent call that lacks the original cron prompt and model/thinking fields; no live end-to-end repro was run in this read-only pass.

## Solution Assessment

The best fix is not the broader `background:false` feature or a full async-route framework; it is a targeted cron/media continuation contract that preserves the original cron execution context while keeping requester-agent delivery safeguards.
