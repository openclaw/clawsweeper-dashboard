## Label Justifications

- `P1`: The reported bug can silently abandon a scheduled workflow after async media completion and skip the final user notification.
- `impact:session-state`: The completion handoff resumes the cron run session without the original cron task context needed to continue the same workflow.
- `impact:message-loss`: The reporter observed NO_REPLY and delivered=false after partial work, so the expected completion message can be lost.
- `impact:auth-provider`: The report involves provider/model routing drift when the completion turn is reconstructed instead of using the originating job's explicit run context.

## Summary

Keep open: current main still routes generated-media completion through a requester-agent handoff that carries the media completion event, while the normal isolated cron run path carries the original prompt, model, thinking, and cron bootstrap context. Current main partially addresses model persistence, but the original cron task instructions still are not re-applied for the completion turn.

## What This Changes

The issue asks OpenClaw to preserve the originating isolated cron run's model and task prompt when async media-generation completions resume the session.

## Best Possible Solution

Add a cron-aware generated-media continuation path that re-enters the originating cron run with its resolved task prompt, model/provider selection, thinking level, bootstrap kind, and delivery context, with regression coverage proving the resumed turn sees more than the media-ready event.

## Reproduction Assessment

Yes, source-reproducible. Current main traces from the media wake into a requester-agent handoff that does not pass the original cron prompt, bootstrap kind, or job thinking, though no live cron/media repro was run in this read-only pass.

## Solution Assessment

Yes for the narrow bug, with maintainer boundary approval. Preserving or reconstructing the originating cron run context at the generated-media handoff is the maintainable fix; background:false and broad async routing work are adjacent mitigations, not replacements.
