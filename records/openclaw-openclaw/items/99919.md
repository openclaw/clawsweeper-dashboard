## Summary

Keep open: current main still routes generated-media completion through a requester-agent handoff that carries the media completion event, not the original cron task prompt, cron bootstrap kind, or explicit job thinking setting; the model-state portion is partially improved by persisted session model fields, but the central task-continuation problem remains.

## What This Changes

The issue reports that async media completion for isolated cron `agentTurn` runs can resume without the cron task/model context and silently drop the remaining scheduled work.

## Best Possible Solution

Add a cron-aware generated-media continuation path that re-enters the originating cron run with its resolved task prompt, bootstrap kind, delivery context, model selection, and thinking setting, with regression coverage proving the resumed turn does not process only the media-ready event.

## Reproduction Assessment

Yes. Current main's generated-media completion path can be traced from the media wake into a requester-agent handoff that does not pass the original cron prompt, cron bootstrap kind, or job thinking into the resumed run.

## Solution Assessment

Yes for the narrow bug: preserving or reconstructing the originating cron run context at the generated-media handoff is the maintainable fix. `background: false` and broader async-result routing are adjacent mitigations, not replacements for the context-loss bug.
