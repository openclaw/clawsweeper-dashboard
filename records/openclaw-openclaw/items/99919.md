## Summary

Keep open: current main still resumes generated-media completion through a generic requester-agent handoff that carries the media-ready event, while the original isolated cron path is the one that carries the cron task prompt, configured provider/model, bootstrap kind, and thinking level.

## What This Changes

The issue reports that async media-generation completion can resume an isolated cron run without the original cron task instructions and configured model context, causing the remaining scheduled workflow to be silently skipped.

## Best Possible Solution

Add a cron-aware generated-media continuation path that re-enters the originating cron run with its resolved task prompt, bootstrap kind, delivery context, provider/model, auth profile, and thinking setting, with image/music/video regression coverage proving the resumed turn sees more than the media-ready event.

## Reproduction Assessment

Yes. Current source traces generated-media completion into a requester-agent handoff that lacks the original cron prompt, bootstrap kind, and thinking context, while the normal cron run path passes those fields explicitly.

## Solution Assessment

Yes for the bug boundary, but maintainers need to choose the owner boundary. Preserving or reconstructing the originating cron context at the generated-media handoff is the maintainable fix; background:false and broad async-route work are adjacent mitigations, not replacements.
