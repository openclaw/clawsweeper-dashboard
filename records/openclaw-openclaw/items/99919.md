## Label Justifications

- `P1`: The issue reports a real scheduled workflow silently abandoning required post-media steps and final notification after async image completion.
- `impact:session-state`: The async completion handoff resumes the cron run session without the original cron task context needed to continue the same workflow.
- `impact:message-loss`: The reporter observes NO_REPLY and delivered:false after partial work, so the expected final user message is lost.
- `impact:auth-provider`: The reported and source-supported path can run completion under the default chat model instead of the cron job's configured model.

## Summary

Keep open: current main still routes inactive isolated cron generated-media completions through a requester-agent handoff that carries the session key and task-completion event, but not the cron job's configured model, thinking level, bootstrap kind, or original task prompt.

## What This Changes

The issue asks for async image/media generation completion in cron or isolated agentTurn sessions to resume with the originating cron model and task instructions instead of the default chat model and generic prompt.

## Best Possible Solution

Add a cron-aware generated-media continuation path that re-enters the originating cron run with its resolved provider/model, thinking setting, bootstrap kind, delivery context, and original task prompt, with regression coverage proving no fallback to account default model or generic prompt.

## Reproduction Assessment

Yes, source-reproducible: current main's media completion handoff can target the cron run session but does not pass the cron model, thinking level, bootstrap kind, or original task prompt into the resumed agent turn.

## Solution Assessment

Yes for the narrow bug: preserving or reconstructing the originating cron run context at the media-completion handoff is a better fix than relying on background:false or a broad async-routing feature.
