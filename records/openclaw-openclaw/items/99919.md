## Label Justifications

- `P1`: The bug can silently abandon a scheduled agent workflow after async media completion and skip the expected final user notification.
- `impact:session-state`: The completion handoff resumes a cron run session without the original cron task context needed to continue the same workflow.
- `impact:message-loss`: The reporter observed NO_REPLY and delivered:false after partial work, so the expected completion message can be lost.
- `impact:auth-provider`: The report and current path involve provider/model routing drift when completion resumes without the originating job's explicit run context.

## Summary

Keep open: current main still routes generated-media completion through a generic requester-agent handoff that lacks the originating isolated cron task context, so the reported silent job abandonment remains source-reproducible.

## What This Changes

The issue asks OpenClaw to preserve an isolated cron run's task prompt, model, thinking, and bootstrap context when async media generation completion resumes the run.

## Best Possible Solution

Add a cron-aware generated-media continuation path that re-enters the originating cron run with its resolved prompt/task context, bootstrap kind, delivery context, model selection, and thinking setting, with regression coverage proving the resumed turn does not process only the media-ready event.

## Reproduction Assessment

Yes. Current source traces generated-media completion into a requester-agent handoff that lacks the original cron prompt, bootstrap kind, thinking setting, and explicit run controls; no live repro was run in this read-only review.

## Solution Assessment

Yes for the narrow bug. Preserving or reconstructing the originating cron run context at the generated-media handoff is the right fix, while background:false and broad async routing are adjacent mitigations.
