## Summary

Keep open: current main still sends generated-media completion through a requester-agent handoff that carries the media-ready event but not the originating cron task prompt, cron bootstrap kind, or explicit job thinking; the model-selection part is partly mitigated by pre-run session state, but the reported task-drop behavior remains source-reproducible.

## What This Changes

The issue asks OpenClaw to preserve an isolated cron agent turn's configured model and full task instructions when async media generation completes and resumes the run.

## Best Possible Solution

Add a cron-aware generated-media continuation path that re-enters the originating run with its resolved task prompt, bootstrap kind, delivery context, model selection, and thinking setting, with regression coverage proving the resumed turn continues the job rather than only acknowledging the media event.

## Reproduction Assessment

Yes, at source level. Current main can be traced from generated-media completion into a requester-agent call that carries only the completion event and does not pass the original cron prompt, bootstrap kind, or job thinking setting; I did not run a live cron/media repro in this read-only review.

## Solution Assessment

Yes for the narrow bug, but maintainers still need to choose the ownership boundary. Preserving or reconstructing the originating cron run context at the generated-media handoff is the maintainable fix; a synchronous media option and broad async routing work are adjacent mitigations, not replacements.
