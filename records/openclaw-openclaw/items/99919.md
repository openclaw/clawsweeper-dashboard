## Summary

Keep open: current main records the cron run’s provider/model on the session entry, but generated-media completion still resumes through a requester-agent handoff that carries only the media completion event, not the original cron task prompt, cron bootstrap kind, or explicit job thinking setting.

## What This Changes

The issue reports that async generated-media completion for an isolated cron agent turn resumes without the cron job’s configured model/task context, causing the continuation to acknowledge only the media-ready event and stop.

## Best Possible Solution

Add a cron-aware generated-media continuation path that re-enters the originating cron run with its resolved prompt/task context, bootstrap kind, delivery context, model selection, and thinking setting, with regression coverage proving the resumed turn does not process only the media-ready event.

## Reproduction Assessment

Yes. Current main’s generated-media completion path can be traced from the media wake into the requester-agent handoff, and that handoff does not pass the original cron prompt, cron bootstrap kind, or job thinking into the resumed run.

## Solution Assessment

Yes for the narrow bug. Preserving or reconstructing the originating cron run context at the generated-media handoff is the maintainable fix; `background:false` and broad async routing work are adjacent mitigations, not replacements.
