## Label Justifications

- `P1`: The issue reports a real scheduled workflow silently abandoning required post-media steps and final notification after async image completion.
- `impact:session-state`: The async completion handoff resumes the cron run session without the original cron task context needed to continue the same workflow.
- `impact:message-loss`: The reporter observes `NO_REPLY` and `delivered: false` after partial work, so the expected final user message is lost.
- `impact:auth-provider`: The reported and source-supported failure path can run the completion under the default chat model instead of the cron job's configured model.

## Summary

Keep open: current main still routes generated-media completion for inactive isolated cron runs through a generic requester-agent handoff that carries the media completion event and session key, but not the cron job's original prompt, thinking level, or explicit model override.

## What This Changes

The issue asks OpenClaw to preserve an isolated cron `agentTurn` job's configured model and task instructions when an async media-generation completion resumes the cron run session.

## Best Possible Solution

Add a cron-aware generated-media continuation path that re-enters the originating cron run with its resolved model, thinking setting, bootstrap context, delivery context, and original task prompt, with regression coverage proving the resumed turn does not fall back to the account default model or generic prompt.

## Reproduction Assessment

Yes, source-reproducible: current main's media completion handoff can target the cron run session but does not pass the cron model, thinking level, bootstrap kind, or original task prompt into the resumed agent turn.

## Solution Assessment

Yes for the narrow bug: preserving or reconstructing the originating cron run context at the media-completion handoff is a better fix than relying on `background:false` or a broad new async queue feature.
