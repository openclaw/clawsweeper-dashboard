## Summary

Keep open: the PR is useful and well-proven, but a P2 blocker remains because active-run `rawBody` is updated before queued steer acceptance, and the branch is currently conflicting against `main`. The public plugin-hook API/provenance contract also needs maintainer acceptance before merge.

## What This Changes

The PR adds an optional provenance-gated `rawBody` field to plugin hook events and threads it through channel ingress, queues, embedded/CLI runners, Codex/Copilot harnesses, docs, and tests.

## Best Possible Solution

Land the optional `rawBody` hook contract only after active-run state updates are success-ordered, the branch is refreshed against current `main`, and maintainers accept the documented provenance semantics.

## Reproduction Assessment

Yes for the remaining blocker: source inspection shows `currentRawBody` is updated before the awaited queue operation succeeds, and the queue wrapper returns `runtime_rejected` on failure. I did not run tests in this read-only review.

## Solution Assessment

Mostly yes: an optional hook field with a shared provenance gate is a maintainable alternative to plugins parsing decorated messages. The implementation should update active-run hook state only after successful queue acceptance, and maintainers still need to accept the public API semantics.
