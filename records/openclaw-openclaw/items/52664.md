## Summary

This is a substantial, proof-backed feature PR rather than stale cleanup. Its implementation appears internally consistent across embedded, CLI-backed, Codex, Copilot, queued, collect, and steer paths, but it adds a permanent plugin-hook API whose name suggests literal transport input while the implementation deliberately exposes provenance-gated, command-normalized clean user text; that semantic contract needs explicit maintainer acceptance before merge.

## What This Changes

The branch adds an optional `rawBody` field to `before_prompt_build` and `agent_end` plugin hook events, carrying clean direct-user text through reply preparation, queued runs, active-run steering, embedded execution, and CLI-backed harnesses.

## System Context

OpenClaw turns inbound channel messages into prepared reply runs, which may be queued, steered into an active run, or executed by embedded and CLI-backed agents. Plugin hooks receive prompt-build and completion events from those runtimes, and this PR adds a provenance-gated clean-input value to those event payloads.

## Best Possible Solution

Have the plugin API owner explicitly accept and document `rawBody` as provenance-gated clean direct-user text, not a literal transport-body promise; then refresh the supplied plugin probe on the current head and merge only if that contract is intended to remain stable across runtimes.
