## Summary

Keep this PR open: the additive hook API is useful and has real behavior proof, but the current head still updates the active run's `rawBody` before the queued steer is accepted, so a rejected/failed steer can leak the failed message into later hook events. The live PR also currently reports conflicts against `main`, and the public plugin-hook provenance contract still needs maintainer acceptance before merge.

## What This Changes

The branch adds an optional `rawBody` field to `before_prompt_build`, `before_agent_start`, and `agent_end` hook events and threads it through channel ingress, embedded/CLI/Codex/Copilot runtimes, queue modes, docs, and tests.

## Best Possible Solution

Land the optional `rawBody` hook contract only after the queue state update is success-ordered, the branch is rebased cleanly, and maintainers accept the provenance semantics as the public plugin API.

## Reproduction Assessment

Yes for the remaining blocker: source inspection shows `currentRawBody` is updated before the awaited queue operation succeeds, and the queue API returns `runtime_rejected` when `queueMessage` throws. I did not run tests in this read-only review.

## Solution Assessment

Mostly yes: an optional hook field with a shared provenance gate is a maintainable alternative to plugins parsing decorated messages. The implementation should update active-run state only after successful queue acceptance, and maintainers still need to accept the public API semantics.
