## Summary

This PR is still useful and current main does not already expose `rawBody` on plugin hook events, but it should not merge as-is because the active embedded run mutates hook-visible `currentRawBody` before queued steer delivery succeeds. The remaining blocker is narrow and repairable; the public hook contract and overlap with the broader trusted inbound-decoration work still need maintainer acceptance before landing.

## What This Changes

The branch adds an optional `rawBody` field to `before_prompt_build`, legacy `before_agent_start`, and `agent_end` plugin hook events, then threads it through embedded, CLI, Codex, Copilot, followup, collect, and steer paths with docs and tests.

## Best Possible Solution

Move the active-run `currentRawBody` update to occur only after queued delivery is accepted or transcript-committed, preserve the additive hook API docs/tests, refresh the branch conflict, and have maintainers accept the contract in light of the broader trusted inbound-decoration work.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: a queued active-run injection can reject after `currentRawBody` has already changed, and later hook events read that mutated value.

## Solution Assessment

No, not as implemented. The additive hook field is a plausible owner-boundary solution, but the active-run state update must move after successful queue acceptance and maintainers still need to accept the public plugin contract.
