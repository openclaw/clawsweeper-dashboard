## Summary

Keep this PR open for maintainer review. The revised branch addresses the prior Codex fail-closed and policy-validation concerns, and its redacted real-environment transcript now directly exercises the Docker-unavailable chat and execution paths; however, it adds a public sandbox mode and changes execution activation semantics across core and the Codex extension, so acceptance needs an explicit product/security decision rather than cleanup closure.

## What This Changes

This PR adds `sandbox.mode: "needed"`, allowing chat-only turns to run without eagerly starting a sandbox while sandbox-bound execution activates the configured backend on demand and fails closed if unavailable.

## System Context

The embedded-agent runtime resolves sandbox state before preparing tools for a chat turn, while the exec tool and Codex app-server expose execution capabilities later in that flow. This PR separates chat-time sandbox status from tool-time activation so a Docker outage does not suppress a chat-only reply, while execution remains isolated or blocked.
