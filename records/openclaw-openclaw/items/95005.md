## Summary

Keep this PR open: it is a useful candidate for the Docker-unavailable chat outage, but it is not merge-ready because `needed` mode still leaves the Codex app-server native execution surface able to run host-side work instead of lazily sandboxing or failing closed.

## What This Changes

The PR adds `agents.defaults.sandbox.mode = "needed"`, lazy sandbox resolution for embedded exec, schema/type updates, sandbox explain/audit/doc copy, and focused tests.

## Best Possible Solution

Before merge, make `needed` lazily sandbox or fail closed every sandbox-bound execution surface, including Codex app-server native tools, then add redacted Docker-off proof for chat-only success and sandbox-bound failure.

## Reproduction Assessment

Yes by source inspection: `needed` reports unsandboxed for default run activation while Codex app-server native execution derives host/native capability from that run-level sandbox context. I did not run a live Docker-off reproduction in this read-only review.

## Solution Assessment

No: lazy embedded exec is a plausible part of the fix, but the PR is too narrow until Codex app-server native process, filesystem, and MCP execution share the same fail-closed sandbox invariant.
