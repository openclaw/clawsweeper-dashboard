## Summary

Keep this PR open: the `needed` mode is useful, but the patch only lazily wires embedded exec while leaving Codex native app-server execution paths able to see the session as unsandboxed, and the posted proof does not cover Docker-unavailable or sandbox-bound fail-closed behavior.

## What This Changes

The PR adds a public `agents.defaults.sandbox.mode: "needed"` value, threads run-vs-tool sandbox activation through sandbox resolution, lazily resolves exec sandbox defaults, and updates sandbox diagnostics and tests.

## Best Possible Solution

Before merge, make every sandbox-bound execution surface, including Codex app-server native shell/process/fs/MCP, either lazily resolve the sandbox or fail closed under `needed`, then prove Docker-off chat success and sandbox-bound failure behavior.

## Solution Assessment
