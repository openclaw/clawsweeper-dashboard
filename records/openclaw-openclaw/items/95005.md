## Summary

Keep open: the PR implements useful lazy embedded exec pieces, but it is not merge-ready because `needed` marks run activation unsandboxed while current Codex app-server native execution still uses run-level sandbox state and can expose host/gateway-native execution instead of sandboxing or failing closed.

## What This Changes

The PR adds `agents.defaults.sandbox.mode = "needed"`, lazy sandbox creation for embedded exec tools, sandbox explain/doctor/audit/docs updates, and focused tests.

## Best Possible Solution

Before merge, make `needed` lazily sandbox or fail closed every sandbox-bound execution surface, including Codex app-server native tools, then add Docker-off proof for chat-only success and sandbox-bound failure.

## Reproduction Assessment

Yes by source inspection: `needed` reports unsandboxed for default run activation while Codex app-server native execution derives host/native capability from that run-level sandbox context.

## Solution Assessment

No: lazy embedded exec is a plausible part of the fix, but the PR is too narrow until Codex app-server native process, filesystem, and MCP execution share the same fail-closed sandbox invariant.
