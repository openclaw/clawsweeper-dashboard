## Summary

Current main and v2026.6.11 still keep context overflow inside same-model compaction/recovery and then return a blocked result or rethrow; the proof-backed implementation PR closed unmerged, so the requested capability remains necessary but needs explicit maintainer product sponsorship.

## What This Changes

Allow configured model fallback to select a model with sufficient context after the primary model exhausts overflow recovery.

## Best Possible Solution

After existing compaction and truncation recovery is exhausted, make only replay-safe overflow results fallback-eligible, select only configured candidates with canonical verified context headroom, log the routing event, and preserve the blocked recovery result when no safe candidate qualifies.
