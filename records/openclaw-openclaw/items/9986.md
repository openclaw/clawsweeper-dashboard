## Summary

Keep open: current main and the latest release still treat context overflow as active-model compaction/retry followed by a blocked overflow result, not as a trigger to choose a larger configured fallback model.

## What This Changes

The issue requests automatic routing from an over-context primary model to a configured fallback model with enough context headroom.

## Best Possible Solution

Maintain compaction-only overflow only if maintainers explicitly choose that policy; otherwise implement guarded larger-context fallback after compaction and oversized-tool-result recovery are exhausted, with replay-safety gates, candidate context-window filtering, logs, docs, and regression coverage.

## Reproduction Assessment

Yes. Source inspection shows current main still rethrows escaped context-overflow errors and returns blocked embedded context_overflow results instead of trying a larger configured fallback model.

## Solution Assessment

Unclear until maintainers decide the policy. A guarded post-recovery larger-window fallback is plausible, but unconditional fallback would be unsafe without context-window filtering and replay-safety gates.
