## Summary

Keep open: current main and v2026.6.11 still implement context overflow as active-model compaction/truncation followed by a blocked overflow result, while the only direct larger-context fallback PR was closed unmerged.

## What This Changes

Request automatic fallback to a configured larger-context model when the primary model exceeds its context window.

## Best Possible Solution

Either document overflow as compaction-only, or implement guarded larger-context fallback only after compaction/truncation recovery is exhausted, with context-window filtering, replay-safety gates, fallback logs, docs, and regression coverage.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should context overflow ever advance to a larger configured model fallback after compaction and oversized-tool-result truncation are exhausted, or should it remain compaction-only?

Rationale: Both choices are defensible: larger-context fallback may recover long sessions, but it changes core provider/model routing and can replay unsafe work unless the policy is tightly constrained.

Likely owner: steipete

Owner reason: This handle has recent current-main ownership across the affected runner/classifier paths and already performed detailed policy-oriented review on this issue.

Owner confidence: high

Options:

- **Implement guarded larger-context fallback (recommended):** Allow fallback only after local recovery is exhausted, only to candidates with sufficient effective context headroom, and only when replay/delivery safety checks pass.
- **Keep compaction-only overflow policy:** Leave overflow outside model fallback and update docs/error copy so users know to reset, compact, or choose a larger model manually.
- **Split diagnostics first:** Land clearer overflow diagnostics and model-switch guidance while deferring automatic fallback policy to a later design decision.

## Reproduction Assessment

Yes, source-level reproduction is high-confidence: current main still rethrows escaped context-overflow errors and returns blocked embedded context_overflow results instead of trying a larger configured fallback model. I did not run a live provider reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers decide the policy. A guarded post-recovery larger-window fallback is plausible, but unconditional fallback is not the best fix because it would bypass context-window filtering, replay-safety gates, and docs alignment.
