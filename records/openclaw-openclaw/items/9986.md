## Summary

Keep open: current main and the latest release still treat context overflow as active-model compaction/retry followed by a blocked overflow result, while the direct larger-context fallback PR was closed unmerged and no open related PR owns this exact behavior.

## What This Changes

The issue requests routing a context-length overflow from the primary model to a configured fallback model with enough context headroom.

## Best Possible Solution

Either document compaction-only overflow as the intended policy, or land a guarded larger-context fallback after compaction and oversized-tool-result recovery are exhausted, with replay-safety gates, context-window filtering, logs, docs, and regression coverage.

## Reproduction Assessment

Yes, source-level: current main still rethrows escaped context-overflow errors and returns blocked embedded context_overflow results instead of trying a larger configured fallback model.

## Solution Assessment

Unclear until maintainers decide the policy. A guarded post-recovery larger-window fallback is plausible, but unconditional fallback would be unsafe without context-window filtering and replay-safety gates.
