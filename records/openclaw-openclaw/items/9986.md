## Summary

Keep open: current main and the latest release still treat context overflow as active-model compaction/retry followed by a blocked overflow result, while the direct larger-context fallback PR is closed unmerged and adjacent open work does not implement the requested fallback routing.

## What This Changes

The issue requests that configured model fallbacks be considered when the active model exceeds its context window, selecting a larger-context fallback instead of freezing or ending in overflow.

## Best Possible Solution

Keep this open until maintainers either document context overflow as compaction-only or implement a guarded fallback path after compaction and truncation recovery are exhausted.

## Reproduction Assessment

Yes from source: current main rethrows escaped context-overflow errors and returns blocked embedded context_overflow results instead of trying a larger configured fallback model. I did not execute the runtime repro in this read-only cleanup pass.

## Solution Assessment

Unclear. A guarded larger-model fallback may be the right end state, but current source and docs intentionally keep overflow inside compaction/retry, so maintainers need to decide the product contract before implementation.
