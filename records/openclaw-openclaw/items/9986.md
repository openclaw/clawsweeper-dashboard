## Summary

Keep open: current main and the latest release still treat context overflow as active-model compaction/truncation followed by a blocked overflow result, and the direct larger-context fallback PR was closed unmerged.

## What This Changes

Request automatic routing to a configured larger-context fallback model when the primary model exceeds its context limit.

## Best Possible Solution

Either document overflow as compaction-only, or implement guarded larger-context fallback only after compaction/truncation recovery is exhausted, with context-window filtering, replay-safety gates, fallback logs, docs, and regression coverage.

Options:

- **Implement guarded larger-window fallback (recommended):** Allow fallback only after compaction and truncation fail, only to candidates with known sufficient effective context, and preserve replay-safety and delivery guards.
- **Keep compaction-only behavior:** Document that context overflow is not a model-fallback trigger and improve the user-facing recovery guidance instead.
- **Defer to narrower UX work:** Keep this issue open while prioritizing diagnostics such as https://github.com/openclaw/openclaw/issues/9409 and model-switch recovery such as https://github.com/openclaw/openclaw/issues/58957.

Yes, by source inspection. Current main still rethrows escaped context-overflow errors and returns blocked embedded context_overflow results instead of trying a larger configured fallback model; I did not run a live provider repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the policy. A guarded post-recovery larger-window fallback is plausible, but unconditional fallback is unsafe without context-window filtering, replay-safety gates, and docs alignment.
