## Summary

Keep open. Current main and the latest release still handle context overflow through active-model compaction, retry, tool-result truncation, and then a blocked overflow result; the larger-context fallback behavior requested here is still a product-sensitive missing capability, and the direct fix PR closed unmerged.

## What This Changes

The issue requests automatic fallback to a configured larger-context model after the primary model exceeds its context window.

## Best Possible Solution

Define the maintainer policy first, then either keep and document compaction-only overflow handling or land a guarded larger-context fallback after compaction and tool-result truncation are exhausted.

## Reproduction Assessment

Yes, at source level. Current main still rethrows escaped context-overflow errors from the fallback loop and returns a blocked context_overflow result after active-model recovery, so a larger configured fallback is not selected by that path.

## Solution Assessment

Unclear. A guarded larger-context fallback is plausible, but current docs intentionally define overflow as compaction/retry-only and the change needs maintainer approval for replay safety, context metadata, and provider-routing policy.
