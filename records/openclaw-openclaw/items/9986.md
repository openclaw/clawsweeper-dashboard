## Summary

Keep open: current main and the latest release still treat context overflow as active-model compaction/truncation followed by a blocked overflow result, while the only direct larger-context fallback implementation was closed unmerged.

## What This Changes

The issue requests trying a configured fallback model with enough context headroom when the primary model exceeds its context limit.

## Best Possible Solution

Either document overflow as compaction-only, or implement guarded larger-context fallback only after compaction/truncation recovery is exhausted, with context-window filtering, replay-safety gates, fallback logs, docs, and regression coverage.

## Reproduction Assessment

Yes. Source inspection shows current main still rethrows escaped context-overflow errors and returns blocked embedded context_overflow results instead of trying a larger configured fallback model; I did not run a live provider repro in this read-only review.

## Solution Assessment

Unclear until maintainers decide the policy. A guarded post-recovery larger-window fallback is plausible, but unconditional fallback is unsafe without context-window filtering, replay-safety gates, and docs alignment.
