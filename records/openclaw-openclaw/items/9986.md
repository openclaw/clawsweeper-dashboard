## Summary

Keep open: current main and the latest tagged release still document and implement context overflow as active-model compaction/retry plus blocked overflow handling, while the direct larger-context fallback PR is closed unmerged and the remaining open related work is adjacent rather than a replacement.

## What This Changes

The issue requests routing a context-overflowed run to a configured fallback model with a larger effective context window.

## Best Possible Solution

Maintain compaction-only overflow only if maintainers explicitly choose that policy; otherwise implement guarded larger-context fallback after compaction and oversized-tool-result recovery are exhausted, with replay-safety gates, candidate context-window filtering, logs, docs, and regression coverage.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 still rethrow escaped context-overflow errors and return blocked embedded context_overflow results instead of trying a larger configured fallback model.

## Solution Assessment

Unclear until maintainers decide the policy. A guarded post-recovery larger-window fallback is plausible, but unconditional fallback would be risky without context-window filtering and replay-safety gates.
