## Summary

Keep open: current main and v2026.6.11 still route context overflow through active-model compaction/truncation and then a blocked overflow result or rethrow, not to a configured larger-context fallback. The direct implementation PR was closed unmerged, so the remaining work is a maintainer product-policy decision.

## What This Changes

Request automatic fallback to a configured larger-context model when the primary model exceeds its context window.

## Best Possible Solution

Maintainers should either document overflow as compaction-only, or implement guarded larger-context fallback only after compaction/truncation recovery is exhausted, with context-window filtering, replay-safety gates, fallback logs, docs, and regression coverage.

Question: Should OpenClaw allow model fallback after context overflow recovery is exhausted, and under what replay-safety and context-window constraints?

Rationale: Both choices are product-valid: current docs and code intentionally keep overflow inside compaction/retry, while the issue reports a real long-session recovery gap that crosses provider routing, replay safety, and context-window semantics.

Options:

- **Implement guarded larger-window fallback (recommended):** Allow fallback only after compaction and truncation fail, only to candidates with known sufficient effective context, and preserve replay-safety and delivery guards.
- **Keep compaction-only behavior:** Document that context overflow is not a model-fallback trigger and improve the user-facing recovery guidance instead.
- **Defer to narrower UX work:** Prioritize diagnostics and model-switch recovery issues while leaving larger-context fallback as an explicit future policy decision.

## Solution Assessment

Unclear until maintainers choose the policy; a guarded post-recovery larger-window fallback is plausible, but unconditional fallback is unsafe without context-window filtering, replay-safety gates, and docs alignment.
