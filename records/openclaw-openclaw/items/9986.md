## Summary

Keep open: current main and the latest release still handle context overflow through active-model compaction/retry and then a blocked overflow result, while the direct larger-context fallback PR was closed unmerged and adjacent open work does not replace this request.

## What This Changes

Request automatic routing to a configured larger-context fallback model when the active model exceeds its context limit.

## Best Possible Solution

Either document that overflow remains compaction-only, or implement guarded larger-context fallback only after compaction/truncation recovery is exhausted, with context-window filtering, replay-safety gates, fallback logs, docs, and regression coverage.

## Reproduction Assessment

Yes, source-level: current main still rethrows escaped context-overflow errors and returns blocked embedded context_overflow results instead of trying a larger configured fallback model. I did not run a live provider repro in this read-only review.

## Solution Assessment

Unclear until maintainers decide the policy. A guarded post-recovery larger-window fallback is plausible, but unconditional fallback would be unsafe without context-window filtering and replay-safety gates.
