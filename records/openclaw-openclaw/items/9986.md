## Summary

Keep open: current main still treats context overflow as same-model compaction/recovery and explicitly excludes it from model fallback, so the requested larger-context fallback remains unimplemented and needs a replay-safety and routing-policy decision.

Likely related people: steipete (high confidence), tyler6204 (high confidence), and vincentkoc (medium confidence), based on fallback and overflow-recovery history.

## What This Changes

Allow configured model fallback to select a candidate with a larger context window after the active model exhausts context-overflow recovery.

## Best Possible Solution

After compaction and oversized-result recovery are exhausted, permit a replay-safe fallback only to explicitly configured candidates with trustworthy, demonstrably larger context headroom; log the switch and define whether it persists for subsequent turns.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should exhausted context overflow remain a compaction-only terminal condition, or may OpenClaw retry the active turn on a configured larger-context fallback model?

Rationale: The choice changes cross-provider replay semantics, tool side-effect safety, model-selection persistence, and how much trust runtime routing places in context-window metadata.

Likely owner: steipete

Owner reason: This person has the strongest combined history in the fallback and embedded-runner paths and already reviewed the issue's product boundary.

Owner confidence: high

Options:

- **Add guarded larger-model fallback (recommended):** Retry only at a replay-safe boundary after normal overflow recovery fails, filtering configured candidates to those with trustworthy larger context windows and recording the routing event.
- **Keep compaction-only behavior:** Retain the current terminal overflow result and document that operators must manually switch models or start a new session after recovery is exhausted.
- **Require explicit opt-in policy:** Add an operator-controlled setting that preserves compaction-only behavior by default and enables guarded context-overflow fallback when configured.

## Reproduction Assessment

Yes at source level: current fallback code explicitly rethrows context-overflow errors, while current documentation routes overflow through compaction and retry on the active model. A live failing session was not required to establish the missing routing behavior.

## Solution Assessment

Unclear until maintainers choose the replay and persistence policy. The narrowest maintainable implementation is a post-recovery, replay-safe, larger-window-only fallback rather than general context-size model routing.
