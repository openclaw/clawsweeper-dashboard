## Summary

Keep open: the request is still a distinct model-routing feature, not merely ordinary compaction or existing failover. The most recent prior review found context overflow deliberately stays on the active-model compaction/retry path, while the newer related report concerns selecting context-capable candidates during an already-triggered failover; neither establishes the requested post-recovery cross-model fallback contract.

## What This Changes

Add guarded fallback routing to a configured model with sufficient context headroom when the primary model still overflows after context recovery.

## Best Possible Solution

Define and implement a single guarded post-recovery fallback path: compact/truncate first, then choose only a larger viable fallback with sufficient measured headroom, record the switch, and preserve a safe session/replay contract.

Question: After active-model compaction and tool-result recovery are exhausted, should OpenClaw switch the session to a larger-context fallback model, and what replay and persistence guarantees should that switch provide?

Rationale: The present behavior deliberately separates context recovery from failover; choosing to cross that boundary determines user-visible model selection, transcript replay, and future-session state rather than a mechanical bug fix.

Likely owner: steipete

Owner reason: The latest issue review and central-path history indicate the strongest connection to both the policy boundary and the implementation surfaces.

Owner confidence: high

Options:

- **Adopt guarded larger-window fallback (recommended):** After recovery is exhausted, permit a one-way fallback only for candidates with verified headroom and explicit replay/session persistence safeguards.
- **Keep compaction-only behavior:** Retain context overflow as an active-model recovery outcome and document that model fallbacks cover provider failures rather than context capacity.
- **Track candidate filtering separately:** Land only context-window-aware filtering for existing failovers and defer overflow-initiated switching until its replay contract is designed.

## Reproduction Assessment

No high-confidence live reproduction was performed in this review. Earlier source inspection provides a clear static path: exhaust compaction/recovery for a context overflow with configured fallbacks and observe that the result remains blocked rather than entering model failover.

## Solution Assessment

Unclear until maintainers choose the intended cross-model replay contract. A guarded fallback after existing recovery is safer than immediately treating every overflow as a retryable provider failure, but it requires candidate-headroom and session-state rules.
