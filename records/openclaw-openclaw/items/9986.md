## Summary

Keep open: current main still documents context overflow as a compaction/retry boundary rather than an automatic fallback trigger, so the requested cross-model recovery remains a product and session-safety decision.

## What This Changes

The issue requests automatically retrying on a configured fallback model with a larger context window when the active model exceeds its context limit.

## Best Possible Solution

If maintainers sponsor this direction, add a guarded fallback only after existing compaction and oversized-result recovery are exhausted, selecting candidates with verified usable headroom, preserving replay safety, logging the switch, and covering session persistence and failed-candidate behavior.

## Solution Assessment

No, not as an unconditional fallback trigger: the current compaction-first contract avoids cross-model replay hazards. A guarded, post-recovery path could be the best solution only after maintainers choose its session and candidate-headroom rules.
