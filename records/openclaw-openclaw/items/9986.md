## Summary

Keep open: current main and the latest release still keep context overflow in the active-model compaction/retry path and then return a blocked overflow result, while the direct larger-context fallback PR is closed unmerged and adjacent open PRs do not replace this request.

## What This Changes

The issue requests routing a context-length overflow to a configured fallback model with enough context headroom instead of failing after the primary model overflows.

## Best Possible Solution

Maintain compaction-only overflow only if maintainers explicitly choose that policy; otherwise implement guarded larger-context fallback after compaction and oversized-tool-result recovery are exhausted, with replay-safety gates, candidate context-window filtering, logs, docs, and regression coverage.

## Reproduction Assessment

Yes, source-level: current main still rethrows escaped context-overflow errors and returns blocked embedded context_overflow results instead of trying a larger configured fallback model.

## Solution Assessment

Unclear until maintainers decide the policy. A guarded post-recovery larger-window fallback is plausible, but unconditional fallback would be unsafe without context-window filtering and replay-safety gates.
