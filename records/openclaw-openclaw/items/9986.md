## Summary

Keep open: current main and the latest release still document and implement context overflow as compaction/retry plus a blocked overflow result after recovery is exhausted, while the direct larger-context fallback PR was closed unmerged and explicitly left this issue valid.

## What This Changes

The issue requests automatic fallback to a configured larger-context model when the active model exceeds its context window.

## Best Possible Solution

Keep this issue open until maintainers either document context overflow as intentionally compaction-only, or approve a guarded larger-context fallback design with replay-safety, context-headroom filtering, logging, and regression coverage.

## Reproduction Assessment

Yes at source level: current main still routes context overflow through compaction/retry and blocked overflow results instead of larger-model fallback. I did not run a live provider reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the policy; the requested fallback is plausible, but the best implementation must run only after recovery exhaustion, filter candidates by sufficient context window, and preserve replay safety.
