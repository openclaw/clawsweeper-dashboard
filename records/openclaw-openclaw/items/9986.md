## Summary

Keep this issue open. Current main still treats a context overflow as a compaction-and-retry boundary, while ordinary model fallback is intentionally prevented from crossing that boundary; the requested larger-context fallback therefore remains a real product and session-safety decision rather than an implemented fix.

## What This Changes

Request automatic selection of a configured fallback model with a larger context window when the active model cannot recover from a context-length overflow.

## System Context

Embedded agent runs use the active model to process a session transcript; when the prompt exceeds that model’s context window, OpenClaw compacts the transcript and retries. Model fallback is a separate recovery path for eligible provider failures, so allowing overflow to cross into another model would affect transcript continuity, replay behavior, and provider selection.

## Architecture Diagram

flowchart LR
  SessionTranscript[Session transcript] --> ActiveModel[Active model run]
  ActiveModel --> Overflow[Context overflow]
  Overflow --> CompactRetry[Compaction and retry]
  CompactRetry --> BlockedResult[Blocked overflow result]
  FallbackConfig[Configured fallback models] --> ProviderFailure[Eligible provider failure]
  ProviderFailure --> AlternateModel[Alternate model run]

## Best Possible Solution

Define and implement one guarded post-compaction recovery policy: only after normal compaction and tool-result trimming are exhausted, select a fallback proven to have sufficient effective context headroom, preserve replay safety and session identity, log the switch, and cover both larger- and smaller-window candidates.

Rationale: The present boundary was intentional to prevent a fallback with a smaller effective context window from making recovery worse; changing it requires a durable decision about candidate eligibility, replay safety, and what model change is visible to the user.

Options:

- **Add guarded larger-window fallback (recommended):** After compaction recovery is exhausted, permit only candidates whose effective context budget can accommodate the prepared request, with replay-safe retry and explicit diagnostics.
- **Keep compaction-only overflow recovery:** Retain the present boundary and improve the terminal recovery guidance instead of switching models automatically.
- **Design candidate eligibility first:** Land the shared context-window-aware candidate-selection contract with the related issue before choosing whether overflow itself may trigger it.
