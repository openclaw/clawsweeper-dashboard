## Summary

Keep open: current main and the latest release still handle context overflow through active-model compaction/truncation and then a blocked overflow result, while the direct larger-context fallback PR was closed unmerged and adjacent open work covers different overflow UX/classification problems.

## What This Changes

The issue requests routing context-length overflow to a configured fallback model with enough context headroom instead of freezing or ending on the primary model.

## Best Possible Solution

Either document overflow as compaction-only, or implement guarded larger-context fallback only after compaction/truncation recovery is exhausted, with context-window filtering, replay-safety gates, fallback logs, docs, and regression coverage.

## Reproduction Assessment

Yes, source-level: current main still rethrows escaped context-overflow errors and returns blocked embedded context_overflow results instead of trying a larger configured fallback model. I did not run a live provider repro in this read-only review.

## Solution Assessment

Unclear until maintainers decide the policy. A guarded post-recovery larger-window fallback is plausible, but unconditional fallback would be unsafe without context-window filtering and replay-safety gates.
