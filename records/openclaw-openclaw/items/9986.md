## Summary

Keep this issue open. Current main and the latest release still exhaust active-model compaction/truncation recovery into a blocked context-overflow result instead of selecting a configured larger-context fallback; the only direct implementation PR closed unmerged, and the remaining behavior requires an explicit replay-safety and model-window policy.

## What This Changes

Request automatic selection of a configured larger-context fallback model after the active model exhausts context-overflow recovery.

## Best Possible Solution

Add fallback eligibility only for exhausted context_overflow results that are replay-safe, filter configured candidates through the canonical effective-context metadata path, and retain the current blocked recovery result when no safe larger candidate exists.
