## Summary

Keep open. Current main and the latest release still treat context overflow as active-model compaction/retry plus a blocked overflow result, while the fallback loop explicitly rethrows overflow errors instead of selecting a larger configured fallback model; the direct fix PR closed unmerged and adjacent work does not supersede this request.

## What This Changes

The issue requests routing context-window overflow from a smaller primary model to a configured larger fallback model after active-model recovery is exhausted.

## Best Possible Solution

Keep the issue open for a maintainer decision between documenting compaction-only behavior or implementing a guarded larger-context fallback after compaction/truncation recovery is exhausted.

## Reproduction Assessment

Yes at source level: current main still rethrows context-overflow errors from the fallback loop and documents overflow as compaction/retry-only, so a larger configured fallback is not selected by that path.

## Solution Assessment

Unclear: guarded larger-model fallback may be the right end state, but the direct fix PR closed unmerged and repository policy treats fallback behavior as a maintainer product decision because of replay and provider-routing risk.
