## Summary

Keep open: current main and the latest release still handle context overflow inside compaction/truncation recovery and then surface a blocked overflow result; configured larger-context fallback remains a product-policy decision rather than implemented behavior.

## What This Changes

The issue requests that context-length-exceeded failures trigger model fallback to a larger configured model instead of stopping on the active model after overflow recovery.

## Best Possible Solution

Maintainers should either reaffirm and document compaction-only overflow handling, or implement guarded larger-context fallback after recovery is exhausted with replay-safety, context-window filtering, logging, docs, and focused regression coverage.
