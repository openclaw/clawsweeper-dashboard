- `impact:auth-provider`: The requested behavior changes provider and model routing through the configured fallback chain.

## Summary

Current main still handles context overflow through compaction and oversized-result recovery, then returns a blocked overflow result when recovery is exhausted. It does not select a configured larger-context fallback, so the central request remains unresolved and requires an explicit cross-model replay and session-state decision.

## What This Changes

Allow configured fallback models with sufficient context headroom to take over after the primary model exhausts context-overflow recovery.

## Best Possible Solution

After compaction and oversized-tool-result recovery are exhausted, allow only replay-safe runs to try configured candidates whose effective context window is known to fit the prompt, reusing the existing automatic-fallback lifecycle without adding another config knob and covering candidate filtering, side-effect guards, persistence, notices, rollback, and primary recovery.

Options:

- **Guarded larger-context fallback (recommended):** After compaction and truncation fail, retry only replay-safe runs on configured candidates with verified sufficient context and use the existing automatic-fallback lifecycle.
- **Keep compaction-only behavior:** Continue returning a blocked overflow result and document that users must compact, reset, or explicitly switch models.
- **Fallback for one turn:** Try a verified larger candidate for the current turn without persisting the model change unless the user explicitly switches.

## Reproduction Assessment

Yes at source level: with a smaller primary and larger configured fallback, exhausting compaction and tool-result recovery reaches a blocked `context_overflow` result without entering model fallback. A live current-main run was not performed during this read-only review.

## Solution Assessment

Unclear as originally proposed: automatic fallback is plausible, but unconditional cross-model retry is unsafe. The maintainable form is a guarded, replay-safe reuse of the existing fallback lifecycle after local overflow recovery is exhausted.
