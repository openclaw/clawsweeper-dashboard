## Summary

Keep open. Current main and the latest release still keep context overflow inside active-model compaction/retry and terminal blocked overflow handling; the direct larger-context fallback PR closed unmerged, and adjacent open work does not supersede the requested behavior.

## What This Changes

The issue requests using configured model fallbacks when the primary model exceeds its context window, choosing a fallback with enough context headroom.

## Best Possible Solution

Maintainers should either explicitly document context overflow as compaction-only, or approve a guarded larger-context fallback path that runs only after compaction and tool-result truncation are exhausted and is covered by replay-safety and context-window tests.

## Reproduction Assessment

Yes, at source level. Current main still rethrows context-overflow errors from the fallback loop and returns blocked overflow results after active-model recovery, so a larger configured fallback is not selected by that path.

## Solution Assessment

Unclear. A guarded larger-model fallback is plausible, but the repository currently documents compaction-only overflow handling and the safe implementation needs a maintainer decision on replay safety, provider routing, and context metadata.
