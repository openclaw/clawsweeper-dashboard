## Summary

Keep open. Current main and the latest release still keep context overflow inside active-model compaction/retry or a blocked overflow result, while the fallback loop still rethrows overflow errors instead of selecting a larger configured fallback; the direct fix PR closed unmerged and adjacent open PRs do not supersede this request.

## What This Changes

The issue requests attempting configured model fallbacks when the active model exceeds its context window and a fallback model has sufficient context headroom.

## Best Possible Solution

Keep the issue open until maintainers either document compaction-only overflow as intentional or approve a guarded larger-context fallback path after compaction and truncation recovery are exhausted.

## Reproduction Assessment

Yes, at source level: current main still rethrows likely context-overflow errors from the fallback loop and returns blocked context_overflow after embedded recovery is exhausted. I did not run a live-provider reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product boundary. A guarded larger-context fallback could solve the report, but unconditional fallback would be the wrong shape without replay-safety checks and context-window filtering.
