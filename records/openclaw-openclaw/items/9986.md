## Summary

Keep open: current main and the latest release still keep context overflow on the active-model compaction/retry path and block after recovery is exhausted, while the direct larger-context fallback PR is closed unmerged and related open work is adjacent rather than a replacement.

## What This Changes

The issue requests using configured model fallbacks when the primary model exceeds its context limit, selecting a fallback model with enough context headroom and logging that route.

## Best Possible Solution

Maintain compaction-only overflow only if maintainers explicitly choose that policy; otherwise implement guarded larger-context fallback after compaction and tool-result recovery are exhausted, with candidate headroom filtering, replay-safety gates, logging, docs, and regression coverage.

## Reproduction Assessment

Yes, at source level: current main still rethrows escaped context-overflow errors and returns blocked embedded context_overflow results instead of trying a larger configured fallback model. I did not run a live provider overflow scenario in this read-only review.

## Solution Assessment

Unclear pending maintainer policy. A guarded post-recovery larger-window fallback is plausible, but unconditional fallback would be unsafe without context-window filtering and replay-safety gates.
