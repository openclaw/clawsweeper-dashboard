## Summary

Keep open: current main and v2026.6.11 still keep context overflow inside active-model compaction/retry and then return or rethrow overflow instead of selecting a configured larger-context fallback. The direct implementation attempt closed unmerged, so the remaining work is a maintainer product-policy decision rather than conservative cleanup.

## What This Changes

The issue requests automatic fallback from an overflowing primary model to a configured fallback model with enough context headroom.

## Best Possible Solution

Maintainers should either document overflow as compaction-only, or implement guarded larger-context fallback only after compaction/truncation exhaustion with context-window filtering, replay-safety gates, fallback logs, docs, and regression coverage.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw allow configured model fallback after context-overflow recovery is exhausted, and what replay-safety and context-window constraints should gate it?

Rationale: Both directions are product-valid: current docs and code intentionally keep overflow inside compaction/retry, while the issue reports a real long-session recovery gap that changes provider/model routing and session replay semantics.

Likely owner: steipete

Owner reason: steipete has the strongest combination of recent central-file history and prior issue-review context for this policy boundary.

Owner confidence: high

Options:

- **Implement guarded larger-window fallback (recommended):** Allow fallback only after compaction and truncation fail, only to candidates with known sufficient effective context, and preserve replay-safety and delivery guards.
- **Keep compaction-only behavior:** Document that context overflow is not a model-fallback trigger and improve visible recovery guidance instead.
- **Defer behind context UX work:** Prioritize diagnostics and model-switch recovery while leaving larger-context fallback as an explicit future policy decision.

## Reproduction Assessment

Yes, at source level: current main rethrows escaped context-overflow errors and returns blocked embedded context_overflow results instead of trying a larger configured fallback model. I did not run a live provider repro in this read-only sweep.

## Solution Assessment

Unclear until maintainers choose the policy. A guarded post-recovery larger-window fallback is plausible, but unconditional fallback is unsafe without context-window filtering, replay-safety gates, and docs alignment.
