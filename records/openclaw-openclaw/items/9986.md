## Summary

Keep open: current main and the latest release still treat context overflow as active-model compaction/retry plus a blocked overflow result after recovery is exhausted, while the model fallback path explicitly keeps escaped overflow errors out of fallback. The direct implementation PR closed unmerged, and the remaining work is a provider-routing/session-replay product decision rather than conservative cleanup.

## What This Changes

Request automatic model fallback to a configured larger-context model when the active model exceeds its context window.

## Best Possible Solution

Keep this open until maintainers either document context overflow as intentionally compaction-only or approve a guarded larger-context fallback design after compaction/truncation exhaustion.

## Reproduction Assessment

Yes, at source level. Current main still rethrows context-overflow errors from `runWithModelFallback`, and embedded overflow exhaustion returns a blocked `context_overflow` result instead of trying a larger fallback model.

## Solution Assessment

Unclear until maintainers choose the policy. A direct larger-model fallback is plausible, but the maintainable version needs replay-safety, context-headroom filtering, docs, and regression coverage because current docs intentionally keep context overflow inside compaction/retry.
