## Label Justifications

- `P2`: This is a normal-priority provider/session recovery improvement with real user impact but a product-sensitive fix shape.
- `impact:session-state`: The issue concerns long-session context overflow, compaction, and whether session state can continue after the active model exhausts its context window.
- `impact:auth-provider`: The requested behavior changes model fallback and provider/model routing when the configured primary cannot handle the current context size.

## Summary

Keep open. Current main and the latest release still route context overflow through active-model compaction/retry and a blocked overflow result, while the fallback loop explicitly rethrows overflow errors instead of selecting a larger configured fallback; the direct larger-fallback PR is closed unmerged and the open adjacent PRs do not supersede this behavior request.

## What This Changes

Request automatic model fallback to a configured larger-context model when the primary model exceeds its context window.

## Best Possible Solution

Keep the issue open until maintainers either document compaction-only overflow as the intended contract or implement a guarded fallback path after compaction/truncation exhaustion that filters for sufficient larger context and preserves replay safety.

## Reproduction Assessment

Yes, source-level. Current main still rethrows thrown context-overflow errors from the fallback loop and returns a blocked context_overflow result after compaction/truncation exhaustion, so a configured larger fallback is not selected by that path.

## Solution Assessment

Unclear. A guarded larger-model fallback may be the right end state, but current source and docs intentionally keep overflow inside compaction/retry, so maintainers need to decide the product contract before implementation.
