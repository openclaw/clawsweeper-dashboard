## Summary

Keep open: current main still treats primary-model context overflow as compaction/retry recovery, while the requested cross-model, larger-context fallback needs an explicit replay, candidate-headroom, and session-state contract.

## What This Changes

The issue requests that a configured fallback model with sufficient context capacity be selected when the active model exceeds its context window.

## Best Possible Solution

Keep compaction and oversized-tool-result recovery as the default, then add one guarded fallback handoff only after those paths are exhausted, selecting only candidates with proven sufficient context headroom and preserving replay/session safety.

Options:

- **Add guarded post-recovery fallback (recommended):** After compaction and tool-result truncation are exhausted, retry only eligible configured fallbacks with validated context headroom and explicit replay/session safeguards.

- **Design an opt-in policy first:** Introduce a narrowly scoped future policy only after maintainers define its upgrade, observability, and session-state semantics.

No, not as an unconditional fallback. The safer solution is a maintainer-approved, post-recovery handoff that verifies candidate context capacity and preserves replay and session-state invariants.
