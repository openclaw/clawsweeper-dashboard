## Summary

Keep open: current main still treats context overflow as active-model compaction/retry plus a blocked user-visible overflow result, and both source and docs explicitly exclude context overflow from model fallback. The requested larger-context fallback remains a product/runtime-policy decision because it needs reliable context-window selection and replay-safety guards.

## What This Changes

Request automatic model fallback to a configured larger-context model when the active model exceeds its context window.

## Best Possible Solution

Decide and document the policy; if allowed, implement fallback only after compaction/truncation is exhausted, require larger effective context headroom, preserve replay safety, log the fallback, and add regression coverage.

## Reproduction Assessment

Yes. Source inspection shows configured model fallback exists, but context-overflow throws are rethrown and embedded overflow terminal results stay blocked after compaction/truncation instead of selecting a larger fallback model.

## Solution Assessment

Not applicable to a submitted patch. The best implementation is a guarded post-recovery fallback policy, not unconditional context-overflow fallback on the first error.
