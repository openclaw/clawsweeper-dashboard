## Summary

Keep open: current main and the latest release still treat context overflow as compaction/retry plus a blocked overflow result after recovery is exhausted, while model fallback intentionally rethrows escaped overflow errors instead of trying a larger configured fallback. The direct implementation attempt was closed unmerged, and the remaining work is a provider-routing/session-replay product decision rather than conservative cleanup.

## What This Changes

The issue requests automatic routing from a context-exhausted primary model to a configured fallback model with a larger context window.

## Best Possible Solution

Keep this issue open until maintainers either document context overflow as intentionally compaction-only, or approve a guarded fallback design that runs only after compaction/truncation recovery is exhausted, filters candidates by known sufficient context headroom, preserves replay safety, logs the fallback event, and adds focused regression coverage.

## Reproduction Assessment

Yes at source level, but I did not run a live provider reproduction in this read-only pass. Current main still rethrows context-overflow errors from `runWithModelFallback`, and embedded overflow exhaustion returns a blocked `context_overflow` result instead of trying a larger fallback model.

## Solution Assessment

Unclear until maintainers choose the policy. A direct larger-model fallback is plausible, but the best maintainable version needs explicit replay-safety, context-headroom filtering, and docs/tests because current docs intentionally keep context overflow inside compaction/retry.
