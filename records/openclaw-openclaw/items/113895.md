## Summary

This is a paired issue and open PR from the same author, but it proposes a new Nephesh-specific configuration and output contract in bundled Memory Core; current evidence does not establish that this vendor-specific change belongs in core rather than an external integration.

## What This Changes

Add an opt-in `dreaming.nephesh.enabled` setting that adds machine-readable provenance to newly generated Dream Diary entries for Nephesh ingestion.

## System Context

Memory Core's optional Dreaming flow consolidates workspace memory and writes human-reviewable narratives to `DREAMS.md`. An external memory system can consume those files, so any added provenance format would become part of the Dream Diary output contract and configuration surface.

## Architecture Diagram

flowchart LR
  A[Operator configuration] --> B[Memory Core Dreaming]
  B --> C[Dream Diary generation]
  C --> D[DREAMS.md entries]
  D --> E[External Nephesh ingestion]
  E --> F[Provenance-aware recall]

## Best Possible Solution

Prefer an external Nephesh importer/plugin that classifies `DREAMS.md` as generated dream material; only sponsor core work if maintainers choose a vendor-neutral Dream Diary provenance contract with documented compatibility and ownership.
