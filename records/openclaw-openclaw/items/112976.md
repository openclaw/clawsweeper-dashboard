## Summary

Keep this PR open: current main still excludes `refreshable` entries from the static-authoritative model-list path, so the reported Novita fallback rows remain unavailable there. The narrow patch aligns that consumer with the static-fallback contract introduced by the live-catalog work; likely related people are `fuller-stack-dev` (feature introducer, high confidence) and `steipete` (current assignee, medium confidence).

## What This Changes

This PR makes the model-list and embedded static resolver treat bundled `refreshable` provider manifest rows as static fallback rows, with regression coverage for Novita.

## System Context

Provider plugins publish manifest catalog rows, and the catalog planner classifies them as static, refreshable, or runtime. Model listing, gateway setup, and embedded agent resolution consume the static fallback rows before provider-specific live discovery augments them.

## Best Possible Solution

Keep `refreshable` as live augmentation with bundled static fallback, make both static consumers accept that fallback, preserve runtime-only gating, then merge a rebased head.

Yes. Widening the two static-fallback consumers to include bundled `refreshable` rows is narrower and safer than changing Novita back to static mode, because it preserves the live-discovery contract while retaining runtime-only exclusion.
