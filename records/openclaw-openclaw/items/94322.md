## Summary

This PR remains necessary: current main passes only the host-provided `agentId` to command handlers while separately resolving agent-scoped and main-session keys for LLM authority. The runtime fix is sound, but the prior public-documentation finding remains because the new JSDoc omits main-session alias resolution and the command-author guide still does not describe `ctx.agentId`.

## What This Changes

The PR resolves the invocation’s bound agent once, exposes it as `PluginCommandContext.agentId`, reuses it for command runtime authority, expands the field JSDoc, and adds two resolution-path tests.

## Best Possible Solution

Keep the single resolver-backed implementation and tests, then document `ctx.agentId` in the public command-author SDK surface with all supported resolution modes and its optional absence semantics.
