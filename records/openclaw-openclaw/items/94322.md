## Summary

Keep open for maintainer API judgment: the implementation is narrow and source-backed, but it adds a new public Plugin SDK command-context field that should be accepted and documented before merge.

## What This Changes

The PR adds optional `PluginCommandContext.agentId`, populates it from the existing bound-agent resolver in `executePluginCommand`, and covers agent-scoped plus host-provided resolution paths with tests.

## Best Possible Solution

If maintainers accept the API, land the resolver-backed field with a short command-author docs note; otherwise decline the public context expansion and keep plugins on existing session/runtime surfaces.

## Reproduction Assessment

Not applicable; this is an additive Plugin SDK feature rather than a bug with an established current behavior contract. Source inspection confirms current main resolves agent authority for runtime context but does not expose top-level `ctx.agentId`.

## Solution Assessment

Yes for the code shape if maintainers accept the API: it reuses `resolveBoundAgentIdForSession` and keeps the exposed field aligned with runtime authority. The safer alternative is to decline the public field if maintainers do not want this SDK contract.
