## Summary

Keep open: current main only partially overlaps with this PR, because it has an optional `PluginCommandContext.agentId` field but does not expose the resolver-backed agent id for agent-scoped session keys. The patch shape is correct, but this is still public Plugin SDK surface that needs maintainer API acceptance and a small command-author docs note before merge.

## What This Changes

The PR populates optional `PluginCommandContext.agentId` in `executePluginCommand` from `resolveBoundAgentIdForSession` and adds command tests for agent-scoped and host-provided resolution paths.

## Best Possible Solution

Accept the resolver-backed command-context field only if maintainers want it as public Plugin SDK API, then land it with a short command-author docs note; otherwise decline the field and keep plugins on existing `sessionKey` and runtime APIs.
