## Summary

Keep open: the PR addresses real raw rejection behavior, but the current patch would make object/number rejection details disappear from the supervisor-visible formatted diagnostic, so it needs a narrow adjustment before merge.

## What This Changes

The PR changes ClickClack websocket message handling to reject non-Error async handler failures as an Error with a ClickClack-specific message and cause while preserving existing Error instances.

## Best Possible Solution

Keep the ClickClack gateway boundary fix, but make the wrapped Error's visible message retain the original non-Error value and cover it with a focused gateway regression.

## Reproduction Assessment

Yes from source: current main and v2026.6.11 pass websocket handler failures to `reject` raw, and the PR changes that rejection shape. The downstream regression is also source-reproducible because `server-channels.ts` formats the wrapped Error through `formatErrorMessage`, which does not serialize object/number causes.

## Solution Assessment

No as written: wrapping at the ClickClack gateway boundary is the right owner-local fix, but the current message shape is too lossy for visible diagnostics. A narrow code/test adjustment is better than a broader core or plugin API change.
