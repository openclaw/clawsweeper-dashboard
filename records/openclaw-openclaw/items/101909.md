## What This Changes

The issue requests recovery for Codex app-server Telegram topic sessions where reply-session initialization conflicts can leave tool results silently empty until the user starts a fresh session.

## Best Possible Solution

Define one Codex/session-owned recovery path that verifies the current SQLite binding generation, rebuilds or seeds mirrored history from canonical session state when safe, retries once, and surfaces a visible failure instead of delivering empty tool-result success when recovery is unsafe.
