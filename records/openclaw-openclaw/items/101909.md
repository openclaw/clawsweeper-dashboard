## Label Justifications

- `P1`: The issue reports a live agent/channel workflow where a persistent session wedge silently drops tool-result content until the user starts a fresh session.
- `impact:session-state`: The failure depends on a persistent session key losing its Codex transcript mirror/thread binding and surviving gateway restart.
- `impact:message-loss`: Completed tool executions reach the server but are delivered back to the model as empty content, effectively losing tool-result messages.
- `impact:auth-provider`: The affected path is the Codex/OpenAI app-server harness binding that routes model turns and tool outputs through provider runtime state.
- `maturity:stable`: The affected gateway runtime/session behavior matches the `gateway-runtime` M4 Stable maturity feature.

## Summary

The issue should stay open because current main still has a source-supported path where a reply-session stale-snapshot conflict throws before Codex app-server mirror/thread recovery, while missing Codex mirrored history is treated as empty history rather than a recoverable failure.

## What This Changes

The issue requests recovery for Codex app-server sessions that lose their transcript mirror after a reply-session initialization conflict, causing completed tool results to be delivered as empty content.

## Best Possible Solution

Add a Codex/session-owned recovery path that detects missing mirror or thread binding after reply-session init conflict, clears stale Codex state only when replay-safe, rebuilds or seeds mirror history from canonical session history, retries once, and surfaces a visible failure instead of empty tool-result success if recovery cannot complete.
