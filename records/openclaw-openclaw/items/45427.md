## Summary

Keep open. Current main still deliberately keeps sender names out of the trusted inbound metadata envelope, and the related implementation PRs are unmerged candidates with unresolved security/product tradeoffs rather than replacements for this issue.

## What This Changes

The issue requests a trusted sender display/name field in the inbound metadata envelope so agents do not infer recipients from untrusted conversation context.

## Best Possible Solution

Settle one trusted identity contract first, preferably a stable principal from channel IDs, `session.identityLinks`, or operator-attested provenance, then land a focused implementation with prompt, protocol/channel, and regression-test coverage.
