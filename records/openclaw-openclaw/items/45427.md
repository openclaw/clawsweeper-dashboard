## Summary

Keep open. Current main still keeps sender names out of the trusted inbound metadata envelope, and the related open PRs are conflicting candidate implementations with unresolved security/product tradeoffs rather than landed replacements.

## What This Changes

The issue requests trusted sender-name or equivalent sender-identity metadata in inbound message context so agents do not infer recipient identity from untrusted conversation text.

## Best Possible Solution

Settle one trusted identity contract first, preferably a stable principal from channel IDs, session.identityLinks, or operator-attested provenance, then land one focused implementation with prompt, protocol/channel, and regression-test coverage.
