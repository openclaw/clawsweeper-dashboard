## Summary

Keep open. Current main still keeps human sender identity out of the trusted inbound system metadata and only carries sender name in the user-role untrusted conversation block, while the overlapping implementation candidates are open, unmerged, or only partial.

## What This Changes

The issue requests a trusted, OpenClaw-resolved sender display name in the inbound metadata envelope so agents do not infer human identity from untrusted conversation context.

## Best Possible Solution

Pick one canonical identity contract: prefer a stable configured principal or explicitly attested source actor as trusted metadata, and keep human display names untrusted unless maintainers approve a verified channel/user-directory authority with privacy tests.
