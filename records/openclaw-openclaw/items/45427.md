## Summary

Keep open. Current main and the latest release still keep sender identity out of the trusted inbound system metadata envelope, and the open related implementation candidates need security/product review rather than cleanup closure.

## What This Changes

Requests a trusted, platform-resolved sender name or display identity in inbound metadata so agents do not infer routing identity from untrusted conversation context.

## Best Possible Solution

Keep this as the canonical security/product decision, then land one approved contract that exposes a stable provider ID or configured principal without trusting conversational display names, with prompt, channel, privacy, routing, and regression coverage.
