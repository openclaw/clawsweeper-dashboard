Required: true

Kind: security_boundary

Question: What sender identity authority should OpenClaw expose as trusted inbound metadata: raw resolved display names, stable provider IDs, or configured principals such as session.identityLinks?

Rationale: The current code deliberately keeps human names and per-turn identifiers out of trusted system metadata, so adding model-visible sender identity changes a security and privacy boundary.

Likely owner: steipete

Owner reason: The relevant history ties this person to sender-spoofing hardening and broad channel inbound context ownership near the trusted/untrusted boundary.

Owner confidence: high

Options:

- **Use Configured Principals (recommended):** Expose a trusted principal only when a stable provider ID matches an operator-configured identity link, keeping raw display names in untrusted context.
- **Use Stable Provider IDs:** Expose stable provider IDs as trusted metadata and require agents or tools to resolve human-readable names outside the prompt contract.
- **Use Resolved Display Names:** Expose platform-resolved names directly, accepting a larger privacy and spoofing-review burden for easier agent ergonomics.

## Reproduction Assessment

Yes for the source-level gap: current main excludes sender identity from the trusted system envelope and places sender id/name only in untrusted user context; the production misroute was not live-reproduced.

## Solution Assessment

Unclear: adding raw trusted sender_name is not obviously the safest fix, and maintainers should choose the stable identity authority before implementation.
