## Summary

Keep open. Current main and v2026.6.11 still keep sender identity out of the trusted inbound system metadata envelope, while the overlapping implementation PRs remain open or closed-unmerged and the trusted identity authority still needs maintainer security/product direction.

## What This Changes

The issue requests a trusted sender name or display-name field in the inbound metadata envelope so agents do not infer recipient identity from untrusted conversational context.

## Best Possible Solution

Keep this as the canonical security/product decision, then land one approved contract that exposes a stable provider ID or configured principal without treating conversational display names as trusted metadata.

Rationale: Current code intentionally keeps sender names and per-turn ids out of trusted system metadata, so adding this field changes a security, privacy, and prompt-cache boundary rather than filling a mechanical omission.

Likely owner: Vincent Koc

Owner confidence: high

Options:

- **Configured Principal Contract (recommended):** Expose a trusted principal only when a stable provider ID matches an operator-configured identity link, while keeping display names in untrusted context.
- **Stable Provider ID Contract:** Expose stable channel/provider IDs as trusted metadata and require agents or tools to resolve human-readable labels outside the prompt contract.
- **Display Name Contract:** Expose platform-resolved display names directly, accepting a higher privacy and spoofing-review burden for easier agent ergonomics.

## Reproduction Assessment

Yes for the source-level contract gap: current main and v2026.6.11 exclude trusted sender identity from the system envelope and place sender id/name in untrusted user context. The specific production misroute was not live-reproduced in this read-only review.

## Solution Assessment

Unclear until maintainers choose the trust boundary. A raw trusted display-name field is not the safest default; a configured-principal or stable-provider-ID contract appears safer than trusting human-readable names.
