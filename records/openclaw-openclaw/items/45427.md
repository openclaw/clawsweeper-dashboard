Keep open. Current main and the latest release still keep sender identity out of the trusted inbound metadata envelope, while the related implementation candidates are open or closed-unmerged and do not settle the trusted identity authority contract.

## What This Changes

The issue requests a trusted, platform-resolved sender display/name identity in the inbound metadata envelope so agents do not infer human identity from untrusted conversation context.

## Best Possible Solution

Keep this as the canonical trusted inbound identity decision, then land one maintainer-approved contract that uses stable provider IDs or configured principals rather than raw conversational display names.

## Reproduction Assessment
