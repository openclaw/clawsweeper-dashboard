## Summary

Keep open. Current main and the latest release still keep sender names out of the trusted inbound metadata envelope, while the open candidate PRs only partially cover the identity contract and still need maintainer/security direction.

## What This Changes

Request adding a trusted platform-resolved sender identity, originally described as `sender_name` or `sender_display_name`, to inbound metadata so agents do not infer recipients from untrusted conversation context.

## Best Possible Solution

Define one maintainer-approved trusted sender identity contract, preferably a stable principal or canonical id rather than raw display name, then land a single canonical implementation with docs and focused tests while closing or redirecting overlapping candidates.
