## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Split multiline batch lines before writing:** `extensions/irc/src/client.ts:249`
  - body: The multiline path writes each newline-delimited `content` directly as one tagged `PRIVMSG`. Long URLs or code lines can exceed IRC's per-frame limit, so split long logical lines into IRC-safe frames and use `draft/multiline-concat` when a single logical line must be reassembled.
  - confidence: 0.94
- **[P2] Honor advertised multiline limits:** `extensions/irc/src/client.ts:325-333`
  - body: The CAP handler checks for the `draft/multiline` token but never parses required values such as `max-bytes` or `max-lines`. Servers may reject batches over those limits, so the raised 16384 outbound cap can produce failed deliveries.
  - confidence: 0.9
- **[P2] Preserve concat semantics when rebuilding batches:** `extensions/irc/src/client.ts:462`
  - body: Incoming batch reconstruction joins every buffered message with `\n`. Lines tagged `draft/multiline-concat` should append to the previous line without a separator, so valid long-line splits would be reshaped for OpenClaw.
  - confidence: 0.88
- **[P2] Scope newline-preserving sanitization to messages:** `extensions/irc/src/protocol.ts:147-148`
  - body: `sanitizeIrcOutboundText` now preserves standalone LF for all callers, but NickServ commands, `USER`, and `QUIT` still pass through this helper before `sendRaw` strips newlines. Keep newline-preserving behavior scoped to multiline message bodies so command tokens do not collapse.
  - confidence: 0.8
