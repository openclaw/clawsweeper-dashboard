Full review comments:

- **[P1] Split batched IRC lines before writing:** `extensions/irc/src/client.ts:249`
  - body: The multiline path still writes each logical line as one tagged PRIVMSG. Long URLs or code lines can exceed IRC's per-frame budget and be truncated or rejected; split overlong lines inside the batch and use draft/multiline-concat for continuations.
  - confidence: 0.93
- **[P2] Honor advertised multiline limits:** `extensions/irc/src/client.ts:323-333`
  - body: The CAP handler only checks whether the capability text contains draft/multiline, but servers advertise required max-bytes and may advertise max-lines. Parse and enforce those values before sending batches.
  - confidence: 0.9
- **[P2] Preserve concat semantics when rebuilding batches:** `extensions/irc/src/client.ts:462`
  - body: Joining every buffered batch message with LF corrupts valid draft/multiline-concat splits, where the tagged line must be appended to the previous line without a separator. Parse that tag and rebuild according to the spec.
  - confidence: 0.88
- **[P2] Keep LF preservation local to multiline PRIVMSG sends:** `extensions/irc/src/protocol.ts:147-148`
  - body: sanitizeIrcOutboundText also feeds NickServ, USER, and QUIT commands that later pass through sendRaw. Preserving standalone LF here lets sendRaw remove it without a separator, so flatten non-message callers or use a PRIVMSG-specific sanitizer.
  - confidence: 0.82
