## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Split multiline batch lines before writing:** `extensions/irc/src/client.ts:249`
  - body: The multiline path sends each logical line directly as one tagged `PRIVMSG`. A long URL or code line can exceed IRC frame limits, so split long lines into IRC-safe frames and use `draft/multiline-concat` when a logical line must be reassembled.
  - confidence: 0.93
- **[P2] Honor advertised multiline limits:** `extensions/irc/src/client.ts:332-333`
  - body: The CAP handler only checks whether `accumulatedCaps` contains `draft/multiline` and never parses required capability values like `max-bytes` or `max-lines`. Strict servers can reject batches above those limits once this PR raises the outbound cap to 16384.
  - confidence: 0.9
- **[P2] Preserve concat semantics when rebuilding batches:** `extensions/irc/src/client.ts:462`
  - body: Incoming batch reconstruction joins every buffered line with `\n`. Lines tagged `draft/multiline-concat` should append to previous content without a separator, so valid long-line splits are reshaped.
  - confidence: 0.88
- **[P2] Keep newline preservation out of generic commands:** `extensions/irc/src/protocol.ts:147-148`
  - body: `sanitizeIrcOutboundText` now preserves standalone LF, but NickServ, `USER`, and `QUIT` also pass through this helper before `sendRaw` strips newlines. Those callers still need newline flattening so tokens do not collapse.
  - confidence: 0.8
