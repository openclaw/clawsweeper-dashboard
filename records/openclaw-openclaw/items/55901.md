## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.93

Full review comments:

- **[P1] Split multiline batch payloads to IRC-safe frames:** `extensions/irc/src/client.ts:249`
  - body: `textChunkLimit` is raised to 16384 and the newline-preserving chunker can leave a single markdown/code/URL line far above IRC's per-frame limit, but this loop writes each line as one tagged `PRIVMSG`. A multiline-capable server can still truncate or reject that line; split long logical lines into IRC-safe frames and use `draft/multiline-concat` when the fragments should reconstruct without extra newlines.
  - confidence: 0.94
- **[P2] Parse and enforce advertised multiline limits:** `extensions/irc/src/client.ts:325-326`
  - body: The IRCv3 `draft/multiline` capability carries server limits such as `max-bytes` and optionally `max-lines`, but this code only checks whether the capability text contains `draft/multiline`. Before sending a batch, parse those values and keep each batch within them or fall back to safe plain PRIVMSG splitting; otherwise capable servers can reject the batch.
  - confidence: 0.9
- **[P2] Honor draft/multiline-concat when rebuilding batches:** `extensions/irc/src/client.ts:462`
  - body: Incoming multiline batches are always reconstructed with `join("\n")`, which changes content for lines tagged with `draft/multiline-concat` because those fragments should concatenate directly. Check the tag on each batch PRIVMSG and append without an inserted newline when it is present.
  - confidence: 0.88
- **[P1] Scope newline-preserving sanitization to message bodies:** `extensions/irc/src/protocol.ts:147-148`
  - body: This shared sanitizer is also used for NickServ passwords, register email, USER realname, and QUIT reason, all of which are sent through `sendRaw`; preserving a literal LF there lets `sendRaw` strip it and collapse adjacent tokens. Keep command/auth sanitization flattening CR/LF to spaces and preserve LF only for the PRIVMSG body path that can actually use multiline BATCH.
  - confidence: 0.92
- **[P1] Rebase onto the current IRC outbound base adapter:** `extensions/irc/src/channel.ts:335-340`
  - body: Current main moved IRC outbound defaults into `ircOutboundBaseAdapter`, including `sanitizeText` that strips assistant/tool scaffolding before delivery. This stale branch edits the old inline `outbound.base` object; resolving the conflict by taking the PR side would drop that sanitizer and current seam test coverage, so the multiline chunker/default change needs to be applied to the current adapter instead.
  - confidence: 0.91
