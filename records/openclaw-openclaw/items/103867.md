## Summary

The PR fixes the demonstrated direct text-message replay case, but its HTTP 502 retry policy remains unsafe for three production paths. Sticker and poll creates omit nonce enforcement, while forum/media thread creation has no documented endpoint-level nonce deduplication; green CI does not settle these contract defects.

## What This Changes

The branch adds stable enforced nonces to several Discord message-create payloads and introduces a non-idempotent retry mode that preserves pre-connect, rate-limit, and HTTP 502 retries.

## Best Possible Solution

Use one stable enforced nonce for every direct Create Message retry, including sticker and poll payloads, while restricting forum/media thread creation to retries that are provably pre-connect or rate-limit-safe rather than treating HTTP 502 as nonce-protected.

No. Nonce enforcement is the right boundary for direct Create Message calls, but the patch misses sticker and poll payloads and incorrectly assumes that a nested starter-message nonce makes forum-thread creation idempotent.
