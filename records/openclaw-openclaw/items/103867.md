## Summary

The latest head fixes the prior component-edit blocker and now cleanly separates nonce-protected direct message creates from non-idempotent thread creates. The implementation matches Discord’s endpoint contract, preserves existing idempotent retry behavior, has strong live proof, and no current-main overlap makes the branch obsolete; it should remain open for maintainer landing rather than cleanup.

## What This Changes

Adds one stable enforced nonce per logical Discord Create Message retry series and endpoint-specific retry safety for direct messages versus forum/media thread creation.

## Best Possible Solution

Land the endpoint-scoped design: one stable enforced nonce for each logical direct Create Message, no nonce fields in edit/shared payloads, and pre-connect-only retries for forum/media thread creation, without adding a new config surface.
