## Summary

The patch appears technically correct and fixes two reproduced release-validation failures, but it intentionally changes the release provenance trust boundary and still lacks independently inspectable after-fix behavior proof. The protected `maintainer` label and unsigned-commit policy choice require explicit release-owner review before merge.

## What This Changes

The PR corrects `v*` tag enumeration and allows a missing commit signature only for an exact release-branch head attributable to a uniquely identified merged-PR merger who currently has maintain or admin permission.

## Best Possible Solution

Keep the narrow exact-merge rule, but provide executable or live proof that accepts the real unsigned branch-head candidate and rejects invalid signatures, unsigned tags, non-head commits, wrong branches, ambiguous attribution, and insufficient permission before explicit release-owner approval.
