## Summary

Keep this PR open for maintainer review: the source path and live proof support the bug fix, but merging intentionally changes when configured fallback providers and auth-profile rotation stop after OpenClaw-owned terminal aborts.

## What This Changes

The branch adds terminal-abort classification for run-budget, cron, client-disconnect, and OpenClaw abortable-wrapper failures, then threads that state through model fallback, embedded failover policy, and trajectory metadata.

## Best Possible Solution

Land the PR only after a fallback/provider owner accepts the terminal-versus-retryable abort contract and the wrapper marker boundary while keeping provider-owned timeouts retryable.

## Reproduction Assessment

Yes. Current main source lacks cron string and OpenClaw wrapper-cause terminal detection, and the PR discussion includes live provider proof where current main made fallback calls but the PR head stopped before fallback.

## Solution Assessment

Yes, with maintainer acceptance. The implementation is the narrowest maintainable shape I found because it keeps provider-owned timeouts retryable, uses an OpenClaw-owned abortable marker for internal wrappers, and puts run-budget policy in the existing failover-policy helper.
