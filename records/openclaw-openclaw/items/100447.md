## Summary

Keep open. Current main and v2026.6.11 still have only partial inbound/system-event primitives; the missing piece is a maintainer-approved public external-channel non-message event contract.

## What This Changes

The issue requests a public plugin SDK path for external channel plugins to dispatch or handle inbound non-message events such as reactions, edits, deletes, typing, read receipts, and presence.

## Best Possible Solution

Bless one public path: document system events for reaction/edit/read-receipt style notifications if sufficient, otherwise add a narrow versioned channel event SDK contract with focused docs and contract tests.

## Solution Assessment

Unclear until maintainers choose the public contract. The narrowest path may be documentation around system events, but a new hook, adapter, or dispatch API would be a compatibility-sensitive SDK feature.
