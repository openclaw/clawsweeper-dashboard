## Summary

Keep open. Current main and v2026.6.11 still lack a dedicated public external-channel non-message event hook or `runEvent` path; existing system-event and inbound-runner primitives only partially cover the request, and the related open hook PR is a partial, compatibility-sensitive implementation path rather than a settled contract.

## What This Changes

Request to expose a public Plugin SDK path for external channel plugins to dispatch or handle inbound non-message events such as reactions, edits, read receipts, and presence.

## Best Possible Solution

Bless one public path: document system events and `runChannelInboundEvent` for external channel non-message activity if that is sufficient, otherwise add a narrow versioned SDK event contract with docs, API-baseline updates, and focused channel/plugin tests.
