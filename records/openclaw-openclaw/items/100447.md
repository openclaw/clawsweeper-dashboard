## Summary

Keep open. Current main has channel inbound, event-auth, and system-event primitives, but it still lacks a settled documented external-channel non-message event contract, and the open `inbound_activity` PR only partially covers the requested reaction/read-receipt surface.

## What This Changes

The issue requests a public Plugin SDK/channel contract that lets external channel plugins deliver or handle inbound non-message events such as reactions, edits, read receipts, typing, and presence.

## Best Possible Solution

Bless one public path: document existing system-event plus heartbeat/inbound-runner semantics if sufficient, otherwise add a narrow versioned channel event SDK hook or adapter with docs and contract tests.
