## Summary

Keep open. Current main still lacks a dedicated public external-channel non-message event contract, and the existing inbound runner plus system-event primitives need maintainer API direction before this can become a safe implementation task.

## What This Changes

The issue requests a public Plugin SDK path for external channel plugins to emit or handle inbound non-message events such as reactions, edits, typing, presence, and read receipts.

## Best Possible Solution

Maintainers should bless one public path: document system events for reaction/edit/read-receipt notifications if sufficient, otherwise add a narrow versioned channel event SDK contract with focused docs and contract tests.
