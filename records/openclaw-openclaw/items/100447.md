## Summary

Keep open. Current main exposes partial inbound/system-event primitives and bundled-channel reaction handling, but it does not yet define a supported public external-channel contract for non-message inbound events; the related open PR only partially overlaps and still needs maintainer API direction.

## What This Changes

Request to expose or document a public Plugin SDK path for external channel plugins to dispatch or handle inbound non-message events such as reactions, edits, deletes, typing, presence, and read receipts.

## Best Possible Solution

Maintainers should bless one public path: document system events and existing inbound helpers for non-message channel activity if sufficient, or add a narrow versioned channel event SDK contract with docs, API baseline updates, and focused contract tests.
