## Summary

Keep open. Current main has partial primitives for raw channel inbound events and system events, but it still lacks a blessed public external-channel non-message event contract, and the related inbound_activity PR is open, conflicting, and only partially overlaps the requested SDK direction.

## What This Changes

The issue requests a public plugin-SDK path for external channel plugins to emit or handle inbound non-message events such as reactions, edits, deletes, typing, presence, and read receipts.

## Best Possible Solution

Bless one public path: document system events for reaction/edit/read-receipt style notifications if sufficient, otherwise add a narrow versioned channel event SDK contract with focused docs and contract tests.
