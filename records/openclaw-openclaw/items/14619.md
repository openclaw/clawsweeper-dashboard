## Summary

Keep open. Current main still renders human-readable Tooling text from effective tool names while also sending callable tool schemas, and there is still no scoped skipToolListText/toolListText config option; the broader open token-overhead tracker overlaps but does not supersede this narrower prompt-text request.

## What This Changes

Request to add an opt-in agent/default setting that omits the human-readable Tooling list from the system prompt while preserving callable tool schemas.

## Best Possible Solution

Decide the product direction, then either add a narrow opt-in prompt-surface setting that suppresses only the Tooling list while preserving customTools, diagnostics, docs, and tests, or explicitly route users to Tool Search/localModelLean as the supported token-pressure path.

## Reproduction Assessment

Yes. Source inspection shows toolNames are rendered into Tooling prompt text and the same effective tools are registered as callable customTools; no live agent turn was run because this review is read-only.

## Solution Assessment

Unclear. The scoped option is plausible, but OpenClaw's config-surface bar is high and Tool Search/localModelLean cover adjacent token-pressure cases without solving this exact prompt-text duplication.
