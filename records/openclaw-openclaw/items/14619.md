## Summary

Keep open. Current main and v2026.6.11 still render the human-readable Tooling list while separately registering callable tool schemas, no scoped skipToolListText/toolListText config exists, and the related open tool-overhead issues overlap without superseding this narrower request.

## What This Changes

The issue requests a scoped agent/default option to omit the human-readable tool list from the system prompt while keeping callable tool schemas available.

## Best Possible Solution

Decide product direction, then either add a narrow opt-in prompt-surface setting that suppresses only the Tooling list while preserving customTools, context diagnostics, docs, and tests, or explicitly route users to Tool Search/code-mode/localModelLean as the supported token-pressure path.

## Reproduction Assessment

Yes. Source inspection on current main shows effective tool names are rendered into Tooling prompt text and the same effective tools are registered as callable customTools; no live agent turn was run because this review is read-only.

## Solution Assessment

Unclear. The scoped config option is a plausible narrow solution, but OpenClaw's config-surface bar is high and existing Tool Search/code-mode/localModelLean cover adjacent token-pressure cases without solving this exact direct-schema prompt-text duplication.
