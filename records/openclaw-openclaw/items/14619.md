## Summary

This issue should stay open because current main still renders the human-readable Tooling section while separately passing callable tool schemas, and the requested scoped suppression option does not exist. The remaining decision is product/config design rather than a strict bug fix, so it should stay in maintainer review rather than an automated fix lane.

## What This Changes

The issue requests an agent-default option to omit the human-readable tool list from the system prompt while continuing to send tool schemas for function calling.

## Best Possible Solution

Add a scoped, documented opt-in agent prompt option only after maintainers confirm the config surface and default behavior, with tests proving Tooling list text is omitted while customTools remain callable.

## Reproduction Assessment

Yes. Source inspection shows toolNames are rendered into Tooling prompt text and the same effective tools are registered as callable customTools; no live agent turn was run because this review is read-only.

## Solution Assessment

Unclear. A scoped option like agents.defaults.skipToolListText is plausible, but OpenClaw's config-surface bar is high and existing Tool Search/localModelLean paths address adjacent token pressure without solving this exact prompt-text duplication.
