## Summary

Keep open. Current main still renders a human-readable Tooling list from effective tool names, still passes callable tool schemas separately as custom tools, and still has no scoped option to suppress only the prompt text.

## What This Changes

The issue requests an agent/default config option to omit the human-readable Tooling list from the system prompt while preserving callable tool schemas.

## Best Possible Solution

Decide the product direction, then either add a narrow opt-in prompt-surface setting that suppresses only the Tooling list while preserving customTools, diagnostics, docs, and tests, or explicitly document Tool Search/localModelLean as the supported token-pressure path.

## Reproduction Assessment

Yes. Source inspection shows effective tool names are rendered into Tooling prompt text while the same effective tools are registered as callable customTools; no live agent turn was run because this review is read-only.

## Solution Assessment

Unclear. The scoped option is plausible, but OpenClaw's config-surface bar is high and existing Tool Search/localModelLean cover adjacent token-pressure cases without solving this exact prompt-text duplication.
