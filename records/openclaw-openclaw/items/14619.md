## Summary

Keep open. Current main still renders the human-readable Tooling list from effective tool names while also passing callable tool schemas as custom tools, and no scoped skipToolListText/toolListText config exists. Tool Search and localModelLean are adjacent token-pressure paths, but they do not implement this narrower prompt-text-only option.

## What This Changes

The issue requests a scoped agent/default option to omit the human-readable tool list from the system prompt while preserving callable tool schemas.

## Best Possible Solution

Decide the product direction, then either add a narrow opt-in prompt-surface setting that suppresses only the Tooling list while preserving customTools, diagnostics, docs, and tests, or explicitly route users to Tool Search/localModelLean as the supported token-pressure path.

## Reproduction Assessment

Yes. Source inspection shows toolNames are rendered into Tooling prompt text and the same effective tools are registered as callable customTools; no live agent turn was run because this review is read-only.

## Solution Assessment

Unclear. The proposed scoped option is plausible, but OpenClaw's config-surface bar is high and existing Tool Search/localModelLean cover adjacent token-pressure cases without solving this exact prompt-text duplication.
