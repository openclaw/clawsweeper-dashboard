## What This Changes

Request to add an opt-in agent/default config setting that suppresses the human-readable Tooling list while preserving callable tool schemas.

## Best Possible Solution

Maintainers should decide the prompt/config direction; if accepted, add a narrow opt-in setting that omits only the human-readable Tooling list while preserving customTools, Tool Search/code-mode behavior, context reporting, docs, and focused tests.

## Reproduction Assessment

Yes, source inspection is enough to reproduce the central behavior: current main builds Tooling toolLines from effective tools and still registers those tools separately as customTools. I did not run a live agent turn because this review is read-only.

## Solution Assessment

Unclear. A narrow opt-in skip setting would solve the reported duplication, but maintainers should first decide whether that new config surface is preferable to existing Tool Search, code-mode, localModelLean, and tool-policy controls.
