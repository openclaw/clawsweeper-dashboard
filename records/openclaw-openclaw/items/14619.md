## Summary

Keep open. Current main and v2026.6.11 still render the human-readable Tooling list while separately registering callable tool schemas, and no scoped `skipToolListText` or `toolListText` config exists; related issues overlap but do not supersede this narrower request.

## What This Changes

The issue requests a scoped option to omit the human-readable tool list from the system prompt while keeping callable tool schemas available.

## Best Possible Solution

Decide product direction, then either add a narrow opt-in prompt-surface setting that suppresses only the Tooling list while preserving `customTools`, diagnostics, docs, and tests, or explicitly route users to existing lean/tool-search/code-mode paths as the supported token-pressure solution.

## Reproduction Assessment

Yes. Source inspection on current main shows effective tool names are rendered into Tooling prompt text and the same effective tools are registered separately as callable `customTools`; no live agent turn was run because this review is read-only.

## Solution Assessment

Unclear. The scoped config option is a plausible narrow solution, but OpenClaw's config-surface bar is high and existing Tool Search/code-mode/localModelLean cover adjacent token-pressure cases without solving this exact direct-schema prompt-text duplication.
