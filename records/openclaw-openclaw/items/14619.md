## Summary

Keep open: current main still renders the human-readable Tooling list while separately registering callable tool schemas, and neither current config nor the latest release exposes a scoped skipToolListText/toolListText option. Existing Tool Search and localModelLean work reduce adjacent token pressure but do not satisfy this narrower prompt-text request.

## What This Changes

Request an opt-in agent/default setting to omit the human-readable Tooling list from the system prompt while keeping tool schemas callable.

## Best Possible Solution

Maintainers should decide whether to accept a scoped opt-in prompt-surface setting; if accepted, implement it across prompt construction, config schema/types/help/docs, context reporting, and tests while preserving customTools.

## Reproduction Assessment

Yes for a source-level current-behavior check: effective tool names are rendered into Tooling prompt text while the same effective tools are registered separately as customTools. I did not run a live agent turn because this review is read-only.

## Solution Assessment

Unclear: the proposed scoped config option is plausible, but OpenClaw's config-surface bar is high and existing Tool Search/localModelLean paths cover adjacent token-pressure cases without solving this exact duplication.
