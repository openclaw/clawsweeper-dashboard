## Summary

Keep open. Current main and the latest release still emit the human-readable Tooling list while also sending callable tool schemas, and there is still no scoped skipToolListText-style config option; the broader token-overhead tracker overlaps but does not clearly replace this narrower request.

## What This Changes

Requests an opt-in agent/default config option to omit the human-readable Tooling/tool-list text from the system prompt while keeping callable tool schemas available.

## Best Possible Solution

Adopt a maintainer-approved prompt policy that suppresses only the human-readable Tooling list when configured, preserves callable tool schemas and diagnostics, and either links or folds the work into https://github.com/openclaw/openclaw/issues/14785 if maintainers make that tracker canonical.

## Reproduction Assessment

Yes for the current behavior: source inspection shows Tooling list text is still emitted from toolLines and tool schemas are still sent separately as customTools. This is a feature request rather than a broken existing contract, so no failing runtime reproduction was needed.

## Solution Assessment

Unclear whether the proposed standalone config option is the best final shape. Existing Tool Search and localModelLean are partial mitigations, but a scoped Tooling-list suppression still needs maintainer approval against the config-surface bar and the broader token-overhead tracker.
