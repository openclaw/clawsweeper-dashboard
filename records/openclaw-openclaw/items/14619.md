## Summary

Keep open. Current main and the latest release still render Tooling prompt text from effective tool names while separately registering callable custom tool schemas, and there is still no scoped config option to suppress only that prompt text; related Tool Search, code mode, and local-model lean paths are useful alternatives but do not fully cover this request.

## What This Changes

The issue requests a scoped agent/default option to omit the human-readable Tooling list from the system prompt while preserving callable tool schemas.

## Best Possible Solution

Decide product direction first, then either add a narrow opt-in prompt-surface setting that suppresses only the Tooling list while preserving customTools, docs, context diagnostics, and tests, or document Tool Search/code-mode/localModelLean as the supported token-pressure path.

## Reproduction Assessment

Yes. Source inspection on current main shows effective tools are rendered into Tooling prompt text and the same effective tools are registered as callable customTools; no live run was needed for that source-level reproduction.

## Solution Assessment

Unclear. A scoped config option is a plausible narrow solution, but OpenClaw's config-surface bar is high and maintainers need to choose whether this should be a new prompt knob or be covered by Tool Search/code-mode/localModelLean.
