## Summary

Keep open. Current main and latest release still emit human-readable Tooling text from effective tool names while separately registering callable tool schemas, and there is no scoped skipToolListText/toolListText config; Tool Search and localModelLean reduce adjacent overhead but do not provide this targeted opt-out.

## What This Changes

Request an opt-in agent/default setting to omit the human-readable Tooling list from the system prompt while preserving callable tool schemas.

## Best Possible Solution

Make a maintainer product decision, then either decline a new prompt knob in favor of existing tool-scope surfaces or add a narrow opt-in setting that suppresses only the human-readable Tooling list while preserving customTools, Tool Search/code-mode behavior, context reporting, docs, config schema/help, and focused tests.

## Reproduction Assessment

Yes. Source inspection on current main shows buildAgentSystemPrompt still emits Tooling toolLines while the embedded runner separately registers the same effective tools as customTools; no live token measurement was run.

## Solution Assessment

Unclear. A narrow opt-in skip setting would solve the reported duplication, but maintainers first need to compare it with existing Tool Search, code mode, localModelLean, and stable tool-scope controls before adding another prompt/config contract.
