## Summary

Keep open. Current main and v2026.6.11 still emit human-readable Tooling text from effective tool names while separately registering callable tool schemas, and no scoped skipToolListText/toolListText config exists; Tool Search and localModelLean reduce broader tool pressure but do not replace this narrower request.

## What This Changes

Request to add an agent/default option that suppresses the human-readable Tooling tool list in the system prompt while still sending callable tool schemas.

## Best Possible Solution

Make a maintainer product decision, then either decline a new prompt knob in favor of existing tool-surface controls or add a narrow opt-in setting that suppresses only the human-readable Tooling list while preserving schemas, Tool Search/code-mode behavior, context reporting, docs, and focused tests.

## Reproduction Assessment

Yes. Source inspection on current main shows buildAgentSystemPrompt still emits toolLines under ## Tooling while the embedded runner separately registers the same effective tools as customTools; no runtime test was run because this review is read-only.

## Solution Assessment

Unclear. A narrow opt-in skip setting would solve the reported duplication, but maintainers should first compare it with Tool Search, code-mode, localModelLean, stable tool allow/deny controls, and the current reporting drift around tools.listChars.
