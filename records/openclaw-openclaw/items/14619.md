## Summary

Keep open. Current main still renders effective tool names and summaries into the Tooling prompt section while also sending callable tool schemas separately, and the requested scoped skipToolListText/toolListText config surface does not exist; the broader token-overhead tracker overlaps but does not replace this narrower prompt-text request.

## What This Changes

The issue requests a scoped option to suppress the human-readable tool list in the agent system prompt while continuing to send callable tool schemas.

## Best Possible Solution

Decide the product direction, then either add a narrow opt-in prompt-surface setting that suppresses only the per-tool Tooling list while preserving customTools, diagnostics, docs, and tests, or explicitly route users to Tool Search/localModelLean as the supported token-pressure path.

## Reproduction Assessment

Yes for the current behavior: source inspection shows effective tool names are rendered into Tooling prompt text and the same effective tools are registered as callable customTools. I did not run a live agent turn because this is a read-only review.

## Solution Assessment

Unclear: the proposed scoped config option is plausible, but OpenClaw's config-surface bar is high and existing Tool Search/localModelLean cover adjacent token-pressure cases without solving this exact prompt-text duplication.
