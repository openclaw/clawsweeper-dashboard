## Summary

Keep open. Current main still emits the human-readable Tooling list from effective tool names, still sends callable tool definitions separately, and still has no scoped skipToolListText/toolListText config surface; the related broader tracker overlaps but does not replace this narrower prompt-text request.

## What This Changes

Request to add a scoped agent/default option that suppresses the human-readable Tooling list in the system prompt while preserving callable tool schemas.

## Best Possible Solution

Decide the product direction, then either add a narrow opt-in prompt-surface setting that omits only the Tooling list while preserving customTools, diagnostics, docs, and tests, or explicitly document Tool Search/localModelLean as the supported token-pressure path.

## Reproduction Assessment

Yes for the current behavior: source inspection shows toolNames are rendered into Tooling prompt text and the same effective tools are registered as callable customTools. I did not run a live agent turn because this was a read-only review.

## Solution Assessment

Unclear: the proposed scoped config option is plausible, but OpenClaw's config-surface bar is high and existing Tool Search/localModelLean cover adjacent token-pressure cases without solving this exact prompt-text duplication.
