## Summary

Keep open. Current main and the latest release still render the human-readable Tooling list from active tool names while separately registering callable tool schemas, and no scoped skipToolListText/toolListText config exists; related token-optimization work does not replace this narrower request.

## What This Changes

Request to add an opt-in agent/default setting that omits the human-readable Tooling list from the system prompt while still sending callable tool schemas.

## Best Possible Solution

Make a maintainer product decision, then either decline a new prompt knob in favor of existing tool-surface controls or add a narrow opt-in setting that suppresses only Tooling text while preserving customTools, docs, context reporting, and focused tests.

## Reproduction Assessment

Yes. Source inspection on current main shows the prompt builder still emits Tooling text from effective tool names while the embedded runner separately registers tool definitions as customTools; no runtime test was run because this review was read-only.

## Solution Assessment

Unclear. A narrow opt-in skip setting would solve the reported duplication, but maintainers still need to compare it against existing Tool Search, code mode, localModelLean, and stable tool policy controls before accepting a new config contract.
