## Summary

Keep open. Current main and the latest release still emit the human-readable Tooling list from effective tool names while separately registering callable tool schemas, and no scoped skipToolListText/toolListText config exists; adjacent Tool Search/localModelLean work reduces broader schema pressure but does not replace this narrower request.

## What This Changes

The issue requests a scoped agent/default option to omit the human-readable tool list from the generated system prompt while still sending callable tool schemas.

## Best Possible Solution

Make a maintainer product decision, then either decline a new prompt knob in favor of existing tool-surface controls or add a narrow opt-in setting that suppresses only the human-readable Tooling list while preserving customTools, Tool Search/code-mode behavior, context reporting, docs, and focused tests.

## Reproduction Assessment

Yes. Source inspection on current main shows buildAgentSystemPrompt still builds and emits toolLines from effective tool names while the embedded runner separately registers those tools as customTools; no runtime test was run because this was read-only review.

## Solution Assessment

Unclear. A narrow opt-in skip setting would solve the reported duplication, but it is not automatically the best fix until maintainers compare it with existing Tool Search, code-mode, localModelLean, stable tool allow/deny controls, and the reporting drift around tools.listChars.
