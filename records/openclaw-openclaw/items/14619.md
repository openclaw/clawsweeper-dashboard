## Summary

Keep open. Current main still emits human-readable Tooling prompt text from effective tool names while also registering callable tool schemas, and no scoped skipToolListText/toolListText config option exists; adjacent Tool Search, code mode, and localModelLean paths reduce other tool-surface costs but do not implement this narrower request.

## What This Changes

The issue requests an agent/default config option to omit the human-readable tool list from the system prompt while keeping function-call tool schemas available.

## Best Possible Solution

Make a maintainer product decision, then either reject another prompt knob in favor of existing tool-surface controls or add a narrow opt-in setting that suppresses only the human-readable Tooling list while preserving customTools, Tool Search/code-mode behavior, context reporting, docs, and focused tests.

## Reproduction Assessment

Yes. Source inspection on current main shows buildAgentSystemPrompt still builds and emits toolLines from effective tool names while the embedded runner still registers those tools as customTools.

## Solution Assessment

Unclear. A narrow opt-in skip setting would solve the reported duplication, but it is not automatically the best fix until maintainers compare it with existing Tool Search, code mode, localModelLean, tools.allow, and tools.deny controls.
