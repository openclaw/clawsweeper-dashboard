## Summary

Keep open: current main still renders the human-readable Tooling list from effective tool names, still sends callable tool definitions separately, and still has no scoped skipToolListText/toolListText config option. Existing Tool Search and localModelLean work reduce adjacent token pressure but do not satisfy this narrower request.

## What This Changes

Request a config option to omit the human-readable Tooling list from the generated system prompt while preserving API tool schemas for function calling.

## Best Possible Solution

Decide the product direction, then either add a narrow opt-in prompt-surface setting that suppresses only Tooling-list text while preserving callable schemas, diagnostics, docs, and tests, or explicitly make Tool Search/localModelLean the supported token-pressure path.

## Reproduction Assessment

Yes for the current behavior: source inspection shows effective tool names are rendered into Tooling prompt text while the same effective tools are registered separately as customTools. I did not run a live agent turn because this review is read-only.

## Solution Assessment

Unclear: the proposed scoped config option is plausible, but OpenClaw's config-surface bar is high and existing Tool Search/localModelLean cover adjacent token-pressure cases without solving this exact prompt-text duplication.
