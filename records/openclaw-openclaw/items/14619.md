## Summary

Keep open. Current main still renders the human-readable Tooling list from effective tool names while also registering callable tool schemas separately, and no scoped skipToolListText/toolListText config exists; this remains a product/config decision rather than a cleanup close.

## What This Changes

The issue requests an opt-in agent/default setting that omits the human-readable Tooling tool list from system prompts while keeping callable tool schemas available.

## Best Possible Solution

Maintainers should decide whether to support a narrow opt-in prompt-surface setting; if accepted, implement it through prompt construction, config schema/help/docs, context reporting, and focused tests while preserving customTools.

## Reproduction Assessment

Yes. Source inspection shows effective tool names are rendered into the Tooling prompt text and the same effective tools are registered as callable customTools; no live agent turn was run because this review is read-only.

## Solution Assessment

Unclear. A scoped option is plausible, but OpenClaw's config-surface bar is high and existing Tool Search/localModelLean cover adjacent token-pressure cases without solving this exact prompt-text duplication.
