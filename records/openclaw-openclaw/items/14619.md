## Summary

Keep open. Current main and the latest release still render the human-readable Tooling list from effective tool names while separately registering callable tool schemas, and existing Tool Search/localModelLean surfaces do not provide this exact opt-in suppression; adding a new prompt/config contract still needs maintainer product approval.

## What This Changes

Requests a scoped agent config option to omit the human-readable Tooling list from the system prompt while continuing to send callable tool schemas.

## Best Possible Solution

Make a maintainer product decision, then either decline a new prompt knob in favor of existing tool-surface controls or add a narrow opt-in setting that suppresses only the human-readable Tooling list while preserving customTools, context reporting, docs, and focused tests.

## Reproduction Assessment

Yes. Source inspection on current main shows buildAgentSystemPrompt still emits toolLines under ## Tooling while the embedded runner separately registers effective tools as customTools; no runtime test was run because this was a read-only review.

## Solution Assessment

Unclear. A narrow opt-in skip setting would solve the reported duplication, but maintainers should first decide whether this new config contract is better than existing Tool Search, code-mode, localModelLean, and tool policy controls.
