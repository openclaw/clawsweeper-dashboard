## Summary

The core fix is well targeted and now has credible exact-head live bridge proof, but the claimed authoritative projection remains incomplete: when history omits `destination_caller_id`, the repaired payload retains the stale notification value. Because downstream self-chat and reflection decisions consume that routing diagnostic, one narrow correction is required before merge.

## What This Changes

Rebuilds anchorless iMessage sender, direction, and conversation metadata from exact-GUID history, rejects incomplete or conflicting recovery projections, suppresses recovered outgoing rows, and adds helper and monitor-path regression tests.

## Best Possible Solution

Make the history projection truly authoritative by replacing or clearing `destination_caller_id` when the exact-GUID row omits it, update the nullable-field regression to assert absence, and retain the existing sender, direction, conflict, group, and live-proof coverage.
