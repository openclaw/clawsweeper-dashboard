## Summary

Keep open: the reported plugin-tool symptom is plausible, but this patch broadens partial registry matching in the shared loaded-registry helper instead of scoping it to tool discovery, and the contributor has not provided real behavior proof.

## What This Changes

The PR adds an optional all/any match mode to `registryContainsRuntimePluginIds`, switches `getLoadedRuntimePluginRegistry` surface reuse to `any`, and adds a unit test for partial plugin-id overlap.

## Best Possible Solution

Keep the shared loaded-registry check strict by default and make partial-overlap reuse a narrowly documented tool-discovery behavior with sibling-surface regression coverage.

## Reproduction Assessment

Yes at source level: current code still has a strict shared registry helper and the PR changes it globally, while prior reports show the plugin-tool symptom family. I did not run a live runtime repro because this review is read-only and tests would write artifacts.

## Solution Assessment

No. The requested symptom should be solved at the tool-discovery resolver boundary or by filtering required tool plugin ids, not by changing the shared loaded-registry contract for every caller.
