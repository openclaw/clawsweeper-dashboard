Full review comments:

- **[P2] Make cache fingerprint reads asynchronous:** `src/agents/cli-credentials.ts:248`
  - body: The async cache helper still calls `readSourceFingerprint` synchronously on both sides of the awaited read. Callers backed by filesystem metadata therefore continue blocking the event loop; make the callback promise-based and await it throughout the async path.
  - confidence: 0.99
- **[P2] Coalesce concurrent credential cache misses:** `src/agents/cli-credentials.ts:261`
  - body: Every caller that observes an expired cache immediately starts its own credential read. Concurrent agent starts can therefore launch duplicate Keychain subprocesses or prompts; retain one in-flight promise per cache key and share it until completion.
  - confidence: 0.99
- **[P2] Use a child-process API that closes stdin:** `src/agents/cli-credentials.ts:12`
  - body: `promisify(exec)` leaves a piped stdin stream, and passing `stdio` here does not provide the explicit closed-stdin lifecycle this path requires. Use `spawn` or `execFile` with stdin ignored so a child cannot wait for input until the timeout.
  - confidence: 0.97
- **[P2] Make the configured Windows shell path asynchronous:** `src/agents/sessions/resolve-config-value.ts:149`
  - body: The Windows branch still calls the synchronous `executeWithConfiguredShell` helper before its async fallback. A configured shell command can therefore continue blocking the gateway; add and await an asynchronous configured-shell implementation.
  - confidence: 0.99
