## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.95

Full review comments:

- **[P1] Remove the unsupported stdio option from exec:** `src/agents/sessions/resolve-config-value.ts:136`
  - body: The promisified `child_process.exec` call is passed `stdio`, but Node's `ExecOptions` does not define that property. Vitest transpilation does not type-check this, so the repository's tsgo/build gate will reject the new helper; remove the option and rely on exec's piped stdout/stderr behavior.
  - confidence: 0.98
- **[P1] Coalesce concurrent credential cache misses:** `src/agents/cli-credentials.ts:259`
  - body: Every caller that reaches an expired cache independently executes `await read()` before any result is cached. Concurrent agent starts can therefore launch several Keychain commands or prompts at once, worsening the exact availability failure this PR targets; store and share an in-flight promise per cache key.
  - confidence: 0.96
- **[P2] Remove synchronous work from the async cache path:** `src/agents/cli-credentials.ts:249`
  - body: The async cache helper still evaluates a synchronous source fingerprint before and after the read, and its credential readers retain synchronous path/stat/metadata helpers. Those operations still block the Gateway event loop; convert the complete fingerprint and fallback-file chain to promises rather than only the final read.
  - confidence: 0.94
- **[P2] Make the configured Windows shell path asynchronous:** `src/agents/sessions/resolve-config-value.ts:150`
  - body: The Windows branch calls `executeWithConfiguredShell` synchronously before falling back to `executeWithDefaultShellAsync`. A configured-shell secret command can therefore still block the event loop on Windows; add an async configured-shell implementation and await it here.
  - confidence: 0.99
- **[P2] Migrate the remaining command-value callers:** `src/agents/sessions/resolve-config-value.ts:173`
  - body: Adding `resolveConfigValueAsync` and switching only `AuthStorage.getApiKey` leaves model/config command callers on the synchronous resolver. Those callers can still run `!command` secrets on the Gateway thread, so migrate all async-capable hot-path callers before presenting this as the credential-path fix.
  - confidence: 0.91
