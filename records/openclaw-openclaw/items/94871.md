## Summary

The event-loop regression remains relevant on current main, but this PR is not merge-ready: important Gateway callers still use synchronous credential/config resolution, the new async paths retain blocking operations and lack concurrent-read deduplication, and proof is limited to mocked tests. Likely related people are @baghvn, who authored the earlier async-Keychain attempt, and @steipete, based on recent adjacent auth/secrets work.

## What This Changes

Adds asynchronous credential-cache and config-value resolvers, awaits them from selected CLI auth-epoch and auth-storage paths, and changes one locked auth-file read to promise-based filesystem I/O.

## Best Possible Solution

Use one fully asynchronous credential-resolution boundary with async path/stat/file operations, per-key in-flight deduplication, and no synchronous configured-shell or runtime caller fallback; then prove unchanged auth semantics and improved liveness with a redacted concurrent macOS Keychain/Gateway run.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Migrate external credential overlays to async readers:** `src/agents/cli-credentials.ts:234`
  - body: The patch adds async readers and switches the auth-epoch path, but the runtime auth-profile external-CLI overlay still uses the synchronous exports. That loader can therefore continue invoking `security` through `execSync` during Gateway auth loading or prewarm. Convert the overlay/store path to await the async readers before treating the event-loop regression as fixed.
  - confidence: 0.86
- **[P2] Deduplicate concurrent async credential reads:** `src/agents/cli-credentials.ts:259`
  - body: Cache misses are not coalesced: every concurrent caller reaches `await read()` before a completed value is stored. Concurrent agent starts can therefore launch multiple Keychain commands at once, causing duplicate prompts, load, and unstable auth timing. Keep one in-flight promise per cache key and clear it after settlement.
  - confidence: 0.91
- **[P2] Remove synchronous filesystem work from async readers:** `src/agents/cli-credentials.ts:248`
  - body: The async cache still calls `readSourceFingerprint` synchronously twice, and the Codex path retains synchronous realpath/stat helpers for path and fallback-expiry resolution. Slow or remote home directories can continue blocking the Gateway event loop. Convert the complete file, path, and fingerprint chain to promise-based I/O.
  - confidence: 0.95
- **[P2] Route model configuration through the async resolver:** `src/agents/sessions/resolve-config-value.ts:174`
  - body: Adding `resolveConfigValueAsync` and using it in `AuthStorage.getApiKey` does not migrate the existing model configuration and status callers that still invoke the synchronous resolver. Command-backed credential values can therefore continue blocking those Gateway-facing auth flows; migrate the runtime callers or centralize resolution behind the async API.
  - confidence: 0.84
- **[P2] Make the configured Windows shell path asynchronous:** `src/agents/sessions/resolve-config-value.ts:153`
  - body: On Windows the new async resolver calls `executeWithConfiguredShell`, which uses the existing synchronous shell execution path, before its async fallback. A configured-shell command can still block the event loop for the full timeout; provide and await an asynchronous configured-shell implementation.
  - confidence: 0.98
