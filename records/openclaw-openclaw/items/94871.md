Full review comments:

- **[P1] Preserve the Codex API-key-mode guard:** `src/agents/cli-credentials.ts:778-779`
  - body: The async Codex auth.json reader skips the existing `codexAuthJsonUsesChatGptTokens` check before reading `tokens`. If this async path becomes the replacement, an API-key-mode Codex auth.json with stale tokens can be treated as OAuth credentials, changing provider auth behavior.
  - confidence: 0.9
- **[P1] Use async readers on the default auth-epoch path:** `src/agents/cli-auth-epoch.ts:184-195`
  - body: With production deps, `hasAsyncDepOverride` is false, so the new async auth-epoch function still calls the synchronous cached readers. The normal runtime path should await the async reader and reserve sync fallback only for sync-only test overrides.
  - confidence: 0.92
- **[P1] Wire external CLI overlays to async readers:** `src/agents/cli-credentials.ts:837-863`
  - body: The PR adds async cached readers, but the external CLI OAuth bootstrap/fallback overlay still calls the synchronous Claude and Codex cached readers. Gateway auth recovery can therefore still hit sync keychain or file I/O after this patch.
  - confidence: 0.88
- **[P2] Remove sync file work from async credential readers:** `src/agents/cli-credentials.ts:617`
  - body: `readClaudeCliCredentialsAsync` still falls back to `loadJsonFile`, and the Codex async reader still uses sync JSON/stat helpers. File-backed credentials can still block the event loop when keychain is unavailable or disabled.
  - confidence: 0.86
- **[P2] Make Windows configured-shell execution async:** `src/agents/sessions/resolve-config-value.ts:151-154`
  - body: The async config resolver still calls `executeWithConfiguredShell` on Windows, and that helper uses `spawnSync`. A command-backed API key or header can still block on the new async path.
  - confidence: 0.82
- **[P2] Route model config commands through async helpers:** `src/agents/sessions/resolve-config-value.ts:193-220`
  - body: The PR adds async config helpers but leaves model-registry provider API keys and headers on the synchronous `resolveConfigValueOrThrow` and `resolveHeadersOrThrow` calls. Custom provider `!command` secrets can still block during model resolution.
  - confidence: 0.84
