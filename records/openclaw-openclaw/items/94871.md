- **[P1] Route external CLI overlays through async readers:** `src/agents/cli-auth-epoch.ts:199-205`
  - body: The new async fingerprint helper does not migrate the external Claude/Codex credential overlay used while loading the runtime auth store. That overlay can still invoke synchronous credential readers during provider-auth prewarm, leaving the primary reported Gateway stall reachable.
  - confidence: 0.91
- **[P2] Make async cache fingerprinting nonblocking:** `src/agents/cli-credentials.ts:247`
  - body: `readCachedCliCredentialAsync` still invokes `readSourceFingerprint` synchronously before and after the awaited read. The file-backed callers use synchronous metadata checks, so cache validation can continue blocking the event loop even when the credential read itself is async.
  - confidence: 0.88
- **[P2] Use async configured-shell execution on Windows:** `src/agents/sessions/resolve-config-value.ts:151-154`
  - body: The Windows branch still calls `executeWithConfiguredShell`, which uses the existing synchronous process path. Config values beginning with `!` therefore continue blocking on Windows despite being routed through `resolveConfigValueAsync`.
  - confidence: 0.99
- **[P2] Migrate remaining model and config callers:** `src/agents/sessions/resolve-config-value.ts:176-182`
  - body: Adding `resolveConfigValueAsync` and using it from `AuthStorage.getApiKey` leaves model/config command surfaces on the synchronous resolver. Those Gateway-adjacent callers remain capable of blocking when a configured key or header executes a shell command.
  - confidence: 0.84
