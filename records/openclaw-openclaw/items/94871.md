- **[P2] Await source fingerprint reads:** `src/agents/cli-credentials.ts:250`
  - body: The async cache helper still invokes `readSourceFingerprint` synchronously before and after every miss. Because the credential readers use filesystem metadata for these fingerprints, this leaves blocking filesystem work in the path the PR promises to make non-blocking; make the callback asynchronous and await it.
  - confidence: 0.97
- **[P2] Coalesce concurrent credential cache misses:** `src/agents/cli-credentials.ts:263`
  - body: A miss directly starts `read()` with no per-key in-flight promise. Concurrent agent starts can therefore launch several identical Keychain commands, increasing prompts and event-loop/process pressure; share one pending read per cache key and clear it after settlement.
  - confidence: 0.96
- **[P2] Use a child-process API that closes stdin:** `src/agents/sessions/resolve-config-value.ts:136-139`
  - body: `child_process.exec` does not support the supplied `stdio` option, so this does not establish the intended ignored-stdin lifecycle. Use `execFile` or `spawn` with explicit pipes and `stdin: ignore`/closure so command-backed credential resolution cannot wait for input.
  - confidence: 0.95
- **[P2] Make the configured Windows shell path asynchronous:** `src/agents/sessions/resolve-config-value.ts:153`
  - body: The Windows branch still calls the synchronous `executeWithConfiguredShell` helper from inside the new async resolver. A configured Bash shell can therefore continue blocking the Gateway; provide and await an asynchronous configured-shell implementation.
  - confidence: 0.98
