Full review comments:

- **[P2] Await source fingerprint reads:** `src/agents/cli-credentials.ts:241`
  - body: `readCachedCliCredentialAsync` still invokes a synchronous fingerprint callback before and after every cache miss, so Codex auth resolution retains `statSync` work on the event loop. Make the callback asynchronous and await an `fs.promises.stat`-based reader.
  - confidence: 0.99
- **[P2] Coalesce concurrent credential cache misses:** `src/agents/cli-credentials.ts:258`
  - body: Every concurrent cache miss starts its own keychain or file read before any caller populates the cache. A burst of auth resolution can therefore spawn duplicate `security` processes and amplify the availability problem; retain one in-flight promise per cache key.
  - confidence: 0.98
- **[P2] Use a child-process API that closes stdin:** `src/agents/cli-credentials.ts:11`
  - body: Promisified `exec` does not provide the explicit ignored-stdin behavior attempted through the `stdio` option, leaving the Keychain subprocess on the default piped-stdin contract. Use `execFile` or `spawn` with an argument array and stdin explicitly ignored.
  - confidence: 0.96
- **[P2] Make the configured Windows shell path asynchronous:** `src/agents/sessions/resolve-config-value.ts:149`
  - body: The new async resolver still calls the existing synchronous configured-shell helper on Windows, preserving the event-loop block for that supported path. Add an asynchronous configured-shell implementation before the default-shell fallback.
  - confidence: 0.99
