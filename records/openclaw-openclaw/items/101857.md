## Summary

Keep open: current main and the latest release still route bare Telegram native commands into ordinary slash-command handling, where missing `/btw` and `/steer` arguments return usage text. The requested ForceReply flow is useful Telegram UX, but it needs maintainer product/API direction because it adds a new missing-argument prompt contract rather than fixing broken existing behavior.

## What This Changes

The issue requests a Telegram ForceReply prompt when an argument-requiring command is tapped from the Telegram command menu without arguments.

## Best Possible Solution

Define a narrow opt-in missing-freeform-argument prompt contract for command definitions or portable presentation actions, then map that contract to Telegram ForceReply with focused source tests and live Telegram proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add an opt-in missing-argument prompt contract for native commands, and should Telegram map that contract to ForceReply for commands such as `/btw` and `/steer`?

Rationale: The source bug is clear, but the durable fix changes command semantics and possibly plugin SDK/gateway command metadata; automation should not choose which commands prompt or how other native channels should behave.

Owner confidence: medium

Options:

- **Add Opt-In Prompt Metadata (recommended):** Define a command-level prompt descriptor or portable prompt action, enable it only for selected freeform-argument commands, and map Telegram to ForceReply.
- **Keep Usage-Only Behavior:** Leave bare menu taps as usage replies until there is a broader native-command prompt design.
- **Prototype Telegram-Only:** Add a local Telegram special case for a small command allowlist, accepting the risk that core command metadata and other native surfaces drift.

## Reproduction Assessment

Yes, source-reproducible: Telegram builds a bare slash command when the menu sends no argument, and the `/btw` and `/steer` handlers return usage text for missing arguments. I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the command contract. The best maintainable shape is an opt-in prompt descriptor mapped by Telegram to ForceReply, not a blanket `acceptsArgs` behavior change or raw Telegram string special case.
