## Summary

Keep open: current main still routes a bare Telegram native command menu tap as `/command`, and the affected handlers return usage text when the argument is missing. The requested ForceReply flow is a valid Telegram UX improvement, but it needs maintainer product/API direction because OpenClaw has no opt-in missing-argument prompt contract yet.

## What This Changes

Request Telegram to show a ForceReply prompt when an argument-requiring native command is tapped from the command menu with no argument.

## Best Possible Solution

Define a narrow opt-in command prompt descriptor or portable input-request action, enable it only for selected missing freeform-argument commands, and have Telegram map that to ForceReply with targeted command and thread/reply tests.

## Reproduction Assessment

Yes, at source level: a Telegram menu tap with no payload gives rawText as empty, builds `/command`, and the /btw and /steer handlers return usage text for empty arguments. I did not run a live Telegram client repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the command contract. The ForceReply primitive fits the Telegram UX, but the best OpenClaw solution should be an opt-in command/prompt contract rather than a blanket acceptsArgs behavior change.
