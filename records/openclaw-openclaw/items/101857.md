## Summary

Keep open: current main and the latest release still turn a bare Telegram native command into normal slash-command text and return usage text for empty `/btw` and `/steer`; the requested ForceReply flow is a useful feature but needs command-surface product/API direction first.

## What This Changes

Request a Telegram ForceReply prompt when an argument-requiring native command is tapped from the Telegram command menu without an argument.

## Best Possible Solution

Define an opt-in missing-freeform-argument prompt descriptor in the shared command surface, enable it for selected commands such as `/btw` and `/steer`, and map Telegram to ForceReply with reply-correlation tests while leaving usage-only commands unchanged.
