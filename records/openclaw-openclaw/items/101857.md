## Summary

Keep open: current main still turns a bare Telegram native command into the normal slash-command text and the relevant handlers return usage text when the argument is missing. The requested ForceReply flow is a useful Telegram UX feature, but it needs maintainer product/API direction before a repair PR because it would add new command-surface semantics.

## What This Changes

Add a Telegram ForceReply prompt when a native command that requires arguments is invoked from the Telegram command menu without an argument.

## Best Possible Solution

Add a maintainer-approved opt-in command metadata or portable prompt action for missing required freeform arguments, then map that to Telegram ForceReply while leaving other channels and commands with meaningful no-argument behavior unchanged.
