## Summary

Keep open: current main still sends a bare Telegram menu command through the normal slash-command path, and the relevant handlers return usage text when the freeform argument is empty. This is a valid Telegram UX feature request, but it needs maintainer product/API direction before repair because it adds missing-argument prompt semantics to command metadata and Telegram rendering.

## What This Changes

The issue requests a Telegram ForceReply prompt when an argument-requiring slash-menu command is tapped without an argument.

## Best Possible Solution

Add a maintainer-approved opt-in command prompt descriptor for missing freeform arguments, then map that descriptor to Telegram ForceReply while preserving usage-only behavior for commands where an empty argument is meaningful.
