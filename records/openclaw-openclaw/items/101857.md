## Summary

Keep open: current main still returns usage text for empty argument-taking commands such as `/btw` and `/steer`, and there is no missing-argument ForceReply flow. The request is a concrete Telegram UX enhancement, but it needs a product/API decision around opt-in command metadata versus inference from existing argument specs.

## What This Changes

The issue requests a Telegram ForceReply prompt when a command that requires arguments is selected from the Telegram command menu without an argument.

## Best Possible Solution

Add a narrow missing-freeform-argument prompt contract to command metadata, implement Telegram ForceReply in the native command path, preserve current usage-string fallback for other surfaces, and cover it with targeted Telegram command tests plus live Telegram proof for the PR.

Unclear until maintainers choose the command metadata contract. ForceReply is a plausible Telegram-specific solution, but the best implementation should avoid hard-coding `/btw` and `/steer` or changing every `acceptsArgs` command implicitly.
