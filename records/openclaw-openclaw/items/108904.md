## Summary

Keep this PR open: it addresses the valid reconnect-driven usage scan loop, but the current freshness timestamp can still suppress recovery after an interrupted user-requested refresh. The protected `maintainer` label also requires explicit maintainer handling rather than cleanup closure.

## Best Possible Solution
