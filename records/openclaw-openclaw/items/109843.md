## Summary

The prior regression-test blocker remains: the emoji case only demonstrates that forwarding completes and returns a non-empty slug, which raw JavaScript slicing also does. Repository history also indicates approval IDs are host-generated UUIDs rather than Unicode-bearing user input, and the PR still lacks after-fix evidence from a real approval flow.

## What This Changes

The PR changes pending and resolved exec approval slug generation from raw eight-code-unit slicing to `sliceUtf16Safe` and adds a dedicated forwarder regression test file.

## Best Possible Solution

Keep exec approval IDs on their host-generated UUID contract and drop this change unless a real non-UUID producer is identified; if one exists, retain `sliceUtf16Safe` but assert the exact intact pending and resolved slugs through that production-reachable path.
