## Summary

Keep open: current main and v2026.6.11 still expose browser SSRF as static private-network allow/deny plus hostname exceptions, while the requested confirmation mode, CIDR allow/block policy, temporary grants, and hard metadata override remain unimplemented and security-sensitive.

## What This Changes

The issue requests a browser SSRF policy that can ask users to approve private-network navigation, support allow/block lists, and provide temporary grants instead of only static allow/deny.

## Best Possible Solution

Define a maintainer-approved staged browser SSRF policy with non-overridable metadata handling, upgrade-safe config schema, docs, and focused navigation/redirect tests before implementation.
