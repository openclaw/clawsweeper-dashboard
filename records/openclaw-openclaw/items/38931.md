## Summary

Keep open: current main and the latest release still provide strict/allow browser SSRF policy plus hostname exceptions, but not the requested interactive confirmation, temporary grant, or explicit blocklist semantics. This is security-boundary product work, not conservative cleanup-close material.

## What This Changes

The issue requests a browser SSRF policy mode that asks the user before private-network access and may add allowlist/blocklist and temporary CLI grant controls.

## Best Possible Solution

Keep this open until maintainers choose a secure browser-private-network policy design, likely preserving strict defaults while adding explicit allowlist/blocklist semantics first and any interactive approval path only with non-overridable metadata/link-local protections, audit logging, rate limits, and clear docs.
