## Summary

Keep open: current main still provides strict browser SSRF blocking, a broad dangerous private-network opt-in, and hostname exceptions, but it does not implement a confirmation mode, CIDR allow/block policy, or temporary private-network grant command. This remains a security-sensitive feature/config request that needs maintainer product and security direction before implementation.

## What This Changes

The issue requests a middle-ground SSRF policy for browser private-network access, including interactive confirmation, allow/block lists, and temporary private-network grants.

## Best Possible Solution

Define a maintainer-approved browser SSRF approval contract in the browser plugin first, then implement schema, UI or command approval flow, grant lifetime, metadata hard-block rules, docs, doctor behavior, and focused redirect/DNS/proxy tests against that contract.
