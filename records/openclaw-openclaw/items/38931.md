## Summary

Keep open: current main and v2026.6.11 still only support strict blocking, broad dangerous private-network allow, and hostname exceptions for browser SSRF; the requested confirm, CIDR allow/block, hard metadata policy, and temporary grants remain security-sensitive product work.

## What This Changes

The issue requests browser SSRF controls that ask for user confirmation, allow/block specific private-network destinations, and temporarily grant private-network access instead of only globally allowing or denying it.

## Best Possible Solution

Define a maintainer-approved browser SSRF policy that keeps strict defaults, preserves hard metadata/link-local handling, and stages any allow/block or approval UX with schema, docs, migration, audit, and focused security tests.
