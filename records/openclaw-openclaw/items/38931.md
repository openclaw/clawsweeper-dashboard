## Summary

Keep open: current main and v2026.6.11 still provide static browser SSRF allow/block plus hostname exceptions, but no confirmation mode, CIDR allow/block lists, temporary grant command, or approval workflow. The request remains a security-sensitive feature that needs maintainer product and security design rather than cleanup closure.

## What This Changes

The issue requests a browser SSRF policy mode that can confirm, allowlist, blocklist, or temporarily grant private-network access instead of only allowing or denying it.

## Best Possible Solution

Define a maintainer-approved browser SSRF approval policy that preserves strict defaults, handles metadata/link-local behavior deliberately, reuses existing approval infrastructure where feasible, and updates schema, docs, UI, browser navigation tests, and release-note context together.
