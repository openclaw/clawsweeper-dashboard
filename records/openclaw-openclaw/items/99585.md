## What This Changes

The branch exports `createSseByteGuard` through `openclaw/plugin-sdk/stream-reader-with-limit`, applies a 16 MiB byte guard to Ollama `/api/chat` and `/api/pull` NDJSON success-body readers, updates SDK surface metadata/docs/budgets, and adds bounded-read regression coverage.

## Best Possible Solution

Land the bounded Ollama reader changes only after maintainers accept the new SDK subpath and the 16 MiB fail-closed compatibility boundary; otherwise keep the cap but move it behind an approved SDK/API shape.

## Reproduction Assessment

## Solution Assessment

Is this the best way to solve the issue? Mostly yes for the Ollama OOM surface because the guard sits before the parser and covers both native success readers; the only unresolved question is whether this exact public SDK subpath is the API maintainers want.
