## What This Changes

The PR adds a public `openclaw/plugin-sdk/stream-reader-with-limit` subpath, wraps Ollama native NDJSON streaming reads with a 16 MiB byte guard, updates SDK export metadata/docs/budgets, and adds Ollama stream regression tests.

## Best Possible Solution

Land the Ollama cap after maintainer acceptance of the SDK and compatibility boundary; if that API is not accepted, keep the runtime cap but avoid publishing the new SDK subpath.

## Reproduction Assessment

Yes. Current main shows `parseNdjsonStream` accumulating decoded chunks into an unbounded string buffer while waiting for newlines, and the PR body plus CI Real behavior proof show after-fix loopback overflow and small-response controls.

## Solution Assessment

Yes for the Ollama runtime path: guarding the reader before `parseNdjsonStream` is the narrow fix and matches sibling stream guards. The PR still needs maintainer acceptance because it also publishes a new plugin SDK API and fail-closed compatibility boundary.
