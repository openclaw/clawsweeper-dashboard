## Best Possible Solution

Land the bounded-read fix after a maintainer explicitly accepts the SDK subpath and 16 MiB fail-fast boundary; otherwise keep the guard behind an existing or owner-approved internal/plugin seam.

## Solution Assessment

Mostly yes. Wrapping the readers before the existing parsers is the narrow runtime fix, but publishing the SDK subpath and accepting the 16 MiB total-stream boundary are maintainer API/product decisions.
