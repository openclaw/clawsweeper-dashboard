## Best Possible Solution

Land this after maintainer acceptance of the public SDK seam and 16 MiB compatibility boundary; otherwise keep the byte cap but revise the branch to avoid creating a new public subpath.

## Reproduction Assessment

Yes for the byte-cap placement: wrapping the exact reader consumed by `parseNdjsonStream` is the narrow owner-boundary fix and matches sibling guard usage. The public SDK promotion is plausible because extensions cannot import core internals, but it still needs maintainer acceptance as new plugin API.
