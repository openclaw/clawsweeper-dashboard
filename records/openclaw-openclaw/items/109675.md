## Summary

Keep this PR open: it fixes the silent radix conversion and includes convincing real Control UI proof, but the previous P1 remains unresolved because the new generic number grammar rejects standard scientific notation such as `1e5`. That is an existing accepted input path for numeric controls, so a maintainer must choose the compatibility contract before merge.

## What This Changes

The PR replaces permissive Control UI numeric coercion with a shared decimal-only helper so radix and other nondecimal strings remain text for schema validation instead of being silently converted.

## Best Possible Solution

Preserve accepted scientific notation for generic numeric configuration fields while rejecting radix-like JavaScript-only spellings, unless a maintainer explicitly chooses and documents a stricter cross-product numeric grammar with upgrade rationale.
