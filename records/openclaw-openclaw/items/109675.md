## Summary

This PR has strong real behavior proof and fixes the earlier plain-number input gap, but it still changes generic Control UI number fields from accepting scientific notation to rejecting it. That compatibility contract needs an explicit maintainer decision before merge.

## What This Changes

The branch centralizes Control UI numeric-string coercion and keeps non-matching numeric text as strings so gateway schema validation, rather than immediate `Number()` conversion, determines whether it can save.

## Best Possible Solution

Preserve scientific decimal notation for generic number and integer config fields while rejecting JavaScript-only radix forms and other spellings that cannot be represented as normal JSON numbers; keep cron-specific restrictions scoped to cron parsing.
