## Summary

The prior missing-boundary finding is addressed: both number-input handlers and serialize-time coercion now use one helper. However, the helper also rejects scientific notation such as `1e5`, although the native number control previously accepts it and it denotes the same numeric value as `100000`; that compatibility choice needs maintainer confirmation before this can merge.

## What This Changes

The PR moves Control UI numeric-string coercion into a shared helper, preserves non-matching numeric text for gateway schema validation, and adds browser and config-save regression coverage.

## Best Possible Solution

Preserve accepted scientific notation for schema-number fields unless maintainers explicitly want a stricter generic UI grammar; reject radix-prefixed and other semantically ambiguous spellings while adding focused exponent compatibility coverage.
