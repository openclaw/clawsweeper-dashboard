## Summary

Keep open: current main and the latest release support Feishu native interactive cards and image upload separately, but they still send media as separate messages before a final card and intentionally drop caller-supplied `img` card elements, so the requested single text-plus-multiple-images card behavior is not implemented.

## What This Changes

Add a Feishu/Lark send path that uploads image attachments and delivers text or presentation plus multiple images as one sanitized interactive card.

## Best Possible Solution

Implement this inside @openclaw/feishu as a controlled image-card builder that uploads bounded image attachments, embeds sanitized image elements with text or presentation content, and falls back to existing sequential media/card delivery with live Feishu proof.
