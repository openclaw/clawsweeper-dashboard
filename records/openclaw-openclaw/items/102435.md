## Summary

Keep open. Current main still sends Feishu payload media as separate messages before finalizing cards and rejects direct card-plus-media sends, so this is an unimplemented Feishu plugin feature that needs maintainer direction on trigger semantics and media-card safety limits.

## What This Changes

Request Feishu/Lark support for composing text or presentation plus multiple image attachments into one interactive card instead of separate media messages.

## Best Possible Solution

Implement this inside @openclaw/feishu as a controlled image-card builder that reuses existing media loading/upload policy, preserves text-only card behavior, and falls back to current sequential sends after maintainers choose automatic versus opt-in triggering.
