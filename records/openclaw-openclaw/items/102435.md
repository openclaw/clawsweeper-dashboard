## Summary

Keep open. Current main and v2026.6.11 still do not compose Feishu text/presentation plus image attachments into one interactive card; the request is valid, but it needs a maintainer product decision on automatic versus opt-in behavior and safety limits before automation should implement it.

## What This Changes

Request to add a Feishu/Lark send path that composes text plus multiple image attachments into one interactive card instead of fragmented media messages.

## Best Possible Solution

Implement this inside @openclaw/feishu as a controlled image-card builder that reuses existing media loading/upload policy, preserves text-only card behavior, and falls back to current sequential sends after maintainers choose the trigger semantics.

Options:

- **Opt-in Image Cards (recommended):** Add a Feishu-scoped opt-in first so existing text-plus-media sends keep sequential behavior unless the sender requests a single card.
- **Automatic Image Cards:** Automatically compose one card whenever Feishu sends include text or presentation plus image attachments, with sequential fallback on upload or card failure.
- **Wait For Generic Presentation Images:** Defer the Feishu-first path until the cross-channel presentation contract grows a portable image block.

## Solution Assessment
