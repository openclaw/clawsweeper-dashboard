## Summary

Keep open. Current main still lacks the requested Feishu image-card send path: direct card-plus-media sends are rejected, and the card-capable payload path sends media sequentially before finalizing the card instead of composing uploaded images into one interactive card.

## What This Changes

Request Feishu/Lark support for sending text or presentation plus multiple image attachments as one interactive card.

## Best Possible Solution

Implement this in @openclaw/feishu as a controlled image-card builder that reuses existing media loading/upload policy, preserves text-only card behavior, and falls back to current sequential sends after maintainers choose automatic versus opt-in triggering.

- **Wait for generic image presentation:** Defer this until the cross-channel presentation contract grows an image block instead of adding a Feishu-first path.
