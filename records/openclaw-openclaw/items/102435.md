## Summary

Keep open: current main still lacks a Feishu path that composes text or presentation plus image attachments into one interactive card; the code either sends media separately before the card or rejects direct card-plus-media sends, and maintainers still need to choose trigger and safety semantics.

## What This Changes

Request to add a Feishu/Lark-specific send path that combines text or presentation with multiple image attachments into one interactive card.

## Best Possible Solution

Implement a Feishu-plugin-local controlled image-card builder that reuses existing media loading/upload policy and card sending after maintainers choose opt-in versus automatic triggering and safety limits.
