## Summary

Keep open. Current main and the latest release still either reject direct Feishu card-plus-media sends or send payload media separately before the card, so the requested single interactive image-card send path remains unimplemented and needs a maintainer product decision.

## What This Changes

Request Feishu/Lark support for sending text or presentation plus multiple images as one Feishu interactive card instead of fragmented sequential media messages.

## Best Possible Solution

Implement this inside @openclaw/feishu as a controlled image-card builder that reuses existing media loading/upload safety, preserves text-only card behavior, and keeps sequential fallback after maintainers choose automatic versus opt-in triggering.
