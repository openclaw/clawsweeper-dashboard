## Summary

Keep open. Current main supports Feishu cards and sequential media sends, but not a single Feishu interactive card containing multiple uploaded images; this is a new Feishu plugin feature that needs maintainer direction on default-vs-opt-in behavior and safety limits.

## What This Changes

The issue requests a Feishu-specific send path that composes text or presentation plus multiple image attachments into one Feishu interactive card message.

## Best Possible Solution

Implement this inside @openclaw/feishu with a controlled card-image builder, existing media loading/security policy, sequential-send fallback, focused tests, and live Feishu send proof after maintainers choose automatic versus opt-in behavior.

Question: Should Feishu text/presentation plus image attachments automatically render as one interactive card, or should this require an explicit Feishu opt-in?

Rationale: The code path is clear, but the default behavior affects existing Feishu send semantics and the final safety limits for image-card upload need owner intent.

Likely owner: m1heng

Owner reason: The package metadata identifies @m1heng as the community owner for the Feishu plugin, and this is a Feishu-only product behavior decision.

Owner confidence: medium

Options:

- **Opt-in Feishu image cards (recommended):** Add an explicit Feishu-scoped option first so existing text-plus-media sends keep their current sequential behavior unless the sender asks for a card.
- **Automatic for text plus images:** Automatically compose a card when Feishu sends include text or presentation plus image attachments, with fallback to sequential sends on upload/card failure.
- **Defer to generic presentation images:** Wait for a cross-channel presentation image block instead of adding a Feishu-first path.

## Reproduction Assessment

Yes for the missing capability by source inspection: current main rejects card plus media in the direct Feishu action path and otherwise sends media sequentially before the card. I did not run a live Feishu send during this read-only review.

## Solution Assessment

Unclear until maintainers choose the product shape. A Feishu-plugin-local controlled builder is safer than exposing arbitrary native card JSON, while a generic presentation image block would be broader than this issue needs.
