- `impact:security`: The issue concerns whether operator revocation remains authoritative at the command-execution boundary.
- `maturity:stable`: The affected `gateway-runtime` feature is M4 Stable and includes Approvals and Remote Execution plus Security Controls.

## Summary

Current main still captures the effective exec configuration when the tool is built and does not re-resolve that hot-reloaded configuration at the final Gateway or Node dispatch boundary. The active approval-race PR adds late checks, but its current resolver is still fed the original tool values and does not cover auto-review eligibility or safe-bin trust changes, so this distinct security issue remains necessary.

## What This Changes

Require in-flight exec authorization to revalidate hot-reloaded `tools.exec` security policy before Gateway or Node dispatch.

## Best Possible Solution

Define a canonical minimal exec-policy authorization snapshot for the effective agent/session policy, auto-review eligibility, safe-bin profiles, and trusted directories; re-resolve it from the active runtime config immediately before Gateway spawn or Node dispatch, then fail closed or recompute when the consumed authority was revoked.
