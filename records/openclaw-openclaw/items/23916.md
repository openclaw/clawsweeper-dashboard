Keep open: current `main` and v2026.6.11 still render a compact paired-device list, while the open rename PR only covers the narrower label slice and does not resolve client/platform/activity/detail output or the default-device explanation.

## What This Changes

The issue requests richer, user-understandable metadata in `openclaw devices list`, including client purpose, host or OS information, detail output, and optional notes or labels for paired devices.

## Best Possible Solution

Adopt one coordinated device-identification UX that shows sanitized client, platform, stable ID, and activity metadata in CLI output, preserves `--json`, updates docs/tests, and coordinates editable labels or notes with the narrower naming work.

## Reproduction Assessment

Yes, at source level: current `main` and v2026.6.11 deterministically render paired devices without client purpose, platform/device family, activity, notes, or detail output while storage carries some of that metadata. This is a feature/UX gap rather than a failing runtime path needing live reproduction.

## Solution Assessment

Unclear for the full request. Displaying existing sanitized metadata is bounded, but editable labels/notes and any `--full` detail mode need a shared Gateway/CLI/UI contract rather than a CLI-only field.
