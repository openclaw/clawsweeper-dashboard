## Summary

Keep open: current main and the latest release still show a compact paired-device list, while storage and Gateway paths carry richer device metadata that is not surfaced as client purpose, platform, activity, notes, or detail output. The open rename PR covers only the human-label slice, so it should not close the broader metadata/default-device UX request.

## What This Changes

The issue requests clearer `openclaw devices list` output, including client purpose, host/browser/OS details, default-device context, optional full/details output, and user-editable notes or names for paired devices.

## Best Possible Solution

Define one coordinated device-identification UX that surfaces sanitized client, platform, stable ID, activity, and default-device context in CLI/docs, preserves `--json`, and coordinates labels or notes with the narrower naming issue and open rename PR.
