## What This Changes

## Best Possible Solution

Adopt one coordinated device-identification UX that shows sanitized client, platform, stable ID, and activity metadata in the CLI, preserves `--json`, updates docs/tests, and coordinates editable labels or notes with https://github.com/openclaw/openclaw/issues/13870 and https://github.com/openclaw/openclaw/pull/94517.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 deterministically render paired devices without client purpose, platform/device family, activity, notes, or detail output while storage carries some of that metadata. This is a missing feature rather than a failing runtime path needing live reproduction.

## Solution Assessment

Unclear for the full request. Displaying existing sanitized metadata is bounded, but editable labels/notes and any `--full` detail mode need a shared Gateway/CLI/UI contract rather than a CLI-only field.
