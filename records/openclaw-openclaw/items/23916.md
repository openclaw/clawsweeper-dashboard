## Summary

Keep open: current main and the latest release still render only the compact paired-device list, and the open rename work covers the label slice rather than the broader client/platform/activity/detail output and default-device explanation.

## What This Changes

The issue asks for richer `openclaw devices list` output, including device purpose/client metadata, OS or host hints, activity/detail output, and user-editable notes or labels.

## Best Possible Solution

Adopt one coordinated device-identification UX that shows sanitized client, platform, stable ID, and activity metadata in the CLI, preserves `--json`, updates docs/tests, and coordinates editable labels or notes with the narrower naming issue and open rename PR.

## Reproduction Assessment

Yes, at source level: current main deterministically renders paired devices without client purpose, platform/device family, activity, notes, or detail output while storage carries some of that metadata. This is a missing feature rather than a failing runtime path needing live reproduction.

## Solution Assessment

Unclear for the full proposal. Displaying existing sanitized metadata is bounded, but editable labels/notes and any `--full` detail mode need a shared Gateway/CLI/UI contract coordinated with https://github.com/openclaw/openclaw/pull/94517.
