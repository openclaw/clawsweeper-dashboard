- `merge-risk: 🚨 compatibility`: The patch changes how previously accepted colon-bearing target strings are interpreted and must preserve every documented and supported target form.
- `merge-risk: 🚨 message-delivery`: A parser regression could select the wrong chat/thread tuple or suppress the intended thread ID before a Telegram API call.

## Summary

Keep this PR open, but do not merge it yet: current main still has the reported deterministic misparse, while the branch duplicates an existing lookup-validation contract and provides parser assertions rather than after-fix proof from a real Telegram setup.

## What This Changes

The branch adds a shared guard to both Telegram thread-suffix parsers and regression coverage so malformed multi-colon targets fall back to the complete target string while documented numeric, topic, username, and t.me forms remain supported.

## Best Possible Solution

Make oversplit detection delegate to the canonical `normalizeTelegramLookupTarget` contract, retain focused parser regressions, and add a redacted live Telegram run proving valid topic targets deliver correctly while malformed inputs do not alter routing or session keys.
