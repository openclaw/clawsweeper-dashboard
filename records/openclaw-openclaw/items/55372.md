## Summary

Keep open: current main and v2026.6.11 still send the routed restart-sentinel notice when a delivery target resolves, and neither config nor protocol exposes a suppression contract. The issue is valid, but adding that contract is a product/API decision rather than a safe automatic cleanup close.

## What This Changes

The issue requests a config or protocol option to suppress visible restart-sentinel notifications while preserving restart wake and heartbeat behavior.

## Best Possible Solution

Maintainers should choose one narrow suppression contract that gates only the direct outbound restart notice while preserving restart wake, queued system events, continuation delivery, and route/thread recovery.

Options:

- **Add narrow outbound-notice suppression (recommended):** Gate only the direct restart-sentinel channel notice while preserving wake, heartbeat, system events, continuation delivery, and route recovery.
- **Keep current visible sentinel behavior:** Preserve restart visibility as the product contract and close suppression requests after documenting why operator noise is accepted.
- **Use per-request quiet mode only:** Avoid a persistent config knob and let control-plane callers request quiet restarts when they own another confirmation path.

## Solution Assessment

Unclear until maintainers choose the API shape. The best fix should split notification suppression from wake and continuation recovery instead of disabling the sentinel entirely.
