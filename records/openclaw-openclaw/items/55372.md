## Summary

Keep open: current main and the latest release still send the routed restart-sentinel notice when a delivery route resolves, and there is no supported config or protocol suppression field. The remaining work is real, but it adds public config/protocol behavior and needs maintainer product/API direction before a repair PR.

## What This Changes

The issue requests a config option to suppress restart-sentinel outbound notifications while preserving the wake and heartbeat behavior.

## Best Possible Solution

Maintainers should choose one narrow core-owned suppression contract that gates only the direct outbound restart notice while preserving queued system events, heartbeat wake, continuation routing, and route/thread behavior.

## Reproduction Assessment

Yes, at source level: current main still delivers the restart-sentinel notice whenever the route resolves, and the protocol/config surfaces expose no supported suppression field. I did not run a live Telegram/dashboard restart in this read-only review.

## Solution Assessment

Unclear until maintainers choose the API shape. The maintainable solution should be a narrow suppression contract for the outbound notice only, not a change that disables wake or continuation recovery.
