## Summary

Keep open: current main and the latest release still deliver restart-sentinel notices whenever a route resolves, and neither the gateway config schema nor config.apply/config.patch protocol exposes a supported suppress/notify field. The remaining work is real, but it adds public config or protocol surface, so it needs maintainer product/API direction before implementation.

## What This Changes

Request a config or per-request option to suppress the restart-sentinel outbound notification while preserving the session wake and heartbeat behavior.

## Best Possible Solution

Choose a narrow core-owned suppression contract that gates only direct outbound restart notices while preserving system events, heartbeat wake, continuations, and route/thread recovery.

## Reproduction Assessment

Yes, at source level: current main still delivers the restart-sentinel notice whenever the route resolves, and the protocol/config schema exposes no suppression field. I did not run a live Telegram/dashboard restart in this read-only review.
