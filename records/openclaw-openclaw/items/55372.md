## Summary

Keep open: current main and v2026.6.11 still send the routed restart-sentinel notice when a channel target resolves, and there is no supported suppression field in config or gateway protocol. The remaining work is real but needs maintainer API/product direction because it adds public config or request surface.

## What This Changes

Request a public option to suppress the visible restart-sentinel notification while preserving restart wake, heartbeat, and session recovery behavior.

## Best Possible Solution

Maintainers should choose one narrow suppression contract that gates only the direct outbound restart notice, then update config/protocol docs and regression tests while preserving wake and continuation recovery.
