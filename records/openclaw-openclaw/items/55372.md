## Summary

Keep open: current main and v2026.6.11 still deliver the restart-sentinel outbound notice whenever a route resolves, and there is no supported config or request parameter to suppress only that notification. The requested behavior is real, but it adds public config/protocol surface and needs maintainer product direction before implementation.

## What This Changes

Request to add a config option that suppresses outbound restart-sentinel notifications while preserving restart wake, heartbeat, and recovery behavior.

## Best Possible Solution

Maintainers should choose one narrow, default-compatible core contract that suppresses only the direct outbound restart-sentinel notice while preserving queued system events, restart continuations, heartbeat wake, and route/thread recovery.

## Reproduction Assessment

Yes. Source inspection shows current main still delivers the routed restart-sentinel notice and exposes no config or request parameter to suppress it; I did not run a live Telegram/dashboard restart in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API shape. The request is plausible, but the best fix must be narrower than disabling restart recovery and should preserve wake/continuation behavior by default.
