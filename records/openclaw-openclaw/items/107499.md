## Summary

Current main still erases method-specific payload types at the request-envelope and shared-handler boundary even though built-in methods have concrete TypeBox schemas. Keep this open, but scope it around an extensible built-in-versus-plugin typing design rather than a closed union of every runtime method.

## What This Changes

Introduce method-specific static types for Gateway RPC request payloads and remove unsafe handler assertions where validation already establishes the payload shape.

## Best Possible Solution

Derive a typed map for built-in RPC methods from the canonical schema descriptors, use it in internal dispatch and handlers, and preserve an explicit generic or extensible registration contract for plugin-owned methods.
