## Summary

Current main still has the architectural gap: TypeBox provides method-specific parameter schemas and derived types, but the server handler contract remains generic. The issue should stay open, though its named files and all-command solution are outdated and too broad for implementation without choosing the core-versus-plugin typing boundary. citeturn7view0turn14view1turn8search1

## What This Changes

Introduce method-specific TypeScript parameter types for Gateway commands and use them at server handler boundaries instead of generic payload records and assertions.

## Best Possible Solution

Define a schema-derived typed map for built-in Gateway methods, preserve an explicitly generic or registration-generic plugin method seam, and migrate handler families incrementally with compile-time contract tests rather than rewriting every command at once.
