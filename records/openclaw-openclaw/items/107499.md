## Summary

Current main confirms the architectural gap described in the prior review: method-specific TypeBox schemas exist, but the request envelope and server handler contract still erase payload types. The issue remains useful, although its named server file is outdated and the proposed all-command refactor needs an explicit core-versus-plugin API decision before implementation.

## What This Changes

Introduce method-specific static types for Gateway command payloads and consume them without broad assertions in server request handlers.

## Best Possible Solution

Define a method-owned typed descriptor map for built-in RPCs and migrate handlers in bounded groups, while preserving dynamic plugin methods through an explicit generic or schema-backed plugin registration seam with compatibility tests.
