## Summary

This PR remains necessary, but its legacy-index handling is still on the runtime read path: the storage schema accepts version 1 and the later snapshot check invalidates it. Rejecting the obsolete index at the read boundary is the safer canonical path, and the PR still lacks directly inspectable live proof of uninstall followed by a successful Gateway restart.

## What This Changes

The PR labels missing configured plugin paths as orphan diagnostics and updates persisted plugin-index handling so Gateway re-derives stale registry data.

## System Context

Plugin discovery reads configured plugin paths and builds a persisted installed-plugin index. Gateway startup loads that index, decides whether it is stale, and either reuses it or re-derives the registry from the current filesystem and configuration.

## Best Possible Solution

Make the persisted-index read boundary reject obsolete version-1 records so normal loading falls through to a fresh derivation, retain focused upgrade coverage for that fallback, and add redacted live restart evidence.
