## Summary

The PR still leaves the upgrade case that motivated it unresolved: a persisted pre-marker diagnostic with neither `pluginId` nor `code` is reused rather than forcing registry regeneration. The proposed marker is a good forward-only distinction, but a bounded persisted-format invalidation is needed before merge.

## Best Possible Solution

Introduce a one-time, versioned persisted-diagnostics/snapshot invalidation for rows written before diagnostic codes were stored, then prove an upgrade from that SQLite state regenerates the registry while ordinary current unmarked diagnostics remain reusable.
