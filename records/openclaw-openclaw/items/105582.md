## Label Justifications

- `P2`: The current Control UI has a concrete, limited-surface race that silently discards accepted Workboard edits during pending saves.
- `impact:data-loss`: User-entered draft changes are accepted by the UI and then silently discarded when the pending response resets the draft.

## Summary

Current `main` still exposes the reported Workboard race: pending saves prevent resubmission but do not prevent draft mutation or modal dismissal, and no related issue or PR owns the fix. The protected `maintainer` label requires explicit maintainer handling.

## What This Changes

Prevent the Control UI Workboard editor from accepting edits or close actions while a card create or update request is pending.

## Best Possible Solution

Use one `draftSaving`-based interaction-lock invariant across every modal mutation and dismissal path for both create and update, with deferred-RPC regression coverage.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level with high confidence: current main leaves mutation and dismissal handlers active while the async save later resets the shared draft. The issue also includes a concrete isolated-Gateway Playwright reproduction on ancestor revision `19c85de2272`.

## Solution Assessment

Yes. The existing shared `draftSaving` state is the correct owner-boundary signal, and comprehensively locking the modal is narrower and safer than attempting to merge post-submit edits into an immutable request snapshot.
