## Summary

Keep open: current main still documents and tests commitments as inheriting the owning agent model, while the newer utility-model surface creates a promising but compatibility-sensitive alternative that needs maintainer direction. Recent production reports add concrete timeout and cost evidence, so this is neither stale nor cleanup-closeable.

## What This Changes

Requests independent model routing for commitments extraction so background inference need not use the agent’s primary interactive model.

## Best Possible Solution

Define commitments as an explicit low-cost internal routing consumer while preserving current primary inheritance for existing configs; preferably reuse an explicitly configured per-agent utility model through canonical model-selection helpers, with focused fresh-install and upgrade tests, and add a commitments-specific key only if maintainers want independent fallback semantics.
