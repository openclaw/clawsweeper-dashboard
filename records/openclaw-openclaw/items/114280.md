## Summary

Keep this PR open for explicit gateway-owner review: current `main` still rejects `stopChannel` on the first failing account hook, while this branch supplies a bounded safety-first replacement that waits for sibling teardown and blocks unsafe replacement after a failed stop. The protected `maintainer` label also requires human handling rather than cleanup closure. Likely related people: `steipete` (current gateway-lifecycle change, medium confidence) and `yangxiansheng` (original reproducer and related implementation, medium confidence).

## What This Changes

The branch adds per-account channel-stop state so a failed teardown waits for sibling accounts, preserves the original error, and prevents restart, reload, or logout from replacing an account until a later stop succeeds.

## System Context

The Gateway channel manager starts and stops each configured account through a channel plugin's lifecycle hooks, then exposes runtime state to health recovery, configuration reload, logout, and shutdown callers. This change sits between plugin teardown and those follow-on lifecycle actions, deciding whether an account is safe to start again or clear credentials.

## Architecture Diagram

flowchart TD
  A[Channel lifecycle caller] --> B[Gateway channel manager]
  B --> C[Per-account plugin stop hook]
  C --> D[Stop outcome and task settlement]
  D --> E{Teardown succeeded?}
  E -->|Yes| F[Clear lifecycle state]
  E -->|No| G[Retain failed-stop safety gate]
  F --> H[Restart, reload, logout, or shutdown]
  G --> H

## Best Possible Solution

Adopt one documented gateway lifecycle contract: wait for all sibling teardown attempts, surface the first failure only afterward, and retain the failed-stop gate until a successful retry proves that replacing the account or clearing credentials is safe.
