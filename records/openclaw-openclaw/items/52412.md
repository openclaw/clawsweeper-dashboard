## Summary

Keep open: current main and the latest release still lack the requested injected `api.runtime.agent.abort({ runId })` plugin runtime API. Adjacent Gateway/session cancellation paths exist, but exposing run-abort authority to plugin code remains a product and security-boundary decision, not a cleanup-close candidate.

## What This Changes

The issue requests a plugin runtime API that lets plugins abort an in-progress agent run by run id.

## Best Possible Solution

Maintainers should decide the plugin abort authority model first; if approved, add a narrow scoped runtime method with SDK docs, API baseline coverage, and focused Gateway/plugin tests, otherwise document the supported Gateway or session-run-cancel boundary.

Options:

- **Approve scoped runtime API (recommended):** Add `api.runtime.agent.abort` only with explicit plugin/session ownership checks, docs, API baseline coverage, and tests for allowed and denied cancellation.
- **Keep Gateway/session boundary:** Do not add an injected runtime abort method; document `sessions.abort`/`chat.abort` or a future session-run-cancel seam as the supported cancellation path.
- **Defer to session-run-cancel design:** Wait for the open session-run-cancel SDK proposal to settle before adding another public cancellation contract.
