## Summary

Keep open: current main and the latest release still lack the requested injected `api.runtime.agent.abort({ runId })` plugin runtime API. Adjacent Gateway and SDK cancellation paths exist, but they do not settle the plugin runtime authority and security model for this new method.

## What This Changes

Requested a new plugin runtime method, `api.runtime.agent.abort({ runId })`, so plugins can cancel in-progress agent runs.

## Best Possible Solution

Settle the plugin cancellation authority model first; if approved, add a narrow gated runtime abort method backed by shared Gateway abort logic with SDK docs, API baseline coverage, and focused tests, otherwise document the supported Gateway or SDK cancellation boundary.

## Reproduction Assessment

Yes. Source inspection reproduces the API gap: current `api.runtime.agent` types, facade, docs, and latest-release source omit `abort`, while runId context and Gateway cancellation exist separately.

## Solution Assessment

Unclear. The requested shape is plausible, but the best permanent fix needs maintainer judgment around plugin authority, run ownership, session scoping, and whether adjacent Gateway/SDK cancellation seams should be the supported contract.
