## Summary

Keep open: current main and the latest release still lack the requested plugin runtime `api.runtime.agent.abort({ runId })` API. Adjacent gateway/session abort paths exist, but exposing run cancellation to plugin code remains a new security-sensitive plugin API decision.

## What This Changes

Request to add a plugin runtime `api.runtime.agent.abort({ runId })` API so plugins can cancel in-progress agent runs.

## Best Possible Solution

Define one maintainer-approved plugin cancellation contract with explicit run/session scope, requester identity, permission checks, docs, SDK baseline updates, and tests, reusing the existing gateway/session abort machinery only through that reviewed boundary.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose plugin-side run cancellation as `api.runtime.agent.abort({ runId })`, or should plugins use a narrower session-scoped cancellation seam instead?

Rationale: The requested API is additive but grants plugins authority over active agent runs, so code inspection cannot decide the permanent plugin contract or security boundary without maintainer intent.

Likely owner: Peter Steinberger

Owner reason: Peter has prior history on the plugin runtime contract and public SDK documentation surfaces where this product/security decision would land.

Owner confidence: medium

Options:

- **Design a scoped plugin cancellation API (recommended):** Approve a narrow plugin-facing cancel/abort contract with explicit session/run ownership checks and then implement it with docs, SDK baseline, and focused gateway/runtime tests.
- **Use existing gateway/session abort only:** Decline a new `api.runtime.agent.abort` method and instead document the supported gateway/session cancellation route or a separately approved plugin SDK subpath.
- **Defer plugin abort authority:** Keep the issue open until a sponsoring plugin and maintainer-owned threat model make the required cancellation authority concrete.

## Reproduction Assessment

Yes, source inspection is enough for the feature gap: current main and `v2026.6.11` expose `api.runtime.agent` helpers but no `abort` method. This is not a failing runtime bug reproduction; it is a missing API surface.

## Solution Assessment

Unclear. The proposed `api.runtime.agent.abort({ runId })` is plausible, but a narrower session-scoped or plugin-SDK cancellation seam may be the safer long-term contract.
