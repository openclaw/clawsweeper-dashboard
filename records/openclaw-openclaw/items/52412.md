## Summary

Keep open: current main still lacks the requested injected `api.runtime.agent.abort({ runId })` plugin API. Adjacent Gateway and session-run cancellation paths exist, but this remains a new plugin runtime/security contract decision rather than something already implemented in core.

## What This Changes

Request to add a plugin runtime method that lets plugins abort in-progress agent runs by `runId`.

## Best Possible Solution

Decide the plugin abort authority model first; if approved, add a narrow gated runtime API backed by shared abort logic with SDK docs, API baseline coverage, and focused tests, otherwise document the supported cancellation boundary.

## Reproduction Assessment

Yes. Source inspection on current main reproduces the gap: `api.runtime.agent` has run/session helpers and hook `runId` exists, but no injected `abort({ runId })` method is exposed.

## Solution Assessment

Unclear. The requested method is plausible, but the best permanent fix needs maintainer judgment around plugin authority, run ownership, session scoping, and overlap with Gateway/session-run-cancel paths.
