- `P2`: This is a normal-priority plugin API feature with real agent-run lifecycle impact but no current core outage.
- `impact:session-state`: The request is about cancelling stale or redundant in-progress agent runs to avoid stale conversation/session behavior.

## Summary

Keep open: current main still lacks the requested injected plugin runtime abort API, and the existing Gateway/session cancellation paths plus the open session-run-cancel PR only partially address the underlying plugin authority problem.

## What This Changes

Requested adding `api.runtime.agent.abort({ runId })` so plugins can cancel in-progress agent runs by run id.

## Best Possible Solution

Maintainers should decide the plugin abort authority model first; if approved, add a narrow gated runtime method backed by shared abort logic with SDK docs, API baseline coverage, and focused tests.

## Reproduction Assessment

Yes. Source inspection reproduces the API gap: current `api.runtime.agent` types, facade, and docs omit `abort`, while hook `runId` context and Gateway cancellation exist separately.

## Solution Assessment

Unclear. The requested shape is plausible, but the best permanent fix needs maintainer judgment around plugin authority, run ownership, session scoping, and whether existing Gateway or session-run-cancel alternatives are the intended contract.
