## Summary

Keep open: current main and the latest release still do not expose the requested injected `api.runtime.agent.abort({ runId })` plugin runtime API. Adjacent Gateway `sessions.abort` / `chat.abort` support and open cancellation PRs overlap, but they do not settle the plugin runtime API or its security model.

## What This Changes

Request to add a runId-based `api.runtime.agent.abort` plugin runtime method for cancelling in-progress agent runs.

## Best Possible Solution

Maintainers should decide the plugin abort authority model first; if approved, add a narrow gated runtime method backed by shared abort logic with SDK docs, API baseline coverage, and focused tests, otherwise document the supported Gateway or session-run-cancel boundary.

## Reproduction Assessment

Yes. Source inspection reproduces the API gap: current `api.runtime.agent` types, factory, facade, mocks, and docs omit `abort`, while hook `runId` context and Gateway cancellation exist separately.

## Solution Assessment

Unclear. The requested shape is plausible, but the best permanent fix depends on maintainer decisions about plugin authority, run ownership, session scoping, and whether existing Gateway/session-run-cancel paths should be the supported boundary.
