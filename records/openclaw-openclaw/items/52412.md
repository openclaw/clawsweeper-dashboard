## Summary

Keep open: current main and the latest release still do not expose the requested injected `api.runtime.agent.abort({ runId })` plugin runtime API. Existing Gateway cancellation paths are adjacent, but this remains a security-sensitive plugin API/product decision rather than a cleanup-close candidate.

## What This Changes

Add a plugin runtime API that lets plugins abort in-progress agent runs by run id.

## Best Possible Solution

Maintainers should decide the plugin abort authority model first; if approved, add a narrow scoped runtime method with SDK docs, API baseline coverage, and focused Gateway/plugin tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose `api.runtime.agent.abort({ runId })` to plugins, and what ownership/session authority must gate that abort?

Rationale: The implementation shape is blocked on whether plugins may terminate runs by opaque run id, or whether cancellation should stay behind Gateway/session-run-cancel surfaces with stricter ownership binding.

Likely owner: steipete

Owner reason: Recent history shows the broadest overlap across PluginRuntime helpers, SDK docs, and Gateway abort behavior.

Owner confidence: high

Options:

- **Design A Scoped Runtime API (recommended):** Approve a plugin runtime abort method only after defining session/plugin ownership, permission checks, response shape, SDK docs, and compatibility tests.
- **Use Existing Gateway/Session Cancel Seams:** Keep plugin runtime unchanged and direct plugin authors toward `sessions.abort`, `chat.abort`, or a reviewed session-run-cancel SDK seam instead.
- **Reject Plugin Abort Authority:** Document that plugins cannot directly cancel arbitrary agent runs and require owner-specific cancellation to remain internal or Gateway-scoped.

## Reproduction Assessment

Yes. Source inspection reproduces the API gap: current `api.runtime.agent` types, facade, factory, and SDK docs omit `abort`, while hook `runId` context and Gateway cancellation exist separately.

## Solution Assessment

Unclear. The requested shape is plausible, but the best permanent fix needs maintainer judgment around plugin authority, run ownership, session scoping, and whether existing Gateway/session-run-cancel alternatives are the intended contract.
