## Label Justifications

- `P2`: This is a bounded plugin API feature with real agent-run lifecycle impact, but no current core outage or urgent regression.
- `impact:session-state`: The requested API is about cancelling stale or redundant in-progress agent runs to avoid stale plugin-managed session behavior.

## Summary

Keep open: current main and the latest release still lack the requested injected `api.runtime.agent.abort({ runId })` plugin runtime API. Adjacent Gateway and SDK cancellation paths exist, but exposing run-abort authority to plugin code remains a product and security-boundary decision.

## What This Changes

The issue requests a new plugin runtime API, `api.runtime.agent.abort({ runId })`, so plugins can cancel in-progress agent runs they manage.

## Best Possible Solution

Maintainers should settle the plugin abort authority model, then either add a narrow scoped runtime method with docs/API baselines/tests or document the existing Gateway/SDK cancel path as the supported plugin boundary.
