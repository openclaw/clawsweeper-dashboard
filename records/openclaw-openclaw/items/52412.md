## Summary

Keep open: current main and the latest release still lack the requested injected `api.runtime.agent.abort({ runId })` plugin runtime API. Adjacent Gateway/session cancellation paths exist, but exposing abort authority to plugin code remains a product and security-boundary decision rather than a cleanup-close candidate.

## What This Changes

The issue requests a plugin runtime API, `api.runtime.agent.abort({ runId })`, so plugins can cancel in-progress agent runs.

## Best Possible Solution

Maintainers should decide the plugin abort authority model first; if approved, add a narrow scoped runtime method with SDK docs, API baseline coverage, and focused Gateway/plugin tests, otherwise document the supported Gateway or session-run-cancel boundary.
