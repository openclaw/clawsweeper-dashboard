## Summary

Keep open: current main still does not expose the requested `api.runtime.agent.abort({ runId })` plugin runtime method. Gateway cancellation and agent-run abort registration exist, but turning that into a plugin SDK contract still needs an explicit product and security-boundary decision.

## What This Changes

The issue requests a plugin runtime API that lets plugins cancel in-progress agent runs by run id.

## Best Possible Solution

Maintainers should first decide the plugin abort authority model, then either add a narrow scoped runtime method with SDK docs, API baseline coverage, and Gateway/plugin runtime tests, or document Gateway/session cancellation as the intended boundary.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose a supported plugin runtime abort API, and if so what session/run ownership and permission boundary must it enforce?

Rationale: The source gap is clear, but granting plugin code authority to abort runs is a new public plugin API and security-boundary decision that automation cannot infer safely.

Likely owner: steipete

Owner reason: This needs product/security direction across Plugin SDK and Gateway surfaces, and this handle has the strongest adjacent runtime/API decision history in the inspected evidence.

Owner confidence: medium

Options:

- **Design a scoped plugin abort API (recommended):** Approve a narrow runtime method only after defining session/run ownership checks, trusted-plugin access, SDK docs, API baseline updates, and focused Gateway/plugin runtime tests.
- **Use existing Gateway cancellation only:** Decline a new runtime method and document `chat.abort`, `api.runtime.gateway.request`, or session cancellation as the supported boundary for operator clients and trusted runtime paths.
- **Defer for lifecycle API design:** Keep this open but block implementation until plugin lifecycle permissions and run-management APIs are designed together.

## Reproduction Assessment

Yes. Source inspection reproduces the API gap: current main exposes Gateway cancellation separately but the plugin runtime type, implementation, shape test, and docs do not expose `api.runtime.agent.abort`.

## Solution Assessment

Unclear. The requested shape is plausible, but the best fix depends on maintainer judgment about plugin authority, run ownership, session scoping, and whether the existing Gateway/session cancellation paths should remain the only supported contract.
