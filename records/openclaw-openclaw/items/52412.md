## Summary

Keep open: current main and the latest release still lack the requested injected `api.runtime.agent.abort({ runId })` plugin runtime API. Adjacent Gateway/session cancellation paths exist, but exposing abort authority to plugin code remains a product and security-boundary decision rather than a cleanup-close candidate.

## What This Changes

Request to add a plugin runtime `api.runtime.agent.abort({ runId })` API so plugins can cancel in-progress agent runs.

## Best Possible Solution

Maintainers should first choose the plugin abort authority model; if approved, add a narrow scoped runtime method with SDK docs, API baseline coverage, and focused Gateway/plugin tests, otherwise document the supported Gateway or session-run-cancel boundary.

## Reproduction Assessment

Yes. Source inspection reproduces the API gap: current `api.runtime.agent` types, facade, factory, docs, and latest release omit `abort`, while hook `runId` context and Gateway cancellation exist separately.

## Solution Assessment

Unclear. The requested shape is plausible, but the best permanent fix needs maintainer judgment around plugin authority, run ownership, session scoping, and whether existing Gateway/SDK alternatives are the intended contract.
