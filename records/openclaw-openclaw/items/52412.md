## Summary

Keep open: current main still does not expose the requested injected `api.runtime.agent.abort({ runId })` plugin runtime API. The repository has adjacent cancellation paths through Gateway `sessions.abort` / `chat.abort` and agent-harness SDK helpers, but adding a plugin runtime abort method remains a new security-sensitive API decision.

## What This Changes

Request to add `api.runtime.agent.abort({ runId })` so plugins can cancel in-progress agent runs by run id.

## Best Possible Solution

Maintainers should decide the plugin abort authority model first; if approved, add a narrow gated runtime method backed by shared abort logic with SDK docs, API baseline coverage, and focused tests, otherwise document the existing Gateway or session-run-cancel path as the supported boundary.

## Reproduction Assessment

Yes. Source inspection reproduces the API gap: current `api.runtime.agent` types, facade, and docs omit `abort`, while hook `runId` context and Gateway cancellation exist separately.

## Solution Assessment

Unclear. The requested shape is plausible, but the best permanent fix needs maintainer judgment around plugin authority, run ownership, session scoping, and whether existing Gateway/session-run-cancel alternatives are the intended contract.
