## Summary

Keep open: current main and the latest release still lack the requested injected `api.runtime.agent.abort({ runId })` plugin runtime API. Gateway and session cancellation paths exist, but exposing run-abort authority to plugins remains a security-sensitive Plugin SDK product decision rather than a cleanup-close candidate.

## What This Changes

The issue requests a new plugin runtime method, `api.runtime.agent.abort({ runId })`, so plugins can cancel in-progress agent runs by run id.

## Best Possible Solution

Maintainers should decide the plugin abort authority model first; if approved, add a narrow scoped runtime method with SDK docs, API baseline coverage, and focused Gateway/plugin tests, otherwise document the supported Gateway or session-run-cancel boundary.

## Reproduction Assessment

Yes. Source inspection reproduces the API gap: current `api.runtime.agent` types, facade, tests, and docs omit `abort`, while runId context and Gateway cancellation exist separately.

## Solution Assessment

Unclear. The requested shape is plausible, but the best permanent fix needs maintainer judgment around plugin authority, run ownership, session scoping, and whether existing Gateway/session-run-cancel alternatives are the intended contract.
