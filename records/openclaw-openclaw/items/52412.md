## Label Justifications

- `P2`: This is a normal-priority plugin API feature with real agent-run lifecycle impact but no current core outage.
- `impact:session-state`: The requested API is about cancelling stale or redundant in-progress agent runs to avoid stale conversation/session behavior.

## Summary

Keep open: current main and the latest release still omit the requested injected `api.runtime.agent.abort({ runId })` plugin runtime API. Adjacent Gateway cancellation paths and the open session-run-cancel PR do not provide this exact plugin runtime surface, so the remaining work is a security-sensitive plugin API/product decision.

## What This Changes

Request to add `api.runtime.agent.abort({ runId })` to the plugin runtime so plugins can cancel in-progress agent runs.

## Best Possible Solution

Maintainers should decide the plugin abort authority model first; if approved, add a narrow gated runtime method backed by shared abort logic with SDK docs, API baseline coverage, and focused tests, otherwise document the Gateway or session-run-cancel path as the supported boundary.

## Reproduction Assessment

Yes. Source inspection reproduces the API gap: current `api.runtime.agent` types, facade, and docs omit `abort`, while hook `runId` context and Gateway cancellation exist separately.

## Solution Assessment

Unclear. The requested shape is plausible, but the best permanent fix needs maintainer judgment around plugin authority, run ownership, session scoping, and whether existing Gateway/session-run-cancel alternatives are the intended contract.
