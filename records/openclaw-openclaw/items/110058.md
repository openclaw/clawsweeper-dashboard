## Summary

Keep this PR open for a migration-boundary decision before merge. The linked regression is concrete, the proposed read path is narrow, and the PR body supplies credible real upgrade evidence; however, the patch keeps a legacy SQLite payload and ID scheme in the steady-state LINE runtime instead of performing a one-time verified migration, which conflicts with the repository’s stated persistent-state policy.

## What This Changes

The PR makes LINE’s durable webhook spool accept pre-drain queue rows whose payload stored an event object and whose row ID was the raw LINE webhook event ID, so pending rows can be delivered after upgrade.

## System Context

LINE acknowledges inbound webhooks only after placing them in the durable channel ingress queue, then a spool drains each persisted row into the LINE handler and agent session. This PR changes the spool’s persisted-row decoding and identity validation during that drain.

## Best Possible Solution

Provide a one-time, verified migration owned by the LINE upgrade/Doctor path that rewrites recoverable legacy rows into the canonical queue payload and ID scheme before the spool starts, then keep the spool runtime canonical-only.
