## Summary

Keep this PR open: it targets the still-open LINE upgrade data-loss regression and has strong real-behavior evidence, but the proposed automatic SQLite rewrite leaves persisted-state migration work in the steady-state spool runtime. OpenClaw policy requires runtime to consume canonical state and assigns legacy state migration to Doctor, so the branch needs that boundary correction before merge.

Likely related people: `steipete` is the strongest routing candidate (high confidence) because the durable LINE spool originated in the merged predecessor; `NianJiuZst` is an adjacent historical contributor (medium confidence).

## What This Changes

This PR rewrites pre-drain LINE webhook spool rows into the current serialized payload and `message:`/`event:` ID format so queued messages survive an upgrade.

## System Context

The LINE extension durably stores acknowledged webhook events in the shared SQLite ingress queue before a worker dispatches them into the LINE handler and agent runtime. This PR handles rows written by a short-lived predecessor format so an upgrade does not incorrectly dead-letter already accepted user messages.

## Best Possible Solution

Move the legacy-row discovery, validation, rewrite, verification, and cleanup into the LINE plugin’s Doctor-owned migration path; keep `webhook-spool.ts` canonical-only and add focused upgrade tests that prove Doctor is idempotent before the normal drain starts.
