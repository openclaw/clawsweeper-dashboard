## Summary

Close this core-repository feature request as a ClawHub/npm plugin path. Current OpenClaw policy directs optional runtime integrations to externally maintained plugins, and the published Agent Harness and provider seams cover the proposed Cursor SDK integration without a missing core API.

## What This Changes

Request an optional Cursor Agent SDK integration that lets OpenClaw agents use Cursor first-party models through a Cursor-billed native harness and optional delegated tool.

## System Context

OpenClaw resolves an agent's provider, model, credentials, session, workspace, and channel delivery before selecting a native agent harness. A Cursor plugin can register a provider for model discovery plus a harness that runs the Cursor SDK, while OpenClaw continues to own session and channel behavior.

## Architecture Diagram

flowchart LR
  A[Operator selects Cursor model] --> B[External Cursor plugin]
  B --> C[Provider catalog and auth]
  C --> D[OpenClaw prepared agent turn]
  D --> E[Cursor SDK harness]
  E --> F[Cursor agent runtime]
  F --> G[OpenClaw channel reply and transcript]

## Best Possible Solution

Build and maintain a `cursor-models` native code plugin outside core, distribute it through npm/ClawHub, pair the provider catalog with the `cursor-sdk` harness, document key handling and local/cloud execution risk, and publish redacted live smoke proof before wider promotion.
