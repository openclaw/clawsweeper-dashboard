## Summary

Keep open: the updated live proof now exercises the defaulted exported paths and no discrete implementation defect remains, but imposing helper-wide 30-second and 10-second idle ceilings is a compatibility policy choice that needs explicit maintainer acceptance before merge.

## What This Changes

The PR adds configurable idle and total timeout handling to four provider response-body helpers, defaults JSON/text reads to 30 seconds and error-body reads to 10 seconds, and adds stalled-stream regression coverage.

## Best Possible Solution

Carry the resolved provider/request timeout into response-body reads, use a bounded fallback only when no explicit budget exists, retain per-call overrides, and test both an explicitly long provider budget and the fallback timeout path.

- **Keep timeouts caller-owned:** Expose the new options but remove shared defaults, then apply explicit budgets only at audited provider call sites.
