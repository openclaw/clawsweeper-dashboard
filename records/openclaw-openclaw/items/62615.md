## Summary

Keep open. Current main and v2026.6.11 include narrower retry, idle-timeout, post-compaction, and tool-loop guards, but they still do not provide the requested first-class session-health breaker with failure receipts, unhealthy-session state, recovery policy, auto-rotation, and operator/UI surfacing.

## What This Changes

Request a gateway/runtime session-level circuit breaker that bounds consecutive unhealthy-session retries and exposes recovery state and actions.

## Best Possible Solution

Define one core session-health contract that composes with existing retry, failover, idle-timeout, tool-loop, and compaction guards, then implement the minimal runtime, persistence, config, and operator surfaces behind upgrade-safe defaults.

Options:

- **Land a narrow no-progress breaker:** Limit the first change to a bounded consecutive no-progress counter in the embedded run loop and leave receipts, persistence, cooldowns, and auto-rotation as explicit follow-up work.
- **Defer to narrower guards:** Keep idle-timeout, tool-loop, post-compaction, provider, cron, and subagent guard tracks separate and narrow this umbrella request later.
