## Summary

Keep open. Current main and the latest release include narrower retry caps, idle-timeout cost-runaway handling, post-compaction loop protection, and session liveness diagnostics, but they do not provide the requested first-class session-health breaker with broad consecutive-failure accounting, failure receipts, recovery policy, optional auto-rotation, and operator/UI surfacing.

## What This Changes

The issue requests a gateway/runtime session circuit breaker that stops repeated retries on unhealthy sessions after consecutive failures, records session-health state, and exposes operator-visible recovery options.

## Best Possible Solution

Define one core-owned session-health breaker contract that complements the existing idle-timeout, compaction, and tool-loop guards, with default pause/receipt semantics, upgrade-safe config/docs, focused tests, and clear operator recovery actions.
