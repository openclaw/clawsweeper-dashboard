## Summary

Keep open. Current main has useful retry caps plus idle-timeout, compaction, and tool-loop guards, but it still lacks the requested first-class session-health breaker with failure receipts, unhealthy-session state, recovery policy, optional auto-rotation, and operator/UI surfacing.

## What This Changes

The issue requests a gateway/runtime session-level circuit breaker that bounds retries on unhealthy sessions, records why the session was stopped, and gives operators safe recovery choices.

## Best Possible Solution

Define one upgrade-safe core session-health contract that composes with existing retry, failover, idle-timeout, tool-loop, and compaction guards, then implement the minimal runtime, persistence, config, and operator surfaces behind deliberate defaults.

Options:

- **Design unified session-health receipts (recommended):** Define failure signature, counters, last success, retry admission, suggested recovery, persistence, and operator recovery semantics before implementation.
- **Land a narrow no-progress breaker:** Limit the first change to a bounded consecutive no-progress counter in the embedded run loop and leave receipts, persistence, cooldowns, and auto-rotation for follow-up work.
- **Defer to narrower guard tracks:** Keep idle-timeout, tool-loop, compaction, provider, cron, and subagent guard work separate and narrow this umbrella request later.

## Reproduction Assessment

## Solution Assessment

No, the current narrower protections are only partial. The best fix is a unified session-health design rather than treating an idle-timeout subset, a broad retry cap, or tool-loop detectors as complete coverage.
