## Summary

Keep open. Current main has useful narrower guardrails for broad retry limits, idle-timeout storms, post-compaction loops, tool loops, cron backoff, and session suspension, but it still lacks the requested first-class unhealthy-session breaker with failure receipts, retry admission, recovery policy, auto-rotation, and operator/UI surfacing.

## What This Changes

The issue requests a gateway/runtime session circuit breaker that bounds repeated failures, marks sessions unhealthy, surfaces operator-visible recovery state, and optionally rotates to a fresh session.

## Best Possible Solution

Define one core session-health contract that composes with existing retry, failover, idle-timeout, compaction, and tool-loop guards, then implement the minimal default-safe runtime and operator surfaces.

Rationale: The source gap is real, but the requested behavior crosses failure taxonomy, config defaults, persisted session state, retry admission, recovery actions, and operator/UI surfacing, which code inspection cannot choose safely.

Options:

- **Design unified session-health receipts (recommended):** Define a first-class receipt with failure signature, counters, last success, retry admission, suggested recovery, persistence, and operator recovery semantics before implementation.
- **Land a narrow no-progress breaker:** Limit the first change to a bounded consecutive no-progress counter in the embedded run loop and explicitly leave UI receipts, persistence, cooldowns, and auto-rotation as follow-up work.
- **Defer to narrower guards:** Keep idle-timeout, tool-loop, compaction, provider, cron, and subagent guard tracks separate and later close or narrow this umbrella request.
