## Summary

Keep open. Current main and the latest release have useful narrower guards for retry caps, idle timeouts, rate limits, post-compaction loops, and tool loops, but they still do not implement the requested first-class session-health circuit breaker with general failure receipts, persisted unhealthy-session state, recovery policy, auto-rotation, and operator/UI surfacing.

## What This Changes

The issue requests a gateway/runtime session-level circuit breaker that bounds retries on unhealthy persistent sessions and exposes operator recovery state.

## Best Possible Solution

Define one core session-health contract that composes with existing retry, failover, idle-timeout, tool-loop, and compaction guards, then add the minimal runtime, persistence, config, and operator surfaces behind upgrade-safe defaults.

Options:

- **Design unified session-health receipts (recommended):** Define failure signatures, counters, last success, retry admission, suggested recovery, persistence, cooldown or half-open behavior, and operator recovery semantics before implementation.
- **Land a narrow no-progress breaker:** Limit the first change to a bounded consecutive no-progress counter in the embedded run loop while leaving UI receipts, persistence, cooldowns, and auto-rotation as explicit follow-up work.
- **Defer to narrower guards:** Keep idle-timeout, tool-loop, compaction, provider, cron, and subagent guard tracks separate and close or narrow this umbrella later.
