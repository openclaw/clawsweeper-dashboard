## Summary

Keep open: current main still resolves missing Skill Workshop approval config as the default pending policy, so a documented `approvalPolicy: "auto"` can be ignored when the before-tool-call context lacks `config`.

## What This Changes

The issue reports that agent-tool Skill Workshop apply, reject, and quarantine still wait for approval despite `skills.workshop.approvalPolicy: "auto"` when the before-tool-call context does not carry config.

## Best Possible Solution

Honor the existing `approvalPolicy: "auto"` contract when explicit hook config is absent, without adding a new config surface or weakening the default pending approval gate.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: current main resolves undefined Skill Workshop approval config to the default pending policy, while docs say `approvalPolicy: "auto"` should skip lifecycle approval. I did not run a live TUI or webchat session in this read-only review.

## Solution Assessment

Yes: the narrow maintainable fix is to resolve the active runtime config only when explicit hook config is absent, keep explicit config precedence, and add regression coverage for the missing-config case. Passing config through every caller is broader and still risks missing future hook contexts.
