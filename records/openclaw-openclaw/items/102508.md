## Summary

Keep open: current main still resolves missing Skill Workshop hook config as the default pending policy, and two open PRs now reference this issue as implementation candidates. The issue should stay open until one fix lands or the PRs are closed.

## What This Changes

The issue reports that agent-initiated Skill Workshop apply, reject, and quarantine calls ignore `skills.workshop.approvalPolicy: "auto"` when the before-tool-call context lacks `config`.

## Best Possible Solution

Land one reviewed linked PR that adds the runtime-config fallback only when explicit hook config is absent, includes regression coverage for that path, and closes this issue after merge.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: current main passes undefined hook config through to `resolveSkillWorkshopConfig`, which resolves to the default pending policy despite docs saying runtime `approvalPolicy: "auto"` skips lifecycle approval. I did not run a live TUI or webchat reproduction in this read-only review.

## Solution Assessment

Yes: the narrow maintainable fix is to use the current runtime config only as a fallback when explicit hook config is absent, preserve explicit config precedence, and keep pending approval as the fail-closed behavior.
