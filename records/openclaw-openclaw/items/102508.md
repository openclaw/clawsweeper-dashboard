## Summary

Keep open: current `main` and the latest release still make Skill Workshop lifecycle approval depend only on `params.config`, so `approvalPolicy: "auto"` can be ignored when the hook context omits config. The safe repair is the runtime-config fallback pattern, not the previously rejected skip-approval-on-missing-config approach.

## What This Changes

The issue reports that agent-driven `skill_workshop` apply/reject/quarantine times out despite `skills.workshop.approvalPolicy: "auto"` because the approval resolver lacks a runtime config fallback.

## Best Possible Solution

Add a narrow runtime-config fallback inside the Skill Workshop approval resolver, preserve explicit passed-config precedence and the default pending approval behavior, and cover both fallback-auto and pending/default paths with focused tests.
