## Summary

Keep open: current main still ignores the documented Skill Workshop `approvalPolicy: "auto"` contract when the before-tool-call context has no `config`, and two open linked PRs now own the candidate fix path.

## What This Changes

Honor `skills.workshop.approvalPolicy: "auto"` for agent-triggered Skill Workshop `apply`, `reject`, and `quarantine` calls when hook context config is absent.

## Best Possible Solution

Land one narrow linked PR that falls back to current runtime config only when hook config is absent, with regression coverage for the resolver and before-tool-call path.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: current main resolves undefined Skill Workshop approval config to the default `pending` policy, while docs say `approvalPolicy: "auto"` should skip lifecycle approval. I did not run a live TUI or webchat session in this read-only review.

## Solution Assessment

Yes: the narrow maintainable fix is to use runtime config only as a fallback when explicit hook config is absent, keep explicit config authoritative, and fail closed if the fallback cannot be read.
