## Summary

Keep open: current main still treats missing Skill Workshop hook config as the default pending approval policy, so the documented `approvalPolicy: "auto"` path can still be ignored; two open linked PRs now own the likely fix path, so this issue should stay open until one lands.

## What This Changes

The issue asks OpenClaw to honor `skills.workshop.approvalPolicy: "auto"` for agent-initiated Skill Workshop lifecycle actions when the before-tool-call context lacks `config`.

## Best Possible Solution

Land one narrow fix PR that falls back to runtime config only when hook config is absent, preserves explicit config precedence and pending fail-closed behavior, adds regression coverage, and closes the duplicate candidate PR.

## Reproduction Assessment

Yes at source level: current main passes no config when `ctx.config` is absent, and the resolver turns undefined config into the default pending approval policy. The issue also includes live timeout logs, but I did not run a live TUI or webchat session in this read-only review.

## Solution Assessment

Yes: the best fix is the narrow resolver fallback already proposed by the linked PRs, with explicit hook config still authoritative and pending approval preserved as the failure mode. Plumbing config through every caller would be broader and still easier to miss in future hook contexts.
