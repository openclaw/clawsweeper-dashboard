## Summary

Keep this PR open. The 180-second default fixes the unconfigured path, but the existing `probeTimeoutMs` precedence can still set a much shorter send deadline and recreate the delivered-then-retried duplicate-message failure for configured installs. The supplied maintainer comment accepts the delayed-fallback proof tradeoff, but it does not resolve that configured-path gap; the protected `maintainer` label also requires human handling.

## What This Changes

The branch raises the default iMessage send RPC timeout from 150 to 180 seconds and replaces the timeout test with a fake-timer regression for an `imsg` fallback response at 158 seconds.

## Best Possible Solution

Resolve the non-explicit iMessage send deadline to at least `DEFAULT_IMESSAGE_SEND_TIMEOUT_MS` while preserving an explicit caller override, then add coverage for a configured low `probeTimeoutMs` plus the delayed fallback boundary.
