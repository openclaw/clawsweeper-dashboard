## Summary

This is a real Telegram conversation-flow problem, but current OpenClaw behavior is immediate per-message dispatch with per-chat/per-thread sequencing rather than inbound turn batching. The requested debounce/coalescing behavior is therefore a new, cross-channel product capability—not a defined bug fix—and needs a maintainer decision before implementation. The earlier batching RFC is closely related but closed, so it is useful design history rather than evidence that the capability is already available.

## What This Changes

Add an opt-in way to group a rapid same-user Telegram message burst, including nearby media, into one ordered agent dispatch instead of starting separate turns for each inbound message.

## System Context

Telegram normalizes each incoming update and deterministically routes it into a chat or topic session before the gateway dispatches an agent turn. The requested change would add a bounded coalescing decision after routing but before dispatch, affecting session timing, media ordering, commands, and reply behavior across chat channels.

## Architecture Diagram

## Best Possible Solution

Define one opt-in gateway-level inbound coalescer after route resolution and before agent dispatch, keyed by resolved session plus sender, with a short sliding window, hard cap, ordered media preservation, and immediate command bypass; then let Telegram use that shared policy.
