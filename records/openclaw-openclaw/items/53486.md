## Summary

Keep open: current main and the latest release still send Feishu card-shaped plain `message`/`text` through the text branch, while exact same-fix PRs are closed unmerged and no open canonical fix currently owns the work.

## What This Changes

The issue requests that Feishu `message(action=send)` detect card-shaped JSON in the plain `message` parameter and send it as an interactive Feishu card instead of raw text.

## Best Possible Solution

Adopt a narrow Feishu-local parser/sanitizer path for valid native interactive-card JSON strings in `send` and `thread-reply`, using the existing native-card sanitizer and preserving ordinary/malformed JSON as text, after live Feishu proof or explicit maintainer proof override.

## Reproduction Assessment

Yes, at source level: current Feishu `send` handling reads plain `message`/`text`, builds cards only from `presentation`, and sends card-shaped text through `sendMessageFeishu`. I did not run a live Feishu tenant send in this read-only review.

## Solution Assessment

Yes for the general fix direction, but this issue is not solved yet. Feishu-local parsing through the existing sanitizer/runtime boundary is narrower than core-wide provider parsing, and the remaining blocker is proof or maintainer adoption rather than product direction.
