## Summary

Keep open: current main and v2026.6.11 still route Feishu card-shaped plain `message` text to the text send path, while the same-fix PRs are closed unmerged and the merged native-card work only covers structured `channelData.feishu.card` payloads.

## What This Changes

The issue reports that Feishu proactive `message(action=send)` sends card-shaped JSON as plain text instead of an interactive card.

## Best Possible Solution

Adopt the narrow Feishu-owned parser/sanitizer shape from the closed candidates, add focused send and thread-reply coverage, and land it with redacted live Feishu proof or an explicit maintainer proof override.

## Reproduction Assessment

Yes, at source level: current Feishu `send` reads `message`/`text`, only builds cards from `presentation`, and falls through to `sendMessageFeishu` for card-shaped text. I did not run a live Feishu tenant repro in this read-only review.

## Solution Assessment

Yes for the implementation direction, but not for another blind automation pass. Feishu-specific card JSON detection should stay in the Feishu plugin boundary and sanitize through the existing native-card path; maintainers should first decide proof override versus live proof/adoption of a known candidate branch.
