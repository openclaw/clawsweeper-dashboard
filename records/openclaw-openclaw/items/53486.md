## Label Justifications

- `P2`: This is a clear Feishu regression with a bounded channel-specific blast radius rather than a core runtime outage.
- `impact:message-loss`: Interactive-card semantics are lost when the card payload is delivered as raw JSON text instead of a native Feishu card.

## Summary

Keep open: current main and v2026.6.11 still route Feishu plain `message`/`text` strings through the text send branch, while structured native-card support only handles `presentation`, `interactive`, or `channelData.feishu.card`; the direct same-fix PRs are closed unmerged.

## What This Changes

The issue asks to restore Feishu proactive sends so valid interactive-card JSON passed as the plain `message` parameter renders as a native card instead of raw text.

## Best Possible Solution

Land a narrow Feishu-plugin-owned parser for valid native card JSON in `send` and `thread-reply`, sanitize through the existing card sanitizer, prove it in live Feishu if maintainers require that, and leave ordinary or malformed JSON on the text path.
