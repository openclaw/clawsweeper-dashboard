## Summary

Keep open: current main and v2026.6.11 still build Feishu proactive-send cards only from structured `presentation` or `channelData`, so card-shaped plain `message` text still falls through to raw text delivery; all same-fix PRs found for this issue are closed unmerged.

## What This Changes

The issue requests restoring Feishu proactive `message(action=send)` so valid interactive-card JSON in the plain `message` parameter renders as a native Feishu card instead of raw text.

## Best Possible Solution

Adopt a narrow Feishu-plugin fix that parses valid native interactive-card JSON from plain `message`/`text` for `send` and `thread-reply`, sanitizes it through the existing native-card path, routes it to `sendCardFeishu`, and leaves malformed or ordinary JSON on the text path.

## Reproduction Assessment

Yes, at source level: a valid Feishu card JSON string in `message` reaches the Feishu action handler as text, and current code only sends cards when structured `presentation` or `channelData` produced one. I did not run live Feishu delivery in this read-only review.

## Solution Assessment

Yes in direction: Feishu-local parsing through the existing sanitizer/card sender is the narrow owner-boundary fix, while core-wide Feishu parsing would duplicate plugin-specific policy in shared message handling.
