## Label Justifications

- `impact:message-loss`: Interactive-card semantics are lost when card JSON is delivered as raw text instead of a native Feishu card.

## Summary

Keep open: current main and latest release still send plain Feishu `message`/`text` strings through `sendMessageFeishu`, while native cards only work when supplied as `presentation`, `interactive`, or `channelData.feishu.card`; the direct parser PRs are closed unmerged.

## What This Changes

The issue reports a Feishu regression where proactive `message(action=send)` sends valid card JSON as raw text instead of rendering it as an interactive card.

## Best Possible Solution

Land a narrow Feishu-plugin-owned compatibility parser for valid native card JSON in `send` and `thread-reply`, sanitize through the existing native-card path, and leave ordinary or malformed JSON on the text path unless maintainers explicitly retire that legacy behavior.
