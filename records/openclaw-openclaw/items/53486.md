## Summary

Keep open: current main and v2026.6.11 still route Feishu `message(action=send)` card-shaped plain text to the post/text sender, while all same-fix PRs found for this issue are closed unmerged.

## What This Changes

The issue asks OpenClaw to restore Feishu proactive sends so card JSON supplied as the message body renders as an interactive card instead of raw text.

## Best Possible Solution

Adopt the narrow Feishu-local parser/sanitizer fix from the closed candidates, add focused routing tests, and require redacted live Feishu proof or an explicit maintainer proof override before landing.

## Reproduction Assessment

Yes, at source level: the shared runner leaves the plain `message` string intact, and the Feishu action handler only turns `presentation` into a card before falling through to `sendMessageFeishu`. I did not run live Feishu delivery in this read-only review.

## Solution Assessment

Yes for the code direction, but not as a fresh automated branch: Feishu-local parsing through the existing sanitizer/runtime boundary is narrower than core-wide provider parsing. The next useful step is maintainer adoption or proof override for one of the closed candidate fixes.
