## What This Changes

The PR makes QA Lab exclude scenarios whose required channel driver or native thread semantics do not match the selected QA lane, preventing incompatible Crabline runs.

## System Context

QA Lab reads taxonomy-backed scenario YAML into a shared catalog, then the lane planner selects scenarios for a provider, channel driver, and channel. The selected plan feeds CI and Testbox QA execution, so eligibility mistakes produce false channel-regression failures and wasted retries.

## Architecture Diagram

flowchart LR
  A[Scenario YAML] --> B[QA scenario catalog]
  B --> C[Driver and channel requirements]
  C --> D[QA lane planner]
  D --> E[Selected compatible scenarios]
  D --> F[Early exclusion reasons]
  E --> G[Crabline or live QA execution]
  F --> H[Accurate planning feedback]

## Best Possible Solution

Retain the single catalog-derived driver contract, finish the in-progress QA smoke and required checks on the exact head, then have a QA Lab reviewer confirm that the intended scenario coverage remains available through the live lanes.
