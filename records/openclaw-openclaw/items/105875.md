## Summary

This PR remains necessary, but the current head still has four previously reported iOS state-transition defects: same-target retries can discard the retained error, route resets can preserve an error from the old target, setup-code attempts can display a stale local failure, and reconnecting error screens leave Retry or Trust actions enabled. Native runtime proof is also still missing.

## What This Changes

The branch changes iOS gateway status and onboarding precedence, adds target-switch error clearing and regression tests, removes unused Watch status snapshot helpers, and resynchronizes native localization metadata.

## Best Possible Solution

Use one target-scoped connection-state path that retains the active gateway's last problem through same-target retries, clears it on every explicit target or route change, gives active setup-code progress precedence over stale local failures, disables problem actions while reconnecting, and is proven with focused tests plus a redacted native recording.
