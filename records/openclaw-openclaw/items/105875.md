- **[P2] Preserve the problem through same-target reconnect setup:** `apps/ios/Sources/Status/GatewayStatusBuilder.swift:26`
  - body: The new unconditional error precedence only works while `lastGatewayProblem` remains populated, but the same-target forced reconnect path clears it during connection preparation before success or a replacement error.   - confidence: 0.97
- **[P2] Clear retained problems when a reset route changes target:** `apps/ios/Sources/Model/NodeAppModel.swift:10682-10684`
  - body: This helper returns when a setup-link or deep-link reset has already cleared both current route identifiers. The subsequent connection to a replacement target then keeps the old gateway's problem, which wins over the new progress state; preserve the previous target through reset or explicitly clear the retained problem when the reset establishes a new target.
  - confidence: 0.98
- **[P2] Let setup-code progress replace stale local failures:** `apps/ios/Sources/Onboarding/OnboardingWizardTypes.swift:50`
  - body: The resolver always returns `localFailure` before active connection progress. Starting a setup-code attempt does not clear that prior local failure until later in the handoff, so the UI can keep showing stale failure text instead of “Connecting via setup code…”; clear the local failure when setup starts or give active setup-code progress precedence.
  - confidence: 0.96
- **[P2] Disable retained-problem actions while reconnecting:** `apps/ios/Sources/Onboarding/OnboardingWizardTypes.swift:51`
  - body: Returning `.failed(problem)` discards the active reconnect detail, so the problem banner continues exposing Retry or Trust as if no attempt were running. Those handlers have no complete in-flight guard and repeated taps can overlap or restart the connection handoff; retain the visible problem while also carrying a busy state that disables its action.
  - confidence: 0.96
