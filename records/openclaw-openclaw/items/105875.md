## What This Changes

The PR changes iOS gateway status and onboarding precedence so retained connection errors remain visible during reconnects and clear when switching gateway targets.

## Best Possible Solution

Use one target-scoped presentation state that retains the prior error through same-target retries while tracking connection-in-flight separately, clears errors on target change or route reset, lets setup-code progress supersede stale local failures, and disables problem actions until the active attempt finishes.
