## Summary

Keep open. Current main still routes browser snapshots through whole-page AI/ARIA/CDP/Chrome-MCP tree reads and only exposes dialog state, so the reported visible-viewport or scroll-position contract is still unresolved rather than implemented or duplicated elsewhere.

## What This Changes

The issue requests that browser snapshots reflect the currently visible viewport after scrolling, instead of returning the same top-of-page/full-tree content.

## Best Possible Solution

Define the browser read contract first: either make snapshot visibly viewport-scoped with scroll metadata, or add an explicit visible-viewport read while preserving full-page/raw reads, then prove it across managed Playwright, raw CDP, and Chrome MCP.

## Reproduction Assessment

No live high-confidence reproduction was run in this read-only review. Source inspection does show that current snapshot paths read full accessibility/AI trees and do not expose scroll or viewport state.

## Solution Assessment

No, not as a narrow autonomous patch yet. The maintainable fix needs a maintainer decision on snapshot semantics, compatibility for full-page reads, and live proof across the existing browser backends.
