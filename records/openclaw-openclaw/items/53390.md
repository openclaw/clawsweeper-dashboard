## Summary

Keep open. Current main and v2026.6.11 still route browser snapshots through full accessibility/tree-style reads without a viewport or scroll-position contract, so the central problem is not implemented and needs a maintainer contract decision plus live proof.

## What This Changes

The issue asks for browser snapshot output to reflect the current scrolled viewport instead of returning top-of-page content after scroll actions.

## Best Possible Solution

Define the browser snapshot contract explicitly: add viewport-aware output or scroll/viewport metadata while preserving an explicit full-tree mode, then prove the scrolled-page behavior across the Playwright, raw CDP, and Chrome-MCP paths.
