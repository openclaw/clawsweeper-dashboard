## Summary

Keep open. Current main still routes browser snapshots through full ARIA/role/CDP/Chrome-MCP tree readers without a visible-viewport contract or scroll metadata, while screenshot labels have separate viewport-aware plumbing; this needs maintainer semantics and live proof rather than cleanup closure.

## What This Changes

The issue requests that browser snapshots reflect the currently visible scrolled viewport instead of returning top-of-page or full-tree content without viewport state.

## Best Possible Solution

Define an explicit browser read contract that preserves full-tree/raw reads where needed while adding or selecting a viewport-aware visible read with scroll/viewport metadata and proof across Playwright, raw CDP, Chrome MCP, and one real long-page flow.

## Reproduction Assessment

No high-confidence live reproduction was run. Source inspection shows current snapshot paths omit scroll/viewport metadata and keep reading ARIA/role/CDP/Chrome-MCP trees, so the reported mismatch remains plausible on current main.

## Solution Assessment

Unclear as a direct default-behavior flip. A viewport-only change may break full-tree ref workflows, so the maintainable fix is a maintainer-approved contract with explicit visible-viewport and full-tree behavior.
