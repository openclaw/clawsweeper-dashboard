## Summary

Keep open. Current main still lacks an explicit visible-viewport or scroll-position contract for browser snapshots, and the linked FSB comment supports treating this as a browser read-contract decision rather than cleanup-close material.

## What This Changes

The issue asks for browser snapshot output to reflect the current scrolled viewport instead of returning top-of-page content after browser actions scroll the page.

## Best Possible Solution

Define the browser read contract first: keep full-tree/raw reads explicit, add or select a viewport-aware visible read with scroll/viewport metadata, then cover Playwright, raw CDP, and Chrome MCP paths with focused tests and live proof.

## Reproduction Assessment

No, not as a high-confidence live current-main reproduction. Source inspection shows the current snapshot contracts omit scroll/viewport metadata and include full-tree reads, but the reported GitHub Issues after-scroll output still needs live browser proof.

## Solution Assessment

Unclear. A direct flip to viewport-only snapshots may break full-tree ref workflows, so the best fix is a maintainer-approved read contract with explicit full-tree and visible-viewport behavior.
