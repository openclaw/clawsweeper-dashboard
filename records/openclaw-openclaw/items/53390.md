## Summary

Keep open. Current main still lacks a visible-viewport browser snapshot contract or scroll-position metadata, and the related discussion supports treating this as a browser read-contract decision rather than cleanup-close material.

## What This Changes

Request a viewport-aware `browser snapshot` result that reflects the current scroll position instead of returning top-of-page content after scrolling.

## Best Possible Solution

Define explicit browser snapshot read semantics: keep full-tree/ref-capable reads available, add or select a visible-viewport read that includes scroll and viewport state, then prove it across Playwright, raw CDP, and Chrome MCP paths.

## Reproduction Assessment

No, not as a high-confidence live current-main reproduction. Source inspection shows snapshot routes do not expose visible-viewport or scroll metadata, which matches the plausible reported failure mode but does not prove the exact GitHub page transcript.

## Solution Assessment

Unclear. A direct default flip to viewport-only snapshots is not clearly the best fix because snapshot refs are a documented automation contract; maintainers should first choose the full-tree versus visible-viewport semantics.
