## Summary

Keep open. Current main still has no explicit visible-viewport or scroll-position snapshot contract, and the browser snapshot paths remain split across full-tree Playwright, raw CDP, and Chrome MCP reads that would need a maintainer decision before changing defaults.

## What This Changes

The issue asks browser snapshots to reflect the current scrolled viewport instead of returning top-of-page or full-tree content after scroll actions.

## Best Possible Solution

Define a browser read contract with explicit full-tree and visible-viewport snapshot behavior, include scroll/viewport metadata, then cover Playwright, raw CDP, and Chrome MCP paths with focused tests and live proof.

## Reproduction Assessment

No, not as a high-confidence live current-main repro. Source inspection shows the current snapshot paths lack viewport/scroll metadata, but the exact after-scroll GitHub page output still needs live browser proof.

## Solution Assessment

Unclear. A direct flip to visible-viewport-only snapshots may break full-tree ref workflows, so the maintainable fix is a maintainer-approved read contract with explicit full-tree and visible-viewport behavior.
