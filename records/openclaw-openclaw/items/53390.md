## Summary

Keep open. Current main and the latest release still route browser snapshots through full-page accessibility/tree readers without a visible-viewport or scroll-position contract, so the reported state drift remains a maintainer behavior decision rather than cleanup-close material.

## What This Changes

The issue asks for `browser snapshot` to reflect the currently visible viewport after scroll actions instead of returning the initial or full-page tree content.

## Best Possible Solution

Define the browser snapshot contract explicitly: either make `snapshot` viewport-scoped with scroll metadata, or add a separate visible-viewport read while preserving full-tree/raw reads for workflows that rely on them.
