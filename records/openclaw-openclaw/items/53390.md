## Summary

Keep open. Current main and the latest release still route browser snapshots through full AI/ARIA/CDP/Chrome-MCP tree reads without a visible-viewport contract or scroll metadata, and the linked FSB comment is useful prior art for treating this as a browser read-contract decision rather than cleanup-close material.

## What This Changes

The issue requests that browser snapshots reflect the currently visible viewport after scrolling instead of returning top-of-page or full-tree content without scroll context.

## Best Possible Solution

Define an explicit browser read contract: preserve full-tree/raw reads as an escape hatch, add or select a viewport-aware visible read with scroll/viewport metadata, and prove it across Playwright, raw CDP, Chrome MCP, and one real long-page flow.

## Reproduction Assessment

No high-confidence live reproduction was run in this read-only review. Source inspection does show current snapshot paths omit scroll and viewport metadata and keep reading AI/ARIA/CDP/Chrome-MCP trees, so the reported behavior remains plausible on current main.

## Solution Assessment

Unclear as a direct bug patch. A viewport-only flip may break full-tree ref workflows, so the maintainable solution is a maintainer-approved contract with explicit visible-viewport and full-tree behavior.
