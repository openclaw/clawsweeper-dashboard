## Summary

Keep open. Current main and the latest release still route browser snapshots through AI/ARIA/CDP/Chrome-MCP tree reads without an explicit visible-viewport contract or scroll-position metadata, so the central user problem is not implemented well enough to close.

## What This Changes

The issue asks for `browser snapshot` to reflect the currently scrolled visible viewport instead of returning pre-scroll/top-of-page content.

## Best Possible Solution

Define an explicit browser read contract: preserve full-tree/raw reads as an escape hatch, add a viewport-aware visible read with scroll/viewport metadata, and prove it across Playwright, raw CDP, Chrome MCP, and one real long-page flow.

## Reproduction Assessment

No high-confidence live reproduction was run. Source inspection shows current snapshot paths omit scroll/viewport metadata and continue using AI/ARIA/CDP/Chrome-MCP tree reads, so the reported behavior remains plausible on current main.

## Solution Assessment

Unclear as a direct bug patch. A default visible-viewport flip may break full-tree ref workflows, so the maintainable solution is a maintainer-approved contract with explicit visible-viewport and full-tree behavior.
