## Summary

Keep open. Current main and the latest release still route browser snapshots through Playwright, raw CDP, and Chrome MCP tree readers without a visible-viewport snapshot contract or scroll/viewport metadata, while the issue discussion includes useful prior art for splitting viewport reads from full-page reads.

## What This Changes

Requests browser snapshots to reflect the currently visible viewport after scrolling instead of returning top-of-page or full-tree content.

## Best Possible Solution

Define an explicit browser read contract: preserve full-tree/raw reads, add or select a viewport-aware visible read with scroll and viewport metadata, and prove it across Playwright, raw CDP, Chrome MCP, and one real long-page flow.

## Reproduction Assessment

No high-confidence live reproduction was run. Source inspection shows current snapshot paths omit viewport/scroll metadata and use full tree-style readers, so the reported behavior remains plausible on current main.

## Solution Assessment

Unclear as a direct bug patch. A viewport-only default would be risky; the best fix is a maintainer-approved contract that separates visible-viewport reads from full-tree reads.
