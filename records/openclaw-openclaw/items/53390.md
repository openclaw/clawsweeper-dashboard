## Summary

Keep open. Current main and the latest release still build browser snapshots from full AI/ARIA/CDP or Chrome MCP trees without a visible-viewport or scroll-position contract, and the linked FSB comment is useful supporting context for treating this as a snapshot semantics decision rather than cleanup-close material.

## What This Changes

The issue asks for browser snapshots to reflect the current viewport after scrolling instead of returning top-of-page/full-page-ordered content.

## Best Possible Solution

Define an explicit browser snapshot contract, likely preserving full-tree reads while adding a visible-viewport mode or viewport metadata, then prove it with a live long-page scroll scenario across the relevant browser profiles.

## Reproduction Assessment

No live high-confidence reproduction was run in this read-only review. Source inspection does show that current snapshot paths are full-tree reads without viewport filtering or scroll metadata, which makes the reported behavior plausible and still actionable.

## Solution Assessment

Unclear until maintainers choose the contract. A direct default behavior change may be too risky; the safer solution is an explicit viewport-aware mode or metadata with tests and live proof.
