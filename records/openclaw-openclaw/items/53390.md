## Summary

Keep open. Current main still lacks a defined visible-viewport/scroll-position snapshot contract across the browser snapshot paths, and the issue discussion plus related FSB comment support treating this as a browser read-contract decision rather than cleanup-close material.

## What This Changes

The issue requests that browser snapshots reflect the current scrolled viewport instead of returning top-of-page content after a scroll action.

## Best Possible Solution

Define the browser read contract first, then make snapshot output either explicitly full-tree or visible-viewport with scroll and viewport metadata across Playwright, raw CDP, and Chrome MCP paths.

## Reproduction Assessment

No high-confidence live reproduction was run. Source inspection supports the contract gap because current snapshot paths do not expose scroll/viewport state, but the exact after-scroll GitHub page output still needs live proof.

## Solution Assessment

Unclear. A direct flip to viewport-only snapshots may break full-tree ref workflows, so the maintainable fix is a maintainer-approved read contract with explicit full-tree and visible-viewport behavior.
