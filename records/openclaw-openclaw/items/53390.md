## Summary

Keep open. Current main still routes browser snapshots through whole-page AI/ARIA/CDP/Chrome-MCP tree reads without a visible-viewport or scroll-position contract, and the related FSB comment is useful prior art for a maintainer decision rather than cleanup-close evidence.

## What This Changes

The issue asks for browser snapshots to reflect the current visible viewport after scrolling instead of returning top-of-page content.

## Best Possible Solution

Define the browser read contract first: either make `snapshot` visibly viewport-scoped with scroll metadata, or add an explicit visible-viewport read while preserving full-page/raw reads as intentional escape hatches, then prove it across managed Playwright, raw CDP, and Chrome MCP.

## Reproduction Assessment

Yes at source level, but not as a live run. Current main still reads full accessibility/AI snapshot trees and does not include viewport scroll state in the snapshot contract.

## Solution Assessment

No, not as a narrow autonomous patch yet. The maintainable fix needs a maintainer decision on `snapshot` semantics, full-read compatibility, and live proof across the existing snapshot backends.
