## Summary

Keep open. Current main and the latest release still implement browser snapshots as accessibility/UI-tree reads without a visible-viewport or scroll-position contract, and the FSB comment is useful prior art for a maintainer product decision rather than cleanup-close evidence.

## What This Changes

The issue requests that browser snapshots reflect the currently visible viewport after scroll, or otherwise expose enough viewport state for agents to know what they are seeing.

## Best Possible Solution

Define the browser read contract first: add a visible-viewport read with scroll metadata or intentionally make snapshot viewport-scoped, while preserving explicit full-page/tree reads and proving all snapshot backends.

Required: true

Kind: product_direction

Question: Should browser `snapshot` become a visible-viewport read after scroll, or should OpenClaw add a separate visible-viewport read while keeping `snapshot` as the full UI-tree/read surface?

Rationale: The current implementation is internally consistent as a tree snapshot, but the user problem is real for agents that need to verify below-the-fold state; changing default snapshot semantics affects model-facing browser contracts and compatibility across Playwright, raw CDP, and Chrome MCP.

Likely owner: steipete

Owner confidence: high

Options:

- **Add visible-viewport read (recommended):** Add an explicit viewport-scoped read with scroll metadata and keep existing full AI/ARIA/tree snapshots as an escape hatch.
- **Change snapshot default:** Make `snapshot` itself viewport-scoped after scroll and require callers to opt into full-tree reads when they need them.
- **Keep tree snapshots:** Document that `snapshot` is a full UI-tree read and direct agents to screenshots or labeled screenshots for visible viewport checks.

Yes at source level, but not as a live run. Current main still reads accessibility/UI snapshot trees and does not include scroll position or visible-viewport metadata in the snapshot response.

## Solution Assessment

No as a narrow autonomous patch. The maintainable solution needs a maintainer-approved browser read contract, a compatibility path for full-tree reads, and live proof across the existing backends.
