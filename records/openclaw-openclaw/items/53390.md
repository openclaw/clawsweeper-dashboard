## Summary

Keep open. Current main and v2026.6.11 still expose browser snapshot as AI/ARIA/CDP/Chrome-MCP tree reads without a visible-viewport contract or scroll/viewport metadata, and the FSB discussion is useful prior art for making this an explicit browser read-semantics decision instead of closing it as cleanup.

## What This Changes

The issue reports that browser snapshots keep returning top-of-page content after a page scroll instead of representing the visible viewport.

## Best Possible Solution

Define an explicit browser snapshot read contract in the browser plugin: preserve full-tree refs where needed, add or select visible-viewport state with scroll/viewport metadata, and prove both paths on a long scrollable page.

## Reproduction Assessment

No high-confidence live reproduction was run in this read-only review. Source inspection shows the current snapshot paths still lack visible-viewport/scroll metadata, so the reported mismatch remains source-reproducible but not fully reproduced.

## Solution Assessment

Unclear as a direct bug patch. A viewport-only flip could break full-tree ref workflows, so the maintainable solution is a maintainer-approved contract that separates visible-viewport reads from full-tree snapshots.
