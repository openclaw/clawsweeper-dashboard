## Summary

Keep open. Current main still routes browser snapshots through full AI/ARIA/CDP/Chrome-MCP tree reads without an explicit visible-viewport or scroll-position contract, so the central report is not implemented on main and still needs maintainer direction plus live browser proof.

## What This Changes

The issue reports that browser snapshots keep returning top-of-page content after scrolling and asks for snapshots to reflect the current visible viewport state.

## Best Possible Solution

Define the browser read contract first: keep full-tree/raw reads explicit, add or select a viewport-aware visible read with scroll metadata, then cover Playwright, raw CDP, and Chrome MCP paths with focused tests and live proof.

## Reproduction Assessment

No, not as a high-confidence live current-main reproduction. Source inspection shows the snapshot paths omit scroll and viewport metadata, but the reported after-scroll GitHub page output still needs live browser proof.

## Solution Assessment

Unclear. A direct flip to viewport-only snapshots may break full-tree ref workflows, so the best fix is a maintainer-approved read contract with explicit full-tree and visible-viewport behavior.
