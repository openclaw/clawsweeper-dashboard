## Label Justifications

- `P1`: The PR has a concrete pre-merge privacy and delivery regression that can expose internal reasoning to real queued follow-up channels.
- `merge-risk: 🚨 message-delivery`: Merging the PR can add an extra reasoning message to queued follow-up deliveries where users did not ask for durable reasoning.
- `merge-risk: 🚨 security-boundary`: The affected payload is internal model reasoning, and the patch currently bypasses an existing opt-in visibility boundary on one delivery path.

## Summary

Keep this PR open: the CLI thinking parser and direct `/reasoning` gate path are useful and supported by real captured Claude CLI frames, but the patch introduces a blocking privacy/delivery bug for queued follow-up runs because durable CLI reasoning is synthesized before every delivery path has applied the existing reasoning gate.

## What This Changes

The PR parses Claude CLI `thinking_delta` and final `thinking` blocks into `stream:"thinking"` events, bridges them into reasoning stream callbacks, and prepends a durable `isReasoning` payload for CLI-backed turns.

## Best Possible Solution

Keep the parser/bridge approach, but only synthesize or deliver durable CLI reasoning through the same reasoning-level gate on both direct dispatch and queued follow-up delivery paths.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: a claude-cli queued follow-up that emits `stream:"thinking"` will cause `runCliAgentWithLifecycle` to prepend an `isReasoning` payload, and the queued follow-up delivery filter has no reasoning-level drop gate.

## Solution Assessment

No. The parser and bridge are a good fit, but the durable payload is attached too early for all callers; the safer fix is to preserve the existing reasoning gate wherever CLI results are delivered.
