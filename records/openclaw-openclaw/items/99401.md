## Summary

Keep open: the current head fixes the core parser gap, but it still synthesizes durable CLI reasoning before the queued follow-up path can apply the normal reasoning visibility gate, so it can expose internal Claude CLI thinking as a final channel message.

## What This Changes

The branch parses Claude CLI native thinking, emits `stream:"thinking"`, bridges those events to reasoning callbacks, and prepends durable reasoning payloads to CLI results.

## Best Possible Solution

Keep the parser and bridge design, but only synthesize or deliver durable CLI reasoning where the existing durable reasoning gate is available for both direct dispatch and queued follow-up delivery.

## Reproduction Assessment

Yes. Source inspection shows the PR head prepends durable `isReasoning` payloads inside `runCliAgentWithLifecycle`, while the queued follow-up caller passes no reasoning level and the queued payload filter has no reasoning drop gate.

## Solution Assessment

No. Parsing `thinking_delta` at the CLI stream boundary is the right direction, but durable payload synthesis must not happen before all delivery callers can enforce the existing reasoning visibility contract.
