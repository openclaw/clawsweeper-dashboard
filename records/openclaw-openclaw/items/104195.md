## Summary

This unchanged head retains three blocking request-lifecycle defects: cancellation does not reach the production node policy, ordinary request timeout or abort does not trigger the server signal, and completed requests retain socket-close listeners. The security-sensitive protocol direction also needs maintainer confirmation, and the PR supplies unit-test output rather than real Gateway behavior proof.

## What This Changes

The PR adds a WebSocket-close-driven abort signal to Gateway request options, races plugin approval against cancellation, and rejects node dispatch when already aborted.

## Best Possible Solution

Implement a typed request-id-scoped cancellation lifecycle covering timeout, explicit abort, and disconnect; forward it through the production node handler and approval runtime; define pending-versus-effecting semantics; clean up listeners when dispatch settles; and prove the complete path with integration tests and a live Gateway run.
