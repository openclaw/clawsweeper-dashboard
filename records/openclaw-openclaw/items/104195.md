## Summary

Keep this PR open, but do not merge the current head: it still substitutes the plugin approval maximum for the caller’s configurable lifetime and records routine request completion as the connection’s close cause. The linked security issue remains canonical, and a Gateway/security owner must confirm the additive cancellation contract before implementation continues.

## What This Changes

The PR propagates a per-request AbortSignal from Gateway WebSocket handling through plugin approval and node dispatch, adding deadline cleanup and cancellation-focused tests.

## Best Possible Solution

Add a wire-compatible, connection-bound request cancellation or deadline contract carrying the caller’s actual lifetime, keep request state separate from connection diagnostics, and prove cancellation wins only while the request is pending—not after node transport dispatch begins.
