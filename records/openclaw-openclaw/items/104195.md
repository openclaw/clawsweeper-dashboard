Full review comments:

- **[P1] Use the caller deadline instead of the approval maximum:** `src/gateway/server/ws-connection/message-handler.ts:2686-2689`
  - body: This schedules cancellation after `MAX_PLUGIN_APPROVAL_TIMEOUT_MS` (600 seconds), even though `GatewayClient.request()` supports configurable per-call timeouts and the reported path normally times out at 30 seconds. On a persistent socket, an approval resolved at 60 seconds still dispatches exactly as before, so the canonical security path remains open. Propagate an authoritative deadline or cancellation event from the originating client/request instead.
  - confidence: 0.99
- **[P2] Keep request completion out of the connection close cause:** `src/gateway/server/ws-connection/message-handler.ts:2709-2712`
  - body: `setCloseCause` retains the first cause for the whole WebSocket connection, but `cancelRequest("request-completed")` calls it after the first ordinary request. Any later socket close is therefore logged as `request-cancelled`, hiding the real disconnect cause and polluting connection diagnostics. Keep cancellation metadata request-scoped and set a connection close cause only when the connection itself is closing.
  - confidence: 0.98
