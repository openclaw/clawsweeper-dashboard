## Summary

This PR addresses a valid security-sensitive request-lifecycle bug and adds useful approval and pre-dispatch cancellation guards, but the current head still does not enforce the caller’s actual timeout: it gives every Gateway request a synthetic 120-second deadline, leaving the reported 30-to-120-second late-dispatch window open and changing unrelated long-running request semantics. It also writes normal request completion into connection-level close diagnostics, and the posted proof remains test-only.

## What This Changes

The PR propagates an `AbortSignal` through Gateway handlers, expires pending plugin approvals on cancellation, and blocks plugin-owned node dispatch after cancellation.

## Best Possible Solution

Adopt one additive, authoritative request-lifetime contract—preferably validated caller deadline metadata, or an explicit cancel frame keyed by request id—then abort only pending work, expire approvals, atomically guard dispatch, and keep request state separate from WebSocket close diagnostics.
