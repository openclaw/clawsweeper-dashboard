## Summary

This candidate fix is not merge-ready: its cancellation signal never reaches the production node-policy call, and connection close does not represent the per-request timeout that causes the reported race. The canonical security issue remains necessary and should own the protocol-level repair decision.

## What This Changes

The PR creates a WebSocket-scoped abort controller, adds an optional gateway request signal, races plugin approval against abort, and rejects node invocation when the signal is already aborted.

## Best Possible Solution

Implement the canonical issue's additive request-scoped cancellation state machine end to end, forward its signal through handler options into node policy, remove lifecycle listeners when requests settle, and prove timeout, explicit abort, disconnect, allow-versus-cancel, late-allow, and already-effecting outcomes.
