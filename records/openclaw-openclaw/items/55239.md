## Summary

Keep open. Current main and v2026.6.11 support Telegram localized menus only when command metadata already carries `descriptionLocalizations`; built-in commands and Telegram `customCommands` still cannot provide Chinese descriptions, so the remaining API/config decision still needs maintainer direction.

## What This Changes

Request support for Simplified Chinese or other localized Telegram bot command-menu descriptions, preferably configurable for commands such as `/tts` and `/help`.

## Best Possible Solution

Use one additive locale-map contract, likely the existing `descriptionLocalizations` shape, for built-in commands and Telegram custom config with schema, docs, and focused Telegram menu tests; alternatively explicitly consolidate the remaining work under https://github.com/openclaw/openclaw/issues/79458.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows localized Telegram registration only works when commands already carry `descriptionLocalizations`, while built-in commands and Telegram custom config still expose one fallback description string.

## Solution Assessment

Unclear. The merged Telegram transport plumbing is a good base, but the best remaining fix depends on maintainer choice for the canonical locale-map API, translation ownership, and whether Telegram custom config should participate directly or via the broader command metadata work.
