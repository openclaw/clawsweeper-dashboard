## Summary

Keep open. Current main and v2026.6.11 include partial Telegram `descriptionLocalizations` transport support from the merged Telegram PR, but built-in commands and Telegram custom config still expose only one default description string, so configurable Chinese command-menu descriptions remain unsolved and need a maintainer API/product decision. The broader https://github.com/openclaw/openclaw/issues/79458 overlaps, but it is not a confirmed replacement for this focused Telegram config request.

## What This Changes

The issue requests Chinese/localized Telegram Bot command-menu descriptions, preferably configurable for commands such as /tts and /help.

## Best Possible Solution

Extend one additive locale-map contract, likely the existing `descriptionLocalizations` shape, through built-in command definitions and Telegram custom config with schema, docs, and focused Telegram menu tests; otherwise explicitly consolidate the remaining work under the broader command-description i18n tracker.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence source-level reproduction: localized Telegram registration only works when commands already carry `descriptionLocalizations`, while built-in commands and Telegram custom config still expose one default description string.

## Solution Assessment

Unclear. A Telegram-only config override would solve the immediate report, but the maintainable path likely requires maintainers to extend the existing `descriptionLocalizations` map consistently instead of inventing a Chinese-only or Telegram-only shape.
