## Summary

Keep open: the PR targets a real source-reproducible compaction/auth bug, but it is not merge-ready because the new fallback is enabled for every compaction auth profile, including user-locked selections, and external real behavior proof is still missing.

## What This Changes

Adds a `fallbackOnIncompatibleProfile` option to model auth resolution, enables it for embedded and harness compaction, and adds resolver tests for OpenAI Responses OAuth-to-API-key fallback behavior.

## Best Possible Solution

Thread `authProfileIdSource` through embedded and harness compaction, enable incompatible-profile fallback only for auto/inherited profiles, keep user-locked profiles fail-fast, and add focused regression coverage plus redacted real compaction proof.

## Reproduction Assessment

Yes, from source inspection: current main throws on an incompatible explicit OpenAI OAuth profile before reaching the auth-order fallback loop, and compaction passes the session profile as `authProfileId`. I did not run a live long-session reproduction in this read-only review.

## Solution Assessment

No, not yet. The resolver-level opt-in is a reasonable shape, but the compaction callers need to preserve the existing user-locked profile contract before this is the best fix.
