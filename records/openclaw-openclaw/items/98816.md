## Summary

Keep open: the PR targets a valid source-reproducible compaction auth failure, but the submitted fix broadens fallback to user-locked compaction profiles and still lacks inspectable after-fix real behavior proof.

## What This Changes

Adds `fallbackOnIncompatibleProfile` to model auth resolution and enables it for embedded and harness compaction so OpenAI Responses can fall through from incompatible OAuth profiles to API-key auth.

## Best Possible Solution

Thread `authProfileIdSource` through compaction, enable incompatible-profile fallback only for auto/inherited profiles, preserve user-locked fail-fast behavior, and add focused regression coverage plus redacted real compaction proof.

## Reproduction Assessment

Yes, from source inspection: current main throws on an incompatible explicit OpenAI OAuth profile before reaching the auth-order fallback loop, while compaction passes the session profile as `authProfileId`. I did not run a live long-session reproduction in this read-only review.

## Solution Assessment

No, not yet. The resolver-level opt-in is a plausible shape, but compaction must preserve the user-vs-auto profile source before this is the narrow maintainable fix.
