## Summary

Keep open: the PR targets a real compaction auth bug, but as written it enables incompatible-profile fallback without preserving the existing user-vs-auto profile source, so it can silently switch user-locked compaction credentials.

## What This Changes

## Best Possible Solution

Thread `authProfileIdSource` through embedded, harness, manual, and native compaction, enable fallback only for explicit auto/inherited sources, and prove user-locked profiles remain fail-fast.

## Solution Assessment

No, not yet. The resolver-level opt-in is a plausible repair shape, but compaction callers must preserve user-locked profile semantics before this is the best fix.
