## Summary

Keep open: the PR addresses a real source-reproducible compaction auth bug, but the current diff still enables fallback without carrying the existing user-vs-auto profile source into the compaction credential lookups, so it can silently change user-locked OpenAI auth selection.

## What This Changes

The PR adds a `fallbackOnIncompatibleProfile` resolver option, enables it from embedded and harness compaction credential lookups, and adds resolver tests for OpenAI Responses OAuth-to-API-key fallback behavior.

## Best Possible Solution

Thread `authProfileIdSource` through embedded, harness, and manual/native compaction, enable fallback only for explicit auto/inherited sources, default user or unknown source to fail-fast, and add focused regression coverage.

## Reproduction Assessment

Yes, this is source-reproducible: current main asserts on an explicit incompatible OpenAI profile before `auth.order` fallback, and compaction forwards the session profile as `authProfileId`. The PR body also reports a redacted live before/after patch run.

## Solution Assessment

No, not yet: the resolver-level opt-in is a plausible repair shape, but the compaction callers must preserve user-locked profile semantics before this is the best fix.
