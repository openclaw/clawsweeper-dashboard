## Summary

Keep open: this is a focused candidate fix with stronger live proof now in the PR body, but it is not merge-ready because the compaction callers enable incompatible-profile fallback without preserving whether the profile was user-locked or auto-selected.

## What This Changes

The PR adds a `fallbackOnIncompatibleProfile` resolver option, enables it for embedded and harness compaction, and adds model-auth tests for OpenAI Responses OAuth-to-API-key fallback behavior.

## Best Possible Solution

Thread `authProfileIdSource` through embedded and harness compaction, enable fallback only for auto/inherited profiles, and default unknown or user sources to fail-fast.

## Reproduction Assessment

Yes at source level: current main fails fast on an incompatible explicit OpenAI OAuth profile before auth-order fallback, and compaction forwards the session profile as `authProfileId`; the PR body also reports a live before/after patch run.

## Solution Assessment

No, not yet: the resolver-level opt-in is a plausible repair shape, but the compaction callers must preserve user-locked profile semantics before this is the best fix.
