## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.99

Full review comments:

- **[P1] Bound the unfinished-line carry state:** `scripts/check-no-conflict-markers.mjs:94-101`
  - body: The chunk buffer is bounded, but `leftover` retains the entire unterminated line and `leftover + text` recopies it on every chunk. A large generated file with no newline therefore still grows memory with file size and can reproduce the OOM this PR is intended to prevent; retain only bounded line-start recognition state while consuming the rest of the line.
  - confidence: 0.99
- **[P2] Isolate open and read failures per candidate:** `scripts/check-no-conflict-markers.mjs:76-81`
  - body: The old loop caught each candidate read and continued, but this helper only catches `statSync`; an `openSync` or `readSync` error now escapes and prevents all later files from being checked. Catch those errors around each candidate, close any opened descriptor, and continue scanning.
  - confidence: 0.99
- **[P2] Do not count the trailing split segment as a line:** `scripts/check-no-conflict-markers.mjs:96-104`
  - body: When a chunk ends exactly with `\n` or `\r\n`, `split` leaves a trailing empty segment and this loop increments `lineNumber` for it, so markers in later chunks are reported one line too high. This was equally visible on the earlier reviewed head and is a late discovery; remove the terminal split segment before counting completed lines and add a chunk-ending-newline regression.
  - late: true
  - confidence: 0.98
