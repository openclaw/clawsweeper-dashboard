## Summary

This PR remains necessary and its move to exact `git grep` matches is directionally sound, but the current parser still breaks NUL-delimited records when a tracked pathname contains a newline. The PR body’s terminal evidence exercises the earlier skip-based implementation rather than the final parser, so current-head real behavior proof is also still required before merge.

## What This Changes

The PR replaces whole-file tracked-file scanning with parsing exact `git grep` conflict-marker records, updates the declarations, and expands regression coverage.

## Best Possible Solution

Parse the `git grep` byte stream by its NUL field delimiters and consume the record-ending newline only after the match field, then prove the final head detects markers in both an oversized tracked file and a newline-containing tracked pathname.
