## Summary

The current head still prevents the large read by silently dropping files that Git has already identified as conflict-marker candidates, weakening a blocking repository gate. Keep the PR open for the narrow bounded-memory repair; likely routing is to `steipete`, who introduced the current scanner and focused tests.

## What This Changes

The PR adds a 50 MiB stat-based cutoff that skips oversized conflict-marker candidates with a warning, updates the script declaration, and adds large-file regression tests.

## Best Possible Solution

Derive exact file and line violations from the existing Git search without whole-file rereads, or stream candidates incrementally, so memory stays bounded while every positive marker candidate remains blocking.
