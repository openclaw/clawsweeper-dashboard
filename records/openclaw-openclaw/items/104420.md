## Summary

The current head still has the previously reported filename-framing defect: it splits `git grep -z` output on newlines before decoding NUL-delimited paths, allowing valid tracked filenames containing newlines to be misparsed and skipped.

## What This Changes

The PR replaces whole-file conflict-marker reads with exact `git grep` match parsing and updates the declaration and regression tests.

## Best Possible Solution

Decode each `git grep -n -z -o` record sequentially by its NUL field boundaries, add a regression for a newline-containing tracked filename, and provide fresh terminal proof from a temporary Git repository using the final parser.
