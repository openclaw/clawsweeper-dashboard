## Summary

The PR should stay open because the current head still retains an entire unfinished logical line across chunks, so a sufficiently large newline-free text file can recreate the OOM it intends to prevent; it also lets one file-open failure abort the remaining scan. The chunked direction is appropriate, but both previously reported blockers remain and the posted real-behavior proof describes an older skip-and-warn implementation rather than this head.

## What This Changes

The PR replaces whole-file conflict-marker reads with chunked scanning, reconstructs lines across chunk boundaries, updates the declaration surface, and adds large-file regression tests.

## Best Possible Solution

Use fixed-size streaming state that retains only the line-start bytes needed to recognize the four conflict-marker forms while counting line boundaries exactly, isolate stat/open/read/close failures to each candidate, and demonstrate the current head with newline-free, cross-boundary, and later-candidate scenarios.
