## Summary

The exact head preserves conflict detection beyond the chunk size, but two prior blockers remain: newline-free input still creates file-sized carry state, and one file I/O race can abort the entire scan. The PR body also proves an older skip-and-warn implementation rather than the current scanner, so focused repairs and fresh exact-head proof are required before merge.

## What This Changes

The PR replaces whole-file conflict-marker reads with bounded chunk scanning, updates the declaration signature, and adds large-file and chunk-boundary regression tests.

## Best Possible Solution

Implement a streaming line-start state machine that retains only the fixed maximum marker-prefix length, preserves one-based line numbers across LF and CRLF chunk boundaries, and catches stat/open/read/close failures per candidate before adding exact-head terminal proof.
