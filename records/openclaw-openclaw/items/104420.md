## Summary

The current head still fails open for tracked files above 50 MiB: `git grep -l` supplies only candidate filenames, and the new size branch discards those candidates before marker lines are detected. The repeated prior P1 finding therefore remains unresolved despite the added test and declaration update.

## What This Changes

The PR adds a 50 MiB pre-read size guard and warning to the conflict-marker checker, tightens its declaration types, and adds tests for oversized-file skipping and tracked-file marker detection.

## Best Possible Solution

Use a bounded-memory scan or line-numbered Git output for oversized candidates so exact marker lines remain reportable, and add a regression test that crosses an injected small threshold without performing a whole-file read.
