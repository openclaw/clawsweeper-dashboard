Full review comments:

- **[P1] Bound the unfinished-line carry buffer:** `scripts/check-no-conflict-markers.mjs:100-106`
  - body: Keep only bounded marker-prefix state here. A newline-free text file appends every chunk to `leftover` and retains the full result, so memory still grows with the file and repeated concatenation can become quadratic, defeating this PR's OOM guarantee.
  - confidence: 0.99
- **[P2] Keep file I/O failures isolated to one candidate:** `scripts/check-no-conflict-markers.mjs:80-83`
  - body: Preserve current main's per-file skip behavior around the complete open/read lifecycle. `openSync` and `readSync` exceptions escape this helper, aborting the check and preventing later candidate files from being reported.
  - confidence: 0.99
- **[P2] Do not count the trailing split segment as another line:** `scripts/check-no-conflict-markers.mjs:101-108`
  - body: When a chunk ends exactly on a newline, `split` leaves a trailing empty segment and this loop increments `lineNumber` for it; the next chunk's first marker is therefore reported one line too high. This was equally visible at the earlier reviewed SHA and is a late discovery; add an aligned-newline chunk regression.
  - late: true
  - confidence: 0.99
