## Summary

The current head still splits newline-delimited output before consuming the NUL-delimited pathname, so valid tracked filenames containing newlines can be misparsed and their conflict markers missed. The PR also lacks contributor-provided real-command proof required for an external scripts change.

## What This Changes

The PR replaces whole-file tracked conflict-marker scanning with parsed line-numbered `git grep` matches, updates the script declarations, and expands regression coverage.

## Best Possible Solution

Keep the `git grep` match-only design, but parse each NUL-delimited pathname and line-number field before consuming the newline-terminated match text; add a newline-containing pathname regression and current-head terminal proof of the real command.
