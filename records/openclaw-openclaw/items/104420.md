## Summary

The latest head does not fix the previously reported NUL-safety defect: its parser still splits `git grep` output on newline before decoding NUL fields, and an exact scratch reproduction shows a legal newline-containing tracked path is truncated to the suffix. The bounded-memory direction remains useful, but this head is not merge-ready and the PR body still demonstrates an obsolete earlier implementation rather than the current parser.

## What This Changes

The PR replaces tracked-file whole-file reads with parsing of exact line-number matches from `git grep`, updates the declaration surface, and expands focused scanner tests.

## Best Possible Solution

Keep the `git grep` bounded-memory approach, but parse each record by its two NUL separators and final match terminator without treating newline bytes inside the path as boundaries; add a real temporary-repository regression for a newline-containing path and post redacted exact-head terminal output.
