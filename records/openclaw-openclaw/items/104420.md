## Summary

This PR addresses a real memory-risk path, but it is not merge-ready because files above the cap are already known marker candidates and are then treated as clean. The previous blocking finding remains unchanged on the current head.

## What This Changes

The PR caps whole-file conflict-marker reads at 50 MiB, skips larger candidates with a warning, updates the declaration, and adds large-file regression tests.

## Best Possible Solution

Scan oversized text with bounded memory, or carry line-numbered `git grep` matches forward, so known candidates still fail with useful file and line locations.

## Reproduction Assessment

Yes. On the PR head, an oversized file passed to `findConflictMarkersInFiles` returns no violation, while the tracked-file caller supplies only paths already matched by the conflict-marker `git grep`.

## Solution Assessment

No. Bounding whole-file reads is appropriate, but treating a known marker candidate as clean is not; bounded scanning or carrying grep locations preserves both memory safety and detection.
