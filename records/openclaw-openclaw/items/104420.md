## Summary

The updated head still weakens the conflict-marker gate: files reach this function because `git grep` found a marker, but candidates above 50 MiB are then skipped without a violation. The follow-up commit adds a roughly 1 MiB test, so it neither crosses the production threshold nor resolves the prior P1 finding.

## What This Changes

The PR adds a 50 MiB per-file limit to the conflict-marker scanner, skips larger files with a warning, and adds focused regression tests.

## Best Possible Solution

Keep memory bounded while preserving rejection of every marker-containing tracked text file, preferably by obtaining exact line matches from `git grep` or scanning incrementally without whole-file buffering.
