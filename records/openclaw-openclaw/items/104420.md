## Summary

Keep this PR open: the current parser still splits `git grep -z` output on newlines before interpreting NUL-delimited fields, so tracked filenames containing newlines can corrupt records and hide conflict markers. The available real-behavior transcript covers the obsolete size-skip implementation rather than the final `git grep` path.

## What This Changes

The PR changes the conflict-marker checker to consume exact line-number matches from `git grep` instead of reading candidate files into memory.

## Best Possible Solution

Parse the raw `git grep` buffer according to its NUL field boundaries without splitting the pathname on newlines, add regression coverage for newline-containing tracked paths, and provide a redacted terminal run of the final tracked-file path against both a large file and an unusual filename.
