## Summary

Keep this PR open for another revision: using `git grep` is a sound bounded-memory direction, but the current parser still splits records on newline before decoding NUL-delimited paths, so valid tracked filenames containing newlines can evade the conflict-marker check. Current-head real behavior proof is also missing because the PR body demonstrates an earlier implementation.

## What This Changes

The PR replaces whole-file conflict-marker candidate reads with parsing exact line matches from `git grep`, with corresponding declaration and regression-test updates.

## Best Possible Solution

Parse each `git grep -z` record from its NUL field boundaries without treating newlines inside the pathname as record separators, then prove the final implementation with a large tracked file and a tracked newline-containing filename.
