## Summary

The exact PR head still has both previously reported blockers: unfinished lines can grow with the full candidate size, and filesystem failures can stop the guard before later files are scanned. The PR body also proves an obsolete skip-based implementation rather than the current chunk scanner.

## What This Changes

## Best Possible Solution

Use a streaming scanner that retains only bounded marker-relevant line state, preserves exact cross-chunk detection and line numbers, isolates stat/open/read/close failures per candidate, and demonstrates bounded peak memory on the repaired head.
