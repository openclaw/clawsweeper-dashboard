## Summary

The latest head still splits `git grep -z` output on newline before decoding the NUL-delimited pathname, so a legal tracked filename containing a newline is fragmented and its conflict markers can be missed; focused tests and green CI do not provide the required real command proof.

## What This Changes

The PR changes the tracked conflict-marker check to parse exact line-numbered `git grep` matches instead of reading candidate files whole, updates declarations, and expands regression tests.

## Best Possible Solution

Decode each record from the NUL-framed pathname and numeric fields without treating pathname newlines as record boundaries, add a newline-path regression, then show a redacted terminal run of `pnpm check:no-conflict-markers` or `node scripts/check-no-conflict-markers.mjs` against a real temporary Git repository containing both a large file and an unusual pathname.
