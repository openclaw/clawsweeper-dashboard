## Summary

This PR is still necessary but not merge-ready: the current head retains unbounded partial-line data, regresses per-file I/O failure isolation, and lacks runtime proof for the exact implementation.

## What This Changes

The branch replaces whole-file conflict-marker reads with chunked scanning, updates the declaration signature, and adds tests for large files and markers crossing chunk boundaries.

## Best Possible Solution

Implement a truly constant-memory marker scanner—preferably exact `git grep` line output or a finite-state line-prefix matcher—while preserving per-candidate I/O isolation, exact line numbers, and current-head proof for long-line and failure-continuation cases.

## Solution Assessment

No. Chunked reads are directionally sound, but this implementation does not bound retained line state and removes existing per-file failure isolation; exact `git grep` output or a finite-state prefix scanner is safer.

  - body: `leftover` accumulates every chunk until a newline appears, so a large minified or generated text file containing one very long line still consumes memory proportional to file size and can OOM.   - confidence: 0.99

  - body: The old loop caught each file read and continued, but the new helper lets `openSync` and `readSync` throw out of `findConflictMarkersInFiles`. A file that disappears or becomes unreadable after `git grep` now prevents all later candidates from being checked; catch those failures per file while still closing any opened descriptor.
