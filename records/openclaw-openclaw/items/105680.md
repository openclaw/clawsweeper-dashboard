## Label Justifications

- `P2`: The bundled memory plugin has a source-backed startup race with a narrow fix and a limited affected population.
- `impact:crash-loop`: Concurrent table initialization can reject creation and prevent a gateway or worker process from starting normally.

## Summary

Keep open. Current `main` still uses a process-local initialization promise around a non-atomic table existence check and creation, while the pinned LanceDB version provides a narrower atomic create-or-exist operation; no related issue or PR owns this repair.

## What This Changes

Prevent separate OpenClaw processes from racing while creating the LanceDB memory table.

## Best Possible Solution

Replace the check-then-create branch with LanceDB 0.30.0 atomic creation using `existOk`, keep schema-row cleanup safely idempotent, and add a real two-process regression test without introducing a filesystem-lock dependency.

## Reproduction Assessment

Yes, there is a high-confidence source reproduction path: coordinate two Node processes so both observe the table as absent and then invoke default `createTable()` against the same directory. A real failure log or executed regression has not yet been supplied.

## Solution Assessment

No, the proposed filesystem lock is broader than necessary. LanceDB already owns atomic table creation through `existOk`, which is the narrower plugin-local fix when paired with idempotent cleanup and concurrent-process proof.

## Repair Work Prompt

Fix the source-backed multi-process initialization race in the bundled `memory-lancedb` plugin. Replace the `tableNames()` check followed by default `createTable()` with the pinned LanceDB 0.30.0 atomic create-or-exist contract using `existOk`; ensure temporary `__schema__` cleanup is safe when two processes initialize simultaneously and both returned table handles can store and search afterward. Add focused regression coverage using two separate Node processes against one temporary LanceDB directory, not merely two promises in one process. Preserve existing single-process retry behavior. Do not add `proper-lockfile`, a new config option, core runtime behavior, broad fallback handling, or corruption-recovery claims beyond the proven duplicate-create failure. Do not edit `CHANGELOG.md`.
