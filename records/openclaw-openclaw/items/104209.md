## Summary

The PR is still necessary and appears correct: current main leaves source ingest outside the same-vault transaction boundary used by competing memory-wiki mutators, while the proposed wrapper closes that gap without adding a parallel mechanism. The coordinator is explicitly reentrant, all production callers use the exported ingest function, the real-vault before/after evidence demonstrates the lost update and preservation, and no actionable functional or security defect was found.

## What This Changes

The PR routes the complete memory-wiki source-ingest operation through the existing reentrant per-vault mutation coordinator and adds concurrency regression coverage.

## Best Possible Solution

Merge the shared coordinator wrapper after ordinary exact-head CI and base-refresh gating; keep one canonical plugin-owned transaction boundary with no new lock, configuration, migration, or compatibility path.
