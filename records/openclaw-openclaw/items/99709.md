## Summary

Keep open: current main still contains the cron hot-reload path that stops and cancels the existing on-exit watcher manager before rebuilding a fresh cron service, and the linked fix candidate is open rather than merged.

## What This Changes

The issue reports that changing any `cron.*` config key during an in-flight on-exit watched command cancels and re-arms the watched command, causing it to run again.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/99724 or an equivalent focused fix that preserves unchanged in-flight on-exit watchers across cron hot reload while still cancelling on shutdown, job removal, command/cwd change, or cron store changes that must not reuse old watcher ownership.

## Reproduction Assessment

Yes. Source inspection shows current main cancels instance-local exit watchers during cron hot reload and reconciles a fresh manager; the reporter's seam proof exercises the same `cancelAll` plus rebuilt watcher sequence.

## Solution Assessment

Yes. The best direction is to preserve live watcher ownership across safe cron hot reloads and let reconciliation cancel only real job changes, rather than adding a config knob or disabling cron reload entirely.
