## What This Changes

The issue reports that editing `cron.*` during an in-flight on-exit watcher cancels and re-spawns the watched command, causing side effects to run twice.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99724 after the cron-store reuse concern is resolved, then close this issue through that merged fix.

## Reproduction Assessment

Yes. Current-main source shows `cron.*` changes still reach `restart-cron`, cancel the instance-local exit watcher manager, rebuild a fresh cron service, and reconcile from the new instance; I did not run a live config-file hot reload in this read-only review.

## Solution Assessment

Yes. The narrow maintainable solution is to preserve live unchanged on-exit watcher state across cron hot reload while still cancelling on shutdown, job removal, command/cwd change, or store-path change; the open fixing PR is the right path to review next.
