## Summary

Keep open: current main still cancels the existing on-exit watcher manager during cron hot reload, rebuilds a fresh watcher instance, and reconciles from empty state. The linked fix pull request is a live candidate, but it is still open, so this issue should remain open until that candidate lands or is replaced.

## What This Changes

Changing a `cron.*` config key while an on-exit watched command is still running should not cancel and re-spawn that watched command.

## Best Possible Solution

Finish review on https://github.com/openclaw/openclaw/pull/99724 or a replacement fix so cron hot reload preserves unchanged live on-exit watchers and cancels them only for real ownership or job changes, then close this issue after merge.

Yes. Source inspection on current main shows `cron.*` reloads still call `stopExitWatchers` and rebuild a fresh watcher instance, matching the reporter’s seam reproduction.

## Solution Assessment

Yes. Preserving unchanged live watcher state across cron hot reload is the narrow maintainable fix; the open candidate pull request is the right lane, with final review needed around ownership changes such as `cron.store`.
