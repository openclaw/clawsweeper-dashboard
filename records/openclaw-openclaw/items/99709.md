## Summary

Keep open: current main still restarts cron by stopping the old cron service, cancelling exit watchers, building a fresh watcher instance, and reconciling it after any `cron.*` hot reload, so the reported in-flight on-exit re-exec path remains valid.

## What This Changes

The issue reports that changing any `cron.*` config during an in-flight on-exit watched command cancels and re-arms the watcher, causing the watched command to run twice.

## Best Possible Solution

Keep the in-flight on-exit watcher state across cron hot reloads when the watched job remains enabled with the same command/cwd, while still cancelling removed, disabled, or changed watchers.

## Reproduction Assessment

Yes, with high confidence from source inspection and the reporter’s seam proof: current main maps `cron.*` changes to `restartCron`, cancels the old watcher instance, and reconciles a fresh empty instance. I did not run a live gateway config-file hot reload in this read-only pass.

## Solution Assessment

Yes, the best fix is to preserve or transfer live watcher state across cron hot reload when the watched job is still valid, rather than adding a config knob or disabling cron reload. The repair should still cancel watchers for actual shutdown, disable, removal, or command/cwd changes.
