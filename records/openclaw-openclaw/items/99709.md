## Summary

Keep open: current main still maps `cron.*` changes to a cron hot restart that cancels the existing on-exit watcher instance, rebuilds a fresh watcher service, and reconciles from an empty active map, so the reported in-flight command re-execution path remains valid.

## What This Changes

The issue asks OpenClaw to preserve an already-running on-exit cron watcher across unrelated `cron.*` hot reloads instead of killing and re-spawning its watched command.

## Best Possible Solution

Preserve or transfer live on-exit watcher state across cron hot reload when the job remains enabled with the same command and cwd, while preserving cancellation for shutdown and real job changes.

## Reproduction Assessment

Yes. Source inspection shows `cron.*` reloads still cancel the old watcher and reconcile a fresh empty instance; the reporter’s seam proof matches the current-main composition, though I did not run a live gateway hot-reload command.

## Solution Assessment

Yes. The narrow maintainable fix is to keep live unchanged watcher state across cron hot reloads, not add a config knob or disable cron reload entirely.

Current main treats any `cron.*` hot reload as `restartCron`, stops cron, cancels `stopExitWatchers`, builds a fresh watcher instance, and reconciles from an empty active map, which can kill and re-spawn an in-flight unchanged on-exit watched command. Keep live watcher state across cron hot reload when the job remains enabled with the same command/cwd, while still cancelling watchers on gateway shutdown, cron disable, job removal/disable, or command/cwd change. Likely files: `src/gateway/server-reload-handlers.ts`, `src/gateway/server-cron.ts`, `src/gateway/cron-exit-watchers.ts`, and their focused tests. Add regression coverage for unchanged active watcher preservation across hot reload and for changed/removed watcher cancellation. Do not add a config flag, do not broadly rewrite cron scheduling, and do not edit `CHANGELOG.md`.
