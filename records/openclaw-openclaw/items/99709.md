## Summary

Keep open: current main still cancels the existing on-exit watcher manager during a `cron.*` hot reload, rebuilds a fresh cron service, and reconciles from a new watcher instance. The issue now has an open candidate fix at https://github.com/openclaw/openclaw/pull/99724, so this issue should stay open until that PR lands or is replaced.

## What This Changes

The issue asks for cron hot reload to preserve an in-flight on-exit watched command instead of terminating and re-spawning it when any `cron.*` config key changes.

## Best Possible Solution

Land a narrow fix like https://github.com/openclaw/openclaw/pull/99724 that stops only scheduling on cron hot reload, reuses live exit watcher state, refreshes callbacks, and still cancels watchers for shutdown or real job changes.

## Reproduction Assessment

Yes. Source inspection on current main shows `cron.*` reload maps to `restartCron`, the handler calls `stopExitWatchers` before rebuilding, and the watcher keeps active children in an instance-local map; the reporter's real-child-process seam proof matches that path.

## Solution Assessment

Yes. The best fix is to preserve or transfer live unchanged watcher state across cron hot reload while preserving cancellation for shutdown and real job changes; the open candidate PR follows that shape, but this issue should stay open until it merges.
