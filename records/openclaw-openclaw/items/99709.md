## Summary

Keep open: current main still restarts cron for `cron.*` changes by stopping the cron service and canceling exit watchers before building a fresh watcher instance, so the reported in-flight watched-command re-execution path remains source-valid. The issue is now paired with an open fixing PR, so it should stay open until that PR lands or is closed.

## What This Changes

Report that cron hot reload can cancel and re-execute an in-flight on-exit watched command when any cron config key changes.

## Best Possible Solution

Land or revise the open fix PR so unchanged on-exit watchers survive cron hot reload, while shutdown, cron disable, job removal, command/cwd change, and cron store changes still use the correct cancellation semantics.

## Reproduction Assessment

Yes. Source inspection on current main shows the `cron.*` hot-reload path cancels the existing exit watcher manager and reconciles a fresh instance; the issue and linked PR also provide seam proof with a real child process.

## Solution Assessment

Yes, with the open PR’s store-path guard resolved. The maintainable solution is to preserve the existing watcher manager across same-store cron hot reloads and let reconciliation cancel only real removals or changed jobs.
