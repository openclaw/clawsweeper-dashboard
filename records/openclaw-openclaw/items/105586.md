## Summary

The current-main detector classifies queued terminal embedded-run progress as stalled and logs `terminalProgressStale=true`, but the recovery executor still uses only progress age and can repeatedly keep an active-reply lane on busy channels. No open linked PR owns this distinct fix, so the issue remains necessary and is a strong narrow repair candidate.

## What This Changes

Treat queued terminal diagnostic run progress as stale in active embedded reply-work recovery so busy channel lanes can self-recover.

## Best Possible Solution

Make the active-reply recovery predicate consume the existing terminal-progress helper, retain progress-age fallback for non-terminal wedges, and add regression coverage for busy activity plus a healthy successor run.
