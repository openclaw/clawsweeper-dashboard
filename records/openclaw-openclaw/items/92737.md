## Summary

Keep open: current main and the latest release still route Android `camera.list` through `ProcessCameraProvider.getInstance()`, so the privacy-sensitive metadata path is not fixed; recent merged camera PRs only addressed snap/clip cleanup.

## What This Changes

The issue asks Android to avoid initializing CameraX/camera hardware on app open or metadata listing before a user-requested capture.

## Best Possible Solution

Make Android `camera.list` use `CameraManager`/`CameraCharacteristics` metadata only, keep `ProcessCameraProvider` initialization inside `camera.snap` and `camera.clip`, and verify app launch plus metadata listing on a real Android 13+ device.

## Reproduction Assessment

No high-confidence full app-open reproduction exists from this read-only review. Source inspection does reproduce the narrower `camera.list` path reaching `ProcessCameraProvider.getInstance()`, which is enough to keep the issue open.

## Solution Assessment

Yes for the confirmed code path: metadata-only `CameraManager` listing is the narrowest maintainable fix while leaving CameraX for actual capture. The app-open caller path should be verified before changing gateway advertisement or command policy.
