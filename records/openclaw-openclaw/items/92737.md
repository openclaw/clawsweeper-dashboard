## What This Changes

The issue reports that opening the Android app eagerly initializes CameraX through camera device listing, causing Android’s camera privacy indicator to appear before any capture command.

## Best Possible Solution

Keep this open until Android `camera.list` uses metadata-only Camera2 enumeration and a real Android 13+ run proves app launch/listing do not light the camera indicator.

## Reproduction Assessment

Source-reproducible for the narrower code path: current main routes `camera.list` to `CameraCaptureManager.listDevices()`, which calls `ProcessCameraProvider.getInstance()`. The full app-open green-dot trigger has not been reproduced on a real Android 13+ device in this review.

## Solution Assessment

Yes for the confirmed code path: make `camera.list` use metadata-only Camera2 APIs and keep CameraX initialization inside `camera.snap` and `camera.clip`. The startup caller should be verified before changing gateway advertisement behavior.
