## Summary

Keep open: current main and the latest release still route Android `camera.list` through `ProcessCameraProvider.getInstance()`, and the merged camera cleanup PR only addressed snap/clip teardown rather than the premature metadata-listing path. The app-open trigger still needs real Android proof, but the remaining source-level privacy concern is concrete enough that this item is still necessary.

## What This Changes

The issue reports that opening the Android app eagerly initializes CameraX and shows the Android camera privacy indicator before any capture command is requested.

## Best Possible Solution

Move Android `camera.list` device enumeration to Camera2 metadata, keep CameraX provider initialization inside actual capture commands, and verify app launch plus metadata listing on a real Android 13+ device.

## Reproduction Assessment

No high-confidence live reproduction exists in this read-only review. Source inspection reproduces the narrower `camera.list` path reaching `ProcessCameraProvider.getInstance()`, while the app-open trigger still needs Android device proof.

## Solution Assessment

Yes for the confirmed code path: moving `camera.list` to Camera2 metadata is the narrowest maintainable fix. Gateway advertisement policy should not change unless live proof shows app open invokes listing independently.
