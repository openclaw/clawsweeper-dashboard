## Summary

Keep open: current main still routes Android `camera.list` through `ProcessCameraProvider.getInstance()`, and the latest release has the same metadata-listing path. The merged Android camera cleanup PRs fixed post-capture `snap`/`clip` teardown, but they do not implement the requested lazy/non-opening camera listing path, and the app-open trigger still needs real Android proof.

## What This Changes

The issue asks Android camera capability listing/startup to avoid initializing CameraX so the camera privacy indicator appears only during intentional capture.

## Best Possible Solution

Move Android `camera.list` to Camera2 `CameraManager`/`CameraCharacteristics` metadata, keep `ProcessCameraProvider` initialization inside `camera.snap` and `camera.clip`, and verify app launch plus `camera.list` on a real Android 13+ device.

## Reproduction Assessment

No high-confidence live reproduction exists for the full app-open behavior in this read-only review. Source inspection does reproduce the narrower current-main path where `camera.list` reaches `ProcessCameraProvider.getInstance()` before capture.

## Solution Assessment

Yes for the confirmed code path: replacing `camera.list` with Camera2 metadata is the narrowest maintainable fix. The recent snap/clip cleanup PRs are useful but are not the best fix for this issue because they address post-capture cleanup rather than eager metadata listing.
