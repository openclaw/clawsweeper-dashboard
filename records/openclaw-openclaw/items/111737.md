## Summary

The device-code path is hardened and well demonstrated, but the proposed solution is incomplete: xAI refresh-token exchange remains a sibling OAuth token-response path that needs the same fatal UTF-8 handling before this auth-integrity fix is ready to merge.

## What This Changes

The PR changes xAI device-code token-response decoding to reject malformed UTF-8 before JSON parsing and adds a regression test for that login path.

## Best Possible Solution

Centralize strict UTF-8 JSON decoding for xAI OAuth token responses, use it for both device-code polling and refresh exchange, and add malformed-byte coverage for each persistence-capable path.
