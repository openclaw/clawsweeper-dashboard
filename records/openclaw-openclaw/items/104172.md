## Summary

This PR remains necessary because current `main` does not count live background execs during suspension or safe restart, but the proposed patch still clears its new blocker too early in fallback kill/remove paths. The earlier live proof convincingly covers normal child exit, yet the current exact head also lacks equivalent live proof after its force-push.

## What This Changes

The PR adds live background-exec accounting to Gateway suspension and safe-restart decisions, including aggregate protocol blockers, detached-exec handoff logic, tests, and docs.

## Best Possible Solution

Separate termination request from confirmed terminal state: retain count-only lifecycle activity until a supervisor exit event or fallback liveness check proves the PID tree is gone, then verify kill, remove, suspension, and safe restart on the exact final head.

## Reproduction Assessment

Yes, at source level. A background session without an active supervisor record takes the fallback kill/remove branch, which requests tree termination and immediately clears lifecycle activity through `markExited`.

## Solution Assessment

No, not yet. The shared count-only registry and active-work snapshot are the correct ownership layer, but the implementation must enforce confirmed exit across every terminal caller instead of treating a fallback kill request as completed termination.
