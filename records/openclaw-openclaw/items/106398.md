## Summary

Keep this PR open: the implementation appears technically sound and fixes a source-reproducible concurrency-accounting bug, but the external contribution still provides only controlled fake-timer proof and changes the availability failure mode when listeners never settle.

## What This Changes

The PR separates Discord dispatch timeout settlement from listener settlement so timed-out listeners retain their concurrency slots until the underlying promises finish, with focused regression coverage.

## Best Possible Solution

Keep the single-start promise and settlement-based slot accounting, but require redacted live-runtime evidence and explicit acceptance that permanently hung listeners produce bounded queue saturation rather than unbounded background execution.
