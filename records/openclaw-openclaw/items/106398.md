The latest head only merges newer `main`; it does not add live Discord evidence beyond the mock-controlled proof from the prior review.

## What This Changes

The PR changes Discord gateway event-queue accounting so timed-out listeners retain concurrency slots until their underlying promises settle, and adds regression coverage for queueing, late rejection, and recovery.

## Best Possible Solution

Keep the slot-retention implementation only if the Discord owner confirms that `maxConcurrency` must bound still-running listeners even when that permits full queue saturation, then require redacted real-runtime proof showing timeout, blocked queue progress, late settlement, and recovery before merge.
