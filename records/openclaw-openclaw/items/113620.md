## Summary

Keep this PR open. It addresses the linked Feishu configuration bug with a focused shared-schema change and regression coverage, but it still lacks after-fix proof from a real Feishu configuration reaching channel startup; the reported test run is supplemental rather than real behavior proof.

## What This Changes

The PR updates Feishu custom-domain validation so uppercase or mixed-case HTTPS schemes are accepted and canonicalized before the Feishu channel passes the configured base URL to the Lark SDK.

## System Context

Feishu channel configuration is parsed during plugin setup, including a top-level custom domain and per-account overrides. The validated domain then flows through Feishu domain resolution into the Lark SDK client used by the running channel.
