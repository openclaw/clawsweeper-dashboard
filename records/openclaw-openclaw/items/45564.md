## Summary

Keep open. Current main and the latest release still leave explicit typed `/new` and hard `/reset` behavior unconfirmed in the Control UI and TUI, while the already-merged button work only covers an adjacent UI affordance; this needs maintainer UX/config policy before implementation.

## What This Changes

The issue requests a confirmation flow for destructive typed `/new` and `/reset` session wipe commands, with optional configuration and loss summary context.

## Best Possible Solution

Define one maintainer-approved hard-reset confirmation contract for explicit commands across Control UI, TUI, and channel/Gateway paths, with no new config knob unless maintainers explicitly accept the compatibility cost.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 tests and handlers show typed `/new` and hard `/reset` bypass confirmation in Control UI, and the TUI command handler resets or rotates sessions immediately.

## Solution Assessment

Unclear as an implementation direction. A single repeat-within-timeout confirmation may be the right UX, but confirmation depth, config shape, timeout behavior, and which command surfaces change need maintainer approval first.
