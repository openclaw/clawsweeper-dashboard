## Summary

Keep open. Current main and v2026.6.11 still preserve unconfirmed typed `/new` and hard `/reset`; the merged button-confirmation work only fixed an adjacent Control UI affordance, while the remaining command-confirmation and config policy needs maintainer direction.

## What This Changes

The issue requests a confirmation step for typed `/new` and `/reset` session-wipe commands, with an optional configurable confirmation policy.

## Best Possible Solution

Adopt one maintainer-approved hard-reset confirmation policy across explicit command surfaces, likely a single short-lived confirmation for typed `/new` and hard `/reset` with `/reset soft` exempt, and avoid a new config knob unless maintainers explicitly choose an opt-out.
