## Summary

Keep open. Current main still protects only the Control UI override/button path; typed `/new`, typed `/reset`, Gateway/channel reset handling, bare Gateway agent requests, and TUI session commands can still rotate or reset sessions without a confirmation step.

## What This Changes

The issue requests a confirmation step, preferably optionally configurable, before `/new` or `/reset` wipe or replace the active session.

## Best Possible Solution

Define one shared default-safe confirmation contract for destructive manual session resets across Control UI, TUI, Gateway, and channel command paths; add config only if maintainers explicitly approve an opt-out surface.
