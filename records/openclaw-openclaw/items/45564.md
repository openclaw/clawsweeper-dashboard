## Summary

Keep open. Current main and the latest release still leave destructive manual reset command paths immediate outside the already-guarded Control UI button flow, so this issue remains valid and needs maintainer product direction for the confirmation UX and any config opt-out.

## What This Changes

The issue requests a confirmation step before `/new` and `/reset` wipe or replace session context, with discussion favoring a short double-submit confirmation and optionally a config knob.

## Best Possible Solution

Define one default-safe confirmation contract for destructive manual session resets across Control UI, TUI, Gateway, and channel command paths, with docs and tests; add config only if maintainers explicitly approve an opt-out surface.
