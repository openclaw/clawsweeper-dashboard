## Summary

Keep open. Current main and v2026.6.11 still preserve unconfirmed typed `/new` and hard `/reset` behavior, while the merged confirmation work only covered button-triggered resets; the remaining command-confirmation and config policy needs maintainer direction.

## What This Changes

The issue requests a confirmation step for typed `/new` and `/reset` session-wipe commands, ideally with a configurable number of confirmation steps.

## Best Possible Solution

Adopt one maintainer-approved hard-reset confirmation policy across explicit command surfaces, likely a single confirmation for `/new` and hard `/reset` with `/reset soft` exempt, and avoid a new config knob unless maintainers explicitly choose an opt-out.
