## Summary

Keep open. Current main still only protects the Control UI button-triggered New Session path; typed `/new`, typed `/reset`, Gateway/channel command handling, bare Gateway agent requests, and TUI reset commands still reset immediately, so the central request remains unresolved and needs maintainer product direction.

## What This Changes

The issue requests a confirmation step before `/new` and `/reset` wipe the active session, ideally with a configurable confirmation count.

## Best Possible Solution

Define one default-safe confirmation contract for destructive manual session resets across Control UI, TUI, Gateway, and channel command paths, with docs and tests; add config only if maintainers explicitly approve an opt-out surface.
