## Summary

Keep open. Current main protects only the button-triggered Control UI New Session path; typed `/new`, hard `/reset`, Gateway/auto-reply command handling, and TUI commands still execute session replacement or reset immediately, so the remaining work needs maintainer product direction.

## What This Changes

The issue requests a confirmation flow, ideally configurable, before `/new` or `/reset` wipes or replaces active session state.

## Best Possible Solution

Define one default-safe confirmation contract for destructive manual session resets across Control UI typed input, TUI, Gateway, and channel command paths, with config added only if maintainers explicitly approve an opt-out surface.
