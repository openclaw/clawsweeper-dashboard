## Summary

Keep open. Current main still leaves typed Control UI `/new` and hard `/reset`, TUI `/new` and `/reset`, and Gateway/channel bare reset commands unconfirmed; PR #73361 only guarded button-triggered Control UI New Session resets, so the remaining command/config policy still needs maintainer direction.

## What This Changes

Request to add confirmation before `/new` and hard `/reset` session wipes, optionally with configurable confirmation steps.

## Best Possible Solution

Adopt one maintainer-approved hard-reset confirmation policy across explicit command surfaces, likely a single confirmation for `/new` and hard `/reset` with `/reset soft` exempt, and avoid a new config knob unless maintainers explicitly choose an opt-out.

## Solution Assessment

Unclear pending maintainer policy. A one-step confirmation for `/new` and hard `/reset` is more maintainable than 2-3 confirmations, but config and cross-client parity need owner direction before implementation.
