## Summary

Keep open. Current main still confirms only the button-triggered Control UI New Session override path; typed `/new`, typed `/reset`, Gateway/channel command handling, and TUI reset commands still execute immediately, so the core request remains unresolved and needs maintainer product direction.

## What This Changes

The issue requests a confirmation step, ideally configurable, before destructive manual `/new` and `/reset` session resets.

## Best Possible Solution

Define one default-safe confirmation contract for destructive manual session resets across Control UI typed input, TUI, Gateway, and channel command paths, with docs and tests; add config only if maintainers explicitly approve an opt-out surface.
