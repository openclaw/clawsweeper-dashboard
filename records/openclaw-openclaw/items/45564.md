## Summary

Keep open. Current main still leaves the central typed-command request unresolved: Control UI has a confirmation helper only for override/button-triggered resets, while typed `/new`, typed `/reset`, Gateway command handling, channel/auto-reply command handling, and TUI reset commands still execute immediately.

## What This Changes

The issue requests a confirmation step for destructive `/new` and `/reset` session resets, ideally with configurable confirmation depth.

## Best Possible Solution

Define one default-safe confirmation contract for destructive manual session resets across Control UI, TUI, Gateway, and channel command paths, with docs and tests; add config only if maintainers explicitly approve an opt-out surface.
