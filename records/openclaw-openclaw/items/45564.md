## Summary

Keep open. Current main and v2026.6.11 still confirm only button-triggered Control UI new-session resets, while typed `/new`, typed hard `/reset`, and TUI reset commands remain immediate; the remaining confirmation and optional config behavior needs maintainer product direction.

## What This Changes

The issue requests a confirmation step, ideally configurable, before `/new` or `/reset` wipes or replaces the active session.

## Best Possible Solution

Adopt one maintainer-approved destructive-command policy across command surfaces, likely a single confirmation for `/new` and hard `/reset` with `/reset soft` exempt, and add config only if maintainers accept that public surface.

## Solution Assessment

Unclear pending maintainer policy. A one-step hard-reset confirmation appears more maintainable than the requested two or three steps, and the config knob should not be added unless maintainers choose that public surface.
