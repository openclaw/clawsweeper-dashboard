## Summary

Keep open. Current main and v2026.6.11 still leave manual typed `/new` and hard `/reset` command paths immediate outside the already-guarded Control UI override flow, so the issue remains valid and needs a maintainer product decision for cross-surface confirmation behavior and any config opt-out.

## What This Changes

The issue requests a confirmation step, ideally configurable, before `/new` or `/reset` wipes or rotates a session.

## Best Possible Solution

Define one default-safe confirmation contract for destructive manual session resets across Control UI, TUI, Gateway, and channel command paths, with docs and tests; add config only if maintainers explicitly approve an opt-out surface.
