## Summary

Keep open. Current main and v2026.6.11 still leave manual typed `/new` and hard `/reset` paths immediate outside the already-guarded Control UI button flow, so the remaining work is a real cross-surface destructive-command policy decision rather than cleanup-close material.

## What This Changes

The issue requests a confirmation step, ideally configurable, before destructive `/new` and `/reset` session-reset commands run.

## Best Possible Solution

Define one default-safe confirmation contract for destructive manual session resets across Control UI typed input, TUI, Gateway, and channel command paths; add config only if maintainers explicitly approve an opt-out surface.
