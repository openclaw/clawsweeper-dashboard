## Summary

Keep open. Current main and v2026.6.11 still confirm only button-triggered reset overrides; typed Control UI `/new` and hard `/reset`, plus TUI `/new` and `/reset`, remain unconfirmed and need maintainer UX/config policy before implementation.

## What This Changes

The issue requests a confirmation step before destructive `/new` and `/reset` session resets, optionally with configurable confirmation depth and a summary of what would be cleared.

## Best Possible Solution

Define one canonical destructive-command policy for typed `/new` and hard `/reset` across Control UI and TUI, preserve `/reset soft`, and avoid a new config knob unless maintainers explicitly approve the schema and migration/docs work.
