## Summary

Keep open. Current main still only confirms button-triggered Control UI New Session resets; typed Control UI commands, TUI commands, and Gateway/channel bare reset commands remain immediate, so the remaining confirmation/config policy needs maintainer product direction.

## What This Changes

The issue requests a confirmation step, ideally configurable, before `/new` and `/reset` reset or replace a session.

## Best Possible Solution

Adopt one maintainer-approved policy for hard reset confirmations across Control UI, TUI, and Gateway/channel commands; prefer one confirmation for `/new` and hard `/reset`, exempt `/reset soft`, and avoid config unless explicitly approved.
