## Summary

Keep open. Current main still has immediate manual reset paths for typed `/new` and `/reset` in chat, TUI, Gateway/channel command handling, and bare Gateway agent requests; the already-shipped Control UI button work only covers part of the accidental-reset problem.

## What This Changes

The issue requests a confirmation flow, possibly configurable, before `/new` or `/reset` wipes or rotates the current session.

## Best Possible Solution

Define one default-safe confirmation contract for destructive manual session resets across Control UI, TUI, Gateway, and channel command paths, with docs and tests; add config only if maintainers explicitly want an opt-out surface.
