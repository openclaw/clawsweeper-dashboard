## Summary

Keep open. Current main and v2026.6.11 still preserve immediate typed `/new` and destructive `/reset` behavior in Control UI/TUI, while the merged button-confirmation and soft-reset fixes only cover adjacent parts of the session-reset surface.

## What This Changes

Request adds a confirmation step, possibly configurable, before `/new` and destructive `/reset` clear or replace session state.

## Best Possible Solution

Define one maintainer-approved confirmation contract for destructive explicit session commands, with tests/docs across chosen surfaces and any config or opt-out added only after the policy is approved.
