## Summary

Keep open. Current main and v2026.6.11 still leave typed `/new` and hard `/reset` unconfirmed, while the merged button/plus work only addressed an adjacent Control UI affordance; the remaining command-confirmation and config policy needs maintainer direction.

## What This Changes

Request a confirmation step, ideally configurable, before destructive typed `/new` and hard `/reset` session resets.

## Best Possible Solution

Adopt one maintainer-approved hard-reset confirmation policy across explicit command surfaces, likely a single confirmation for `/new` and hard `/reset` with `/reset soft` exempt, and avoid a new config knob unless maintainers explicitly choose an opt-out.

Unclear pending maintainer policy. A one-step confirmation looks more maintainable than the requested 2-3 confirmations, but config and cross-client parity need an owner decision before implementation.
