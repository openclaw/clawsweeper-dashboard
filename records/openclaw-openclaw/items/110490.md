## Summary

Keep this issue open: the supplied prior review indicates current main resolved the legacy plugin-index convergence deadlock, but generated macOS LaunchAgents still discard gateway stderr, leaving operators unable to diagnose a separate fail-closed crash loop. The remaining service-diagnostics behavior needs an owner decision on the supported log location and treatment of explicit operator overrides.

## What This Changes

Report that macOS LaunchAgent regeneration writes gateway stderr to `/dev/null` and that the v2026.7.1 legacy plugin-index migration could not converge through `doctor --fix`.

## Best Possible Solution

Narrow the remaining work to macOS service diagnostics: generate a supported local stderr log destination and define whether explicit operator redirects are preserved or managed through an OpenClaw-owned setting, without reopening the already-addressed legacy-index merge behavior.

- **Keep stderr suppressed:** Retain `/dev/null` and rely on another structured diagnostic path, only if that path demonstrably captures startup failures before launchd restarts.
