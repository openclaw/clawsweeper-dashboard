## Summary

Keep this maintainer-authored, protected-label PR open for security-boundary review. The new recovery owner resolver uses the raw Gateway connect-device identifier despite the adjacent client contract exposing `pairedClientId` as the server-verified pairing identity; that can let a caller select another device’s recoverable hosted setup identity if the raw identifier is client-controlled.

## What This Changes

The branch adds cancellation, durable-effect locking, reconnect ownership, and retained completion handling for hosted channel-setup wizards used through Gateway RPC and system-agent chat.

## System Context

Gateway-hosted channel setup creates an in-memory wizard session that asks channel configuration questions and eventually writes configuration or installs a plugin. This PR threads the session’s cancellation and ownership information through channel setup, then lets Gateway and system-agent callers recover locked work and owner-bound terminal results after reconnecting.

  D --> E{Durable effect begins?}
  E -->|No| F[Cancellation or idle expiry]
  E -->|Yes| G[Locked owner-bound work]
  G --> H[Reconnect recovery and result delivery]

## Best Possible Solution

Bind device-scoped hosted-wizard recovery exclusively to the server-verified paired-client identity, retain the existing user/shared-auth routes only where their authentication contracts are explicit, and add an adversarial recovery test proving a spoofed connect-device id cannot adopt or read another caller’s locked work.
