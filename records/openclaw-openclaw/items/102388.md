## Label Justifications

- `P0`: The issue reports deterministic persistence of provider credential values into debug capture storage, which is a high-severity sensitive-data exposure.
- `impact:security`: The affected behavior can leave credentials in persisted diagnostic storage and same-process sentinel maps.
- `impact:auth-provider`: The secrets involved are provider credentials resolved through SecretRef and sentinel auth paths.
- `maturity:stable`: The affected debug proxy, WebSocket diagnostics, and security-control surface falls under `gateway-runtime`, which the maturity shortlist marks M4 Stable.

## Summary

Keep open: current main still has the reported WebSocket capture and sentinel-retention behavior, and the protected `maintainer` label blocks conservative cleanup closure even if the path is well understood.

## What This Changes

The issue asks for exact-value redaction before debug WebSocket capture persistence and for process-local secret sentinels to stop retaining historical plaintext credentials.

## Best Possible Solution

Redact registered exact values before any WebSocket capture field or blob is persisted, add regression coverage for URL/payload/error/meta capture, and bound or revoke sentinel plaintext maps under an explicit security-owned lifetime contract.
