## Summary

Keep this PR open: its intended hardening is valuable, but the current head still has a P1 legacy-store regression in transcript search and the PR body supplies tests/autoreview rather than after-fix runtime proof. The protected `maintainer` label also calls for explicit maintainer handling before merge.

## What This Changes

The PR changes gateway session describe, search, and abort resolution so unknown agent IDs do not provision persistent agent stores while existing configured, retired, legacy, shared-store, and active-run sessions remain reachable.

## Best Possible Solution

Keep all lookup-only gateway operations non-provisioning: search legacy-only stores through a read-only/missing-database path, preserve their legacy contents, and add focused runtime proof that neither unknown nor legacy-only requests create persistent agent state.

## Solution Assessment

No. Rejecting unknown agents is the right boundary, but the proposed legacy-only transcript-search path still crosses that boundary by opening a missing writable SQLite database; it needs a genuinely read-only legacy/missing-store path.
