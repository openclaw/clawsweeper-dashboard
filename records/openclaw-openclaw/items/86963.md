## What This Changes

The issue requests that OpenClaw prevent a persisted oversized or orphaned native Codex thread from accepting a chat send without ever starting a run or surfacing an error.

## System Context

Inbound chat messages enter the gateway's agent-run pipeline, which invokes the Codex plugin to resume or replace a persisted native thread and start a Codex turn. The resulting lifecycle events determine whether the transcript and channel receive a durable reply or a recoverable failure.

## Architecture Diagram

flowchart TD
  A[Inbound chat message] --> B[Gateway run admission]
  B --> C[Codex native-thread binding]
  C --> D{Resume or rotate thread}
  D --> E[Codex turn start]
  E --> F{Turn actually starts}
  F -->|yes| G[Transcript and reply delivery]
  F -->|no or stalled| H[Bounded recovery or visible error]

## Best Possible Solution

Define a single bounded post-submission liveness contract: wait for the matching Codex turn to start, then either recover through a safely deduplicated fresh-thread path or return a visible, durable failure instead of reporting a successful send.
