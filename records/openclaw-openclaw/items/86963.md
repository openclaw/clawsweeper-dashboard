## Summary

Keep open: current main has relevant Codex native-thread overflow and compaction mitigations, but I did not find proof that the reported `chat.send` accepted/no-run wedge is fixed or superseded.

## What This Changes

The issue asks OpenClaw to prevent WebChat/Codex sessions from returning `chat.send` `started` when an oversized persisted native Codex thread prevents any agent run or transcript write.

## Best Possible Solution

Define and implement a liveness contract where `chat.send` either reaches dispatch and Codex `turn/start`, safely rotates the native thread first, or returns/surfaces a visible auditable failure instead of silent `started`.
