## Summary

## What This Changes

The issue asks OpenClaw to prevent WebChat/Codex sessions from returning `chat.send` as started when an oversized or orphaned native Codex thread prevents any run or transcript write.

## Best Possible Solution

Define and prove a WebChat/Codex liveness contract: after `chat.send` ACK, dispatch and Codex turn startup progress, the native thread safely rotates, or the user gets a visible auditable failure.
