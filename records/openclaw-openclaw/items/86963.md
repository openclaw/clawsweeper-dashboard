## What This Changes

The issue requests reliable recovery or visible failure when a persisted oversized or orphaned Codex app-server thread accepts a chat send but never runs the agent turn.

## System Context

The Codex plugin maps an OpenClaw session to a persisted native Codex app-server thread. Before a new agent turn starts, its startup and route preparation decide whether to resume the stored thread or discard it and start a fresh one; the resulting turn writes the normal session transcript and channel reply.

  B --> C[Codex native-thread binding]
  C --> D{Binding safe to resume?}
  D -->|No: oversized or stale| E[Clear binding and start fresh thread]
  D -->|Yes| F[Resume native thread]
  E --> G[Start agent turn]
  F --> G
  G --> H[Transcript and channel reply]

## Best Possible Solution

Keep the existing pre-turn native-binding safety path and its regression coverage; new reports should include a current-release reproduction if a distinct accepted-send/no-run path remains.
