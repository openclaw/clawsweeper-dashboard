## Summary

Keep open: the reported permanent accepted-send/no-run failure remains materially different from the merged oversized-thread rotation and compaction-timeout recovery work in the supplied history. Those changes are relevant safeguards, but the available evidence does not prove that current main either starts a run or returns a visible failure when a persisted Codex thread wedges after `chat.send` has been accepted.

## What This Changes

Prevent a persisted oversized or orphaned Codex native thread from silently accepting chat messages without ever executing an agent run or recording the message.

## System Context

WebChat and other channels submit a user message through Gateway dispatch into an agent session. For Codex-backed sessions, the Codex plugin resumes or rotates a persisted native app-server thread before the run begins; a failure in that handoff must not leave the accepted message without a run or user-visible outcome.

## Best Possible Solution

Define a single liveness contract at the Gateway-to-Codex handoff: after an accepted message, either durably start/queue the run or surface a terminal visible error, while rotating only demonstrably unsafe native bindings and preserving a diagnostic/recovery path for the affected session.

- **Fail fast only:** Return an actionable error without automatic rotation when native-thread preflight cannot prove the binding is safe.
