## Summary

Keep open: current main has several adjacent Codex native-thread rotation and continuity fixes, but I found no proof that the reported `chat.send` accepted/no-run silent message-loss wedge is fixed or safely superseded.

## What This Changes

The issue asks OpenClaw to prevent Codex-backed WebChat sessions from returning `started` for sends that never dispatch, persist, or run when a native Codex thread is orphaned or oversized.

## Best Possible Solution

Define and implement a Codex/WebChat liveness contract where accepted sends either reach dispatch and Codex turn startup, safely rotate the native thread first, or fail visibly before returning `started`.
