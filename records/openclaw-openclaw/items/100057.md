## Summary

Keep this PR open, but the current patch is not merge-ready: it adds a plausible, proof-backed Dreaming allowlist, yet it also makes the shared Dreaming workspace helper scoped for existing doctor migrations that must continue scanning every configured memory workspace.

## What This Changes

The PR adds `plugins.entries.memory-core.config.dreaming.agents`, applies that allowlist to Dreaming workspace selection and doctor status, keeps public artifact discovery unscoped, and updates docs, manifest schema, tests, and generated baseline hashes.

## Best Possible Solution

Split scoped and unscoped memory workspace resolution: Dreaming sweeps and doctor status should honor `dreaming.agents`, while doctor migrations and public artifact discovery keep scanning all configured memory workspaces, with regression coverage for both paths.

## Reproduction Assessment

Not applicable as a bug reproduction for the feature request; source inspection confirms current main sweeps all configured Dreaming workspaces and the PR changes that behavior. The introduced migration regression is source-reproducible because an unchanged doctor migration caller now receives allowlist-scoped workspaces from the changed helper.

## Solution Assessment

No. The global allowlist is a plausible minimum feature, but the implementation should keep doctor migrations on an unscoped resolver while only Dreaming sweep/status paths honor the allowlist.
