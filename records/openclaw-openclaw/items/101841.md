## Summary

Keep this PR open: the design is valuable and well-tested at unit level, but the current head still allows iframe reloads to reset the publish quota and does not include after-fix browser proof of the real widget-to-widget flow.

## What This Changes

Adds a capability-gated, parent-brokered publish/subscribe API for JSON messages between approved custom widgets in the same Workspaces tab.

## Best Possible Solution

Keep the parent-owned tab broker, strict JSON normalization, and capability gate, but make publish accounting survive iframe reconnects for the lifetime of the host-bound widget connection and prove the complete flow with a redacted browser recording or linked Playwright artifact.

## Reproduction Assessment

Yes, the remaining defect is source-reproducible: reload or reconnect the iframe so `attachWidgetBridge` constructs a fresh `WidgetBridge`, which resets bridge-local publish timestamps while retaining the widget's bus access.

## Solution Assessment

No, not yet. A parent-owned in-memory broker is the right architectural boundary, but the quota must share the host connection's lifetime rather than the replaceable iframe bridge, followed by real browser proof.
