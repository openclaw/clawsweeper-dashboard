## Summary

This PR remains necessary because current main still starts every sweep tick unconditionally. The single-flight guard and finite probe timeout address the overlap and permanent-stall paths without changing public API or configuration; no actionable patch defect remains, but the branch should be refreshed from current main before merge.

## What This Changes

The PR adds a single-flight interval guard and a 15-second Discord REST timeout to thread-binding sweeps, with regression coverage for overlap and recovery paths.

## Best Possible Solution

Keep one account-scoped sweep in flight, bound every Discord channel probe with the existing request-client timeout contract, and always release the guard so later scheduled sweeps can recover.

## Solution Assessment

Yes. Combining a single-flight guard with a finite request timeout is the narrow root-cause fix because the guard prevents duplicate sweeps while the timeout ensures one stalled request cannot disable sweeping permanently.
