## Summary

Keep open. Current main and v2026.6.11 partially cover sanitized tool execution diagnostics, but the requested ToolResultMessage error fields, soft-error diagnostic classification on main, and a general write/edit/memory writeback audit contract are still missing.

## What This Changes

Issue requests safer tool-call observability: sanitized input summaries, structured tool error categorization, and metadata about file/memory writebacks.

## Best Possible Solution

Define a bounded additive diagnostics/writeback contract that defaults to redacted metadata, then align ToolResultMessage or diagnostic event types, runtime emitters, exporters, docs, and focused tests through maintainer-approved follow-up work.

## Reproduction Assessment

Yes, at source level. Current main shows partial sanitized tool events and diagnostic errorCategory support, while ToolResultMessage lacks the requested structured error fields and no general write/edit/memory writeback audit surface was found.

## Solution Assessment

Unclear as requested. A schema-first metadata-only diagnostics/writeback contract is likely the maintainable path, while raw INFO logging or unbounded writeback content would be unsafe until privacy and compatibility semantics are settled.
