## Summary

Keep open. Current main now has redaction-safe tool execution diagnostics and a metadata-only audit ledger, but the requested ToolResultMessage error fields and write/edit/memory writeback audit contract remain unresolved product and security work.

## What This Changes

The issue requests sanitized tool-call input observability, structured tool-result error categorization, and context writeback tracking for files or memory changed by tools.

## Best Possible Solution

Define a schema-first, metadata-only diagnostics/audit contract for tool writebacks and tool-result error codes, keep raw content behind explicit content-capture settings, and split implementation into narrow PRs after maintainer sign-off.
