  - body: `broadcastPush` stores the full JSONL payload and sends it to every Activity WebSocket client without a size limit or backpressure check.   - confidence: 0.84
- **[P2] Fix the launch test to use a guild interaction:** `src/discord/monitor/monitor.test.ts:325-329`
  - body: The handler rejects `launch-activity` when `rawData.guild_id` is missing, but this new test constructs rawData without a guild id and still expects the REST launch callback. Add a guild id to cover the allowed path or assert the DM rejection path separately.
  - confidence: 0.88

## Security Review

Status: needs_attention

Summary: The diff introduces a public Activity auth bypass path, URL-token handling, and unbounded Activity WebSocket broadcasts that need hardening before merge.

Concerns:

- **[high] Activity mode bypasses Gateway auth without a token:** `src/gateway/a2ui-activity.ts:35`
  - body: When `activity.enabled` is true and `activity.token` is blank, `isA2uiActivityAccessAllowed` returns true; `server-http.ts` checks that before bearer/capability auth for A2UI HTTP and WS requests.
  - confidence: 0.93
- **[medium] Activity token travels in URLs and can use plain WS:** `src/canvas-host/a2ui/index.html:321`
  - body: The A2UI page reads `activityToken` from the URL and appends it to the WebSocket URL, using `ws://` when served over HTTP, which can leak the token through logs/history or cleartext transport.
  - confidence: 0.78
- **[medium] Activity hub lacks resource limits:** `src/gateway/a2ui-activity.ts:79`
  - body: The hub retains the last JSONL payload and sends it to all clients without payload-size or bufferedAmount checks, creating denial-of-service risk on a Gateway-owned server path.
  - confidence: 0.84
