  - confidence: 0.9

  - body: `broadcastPush` stores the full JSONL payload and sends it to every Activity WebSocket client without a size limit or backpressure check. A large A2UI payload or slow clients can grow memory and stall the Gateway; cap payload size and terminate/drop clients with excessive buffered data.
  - confidence: 0.84

## Security Review

Status: needs_attention

Summary: The diff introduces a public Activity auth bypass path and unbounded Activity WebSocket broadcast state that need security hardening before merge.

Concerns:

- **[high] Activity mode bypasses Gateway auth without a token:** `src/gateway/a2ui-activity.ts:35`
  - body: When Activity mode is enabled and `activity.token` is blank, `isA2uiActivityAccessAllowed` returns true; `authorizeCanvasRequest` checks that before bearer/capability auth, exposing A2UI HTTP/WS without Gateway auth.
  - confidence: 0.92
- **[medium] Activity token travels through URL query strings:** `src/canvas-host/a2ui/index.html:321`
  - body: The A2UI page reads `activityToken` from the URL and appends it to the WebSocket URL, which can leak through logs/history and uses `ws://` when the page is served over HTTP.
  - confidence: 0.78
- **[medium] Activity hub lacks resource limits:** `src/gateway/a2ui-activity.ts:79`
  - body: The hub retains the last JSONL payload and sends it to all clients without payload-size or bufferedAmount checks, creating a denial-of-service risk on a Gateway-owned server path.
