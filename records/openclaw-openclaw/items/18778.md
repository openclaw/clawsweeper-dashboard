Full review comments:

- **[P1] Port the Discord changes into current plugin paths:** `src/discord/components.ts:365-373`
  - body: This branch still adds the launch action under old `src/discord/**` files and the core message-tool schema, but current main has moved Discord component parsing/runtime to `extensions/discord/src/**`. As a result the PR is dirty and the feature would either fail to land or recreate behavior outside the current Discord plugin owner boundary.
  - confidence: 0.93
- **[P1] Require Activity credentials before bypassing Gateway auth:** `src/gateway/a2ui-activity.ts:34-37`
  - body: When `canvasHost.activity.enabled` is true but no token is configured, `isA2uiActivityAccessAllowed` returns true, so a public A2UI request bypasses the normal Gateway auth gate. Activity access needs to fail closed unless an explicit Activity credential or launch-context check is present.
  - confidence: 0.95
- **[P1] Move Activity config under the Canvas plugin contract:** `src/config/types.gateway.ts:39-55`
  - body: The PR adds `canvasHost.activity` to the root Gateway config, but current main moved Canvas host ownership to the Canvas plugin and migrates legacy root `canvasHost` into `plugins.entries.canvas.config.host`. Adding a new root child here creates a second config source that doctor/runtime will not treat as the canonical Canvas plugin contract.
  - confidence: 0.92
- **[P1] Stop carrying Activity tokens in URLs:** `src/canvas-host/a2ui/index.html:321-325`
  - body: The Activity page reads `activityToken` from the page URL and reuses it in the WebSocket URL. That makes the shared access credential likely to leak through browser history, reverse-proxy access logs, referrers, screenshots, or support bundles; use a non-URL credential handoff or a launch-context bound token instead.
  - confidence: 0.9
- **[P2] Bound Activity broadcasts before fanning out:** `src/gateway/a2ui-activity.ts:79-83`
  - body: The hub stores the full latest JSONL payload and sends every push to every connected Activity socket without bounding payload size, retained state, or client count. A large canvas update or many Activity clients can create avoidable Gateway memory and send pressure before the node response is returned.
  - confidence: 0.86
