## Security Review

Status: needs_attention

Summary: The diff introduces concrete auth-boundary and credential-transport concerns that need repair before merge.

Concerns:

- **[high] Activity mode can bypass Gateway auth without a token:** `src/gateway/a2ui-activity.ts:35`
  - body: `isA2uiActivityAccessAllowed` returns true when Activity mode is enabled and no token is configured, allowing A2UI access before normal Gateway bearer or plugin capability auth runs.
  - confidence: 0.94
- **[medium] Activity token is carried in URLs:** `src/canvas-host/a2ui/index.html:321`
  - body: The browser bridge reads `activityToken` from the page URL and appends it to the WebSocket query string, which can expose the token through logs, referrers, browser history, or cleartext `ws://` on a misconfigured host.
  - confidence: 0.9
- **[medium] A2UI fanout lacks payload and backpressure limits:** `src/gateway/a2ui-activity.ts:79`
  - body: The Activity hub stores the last JSONL payload and broadcasts it to all clients without size caps or slow-client handling, creating a Gateway availability risk.
  - confidence: 0.88
