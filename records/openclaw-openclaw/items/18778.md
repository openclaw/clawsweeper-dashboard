- **[P1] Port the Discord changes out of removed core paths:** `src/discord/components.ts:34`
  - body: Current main no longer has `src/discord`; Discord components now live under `extensions/discord` with persistent registry and plugin-interactive dispatch.   - confidence: 0.9
- **[P1] Keep activity access fail-closed without a token:** `src/gateway/a2ui-activity.ts:35-36`
  - body: When `canvasHost.activity.enabled` is true but `activity.token` is blank, this returns `true`, and the PR calls it before normal gateway auth for A2UI HTTP/WS. That exposes the A2UI surface for any deployment that enables Activities without a token; require a strong token or verifiable Discord launch assertion before bypassing gateway auth.
  - confidence: 0.92
- **[P1] Move the config surface to the Canvas plugin contract:** `src/config/types.gateway.ts:39-55`
  - body: Current main treats root `canvasHost` as legacy migration input and documents Canvas under `plugins.entries.canvas.config.host`. Adding new `canvasHost.activity` resurrects a root config surface that doctor/plugin migration will not own consistently; define this in the Canvas plugin schema/migration/docs or remove it until the product direction is confirmed.
  - confidence: 0.87
- **[P2] Bound activity bridge payloads before retaining them:** `src/gateway/a2ui-activity.ts:79-82`
  - body: Every `canvas.a2ui.pushJSONL` stores the full string in `lastJsonl` and sends it to every connected WebSocket without size or backpressure checks. Large or repeated canvas payloads can pin memory or stall the gateway; reject or truncate oversized payloads and drop slow clients before retaining or broadcasting.
  - confidence: 0.84
- **[P3] Remove the direct changelog edit:** `CHANGELOG.md:16`
  - body: `CHANGELOG.md` is release-owned in this repo, so normal feature PRs should carry release-note context in the PR body or squash message instead of editing the generated release file. Drop this entry during the rebase/port.
  - confidence: 0.78
