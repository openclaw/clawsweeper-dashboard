## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Port the Discord changes into current plugin paths:** `src/discord/components.ts:60`
  - body: This branch adds the new button action under `src/discord`, but current main owns Discord components under `extensions/discord/src` and no longer has a `src/discord` runtime. As-is, the Activity launch behavior will not land in the current Discord plugin and the PR is already conflict-prone; port the action through the extension parser/types/builders and monitor handlers.
  - confidence: 0.95
- **[P1] Require Activity credentials before bypassing Gateway auth:** `src/gateway/a2ui-activity.ts:35-36`
  - body: When `canvasHost.activity.enabled` is true and no token is configured, `isA2uiActivityAccessAllowed` returns true, and `authorizeCanvasRequest` accepts that before normal Gateway auth. That makes an enabled Activity surface fully unauthenticated; make Activity access fail closed unless a valid Activity credential or verified launch assertion is present.
  - confidence: 0.93
- **[P1] Move Activity config under the Canvas plugin contract:** `src/config/types.gateway.ts:39-55`
  - body: The PR adds `canvasHost.activity` back to root gateway config, but current main migrated root `canvasHost` into `plugins.entries.canvas.config.host`. Adding a new root subkey creates two Canvas config sources and bypasses the plugin config/migration contract; put Activity config under the Canvas plugin surface instead.
  - confidence: 0.9
- **[P1] Stop carrying Activity tokens in URLs:** `src/canvas-host/a2ui/index.html:321-325`
  - body: The Activity page reads `activityToken` from the URL and reconnects the WebSocket with the same query parameter. Those URLs are likely to appear in reverse-proxy logs, browser history, and referrers; use a non-URL credential path such as a scoped capability, secure cookie, or signed launch exchange before exposing this publicly.
  - confidence: 0.9
- **[P2] Bound Activity broadcasts before fanning out:** `src/gateway/a2ui-activity.ts:79-82`
  - body: `broadcastPush` stores the full JSONL payload and sends it to every connected Activity client without size or backpressure limits, while `node.invoke` forwards arbitrary A2UI JSONL into that path. A large or repeated payload can retain memory and stall the Gateway; enforce payload caps and slow-client handling before merge.
  - confidence: 0.87

## Security Review
