  - body: With `activity.enabled` and no token, this returns true, and the HTTP/WS authorization path accepts Activity A2UI before normal Gateway auth. Activity access should require a token or verifiable Discord assertion before public A2UI is exposed.
  - confidence: 0.96

  - body: Current main migrates root `canvasHost` into `plugins.entries.canvas.config.host` and serves Canvas/A2UI from the Canvas plugin. Adding a new root `canvasHost.activity` contract creates a competing config surface and does not fit the current upgrade path.
  - confidence: 0.94
- **[P1] Stop putting Activity tokens in WebSocket URLs:** `src/canvas-host/a2ui/index.html:321-325`
  - body: The bridge reads `activityToken` from the page URL, forwards it in the WebSocket query string, and falls back to cleartext `ws://` on HTTP pages. Use a safer token exchange, cookie, or protocol path and fail closed for insecure transport.
  - confidence: 0.9
- **[P2] Bound Activity payloads and slow clients:** `src/gateway/a2ui-activity.ts:79-82`
  - body: `broadcastPush` stores arbitrary JSONL and sends it to every Activity WebSocket without byte limits or `bufferedAmount` handling. Add payload caps and slow-client behavior before exposing this public fanout path.
  - confidence: 0.91
- **[P2] Make the launch test use a guild interaction:** `src/discord/monitor/monitor.test.ts:325-329`
  - body: The handler rejects launch-activity when `rawData.guild_id` is absent, but this added test builds a DM-like interaction and still expects the Activity REST callback. Add a guild id or assert the DM rejection path so the test matches the implementation.
  - confidence: 0.9

## Security Review

Status: needs_attention

Summary: The diff introduces public Activity auth, URL token transport, and WebSocket fanout concerns that need security and owner review before merge.

Concerns:

- **[high] Activity mode can bypass Gateway auth without a token:** `src/gateway/a2ui-activity.ts:35`
  - body: `isA2uiActivityAccessAllowed` returns true when Activity mode is enabled and no token is configured, and the HTTP/WS authorization path can accept that before normal Gateway auth.
  - confidence: 0.96
- **[medium] Activity token is copied into URL query strings:** `src/canvas-host/a2ui/index.html:321`
  - body: The A2UI bridge reads `activityToken` from the page URL and forwards it in the WebSocket URL query, which can leak through logs, intermediaries, browser history, or HTTP deployments.
  - confidence: 0.9
- **[medium] A2UI Activity fanout is unbounded:** `src/gateway/a2ui-activity.ts:79`
  - body: The Activity hub retains and broadcasts arbitrary JSONL without size limits or slow-client backpressure, creating memory and event-loop risk for public Activity connections.
  - confidence: 0.91
