- **[P1] Port Discord Activity work to current plugin paths:** `src/discord/components.ts:35`
  - body: Current main and shipped v2026.6.11 put Discord components under `extensions/discord` and Canvas/A2UI under `extensions/canvas`, but this branch adds the launch action to the old `src/discord`/`src/canvas-host` layout.   - confidence: 0.93
- **[P1] Require Activity credentials before bypassing Gateway auth:** `src/gateway/a2ui-activity.ts:35-36`
  - body: When Activity mode is enabled and `activity.token` is unset, this helper returns `true`, and `authorizeCanvasRequest` accepts the request before normal Gateway auth. A public Activity route should fail closed unless a credentialed launch/exchange path verifies the request.
  - confidence: 0.95
- **[P1] Move Activity config under the Canvas plugin contract:** `src/config/zod-schema.ts:371-377`
  - body: Current shipped behavior treats root `canvasHost` as legacy migration input into `plugins.entries.canvas.config.host`; adding active `canvasHost.activity` fields creates a second root config surface that the current Canvas plugin model will not own. Put this under the Canvas plugin config or add an explicit maintainer-approved migration path.
  - confidence: 0.92
- **[P1] Stop passing Activity tokens through URLs:** `src/canvas-host/a2ui/index.html:321-325`
  - body: The page reads `activityToken`/`a2uiToken` from the URL and forwards the value into the WebSocket query. That exposes the Activity credential through browser history, logs, referrers, and diagnostics, so this needs a non-URL credential or launch exchange path before merge.
  - confidence: 0.94
- **[P2] Bound Activity broadcasts before retaining and fanout:** `src/gateway/a2ui-activity.ts:79-82`
  - body: `broadcastPush` stores arbitrary JSONL and sends it to every connected Activity socket without size limits, queue bounds, or backpressure handling. A node can therefore grow Gateway memory or stall the process with large/frequent Activity payloads.
  - confidence: 0.88
