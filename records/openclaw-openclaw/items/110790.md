## Summary

Keep this PR open: it fixes the full-transcript scan, but the new SQLite head reader materializes an entire `event_json` value before applying its 8 KiB budget, so one oversized early event can still cause the unbounded allocation the change is meant to prevent. The remaining title-semantics trade-off also needs an explicit maintainer decision after that bound is corrected.

## What This Changes

The branch replaces full SQLite transcript materialization for derived session titles with bounded head and tail event reads and adds SQLite regression coverage.

## Best Possible Solution

Enforce the head byte budget at the SQLite query/result boundary, add an oversized-first-event regression, then have a maintainer explicitly accept or reject SQLite/file title-parity semantics for existing sessions.
