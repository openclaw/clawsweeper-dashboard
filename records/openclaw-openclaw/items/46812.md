## Summary

Keep open: current main and v2026.6.11 still provide generic editable bootstrap-file surfaces and memory routing, but they do not provide a pinned key-value facts panel, dedicated pinned-context storage, or a guaranteed-injection/freshness contract. The remaining work needs maintainer product and security review rather than conservative cleanup.

## What This Changes

Requested a Control UI pinned-context panel for adding, editing, and always injecting user-defined persistent facts.

## Best Possible Solution

Define a first-class pinned-facts contract before implementation: storage owner, always-injected versus last-seen semantics, visible diff/audit on save, authorization boundary, and context-injection tests coordinated with the memory panel and Control UI plugin-slot work.

## Reproduction Assessment

Not applicable: this is a feature request rather than a broken current-main behavior report. Source and release inspection give high-confidence absence proof for a pinned-facts API/UI and show only raw workspace-file editing for allowlisted files.

## Solution Assessment

Unclear: the pinned panel UX is plausible, but direct raw file editing or a new pinned-context file is not clearly the best permanent answer until maintainers decide storage, freshness, injection, and browser write security semantics.
