## Label Justifications

- `P2`: This is a normal-priority Control UI/context feature with meaningful UX and safety impact but no shipped regression or outage.
- `impact:session-state`: The request changes which user facts persist and are injected into agent context across sessions and turns.
- `impact:security`: A UI that writes always-injected context can expose or corrupt sensitive prompt-influencing user facts without a defined authorization and audit boundary.
- `impact:ux-friction`: The report describes a non-discoverable raw-file workflow for users who want to add or correct persistent context.

## Summary

Keep open: current main and v2026.6.11 still expose only generic editable agent files and memory routing, not a pinned key-value facts panel, dedicated pinned-context storage, or an always-injected/freshness contract. The remaining work needs maintainer product and security review before implementation.

## What This Changes

Add a Control UI panel for user-defined persistent facts that can be added, edited, deleted, and guaranteed to influence agent context on future turns.

## Best Possible Solution

Define a first-class pinned-facts contract with storage ownership, always-injected versus last-seen semantics, visible save diff/audit, authorization boundaries, and context-injection tests coordinated with the memory panel and Control UI plugin-slot work.
