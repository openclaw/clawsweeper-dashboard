## Label Justifications

- `P2`: This is a normal-priority Control UI/context feature with meaningful UX and safety impact but no broken shipped behavior.
- `impact:session-state`: The request changes which user facts persist and are injected into agent context across sessions and turns.
- `impact:security`: A UI that writes always-injected context can expose or corrupt sensitive user facts without a defined authorization and audit boundary.

## Summary

Keep open: current main and v2026.6.11 still provide generic editable bootstrap-file surfaces and memory routing, but they do not provide a pinned key-value facts panel, dedicated pinned-context storage, or a guaranteed-injection/freshness contract. The remaining work is product and security design, not maintainer cleanup.

## What This Changes

Requested a Control UI panel or sidebar widget for user-defined pinned facts that are editable in the UI and guaranteed to be available in agent context.

## Best Possible Solution

Define a first-class pinned-facts contract before implementation: storage owner, always-injected versus last-seen semantics, visible diff/audit on save, authorization boundary, and context-injection tests coordinated with the memory panel and Control UI plugin-slot work.

## Reproduction Assessment

Not applicable: this is a feature request rather than a broken current behavior report. Source inspection gives high-confidence absence proof for a pinned-facts API/UI and shows only raw workspace-file editing for allowlisted files.

## Solution Assessment

Unclear: the pinned panel UX is plausible, but direct raw file editing is not the best permanent answer until maintainers decide storage, freshness, injection, and browser write security semantics.
