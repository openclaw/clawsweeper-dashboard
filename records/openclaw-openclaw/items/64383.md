## Summary

Keep open. Current main and latest release no longer use the old socat binary, but the sandbox browser CDP path still deliberately uses a generated-token Python relay and derived Chromium loopback port, so direct CDP remains an unresolved security/product decision.

## What This Changes

The issue asks maintainers to evaluate replacing the sandbox browser CDP relay and port-offset path with direct Chromium CDP or an equivalent clearer design.

## Best Possible Solution

Have sandbox/browser owners either document the authenticated Python relay as the intended post-socat design, or approve a direct-CDP migration that preserves equivalent auth, source filtering, loopback publishing, readiness checks, tests, and docs.

- **Fold into backend/API design:** Supersede this into the broader sandbox browser endpoint/backend decision if maintainers want direct CDP handled as part of a larger external-browser contract.
