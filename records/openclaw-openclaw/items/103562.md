## Summary

The latest head still has the previously reported P1 correctness defect: its retry loop re-enters the full shared channel-turn helper, so one Discord event can repeat session recording and post-record side effects before each retry. The PR also remains merge-gated on real Discord evidence, and maintainers should confirm whether this channel-level fallback should coexist with the proof-positive shared session self-heal in https://github.com/openclaw/openclaw/pull/101920.

## What This Changes

Adds bounded, abort-aware retries for Discord reply-session initialization conflicts, marks exhausted conflicts retryable for replay-claim release, and adds focused regression tests.

## Best Possible Solution

Use the prepared-turn seam so inbound recording, history, and ack preparation execute once; retry only the session-init/dispatch closure, preserve retryable queue signaling after exhaustion, and retain the Discord defense only if maintainers intentionally want it layered with the shared session self-heal.
