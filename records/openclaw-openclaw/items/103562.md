## Summary

Keep open: retry exhaustion still reaches Discord’s durable ingress queue as a plain error, causing the replay key to be committed even though dispatch never succeeded; the prior P1 finding remains unresolved on the current head.

## What This Changes

The PR adds bounded, abort-aware retries for Discord reply-session initialization conflicts and focused retry, abort, exhaustion, and exact-once history tests.

## Best Possible Solution

When the bounded retries exhaust, wrap only the recognized session-init conflict in `DiscordRetryableInboundError` with the original error as its cause, then prove at queue level that the replay key is released and with redacted runtime evidence that a real Discord conflict recovers.
