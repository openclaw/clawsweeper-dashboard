## Summary

This PR remains necessary for the linked Discord message-loss bug, but it is not merge-ready: after its bounded retries exhaust, it rethrows a plain error that the outer run queue treats as terminal, permanently committing the replay key for an undelivered event. The prior P1 blocker therefore remains on the current head despite green CI.

## What This Changes

The PR adds bounded abort-aware retries around Discord reply dispatch for reply-session initialization conflicts, plus focused tests for success, exhaustion, abort, unrelated errors, and exact-once room history.

## Best Possible Solution

Keep the narrow dispatch-only backoff, but wrap an exhausted session-init conflict in `DiscordRetryableInboundError` with the original error as its cause, then add queue-level coverage proving one later redelivery without duplicate history or replies and provide a redacted live Discord trace.
