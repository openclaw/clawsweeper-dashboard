## Summary

The current head still has the previously reported replay-settlement defect and adds a retry loop that repeats session-recording work, so it can continue suppressing redelivery or generate fresh session-store contention instead of reliably recovering the Discord message.

## What This Changes

Adds Discord-specific bounded backoff for reply-session initialization conflicts and regression tests for success, exhaustion, abort handling, unrelated errors, and room-history behavior.

## Best Possible Solution

Resolve the shared session self-heal direction, then implement any Discord defense by recording the inbound turn once, retrying only the prepared dispatch/session-init operation, and converting exhausted pre-delivery conflicts into the queue's typed retryable outcome so replay remains available.
