## Summary

The PR addresses a real Discord message-loss race with a sensible bounded dispatch retry, but the terminal path preserves the original plain error. Discord’s queue treats that as non-retryable and commits the replay key, so a message that exhausts retries cannot be accepted on later redelivery. The prior P1 remains valid, and real Discord behavior proof is still absent.

## What This Changes

The PR adds bounded exponential-backoff retries around Discord inbound reply dispatch for reply-session initialization conflicts and adds focused retry, abort, and history regression tests.

## Best Possible Solution

Convert only an exhausted reply-session initialization conflict into `DiscordRetryableInboundError` with the original error as its cause, extend queue-level coverage proving later reclaim, and provide a redacted live Discord conflict-to-success trace before merge.
