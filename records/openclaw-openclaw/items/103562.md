## Summary

The latest head still preserves the core P1 defect: after four local session-init conflict attempts, it throws the original plain error, causing Discord’s durable queue to commit the replay claim even though dispatch never succeeded. Focused tests and CI are useful, but no real Discord conflict-to-success proof is provided.

## What This Changes

The PR adds bounded, abort-aware retries around Discord inbound reply dispatch for reply-session initialization conflicts and process-level regression tests for retry, exhaustion, abort, unrelated errors, and exact-once history handling.

## Best Possible Solution

When bounded retries exhaust, wrap only the recognized session-init conflict in `DiscordRetryableInboundError` with the original cause, add queue-level proof that the replay key is released and reclaimable, and provide a redacted live Discord recovery trace before merge.
