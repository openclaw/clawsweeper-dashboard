## Summary

The Discord retry is useful containment, but the current head still commits the inbound replay claim after all session-init retries fail, suppressing a platform redelivery even though no reply was produced. The repeated P1 remains blocking, and mocked tests do not satisfy the external-PR live behavior proof gate.

## What This Changes

Adds bounded, abort-aware Discord retries around inbound reply dispatch for reply-session initialization conflicts, plus focused retry, exhaustion, abort, and history tests.

## Best Possible Solution

Keep a bounded Discord transport fallback for transient conflicts, translate terminal conflicts into the existing retryable inbound contract with queue-level replay-release coverage, and leave persistent session-wedge repair to the shared reply-session layer.
