## Summary

This PR addresses a real Discord message-loss race, but the current retry loop still re-enters the assembled inbound helper, which records session state and runs post-record callbacks on every attempt. The prior P1 therefore remains unresolved, and the external-PR real behavior proof gate is also unmet.

## What This Changes

The branch adds bounded backoff retries for Discord reply-session initialization conflicts, classifies exhausted conflicts for replay redelivery, and adds focused retry, abort, and history tests.

## Best Possible Solution

Record and prepare each Discord inbound event once, retry only the session-init and dispatch continuation with the existing bounded delays, retain replay-claim release after exhaustion, and prove both recovery and redelivery in a real Discord setup.
