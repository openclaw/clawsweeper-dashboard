Keep open: current main and v2026.6.11 still expose terminal-looking session `status` values without a resumability signal or model-facing status semantics, and the proven candidate fix is closed unmerged.

## What This Changes

The issue asks OpenClaw to make session status semantics clear enough that orchestrator agents resume existing sessions instead of spawning duplicates.

## Best Possible Solution

Maintainers should confirm the additive resumability/status-semantics contract, then reopen or replace https://github.com/openclaw/openclaw/pull/89101 rather than renaming shipped status values without an explicit compatibility decision.
