## Summary

Keep open: current main and the latest release still expose terminal-looking session `status` values without an explicit resumability signal or model-facing status semantics, and both linked resumability PRs are now closed unmerged.

## What This Changes

The issue asks OpenClaw to clarify session `status` as last-turn state and expose or rename resumability semantics so agents resume existing sessions instead of spawning duplicates.

## Best Possible Solution

Define a backward-compatible session resumability contract, likely additive metadata plus tool guidance rather than renaming shipped statuses, with focused Gateway and model-facing `sessions_list` tests.

Yes, at source level: current main exposes only terminal-looking `status` values and no resumability hint, while `sessions_send` can reactivate ended sub-agent sessions. I did not run a live orchestrator duplicate-spawn scenario in this read-only review.

## Solution Assessment

Unclear until maintainers choose the contract. Additive `resumable` metadata and concise tool guidance look safer than renaming shipped status values, but `killed` semantics and Gateway/client scope need a product decision.
