## Summary

Keep open: current main and v2026.6.11 still expose terminal-looking session statuses without a resumability/status-semantics signal, and both related resumability PRs are closed unmerged.

## What This Changes

The issue reports that session `status` values like `failed`, `timeout`, and `done` describe the last turn but look like terminal lifecycle states, causing orchestrators to spawn duplicate sessions instead of resuming existing ones.

## Best Possible Solution

Keep this as the canonical tracker, have maintainers confirm the additive resumability/status-semantics contract, then land a narrow replacement PR scoped to agent-visible session routing and any approved Gateway row contract.
