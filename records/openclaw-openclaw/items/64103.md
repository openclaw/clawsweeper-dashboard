## Summary

Keep open: current main and v2026.6.11 still expose terminal-looking session `status` values without a resumability or lifecycle-semantics hint, and both PRs that attempted the additive `resumable` fix are closed unmerged.

## What This Changes

The issue requests clearer session status semantics or an explicit resumability signal so agents resume existing sessions instead of spawning duplicates.

## Best Possible Solution

Define a backward-compatible session-list contract that tells agents which rows are resumable, then update Gateway/agent row types, tool description/system prompt, and focused tests; avoid breaking status renames unless maintainers explicitly choose them.
