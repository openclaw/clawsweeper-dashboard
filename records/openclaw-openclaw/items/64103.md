## Summary

Keep open: current main and v2026.6.11 still expose terminal-looking session `status` values without a resumability signal, and both prior `resumable` PRs are closed unmerged.

## What This Changes

Clarify session-list status semantics so agents know `failed`, `timeout`, and `done` sessions can often be resumed instead of spawning duplicate sub-agent sessions.

## Best Possible Solution

Define a backward-compatible session resumability contract, preferably additive `resumable` metadata plus tool/prompt guidance, then land a refreshed focused PR with coverage for all current statuses.
