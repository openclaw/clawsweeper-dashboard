## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Prove the union_id source before relying on it:** `extensions/feishu/src/probe.ts:137`
  - body: This reads `bot?.union_id`, but the canonical linked issue and the official Feishu bot/v3/info response do not show `union_id`. If that remains true, `botUnionId` is always undefined and the fallback never fixes the reported multi-bot mention loss.
  - confidence: 0.94
- **[P2] Cover post mentions with the fallback identity:** `extensions/feishu/src/bot.ts:477-479`
  - body: The fallback only participates in the top-level `message.mentions` branch. Rich-text post mentions still flow through the open_id-only post branch, so the same app-scoped mismatch can still make a post @mention look unmentioned.
  - confidence: 0.83
- **[P2] Strip fallback-matched mentions before command parsing:** `extensions/feishu/src/bot.ts:797`
  - body: This can set `mentionedBot` through `botUnionId`, but content normalization still strips only by `botOpenId`. A multi-bot `@Bot /help` that matched by union_id can keep the raw mention before `/help`, undermining the slash-command behavior this parser comment protects.
  - confidence: 0.86
- **[P2] Carry fallback identity through debounce batching:** `extensions/feishu/src/monitor.account.ts:251`
  - body: Adding `botUnionId` to the final handler call is not enough because the debounce path still derives merged text and merged mentions with `botOpenId` only. A burst where the target mention is only in an earlier event can still produce a merged dispatch that fails the requireMention gate.
  - confidence: 0.8
