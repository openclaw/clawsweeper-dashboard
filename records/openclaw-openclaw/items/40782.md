Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Prove the union_id source before relying on it:** `extensions/feishu/src/probe.ts:137`
  - body: This stores `botUnionId` from `bot?.union_id`, but the response type here does not model that field and the linked issue/sibling PR say this endpoint does not return bot `union_id`. If that remains true, the fallback never populates and the multi-bot mention loss is unchanged.
  - confidence: 0.93
- **[P1] Pass the prefetched union id through startup:** `extensions/feishu/src/monitor.account.ts:510`
  - body: Late discovery from the unchanged reviewed head: even if `fetchBotIdentityForMonitor` returns a union id, the normal `monitorFeishu` startup caller destructures only `botOpenId` and `botName` before passing `botOpenIdSource`, so `botUnionIds` never gets populated on the default startup path.
  - late: true
  - confidence: 0.88
- **[P2] Cover post mentions with the fallback identity:** `extensions/feishu/src/bot.ts:477-479`
  - body: The new fallback only participates in the top-level `message.mentions` branch. Rich-text post mentions still compare parsed mention IDs to `botOpenId`, so the same app-scoped mismatch can still make a post @mention look unmentioned.
  - confidence: 0.82
- **[P2] Strip fallback-matched mentions before command parsing:** `extensions/feishu/src/bot.ts:797`
  - body: This can set `mentionedBot` through `botUnionId`, but content normalization still strips only by `botOpenId`. A multi-bot `@Bot /help` that matched by union_id can keep the raw mention before `/help`, undermining the slash-command behavior this parser comment protects.
  - confidence: 0.86
- **[P2] Carry fallback identity through debounce batching:** `extensions/feishu/src/monitor.account.ts:251`
  - body: Adding `botUnionId` to the final handler is not enough because debounce text parsing and merged mention filtering remain `botOpenId`-only. A burst where the target mention appears only in an earlier event can still produce a merged dispatch that fails the requireMention gate.
  - confidence: 0.8
