- **[P1] Prove the union_id source before relying on it:** `extensions/feishu/src/probe.ts:137`
  - body: This reads `bot?.union_id`, but https://github.com/openclaw/openclaw/issues/40768 and https://github.com/openclaw/openclaw/pull/40783 both record that the bot-info response does not return that field.   - confidence: 0.91
- **[P2] Cover post mentions with the fallback identity:** `extensions/feishu/src/bot.ts:479`
  - body: The new fallback only participates in the top-level `message.mentions` branch. Rich-text post mentions still compare parsed ids only to `botOpenId`, so the same app-scoped mismatch can still make a post @mention look unmentioned.
  - confidence: 0.82
- **[P2] Strip fallback-matched mentions before command parsing:** `extensions/feishu/src/bot.ts:797`
  - body: `parseFeishuMessageEvent` accepts `botUnionId`, but content normalization still strips only by `botOpenId`. A multi-bot `@Bot /help` that matched by `union_id` can keep the raw mention before `/help`, undermining the slash-command behavior this parser comment protects.
  - confidence: 0.86
- **[P2] Carry fallback identity through debounced batches:** `extensions/feishu/src/monitor.account.ts:251`
  - body: This passes `botUnionId` to the final handler, but the debounce helpers still build merged text and merged mentions with `parseFeishuMessageEvent(event, botOpenId, ...)` and `resolveFeishuDebounceMentions(...botOpenId)`. A burst where only an earlier event carries the target mention can still merge into a message that fails the `requireMention` gate.
  - confidence: 0.8
