## Summary

Request changes: the added client-level HTTP timeout does not bound the Google Live WebSocket handshake. The SDK creates a separate WebSocket, calls `connect()`, and waits for its open callback without applying `httpOptions.timeout`, so the reported hang remains. ([github.com](https://github.com/googleapis/js-genai/blob/v2.12.0/src/live.ts))

## What This Changes

The PR adds a 30-second `httpOptions.timeout` to the Google realtime live-session client and a regression assertion for that client configuration.

## Best Possible Solution

Enforce a finite deadline at the actual Google Live WebSocket connection or setup boundary with guaranteed socket cleanup, then prove a pre-open stall times out, closes its transport, and permits a subsequent normal connection.
