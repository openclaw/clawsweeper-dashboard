## Label Justifications

- `P1`: The reported failure breaks manual compaction for valid CLI-backed sessions and can repeatedly disrupt an active long-running session workflow.
- `impact:session-state`: The failure occurs during session compaction and prevents expected context/session maintenance.
- `impact:auth-provider`: The root inconsistency is provider/runtime classification for a configured CLI backend and results in the wrong harness/auth precheck path.

## Summary

Keep this issue open for a focused provenance and regression-proof check. Current main's model-fallback guard already treats IDs under `agents.defaults.cliBackends` as CLI runtimes, which appears to address the reported blind spot, but this review could not establish the introducing fix commit or verify that the `sessions.compact` path exercises that guard with a config-only backend. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/agents/model-selection-cli.ts))

## What This Changes

Ensure manual session compaction recognizes executable custom CLI backend IDs defined only in `agents.defaults.cliBackends` instead of rejecting them as unregistered agent harnesses.

## Best Possible Solution

Keep runtime identity checks config-aware without inventing canonical provider bindings, add a gateway regression test for `sessions.compact` using an override-only executable backend, and close after identifying the fixing commit and its release status.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes for the shipped `v2026.6.11` report at source level: an executable config-only backend can be accepted for execution while an older registry-only runtime classifier rejects it during compaction. A failing current-main path was not independently established because current main now contains a config-aware guard.

## Solution Assessment

The issue's goal is correct, but merging arbitrary config IDs into canonical runtime bindings is not the safest general fix. The narrower solution is to use the existing config-aware backend predicate or executable-backend resolution at the harness precheck and cover the gateway compaction caller with a regression test.
