## What This Changes

The issue reports a regression where the Control UI header logo/favicon disappear after the 2026.3.24 update, with later discussion expanding it to public assets failing on deep or prefixed routes.

## Best Possible Solution

Resolve the supported Control UI URL contract, then land or reject one narrow fix that makes shipped public assets load on supported root/deep/basePath routes while preserving static-file safety and the existing 404 behavior for unknown files.
