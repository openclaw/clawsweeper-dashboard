## Summary

Keep open: current main and the latest release contain several partial Control UI asset fixes, but they still intentionally preserve 404 behavior for unconfigured prefixed public assets, so this is not safely implemented-on-main without a maintainer URL-support decision.

## What This Changes

The issue reports missing Control UI header/favicon assets after the 2026.3.24 update, with later discussion narrowing the root cause to relative public asset paths on deep routes.

## Best Possible Solution

Maintain one documented Control UI URL contract and make public asset, Vite bundle, service worker, and gateway static-file behavior match that contract for root and configured-basePath deployments.
