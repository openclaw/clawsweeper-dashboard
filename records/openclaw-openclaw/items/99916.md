## Summary

Keep open: the reported cancellation bug is valid, but this patch is too narrow because the production gateway invoke boundary still catches `CancellationException` as `Throwable` after `CameraHandler` rethrows it. The PR also has only unit-test output, not real Android behavior proof.

## What This Changes

The PR adds `CancellationException` rethrows before `Throwable` catches in Android `CameraHandler` camera list, snap, and clip handling.

## Best Possible Solution

Handle `CancellationException` consistently at the production gateway invoke coroutine boundary, keep the `CameraHandler` cleanup behavior, and add focused coverage proving camera cancellation is not serialized as a normal invoke error.

## Reproduction Assessment

Yes, source inspection gives a high-confidence path: current main catches camera-operation `CancellationException` in `CameraHandler`, and the production `GatewaySession` invoke coroutine also catches `Throwable` around `onInvoke`. I did not run a live Android cancellation scenario.

## Solution Assessment

No. The local `CameraHandler` rethrows are directionally correct, but the best fix must also preserve cancellation at the `GatewaySession` invoke boundary and prove the full production path.
