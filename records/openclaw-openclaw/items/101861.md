## Summary

Keep open: the PR targets a real Discord/ACP thread-spawn routing gap, but the latest delivery-context change can graft a stale `threadParentId` onto a new or cleared thread route, and after-fix real Discord/ACP proof is still missing.

## What This Changes

## Best Possible Solution

Keep the generic parent-context propagation, but first make `threadParentId` follow the same source as the selected `threadId` and clear it with cleared thread routes, then require redacted Discord/ACP proof of successful sibling-thread spawn.
