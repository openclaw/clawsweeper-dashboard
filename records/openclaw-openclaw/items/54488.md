## Summary

Keep open: current main still queues active same-session non-heartbeat work into follow-up handling and drains that backlog without a foreground preemption or yield guarantee, so the reported channel starvation remains. Recent queue lifecycle and deferred-maintenance work mitigates adjacent cases but does not implement the requested scheduler fairness.

## What This Changes

Request to prevent follow-up/background session-drain work from monopolizing a per-session lane and delaying foreground inbound or outbound chat messages for many minutes.

## Best Possible Solution

Define a core scheduler policy where fresh foreground user/control turns can overtake, interrupt, or defer accumulated background/follow-up work while preserving ordering within each priority class and safe session writes.

## Reproduction Assessment

Yes, at source level: current main still enqueues active non-heartbeat follow-up work and drains the queue until empty without a foreground-yield point; I did not run the full live delay scenario.

## Solution Assessment

Not as an automated one-off fix: the owner boundary is core reply/session scheduling, but maintainers need to choose the foreground priority, background abort/yield, and session-state ordering policy.
