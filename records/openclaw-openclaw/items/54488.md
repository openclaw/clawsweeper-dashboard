## Summary

Keep open: current main still admits active non-heartbeat same-session work into the follow-up queue, appends it at the tail, and drains queued follow-ups until empty through the same single-session lane. Recent fixes address narrower dormant-drain, queued-prompt, and recovery cases, but the foreground-vs-background scheduler fairness problem remains.

## What This Changes

The issue reports session-lane starvation where follow-up/background drains can monopolize a single-session lane and delay inbound user dispatch for many minutes.

## Best Possible Solution

Define and land a core scheduler policy that lets fresh foreground user/control work overtake, interrupt, or defer accumulated background/follow-up work while preserving one active writer per session and ordering within each priority class.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: active non-heartbeat work still enters enqueue-followup, tail-appends to the same queue, and the drain awaits queued work until empty. I did not run the full live 20-30 minute multi-channel scenario in this read-only review.

## Solution Assessment

Unclear as an automated fix: the implicated owner boundary is core reply/session scheduling, but maintainers still need to choose the foreground-priority, background-abort/yield, and transcript-ordering policy before a safe repair PR is queued.
