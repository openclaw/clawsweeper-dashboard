## Summary

Keep open: current main and the latest release still enqueue active non-heartbeat follow-up work and drain the follow-up queue until empty, so the reported session-lane starvation is not implemented away. Related merged work fixed a narrower dormant-drain race, and open related work covers admission or recovery slices, but no safe canonical fix has landed for foreground scheduler fairness.

## What This Changes

The issue reports session-lane starvation where follow-up/background drains monopolize a per-session lane and delay inbound Discord, WhatsApp, Slack, and control messages for many minutes.

## Best Possible Solution

Define a core scheduler policy that separates foreground user/control work from background/follow-up work, with bounded follow-up draining or safe interruption while preserving ordering within each priority class and one active writer per session.
