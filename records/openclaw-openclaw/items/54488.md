## Summary

Keep open: current main still routes active same-session non-heartbeat work into the follow-up queue and drains that queue serially until empty, so the foreground starvation reported here is not implemented away. Recent fixes reduce adjacent races and some maintenance cost, but they do not establish foreground-user priority over accumulated background/follow-up work.

## What This Changes

The issue reports that follow-up/background drain work can monopolize a session lane and delay inbound or outbound channel dispatch for 20-30 minutes.

## Best Possible Solution

Define one core scheduler policy where fresh foreground user/control work can overtake, interrupt, or defer accumulated background/follow-up work while preserving single-writer session safety and ordering within each priority class.

Rationale: The code path is clear, but the fix determines product semantics for queue modes, STOP/abort behavior, transcript ordering, and background task reliability; automation should not choose that contract unaided.

Options:

- **User messages win by default (recommended):** Make visible inbound user/control work interrupt, preempt, or force-yield background and follow-up drains while keeping background work best-effort.
- **Bound consecutive follow-ups:** Keep existing follow-up semantics but cap consecutive drain turns or elapsed drain time and re-check foreground admission between queued turns.
- **Keep current queue contract:** Document the current followup/collect waiting behavior and rely on operational mitigations rather than changing scheduler precedence.

## Reproduction Assessment

Yes at source level: current main still enqueues active non-heartbeat work as follow-up, appends it FIFO, and drains queued follow-ups until empty on the same session execution path. I did not run the full live multi-channel 20-30 minute scenario in this read-only review.

## Solution Assessment

Unclear as an automated fix: the suggested cap/yield approach is plausible, but the best maintainable solution is a maintainer-approved scheduler policy for foreground user/control priority over background follow-up work.
