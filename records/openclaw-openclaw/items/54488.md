## Summary

Keep open: current main and the latest stable release still enqueue active non-heartbeat same-session work into a FIFO follow-up queue and drain it until empty, so the reported foreground starvation remains unresolved.

## What This Changes

The issue asks OpenClaw to prevent follow-up drain work from monopolizing a session lane and delaying fresh inbound or outbound channel messages for many minutes.

## Best Possible Solution

Define a core session scheduler fairness policy where fresh user/control work can overtake, interrupt, or defer accumulated background/follow-up work while preserving one active writer per session and ordered delivery within priority classes.

## Reproduction Assessment

Yes at source level: active non-heartbeat follow-up turns still enqueue, the queue appends FIFO, and the drain loop awaits queued follow-ups until the queue is empty; no full 20-30 minute live channel run was executed in this read-only review.

## Solution Assessment

Unclear as an automated fix: the owner boundary is core reply/session scheduling, but maintainers need to choose the policy for user priority, background abort/yield, and session-state safety before a repair branch is safe.
