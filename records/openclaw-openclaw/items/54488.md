## Label Justifications

- `P1`: The issue describes real user messages and sends waiting 20-30 minutes behind same-session queued work, which is an urgent broken channel/agent workflow.
- `impact:session-state`: The bug is in session-lane admission and follow-up drain ordering, so it directly affects session/run state progression.
- `impact:message-loss`: Inbound and outbound channel messages can appear silently stuck or delayed long enough to look lost to users.

## Summary

Keep open: current main has narrowed parts of the starvation problem, but it still admits active non-heartbeat same-session turns into the follow-up queue and drains that queue until empty, so the central foreground-user starvation report is not implemented away.

## What This Changes

The issue reports that follow-up/background drains can monopolize a single-session lane and delay inbound Discord, WhatsApp, Telegram, and CLI send work for many minutes.

## Best Possible Solution

Adopt a maintainer-approved foreground-user versus background/follow-up scheduling rule that yields or preempts the session lane for inbound user turns, then cover follow-up drain, cron/heartbeat/system-event, and stuck-session recovery paths with focused tests.

Rationale: The source-level bug is clear, but the correct invariant affects session ordering, STOP semantics, transcript state, and channel delivery, so automation should not choose the scheduler policy without owner intent.

Owner confidence: medium

Options:

- **Foreground-user scheduler invariant (recommended):** Make user-visible inbound turns the privileged foreground class, defer or abort background/follow-up work when necessary, and keep background/system events best-effort.
- **Bound consecutive follow-up drain:** Limit the number or time budget of consecutive follow-up turns before yielding to newly queued inbound work, with lower architectural churn but weaker STOP semantics.
- **Wait for slice PRs only:** Land narrow fixes such as related admission or cron-binding PRs first and leave the broader fairness invariant unresolved for a later design pass.
