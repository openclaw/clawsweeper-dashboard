## Summary

Keep open: current main and latest release still route same-session active non-heartbeat work into a FIFO follow-up queue and drain that queue until empty, so the reported foreground starvation is not implemented away.

## What This Changes

The issue asks OpenClaw to prevent follow-up drain work from monopolizing a session lane and delaying fresh inbound channel messages for many minutes.

## Best Possible Solution

Define a core scheduler policy where fresh foreground user/control work can overtake, interrupt, or defer accumulated background/follow-up work while preserving ordering within each priority class and one active writer per session.

## Reproduction Assessment

Yes at source level: active non-heartbeat follow-up turns still enqueue, the queue appends FIFO, and the drain loop awaits queued follow-ups until the queue/dropped work is empty; no live 20-30 minute Discord/WhatsApp reproduction was run in this read-only review.

## Solution Assessment

Unclear as an automated fix: the owner boundary is core reply/session scheduling, but maintainers need to choose foreground priority, background abort/yield, and session-state ordering semantics before a repair PR is safe.
