## Summary

Keep open: current main and the latest release still enqueue active non-heartbeat same-session work into the follow-up queue and drain that queue until empty. Recent merged fixes address narrower dormant-drain and foreground delivery deadlock cases, but they do not implement the requested foreground-vs-background scheduling rule.

## What This Changes

The issue reports session-lane starvation where background follow-up work can monopolize a single-session lane and delay inbound or outbound channel dispatch for many minutes.

## Best Possible Solution

Keep this as the canonical scheduler-fairness issue until maintainers choose and implement a core rule that makes fresh user/control work win over background or follow-up drains without racing transcripts.
