## Label Justifications

- `P1`: Multiple reports describe real channel messages, outbound sends, and STOP/control turns delayed for many minutes behind same-session queued work.
- `impact:message-loss`: The user-visible failure is channel messages being silently delayed or effectively suppressed while the session lane is monopolized.

## Summary

Keep open: current main still admits active same-session non-heartbeat work into the follow-up queue and drains that queue until empty, so the foreground starvation reported by users is not resolved by the latest code or latest release.

## What This Changes

The issue asks OpenClaw to prevent busy same-session follow-up/background work from delaying fresh user messages, STOP/control turns, and channel dispatch for minutes.

## Best Possible Solution

Define a core session-scheduler fairness contract where fresh user/control work wins over accumulated background or follow-up work while preserving one active writer and deterministic ordering within each priority class.

Rationale: The source-level bug is clear, but the fix changes core ordering and cancellation semantics for session state, background jobs, follow-up queues, and STOP behavior.

Owner confidence: high

Options:

- **Adopt foreground-control priority (recommended):** Make user and STOP/control turns structurally outrank background/follow-up work, with bounded abort/defer behavior for background tasks and regression tests for transcript ordering.
- **Add a narrow follow-up drain cap:** Limit consecutive follow-up turns or elapsed drain time, yielding when fresh foreground work exists while leaving most current queue semantics intact.
- **Keep ordering and improve recovery:** Treat the waits as acceptable serialized-session behavior and focus only on stuck diagnostics, operator warnings, and recovery timing.

## Reproduction Assessment

Yes, by source inspection and corroborating field reports: active same-session non-heartbeat work still enqueues FIFO and the drain awaits queued follow-ups until empty, but no live 20-30 minute channel repro was run in this read-only review.

## Solution Assessment

No: current main has partial mitigations such as command-lane priority, deferred maintenance lanes, and stuck recovery, but it does not give fresh foreground work priority over older follow-up backlog.
