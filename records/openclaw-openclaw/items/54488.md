## Summary

Keep open: current main and the latest checked release still route active same-session non-heartbeat work into a FIFO follow-up queue and drain it until empty, so the reported foreground/user-message starvation remains real despite adjacent priority, timeout, and maintenance fixes.

## What This Changes

The issue asks OpenClaw to prevent follow-up drain work from monopolizing a session lane and delaying fresh inbound or control messages for many minutes.

## Best Possible Solution

Define a core scheduler policy where fresh foreground user/control work can overtake, interrupt, or defer accumulated background/follow-up work while preserving ordering within each priority class, then cover follow-up drain, active reply admission, and recovery interactions with regression tests.

## Reproduction Assessment

Yes. Source inspection shows active non-heartbeat turns enqueue into the same FIFO follow-up queue and the drain loop continues until empty; live comments add field evidence, though no long-running live reproduction was executed in this read-only pass.

## Solution Assessment

No single narrow patch is proven best yet. A queue admission bypass or wider lane concurrency would be partial; maintainers need to choose foreground/background scheduler semantics before implementation.
