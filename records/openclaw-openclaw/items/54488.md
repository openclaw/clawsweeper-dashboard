## Summary

Keep open: current main still routes active non-heartbeat same-session work into the follow-up queue, appends it FIFO, and drains queued follow-ups until empty on the same serialized session lane. Recent merged work improves TUI queued-turn ownership and a dormant-drain race, but it does not implement the requested foreground/background scheduler fairness for channel messages.

## What This Changes

The issue requests fixing session-lane starvation where follow-up/background drain work can monopolize a session and delay inbound or outbound channel messages for many minutes.

## Best Possible Solution

Define a core scheduler policy where fresh foreground user/control work can overtake, interrupt, or defer accumulated background/follow-up work while preserving ordering within each priority class and one active writer per session.

## Reproduction Assessment

Yes at source level: active non-heartbeat turns still enqueue as follow-ups, the queue appends FIFO, and the drain loop awaits queued follow-ups until queue and dropped work are empty on the serialized session lane.

## Solution Assessment

Unclear as an automated fix: the owner boundary is core reply/session scheduling, but maintainers need to choose the priority, abort/yield, and session-state safety semantics before a new repair PR is safe.
