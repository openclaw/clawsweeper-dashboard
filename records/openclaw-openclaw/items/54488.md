## Summary

Keep open: current main still enqueues non-heartbeat same-session foreground work behind active reply/follow-up work and drains the follow-up queue until empty, so the central scheduler-fairness problem is not fixed. Merged work fixed narrower dormant-drain and stale-recovery slices, and open pull requests cover adjacent slices, but none replaces this canonical issue.

## What This Changes

The issue reports session-lane starvation where follow-up/background drain work monopolizes a session lane and delays inbound or outbound user messages for many minutes.

## Best Possible Solution

Define the session scheduler invariant that user-visible foreground input wins over background/follow-up work, then land focused changes and regression coverage that enforce it without racing session state or message delivery.

## Reproduction Assessment

Yes at source level: current main still routes active non-heartbeat same-session work into enqueue-followup and drains the same queue until empty. I did not run the full live multi-channel reproduction in this read-only pass.

## Solution Assessment

No, current main is not the best complete solution yet: it fixes some dormant/recovery slices, but it still lacks a clear foreground-priority scheduler invariant. The open admission-fence PR may be useful, but it should be treated as partial until the broader starvation path is covered.
