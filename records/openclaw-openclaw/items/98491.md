## Summary

Keep open: current main still has the duplicate macOS local-startup launchd enable path, and https://github.com/openclaw/openclaw/pull/98492 is open as the direct candidate fix.

## What This Changes

Make `GatewayProcessManager` the sole macOS launchd-enable owner during local startup to avoid duplicate launchd installs.

## Best Possible Solution

End with one macOS local-startup launchd-enable owner inside `GatewayProcessManager`, plus regression coverage for attach-existing and no-listener paths.

## Reproduction Assessment

Yes from source inspection: local mode schedules both `setActive(true)` and a separate launch-agent ensure, while `startIfNeeded()` can independently call `enableLaunchdGateway()`. I did not run a live macOS startup reproduction.

## Solution Assessment

Yes in direction: the narrow maintainable fix is to make `GatewayProcessManager` the single launchd-enable owner. The linked open PR targets that boundary, so the issue should stay open while it is reviewed.
