## Summary

Keep open: current main still has the duplicate macOS local-startup launchd enable path, and an open draft PR is already linked as the candidate fix. The issue should remain open until that PR lands or maintainers choose a different repair.

## What This Changes

The issue reports that macOS local startup can run two concurrent Gateway launchd enable/install paths.

## Best Possible Solution

Review and land or reject the linked fix PR; the desired end state is one macOS local-startup owner for launchd enable with regression coverage for attach-existing and no-listener paths.

## Reproduction Assessment

Yes from source: local startup currently invokes `setActive(true)` and a separate `ensureLaunchAgentEnabledIfNeeded()` task, while `startIfNeeded()` can independently call `enableLaunchdGateway()`. No live macOS run was performed in this read-only review.

## Solution Assessment

Yes in direction: the narrow maintainable fix is to make `GatewayProcessManager` the single launchd-enable owner and cover both attach-existing and normal launch paths. The linked open PR targets that boundary, so the issue should stay open while that PR is reviewed.
