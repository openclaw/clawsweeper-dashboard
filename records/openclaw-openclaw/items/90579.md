## Summary

Keep open: the patch appears to be the active, well-scoped fix for the trusted generated HTML outbound-staging regression, but it still needs explicit maintainer/security acceptance because it expands the host-read HTML trust lifecycle beyond the temp root.

## What This Changes

The PR adds SQLite-backed sha256/size provenance for trusted generated HTML copied into outbound media staging, then verifies that provenance when the staged file is reloaded for host-read delivery.

## Best Possible Solution

Approve or reject the provenance-gated trust lifecycle; if approved, merge after exact-head gates and keep cleanup-scale or send-stage degradation hardening as follow-up work.

Options:

- **Tighten lifecycle first:** Require additional lifecycle constraints such as TTL-based row pruning or chunked stale-row deletion before accepting the new stored trust surface.
- **Reject staged HTML trust:** Keep outbound-staged HTML blocked and rely on PDF or another non-HTML workaround until a different security design is chosen.

## Reproduction Assessment

Yes, at source level. Current main stages local reply media into media/outbound and Telegram reloads that staged .html through a host-read gate that only trusts temp-root realpaths; I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Yes, this appears to be the best fix shape. Path-only outbound trust is too broad, JSON sidecars conflict with repository state policy, and an in-memory allowlist would not survive delayed or restarted delivery.
