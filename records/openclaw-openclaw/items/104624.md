Keep open for maintainer review: the revised head resolves both prior lifecycle findings, supplies credible standalone runtime proof, and has no remaining correctness or security defect, but the unconditional 30-second timeout policy needs explicit acceptance because existing media integrations use different deadlines.

## What This Changes

The PR adds response-header and body-idle deadlines to remote `saveMediaSource()` downloads, coordinates stream teardown before partial-file removal, and adds real-socket regression coverage.

## Best Possible Solution

Retain the revised deterministic teardown and adopt one explicit generic media-store timeout policy without adding public configuration; add a narrow internal caller override only if a concrete gateway or QA use case needs a longer deadline.
