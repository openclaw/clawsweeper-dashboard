## Label Justifications

- `P1`: A current released Control UI can lose trustworthy active-run presentation during reconnect in a real long-running chat workflow.
- `impact:session-state`: Reconnect clears local run identity and stream state even when the selected gateway session may still be active.
- `impact:message-loss`: The surviving run's in-flight output can disappear from the operator's view or appear terminated until history is recovered.

## Summary

Keep open: current main has improved server-side active-session tracking, but Control UI still clears its local run identity and streamed state after a reconnect instead of adopting the surviving active run. A live reproduction on July 16, 2026 against v2026.7.1 confirms the remaining user-visible blank/rebind behavior while the gateway and durable history survive.

## What This Changes

Preserve active Control UI chat run identity, transcript presentation, and appropriate controls across WebSocket reconnects.

## Best Possible Solution

Add an authoritative reconnect-safe active-run descriptor at the gateway/UI boundary, then let Control UI adopt it for the selected session, reload durable history, preserve valid busy and queue controls, and show an explicit detached or terminal recovery state when full adoption is unsafe.
