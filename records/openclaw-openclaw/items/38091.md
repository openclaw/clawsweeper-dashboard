The issue requests that OpenClaw WebChat/Gateway reconnects preserve active AI session state instead of terminating or killing an in-flight run.

## Best Possible Solution

Define one authoritative active-run recovery contract across Gateway sessions/chat history and Control UI reconnect, then stop marking reconnecting active runs killed unless server state proves a terminal outcome.
