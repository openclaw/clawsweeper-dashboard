## Label Justifications

- `P2`: This is a concrete plugin SDK improvement with user-visible impact in third-party channels, but it is not a core-runtime emergency.
- `impact:security`: Without a canonical sanitizer, channel plugins can expose hidden sender, conversation, and untrusted-context metadata to users.
- `impact:ux-friction`: External channel users can receive metadata garbage instead of clean assistant replies until plugin authors copy or reimplement the sanitizer.

## Summary

Keep open: current main and the latest release keep the sanitizer internal, while the linked Weixin plugin PR is already copying the logic because no SDK helper exists. The request fits OpenClaw's plugin-API direction, but adding a public SDK surface needs maintainer API-shape approval.

## What This Changes

Expose the existing inbound metadata stripping helper through the plugin SDK for channel plugins.

## Best Possible Solution

Promote a narrow, documented SDK helper or subpath for channel reply sanitization that reuses the canonical core implementation and locks it with export/API and sanitizer tests.

## Reproduction Assessment

Not applicable as a bug reproduction. Source inspection verifies the requested SDK export is absent while the internal helper exists, and the linked Weixin PR demonstrates the downstream workaround.

## Solution Assessment

Yes, with one adjustment: the maintainable fix is a narrow SDK sanitizer contract rather than asking plugins to import core internals or copy the implementation.
