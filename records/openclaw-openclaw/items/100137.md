## Summary

Keep open. Current main and the latest release have the internal sanitizer and public delivery-hints subpath, but no public plugin SDK export for `stripInboundMetadata`, and the linked Weixin PR shows real external-plugin duplication pressure.

## What This Changes

The issue asks OpenClaw to expose the inbound-metadata stripping helper through the plugin SDK for external channel plugins.

## Best Possible Solution

Keep this open as a focused plugin SDK API decision: expose a narrow documented channel-plugin sanitization contract if maintainers accept that contract, or explicitly fold the need into the broader trusted-decoration design.

## Reproduction Assessment

Yes for the SDK gap from source inspection: the helper exists in core and the public SDK entrypoint/export lists lack a matching helper. This is not a failing OpenClaw runtime repro; it is a source-reproducible public API absence.

## Solution Assessment

Unclear in exact shape. A plugin SDK sanitization helper is policy-aligned, but maintainers should decide whether to export the exact text-strip helper or defer to a broader trusted inbound-decoration contract.
