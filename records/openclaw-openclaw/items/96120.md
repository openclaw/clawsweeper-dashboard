## Summary

Keep open: current main still lacks the auth-profile-backed MCP bearer projection, and the patch appears technically sound, but merging remains a maintainer product/security decision because it adds a credential-selection config surface and sends refreshed OAuth access tokens into local Codex MCP config.

## What This Changes

Adds `mcp.servers.*.oauth.authProfileId` plus refreshed bearer projection for embedded MCP, CLI bundle MCP, and local Codex app-server user MCP config.

## Best Possible Solution

Land only after maintainer acceptance of the new config/auth boundary, with the native OAuth no-authProfileId gap left canonical in https://github.com/openclaw/openclaw/issues/98447.

## Reproduction Assessment

Yes at source level: current main projects Codex MCP servers from common fields and headers only, so an auth-profile-backed OAuth token cannot be refreshed or injected through that path.

## Solution Assessment

Mostly yes for the scoped auth-profile path: the patch uses Codex-supported header fields, strips refresh tokens and OpenClaw-only auth metadata, and fails closed remotely, but maintainers still need to accept this product/security boundary.
