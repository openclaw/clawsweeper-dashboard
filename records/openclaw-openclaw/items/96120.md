## Summary

Keep open: the current head still leaves MCP SDK transport-triggered refresh outside the new credential-store lock, so it can race external-runtime projection refresh and replay a rotating refresh token. The architecture is otherwise well-developed, but direct live proof of the projected CLI or local Codex path is also still incomplete.

## What This Changes

Adds refresh-capable projection of OpenClaw-managed MCP OAuth access tokens into CLI runners and local Codex app-server sessions, including an optional auth-profile selector, token-expiry persistence, tool-filter projection, and unavailable-server omission.

## Best Possible Solution

Use one store-owned refresh primitive or wrap the MCP SDK transport refresh fetch so every token refresh acquires the same in-process and cross-process lock, persists the rotated response before release, and is covered by a transport-versus-projection concurrency regression plus redacted live external-runtime proof.
