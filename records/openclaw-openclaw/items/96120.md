## Summary

The PR addresses the real Codex MCP OAuth projection gap at the correct OpenClaw credential-owner boundary, but it is not merge-ready: the latest head introduces a cross-runtime rotating-refresh-token race, lacks real-service proof for the new MCP-native path, and still needs explicit approval for the new public credential selector and local Codex token boundary.

## What This Changes

The branch refreshes and projects MCP-native or auth-profile OAuth access tokens into embedded MCP, CLI runners, and local Codex app-server threads, while adding an optional `mcp.servers.*.oauth.authProfileId` selector and related config, SDK, docs, and tests.

## Best Possible Solution

Put every MCP OAuth refresh request and credential-store mutation—embedded SDK, CLI projection, and Codex projection—behind one per-store queue and cross-process lock, then retain the guarded local-only access-token projection only after maintainers approve and document `oauth.authProfileId` precedence and the local Codex security boundary.
