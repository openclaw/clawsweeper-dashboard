## Summary

The reorder correctly prevents a failed plugin preparation from permanently publishing metadata for code that never loaded, and the current head merges cleanly with green CI. Keep the PR open because contributor-supplied after-fix gateway proof is still required, and the publication point should ideally sit beside the runtime replacement after old services stop.

## What This Changes

Moves publication of the current plugin metadata snapshot until after plugin reload preparation succeeds.

## Best Possible Solution

After preparation succeeds, stop the previous services and publish the new metadata immediately beside the synchronous attached-runtime replacement, then prove with a real gateway reload that preparation failure preserves both previous states.
