## Summary

Keep this PR open, but the patch is not merge-ready: it fixes a real `api` owner-routing gap, yet it also changes baseUrl-only `openai` memory configs to the generic adapter even though current OpenAI memory code already honors provider `baseUrl`, and it leaves index-identity resolution on the old adapter lookup path.

## What This Changes

The PR threads an `actualProvider` value from memory-search config resolution into memory-core embedding creation so configured provider aliases can choose a different adapter at runtime.

## Best Possible Solution

Keep direct provider `baseUrl` on the direct memory adapter unless maintainers explicitly change that contract, use `actualProvider` only for explicit api-owner routing, and make runtime creation plus index identity resolve through the same adapter choice.

## Reproduction Assessment

Yes for part of the report: source inspection shows current main short-circuits direct `openai` before explicit `api` owner routing. The baseUrl-only claim is not reproduced because current OpenAI memory code already reads configured provider `baseUrl`.

## Solution Assessment

No. The best fix is narrower than this PR: preserve direct baseUrl behavior, route only explicit api-owner overrides, and keep index identity aligned with runtime adapter lookup.
