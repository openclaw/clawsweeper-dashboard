## Summary

Keep open. The current patch is still incomplete: it changes config metadata selection but does not route baseUrl-only OpenAI-compatible configs through the generic adapter, and it does not carry the resolved provider identity into runtime creation or index identity.

## What This Changes

The branch adds a config-level direct-adapter override in `src/agents/memory-search.ts` plus one memory-search resolver test for `openai` configured with `api: "ollama"`.

## Best Possible Solution

Use one provider-resolution path that returns both the configured provider id and the adapter id, then pass that resolved adapter identity through runtime creation, fallback model resolution, and index identity while preserving the original configured id for config/auth lookup.

  - confidence: 0.94
