## Summary

Keep open: current main still treats registered reply work with no embedded handle and no numeric progress sample as non-stale, so recovery can return `active_reply_work` indefinitely; the cited fixes cover adjacent states but not this missing-progress case.

## What This Changes

Make stuck-session recovery reclaim phantom reply-work ownership when no embedded run or progress record backs the claim, instead of permanently keeping the lane.

## Best Possible Solution

After the existing stale threshold, treat queued reply ownership with neither an embedded handle nor authoritative progress as phantom and clear it through the existing generation-safe abort/drain and lane-reset paths, while preserving fresh work and deferred maintenance.
