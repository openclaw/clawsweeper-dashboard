## Summary

This is a credible, narrowly scoped doctor migration bug: the shipped migration can repeatedly detect an expired Telegram legacy sidecar without importing, archiving, or explaining it when the namespace is full. Current evidence does not show a merged fix or canonical replacement, so the issue remains necessary.

## What This Changes

Make Telegram sent-message-cache legacy migration discard expired entries, clean up fully expired sources, and report namespace-capacity skips instead of silently repeating forever.

## Best Possible Solution

Filter expired Telegram legacy records before registration, count them as safely covered for source cleanup, emit one clear warning whenever unexpired records cannot fit at namespace capacity, and add regression coverage for fully expired, mixed-expiry, and full-namespace cases without adding runtime fallback state.

## Solution Assessment

Yes, with a narrow boundary: expired entries should be excluded and treated as covered by the Telegram migration reader, while the generic runner should diagnose unexpired entries blocked by namespace capacity. Broad runtime compatibility or fallback handling would be less maintainable.
