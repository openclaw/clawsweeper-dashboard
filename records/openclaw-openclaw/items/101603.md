## Summary

Keep open: current main and v2026.6.11 still have the fixed 60-second Dream Diary wait, the parsed timeout field is not exposed or wired into the memory-core narrative wait, and timeout fallback cleanup still deletes accepted attempt sessions after writing the stub. The older timeout/config issue and the open timeout-only PR overlap, but this report adds queue-time and late-output cleanup behavior that remains unresolved.

## What This Changes

Fix memory-core Dream Diary narrative generation so timeout/config handling accounts for queued runs and timeout cleanup does not discard successful late or fallback-model output.

## Best Possible Solution

Define one Dream Diary narrative contract that wires timeout config through manifest/runtime if accepted, treats queued versus executing time explicitly, and prevents timeout cleanup from silently discarding late successful output.
