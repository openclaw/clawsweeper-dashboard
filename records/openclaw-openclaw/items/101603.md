## Summary

Keep open: current main and the latest release still have the fixed 60-second Dream Diary wait, the parsed timeout field is not accepted by the plugin manifest or wired into the narrative wait, and timeout cleanup still deletes accepted attempt sessions after writing the fallback stub. The older timeout/config issue and open timeout-only PR overlap, but this report adds a distinct queue-time plus cleanup/discarded-output failure mode that should stay visible.

## What This Changes

The issue reports that memory-core Dream Diary narrative generation uses a hardcoded 60s wait that includes queue time, rejects the parsed timeout config at manifest validation, and discards later successful fallback-model output after timeout disposal.

## Best Possible Solution

Land one memory-core narrative contract that wires timeout config through manifest and runtime, accounts for queued versus executing time, and preserves or intentionally terminates late successful model output without misleading provider-fallback telemetry.
