## Summary

Keep open: current main and v2026.6.11 still use a fixed 60-second Dream Diary wait, reject the parsed timeout setting at the memory-core manifest boundary, and delete accepted narrative sessions after timeout fallback. Older no-text and timeout reports overlap, but this issue adds a distinct queue-time plus timeout-cleanup/discarded-output failure mode with fresh corroboration.

## What This Changes

The issue asks memory-core Dream Diary to stop using an unwired fixed 60-second narrative wait that counts queued time and to avoid discarding successful late or fallback-model output after timeout cleanup.

## Best Possible Solution

Define one memory-core Dream Diary timeout and lifecycle contract that wires accepted config through manifest/runtime, separates queued versus executing deadline semantics, and preserves or intentionally cancels late output with tests and docs.
