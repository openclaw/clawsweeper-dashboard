## Summary

Keep open: current main and v2026.6.11 still use a fixed 60-second Dream Diary narrative wait, parse but do not expose or wire timeout config, and write fallback text before cleaning up accepted attempt sessions. Existing related work covers timeout config or adjacent readback/concurrency slices, but no merged item owns the combined queue-time timeout plus late successful output discard described here.

## What This Changes

The issue requests a memory-core Dream Diary fix for fixed timeout accounting, unwired timeout config, and timeout cleanup that can discard successful fallback-model narrative output.

## Best Possible Solution

Land one maintainer-approved memory-core Dream Diary contract that wires timeout config through manifest and runtime, accounts for queue versus execution time, and preserves or intentionally terminates late successful narrative output without misleading fallback telemetry.
