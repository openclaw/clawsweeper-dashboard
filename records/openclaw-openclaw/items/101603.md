## Summary

Keep open: current main and v2026.6.11 still use a fixed 60-second Dream Diary wait, only expose `model` in the strict memory-core execution schema, and delete accepted narrative sessions after timeout fallback. The overlapping timeout PR #78440 is open/conflicting and covers only part of the queue-time plus late-output cleanup problem.

## What This Changes

The issue requests fixing memory-core Dream Diary narrative runs so queue wait, timeout configuration, and timeout cleanup do not replace successful model output with fallback diary stubs.

## Best Possible Solution

Define one memory-core Dream Diary timeout and cleanup contract, then update manifest, runtime, docs, and tests so queue wait does not consume the execution deadline and timeout cleanup does not discard useful late output unintentionally.
