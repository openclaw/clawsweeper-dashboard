## Summary

Keep open: current main and v2026.6.11 still have the fixed 60-second Dream Diary wait, strict manifest schemas that reject the parsed timeout field, and cleanup that deletes accepted narrative sessions after timeout fallback. The open timeout-only PR overlaps, but it does not cover queue-time accounting or the reported late successful output being discarded.

## What This Changes

The issue reports that memory-core Dream Diary narrative generation uses a fixed 60s wait that includes queue time, rejects timeout config, and deletes sessions after timeout so later successful output is discarded.

## Best Possible Solution

Land one maintainer-approved memory-core Dream Diary contract that covers timeout configuration, queued-versus-executing deadline semantics, readback of late successful output, and cleanup/telemetry behavior without creating parallel config surfaces.
