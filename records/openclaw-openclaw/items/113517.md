## What This Changes

This PR adds a plugin-owned external verification ceremony for protected tool approvals, with Gateway-owned denial, lifecycle handling, final resolution, and audit state.

## System Context

A plugin can intercept a protected tool call and request a Gateway approval before the tool runs. This PR lets the reviewer start a plugin verifier for allow decisions while the Gateway keeps the approval record, authorization checks, cancellation, timeout, and final tool continuation under host control.

## Architecture Diagram

flowchart LR
  Tool[Protected tool call] --> Hook[Plugin approval hook]
  Hook --> Gateway[Gateway approval record]
  Gateway --> Reviewer[Authorized reviewer]
  Reviewer --> Verifier[Plugin external verifier]
  Verifier --> Resolution[Host-bound completion]
  Resolution --> Ledger[Gateway audit and decision ledger]
  Ledger --> Result[Tool allowed or denied]

## Best Possible Solution

Adopt the API only if maintainers explicitly endorse a narrow, host-bound external-verification contract: one verifier per plugin, generic deny-only resolution, host-authoritative final state, documented lifecycle semantics, and compatibility coverage for future plugin SDK changes.
