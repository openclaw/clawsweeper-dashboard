## What This Changes

This PR adds a plugin SDK capability for external verification of protected tool approvals, while keeping Gateway-owned approval identity, denial, lifecycle handling, final resolution, audit history, and reviewer-facing presentation.

## System Context

A plugin’s `before_tool_call` hook can require approval before a protected tool runs. The Gateway owns the pending approval and resolution ledger; this feature lets the owning plugin run an external verification ceremony and report a bounded allow outcome back to that Gateway-controlled lifecycle.

## Architecture Diagram

flowchart LR
  Hook[Plugin tool hook] --> Pending[Gateway pending approval]
  Pending --> Reviewer[Authorized reviewer]
  Reviewer --> Verifier[Owning plugin verifier]
  Verifier --> Completion[Gateway completion check]
  Completion --> Ledger[Approval and attempt ledger]
  Ledger --> Result[Allow protected tool or deny/cancel it]

## Best Possible Solution

Merge only after the approval/plugin-SDK owners explicitly sponsor the external-verification authority model, durable ledger semantics, and compatibility/deprecation plan as the supported narrow host contract.
