## What This Changes

This PR adds host-owned external-verification approvals so plugins can defer a protected tool’s allow decision to a verifier while the Gateway retains approval identity, reviewer authorization, lifecycle control, and final resolution.

## System Context

A plugin’s `before_tool_call` hook can block a sensitive tool and ask the Gateway to present an approval. Native clients and the TUI then start a plugin-owned verification ceremony, while the Gateway persists the attempt and permits or denies the original tool call.

  Gateway --> Client[Native client or TUI]
  Client --> Verifier[External verifier]
  Verifier --> Gateway
  Gateway --> Result[Allow or deny tool execution]
