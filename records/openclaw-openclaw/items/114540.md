## Summary

The current-main hunk releases the SSRF-safe dispatcher without cancelling the status-only response body, while this branch starts best-effort cancellation before release; the same root cause is also addressed by the still-open related PR, so a maintainer should select one landing path rather than auto-close either proposal.

## What This Changes

The PR cancels unread local-provider HTTP response bodies during cron model preflight before releasing the guarded HTTP dispatcher, with regression coverage for stalled and concurrent streams.

## System Context

Cron jobs preflight local Ollama and OpenAI-compatible endpoints before running an isolated agent. The preflight only needs an HTTP status, then releases its SSRF-safe HTTP dispatcher and returns an availability result that is cached for later cron runs.
