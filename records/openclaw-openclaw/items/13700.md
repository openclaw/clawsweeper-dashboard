## Summary

Keep open: current main and the latest release only provide compaction-created checkpoint branch/restore primitives, while this issue still asks for named `/session save` and `/session load` snapshots, reusable templates, archive import, and prompt-cache-sensitive forking that need product and security design.

## What This Changes

Request to add explicit session snapshot save/load/restore/fork capabilities so users can checkpoint and rehydrate conversation context.

## Best Possible Solution

Define a native session snapshot design that builds on current compaction checkpoint branch/restore, session-store metadata, transcript archive handling, and active-run interruption rules, then add save/list/load/branch semantics across chat commands, Gateway protocol, CLI/UI, docs, and focused tests.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature/design request. Source inspection gives high confidence that the requested `/session save` and `/session load` workflow is absent from current main and v2026.6.11.

## Solution Assessment

No autonomous implementation path is best yet. The best fix is a maintainer-owned design that decides destructive restore versus branch/import behavior, retention, archive trust, prompt-cache constraints, and security boundaries before code is written.
