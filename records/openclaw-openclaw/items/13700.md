## Summary

Keep open: current main and v2026.6.11 still lack named `/session save` and `/session load` snapshots, reusable templates, prompt-cache-safe forks, and reset/deleted archive import; existing compaction checkpoints and open related work cover narrower slices only.

## What This Changes

The issue requests named session checkpoints and restore/fork workflows such as `/session save` and `/session load` for conversation state, context, model choice, and reusable branches.

## Best Possible Solution

Define one native session snapshot design that composes SessionManager transcript lineage, compaction checkpoints, reset/deleted archive discovery, Gateway protocol, chat/CLI/UI commands, security rules, docs, and focused tests.

## Security Review

Status: needs_attention

Summary: Any implementation must treat snapshots, archive import, restored provider bindings, and forked context as sensitive session-state boundaries.

Concerns:

- **[medium] Define snapshot and archive visibility boundaries:**
  - body: Saved and archived transcripts can contain private user messages, tool output, and workspace state; exposing them through commands or Gateway APIs needs explicit ownership checks, retention rules, redaction expectations, and docs.
  - confidence: 0.84
- **[medium] Avoid stale backend or approval inheritance on restore:**
  - body: Restoring or forking a transcript can accidentally carry provider-side session bindings, auth/runtime overrides, or expired approvals unless the design deliberately clears, verifies, or restores those fields.
  - confidence: 0.82
