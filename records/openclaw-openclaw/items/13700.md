## Summary

Keep open: current main and the latest release only provide settings-style `/session` commands plus compaction-scoped checkpoint branch/restore, not the requested named save/load snapshots, reusable templates, arbitrary archive restore, or settled product/API contract.

## What This Changes

The issue requests first-class session snapshots with `/session save <name>` and `/session load <name>` plus branching/reuse semantics for long-running agent sessions.

## Best Possible Solution

Define a maintainer-approved native session snapshot contract that composes SessionManager, session store metadata, compaction checkpoints, reset/deleted archives, and subagent fork primitives before exposing save/list/load/branch behavior.
