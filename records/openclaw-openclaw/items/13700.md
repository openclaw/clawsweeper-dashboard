## Summary

Keep open: current main has adjacent session switching, read-only history, reset-archive fallback reads, and compaction checkpoint branch/restore, but it still lacks the requested named `/session save` and `/session load` snapshot workflow, reusable session templates, arbitrary archive import/restore, and a settled product contract.

## What This Changes

Request adds first-class named session snapshots with `/session save` and `/session load` for restoring or forking conversation context, model choice, and related session state.

## Best Possible Solution

Define a maintainer-approved native snapshot contract that composes the session store, SessionManager, compaction checkpoints, reset/deleted archive handling, and fork support before exposing save/list/load/branch behavior across chat commands, Gateway protocol, CLI/UI, docs, and tests.
