## Summary

Keep open: current main still lacks arbitrary named session snapshots and exact save/load behavior. Existing compaction recovery, session branching primitives, and the narrower open `/resume` work address adjacent cases but do not cover the full request.

## What This Changes

Add named session checkpoints that can save, restore, and fork conversation, context, and model state.

## Best Possible Solution

Define a Gateway-owned, branch-first snapshot contract backed by canonical per-agent persisted state, then add named list, branch, and explicitly confirmed restore flows with retention, authorization, migration, and fresh-install tests.

Question: Should named snapshots become a branch-first core session capability, and should destructive replacement of the active session be supported at all?

Rationale: Existing primitives do not settle persistence ownership, destructive restore semantics, retained model metadata, archive handling, authorization, or the intended chat, CLI, and UI scope.

Likely owner: steipete

Owner confidence: high

Options:

- **Branch-First Snapshots (recommended):** Add immutable named checkpoints that create a new session branch by default, deferring destructive replacement or requiring a separate explicit action.
- **Full Save and Load:** Allow snapshots to replace the active session after explicit confirmation and strict transcript, model, provider, and metadata validation.
- **Keep Recovery Narrow:** Retain only compaction recovery and ordinary prior-session resume rather than introducing general named snapshots.
