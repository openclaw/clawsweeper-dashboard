## Summary

Keep open: current main and v2026.6.11 still lack first-class named `/session save` and `/session load` snapshots, reusable templates, or reset/deleted archive import; existing compaction checkpoint branch/restore and subagent fork primitives only cover adjacent slices.

## What This Changes

The issue asks for explicit session checkpoints with `/session save <name>` and `/session load <name>` so users can restore or branch messages, context, model choice, and transcript state.

## Best Possible Solution

Define one maintainer-approved core session snapshot contract that composes existing compaction checkpoints, session-store metadata, reset/deleted archive recovery, public fork/resume semantics, retention, permissions, and CLI/chat/UI docs/tests.
