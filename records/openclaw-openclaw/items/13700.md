## Summary

Keep open: current main and v2026.6.11 have adjacent compaction checkpoint branch/restore and subagent fork primitives, but still lack the requested first-class named `/session save`/`load` snapshots, reusable templates, and reset/deleted archive import workflow.

## What This Changes

Request first-class named session snapshots with save/load, restore, and branch/fork semantics for long-running sessions.

## Best Possible Solution

Define one versioned session snapshot contract that composes the existing compaction checkpoint primitive, SQLite-backed session persistence, reset archive recovery, public fork/resume semantics, retention, permissions, and CLI/chat/UI documentation/tests.

## Reproduction Assessment

Not applicable as a bug reproduction; source and docs inspection on current main and v2026.6.11 verify the requested `/session save`/`load` and arbitrary snapshot APIs are absent while compaction checkpoint APIs exist.

## Solution Assessment

Unclear for implementation: the capability is valid, but the proposed checkpoint-file shape conflicts with current storage policy and needs a maintainer-approved session-store, Gateway protocol, security, and UX design.
