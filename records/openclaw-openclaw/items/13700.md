## Summary

Keep open: current main and v2026.6.11 still provide only compaction-scoped checkpoint list/get/branch/restore and adjacent session primitives, not first-class named `/session save`/`load` snapshots, reusable templates, or reset/deleted archive import.

## What This Changes

The issue requests explicit session snapshots with named save/load, restore, fork, and reusable checkpoint semantics for long-running sessions.

## Best Possible Solution

Define one maintainer-approved session snapshot contract that composes compaction checkpoints, session metadata, reset/deleted archive recovery, fork/resume semantics, retention, permissions, CLI/chat/UI behavior, docs, and focused tests.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature/API request. Source and docs inspection on current main and v2026.6.11 give high-confidence evidence that the requested named save/load snapshot workflow is absent while narrower compaction checkpoint APIs exist.

## Solution Assessment

Unclear as a concrete implementation. The capability is useful, but the proposed file-based checkpoint shape is not the best solution until maintainers choose the storage model, protocol, restore safety rules, and UI/CLI command semantics.
