## Summary

Keep open: current main and v2026.6.11 still lack the requested named `/session save` and `/session load` snapshot workflow; existing compaction checkpoint branch/restore and SessionManager fork/resume primitives are useful building blocks but do not cover arbitrary named checkpoints, archive import, reusable templates, or prompt-cache-sensitive forks.

## What This Changes

The issue requests explicit named session snapshot commands for saving, loading, restoring, and forking agent context checkpoints.

## Best Possible Solution

Define a native session snapshot design that builds on session store metadata, SessionManager transcript branching, compaction checkpoint artifacts, reset/deleted archive handling, and subagent fork support, then add save/list/load/branch semantics across slash commands, Gateway protocol, CLI/UI docs, and focused tests.
