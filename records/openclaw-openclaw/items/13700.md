## Summary

Keep open: current main and the latest release still have only compaction-scoped checkpoint branch/restore plus parent transcript forking, not the requested named `/session save`/`load` snapshots, reusable templates, or reset/deleted archive import. The issue remains useful, but it needs maintainer product/API/security design rather than conservative cleanup closure.

## What This Changes

Request adding explicit session snapshot save/load/restore/fork workflows for long-running conversations, including named checkpoints, branching, reusable templates, and archive recovery.

## Best Possible Solution

Define one maintainer-approved native snapshot contract that composes session-store metadata, compaction checkpoints, reset/deleted archive recovery, branch/load semantics, permissions, retention, CLI/chat/UI behavior, docs, and focused tests.
