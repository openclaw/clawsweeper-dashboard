## Summary

Keep open: current main has compaction-scoped checkpoint list/get/branch/restore and UI recovery affordances, but it still does not provide the requested named `/session save` and `/session load` snapshots, reusable templates, archive import, or prompt-cache-aware fork semantics. The remaining work is a session-state product/API design rather than a cleanup-close candidate.

## What This Changes

Request to add named session save/load snapshots, restore/import existing transcript archives, and support branching or forking from saved session state.

## Best Possible Solution

Define a maintainer-approved native session snapshot design with versioned Gateway/session protocol, canonical SQLite-backed storage, retention/security rules, slash/CLI/UI docs/tests, and reuse of the existing compaction checkpoint accessor primitives where they fit.
