## Summary

Keep open: current main and v2026.6.11 still provide only adjacent compaction-checkpoint branch/restore and reset-archive fallback reads, not the requested named `/session save` and `/session load` snapshot workflow; related open items cover narrower slices and do not replace the needed product/API decision.

## What This Changes

The issue requests first-class session snapshots so users can save, load, restore, and branch conversation context checkpoints across long-running sessions.

## Best Possible Solution

Define a maintainer-approved native snapshot contract that composes the session store, SessionManager, compaction checkpoints, reset/deleted archive handling, and fork support before exposing save/list/load/branch behavior across chat commands, Gateway protocol, CLI/UI, docs, and tests.
