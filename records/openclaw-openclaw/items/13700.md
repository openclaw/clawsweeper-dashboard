## Summary

Keep open: current main and the latest release still have adjacent session switching, read-only history, reset-archive fallback reads, and compaction checkpoint branch/restore, but not the requested named session snapshot save/load workflow or settled snapshot/fork/archive-restore contract.

## What This Changes

The issue requests explicit session snapshot commands to save, load, restore, and fork conversation/context checkpoints for rollback, branching, batch reuse, and session-loss recovery.

## Best Possible Solution

Define one maintainer-approved native session snapshot contract that composes the session store, compaction checkpoints, reset/deleted archive handling, and fork support before exposing save/list/load/branch behavior across chat commands, Gateway protocol, CLI/UI, docs, and tests.
