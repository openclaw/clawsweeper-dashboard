## Summary

Keep open: current main still exposes task-suggestion tools from session-key presence rather than a surface/action-sink capability, and the Gateway-backed TUI event loop does not handle task-suggestion accept or dismiss actions. The live issue also carries the protected `maintainer` label, so conservative cleanup should not close it.

## What This Changes

The issue reports that task-suggestion tools can appear on sessions without actionable suggestion UI, especially the Gateway-backed TUI, which lacks accept/dismiss handling.

## Best Possible Solution

Add an explicit per-turn task-suggestion action-sink capability, expose `spawn_task` and `dismiss_task` only when that sink exists, and either implement the Gateway-backed TUI accept/dismiss flow or keep the tools Control UI-only until the TUI flow is sponsored.
