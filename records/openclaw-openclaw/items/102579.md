## Summary

This issue should stay open: current main still exposes `spawn_task` and `dismiss_task` whenever a run/session key exists, while only Control UI has an accept/dismiss action flow and the protected `maintainer` label requires explicit maintainer handling.

## What This Changes

The issue asks for task-suggestion tools to be exposed only on surfaces with an actionable suggestion sink and for the Gateway-backed TUI to support inspect, accept, and dismiss flows.

## Best Possible Solution

Add an explicit per-turn task-suggestion action-sink capability, expose `spawn_task` and `dismiss_task` only when that sink is present, and make the TUI accept/dismiss path match the managed-worktree session contract if maintainers want TUI support now.
