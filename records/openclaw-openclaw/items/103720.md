## Summary

This issue remains necessary on current main. Archived transcripts are intentionally retained for memory search, but Dreaming consumes the same corpus metadata without a separate eligibility or deduplication rule; the sanitizer also drops only the exact `HEARTBEAT_OK` token, so generated natural-language heartbeat replies can remain. The two suggested one-line changes are not safe as written, but the underlying Dreaming corpus-contamination bug is actionable and is not fully owned by the related issues or their closed PRs.

## What This Changes

Prevent archived transcript duplicates and generated heartbeat replies from contaminating Dreaming while preserving archived-session search coverage.

## Best Possible Solution

Add explicit Dreaming eligibility or deduplication metadata to the shared transcript-corpus entry while retaining archives for search, and carry generated-heartbeat turn provenance through parsing so only the paired synthetic assistant response is excluded.

Required: false

## Reproduction Assessment

Yes, at source level. Current main deliberately enumerates archived transcript artifacts and removes only exact-token heartbeat assistant replies, so focused fixtures can reproduce both ingestion paths without relying on the reporter's installation.

## Solution Assessment

No, the proposed direct changes are not the best solution. Excluding archives from the shared lister would regress search, while replacing the exact comparison with `isHeartbeatOkResponse` would still not catch natural-language acknowledgments lacking the heartbeat token; the fix should use Dreaming-specific eligibility and heartbeat-turn provenance.
