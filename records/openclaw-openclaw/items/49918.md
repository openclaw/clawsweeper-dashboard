Restore hook-visible `command:new` and session-memory behavior for TUI `/new` while preserving isolated per-client `tui-*` sessions.

## Best Possible Solution

Review or replace the open fork PR with a narrow fix that emits `command:new`, `before_reset`, and session lifecycle hooks for the session being left while preserving isolated `tui-*` TUI sessions.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: TUI `/new` calls `setEmptySession(uniqueKey)`, while the gateway reset/create paths are the code that emits `command:new` hooks.

## Solution Assessment

No for current main. The maintainable fix should reuse the existing gateway/session lifecycle with correct previous-session attribution instead of adding a parallel TUI-only hook event or resetting the wrong future key.
