## What This Changes

The issue asks OpenClaw to restore hook-visible `command:new` behavior for TUI `/new` while preserving isolated `tui-*` sessions.

## Best Possible Solution

Restore TUI `/new` through the existing gateway session lifecycle so `command:new`, `before_reset`, and session lifecycle hooks observe the previous session while unique `tui-*` isolation is preserved.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: TUI `/new` calls local `setEmptySession(uniqueKey)`, while docs and gateway reset/create tests show `command:new` hooks are emitted through gateway lifecycle paths.

## Solution Assessment

Yes on direction, not on the currently linked fork branch. The maintainable fix should reuse the existing gateway session lifecycle with correct previous-session attribution, not add a parallel TUI-only hook event.
