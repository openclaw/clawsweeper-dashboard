## Summary

Keep open: current main and latest release still route TUI `/new` through a local empty-session switch, while the gateway reset/create lifecycle is the path that emits `command:new` hooks. The issue is valid, but a conflicting open fork PR already claims the fix, so this should remain a maintainer follow-up rather than a new automated repair.

## What This Changes

The issue reports that TUI `/new` stopped emitting hook-visible new-session behavior after the TUI session-isolation change switched the path to a local session-key update.

## Best Possible Solution

Restore TUI `/new` through the existing gateway/session lifecycle so `command:new`, `before_reset`, and session lifecycle hooks observe the previous session while preserving unique `tui-*` isolation.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: TUI `/new` calls local `setEmptySession(uniqueKey)`, while the gateway reset/create paths are the code that emits `command:new` hooks.

## Solution Assessment

Yes for the requested direction: the narrow maintainable fix is to reuse the existing gateway/session lifecycle with correct previous-session attribution, not add a parallel TUI-only hook event.
