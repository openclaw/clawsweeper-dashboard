## Summary

Current main still violates Node’s writable-stream backpressure contract in the debug capture proxy. The central reliability bug remains necessary to fix, no duplicate or linked fix was found, and the implementation is not present in the latest release because the affected proxy was added afterward.

## What This Changes

Harden the debug capture proxy against ignored response backpressure and downstream client disconnects.

## Best Possible Solution

Give the HTTP forwarding path one lifecycle controller that pauses the upstream response when downstream writes apply pressure, resumes only after `drain`, and cancels upstream work when the downstream closes, while preserving capture and partial-response semantics.

## Solution Assessment

Yes in direction, provided the repair coordinates pause, drain, and teardown across the forwarding lifecycle rather than adding isolated try/catch wrappers around writes.

Respect downstream `ServerResponse.write()` backpressure, pause and resume the upstream response without accumulating `drain` listeners, and cancel or destroy upstream work when the downstream request or response closes or aborts. Preserve body-preview capture, event recording, partial-response handling, current 502 behavior, and CONNECT tunnel semantics.
