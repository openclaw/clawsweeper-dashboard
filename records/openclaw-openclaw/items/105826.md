## Summary

This PR remains necessary because current main no longer enforces the unused-export ratchet, and its current-target versus historical-target CI split is well supported. It is not merge-ready yet: the unchanged broad fixture exclusions suppress export diagnostics for dynamically loaded QA runtime fixtures, so the restored guard would retain a known blind spot.

## Best Possible Solution

Retain mandatory export checks for current targets and feature-detected compatibility for historical targets, but narrow or negate the fixture exclusions so dynamically loaded QA runtime modules remain scanned, with a guard test covering that boundary.
