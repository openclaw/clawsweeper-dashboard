## Summary

Keep open: current main and v2026.6.11 are still Node-hosted, and the current agent-core and harness surfaces do not provide the requested no-Node/no-Linux runtime protocol for embedded devices. MimiClaw is useful prior art, but the remaining work is a broad runtime/API product decision rather than conservative cleanup.

## What This Changes

The issue requests a runtime-agnostic OpenClaw agent interface or protocol so C, Rust, WASM, or embedded ports can run OpenClaw-style agents without Linux or Node.js.

## Best Possible Solution

Keep this as the canonical maintainer design issue for a runtime-neutral agent-core contract, including schemas for tool calls, memory/session state, streaming/events, auth/model selection, platform adapters, security boundaries, conformance tests, and a decision on whether OpenClaw will support external embedded ports.

Owner confidence: high

Options:

- **Keep As Runtime-Portability RFC (recommended):** Use this issue to design minimal schemas, conformance tests, and ownership boundaries before accepting embedded or WASM implementation work.
- **Scope To Plugin SDK Only:** Route near-term language/runtime work through JSON-RPC plugin or harness APIs and leave full no-Node ports outside the supported OpenClaw contract.
- **Close As Not Planned:** Decide that OpenClaw remains Node-hosted and external projects such as MimiClaw are independent ports without compatibility promises.
