## Summary

Keep open: current main and the latest release still require a Node-hosted OpenClaw CLI/Gateway, and the existing plugin and agent-harness surfaces are in-process TypeScript contracts rather than a runtime-neutral protocol for bare-metal, C/Rust/WASM, or ESP32-class ports. MimiClaw is useful prior art, but it does not make this OpenClaw core/API direction implemented or safely ClawHub-only.

## What This Changes

The issue requests support for running OpenClaw-style agent loops on embedded or ultra-low-resource devices without Linux or Node.js.

## Best Possible Solution

Keep this as the canonical maintainer design discussion for a runtime-neutral agent-core contract, conformance tests, platform-adapter boundaries, and a decision on what belongs in core versus external ports or plugin APIs.

## Reproduction Assessment

Not applicable: this is a feature and architecture request rather than a bug report. Source and docs inspection confirm the missing behavior because current main and v2026.6.11 only support Node-hosted OpenClaw runtimes.

## Solution Assessment

Unclear: the requested direction is plausible, but the best first step is a maintainer-approved protocol/RFC and conformance boundary rather than a one-off embedded runtime patch. MimiClaw is useful prior art, not a drop-in solution for OpenClaw core.
