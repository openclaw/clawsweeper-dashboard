## Summary

Keep open: current main and the latest release still run OpenClaw as a Node-hosted CLI/Gateway, and the newer `@openclaw/agent-core` extraction is a useful private TypeScript/runtime contract rather than a stable no-Node, bare-metal, C/Rust/WASM-compatible agent protocol. MimiClaw remains relevant external prior art, but it does not make the OpenClaw core/API direction implemented or safely ClawHub-only.

## What This Changes

The issue requests support for running an OpenClaw-style agent loop on no-Linux/no-Node embedded or ultra-low-resource devices, inspired by MimiClaw.

## Best Possible Solution

Keep this as the canonical design discussion for a runtime-neutral agent-core contract, platform-adapter boundary, conformance tests, and a maintainer decision on what should live in OpenClaw core versus external ports or plugins.

## Reproduction Assessment

Not applicable: this is a feature and architecture request rather than a bug report. Source and docs inspection confirm the missing behavior because current main and v2026.6.11 still require a Node-hosted OpenClaw runtime.

## Solution Assessment

Unclear: the requested direction is plausible, especially with the newer agent-core extraction, but the best first step is a maintainer-approved protocol/RFC and conformance boundary rather than a one-off embedded runtime patch.
