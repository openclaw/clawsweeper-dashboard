## Summary

Keep open: current main and v2026.6.11 remain Node-hosted, and the reusable `agent-core` package does not provide the requested no-Node/no-Linux runtime protocol for embedded devices. MimiClaw remains useful prior art, but this is a maintainer product/API decision rather than a cleanup-close candidate.

## What This Changes

The issue requests a runtime-agnostic OpenClaw agent interface or core that can run on embedded, bare-metal, C/Rust/WASM, or other no-Node/no-Linux environments.

## Best Possible Solution

Keep this as the canonical maintainer design issue for a runtime-neutral agent-core contract, conformance tests, platform-adapter boundaries, and the core-versus-external-port decision.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw define and support a runtime-neutral agent-core protocol for no-Node embedded or WASM ports, or should those ports remain independent external projects without a core compatibility contract?

Rationale: Current source and docs show OpenClaw is intentionally Node-hosted, and choosing a portable agent ABI affects runtime ownership, plugin SDK boundaries, storage/session semantics, providers, tools, and security policy.

Likely owner: steipete

Owner reason: The strongest current history is on the agent runtime extraction, reusable runtime package, harness docs, and prior discussion on this issue.

Owner confidence: high

Options:

- **Keep As Runtime-Portability RFC (recommended):** Use this issue to design minimal schemas, conformance tests, and ownership boundaries before accepting embedded or WASM implementation work.
- **Scope To Plugin SDK Only:** Route near-term language/runtime work through JSON-RPC plugin or harness APIs and leave full no-Node ports outside the supported OpenClaw contract.
- **Close As Not Planned:** Decide that OpenClaw remains Node-hosted and external projects such as MimiClaw are independent ports without compatibility promises.
