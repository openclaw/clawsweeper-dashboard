## Summary

Keep open: current main and latest release still require a Node-hosted OpenClaw runtime, and the existing Gateway, plugin SDK, agent harness, and private TypeScript agent-core package do not satisfy the requested bare-metal/no-Node runtime-neutral agent protocol. This remains a maintainer product/API design item, with MimiClaw useful as external prior art.

## What This Changes

Request support for running OpenClaw-style agent logic on no-Linux/no-Node embedded or ultra-low-resource devices through runtime decoupling, a portable agent protocol, platform adapters, and optional reference implementations.

## Best Possible Solution

Keep this as the canonical maintainer design discussion for a runtime-neutral agent-core contract, conformance tests, platform-adapter boundaries, and the decision about which parts belong in OpenClaw core versus external ports or plugins.

## Reproduction Assessment

Not applicable: this is a feature and architecture request rather than a bug report. Source and docs inspection confirm the missing behavior because current main and v2026.6.11 only support Node-hosted OpenClaw runtimes.

## Solution Assessment

Unclear: the requested direction is plausible, but the best first step is a maintainer-approved protocol/RFC and conformance boundary rather than a one-off embedded runtime patch. MimiClaw is useful prior art, not a drop-in implementation for OpenClaw core.
