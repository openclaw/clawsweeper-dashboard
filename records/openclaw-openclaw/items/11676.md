## Summary

Current main and v2026.6.11 contain a reusable TypeScript agent-core extraction, but OpenClaw still requires Node and does not define the requested cross-language, bare-metal-compatible runtime protocol; the broader product/API decision remains necessary and no related item fully owns it.

## What This Changes

Define a runtime-agnostic OpenClaw agent-core contract that can support C, Rust, WASM, embedded, and bare-metal implementations without Linux or Node.js.

## Best Possible Solution

If maintainers sponsor this direction, define a small versioned protocol and conformance suite for agent events, tool calls, session state, model/auth inputs, and platform capabilities before attempting any full C, Rust, WASM, or embedded port.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw own a stable cross-language agent-runtime protocol for non-Node and embedded implementations, beyond its Node-hosted TypeScript runtime and plugin SDK?

Rationale: This choice creates a permanent product, compatibility, and security boundary; repository evidence can describe the gap but cannot determine whether OpenClaw should support and maintain that contract.

Likely owner: steipete

Owner reason: The runtime-internalization history and existing keep-open discussion make this the strongest available owner for the product boundary decision.

Owner confidence: high

Options:

- **Define Narrow Runtime Protocol (recommended):** Sponsor a versioned language-neutral agent-loop protocol and conformance suite without committing to porting the full Gateway or every tool.
- **Limit Cross-Language Work To Plugins:** Keep OpenClaw Node-hosted and use https://github.com/openclaw/openclaw/issues/98004 for non-TypeScript plugin implementations.
- **Keep Embedded Ports Independent:** Treat MimiClaw-style projects as external OpenClaw-inspired implementations without an official compatibility contract.
