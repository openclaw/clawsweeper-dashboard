## Summary

Keep open: current main and latest release still require a Node-hosted OpenClaw CLI/Gateway, while the existing agent-core and harness surfaces are TypeScript/OpenClaw-process seams rather than a runtime-neutral protocol for bare-metal, C/Rust/WASM, or ESP32-class ports. MimiClaw is useful external prior art, but it does not make the OpenClaw core request implemented or ClawHub-only.

## What This Changes

The issue requests runtime-agnostic/no-Node OpenClaw support for embedded and ultra-low-resource devices.

## Best Possible Solution

Keep this as the canonical maintainer design discussion for a runtime-neutral agent-core contract, conformance tests, platform-adapter boundaries, and a clear decision on what belongs in core versus external ports or plugin APIs, with MimiClaw retained as prior art.

## Reproduction Assessment

Not applicable. This is a feature and architecture request, and source/docs inspection confirms there is no supported no-Node runtime path to reproduce as broken current behavior.

## Solution Assessment

Unclear. Existing agent-core and harness work is useful groundwork, but the best permanent solution requires maintainer direction on whether OpenClaw should own a stable runtime-neutral protocol, extend plugin APIs, publish reference docs, or decline the core scope.
