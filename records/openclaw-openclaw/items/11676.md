## Summary

Keep open: current main and v2026.6.11 now include a reusable TypeScript agent-core extraction, but they still do not provide the requested versioned cross-language protocol or a bare-metal, C/Rust/WASM, or microcontroller-compatible runtime. No narrower related item owns that remaining product/API decision.

## What This Changes

Request a runtime-agnostic OpenClaw agent-core interface and reference path for bare-metal, C/C++/Rust/WASM, or microcontroller deployments without Node.js.

## Best Possible Solution

Build on `@openclaw/agent-core` by defining a small versioned language-neutral contract for turns, tool calls, streamed events, session state, model/auth inputs, and platform capabilities, then validate it with one maintained non-Node constrained-runtime implementation before promising broader portability.

Options:

- **Sponsor a minimal protocol (recommended):** Define a narrow versioned contract around the existing agent-core concepts and require one non-Node conformance implementation before expanding scope.
- **Keep TypeScript-only core:** Treat `@openclaw/agent-core` as the supported portability boundary and document embedded projects as independent implementations rather than compatible OpenClaw runtimes.
- **Defer protocol ownership:** Leave the discussion open without committing to an ABI until multiple external runtimes demonstrate concrete interoperability requirements.
