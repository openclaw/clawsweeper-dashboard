## Summary

Keep open: current main and the latest release still describe and enforce a Node-hosted OpenClaw CLI/Gateway, while MimiClaw remains useful prior art rather than an implementation of a runtime-neutral OpenClaw agent protocol. Existing Gateway, plugin, and agent-harness surfaces do not satisfy the bare-metal/no-Node request, and related browser/WASM work has already been consolidated into this issue.

## What This Changes

The issue requests support for running OpenClaw-style agent loops on devices without Linux or Node.js, including embedded or microcontroller-class runtimes, inspired by MimiClaw.

## Best Possible Solution

Keep this as the canonical maintainer design discussion for a runtime-neutral agent-core contract, conformance tests, platform-adapter boundaries, and the core-versus-external-port decision.

## Reproduction Assessment

Not applicable: this is a feature and architecture request rather than a bug report. Source and docs inspection confirm the missing behavior because current main and v2026.6.11 only support Node-hosted OpenClaw runtimes.

## Solution Assessment

Unclear: the requested direction is plausible, but the best first step is a maintainer-approved protocol/RFC and conformance boundary rather than a one-off embedded runtime patch. MimiClaw is useful prior art, not a drop-in implementation for OpenClaw core.
