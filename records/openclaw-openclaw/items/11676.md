## Summary

Keep open: current main and the latest release still require a Node-hosted OpenClaw runtime, and the current agent-core and harness surfaces are TypeScript/in-process contracts rather than a runtime-neutral protocol for bare-metal, C/Rust/WASM, or ESP32-class ports.

## What This Changes

Request to support no-Linux/no-Node OpenClaw ports through a runtime-neutral agent core or protocol for embedded, WASM, C/C++/Rust, and microcontroller environments.

## Best Possible Solution

Keep this as the canonical design/RFC issue for a runtime-neutral agent-core contract, using MimiClaw as prior art while defining schemas, platform adapters, security boundaries, and conformance proof before accepting embedded or WASM implementation work.

- **Close As Not Planned:** Decide that OpenClaw remains Node-hosted and external projects such as MimiClaw are independent ports without compatibility promises.
