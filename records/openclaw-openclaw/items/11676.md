## Summary

Current main has a reusable TypeScript agent-core extraction, but OpenClaw remains a Node-hosted orchestration system and does not define the requested cross-language contract for bare-metal or microcontroller runtimes; the explicit product/API decision remains unresolved.

## What This Changes

Define a runtime-agnostic OpenClaw agent-core protocol that supports bare-metal, C/C++, Rust, WASM, and other non-Node implementations.

## Best Possible Solution

Use a maintainer-sponsored RFC to define the smallest stable compatibility contract, capability negotiation, conformance tests, and a constrained reference port while keeping Node-specific host capabilities outside the portable core.

## Risks / Open Questions

- A portable specification could prematurely freeze unstable internal concepts such as session state, auth selection, streaming events, approvals, compaction, and tool lifecycle.
- A second protocol could overlap or drift from the Gateway, agent-harness, ACPX, MCP, and proposed JSON-RPC plugin boundaries unless ownership and conformance are explicit.
- ESP32-class targets cannot implement many host capabilities such as arbitrary filesystem, subprocess, browser, or shell tools, so the supported subset and security model require product judgment.
