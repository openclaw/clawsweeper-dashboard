## Summary

Keep open for an explicit maintainer product/API decision. Current main has an extracted OpenClaw agent core and Node-hosted runtime seams, but it does not establish the stable cross-language, bare-metal runtime contract requested here; the existing maintainer discussion likewise treats this as unresolved direction. citeturn3view0turn2view0

## What This Changes

The issue requests a runtime-agnostic OpenClaw agent contract that could support bare-metal, embedded, C/Rust, WASM, or other non-Node implementations.

## Best Possible Solution

Keep the current Node-hosted product boundary unless a maintainer sponsors a narrow RFC that defines the supported portable-runtime subset, capability/security model, versioning policy, and conformance proof before any cross-language implementation begins.

Options:

- **Defer a stable portable ABI (recommended):** Keep OpenClaw's supported runtime Node-hosted for now and allow independent ports to experiment without an OpenClaw compatibility promise.
- **Sponsor a scoped protocol RFC:** Define a deliberately small versioned agent-loop and capability protocol with conformance tests before accepting an embedded reference implementation.
- **Treat it as an external port:** Encourage MimiClaw-style projects to remain separate implementations rather than claiming OpenClaw runtime compatibility.
