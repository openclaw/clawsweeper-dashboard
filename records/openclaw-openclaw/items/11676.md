## Summary

Keep open: current main and the latest release still require an OS-hosted Node CLI/Gateway, while the newer agent-core and harness surfaces remain TypeScript/OpenClaw-process contracts rather than a runtime-neutral protocol for bare-metal, C/Rust/WASM, or ESP32-class ports. MimiClaw remains useful prior art, and the related closed WASM/browser and sandbox-backend issues do not supersede this broader embedded/no-Node product request.

## What This Changes

The issue requests runtime-agnostic OpenClaw support for devices without Linux or Node.js, using MimiClaw as prior art for embedded and microcontroller ports.

## Best Possible Solution

Keep this as the canonical maintainer design discussion for a runtime-neutral agent-core contract, conformance tests, platform-adapter boundaries, and a clear decision on what belongs in core versus external ports or plugin APIs, with MimiClaw retained as prior art.

## Reproduction Assessment

Not applicable: this is a feature and architecture request rather than a bug report. Source and docs inspection confirm the missing behavior because current main and v2026.6.11 only support Node-hosted OpenClaw runtimes.

## Solution Assessment

Unclear: the requested direction is plausible, but the best first step is a maintainer-approved protocol/RFC and conformance boundary rather than a one-off embedded runtime patch. MimiClaw is useful prior art, not a drop-in solution for OpenClaw core.
