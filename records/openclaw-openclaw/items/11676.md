## Summary

Keep open: current main still enforces and documents a Node-hosted OpenClaw CLI/Gateway, while the existing plugin and agent-harness seams are in-process TypeScript contracts rather than a runtime-neutral protocol for bare-metal, C/Rust/WASM, or ESP32-class ports. MimiClaw is useful prior art, and the related browser/WASM item was already closed into this issue rather than replacing it.

## What This Changes

The issue requests runtime-agnostic or no-Node support for OpenClaw on embedded, bare-metal, WASM, C/Rust, or ESP32-class environments, using MimiClaw as prior art.

## Best Possible Solution

Keep this as the canonical maintainer design discussion for a runtime-neutral agent-core contract, conformance tests, platform-adapter boundaries, and a decision on what belongs in core versus external ports or plugin APIs, with MimiClaw linked as prior art.

## Reproduction Assessment

Not applicable: this is a feature and architecture request rather than a bug report. Source and docs inspection confirm the missing behavior because current main only documents and enforces Node-hosted OpenClaw runtimes.

## Solution Assessment

Unclear: the requested direction is plausible, but the best first step is a maintainer-approved runtime/protocol design rather than a one-off embedded runtime patch. MimiClaw is useful prior art, not a drop-in OpenClaw core implementation.
