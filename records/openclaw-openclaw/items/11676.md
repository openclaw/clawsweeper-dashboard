## Summary

Keep open: current main and v2026.6.11 still require an OS-hosted Node runtime, and the existing agent-core/harness work is not a stable no-Node or bare-metal protocol; this remains a maintainer product/API decision rather than a cleanup close.

## What This Changes

The issue asks OpenClaw to support a runtime-agnostic, no-Node agent core for bare-metal, embedded, C/Rust/WASM, and ESP32-class ports, with MimiClaw as prior art.

## Best Possible Solution

Keep this as the canonical maintainer design discussion for a runtime-neutral agent-core contract, conformance tests, platform-adapter boundaries, and a clear decision on what belongs in core versus external ports or plugin APIs.
