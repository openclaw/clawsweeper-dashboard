## Summary

Keep open: the requested bare-metal/non-Node runtime is still necessary product-direction work. Current OpenClaw has an extracted agent-core package and Node-hosted runtime seams, but the reviewed current docs and existing maintainer discussion do not establish a versioned cross-language protocol or a supported ESP32/bare-metal execution contract. Likely related people: steipete is the strongest routing candidate from the agent-runtime refactor and the existing issue discussion (high confidence).

## What This Changes

Request a runtime-agnostic OpenClaw agent architecture and protocol so third-party ports can run an OpenClaw-style loop on bare-metal, embedded, WASM, or other non-Node platforms.

## System Context

OpenClaw's agent runtime receives sessions, model/provider configuration, tools, and channel events, then executes an agent loop through the Gateway and plugin ecosystem. The current product is hosted in a JavaScript runtime; a portable agent-core contract would need to define what external runtimes may exchange without importing the in-process Node-oriented implementation.

## Best Possible Solution

Make an explicit product decision on a supported external-runtime boundary; if accepted, design a versioned protocol with conformance tests and a minimal non-Node reference implementation before exposing it as a durable OpenClaw contract.
