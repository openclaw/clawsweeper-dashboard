## Summary

Keep open. Current main still contains the Telegram history gating, destructive pending-window clearing, room-event prompt posture, and overflow-summary behavior described in the report; the issue also has the protected maintainer label and three open implementation PRs, so conservative cleanup should leave it as the canonical tracker.

## What This Changes

The issue reports that Telegram ambient group room-event turns lack recent room context, are prompted too eagerly to reply, and can leak notices despite the room-event silence contract.

## Best Possible Solution

Keep this issue as the canonical tracker while maintainers review the three linked PRs together, then land a coordinated fix that restores ambient room context, defaults room events to silence, suppresses notice leaks, and includes the required migration and regression tests.

## Reproduction Assessment

Yes at source level: default Telegram config resolves to `mention-only`, both pending-history delivery paths require `recent`, only room events are recorded, and the dispatch path can clear the window. I did not run a live Telegram deployment repro in this read-only review.

## Solution Assessment

Unclear until the linked PRs receive maintainer review: their split matches the observed root causes, but the history PR removes a shipped config surface and needs coordinated upgrade proof. The safest path is to review the three PRs as one bug-fix set rather than opening a fourth repair PR.
