## What This Changes

The PR changes `src/gateway/server-channels.ts` so stopAccount receives `AbortSignal.abort()` when no stored account AbortController exists.

## Best Possible Solution

Land the semantic fix only after the branch is rebased, a focused idle stopAccount regression or equivalent proof is added, and maintainers accept the plugin API behavior.

## Reproduction Assessment

Yes at source level: current main reaches `abort?.signal ?? new AbortController().signal` when `stopChannel(channel, accountId)` calls a stopAccount hook without a stored controller. I did not run a live gateway shutdown in this read-only review.

## Solution Assessment

Yes, if maintainers want stopAccount to always receive a stop-requested signal; `AbortSignal.abort()` is the narrowest code shape and matches the active-controller path after `abort?.abort()`. The PR still needs rebase, proof, and compatibility acceptance.
