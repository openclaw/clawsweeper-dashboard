## Summary

## What This Changes

The PR changes `stopChannel` so the fallback `stopAccount` context receives `AbortSignal.abort()` instead of a fresh never-aborted signal when no controller exists.

## Best Possible Solution

Refresh the branch onto current main, add focused regression coverage for explicit-account `stopAccount` without a stored controller, and provide redacted real gateway/plugin lifecycle proof before merge.

## Reproduction Assessment

Yes at source level: current main reaches `abort?.signal ?? new AbortController().signal` when explicit `stopChannel(channel, accountId)` calls a `stopAccount` hook without a stored controller. I did not run a live gateway shutdown in this read-only review.

## Solution Assessment

Yes, the one-line code shape is likely the narrowest fix because `AbortSignal.abort()` matches the already-aborted primary path after `abort?.abort()`. It is not merge-ready until the branch is refreshed and the plugin lifecycle behavior is proven.
