## What This Changes

The PR changes `src/gateway/server-channels.ts` so the `stopChannel` fallback passes an already-aborted signal to channel `stopAccount`.

## Best Possible Solution

Rebase the PR, add focused coverage for explicit-account stop hooks with no active controller, and provide redacted real gateway stop proof before maintainers decide whether the aborted fallback is the intended plugin lifecycle contract.

## Reproduction Assessment

Yes at source level: explicit-account `stopChannel` with a `stopAccount` hook and no stored controller reaches the fallback signal path on current main. I did not run a live gateway stop in this read-only review.

## Solution Assessment

Yes, if maintainers want `stopAccount` to always see a stop-requested signal; `AbortSignal.abort()` is the narrowest code shape and matches the active-controller path after `abort?.abort()`. It still needs rebase, proof, and compatibility acceptance before merge.
