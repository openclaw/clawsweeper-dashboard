## What This Changes

The PR changes the gateway channel manager so `stopAccount` receives an already-aborted signal when an explicit stop has no stored account abort controller.

## Best Possible Solution

Refresh this branch or replace it with the same narrow signal fallback plus focused regression coverage and redacted real gateway/plugin shutdown proof.

## Reproduction Assessment

Yes at source level: current main reaches the `abort?.signal ?? new AbortController().signal` fallback when `stopChannel` is called for an explicit account with a stop hook but no stored controller. I did not run a live gateway shutdown in this read-only review.

## Solution Assessment

Yes as the code shape: using `AbortSignal.abort()` is the narrowest fix for matching the primary path where an existing controller is aborted before `stopAccount`. It is not merge-ready until the branch is refreshed, a regression test covers the no-controller fallback, and real behavior proof is added.
