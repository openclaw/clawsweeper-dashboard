## Summary

Keep this PR open: it addresses a real missing plugin seam, but its new enforcement hook currently inherits fail-open timeout/error behavior, so it cannot safely serve the strict outbound-policy boundary described by the PR and related reports. The public plugin API and failure semantics need maintainer confirmation before merge.

## What This Changes

The branch adds `source_policy` and `outbound_delivery_policy` plugin hooks, wiring them into inbound reply preparation, durable outbound delivery, and message-tool sends with SDK exports, audit reasons, docs, and tests.

## Best Possible Solution

Define `outbound_delivery_policy` as a narrow, documented fail-safe policy boundary before publishing it: a registered policy handler must suppress delivery on timeout/error unless maintainers deliberately choose and document best-effort semantics, then prove automatic replies and message-tool sends on both allow and denial paths.
