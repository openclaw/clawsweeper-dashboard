## Summary

Keep this PR open: it addresses a valid released Control UI regression, but the previously reported storage-failure bug remains because the callback discards the helper’s in-memory result and immediately re-renders from unchanged storage; the submitted behavior proof is still mock-only.

## What This Changes

Adds a browser-local user-identity save helper, reconnects Quick Settings avatar changes to that persistence path, and adds focused persistence and merge tests.

## Best Possible Solution

Let ConfigPage own the current local identity in reactive memory, update that state before best-effort persistence, and cover both storage-failure behavior and the complete browser select/clear/reload flow.

## Solution Assessment

No. Restoring the callback is directionally correct, but storage must not become the immediate UI source of truth after a best-effort write; component-owned identity state is the narrower robust design.
