## Summary

Keep this PR open: it restores the missing avatar callback, but the callback still loses the visible selection when browser storage rejects the write, and the supplied validation does not exercise the real browser flow.

## What This Changes

Restores Quick Settings user-avatar persistence through browser-local storage and adds focused storage-helper tests.

## Best Possible Solution

Route avatar changes through the UI's in-memory user-identity owner before best-effort persistence, pass that state into Quick Settings, and cover both storage-failure behavior and the complete browser selection/clear/reload flow.

## Solution Assessment
