## Summary

The reported slow-network race does not match current or shipped behavior: the pinned lock library heartbeats the lock while the asynchronous OAuth request is pending, so crossing 30 seconds alone does not compromise or steal it.

## What This Changes

Prevent a slow OAuth refresh from losing rotated credentials when the auth-file lock becomes compromised and another process acquires it.

## Best Possible Solution

Keep the current heartbeat-backed lock behavior; if an actual `ECOMPROMISED` event causes token loss, file a new focused report with the compromise error, environment, timestamps, and deterministic fault-injection steps so recovery can revalidate canonical state under a fresh lock without sidecars or dual writes.
