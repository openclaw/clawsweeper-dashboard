## Summary

Keep open for maintainer product/security review: current main and v2026.6.11 intentionally force tool payload redaction with no config key, and related PRs show raw tool-payload debugging is a safety-boundary decision rather than a strict bug.

## What This Changes

The issue requests a persistent `logging.redactToolSensitive` config option for tool payload redaction, with an opt-out value while preserving the current redacted default.

## Best Possible Solution

Keep secure tool payload redaction as the default and let maintainers decide whether a narrower raw-payload/debug control should exist, with schema, docs, security review, and regression coverage if accepted.

## Reproduction Assessment

Yes, at source level: current main hardcodes tool payload redaction to tools mode, has no `logging.redactToolSensitive` schema key, and documents that safety-boundary payloads still redact when general log redaction is off.

## Solution Assessment

Unclear. A separate config key is more explicit than reusing `logging.redactSensitive`, but maintainers may prefer a narrower privileged, local-only, ephemeral debug surface that preserves the documented safety boundary.
