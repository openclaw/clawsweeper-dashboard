## Summary

Keep open for maintainer product/security review: current main intentionally keeps tool/UI/diagnostic payload redaction separate from general log redaction, and adding a config-file opt-out would expand a security-sensitive config surface.

## What This Changes

The issue requests a `logging.redactToolSensitive` config-file toggle for tool payload redaction, with any environment override retaining precedence.

## Best Possible Solution

Keep tool payload redaction on by default and only add an explicit raw-payload/debug control if maintainers approve the security model and config contract.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes for the source-level claim: current main lacks `logging.redactToolSensitive`, and the tool payload helper forces tools-mode redaction.

## Solution Assessment

Is this the best way to solve the issue? Unclear. A separate config key is more explicit than reusing `redactSensitive`, but the approved shape should come from maintainers because this weakens a documented security boundary.
