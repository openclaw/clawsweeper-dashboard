## Label Justifications

- `P1`: Guarded model-provider requests can fail entirely on affected dual-stack networks, leaving gateway message handling unable to obtain a model response.
- `impact:security`: The affected mechanism is the SSRF guard’s validated and pinned outbound DNS-dispatch boundary.
- `impact:auth-provider`: The failure prevents configured OpenAI-compatible and OpenRouter provider requests from reaching the provider.

## Summary

Keep open: two independent dual-stack reproductions and the current guarded-fetch design establish a real provider-availability bug, while the open candidate fix in https://github.com/openclaw/openclaw/pull/110124 explicitly closes this issue and needs security-boundary review before merge. The existing IPv4-first behavior was deliberately added to protect IPv4-working and IPv6-unreachable hosts, so the remaining decision is how to preserve that protection while allowing Node/Undici automatic family fallback.

## What This Changes

Fix SSRF-pinned DNS lookup behavior so guarded model-provider fetches can use already validated IPv6 records when IPv4 is unreachable under automatic family selection.

## Best Possible Solution

Land a narrowly tested guarded-lookup change that keeps ordinary automatic single-address selection IPv4-first while returning the complete SSRF-validated IPv4-first record set for Node/Undici `{ all: true }` lookups, with real dual-stack proof for both IPv4-only and IPv6-only reachability cases.
