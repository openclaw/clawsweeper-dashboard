## Summary

Keep open: current main has already moved the shared JSON, exec-approval, and restart-sentinel paths away from the originally reported direct target writes, but shell completion installation still creates and rewrites user profile files with direct `fs.writeFile`; the same remaining gap is present in the latest release tag.

## What This Changes

The issue requests atomic file writes for crash safety across restart sentinel, shell completion profile updates, shared JSON saves, and exec approval persistence.

## Best Possible Solution

Keep the already-fixed persistence paths unchanged and land a narrow shell-completion profile write patch using the existing atomic text replacement helper without changing profile path resolution in the same work.

## Reproduction Assessment

Yes. Source inspection on current main shows `installCompletion` rewrites the selected shell profile with direct `fs.writeFile`, which is the reported crash-window behavior; I did not run crash injection because this review is read-only.

## Solution Assessment

Yes for the remaining gap. The narrow maintainable fix is to route shell profile creation and update through the existing atomic text writer while leaving the already-fixed JSON, exec-approval, and restart-sentinel paths alone.
