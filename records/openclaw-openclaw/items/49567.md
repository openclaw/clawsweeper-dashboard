Keep open. Current main and v2026.6.11 still reject `bindings[].tools`, and the remaining work is a security-sensitive public config/enforcement decision rather than a stale cleanup target.

## What This Changes

The issue requests optional per-binding `tools.allow`/`tools.deny` policy on route and ACP bindings so channel/group bindings can restrict specific tools.

## Best Possible Solution

Define one maintainer-approved binding policy contract and implement schema, types, matched-binding propagation, runtime enforcement, docs, and regression proof together, or document existing group/sender/session policy as the supported boundary.
