## Summary

Keep open. Current `origin/main` and latest release still reject binding-scoped `tools` config, and the current route/ACP binding and tool-policy paths do not carry or enforce a matched binding policy; this remains a product/security-boundary decision.

## What This Changes

The issue requests binding-scoped `tools.allow`/`tools.deny` policy for route/ACP bindings so operators can restrict tools per channel or group.

## Best Possible Solution

Define one maintainer-approved, enforced binding policy contract with schema/types, matched-binding propagation, route and ACP enforcement, docs, and regression proof; otherwise document existing group/sender/session policy as the supported boundary.
