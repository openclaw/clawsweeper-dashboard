## Summary

Keep open. Current main and the latest release still reject binding-scoped tool policy, while related items cover adjacent session, sender, and identity work rather than a merged replacement for route/ACP binding `tools.allow` or `tools.deny`.

## What This Changes

Request adding optional per-binding `tools.allow`/`tools.deny` policy to route and ACP bindings so channel or group routes can restrict tools without an MCP/proxy workaround.

## Best Possible Solution

Define one maintainer-approved contract: either implement binding-scoped policy end to end across schema, types, route/ACP propagation, enforcement, docs, and tests, or document existing group/sender/session policy as the supported boundary.

- **Defer to broader identity work:** Block this on scoped session or conversation identity design if maintainers want one authorization model instead of a binding-specific slice.

Unclear for the proposed shape. A schema-only change is not the best fix; the maintainable solution needs either complete enforcement with precedence rules or clear documentation that existing group/sender/session policy is the supported boundary.
