## Summary

Keep open: current main still has route/ACP binding schemas and routing/tool-resolution paths with no binding-scoped tool policy carrier or enforcement, while adjacent work only covers group/sender/session/per-request surfaces. ## What This Changes

Request support for optional `tools.allow`/`tools.deny` restrictions on route or ACP bindings so matched conversations can receive a narrower tool set.

## Best Possible Solution

Define a maintainer-approved binding-policy contract first, then implement one enforced route/ACP binding layer with documented precedence and tests against existing group/sender/session policy.
