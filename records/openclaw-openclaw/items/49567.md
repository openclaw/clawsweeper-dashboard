## Summary

Keep open. Current main and v2026.6.11 still have strict route/ACP binding schemas with no `tools` payload and the runtime tool-policy pipeline has no matched-binding layer, so this remains a real product/security decision rather than cleanup.

## What This Changes

The issue requests `tools.allow`/`tools.deny` policy on route and ACP bindings so particular tools can be disabled for selected channels, groups, or conversations.

## Best Possible Solution

Define a maintainer-approved route/ACP binding tool-policy contract before implementation, then wire it through schema, route resolution, ACP/runtime tool preparation, documentation, and regression proof.
