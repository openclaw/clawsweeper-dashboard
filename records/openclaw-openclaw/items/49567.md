Keep open: current main and v2026.6.11 still do not support `tools.allow` or `tools.deny` on route or ACP bindings, and the remaining work is a security-sensitive product/config contract rather than cleanup closure.

## What This Changes

## Best Possible Solution

Define the binding-level tool-policy contract first, then implement it end to end through schema/types, matched route or ACP binding propagation, scoped capability profile or equivalent policy context, embedded and Gateway tool filtering, docs, and focused regression proof.
