## Summary

Keep open. Current main and v2026.6.11 still reject `bindings[].tools`, and the remaining work is an end-to-end security/config contract rather than a cleanup close candidate.

## What This Changes

The issue requests binding-scoped `tools.allow`/`tools.deny` policy for route and ACP bindings so operators can restrict tools per channel or group without external MCP filtering.

## Best Possible Solution

Define one maintainer-approved binding policy contract and implement schema, types, matched-binding propagation, runtime enforcement, docs, and regression proof together, or explicitly document existing group/sender/session policy as the supported boundary.
