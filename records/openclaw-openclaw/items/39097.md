## Summary

Keep open. Current main and v2026.6.11 still have browser SSRF hostname exception support but no browser URL/path/domain denylist or warnlist; related open issues overlap on broader egress and private-network SSRF policy but do not replace this browser-specific product/security decision.

## Best Possible Solution

Define a browser navigation policy contract that separates hard deny rules from advisory bot-block warnings, then implement schema, guard integration, docs, and tests across the approved traffic classes.
