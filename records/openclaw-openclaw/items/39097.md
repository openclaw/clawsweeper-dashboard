## Summary

Keep open. Current main and v2026.6.11 still provide browser SSRF/private-network controls and hostname allow exceptions, but not the requested browser URL/path/domain denylist or warnlist; the overlapping egress-firewall and SSRF-confirmation issues do not replace this browser-navigation policy request.

## What This Changes

Request to add browser-level blocked URL/path/domain denylist config and optional warnlist behavior with clearer navigation errors for known-blocked sites.

## Best Possible Solution

Define one maintainer-approved browser navigation policy contract, then implement schema, guard integration, docs, and regression tests for host/path matching, redirects, subframes or subresources, proxy behavior, and warn-versus-block semantics.
