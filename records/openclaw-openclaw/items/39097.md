## Summary

Keep open. Current main and v2026.6.11 have browser SSRF private-network controls and hostname allow exceptions, but not a browser blocked-URL/path denylist or warnlist; this remains a security-sensitive product/config decision.

## What This Changes

The issue requests browser configuration for blocked URL/domain patterns, plus optional warning behavior, so navigation can fail early with a clear message for known bot-blocking sites.

## Best Possible Solution

Define a maintainer-approved browser navigation policy contract first, then implement schema, guard integration, docs, and regression coverage for hard block versus advisory warn semantics.
