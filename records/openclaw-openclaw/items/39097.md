## Summary

Keep open: current main and v2026.6.11 still have browser SSRF hostname exceptions, but no browser URL/path denylist or warnlist; the related egress and SSRF-confirmation issues only partially overlap and do not replace this browser-specific product/security decision.

## What This Changes

The issue requests a browser navigation denylist or warnlist for blocked URL/domain patterns so agents fail fast with clearer guidance on known bot-blocked sites.

## Best Possible Solution

Define a browser navigation policy contract that separates hard deny rules from advisory bot-block warnings, then implement schema, guard integration, docs, and tests across the approved traffic classes.
