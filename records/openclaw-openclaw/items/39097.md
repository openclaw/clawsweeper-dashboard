## Summary

Keep open. Current main and v2026.6.11 still provide browser SSRF/private-network blocking and hostname allow exceptions, but not the requested browser URL/path/domain denylist or warnlist; related egress work overlaps without replacing the browser-navigation policy decision.

## What This Changes

The issue requests a browser navigation URL/path/domain denylist or warnlist so known bot-blocked sites fail fast with a clear message.

## Best Possible Solution

Define a browser-scoped navigation policy contract first, then implement schema, guard integration, docs, and tests for block and warn semantics across redirects, subframes or subresources, downloads, and proxy-routed profiles.
