## Summary

Keep open. Current main and v2026.6.11 still have browser SSRF private-network blocking plus hostname allow exceptions, but no browser URL/path/domain denylist or warnlist; the related egress-firewall issue and web_fetch allowlist PR overlap without replacing the browser-navigation policy decision.

## What This Changes

Request to add a browser URL/path/domain denylist, plus optional warnlist behavior, so blocked or bot-protected destinations fail fast with clear agent-facing feedback.

## Best Possible Solution

Define a browser-scoped navigation policy contract first, then implement schema, guard integration, docs, and tests for block and warn semantics across redirects, page transitions, downloads, and proxy-routed profiles.
