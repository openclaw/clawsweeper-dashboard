## Summary

Keep open: current main and v2026.6.11 still do not provide the requested browser URL/path/domain denylist or warnlist. The existing browser SSRF hostname allowlist is a private-network navigation control, not a public-domain bot-block deny/warn policy, and related issues cover broader egress or private-network confirmation rather than replacing this browser-specific request.

## What This Changes

The issue requests a browser URL/path/domain denylist or warnlist that fails fast with a clear message when browser navigation targets known-blocked sites.

## Best Possible Solution

Define one maintainer-approved browser navigation policy contract, then implement schema, guard integration, docs, and regression tests for host/path matching, redirects, subframes or subresources, proxy behavior, bundled defaults, and warn-versus-block semantics.
