## Summary

Keep open. Current main and the latest release still have browser SSRF/private-network controls and hostname allow exceptions, but not the requested browser URL/path/domain denylist or warnlist; related egress-firewall work overlaps without replacing the browser-navigation policy decision.

## What This Changes

Request a browser navigation blocked-URL/domain/path denylist and optional warnlist so known bot-protected sites fail fast with a clear agent-facing message.

## Best Possible Solution

Define a browser-scoped navigation policy contract first, then implement schema, guard integration, docs, and tests for block and warn semantics across redirects, subframes or subresources, downloads, and proxy-routed profiles.
