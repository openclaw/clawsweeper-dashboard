## Summary

Keep open: current main and v2026.6.11 still only provide browser SSRF/private-network controls plus hostname allow exceptions, not the requested browser URL/path/domain denylist or warnlist.

## What This Changes

Add browser-level URL/path/domain denylist and optional warnlist config so blocked navigations return a clear browser-tool error before wasting agent turns.

## Best Possible Solution

Define one maintainer-approved browser navigation policy contract in the browser plugin, with schema, docs, and tests for host/path matching, redirects, warning versus hard-block behavior, and the boundary between advisory bot-block hints and enforceable egress policy.

Not applicable as a bug reproduction; this asks for a new browser policy/config capability. Source, docs, and the latest release show the requested denylist/warnlist surface is absent rather than broken.

## Solution Assessment

Unclear as proposed. The browser navigation guard is the likely enforcement boundary, but maintainers still need to choose advisory hints versus hard blocking and the exact request classes covered.
