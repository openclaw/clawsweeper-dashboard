## Summary

Keep open. Current main and v2026.6.11 still only expose browser SSRF private-network controls and hostname allow exceptions; no browser URL/path/domain denylist or warnlist exists, and related web-fetch egress work does not replace the browser-navigation policy decision.

## What This Changes

Request browser configuration for URL/path/domain deny or warning lists so browser navigation can fail fast on known bot-blocked or disallowed sites.

## Best Possible Solution

Define a browser-scoped navigation policy contract first, then implement strict schema, guard integration, docs, and tests for block and warn behavior across redirects, proxy-routed profiles, subresources/downloads, and user-facing error text.
