## Summary

Keep this open: current main fixed the adjacent live tool-card ordering race, but the reported merged-session WebChat ordering gap remains source-backed because hydrated history still carries canonical transcript time in `__openclaw.recordTimestampMs` while the Control UI visible sorter only reads top-level numeric `timestamp`.

## What This Changes

The issue requests that WebChat render merged WebChat and WeChat session messages in canonical chronological order instead of occasionally showing an assistant reply before its user message.

## Best Possible Solution

Teach the Control UI chat timestamp normalization path to use canonical transcript metadata such as `__openclaw.recordTimestampMs` and, if needed, `seq` for hydrated history ordering, with focused regression coverage for merged WebChat/WeChat session messages while preserving the merged live tool ordering fix.
