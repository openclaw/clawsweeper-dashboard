## Summary

Keep open: current main still has a source-backed WebChat render-order gap because ordinary message items sort only by top-level numeric `timestamp`, while Gateway history can carry canonical transcript order/time in `__openclaw` metadata. The merged WebChat ordering work at https://github.com/openclaw/openclaw/pull/93184 overlaps but fixes a narrower live tool-stream causal race, and the closed LAN report points back to this issue as the canonical remaining tracker.

## What This Changes

The issue reports WebChat rendering messages out of chronological order after WebChat and openclaw-weixin traffic are merged into the same agent main session.

## Best Possible Solution

Make WebChat visible ordering consume canonical transcript metadata such as `__openclaw.recordTimestampMs` or `__openclaw.seq` for history-backed messages, then add a focused regression covering merged-channel or stale-history user-before-assistant order.
