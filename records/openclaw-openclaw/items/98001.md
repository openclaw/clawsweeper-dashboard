## Summary

Keep this open: current main still has a source-backed WebChat ordering gap because message rows sort by top-level numeric `timestamp`, while Gateway history can carry canonical transcript time only in `__openclaw.recordTimestampMs`. The merged adjacent WebChat tool-stream PR fixes a narrower live assistant/tool-card race, not this cross-channel merged-session history metadata case.

## What This Changes

The issue reports WebChat message order inversion after WebChat and WeChat sessions merge into one agent main session.

## Best Possible Solution

Make WebChat message ordering consume canonical transcript metadata such as `__openclaw.recordTimestampMs` or sequence when top-level timestamps are absent, with regression coverage for merged-channel history.
