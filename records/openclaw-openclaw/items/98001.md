- `impact:session-state`: The report is about visible session transcript ordering drifting from the canonical history order.

## Summary

Keep this open: current main still has a source-backed WebChat ordering gap because visible message ordering uses top-level numeric timestamps, while Gateway history preserves the canonical transcript record time in `__openclaw.recordTimestampMs`; the merged adjacent WebChat fix covers live tool-card ordering, not this merged-session user/assistant ordering case.

## What This Changes

The issue reports WebChat rendering messages out of chronological order after WebChat and openclaw-weixin traffic are merged into the same agent main session.

## Best Possible Solution

Make WebChat render ordering consume canonical transcript time or sequence, especially `__openclaw.recordTimestampMs`, while preserving the live tool causal ordering from https://github.com/openclaw/openclaw/pull/93184 and covering merged-session history with regression tests.
