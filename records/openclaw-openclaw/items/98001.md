## Summary

Keep this open: current main still has the WebChat merged-session ordering gap because the render sorter uses only top-level numeric message timestamps, while Gateway history can carry canonical transcript time and sequence in `__openclaw` metadata. The merged live-tool ordering fix overlaps the same renderer but does not solve this cross-channel history metadata case.

## What This Changes

The issue reports WebChat rendering merged WebChat and WeChat messages out of chronological order in a shared agent main session while `sessions_history` returns the correct order.

## Best Possible Solution

Normalize WebChat render ordering around canonical transcript metadata or sequence for history messages, preserve the existing live tool causal tie-break, and add a merged-channel regression test that keeps each user turn before its assistant reply.
