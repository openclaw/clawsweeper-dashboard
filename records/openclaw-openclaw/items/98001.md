## Summary

Keep open: current main still has a source-backed WebChat ordering gap because visible item sorting only uses top-level numeric timestamps, while Gateway transcript history can expose canonical record time in `__openclaw.recordTimestampMs`. The merged live-tool ordering PR fixed an adjacent causal tool-card race, but it does not cover this merged-session history metadata case.

## What This Changes

The issue reports that WebChat renders merged WebChat and WeChat messages out of order when both channels write into the same agent main session.

## Best Possible Solution

Normalize WebChat visible ordering around canonical transcript time, especially `__openclaw.recordTimestampMs`, while preserving the live tool causal tie-break and adding a merged-channel history regression test.
