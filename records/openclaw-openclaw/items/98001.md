## Summary

Keep this open: the merged live tool-ordering fix covers an adjacent WebChat race, but current main still sorts persisted WebChat history by top-level numeric `timestamp` and does not consume Gateway transcript metadata for the merged-session case.

## What This Changes

The issue asks WebChat to render merged WebChat and openclaw-weixin messages in canonical chronological order when both channels share the same agent main session.

## Best Possible Solution

Normalize WebChat visible ordering around canonical transcript metadata or sequence for persisted history while preserving the existing live stream/tool causal tie-break, then cover the merged-channel history/live interleave with regression tests.
