## Summary

Keep this open: current main still has a source-backed WebChat ordering gap for merged-channel history because chat-thread sorting reads only the top-level numeric message timestamp, while Gateway transcript hydration preserves the canonical record time in __openclaw.recordTimestampMs. The linked merged WebChat ordering PR fixes live tool-stream causality, not this persisted merged-session metadata case.

## What This Changes

The issue asks WebChat to render merged WebChat and openclaw-weixin messages in chronological order so each assistant reply follows the user message it answers.

## Best Possible Solution

Use Gateway's canonical transcript record timestamp for persisted WebChat history ordering when present, preserve the existing live stream/tool causal tie-breaks, and add regression coverage for merged-channel history rows.
