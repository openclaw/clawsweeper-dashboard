## Label Justifications

- `P1`: A shipped least-privilege node execution workflow breaks when operators strengthen gateway security, affecting real node-host command use now.
- `impact:security`: The false approval loop incentivizes operators to revert the gateway from allowlist/on-miss to permissive full/off execution.
- `impact:ux-friction`: Commands already scoped by the node allowlist require repeated manual approvals as their arguments vary.
- `maturity:stable`: The affected gateway-runtime feature is M4 Stable and explicitly includes approvals, remote execution, nodes, and security controls.

## Summary

This is a valid shipped bug: gateway allowlist mode re-evaluates node commands without the node PATH, so valid node-local executable entries cannot suppress approvals. No related issue or pull request currently owns this specific defect.

## What This Changes

Fix node-host exec approval analysis so node-side path, basename, and argument allowlists remain matchable when gateway exec security is also allowlist/on-miss.

## Best Possible Solution

Extend system.run.prepare additively with node-authoritative executable identity, use that identity for gateway allowlist matching, and retain node-side identity and mutable-operand revalidation before execution.
