## Summary

Keep this PR open for contributor follow-up rather than merge it: on Windows, Node forcefully terminates child processes for both the default `SIGTERM` and `SIGKILL`, so the proposed option change does not address the claimed timeout failure.

## Best Possible Solution

Remove this no-op signal change unless a real Windows reproduction demonstrates a timeout failure that Node’s documented forced-termination behavior does not cover; then fix the demonstrated process or descendant-process boundary and add platform-real proof.
