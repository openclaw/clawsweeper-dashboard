## Summary

Keep open. Current main still has the reported source-level gap: plugin-owned context engines may compact proactively in `afterTurn`, but that hook has no compaction-reporting channel and `/status` still renders only the persisted session counter.

## What This Changes

The issue asks for plugin-owned context-engine compactions performed after a turn to increment the `/status` and `session_status` compaction counter.

## Best Possible Solution

Define one additive context-engine compaction reporting contract, persist confirmed plugin-owned deltas into `SessionEntry.compactionCount`, and cover after-turn, manual compact, overflow, and built-in runtime paths with double-counting safeguards.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: an `ownsCompaction` engine can compact in `afterTurn`, but that hook returns `Promise<void>` and status reads only `SessionEntry.compactionCount`.

## Solution Assessment

Unclear as an implementation choice. The gap is valid, but maintainers still need to choose the stable plugin API shape before a code fix should proceed; the open status-outcome PR is adjacent and explicitly out of scope for this count bug.
