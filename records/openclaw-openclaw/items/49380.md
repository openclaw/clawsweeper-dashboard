## Summary

Keep open: current main and the latest release still lack a plugin-facing way for context engines that own compaction to report successful after-turn or maintenance compactions into the session counter rendered by `/status`. The remaining work is real, but the permanent plugin lifecycle contract is a maintainer API decision.

## What This Changes

The issue asks for plugin-owned context-engine compactions to be reflected in `/status` and `session_status` compaction counts.

## Best Possible Solution

Add one narrow plugin lifecycle reporting contract that lets context engines report successful owned compactions to the canonical session store, then keep `/status` and `session_status` rendering from that counter.

Question: Which plugin-facing compaction reporting contract should OpenClaw support for context engines that own compaction: an `afterTurn` notification callback, an `afterTurn` result shape, or a status/stats query surface?

Rationale: The bug is source-reproducible, but the fix changes the public context-engine/plugin lifecycle contract and needs maintainer intent before implementation.

Likely owner: jalehman

Owner reason: jalehman introduced the context-engine plugin API and is the strongest history-backed owner for the lifecycle contract choice.

Owner confidence: high

Options:

- **Add an afterTurn callback (recommended):** Pass a narrow callback in lifecycle params so engines can report successful owned compactions into the canonical session counter without making status query plugin-private stores.
- **Return compaction metadata:** Allow `afterTurn` or maintenance to return a small result object, but this broadens existing lifecycle signatures for plugin implementations.
- **Query engine stats:** Let status query optional engine stats, but reconcile carefully so it does not create a second source of truth beside session state.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: `afterTurn` and maintenance can run plugin-owned work but expose no count delta, while `/status` renders only `SessionEntry.compactionCount`.

## Solution Assessment

Unclear until maintainers choose the plugin API shape. A callback is the narrowest likely repair because it keeps the session store canonical and lets plugins report only successful owned compactions.
