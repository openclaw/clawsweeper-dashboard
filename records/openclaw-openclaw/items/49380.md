- `impact:session-state`: The displayed session compaction state can drift from actual context-engine compaction activity.

## Summary

Keep open: current main and v2026.6.11 still lack a way for plugin-owned `afterTurn` or maintenance compactions to update the session compaction counter rendered by `/status`, and the related status-outcome work was closed as adjacent rather than a fix for count accuracy.

## What This Changes

The issue asks OpenClaw to let plugin-owned context engines report successful background compactions so `/status` and session status counts stay accurate.

## Best Possible Solution

Add one narrow plugin lifecycle reporting contract that lets context engines report successful owned compactions to the canonical session store, then keep `/status` and `session_status` rendering from that counter.

Rationale: The source-level bug is clear, but the fix changes the public context-engine/plugin lifecycle contract and needs maintainer intent before implementation.

Likely owner: jalehman

Owner reason: The decision is on the context-engine plugin API contract that `jalehman` introduced and later extended.

Owner confidence: high

Options:

- **Add an afterTurn callback (recommended):** Pass a narrow callback in `afterTurn` and maintenance params so engines can increment the canonical session counter only after successful owned compactions.
- **Return compaction metadata:** Allow `afterTurn` or maintenance to return a small result object, but this broadens existing lifecycle signatures for plugin implementations.
- **Query engine stats:** Let status query an optional engine stats method, but reconcile carefully so it does not create a second source of truth beside session state.

## Reproduction Assessment

Yes, source-level. `afterTurn` and maintenance can run plugin-owned background compactions but currently have no compaction notification path, while `/status` renders only `SessionEntry.compactionCount`.

## Solution Assessment

Unclear until maintainers choose the plugin API shape. A callback is the narrowest likely repair because it keeps the session store canonical and lets plugins report only successful owned compactions.
