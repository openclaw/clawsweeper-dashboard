## Label Justifications

- `impact:session-state`: The displayed session compaction state can drift from actual plugin context-engine compaction activity.

## Summary

Keep open: current main and the latest release still have no plugin-facing way for context engines that own compaction to report after-turn or background compactions into the canonical session counter, so /status can still show zero while plugin compaction happened.

## What This Changes

Requests a plugin context-engine reporting path so /status reflects compactions performed by engines that own compaction.

## Best Possible Solution

Add one narrow plugin lifecycle reporting contract that lets owning context engines persist successful compaction deltas into SessionEntry.compactionCount, keeping /status and session_status on the canonical session store.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which plugin-facing compaction reporting contract should OpenClaw support for context engines that own compaction: an afterTurn notification callback, an afterTurn result shape, or a status/stats query surface?

Rationale: The bug is source-reproducible, but fixing it changes the public context-engine/plugin lifecycle contract and should not be chosen by automation without owner intent.

Likely owner: jalehman

Owner reason: They introduced the context-engine plugin API and later maintenance lifecycle where this contract would be added.

Owner confidence: high

Options:

- **Add a notification callback (recommended):** Pass a narrow notifyCompaction(count?) callback in post-turn and maintenance params so engines can increment the canonical session counter only after successful owned compactions.
- **Return compaction metadata:** Allow afterTurn or maintenance to return a small result object, accepting a broader signature change for direct host reconciliation.
- **Query engine stats:** Add an optional stats surface for status rendering, but avoid creating a second source of truth beside session state.

## Reproduction Assessment

Yes. Source-level reproduction is high-confidence: ownsCompaction engines can compact in afterTurn or background maintenance, but those paths have no channel to update SessionEntry.compactionCount while /status renders only that field.

## Solution Assessment

Unclear until maintainers choose the plugin API shape. A notification callback looks like the narrowest repair because it preserves the session store as the canonical counter while letting plugins report only successful owned compactions.
