## Label Justifications

- `P2`: This is a normal-priority status accuracy bug for plugin context engines; sessions continue, but the operator-visible compaction counter can be wrong.
- `impact:session-state`: The displayed session compaction state can drift from actual plugin context-engine compaction activity.

## Summary

Keep open: current main and v2026.6.11 still lack a plugin-facing way for owning context engines to report after-turn/background compaction deltas into the session counter, so `/status` can still show zero after plugin compactions succeeded.

## What This Changes

Request that plugin context engines with `ownsCompaction` can report successful after-turn or background compactions so `/status` and session counters reflect them.

## Best Possible Solution

Add one narrow plugin lifecycle reporting contract that lets owning context engines persist successful compaction deltas into `SessionEntry.compactionCount`, keeping `/status` and session status on the canonical session store.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which plugin-facing compaction reporting contract should OpenClaw support for context engines that own compaction: an after-turn notification callback, an after-turn result shape, or a status/stats query surface?

Rationale: The bug is source-reproducible, but fixing it changes the public context-engine/plugin lifecycle contract and should not be selected by automation without maintainer intent.

Likely owner: jalehman

Owner reason: They introduced the context-engine plugin API and follow-up lifecycle hooks where the public contract would be extended.

Owner confidence: high

Options:

- **Add a notification callback (recommended):** Pass a narrow `notifyCompaction(count?)` callback in post-turn or maintenance params so engines can increment the canonical session counter only after successful owned compactions.
- **Return compaction metadata:** Allow `afterTurn` or maintenance to return a small result object, accepting a broader signature change for direct host reconciliation.
- **Query engine stats:** Add an optional stats surface for status rendering, but this risks creating a second source of truth beside session state.

## Reproduction Assessment

Yes. Source-level reproduction is high-confidence: `ownsCompaction` engines can compact in `afterTurn` or maintenance, but those paths have no channel to update `SessionEntry.compactionCount` while `/status` renders only that field.

## Solution Assessment

Unclear until maintainers choose the plugin API shape. A notification callback looks like the narrowest repair because it preserves the session store as the canonical counter while letting plugins report only successful owned compactions.
