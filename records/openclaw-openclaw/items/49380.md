## Summary

Keep open. Current main still has the source-level reporting gap: plugin-owned context engines can perform proactive/background compaction from `afterTurn()`, but that lifecycle surface has no way to report completed compactions into the persisted session counter that `/status` renders.

## What This Changes

The issue asks for `/status` and session status to count successful compactions performed by plugin-owned context engines, including background leaf compactions after a turn.

## Best Possible Solution

Define an additive context-engine compaction reporting contract, persist confirmed plugin-owned deltas into `SessionEntry.compactionCount`, and cover after-turn, manual compact, overflow, and built-in/native runtime paths without double-counting.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: an `ownsCompaction` engine can compact in `afterTurn`, but that hook returns `Promise<void>` and status reads only `SessionEntry.compactionCount`.

## Solution Assessment

Unclear as an implementation choice. The reported gap is valid, but maintainers still need to choose the stable plugin API shape before a code fix should proceed.
