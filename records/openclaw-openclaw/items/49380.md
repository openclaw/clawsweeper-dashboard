## Label Justifications

- `impact:session-state`: The displayed session compaction state can drift from actual plugin context-engine compaction activity.

## Summary

Keep open: current main and the latest release still have no plugin-facing way for compaction-owning context engines to report after-turn or background compactions into the canonical session counter, so `/status` can still display zero after plugin compaction succeeds.

## What This Changes

The issue asks for plugin-owned context engines to report successful after-turn or background compactions so `/status` and session status counters reflect them.

## Best Possible Solution

Add one narrow plugin lifecycle reporting contract that lets compaction-owning engines persist successful compaction deltas into `SessionEntry.compactionCount`, keeping status surfaces on the canonical session store.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which plugin-facing compaction reporting contract should OpenClaw support for context engines that own compaction: an after-turn/maintenance notification callback, a returned metadata shape, or a status/stats query surface?

Rationale: The bug is source-reproducible, but fixing it changes the public context-engine/plugin lifecycle contract and should not be chosen by automation without owner intent.

Likely owner: jalehman

Owner reason: They introduced the context-engine plugin API and transcript maintenance contract where this reporting surface would likely be defined.

Owner confidence: high

Options:

- **Add a notification callback (recommended):** Pass a narrow `notifyCompaction(count?)` callback in post-turn or maintenance params so engines can increment the canonical session counter only after successful owned compactions.
- **Return compaction metadata:** Allow `afterTurn` or maintenance to return a small result object, accepting a broader signature and compatibility discussion for lifecycle hooks.
- **Query engine stats:** Add an optional status/stats surface for rendering, but own the risk of a second source of truth beside session state.

## Reproduction Assessment

Yes. Source-level reproduction is high-confidence: compaction-owning engines can compact in `afterTurn` or background maintenance, but those paths have no channel to update `SessionEntry.compactionCount` while `/status` renders only that field.

## Solution Assessment

Unclear until maintainers choose the plugin API shape. A notification callback appears to be the narrowest maintainable repair because it preserves the session store as the canonical counter while letting plugins report only successful owned compactions.
