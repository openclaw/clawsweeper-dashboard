## Summary

Keep open: current main and v2026.6.11 still have the source-level gap described here. Plugin-owned `afterTurn`/maintenance work has no compaction-delta reporting path into the persisted session counter, and the open related status PR is explicitly adjacent rather than a fix for this count accuracy issue.

## What This Changes

The issue requests that successful compactions performed by plugin-owned context engines update the `/status` and `session_status` compaction count.

## Best Possible Solution

Add one narrow plugin lifecycle reporting contract that lets context engines report successful owned compactions to the canonical session store, then keep `/status` and `session_status` rendering from that canonical counter.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which plugin-facing compaction reporting contract should OpenClaw support for context engines that own compaction: an `afterTurn` notification callback, an `afterTurn` result shape, or a status/stats query surface?

Rationale: The bug is source-reproducible, but the fix changes the public context-engine/plugin lifecycle contract and needs owner intent before implementation.

Likely owner: jalehman

Owner reason: `@jalehman` authored and merged the central context-engine plugin API and maintenance lifecycle contracts that need the product/API decision.

Owner confidence: high

Options:

- **Add an afterTurn callback (recommended):** Pass a narrow callback in `afterTurn` and maintenance params so engines can increment the canonical session counter only after successful owned compactions.
- **Return compaction metadata:** Allow `afterTurn` to return a small result object, but this is a broader signature change for existing plugin implementations.
- **Query engine stats:** Let status query an optional engine stats method, but reconcile carefully or it becomes a second source of truth beside session state.

## Reproduction Assessment

Yes. Source inspection shows `afterTurn` returns `Promise<void>` with no compaction notification channel, while `/status` renders only `SessionEntry.compactionCount`; that reproduces the reported zero-count path for plugin-private leaf compactions.

## Solution Assessment

Unclear until maintainers choose the plugin API shape. A callback is the narrowest likely repair because it keeps the session store canonical and lets plugins report only successful owned compactions.
