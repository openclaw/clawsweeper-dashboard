## Label Justifications

- `P2`: This is a normal-priority status accuracy bug for plugin context engines; sessions continue, but the operator-visible compaction counter can be wrong.
- `impact:session-state`: The displayed session compaction state can drift from actual plugin context-engine compaction activity.

## Summary

Keep open: current main and the latest release still have no plugin-facing way for compaction-owning context engines to report after-turn/background compactions into the canonical session counter, so `/status` can still show zero after plugin compaction succeeds.

## What This Changes

The issue requests a way for plugin-owned context engines to report successful background or after-turn compactions so `/status` can show a nonzero compaction count.

## Best Possible Solution

Add one narrow plugin lifecycle reporting contract that lets compaction-owning engines persist successful compaction deltas into `SessionEntry.compactionCount`, keeping `/status` and session status on the canonical session store.

Owner confidence: high

Options:

- **Add a notification callback (recommended):** Pass a narrow `notifyCompaction(count?)` callback in post-turn or maintenance params so engines can increment the canonical session counter only after successful owned compactions.
- **Return compaction metadata:** Allow `afterTurn` or maintenance to return a small result object, accepting a broader signature change for direct host reconciliation.
- **Query engine stats:** Add an optional stats surface for status rendering, but avoid creating a second source of truth beside session state.

## Reproduction Assessment

Yes. Source-level reproduction is high-confidence: compaction-owning engines can compact in `afterTurn` or background maintenance, but those paths have no channel to update `SessionEntry.compactionCount` while `/status` renders only that field.

## Solution Assessment

Unclear until maintainers choose the plugin API shape. A notification callback looks like the narrowest repair because it preserves the session store as the canonical counter while letting plugins report only successful owned compactions.
