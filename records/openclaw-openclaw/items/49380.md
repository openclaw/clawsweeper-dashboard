## Summary

Keep open: current main still has the reported source-level gap, because plugin-owned context-engine lifecycle work can compact during `afterTurn` or background maintenance while `/status` still renders only the persisted session-store counter. The open last-compaction-outcome PR is adjacent, but it explicitly does not add the plugin reporting contract needed for count accuracy.

## What This Changes

Request that plugin-owned context engines can report successful compactions so `/status` and session status counts reflect engine-owned leaf or proactive compactions.

## Best Possible Solution

Define one additive context-engine reporting contract, persist confirmed plugin-owned compaction deltas into the canonical session counter, and cover built-in, manual, overflow, Codex app-server, and plugin lifecycle paths without double-counting.
