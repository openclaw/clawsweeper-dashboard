## Summary

The PR is still necessary: blank gateway credential environment variables can shadow configured credentials during configure-wizard probes. The patch restores the established optional-env precedence at the wizard boundary, includes focused regression coverage, and supplies credible before/after real-wizard terminal proof. Likely related people: `steipete` appears to be the historical configure-wizard routing candidate (low confidence; commit attribution should be confirmed during normal maintainer review).

## What This Changes

The configure wizard now treats blank `OPENCLAW_GATEWAY_TOKEN` and `OPENCLAW_GATEWAY_PASSWORD` values as unset when probing a local gateway, allowing configured credentials to be used instead.

## System Context

The configure wizard reads gateway settings and environment overrides, then probes a local Gateway over WebSocket to decide whether setup is healthy. Those probe results drive gateway setup hints and the final Control UI summary shown to the operator.

## Architecture Diagram

  F --> G[Setup hints and Control UI summary]

## Best Possible Solution

Keep optional gateway environment credentials meaningful at the configure-wizard boundary, with blank values falling back to the canonical configured token or password while explicit non-blank overrides remain authoritative.
