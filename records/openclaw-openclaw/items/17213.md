## Summary

Keep open: current main and the latest release still have adjacent terminal-outcome, liveness, and strict-agentic safeguards, but not the requested public atomic run.begin/run.exec/run.commit-or-run.abort lifecycle contract with structured abort blockers.

## What This Changes

Request a transaction-style run lifecycle so announced action intent always resolves to explicit execution, commit, or abort state.

## Best Possible Solution

Define an additive public run lifecycle contract at the gateway/event boundary, then wire structured begin, execution, commit, abort, and abort-blocker semantics through runtime emitters, agent.wait, session projection, clients/plugin-visible APIs, docs, and regression tests.

## Solution Assessment

Unclear. The transaction-style direction fits the reliability goal, but maintainers need to choose the additive protocol shape and policy behavior so it extends current terminal-outcome architecture rather than duplicating it.
