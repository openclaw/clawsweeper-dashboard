## Summary

Keep open: current main has stricter execution and terminal-outcome safeguards, but it still does not define the requested public atomic begin/exec/commit-or-abort lifecycle contract with structured abort blockers across agent events, gateway protocol, runtime lifecycle, session projection, and agent.wait.

## What This Changes

The issue requests a transaction-style run lifecycle so announced execution intent must end in explicit commit or abort status with machine-readable blocker details.

## Best Possible Solution

Define an additive public run lifecycle contract at the gateway protocol boundary, then propagate structured begin, execution evidence, commit, abort, and blocker semantics through runtime events, wait results, session projection, SDK/plugin-visible APIs, docs, and regression tests.

## Reproduction Assessment

Yes for the source-level contract gap: current main still lacks typed transaction lifecycle phases in the event, protocol, runtime, session, and wait paths. The intermittent orphan pre-action symptom itself was not live-reproduced from a deterministic trace.

## Solution Assessment

Unclear. The transaction-style direction fits the reliability goal, but the best implementation needs maintainer design so it extends the current terminal-outcome architecture instead of adding a parallel lifecycle state machine or premature policy knob.
