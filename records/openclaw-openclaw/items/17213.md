## Summary

Keep open: current main has adjacent strict-agentic, incomplete-turn, terminal-outcome, wait, and liveness safeguards, but it still does not define the requested atomic run.begin/run.exec/run.commit-or-run.abort lifecycle contract with structured abort blockers across the public event, protocol, runtime, session, and wait surfaces.

## What This Changes

The issue requests a transaction-style agent run lifecycle so announced execution intent must end in explicit commit or abort status with machine-readable abort context.

## Best Possible Solution

Define one additive lifecycle contract at the gateway protocol boundary, then propagate structured begin, execution evidence, commit, abort, and blocker semantics through runtime events, wait results, session projection, SDK/plugin-visible APIs, docs, and regression tests.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes for the source-level contract gap: current main still lacks typed transaction lifecycle phases in the event, protocol, runtime, session, and wait paths. The intermittent orphan pre-action symptom itself was not live-reproduced from a deterministic trace.

## Solution Assessment

Is this the best way to solve the issue? Unclear. The transaction-style direction fits the reliability goal, but maintainers need to define the public lifecycle, compatibility, and policy contract so it extends the current terminal-outcome architecture rather than adding a parallel state machine.
