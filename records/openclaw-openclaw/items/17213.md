## Summary

Keep open: current main and the latest release have adjacent strict-agentic, incomplete-turn, liveness, and terminal-outcome safeguards, but they still do not implement the requested public atomic begin/exec/commit-or-abort lifecycle contract with structured abort blockers.

## What This Changes

The issue requests a transaction-style run lifecycle so pre-action intent notices must be followed by execution and an explicit commit or abort state.

## Best Possible Solution

Define an additive public run lifecycle contract at the gateway protocol boundary, reuse existing terminal-outcome normalization, carry structured abort blockers, and propagate it through runtime emitters, wait responses, session projections, SDK/plugin-visible APIs, docs, and regression tests.

## Reproduction Assessment

Yes for the source-level contract gap: current main still lacks typed transaction lifecycle phases in the event, protocol, runtime, session, and wait paths. The intermittent orphan pre-action symptom itself was not live-reproduced from a deterministic trace.

## Solution Assessment

Unclear. The transaction-style direction fits the reliability goal, but the best implementation needs maintainer design so it extends current terminal-outcome architecture instead of adding a parallel lifecycle state machine or premature policy knob.
