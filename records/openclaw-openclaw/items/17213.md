## Summary

Keep open: current main has adjacent strict-agentic, liveness, terminal-outcome, abort, and wait safeguards, but it still lacks the requested public atomic begin/exec/commit-or-abort lifecycle contract with structured abort blockers across event, protocol, runtime, session, and wait surfaces.

## What This Changes

The issue requests an atomic run lifecycle contract where announced execution intent must end in an explicit commit or abort state with structured abort details.

## Best Possible Solution

Define an additive public run lifecycle contract at the protocol boundary, reuse existing terminal-outcome normalization, and propagate structured begin, execution, commit, abort, and blocker semantics through gateway events, wait responses, session projection, SDK/plugin-visible APIs, docs, and regression tests.

## Reproduction Assessment

Yes for the source-level contract gap: current main lacks typed transaction lifecycle phases in event, protocol, runtime, session, and wait paths. The intermittent orphan pre-action symptom itself was not live-reproduced from a deterministic trace.

## Solution Assessment

Unclear. The transaction-style direction fits the reliability goal, but the best implementation needs maintainer design so it extends current terminal-outcome architecture instead of adding a parallel lifecycle state machine or premature policy knob.
