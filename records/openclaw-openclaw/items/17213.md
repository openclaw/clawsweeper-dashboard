## Summary

Keep open: current main and the latest release still expose generic lifecycle start/end/error events and terminal wait snapshots, not the requested atomic begin/exec/commit-or-abort contract with structured abort blockers.

## What This Changes

Request to add a transaction-style run lifecycle so announced action intent always reaches explicit execution, commit, or abort state.

## Best Possible Solution

Define an additive public run lifecycle contract at the Gateway protocol boundary and propagate structured begin, execution evidence, commit, abort, and blocker semantics through runtime events, session projection, wait results, SDK/plugin-visible APIs, docs, and regression tests.

## Reproduction Assessment

Yes for the source-level contract gap: current main still lacks typed transaction lifecycle phases in the event, protocol, runtime, session, and wait paths. The intermittent orphan pre-action symptom itself was not live-reproduced from a deterministic trace.

## Solution Assessment

Unclear. The transaction-style direction fits the reliability goal, but the best implementation needs maintainer design so it extends the current terminal-outcome architecture instead of adding a parallel lifecycle state machine or premature policy knob.
