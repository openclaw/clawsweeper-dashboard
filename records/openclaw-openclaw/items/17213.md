## Summary

Keep open: current main and the latest release have adjacent terminal-outcome, liveness, and false-start safeguards, but they still do not provide the requested public atomic begin/exec/commit-or-abort lifecycle contract with structured abort blockers.

## What This Changes

The issue requests an atomic run lifecycle contract so announced agent actions always resolve into explicit execution, commit, or abort state.

## Best Possible Solution

Define an additive core lifecycle contract at the protocol boundary, reuse the existing terminal-outcome normalization, carry structured abort/blocker details, and propagate it through gateway events, agent.wait, session projection, SDK/plugin-visible surfaces, docs, and regression tests.

## Reproduction Assessment

Yes for the source-level contract gap: current main still lacks typed transaction lifecycle phases in the event, protocol, runtime, session, and wait paths. The intermittent orphan pre-action symptom itself was not live-reproduced from a deterministic trace.

## Solution Assessment

Unclear. The transaction-style direction fits the reliability goal, but the best implementation needs maintainer design so it extends the current terminal-outcome and gateway protocol architecture instead of adding a parallel state machine or premature policy knob.
