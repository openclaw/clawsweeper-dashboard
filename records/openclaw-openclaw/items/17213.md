## Summary

Keep open: current main and the latest release still have adjacent liveness, incomplete-turn, and terminal-outcome safeguards, but they do not define the requested atomic begin/exec/commit-or-abort run lifecycle with structured abort blockers across events, Gateway protocol, runtime lifecycle, session projection, and agent.wait.

## What This Changes

The issue asks for a transaction-style run lifecycle that prevents user-visible pre-action notices from being left without an explicit execution, commit, or abort outcome.

## Best Possible Solution

Define an additive public run lifecycle contract at the Gateway protocol boundary, reuse existing terminal-outcome normalization, carry structured abort blockers, and propagate it through events, wait results, session projection, SDK/plugin-visible APIs, docs, and regression tests.

## Reproduction Assessment

Yes for the source-level contract gap: current main still lacks typed transaction lifecycle phases in the event, protocol, runtime, session, and wait paths. The intermittent orphan pre-action symptom itself was not live-reproduced from a deterministic trace.

## Solution Assessment

Unclear. The transaction-style direction fits the reliability goal, but the best implementation needs maintainer design so it extends current terminal-outcome architecture instead of adding a parallel lifecycle state machine or premature policy knob.
