## Summary

Keep open. Current main has adjacent followthrough, liveness, restart, and terminal-outcome safeguards, but it still lacks the requested public atomic begin/exec/commit-or-abort lifecycle contract with structured abort blockers across agent events, gateway protocol, runtime lifecycle emitters, session projection, docs, and agent.wait.

## What This Changes

The issue requests a core run lifecycle contract that turns pre-action intent into guaranteed execution followed by an explicit commit or abort state with machine-readable abort blockers.

## Best Possible Solution

Define an additive public run lifecycle contract that extends the current terminal-outcome model, carries structured abort/blocker details, and propagates through gateway events, wait responses, session projection, SDK/plugin-visible APIs, docs, and regression tests.

## Reproduction Assessment

Yes for the source-level contract gap: current main still lacks typed transaction lifecycle phases in the event, protocol, runtime, session, docs, and wait paths. The intermittent orphan-notice runtime symptom itself was not live-reproduced from a deterministic trace.

## Solution Assessment

Unclear. The transaction-style direction fits the reliability goal, but the best implementation needs maintainer API/product design so it extends current terminal-outcome handling instead of adding a parallel lifecycle state machine or premature policy knob.
