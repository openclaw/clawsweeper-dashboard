## Summary

Keep open: current main has strict-agentic and terminal-outcome safeguards, but it still lacks the requested public begin/exec/commit-or-abort lifecycle contract with structured abort blockers across events, protocol, wait results, and session projection.

## What This Changes

The issue requests an atomic run lifecycle contract so announced action intent cannot remain orphaned without explicit execution, commit, or abort status.

## Best Possible Solution

Define an additive core lifecycle contract that extends the existing terminal-outcome model and carries begin intent, execution evidence, mandatory commit or abort, and structured blocker details through gateway events, agent.wait, session projection, SDK/plugin-visible APIs, docs, and regression tests.

## Reproduction Assessment

Yes for the source-level contract gap: current main still lacks typed transaction lifecycle phases in the event, protocol, runtime, session, docs, and wait paths. The intermittent orphan-notice runtime symptom itself was not live-reproduced from a deterministic trace.

## Solution Assessment

Unclear. The transaction-style direction fits the reliability goal, but the best implementation needs maintainer design so it extends current terminal-outcome handling instead of adding a parallel lifecycle state machine or premature policy knob.
