## Summary

Keep open: current main and the latest release have adjacent safeguards for strict-agentic turns, liveness, restart recovery, and terminal outcomes, but they still do not define the requested public begin/exec/commit-or-abort transaction lifecycle with structured abort blockers across event, protocol, runtime, session, and wait surfaces.

## What This Changes

The issue requests a core run lifecycle contract that guarantees announced action intent is followed by execution evidence and a mandatory commit or abort status.

## Best Possible Solution

Define an additive core lifecycle contract at the gateway protocol boundary, reuse terminal-outcome normalization, and propagate structured begin, execution, commit, abort, and blocker semantics through events, wait responses, session projection, SDK/plugin-visible APIs, docs, and regression tests.

## Reproduction Assessment

Yes for the source-level contract gap: current main still lacks typed transaction lifecycle phases in the event, protocol, runtime, session, and wait paths. The intermittent orphan pre-action symptom itself was not live-reproduced from a deterministic trace.

## Solution Assessment

Unclear. The transaction-style direction fits OpenClaw's reliability goal, but the best implementation needs maintainer design so it extends current terminal-outcome architecture instead of adding a parallel lifecycle state machine or premature policy knob.
