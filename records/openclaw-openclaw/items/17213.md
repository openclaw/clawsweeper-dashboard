## Summary

Keep open. Current main has materially improved terminal snapshots, session-operation events, task tracking, and audit records, but those are observability and projection safeguards; they still do not guarantee that a user-visible action announcement is atomically coupled to execution and a mandatory structured terminal outcome.

## What This Changes

Add an atomic intent-to-execution lifecycle so every announced action finishes with an explicit committed or aborted outcome and machine-readable blocker details.

## Best Possible Solution

Extend the canonical run terminal-outcome and session-operation contracts with structured intent provenance, execution evidence, and a mandatory success-or-abort projection, then make user-visible progress surfaces render only from that shared state rather than introducing a separate transaction subsystem or new config knob.
