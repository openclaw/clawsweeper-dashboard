## Summary

Keep open: current main and v2026.6.11 still have adjacent terminal-outcome, liveness, and wait safeguards, but they do not define the requested atomic begin/execution/commit-or-abort lifecycle contract with structured abort blockers across event, protocol, runtime, session, and wait surfaces.

## What This Changes

The issue asks OpenClaw to enforce an atomic intent-to-execution lifecycle so pre-action notices always end in explicit commit or structured abort status.

## Best Possible Solution

Define one additive gateway lifecycle contract for begin intent, execution evidence, mandatory commit or abort, and structured blocker details, then wire it through AgentEvent, protocol schemas, runtime emitters, agent.wait, session projection, SDK/plugin-visible surfaces, docs, and regression tests.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes for the source-level contract gap: current main lacks typed transaction lifecycle phases in event, protocol, runtime, session, and wait paths. The intermittent orphan pre-action notice symptom itself was not live-reproduced from a deterministic trace.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainers define the public lifecycle contract. A transaction-style flow is the right problem framing, but it should extend the current terminal-outcome architecture rather than add a parallel state machine.
