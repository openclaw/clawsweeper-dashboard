## Summary

Keep open: current main has adjacent strict-agentic, incomplete-turn, liveness, and terminal-outcome safeguards, but it still lacks the requested public atomic begin/exec/commit-or-abort contract with structured abort blockers across event, gateway, runtime, session, docs, and wait surfaces.

## What This Changes

The issue requests an atomic run lifecycle where visible execution intent must be followed by execution and a mandatory commit or abort status.

## Best Possible Solution

Define an additive public run lifecycle contract at the protocol boundary, reuse existing terminal-outcome normalization, carry structured abort blockers, and propagate it through gateway events, wait responses, session projection, SDK/plugin-visible APIs, docs, and regression tests.

## Reproduction Assessment

Yes for the source-level contract gap: current main still lacks typed transaction lifecycle phases in the event, protocol, runtime, session, and wait paths. The intermittent orphan pre-action symptom itself was not live-reproduced from a deterministic trace.

## Solution Assessment

Unclear. The transaction-style direction fits the reliability goal, but the best implementation needs maintainer design so it extends current terminal-outcome architecture instead of adding a parallel lifecycle state machine or premature policy knob.
