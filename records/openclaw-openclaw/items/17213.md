## Summary

Keep open: current main has adjacent strict-agentic, liveness, terminal-outcome, and wait safeguards, but it still does not define the requested public atomic begin/exec/commit-or-abort lifecycle contract with structured abort blockers across event, gateway, runtime, session, and wait surfaces.

## What This Changes

Request an atomic run lifecycle contract so announced execution intent must end in explicit commit or abort status rather than leaving orphan pre-action notices.

## Best Possible Solution

Define an additive public run lifecycle contract at the gateway protocol boundary, reuse existing terminal-outcome normalization, and propagate structured begin, execution, commit, abort, and blocker semantics through events, wait responses, session projection, SDK/plugin-visible APIs, docs, and regression tests.

## Reproduction Assessment

Yes for the source-level contract gap: current main still lacks typed transaction lifecycle phases in the event, protocol, runtime, session, and wait paths. The intermittent orphan pre-action symptom itself was not live-reproduced from a deterministic trace.

## Solution Assessment

Unclear. The transaction-style direction fits the reliability goal, but the best implementation needs maintainer design so it extends current terminal-outcome architecture instead of adding a parallel lifecycle state machine or premature policy knob.
