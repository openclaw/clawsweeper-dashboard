## Summary

Keep open: current main has adjacent strict-agentic, incomplete-turn, timeout, and lifecycle safeguards, but it still lacks the requested public atomic begin/exec/commit-or-abort contract with structured abort blockers across agent events, gateway protocol, runtime lifecycle, session projection, docs, and agent.wait.

## What This Changes

Request an atomic run lifecycle contract so announced action intent must lead to execution evidence and an explicit commit or abort result.

## Best Possible Solution

Define an additive core run lifecycle contract that reuses terminal-outcome normalization, carries structured abort/blocker details, and propagates through gateway events, agent.wait, session projection, SDK/plugin-visible APIs, docs, and regression tests.

## Reproduction Assessment

Yes for the source-level contract gap: current main still lacks typed transaction lifecycle phases in the event, protocol, runtime, session, and wait paths. The intermittent orphan pre-action notice symptom itself was not live-reproduced from a deterministic trace.

## Solution Assessment

Unclear. The transaction-style direction fits the reliability goal, but the best implementation needs maintainer design so it extends the current terminal-outcome architecture instead of adding a parallel state machine or premature policy knob.
