## Summary

The claimed lone-surrogate failure is unreachable on current main and in the latest release because the formatter converts all non-ASCII code units to an ASCII underscore token before truncation; the proposed helper substitution is therefore behaviorally redundant.

## What This Changes

The PR replaces the final raw 100-code-unit slice in unknown compaction-reason formatting with the shared UTF-16-safe truncation helper.

## Best Possible Solution

Keep the current ASCII-only diagnostic-token formatter; if a future change intentionally preserves Unicode, introduce UTF-16-safe truncation and a surrogate-boundary regression test as part of that same behavior change.

No. The shared helper is appropriate when Unicode is retained, but this formatter deliberately removes Unicode first, so the patch does not change observable behavior.
