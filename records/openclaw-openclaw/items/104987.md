## Summary

Current main cannot exhibit the reported lone-surrogate bug because the formatter converts unknown reason text to an ASCII-only diagnostic token before truncating it. The proposed helper substitution is therefore redundant, and an earlier identical PR was closed after reaching the same conclusion.

## What This Changes

Replaces raw slicing with `truncateUtf16Safe` when limiting sanitized unknown compaction-reason details to 100 characters.

## Best Possible Solution

Keep the existing ASCII-token formatter unchanged; only add surrogate-safe truncation here if a future intentional sanitizer change allows Unicode to survive, with corresponding telemetry-safety and boundary tests.

## Reproduction Assessment

## Solution Assessment

No. Although `truncateUtf16Safe` is correct for Unicode-bearing strings, using it after an ASCII-only normalization step does not solve a reachable defect and obscures the formatter invariant.
