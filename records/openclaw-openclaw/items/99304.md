## Summary

Keep open: the failure-surfacing behavior is useful, but the latest head still returns a generic final failure from the inner runner before the outer reply path drains pending tool and block delivery, so it can duplicate or misorder visible output.

## What This Changes

The PR changes auto-reply terminal embedded-agent failures to return a marked visible failure payload when no visible payload or committed source delivery exists, with regression tests for fallback-exhausted and completed-terminal-error cases.

## Best Possible Solution

Keep the visible terminal-failure fallback, but route the generated failure payload through the existing drained reply pipeline or explicitly drain pending delivery before returning it.

## Reproduction Assessment

Yes, from source inspection: current main can mark a terminal embedded-agent failure and still flow back with empty visible payloads that the caller may treat as nothing to send. I did not run a live chat/control/terminal reproduction.

## Solution Assessment

No. The requested behavior is appropriate, but the current implementation is not the best fix because it returns before the existing drained reply path can account for late tool-result or block delivery.
