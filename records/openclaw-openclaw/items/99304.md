## Summary

Keep open: the bug-fix direction is useful, but the patch is not merge-ready because the new early terminal-failure return can bypass the caller path that drains pending tool-result delivery before deciding there is no visible reply. The external PR also has only test and static-check proof, not after-fix real behavior proof from a real setup.

## What This Changes

The PR makes `runAgentTurnWithFallback` return a marked failure payload when terminal embedded-agent failures have no visible payload or committed source delivery, and adds regression tests for those cases.

## Best Possible Solution

Keep the terminal-failure surfacing, but route the generated failure payload through the existing drained reply pipeline or explicitly drain pending delivery before returning, then add a regression for pending tool-result delivery and real behavior proof.

## Reproduction Assessment

Yes, from source inspection: current main can mark a terminal embedded-agent error as failed, then continue with an empty success-shaped run result that the caller may turn into no visible reply. I did not run a live reproduction.

## Solution Assessment

No, this is a plausible fix but not the best shape because it returns before the normal drained reply path can account for late tool-result delivery. The safer fix is to preserve that pipeline while adding the fallback failure payload.
