## Summary

Keep open. This is a distinct recovery-convergence bug: the documented restore-before-migration path can repeatedly replace an operator’s live-file repair with a last-known-good snapshot that cannot be written under the current schema. The companion migration report may remove the reported trigger, but it does not establish a general guard for other legacy snapshots that fail post-restore migration or validation.

## What This Changes

Prevent `openclaw doctor --fix` from repeatedly restoring a last-known-good configuration that fails current migrations or validation and overwrites an operator’s in-progress repair.

## System Context

Doctor is OpenClaw’s configuration recovery path: it reads an invalid live configuration, may restore a last-known-good snapshot, then applies legacy migrations and writes the canonical current shape. A failed final write currently leaves the restored snapshot live, so the next repair attempt can repeat the same restore cycle.

## Architecture Diagram

flowchart LR
  A[Invalid live config] --> B[Doctor preflight]
  C[Last-known-good snapshot] --> B
  B --> D[Restore snapshot]
  D --> E[Legacy migrations]
  E --> F[Current-schema validation and write]
  F -->|fails| G[Restored file remains live]
  G --> B

## Best Possible Solution

Validate and migrate the last-known-good candidate in memory before replacing the live file; restore only a candidate that can be written as the current canonical configuration, otherwise preserve both files and emit a clear actionable recovery error.
