## Summary

Keep open: this PR is a focused fix for the transcript readline cleanup path, but the patch still returns immediately after `stream.destroy()` even though Node closes `fs.ReadStream` asynchronously after pending IO, so it does not fully prove descriptor release before the failed read returns.

## What This Changes

This PR changes `src/transcripts/store.ts` to name the transcript read stream and call `lines.close()` plus `stream.destroy()` from a `finally` block in the bounded `maxUtterances` JSONL reader.

## Best Possible Solution

Land one canonical fix that closes the readline interface, destroys and awaits the read stream close, and includes focused regression coverage for the malformed JSON path.

## Reproduction Assessment

Yes. Current main has a source-level reproduction path: the bounded transcript reader opens a file stream, parses JSONL inside the async iteration, and can throw before any explicit stream cleanup.

## Solution Assessment

No as submitted. The local `finally` cleanup is the right layer, but it should wait for the read stream to close before the method returns or rethrows, and the final landing branch should include focused regression coverage.
