## Label Justifications

- `impact:data-loss`: Concurrent allow-always approvals can silently drop earlier persisted allowlist entries from exec-approvals.json.
- `impact:security`: The affected file controls command execution authorization, so stale writes can alter future exec approval policy.
- `maturity:stable`: The issue affects gateway-runtime Approvals and Remote Execution, including Exec approvals and Node exec approvals, scored M4 Stable in the maturity data.

## Summary

Keep open: current main and v2026.6.11 still save allow-always entries from request-local approval snapshots, so concurrent approvals can still clobber earlier entries; the direct fix PRs are closed unmerged and the broader open PR is dirty and incomplete.

## What This Changes

The issue asks OpenClaw to prevent concurrent allow-always exec approvals from overwriting each other's entries in exec-approvals.json.

## Best Possible Solution

Implement one core exec-approvals persistence path that reloads and merges under a lock or freshness contract for gateway and node allow-always and usage writes, with focused concurrent-write regression coverage.

## Reproduction Assessment

Yes for a source-level reproduction: the reporter provided concrete concurrent approval steps, and current main still saves allow-always changes from request-local ExecApprovalsFile snapshots. I did not run a live concurrent Telegram approval flow in this read-only review.

## Solution Assessment

Yes, the best fix belongs in core exec-approvals persistence rather than an external backup or ClawHub workaround. The fix should make each allow-always or usage write merge against the latest file under one freshness contract.
