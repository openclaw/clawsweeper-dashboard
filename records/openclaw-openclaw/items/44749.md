## Summary

Keep open: current main and v2026.6.11 still save allow-always and allowlist-usage updates through request-local `ExecApprovalsFile` snapshots, so concurrent approvals can still overwrite earlier persisted entries. The direct fix PRs are closed unmerged, and the broader overlapping PR is still open/proof-gated rather than a safe canonical fix.

## What This Changes

The issue reports concurrent `allow-always` exec approvals losing earlier allowlist entries because stale in-memory approval snapshots are saved back to `exec-approvals.json`.

## Best Possible Solution

Land a vetted core fix that reloads and merges, locks, or CAS-checks exec approval writes across gateway and node paths so concurrent allow-always approvals preserve every accepted allowlist entry.

## Reproduction Assessment

Yes, at source level. Current main still passes stale approval snapshots into writeback helpers that save the whole approvals object, matching the reporter's concurrent last-write-wins reproduction; I did not run a live concurrent approval scenario in this read-only review.

## Solution Assessment

Yes, the right fix belongs in the core exec approval persistence path. The external backup workaround mentioned in discussion can help recover data, but it does not prevent the internal race.
