## Summary

Keep open: current main and v2026.6.11 still persist exec approval allowlist changes by mutating a request-local `ExecApprovalsFile` snapshot and saving the whole file, so concurrent `allow-always` approvals can still clobber earlier entries. The direct fix PRs are closed unmerged, and the broader related PR is open but conflicting/proof-gated rather than a safe canonical fix.

## What This Changes

The issue asks OpenClaw to prevent concurrent `allow-always` exec approvals from overwriting each other in `exec-approvals.json`.

## Best Possible Solution

Land a vetted exec-approval persistence fix that serializes or freshness-checks every allow-always and allowlist-usage write, re-reads/merges current state before saving, and covers both gateway and node execution paths with focused regression tests.

## Reproduction Assessment

Yes at source level. Current main still passes request-local approval snapshots into `persistAllowAlwaysDecision()` and `recordAllowlistMatchesUse()`, and the helpers save the whole supplied object without re-reading or merging current file state.

## Solution Assessment

Yes, the right fix belongs in the exec approval persistence owner. External backup/merge tooling mentioned in the discussion can reduce damage, but it cannot make the internal read-modify-write path correct.
