## Label Justifications

- `P1`: The issue is a high-confidence exec approval race that silently drops persisted allowlist state in normal parallel agent workflows.
- `impact:data-loss`: Concurrent approvals can silently lose allowlist entries from `exec-approvals.json`.

- `maturity:stable`: The affected Gateway runtime `Exec approvals` feature is part of the M4 Stable Gateway runtime surface.

## Summary

Keep open: current `main` and the latest release still save allow-always and usage updates from caller-held exec approval snapshots, so concurrent approvals can still silently overwrite earlier allowlist entries.

## What This Changes

The issue reports concurrent `allow-always` exec approvals overwriting each other in `exec-approvals.json`, causing earlier allowlist entries to be silently lost.

## Best Possible Solution

Land a vetted exec-approvals persistence fix that reloads and merges or hash-checks under one lock/CAS boundary for allow-always and usage metadata writes across gateway and node paths, with focused concurrent-write regression coverage.
