Keep open: current main and v2026.6.11 still mutate and save stale exec approval snapshots for allow-always persistence and allowlist usage, so concurrent approvals can still silently drop earlier allowlist entries. The backup workaround mentioned in discussion may help recovery, but it does not repair the in-repo write path, and the overlapping open PR is still blocked by proof/review concerns.

The issue reports concurrent allow-always exec approvals overwriting earlier allowlist entries in exec-approvals.json.
