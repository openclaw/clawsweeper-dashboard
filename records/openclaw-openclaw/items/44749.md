## Summary

Keep open: current main and the latest release still persist allow-always and allowlist metadata by mutating a caller-held ExecApprovalsFile snapshot and saving the whole file, so concurrent approvals can still clobber earlier entries. The direct fix PRs are closed unmerged, and the broader open PR targets an adjacent stale-writeback security issue rather than a merged fix for this issue.

## What This Changes

This issue asks OpenClaw to prevent concurrent allow-always exec approvals from silently overwriting earlier allowlist entries in exec-approvals.json.

## Best Possible Solution

Land one reviewed core exec-approvals persistence fix that reloads and merges or CAS/locks updates through a shared store path for gateway and node-host allow-always plus usage writes, with regression coverage for concurrent approvals and stale snapshot writeback.

## Reproduction Assessment

Yes. Source inspection shows two approval handlers can hold separate ExecApprovalsFile snapshots, then addAllowlistEntry saves each whole-file object without a fresh merge; I did not run the live race in this read-only review.

## Solution Assessment

Yes, the best fix belongs in the core exec approvals persistence boundary rather than in backup or polling workarounds. The repair should use one shared freshness/locking contract across gateway and node-host callers instead of one-sided call-site patches.
