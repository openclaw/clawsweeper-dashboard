## Summary

Keep open: current main and the latest release still save allow-always and allowlist-usage updates by mutating a previously loaded approvals object and writing the whole `exec-approvals.json`, so concurrent approvals can still clobber earlier entries. The backup workaround mentioned in the discussion can help recovery, but it does not fix the in-repo stale write path; the related open PR is overlapping but not merged or landable yet.

## What This Changes

The issue reports silent loss of concurrent `allow-always` exec approvals because multiple handlers mutate stale `exec-approvals.json` snapshots and save the whole file.

## Best Possible Solution

Centralize exec-approval writes behind a guarded read-merge-write, CAS, or lock-backed helper that covers allow-always persistence and usage metadata across gateway and node; maintainers can adopt or replace https://github.com/openclaw/openclaw/pull/78226, but this issue should stay open until a merged fix reaches main.
