## Label Justifications

- `P1`: Concurrent allow-always approvals can silently lose persisted exec approval state in a real agent/channel workflow.
- `impact:data-loss`: The reported race drops allowlist entries from the persisted approval file without an explicit failure.
- `impact:security`: The affected file controls exec allowlist security state and future approval reuse.
- `maturity:stable`: The issue affects the Gateway runtime M4 Stable surface, specifically Approvals and Remote Execution / exec approvals.

## Summary

Keep open: current main and `v2026.6.11` still persist `allow-always` and allowlist-usage updates by saving a previously loaded approvals object, so the reported concurrent last-write-wins loss remains possible; the overlapping open PR is not merged and still has review/proof blockers.

## What This Changes

The issue reports concurrent `allow-always` exec approvals silently losing earlier allowlist entries from `exec-approvals.json`.

## Best Possible Solution

Centralize exec-approval writes behind a guarded read-merge-write, CAS, or lock-backed helper that covers allow-always persistence and usage metadata across gateway and node, then close this issue only after the fix is merged to main.
