## Summary

Keep open: current main and the latest release still save allow-always and allowlist-usage updates by mutating a previously loaded approvals object and writing the whole `exec-approvals.json`, so concurrent approvals can still clobber earlier entries. The linked backup workaround may help recovery, but it does not fix the in-repo stale write path.

The issue reports silent allowlist data loss when concurrent `allow-always` exec approvals write stale `exec-approvals.json` snapshots.
