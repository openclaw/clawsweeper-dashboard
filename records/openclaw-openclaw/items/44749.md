## Summary

Keep open: current `main` and `v2026.6.11` still persist allow-always and allowlist-usage updates by saving a caller-supplied approvals snapshot, so concurrent approvals can still clobber entries. The related direct fix PRs are closed unmerged, and the open guarded-write PR overlaps but is not yet merged or safe to treat as the canonical resolution.

## What This Changes

The issue reports concurrent `allow-always` exec approvals overwriting each other in `exec-approvals.json`, losing earlier allowlist entries.

## Best Possible Solution

Land a vetted exec-approvals persistence fix that reloads and merges or hash-checks under one lock/CAS boundary for allow-always and usage metadata writes across gateway and node paths, with focused concurrent-write regression coverage.
