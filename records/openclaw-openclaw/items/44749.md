## Summary

Keep open: current main and v2026.6.11 still persist allow-always and usage writes from request-local exec-approvals snapshots, so concurrent approvals can still lose earlier allowlist entries.

## What This Changes

The issue reports that concurrent allow-always exec approvals can overwrite each other in exec-approvals.json and silently drop persisted allowlist entries.

## Best Possible Solution

Land a core exec-approvals persistence fix that reloads and merges under one freshness/locking contract for gateway and node allow-always and usage writes, with regression coverage for concurrent approvals and stale admin updates.

## Reproduction Assessment

Yes. The reporter provided concrete concurrent approval steps, and current source shows gateway and node allow-always paths save request-local ExecApprovalsFile snapshots without a fresh merge or hash guard.

## Solution Assessment

Yes. The fix belongs in the core exec approvals persistence boundary; backup or polling workarounds can recover data after clobbering but do not prevent the stale-write race.
