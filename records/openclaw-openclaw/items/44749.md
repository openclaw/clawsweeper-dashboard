## Summary

Keep open: current main and the latest release still persist allow-always and allowlist-usage updates by mutating a previously loaded approvals object and saving the whole exec approvals file, so the reported concurrent stale-write race remains. Closed PRs tried narrower fixes, while the open overlapping PR is not merged and still has security/proof blockers.

## What This Changes

The issue asks OpenClaw to preserve all concurrent allow-always exec approvals instead of letting later stale writes overwrite earlier allowlist entries in exec-approvals.json.

## Best Possible Solution

Centralize exec-approval persistence behind a guarded read-merge-write, CAS, or lock-backed helper that covers allow-always and usage metadata across gateway and node, then land it with focused race regression coverage and security review.
