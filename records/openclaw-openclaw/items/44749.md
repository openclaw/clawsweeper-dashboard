## Label Justifications

- `P1`: Concurrent user approvals can silently lose persisted exec allowlist entries in a normal agent workflow, affecting trusted command execution state.
- `impact:data-loss`: The issue is specifically about silently dropping user-approved allowlist entries from `exec-approvals.json`.
- `impact:security`: The lost entries live in the exec approval policy store that gates host and node command execution.

## Summary

Keep open: current main and the latest release still mutate and save caller-supplied exec approvals snapshots for allow-always and allowlist-use updates, so the reported last-write-wins data loss remains source-reproducible.

## What This Changes

This issue requests fixing concurrent `allow-always` exec approvals so all approved allowlist entries persist instead of being silently overwritten in `exec-approvals.json`.

## Best Possible Solution

Move allow-always and allowlist-use persistence onto one guarded current-file merge or hash/CAS write path shared by gateway and node execution, with regression coverage for concurrent approvals and admin policy freshness.
