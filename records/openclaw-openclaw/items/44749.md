## Label Justifications

- `P1`: The issue describes a high-confidence race in command approval persistence that silently loses allow-always entries in a security-sensitive execution workflow.

## Summary

Keep open: current main and the latest release still save allow-always updates from request-local exec approval snapshots, so concurrent approvals can still clobber earlier allowlist entries; direct fix attempts are closed unmerged and the broader open stale-write PR still needs maintainer/security review.

## What This Changes

The issue reports concurrent `allow-always` exec approvals losing earlier allowlist entries because stale `exec-approvals.json` snapshots are saved whole-file after approval resolution.

## Best Possible Solution

Land a reviewed core exec-approvals persistence fix that reloads and merges under one lock/freshness contract for gateway and node allow-always and usage writes, with regression coverage for concurrent approvals and admin-revocation races.
