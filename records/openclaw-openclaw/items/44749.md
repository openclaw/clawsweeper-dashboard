## Summary

Keep open: current main and v2026.6.11 still persist allow-always entries by mutating and saving request-local ExecApprovalsFile snapshots, so concurrent approval completions can still overwrite earlier allowlist entries; the direct fix PRs are closed unmerged and the broader open stale-write PR is still conflicting and proof-gated.

## What This Changes

The issue reports that concurrent allow-always exec approvals can overwrite each other in exec-approvals.json, silently dropping earlier allowlist entries.

## Best Possible Solution

Land a reviewed core exec-approvals persistence fix that reloads and merges under one lock or freshness contract for gateway and node allow-always and usage writes, with regression coverage for concurrent approvals and admin-revocation races.

## Reproduction Assessment

Yes. The issue has concrete reporter steps, and source inspection on current main shows gateway and node allow-always paths can save request-local ExecApprovalsFile snapshots without a re-read, merge, or hash guard; I did not run a live concurrent Telegram flow in this read-only review.

## Solution Assessment

Yes, the best fix belongs in the core exec approvals persistence boundary, not in a backup workaround. A lock-only replacement write is not enough unless the implementation also reloads/merges or validates freshness before saving.
