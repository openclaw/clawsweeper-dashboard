## Summary

Keep open: current main and v2026.6.11 still persist allow-always and allowlist-usage updates by mutating a request-local approvals snapshot and saving the whole file, so concurrent approvals can still clobber earlier entries. The direct fix attempts are closed unmerged, and the broader open stale-write PR is still conflicting and not a clean canonical fix for this issue.

## What This Changes

The issue reports concurrent allow-always exec approval writes to exec-approvals.json losing earlier allowlist entries because stale request-local approval snapshots overwrite the whole file.

## Best Possible Solution

Land a reviewed core exec-approvals persistence fix that reloads and merges under one locking/freshness contract for gateway and node allow-always and usage writes, with regression coverage for concurrent approvals and admin-revocation races.

## Reproduction Assessment

Yes, at source level. The issue provides concrete concurrent approval steps, and current main still shows gateway and node allow-always paths saving request-local ExecApprovalsFile snapshots without a fresh merge or hash guard.

## Solution Assessment

Yes. The best fix belongs in the core exec-approvals persistence boundary; a backup skill or external merge workaround can recover some loss but cannot prevent the internal stale-write race.
