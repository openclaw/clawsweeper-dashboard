## Summary

Keep open: current main and v2026.6.11 still save request-local exec approval snapshots back to the whole approvals file from the gateway and node allow-always paths, so concurrent approvals can still clobber earlier allowlist entries. The direct fix attempts are closed unmerged, and the broader related PR at https://github.com/openclaw/openclaw/pull/78226 is still open but conflicting and proof-gated.

## What This Changes

The issue asks OpenClaw to preserve all concurrent allow-always exec approval entries instead of losing earlier entries through last-write-wins writes to exec-approvals.json.

## Best Possible Solution

Centralize exec approval mutations behind a locked or CAS-style reload-and-merge write path that covers allow-always persistence and allowlist usage metadata for both gateway and node hosts, with regression coverage for concurrent allow-always approvals and stale writeback.

## Reproduction Assessment

Yes from source inspection: both gateway and node paths pass stale approvals.file snapshots into helpers that save the whole file without reloading or merging latest state. I did not run a live concurrent approval scenario because this cleanup review is read-only.

## Solution Assessment

No, the current implementation is not the best solution because atomic temp-file replacement alone does not make the read-modify-write operation safe. The best fix is a single locked or hash-checked mutation path shared by addAllowlistEntry and allowlist usage writeback.
