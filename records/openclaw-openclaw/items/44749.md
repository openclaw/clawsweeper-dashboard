## Summary

Keep open: current main still mutates request-local exec approval snapshots and saves the whole approvals file from both gateway-host and node-host approval paths, so concurrent allow-always approvals can still clobber earlier persisted entries. The direct fix PRs are closed unmerged, and the broader stale-write PR is open but conflicting and still needs proof/security review.

## What This Changes

The issue reports that concurrent allow-always exec approvals can overwrite each other in exec-approvals.json, silently dropping earlier allowlist entries.

## Best Possible Solution

Keep this issue open until exec approvals update allowlist and usage metadata through a fresh serialized/CAS-aware store path, with regression coverage for concurrent allow-always approvals on both gateway-host and node-host paths.

## Reproduction Assessment

Yes: the issue gives concrete concurrent approval steps, and current source still lets separate gateway/node approval handlers save stale approvals.file snapshots through addAllowlistEntry and recordAllowlistUse. I did not execute the live race in this read-only pass.

## Solution Assessment

No: current main has not implemented the needed fix. The best repair should move allow-always and usage metadata writes into a shared fresh-read, serialized, CAS-aware store helper instead of saving request-local snapshots.
