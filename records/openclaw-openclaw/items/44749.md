## Summary

Keep open: current main and the latest release still save exec approval allowlist additions and usage updates from request-local `ExecApprovalsFile` snapshots, so concurrent `allow-always` completions can still overwrite earlier entries. The direct fix PRs are closed unmerged, and the broader overlapping PR is still dirty/proof-gated rather than a safe canonical fix.

## What This Changes

The issue reports concurrent `allow-always` exec approvals overwriting each other in `exec-approvals.json`, silently dropping earlier per-agent allowlist entries.

## Best Possible Solution

Land or adopt a maintainer-reviewed core exec-approvals persistence fix that reloads and merges under one lock or freshness contract for gateway and node `allow-always` and usage writes, with regression proof for concurrent approvals and admin-revocation races.

## Reproduction Assessment

Yes. The reporter supplied concrete concurrent approval cases, and current main still shows `addAllowlistEntry`, gateway usage recording, and node `allow-always` persistence saving request-local approval snapshots without freshness merging.

## Solution Assessment

Yes. The fix belongs in the core exec approvals persistence boundary; a backup skill is only mitigation, and a lock-only replacement write is insufficient unless writes also reload/merge or validate freshness.
