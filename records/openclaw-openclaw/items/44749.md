## Summary

Keep open: current main and the latest release still save allow-always and allowlist-usage updates by mutating a request-local approvals snapshot and replacing the whole exec-approvals.json file, so concurrent approvals can still clobber earlier entries. Direct fix attempts are closed unmerged, and the broader open stale-write PR is still not a clean canonical fix for this issue.

## What This Changes

The issue reports concurrent allow-always exec approvals overwriting each other in exec-approvals.json and silently dropping earlier allowlist entries.

## Best Possible Solution

Land a reviewed core exec-approvals persistence fix that reloads and merges under one lock/freshness contract for gateway and node allow-always and usage writes, with regression coverage for concurrent approvals and admin-revocation races.

## Reproduction Assessment

Yes, source-reproducible: current main still persists allow-always and usage updates by saving the request-local approvals file object, matching the reporter's concurrent stale-snapshot race. I did not run a live concurrent Telegram approval flow in this read-only review.

## Solution Assessment

Yes, the right solution is a core exec approvals persistence fix with a fresh/locked merge or CAS-style guard across gateway and node writers. The keepmyclaw backup suggestion in the discussion can help recovery but does not prevent the internal stale-write race.
