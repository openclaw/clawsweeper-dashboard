## Summary

The side-panel idea is well demonstrated and the previous branch-specific findings are gone, but the current design does not bind agent browser actions to the tab that owns the conversation: it sends only page-controlled URL/title text and relies on the model to rediscover the intended tab among all shared tabs. That makes wrong-tab actions possible in the exact multi-tab workflow the feature promises to solve, so the PR needs a browser/gateway owner decision and a trusted targeting seam before merge.

## What This Changes

Adds a Chrome extension side-panel chat client with per-tab gateway sessions, device identity, popup entry point, documentation, and focused helper tests.

## Best Possible Solution

Keep the side-panel UI and least-privilege operator scopes, but pass a stable shared-tab target through a typed browser/gateway-owned context that the browser tool enforces, add safe in-product or pairing-time origin authorization, and prove two simultaneously shared lookalike tabs cannot cross-target.
