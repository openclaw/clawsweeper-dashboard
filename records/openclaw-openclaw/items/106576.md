## Summary

The report identifies a current locale-dependent error branch: sandbox stat recognizes a missing path by matching one English stderr sentence, so localized environments can turn the expected null result into an exception. This is a narrow existing-behavior bug worth fixing.

Likely related people: `steipete` appears to have introduced and substantially refactored the sandbox filesystem bridge; `tasaankaeris` is connected through later sandbox filesystem work. Routing confidence is medium.

## What This Changes

Make sandbox file-stat handling return null for absent paths without depending on localized shell output.

## Best Possible Solution

Use a locale-independent, machine-readable stat protocol—such as a fixed missing-path sentinel plus numeric mode/type data—and add regression coverage proving localized stderr cannot change ENOENT semantics while other failures still throw.

Yes at source level: return a failing stat result whose stderr contains a localized ENOENT diagnostic, and the current English substring check falls through to an exception. A live localized-container run was not established during this read-only review.
