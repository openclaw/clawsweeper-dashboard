## Summary

The observability goal is valid, but the breaker warning is attached to the repeated open-state skip rather than the trip transition, so it can warn on every prompt during cooldown. The linked issue should remain open with this PR while that bounded logging defect and missing real-runtime proof are addressed.

## What This Changes

The PR changes active-memory circuit-breaker skips, counted recall timeouts, and prompt-build deadline aborts to emit unconditional warning logs and updates the breaker test to expect warning severity.

## Best Possible Solution

Emit one warning when the breaker transitions open, or explicitly bound it to one warning per trip/cooldown, while retaining accurate timeout/deadline diagnostics and proving the final warning rate with redacted live Gateway logs.

## Reproduction Assessment

Yes, from source with high confidence: the breaker remains open until cooldown expiry and its early-return branch runs for every recall attempt, so the proposed repeated warning path is directly reproducible. The reporter's original hours-long production degradation was not independently run in this review.

## Solution Assessment

No, not in its current placement. Raising degradation to warning level is appropriate, but the breaker warning should be tied to the state transition or rate-limited rather than emitted for every skipped recall.
