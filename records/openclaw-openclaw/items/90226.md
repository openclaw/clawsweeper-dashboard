## What This Changes

This PR adds a durable `sessionClosedAt` marker for closed thread sessions, wires it through session freshness and rollover paths, preserves the shipped daily reset default, and updates docs and regression tests.

## Best Possible Solution

Land this only after maintainers explicitly accept `sessionClosedAt` as the durable closed-thread lifecycle marker, with the shipped daily default preserved and the regression coverage retained.

## Reproduction Assessment

Yes, at source level. Current main marks archived Discord thread sessions by zeroing `updatedAt`, while idle/no-expiry freshness has no idle deadline and no closed marker, so a later message can reuse the closed session.

## Solution Assessment

Yes, this is the best maintainable fix shape I found: carry an explicit closed marker through the shared freshness contract instead of relying only on `updatedAt` side effects, while preserving the shipped daily default for unconfigured threads.
