## Summary

Keep open: current main still has gh-issues workers carry issue body text into spawned tasks, while the durable content-boundary and child capability pieces remain unmerged or only partially covered by related work.

## What This Changes

The issue asks OpenClaw to stop passing untrusted GitHub issue and review-comment text into gh-issues sub-agent prompts without a runtime content boundary or isolation strategy.

## Best Possible Solution

Keep this as the canonical gh-issues hardening tracker, then land a maintainer-approved content-boundary design for issue/review text and pair unattended workers with sandbox or per-spawn least-privilege controls where needed.
