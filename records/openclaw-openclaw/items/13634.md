## Summary

Keep open: current main handles workspace bootstrap through shared Project Context, but Slack still lacks the requested account/global prompt contract. Related merged work deliberately kept Slack prompt behavior scoped to existing per-channel config, so the remaining request needs maintainer product/config approval.

## What This Changes

The issue asks for Slack workspace context injection plus a Slack-wide `systemPrompt` setting so operators do not repeat file-backed prompts for every room.

## Best Possible Solution

Keep shared Project Context as the workspace-file mechanism, then define a maintainer-approved Slack global/account prompt contract with explicit precedence across rooms, DMs, MPIMs, and slash commands.

## Reproduction Assessment

Yes, at source level. Current main shows workspace files are injected through shared Project Context, while Slack account/global prompt config is absent from the account type, strict schema, and runtime prompt resolution paths.

## Solution Assessment

Unclear until maintainers approve the public Slack config semantics. Slack-specific workspace-file injection would duplicate shared Project Context; the maintainable remaining path is a documented global prompt contract with explicit precedence.
