## Summary

Keep open. Current main and v2026.6.11 already cover workspace-file injection through shared Project Context, but Slack still lacks a maintainer-approved account/global `systemPrompt` config contract and runtime inheritance path.

## What This Changes

The issue requests Slack workspace-file context parity with Telegram plus a global Slack `systemPrompt` that applies across Slack rooms unless overridden.

## Best Possible Solution

Keep shared Project Context as the workspace-file mechanism, then define a maintainer-approved Slack account/global prompt contract with explicit precedence across rooms, DMs, MPIMs, wildcard channel defaults, and slash commands.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 load workspace files through shared Project Context, while Slack account/global prompt config is absent from the account type, strict schema, docs, and runtime prompt resolver paths.

## Solution Assessment

Unclear until maintainers approve the public config semantics. Slack-specific workspace-file injection would duplicate shared Project Context; the maintainable remaining path is a documented global prompt contract with explicit precedence.
