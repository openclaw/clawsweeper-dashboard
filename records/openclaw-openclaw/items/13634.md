## Summary

Keep open. Current main and the latest release cover the workspace-file part through shared Project Context, but the requested Slack account/global `systemPrompt` surface is still absent; a prior merged Slack prompt PR also explicitly avoided exposing new global/DM prompt config.

## What This Changes

The issue requests Slack workspace context injection parity and a Slack-wide `systemPrompt` setting that applies across Slack rooms unless overridden.

## Best Possible Solution

Keep shared Project Context as the workspace-file mechanism; maintainers should either explicitly close the global Slack prompt direction as not planned, or approve one documented account/global inheritance contract with schema, docs, precedence tests, and normal/slash path coverage.

## Reproduction Assessment

Yes for source reproducibility: current main shows shared workspace bootstrap files are injected, while Slack account/global `systemPrompt` is missing from the type, strict schema, resolver, and prompt assembly path. I did not run a live Slack gateway repro because this is a config-surface feature request, not a current-main runtime regression.

## Solution Assessment

Unclear until maintainers confirm product direction. An account/global Slack prompt inheritance path is plausible, but existing per-room wildcard config and the open raw-text include work do not solve full global Slack prompt inheritance.
