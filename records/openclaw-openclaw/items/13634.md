## Summary

Keep open. Current main and the latest release already cover workspace bootstrap files through shared Project Context, but the requested Slack account/global `systemPrompt` contract is still absent; related PRs either intentionally avoided that surface or only partially overlap with file-backed prompt ergonomics.

## What This Changes

The issue asks for Slack-wide prompt inheritance and workspace file context parity so Slack sessions do not require repeating `systemPrompt` on every configured channel.

## Best Possible Solution

Keep shared Project Context as the workspace-file mechanism, then make a maintainer decision on whether Slack should gain a documented account/global prompt contract or instead document wildcard per-channel config plus raw-text includes as the supported path.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 inject workspace files through shared Project Context, while Slack account/global prompt config is absent from the account type, strict schema, resolver, normal-message path, and slash-command path.

## Solution Assessment

Unclear until maintainers approve the public Slack config semantics. Slack-specific workspace-file injection would duplicate shared Project Context; the maintainable remaining path is a documented prompt inheritance contract or an explicit decision to use existing wildcard/file-include alternatives.
