Keep open. ## What This Changes

The issue requests Slack parity with Telegram by adding a Slack-wide `systemPrompt` and automatic workspace file context injection for Slack sessions.

## Best Possible Solution

Keep shared Project Context as the workspace-file mechanism, then define a maintainer-approved Slack account/global prompt contract with explicit precedence across rooms, DMs, MPIMs, and slash commands.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 show workspace files are injected through shared Project Context, while Slack account/global prompt config is absent from the account type, strict schema, and runtime prompt resolution paths.

## Solution Assessment

Unclear until maintainers approve the public Slack config semantics. Slack-specific workspace-file injection would duplicate shared Project Context; the maintainable remaining path is a documented global prompt contract with explicit precedence.
