## Summary

Keep open. Current main and the latest release already cover workspace-file injection through shared Project Context, but the requested Slack account/global `systemPrompt` surface still has no typed config/schema contract or runtime inheritance path.

## What This Changes

Request to add Slack-wide system prompt inheritance and workspace context parity so Slack sessions can use shared prompt files without repeating `systemPrompt` in every room entry.

## Best Possible Solution

Keep shared Project Context as the workspace-file mechanism; if maintainers approve the config direction, add documented Slack account/global prompt inheritance through typed config, strict schema, account merge, room resolution, normal-message handling, slash handling, and focused precedence tests.

## Reproduction Assessment

Yes for source reproducibility: current main shows shared workspace bootstrap files are injected, and Slack account/global `systemPrompt` is missing from the type, strict schema, resolver, and prompt assembly path. I did not run a live Slack gateway repro because this is a config-surface feature request, not a current-main runtime regression.

## Solution Assessment

Unclear until maintainers confirm product direction. An account-level Slack prompt inheritance path may be the right fix, but the existing per-channel `*` wildcard only covers room entries and the related `$includeText` work only covers file-backed string ergonomics, not global Slack prompt inheritance.
