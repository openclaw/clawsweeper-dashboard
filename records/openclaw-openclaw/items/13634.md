## Summary

Keep open. Current main and v2026.6.11 already cover workspace-file injection through shared Project Context, but Slack still lacks an approved account/global `systemPrompt` config surface and runtime inheritance path; prior Slack prompt work explicitly avoided adding that public API shape.

## What This Changes

The issue requests Slack-wide prompt inheritance plus workspace context parity so operators do not need to repeat the same file-backed `systemPrompt` for every Slack room.

## Best Possible Solution

Keep shared Project Context as the workspace-file mechanism, then make a maintainer product decision on whether Slack should get an account/global prompt contract or stay with per-channel/wildcard prompts plus raw-text include ergonomics.
