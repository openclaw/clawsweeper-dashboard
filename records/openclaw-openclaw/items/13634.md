## Summary

Keep open: current main and v2026.6.11 cover workspace bootstrap files through shared Project Context, but Slack still lacks a maintainer-approved account/global prompt contract that applies consistently across rooms, DMs, MPIM/group DMs, and slash commands.

## What This Changes

The issue requests Slack workspace-file context parity plus a Slack-wide `systemPrompt` so operators do not have to repeat prompt config for every Slack conversation.

## Best Possible Solution

Keep shared Project Context as the workspace-file mechanism, then add a maintainer-approved Slack prompt inheritance contract with explicit precedence across account/global, room, DM, MPIM/group DM, and slash-command paths.

## Reproduction Assessment

Yes, at source level. Current main shows workspace files are injected through shared Project Context, while Slack account/global prompt config is absent from the account type, strict schema, normal-message path, and slash-command path.

## Solution Assessment

Unclear until maintainers approve the public config semantics. Slack-specific workspace-file injection would duplicate shared Project Context; the maintainable remaining path is a documented Slack prompt inheritance contract with explicit precedence.
