## Summary

Keep open: current main and the latest release already load workspace bootstrap files through shared Project Context, but Slack still has no account/global `systemPrompt` contract. The remaining request is a real Slack config/product decision, while related work only covers adjacent prompt formatting or raw-text include ergonomics.

## What This Changes

The issue requests Slack-wide workspace file context and a global Slack `systemPrompt` so operators do not repeat the same prompt on every Slack room.

## Best Possible Solution

Keep shared Project Context as the workspace-file mechanism, then decide and document a Slack account/global prompt inheritance contract with explicit precedence across rooms, DMs, MPIM, and slash commands.

## Reproduction Assessment

Yes, at source level. Current main shows workspace files are injected through shared Project Context, while Slack account/global prompt config is absent from the account type, strict schema, normal-message path, and slash-command path.

## Solution Assessment

No for Slack-specific workspace-file injection, because shared Project Context already handles that part. The maintainable remaining path is a maintainer-approved Slack global prompt inheritance contract, optionally coordinated with the separate raw-text include work for file-backed prompt ergonomics.
