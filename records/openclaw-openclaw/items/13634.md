## Summary

Keep open. Current main and the latest release cover the workspace-file half through shared Project Context, but Slack still lacks the requested account/global `systemPrompt` contract and the remaining choice is a public config/product decision.

## What This Changes

The issue requests Slack-wide `systemPrompt` inheritance and Slack workspace context-file injection parity with Telegram.

## Best Possible Solution

Keep shared Project Context as the workspace-file mechanism, then either add a maintainer-approved Slack account/global prompt contract with explicit precedence or document `channels.slack.channels["*"].systemPrompt` as the supported Slack-wide prompt pattern.

## Reproduction Assessment

Yes, at source level. Current main shows workspace files are injected through shared Project Context, while Slack account/global prompt config is absent from the account type, strict schema, normal-message path, and slash-command path.

## Solution Assessment

Unclear until maintainers approve the public config semantics. Slack-specific workspace-file injection would duplicate shared Project Context; the maintainable remaining path is a documented Slack global prompt contract with explicit precedence or a documented wildcard-channel prompt pattern.
