## Summary

Keep open: current main and v2026.6.11 already cover workspace bootstrap files through shared Project Context and have a per-room wildcard prompt workaround, but Slack still lacks the requested account/global `channels.slack.systemPrompt` contract and maintainer-approved precedence across Slack surfaces.

## What This Changes

The issue requests Slack parity with Telegram by adding a Slack-wide `systemPrompt` field and automatic workspace file context injection for Slack sessions.

## Best Possible Solution

Keep shared Project Context as the workspace-file mechanism, then make a maintainer-approved decision on a Slack account/global prompt contract with documented precedence and coverage for rooms, DMs, MPIMs, and slash commands.

## Reproduction Assessment

Yes, at source level. Current main shows workspace files are injected through shared Project Context, while Slack account/global prompt config is absent from the account type, strict schema, normal-message path, and slash-command path.

## Solution Assessment

Unclear until maintainers approve the public config semantics. Slack-specific workspace-file injection would duplicate shared Project Context; the maintainable remaining path is a documented Slack global prompt contract if maintainers want it beyond the existing per-room wildcard.
