## Summary

Keep open: current main and v2026.6.11 already inject workspace bootstrap files through shared Project Context, and Slack has a per-room wildcard prompt fallback, but the requested `channels.slack.systemPrompt` account/global contract is still absent and Slack DMs/MPIMs do not get that per-room prompt path.

## What This Changes

Request Slack-wide prompt inheritance and workspace-file context parity so operators do not have to repeat prompt files on every Slack conversation.

## Best Possible Solution

Keep shared Project Context as the workspace-file mechanism, document or preserve the existing room wildcard where appropriate, and add a maintainer-approved Slack account/global prompt contract only with explicit precedence across rooms, DMs, MPIMs, and slash commands.

## Reproduction Assessment

Yes, at source level. Current main shows shared workspace files are injected, room channels can use a `channels.slack.channels["*"]` fallback, but the requested `channels.slack.systemPrompt` field is absent and DMs/MPIMs do not consume the room channel prompt path.

## Solution Assessment

Unclear until maintainers decide the public Slack config shape. A Slack-specific workspace-file loader would duplicate shared Project Context; the maintainable remaining choice is either document the existing room wildcard or add an explicit account/global prompt contract with clear precedence.
