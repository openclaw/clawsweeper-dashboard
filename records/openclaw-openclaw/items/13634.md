## Summary

Keep open. Current main and the latest release already handle the workspace-file injection half through shared Project Context, but Slack still lacks a documented account/global prompt contract that covers rooms, DMs, MPIM/group DMs, and slash-command paths; the existing room wildcard fallback is not the requested public config surface and does not cover the whole Slack conversation surface.

## What This Changes

The issue requests Slack-wide prompt inheritance and Slack workspace context injection parity with Telegram.

## Best Possible Solution

Keep shared Project Context as the workspace-file mechanism, then have maintainers choose and document Slack prompt inheritance semantics across account, wildcard room, DM, MPIM, and slash-command paths with explicit precedence.

## Reproduction Assessment

Yes, at source level. Current main shows shared workspace files are injected through Project Context, while Slack account/global prompt config is absent from the account type, strict schema, normal-message path, and slash-command path.

## Solution Assessment

Unclear until maintainers approve the public config semantics. Slack-specific workspace-file injection would duplicate shared Project Context; the maintainable remaining path is a documented Slack prompt inheritance contract rather than an ad hoc extra injection path.
