## Summary

Keep open: current main and the latest release still parse TLS gateway deep links without an explicit port through the old 18789 default, while this focused PR aligns that path with the existing setup-code/raw-URL 443 default and adds targeted parser coverage. I found no blocking patch findings; https://github.com/openclaw/openclaw/pull/100258 overlaps with the same fix but is still an open broad batch, not a terminal supersession for this active narrow PR.

## What This Changes

The PR changes iOS/OpenClawKit gateway deep-link parsing to use port 443 for omitted TLS ports, routes pending gateway setup requests through canonical Settings views, refreshes native i18n line inventory, and removes an unused terminal identity overload.

## Best Possible Solution

Land the narrow iOS/OpenClawKit fix, or fold it into the overlapping maintainer batch if that lands first, while preserving explicit-port behavior and canonical Settings ownership coverage.
