## Summary

The patch is mechanically correct and strongly proven, but it changes a security boundary: OpenRouter music generation would honor an explicit private-network opt-in instead of always denying it. Current docs and the shared resolver support that opt-in, while the sibling OpenRouter video path still overrides it, so the PR needs provider-policy owner confirmation before merge.

## What This Changes

The PR forwards sanitized OpenRouter provider request policy into music-generation HTTP resolution, removes the music path’s hard-coded private-network denial, and adds unit plus local HTTP transport coverage.

## Best Possible Solution

Use the shared sanitized policy path for headers, proxy, and TLS, and merge private-network opt-in behavior only after the OpenRouter provider-policy owner confirms that music generation should honor the documented setting despite the stricter video sibling.
