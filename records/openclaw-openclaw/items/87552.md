## Summary

Keep this PR open, but not merge-ready: the recoverable-pending behavior has useful proof and no security concern, yet the current patch leaves no-op unavailable-reconciler deferrals behind the shared replay pacer, which can delay later replayable deliveries.

## What This Changes

The PR changes outbound delivery recovery so ambiguous post-send queue entries without adapter reconciliation stay pending with non-budget deferral/backoff while completed reconciliation attempts still consume retry budget.

## Best Possible Solution

Keep the recoverable-pending mitigation only if unavailable-reconciler rows are classified before replay pacing, while preserving no-blind-replay, no-budget deferral, and retry-budget accounting for completed reconciliation attempts.
