## Summary

Keep open for maintainer review: current main still terminalizes capped ambiguous sends before later reconciliation, while this technically sound and well-proven PR intentionally changes that durable message-delivery policy. The remaining blocker is owner acceptance of retaining unreconcilable rows pending rather than a patch defect.

## What This Changes

The PR keeps ambiguous outbound deliveries pending without spending retry budget when no reconciler exists, lets later reconciliation run before terminal handling, and updates recovery tests and Discord troubleshooting guidance.

## Best Possible Solution

Adopt an explicit owner-approved policy where ambiguous sends are never blindly replayed, unavailable-reconciler rows remain recoverable with durable backoff and visible operator resolution, and a later reconciler runs before any terminal retry-limit decision.
