## Summary

Keep open for maintainer review: current main still fails or terminalizes ambiguous outbound rows without reconciliation, while this PR intentionally changes that policy to pending deferral with backoff. The patch appears technically sound, but maintainers need to accept the compatibility and message-delivery tradeoff before merge.

## What This Changes

The PR changes outbound delivery recovery so `send_attempt_started` and `unknown_after_send` queue entries without reconciliation stay pending with non-budget backoff, adds focused recovery/storage/integration tests, and updates Discord troubleshooting docs.

## Best Possible Solution

Land this only as an interim duplicate-prevention mitigation if maintainers accept the pending ambiguous-row policy, while keeping the durable delivery ledger and surfacing design tracked under https://github.com/openclaw/openclaw/issues/87544.
