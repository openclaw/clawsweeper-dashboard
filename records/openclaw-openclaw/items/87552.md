## Summary

Keep open. Current main has a broader outbound recovery rewrite from https://github.com/openclaw/openclaw/pull/99600, but it still does not implement this PR's central no-budget pending deferral for ambiguous no-adapter rows; the PR remains meaningful but now needs maintainer policy review and a rebase against the newer recovery code.

## What This Changes

The PR changes outbound delivery recovery so ambiguous `send_attempt_started` and `unknown_after_send` entries stay pending with backoff, rather than being blindly replayed or terminalized when reconciliation is unavailable.

## Best Possible Solution

Rebase the no-budget deferral onto the post-https://github.com/openclaw/openclaw/pull/99600 recovery model only if maintainers accept pending ambiguous no-adapter rows as the interim policy while the full delivery ledger remains tracked separately.

## Reproduction Assessment

Yes, at source level. Persist a pending outbound entry with `recoveryState` set to `send_attempt_started` or `unknown_after_send` and no reconciliation-capable adapter; current main refuses replay but moves the entry to failed instead of keeping a non-budget pending deferral.

## Solution Assessment

The PR is an acceptable narrow mitigation, but not the final delivery-consistency solution. The safest path is to reapply the deferral policy on top of current main's receipt-aware recovery rewrite only after maintainers accept the pending-row tradeoff.
