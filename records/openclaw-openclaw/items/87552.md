## Summary

Keep open. The PR has useful proof and a plausible mitigation, but the current patch leaves no-adapter deferrals behind the replay pacer, so old unreconcilable rows can consume startup/reconnect recovery budget before newer replayable entries are reached; the pending-versus-failed behavior also still needs maintainer acceptance.

## What This Changes

The branch changes outbound recovery so ambiguous send states without reconciliation-capable adapters remain pending with non-budget deferral/backoff, updates null reconciliation handling, tests, and Discord troubleshooting docs.

## Best Possible Solution

Move unavailable-reconciler rows onto a no-op deferral path that records backoff without consuming replay pacing/deadline, then have maintainers decide whether the recoverable-pending behavior is acceptable under https://github.com/openclaw/openclaw/issues/87544.
