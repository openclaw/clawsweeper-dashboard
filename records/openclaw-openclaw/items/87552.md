## What This Changes

The PR changes outbound delivery recovery so ambiguous `send_attempt_started`/`unknown_after_send` rows without reconciliation-capable adapters stay pending with backoff instead of moving to failed or spending retry budget.

## Best Possible Solution

Move the unavailable-reconciler classification before `recoveryReplayPacer.wait` or skip the pacer for that no-op deferral branch, preserve the PR's backoff and retry-budget behavior, then merge only if maintainers accept the pending-state tradeoff.
