## Summary

Keep this PR open for an outbound-recovery owner decision. The patch is technically coherent, the prior review findings are resolved, and the supplied proof demonstrates the central no-blind-replay behavior, but merging it intentionally changes ambiguous-delivery terminal policy from retry-capped failure to durable pending retention when no reconciler exists. Current main still terminalizes the no-reconciler path, so the work remains necessary rather than superseded. citeturn13view3turn18view0

## What This Changes

Keeps ambiguous outbound queue entries pending without spending retry budget when reconciliation is unavailable, reconciles before max-retry terminal handling, and updates recovery tests and Discord troubleshooting guidance.

## Best Possible Solution

Represent ambiguous no-reconciler deliveries as a durable, backoff-controlled awaiting-reconciliation state with no blind replay, explicit health or operator visibility, and retry-capped terminal handling only after a real reconciliation attempt; keep the broader receipt and UI work canonical in https://github.com/openclaw/openclaw/issues/87544.
