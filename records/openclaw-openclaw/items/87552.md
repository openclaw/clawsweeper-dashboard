## Summary

The PR is still useful and not implemented on current main, but the current head has a blocking pacing regression: unavailable-reconciler entries now remain pending and every eligible pass still consumes the shared replay pacer before discovering that no send or reconciliation will run.

## What This Changes

The PR keeps ambiguous outbound delivery entries pending with backoff when no reconciliation-capable adapter is available, preserves retry budget for that path, counts adapter-null reconciliation attempts, and updates focused outbound recovery tests plus Discord troubleshooting docs.

## Best Possible Solution
