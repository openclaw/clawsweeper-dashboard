## Summary

Current main still moves ambiguous no-adapter outbound rows to failed, while this PR keeps them pending with backoff, so the branch is not obsolete or superseded. The remaining decision is whether maintainers want that pending-row policy as the interim behavior while the broader delivery-ledger work remains open.

## What This Changes

The branch changes outbound delivery recovery so `send_attempt_started` and `unknown_after_send` rows stay pending with backoff when adapter reconciliation is unavailable, while preserving retry-budget accounting for real reconciliation attempts.

## Best Possible Solution

Land the no-budget pending deferral only if maintainers explicitly accept it as the interim policy on top of the current receipt-aware recovery model; otherwise keep the current terminal policy and leave the broader delivery-ledger work in the canonical issue.

## Reproduction Assessment

## Solution Assessment

Unclear pending maintainer policy. The PR is a narrow and coherent mitigation, but deciding pending versus terminal handling for no-adapter ambiguous rows is a product/operator tradeoff rather than a purely mechanical bug fix.
