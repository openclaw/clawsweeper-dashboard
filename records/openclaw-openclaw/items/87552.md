## Summary

Keep this PR open: it is a useful, proof-backed outbound recovery mitigation, but current head still has a blocking pacing defect where no-op unavailable-reconciler deferrals consume replay pacing and recovery deadline before any send or reconciliation can occur.

## What This Changes

## Best Possible Solution

Move unavailable-reconciler deferral classification ahead of replay pacing or make that branch skip the pacer, keep the retry-budget/backoff guarantees, then merge only if maintainers accept the pending-state tradeoff.
