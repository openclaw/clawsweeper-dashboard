## Summary

Keep this PR open for maintainer review: the latest head addresses the earlier concrete review defects, but it intentionally changes ambiguous outbound delivery recovery from terminal failure/retry-budget consumption into pending backoff, which is a compatibility and message-delivery policy choice.

## What This Changes

The PR changes outbound delivery recovery so ambiguous `send_attempt_started` and `unknown_after_send` queue rows stay pending with backoff when no reconciliation-capable adapter is available, adds focused tests, and updates Discord troubleshooting docs.

## Best Possible Solution

Land this as a narrow mitigation only if maintainers accept the pending ambiguous-row policy, while keeping the broader delivery ledger and UI/API surfacing work tracked under https://github.com/openclaw/openclaw/issues/87544.

## Reproduction Assessment

Yes. Source inspection and the PR proof show the path: enqueue an ambiguous `send_attempt_started` or `unknown_after_send` entry with no reconciliation-capable adapter, then run startup or reconnect recovery and observe that delivery is not replayed while the row remains pending.

## Solution Assessment

Yes for the narrow mitigation: it preserves no-blind-replay, distinguishes unavailable reconciliation from null adapter results, and records a non-budget backoff timestamp. It is not the full delivery consistency solution, so maintainer acceptance of the interim pending-row policy is still needed.
