## Summary

Keep open: the latest head fixes the prior no-budget deferral backoff defect and the patch looks correct, but it intentionally changes delivery/upgrade policy for ambiguous rows and needs maintainer acceptance before merge.

## What This Changes

This PR changes outbound delivery recovery so ambiguous send states stay pending with backoff when adapter reconciliation is unavailable, with focused recovery/storage tests and Discord troubleshooting docs updated.

## Best Possible Solution

Land this as a narrow mitigation only if maintainers accept the pending ambiguous-row policy, and keep the broader delivery ledger and UI/API surfacing work tracked under https://github.com/openclaw/openclaw/issues/87544.

## Reproduction Assessment

Yes. Source inspection and the PR proof show the path: enqueue an ambiguous send_attempt_started or unknown_after_send entry with no reconciliation-capable adapter, then run startup or reconnect recovery and observe that delivery is not replayed while the row remains pending.

## Solution Assessment

Yes for the narrow mitigation: it preserves no-blind-replay, distinguishes unavailable reconciliation from null adapter results, and now records a non-budget backoff timestamp. It is not the full delivery consistency solution, so maintainer acceptance of the interim pending-row policy is still needed.
