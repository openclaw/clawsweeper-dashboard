## Summary

The patch appears technically correct and proof-positive, but it intentionally replaces bounded dead-letter behavior with potentially indefinite pending state for ambiguous deliveries that no current adapter can reconcile. That retention and fallback policy needs explicit maintainer approval before merge; current main still terminalizes these entries rather than preserving them indefinitely. ([raw.githubusercontent.com](https://raw.githubusercontent.com/openclaw/openclaw/main/src/infra/outbound/delivery-queue-recovery.ts))

## What This Changes

The PR keeps ambiguous outbound deliveries pending without consuming retry budget when reconciliation is unavailable, permits later reconciliation before terminal handling, and updates recovery tests and Discord troubleshooting guidance.

## Best Possible Solution

Approve one canonical ambiguous-send policy that preserves no-blind-replay and later reconciliation while also defining retention, health visibility, and an operator recovery path for entries that remain non-reconcilable; then land or narrow this branch to that contract.
