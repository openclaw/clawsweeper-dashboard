## Summary

Keep this PR open, but it is not merge-ready: the core recoverability idea is useful, yet the new unavailable-reconciler deferral path still consumes replay pacing before doing no delivery or reconciliation work, which can delay newer recoverable entries.

## What This Changes

The branch changes outbound delivery recovery to keep ambiguous post-send queue entries pending when no reconciliation-capable adapter is available, adds a non-budget deferral helper, updates recovery/storage/reconnect tests, and adjusts Discord troubleshooting docs.

## Best Possible Solution

Land the narrow no-blind-replay mitigation only after unavailable-reconciler rows are deferred without consuming replay pacing or recovery deadline, exact-head validation is green, and a maintainer accepts the pending-versus-failed queue-state tradeoff while the broader ledger remains tracked by https://github.com/openclaw/openclaw/issues/87544.
