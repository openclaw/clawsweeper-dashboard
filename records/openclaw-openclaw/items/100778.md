## Summary

Keep open: current `main` still appears to hard-fail some preflight compaction failures before the agent run starts, and an open linked fix PR now owns the implementation path, so this issue should stay open until that PR lands or is replaced.

## What This Changes

The issue reports that failed preflight memory compaction can turn a chat dispatch error into a terminated session state that leaves the Composer disabled until refresh.

## Best Possible Solution

Land or revise the linked fix so retryable preflight compaction failures do not permanently terminate the Composer, while preserving hard failure behavior for auth, request-shape, guard, and summary failures unless maintainers explicitly choose UI-side recovery.

Options:

- **Skip only retryable failures (recommended):** Treat timeout, 429, and 5xx preflight compaction failures as non-fatal while preserving 400/401/403, guard, request-shape, and broad summary failures as hard errors.
- **Recover in the UI lifecycle:** Keep gateway compaction failures hard but make preflight-originated dispatch errors restore the Composer and show an actionable retry message.
- **Combine gateway and UI guards:** Add narrow retryable gateway skips plus a UI recovery safety net for unexpected preflight dispatch errors.
