## Summary

Keep this issue open: current main and the latest release still reject Feishu/Lark webhook requests without signature headers before challenge handling, and all direct fix candidates found are closed unmerged.

## What This Changes

The issue reports that Feishu/Lark webhook URL verification rejects encrypted challenge requests without signature headers when `encryptKey` is configured.

## Best Possible Solution

Implement a narrow Feishu plugin fix that parses or decrypts only setup-time `url_verification` challenges before normal signature rejection, validates the decrypted verification token, keeps unsigned non-challenge events on the signature-required path, and adds focused e2e/security coverage plus redacted live callback proof.
