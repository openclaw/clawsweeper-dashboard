## Summary

Keep this issue open: current main and the latest release still validate Feishu webhook signatures before URL-verification challenge handling, so unsigned encrypted setup challenges cannot reach `Lark.generateChallenge`. The direct fix PRs are closed unmerged, and the remaining fix changes a webhook authentication boundary that should get maintainer/security review.

## What This Changes

The issue reports that Feishu/Lark webhook URL verification fails because unsigned encrypted `url_verification` challenge requests are rejected with `401 Invalid signature` when `encryptKey` is configured.

## Best Possible Solution

Land a narrow Feishu plugin fix that parses or decrypts only setup-time encrypted `url_verification` challenges before normal signature rejection, validates the decrypted verification token, and preserves strict signature enforcement for ordinary webhook events.
