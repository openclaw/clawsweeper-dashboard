## What This Changes

Prevent a running gateway or recovered task from lazy-importing removed content-hashed bundle chunks after code or plugin files are rotated during an update.

## System Context

OpenClaw updates its core package and managed plugins while a gateway can still be serving requests and recovery work. The gateway, plugin loader, and Codex harness then resolve runtime chunks from the installed tree; a process that retains an older module graph can fail when those hashed chunk files are replaced.

## Architecture Diagram

flowchart TD
  A[Package or plugin update] --> B[Installed files rotate]
  C[Running gateway or recovered turn] --> D[Older loaded module graph]
  B --> E[Old hashed chunks absent]
  D --> F[Lazy runtime import]
  E --> F
  F --> G[Module-not-found failure]
  G --> H[Restart, task failure, or degraded delivery]

## Best Possible Solution

Define and prove one update-lifecycle contract: controlled OpenClaw updates must preserve the active generation until its gateway and in-flight work exit, while unsupported out-of-band swaps must surface an explicit restart-required failure rather than continue serving from a mixed module graph.
