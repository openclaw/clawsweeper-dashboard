## Label Justifications

- `P1`: The reported collision can prevent an ACP child-agent workflow from starting, rather than merely omitting optional session metadata.

## Summary

This PR addresses a credible ACP spawn failure mode: a duplicate optional session label can reject the session patch and prevent the child task from being dispatched. The proposed split between required session creation and best-effort label metadata is directionally appropriate, but the submitted evidence is mock-only and does not yet demonstrate the after-fix behavior in a real ACP/Gateway setup.

## What This Changes

The PR creates an ACP child session without its optional label, then applies the label separately so label collisions do not abort the child-agent dispatch.

## System Context

ACP spawning asks the Gateway to create a child session, records optional metadata and delivery binding, then dispatches the agent task. A rejected session metadata update currently sits on the critical path before the child task can run, so this change makes label persistence non-fatal while preserving task dispatch.

## Architecture Diagram

flowchart LR
  Request[ACP spawn request] --> Create[Create child session]
  Create --> Label[Attempt optional session label]
  Label --> Binding[Store delivery binding]
  Binding --> Dispatch[Dispatch child agent]
  Dispatch --> Result[Deliver child result]

## Best Possible Solution

Keep session creation and task dispatch independent from optional label persistence, retain a focused regression test, and add redacted runtime evidence showing that a forced duplicate label produces a warning while the child task starts and reaches its expected delivery path.
