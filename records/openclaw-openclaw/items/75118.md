## Summary

Keep this PR open because it is still the candidate implementation for the linked caller-context feature, but the merge ref is not safe to land: it weakens existing bundle MCP loopback startup failure handling and can expose loopback-only MCP context variables in a caller-context-only path.

## What This Changes

The PR adds a default-off `mcp.servers.<name>.injectCallerContext` option that injects OpenClaw agent, account, and message-channel headers into opted-in remote bundle MCP servers across CLI, embedded runtime, Codex/Gemini projection, schema/help, docs, and tests.

## Best Possible Solution

Keep the feature default-off and URL-bound, but preserve existing fail-closed loopback startup behavior and limit caller-context-only environments to the three identity variables before maintainers decide whether to land the new contract.

## Reproduction Assessment

Yes for the PR findings: the merge-ref source shows warn-and-continue loopback startup behavior and broad MCP placeholder env construction when caller-context injection is requested. For the feature request itself, a bug reproduction is not applicable because current main lacks the new capability.

## Solution Assessment

No, not as currently patched. The owner URL-bound identity-header design is plausible, but the implementation should not weaken existing loopback startup failure behavior or expose loopback-only session variables for caller-context-only injection.
