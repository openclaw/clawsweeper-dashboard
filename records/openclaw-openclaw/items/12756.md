## Summary

Keep open: current main and v2026.6.11 still omit Telegram from `message read` discovery, action mapping, runtime dispatch, config gating, tests, and docs. The request is valid, but it needs maintainer product/security direction before implementation because Telegram can only support an observed-message/retained-message contract, not arbitrary chat history reads.

## What This Changes

Add Telegram support for the shared `message read` action so agents and CLI users can read recent Telegram group messages with target and limit parameters.

## Best Possible Solution

Implement Telegram `message read` inside the Telegram plugin as an observed-only, bounded, explicitly gated read path with target/topic authorization, clear retention semantics, docs, and focused tests, without adding a secondary `getUpdates` poller.

- **Defer behind passive hook work:** Keep this issue open until the passive history/plugin hook direction lands, then design `message read` on top of that contract.
