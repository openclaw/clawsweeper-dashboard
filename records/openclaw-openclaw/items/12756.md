## Summary

Keep open: current main and v2026.6.11 still omit Telegram from `message read` discovery, mapping, runtime dispatch, config gating, tests, and docs; the closed inbound-store attempt did not merge, and the open passive-observation PR does not provide the explicit read action requested here.

## What This Changes

Request support for `openclaw message read --channel telegram` so agents can read recent Telegram chat messages for monitoring and follow-up workflows.

## Best Possible Solution

Implement Telegram `message read` inside the Telegram plugin with a bounded observed-message store or equivalent cache, no secondary `getUpdates` polling, explicit action/config gating, documented Telegram-only limits, focused unit/contract/docs coverage, and live Telegram proof.
