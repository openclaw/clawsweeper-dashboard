## Summary

Keep open: current main and the latest release still expose the shared `read` action but do not advertise, gate, dispatch, test, or document Telegram `message read`; the remaining work is a security-sensitive Telegram plugin feature that needs maintainer product review before implementation.

## What This Changes

Add Telegram support for the shared `message read` action so agents and the CLI can read recent Telegram chat history or observed messages.

## Best Possible Solution

Define Telegram `message read` in the Telegram plugin with an explicit observed-message contract, privacy/config gate, target/topic semantics, docs, focused tests, and live Telegram proof; avoid a second `getUpdates` poller.

## Reproduction Assessment

Yes. Source inspection is enough: the shared `read` action exists, but Telegram discovery, mapping, runtime aliases, config gating, tests, and docs still omit it on current main.

## Solution Assessment

Unclear until maintainers choose the retained-message contract. The correct layer is the Telegram plugin, but the implementation must first settle privacy, retention, and observed-history semantics instead of copying Discord/Slack behavior blindly.
