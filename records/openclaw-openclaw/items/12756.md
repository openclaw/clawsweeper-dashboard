## What This Changes

The issue requests adding Telegram support for the shared `openclaw message read` action so agents can read recent Telegram group messages.

## Best Possible Solution

Define Telegram `message read` inside the Telegram plugin with an explicit observed-message retention contract, privacy/config gate, target/topic semantics, docs, focused tests, and live Telegram proof.

## Reproduction Assessment

Yes. Source inspection is enough: the shared `read` action exists, but Telegram discovery, mapping, runtime dispatch, config gating, tests, and docs still omit it on current main and v2026.6.11.

## Solution Assessment

Unclear until maintainers choose the retained-message contract. The Telegram plugin is the right owner boundary, but exposing observed-message cache/history as a user-facing read action needs explicit privacy, authorization, and scope decisions first.
