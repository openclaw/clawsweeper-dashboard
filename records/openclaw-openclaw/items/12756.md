## Summary

Keep open: current main and the latest release still omit Telegram from `message read` discovery, mapping, runtime dispatch, config gating, tests, and docs. The remaining work is valid but needs maintainer product/security direction because Telegram can only support observed-message semantics and would expose retained chat content.

## What This Changes

Request support for Telegram `message read` so agents and CLI users can read recent Telegram group messages for monitoring workflows.

## Best Possible Solution

Define Telegram `message read` inside the Telegram plugin with an explicit observed-message contract, privacy/config gate, target/topic authorization, docs, focused tests, and no secondary `getUpdates` poller.
