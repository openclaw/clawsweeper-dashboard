## Summary

Keep open: current main and the latest release still omit Telegram from `message read` discovery, mapping, runtime dispatch, config gating, tests, and docs. The remaining work is valid but needs maintainer product/security direction because Telegram reads would expose retained, observed chat content rather than arbitrary Bot API history.

## What This Changes

Add Telegram support for the shared `openclaw message read` action so agents can query recent Telegram chat messages.

## Best Possible Solution

Define Telegram `message read` inside the Telegram plugin with an explicit observed-message contract, privacy/config gate, target/topic authorization, docs, focused tests, and no secondary `getUpdates` poller.
