## Summary

Keep open: current main and the latest release still omit Telegram from `message read` discovery, action mapping, runtime dispatch, config gating, tests, and docs. The gap is source-reproducible, but implementing it safely needs maintainer product/security direction for observed-message retention and authorization.

## What This Changes

The issue requests Telegram support for the shared `openclaw message read` action so agents can retrieve recent Telegram group messages.

## Best Possible Solution

Implement Telegram `message read` inside the Telegram plugin as an observed-only, bounded, explicitly gated read path with target/topic authorization, clear retention semantics, docs, focused tests, and live Telegram proof.
