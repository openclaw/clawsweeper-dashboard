## Summary

Keep open: current main and v2026.6.11 still have the shared `read` action, but Telegram does not advertise, map, gate, dispatch, test, or document Telegram `message read`; the remaining work is a security-sensitive Telegram plugin feature needing maintainer product review.

## What This Changes

The issue requests adding Telegram support for the shared `openclaw message read` action so agents can inspect recent Telegram group messages.

## Best Possible Solution

Define Telegram `message read` in the Telegram plugin with explicit observed-history semantics, privacy/config gating, target/topic authorization, docs, tests, and live Telegram proof; avoid a second `getUpdates` poller.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: What retained-message contract should Telegram `message read` expose, and should it be default-off behind an explicit action/config gate?

Rationale: The source gap is clear, but exposing Telegram history changes what retained chat content agents and operators can read, and automation cannot choose the privacy, retention, authorization, or default posture safely.

Likely owner: steipete

Owner reason: The latest issue review and adjacent message-tool read-hint work came from this handle, and the remaining question is product/security direction rather than a narrow code owner decision.

Owner confidence: medium

Options:

- **Observed-only gated read (recommended):** Expose only messages already observed by the running gateway/cache, behind explicit Telegram action/config gates and chat/topic authorization.
- **Broader Bot API fetch design:** Design a separate fetch/copy/forward path for specific message IDs or links, with stronger user-visible limits and live proof before implementation.
- **Do not add Telegram read:** Keep Telegram without `message read` and direct users toward plugin/archive surfaces if maintainers reject retained-message exposure.

## Reproduction Assessment

Yes. Source inspection is enough: the shared `read` action exists, but Telegram discovery, mapping, runtime aliases, config gating, tests, and docs still omit it on current main and v2026.6.11.

## Solution Assessment

Unclear until maintainers choose the retained-message contract. The correct layer is the Telegram plugin, but the implementation must first settle privacy, retention, observed-history semantics, and the default action gate.
