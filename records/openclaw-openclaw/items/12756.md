## Summary

Keep open: current main and the latest release still do not expose Telegram `message read`, and the remaining work is a security-sensitive Telegram plugin feature that needs maintainer product review before implementation.

## What This Changes

The issue requests Telegram support for the shared `message read` action so agents can read recent Telegram group messages similarly to Slack and Discord.

## Best Possible Solution

Define Telegram `message read` in the Telegram plugin with an explicit retained-message contract, privacy/config gate, target/topic semantics, docs, focused tests, and live Telegram proof.

## Reproduction Assessment

Yes. Source inspection is enough: the shared `read` action exists, but Telegram discovery, mapping, runtime dispatch, config gating, tests, and docs still omit it on current main and the latest release.

## Solution Assessment

Unclear until maintainers choose the retained-message contract. The best implementation layer is the Telegram plugin, but exposing cached or observed messages as a user-facing read action needs explicit privacy, authorization, and scope decisions first.
