## Summary

Keep open: current main and the latest release still omit Telegram from `message read` discovery, action mapping, runtime dispatch, config gating, tests, and docs. The feature is valid, but it should not be auto-implemented until maintainers decide the observed-message, retention, authorization, and privacy contract.

## What This Changes

Request to add Telegram support to `openclaw message read` so agents can read recent Telegram chat messages for monitoring and notification workflows.

## Best Possible Solution

Implement Telegram `message read` inside the Telegram plugin as an observed-only, bounded, explicitly gated read path with target/topic authorization, clear retention semantics, docs, and focused tests, without adding a secondary `getUpdates` poller.
