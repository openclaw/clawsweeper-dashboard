## Summary

Keep open: current main and v2026.6.11 still omit Telegram from `message read` discovery, mapping, runtime dispatch, config gating, tests, and docs. The remaining work is valid but needs maintainer product/security direction because Telegram reads would be observed-message reads with retained chat-content exposure, not Slack/Discord-style arbitrary history reads.

## What This Changes

Request to add Telegram support for `openclaw message read` so agents and CLI users can retrieve recent Telegram group messages.

## Best Possible Solution

Define Telegram `message read` inside the Telegram plugin as an explicitly gated observed-message read path with bounded retention, target/topic authorization, docs, focused tests, and no secondary `getUpdates` poller.
