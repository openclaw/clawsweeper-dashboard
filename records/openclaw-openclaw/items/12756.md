## Summary

Keep open: current main still lacks Telegram `message read` discovery, action mapping, runtime dispatch, config gating, tests, and docs. The active `inbound_observed` PR is adjacent passive-plugin visibility work, not an implementation of the explicit CLI/tool read action.

## What This Changes

The issue requests adding Telegram support for the shared `openclaw message read` action so agents can read recent Telegram group messages.

## Best Possible Solution

Implement Telegram `message read` inside the Telegram plugin as an observed-only, bounded, explicitly gated read path with target/topic authorization, clear retention semantics, docs, and focused tests, without adding a secondary `getUpdates` poller.
