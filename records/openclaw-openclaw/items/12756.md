## Summary

Keep open: current main and v2026.6.11 still omit Telegram from `message read` discovery, mapping, runtime dispatch, config gating, tests, and docs; this remains the canonical general Telegram read request and needs maintainer product/security direction before implementation.

## What This Changes

The issue requests Telegram support for the shared `openclaw message read` action so agents can read recent Telegram group messages for monitoring workflows.

## Best Possible Solution

Define Telegram `message read` inside the Telegram plugin with an explicit observed-message contract, privacy/config gate, target/topic authorization, docs, focused tests, and no secondary `getUpdates` poller.
