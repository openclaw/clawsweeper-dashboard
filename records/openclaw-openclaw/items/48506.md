## Summary

Keep open: current main and the latest release still expose only raw destination/content plus basic routing metadata on `message_sending`; adding resolved target context remains a public Plugin SDK and security-disclosure decision.

## What This Changes

The issue asks OpenClaw to add optional resolved target context to the Plugin SDK `message_sending` hook so security plugins can distinguish external, cross-context, and same-account outbound messages.

## Best Possible Solution

Approve a narrow optional `message_sending` target-context contract, populate it from canonical outbound resolver and cross-context policy facts, and document/test the disclosure boundary.

- **Use an explicit resolver helper:** Document a supported plugin-side resolver path, accepting that plugins may need lookup cost and may not see the exact runtime-resolved destination for every send.

## Solution Assessment

Unclear until maintainer design review. Optional nested fields are plausible, but the best fix should be an approved narrow SDK contract populated from existing resolver/policy facts, not plugin-side parsing of raw destinations.
