## Summary

Keep open: current main and v2026.6.11 still do not expose resolved target or cross-context facts on `message_sending`, while the remaining work is a public Plugin SDK and security-disclosure design decision rather than cleanup-closeable stale work.

## What This Changes

Request to add optional resolved target and cross-context context fields to the public `message_sending` plugin hook so policy plugins can make outbound delivery decisions without reimplementing target resolution.

## Best Possible Solution

Approve a narrow optional `message_sending` target-context contract, reuse canonical outbound resolver and cross-context policy facts, document the plugin disclosure boundary, and add focused SDK/docs/tests.

## Reproduction Assessment

Yes, for the source-level capability gap: current main and v2026.6.11 can be checked by inspecting the hook type, delivery call site, docs, and tests, which all omit resolved target context. This is not a runtime bug reproduction; it is a missing public API capability.

## Solution Assessment

Unclear until maintainer/security design review. Optional nested fields are plausible, but the best solution should settle the public target-context contract and disclosure boundary while reusing canonical resolver and policy facts.
