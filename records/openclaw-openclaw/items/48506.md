## What This Changes

The issue requests optional resolved target context on the `message_sending` plugin hook so security plugins can reason about outbound destinations without duplicating core target resolution.

## Best Possible Solution

Define a narrow optional `message_sending` target-context contract after maintainer approval, reusing canonical outbound resolver and cross-context policy facts with docs, tests, and an explicit plugin disclosure boundary.

Yes, for the source-level capability gap: the current hook type, delivery call site, public docs, adjacent tests, and latest release tag still omit resolved target context while internal resolver and cross-context policy facts exist elsewhere.
