## Summary

Keep open: current main and the latest release still expose only raw `message_sending` destination/content metadata, while the requested resolved target context remains a public Plugin SDK and security-disclosure design decision.

## What This Changes

Request to add optional resolved target context to `PluginHookMessageSendingEvent` so policy plugins can reason about outbound destination, externality, and cross-context routing without reimplementing target resolution.

## Best Possible Solution

Approve a narrow optional `message_sending` target-context contract, then populate it from canonical outbound resolver and cross-context policy facts with SDK docs and focused hook/delivery tests.
