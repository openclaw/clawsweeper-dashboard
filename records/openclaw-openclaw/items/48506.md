## What This Changes

Request to add optional resolved target context fields to the `message_sending` plugin hook so policy plugins can distinguish internal routing, external destinations, and cross-context sends.

## Best Possible Solution

Define a narrow optional `message_sending` target-context contract after maintainer/security approval, reusing canonical outbound resolver and cross-context policy facts and documenting the plugin disclosure boundary.

## Reproduction Assessment

Yes, for the source-level capability gap: current main and v2026.6.11 can be checked by inspecting the hook type, delivery call site, docs, and internal resolver/policy files. This is not a runtime bug reproduction; it is a missing public API capability.

## Solution Assessment

Unclear until maintainer design review. Optional nested fields are plausible, but the exact target-context contract and sensitive disclosure boundary should be approved before implementation because this is a public Plugin SDK/security surface.
