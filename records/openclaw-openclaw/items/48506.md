## Summary

Keep open: current main and the latest release still expose only raw outbound hook fields, while target resolution and cross-context policy exist internally, so this remains a valid plugin-SDK/product-security design request rather than an implemented or stale item.

## What This Changes

The issue requests optional resolved target context on the `message_sending` plugin hook so policy plugins can distinguish external, cross-context, and target-type routing decisions.

## Best Possible Solution

Design a narrow, stable, least-privilege `message_sending` target-context contract at the plugin SDK boundary and populate it consistently from existing target resolver, session-route, and cross-context policy facts after maintainer security review.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature request. Source inspection does confirm the requested fields are absent today: current `message_sending` events carry raw target/content fields and basic metadata only.

## Solution Assessment

Unclear. A nested optional `targetContext` is plausible, but the best solution needs maintainer agreement on stable field names, least-privilege exposure, and whether this belongs on the event, context, or a narrower target-resolution SDK shape.
