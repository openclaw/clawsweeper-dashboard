## Summary

Keep this open. Current `main` and the latest release still do not expose resolved target or cross-context facts on `message_sending`, and the remaining work is a public Plugin SDK/security-disclosure design decision rather than conservative cleanup.

## What This Changes

Request to add optional resolved target context fields to the `message_sending` plugin hook so security plugins can reason about outbound destinations.

## Best Possible Solution

Define a narrow optional `message_sending` target-context contract after maintainer/security approval, reusing canonical outbound resolver and cross-context policy facts and documenting the plugin disclosure boundary.

## Reproduction Assessment

Yes. Current main shows `PluginHookMessageSendingEvent` lacks resolved target context while resolver and cross-context policy facts exist internally; this is a source-level missing API capability, not a runtime bug reproduction.

## Solution Assessment

Unclear until maintainer design review. Optional nested fields are plausible, but the exact target-context contract and sensitive disclosure boundary should be approved before implementation because this is a public Plugin SDK/security surface.
