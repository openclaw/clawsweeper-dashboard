## Summary

This should stay open: current `main` and v2026.6.11 still expose only raw/basic `message_sending` hook data, while the requested resolved target and cross-context facts remain internal policy/resolver state. The remaining work is a public Plugin SDK and security-disclosure design decision, not conservative cleanup.

## What This Changes

The issue requests optional resolved target context on the `message_sending` plugin hook so security plugins can distinguish internal routing from external or cross-context delivery.

## Best Possible Solution

Define a narrow optional `message_sending` target-context contract after maintainer approval, reusing canonical outbound resolver and cross-context policy facts without adding a second target discovery path.

## Reproduction Assessment

Yes, for the source-level capability gap: current `main` and v2026.6.11 both omit resolved target context from the `message_sending` event while resolver and cross-context facts exist in outbound internals. This is a missing API capability, not a runtime bug reproduction.

## Solution Assessment

Unclear until maintainer design review. Optional nested fields are plausible, but the exact plugin SDK contract and sensitive disclosure boundary should be approved before implementation.
