## Summary

Keep open: current main and v2026.6.11 still expose only raw/basic `message_sending` destination data, while the requested resolved target and cross-context facts remain an undecided public Plugin SDK and security-disclosure contract.

## What This Changes

Add optional resolved target, externality, cross-context, channel, and account context to the `message_sending` hook for plugin DLP, allowlist, compliance, and audit decisions.

## Best Possible Solution

Approve a narrow optional Plugin SDK target-context contract, then plumb canonical resolved-target and cross-context facts into `message_sending` with focused docs and tests.

## Reproduction Assessment

Yes, for the source-level capability gap: current main and v2026.6.11 omit resolved target context from `message_sending` while resolver and cross-context policy facts exist internally. This is a missing public API capability, not a runtime bug reproduction.

## Solution Assessment

Unclear until maintainer/security review. Optional nested fields are plausible, but the exact stable shape and disclosure boundary should be approved before implementation because this is a public Plugin SDK security surface.
