## Summary

Keep open: current main and v2026.6.11 still do not expose resolved target, target kind, externality, same-account, or cross-context facts on `message_sending`; the remaining work is a public Plugin SDK/security-disclosure design decision, not conservative cleanup.

## What This Changes

The issue requests additive resolved target-context fields on the `message_sending` plugin hook so policy plugins can reason about outbound destinations without reimplementing OpenClaw target resolution.

## Best Possible Solution

Define a narrow optional `message_sending` target-context contract after maintainer/security approval, reuse canonical outbound resolver and cross-context policy facts, and document the plugin disclosure boundary.

## Reproduction Assessment

Yes, for the source-level capability gap: current main and v2026.6.11 can be checked by inspecting the hook type, delivery call site, docs, resolver, and outbound policy. This is not a runtime bug reproduction; it is a missing public API capability.

## Solution Assessment

Unclear until maintainer/security design review. Optional nested fields are plausible, but the exact target-context contract and disclosure boundary should be approved before implementation because this is a public Plugin SDK security surface.
