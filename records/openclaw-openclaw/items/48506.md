## Summary

Keep open: current `main` and latest release still expose only raw outbound destination plus basic routing metadata to `message_sending`, while the requested resolved target context remains a public Plugin SDK and security-disclosure design decision.

## What This Changes

The issue requests optional resolved target context on `PluginHookMessageSendingEvent` so policy plugins can distinguish external, cross-context, and channel-specific outbound targets without reimplementing core resolution.

## Best Possible Solution

Define a narrow optional `message_sending` target-context contract after maintainer approval, reusing canonical outbound resolver and cross-context policy facts without adding duplicate target discovery.

## Reproduction Assessment

Yes for source-level verification: current `PluginHookMessageSendingEvent` lacks `targetContext`, while delivery passes only raw `to`, content, reply/thread ids, and basic metadata/context into `runMessageSending`. This is not a runtime failure reproduction because the item is a feature request.

## Solution Assessment

Unclear until maintainer design review. Optional nested fields are plausible, but the exact target-context contract and sensitive disclosure boundary should be approved before implementation because this is a public Plugin SDK/security surface.
