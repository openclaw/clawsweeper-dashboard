## Summary

Keep this open: current main and v2026.6.11 still do not expose resolved target or cross-context facts on `message_sending`, and the remaining work is a public Plugin SDK/security-disclosure design decision rather than conservative cleanup.

## What This Changes

The issue requests optional resolved target context on the `message_sending` plugin hook so security plugins can distinguish internal routing from external or cross-context outbound communication.

## Best Possible Solution

Approve and document a narrow optional outbound target-context contract, populate it from canonical resolver/cross-context facts already carried by delivery, and add focused hook/API tests without introducing duplicate target discovery.

## Reproduction Assessment

Yes, for the source-level capability gap: the current hook type, delivery call site, docs, and v2026.6.11 release tag all omit resolved target context while internal resolver and cross-context policy facts exist elsewhere. This is not a runtime bug reproduction; it is a missing public API capability.

## Solution Assessment

Unclear until maintainer design review. Optional nested fields are plausible, but the exact target-context contract and sensitive disclosure boundary should be approved before implementation because this is a public Plugin SDK/security surface.
