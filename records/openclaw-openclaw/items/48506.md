## Summary

This should stay open: current main and the latest release still do not expose resolved target or cross-context facts on `message_sending`, while the requested change is a public Plugin SDK and security-disclosure design decision rather than cleanup that can be swept closed.

## What This Changes

The issue requests optional resolved outbound target context fields on the `message_sending` plugin hook so policy plugins can distinguish internal, external, and cross-context destinations.

## Best Possible Solution

Define a narrow optional `message_sending` target-context contract after maintainer/security approval, reusing canonical outbound resolver and cross-context policy facts with SDK docs and focused tests.

## Reproduction Assessment

Yes, for the source-level capability gap: the current hook type, delivery call site, docs, and v2026.6.11 release tag omit resolved target context while internal resolver and cross-context policy facts exist elsewhere. This is not a runtime bug reproduction; it is a missing public API capability.

## Solution Assessment

Unclear until maintainer design review. Optional nested fields are plausible, but the exact Plugin SDK contract and sensitive disclosure boundary should be approved before implementation.
