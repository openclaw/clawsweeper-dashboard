## Summary

Keep open: current main and v2026.6.11 still pass only the raw target plus basic metadata to `message_sending`, while resolved target and cross-context policy facts remain internal. This is still a public Plugin SDK and security-disclosure design decision, not conservative cleanup.

## What This Changes

Add optional resolved target and cross-context context to `message_sending` plugin hook events for security policy plugins.

## Best Possible Solution

Define a narrow optional `message_sending` target-context contract populated from canonical outbound resolution and policy facts, with docs and tests, after approving the plugin disclosure boundary.

## Reproduction Assessment

Yes, for the source-level capability gap: current main and v2026.6.11 omit resolved target context from `message_sending` while internal resolver and cross-context policy facts exist elsewhere. This is not a runtime bug reproduction; it is a missing public API capability.

## Solution Assessment

Unclear until maintainer design review. Optional nested fields are plausible, but the exact target-context contract and sensitive disclosure boundary should be approved before implementation because this is a public Plugin SDK/security surface.
