## Summary

Keep open: current main and the latest release still do not expose resolved target or cross-context facts on `message_sending`, and the remaining work is a public Plugin SDK plus security-disclosure design decision rather than conservative cleanup.

## What This Changes

The issue requests optional resolved target context fields on `PluginHookMessageSendingEvent` so policy plugins can distinguish internal routing, external recipients, and cross-context outbound delivery.

## Best Possible Solution

Define a narrow optional `message_sending` target-context contract after maintainer and security approval, reusing canonical outbound resolver and cross-context policy facts and documenting the plugin disclosure boundary.

## Reproduction Assessment

Yes, for the source-level capability gap: current main and v2026.6.11 omit resolved target context from `message_sending` while internal resolver and cross-context policy facts exist elsewhere. This is not a runtime bug reproduction; it is a missing public API capability.

## Solution Assessment

Unclear until maintainer design review. Optional nested fields are plausible, but the exact field shape and sensitive disclosure boundary should be approved before implementation because this is a public Plugin SDK/security surface.
