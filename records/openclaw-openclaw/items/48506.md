## Summary

Keep open: current main and v2026.6.11 still do not expose resolved target, externality, or cross-context facts on the public `message_sending` hook, and the remaining work is a Plugin SDK/security disclosure design decision rather than cleanup-closeable stale work.

## What This Changes

Request to add optional resolved target context to `PluginHookMessageSendingEvent` so policy plugins can distinguish internal routing, external recipients, and cross-context sends.

## Best Possible Solution

Approve a narrow optional `message_sending` target-context contract, then implement it from canonical outbound resolver and cross-context policy facts with SDK docs and focused hook/delivery tests.

## Reproduction Assessment

Yes, for the source-level capability gap: current main and v2026.6.11 can be checked by inspecting the hook type, delivery call site, docs, target resolver, and outbound policy. This is not a runtime bug reproduction; it is a missing public API capability.

## Solution Assessment

Unclear until maintainer design review. Optional nested fields are plausible, but the exact target-context contract and sensitive disclosure boundary should be approved before implementation because this is a public Plugin SDK/security surface.
