## Summary

Keep open: current main and v2026.6.11 still do not expose resolved target, externality, or cross-context facts on `message_sending`, and the remaining work is a public Plugin SDK/security disclosure decision rather than stale cleanup.

## What This Changes

Add optional resolved target context to the `message_sending` plugin hook so policy plugins can reason about outbound destinations without reimplementing OpenClaw target resolution.

## Best Possible Solution

Approve a narrow optional target-context contract, then populate it from canonical outbound resolver and cross-context policy facts with SDK docs and focused hook/delivery tests.

## Reproduction Assessment

Yes, for the source-level capability gap: current main and v2026.6.11 can be checked by inspecting the hook type, delivery call site, docs, target resolver, and outbound policy. This is not a runtime bug reproduction; it is a missing public API capability.

## Solution Assessment

Unclear until maintainer design review. Optional nested fields are plausible, but the exact target-context contract and plugin visibility boundary should be approved before implementation because this is a public Plugin SDK/security surface.
