## Summary

Keep open: current main and the latest release still do not expose resolved target or cross-context facts on `message_sending`, and the remaining work is a public Plugin SDK/security-disclosure design decision rather than conservative cleanup.

## What This Changes

The issue requests optional resolved target context fields on the `message_sending` plugin hook so security plugins can distinguish internal routing from external or cross-context delivery.

## Best Possible Solution

Define a narrow optional `message_sending` target-context contract after maintainer/security approval, reusing canonical outbound resolver and cross-context policy facts and documenting the plugin disclosure boundary.

## Reproduction Assessment

Yes, for the source-level capability gap: current hook types, delivery code, docs, and v2026.6.11 all omit resolved target context while internal resolver and cross-context policy facts exist elsewhere. This is a missing public API capability, not a runtime bug reproduction.

## Solution Assessment

Unclear until maintainer design review. Optional nested fields are plausible, but the exact target-context contract and sensitive disclosure boundary should be approved before implementation because this is a public Plugin SDK/security surface.
