## Summary

Keep open: current main and v2026.6.11 still do not expose resolved target, target kind, externality, same-account, or cross-context facts on `message_sending`; this remains a security-sensitive public Plugin SDK design decision rather than cleanup.

## What This Changes

The issue requests optional resolved target context on the `message_sending` plugin hook so policy plugins can distinguish internal routing from external or cross-context delivery.

## Best Possible Solution

Define a narrow optional `message_sending` target-context contract after maintainer and security approval, reusing canonical outbound resolver and cross-context policy facts and documenting the plugin disclosure boundary.

## Reproduction Assessment

Yes, for the source-level capability gap: current main and v2026.6.11 expose only raw/basic outbound hook fields while internal resolver and cross-context policy facts exist elsewhere. This is not a runtime bug reproduction; it is a missing public API capability.

## Solution Assessment

Unclear until maintainer design review. Optional nested fields are plausible, but the exact target-context contract and sensitive disclosure boundary should be approved before implementation because this is a public Plugin SDK/security surface.
