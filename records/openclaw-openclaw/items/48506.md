## Summary

Keep open: current main and the latest release still expose raw `message_sending` destination/content plus basic routing metadata, while resolved target and cross-context facts remain internal and need maintainer/security approval before becoming Plugin SDK fields.

## What This Changes

Request to add optional resolved target context to the public `message_sending` plugin hook so policy plugins can distinguish internal, external, and cross-context outbound sends.

## Best Possible Solution

Approve a narrow optional `message_sending` target-context contract, populate it from canonical outbound resolver and cross-context policy facts, and document/test the disclosure boundary.

## Solution Assessment

Unclear until maintainer design review. Optional nested fields are plausible, but the best fix should be an approved narrow SDK contract populated from existing resolver/policy facts, not plugin-side parsing of raw destinations.
