## Summary

Keep open: current main and the latest release still do not expose resolved target, externality, or cross-context facts on the public `message_sending` hook, and the remaining work is a Plugin SDK/security disclosure decision rather than stale cleanup.

## What This Changes

The issue requests optional resolved target context fields on `PluginHookMessageSendingEvent` so policy plugins can reason about outbound destinations without reimplementing OpenClaw routing logic.

## Best Possible Solution

Approve a narrow optional `message_sending` target-context contract, then implement it from canonical outbound resolver and cross-context policy facts with SDK docs and focused hook/delivery tests.

- **Use an explicit resolver helper instead:** Document a supported plugin-side resolver path, accepting that plugins may need to opt into lookup cost and may not see the exact runtime-resolved destination for every send.
