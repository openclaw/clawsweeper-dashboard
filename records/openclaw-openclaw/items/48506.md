## Summary

Keep this open: current main and v2026.6.11 still do not expose resolved target or cross-context facts on `message_sending`, while the remaining work is a public Plugin SDK and security-disclosure design decision rather than conservative cleanup.

## What This Changes

Add optional resolved target and cross-context fields to `PluginHookMessageSendingEvent` so policy plugins can evaluate outbound destinations without reimplementing OpenClaw target resolution.

## Best Possible Solution

Design a narrow additive hook contract that exposes only reviewed destination facts computed once in outbound routing, with Plugin SDK docs and focused tests for privacy, cross-context, and compatibility behavior.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Not as a runtime bug, but yes at source level: main and `v2026.6.11` show `message_sending` lacks resolved target context while routing code resolves targets internally before dispatch.

## Solution Assessment

Is this the best way to solve the issue? Unclear: adding optional fields is plausible, but maintainers still need to decide the transport-agnostic shape and security disclosure boundary before code should be queued.
