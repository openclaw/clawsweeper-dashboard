## Label Justifications

- `P1`: Invalid traffic can suppress real inbound SMS callbacks, and the patch leaves that urgent delivery failure possible for a shared key.
- `merge-risk: 🚨 security-boundary`: The PR changes trusted-proxy identity handling and raises the amount of traffic admitted before signature validation.

- `merge-risk: 🚨 message-delivery`: A same-key invalid burst can still cause a later valid Twilio callback to receive HTTP 429 instead of reaching inbound dispatch.

## Summary

The patch and proof establish cross-client proxy isolation, but invalid traffic can still exhaust the early gate required by a later valid callback when both resolve to the same key. The branch also conflicts with newer replay-cache hardening on current main, so it is not ready to land.

## What This Changes

The PR splits SMS webhook throttling into pre-validation and signed-callback quotas, keys them by SMS account, route, and trusted-proxy-resolved client address, documents both stages, and adds regression coverage.

## Best Possible Solution

Integrate with current main and use an authentication-aware quota design that bounds hostile work without making invalid requests consume admission capacity required by valid callbacks; preserve the current replay guard and prove the same-key sequence.
