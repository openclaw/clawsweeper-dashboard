## Summary

Keep this PR open for SMS-owner review: current main still lets invalid same-key webhook traffic consume the only callback quota, while the exact head cleanly separates failed-request and dispatch capacity with focused coverage and no concrete correctness or security defect. ## What This Changes

The PR replaces the SMS webhook’s single pre-validation 30/min request gate with a 300/min failed-request budget and a separate 30/min dispatchable-callback limit keyed by SMS account route and proxy-resolved client address, with tests and docs.

## Best Possible Solution

Keep the plugin-owned two-stage limiter, with the SMS owner explicitly accepting the 300/min failed-request threshold and delayed invalid-request rejection as the intended balance between abuse resistance and valid callback availability.
