## Summary

The exact head still lets unauthenticated requests exhaust the pre-validation key and reject the next valid signed callback before Twilio authentication. The latest merge-conflict commit retains the previously raised blocker, so this PR is not merge-ready.

## What This Changes

The PR splits SMS webhook throttling into pre-validation and authenticated stages, scopes both quotas by SMS account, webhook route, and proxy-resolved client address, and updates tests and documentation.

## Best Possible Solution

Adopt bounded pre-authentication abuse controls that do not let invalid same-key traffic exhaust authenticated callback capacity, then add a same-key regression test and exact-head reverse-proxy proof showing the valid callback reaches dispatch.
