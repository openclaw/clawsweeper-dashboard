## Summary

Keep this PR open, but request one small correction before merge: it replaces a nonexistent command with a command that silently targets the default Telegram account, while the suspended handler is explicitly per-account. The repair should give account-safe recovery guidance and retain focused proof; the linked issue remains the canonical report. Likely related people: the original Telegram circuit-breaker author could not be identified from available history, so owner routing is low confidence.

## What This Changes

The PR replaces the invalid `openclaw channels restart telegram` text in Telegram’s 401-suspension log with token-update and gateway-restart commands, and adds regression coverage for that guidance.

## System Context

The Telegram plugin creates one send-chat-action circuit breaker for each configured Telegram account and logs recovery guidance after repeated authentication failures. Operators use that guidance to repair the affected account’s credentials before the gateway resumes channel activity.

## Architecture Diagram

flowchart LR
  A[Telegram account token] --> B[sendChatAction request]
  B --> C[401 circuit breaker]
  C --> D[Critical recovery guidance]
  D --> E[Update affected account token]
  E --> F[Gateway restart]
  F --> G[Telegram channel resumes]

## Best Possible Solution

Use account-safe, configuration-neutral recovery text: tell operators to update the bot token for the affected Telegram account through its configured token source, then run `openclaw gateway restart`; if a CLI example remains, make the account parameter explicit rather than defaulting silently.
