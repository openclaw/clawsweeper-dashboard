## Summary

This is a concrete data-loss bug report with a focused linked implementation PR, so it should remain open until that PR is reviewed and merged or replaced. The reported behavior conflicts with the documented rule that Workboard removes a run worktree only when removal is provably lossless. ([docs.openclaw.ai](https://docs.openclaw.ai/concepts/managed-worktrees?utm_source=openai))

## What This Changes

Prevent Workboard from deleting a managed worktree when a completed card still declares a local artifact path inside that worktree.

## Best Possible Solution

Land a narrowly scoped Workboard cleanup guard that preserves managed worktrees only when persisted local artifact paths resolve within that worktree, while retaining existing cleanup for URLs and paths outside it.
