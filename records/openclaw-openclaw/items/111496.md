## Summary

Keep open: this is a concrete data-loss bug, and the open linked PR https://github.com/openclaw/openclaw/pull/111497 uses closing syntax and is the focused candidate repair. The issue should remain open until that repair is reviewed and merged, replaced, or closed.

## What This Changes

Prevent Workboard run cleanup from removing a managed worktree when a completed card still declares a local artifact path inside it.

## Best Possible Solution

Land a narrow Workboard-owned cleanup guard that preserves a managed worktree only for persisted local artifacts canonically contained by it, while releasing the run lock so existing retention and garbage collection still apply.

## Reproduction Assessment

Yes, from source-level evidence: create a managed-worktree card with an ignored artifact path inside that worktree, end the subagent run, and observe lossless cleanup call `removeIfLossless` despite the persisted artifact reference. The linked PR also reports a focused regression test and a real temporary-repository proof.

## Solution Assessment

Yes, conditionally: preserving only canonically contained local artifact paths at the Workboard cleanup owner boundary is narrower than adding a copy or parallel artifact-storage protocol. The open PR still needs normal maintainer review before this issue can close.
