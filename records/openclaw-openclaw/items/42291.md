## Summary

Keep open: current main still runs provider auth login through the local agent auth store with no remote node-host preflight, and the only live closing candidate is a dirty, non-maintainer-editable fork PR rather than an implemented fix.

## What This Changes

The issue reports that provider OAuth login on a remote node host stores refreshed credentials on the node instead of the gateway that owns model calls.

## Best Possible Solution

Land a focused preflight that detects non-loopback remote node-host gateway config before provider auth starts, uses shared gateway loopback semantics, blocks or clearly warns before any credential write, and covers blocked plus local-loopback cases in tests.

## Reproduction Assessment

Yes, at source level. Current main resolves a local agentDir, runs provider auth, and upserts returned credentials there while node-host config can point at a non-loopback gateway.

## Solution Assessment

Yes for the narrow guard direction, with maintainer ownership still needed. Blocking or warning before auth starts is smaller and safer than silent gateway credential forwarding, but fail-closed behavior is a product/security choice.
