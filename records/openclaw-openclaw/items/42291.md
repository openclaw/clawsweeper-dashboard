- `impact:data-loss`: A refresh token can be consumed or rotated into the node-local auth store where the gateway cannot use it, making the gateway credential effectively lost for that run path.

## Summary

Keep open: current main and the latest release still run provider OAuth login against the locally resolved agent auth store, so a remote node host can consume OAuth credentials without updating the gateway. The linked repair PRs are unmerged, and the only open closing candidate is conflicting and not maintainer-editable.

## What This Changes

The issue requests that `openclaw models auth login` on a remote node host stop writing provider OAuth credentials only to the node-local auth store and instead route or block the flow for gateway-owned model execution.

## Best Possible Solution

Make remote node-host OAuth login fail closed before provider auth starts unless maintainers explicitly design a gateway-side credential forwarding flow with security-reviewed storage and tests.
