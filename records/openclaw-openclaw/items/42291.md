## Label Justifications

- `P1`: The issue describes a broken remote node/gateway auth workflow where OAuth credentials can be consumed locally and leave gateway model calls failing.
- `impact:data-loss`: The reported flow can rotate or consume refresh-token state into the wrong local store, leaving the gateway with unusable credential state.
- `impact:security`: Provider OAuth credentials are sensitive data and the report shows them being written to a node host rather than the intended gateway host.
- `impact:auth-provider`: The affected surface is provider auth profile routing and OAuth refresh behavior for OpenAI/Codex-backed model calls.
- `maturity:stable`: The affected remote gateway/auth boundary falls under `gateway-runtime`, which is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and the latest release still write model auth login profiles through the local agent auth store without checking node-host gateway state, and the only open closing PR is a conflicting fork PR rather than an implemented fix.

## What This Changes

The issue reports that `openclaw models auth login` on a remote node host saves OAuth/provider credentials to the node-local auth store instead of the gateway that performs model calls.

## Best Possible Solution

Land a focused, maintainer-approved fix that detects non-loopback node-host gateway config before provider auth writes, reuses shared gateway loopback semantics, and covers remote and loopback cases with regression tests.

Rationale: Both options prevent wrong-host credential writes, but forwarding OAuth/provider credentials across the node-gateway boundary is a larger security and protocol decision, while the existing maintainer draft favored fail-closed gateway-host login.
