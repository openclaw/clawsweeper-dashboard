## Label Justifications

- `P1`: The issue describes a real remote-gateway auth-provider workflow where OAuth refresh-token material can be consumed locally and leave model calls failing.

## Summary

Keep open: current main and the latest shipped release still persist provider auth login results into the local agent auth store with no node-host preflight, and the only live closing candidate is a conflicting, non-maintainer-editable fork PR rather than an implemented fix.

## What This Changes

The issue requests that `openclaw models auth login` on a remote node host avoid silently writing OAuth credentials to the node-local auth store and instead sync, block, or warn before gateway model calls use stale credentials.

## Best Possible Solution

Land a focused pre-auth guard that detects non-loopback remote node-host gateway config before provider auth starts, blocks or redirects before any credential write, preserves loopback/tunnel setups, and covers both blocked-remote and allowed-local cases in tests.
