## Summary

Keep open: current main and the latest release still persist `openclaw models auth login` results through the local agent auth store, while node-host config can point at a non-loopback Gateway. A linked fork PR is open but conflicting and not maintainer-editable, so it is only a candidate path, not an implemented fix.

## What This Changes

The issue asks OpenClaw to stop silently writing OAuth credentials to a remote node host's local auth store when model execution uses a separate Gateway.

## Best Possible Solution

Land a focused pre-auth guard that detects non-loopback remote node-host Gateway config before provider auth starts, blocks or redirects before any credential write, reuses shared Gateway loopback handling, and covers remote-block plus local-loopback cases in tests.
