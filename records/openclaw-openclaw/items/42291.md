## Summary

Keep open: current main still persists provider OAuth login results to the local resolved agent auth store, and the same-repo fix attempts are closed unmerged while the remaining fork PR is conflicting and not maintainer-editable.

## What This Changes

The issue reports that `openclaw models auth login` on a remote node host stores OAuth credentials in the node-local auth profile instead of making them usable by the gateway.

## Best Possible Solution

Land a focused maintainer-owned or adopted fix that blocks non-loopback node-host auth before OAuth starts, or explicitly design a secure gateway-forwarding path before allowing node hosts to acquire gateway-owned OAuth material.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should remote node-host `openclaw models auth login` fail closed before provider auth starts, or should OpenClaw support gateway-side credential forwarding for this flow?

Rationale: The fix changes a provider credential boundary and determines whether node hosts may acquire and transfer gateway-owned OAuth material, which is a product/security decision rather than a mechanical bug fix.

Likely owner: Vincent Koc

Owner reason: He authored the maintainer draft for this exact guard and already framed the fail-closed behavior and verification path.

Owner confidence: medium

Options:

- **Fail closed before auth starts (recommended):** Block auth login when node-host config points at a non-loopback remote gateway and instruct the user to run auth on the gateway host.
- **Forward credentials to gateway:** Design an authenticated gateway RPC/setup flow that stores the returned provider credential in the gateway auth store without consuming it locally first.
- **Warn but allow local write:** Keep the current local write path with an explicit warning, accepting that users can still consume credentials on the wrong host.

## Reproduction Assessment

Yes, source-reproducible: current main resolves a local `agentDir`, runs provider auth, and upserts profiles there while node-host config can point at a remote gateway. I did not run a live OAuth flow because this read-only review cannot safely consume real credentials.

## Solution Assessment

Unclear until maintainer intent is set. A pre-auth fail-closed guard is the narrowest safe repair if maintainers accept it, while transparent gateway forwarding would need separate protocol/security design.
