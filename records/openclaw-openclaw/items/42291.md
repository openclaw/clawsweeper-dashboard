## Summary

Keep open: current main and v2026.6.11 still persist provider OAuth login to the locally resolved agent auth store, and the only open closing PR is conflicting and not maintainer-editable.

## What This Changes

The issue asks OpenClaw to prevent `openclaw models auth login` on a remote node host from consuming OAuth credentials into the node-local auth store when model execution uses the gateway.

## Best Possible Solution

Prevent wrong-store OAuth writes before token exchange by adding a maintainer-approved remote node-host guard, unless maintainers explicitly choose and design a gateway-side credential forwarding flow.
