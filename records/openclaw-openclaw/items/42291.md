## Label Justifications

- `P1`: The report describes an urgent remote-gateway auth-provider workflow where OAuth refresh-token material can be consumed locally and leave gateway model calls failing.
- `impact:data-loss`: Provider OAuth refresh credentials can be rotated or consumed into the wrong local store, making the intended gateway credential unusable.
- `impact:security`: Sensitive provider credential material can cross the wrong node/gateway trust boundary without warning.
- `impact:auth-provider`: The failure directly affects provider OAuth state, model auth routing, and recovery from refresh-token reuse errors.
- `maturity:stable`: The issue affects the gateway/node remote boundary, and `gateway-runtime` is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and the latest release still persist provider auth login results to the local agent auth store with no remote node-host preflight, and the only open closing PR is a conflicting, non-maintainer-editable fork candidate rather than an implemented fix.

## What This Changes

The issue requests preventing `openclaw models auth login` on a remote node host from silently consuming and storing OAuth credentials locally when model execution happens on the gateway.

## Best Possible Solution

Land a focused pre-auth guard that detects non-loopback remote node-host gateway config before provider auth starts, blocks or redirects before any credential write, and covers remote-block plus loopback/tunnel-allowed cases in tests; if maintainers want credential forwarding instead, design that gateway RPC/security model first.
