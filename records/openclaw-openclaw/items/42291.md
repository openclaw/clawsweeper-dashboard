## Summary

Keep open: current main and the latest release still route provider OAuth login through the locally resolved agent auth store, so a remote node host can consume credentials without updating the gateway. The same-repo repair PRs are closed unmerged, and the only open closing candidate is a conflicting, non-maintainer-editable fork PR.

## What This Changes

This issue requests that `openclaw models auth login` on a remote node host either sync OAuth credentials to the gateway or stop/warn before writing node-local credentials.

## Best Possible Solution

Make remote node-host provider auth login fail closed before OAuth starts unless maintainers explicitly approve a gateway-side credential-forwarding design; the guard should use node-host config plus shared gateway loopback semantics and focused regression coverage.

Options:

- **Fail closed before auth starts (recommended):** Block auth login when node-host config points at a non-loopback gateway and instruct the user to run auth on the gateway host.
- **Design gateway credential forwarding:** Add an authenticated gateway-side flow that stores provider credentials only in the gateway auth store without first consuming them into the node-local store.
- **Warn but allow local write:** Keep local login possible with a clear warning, accepting that users may still create wrong-host credentials that the gateway cannot use.
