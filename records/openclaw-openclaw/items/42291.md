## Summary

Keep open: current main and v2026.6.11 still route provider auth login through the local agent auth store, while same-repo fix attempts are closed unmerged and the only live linked PR is a conflicting fork PR outside the target repository.

## What This Changes

The issue reports that provider OAuth login on a remote node host stores credentials in the node-local auth profile instead of making them usable by the gateway.

## Best Possible Solution

Land a focused pre-auth remote-node guard that blocks non-loopback node-host provider auth login before any OAuth credential is acquired or written, unless maintainers explicitly choose and design a gateway-side credential-forwarding flow.

- **Warn but allow local write:** Keep local writes possible with warning copy, accepting the risk that users may still consume refresh credentials on the wrong host.

## Solution Assessment
