## Summary

Keep open: current main and v2026.6.11 still persist provider OAuth profiles to the CLI-resolved local agent store and only refresh gateway auth status afterward; the same-repo fix attempts are closed unmerged and the only open fork PR is dirty.

## What This Changes

The issue asks `openclaw models auth login` on remote node hosts to avoid consuming OAuth credentials into the node-local store when model execution happens on the gateway.

## Best Possible Solution

Add a pre-auth remote-node guard using `loadNodeHostConfig` and `isLoopbackHost`, unless maintainers explicitly choose a gateway-owned credential-sync API with security review.
