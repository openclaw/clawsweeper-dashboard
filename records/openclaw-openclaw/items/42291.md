## Summary

Keep open: current main and the latest release still write provider auth results to the CLI-resolved local agent store before only refreshing gateway auth status, while the open linked fork PR is conflicting and the same-repo fix attempts are closed unmerged.

## What This Changes

The issue reports that `openclaw models auth login` on a remote node host stores OAuth credentials in the node-local auth profile store instead of the gateway auth store used for model calls.

## Best Possible Solution

Add a focused auth-boundary fix that detects non-loopback remote node-host mode before provider auth starts and either fails closed with gateway-host instructions or uses an explicitly approved gateway-owned credential-sync API.

Rationale: Both valid repairs decide where OAuth credentials are minted and stored across hosts, so automation should not choose the cross-host credential policy without maintainer intent.

Options:

- **Fail Closed On Remote Node Hosts (recommended):** Block login before OAuth/token creation when `node.json` points at a non-loopback gateway and tell the operator to run auth on the gateway host.
- **Design Gateway Credential Sync:** Keep node-host login convenience by adding an explicit gateway API for credential transfer with security review and upgrade tests.
- **Document Node-Local Auth Only:** Accept the current ownership boundary by documenting that node-host auth login only affects the node-local store and requiring gateway-host authentication.

## Solution Assessment

No. The current behavior is not the best solution because it allows credential-bearing OAuth state to land on the wrong host; a fail-closed node-host preflight looks like the smallest safe fix, but maintainers need to choose that over gateway credential sync.
