## Label Justifications

- `P1`: The issue breaks a real provider-auth workflow by consuming or rotating OAuth credentials on a node host while gateway model calls continue using stale credentials.
- `impact:data-loss`: The reported refresh token can be consumed by the wrong local write, leaving the intended gateway credential state unrecoverable without re-authentication.
- `impact:security`: OAuth credentials are minted and stored on a node host outside the intended gateway credential-owner boundary.
- `impact:auth-provider`: The failure is directly in provider auth login, auth-profile storage, and model credential routing.
- `maturity:stable`: The affected CLI onboarding/auth setup surface maps to `cli-install-update-onboard-doctor`, which is scored M4 Stable in the checked-in maturity scorecard.

## Summary

Keep open: current main still writes provider auth profiles to the CLI-resolved local agent store and only refreshes gateway auth status afterward; the latest release has the same wrong-host behavior, and the same-repo fix attempts are closed unmerged while the open fork PR is conflicting.

## What This Changes

The issue asks OpenClaw to prevent `models auth login` on a remote node host from consuming OAuth credentials into the node-local auth store instead of making them usable by the gateway.

## Best Possible Solution

Add a focused auth-boundary fix that detects non-loopback remote node-host mode before provider OAuth starts and either fails closed with gateway-host instructions or uses an explicitly approved gateway-owned credential-sync API.

- **Document Node-Local Scope:** Keep current behavior but document that node-host auth login only affects the node-local store and operators must authenticate directly on the gateway.
