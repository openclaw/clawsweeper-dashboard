## Label Justifications

- `P1`: The issue affects an auth-provider workflow where remote node users can consume or rotate OAuth credentials locally while the gateway used for model calls remains stale.
- `impact:data-loss`: The reported OAuth refresh token can be consumed by the wrong local write, leaving the intended gateway credential state unrecoverable without re-auth.
- `impact:security`: OAuth credentials are written on a node host outside the intended gateway credential boundary.
- `impact:auth-provider`: The failure is directly in provider auth login, auth-profile storage, and model credential routing.
- `maturity:stable`: The affected CLI setup/auth surface maps to `cli-install-update-onboard-doctor`, which is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and latest release still write provider auth profiles into the resolved local agent directory and only refresh a gateway status snapshot afterward, so the reported wrong-host OAuth credential path remains. A linked fork PR exists, but it is open and conflicting, while the same-repo repair attempts were closed unmerged.

## What This Changes

The issue requests that `openclaw models auth login` stop silently writing OAuth credentials to node-local auth storage when a node host is connected to a remote gateway.

## Best Possible Solution

Keep the issue open and land a focused auth-boundary fix that blocks remote node-host auth login before credentials are minted, or implements an explicitly reviewed gateway-owned credential-sync API with regression coverage.
