## Summary

Keep open: current main still runs provider auth login against the local agent auth store with no remote node-host preflight, while the only live closing candidate is a conflicting, non-maintainer-editable fork PR rather than an implemented fix.

## What This Changes

The issue asks OpenClaw to stop `openclaw models auth login` on remote node hosts from silently writing OAuth credentials to the node-local auth store instead of the gateway-owned auth store.

## Best Possible Solution

Land a focused pre-auth guard for node-host configs that point at non-loopback gateways, reuse shared loopback handling, block before any provider auth or token write, and test remote-block plus local-loopback allow behavior unless maintainers explicitly choose a gateway credential-forwarding design.

- **Forward credentials to the gateway:** Design an authenticated gateway RPC or setup flow that moves provider auth material into the gateway store without consuming tokens into the node-local store first.
- **Warn but keep permissive:** Warn node-host users that auth only affects the local node, accepting the wrong-host credential risk for compatibility.
