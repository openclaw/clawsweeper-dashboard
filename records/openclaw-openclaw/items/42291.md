## Summary

Keep open: current main and v2026.6.11 still run provider OAuth login against the locally resolved agent auth store, with no remote node-host guard or gateway credential sync, and the only live candidate PR is a conflicting, non-maintainer-editable fork.

## What This Changes

The issue asks OpenClaw to stop `models auth login` on a remote node host from silently saving OAuth credentials to the node-local auth store instead of the gateway-owned store.

## Best Possible Solution

Fail before OAuth starts on remote node hosts unless maintainers explicitly choose and design a secure gateway-owned auth-forwarding path.

- **Design gateway-owned auth forwarding:** Allow node-host login only after adding an authenticated gateway credential-transfer protocol with security review and upgrade tests.
- **Document the current limitation:** Leave runtime behavior unchanged and document that remote node users must run OAuth login on the gateway, accepting continued risk of silent local writes.

## Reproduction Assessment

Yes by source inspection: `runModelsAuthLoginFlow` resolves a local `agentDir`, then `persistProviderAuthResult` writes returned profiles to that local directory with no remote node-host check or gateway RPC. I did not run a live OAuth flow in this read-only review.

## Solution Assessment

No final fix can be selected without maintainer intent. Blocking remote-node OAuth before it starts is the narrowest safe mitigation, while automatic sync needs explicit gateway credential-transfer design and security review.
