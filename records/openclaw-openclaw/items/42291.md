## Label Justifications

- `P1`: The report describes a real remote-gateway auth workflow where OAuth refresh-token material can be consumed locally and leave model calls failing.
- `impact:data-loss`: Provider OAuth refresh credentials can be rotated or consumed into the wrong local store, making the intended gateway credential unusable.

- `impact:auth-provider`: The failure directly affects provider OAuth state, model auth routing, and recovery from refresh-token reuse errors.
- `maturity:stable`: The issue affects the gateway/node remote boundary, and `gateway-runtime` is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and the latest release still persist provider auth login results to the resolved local agent auth store without a remote node-host guard, and the only open closing candidate is a conflicting fork PR that maintainers cannot edit.

## What This Changes

Running `openclaw models auth login` on a remote node host can store provider OAuth credentials in the node-local auth profile store instead of the gateway-owned store.

## Best Possible Solution

Land a focused pre-auth guard that detects non-loopback remote node-host gateway config before provider auth starts, blocks with an actionable gateway-host instruction, preserves loopback/tunnel setups, and adds regression coverage for both paths.

Options:

- **Fail closed before auth starts (recommended):** Block non-loopback remote node-host auth login with a clear instruction to run auth on the gateway host while preserving loopback/tunnel setups.
- **Forward credentials to the gateway:** Design an authenticated gateway RPC or setup flow that moves provider auth material to the gateway store without consuming tokens locally first.
- **Warn but allow local writes:** Keep the current permissive behavior with a warning, accepting that users can still consume provider OAuth material on the wrong host.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: a node host can have non-loopback gateway metadata while `models auth login` still resolves a local `agentDir` and persists returned OAuth profiles there.

## Solution Assessment

Unclear until maintainer intent is set. A pre-auth fail-closed guard is the narrowest safe fix if maintainers accept that behavior; transparent gateway credential forwarding needs a separate security design.
