## Label Justifications

- `P1`: The report describes a broken remote-gateway auth workflow where OAuth refresh-token material can be consumed locally and leave Gateway model calls failing.

## Summary

Keep open: current main and the latest release still run provider auth login against the locally resolved agent auth store, while node-host config can point at a non-loopback remote Gateway; the only open closing PR is a conflicting, non-maintainer-editable fork candidate rather than an implemented fix.

## What This Changes

The issue reports that `openclaw models auth login` on a remote node host stores OAuth credentials in the node-local auth profile instead of making them available to the Gateway that runs model calls.

## Best Possible Solution

Land a focused pre-auth guard that detects non-loopback remote node-host Gateway config before provider auth starts and blocks with an actionable Gateway-host instruction; if maintainers want credential forwarding instead, design that Gateway RPC/security model first.

- **Warn but allow local write:** Keep permissive local node writes with a warning, accepting the wrong-host credential risk for compatibility.

## Solution Assessment

Unclear until maintainer intent is set. A pre-auth fail-closed guard is the narrowest safe fix if maintainers accept that boundary, while transparent Gateway credential forwarding needs a separate security design.
