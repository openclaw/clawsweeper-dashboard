## Summary

Keep open: current main and the latest release still route provider login through the local agent auth store with no node-host gateway preflight, and the only live closing PR is a conflicting, non-maintainer-editable fork rather than an implemented fix.

## What This Changes

The issue asks OpenClaw to stop `models auth login` on a remote node host from consuming OAuth credentials into the node-local auth store instead of the gateway-owned store.

## Best Possible Solution

Land or replace the prior attempts with a focused pre-auth guard for non-loopback node-host gateway configs, unless maintainers explicitly choose a designed gateway credential-forwarding flow.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should remote node-host `openclaw models auth login` fail closed before provider auth starts, or should OpenClaw implement authenticated gateway-side credential forwarding for this flow?

Rationale: Both options change a sensitive provider credential boundary, and automation should not decide whether node hosts may acquire or transfer gateway-owned OAuth material without maintainer intent.

Likely owner: vincentkoc

Owner reason: They authored and verified the linked maintainer repair direction for this exact remote-node auth guard.

Owner confidence: high

Options:

- **Fail closed before auth starts (recommended):** Block non-loopback remote node-host auth login with an actionable gateway-host instruction while preserving local loopback and tunnel setups.
- **Forward credentials to gateway:** Design a gateway RPC or setup flow that stores provider auth material on the gateway without consuming tokens into the node-local store first.
- **Warn but allow local write:** Warn node-host users that auth only affects the node, accepting the wrong-host credential risk for compatibility.

## Reproduction Assessment

Yes, source-reproducible: current main resolves a local `agentDir`, runs provider auth, and upserts returned profiles there while node-host config can persist a non-loopback gateway target.

## Solution Assessment

Unclear until maintainer intent is set. A pre-auth fail-closed guard is the narrowest safe fix if maintainers accept that behavior; transparent credential forwarding needs explicit design and protocol review.
