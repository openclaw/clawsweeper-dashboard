## What This Changes

The issue asks to guard `AgentSession.checkCompaction` compaction-boundary timestamp parsing so malformed timestamps do not leave stale pre-compaction assistant or usage messages misclassified.

## Best Possible Solution

Review and either land https://github.com/openclaw/openclaw/pull/99501 or choose a different malformed-boundary policy, then close this issue only after the fix merges.

## Reproduction Assessment

## Solution Assessment

Unclear until maintainers accept the malformed-boundary policy. A centralized internal helper covering both call sites is the narrow fix if unreliable boundaries should be treated as absent; a stricter persisted-data repair path would be a different decision.
