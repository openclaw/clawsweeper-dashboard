## Summary

Keep open: current main and the latest release still have the unguarded compaction-boundary timestamp comparisons, and https://github.com/openclaw/openclaw/pull/99501 is now the live closing fix candidate rather than merged behavior.

## What This Changes

The issue asks OpenClaw to handle malformed compaction boundary timestamps in `AgentSession.checkCompaction` so stale pre-compaction assistant or usage messages cannot drive duplicate compaction decisions.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/99501; if rejected, choose one explicit malformed compaction-boundary policy for `AgentSession` and cover both stale checks with regression tests.

## Reproduction Assessment

Partly: current main has the two unguarded timestamp comparisons, and a Node probe confirms invalid dates produce `NaN` with false `<=` comparisons. There is not yet a high-confidence live reproduction of duplicate compaction cycles or OOM.

## Solution Assessment

Unclear until maintainer review: the open PR's explicit `undefined` fallback is a plausible small fix, but it preserves the current effective non-stale behavior for malformed timestamps. Maintainers should decide whether skipping the guard, strict persisted timestamp parsing, or another ordering fallback is the intended policy.
