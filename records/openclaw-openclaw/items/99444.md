## Summary

## What This Changes

The issue requests guarding invalid compaction boundary timestamps in `AgentSession` stale assistant and usage-message checks.

## Best Possible Solution

Define one explicit invalid compaction-boundary policy for `AgentSession`, then add focused regression coverage and coordinate with the persisted timestamp parser work if that becomes the canonical reader fix.

## Reproduction Assessment

Partly. Source inspection and a Node probe confirm the invalid timestamp comparison behavior on current main, but there is no high-confidence runtime reproduction of duplicate compaction or OOM.

## Solution Assessment

Unclear. A `Number.isNaN` guard is only the best fix if invalid compaction timestamps should be ignored; if stale detection must survive malformed persisted boundaries, the fix needs a different fallback such as ordering/index semantics.
