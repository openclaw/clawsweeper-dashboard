## Summary

The reported bug is valid, but this PR is not merge-ready: it extends the retry count for every retryable embedding failure rather than only rate limits, and it provides no after-fix live provider proof.

## What This Changes

The PR forwards embedding errors into the retry wait helper, increases the shared retry limit from 3 to 7, and applies longer capped waits to messages recognized as rate limits.

## Best Possible Solution

Keep the existing generic retry budget, add a separate abortable 429 policy that honors structured Retry-After metadata when available and uses a bounded fallback otherwise, then cover 429, 5xx, and cancellation behavior plus a redacted live terminal run.
