## Summary

The revised head fixes the prior retry-budget finding by keeping seven attempts specific to detected rate limits, but the new classifier does not cover every rate-limit form already recognized by the shared policy, and the PR still lacks a real provider roundtrip showing that a 429 recovers after the longer wait.

## What This Changes

The PR changes memory-core embedding retries to give detected rate-limit errors seven attempts with delays capped at 60 seconds while retaining three attempts and the existing delay cap for other transient errors.

## Best Possible Solution

Use one structured, provider-owned rate-limit classification that carries Retry-After when available, applies a bounded fallback only to recoverable throttling, preserves the short transient-error budget, and is demonstrated with a redacted real `openclaw memory index` 429 recovery transcript.

## Solution Assessment

No, not yet: separating rate-limit and transient budgets is the correct boundary, but the classifier should cover the shared policy's rate-limit forms and prefer structured Retry-After information where available before the fixed fallback is considered the best fix.
