## What This Changes

The issue requests that spawned-session lookup failures be logged and reported distinctly from tree-policy denials, with one bounded retry before rejecting `sessions_send` or `sessions_history`.

## System Context

Session tools use the configured visibility policy to decide whether one agent session may inspect or message another session. Direct-key tools derive child-session ownership through a lookup, then either permit the requested session operation or return a visibility denial.

## Architecture Diagram

flowchart LR
  A[Agent session request] --> B[Session tool]
  B --> C[Tree visibility guard]
  C --> D[Spawned-session lookup]
  D --> E{Lookup outcome}
  E -->|Owned child| F[Allow send or history]
  E -->|Not owned| G[Policy denial]
  E -->|Lookup error| H[Distinct transient failure]

## Best Possible Solution

First unify direct-key authorization with durable normalized row ownership where available; if the lookup can still fail, return a distinct fail-closed operational error with safe diagnostics rather than a policy denial, and add a narrowly bounded retry only when the underlying storage contract supports it.
