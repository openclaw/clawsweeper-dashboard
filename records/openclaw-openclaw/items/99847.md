## What This Changes

The issue reports that stuck-session recovery can leave an orphaned active session lane in `keep_lane` forever when no embedded run handle remains, blocking queued work until Gateway restart.

## Best Possible Solution

Review and land one focused linked PR that adds a time-gated, safety-guarded lane reset for orphaned active lane tasks, then close this issue after the fix reaches main.

Yes from source inspection: create a session lane with active work, no active embedded run handle, and queued work; current main returns `keep_lane` from the `active_lane_task` branch before reset. I did not run the live Gateway repro in this read-only sweep.
