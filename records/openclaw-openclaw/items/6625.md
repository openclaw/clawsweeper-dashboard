## Summary

Keep open: current main and the latest release still only have hard sub-agent run timeouts plus post-timeout handling, not a configurable child-visible pre-timeout warning or grace contract.

## What This Changes

Request a configurable child-visible warning before sub-agent `runTimeoutSeconds` expires so child agents can checkpoint progress before hard termination.

## Best Possible Solution

Define one core sub-agent lifecycle contract for configurable pre-timeout warnings, then implement it consistently across config, `sessions_spawn`, native spawn, ACP spawn, docs, and focused lifecycle tests while preserving existing post-timeout recovery.

Options:

- **Add global plus per-spawn controls (recommended):** Expose a documented default plus a per-spawn override, schedule a child-visible warning before hard timeout, and test native plus ACP behavior.

- **Defer to post-timeout recovery:** Keep the current hard-timeout and recovery model if maintainers do not want child-visible timeout warnings in the core lifecycle.
