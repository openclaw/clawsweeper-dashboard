## Summary

Keep open. Current main still has operator-controlled hard sub-agent run timeouts and post-timeout recovery, but no configurable pre-timeout child warning or checkpoint grace path.

## What This Changes

Request a graceful pre-timeout warning for sub-agent runs so child agents can checkpoint before a hard timeout ends the run.

## Best Possible Solution

Define a maintainer-approved core sub-agent lifecycle contract for warning/grace behavior, including public config/API naming, native and ACP delivery semantics, focused tests, and docs while preserving current post-timeout recovery.

## Reproduction Assessment

Yes, at source level: current main has hard sub-agent deadlines and post-timeout lifecycle handling but no config key, tool input, or scheduled child warning before termination. No live timeout run was executed in this read-only review.

## Solution Assessment

Unclear as proposed. A pre-timeout warning addresses the reported loss mode, but maintainers need to choose the public config/tool semantics and a lifecycle-owned delivery design across native and ACP runs.
