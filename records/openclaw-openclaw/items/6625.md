## Label Justifications

- `P2`: The feature would reduce meaningful lost progress in long-running sub-agent workflows but is not an emergency failure of the core runtime.
- `impact:session-state`: Hard timeout can terminate accumulated child-session state before the child can deliberately checkpoint it.
- `impact:data-loss`: Unsaved code, research, analysis, and generated content may be lost when the child is forcibly terminated.

## Summary

Current main and v2026.6.11 still provide a hard sub-agent run deadline and post-timeout lifecycle handling, but no child-visible pre-timeout warning or grace contract. The request remains distinct from the related stall, idle-timeout, and parent-notification reports; implementation should wait for maintainer direction on the new public configuration and native-versus-ACP delivery guarantee.

## What This Changes

Request a configurable warning or grace interval before hard sub-agent run timeout so the child can checkpoint progress.

## Best Possible Solution

Add one lifecycle-owned warning tied to the canonical run deadline and generation, deliver it through proven native or ACP steering capabilities, cancel it on every terminal or replacement path, and explicitly report runtimes that cannot accept a durable warning.
