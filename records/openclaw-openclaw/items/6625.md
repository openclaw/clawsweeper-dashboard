## Summary

Keep open: current main and v2026.6.11 still enforce hard sub-agent deadlines without a child-visible pre-timeout warning, and the related reports address different inactivity or post-timeout delivery failures. The remaining work needs a maintainer decision because native and ACP runtimes do not currently share a portable in-flight warning primitive.

## What This Changes

The issue requests a child-visible warning shortly before a sub-agent hard timeout so it can checkpoint partial work.

## Best Possible Solution

Define a capability-gated core deadline-warning contract driven by the canonical run deadline, use genuine same-turn delivery only where the runtime supports it, preserve hard-timeout and partial-result recovery, and add configuration only if a fixed or derived warning interval is insufficient.

Owner confidence: high

Options:

- **Capability-gated warning (recommended):** Add a core deadline-warning lifecycle capability and deliver it only through runtimes that explicitly support same-turn input, with documented best-effort behavior elsewhere.
- **Native-only warning:** Implement warning delivery for native subagents now and document that ACP runs retain hard-timeout behavior until a portable ACP steer contract exists.
- **Keep timeout-only behavior:** Do not add a warning surface and rely on durable progress practices plus post-timeout partial-result and parent-notification improvements.
