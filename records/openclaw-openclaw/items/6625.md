## Summary

Keep open: current main still enforces a hard sub-agent run deadline without warning the child first. The related stall-recovery work uses inactivity rather than the absolute deadline requested here, and recent discussion is explicitly asking for an ownership/product decision rather than supplying grounds for cleanup.

## What This Changes

Add a configurable warning shortly before a sub-agent's hard run timeout so it can checkpoint progress before termination.

## Best Possible Solution

Implement one core-owned, idempotent sub-agent lifecycle monitor shared by native and ACP runs, with a documented config-level pre-deadline warning, a cancellable child-control delivery path, and tests for completion-before-warning, warning-before-timeout, disabled/unlimited timeouts, cleanup, and restart behavior; reuse its scheduling/message seam for the distinct inactivity policy in https://github.com/openclaw/openclaw/issues/39305.

- **Decline warning surface:** Keep the hard timeout contract unchanged and rely on unlimited or longer timeouts plus task-level checkpoint instructions.

## Reproduction Assessment

Yes at source level: current main exposes and enforces the hard run timeout but has no warning/grace configuration or scheduled child message. No live timeout run was performed during this read-only review.

## Solution Assessment

No, not exactly as proposed: the product need is valid, but adding an isolated sessions key and per-spawn override would conflict with the current config-owned timeout contract. A shared native/ACP lifecycle monitor with one explicit policy boundary is the safer design.
