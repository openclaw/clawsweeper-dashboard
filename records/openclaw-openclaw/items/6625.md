## Summary

Keep open. Current main and v2026.6.11 still expose hard sub-agent run timeouts and post-timeout completion handling, but I did not find a configurable pre-timeout warning/grace path delivered to the child agent before termination.

## What This Changes

The issue requests a configurable pre-timeout warning for sub-agents so they can checkpoint progress before `runTimeoutSeconds` terminates the run.

## Best Possible Solution

Define one maintainer-approved pre-timeout child notification contract shared by native and ACP sub-agent runs, then add focused tests and docs while preserving current post-timeout recovery.
