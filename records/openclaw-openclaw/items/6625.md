## Summary

Keep open. Current main and v2026.6.11 still provide hard sub-agent run timeouts plus post-timeout recovery, but no configurable pre-timeout warning/grace path that lets a child checkpoint before the deadline.

## What This Changes

Request to add a configurable pre-timeout warning/grace period for sub-agents so they can checkpoint before `runTimeoutSeconds` kills the run.

## Best Possible Solution

Define a maintainer-approved core sub-agent lifecycle contract that adds a documented grace setting, schedules a child warning before hard timeout for native and ACP where feasible, and preserves existing post-timeout recovery behavior.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 have hard sub-agent deadlines and post-timeout handling, but no config key, tool input, or scheduled child warning before termination. I did not run a live timeout scenario during this read-only review.

## Solution Assessment

Unclear as proposed. A pre-timeout warning targets the reported loss mode, but maintainers still need to choose the public config/tool API and native/ACP delivery semantics before implementation.
