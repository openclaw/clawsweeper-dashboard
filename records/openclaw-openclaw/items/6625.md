## Summary

Current main still lacks the requested child-visible pre-timeout warning/grace contract; the code and docs cover hard sub-agent run timeouts plus post-timeout handling, but not a configurable warning before `runTimeoutSeconds` expires.

## What This Changes

The issue requests a configurable grace period that warns a sub-agent shortly before `runTimeoutSeconds` so it can checkpoint work before the hard timeout.

## Best Possible Solution

Define a maintainer-approved core pre-timeout warning contract, then implement native and ACP delivery with focused tests and docs while preserving current post-timeout recovery.
