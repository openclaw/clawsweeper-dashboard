## Summary

Keep open: current main and v2026.6.11 still enforce sub-agent run deadlines without warning the child beforehand, and the related reports address inactivity detection, premature idle termination, or post-timeout delivery instead. The remaining direction needs maintainer judgment because native steering restarts the run and ACP uses separate lifecycle controls.

## What This Changes

Requests a child-visible warning shortly before a sub-agent’s hard run timeout so it can checkpoint progress.

## Best Possible Solution

Add a true non-destructive in-flight child-message primitive, schedule one idempotent warning from the canonical run deadline across supported runtimes, and retain the current global-only API unless maintainers explicitly approve configurable or per-spawn overrides.
