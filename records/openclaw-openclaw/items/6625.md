## Summary

Keep open. Current main and the latest release still have configurable hard sub-agent run timeouts and post-timeout partial-progress handling, but no pre-timeout warning/grace path that lets the child checkpoint before termination.

## What This Changes

Request a configurable pre-timeout warning/grace period for sub-agent runs so the child can checkpoint before `runTimeoutSeconds` terminates it.

## Best Possible Solution

Define a maintainer-approved core sub-agent lifecycle contract that adds a grace setting or equivalent policy, delivers a warning through native and ACP child-session paths before the hard timeout, and preserves current post-timeout recovery behavior.

## Reproduction Assessment

Yes, at the source level: current main has configurable hard sub-agent timeouts and post-timeout handling, but no config key, tool input, or scheduled child warning before termination. I did not run a live timeout scenario during this read-only review.

## Solution Assessment

Unclear as proposed. A pre-timeout warning addresses the reported loss mode, but maintainers need to choose the public config/tool API and native/ACP delivery semantics before implementation.
