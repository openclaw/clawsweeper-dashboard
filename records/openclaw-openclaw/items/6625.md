## Summary

Keep open. Current main and v2026.6.11 still expose hard sub-agent run timeouts and post-timeout handling, but no pre-timeout warning/grace contract that lets the child checkpoint before termination.

## What This Changes

The issue requests a configurable pre-timeout warning/grace path for sub-agents before `runTimeoutSeconds` kills the child run.

## Best Possible Solution

Keep this open for a maintainer-approved core sub-agent lifecycle contract that defines the grace setting, warning delivery path, native/ACP behavior, tests, and docs while preserving current post-timeout recovery.

Unclear as proposed. A pre-timeout warning targets the reported loss mode, but maintainers need to choose the public config/tool API and native/ACP delivery semantics before implementation.
