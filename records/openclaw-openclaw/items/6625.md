## Summary

Keep open. Current main and the latest release still have operator-controlled hard sub-agent run timeouts plus post-timeout handling, but no configurable pre-timeout child warning or checkpoint grace path.

## What This Changes

Request a configurable pre-timeout warning/grace mechanism for sub-agents so a child can checkpoint before `runTimeoutSeconds` terminates the run.

## Best Possible Solution

Define a maintainer-approved core sub-agent lifecycle contract for warning/grace behavior, then implement native and ACP warning delivery with focused tests and docs while preserving current timeout recovery.

## Reproduction Assessment

Yes, at source level: current main has hard sub-agent deadlines and post-timeout lifecycle handling but no config key, tool input, or scheduled child warning before termination. No live timeout run was executed in this read-only review.

## Solution Assessment

Unclear as proposed. A pre-timeout warning addresses the reported loss mode, but maintainers need to choose the public config/API semantics and a delivery design that works across native and ACP runs.
