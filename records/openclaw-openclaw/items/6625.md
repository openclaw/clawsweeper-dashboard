## Summary

Keep open. Current main and the latest release still provide hard sub-agent run timeouts plus post-timeout retry/recovery paths, but they do not provide a configurable pre-timeout warning/grace message that lets the child checkpoint before the hard timeout.

## What This Changes

The issue requests a configurable pre-timeout warning/grace period for sub-agents before `runTimeoutSeconds` terminates the child run.

## Best Possible Solution

Define a maintainer-approved core sub-agent timeout-warning contract covering config/defaults, native and ACP warning delivery, tests, and docs while preserving current post-timeout recovery.

## Reproduction Assessment

Yes. Source inspection on current main shows hard sub-agent deadlines and post-timeout handling, but no config key, tool input, or scheduled child warning before termination; I did not run a live timeout scenario in this read-only review.

## Solution Assessment

Unclear as proposed. A pre-timeout warning targets the reported progress-loss mode, but maintainers need to choose the public config/tool API and native/ACP delivery semantics before implementation.
