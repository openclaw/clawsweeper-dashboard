## What This Changes

Add a configurable pre-timeout warning that lets sub-agents checkpoint work before the existing hard `runTimeoutSeconds` termination.

## System Context

Sub-agent spawning accepts an optional wall-clock timeout and runs child work through either the native gateway path or ACP runtime path. Each path currently enforces the deadline and then performs completion or cleanup handling; the requested feature would need to send a reliable child-facing warning before that deadline.

## Best Possible Solution

Define one documented pre-timeout warning contract, including default/override behavior and native-versus-ACP delivery guarantees, then implement it with focused lifecycle tests while preserving existing hard-timeout recovery.

## Maintainer Decision

Question: Should OpenClaw add a persistent configurable pre-timeout warning for sub-agents, and must that guarantee apply equally to native and ACP child runtimes before the setting is exposed?

Rationale: The feature adds a public configuration and lifecycle contract whose warning semantics, default, and unsupported-runtime behavior cannot be safely inferred from the existing hard-timeout implementation.

Likely owner: steipete

Owner reason: Recent ownership evidence spans the native spawn, ACP spawn, timeout announcement, and configuration boundaries that must agree on the policy.

Owner confidence: high

Options:

- **Define a cross-runtime warning contract (recommended):** Add a documented default plus optional per-spawn control, with an explicit delivery guarantee or fallback for both native and ACP children.
- **Keep the hard timeout only:** Decline a new warning contract and retain prompt-level checkpoint guidance plus existing post-timeout recovery.
- **Start with a native-only experiment:** Implement native child-session warning delivery first, but defer any public setting until ACP semantics are designed.

No live reproduction was established in this read-only review. Source evidence supports the current hard timeout path and the absence of a child-facing grace-warning contract, but proving runtime timing behavior requires a controlled sub-agent run.

## Solution Assessment

Unclear until a maintainer chooses the public contract. A shared lifecycle design is preferable to separate native and ACP ad hoc timers because both paths must preserve deadline, cleanup, and parent-notification invariants.
