## What This Changes

Add a configurable warning before a sub-agent’s hard run timeout so the child can checkpoint or report progress before termination.

## System Context

Sub-agent execution starts from the agent tool and resolves a total runtime deadline from sub-agent configuration before dispatching native gateway or ACP work. The deadline ends a child run and feeds completion/timeout handling back to the parent session; the requested feature would add a warning phase before that hard stop.

## Best Possible Solution

Define one documented core pre-timeout-warning contract before implementation: default it off or otherwise preserve existing timeout behavior, deliver a reliable native child control message, specify ACP capability/fallback semantics, and add focused lifecycle tests and docs for both normal completion and hard timeout.

Options:

- **Native-only capability first:** Implement a warning only for native child sessions and document ACP as unsupported until its control-message contract is available.
- **Keep hard timeout only:** Decline a new warning surface and continue relying on existing completion/timeout recovery behavior and prompt-level checkpoint guidance.

## Solution Assessment

Unclear until maintainers choose the public contract. A warning can be the right solution, but it should be one lifecycle design across native and ACP capability boundaries rather than an uncoordinated extra timeout setting.
