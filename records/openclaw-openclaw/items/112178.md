## Summary

Keep this PR open for security-owner review and contributor proof. The source confirms that current main already applies `agents.defaults.sandbox` through the sandbox resolver, while tool-policy and sender-policy resolution ignore a missing agent’s defaults; the proposed tool-policy hardening is plausible, but it introduces a public containment-default contract without documenting its precedence or demonstrating it in a real configured runtime.

## What This Changes

The PR adds `agents.defaults.tools` to config schema/types and applies default tools and sandbox settings when an agent entry omits them or an agent ID is absent from `agents.list`.

## Best Possible Solution

Approve one explicit unknown-agent containment policy, document `agents.defaults.tools` precedence alongside global and per-agent policies, and land only after a redacted real runtime proof shows the declared default deny and sandbox behavior for both a list-omitted and a missing agent ID.
