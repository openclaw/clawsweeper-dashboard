## Summary

Current main still appears to omit cross-message pairing for this native transcript shape: the extractor creates input-bearing cards from an assistant message and output-only cards from a standalone result message, without a shared call-id join. Likely related people: mickahouan is a low-confidence adjacent Control UI chat contributor from prior UI history.

## What This Changes

Render the stored tool-call arguments alongside the separately stored native-runtime tool result in Control UI tool cards.

## Best Possible Solution

Add a transcript-level join keyed by `toolCall.id`/`toolCallId` before rendering the result card, with regression coverage for separate native assistant and tool-result messages plus repeated same-name calls.
