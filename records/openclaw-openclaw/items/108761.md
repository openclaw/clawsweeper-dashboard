## Summary

Keep this PR open for merge review: current main still reads Vault credential files without a size bound, while the focused patch uses the repository’s existing strict secret-file contract and provides convincing before/after runtime proof. No correctness or security defect was found; maintainers should explicitly accept the new fail-closed 16 KiB compatibility boundary.

## What This Changes

The PR replaces unbounded Vault token and workload-JWT file reads with the shared 16 KiB fs-safe secret reader and adds regression coverage for oversized files.

## Best Possible Solution

Land the shared bounded-reader implementation after accepting the 16 KiB credential limit, preserving the tested symlink, hardlink, missing, and empty-file behavior and documenting the limit in the Vault operator guide if maintainers expect nonstandard large JWT deployments.
