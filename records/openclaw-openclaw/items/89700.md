## Summary

Keep open: current main and v2026.7.1 still expose and write the legacy exec-policy keys, and the documented `exec-policy preset yolo` path can produce a schema-invalid mixed configuration when `tools.exec.mode` already exists. The linked closing PR remains open with unresolved upgrade-safety proof and a known migration blocker, while the protected `maintainer` label requires explicit human handling. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/config/types.tools.ts))

## What This Changes

Remove `tools.exec.security` and `tools.exec.ask` from steady-state configuration, migrate existing values through doctor, and make runtime and CLI paths consume only canonical `tools.exec.mode`.

## Best Possible Solution

Adopt one canonical mode-only configuration contract, but first approve an exact semantics table for all shipped legacy combinations; then make doctor migrate and validate those shapes, make every config writer remove legacy keys, retain raw security/ask only in the separate host approvals store, and prove fresh and upgraded yolo, cautious, deny, sandbox ask-only, per-agent, and Codex paths with redacted live CLI output.
