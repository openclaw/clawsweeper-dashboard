Full review comments:

- **[P2] Avoid stopping again after max-duration info:** `apps/android/app/src/main/java/ai/openclaw/app/chat/VoiceNoteRecorderController.kt:99`
  - body: The max-duration info callback routes into `finish()`, whose first real action is `engine.stop()`. Android's `setMaxDuration` contract says the platform stops recording asynchronously when this info fires, so on devices where the recorder has already left the recording state, `stop()` throws, this code deletes the temp file, and a user who records to the cap loses the note. Use an app-owned timer or a max-duration finalization path that does not call `stop()` again after the platform cap fires.
  - confidence: 0.87
