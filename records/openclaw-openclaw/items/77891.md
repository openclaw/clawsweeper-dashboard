## Summary

Keep open: the narrow cleanup-time stale-binding repair is useful, but the current patch still has a blocking session-state compatibility issue because explicit offline `--store` cleanup can remove process-global conversation bindings by session key only.

## What This Changes

The PR adds an unbind call after missing-transcript session cleanup removes store rows and adds focused cleanup-service tests for that behavior.

## Best Possible Solution

Keep the cleanup-time stale-binding repair, but scope binding removal to the matching active/default store context and keep broader route-time and stuck-session follow-up explicit before closing the canonical issue.

## Reproduction Assessment

Yes, source-level: current main can apply missing-transcript removals without unbinding matching current-conversation records, and the PR's `--store` regression follows from the CLI and binding-store code paths.

## Solution Assessment

No as submitted. Cleanup-time unbinding is the right invariant for live/default cleanup, but it needs active-store scoping before it is the safest maintainable fix.
