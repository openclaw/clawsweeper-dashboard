## Summary

Keep open for a narrow correctness repair: the approach is well motivated and strongly exercised, but the single-flight teardown leaves a small interval where a new mock-resolution caller can be released without its queued mock being drained.

## What This Changes

The PR wraps Vitest mock resolution with per-worker serialization for non-isolated shared test workers and adds focused concurrency regression tests.

## Best Possible Solution

Keep the runner-owned workaround but make it generation-aware so every caller arriving before the shared promise settles forces another drain, add a regression test for the post-drain/pre-finally handoff, and file the minimized race upstream with Vitest.
