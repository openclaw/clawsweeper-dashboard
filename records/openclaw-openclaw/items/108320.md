## Label Justifications

- `P1`: A real Feishu workflow can intermittently discard authorized inbound messages without feedback, matching an urgent broken-channel reliability issue.
- `impact:message-loss`: After retry exhaustion, the Feishu handler logs the dispatch error and permanently loses the inbound message.
- `impact:session-state`: The loss occurs when reply-session initialization cannot commit after its bounded conflict retries.

## Summary

Keep open: current main performs bounded session-initialization retries, but Feishu still only logs and returns when those retries are exhausted, leaving a source-reproducible silent message-loss path that merged Slack and Signal fixes handle at the channel boundary.

## What This Changes

Prevent Feishu inbound messages from being silently lost when reply-session initialization conflicts exhaust their retries.

## Best Possible Solution

Add a Feishu-owned, abort-aware bounded retry around the retained original inbound payload with same-conversation ordering, then send a visible resend notice if terminal exhaustion remains; reuse the shared conflict classifier and add no new configuration.
