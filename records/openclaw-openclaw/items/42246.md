## Summary

Keep open: current main still has direct Telegram outbound delivery, durable caller-provided batching, throttling, and retry_after handling, but it does not implement configurable timed digest aggregation for independent outbound Telegram notifications; the remaining work needs maintainer product/config direction.

## What This Changes

Add opt-in configurable batching/digest aggregation for outbound Telegram notifications so bursty automation can send fewer grouped messages.

## Best Possible Solution

Define an opt-in Telegram-owned or shared outbound digest policy that keeps immediate delivery as the default, persists pending digest state when durability is required, and flushes through the existing durable delivery and Telegram throttling paths.
