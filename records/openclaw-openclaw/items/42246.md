## Summary

Keep open: current main still has direct Telegram outbound delivery, chunking, durable send batching for concrete payloads, and retry_after-aware throttling, but no opt-in timed digest layer that groups independent outbound notifications over a window.

## What This Changes

The issue requests opt-in Telegram outbound notification batching that groups independent short events into digest messages over a configurable window.

## Best Possible Solution

Define an opt-in Telegram-owned or shared outbound digest policy that keeps immediate delivery as the default, persists pending digest state when durability is required, and flushes through existing durable delivery and Telegram throttling.
