## Summary

Keep open: current main and latest release still lack configurable outbound Telegram notification digest aggregation. The existing implementation has direct Telegram sends, durable payload batches, transport throttling/retry behavior, streaming-progress coalescing, inbound media-group buffering, and error suppression, but none of those collect independent outbound notifications over a timed window into grouped digest messages.

## What This Changes

Request configurable outbound Telegram notification batching/digesting so bursts of automated events can be grouped before delivery.

## Best Possible Solution

Define a maintainer-approved digest policy seam above final Telegram transport, persist pending digest state in SQLite when durability is required, and route completed digest payloads through the existing durable delivery and throttled Telegram send paths.

## Reproduction Assessment

Yes, at source level: current Telegram delivery sends caller-provided payloads directly through durable delivery/throttling paths, and the Telegram config/docs expose no digest batching surface. I did not run a live Telegram flood scenario because the missing behavior is clear from current source and docs.

## Solution Assessment

No, not as a Telegram-local ring buffer alone. The best solution is a policy seam above final Telegram transport so grouping, urgent bypass, media/thread targets, persistence, and shutdown flush are decided before delivery.
