## Summary

Keep open: current main still has direct Telegram durable sends, chunking, retry_after-aware throttling, and a cosmetic per-turn progress summary, but no opt-in timed outbound notification digest that groups independent events over a window.

## What This Changes

Request an opt-in configurable batching layer that aggregates outbound Telegram notifications into digest messages instead of sending every event immediately.

## Best Possible Solution

Define an opt-in Telegram-owned or shared outbound digest policy that keeps immediate delivery as the default, persists pending digest state when durability is required, and flushes through existing durable delivery and Telegram throttling.
