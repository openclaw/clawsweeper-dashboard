## Summary

Keep open: current main still lacks an opt-in timed Telegram notification digest; the existing durable send queue, chunking, throttling, and retry_after handling do not aggregate independent outbound notifications.

## What This Changes

The issue requests configurable outbound Telegram notification batching so bursts of task, cron, skill, or agent updates can be delivered as grouped digest messages instead of immediate one-message-per-event sends.

## Best Possible Solution

Define an opt-in Telegram-owned or shared outbound digest policy that keeps immediate delivery as the default, persists pending digest state when durability is required, and flushes through existing durable delivery and Telegram throttling.
