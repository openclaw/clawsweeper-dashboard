## Summary

Keep open: current main and v2026.6.11 still lack timed outbound Telegram digest aggregation, and the remaining work needs maintainer direction on owner boundary, config shape, urgency bypass, media/thread semantics, and durable flush behavior.

## What This Changes

The issue requests an opt-in Telegram outbound notification batching layer that groups many short automation events into digest messages instead of sending every event immediately.

## Best Possible Solution

Define an opt-in digest policy seam above final Telegram transport, persist pending digest state in SQLite when durability is required, and route completed digest payloads through the existing durable delivery and throttled Telegram send paths.
