## Summary

Keep open: current main still lacks an opt-in timed Telegram digest/aggregation policy for independent outbound notifications; existing chunking, durable send, retry_after handling, and per-token/per-chat throttling do not merge multiple notification bodies into fewer digest messages.

## What This Changes

Request an opt-in configurable batching layer that aggregates outbound Telegram notifications into digest messages instead of sending every event immediately.

## Best Possible Solution

Define a default-off Telegram-owned or shared outbound digest policy that preserves existing durable delivery and throttling, uses SQLite-backed state when durability is required, and has explicit urgent bypass and media/thread semantics.
