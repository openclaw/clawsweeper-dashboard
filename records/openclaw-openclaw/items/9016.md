## Summary

Keep open: current main has adjacent local estimated-cost support and OpenRouter billed-total reconciliation, but it still does not expose provider-reported OpenRouter cost metadata, units/source, or cost details through agent runtime or session_status.

## What This Changes

Issue requests exposing OpenRouter provider-reported usage cost data to agent runtime/session metadata so agents can report per-reply cost.

## Best Possible Solution

Define an additive provider-reported cost metadata contract, capture OpenRouter raw usage at the transport/provider boundary, persist it separately from local estimates, and expose per-turn/cumulative values through agent runtime and session_status before channel rendering consumes them.

## Reproduction Assessment

Yes. Source inspection is sufficient: current main captures a single OpenRouter billed total in message usage, but the public runtime/session contracts expose token fields and local estimatedCostUsd rather than provider-reported cost metadata.

## Solution Assessment

Unclear until maintainers choose the public contract. Relabeling estimatedCostUsd would be the wrong fix because exact OpenRouter charges need separate source, units, and cost_details semantics.
