## Summary

Keep open: current main has local estimated-cost reporting and an OpenRouter billed-total reconciliation, but it still does not expose provider-reported cost metadata, source/units, or cost details through agent runtime or session_status.

## What This Changes

The issue requests exposing OpenRouter provider-reported per-response cost data to agent runtime/session metadata so channels can show exact costs.

## Best Possible Solution

Define an additive provider-reported cost metadata contract, capture OpenRouter raw usage at the provider/transport boundary, persist it separately from local estimates, and expose per-turn/cumulative values through agent runtime and session_status before channel rendering consumes them.

- **Add exact provider-cost metadata (recommended):** Expose OpenRouter raw `usage.cost`, source/units, and `cost_details` as a separate additive contract alongside existing estimated USD fields.
- **Fold into broader usage API:** Keep this issue open but resolve it through the broader session_status/runtime usage API work so token, exact cost, and model attribution share one contract.
- **Defer exact provider billing:** Keep OpenClaw on local estimated costs only and close or deprioritize exact OpenRouter billing visibility as out of product scope.

## Reproduction Assessment

Yes. Source inspection is sufficient: current main captures at most a single OpenRouter billed total and otherwise exposes token fields plus local estimatedCostUsd, not provider-reported cost metadata.

## Solution Assessment

Unclear until maintainers choose the public contract. Relabeling estimatedCostUsd would be the wrong fix; exact OpenRouter charges need separate source, units, and cost_details semantics.
