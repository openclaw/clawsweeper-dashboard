## Summary

Keep this issue open: current main has adjacent OpenRouter billed-total reconciliation and local estimated-cost/status surfaces, but it still does not expose provider-reported OpenRouter cost metadata with source, units, or `cost_details` through agent runtime or `session_status`.

## What This Changes

Expose OpenRouter per-response `usage.cost` and related cost details to agents so replies and session tools can show exact provider-reported cost.

## Best Possible Solution

Define an additive provider-reported cost metadata contract with explicit source and units, capture OpenRouter cost fields at the provider/transport boundary, persist them through transcript/session/runtime metadata, and let `session_status` or a dedicated usage tool expose exact cost when available with estimated-cost fallback.

## Reproduction Assessment

Yes, at source level: current main reconciles an OpenRouter billed total internally, but the public runtime/session contracts still expose token fields and local estimated cost rather than provider-reported cost metadata. I did not run a live OpenRouter request in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract; relabeling `estimatedCostUsd` would be the wrong fix because exact OpenRouter charges need separate source and unit semantics. The maintainable path is an additive provider-reported cost contract consumed by status/tool/channel surfaces.
