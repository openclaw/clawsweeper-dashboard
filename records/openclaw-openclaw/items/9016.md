## Summary

Keep this issue open for a maintainer product decision. The merged OpenRouter cache-write/accounting correction fixes underlying token-accounting defects, but the evidence still distinguishes OpenClaw’s local estimates from the requested provider-reported per-response charge exposed to agents and session tools; no canonical merged item establishes that public runtime contract.

## What This Changes

Expose OpenRouter’s provider-reported per-response cost to agent runtime and session-facing usage surfaces so agents can report exact turn and cumulative charges.

## System Context

OpenRouter is configured through OpenClaw’s OpenAI-compatible provider transport, which receives streaming response usage and normalizes it for agent runs and session accounting. That normalized data feeds session status and optional reply usage presentation, but the requested feature would additionally preserve provider-billed cost provenance for agent-visible use.

## Architecture Diagram

flowchart LR
  A[OpenRouter response stream] --> B[OpenAI-compatible transport]
  B --> C[Normalized token usage]
  C --> D[Agent run metadata]
  C --> E[Session usage accounting]
  D --> F[Agent tools and status]
  E --> G[Reply and session displays]

## Best Possible Solution

Define one provider-neutral, optional exact-cost representation that keeps provider-reported charges separate from estimated USD cost, then carry it from the transport boundary through run/session usage into an agent-readable per-turn and cumulative surface; channel rendering should consume that shared surface rather than introduce Telegram-specific accounting.
