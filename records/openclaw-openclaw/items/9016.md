## Label Justifications

- `P2`: This is a normal-priority provider/session observability feature with clear cost-transparency value but no current outage, data loss, security bypass, or crash loop.
- `impact:session-state`: The requested exact cost metadata needs to flow through runtime/session metadata, transcripts, and `session_status` so agents can inspect per-turn and cumulative state.
- `impact:auth-provider`: The gap is provider-specific OpenRouter billing metadata and exact-versus-estimated attribution in the model/provider path.

## Summary

Keep open: current main has local estimated-cost reporting and an OpenRouter generation-total reconciliation, but it still does not expose OpenRouter provider-reported `usage.cost`, `cost_details`, source/units, or upstream inference cost through agent runtime or session metadata.

## What This Changes

Expose OpenRouter provider-reported per-response cost metadata to agents so replies and session/status surfaces can show exact OpenRouter costs.

## Best Possible Solution

Define an additive provider-reported cost metadata contract, capture OpenRouter raw usage at the provider/transport boundary, persist it separately from local estimates, and expose per-turn/cumulative values through agent runtime and `session_status` before channel rendering consumes them.

- **Keep estimates only:** Document current local estimated-cost behavior and leave exact provider-billing capture to external plugins or future ClawHub accounting integrations.

## Reproduction Assessment

Yes. Source inspection shows current main captures local estimated cost and a single OpenRouter billed total, but public runtime/session contracts expose token fields and `estimatedCostUsd` rather than provider-reported cost metadata.

## Solution Assessment

Unclear until maintainers choose the public contract. Relabeling `estimatedCostUsd` would be the wrong fix; exact OpenRouter charges need separate source, units, and `cost_details` semantics.
