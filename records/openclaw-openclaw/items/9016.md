## Summary

Keep this issue open. Current main now captures and aggregates OpenRouter’s provider-reported billed total, but the requested exact value is still not established as part of the agent-callable session status/runtime contract; selecting that public API and its exact-versus-estimated semantics requires maintainer direction.

## What This Changes

Expose OpenRouter’s provider-reported per-response cost to agent runtime and session status for per-turn and cumulative reporting.

## Best Possible Solution

Define one channel-neutral usage contract that preserves provider-reported billed cost separately from local estimates, identifies source and currency, handles authoritative zero values, and exposes both last-turn and cumulative values to agents; Telegram and other channels can render that shared data without owning accounting policy.
