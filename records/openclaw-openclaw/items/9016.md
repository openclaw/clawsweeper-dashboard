## Summary

Keep open: the checked-out main and v2026.6.11 still provide local estimated-cost/session usage surfaces and OpenRouter generation total reconciliation, but not the requested provider-reported `usage.cost` / `cost_details.upstream_inference_cost` contract through agent runtime or `session_status`.

## What This Changes

Expose OpenRouter response-level cost data to agent runtime/session metadata so agents can show exact per-reply costs.

## Best Possible Solution

Define an additive provider-reported cost metadata contract with source and units, preserve it separately from local estimates, and expose it consistently through transcript/session/runtime/status surfaces before channels render it.

Options:

- **Add exact-cost metadata contract (recommended):** Expose provider-reported cost as additive structured metadata with source, units, raw details, and fallback to existing local estimates when exact data is unavailable.
- **Keep exact cost outside core:** Leave core on estimated cost fields and route exact OpenRouter accounting to a plugin or external ledger surface until a broader accounting contract exists.
- **Fold into broader usage ledger:** Defer this issue until the native per-call usage ledger and agent-facing usage API define the shared cost metadata contract.

## Reproduction Assessment

Yes, at source level. Current main shows OpenRouter only reconciles a total/local cost field while agent metadata and session status expose token/local-estimate surfaces without raw provider-cost details.

## Solution Assessment

No current implementation fully solves it. The best path is an additive exact-cost metadata contract, not relabeling `estimatedCostUsd` or adding a Telegram-only footer.
