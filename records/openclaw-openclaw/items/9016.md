## Summary

This issue remains necessary: current main captures OpenRouter-compatible provider-billed totals in transcript usage, but agent-facing normalized usage still omits cost, and no related item fully owns that exact remaining gap.

## What This Changes

Expose OpenRouter’s provider-reported per-response cost and optional upstream cost details to agent runtime and session usage surfaces.

## Best Possible Solution

Thread the existing authoritative `usage.cost.total` and `provider-billed` provenance through a shared per-turn/session usage snapshot and expose it through `session_status` or the canonical usage tool; add OpenRouter-specific detail fields only after an explicit portable metadata decision.

- **Keep details provider-owned:** Expose the shared total in core and leave richer OpenRouter accounting to a provider/plugin-owned runtime API.

## Solution Assessment

Partly yes: exposing authoritative provider cost is the right direction, but the narrowest maintainable implementation reuses the shared usage contract rather than creating an OpenRouter-only side channel. Provider-specific upstream-cost details require a separate product choice.
