## Summary

Keep open: current main has local estimated-cost surfaces and an OpenRouter wrapper that reconciles one billed total into message usage, but it still does not expose provider-reported OpenRouter usage cost, source/units, or upstream cost details through the agent runtime or session status contract.

## What This Changes

Request to expose exact OpenRouter usage-cost metadata to agents and session status instead of only token counts or locally estimated costs.

## Best Possible Solution

Define an additive provider-reported cost metadata contract, capture OpenRouter raw usage at the OpenAI-compatible/OpenRouter boundary, preserve it separately from local estimates with explicit source and units, persist it through transcript/session metadata, and expose per-turn and cumulative values through agent runtime and session_status.

## Reproduction Assessment

Yes. Source inspection reproduces the gap: current main captures a single OpenRouter billed total in message usage, while public runtime and session contracts expose token fields and local estimatedCostUsd rather than provider-reported cost metadata or cost details.

## Solution Assessment

Unclear until maintainers choose the public contract; relabeling estimatedCostUsd would be the wrong fix because exact OpenRouter charges need separate source, units, detail, and fallback semantics.
