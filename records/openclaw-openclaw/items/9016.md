## Summary

Keep open: current main has OpenRouter billed-total reconciliation and local estimated-cost display, but it still does not expose OpenRouter provider-reported cost metadata with source/units through agent runtime or session_status.

## What This Changes

Request to capture OpenRouter provider-reported per-message cost/usage metadata and expose it to agents or session status for cost-aware replies.

## Best Possible Solution

Define an additive provider-reported cost metadata contract with explicit source and units, capture OpenRouter streaming and non-streaming cost fields at the provider boundary, persist them through transcript/session/runtime metadata, and render exact costs only when available with estimated-cost fallback.

## Reproduction Assessment

Yes, at source level: current main reconciles an OpenRouter billed total into assistant message usage, but the public agent/session contracts only expose token counts and locally estimated cost fields. I did not run a live OpenRouter request in this read-only review.

## Solution Assessment

No current implementation fully solves this. The maintainable solution needs a provider-neutral exact-cost metadata contract before Telegram, session_status, plugin hooks, or status rendering consume the data.
