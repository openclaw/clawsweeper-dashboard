## Summary

Keep open: current main has local estimated-cost reporting and an OpenRouter billed-total reconciliation, but it still does not expose OpenRouter provider-reported cost metadata, source/units, or cost details through agent runtime or session_status.

## What This Changes

Request to expose OpenRouter per-response usage cost to agent runtime/session metadata so agents and channels can display exact per-turn and cumulative cost.

## Best Possible Solution

Define an additive provider-reported cost metadata contract, capture OpenRouter raw usage at the provider/transport boundary, persist it separately from local estimates, and expose per-turn/cumulative values through agent runtime and session_status before channel rendering consumes them.

## Reproduction Assessment

Yes. Source inspection is sufficient: current main captures a single OpenRouter billed total in message usage, but the public runtime/session contracts expose token fields and local estimatedCostUsd rather than provider-reported cost metadata.

## Solution Assessment

Unclear until maintainers choose the public contract. Relabeling estimatedCostUsd would be the wrong fix; exact OpenRouter charges need separate source, units, and cost_details semantics.
