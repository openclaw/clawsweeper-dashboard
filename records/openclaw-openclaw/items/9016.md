## Summary

Keep open: current main has partial OpenRouter billed-total reconciliation and local estimated-cost surfaces, but the requested provider-reported cost metadata is still not available through agent runtime or session_status.

## What This Changes

Request to capture OpenRouter provider-reported per-response usage cost and expose it to agents/session status for per-turn cost display.

## Best Possible Solution

Define an additive provider-reported cost metadata contract, capture OpenRouter raw usage at the transport/provider boundary, persist it separately from local estimates, and expose per-turn/cumulative values through agent runtime and session_status before channels render it.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What provider-reported cost metadata contract should OpenClaw expose for OpenRouter responses, and which runtime/session surfaces should consume it?

Rationale: The remaining change defines stable semantics for exact versus estimated cost, units/source, raw cost_details, persistence, and agent-facing API shape; automation should not choose that product/API contract.

Likely owner: steipete

Owner reason: steipete has the strongest recent history across OpenRouter billed-cost reconciliation, usage-cost reporting, and the runtime/session files that would define the contract.

Owner confidence: high

Options:

- **Define Additive Exact-Cost Metadata (recommended):** Add separate provider-reported cost fields with source and units, then thread them through transcript/session/runtime/status surfaces while preserving existing local estimates.
- **Limit Core To Local Estimates:** Keep OpenClaw's core cost surfaces estimate-based and point exact OpenRouter charge display to a plugin or external accounting layer.
- **Defer To Broader Usage API:** Leave this issue open but fold the implementation into a broader structured session usage API such as the related session_status usage work.

## Reproduction Assessment

Yes, at source level. Current main captures only a single OpenRouter billed total in message usage and exposes token/local-estimate fields through runtime/session contracts, not raw provider-reported `usage.cost` and `cost_details`.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable path is separate provider-reported metadata with source/units rather than relabeling `estimatedCostUsd` or adding a Telegram-only footer.
