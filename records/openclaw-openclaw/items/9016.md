## Summary

Keep open: current main has local estimated-cost reporting and an OpenRouter generation-total reconciliation path, but it still does not expose provider-reported OpenRouter `usage.cost`, `cost_details.upstream_inference_cost`, source, or units through agent runtime/session metadata. Related open issues and PRs cover resolved model identity, structured session usage, auth-profile attribution, native ledgers, or plugin pricing helpers, but none replaces this exact provider-cost metadata request.

## What This Changes

Expose OpenRouter provider-reported per-response cost data to agent runtime or session metadata so agents can surface exact cost information in replies.

## Best Possible Solution

Define an additive provider-reported cost metadata contract with explicit source and units, capture OpenRouter streaming and non-streaming cost fields at the provider boundary, persist them through transcript/session/runtime metadata, and render exact costs only when available with estimated-cost fallback.

## Reproduction Assessment

Yes. Source inspection on current main shows OpenRouter billed totals can be reconciled internally, while the public runtime/session contracts only expose token counts and locally estimated cost fields; no live OpenRouter call was run in this read-only pass.

## Solution Assessment

No current implementation fully solves it. The maintainable fix needs a maintainer-approved exact-cost metadata contract before Telegram, `session_status`, `/usage`, plugins, or status rendering consume the data.
