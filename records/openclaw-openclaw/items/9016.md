## Summary

Keep open: current main has adjacent OpenRouter billed-total reconciliation and local estimated-cost displays, but the requested provider-reported OpenRouter cost metadata is still not exposed through agent runtime or session_status with source, units, and cost_details semantics.

## What This Changes

The issue requests capturing OpenRouter provider-reported usage cost from responses and exposing per-turn and cumulative cost metadata to agent runtime/session surfaces so channels like Telegram can show exact reply cost.

## Best Possible Solution

Define an additive provider-reported cost metadata contract, capture OpenRouter raw usage at the transport/provider boundary, persist it separately from local estimates, and expose per-turn and cumulative values through agent runtime and session_status before channel rendering consumes them.

## Reproduction Assessment

Yes. Source inspection on current main shows the OpenRouter wrapper can patch one billed total, while the public runtime/session contracts expose token fields and local estimatedCostUsd rather than provider-reported cost metadata.

## Solution Assessment

Unclear until maintainers choose the public contract. Relabeling estimatedCostUsd would be the wrong fix; the maintainable path is an additive exact-cost metadata contract with explicit source, units, fallback, and cost_details semantics.
