## Summary

Keep open: current main has OpenRouter billed-cost reconciliation and local estimated-cost displays, but it still does not expose provider-reported OpenRouter cost metadata, source/units, or cost details through agent runtime or session_status.

## What This Changes

Request to capture OpenRouter per-response usage.cost and cost_details and expose per-turn/cumulative cost data to agents and channel replies.

## Best Possible Solution

Define an additive provider-reported cost metadata contract, capture OpenRouter raw usage at the transport/provider boundary, persist it separately from local estimates, and expose per-turn/cumulative values through agent runtime and session_status before channel rendering consumes them.

## Reproduction Assessment

Yes, source inspection is sufficient: current main captures a single OpenRouter billed total in message usage, but the public runtime/session contracts expose token fields and local estimatedCostUsd rather than provider-reported cost metadata. I did not run a live OpenRouter request in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract; relabeling estimatedCostUsd would be the wrong fix because exact OpenRouter charges need separate source, units, and cost_details semantics. The maintainable path is an additive provider-reported cost contract consumed by status, tool, and channel surfaces.
