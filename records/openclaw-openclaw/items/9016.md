## Summary

Keep this issue open for a maintainer product decision. Current documentation still distinguishes the reply/footer and session-cost values as locally estimated, while this request is specifically for an OpenRouter-reported charge and its provenance to be available to agent runtime; the related OpenRouter transcript-cost correction does not establish that public agent contract.

## What This Changes

Expose OpenRouter-reported per-response cost data, including aggregate per-turn/session values, to the agent runtime so replies can show exact OpenRouter charges.

## Best Possible Solution

Define one provider-neutral usage-cost contract that carries an optional provider-reported USD charge with source/precision metadata separately from the existing local estimate; capture it for OpenRouter at the transport boundary, aggregate it through transcript/session metadata, and let channel or plugin presentation render it without adding a Telegram-only core policy.
