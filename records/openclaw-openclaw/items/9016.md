## Summary

Keep open: current main has an adjacent OpenRouter billed-total reconciliation path, but it still does not expose provider-reported OpenRouter cost metadata, source/units, or cost details through agent runtime or session_status for agents to use.

## What This Changes

The issue requests capturing OpenRouter provider-reported per-message cost fields and exposing them to agent runtime or session metadata for per-reply cost reporting.

## Best Possible Solution

Define an additive provider-reported cost metadata contract, capture OpenRouter raw usage at the provider/transport boundary, persist it separately from local estimates, and expose per-turn/cumulative values through agent runtime and session_status before channel rendering consumes them.

## Reproduction Assessment

Yes. Source inspection reproduces the gap: current main captures a single OpenRouter billed total in assistant message usage, but the public runtime/session contracts expose token fields and local estimated cost rather than provider-reported cost metadata.

## Solution Assessment

Unclear until maintainers choose the public contract; relabeling estimatedCostUsd would be the wrong fix because exact OpenRouter charges need separate source, units, and cost_details semantics.
