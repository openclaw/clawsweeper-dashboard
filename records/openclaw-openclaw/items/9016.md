## Label Justifications

- `P2`: This is a normal-priority provider/session observability feature with clear user value but no outage, data loss, or security emergency.
- `impact:session-state`: The requested data must flow through session/runtime metadata and session_status so agents can inspect per-turn and cumulative cost state.
- `impact:auth-provider`: The missing signal is provider-specific OpenRouter billing metadata and exact-versus-estimated attribution in the model/provider path.

## Summary

Keep open: current main and the latest stable release have adjacent OpenRouter cost reconciliation and local estimated-cost reporting, but they still do not expose provider-reported OpenRouter cost metadata, source/units, or cost_details through agent runtime or session_status.

## What This Changes

Expose OpenRouter provider-reported per-response usage cost and cost_details to agents/runtime/session_status so replies can show exact per-turn costs.

## Best Possible Solution

Define an additive provider-reported cost metadata contract with explicit source and units, capture OpenRouter cost fields at the provider/transport boundary, persist them separately from local estimates, and expose per-turn/cumulative values through agent runtime and session_status before channels render them.

## Reproduction Assessment

Yes, source-level: current main reconciles OpenRouter billed total into message.usage.cost.total, but Usage, EmbeddedAgentMeta, estimatedCostUsd, and session_status still expose local estimates/token fields rather than provider-reported cost metadata.

## Solution Assessment

Unclear until maintainers choose the public contract; the best direction is an additive provider-reported cost surface rather than reusing estimatedCostUsd for exact charges.
