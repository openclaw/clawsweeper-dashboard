## Summary

Keep open: current main still only reconciles a single OpenRouter billed total into message usage and local estimate displays; it does not expose provider-reported `usage.cost`, source/units, or `cost_details` through agent runtime metadata or `session_status`.

## What This Changes

Request to capture OpenRouter provider-reported per-message usage cost and expose it to agents/session status so replies can show exact costs.

## Best Possible Solution

Define an additive provider-reported cost metadata contract, capture OpenRouter raw usage at the transport/provider boundary, persist it separately from local estimates, and expose per-turn/cumulative values through agent runtime and `session_status` before channel rendering consumes them.

## Reproduction Assessment

Yes. Source inspection is sufficient: current main captures a single OpenRouter billed total in message usage, but the public runtime/session contracts expose token fields and local estimated cost rather than provider-reported cost metadata.

## Solution Assessment

Unclear until maintainers choose the public contract. Relabeling `estimatedCostUsd` would be the wrong fix because exact OpenRouter charges need separate source, units, and `cost_details` semantics.
