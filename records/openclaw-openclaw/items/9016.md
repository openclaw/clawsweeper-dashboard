## Summary

Keep open: current main and the latest release have adjacent estimated-cost reporting and OpenRouter billed-total reconciliation, but they still do not expose provider-reported OpenRouter cost metadata with source, units, or cost_details through agent runtime or session_status.

## What This Changes

Request to expose OpenRouter per-response usage.cost and cost_details to agent/session runtime so replies can display exact provider-reported cost.

## Best Possible Solution

Define an additive provider-reported cost metadata contract with explicit source and units, capture OpenRouter cost fields at the provider/transport boundary, carry them through transcript/session/agent metadata, and let session_status or a dedicated usage tool expose exact cost when available with estimated-cost fallback.

## Reproduction Assessment

Yes, at source level: current main captures or estimates cost in adjacent places, but the public agent/session contracts still expose token fields and estimatedCostUsd rather than provider-reported OpenRouter cost metadata. I did not run a live OpenRouter request in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract; relabeling estimatedCostUsd would not be the best fix because exact OpenRouter charges need separate source and unit semantics. The maintainable direction is an additive provider-reported cost contract consumed by status/tool/channel surfaces.
