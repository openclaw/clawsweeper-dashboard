## Summary

Keep this issue open because current main captures authoritative OpenRouter charges in the provider path but still exposes locally estimated cost through the documented agent-facing usage and session contracts. The remaining work requires an intentional public contract for exact-versus-estimated semantics.

## What This Changes

Expose provider-reported OpenRouter per-response costs to agent runtime and session-facing usage surfaces.

## Best Possible Solution

Add source-tagged exact and estimated values to the canonical per-turn usage contract, aggregate exact OpenRouter charges across calls, persist equivalent session semantics, and let generic renderers use exact cost with an estimate fallback.

Rationale: Current main intentionally exposes estimated USD cost while OpenRouter supplies provider-reported charges that may be reconciled after streaming, so naming, units, fallback, aggregation, and durability require maintainer intent.

Owner confidence: high

Options:

- **Expose both exact and estimated (recommended):** Add source and unit metadata with exact per-call and per-turn provider cost plus the existing estimate fallback across live and durable usage surfaces.
- **Expose exact cost live only:** Add provider cost to live per-turn usage state while deferring durable session-schema expansion to the broader usage API design.
- **Keep estimates canonical:** Retain estimated agent-facing costs and reserve authoritative provider charges for provider-account or transcript-analysis surfaces.

## Reproduction Assessment

Yes, at source level. Current documentation and session types expose estimated cost, while the authoritative OpenRouter charge remains confined to the provider and message path rather than an agent-queryable contract.

## Solution Assessment

The capability is still needed, but an unqualified `cost` field is not the best solution; exact provider charges and local estimates should remain distinct and source-tagged through one reusable usage contract.
