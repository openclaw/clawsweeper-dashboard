## Summary

Keep open: current main has adjacent OpenRouter billed-total reconciliation and estimated-cost surfaces, but it still does not expose provider-reported `usage.cost` / `cost_details.upstream_inference_cost` through agent runtime or `session_status`; related usage, plugin, and ledger items are partial overlaps rather than a replacement for this contract.

## What This Changes

The issue asks OpenClaw to capture OpenRouter provider-reported per-response cost data and expose it to agent runtime/session metadata so agents or channels can display exact costs.

## Best Possible Solution

Define additive provider-reported cost metadata with explicit source and units, preserve it separately from local estimates, and thread it through transcript, session, runtime, and status surfaces before channels render it.

- **Fold Into Broader Usage Ledger:** Defer implementation until the per-call usage ledger and `session_status` usage API define one shared contract for exact and estimated costs.
- **Keep Exact Cost Outside Core:** Leave core on local estimates and require exact OpenRouter accounting to live in a plugin or external ledger surface.

## Reproduction Assessment

Yes, at source level: current main can be inspected to show OpenRouter only reconciles a total into assistant-message cost, while runtime/session surfaces still expose token counters or estimated USD cost rather than exact provider-cost metadata.

## Solution Assessment

Unclear as final product direction: the narrow implementation should be an additive exact-cost metadata contract with estimate fallback, but maintainers still need to choose the public API shape before a fix PR is safe.
