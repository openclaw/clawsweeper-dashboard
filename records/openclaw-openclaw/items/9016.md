## Summary

Keep open: current main has adjacent OpenRouter billed-cost reconciliation, transcript-backed usage aggregation, `/usage cost`, and local estimated-cost display, but it still does not expose provider-reported OpenRouter cost metadata with source, units, or `cost_details` through agent runtime or `session_status`.

## What This Changes

Expose provider-reported OpenRouter per-response cost data to agent runtime/session metadata so agents can report exact per-turn and cumulative cost, including Telegram replies.

## Best Possible Solution

Define an additive provider-reported cost metadata contract with explicit source and units, capture OpenRouter cost fields at the provider/transport boundary, persist them separately from local estimates, and expose per-turn/cumulative values through agent runtime and `session_status` before channel-specific rendering uses them.

## Reproduction Assessment

Yes, at source level: current main has OpenRouter cost reconciliation into `message.usage.cost.total`, but the public runtime/session contracts still expose token fields and local estimated cost rather than provider-reported cost metadata. I did not run a live OpenRouter request in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract; relabeling `estimatedCostUsd` would be the wrong fix because exact OpenRouter charges need separate source and unit semantics. The maintainable path is an additive provider-reported cost contract consumed by status, tool, and channel surfaces.
