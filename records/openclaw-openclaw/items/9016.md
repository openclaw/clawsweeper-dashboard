## Summary

Keep open: current main partially reconciles OpenRouter streamed billing into assistant message usage, but agent runtime, session status, and reply usage surfaces still strip or recompute cost as local estimates rather than exposing provider-reported `usage.cost` / `cost_details` metadata.

## What This Changes

Expose OpenRouter provider-reported per-message cost from API responses to agent runtime or session metadata so agents and channels can render exact costs.

## Best Possible Solution

Define additive provider-reported cost metadata with source and units, keep it separate from local estimates, and thread it through transcript, session/runtime metadata, `session_status` or a usage tool, and channel footer rendering.
