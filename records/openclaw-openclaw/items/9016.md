## Summary

Keep this issue open for a maintainer product decision. Current main can retain token usage and local estimated session cost, but the agent runtime metadata has no provider-reported cost field and session persistence still derives `estimatedCostUsd` from configured pricing; the merged OpenRouter cache-write repair was an adjacent correctness fix, not the requested exact-cost runtime contract.

## What This Changes

Expose OpenRouter’s provider-reported per-response cost to agents so they can use exact per-turn and cumulative charges in runtime or session output.

## System Context

OpenRouter uses OpenClaw’s OpenAI-compatible transport to return usage data after an agent call. That data is normalized into agent-run metadata and session state before tools or channels can display it, so a provider-reported charge needs a deliberate contract across those layers.

## Architecture Diagram

flowchart LR
  A[OpenRouter response or final stream event] --> B[OpenAI-compatible usage parsing]
  B --> C[Normalized call usage]
  C --> D[Agent-run metadata]
  D --> E[Session usage persistence]
  E --> F[Agent status tools and channel presentation]

## Best Possible Solution

Define one optional provider-neutral exact-cost record with explicit source, currency, per-call and cumulative semantics; carry it through normalized usage, agent metadata, and session status, while leaving Telegram/footer rendering to channel or plugin presentation that falls back to the existing estimate when no provider value is available.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a provider-neutral agent/runtime and session-status contract for provider-reported usage charges, with channel/plugin presentation built on top of it?

Rationale: The missing data cannot be safely exposed by a narrow OpenRouter-only patch without deciding the stable semantics for provenance, currency, aggregation, persisted session state, and the distinction from existing estimates.

Likely owner: steipete

Owner reason: The current session-cost and OpenAI-compatible transport paths, plus the earlier maintainer-facing review, make this the strongest available routing candidate.

Owner confidence: high

Options:

- **Adopt a minimal neutral exact-cost contract (recommended):** Add an optional source-tagged, currency-aware reported-cost value through the shared usage, agent metadata, and session-status paths, then let plugins or channels opt into presentation.
- **Keep exact costs outside core:** Document that OpenRouter cost visibility belongs to an external provider/accounting plugin and do not add runtime or session fields.
- **Support estimates only:** Retain the current configured-pricing estimate path and decline provider-reported billing values as a first-class runtime feature.

## Reproduction Assessment

Yes at source level: current-main metadata is token-only and session persistence computes `estimatedCostUsd` from local pricing, so there is no path for an agent to read OpenRouter’s exact reported charge. This read-only review did not make a live OpenRouter request.

## Solution Assessment

Unclear until maintainers choose the public contract. The narrowest maintainable direction is a provider-neutral optional reported-cost record rather than an OpenRouter-only Telegram footer or an overload of the existing estimated-cost field.
