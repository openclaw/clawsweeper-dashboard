## Summary

Keep open: current main and the latest release have adjacent OpenRouter billed-cost reconciliation and local estimated-cost displays, but they still do not expose provider-reported OpenRouter cost metadata, source/units, or `cost_details` through agent runtime or structured session status surfaces.

## What This Changes

The issue asks OpenClaw to capture OpenRouter provider-reported `usage.cost` data and expose per-turn or cumulative cost to agent runtime/session metadata so agents can render exact costs in replies.

## Best Possible Solution

Define one typed provider-reported usage-cost contract with explicit source and units, carry OpenRouter per-call total plus relevant details from the transport/wrapper into agent metadata and session/status surfaces, and keep local `estimatedCostUsd` as a clearly labeled fallback.

## Reproduction Assessment

Yes. Source inspection reproduces the gap: exact OpenRouter billed totals can exist on assistant message usage, but runtime/session metadata and `session_status` only expose token buckets and local estimated cost.

## Solution Assessment

Unclear. The maintainable path needs a maintainer-chosen API contract for exact versus estimated cost, source/units, details, and aggregation before a code repair should be attempted.
