## Summary

Keep open: current main and v2026.6.11 have adjacent OpenRouter total-cost reconciliation and local estimated-cost displays, but they still do not expose OpenRouter provider-reported `usage.cost` / `cost_details.upstream_inference_cost` with source, units, or raw details through agent runtime or `session_status`.

## What This Changes

The issue requests OpenRouter provider-reported per-response usage cost data be exposed to agent runtime/session metadata so agents can display exact cost information.

## Best Possible Solution

Define additive provider-reported cost metadata with explicit source and units, keep it separate from estimated USD, and thread it through transcript, session, runtime, status, and usage-template surfaces before channel footers render it.

- **Keep exact cost outside core:** Leave core on local estimates and route exact OpenRouter accounting to plugin or external ledger surfaces until a broader billing contract exists.
- **Fold into broader usage ledger:** Defer this issue until the native per-call usage ledger and agent-facing usage API define the shared accounting contract.

## Solution Assessment

No current implementation fully solves it; the maintainable path is an additive exact-cost metadata contract with explicit source and units, not relabeling estimated cost fields.
