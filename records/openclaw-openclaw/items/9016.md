## Summary

Keep open: current main has adjacent OpenRouter billed-total reconciliation, local estimated-cost footers, transcript-backed usage summaries, and Gateway `usage.cost`, but it still does not expose OpenRouter provider-reported `usage.cost`/`cost_details` with source and units through agent runtime or session/status metadata.

## What This Changes

Expose OpenRouter provider-reported per-response cost data to agents and session/runtime surfaces so replies can include exact per-turn cost when available.

## Best Possible Solution

Define an additive provider-reported cost metadata contract with explicit source and units, capture OpenRouter usage/cost details at the provider boundary, persist them through transcript/session/runtime metadata, and expose exact cost through `session_status` or a dedicated usage tool with estimated-cost fallback.

## Reproduction Assessment

Yes, at source level: current main reconciles an OpenRouter billed total internally, but the public runtime/session contracts still expose token fields and local estimated cost rather than provider-reported cost metadata. I did not run a live OpenRouter request in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract; relabeling `estimatedCostUsd` would be the wrong fix because exact OpenRouter charges need separate source and unit semantics. The maintainable path is an additive provider-reported cost contract consumed by status, tool, transcript, and channel surfaces.
