## Summary

Keep this issue open. Current main has substantial usage accounting, including transcript-backed cost aggregation and an internal path for OpenRouter billed totals, but the documented agent-facing session and reply contracts still expose locally estimated cost rather than an explicit provider-reported per-call value; choosing that public contract and its exact-versus-estimated semantics requires maintainer direction. ([docs.openclaw.ai](https://docs.openclaw.ai/concepts/usage-tracking))

## What This Changes

Expose OpenRouter’s provider-reported per-response cost to agent-accessible runtime or session metadata for per-turn and cumulative reporting.

## Best Possible Solution

Define one provider-neutral usage-cost object with amount, unit/currency, source, finality, and optional upstream detail; persist it with each call, aggregate it per turn/session, and expose it through `session_status` and the reply-usage contract, preferring finalized provider-reported charges while clearly labeling local estimates as fallback.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should finalized provider-reported per-call costs become part of the canonical agent-facing usage/session contract, and if so how should they take precedence over the existing estimated `cost.turn_usd` value?

Rationale: The repository currently separates provider billing from session estimates, and OpenRouter’s authoritative value may be finalized asynchronously; selecting the public schema, source semantics, and rendering precedence is a product/API decision rather than a mechanical repair.

Likely owner: steipete

Owner reason: They have the strongest combined history across the affected transport, session usage, runtime metadata, documentation, and prior product review.

Owner confidence: high

Options:

- **Add a typed exact-cost contract (recommended):** Expose provider-reported and estimated values in one provider-neutral typed structure, with explicit source, units, and finality, and prefer finalized provider cost when available.
- **Expose a dedicated cost query:** Keep reply and session fields estimate-based, but add an agent-callable tool or RPC for finalized per-call and cumulative provider charges.
- **Keep exact cost operator-only:** Retain provider-reported billing in transcripts and operator usage views without making it available to agents or automatic reply rendering.

## Reproduction Assessment

Yes, at source-contract level: current documentation explicitly describes agent-visible per-turn and session costs as estimated and lists no provider-reported exact-cost field in the usage footer or `session_status` contract. ([docs.openclaw.ai](https://docs.openclaw.ai/concepts/usage-tracking))

## Solution Assessment

The requested outcome is valid, but an OpenRouter-specific field or Telegram-only append path is not the best solution; the maintainable approach is a provider-neutral typed cost contract that preserves exact and estimated values without conflating them.
