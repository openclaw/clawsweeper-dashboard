## Summary

Keep open: current main has OpenRouter billed-total reconciliation and estimated-cost reporting, but it still does not expose OpenRouter provider-reported `usage.cost` / `cost_details.upstream_inference_cost` as additive agent/runtime/session metadata.

## What This Changes

The issue requests per-message OpenRouter provider cost fields to be captured and exposed to agents, session/status surfaces, and channel footers.

## Best Possible Solution

Define additive provider-reported cost metadata with source and units, preserve it separately from local estimates, and thread it through transcript, session, runtime, status, and channel rendering surfaces.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What provider-reported OpenRouter cost metadata contract should OpenClaw expose, and which runtime/session/channel surfaces should consume it?

Rationale: The source gap is clear, but the fix affects public runtime/session semantics, provider-cost precedence, persistence, plugin/channel consumption, and user-facing wording, so automation should not choose the contract alone.

Likely owner: steipete

Owner reason: They have the strongest combined history on OpenRouter billed-cost reconciliation, usage/session persistence, and prior contract review for this issue family.

Owner confidence: high

Options:

- **Add exact-cost metadata contract (recommended):** Expose provider-reported OpenRouter cost as additive structured metadata with source, units, and raw details, while keeping local estimates as fallback display data.
- **Keep exact cost outside core:** Leave core runtime/status surfaces on estimated cost fields and route exact OpenRouter accounting to a plugin or external ledger surface.
- **Fold into broader usage ledger:** Defer this issue until the native per-call usage ledger or resolved-model observability work defines a shared completed-call accounting contract.

## Reproduction Assessment

Yes, at source level: current main can be inspected to show OpenRouter only reconciles a total/local estimate and runtime/session surfaces lack exact provider-cost metadata. I did not run a live OpenRouter call in this read-only review.

## Solution Assessment

No current implementation fully solves it. The best path is an additive exact-cost contract with fallback to existing estimates, not a footer-only display change or a relabeling of `estimatedCostUsd`.
