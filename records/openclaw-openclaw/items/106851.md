## Summary

The linked retry bug is valid and the patch targets the correct classifier, but the new match is broader than the built-in adapter contract and can reintroduce false-positive retries; the external PR also lacks after-fix proof through a real session path.

## What This Changes

The PR adds recognition of transient HTTP statuses inside OpenAI, Azure OpenAI, and Mistral error wrappers and adds focused retry-classifier tests.

## Best Possible Solution

Recognize only the canonical built-in wrapper at the start of the error, add a negative test for incidental embedded `API error (500)` text, and prove that a real session schedules a bounded retry after a wrapped transient response.
