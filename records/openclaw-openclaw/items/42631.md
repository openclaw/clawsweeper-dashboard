## Summary

Keep open: current main still treats explicit main-session systemEvent cron payloads as text-only queued reminders and strips or omits model fields; merged related work covers isolated/agentTurn model selection and UI display, not this main/systemEvent override contract.

## What This Changes

Requested first-class per-job model/provider override support for cron jobs using sessionTarget="main" with payload.kind="systemEvent".

## Best Possible Solution

Maintainers should decide the public cron/session override contract first; if accepted, prefer an explicit top-level or sessionOverride model/provider design with validation, persistence, runtime, UI, docs, and tests over resurrecting the brittle closed payload.model/contextKey attempt.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support model/provider overrides for main-session systemEvent cron jobs, and if so should the contract be payload.model, top-level model/provider, or an explicit sessionOverride block?

Rationale: Current code intentionally separates text-only systemEvent reminders from model-backed agentTurn payloads, and changing that affects provider routing, session override state, validation, persistence, UI, and docs.

Likely owner: vincentkoc

Owner reason: Recent merged cron normalization work preserved the current systemEvent boundary while handling adjacent model override behavior.

Owner confidence: medium

Options:

- **Keep systemEvent text-only:** Close or redirect this request and guide users to isolated or custom-session agentTurn jobs for per-job model selection.
- **Add explicit sessionOverride contract (recommended):** Accept the feature but implement model/provider as a clear cron/session override surface with validation and upgrade-proof tests across main-systemEvent execution paths.
- **Overload systemEvent payload.model:** Allow payload.model on systemEvent, but require a redesigned transport that avoids the closed PR's contextKey coupling and documents why systemEvent now carries model state.

## Reproduction Assessment

Yes from source inspection: systemEvent schemas/types are text-only, normalization prunes model-like fields, persistence stores no payload_model, and main-session execution passes no model/provider override.

## Solution Assessment

Unclear until maintainer direction: current code consistently follows the text-only systemEvent contract, while the requested behavior needs a new explicit cron/session model override contract.
