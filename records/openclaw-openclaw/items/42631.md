## Summary

Keep open. Current main and v2026.6.11 still keep main-session systemEvent cron payloads text-only; merged cron model work covers agentTurn and UI paths but does not add a provider/model override for this route.

## What This Changes

The issue requests job-level provider/model selection for cron jobs that run in the main session with systemEvent payloads.

## Best Possible Solution

Choose one explicit cron-owned override contract, validate provider/model like isolated cron payload models, and prove the override is per-run without leaking into the main session.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support explicit provider/model overrides for main-session systemEvent cron jobs, and should the public contract be payload.model, top-level cron fields, or a sessionOverride block?

Rationale: Current code treats main-session systemEvent jobs as text-only injections, and enabling overrides crosses provider routing, session state, cron persistence, UI/CLI, docs, and heartbeat semantics.

Likely owner: steipete

Owner reason: Recent cron runtime/schema work makes this the strongest available owner for the API and session-state direction decision.

Owner confidence: high

Options:

- **Design explicit override contract (recommended):** Add a public cron-owned provider/model override shape, validate it like isolated cron payload models, and prove both wake-now and next-heartbeat runs isolate state correctly.
- **Keep systemEvent text-only:** Document main-session systemEvent jobs as unsupported for model selection and steer cheap scheduled model calls to isolated/current/custom-session agentTurn jobs.
- **Defer to broader cron API work:** Track this decision with broader cron schema and cost-control work so model, context, timeout, and spend semantics are decided together.

## Reproduction Assessment

Yes, at source level. Current schemas/types keep systemEvent text-only, explicit systemEvent normalization prunes model/provider-like fields, and main-session execution enqueues text without passing a model override.

## Solution Assessment

Unclear until maintainers choose the public contract. payload.model is plausible, but a dedicated cron/session override block may better reflect that systemEvent only queues text and the heartbeat performs the model call.
