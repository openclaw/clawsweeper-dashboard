## Summary

Keep open: current main still has no supported model/provider override path for main-session systemEvent cron jobs. The merged UI and isolated-cron work covers agentTurn/default visibility, but the requested main + systemEvent runtime/API contract remains text-only today.

## What This Changes

Request job-level model/provider selection for cron jobs using `sessionTarget: "main"` and `payload.kind: "systemEvent"`.

## Best Possible Solution

Define one explicit cron override contract, validate it through the normal provider/model allowlist, scope it to only the cron run, then update protocol, normalization, persistence, execution, UI/tool/docs, and focused tests for wake-now and scheduled execution.

Options:

- **Extend systemEvent payload.model (recommended):** Add `payload.model` to systemEvent as the narrowest contract matching agentTurn, with allowlist validation and run-scoped session override behavior.
- **Add a broader job override shape:** Introduce job-level `model`/`provider` or a `sessionOverride` object so multiple payload kinds can share one explicit override model at the cost of a larger schema surface.
- **Keep main systemEvent text-only:** Leave main-session systemEvent jobs on the session default and document isolated agentTurn jobs as the supported model-controlled cron path.

## Reproduction Assessment

Yes, source-level: current schema/type/normalizer keep systemEvent text-only, main jobs require systemEvent, and the main execution path enqueues text without model/provider data.

## Solution Assessment

Unclear until maintainers choose the public contract; `payload.model` is the narrowest shape consistent with agentTurn, but broader job-level or sessionOverride contracts are product choices.
