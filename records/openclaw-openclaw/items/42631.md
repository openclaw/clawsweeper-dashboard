## Summary

Keep open: current `main` and the latest release still keep `systemEvent` cron payloads text-only, while `payload.model` is only honored for `agentTurn`; the central main-session model override request remains a product/API decision.

## What This Changes

Request job-level provider/model selection for cron jobs that run as main-session system events without editing internal session metadata.

## Best Possible Solution

Adopt a maintainer-approved cron model-override contract for main-session system events, then implement schema, runtime heartbeat/session targeting, UI/docs, and regression coverage around that one canonical path.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should main-session `systemEvent` cron jobs support a first-class job-level provider/model override, and if so which cron API surface owns that override?

Rationale: The requested behavior is useful but changes cron job schema, session-state/model-precedence semantics, and the boundary between text-only system events and model-backed agent turns; automation should not choose among those product/API shapes.

Likely owner: steipete

Owner reason: Recent cron protocol/service ownership and broad cron schema changes make this the best available product/API routing owner.

Owner confidence: high

Options:

- **Approve explicit cron execution override (recommended):** Add a canonical validated job-level provider/model override that works for `main + systemEvent` and other payload kinds without mutating session-store metadata.
- **Keep systemEvent model-less:** Document that main-session system events only wake the main session and recommend isolated `agentTurn` for per-job model control once reliability is acceptable.
- **Reuse `payload.model` on systemEvent:** Extend the existing payload field to system events, but require explicit heartbeat/session transport tests so it does not recreate the closed PR's context-key risk.

## Reproduction Assessment

Yes. Source inspection reproduces the missing capability: `systemEvent` payloads are text-only and the main-session cron path never forwards a provider/model override, while `payload.model` is only read for `agentTurn`.

## Solution Assessment

Unclear until maintainers choose the API contract. The best implementation should avoid implicit session-store mutation and use one explicit validated cron override path rather than overloading hidden heartbeat context.
