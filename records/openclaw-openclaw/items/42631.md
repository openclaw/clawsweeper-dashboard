## Summary

Keep open: current main and v2026.6.11 still lack a supported model/provider override for main-session systemEvent cron jobs. The related merged UI work exposes model selection only for agentTurn cron jobs and intentionally omits silent systemEvent jobs.

## What This Changes

The issue requests a supported per-cron model/provider override for `sessionTarget: "main"` plus `payload.kind: "systemEvent"` jobs.

## Best Possible Solution

Define one canonical cron job model/provider override contract, validate it through existing allowlist and fallback rules, and route it into main-session heartbeat execution with schema, runtime, UI, docs, and regression coverage.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should main-session systemEvent cron jobs support a first-class model/provider override, and which single public API shape should own it?

Rationale: The request changes public cron protocol plus provider/session routing semantics, so automation should not choose between `payload.model`, top-level job fields, or a `sessionOverride` block without maintainer intent.

Likely owner: vincentkoc

Owner reason: The current cron schema/type/normalization/main execution lines blame to recent Vincent Koc commits, and the choice is centered on that public cron API/runtime surface.

Owner confidence: medium

Options:

- **Add one canonical job-level override (recommended):** Define a single job-level override contract and pass it through validation and heartbeat execution for main-session systemEvent jobs.
- **Reuse payload.model on systemEvent:** Extend the existing payload field as the smallest schema change, accepting that text-only system events also carry routing metadata.
- **Keep main systemEvent default-only:** Document that cheap per-cron models require isolated or agentTurn jobs and leave main-session system events on their default model.

## Reproduction Assessment

Yes, at source level. Current schema/types make `systemEvent` text-only, normalization strips `model`, main cron jobs cannot use agentTurn payloads, and main execution never passes a model/provider override into heartbeat execution.

## Solution Assessment

Unclear until maintainers choose the public API shape. `payload.model` is the smallest extension, but a top-level job override or `sessionOverride` block may better express run-level routing without overloading system-event text.
