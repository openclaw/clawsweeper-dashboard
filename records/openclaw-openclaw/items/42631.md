## Summary

Keep open: current main and the latest release still support cron `payload.model` only for model-backed `agentTurn` jobs, not for `sessionTarget: "main"` plus `payload.kind: "systemEvent"`. The adjacent merged UI work intentionally omits silent system-event jobs, so it does not close this runtime/API request.

## What This Changes

The issue requests job-level model/provider selection for main-session `systemEvent` cron jobs so scheduled automation can use a cheaper model without manual session metadata edits.

## Best Possible Solution

Define one supported cron override contract for main-session `systemEvent` jobs, validate provider/model before enqueueing, apply it to the per-run session or heartbeat state for both wake modes, and document the failure/fallback behavior.

Rationale: The source gap is clear, but the permanent API shape affects cron protocol compatibility, session state ownership, provider/auth routing, and upgrade semantics.

Owner confidence: high

Options:

- **Add explicit sessionOverride block (recommended):** Create a typed provider/model override block for main-session systemEvent jobs, with validation and tests for wake-now and next-heartbeat paths.
- **Reuse payload.model:** Extend the existing agentTurn model field onto systemEvent payloads for parity, but require direct typed propagation instead of context-key encoding.
- **Keep systemEvent tied to session state:** Document dedicated cron session keys plus session model selection as the supported workaround and leave job-level overrides unsupported.

## Reproduction Assessment

Yes, at source level: current main accepts model fields only on agentTurn cron payloads, while the main-session systemEvent execution path queues text and calls heartbeat without model/provider override state. I did not run a live provider job because the schema and runtime path already show the requested contract is absent.

## Solution Assessment

Unclear until maintainers choose the public API shape. The safest direction is a typed override contract that reuses existing model/provider validation and applies state directly, rather than reviving context-key encoding from the closed attempt.
