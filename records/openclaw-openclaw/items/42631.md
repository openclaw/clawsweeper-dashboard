## Summary

Keep open: current main still keeps `systemEvent` cron payloads text-only and only honors per-job model selection for `agentTurn`, so the requested stable main-session cron model/provider override remains unresolved.

## What This Changes

The issue requests a supported cron job-level model/provider override for `sessionTarget: "main"` jobs that use `payload.kind: "systemEvent"`, without manual session-store edits.

## Best Possible Solution

Define one supported cron override contract for main-session system events, validate provider/model routing through the normal allowlist path, scope it to the cron run, and update CLI/UI/docs/tests around the chosen precedence rules.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support model/provider overrides for `main` + `systemEvent` cron jobs, and should that public contract be `payload.model`, top-level cron fields, or an explicit session override block?

Rationale: The source gap is clear, but the choice affects public cron schema, provider validation, session override precedence, UI display, docs, and upgrade compatibility.

Likely owner: steipete

Owner reason: They have the strongest recent routing signal through merged isolated cron model behavior and adjacent cron UI proof work.

Owner confidence: high

Options:

- **Add a first-class cron override contract (recommended):** Choose one public shape and require runtime, protocol, UI, docs, and tests to honor the same model/provider precedence for main-session system events.
- **Keep systemEvent text-only:** Document that per-job model selection is supported for model-backed agent-turn jobs and leave system events tied to the target session model.
- **Fold into broader task routing:** Track this with adjacent heartbeat/task model override work so scheduled-work surfaces do not grow incompatible provider-routing semantics.

## Reproduction Assessment

Yes. Current main source and tests show that `systemEvent` cron payloads cannot carry `model`/provider data and the main-session enqueue path forwards only text plus session context.

## Solution Assessment

Unclear until maintainers choose the API. Reusing `payload.model` is a plausible narrow path, but the best fix must settle one canonical override shape and run-scoped precedence semantics.
