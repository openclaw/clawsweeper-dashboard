## Summary

Keep open. Current main and the latest release still treat main-session `systemEvent` cron jobs as text-only queued system events, while the related merged UI work only exposes model selection for `agentTurn` jobs and intentionally omits silent system-event jobs.

## What This Changes

The issue requests first-class per-cron provider/model override support for `sessionTarget: "main"` jobs with `payload.kind: "systemEvent"`.

## Best Possible Solution

Define an explicit main-session cron override contract with provider/model validation and per-run isolation, or document systemEvent jobs as text-only and steer cheap scheduled model calls to isolated/current/custom-session `agentTurn` jobs.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support explicit provider/model overrides for main-session `systemEvent` cron jobs, and should the public contract be `payload.model`, top-level cron fields, or a `sessionOverride` block?

Rationale: Current code intentionally treats system events as text-only main-session injections, and enabling model overrides crosses provider routing, session state, cron persistence, UI/CLI, docs, and heartbeat semantics.

Likely owner: steipete

Owner reason: Recent cron runtime/schema work makes this the strongest available routing candidate for the API and session-state decision.

Owner confidence: high

Options:

- **Design explicit override contract (recommended):** Add a public cron-owned provider/model override shape, validate it like isolated cron payload models, and prove both main-session wake modes isolate state correctly.
- **Keep systemEvent text-only:** Document this path as unsupported and steer cheap scheduled model calls to isolated/current/custom-session `agentTurn` jobs.
- **Defer to broader cron API work:** Track the model decision with broader cron schema and cost-control work so model, context, timeout, and spend semantics are decided together.

## Reproduction Assessment

Yes, at source level. Current main keeps `systemEvent` payloads text-only, deletes `model` during normalization, and only resolves `payload.model` for `agentTurn` cron jobs.

## Solution Assessment

Unclear until maintainers choose the product contract. `payload.model` is plausible, but an explicit cron/session override may be safer because main-session system events do not start a model call by themselves.
