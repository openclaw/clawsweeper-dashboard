## Summary

Keep open: current main and the latest release still keep `systemEvent` cron payloads text-only and only apply `payload.model` to `agentTurn`; the merged UI work covers agent-turn selection/display and deliberately leaves silent system-event jobs without a model override.

## What This Changes

Request support for per-job provider/model overrides on main-session `systemEvent` cron jobs without manual session-store edits.

## Best Possible Solution

Maintainers should choose one explicit cron override contract, validate it through the allowed provider/model resolver, keep cron-specific overrides isolated from interactive session state, and prove both wake-now and next-heartbeat main-session behavior.

- **Keep systemEvent text-only:** Document isolated `agentTurn` as the supported per-job model path and keep main-session system events tied to the target session's model state.

## Reproduction Assessment

Yes, source-level. Current protocol, runtime types, normalization, and main-session execution show `systemEvent` cron jobs cannot carry or forward a supported model/provider override.

## Solution Assessment

Unclear until maintainers choose the public contract. Reusing `payload.model` is the narrowest visible option, but top-level job overrides or an explicit `sessionOverride` block remain plausible product choices.
