## Summary

Keep open: current main still has no supported model/provider override path for main-session systemEvent cron jobs. The merged UI work and isolated-agentTurn model handling cover adjacent surfaces, but the requested runtime/API contract remains missing and needs maintainer product direction.

## What This Changes

The issue requests a supported per-cron model/provider override for main-session systemEvent cron jobs so automation can use a cheaper model without editing internal session metadata.

## Best Possible Solution

Define one explicit cron override contract, validate it through the normal provider/model allowlist, scope it to only the cron run, then update protocol, normalization, persistence, execution, UI/tooling, docs, and focused tests for wake-now and scheduled execution.

Options:

- **Extend systemEvent payload.model (recommended):** Add payload.model to systemEvent as the narrowest contract matching agentTurn, with allowlist validation and run-scoped session override behavior.
- **Add job-level override shape:** Introduce model/provider or sessionOverride at the job level so multiple payload kinds share one explicit override contract, at the cost of a broader schema surface.
- **Keep systemEvent text-only:** Document isolated agentTurn jobs as the supported model-controlled cron path and leave main-session systemEvent jobs on the session default.

Yes. Source-level reproduction is high-confidence: current schema/type/normalizer keep systemEvent text-only, main jobs require systemEvent, and the main execution path enqueues text without model/provider data.

## Solution Assessment

Unclear until maintainers choose the public contract. payload.model is the narrowest shape consistent with agentTurn, but job-level fields or sessionOverride are plausible product/API alternatives.
