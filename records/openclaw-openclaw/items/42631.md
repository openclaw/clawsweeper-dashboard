## Summary

Keep open: current main and latest v2026.6.11 still treat `systemEvent` cron payloads as text-only while model overrides apply only to `agentTurn`; the merged UI work intentionally omitted silent/systemEvent model choice, so the remaining work is a maintainer product decision, not cleanup-closeable.

## What This Changes

Request first-class job-level provider/model selection for main-session `systemEvent` cron jobs without manual session-store metadata edits.

## Best Possible Solution

Choose and document one explicit cron override contract for `main` + `systemEvent` jobs, then implement it with allowlist validation, scoped session-state behavior, and coverage for both wake modes; otherwise document systemEvent as model-free and steer model-specific automation to agentTurn jobs.

Required: true

Question: Should OpenClaw support a first-class per-job model/provider override for `sessionTarget: "main"` plus `payload.kind: "systemEvent"` cron jobs, and if so should the contract be `payload.model`, a top-level cron job field, or an explicit `sessionOverride` block?

Rationale: Current code intentionally makes systemEvent text-only and model selection is tied to agentTurn/session state; changing that affects provider routing, session state, and wake-mode behavior that repository policy treats as product-sensitive.

Owner confidence: high

Options:

- **Design explicit systemEvent override contract (recommended):** Approve one durable API shape, require allowlist validation and scoped lifetime semantics, and then implement/runtime-test both wake modes before closing this issue.
- **Keep systemEvent model-free:** Decide that systemEvent only queues main-session context and should not pick models, then close or update docs to direct model-specific scheduled work to agentTurn jobs.
- **Defer into broader cron schema redesign:** Hold this issue behind the broader cron tool/API schema direction if maintainers want one unified model-facing cron contract first.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 keep `systemEvent` payloads text-only, prune model-like fields from explicit system events, and read `payload.model` only for `agentTurn`. I did not run a live cron job because the missing contract is clear from schema, normalization, runtime, docs, and tests.

## Solution Assessment

Unclear until maintainers choose the product contract. The request is valid, but the best implementation is not the closed unmerged ad hoc path; it needs an explicit API shape and wake-mode/session-state semantics.
