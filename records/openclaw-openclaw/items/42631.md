## Summary

Keep open. Current main and the latest release still keep main-session systemEvent cron payloads text-only, while merged cron model work covers agentTurn/UI paths and does not implement this provider/model override route.

## What This Changes

The issue requests a first-class model/provider override for cron jobs that use main-session systemEvent delivery.

## Best Possible Solution

Maintainers should choose one explicit cron-owned override contract, validate provider/model like isolated cron payload models, and prove the override is per-run without leaking into the main session.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support explicit provider/model overrides for main-session systemEvent cron jobs, and should the public contract be payload.model, top-level cron fields, or a sessionOverride block?

Rationale: Current code intentionally treats main-session systemEvent jobs as text-only injections, and enabling overrides crosses provider routing, session state, cron persistence, UI/CLI, docs, and heartbeat semantics.

Likely owner: steipete

Owner reason: Recent cron runtime/schema work makes this the strongest available owner for the API and session-state direction decision.

Owner confidence: high

Options:

- **Design explicit override contract (recommended):** Add a public cron-owned provider/model override shape, validate it like isolated cron payload models, and prove both wake-now and next-heartbeat runs isolate state correctly.
- **Keep systemEvent text-only:** Document main-session systemEvent jobs as unsupported for model selection and steer cheap scheduled model calls to isolated/current/custom-session agentTurn jobs.
- **Defer to broader cron API work:** Track this decision with broader cron schema and cost-control work so model, context, timeout, and spend semantics are decided together.

## Reproduction Assessment

Yes, at source level. Current main keeps systemEvent payloads text-only, deletes model during normalization, and only resolves payload.model for agentTurn cron jobs.

## Solution Assessment

Unclear until maintainers choose the product contract. payload.model is plausible, but an explicit cron/session override may be safer because main-session system events enqueue text and do not start a model call by themselves.
