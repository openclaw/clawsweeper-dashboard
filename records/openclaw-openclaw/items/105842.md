## Label Justifications

- `P2`: The refactor is useful and bounded, but the introduced public helper has a deterministic process-hang edge case that should block merge.
- `merge-risk: 🚨 availability`: A caller using a one-code-unit limit at a leading surrogate pair can enter a non-advancing synchronous loop.

## Summary

Keep this PR open for a focused correction: the shared owner boundary is sensible and removes Zalouser’s duplicate splitting policy, but the new range loop can stop advancing when a one-code-unit boundary lands on a leading surrogate pair. The protected `maintainer` label also requires explicit maintainer handling rather than cleanup closure.

## What This Changes

Adds an offset-preserving range chunker to markdown-core and the public text-chunking SDK, migrates Zalouser to it, and updates tests, docs, and SDK baselines.

## Best Possible Solution

Keep the shared markdown-core and SDK seam, but guarantee every iteration advances—allowing a surrogate pair to exceed an otherwise impossible one-code-unit limit is safer than emitting an empty range—and lock that behavior with SDK and Zalouser regression coverage.
