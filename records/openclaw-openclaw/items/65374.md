## Label Justifications

- `P1`: The issue describes an active multi-agent memory workflow where one agent's session history can be synthesized into another agent's dream output.
- `impact:session-state`: Dreaming can associate session snippets and first-person narrative state with the wrong agent identity.
- `impact:data-loss`: Derived dreaming corpus, recall artifacts, and promotion candidates can be silently polluted with another agent's memory material.
- `impact:security`: Cross-agent corpus pooling can expose one agent's session content to another agent's memory and narrative path.

## Summary

Keep open: current main and v2026.6.11 still group shared-workspace agents into one memory-core dreaming workspace, ingest every matched agent's sessions, and write/read one workspace-level dreaming corpus. The issue has a current open partial PR, but no merged fix yet.

## What This Changes

The issue asks for memory-core dreaming to stop pooling session snippets across agents and synthesizing another agent's experiences as first-person memory.

## Best Possible Solution

Land or replace a memory-core fix that makes the current agent the default dreaming isolation boundary across workspace resolution, session ingestion, corpus read/write, ranking, promotion, and cleanup of already pooled artifacts.
