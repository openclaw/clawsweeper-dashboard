## Summary

Keep open: current main and v2026.6.11 still group Dreaming work by shared workspace, ingest every resolved agent's session transcripts into that workspace corpus, and record recall using a workspace-scoped `__dreaming_sessions__` query. The current direct fix candidate is still an open PR, so this issue should close only after a reviewed fix lands.

## What This Changes

The issue reports that memory-core Dreaming pools session snippets from multiple agents sharing a workspace or gateway and synthesizes them as another agent's first-person memories.

## Best Possible Solution

Land or replace the direct memory-core fix so Dreaming carries an agent boundary through workspace selection, transcript ingestion, session corpus writes, recall/ranking, promotion, and cleanup of existing pooled artifacts.
