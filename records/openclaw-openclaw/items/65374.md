## Label Justifications

- `P1`: The issue describes a real multi-agent memory workflow where one agent's session history can be synthesized into another agent's Dreaming output.
- `impact:session-state`: Dreaming can associate session snippets and generated narrative state with the wrong agent identity.
- `impact:data-loss`: Derived Dreaming corpus, recall artifacts, and promotion candidates can be silently polluted with another agent's material.
- `impact:security`: Cross-agent corpus pooling can expose one agent's session content through another agent's memory and narrative path.

## Summary

Keep open: current main and v2026.6.11 still group all configured agents that share a Dreaming workspace, ingest their session transcripts together, and write/recall from a workspace-level corpus. The open PR now overlaps this area but does not yet prove the full per-current-agent isolation boundary, so this issue remains the canonical security/session-state bug.

## What This Changes

The issue reports that memory-core Dreaming can pool session snippets from multiple agents in a shared Gateway/workspace and synthesize another agent's material as first-person memory.

## Best Possible Solution

Land or replace a reviewed memory-core fix that preserves compatibility while carrying agent identity through Dreaming workspace resolution, session ingestion, recall, ranking, promotion, and repair of pooled derived artifacts.
