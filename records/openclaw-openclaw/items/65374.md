## Label Justifications

- `P1`: The issue describes a real multi-agent memory workflow where one agent's session history can be synthesized into another agent's dreaming output.
- `impact:data-loss`: Derived dreaming corpus, recall artifacts, and promoted memory candidates can be silently corrupted with another agent's material.

- `impact:security`: Cross-agent corpus pooling can expose one agent's session content through another agent's memory and narrative path.

## Summary

Keep open: current main and v2026.6.11 still group same-workspace agents into one memory-core dreaming workspace and ingest all resolved agents' transcripts into a workspace-level corpus. The prior direct fix PR is closed, and the current open PR only partially overlaps, so no merged fix owns the central isolation bug yet.

## What This Changes

The issue asks for memory-core dreaming to keep each agent's session corpus, recall, and first-person dream synthesis isolated in multi-agent gateway setups.

## Best Possible Solution

Land or replace a focused memory-core fix that carries the current agent boundary through workspace resolution, session-corpus ingestion, recall/ranking, promotion, and repair of existing pooled artifacts.
