## Label Justifications

- `P1`: A real multi-agent memory workflow can synthesize one agent's session history into another agent's dreaming output and future recall.
- `impact:session-state`: The bug can associate transcript snippets and dream narratives with the wrong agent identity.
- `impact:data-loss`: Derived dreaming corpus, recall, and promotion artifacts can be silently polluted with another agent's memory material.
- `impact:security`: Cross-agent corpus pooling can expose one agent's session content to another agent's memory and narrative path.

## Summary

Keep open: current main and the latest release still group every configured agent that resolves to the same workspace and ingest their sessions into one workspace-level dreaming corpus. The newer allowlist PR only partially overlaps this isolation bug, and the older direct fix PR was closed as superseded rather than merged.

## What This Changes

The issue asks memory-core dreaming to preserve an agent boundary so one agent's session snippets cannot become another agent's dream corpus, recall, or narrative memory.

## Best Possible Solution

Land or replace a focused memory-core fix that carries the current agent boundary through workspace resolution, session-corpus ingestion, recall/ranking, promotion, and repair of already pooled derived artifacts.

## Solution Assessment

Yes on the requested direction, but not yet on a specific patch. The best fix is default agent-scoped isolation across dreaming ingestion and downstream memory paths, not only an optional allowlist that can leave shared allowed agents pooled.
