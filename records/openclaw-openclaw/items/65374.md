## Label Justifications

- `P1`: The issue affects real multi-agent memory workflows by letting one agent's session history appear in another agent's dreaming output.
- `impact:session-state`: Shared-workspace dreaming can associate transcript snippets and first-person dream narratives with the wrong agent identity.
- `impact:data-loss`: Derived dreaming corpus, recall artifacts, and promotion candidates can be silently polluted with another agent's memory material.
- `impact:security`: Cross-agent corpus pooling can expose one agent's session content to another agent's memory and narrative path.

## Summary

Keep open: current main and v2026.6.11 still group multiple agent IDs by workspace, ingest all matching agents' sessions, and write them into one workspace-level dreaming corpus. The open PR is only a partial/config-path candidate, while the direct isolation PR was closed unmerged, so the central shared-workspace identity contamination problem is not implemented away.

## What This Changes

The issue asks memory-core dreaming to stop pooling session snippets across agents in multi-agent setups so one agent cannot synthesize another agent's memories as its own.

## Best Possible Solution

Land or replace a memory-core fix that carries the current agent boundary through workspace resolution, session ingestion, corpus storage, recall/ranking, promotion, and repair of already-pooled derived artifacts.
