## Label Justifications

- `P1`: The issue describes a real multi-agent memory workflow where one agent's session history can be synthesized into another agent's dreaming output.
- `impact:session-state`: The bug can associate session snippets, recall evidence, and dream narratives with the wrong agent identity.
- `impact:data-loss`: Derived dreaming corpus, recall artifacts, and promotion candidates can be silently polluted with another agent's memory material.
- `impact:security`: Cross-agent corpus pooling can expose one agent's session content to another agent's memory and narrative path.

## Summary

Keep open: current main and v2026.6.11 still group all agent IDs that resolve to the same dreaming workspace, ingest each resolved agent's transcripts, and write them into one workspace-level dreaming corpus. The remaining work is not obsolete because the direct stale fix was closed unmerged and the newer open PR only covers a conflicting allowlist/config subset rather than a reviewed default isolation fix.

## What This Changes

The issue requests agent-boundary isolation for memory-core dreaming so one agent's session snippets cannot enter another agent's dream corpus, recall, diary, or promotions in shared-gateway multi-agent setups.

## Best Possible Solution

Land or replace a reviewed memory-core fix that carries the current agent boundary through workspace resolution, transcript ingestion, short-term recall, ranking, promotion, diary generation, and cleanup of existing pooled artifacts, with redacted shared-workspace proof.
