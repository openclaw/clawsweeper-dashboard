## Summary

Keep open: the protected `maintainer` label requires explicit maintainer handling, and current `main` still has the central aggregate tool-result cap versus window-relative compaction mismatch. Recent main code appears to mitigate the fresh trailing zero-text symptom, but it does not make repeated aggregate truncation a compaction pressure signal or an operator-visible warning.

## What This Changes

The issue requests a fix for long-lived sessions where large configured context windows prevent compaction while absolute aggregate tool-result caps repeatedly truncate prompt history.

## Best Possible Solution

Keep this as a maintainer-owned core runtime bug and fix the remaining mismatch by making repeated aggregate truncation count as context pressure, preserving fresh tool output, and surfacing operator guidance without adding another config knob unless maintainers explicitly choose one.

## Reproduction Assessment

Yes for the central source path: current main still applies a fixed aggregate prompt-history cap while preemptive compaction only reacts to token-budget overflow. No live long-session run was executed, and the fresh-zero symptom appears partially mitigated by current tests.

## Solution Assessment

Unclear as an implementation path: the issue identifies the right runtime boundary, but maintainers still need to choose between cap scaling, truncation-as-pressure compaction, operator diagnostics, or a combination.
