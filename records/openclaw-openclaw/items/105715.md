## Summary

The reported failure is credible, but current OpenClaw does not own either the Google API transport that produced the IPv6 dial error or the custom `GOG_OAUTH_HEALTH_FAIL` alert; the actionable transport work belongs in Gog, while alert classification belongs in the external cron automation that emits it.

## What This Changes

Address Gog Google API failures when an unroutable IPv6 address is selected despite reachable IPv4 service addresses.

## Best Possible Solution

File a focused report against `openclaw/gogcli` with the supplied dual-stack macOS evidence, reproduce against current Gog, and change its HTTP transport only after identifying why Go's normal address-family fallback did not reach IPv4; separately update the external cron wrapper to classify `no route to host` as network reachability rather than OAuth health.
