## Summary

Current OpenClaw only documents, invokes, and supervises the separately installed Gog executable; it does not own the Google API transport or the reported OAuth-health alert. The actionable work belongs in Gog and the external scheduled health-check wrapper.

## What This Changes

Investigate Gog Google API failures when IPv6 is unroutable but IPv4 remains reachable, and avoid misclassifying that condition as OAuth failure.

## Best Possible Solution

Report and reproduce the dual-stack failure in Gog, fix its HTTP transport only if normal Go fallback is being bypassed, and update the external health-check wrapper to classify `no route to host` as network reachability rather than OAuth failure.
