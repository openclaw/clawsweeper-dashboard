## Summary

Keep this PR open for correction rather than merging or closing it. The proposed removal plausibly fixes the linked escaped-newline regression, but it also removes the repair path for malformed model-generated Windows paths such as `C:\newfolder`; because `\n` is a valid JSON escape, that input can be parsed into a newline rather than reaching the stated fallback. The PR also needs after-fix real behavior proof.

## What This Changes

This PR removes a Windows-path heuristic from streaming JSON repair so escaped newline sequences in model tool-call arguments are not double-escaped before tools receive them.

## System Context

Provider streaming code accumulates model-generated tool-call arguments and sends them through the AI package’s repair parser before exposing structured values to tools such as file writing. That parser must preserve valid JSON escapes while safely recovering from the malformed JSON commonly emitted by models.

## Best Possible Solution

Preserve both compatibility cases with focused tests: valid escaped newlines after path-like text must decode to newlines, while malformed raw Windows paths must not be silently converted into control characters; choose and document the parser boundary if one case must be intentionally unsupported.
