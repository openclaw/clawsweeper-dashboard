## Summary

This PR still needs revision: its new pure-prefix check cannot recognize the first malformed escape in a path such as `C:\newfolder`, because the accumulated prefix is only `C:` when the parser evaluates the `\n`. That drops the recovery behavior the PR says it preserves. The supplied verification text also is not after-fix proof from an actual write-tool run.

## What This Changes

The PR replaces a broad Windows-path heuristic in streaming JSON repair with a stricter path-prefix and continuation check intended to keep escaped newlines in tool arguments from becoming literal backslash-n text.

## System Context

Model tool-call arguments may arrive as malformed JSON and pass through the AI package's repair parser before tools receive the decoded values. This path affects file-writing and other tools whose string arguments need both valid JSON escapes and limited recovery for malformed Windows paths.

## Best Possible Solution

Keep the narrow JSON-repair strategy, but make the path decision account for the current backslash so the initial `C:\n...` component is recovered, then add focused regression coverage and a redacted real write-tool proof for both newline and Windows-path cases.
