Rationale: Both sides protect real behavior: the current default supports launchd TLS, while the reported failure affects auth/keychain and fresh runtime launch paths, so an automated patch should not choose the product/security boundary without maintainer intent and live macOS proof.

Owner confidence: high

Options:

- **Scope auth/keychain boundary (recommended):** Keep the launchd TLS default and make Codex/OpenAI auth/status/app-server launch paths use a keychain-safe, non-prompting boundary with live macOS verification.

- **Pursue credential delegation:** Treat the external delegation idea as a larger auth architecture change only if maintainers want that product direction and can own its security model.
