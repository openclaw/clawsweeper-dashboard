## What This Changes

The issue reports an iOS Voice Wake crash when it restarts microphone recognition after Talk or another external microphone capture path.

## Best Possible Solution

Voice Wake should use one guarded restart lifecycle that serializes/debounces starts, stays paused during external capture, re-checks state before tap installation, and treats invalid or contended microphone startup as recoverable.

## Reproduction Assessment

No high-confidence standalone reproduction path yet: the issue has three physical iPhone crash logs and current source still matches the failing restart/tap path, but the exact minimal sequence was not isolated and I did not reproduce it on hardware.

## Solution Assessment

Yes as a direction: the best fix is narrow Voice Wake lifecycle hardening around restart serialization, external-capture suspension, and tap-install recovery, not a Talk routing or product-setting change.
