## Summary

Keep open: current main and the latest stable tag still show the reported Voice Wake restart paths installing an AVAudioEngine input tap without serialization or a delayed/rechecked resume, and no related PR currently owns this specific crash hardening.

## What This Changes

The issue reports an iOS crash when Voice Wake reinstalls its AVAudioEngine input tap while Talk, screen recording, or another microphone capture path is active or has just ended.

## Best Possible Solution

Add narrow iOS Voice Wake restart serialization and recoverable tap-start failure handling around the existing Talk/external-capture suppression boundary, without changing Talk provider routing or adding new config.

## Reproduction Assessment

Yes, for source-level reproduction; no, for a minimal live-device sequence in this read-only review. Current main shows the reported restart paths and unguarded installTap call, and the issue body provides three physical-device crash backtraces through those paths.

## Solution Assessment

Yes, a focused hardening fix in VoiceWakeManager and NodeAppModel is the best boundary. Sibling Talk tap installers should be preserved, while Voice Wake should coordinate microphone ownership and recover from tap/start failure instead of changing provider routing.
