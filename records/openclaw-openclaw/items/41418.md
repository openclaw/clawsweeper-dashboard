## Summary

Keep open: current main and the latest release still lack a global `openclaw agent --dry-run` mode, and the remaining work is a product/security contract for agent-wide tool execution rather than stale cleanup or an already-implemented feature.

## What This Changes

Requested a global `openclaw agent --dry-run` mode that previews agent tool calls without executing built-in, plugin, channel, client, web, browser, or shell tools.

## Best Possible Solution

Define a maintainer-owned agent dry-run contract covering scope, redaction, hook ordering, client/native tools, Gateway behavior, output shape, docs, and tests before accepting an implementation; keep command-specific dry-runs such as cron and doctor as separate scoped work.

No, the proposed adapter-only implementation is plausible but not yet proven to be the best fix. The safer path is to decide the request-scoped security contract first, then implement across CLI, embedded/Gateway fallback, client tools, hooks, docs, and regression tests.
