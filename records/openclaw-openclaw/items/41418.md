## Summary

Keep open: current main and the latest release still lack a global agent tool-execution dry-run, and the requested behavior is a security/product contract that needs maintainer direction before implementation.

## What This Changes

The issue requests a global `openclaw agent --dry-run` mode that intercepts all agent tool calls and returns preview payloads instead of executing tools.

## Best Possible Solution

Define an additive request-scoped no-side-effects contract across CLI, Gateway/embedded runs, direct tool invocation, built-in/plugin/client tools, hook ordering, logging, docs, and regression proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What request-scoped no-side-effects contract should OpenClaw expose for global agent tool dry-run across CLI, Gateway/embedded runs, built-in/plugin/client tools, direct tool invocation, and hooks?

Rationale: The feature is a security-relevant product guarantee, and current source shows multiple execution surfaces that a narrow process-global adapter flag would not safely cover.

Likely owner: steipete

Owner reason: The decision is product/security-contract shaped, and this handle has substantial history in the tool adapter and hook execution path.

Owner confidence: medium

Options:

- **Design request-scoped core dry-run (recommended):** Specify the runtime contract first, then implement an additive CLI/runtime path with tests for built-in, plugin, client, Gateway, embedded, direct-invoke, and hook behavior.
- **Fold into broader workflow modes:** Keep this open but block implementation until Ask/Plan/Modify or scoped-agent mode defines the shared preview vocabulary and guarantees.
- **Keep only scoped dry-runs:** Reject a global mode if maintainers decide it is too easy to confuse with sandboxing, and continue improving command-specific preview paths instead.

## Reproduction Assessment

Yes. Source inspection shows `openclaw agent` has no `--dry-run` flag, the public agent docs have no such option, and the shared tool paths still execute or delegate tools rather than returning preview payloads.

## Solution Assessment

No, not as proposed. The safety goal is aligned, but the proposed process-global adapter flag is too narrow; the maintainable solution is a request-scoped contract covering all agent/tool execution surfaces.
