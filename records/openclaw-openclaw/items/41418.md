## Summary

Keep open: current main and the latest release still do not provide a global agent tool-execution dry-run, and the remaining work needs maintainer product/security direction rather than cleanup closure.

## What This Changes

The issue requests a global `openclaw agent --dry-run` mode that exposes tools to the model but intercepts every tool execution with a structured preview instead of side effects.

## Best Possible Solution

Define an additive request-scoped dry-run contract with redacted preview payloads, covering CLI, Gateway/embedded runs, built-in tools, plugin tools, client tools, hooks, and delegated tool paths before implementation.

- **Defer to broader safe modes:** Keep this issue open until the Ask/Plan/Modify or scoped-agent-mode design chooses the shared vocabulary and guarantees.
- **Reject global dry-run:** Keep only command-specific dry-runs plus documented sandbox and tool-policy controls if maintainers decide global preview would be too easy to mistake for a full sandbox.

## Reproduction Assessment

Yes for the feature gap: current main registers no `--dry-run` option for `openclaw agent`, the agent docs do not list one, and the shared tool adapter still executes or delegates tool calls.

## Solution Assessment

Unclear: a global dry-run mode fits the safety goal, but the proposed process-global CLI flag is not yet the best design; request-scoped semantics across CLI, Gateway, embedded, plugin, client, hook, and delegated-tool paths are safer.
