## Summary

Keep open: current main and the latest release still lack a global `openclaw agent --dry-run` mode, and the requested behavior is a security-sensitive product contract rather than a stale cleanup item.

## What This Changes

Add a global `openclaw agent --dry-run` mode that previews all tool calls and prevents built-in, plugin, client, browser, web, exec, and file tools from executing.

## Best Possible Solution

Define an additive request-scoped no-side-effects contract first, then implement one canonical dry-run path across CLI, Gateway/embedded runs, direct invoke, built-in/plugin/client tools, hooks, docs, and regression tests.

## Solution Assessment

No, not as proposed. The safety goal is aligned, but the specific process-global adapter flag is too narrow; the best fix is a request-scoped contract that covers every relevant tool execution surface.
