## Label Justifications

- `P1`: A managed Anthropic-compatible text-only model can receive an invalid image-bearing tool_result payload and fail an agent turn with a provider 400.
- `impact:session-state`: The failure can be triggered by replayed tool-result history after image-producing turns or model switches, affecting later session turns.
- `impact:auth-provider`: The bug is in provider/model capability handling for anthropic-messages request payloads.

## Summary

Keep open: current main still sends Anthropic tool_result image blocks without checking the model input capability, and the linked open PR is the active candidate fix rather than a reason to close before merge.

## What This Changes

The issue asks OpenClaw to drop image blocks from Anthropic Messages tool_result payloads when the target model declares only text input.

## Best Possible Solution

Review and land or replace the linked narrow PR so the Anthropic tool-result converter receives model capability, drops images for text-only models, and preserves image-capable behavior.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current main has a high-confidence source reproduction: convertContentBlocks emits native image blocks from tool_result content without consulting model.input, and the existing default text-only fixture still exercises that shape.

## Solution Assessment

Yes. Passing model capability, or an equivalent allowImages boolean, into convertContentBlocks is the narrow maintainable fix and matches the existing Anthropic user-message and OpenAI tool-result gates.
