## Label Justifications

- `P1`: A managed Anthropic-compatible text-only model can receive an invalid image-bearing tool_result payload and fail an agent/provider turn with a 400.
- `impact:session-state`: The bad payload can come from replayed tool-result history after image-producing turns or model switches, affecting later session turns.
- `impact:auth-provider`: The bug is in provider/model capability handling for anthropic-messages request payload construction.

## Summary

Keep open: current main still builds Anthropic tool_result image content without consulting model.input, and the linked open PR is the active fix candidate rather than a reason to close the issue.

## What This Changes

The issue asks OpenClaw to stop emitting native Anthropic tool_result image blocks when a text-only anthropic-messages model is selected.

## Best Possible Solution

Land a narrow model.input-based gate in Anthropic tool-result conversion, with coverage for both text-only image dropping and image-capable preservation.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current main has a high-confidence source reproduction: the Anthropic tool-result converter ignores model.input, and the existing text-only fixture can still expect a native image block in the outgoing payload.

## Solution Assessment

Yes. Passing model capability, or an equivalent allowImages boolean, into convertContentBlocks is the narrow maintainable fix and matches the existing Anthropic user-message and OpenAI tool-result gates.
