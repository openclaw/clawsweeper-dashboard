## Label Justifications

- `P1`: A managed Anthropic-compatible text-only model can receive an invalid image-bearing tool_result payload and fail an agent turn with a provider 400.
- `impact:session-state`: The failure can be triggered by replayed tool-result history after image-producing turns or model switches, poisoning later session turns.
- `impact:auth-provider`: The bug is in provider/model capability handling for anthropic-messages request payloads.

## Summary

Keep open: current main still emits Anthropic tool_result image content without checking the model's input capability, and the linked open PR is the active candidate fix rather than a reason to close this issue.

## What This Changes

The issue asks OpenClaw to drop image blocks from managed Anthropic Messages tool_result payloads when the configured model is text-only.

## Best Possible Solution

Land or replace the linked narrow PR so convertContentBlocks receives the model capability, drops tool-result images for text-only models, and preserves image-capable behavior with focused regression coverage.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current main has a high-confidence source reproduction: the Anthropic tool-result converter ignores model.input, and the existing text-only fixture can still expect a native image block in the outgoing payload.

## Solution Assessment

Yes. Threading model capability, or an equivalent allowImages boolean, into convertContentBlocks is the narrow maintainable fix and matches the existing Anthropic user-message and OpenAI tool-result gates.
