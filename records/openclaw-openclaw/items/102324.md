- `P1`: A managed Anthropic-compatible text-only model can receive an invalid image-bearing tool_result payload and fail an agent/provider turn with a 400.
- `impact:session-state`: The bad payload can come from replayed tool-result history after image-producing turns or model switches, affecting later session turns.

## Summary

Keep open: current main and the latest release still have the ungated Anthropic tool_result image path, while the linked open PR is the active candidate fix rather than grounds to close the issue.

## What This Changes

The issue reports that the managed Anthropic Messages transport sends image tool_result blocks to text-only anthropic-messages models, causing provider 400s.

## Best Possible Solution

Review and land or replace the linked narrow PR so Anthropic tool_result conversion drops image blocks for text-only models while preserving image-capable behavior with regression coverage.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current main has a high-confidence source reproduction: the Anthropic tool-result converter ignores model.input, and the text-only fixture still expects a native image block in the outgoing payload.

## Solution Assessment

Yes. Passing model capability, or an equivalent allowImages boolean, into convertContentBlocks is the narrow maintainable fix and matches the existing Anthropic user-message and OpenAI tool-result gates.
