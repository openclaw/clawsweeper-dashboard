## Summary

Keep open: current main still builds Anthropic tool_result image blocks without checking the model input capability, and the linked open PR is the active candidate fix rather than a reason to close this issue.

## What This Changes

The issue reports that the OpenClaw-managed Anthropic Messages transport sends image tool_result blocks to text-only anthropic-messages models instead of dropping them.

## Best Possible Solution

Land or replace the linked narrow PR so the Anthropic tool-result converter receives model capability, drops image blocks for text-only models, and preserves image-capable behavior with focused regression coverage.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current main has a high-confidence source reproduction: the Anthropic tool-result converter ignores model.input, and the current conversion test still expects a native image block in the outgoing payload.

## Solution Assessment

Yes. Passing model capability, or an equivalent allowImages boolean, into convertContentBlocks is the narrow maintainable fix and matches the existing Anthropic user-message and OpenAI tool-result gates.
