## Summary

Keep open: current main still sends Anthropic `tool_result` image blocks without checking text-only model capability, and the linked open fix PR is the active path rather than a reason to close this issue.

## What This Changes

The issue reports that the OpenClaw-managed `anthropic-messages` transport sends image-bearing `tool_result` content to text-only models, causing provider 400s.

## Best Possible Solution

Review and land or replace the linked focused fix so Anthropic tool-result image emission uses the same `model.input` capability gate as user messages and sibling transports, with regression coverage for text-only models.

## Solution Assessment

Yes: the best fix is to pass model capability into Anthropic tool-result content conversion and drop native image blocks for text-only models. That is narrower than changing session storage or global media handling and matches existing sibling behavior.
