## Summary

Keep open: current main still has the ungated Anthropic tool_result image path, and the linked open pull request is the active fix candidate rather than a reason to close this issue.

## What This Changes

The issue asks OpenClaw to drop image blocks from Anthropic Messages tool_result payloads when the target anthropic-messages model declares text-only input.

## Best Possible Solution

Review and land or replace https://github.com/openclaw/openclaw/pull/102329 so the managed Anthropic transport drops image tool_result blocks for text-only models while preserving image-capable behavior and regression coverage.

## Maintainer Decision

## Reproduction Assessment

Yes. Current main has a high-confidence source reproduction: convertContentBlocks ignores model.input, and the current text-only fixture can still expect a native image block in the outgoing payload.

## Solution Assessment

Yes. Passing model capability, or an equivalent allowImages boolean, into convertContentBlocks is the narrow maintainable fix and matches the existing Anthropic user-message and OpenAI tool-result gates.
