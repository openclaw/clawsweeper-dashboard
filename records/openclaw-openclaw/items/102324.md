- `impact:session-state`: The bad payload can come from replayed tool-result history after image-producing turns or model switches, affecting later session turns.
- `impact:auth-provider`: The bug is in provider/model capability handling for anthropic-messages request payload construction.

## Summary

Keep open: current main still builds Anthropic tool_result image blocks without checking text-only model capability, and the linked open pull request is the active fix candidate rather than a reason to close this issue.

## What This Changes

The issue requests that the managed anthropic-messages transport drop image blocks from tool_result payloads when the selected model only declares text input support.

## Best Possible Solution

Review and land or replace the linked narrow fix so managed Anthropic tool_result conversion respects model.input for image blocks while preserving image-capable behavior with regression coverage.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current main has a high-confidence source reproduction: the Anthropic tool-result converter ignores model.input, and the existing text-only fixture still expects a native image block in the outgoing payload.

## Solution Assessment

Yes. Passing model capability, or an equivalent allowImages boolean, into convertContentBlocks is the narrow maintainable fix and matches the existing Anthropic user-message and OpenAI tool-result gates.
