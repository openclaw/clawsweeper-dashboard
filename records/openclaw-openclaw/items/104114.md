Keep this PR open, but do not merge the current head: it still assumes `skill-creator` is available whenever Skill Workshop is enabled, which can replace a supported direct authoring path with an impossible instruction. The external contributor also has not supplied after-fix real behavior proof.

## What This Changes

## Best Possible Solution

Make the authoring preference depend on the actual eligible skill inventory, preserve direct `skill_workshop` creation and editing when `skill-creator` is absent, keep lifecycle actions direct, and prove all three routing states on the final head.
