## Summary

Keep open: current main has adjacent OpenRouter billed-cost reconciliation, but it still does not expose the resolved `openrouter/auto` model or a provider-reported cost metadata contract through agent, session, status, and footer surfaces.

## What This Changes

The issue requests that `openrouter/auto` expose the actual routed model name and usage cost to the agent so response footers can show the resolved model and cost.

## Best Possible Solution

Define a selected-versus-resolved model and provider-cost metadata contract, capture it in the OpenRouter/OpenAI-compatible transport, and thread it through assistant records, session usage, status surfaces, and response footers.

## Reproduction Assessment

Yes, source inspection reproduces the gap: current main keeps `model.id`, ignores OpenAI-compatible `chunk.model` in this path, and formats footers from local estimates only; no live OpenRouter turn was run in this read-only review.

## Solution Assessment

Keeping the issue open is the best review outcome because current cost-only and footer-only related work does not define or propagate the full resolved-model and provider-cost metadata contract.
