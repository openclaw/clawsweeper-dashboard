## Summary

Keep open: current main has adjacent support for OpenRouter billed-cost reconciliation and an `AssistantMessage.responseModel` concept, but it still does not expose the resolved `openrouter/auto` model plus provider-reported cost through the agent/runtime/session/footer surfaces requested here.

## What This Changes

Requested feature: expose the actual model selected by OpenRouter when using `openrouter/auto`, plus provider-reported cost, so agents and response footers can show accurate resolved model and cost information.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-cost contract, reuse `AssistantMessage.responseModel` where appropriate, then thread OpenRouter response/generation metadata through the OpenAI-compatible transport, agent/session metadata, response footers, usage/status surfaces, transcripts, and targeted `openrouter/auto` tests.

## Reproduction Assessment

Yes, from source inspection and upstream docs: use `openrouter/auto`; OpenRouter can return the routed model and cost, but current OpenClaw agent/session/footer paths retain selected model identity and local usage/estimate fields.

## Solution Assessment

No for a footer-only implementation. The maintainable solution needs a shared selected-versus-resolved model and provider-cost metadata contract so transport, session/status, runtime, templates, and footers agree.
