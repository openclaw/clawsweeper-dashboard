## Summary

Keep open: current main has partial OpenRouter billed-total reconciliation and lower-level response-model plumbing, but the active OpenAI-compatible agent path still does not expose the combined resolved `openrouter/auto` backend model plus provider-reported cost through the agent/session/footer contract requested here.

## What This Changes

The issue requests exposing the actual model selected by OpenRouter `openrouter/auto` and its usage cost so agents and response footers can report the resolved model and cost accurately.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-cost metadata contract, capture it at the OpenRouter/OpenAI-compatible boundary, and thread it through agent metadata, session/status, usage templates, transcripts, and response footers with targeted `openrouter/auto` coverage.
