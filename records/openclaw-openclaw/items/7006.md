## Summary

Keep open: current main still keeps the selected `openrouter/auto` model in OpenAI-compatible runtime/session/footer paths and does not preserve OpenRouter provider-reported cost details for agent-visible reporting.

## What This Changes

Request to expose the actual model and cost selected by OpenRouter `auto` so agent replies can show the resolved model and accurate usage/cost in the footer.

## Best Possible Solution

Define the selected-versus-resolved model and provider-cost metadata contract, capture OpenRouter response model/cost metadata in the OpenAI-compatible path, and thread it through assistant records, session/status surfaces, and response footers.

## Reproduction Assessment

Yes by source inspection: current main keeps `model.id`, ignores OpenAI-compatible `chunk.model` and provider cost details, and formats footers from local estimates only; no live OpenRouter turn was run in this read-only review.

## Solution Assessment

The issue should stay open for a contract decision; a footer-only or cost-only patch would not cover the required transport, session, status, and agent metadata behavior.
