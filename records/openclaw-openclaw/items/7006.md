## Summary

Keep open: current main still has partial lower-level response-model plumbing, but the active OpenRouter/OpenAI-compatible agent path does not expose the resolved `openrouter/auto` model or provider-reported cost through the requested agent/session/footer surfaces.

## What This Changes

Expose the actual OpenRouter-routed model and usage cost when a user selects `openrouter/auto`.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-cost metadata contract, then capture OpenRouter response model/cost at the OpenAI-compatible boundary and thread it through assistant records, session/status surfaces, usage templates, and response footers.
