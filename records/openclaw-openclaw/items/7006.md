## Summary

Keep open: current main has partial OpenRouter billed-cost reconciliation and now captures a low-level `responseModel`, but it still does not expose the resolved `openrouter/auto` model and provider-reported cost through the agent-visible footer, session/runtime metadata, or status surfaces requested here.

## What This Changes

Expose the actual model and cost selected by OpenRouter `openrouter/auto` so agents and response footers can report the resolved backend model and charge instead of only the selected auto alias.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-cost metadata contract, then carry it from the OpenRouter/OpenAI-compatible transport through assistant records, agent/session metadata, status/tool output, usage templates, and response footers with targeted OpenRouter auto coverage.

## Reproduction Assessment

Yes. Source inspection shows the low-level stream can carry `responseModel` and OpenRouter can reconcile `usage.cost.total`, but current agent metadata and response footer paths still expose selected model/local estimates rather than the requested resolved model and provider cost.

## Solution Assessment

Unclear until maintainers choose the public metadata contract. The maintainable path is additive selected-versus-resolved model and cost metadata across transport, persistence, status, and footer surfaces rather than relabeling the existing local estimate fields.
