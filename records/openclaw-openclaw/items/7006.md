## Summary

Keep open: current main has partial OpenRouter billed-cost reconciliation and a low-level `responseModel` type, but it still does not expose a coherent selected-versus-resolved OpenRouter auto model plus provider-cost/source contract through agent metadata, session/status, transcripts, or response footers.

## What This Changes

The issue requests exposing the actual model and cost selected by `openrouter/auto` so agents and response footers can report the routed model instead of only `openrouter/auto`.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-reported cost contract, populate it from OpenRouter/OpenAI-compatible responses, and expose it consistently through agent metadata, session/status, transcripts, and `/usage full` footer surfaces.

## Reproduction Assessment

Yes at source level: current main still keeps `openrouter/auto` as the selected model in key paths, parses usage into local cost fields, and renders footers without the concrete OpenRouter response model or provider-cost source metadata.

## Solution Assessment

No current implementation fully solves it; the best fix is a generic provider/session metadata contract, not the closed footer-only PR or an external routing workaround.
