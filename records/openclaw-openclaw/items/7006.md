## Summary

Keep open: current main and the latest release still do not expose the resolved `openrouter/auto` model or provider-reported cost through the agent-visible footer/session/runtime metadata requested here. ## What This Changes

Expose the actual model selected by OpenRouter Auto and its cost so agents and response footers can report the resolved model instead of only `openrouter/auto`.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-cost metadata contract, capture OpenRouter response `model` plus provider cost fields at the provider/transport boundary, then thread that through assistant records, session/status/runtime surfaces, usage templates, and response footers with targeted OpenRouter Auto tests.

## Reproduction Assessment

Yes. Source inspection on current main shows the OpenAI-compatible path keeps `model.id`, does not populate resolved response-model metadata from OpenRouter chunks, and formats response usage from local estimates rather than provider-reported cost.

## Solution Assessment

Unclear until maintainers choose the public metadata contract. The maintainable path is not a footer-only patch; it needs a selected-versus-resolved model and provider-cost contract carried consistently through transport, session, status, transcript, and footer surfaces.
