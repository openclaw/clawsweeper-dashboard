## Summary

Keep open: current main still has selected-model and local-estimated-cost plumbing, but it does not expose the resolved OpenRouter auto backend model or provider-reported cost through the agent/session/footer contract requested here.

## What This Changes

Issue requests exposing the concrete OpenRouter model and provider cost resolved from `openrouter/auto` so agents and response footers can report the actual routed model and cost.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-cost metadata contract, then capture OpenRouter response model/cost at the OpenAI-compatible boundary and thread it consistently through assistant records, session/status surfaces, usage templates, and response footers.
