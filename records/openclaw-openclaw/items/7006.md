## Summary

Keep open: current main has partial OpenRouter billed-cost reconciliation and a generic `responseModel` type, but the managed OpenAI-completions/OpenRouter agent path still reports the selected `openrouter/auto` model, drops provider cost from agent-visible normalized usage, and formats the built-in footer from local estimates. The related open items cover cost-only, broader resolved-model metadata, or HTTP header visibility rather than replacing this exact OpenRouter auto footer request.

## What This Changes

The issue requests exposing the resolved OpenRouter auto model and usage cost to the agent so response footers can show the actual routed model and cost.

## Best Possible Solution

Define a selected-versus-resolved model and provider-cost metadata contract, then thread it through the OpenRouter/OpenAI-compatible transport, assistant records, session/status surfaces, usage template contract, and built-in response footer with targeted OpenRouter auto regression coverage.

## Reproduction Assessment

Yes. Source inspection is enough to reproduce the missing behavior: the managed OpenAI-compatible path keeps the selected model, the normalized agent usage does not carry provider cost, and the built-in footer formats local estimates only.

## Solution Assessment

Unclear as an implementation until maintainers choose the metadata contract. Keeping the issue open is the best review outcome because a narrow footer-only patch would be too one-sided for the transport, session, hook, status, and transcript surfaces involved.
