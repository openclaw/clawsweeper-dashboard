## Summary

Keep open: current main now has partial OpenRouter cost and response-model plumbing, but it still does not expose a coherent resolved `openrouter/auto` model plus provider-reported cost through the agent-visible footer, session/status, transcript, and runtime metadata surfaces requested here.

## What This Changes

Request to expose the concrete model selected by OpenRouter auto routing and its usage cost to agents and response footers.

## Best Possible Solution

Define a selected-versus-resolved model and provider-cost metadata contract, then thread OpenRouter `response.model` and cost data through assistant/session records, agent runtime metadata, response footers or usage templates, session_status, diagnostics, transcripts, and focused regression tests.

## Reproduction Assessment

Yes, at source level. Current main still formats response usage from selected `modelUsed` plus local cost config, while resolved OpenRouter response-model and provider-cost data do not reach the agent-visible footer/session surfaces requested here.

## Solution Assessment

No current implementation is complete. The maintainable path is a generic selected-versus-resolved model and provider-cost contract, not a one-off footer suffix or a switch to a different routing service.
