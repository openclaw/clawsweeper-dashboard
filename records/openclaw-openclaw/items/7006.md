## Summary

Keep open: current main and the latest release still leave the requested OpenRouter auto transparency incomplete. OpenClaw now has some routed-model and billed-cost primitives, but the resolved `openrouter/auto` model and provider-reported cost are not consistently exposed through agent-visible metadata, session/status surfaces, or the default response footer.

## What This Changes

The issue asks OpenClaw to expose the concrete model and cost selected by OpenRouter for `openrouter/auto` so agents and response footers can report the actual routed model and spend.

## Best Possible Solution

Define a selected-versus-resolved model and provider-cost metadata contract, then wire it through the OpenRouter/OpenAI-compatible transport, assistant records, session/status surfaces, usage templates, and response footers with targeted `openrouter/auto` regression coverage.

## Reproduction Assessment

Yes for source-level reproduction: current code shows the selected model and local estimate are still the agent/footer contract, while the resolved model and provider-reported cost are only partial lower-level primitives. I did not run a live OpenRouter call in this read-only cleanup review.

## Solution Assessment

Yes, keeping this open is the best review outcome. The remaining work is not a narrow bug patch; it needs a maintainer-approved metadata and cost-display contract before implementation.
