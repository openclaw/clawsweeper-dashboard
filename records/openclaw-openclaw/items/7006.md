## Summary

Keep open: current main has OpenRouter billed-cost reconciliation and generic usage display surfaces, but it still does not expose the resolved `openrouter/auto` backend model or provider-reported cost metadata through the agent/runtime/session/footer contract requested here.

## What This Changes

The issue requests exposing the actual routed model and accurate usage cost when `openrouter/auto` selects a backend model.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-cost metadata contract, then capture OpenRouter response model/cost at the transport/provider boundary and thread it through assistant records, session/status surfaces, usage templates, and response footers with targeted `openrouter/auto` regression coverage.
