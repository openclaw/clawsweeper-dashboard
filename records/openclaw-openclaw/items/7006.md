## Summary

Keep open: current main only partially improves OpenRouter billed-cost accuracy and still does not propagate OpenRouter's routed model or provider cost details into agent-visible metadata or response footers.

## What This Changes

Request to expose the concrete model selected by OpenRouter auto-routing and provider-reported cost metadata to agents and response footers instead of showing only the configured `openrouter/auto` alias.

## Best Possible Solution

Define a selected-versus-resolved model and provider-cost metadata contract, capture it in the OpenRouter/OpenAI-compatible transport, and thread it through assistant records, session usage, status surfaces, usage templates, and response footers.

## Reproduction Assessment

Yes by source inspection: the current OpenAI-compatible stream ignores `chunk.model`, and footer/session code uses `agentMeta.model` or execution winner metadata, so an `openrouter/auto` turn still lacks routed-model display metadata. I did not run a live OpenRouter turn in this read-only review.

## Solution Assessment

Yes, keeping this issue open is the best review outcome because neither the partial billed-cost wrapper nor related broader/narrower issues covers the full selected-versus-resolved model and cost metadata contract. A footer-only patch would be too narrow unless it is backed by transport and session metadata changes.
