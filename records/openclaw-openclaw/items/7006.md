## Summary

Keep open: current main has adjacent model-rich `/usage full` footers and OpenRouter billed-total reconciliation, but it still does not expose the OpenRouter `openrouter/auto` resolved model plus provider-reported cost as a stable agent/session/footer contract.

## What This Changes

The issue requests exposing the concrete model and provider-reported cost selected by OpenRouter when users choose `openrouter/auto`.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-reported cost metadata contract, capture OpenRouter response model/cost details at the provider boundary, and thread it through agent metadata, session/status surfaces, usage templates, and response footers with targeted OpenRouter auto coverage.

## Reproduction Assessment

Yes, at source level. Current main can record a provider response model in some lower-level message types and can reconcile OpenRouter billed totals internally, but the agent/session/footer contract still uses selected model metadata and local estimated cost.

## Solution Assessment

Unclear until maintainers choose the public metadata contract. The requested direction is valid, but a narrow footer-only patch would not be the best solution because the same semantics need to line up across transport, session persistence, status/runtime metadata, and usage templates.
