The issue requests exposing the concrete model and cost selected behind `openrouter/auto` to the agent and response footer.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-reported-cost contract, then thread it through OpenRouter/OpenAI-compatible transport, assistant records, session/status surfaces, usage templates, and response footers with targeted OpenRouter auto regression coverage.

## Reproduction Assessment

Yes. Source inspection on current main shows the selected `openrouter/auto` model is retained through the central agent/footer path while provider-reported resolved-model and exact-cost metadata are not exposed to the requested user-facing surfaces.

## Solution Assessment

Unclear until maintainers choose the public metadata contract. A footer-only patch would be too narrow because the same selected-versus-resolved model and exact-versus-estimated cost semantics need to stay consistent across transport, session, status, transcript, and usage-template surfaces.
