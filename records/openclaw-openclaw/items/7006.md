## Summary

Keep this issue open: current main has partial OpenRouter billed-total reconciliation, but it still does not expose the routed `openrouter/auto` model or provider-reported cost metadata through agent/runtime/session/footer surfaces.

## What This Changes

The issue requests exposing the concrete model and usage cost resolved by OpenRouter when users select `openrouter/auto`.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-cost metadata contract, capture OpenRouter response `model` and cost details at the provider/transport boundary, then thread it through assistant/session metadata and response footers with targeted OpenRouter auto tests.

## Reproduction Assessment

Yes, at source level: current main still keeps the selected `openrouter/auto` model in the OpenAI-compatible stream path and exposes token/local-estimate usage surfaces rather than routed model plus provider-reported cost metadata. I did not run a live OpenRouter request in this read-only review.

## Solution Assessment

Unclear for a one-off footer-only fix; the best maintainable direction is an additive provider/runtime metadata contract consumed by footer, transcript, session, and status surfaces. Reusing `estimatedCostUsd` or only patching one channel would be too narrow.
