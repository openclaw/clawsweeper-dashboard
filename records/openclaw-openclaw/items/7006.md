## Summary

Keep open: current main only partially addresses OpenRouter billed-total reconciliation and still does not expose the resolved `openrouter/auto` backend model or provider-reported cost metadata through the requested agent, session, and response-footer surfaces.

## What This Changes

The issue requests exposing the actual model and cost returned by OpenRouter when `openrouter/auto` is selected, so replies can show the routed model and charge instead of only the selected auto model.

## Best Possible Solution

Define additive selected/resolved model metadata and provider-reported cost fields at the OpenRouter/OpenAI-compatible transport boundary, persist them separately from local estimates, and render them consistently in agent, session, status, usage-template, and response-footer surfaces.
