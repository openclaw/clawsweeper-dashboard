## Summary

Keep open: current main and v2026.6.11 have shipped adjacent OpenRouter billed-cost reconciliation, but they still do not expose the concrete `openrouter/auto` routed model through the OpenAI-compatible assistant, agent metadata, session/status, or default response footer path.

## What This Changes

Requested feature is to expose the concrete OpenRouter model selected for `openrouter/auto` and provider-reported cost so agents and response footers can report it accurately.

## Best Possible Solution

Define an OpenAI-compatible/OpenRouter selected-versus-resolved model and billed-cost metadata contract, capture it in the transport, and thread it through assistant records, agent meta, session/status surfaces, usage templates, and response footers with targeted `openrouter/auto` tests.

## Reproduction Assessment

Yes by source inspection: current main keeps `model.id`, does not propagate chat-completions `chunk.model`, and formats default response usage lines from local estimates only. I did not run a live OpenRouter turn in this read-only review.

## Solution Assessment

Keeping this issue open is the best review outcome; a footer-only or cost-only fix would not cover the transport, agent metadata, session/status, and transcript contract implied by the request.
