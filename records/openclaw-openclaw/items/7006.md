## Summary

Keep open: current main has partial OpenRouter billed-cost reconciliation and a shared `responseModel` type, but the OpenAI-compatible OpenRouter path still does not expose the resolved `openrouter/auto` model or provider-reported cost through agent-visible footer/session/runtime metadata.

## What This Changes

The issue requests exposing the actual model and cost selected behind `openrouter/auto` so agents and response footers can report the routed model and usage cost.

## Best Possible Solution

Define a selected-versus-resolved model and provider-cost metadata contract, then thread it through the OpenRouter/OpenAI-compatible transport, assistant records, session/status surfaces, usage templates, and response footers with targeted `openrouter/auto` regression coverage.

## Reproduction Assessment

Yes, at source level. Current main keeps the selected `model.id`, does not populate a resolved response model in the OpenAI-compatible success path, and formats the default footer from local estimates rather than provider-reported routed-model/cost metadata.

## Solution Assessment

Yes, keeping this open is the best review outcome. Current main only fixed a billed-cost reconciliation slice, while the remaining fix needs a maintainer-approved selected-versus-resolved model and provider-cost contract before implementation.
