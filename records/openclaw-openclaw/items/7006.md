## Summary

Keep open: current main has partial pieces for OpenRouter response model capture, billed-cost reconciliation, and rich usage footers, but it still does not expose the resolved `openrouter/auto` model plus provider cost through the agent-visible footer/session/runtime contract requested here.

## What This Changes

Expose the actual model selected by `openrouter/auto` and its usage cost so agents and response footers can report the resolved model and cost instead of only the selected auto alias.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-cost metadata contract, then thread it through the OpenRouter/OpenAI-compatible response path, assistant records, session/status metadata, usage templates, and response footers with targeted OpenRouter auto coverage.

## Reproduction Assessment

Yes. Source inspection reproduces the missing behavior: current main captures `responseModel` in one stream layer, but the agent metadata/footer paths still report selected model identity and local estimated cost rather than the resolved OpenRouter model plus provider cost.

## Solution Assessment

Yes, keeping this open is the best review outcome. The maintainable fix is a cross-surface metadata contract; closing based on partial response-model capture or billed-cost reconciliation would miss the user-visible request.
