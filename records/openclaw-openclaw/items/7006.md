## Summary

Keep open: current main has partial OpenRouter billed-cost reconciliation and lower-level response-model plumbing, but the active OpenAI-compatible agent path still does not expose the resolved `openrouter/auto` backend model or provider-reported cost through the agent/session/footer contract requested here.

## What This Changes

The issue asks OpenClaw to expose the concrete model and usage cost selected by OpenRouter when `openrouter/auto` is used, including response-footer reporting.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-cost metadata contract, capture it at the OpenRouter/OpenAI-compatible boundary, and thread it through agent metadata, session/status, usage templates, transcripts, and response footers with targeted `openrouter/auto` coverage.

- **Limit to response footer:** Only display the routed OpenRouter model and exact cost in response footers, accepting that runtime and status metadata remain incomplete.
- **Fold into broader observability:** Make the broader resolved-backend-model work own the contract, but keep this issue open until it explicitly covers OpenRouter auto footer and cost semantics.

## Reproduction Assessment

Yes. Source inspection on current main shows `openrouter/auto` is still a selected placeholder, the active stream path does not carry successful `chunk.model` into runtime metadata, and footer/session surfaces still consume selected model plus local estimates.

## Solution Assessment

Yes for keeping this open, but not for a footer-only patch. The maintainable solution is an additive metadata contract that separates selected model, resolved backend model, local estimates, and provider-reported costs before rendering any footer text.
