## Summary

Keep open: current main partially addresses OpenRouter billed-cost reconciliation, but it still does not expose the resolved `openrouter/auto` model or provider-reported cost through the agent-visible footer/session/runtime metadata requested here.

## What This Changes

Expose the concrete model selected by OpenRouter `openrouter/auto` and its cost to agents and response footers.

## Best Possible Solution

Define a selected-versus-resolved model and provider-cost metadata contract, then thread it through the OpenRouter/OpenAI-compatible transport, assistant records, session/status surfaces, usage templates, and response footers with targeted `openrouter/auto` regression coverage.

## Reproduction Assessment

Yes. Source inspection is enough to reproduce the missing behavior: current main keeps the selected `model.id`, does not populate a resolved response model in the OpenAI-compatible success path, and formats the default footer from local estimates.

## Solution Assessment

Yes, keeping this open is the best review outcome because current main only fixed a billed-cost reconciliation slice. The remaining fix needs a maintainer-approved selected-versus-resolved model and provider-cost contract before implementation.
