## Summary

Keep open: current main has adjacent OpenRouter billed-total reconciliation and usage-template fields, but it still does not expose the concrete `openrouter/auto` routed model or provider-reported cost through the agent/session/footer contract requested here, and the related open issues split cost and resolved-model work rather than replacing this combined request.

## What This Changes

The issue requests exposing the concrete model and cost chosen by OpenRouter when a user selects `openrouter/auto`.

## Best Possible Solution

Define an additive provider/runtime metadata contract that preserves selected model, resolved provider model, and provider-reported cost source/units, then thread it through OpenAI-compatible transport, assistant/session records, response footers, usage templates, `session_status`, and targeted OpenRouter auto tests.

## Reproduction Assessment

Yes, at source level: current main still passes selected/reported model and local estimated-cost inputs into the footer/session paths, while the OpenAI-compatible stream does not expose OpenRouter's routed `model` or raw cost details to agent metadata. I did not run a live OpenRouter request in this read-only review.

## Solution Assessment

No for the earlier footer-only approach; the best fix is a shared metadata contract so the same resolved model and provider-cost semantics line up across transport, session persistence, status, transcripts, diagnostics, and footer rendering.
