## Summary

Keep open: current main now has OpenRouter billed-cost reconciliation, but it still does not expose the resolved OpenRouter auto model or provider-reported cost through the agent-visible footer/session/runtime metadata requested here; the related open items cover broader or narrower slices rather than replacing this exact request.

## What This Changes

Request to expose the actual model selected by `openrouter/auto` and its cost so agents and response footers can report the routed model instead of only the configured auto selector.

## Best Possible Solution

Define a selected-versus-resolved model and provider-cost metadata contract, then thread it through OpenRouter/OpenAI-compatible transport, assistant records, session/status surfaces, usage templates, and response footers with targeted OpenRouter auto regression coverage.

## Reproduction Assessment

Yes, source inspection is enough to reproduce the missing behavior: current main keeps the selected `model.id`, does not populate a resolved response model in the OpenAI-compatible success path, and formats the default footer from local estimates. I did not run a live OpenRouter credentialed turn in this read-only review.

## Solution Assessment

Yes, keeping this open is the best review outcome because current main only fixed the billed-cost reconciliation slice, while the requested resolved-model and agent-visible cost contract still spans transport, session, status, transcript, and footer surfaces. A maintainer should choose that metadata contract before implementation.
