## Summary

Keep open: current main has partial OpenRouter billed-cost reconciliation, but it still does not expose the resolved `openrouter/auto` model and provider-reported cost as one agent/session/footer metadata contract.

## What This Changes

The issue requests exposing the actual OpenRouter model resolved from `openrouter/auto` and its cost so agents and response footers can report accurate model and cost metadata.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-cost metadata contract, capture it at the OpenRouter/OpenAI-compatible boundary, and thread it through assistant records, agent/session metadata, status surfaces, transcripts, and response footers.

## Reproduction Assessment

Yes by source inspection: current main still initializes the OpenAI-compatible assistant output with the requested `model.id`, and response/session surfaces format or store local estimated cost rather than a resolved model plus provider-cost contract. I did not run a live OpenRouter turn in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public metadata contract; a footer-only implementation is too narrow because the same selected/resolved model and exact-versus-estimated cost semantics need to be available across transport, transcript, session/status, and reply surfaces.
