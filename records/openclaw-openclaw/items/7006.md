## Summary

Keep open: current main has partial lower-level response-model and usage plumbing, but the active OpenRouter/OpenAI-compatible agent path still does not expose the resolved `openrouter/auto` backend model or provider-reported cost through the agent, session, or response-footer contract requested here.

## What This Changes

Expose the concrete model selected by `openrouter/auto` and the provider-reported usage cost to agents and response footers.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-cost metadata contract, then capture OpenRouter response model/cost at the OpenAI-compatible provider boundary and thread it through assistant records, session/status surfaces, usage templates, and response footers with targeted `openrouter/auto` coverage.
