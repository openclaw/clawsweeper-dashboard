## Summary

Keep open: current main preserves OpenRouter’s provider-billed total at the transport and transcript layer, but still does not carry the routed backend model or authoritative cost into normalized agent/session metadata or the standard response footer. The related open issues divide the generic routed-model and cost contracts, so none fully replaces this combined user-facing request.

## What This Changes

Expose the concrete backend model selected by OpenRouter Auto and its provider-reported cost to agents, sessions, and response footers.

## Best Possible Solution

Preserve the selected alias, add generic per-turn resolved provider/model and authoritative cost fields with provenance, and consume that single contract across transcripts, agent metadata, session status, usage hooks, and response footers.

No, a footer-only OpenRouter condition is not the best solution. The narrow maintainable path is one generic resolved-model and authoritative-cost metadata contract shared by every relevant runtime and presentation surface.
