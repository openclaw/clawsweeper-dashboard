## Summary

Keep open: current main has partial low-level `responseModel` capture for OpenAI-compatible completions, but OpenClaw still does not expose a coherent selected-versus-resolved OpenRouter auto model plus provider-reported cost contract through agent metadata, session/status, transcripts, or response footers.

## What This Changes

The issue requests exposing the actual model selected by `openrouter/auto` and its provider-reported cost so agents and reply footers can show the resolved model and charge instead of only `openrouter/auto`.

## Best Possible Solution

Define an additive selected-versus-resolved model and provider-cost metadata contract, capture OpenRouter response `model` and provider cost fields at the OpenAI-compatible boundary, then propagate that contract through agent metadata, session/status, transcripts, and response footers with focused OpenRouter auto tests.

## Reproduction Assessment

Yes, at source level. Current main keeps the selected model/cost-estimate surfaces separate from the low-level `responseModel` capture and still does not expose provider-reported OpenRouter cost or a resolved-model footer contract.

## Solution Assessment

No current implementation fully solves it. The maintainable path is a generic transport-to-session metadata contract, not the external ClawRouter workaround or a one-off footer suffix.
