## Summary

Keep open. Current main partially improved OpenRouter billed-cost reconciliation, but it still does not expose the resolved `openrouter/auto` model or provider-reported turn cost through the agent/runtime response footer contract requested here.

## What This Changes

The issue requests exposing the concrete model selected by OpenRouter auto and its provider-reported usage cost to the agent/user-visible response footer.

## Best Possible Solution

Define one selected-versus-resolved model and provider-billed-cost metadata contract, then thread it through OpenAI-compatible transport, assistant/session or reply usage state, response footer/usage-bar surfaces, and focused OpenRouter auto regression tests.

## Reproduction Assessment

Yes. Source inspection on current main shows the OpenAI-compatible stream stores `model.id` and the footer computes a local estimate, while the newer OpenRouter billed-cost wrapper does not add resolved-model footer/runtime metadata.

## Solution Assessment

No. The best solution is broader than a one-off footer suffix because selected model, resolved provider model, fallback/session metadata, and provider-reported cost need one maintainable contract.
