## Summary

Keep open for maintainer product direction: current OpenClaw still has separate heartbeat and cron contracts, while this proposal would change persisted configuration, scheduling semantics, and workspace-state ownership. Likely related people: steipete (high confidence) and zeroaltitude (medium confidence).

## What This Changes

The issue proposes making cron the single automation primitive for heartbeats, watchers, adaptive schedules, script payloads, stream inputs, and per-job scratch state.

## Best Possible Solution

Approve a bounded RFC and land independently reviewable, doctor-backed phases that first preserve existing heartbeat and cron behavior, then prove any shared primitive before migrating storage or adding script and stream execution.
