## Summary

Keep open: this is a focused candidate fix for a real Microsoft Teams ClawHub crash-loop, and the diff looks correct, but it changes the trusted-plugin capability boundary and should get explicit maintainer security-boundary acceptance before merge.

## What This Changes

The PR changes plugin manifest trust classification so official ClawHub install records can satisfy trusted official install checks when the official catalog entry is npmSpec-only, and adds regression coverage for trusted and untrusted ClawHub cases.

## Best Possible Solution

Land the narrow official ClawHub npmSpec-only trust rule after maintainer acceptance of the boundary, while keeping broader self-hosted and non-ClawHub trust work tracked separately.

## Reproduction Assessment

Yes. Source inspection shows current main requires `officialInstall?.clawhubSpec` before a ClawHub official install can be trusted, which excludes npmSpec-only catalog entries such as Microsoft Teams.

## Solution Assessment

Likely yes. The PR changes the shared manifest trust predicate instead of adding a Teams-specific bypass, and its negative tests cover community, private, custom-URL, mismatched-package, and unrecorded global installs.
