## What This Changes

The PR moves OpenClawKit node.invoke execution out of the gateway WebSocket push callback and adds a Swift regression test that keeps receiving while a system.run invoke is blocked.

## Best Possible Solution

Merge the shared OpenClawKit receive-loop isolation after exact-head macOS Swift/node CI completes, preserving the channel-generation result guard and regression coverage.

## Reproduction Assessment

Yes, at source level: current main rearms GatewayChannel receive only after handle(msg) returns, while GatewayNodeSession awaits the invoke inline. The linked issue provides a live v2026.5.28 repro, but this review did not run a signed current-main macOS repro.

## Solution Assessment

Yes, this is the best narrow fix: the receive-loop starvation is at the shared OpenClawKit transport callback boundary, so moving invoke execution out of that callback is safer than changing ShellExecutor or gateway timeouts.
