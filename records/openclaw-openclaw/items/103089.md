## Label Justifications

- `P1`: This is a stable gateway trust-boundary bug that can expose another plugin's session transcript to an in-process plugin-runtime caller under realistic preconditions.
- `impact:security`: The report concerns a missing cross-plugin ownership check before a privileged session fork/read path.
- `impact:session-state`: The unchecked path can clone transcript state and graft parent-child relationships across plugin-owned sessions.
- `maturity:stable`: The affected gateway RPC/session security surface matches the M4 Stable `gateway-runtime` maturity shortlist entry.

## Summary

Keep open: current main still lets `sessions.create` resolve and fork or link a parent session without checking the parent entry's plugin owner against the plugin-runtime caller, while the sibling delete path enforces that boundary.

## What This Changes

The issue asks for `sessions.create` fork and parent-link creation to enforce source-session plugin ownership before copying or linking another session.

## Best Possible Solution

Add a narrow gateway security fix that denies plugin-runtime `sessions.create` parent-link and fork operations when the resolved parent entry belongs to another plugin, with regression coverage for foreign fork denial, foreign parent-link denial, and owned-parent success.
