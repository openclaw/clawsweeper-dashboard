## Label Justifications

- `P1`: The issue describes a stable gateway trust-boundary bug that can expose another plugin's session transcript to an in-process plugin-runtime caller under realistic preconditions.
- `impact:security`: The affected path lacks an ownership check before a plugin-runtime caller can fork another plugin-owned session transcript.
- `impact:session-state`: The unchecked create path can clone transcript state and graft parent-child relationships across plugin-owned sessions.
- `maturity:stable`: The affected `sessions.*` Gateway RPC surface belongs to the M4 Stable `gateway-runtime` maturity feature.

## Summary

Keep open: current main still lets `sessions.create` resolve and parent-link or fork a session by key without comparing the parent entry's `pluginOwnerId` to the plugin-runtime caller, while the sibling delete path enforces that ownership boundary.

## What This Changes

The issue asks OpenClaw to add a plugin-ownership check before `sessions.create` links to or forks a parent session owned by another plugin.

## Best Possible Solution

Add a narrow gateway fix that denies plugin-runtime `sessions.create` parent-link and fork operations when the resolved parent entry belongs to another plugin, with regression coverage for foreign fork denial, foreign parent-link denial, and owned-parent success.
