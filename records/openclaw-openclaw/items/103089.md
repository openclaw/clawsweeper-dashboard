## Summary

Keep open: current main still lets `sessions.create` resolve, parent-link, and fork a source session without checking the parent entry's `pluginOwnerId` against the plugin-runtime caller, while `sessions.delete` enforces that ownership boundary.

## What This Changes

The issue asks OpenClaw to deny `sessions.create` fork and parent-link operations when a plugin-runtime caller does not own the source session.

## Best Possible Solution

Add a narrow gateway security fix that checks the resolved parent session owner before `sessions.create` parent-linking or forking, with regression coverage for foreign-owner denial and same-owner success.
