## Summary

Keep this PR open, but it is not merge-ready: the credentialed-URL guard is useful security hardening, yet current main and the latest release still accept those cron webhook URLs, and the shared helper feeds validation, runtime delivery, and doctor migration paths without an approved upgrade policy or real cron-path proof.

The PR adds a username/password guard to `normalizeHttpWebhookUrl` so cron webhook URLs with URL userinfo are rejected.

## Best Possible Solution
