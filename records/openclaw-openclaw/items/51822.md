## Summary

Keep this PR open: the security hardening is useful, but the shared cron webhook normalizer also controls stored delivery, completion, failure, and doctor migration paths, so the fail-closed upgrade behavior needs maintainer/security acceptance and real cron-path proof before merge.

## What This Changes

The branch adds a username/password userinfo guard to `normalizeHttpWebhookUrl` so credentialed HTTP(S) cron webhook URLs normalize to `null`.

## Best Possible Solution

Land the credential guard only after maintainers choose the fail-closed policy and the PR adds upgrade-aware coverage or remediation for stored cron webhook targets plus real cron-path proof.

## Reproduction Assessment

Yes, source-level. Current main accepts credentialed HTTP(S) URLs in the shared helper, and the PR makes the helper return `null` for userinfo URLs that callers then reject or skip.

## Solution Assessment

No. The shared helper is a plausible choke point for new inputs, but it is not the best mergeable fix until stored-job upgrade behavior, maintainer security policy, and real cron-path proof are covered.
