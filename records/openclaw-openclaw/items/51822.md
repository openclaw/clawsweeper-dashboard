## Summary

The security hardening idea is valid, but this PR is still not merge-ready: the shared cron webhook normalizer feeds stored primary, completion, failure, and legacy doctor paths, so rejecting URL userinfo can stop existing webhook delivery without an upgrade-safe policy and tests. The supplied proof is only a direct helper screenshot, not a real cron add/update, doctor, dispatch, or webhook-delivery path.

## What This Changes

The PR adds a username/password userinfo rejection to the cron HTTP(S) webhook URL normalizer.

## Best Possible Solution
