## Summary

Keep open: the security hardening is still useful because current main and v2026.6.11 still accept credentialed cron webhook URLs, but this branch is not merge-ready because the shared helper change can fail closed across stored cron delivery and doctor migration paths without an explicit upgrade-safe policy and real cron-path proof.

## What This Changes

The PR adds a username/password userinfo rejection to the shared cron HTTP(S) webhook URL normalizer.

## Best Possible Solution

Land a current-main cron credential policy that covers primary, completion, failure, and legacy doctor paths with focused tests, redacted warnings or migration behavior, and real cron-path proof, or get an explicit maintainer decision to fail closed for existing credential-bearing webhook URLs.

## Solution Assessment

No. The helper guard is a plausible security check, but it is not the best complete fix until upgrade behavior, doctor handling, current-main integration, and real cron-path proof cover the shared validation surface.
