## Summary

Current `main` appears to have removed the reported forwarding failure: the gateway tool reads `path` and sends it to `config.schema.lookup`, while the process tool receives `sessionId` directly from its argument object. The remaining uncertainty is release provenance and whether the reporter’s installed 2026.6.11 tool surface predates the current intentional split between read-only `gateway` access and configuration writes through the `openclaw`/CLI path, so this should stay open until that version boundary is confirmed.

## What This Changes

Fix agent-tool calls so `path`, `raw`, `baseHash`, and `sessionId` reach the intended configuration or process operation instead of being silently discarded.

## System Context

Agent models invoke typed built-in tools. The gateway tool reads configuration and schema data through Gateway RPC, while the process tool manages background command sessions; each tool validates its own arguments before returning an agent-visible result.
