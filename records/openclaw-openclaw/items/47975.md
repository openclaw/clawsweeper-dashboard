## What This Changes

Completed one-shot subagent sessions remain visible or retained after completion and can leave the parent WebChat or dashboard session appearing unresponsive.

## Best Possible Solution

Define one contract for completed one-shot subagents: terminal child runs should leave active/status surfaces promptly, preserve intentionally retained transcripts and attachments, and align registry cleanup, sessions.list/Control UI projections, task reconciliation, and docs.

Question: What should the default contract be for completed run-mode subagent sessions: auto-archive them after archiveAfterMinutes, retain but hide them from active/status surfaces, or keep current retention and update docs?

Rationale: Current code and tests preserve keep-mode retention while docs promise auto-archive, and changing the default affects retained history, attachments, Control UI status, and users relying on completed child transcripts.

Likely owner: steipete

Owner reason: steipete has the strongest recent history across subagent lifecycle, session listing, and Control UI session surfaces.

Owner confidence: high

Options:

- **Retain but hide active status (recommended):** Keep completed subagent history by default while changing sessions/status/Control UI projections so terminal child runs do not look active or block the parent workflow.
- **Auto-archive run-mode subagents:** Make archiveAfterMinutes apply to completed run-mode subagents by default, preserving transcript archives while removing stale child rows from active list surfaces.
- **Keep retention and fix docs:** Document that default cleanup keeps run-mode subagent sessions and require callers to opt into cleanup="delete" for archival behavior.

## Reproduction Assessment

Yes for the cleanup/visibility gap at source level: default sessions_spawn uses cleanup="keep", keep-mode run registrations get no archive timer, and unfiltered session listings still include stored child rows. The full WebChat unresponsive/frozen symptom still needs live current-main proof.

## Solution Assessment

No, the current implementation is not the best complete solution because docs promise auto-archive while code/tests preserve keep-mode retention. A narrow predicate flip is risky; maintainers should choose retention versus hidden-active-surface semantics first.
