## Summary

Keep open: current main still defaults one-shot subagent cleanup to retained history, omits archive timers for keep-mode runs, and lets stored completed subagent rows flow into session listing/status paths, so the reported cleanup and responsiveness problem is not fully implemented away.

## What This Changes

Issue requests cleanup and recovery behavior so completed or failed one-shot subagent sessions do not persist in a way that leaves the main session unresponsive.

## Best Possible Solution

Define the terminal one-shot subagent retention contract, then implement it consistently across registry cleanup, sessions.list defaults, Control UI/status, task reconciliation, attachment retention, and docs.
