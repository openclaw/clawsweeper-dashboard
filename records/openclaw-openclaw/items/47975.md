## Summary

Keep open: current main still retains default run-mode subagent sessions, keep-mode runs are not auto-archived, and unfiltered session listing still starts from stored rows. Related issues cover narrower quota, replay, or scheduler-fairness slices, but this remains the canonical retained subagent session and responsiveness contract issue.

## What This Changes

The issue reports stale completed subagent sessions and delayed main-session responsiveness after subagent completion, especially in WebChat and attachment-backed runs.

## Best Possible Solution

Define the terminal one-shot subagent contract so completed children are immediately non-blocking in session/task/UI views while retained history is preserved, hidden, archived, or pruned according to a maintainer-approved policy.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should completed one-shot/run-mode subagent sessions remain visible retained history by default, be automatically hidden/archived/deleted after completion, or be split into retained history plus non-active UI/status projections?

Rationale: Current code and tests deliberately preserve keep-mode run subagents, while the issue and docs expect completed subagents not to pollute active session/status surfaces; changing this default is a user-visible session-history and upgrade contract decision.

Likely owner: steipete

Owner reason: Recent session organization and multi-surface UI/Gateway history make steipete the strongest routing candidate for the retention and visibility contract choice.

Owner confidence: high

Options:

- **Preserve History, Fix Visibility (recommended):** Keep completed child transcripts by default, but make session/task/Control UI/WebChat projections immediately mark them terminal and non-blocking with explicit cleanup actions.
- **Auto-Archive Completed Runs:** Archive or hide completed one-shot subagent sessions by default, accepting a retention behavior change that needs docs, migration/upgrade proof, and focused UI/session tests.
- **Add Explicit Retention Policy:** Introduce a retention knob only if maintainers decide existing cleanup, archive, and doctor surfaces cannot safely express the desired behavior.

## Reproduction Assessment

Partly. Source inspection on current main shows retained default subagent rows, no keep-mode archive timer, and unfiltered session-list eligibility; a live WSL2/WebChat run is still needed to reproduce the exact post-completion unresponsive timing.

## Solution Assessment

Unclear as an automated fix. The maintainable path is terminal-state reconciliation plus honest UI/status behavior, but maintainers must choose whether completed run-mode history should stay visible, be hidden, or be archived by default.
