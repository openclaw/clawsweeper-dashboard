## Summary

Keep open: current main still defaults one-shot subagent runs to retained `cleanup: "keep"`, gives keep-mode run subagents no archive timer, skips those retained runs in the sweeper, and includes retained child session rows in default session-list/status projections. That source-proves the stale retained-session part, while the exact WebChat parent-session freeze still needs live proof and a maintainer decision about one-shot retention, history, attachment, status, and UI semantics.

## What This Changes

The issue reports completed or failed one-shot subagent sessions remaining visible/retained after completion and causing the main WebChat/dashboard session to become temporarily unresponsive to follow-up messages.

## Best Possible Solution

Define a single terminal lifecycle contract for one-shot subagents: final delivery makes rows terminal and non-blocking, default views hide or archive them after configured retention, attachments/tasks reconcile to the same rule, and persistent session-mode history remains intentionally inspectable.
