## Summary

Keep open: current main still defaults one-shot subagent cleanup to retained history, does not assign archive timers to keep-mode runs, skips those rows in the sweeper, and still lets retained non-archived child rows flow into session listing/status paths. The retained-state part is source-proven, while the exact WebChat parent-session freeze still needs live proof and maintainer retention semantics.

## What This Changes

Requests cleanup or hiding of completed one-shot subagent sessions so stale child rows do not confuse Control UI/status or degrade parent-session responsiveness.

## Best Possible Solution

Define one terminal one-shot subagent lifecycle: final delivery makes rows terminal and non-blocking, default views hide or archive them after the configured retention, attachments and tasks reconcile to the same contract, and persistent session-mode history remains intentionally inspectable.

Rationale: Current source and docs disagree, and each direction changes user-visible history, attachment retention, Control UI status, task reconciliation, and recovery behavior.

Likely owner: steipete

Owner confidence: high

Options:

- **Retain but hide/archive by default (recommended):** Keep completed one-shot history inspectable while excluding terminal child rows from active/default session and status views after final delivery settles.
- **Delete after final delivery or TTL:** Make run-mode subagent cleanup remove child session rows according to archiveAfterMinutes, accepting reduced default history retention.
- **Keep current retention contract:** Document cleanup=keep as preserving completed rows and limit the code change to status honesty, manual maintenance, and clearer filtering.

Unclear as an automated fix: immediate deletion is only one plausible path, and maintainers need to choose retention, history, attachment, status, and UI semantics before changing defaults.
