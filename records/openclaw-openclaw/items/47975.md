## Summary

Keep open: current main and latest v2026.6.11 still default one-shot subagent runs to retained sessions, and current cleanup/listing code hides some stale child links rather than settling the broader post-completion retention, status, and parent responsiveness contract.

## What This Changes

The issue reports completed or failed run-mode subagent sessions remaining visible and contributing to main-session/WebChat unresponsiveness after subagent completion.

## Best Possible Solution

Define the post-completion contract so completed run-mode subagents become immediately terminal and non-blocking in session/task/UI views while preserving or deleting history only according to an explicit maintainer-approved retention policy.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should default run-mode subagent sessions be preserved as history after terminal cleanup, or should OpenClaw auto-hide/archive/delete them as ephemeral work by default?

Rationale: Current code deliberately preserves run-mode sessions by default, and changing that affects transcript retention, attachments, task reconciliation, session list semantics, and Control UI/WebChat expectations.

Likely owner: Peter Steinberger

Owner reason: The strongest current history signal is ownership of the subagent registry lifecycle/run-manager split and recent registry maintenance.

Owner confidence: high

Options:

- **Preserve History, Fix Visibility (recommended):** Keep completed run-mode subagent transcripts by default, but make session/task lists and WebChat status immediately mark them terminal and non-blocking.
- **Auto-Archive/Delete Run Children:** Make one-shot subagents ephemeral by default, accepting a retention behavior change that needs migration, docs, and fresh/upgrade proof.
- **Add A Retention Policy:** Introduce an explicit retention setting only if maintainers decide existing cleanup, status, and doctor behavior cannot express the desired contract.

## Reproduction Assessment

Yes at source level, but not live: current main still defaults one-shot subagents to kept sessions and explicitly skips archive timers for keep-mode run subagents. The live WebChat freeze still needs Crabbox or manual reproduction because the code evidence proves retention/listing behavior, not the exact unresponsive timing.

## Solution Assessment

Unclear: deleting completed sessions would solve the visible stale-row symptom, but it may be the wrong contract for retained history. The safer fix shape is terminal-state reconciliation plus honest UI/status behavior unless maintainers decide run-mode history should be discarded by default.
