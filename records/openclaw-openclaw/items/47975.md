The issue remains useful as the canonical tracker for subagent retention, stale UI/session visibility, and related responsiveness symptoms, but the fix needs a maintainer decision on history retention versus hiding/archive/delete semantics.

## What This Changes

The issue requests cleanup of completed subagent sessions and immediate main-session responsiveness after subagent completion.

## Best Possible Solution

Define the completed one-shot subagent contract first, then make terminal child sessions non-blocking and honest in session/task/UI views while preserving, hiding, archiving, or pruning history according to that chosen policy.
