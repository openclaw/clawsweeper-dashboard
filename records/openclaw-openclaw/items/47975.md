## Summary

Keep open: current main still keeps default run-mode subagent sessions and skips archive sweep for keep-mode subagent runs, while latest release v2026.6.11 shows the same behavior. The remaining fix needs a maintainer decision because cleanup, retained history, session/status visibility, and WebChat responsiveness semantics all meet here.

## What This Changes

The issue requests cleanup of completed run-mode subagent sessions so stale subagent state no longer leaves the main WebChat/dashboard session unresponsive or noisy.

## Best Possible Solution

Define one maintainer-approved contract for run-mode subagent retention and visibility: completed children should leave active/status surfaces promptly, preserve intentional transcript or attachment history, and make docs match the default cleanup path.

## Maintainer Decision

Kind: product_direction

Question: What should the default contract be for completed run-mode subagent sessions: retain them as history, auto-archive them after archiveAfterMinutes, or hide them from active/status surfaces while retaining records?

Rationale: Current code, tests, and docs disagree, and changing the default affects retained history, attachments, Control UI status, and users who rely on completed subagent transcripts.

Likely owner: steipete

Owner reason: The strongest local history signal is Peter Steinberger's recent work across subagent cleanup, registry, and docs, including the current-line blame in this checkout.

Owner confidence: high

Options:

- **Auto-archive completed run-mode subagents (recommended):** Make archiveAfterMinutes apply to completed run-mode subagents by default, preserving transcript archives while removing stale session rows from active/list surfaces.
- **Retain but hide from active surfaces:** Keep completed subagent records by default, but change sessions/status/Control UI projections so terminal children do not appear active or block the parent workflow.
- **Keep current retention and update docs:** Document that default cleanup keeps run-mode subagent sessions and require users or agents to opt into cleanup="delete" for archival behavior.

## Reproduction Assessment

Yes for the cleanup gap at source level: default run-mode subagents use cleanup="keep", receive no archive timer, and the sweeper skips those completed records. The full WebChat unresponsiveness symptom still needs live current-main proof.

## Solution Assessment

No, the current implementation is not the best complete solution because docs promise auto-archive while code and tests preserve keep-mode retention. The safer repair is a maintainer-approved retention/status contract rather than a one-line cleanup predicate change.
