## Label Justifications

- `P1`: The issue reports a broken agent/session workflow where completed subagents can leave the main user session delayed or apparently unresponsive after completion.
- `impact:session-state`: The affected behavior is divergence between completed subagent lifecycle state, retained session rows, status projections, and stored session cleanup.
- `impact:message-loss`: The user-visible impact is new WebChat/dashboard messages appearing queued, ignored, or lost after subagent completion.
- `maturity:stable`: The affected agents.subagents, gateway.sessions-list, and tools.session-status surfaces map to Gateway runtime M4 Stable in qa/maturity-scores.yaml and taxonomy.yaml.

## Summary

Keep open: current main and the latest stable release still default one-shot subagents to cleanup="keep", preserve keep-mode rows without archive timers, and leave stored rows visible through default session-list paths. A maintainer needs to choose the retention and visibility contract before a safe repair changes user history, attachments, docs, and Control UI behavior.

## What This Changes

Clean up or hide completed one-shot subagent sessions so the main WebChat/session workflow resumes promptly and status/session lists stop showing stale subagents.

## Best Possible Solution

Define one maintainer-approved contract for run-mode subagent retention and visibility, then make runtime cleanup, sessions.list/status, Control UI, docs, and tests agree while preserving intentional history.

Options:

- **Retain History, Hide Terminal Rows (recommended):** Keep cleanup="keep" as the history-preserving default, but mark completed run-mode children terminal and exclude them from active/default status and session-list surfaces so they cannot look live or block parent workflows.
- **Honor Auto-Archive Docs:** Make archiveAfterMinutes apply to completed run-mode subagents by default, preserving transcript archives while removing stale rows after the configured window but changing the currently shipped keep behavior.
- **Document Keep-Only Default:** Leave runtime retention unchanged and update docs/UI expectations so users must opt into cleanup="delete" or explicit cleanup commands for archival behavior.
