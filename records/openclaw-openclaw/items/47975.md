## Summary

Keep open: current main still retains default one-shot subagent sessions, skips archive/delete scheduling for keep-mode runs, and exposes terminal non-archived subagent rows through session-list/UI paths. The full WebChat stall was not live-reproduced in this read-only pass, but the retained-row/session-state path remains source-reproducible and recent issue discussion says it is still happening.

## What This Changes

The issue requests cleanup/reconciliation for completed subagent sessions so stale child rows do not leave the main session or status surfaces unresponsive after subagent completion.

## Best Possible Solution

Define the terminal one-shot subagent retention and visibility contract, then implement it consistently across registry cleanup, sessions.list defaults, Control UI/status, task reconciliation, attachment retention, docs, and focused regression coverage.

## Reproduction Assessment

Partly: there is a source-level reproduction for retained completed subagent rows, default keep cleanup, list/UI visibility, and task backing on current main. I do not have a high-confidence live reproduction of the full WebChat parent-stall symptom in this read-only review.

## Solution Assessment

Unclear: deleting or hiding rows immediately would address stale status noise, but maintainers first need to choose the retention, history, attachment, status, and delivery semantics that should become the product contract.
