## Summary

Keep open: current main still keeps normal run-mode subagent sessions by default, keep-mode runs do not receive archive timers, and unfiltered session-list paths still enumerate retained rows; existing liveness and task-reconciliation code only partially mitigates stale active display, so the reported cleanup/responsiveness problem is not fully implemented on main.

## What This Changes

The issue requests cleanup or hiding of completed one-shot subagent sessions so stale child rows do not persist or make the parent session appear unresponsive after subagent completion.

## Best Possible Solution

Define the terminal one-shot subagent lifecycle contract first, then implement it consistently across subagent registry cleanup, task reconciliation, session listing, Control UI/status visibility, attachment retention, and docs while leaving lane-starvation and orchestration UI improvements to their narrower trackers.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What should OpenClaw’s default terminal one-shot subagent retention and visibility contract be?

Rationale: The code has several plausible repair paths, but changing default cleanup or hiding retained child sessions changes user-visible history, attachment retention, task status, and operator recovery semantics.

Likely owner: steipete

Owner reason: The decision crosses subagent registry, gateway session listing, task maintenance, and product retention semantics, and this person has recent broad history across those paths.

Owner confidence: medium

Options:

- **Archive/hide terminal one-shot subagents by default (recommended):** Keep enough recent history for debugging but stop completed one-shot children from appearing active or blocking parent/session status surfaces after a defined retention window.
- **Delete terminal one-shot subagents by default:** Remove run-mode child session rows and attachments after successful delivery unless callers explicitly request `cleanup=keep`, at the cost of less default history.
- **Preserve current retention and improve diagnostics only:** Leave child rows visible by default and focus on making UI, status, and task surfaces distinguish retained history from active work.

## Reproduction Assessment

Partly: current source still preserves terminal subagent rows by default and tests assert keep-mode rows are not archived, but I did not live-reproduce the WebChat freeze interval in this read-only review.

## Solution Assessment

Unclear: immediate deletion or hiding is plausible, but maintainers should first choose the retention, history, attachment, task-status, and UI contract so the fix does not create a second inconsistent lifecycle path.
