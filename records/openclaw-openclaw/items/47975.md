## Summary

Keep open: current main still retains default run-mode subagent sessions and unfiltered session listing still starts from stored rows, while existing liveness/task-maintenance code only partially mitigates stale display and lost-task cases. The remaining fix needs a maintainer decision on retained history versus automatic hiding/archive/delete semantics before changing core session behavior.

## What This Changes

The issue asks OpenClaw to clean up completed one-shot subagent sessions and keep the parent session responsive immediately after subagent completion.

## Best Possible Solution

Define the post-completion contract so terminal one-shot subagents become immediately non-blocking in session/task/UI views, while history is preserved, archived, hidden, or pruned only according to a maintainer-approved retention policy.

Rationale: Current code and tests deliberately preserve keep-mode run subagents, but the issue reports that this retained state makes status/session surfaces misleading and can affect parent responsiveness; changing the default is a user-visible session-history contract decision.

Owner confidence: high

Options:

- **Preserve History, Fix Visibility (recommended):** Keep completed child transcripts by default, but make session/task/Control UI/WebChat projections immediately mark them terminal and non-blocking, with cleanup available through explicit actions.
- **Auto-Archive Completed Runs:** Archive or hide completed one-shot subagent sessions after terminal cleanup by default, accepting a retention behavior change that needs docs, migration/upgrade proof, and focused UI tests.
- **Add Explicit Retention Policy:** Introduce a retention setting only if maintainers decide existing cleanup and doctor/session maintenance surfaces cannot express the desired behavior safely.
