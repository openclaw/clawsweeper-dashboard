## Summary

Keep open: current main still defaults one-shot subagent runs to retained keep-mode sessions, keep-mode runs do not receive archive timers, and default session-list/UI paths still start from stored unarchived rows. The remaining work needs a maintainer decision on history retention versus active/default-list visibility before changing core session behavior.

## What This Changes

The issue requests that completed one-shot subagent sessions stop lingering in active/session surfaces and stop making the parent session/WebChat workflow appear unresponsive.

## Best Possible Solution

Define separate contracts for retained history, active/busy accounting, and default session-list visibility so terminal run-mode children stop affecting responsiveness immediately while intentional history remains accessible.
