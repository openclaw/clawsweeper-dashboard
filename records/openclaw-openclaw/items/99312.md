## Label Justifications

## Summary

This PR remains necessary: it supplies a bounded Mattermost fix for the open multi-account reload disruption, but it also introduces a new channel-plugin capability contract that needs gateway/plugin-owner acceptance before merge. The submitted proof and focused coverage support the implementation; the remaining blocker is the intended long-term API and opt-in boundary, not a confirmed patch defect.

## What This Changes

Adds optional `reload.accountScopedRestart` channel-plugin metadata and uses it for Mattermost so isolated named-account config changes restart only the affected account instead of the entire channel.

## Best Possible Solution

Accept one explicit, documented plugin capability only if gateway/plugin owners agree that per-account lifecycle isolation is an appropriate SDK contract; then land Mattermost as the first opt-in while other channels remain wholesale until they independently prove the contract.
