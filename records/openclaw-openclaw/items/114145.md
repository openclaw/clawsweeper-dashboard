## Summary

## What This Changes

Define a host-neutral contract for safely capturing Gateway state, retiring an idle generation, and admitting work only after replacement compute restores the accepted state and scheduler projection.

## System Context

Gateway suspension fences OpenClaw-owned admission and cron work while host infrastructure manages retained ingress, storage, compute placement, and wake-up. The proposed recovery contract would connect the Gateway's suspension, snapshot, restore, and scheduler-reconciliation seams so a replacement Gateway can safely reopen admission.

## Architecture Diagram

flowchart LR
  A[Host receives work or idle signal] --> B[Gateway suspension fence]
  B --> C[State-owner recovery inventory]
  C --> D[Verified recovery point]
  D --> E[Host retains state and wakes replacement]
  E --> F[Gateway restores scheduler and owners]
  F --> G[Restored-admission decision]
  G --> H[Host delivers retained work]

## Best Possible Solution

Agree a narrow, host-neutral OpenClaw contract for state-owner inventory, verified recovery points, and restored-admission identity; keep ingress retention, wake coalescing, placement, and rollout policy in the host implementation or plugin, then land only the smallest missing core seam with end-to-end failure-path proof.
