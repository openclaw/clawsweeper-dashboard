## Summary

Keep open: current main and v2026.6.11 still load and watch `~/.agents/skills` as an always-on personal skill source, and the overlapping source-disable report was closed in favor of this issue. The remaining work is a maintainer product/config decision, not conservative cleanup.

## What This Changes

The issue requests a config option to disable loading Claude Code-style personal skills from `~/.agents/skills` so they are not injected into every agent prompt.

## Best Possible Solution

Add a maintainer-approved, backward-compatible built-in skill-source opt-out that skips disabled roots before discovery and watcher registration, with defaults preserving existing behavior.

- **Decline new config:** Keep current discovery and direct users to per-agent allowlists, prompt limits, and per-skill disables even though those do not prevent scanning.

Yes. Source inspection shows current main and v2026.6.11 still load and watch `~/.agents/skills` as `agents-skills-personal`, while strict `skills.load` config has no source-disable field.

## Solution Assessment

Unclear until maintainers choose the API shape. A typed source-disable setting is the cleanest current path, but it needs owner approval because existing per-skill disables and prompt limits are not equivalent to skipping discovery.
