## Summary

Keep open: current main and v2026.6.11 still load and watch the `$HOME/.agents/skills` source with no source-level opt-out, and the duplicate source-disable report was already closed in favor of this issue. The remaining work is a maintainer product/config decision, not conservative cleanup.

## What This Changes

Request an opt-out for OpenClaw's personal `.agents/skills` source so Claude Code skill directories are not always discovered, watched, and injected into prompts.

## Best Possible Solution

Maintainers should choose a backward-compatible source opt-out contract and implement it across discovery, watcher registration, config schema/help, docs, status behavior, and focused regression tests while preserving the default loading order when unset.

Options:

- **Typed Source Disable List (recommended):** Add a narrow `skills.load.disableSources`-style list with explicit allowed source ids and make discovery, watchers, docs, and status respect it.
- **Personal-Source Toggle Only:** Expose only a boolean for the personal `.agents/skills` source, minimizing scope but leaving project-source and future source opt-outs unresolved.
- **Decline Source Opt-Out:** Keep built-in source scanning always on and direct users to prompt limits and per-skill disables, accepting that source conflicts and watcher overhead remain.

## Solution Assessment
