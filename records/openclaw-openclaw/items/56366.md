## Summary

Keep open: current main and the latest release still load and watch `~/.agents/skills` as a built-in personal skill source, and the remaining work is a maintainer decision about public `skills.load` config semantics.

## What This Changes

The issue requests a configurable way to disable automatic scanning of `~/.agents/skills` so Claude Code personal skills are not injected into OpenClaw prompts.

## Best Possible Solution

Maintainers should choose a backward-compatible skill-source opt-out contract and apply it consistently across discovery, watcher registration, config schema/help, docs, status/snapshot behavior, and focused regression tests.

Options:

- **Add typed source disable list (recommended):** Expose a closed, documented `skills.load.disableSources` list for sources such as `agents-skills-personal`, default it to empty, and make loader/watcher/status/docs honor it together.
- **Add narrow personal toggle:** Expose only a personal `.agents/skills` toggle, which solves this issue with less flexibility but may need another option later for project-agent sources.
- **Decline source-level opt-out:** Keep current source discovery and direct users to per-agent allowlists, prompt budgets, or per-skill disables, then close this issue as a deliberate product decision.

## Solution Assessment

Unclear until maintainers choose the public API shape. A typed source-disable list is the cleanest observed option, but the repository has a high bar for new config surface and the implementation must cover loader, watcher, docs, and tests together.
