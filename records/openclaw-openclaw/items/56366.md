## Summary

Keep open: current main and latest release still load and watch the personal `~/.agents/skills` source with no source-level opt-out, and the matching duplicate was already closed in favor of this issue. The remaining work is a maintainer product/config decision, not conservative cleanup.

## What This Changes

Request an option to disable or ignore automatic `~/.agents/skills` discovery so OpenClaw can coexist with Claude Code without unwanted skill conflicts or prompt bloat.

## Best Possible Solution

Maintainers should choose a backward-compatible typed skill-source opt-out contract and implement it consistently in the loader, watcher, config schema/help, docs, and focused tests while leaving current discovery enabled by default.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What public `skills.load` contract should OpenClaw support for disabling built-in skill sources such as `agents-skills-personal`?

Rationale: The source-level behavior is reproducible, but fixing it adds public config surface and changes built-in skill-source semantics, which the repository policy treats as maintainer-owned product/API direction.

Likely owner: steipete

Owner reason: Recent blame and refactor history place this account closest to the current skills loader, watcher, and config surface.

Owner confidence: high

Options:

- **Typed source-disable list (recommended):** Add a small enum-backed `skills.load.disableSources` contract and apply it before discovery and watcher registration for built-in source ids.
- **Narrow personal toggle:** Add only a personal `.agents/skills` toggle, which solves this issue with less generality but may create another one-off config knob later.
- **No new config:** Keep current discovery and rely on prompt limits, per-skill disables, and agent allowlists, accepting that users with shared Claude Code skill directories still need manual cleanup.

## Reproduction Assessment

Yes. Source inspection shows current main and `v2026.6.11` still load and watch `~/.agents/skills` as `agents-skills-personal`, and the strict `skills.load` schema has no source-disable field.

## Solution Assessment

Unclear until maintainers choose the API shape. A typed source-disable list looks cleaner than a raw path ignore list because discovery and watcher code already use stable source ids, but adding config surface needs explicit product approval.
