## Summary

Keep open: current main and v2026.6.11 still hardcode the personal `~/.agents/skills` source in both discovery and watcher setup, while strict `skills.load` config has no source-level opt-out. The duplicate report at https://github.com/openclaw/openclaw/issues/64639 was closed in favor of this issue, so the remaining work is a maintainer product/config decision rather than cleanup.

## What This Changes

The issue requests a configuration option to disable OpenClaw's scan of `~/.agents/skills` so Claude Code personal skills are not always loaded into OpenClaw prompts.

## Best Possible Solution

Maintainers should choose a backward-compatible skill-source opt-out contract, then implement it consistently across discovery, watcher registration, config schema/help, docs, status behavior, and focused regression tests.

Rationale: The source-level problem is clear, but adding config surface and changing built-in skill-source behavior is an operator-facing product/API choice under the repo's config-surface policy.

Options:

- **Add typed source disable list (recommended):** Expose a backward-compatible enum-style setting such as `skills.load.disableSources` and make discovery, watcher targets, status, docs, and tests honor it for built-in skill roots.
- **Add narrow personal toggle:** Expose only a personal `.agents/skills` toggle, minimizing API surface but leaving project-agent or future source controls to later decisions.
- **Reject source opt-out:** Keep current source behavior and direct affected users to per-skill disables and prompt limits, accepting that large Claude Code skill directories remain noisy.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 still load and watch `~/.agents/skills` as `agents-skills-personal`, while strict `skills.load` config has no source-disable field.

## Solution Assessment

Unclear until maintainers choose the public API shape. A generic source-disable setting is plausible, but the broader on-demand skill-routing idea should stay separate from this short-term source opt-out.
