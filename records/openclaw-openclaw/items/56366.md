## Summary

Keep open: current main and the latest release still load and watch the personal `~/.agents/skills` source with no source-level opt-out, and the exact duplicate was closed in favor of this issue. This remains a product/config API decision rather than conservative cleanup.

## What This Changes

Request an opt-out for OpenClaw's automatic personal `.agents/skills` discovery so Claude Code skill directories do not inflate or override OpenClaw skill prompts.

## Best Possible Solution

Maintainers should choose a backward-compatible built-in skill-source opt-out contract and implement it consistently across discovery, watcher registration, schema/help, docs, and focused tests while preserving current defaults when unset.

Rationale: The source-level problem is real, but every useful repair adds or changes public `skills.load` configuration and built-in source semantics, which repository policy treats as a maintainer product/API decision.

Likely owner: steipete

Owner reason: This account has the strongest recent history on the watcher/config/docs side of the skills surface and is the best available owner for the API-shape decision.

Owner confidence: high

Options:

- **Add typed source disables (recommended):** Expose a narrow enum-like `skills.load.disabledSources` list, default to current behavior, and skip disabled sources before both discovery and watcher registration.
- **Add personal-source toggle:** Expose a smaller boolean for only `~/.agents/skills`, reducing immediate API surface but leaving project-agent and future source opt-outs unresolved.
- **Keep current loading model:** Decline new config surface and document per-agent allowlists, prompt limits, and per-skill disables as the supported controls.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 still load and watch `~/.agents/skills` as `agents-skills-personal`, while strict `skills.load` config has no source-disable field.

## Solution Assessment

Unclear until maintainers choose the public API shape. A typed source-id disable list looks narrower than a path ignore list, but automation should not choose that config contract unilaterally.
