## Summary

Keep open: current main and the latest release still load and watch the personal `.agents/skills` source with no source-level opt-out, and the only exact duplicate was closed in favor of this issue. The remaining work is a real skills/config product decision, not conservative cleanup.

## What This Changes

The issue asks for a public configuration option to stop OpenClaw from automatically scanning personal or project `.agents/skills` directories to avoid coexistence conflicts and prompt-token bloat.

## Best Possible Solution

Maintainers should choose one backward-compatible built-in skill-source opt-out contract and apply it consistently to discovery, watcher registration, config schema/help, docs, status behavior, and focused tests.

## Maintainer Decision

Kind: product_direction

Question: Which public contract should OpenClaw expose, if any, for disabling built-in skill source roots such as `agents-skills-personal`?

Rationale: The source-level problem is real, but adding or declining a `skills.load` opt-out changes public config semantics and built-in skill-source behavior, which repo policy treats as maintainer product/API direction.

Likely owner: steipete

Owner reason: This account has the strongest recent history on watcher/config/docs handling for the skills source surface and is the best available owner for the API-shape decision.

Owner confidence: medium

Options:

- **Add typed disabled sources (recommended):** Expose a narrow enum-like `skills.load.disabledSources` list for built-in skill source ids, defaulting to current behavior and skipping disabled sources before discovery and watcher registration.
- **Add personal-source toggle:** Expose a smaller boolean for only the personal `.agents/skills` source, reducing API surface but leaving project-agent and future source opt-outs unresolved.
- **Keep current loading model:** Decline new config surface and document per-skill disables, allowlists, and prompt limits as the supported controls.

## Reproduction Assessment

Yes. Source inspection on current main and `v2026.6.11` shows `.agents/skills` is loaded and watched as `agents-skills-personal`, while strict `skills.load` config has no source-disable or ignore-dir field.

## Solution Assessment

Unclear until maintainers choose the public API shape. A typed built-in source-disable list is the cleanest narrow option, but adding that config contract should not be chosen by cleanup automation.
