## Summary

Keep open: current main and the latest release still load and watch `~/.agents/skills` as a built-in personal skill source with no source-level opt-out, and the overlapping report was closed in favor of this issue. The remaining work is a maintainer product/config decision, not conservative cleanup.

## What This Changes

The issue requests a configuration option to disable scanning of the personal `~/.agents/skills` source so OpenClaw can coexist with Claude Code skill directories without prompt bloat or source collisions.

## Best Possible Solution

Maintainers should choose one backward-compatible skill-source opt-out contract and apply it consistently across discovery, watcher registration, schema/help, docs, and regression tests.

## Reproduction Assessment

Yes. Source inspection shows current `main` and `v2026.6.11` still load and watch `~/.agents/skills` as `agents-skills-personal`, while strict `skills.load` config has no source-disable field.

## Solution Assessment

Unclear until maintainers choose the public API shape. A general source-disable setting is plausible, but OpenClaw policy sets a high bar for new config surface and the implementation must cover discovery, watching, docs, and tests together.
