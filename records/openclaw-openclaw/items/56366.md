## Summary

Keep open: current main and v2026.6.11 still load and watch `~/.agents/skills` as a built-in personal skill source with no source-level opt-out, and the overlapping report was closed in favor of this issue. The remaining work is a maintainer product/config decision, not conservative cleanup.

## What This Changes

Request to add a configuration option that disables or ignores OpenClaw scanning of the personal Claude Code-compatible `~/.agents/skills` directory.

## Best Possible Solution

Maintainers should choose a backward-compatible skill-source opt-out contract, then implement it consistently across discovery, watcher registration, config schema/help, docs, status behavior, and focused regression tests.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 still load and watch `~/.agents/skills` as `agents-skills-personal`, while the strict `skills.load` config schema has no source-disable field.

## Solution Assessment

Unclear until maintainers choose the public API shape. A generic source-disable setting is plausible, but existing per-skill disables and prompt limits do not provide a source-level opt-out, and the implementation must cover discovery, watching, docs, and tests together.
