## Summary

Keep open: current main and v2026.6.11 still load and watch the personal `~/.agents/skills` source with no source-level opt-out, and the exact duplicate was closed in favor of this issue. The remaining work is a real skills/config product decision, not conservative cleanup.

## What This Changes

Request to add a configuration option that disables or ignores `~/.agents/skills` scanning so Claude Code personal skills do not automatically enter OpenClaw skill discovery and prompts.

## Best Possible Solution

Expose a backward-compatible, typed built-in skill-source opt-out that skips disabled roots before discovery and watcher registration, preserves current behavior by default, and documents status/snapshot semantics.

Options:

- **Add typed disabled sources (recommended):** Expose a narrow enum-like `skills.load` list for built-in skill source ids, defaulting to current behavior and skipping disabled sources before discovery and watcher registration.
- **Add personal-source toggle:** Expose a smaller boolean for `~/.agents/skills` only, reducing API surface but leaving project-agent and future source opt-outs unresolved.
- **Keep current loading model:** Decline new source-level config and document per-agent skill allowlists, prompt limits, and per-skill disables as the supported controls.

Yes, at source level. Current main and v2026.6.11 still load and watch `~/.agents/skills` as `agents-skills-personal`, while strict `skills.load` config has no source-disable field.

## Solution Assessment

Unclear until maintainers choose the public API shape. A typed disabled-source setting is the narrowest maintainable option I saw, but automation should not pick that contract unilaterally.
