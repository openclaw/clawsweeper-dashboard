## Summary

Keep open: current main and the latest release still load and watch `~/.agents/skills` as a built-in skill source with no source-level opt-out, and the related duplicate was already closed in favor of this issue. The remaining work is a maintainer product/config decision, not conservative cleanup.

## What This Changes

The issue requests an OpenClaw config option to skip the built-in personal `~/.agents/skills` skill source so Claude Code skills do not inflate prompts or override OpenClaw skills.

## Best Possible Solution

Maintainers should choose a backward-compatible skill-source opt-out contract, then implement it consistently across discovery, watcher registration, config schema/help, docs, status behavior, and focused regression tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a public opt-out for the built-in personal `~/.agents/skills` source, and if so should the config be a general typed source-disable list or a narrower personal-source toggle?

Rationale: The source-level problem is clear, but repository policy sets a high bar for new config surface and the choice affects a documented built-in skill source, watcher behavior, status output, docs, and upgrade expectations.

Likely owner: steipete

Owner reason: Current main blame and adjacent issue handling place this account closest to the present skills loader, watcher, config, and docs surfaces.

Owner confidence: high

Options:

- **Add a typed source-disable list (recommended):** Expose a narrow `skills.load` setting for named built-in sources and make discovery, watchers, status, docs, and tests honor it while preserving current defaults when unset.
- **Add only a personal-source toggle:** Solve this issue with a smaller `~/.agents/skills` opt-out, but accept a less extensible contract if other built-in roots later need similar handling.
- **Keep current source model:** Decline the source opt-out and steer users to skill allowlists, prompt budgets, or per-skill disables, leaving scanning and precedence unchanged.

## Reproduction Assessment

Yes at source level. Current main and `v2026.6.11` still load and watch `~/.agents/skills` as `agents-skills-personal`, while the strict `skills.load` config has no source-disable field.

## Solution Assessment

Unclear until maintainers choose the public API shape. A general typed source-disable setting looks like the best long-term fit, but existing prompt budget and allowlist knobs only mitigate prompt size and do not stop source scanning or precedence effects.
