## Summary

Keep open: current main and the latest release still load and watch `~/.agents/skills` as a built-in personal skill source, while the strict `skills.load` config has no source-level opt-out. The overlapping report was closed in favor of this issue, so the remaining work is a maintainer product/config decision rather than cleanup.

## What This Changes

The issue requests a configuration option to disable scanning `~/.agents/skills`, and possibly `<workspace>/.agents/skills`, to avoid Claude Code skill conflicts and prompt bloat.

## Best Possible Solution

Maintainers should choose a backward-compatible source-disable contract, preferably a typed built-in source list defaulting empty, and apply it consistently before discovery and watcher registration with docs and focused regression coverage.
