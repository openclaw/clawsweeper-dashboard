## Summary

Keep open: current main and the latest release still load and watch `~/.agents/skills` as a built-in skill source with no source-level opt-out. The overlapping source-disable issue was closed in favor of this issue, so the remaining work is a maintainer product/config decision rather than cleanup-closeable.

## What This Changes

The issue requests a configuration-supported way to disable or ignore OpenClaw's automatic `.agents/skills` discovery, especially `~/.agents/skills`, for Claude Code coexistence and large external skill collections.

## Best Possible Solution

Define a backward-compatible skill-source policy that keeps existing discovery enabled by default, adds an explicit documented opt-out if maintainers want it, and applies it consistently to discovery, watcher registration, status/snapshots, docs, and tests.

- **Use existing allowlists only:** Keep source discovery always-on and document `agents.defaults.skills` or per-agent `skills: []` as the supported way to avoid prompt exposure.

## Reproduction Assessment

Yes. Source inspection shows current main and `v2026.6.11` still load and watch `~/.agents/skills` as `agents-skills-personal`, while strict `skills.load` config has no source-disable field.

## Solution Assessment

Unclear until maintainers choose the public API shape. A source-id opt-out looks narrower than a filesystem ignore list because the implementation already has named source ids, but existing per-agent allowlists should remain the documented prompt-visibility mitigation.
