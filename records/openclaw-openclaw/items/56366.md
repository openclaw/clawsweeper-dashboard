## Label Justifications

- `P2`: The issue reports real prompt/context bloat and skill precedence effects, but it is a bounded feature/config decision rather than an urgent outage.
- `impact:session-state`: The always-on personal skill source can inject unwanted skill metadata into the agent prompt/session context across runs.
- `impact:ux-friction`: Users with large Claude Code skill directories currently need impractical per-skill disables or filesystem workarounds to avoid prompt bloat.

## Summary

Keep open: current main and v2026.6.11 still load and watch the personal `~/.agents/skills` source with no source-level opt-out, and the exact duplicate was closed in favor of this canonical issue. This remains a valid config/product decision rather than conservative cleanup.

## What This Changes

The issue requests a configuration option to disable scanning `~/.agents/skills` so OpenClaw can coexist with Claude Code skill directories without prompt bloat or source conflicts.

## Best Possible Solution

Maintainers should choose a backward-compatible built-in skill-source opt-out contract and implement it consistently across discovery, watcher registration, config schema/help, docs, status/snapshot behavior, and focused tests.

## Maintainer Decision

Kind: product_direction

Question: Which public contract should OpenClaw expose, if any, for disabling built-in skill source roots such as `agents-skills-personal`?

Rationale: The source-level problem is real, but every plausible fix adds public `skills.load` configuration and changes built-in skill-source behavior, which repository policy reserves for maintainer product/API judgment.

Likely owner: steipete

Owner reason: This person has the strongest verified recent history on the skills config, loader, watcher, and docs surfaces that the decision would change.

Owner confidence: high

Options:

- **Add typed `disabledSources` (recommended):** Expose a narrow enum-like list of built-in skill source ids, default to current behavior, and skip disabled sources before discovery and watcher registration.
- **Add a personal-source toggle:** Expose a smaller boolean for `~/.agents/skills` only, reducing API surface but leaving project-agent and future source opt-outs unresolved.
- **Keep current loading model:** Decline new config surface and document per-agent skill allowlists, prompt limits, and per-skill disables as the supported controls.

## Reproduction Assessment

Yes, source-level. Current main and v2026.6.11 still load and watch `~/.agents/skills` as `agents-skills-personal`, and strict `skills.load` config has no source-disable field.

## Solution Assessment

Unclear until maintainers choose the public API shape. A typed source-disable setting is the cleanest narrow option, but the repository's config-surface policy means automation should not pick it unilaterally.
