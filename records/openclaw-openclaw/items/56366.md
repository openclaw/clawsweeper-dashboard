## What This Changes

The issue requests a configuration option to disable scanning Claude Code-compatible personal skill directories such as `~/.agents/skills`.

## Best Possible Solution

Choose a backward-compatible `skills.load` source opt-out contract, keep existing defaults when unset, and apply it consistently before discovery and watcher registration with docs and regression coverage.

Options:

- **Add a typed source-disable list (recommended):** Expose a default-empty `skills.load.disableSources` constrained to known source ids and apply it before both discovery and watcher target registration.
- **Add a narrow personal-source toggle:** Expose only a `skills.load.personalAgentsSkills` or equivalent boolean if maintainers want the smallest public API for this coexistence case.
- **Decline new config surface:** Keep current behavior and document allowlists, prompt limits, and per-skill disables as the supported mitigations, accepting that scanning still occurs.

## Solution Assessment

Unclear until maintainers choose the public API shape. A typed source-disable list looks cleaner than path-based ignores because it avoids path-normalization ambiguity and can cover discovery plus watcher behavior together.
