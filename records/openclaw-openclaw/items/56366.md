## Summary

## What This Changes

Request to add a configuration option that disables or ignores the personal `~/.agents/skills` scan so Claude Code skills are not automatically injected into OpenClaw skill context.

## Best Possible Solution

Maintainers should choose a backward-compatible built-in skill-source opt-out contract and implement it consistently across discovery, watcher registration, config schema/help, docs, status/snapshot behavior, and focused tests.

Options:

- **Add typed disabled sources (recommended):** Expose a narrow enum-like `skills.load.disabledSources` list, defaulting to current behavior and skipping disabled sources before discovery and watcher registration.
- **Add a personal-source toggle:** Expose a smaller boolean for `~/.agents/skills` only, reducing API surface but leaving project-agent and future source opt-outs unresolved.
- **Keep current loading model:** Decline new config surface and document per-agent skill allowlists, prompt limits, and per-skill disables as the supported controls.

Yes. Source inspection is enough to reproduce the missing opt-out because current main and v2026.6.11 still load and watch `~/.agents/skills`, while strict `skills.load` config lacks a source-disable field.

## Solution Assessment

Unclear until maintainers choose the public API shape. A typed source-disable setting is the cleanest narrow option, but repository config-surface policy means automation should not pick it unilaterally.
