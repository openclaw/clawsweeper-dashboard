## Summary

The remaining blocker is a maintainer product/API decision because the fix adds public `skills.load` config surface.

## What This Changes

Request an OpenClaw config option to disable or ignore scanning `~/.agents/skills` so Claude Code personal skills do not inflate or conflict with OpenClaw skill context.

## Best Possible Solution

Maintainers should choose one backward-compatible skill-source opt-out contract, then apply it consistently before discovery and watcher registration with schema/help/docs/status coverage and focused regression tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which public opt-out contract should OpenClaw support for built-in skill sources such as `agents-skills-personal`?

Rationale: The code evidence supports the problem, but adding a `skills.load` setting changes public config semantics and built-in source behavior, which repository policy reserves for maintainer product/API judgment.

Likely owner: steipete

Owner reason: The current loader, watcher, and config files blame to Peter Steinberger, making this the strongest current-main owner signal for deciding the config surface.

Owner confidence: medium

Options:

- **Typed disabled source list (recommended):** Add a default-empty `skills.load.disabledSources` style list over known source IDs and apply it consistently to discovery, watching, status, docs, and tests.
- **Narrow personal-source toggle:** Add only a personal `.agents/skills` toggle, minimizing surface area but leaving future source opt-outs as separate product decisions.
- **Keep current source scanning:** Do not add a source-level opt-out and instead rely on per-skill disables or agent allowlists despite the reported bulk-management and token-cost limitations.

## Reproduction Assessment

Yes. Source inspection on current main and `v2026.6.11` shows `~/.agents/skills` is still loaded and watched as `agents-skills-personal`, while `skills.load` has no source-disable setting.

## Solution Assessment

Unclear until maintainers choose the public API shape. A typed disabled-source list looks cleaner than path ignores, but the best fix must cover loader, watcher, config schema/help, docs, and tests together.
