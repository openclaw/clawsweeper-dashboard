## Summary

Keep open: current main and the latest release still load and watch `$HOME/.agents/skills` as a built-in personal skill source with no source-level opt-out, while the overlapping report was closed in favor of this issue. The remaining work is a maintainer product/config decision, not conservative cleanup.

## What This Changes

Request to add a supported config-level way to skip scanning `$HOME/.agents/skills` and possibly other built-in skill roots so Claude Code skills do not bloat or override OpenClaw skill prompts.

## Best Possible Solution

Maintainers should choose a backward-compatible skill-source opt-out contract, then implement it consistently across discovery, watcher registration, config schema/help, docs, status behavior, and focused regression tests.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 still load and watch `$HOME/.agents/skills` as `agents-skills-personal`, while strict `skills.load` config has no source-disable field.

## Solution Assessment

Unclear until maintainers choose the public API shape. A general source-disable setting is plausible, but OpenClaw policy sets a high bar for new config surface and the implementation must cover discovery, watching, docs, and tests together.
