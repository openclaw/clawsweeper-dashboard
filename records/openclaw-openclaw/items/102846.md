## Label Justifications

- `P1`: Named profile startup can silently mutate approval policy state across an isolation boundary for users running separate gateways or test profiles.
- `impact:data-loss`: The reported path archives or moves the default profile's approval JSON while launching a separate profile.
- `impact:security`: Exec and plugin approval trust decisions can be imported across profile boundaries, weakening approval-policy isolation.
- `maturity:stable`: The issue affects Gateway runtime approval behavior, and `gateway-runtime` is M4 Stable in the maturity scorecard.

## Summary

Keep open: current main and the latest release still allow profile-derived state roots to look like explicit state-dir relocations, and the linked closing PR is still open rather than merged.

## What This Changes

The issue asks OpenClaw to keep named `--profile` approval state isolated from the default profile while preserving the shipped explicit `OPENCLAW_STATE_DIR` relocation migration.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/102883, or an equivalent fix, so non-default profiles skip default-profile approval imports, archives, and pending-migration fallback while explicit state-dir relocation remains covered.
