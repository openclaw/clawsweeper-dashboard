## Label Justifications

- `impact:data-loss`: The reported migration renames the default profile's approval file to a migrated archive while launching a different profile.
- `impact:security`: Exec and plugin approval trust decisions can cross the named-profile isolation boundary.
- `maturity:stable`: The affected CLI/profile and Gateway approval surfaces map to M4 Stable entries in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main still lets named-profile startup paths look like bare state-dir relocations for approval migrations, and the linked candidate fix is still an open PR rather than merged code.

## What This Changes

This issue reports that non-default profiles can import and archive default-profile exec and plugin-binding approval state during startup migration.

## Best Possible Solution

Land or replace the linked profile-aware migration fix so non-default profiles skip default-profile approval imports, archives, and legacy fail-closed fallback while bare state-dir relocation keeps its compatibility path.
