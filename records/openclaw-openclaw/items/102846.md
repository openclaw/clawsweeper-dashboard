## Label Justifications

- `P1`: Named-profile startup can silently mutate default-profile approval state and import trust decisions across an isolation boundary.
- `impact:data-loss`: The reported path archives the default profile's approval JSON while launching a separate named profile.
- `impact:security`: Exec and plugin approval trust decisions can cross named-profile boundaries, weakening the expected approval isolation.
- `maturity:stable`: The issue affects the M4 Stable Gateway runtime approvals surface, including gateway.exec-approvals and gateway.plugin-approvals.

## Summary

Keep open: current main and v2026.6.11 still let profile-derived state dirs hit the default-profile approval migration path, and the open linked PR is a candidate fix but has not merged.

## What This Changes

Named profiles should not import, archive, or otherwise mutate default-profile exec or plugin-binding approval state while bare OPENCLAW_STATE_DIR relocation keeps its shipped migration.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/102883 or an equivalent narrow fix that guards non-default profiles in TypeScript and macOS approval migration paths while preserving bare state-dir relocation coverage.
