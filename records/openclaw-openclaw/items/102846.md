## Label Justifications

- `P1`: A startup migration can silently move approval policy across profile boundaries for users running named profiles or multiple gateways.
- `impact:security`: The report concerns approval-policy trust decisions being imported into an isolated profile.
- `impact:data-loss`: The default profile's active approval file can be archived away during a named-profile launch, removing active config state from that profile.
- `maturity:stable`: The issue affects the M4 Stable macOS Gateway host Profiles and Isolation surface, specifically profile-specific state roots.

## Summary

Keep this issue open: current main and the latest release still show the named-profile approval migration boundary problem, and no canonical fix or duplicate was found.

## What This Changes

The issue reports that named profiles can import and archive default-profile approval state during startup migration.

## Best Possible Solution

Keep the bare `OPENCLAW_STATE_DIR` compatibility migration, but skip default-profile approval imports and archives when the state dir came from an explicit non-default named profile unless a maintainer-approved migration policy says otherwise.
