## Summary

Keep open: current main still does not provide Redis/BullMQ-style distributed job orchestration, shared worker claiming, or horizontal worker coordination. The ScalyClaw prototype is useful prior art, but this remains a broad architecture/product decision rather than cleanup-close material.

## What This Changes

The issue proposes Redis/BullMQ-style horizontal scaling for background jobs, delayed work, cron scheduling, retries, dead-letter handling, and worker coordination.

## Best Possible Solution

Keep this open for maintainer architecture review and define a backend-neutral distributed scheduler/job ownership contract or plugin API before choosing Redis/BullMQ as the implementation detail.

No, not as a direct Redis/BullMQ core integration yet. The maintainable path is a maintainer-approved backend-neutral scheduler/job ownership contract with a clear core-or-plugin boundary.
