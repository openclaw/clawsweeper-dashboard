## Summary

Keep open. Current main still does not provide the requested Redis/BullMQ-style distributed job orchestration, shared worker claiming, dead-letter handling, queue observability, or horizontal worker coordination; related open items cover narrower cron, session storage, distributed runtime, and worker placement slices without superseding this broader architecture proposal.

## What This Changes

The issue proposes adding Redis/BullMQ-style distributed job orchestration and worker coordination for horizontally scaled OpenClaw deployments.

## Best Possible Solution

Keep this as the broad horizontal job-orchestration architecture tracker until maintainers decide whether OpenClaw should add a backend-neutral distributed scheduler/job seam, split pieces into narrower cron/session/runtime trackers, or document the ScalyClaw-style Redis/BullMQ approach as an external/plugin pattern.

## Reproduction Assessment

Yes for source confirmation, not as a bug reproduction: current main still uses in-process command lanes, Gateway-local cron execution, and SQLite-backed local ledgers rather than a Redis/BullMQ-style distributed worker queue.

## Solution Assessment

Unclear as a direct implementation: Redis/BullMQ and the ScalyClaw prototype are useful prior art, but OpenClaw needs maintainer direction on backend-neutral API shape, core versus plugin ownership, credentials, failure semantics, and upgrade behavior.
