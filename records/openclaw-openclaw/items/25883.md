## Summary

Keep open: current main and v2026.6.11 still use in-process command lanes, Gateway-local cron execution, process-local cron ownership, and local SQLite-backed task/cron ledgers rather than Redis/BullMQ-style distributed worker coordination. The linked ScalyClaw prototype is useful prior art, but integrating this needs maintainer architecture direction.

## What This Changes

Proposal to add Redis/BullMQ-style distributed job orchestration with separate workers, retries/backoff, delayed and cron jobs, dead-letter handling, and queue observability for horizontally scaled deployments.

## Best Possible Solution

Define a maintainer-approved backend-neutral distributed scheduler/job ownership contract or plugin API first, then decide whether ScalyClaw/BullMQ-style Redis orchestration belongs in core, a plugin, or external deployment docs.
