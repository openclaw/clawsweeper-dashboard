## Summary

Keep open. Current main and v2026.6.11 still lack the requested Redis/BullMQ-style distributed job orchestration, shared worker claiming, dead-letter queue, queue observability, and horizontal worker coordination; related open issues cover narrower cron, session-storage, runtime-split, and subagent-placement slices without replacing this broader architecture proposal.

## What This Changes

The issue proposes a Redis/BullMQ-backed distributed job orchestration layer for background, delayed, scheduled, and long-running OpenClaw work.

## Best Possible Solution

Keep this issue open as the broad horizontal job-orchestration architecture tracker until maintainers decide whether OpenClaw should add a backend-neutral distributed scheduler/job seam, split remaining work into narrower cron/session/runtime trackers, or document the ScalyClaw-style Redis/BullMQ approach as an external/plugin pattern.

## Reproduction Assessment

Yes for source confirmation, not as a bug reproduction: current main uses in-process command lanes, Gateway-local cron execution, process-local active-run markers, and SQLite-backed ledgers rather than a distributed Redis/BullMQ-style worker queue.

## Solution Assessment

Unclear as a direct implementation: Redis/BullMQ is useful prior art, but the best OpenClaw path needs maintainer direction on backend-neutral API shape, core versus plugin ownership, config surface, credentials, failure semantics, and upgrade behavior.
