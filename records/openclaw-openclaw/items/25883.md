## Summary

Keep open: current main and the latest release still lack the requested distributed job orchestration layer, shared worker claiming, dead-letter semantics, and horizontal worker coordination, so this is still a product/architecture decision rather than cleanup-close material.

## What This Changes

The issue proposes Redis/BullMQ-style horizontal scaling for background jobs, delayed work, scheduled tasks, retries, workers, and job-state observability.

## Best Possible Solution

Keep this open for maintainer architecture review and define a backend-neutral distributed scheduler/job ownership contract or plugin API before choosing Redis/BullMQ as the implementation detail.
