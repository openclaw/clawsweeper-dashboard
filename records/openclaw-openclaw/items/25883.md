## Summary

Keep open: current main and v2026.6.11 still lack the requested Redis/BullMQ-style distributed job orchestration, shared worker claiming, dead-letter semantics, and horizontal worker coordination, so this remains architecture/product work rather than cleanup-close material.

## What This Changes

The issue proposes adding a Redis/BullMQ-backed distributed job orchestration layer for background, delayed, scheduled, retryable, and observable work across horizontally scaled OpenClaw instances.

## Best Possible Solution

Keep this as the broad architecture tracker and design a backend-neutral scheduler/job ownership contract or plugin API before choosing Redis/BullMQ as an implementation detail.
