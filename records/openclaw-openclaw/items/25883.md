## Summary

Keep open: current main still has process-local command queues, Gateway-local cron execution, SQLite-backed task ledgers, and no distributed Redis/BullMQ-style worker queue or shared job-claiming contract, so the central horizontal-scaling request remains unresolved and needs architecture review.

## What This Changes

The issue requests a horizontal-scaling architecture with Redis/BullMQ-style job orchestration, workers, retries, delayed/cron jobs, dead-letter handling, and observability.

## Best Possible Solution

Define a backend-neutral distributed scheduler/job ownership contract or plugin API first, then coordinate the Redis/BullMQ prototype with the cron HA, external session storage, distributed runtime, and K8s worker-auth trackers.
