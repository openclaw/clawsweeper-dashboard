## Summary

Keep open: current main still has in-process command lanes, Gateway-local cron ownership, process-local cron locks, and SQLite-backed local task ledgers rather than the requested Redis/BullMQ-style distributed job orchestration layer. The ScalyClaw prototype is useful prior art, but this remains a maintainer architecture decision rather than a cleanup close.

## What This Changes

The issue proposes adding a Redis/BullMQ-style distributed job orchestration layer for scalable workers, delayed jobs, cron scheduling, retries, dead-letter handling, and queue observability.

## Best Possible Solution

Keep this open for maintainer architecture review and define a backend-neutral distributed scheduler/job ownership contract or plugin API before choosing Redis/BullMQ as the implementation detail.
