## Summary

Keep open: current main and v2026.6.11 still lack a Redis/BullMQ-style distributed job backend, shared worker claiming, dead-letter orchestration, and horizontal worker coordination; related issues cover narrower slices rather than replacing this broad architecture tracker.

## What This Changes

Request to add horizontal scaling through Redis/BullMQ-style distributed job orchestration for background, delayed, and scheduled work.

## Best Possible Solution

Keep this as the broad horizontal-scaling architecture tracker, preserve ScalyClaw as prior art, and have maintainers define a backend-neutral scheduler/job ownership contract or explicitly split the work into cron, session, runtime, federation, and plugin/API tracks.

- **Document External Orchestration:** Decide not to add a core backend for now and document safe external queue or scheduler patterns around OpenClaw deployments.

## Solution Assessment

No, not as a direct Redis/BullMQ core integration yet. The maintainable path is a maintainer-approved backend-neutral ownership/API boundary, with backend-specific implementations, migrations, docs, and proof added only after that decision.
