## Summary

Keep open: current main and v2026.6.11 still use process-local command lanes, Gateway-local cron execution, process-local cron/task runtime ownership, and local SQLite task ledgers rather than a Redis/BullMQ-style distributed job orchestration layer. The ScalyClaw prototype is useful prior art, but integration needs maintainer architecture direction before code.

## What This Changes

The issue proposes horizontal scaling through a Redis/BullMQ-backed job orchestration layer with separate workers, retries/backoff, delayed and scheduled jobs, dead-letter handling, and observability.

## Best Possible Solution

Define a maintainer-approved, backend-neutral distributed scheduler/job ownership contract or plugin API first, then decide whether ScalyClaw/BullMQ-style Redis orchestration belongs in core, a plugin, or external deployment docs.
