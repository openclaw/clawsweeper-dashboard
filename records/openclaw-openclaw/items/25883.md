## Label Justifications

- `P2`: The issue describes a meaningful production scaling and reliability feature gap, but it is broad architecture work rather than an urgent confirmed regression.
- `impact:message-loss`: The proposal targets background jobs, scheduled runs, and worker coordination failures that can delay, duplicate, or drop user-visible work under multi-instance deployments.
- `impact:session-state`: Horizontal worker coordination would affect which process owns in-flight agent work, cron sessions, task ledgers, and detached run state.

## Summary

Keep open: current main still lacks the requested Redis/BullMQ-style distributed job orchestration, shared worker claiming, dead-letter handling, and horizontal worker coordination. Existing cron, task, flow, and delivery queues improve local durability and recovery, but they remain Gateway/process-local or SQLite ledger surfaces rather than a distributed job backend.

## What This Changes

The issue proposes adding a Redis/BullMQ-style distributed job orchestration layer for background work, delayed jobs, scheduled jobs, retries, worker scaling, and queue observability.

## Best Possible Solution

Keep this as the broad horizontal-scaling architecture tracker, preserve the ScalyClaw prototype as prior art, and have maintainers first define a backend-neutral scheduler/job ownership contract or explicitly split the work into narrower cron, session, runtime, and plugin/API tracks.
