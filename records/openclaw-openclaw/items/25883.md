- `P2`: The issue describes a meaningful production scaling and reliability feature gap, but it is broad architecture work rather than an urgent confirmed regression.
- `impact:session-state`: Distributed worker coordination would affect ownership of in-flight agent work, cron sessions, task ledgers, and detached run state.

## Summary

Keep open: current main and v2026.6.11 still lack the requested Redis/BullMQ-style distributed job orchestration, shared worker claiming, dead-letter handling, and horizontally coordinated worker backend. The related open issues cover narrower cron HA, distributed runtime, and session-storage slices rather than replacing this broader architecture proposal.

## What This Changes

The issue proposes a Redis/BullMQ-style job orchestration layer with separate workers, retries, delayed and scheduled jobs, failure handling, and observability for horizontal scaling.

## Best Possible Solution

Keep this as the broad horizontal-scaling architecture tracker, preserve ScalyClaw as prior art, and have maintainers first choose a backend-neutral scheduler/job ownership seam or explicitly split the work into cron, session, runtime, and plugin/API tracks.
