## Summary

Keep open: current main and v2026.6.11 still use in-process queues, Gateway-local cron, process-local locks, and local SQLite task ledgers rather than Redis/BullMQ-style distributed job and worker coordination. The linked ScalyClaw prototype is useful prior art, but integration needs maintainer architecture direction.

## What This Changes

Request to add Redis/BullMQ-style distributed job orchestration with worker processes, retries/backoff, delayed and cron jobs, dead-letter handling, and observability for horizontally scaled OpenClaw deployments.

## Best Possible Solution

Define a maintainer-approved backend-neutral distributed scheduler/job ownership contract or plugin API first, then decide whether ScalyClaw/BullMQ-style Redis orchestration belongs in core, a plugin, or external deployment docs.
