## Summary

Keep open. Current main still lacks the requested Redis/BullMQ-style distributed job orchestration, shared worker claiming, distributed retry/dead-letter semantics, and horizontal worker coordination; related issues cover narrower cron, session, runtime, and worker-placement slices without replacing this broader architecture proposal.

## What This Changes

The issue proposes adding a Redis/BullMQ-backed distributed job orchestration layer with separate workers, retries/backoff, delayed and scheduled jobs, dead-letter handling, observability, and horizontal scaling support.

## Best Possible Solution

Keep this as the broad horizontal job-orchestration architecture tracker until maintainers decide whether to add a backend-neutral distributed scheduler/job seam, split the work into narrower canonical trackers, or document ScalyClaw-style Redis/BullMQ orchestration as an external/plugin pattern.

## Reproduction Assessment

Yes for source confirmation, not as a bug reproduction: current main uses in-process command lanes, Gateway-local cron execution, and SQLite-backed local ledgers, so the absence of a distributed Redis/BullMQ-style worker queue is directly visible in code and docs.

## Solution Assessment

Unclear as a direct implementation: Redis/BullMQ is useful prior art, but the best OpenClaw path needs maintainer direction on backend-neutral API shape, core versus plugin ownership, config surface, credentials, failure semantics, and upgrade behavior.
