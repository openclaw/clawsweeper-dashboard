## Summary

Keep open: current main and latest release still lack Redis/BullMQ-style distributed job orchestration, shared worker claiming, external queue backends, dead-letter semantics, or horizontal worker coordination; narrower open issues cover cron HA and session storage slices but do not replace this broader architecture proposal.

## What This Changes

The issue proposes a Redis/BullMQ-backed horizontal-scaling architecture with dedicated worker processes, distributed queues, delayed and scheduled jobs, retries, dead-letter handling, and queue observability.

## Best Possible Solution

Keep this as the broad horizontal-scaling architecture tracker, decide the core-vs-plugin/API boundary first, and coordinate narrower design slices with https://github.com/openclaw/openclaw/issues/13613 and https://github.com/openclaw/openclaw/issues/63492 while preserving ScalyClaw as prior art.

## Reproduction Assessment

Yes. Source inspection shows current main still uses process-local queues and Gateway-local cron execution without Redis/BullMQ, shared worker claiming, or distributed lease semantics; this is a feature-gap reproduction rather than a failing bug run.

## Solution Assessment

Unclear. A Redis/BullMQ prototype is useful prior art, but maintainers first need to choose the supported ownership boundary, failure semantics, config shape, and whether the permanent path is core, plugin API, or deployment guidance.
