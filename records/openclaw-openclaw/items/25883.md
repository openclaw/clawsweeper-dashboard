## Label Justifications

- `P2`: The issue is a normal-priority production scalability and reliability improvement with meaningful impact, but it is not an urgent regression or release-blocking first-run failure.
- `impact:session-state`: The requested horizontal worker coordination would affect how agent/task/session-adjacent state is owned across multiple Gateway processes.
- `impact:message-loss`: Uncoordinated distributed cron or job execution can duplicate, misroute, or suppress channel deliveries in multi-Gateway deployments.

## Summary

Keep open: current main still lacks the requested distributed Redis/BullMQ-style job orchestration and horizontal worker coordination; the remaining work is an architecture/product decision rather than a small core fix.

## What This Changes

Request a Redis/BullMQ-style distributed job orchestration layer with worker processes, retries/backoff, delayed and scheduled jobs, dead-letter handling, and observability for horizontal scaling.

## Best Possible Solution

Define a backend-neutral distributed scheduler/job ownership contract or plugin API before choosing Redis/BullMQ as an implementation; coordinate the cron HA, session storage, and distributed runtime trackers.

No, not as direct Redis/BullMQ core integration yet; the maintainable path is a maintainer-approved backend-neutral scheduler/job ownership contract with a clear core-or-plugin boundary.
