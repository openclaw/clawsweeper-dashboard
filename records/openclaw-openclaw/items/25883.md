## Summary

Keep open. Current main and v2026.6.11 still lack the requested Redis/BullMQ-style distributed job orchestration, shared worker claiming, dead-letter semantics, queue observability, and horizontal worker coordination; related open issues cover narrower cron, session-storage, runtime-split, claim/lease, and worker-placement slices rather than replacing this broader architecture tracker.

## What This Changes

The issue requests Redis/BullMQ-style horizontal scaling with distributed job queues, separate worker processes, retries/backoff, dead-letter handling, cron scheduling, and queue observability.

## Best Possible Solution

Keep this issue open as the broad horizontal job-orchestration architecture tracker until maintainers decide whether to add a backend-neutral distributed scheduler/job seam, split pieces into narrower cron/session/runtime trackers, or document the ScalyClaw-style Redis/BullMQ approach as an external/plugin pattern.

## Reproduction Assessment

Yes for source confirmation, not as a bug reproduction: current main uses in-process command lanes, Gateway-local cron execution, and local SQLite-backed ledgers rather than a distributed Redis/BullMQ-style worker queue.

## Solution Assessment

Unclear as a direct implementation: Redis/BullMQ is useful prior art, but the best OpenClaw path needs maintainer direction on backend-neutral API shape, core versus plugin ownership, config surface, credentials, failure semantics, and upgrade behavior.
