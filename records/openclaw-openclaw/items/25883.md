## Summary

Keep open: current main and v2026.6.11 still use in-process command lanes, Gateway-local cron execution, SQLite/local task ledgers, and no Redis/BullMQ-style distributed worker claiming, so the horizontal-scaling proposal remains a maintainer architecture decision.

## What This Changes

Request to add Redis/BullMQ-style distributed job orchestration, separate workers, retries/backoff, delayed and scheduled jobs, dead-letter semantics, and observability for horizontally scaled OpenClaw deployments.

## Best Possible Solution

Keep this open for maintainer architecture review and define a backend-neutral distributed scheduler/job ownership contract or plugin API before choosing Redis/BullMQ as an implementation detail.
