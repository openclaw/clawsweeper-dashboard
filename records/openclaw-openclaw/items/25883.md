## Summary

Keep open: current main still lacks Redis/BullMQ-style distributed job orchestration, shared worker claiming, dead-lettered job handling, and horizontal worker coordination. The ScalyClaw prototype is useful prior art, but this remains a broad architecture/product decision rather than cleanup-close material.

## What This Changes

The issue proposes adding a Redis/BullMQ-backed distributed job orchestration layer for background, delayed, scheduled, and retryable work across horizontally scaled OpenClaw instances.

## Best Possible Solution

Keep this open for maintainer architecture review and define a backend-neutral distributed scheduler/job ownership contract or plugin API before choosing Redis/BullMQ as the implementation detail.
