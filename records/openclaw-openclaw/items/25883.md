## Summary

Keep open: current main still lacks the requested Redis/BullMQ-style distributed job orchestration, shared worker claiming, and horizontal worker coordination, while the remaining decision is broad architecture rather than cleanup-close material.

## What This Changes

The issue proposes Redis/BullMQ-backed distributed job orchestration for background, delayed, scheduled, and long-running OpenClaw work.

## Best Possible Solution

Keep this open for maintainer architecture review and define a backend-neutral distributed scheduler/job ownership contract or plugin API before choosing Redis/BullMQ as an implementation detail.
