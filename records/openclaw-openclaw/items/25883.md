## Summary

Keep open. Current main has improved cron persistence into SQLite, but it still does not provide the requested Redis/BullMQ-style distributed job orchestration, shared worker claiming, distributed scheduler ownership, dead-letter queue, or horizontal worker coordination; the linked open issues cover narrower cron and session-storage slices rather than replacing this broader architecture discussion.

## What This Changes

Request to add a Redis/BullMQ-style distributed orchestration layer for background, delayed, scheduled, and horizontally scaled OpenClaw work.

## Best Possible Solution

Keep this as the broad horizontal-scaling architecture tracker, decide the core versus plugin/API boundary, coordinate the cron and session-storage slices with the narrower open issues, and preserve the ScalyClaw prototype as prior art.

## Reproduction Assessment

Yes for source-level confirmation: current docs and code show in-process queues, Gateway-local cron execution, and process-local active-job markers without a distributed worker-claiming backend. I did not run a live multi-host reproduction in this read-only review.

## Solution Assessment

Unclear as an implementation direction: Redis/BullMQ is useful prior art, but maintainers first need to choose the supported ownership boundary, failure semantics, and whether the permanent surface belongs in core or a plugin/API seam.
