## Summary

Keep open: current main and v2026.6.11 still use in-process command lanes, Gateway-local cron execution, process-local cron locks, and SQLite-backed task ledgers rather than the requested Redis/BullMQ-style distributed worker and job orchestration layer. The linked ScalyClaw prototype is useful prior art, but integration needs maintainer architecture direction.

## What This Changes

The issue proposes Redis/BullMQ-backed distributed job orchestration with separate workers, retries/backoff, dead-lettering, delayed and cron jobs, and observability for horizontal scaling.

## Best Possible Solution

Define a maintainer-approved backend-neutral distributed scheduler/job ownership contract or plugin API first, then decide whether ScalyClaw/BullMQ-style Redis orchestration belongs in core, a plugin, or external deployment docs.
