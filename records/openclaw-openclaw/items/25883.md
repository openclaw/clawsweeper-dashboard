## Summary

Keep open: current main still lacks the requested distributed job orchestration, horizontal worker coordination, shared claiming, and dead-letter semantics. The ScalyClaw Redis/BullMQ prototype is useful prior art, but integrating this into OpenClaw needs maintainer architecture and product review.

## What This Changes

Request to add a Redis/BullMQ-style distributed job orchestration layer with worker processes, retries/backoff, delayed and cron jobs, job state visibility, and horizontal scaling.

## Best Possible Solution

Make a maintainer architecture decision on the core/plugin/deployment boundary first, then design a backend-neutral scheduler/job contract with shared claiming, retries, dead-letter semantics, observability, config/docs, and security review.

## Reproduction Assessment

Yes at source level: current docs and code show in-process queues, Gateway-local cron execution, SQLite ledgers, and no distributed queue/backend configuration; no live multi-node repro was run in this read-only review.

## Solution Assessment

Unclear: Redis/BullMQ is plausible prior art, but maintainers still need to choose the permanent backend-neutral boundary, plugin/core ownership, config, migration, and security posture.
