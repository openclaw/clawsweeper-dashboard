## Summary

Keep open: current main and v2026.6.11 still use an in-process command queue, Gateway-local cron execution, process-local cron locks, and task ledgers rather than Redis/BullMQ-style distributed worker claiming, dead-letter handling, or horizontal job orchestration. The ScalyClaw prototype is useful prior art, while the related open issues cover narrower cron HA, runtime split, and external session-storage slices rather than replacing this broad architecture request.

## What This Changes

The issue proposes adding Redis/BullMQ-style distributed job orchestration for background, delayed, and cron-based OpenClaw work.

## Best Possible Solution

Keep this as the broad horizontal-scaling architecture tracker, preserve ScalyClaw as prior art, and have maintainers first define a backend-neutral scheduler/job ownership contract or explicitly split the work into cron, session, runtime, and plugin/API tracks.
