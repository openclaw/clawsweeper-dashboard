## Summary

Keep open: current main and v2026.6.11 still use in-process command lanes, Gateway-local cron execution, process-local cron locking, and SQLite-backed task ledgers rather than the requested Redis/BullMQ-style distributed job orchestration with shared worker claiming and dead-letter handling. The ScalyClaw prototype is useful prior art, while related open issues cover narrower cron, runtime, and session-storage slices rather than replacing this broad architecture tracker.

## What This Changes

The issue proposes horizontal scaling for OpenClaw through a Redis/BullMQ-backed job orchestration layer with separate workers, retries, dead-letter handling, cron/delayed jobs, and observability.

## Best Possible Solution

Keep this as the broad horizontal-scaling architecture tracker, preserve ScalyClaw as prior art, and have maintainers first define a backend-neutral scheduler/job ownership contract or explicitly split the work into cron, session, runtime, and plugin/API tracks.
