- `P2`: The proposal targets meaningful production scalability and reliability, but it is a broad feature/design item rather than an urgent confirmed regression.
- `impact:session-state`: The requested distributed ownership layer would prevent local task, run, and worker state from drifting across horizontally scaled instances.

- `maturity:stable`: The issue affects Gateway runtime architecture, and the scorecard currently marks gateway-runtime as M4 Stable with quality 81 and completeness 89.

## Summary

Keep open: current main and v2026.6.11 still use in-process queues, Gateway-local cron execution, process-local cron locks, and local SQLite-backed task state rather than the proposed Redis/BullMQ-style distributed job orchestration. The ScalyClaw prototype is useful prior art, but adopting any part of it needs maintainer architecture direction first.

## What This Changes

Proposal to add Redis/BullMQ-backed horizontal scaling for background jobs, delayed/cron work, worker processes, retries/backoff, dead-letter handling, and queue observability.

## Best Possible Solution

Define a maintainer-approved backend-neutral distributed scheduler/job ownership contract or plugin API first, then decide whether ScalyClaw/BullMQ-style Redis orchestration belongs in core, a plugin, or external deployment docs.
