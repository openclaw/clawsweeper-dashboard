## Summary

Keep open: current main still has process-local command lanes, Gateway-local cron execution, process-local active-job ownership, and no Redis/BullMQ-style distributed worker or job-claiming contract, so the remaining work is a maintainer architecture decision.

## What This Changes

The issue proposes adding a Redis/BullMQ-backed horizontal scaling layer for background jobs, delayed jobs, cron scheduling, worker processes, retries, dead-letter handling, and queue observability.

## Best Possible Solution

Keep this open as the broad horizontal-scaling architecture tracker, define a backend-neutral distributed scheduler/job ownership contract or plugin API, and use ScalyClaw as prior art while coordinating the narrower cron, session-storage, and distributed-runtime issues.
