## Summary

Keep open: current main and the latest release still use in-process queues, Gateway-local cron execution, process-local cron/task ownership, and SQLite-backed ledgers rather than Redis/BullMQ-style distributed job orchestration. The ScalyClaw prototype is useful prior art, but this needs maintainer architecture direction before any code work.

## What This Changes

The issue proposes a Redis/BullMQ-style distributed job orchestration layer for background work, delayed jobs, cron, retries, dead-letter handling, worker scaling, and observability.

## Best Possible Solution

Define a maintainer-approved backend-neutral distributed scheduler/job ownership contract or plugin API first, then decide whether ScalyClaw/BullMQ-style Redis orchestration belongs in core, a plugin, or external deployment docs.
