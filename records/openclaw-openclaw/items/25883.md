## Summary

Keep open: current main still has process-local command queues, Gateway-local cron execution, process-local cron locks, and task/flow ledgers rather than the requested Redis/BullMQ-style distributed job orchestration layer, so this remains a maintainer architecture decision.

## What This Changes

The issue proposes a Redis/BullMQ-style distributed job orchestration layer for horizontal scaling, including workers, retries, delayed and scheduled jobs, dead-letter handling, and observability.

## Best Possible Solution

Keep this open for maintainer architecture review and define a backend-neutral distributed scheduler/job ownership contract or plugin API before choosing Redis/BullMQ as the implementation detail.
