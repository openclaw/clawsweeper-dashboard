## Summary

Keep open. Current main and the latest release still do not provide the requested Redis/BullMQ-style distributed job orchestration, shared worker claiming, dead-letter queue, or horizontal worker coordination; related open issues cover narrower cron, session-storage, runtime-split, and worker-placement slices without replacing this broad architecture proposal.

## What This Changes

Request to add a Redis/BullMQ-style distributed job orchestration layer for background, delayed, and scheduled work so OpenClaw can coordinate horizontally scaled workers.

## Best Possible Solution

Keep this as the broad architecture tracker until maintainers choose a backend-neutral scheduler/job seam, split the work into narrower canonical trackers, or document the ScalyClaw-style approach as an external/plugin deployment pattern.

## Reproduction Assessment

Yes for source confirmation, not as a bug reproduction: current main visibly uses in-process command lanes, Gateway-owned cron execution, and local SQLite-backed ledgers rather than a distributed Redis/BullMQ-style worker queue.

## Solution Assessment

Unclear as a direct Redis/BullMQ implementation: the best OpenClaw path needs maintainer direction on backend-neutral API shape, core versus plugin ownership, config surface, credentials, failure semantics, and upgrade behavior.
