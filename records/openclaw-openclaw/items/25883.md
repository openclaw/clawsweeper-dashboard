## Summary

Keep open. Current main and v2026.6.11 still lack the requested Redis/BullMQ-style distributed job orchestration layer, shared worker claiming, dead-letter semantics, and horizontal worker coordination; this remains a broad architecture/product decision rather than cleanup-close material.

## What This Changes

The issue proposes adding a Redis/BullMQ-style distributed job orchestration layer with worker processes, retries, delayed/cron jobs, dead-letter handling, and observability for horizontally scaled OpenClaw deployments.

## Best Possible Solution

Keep this as the broad horizontal-scaling architecture tracker while maintainers decide whether to add a backend-neutral distributed scheduler/job API, split narrower slices to cron/session/runtime trackers, or document external orchestration as a deployment pattern.

## Reproduction Assessment

Yes, as source-level confirmation of a missing feature rather than a bug reproduction: current main still has process-local queues/cron ownership and no Redis/BullMQ-style distributed job backend. I did not run a live high-load or multi-host reproduction in this read-only review.

## Solution Assessment

Unclear as an implementation: the Redis/BullMQ prototype is useful prior art, but maintainers need to choose the backend boundary, failure semantics, and core-versus-plugin/API ownership before code work.
