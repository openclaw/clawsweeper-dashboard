## Label Justifications

- `P2`: This is a normal-priority architecture improvement for HA and horizontally scaled deployments, not a current release-blocking regression in single-gateway use.
- `impact:session-state`: The requested distributed orchestration would determine which gateway or worker owns stateful jobs and session-affecting work across multiple processes.
- `impact:message-loss`: The issue explicitly targets duplicate or missed background deliveries when multiple gateways or workers process the same work without coordination.

## Summary

Keep open. Current main still uses local in-process command lanes, Gateway-owned cron scheduling, local cron locks, and SQLite task ledgers; it does not implement the requested Redis/BullMQ-style distributed orchestration, shared worker claiming, dead-letter handling, or horizontal worker coordination, and the related open issues only cover narrower slices of the broader architecture.

## What This Changes

Request to add a distributed job orchestration layer for OpenClaw so multiple gateways or workers can coordinate jobs across a shared backend such as Redis/BullMQ.

## Best Possible Solution

Keep #25883 as the broad architecture tracker until maintainers choose a backend-neutral scheduler/job seam, split it into narrower canonical cron/session/runtime items, or document an external/plugin pattern such as ScalyClaw-style distributed orchestration.

## Reproduction Assessment

Yes for source confirmation, not for a bug reproduction: current main exposes process-local command lanes, Gateway-owned cron execution, and SQLite task ledgers instead of distributed queueing or shared worker claims.

## Solution Assessment

Unclear. Redis/BullMQ may be useful prior art, but the best OpenClaw fix needs maintainer direction on backend-neutral APIs, core/plugin ownership, config and secret handling, lease semantics, and upgrade behavior.
