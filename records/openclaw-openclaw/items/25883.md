## Summary

Keep open. Current main has improved local cron/task durability, including SQLite-backed cron and task ledgers, but it still does not provide the requested Redis/BullMQ-style distributed queue, shared worker claiming, dead-letter handling, or horizontally coordinated job orchestration.

## What This Changes

The issue proposes a Redis/BullMQ-style distributed job orchestration layer with independent workers, retries/backoff, delayed and scheduled jobs, dead-letter handling, and queue observability for horizontally scaled OpenClaw deployments.

## Best Possible Solution

Keep this as maintainer architecture input, decide whether OpenClaw should expose a generic distributed scheduler/job backend seam or document Redis/BullMQ-style orchestration as external/plugin guidance, then split any accepted direction into narrow cron, task-ledger, worker-claiming, retry/dead-letter, config, and observability work.

## Reproduction Assessment

Yes, source inspection gives a high-confidence path: current main uses in-process command lanes, Gateway-local cron ownership, and SQLite task/cron ledgers rather than a distributed queue/worker backend. I did not run a load or multi-instance deployment repro, so this is source-reproducible rather than fully reproduced.

## Solution Assessment

Unclear as a concrete implementation. The ScalyClaw Redis/BullMQ prototype is useful prior art, but the best OpenClaw solution needs maintainer architecture choice about core seams, plugin ownership, config surface, upgrade behavior, and operations/security tradeoffs.
