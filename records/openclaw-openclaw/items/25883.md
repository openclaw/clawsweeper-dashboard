## Summary

Keep open: current main and the latest release still do not provide Redis/BullMQ-style distributed job orchestration, shared worker claiming, or horizontal worker coordination. Existing SQLite-backed cron/task state and task visibility are useful progress, but they remain Gateway/process-owned and do not settle the product architecture.

## What This Changes

The issue proposes Redis/BullMQ-style distributed job orchestration with separate workers, retries/backoff, dead-letter handling, cron support, and queue observability for horizontal scaling.

## Best Possible Solution

Keep this open for architecture review, define a backend-neutral job/scheduler ownership contract or plugin API first, and coordinate the cron HA, distributed runtime, and external session storage slices before selecting Redis/BullMQ as an implementation detail.
