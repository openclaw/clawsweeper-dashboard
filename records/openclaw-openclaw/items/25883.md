## Summary

Keep open: current main still has local SQLite persistence and durable delivery/task ledgers, but it does not provide the requested Redis/BullMQ-style distributed job orchestration, shared worker claiming, dead-letter backend, or horizontally scaled worker coordination.

## What This Changes

Request to add a Redis/BullMQ-style distributed job orchestration layer for background, delayed, scheduled, and long-running work across horizontally scaled OpenClaw instances.

## Best Possible Solution

Define a backend-neutral distributed scheduler/job ownership contract or plugin API first, then evaluate Redis/BullMQ as one implementation and coordinate the cron HA, external session storage, distributed runtime, and worker-auth trackers.
