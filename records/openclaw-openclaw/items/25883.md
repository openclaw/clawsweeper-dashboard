## What This Changes

The issue proposes adding a Redis/BullMQ-style distributed job orchestration layer for scalable background jobs, delayed work, cron tasks, workers, retries, dead-letter handling, and observability.

## Best Possible Solution

Keep this as the broad architecture tracker and design a backend-neutral scheduler/job ownership contract or plugin API before choosing Redis/BullMQ as an implementation detail.
