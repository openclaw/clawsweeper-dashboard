## Summary

Keep open: current main and v2026.6.11 still lack the requested Redis/BullMQ-style distributed job orchestration, shared worker claiming, dead-letter semantics, and horizontal worker coordination. The ScalyClaw prototype is useful prior art, but the right OpenClaw boundary needs maintainer architecture direction rather than cleanup closure.

## What This Changes

The issue proposes adding a Redis/BullMQ-style distributed job orchestration layer with separate workers for background, delayed, and scheduled work plus retries, failure handling, and observability for horizontal scaling.

## Best Possible Solution

Keep this open as the broad architecture tracker, define a backend-neutral scheduler/job ownership contract or plugin API before choosing Redis/BullMQ, and coordinate the cron HA, session storage, and distributed-runtime slices while preserving ScalyClaw as prior art.
