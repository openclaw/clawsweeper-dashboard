## Summary

Keep open. Current main still lacks the requested Redis/BullMQ-style distributed job orchestration, shared worker claiming, dead-letter handling, queue observability, and horizontal worker coordination; the open related items cover narrower cron, session-storage, distributed-runtime, and subagent-placement slices without superseding this broader architecture proposal.

## What This Changes

The issue requests a Redis/BullMQ-style distributed job orchestration layer so OpenClaw can coordinate background, delayed, scheduled, and long-running work across horizontally scaled deployments.

## Best Possible Solution

Keep this issue open as the broad horizontal job-orchestration architecture tracker until maintainers decide whether OpenClaw should add a backend-neutral distributed scheduler/job seam, split pieces into narrower cron/session/runtime trackers, or document the ScalyClaw-style Redis/BullMQ approach as an external/plugin pattern.

## Reproduction Assessment

Yes for source confirmation, not as a bug reproduction: current main uses in-process command lanes, Gateway-local cron execution, and SQLite-backed local ledgers, so the absence of a distributed Redis/BullMQ-style worker queue is directly visible in code and docs.

## Solution Assessment

Unclear as a direct implementation: Redis/BullMQ is useful prior art, but the best OpenClaw path needs maintainer direction on backend-neutral API shape, core versus plugin ownership, config surface, credentials, failure semantics, and upgrade behavior.
