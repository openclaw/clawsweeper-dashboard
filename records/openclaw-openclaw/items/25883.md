## Summary

Keep open: current main still has process-local command lanes, Gateway-owned cron execution, process-local cron duplicate guards, and SQLite task ledgers rather than the requested Redis/BullMQ-style distributed job orchestration layer. The ScalyClaw prototype is useful prior art, but this remains a maintainer architecture/product decision rather than a cleanup-close candidate.

## What This Changes

The issue proposes a Redis/BullMQ-backed distributed job orchestration layer with separate workers, retries/backoff, delayed and scheduled jobs, dead-letter handling, and queue observability for horizontal scaling.

## Best Possible Solution

Keep this open for maintainer architecture review and define a backend-neutral distributed scheduler/job ownership contract or plugin API before choosing Redis/BullMQ as an implementation detail.
