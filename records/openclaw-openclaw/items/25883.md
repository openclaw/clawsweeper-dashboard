- `P2`: The proposal targets meaningful production scalability and reliability, but it is a broad architecture feature rather than an urgent confirmed regression.
- `impact:session-state`: The reported multi-instance scaling gap can leave session, task, and worker ownership local to one Gateway instead of shared across workers.

## Summary

Keep open: current main still uses process-local command lanes, Gateway-local cron execution, process-local active-job ownership, and SQLite task ledgers rather than a distributed Redis/BullMQ-style worker and job-claiming layer.

## What This Changes

The issue requests a Redis/BullMQ-style horizontal-scaling architecture for background jobs, delayed work, cron scheduling, worker coordination, retries, dead-letter handling, and job observability.

## Best Possible Solution

Keep this open as the broad horizontal-scaling architecture tracker, define a backend-neutral scheduler/job ownership contract or plugin API, and use ScalyClaw as prior art while coordinating narrower cron, session-storage, and distributed-runtime issues.
