## Summary

Keep open: current main still has process-local command lanes, Gateway-local cron execution, process-local cron locks, and local task ledgers, so the requested distributed Redis/BullMQ-style job orchestration remains unresolved architecture work.

## What This Changes

The issue proposes a Redis/BullMQ-backed distributed job orchestration layer with worker processes, retries/backoff, delayed and cron jobs, and queue observability for horizontal scaling.

## Best Possible Solution

Keep this as the broad architecture tracker and design a backend-neutral scheduler/job ownership contract or plugin API before choosing Redis/BullMQ as an implementation detail, using ScalyClaw as prior art.
