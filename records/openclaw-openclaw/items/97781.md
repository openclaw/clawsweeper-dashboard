## Summary

Keep this PR open, but it is not merge-ready because the bounded read is applied to the manual SSO helper while the live Microsoft Teams sign-in invoke route still delegates to the SDK token handlers without OpenClaw-owned response-size proof.

## What This Changes

The PR adds a 16 MiB bounded successful-response read to `extensions/msteams/src/sso.ts` and adds loopback tests for oversized and normal SSO token responses.

## Best Possible Solution

Retarget the response-size guard and loopback proof to the production SDK-backed `signin.token-exchange` and `signin.verify-state` path, or document source-backed dependency proof that the SDK already enforces an equivalent cap.
