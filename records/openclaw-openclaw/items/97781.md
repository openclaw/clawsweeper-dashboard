## Summary

Keep open: the branch adds a bounded read and loopback proof around the `sso.ts` helper, but current production Microsoft Teams SSO invokes in `monitor.ts` still delegate to the Teams SDK `onTokenExchange` / `onVerifyState` path, so the central OOM guard is not on the live route.

## What This Changes

The PR bounds Microsoft Teams SSO User Token service success JSON reads in `extensions/msteams/src/sso.ts` and adds loopback tests in `extensions/msteams/src/sso.test.ts`.

## Best Possible Solution

Put the 16 MiB bounded read on the monitor-registered production SSO route or its SDK HTTP client adapter, then prove that route with loopback oversized and normal token-exchange coverage while preserving SDK sign-in event persistence.
