## Summary

This remains a useful, narrowly scoped bug fix: current `main` still expands a `~`-prefixed wrapper only through `process.env.HOME`, so a blank value produces an invalid relative path. The patch instead reuses the iMessage path resolver’s OS-home fallback, preserves the existing parser and error handling, and includes focused plus real Windows-path evidence; no actionable patch defect was found.

## What This Changes

The PR extracts iMessage SSH-wrapper remote-host detection into a helper and expands `~` through the existing iMessage user-path resolver when `HOME` is blank.

## Best Possible Solution

Land the focused helper extraction after the normal required checks complete, retaining `expandIMessageUserPath` as the single iMessage `~` expansion rule for both CLI execution and wrapper inspection.
