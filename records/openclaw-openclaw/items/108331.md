## Summary

Keep this issue open: the production evidence describes a severe dead-session and silent-message-loss failure, while current main contains newer stale-run reclamation and terminal-session recovery logic that may address part of it but has not been shown to cover this Feishu/provider-timeout path. citeturn8search6turn12view0

## What This Changes

Recover sessions after provider timeouts or 503 failures so later same-key messages are processed instead of silently disappearing.

## Best Possible Solution

Make reply admission atomically reclaim a timed-out or orphaned run, preserve the canonical transcript, requeue the accepted message, and surface an in-product interruption notice with a visible Start fresh or Fix action when automatic recovery cannot safely continue.
