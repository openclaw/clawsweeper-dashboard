## Summary

Keep open: current main and v2026.6.11 still hardcode the reply-producing reset prompt, and strict config schemas do not expose the requested global or per-agent reset prompt override. This remains a real feature/config request, but the public reset-start config contract needs maintainer direction before implementation.

## What This Changes

The issue requests a global and per-agent `session.resetPrompt` config key to override the startup prompt injected after `/new` or `/reset`.

## Best Possible Solution

Define one maintainer-approved reset-start policy that covers prompt customization, bootstrap/current-time safeguards, acknowledgement-only reset behavior, schema/help/docs, and focused tests before adding a new config key.
