## Summary

Keep open: current main and v2026.6.11 still have hardcoded reset/startup prompt behavior and no accepted global or per-agent `resetPrompt` config surface, so this remains a product/config contract decision rather than cleanup-closeable work.

## What This Changes

Add a global and per-agent `session.resetPrompt` config key to override the startup prompt used after `/new` or `/reset`, falling back to current behavior when unset.

## Best Possible Solution

Define one maintainer-approved reset-start policy that covers prompt customization, startup-turn behavior, current-time/bootstrap safeguards, and related greeting/model knobs before adding schema, docs, and tests.
