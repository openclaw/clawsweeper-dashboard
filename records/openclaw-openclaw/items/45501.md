## Summary

Keep open: current main and v2026.6.11 still hardcode the bare reset startup prompt and do not accept the requested global or per-agent prompt override. The request is real and source-reproducible, but it needs maintainer product direction because it adds a public session/config contract that overlaps reset greeting, bootstrap, and startup-context behavior.

## What This Changes

The issue requests a configurable global and per-agent `session.resetPrompt` that replaces the hardcoded startup message injected after bare `/new` or `/reset` while preserving the current default when unset.

## Best Possible Solution

Define one maintainer-approved reset-start policy that covers prompt text customization, bootstrap/current-time safeguards, acknowledgement-only reset behavior, and related greeting/model knobs before adding schema, docs, and tests.
