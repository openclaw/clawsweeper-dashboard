## Summary

Keep this issue open. The reported loss of a live conversation after an idle timeout is a serious session-state symptom, but the supplied `sessions.resolve: No session found: current` line does not yet establish whether the persisted session was deleted or a client resolution target failed. A prior gateway lifecycle fix addressed timeout runs stuck in `running`, but the report names version 2026.6.8, so it does not prove that earlier fix covers this newer observation.

## What This Changes

The issue requests that LLM idle-timeout cleanup preserve the active conversation and its session mapping so a user can retry without losing context.

## System Context

Webchat sends a turn into the embedded agent runner, whose idle watchdog can abort a model stream and hand terminal state to gateway session lifecycle handling. That lifecycle updates persisted session metadata and the next webchat request resolves the session before loading its transcript and context.

## Architecture Diagram

flowchart LR

  B --> C[LLM idle watchdog]
  C --> D[Abort and settle handling]
  D --> E[Gateway session lifecycle]
  E --> F[Persisted session and transcript]
  F --> G[Next webchat turn]
  G --> H[Session resolution and context load]

## Best Possible Solution

Add a focused regression that drives two idle-timeout attempts through webchat, then verifies the stored session row, transcript, current-session mapping, and a successful retry; repair only the lifecycle or resolution owner that fails that check.
