## Summary

Keep open: current `main` and the latest release still show env-backed SecretRefs as generic read-only empty fields, and the remaining Control UI/config UX needs an explicit product/security decision about safe source metadata disclosure.

## What This Changes

The issue requests first-class `.env` / environment-backed SecretRef UX in CLI and Control UI, including source badges, masked state, env-reference preservation, and migration guidance.

## Best Possible Solution

Add a maintainer-approved source-aware SecretInput renderer and metadata flow that keeps values masked, shows safe source/resolution state, preserves env references, and aligns with existing SecretRef CLI/docs/tests.
