## Summary

Keep open: current main has a strong SecretRef runtime, shorthand, redaction, and write-path foundation, but the requested source-aware Control UI/config UX is still missing and needs a product/security decision before implementation.

## What This Changes

The issue requests first-class env-backed secret UX in CLI/config views, especially masked source-aware Control UI fields for config/env/unset secrets instead of blank-looking inputs.

## Best Possible Solution

Add a maintainer-approved source-aware SecretInput renderer and metadata flow on top of existing SecretRef contracts, with masked display, safe source labels, optional env identity, resolved/unresolved state, config/env/unset editing, and aligned docs/tests.
