## Summary

Keep open: current main and v2026.6.11 still show env-backed SecretRefs as generic read-only structured values, while the remaining first-class UX work needs product/security decisions before implementation.

## What This Changes

Request first-class CLI and Control UI UX for env-backed secrets so SecretRefs show safe source and resolution state instead of blank-looking redacted fields.

## Best Possible Solution

Add a source-aware SecretInput renderer and metadata contract over the existing SecretRef flow: masked display, safe source labels, approved env identity disclosure, resolved/unresolved state, config/env/unset editing, and aligned docs/tests.
