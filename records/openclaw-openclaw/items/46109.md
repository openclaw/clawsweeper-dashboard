## Summary

Keep open: current main and the latest release still render env-backed SecretRefs as generic read-only placeholders, while related SecretRef hardening fixed round-trip safety rather than the requested source-aware config/env/unset UX.

## What This Changes

The issue requests first-class env-backed secret UX in CLI and Control UI, including masked source-aware display, config/env/unset editing, and migration guidance.

## Best Possible Solution

Add a maintainer-approved source-aware SecretInput UI and metadata flow that displays masked source labels and resolved state without leaking sensitive details, plus matching CLI/docs/tests on the existing SecretRef contracts.

## Reproduction Assessment

Yes. Source inspection and the existing browser test show an env SecretRef such as `channels.discord.token` renders as a read-only empty input with a generic structured placeholder rather than a source-aware env-backed field.

## Solution Assessment

Unclear. A source-aware SecretInput renderer is the likely right layer, but maintainers need to decide the safe disclosure and editing semantics before implementation.
