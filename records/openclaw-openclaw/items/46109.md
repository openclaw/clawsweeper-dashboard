## Summary

Keep open: current main and the latest release still render env-backed SecretRefs as generic read-only empty config fields, so the central Control UI/source-aware secret UX is not implemented and needs maintainer security/product direction.

## What This Changes

The issue requests first-class env-backed secret UX in CLI and Control UI, including masked source metadata, env reference preservation, and safer migration guidance.

## Best Possible Solution

Add a maintainer-approved source-aware SecretInput renderer and metadata flow on top of existing SecretRef contracts, with masked display, safe source labels, resolved/unresolved state, explicit config/env/unset editing, and aligned docs/tests.
