## Summary

Keep open: current main and the latest release have strong SecretRef runtime, redaction, write-preflight, CLI, and docs foundations, but the requested source-aware Control UI/config UX still renders env-backed SecretRefs as generic read-only empty inputs and needs a maintainer security/product decision on safe metadata disclosure.

## What This Changes

Request source-aware `.env`/SecretRef configuration UX so env-backed secrets show masked source and resolution state instead of blank-looking fields.

## Best Possible Solution

Add a maintainer-approved SecretInput metadata/rendering contract with masked values, safe source labels, resolved/unresolved state, explicit config/env/unset editing, and aligned docs/tests on the existing SecretRef registry and config RPCs.

Kind: security_boundary

Question: What SecretRef source metadata may Control UI safely show for env-backed secrets: source category only, env variable name, provider alias, and/or resolved status?

Rationale: The implementation is straightforward only after maintainers decide which secret-source details are safe to disclose and edit in a browser UI.

Likely owner: steipete

Owner reason: Recent current-main Control UI/config history and issue timeline mentions make this the best available routing candidate for the product/security boundary decision.

Owner confidence: medium

Options:

- **Conservative source-aware UI (recommended):** Show masked values with source category and resolved/unresolved state, but hide exact env variable names unless the user explicitly reveals or edits that field.
- **Full env identity display:** Show exact env variable names and provider aliases by default, improving clarity but exposing more operator topology in Control UI.
- **Defer source metadata:** Keep the read-only generic SecretRef behavior until a broader secrets UX/security model is designed.

Yes. Current source and the existing browser test show an env SecretRef renders as a read-only empty input with a generic Structured value placeholder rather than a source-aware env-backed control.

## Solution Assessment

Unclear until maintainers set the disclosure boundary. The likely implementation layer is a source-aware SecretInput renderer plus metadata flow, not a new config format.
