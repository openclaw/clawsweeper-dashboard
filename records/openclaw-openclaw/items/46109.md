## Summary

Keep open: current main still renders structured env SecretRefs as generic read-only placeholders rather than source-aware env/config/unset controls, and the remaining work needs a maintainer security/product decision before implementation.

## What This Changes

Request first-class `.env` and environment-backed SecretRef UX in the CLI and Control UI, including masked source-aware display, env reference preservation, and migration guidance away from plaintext secrets.

## Best Possible Solution

Add a maintainer-approved source-aware SecretInput renderer and metadata flow that shows masked source labels and safe resolution state, preserves env references, supports explicit config/env/unset editing, and aligns docs/tests with the existing SecretRef contracts.
