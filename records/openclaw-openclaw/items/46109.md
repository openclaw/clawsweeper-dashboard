## Summary

Keep open: current main and the latest release still render env-backed SecretRefs as empty, read-only generic structured placeholders, so the requested source-aware Control UI/config UX remains missing and needs maintainer product/security direction.

## What This Changes

The issue requests first-class environment-backed secret configuration UX in the CLI and Control UI, including source-aware secret display, env-reference preservation, and migration guidance.

## Best Possible Solution

Add a maintainer-approved source-aware SecretInput renderer and metadata flow that keeps values masked, shows safe source/resolution status, supports explicit config/env/unset editing, and stays aligned with SecretRef registry, redaction, docs, and tests.
