## What This Changes

The branch moves startup catch-up deferral markers from a process-local cron service Set into persisted CronJobState, updates maintenance/timer cleanup, and adds restart-survival regression coverage.

## Best Possible Solution

Land the durable CronJobState marker approach after required CI, keeping stale-future repair active for unrelated jobs and clearing the marker on execution, disabled jobs, or invalid deferred slots.

Yes, at source level: current main can persist a staggered overflow nextRunAtMs while the protection marker exists only in a fresh process-local Set. The PR adds an integration-style restart test that uses one SQLite store and two fresh CronServiceState instances to cover that path.

## Solution Assessment
