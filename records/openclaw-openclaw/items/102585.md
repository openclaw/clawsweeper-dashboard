## Summary

This PR addresses a real cost and scheduling concern, but it is not ready to merge as a bug-only repair: it introduces a new public heartbeat setting and changes the default behavior of existing installations to suppress scheduled turns after 48 hours. The open activity-timeout design discussion at https://github.com/openclaw/openclaw/issues/14051 already owns the policy choices around activity definition, setting shape, and defaults. Likely related people: steipete is the most likely product-decision contact from the review request, with low-confidence routing evidence.

## What This Changes

The branch adds `heartbeat.maxIdleMinutes`, defaulting to 48 hours, and skips scheduled heartbeat runs for sessions whose recorded interaction timestamp is older than that threshold unless pending work is present.

## System Context

The heartbeat runner periodically prepares an agent session, checks for commitments and queued events, then starts a model turn that can generate outbound delivery. This PR inserts a session-activity decision between preflight and the normal heartbeat execution path.

## Best Possible Solution

Resolve the canonical heartbeat activity policy first, then land one agreed contract—preferably an explicitly scoped safety behavior or a documented, tested configuration design—rather than adding a competing default-on timeout here.
