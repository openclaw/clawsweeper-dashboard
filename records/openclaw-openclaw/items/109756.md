## Label Justifications

- `P1`: A deterministic daily-boundary sequence can disconnect an agent's visible greeting from the user's immediate reply, breaking a real conversation workflow.
- `impact:session-state`: The issue concerns a session ID rollover that splits causally connected messages across old and new transcripts.

## Summary

Keep this issue open: current main still forces heartbeat system events to reuse an existing daily-stale session, while the next user message evaluates freshness and can roll to a disconnected transcript. The related proactive-reset PR is unmerged, conflicted, broader than this report, and does not yet prove the exact greeting-then-reply invariant.

## What This Changes

Ensure a visible main-session heartbeat after the daily boundary and the user's reply remain in the same newly rolled session.

## Best Possible Solution

Define one canonical daily rollover before any post-boundary main-session conversation is generated, preferably by adapting the scheduled-reset path with active-run and provider-owned-session protections, then prove that a visible heartbeat and immediate reply share one new session without regressing idle, cron, exec, or context-preservation behavior.
