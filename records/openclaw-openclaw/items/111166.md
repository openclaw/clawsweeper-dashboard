## Summary

The patch improves the ordinary timeout path, but it does not provide the stated bound on footer rendering: Node keeps `spawnSync()` blocked until the child has actually exited after the timeout signal. Keep this PR open for a fix that removes the synchronous probe from the render-critical path or narrows the claim and proves the intended failure mode.

## What This Changes

The PR adds a 2-second `timeout` and `SIGKILL` to the synchronous `git symbolic-ref` branch probe used by agent-session footer rendering.

## Best Possible Solution

Move branch discovery off the synchronous footer-render path and serve the footer from a cached last-known branch or no-branch value while an asynchronously bounded refresh runs; add focused proof for the timeout and fallback behavior.

## Reproduction Assessment

Yes, from source and the Node contract: a child that remains alive after the timeout signal leaves `spawnSync()` blocked because it returns only after child exit. A real stalled-child fixture or controlled executable is still needed to demonstrate the footer result end-to-end.

## Solution Assessment

No. Adding a timeout signal is useful mitigation for a normally killable direct `git` process, but it is not the best fix for the reported render-path freeze because the API remains synchronous and has no guaranteed return deadline.
