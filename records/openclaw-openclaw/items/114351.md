## Summary

Keep this PR open for maintainer review. It fixes a current Control UI dispatch gap by applying the established outbound-hook policy before WebChat delivery and transcript capture; the patch and supplied real-system proof are strong, but this deliberately changes how installed plugins can rewrite or suppress persisted Control UI replies.

## What This Changes

The branch routes Control UI chat replies through a projected auto-reply dispatcher so `reply_payload_sending` and media-aware `message_sending` hooks run before WebChat output and chat-history capture.

## System Context

A Control UI `chat.send` request runs an agent through the Gateway, which dispatches assistant replies and captures them for WebChat and transcript history. Outbound plugin hooks sit immediately before delivery, where they can rewrite or cancel a reply before those visible and durable side effects occur.

## Best Possible Solution

Keep outbound-hook composition owned by the shared auto-reply dispatcher, with Gateway capture and transcript projection occurring only after a reply survives the composed hook chain.
