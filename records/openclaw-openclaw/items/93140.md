## Summary

Keep open: current `main` still has a concrete sandbox bind-mount regression in `apply_patch`. The bridge recognizes configured writable binds, and sandboxed `write`/`edit` use it directly, but `apply_patch` resolves through that bridge and then re-applies a narrower workspace-root check to the host path. Likely related people: `steipete` (high confidence) and `vincentkoc` (medium confidence). ([github.com](https://github.com/openclaw/openclaw/blob/main/src/agents/apply-patch.ts))

## What This Changes

The issue requests that file tools consistently support explicitly authorized sandbox bind mounts and clarifies that `apply_patch` alone rejects those paths despite `write` and `edit` succeeding.

## Best Possible Solution

Make sandboxed `apply_patch` honor the bridge’s mount-aware authorization for explicitly configured writable binds, retain the existing host-mode workspace guard, and add regression coverage for writable bind mounts, readonly binds, and path-alias escape attempts.

Options:

- **Design a separate opt-in policy:** Add a clearly scoped setting only if maintainers decide configured Docker binds must not themselves establish apply-patch authority.
