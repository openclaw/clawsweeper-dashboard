## Summary

The timeout is a plausible, narrowly owned fix with focused regression coverage, but this external PR still needs real handler-level behavior proof before merge; the supplied evidence only exercises mocked Baileys and media-store boundaries and does not show that a timed-out media message releases WhatsApp inbound processing for subsequent messages.

## What This Changes

The PR wraps WhatsApp inbound media streams in a fixed 30-second per-chunk idle timeout, closes the iterator on timeout, and adds focused regression tests.

## Best Possible Solution

Keep the timeout at the WhatsApp-owned download boundary, but require redacted handler-level proof with the pinned Baileys runtime showing a stall times out, cleanup settles without an unhandled rejection, a following message is dispatched, and slow-progress media remains successful.
