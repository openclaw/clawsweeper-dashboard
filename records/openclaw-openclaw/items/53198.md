## Summary

Keep open: current main and the latest release still do not implement the documented Discord elevated allowFrom fallback, and the linked open fix path is a conflicting fork PR that needs maintainer/security review rather than another cleanup close.

## What This Changes

The issue reports that Discord elevated authorization should fall back from `tools.elevated.allowFrom.discord` to `channels.discord.allowFrom`, and that `sandbox explain` should report that path consistently.

## Best Possible Solution

Keep this issue open until maintainers land a narrow fix that shares the documented Discord fallback between runtime elevated authorization and `sandbox explain`, preserving explicit empty elevated allowlists as overrides.

## Reproduction Assessment

Yes at source level: the current runtime fallback hook has no Discord implementation, and `sandbox explain` reads only `tools.elevated.allowFrom.<channel>`. I did not run a live Discord gateway repro in this read-only review.

## Solution Assessment

Yes: the best fix is a narrow shared resolver for the documented Discord fallback used by both runtime elevated auth and diagnostics, with regression coverage for omitted versus explicitly empty `tools.elevated.allowFrom.discord`.
