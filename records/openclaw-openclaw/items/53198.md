## Summary

Keep open: current main still lacks a Discord elevated fallback implementation, latest release v2026.6.11 still documents that fallback, and an open linked fork PR exists but is conflicting and security-sensitive. Current main docs now say bundled channels do not implement fallback, so maintainers need to decide whether to restore the release contract or retire it deliberately.

## What This Changes

The issue reports that Discord elevated authorization does not honor the documented `channels.discord.allowFrom` fallback when `tools.elevated.allowFrom.discord` is omitted.

## Best Possible Solution

Decide the contract, then either land a narrow Discord plugin-owned fallback reused by `sandbox explain` with explicit-empty, per-agent, and account-scoped tests, or retire the release-doc fallback promise deliberately.

## Reproduction Assessment

Yes. Source inspection shows current main only consults a generic channel `elevated.allowFromFallback` hook, Discord does not implement that hook, and `sandbox explain` reads only explicit `tools.elevated.allowFrom`; no live Discord run was performed.

## Solution Assessment

Unclear until maintainers settle the contract. If preserving v2026.6.11 docs, the best fix is the Discord-owned fallback shared with diagnostics; if the main-docs change is intentional, the project should retire the fallback promise explicitly instead of leaving the issue half-resolved.
