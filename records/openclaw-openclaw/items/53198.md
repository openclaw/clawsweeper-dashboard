## Summary

Keep open: current main still does not implement the Discord elevated fallback, the latest release still promised it, and the only open linked fix is a conflicting fork PR that maintainers cannot modify. The remaining decision is security/product direction, not stale cleanup.

## What This Changes

Discord elevated exec should honor the shipped/documented fallback from `channels.discord.allowFrom` when `tools.elevated.allowFrom.discord` is omitted, and `sandbox explain` should report that path consistently.

## Best Possible Solution

Maintainers should explicitly choose the elevated authorization contract, then either land a narrow Discord-plugin fallback shared by runtime and diagnostics with security tests or close this as an intentional explicit-allowlist policy change.
