## Summary

Keep open: current main and the latest release still miss the documented Discord elevated `allowFrom` fallback, and the linked fork PR is open, conflicting, and unmerged rather than implementation provenance. Source inspection still shows runtime elevated auth only calls a generic plugin fallback hook, while Discord does not register that hook and `sandbox explain` still reads only explicit `tools.elevated.allowFrom.discord` entries.

## What This Changes

The issue asks OpenClaw to honor the documented Discord elevated fallback from `channels.discord.allowFrom` when `tools.elevated.allowFrom.discord` is omitted, and to make `sandbox explain` report the same effective authorization path.

## Best Possible Solution

Implement the documented fallback through the Discord-owned channel/plugin adapter and reuse that same resolver in `sandbox explain`, with focused coverage for omitted fallback, explicit empty override, per-agent restriction, and account-scoped Discord allowlists.

## Reproduction Assessment

Yes for source reproduction: docs promise the Discord fallback, runtime only calls a plugin fallback hook, Discord does not implement that hook, and `sandbox explain` reads only explicit elevated allowFrom config. I did not run a live Discord elevated command in this read-only review.

## Solution Assessment

Yes: the best fix is the documented narrow fallback, but it should live in the Discord-owned adapter and shared diagnostics path rather than as an ad hoc core special case. The linked fork PR is a candidate to review or replace, not proof that the issue is fixed.
