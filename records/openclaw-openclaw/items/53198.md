## What This Changes

The issue requests restoring the documented Discord elevated authorization fallback from `channels.discord.allowFrom` when `tools.elevated.allowFrom.discord` is omitted, plus aligned `sandbox explain` diagnostics.

## Best Possible Solution

Land a narrow Discord plugin-owned `elevated.allowFromFallback` path shared by runtime auth and `sandbox explain`, with regression coverage for omitted fallback, explicit empty override, per-agent restriction, and account-scoped diagnostics.

## Reproduction Assessment

Yes. Source inspection reproduces the mismatch: docs promise the Discord fallback, runtime only calls a plugin fallback hook, Discord does not register that hook, and `sandbox explain` reads only explicit elevated allowFrom config.

## Solution Assessment

Yes. The narrow maintainable fix is to implement the documented fallback through the Discord-owned plugin adapter and reuse that resolution in diagnostics rather than hard-coding Discord policy in core.
