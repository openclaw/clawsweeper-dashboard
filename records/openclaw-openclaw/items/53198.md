## What This Changes

The issue reports that Discord elevated authorization should fall back from omitted `tools.elevated.allowFrom.discord` to `channels.discord.allowFrom`, and that `sandbox explain` should report the same decision path.

## Best Possible Solution

Adopt or replace the linked fix with a narrow Discord plugin-owned fallback adapter and shared diagnostics/runtime resolution, with regression coverage for omitted versus explicitly empty `tools.elevated.allowFrom.discord`.

## Reproduction Assessment

Yes. Source inspection reproduces the bug: the docs require a Discord fallback, but current main has no Discord `allowFromFallback` implementation and `sandbox explain` reads only explicit elevated config.

## Solution Assessment

Yes, the best fix is a narrow channel-owned fallback shared by runtime elevated auth and `sandbox explain`; duplicating the user allowlist under `tools.elevated.allowFrom.discord` should remain only a workaround.
