## Summary

Keep open: current main and v2026.6.11 still miss the documented Discord elevated allowFrom fallback, and the only open linked implementation path is a conflicting fork PR that changes an elevated authorization boundary.

## What This Changes

The issue reports that Discord elevated exec ignores the documented fallback from `channels.discord.allowFrom` when `tools.elevated.allowFrom.discord` is omitted, and that `sandbox explain` misreports the same path.

## Best Possible Solution

Land a narrow Discord-owned elevated fallback resolver shared by runtime authorization and `sandbox explain`, with tests for omitted fallback, explicit empty override, per-agent restriction, identity formatting, and account-scoped diagnostics.

## Reproduction Assessment

Yes. Source inspection reproduces the mismatch: docs promise the Discord fallback, runtime only calls a plugin fallback hook, Discord does not register that hook, and `sandbox explain` reads only explicit elevated allowFrom config.

## Solution Assessment

Yes, the best fix is a narrow Discord-owned fallback implementation reused by runtime and diagnostics; the open fork PR shows the right test shape but needs maintainer/security review or replacement because it is conflicting.
