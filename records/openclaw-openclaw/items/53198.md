## What This Changes

The issue requests restoring or reconciling the Discord elevated allowlist fallback from `channels.discord.allowFrom` when `tools.elevated.allowFrom.discord` is omitted, plus consistent `sandbox explain` diagnostics.

## Best Possible Solution

Maintainers should either close the product direction by keeping explicit elevated allowlists as the supported contract, or land a narrow Discord-owned fallback shared by runtime and diagnostics with focused security tests.

## Reproduction Assessment

Yes. Source inspection shows runtime only uses the channel plugin fallback hook and Discord does not implement it, while `v2026.6.11` docs promised the Discord fallback; no live Discord run was performed.

## Solution Assessment

Unclear. A narrow Discord adapter is the best fix if the shipped docs remain a contract, but current main now documents explicit elevated allowlists as required, so maintainers need to choose the security/product direction.
