## What This Changes

Extends agent session recovery cleanup so rows with missing status, stale restart-recovery fences, and no active recovery owner are admitted on the next foreground claim.

## System Context

Agent message admission claims ownership of a persisted session before work starts. Restart recovery leaves temporary fences on interrupted sessions; the recovery-state transition decides whether those fences remain authoritative or are cleared so the next message can proceed.

## Architecture Diagram

flowchart TD
  A[Incoming agent message] --> B[Foreground session claim]
  B --> C[Persisted session recovery state]
  C --> D{Status and recovery fences}
  D -->|Running recovery remains active| E[Keep recovery ownership]
  D -->|Terminal or absent status residue| F[Clear orphaned recovery residue]
  E --> G[Reject or retry admission]
  F --> H[Admit next agent run]

## Best Possible Solution

Retain the narrow non-running-status cleanup rule if a real affected session successfully accepts a subsequent message while a genuinely running recovery case remains protected.
