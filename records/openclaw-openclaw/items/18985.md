## Summary

Keep open: current main and the latest release still reject the reported MSYS2/MINGW `install.sh` path and still provide bash/zsh-only PATH persistence and warning guidance, so this remains a Windows shell support-boundary decision.

## What This Changes

Request support for running the Unix installer under Windows 11 MSYS2/MINGW and for fish-shell PATH guidance after install.

## Best Possible Solution

Maintain one explicit Windows Unix-shell policy: either support MSYS2/MINGW with installer logic, docs, focused tests, and Windows smoke proof, or document PowerShell and WSL2 as the supported Windows paths.

## Reproduction Assessment

Yes, at source level: current `scripts/install.sh` sends MSYS/MINGW-style `OSTYPE` values to the unsupported-OS branch, and the fish PATH concern is visible in bash/zsh-only code paths. I did not run a real Windows 11 MSYS2 smoke test in this read-only review.

## Solution Assessment

Unclear until maintainers decide the support boundary. The maintainable solution is either tested MSYS2/MINGW plus fish support in installer/docs/tests, or explicit documentation that Windows users should use PowerShell or WSL2 instead.
