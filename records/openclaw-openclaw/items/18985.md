## Summary

Keep open: current main and v2026.6.11 still do not support the reported MSYS2/MINGW `install.sh` path or fish-specific PATH persistence, and adding that support remains a Windows shell support-boundary decision rather than a cleanup close.

## What This Changes

The issue requests support for running the Unix installer and OpenClaw in Windows 11 MSYS2/MINGW environments, plus fish-shell PATH guidance.

## Best Possible Solution

Maintain one explicit Windows Unix-shell policy: either support MSYS2/MINGW with installer logic, fish-aware PATH handling, docs, tests, and Windows smoke proof, or document PowerShell and WSL2 as the supported Windows paths.

## Reproduction Assessment

Yes, at source level: current `scripts/install.sh` sends MSYS/MINGW-style environments to the unsupported-OS branch, and the fish PATH concern is visible in bash/zsh-only persistence and warning code. I did not run a real Windows 11 MSYS2 smoke test in this read-only review.

## Solution Assessment

No, the proposed guard removal is not the best complete fix by itself. The maintainable path is either tested MSYS2/MINGW plus fish support across installer/docs/tests, or explicit docs that Windows users should use PowerShell or WSL2 instead.
