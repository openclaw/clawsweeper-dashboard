## Summary

Keep open: current main and the latest release still reject MSYS2/MINGW through the Unix installer and still provide bash/zsh-only PATH guidance, so this remains a concrete Windows shell support request that needs a maintainer support-boundary decision.

## What This Changes

The issue requests `install.sh` support for Windows 11 MSYS2/MINGW Unix-like shells plus fish-shell PATH persistence or guidance.

## Best Possible Solution

Maintain one explicit Windows Unix-shell policy: either support MSYS2/MINGW with installer logic, docs, focused tests, and Windows smoke proof, or document PowerShell and WSL2 as the supported Windows paths.

## Reproduction Assessment

Yes, at source level: current `scripts/install.sh` routes MSYS/MINGW-style `OSTYPE` values to the unsupported-OS branch, and the fish PATH concern is visible in bash/zsh-only code paths. I did not run a real Windows 11 MSYS2 smoke test in this read-only review.

## Solution Assessment

No, the proposed workaround of commenting out the OS guard is not the best fix because it leaves `OS=unknown` and lets Windows Unix shells run through Linux assumptions. The maintainable answer is a deliberate support policy with tests and docs, or an explicit documented non-support path.
