## What This Changes

Investigate and prevent multi-second Gateway event-loop stalls during multi-agent Slack group activity that disconnect Socket Mode, starve timers, and cause embedded session-write-lock timeouts.

## System Context

The Gateway receives channel events, schedules concurrent agent turns, persists session updates, and sends channel replies from one Node.js process. A long synchronous or unyielding turn-path phase prevents Slack Socket Mode callbacks, timer callbacks, and queued session work from running until the event loop returns.

  D --> E[Session updates and timers]

## Best Possible Solution

Add bounded, content-free timing and event-loop-delay attribution around the group-turn hot path, reproduce the stall under representative concurrent load, then fix the measured synchronous phase with a focused regression test; keep Socket Mode tolerance changes only as secondary resilience work.
