## Summary

The proposed fix handles the reported invalid-template sequence, but it does not restore watching when the cached template is still valid: subsequent edits can remain permanently stale after a watcher error. A small mechanical follow-up is needed before merge.

## What This Changes

The PR clears a cached usage-bar template watcher reference after an `FSWatcher` error and adds a regression test for recovery after invalid file contents are fixed.

## Best Possible Solution

On watcher error, invalidate the cached template together with the watcher reference, or otherwise make the next access recreate the watcher even when a prior template value exists; cover both valid-cache and invalid-cache recovery sequences.
