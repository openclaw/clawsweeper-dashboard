## Summary

Current `main` still has a source-level mismatch: the documented embedded ChatGPT OAuth path accepts `params.transport: "websocket"`, but the OpenClaw runtime’s WebSocket selector deliberately rejects the ChatGPT backend URL and falls through to the HTTP Responses transport. The earlier legacy-provider fix does not cover this canonical `openai/*` plus explicit OpenClaw-runtime path, so this issue remains necessary.

## What This Changes

Make model-scoped `params.transport: "websocket"` control the embedded ChatGPT/Codex OAuth transport for canonical `openai/*` models instead of silently sending HTTP POST requests.

## Best Possible Solution

Add a provider-correct ChatGPT Responses WebSocket path for the embedded OpenClaw runtime—preferably by reusing the pinned PI/Codex native transport—while preserving `auto` fallback, making forced `websocket` fail clearly instead of silently using POST, and covering canonical `openai/*` OAuth routing in focused tests.
