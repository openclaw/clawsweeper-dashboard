## Summary

Keep open: current main still renders assistant shell snippets as copyable markdown code blocks, while approval controls only appear for Gateway-created exec approval events; the requested Control UI command proposal flow remains a distinct product/security design item.

## What This Changes

The issue requests Control UI command cards with Copy and Approve and Run actions for assistant-suggested shell commands.

## Best Possible Solution

Define a structured command-proposal contract that reuses the existing exec approval and canonical execution safeguards, rather than adding a run button to arbitrary markdown code blocks.

## Reproduction Assessment

Yes at source level: assistant code blocks render copy-only markdown controls, while approve/run controls are only created from Gateway exec approval events. I did not run a live browser session in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product/security boundary. A structured proposal-to-approval path is safer than inferring executable commands from arbitrary markdown.
