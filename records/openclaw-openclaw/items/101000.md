## Summary

Keep open; the PR is useful cleanup, but it is not merge-ready because the claimed non-streaming OOM fix still routes body-less responses through a full `arrayBuffer()` read before enforcing `maxBytes`.

## What This Changes

The PR replaces the hosted plugin catalog reader's local streaming loop with `readResponseWithLimit` and adds oversized hosted-feed regression tests.

## Best Possible Solution

Keep the shared streaming reader for stream-backed responses, but make hosted catalog reads fail before the body-less `arrayBuffer()` fallback or prove a genuinely bounded non-stream reader before merge.
