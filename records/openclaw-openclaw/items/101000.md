## Summary

This PR is still necessary and should stay open for maintainer review: current main still has the source-visible streamless hosted catalog path that calls `response.text()` before enforcing `maxBytes`, while the branch removes that unsafe path and adds focused proof. I found no concrete patch defect; the remaining decision is whether maintainers accept the intentional fail-closed behavior for streamless hosted feed responses.

## What This Changes

The PR replaces the hosted external plugin catalog response reader with the shared bounded HTTP body reader, rejects streamless hosted feed responses before buffering, adds regression tests, and adds a loopback proof script.

## Best Possible Solution

Land this shape after maintainers accept fail-closed streamless fallback; otherwise require a bounded streamless design that avoids trusting `Content-Length` or buffering untrusted hosted feed bodies.
