## Summary

Keep this PR open: it resolves the previously missed safe-child-process path, but its new “first nonblank alias” lookup disagrees with Node’s Windows duplicate-environment forwarding rule. A command can be resolved to an absolute executable while the child still receives the blank `PATH`, which can break shims and their downstream command lookup; the supplied live proof also names an earlier head rather than the current one.

## What This Changes

The PR changes Windows executable lookup in the shared process and plugin-SDK paths to select a nonblank case-insensitive `PATH` or `PATHEXT` alias while treating an all-blank alias set as explicitly empty.

## Best Possible Solution

Normalize duplicate Windows `PATH` and `PATHEXT` aliases into the same single values passed to the spawned child, or deliberately follow Node’s lexicographic first-key behavior; add a real Windows integration test that executes a shim requiring the inherited search path.
