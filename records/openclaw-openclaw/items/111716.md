## Summary

Keep open: the patch improves the tested `PATH`/`Path` and `PATHEXT`/`Pathext` cases, but it still does not implement case-insensitive lookup for arbitrary injected Windows environment-key casing.

## What This Changes

Updates Windows executable resolution to prefer a nonblank `PATH`/`Path` or `PATHEXT`/`Pathext` value and adds regression coverage for blank uppercase aliases.

## Best Possible Solution

Normalize lookup across all own environment entries whose keys case-fold to `PATH` or `PATHEXT`, preserving the explicit-empty-path rule, and add regressions for non-title-case variants.
