## Label Justifications

- `P1`: The report describes a current runtime-policy regression that reportedly blocks unattended Codex cron workflows across otherwise unrelated agents.
- `impact:auth-provider`: The affected behavior selects Codex app-server approval policy and approval routing for OpenAI/Codex-backed sessions.

## Summary

The reported fleet-wide promotion is consistent with the shipped Codex integration design, but a safe scope-aware replacement needs a maintainer decision because it changes the plugin hook contract and can weaken the existing fail-closed guarantee if a native tool run is misclassified.

## What This Changes

Add a scope-aware mechanism so Codex app-server approval-policy promotion for `before_tool_call` hooks applies only to matching agent/session runs while unscoped hooks retain global behavior.

## Best Possible Solution

Introduce a declarative hook-scope descriptor owned by the plugin hook runner, evaluate it against the prepared agent/session context before selecting the Codex approval policy, preserve global promotion for hooks without scope metadata, and log the matching plugin/hook identity.
