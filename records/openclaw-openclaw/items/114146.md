## What This Changes

Add a configurable WebSocket endpoint and an optional direct API-key authentication mode for Talk realtime providers that are compatible with OpenAI Realtime.

## System Context

Talk realtime connects a client voice session to a selected realtime provider using provider configuration and an authentication flow. The proposed settings would change how Talk selects the provider endpoint and whether credentials are exchanged through a client-secret flow or presented directly to the realtime service.

## Best Possible Solution

Define a provider-capability and transport design that keeps durable credentials server-side by default, then add a narrowly validated provider-owned configuration path only for services whose realtime protocol and authentication model are explicitly supported.

Options:

- **Design a relay/provider capability (recommended):** Define provider-owned endpoint and authentication capabilities that preserve server-side credential handling, then implement supported providers against that contract.
- **Add a narrow OpenAI-compatible mode:** Permit only documented compatible endpoints after proving their session protocol and direct-key browser exposure are safe and adding explicit upgrade and security tests.
- **Defer direct compatibility support:** Keep the current OpenAI-specific path and route provider-specific realtime integrations through plugins or a future relay design.
