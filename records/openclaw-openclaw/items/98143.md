## Summary

Keep this PR open for maintainer/security policy review: the patch looks focused and correct, but it intentionally changes the shipped bodyless MCP OAuth fallback from text preservation to null-body responses when `Content-Length` is missing, malformed, or oversized.

## What This Changes

The PR adds a 1 MiB `Content-Length` gate for bodyless MCP HTTP foreign-response text fallback and expands regression coverage for safe, missing, malformed, oversized, and dishonest lengths.

## Best Possible Solution

Land one focused MCP HTTP fallback policy after maintainer/security sign-off, either this declared-length fail-closed approach or a stricter full fail-closed policy if compatibility can be broken.
