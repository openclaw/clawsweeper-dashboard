## Summary

## What This Changes

The PR authorizes the gateway’s agent-file cleanup to move each configured agent path to trash from its own parent directory instead of relying on the safe-trash utility’s home and temporary-directory defaults.

## System Context

The gateway agent-deletion method removes an agent from configuration and then attempts to trash its workspace, agent directory, and session directory. The shared filesystem safety utility decides whether each deletion target is inside an authorized root before the operating system trash move occurs.

## Best Possible Solution

Use one well-tested authorized-root derivation consistent with the CLI safe-trash contract, then prove gateway deletion succeeds for an agent stored outside the home and temporary directories while retaining symlink safety coverage.
