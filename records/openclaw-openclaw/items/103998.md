## Summary

The PR remains necessary and has strong real-behavior proof, but the unchanged head still introduces a blocking timeout regression: a caller-selected short `--timeout` limits each RPC, not the new five-minute settle loop.

## What This Changes

The PR makes `gateway usage-cost` poll refreshing or partial cache responses with exponential backoff before printing totals and adds transcript-backed regression coverage through the real Gateway usage handler.

## Best Possible Solution

Keep the CLI-side settle loop, but use one end-to-end deadline derived from `--timeout`, pass only the remaining budget to each retry RPC, cap each sleep to that remaining budget, and cover both cold-cache success and persistent-refresh timeout behavior.
