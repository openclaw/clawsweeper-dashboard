## Label Justifications

- `P1`: The operator-facing audit command can return a false zero despite existing usage data and material spend.
- `merge-risk: 🚨 compatibility`: The shipped command’s implicit timeout changes from ten seconds to five minutes for existing callers that omit the flag.

## Summary

Keep open for landing: current main still prints the first `usage.cost` response immediately, while this clean final head waits through every unsettled cache state under one deadline. Earlier timeout and stale-cache review blockers are resolved, real behavior proof is sufficient, and no correctness or security finding remains; maintainers should only acknowledge the intentional longer default timeout before merge.

## What This Changes

The branch makes `gateway usage-cost` poll until the usage cache is fresh under a command-wide timeout, changes that command’s default timeout from 10 seconds to five minutes, and adds real-handler regression coverage.

## Best Possible Solution

Land the CLI-scoped settlement loop with the five-minute default as an intentional audit-correctness tradeoff, while retaining explicit `--timeout` for automation requiring a shorter deadline and preserving immediate cache-backed responses for other RPC consumers.
