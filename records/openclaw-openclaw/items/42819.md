## Summary

Keep open: current main and the latest release solve the brittle versioned Playwright executable lookup through runtime cache autodetection, but Docker still stores browsers under `/home/node/.cache/ms-playwright` and does not expose stable `chrome` or `chromium` commands on PATH. The remaining `/opt` and PATH behavior changes the Docker image contract and needs maintainer product direction.

## What This Changes

The issue requests moving Docker Playwright browsers out of the hidden node cache and exposing a stable Chrome/Chromium binary on PATH.

## Best Possible Solution

Keep the shipped Playwright cache autodetection unless maintainers explicitly approve a Docker image contract change; if approved, land a focused Dockerfile/docs/test update with live proof for browser-enabled, browser-disabled, runtime-install, and upgrade scenarios.
