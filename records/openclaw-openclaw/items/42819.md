## Summary

Keep open: current main and the latest release solve the brittle versioned Playwright executable lookup by auto-detecting Playwright-managed Chromium, but they still install Docker browser assets under `/home/node/.cache/ms-playwright` and do not expose stable `chrome` or `chromium` commands on PATH. The remaining request changes the Docker image contract and needs maintainer product direction rather than automatic cleanup.

## What This Changes

The issue asks Docker browser-enabled images to avoid versioned Playwright cache paths by exposing Chrome/Chromium on PATH and preferably storing browser assets outside a hidden cache directory.

## Best Possible Solution

Keep the shipped Playwright cache autodetection, and only change the Docker browser storage/PATH contract if maintainers approve the migration story with focused Dockerfile, docs, tests, and live container proof.
