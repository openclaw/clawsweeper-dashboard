## Summary

Keep open: current main and the latest release solve the brittle versioned executable lookup through Playwright cache autodetection, but they still keep Docker browsers under `/home/node/.cache/ms-playwright` and do not provide stable `chrome` or `chromium` PATH commands. The remaining request changes the Docker image contract and needs maintainer product direction before implementation.

## What This Changes

The issue asks Docker browser-enabled images to avoid versioned hidden Playwright cache paths by exposing a stable browser command and/or moving browser assets outside `.cache`.

## Best Possible Solution

Keep the shipped Playwright cache autodetection unless maintainers explicitly approve a Docker image contract change; if approved, land a focused Dockerfile/docs/test update with live proof for browser-enabled, browser-disabled, runtime-install, and upgrade scenarios.
