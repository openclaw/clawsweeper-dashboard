## Summary

Keep open: current main and the latest release solve the brittle versioned executable lookup by autodetecting Playwright-managed Chromium, but they still keep Docker browser assets under `/home/node/.cache/ms-playwright` and do not expose stable `chrome` or `chromium` commands on PATH.

## What This Changes

The issue requests Docker browser-enabled images move Playwright browser files out of the hidden cache path and expose a stable browser executable on PATH.

## Best Possible Solution

Keep the shipped Playwright cache autodetection unless maintainers explicitly approve a Docker image contract change; if approved, land a focused Dockerfile/docs/test update with live proof for browser-enabled, browser-disabled, runtime-install, and upgrade scenarios.
