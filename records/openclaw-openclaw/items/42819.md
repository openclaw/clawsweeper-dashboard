## Summary

Keep open: current main and the latest release solve the brittle versioned Playwright executable lookup through runtime autodetection, but the requested Docker image contract still remains: browser assets are still under `/home/node/.cache/ms-playwright` and no stable `chrome` or `chromium` command is created on PATH. The remaining change is compatibility-sensitive Docker packaging behavior and needs maintainer product direction rather than an automatic cleanup close.

## What This Changes

The issue asks for Docker browser-enabled images to store Playwright browsers outside the hidden cache path and expose a stable browser command on PATH.

## Best Possible Solution

Keep the shipped Playwright cache autodetection unless maintainers explicitly approve a Docker image contract change; if approved, land a focused Dockerfile/docs/test update with live proof for browser-enabled, browser-disabled, runtime-install, and upgrade scenarios.
