## Summary

Keep open: current main and the latest release already solve the brittle versioned Playwright executable lookup by detecting Playwright-managed Chromium, but the requested Docker image contract still is not implemented because browsers remain under `/home/node/.cache/ms-playwright` and no stable `chrome` or `chromium` command is created on PATH. The remaining work is a Docker default and upgrade-policy decision, not conservative cleanup.

## What This Changes

The issue requests Docker browser-enabled builds to store Playwright browser files outside the hidden node cache and expose a stable Chrome/Chromium command on PATH.

## Best Possible Solution

Keep the shipped Playwright cache autodetection, and only change the Docker browser storage or PATH command contract if maintainers approve a migration story with focused Dockerfile, docs, tests, and live container proof.
