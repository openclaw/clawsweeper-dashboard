## Summary

Keep open: current main and the latest release fix the brittle versioned Playwright executable lookup through runtime autodetection, but they still keep Docker browser assets under the node home cache and do not expose stable `chrome` or `chromium` PATH commands.

## What This Changes

The issue requests Docker browser-enabled builds to place Playwright browser files outside `/home/node/.cache/ms-playwright` and expose a stable Chrome/Chromium command instead of requiring versioned executable paths.

## Best Possible Solution

Keep the shipped Playwright cache autodetection unless maintainers explicitly approve a Docker image contract change; if approved, land a focused Dockerfile/docs/test update with live proof for browser-enabled, browser-disabled, runtime-install, and upgrade scenarios.
