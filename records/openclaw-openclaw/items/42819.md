## Summary

Keep open: current main and the latest release fixed OpenClaw's need to hard-code a versioned Playwright Chromium path, but Docker browser assets still live under `/home/node/.cache/ms-playwright` and no stable `chrome`/`chromium` PATH command is created. ## What This Changes

The issue asks Docker browser-enabled builds to expose a stable Chrome/Chromium command and store Playwright browsers somewhere less hidden than the node cache.

## Best Possible Solution

Keep the shipped Playwright cache autodetection unless maintainers explicitly approve a Docker image contract change; if approved, land a focused Dockerfile/docs/test update with live proof for browser-enabled, browser-disabled, runtime-install, and upgrade scenarios.
