## Summary

Keep open: current main and `v2026.6.11` already solve the brittle versioned Playwright executable lookup by detecting Playwright-managed Chromium, but Docker still stores browsers under `/home/node/.cache/ms-playwright` and does not expose stable `chrome` or `chromium` commands on PATH. The remaining request changes the Docker image contract, so it needs maintainer product direction rather than conservative cleanup.

## What This Changes

The issue asks OpenClaw's Docker image to place Playwright browser assets outside the hidden node cache and expose a stable Chrome/Chromium executable on PATH.

## Best Possible Solution

Keep the shipped Playwright cache autodetection, and only change Docker browser storage or PATH aliases after maintainers choose the image contract and require Dockerfile, docs, tests, and live container proof for browser-enabled, browser-disabled, runtime-install, and upgrade scenarios.
