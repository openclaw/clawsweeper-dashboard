## Summary

Keep open: current main and the latest release fix the brittle versioned executable lookup by autodetecting Playwright-managed Chromium, but they still keep Docker browser assets under `/home/node/.cache/ms-playwright` and do not create stable Docker `chrome` or `chromium` commands on PATH.

## What This Changes

Request Docker browser-enabled images to store Playwright browsers outside a hidden cache path and expose stable Chrome or Chromium commands on PATH.

## Best Possible Solution

Keep the shipped Playwright cache autodetection unless maintainers explicitly approve a Docker image contract change; if approved, land a focused Dockerfile/docs/test update with live proof for browser-enabled, browser-disabled, runtime-install, and upgrade scenarios.
