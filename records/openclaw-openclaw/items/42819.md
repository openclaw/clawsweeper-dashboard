## Summary

Keep open: current main and the latest release solve the brittle versioned Playwright executable lookup by autodetecting the cache layout, but they still keep Docker browsers under `/home/node/.cache/ms-playwright` and do not create stable `chrome` or `chromium` PATH commands. The remaining request changes the Docker image contract and needs maintainer product direction before implementation.

## What This Changes

Move Docker Playwright browser files out of the hidden cache path and expose a stable Chrome/Chromium command on PATH.

## Best Possible Solution

Keep the shipped Playwright cache autodetection unless maintainers explicitly approve a Docker image contract change; if approved, land a focused Dockerfile/docs/test update with live proof for browser-enabled, browser-disabled, runtime-install, and upgrade scenarios.
