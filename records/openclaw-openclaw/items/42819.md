## Summary

Keep open: current main and v2026.6.11 solve the brittle versioned executable lookup by autodetecting Playwright-managed Chromium, but Docker still stores browsers under the home cache and exposes no stable `chrome` or `chromium` PATH command; changing that contract needs maintainer direction and upgrade proof.

## What This Changes

The issue asks Docker browser-enabled images to move Playwright browsers out of `.cache` into an `/opt`-style path and expose a stable Chrome/Chromium binary on PATH.

## Best Possible Solution

Keep the shipped Playwright cache autodetection unless maintainers explicitly approve a Docker image contract change; if approved, land a focused Dockerfile/docs/test update with live proof for browser-enabled, browser-disabled, runtime-install, mounted-cache, and upgrade scenarios.
