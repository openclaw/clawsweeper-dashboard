## Summary

The feature belongs in the existing provider streaming seam and has convincing live MP3 proof, but the branch advertises all existing buffered xAI formats through a Discord stream consumer that cannot reliably decode unsupported or raw formats after fallback has been bypassed. Keep this PR and its paired issue open for a focused compatibility repair; exact-head dependency authorization is also still required.

## Best Possible Solution

Keep native streaming provider-local, enable it only for xAI codecs proven compatible with the existing Discord pipe consumer, preserve buffered synthesis for every other existing format, and add format-specific caller coverage before dependency approval and merge.
