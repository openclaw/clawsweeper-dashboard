## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Keep target parsing behind plugin contracts:** `src/channels/plugins/target-parsing.ts:5-7`
  - body: These new core imports reach directly into bundled extension private `src/**` parser modules. The Teams parser lives in `resolve-allowlist.ts`, which also imports Graph/token allowlist helpers, so command/binding target parsing can now pull channel-owned runtime dependencies into a core path and bypass the registered plugin contract. Keep this path on `messaging.resolveOutboundSessionRoute`/targetResolver or a light public plugin artifact instead of deep-importing extension internals.
  - confidence: 0.89
- **[P1] Remove Teams host ops from the public SDK facade:** `src/plugin-sdk/msteams.ts:111-118`
  - body: This publishes Teams send/edit/delete/typing/channel-edit helpers through `openclaw/plugin-sdk/msteams`, and the runtime then consumes those public exports. Those helpers are backed by host Teams credentials and Microsoft Graph operations, so landing them as a public plugin SDK surface without an approved contract, docs, and security model widens what plugins can do with host credentials. Keep these host-owned operations behind the Teams runtime/extension boundary or land an explicit maintainer-sponsored API contract.
  - confidence: 0.84
- **[P1] Migrate or preserve channel Graph metadata before requiring it:** `extensions/msteams/src/graph-messages.ts:140-143`
  - body: Existing `msteams-conversations` records will not have the newly added `graphChannelId`, but this branch now throws for any stored channel conversation missing it before channel Graph operations run. The same branch writes `graphChannelId` from every inbound activity even when `channelData.channel` is absent, and the merge helper only preserves timezone, so a sparse activity can erase a previously known channel id. Add a doctor/backfill or preserve fallback before requiring the new field.
  - confidence: 0.9
