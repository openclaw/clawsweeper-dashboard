## Label Justifications

## Summary

Keep open: current main has fixed the legacy JSON-state failure class, but the remaining managed Dreaming cron status problem is still real enough for maintainer review because per-workspace failures can be logged while the cron run remains a handled success.

## What This Changes

The issue asks OpenClaw to stop silently treating managed memory Dreaming cron `NO_REPLY`/no-diary runs as healthy when promotion work did not actually produce durable memory or diary output.

## Best Possible Solution

Managed Dreaming should keep the SQLite-backed state path while making failed or no-op scheduled promotion visibly actionable in cron/doctor/Dreams status without requiring users to inspect raw logs.
