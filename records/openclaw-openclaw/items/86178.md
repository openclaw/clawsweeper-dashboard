## Label Justifications

- `P1`: The issue reports a real user-facing regression where scheduled memory Dreaming stops producing expected session-ingestion and diary state across deployments.
- `impact:session-state`: The affected path controls Dreaming session ingestion, recall freshness, and durable memory promotion state.

## Summary

Keep open: current main and v2026.6.11 have fixed the legacy JSON/WSL2 Dreaming-state causes, but the broader managed Dreaming cron status-visibility problem is still not proven gone because per-workspace failures can remain plugin-local while cron records the outer run as handled.

## What This Changes

The issue asks OpenClaw to stop silently no-oping the managed Memory Dreaming Promotion cron when run state stays stale and DREAMS.md/session-ingestion output stops updating.

## Best Possible Solution

Keep this as the status-visibility tracker, preserve the shipped SQLite-state fixes, and have maintainers decide how managed Dreaming partial failures or no-op sweeps surface through cron diagnostics, doctor, and memory status before validating on a live affected deployment.
