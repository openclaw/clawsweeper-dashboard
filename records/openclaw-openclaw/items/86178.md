## Summary

Keep open: current main and the latest release removed the legacy JSON-state causes, and current main adds structured failed Dreaming events, but the managed Dreaming cron can still handle workspace failures while returning a successful outer cron result, so the broader NO_REPLY/status-visibility problem is not conclusively fixed.

## What This Changes

The issue asks OpenClaw to stop silently accepting managed Memory Dreaming Promotion cron runs that produce NO_REPLY and stale or missing Dreaming output without operator-visible run state.

## Best Possible Solution

Keep the SQLite state fixes, then make managed Dreaming failures operator-visible through cron diagnostics, doctor or memory status, and close only after live current-main proof or an explicit maintainer status-semantics decision.
