## Summary

Keep open: current main fixed the legacy JSON-state causes, but it has not proven the broader managed Dreaming cron NO_REPLY/status-visibility failure is gone because memory-core can log per-workspace failures while returning a handled cron result.

## What This Changes

The issue asks OpenClaw to stop silently treating managed Memory Dreaming cron no-op or failure runs as successful when diary and session-promotion state stops updating.

## Best Possible Solution

Keep this issue open until a maintainer-approved status, doctor, and run-log policy for managed Dreaming failed or no-op sweeps is implemented and live-proved.
