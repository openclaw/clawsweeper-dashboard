## Summary

Keep open: current main has migrated the legacy JSON cron and Dreaming state causes, but source inspection still shows managed Dreaming can return an outer handled cron result while per-workspace Dreaming failures/no-op work remain local to memory-core logs/events, so the reported status-visibility/session-memory loss class is not proven fixed.

## What This Changes

The issue reports managed Memory Dreaming cron runs that silently return `NO_REPLY`/never update visible run state while session ingestion and `DREAMS.md` stop advancing.

## Best Possible Solution

Define and implement a maintained status contract for managed Dreaming so no-op or per-workspace failed runs surface through cron state, doctor, and logs without relying on users to inspect memory-core internals.
