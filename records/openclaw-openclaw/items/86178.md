## Summary

Keep open: current main has fixed the legacy JSON cron/dreaming-state causes through SQLite, but source still lets memory-core log per-workspace Dreaming failures while returning a handled cron result, so the remaining NO_REPLY/status-visibility contract still needs maintainer review.

## What This Changes

The issue asks for managed Memory Dreaming Promotion cron runs to record execution or error state and produce Dreaming diary output instead of silently returning NO_REPLY while legacy jobs.json fields stay null.

## Best Possible Solution

Keep the shipped SQLite state migration, then define one observable failure contract for managed Dreaming cron so failed workspaces surface through cron run history, doctor, or Dreams Digest instead of only an ok/NO_REPLY run.
