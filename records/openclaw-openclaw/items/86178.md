## Summary

Keep open: SQLite and isolated-cron changes fix the old `jobs.json`/null-state and WSL2 or over-limit JSON causes, but current main and the latest release still allow memory-core to catch per-workspace Dreaming failures and return a handled cron result, so the remaining status-visibility behavior needs maintainer direction.

## What This Changes

The issue reports that the managed memory Dreaming Promotion cron can run or be accepted but return `NO_REPLY` without updating visible cron state, session ingestion state, or `DREAMS.md`.

## Best Possible Solution

Keep the SQLite state and isolated-cron fixes, then define one maintainer-approved status contract for managed Dreaming sweeps so cron, doctor/status, logs, and Dreaming diagnostics agree when a run fails, does no useful work, or completes cleanly.
