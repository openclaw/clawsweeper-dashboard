## Summary

Keep open: current main and v2026.6.11 still intentionally exclude macOS user-bin and Nix profile dirs from the managed Gateway service PATH, so this remains a maintainer product/security decision rather than cleanup.

## What This Changes

The issue asks OpenClaw to include macOS user bin directories such as Nix, Bun, and local bin paths in the Gateway daemon PATH, or expose an opt-in service PATH setting.

## Best Possible Solution

Decide the macOS managed-service PATH policy first; if supporting these dirs, prefer an explicit opt-in service PATH setting with doctor guidance, docs, and regression coverage over silently changing the canonical default.

- **Change the default:** Include Darwin user dirs by default and accept the upgrade/security risk that service child processes may resolve tools from user or version-manager directories.
- **Keep current policy:** Document that macOS service PATH remains canonical and route user-specific exec tool discovery through tools.exec.pathPrepend, login-shell PATH merging, or explicit command paths.

Yes for the service PATH behavior: current source and tests show Darwin user dirs and Nix profile dirs are omitted by default, and v2026.6.11 ships the same behavior. I did not live-reproduce the user-visible exec failure on macOS.

## Solution Assessment

Unclear: flipping the Darwin default is not clearly the best fix because current docs and tests encode a canonical PATH for service hardening. A maintainer-approved opt-in, or using the existing exec PATH mechanisms when sufficient, is safer.
