## Summary

Keep open: current main and the latest release still skip macOS user/Nix service PATH dirs by default, while current Nix docs promise launchd Nix-profile discovery. The remaining question is a maintainer security/product choice, not conservative cleanup.

## What This Changes

The issue asks OpenClaw to include macOS Gateway daemon user-bin and Nix paths, or expose an opt-in, so gateway exec commands can find tools installed outside canonical system directories.

## Best Possible Solution

Maintainers should choose the macOS service PATH policy, then either implement narrow Nix-mode or opt-in support with doctor/docs/tests, or correct the Nix docs to match the hardened canonical default.
