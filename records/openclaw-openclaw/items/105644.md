## Summary

Current main still cannot retrieve imported CLI transcript rows omitted by the `chat.history` byte budget. The broader scroll-back issue and open pagination PR intentionally leave this gap unresolved, while the protected `maintainer` label requires an explicit protocol and lifecycle-ownership decision.

## What This Changes

Add stable snapshot-cursor paging for oversized imported CLI transcripts returned by `chat.history`.

## Best Possible Solution

Create one shared lifecycle-owned imported-history snapshot/page service used by Gateway, embedded Gateway, and TUI; bind pages to a stable session generation, preserve strictly advancing semantics, bound memory and lifetime, invalidate on mutations, and add combined oversized-import regression proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should imported transcript paging extend the existing offset/total contract over a shared snapshot generation, or should opaque cursors become the canonical native `chat.history` paging contract?

Rationale: Both approaches solve the missing retrieval path, but they differ in public protocol compatibility, client migration, memory ownership, expiry, invalidation, and stale-page behavior; repository evidence cannot select that permanent contract without maintainer intent.

Likely owner: steipete

Owner reason: This person authored both protected design issues and provides the clearest available signal for the permanent protocol choice.

Owner confidence: high

Options:

- **Extend existing offsets (recommended):** Bind current offset and total metadata to one bounded merged snapshot generation, adding only explicit stale-generation handling where needed.
- **Adopt opaque cursors:** Make cursors the canonical native-history contract and migrate local and imported paging together with shared expiry and invalidation semantics.
- **Keep imports non-pageable:** Retain terminal-snapshot truncation disclosure and accept that omitted imported rows cannot be retrieved.

## Reproduction Assessment

Yes, at source level with high confidence: bind a Claude CLI session, make its merged transcript exceed the history byte budget, receive the truncated terminal snapshot, then request older offsets; the offset branch reads only local transcript rows. This read-only review did not execute a multi-megabyte fixture.

## Solution Assessment

Not fully yet. A shared lifecycle-owned snapshot/page service is the best implementation boundary, but maintainers must choose whether the permanent public contract extends current offsets or migrates all native history paging to opaque cursors.
