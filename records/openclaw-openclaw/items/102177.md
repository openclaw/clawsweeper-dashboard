## Summary

Keep open: current main still has APNs registration, relay, push-test, wake, and exec-approval notification plumbing, but ordinary assistant chat finals are not converted into native iOS assistant-message APNs alerts, and background Talk remains a policy-sensitive best-effort/default-off path.

## What This Changes

The issue requests native iOS APNs notifications for assistant messages plus supported background Talk mode or a clear paused/resume state.

## Best Possible Solution

Define a dedicated privacy-safe assistant-reply APNs contract with generic default content, explicit preview opt-in if desired, correct chat tap routing, and live iOS proof; keep background Talk paused/resumable unless maintainers approve broader background audio behavior.
