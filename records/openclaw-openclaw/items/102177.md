## Summary

Keep open: current main has APNs registration/test/wake plumbing and a local iOS chat-push command, but assistant chat finalization still only broadcasts chat payloads and does not trigger native APNs; background Talk is present only as a default-off keep-active/paused-resume path that needs privacy, Apple-policy, and product direction.

Request APNs remote pushes for native iOS assistant messages and background or clear paused/resume behavior for Talk mode.

## Best Possible Solution

Define a dedicated privacy-safe assistant-reply APNs contract with generic default content, optional explicit preview opt-in, correct tap routing, live iOS proof, and keep default background Talk paused unless maintainers approve broader background audio behavior.
