## Summary

Keep open: current main has APNs registration, relay-backed push tests/wakes, and a local iOS chat-push command, but no Gateway-owned APNs path that turns assistant chat finals into native iOS notifications. Background Talk is partly handled by pause/resume and a default-off keep-active setting, so the remaining work needs product, privacy, and live iOS review.

## What This Changes

Request native iOS APNs notifications for assistant replies plus supported background Talk behavior or a clear paused/resume state.

## Best Possible Solution

Define a dedicated privacy-safe assistant-reply APNs contract with generic default content, explicit preview opt-in if desired, correct tap routing, iOS live proof, and keep the current default-off background Talk/pause behavior unless maintainers approve broader background audio.
