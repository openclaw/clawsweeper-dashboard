## Summary

Keep open: current main and v2026.6.11 still lack a dedicated assistant-message APNs path for native iOS chat notifications, while background Talk remains a policy-sensitive default-off or pause/resume behavior.

## What This Changes

The issue requests native iOS APNs notifications for new assistant messages and a maintained background Talk mode or clear paused/resume state.

## Best Possible Solution

Define a dedicated privacy-safe assistant-reply APNs contract with generic default content, explicit preview opt-in only if approved, correct chat tap routing, and live iOS proof; keep background Talk default-off or paused/resumable unless maintainers approve broader background audio.
