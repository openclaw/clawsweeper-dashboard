## Summary

Keep open: current main still has APNs registration, test/wake, and exec-approval notification paths, but it does not route normal assistant chat finals into native iOS APNs alerts; background Talk also remains a product-sensitive default-off or pause/resume path rather than a settled always-on background-audio behavior.

## What This Changes

The issue requests native iOS push notifications for assistant messages plus continued or clearly paused/resumable Talk mode behavior while the app is backgrounded.

## Best Possible Solution

Define a dedicated privacy-safe assistant-reply APNs contract with generic default content, optional explicit preview opt-in, correct chat tap routing, and live iOS proof; keep background Talk paused/resumable unless maintainers approve broader background audio.
