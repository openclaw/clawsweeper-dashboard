## Summary

Keep open: current main still has APNs registration, test/wake/exec-approval push plumbing, and partial background Talk handling, but it does not route assistant chat finals into native iOS APNs alerts and the background Talk behavior still needs maintainer product, privacy, and live-device validation.

## What This Changes

Request native iOS APNs notifications for assistant messages plus a supported background Talk continuation or clear paused/resume experience.

## Best Possible Solution

Define a maintainer-approved, privacy-safe assistant-reply APNs contract with generic default content, tap routing, tests, and live iOS proof; make background Talk either explicit opt-in background audio or a clearly documented paused/resume state, and split the QR, camera, and re-pair observations into separate bugs.
