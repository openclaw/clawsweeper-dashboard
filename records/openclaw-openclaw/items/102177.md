## Summary

Keep open: current main still has APNs registration, push-test, wake, and exec-approval notification paths, but it does not turn normal assistant chat finals into native iOS APNs notifications, and background Talk still depends on a default-off keep-active preference or pause/resume behavior.

## What This Changes

Request native iOS APNs notifications for assistant messages plus a settled background Talk behavior or clear paused/resume state.

## Best Possible Solution

Define a dedicated privacy-safe assistant-reply APNs contract with generic default content, optional explicit preview opt-in, correct chat tap routing, foreground duplicate suppression, and live iOS proof; keep background Talk default-off or paused/resumable unless maintainers approve broader background audio.
