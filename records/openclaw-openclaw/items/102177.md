## Summary

Keep open: current main still has APNs registration, test push, wake, and exec-approval notification paths, but no end-to-end native iOS APNs path for assistant chat finals; background Talk remains a product/security decision around default-off background audio versus pause/resume behavior.

## What This Changes

Request APNs notifications for native iOS assistant messages and background or clearly resumable Talk mode behavior.

## Best Possible Solution

Define a dedicated privacy-safe assistant-reply APNs contract with generic default content, explicit preview opt-in if maintainers want it, correct chat tap routing, foreground duplicate suppression, and live iOS proof; keep background Talk paused/resumable by default unless maintainers approve broader background audio.

## Reproduction Assessment

No live iOS device reproduction was run, but source inspection is enough to reproduce the remaining gap: assistant chat finals broadcast to connected clients and node chat subscribers, while APNs sends are limited to push.test, node wakes, reconnect wakes, and exec-approval paths.

## Solution Assessment

Unclear until maintainers choose the notification privacy contract. The Gateway/iOS APNs layer is the right place for native alerts, but the best fix should add a chat-specific payload and routing design rather than reuse push.test or expose transcript text by default.
