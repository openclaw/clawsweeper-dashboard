## Summary

Keep open: current main still lacks a Gateway-owned APNs path for native iOS assistant-message notifications, and background Talk remains a product/privacy decision rather than a completed behavior. Source inspection shows existing APNs support is test/wake/exec-approval oriented, while Talk has a default-off background setting plus pause/resume behavior.

## What This Changes

Request native iOS APNs notifications for assistant replies and a policy-backed background Talk mode or clearer paused/resume behavior.

## Best Possible Solution

Define a dedicated privacy-safe assistant-reply APNs contract with generic default content, explicit preview opt-in if approved, correct chat tap routing, live iOS proof, and keep background Talk default-off or paused unless maintainers approve a broader background audio mode.
