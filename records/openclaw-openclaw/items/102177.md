## Summary

Keep open: current main and v2026.6.11 still do not wire ordinary assistant/webchat final replies to Gateway-initiated iOS APNs alerts, while the background Talk request is already partly covered by a default-off background listening toggle and paused/resume behavior.

## What This Changes

The issue requests native iOS APNs notifications for assistant messages and background-capable Talk mode, with separate QR scanner, camera shortcut, and re-pairing observations noted as follow-ups.

## Best Possible Solution

Define a privacy-safe assistant-reply APNs contract with generic default content, explicit preview opt-in if desired, per-gateway/session tap routing, iOS live proof, and keep the existing background Talk pause/keep-active behavior unless maintainers choose a broader Apple-policy-compliant audio mode.
