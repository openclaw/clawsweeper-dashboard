## Label Justifications

- `P2`: The issue affects stable iOS mobile chat and Talk ergonomics but is a privacy-sensitive feature gap rather than an urgent regression or release blocker.
- `impact:security`: Assistant-message APNs delivery needs an explicit privacy contract for relay payload content and lock-screen exposure.

- `maturity:stable`: The checked-in maturity scorecard marks ios-app as M4 Stable, including Chat and Sessions, Notifications and Background, and Voice areas affected by this issue.

## Summary

Keep open: current main still has APNs infrastructure for tests, node wakes, wake nudges, and exec approvals, but ordinary iOS assistant/webchat replies are not routed to native APNs notifications; the background Talk half is partly covered by existing pause/resume and default-off keep-active behavior, so the remaining work needs maintainer product and privacy direction.

## What This Changes

Request APNs push notifications for native iOS assistant/webchat replies and background Talk continuation or clearer pause/resume behavior.

## Best Possible Solution

Define a privacy-safe assistant-reply APNs contract with generic default content, explicit preview opt-in only if desired, per-gateway/session tap routing, iOS live proof, and keep the existing background Talk pause/keep-active behavior unless maintainers choose a broader Apple-policy-compliant audio mode.

Options:

- **Allow opt-in transcript previews:** Permit assistant reply text in APNs only behind a visible per-device or per-gateway privacy setting with tests and docs for lock-screen behavior.
- **Defer native chat pushes:** Keep relying on foreground app state and third-party channels until maintainers define a broader mobile notification policy.

No high-confidence live iOS reproduction was run. Source inspection supports the remaining gap: chat finals are broadcast to connected clients and node chat sessions, while Gateway APNs sends are limited to push.test, node wake/nudge, and exec-approval-style paths.

## Solution Assessment

Unclear until maintainers choose the notification privacy contract. The Gateway/iOS APNs layer is the right place for native alerts, but the best fix should add a chat-specific payload and routing design rather than reusing push.test or exposing transcript text by default.
