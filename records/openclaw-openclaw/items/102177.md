## Summary

Keep open: current main and v2026.6.11 still do not route normal assistant chat finals into a native iOS APNs alert, and background Talk remains a product/security-sensitive behavior rather than a settled always-on background-audio path.

## What This Changes

Request native iOS APNs notifications for assistant messages and either continued background Talk capture or a clear paused/resume state.

## Best Possible Solution

Define a dedicated privacy-safe assistant-reply APNs contract with generic default content, optional explicit preview opt-in, correct chat tap routing, foreground duplicate suppression, and live iOS proof; keep background Talk paused/resumable unless maintainers approve broader background audio.
