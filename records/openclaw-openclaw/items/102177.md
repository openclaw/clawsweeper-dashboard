## Summary

Keep open: current main still has APNs infrastructure for push tests, iOS wake/nudge, and exec approvals, but ordinary assistant/webchat final replies are still only broadcast to connected chat/node sessions and are not converted into native iOS APNs alerts. The background Talk request is partly covered by existing pause/resume and default-off background keep-active behavior, so the remaining work needs a privacy/product decision rather than an automatic fix PR.

## What This Changes

Request native iOS APNs notifications for assistant replies plus Apple-policy-compliant background Talk continuation or a clear paused/resume state.

## Best Possible Solution

Define a privacy-safe assistant-reply APNs contract with generic default content, explicit preview opt-in if maintainers want it, per-gateway/session tap routing, live iOS proof, and leave the existing background Talk pause/keep-active behavior in place unless maintainers approve a broader Apple-policy-compliant audio mode.
