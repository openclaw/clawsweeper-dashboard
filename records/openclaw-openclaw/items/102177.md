## Summary

Keep open: current main has iOS APNs registration, relay, test, wake, and exec-approval push plumbing, but it still does not turn assistant chat finals into native iOS APNs alerts; background Talk also remains a policy-sensitive opt-in or pause/resume behavior rather than a settled default.

## What This Changes

The issue requests native iOS APNs notifications for assistant webchat messages plus background Talk capture or a clear paused/resume state when iOS backgrounds the app.

## Best Possible Solution

Define a privacy-safe assistant-reply APNs contract with generic default content, explicit preview opt-in if approved, correct chat tap routing, and live iOS proof; keep background Talk paused/resumable unless maintainers approve broader background audio behavior.
