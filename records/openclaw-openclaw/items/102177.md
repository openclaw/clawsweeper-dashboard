## Summary

Keep open: current main and v2026.6.11 still do not turn assistant chat finals into native iOS APNs alerts, and background Talk remains a conservative opt-in or pause/resume behavior rather than a settled background-audio product path.

## What This Changes

The request asks for native iOS APNs notifications for assistant messages and background-safe Talk behavior or a clear paused/resume state.

## Best Possible Solution

Define a dedicated privacy-safe assistant-reply APNs contract with generic default content, explicit preview opt-in if desired, correct chat tap routing, and live iOS proof; keep background Talk default-off or paused/resumable unless maintainers approve broader background audio.

## Solution Assessment

Unclear until maintainers choose the notification privacy contract. The existing Gateway/iOS APNs layer is the right place for native alerts, but the best fix should add a chat-specific payload and routing design rather than reuse push.test or expose transcript text by default.
