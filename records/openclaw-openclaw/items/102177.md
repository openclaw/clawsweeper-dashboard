## Summary

Keep open: current main and v2026.6.11 have APNs registration, push.test, wake nudges, exec-approval pushes, and a default-off/paused background Talk path, but they still do not wire ordinary assistant/webchat replies to native iOS APNs alerts.

## What This Changes

Request for native iOS push notifications for assistant messages plus continued or clearly paused background Talk mode.

## Best Possible Solution

Define a privacy-safe chat-reply push contract with a dedicated payload kind, opt-in or generic alert content, iOS tap routing, per-gateway scoping, and live iOS proof while preserving the existing default-off/paused background Talk behavior.

Question: Should native iOS assistant-message notifications send generic alerts only, include assistant reply text behind an explicit opt-in, or stay unsupported until a broader mobile notification privacy model is approved?

Rationale: The missing APNs chat path is feasible with current push infrastructure, but the permanent payload kind, transcript-content policy, lock-screen behavior, and routing semantics are privacy-sensitive product choices that automation should not decide.

Likely owner: steipete

Owner confidence: medium

Options:

- **Approve generic chat alerts first (recommended):** Add a dedicated chat-reply APNs kind and iOS tap route with generic notification content by default, leaving transcript text for a later explicit opt-in.
- **Allow opt-in transcript previews:** Permit assistant reply text in APNs only behind a visible per-device or per-gateway privacy setting with tests and docs for lock-screen behavior.
- **Defer native chat pushes:** Keep relying on foreground app state and third-party channels until maintainers define a broader mobile notification policy.

## Solution Assessment

Unclear until maintainers choose the notification privacy contract. The APNs infrastructure is the right layer for native iOS alerts, but the maintainable fix needs a chat-specific payload/routing design instead of reusing the generic push.test sender or exposing transcript text by default.
