## Summary

Current main still has the reported routing mismatch: iOS chat operations scope unscoped keys to the selected agent, while patch, delete, and fork send raw keys that the gateway resolves against the default agent. Keep this issue open while the focused candidate fix at https://github.com/openclaw/openclaw/pull/103415 is reviewed and merged or rejected.

## What This Changes

Ensure iOS session delete, patch, and fork operations use the same selected-agent session-key normalization as chat send, history, and reset.

## Best Possible Solution

Rebase and review the linked pull request, retain one canonical `sessionTarget(for:)` path for every iOS chat and session operation, and keep instance-level request tests for unscoped, global, and already-scoped keys.
