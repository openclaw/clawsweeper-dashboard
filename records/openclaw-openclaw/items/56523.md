## Label Justifications

- `P2`: The issue affects cost telemetry accuracy for configured model pricing, with a narrow formatter fix and limited runtime blast radius.
- `impact:data-loss`: Unset cache pricing can silently suppress expected cost telemetry even when usage and other pricing data are available.

## Summary

Keep open: current main still accepts partial model cost config, preserves missing cache price fields in the shared cost formatter, and can produce an undefined estimated cost that diagnostics-otel cannot export. The linked fork PR is useful evidence but is still open outside openclaw/openclaw, so it does not close the upstream issue.

## What This Changes

The issue requests defaulting unset cost cache-read and cache-write pricing to zero so OpenTelemetry cost metrics are still emitted when other model pricing fields are configured.

## Best Possible Solution

Normalize missing cache price rates to zero at the shared pricing boundary and add regression coverage for a partial input/output-priced model plus diagnostics cost emission.

## Reproduction Assessment

Yes. Source inspection shows a schema-valid partial cost object can reach `normalizeModelCostConfig` unchanged and then make `estimateUsageCost` return undefined through a non-finite total; no runtime command was run because this review is read-only.

## Solution Assessment

Yes. Defaulting missing cache price rates at the shared pricing boundary is narrower and cleaner than adding an OTEL-only fallback or changing provider cache-token reporting.
