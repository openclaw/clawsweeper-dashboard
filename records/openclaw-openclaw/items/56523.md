## Label Justifications

- `P2`: The bug silently drops diagnostics cost telemetry for partial model pricing, but the blast radius is limited to reporting rather than core runtime availability.
- `impact:data-loss`: Expected cost metric data can be silently omitted even when usage and input/output pricing are otherwise present.

## Summary

Keep open: current main and v2026.6.11 still allow partial model cost pricing to make estimated cost undefined, which prevents diagnostics-otel from recording the cost counter. The linked fork PR is useful evidence, but it remains open outside upstream, so this issue is still the canonical upstream item.

## What This Changes

The issue requests defaulting missing `cacheRead` and `cacheWrite` pricing values to zero so diagnostics-otel cost metrics are not omitted.

## Best Possible Solution

Default missing flat cache price rates to zero at the shared model-cost normalization boundary, then cover both cost estimation and diagnostics exporter-facing cost emission with focused regression tests.

## Reproduction Assessment

Yes, source-reproducible: partial model cost config is accepted, missing cache rates stay undefined, `estimateUsageCost` returns undefined for the resulting non-finite total, and diagnostics-otel skips the cost metric when cost is absent.

## Solution Assessment

Yes. Defaulting missing cache price rates in the shared pricing path is narrower and more maintainable than an otel-only fallback because session, runtime, and exporter cost paths all share the estimator.
