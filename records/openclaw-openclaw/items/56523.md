## Summary

Keep open: current main still allows schema-valid partial model cost objects to reach the shared estimator with missing cache price rates, which can make `costUsd` undefined and leave diagnostics-otel without a cost counter sample. The issue is narrow and source-reproducible, but an open fork PR plus the existing no-new-fix-pr signal make this a maintainer-routing item rather than a new automated fix request.

## What This Changes

The issue asks OpenClaw to treat missing `cost.cacheRead` and `cost.cacheWrite` pricing fields as zero so cost telemetry is still emitted when input/output prices are present.

## Best Possible Solution

Normalize missing flat cache price rates to zero in the shared usage-format pricing boundary, keep provider cache-token semantics unchanged, and add focused regression coverage for partial cost objects reaching diagnostics `costUsd`.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level. A schema-valid cost object with input/output prices but omitted cache rates can reach `estimateUsageCost`, produce an undefined estimate, and leave diagnostics-otel with no `costUsd` to record.

## Solution Assessment

Yes. Defaulting omitted price rates at the shared pricing boundary is narrower and cleaner than changing provider cache-token reporting or adding an OTEL-only fallback.
