## Label Justifications

- `P2`: The issue affects cost telemetry completeness for configured models, but agent execution and core runtime availability continue to work.
- `impact:data-loss`: Expected cost telemetry can be silently omitted when partial pricing is accepted but later produces an undefined estimate.

## Summary

Keep open: current main and v2026.6.11 still allow partial model cost objects to make estimated cost undefined, so diagnostics-otel can skip the cost counter even when input/output pricing is present. The linked fork PR is useful evidence, but it is not an upstream OpenClaw PR and no same-repository PR currently owns the fix.

## What This Changes

Request defaulting omitted `cacheRead` and `cacheWrite` cost rates to zero so diagnostics OTEL still emits cost metrics for partial model pricing.

## Best Possible Solution

Normalize missing flat cache price rates to zero in the shared usage-format pricing boundary, keep provider usage counters unchanged, and add regression coverage for partial cost objects reaching diagnostics `costUsd`.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level. A schema-valid cost object with input/output prices but omitted cache rates reaches `estimateUsageCost`, can return undefined, and then diagnostics-otel has no `costUsd` to record; I did not run a live collector in this read-only review.

## Solution Assessment

Yes. Defaulting omitted cache price rates at the shared pricing boundary is narrower and cleaner than changing provider cache-token reporting or adding an OTEL-only fallback.
