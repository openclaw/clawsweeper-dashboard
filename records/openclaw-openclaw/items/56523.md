## Label Justifications

- `P2`: The source-reproducible bug can silently omit cost telemetry, but its blast radius is limited to diagnostics and cost reporting.
- `impact:data-loss`: Expected OpenTelemetry cost metric data can be silently dropped when cache cost rates are missing from otherwise usable model pricing.

## Summary

Keep open: current main and the latest release still accept partial model cost pricing, preserve missing cacheRead/cacheWrite rates, and can produce an undefined cost estimate, which makes diagnostics-otel skip the cost counter. The linked fork PR is useful evidence, but it remains open outside upstream and is not a merged fix path.

## What This Changes

The issue asks to treat omitted cacheRead/cacheWrite model pricing as zero so OpenTelemetry cost metrics continue to emit when input/output prices are present.

## Best Possible Solution

Default missing cacheRead/cacheWrite rates to zero at the shared model-cost normalization boundary, then add focused regression coverage for estimateUsageCost and diagnostics exporter-facing costUsd behavior while avoiding unrelated fork-branch churn.

## Reproduction Assessment

Yes, source-reproducible: current main accepts partial cost config, preserves omitted cache rates, and returns undefined cost for the resulting non-finite estimate. I did not run a live OTEL collector in this read-only review.

## Solution Assessment

Yes. Defaulting missing cache price rates at shared model-cost normalization is the narrow maintainable fix; an OTEL-only fallback would leave other cost consumers with the same undefined-estimate behavior.
