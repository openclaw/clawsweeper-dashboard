## Label Justifications

- `P2`: The bug silently suppresses cost telemetry for partial pricing config, but the blast radius is limited to diagnostics and cost reporting.
- `impact:data-loss`: Expected cost telemetry can be silently omitted even when usage tokens and input/output prices are available.

## Summary

Keep open: current main still lets schema-valid partial model pricing omit cache rates, which makes shared cost estimation return undefined and leaves diagnostics-otel without a cost metric to export.

## What This Changes

The issue asks for missing `cost.cacheRead` and `cost.cacheWrite` pricing fields to default to zero so OpenTelemetry cost metrics are still emitted.

## Best Possible Solution

Normalize missing cache price rates to zero at the shared model-cost boundary and add focused regression coverage for partial input/output-only pricing reaching diagnostics cost export.

## Reproduction Assessment

Yes. A schema-valid partial cost object with input/output only reaches `estimateUsageCost`, where `0 * undefined` for missing cache rates makes the total non-finite and causes `costUsd` to be omitted from `model.usage`.

## Solution Assessment

Yes. Defaulting missing cache price rates at the shared pricing normalization boundary is narrower than adding an OTEL-only fallback, because sessions, plugin runtime usage, and diagnostics all share that estimator.
