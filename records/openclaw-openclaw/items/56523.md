## Label Justifications

- `P2`: The bug silently drops cost telemetry for partial model pricing, but agent execution and the core runtime continue to operate.
- `impact:data-loss`: Expected cost metric data can be silently omitted even when usage and input/output pricing are otherwise available.

## Summary

Keep open: current main and the latest release still preserve missing cache price rates in shared model-cost normalization, which can make estimated cost undefined and suppress diagnostics-otel cost emission. The linked fork PR is useful evidence, but it is still open outside upstream, so this issue remains necessary.

## What This Changes

The issue asks for missing `cost.cacheRead` and `cost.cacheWrite` values to default to zero so OpenTelemetry cost metrics are emitted instead of silently omitted.

## Best Possible Solution

Default missing cache price rates to zero at the shared model-cost normalization boundary and cover both cost estimation and diagnostics exporter-facing cost emission.

## Reproduction Assessment

Yes. Source inspection shows partial model cost config is accepted, current cost normalization preserves missing cache rates, `estimateUsageCost` returns undefined for the resulting non-finite total, and diagnostics-otel skips the cost counter when cost is undefined.

## Solution Assessment

Yes. Defaulting missing cache price rates at the shared pricing boundary is narrower and more maintainable than adding an OTEL-only fallback or changing provider cache-token semantics.
