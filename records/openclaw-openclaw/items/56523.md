## Label Justifications

- `P2`: The bug silently drops cost telemetry for partial model pricing, but the blast radius is limited to diagnostics and cost reporting.
- `impact:data-loss`: Expected cost metric data can be silently omitted even when usage and input/output pricing are otherwise available.

## Summary

Keep open: current main and the latest release still allow partial model cost pricing to make estimated cost undefined, which prevents diagnostics-otel from recording the cost counter. The linked fork PR is useful evidence, but it is still open outside upstream, so the upstream issue remains necessary.

## What This Changes

The issue requests defaulting missing `cacheRead` and `cacheWrite` cost inputs to zero so diagnostics OTEL cost metrics still emit.

## Best Possible Solution

Default missing cache price rates to zero at the shared model-cost normalization boundary and cover both cost estimation and diagnostics exporter-facing cost emission.

## Reproduction Assessment

Yes, source-reproducible: partial model cost config is accepted, current cost normalization preserves missing cache rates, `estimateUsageCost` returns undefined for the resulting non-finite total, and diagnostics OTEL skips the cost counter when cost is undefined. I did not run a live OTEL collector in this read-only review.

## Solution Assessment

Yes. Defaulting missing cache price rates at the shared pricing boundary is narrower and more maintainable than adding an OTEL-only fallback or changing provider cache-token semantics.
