## Label Justifications

- `impact:data-loss`: A valid cost estimate can be silently dropped from telemetry when optional cache price rates are missing.

## Summary

Keep open: current main and v2026.6.11 still multiply usage by possibly undefined cache pricing rates from raw model pricing, so a partial cost definition can drop costUsd before diagnostics-otel records cost.

## What This Changes

The issue asks for missing cacheRead/cacheWrite pricing rates to default to zero so diagnostics cost metrics are still emitted.

## Best Possible Solution

Normalize absent cache pricing rates to zero in the shared cost estimator or raw cost normalization path, then add focused regression coverage for partial pricing flowing to diagnostics costUsd.
