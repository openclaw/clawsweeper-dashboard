## Label Justifications

- `P2`: The bug silently drops cost telemetry for partial model pricing, but the blast radius is limited to diagnostics and cost reporting.
- `impact:data-loss`: Expected cost metric data can be silently omitted even when usage and input/output pricing are otherwise available.

## Summary

Keep open: current main and v2026.6.11 still allow partial model pricing to make estimated cost undefined, which prevents diagnostics-otel from recording the cost counter. The linked fork PR is useful evidence, but it is still open outside upstream and is not a safe close target.

## What This Changes

Request defaulting missing `cost.cacheRead` and `cost.cacheWrite` pricing fields to zero so diagnostics-otel continues reporting cost metrics.

## Best Possible Solution

Default omitted `cacheRead` and `cacheWrite` price rates to zero at the shared model-cost normalization or estimation boundary, then cover cost estimation and diagnostics exporter-facing cost emission with focused regression tests.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: partial model cost config is accepted, missing cache rates remain undefined, `estimateUsageCost` returns undefined for the non-finite total, and diagnostics-otel skips the cost counter when `costUsd` is absent.

## Solution Assessment

Yes. Defaulting missing cache price rates in the shared pricing path is narrower and more maintainable than adding an OTEL-only fallback or changing provider cache-token semantics.
