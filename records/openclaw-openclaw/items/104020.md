## Summary

This remains necessary because both v2026.6.11 and current main contain the reported takeover and bounded give-up paths. Current main already reconciles several benign transcript changes, so the issue overstates the lock as universally fail-fast, but deterministic proof is still needed for the narrower claim that concurrent writers can exhaust retries and discard a contract-required successful completion.

## What This Changes

Prevent concurrent embedded-session writers from causing repeated takeover conflicts and loss of contract-required subagent completion delivery.

## Best Possible Solution

Preserve merge-aware prompt lock release, add a deterministic competing-writer regression that asserts transcript integrity and delivery state, and durably retain every completion required by the requester contract until delivery is acknowledged.
