## Summary

Keep open: current main and the latest release still have the equality-only memoryFlush guard, and the open linked PR is the active candidate for the exact 0/0 counter fix.

## What This Changes

The issue reports that `memoryFlush` is skipped for never-compacted sessions when `compactionCount` and `memoryFlushCompactionCount` are both `0`.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/83015, or an equivalent narrow guard that distinguishes real cycle-0 flushes from never-flushed 0/0 rows using existing session metadata.

## Reproduction Assessment

Yes, at source level: current main returns true for a 0/0 memory-flush counter state and `runMemoryFlushIfNeeded` uses that helper to skip flushing. I did not run a live over-threshold session in this read-only review.

## Solution Assessment

Yes, the linked PR's `memoryFlushAt` discriminator is the narrowest maintainable fix for this specific false positive. Broader preflight and context-budget issues should remain separate work.
