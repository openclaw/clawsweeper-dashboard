## Summary

Keep this maintainer-tracked performance issue open: current main still eagerly imports page-owned styles into the entry stylesheet, while the existing lazy-view architecture and Vite contract support the proposed route-level split.

## What This Changes

Load page-owned Control UI styles from their lazy route modules while keeping shell, shared component, approval, and Markdown styles eager.

## Best Possible Solution

Keep only shell-wide and genuinely shared rules eager, import each page stylesheet from its lazy view boundary, and enforce the split with production-asset assertions plus mocked browser navigation and visual coverage.

Required: false

## Reproduction Assessment

Yes from source: current main imports all page styles through the eager entry stylesheet while page JavaScript already has a lazy-module boundary. The reported approximately 580 KB production asset size was not independently rebuilt during this read-only review.

## Solution Assessment

Yes. Using the existing lazy module boundary and Vite's native CSS splitting is narrower and more maintainable than adding a stylesheet registry or manual link lifecycle.
