## Summary

Current main still rejects valid local `file://` image sources because the gateway authorizes the resolved filesystem path but sends the original URI to a path-or-HTTP storage API. The linked fix PR directly owns this issue, so it should remain open until that PR is reviewed and merged.

**Likely related people**
- @obviyus — high confidence; introduced and most recently maintained this newly added managed-image path.

## What This Changes

Allow managed outgoing image preparation to ingest valid local `file://` sources the same way as equivalent absolute paths.

## Best Possible Solution

Land a focused change that carries the already-resolved local path through metadata, policy validation, and storage ingestion while retaining local-root enforcement and source-metadata redaction.
