## Summary

This PR fixes the Firecrawl-local signal loss, but it does not fully stop canceled searches: during implicit provider selection, the shared runtime catches the resulting abort and can start another provider. The branch therefore needs the shared terminal-abort guard already proposed in the related SearXNG work, plus real request-path proof before merge.

## What This Changes

The PR forwards the web-search execution AbortSignal through the Firecrawl provider and client into guarded HTTP fetches and adds a mocked signal-handoff test.

## Best Possible Solution

Retain the Firecrawl-owned signal propagation, land one canonical shared runtime guard that makes an aborted parent signal terminal, and prove that a held request closes without invoking a fallback provider.
