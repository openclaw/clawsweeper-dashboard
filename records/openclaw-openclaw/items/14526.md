## Summary

Keep open: current main and v2026.6.11 have update, backup, health, doctor, and manual rollback primitives, but not the requested opt-in safe-update transaction with update-tied snapshots, retention, real channel/agent smoke checks, and automatic package plus state restore.

## What This Changes

Request an optional safe-update workflow that backs up OpenClaw state before updating, runs health or smoke checks after updating, and rolls back or restores state on failure.

## Best Possible Solution

Make an explicit maintainer product decision on a default-off core safe-update mode; if accepted, orchestrate existing update, backup, doctor/status, health, channel-status, and package rollback primitives with retention and secret-safe restore guarantees.
