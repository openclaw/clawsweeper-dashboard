## Summary

Keep open: current main and v2026.6.11 have adjacent update, backup, doctor, restart-health, and manual rollback primitives, but not the requested opt-in safe-update transaction with update-tied full-state snapshots, retention, real channel/agent smoke checks, and automatic package plus state restore.

## What This Changes

The issue requests an opt-in safe-update workflow with pre-update state backup, post-update health/smoke checks, and rollback or restore on failed checks.

## Best Possible Solution

Keep this as a maintainer-owned core updater design item; if accepted, implement a default-off updater mode that orchestrates existing update, backup, doctor/status/health, channel probe, and rollback primitives with explicit retention and secret-safe restore guarantees.
