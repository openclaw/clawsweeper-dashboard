## Summary

Keep open: this PR is not merge-ready because the heartbeat wiring is ineffective on the reported path and lacks real behavior proof. The stronger candidate is https://github.com/openclaw/openclaw/pull/95536, but this PR is paired with the same contributor's still-open canonical issue at https://github.com/openclaw/openclaw/issues/94124, so conservative cleanup should not close only this side without maintainer action.

## What This Changes

Adds an AbortSignal-keyed tool-activity heartbeat, subscribes the embedded-runner LLM idle watchdog to it, and notifies after Tool Search catalog executor calls complete.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/95536 or an equivalent runId-scoped heartbeat with persisted activity, direct/deferred tool coverage, tests, and real subagent proof; if maintainers prefer this branch, it should be reworked to that shape first.

## Reproduction Assessment

Yes, for the PR defects at source level: the signal keys differ, the notification is not persisted across stream waits, and direct tools use the shared agent-core execution path. I did not run a live subagent timeout reproduction in this read-only review.

## Solution Assessment

No. The owner boundary is plausible, but this implementation is not the best fix because it does not use one lifecycle key, does not bridge tool activity across provider waits, and does not cover shared direct-tool execution.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Use the same lifecycle key for heartbeats:** `src/agents/embedded-agent-runner/run/llm-idle-timeout.ts:299`
  - body: `onToolActivity` is registered with `streamAbortController.signal`, but `notifyToolActivity` is called with `runAbortController.signal`. Because the new listener map is keyed by `AbortSignal`, the notification will not reach `armTimer()` on the reported timeout path.
  - confidence: 0.95
- **[P1] Persist tool activity across provider waits:** `src/agents/embedded-agent-runner/run/attempt.ts:3678`
  - body: The notifier fires after a cataloged tool finishes, but the previous provider stream listener may already be cleaned up and the next provider wait has not registered its listener yet. Store run-scoped last-activity state instead of relying on a one-shot event.
  - confidence: 0.88
- **[P2] Emit heartbeats from shared tool execution:** `src/agents/embedded-agent-runner/run/attempt.ts:3678`
  - body: This adds the heartbeat only inside the Tool Search catalog executor, while normal direct tools execute through agent-core's shared `executePreparedToolCall` path. Reported tools such as `read` and `exec` can bypass the heartbeat unless the shared path is wired or proved irrelevant.
  - confidence: 0.84
