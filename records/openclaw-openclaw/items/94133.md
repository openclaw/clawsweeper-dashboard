## Summary

Keep open: this focused bug-fix PR is still not merge-ready because the heartbeat is wired to the wrong lifecycle key, can be dropped between stream waits, misses the shared direct-tool execution path, and has no real after-fix subagent proof. The proof-positive sibling at https://github.com/openclaw/openclaw/pull/95536 is relevant, but it is still open and currently reported as conflicting, so it is not a safe supersession close target yet.

## What This Changes

The PR adds an AbortSignal-keyed tool-activity heartbeat module, subscribes the embedded-runner LLM idle watchdog to it, and emits notifications after Tool Search catalog tool calls.

## Best Possible Solution

Rework the heartbeat around runId-scoped persistent activity emitted from the shared tool execution boundary, add focused idle-timeout coverage, and provide redacted real subagent proof; alternatively let a mergeable proof-positive sibling land first.

## Reproduction Assessment

Yes, for the PR defects at source level: the listener/notifier key mismatch, stream-wait lifecycle gap, and direct-tool bypass are visible from the patch and current main. I did not run a live subagent timeout reproduction in this read-only review.

## Solution Assessment

No. The direction is plausible, but this implementation is not the best fix because it is signal-keyed, transient, and hooked to a catalog side path instead of persistent run-scoped activity at the shared tool boundary.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Use one lifecycle key for tool heartbeats:** `src/agents/embedded-agent-runner/run/llm-idle-timeout.ts:299`
  - body: `onToolActivity` subscribes with `streamAbortController.signal`, but the notifier calls `notifyToolActivity(runAbortController.signal)`. Because the new listener map is keyed by `AbortSignal`, the notification will not reach `armTimer()` on the reported timeout path.
  - confidence: 0.95
- **[P1] Persist tool activity across stream waits:** `src/agents/embedded-agent-runner/run/attempt.ts:3678`
  - body: The notification fires after the cataloged tool finishes, but the previous provider stream listener has already been cleaned up and the next provider wait has not registered yet. A one-shot event can be dropped instead of refreshing the first post-tool idle budget.
  - confidence: 0.88
- **[P2] Emit heartbeats from shared tool execution:** `src/agents/embedded-agent-runner/run/attempt.ts:3678`
  - body: This only notifies inside the Tool Search catalog executor. Normal direct tools execute through `packages/agent-core/src/agent-loop.ts`'s shared `executePreparedToolCall` path, so read/exec-style tools can still bypass the heartbeat.
  - confidence: 0.84
