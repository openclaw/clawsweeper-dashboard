## Summary

Keep open: the underlying subagent timeout bug remains real, but this branch is not merge-ready because the heartbeat can miss the registered listener, can be dropped between stream lifecycles, only covers the Tool Search catalog executor, and has no after-fix real subagent proof. A newer sibling fix is stronger, but the paired canonical issue remains open until a fix merges.

## What This Changes

This PR adds a signal-keyed tool-activity heartbeat, subscribes the embedded-runner LLM idle watchdog to it, and notifies after Tool Search catalog executor tool completions.

## Best Possible Solution

Use a run-scoped persistent activity signal at the shared tool execution boundary, with focused direct/cataloged tool coverage and redacted real subagent proof; maintainers can also choose to land the stronger sibling implementation at https://github.com/openclaw/openclaw/pull/95536 instead.

## Solution Assessment

No. The direction is plausible, but this implementation is too narrow and lifecycle-fragile; a runId-scoped persistent heartbeat at the shared tool execution boundary is the safer fix shape.

  - body: The notifier fires after a cataloged tool finishes, but the provider stream listener has already been cleaned up and the next stream wait has not registered its listener yet. This drops the activity instead of recording it for the first post-tool provider wait.
  - confidence: 0.88
