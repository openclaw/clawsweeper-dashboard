## Summary

This PR should not merge as written: LM Studio distinguishes native tool training from tool availability, so translating `trained_for_tool_use: false` into `supportsTools: false` would disable an existing fallback tool mode rather than accurately describe the server capability.

## What This Changes

The PR maps LM Studio’s `trained_for_tool_use` discovery field into `compat.supportsTools` and adds unit coverage for true, false, and omitted metadata.

## Best Possible Solution

Preserve tool availability for `trained_for_tool_use: false`; if OpenClaw needs to distinguish LM Studio’s native and default tool modes, model that distinction with separate provider-owned metadata and live behavior coverage rather than `supportsTools`.
