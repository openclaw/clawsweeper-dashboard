## Summary

Keep open: current main has source-side reply-session conflict fixes, but restart recovery still lacks an explicit boot-session ownership guard, so the reported post-restart WebChat boot takeover path is not proven fixed.

## What This Changes

The issue reports that WebChat direct restart recovery can route later direct user turns into an `agent:main:boot` recovery session after a gateway restart while `agent:main:main` fails during reply-session initialization.

## Best Possible Solution

Define and test the boot-session ownership rule so restart recovery cannot preserve or resume user-facing WebChat direct route ownership for `agent:main:boot`, while leaving the generic v2026.6.11 reply-init package defect tracked separately.

## Reproduction Assessment

Partially yes: the reporter provided detailed v2026.6.11 field evidence, and current source still shows the boot-session exclusion gap in restart recovery. I did not reproduce the full macOS launchd/WebChat misrouting path live.

## Solution Assessment

Unclear: the likely implementation is small, but maintainers should first choose the durable boot-session ownership rule and then add focused restart-recovery/WebChat regression coverage.
