## Summary

Keep open for maintainer review: current main still lacks the active target exec-ref skip, and the PR appears to implement the focused fix with coverage, but it changes the auth/security boundary by resolving active exec-backed command targets locally before attempting the gateway snapshot RPC.

## What This Changes

The PR extends `resolveCommandSecretRefsViaGateway` to skip gateway `secrets.resolve` for active exec-backed command target SecretRefs and adds regression tests for active, inactive, and no-local-exec cases.

## Best Possible Solution

Land this focused resolver change only if maintainers accept active exec-backed command targets as local-resolution triggers; otherwise rework toward preserving gateway-first snapshot behavior while suppressing the expected log noise.

## Reproduction Assessment

Yes, at source level: current main routes queued replies through `resolveCommandSecretRefsViaGateway` with agent-runtime targets that include `models.providers.*.apiKey`, while the existing pre-skip only covers gateway credential exec refs. I did not run a live gateway turn in this read-only review.

## Solution Assessment

Yes, if maintainers accept the boundary: the shared command-secret resolver is the narrow layer, and the PR filters to active refs while honoring no-local-exec policy. The safer alternative is a gateway-first rework that only suppresses the expected noisy failure path.
