## What This Changes

Extends `resolveCommandSecretRefsViaGateway` to bypass `secrets.resolve` for active exec-backed command target SecretRefs and adds regression tests for active, inactive, and no-local-exec cases.

## Best Possible Solution

Land this focused resolver change only after maintainers accept active exec targets as local-resolution triggers; keep the diagnostic-visibility ask on https://github.com/openclaw/openclaw/issues/96653 or a narrower follow-up if needed.

## Reproduction Assessment

Yes at source level: current main routes queued replies through `resolveCommandSecretRefsViaGateway` with agent-runtime targets that include model-provider credentials, while the existing pre-skip only covers gateway credential exec refs. I did not run tests or a live gateway turn because this review is read-only.

## Solution Assessment

Yes for the focused log-flood bug if maintainers accept the auth/security boundary: the shared command-secret resolver is the right layer, and the PR filters to active refs while honoring no-local-exec policy. A safer alternative, if snapshot-first behavior must be preserved, is a gateway partial-result or targeted fallback rework.
