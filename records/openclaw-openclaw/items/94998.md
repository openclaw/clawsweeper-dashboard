Close: current main implements the central provider-side AbortError fallback path, with regression coverage proving the fallback candidate runs when the provider throws `AbortError("This operation was aborted")`; the fix is current-main-only and is not in v2026.6.11.

## What This Changes

The issue reports that provider transport AbortError timeouts with message "This operation was aborted" are not recognized as timeouts, so configured model fallbacks are skipped.

## Best Possible Solution

Keep the current-main runtime fallback behavior from the merged provider-side AbortError fix; users need a build after v2026.6.11 for this exact fix.
