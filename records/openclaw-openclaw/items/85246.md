## Summary

Keep open. Two live macOS npm-global LaunchAgent reports show update-triggered restarts can still leave the Gateway unhealthy or offline after the earlier merged hardening; the assigned maintainer explicitly kept this issue open pending direct proof of the UI/latest-version path. The remaining question is the product contract for no-op/failed update handoff, not another isolated launchd race patch.

## What This Changes

The issue requests that Control UI `update.run` avoid or safely recover from a managed launchd handoff when an npm-global Gateway is already current or update recovery fails.

## Best Possible Solution

Define one explicit managed-update result contract: prove no package change before stopping the LaunchAgent when possible, otherwise report final handoff health accurately and recover a missing launchd service through the canonical service-install/restart path.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For a managed npm-global LaunchAgent Gateway, should an update with no version change return before restart, refuse UI-managed execution with a clear recovery action, or retain a durable handoff that reports final service health?

Rationale: The reports establish real failure modes, but choosing between no-op short-circuiting, explicit refusal, and durable recovery changes the public update and operator-recovery contract.

Likely owner: vincentkoc

Owner reason: They are assigned and previously framed the exact pending product/restart-contract decision.

Owner confidence: high

Options:

- **Short-circuit proven no-op updates (recommended):** Return without stopping the Gateway only when package resolution proves the installed version will not change, while preserving handoff for real upgrades.
- **Refuse managed UI handoff:** Return an explicit unsupported or recovery-required result for this install/service shape instead of attempting a potentially unsafe handoff.
- **Strengthen durable handoff:** Keep managed handoff but require launchd bootstrap recovery and final health confirmation before reporting success.

## Solution Assessment

Unclear — short-circuiting a proven no-op is the narrowest candidate, but maintainers must first choose whether failed/indeterminate managed updates should refuse, hand off durably, or use a separate recovery contract.
