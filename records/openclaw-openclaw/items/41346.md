## Label Justifications

- `P1`: The issue reports a source-reproducible background cron path that can rapidly consume real provider quota under normal user configuration.
- `impact:security`: External/plugin scheduling provenance and enabled-by-default recurring jobs are a security boundary for persistent unattended model execution.
- `impact:auth-provider`: The affected jobs inherit provider/model defaults and can consume or exhaust auth-provider quota without an explicit per-job model or guard.
- `impact:ux-friction`: Users currently need manual cron/config/usage inspection to discover and stop unintended background model spend.

## Summary

Keep open. Current main still has source-reproducible paths where plugin/external cron creation can persist enabled recurring `agentTurn` jobs without a per-job model, inherit configured agent/default models, and use recurring backoff rather than billing/auth/quota circuit breaking.

## What This Changes

The issue asks OpenClaw to stop externally or plugin-registered model-backed cron jobs from silently enabling, inheriting expensive default models, and running without quota or cost guardrails.

## Best Possible Solution

Define the cron trust/provenance policy first, then require explicit activation or confirmation plus model/cost safeguards for externally scheduled recurring `agentTurn` jobs while tracking broader circuit breaker and budget work in the related open issues.
