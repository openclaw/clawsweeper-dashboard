## Summary

Keep open. Current main and the latest release still default omitted cron enablement to on, agentTurn cron jobs without payload.model still inherit configured agent defaults, and the remaining consent, provenance, model-cost, and quota circuit-breaker behavior needs maintainer security/product direction.

## What This Changes

The issue requests safer handling for externally registered recurring cron jobs: default-disabled or confirmed activation, model-cost warnings, dry-run diffs, and quota circuit breakers.

## Best Possible Solution

Adopt a maintainer-approved cron provenance and consent policy that keeps trusted operator-authored cron compatible while making externally or declaratively registered recurring agentTurn jobs pending/disabled until explicitly enabled with an explicit model/cost posture.
