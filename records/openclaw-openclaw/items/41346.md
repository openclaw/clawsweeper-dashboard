## Summary

Keep open. Current main still lets new external/plugin/agent cron registrations create enabled model-backed recurring jobs and still resolves agentTurn crons without payload.model through the configured agent/default model, while existing usage reporting, retries, and failure alerts do not provide the requested activation, model-cost, or quota circuit breaker policy.

## What This Changes

The issue asks OpenClaw to add confirmation, disabled-by-default activation, model-cost guards, dry-run visibility, and usage circuit breakers for externally registered model-backed cron jobs.

## Best Possible Solution

Maintainers should define one cron safety policy that distinguishes operator-authored, plugin-registered, and future agent-authored schedules, then add provenance, activation preview, explicit model/cost visibility, and budget/circuit-breaker behavior with upgrade-safe doctor handling.
