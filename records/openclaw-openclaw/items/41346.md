## Label Justifications

- `P1`: The issue reports source-reproducible unattended model-backed cron execution that can burn real user quota or spend during normal installed usage.

## Summary

Keep open. Current main and v2026.6.11 still allow externally or plugin-created cron jobs to run enabled, inherit agent/default model selection when no job model is set, and rely on retry/backoff rather than the requested consent, provenance, model-cost, and quota guardrails.

## What This Changes

Require consent and cost guardrails for externally or plugin-registered recurring cron jobs that otherwise auto-enable and inherit agent/default models.

## Best Possible Solution

Adopt a maintainer-approved cron safety design that covers external/plugin schedule provenance, operator activation or confirmation, explicit model/cost visibility, doctor/update dry-run reporting, and quota/cost pause semantics across the related issues.
