## Summary

Keep open. Current main and the latest release still allow cron jobs to be created enabled by default, plugin scheduled turns still register enabled recurring `agentTurn` jobs without a payload model, model selection can fall through to configured defaults, and the related issues cover only narrower slices of the consent, provenance, model-cost, and circuit-breaker problem.

## What This Changes

The issue requests guardrails so external or plugin-registered cron jobs do not silently enable recurring model-backed work, inherit expensive defaults, or run without usage limits.

## Best Possible Solution

Define one cron safety policy for externally or plugin-registered recurring `agentTurn` jobs covering operator-visible activation, non-forgeable provenance, explicit model or cost-warning behavior, doctor/update visibility, and quota-aware pause or notification semantics.
