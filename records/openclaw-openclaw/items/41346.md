## Summary

Keep open. Current main and the latest release still allow omitted cron enablement to become active by default, bundled plugin scheduled turns explicitly register enabled model-backed jobs without a job model, and the remaining consent, cost, provenance, and quota policy needs maintainer security/product direction.

## What This Changes

The issue asks OpenClaw to require explicit activation or guardrails for externally registered recurring cron jobs so they do not silently run on expensive inherited model defaults without usage protection.

## Best Possible Solution

Define one maintainer-approved cron safety policy covering registration provenance, activation consent, explicit model or cost-warning behavior, update/doctor visibility, and quota-aware pause/notification semantics.
