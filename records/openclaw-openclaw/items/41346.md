## Summary

Keep open. Current main still has source-reproducible cron paths where plugin or external scheduling can create enabled recurring agentTurn jobs without an explicit job model or cost circuit breaker, and the remaining fix needs maintainer security/product policy rather than conservative cleanup.

## What This Changes

The issue requests safer handling for externally registered cron jobs so they do not auto-enable, silently inherit expensive agent defaults, or run without cost/quota guardrails.

## Best Possible Solution

Define a coordinated cron safety policy that distinguishes operator-authored, plugin-registered, and future agent-authored schedules, then add explicit activation/provenance, model-cost visibility, and upgrade/doctor handling for recurring model-backed jobs.
