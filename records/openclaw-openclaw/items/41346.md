## Summary

Keep open. Current main and the latest release still allow plugin/external cron creation paths to create enabled recurring model-backed jobs without an explicit job model, and the remaining consent, provenance, cost-guard, and circuit-breaker behavior needs maintainer security/product direction.

## What This Changes

The issue requests cron safety guardrails so externally or plugin-registered recurring jobs do not auto-enable and run expensive inherited models without operator confirmation or usage protection.

## Best Possible Solution

Define one maintainer-approved cron safety policy covering external/plugin registration provenance, activation consent, explicit model or model-cost warning behavior, update/doctor visibility, and quota-aware pause/notification semantics.
