## Summary

Keep open. Current main still allows model-backed cron jobs created through plugin/cron APIs to become enabled immediately and inherit default model selection when no job model is set, while the requested consent, provenance, cost guard, and circuit-breaker policy remains unresolved.

## What This Changes

Request explicit activation/confirmation and cost guardrails for externally or plugin-registered cron jobs so they do not silently run expensive inherited models.

## Best Possible Solution

Decide a coordinated cron safety policy covering non-operator/plugin provenance, explicit activation or confirmation, explicit model/cost defaults, doctor/update visibility, and linkage to budget/circuit-breaker work.
