## Summary

Keep open. Current main and the latest release still default new cron jobs to enabled, bundled plugin scheduled turns explicitly create enabled model-backed cron jobs without a payload model, missing cron payload models can inherit the configured default model, and recurring failures still use generic backoff rather than the requested consent, cost, provenance, and quota guardrails.

## What This Changes

The issue requests default-disabled or user-confirmed external cron registration, explicit model-cost safeguards, update/doctor dry-run diffs, and usage circuit breakers for model-backed polling jobs.

## Best Possible Solution

Define a coordinated cron safety policy for externally registered recurring model-backed jobs that covers explicit activation consent, provenance, model-cost defaults, doctor/update previews, and budget or circuit-breaker behavior across cron, plugin, protocol, docs, and UI surfaces.
