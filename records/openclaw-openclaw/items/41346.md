## Label Justifications

- `P1`: The issue reports real quota/cost burn from recurring background cron model calls and current source still permits that workflow without consent or circuit breaking.
- `impact:security`: Externally or agent-declared persistent schedules can be created and run without a non-forgeable provenance or explicit activation policy.
- `impact:auth-provider`: Cron agent-turns without an explicit payload model can inherit the configured agent/default provider model, including expensive or quota-sensitive profiles.

## Summary

Keep open. Current main and the latest release still default omitted cron `enabled` values to active, document the agent cron-tool default as true, let isolated agent-turn jobs without `payload.model` fall through to stored session or agent/default model selection, and only provide generic retry/backoff rather than consent, provenance, model-cost admission, or usage circuit breakers.

## What This Changes

Requests scheduler safety guardrails for external or declarative cron registrations so jobs do not auto-enable, inherit expensive default models, or run without cost/provenance circuit breakers.

## Best Possible Solution

Define a maintainer-approved scheduler-safety contract for external/declarative cron registration: explicit activation or confirmation, provenance/ownership, safe model selection or warnings, dry-run/doctor update diff, usage or budget circuit breakers, and matching protocol/state/docs/tests/migrations.
