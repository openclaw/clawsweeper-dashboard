## Label Justifications

- `P1`: The issue describes current background cron paths that can start recurring model-backed work and burn provider quota without operator confirmation.
- `impact:security`: Externally or plugin-created recurring schedules are a persistent execution surface without a confirmed consent/provenance guard.
- `impact:auth-provider`: Cron model selection falls through to agents.defaults.model when payload.model is absent, directly affecting provider/model choice and quota spend.

## Summary

Keep open. Current main and the latest release still allow plugin/external cron creation paths to create enabled recurring agent-turn jobs without a payload model, so those runs can inherit the configured default model and there is no quota/spend circuit breaker that covers the reported cost failure.

## What This Changes

Request that externally or plugin-registered recurring cron jobs require explicit activation and model/spend safeguards instead of auto-enabling and inheriting the global model without cost controls.

## Best Possible Solution

Adopt a maintainer-approved cron safety policy that gates external/plugin-created recurring agentTurn jobs behind operator consent, requires explicit model or cost-aware warnings, and leaves broader quota/budget enforcement tracked by the related guardrail issues.

- **Keep enabled but warn loudly:** Preserve existing enabled-by-default compatibility and add doctor/status/run warnings for inherited expensive models, accepting that jobs can still run before acknowledgement.
- **Defer to scheduling RFC:** Leave this issue open only as input to the broader non-forgeable scheduling API and avoid changing current cron defaults until that design lands.

Yes. Source inspection on current main shows create defaults and plugin scheduled turns create enabled agentTurn jobs, and model selection falls through to the configured agent/default model when no payload model is set.

## Solution Assessment

No current implementation is not the best end state because it only provides explicit model overrides, diagnostics, and transient retry backoff. The maintainable fix needs a compatibility-aware product/security decision across cron creation, plugin scheduling, doctor/update surfaces, and spend guardrails.
