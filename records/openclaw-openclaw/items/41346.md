## Summary

Keep open. Current main and the latest release still support the reported cron safety gap: new cron jobs default enabled, plugin scheduled turns create enabled recurring agentTurn jobs without an explicit model, missing payload models resolve from configured defaults, and recurring failures back off rather than applying consent, provenance, spend, or quota guardrails.

## What This Changes

Externally or plugin-registered recurring cron jobs should not silently start model-running work on inherited expensive defaults without operator consent, cost visibility, provenance, and usage guardrails.

## Best Possible Solution

Define one maintainer-approved cron safety policy covering external/plugin registration provenance, activation consent, explicit model or model-cost warning behavior, update/doctor visibility, and quota-aware pause or notification semantics.
