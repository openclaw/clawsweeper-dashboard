## Summary

Keep open. Current main and the latest release still allow bundled plugin scheduling to create enabled Cron-backed agent turns without an explicit model, so the core consent, provenance, model-cost, and quota-guardrail problem remains.

## What This Changes

The issue asks OpenClaw to add consent, provenance, model-cost, dry-run, and usage circuit-breaker safeguards for externally or plugin-registered recurring cron jobs.

## Best Possible Solution

Define a core scheduling policy where externally or plugin-created recurring agentTurn jobs carry trusted provenance, default to inactive or require explicit activation, surface a doctor/update dry-run diff, require an explicit model or cost-aware confirmation, and enforce a maintainer-approved quota/circuit-breaker path.
