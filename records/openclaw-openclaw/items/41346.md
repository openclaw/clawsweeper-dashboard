## Summary

Keep open: current main and the latest release still allow plugin/external cron-backed scheduled agent turns to be enabled immediately and to run without an explicit model, while existing retry logic records errors and backs off but does not provide the requested consent, cost, or quota circuit breaker.

## What This Changes

The issue requests safer defaults and guardrails for externally or plugin-registered recurring cron agent turns, including disabled-by-default registration, update/doctor confirmation, explicit model handling, and quota/cost circuit breakers.

## Best Possible Solution

Define a core cron registration contract where plugin or third-party recurring agent-turn jobs are created disabled or pending approval unless explicitly operator-enabled, require explicit model or a clear inherited-model warning, and route quota/cost circuit-breaker enforcement through the related cron and gateway budget guardrail work.
