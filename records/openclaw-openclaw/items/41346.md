## Summary

Keep open. Current main still defaults new cron jobs to enabled, bundled plugin scheduled turns still create enabled recurring agent-turn jobs without an explicit model, and cron execution records/backoffs usage after runs rather than enforcing consent, provenance, budget, or quota circuit breakers.

## What This Changes

The issue requests safer defaults and guardrails for externally registered recurring cron jobs so they do not start automatically, inherit expensive default models, or run through quota without user consent.

## Best Possible Solution

Design an owner-approved cron provenance and consent policy that preserves explicit operator cron behavior while requiring activation or guardrails for non-operator recurring agent-turn jobs, including explicit model/cost controls and a gateway budget circuit breaker.

## Maintainer Decision

Required: true

Question: What policy should OpenClaw apply to non-operator-created recurring cron jobs that can dispatch agent turns and spend model quota?

Rationale: Changing defaults, requiring confirmation, adding provenance, or enforcing spend limits affects compatibility, plugin contracts, provider spend policy, and security posture, so automation should not pick the permanent policy alone.

Likely owner: steipete

Owner reason: The strongest history trail is recent merged cron and plugin workflow-seam work across the affected files.

Owner confidence: high

Options:

- **Stage provenance plus consent guardrails (recommended):** Preserve explicit operator-created cron semantics, but require provenance and explicit activation or model/budget guardrails for plugin or agent-created recurring agentTurn jobs.
- **Default all new recurring cron jobs disabled:** This maximizes spend safety but is likely to break existing users and bundled plugins that rely on scheduled jobs starting immediately.
- **Keep auto-enable and add observability only:** This avoids compatibility churn but leaves the reported consent and runaway-spend failure mode mostly intact.

Yes by source inspection: current main still enables omitted cron jobs, bundled scheduled-turn registrations explicitly set enabled true, and missing payload models fall back to configured defaults; no live overnight quota reproduction was run.

## Solution Assessment

No one-line fix is best; the durable solution needs a maintainer-approved split between operator cron compatibility, plugin/agent provenance, model selection policy, doctor/update UX, and cost-budget enforcement.
