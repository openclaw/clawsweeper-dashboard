## Summary

Keep open because current main and v2026.6.11 still allow plugin/external cron paths to create enabled model-backed jobs without operator confirmation or cost circuit breaking, and the remaining work needs a coordinated security/product policy.

## What This Changes

The issue requests consent, model-cost visibility, dry-run/update diffs, and usage circuit breakers for externally registered recurring cron jobs.

## Best Possible Solution

Define one cron safety policy that distinguishes operator-created from external/plugin recurring agentTurn jobs, makes costful polling opt-in or explicitly modeled, and includes upgrade/doctor proof.

## Solution Assessment

Unclear until maintainers choose the policy; a narrow default flip could break existing schedules, so the best path is a coordinated cron/provenance/cost guard design with migration proof.
