## Label Justifications

- `P1`: The issue reports real runaway model usage from unconfirmed background cron jobs and unsafe provider/model inheritance, affecting real operator workflows without being a core-runtime outage.
- `impact:security`: Persistent externally registered schedules can start recurring model-backed work without explicit user confirmation, making cron authority and provenance a security-sensitive boundary.
- `impact:auth-provider`: The reported failure depends on inherited provider/model selection, quota exhaustion, and missing cost/budget enforcement for model calls.

## Summary

Keep open: current main still allows omitted cron `enabled` to become true, plugin scheduling can explicitly create enabled agent-turn jobs, isolated cron can inherit the agent/default model, and current cost usage is reported after runs rather than enforced as a consent or budget guard.

## What This Changes

Request that externally or plugin-registered cron jobs require explicit activation/confirmation, avoid silently inheriting expensive default models, and add cron usage/cost circuit breakers.

## Best Possible Solution

Keep this as the maintainer-owned umbrella until OpenClaw defines one coordinated cron authority policy for external job activation, model/cost preflight, usage circuit breaking, protocol/doctor visibility, and compatibility-safe migration.
