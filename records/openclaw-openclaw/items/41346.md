## Summary

Keep open. Current main and v2026.6.11 still default omitted cron `enabled` to true, plugin scheduled turns still register enabled `agentTurn` jobs without a job model, and the consent, provenance, model-cost, and quota circuit-breaker policy remains unresolved.

## What This Changes

The issue requests safer defaults and guardrails for externally or plugin-registered recurring cron jobs that can start running model calls without explicit user activation.

## Best Possible Solution

Define one cron safety policy for external or plugin recurring `agentTurn` jobs that covers operator-visible activation, non-forgeable provenance, explicit model or cost-warning behavior, doctor/update visibility, and quota-aware pause or notification semantics.
