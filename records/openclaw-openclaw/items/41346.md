## Summary

Keep open. Current main and the latest release still allow enabled plugin/external cron registration without an explicit model or spend guard, while the related issues cover narrower pieces rather than the full consent, provenance, model-cost, and circuit-breaker problem.

## What This Changes

The issue requests safer externally registered cron behavior: disabled-or-confirmed activation, cron diffs/dry runs, explicit model-cost checks, and usage circuit breakers.

## Best Possible Solution

Adopt a maintainer-approved cron safety design where operator cron stays explicit, externally/plugin/agent-created recurring jobs have trusted provenance, disabled-or-approved activation, explicit model/cost policy, and upgrade proof.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: What trust boundary and default activation policy should OpenClaw enforce for plugin, agent, or external recurring cron jobs that can spend model quota?

Rationale: A mechanical fix would change public cron defaults, plugin scheduling contracts, provider/model spend policy, and upgrade behavior, so maintainer intent is needed before implementation.

Likely owner: Vincent Koc

Owner reason: Recent cron/model-selection and release history puts the active implementation surface closest to Vincent Koc, while the final policy still needs broader security/product agreement.

Owner confidence: medium

Options:

- **Provenance-gated scheduling API (recommended):** Require trusted origin attribution plus approval or disabled-by-default activation for non-operator recurring jobs, and require explicit model/cost policy before execution.
- **Default external jobs disabled:** Make plugin, agent, and external recurring registrations inactive until the operator enables them, accepting a compatibility migration and UX cost for existing automation.
- **Keep auto-enable with spend guards:** Preserve current activation behavior but add budget, quota, and cost circuit breakers, leaving consent and provenance weaker than the issue requests.

## Reproduction Assessment

Yes, at source level. Cron create defaults missing enabled to true, plugin scheduled turns register enabled agentTurn jobs without model overrides, and model selection falls through to agent/default model when payload.model is omitted.

## Solution Assessment

No narrow default flip is clearly the best fix. The maintainable path is a product/security decision that covers provenance, consent, model-cost policy, circuit breaking, and upgrade behavior together.
