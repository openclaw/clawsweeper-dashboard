## Summary

Keep open. Current main and latest release still create cron jobs as enabled by default, bundled plugin scheduled turns explicitly add enabled agentTurn jobs without a payload model, cron model resolution can inherit the configured default model, and recurring cron failures back off rather than enforcing the requested consent, cost, provenance, and quota guardrails.

## What This Changes

The issue requests safer defaults and guardrails for externally or plugin-registered recurring cron jobs, including activation consent, model-cost warnings, doctor/update visibility, and quota circuit breaking.

## Best Possible Solution

Define one maintainer-approved cron safety policy covering external/plugin registration provenance, activation consent, explicit model or cost-warning behavior, update/doctor visibility, and quota-aware pause/notification semantics.
