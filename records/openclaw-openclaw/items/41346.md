## Summary

Keep open. Current main still has source-reproducible paths where plugin/external cron registration can create enabled model-backed jobs without per-job model or cost guardrails, and the remaining fix needs maintainer security/product policy rather than conservative cleanup.

## What This Changes

The issue asks OpenClaw to require confirmation and cost guardrails before externally or plugin-registered recurring cron jobs run on inherited default models.

## Best Possible Solution

Define a coordinated cron safety policy that distinguishes operator-authored, plugin-registered, and future agent-authored schedules, then add explicit activation/provenance, model-cost visibility, and upgrade/doctor handling for recurring model-backed jobs.
