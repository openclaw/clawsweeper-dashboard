## Summary

Keep open. Current main still lets plugin/external cron registration create enabled model-backed jobs and resolve them from default model selection without the requested activation, inherited-model, or budget guardrails; the fix needs maintainer security/product policy rather than conservative cleanup.

## What This Changes

The issue requests cron safety guardrails for externally or plugin-registered recurring jobs: explicit activation, model-cost visibility, doctor/update diffing, and usage circuit breakers.

## Best Possible Solution

Define one maintainer-approved cron safety policy that distinguishes operator-authored, plugin-registered, and future agent-authored schedules, then add activation/provenance, inherited-model cost visibility, doctor/update handling, and budget/circuit-break behavior with compatibility proof.
