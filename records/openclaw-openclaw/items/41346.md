## Summary

Keep open. Current main and latest release still default new cron jobs to enabled, bundled plugin scheduled turns still create enabled recurring `agentTurn` jobs without a payload model, model selection still falls through to configured defaults, and recurring failures still back off rather than enforcing the requested consent, provenance, cost, or quota guardrails.

## What This Changes

Request external or plugin-registered recurring cron jobs to require user activation or visible approval, avoid silently inheriting expensive default models, and add cost or usage circuit breakers.

## Best Possible Solution

Define one cron safety policy for externally or plugin-registered recurring `agentTurn` jobs covering activation approval, provenance, explicit model or cost-warning behavior, doctor/update visibility, and quota-aware pause or notification semantics.
