## Label Justifications

- `P1`: The issue reports source-reproducible unattended model-backed cron execution that can burn real user quota or spend during normal installed usage.
- `impact:security`: Externally or plugin-created recurring schedules can become durable unattended automation without an operator approval or provenance boundary.
- `impact:auth-provider`: The harmful path depends on inherited provider/model selection and metered auth-profile usage for background agent turns.

## Summary

Keep open. Current main and v2026.6.11 still allow plugin/external cron registration to create enabled model-backed jobs, inherit agent/default model selection when no job model is set, and rely on retry/backoff rather than consent, provenance, model-cost, or quota circuit-breaker guardrails.

## What This Changes

Request safeguards so externally, plugin, or agent-registered recurring cron jobs cannot silently run enabled on expensive inherited default models without operator consent or usage limits.

## Best Possible Solution

Adopt a maintainer-approved cron safety design covering external/plugin schedule provenance, operator activation or confirmation, explicit model/cost visibility, doctor/update dry-run reporting, and quota/cost pause semantics across the related issues.
