## Summary

Keep open. Current main and v2026.6.11 still allow cron creation paths to enable jobs by default, plugin scheduled turns explicitly register enabled recurring agent-turn jobs without a payload model, and the consent, provenance, model-cost, and quota circuit-breaker behavior needs maintainer security/product direction.

## What This Changes

Request guardrails so externally registered cron jobs do not silently auto-enable, inherit expensive default models, or run without spend circuit breakers.

## Best Possible Solution

Adopt a maintainer-approved cron scheduling safety design with explicit provenance and consent for plugin or agent-created recurring jobs, explicit model/cost policy, and gateway-level budget or circuit-breaker behavior with doctor/upgrade proof.

Rationale: The answer changes cron defaults, plugin scheduling contracts, provider/model spend policy, doctor/update behavior, and the security boundary for persistent automation.

Owner confidence: medium

Options:

- **Provenance-based scheduling API (recommended):** Introduce a trusted scheduling path that records who created the job, requires operator approval or safe defaults for untrusted recurring jobs, and makes model/cost policy explicit.
- **Default external jobs disabled:** Keep the current cron API but make externally registered recurring jobs inactive until the operator enables them, with migration and doctor messaging for existing jobs.
- **Keep auto-enable with spend guards:** Preserve current auto-enable behavior but add model warnings, budget enforcement, and quota circuit breakers to reduce runaway-cost impact.

## Reproduction Assessment

Yes at source level: cron create/add paths default missing `enabled` to true, plugin scheduled turns explicitly pass `enabled: true` without `payload.model`, and isolated cron model selection falls back to agent/default model.

## Solution Assessment

No as a narrow default flip; the best fix needs one maintainer-approved policy separating operator-created jobs from plugin/agent-created jobs while coordinating model spend and quota guardrails.
