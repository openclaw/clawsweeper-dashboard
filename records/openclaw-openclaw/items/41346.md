## Summary

Keep open. Current main and v2026.6.11 still preserve the reported cron behavior: new or omitted cron enablement defaults to active, agent-turn cron jobs can fall through to agent/default model selection, and recurring failures back off rather than enforcing the requested consent, provenance, cost-budget, or quota circuit-breaker policy. Related open issues cover pieces of the problem, but none supersedes the activation/consent gap end to end.

## What This Changes

The issue requests consent, model-cost, provenance, and quota guardrails for externally registered cron jobs that currently enable and inherit model defaults.

## Best Possible Solution

Adopt one maintainer-approved cron safety design that records external provenance, requires explicit activation or a reviewed diff for external recurring jobs, defaults background model choice safely, and connects cron runs to budget or circuit-breaker policy.
