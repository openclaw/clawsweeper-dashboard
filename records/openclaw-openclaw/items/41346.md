## Summary

Keep open. Current main still has a source-reproducible path where bundled/plugin scheduling creates enabled model-backed cron jobs without an explicit per-job model or user confirmation, while recurring failures receive backoff/alerts rather than a cost or quota circuit breaker.

## What This Changes

The issue requests safer cron/plugin scheduling defaults so externally registered recurring jobs do not silently enable and run on expensive inherited models without activation and cost guardrails.

## Best Possible Solution

Maintainers should define one cron scheduling security policy covering external/plugin activation, explicit model requirements for recurring model-backed jobs, and quota/cost circuit-break behavior, then implement the smallest compatible core and plugin-SDK changes with doctor/docs coverage.
