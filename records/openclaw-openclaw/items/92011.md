## Summary

The PR remains necessary because current main has no equivalent fallback-completion guard, and it provides a well-proven scoped mitigation. It should not merge yet because the unconditional turn-wide spawn denial also removes legitimate delegation for distinct remaining work, requiring either a narrower implementation or explicit maintainer approval.

## What This Changes

The branch marks completion announcements as completed-work evidence, propagates fallback-attempt context into embedded runs, classifies completion provenance, and rejects embedded subagent or ACP spawns on fallback completion-announcement turns.

## Best Possible Solution

Preserve the completed-work evidence prompt and shared fallback/provenance facts, but gate replay of announced work rather than removing all spawn capability from the turn; keep the canonical issue open for gateway, sibling-delegation, and Codex-native follow-ups.
