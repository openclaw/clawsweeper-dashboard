## Summary

Keep open; current main and v2026.6.11 still only expose TUI completion through visual status/final-message state, while sound, bell, or desktop alerts would add a new opt-in notification and config contract that needs maintainer direction.

## What This Changes

Request an opt-in TUI completion alert for long agent runs, such as a desktop notification, terminal bell, configurable sound, or badge/status highlight.

## Best Possible Solution

Define a narrow default-off TUI completion-notification contract first, then implement it on the active-run finalization path with schema/help/docs and PTY coverage for local, gateway, concurrent-run, and stale-final cases.
