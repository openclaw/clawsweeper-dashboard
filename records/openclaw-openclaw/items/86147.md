## Summary

Keep open; current main and v2026.6.11 still make TUI completion visible through final-message and idle status only, while sound, bell, or desktop alerts would add a new default-off notification and config contract that needs maintainer product direction.

## What This Changes

Request a TUI completion notifier, such as desktop notification, terminal bell, or configurable sound, for local and Gateway-backed TUI runs.

## Best Possible Solution

Define a narrow default-off TUI completion-notification contract, reuse existing node or system notification plumbing where it fits, and cover local plus Gateway completion paths with config, docs, and PTY tests while leaving broader operator watchdog alerts to the related gateway alerting work.
