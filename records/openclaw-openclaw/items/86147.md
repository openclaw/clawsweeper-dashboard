Keep open; current main and v2026.6.11 still expose TUI completion through final-message/status-line state only, while sound, bell, or desktop alerts would add a new user-facing notification and config contract that needs maintainer product direction.

Define a narrow default-off TUI completion-notification contract first, preferably starting with a safe terminal-bell mode or shared notification primitive, then add schema/help/docs and PTY coverage for Gateway-backed, local, concurrent, and stale-final completion paths.
