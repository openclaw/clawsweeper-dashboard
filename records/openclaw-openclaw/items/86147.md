## Summary

Keep open; current main still exposes TUI completion through visual final-message/status-line state only, while sound, bell, or desktop alerts would add a new local TUI notification and config contract that needs maintainer product direction.

## What This Changes

The issue requests opt-in TUI completion notifications such as desktop alerts, terminal bell, sound, or badges for long-running agent tasks.

## Best Possible Solution

Define a narrow default-off TUI completion-notification contract first, then implement it in the active-run finalization path with config schema/help/docs and PTY/local-mode coverage for active, inactive, concurrent, and stale-final cases.
