## Summary

Keep open: current main and the latest release still only expose TUI completion through final message/status-line state, while sound, bell, or desktop alerts would add new TUI behavior and config surface that needs maintainer product direction.

## What This Changes

Add an opt-in TUI notification mechanism, such as desktop notification, terminal bell, sound, or status highlight, when an agent run completes.

## Best Possible Solution

Define a narrow default-off TUI-client notification contract first, then implement it on the active-run finalization/status path with schema/help/docs and PTY coverage for local, Gateway, concurrent-run, and inactive-final cases.
