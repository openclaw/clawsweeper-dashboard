## Summary

Keep open: current main has OpenRouter dynamic runtime mitigation and shared live-catalog plumbing, but OpenRouter still does not populate a credential-backed text model catalog/list/picker from `/models`, and the remaining behavior is a provider/config/product-policy decision rather than a completed fix.

## What This Changes

The issue requests fully dynamic provider-backed model discovery, especially for OpenRouter, so configured and available models appear in model lists, pickers, allowlists, and runtime selection without static catalog updates.

## Best Possible Solution

Keep #10687 as the canonical design thread, settle provider-owned live text catalog/list/picker/allowlist/cache semantics, then implement OpenRouter discovery through the guarded live-catalog SDK with real OpenRouter proof.

## Reproduction Assessment

Yes at source level, but not with a live credential run: OpenRouter text catalog rows still come from a fixed provider catalog while dynamic hooks only materialize explicitly requested runtime models.

## Solution Assessment

No complete solution is present yet; the best path is provider-owned live text catalog discovery through the existing guarded SDK after maintainers settle picker defaults, allowlists, cache TTL/offline behavior, endpoint trust, and safety policy.
