## Summary

Keep open: current main and v2026.6.11 partially mitigate newly added OpenRouter model IDs at runtime and provide guarded live-catalog infrastructure, but OpenRouter text catalog/list/picker discovery is still static and the remaining allowlist, cache, offline, and credential-safety choices require maintainer direction.

## What This Changes

The issue requests fully dynamic provider model discovery, starting with OpenRouter, so model lists, pickers, allowlists, and runtime validation stay current without static catalog refreshes.

## Best Possible Solution

Keep this as the canonical design thread, then implement provider-owned OpenRouter text live catalogs through the guarded provider-catalog SDK after maintainers settle picker/list defaults, wildcard semantics, cache/offline policy, and credential safety.

## Reproduction Assessment

Yes at source level for the remaining limitation: OpenRouter still exposes a small static text catalog while dynamic OpenRouter /models fetching is used for requested runtime capability metadata, not text list/picker discovery; no live OpenRouter credential flow was run.

## Solution Assessment

No complete solution is present on main; the best path is to reuse the guarded live catalog SDK through provider-owned OpenRouter text catalog hooks after maintainer decisions on picker/list defaults, allowlists, caching, offline failure, and credential safety.
