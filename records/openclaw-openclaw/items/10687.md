## Summary

Keep open: current main has provider live-catalog infrastructure and OpenRouter dynamic-ID execution mitigation, but the maintainer-labeled umbrella still owns unresolved OpenRouter and cross-provider listing, picker, allowlist, cache/offline, and endpoint-trust semantics.

## What This Changes

Request fully dynamic provider model discovery so OpenRouter and similar providers can list and select current models without static catalog updates or disabling model allowlists.

## Best Possible Solution

Keep this as the maintainer-owned umbrella, choose the provider-owned live catalog contract and safety semantics, then land focused provider implementations through the guarded live catalog SDK and existing visibility paths.

Options:

- **Provider-owned live catalogs (recommended):** Use the guarded plugin SDK live catalog path per provider, with explicit wildcard, cache, fallback, and picker/list rules for OpenRouter and similar providers.
- **Generated catalog refresh:** Add a command or config-driven refresh that writes local catalog rows, trading better offline behavior for stricter migration, SecretRef, and stale-file policy work.
- **Runtime fallback only:** Continue allowing unknown provider IDs at execution time while accepting that model list and picker discovery remain incomplete for fast-moving providers.

## Reproduction Assessment

Yes, at source level: OpenRouter catalog rows remain static and models.list reuses catalog snapshots, while dynamic hooks only mitigate unknown model execution. I did not run a live OpenRouter credential path in this read-only review.

## Solution Assessment

Unclear as an implementation: the issue identifies the right gap, but maintainers still need to choose provider-owned discovery versus generated refresh or runtime fallback, plus wildcard, cache, offline, picker, and safety-control semantics.
