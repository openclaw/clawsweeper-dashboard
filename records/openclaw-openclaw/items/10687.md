## Summary

Keep open: current main has useful runtime-side OpenRouter dynamic-model mitigation and shared live-catalog infrastructure, but the broad picker/list/catalog, cache, allowlist, credential, and UX behavior requested here is still incomplete and the issue has a protected maintainer label.

## What This Changes

The issue requests fully dynamic provider model discovery, starting with OpenRouter, so current provider catalogs can be listed, selected, and allowed without waiting for static catalog updates.

## Best Possible Solution

Keep this as the canonical maintainer design thread and implement OpenRouter/provider-owned live catalog discovery through the guarded SDK after picker defaults, caching, allowlist, and credential-safety policy are settled.

## Reproduction Assessment

Yes, at source level: current main still exposes only a three-row OpenRouter catalog while the public OpenRouter endpoint returns hundreds of models. The direct runtime path is partially mitigated, but the requested picker/list dynamic catalog behavior is still missing.

## Solution Assessment

No current fix is complete. The best path is provider-owned live catalog discovery through the existing guarded SDK, with maintainer decisions for wildcard allowlists, cache/offline behavior, credential use, and picker defaults.
