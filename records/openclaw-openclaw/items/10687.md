## Label Justifications

- `P2`: Dynamic model discovery affects real OpenRouter/provider model selection, but the issue is a bounded provider catalog improvement rather than an urgent runtime outage.
- `impact:auth-provider`: The affected behavior is provider model discovery, model choice, configured allowlists, and credential-scoped provider catalog resolution.

## Summary

Keep open: current main has useful partial runtime mitigation and guarded live-catalog infrastructure, but the OpenRouter text model catalog used by list/picker surfaces is still a small static catalog, and the protected maintainer/product-decision labels require explicit maintainer direction.

## What This Changes

The issue requests fully dynamic provider-backed model discovery so fast-moving catalogs such as OpenRouter can list and use current model IDs without waiting for static catalog regeneration.

## Best Possible Solution

Keep this as the canonical maintainer design thread and implement OpenRouter/provider-owned live catalog discovery through the guarded provider catalog SDK after cache, credential, allowlist, and picker UX policy are settled.

## Reproduction Assessment

Yes, at source level: current main still exposes a static OpenRouter text model catalog while OpenRouter's public endpoint returns hundreds of model IDs. I did not run a full authenticated OpenClaw picker or agent turn in this read-only review.

## Solution Assessment

No current implementation is complete: the runtime dynamic-model hook and guarded live-catalog SDK are useful building blocks, but the best fix needs maintainer-approved provider catalog semantics before wiring OpenRouter into list and picker behavior.
