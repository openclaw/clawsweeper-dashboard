## Summary

Keep open: current main mitigates OpenRouter unknown-model execution, but the issue still owns broader dynamic catalog, list/picker, allowlist, cache/offline, and cross-provider contract decisions.

## What This Changes

Requests provider-backed dynamic model discovery so OpenRouter and other fast-moving providers can list, select, and execute current model IDs without static catalog refreshes.

## Best Possible Solution

Keep this umbrella open until maintainers choose the provider-owned live catalog contract, safety semantics, and picker/list behavior, then land focused provider implementations.

Rationale: The answer changes plugin API shape, provider routing, configured allowlists, endpoint trust, cache/offline policy, and model-picker defaults, so code inspection cannot safely choose it automatically.

Options:

- **Provider-owned live catalogs (recommended):** Build on current provider/plugin live catalog hooks with explicit wildcard, cache, fallback, and picker rules per provider.
- **Generated catalog refresh:** Add a command or config-driven refresh that writes local catalog rows, trading better offline behavior for migration and SecretRef-safe write-policy work.
- **Runtime fallback only:** Keep synthesizing unknown models at execution time and accept incomplete model-list and picker discovery for fast-moving catalogs.

## Solution Assessment

Unclear as a final implementation: the issue identifies the right gap, but maintainers still need to choose provider-owned discovery versus generated refresh or runtime fallback plus cache, picker, and safety semantics.
