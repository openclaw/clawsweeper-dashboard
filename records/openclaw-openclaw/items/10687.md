## Summary

Keep open: current main has partial live-catalog infrastructure and OpenRouter runtime metadata mitigation, but the central OpenRouter/provider-backed list, picker, allowlist, cache, and safety policy remains unresolved and the issue has protected maintainer/product-decision labels.

## What This Changes

The issue requests fully dynamic provider model discovery, starting with OpenRouter, so current models can be listed and selected without waiting for static Pi catalog or manual allowlist updates.

## Best Possible Solution

Keep this issue as the canonical broad dynamic model-discovery design thread, then implement provider-owned OpenRouter live catalog discovery through the existing guarded SDK after maintainers settle picker defaults, wildcard/allowlist behavior, caching, offline failure, and credential-safety policy.

## Reproduction Assessment

Yes at source level for the remaining catalog gap: current main still wires OpenRouter list/picker catalog rows through a static provider config, while dynamic runtime hooks only prepare requested OpenRouter model metadata. I did not run a live authenticated OpenRouter flow.

## Solution Assessment

No complete solution is present yet; the maintainable path is provider-owned live catalog discovery using existing guarded SDK primitives after maintainer decisions on picker defaults, allowlists, caching, offline behavior, and credential safety.
