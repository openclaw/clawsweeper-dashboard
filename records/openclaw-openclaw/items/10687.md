## Summary

Keep open: current main has partial OpenRouter runtime mitigation and shared live-catalog infrastructure, but it still does not complete the requested provider-backed text model catalog/list/picker/allowlist/cache policy and the issue is already marked for maintainer/product review.

## What This Changes

The issue requests fully dynamic runtime model discovery for OpenRouter and other fast-moving providers while preserving model allowlist, picker usability, and safety/cost controls.

## Best Possible Solution

Keep this as the broad dynamic-discovery design thread, settle provider-owned catalog/list/picker semantics, then wire OpenRouter text models through the guarded live catalog SDK with live OpenRouter proof.

## Reproduction Assessment

Yes at source level, but not with live credentials: current main still uses a small static OpenRouter text catalog while dynamic OpenRouter /models fetching only prepares requested runtime model metadata.

## Solution Assessment

No complete solution is present yet; the best path is a provider-owned dynamic catalog design using existing guarded SDK primitives after maintainer decisions on picker defaults, allowlists, caching, offline behavior, and credential safety.
