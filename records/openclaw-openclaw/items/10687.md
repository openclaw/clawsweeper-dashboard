- `impact:auth-provider`: The requested behavior changes provider model choice, model routing, configured-model validation, and credential-scoped catalog semantics.

## Summary

Keep open: current main and the latest stable release still have only partial OpenRouter dynamic-model mitigation, while the requested provider-backed list/picker/catalog behavior remains a maintainer-scoped product and security design item.

## What This Changes

Request fully dynamic provider model discovery, starting with OpenRouter, so runtime selection, model listing, and pickers can use current provider catalogs without stale static OpenClaw/Pi catalog entries or disabled allowlists.

## Best Possible Solution

Keep #10687 as the canonical design thread and implement provider-owned OpenRouter live catalog discovery through the existing guarded SDK after maintainers settle picker defaults, caching, offline fallback, allowlist, and credential-safety policy.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 still expose a static three-row OpenRouter catalog for list/picker surfaces while runtime hooks only synthesize metadata for requested model IDs; I did not run a live authenticated OpenRouter picker or agent flow.

## Solution Assessment

No current fix is complete: runtime dynamic-model resolution is a useful partial mitigation, but the best fix is maintainer-approved provider catalog discovery through the existing guarded SDK rather than ad hoc fallback behavior.
