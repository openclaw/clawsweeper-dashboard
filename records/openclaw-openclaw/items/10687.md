## Summary

Keep open: current main can synthesize and execute arbitrary configured OpenRouter model IDs, but OpenRouter’s user-visible text catalog remains a three-entry static list rather than current provider discovery. The existing generic live-catalog SDK makes the implementation boundary clear, while picker size, allowlist authority, capability defaults, and offline behavior still require the protected issue’s assignee to choose product policy.

**Likely related people**
- `joshp123` — high confidence; current assignee and author of the discovery-policy design.
- `steipete` — medium confidence; recent contributor across the current catalog architecture.
- Vincent Koc — medium confidence; recent provider-policy and catalog contributor.

## What This Changes

Add runtime discovery and safe selection of current provider model catalogs, initially OpenRouter, without waiting for static catalog releases or disabling model controls.

## Best Possible Solution

Connect OpenRouter text discovery to the existing provider live-catalog SDK, retain arbitrary-ID runtime synthesis, show a curated default set with explicit full search/listing, and preserve `agents.defaults.models` plus provider-wildcard authorization with tested cached/offline fallback.

Question: How should dynamically fetched OpenRouter text models be filtered and authorized in normal pickers and `/model` flows?

Rationale: The runtime and fetch primitives exist, but acceptable catalog size, capability defaults, cost safeguards, allowlist authority, and offline fallback are product choices that source inspection cannot settle.

Likely owner: joshp123

Owner confidence: high

Options:

- **Curated live catalog (recommended):** Fetch current models, show a bounded recommended subset by default, expose the full set through explicit search or all-catalog views, and keep configured allowlists authoritative.
- **Full live catalog:** Show every fetched model in normal list and picker surfaces, accepting a large and rapidly changing selection experience.
- **Runtime fallback only:** Keep arbitrary configured models executable but leave normal discovery static, preserving the primary user-facing gap.

## Solution Assessment

Yes after narrowing the design: OpenRouter should consume the existing provider-owned live-catalog SDK rather than add another core catalog abstraction or a new config mode before policy requires one.
