## Summary

Keep open: protected maintainer/product-decision labels block cleanup, and current main plus v2026.6.11 still expose OpenRouter picker/list catalog rows from a small static provider catalog while only runtime unknown-model resolution is partially dynamic.

## What This Changes

The issue requests provider-backed dynamic model discovery so OpenRouter and similar fast-moving providers can list and run current model IDs without waiting for static catalog updates.

## Best Possible Solution

Keep this as the canonical maintainer design thread and implement provider-owned live catalogs through the existing guarded SDK once cache, allowlist, picker, offline, and credential-safety policy are settled.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 still expose OpenRouter's list/picker catalog through static bundled rows while OpenRouter's public model endpoint returns hundreds of rows. I did not run a live authenticated OpenClaw picker or agent turn in this read-only review.

## Solution Assessment

No current implementation is complete. The best fix is a maintainer-approved provider-catalog design using the existing guarded live catalog SDK, not an ad hoc unknown-model fallback or one-off static catalog refresh.
