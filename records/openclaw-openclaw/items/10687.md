## Summary

Keep open for an explicit maintainer product decision. The issue’s central request—provider-backed, runtime-refreshable catalogs with safe model visibility and selection—still has meaningful scope beyond the reported historical OpenRouter failure, and the open canonical tracker already owns the shared design discussion. The existing `maintainer` label also rules out automated cleanup.

## What This Changes

Add a safe runtime model-catalog discovery path for fast-changing providers such as OpenRouter, so current provider models can be listed and selected without waiting for static catalog releases.

## System Context

OpenClaw resolves configured provider/model references for agent runs and exposes the resulting catalog through model-selection UX and CLI surfaces. Provider-backed discovery would feed that catalog while preserving configured model restrictions, capability metadata, and safe fallback behavior.

## Architecture Diagram

flowchart LR

  B --> C[Catalog refresh and cache]

  E[Configured model policy] --> F[Selection validation]
  D --> F
  F --> G[CLI and chat model picker]
  F --> H[Agent model resolution]

## Best Possible Solution

Use the open canonical tracker to define one provider-owned live-catalog contract with bounded caching, normalized metadata, configured-model policy enforcement, and clear offline behavior; then implement OpenRouter and other providers through that contract rather than adding a parallel broad core catalog system.
