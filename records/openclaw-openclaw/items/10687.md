## Summary

Keep open: current main and v2026.6.11 have partial dynamic-catalog infrastructure, but OpenRouter's provider catalog still returns a fixed small list and the broader picker, allowlist, cache, endpoint-trust, and safety policy remains an active protected maintainer decision.

## What This Changes

The issue requests fully dynamic model discovery for OpenRouter and other fast-moving provider catalogs while preserving picker usability and allowlist/safety controls.

## Best Possible Solution

Extend the existing guarded provider-catalog SDK and provider-plugin paths so OpenRouter and selected compatible providers can refresh live catalogs with bounded auth-scoped caching, picker-sized defaults, wildcard allowlists, static fallback, and maintainer-approved safety semantics.

## Reproduction Assessment

Yes, at source level for the remaining gap: current OpenRouter catalog/listing still returns buildOpenrouterProvider() static rows, while dynamic OpenRouter capability fetching only happens around explicit runtime model lookup. I did not run a live credentialed OpenRouter reproduction.

## Solution Assessment

No, this is not solved well enough to close: current main has useful live-catalog infrastructure and explicit OpenRouter dynamic-model mitigation, but not the full provider-backed list, picker, allowlist, cache, and safety policy requested here.
