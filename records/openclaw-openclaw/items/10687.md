## Summary

Keep open: current main has dynamic runtime mitigation and shared live-catalog infrastructure, but it still lacks a complete OpenRouter text catalog/list/picker/allowlist/cache policy and protected maintainer/product-decision labels require human handling.

## What This Changes

The issue requests runtime dynamic model discovery for fast-moving provider catalogs such as OpenRouter while preserving model selection and safety controls.

## Best Possible Solution

Keep this as the canonical design thread, then wire OpenRouter text catalogs through a provider-owned guarded live catalog path once maintainers settle picker defaults, wildcard allowlists, cache/offline behavior, and credential safety.

## Reproduction Assessment

Yes at source level: current OpenRouter code still exposes a small static text catalog while dynamic OpenRouter /models fetching is used for requested runtime capability metadata. I did not run a live OpenRouter credential flow in this read-only review.

## Solution Assessment

No complete solution is present yet; the best path is to reuse the guarded live catalog SDK through provider-owned OpenRouter text catalog hooks after maintainer decisions on picker/list defaults, allowlists, caching, offline failure, and credential safety.
