## Summary

Keep open: current main and v2026.6.11 still expose a static OpenRouter picker/list catalog, while runtime-only dynamic model resolution is only a partial mitigation; the protected maintainer label and remaining cache, allowlist, credential, and UX decisions make this a maintainer design item.

## What This Changes

Request fully dynamic model discovery for fast-moving provider catalogs, especially OpenRouter, while preserving model-selection safety and configured-model controls.

## Best Possible Solution

Keep this as the broad maintainer design thread and implement OpenRouter/provider-owned live catalog discovery through the guarded SDK after picker defaults, cache policy, allowlist behavior, and credential safety are settled.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 still expose only three static OpenRouter catalog rows while OpenRouter's public endpoint returned 340 models. I did not run a credentialed OpenClaw picker or agent turn in this read-only review.

## Solution Assessment

No complete fix exists on main. The best path is a maintainer-approved provider-owned live catalog design using the existing guarded SDK, not an ad hoc unknown-model fallback or broad core catalog rewrite.
