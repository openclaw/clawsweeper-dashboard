## Label Justifications

- `P2`: The runtime blocker is largely fixed, but incomplete provider catalog discovery remains a normal-priority model-selection improvement with limited blast radius.
- `impact:auth-provider`: The issue concerns provider model availability, dynamic resolution, credential-scoped catalogs, and model-selection routing.
- `impact:ux-friction`: Users can run arbitrary OpenRouter models but still face stale or incomplete picker/list surfaces and may need manual model references or configuration.

## Summary

Keep open: current main fixes the original OpenRouter “Unknown model” runtime failure, but OpenRouter still publishes only three static catalog rows to model-list and picker surfaces, so the requested live discovery UX and its allowlist/cache policy remain unresolved; the protected maintainer label also requires an explicit product decision.

## What This Changes

Add provider-backed dynamic model discovery so current OpenRouter and other provider models appear in selection surfaces and resolve without static catalog updates.

## Best Possible Solution

Have the OpenRouter plugin publish cached live `/api/v1/models` rows through the existing provider catalog augmentation seam, retain its small static catalog as offline fallback, keep `agents.defaults.models` authoritative when configured, and reuse the same SDK primitive for other providers without adding provider-specific core policy.
