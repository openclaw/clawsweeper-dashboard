## Summary

Keep open: current main and v2026.6.11 mitigate unknown OpenRouter models at runtime, but OpenRouter text catalog/list/picker/allowlist/cache policy is still not fully dynamic and the issue has protected maintainer/product-decision labels.

## What This Changes

Request fully dynamic model discovery so OpenClaw can list, select, and run current OpenRouter and other provider models without waiting for static catalog refreshes.

## Best Possible Solution

Keep this as the canonical design thread, then wire OpenRouter text catalogs through a provider-owned guarded live catalog path after maintainers settle picker defaults, wildcard allowlists, cache/offline behavior, and credential safety.

## Reproduction Assessment

Yes at source level: current OpenRouter code still exposes a small static text catalog while dynamic OpenRouter /models fetching is used only for requested runtime capability metadata; no live OpenRouter credential flow was run.

## Solution Assessment

No complete solution is present yet; the best path is to reuse the guarded live catalog SDK through provider-owned OpenRouter text catalog hooks after maintainer decisions on picker/list defaults, allowlists, caching, offline failure, and credential safety.
