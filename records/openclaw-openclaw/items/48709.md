## Summary

Keep open: current main and v2026.6.11 fixed the Gemini tagged/native reasoning conflict, but the central visible-text signature bloat path still exists because same-route Gemini text signatures are stored and replayed as thought signatures.

## What This Changes

The issue requests a fix for Gemini 2.5 Pro sessions accumulating large text signatures, leaking or suppressing thinking-tag text, and dropping user-visible text around mixed text/tool turns.

## Best Possible Solution

Define a Google-provider replay policy that preserves required tool-call/native-thinking signatures while bounding, dropping, or externalizing optional visible-text signatures, then prove it with focused replay tests and a live Gemini tool-turn scan.

## Reproduction Assessment

Yes, at source level: current main stores Gemini thought signatures on visible text blocks and replays those textSignature values as thoughtSignature on same-route history. I did not run the paid Gemini plus Telegram loop in this read-only review.

## Solution Assessment

No, current main is only a partial solution: the native reasoning conflict is fixed, but the remaining bloat needs a maintainer-selected Google signature retention and replay contract rather than an unconditional strip-all patch.
