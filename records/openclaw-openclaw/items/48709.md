## Summary

Keep open: current main fixed the direct Gemini tagged/native reasoning conflict, but it still stores visible Google text signatures and replays same-route textSignature values as Gemini thoughtSignature. That leaves the central session-bloat failure unresolved and makes this a maintainer replay-policy decision rather than a safe cleanup close.

## What This Changes

The issue requests that Gemini 2.5 Pro session handling avoid textSignature context bloat, handle embedded think tags safely, and preserve visible text from mixed text/tool responses.

## Best Possible Solution

Define a Google replay policy that preserves required tool-call/native-thinking signatures while bounding, externalizing, or dropping optional visible-text signatures; keep broad inter-tool channel delivery policy on its own canonical issue.
