## Summary

Keep open: current main and the latest release have fixed the tagged/native Gemini reasoning subset, but the central session-bloat path remains because valid same-route Gemini text signatures are still stored and replayed as `thoughtSignature`.

## What This Changes

The issue reports Gemini provider session bloat and message loss from retained text signatures, embedded thinking tags, and mixed text/tool responses.

## Best Possible Solution

Define a Google provider replay policy that preserves required function-call and native-thinking signatures while bounding, externalizing, or dropping optional completed visible-text signatures, with regression coverage and live Gemini/Telegram proof.

Rationale: Current code intentionally replays valid same-route signatures, and Google’s API contract treats some signatures as required but visible-text signatures as quality-affecting rather than strictly enforced, so automation should not choose the permanent provider semantics alone.

Options:

- **Bound completed text signatures (recommended):** Preserve required tool-call/native-thinking signatures, but drop, cap, or externalize completed visible `textSignature` values before replay to stop session bloat.
- **Externalize replay metadata:** Move provider signatures out of visible transcript content and replay only the metadata needed for active same-route continuation.
- **Keep current replay pending live proof:** Accept the bloat risk until maintainers obtain stronger live Google proof for a narrower stripping rule.
