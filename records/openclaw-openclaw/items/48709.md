## Summary

Keep open: current main fixed the Gemini tagged/native reasoning conflict and has channel-side protections for several `<think>`/tool-call symptoms, but direct Gemini same-route `textSignature` values are still retained on text blocks and replayed as `thoughtSignature`, so the central session-bloat and replay-contract question remains.

## What This Changes

The issue requests that Gemini 2.5 Pro session history avoid retaining or replaying large `textSignature` blobs and stop dropping visible text when Gemini emits thinking tags and mixed text/tool turns.

## Best Possible Solution

Define the Google-owned signature contract first, then implement a focused provider/session fix that prevents old large `textSignature` blobs from bloating replay while preserving any Gemini signatures that are actually required for tool-call continuity.
