## Summary

Keep open: current main and v2026.6.11 have fixed the direct Google tagged/native reasoning conflict, but valid Gemini text signatures are still stored on visible text blocks and replayed as thought signatures, so the central session-bloat failure is not implemented away.

## What This Changes

The issue asks OpenClaw to prevent Gemini 2.5 Pro textSignature bloat, reasoning-tag suppression, and mixed text/tool turns from breaking session replay and Telegram delivery.

## Best Possible Solution

Define a Google-provider replay policy that preserves required function-call/native-thinking signatures while bounding, externalizing, or dropping optional visible-text signatures, with focused replay tests and live Gemini proof.

## Reproduction Assessment

Yes, at source level: current main stores Gemini thoughtSignature values on visible text blocks and replays stored textSignature values as outbound thoughtSignature. I did not run a live paid Gemini plus Telegram loop in this read-only review.

## Solution Assessment

No, current main is only a partial solution because it fixed direct Google native reasoning but still preserves valid visible-text signatures. The best fix is a maintainer-selected Google signature retention and replay contract, not a stale close or unconditional strip-all patch.
