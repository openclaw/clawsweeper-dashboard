## What This Changes

The PR scopes OpenAI/Codex subscription-limit auth-profile blocks to the failing model across WHAM writes, Codex app-server block writes, cooldown/reason readers, fallback routing, and regression tests.

## Best Possible Solution

Land this bounded `blockedModel` scoping fix if maintainers accept the conservative profile-wide widening behavior; defer a richer per-model block map to a separate stored data-model design if exact overlapping windows become necessary.

## Reproduction Assessment

Yes. Source inspection gives a deterministic current-main repro by seeding a `blockedUntil`/`blockedModel` subscription-limit block for one model and querying a sibling `forModel`; current main treats it as profile-wide while PR head bypasses it for the sibling model.

## Solution Assessment

Yes, with maintainer acceptance of the storage tradeoff. Reusing the existing `blockedModel` field and mirroring the established `cooldownModel` gate is the narrow owner-boundary fix; a per-model block map would be a larger data-model change.
