## Summary

Keep open: this is a focused auth-profile bug fix, but the new read-side `blockedModel` gate leaves the Codex app-server block writer able to narrow an already-active block for another model, and the external contributor proof is still only a mocked Vitest run.

## What This Changes

Threads WHAM `subscription_limit` failures through `blockedModel`, makes cooldown reads model-aware for `blockedModel`, and adds auth-profile regression tests for WHAM block merging.

## Best Possible Solution

Share the active-block merge semantics across both blocked-profile writers, add coverage for the `codex_rate_limits` writer, then supply redacted real-runtime proof for the reported shared-profile model flow before merge.

## Reproduction Assessment

Yes. Source inspection gives a deterministic reproduction by seeding an active `codex_rate_limits` block for one model through `markAuthProfileBlockedUntil`, recording a second model block on the same profile, and observing the PR read path bypass the first model's still-active block.

## Solution Assessment

No as submitted. Reusing `blockedModel` is the right owner-boundary shape, but the implementation must apply the same conflict-merge rule to the app-server block writer before the new read semantics are safe.
