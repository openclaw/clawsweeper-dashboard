## Summary

Keep this PR open: it fixes the default 300-second case, but it still hard-codes a 315-second reload-handoff limit even though OpenClaw supports configured and indefinite restart-deferral windows. That can reintroduce the same stranded-gateway outcome for valid existing settings, and the submitted proof is simulation-only rather than a real launchd lifecycle result.

## What This Changes

The PR makes the macOS reload handoff wait through the default drain budget and retry `launchctl bootstrap` after a failed reload bootstrap.

## Best Possible Solution

Pass the resolved effective restart-deferral budget into the detached reload handoff, define a safe contract for the indefinite setting, cover both non-default paths, and attach redacted real-launchd proof that the service returns after an active-run reload.
