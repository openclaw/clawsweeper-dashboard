## What This Changes

Fix spawned sub-agents so a restrictive inherited tool policy does not remove bundled MCP server tools that remain available to the parent session.

## System Context

`sessions_spawn` creates a child agent session and carries tool-policy facts from the parent into the child. Bundled MCP tools are added by the per-attempt MCP runtime and then pass through the final effective-tool policy before becoming available to the child model.

## Architecture Diagram

flowchart LR
  A[Parent agent session] --> B[Spawn sub-agent]
  B --> C[Inherited tool policy]
  C --> D[Bundle MCP runtime]
  D --> E[Final effective policy]
  E --> F[Child tool catalog]
  F --> G[Sub-agent tool calls]

## Best Possible Solution

Confirm the current policy order, then preserve the parent’s effective bundled-MCP authorization through child-session inheritance without widening unrelated sub-agent tools or bypassing explicit allow and deny rules.
