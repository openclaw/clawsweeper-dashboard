## Summary

Keep this PR open for revision: it improves the normal timeout case, but the synchronous cleanup can still block beyond five seconds under the exact stalled-process condition the patch claims to bound, and the available proof does not exercise Windows taskkill behavior.

## What This Changes

The PR adds five-second deadlines to Windows QMD taskkill cleanup and avoids forced PID-tree retry after a graceful taskkill timeout.

## Best Possible Solution

Run taskkill through an asynchronous process-cleanup helper that never synchronously blocks the event loop, applies a real deadline, safely falls back through the retained child handle, and is proven on Windows with a deliberately delayed or intercepted taskkill path.
