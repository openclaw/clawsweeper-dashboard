## Summary

This PR remains necessary as a resource-hardening attempt, but the unchanged cap violates both Markdown containment contracts: inline delimiters can collide with an existing 100-backtick run, while fenced payload lines of 100 or more backticks can terminate the generated block. The prior blocking concern therefore remains unresolved.

## What This Changes

The PR caps inline-code and fenced-code backtick delimiters at 100 characters and adds regression tests for long backtick runs.

## Best Possible Solution

Preserve the formatter’s containment invariant and enforce a reasonable payload budget at the owning input boundary; if these helpers must accept arbitrary strings, define an explicitly approved alternate encoding or failure result and prove it across supported Markdown renderers.
