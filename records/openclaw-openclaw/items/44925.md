## Summary

Keep this open: current main has partial failure accounting for subagent completion delivery, but it still uses bounded announce retry/give-up behavior, docs still call announce-back best-effort across gateway restarts, and the linked closing PR is open and conflicting rather than merged.

## What This Changes

The issue asks OpenClaw to stop silently losing subagent completions or timeouts by retrying, notifying, or recovering/restarting instead of leaving the requester waiting.

## Best Possible Solution

Keep this as the canonical maintainer-owned reliability issue until OpenClaw has a durable completion-delivery policy that preserves results, records terminal blocked state, and proves requester/channel-visible behavior across the main subagent paths.
