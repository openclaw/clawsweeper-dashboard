## Label Justifications

- `P1`: The issue affects real subagent/channel workflows where completed work is not delivered back to the requester, but it is not a first-run or whole-runtime outage.
- `impact:message-loss`: The reported and current source behavior can lose requester-visible subagent completion messages even when the child work finishes.
- `impact:session-state`: The failure leaves parent sessions, sessions_yield waiters, task records, and TaskFlows out of sync with completed subagent work.

## Summary

Keep open: current main and v2026.6.11 still have bounded best-effort subagent completion delivery with retry-limit, expiry, suspend, and discard paths; recent v2026.6.11 production evidence reports the same silent requester-visible loss; and the linked closing PR remains open and conflicting rather than merged.

## What This Changes

The issue asks OpenClaw to reliably deliver subagent completion notifications with retry, notification, and recovery instead of silently losing completions on timeout or requester/session failures.

## Best Possible Solution

Keep a core-owned durable completion delivery model that persists completion payloads through retry-limit, expiry, restart, and orphan-prune windows, wakes sessions_yield reliably, records external delivery, and dedupes visible replies.
