## Summary

Keep this open: current main has partial subagent announce hardening, but the core problem is not fully closed because announce delivery still has finite retry/give-up paths, docs still describe best-effort loss on restart, and the direct closing PR remains open and conflicting.

## What This Changes

The issue asks for reliable subagent completion handling so successful results are not silently lost, timeouts notify or recover, and claimed artifacts are verified before completion is announced.

## Best Possible Solution

Adopt one durable completion-delivery design that persists expected completions until ACK or visible failure, wakes or notifies the requester on give-up/timeout, and splits auto-restart or artifact-verification policy into explicit follow-up decisions if needed.

## Reproduction Assessment

Yes from source and report evidence, but not by a live run in this review. The current sessions_spawn/sessions_yield completion path still has finite retry/give-up states, and the issue discussion includes repeated production logs matching those paths.

## Solution Assessment

No, a retry-count-only fix is only a mitigation. The best fix is a single durable delivery/ACK/failure-notification model; auto-restart and file-claim verification should be explicit product decisions rather than hidden side effects.
