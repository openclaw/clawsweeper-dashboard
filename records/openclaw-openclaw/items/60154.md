## Label Justifications

- `P2`: The issue describes a real, source-backed privacy gap in a bounded Feishu/media surface, but it needs product and security design rather than emergency repair.
- `impact:security`: The reported failure mode is cross-account read access to sensitive inbound media through a shared managed media root.

## Summary

Keep open: current main still saves Feishu downloaded media into the shared managed inbound bucket, and neither the Feishu account schema nor current media resolver/staging surfaces support an account-scoped inbound root; the broad media-isolation tracker overlaps but does not fully replace this Feishu-specific security/config slice.

## What This Changes

Request to add per-account Feishu inbound media storage, proposed as `channels.feishu.accounts.<id>.inboundDir`, so multi-account Feishu downloads are isolated by account.

## Best Possible Solution

Define a managed scoped inbound-media/provenance contract for Feishu accounts that constrains storage roots and updates save, resolve, staging, access, cleanup, docs, and tests together.
