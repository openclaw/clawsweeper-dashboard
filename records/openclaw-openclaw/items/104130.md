## Summary

Keep open: current `main` still has the reported pre-commit removal behavior, while this patch follows the established cron reconciliation design, covers all known automatic deletion paths, and has no actionable correctness or security finding. The protected `maintainer` label also requires normal human handling rather than cleanup closure.

## What This Changes

The PR buffers automatic cron `removed` events until durable persistence succeeds, restores live scheduler state after failed writes, and updates regression coverage and plugin-hook documentation.

## Best Possible Solution

Use one shared cron persistence transaction boundary that restores the complete durable-view state on failure and publishes automatic removal reconciliation only after confirmed commit, while preserving existing `started` and `finished` lifecycle timing.
