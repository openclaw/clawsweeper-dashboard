## Summary

This PR should remain open because its new rollback helper ignores a non-throwing skipped persistence result, allowing an automatic `removed` event even when the durable deletion was not written.

Likely related people
- `steipete` — high confidence; feature owner and dominant recent contributor across the cron persistence and lifecycle-event paths.

## What This Changes

This PR defers automatic cron removal events until persistence succeeds, restores cron state after failed writes, adds manual, timer, and startup-catch-up regressions, and updates plugin-hook documentation.

## Best Possible Solution

Represent persistence as an explicit committed or uncommitted result, restore every durable-coupled in-memory projection for either thrown or skipped writes, and publish buffered lifecycle events only after a confirmed commit.

## Solution Assessment

No, not yet. Moving publication to the persistence boundary is the right design, but the boundary must treat the existing false or skipped result as uncommitted rather than recognizing only thrown errors.
