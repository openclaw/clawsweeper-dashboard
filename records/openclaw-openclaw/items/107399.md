## Label Justifications

- `P1`: A reproducible stale-session route can permanently break replies in an active inter-agent workflow without an automatic recovery path.
- `impact:message-loss`: Replies are delivered to an unmonitored ghost session, making them effectively unavailable to the sending agent.
- `impact:session-state`: The defect splits one logical conversation across the canonical main session and a stale persisted session key.

## Summary

The report identifies a credible session-routing defect that can strand inter-agent replies in a stale ghost session, and the open linked fix PR is the appropriate implementation candidate; this issue should remain open until that PR is reviewed and merged or replaced.

## What This Changes

Normalize the `sessions_send` requester provenance key to the canonical session selected by the current `dmScope` rather than preserving a historical stored key.

## Best Possible Solution

Land a focused fix that derives one canonical requester key before provenance, watch registration, same-session detection, and A2A follow-up routing, with regression coverage for both stale `dmScope="main"` sessions and unaffected non-main scopes.

Required: false

## Reproduction Assessment

Yes at source level: retain a DM session key created under a non-main scope, switch or default to `dmScope="main"`, then send and reply through `sessions_send`; the receiving agent is given the stale reply address. A live current-main run was not performed during this read-only review.

## Solution Assessment

Yes in direction: canonicalizing the requester once at the session-tool context boundary is preferable to patching only the provenance field because the same identity also governs watches, same-session checks, visibility, and A2A follow-ups. The linked PR should prove that all those consumers use the same canonical value.
