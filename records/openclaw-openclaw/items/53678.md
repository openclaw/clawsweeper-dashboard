## Summary

Keep open: current main and the latest release still expose only the source-channel timestamp in agent-visible inbound metadata. The request is source-reproducible and aligned with performance observability, but it needs maintainer API/product direction because the field name, timestamp format, and propagation boundary would become a cross-channel contract.

## What This Changes

The issue requests a Gateway-received timestamp in inbound agent metadata so latency can be split between channel delivery delay and OpenClaw processing time.

## Best Possible Solution

Define one additive generic ingress timing contract, expose it consistently through inbound context and agent-visible metadata, document the semantics, and add focused tests proving source timestamp and Gateway receipt timestamp remain distinct.
