## Summary

Keep open: current main and the latest release still expose only the source-channel timestamp in generic inbound and agent-visible metadata, so a Gateway receipt timestamp remains missing and needs cross-channel SDK/product direction.

## What This Changes

Request to add a Gateway-received timestamp to inbound metadata so agents can distinguish channel delivery latency from OpenClaw processing latency.

## Best Possible Solution

Define one additive generic ingress timing contract, reuse existing receive-time sources where available, and expose it consistently through channel inbound context, agent-visible metadata, docs, and focused tests.

## Reproduction Assessment

Yes. Source inspection on current main and `v2026.6.11` shows the generic inbound and agent-visible metadata paths expose the source `timestamp` but no Gateway receipt timestamp; I did not run a live channel flow in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract. The requested field is plausible, but the best implementation should be one additive generic timing contract rather than a per-channel or prompt-only patch.
