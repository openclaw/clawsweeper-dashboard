## Summary

Keep open: current main and the latest release still expose only the source-channel timestamp in generic inbound agent metadata, while separate receive-time state exists internally and is not projected to agents. The gap is source-reproducible, but the field name, format, and propagation boundary need maintainer product/API direction before implementation.

## What This Changes

Add a Gateway-received timestamp to inbound agent metadata so latency can be measured separately from source-channel message time.

## Best Possible Solution

Define one additive generic ingress timing contract, then expose it consistently through inbound context, agent-visible metadata, SDK/docs, and focused cross-channel tests.
