## Summary

Keep open: current main and the latest release still expose the source-channel `timestamp` in agent-visible inbound metadata, but not a generic Gateway-received timestamp. The request remains useful, especially with the related LINE delay report, but it changes a cross-channel/plugin SDK metadata contract and needs maintainer API/product direction before implementation.

## What This Changes

The issue requests a Gateway-received timestamp in inbound metadata so agents and operators can separate channel delivery latency from OpenClaw processing latency.

## Best Possible Solution

Define a documented generic ingress timing contract that captures Gateway receipt at the channel/plugin boundary and projects it consistently to agent-visible metadata or diagnostics without breaking prompt-cache and privacy rules.

## Reproduction Assessment

Yes by source inspection: current main has a source-channel `Timestamp` path and no generic Gateway-received field in the inbound context or agent-visible metadata. I did not run a live channel flow in this read-only review.

## Solution Assessment
