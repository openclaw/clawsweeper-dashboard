## Summary

Keep open: current main and the latest release still expose source-message timestamps in agent-visible inbound metadata, but not a Gateway receipt timestamp. The remaining work is a cross-channel metadata/API contract decision, not a stale or already-implemented cleanup item.

## What This Changes

Requests a Gateway receipt timestamp in inbound metadata so agents can separate source-channel delivery delay from OpenClaw processing latency.

## Best Possible Solution

Define one generic Gateway receipt timestamp contract, then propagate it from channel ingress into inbound context formatting with focused cross-channel coverage.
