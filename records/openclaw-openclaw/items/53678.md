## Summary

Keep open: current main and the latest release still expose the source-channel message timestamp but not a generic Gateway-received timestamp in inbound or agent-visible metadata. The request remains valid observability work, but it defines a cross-channel plugin/SDK metadata contract and needs maintainer product/API direction before implementation.

## What This Changes

The issue requests an agent-visible inbound metadata timestamp for when the Gateway receives a channel message so latency can be split between channel delivery and OpenClaw processing.

## Best Possible Solution

Define one additive generic ingress timing contract, reuse existing internal receive-time sources where available, and expose it consistently through inbound context, agent-visible metadata, docs, and focused tests.

## Reproduction Assessment

Yes. Source inspection on current main shows generic inbound context and agent-visible metadata have only the source `Timestamp`, while internal receive-time state is not propagated to that contract.

## Solution Assessment

Unclear until maintainers choose the public contract. The requested field is plausible, but the maintainable solution should be one additive generic timing contract rather than a per-channel or prompt-only patch.
