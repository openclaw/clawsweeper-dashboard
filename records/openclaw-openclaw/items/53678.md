## Summary

Keep open: current main and v2026.6.11 still expose only the source message timestamp in agent-visible inbound metadata, while the requested Gateway receipt timestamp would be a new public metadata/API contract that needs maintainer direction.

## What This Changes

Add a Gateway receive timestamp to inbound metadata so agents can distinguish channel delivery latency from agent processing latency.

## Best Possible Solution

Define one additive generic ingress timing contract, reuse internal receive-time facts where available, and expose it consistently through inbound context, agent-visible metadata, docs, and focused tests.
