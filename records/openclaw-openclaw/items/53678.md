## Summary

Keep open: current main and the latest release still expose the source-channel message timestamp in inbound metadata, but not a separate Gateway receipt timestamp. Internal `receivedAt` state exists for receive/queue mechanics, yet it is not propagated into the shared agent-visible metadata contract, so this needs maintainer API/product direction before implementation.

## What This Changes

Request to add a Gateway receipt timestamp to inbound metadata so agents can distinguish source-channel delay from OpenClaw processing latency.

## Best Possible Solution

Define one additive generic ingress timing contract, reuse existing receive-time sources where appropriate, and expose it consistently through inbound context, agent-visible metadata, docs, and focused tests.

## Reproduction Assessment

Yes. Source inspection on current main and `v2026.6.11` shows generic inbound context and agent-visible metadata have only the source `Timestamp`, while internal receive-time state is not propagated to that contract.

## Solution Assessment

Unclear until maintainers choose the public contract. The requested field is plausible, but the maintainable solution should be one additive generic timing contract rather than a per-channel or prompt-only patch.
