## Summary

Keep open: current main and v2026.6.11 still expose only the source message timestamp in agent-visible inbound metadata. Internal receive-time state exists, but it is not wired to the generic inbound context or prompt metadata, and the related cache-stability work in https://github.com/openclaw/openclaw/issues/100271 makes the public contract a maintainer decision.

## What This Changes

Request to add a Gateway receipt timestamp to generic inbound metadata so agents can distinguish source-channel latency from OpenClaw processing latency.

## Best Possible Solution

Define one additive, cache-aware generic ingress timing contract, reuse internal receive-time facts where available, and expose it consistently through inbound context, agent-visible metadata, docs, and focused tests.
