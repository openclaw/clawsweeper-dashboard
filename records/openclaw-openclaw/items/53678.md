## Summary

Keep open: current main and the latest release still expose the source-channel timestamp in generic inbound agent metadata, but not a separate Gateway receipt timestamp. The Discord and LINE latency reports support the need, but adding this becomes an agent-visible cross-channel metadata contract that needs maintainer API/product direction.

## What This Changes

Request adding a Gateway receipt timestamp to generic inbound metadata so agents can separate source-channel delay from OpenClaw processing latency.

## Best Possible Solution

Define one additive generic ingress timing contract, then expose it consistently through inbound context, message_received hooks, agent-visible metadata, docs, and focused cross-channel tests.
