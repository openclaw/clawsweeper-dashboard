## Summary

Keep open: current main still exposes only the source message timestamp in the generic inbound/agent-visible metadata path, while Gateway receive-time facts exist only in internal queue/receive contexts and do not satisfy this cross-channel metadata request.

## What This Changes

Request to add a Gateway-received timestamp such as `receivedAt` or `gatewayReceivedAt` to inbound metadata so agents and diagnostics can separate channel delivery latency from OpenClaw processing latency.

## Best Possible Solution

Define one additive generic ingress timing contract, reuse internal receive-time facts where available, and expose it consistently through inbound context, agent-visible metadata, docs, and focused tests.
