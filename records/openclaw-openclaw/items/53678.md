## Summary

Keep open: current main and the latest release still expose the source-channel timestamp in inbound prompt metadata, while existing `receivedAt` fields stay internal to channel receive/queue plumbing and are not projected into the agent-visible inbound metadata. The request remains useful, but it defines a cross-channel prompt/SDK metadata contract, so it needs maintainer API/product direction before implementation.

## What This Changes

Add a Gateway receipt timestamp to inbound metadata so agents can separate channel delivery latency from OpenClaw processing latency.

## Best Possible Solution

Define one cross-channel receipt-time contract, probably a volatile per-turn `gateway_received_at` or `received_at` field populated from the earliest Gateway/channel ingress point, with source timestamp preserved separately and focused SDK/channel tests proving prompt-cache-safe placement.
