## Summary

Keep open: current main and the latest release still expose the source-channel timestamp in generic inbound agent metadata, but not a Gateway-received timestamp. The gap is source-reproducible, but adding the field would define a cross-channel, agent-visible metadata contract that needs maintainer API/product direction.

## What This Changes

Add a Gateway receipt timestamp such as `receivedAt` or `gatewayReceivedAt` to inbound metadata so agents can separate channel delivery delay from OpenClaw processing latency.

## Best Possible Solution

Define one additive generic ingress timing contract, then expose it consistently through inbound context, agent-visible metadata, SDK/docs, and focused cross-channel tests.
