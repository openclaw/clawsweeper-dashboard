## Summary

Keep open: current main and the latest release still expose the source-channel timestamp in agent-visible inbound metadata, but not a Gateway receipt timestamp. Internal receive timestamps exist in durable receive paths, so the remaining work is a cross-channel API/prompt contract decision rather than an already-implemented fix.

## What This Changes

Request to add a Gateway receipt timestamp to inbound metadata so agents can separate channel delivery delay from OpenClaw processing latency.

## Best Possible Solution

Expose one maintainer-approved cross-channel receipt timestamp contract from ingress through agent-visible metadata while preserving the existing source timestamp.
