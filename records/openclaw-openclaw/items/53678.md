## Summary

Keep open: current main and the latest release still expose only source-message timestamps in agent-visible inbound metadata, while the existing internal receive timestamps are not propagated as a stable cross-channel Gateway receipt field. The request remains useful, but it needs maintainer API/product direction because the fix would define a plugin SDK and prompt metadata contract across channel surfaces.

## What This Changes

Add a Gateway receipt timestamp such as `receivedAt` or `gatewayReceivedAt` to inbound metadata so agents can distinguish channel delivery latency from OpenClaw processing latency.

## Best Possible Solution

Define one generic receipt-timestamp contract, choose the trusted vs untrusted metadata location and timestamp format, then propagate it through the shared inbound context/envelope APIs with cross-channel tests.
