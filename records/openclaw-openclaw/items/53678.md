## Summary

Keep open: current main still does not expose a generic Gateway receive timestamp in inbound or agent-visible metadata. Internal receive-time state exists in newer channel receive paths, but it is not the requested cross-channel metadata contract.

## What This Changes

The issue requests a `receivedAt` or `gatewayReceivedAt` field in inbound metadata so agents can separate channel delivery latency from OpenClaw processing latency.

## Best Possible Solution

Define one additive generic ingress timing contract, reuse internal receive-time facts where available, and expose it consistently through inbound context, agent-visible metadata, docs, and focused tests.

## Reproduction Assessment

Yes. Source inspection on current main shows generic inbound context accepts only source `timestamp`, and prompt metadata renders only `conversationInfo.timestamp`; targeted searches found no public `receivedAt` or `gatewayReceivedAt` field in the relevant inbound metadata paths.

## Solution Assessment

Unclear until maintainers choose the public contract. The requested field is plausible, but the maintainable solution should be one additive generic timing contract rather than a per-channel or prompt-only patch.
