## Summary

Keep open: current `main` and `v2026.6.11` still expose the source-channel message timestamp but not a Gateway-received timestamp in generic inbound or agent-visible metadata. The request is useful, but it creates a cross-channel plugin SDK and prompt metadata contract, so it needs maintainer product/API direction before implementation.

## What This Changes

Request to add a Gateway-received timestamp to inbound metadata so agents can distinguish channel delivery delay from OpenClaw processing latency.

## Best Possible Solution

Define one additive generic ingress timing contract, reuse existing internal receive-time sources where available, and expose it consistently through the SDK inbound params, TemplateContext, agent-visible metadata, docs, and focused tests.
