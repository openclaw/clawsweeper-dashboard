Keep open: current main still does not expose a Gateway receive timestamp through the generic inbound event context or the agent-visible inbound metadata block, while existing receive-time fields are internal telemetry/queue state rather than the requested per-message metadata contract.

## What This Changes

The issue requests a Gateway-received timestamp in inbound metadata so agents and operators can separate channel delivery delay from OpenClaw processing latency.

## Best Possible Solution

Keep the issue open for a maintainer decision on a canonical receive-time contract, then implement it once across inbound context, agent metadata, docs, and focused tests.
