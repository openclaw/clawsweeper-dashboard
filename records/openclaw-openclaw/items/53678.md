## Summary

Keep open: current main and the latest release still expose the source-channel timestamp in agent-visible inbound metadata, but not a separate Gateway receipt timestamp. The request is source-proven and useful for latency attribution, but it defines a durable cross-channel prompt/plugin metadata contract that needs maintainer product direction before implementation.

## What This Changes

The issue requests adding a Gateway receipt timestamp such as `receivedAt` or `gatewayReceivedAt` to inbound metadata so agents can separate channel delivery latency from processing latency.

## Best Possible Solution

Define one generic Gateway receipt timestamp contract, then propagate it from channel ingress through `MsgContext`, plugin SDK helpers, and inbound prompt metadata with focused cross-channel coverage.
