## Summary

Keep open: current main still lacks a generic Gateway receive timestamp in agent-visible inbound metadata, and the related reports only cover timestamp precision or channel-specific latency incidents. The remaining decision is the public timing contract, not whether the source gap exists.

## What This Changes

Request to expose a Gateway receive timestamp such as `receivedAt` or `gatewayReceivedAt` in inbound metadata so agents can separate channel delivery latency from processing latency.

## Best Possible Solution

Define one additive generic ingress timing contract, reuse existing receive-time facts where available, and expose it consistently through inbound context, agent-visible metadata, SDK docs, and focused tests.
