## Summary

Keep open: current main and v2026.6.11 still carry the source-channel timestamp into generic inbound context and prompt metadata, while internal receive-time state is not exposed as an agent-visible Gateway receipt contract. The request is useful and aligned, but it needs maintainer product/API direction before choosing the cross-channel field name, format, and propagation boundary.

## What This Changes

Request to add a Gateway-received timestamp such as `receivedAt` or `gatewayReceivedAt` to inbound metadata so agents can separate channel delivery delay from OpenClaw processing latency.

## Best Possible Solution

Define one additive generic ingress timing contract, reuse existing internal receive-time sources where their semantics match, and expose it consistently through inbound context, agent-visible metadata, docs, and representative channel tests.
