## Summary

## What This Changes

The PR updates the llama.cpp provider from optional `node-llama-cpp` 3.18.1 to a direct `^3.19.0` dependency, adds `nodeLlamaCppPostinstall: "ignoreFailedBuild"` package config, and regenerates pnpm/npm shrinkwrap metadata.

## Best Possible Solution

Preserve the optional native dependency contract; if maintainers want the 3.19.0 upgrade or `ignoreFailedBuild`, land it through the owner/security dependency lane with reproducible shrinkwrap and real failing-install proof.

## Reproduction Assessment

Yes for the PR defect: CI and source inspection show the direct dependency creates a shrinkwrap override failure on the PR head. No high-confidence reproduction was provided for the rare user install environment; the PR body explicitly says it was not reproduced locally.

## Solution Assessment

No. The proposed fix is not the best shape because it removes the current optional native dependency contract; the safer path is to preserve optional install semantics and handle any version/config change through owner-approved dependency generation with real install proof.
