## Summary

This PR appears to make the right narrow separation: sandbox-bound `sessionKey` remains the gateway identity input, while a distinct live-run key is used only for the terminal source-reply receipt. Current source and the earlier split-session fix support that boundary, but the updated branch still lacks inspectable after-fix real behavior proof from a sandboxed channel turn, so it should remain open pending that merge gate.

## What This Changes

The branch threads the live run session key into the message tool and uses it only to locate restart-recovery ownership for terminal source replies, while retaining the sandbox session key for gateway authorization.

## System Context

Agent runtimes create message tools for channel replies. In sandboxed runtimes, the capability-bound sandbox session authorizes a gateway action, while the live run session owns durable restart-recovery and source-reply state that determines whether the visible reply may be delivered.
