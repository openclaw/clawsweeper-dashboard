## What This Changes

Add bounded, escalating retry behavior and an operator-visible terminal failure for macOS SSH control-tunnel restarts when a remote gateway cannot become usable.

## System Context

The macOS app’s Remote-over-SSH mode creates a local SSH control tunnel, then the control channel uses that local endpoint to communicate with the remote Gateway. Tunnel supervision currently decides when to tear down and recreate the SSH process, so its retry policy controls process churn and how remote users recover after a failed connection.

## Architecture Diagram

flowchart LR

  B --> C[SSH control tunnel]
  C --> D[Local forwarded endpoint]
  D --> E[Control channel]
  E --> F[Remote Gateway]
  C --> G[Restart policy]
  G --> H[Backoff, terminal state, or user retry]

## Best Possible Solution

Define a tunnel-local policy keyed to the effective SSH target and relevant configuration: escalate and cap failed recreations, expose a clear terminal diagnostic and explicit retry action, and reset the budget only for a materially changed target/configuration or that explicit user retry.

- **Keep the current flat retry policy:** Avoid new recovery semantics but retain continuous process and log churn for permanently unreachable targets.
