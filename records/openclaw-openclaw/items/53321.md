## Summary

Keep open: current main and v2026.6.11 still handle token pressure through compaction, memory flush, successor transcript rotation, and daily/idle/manual reset, but they do not implement the requested configurable context-threshold auto-rollover with durable handoff and fresh-session routing.

## What This Changes

The issue requests configurable automatic session splitting when context usage nears the model limit, preserving continuity through memory flush, handoff summary injection, and subsequent routing to a fresh backing session.

## Best Possible Solution

Define one maintainer-approved, opt-in session lifecycle policy that covers token-pressure rollover, durable handoff, delivery identity preservation, docs, config schema, and upgrade behavior.
