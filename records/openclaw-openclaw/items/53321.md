Keep open: current main still handles token pressure with compaction, memory flush, transcript rotation, daily/idle reset, and manual reset, but not the requested configurable context-threshold auto split that creates a fresh backing session and routes future channel messages through a durable handoff. This remains a core session-lifecycle product/config decision rather than stale cleanup.

## What This Changes

Request a configurable automatic session split when context usage nears the model window, with memory flush, continuity handoff, fresh-session routing, and no manual `/new`.

## Best Possible Solution

Design one core context-pressure rollover policy that layers beside compaction and reset: canonical config, threshold evaluation before session reuse, durable handoff state, preserved delivery identity, idempotent fresh-session routing, docs, and focused upgrade tests.
