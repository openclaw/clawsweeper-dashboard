## Summary

This PR targets a real, severe delivery deadlock, but the revised patch still places an unconditional 30-second default around the entire composed `beforeDeliver` chain. That can preempt existing hook-owned deadlines, silently cancel replies, and does not identify the actual production hook that stalls; the supplied recovery evidence remains synthetic rather than a live assembled channel run.

## What This Changes

The branch adds an optional `beforeDeliverTimeoutMs` dispatcher API with a 30-second default, races the complete hook chain against that deadline, adds two timeout regression tests, and adds a synthetic lane-recovery proof script.

## Best Possible Solution

Identify the non-settling hook or composition boundary and enforce recovery through its existing owner contract. If maintainers intentionally want a dispatcher-wide safety deadline, use a distinct timeout outcome, derive a budget compatible with all composed hooks, wire the actual configuration owner, preserve cancellation and settlement observability, add deterministic tests, and prove recovery through a live assembled channel path.
