## Summary

The intended composer states are well proven and the existing attachment payload path is the right boundary, but the repaired head still has a blocking state-loss bug: concurrent long-paste reads append against the same stale render snapshot, so one completed paste can replace another. This maintainer-authored, protected-label PR should remain open for a narrow autofix and explicit acceptance of the new default paste behavior.

## What This Changes

The branch converts plain-text pastes over 1000 characters into compact, restorable `text/plain` composer attachments and adds focused rendering, restore, removal, and send-path coverage.

## Best Possible Solution

Add an owner-side current-state attachment append/update operation, use it when each asynchronous paste conversion completes, and prove two delayed long pastes preserve both attachments while retaining image precedence, restore behavior, and the existing payload lifecycle.
