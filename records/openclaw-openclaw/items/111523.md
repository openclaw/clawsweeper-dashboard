## Summary

Keep this PR open for maintainer review. The prior parser findings appear addressed: the guard now evaluates text before the candidate separator and the tests cover both affected parsing entry points, conventional uppercase paths, punctuation-delimited paths, and the reported code-header cases. The remaining decision is intentional compatibility policy: lowercase Windows drive letters immediately after a block keyword are inherently indistinguishable from the reported code form, so a maintainer must explicitly accept the new code-biased behavior before merge.

## What This Changes

The PR changes malformed-JSON repair so lowercase one-letter code block headers such as `if x:` and `as f:` preserve following newline escapes, while tests retain recovery for conventional Windows-path forms.

## System Context

OpenClaw repairs malformed JSON from model tool calls before command strings and file content reach agent tools. Its Windows-path heuristic prevents invalid path backslashes from being decoded as JSON escapes, but can also mistake a code header ending in `&lt;letter>:` for a drive prefix.
