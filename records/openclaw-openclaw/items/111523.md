## Label Justifications

- `P1`: The patch can silently corrupt valid Windows path arguments in common command payloads rather than merely rejecting malformed input.
- `merge-risk: 🚨 compatibility`: The changed JSON-repair fallback alters how existing malformed Windows paths with `\n` or `\t` are decoded when prior payload text contains code punctuation.

## Summary

The reported parser bug is real, but this patch broadens the exclusion over the entire 160-character prefix and regresses legitimate Windows paths that follow ordinary code or shell punctuation; keep it open for a narrow suffix-aware repair and real after-fix evidence.

## What This Changes

The branch rejects code-like characters in the JSON repair helper’s Windows-path prefix heuristic and adds regression cases for multiline Python and shell payloads.

## Best Possible Solution

Replace the whole-tail marker rejection with logic that evaluates only the active drive-path candidate, then cover both the reported code-header cases and valid control-escape path segments after realistic shell/code text.
