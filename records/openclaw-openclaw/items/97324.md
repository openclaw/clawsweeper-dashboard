## Summary

Keep open. Two independent reports show the same `stopReason=stop`, tool-present, zero-payload failure across providers, but the available evidence does not establish that the safe terminal path corrupts later session state or that retrying a current replay-unsafe tool attempt is safe. The narrower recovery policy needs an agent-runtime owner decision before implementation.

## What This Changes

Investigate and safely recover or quarantine incomplete embedded-agent turns that contain tool activity but no response payload, without allowing malformed state to affect later prompts.

## System Context

The embedded agent runner turns provider streaming output and tool activity into an assistant attempt, then decides whether to retry, surface an error, or retain state for the session. Its terminal outcome is consumed by channel and cron callers, which may deliver a user-visible failure or schedule later work.

## Best Possible Solution

Define one explicit terminal-state contract for incomplete tool turns: preserve the completed safe transcript boundary, record enough structured outcome data to diagnose the attempt, and route only demonstrably side-effect-free cases into retry or model fallback; add focused regression coverage for both safe recovery and no-duplicate-side-effect paths.
