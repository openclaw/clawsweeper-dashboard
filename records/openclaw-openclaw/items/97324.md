## Summary

Keep open: current main still routes replay-unsafe payloads=0/tools>0 empty turns to the incomplete-turn error path instead of retry/fallback, and the latest field comment adds recurring cron failures on v2026.6.11. This needs maintainer policy on safe retry, fallback, or quarantine rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to prevent replay-unsafe incomplete assistant/tool turns with no visible payload from poisoning later session state and to retry, fall back, or quarantine them with clearer diagnostics.

## Best Possible Solution

Define a current-attempt replay-safety and quarantine policy for tools>0/payloads=0 stop turns, then implement one recovery path with embedded-runner and cron/fallback coverage while keeping real side effects fail-closed.
