## Summary

Keep open conservatively. The reports show a repeated live `stopReason=stop`, `tools>0`, `payloads=0`, `replaySafe=no` signature with a user-visible failure, but the available evidence does not establish that current `main` repairs, quarantines, or safely excludes this exact current-attempt shape from later session construction. The related retry work addresses clean silent provider-error turns, not an incomplete turn that already contains a replay-unsafe tool call.

## What This Changes

Add a safe recovery or quarantine path for incomplete assistant turns that have tool activity but no payload, preventing unsafe state from reaching later session prompts.

## System Context

The embedded agent runner collects an assistant attempt, its tool activity, and replay metadata before producing a user response and updating the session transcript. Incomplete-turn handling decides whether to retry, surface an error, or preserve enough state for later prompt construction and channel delivery.

## Best Possible Solution

Define and implement one explicit terminal-state contract for incomplete current attempts with tool activity: record whether the tool executed, exclude unresolved tool state from subsequent prompts, and surface a structured recovery outcome without blindly retrying unsafe work.
