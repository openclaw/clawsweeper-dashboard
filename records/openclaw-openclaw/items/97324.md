## Summary

Keep open: current main still treats the reported replay-unsafe empty stop/tool turn as an incomplete abandoned run and skips the empty-response retry when replay metadata has potential side effects. The remaining fix is a maintainer policy call on safe retry/fallback versus durable quarantine, not a cleanup close.

## What This Changes

The issue asks OpenClaw to prevent replay-unsafe incomplete turns with tool activity and zero payloads from corrupting later session or prompt state.

## Best Possible Solution

Define a maintainer-approved replay-safety policy for replay-unsafe empty stop/tool turns, then implement narrow retry/fallback or explicit quarantine so malformed attempts cannot feed later prompts.

Options:

- **Current-attempt-safe retry plus quarantine (recommended):** Track current-attempt side effects separately, retry/fallback only when the failed attempt itself is safe, and persist/log a quarantine or branch record when it is not.
- **Fail closed with better quarantine only:** Keep replay-unsafe turns non-retryable, but make the abandoned/quarantine outcome durable and diagnostic enough to protect later prompts and operator triage.
- **Broader retry despite replayUnsafe:** Retry all empty stop/tool turns even when replay metadata is unsafe, accepting the risk of duplicated side-effectful tool work.

## Reproduction Assessment

Yes at source level, but not as a fresh live run. Current main still skips empty-response retry when replay metadata reports potential side effects and then surfaces the incomplete-turn path with replay/liveness metadata.

## Solution Assessment

No for a blanket retry of `replaySafe=no` turns. The safer fix is to distinguish current-attempt side effects from accumulated replay state and add an explicit quarantine/diagnostic path for turns that remain unsafe.
