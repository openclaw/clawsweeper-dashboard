## Summary

Keep open: current main still surfaces the replay-unsafe `tools>0`/`payloads=0` incomplete-turn path as a user error, and v2026.6.11 has the same retry gates. Fresh field evidence shows recurring cron failures on the latest release, while related PRs cover adjacent retry/fallback layers rather than the full replay-unsafe quarantine policy.

## What This Changes

The issue requests safer handling for replay-unsafe embedded turns where a tool call is present but no user payload is produced, including retry/fallback behavior and durable repair or quarantine diagnostics.

## Best Possible Solution

Adopt a maintainer-approved current-attempt replay-safety policy that retries or fails over malformed empty turns only when no same-attempt side effects were committed, and records durable quarantine or diagnostic state when the runner must fail closed.
