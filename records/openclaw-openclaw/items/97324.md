## Summary

Keep open: current main still treats `payloads=0` plus replay-unsafe tool activity as an incomplete turn that skips the empty-response retry budget and returns an error, and the newer cron evidence shows this is still observable on v2026.6.11. The remaining work is policy-sensitive because retrying replay-unsafe tool turns can duplicate side effects, while the requested durable quarantine/repair record is not implemented by the current metadata-only handling.

## What This Changes

The issue reports replay-unsafe incomplete embedded-agent turns with tool calls and zero payloads, asking for retry, failover, or quarantine behavior that prevents later prompt/session poisoning.

## Best Possible Solution

Define one maintainer-approved recovery policy for replay-unsafe `tools>0/payloads=0` turns: safe retry or fallback only when current-attempt side effects are proven absent, and durable quarantine/repair logging when the turn must fail closed.
