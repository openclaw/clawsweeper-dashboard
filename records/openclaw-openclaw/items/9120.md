## Summary

Current main and v2026.6.11 already batch rapid same-sender messages through renewable inbound debounce, but they do not implement user-declared hold-until-final continuation across longer pauses. Related reviews explicitly distinguish marker continuation from adaptive debounce, and prior maintainer-side discussion leaves this product/API choice open, so the issue remains necessary.

## What This Changes

Add a configurable suffix marker that buffers marked inbound message fragments until an unmarked fragment or timeout completes the batch.

## Best Possible Solution

If explicit long-pause composition is desired, extend one shared inbound aggregation state machine with typed marker and timeout semantics plus clear flush and recovery rules; otherwise retain renewable debounce as the sole supported pre-run batching contract.
