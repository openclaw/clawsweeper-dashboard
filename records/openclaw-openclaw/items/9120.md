## Summary

Keep open. Current main and v2026.6.11 have fixed timer-based same-sender inbound debouncing and collect-mode queueing, but they do not implement the requested marker-controlled buffer that holds marked fragments until a later unmarked message; this remains a product/API decision.

## What This Changes

Add configurable marker-controlled inbound message batching that buffers marked fragments until an unmarked final message to reduce redundant agent turns.

## Best Possible Solution

Keep fixed debounce as the baseline; if maintainers want this workflow, design one opt-in generic ingress continuation contract with typed schema/docs, marker stripping, timeout behavior, and representative channel tests.
