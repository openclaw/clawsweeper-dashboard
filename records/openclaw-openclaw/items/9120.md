## Summary

Keep open. Current main and v2026.6.11 still provide timer-based inbound debouncing and queue modes, but not user-controlled continuation markers; the remaining work is a feature/config/product decision rather than stale or implemented.

## What This Changes

Request marker-controlled batching for rapid inbound messages so continuation-marked fragments buffer until a final unmarked message invokes one agent turn.

## Best Possible Solution

Maintainers should decide whether marker-controlled continuation belongs in core ingress or a plugin/API seam; if accepted, implement it as opt-in schema/docs/runtime/tests with marker stripping, timeout, media/control-command, and typing semantics.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature request. Source, docs, tests, and the latest release provide a high-confidence behavior check that current OpenClaw has timer-based batching but not marker-controlled continuation.

## Solution Assessment

No for automation: this is not a strict bug fix. The maintainable path requires a maintainer choice about whether marker syntax belongs in core, a plugin/API seam, or documentation of the existing debounce/queue modes as the supported answer.
