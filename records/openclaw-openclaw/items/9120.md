## Summary

Keep open. Current main and v2026.6.11 still provide fixed timer-based inbound debounce and active-run collect queueing, but not the requested marker-controlled hold-and-flush behavior; adding it would create public config and session-ingress semantics that need maintainer product/API direction.

## What This Changes

Request to add an opt-in message continuation marker, timeout, and typing behavior so marked inbound fragments buffer until a later unmarked message is sent as one agent turn.

## Best Possible Solution

Keep the timer-based debounce baseline; if maintainers want this workflow, add one opt-in generic ingress continuation contract with typed schema/docs, marker stripping, timeout behavior, and media/control-command/transcript/typing rules.
