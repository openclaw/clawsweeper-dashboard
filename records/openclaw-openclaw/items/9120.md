## Summary

Keep open. Current main and v2026.6.11 support timer-based same-sender inbound debounce and collect/steer queueing, but not the requested marker-controlled continuation workflow; accepting it still needs a maintainer product/API decision because it adds config and changes how inbound fragments become an agent turn.

## What This Changes

The issue requests a configurable continuation marker that buffers marked inbound message fragments and invokes the agent only when a later unmarked final message arrives.

## Best Possible Solution

Keep the fixed timer-based debounce baseline; if maintainers want this workflow, design one opt-in generic session-ingress continuation or bundle contract with schema/docs/tests, marker stripping, timeout behavior, and media/control-command rules.

## Reproduction Assessment

Not applicable as a bug repro: this is a feature request. Source, docs, tests, and the latest release give a high-confidence behavior check that current OpenClaw has timer-based batching but not marker-controlled continuation.

## Solution Assessment

No for automation: this is not a strict bug fix. The maintainable path requires a maintainer choice about whether marker syntax belongs in core, a plugin/API seam, or documentation of the existing debounce/queue modes as the supported answer.
