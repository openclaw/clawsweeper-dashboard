## Summary

Keep open. Current main and the latest release still provide timer-based inbound debouncing and active-run collect queueing, but not the requested marker-controlled continuation flow; accepting it still needs maintainer product/API judgment because it adds config and changes how inbound fragments become one agent turn.

## What This Changes

The issue requests an opt-in message continuation marker that buffers marked inbound fragments and invokes the agent only when a later unmarked message arrives.

## Best Possible Solution

Keep the timer-based debounce baseline; if maintainers want this workflow, design one opt-in generic continuation ingress contract with schema, docs, tests, marker stripping, timeout behavior, and media/control-command/typing rules.

## Reproduction Assessment

Not applicable as a bug repro: this is a feature request. Source, docs, tests, and v2026.6.11 give a high-confidence behavior check that current OpenClaw has timer-based batching but not marker-controlled continuation.

## Solution Assessment

No for automation. The maintainable solution needs maintainer choice about whether marker syntax belongs in core ingress, a plugin/API seam, or documentation of existing debounce and collect modes as the supported answer.
