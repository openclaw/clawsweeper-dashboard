## Summary

Keep open. Current main and v2026.6.11 support renewable timer-based inbound debouncing and active-run collect batching, but they do not provide explicit user-controlled continuation markers; the remaining choice between timer-only behavior, a generic aggregation seam, and new core configuration requires maintainer product direction.

## What This Changes

Add an optional continuation marker that buffers marked inbound fragments until an unmarked message or timeout releases one combined agent turn.

## Best Possible Solution

Define one generic pre-agent inbound aggregation contract with explicit keying, flush, timeout, command/media, restart, and typing behavior; expose marker semantics through that contract only if maintainers choose it over documenting the existing timer-based controls.
