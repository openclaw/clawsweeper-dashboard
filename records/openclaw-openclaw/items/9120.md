## Summary

Keep open. Current main and the latest release still have timer-based inbound debounce plus active-run collect queueing, but not the requested marker-controlled continuation buffer that waits for an unmarked final message before invoking the agent.

## What This Changes

The issue requests configurable user-controlled batching for rapid multi-message input using a continuation marker such as `(cont)`.

## Best Possible Solution

Keep this as the focused marker-controlled continuation design item until maintainers approve a shared inbound/plugin API contract or explicitly decide that existing debounce and collect modes are the intended answer.
