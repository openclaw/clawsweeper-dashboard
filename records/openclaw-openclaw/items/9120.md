## Summary

Keep open. Current main still has timer-based inbound debounce and collect-mode queue batching, but it does not implement the requested user-controlled continuation marker, marker timeout, marker stripping, or continuation-specific typing behavior; the related Batch API issue only partially overlaps on cost savings.

## What This Changes

The issue requests a configurable message continuation marker that buffers marked inbound fragments and dispatches them as one agent turn when a later unmarked message arrives.

## Best Possible Solution

Keep this as the focused marker-controlled continuation design item until maintainers approve a shared inbound or plugin API contract, or explicitly decide that existing timer-based batching is the supported answer.

## Reproduction Assessment

Not applicable: this is a feature request rather than a broken existing behavior report. Source inspection gives high-confidence evidence that current main supports timer-based batching but not marker-controlled continuation buffering.

## Solution Assessment

No for automatic implementation: the proposed marker, timeout, queue mode, and typing mode are plausible but add core config and turn semantics. The safer path is a maintainer-approved shared inbound or plugin/API continuation contract, or an explicit product decision that existing debounce/collect behavior is enough.
