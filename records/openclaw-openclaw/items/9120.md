## Summary

Keep open. Current main and the latest release have timer-based inbound debouncing and active-run queue batching, but they still do not implement the requested user-controlled continuation marker that buffers marked fragments until a later unmarked message arrives; the existing issue discussion also has prior reviews keeping this open for maintainer product/API follow-up.

## What This Changes

The issue requests a configurable continuation marker that buffers multi-part user messages until a final unmarked message arrives, reducing redundant agent turns and context-load cost.

## Best Possible Solution

Keep this as the focused marker-controlled continuation design item until maintainers approve a shared inbound/plugin API contract or explicitly decide that existing timer-based batching is the supported answer.

## Reproduction Assessment

Not applicable: this is a feature request rather than a broken existing behavior report. Source inspection gives high-confidence evidence that current main supports fixed-window batching but not marker-controlled continuation buffering.

## Solution Assessment

No, not as an automatic implementation: the marker, timeout, queue mode, and typing mode are plausible but add core config and session turn semantics. The best path is maintainer-approved shared inbound or plugin/API continuation behavior, or an explicit product decision that existing batching is enough.
