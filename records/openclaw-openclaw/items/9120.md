## Summary

Keep open. Current main and the latest release still provide timer-based inbound debouncing and active-run collect queueing, but not the requested marker-controlled continuation buffer that waits for an unmarked final message before invoking the agent.

## What This Changes

The issue requests marker-controlled batching for multi-part inbound user messages so marked fragments are buffered until a final unmarked message invokes one agent turn.

## Best Possible Solution

Keep this as the focused marker-controlled continuation design item until maintainers approve shared inbound/plugin API semantics or explicitly decide that existing timer-based batching is sufficient.

## Reproduction Assessment

Not applicable: this is a feature request, not a broken existing behavior report. Source inspection gives high-confidence evidence that current main supports timer-based inbound debounce and active-run collect batching, but not marker-controlled continuation buffering.

## Solution Assessment

No, not as an automatic fix. The proposed marker, timeout, queue mode, and typing behavior are plausible, but they add core config and session turn semantics that need maintainer-approved shared inbound or plugin/API design.
