## Summary

Keep open. Current main and v2026.6.11 still provide timer-based inbound debounce and active-run collect queueing, but not the requested user-controlled continuation marker; adding it would introduce public config and ingress/session semantics that need maintainer product/API direction.

## What This Changes

The issue requests a configurable `(cont)`-style marker that buffers multiple inbound user message fragments and invokes one agent turn when an unmarked final message arrives.

## Best Possible Solution

Keep the timer-based debounce baseline; if maintainers want this workflow, design one opt-in generic continuation ingress contract with schema, docs, tests, marker stripping, timeout behavior, and media/control-command/typing rules.
