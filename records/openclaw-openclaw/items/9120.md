## Summary

Keep open. Current main and v2026.6.11 provide renewable timer-based inbound batching and active-run collect queueing, but neither implements explicit marker-controlled buffering; related issues cover different policies, and the remaining core-versus-plugin contract requires maintainer direction.

## What This Changes

Add an opt-in continuation marker that buffers marked inbound fragments until an unmarked message or timeout triggers one combined agent turn.

## Best Possible Solution

Define one typed pre-agent aggregation contract, preferably as a generic plugin hook with marker syntax shipped externally unless maintainers explicitly choose shared core semantics, and specify flush, timeout, marker stripping, media, command, restart, and typing behavior before implementation.

- **Keep debounce only:** Treat renewable idle-time debounce as the supported cost-saving workflow and decline explicit marker-controlled completion.
