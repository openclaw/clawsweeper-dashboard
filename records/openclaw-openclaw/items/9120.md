## Summary

Keep open. The requested sender-controlled continuation marker remains a distinct product capability from the existing timer-based inbound debounce and active-run queue collection, and the recent maintainer-side review explicitly retained it for product follow-up.

## What This Changes

Add configurable marker-based inbound batching that holds marked message fragments until an unmarked message triggers one combined agent turn.

## Best Possible Solution

Define one documented shared inbound-continuation contract, preferably as a generic inbound policy or a narrowly scoped plugin SDK seam, then implement it with regression coverage for final-message flush, timeout, commands, media, queue interaction, and typing behavior.
