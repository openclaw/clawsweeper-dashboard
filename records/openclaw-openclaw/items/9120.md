## Summary

Keep open. Current main and v2026.6.11 support timer-based same-sender inbound debounce plus active-run queue modes, but they do not implement the requested marker-controlled continuation workflow; accepting it still needs a maintainer product/API decision because it adds config and changes how inbound fragments become an agent turn.

## What This Changes

The issue requests a configurable message continuation marker that buffers marked inbound fragments and invokes the agent only when a later unmarked message arrives.

## Best Possible Solution

Keep the existing timer-based debounce and queue baseline; if maintainers want this workflow, design one opt-in generic session-ingress continuation contract or plugin SDK seam with schema, docs, tests, marker stripping, timeout behavior, and media/control-command rules.

## Reproduction Assessment

Not applicable as a bug repro: this is a feature request. Source, docs, and the latest release give a high-confidence behavior check that current OpenClaw has timer-based batching but not marker-controlled continuation.

## Solution Assessment

No for automation: adding marker syntax is not a narrow bug fix. The maintainable path needs a maintainer decision about whether marker-controlled ingress belongs in core, plugin APIs, or documentation of current queue/debounce modes.
