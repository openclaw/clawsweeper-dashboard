## Summary

Keep open. Current `main` and v2026.6.11 still provide timer-based inbound debounce and collect-queue batching, but not the requested marker-controlled hold-and-flush behavior; the issue remains a product/API decision rather than a cleanup close.

## What This Changes

The issue requests configurable marker-based batching of rapid inbound message fragments so marked messages are buffered and flushed with a later unmarked message in one agent turn.

## Best Possible Solution

Keep the timer-based debounce baseline; if maintainers want this workflow, add one opt-in generic ingress continuation contract with typed schema/docs, marker stripping, timeout behavior, and media/control-command/transcript/typing rules.

- **Require Plugin/API Seam First:** Defer the feature until a typed channel or plugin ingress hook can implement marker buffering without growing core message config directly.
