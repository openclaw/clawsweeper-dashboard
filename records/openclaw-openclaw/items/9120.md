## Summary

Keep open for a maintainer product decision. The requested sender-controlled marker remains distinct from timer-based inbound debounce and active-run collection: it needs a public buffering, timeout, ordering, and channel-behavior contract rather than a narrow bug repair. Likely related people: steipete and Vincent Koc are the strongest routing candidates from the shared inbound-debounce and queue history (medium confidence).

## What This Changes

Add an opt-in message suffix marker that buffers marked inbound fragments and sends them together when a later unmarked message arrives, reducing repeated agent context loads.

## System Context

Inbound channel messages are routed into shared debounce and reply-queue handling before an agent turn is created. This request would add a user-signaled batching decision before that turn, affecting the text and session context supplied to the agent.

## Architecture Diagram

## Best Possible Solution

Either retain the existing documented debounce/collect behavior as the supported cost-control path, or sponsor one narrow pre-agent aggregation contract with explicit per-session flush, timeout, marker-removal, and channel/media rules plus focused regression coverage.
