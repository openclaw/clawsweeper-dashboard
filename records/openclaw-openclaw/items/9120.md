## Summary

Keep open. Current main and v2026.6.11 support fixed timer-based inbound debounce and active-run queue batching, but not the requested marker-controlled continuation workflow; accepting this still requires a maintainer product/API decision because it adds config and changes inbound turn boundaries.

## What This Changes

The issue requests a configurable continuation marker that buffers marked multi-message input until an unmarked final message arrives, reducing repeated agent turns and context loads.

## Best Possible Solution

Maintain the shipped timer-based debounce baseline, then either fold marker semantics into a maintainer-approved generic inbound debounce contract or explicitly decide that adaptive/timer debounce is the supported answer.

## Reproduction Assessment

Not applicable as a bug repro: this is a feature request. Source and release inspection give a high-confidence behavior check that current OpenClaw has timer-based batching but not marker-controlled continuation.

## Solution Assessment

No for automation. The requested direction is plausible, but the best fix needs maintainer choice across marker syntax, timeout, marker stripping, media/control-command behavior, typing behavior, and whether this belongs in core or a plugin/API seam.
