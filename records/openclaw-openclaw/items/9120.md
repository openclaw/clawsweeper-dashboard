## Summary

Keep open. Current main and v2026.6.11 support fixed-window inbound debounce and collect-mode queueing, but they still do not implement the requested user-controlled continuation marker that buffers marked fragments until a later unmarked message.

## What This Changes

The issue requests a configurable continuation marker that buffers user message fragments until an unmarked final message arrives, reducing redundant agent turns and context loads.

## Best Possible Solution

Keep this as the focused marker-controlled continuation design item until maintainers approve a shared inbound or plugin API contract, or explicitly decide that existing timer-based batching is the supported answer.

## Reproduction Assessment

Not applicable: this is a feature request rather than a broken existing behavior report. Source inspection gives high-confidence evidence that current main supports fixed-window batching but not marker-controlled continuation buffering.

## Solution Assessment

No for automatic implementation: the marker, timeout, queue mode, and typing mode are plausible but add core config and session turn semantics. The best path is maintainer-approved shared inbound or plugin/API continuation behavior, or an explicit product decision that existing batching is enough.
