## Summary

Keep open. Current main and v2026.6.11 provide fixed timer-based inbound debounce and collect queueing, but not the requested marker-controlled hold-and-flush behavior; adding it would create public config and session-ingress semantics that need maintainer product/API direction.

## What This Changes

Request marker-controlled batching that buffers inbound messages ending with a continuation marker until an unmarked message arrives, with config, timeout, and typing/status semantics.

## Best Possible Solution

Keep fixed inbound debounce as the baseline; if maintainers want this workflow, add one opt-in generic ingress continuation contract with typed schema/docs, marker stripping, timeout behavior, and media/control-command/transcript/typing rules.

- **Require Plugin/API Seam First:** Defer the feature until a typed channel or plugin ingress hook can implement marker buffering without growing core message config directly.
