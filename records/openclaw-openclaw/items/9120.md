## Summary

Keep open: current main and v2026.6.11 still provide timer-based inbound debouncing and active-run collect queueing, but not the requested marker-controlled hold-and-flush workflow; the related issues are adjacent rather than canonical replacements, so this still needs maintainer product/API direction.

## What This Changes

The issue requests an opt-in message continuation marker that buffers marked inbound fragments and invokes one agent turn when an unmarked final message arrives.

## Best Possible Solution

Keep fixed debounce as the baseline; if maintainers want this workflow, add one opt-in generic ingress continuation contract with typed schema/docs, marker stripping, timeout behavior, and media/control-command/transcript/typing rules.
