## Summary

Keep open. Current main and the latest release still support timer-based inbound debounce and active-run collect mode, but not the requested marker-controlled continuation flow; adding it would create new config and turn-boundary semantics that need maintainer product/API direction.

## What This Changes

Requests an opt-in marker such as `(cont)` that buffers multiple inbound user messages and sends them as one agent turn when an unmarked message arrives.

## Best Possible Solution

Keep the timer-based debounce baseline; if maintainers want this workflow, design one opt-in generic continuation ingress contract with schema, docs, tests, marker stripping, timeout behavior, and media/control-command/typing rules.
