## Summary

Current main and v2026.6.11 provide timer-based inbound debounce and active-run collect batching, but not the requested sender-controlled continuation marker. The remaining choice between explicit markers, adaptive timing, or timer-only behavior changes public message semantics and needs maintainer product direction; the prior project review also explicitly kept this issue open.

## What This Changes

Add an opt-in marker and timeout that buffer marked inbound message fragments until an unmarked fragment arrives, then invoke one agent turn with the combined input.

## Best Possible Solution

Define one shared pre-agent inbound aggregation contract keyed by routed conversation and sender, with explicit flush, bypass, timeout, and ordering semantics; expose a marker mode only if maintainers choose user-declared completion over timer-only aggregation, while keeping channels transport-only.
