## Summary

Current main and v2026.6.11 provide timer-based inbound debounce plus active-run steering/collect batching, but they still do not provide the requested sender-controlled continuation marker. The request remains a product choice because explicit markers, adaptive coalescing, and timer-only batching impose different latency, command, media, and transcript semantics; the prior project review also explicitly kept this issue open for that decision.

## What This Changes

Add an opt-in continuation marker that buffers marked inbound message fragments and dispatches them together after an unmarked message or timeout.

## Best Possible Solution

Define one opt-in shared inbound aggregation contract keyed by resolved session and sender, preserving ordered text/media parts and providing atomic timeout, final-message, command-bypass, reset, and shutdown semantics; treat an explicit continuation marker as an optional signal within that contract rather than adding parallel queue and typing modes.
