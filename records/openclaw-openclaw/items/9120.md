## Summary

Keep open. Current main and the latest release support same-sender fixed-window inbound debouncing and active-run queue collection, but not the requested user-controlled continuation marker that buffers marked fragments until a later unmarked message arrives.

## What This Changes

The issue requests a configurable continuation marker such as `(cont)` that buffers multiple inbound fragments and invokes the agent only when a later unmarked message arrives.

## Best Possible Solution

Keep this as the focused marker-controlled continuation design item until maintainers approve a shared inbound/plugin API contract or explicitly decide that existing timer-based batching is the supported answer.

## Reproduction Assessment

Not applicable: this is a feature request rather than a broken existing behavior report. Source inspection gives high-confidence evidence that current main supports fixed-window batching but not marker-controlled continuation buffering.

## Solution Assessment

Unclear as an implementation plan: the marker and timeout are plausible, but they add core config and change session turn semantics. The best path is a maintainer-approved shared inbound or plugin/API continuation contract, or an explicit product decision that existing timer-based batching is enough.
