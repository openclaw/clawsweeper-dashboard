## Summary

Keep open. Current main still has timer-based inbound debounce and active-run collect batching, but not the requested user-controlled continuation marker that buffers marked fragments until an unmarked final message arrives.

## What This Changes

Request a configurable message continuation marker that batches quick message fragments into one agent turn to reduce repeated context-load cost.

## Best Possible Solution

Keep this as the focused marker-controlled continuation design item until maintainers approve a shared inbound/plugin API contract or explicitly decide that existing timer-based batching is the supported answer.

## Reproduction Assessment

Not applicable: this is a feature request rather than a broken existing behavior report. Source inspection gives high-confidence evidence that current main supports timer-based batching but not marker-controlled continuation buffering.

## Solution Assessment

No, not as an automatic implementation: the marker, timeout, queue mode, and typing mode are plausible but add core config and session turn semantics. The best path is maintainer-approved shared inbound or plugin/API continuation behavior, or an explicit product decision that existing batching is enough.
