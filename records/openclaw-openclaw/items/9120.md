## Summary

Keep open: current main and v2026.6.11 still provide timer-based inbound debouncing and active-run collect queueing, but not the requested marker-controlled continuation flow; accepting it still needs maintainer product/API judgment.

## What This Changes

The issue requests a configurable message continuation marker that buffers rapid multi-part inbound messages until a final unmarked message arrives, reducing redundant agent turns and context loads.

## Best Possible Solution

Keep the timer-based debounce baseline; if maintainers want this workflow, design one opt-in generic continuation ingress contract with schema, docs, tests, marker stripping, timeout behavior, and media/control-command/typing rules.
