## Summary

Keep open. Current main and the latest release still provide timer-based inbound debounce plus queue collect/steer behavior, but not the requested user-controlled continuation marker that buffers marked fragments until a later unmarked message arrives.

## What This Changes

The issue requests a configurable continuation marker that buffers marked inbound message fragments and invokes one agent turn when a final unmarked message arrives.

## Best Possible Solution

Keep the timer-based debounce baseline; if maintainers want this workflow, design one opt-in generic ingress continuation contract with schema, docs, marker stripping, timeout behavior, and media/control-command tests.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature request. Source, docs, tests, and latest-release inspection give a high-confidence behavior check that current OpenClaw has timer-based batching but not marker-controlled continuation.

## Solution Assessment

No for automation: this is not a strict bug fix. The maintainable path requires a maintainer choice about whether marker syntax belongs in core, a plugin/API seam, or documentation of the existing debounce/queue modes as the supported answer.
