## Summary

Keep open. Current main and v2026.6.11 still have timer-based inbound debouncing and collect-mode queueing, but not the requested user-controlled continuation marker that buffers marked fragments until a later unmarked message arrives.

## What This Changes

The issue requests a configurable user-controlled continuation marker, such as `(cont)`, to buffer several inbound user fragments and invoke the agent only after the final unmarked message.

## Best Possible Solution

Keep this as the focused marker-controlled continuation design item until maintainers approve shared inbound/plugin API semantics or explicitly decide that existing timer-based batching is the intended product answer.

## Reproduction Assessment

Not applicable: this is a feature request rather than a broken existing behavior report. Source inspection gives high-confidence evidence that current main supports timer-based batching but not marker-controlled continuation buffering.

## Solution Assessment

No, not as an automatic fix: the proposed marker, timeout, queue mode, and typing mode are plausible but add core config and session turn semantics. The best path is maintainer-approved shared inbound or plugin/API continuation behavior, or an explicit product decision that existing batching is enough.
