## Summary

Keep open. The requested sender-controlled “hold marked fragments until an unmarked final message” behavior remains a distinct product feature from the existing timer-based inbound debounce and active-run collect queue; the discussion also contains a recent maintainer-side review explicitly retaining this issue for product follow-up.

## What This Changes

Add an optional continuation marker that batches marked inbound text fragments and invokes one agent turn when a later unmarked message arrives.

## Best Possible Solution

Choose whether explicit sender-controlled batching is a supported core message contract; if approved, implement it once in shared inbound handling with a narrow documented config shape, deterministic timeout/flush rules, marker removal before model input, and cross-channel regression coverage.
