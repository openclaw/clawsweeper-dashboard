## Summary

Keep open. Current main still has timer-based inbound debounce, collect-mode active-run batching, and Telegram near-limit text-fragment buffering, but not the requested user-controlled continuation marker that buffers marked fragments until an unmarked final message arrives.

## What This Changes

The issue requests a configurable message continuation marker, timeout, queue behavior, and optional typing suppression so multi-part user input can be batched into one agent turn.

## Best Possible Solution

Keep this as the focused marker-controlled continuation design item until maintainers approve a shared inbound/plugin API contract or explicitly decide that existing timer-based batching is the intended product answer.

## Reproduction Assessment

Not applicable: this is a feature request rather than a broken existing behavior report. Source inspection gives high-confidence evidence that current main supports timer-based batching but not marker-controlled continuation buffering.

## Solution Assessment

No, not as an automatic fix: the proposed marker, timeout, queue mode, and typing mode are plausible but add core config and session turn semantics. The best path is maintainer-approved shared inbound or plugin/API continuation behavior, or an explicit product decision that existing batching is enough.
