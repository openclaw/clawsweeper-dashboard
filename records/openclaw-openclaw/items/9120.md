## Summary

Keep open. Current main and the latest release still provide fixed-window inbound debouncing and collect/steer queueing, but not the requested user-controlled continuation marker that buffers marked fragments until a later unmarked message; adding it remains a product/API and config-surface decision.

## What This Changes

The issue requests a configurable continuation marker that buffers rapid multi-message user input until a final unmarked message arrives, reducing repeated context loads.

## Best Possible Solution

Keep this open for maintainer product/API judgment; if accepted, implement an opt-in generic session-ingress continuation contract with schema/docs/tests, marker stripping, timeout behavior, media/control-command rules, and typing/status semantics while preserving the current timer-based debounce baseline.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature request. Source, docs, tests, and the latest release give a high-confidence behavior check that OpenClaw has timer-based batching but not marker-controlled continuation.

## Solution Assessment

No for automation: this is not a strict bug fix. The maintainable path requires a maintainer choice about whether marker syntax belongs in core, a plugin/API seam, or documentation of the existing debounce/adaptive trackers as the supported answer.
