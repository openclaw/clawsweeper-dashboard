## Summary

Keep open. Current main and v2026.6.11 still support timer-based same-sender inbound batching, but not the requested user-controlled continuation marker that buffers marked fragments until a later unmarked message arrives.

## What This Changes

Request adds an opt-in continuation marker such as `(cont)` that buffers marked inbound message fragments and invokes one agent turn when an unmarked final message arrives.

## Best Possible Solution

Keep this as the focused marker-controlled continuation design item; if approved, implement an opt-in shared inbound or plugin API contract that strips markers, buffers text fragments, flushes on unmarked final message or timeout, and preserves clear turn/transcript semantics.

## Reproduction Assessment

Not applicable: this is a feature request rather than a broken existing behavior report. Source inspection gives high-confidence evidence that current main supports fixed-window batching but not marker-controlled continuation buffering.

## Solution Assessment

No, not as an automatic implementation: the marker, timeout, queue mode, and typing mode are plausible but add core config and session turn semantics. The best path is maintainer-approved shared inbound or plugin/API continuation behavior, or an explicit product decision that existing batching is enough.
