## Summary

Keep open: current `main` still forwards only nested `args` or `input`, so flattened compact `tool_call` payloads continue to dispatch an empty object. The linked fix at https://github.com/openclaw/openclaw/pull/96127 remains open and needs selector-collision repair plus real runtime proof before it can close this issue.

Likely related people: @hanZeng-08 is the high-confidence candidate-fix author; @ly85206559 independently explored the same parser path.

## What This Changes

Fix compact Tool Search `tool_call` dispatch so plausible flattened target-tool arguments are not silently discarded in local-model lean sessions.

## Best Possible Solution

Land one selector-aware normalization that preserves explicit `args` or `input`, removes only the selector actually consumed to identify the wrapper target, preserves target fields with colliding names, adds focused collision tests, and demonstrates the fix in a redacted long local-model session before closing this issue.

## Reproduction Assessment

Yes at source level: on current main, a compact call shaped like `{ id, command }` deterministically parses to an empty target input. The provided production transcripts independently corroborate the resulting missing-parameter failures, although this review did not run a fresh live session.

## Solution Assessment

The linked parser normalization is the correct boundary, but its current selector handling is not yet the best complete fix. It should remove only consumed wrapper metadata and prove both ordinary flattened calls and selector-collision cases in a real local-model run.
