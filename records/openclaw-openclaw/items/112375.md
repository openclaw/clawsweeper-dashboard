## Summary

Keep this PR open: it adds a useful cron cost-control feature, but the proposed runner directly grants persisted cron jobs an unattended Gateway-host shell execution path without reusing the existing execution-policy boundary. It also needs real after-fix evidence from a controlled Gateway setup before merge.

## What This Changes

Adds an optional cron-job shell precheck that can skip a payload before an agent turn, plus CLI editing and run-cost statistics support, protocol fields, persistence, tests, and cron documentation.

## System Context

Cron jobs are created through the CLI and Gateway protocol, persisted in the cron store, and later executed by the scheduler. This change inserts a shell-based decision before trigger evaluation and payload execution, affecting whether an agent session, delivery, and run-log outcome occur.

## Architecture Diagram

flowchart LR
  A[CLI or Gateway cron request] --> B[Persisted cron job]
  B --> C[Scheduler starts job]
  C --> D[Shell precheck]
  D -->|work needed| E[Trigger and payload execution]
  D -->|no work| F[Skipped run log]
  D -->|failure| G[Error or configured skip]
  E --> H[Agent session or command result]

## Best Possible Solution

Keep the precheck as a first-class cron optimization, but route it through a deliberate, documented, tested host-execution policy that preserves the existing authorization and sandboxing boundary for scheduled commands.
