## Label Justifications

- `P1`: Intermediate model narration is being delivered into real customer and group chats during otherwise valid tool-calling workflows.
- `impact:message-loss`: The defect misroutes internal commentary as user-visible channel messages, corrupting the intended delivered conversation.

## Summary

This remains a concrete transport bug: current main suppresses commentary only when phase metadata exists, while the pinned Pi Chat Completions transport emits text-plus-tool-call turns without any phase signature. The narrower dependency-level defect is actionable and should remain open rather than being folded into the broader product discussion. ([github.com](https://github.com/earendil-works/pi/blob/main/packages/ai/src/providers/openai-completions.ts))

## What This Changes

Tag non-empty Chat Completions text as commentary when the same turn terminates with tool calls, preventing tool-call preambles from being delivered to messaging channels.

## Best Possible Solution

Fix the Pi Chat Completions transport at its owner boundary by assigning a stable per-completion commentary signature to non-empty text blocks when the completed turn has `stopReason: "toolUse"`, preserve any existing signature, add transport regression coverage, and carry only a temporary OpenClaw dependency patch until an upstream release is pinned.
