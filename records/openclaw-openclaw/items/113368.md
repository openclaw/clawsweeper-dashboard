## Summary

This PR still addresses a real P1 Telegram message-loss boundary: the isolated polling worker must not make an update ineligible for redelivery before its durable ingress handoff succeeds. The latest branch replaces the earlier one-sided offset update with serialized spool/offset handling, but the supplied record does not include after-fix live evidence for the current head; keep it open for that proof rather than closing the linked loss report prematurely.

## What This Changes

The branch changes isolated Telegram polling so it durably spools each inbound update before persisting its Telegram offset, then adds ordering, failure, and non-consecutive-update regression coverage.

## System Context

Telegram isolated polling receives updates in a worker and hands them to the parent session’s durable ingress spool. The persisted polling offset controls what Telegram will redeliver, so it must advance only after the spool confirms storage and before the worker accepts the next update.
