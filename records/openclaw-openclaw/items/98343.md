## Summary

Keep this PR open, but it is not merge-ready: the current-head terminal proof is sufficient, while the patch still gates shipped Gemini CLI runtime availability behind a new env opt-in and the main setup flow does not teach that required setting.

## What This Changes

The PR gates direct bundled Google Gemini CLI runtime provider/backend registration behind `OPENCLAW_ENABLE_GOOGLE_GEMINI_CLI_HARNESS`, preserves setup-registry compatibility, and updates Google docs, metadata, runtime-alias logic, and tests.

## Best Possible Solution

Either keep shipped Gemini CLI runtime registration enabled by default, or land an explicitly approved opt-in migration with setup-flow docs, legacy compatibility proof, and clear operator upgrade guidance.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 register `google-gemini-cli` directly by default, while the PR head only registers it when `OPENCLAW_ENABLE_GOOGLE_GEMINI_CLI_HARNESS` is enabled. I did not run tests because this was a read-only review, but the PR body includes current-head terminal proof.

## Solution Assessment

No, not as-is: the env gate is a plausible product direction, but the best fix needs maintainer-approved compatibility policy, direct setup-flow docs, and legacy runtime compatibility proof. Preserving default registration is safer unless maintainers explicitly choose the opt-in migration.
