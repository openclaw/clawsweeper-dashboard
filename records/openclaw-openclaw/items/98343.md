## Summary

Keep this PR open: the setup-registry fallback work is useful, but the branch still turns shipped direct `google-gemini-cli` provider/backend registration into a new unset-by-default operator opt-in without maintainer-approved migration policy, and the main setup docs still do not tell Gemini CLI users to set that runtime flag.

## What This Changes

The PR gates bundled Google Gemini CLI runtime provider/backend registration behind `OPENCLAW_ENABLE_GOOGLE_GEMINI_CLI_HARNESS`, preserves setup-registry fallback handling, and updates Google docs, metadata, alias resolution, and tests.

## Best Possible Solution

Land only after maintainers either keep default Gemini CLI runtime registration or explicitly approve the opt-in migration with setup-flow docs and upgrade proof.

## Reproduction Assessment

Yes. At source level, current main and v2026.6.11 register `google-gemini-cli` directly by default, while the PR head only registers it when `OPENCLAW_ENABLE_GOOGLE_GEMINI_CLI_HARNESS` is enabled.

## Solution Assessment

No, not as-is. The setup fallback is a useful mitigation, but the best fix needs maintainer-approved compatibility policy and direct setup-flow docs, or the shipped default runtime registration should stay enabled.
