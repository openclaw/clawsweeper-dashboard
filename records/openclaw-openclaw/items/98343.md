## Summary

Keep open. Current head has meaningful Google Antigravity and Gemini CLI auth work plus current-head terminal proof, but it is not merge-ready because the new SDK auth-forwarding hook exposes too much credential state and the Gemini CLI refresh change is still an upgrade-sensitive compatibility break without maintainer acceptance.

## What This Changes

The PR adds a bundled `google-antigravity` provider/CLI backend, changes Gemini CLI OAuth to import the official cache with identity checks, adds a public SDK auth-forwarding hook, and updates related docs, tests, and proof scripts.

## Best Possible Solution

Land a narrower owner-approved Google auth/runtime contract that forwards only selected credential material, preserves or migrates shipped Gemini CLI OAuth profiles unless maintainers accept the break, and exposes Antigravity setup consistently in manifest and runtime metadata.

## Reproduction Assessment

Yes for the PR blockers from source inspection: PR head exposes the full `AuthProfileStore` to the provider hook and changes Gemini CLI refresh to require an official cache. I did not run live Google auth locally, but the source and PR-body terminal proof are enough to review the merge blockers.

## Solution Assessment

No. Provider-owned cache import and Antigravity via `agy --print` are plausible directions, but the current merge shape is not the best fix until the credential boundary is narrowed, shipped OAuth profiles are preserved or deliberately broken with approval, and setup metadata is aligned.
