## Summary

Keep this PR open, but it is not merge-ready: the new public auth-forwarding hook is documented as generic while the runtime resolver is Google-only, and the branch still leaves Gemini CLI setup metadata contradicting default registration.

## What This Changes

## Best Possible Solution

Make the auth-forwarding boundary either Google-private or fully provider-generic with resolved typed credentials, then align Gemini CLI setup metadata with the default registration policy before maintainers decide whether to accept the SDK expansion.

## Solution Assessment

No, not as-is. The typed Google boundary is a good direction, but the public SDK shape must either be narrowed to Google or backed by a generic resolver, and setup metadata must match the selected registration policy.

  - confidence: 0.93
