## Summary

Keep open: the Google auth boundary is directionally useful, but the PR exposes `authProfileForwarding` as a generic Plugin SDK contract while the runner only resolves Google credentials, so third-party backends following the new docs cannot receive `ctx.authCredential`.

## What This Changes

The PR adds a typed Google/Gemini CLI auth credential resolver, public CLI backend auth-forwarding SDK types/docs, Google OAuth-only forwarding, and focused tests/proof for Gemini CLI auth staging.

## Best Possible Solution

Align the public SDK contract with the implementation before merge, either by adding a generic provider/plugin-owned credential resolver or by narrowing/removing the public SDK/docs surface and keeping the Google bridge private.

## Reproduction Assessment

Yes, source inspection is sufficient: a non-Google backend can declare the documented `authProfileForwarding` allowlist, but the runner resolves only through the Google credential resolver, so no credential can be forwarded for that documented third-party path.

## Solution Assessment

No; the Google-specific resolver is reasonable for the bundled backend, but exposing it as a generic SDK capability without a generic resolver creates a broken plugin contract.
