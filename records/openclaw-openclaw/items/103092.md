## Label Justifications

- `P2`: The issue is a bounded analytics correctness bug affecting DST-observing users, without data loss or a blocked core workflow.
- `impact:session-state`: The bug mis-buckets usage and session history events into the wrong local calendar day for Profile and Usage aggregations.
- `maturity:stable`: The affected Gateway RPC and hosted web usage surface maps to gateway-runtime, which the maturity shortlist reports as M4 Stable.

## Summary

This issue is still necessary: current main still sends and consumes one fixed utcOffset for local usage history, so midnight-adjacent records from a different DST season can be bucketed onto the wrong day. The live maintainer label also makes cleanup closure inappropriate.

## What This Changes

The issue requests DST-correct local-day bucketing for Usage and Profile history while preserving fixed utcOffset compatibility for older clients.

## Best Possible Solution

Add an optional IANA timeZone request field for usage.cost and sessions.usage, use timestamp-specific zone day keys for local history, and keep utcOffset as the fixed-offset compatibility path.
