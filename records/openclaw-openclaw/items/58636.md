  - body: Adding `upload` to the built-in list seeds `seen` before Gateway and dynamic aliases are appended, so a plugin or Gateway command with that alias would be suppressed unless maintainers explicitly reserve it for core.
  - confidence: 0.92
- **[P1] Keep upload context queued until sendChat accepts the turn:** `src/tui/tui-command-handlers.ts:572`
  - body: `pendingFileContext` is cleared before `client.sendChat` returns. If the send fails or times out, retrying sends only the typed message and drops the files the user selected.
  - confidence: 0.93
- **[P1] Clear stale upload context when replacement attaches nothing:** `src/tui/tui-command-handlers.ts:278`
  - body: When every selected path is skipped or fails to read, `blocks.length` stays zero and the old queued context remains. Clear the pending upload before processing a replacement or explicitly clear it on an empty result.
  - confidence: 0.91
- **[P1] Validate regular bounded files before reading:** `src/tui/tui-command-handlers.ts:257`
  - body: The handler reads each selected path fully before size or regular-file validation. A FIFO, device, socket, or large text file can block the event loop or create an enormous prompt, so validate and cap the path before reading.
  - confidence: 0.9
- **[P1] Wrap attached file text as untrusted content:** `src/tui/tui-command-handlers.ts:273`
  - body: Raw file text is concatenated into the user message with spoofable delimiters, bypassing the external-content wrapper used for decoded file text. Use that boundary so local file bytes are treated as data, not trusted prompt structure.
  - confidence: 0.88
