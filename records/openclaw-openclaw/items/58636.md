  - body: `getSlashCommands` seeds built-ins into `seen` before appending Gateway and dynamic command aliases, so adding `upload` here suppresses any plugin or Gateway command with that alias. This needs an explicit ownership or collision policy before merge.
  - confidence: 0.92

  - body: `pendingFileContext` is cleared before `client.sendChat` returns. If the send fails or times out, retrying sends only the typed message and drops the files the user selected.
  - confidence: 0.93
- **[P1] Clear stale upload context when replacement attaches nothing:** `src/tui/tui-command-handlers.ts:280`
  - body: When every selected path is skipped or fails to read, `blocks.length` stays zero and the old queued context remains. Clear the pending upload before processing a replacement or explicitly clear it on an empty result.
  - confidence: 0.91
- **[P1] Validate regular bounded files before reading:** `src/tui/tui-command-handlers.ts:257`
  - body: The handler reads each selected path fully before size or regular-file validation. A FIFO, device, socket, or large text file can block the TUI or create an enormous prompt, so stat and cap the path before reading.
  - confidence: 0.93
- **[P1] Wrap attached file text as untrusted content:** `src/tui/tui-command-handlers.ts:273`
  - body: The PR places raw file text into the user message, while current file-input paths wrap decoded file text with external untrusted-content markers. Without that boundary, selected file text can carry prompt-injection or chat-template special-token content as ordinary user instructions.
  - confidence: 0.9
