Full review comments:

- **[P1] Keep installable channel setup behind approval:** `src/crestodian/operations.ts:387-400`
  - body: Removing `channel-setup` from the persistent-operation set lets `connect <channel>` and `connect_channel` start the hosted setup without Crestodian approval. That hosted path calls `setupChannels(..., skipConfirm: true)`, and current setup can auto-confirm a single install source before writing config, so installable channels can download/enable plugin code from one AI turn. Keep an approval/confirmation gate before any install/write step.
  - confidence: 0.92
- **[P2] Parse command pivots before decline shortcuts:** `src/crestodian/approval-intent.ts:35`
  - body: `DECLINE_RE` treats any message starting with `stop` or `abort` as a decline. Because pending chat and rescue check approval intent before parsing commands, a documented command such as `stop gateway` can drop the pending proposal or return “No pending...” instead of queuing the gateway-stop operation. Parse exact commands first or make command verbs whole-message declines only.
  - confidence: 0.9
- **[P2] Mirror CLI directive args from start events:** `src/crestodian/agent-turn.ts:195-205`
  - body: The CLI mirror resolves directives from result events, but current CLI result events do not include tool args; args are only emitted on start events. For Claude/Gemini CLI runs, `connect_channel` and `open_agent` will return directive text while `directiveRef` stays unset, so the chat never starts the wizard or opens the agent. Cache args by `toolCallId` from start events or include them in result events.
  - confidence: 0.91
- **[P2] Expose all typed read commands to the agent loop:** `src/agents/tools/crestodian-tool.ts:118-145`
  - body: Configured machines now return after an agent-loop reply before deterministic parsing, but the ring-zero tool does not expose `health` or `plugin_list` even though the parser/docs still support `health` and `plugins list`. Exact read commands can therefore become model text instead of the real operation. Either keep exact read commands deterministic or add matching tool actions.
  - confidence: 0.86
- **[P2] Preserve rescue status completion markers:** `src/crestodian/operations.ts:1148-1151`
  - body: The refactored `status` branch calls `statusCommand` and returns without the existing `[crestodian] done: status.check` marker. Current main's rescue live test still asserts that marker for `/crestodian status`, so the rescue smoke will report an incomplete command even when status itself succeeds.
  - confidence: 0.84
- **[P2] Clear stale agent proposals before starting directives:** `src/crestodian/chat-engine.ts:507-508`
  - body: When an agent-loop proposal is pending and the next turn produces a directive, `applyAgentTurnReply` starts the wizard or TUI handoff without clearing `agentSession.proposalRef`. A later clear approval can still arm the old mutation even though the user moved into a different flow. Clear proposal state before accepting directive handoffs.
  - confidence: 0.87
