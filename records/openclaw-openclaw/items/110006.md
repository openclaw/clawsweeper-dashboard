## Summary

Keep open for normal landing review. Current main deterministically returns a synthetic timestamp receipt after a successful Nostr publish, while this PR propagates the signed event ID already created by the Nostr bus; the change is narrowly owned, has focused regression coverage and convincing live relay proof, and introduces no blocking finding.

## What This Changes

The PR changes Nostr DM sends to return the finalized event ID from the bus and use it as the outbound delivery receipt message ID, with regression coverage.

## Best Possible Solution

Keep one canonical Nostr send path that returns the locally finalized event ID only after a relay accepts the event, and expose that same ID in delivery receipts while preserving existing retry and failure semantics.
