## Summary

Keep open: current main has useful failure classification, invalid-request handling, and partial auth cooldown/skip foundations, but the requested default auth-broken quarantine, redacted provider-health status surface, and released-build restart/session-disruption report are not proven resolved.

## What This Changes

The issue requests failure-class-aware provider fallback that quarantines auth-broken providers, treats rate limits/network/invalid requests differently, and exposes provider health in status output.

## Best Possible Solution

Define a documented provider/profile health model that confirms transient 401s before marking hard auth broken, quarantines durable failures with safe recovery, and exposes redacted status without causing config-write restart loops.

## Reproduction Assessment

Yes for the central source-level gap: current code shows repeat auth skipping is opt-in and excludes primary candidates. No for the July 2 single-provider restart subcase, which remains reporter-log backed without live reproduction here.
