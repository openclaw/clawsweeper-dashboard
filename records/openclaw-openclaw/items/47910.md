## Summary

Keep open: current main has failure classification, cooldown state, opt-in non-primary auth skip caching, and related diagnostics, but the requested default hard-auth quarantine and redacted provider-health/status contract remain product-sensitive and incomplete, especially after the recent single-provider 401-to-restart report.

## What This Changes

The issue requests failure-class-aware provider fallback that quarantines auth-broken providers, treats rate-limit/network/invalid-request failures differently, and exposes provider health in status output.

## Best Possible Solution

Define a provider/profile incident-health model that confirms transient 401s before hard quarantine, applies durable backoff by failure class, and exposes redacted status or doctor visibility without config-write restart loops.
