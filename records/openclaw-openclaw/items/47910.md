## Summary

Keep open: current main has auth cooldown, an opt-in session skip cache, and log-spam mitigation, but it still does not provide the requested default provider-level auth quarantine/status policy; the July 2, 2026 401-to-restart report keeps the impact active.

## What This Changes

Request failure-class-aware provider fallback that quarantines auth-broken providers, treats transient failures differently, and exposes provider health/status.

## Best Possible Solution

Define a maintainer-approved default auth-provider health/quarantine policy, then implement it in the auth-profile/fallback/status path with focused tests and redacted live proof for the Anthropic 401 restart case.

## Solution Assessment

No complete solution exists yet; current mitigations reduce repeat auth retries and log spam, but choosing default quarantine/status behavior is a compatibility-sensitive maintainer policy decision.
