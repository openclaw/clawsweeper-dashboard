## Summary

Keep open: current main has useful failure-class classification and partial auth cooldown/skip foundations, but the requested default auth-broken quarantine, redacted provider-health status surface, and latest released-build restart/session-disruption report are not proven resolved.

## What This Changes

Request failure-class-aware provider fallback that quarantines auth-broken providers, treats rate limits/network/invalid requests differently, and surfaces provider health in status.

## Best Possible Solution

Define a documented provider/profile health model that confirms transient 401s before marking hard auth broken, quarantines durable failures with safe recovery, and exposes redacted status without causing config-write restart loops.

## Reproduction Assessment

Yes for the central source-level gap: current code shows repeat auth skipping is opt-in and not a default provider quarantine/status model. No for the July 2 single-provider restart subcase, which remains reporter-log backed without live reproduction.

## Solution Assessment

Unclear until maintainers choose the default policy; a blanket fail-closed quarantine is not automatically best because transient 401 recovery, status redaction, and upgrade-safe behavior all need explicit decisions.
