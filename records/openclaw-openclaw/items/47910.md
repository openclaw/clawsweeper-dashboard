## Summary

Keep open: current main has useful failure classification and partial skip/status surfaces, but it still does not provide the requested default hard-auth quarantine policy or normal provider-health status for auth-broken providers.

## What This Changes

The issue requests failure-class-aware provider fallback, including hard-auth quarantine, distinct rate-limit/network handling, invalid-request fail-fast behavior, and provider health in status output.

## Best Possible Solution

Define a provider/profile incident-health model that confirms transient 401s before hard quarantine, applies durable backoff by failure class, and exposes redacted status plus doctor visibility without config-write restart loops.

## Reproduction Assessment

Yes for the central source-level gap: default auth skip is disabled, primary candidates are not skipped, generic auth uses cooldown rather than default quarantine, and normal status lacks provider quarantine health. The July 2 restart subcase still needs live or redacted-log proof on current main.

## Solution Assessment

Unclear: the requested blanket quarantine is not automatically the best solution until maintainers choose the hard-auth versus transient-401 boundary and redacted status contract. The maintainable direction is a documented provider/profile incident-health policy rather than another ad hoc fallback branch.
