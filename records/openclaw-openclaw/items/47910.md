## Summary

Keep open: current main now has failure-class classification and partial auth cooldown/skip behavior, but it still does not fully cover the requested default hard-auth quarantine, single-provider transient-401/restart subcase, or normal status health contract.

## What This Changes

The issue requests failure-class-aware provider fallback with auth-broken provider quarantine, transient failure handling, invalid-request fast-fail behavior, and provider health/status visibility.

## Best Possible Solution

Define a maintainer-approved provider/profile health policy that verifies transient 401s before marking hard auth broken, avoids config-write restart loops, skips durable auth-broken providers by default, and exposes redacted status health.

## Reproduction Assessment

Yes for the source-level gap: current main shows opt-in/non-primary-only skip behavior and no normal status provider-health payload. The single-provider 401-to-restart subcase is not live-reproduced here and still depends on reporter logs or a fresh live proof path.

## Solution Assessment

Unclear: the requested direction is valid, but a blanket hard quarantine is not automatically the best fix until maintainers choose the transient-vs-hard auth boundary, redaction contract, and restart-safe recovery behavior.
