## Summary

Keep open: current main has partial failure-class handling and an opt-in session-scoped auth skip cache, but it still lacks the requested default provider-level auth quarantine/status model, and fresh released-build evidence keeps the 401/auth-restart failure mode active.

Request provider fallback policy that quarantines auth-broken providers by failure class, distinguishes hard auth from transient/rate-limit failures, and exposes safer provider health/status.

## Best Possible Solution

Define a redacted provider/auth health model, classify hard auth, transient refresh, quota/rate limit, network, and invalid request consistently, apply it through fallback/profile state, and prove the Anthropic 401 restart case.

## Solution Assessment
