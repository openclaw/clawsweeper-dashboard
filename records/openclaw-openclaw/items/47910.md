## Summary

Keep open: current main has failure-class classification, auth_permanent disabled windows, and an opt-in session skip cache, but it still does not provide the requested default hard-auth provider quarantine, invalid-request fail-fast/status contract, or proof that the reported single-provider restart loop is fixed.

## What This Changes

Request provider fallback policy that distinguishes auth-broken providers from transient rate limits/timeouts, quarantines failed credentials, and exposes provider health in status output.

## Best Possible Solution

Define a core-owned provider health/quarantine policy with redacted status/doctor visibility, explicit hard-auth versus transient-auth rules, and regression/live proof for both multi-provider fallback and the reported single-provider restart case.

## Reproduction Assessment

Yes for the central source-level gap: current source and docs show default repeat auth attempts plus only opt-in non-primary skip behavior; no live reproduction was established for the July 2 single-provider restart subcase.

## Solution Assessment
