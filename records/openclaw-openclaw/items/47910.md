## Summary

Keep open: current main has failure-class foundations and partial mitigations, but the requested default auth-broken quarantine, redacted provider-health status, and released-build restart/session-disruption subcase are not resolved.

## What This Changes

The issue requests provider fallback behavior that distinguishes auth-broken, rate-limited, network, and invalid-request failures, quarantines broken auth paths, and exposes provider health in status output.

## Best Possible Solution

Define a documented provider/profile incident-health model that confirms transient 401s before marking hard auth broken, applies durable quarantine consistently, and exposes redacted status without causing config-write restart loops.
