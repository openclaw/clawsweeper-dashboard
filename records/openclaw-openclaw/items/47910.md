## Summary

Keep open: current main has useful failure classification, auth cooldown/disabled state, and a `models status` unusable-profile snapshot, but the requested default auth-broken quarantine, transient-401 handling, restart-loop prevention, and normal status health contract remain unresolved.

## What This Changes

The issue requests failure-class-aware provider fallback that quarantines auth-broken providers, handles rate limits/network/invalid requests differently, and exposes provider health in status output.

## Best Possible Solution

Define a maintainer-approved provider/profile health model that confirms transient 401s before hard quarantine, prevents auth rewarm from causing config-write restart loops, applies fallback decisions consistently, and exposes redacted provider health in the normal status surface.

## Reproduction Assessment

Yes for the central source-level gap: current main still keeps repeat-auth skipping opt-in, process-local, and non-primary-only, while normal status lacks provider-health output. ## Solution Assessment

Unclear until maintainers choose the default policy; a blanket auth quarantine is not automatically best because transient 401 recovery, status redaction, and upgrade-safe behavior all need explicit decisions.
