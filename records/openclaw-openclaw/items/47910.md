## Summary

Keep open: current main has failure-class classifiers and partial mitigations, but it still lacks the requested default hard-auth provider quarantine, normal status/provider-health surface, and safe policy for transient 401s versus permanently broken auth.

## What This Changes

Request failure-class-aware model fallback that quarantines auth-broken providers, treats rate limits/network/invalid requests differently, and exposes provider health in status.

## Best Possible Solution

Define a provider/profile incident-health model that confirms transient 401s before hard quarantine, applies durable backoff by failure class, and exposes redacted status/doctor visibility without config-write restart loops.
