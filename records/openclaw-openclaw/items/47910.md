## Summary

Keep open: current main has useful failure-class classification and partial auth cooldown/skip handling, but it still does not provide the requested default auth-broken provider quarantine, redacted provider-health status surface, or proof that the released-build restart/session-disruption subcase is resolved.

## What This Changes

Request default failure-class-aware provider fallback/quarantine for auth-broken providers, distinct rate-limit/network/invalid-request behavior, and provider health in status output.

## Best Possible Solution

Define a documented provider/profile incident-health model that confirms transient 401s before marking hard auth broken, applies durable quarantine or recovery consistently, and exposes redacted status without causing config-write restart loops.

## Reproduction Assessment

Yes for the central source-level gap: current main shows default auth skip is disabled, primary candidates are never skipped, and status lacks provider quarantine health. The July 2 restart subcase remains reporter-log backed rather than live-reproduced in this review.

## Solution Assessment

Unclear: a blanket fail-closed quarantine is not automatically the best fix until maintainers choose the hard-auth versus transient-401 boundary and status redaction contract.
