## Summary

Keep open: current main has partial failure-class foundations, but the requested default hard-auth quarantine and operator-visible provider health are still not implemented; the new v2026.6.11 report ties the same classification gap to repeated gateway restarts and session disruption.

## What This Changes

Add failure-class-aware provider fallback that quarantines hard auth failures, handles rate limits/network/invalid requests differently, and exposes provider health in status.

## Best Possible Solution

Define a documented provider/profile health model for hard auth, transient refresh, rate-limit, network, and invalid-request outcomes, then apply it consistently in fallback and redacted status.

## Reproduction Assessment

Yes, at source level: current main still keeps auth skip behavior default-off, never skips primary candidates, and lacks a normal status provider-health snapshot. I did not run a live expired-token or spurious-401 provider scenario.

## Solution Assessment

No automated fix path is best yet. The durable fix needs maintainer decisions about hard-auth classification, same-key transient 401 retry, default quarantine duration, and redacted status semantics.
