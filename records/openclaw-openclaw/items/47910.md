## Summary

Keep open: current main has failure-class foundations, auth cooldowns, and opt-in session skip state, but it still lacks the requested default hard-auth provider quarantine, provider-health status surface, and reproduced protection for the reported single-provider 401 restart loop.

## What This Changes

Request provider fallback policy that classifies failures, quarantines auth-broken providers, handles rate/network/invalid-request cases differently, and exposes provider health in status.

## Best Possible Solution

Define the hard-auth versus transient-auth policy and a redacted provider-health/status contract, then implement the narrow fallback/auth-state path with live proof for the single-provider 401 restart case.

## Reproduction Assessment

No high-confidence current-main reproduction was run; the issue includes concrete logs and current source explains the rewarm/cooldown path, but the single-provider 401-to-restart loop still needs focused live proof or a replay.

## Solution Assessment

Current main is not the full best solution because the only automatic skip is opt-in and session-local, while ordinary auth remains cooldown-based rather than a default provider quarantine.
