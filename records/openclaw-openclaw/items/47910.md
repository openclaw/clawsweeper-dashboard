## Summary

Keep open: current main has useful foundations, but not the requested default provider quarantine, invalid-request policy, or normal status health contract; the fresh Anthropic 401→200/restart report also adds unresolved auth-state behavior.

## What This Changes

Provider fallback should classify failures by class, quarantine auth-broken providers, handle transient/rate-limit/invalid-request failures differently, and expose redacted provider health in status.

## Best Possible Solution

Define a documented provider/profile health model that separates hard auth, transient refresh, rate-limit, network, invalid-request, and same-key transient 401 outcomes; apply it consistently in fallback selection; avoid destructive rewarm/config rewrites for recoverable 401s; and expose a redacted provider health snapshot in status.

## Reproduction Assessment

Yes, at source level: current main still has default-off, session-scoped non-primary auth skip behavior and no normal status provider-health contract. No live expired-token or Anthropic 401→200 restart reproduction was run in this read-only review.

## Solution Assessment

No automated fix path is best yet: the direction is strong, but hard-auth classification, invalid-request fail-fast behavior, transient same-key 401 handling, and redacted status semantics need maintainer policy before implementation.
