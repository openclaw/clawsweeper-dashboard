## Summary

The item remains necessary: current main has failure classification and partial auth-profile cooldown/disabled plumbing, but ordinary auth failures still use short cooldowns, the skip cache is opt-in/session-scoped/non-primary, and the requested default provider quarantine plus status visibility are not fully implemented.

## What This Changes

Requests failure-class-aware provider fallback with default quarantine for auth-broken providers and provider health visibility in status surfaces.

## Best Possible Solution

Define a maintainer-approved provider/auth incident model that confirms hard auth failures before quarantine, applies selection consistently, exposes redacted health in status/doctor/models surfaces, and avoids config-write restart loops.
