## Summary

Keep open: current main has useful failure-class plumbing and partial mitigations, but it still lacks the requested default hard-auth quarantine policy, transient-401 confirmation boundary, and ordinary status/provider-health surface.

## What This Changes

Request to classify provider fallback failures by class, quarantine auth-broken providers or profiles, avoid repeated bad-auth retries, and expose provider health in status output.

## Best Possible Solution

Define a provider/profile incident-health model that confirms transient 401s before hard quarantine, applies durable backoff by failure class, and exposes redacted status/doctor visibility without config-write restart loops.

Rationale: Current main can classify several failure classes, but changing when auth becomes a default quarantine and what status exposes changes provider routing, session behavior, and operator diagnostics.

Options:

- **Default incident-health model (recommended):** Implement hard-auth quarantine only after a documented confirmation boundary, preserve transient 401 recovery, and add redacted status/doctor visibility.
- **Keep opt-in skip only:** Leave default fallback behavior unchanged and improve operator guidance/status, accepting repeated attempts unless operators set the skip TTL.
- **Split restart subcase first:** Repair the config-write restart loop separately before deciding the broader provider quarantine policy.

## Reproduction Assessment

Yes for the central source-level gap: default auth skip is disabled, primary candidates are not skipped, generic auth uses cooldown rather than default quarantine, and normal status lacks provider quarantine health. The July 2 restart subcase still needs live or redacted-log proof against current main.

## Solution Assessment

Unclear: blanket fail-closed quarantine is not automatically the best fix until maintainers choose the hard-auth versus transient-401 boundary and redacted status contract. The maintainable path is a documented incident-health model shared by fallback, auth state, status, and doctor.
