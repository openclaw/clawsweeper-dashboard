Keep open: current main has partial memory reindex safety work, including per-agent database table publication, but the in-process safe-reindex search/status reader race remains source-reproducible and an open clean closing PR owns the direct fix path.

## What This Changes

The issue reports intermittent first-class `memory_search` failures where overlapping search/reindex work can return `index metadata is missing` despite a valid durable builtin memory index.

## Best Possible Solution

Review, land, or explicitly replace https://github.com/openclaw/openclaw/pull/90453 with one manager-level read barrier that keeps real provider/model mismatches fail-closed and coordinates adjacent metadata durability work.

## Reproduction Assessment

Yes, at source level: current main still points the manager at a shadow reindex database during full reindex and the tool still fail-closes on a post-search status result with missing identity. I did not run a live concurrent gateway reproduction in this read-only review.

## Solution Assessment

Yes, the best direction is a manager-level read barrier and stable status behavior rather than a tool-wrapper workaround. The remaining question is maintainer acceptance of wait-through-reindex semantics and adjacent metadata cleanup ordering.
