## Summary

Keep open: current main and v2026.6.11 cover important cross-process memory DB replacement/reindex safety, but the direct safe-reindex search/status reader guard for this issue is still owned by the open closing PR and has not landed.

## What This Changes

The issue reports intermittent first-class `memory_search` failures with `index metadata is missing` while the durable builtin memory index remains valid, likely during overlapping search/reindex activity.

## Best Possible Solution

Review, land, or explicitly replace the open manager-level read/status guard so searches and status reads cannot observe transient reindex state while preserving fail-closed behavior for true provider/model mismatches.

## Reproduction Assessment

Yes, at source level with medium confidence: current main still has a status path that can read the manager's current DB handle while full reindex can temporarily point that handle at a shadow DB. I did not run a live concurrent gateway reproduction in this read-only review.

## Solution Assessment

Unclear until maintainer review of the linked PR: a manager-level read/status guard is the right layer, but maintainers still need to accept the wait-through-reindex latency tradeoff and coordinate adjacent metadata cleanup.
