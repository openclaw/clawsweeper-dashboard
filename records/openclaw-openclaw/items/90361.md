## Summary

Keep open: current main still has the source-level safe-reindex search/status window, and the open closing PR is the active candidate fix. The latest field comment supports that one cross-process variant improved on main, but it does not prove the central concurrent safe-reindex race is fully implemented or shipped.

## What This Changes

The issue requests a memory-core fix so first-class `memory_search` does not return `index metadata is missing` when the durable builtin memory index is valid during overlapping search/reindex work.

## Best Possible Solution

Review, land, or explicitly replace https://github.com/openclaw/openclaw/pull/90453 with a manager-level read barrier that keeps true provider/model mismatches fail-closed while preventing search/status readers from observing half-built reindex metadata.

## Reproduction Assessment

Yes, at source level: current main still starts search-triggered sync before identity-gated querying, temporarily points the shared manager at a reindex temp DB, and fail-closes the tool on a post-search missing identity status. I did not run a live concurrent gateway stress reproduction in this read-only review.

## Solution Assessment

Yes for the current direction: a manager-level read barrier and stable status snapshot are more maintainable than a tool-wrapper mitigation that preserves hits after the fact. The unresolved part is maintainer acceptance of wait-through-reindex semantics and adjacent metadata cleanup ordering.
