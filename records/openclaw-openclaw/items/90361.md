## Summary

Keep open: current main has fixed adjacent stale-handle and table-publication failure modes, but the same-manager safe-reindex search/status race is still present and is owned by the open closing PR.

## What This Changes

The issue reports intermittent builtin `memory_search` failures where a valid durable memory index can be hidden by transient or stale live-manager state reporting `index metadata is missing`.

## Best Possible Solution

Review and land, revise, or explicitly replace the open manager-level reindex read barrier so searches and status reads cannot observe the half-built temp DB.

## Reproduction Assessment

Yes, at source level: current main still has a temp-DB assignment window inside the manager, and search/status can read from the manager DB without the linked PR's full-reindex reader guard. I did not run a fresh live concurrent gateway repro in this read-only review.

## Solution Assessment

No, current main is not enough to close this issue. The best fix direction is the linked manager-level read barrier or an equivalent serialization/status-snapshot design, not a tool-wrapper-only workaround.
