## Summary

Keep open: current main fixed the cross-process file-swap/stale-handle variant, but the direct in-process safe-reindex reader window is still present and an open closing PR owns that remaining race fix.

## What This Changes

The issue reports intermittent first-class `memory_search` false unavailability from `index metadata is missing` during builtin memory index search/reindex concurrency despite a valid durable SQLite index.

## Best Possible Solution

Review, land, or explicitly replace https://github.com/openclaw/openclaw/pull/90453 with one manager-level reindex/search/status coordination fix that prevents transient shadow-DB reads while preserving real provider/model mismatch fail-closed behavior.

## Reproduction Assessment

Yes, at source level: current main still points the manager at a shadow reindex database before metadata publication, and the tool still fail-closes on a post-search missing-identity status. I did not run a live concurrent gateway stress reproduction in this read-only review.

## Solution Assessment

Yes for the current direction: a manager-level read/reindex coordination guard is the maintainable fix, while a tool-wrapper mitigation would hide one symptom and risk weakening real mismatch handling.
