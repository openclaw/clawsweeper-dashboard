## Summary

Keep open: current main has partial missing-metadata and reindex recovery work, but the direct in-process safe-reindex search/status reader race is still not fully covered on main, and an open mergeable closing PR owns the remaining fix path.

## What This Changes

The issue asks OpenClaw to stop first-class `memory_search` from intermittently returning `index metadata is missing` while the durable builtin memory index is valid, especially during overlapping search/reindex work.

## Best Possible Solution

Review, land, or explicitly replace https://github.com/openclaw/openclaw/pull/90453 with a manager-level read barrier that prevents readers from observing the half-built reindex database while preserving true provider/model mismatch fail-closed behavior.

## Reproduction Assessment

Yes. The issue has high-confidence source-level reproduction evidence: current main still assigns the live manager to a reindex shadow DB while status/search can read identity, and field reports confirm the same `index metadata is missing` symptom on affected installs.

## Solution Assessment

Yes, the active direction is the best known fix shape: a manager-level read barrier and stable status snapshot address the lifecycle race more directly than a tool-wrapper mitigation. The unresolved part is maintainer acceptance of the wait-through-reindex tradeoff and adjacent metadata cleanup ordering.
