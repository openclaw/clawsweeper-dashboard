## Summary

Keep open: current main and v2026.6.11 include partial memory metadata and table-publication recovery, but the direct safe-reindex search/status reader race is still source-reproducible and an open mergeable closing PR owns the remaining manager-level fix.

## What This Changes

The issue reports intermittent builtin memory_search failures where a valid durable memory index is surfaced as unavailable with "index metadata is missing" during overlapping search/reindex activity.

## Best Possible Solution

Review, land, or explicitly replace https://github.com/openclaw/openclaw/pull/90453 with one manager-level read barrier that keeps true provider/model mismatches fail-closed and coordinates adjacent metadata durability work.

## Reproduction Assessment

Yes, at source level: current main still assigns the live manager to a shadow reindex DB while status reads refresh identity from the current handle, and memory_search fail-closes on a post-search missing identity. I did not run a live concurrent gateway stress reproduction in this read-only review.

## Solution Assessment

Yes for the current direction: a manager-level read barrier and stable status snapshot address the lifecycle race more directly than a tool-wrapper workaround. The issue should stay open until the linked PR lands, is replaced, or maintainers explicitly choose a different recovery policy.
