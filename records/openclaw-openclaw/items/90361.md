## Summary

Keep open: current main has important memory-index durability work, including per-agent database/table publication, but it still lacks the active-reader reindex guard and stable status snapshot covered by the open closing PR. The issue remains necessary until that PR lands, is explicitly replaced, or current main gains equivalent source and test coverage.

## What This Changes

The issue reports intermittent built-in `memory_search` failures where the live tool returns `index metadata is missing` despite a valid durable SQLite memory index during overlapping search/reindex activity.

## Best Possible Solution

Review and either land or explicitly replace https://github.com/openclaw/openclaw/pull/90453 with a manager-level read barrier/stable status snapshot that preserves true provider/model mismatch fail-closed behavior.

## Reproduction Assessment

Yes, at source level: current main still lets full reindex temporarily repoint the manager at a shadow DB while `status()` reads the active manager DB, and the open PR adds tests that force that window. I did not execute a live concurrent gateway reproduction in this read-only review.

## Solution Assessment

Yes for the current direction: a manager-level read barrier and stable status snapshot are narrower and safer than a tool-wrapper mitigation that preserves hits after a bad status read. The remaining choice is maintainer acceptance of wait semantics and coordination with adjacent memory reindex work.
