## What This Changes

The issue reports intermittent first-class `memory_search` failures where live tool calls return `index metadata is missing` despite a valid durable builtin memory index during overlapping search/reindex activity.

## Best Possible Solution

Review, land, or explicitly replace https://github.com/openclaw/openclaw/pull/90453 with one manager-level read barrier that preserves true provider/model mismatch fail-closed behavior and coordinates adjacent metadata durability work.

## Reproduction Assessment

Yes, at source level: current main still points the manager at a shadow reindex database during full reindex and the tool still fail-closes when status reports missing identity. I did not run a live concurrent gateway reproduction.

## Solution Assessment

Yes for the current direction: a manager-level read barrier and stable status snapshot address the lifecycle race more directly than a tool-wrapper mitigation. The remaining question is maintainer acceptance of wait semantics and adjacent metadata cleanup ordering.
