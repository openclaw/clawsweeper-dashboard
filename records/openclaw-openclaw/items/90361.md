## What This Changes

The issue asks for first-class memory_search to avoid reporting `index metadata is missing` during concurrent safe reindex when the durable builtin memory index is valid.

## Best Possible Solution

Land or explicitly replace https://github.com/openclaw/openclaw/pull/90453 with a manager-level reindex read barrier that preserves real provider/model mismatch fail-closed behavior and coordinates adjacent metadata cleanup.

## Reproduction Assessment

Yes. Current main still assigns the manager DB handle to a shadow reindex database and the tool still fail-closes on post-search missing identity status; I did not run a live concurrent stress repro.

## Solution Assessment

Yes, the manager-level read barrier and stable status snapshot are the best direction because they address the lifecycle race directly while preserving true mismatch fail-closed behavior. A tool-wrapper-only mitigation would be too narrow.
