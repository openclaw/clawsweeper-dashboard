Keep open: current main has fixed important adjacent stale-handle/table-publication paths, but the exact in-flight safe-reindex search/status reader race is still not implemented on main and the open closing PR remains the active repair path.

## What This Changes

The issue reports intermittent first-class `memory_search` returning `index metadata is missing` during overlapping search/reindex activity even though the durable builtin memory index is valid.

## Best Possible Solution

Review, land, or explicitly replace https://github.com/openclaw/openclaw/pull/90453 with one manager-level read barrier and stable status path that preserves real provider/model mismatch fail-closed behavior.

## Reproduction Assessment

Yes, at source level: current main still swaps the live manager DB handle to a shadow reindex DB and the tool/status path can treat missing identity as unavailable. I did not run a live concurrent gateway stress reproduction in this read-only review.

## Solution Assessment

Yes for the current direction: a manager-level read barrier and stable status snapshot are narrower and safer than a tool-wrapper-only mitigation. The remaining decision is maintainer acceptance of wait-through-reindex behavior and adjacent metadata cleanup ordering.
