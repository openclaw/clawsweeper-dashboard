## Summary

Keep open: current `main` and `v2026.6.11` include important memory reindex publication repairs, but the direct in-process safe-reindex search/status race is still not settled, and an open closing PR owns the remaining fix path.

## What This Changes

The issue reports intermittent first-class `memory_search` failures with `index metadata is missing` while the durable builtin memory index remains valid, especially during overlapping search and reindex work.

## Best Possible Solution

Land or replace one manager-level reindex/read coordination fix that keeps durable memory reads stable during full reindex and preserves real provider/model mismatch fail-closed behavior; close this issue after that path merges with proof.

## Reproduction Assessment

Yes, at source level: current code still points the live manager at a shadow reindex DB during full reindex and the tool still fail-closes on post-search missing identity. I did not run a live concurrent gateway stress reproduction in this read-only review.

## Solution Assessment

Yes for the current direction: a manager-level read barrier and stable status snapshot are a better fit than a tool-wrapper workaround. The unresolved part is maintainer acceptance of wait semantics and coordination with adjacent metadata cleanup work.
