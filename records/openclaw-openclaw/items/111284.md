## Summary

No concrete defect is evident in this focused hardening patch: fatal UTF-8 decoding prevents malformed provider catalog bytes from becoming corrupted model IDs, while the existing BOM behavior remains covered. The PR is still necessary because it is open and its branch change has not been established as present on current main; it needs ordinary current-head merge gating rather than an automated repair.

## What This Changes

This PR makes live provider model-catalog responses fail on malformed UTF-8 instead of silently registering replacement-character model IDs, and adds a regression test using an invalid response byte.

## System Context

Live provider catalog discovery fetches a provider’s model-list response, reads its bounded byte body, parses JSON, and projects model IDs for provider/model selection. This change tightens the byte-to-text boundary so malformed catalog data fails before it can enter the model-selection path.
