## Summary

Keep open: the patch is a focused and likely-correct candidate fix for the open diagnostics-otel bug, but it is an external draft PR with only mocked/unit proof and a compatibility-sensitive shared-endpoint fallback change that should get real collector proof before merge.

## What This Changes

The PR changes diagnostics-otel shared OTLP endpoint resolution so a trailing `/v1/traces`, `/v1/metrics`, or `/v1/logs` segment is rewritten per enabled signal, while explicit per-signal endpoints remain exact, and updates docs/tests for that behavior.

## Best Possible Solution

Land this after real collector proof shows the changed routing works and maintainers accept the shared-endpoint compatibility change, keeping explicit per-signal endpoints as the exact override escape hatch.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: current main returns a shared `/v1/traces` endpoint unchanged for metrics and logs when multiple OTLP signals are enabled. I did not run a live collector reproduction in this read-only review.

## Solution Assessment

Yes, with one proof gap: rewriting only the shared signal-qualified fallback while preserving exact explicit signal endpoints is the narrowest maintainable fix for the reported routing bug. The safer alternative would be to skip or warn for mismatched signals, but that would drop requested telemetry instead of routing it to the standard OTLP paths.
