## What This Changes

The issue requests that a duplicate subagent session label cannot prevent a completed result from reaching Telegram, and that a terminal undelivered completion is reported separately from a transient empty yield.

## System Context

Subagent runs emit completion events that the Codex app-server harness projects into an OpenClaw agent result, which is then turned into queued channel replies such as Telegram messages. Session metadata updates use the Gateway session patch API, whose labels are globally unique when non-null, so an error at that boundary must not silently erase an otherwise deliverable completion.

Add a focused current-main integration regression that deliberately creates a duplicate completed-session label, runs a subagent completion through the Codex app-server path, and proves that the completion reaches Telegram while the metadata collision is surfaced as a separate diagnostic; then place the minimal failure isolation at the component that currently couples patch failure to delivery.
