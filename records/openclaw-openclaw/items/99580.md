## Summary

Keep open. Current main and v2026.6.11 still accept surrogate-range numeric entities in the shared decoder, while this PR applies the guard at the shared helper used by web_fetch and syntax highlighting, adds focused coverage, and now includes copied runtime output proof.

## What This Changes

The PR rejects surrogate-range HTML numeric entities in the shared agent HTML decoder and adds web_fetch regression coverage.

## Best Possible Solution

Land this focused shared-decoder guard after normal maintainer review and required checks, while keeping the sibling tool-call decoder fix tracked separately at https://github.com/openclaw/openclaw/pull/99564.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 call String.fromCodePoint for surrogate-range numeric entities, and a focused Node probe shows that resulting lone surrogate breaks URI encoding.

## Solution Assessment

Yes. The shared decodeCodePoint helper is the narrowest maintainable fix point because both web_fetch markdown conversion and syntax-highlight rendering consume decodeHtmlEntityAt, and invalid-entity fallback already preserves literal text.
