## What This Changes

The PR rejects surrogate-range HTML numeric entities in `src/agents/utils/html.ts` and adds web_fetch regression coverage for literal surrogate-entity preservation.

## Best Possible Solution

Land this focused shared-decoder guard after maintainer review, while keeping the separate tool-call decoder hardening tracked at https://github.com/openclaw/openclaw/pull/99564.

## Reproduction Assessment

Yes, at source level: current main and `v2026.6.11` pass surrogate-range numeric entities to `String.fromCodePoint`, and a focused Node probe shows the resulting lone surrogate breaks URI encoding. I did not run a full product E2E repro in this read-only review.

## Solution Assessment

Yes. Guarding the shared `decodeCodePoint` helper is the narrowest maintainable fix because both web_fetch extraction and syntax-highlight rendering consume `decodeHtmlEntityAt`, while invalid-entity fallback already preserves literal text.
