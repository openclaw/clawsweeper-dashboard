## What This Changes

QA Lab Gateway child startup, restart, and recovery should wait for `HEAD /readyz` instead of accepting `GET` or `HEAD /healthz` liveness as readiness.

## System Context

QA Lab starts and supervises a child OpenClaw Gateway for controlled test scenarios. Its probe result determines when QA flows may send work to that Gateway, so confusing liveness with readiness can advance startup before the Gateway accepts requests.

## Architecture Diagram

flowchart LR
  A[QA scenario starts] --> B[QA Gateway child manager]
  B --> C[Gateway HTTP listener]
  C --> D[/healthz liveness probe]
  C --> E[/readyz readiness probe]
  D --> F[Listener is alive]
  E --> G[Gateway accepts work]
  G --> H[QA startup or recovery continues]

## Best Possible Solution

Make the shared QA Gateway readiness gate require successful `/readyz`, retain `/healthz` only for listener liveness, and add focused startup, restart, and recovery regression coverage for the `healthz=200` plus `readyz=503` state.
