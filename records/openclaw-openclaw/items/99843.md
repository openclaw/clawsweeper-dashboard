## What This Changes

The issue reports premature safeguard compaction because context estimation can fall back to summing turn-aggregated cached token fields when `totalTokens` is missing or zero.

## Best Possible Solution

Fix compaction estimation so it prefers the latest real context snapshot and never uses turn-aggregated cache buckets as a context-window fallback.

## Reproduction Assessment

## Solution Assessment

Yes: the best fix is in the estimator/usage handoff, not a new config knob or reserve-token tuning. The repair should preserve cost accounting while ensuring compaction uses current-context tokens only.

## Repair Work Prompt

Fix https://github.com/openclaw/openclaw/issues/99843. Current main and v2026.6.11 still let `calculateContextTokens` fall back to `input + output + cacheRead + cacheWrite` when `totalTokens` is zero or absent, which can over-count turn-aggregated prompt-cache reads and trigger compaction below `contextWindow - reserveTokens`. Keep the fix inside the compaction estimator/usage handoff: prefer the latest real context snapshot (`totalTokens` when trustworthy, latest-call prompt/context usage where available) and do not use accumulated cache buckets as a context-window estimate. Add focused regression coverage for a multi-call cached tool-loop usage object where aggregate `cacheRead` is much larger than final context, plus zero-usage error entries when choosing last assistant usage. Preserve billing/cost aggregation semantics, do not add config/env knobs, and do not edit `CHANGELOG.md`; include PR-body release-note context if user-visible.
