## Summary

This PR remains necessary: the base-side implementation shown by the PR diff decodes provider text responses with a forgiving decoder, while the branch makes malformed bytes fail consistently with the adjacent JSON path. The one-line change is plausible and has submitted terminal proof, but a maintainer should complete the shared-caller review before merge because this helper is part of the provider HTTP surface.

## What This Changes

The branch makes `readProviderTextResponse` decode UTF-8 in fatal mode so malformed provider response bytes throw instead of being replaced with U+FFFD.

## Best Possible Solution

Keep the strict decoder if maintainer review confirms every caller converts the resulting decode failure into the intended provider-error path, and add focused text-response regression coverage alongside the existing JSON invalid-UTF-8 coverage when practical.
