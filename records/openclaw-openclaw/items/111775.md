## Summary

Keep this PR open for revision: strict UTF-8 is appropriate for JSON parsing, but this helper is the plain-text fallback used to preserve provider error diagnostics, so turning malformed bytes into an uncaught decode error can replace a usable provider failure with a generic `TypeError`.

## What This Changes

The branch changes `readProviderTextResponse` to use fatal UTF-8 decoding so malformed provider response bytes throw instead of being replacement-decoded.

## Best Possible Solution

Keep the plain-text fallback tolerant and preserve the provider diagnostic; if a particular structured consumer requires strict encoding validation, apply it only there with focused caller-level coverage and a clear error-preservation policy.
