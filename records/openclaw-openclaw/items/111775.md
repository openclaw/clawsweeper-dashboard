## Summary

Keep this PR open: the text-path change is directionally correct, but it does not deliver the malformed-JSON rejection claimed in the PR body, because the sibling JSON decoder on current main still replaces invalid UTF-8 bytes before parsing.

## What This Changes

The branch changes `readProviderTextResponse` to decode provider text with a fatal UTF-8 `TextDecoder` instead of silently replacing malformed bytes.

## Best Possible Solution

Use fatal UTF-8 decoding for both successful plain-text and JSON provider response readers, retain best-effort decoding for non-2xx diagnostic-body extraction, and add focused regression tests for both successful-response paths.
