## Summary

Keep this PR open, but do not merge it as written. The deleted branch is still required for Bun canaries that OpenClaw currently admits through the `node:sqlite` capability probe but that predate Bun commit `6c12afd8e`; the PR body identifies such builds as regressing back to `ERR_UNKNOWN_ENCODING` for child-process spawns.

## What This Changes

This PR removes the Bun-only process-spawn workaround that clears execa’s buffered-output encoding before it reaches Bun’s `child_process.spawn`.

## System Context

OpenClaw routes CLI, Doctor, and other child-process work through one process-execution boundary. That boundary passes execa options to the runtime spawn implementation, so its Bun compatibility handling affects command execution and buffered output across the product.

## Architecture Diagram

flowchart TD

  B --> C[execa process options]
  C --> D[Bun child-process spawn]
  D --> E[Command output and exit result]
  F[Bun runtime capability guard] --> B

## Best Possible Solution

Keep the Bun encoding workaround until OpenClaw’s Bun admission path and user guidance require a tested upstream Bun release that definitely includes the spawn fix, then remove the workaround as one compatibility-validated change.

## Solution Assessment

No. Removing the workaround is only safe once every Bun runtime OpenClaw admits contains the upstream fix; retaining the narrow compatibility branch until a fixed minimum is enforced is the safer and more maintainable path.
