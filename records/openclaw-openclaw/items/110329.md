## Summary

Keep this PR open for its assigned maintainer review. The branch addresses a remaining message-tool discovery failure not covered by the earlier gateway-level isolation work: unavailable SecretRefs should exclude only the affected account while healthy sibling accounts remain actionable; the exact-head dependency check still needs resolution and several required gates are in progress.

## What This Changes

This PR changes Google Chat, Slack, Zalo, and Mattermost account inspection so read-only message-action discovery skips accounts with unavailable SecretRef credentials without weakening strict credential resolution for sends, startup, and other direct account use.

## System Context

Each channel plugin turns configured account credentials into an advertised set of message actions for the gateway and agent `message` tool. Account inspection feeds that discovery path, while direct channel operations use strict resolution and fail closed when credentials are unavailable.

## Architecture Diagram

  Inspect --> Filter[Available account filtering]
  Filter --> Discovery[Message-action discovery]
  Discovery --> Gateway[Gateway tool schema]
  Gateway --> Agent[Agent message tool]
  Config --> Strict[Strict direct resolution]
  Strict --> Send[Send and startup paths]

## Best Possible Solution

Keep strict resolution for operational paths and land the inspection-only account isolation once the exact-head dependency failure is resolved or shown unrelated and the remaining required checks complete successfully.
