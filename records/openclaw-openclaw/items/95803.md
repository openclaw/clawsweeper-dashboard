## What This Changes

The PR updates the embedded agent tool-end handler to remove pending tool-media entries already delivered by the `message` tool and adds focused regression tests for success, failure, and pending flag cleanup cases.

## Best Possible Solution

Keep the handler-level success/failure suppression, but make media matching one-to-one or path-aware so distinct same-name files survive, keep the pending flags consistent, and require real behavior proof or a maintainer override before merge.

## Reproduction Assessment

Yes, source inspection gives a high-confidence path: current main records successful message-tool media while leaving pending tool media to be flushed later as a fallback. I did not run the regression tests or a live transport repro in this read-only review.

## Solution Assessment

No as submitted. `handleToolExecutionEnd` is the right layer because it sees successful versus failed message-tool sends, but the basename Set should not delete every same-name pending file when only one was delivered.
