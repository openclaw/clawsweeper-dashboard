## Label Justifications

- `P2`: The report identifies a bounded but meaningful workspace and Git integrity hazard for Android Termux/proot users, without evidence of a broad current OpenClaw outage.
- `impact:data-loss`: The report includes a concrete claim that Git can commit a zero-byte blob after shared-storage bulk writes, which can silently corrupt workspace history.
- `impact:ux-friction`: Users lack clear in-product documentation that keeps dependencies and workspaces off Android shared storage, increasing setup and recovery burden.

## Summary

Keep open for maintainer direction. Current documentation explicitly describes Android only as a companion node and says its Gateway runs on macOS, Linux, or Windows via WSL2, while the environment documentation already includes a Termux-specific home fallback. The requested warning is credible—Termux documents that shared storage disallows executable files and symlinks and can disrupt Git repositories—but calling Termux/proot Gateway hosting “supported in practice” would change the documented platform boundary. Likely related people: `steipete` is the low-confidence routing candidate through current Android/release ownership signals.

## What This Changes

Document the safe Android Termux/proot workspace location and shared-storage hazards, with an optional health check for workspaces under `/storage/emulated/0`.

## System Context

OpenClaw’s Gateway owns agent workspaces, configuration, and Git-backed workflows, while the Android app normally connects as a companion node. A Termux/proot host changes the filesystem underneath those workspace operations, so storage semantics can affect dependency installation and Git’s view of created files.

## Architecture Diagram

flowchart LR
  A[Termux or proot host] --> B[OpenClaw Gateway]
  B --> C[Agent workspace]
  C --> D[Shared Android storage check]
  D -->|safe private filesystem| E[Git and dependency workflows]
  D -->|noexec or no symlinks| F[Documented mitigation]
  F --> E

## Best Possible Solution

After maintainer confirmation, add a short, clearly scoped Termux/proot note that keeps Gateway state, `node_modules`, and Git workspaces on the private `$HOME` filesystem; link to supported host guidance and describe shared storage as unsuitable for executable, symlink-heavy, or Git-sensitive work. Defer any Doctor warning until its cross-platform detection and support promise are explicitly defined.
