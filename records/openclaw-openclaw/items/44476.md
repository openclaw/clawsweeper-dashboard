## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve systemd exit-78 on healthy lock conflicts:** `src/cli/gateway-cli/run.ts:568`
  - body: Current main and v2026.6.11 intentionally return exit 78 for healthy systemd already-running locks so `Restart=always` respects `RestartPreventExitStatus=78`. This branch's healthy-probe path exits 0 unconditionally; a rebase that keeps that behavior would reopen the restart storm the current code prevents.
  - confidence: 0.89
- **[P2] Probe trusted-proxy through a trusted source:** `src/cli/gateway-cli/run.ts:562`
  - body: Adding synthetic trusted-proxy headers is not enough for trusted-proxy mode because current auth also checks `req.socket.remoteAddress` against `gateway.trustedProxies` and rejects loopback unless configured. In deployments where the real proxy is a different host, this direct local probe still reports a healthy gateway as unhealthy.
  - confidence: 0.86
- **[P2] Bracket IPv6 custom bind hosts before probing:** `src/cli/gateway-cli/run.ts:173`
  - body: This path feeds `resolveGatewayBindUrl` output directly into the probe list, but that helper emits unbracketed custom IPv6 hosts such as `ws://::1:18789`. That invalid URL gets filtered or fails parsing, so an IPv6-only healthy listener can still be treated as unhealthy.
  - confidence: 0.8
- **[P3] Restore the unrelated update package-spec coverage:** `src/cli/update-cli.test.ts:513-517`
  - body: The branch removes the existing `OPENCLAW_UPDATE_PACKAGE_SPEC` package-update test while only needing a null guard in the previous test. Rebase onto current main's replacement table or restore the coverage so this gateway fix does not drop an unrelated update contract check.
  - confidence: 0.78
