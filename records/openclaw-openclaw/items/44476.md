## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P2] Make trusted-proxy probes satisfy source trust:** `src/cli/gateway-cli/run.ts:559`
  - body: Adding synthetic identity headers here is not enough for `gateway.auth.mode=trusted-proxy`: the server also verifies that `req.socket.remoteAddress` is in `gateway.trustedProxies`, and rejects loopback sources unless `allowLoopback` is true. In common trusted-proxy deployments this probe still reports unhealthy, so EADDRINUSE keeps exiting non-zero for an auth mode the PR says it handles.
  - confidence: 0.9
- **[P2] Bracket IPv6 bind hosts before probing:** `src/cli/gateway-cli/run.ts:168`
  - body: The bind URL helper concatenates custom hosts as `scheme://host:port`, so an IPv6 custom host such as `::1` becomes an invalid `ws://::1:18789` candidate and gets filtered out before probing. If the healthy gateway is bound only to that IPv6 address, the fallback to `127.0.0.1` misclassifies it as unhealthy and the restart-loop fix still fails.
  - confidence: 0.84
- **[P3] Restore the package-spec update coverage:** `src/cli/update-cli.test.ts:523`
  - body: This hunk deletes the branch's coverage for `OPENCLAW_UPDATE_PACKAGE_SPEC` even though the PR does not intentionally change update behavior. Keep the test while fixing the local type issue so an unrelated update override contract does not lose regression coverage.
  - confidence: 0.82
