## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.83

Full review comments:

- **[P1] Preserve systemd exit-78 duplicate-start semantics:** `src/cli/gateway-cli/run.ts:568`
  - body: Current main intentionally returns exit 78 for healthy systemd-supervised lock conflicts so `RestartPreventExitStatus=78` stops `Restart=always` loops. This branch exits 0 for every confirmed healthy listener, so a rebase that keeps this behavior would regress systemd users while solving only the `Restart=on-failure` case.
  - confidence: 0.86
- **[P2] Do not authenticate trusted-proxy probes with headers alone:** `src/cli/gateway-cli/run.ts:562`
  - body: In trusted-proxy mode, server auth also verifies the socket source address and may reject loopback unless explicitly allowed. This code only injects proxy headers while dialing directly, so deployments where the real trusted proxy is elsewhere still report the healthy listener as unhealthy and keep the EADDRINUSE loop.
  - confidence: 0.82
- **[P2] Move header forwarding to the current package client:** `src/gateway/client.ts:77`
  - body: Current main delegates the OpenClaw wrapper to `packages/gateway-client`, whose options and WebSocket construction do not accept `headers`. A rebase that keeps this wrapper-only addition will not reliably deliver trusted-proxy headers; the package client and probe contract need to be updated together.
  - confidence: 0.8
- **[P2] Normalize IPv6 bind hosts before probing:** `src/cli/gateway-cli/run.ts:166`
  - body: `resolveGatewayBindUrl` currently concatenates custom hosts directly, so an IPv6 custom host such as `::1` becomes an invalid URL like `ws://::1:18789`. The probe then filters it out and falls back to IPv4 loopback, misclassifying a healthy IPv6-bound gateway as unhealthy.
  - confidence: 0.74
