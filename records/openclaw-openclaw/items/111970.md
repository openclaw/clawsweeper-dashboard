## Summary

Keep this PR open. The defect report, focused regression coverage, and current-head Telegram evidence support the bounded-wait behavior, but releasing an older completed reply after 20 seconds changes the foreground freshness/ordering contract and needs an explicit owner decision before merge.

## What This Changes

This PR moves foreground reply fencing into a dedicated auto-reply module, caps an older final reply’s wait behind a newer active same-target turn at 20 seconds, and lets non-stale tool-status payloads proceed without waiting.

## System Context

Auto-reply dispatch serializes outbound tool updates and final answers, then runs delivery hooks before a channel sends them. The foreground reply fence coordinates concurrent turns for one conversation target, suppressing an older reply when a newer visible reply wins.
