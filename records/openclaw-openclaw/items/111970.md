## Summary

Keep this PR open for maintainer merge review: it is a focused P1 reliability repair with targeted regression coverage and reported production evidence, but it intentionally permits an older reply to deliver after a 20-second settlement window, changing the foreground freshness tradeoff for visible channel messages.

## What This Changes

The PR bounds foreground reply-fence waits at 20 seconds, immediately passes through non-stale tool-status payloads, extracts the fence into a dedicated module, and adds regression tests.

## Best Possible Solution

Keep one generic foreground-fence owner, retain stale suppression when a newer visible response actually wins, and merge the bounded fail-open behavior only if the reply-delivery owners accept the 20-second ordering tradeoff for long successor turns.
