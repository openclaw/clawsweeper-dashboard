## Summary

Keep open: current main and the latest release still omit `label`/`displayName` from the shared status summary and render raw session keys in the CLI/TUI status surfaces; the picker/control UI work only partially overlaps, and an open conflicting fork PR already claims the narrow fix path.

## What This Changes

The issue asks for cron/session labels to be shown in `/status`, the TUI statusline, and session picker instead of UUID-heavy session keys.

## Best Possible Solution

Propagate a single sanitized display label through the shared status summary contract, render it consistently in CLI/TUI status surfaces and the footer/statusline with raw-key fallback/detail, and leave broader status/usage JSON attribution to the separate open request.
