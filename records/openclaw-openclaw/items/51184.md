## Summary

Keep open: current main still has the reported CLI/TUI gap. Cron sessions can carry friendly labels, and sibling session list surfaces can expose labels, but the shared `/status` contract and TUI status renderers still omit `label`/`displayName` and render the raw session key.

## What This Changes

Request to show cron job/session labels instead of UUID-heavy session keys in `/status`, the TUI statusline, and session selection surfaces.

## Best Possible Solution

Propagate sanitized session `label`/`displayName` through the shared status contract, render the friendly label as the primary CLI/TUI status display with raw-key fallback/detail, and keep stable JSON attribution fields in the separate broader issue.
