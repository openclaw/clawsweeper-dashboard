## Summary

Keep open: current main still drops existing `label`/`displayName` metadata before the shared status renderers and still renders raw session keys in the TUI status summary, CLI status rows, and statusline. The merged Control UI dropdown fix only covers a sibling surface, and the same-scope PRs are closed or conflicting rather than merged into the target repository.

## What This Changes

Surface existing session labels, display names, or cron job names in TUI `/status`, the statusline, and the session picker instead of raw UUID-heavy session keys.

## Best Possible Solution

Propagate existing sanitized session `label`/`displayName` through the shared status contract, render the friendly label as primary in CLI/TUI status and the statusline with raw-key fallback/detail, and leave broader JSON attribution fields to https://github.com/openclaw/openclaw/issues/85688.

## Reproduction Assessment

Yes. Source inspection on current main shows stored session labels exist, but the shared status summary omits them and CLI/TUI status renderers still print raw session keys.

## Solution Assessment

Yes for the requested end state, but not as the stale/conflicting PR branch currently stands. The maintainable fix is shared status-summary label propagation plus terminal-safe rendering and raw-key fallback, not per-renderer cron-key parsing.
