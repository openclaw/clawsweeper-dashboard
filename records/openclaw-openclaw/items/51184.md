## Summary

Keep open: current main and the latest release still omit stored session `label`/`displayName` from the shared `/status` session contract and keep raw cron session keys primary in CLI/TUI status surfaces. The Control UI dropdown and dashboard-style session displays are partially fixed elsewhere, but they do not cover the requested `/status` and statusline behavior.

## What This Changes

Request to show cron job names or session labels instead of UUID-heavy session keys in `/status`, the TUI statusline, and session pickers.

## Best Possible Solution

Propagate terminal-sanitized `label`/`displayName` through the shared status contract, render the friendly label primary with raw-key fallback/detail in CLI/TUI `/status` and the statusline, and keep broader JSON attribution fields in the separate open request.
