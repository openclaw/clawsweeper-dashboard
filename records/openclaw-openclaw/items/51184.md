## Summary

Keep open: current main still has the reported CLI/TUI status gap. Cron sessions already carry friendly labels and sibling session-list surfaces expose label/displayName metadata, but the shared `/status` rows and TUI status rendering still use raw session keys; maintainer direction is needed before starting a competing fix while product-decision labels and an open cross-repository candidate PR exist.

## What This Changes

Request to show cron job names or session labels in `/status`, the TUI statusline, and session selection surfaces instead of UUID-heavy session keys.

## Best Possible Solution

Propagate sanitized `label`/`displayName` through the shared status contract, render the friendly label as the primary CLI/TUI status display with raw-key fallback or detail, and keep stable JSON attribution fields in the broader follow-up issue.
