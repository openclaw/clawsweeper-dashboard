## Summary

Keep open: current main and the latest release still omit `label`/`displayName` from the shared status summary and render raw session keys in CLI/TUI status surfaces; the merged Control UI dropdown fix and broader JSON attribution issue only partially overlap.

## What This Changes

The issue requests surfacing cron job names or session labels in `/status`, the TUI statusline, and session selection instead of UUID-heavy session keys.

## Best Possible Solution

Propagate existing sanitized session `label`/`displayName` through the shared status contract, render the friendly label as primary in CLI/TUI status and statusline with raw-key fallback/detail, and leave broader JSON attribution fields to the separate open attribution issue.

## Reproduction Assessment

Yes. Source inspection shows current main and `v2026.6.11` still drop `label`/`displayName` before the shared status renderers, and the CLI/TUI status surfaces print raw session keys.

## Solution Assessment

Yes on the desired fix shape, but not as the stale linked PR currently stands. The maintainable solution is shared status-summary label propagation with terminal sanitization and raw-key fallback, not per-renderer cron-key parsing.
