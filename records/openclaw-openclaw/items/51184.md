## Summary

Keep open: current main and v2026.6.11 still drop session `label`/`displayName` before the shared `/status` and TUI status renderers, so cron runs still render as raw session keys there. ## What This Changes

Request to surface cron job names or session labels in `/status`, the TUI statusline, and the session picker instead of raw UUID-heavy session keys.

## Best Possible Solution

Land or replace the linked candidate with a bounded shared status-contract change that carries sanitized friendly labels into CLI/TUI status displays while preserving raw session-key fallback and copyability.

## Reproduction Assessment

Yes. Source inspection shows current main does not carry `label`/`displayName` into `SessionStatus`, and the CLI/TUI status renderers print raw session keys.

## Solution Assessment

Yes on the likely fix shape, but maintainers still need to confirm the product contract. The maintainable path is shared status-summary label propagation with sanitized friendly text and raw-key fallback, not per-renderer cron-key parsing.
