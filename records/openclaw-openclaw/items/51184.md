## Summary

Keep open: current main still drops `label`/`displayName` before the shared `/status` and TUI status summary renderers, and the latest release has the same gap. The session picker path has been partly improved, but the open linked fork PR is still unmerged and conflicting, so this needs maintainer adoption or replacement rather than cleanup closure.

## What This Changes

The issue requests friendly cron job and session labels in `/status`, the TUI statusline, and session pickers instead of UUID-heavy session keys.

## Best Possible Solution

Define one sanitized friendly session display field in the shared status summary, render that field in human CLI/TUI status surfaces, and keep raw session keys available for identity, JSON, and commands.

## Reproduction Assessment

Yes. Source inspection shows the session store carries `label`/`displayName`, while current main and `v2026.6.11` omit those fields from `SessionStatus` and render recent status rows from raw `key`; I did not run a live TUI scenario in this read-only review.

## Solution Assessment

Unclear for the linked PR as-is because maintainers still need to settle the display contract and repair the conflicting branch. The maintainable direction is a shared sanitized display field for human status rows while preserving raw keys for identity/API use.
