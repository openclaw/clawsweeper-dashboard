## Summary

Keep open: current main and the latest release still omit stored session label/displayName fields from the shared status row contract, so CLI/TUI `/status` continues to render raw session keys. The Control UI and derived-title fixes are useful partial overlaps, but the remaining status/statusline work still needs maintainer adoption or a fresh replacement for the conflicting fork candidate.

## What This Changes

Request to show stored session labels, display names, or cron job names instead of UUID-heavy keys in CLI/TUI `/status`, the TUI statusline, and session selection surfaces.

## Best Possible Solution

Land or replace the linked candidate with a bounded shared status-contract change that carries sanitized `label`/`displayName` into CLI/TUI status displays while preserving raw session-key fallback and leaving broader JSON attribution to https://github.com/openclaw/openclaw/issues/85688.

## Reproduction Assessment

Yes. Source inspection shows current main and the latest release do not carry label/displayName into `SessionStatus`, and the CLI/TUI status renderers still print raw session keys.

## Solution Assessment

Yes on the product direction, but not through the stale branch as-is. The maintainable fix is shared status-summary label propagation with terminal-safe friendly text and raw-key fallback, not per-renderer cron-key parsing.
