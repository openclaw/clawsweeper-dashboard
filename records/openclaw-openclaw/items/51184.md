## Summary

Keep open: current main still drops session label/displayName before the shared status renderers, so CLI status and the TUI status summary continue to render raw session keys. Recent work fixed adjacent picker/derived-title behavior, but the requested status/statusline display contract remains unresolved and should be handled by maintainer-reviewed adoption or replacement of the stale linked implementation.

## What This Changes

Request to show cron job names, session labels, or display names in status, the TUI statusline, and session selection instead of UUID-heavy session keys.

## Best Possible Solution

Carry sanitized friendly display fields through the shared status summary for CLI and TUI human output, while preserving raw session keys as stable identifiers for JSON, selectors, and commands.

## Reproduction Assessment

Yes, by source inspection: current main has session label/displayName metadata, but the shared status summary and CLI/TUI status renderers still expose only raw keys. I did not run a live TUI scenario in this read-only review.

## Solution Assessment

Unclear until maintainers settle the human-display contract; the narrow maintainable path is to add sanitized friendly display fields to shared status rows while keeping raw keys for identity and machine-facing consumers.
