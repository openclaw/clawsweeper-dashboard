## Summary

Keep open: current main still drops session `label` and `displayName` before the shared CLI/TUI status renderers, and the latest release has the same gap. The Control UI picker portion is partially fixed, but `/status` and the TUI status summary still render raw session keys, while the statusline still keeps the raw key as the primary label.

## What This Changes

The issue asks for cron job/session labels to appear in `/status`, the statusline, and session picker instead of raw UUID-heavy session keys.

## Best Possible Solution

Carry sanitized friendly session display fields through the shared status summary for CLI and TUI rendering while preserving raw session keys as stable identity for selectors, JSON consumers, and follow-up commands.

## Reproduction Assessment

Yes, by source inspection: current main has session `label`/`displayName` metadata, but the shared status summary, CLI session table, and TUI status summary still render only raw keys. I did not run a live TUI scenario in this read-only review.

## Solution Assessment

Unclear as an implementation choice until maintainers settle the display contract. The maintainable direction is to add sanitized display fields to the shared status summary while keeping raw keys available for identity and commands.
