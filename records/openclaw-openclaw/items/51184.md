## What This Changes

Request to show cron job names or session labels instead of raw UUID-heavy session keys in `/status`, the TUI statusline, and session pickers.

## Best Possible Solution

Carry sanitized `label`/`displayName` through the shared status summary contract and render it as the friendly primary identifier in CLI/TUI status surfaces while preserving raw-key fallback/copyability.

## Reproduction Assessment

Yes. Source inspection on current main shows `SessionStatus` lacks `label`/`displayName`, the summary builder returns key-only rows, and the CLI/TUI status renderers still print raw keys.

## Solution Assessment

Unclear pending maintainer choice. The maintainable fix is shared status-summary label propagation with sanitized display text and raw-key fallback, not per-renderer cron-key parsing or the stale conflicting PR as-is.
