## Summary

Keep open: current main still drops session `label`/`displayName` before the shared status renderers, so `/status` and the TUI status summary continue to show raw cron run keys. The Control UI/session-picker work is only a partial overlap, and the open fork PR that references this issue is conflicting, so maintainers should adopt or replace that path rather than close this issue now.

## What This Changes

The issue requests friendly cron/session labels in `/status`, the TUI statusline, and session selection surfaces instead of raw UUID-heavy session keys.

## Best Possible Solution

Adopt or replace the linked candidate with a bounded shared status-contract change that carries sanitized `label`/`displayName` into CLI/TUI status displays while preserving raw-key fallback and copyability.

## Reproduction Assessment

Yes. Source inspection shows current main does not carry `label`/`displayName` into `SessionStatus`, and the CLI/TUI status renderers print raw session keys.

## Solution Assessment

Yes on the narrow direction, but not by merging the old candidate as-is. The maintainable path is shared status-summary label propagation with sanitized friendly text and raw-key fallback, not ad hoc cron-key parsing in each renderer.
