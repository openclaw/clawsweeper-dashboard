## Summary

Keep open: current main and the latest release still carry cron/session labels in stored metadata but drop them before the shared CLI/TUI status renderers, while the TUI picker/statusline only partially use displayName. ## What This Changes

The issue requests friendly cron job and session labels in `/status`, the TUI statusline, and the session picker instead of raw UUID-heavy session keys.

## Best Possible Solution

Carry sanitized friendly display fields through the shared status summary for CLI and TUI rendering, while preserving raw session keys as stable identity for selectors, JSON consumers, and follow-up commands.

## Reproduction Assessment

Yes, by source inspection: session and cron metadata include labels, but current main drops those fields before the CLI/TUI status renderers and prints raw keys. I did not run a live TUI scenario in this read-only review.

## Solution Assessment

Unclear as an implementation choice until maintainers settle the display contract. The narrow maintainable direction is sanitized friendly display fields plus raw-key preservation for identity and follow-up commands.
