## Summary

Keep open: current main still has the same status-display gap. Cron sessions already get human-readable labels, and Control UI picker behavior was partly fixed, but the shared status summary, CLI status rows, TUI status summary, and TUI footer still expose raw session keys as the primary identifier.

## What This Changes

The issue requests surfacing existing cron job names or session labels in status output, the TUI statusline, and session-picking surfaces instead of raw UUID-heavy session keys.

## Best Possible Solution

Propagate existing sanitized session `label`/`displayName` through the shared status contract, render the friendly label as primary in CLI/TUI status and the statusline with raw-key fallback/detail, and leave broader stable JSON attribution fields to https://github.com/openclaw/openclaw/issues/85688.

## Reproduction Assessment

Yes. Source inspection on current main shows cron run labels are populated, but the shared status summary and CLI/TUI status renderers still carry and display the raw `key` only; I did not run a live TUI session.

## Solution Assessment

Yes on the desired fix shape, but not as a stale or conflicting PR. The maintainable solution is shared status-summary label propagation with terminal sanitization and raw-key fallback/detail, not per-renderer cron-key parsing.
