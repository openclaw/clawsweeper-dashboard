## Summary

Keep open: current `main` and latest release still drop session `label`/`displayName` before the shared status renderers, so CLI `/status` and the TUI status summary continue to show raw session keys. ## What This Changes

The issue requests friendly cron job/session labels in `/status`, the TUI statusline, and session picker instead of raw UUID-heavy session keys.

## Best Possible Solution

Carry sanitized friendly session display fields through the shared status summary for CLI and TUI rendering while preserving raw session keys as stable identity for selectors, JSON consumers, and follow-up commands.

Unclear as an implementation choice until maintainers settle the display contract. The narrow maintainable solution is to add sanitized display fields to the shared status summary while keeping raw keys for identity and selection.
