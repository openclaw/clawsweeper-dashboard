## Summary

Keep open: current main and the latest release still drop session `label`/`displayName` before `/status` and TUI status rendering, so cron runs remain UUID-heavy outside the already-fixed Control UI dropdown path.

## What This Changes

The issue requests showing friendly cron/session labels in `/status`, the TUI statusline, and session selection instead of raw cron run session keys.

## Best Possible Solution

Propagate existing sanitized session `label`/`displayName` through the shared status contract, render the friendly label as primary in CLI/TUI status and the footer with raw-key fallback, and leave broader JSON attribution fields to #85688.

Yes, if implemented through the shared status summary and one sanitized display helper. Per-renderer cron-key parsing would be a weaker fix, and the broader stable JSON attribution work should remain separate.
