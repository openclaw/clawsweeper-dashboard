## Summary

Keep open: current main and v2026.6.11 still render raw session keys in the shared CLI/TUI status paths, while the merged Control UI picker work and the broader JSON attribution issue only partially overlap.

## What This Changes

The issue requests friendlier cron/session labels in `/status`, the TUI statusline, and the session picker instead of UUID-heavy session keys.

## Best Possible Solution

Propagate sanitized `label`/`displayName` through the shared status summary and render the friendly label as primary in CLI/TUI status and the TUI footer, with raw-key fallback/detail and the broader JSON attribution work left to the separate issue.
