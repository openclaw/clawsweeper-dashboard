## Summary

Keep open: current main and v2026.6.11 still omit session label/displayName from the CLI/TUI status rows, while the session picker is only partly addressed and the remaining fix needs maintainer choice around sanitized friendly labels and selector/key behavior.

## What This Changes

The issue requests friendly cron job/session labels in TUI `/status`, the statusline, and the session picker instead of UUID-heavy raw session keys.

## Best Possible Solution

Add a shared, terminal-sanitized session display label for status rows and the statusline while keeping the raw key available for precise selection/copying, then review/land or close the linked repair path.
