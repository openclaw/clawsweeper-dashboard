## Summary

Keep open: current main still drops `label`/`displayName` before the CLI/TUI status render paths and keeps the raw session key primary in the TUI footer. The merged Control UI dropdown fix only covers a related picker surface, and the direct status fix remains an unmerged open fork PR.

## What This Changes

Request to show friendly cron/session labels instead of raw UUID-heavy session keys in `/status`, the statusline, and session picker.

## Best Possible Solution

Land a maintained current-main implementation that computes one friendly session display label from `displayName`, `label`, cron metadata, and raw-key fallback, then carries it through the shared status/session row contract into CLI `/status`, TUI gateway status, and the TUI footer.

## Reproduction Assessment

Yes: source inspection on current main shows `/status` and the TUI status summary still render the raw session key as the primary identifier. I did not run a live TUI session because this read-only review already has a clear source-level path.

## Solution Assessment

Yes in direction, but not via the stale branch without maintainer refresh. The best fix should use a shared display-label contract and preserve raw-key fallback instead of adding separate formatting rules to each status surface.
