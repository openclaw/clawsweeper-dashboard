## Summary

Keep open. Current main and v2026.6.11 contain useful macOS update and node-host recovery hardening, but the reported `ai.openclaw.manualupdate.<date>.<epoch>` keepalive job family still is not recognized by stale-updater cleanup, and the same-version update/no-op restart policy remains a maintainer decision rather than a completed fix.

## What This Changes

The issue asks OpenClaw to make macOS updates leave the LaunchAgent Gateway and local node host in a coherent state instead of looping through stale manual updater jobs, repeated Gateway restarts, and node/Gateway version mismatch recovery.

## Best Possible Solution

Define the macOS managed-update contract, then implement a safe stale-job cleanup/dedupe path for `manualupdate` jobs, a same-version no-op or refusal policy before service churn, launchd health proof, and a non-terminal Doctor/Fix recovery surface for affected users.
