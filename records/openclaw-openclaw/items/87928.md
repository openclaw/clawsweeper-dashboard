Question: For macOS package updates already at the target version, should OpenClaw skip managed-service stop/restart by default while cleaning up duplicate submitted launchd updater jobs, or preserve same-version refresh semantics and solve only the stale-job supervisor loop?

Rationale: Current tests intentionally refresh same-version package installs, but the live failure shows that behavior becomes destructive when launchd relaunches submitted updater jobs; automation should not choose that product policy silently.

Likely owner: Vincent Koc

Owner reason: The unresolved choice centers on package update service-state behavior, where this owner has adjacent merged history.

Owner confidence: medium

Options:

- **Split and fix lifecycle policy (recommended):** Default no-op package updates should avoid managed-service stop/restart, stale `manualupdate`/manual-update submitted jobs should be deduped and cleaned up, and a real macOS LaunchAgent smoke should prove recovery.
- **Preserve refresh semantics:** Keep same-version package refresh as an explicit update behavior and narrowly repair submitted-job cleanup/dedupe so repeated launchd relaunches cannot keep killing the Gateway.
- **Defer to node-host fix only:** Treat the node-host mismatch fix as sufficient and leave the manual updater-loop/no-op refresh behavior unchanged, accepting that the 2026.6.1 repro path remains possible.
