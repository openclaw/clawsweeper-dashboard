## Summary

Keep open: current main and v2026.6.11 still do not provide a supported plugin source/Jiti hot-reload or cache-clear command, and the remaining work is an explicit plugin/Gateway lifecycle design rather than stale cleanup.

## What This Changes

The issue requests a faster plugin development reload path, such as `openclaw plugins reload <id>`, a source watcher, or a supported cache-clear command that avoids manual Jiti cache deletion plus container restart.

## Best Possible Solution

Design an explicit plugin development reload workflow through the Gateway/plugin loader that safely invalidates module and registry state, disposes old runtime registrations, and exposes a documented CLI/RPC command; if live runtime reload remains unsupported, document restart-only behavior with precise diagnostics.

## Reproduction Assessment

Yes, at source level: current main has no plugin reload/cache-clear CLI, keeps plugin install/load changes restart-backed, and documents restart as required. I did not run the Docker workflow, but the requested feature gap is clear in code and docs.

## Solution Assessment

No, a bare cache-delete command is not the best standalone fix because loader/Jiti invalidation without runtime disposal can leave stale or duplicated registrations. The maintainable solution needs a maintainer-approved reload contract or clearer restart-only documentation.
