## Summary

Keep open: current main and v2026.6.11 still do not provide a supported plugin source/Jiti hot-reload or cache-clear command. Current hot reload covers some plugin config changes, while plugin code, install records, and load paths remain restart-backed, and the latest substantive issue discussion explicitly kept the design work open.

## What This Changes

Request a supported plugin development reload path, such as `openclaw plugins reload <id>`, cache clearing, or a watcher, so TypeScript plugin edits can take effect without restarting the container.

## Best Possible Solution

Design an explicit plugin development reload workflow through the Gateway/plugin loader that safely invalidates module and registry state, disposes old runtime registrations, and exposes a documented CLI/RPC command; if that remains unsupported, document restart-only behavior with precise diagnostics.

## Reproduction Assessment

Yes, by source inspection: current main lacks a plugin reload/cache-clear CLI and tests still assert restart for plugin install and load-path changes. I did not run the Docker workflow, but the requested feature gap is clear in current code and docs.

## Solution Assessment

No, not as a small cache-delete command alone. The maintainable solution needs an owner-approved reload contract that handles loader cache invalidation plus runtime disposal/replacement, or else clearer restart-only documentation.
