## Summary

Keep open: current main and v2026.6.11 still leave plugin source/install changes restart-backed, there is no public plugin reload/cache-clear CLI, and the remaining work needs a Gateway/plugin-loader lifecycle decision rather than cleanup closure.

## What This Changes

The issue requests a supported plugin development reload or cache-clear workflow so TypeScript plugin edits can take effect without manually clearing Jiti cache and restarting the OpenClaw process/container.

## Best Possible Solution

Design a Gateway-owned plugin development reload lifecycle with explicit teardown, loader/Jiti/module cache invalidation, registry replacement, and documented CLI/RPC UX; if live source reload remains unsupported, make restart-only behavior and cache diagnostics precise.

Options:

- **Design first-class reload (recommended):** Specify and implement a Gateway-owned reload operation that safely disposes old plugin state, invalidates loader caches, replaces runtime registries, and exposes a documented CLI/RPC entrypoint.
- **Keep restart-only:** Leave source/install changes restart-backed and improve docs/logging so users know when a full Gateway restart is required and how to verify the active runtime.
- **Add cache diagnostics only:** Expose a narrow cache diagnostic or clear command without live registry replacement, accepting that users still need a restart for safe activation.

Yes, source-level: current main has no public plugin reload/cache-clear command, keeps plugin source/install paths restart-backed, and documents Gateway restart after plugin code changes. I did not run a live Docker plugin edit cycle in this read-only review.
