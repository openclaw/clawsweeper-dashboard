## Summary

Keep open: current main and v2026.6.11 still do not provide a supported plugin source/Jiti hot-reload or cache-clear command, and the remaining work needs plugin-loader/Gateway lifecycle design rather than conservative cleanup.

## What This Changes

The issue requests a supported plugin development reload or cache-clear workflow so TypeScript plugin changes can take effect without manually clearing Jiti cache and restarting the OpenClaw container.

## Best Possible Solution

Design an explicit plugin development reload workflow through the Gateway/plugin loader that invalidates loader/Jiti/module state, safely replaces runtime registrations, and exposes a documented CLI/RPC command; if live reload remains unsupported, document restart-only behavior with precise diagnostics.

## Reproduction Assessment

Yes, by source inspection: current main lacks a plugin reload/cache-clear CLI and still treats plugin source/install/load-path changes as restart-backed. I did not rerun the Docker workflow, but the requested feature gap is clear in code, tests, docs, and release state.

## Solution Assessment

No, a small cache-delete command alone is not the best solution. The maintainable fix needs an owner-approved reload contract that handles cache invalidation plus runtime disposal/replacement, or else clearer restart-only documentation.
