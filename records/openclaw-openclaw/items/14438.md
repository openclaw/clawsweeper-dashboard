## Summary

Keep open: current main and v2026.6.11 still lack a supported plugin source/Jiti reload or cache-clear command, and the remaining work needs Gateway/plugin-loader lifecycle design rather than conservative cleanup closure.

## What This Changes

Request a supported plugin hot-reload or Jiti cache-invalidation workflow so plugin developers do not need to restart OpenClaw or manually delete cache files after TypeScript plugin edits.

## Best Possible Solution

Design a Gateway-owned plugin development reload lifecycle with explicit teardown, loader/Jiti/module cache invalidation, registry replacement, and a documented CLI/API command; otherwise document restart-only behavior and supported cache diagnostics precisely.

## Reproduction Assessment

Yes, at source level. Current main has no public plugin reload/cache-clear command, keeps plugin source/install paths restart-backed, and documents Gateway restart after plugin code changes; I did not run a live container edit cycle in this read-only review.

## Solution Assessment

No, deleting Jiti cache files is only a workaround. The maintainable solution is a lifecycle-owned Gateway reload operation with explicit teardown, cache invalidation, registry replacement, and CLI/API semantics.
