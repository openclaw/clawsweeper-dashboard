## Summary

Keep open: current main has partial plugin-config hot reload, but the central request is still missing because plugin code/install/load-path changes remain restart-backed, there is no supported `openclaw plugins reload` or cache-clear command, and recent discussion still frames this as Gateway/plugin-loader lifecycle design work.

## What This Changes

Request a supported plugin hot-reload or cache-clear workflow so TypeScript plugin edits can invalidate Jiti/module caches and re-register runtime surfaces without restarting the container.

## Best Possible Solution

Design a generic Gateway/plugin reload API and CLI that invalidates loader/Jiti/module state, safely disposes and replaces plugin registrations, and documents restart-only boundaries where live reload remains unsupported.

## Reproduction Assessment

Yes. Source inspection shows no supported plugin reload/cache-clear command, docs still require restart for plugin code changes, and tests preserve restart-backed behavior for plugin install/source-path changes.

## Solution Assessment

Unclear as a concrete implementation path. A cache-file deletion command alone is not the best fix because the safe solution needs a maintainer-designed Gateway/plugin lifecycle seam with registry replacement and resource disposal semantics.
