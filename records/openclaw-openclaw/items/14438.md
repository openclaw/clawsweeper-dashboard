## Summary

Keep open: current main and v2026.6.11 still do not provide a supported plugin source/Jiti reload or cache-clear command, and source-changing plugin install/load-path changes remain restart-backed. A merged partial fix added hot reload for plugin management/config paths, but it deliberately left the central source-code reload request unresolved.

## What This Changes

The issue requests a supported plugin development hot-reload or cache-clear workflow so TypeScript plugin source changes can take effect without restarting the OpenClaw process/container.

## Best Possible Solution

Design a supported plugin development reload workflow that invalidates OpenClaw loader state plus Jiti module/filesystem cache state, safely swaps plugin registrations, and exposes it through a CLI/Gateway path; until then, keep restart-only source-change behavior documented.

## Reproduction Assessment

Yes. Source inspection shows current main has no `openclaw plugins reload` or cache-clear command, and tests/docs still keep plugin source/install/load-path changes restart-backed rather than live-reloadable.

## Solution Assessment

Unclear. A raw cache-clear command would help some Docker development loops, but the maintainable fix needs an explicit Gateway/plugin-loader lifecycle design so cache invalidation, runtime teardown, and registry replacement happen together.
