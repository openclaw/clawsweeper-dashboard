## Summary

Keep open: current main has improved plugin config hot reload, but it still does not provide the requested plugin source/Jiti cache reload or public `openclaw plugins reload` / cache-clear workflow, and the docs still route plugin code changes through Gateway restart behavior.

## What This Changes

The issue requests a supported plugin development reload path that invalidates Jiti/module caches and refreshes plugin registrations without restarting the container or Gateway process.

## Best Possible Solution

Design a Gateway-owned plugin development reload lifecycle with explicit teardown, loader/Jiti/module cache invalidation, registry replacement, and a documented CLI/RPC command; if live source reload remains unsupported, document restart-only behavior and cache diagnostics precisely.

## Reproduction Assessment

Yes, source-level: current main has no public plugin reload/cache-clear command, keeps plugin source/install paths restart-backed, and documents Gateway restart after plugin code changes. I did not run a live container edit cycle in this read-only review.

## Solution Assessment

No, a cache-clear-only command is not the best durable solution. The maintainable path is a lifecycle-owned Gateway reload operation that safely tears down old plugin state, invalidates loader caches, replaces registries, and exposes clear CLI/RPC semantics.
