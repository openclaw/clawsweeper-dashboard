## Summary

Keep open: current main still treats plugin code/install/load-path changes as restart-backed, has no supported `openclaw plugins reload` or cache-clear command, and the latest maintainer discussion keeps this as Gateway/plugin-loader lifecycle design work rather than cleanup-closeable stale noise.

## What This Changes

Request to add a supported plugin hot-reload or cache-clear workflow so TypeScript plugin changes can take effect without restarting the OpenClaw process/container.

## Best Possible Solution

Design a supported plugin development reload workflow backed by explicit Gateway/plugin-loader lifecycle ownership, including safe cache invalidation, runtime replacement, resource disposal, channel/provider/tool refresh, CLI/RPC UX, and docs; if live runtime swapping remains unsupported, document restart-only behavior with precise diagnostics and cache guidance.

## Reproduction Assessment

Yes from source: current main documents plugin code changes as restart-required, tests enforce restart-backed plugin install/load-path changes, and the plugin CLI lacks reload/cache-clear commands. I did not run a live Docker plugin edit loop in this read-only review.

## Solution Assessment

No, a narrow cache deletion command alone is not the best solution because it would not safely replace Gateway plugin registrations, services, hooks, tools, providers, and channel state. The best path is a maintainer-designed reload lifecycle or an explicit restart-only product decision with better diagnostics.
