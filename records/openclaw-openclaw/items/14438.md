## Summary

Keep open: current main and v2026.6.11 still lack a supported plugin source/Jiti reload or cache-clear CLI/RPC path; current code only hot-reloads some plugin policy/config changes while plugin load/install source changes remain restart-backed.

## What This Changes

Request a supported plugin development reload or cache-clear workflow so TypeScript plugin edits can take effect without restarting containers or manually deleting Jiti caches.

## Best Possible Solution

Design a Gateway-owned plugin development reload lifecycle with explicit teardown, loader/Jiti/module cache invalidation, registry replacement, and a documented CLI/RPC command; if live source reload remains unsupported, document restart-only behavior and cache diagnostics precisely.

## Reproduction Assessment

Yes, at source level: current main has no public plugin reload/cache-clear command, keeps plugin source/install changes restart-backed, and documents Gateway restart after plugin code changes. I did not run a live container edit cycle in this read-only review.

## Solution Assessment

No. Manual Jiti cache deletion is not the best fix; the maintainable solution is a lifecycle-owned Gateway reload operation with explicit teardown, cache invalidation, registry replacement, and CLI/RPC semantics.
