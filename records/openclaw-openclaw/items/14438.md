## Summary

Keep open: current main and the latest release still make plugin source/install changes restart-backed, expose no `openclaw plugins reload` or cache-clear command, and the issue already has maintainer/product-decision context plus later user evidence that a plugin install was not live until Gateway restart.

## What This Changes

Request a supported plugin development hot-reload or cache-clear workflow so TypeScript plugin edits can take effect without manually clearing Jiti cache and restarting the container.

## Best Possible Solution

Design a Gateway-owned plugin development reload lifecycle with explicit teardown, loader/Jiti/module cache invalidation, registry replacement, and a documented CLI/RPC command; if live source reload remains unsupported, document restart-only behavior and cache diagnostics precisely.

## Reproduction Assessment

Yes, at source level: current main has no public plugin reload/cache-clear command, documents plugin source/install changes as Gateway-restart-backed, and tests keep plugin source/install changes on the restart path. I did not run a live container edit cycle in this read-only review.

## Solution Assessment

Unclear until maintainers choose the plugin reload contract; a manual Jiti cache deletion or cache-clear-only command is not the durable fix. The maintainable path is a lifecycle-owned Gateway reload operation that safely tears down old plugin state, invalidates loader caches, replaces registries, and exposes clear CLI/RPC semantics.
