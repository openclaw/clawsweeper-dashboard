## Summary

Keep open: current main and v2026.6.11 still lack a supported plugin source/Jiti reload or cache-clear command, while source, docs, and tests keep plugin install/load changes restart-backed. The issue remains a valid feature/design request rather than a conservative cleanup close.

## What This Changes

Request a supported plugin development hot-reload or cache-clear workflow so TypeScript plugin edits can take effect without manually deleting Jiti cache files and restarting the container.

## Best Possible Solution

Design a Gateway-owned plugin development reload lifecycle with explicit teardown, loader/Jiti/module cache invalidation, registry replacement, and a documented CLI/API command; if live runtime reload stays unsupported, document restart-only behavior and supported cache diagnostics precisely.

## Reproduction Assessment

Yes, at source level. Current main has no public plugin reload/cache-clear command, keeps plugin install/load paths restart-backed, and documents Gateway restart after plugin code changes; I did not run a live container edit cycle in this read-only review.

## Solution Assessment

No, manual Jiti cache deletion is only a workaround. The maintainable solution needs a lifecycle-owned Gateway reload operation with teardown, cache invalidation, registry replacement, and CLI/API semantics.
