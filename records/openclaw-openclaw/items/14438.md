## Summary

Keep open: current main and the latest release still lack a supported plugin source/Jiti reload or cache-clear command, while plugin source/install changes remain restart-backed and the live discussion has maintainer/context evidence that this needs Gateway/plugin-loader lifecycle design.

## What This Changes

Request a supported plugin development hot-reload or cache-clear workflow so TypeScript plugin edits can take effect without restarting the OpenClaw process or container.

## Best Possible Solution

Design a Gateway-owned plugin development reload lifecycle with explicit teardown, loader/Jiti/module cache invalidation, registry replacement, and a documented CLI/API command; otherwise document restart-only behavior and supported cache diagnostics precisely.

## Reproduction Assessment

Yes, at source level. Current main has no public plugin reload/cache-clear command, keeps plugin source/install paths restart-backed, and documents Gateway restart after plugin code changes; I did not run a live container edit cycle in this read-only review.

## Solution Assessment

No, deleting Jiti cache files or adding a narrow cache-clear command alone is not the best fix. The maintainable solution is a lifecycle-owned Gateway reload operation with teardown, cache invalidation, registry replacement, and public CLI/API semantics.
