## Summary

Keep open: current main and v2026.6.11 still do not provide a supported plugin source/Jiti reload or cache-clear command, and the documented behavior still says plugin code install/update/uninstall requires a Gateway restart. Current hot reload covers plugin config/runtime replacement paths, but the requested developer workflow needs an explicit lifecycle design before implementation.

## What This Changes

The issue requests a supported plugin development reload or cache-clear workflow so TypeScript plugin changes do not require manual Jiti cache deletion and a process/container restart.

## Best Possible Solution

Design a supported plugin development reload path backed by Gateway/plugin-loader lifecycle ownership, then expose it as `openclaw plugins reload <id>` and/or `openclaw plugins clear-cache`; if source reload remains unsupported, document restart-only behavior and precise cache diagnostics.

## Reproduction Assessment

Yes, at source level: current main has no plugin reload/cache-clear CLI and still classifies plugin install/load-path changes as restart-backed. I did not run a live Docker/Jiti edit loop.

## Solution Assessment

Unclear: a reload or cache-clear command is plausible, but the best fix needs maintainer design for Gateway lifecycle, plugin teardown, runtime replacement, and Jiti/OpenClaw cache invalidation rather than a narrow cache deletion shortcut.
