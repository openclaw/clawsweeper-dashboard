## Summary

Keep open: current main and v2026.6.11 still require restart for plugin source/load-path changes and provide no plugin reload or cache-clear CLI/RPC, and the issue discussion includes user and maintainer context that the lifecycle design remains open.

## What This Changes

Request a supported plugin development reload or cache-clear workflow for TypeScript plugin/Jiti changes without restarting the OpenClaw process or container.

## Best Possible Solution

Design an explicit Gateway/plugin-loader reload contract that safely invalidates module and registry state, disposes old runtime registrations, and exposes a documented CLI/RPC command; if live source reload remains unsupported, keep restart-only behavior but document precise diagnostics and cache guidance.

## Reproduction Assessment

Yes. Source inspection shows current main lacks a plugin reload/cache-clear CLI and still treats plugin source/install/load-path changes as restart-backed; I did not run the Docker workflow.

## Solution Assessment

No, not as a small cache-delete command alone. The maintainable solution needs an owner-approved reload lifecycle that handles cache invalidation, runtime disposal, and registry replacement, or else clearer restart-only documentation.
