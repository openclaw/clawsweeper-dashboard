## Summary

Keep open: current main and v2026.6.11 still lack a supported plugin source/Jiti reload or cache-clear command, and plugin source/install changes remain restart-backed rather than live-reloadable.

## What This Changes

Request for a supported plugin development workflow that reloads TypeScript plugin code or clears the Jiti/plugin loader cache without restarting the OpenClaw process or container.

## Best Possible Solution

Design a Gateway-owned plugin development reload lifecycle with explicit teardown, loader/Jiti/module cache invalidation, registry replacement, and a documented CLI/RPC command; if live reload remains unsupported, document restart-only behavior and cache diagnostics precisely.

## Reproduction Assessment

Yes, at source level: current main has no public plugin reload/cache-clear command, keeps plugin source/install paths restart-backed, and documents Gateway restart after plugin code changes. I did not run a live container edit cycle in this read-only review.

## Solution Assessment

No. Manual Jiti cache deletion is only a workaround; the maintainable solution is a lifecycle-owned Gateway reload operation with explicit teardown, cache invalidation, registry replacement, and CLI/RPC semantics.
