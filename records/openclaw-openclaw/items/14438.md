## Summary

Keep open: current main and the latest release still require a Gateway restart for plugin code/install source changes, and there is still no supported `openclaw plugins reload` or cache-clear command. The remaining work is real core plugin-loader/Gateway lifecycle design, not stale cleanup.

## What This Changes

Request a supported plugin development reload workflow that invalidates Jiti/plugin loader state and re-registers plugin runtime surfaces without a full container restart.

## Best Possible Solution

Design a supported Gateway/plugin-loader reload workflow that safely invalidates module/Jiti state, swaps plugin registrations, disposes plugin-owned resources, restarts affected channels when needed, and exposes a clear `openclaw plugins reload <id>` or cache-clear UX with docs.
