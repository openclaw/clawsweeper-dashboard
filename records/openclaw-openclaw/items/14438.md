## Summary

Keep open: current main still lacks a supported plugin source/Jiti reload or cache-clear command, and both current source and docs keep plugin code/install/load-path changes restart-backed. The issue remains a valid plugin/Gateway lifecycle feature request, not conservative cleanup material.

## What This Changes

The issue requests a supported plugin development reload/cache-clear workflow so TypeScript plugin changes can take effect without a full process or container restart.

## Best Possible Solution

Design a Gateway-owned plugin development reload lifecycle with explicit teardown, loader/Jiti/module cache invalidation, registry replacement, and a documented CLI/API command; if live runtime reload stays unsupported, document restart-only behavior and supported cache diagnostics precisely.

## Reproduction Assessment

Yes, at source level. Current main has no public plugin reload/cache-clear command, keeps plugin install/load paths restart-backed, and documents Gateway restart after plugin code changes; no live container edit cycle was run in this read-only review.

## Solution Assessment

No, manual Jiti cache deletion is only a workaround. The maintainable solution needs a lifecycle-owned Gateway reload operation with teardown, cache invalidation, registry replacement, and CLI/API semantics.
