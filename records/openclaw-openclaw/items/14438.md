## Summary

Keep open: current main still has no supported plugin source/Jiti reload or cache-clear command, and current docs/tests keep plugin code/install/load-path changes restart-backed. This remains a valid product/design feature request rather than a conservative cleanup close.

## What This Changes

Request a supported plugin development hot-reload or cache-clear workflow so TypeScript plugin code changes can take effect without manual Jiti cache deletion and container or Gateway restart.

## Best Possible Solution

Design a Gateway-owned plugin development reload lifecycle with explicit teardown, loader/Jiti/module cache invalidation, registry replacement, and a documented CLI/API command; if live runtime reload stays unsupported, document restart-only behavior and supported cache diagnostics precisely.

## Reproduction Assessment

Yes, at source level. Current main has no public plugin reload/cache-clear command, keeps plugin install/load paths restart-backed, and documents Gateway restart after plugin code changes; I did not run a live container edit cycle in this read-only review.

## Solution Assessment

Unclear as proposed: manual Jiti cache deletion or a bare cache-clear command would be too narrow. The maintainable solution needs a lifecycle-owned Gateway reload operation with teardown, cache invalidation, registry replacement, and CLI/API semantics.
