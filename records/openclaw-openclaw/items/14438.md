## Summary

Keep open: current main and v2026.6.11 still do not provide a supported plugin source/Jiti hot-reload or cache-clear command, and the current code intentionally keeps plugin install/load-path changes restart-backed. The remaining work is valid but needs maintainer design across plugin loader cache invalidation, runtime replacement, Gateway lifecycle, and public CLI/RPC semantics.

## What This Changes

The issue requests a supported plugin development hot-reload or cache-clear workflow so TypeScript plugin edits can take effect without restarting the OpenClaw process/container.

## Best Possible Solution

Design a supported plugin development reload workflow through the Gateway/plugin loader that safely invalidates module and registry state, disposes old runtime registrations, and exposes a documented CLI/RPC command; if live runtime reload remains unsupported, document restart-only behavior with precise diagnostics.

## Reproduction Assessment

Yes, by source inspection: current main lacks a plugin reload/cache-clear CLI, docs still describe plugin code changes as restart-required, and tests assert installed plugin source changes stay restart-backed. I did not run the Docker workflow, but the feature gap is clear in current code and docs.

## Solution Assessment

No, a small cache-delete command alone is not the best fix. The maintainable solution needs an owner-approved reload contract that handles loader/Jiti cache invalidation plus runtime disposal and replacement, or else clearer restart-only documentation.
