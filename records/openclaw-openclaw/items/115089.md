## Summary

Keep this PR open: the warm-reuse optimization bypasses an upstream resume safety check because its new compatibility fingerprint omits the working directory and runtime workspace roots. A subsequent turn on the same physical client can therefore keep operating with the prior workspace identity instead of forcing the existing safe resume/reload path. Likely related people: steipete (high confidence, recent Codex lifecycle contributor).

## What This Changes

The PR retains one compatible persistent Codex app-server thread per physical client so the next ordinary turn can reuse its live subscription instead of resuming it from storage.

## System Context

The Codex extension maps an OpenClaw session binding to a native Codex app-server thread. On each turn it decides whether to start, resume, or reuse that thread, and that choice controls the active workspace, tools, approvals, and sandbox context used by the native runtime.

## Architecture Diagram

flowchart LR
  A[OpenClaw session turn] --> B[Stored Codex thread binding]
  B --> C[Lifecycle compatibility checks]
  C --> D{Retained live thread matches?}
  D -->|Yes| E[Reuse existing subscription]
  D -->|No| F[Resume or start native thread]
  F --> G[Upstream validates workspace and settings]
  E --> H[Run Codex turn]
  G --> H

## Best Possible Solution

Extend the warm-thread compatibility identity to include every upstream resume-visible workspace field, at minimum `cwd` and runtime workspace roots, and add a regression proving a same-client workspace change cannot reuse the retained subscription.

Yes, from source: retain a completed ordinary thread, then issue the next turn through the same physical client with a different `cwd` or runtime workspace-root set. No: retaining a live thread is a reasonable optimization, but the current fingerprint is not the complete native resume identity. The safe implementation must include the upstream workspace mismatch inputs or deliberately fall back to resume whenever those values are not provably identical.
