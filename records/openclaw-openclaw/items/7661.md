## Summary

Keep open. Current `main` and latest release still do not provide the requested end-to-end channel creation path: Slack does not advertise or dispatch channel creation, the CLI/docs expose only channel `info` and `list`, and the open Discord CLI PR covers only a narrower subset.

## What This Changes

The issue requests native `message` tool and CLI support for creating Slack, Discord, and similar messaging channels.

## Best Possible Solution

Approve a provider-owned, default-off channel-creation design first, then implement Slack discovery/runtime/setup/docs/tests and land or supersede the narrower Discord CLI wiring without moving provider policy into core.

## Reproduction Assessment

Yes. Source inspection on current main shows the shared `channel-create` action name and partial Discord provider support, while Slack discovery/runtime and the message CLI/docs still lack an end-to-end channel-creation surface.

## Solution Assessment

Unclear pending maintainer approval of the authority model. The maintainable direction is provider-owned channel creation behind explicit default-off gates and documented scopes, not treating admin channel creation as an ordinary send-style action.
