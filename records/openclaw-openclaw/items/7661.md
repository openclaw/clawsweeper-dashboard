## Summary

Keep open. Current main and v2026.6.11 still lack the requested complete path: Discord supports gated channel creation but the CLI exposes only channel info/list, while Slack has no channel-create gate, discovery, dispatch, or documented scope setup. The related open PR covers only Discord CLI wiring and does not resolve the Slack or authorization design.

## What This Changes

Add provider channel creation to the message tool and CLI, initially for Slack and Discord.

## Best Possible Solution

Keep Discord administration behind its existing provider gate and add a focused Slack plugin implementation behind a default-off channel-management gate, with explicit requester authorization, account-safe credential selection, required-scope documentation, CLI wiring, and provider-level regression tests.

Options:

- **Gate and authorize administration (recommended):** Keep provider action gates default-off and require a distinct maintainer-approved administrative authorization check before workspace or server mutation.
- **Use provider gate alone:** Treat the provider configuration gate and existing message-action write authority as sufficient, documenting the intentional expansion of authority.
- **Keep provisioning external:** Do not expose channel creation through OpenClaw and continue directing operators to provider APIs or external automation.

Yes. Current source clearly shows that the CLI exposes only channel info/list, Discord implements channel-create behind its channels gate, and Slack neither advertises nor dispatches channel-create.

## Solution Assessment

No, not as an unconditional cross-provider command. The narrow maintainable solution is provider-owned, default-off administration with explicit authorization, credential rules, documentation, and focused tests.
