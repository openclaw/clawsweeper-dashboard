## Summary

Keep open. Current main and v2026.6.11 remain incomplete: Discord has gated provider-side channel creation, but the CLI still exposes only channel info/list and Slack has no channel-create discovery or execution path. The open Discord PR addresses only part of the request, and the Slack proposal closed unmerged for fork-only use.

## What This Changes

Add provider-gated channel creation to the message tool and CLI for Slack, Discord, and other applicable messaging providers.

## Best Possible Solution

Add provider-owned, default-off channel creation after defining trusted-requester authorization and least-privilege credential scopes; then wire Slack discovery/runtime and the CLI, retain Discord's existing gate, document setup, and prove both disabled and enabled behavior.

Rationale: Channel creation is an administrative workspace or server mutation rather than ordinary message delivery, so automation cannot safely choose requester authority, executing credentials, or whether agent and operator CLI authority should differ.

Likely owner: steipete

Owner confidence: high

Options:

- **Explicit provider gates (recommended):** Require default-off provider action gates, trusted-requester checks, and least-privilege credentials before advertising or executing channel creation.
- **Operator CLI only:** Expose channel creation only through an operator-run CLI while keeping it unavailable to agent message-tool calls.
- **Keep external:** Leave channel provisioning to direct Slack and Discord administration APIs outside OpenClaw.
