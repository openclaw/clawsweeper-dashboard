Keep open. Current main still lacks the requested end-to-end channel creation surface: Discord has partial provider/runtime support and an open CLI-only PR, while Slack still lacks discovery, dispatch, setup scopes, docs, and an accepted admin authority boundary.

The issue requests native message-tool and CLI channel creation for Slack, Discord, and similar messaging providers.

## Best Possible Solution

Approve a provider-owned, default-off channel-creation design, then implement Slack discovery/runtime/setup/docs/tests and land or replace the narrower Discord CLI wiring without moving provider-specific admin policy into core.
