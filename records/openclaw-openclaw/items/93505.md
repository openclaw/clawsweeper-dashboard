## What This Changes

The PR adds a `models.providers.*.baseURL` provider-config alias that normalizes to `baseUrl`, updates sensitive URL hint/redaction metadata and docs, and adds regression coverage for config and memory embedding resolution.

## Best Possible Solution

Keep `baseUrl` as the canonical core spelling unless a maintainer explicitly sponsors the `baseURL` alias; if sponsored, land one coordinated endpoint-routing contract with redaction, docs, tests, and related PR cleanup.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 expose only canonical `baseUrl` in the core provider schema, while the embedding client consumes `providerConfig.baseUrl` for endpoint selection. I did not run the contributor's local endpoint proof in this read-only review.

## Solution Assessment

No, not as an unsponsored cleanup PR: the schema-boundary normalization is clean, but making `baseURL` a supported core config alias needs maintainer product and security-boundary acceptance. A safer accepted alternative is to keep `baseUrl` canonical and handle the reporter path through docs, doctor guidance, or a narrower runtime fix.
