## Label Justifications

- `P1`: Third-party skill installation is a live supply-chain security workflow, and the remaining hook/audit contract blocks scanner and compliance integrations even though the blocking pre-install path now exists.
- `impact:security`: The issue is about scanning, blocking, and auditing untrusted skills before or after they are accepted onto a user's machine.

## Summary

Keep open. Current main now covers the blocking pre-install side through `security.installPolicy` and plugin `before_install`, including OpenClaw-managed ClawHub install/update paths, but it still lacks a plugin-visible post-install/update completion observer with redacted audit/outcome metadata.

## What This Changes

The issue requests blocking pre-install and observational post-install lifecycle hooks for skills so policy plugins can scan, block, warn, and audit skill installs.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then design a minimal redacted non-blocking skill install/update completion observer with explicit ordering, failure semantics, docs, and coverage for OpenClaw-managed CLI, Gateway, and UI install/update paths.
