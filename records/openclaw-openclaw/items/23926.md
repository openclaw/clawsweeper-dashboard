## Label Justifications

## Summary

Keep open: current main now covers the blocking pre-install side through `security.installPolicy` and plugin `before_install`, including ClawHub install/update paths, but the requested plugin-visible post-install/update observer with audit and outcome metadata is still missing.

## What This Changes

The issue requests blocking skill pre-install and observational post-install hook events so scanner and audit plugins can inspect or record skill installs across OpenClaw-managed install paths.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then design a minimal redacted non-blocking skill install/update completion observer with explicit ordering, failure semantics, docs, and coverage for OpenClaw-managed CLI, Gateway, and UI paths.
