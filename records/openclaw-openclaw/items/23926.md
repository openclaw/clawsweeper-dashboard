## Label Justifications

- `P1`: Third-party skill installation is a live supply-chain security workflow, and the remaining hook/audit contract blocks scanner and compliance integrations even though the blocking pre-install path now exists.
- `impact:security`: The issue is about scanning, blocking, and auditing untrusted skills before or after they are accepted onto a user's machine.

## Summary

Keep open. Current main covers the blocking side through `security.installPolicy` and plugin `before_install` for OpenClaw-managed skill install/update paths, but it still lacks a plugin-visible post-install/update completion observer with redacted audit/outcome metadata.

## What This Changes

Request to add blocking pre-install and observational post-install hook events for skill install/update so security scanners and auditors can inspect or record untrusted skill installs.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then design a minimal redacted non-blocking skill install/update completion observer with explicit ordering, failure semantics, docs, and coverage for OpenClaw-managed CLI, Gateway, and UI paths.
