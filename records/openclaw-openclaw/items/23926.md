## Summary

Keep open: current main now covers the blocking pre-install side with `security.installPolicy` and plugin `before_install`, but it still lacks the requested plugin-visible skill install/update completion observer and remains a security-sensitive API decision.

## What This Changes

The issue requests blocking `skill:pre-install` and observational `skill:post-install` lifecycle hooks for skill installs so scanners and auditors can inspect or record untrusted skills around installation.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then design a minimal redacted non-blocking skill install/update completion observer for OpenClaw-managed CLI, Gateway, and UI install paths.

Options:

- **Add Minimal Observer (recommended):** Add a non-blocking completion hook with redacted source, target, provenance, outcome, and timestamp metadata plus documented fail-open logging semantics.
- **Keep Pre-Install Only:** Declare `security.installPolicy` and `before_install` sufficient for install security, then narrow or close the audit-observer part separately.
- **Defer To ClawHub Trust Design:** Hold the observer until maintainers define a broader ClawHub trust/provenance API that can supply the same audit events.

## Reproduction Assessment

Yes, at source level. Current main exposes blocking install policy through `security.installPolicy` and `before_install`, but the hook registry and ClawHub success/update paths show no post-install/update completion observer.

## Solution Assessment

Partly. Reusing `security.installPolicy` and `before_install` is the best blocking path, but the remaining audit capability should be specified as a redacted non-blocking completion observer rather than accepting the original event names and payload unchanged.
