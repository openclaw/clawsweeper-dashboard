## Summary

Keep open. Current main covers the blocking side through `security.installPolicy` and plugin `before_install` for OpenClaw-managed install/update paths, but it still has no plugin-visible post-install/update completion observer with redacted audit/outcome metadata, and the issue carries a security-sensitive maintainer-review signal.

## What This Changes

The issue requests blocking `skill:pre-install` and observational `skill:post-install` lifecycle hooks for skill installation security policy and auditing.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then design a minimal redacted non-blocking skill install/update completion observer with explicit ordering, failure semantics, docs, and coverage for OpenClaw-managed CLI, Gateway, and UI install/update paths.
