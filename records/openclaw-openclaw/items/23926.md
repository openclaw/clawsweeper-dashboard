## Summary

Keep open: current main covers the blocking pre-install side through `security.installPolicy` and plugin `before_install`, including OpenClaw-managed ClawHub installs, but it still lacks a plugin-visible post-install/update completion observer and needs a maintainer security-boundary decision.

## What This Changes

The issue requests blocking `skill:pre-install` and observational `skill:post-install` hook events so scanner/audit plugins can inspect, warn, block, or log skill installs.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then design a minimal redacted non-blocking skill install/update completion observer for OpenClaw-managed CLI, Gateway, and UI install paths.

- **Keep Pre-Install Only:** Declare `security.installPolicy` and `before_install` sufficient for install security, then narrow or close the audit-observer request separately.
- **Defer To ClawHub Trust Design:** Hold the observer until maintainers define a broader ClawHub trust/provenance API that can supply the same audit events.

Yes, at source level. Current main exposes blocking install policy through `security.installPolicy` and `before_install`, but the hook registry and ClawHub success path show no post-install/update completion observer.

## Solution Assessment

Unclear until maintainer decision. Reusing `security.installPolicy` and `before_install` is the right blocking path, but the remaining audit capability should be specified as a redacted non-blocking completion hook rather than accepting the original event names and payload unchanged.
