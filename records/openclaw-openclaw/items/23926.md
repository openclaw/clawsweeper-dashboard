## Summary

Keep open: current main and shipped releases cover the blocking pre-install side through operator install policy and plugin `before_install`, but the requested plugin-visible post-install/update observer with completion/audit metadata is still absent and needs a maintainer security/product decision.

## What This Changes

Request blocking pre-install and observational post-install hook events for skill installation so security tools can scan, block, warn, and audit skill installs.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking gates, and design a narrow non-blocking post-install/update observer with redacted provenance, outcome, timestamp, and fail-open logging semantics.
