## Label Justifications

- `P1`: Third-party skill installation is a live supply-chain security workflow and the missing observer blocks scanner/audit integrations despite the existing blocking pre-install path.
- `impact:security`: The issue is about scanning, blocking, and auditing untrusted skill installs before or after they are accepted onto a user's machine.

## Summary

Keep open: current main covers the blocking pre-install side through `security.installPolicy` and plugin `before_install`, including ClawHub skill installs, but there is still no plugin-visible post-install/update observer with audit or outcome metadata.

## What This Changes

The issue requests blocking pre-install and observational post-install hook events for skill installation so scanners and audit tools can inspect or record ClawHub/UI skill installs.

## Best Possible Solution

Keep the blocking path on `security.installPolicy` and `before_install`, then define a minimal redacted non-blocking skill install/update completion observer with explicit failure semantics and test coverage.
