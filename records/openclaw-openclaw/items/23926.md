## Label Justifications

- `P1`: Third-party skill installation is a live supply-chain security workflow, and the missing completion observer blocks scanner/audit integrations even though the blocking pre-install path now exists.

## Summary

Keep open: current main covers the blocking install-policy side through `security.installPolicy` and plugin `before_install`, but it still lacks a plugin-visible post-install/update completion observer with redacted audit/outcome metadata.

## What This Changes

Request to add blocking pre-install and observational post-install skill lifecycle hook events for security scanning and audit integrations.

## Best Possible Solution

Keep the existing blocking `security.installPolicy` and `before_install` seams, then design a minimal redacted non-blocking skill install/update completion observer with explicit ordering, failure semantics, docs, and coverage for OpenClaw-managed ClawHub, upload, git/local, Gateway, UI, and update paths.

- **Defer to ClawHub trust design:** Hold the observer until maintainers define a broader ClawHub trust/provenance API that can supply the same audit events.

## Solution Assessment
