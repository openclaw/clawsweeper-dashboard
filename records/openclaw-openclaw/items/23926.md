## Label Justifications

- `P1`: Third-party skill installation is a live supply-chain security workflow, and the missing completion observer blocks standard scanner and enterprise audit integrations.
- `impact:security`: The issue is about scanning, blocking, and auditing untrusted skills before or after they are accepted onto a user's machine.

## Summary

Keep open: current main and v2026.6.11 cover the blocking pre-install side through `security.installPolicy` and `before_install`, but there is still no plugin-visible post-install or audit observer for completed skill installs, so the central requested lifecycle contract remains unresolved.

## What This Changes

Requested skill installation lifecycle hook events so security or audit integrations can block staged skill installs and observe completed installs.

## Best Possible Solution

Keep the existing blocking `security.installPolicy` and `before_install` seams, then add a documented non-blocking skill install/update completion hook with minimal redacted metadata and explicit ordering and failure semantics.

## Reproduction Assessment

Yes, at source level. Current main exposes `before_install` only, while ClawHub and local/Git install success paths write install metadata and return without dispatching a post-install observer.

## Solution Assessment

Partly. Reusing `security.installPolicy` and `before_install` is the right blocking solution, but the remaining audit capability should be specified as a non-blocking completion hook rather than accepting the original event names and payload unchanged.
