## Label Justifications

- `P1`: The issue tracks a security-sensitive lifecycle gap for third-party skill installs, where users and security tools still lack a completion/audit integration point.
- `impact:security`: The requested hooks are explicitly about scanning, blocking, and auditing potentially dangerous third-party skills before or after installation.

## Summary

Keep open. Current main and the latest release cover the blocking pre-install side through `security.installPolicy` and plugin `before_install`, but they still do not expose a plugin-visible post-install/update observer carrying outcome/audit metadata, so the central lifecycle request remains unresolved.

## What This Changes

Request to add blocking pre-install and observational post-install skill lifecycle hook events for security scanning, warnings, blocking, and audit integrations.

## Best Possible Solution

Keep the existing blocking pre-install policy path, then add or explicitly reject a documented plugin-visible post-install/update observer with redacted `targetDir`, source, installedAt, outcome, and audit metadata for OpenClaw-managed skill installs.
