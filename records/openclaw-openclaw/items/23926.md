## Label Justifications

- `P1`: Third-party skill installation is a live supply-chain security workflow, and the missing completion/audit lifecycle hook blocks standard scanner and enterprise audit integrations.
- `impact:security`: The issue is about scanning, blocking, warning on, and auditing untrusted skills before or after they are accepted onto a user's machine.

## Summary

Keep open: current main and v2026.6.11 cover much of the blocking pre-install side through `security.installPolicy` and `before_install`, including ClawHub update hardening, but there is still no plugin-visible post-install/update completion observer with audit/outcome metadata, and the remaining hook contract is security-sensitive product surface.

## What This Changes

Request to add blocking pre-install and observational post-install skill lifecycle hook events so plugins can scan, warn, block, and audit skill installs and updates.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking policy seams, then add a documented non-blocking skill install/update completion observer with minimal redacted metadata and explicit ordering, failure, and audit semantics.

## Reproduction Assessment

Yes, at source level. Current main exposes `security.installPolicy` plus `before_install`, and the ClawHub success path shows no post-install/update completion observer or audit hook.

## Solution Assessment

Partly. Reusing `security.installPolicy` and `before_install` is the best blocking solution, but the remaining audit capability should be specified as a non-blocking completion hook rather than accepting the original event names and payload unchanged.
