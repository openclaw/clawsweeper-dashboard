## Label Justifications

- `P1`: Third-party skill installation is a live supply-chain security workflow, and the missing completion/audit hook blocks scanner and compliance integrations even though the blocking pre-install path now exists.
- `impact:security`: The issue is about scanning, blocking, and auditing untrusted skills before or after they are accepted onto a user's machine.

## Summary

Keep open: current main covers the blocking install-policy side through `security.installPolicy` and plugin `before_install`, but it still lacks the requested plugin-visible post-install/update observer with audit/outcome metadata. The remaining API shape is security-sensitive product direction, not conservative cleanup.

## What This Changes

Request to add blocking `skill:pre-install` and observational `skill:post-install` hook events for skill installation, ClawHub sync/update, and UI install paths.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then design a minimal redacted non-blocking skill install/update completion observer for OpenClaw-managed CLI, Gateway, and UI install paths if maintainers want plugin-visible audit events.

- **Keep Pre-Install Only:** Declare `security.installPolicy` and `before_install` sufficient for install security, then narrow or close the audit-observer request separately.
- **Defer To ClawHub Trust Design:** Hold the observer until maintainers define a broader ClawHub trust/provenance API that can supply the same audit events.

## Solution Assessment
