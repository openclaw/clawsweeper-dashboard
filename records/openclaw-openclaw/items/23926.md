## Label Justifications

- `P1`: Third-party skill installation is a live supply-chain security workflow, and the missing completion observer blocks scanner and audit integrations even though the blocking pre-install path now exists.
- `impact:security`: The issue is about scanning, blocking, and auditing untrusted skills before or after they are accepted onto a user's machine.

## Summary

Keep open. Current main and the latest release cover the blocking side through `security.installPolicy` and plugin `before_install`, but there is still no plugin-visible post-install/update completion observer for skill audit metadata, so the central lifecycle request remains unresolved.

## What This Changes

Request to add blocking pre-install and observational post-install skill lifecycle hooks so plugins and security tools can scan, block, warn, and audit skill installs and updates.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then design a minimal redacted non-blocking skill install/update completion observer with explicit ordering, failure semantics, docs, and coverage for OpenClaw-managed CLI, Gateway, UI, install, and update paths.

- **Defer To ClawHub Trust Design:** Hold the observer until maintainers define a broader ClawHub trust/provenance API that can supply the same audit events.
