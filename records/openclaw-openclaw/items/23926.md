## Label Justifications

- `P1`: Third-party skill installation is a live supply-chain security workflow, and the missing completion/audit hook blocks scanner and compliance integrations even though the blocking pre-install path now exists.
- `impact:security`: The issue is about scanning, blocking, and auditing untrusted skills before or after they are accepted onto a user's machine.

## Summary

Keep open: current main covers the blocking side through `security.installPolicy` and `before_install`, but it still lacks the requested plugin-visible post-install/update observer with audit/outcome metadata. The remaining API shape is security-sensitive product direction, not conservative cleanup.

## What This Changes

The issue requests blocking `skill:pre-install` and observational `skill:post-install` hook events for skill installation and update security/audit integrations.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then design a minimal redacted non-blocking skill install/update completion observer for OpenClaw-managed CLI, Gateway, and UI install paths if maintainers want plugin-visible audit events.
