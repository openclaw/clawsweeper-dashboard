## Label Justifications

- `P1`: Third-party skill installation is a live supply-chain security workflow, and the missing completion observer blocks scanner and audit integrations even though the blocking pre-install path now exists.
- `impact:security`: The issue is about scanning, blocking, and auditing untrusted skills before or after they are accepted onto a user's machine.

## Summary

Keep open: current main now covers the blocking side through `security.installPolicy` and plugin `before_install`, including ClawHub install/update paths, but there is still no plugin-visible post-install/update observer with audit/outcome metadata and the remaining API is security-sensitive.

## What This Changes

The issue requests blocking `skill:pre-install` and observational `skill:post-install` lifecycle hooks so scanners and audit plugins can inspect or record skill installs.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then design a minimal redacted non-blocking skill install/update completion observer with explicit ordering, failure semantics, docs, and coverage for OpenClaw-managed install, update, Gateway, UI, and CLI paths.
