## Summary

Keep open: current main covers blocking install decisions through `security.installPolicy` and plugin `before_install`, but it still lacks a plugin-visible skill install/update completion observer and the remaining public security contract needs maintainer direction.

## What This Changes

Request to add blocking skill pre-install scanning and observational skill post-install audit hook events across ClawHub, UI, and skill install flows.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then design a minimal redacted non-blocking skill install/update completion observer with explicit ordering, failure semantics, docs, and coverage for OpenClaw-managed install, update, Gateway, UI, and CLI paths.

Options:

- **Add Minimal Observer (recommended):** Add a non-blocking completion hook with redacted source/provenance/outcome metadata and documented fail-open logging semantics.
- **Keep Pre-Install Only:** Declare `security.installPolicy` and `before_install` sufficient for install security, then narrow or close the audit-observer request separately.
- **Defer To ClawHub Trust Design:** Hold the observer until maintainers define a broader ClawHub trust/provenance API that can supply the same audit events.

Yes, at source level. Current main exposes `security.installPolicy` and `before_install` for blocking install decisions, but the hook registry and skill lifecycle code show no post-install/update completion observer.

## Solution Assessment

Partly. Reusing `security.installPolicy` and `before_install` is the right blocking path, but the remaining audit capability should be specified as a redacted non-blocking completion hook rather than accepting the original event names and payload unchanged.
