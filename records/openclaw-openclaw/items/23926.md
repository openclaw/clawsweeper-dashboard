## Summary

Keep open: current main now covers the blocking pre-install side through `security.installPolicy` and plugin `before_install`, but it still lacks the requested plugin-visible post-install/update observer and audit lifecycle contract.

## What This Changes

Request adding blocking pre-install and observational post-install skill lifecycle hook events for ClawHub, UI, sync/update, and plugin-shipped skill installs.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then decide a minimal redacted, non-blocking skill install/update completion observer for OpenClaw-managed install paths or explicitly reject that observer as out of scope.

Rationale: Automation can prove the missing lifecycle surface, but deciding what install metadata plugins may see and whether observer failures affect an already-written install is a security and product boundary choice.

Options:

- **Add Minimal Observer (recommended):** Add a non-blocking completion hook with redacted source, target, provenance, outcome, and timestamp metadata plus documented fail-open logging semantics.
- **Keep Pre-Install Only:** Declare `security.installPolicy` and `before_install` sufficient for install security, then narrow or reject the audit-observer portion explicitly.
- **Defer To ClawHub Trust Design:** Hold the observer until maintainers define a broader ClawHub trust/provenance API that supplies the same audit events.

## Solution Assessment

Partly. Reusing `security.installPolicy` and `before_install` is the right blocking path, but the remaining audit capability should be specified as a redacted non-blocking completion hook rather than accepting the original event names and payload unchanged.
