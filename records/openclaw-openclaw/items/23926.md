## Summary

Current main covers the blocking install-policy side through `security.installPolicy` and `before_install`, but it still lacks a plugin-visible post-install/update observer for skill lifecycle auditing. The issue should stay open as the canonical product/security decision for the remaining lifecycle API.

## What This Changes

The issue requests pre-install and post-install hook events around skill installation so security plugins can scan, block, and audit skill installs.

## Best Possible Solution

Keep the implemented pre-install policy path and add, if approved, a narrow non-blocking post-install/update observer with redacted outcome metadata and explicit fail-open logging semantics.
