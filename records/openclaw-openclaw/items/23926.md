## Summary

Keep open: current main and v2026.6.11 cover the blocking pre-install side through `security.installPolicy` and `before_install`, but they still lack the requested plugin-visible post-install/update audit observer and the remaining lifecycle contract needs maintainer security/product review.

## What This Changes

The issue requests `skill:pre-install` and `skill:post-install` hook events so plugins can block, warn, scan, or audit skill installation and updates.

## Best Possible Solution

Keep the existing blocking policy seams, then add a documented non-blocking skill install/update completion hook with minimal redacted metadata, explicit ordering and failure semantics, and focused coverage for ClawHub, gateway, UI, and update paths.

## Reproduction Assessment

Yes, at source level. Current main exposes `security.installPolicy` plus `before_install`, but the hook registry and ClawHub success path show no post-install/update completion observer.

## Solution Assessment

Partly. Reusing `security.installPolicy` and `before_install` is the narrowest blocking solution, but the remaining audit capability should be specified as a non-blocking completion hook rather than accepting the original event names and payload unchanged.
