## Label Justifications

- `P1`: Third-party skill installation is a live supply-chain security workflow, and the missing completion observer blocks scanner and audit integrations even though the blocking pre-install path now exists.
- `impact:security`: The issue is about scanning, blocking, and auditing untrusted skills before or after they are accepted onto a user's machine.

## Summary

Keep open: current main covers the blocking pre-install side through `security.installPolicy` and plugin `before_install`, but it still lacks the requested plugin-visible post-install/update completion observer. The remaining API shape, redaction, and failure semantics are security-sensitive product decisions.

## What This Changes

Add skill install lifecycle hooks so security plugins can block before install and observe or audit after install.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then design a minimal redacted non-blocking skill install/update completion observer for OpenClaw-managed CLI, Gateway, and UI install paths.
