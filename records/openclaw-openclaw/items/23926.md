## Summary

Keep open: current main now covers the blocking pre-install side through `security.installPolicy` and plugin `before_install` across OpenClaw-managed skill install/update paths, but the requested plugin-visible post-install/update observer with safe audit/outcome metadata is still missing and needs maintainer security/product direction.

## What This Changes

The issue requests `skill:pre-install` and `skill:post-install` lifecycle hook events so security and audit plugins can block or observe skill installation.

## Best Possible Solution

Keep the existing blocking `security.installPolicy` and `before_install` seams, then design a minimal redacted non-blocking skill install/update completion observer for OpenClaw-managed flows if maintainers approve the payload and failure semantics.

- **Defer to ClawHub trust design:** Hold the observer until maintainers define a broader ClawHub trust/provenance API that can supply the same audit events.
