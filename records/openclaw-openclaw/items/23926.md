## Label Justifications

- `P1`: Third-party skill installation is a live supply-chain security workflow, and the missing completion observer blocks scanner and audit integrations even though the blocking pre-install path exists.
- `impact:security`: The issue is about scanning, blocking, and auditing untrusted skills before or after they are accepted onto a user's machine.

## Summary

Keep open: current main covers blocking install decisions through `security.installPolicy` and plugin `before_install`, including OpenClaw-managed ClawHub skill installs, but it still lacks the requested plugin-visible post-install/update observer and needs maintainer security/product direction.

## What This Changes

The issue requests blocking pre-install and observational post-install skill hook events so plugins can scan, block, warn, or audit skill installs.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then add a minimal redacted, non-blocking skill install/update completion observer with explicit ordering, failure semantics, docs, and coverage for CLI, Gateway, UI, and ClawHub install/update paths.
