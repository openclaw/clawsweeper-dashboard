## Summary

Keep open: current main covers pre-copy blocking for OpenClaw-managed skill installs through `security.installPolicy` plus plugin `before_install`, but it still lacks the requested post-install/update observer and that remaining public security lifecycle API needs maintainer direction.

## What This Changes

Request to add blocking pre-install skill scanning hooks and post-install audit hooks across ClawHub, sync, UI, and plugin-shipped skill install flows.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then decide a minimal redacted, non-blocking skill install/update completion observer for OpenClaw-managed CLI, Gateway, and UI flows, or explicitly reject that observer as out of scope.

Rationale: Automation can prove the missing lifecycle surface, but deciding what install metadata plugins may see and whether observer failures affect an already-written install is a security and product boundary choice.

Options:

- **Add Minimal Completion Observer (recommended):** Add a non-blocking completion hook with redacted source, target, provenance, outcome, and timestamp metadata plus documented fail-open logging semantics.
- **Keep Pre-Install Only:** Declare `security.installPolicy` and `before_install` sufficient for install security and explicitly reject the audit-observer portion.
- **Defer To ClawHub Trust Design:** Hold the observer until maintainers define a broader ClawHub trust/provenance API that can supply the same audit events.

## Solution Assessment
