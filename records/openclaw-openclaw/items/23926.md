## Label Justifications

- `P1`: Third-party skill installation is a live supply-chain security workflow, and scanner/audit integrations still lack the requested completion hook contract.
- `impact:security`: The issue is about scanning, blocking, and auditing untrusted skills before or after they are accepted onto a user's machine.

## Summary

Current main has closed the blocking pre-install part of the request through operator install policy and the `before_install` plugin hook, but the requested post-install/update observer remains absent, so the item is still necessary as a maintainer-owned lifecycle API and security-design decision.

## What This Changes

The issue requests plugin-visible `skill:pre-install` and `skill:post-install` lifecycle events so security integrations can block, scan, audit, and observe skill installs across ClawHub, UI, and sync flows.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then decide a minimal redacted, non-blocking skill install/update completion observer for OpenClaw-managed install paths or explicitly reject that observer as out of scope.
