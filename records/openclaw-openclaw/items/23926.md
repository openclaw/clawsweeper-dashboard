## Label Justifications

- `impact:security`: The issue is about scanning, blocking, and auditing untrusted skills before or after they are accepted onto a user's machine.

## Summary

Keep open: current main covers the blocking pre-install side through `security.installPolicy` and plugin `before_install`, but it still lacks the requested plugin-visible post-install/update observer, and that remaining lifecycle API is security-sensitive.

## What This Changes

The issue requests blocking skill pre-install and observational post-install hook events so scanners and audit plugins can enforce or record skill install policy.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then design a minimal redacted non-blocking skill install/update completion observer for OpenClaw-managed CLI, Gateway, and UI install paths.
