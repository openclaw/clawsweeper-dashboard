## Label Justifications

- `P1`: Third-party skill installation is a live supply-chain security workflow, and the missing completion observer blocks scanner/audit integrations even though the blocking pre-install path now exists.
- `impact:security`: The issue is about scanning, blocking, and auditing untrusted skills before or after they are accepted onto a user's machine.

## Summary

Keep open: current main covers much of the blocking pre-install side through `security.installPolicy` and plugin `before_install`, including ClawHub install/update, but the requested plugin-visible post-install/update observer is still missing and needs maintainer security/product direction.

## What This Changes

The issue requests blocking pre-install and observational post-install hook events for skill installation so scanner and audit plugins can warn, block, or log third-party skill installs.

## Best Possible Solution

Keep `security.installPolicy` and `before_install` as the blocking path, then design a minimal redacted non-blocking skill install/update completion observer with explicit ordering, failure semantics, docs, and coverage for OpenClaw-managed CLI, Gateway, and UI paths.
