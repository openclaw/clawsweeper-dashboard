## Summary

Close: current main and the latest stable release route isolated cron announce delivery through the durable outbound send path, so channels like openclaw-weixin that expose outbound sendText/sendMedia no longer need a message.action send handler for the central reported flow.

## What This Changes

The issue reports isolated cron announce delivery to openclaw-weixin failing because delivery used message.action=send instead of the channel outbound send contract.

## Best Possible Solution

Keep the durable outbound cron delivery path in v2026.6.11/current main and have affected v2026.6.10 users update to the latest stable release.

Yes. The shipped fix is at the right owner boundary: cron announce delivery uses the shared durable outbound send contract instead of adding a Weixin-specific action shim.
