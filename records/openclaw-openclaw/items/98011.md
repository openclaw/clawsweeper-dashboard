## Summary

Close: current main and v2026.6.11 route isolated cron announce delivery through the durable outbound send path, so the reported v2026.6.10 `message.action` unsupported-action failure no longer matches the shipped cron delivery path.

## What This Changes

The issue reports isolated cron `delivery.mode="announce"` to `openclaw-weixin` failing because output was sent through `message.action` instead of the channel outbound send contract.

## Best Possible Solution

Keep the shared cron durable-outbound delivery path in v2026.6.11/current main; any future Weixin cron delivery failure should be filed with fresh logs against the current release.

## Solution Assessment

Yes. The shared cron/outbound delivery path is the right owner-boundary fix because it uses the channel `sendText` contract instead of adding a Weixin-specific action shim.
