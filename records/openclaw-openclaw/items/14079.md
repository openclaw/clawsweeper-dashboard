## Summary

Keep open. Current main and v2026.6.11 still do not deliver Linux desktop notifications through the reserved `system.notify` node command: the headless node host does not advertise or handle it, the CLI/docs still describe notify as mac-only/mac-node behavior, and an external plugin cannot claim the exact reserved command.

## What This Changes

Request Linux desktop notification delivery for OpenClaw node notifications, likely via notify-send/libnotify or D-Bus fallback with graceful headless degradation.

## Best Possible Solution

Make an explicit maintainer decision on the Linux notifier backend contract, then implement a focused core node-host `system.notify` path with safe invocation, clear unavailable results, CLI/docs updates, and targeted regression coverage.

## Reproduction Assessment

Yes. Source inspection shows Linux can pass the Gateway allowlist, but the headless node host does not advertise or handle `system.notify`; I did not run a live Linux desktop notification scenario.

## Solution Assessment

Unclear until maintainers choose backend scope. The owner boundary should be core node-host code because `system.notify` is a reserved core command and plugins cannot register the exact missing surface.
