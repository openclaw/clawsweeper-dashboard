## Summary

Keep open. Current main and v2026.6.11 still do not deliver Linux desktop notifications for the existing `system.notify` node command: Linux policy can allow it, but the headless node host neither advertises nor dispatches the command. The broader Linux app tracker and open GTK companion PR do not replace this focused gap, and the closed error-message issue only covered the failure wording.

## What This Changes

Request Linux desktop notification support for the existing node notification surface, likely through a Linux desktop notification backend such as notify-send.

## Best Possible Solution

Choose the Linux notification backend contract, then implement a focused core node-host `system.notify` path with safe invocation, structured unavailable results, docs/CLI updates, targeted regression coverage, and real Linux desktop-session proof.

## Reproduction Assessment

Yes. Source inspection on current main shows Linux policy can allow `system.notify`, but the headless node host neither declares nor dispatches it; I did not run a live Linux desktop notification scenario.

## Solution Assessment

Unclear until maintainers choose the backend scope. The implementation boundary should stay in core node-host code because `system.notify` is a reserved core command and plugins cannot register the exact missing surface.
