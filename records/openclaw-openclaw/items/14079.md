- `impact:ux-friction`: The missing Linux desktop notification path forces users to rely on manual checking or channel messages instead of the expected local notification workflow.

## Summary

Keep open. Current main and v2026.6.11 still do not implement Linux desktop notification delivery for the reserved `system.notify` node command: Linux policy can allow it, but the headless node host does not advertise or handle it, and maintainer direction is still needed on the Linux backend scope.

## What This Changes

Add Linux desktop notification support for OpenClaw node notifications, with graceful behavior on headless Linux hosts.

## Best Possible Solution

Implement a focused core-owned Linux headless node-host `system.notify` path only after maintainers choose the backend scope, with desktop-session detection, clear unavailable errors, no shell interpolation, targeted tests, and docs updates while keeping the broader Linux app work separate.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: run `openclaw nodes notify` against a Linux headless node host and the node will not have declared `system.notify`; if invoked anyway, the node-host dispatcher returns `UNAVAILABLE`.

## Solution Assessment

Unclear until maintainers choose the Linux backend scope. A narrow core node-host implementation appears to be the right boundary because `system.notify` is reserved and cannot be filled by an external plugin, while the broad Linux companion app path is too large for this specific gap.
