## Summary

Keep open. Current main and the latest release still do not deliver Linux desktop notifications through the reserved `system.notify` node command: Linux is allowlisted, but the headless node host does not advertise or handle the command, and maintainer direction is still needed for the Linux backend contract.

## What This Changes

Add Linux desktop notification support for `openclaw nodes notify` / `system.notify`, with graceful behavior on headless Linux hosts.

## Best Possible Solution

Decide the Linux backend contract, then implement `system.notify` in core node-host code with safe process invocation, desktop-session detection, structured unavailable results, CLI/docs updates, and focused tests.

## Reproduction Assessment

Yes. Source inspection shows Linux can pass the Gateway allowlist, but the headless node host neither advertises nor handles `system.notify`; I did not run a live Linux desktop notification scenario.

## Solution Assessment

Unclear until maintainers choose backend scope. The owner boundary should be core node-host code because `system.notify` is a reserved command and plugins cannot register the exact missing surface.
