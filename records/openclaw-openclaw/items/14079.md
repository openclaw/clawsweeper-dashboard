## Summary

Keep open. Current main and v2026.6.11 still lack Linux desktop delivery for the reserved `system.notify` node command: the headless node host neither advertises nor handles it, and the backend/dependency contract still needs maintainer direction.

## What This Changes

The issue requests Linux desktop notification support for OpenClaw node notifications, likely via `notify-send`/libnotify or D-Bus with graceful headless degradation.

## Best Possible Solution

Make an explicit maintainer decision on the Linux notification backend contract, then implement a focused core node-host `system.notify` path with safe invocation, unavailable results, CLI/docs updates, and targeted regression tests.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: a Linux headless node host does not declare `system.notify`, so Gateway rejects it before delivery; if invoked directly, the node-host dispatcher returns `UNAVAILABLE`.

## Solution Assessment

Unclear. The core node-host path is the right owner for the reserved `system.notify` command, but the backend and dependency scope need maintainer choice before this should be queued as an automated fix.
