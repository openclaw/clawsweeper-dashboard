## Summary

Keep open. Current main and v2026.6.11 still lack Linux desktop delivery for the reserved `system.notify` node command: the gateway can allow it, but the headless node host neither advertises nor handles it, and backend scope still needs maintainer direction.

## What This Changes

Add Linux desktop notification delivery for the existing `system.notify` / `openclaw nodes notify` surface, likely through a Linux notification backend such as `notify-send`.

## Best Possible Solution

Make an explicit maintainer decision on the Linux notification backend, then implement a focused core node-host `system.notify` path with safe invocation, structured unavailable results, docs/CLI updates, and targeted regression tests.

## Reproduction Assessment

Yes, source-level. Current main shows Linux can be allowlisted at the gateway, but the headless node host does not advertise or dispatch `system.notify`, so a Linux node cannot deliver the requested notification path.

## Solution Assessment

Unclear until maintainers choose backend scope. The owner boundary should be core node-host code because `system.notify` is reserved and plugins cannot register the exact missing command surface.
