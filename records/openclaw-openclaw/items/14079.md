## Summary

Keep open. Current main and v2026.6.11 still do not deliver Linux desktop notifications for the core `system.notify` node command: Linux policy can allow it, but the headless node host neither advertises nor dispatches the command, and backend scope still needs maintainer direction.

## What This Changes

Add Linux desktop notification delivery for the core `system.notify` / `openclaw nodes notify` node surface.

## Best Possible Solution

Choose the Linux notification backend contract, then implement a focused core node-host `system.notify` path with safe invocation, structured unavailable results, docs/CLI updates, targeted regression coverage, and real Linux desktop-session proof.

Owner confidence: high

Options:

- **Bounded notify-send backend (recommended):** Implement `notify-send` as the first argv-only backend with display-session detection, clear unavailable results, dependency docs, tests, and Linux desktop proof.
- **Broader D-Bus/dunstify fallback:** Support direct D-Bus or `dunstify` fallback now, accepting more code and security review for broader desktop coverage.
- **Defer to Linux companion app:** Keep headless node-host notifications unsupported and let the broader Linux companion app direction own desktop notification UX later.

## Reproduction Assessment

Yes, as a source-level reproduction. Current main allows `system.notify` in Linux node policy, but the headless node host does not declare or dispatch it; I did not run a live Linux desktop notification scenario.

## Solution Assessment

Unclear until maintainers choose the backend scope. The implementation boundary should stay in core node-host code because `system.notify` is a reserved core command and plugins cannot register the exact missing surface.
