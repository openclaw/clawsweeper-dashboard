## Summary

Keep open. Current main and the latest release still do not deliver Linux desktop notifications for the existing node notification command: Linux policy can allow `system.notify`, but the headless node host neither advertises nor dispatches it, and the remaining backend/dependency scope needs maintainer direction.

## What This Changes

Add Linux desktop notification delivery for OpenClaw's existing node notification command, with graceful headless-session degradation.

## Best Possible Solution

Choose the Linux notification backend contract, then implement a focused core node-host `system.notify` path with safe invocation, structured unavailable results, docs/CLI updates, regression coverage, and real Linux desktop-session proof.

- **Broader desktop backend matrix:** Design a larger backend layer that includes D-Bus and/or `dunstify`, accepting extra implementation and support scope before work starts.
- **Defer to Linux companion app:** Keep headless node-host notifications unsupported and let the broader Linux companion app direction own desktop notification delivery later.

Yes, as a source-level reproduction. Current main allows `system.notify` in Linux policy but the headless node host does not declare or dispatch it; I did not run a live Linux desktop notification scenario.

## Solution Assessment

Unclear until maintainers choose the backend scope. If Linux support is accepted, the implementation belongs in core node-host code because `system.notify` is a reserved core command and plugins cannot register the exact missing surface.
