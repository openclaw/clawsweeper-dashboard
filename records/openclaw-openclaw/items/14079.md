## Summary

Keep open. Current main and the latest release still do not deliver Linux desktop notifications for `system.notify`: Linux policy can allow the command, but the headless node host neither advertises nor handles it, and the Linux backend/dependency contract still needs maintainer direction.

## What This Changes

Request Linux desktop notification delivery for the existing `system.notify` node command, likely through a Linux desktop notification backend.

## Best Possible Solution

Choose the Linux notification backend/dependency policy, then add a focused core node-host `system.notify` implementation with CLI/docs/tests while leaving existing macOS, iOS, and Android behavior unchanged.

## Reproduction Assessment

Yes, at source level: current main shows the Linux node host omits and does not handle `system.notify`, while the Gateway still requires a live node declaration before invoking it. I did not run a live Linux desktop notification flow.

## Solution Assessment

Unclear until maintainers choose the backend policy. A core node-host change is the right boundary for the reserved command, but the proposed multi-backend fallback stack should be narrowed or explicitly approved before implementation.
