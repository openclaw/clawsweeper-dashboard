## Summary

Keep open. Current main and v2026.6.11 still do not deliver Linux desktop notifications for the reserved `system.notify` node command: the Linux policy can allow it, but the headless node host neither advertises nor handles it, and backend scope needs maintainer direction.

## What This Changes

Request Linux desktop notification support for OpenClaw nodes via notify-send/libnotify or D-Bus with graceful headless degradation.

## Best Possible Solution

Choose the Linux notification backend contract, then implement a focused core node-host `system.notify` path with safe invocation, structured unavailable results, docs/CLI updates, and targeted regression plus real Linux desktop-session proof.

## Reproduction Assessment

Yes, as a source-level reproduction. Current main allows `system.notify` for Linux in policy, but the headless node host does not declare or dispatch it; I did not run a live Linux desktop notification scenario.

## Solution Assessment

Unclear until maintainers choose backend scope. The owner boundary should be core node-host code because `system.notify` is a reserved core command and plugins cannot register the exact missing surface.
