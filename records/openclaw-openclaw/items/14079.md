## Summary

Current main and v2026.6.11 still do not deliver Linux desktop notifications through the reserved `system.notify` node command. The gateway allowlist includes the command for Linux, but the headless node host does not advertise or dispatch it, and the current docs/CLI still describe notification delivery as macOS/node-app-only; related Linux app work is adjacent, open, and not a merged canonical fix.

## What This Changes

The issue requests Linux desktop notification support for OpenClaw, likely through `notify-send` or another Linux notification backend behind the existing node notification surface.

## Best Possible Solution

Add a focused core headless node-host Linux `system.notify` implementation with desktop-session detection, argv-only backend invocation, clear unavailable behavior, CLI/docs updates, and tests that preserve existing macOS, iOS, Android, and headless `system.run` behavior.

## Reproduction Assessment

Yes, from source inspection: current main allows `system.notify` for Linux in the gateway policy, but the headless node host neither advertises nor dispatches that command. I did not run a live Linux desktop node, so this is source-reproducible rather than runtime-reproduced.

## Solution Assessment

Unclear until maintainers choose the Linux backend and fallback policy. The right ownership boundary is core node-host support for the reserved `system.notify` command, but the exact backend scope should be decided before implementation.
