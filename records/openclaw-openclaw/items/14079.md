## Summary

Keep open. Current main and the latest release still lack Linux desktop delivery for the reserved `system.notify` node command: Gateway policy can allow it, but the headless node host neither advertises nor handles it, and maintainer direction is still needed for the Linux backend contract.

## What This Changes

Issue requests Linux desktop notification delivery for OpenClaw node notifications, primarily through `notify-send` or another Linux desktop notification backend.

## Best Possible Solution

Make an explicit maintainer decision on the Linux notification backend contract, then implement a focused core node-host `system.notify` path with safe invocation, structured unavailable results, CLI/docs updates, and targeted regression tests.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: a Linux headless node host does not declare `system.notify`, so Gateway rejects it before delivery; if invoked directly, the node-host dispatcher would return `UNAVAILABLE`.

## Solution Assessment

Unclear. The reserved `system.notify` surface belongs in the core node-host path, but the backend and dependency scope need maintainer choice before this should be queued as an automated fix.
