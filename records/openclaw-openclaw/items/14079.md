## Summary

Keep open. Current main and v2026.6.11 still do not deliver Linux desktop notifications through the reserved `system.notify` node command: Linux policy can allow it, but the headless node host neither declares nor handles it, and the current CLI/docs still describe notification delivery as macOS or native-node behavior. The related error-report thread is adjacent, while https://github.com/openclaw/openclaw/issues/75 and https://github.com/openclaw/openclaw/pull/59859 are broader Linux-app work rather than a safe canonical fix for this narrower surface.

## What This Changes

The issue requests Linux desktop notification support for OpenClaw node notifications, such as `notify-send` or D-Bus delivery when a Linux desktop session is available.

## Best Possible Solution

Add a focused core Linux headless node-host `system.notify` implementation after maintainers choose the supported backend scope, with desktop-session detection, no-shell spawning, clear unavailable results, CLI/docs updates, and targeted tests while leaving macOS, Android, and iOS notification behavior unchanged.

## Reproduction Assessment

Yes, by source inspection: current main's Linux headless node host does not declare `system.notify`, and its dispatcher would return `UNAVAILABLE` if that command reached it. I did not run a live Linux desktop notification attempt in this read-only review.

## Solution Assessment

Unclear until maintainers choose backend scope: the core node-host boundary is likely right because `system.notify` is reserved, but `notify-send` only versus D-Bus or `dunstify` fallback support is still a product and dependency decision.
