## Summary

Keep open. Current main and v2026.6.11 still do not deliver Linux desktop notifications for the existing `system.notify` node command: Linux policy can allow it, but the headless node host neither advertises nor dispatches the command, and backend scope still needs maintainer direction.

## What This Changes

Request Linux desktop notification delivery for `system.notify`, likely through `notify-send` or a Linux notification backend with graceful headless fallback.

## Best Possible Solution

Choose the Linux notification backend contract, then implement a focused core node-host `system.notify` path with safe invocation, structured unavailable results, docs/CLI updates, targeted regression coverage, and real Linux desktop-session proof.

## Reproduction Assessment

Yes, as a source-level reproduction. Current main allows `system.notify` in Linux policy but the headless node host does not declare or dispatch it; I did not run a live Linux desktop notification scenario.

## Solution Assessment

Unclear until maintainers choose the backend scope. The implementation boundary should stay in core node-host code because `system.notify` is a reserved core command and plugins cannot register the exact missing surface.
