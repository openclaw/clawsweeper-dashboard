## Summary

Keep open. Current main and v2026.6.11 still do not deliver Linux desktop notifications for the reserved `system.notify` node command; the source gap is clear, but backend/dependency/headless behavior needs maintainer direction before another automated fix PR is queued.

## What This Changes

Add Linux desktop notification delivery for OpenClaw node notifications, likely through `notify-send` or a freedesktop notification backend, while degrading safely on headless Linux hosts.

## Best Possible Solution

Choose the Linux notification backend contract, then implement a focused core node-host `system.notify` path with safe invocation, structured unavailable results, CLI/docs updates, targeted tests, and real Linux desktop-session proof.

## Reproduction Assessment

Yes, as a source-level reproduction. Current main allows `system.notify` for Linux in policy, but the headless node host neither declares nor dispatches it; I did not run a live Linux desktop notification scenario.

## Solution Assessment

Unclear until maintainers choose backend scope. The owner boundary should be core node-host code because `system.notify` is a reserved core command and plugins cannot register the exact missing surface.
