## Summary

Keep open. Current main and the latest release still do not implement Linux desktop notification delivery for the reserved `system.notify` node command: Linux policy can allow it, but the headless node host neither advertises nor handles it, and backend scope needs maintainer direction.

## What This Changes

The issue requests Linux desktop notification support for OpenClaw node notifications, likely through notify-send/libnotify or a D-Bus backend.

## Best Possible Solution

Maintainers should choose the Linux notification backend boundary, then add a focused headless node-host `system.notify` implementation with safe spawning, desktop-session detection, tests, and docs rather than folding this into a broad Linux companion-app PR.

## Reproduction Assessment

Yes from source inspection: a Linux headless node host cannot deliver `system.notify` because it neither advertises nor handles that command. I did not run a live Linux desktop notification flow in this read-only review.

## Solution Assessment

The core command boundary is the right place because `system.notify` is reserved by core, but the suggested fallback stack is not yet proven to be the best permanent scope. A notify-send-first implementation with safe argv spawning and explicit unavailable results looks like the likely first slice once maintainers decide dependency policy.
