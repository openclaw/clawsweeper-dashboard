## Summary

Keep open. Current main and the latest release still do not provide Linux desktop delivery for the reserved `system.notify` node command; the remaining decision is which Linux backend/dependency/headless contract maintainers want before implementation.

## What This Changes

Request to add Linux desktop notification delivery for OpenClaw node `system.notify`, with graceful behavior when no desktop notification backend is available.

## Best Possible Solution

Decide the narrow Linux notification backend contract, then implement core node-host `system.notify` advertisement and handling with argv-safe invocation, structured unavailable behavior, docs/CLI updates, and focused tests.

## Reproduction Assessment

Yes at source level: current main shows Linux policy may allow `system.notify`, but the headless node host neither advertises nor handles that command. I did not run a live Linux desktop notification path because the missing path is already clear from source and docs.

## Solution Assessment

Unclear until maintainers choose the backend and dependency contract. Core node-host is the right owner because `system.notify` is reserved, but the fallback and headless behavior should be narrowed before implementation.
