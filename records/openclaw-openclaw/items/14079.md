## Summary

Keep open. Current main and v2026.6.11 still lack Linux desktop delivery for the reserved `system.notify` node command; the source path is clear, but the Linux backend/dependency/headless behavior needs maintainer direction before implementation.

## What This Changes

Request Linux desktop notification support for OpenClaw node notifications, primarily via `notify-send` or another Linux desktop notification backend.

## Best Possible Solution

Make an explicit maintainer decision on the Linux notification backend contract, then implement a focused core node-host `system.notify` path with safe invocation, unavailable/headless handling, CLI/docs updates, and targeted regression tests.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: a Linux headless node host does not declare `system.notify`, so Gateway rejects it before delivery; if invoked directly, the node-host dispatcher returns `UNAVAILABLE`.

## Solution Assessment

Unclear. The core node-host path is the right owner for the reserved `system.notify` command, but backend and dependency scope need maintainer choice before this should be queued as an automated fix.
