## Summary

Keep open. Current main and v2026.6.11 still lack Linux desktop delivery for the existing `system.notify` node surface; the command is core-reserved, and the related reports neither implement nor supersede this narrower request. Maintainer direction is still needed on the initial Linux backend and dependency contract.

## What This Changes

Add Linux desktop notification delivery for the existing `system.notify` node command, with graceful handling for headless sessions and unavailable backends.

## Best Possible Solution

Add a core-owned Linux headless-node `system.notify` implementation using `notify-send` as the initial explicit backend, advertise it only when the runtime contract is supportable, return structured unavailable errors for headless or missing-backend cases, and cover advertisement, invocation, environment, and documentation behavior without changing other platforms.

- **Defer to Linux app work:** Leave headless Linux nodes unsupported and revisit notifications only through a future native Linux companion, despite `system.notify` remaining core-reserved.

## Solution Assessment

Yes, a focused core node-host implementation is the narrowest maintainable direction because the command is already core-reserved. The issue's proposed multi-backend fallback stack should be narrowed unless maintainers explicitly choose the broader contract.
