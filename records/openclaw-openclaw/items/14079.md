## Summary

Keep open. Current main and v2026.6.11 still do not deliver Linux desktop notifications for the existing `system.notify` node command: Linux policy can allow it, but the headless node host neither advertises nor dispatches it, and related items do not supersede this narrower gap.

## What This Changes

Request Linux desktop-session delivery for the existing core `system.notify` node notification command, with graceful headless degradation.

## Best Possible Solution

Choose a minimal Linux notification backend contract, then implement core node-host `system.notify` with safe invocation, structured unavailable results, docs/CLI updates, focused tests, and real Linux desktop-session proof.

## Reproduction Assessment

Yes, as a source-level reproduction. Current main allows `system.notify` in Linux policy but the headless node host does not declare or dispatch it; I did not run a live Linux desktop notification scenario.

## Solution Assessment

Unclear until maintainers choose the backend scope. The implementation boundary should stay in core node-host code because `system.notify` is a reserved core command and plugins cannot register the exact missing surface.
