## Summary

Keep open. Current main and the latest release still do not deliver Linux desktop notifications for the reserved `system.notify` node command: Linux policy can allow it, but the headless node host neither advertises nor handles it, and the broad Linux companion app PR is not a merged or viable canonical fix for this narrower core-command gap.

## What This Changes

The issue requests Linux desktop notification support for the existing `system.notify` / `openclaw nodes notify` surface.

## Best Possible Solution

Choose the Linux notification backend contract, then implement a focused core node-host `system.notify` path with safe invocation, structured unavailable results, docs/CLI updates, targeted regression coverage, and real Linux desktop-session proof.

## Reproduction Assessment

Yes, as a source-level reproduction: current main allows `system.notify` for Linux in policy, but the headless node host does not declare or dispatch it. I did not run a live Linux desktop notification scenario.

## Solution Assessment

Unclear until maintainers choose backend scope. The owner boundary should be core node-host code because `system.notify` is reserved and plugins cannot register the exact missing command surface.
