## Summary

Keep open. Current main and the latest release still do not deliver Linux desktop notifications for the existing `system.notify` node command: policy can allow it, but the headless node host neither advertises nor dispatches that command, and the backend/security scope still needs maintainer direction.

## What This Changes

Add Linux desktop notification delivery for OpenClaw's existing `system.notify` node command.

## Best Possible Solution

Choose the Linux notification backend/dependency contract, then implement core node-host `system.notify` with safe invocation, structured unavailable results, docs/CLI updates, targeted tests, and real Linux desktop-session proof.

Options:

- **Support multiple backends now:** Add `notify-send` plus D-Bus or `dunstify` fallbacks, accepting a larger support and security-review surface for better desktop coverage.
- **Defer to native Linux app:** Leave headless Linux `system.notify` unsupported until Linux companion-app ownership defines native notification behavior.

## Reproduction Assessment

Yes, as a source-level reproduction. Current main allows `system.notify` in Linux policy, but the headless node host does not declare or dispatch it; I did not run a live Linux desktop notification scenario.

## Solution Assessment

Unclear until maintainers choose the backend scope. If Linux support is accepted, the implementation belongs in core node-host code because `system.notify` is a reserved core command that plugins cannot register directly.
