## Summary

Keep open. Current main and v2026.6.11 still do not deliver Linux desktop notifications for the existing `system.notify` node command: the Linux policy can allow it, but the headless node host neither advertises nor dispatches that command, and backend scope remains a maintainer product/security decision.

## What This Changes

The issue requests Linux desktop notification delivery for the existing node notification command surface.

## Best Possible Solution

Choose the Linux notification backend contract, then implement a focused core node-host `system.notify` path with safe invocation, structured unavailable results, docs/CLI updates, targeted regression coverage, and real Linux desktop-session proof.

## Reproduction Assessment

Yes, as a source-level reproduction. Current main allows `system.notify` in Linux policy but the headless node host does not declare or dispatch it; I did not run a live Linux desktop notification scenario.

## Solution Assessment

Unclear until maintainers choose the backend scope. The implementation boundary should stay in core node-host code if support is accepted because `system.notify` is a reserved core command and plugins cannot register the exact missing surface.
