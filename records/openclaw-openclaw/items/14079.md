## Summary

Keep open. Current main and v2026.6.11 still do not implement Linux `system.notify` delivery for the headless node host; the gap is clear, but backend, dependency, and safe-invocation scope need maintainer direction.

## What This Changes

Add Linux desktop notification support for the existing `system.notify` node command, with desktop-session detection and graceful headless degradation.

## Best Possible Solution

Choose a narrow Linux notification backend contract, then implement core node-host `system.notify` with safe argv invocation, structured unavailable results, docs/CLI updates, regression coverage, and live Linux desktop proof.

Options:

- **Core notify-send first (recommended):** Implement a narrow core node-host handler that uses `notify-send` only when a desktop session is present, returns structured unavailable results otherwise, and documents the optional OS package dependency.
- **Broader backend matrix:** Design a larger backend layer including D-Bus and/or `dunstify`, accepting extra implementation and support scope before work starts.
- **Defer to Linux companion app:** Keep headless node-host notifications unsupported and let the broader Linux companion app direction own desktop notification delivery later.

Yes, as a source-level absence proof: current main allows `system.notify` in Linux policy but the headless node host neither declares nor dispatches it. I did not run a live Linux desktop notification scenario.

## Solution Assessment

Unclear until maintainers choose the backend scope. If Linux support is accepted, the implementation belongs in core node-host code because `system.notify` is a reserved core command and plugins cannot register the exact missing surface.
