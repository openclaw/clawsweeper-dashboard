## Summary

Keep open. Current main and the latest release still lack Linux desktop delivery for the reserved `system.notify` node command: Gateway policy can allow it, but the headless node host neither advertises nor handles it, and maintainer direction is still needed for the Linux backend/dependency contract.

## What This Changes

The issue requests Linux desktop notification support for OpenClaw nodes, including a Linux notification backend and graceful behavior on headless hosts.

## Best Possible Solution

Make an explicit maintainer decision on the Linux notification backend contract, then implement a focused core node-host `system.notify` path with safe invocation, unavailable results, CLI/docs updates, and targeted regression tests.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: a Linux headless node host does not declare `system.notify`, so Gateway rejects it before delivery; if invoked directly, the node-host dispatcher would return `UNAVAILABLE`.

## Solution Assessment

Unclear. The core node-host path is the right owner for the reserved `system.notify` command, but the backend and dependency scope need maintainer choice before this should be queued as an automated fix.
