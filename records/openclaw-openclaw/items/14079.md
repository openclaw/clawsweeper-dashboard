## Summary

Keep open. Current main and the latest release still do not implement Linux node-host desktop notification delivery: the reserved `system.notify` command is allowed by policy in places, but the headless node host does not advertise or dispatch it, and backend/dependency scope still needs maintainer direction.

## What This Changes

The issue requests Linux desktop notification support for the existing node `system.notify` surface.

## Best Possible Solution

Choose the Linux notification backend contract, then implement a focused core node-host `system.notify` path with safe invocation, structured unavailable results, docs/CLI alignment, regression coverage, and real Linux desktop-session proof.

## Maintainer Decision

Rationale: The exact command is reserved by core and cannot be filled by a plugin, but backend choice affects dependency expectations, headless behavior, and safe process invocation.

Likely owner: steipete

Owner confidence: medium

Options:

- **Core notify-send first (recommended):** Implement a narrow core node-host handler that uses `notify-send` when a desktop session is present, returns structured unavailable results otherwise, and documents any optional OS package dependency.
- **Broader backend matrix:** Design a larger backend layer that includes D-Bus and/or `dunstify`, accepting extra implementation and support scope before work starts.
- **Defer to Linux companion app:** Keep headless node-host notifications unsupported and let the broader Linux companion app direction own desktop notification delivery later.

## Reproduction Assessment

Yes. Source inspection on current main shows Linux policy can allow `system.notify`, but the headless node host neither declares nor handles that command; I did not run a live Linux desktop notification scenario in this read-only review.

## Solution Assessment

Unclear until maintainers choose the backend scope. If Linux support is accepted, the implementation belongs in core node-host code because `system.notify` is a reserved core command and plugins cannot register the exact missing surface.
