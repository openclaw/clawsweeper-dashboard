## Summary

Keep open: current `main` still runs Android link-preview metadata and image fetches through blocking OkHttp `execute()` calls without tying the active `Call` to coroutine cancellation, and no duplicate or merged fix owns the remaining cancellation work.

## What This Changes

The issue requests cancellation-aware Android link-preview fetching so cancelled chat preview coroutines do not leave active OkHttp work running on `Dispatchers.IO`.

## Best Possible Solution

Make the shared link-preview body fetch cancellation-aware for both metadata and image paths by cancelling the active OkHttp `Call` when the calling coroutine is cancelled, while preserving tap-to-expand behavior, host policy, redirect limits, body caps, timeouts, and cache semantics.

## Solution Assessment

Yes, a narrow fetcher-level fix is the best shape: the UI, cache, parser, redirect policy, and host policy can stay intact while the OkHttp call execution helper becomes cancellation-aware.
