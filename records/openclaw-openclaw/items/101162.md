## Summary

Current main still has a credible parity gap: the `chat.abort` session path does not carry the stored session id into the abort resolver, while the `/stop` path does, so an active embedded run can be missed even though the stronger text stop path can reach it. The issue is still actionable as a narrow Gateway cancellation bug rather than a close candidate.

## What This Changes

Make Gateway `chat.abort` stop the same active embedded/tool run and cleanup surfaces that `/stop` reaches for the target session, or expose an equivalent public stop RPC.

## Best Possible Solution

Fix `chat.abort` to resolve the canonical session entry and pass the stored session id into the existing full-stop/abort helpers, with focused Gateway regression coverage for active embedded runs and queued-turn cleanup.
