- `P2`: The bug leaves stale duplicate Discord content after an uncommon transient preview-delete failure, with limited channel blast radius.

## Summary

Keep open: the shared ownership fix is useful, but the production Discord flow performs only one cleanup attempt and skips teardown cleanup after final delivery, so the reported stale preview remains after a transient DELETE failure.

## What This Changes

The branch retains a draft preview ID after failed deletion, clears it only after a successful compare-and-clear deletion, and adds a helper-level retry test.

## Best Possible Solution

Keep the shared compare-and-clear behavior, then retry cleanup exactly once during Discord teardown when a fresh final succeeded but the same unfinalized preview ID remains.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source inspection: a fresh final is delivered, preview clear is attempted once, its DELETE error is swallowed, and final teardown then skips another clear. The branch test reproduces ID retention but manually supplies a second call that production does not make.

## Solution Assessment

No. Compare-and-clear is necessary ownership safety, but the narrow complete fix also requires one production Discord teardown retry and caller-level regression coverage.
