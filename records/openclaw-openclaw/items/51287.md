## Summary

Keep open: current main and the latest release still use a fixed exec approval timeout and do not expose a supported approval wait-timeout config key; the remaining work is a security-sensitive public config/API decision.

## What This Changes

Requested behavior: allow operators to configure how long exec approval requests remain pending before timing out.

## Best Possible Solution

Define one canonical, bounded approval-timeout setting, preserve the safe default, reject unsafe values, and thread the resolved value through approval creation, wait budgets, transport slack, schema/help/docs, and tests.

## Reproduction Assessment

Yes, at source level: current main has fixed exec approval timeout constants and no public approval-timeout config or environment override in the config schema. A live approval flow is not required to prove the missing public config surface.

## Solution Assessment

Unclear as proposed: configurability is plausible, but exposing internal constant names is not the right public contract. Maintainers still need to choose the key, bounds, precedence, and security semantics.
