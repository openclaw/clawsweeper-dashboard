## Summary

Keep open: current main and the latest release still do not expose a supported exec-approval timeout setting, and the remaining work is a security-sensitive public config/API decision rather than an obsolete request.

## What This Changes

Request to let operators configure how long exec approval requests remain pending instead of relying on the fixed default timeout.

## Best Possible Solution

Define one maintainer-approved, bounded timeout contract with conservative defaults, then thread it consistently through config/schema/help/docs, approval registration, wait budgets, and focused tests.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 use a fixed exec approval timeout constant, and the strict config schemas do not expose an approval-timeout key. No live approval flow is required to prove the missing public config surface.

## Solution Assessment

Unclear as proposed: exposing internal constant names is not the right public contract. A maintainable fix needs a maintainer-chosen key, bounds, precedence, security semantics, and end-to-end propagation tests.
