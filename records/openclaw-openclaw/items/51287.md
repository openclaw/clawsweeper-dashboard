## Summary

Keep open: current main and the latest release still use a fixed 30-minute exec approval timeout with no supported config or environment override, so this remains the canonical product/security decision for a bounded public timeout contract.

## What This Changes

The issue requests a user-configurable exec approval timeout, likely through `openclaw.json`, so operators can tune how long approval-gated exec requests remain pending.

## Best Possible Solution

Define one bounded public approval-timeout contract with a safe default, maximum, documented precedence, and coverage across schema, runtime registration, wait budgets, transport timeout, docs, and focused tests.
