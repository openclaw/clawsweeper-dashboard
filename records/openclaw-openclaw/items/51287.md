## Summary

Keep open: this remains a security-sensitive product/configuration decision, and the recent July 17 proposal confirms active demand rather than an obsolete request. Earlier timeout PRs were closed unmerged, while the linked heartbeat fail-fast report is explicitly a distinct bug; maintainers should decide whether one bounded, shared approval-timeout contract belongs in the supported configuration surface.

## What This Changes

Request a supported configuration setting that controls how long exec approvals remain pending before timing out.

## Best Possible Solution

Choose one documented, schema-validated approval-timeout setting at the shared approval boundary, retain a conservative maximum and current default unless an upgrade decision says otherwise, derive all linked approval waits from it, and keep unsupported-initiating-surface fail-fast behavior independent.
