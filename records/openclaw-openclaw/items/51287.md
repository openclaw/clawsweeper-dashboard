## Summary

Keep open: current main and the latest release still use a fixed 30-minute exec approval timeout with no supported openclaw.json or environment override, and this remains the canonical thread for a security-sensitive public config decision.

## What This Changes

Request to expose a configurable exec approval timeout so operators can tune how long pending host-exec approvals remain valid.

## Best Possible Solution

Define one stable, bounded timeout contract, keep the safe default, reject unsafe values, and thread the resolved value through config validation, approval registration, wait budgets, transport timeouts, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 use fixed exec approval timeout constants and the config schemas expose no supported approval-expiry key. No live approval flow is required to prove the missing public config surface.

## Solution Assessment

Unclear as proposed: configurability is plausible, but exposing internal constant names is not the right public contract. Maintainers still need to choose the key, bounds, precedence, and security semantics.
