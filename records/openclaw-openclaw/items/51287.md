## Summary

Keep open: current main and v2026.6.11 still use a fixed 30-minute exec-approval timeout with no supported openclaw.json or environment override, and the closed implementation attempts did not land. The remaining work is a security-sensitive public config/API decision rather than a strict bug fix.

## What This Changes

Request to expose a supported, configurable timeout for pending exec approvals instead of relying on the hardcoded default.

## Best Possible Solution

Define one stable, bounded approval-timeout contract that preserves the shipped safe default and threads the resolved value through approval registration, wait budgets, transport timeouts, schemas, docs, and regression tests.

## Reproduction Assessment

Yes, at source level for the missing requested surface: current main has fixed exec approval timeout constants and strict config schemas without an approval-timeout key. No live approval flow is required to prove that the public config override is absent.

## Solution Assessment

Unclear as proposed: configurability is plausible, but exposing internal constant names is not the right public contract. Maintainers still need to choose the key, bounds, precedence, and security semantics.
