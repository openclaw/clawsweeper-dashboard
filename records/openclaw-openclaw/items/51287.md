## Summary

Keep open: current main and v2026.6.11 still use a fixed 30-minute exec approval timeout and do not expose a supported approval-timeout config key. The remaining work is a public config/security policy decision, and prior implementation attempts were closed unmerged.

## What This Changes

Issue requests a supported config path for the exec approval timeout so operators can tune the approval wait window instead of patching built output.

## Best Possible Solution

Expose a bounded, documented approval-wait policy at the owner-approved config boundary and thread it through gateway and node exec approval paths without changing safe defaults unexpectedly.

## Reproduction Assessment

Yes. Current main exposes tools.exec.approvalRunningNoticeMs but not an approval timeout setting, while the approval request path still uses the fixed DEFAULT_EXEC_APPROVAL_TIMEOUT_MS.

## Solution Assessment

Unclear. A config knob is plausible, but the best surface, minimum and maximum bounds, default, env support, and relationship to exec-approvals.json need maintainer security/product judgment.
