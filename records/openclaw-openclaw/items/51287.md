## Summary

Keep open: current main and v2026.6.11 still use a fixed 30-minute exec approval window with no supported user config key, so this remains the canonical product/security decision thread for a bounded timeout setting.

## What This Changes

Request to let operators configure the exec approval wait timeout instead of relying on hardcoded default approval constants.

## Best Possible Solution

Define one canonical, bounded approval-timeout contract after product/security review, keep the safe default, reject unsafe values, and wire the resolved value through approval registration, wait budgets, transport timeouts, docs, and tests.

## Solution Assessment

Unclear as proposed: configurability is plausible, but exposing internal constant names is not the right public contract; maintainers still need to choose the key, bounds, precedence, and security semantics.
