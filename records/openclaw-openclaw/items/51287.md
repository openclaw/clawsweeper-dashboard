## Summary

Keep open: current main and v2026.6.11 still use a fixed 30-minute exec approval timeout with no supported config or environment override, so this remains the canonical product/security decision thread rather than a cleanup-close candidate.

## What This Changes

The issue requests a supported way to configure the exec approval timeout instead of relying on the hardcoded default.

## Best Possible Solution

Define one bounded public approval-timeout contract with a safe default, maximum, documented precedence, and coverage across registration, wait, transport timeout, schema, docs, and release-note context.
