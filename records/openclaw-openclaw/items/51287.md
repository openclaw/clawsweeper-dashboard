## Summary

Keep open: current main and v2026.6.11 still do not expose a supported exec-approval timeout setting; the old two-minute default was raised to 30 minutes, but the remaining operator-configurable timeout contract is still a security-sensitive product/config decision.

## What This Changes

The issue requests a supported openclaw.json setting to configure the exec approval wait timeout instead of relying on the current hardcoded default.

## Best Possible Solution

Define one stable, bounded approval-timeout contract after maintainer product/security agreement, preserve the shipped safe default, reject unsafe values, and thread the resolved value consistently through approval registration, wait budgets, transport timeouts, docs, and tests.

## Reproduction Assessment

Yes, at source level: current main uses fixed exec approval timeout constants and has no public approval-timeout key in the strict config schema. No live approval flow is needed to prove the missing config surface.

## Solution Assessment

Unclear as proposed: configurability is plausible, but exposing internal constant names is not the right public contract. Maintainers still need to choose the supported key, bounds, precedence, and security semantics.
