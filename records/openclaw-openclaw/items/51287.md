## Summary

Keep open: current main and v2026.6.11 still use a fixed 30-minute exec approval timeout with no supported config or environment override, so this remains the canonical security-sensitive config decision.

## What This Changes

The issue requests exposing the exec approval timeout as a configurable OpenClaw setting instead of relying on the hardcoded default.

## Best Possible Solution

Define one bounded public approval-timeout contract with a safe default, maximum, documented precedence, and coverage across registration, wait, transport timeout, schema, docs, and release-note context.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 use fixed exec approval timeout constants and expose no supported approval-timeout config or environment override. No live approval flow is required to prove the missing public config surface.

## Solution Assessment

Unclear as proposed: making the timeout configurable is plausible, but exposing internal constant names is not the right public contract. Maintainers should first choose the bounded key, precedence, and security semantics.
