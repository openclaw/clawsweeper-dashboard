## Summary

Keep open: current main and v2026.6.11 still use a fixed 30-minute exec approval timeout with no supported config or environment override, so this remains the canonical security-sensitive config decision.

## What This Changes

The issue asks for a supported `openclaw.json` or equivalent override for the exec approval wait timeout instead of a fixed compiled default.

## Best Possible Solution

Define one bounded public approval-timeout contract with a safe default, maximum, documented precedence, and coverage across registration, wait, schema, docs, and tests.

Options:

- **Add bounded canonical config (recommended):** Expose one documented timeout key with conservative minimum/maximum validation and wire it through all exec approval request and wait paths.
- **Keep fixed default:** Decline the public knob and keep the current 30-minute default, possibly improving UX around missed approvals instead.
- **Config-only, no env var:** Allow `openclaw.json` control but avoid a process-wide environment override for this security-sensitive window.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 hard-code the exec approval timeout in the request path, while the config schema has no supported approval-timeout key.

## Solution Assessment

No as originally proposed. Making internal constants configurable is not the public contract; maintainers should first choose the bounded key, precedence, and security semantics.
