## Summary

Keep open: current main and v2026.6.11 still do not expose a supported exec approval timeout setting; the remaining work is a security-sensitive public config/API decision, and prior implementation PRs are closed unmerged.

## What This Changes

The issue requests a supported configuration surface for changing the exec approval timeout instead of relying on the hardcoded default.

## Best Possible Solution

Define one stable, bounded approval-timeout contract, preserve the safe default, reject unsafe values, and thread the resolved value consistently through approval registration, wait budgets, transport timeouts, docs, and tests.

## Reproduction Assessment

Yes, at source level: current main has fixed exec approval timeout constants and no public approval-timeout config or environment override in the config schema. No live approval flow is required to prove the missing public config surface.

## Solution Assessment

Unclear as proposed: configurability is plausible, but exposing internal constant names is not the right public contract. Maintainers still need to choose the key, bounds, precedence, and security semantics.
