## Summary

Keep open: current main and v2026.6.11 still use a fixed 30-minute exec approval timeout with no supported config or environment override, so this remains the canonical security-sensitive product decision.

## What This Changes

Request to let operators configure the exec approval timeout, likely through `openclaw.json`, instead of relying on the built-in default.

## Best Possible Solution

Define one bounded public approval-timeout contract with safe defaults, a maximum, schema/help/docs coverage, and aligned registration, wait, transport-timeout, and follow-up behavior.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 use fixed exec approval timeout constants and expose no supported config or environment override. No live approval flow is required to prove the missing public config surface.

## Solution Assessment

Unclear as proposed: making the timeout configurable is plausible, but exposing internal constant names is not the right public contract. Maintainers should first choose the bounded key, precedence, validation, and security semantics.
