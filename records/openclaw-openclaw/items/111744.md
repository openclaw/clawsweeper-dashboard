## Summary

Keep this PR open, but it is not merge-ready: the new message-only match can turn a Z.AI parameter rejection into context-overflow recovery even though Z.AI documents error 1210 as a generic invalid-parameter class and distinguishes output `max_tokens` from the total context window. The reported bug is valid, but the classifier needs a confirmed context-specific contract plus real after-fix provider proof.

## What This Changes

The branch adds the Z.AI/Zhipu phrase `tokens in request more than max tokens allowed` to the package and embedded-agent overflow classifiers, with focused regression cases.

## Best Possible Solution

Gate overflow recovery on a Z.AI context-limit condition confirmed by the provider contract or live payload, preserve parameter/output-limit failures as ordinary format errors, add positive and negative regression coverage, and attach redacted real-run proof of a recovered long-context turn.
