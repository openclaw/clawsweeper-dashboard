## Summary

Keep open, but the reported root cause is not yet established: current main already creates a fresh session for reset or expired entries, and `/compact` does not archive the session. The report needs gateway diagnostics showing where the inbound message stops before a repair can be safely scoped. Likely related people: @steipete and @vincentkoc for session rollover history, and @obviyus for recent reply-session initialization work.

## What This Changes

Prevent inbound channel messages from being silently lost when their conversation session has been reset or marked archived.

## Best Possible Solution

Capture the failing inbound turn with session key, old and new session IDs, archivedAt/status fields, and diagnostic outcome; then add a generic session-lifecycle regression test and fix the earliest shared boundary that loses the turn, without introducing a channel-specific fallback or new configuration option.
