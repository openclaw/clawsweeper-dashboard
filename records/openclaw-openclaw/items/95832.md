## Summary

Keep this PR open: current main and the latest release still hardcode Twilio voice-call REST traffic to US1, while this PR is a focused, mergeable implementation of the linked regional-routing feature. I found no concrete line-level correctness defect; the remaining blocker is maintainer acceptance of the new public `twilio.region` config and provider-auth routing contract.

## What This Changes

The PR adds optional `twilio.region` voice-call config for `us1`, `ie1`, and `au1`, derives exact Twilio regional REST hostnames, applies them to Twilio requests and SSRF allowlists, and updates docs, manifest metadata, and tests.

## Best Possible Solution

Land the region-only `twilio.region` contract if maintainers accept the new plugin config surface, keeping exact enum-derived Twilio hostnames coupled to SSRF allowlists and the linked feature issue as the product record.

## Reproduction Assessment

Yes, at source level: current main still constructs Twilio REST calls against `api.twilio.com`, allowlists only that hostname, and has no `twilio.region` schema field. I did not run a credentialed current-main regional failure path.

## Solution Assessment

Yes: the closed region-to-hostname mapping is narrower and safer than arbitrary base URLs or exposing independent edge labels, while still needing maintainer acceptance as a public config contract.
