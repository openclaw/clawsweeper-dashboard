## What This Changes

The PR adds optional `twilio.region` voice-call configuration, derives Twilio REST hostnames for US1, IE1, and AU1, threads the target through Twilio REST requests/status lookups, and updates docs, metadata, and tests.

## Best Possible Solution

Land the region-only `twilio.region` contract if maintainers accept the new plugin config surface, keeping exact enum-derived Twilio hostnames coupled to SSRF allowlists and the linked issue as the product record.

## Reproduction Assessment

## Solution Assessment

Yes, this appears to be the narrow maintainable implementation shape: it avoids arbitrary base URLs, derives exact Twilio hostnames from a closed region enum, and keeps SSRF policy coupled to the request host. The remaining question is product acceptance of the new public config contract.
