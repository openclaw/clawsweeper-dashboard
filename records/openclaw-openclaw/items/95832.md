## Summary

Keep open for maintainer review: current main and the latest release still lack Twilio regional REST routing, and this PR looks like a correct region-only implementation with sufficient IE1 status proof, but it adds a public plugin config/auth-routing contract that needs maintainer acceptance before merge.

## What This Changes

The PR adds optional voice-call `twilio.region` config, maps `us1 | ie1 | au1` to exact Twilio REST hostnames, uses that target for Twilio POST/status SSRF allowlists, and updates docs, manifest metadata, and tests.

## Best Possible Solution

Land the region-only contract if maintainers accept the new Twilio config surface; otherwise keep the linked feature issue as the product decision record rather than merging a broader base URL or edge API.

## Reproduction Assessment

Yes, at source level: current main and `v2026.6.11` hardcode Twilio REST requests and SSRF allowlists to `api.twilio.com`, with no `twilio.region` config. I did not run a credentialed current-main regional failure path.

## Solution Assessment

Yes, this appears to be the best narrow implementation shape: it avoids arbitrary base URLs, derives exact Twilio hostnames from a closed region enum, and keeps SSRF policy coupled to the request host. The remaining question is maintainer acceptance of the new public config contract.
