## Summary

Keep open for maintainer review: the patch appears correct and well-proven, but it adds a new public Twilio region config and provider-auth routing contract that needs maintainer acceptance before merge.

## What This Changes

Adds optional `twilio.region` voice-call config, derives exact Twilio REST hostnames for US1/IE1/AU1, uses the derived host for Twilio POST/status requests and SSRF allowlists, and updates docs, manifest metadata, and tests.

## Best Possible Solution

Land the region-only `twilio.region` contract if maintainers accept the new public config surface, keeping exact enum-derived Twilio hostnames coupled to SSRF allowlists and the linked feature issue as the product record.

## Reproduction Assessment

Yes, at source level: current main and `v2026.6.11` hardcode Twilio REST requests and SSRF allowlists to `api.twilio.com`, while Twilio's regional REST contract requires regional hostnames for IE1/AU1. I did not run a credentialed current-main regional failure path.

## Solution Assessment

Yes, this appears to be the narrowest maintainable implementation if maintainers accept the config surface: it avoids arbitrary base URLs, hides REST edge labels behind a closed region enum, and keeps the SSRF allowlist tied to the derived request host.
