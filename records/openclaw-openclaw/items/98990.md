## Summary

Keep open: the underlying resource-leak bug is real, but the current PR head is not merge-ready because it still evicts after watcher allocation, can evict an unrelated watcher on same-key retries, and the updated body/proof claims tests and guarded insertion that are not present in the live diff.

## What This Changes

The PR adds a 64-entry cap to the usage-bar template file cache and evicts the oldest cached watcher when the cache is full.

## Best Possible Solution

Land a corrected bounded-cache implementation that evicts only before inserting a new key, frees an old watcher before opening the replacement watcher, and includes focused regression tests plus current-head real behavior proof.

## Reproduction Assessment

Yes. Source inspection on current main shows each distinct valid template path can allocate an `fs.watch` watcher and is stored in `fileCache` with no production eviction path.

## Solution Assessment

No. Bounding the cache in `src/auto-reply/usage-bar/template.ts` is the right layer, but the live patch should evict before watcher allocation, guard eviction to new keys, and commit the tests described in the body.
