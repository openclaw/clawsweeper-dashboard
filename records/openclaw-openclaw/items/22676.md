## Summary

Keep open. Current main and the latest release still have synchronous Signal daemon shutdown, and the open linked PR is the active closing candidate, so closing this issue now would drop tracking for an unfixed channel restart bug.

## What This Changes

The issue reports a Signal daemon restart race where shutdown sends SIGTERM without waiting, allowing a new signal-cli process to race old process cleanup and fail sends.

## Best Possible Solution

Keep this issue open while maintainers review and land https://github.com/openclaw/openclaw/pull/71863 or an equivalent Signal-owned fix that awaits daemon shutdown before restart.

## Reproduction Assessment

Yes from source: current main and v2026.6.11 still have synchronous Signal daemon stop and synchronous monitor teardown on abort/finally, matching the reported restart race path. I did not run a live Signal restart reproduction in this read-only cleanup pass.

## Solution Assessment

Yes, the narrow maintainable fix is to make the Signal daemon handle stop async/idempotent, wait for child exit, and have monitor teardown await it before channel restart. The open linked PR is the current implementation candidate for that shape.
