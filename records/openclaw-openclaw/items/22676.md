## Summary

Keep open. Current main and the latest release still have synchronous SIGTERM-only Signal daemon shutdown, and https://github.com/openclaw/openclaw/pull/71863 is the open unmerged closing candidate for the focused fix.

## What This Changes

The issue reports a Signal daemon stop race during gateway restart that can leave orphaned signal-cli processes and cause Signal send failures.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/71863, or an equivalent focused Signal-owned lifecycle fix that awaits daemon exit after SIGTERM, escalates after a bounded timeout, and keeps monitor shutdown pending before restart.

Yes, at source level. Current main sends SIGTERM without awaiting child exit, and Signal config hot reload can stop then restart the channel; I did not run a live linked Signal restart.

Yes. The best fix belongs in the Signal daemon lifecycle and monitor cleanup, not in a gateway sleep or broad unrelated child-process rewrite; the linked PR is the active focused implementation candidate.
