## Summary

Keep open. Current main and the latest release still have synchronous SIGTERM-only Signal daemon shutdown, and https://github.com/openclaw/openclaw/pull/71863 is the open closing implementation candidate.

## What This Changes

The issue reports that Signal daemon shutdown during SIGUSR1/config hot-reload sends SIGTERM without waiting, causing orphaned signal-cli processes and message send failures.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/71863, or an equivalent focused Signal-owned lifecycle fix that awaits daemon exit after SIGTERM, escalates after a bounded timeout, and awaits monitor cleanup before restart.

## Reproduction Assessment

Yes, source-reproducible. Current main shows Signal daemon stop sends SIGTERM without awaiting child exit, and Signal config reload can stop and restart the channel; I did not run a live linked Signal restart.

## Solution Assessment

Yes. The best fix belongs in the Signal daemon lifecycle and monitor cleanup, and the linked PR is already the focused implementation candidate.
