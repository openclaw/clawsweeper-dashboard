- `impact:message-loss`: The reported race can route Signal RPC calls to a stale or failed daemon and produce send failures.

## Summary

Keep open: current main and v2026.6.11 still have synchronous SIGTERM-only Signal daemon shutdown, and https://github.com/openclaw/openclaw/pull/71863 is the open, clean implementation candidate that specifically closes this issue.

## What This Changes

The issue asks OpenClaw to make Signal daemon shutdown on restart await signal-cli exit and escalate to SIGKILL so restarts do not leave orphaned processes or cause send failures.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/71863, or an equivalent focused Signal plugin fix that makes daemon stop async/idempotent, waits for process exit, escalates after a bounded timeout, and keeps monitor teardown open until shutdown completes.

## Reproduction Assessment

Yes for source-level reproduction: current main still has a void SIGTERM-only daemon stop and monitor teardown calls it without awaiting process exit. I did not run a live Signal account repro in this read-only review.

## Solution Assessment

Yes, the requested fix shape is the narrow owner-boundary repair: make Signal daemon stop await exit with bounded escalation and await it through monitor teardown. The best path is to review and land the already-open linked PR rather than queue another fix.
