## Summary

Keep open: current main and the latest release still have the Signal daemon fire-and-forget shutdown path, and the open, mergeable linked PR is the active candidate fix rather than a reason to close this issue early.

## What This Changes

The issue reports a Signal daemon restart race where stop() sends SIGTERM without waiting for signal-cli to exit, causing orphaned processes and send failures.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/71863, or an equivalent Signal-owned lifecycle fix that awaits daemon exit with bounded SIGKILL escalation before channel restart.

## Reproduction Assessment

Yes, at source level: current main sends SIGTERM from SignalDaemonHandle.stop without awaiting child exit, while Signal config reload can stop and immediately restart the channel. I did not run a live linked Signal restart in this read-only review.

## Solution Assessment

Yes, the best fix belongs in the Signal daemon lifecycle and monitor cleanup, not in a gateway delay or a broad child-process rewrite. The open linked PR is the current focused implementation candidate.
