## Summary

Keep open. Current main and the latest release still have synchronous SIGTERM-only Signal daemon shutdown, and https://github.com/openclaw/openclaw/pull/71863 is still the open, unmerged closing candidate for this issue.

## What This Changes

The issue reports that Signal daemon restart teardown sends SIGTERM without waiting for signal-cli to exit, causing orphaned processes and send failures.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/71863, or an equivalent focused Signal-owned lifecycle fix that awaits daemon exit after SIGTERM, escalates after a bounded timeout, and awaits monitor shutdown before restart.

## Reproduction Assessment

Yes at source level. Current main shows Signal daemon stop sends SIGTERM without awaiting child exit, while Signal config hot reload can stop and restart the channel; I did not run a live linked Signal restart.

## Solution Assessment

Yes. The best fix belongs in the Signal daemon lifecycle and monitor cleanup, not in a gateway delay or a broad unrelated child-process rewrite.
