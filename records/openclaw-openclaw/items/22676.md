## Label Justifications

- `P1`: The bug can break an active Signal channel workflow after config/SIGUSR1 restart by leaving old signal-cli processes holding the port or config lock.
- `impact:message-loss`: The reported stale/orphaned daemon state produces Signal send failures after restart.
- `impact:crash-loop`: The issue concerns process lifecycle availability: orphaned signal-cli processes and restart races can leave the channel unable to recover without manual process cleanup.

## Summary

Keep open: current main still has the Signal daemon restart race, and the focused closing fix at https://github.com/openclaw/openclaw/pull/71863 remains open and unmerged. This issue is also assigned with member follow-up, so conservative cleanup should not close it before that fix path is resolved.

## What This Changes

The issue asks for Signal daemon shutdown to wait for signal-cli exit during SIGUSR1/config hot restarts so old processes do not keep ports or config locks and cause send failures.

## Best Possible Solution

Keep this issue open and land https://github.com/openclaw/openclaw/pull/71863 or an equivalent Signal-owned lifecycle fix that awaits daemon exit after SIGTERM, escalates after a bounded timeout, and keeps monitor teardown open until cleanup finishes.
