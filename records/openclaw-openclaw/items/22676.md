## Summary

Keep open: current main and the latest release still use fire-and-forget Signal daemon shutdown, and https://github.com/openclaw/openclaw/pull/71863 is an open closing PR that owns the focused fix path.

## What This Changes

The issue reports that Signal hot-reload restarts can start a new signal-cli daemon before the old daemon exits, leaving orphaned processes and causing send failures.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/71863, or an equivalent Signal-owned fix that makes daemon stop async, idempotent, bounded by SIGKILL escalation, and awaited through monitor teardown.
