## Summary

Keep open: current main and the latest release still have synchronous SIGTERM-only Signal daemon shutdown, and the open linked PR is the active implementation candidate.

## What This Changes

The issue reports a Signal daemon restart race where SIGTERM is sent without awaiting signal-cli exit, leaving orphaned processes and causing send failures.

## Best Possible Solution

Review and land the active Signal lifecycle PR, or an equivalent focused Signal-owned fix that awaits daemon exit after SIGTERM, escalates after a bounded timeout, and awaits monitor cleanup before restart.

## Reproduction Assessment

Yes. Current main source still has synchronous SIGTERM-only daemon stop, while Signal config hot reload can stop and then restart the channel; I did not run a live linked Signal restart in this read-only review.

## Solution Assessment

Yes. The best fix belongs in the Signal daemon lifecycle and monitor cleanup rather than a gateway delay or broad child-process rewrite; the open linked PR is the focused candidate.
