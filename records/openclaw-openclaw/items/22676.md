- `impact:message-loss`: The stale or orphaned Signal daemon state can produce message send failures after restart.

## Summary

Keep open: current main and the latest release still use fire-and-forget Signal daemon shutdown, and the open closing PR at https://github.com/openclaw/openclaw/pull/71863 is the active fix candidate.

## What This Changes

Fix the Signal plugin daemon shutdown so SIGUSR1/config hot reload waits for signal-cli to exit, with bounded SIGKILL escalation, before restarting.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/71863, or an equivalent focused Signal plugin fix that awaits daemon exit after SIGTERM, escalates after a bounded timeout, and keeps monitor teardown open until cleanup completes.
