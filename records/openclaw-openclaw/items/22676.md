- `impact:message-loss`: The reported stale/orphaned daemon state can produce Signal send failures after restart.

## Summary

Keep open: current main and the latest release still use fire-and-forget Signal daemon shutdown, and the focused closing fix at https://github.com/openclaw/openclaw/pull/71863 remains open and unmerged.

## What This Changes

The issue reports that Signal daemon shutdown during gateway hot reload returns after SIGTERM without waiting for signal-cli to exit, allowing orphaned processes and send failures on restart.

## Best Possible Solution

Keep this issue open and land https://github.com/openclaw/openclaw/pull/71863 or an equivalent Signal-owned lifecycle fix that awaits daemon exit after SIGTERM, escalates after a bounded timeout, and keeps monitor teardown open until cleanup finishes.
