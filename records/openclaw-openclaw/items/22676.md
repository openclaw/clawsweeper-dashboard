- `impact:message-loss`: The reported stale or orphaned Signal daemon state can produce send failures after restart.

## Summary

Keep open: current main and v2026.6.11 still use fire-and-forget Signal daemon shutdown, and the focused closing PR remains open and unmerged.

## What This Changes

The issue reports that Signal daemon hot-restart sends SIGTERM without waiting for signal-cli to exit, leaving orphaned daemons and causing send failures.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/71863, or an equivalent Signal-owned lifecycle fix that awaits daemon exit after SIGTERM, escalates after a bounded timeout, and keeps monitor teardown open until cleanup finishes.
