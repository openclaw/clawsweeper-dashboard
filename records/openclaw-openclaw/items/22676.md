- `impact:message-loss`: The reported stale or orphaned Signal daemon state can produce Signal send failures after restart.

## Summary

Keep open: current main and v2026.6.11 still use fire-and-forget Signal daemon shutdown, while the focused closing fix remains open at https://github.com/openclaw/openclaw/pull/71863.

## What This Changes

The issue asks for Signal daemon shutdown to wait for signal-cli exit during SIGUSR1/config hot-reload restarts so old processes do not hold the port or config lock.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/71863, or an equivalent focused Signal-owned fix that awaits daemon exit after SIGTERM, escalates after a bounded timeout, and keeps monitor teardown open until cleanup finishes.
