## Label Justifications

- `P1`: The bug can break an active Signal channel workflow after config or SIGUSR1 restart by leaving old signal-cli processes holding the port or config lock.
- `impact:message-loss`: The reported stale or orphaned Signal daemon state can produce Signal send failures after restart.
- `impact:crash-loop`: The issue concerns process lifecycle availability: orphaned signal-cli processes and restart races can leave the channel unable to recover without manual cleanup.

## Summary

Keep open: current main still uses fire-and-forget Signal daemon shutdown, the latest release still ships that behavior, and https://github.com/openclaw/openclaw/pull/71863 is the active open fix candidate.

## What This Changes

The issue requests fixing the Signal plugin restart race by making signal-cli daemon shutdown asynchronous, awaited, and bounded with SIGKILL escalation before restart.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/71863, or an equivalent Signal-owned lifecycle fix that awaits daemon exit after SIGTERM, escalates after a bounded timeout, and keeps monitor teardown open until cleanup finishes.
