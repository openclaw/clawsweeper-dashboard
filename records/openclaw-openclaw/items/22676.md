## Summary

Keep open: current main and the latest release still use fire-and-forget Signal daemon shutdown, while the focused closing fix remains open at https://github.com/openclaw/openclaw/pull/71863.

## What This Changes

The issue asks for Signal daemon shutdown to await signal-cli exit, with bounded SIGKILL escalation, before hot restart starts a replacement daemon.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/71863, or an equivalent focused Signal-owned fix, so monitor teardown awaits daemon exit before channel restart proceeds.

## Maintainer Decision

## Reproduction Assessment

Yes. Source inspection on current main shows Signal stop still returns void after SIGTERM, and the gateway reload path can stop then immediately start the channel; I did not run a live linked Signal account repro.

## Solution Assessment

Yes. The best fix is a narrow Signal lifecycle change that makes stop async/idempotent, waits for process exit, escalates after a bounded timeout, and keeps monitor teardown pending until that completes.
