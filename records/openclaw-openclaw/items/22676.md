## Summary

Keep open: current main and the latest release still use synchronous SIGTERM-only Signal daemon shutdown, and the open linked PR is the active closing candidate.

## What This Changes

The issue requests fixing Signal daemon restart shutdown so signal-cli exits before a new daemon is started during config/SIGUSR1 restarts.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/71863, or an equivalent focused Signal-owned lifecycle fix that awaits daemon exit after SIGTERM and escalates after a bounded timeout before restart.

## Reproduction Assessment

Yes. Current main source shows Signal daemon stop sends SIGTERM without awaiting child exit, while Signal config hot reload can stop and restart the channel; I did not run a live linked Signal restart.

Yes. The best fix belongs in the Signal daemon lifecycle and monitor cleanup, not in a gateway delay or broad child-process rewrite; the linked PR is the active focused implementation candidate.
