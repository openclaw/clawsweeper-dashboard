## Label Justifications

- `P1`: The bug can break an active Signal channel workflow after config or SIGUSR1 restart by leaving old signal-cli processes holding the port or config lock.
- `impact:message-loss`: The reported stale or orphaned Signal daemon state can produce Signal send failures after restart.
- `impact:crash-loop`: The issue concerns process-level availability: orphaned signal-cli processes and restart races can leave the channel unable to recover without manual cleanup.

## Summary

Keep open: current main and v2026.6.11 still use fire-and-forget Signal daemon shutdown, and the live closing PR at https://github.com/openclaw/openclaw/pull/71863 is the active fix candidate rather than a reason to close this issue early.

## What This Changes

Fix the Signal daemon restart race by making shutdown wait for signal-cli to exit, with bounded SIGKILL escalation, before hot reload starts a new daemon.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/71863, or an equivalent Signal-owned lifecycle fix that awaits daemon exit after SIGTERM, escalates after a bounded timeout, and keeps monitor teardown open until cleanup finishes.
