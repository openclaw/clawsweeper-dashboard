## Summary

Close as implemented: current main and v2026.6.11 no longer have the write-time media pruning that could make an inbound media ID disappear after initial use, and the reported WhatsApp double-save route is not present in the current channel pipeline.

## What This Changes

The issue asks for WhatsApp inbound images to remain readable through the same `media://inbound/<id>` reference across later turns or subagent contexts.

## Best Possible Solution

Keep the shipped v2026.6.11 media cleanup behavior; if the failure still appears after upgrading, open a new report with `media.ttlHours` and gateway logs so the remaining TTL/session-retention path can be isolated.

## Reproduction Assessment

No live current-main reproduction was established. Source and history show the old disappearing-file cause and its fix, while current main no longer has the reported double-save path or write-time pruning behavior.

## Solution Assessment

Yes. The maintainable solution is the current ownership split: WhatsApp saves inbound media once, prompt projection uses that saved basename, and cleanup is owned by the configured maintenance timer rather than media writes.
