## Summary

Current main and the published v2026.6.11 release no longer match the reported double-save/missing-file behavior: WhatsApp inbound media is saved once, prompt refs are derived from that saved path, and the media store no longer prunes retained media during writes.

## What This Changes

The issue reports repeated reads of a WhatsApp inbound image failing because the `media://inbound/` reference allegedly points at a second saved copy that later disappears.

## Best Possible Solution

Keep the shipped current media-store behavior: WhatsApp inbound media is saved once, prompt references are derived from that saved path, and media writes no longer run opportunistic cleanup.

## Reproduction Assessment

No high-confidence current-main failure reproduction was run. Source inspection shows the alleged double-save route is absent on current main, and history plus release evidence show the plausible missing-file cleanup path has been fixed and shipped.

## Solution Assessment

Yes. The shipped solution is the right layer because it removes write-triggered media cleanup and keeps retention owned by configured gateway maintenance instead of adding a WhatsApp-specific UUID workaround.
