## Summary

The PR’s lifecycle-owned, non-recursive cleanup is the right approach and the immediate auto-reply path is well proven, but Gateway-prestaged attachments lose their cleanup owner when work transfers into the follow-up/collect queue, so the original empty-directory leak remains for that supported path.

## What This Changes

The PR adds best-effort cleanup callbacks to inbound-media staging and invokes them after auto-reply or Gateway attachment consumers finish, with tests for empty-directory removal and non-empty preservation.

## Best Possible Solution

Transfer Gateway attachment cleanup into the existing queued follow-up lifecycle when enqueue succeeds, while retaining immediate cleanup for non-queued completion, preparation failures, aborts, routing changes, and thrown dispatch errors.
