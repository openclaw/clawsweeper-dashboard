## Label Justifications

- `P1`: The patch can silently disable existing package and resource configurations for users who rely on supported paths outside the settings directory.
- `merge-risk: 🚨 compatibility`: The new containment checks reject previously supported absolute and parent-relative local package and resource paths during upgrade.

## Summary

This PR should not merge as written: both guards convert intentionally user-selected local paths into paths confined beneath the settings directory, contradicting the package-manager contract that supports absolute local paths. The proposed security boundary is appropriate for package-manifest-owned entries, not explicit user configuration, and the PR supplies no real traversal proof or regression coverage.

## What This Changes

The PR rejects local package sources and plain local resource entries whose real paths fall outside their scope-specific base directory.

## Best Possible Solution

Keep explicit user-configured local paths unrestricted, retain containment checks for package-manifest-owned paths relative to the package root, and add focused tests proving manifest traversal rejection and continued support for absolute and parent-relative configured paths.
