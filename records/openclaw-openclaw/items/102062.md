## Summary

Keep this PR open, but it is not merge-ready: the fix is aimed at the right OpenRouter video catalog path, yet the new request-policy-sensitive fetch still reuses a cache key that ignores request headers and private-network policy.

## What This Changes

This PR passes configured OpenRouter provider request overrides into video catalog discovery and per-model video capability resolution, with focused video provider test coverage.

## Best Possible Solution

Keep the provider-local fix, but make the live catalog cache identity include a stable discriminator for the sanitized request policy and add a regression test that changes request headers or `allowPrivateNetwork` across sequential catalog calls.

Full review comments:

- **[P1] Include request policy in the video catalog cache key:** `extensions/openrouter/video-model-catalog.ts:216`
  - body: This PR makes headers and `allowPrivateNetwork` part of the catalog fetch, but the live catalog cache still keys only on provider/baseUrl/API key.
