Keep open: current main has coarse compaction start/end indicators and existing context-engine hooks, but it still lacks the requested staged WebChat lifecycle, compaction-specific diagnostics API/CLI, and completed running-summary guidance.

## Best Possible Solution

Define a narrow core observability contract: safe staged compaction events for WebChat, redacted compaction diagnostics through the existing Gateway/CLI diagnostics model, and separate context-engine or ClawHub documentation for running-summary implementations.
