## Summary

Keep open: current main and the latest release still have only DM-specific session scoping, group/channel peers remain isolated, strict config cannot express `groupScope`, and the open linked PR is an unmerged conflicting implementation candidate rather than landed behavior.

## What This Changes

Add an opt-in `groupScope` configuration so selected group chats can share an agent's main session instead of always using isolated group session keys.

## Best Possible Solution

Keep this focused tracker open until the linked PR or an equivalent backwards-compatible, opt-in group-to-main routing contract lands with inbound/outbound parity, config/docs coverage, regression tests, and shared-context security guidance.

## Reproduction Assessment

Yes, at source level for the missing capability. Current main deterministically derives isolated keys for non-direct peers, and the strict schemas cannot express a group-to-main option.

## Solution Assessment

Unclear as a final product path. `groupScope` is a plausible additive direction with an open implementation PR, but maintainers still need to settle security posture, config scope, proof, and PR readiness before this issue can close.
