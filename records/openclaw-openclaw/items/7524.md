## Summary

Current main still isolates group and channel peers, and the open linked PR is the active implementation candidate. Keep this issue open while maintainers decide whether the trust-boundary feature should be limited to exact bindings or also expose a global default.

## What This Changes

Add an opt-in global or per-binding setting that routes selected group conversations into an agent’s main session.

## Best Possible Solution

Keep isolation as the default and allow only explicitly matched trusted peers to share the main session, with visible context-leakage warnings and proof that delivery and runtime policy remain tied to the originating peer.

## Maintainer Decision

Question: Should the supported contract include a global group-to-main default, or only an explicit per-binding opt-in for trusted peers?

Rationale: Both enable the workflow, but the global option materially broadens accidental context sharing and creates a long-lived compatibility-sensitive core configuration surface.

Likely owner: steipete

Owner confidence: high

Options:

- **Per-binding only (recommended):** Land only an exact-binding opt-in so every trusted group or channel is deliberately selected and all others remain isolated.
- **Global plus override:** Allow a global group default with binding exceptions, accepting wider cross-channel and cross-account exposure risk.
- **Named shared sessions:** Keep main private and route selected conversations into separate named shared sessions instead.

## Reproduction Assessment

Yes. Current-main source and docs provide a high-confidence source reproduction: only direct peers can fold into main, while group and channel peers remain isolated with no override.

## Solution Assessment

No, not yet as proposed. The capability is useful, but an exact per-binding opt-in is safer than a global group-to-main default unless maintainers explicitly approve the wider trust boundary.
