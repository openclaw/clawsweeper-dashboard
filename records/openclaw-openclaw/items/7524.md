## Summary

Keep this issue open: current main and v2026.6.11 still isolate group/channel peers, while the direct implementation candidate remains open, conflicting, and unmerged; the remaining choice is an explicit product and security-boundary decision, not stale cleanup.

## What This Changes

Add an opt-in global or per-binding session scope that routes selected group chats into an agent’s main session instead of isolated group sessions.

## Best Possible Solution

Keep group and channel isolation as the default, then land one opt-in binding-aware routing contract that preserves origin-based reply delivery and sandbox policy, documents cross-conversation exposure, adds security diagnostics, and proves fresh-config plus upgrade behavior; prefer the focused `groupScope` only if maintainers do not want the broader canonical-session abstraction.
