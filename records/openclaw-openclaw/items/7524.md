## Summary

Keep this issue open: current main still isolates non-direct peers, while the open linked implementation PR has not yet resolved the product and trust-boundary decision for sharing group context with the main session. 

## What This Changes

Add an opt-in global or per-binding session scope that lets selected group conversations share an agent’s main session.

## Best Possible Solution

Keep isolation as the default and add an explicit per-binding trusted-conversation opt-in, with clear security warnings, preserved origin metadata, consistent inbound/outbound routing, and cross-channel regression proof before considering any broader global switch.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support group-to-main sharing only for explicitly matched bindings, or also expose a global switch that can merge every group conversation?

Rationale: Both shapes are technically feasible, but they establish different public configuration and privacy contracts that automation cannot choose safely.

Likely owner: steipete

Owner reason: The existing issue discussion and routing history make steipete the strongest available owner for the product and security-boundary choice.

Owner confidence: high

Options:

- **Per-binding opt-in only (recommended):** Allow only explicitly matched trusted group/channel bindings to share main, preserving isolation everywhere else and minimizing accidental context exposure.
- **Global plus binding overrides:** Accept a global default with per-binding exceptions, providing convenience at the cost of a much broader and easier-to-misconfigure trust boundary.
- **Keep group isolation:** Reject group-to-main routing and retain separate sessions, directing users toward memory or future named shared-session capabilities instead.
