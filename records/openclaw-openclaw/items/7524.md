## Summary

Keep this issue open. Current main still applies `dmScope` only to direct peers and keeps group/channel peers in isolated keys; the linked open PR is a concrete implementation candidate, but maintainers need to confirm the opt-in trust boundary before any group can share a private main session.

## What This Changes

Add an opt-in session-routing setting that lets selected group chats use an agent’s main session instead of their isolated group session.

## System Context

Inbound channel messages are matched to an agent and converted into a session key before the agent run and outbound reply path use that session’s context. Today direct-message scope can fold into the main session, while group and channel peers retain their own isolated contexts.

## Best Possible Solution

Adopt an explicit per-binding or per-peer allowlist for trusted groups, retain isolated groups as the default, and document a clear privacy warning while proving identical inbound and outbound session selection.

## Risks / Open Questions

- Folding a multi-person group into a main session can expose private direct-message context or cause group participants to steer an agent using context meant for a different trust boundary.
- A global `session.groupScope: "main"` setting could unintentionally fold every configured group; an explicit peer/binding allowlist is safer for the stated selective-use case.
- Inbound and outbound routing, queue serialization, and sandbox/trust handling must use one consistent session decision or replies may be associated with the wrong conversation context.
