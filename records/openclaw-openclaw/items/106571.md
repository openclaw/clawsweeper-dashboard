## Summary

The reported leak mechanism does not apply to supported OpenClaw runtimes: Node exposes `DatabaseSync.isOpen`, so the current cache-hit condition can reuse an open connection rather than reopening it on every state operation.

## What This Changes

Investigate and prevent an alleged shared-state SQLite connection leak attributed to `DatabaseSync.isOpen` being unavailable.

## Best Possible Solution

Keep the runtime-owned `DatabaseSync.isOpen` cache check and investigate further only if a supported OpenClaw and Node version shows measured descriptor growth despite repeated opens of the same pathname.

## Maintainer Decision

Required: false

## Reproduction Assessment

No. The proposed reproduction requires `DatabaseSync.isOpen` to be undefined, but Node has exposed that boolean since 22.15.0 and OpenClaw requires newer Node versions.

## Solution Assessment

No. Adding a second closed-state flag would duplicate the runtime's authoritative connection state without addressing a reproduced defect.
