## Summary

This is a focused fix for a reproducible session-state regression: the edit form previously read only the top-level card session key, while the canonical Workboard resolver also supports execution-owned links. The patch reuses that resolver and adds rendered plus Chromium regression coverage; no discrete correctness or security defect is evident in the patch. It must remain open because the author is a contributor, the PR carries the protected `maintainer` label, and the submitted browser evidence still exercises a mocked Gateway rather than showing after-fix persistence in a real isolated Workboard setup.

## What This Changes

The PR initializes Workboard card editing from the canonical session resolver so title, notes, or priority changes retain execution-owned session links, and adjusts a Control UI recovery-test fixture to avoid load-related flakiness.

## System Context

The Control UI loads Workboard cards from the Gateway and opens an edit dialog whose draft becomes a `workboard.cards.update` request. The Workboard plugin store treats an empty session key as an intentional unlink, so the dialog must preserve the card’s canonical effective session before submitting unrelated edits.
