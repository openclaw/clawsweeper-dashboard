## Summary

Keep open: current main and v2026.6.11 still do not implement Feishu/Lark `thread=true` subagent binding for plain non-topic group chats; support remains limited to DMs and topic-scoped group conversations, and plain-group semantics need a maintainer product decision.

## What This Changes

Request to restore Feishu/Lark `thread=true` subagent session binding for plain group chats so different groups can stay bound to different subagent personas.

## Best Possible Solution

Define the Feishu plain-group binding contract, then implement it in the Feishu plugin conversation resolver, inbound routing, session-binding path, docs, and regression tests while preserving DM and topic behavior.

## Reproduction Assessment

Yes, at source level. Current main still excludes plain Feishu group conversations from the plugin-owned binding grammar and runtime binding route; I did not run a live Feishu/Lark tenant.

## Solution Assessment

Unclear as an implementation choice. Enabling plain groups is plausible, but the maintainable fix needs a maintainer-approved policy for whole-group versus sender-scoped, topic-only, or configured binding semantics.
