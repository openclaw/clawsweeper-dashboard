## Summary

Keep open: current main and v2026.6.11 still exclude plain non-topic Feishu/Lark groups from current-conversation `thread=true` subagent binding, while the related open items cover broader auto-injection, per-user group subagents, or topic-specific repairs rather than this exact binding policy.

## What This Changes

The issue requests restoring Feishu/Lark group-chat `thread=true` subagent binding so plain group conversations can bind to dedicated child sessions instead of only DMs or topic conversations.

## Best Possible Solution

Define the Feishu plain-group current-conversation binding semantics first, then update the Feishu plugin-owned resolver/binding path, docs, and regression coverage while preserving current DM and topic behavior.

## Reproduction Assessment

Yes, at source level. Current main still rejects non-topic Feishu group current-conversation binding and existing tests assert the reported error; I did not run a live Feishu/Lark tenant.

## Solution Assessment

Unclear as an implementation choice. Enabling plain groups mechanically is plausible, but the maintainable fix needs a maintainer-approved policy for whole-group versus sender/topic/static binding semantics.
