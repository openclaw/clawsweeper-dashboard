## Summary

Keep open: current main and v2026.6.11 still support Feishu/Lark current-conversation subagent binding only for direct messages or topic-scoped groups, so the requested plain group-chat `thread=true` binding remains unresolved and needs a maintainer policy decision.

## What This Changes

Request to restore Feishu/Lark plain group-chat `thread=true` subagent binding so different business groups can bind to different subagent personas instead of routing through the main agent.

## Best Possible Solution

Define the Feishu plain-group current-conversation binding contract, then align the plugin-owned resolver/binding path, inbound routing, docs, and regression tests while preserving existing DM and topic behavior.

## Reproduction Assessment

Yes, at source level: current main still returns null for non-topic Feishu chat/group targets in the thread-binding resolver and has a test asserting that error. I did not exercise a live Feishu/Lark tenant.

## Solution Assessment

Unclear as an implementation choice. Enabling plain groups mechanically is plausible, but the maintainable fix needs a maintainer-approved policy for whole-group versus sender/topic/static binding semantics.
