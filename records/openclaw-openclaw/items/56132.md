## Summary

Keep open: current main and v2026.6.11 still reject Feishu/Lark plain group current-conversation subagent binding while docs and tests limit `thread=true` binding to DMs or topic conversations. Existing static group bindings cover part of the per-group persona use case, but not the requested thread-bound subagent session behavior.

## What This Changes

Request to restore Feishu/Lark `sessions_spawn(..., thread: true, mode: "session")` subagent binding for non-topic group chats.

## Best Possible Solution

Define the Feishu plain-group thread-binding contract, keep static group `bindings` as today’s supported workaround, then implement the plugin-owned resolver/binding/docs/tests without regressing DM or topic behavior.

## Reproduction Assessment

Yes, at source level. Current main rejects non-topic Feishu group current-conversation binding and the existing regression test asserts the reported error; I did not run a live Feishu/Lark tenant.

## Solution Assessment

Unclear as an implementation choice. Restoring `thread=true` mechanically is plausible, but the maintainable fix needs a maintainer-approved policy for whole-group versus sender/topic/static binding semantics, especially because static group `bindings` already cover part of the persona use case.
