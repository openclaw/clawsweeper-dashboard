## Label Justifications

- `P2`: Remote reranker support is a normal-priority memory-search improvement with real user demand but no urgent regression, data loss, or runtime outage.
- `impact:session-state`: Changing memory reranking changes which memory snippets reach agent context and can affect session behavior.
- `impact:security`: The requested endpoint support would add remote network and credential handling around memory-search data.

## Summary

Keep open: current main and the latest release still lack remote reranker endpoint support or a generic rerank-provider hook, and the issue is paired with open implementation/API-direction work that needs maintainer product and security review before closure.

## What This Changes

Add support for external Cohere-style reranker endpoints so memory search can use self-hosted or hosted reranker services instead of only local reranking paths.

## Best Possible Solution

Keep this issue as the concrete user-demand anchor, then land or reject a maintainer-approved plugin/API path, preferably a generic rerank-provider seam with a separately distributed endpoint plugin and explicit security docs.
