## Summary

This PR still targets the open dynamic-TTS delivery bug rather than work already present on current `main`. The implementation is a plausible narrow repair, but the contributor’s own current-head statement confirms that exact-head live Telegram proof is still absent, and the new trusted-media bypass needs owner approval before merge because it deliberately crosses `message_tool_only` suppression.

## What This Changes

The branch keeps message-tool transcript mirrors text-only, creates a separate media-only payload for trusted locally generated TTS audio, and permits that stripped payload to reach channel dispatch in `message_tool_only` flows.

## System Context

Dynamic TTS produces a local audio artifact that becomes an outbound reply payload during an agent run. The reply dispatcher normally suppresses automatic source replies in `message_tool_only` rooms, then hands eligible media payloads to the channel adapter for delivery.

## Best Possible Solution

Keep transcript mirrors and ordinary source replies suppressed, allow only auditable TTS-origin media through a text-free payload, then obtain redacted exact-head Telegram proof and explicit owner approval for that narrow trust boundary before merge.
