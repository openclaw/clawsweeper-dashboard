## Summary

Keep open. The requested presentation capability remains distinct from the closed, unmerged implementation attempt, and choosing a stable configuration owner, precedence, and portable channel semantics requires maintainer product direction before a safe implementation can begin.

## What This Changes

Add a configurable format for user-visible reasoning blocks, with a possible agent-default and/or per-channel override for styles such as italic, code, spoiler, or blockquote.

## Best Possible Solution

Define one portable reasoning-presentation contract with italic as the compatibility default, explicit agent-versus-channel precedence, documented channel fallbacks, and end-to-end coverage for the shared subscription/runner and Telegram reasoning lanes before adding configuration.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should visible reasoning formatting be a shared agent presentation setting with optional channel overrides, or should each channel own its display policy through a portable presentation contract?

Rationale: The formatter is shared across agent output paths, but styles such as spoilers and blockquotes have channel-specific support and escaping behavior; code alone cannot choose the durable public configuration and fallback contract.

Likely owner: steipete

Owner reason: The shared reasoning projection and agent-output paths are central to the configuration boundary being chosen.

Owner confidence: high

Options:

- **Shared contract plus channel overrides (recommended):** Define a portable agent-level default and allow channel plugins to override only supported presentation styles with documented fallbacks.
- **Agent-level setting only:** Expose one cross-channel style vocabulary and map unsupported styles to the compatibility format in channel adapters.
- **Telegram-only policy:** Keep the change inside the Telegram plugin and defer a generic setting until multiple channels need the same capability.

## Reproduction Assessment

No live failure reproduction is needed for this feature request; source evidence shows the shared formatter has a fixed one-argument italic-output contract and no configurable presentation format.

## Solution Assessment

Unclear until maintainers choose the public owner and fallback semantics. The closed unmerged PR demonstrates that adding a schema field alone is not sufficient because the format must traverse every shared reasoning-delivery path.
