## Summary

Keep open for maintainer product direction. Current `main` still hardcodes italic reasoning output and exposes reasoning visibility/level controls but no display-format setting; the prior implementation attempt was closed unmerged and does not supersede this request.

## What This Changes

Add a configurable presentation format for visible thinking/reasoning messages, with possible per-channel or per-agent scope.

## System Context

The embedded agent runtime extracts structured thinking blocks and turns enabled reasoning into a separate user-visible message. Channel adapters, including Telegram, then deliver that formatted text under their own Markdown and streaming constraints.

## Architecture Diagram

flowchart LR
  A[Model thinking blocks] --> B[Embedded agent runtime]
  B --> C[Reasoning visibility policy]
  C --> D[Display-format policy]
  D --> E[Channel adapter]
  E --> F[Visible reasoning message]

## Best Possible Solution

Choose a small portable reasoning-presentation contract with italic as the compatibility default, then implement it at the selected owner boundary with explicit channel capability/fallback rules and coverage for normal, streaming, and Telegram reasoning delivery.

## Maintainer Decision

Kind: product_direction

Question: Should visible reasoning formatting be a shared agent-level presentation policy with channel capability fallbacks, a Telegram/plugin-owned setting, or remain fixed while reasoning visibility alone stays configurable?

Rationale: The answer establishes a new durable config/API boundary, precedence rules, and the expected behavior for channels that cannot faithfully render every proposed format.

Likely owner: steipete

Owner confidence: high

Options:

- **Adopt a portable policy (recommended):** Add a small shared format vocabulary with italic as the default and channel adapters using documented fallbacks for unsupported styles.
- **Keep it channel-owned:** Allow the Telegram plugin to define its own supported presentation setting without adding a cross-channel runtime contract.
- **Defer the setting:** Keep the fixed presentation and rely on the existing reasoning visibility controls until broader channel presentation policy is prioritized.
