## Summary

Current main and v2026.6.11 improve Telegram’s reasoning header but still provide no selectable reasoning presentation; the only direct implementation PR closed unmerged, and the public configuration and ownership choices require maintainer direction.

## What This Changes

Add configurable reasoning-message presentation, such as italic, code, spoiler, or blockquote, at a per-channel or agent-wide scope.

## Best Possible Solution

Define a small typed reasoning-presentation contract with the current style as the compatibility default, resolve clear channel-versus-agent precedence, and let each channel adapter map only supported presentation modes across durable replies and streaming previews.

Question: Should reasoning presentation become a public configurable contract, and should its canonical ownership be portable agent-level presentation with channel overrides or Telegram-only configuration?

Rationale: The source gap is clear, but repository policy sets a high bar for new configuration and current architecture deliberately splits raw reasoning from channel-edge presentation.

Likely owner: steipete

Owner reason: They introduced the existing italic contract, led the current agent-runtime ownership refactor, and have already provided direction on this issue.

Owner confidence: high

Options:

- **Portable contract with overrides (recommended):** Define a small core presentation enum and allow channel-owned overrides or capability mapping while preserving the current default.
- **Telegram-only configuration:** Keep the shared formatter unchanged and expose only Telegram-supported presentation modes in the Telegram plugin config.
- **Choose one improved default:** Avoid new configuration and replace the fixed italic presentation with one more readable portable default across supported channels.

## Reproduction Assessment

Yes, at the source level. Current main has a one-argument fixed-italic formatter, Telegram preserves that italic body, and no reasoning presentation setting appears in the relevant config or docs.

## Solution Assessment

No, not exactly as proposed. Passing raw Markdown format names through agent defaults would blur channel ownership; a typed portable presentation contract with channel capability mapping is the narrower maintainable design.
