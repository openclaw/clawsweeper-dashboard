## What This Changes

Add a configurable display format for visible assistant reasoning blocks, including channel-specific rendering where appropriate.

## System Context

OpenClaw projects model reasoning into embedded-agent payloads and then sends the formatted text through channel adapters such as Telegram. A display-format choice would need to travel from canonical configuration through shared reasoning projection and into channel-capability-aware rendering.

## Architecture Diagram

flowchart LR
  A[Model reasoning events] --> B[Embedded agent projection]
  E[Agent and channel configuration] --> B
  B --> C[Reasoning formatter]
  C --> D[Channel delivery adapters]
  D --> F[Telegram and other clients]

## Best Possible Solution

Choose one small, documented reasoning-presentation contract with explicit precedence and unsupported-channel fallback, preserve italic as the upgrade-safe default, then thread it through every shared and Telegram reasoning delivery path with focused regression coverage.
