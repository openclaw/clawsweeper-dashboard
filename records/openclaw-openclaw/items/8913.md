## Label Justifications

- `P3`: This is a non-blocking presentation and ergonomics feature with limited user impact and no regression in an established configurable contract.
- `impact:ux-friction`: Long italic reasoning messages are harder to read on Telegram, creating avoidable user-facing friction without blocking message delivery.

## Summary

Keep open: current main and v2026.6.11 still expose only fixed italic reasoning presentation, while the remaining configuration ownership, precedence, and cross-channel semantics require maintainer product direction.

## What This Changes

Add configurable reasoning-block presentation, such as italic, code, spoiler, or blockquote, with per-channel or per-agent selection.

## Best Possible Solution

Define one typed reasoning-presentation contract with italic as the compatibility default, let capable channel plugins map supported styles, document a minimal precedence rule, and cover payload, streaming, message-end, and Telegram lanes with focused tests and live Telegram proof.

Yes at source level: current main deterministically formats visible reasoning as per-line italics and exposes no alternative style setting; no live Telegram run was needed to establish that limitation.

## Solution Assessment

Unclear: the readability goal is valid, but directly adding `thinkingFormat` under agent defaults or Telegram config is not yet proven to be the narrowest maintainable boundary; a typed portable presentation contract is safer than propagating raw markup policy.
