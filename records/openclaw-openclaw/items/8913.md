## Summary

Keep open: current main and v2026.6.11 still use fixed italic reasoning presentation, while the requested configuration owner, precedence, supported styles, and cross-channel fallback semantics require maintainer product direction.

## What This Changes

Requests configurable reasoning-block presentation per channel or agent instead of fixed italic formatting.

## Best Possible Solution

Define one typed reasoning-presentation contract with italic as the compatibility default, documented agent-versus-channel precedence, and channel-owned capability fallbacks, then thread it through all isReasoning rendering paths with schema, docs, and regression coverage.

- **Retain fixed rendering:** Keep the current italic presentation and avoid adding another configuration surface.

## Solution Assessment

Not yet: adding an isolated format string would leave ownership and fallback behavior ambiguous; the narrowest maintainable solution is a typed contract selected by maintainers and rendered by each channel according to its capabilities.
