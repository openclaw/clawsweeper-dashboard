## Summary

Keep open. Current main and the latest release still hardcode visible reasoning as a fixed `Thinking` message with italic-wrapped lines, and the only matching implementation attempt is closed unmerged after review found incomplete threading.

## What This Changes

The issue requests configurable per-channel or per-agent formatting for visible thinking/reasoning blocks, especially Telegram alternatives to italic markdown.

## Best Possible Solution

Define one small reasoning display-format contract with italic as the compatibility default, document precedence, and thread it through shared agent delivery plus Telegram-owned rendering with focused regression tests.

## Reproduction Assessment

Yes. Source-level reproduction is high confidence: current main and v2026.6.11 still have fixed italic-line reasoning display and no reasoning display-format config key; this is a feature gap rather than a failing runtime bug.

## Solution Assessment

No, not as a formatter-only option. The maintainable solution is a deliberate config/display contract threaded through shared delivery, Telegram rendering, docs, schema/types, and tests.
