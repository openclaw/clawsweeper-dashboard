## Summary

Keep open: current main and v2026.6.11 still parse custom-scheme origins through `URL.origin`, which serializes as `null`, so exact `gateway.controlUi.allowedOrigins` entries do not match. The remaining fix path is already owned by open linked PRs https://github.com/openclaw/openclaw/pull/73511 and https://github.com/openclaw/openclaw/pull/94132.

## What This Changes

The issue reports that exact `gateway.controlUi.allowedOrigins` entries for custom desktop-app schemes such as `tauri://localhost` and `electron://localhost` are rejected, forcing wildcard origin workarounds.

## Best Possible Solution

Land one narrow origin-check fix that preserves exact custom-scheme origins with focused allow/reject coverage while keeping literal `Origin: null`, malformed origins, unlisted custom origins, and existing fallback behavior unchanged.
