## Summary

Keep open: current main and v2026.6.11 still compare exact custom-scheme allowlist entries against `URL.origin`, which is `null` for the reported schemes, and open linked fix PRs already own the narrow path.

## What This Changes

This issue asks Gateway browser-origin allowlisting to accept exact custom URL scheme origins such as `tauri://localhost` and `electron://localhost` without requiring `allowedOrigins: ["*"]`.

## Best Possible Solution

Land one narrow security-reviewed exact-origin parser fix that preserves standard `URL.origin` behavior, accepts hosted custom-scheme origins only when explicitly listed, and keeps literal `Origin: null`, malformed, hostless, and unlisted origins rejected.
