## Summary

Keep open: current main and the latest release still compare exact custom-scheme allowlist entries against `URL.origin`, which is `null` for the reported schemes, and two open linked PRs already own the narrow fix path.

## What This Changes

The issue reports that exact `gateway.controlUi.allowedOrigins` entries such as `tauri://localhost` and `electron://localhost` are rejected because custom-scheme origins collapse to an opaque `null` origin.

## Best Possible Solution

Land one narrow security-reviewed exact-origin parser fix that preserves standard `URL.origin` behavior, accepts hosted custom-scheme origins only when explicitly listed, and keeps literal `Origin: null`, malformed, hostless, and unlisted origins rejected.
