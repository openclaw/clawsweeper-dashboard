## Summary

Keep open: current main and the latest release still reject exact custom-scheme origins because allowlist matching uses `URL.origin`, and open linked PRs already target the narrow Gateway origin-security fix.

## What This Changes

The issue asks for exact `gateway.controlUi.allowedOrigins` entries such as `tauri://localhost` and `electron://localhost` to match custom-scheme browser `Origin` headers instead of requiring `*`.

## Best Possible Solution

Land one narrow security-reviewed exact-origin parser fix that preserves standard web-origin behavior, accepts hosted custom schemes only when explicitly listed, and keeps literal `Origin: null`, malformed, hostless, and unlisted origins rejected.
