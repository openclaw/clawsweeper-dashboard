## Label Justifications

- `P1`: The PR changes an active inbound SMS path in a way that can permanently suppress valid user messages during ordinary quota exhaustion.
- `merge-risk: 🚨 compatibility`: Existing SMS deployments would observe a provider-visible success response where current main reports an overload failure.

## Summary

Keep this PR open, but do not merge the current response contract: HTTP 200 tells Twilio that an inbound message was accepted even though OpenClaw intentionally discards it, replacing a visible delivery failure with permanent message loss. The focused tests establish the branch behavior, but an SMS owner must choose the overload acceptance contract and the contributor must provide exact-head live proof after revising it.

## What This Changes

Changes signature-validated Twilio SMS callbacks above the dispatch quota from HTTP 429 to HTTP 200 with empty TwiML while logging the message SID and skipping dispatch and replay-cache insertion.

## Best Possible Solution

Admit validated over-limit callbacks to a bounded durable queue and return 2xx only after successful admission; when admission is unavailable, preserve an explicit non-2xx response so Twilio and operators can observe or route the delivery failure.
