## Summary

Keep open: the PR fixes the observable 429 response, but replaces it with HTTP 200 while deliberately discarding the authenticated message, so Twilio and operators are told the callback succeeded when OpenClaw did not accept it.

Likely related people
- @pgondhi987 — medium confidence; introduced the current post-validation callback quota.
- @clawSean — high confidence; recently contributed merged SMS webhook handling and the current proposal.

## What This Changes

Changes signature-validated Twilio SMS callbacks above the dispatch quota from HTTP 429 to HTTP 200 with empty TwiML while logging the message SID and skipping dispatch and replay-cache insertion.

## Best Possible Solution

Return HTTP 200 only after the validated callback is admitted to a bounded durable processing path; otherwise retain an honest non-2xx response and document Twilio 4xx retry/fallback configuration.
