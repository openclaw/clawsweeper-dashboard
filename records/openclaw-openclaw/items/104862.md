It identifies a real SMS overload problem, but the implementation changes both delivery and abuse-protection contracts without approved semantics, conflicts with the stronger two-budget direction in the related quota PR, and lacks inspectable exact-head behavior proof.

## What This Changes

The branch defers SMS webhook rate-limit rejection until after Twilio validation, acknowledges authenticated over-limit callbacks with HTTP 200 and empty TwiML without dispatching them, and adds focused tests and documentation.

## Best Possible Solution

Use the related PR's separate invalid-traffic and validated-callback budgets, then return success only after a validated callback is accepted for processing; otherwise preserve a Twilio-visible failure path so configured retry or fallback handling remains possible.
