## Summary

Keep open: returning success for a callback that the handler intentionally discards does not solve message loss and removes Twilio's opt-in 4xx retry path. The branch has useful regression coverage, but the webhook acceptance contract still needs owner confirmation and exact-head Twilio proof.

Likely related people
- @pgondhi987 — high confidence; introduced the current post-validation callback quota.
- @clawSean — medium confidence; recently contributed merged SMS ingress handling in the same webhook path.

## What This Changes

Changes signature-validated Twilio SMS callbacks above the dispatch quota from HTTP 429 to HTTP 200 with empty TwiML while logging the message SID and skipping dispatch and replay-cache insertion.

## Best Possible Solution

Return 2xx only after a signature-validated callback is durably accepted for dispatch or a bounded queue; otherwise preserve an explicit retry/failure response, keep unauthenticated traffic fail-closed, and prove accepted, overflow, and recovery behavior against Twilio.
