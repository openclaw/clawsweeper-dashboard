- `merge-risk: 🚨 compatibility`: Existing operators may rely on the documented HTTP 429 rejection and Twilio fallback behavior during overload.

## Summary

This PR should remain open but is not merge-ready: current main deliberately exposes dispatch-quota rejection to Twilio, while the patch reports success for callbacks that OpenClaw neither dispatches nor durably accepts. That still loses the message and additionally suppresses failure and fallback signaling.

## What This Changes

Changes validated Twilio SMS callbacks above the dispatch quota from HTTP 429 rejection to HTTP 200 with empty TwiML while logging and skipping dispatch and replay-cache insertion.

## Best Possible Solution

Return HTTP 2xx only after the validated callback is durably accepted for later processing; until that queue or admission path exists, preserve HTTP 429 and the operator-visible Twilio failure and fallback semantics.
