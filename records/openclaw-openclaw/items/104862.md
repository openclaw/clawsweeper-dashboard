## Label Justifications

- `P1`: The PR changes a real inbound SMS delivery path and can suppress recovery for messages received during quota exhaustion.
- `merge-risk: 🚨 compatibility`: Existing Twilio fallback and retry configurations may stop activating because overloaded callbacks change from failure to success responses.
- `merge-risk: 🚨 message-delivery`: Merging the branch can definitively discard validated inbound messages while telling Twilio that processing succeeded.

## Summary

Keep this PR open, but do not merge its current overload behavior: it reports success for a callback that OpenClaw neither dispatches nor stores, suppressing Twilio’s configured failure handling. The underlying rate-limit problem is valid; an SMS owner must choose a truthful rejection or durable-acceptance design, followed by exact-head runtime proof.

## What This Changes

Changes validated Twilio SMS callbacks above the dispatch quota from HTTP 429 rejection to HTTP 200 with empty TwiML while logging and skipping dispatch and replay-cache insertion.

## Best Possible Solution

Return success only after the callback has been accepted for dispatch or durably queued; otherwise preserve a non-2xx response so Twilio retry overrides and configured fallback handlers remain usable, with focused tests and redacted live overload-and-recovery proof.
