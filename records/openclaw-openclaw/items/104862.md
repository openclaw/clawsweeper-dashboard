## Summary

Keep this PR open but do not merge it as written: the central blocker from prior review remains because it reports success for a callback that OpenClaw deliberately discards, preventing any configured Twilio retry and leaving the message permanently unprocessed.

## What This Changes

Changes validated Twilio SMS callbacks above the dispatch quota from HTTP 429 to HTTP 200 with empty TwiML while logging and skipping dispatch and replay-cache insertion.

## Best Possible Solution

Return 2xx only after dispatch or durable queue acceptance; if OpenClaw cannot take ownership of the callback, preserve an explicit failure response and document the supported Twilio retry policy rather than acknowledging and dropping it.
