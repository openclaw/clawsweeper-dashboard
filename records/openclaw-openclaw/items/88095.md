## Summary

Keep open: current main and v2026.6.11 still route Voice Wake, push-to-talk, and Talk through transcript, wake-word, silence, and provider voice paths with no enrolled-speaker match gate; the FunASR/cam++ comment is useful implementation input, but this remains a product and security design item.

## What This Changes

The issue requests speaker enrollment and speaker-identification filtering for Voice Wake, push-to-talk, and Talk mode so background or unauthorized voices are ignored.

## Best Possible Solution

Define one speaker-gating contract for native and realtime voice input that covers enrollment UX, local state, provider egress, fallback semantics, and plugin/API boundaries before implementation; use the FunASR/cam++ comment as candidate backend input, not as the product contract.
