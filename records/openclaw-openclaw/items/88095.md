## Summary

Keep open: current main and the latest release still run Voice Wake, push-to-talk, and Talk mode through wake-word/transcript or realtime-provider audio paths without an enrolled-speaker match gate. The FunASR/cam++ discussion is useful implementation input, but this feature needs maintainer product and security design before implementation.

## What This Changes

The issue requests enrolled-speaker recognition or diarization for Voice Wake, Push-to-Talk, and Talk mode so OpenClaw can ignore background or unauthorized voices.

## Best Possible Solution

Define a speaker-gating contract for native and realtime voice first, including enrollment UX, SQLite-backed local state, provider-egress policy, thresholds, fallback semantics, and plugin/API ownership, then implement the chosen path with cross-platform proof.
