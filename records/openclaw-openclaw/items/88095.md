## Summary

Keep open: current main still has no enrolled-speaker or voiceprint gate for Voice Wake, push-to-talk, native Talk, or realtime/transcription provider callbacks. The FunASR/cam++ comment is useful prior art, but this is a product and security-boundary design item, not a narrow cleanup close.

## What This Changes

Request speaker enrollment and speaker-identification gating for OpenClaw voice input so only enrolled voices trigger or contribute to voice sessions.

## Best Possible Solution

Define one speaker-gating contract for native and realtime voice input, covering enrollment UX, local sensitive-state ownership, provider egress, fallback semantics, and plugin/API boundaries before implementation.
