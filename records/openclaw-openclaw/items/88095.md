## Summary

Keep open: current main and v2026.6.11 still have wake-word, push-to-talk, and Talk pipelines that accept microphone speech by trigger/hotkey/silence behavior, with no enrolled-speaker match gate. The FunASR/cam++ comment is useful implementation input, but this needs product and security design before code.

## What This Changes

The issue requests enrolled-speaker recognition for OpenClaw voice modes so only the primary user's voice can trigger or affect voice sessions.

## Best Possible Solution

Define a security-reviewed, opt-in speaker-verification contract for native voice input, including owner boundary, storage, thresholds, fallback UX, provider/diarization policy, and focused proof before implementation.
