## Summary

Keep open: current main and the latest release still have wake/PTT/Talk pipelines based on wake words, speech transcripts, realtime audio relay, and silence timing, with no enrolled-speaker match gate. The request is useful and security-relevant, but it needs maintainer product and security design before implementation.

## What This Changes

Request to add enrolled-speaker recognition for Voice Wake, Push-to-Talk, and Talk so background or unauthorized voices are ignored.

## Best Possible Solution

Define a default-off speaker-gating contract for native and Gateway-relay voice input that covers enrollment UX, local state storage/deletion, provider egress consent, threshold/fallback policy, and plugin/API ownership before implementing the smallest approved flow.
