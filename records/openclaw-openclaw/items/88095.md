## Summary

Keep open: current main and v2026.6.11 still route Voice Wake, push-to-talk, and native Talk through platform speech recognition and transcript/wake gates without enrolled-speaker matching. The related custom ASR, native audio, and diarized-segment threads are useful input, but they do not replace the product/security decision for speaker enrollment, voice-profile storage, provider egress, and fallback policy.

## What This Changes

Add speaker enrollment and speaker-recognition gating so Voice Wake, push-to-talk, and Talk mode act only on enrolled voices while suppressing background speakers.

## Best Possible Solution

Define one speaker-gating contract for native voice input that covers enrollment UX, local state ownership, provider egress, fallback semantics, and plugin/API boundaries before implementation.
