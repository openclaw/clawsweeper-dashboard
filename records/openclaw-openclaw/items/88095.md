## Summary

Keep open: current main and v2026.6.11 still run Voice Wake, push-to-talk, and native Talk through transcript/wake-word or provider VAD paths with no enrolled-speaker verification gate. The FunASR/cam++ comment is useful implementation input, but the remaining work needs product and security design around voice enrollment, biometric state, thresholds, fallback, provider diarization, and native app ownership.

## What This Changes

The issue requests opt-in enrolled-speaker recognition for Voice Wake, push-to-talk, and Talk mode so non-primary voices do not trigger or contaminate voice sessions.

## Best Possible Solution

Define an opt-in speaker verification boundary that is local-by-default, stores enrolled profiles through the approved state/security model, gates voice segments before wake/send decisions, and documents provider diarization, fallback, and multi-user policy before code lands.
