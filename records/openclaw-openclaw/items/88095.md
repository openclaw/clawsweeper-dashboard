## Summary

Keep open: current main and the latest release still route Voice Wake, push-to-talk, and Talk through transcript, wake-word, silence, or provider VAD paths without an enrolled-speaker gate. The request is useful but security- and product-sensitive, so it should not be converted into an automated fix PR without a maintainer-owned design.

## What This Changes

Add opt-in speaker recognition for Voice Wake, push-to-talk, and Talk so enrolled voices can trigger or contribute to voice sessions while other speakers are suppressed.

## Best Possible Solution

Define a single opt-in speaker-gating contract covering enrollment UX, local state ownership, provider egress, fallback semantics, and plugin/API boundaries before adding runtime behavior.
