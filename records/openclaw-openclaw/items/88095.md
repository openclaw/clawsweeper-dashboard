## Summary

Keep open: current main still has transcript, wake-word, and realtime-provider voice pipelines with no enrolled-speaker matching gate. The FunASR/cam++ comment is useful implementation input, but this needs maintainer product and security design before code because it introduces biometric-like local state, probabilistic voice authorization, provider egress choices, and new config/settings surface.

## What This Changes

Request speaker enrollment and speaker-identification gating for Voice Wake, push-to-talk, and Talk so only an enrolled user's speech triggers or contaminates voice sessions.

## Best Possible Solution

Define one speaker-gating contract across native and realtime voice input, with enrollment UX, secure local state ownership, provider egress rules, fallback semantics, and plugin/API boundaries settled before implementation.
