## Summary

Current main partially handles credential freshness through per-run embedded auth resolution and reusable CLI auth epochs, but it still lacks a global, context-preserving refresh across runtime owners; this remains useful canonical product work requiring maintainer direction.

## What This Changes

Add a global mechanism to refresh provider authentication across active sessions without losing conversation context.

## Best Possible Solution

Keep per-run embedded auth resolution and CLI auth epochs, then add a generic runtime-owner refresh contract that preserves session IDs and transcripts, exposing an operator-admin trigger only with agent/provider filters and defined active-run semantics.

Rationale: Current main has distinct embedded, CLI, ACP, and plugin runtime owners with different refresh behavior; source cannot safely choose the host-wide authorization, filtering, and interruption policy.

Owner confidence: high

Options:

- **Scoped owner refresh RPC (recommended):** Add a generic operator-admin refresh with agent/provider filters and runtime-owner hooks, preserving session and transcript state while defining active-run behavior.
- **Automatic mutation notifications:** Have auth and config mutation flows notify affected runtime owners directly without exposing a general all-session RPC.
- **Document current behavior:** Keep per-run refresh, CLI epochs, and manual session operations without promising an atomic global switch.

## Reproduction Assessment

Yes at the source level: exact current main has runtime-specific auth refresh but no public global auth-only operation. A live multi-runtime switch remains implementation proof rather than a blocker to identifying the capability gap.

## Solution Assessment

No, invoking hard session reset globally is not the best solution because it conflates credential invalidation with session lifecycle; a scoped runtime-owner refresh is narrower and safer.
