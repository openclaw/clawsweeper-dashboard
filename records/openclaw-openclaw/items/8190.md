## Summary

Keep open. Current main still offers only keyed hard reset and keyed soft CLI-binding cleanup; it has no global, context-preserving auth refresh. The capability remains useful, but its authorization and lifecycle semantics require maintainer direction.

## What This Changes

Add an operator-controlled way to refresh authentication across active sessions without discarding their conversation context.

## Best Possible Solution

Add one additive, admin-only session lifecycle operation that enumerates canonical stores, refreshes auth-dependent runtime bindings at safe turn boundaries, preserves session IDs and transcripts, respects explicit auth pins, and returns per-session outcomes.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support an admin-only global auth refresh, and if so should it override explicit session auth-profile pins and interrupt active runs or defer them until the next safe turn boundary?

Rationale: Current code separates durable auth pins, CLI auth epochs, active-run admission, credential resolution, and destructive reset behavior; their precedence and security semantics cannot be selected mechanically.

Likely owner: steipete

Owner reason: The strongest available history and prior review connect this person to Gateway reset and session lifecycle decisions.

Owner confidence: high

Options:

- **Safe-boundary global refresh (recommended):** Refresh unpinned idle sessions immediately, defer active sessions, preserve identity and transcripts, and report pinned or failed sessions.
- **Destructive reset-all:** Expose a clearly destructive admin operation that rotates every session and accepts runtime and context discontinuity.
- **Keep per-session controls:** Decline a global operation and document credential reload plus per-session soft reset as the supported model.

## Reproduction Assessment

Yes at source level: current main has only keyed hard-reset and keyed soft-reset paths, so there is no global context-preserving auth refresh to invoke. A live multi-channel credential-switch scenario was not run.

## Solution Assessment

No, broadly invoking the existing reset service is not the best solution because it rotates session identity and clears runtime continuity. A narrow refresh of auth-dependent bindings at safe turn boundaries is the more maintainable design.
