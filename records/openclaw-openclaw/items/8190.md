## Summary

Keep open as the canonical tracker: current main refreshes auth at individual turn/runtime boundaries but still lacks an operator-authorized, context-preserving refresh across active sessions, and the related open issues cover narrower defects rather than superseding this product decision.

## What This Changes

Add a global auth refresh for active sessions after provider or credential switches without losing conversation context.

## Best Possible Solution

Add an operator-admin auth-refresh method that enumerates affected session stores, invalidates automatic runtime bindings and stale auth epochs at a safe turn boundary, preserves OpenClaw session ids/transcripts and explicit user pins by default, and reports skipped pinned or active sessions.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should global auth refresh preserve explicit per-session user-selected profiles and wait for safe turn boundaries, or forcibly move every active session to the newly selected credentials?

Rationale: Current main deliberately preserves explicit auth pins and active-run lifecycle ownership, so automation cannot safely decide which of those security and state contracts a global operation may override.

Likely owner: steipete

Owner reason: He has the strongest current-main history across the Gateway session reset and auth lifecycle surfaces and has already participated in this issue's product review.

Owner confidence: high

Options:

- **Preserve pins and defer runs (recommended):** Refresh automatic bindings at the next safe turn boundary while leaving explicit user-selected profiles unchanged and reporting skipped sessions.
- **Force every session immediately:** Override explicit pins and interrupt active runs so all sessions adopt the newly selected credentials at once.
- **Keep targeted controls only:** Decline a bulk mutation and instead improve diagnostics and per-session recovery for stale or pinned auth state.

## Reproduction Assessment

Yes, at source level with high confidence. Current main exposes only keyed hard reset plus per-turn and runtime-specific auth resolution; no global, context-preserving operator refresh exists.

## Solution Assessment

No, a global hard reset is not the best solution because it replaces session lifecycle state. The narrower maintainable approach is auth-only invalidation integrated with existing session override, auth-epoch, and active-run ownership contracts.
