## Summary

Keep open: current main still has single-session reset plus per-session CLI/auth invalidation, but no global, context-preserving auth refresh across active sessions. The related provider-switch and auth-migration reports overlap but do not supersede this broader Gateway/session lifecycle design.

## What This Changes

Request a global Gateway/session auth-refresh or reset action that invalidates stale auth across active sessions while preserving conversation context after provider or API-key switches.

## Best Possible Solution

Design an additive, maintainer-approved Gateway/session auth-refresh contract that enumerates active sessions, invalidates stale auth-owned runtime state, preserves context and user-owned selections, and documents admin/security semantics.

## Reproduction Assessment

Yes, at source level: current main exposes single-key sessions.reset and per-session CLI auth invalidation, while no global auth-refresh/reset method exists. I did not run a live multi-channel auth-switch scenario in this read-only review.

## Solution Assessment

Unclear as a final implementation: a global Gateway action is plausible, but maintainers need to define admin scope, preservation rules, and stale-auth versus intentional pin semantics before a safe fix lands.
