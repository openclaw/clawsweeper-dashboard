## Summary

Current documentation still exposes only keyed session maintenance and describes reset as creating a new session ID, while auth/profile selection remains persisted per session. The requested cross-session, context-preserving credential refresh remains necessary and requires explicit product and authorization design.

## What This Changes

Add a global, context-preserving session auth refresh so active sessions adopt current credentials or provider routing without manual per-session resets.

## Best Possible Solution

Add one admin-scoped Gateway operation that refreshes inherited auth/runtime bindings across agent session stores without rotating session IDs or transcripts, preserves explicit user auth pins unless requested, safely handles active runs, and returns a dry-run/reportable per-session result.

## Solution Assessment

No, a global hard reset is not the best fix because it changes session identity and risks context loss. The narrow maintainable direction is an authorized auth-binding refresh that preserves transcripts and explicit user pins and defines active-run behavior.
