## Summary

Keep open: current main and v2026.6.11 still expose single-session reset and per-session auth invalidation, but not a global, context-preserving active-session auth refresh for auth/provider switches.

## What This Changes

The issue requests a gateway-level global auth/session refresh or reset for provider/auth switches that preserves active session context instead of requiring per-channel `/reset`.

## Best Possible Solution

Design an additive, maintainer-approved Gateway/session auth-refresh contract that enumerates active sessions, invalidates stale auth-backed runtime state, preserves intended context and user selections, and documents admin/security semantics.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 expose single-key sessions.reset plus per-session CLI auth invalidation, but no global context-preserving auth refresh method. I did not run a live multi-channel auth-switch scenario in this read-only review.

## Solution Assessment

Unclear as a final implementation: a global Gateway action is plausible, but maintainers need to define admin scope, preservation rules, auth-epoch invalidation, and stale-auth versus intentional pin semantics before a safe fix lands.
