## Summary

The requested all-session, context-preserving auth refresh is a new gateway/session lifecycle capability, and the available evidence does not establish that current main now provides an equivalent global operation; its authorization, scope, and preservation contract need maintainer direction.

## What This Changes

Add a global auth-switch operation that refreshes active sessions without losing their conversation context.

## System Context

OpenClaw sessions bind channel conversations to agent runtime state and provider authentication. Gateway and chat reset paths currently control individual sessions; the requested capability would coordinate an auth refresh across active sessions after configuration changes.

## Architecture Diagram

flowchart LR

  B --> C[Global session refresh decision]
  C --> D[Active channel sessions]
  D --> E[Refresh runtime auth bindings]
  E --> F[Preserved conversation context]
  F --> G[Next user message uses new auth]

## Best Possible Solution

Design an additive, administrator-authorized global auth-refresh contract that preserves canonical session identity and transcript context while invalidating only authentication-backed runtime bindings; then implement it with gateway, session-store, channel, and documentation coverage.
