## Summary

Keep open. This remains a core gateway/session lifecycle feature: the prior review found only single-session reset paths, while the requested global auth refresh must preserve session context and define authorization and upgrade behavior. The related closed auth-switch issues do not establish that capability.

## What This Changes

Add a global way to refresh active sessions after an auth or provider switch without forcing users to reset each channel session or lose its conversation context.

## System Context

OpenClaw’s Gateway owns channel routing and session lifecycle. Auth and provider configuration feed agent runs through those sessions, so a global refresh would need to update live session bindings while retaining each session’s transcript and context.

## Architecture Diagram

flowchart LR
  A[Auth or provider change] --> B[Gateway configuration]
  B --> C[Global session refresh action]
  C --> D[Active channel sessions]
  D --> E[Refreshed auth bindings]
  D --> F[Preserved session context]
  E --> G[Next agent run]
  F --> G

## Best Possible Solution

Design an additive Gateway-owned refresh operation that invalidates auth-derived runtime bindings across a defined set of active sessions while retaining canonical session IDs, transcripts, and context, then cover authorization, provider precedence, and upgrade behavior with focused tests and docs.
