## What This Changes

Add a global, context-preserving session auth refresh when provider credentials or accounts switch.

## Best Possible Solution

Add an additive, admin-scoped sessions.refreshAuth-style operation that enumerates affected session stores, invalidates auth-backed runtime and CLI bindings, preserves canonical session IDs and transcripts, and specifies deterministic in-flight-run behavior.

Question: When an administrator switches credentials, should global auth refresh let in-flight turns finish with their original credential snapshot or cancel them before recreating every affected binding?

Rationale: Source inspection proves the capability is missing, but repository behavior cannot determine the intended credential cutoff and disruption boundary across active agents and channels.

Likely owner: steipete

Owner reason: The strongest history and discussion signals are in the Gateway/session lifecycle work and the prior review of this exact boundary.

Owner confidence: high

Options:

- **Refresh idle bindings (recommended):** Refresh idle bindings immediately while preserving session records, and allow already-running turns to finish with their original credential snapshot.
- **Cancel and refresh all:** Cancel all affected runs before recreating bindings, enforcing an immediate credential cutoff at the cost of greater disruption.
- **Keep per-session control:** Decline a global operation and retain explicit refresh or reset of each individual session.

## Reproduction Assessment

Yes at source level: current main deterministically exposes only a keyed destructive reset, not a global auth-only refresh. This read-only review did not run a live multi-channel credential-switch scenario.

## Solution Assessment

No, applying the existing hard reset globally is not the best solution because it tears down lifecycle state. A narrow auth-binding refresh that preserves session records and defines run-boundary semantics is the maintainable path.
