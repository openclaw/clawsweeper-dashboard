## Summary

Keep open: current main and v2026.6.11 still expose single-session reset plus per-session auth/CLI invalidation, not a global, context-preserving auth refresh across active sessions. The related issues cover narrower account switching, stale Windows provider switching, or auth-profile migration and do not supersede this broader Gateway/session lifecycle request.

## What This Changes

The issue requests a global auth-switch/session-refresh capability that invalidates cached session auth across active channels while preserving conversation context.

## Best Possible Solution

Keep this open as the canonical core design item for an additive Gateway/session auth-refresh contract that enumerates active sessions, invalidates stale auth-backed runtime state, preserves intended context and user selections, and documents admin/security semantics.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 have single-key sessions.reset plus per-session auth/CLI invalidation, but no global context-preserving auth refresh method. I did not run a live multi-channel auth-switch scenario in this read-only pass.

## Solution Assessment

Unclear as a final implementation: a global Gateway refresh capability is plausible, but a hard reset-all implementation would be the wrong shape if it loses transcripts or intentional pins. Maintainers should first define admin scope, preservation rules, and stale-auth versus intentional selection semantics.
