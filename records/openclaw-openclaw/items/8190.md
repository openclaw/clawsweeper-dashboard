## Summary

Keep open: current main and v2026.6.11 still only expose single-session reset plus per-session auth invalidation, so the requested global, context-preserving auth refresh remains unsolved and needs maintainer product/security design.

## What This Changes

The issue requests a global auth-switch/session-refresh action that updates active sessions to current credentials while preserving conversation context across channels.

## Best Possible Solution

Design an additive, admin-scoped Gateway/session auth-refresh contract that enumerates active sessions, invalidates stale auth-backed runtime state, preserves intended context and user selections, and documents security semantics.

## Solution Assessment

Unclear as a final implementation until maintainers choose the contract. A new admin-scoped auth-refresh capability looks safer than broad use of the existing hard reset service, because the current reset rolls session identity and transcript files.
