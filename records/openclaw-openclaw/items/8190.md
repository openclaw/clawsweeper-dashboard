## Summary

Keep open: current main has single-session reset plus per-session auth/CLI invalidation safeguards, but no global, context-preserving auth refresh across active sessions. Related provider-switch and auth-profile reports overlap, but none supersedes this broader Gateway/session lifecycle design.

## What This Changes

The issue requests a global Gateway/session action that refreshes or resets auth-backed session state after provider/API-key switches while preserving conversation context across active channels.

## Best Possible Solution

Design a maintainer-approved additive Gateway/session auth-refresh contract that enumerates active sessions, invalidates stale auth-owned runtime state, preserves context and intentional selections, and documents admin/security semantics.

## Reproduction Assessment

Yes, at source level: current main exposes single-key sessions.reset and per-session CLI auth invalidation, while no global auth-refresh/reset method exists. I did not run a live multi-channel auth-switch scenario in this read-only review.

## Solution Assessment

Unclear as a final implementation: a global Gateway action is plausible, but maintainers need to define admin scope, preservation rules, and stale-auth versus intentional-pin semantics before a safe fix lands.
