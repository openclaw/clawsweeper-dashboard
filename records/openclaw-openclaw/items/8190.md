## Summary

Keep open: current main and v2026.6.11 still expose only single-session reset plus per-session CLI auth invalidation, not a global, context-preserving auth refresh across active sessions. The related provider-switch and auth-migration items overlap, but none supersedes this broader Gateway/session lifecycle request.

## What This Changes

Request for a Gateway-level global session auth reset/refresh that invalidates stale auth after provider or API-key switches while preserving conversation context.

## Best Possible Solution

Design an additive, maintainer-approved Gateway/session auth-refresh contract that enumerates active sessions, invalidates stale auth-backed runtime state, preserves intended context and user selections, and documents admin/security semantics.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 expose only single-key sessions.reset plus per-session CLI auth invalidation, and no global auth-refresh/reset method exists. I did not run a live multi-channel auth-switch scenario in this read-only pass.

## Solution Assessment

Unclear as a final implementation: a global Gateway action is plausible, but maintainers need to define admin scope, auth-only versus hard-reset semantics, and stale-auth versus intentional pin preservation before a safe fix lands.
