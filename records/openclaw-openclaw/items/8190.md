## Summary

Keep open: current main still has single-session reset plus per-session CLI auth invalidation, but no global, context-preserving auth refresh/reset across active sessions. The related Windows/provider-switch issue overlaps, but does not supersede this broader Gateway/session lifecycle design request.

## What This Changes

The issue requests a global, context-preserving session auth refresh/reset when provider credentials or auth backends change.

## Best Possible Solution

Design an additive, maintainer-approved Gateway/session auth-refresh contract that enumerates active sessions, invalidates stale auth-backed runtime state, preserves intended context and user selections, and documents admin/security semantics.

## Reproduction Assessment

Yes at source level: current main exposes only single-session reset schema/handler and per-session soft CLI binding clearing, while no global auth-refresh method is present. I did not run a live multi-channel auth-switch scenario in this read-only pass.

## Solution Assessment

Unclear as a final implementation: a global Gateway action is plausible, but maintainers need to define admin scope, preservation rules, and stale-auth versus intentional pin semantics before a safe fix lands.
