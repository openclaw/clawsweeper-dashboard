## Summary

Keep open: current main and the latest release still provide single-session reset plus per-session auth invalidation, not a global, context-preserving auth refresh across active sessions. The related issues cover narrower account switching, auth-profile migration, or Windows provider-switch symptoms and do not supersede this broader Gateway/session lifecycle request.

## What This Changes

The issue requests a global, context-preserving session auth refresh/reset when provider credentials or auth backends change.

## Best Possible Solution

Design an additive, maintainer-approved Gateway/session auth-refresh contract that enumerates active sessions, invalidates stale auth-backed runtime state, preserves intended context and user selections, and documents admin/security semantics.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 have single-key sessions.reset plus per-session CLI/auth cleanup, but no global context-preserving auth refresh method. I did not run a live multi-channel auth-switch scenario in this read-only review.

## Solution Assessment

Unclear as a final implementation: a global Gateway action is plausible, but maintainers need to define admin scope, preservation rules, and stale-auth versus intentional pin semantics before a safe fix lands.
