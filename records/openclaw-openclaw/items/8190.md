## Summary

The feature is still necessary: current main and v2026.6.11 pin provider auth per session, expose only a keyed administrative reset, and provide no auth-only all-session refresh. Keep this issue as the canonical product and security-design tracker while narrower credential-freshness and auth-epoch bugs remain separately tracked.

## What This Changes

Add an operator-controlled global refresh of session-pinned authentication after provider or account changes while preserving session identity, transcript, and conversation context.

## Best Possible Solution

Add a distinct `operator.admin` Gateway/session capability that enumerates canonical session stores, clears only auto-selected provider auth pins and reusable auth-bound runtime bindings, preserves session IDs, transcripts, and context, leaves explicit user profile overrides intact unless separately requested, and defines tested graceful or immediate behavior for active runs.

Options:

- **Graceful refresh, preserve overrides (recommended):** Use `operator.admin`, clear automatic auth pins and backend bindings for subsequent runs, allow already-admitted runs to finish, and preserve explicit user-selected profile overrides.
- **Immediate refresh, preserve overrides:** Cancel active runs before clearing automatic auth pins and backend bindings, while retaining explicit user-selected profile overrides.
- **Refresh every auth selection:** Cancel or drain active runs and clear both automatic pins and explicit user overrides, making current global configuration authoritative for every session.

## Reproduction Assessment

Yes at source level. Current main and v2026.6.11 document session-pinned auth profiles, require a single key for `sessions.reset`, and expose no global auth-only refresh; no live multi-provider scenario was run in this read-only review.

## Solution Assessment

The requested outcome is valid, but broad use of `sessions.reset` is not the best implementation because it owns destructive lifecycle-reset behavior. A separate administrative auth-pin and binding refresh, with explicit active-run and user-override policy, is the narrowest maintainable solution.
