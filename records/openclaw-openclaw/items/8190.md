## Summary

Current main still exposes only keyed session reset behavior and does not provide a global, context-preserving credential refresh across active sessions. The issue remains necessary, but the cross-agent authorization boundary, persisted override precedence, and active-run behavior require explicit product and security decisions before implementation.

## What This Changes

Add a global, context-preserving mechanism to refresh active sessions after authentication credentials or providers change.

## Best Possible Solution

Add an explicit administrative auth-refresh capability that enumerates authorized session stores, invalidates only auth-dependent runtime bindings and epochs, preserves session IDs and transcripts, respects explicit persisted overrides, and defines atomic behavior for active runs with focused protocol, lifecycle, and authorization coverage.

Rationale: Source inspection establishes the missing capability, but code alone cannot decide the intended authorization scope, explicit-pin precedence, or whether active runs should finish, cancel, or retry across a credential transition.

Owner confidence: high

Options:

- **Add scoped auth refresh (recommended):** Introduce an additive admin-only refresh operation with explicit agent/session scope, preserved context, override precedence, and defined active-run semantics.
- **Refresh only on new runs:** Keep session state intact but reload credentials only when each session begins its next idle run, avoiding a global immediate transition.
- **Keep manual session control:** Retain keyed reset and per-session override commands rather than adding a cross-session administrative operation.

## Reproduction Assessment

Not applicable as a failure reproduction: this is a new capability request. Current-main source inspection does, however, clearly confirm that only keyed reset behavior exists and that the proposed global auth-refresh operation is absent.

## Solution Assessment

No, a global hard reset is not the best solution because it would roll session identity and context. The narrower maintainable design is an additive auth-only refresh operation built on existing auth-epoch and runtime-binding invalidation concepts, with explicit administrative scope and concurrency rules.
