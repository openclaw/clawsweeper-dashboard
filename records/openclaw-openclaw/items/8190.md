## Summary

Keep open: current main and v2026.6.11 still provide per-session reset/auth invalidation, but not the requested global, context-preserving auth refresh across active sessions.

## What This Changes

The issue requests a global auth-switch action that refreshes or resets all active sessions while preserving conversation context.

## Best Possible Solution

Define an additive, admin-scoped Gateway/session auth-refresh contract that enumerates active sessions, invalidates stale auth-backed runtime state, preserves intended context and user selections, and documents security semantics.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add an admin-scoped all-session auth refresh API, and which session/auth state may it invalidate while preserving context?

Rationale: The code gap is clear, but the safe behavior crosses credential ownership, explicit per-session pins, transcript continuity, Gateway protocol scope, and provider routing policy.

Likely owner: steipete

Owner reason: steipete has the strongest combined history on Gateway reset semantics and auth-driven CLI session invalidation.

Owner confidence: high

Options:

- **Add admin auth refresh contract (recommended):** Define a sessions.refreshAuth-style API with all-sessions scope, explicit stale-state ownership rules, and regression coverage for context preservation and credential invalidation.
- **Fold into provider-switch transaction:** Make provider/auth switching own session refresh as part of one transaction, reducing standalone API surface but coupling the behavior to switch workflows.
- **Keep per-session reset only:** Leave current reset behavior unchanged and document per-session recovery, accepting continued multi-channel auth-switch friction.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 expose single-key sessions.reset plus per-session CLI auth invalidation, but no global context-preserving auth refresh method. I did not run a live multi-channel auth-switch scenario in this read-only review.

## Solution Assessment

Unclear as a final implementation: a global Gateway action is plausible, but maintainers need to define admin scope, preservation rules, auth-epoch invalidation, and stale-auth versus intentional pin semantics before a safe fix lands.
