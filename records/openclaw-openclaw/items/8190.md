## Summary

Keep open: current main and v2026.6.11 still expose only single-session reset plus per-session auth/session invalidation, not a global context-preserving auth refresh across active sessions. Related provider-switch and session-state issues are useful context, but none supersedes this broader Gateway/session lifecycle request.

## What This Changes

Request a global Gateway/session action that refreshes or resets all active session auth caches after auth/provider changes while preserving conversation context.

## Best Possible Solution

Design an additive maintainer-approved Gateway/session auth-refresh contract that enumerates active sessions, invalidates stale auth-backed runtime state, preserves intended context and user selections, and documents admin/security semantics.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 have a single-key sessions.reset schema/handler and per-session CLI auth invalidation, while no global auth-refresh/reset method exists. I did not run a live multi-channel auth-switch scenario in this read-only review.

## Solution Assessment

Unclear as a final implementation: a global Gateway action is plausible, but maintainers need to define admin scope, preservation rules, and stale-auth versus intentional pin semantics before a safe fix lands.
