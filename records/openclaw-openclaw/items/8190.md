## Summary

Keep this issue open: the requested global, context-preserving auth refresh remains a new gateway/session lifecycle capability that needs an explicit maintainer contract for scope, authorization, and compatibility; the related closed auth-migration work does not implement it.

## What This Changes

Requests an authorized global refresh of active sessions after an auth or provider switch while preserving each session’s conversation context.

## Best Possible Solution

Define an additive, admin-authorized auth-refresh lifecycle that invalidates only auth-backed runtime bindings across a deliberate session scope, preserves canonical session IDs/transcripts, reports per-session failures, and has focused Gateway, session-store, and channel coverage.

Question: Should OpenClaw expose a Gateway-level global auth-refresh operation that preserves active session context, and if so what session scope and administrator authorization contract should it use?

Rationale: The existing reset operation is intentionally session-scoped and destructive to session continuity; choosing a global credential-rebind capability determines public protocol semantics, security boundaries, and upgrade behavior.

Likely owner: steipete

Owner confidence: high

Options:

- **Design an additive global refresh (recommended):** Add an admin-scoped auth-refresh operation with explicit all-active or selected-session scope, preserving session identity and transcript state.
- **Keep session refresh manual:** Retain single-session reset behavior and document that auth changes require per-session recovery until a supported lifecycle contract is sponsored.
- **Fold into provider switching:** Make global session refresh part of a future provider-switch transaction rather than exposing a separate Gateway action.
