## Summary

Keep open: current main and v2026.6.11 still expose per-session reset and per-session auth invalidation, but not a global, context-preserving auth refresh across active sessions. The related auth-switching reports overlap, but none supersedes this broader Gateway/session lifecycle request.

## What This Changes

Request a Gateway-level way to refresh or reset all active sessions after auth/provider changes while preserving conversation context.

## Best Possible Solution

Design an additive, maintainer-approved Gateway/session auth-refresh contract that enumerates active sessions, invalidates stale auth-backed runtime state, preserves intended context and explicit user selections, and documents admin/security semantics.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 have single-key sessions.reset plus per-session CLI/auth cleanup, but no global context-preserving auth refresh method. I did not run a live multi-channel auth-switch scenario in this read-only review.

## Solution Assessment

Unclear as a final implementation: a global Gateway action is plausible, but maintainers need to define admin scope, preservation rules, and stale-auth versus intentional pin semantics before a safe fix lands.
