## Summary

Keep open: current main and v2026.6.11 still expose single-session reset plus per-session auth/CLI invalidation, not a global, context-preserving auth refresh across active sessions. Related issues cover narrower credential-rotation or provider-switch symptoms and do not supersede this broader Gateway/session lifecycle request.

## What This Changes

Request a global Gateway/session action that refreshes stale auth across active sessions while preserving session context after provider or credential changes.

## Best Possible Solution

Design an additive admin-scoped Gateway/session auth-refresh contract that enumerates active sessions, invalidates stale auth-backed runtime state, preserves intended context and user selections, and documents security semantics.

## Reproduction Assessment

Yes, at source level: current main has single-key sessions.reset plus per-session CLI/auth cleanup, but no global context-preserving auth refresh method. I did not run a live multi-channel auth-switch scenario in this read-only review.

## Solution Assessment

Unclear as a final implementation: a global Gateway action is plausible, but maintainers need to define admin scope, preservation rules, and stale-auth versus intentional pin semantics before a safe fix lands.
