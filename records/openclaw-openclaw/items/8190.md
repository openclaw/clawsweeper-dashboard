## Summary

Keep open: current main still has single-session reset plus per-session CLI auth invalidation, not a global, context-preserving auth refresh across active sessions. The issue remains a valid core Gateway/session lifecycle feature that needs maintainer product and security design before implementation.

## What This Changes

The issue requests a global, context-preserving session auth refresh/reset when auth backends, provider profiles, or API keys change.

## Best Possible Solution

Design an additive Gateway/session auth-refresh contract that enumerates active sessions, invalidates stale auth-backed runtime state, preserves session ids/transcripts and intentional user pins, and documents admin/security semantics with focused tests.

## Reproduction Assessment

Yes, at source level: current main exposes only single-key sessions.reset and per-session CLI auth invalidation, with no global active-session auth refresh method. I did not run a live multi-channel auth-switch scenario in this read-only review.

## Solution Assessment

Unclear as a final implementation: a global Gateway action is plausible, but maintainers need to define admin scope, preservation rules, and stale-auth versus intentional pin semantics before a safe fix lands.
