## Summary

Keep open: current main and v2026.6.11 still provide single-session reset and per-session auth/profile invalidation, but not the requested global, context-preserving auth refresh across active sessions.

## What This Changes

Request a global, context-preserving session auth refresh/reset for auth backend or API-key switches across active channels.

## Best Possible Solution

Design an additive, admin-scoped Gateway/session auth-refresh contract that enumerates active sessions, invalidates stale auth-backed runtime state, preserves intended context and user selections, and documents security semantics.

Rationale: The implementation gap is clear, but the safe behavior crosses credential ownership, explicit per-session pins, transcript continuity, Gateway protocol scope, provider routing, and security expectations.

Likely owner: steipete

Owner confidence: high

Options:

- **Add Admin Auth Refresh Contract (recommended):** Define a sessions.refreshAuth-style API with all-sessions scope, stale-state ownership rules, authorization semantics, and regression coverage for context preservation and credential invalidation.
- **Fold Into Provider Switch:** Make provider/auth switching own the session refresh as one transaction, reducing standalone API surface but tying the behavior to switch workflows.
- **Keep Per-Session Reset Only:** Leave current reset behavior unchanged and document per-session recovery, accepting continued multi-channel auth-switch friction.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 expose single-key sessions.reset plus per-session CLI auth invalidation, but no global context-preserving auth refresh method. I did not run a live multi-channel auth-switch scenario in this read-only review.

## Solution Assessment

Unclear as a final implementation: a global Gateway action is plausible, but maintainers need to define admin scope, preservation rules, auth-epoch invalidation, and stale-auth versus intentional pin semantics before a safe fix lands.
