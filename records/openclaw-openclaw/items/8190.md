## Summary

Keep open: current main and v2026.6.11 still have single-session reset and per-session CLI auth invalidation, but no global, context-preserving active-session auth refresh for provider or credential switches.

## What This Changes

Request to add a global, context-preserving session auth refresh/reset that can be triggered after auth backend, API key, or provider changes.

## Best Possible Solution

Design an additive Gateway/session auth-refresh contract that enumerates active sessions, invalidates stale auth-owned runtime state, preserves session ids/transcripts and explicit selections, and documents admin/security semantics.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 expose single-key sessions.reset plus per-session CLI auth invalidation, but no global context-preserving auth refresh method. I did not run a live multi-channel auth-switch scenario in this read-only review.

## Solution Assessment

Unclear as a final implementation: a global Gateway action is plausible, but maintainers need to define admin scope, preservation rules, auth-epoch invalidation, and stale-auth versus intentional pin semantics before a safe fix lands.
