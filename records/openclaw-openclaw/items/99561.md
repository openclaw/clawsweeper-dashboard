## Summary

Keep open for maintainer review: current main and the latest release still leave the reported control tools deferred, while this PR implements a focused direct-control mitigation with matching tests and live before/after proof. The remaining blocker is not a code defect; it is maintainer acceptance of the intentional Codex app-server startup tool-surface and session-control contract change.

## What This Changes

The PR makes `agents_list`, `sessions_spawn`, and `sessions_yield` direct Codex app-server dynamic tools while keeping broad OpenClaw tools and `heartbeat_respond` deferred.

## Best Possible Solution

Land the narrow direct-control mitigation if maintainers accept the startup-session control contract; otherwise keep the linked bug open for a tested preflight or fail-loud fallback design.

## Reproduction Assessment

Source-level yes, live-local no: current main still keeps only `sessions_yield` direct, and the linked issue plus PR body provide incident and before/after live evidence for `sessions_spawn` not becoming callable through `tool_search`. I did not rerun the live Codex app-server path in this read-only review.

## Solution Assessment

Yes, if maintainers accept the startup-surface change: keeping only OpenClaw control tools direct is narrower than making the full OpenClaw catalog direct and avoids the misrouted `tool_search` dependency. A preflight or fail-loud fallback remains the safer alternative if maintainers reject direct `sessions_spawn`.
