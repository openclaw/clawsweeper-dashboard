## Summary

Keep this PR open: the added `statSync` preflight does not bound the subsequent path-based `readFileSync`, so a replacement or growth between those operations can still make `openclaw doctor` allocate an unbounded file. It also still needs contributor-supplied real behavior proof of the recovery path.

## What This Changes

The branch adds regular-file, missing-file, and 50 MiB size checks before the SQLite doctor migration reads a legacy session-store JSON file.

## Best Possible Solution

Use a single opened descriptor with a truly byte-bounded read path, classify oversized or changed stores as `store_unreadable`, and cover the replacement/growth case with a focused regression test.
