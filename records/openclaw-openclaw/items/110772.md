## Summary

Keep this PR open: binding the descriptor prevents pathname replacement, but `readFileSync(fd)` can still buffer an arbitrarily enlarged file after `fstatSync(fd)` validates its earlier size. Likely related people: current-main Doctor/session ownership could not be attributed confidently from the available history evidence.

## What This Changes

The PR changes Doctor’s legacy session-store reader to open, validate, and read through one file descriptor, with tests for unreadable, non-regular, and oversized stores.

## Best Possible Solution

Keep the descriptor-bound ownership check, but replace the EOF-based read with an explicitly length-bounded `fs.readSync` loop or equivalent that reads no more than the validated byte count, with regression coverage for post-stat growth.
