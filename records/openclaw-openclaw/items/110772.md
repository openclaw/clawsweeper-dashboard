## Summary

Keep this PR open: the latest head still preflights a pathname and then performs an unbounded `readFileSync` on that pathname, so a replacement or growth between those operations can still make `openclaw doctor` allocate without the intended cap. The PR body provides focused test output, but not an after-fix doctor run proving the recovery path stays non-crashing.

## What This Changes

The branch adds legacy-session-store metadata checks, a 50 MiB size cap, and missing-parent handling before doctor imports legacy session records.

## Best Possible Solution

Open the legacy store once and read through a descriptor with a fixed maximum byte request (including overflow detection), keep all metadata/read failures on `store_unreadable`, then show a redacted `openclaw doctor` run against an oversized fixture.
