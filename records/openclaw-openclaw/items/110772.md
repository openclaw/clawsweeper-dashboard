## Summary

Keep this PR open: the descriptor pins the pathname target but `readFileSync(fd, "utf-8")` can still allocate beyond the 50 MiB limit if the already-open file grows after `fstatSync`. The preceding P1 was not fixed on the current head, and the PR body still provides test output rather than after-fix Doctor behavior proof.

## What This Changes

The branch changes Doctor’s legacy session-store reader to open, stat, and read through one file descriptor, and adds tests for unreadable, non-regular, and oversized stores.

## Best Possible Solution

Keep the descriptor-based pathname protection, but replace the EOF-reading API with an exact-size bounded descriptor read and add focused coverage for the growth/race boundary before obtaining contributor-provided Doctor output.
