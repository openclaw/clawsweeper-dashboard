## Summary

Keep this PR open, but it is not ready to merge: validating an inode with `fstatSync` does not bound a later `readFileSync(fd)` if that same file grows before the read. The supplied terminal output proves ordinary valid and already-oversized files, not the growth-after-validation case the PR claims to fix.

## What This Changes

The branch replaces Doctor’s path-based legacy session-store read with an opened descriptor plus descriptor stat/read flow, and adds unreadable, non-regular, and oversized-store tests.

## Best Possible Solution

Replace EOF-based `readFileSync(fd)` with a descriptor read capped to the validated size (or the 50 MiB maximum), add a deterministic same-inode growth regression test, and post redacted terminal or runtime proof showing the bounded outcome.

Required: false

## Reproduction Assessment

Yes from source: open a store below the cap, append to that same inode after `fstatSync`, and the following EOF-based `readFileSync(fd)` can read beyond the validated size. The supplied evidence does not include that mutation case running against the branch.

## Solution Assessment

No. Using one descriptor removes path replacement, but an EOF read is not bounded by the earlier descriptor size; a fixed-length descriptor read is the narrow maintainable fix.
