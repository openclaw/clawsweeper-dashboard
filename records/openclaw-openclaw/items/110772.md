## Summary

Keep this PR open: the descriptor pins the opened file against pathname substitution, but `fs.readFileSync(fd, "utf-8")` still reads to EOF after a point-in-time `fstat`, so concurrent in-place growth can still allocate beyond the 50 MiB cap. The prior P1 blocker therefore remains; focused test output is helpful but is not real Doctor behavior proof.

## What This Changes

The PR changes Doctor’s legacy session-store reader to open, stat, and read through one file descriptor and adds tests for unreadable, non-regular, and oversized stores.

## Best Possible Solution

Retain descriptor-based opening, but allocate and read no more than the validated size (and the 50 MiB maximum) with descriptor-level bounded reads; then add a regression that simulates growth after metadata inspection and publish a redacted successful Doctor transcript.
