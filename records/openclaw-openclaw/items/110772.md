## Label Justifications

- `P1`: A user-invoked Doctor migration command can hang indefinitely on a FIFO path instead of producing its structured diagnostic.
- `merge-risk: 🚨 availability`: The new synchronous open precedes regular-file validation, so merging can introduce a blocking maintenance-command path for special files.

## Summary

The descriptor-bound read correctly addresses the stat/read substitution and post-stat growth path, but this PR still opens a user-selected path synchronously before it verifies the descriptor is a regular file. A FIFO can therefore block `openclaw doctor` indefinitely instead of producing the intended `store_unreadable` result; the prior P1 remains unfixed on the current head.

## What This Changes

The PR changes Doctor’s legacy session-store migration reader to use an `open`/`fstat`/bounded-read sequence and adds tests for unreadable and non-regular store paths.

## Best Possible Solution

Retain the descriptor-bound, exact-validated-size read, but make the initial open safe for FIFOs and other special paths, then verify the opened descriptor is a regular file before any potentially blocking read and cover that contract with a platform-gated regression test.

## Solution Assessment

No. The descriptor-bound bounded read is the right core direction for the TOCTOU concern, but it must avoid a blocking open before it can reject non-regular files; a nonblocking-safe open plus descriptor validation is the narrower complete fix.
