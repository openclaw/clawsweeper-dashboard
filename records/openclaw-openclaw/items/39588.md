## Summary

Keep open: current main and the latest release still derive the macOS Launch at login toggle from live LaunchAgent state, with no persisted app-owned intent or Sparkle/update-time reconciliation for the reported post-update drift.

## What This Changes

The issue asks for the macOS app's Launch at login setting to remain enabled and functional across app restarts and Sparkle updates.

## Best Possible Solution

Define the macOS app's Launch at login source of truth, then add guarded startup/update reconciliation that preserves explicit in-app enablement without overriding deliberate OS-level disables.
