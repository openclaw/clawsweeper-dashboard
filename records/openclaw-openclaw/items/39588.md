## Summary

Keep open: current main and the latest release shipped a related KeepAlive cleanup, but the remaining update-time stickiness problem is not proven fixed because the app still derives the UI toggle from live launchd state and has no Sparkle/update reconciliation path for the user’s desired launch-at-login setting.

## What This Changes

Make the macOS app Launch at login setting stay enabled and auto-launch reliably across app restarts and Sparkle app updates.

## Best Possible Solution

Define one canonical macOS launch-at-login contract that preserves user intent across Sparkle updates and offers an in-app repair path when launchd or login-item state drifts.
