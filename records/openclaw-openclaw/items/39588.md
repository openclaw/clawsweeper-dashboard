## Summary

Keep open: current main and the latest release still model the macOS Launch at login toggle from live launchd state, without durable user intent or Sparkle/update-time reconciliation. The related merged fixes cover startup-time plist deletion and KeepAlive relaunch behavior, not this update-correlated toggle drift.

## What This Changes

The issue requests that the macOS app's Launch at login setting persist across app restarts and Sparkle app updates instead of appearing to turn itself off.

## Best Possible Solution

Define the macOS app's launch-at-login source of truth, then add guarded startup/update reconciliation for the app-owned LaunchAgent with packaged Sparkle update or launchctl proof.
