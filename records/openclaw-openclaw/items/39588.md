## Summary

Keep open: current main and v2026.6.11 still derive the macOS app toggle from live LaunchAgent state and do not persist/reconcile app-owned enabled intent after updates, so the reported update-related drift is not fixed by the adjacent KeepAlive or gateway LaunchAgent work.

## What This Changes

The issue asks for the macOS app Launch at login setting and `ai.openclaw.mac` LaunchAgent registration to remain enabled and consistent across app restarts and Sparkle updates.

## Best Possible Solution

Define the macOS app Launch at login source of truth, then add guarded startup/update reconciliation for the app-owned LaunchAgent with signed packaged update proof and deliberate-disablement coverage.
