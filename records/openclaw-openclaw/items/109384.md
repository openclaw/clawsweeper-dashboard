## Summary

Keep this PR open for maintainer review: the latest head proves the new stall signal, but it also changes the effective timeout contract for every xAI generated-video download from the configured total budget to a half-budget inter-chunk limit. That can reject slow-but-progressing downloads that previously completed within the configured request timeout, so the permanent threshold needs an explicit compatibility decision before merge.

## What This Changes

The branch replaces the xAI video body-read deadline with a half-request per-chunk idle timeout and adds mocked and real-loopback stalled/dripping-body regressions.

## Best Possible Solution

Retain the configured total download budget for progressing streams and derive any download-owned idle deadline from the remaining guarded deadline with only a narrow, documented margin; add coverage for a slow-but-valid inter-chunk gap as well as a true stall.
