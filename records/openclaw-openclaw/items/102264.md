## Summary

Keep this PR open: the branch is useful and the real-behavior proof is strong, but the current head still has a merge-blocking readiness bug where a failed live `list_apps` probe can be surfaced as `Computer Use: ready` when non-strict startup compatibility is enabled.

## What This Changes

This PR changes the Codex plugin’s Computer Use setup/status path by adding shared plugin-cache reconciliation, live `list_apps` readiness probes, opt-in health and repair settings, strict-readiness config/docs, doctor warnings, sandbox probe narrowing, and window leases.

## Best Possible Solution

Separate live readiness from startup compatibility: status should report not ready on `live_test_failed`, while startup may continue in non-strict mode with an explicit warning.

## Solution Assessment

No. The PR is close, but the best fix is to separate live readiness from startup compatibility instead of overloading the `ready` flag for both meanings.
