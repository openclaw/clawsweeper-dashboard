## Summary

## What This Changes

The PR adds a 30-second transport-neutral WebSocket connection deadline, a nominal 16 MiB inbound-message limit, and mock-based regression tests for the OpenAI ChatGPT Responses provider.

## Best Possible Solution

Measure raw event bytes before decoding where the runtime exposes `byteLength` or `size`, calculate UTF-8 bytes for string events, settle timeout rejection independently of fallible socket closure, and demonstrate both limits with redacted controlled-server output.

Full review comments:

- **[P1] Enforce the payload limit in bytes before decoding:** `packages/ai/src/providers/openai-chatgpt-responses.ts:1254`
  - body: `text.length` counts UTF-16 code units rather than payload bytes, so multibyte UTF-8 messages can exceed the advertised 16 MiB limit and still be parsed. The complete event is also decoded before this check, so it does not provide the claimed allocation bound. Determine raw `byteLength`/Blob `size` before decoding where available and use encoded byte length for string events; add a multibyte regression case.
  - confidence: 0.99
- **[P1] Settle the timeout even when socket closure throws:** `packages/ai/src/providers/openai-chatgpt-responses.ts:1074`
  - body: The deadline callback calls `socket.close()` before `reject()`. A WebSocket implementation may throw while still connecting, which exits the timer callback before the promise is rejected and defeats the new bound. Use the existing silent-close helper or reject in a `finally`, and cover a throwing `close()` implementation.
  - confidence: 0.94
