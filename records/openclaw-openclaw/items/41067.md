## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Gate restart abort cleanup to restart closes:** `src/gateway/server-close.ts:121-142`
  - body: This loop runs for every gateway close and aborts active chat runs while writing gateway-restart interruption notices. Ordinary shutdown should not synthesize restart semantics; current main gates restart drain/abort behavior on restart metadata.
  - confidence: 0.89
- **[P1] Filter active-run snapshots before sending hello:** `src/gateway/server/ws-connection/message-handler.ts:1034-1037`
  - body: The hello payload lists every abort-controller entry. That bypasses current main's filtering for hidden, aborted, inactive, and agent-owned runs, so the UI can recover to the wrong run and ignore the real run's events.
  - confidence: 0.87
- **[P2] Return false when restart transcript injection fails:** `src/gateway/server-restart-sentinel.ts:29-30`
  - body: `injectRestartNoticeIntoSession` can throw while preparing the transcript, but callers only enqueue the fallback system event when it returns `false`. Catch setup/append failures inside the helper so a consumed sentinel notice is not dropped.
  - confidence: 0.86
- **[P2] Pick recovered active runs deterministically:** `ui/src/ui/app-gateway.ts:126-142`
  - body: `resolveActiveChatRunForSession` returns the first matching run for a session. If multiple entries exist, reconnect can recover an older run ID and then drop deltas or finals from the newer run due to run-id mismatch.
  - confidence: 0.82
