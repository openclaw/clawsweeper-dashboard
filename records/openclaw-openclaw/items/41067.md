## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.87

Full review comments:

- **[P1] Gate run aborts to restart closes:** `src/gateway/server-close.ts:125-137`
  - body: This loop runs for every `createGatewayCloseHandler` close, including ordinary gateway stops, and aborts active chat runs with a restart-style transcript notice before checking that the close is actually a restart. Current main keeps restart drain/abort behavior on the restart path; merging this would turn normal shutdown into user-visible aborted runs.
  - confidence: 0.89
- **[P1] Use the filtered active-run contract:** `src/gateway/server/ws-connection/message-handler.ts:100-111`
  - body: `listActiveChatRuns` projects every abort-controller entry into the hello snapshot, but current main filters out hidden/internal and cleanup-retained entries before exposing session active state. Reusing the raw map can recover a Control UI busy state for a run that should not be visible or active for the selected session.
  - confidence: 0.87
- **[P1] Move the snapshot field to the live protocol package:** `src/gateway/protocol/schema/snapshot.ts:38-45`
  - body: The added `activeChatRuns` schema lives under the old `src/gateway/protocol` path, while current main's exported protocol schemas are in `packages/gateway-protocol`. After rebase, clients and generated/native protocol checks would not see the new field from this file.
  - confidence: 0.9
- **[P2] Preserve fallback when transcript injection throws:** `src/gateway/server-restart-sentinel.ts:54-55`
  - body: If `injectRestartNoticeIntoSession` throws while ensuring or appending the transcript notice, the caller never reaches the `enqueueSystemEvent` fallback, so the consumed restart sentinel can still disappear without any visible recovery message. Catch injection failures and return `false` so the fallback path runs.
  - confidence: 0.82
- **[P2] Pick recovered active runs deterministically:** `ui/src/ui/app-gateway.ts:126-136`
  - body: The resolver returns the first active run for a session, but the server tracks active entries by run id and can have more than one matching session entry. Recovering an older run id can cause later deltas/finals for the newer run to be ignored, leaving the chat stuck in stale busy state.
  - confidence: 0.78
