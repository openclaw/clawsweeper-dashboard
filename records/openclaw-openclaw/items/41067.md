## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Gate run aborts to restart closes:** `src/gateway/server-close.ts:125-147`
  - body: This loop runs for every gateway close, aborts all active chat runs with `stopReason: "shutdown"`, and writes a restart-style notice before broadcasting shutdown. Current main only aborts active runs inside the restart reply-drain path when `restartExpectedMs` is present, so ordinary shutdown can falsely mark user runs as restart-interrupted.
  - confidence: 0.91
- **[P1] Use the filtered active-run contract:** `src/gateway/server/ws-connection/message-handler.ts:100-109`
  - body: The hello snapshot emits every `chatAbortControllers` entry, but current session active-run projection filters hidden, inactive, wrong-agent, and wrong-scope runs. Reconnect recovery can therefore restore a background or hidden run and leave Dashboard in the wrong busy state.
  - confidence: 0.89
- **[P1] Move the snapshot field to the live protocol package:** `src/gateway/protocol/schema/snapshot.ts:38-64`
  - body: This branch adds `activeChatRuns` under `src/gateway/protocol`, but current main imports the live Gateway protocol schema from `packages/gateway-protocol`. As written, current generated clients and validation would not receive this field.
  - confidence: 0.88
- **[P2] Preserve fallback when transcript injection throws:** `src/gateway/server-restart-sentinel.ts:82-84`
  - body: `injectRestartNoticeIntoSession` can reject before returning `false`, so this await skips the existing `enqueueSystemEvent` fallback after the restart sentinel has been consumed. Catch injection failures inside the helper and return `false` so fallback delivery still runs.
  - confidence: 0.87
- **[P2] Pick recovered active runs deterministically:** `ui/src/ui/app-gateway.ts:126-136`
  - body: `resolveActiveChatRunForSession` returns the first matching run, but the server can hold multiple active runs for one session. If an older entry appears first, the UI restores that run id and then ignores events for the newer run, leaving chat stuck busy.
  - confidence: 0.82
