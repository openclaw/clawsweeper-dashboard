Full review comments:

- **[P1] Gate run aborts to restart closes:** `src/gateway/server-close.ts:125-147`
  - body: This loop runs for every gateway close, not only restart closes. A normal shutdown or startup-failed close would abort active chat runs and write a "gateway restart" transcript notice even when `restartExpectedMs` was absent; gate this on the restart path and use the current restart stop reason.
  - confidence: 0.9
- **[P1] Use the current filtered active-run contract:** `src/gateway/server/ws-connection/message-handler.ts:1038-1040`
  - body: The hello snapshot serializes every `chatAbortControllers` entry. Current main filters restart/chat run candidates by lifecycle and abortability; exposing the raw map can recover stale or non-visible runs and leave the Dashboard busy for the wrong run.
  - confidence: 0.84
- **[P1] Move the snapshot field to the live protocol package:** `src/gateway/protocol/schema/snapshot.ts:61`
  - body: `src/gateway/protocol` has been removed on current main; the live schema is under `packages/gateway-protocol/src/schema`. Adding `activeChatRuns` here will not update the real validator after rebase and risks resurrecting a deleted protocol tree.
  - confidence: 0.92
- **[P2] Preserve fallback when transcript injection throws:** `src/gateway/server-restart-sentinel.ts:54-55`
  - body: If `injectRestartNoticeIntoSession` throws while resolving or creating the transcript, this condition never reaches `enqueueSystemEvent`, so the consumed restart sentinel notice is dropped. Catch inside the helper and return `false` so the existing fallback still runs.
  - confidence: 0.86
- **[P2] Pick recovered active runs deterministically:** `ui/src/ui/app-gateway.ts:126-137`
  - body: Returning the first matching `activeChatRuns` entry can select an older run when more than one run exists for the session. Then later events for the newer run are ignored by run-id matching, leaving the UI stuck; choose the existing current run or newest `startedAtMs`.
  - confidence: 0.82
