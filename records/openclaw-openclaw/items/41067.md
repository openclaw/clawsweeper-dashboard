Full review comments:

- **[P1] Gate run aborts to restart closes:** `src/gateway/server-close.ts:125-147`
  - body: This loop runs for every gateway close, not only restart closes. A normal shutdown would abort active chat runs and write a gateway-restart transcript notice even when `restartExpectedMs` is absent; gate this to restart shutdown and use the current restart stop reason.
  - confidence: 0.9
- **[P1] Use the current filtered active-run contract:** `src/gateway/server/ws-connection/message-handler.ts:1038-1040`
  - body: The hello snapshot serializes every `chatAbortControllers` entry. Current main filters hidden, agent-owned, inactive, and aborted runs before projecting recoverable in-flight state, so this raw map can recover a stale or non-visible run and leave Dashboard busy for the wrong run.
  - confidence: 0.86
- **[P1] Move the snapshot field to the live protocol package:** `src/gateway/protocol/schema/snapshot.ts:64`
  - body: `src/gateway/protocol` is stale relative to current main; the live snapshot schema is under `packages/gateway-protocol/src/schema`. Adding `activeChatRuns` here will miss the real validator after rebase and risks resurrecting a deleted protocol tree.
  - confidence: 0.92
- **[P2] Preserve fallback when transcript injection throws:** `src/gateway/server-restart-sentinel.ts:54-55`
  - body: If `injectRestartNoticeIntoSession` throws while resolving or creating the transcript, the caller never reaches `enqueueSystemEvent`, so the consumed restart sentinel notice is dropped. Catch inside the helper and return `false` so fallback delivery still runs.
  - confidence: 0.86
- **[P2] Pick recovered active runs deterministically:** `ui/src/ui/app-gateway.ts:126-137`
  - body: Returning the first matching `activeChatRuns` entry can select an older run when a session has multiple active entries. Later events for the newer run are then ignored by run-id matching; prefer the existing current run or newest `startedAtMs`.
  - confidence: 0.82
