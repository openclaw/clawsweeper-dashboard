Full review comments:

- **[P1] Gate run aborts to restart closes:** `src/gateway/server-close.ts:125-138`
  - body: This close handler aborts every active chat run and writes a restart-style notice on any gateway close. Current main limits active-run abort/recovery work to the restart path, so ordinary shutdown can become a user-visible interrupted run with the wrong notice.
  - confidence: 0.91
- **[P1] Use the filtered active-run contract:** `src/gateway/server/ws-connection/message-handler.ts:100-109`
  - body: The hello snapshot emits every `chatAbortControllers` entry, but current session busy-state helpers filter hidden, inactive, and wrong-scope runs. Reconnect recovery can therefore restore a background or other-agent run and leave Dashboard in the wrong busy state.
  - confidence: 0.9
- **[P1] Move the snapshot field to the live protocol package:** `src/gateway/protocol/schema/snapshot.ts:38-64`
  - body: The branch adds `activeChatRuns` under `src/gateway/protocol`, but current main validates Gateway snapshots from `packages/gateway-protocol`; generated clients and validation would not receive this field.
  - confidence: 0.88
- **[P2] Preserve fallback when transcript injection throws:** `src/gateway/server-restart-sentinel.ts:83-84`
  - body: `injectRestartNoticeIntoSession` can reject before returning `false`, so this await skips the existing `enqueueSystemEvent` fallback and drops the consumed restart sentinel notice.
  - confidence: 0.86
- **[P2] Pick recovered active runs deterministically:** `ui/src/ui/app-gateway.ts:126-136`
  - body: `resolveActiveChatRunForSession` returns the first matching run even if the server holds multiple active runs for one session. If an older entry appears first, the UI restores that run id and then ignores events for the newer run.
  - confidence: 0.82
