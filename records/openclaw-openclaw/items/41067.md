## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Gate shutdown run aborts to restart closes:** `src/gateway/server-close.ts:124-147`
  - body: This loop aborts every active chat run and injects a gateway-restart notice on every close path. Ordinary shutdown/SIGTERM should not synthesize restart semantics or cancel active runs as a restart; current main gates restart-specific drain behavior on `restartExpectedMs`.
  - confidence: 0.9
- **[P1] Use the current filtered active-run contract:** `src/gateway/server/ws-connection/message-handler.ts:1038-1040`
  - body: The hello payload lists every abort-controller entry. That bypasses current main's filtering for projected-inactive, hidden, aborted, agent-owned, and agent-scoped global runs, so reconnect can adopt a run whose terminal events the UI should not own.
  - confidence: 0.88
- **[P1] Move the snapshot field to the current protocol package:** `src/gateway/protocol/schema/snapshot.ts:61`
  - body: The PR adds `activeChatRuns` under the old `src/gateway/protocol` schema path, but current main's canonical schema is `packages/gateway-protocol/src/schema/snapshot.ts`. A refreshed patch must update the canonical schema and generated clients together.
  - confidence: 0.86
- **[P2] Fallback when transcript injection fails:** `src/gateway/server-restart-sentinel.ts:32-39`
  - body: `injectRestartNoticeIntoSession` can throw while preparing the transcript, but callers only enqueue the fallback system event when it returns `false`. Catch setup/append failures inside the helper so a consumed sentinel notice is not dropped.
  - confidence: 0.84
- **[P2] Pick recovered active runs deterministically:** `ui/src/ui/app-gateway.ts:126-136`
  - body: `resolveActiveChatRunForSession` returns the first matching entry for a session. If multiple entries exist, reconnect can recover an older run ID and then ignore the newer run's events due to run-id mismatch.
  - confidence: 0.8
