Full review comments:

- **[P1] Gate run aborts to restart closes:** `src/gateway/server-close.ts:125-138`
  - body: This close handler aborts every active chat run for any gateway close, then writes a restart-style transcript notice. Current main only drains or aborts active runs inside the restart path, so ordinary shutdown/SIGTERM can become a user-visible aborted run with the wrong recovery message.
  - confidence: 0.9
- **[P1] Use the filtered active-run contract:** `src/gateway/server/ws-connection/message-handler.ts:100-109`
  - body: The snapshot helper emits every chatAbortControllers entry, but current session busy-state helpers filter out hidden/non-project and wrong-scope runs. Reconnect recovery can therefore restore a background or other-agent run and leave the Dashboard in the wrong busy state.
  - confidence: 0.88
- **[P1] Move the snapshot field to the live protocol package:** `src/gateway/protocol/schema/snapshot.ts:38-64`
  - body: The branch adds activeChatRuns under the old src/gateway/protocol schema path, while current main's live schema is packages/gateway-protocol/src/schema/snapshot.ts. As rebased, clients generated from the current protocol package would not receive this field.
  - confidence: 0.86
- **[P2] Preserve fallback when transcript injection throws:** `src/gateway/server-restart-sentinel.ts:83-84`
  - body: When injectRestartNoticeIntoSession rejects, this await skips the enqueueSystemEvent fallback and the consumed restart sentinel notice can be dropped. Catch injection failures and return false so the existing fallback path still runs.
  - confidence: 0.88
- **[P2] Pick recovered active runs deterministically:** `ui/src/ui/app-gateway.ts:126-136`
  - body: resolveActiveChatRunForSession returns the first matching run, but the server can hold multiple active runs for one session. If an older entry is first, the UI can restore that runId and then ignore deltas/finals from the newer run, leaving chat stuck busy.
  - confidence: 0.82
