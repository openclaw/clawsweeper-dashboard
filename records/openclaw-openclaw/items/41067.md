Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Gate restart abort cleanup to restart closes:** `src/gateway/server-close.ts:125-147`
  - body: This loop runs for every server close, so a normal shutdown can abort active chat runs and write gateway-restart interruption notices. Gate this cleanup behind the restart path or reuse current main's restart-drain boundary.
  - confidence: 0.89
- **[P1] Filter active-run snapshots before sending hello:** `src/gateway/server/ws-connection/message-handler.ts:1038-1040`
  - body: The hello payload is populated from every abort-controller entry. That can let hidden/background, inactive, aborted, or agent-owned runs be adopted by the UI even though those runs should not drive visible chat recovery.
  - confidence: 0.86
- **[P1] Fall back when transcript setup fails:** `src/gateway/server-restart-sentinel.ts:32-39`
  - body: `injectRestartNoticeIntoSession` can throw while creating or opening the transcript, but callers only enqueue the fallback system event when it returns `false`. Catch setup errors inside this helper so a consumed restart sentinel notice is not dropped.
  - confidence: 0.87
- **[P2] Pick the recovered run deterministically:** `ui/src/ui/app-gateway.ts:126-136`
  - body: This helper returns the first active run for a session. If multiple runs are tracked for the same session, reconnect can recover an older run ID and then ignore deltas or finals from the newer run because they do not match the recovered ID.
  - confidence: 0.82
