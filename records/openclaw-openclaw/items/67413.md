Keep open. Current main still has global-only memory-core Dreaming configuration and an all-agent workspace sweep, while two open PRs now attempt different parts of the fix and need maintainer API/scope review before this issue can close.

The issue requests per-agent memory-core Dreaming controls so operators can disable, scope, or schedule Dreaming per agent instead of running one global sweep over every configured workspace.

Keep this issue open while maintainers choose the Dreaming config API, then land one implementation that aligns schema, manifest, docs, runtime resolver/status behavior, doctor/migration behavior, and focused tests before closing it.
