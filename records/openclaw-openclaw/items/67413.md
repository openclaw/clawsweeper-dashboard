## Label Justifications

- `P2`: The issue has source-backed multi-agent memory-core resource and state impact, but the blast radius is bounded to installs that enable dreaming across multiple agent workspaces.
- `impact:session-state`: Dreaming writes memory and narrative artifacts across configured agent workspaces with no durable agent-level scope or opt-out today.
- `impact:crash-loop`: The reporter describes gateway OOM kills under a 6GB MemoryMax limit when the scheduled dreaming sweep processes all configured agents.

## Summary

Keep open. Current main and the latest release still expose global-only memory-core dreaming configuration and still fan one managed sweep across configured agent workspaces; https://github.com/openclaw/openclaw/pull/67420 and https://github.com/openclaw/openclaw/pull/100057 are unmerged candidate fixes, and the durable config shape still needs maintainer direction.

## What This Changes

Add a durable memory-core configuration surface to scope or stagger dreaming per agent so multi-agent installs can avoid all workspaces dreaming in one global sweep.

## Best Possible Solution

Keep this issue open until maintainers choose the plugin-owned config/API shape, then land a refreshed implementation such as a documented memory-core allowlist or per-agent override with schema, runtime, docs, and tests; split custom schedules or pressure backoff into separate follow-ups if they are not part of the first accepted contract.
