## Summary

Keep open. Current main and the latest release still expose global-only memory-core dreaming configuration, while two open PRs now cover candidate fixes and need maintainer review rather than early issue closure.

## What This Changes

Request per-agent memory-core dreaming controls so operators can disable or schedule dreaming for specific agents instead of sweeping every configured workspace from one shared cron.

## Best Possible Solution

Land a maintainer-approved, schema-backed scoped Dreaming config for bounded sweeps, likely the narrower global `dreaming.agents` allowlist from the newer candidate PR after its blocker is fixed, and split per-agent schedules, staggering, or memory-pressure deferral into separate follow-ups unless maintainers explicitly keep them in scope.
