## Summary

Keep open. Current main and the latest release still expose only global memory-core Dreaming configuration and still sweep every configured agent workspace; the remaining work is active in open PR candidates and needs maintainer API/schedule scope judgment before landing.

## What This Changes

The issue requests per-agent memory-core Dreaming control so operators can disable, scope, or schedule Dreaming per agent instead of running every workspace under one global schedule.

## Best Possible Solution

Land a maintainer-approved, schema-backed memory-core scoped Dreaming config with default behavior preserved, then split per-agent schedule/stagger and pressure-backoff policy into explicit follow-ups if they are not included in the accepted first pass.
