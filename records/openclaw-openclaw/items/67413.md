## Label Justifications

- `P2`: This is a normal-priority memory-core improvement with real multi-agent resource and artifact impact but a bounded plugin/config surface.
- `impact:session-state`: Dreaming writes memory and narrative artifacts across configured agent workspaces without an accepted agent-level opt-out or scope boundary.
- `impact:crash-loop`: The reporter and commenters describe OOM kills or severe pressure when the scheduled dreaming sweep processes many agents in one run.

## Summary

Keep open. Current main and v2026.6.11 still expose global-only memory-core dreaming configuration and still resolve every configured agent workspace; open PRs are candidate fixes, but no implementation has landed on main.

## What This Changes

Request durable per-agent or scoped memory-core dreaming configuration so operators can disable or stagger dreaming instead of running one global all-workspace sweep.

## Best Possible Solution

Choose a narrow schema-backed dreaming scoping API, land https://github.com/openclaw/openclaw/pull/100057 or a replacement, and split per-agent schedules or stagger offsets into a follow-up unless maintainers explicitly accept that broader scope now.
