Full review comments:

- **[P1] Preserve explicitly allowed cross-origin WebSocket clients:** `src/config/types.gateway.ts:544-548`
  - body: Do not default this field to rejecting every `Sec-Fetch-Site: cross-site` upgrade. `gateway.controlUi.allowedOrigins` intentionally supports browser UIs hosted on another origin, and browsers mark those requests cross-site; this pre-check would turn a supported configuration into a 403 before consulting the allowlist. Make the signal supplemental to the canonical origin decision or require explicit strict opt-in.
  - confidence: 0.98
- **[P1] Use the existing Host-header fallback setting:** `src/config/types.gateway.ts:549-553`
  - body: Remove this parallel `gateway.security.dangerouslyAllowHostHeaderOriginFallback` key and read the established `gateway.controlUi.dangerouslyAllowHostHeaderOriginFallback` policy. With two keys, the new pre-handshake check and existing post-handshake check can make opposite decisions, so neither old nor new configuration reliably enables the documented behavior.
  - confidence: 0.99
- **[P1] Parse IPv6 addresses without splitting on every colon:** `src/gateway/forwarded-headers.ts:22-25`
  - body: Replace the `.split(":")[0]` extraction with the repository's canonical address parser. Distinct IPv6 values such as `2001:db8::1` and `2001:ffff::2` both collapse to `2001`, so the new X-Forwarded-For versus Forwarded contradiction check can accept conflicting attacker-controlled headers; bracketed IPv6-with-port values are also malformed.
  - confidence: 0.97
- **[P2] Complete the security config contract:** `src/config/zod-schema.ts:1201-1208`
  - body: Add the four fields to canonical config labels/help, public Gateway security/reference docs, and schema coverage with exact defaults and reload behavior. These options change upgrade admission at a security boundary, but the patch currently exposes only TypeScript and Zod keys, leaving operators and generated configuration UI without recovery guidance.
  - confidence: 0.94
