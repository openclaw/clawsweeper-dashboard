## Summary

The shared bounded-reader direction is sound and follows the related merged hardening work in https://github.com/openclaw/openclaw/pull/101472, but this PR introduces an unconditional 8 MiB compatibility limit for existing `--batch-file` workflows without a maintainer-confirmed contract or direct CLI-level regression coverage.

## What This Changes

The PR replaces the unbounded synchronous `config set --batch-file` read with `readRegularFileSync` and a new 8 MiB maximum input size.

## Best Possible Solution

Retain a bounded shared-reader mitigation only after maintainers select and document a compatible batch-file size contract, then add focused parser/CLI coverage for normal, exact-limit, over-limit, and missing-file cases.
