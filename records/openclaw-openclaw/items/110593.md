## Summary

Keep this PR open for a maintainer decision: the bounded-read hardening is coherent and has real terminal proof, but the new unconditional 8 MiB rejection threshold changes the compatibility contract of an existing public CLI input without an owner-approved capacity or upgrade policy.

## What This Changes

The branch replaces the unbounded synchronous `config set --batch-file` read with `readRegularFileSync` capped at 8 MiB and adds an oversized-file rejection test.

## Best Possible Solution

Retain the shared bounded-reader approach only after the CLI owner explicitly approves a batch-file capacity contract and its failure behavior; then document and test the chosen fresh-install and upgrade expectations, or select a compatibility-preserving limit strategy.
