## Summary

Keep open: current main still exposes `session_status` as a rendered status-card tool result, while raw session, last-turn, cost, and quota/budget usage data remains on separate Gateway/status/transcript surfaces. ## What This Changes

Expose raw per-session, last-turn, token, cost, and budget usage data through the agent-facing `session_status` tool.

## Best Possible Solution

Define a documented structured agent-facing usage surface under existing session visibility checks, with explicit measured, estimated, stale, unavailable, source, cost, and quota semantics for session totals and last-turn usage.
