## Summary

Keep open: current main and latest release still expose `session_status` as a rendered status-card tool with minimal structured details, while raw session token, cost, quota-window, source, and freshness data remain on other gateway/status/transcript surfaces rather than a stable agent-facing usage API.

## What This Changes

Request to expose structured per-session, last-turn, cost, and quota usage data through `session_status` so agents can budget token consumption without parsing transcript JSONL files.

## Best Possible Solution

Define a maintainer-approved structured agent-facing usage contract, then implement it through the existing `session_status` visibility checks or an equivalent supported tool that reuses gateway/transcript usage sources.
