## Summary

Keep open: current main and v2026.6.11 still expose `session_status` as rendered status text plus minimal details, while raw session, last-turn, cost, quota-window, source, and freshness metadata remain outside a stable agent-facing tool contract. The merged context-budget work is useful adjacent reporting, but it does not satisfy the broader structured usage API request.

## What This Changes

Expose structured per-session token, cost, last-turn, and budget/quota usage data through the agent-facing `session_status` tool.

## Best Possible Solution

Define a maintainer-approved structured agent-facing usage contract, then implement it through the existing `session_status` visibility checks or an equivalent supported tool that reuses gateway/transcript usage sources.

Options:

- **Extend `session_status.details` (recommended):** Add a stable `details.usage` contract to the existing tool while preserving rendered status text and current visibility checks.
- **Create a separate usage tool:** Keep `session_status` display-oriented and add a narrower agent-facing usage query surface backed by gateway and transcript usage code.
- **Keep raw usage out of agent tools:** Leave raw usage behind gateway, UI, and CLI surfaces and document that agents should not consume it through `session_status`.

## Reproduction Assessment

## Solution Assessment

Unclear until maintainers choose the API shape. Extending `session_status.details` is likely the narrowest maintainable path if it reuses existing visibility checks and gateway/transcript usage sources.
