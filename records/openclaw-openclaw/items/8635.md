## Summary

Keep open: current main still exposes `session_status` as a `/status`-style rendered text result, while raw session, last-turn, cost, and quota-window data remains in separate status/Gateway usage paths. The merged context-budget work is useful adjacent progress, but it does not provide the broader structured agent-facing usage API requested here.

## What This Changes

The issue requests structured per-session token, cost, last-turn, and budget-window usage data through the agent-facing `session_status` tool.

## Best Possible Solution

Define a documented structured agent-facing usage surface under existing session visibility checks, with explicit measured, estimated, stale, unavailable, source, cost, and quota-window semantics for session totals and last-turn usage.

## Reproduction Assessment

Yes. Source inspection on current main shows `session_status` details lack a structured usage object, while usage data exists only as rendered status text or separate Gateway RPCs.

## Solution Assessment

Unclear. The requested capability is reasonable, but maintainers still need to choose the stable response schema, freshness rules, cost-source semantics, quota-window availability metadata, and privacy boundaries before implementation.
