## Summary

Keep open. Current main provides rendered status text, structured context-pressure metadata, and separate gateway usage RPCs, but it still lacks a stable agent-facing contract for cumulative session usage, last-turn tokens, cost, and provider quota windows; the related work addresses narrower context, provider-cost, logging, or freshness concerns without superseding this request.

## What This Changes

Expose structured per-session and last-turn token, cost, and provider-budget usage to agents through `session_status` or an equivalent supported tool.

## Best Possible Solution

Add a documented, bounded structured usage result—preferably optional details on `session_status` reusing existing gateway aggregation—with session and last-turn tokens/cost, quota availability, source and freshness metadata, and the existing session-visibility checks.

Options:

- **Extend status details (recommended):** Add an optional bounded `usage` object to `session_status.details`, backed by existing aggregators and explicit availability, source, and freshness fields.
- **Create a usage tool:** Keep `session_status` lightweight and introduce a dedicated agent-facing usage query with session and last-turn modes.
- **Keep display-only behavior:** Retain status cards and operator gateway RPCs without creating a supported agent-facing raw-usage contract.

## Reproduction Assessment

Yes, at source level: the current tool contract and documentation expose rendered status plus limited operational details, while the requested raw session and last-turn usage fields remain absent. This is a missing capability rather than a failing existing contract.

## Solution Assessment

Unclear pending the API-boundary decision. Reusing existing usage aggregation is preferable to parsing transcripts again, but maintainers must choose between optional `session_status` details and a dedicated tool while defining visibility and freshness semantics.
