## Summary

Keep open: current main and the latest release still expose `session_status` as a rendered status-card tool with minimal structured details, while raw session, last-turn, cost, quota-window, source, and freshness data remain on separate gateway/status/transcript surfaces rather than a stable agent-facing usage API.

## What This Changes

The issue requests structured token usage fields from `session_status` so agents can inspect per-session, per-turn, cost, and budget data programmatically.

## Best Possible Solution

Define a maintainer-approved structured agent-facing usage contract, then implement it through existing `session_status` visibility checks or an equivalent supported tool that reuses gateway/transcript usage sources.
