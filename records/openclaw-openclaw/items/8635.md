## Summary

Keep open: current main and the latest release still expose `session_status` as rendered status text plus route/model details, while raw session/last-turn usage remains in transcript readers and separate Gateway usage RPCs rather than a documented agent-facing `session_status` usage contract.

## What This Changes

Requested exposing raw per-session and last-turn token, cost, and quota usage data through the agent-facing `session_status` tool.

## Best Possible Solution

Ship a documented, visibility-aware structured usage contract for agent callers, either in `session_status.details` or an equivalent agent-facing usage tool, reusing existing status and `sessions.usage` parsers instead of exposing transcript files directly.
