## Summary

Keep open: current main and the latest release still expose `session_status` as a rendered status-card result, while raw session totals, last-turn tokens, costs, and provider quota windows remain separate status/Gateway/transcript surfaces rather than a documented agent-facing usage contract.

## What This Changes

Request to expose structured per-session and last-turn token, cost, and budget usage data through the `session_status` tool.

## Best Possible Solution

Define a documented agent-facing usage contract that reuses existing session visibility checks and explicitly represents session totals, last-turn usage, cost source, provider quota/window availability, freshness, and unavailable states.

## Reproduction Assessment

Yes for the current gap: source inspection on current main shows `session_status` schema/result details lack a structured usage object while status text and `sessions.usage` handle usage elsewhere.

## Solution Assessment

Unclear. The requested direction is plausible, but maintainers still need to choose the stable response schema, source/freshness rules, cost semantics, quota availability metadata, and privacy boundaries before implementation.
