## Summary

Keep open: current main and the latest release still expose `session_status` as a rendered status-card tool with limited structured details, while raw token, cost, budget, source, and freshness data remain on separate status/gateway/transcript surfaces rather than a stable agent-facing usage API.

## What This Changes

The issue requests structured per-session, last-turn, cost, and budget usage data through the agent-facing `session_status` tool.

## Best Possible Solution

Ship a documented, visibility-aware structured usage contract for agent callers, either in `session_status.details` or a dedicated usage tool, reusing existing transcript and Gateway usage parsers with explicit source, freshness, availability, cost, and quota metadata.
