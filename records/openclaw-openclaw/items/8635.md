## Summary

Keep open: current main still exposes usage through a rendered status card while structured details cover route and state metadata, not cumulative session tokens, last-turn usage, cost, or provider quota windows; the separate `sessions.usage` Gateway RPC does not satisfy the requested agent-facing contract.

## What This Changes

Expose structured per-session and last-turn token, cost, and budget data through the agent-facing `session_status` tool.

## Best Possible Solution

Define one compact structured agent-facing usage contract that reuses canonical Gateway and transcript aggregation, preserves existing session-access checks, and explicitly reports totals, last-turn usage, cost, quota windows, source, availability, and freshness.
