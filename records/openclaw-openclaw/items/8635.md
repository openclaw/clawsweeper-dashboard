## Summary

Keep open: current main and the latest release still expose `session_status` as a rendered status-card tool result, not a structured agent-facing usage API. Separate Gateway usage RPCs and the merged context-budget work cover adjacent data sources, but they do not satisfy the requested `session_status` session/last-turn token, cost, and budget contract.

## What This Changes

The issue requests raw per-session, last-turn, cost, and budget usage fields on the `session_status` agent tool so agents can programmatically track capacity.

## Best Possible Solution

Define a documented structured agent-facing usage surface under existing session visibility checks, with explicit measured, estimated, stale, unavailable, source, cost, and quota semantics for session totals and last-turn usage.

## Reproduction Assessment

Yes. Source inspection shows `session_status` accepts only `sessionKey` and `model` and returns rendered status text plus minimal details, while structured usage data exists under separate Gateway usage RPCs.

## Solution Assessment

Unclear. Extending `session_status.details` is plausible, but maintainers still need to choose the stable schema, source/freshness rules, cost semantics, quota-window metadata, and privacy boundaries; an equivalent dedicated agent tool could also be acceptable.
