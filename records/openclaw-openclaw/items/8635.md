## Summary

Keep open: current main and the latest release still expose session_status as a rendered status-card tool result, while the requested raw session, last-turn, cost, and quota/budget usage contract remains absent. Related usage work is useful but only partial, so this needs maintainer product/API review rather than cleanup closure.

## What This Changes

The issue requests a structured token, cost, and budget usage API in the agent-facing session_status tool.

## Best Possible Solution

Add a documented structured agent-facing usage surface that reuses gateway/session usage and transcript parsers while preserving existing visibility checks and clear availability metadata.

## Reproduction Assessment

Yes, from source inspection: current main and v2026.6.11 both show session_status returning rendered status text and minimal details without a stable structured usage object. I did not run a live tool call because the missing contract is directly visible in the tool schema and return shape.

## Solution Assessment

No, the current merged context-budget and gateway usage surfaces are not the full solution because they do not expose raw session/last-turn token and cost data through session_status. The maintainable path is a deliberate API contract, not parsing rendered status text or blindly mirroring gateway data.
