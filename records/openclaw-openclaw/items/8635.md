## Summary

Keep open: current main still exposes `session_status` as a rendered status-card tool result with minimal structured details, while raw session totals, last-turn usage, cost, and quota/budget data remain in separate Gateway/status/transcript surfaces. The merged https://github.com/openclaw/openclaw/pull/84830 and newer status-routing work are adjacent, but they do not implement the requested agent-facing structured usage API.

## What This Changes

The issue requests a structured token and cost usage API on `session_status`, including session totals, last-turn usage, and quota/budget metadata.

## Best Possible Solution

Define a documented additive `session_status.details.usage` contract, or an equivalent supported agent usage tool, that reuses existing `sessions.usage`, transcript usage, and provider quota surfaces while carrying explicit source, freshness, availability, cost, and visibility semantics.

## Reproduction Assessment

Yes. Source inspection on current main shows `session_status` has no structured usage schema or `details.usage` result, while structured usage exists in separate Gateway usage RPCs and rendered status text.

## Solution Assessment

Unclear. The requested capability is reasonable, but maintainers still need to choose the response schema, source/freshness semantics, cost/quota behavior, and privacy boundary before implementation.
