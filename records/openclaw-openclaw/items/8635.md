## Summary

Keep open: current main and the latest release still expose `session_status` as a rendered status-card result, not a structured session/last-turn token, cost, or quota API. Structured usage data exists on separate Gateway RPCs, and the merged context-budget work at https://github.com/openclaw/openclaw/pull/84830 is adjacent but does not supersede this broader agent-facing usage contract request.

## What This Changes

Expose structured token, cost, last-turn, and budget usage data through `session_status` so agents do not need to parse transcript files directly.

## Best Possible Solution

Define a documented structured agent-facing usage surface under existing session visibility guards, reusing Gateway/transcript aggregation while returning explicit measured, estimated, stale, unavailable, source, cost, quota, and last-turn semantics.

## Reproduction Assessment

Yes, at source level. Current `session_status` schema and returned details have no structured usage object, while structured usage data exists under separate Gateway usage RPCs and rendered status text.

## Solution Assessment

Unclear. The requested capability is reasonable, but maintainers still need to choose the stable response schema, freshness rules, cost-source semantics, quota-window availability metadata, and privacy boundaries before implementation.
