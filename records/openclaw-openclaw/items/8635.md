## Summary

Keep open: current main and latest release still expose session_status as rendered status text with small route/model details, while raw cumulative usage remains on separate Gateway usage RPCs and transcript readers rather than a stable agent-facing session_status usage contract.

## What This Changes

Request to expose raw per-session, last-turn, budget-window, and cost usage data through the agent-facing session_status tool.

## Best Possible Solution

Ship a documented, visibility-aware structured usage contract for agent callers, either in session_status.details or a clearly equivalent agent-facing usage tool, reusing the existing status and sessions.usage parsers instead of exposing transcript files directly.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes: source inspection shows session_status has no structured usage fields while the requested raw usage exists only in rendered status text, transcript parsing, or Gateway usage RPCs.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainers choose the stable API boundary; extending session_status.details is plausible, but a separate agent-facing usage tool may be cleaner if it avoids overloading status-card behavior.
