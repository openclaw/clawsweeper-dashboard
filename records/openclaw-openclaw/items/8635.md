## Summary

Keep open: current main still exposes `session_status` as a rendered `/status`-style card with minimal structured details, while raw token, cost, last-turn, freshness, and quota data remain on separate status/Gateway/transcript surfaces. The merged context-budget work helps display estimated context pressure, but it does not provide the requested agent-facing structured usage API.

## What This Changes

The issue requests structured token, cost, last-turn, and budget usage data through the agent-facing `session_status` tool.

## Best Possible Solution

Define a documented structured agent-facing usage surface under existing session visibility checks, reusing `sessions.usage` and transcript/status parsers while making measured, estimated, stale, unavailable, source, cost, quota, and last-turn semantics explicit.

## Reproduction Assessment

Yes, at source level. Current `SessionStatusToolSchema` accepts only `sessionKey` and `model`, and successful tool details return rendered `statusText` without a structured `usage` object.

## Solution Assessment

Unclear until maintainers choose the API contract. Extending `session_status.details` or adding an equivalent usage tool is plausible, but the stable schema, freshness rules, cost-source semantics, quota availability, and privacy boundaries need product/API review first.
