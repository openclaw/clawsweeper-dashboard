## Summary

Keep open: current main and latest release still expose `session_status` as a rendered status card plus limited `details`, while raw session/last-turn token, cost, quota, source, and freshness data remain on transcript state or separate Gateway usage RPCs instead of an agent-facing tool contract.

## What This Changes

Expose per-session and last-turn token, cost, and budget usage through `session_status` so agents can programmatically budget work without parsing transcript files.

## Best Possible Solution

Ship a documented, visibility-aware structured usage contract for agent callers, either as `session_status.details.usage` or a dedicated usage tool, reusing existing transcript and Gateway usage parsers with explicit source, freshness, availability, cost, and quota metadata.
