## Summary

Keep open: current main still exposes `session_status` as rendered status text plus minimal details, while structured token, cost, last-turn, and quota usage remain on separate Gateway/status/transcript surfaces. The merged context-budget work is adjacent reporting, not the requested agent-facing structured usage API.

## What This Changes

Request to expose raw per-session and last-turn token, cost, and budget usage through the agent-facing `session_status` response.

## Best Possible Solution

Define a documented structured agent-facing usage surface under existing session visibility checks, with explicit measured, estimated, stale, unavailable, source, cost, quota, and last-turn semantics.

## Reproduction Assessment

Yes, at source level. Current `SessionStatusToolSchema` accepts only `sessionKey` and `model`, and successful tool details return rendered `statusText` without a structured `usage` object.

## Solution Assessment

Unclear until maintainers choose the API contract. Extending `session_status.details` or adding an equivalent usage tool is plausible, but the stable schema, freshness rules, cost-source semantics, quota availability, and privacy boundaries need product/API review first.
