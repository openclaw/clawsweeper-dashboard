## Summary

Keep open: current main still exposes `session_status` as a `/status`-style text result with limited structured details, while raw session, last-turn, cost, and quota/budget usage data remains on separate Gateway/status/transcript surfaces. The merged context-budget work is useful adjacent reporting, but it does not replace this broader agent-facing structured usage API request.

## What This Changes

The issue requests structured token and cost usage data on `session_status` so agents can read session and last-turn usage without parsing transcript files.

## Best Possible Solution

Define a documented structured usage contract for agents, likely reusing transcript/session usage parsers and Gateway `sessions.usage` data, while preserving the current text status card and adding explicit source, freshness, visibility, and unavailable-state metadata.

## Reproduction Assessment

Yes, at source level: current `session_status` returns rendered status text plus limited details, while structured usage remains on separate Gateway/status/transcript paths. I did not run a live agent turn because the missing API contract is clear from current source and docs.

## Solution Assessment

Unclear until maintainers choose the public contract. Extending `session_status.details` or adding a dedicated usage tool are both plausible, but parsing `statusText` or reinterpreting existing estimated-cost fields would be the wrong long-term solution.
