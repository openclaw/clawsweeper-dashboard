## Summary

Keep open. Current main exposes rendered status text and structured context-pressure metadata, but it still lacks a stable agent-facing contract for cumulative session usage, last-turn tokens, cost, and provider quota windows; the related work addresses narrower context, provider-cost, logging, or freshness concerns without superseding this request.

## What This Changes

Expose structured per-session, last-turn, cost, and quota-window usage data to agents through `session_status` or an equivalent supported tool.

## Best Possible Solution

Add a documented structured agent-facing usage surface—preferably additive fields in `session_status.details` reusing the existing transcript and gateway usage machinery—with separately typed session totals, last-turn usage, provider windows, cost, source, freshness, and unavailable states while enforcing current session-visibility checks and adding no new configuration option.

## Risks / Open Questions

- Exposing transcript-derived totals or cost to agents must preserve existing session visibility, sandbox, and cross-agent access boundaries.
