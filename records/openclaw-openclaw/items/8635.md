## Summary

Keep open: current main and v2026.6.11 still expose `session_status` as rendered status text plus minimal details, while raw session, last-turn, cost, and quota/budget usage data remains on separate Gateway/status/transcript surfaces.

## What This Changes

Request structured token, cost, budget, and last-turn usage data in the agent-facing `session_status` tool instead of requiring transcript JSONL parsing.

## Best Possible Solution

Define a documented structured agent-facing usage contract under existing session visibility checks, with explicit measured, estimated, stale, unavailable, source, cost, and quota semantics.

## Reproduction Assessment

Yes. Source inspection shows current `session_status` has no structured `usage` object while related usage data exists only in rendered status text and separate Gateway RPCs.

## Solution Assessment
