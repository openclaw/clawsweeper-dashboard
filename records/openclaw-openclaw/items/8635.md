## Summary

Keep open: current main and the latest release still expose `session_status` as a rendered status-card tool, while raw token, cost, budget, and freshness data remain on separate gateway/transcript surfaces rather than a stable agent-facing usage API.

## What This Changes

Request to expose per-session and last-turn token, cost, and budget usage through `session_status` so agents can budget their own capacity.

## Best Possible Solution

Define an additive, documented agent-facing usage contract, either on `session_status.details.usage` or an equivalent supported tool, backed by existing `sessions.usage` and transcript parsers with visibility, privacy, freshness, and tests covered.
