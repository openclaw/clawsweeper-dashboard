## Summary

Keep open: current main and the latest release still expose `session_status` as a rendered status-card result, while raw session, last-turn, cost, and provider quota usage remain separate status/Gateway/transcript surfaces. The merged context-budget work is useful adjacent reporting, but it does not satisfy the requested structured agent-facing usage API.

## What This Changes

The issue requests structured token, cost, last-turn, and budget/window usage fields on the agent-facing `session_status` tool.

## Best Possible Solution

Define a documented agent-facing usage surface that reuses existing session visibility checks and exposes measured, estimated, stale, unavailable, source, cost, quota-window, session-total, and last-turn semantics explicitly.

## Reproduction Assessment

Yes. Source inspection on current main shows `session_status` schema/result details lack a structured usage object while status text and `sessions.usage` handle usage elsewhere.

## Solution Assessment

Unclear. The requested direction is plausible, but maintainers still need to choose the stable response schema, source/freshness rules, cost semantics, quota availability metadata, and privacy boundaries before implementation.
