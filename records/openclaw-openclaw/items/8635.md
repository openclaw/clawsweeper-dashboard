## Summary

The request remains necessary: current `main` and v2026.6.11 expose structured usage to gateway/UI consumers but still give agents only the rendered `session_status` card and limited metadata. This is a valid core feature aligned with the vision, but maintainers must choose the durable tool contract and its visibility, availability, and freshness semantics before implementation.

## What This Changes

Expose structured per-session, last-turn, cost, and provider-budget usage through the agent-facing `session_status` tool.

## Best Possible Solution

Add a documented structured usage payload to `session_status.details` behind its existing visibility checks, reusing shared transcript/gateway usage parsers and returning explicit source, availability, and freshness metadata while preserving the current text card.
