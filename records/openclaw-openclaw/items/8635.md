## Summary

Keep open: current main and v2026.6.11 still expose `session_status` as rendered status text plus limited route/model details, while structured token, cost, budget/window, source, and freshness data remains outside the agent-facing tool contract.

## What This Changes

Request to expose raw per-session and last-turn token, cost, and budget/window usage data through `session_status` or an equivalent agent-facing API.

## Best Possible Solution

Ship a documented, visibility-aware structured usage contract for agent callers, either in `session_status.details` or a dedicated usage tool, reusing existing transcript and Gateway usage parsers with explicit source, freshness, availability, cost, and quota metadata.

Options:

- **Add `session_status` usage details (recommended):** Extend `session_status.details` with stable session, last-turn, budget/window, source, freshness, and unavailable metadata while preserving the rendered status card.
- **Create a separate usage tool:** Keep `session_status` display-oriented and add a narrower agent-facing usage query tool under the same visibility guards.
- **Keep usage operator-only:** Leave raw usage on Gateway/operator surfaces until broader usage-ledger and freshness designs settle.

## Reproduction Assessment

Not applicable as a runtime bug, but source inspection gives a high-confidence reproduction of the missing feature: current main and v2026.6.11 lack structured usage fields in `session_status` while rendering usage text and exposing separate Gateway usage RPCs.

## Solution Assessment

Unclear until maintainers choose the stable API boundary. Extending `session_status.details` is plausible, but a dedicated agent-facing usage tool may be cleaner if raw usage queries should stay separate from status-card rendering.
