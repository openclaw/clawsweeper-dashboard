## Summary

Keep this issue open. The supplied July 18 current-main review found that `session_status` still returns a rendered status card rather than a documented structured agent-facing usage contract, while structured transcript aggregation remains on separate gateway surfaces. The merged context-budget work is useful adjacent reporting, but does not provide the requested session/last-turn token and cost API. A maintainer must choose the permanent contract, privacy boundary, and freshness semantics before implementation.

## What This Changes

Expose stable per-session and per-turn token, cost, and provider-window usage data to agents through `session_status` or an equivalent supported tool API.

## System Context

`session_status` is the agent-facing counterpart to OpenClaw’s human-readable status card: it resolves a permitted session and renders model, token, context, and quota information. Session transcript usage and aggregated usage RPCs feed related gateway and UI surfaces, but the requested change would carry a stable structured subset into an agent tool response.

## Best Possible Solution

Define one additive, documented agent-facing usage contract that reuses existing session aggregation, distinguishes fresh transcript totals from provider windows and estimates, reports explicit source/availability metadata, preserves session access controls, and receives focused tool-schema and privacy-boundary tests.
