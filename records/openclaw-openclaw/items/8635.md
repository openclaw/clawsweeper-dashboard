## Summary

Keep open: current main still exposes `session_status` as a rendered status-card tool with minimal structured details, while raw session token, cost, quota-window, source, and freshness data remain on status rendering, transcript parsing, Codex, or gateway usage surfaces rather than a stable agent-facing usage API.

## What This Changes

The issue requests a structured token and cost usage API in the `session_status` tool for session and last-turn budgeting.

## Best Possible Solution

Add a documented structured agent-facing usage contract that reuses existing transcript and gateway usage parsers while preserving session visibility, privacy, and explicit unavailable/freshness metadata.

Options:

- **Extend `session_status.details` (recommended):** Add a stable `details.usage` payload to the existing tool while preserving the rendered status card and current session visibility checks.
- **Create a separate usage tool:** Keep `session_status` display-oriented and add a narrower agent-facing usage query backed by gateway/transcript usage code.
- **Keep status display-only:** Leave raw usage behind gateway/UI/CLI surfaces and document that agents should not consume raw usage through `session_status`.
