- `merge-risk: 🚨 compatibility`: The patch changes which plugin metadata an existing auto-reply run uses to normalize configured and persisted model references.

## Summary

Keep this PR open, but do not merge it as written: the new resolver explicitly permits reuse of a workspace-scoped plugin snapshot without receiving a matching workspace identity. That can make auto-reply model-policy normalization use another workspace’s plugin set rather than the established discovery fallback. The submitted terminal benchmark is useful real behavior proof for the latency improvement, but it does not cover this compatibility boundary.

## What This Changes

The branch resolves one Gateway plugin-metadata snapshot at the start of each auto-reply model-selection run and passes it through policy, catalog, configured-model, stored-override, and fallback reference normalization.

## System Context

Auto-reply model selection turns agent configuration, session overrides, and provider/model references into the provider and model used for a reply. It consults Gateway plugin metadata to normalize provider-owned model references before the reply runtime starts.

## Architecture Diagram

flowchart LR
  A[Agent reply request] --> B[Auto-reply model selection]
  B --> C[Plugin metadata snapshot]
  C --> D[Policy and catalog normalization]
  D --> E[Provider and model selection]
  E --> F[Reply runtime request]

## Best Possible Solution

Keep one prepared snapshot per model-selection run, but use it only when it is global or demonstrably compatible with the reply’s workspace; otherwise retain the existing manifest-discovery fallback and cover both branches with focused tests.
