- `impact:other`: The issue concerns incorrect cron run accounting and alert behavior, which does not map more specifically to the owned impact taxonomy.

## Summary

The reported symptom is plausible, but current OpenClaw deliberately recognizes only a small set of documented execution-denial markers rather than treating arbitrary assistant prose as an error contract. `===DONE_ERR===` is not established as a core sentinel, so this needs a maintainer decision on the intended cron outcome protocol rather than an automatic duplicate/implemented close.

## What This Changes

Add a cron outcome rule that treats a final isolated-agent response ending in `===DONE_ERR=== …` as a failed run so failure alerts and consecutive-error accounting apply.

## Best Possible Solution

Define one documented cron outcome protocol: prefer structured runtime failures, then—only if maintainers approve it—recognize an exact final-line `===DONE_ERR===` marker with focused tests for status, alerting, and a successful/quoted-marker control case.
