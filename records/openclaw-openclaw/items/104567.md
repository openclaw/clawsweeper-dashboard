## Summary

The earlier property-order blocker is fixed, and the live evidence shows Gemini accepts the rewritten schema. However, the patch has a blocking compatibility defect: the provider-normalized schema is also the runtime validation schema, so retyping enum nodes as strings prevents the existing validator from restoring numeric and boolean values before handler execution.

## What This Changes

The PR converts supported Gemini-facing `enum` and `const` scalar values to strings, removes invalid or duplicate entries, retypes affected schema nodes as strings, and adds focused regression tests.

## Best Possible Solution

Project Gemini-compatible string enums only into the provider request while retaining the original tool schema for local coercion, validation, and handler execution, with focused tests proving both boundaries.
