## Summary

Keep open: current main and the latest release still do not provide hook/webhook-specific cleanup or archival policy; the merged cron cleanup only covers cron-keyed deleteAfterRun sessions.

## What This Changes

The issue requests configurable cleanup or archival behavior for completed webhook/hook-triggered sessions, including timing and transcript-retention controls.

## Best Possible Solution

Add an explicit hook-session lifecycle policy in core hooks config, schema/help/docs, and hook-run finalization, preserving safe defaults while supporting on-complete or delayed cleanup with clear transcript-retention semantics.

Options:

- **Add explicit hook cleanup policy (recommended):** Introduce a safe-default hooks.sessionCleanup-style policy with on-complete, delayed, and never modes plus explicit transcript-retention behavior.
- **Use generic session maintenance only:** Document that hook sessions are governed only by session.maintenance age/count/disk controls and decline hook-specific lifecycle behavior.

## Reproduction Assessment

Yes, by source inspection. Current main creates isolated hook-agent runs without cleanup intent, persists non-cron hook keys as ordinary agent session rows, and only immediate cleanup is gated to cron session keys with deleteAfterRun.

## Solution Assessment

Unclear until maintainers choose the policy. A dedicated hook lifecycle policy is more maintainable than silently reusing subagent or cron retention, but the exact defaults and transcript semantics need product approval.
