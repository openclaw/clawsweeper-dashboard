## Label Justifications

- `P2`: This is a source-confirmed hook/session lifecycle gap with storage and UI impact, but it is a bounded feature decision rather than an emergency runtime outage.
- `impact:session-state`: Completed hook sessions remain ordinary session-store entries without hook-specific lifecycle semantics.
- `impact:data-loss`: The requested policy controls transcript deletion or archival, and the current workarounds involve manually deleting session store rows or transcript files.

## Summary

Keep open: current main still does not provide a hook/webhook-specific lifecycle policy for on-complete cleanup, delayed cleanup, archival, transcript retention, or completed-hook visibility. Generic session maintenance can age out synthetic hook entries, and the merged cron cleanup helper is useful adjacent work, but neither is the requested hook policy.

## What This Changes

The issue requests configurable lifecycle cleanup and archival for hook/webhook-created sessions, including on-complete or delayed cleanup and transcript-retention controls.

## Best Possible Solution

Add an explicit, default-safe hook-session lifecycle policy in core hooks config, schema/help/docs, and hook-run finalization, with clear precedence against session.maintenance, cron cleanup, and persistent hook-session reuse.

Options:

- **Add Explicit Hook Cleanup Policy (recommended):** Introduce a default-safe hooks.sessionCleanup style policy with on-complete, delayed, and never modes plus transcript-retention behavior and focused hook/session tests.
- **Rely On Generic Session Maintenance:** Document that hook sessions are governed only by session.maintenance age/count/disk controls and close hook-specific cleanup as not planned.
- **Defer Until Persistent Mode Settles:** Pause this policy until https://github.com/openclaw/openclaw/issues/11665 and its persistent hook-session API are accepted or rejected.

## Reproduction Assessment

Yes, by source inspection. Hook-agent runs still dispatch through isolated cron-style execution and persist agent-scoped hook session rows, while cleanup paths are either broad session maintenance or cron-key gated.

## Solution Assessment

Unclear until maintainers choose the policy. A dedicated hook lifecycle policy is more maintainable than silently borrowing subagent or cron retention, but defaults and transcript semantics need product approval.
