## Summary

Current main and v2026.6.11 still lack hook-specific session lifecycle controls, and the merged cron cleanup work does not cover hook-created rows or transcript policy. The request remains useful but needs maintainer direction because disposable task hooks and persistent multi-turn hooks require conflicting defaults.

## What This Changes

Add configurable completion cleanup, delayed retention, archival, transcript preservation, and completed-session visibility behavior for hook-created sessions.

## Best Possible Solution

Add a typed hook lifecycle intent at the mapping/dispatch boundary, preserve current persistence by default, and reuse canonical session maintenance/deletion machinery with independently defined transcript-retention and list-filtering semantics.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should hook mappings support explicit persistent, cleanup-on-completion, and delayed-retention modes while retaining current persistent behavior as the compatibility default?

Rationale: OpenClaw has valid disposable task-hook and persistent multi-turn-hook use cases, so defaults, transcript ownership, and precedence with generic maintenance require maintainer intent.

Likely owner: steipete

Owner confidence: high

Options:

- **Add explicit lifecycle modes (recommended):** Preserve current persistence by default and allow mappings to opt into completion or delayed cleanup with explicit transcript handling.
- **Use generic maintenance only:** Avoid hook-specific configuration and address accumulation through session.maintenance, documentation, and session-list filtering.
- **Make hooks ephemeral by default:** Automatically remove isolated hook sessions unless a mapping explicitly requests persistent history.

## Reproduction Assessment

Yes, from current source with high confidence: hook agent requests use isolated execution with persisted session keys, while current main and v2026.6.11 expose no hook lifecycle policy. This read-only review did not execute a live webhook workload.

## Solution Assessment

Yes in direction, but not exactly as proposed: explicit hook lifecycle intent is the narrowest maintainable abstraction, while canonical session storage and maintenance should own deletion and retention mechanics rather than a separate hook cleanup subsystem.
