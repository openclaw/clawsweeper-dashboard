## Summary

Keep open: current main still lacks a hook/webhook-specific cleanup or archival policy, and the shipped cron cleanup only covers cron session keys rather than completed `hook:*` sessions.

## What This Changes

Request to add configurable auto-cleanup, archival, delay, and transcript-retention behavior for completed webhook/hook agent sessions.

## Best Possible Solution

Add a core hook-session lifecycle policy with conservative defaults, explicit archive/delete/no-op semantics, transcript retention rules, docs/schema/help updates, and tests for direct hooks, mapped hooks, Gmail preset hooks, and interaction with existing session maintenance.

## Reproduction Assessment

Yes for the current behavior: source inspection shows hook agent runs are dispatched through isolated cron-style execution, persisted under non-cron hook session keys, and excluded from cron-specific cleanup. I did not run a live Gmail webhook, but the storage and cleanup paths are clear from current main.

## Solution Assessment

No current implementation solves this issue yet. The cron-only `deleteAfterRun` fix is useful adjacent work, but the best fix is a maintainer-approved hook lifecycle policy rather than closing this issue or relying on generic age/count maintenance.
