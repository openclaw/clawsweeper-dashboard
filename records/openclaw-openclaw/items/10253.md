## Summary

Keep open: current main still has only generic session maintenance and cron-specific delete-after-run cleanup, not the requested hook/webhook lifecycle policy for completion cleanup, delayed cleanup, transcript retention, or completed-session visibility.

## What This Changes

The issue requests configurable cleanup or archival policy for completed webhook/hook sessions, including delayed cleanup and transcript retention.

## Best Possible Solution

Define a maintainer-approved hook session lifecycle contract with safe defaults, explicit archive/delete/no-op or delay modes, transcript-retention semantics, direct/mapped/Gmail hook coverage, docs/schema updates, and precedence with existing maintenance.

## Reproduction Assessment

Yes, at source level. Current main has no hook cleanup config/schema surface, dispatches hook agents through isolated cron-style execution, and only the cron-specific cleanup helper deletes cron session keys.

## Solution Assessment

Unclear until maintainers choose the lifecycle contract. A hook-specific policy is plausible, but cleanup/archive/delete defaults must be coordinated with generic session maintenance, cron retention, and persistent hook-session semantics.
