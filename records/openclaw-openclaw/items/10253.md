## Summary

Keep open: current main still lacks hook-specific cleanup, archive/delete, delayed cleanup, completed-session visibility, and transcript-retention policy; the merged cleanup work only covers cron-keyed delete-after-run sessions.

## What This Changes

Request adds a configurable lifecycle policy for completed webhook/hook agent sessions, including on-complete or delayed cleanup and transcript retention.

## Best Possible Solution

Add an explicit hook-session lifecycle policy in core hooks config, schema/help/docs, and hook-run finalization, with safe defaults plus clear on-complete or delayed cleanup and transcript-retention semantics.

## Maintainer Decision

Rationale: The source gap is clear, but the permanent config API, default cleanup behavior, transcript deletion or archival semantics, and upgrade safety are product/data-retention decisions.

Owner confidence: high

Options:

- **Add Explicit Hook Cleanup Policy (recommended):** Introduce a default-safe hooks.sessionCleanup-style policy with on-complete, delayed, and never modes plus transcript-retention behavior and focused hook/session tests.
- **Rely On Generic Maintenance:** Document that hook sessions are governed only by session.maintenance age, count, and disk controls, and close hook-specific cleanup as not planned.
- **Defer For Persistent Mode:** Pause cleanup policy until persistent hook-session semantics are settled so reuse and cleanup are designed together.

## Reproduction Assessment

Yes, by source inspection. Hook-agent runs dispatch through isolated cron-style execution, hooks lack a cleanup config surface, and the only run-end deletion helper is gated to cron session keys.

## Solution Assessment

Unclear until maintainers choose the policy. A dedicated hook lifecycle policy is more maintainable than silently reusing subagent or cron retention, but the exact defaults and transcript semantics need product approval.
