## Label Justifications

- `P2`: This is a normal-priority hook/session lifecycle improvement with concrete source evidence and limited but real production storage and session-list impact.
- `impact:session-state`: Completed hook sessions remain ordinary session rows without a hook-specific terminal lifecycle, so active-session visibility and retained session state can drift from operator intent.

## Summary

Keep open: current main and v2026.6.11 still lack a hook/webhook-specific cleanup or archival policy. The merged cron cleanup is useful adjacent work, but it only covers cron-owned session keys, and the open persistent hook-session PR addresses reuse rather than completion cleanup.

## What This Changes

Request to add a configurable cleanup/archive lifecycle policy for completed webhook/hook sessions, including delayed cleanup and transcript retention.

## Best Possible Solution

Add a core hook-session lifecycle policy with conservative defaults, explicit archive/delete/no-op semantics, transcript retention rules, schema/help/docs updates, and tests for direct hooks, mapped hooks, Gmail preset hooks, and interaction with existing session maintenance.

## Reproduction Assessment

Yes, at source level. Current main dispatches hook-agent work through isolated cron-style execution, stores non-cron hook keys as ordinary agent session rows, and excludes those keys from the cron cleanup helper.

## Solution Assessment

Unclear until maintainers decide the policy. A hook-specific lifecycle surface is the right area, but defaults, cleanup modes, transcript retention, and precedence with existing maintenance need product review before implementation.
