## Summary

Current main already provides configurable retention, pruning, archive handling, and active-list cleanup for hook-created synthetic sessions through the generic `session.maintenance` policy; a separate hook-only lifecycle config is no longer necessary for the issue's central storage-growth and UI-clutter problem.

## What This Changes

The issue requests configurable automatic cleanup or archival of completed hook/webhook sessions and their transcripts.

## Best Possible Solution

Keep the generic `session.maintenance` policy as the single lifecycle surface, using `include` or `exclude` selectors to target hook keys and archive mode when transcripts must remain recoverable.
