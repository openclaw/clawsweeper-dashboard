## Summary

Keep open: current main and the latest release still lack a hook-specific cleanup/archive policy, while the merged cleanup work is cron-only and does not cover hook-created session rows or transcript-retention choices.

## What This Changes

The issue requests configurable auto-cleanup, archival, delay, and transcript-retention behavior for completed webhook or hook-triggered sessions.

## Best Possible Solution

Define an explicit core hook session lifecycle policy with conservative defaults, schema/docs alignment, runtime finalization for direct and mapped hooks, and tests for on-complete cleanup, delayed cleanup, completed-session visibility, and transcript retention.

- **Use Existing Maintenance Only:** Decline a hook-specific lifecycle knob and document that operators should use global session.maintenance for eventual hook-session pruning.
- **Design Broader Ephemeral Sessions:** Fold hook cleanup into a wider cron/hook ephemeral-session model before adding public config surface.

## Reproduction Assessment

Yes. Source inspection shows hook-agent requests run through isolated cron-style execution, while current cleanup only applies to cron-keyed deleteAfterRun sessions; I did not run a live Gmail webhook in this read-only review.

## Solution Assessment

Unclear until maintainers choose the lifecycle contract. A hook-specific policy is plausible, but the safest implementation should make cleanup and transcript retention explicit instead of silently reusing cron or global maintenance settings.
