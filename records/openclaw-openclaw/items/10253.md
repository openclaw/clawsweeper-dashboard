## Label Justifications

- `P2`: This is a source-confirmed hook/session lifecycle gap with storage and UI impact, but it is a bounded enhancement rather than an emergency runtime outage.
- `impact:session-state`: Completed hook sessions remain in the session store and session list without hook-specific lifecycle semantics.
- `impact:data-loss`: The requested policy controls whether transcripts are retained, archived, or deleted, and the current workarounds involve manual store or file deletion.

## Summary

Keep open: current main still has no hook/webhook-specific lifecycle policy for on-complete cleanup, delayed archival, transcript retention, or completed-session visibility. The merged cron cleanup work is useful adjacent prior art, but it is gated to cron session keys and does not solve completed `agent:<id>:hook:*` rows.

## What This Changes

Request a configurable lifecycle policy for hook/webhook-created sessions so completed hook runs can be archived or cleaned up without unsafe manual session/transcript deletion.

## Best Possible Solution

Add an explicit core hook-session lifecycle policy with safe defaults, on-complete or delayed cleanup modes, clear transcript retention semantics, docs/schema/help coverage, and tests for direct `/hooks/agent`, mapped hooks, Gmail presets, and generated `hook:*` keys.
