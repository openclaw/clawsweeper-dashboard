## Label Justifications

- `P2`: This is a source-confirmed hook/session lifecycle gap with storage and UI impact, but it is a bounded enhancement rather than an emergency runtime outage.
- `impact:session-state`: Completed hook sessions remain in the session store and sessions.list without hook-specific lifecycle semantics.

## Summary

Keep open: current main and v2026.6.11 still lack a hook/webhook-specific cleanup or archival policy; the merged cleanup work is cron-key-gated and does not provide on-complete, delayed, visibility, or transcript-retention semantics for hook sessions.

## What This Changes

The issue requests configurable cleanup, archival, and transcript-retention behavior for completed webhook/hook agent sessions.

## Best Possible Solution

Add an explicit hook-session lifecycle policy in core hooks config, schema/help/docs, and hook-run finalization, with safe defaults plus on-complete or delayed cleanup and clear transcript-retention semantics.

## Maintainer Decision

Question: What hook-session lifecycle policy should OpenClaw support for completed webhook agent runs, and how should it interact with generic session maintenance, cron retention, and persistent hook sessions?

Rationale: The source gap is clear, but the permanent config API, default behavior, transcript deletion or archival semantics, and upgrade safety are product/data-retention decisions.

Likely owner: steipete

Owner confidence: high

Options:

- **Add Explicit Hook Cleanup Policy (recommended):** Introduce a default-safe hooks.sessionCleanup-style policy with on-complete, delayed, and never modes plus transcript-retention behavior and focused hook/session tests.
- **Rely On Generic Maintenance:** Document that hook sessions are governed only by session.maintenance age/count/disk controls and close the request for hook-specific cleanup.
- **Defer Until Persistent Hooks Settle:** Pause cleanup policy until the persistent hook-session direction is settled so cleanup and reuse semantics are designed together.

## Reproduction Assessment

Yes, by source inspection. Current main routes hook-agent runs through isolated cron execution, persists non-cron hook keys as ordinary agent session rows, and only cleans up cron-key sessions when deleteAfterRun is true.

## Solution Assessment

Unclear until maintainers choose the policy. A dedicated hook lifecycle policy is more maintainable than silently reusing subagent or cron retention, but the defaults and transcript semantics need product approval.
