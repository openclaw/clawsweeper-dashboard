## Summary

Keep open: current main still persists hook-triggered isolated runs without a hook-specific completion, retention, archival, transcript-retention, or completed-session visibility policy; the merged cron cleanup work does not solve the hook lifecycle request.

## What This Changes

Add configurable cleanup, archival, transcript-retention, and completed-session visibility behavior for hook-triggered agent sessions.

## Best Possible Solution

Add an explicit core-owned lifecycle classification for hook sessions, defaulting to current preservation behavior, then expose the smallest config-only policy that can select persistent versus task-scoped retention and route cleanup through the canonical session deletion/archive service with transcript-safe tests.

## Solution Assessment

Unclear until maintainers choose lifecycle semantics. A dedicated core cleanup owner is appropriate, but the proposed multi-mode config may be broader than necessary; a compatibility-preserving retention-first contract is the safer initial solution.
