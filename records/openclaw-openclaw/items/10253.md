## Label Justifications

- `P2`: This is a source-confirmed hook/session lifecycle gap with storage and UI impact, but it is a bounded enhancement rather than an emergency runtime outage.
- `impact:session-state`: Completed hook sessions remain in the session store and session list without hook-specific lifecycle semantics.
- `impact:data-loss`: The requested policy controls whether transcripts are retained, archived, or deleted, and the current workarounds involve manual store or file deletion.

## Summary

Keep open: current main still lacks a hook/webhook-specific lifecycle policy for on-complete cleanup, delayed cleanup, archival, or transcript-retention semantics. The merged cron cleanup work is useful adjacent prior art, but it is gated to cron session keys and does not solve completed `agent:<id>:hook:*` rows.

## What This Changes

Add a configurable cleanup and archival policy for completed webhook or hook-triggered sessions so hook session rows and transcripts do not accumulate indefinitely.

## Best Possible Solution

Add an explicit hook-session lifecycle policy in core hooks config, schema/help/docs, and hook-run finalization, preserving safe defaults while supporting on-complete or delayed cleanup with clear transcript-retention semantics.

Options:

- **Add Explicit Hook Cleanup Policy (recommended):** Introduce a default-safe `hooks.sessionCleanup` style policy with on-complete, delayed, and never modes plus transcript-retention behavior and focused hook/session tests.
- **Rely On Generic Maintenance:** Document that hook sessions are governed only by `session.maintenance` age, count, and disk controls, and close hook-specific cleanup as not planned.
- **Defer For Persistent Mode:** Pause cleanup policy until persistent hook-session semantics are settled so reuse and cleanup are designed together.

## Reproduction Assessment

Yes, by source inspection. Hook-agent runs normalize `hook:*` keys into `agent:<id>:hook:*` session rows, and the existing run-end cleanup helper is gated to cron session keys.

## Solution Assessment

Unclear until maintainers choose the policy. A dedicated hook lifecycle policy is more maintainable than silently reusing subagent or cron retention, but the exact defaults and transcript semantics need product approval.
