## Summary

Keep open: current main still has no hook/webhook-specific cleanup or archival policy, and the merged cron cleanup work only handles cron session keys, not completed `hook:*` sessions.

## What This Changes

Request to add configurable lifecycle cleanup or archival policy for webhook/hook sessions so completed hook sessions can be removed or archived without manual session/transcript edits.

## Best Possible Solution

Define a maintainer-approved hook session lifecycle contract with safe defaults, explicit archive/delete/no-op or delay modes, transcript-retention semantics, direct/mapped/Gmail hook coverage, docs/schema updates, and precedence with existing maintenance.

## Reproduction Assessment

Yes, at source level. Current main lacks a hook cleanup config/schema surface, dispatches hook agents through isolated cron-style execution, and only the cron-specific cleanup helper deletes cron session keys.

## Solution Assessment

Unclear until maintainers choose the lifecycle contract. A hook-specific policy is plausible, but cleanup/archive/delete defaults must be coordinated with generic session maintenance, cron retention, and persistent hook-session semantics.
