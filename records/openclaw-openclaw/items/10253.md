## Summary

Keep open for maintainer product direction. Current main still persists hook-created sessions without a hook-specific completion, TTL, archival, transcript-retention, or completed-session visibility policy; generic maintenance can eventually age them out, while the merged cleanup work applies only to cron jobs.

## What This Changes

Add configurable completion- or time-based cleanup, archival, transcript retention, and completed-session visibility behavior for hook-created sessions.

## Best Possible Solution

Add a default-off hook lifecycle policy with explicit completion or TTL modes, transcript retention behavior, completed-session visibility, and documented precedence over generic maintenance, while preserving stable-key persistent hook sessions by default.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should hook-created sessions gain a dedicated lifecycle policy, and which default preserves existing persistent-session and transcript expectations?

Rationale: Generic maintenance bounds storage eventually, but completion deletion, delayed cleanup, visibility, and transcript retention create new compatibility and data-retention semantics that require maintainer intent.

Likely owner: Peter Steinberger

Owner reason: He has the strongest current-main history and issue-discussion signal across the hook configuration and dispatch decision surface.

Owner confidence: high

Options:

- **Add opt-in hook lifecycle (recommended):** Introduce a default-off hook policy with explicit completion or TTL cleanup and transcript handling, preserving current behavior for existing configurations.
- **Use generic maintenance only:** Document session.maintenance as the supported cleanup mechanism and decline another hook-specific configuration surface.
- **Unify ephemeral sessions:** Design a shared task-scoped ephemeral-session contract for hooks and cron instead of adding a hook-only lifecycle policy.

## Reproduction Assessment

Yes. Current-main types, strict schemas, dispatch code, tests, and docs establish that hook sessions have no hook-specific completion or retention lifecycle and rely only on generic age/cap maintenance.

## Solution Assessment

Unclear pending product direction. A default-off dedicated policy is safer than reusing subagent timing, but maintainers should decide whether the permanent contract belongs under hooks or in a shared ephemeral-session abstraction.
