- `P2`: This is a source-confirmed hook/session lifecycle gap with storage and UI impact, but it is a bounded enhancement rather than an emergency runtime outage.

## Summary

Keep open: current main and the latest release still lack a hook/webhook-specific cleanup or archival policy, and the merged cron cleanup only applies to cron session keys with `deleteAfterRun`.

## What This Changes

The issue requests configurable lifecycle cleanup for hook/webhook agent sessions, including on-complete or delayed archival/removal and transcript-retention control.

## Best Possible Solution

Add an explicit hook-session lifecycle policy in core hooks config, schema/help/docs, and hook-run finalization, preserving safe defaults while supporting on-complete or delayed cleanup with clear transcript-retention semantics.

## Maintainer Decision

Question: What hook-session lifecycle policy should OpenClaw support for completed webhook agent runs, and how should it interact with generic session maintenance and persistent hook sessions?

Rationale: The source gap is clear, but the permanent config API, default behavior, transcript deletion/archival semantics, and upgrade safety are product decisions with data-retention consequences.

Owner confidence: medium

Options:

- **Add explicit hook cleanup policy (recommended):** Introduce a default-safe `hooks.sessionCleanup` style policy with on-complete, delayed, and never modes plus transcript-retention behavior and focused hook/session tests.
- **Reuse generic maintenance only:** Document that hook sessions are governed only by `session.maintenance` age/count/disk controls and close the request for hook-specific cleanup.
- **Wait for persistent mode decision:** Defer cleanup policy until the persistent hook-session direction is settled so cleanup and reuse semantics are designed together.

## Reproduction Assessment

Yes by source inspection. Current main routes hook-agent runs through isolated cron execution, persists non-cron `hook:*` keys as ordinary agent session rows, and only cleans up cron-key sessions when `deleteAfterRun` is true.

## Solution Assessment

Unclear until maintainers choose the policy. A dedicated hook lifecycle policy is more maintainable than silently reusing subagent or cron retention, but the exact defaults and transcript semantics need product approval.
