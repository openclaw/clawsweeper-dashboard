## Summary

Keep open: current main still lacks a hook-specific configurable cleanup/archive policy, and the merged cron cleanup path only handles cron-owned session keys rather than completed webhook or Gmail hook sessions.

## What This Changes

The issue requests configurable lifecycle cleanup for webhook/hook-created sessions, including completion-based or delayed archival/removal and transcript-retention controls.

## Best Possible Solution

Define a maintainer-approved hook lifecycle contract with safe defaults, explicit archive/delete/no-op or delay modes, transcript-retention semantics, direct/mapped/Gmail hook coverage, docs/schema updates, and precedence with existing maintenance.

## Reproduction Assessment

Yes, at source level. Current main has no hook cleanup config/schema surface, dispatches hook agents through isolated cron-style execution, and only the cron-specific cleanup helper deletes cron session keys.

## Solution Assessment

Unclear until maintainers choose the lifecycle contract. A hook-specific policy is plausible, but cleanup/archive/delete defaults must be coordinated with generic session maintenance, cron retention, and persistent hook-session semantics.
