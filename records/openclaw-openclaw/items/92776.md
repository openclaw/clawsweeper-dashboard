## Summary

Keep open. A July 23 report describes the same auto-fallback provenance shape on stable `v2026.7.1`, including a direct Telegram session that then selected the recorded origin model and timed out without a visible response. The merged primary-probe work from May established the intended recovery behavior, but the available issue evidence does not show that current `main` corrects the initial provenance write or repairs already-polluted session records.

Likely related people: `steipete` is the strongest routing candidate because the merged primary-probe implementation originated in the fallback-recovery work; confidence is medium.

## What This Changes

Fix automatic model fallback so session provenance records the configured primary correctly and later turns can safely retry it instead of remaining pinned to a fallback route.

## System Context

OpenClaw resolves an agent’s configured primary and fallback models for each run, then records automatic fallback state in the session entry. On later turns, the agent session layer uses that persisted provenance to decide whether it can retry the configured primary or must keep the fallback route.

## Architecture Diagram

flowchart LR
  A[Agent model configuration] --> B[Fallback candidate selection]
  B --> C[Automatic fallback result]
  C --> D[Persisted session override and origin]
  D --> E[Next user or channel turn]
  E --> F[Primary retry decision]
  F --> G[Configured primary or fallback route]

## Best Possible Solution

Preserve the existing automatic primary-retry contract by recording the configured primary at the first automatic fallback, add focused regressions for multi-step fallback chains and direct Telegram sessions, and provide a Doctor-owned repair for already-polluted automatic entries after validating that it cannot clear user-selected overrides.

Rationale: Both paths can prevent indefinite pinning, but they differ in the persisted-session contract established by the merged primary-probe behavior and in upgrade semantics for existing sessions.

- **Repair provenance and migrate polluted auto state (recommended):** Keep the current probe-backed automatic fallback model, write the configured primary as origin, and repair only proven stale automatic entries through Doctor.

- **Pause for a narrower root-cause split:** First separate wrong-candidate selection after hot reload from provenance pollution if they prove to be independent defects.
