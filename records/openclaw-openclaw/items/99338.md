## Summary

Keep open: the payload guard is a useful direction, but it runs too late for the reported text-only OpenAI-compatible path because `transformMessages` downgrades `type: "image"` tool blocks before the changed extractor can recover them.

## What This Changes

The PR adds a media-payload guard to shared tool-result text extraction and regression tests for payload-less media-typed blocks.

## Best Possible Solution

Move or share the payload validation at the pre-extractor image downgrade and provider image-forwarding boundary, then keep the shared extractor tests as regression coverage.

## Reproduction Assessment

Yes, source-reproducible: current OpenAI completions conversion calls `transformMessages` first, and that transform replaces `type: "image"` tool-result blocks for text-only models before `extractToolResultText` runs.

## Solution Assessment

No. The shared-helper guard is useful, but the best fix must also guard the earlier unsupported-image downgrade and prove the full DeepSeek-style `convertMessages` path.
