## Summary

The patch targets a credible current-main race: `update.run` performs several awaited setup steps before the existing managed-handoff guard, while the direct update path has no equivalent serialization. The handler-level guard is a narrow, plausible fix, but this external PR needs redacted after-fix runtime evidence before merge because its only supplied proof is a mocked gateway-method test harness.

## What This Changes

The PR adds a module-level single-flight guard to the gateway `update.run` RPC handler and adds focused tests for concurrent direct and managed-handoff update requests.

## Best Possible Solution

Keep one process-wide guard at the `update.run` entry boundary, retain the existing managed-handoff guard as defense in depth, and add redacted real-gateway before/after evidence showing rejection of a concurrent request and normal completion of the original request.
