## What This Changes

The branch adds an opt-in `returnEvents` mode to the shared realtime voice-session harness and changes the Gateway relay to forward those authoritative Talk events rather than recreate them.

## System Context

The shared realtime voice-session harness owns Talk turn and audio lifecycle events for realtime transports. The Gateway relay uses the harness to create owner-scoped Gateway messages, so it must preserve the existing behavior for every harness caller that does not opt into event returns.

## Architecture Diagram

flowchart LR
  Transport[Realtime voice transport] --> Relay[Gateway realtime relay]
  Relay --> Harness[Shared session harness]
  Harness --> Controller[Talk session controller]
  Controller --> Events[Authoritative Talk events]
  Events --> Relay
  Relay --> Owner[Owner-scoped Gateway stream]

## Best Possible Solution

Retain one authoritative event owner in the shared harness, make the relay consume the returned events only through its explicit opt-in, and land after a maintainer confirms non-opt-in caller compatibility.
