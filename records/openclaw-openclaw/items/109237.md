## Label Justifications

- `P0`: The current bug is a plugin deny-policy bypass that can load operator-blocked runtime code, but the proposed fix still needs a security-boundary correction before merge.
- `merge-risk: 🚨 compatibility`: Positive policy folding changes upgrade behavior for existing mixed-case and case-colliding third-party plugin IDs and their persisted allow or entry settings.
- `merge-risk: 🚨 security-boundary`: The patch changes how plugin allowlists and manifest-owner trust authorize declared identities, and distinct case-colliding IDs can share that authorization key.

## Summary

The denylist and reserved-ID bypass is real, and the revised patch correctly preserves manifest/runtime identity, but it now uses the same lowercase key for positive allowlist and entry trust without preventing distinct manifest IDs that differ only by case. That leaves a merge-blocking plugin authorization collision requiring an explicit identity-boundary fix.

## What This Changes

The PR preserves manifest-declared plugin IDs while using a lowercase derived key for deny, allow, per-entry activation, manifest-owner trust, and reserved-ID policy comparisons.

## Best Possible Solution

Preserve the declared manifest/runtime ID, make negative deny and reserved checks case-insensitive, and define a single safe positive-policy identity by rejecting case-folded discovery collisions before allowlist, entry, or owner-trust evaluation, with regression coverage for two case-distinct manifests.
