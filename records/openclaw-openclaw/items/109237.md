## Summary

Keep this PR open: it addresses a valid plugin-policy bypass with strong regression evidence, but lowercasing the parsed manifest ID also changes the plugin’s public identity and may create drift from existing mixed-case runtime exports or package metadata. Maintainer confirmation of the canonical ID contract and full-runtime compatibility proof are needed before merge.

## What This Changes

Lowercase manifest-declared plugin IDs at parse time and add regression coverage for denylist, allowlist, per-entry disablement, reserved IDs, and already-lowercase IDs.

## Best Possible Solution

Preserve the declared manifest ID for the public manifest/runtime contract while introducing one canonical lowercase policy identity used consistently for allow, deny, entries, reserved-ID, duplicate-selection, and registry comparisons; document that contract and prove both denied and allowed mixed-case plugins through a full runtime load.
