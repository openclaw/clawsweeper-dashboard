## Summary

The reported policy bypass remains necessary to fix, and the PR has a strong root-cause analysis, but it is not merge-ready: the parse-boundary change can break the shipped manifest/runtime identity contract for existing mixed-case third-party plugins, while the new Gateway evidence is still test-fixture proof rather than an observed live installation.

## What This Changes

The PR lowercases native manifest-declared plugin IDs at parse time and adds unit and Gateway integration coverage for denylist, allowlist, disabled-entry, reserved-ID, and runtime-registration behavior.

## Best Possible Solution

Preserve the public manifest/runtime identity contract while deriving one canonical lowercase policy key for deny, allow, entry, reserved-ID, registry, and duplicate checks; add an upgrade regression for a previously matching mixed-case manifest/runtime pair and prove the result on a real installed plugin through `plugins inspect --runtime --json` or redacted Gateway logs.
