## Summary

Keep this PR open. It has a real WeChat multi-account reliability goal and its generic Gateway direction is plausible, but the current branch still does not make the catalogued, loaded Weixin plugin provide the new reload-marker capability, and a permanently hung private handoff can leave an account offline. It also lacks provider-level after-fix proof or an explicit gateway-owner waiver.

## What This Changes

This PR adds Gateway reload handoff logic and plugin reload metadata intended to keep an already-running WeChat account online when a second account refreshes the channel-owned account index.

## System Context

Gateway config changes are converted into reload plans, which stop and restart channel account runtimes. This change adds a plugin-declared account-index marker so the Gateway can preserve active accounts during an external channel's account-list refresh without reviving accounts removed by ordinary configuration edits.

## Best Possible Solution

Keep the generic Gateway capability, but have the loaded Weixin plugin release and declare the reload marker itself (then update the official catalog pin), add a bounded recovery path for permanently hung paired handoffs, and obtain redacted live WeChat A+B evidence or an explicit gateway-owner waiver before merge.
