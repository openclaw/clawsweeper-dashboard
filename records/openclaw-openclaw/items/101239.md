## Summary

Keep open: current main now handles plain physical Enter, but the reopened live Android E2E found a narrower repeat/key-up sequence bug and current source still lets repeated Enter key-downs and key-up events fall through after the initial send.

## What This Changes

Request Android chat composer behavior where physical Enter sends a message, modified Enter remains text input, and owned Enter key sequences do not leak repeat/key-up events into the text field.

## Best Possible Solution

Update the shared Android hardware-key handler so the first unmodified Enter sends once, any owned repeat/key-up events are consumed without inserting text, modified/composing IME sequences still pass through, and the behavior is proven with focused Robolectric plus live emulator coverage.
