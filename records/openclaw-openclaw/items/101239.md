## Summary

Keep open: current main handles plain physical Enter, but the reopened live Android E2E and current source show the held-key sequence remains incomplete because repeats and the paired key-up still fall through after the first send. The only open linked PR is a blocked earlier attempt, not a canonical fix for the remaining sequence bug.

## What This Changes

Android physical-keyboard Enter should submit chat messages while preserving multiline/composing input and handling held-key repeat/key-up events cleanly.

## Best Possible Solution

Make the Android hardware-Enter handler sequence-aware and shared by ChatScreen and the sheet composer: consume repeat/key-up events for a claimed plain Enter, leave modified and composing IME sequences intact, and prove it with focused Robolectric coverage plus live Android emulator/device proof.
