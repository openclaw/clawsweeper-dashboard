  - body: `resolveMemorySearchConfig` and the schema make isolation default to enabled, but this resolver returns `null` when `memory.isolation` is absent, so existing configs create unscoped memory tools and the QMD fail-closed guard never runs. Use one canonical resolver/default path and cover the absent-config case, otherwise the advertised default privacy boundary is not enforced.
  - confidence: 0.91
- **[P1] Scope the QMD indexed corpus, not only manager state:** `extensions/memory-core/src/memory/search-manager.ts:61-64`
  - body: This threads `userId` into the QMD cache key and manager, but `resolveMemoryBackendConfig(params)` still builds the default QMD collections from the whole workspace `memory/**/*.md` tree before any user scope is applied. Per-user QMD managers would still search the same shared memory corpus, so `memory_search` can return another user's notes.
  - confidence: 0.88
- **[P1] Route memory flush files out of the shared root:** `packages/memory-host-sdk/src/host/internal.ts:263-264`
  - body: In isolated mode this still adds root-level `memory/*.md` to every user's results, while current memory-core flush plans write compaction output to `memory/YYYY-MM-DD.md`. A flush from one user will therefore be indexed/read as shared memory for other users unless flush writes are user-scoped or root files are treated with an explicit shared-memory policy and proof.
  - confidence: 0.86
- **[P1] Preserve upgrade behavior before defaulting isolation on:** `src/agents/memory-search.ts:421-423`
  - body: Defaulting `memory.isolation.enabled` to true changes the memory layout and lookup semantics for existing shared-memory deployments, but the PR has no doctor migration, legacy shared-root policy, or maintainer-approved compatibility path. Keep the shipped default stable or add the explicit migration and proof before changing this runtime default.
  - confidence: 0.84
