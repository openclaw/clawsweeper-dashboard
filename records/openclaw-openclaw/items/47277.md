Overall correctness: patch is incorrect

Overall confidence: 0.87

Full review comments:

- **[P1] Honor default-on isolation when the config block is absent:** `extensions/memory-core/src/isolation-identity.ts:65-66`
  - body: `resolveMemorySearchConfig` reports isolation as enabled when `memory.isolation` is omitted, but this resolver returns `undefined` for the same config because `readIsolation()` returns null. That makes default installs appear isolated while `memory_search`/`memory_get` and the QMD guard run without a user scope.
  - confidence: 0.93
- **[P1] Scope QMD collections, not only state directories:** `extensions/memory-core/src/memory/qmd-manager.ts:347-351`
  - body: This creates a per-user QMD state directory, but `resolved.qmd.collections` still points at the workspace root memory file and `memory/**/*.md`. Each user's QMD index can therefore ingest the same workspace-wide memory collection and return another user's files despite the per-user cache/state path.
  - confidence: 0.9
- **[P1] Stop indexing shared flush files for every isolated user:** `src/memory-host-sdk/host/internal.ts:213`
  - body: In isolation mode this still indexes root-level `memory/*.md` for every user. The current memory-flush plan writes durable compaction notes to `memory/YYYY-MM-DD.md`, so one user's flushed session memories can be scanned and returned to other isolated users unless flushes are user-scoped or root files are explicitly non-private shared memory.
  - confidence: 0.88
- **[P1] Bound per-user memory manager cache growth:** `extensions/memory-core/src/memory/manager.ts:169-171`
  - body: Adding `userId` to the builtin manager cache key creates a long-lived cached manager per sender, and those managers own SQLite handles, watchers, timers, and dirty-sync state until explicit close. A busy channel deployment can accumulate unbounded per-user managers unless this uses bounded eviction/idle teardown or a shared manager with per-request scoping.
  - confidence: 0.82
