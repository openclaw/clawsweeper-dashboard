Full review comments:

- **[P1] Honor default-on isolation when config is absent:** `extensions/memory-core/src/isolation-identity.ts:64-66`
  - body: `resolveMemorySearchConfig` now treats missing `memory.isolation` as enabled, but this resolver returns `undefined` when the block is absent. A fresh install with no isolation block can therefore create unscoped memory managers even though the rest of the branch believes isolation is default-on.
  - confidence: 0.92
- **[P1] Scope QMD collections, not only QMD state dirs:** `extensions/memory-core/src/memory/qmd-manager.ts:347-351`
  - body: This adds a per-user QMD state directory, but the resolved QMD collections are still built from the agent-wide workspace memory tree. Each user's separate index can still ingest the same `memory/**/*.md` corpus, so QMD does not enforce the per-user privacy boundary this PR advertises.
  - confidence: 0.9
- **[P1] Do not share flush root files across isolated users:** `src/memory-host-sdk/host/internal.ts:199-213`
  - body: Isolated builtin scans still include root-level `memory/*.md` files for every user. Since current memory flush writes durable notes to the root memory directory, one user's compaction output can remain searchable by other isolated users unless the PR moves flush writes or documents a maintainer-approved shared-memory contract.
  - confidence: 0.86
- **[P1] Add upgrade policy before default-on isolation:** `src/agents/memory-search.ts:420-426`
  - body: The branch makes missing config resolve to isolation enabled, but existing users already have shared `MEMORY.md`, `memory/`, and QMD index state. Without a doctor migration or explicit compatibility policy, upgrading can silently hide prior memory, fail closed for contexts without sender identity, or change retrieval semantics.
  - confidence: 0.88
