- **[P1] Honor default-on isolation when config is absent:** `extensions/memory-core/src/isolation-identity.ts:64-66`
  - body: `resolveMemorySearchConfig()` now reports isolation as enabled by default, but this resolver returns `undefined` whenever the `memory.isolation` block is absent. On a normal config with no new block, `memory_search` and `memory_get` get no user scope instead of failing closed or deriving one, so the advertised default-on privacy boundary is bypassed.
  - confidence: 0.94
- **[P1] Scope QMD collections, not only state directories:** `extensions/memory-core/src/memory/qmd-manager.ts:347-350`
  - body: This only moves QMD's XDG state/cache under a per-user directory; the resolved default collections still point at workspace `MEMORY.md` and `memory/**/*.md`. Each isolated QMD manager can therefore build its own index from every user's memory files, so QMD search remains cross-user despite the new cache/state key.
  - confidence: 0.93
- **[P1] Stop indexing shared flush files for every isolated user:** `src/memory-host-sdk/host/internal.ts:213`
  - body: In isolation mode this still adds root-level `memory/*.md` files for every user. The current memory flush plan writes private compaction notes to `memory/YYYY-MM-DD.md` by default, so one user's durable flush can be indexed and returned to another isolated user.
  - confidence: 0.91
- **[P1] Define the upgrade path for default-on memory isolation:** `src/config/zod-schema.ts:119-128`
  - body: The new schema accepts a default-on privacy/config surface, but the PR does not define how existing shared root memory files or old QMD indexes migrate, stay intentionally shared, or get rebuilt. Existing deployments can silently lose expected memory visibility or keep sharing sensitive notes unless this policy is explicit and tested.
  - confidence: 0.86
