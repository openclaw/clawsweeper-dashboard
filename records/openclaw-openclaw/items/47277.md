Full review comments:

- **[P1] Honor default-on isolation when config is absent:** `extensions/memory-core/src/isolation-identity.ts:27-29`
  - body: `readIsolation()` returns `null` when the config has no `memory.isolation` block, and `resolveIsolationIdentity()` treats that as disabled. Since the schema/search config default isolation to enabled, normal fresh or upgraded configs can still create memory managers with `userId` undefined and use shared memory instead of the promised isolated path.
  - confidence: 0.93
- **[P1] Scope QMD collections, not only QMD state dirs:** `extensions/memory-core/src/memory/qmd-manager.ts:347-351`
  - body: The new per-user QMD state directory creates separate indexes, but the collection list is still resolved before `userId` is known and points at `memory/**/*.md`. With user folders under `memory/`, each user's QMD index can ingest other users' files, so QMD isolation is not end to end.
  - confidence: 0.88
- **[P1] Keep root flush files out of every isolated scan:** `src/memory-host-sdk/host/internal.ts:213`
  - body: In isolated mode this still indexes root-level `memory/*.md` for every user. The existing memory flush plan writes durable compaction memories to `memory/YYYY-MM-DD.md`, so one user's flushed memories can be returned to other isolated users unless flush writes are scoped or root flush files are excluded.
  - confidence: 0.87
- **[P1] Add an upgrade policy before default-on isolation:** `src/config/zod-schema.ts:121-126`
  - body: The schema accepts a new default-on `memory.isolation` block, but the PR does not define how existing shared `memory/` files, QMD indexes, or users who relied on shared memory are migrated or intentionally preserved. That is a compatibility break for existing setups and needs a maintainer-approved default plus migration/docs proof before merge.
  - confidence: 0.84
