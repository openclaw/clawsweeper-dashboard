## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Honor default-on isolation when config is absent:** `extensions/memory-core/src/isolation-identity.ts:27-29`
  - body: `memory.isolation.enabled` is documented and schema-defaulted to true, but `readIsolation()` returns `null` when the block is absent and `resolveIsolationIdentity()` then returns `undefined`. Existing configs without the new block therefore run unscoped, and QMD's fail-closed guard is also bypassed, which defeats the claimed default-on privacy behavior.
  - confidence: 0.94
- **[P1] Scope the QMD indexed corpus, not only QMD state dirs:** `extensions/memory-core/src/memory/qmd-manager.ts:347-351`
  - body: Passing `userId` into `resolveQmdAgentDir()` gives each user separate QMD state, but the default QMD collection still points at the workspace `memory/**/*.md` corpus. Each per-user QMD manager can therefore index every user's files into its private index, so `memory_search` can still return another user's memory unless the collection paths or query filters are user-scoped too.
  - confidence: 0.91
- **[P1] Route flush memory out of the shared root in isolation mode:** `src/memory-host-sdk/host/internal.ts:213`
  - body: In isolation mode this still indexes root-level `memory/*.md` for every user. The existing compaction flush plan writes durable notes to `memory/YYYY-MM-DD.md`, so one user's automatic memory flush remains visible to every other isolated user unless that shared-root boundary is explicitly redesigned or approved.
  - confidence: 0.9
