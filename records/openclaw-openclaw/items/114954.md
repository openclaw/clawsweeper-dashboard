## What This Changes

The branch makes OpenClaw’s agent `edit` and `apply_patch` tools strictly decode existing files as UTF-8 and reject invalid byte sequences before a whole-file rewrite can corrupt untouched bytes.

## System Context

Agent coding tools read a target file, match or apply a requested text change, and then write the resulting content back to disk. This change sits at the byte-to-text boundary so invalidly encoded files fail before the edit or patch pipeline can produce a lossy rewrite.

## Architecture Diagram

flowchart LR
  A[Agent edit or patch request] --> B[Read target file bytes]
  B --> C{Valid UTF-8?}
  C -->|No| D[Return clear error]
  D --> E[Leave original bytes intact]
  C -->|Yes| F[Match and apply requested change]
  F --> G[Write updated text]
  G --> H[Return tool result]

## Best Possible Solution

Keep one focused strict-decode fix, retain byte-preservation regression coverage for every existing-file read path, and accept the intentional failure mode rather than preserving a workflow that silently corrupts file contents.
