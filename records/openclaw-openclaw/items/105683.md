## Summary

Current main still silently replaces valid authored JSON5 with freshly serialized JSON, so comments and commented-out settings are lost during normal config mutations. The report is valid, focused, and not owned by another active issue or pull request.

## What This Changes

Preserve user-authored JSON5 comments and commented-out content when OpenClaw updates `openclaw.json`.

## Best Possible Solution

Add lossless authored-document mutation to the centralized config writer, preserving untouched comments while retaining every existing semantic validation and atomic-write safeguard, with canonical serialization reserved for new or unrecoverably invalid files.

## Reproduction Assessment

Yes at source level with high confidence: valid JSON5 is parsed into plain values and the final full-document serializer is `JSON.stringify`, which has no representation for comments. A live temporary-home run was not needed to establish that deterministic path.

## Solution Assessment

No, the separate runtime JSON-file proposal is not the best fix because it conflicts with the repository's canonical-config and SQLite state rules. The narrow maintainable solution is lossless editing inside the existing centralized writer.
