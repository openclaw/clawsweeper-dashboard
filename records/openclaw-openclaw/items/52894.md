## Summary

Keep open. Current main and the latest release still intentionally show Homebrew guidance or missing-brew failures instead of installing Homebrew, and changing that behavior needs maintainer product/security direction.

## What This Changes

The issue requests automatic Homebrew installation when a brew-backed skill dependency is selected and `brew` is missing.

## Best Possible Solution

Keep manual Homebrew guidance unless maintainers approve an explicit-consent bootstrap policy; if approved, implement it through the shared skill install lifecycle with docs and coverage for onboarding, direct install, macOS, Linux, and container cases.

Question: Should OpenClaw skill setup ever execute the Homebrew bootstrap installer when `brew` is missing, and under what consent/security policy?

Rationale: The source path is clear, but automation should not decide whether onboarding may run external package-manager bootstrap code on the user's machine.

Likely owner: fuller-stack-dev

Owner reason: They most recently owned the shared skill installer readiness path that would need to carry or reject this behavior.

Owner confidence: medium

Options:

- **Keep Manual Guidance (recommended):** Preserve the current policy: show Homebrew guidance, skip unavailable brew-backed installers, and avoid executing the Homebrew bootstrapper from skill setup.
- **Add Explicit Bootstrap:** Allow an opt-in Homebrew bootstrap flow with maintainer-approved consent, provenance, timeout, logging, platform, and failure handling.
- **Limit Auto-Brew To Installer:** Keep automatic Homebrew installation only in the top-level OpenClaw installer when needed for Node or Git, and leave skill dependencies manual.
