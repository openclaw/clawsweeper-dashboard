## Label Justifications

- `P2`: The defect accumulates disk and rotation overhead in long-lived sessions but does not establish an immediate universal outage or data-loss emergency.
- `impact:session-state`: Unreachable transcript branches remain in persisted session lineage files and distort session-state size and maintenance behavior.

## Summary

Keep open: current main and the latest release still exhibit the reported retention mechanism, and neither related open PR addresses unreachable-entry collection during successor rotation.

## What This Changes

Prune unreachable transcript branches during compaction successor rotation so overflow-rewrite debris is not copied indefinitely.

## Best Possible Solution

During successor construction, retain the active leaf ancestry after existing compaction pruning plus only metadata explicitly referenced by retained entries, then add a rewrite-then-rotate regression proving abandoned suffix entries disappear without losing labels, state entries, compaction boundaries, or preserved assistant/tool-result turns.

Yes in direction: successor rotation is the narrowest existing full-rewrite choke point, but the implementation should compute a tested reachable/reference closure instead of blindly discarding every non-active entry.
