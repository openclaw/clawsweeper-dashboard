## Label Justifications

- `P2`: The issue describes a real production HA reliability gap, but the remaining work is an architectural feature rather than an urgent confirmed regression.
- `impact:message-loss`: Multiple Gateway instances can duplicate scheduled channel deliveries when cron jobs run without shared ownership.

## Summary

Keep open: current main and the latest release still implement cron as Gateway-local scheduling with process-local locks, and no merged related issue or PR owns the cron-specific HA coordination contract.

## What This Changes

The issue requests distributed coordination or leader election so multiple Gateway instances do not run the same cron job concurrently.

## Best Possible Solution

Define a backend-neutral cron ownership contract first, then implement leased claiming or leader election with upgrade-safe config or plugin API, health/status and CLI visibility, docs, and separate-process tests.
