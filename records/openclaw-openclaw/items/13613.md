## Summary

Keep open. Current main and latest release v2026.6.11 still have Gateway-local cron scheduling, process-local cron serialization, no distributed lease/leader API, no coordination config, and no HA cron status surface; related horizontal-scaling issues overlap but do not replace this narrower cron-ownership tracker.

## What This Changes

The issue requests distributed coordination for cron jobs so multiple Gateway instances do not run the same scheduled work concurrently.

## Best Possible Solution

Define a supported distributed cron ownership contract first, then implement backend-neutral fenced claiming or leader leasing with upgrade-safe config or a plugin API, health/CLI visibility, docs, and separate-process tests.

## Reproduction Assessment

Yes for source confirmation, not as a bug reproduction: current main has no shared cron lease, leader check, coordination config, or coordination API across independent Gateway processes. I did not run a live multi-host reproduction in this read-only review.

## Solution Assessment

No, not as the backend-specific Redis/etcd/DynamoDB config proposal alone. The best path needs maintainer direction on the ownership boundary, failure semantics, backend neutrality, and whether coordination belongs in core or a plugin/API seam.
