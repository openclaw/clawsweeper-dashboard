## Summary

Keep open: current main and v2026.6.11 still have Gateway-local cron execution with process-local coordination only, so the HA cron ownership gap remains and needs maintainer architecture direction.

## What This Changes

The issue requests distributed cron job ownership or locking so multiple Gateway instances do not run the same scheduled job concurrently.

## Best Possible Solution

Define a backend-neutral cron ownership contract first, then implement leased claiming or leader election with upgrade-safe config or plugin API, health/status and CLI visibility, docs, and separate-process tests.
