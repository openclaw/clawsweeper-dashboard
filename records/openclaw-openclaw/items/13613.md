## Summary

Keep open: current main and the latest release still lack cross-Gateway cron ownership, leader election, distributed leases, coordination config, or HA cron status. The related horizontal-scaling and distributed-runtime issues overlap, but they are open architecture discussions rather than merged replacements for this cron-specific request.

## What This Changes

The issue requests distributed coordination for cron jobs across multiple Gateway instances in high-availability deployments.

## Best Possible Solution

Define a supported distributed cron ownership contract first, then implement backend-neutral fenced claiming or leader leasing with upgrade-safe config or plugin API, health/CLI visibility, docs, and separate-process tests.

## Reproduction Assessment

Yes. Source inspection shows independent Gateway processes still have no shared cron lease, leader check, or coordination config/API, so the reported HA duplicate-execution risk remains reproducible from current main design.

## Solution Assessment

No, not as the backend-specific proposal alone. Redis, etcd, and DynamoDB are plausible backends, but maintainers first need to choose the supported ownership boundary, failure semantics, and whether this belongs in core or a plugin/API seam.
