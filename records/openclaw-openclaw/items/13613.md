## Label Justifications

- `P2`: The issue describes a meaningful production HA reliability gap, but the remaining work is an architectural feature rather than an urgent confirmed regression.
- `impact:message-loss`: Multiple Gateway instances can duplicate scheduled Slack or Discord deliveries when cron jobs run without shared ownership.

## Summary

Keep open: current main and v2026.6.11 still run cron inside each Gateway process with process-local serialization and no distributed cron owner, lease, leader, or accepted coordination config. The broader horizontal-scaling and distributed-runtime issues overlap, but they are open design tracks rather than merged replacements for this cron-specific HA request.

## What This Changes

The issue asks for distributed cron job ownership so multiple Gateway instances in HA deployments do not all run the same scheduled job.

## Best Possible Solution

Define a backend-neutral cron ownership contract first, then implement leased claiming or leader election with upgrade-safe config or plugin API, health/status and CLI visibility, docs, and separate-process tests.
