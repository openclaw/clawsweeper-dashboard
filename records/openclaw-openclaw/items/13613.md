## Summary

Keep open: current main and v2026.6.11 still have Gateway-local cron ownership with process-local locking and no distributed lease, leader election, shared backend, or cron leader/status surface. The broader horizontal-scaling and distributed-runtime issues overlap, but neither is a merged or exact replacement for this cron-specific HA coordination request.

## What This Changes

The issue requests distributed cron job coordination across multiple OpenClaw Gateway instances for high-availability deployments.

## Best Possible Solution

Define a backend-neutral cron ownership contract first, then implement leased claiming or leader election with upgrade-safe config or plugin API, health/status and CLI visibility, docs, and separate-process tests.
