## Summary

Keep open. Current main still lacks cross-Gateway cron ownership, leader election, distributed leases, coordination config, or HA cron status; the broader horizontal-scaling and distributed-runtime issues overlap but do not replace this cron-specific request.

## What This Changes

The issue requests distributed coordination for cron jobs across multiple Gateway instances in HA deployments, using leader election or per-job locks plus status and configuration surfaces.

## Best Possible Solution

Define a supported distributed cron ownership contract first, then implement backend-neutral fenced claiming or leader leasing with upgrade-safe config or plugin API, health/CLI visibility, docs, and separate-process tests.

## Reproduction Assessment

Yes, at source level: current main has Gateway-local cron scheduling with process-local serialization and no coordination config, leader check, or shared lease API. I did not run a live multi-host reproduction in this read-only review.

## Solution Assessment

No, not as the backend-specific proposal alone. Redis, etcd, and DynamoDB are plausible backends, but maintainers first need to choose the supported ownership boundary, failure semantics, and whether this belongs in core or a plugin/API seam.
