## Label Justifications

- `P2`: The issue describes a production HA reliability gap, but the remaining work is an architectural feature rather than an urgent confirmed regression.
- `impact:message-loss`: Multiple Gateway instances can duplicate scheduled channel deliveries when cron jobs run without shared ownership.

## Summary

Keep open: current main and v2026.6.11 still run cron inside each Gateway with process-local coordination only, while the related scaling/runtime issues remain broader open design tracks rather than merged replacements for this cron-specific HA request.

## What This Changes

The issue requests distributed coordination for cron execution across multiple Gateway instances so HA deployments do not run the same scheduled job more than once.

## Best Possible Solution

Define a backend-neutral cron ownership contract first, then implement leased claiming or leader election with upgrade-safe config or plugin API, health/status and CLI visibility, docs, and separate-process tests.
