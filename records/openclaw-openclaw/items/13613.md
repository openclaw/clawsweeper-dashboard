## Label Justifications

- `P2`: Duplicate scheduled execution in HA deployments is a production reliability gap, but this is a feature requiring architecture decisions rather than an urgent confirmed regression.
- `impact:message-loss`: The issue describes duplicate Slack, Discord, and other channel deliveries when multiple Gateways execute the same scheduled slot.

## Summary

Keep open: current main still implements cron as Gateway-local scheduling with process-local serialization and no shared lease, leader, accepted coordination config, or HA status surface; the related horizontal-scaling and distributed-runtime items overlap but do not replace this cron-specific request.

## What This Changes

Request distributed ownership or locking for cron jobs so multiple Gateway instances do not execute the same scheduled work.

## Best Possible Solution

Define a supported distributed cron ownership contract first, then implement backend-neutral claiming or leader leasing with upgrade-safe config or plugin API, health/CLI visibility, docs, and separate-process tests.

## Reproduction Assessment

Yes, at source level: current main has no shared cron lease, leader check, conditional owner claim, or accepted coordination config/API. I did not run a live multi-gateway reproduction in this read-only review.

## Solution Assessment

No, not yet. Redis, etcd, DynamoDB, and queue-backed workers are plausible directions, but maintainers first need to choose the ownership boundary, failure semantics, and core-versus-plugin API shape.
