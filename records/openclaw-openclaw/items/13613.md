## Summary

Keep open: current main and v2026.6.11 still run cron inside each Gateway with process-local coordination only, so multi-Gateway HA cron ownership remains a real feature gap that needs maintainer architecture direction.

## What This Changes

Request distributed locking or leader election for cron jobs across multiple Gateway deployments to prevent duplicate scheduled execution and duplicate channel deliveries.

## Best Possible Solution

Define a backend-neutral cron ownership contract first, then implement leased claiming or leader election with upgrade-safe config or plugin API, health/status and CLI visibility, docs, and separate-process tests.
