## Label Justifications

- `P2`: This is a production HA reliability improvement with limited blast radius, but it is a feature/product-design gap rather than an urgent regression in the default single-Gateway path.
- `impact:message-loss`: The reported failure mode is duplicate cron-triggered deliveries and state-modifying scheduled work when multiple Gateways execute the same job.

## Summary

Keep open: current main and the latest release still implement cron as Gateway-local scheduling with process-local guards only. The related horizontal-scaling and distributed-runtime discussions are still open overlaps rather than merged replacements, and shared leases or leader election need maintainer product and architecture direction.

## What This Changes

The issue requests distributed coordination for cron jobs so multiple OpenClaw gateways in HA deployments do not execute the same scheduled work independently.

## Best Possible Solution

Define a supported distributed cron ownership model first, then implement it with an explicit compatibility plan, coordination backend boundary, health/status and CLI visibility, docs, and tests that exercise separate Gateway processes sharing scheduled jobs.

## Reproduction Assessment

Yes, at source level: independent Gateway processes would each run their own CronService, while the current reservation, active-job, and lock guards are process-local and there is no shared leader or lease. I did not run a live multi-Gateway reproduction because this was a read-only cleanup review.

## Solution Assessment

Unclear as an implementation path: Redis, etcd, DynamoDB, or leader election are plausible options, but the best fix needs a maintainer-owned ownership model and upgrade/security policy before code. Keeping this issue open for architecture review is the maintainable path.
