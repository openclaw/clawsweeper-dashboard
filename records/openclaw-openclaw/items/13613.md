## Summary

Keep open: current main and v2026.6.11 still run cron inside each Gateway with process-local duplicate guards only, so multi-Gateway cron ownership remains a real feature gap that needs maintainer architecture direction.

## What This Changes

The issue requests distributed cron coordination or leader election so HA deployments with multiple Gateways do not run the same scheduled job multiple times.

## Best Possible Solution

Define a backend-neutral cron ownership contract first, then implement leased claiming or leader election with upgrade-safe config or plugin API, health/status and CLI visibility, docs, and separate-process tests.
