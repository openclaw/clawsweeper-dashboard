## Summary

Keep open: current main and v2026.6.11 still run cron as Gateway-local scheduling with process-local guards, no distributed lease/leader contract, and no accepted coordination config, so the remaining work needs maintainer architecture direction.

## What This Changes

The issue requests distributed cron ownership for multi-Gateway HA deployments, including leader election or per-job locks plus config, health, and CLI visibility.

## Best Possible Solution

Define a backend-neutral cron ownership contract first, then implement leased claiming or leader election with upgrade-safe config or plugin API, health/status and CLI visibility, docs, and separate-process tests.
