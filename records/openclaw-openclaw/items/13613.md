## Label Justifications

- `P2`: The issue describes a real production HA reliability gap, but the remaining work is an architectural feature rather than an urgent confirmed regression.
- `impact:message-loss`: Multiple Gateways can duplicate scheduled channel deliveries when cron jobs run without shared ownership.

## Summary

Keep open: current main and v2026.6.11 still have Gateway-local cron scheduling with process-local locking, no accepted distributed lease or leader contract, and no canonical replacement issue or PR that fully owns cron HA coordination.

## What This Changes

The issue requests distributed coordination for cron execution across multiple Gateway instances so HA deployments do not run the same scheduled job more than once.

## Best Possible Solution

Define a backend-neutral cron ownership contract first, then implement leased claiming or leader election with upgrade-safe config or plugin API, health/status and CLI visibility, docs, and separate-process tests.
