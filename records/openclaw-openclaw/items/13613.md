## Summary

Keep open: current main still lacks cross-Gateway cron ownership, leader election, distributed leases, coordination config, or HA cron status, and the related horizontal-scaling/runtime RFCs remain broader open architecture discussions rather than merged replacements for this cron-specific request.

## What This Changes

Request distributed coordination or leader election for cron jobs across multiple OpenClaw Gateways in HA deployments.

## Best Possible Solution

Define a backend-neutral distributed cron ownership contract first, then implement fenced claiming or leader leasing with upgrade-safe config or plugin API, health/CLI visibility, docs, and separate-process tests.

## Reproduction Assessment

Yes, from source inspection with high confidence: independent Gateway processes still have no shared cron lease, leader check, or coordination config/API. I did not run a live multi-host reproduction in this read-only review.

## Solution Assessment

No, not as the backend-specific proposal alone. Redis, etcd, and DynamoDB are plausible backends, but maintainers first need to choose the supported ownership boundary, failure semantics, and core-versus-plugin seam.
