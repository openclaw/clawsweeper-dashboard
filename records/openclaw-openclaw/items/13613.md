- `impact:message-loss`: The issue describes duplicate Slack, Discord, and other channel deliveries when multiple Gateways execute the same scheduled slot.

## Summary

Keep open. Current main and v2026.6.11 still lack cross-Gateway cron ownership, leader election, distributed leases, coordination config, or HA cron status, so this remains a valid architecture/product follow-up rather than cleanup-close material.

## What This Changes

The issue requests distributed coordination for cron jobs across multiple Gateway instances so high-availability deployments do not execute the same scheduled work more than once.

## Best Possible Solution

Define a supported distributed cron ownership contract first, then implement backend-neutral fenced claiming or leader leasing with upgrade-safe config or plugin API, health/CLI visibility, docs, and separate-process tests.

## Reproduction Assessment

Yes, from source inspection: independent Gateway processes still have no shared cron lease, leader check, or coordination config/API. I did not run a live multi-host reproduction in this read-only review.

## Solution Assessment

No, not as the backend-specific proposal alone. Redis, etcd, and DynamoDB are plausible backends, but maintainers first need to choose the supported ownership boundary, failure semantics, and whether this belongs in core or a plugin/API seam.
