- `impact:message-loss`: The issue describes duplicate Slack, Discord, and other channel deliveries when multiple Gateways execute the same scheduled slot.

## Summary

Keep open: current main still lacks distributed cron ownership, leader election, shared leases, coordination config, and HA cron status; the related horizontal-scaling and distributed-runtime RFCs overlap but remain broader open design items rather than merged replacements.

## What This Changes

The issue requests distributed coordination for cron jobs across multiple Gateway instances in high-availability deployments.

## Best Possible Solution

Define a supported distributed cron ownership contract first, then implement backend-neutral fenced claiming or leader leasing with upgrade-safe config or plugin API, health/CLI visibility, docs, and separate-process tests.

## Reproduction Assessment

Yes, at source level: independent Gateway processes still have no shared cron lease, leader check, conditional claim, or accepted coordination config/API. I did not run a live multi-host reproduction in this read-only review.

## Solution Assessment

No, not as the backend-specific proposal alone. Redis, etcd, and DynamoDB are plausible backends, but maintainers first need to choose the supported ownership boundary, failure semantics, and whether this belongs in core or a plugin/API seam.
