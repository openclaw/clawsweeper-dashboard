## Label Justifications

- `P2`: Duplicate scheduled execution in HA deployments is a production reliability gap, but this is a broad feature requiring architecture decisions rather than an urgent confirmed regression.
- `impact:message-loss`: The issue describes duplicate Slack, Discord, and other channel deliveries when multiple Gateways execute the same scheduled slot.

## Summary

Keep open: current main and the latest release still implement cron as Gateway-local scheduling with process-local coordination only, while the related horizontal-scaling and distributed-runtime items remain broader open design discussions rather than merged replacements.

## What This Changes

Request distributed cron ownership or locking so multiple Gateway instances do not execute the same scheduled job in HA deployments.

## Best Possible Solution

Define a supported distributed cron ownership contract first, then implement backend-neutral fenced claiming or leader leasing with upgrade-safe config or plugin API, health/CLI visibility, docs, and separate-process tests.

## Reproduction Assessment

Yes, at source level: independent Gateway processes still have no shared cron lease, leader check, conditional claim, or accepted coordination config/API. I did not run a live multi-host reproduction in this read-only review.

## Solution Assessment

No, the backend-specific proposal alone is not yet the best fix. Redis, etcd, DynamoDB, and queue-backed workers are plausible options, but maintainers first need to choose the ownership boundary, failure semantics, and core-versus-plugin API shape.
