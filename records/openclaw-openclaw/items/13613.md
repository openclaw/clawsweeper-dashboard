## Label Justifications

- `P2`: Duplicate scheduled execution in HA deployments is a production reliability gap, but it is not a confirmed urgent regression for single-Gateway users.
- `impact:message-loss`: Multiple Gateways can duplicate scheduled Slack, Discord, or other channel deliveries for the same cron slot.

## Summary

Keep open: current main and v2026.6.11 still lack cross-Gateway cron ownership, leader election, distributed leases, coordination config, or HA cron status, so this remains a valid architecture/product item rather than cleanup-close material.

## What This Changes

The issue requests distributed coordination for cron jobs across multiple Gateway instances in HA deployments.

## Best Possible Solution

Define a backend-neutral distributed cron ownership contract first, then implement fenced claiming or leader leasing with upgrade-safe config or plugin API, health/CLI visibility, docs, and separate-process tests.

## Reproduction Assessment

Yes, from source inspection: independent Gateway processes still have no shared cron lease, leader check, or coordination config/API. I did not run a live multi-host reproduction in this read-only review.

## Solution Assessment

No, not as the backend-specific proposal alone. Redis, etcd, and DynamoDB are plausible backends, but maintainers first need to choose the supported ownership boundary, failure semantics, and core-vs-plugin API shape.
