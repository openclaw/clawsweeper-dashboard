## Summary

Keep open: current main still has Gateway-local cron scheduling with process-local coordination only, so multi-Gateway HA cron ownership remains a real feature gap that needs maintainer architecture direction.

## What This Changes

The issue requests distributed cron coordination for HA deployments, such as leader election or per-job locks across multiple Gateway instances.

## Best Possible Solution

Define a backend-neutral cron ownership contract first, then implement leased claiming or leader election with upgrade-safe config or plugin API, health/status and CLI visibility, docs, and separate-process tests.
