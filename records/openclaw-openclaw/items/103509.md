## Label Justifications

- `impact:message-loss`: The current Feishu path suppresses the visible text portion of a text-plus-voice Auto-TTS reply.

## Summary

Keep this issue open: current main still suppresses Feishu text for voice-media replies, while the newer shared TTS supplement contract supports one visible reply plus supplemental audio without duplication. Feishu never adopted that contract, so this is a focused bundled-plugin regression rather than already-implemented or duplicate work.

## What This Changes

Change Feishu Auto-TTS delivery so the reply text remains visible as a separate message alongside the native voice note.

## Best Possible Solution

Integrate Feishu with the shared TTS supplement contract: send supplement spoken text only when it has not already been delivered, then send a media-only native voice note, while preserving ordinary voice-only payloads and degraded-file fallback behavior.
