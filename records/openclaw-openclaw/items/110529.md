## Summary

This remains a useful, evidence-backed fix candidate: current main still uses the shared short retry loop for embedding failures, while the PR adds a bounded 429-specific path without changing transport-error timing. The remaining merge question is whether a roughly three-minute retry window is the intended memory-index availability policy; that is a maintainer choice rather than a discrete defect in the patch.

## What This Changes

The PR gives memory embedding 429/quota failures a longer bounded retry budget, carries Retry-After metadata through the memory host SDK, and adds retry-policy and timeout regression coverage.

## Best Possible Solution

Keep the short retry policy for transport failures and land a bounded 429/Retry-After policy only after the memory-core owner confirms that up to five long cooldown retries are preferable to promptly surfacing quota exhaustion.
