## Summary

This PR targets the open rate-limit failure in https://github.com/openclaw/openclaw/issues/108893, but its production callers still allow only three total attempts. That gives no-`Retry-After` 429 responses only 10s and 20s waits before failure, while the supplied recovery transcript needs five attempts; keep the PR open for the narrow retry-budget repair and production-path proof.

## What This Changes

The branch adds rate-limit detection and `Retry-After` extraction for memory embeddings, uses longer rate-limit delays at embedding call sites, and expands retry-policy tests.

## Best Possible Solution

Give rate-limit errors a bounded retry budget that reaches the intended cooldown window without changing transport-error retries, then prove the configured `openclaw memory index` path recovers from a no-header 429 sequence.
