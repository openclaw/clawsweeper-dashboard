## Summary

Keep this PR open: it has useful, proof-backed 429 recovery work, but the new roughly 190-second rate-limit retry budget exceeds the 120-second remote embedding batch deadline, so remote providers can still time out before the intended cooldown path completes.

## What This Changes

The branch adds a rate-limit-specific embedding retry schedule, propagates HTTP `Retry-After` metadata through the memory host SDK, and expands memory retry-policy tests.

## Best Possible Solution

Make the rate-limit retry budget deadline-aware: either extend the relevant remote batch deadline to cover the bounded policy or cap retries by the enclosing deadline, then add a regression test for a remote 429 sequence that reaches the final allowed attempt.
