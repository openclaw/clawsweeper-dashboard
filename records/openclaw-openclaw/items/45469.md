## Summary

Keep open: current main and the latest release still leave the active GatewayClient reconnect scheduler unbounded, and https://github.com/openclaw/openclaw/pull/77961 is the open implementation candidate that needs maintainer disposition before this issue can close.

## What This Changes

The issue asks OpenClaw to prevent `GatewayClient.scheduleReconnect()` from retrying forever when the gateway remains unreachable.

## Best Possible Solution

A package-level, maintainer-approved opt-in retry ceiling should exist for short-lived Gateway clients while node-host keeps unlimited recovery by default, with focused tests and redacted live reconnect proof.

## Reproduction Assessment

Yes at source level: current package-client close handling reaches `scheduleReconnect()`, which schedules another `start()` without a max-attempt counter. I did not run a live long-duration reproduction of the reported zombie-process accumulation.

## Solution Assessment

No, the blanket max-retry suggestion is not the best final shape because node-host depends on long-lived recovery. The maintainable fix is an opt-in package-level policy wired only to maintainer-approved short-lived callers, with proof that the unlimited default remains intact.
