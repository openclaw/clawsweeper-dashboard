## Summary

The PR fixes the reported incidental-status-number retries, but it also makes generic rate-limit errors terminal by treating every rate-limit message that is not positively short-window as long-window. That changes current session behavior for messages such as `rate limit exceeded`, so the branch needs a narrow policy correction and real control-flow proof before it is a safe canonical fix.

## What This Changes

The PR extracts rate-limit window parsing into `src/shared/rate-limit-window.ts`, rewires embedded failover callers to it, and changes the session retry classifier to reject leading permanent statuses and long-window limits.

## Best Possible Solution

Use an explicit `short`, `long`, or `unknown` window result: share parsing and positive window facts, preserve current session retry behavior for unknown-window throttles, and suppress outer retries only for positively identified long-window limits or permanent errors.
