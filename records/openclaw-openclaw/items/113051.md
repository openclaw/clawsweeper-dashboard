## Summary

The reported behavior is not a current provider-selection regression: OpenAI provider identity, API-key authentication, and agent runtime are separate choices, and an eligible official OpenAI route may intentionally select Codex implicitly. Current routing limits that implicit selection to eligible route facts and keeps custom, authored, or explicitly OpenClaw-routed requests on the OpenClaw runtime.

## What This Changes

The issue requests that an OpenAI API configuration never select the Codex agent runtime implicitly and instead always execute through the OpenClaw runtime.

## System Context

OpenClaw first resolves the selected OpenAI model and its concrete endpoint/adapter route, then chooses an agent harness for the turn. That harness selection determines whether the turn runs through the native Codex app-server or OpenClaw's built-in runtime, while authentication and billing credentials remain separate.

  E -->|Yes| F[Codex app-server runtime]

## Best Possible Solution

Keep the route-sensitive runtime policy and use the documented OpenAI API-key profile plus explicit provider/model runtime policy when a deployment requires the built-in OpenClaw runtime rather than the eligible Codex harness.
