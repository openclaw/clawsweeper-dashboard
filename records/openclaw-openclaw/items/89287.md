## Summary

## What This Changes

This PR carries each outbound payload’s provider, account, destination, and thread metadata into delivery results, then counts ACP/subagent completion delivery as visible only when that evidence matches the requester route.

## System Context

Subagent and ACP completion announcements reuse the outbound delivery stack to notify the requester after background work ends. This change carries the concrete outbound route through delivery outcomes, then compares it with the requester route before the agent lifecycle treats the completion as visibly delivered.

## Architecture Diagram

  D --> E[Route-evidence comparison]
  E -->|Exact match| F[Count visible delivery]
  E -->|Missing or wrong target| G[Continue fallback or report missing delivery]

## Best Possible Solution

Adopt one documented compatibility rule: require exact provider/account/destination/thread evidence whenever the requester route is concrete, while retaining only the narrowly justified non-threaded current-chat exception; then add focused cross-channel regressions for that contract before merging.
