## Label Justifications

- `P1`: Incorrectly crediting completion delivery to another thread or account can leave an active agent/channel workflow without its requester-visible completion.
- `merge-risk: 🚨 compatibility`: Existing integrations that emit incomplete target evidence may shift from broad success accounting to fallback or failure behavior.
- `merge-risk: 🚨 message-delivery`: The patch changes when a completion is considered visibly delivered and can trigger a different delivery path for wrong-target evidence.

## Summary

Keep this PR open for maintainer review: it adds target-aware completion-delivery accounting that current main does not provide, but maintainers need to confirm the intended compatibility boundary for absent account/thread evidence before merge.

## What This Changes

The branch propagates per-payload delivery targets and requires ACP/subagent completion evidence to match the requester provider, account, destination, and thread before treating delivery as visible success.

## Best Possible Solution

Adopt one explicit, centrally tested completion-evidence contract: exact provider, destination, and thread matching for concrete threaded routes, with only the documented generated-media compatibility exception retained.
