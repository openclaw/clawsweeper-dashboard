## Summary

Keep open, but narrow the remaining work to Android parity. Current main implements the shared Apple metadata footer and the canonical optional channel footer, while Android still discards message-level usage during history parsing and cannot render it; a maintainer should confirm whether Android follows Apple's automatic visibility behavior.

## What This Changes

Surface compact per-message token, cache, cost, model, and context metadata in native mobile chat and optionally in messaging-channel replies.

## Best Possible Solution

Narrow this issue to Android parity: preserve decoded message usage and render the established compact footer beneath completed assistant replies, without adding a protocol, channel-specific logic, or new configuration option.
