Full review comments:

- **[P1] Preserve the activation retry:** `src/daemon/systemd.ts:735-740`
  - body: This branch calls `systemctl enable` and `restart` once after `daemon-reload`. Current main retries `daemon-reload` plus the failed action when systemd reports the just-written unit as missing, with regression coverage for migrated user services, so refreshing this branch without that logic can reopen install failures.
  - confidence: 0.93
- **[P1] Honor custom systemd units during uninstall:** `src/daemon/systemd.ts:794-796`
  - body: `uninstallSystemdService` still resolves the gateway service name from `OPENCLAW_PROFILE`, ignoring `OPENCLAW_SYSTEMD_UNIT`. Current main uses `resolveSystemdServiceName(env)`, so this branch would disable the wrong unit for node/custom installs such as `openclaw-node`.
  - confidence: 0.94
- **[P1] Reject option-like unit names:** `src/daemon/systemd.ts:55-63`
  - body: The new validation still allows names beginning with `-`, and the later `systemctl` calls pass the unit operand without a `--` terminator. A custom `OPENCLAW_SYSTEMD_UNIT` can therefore be parsed as a `systemctl` option instead of a unit name.
  - confidence: 0.9
- **[P1] Carry current env-file preservation into the migration:** `src/daemon/systemd.ts:559-562`
  - body: This branch's systemd env-file writer only emits the current state-dir dotenv values. Current main preserves operator-added env-file secrets, drops stale managed keys, and skips unresolved shell references, so the drop-in migration needs to keep that newer path instead of reverting to the older writer.
  - confidence: 0.88
- **[P1] Preserve kept Environment assignment values:** `src/daemon/systemd-unit.ts:270-273`
  - body: When only some assignments on an `Environment=` line are stripped, the kept assignments are re-rendered through `renderEnvLines`, which filters empty values and trims values. That changes valid systemd semantics such as `Environment=LD_PRELOAD=` during upgrade migration.
  - confidence: 0.86
- **[P1] Avoid direct writes for token-bearing drop-ins:** `src/daemon/systemd.ts:637-638`
  - body: The new managed drop-in can contain gateway tokens, but it is written with direct `writeFile` on a predictable HOME-derived path and backups use direct copy/write behavior. Either harden the write path against symlink/hardlink overwrite or add an explicit owner-approved threat-model note and tests.
  - confidence: 0.82
- **[P2] Remove the release-owned changelog edit:** `CHANGELOG.md:20`
  - body: `CHANGELOG.md` is release-owned for this repository, and this PR also removes unrelated historical entries in the diff. Keep the release-note context in the PR body or squash message and leave changelog generation to the release flow.
  - confidence: 0.91

## Security Review

Status: needs_attention

Summary: The diff changes systemd command operands and writes token-bearing service files, and the current branch has unresolved option-injection, symlink/write-path, and environment-rewrite security concerns.

Concerns:

- **[high] Option-like systemd unit names are still accepted:** `src/daemon/systemd.ts:55`
  - body: `OPENCLAW_SYSTEMD_UNIT` validation permits a leading dash, and unit names are passed to `systemctl` without an end-of-options marker, so a custom unit value can be interpreted as a `systemctl` option.
  - confidence: 0.9
- **[high] Token-bearing drop-in writes follow HOME-derived paths:** `src/daemon/systemd.ts:637`
  - body: The managed drop-in can contain gateway tokens and is written through predictable HOME-derived paths with direct `writeFile`; the branch also copies/writes backups directly, leaving symlink/hardlink overwrite concerns unresolved.
  - confidence: 0.83
- **[medium] Environment rewrite changes clearing semantics:** `src/daemon/systemd-unit.ts:270`
  - body: The partial strip path re-renders kept assignments through a helper that drops empty values and trims whitespace, which can remove deliberate environment clearing such as `LD_PRELOAD=`.
  - confidence: 0.86
- **[medium] Sentinel-absent secrets can still land in the main unit:** `src/daemon/systemd-unit.ts:100`
  - body: When the managed-env sentinel is absent, all environment values are treated as user-owned and rendered into the main unit, while fresh main-unit writes use default file permissions rather than an explicit restrictive mode.
  - confidence: 0.74
