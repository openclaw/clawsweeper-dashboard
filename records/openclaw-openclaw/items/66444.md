- **[P1] Preserve the activation retry:** `src/daemon/systemd.ts:735-740`
  - body: This branch's activation path calls `enable` and `restart` once after `daemon-reload`, but current main retries the failed action after a second reload when systemd reports the just-written unit as missing. Carry that retry forward or the branch can reintroduce the closed install failure on migrated systemd user managers.
  - confidence: 0.92
- **[P1] Honor custom systemd units during uninstall:** `src/daemon/systemd.ts:794-796`
  - body: `uninstallSystemdService` still disables `resolveGatewaySystemdServiceName(...)`, while current main uses `resolveSystemdServiceName(env)` so `OPENCLAW_SYSTEMD_UNIT=openclaw-node` disables/removes the node unit. This branch would leave custom units enabled or fail against the wrong service name unless it carries the current-main fix.
  - confidence: 0.95
- **[P1] Reject option-like unit names:** `src/daemon/systemd.ts:55-63`
  - body: The new validator permits names beginning with `-`, and the unit operand is later passed to `systemctl` without a `--` separator. Reject leading dashes or terminate options consistently so `OPENCLAW_SYSTEMD_UNIT` cannot be parsed as a systemctl option.
  - confidence: 0.9
- **[P1] Carry current env-file preservation into the migration:** `src/daemon/systemd.ts:662-681`
  - body: The branch writes only the current state-dir dotenv values into `gateway.systemd.env`, but current main now preserves operator-only env-file entries, file-managed SecretRef values, node env files, and skipped unresolved references. The drop-in migration needs to build on that current writer or existing service secrets and compatibility fixes can be lost during re-stage.
  - confidence: 0.88
- **[P1] Preserve kept Environment assignment values:** `src/daemon/systemd-unit.ts:270-273`
  - body: When stripping one assignment from a mixed `Environment=` line, this path re-renders the kept assignments through `renderEnvLines`, which filters empty values and trims all values. That changes valid operator-authored systemd semantics such as `Environment=LD_PRELOAD=` during migration.
  - confidence: 0.9
- **[P1] Avoid direct writes for token-bearing drop-ins:** `src/daemon/systemd.ts:627-638`
  - body: The migration writes predictable HOME-derived unit, backup, and managed drop-in paths with direct `copyFile`/`writeFile`; the drop-in can contain gateway tokens. Either harden these writes against symlink/path redirection or document an explicit maintainer-approved local threat model before landing.
  - confidence: 0.82
- **[P2] Remove the release-owned changelog edit:** `CHANGELOG.md:17`

  - confidence: 0.96

## Security Review

Status: needs_attention
