## Summary

Keep open. Current main and the latest release still do not provide layered Tailscale Serve identity plus token/password authentication; the existing mitigation is to disable Tailscale identity auth and use shared-secret auth, which does not preserve Tailscale user identity.

## What This Changes

Request optional secondary token/password authentication for Tailscale Serve identity access, plus clearer runtime warnings and docs for the current trust boundary.

## Best Possible Solution

Define a maintainer-approved layered Gateway auth contract, then update config types/schema/help, WebSocket auth enforcement, warning or audit messaging, public docs, and focused auth tests together.

## Reproduction Assessment

Yes, at source level. Current main accepts verified Tailscale Serve identity for ws-control-ui without token/password when allowTailscale is enabled, and the config/schema have no layered secondary-auth option.

## Solution Assessment

Unclear. The proposed opt-in flag is plausible, but maintainers should settle the permanent layered-auth contract instead of adding a one-off key around one auth branch.
