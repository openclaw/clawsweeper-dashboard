## Summary

Keep open. Current main and v2026.6.11 still provide either verified Tailscale Serve identity or explicit token/password auth, but not an opt-in identity-plus-shared-secret requirement; this remains a security-sensitive Gateway auth product decision.

## What This Changes

Request optional secondary token/password auth plus clearer warnings/docs for Tailscale Serve identity-based Gateway access.

## Best Possible Solution

Define a maintainer-approved layered Gateway auth contract, then update config types/schema/help, WebSocket auth enforcement, warning or audit messaging, public docs, and focused auth tests together.

## Solution Assessment

Unclear. The requested opt-in flag is plausible, but maintainers should settle the permanent layered-auth contract instead of adding a one-off config key around one auth branch.
