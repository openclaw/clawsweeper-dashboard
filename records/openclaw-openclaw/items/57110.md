## Summary

Keep open. Current main and v2026.6.11 fixed the separate no-auth Tailscale exposure problem, but they still do not provide an opt-in mode that preserves verified Tailscale identity while also requiring token/password authentication.

## What This Changes

Requested optional secondary token/password authentication plus clearer warnings/docs for Tailscale Serve trusted-proxy gateway access.

## Best Possible Solution

Define a maintainer-approved layered Gateway auth contract that preserves verified Tailscale identity while requiring a shared secret when explicitly enabled, then update config types/schema, auth enforcement, warnings or audit output, public docs, and focused auth tests together.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 accept verified Tailscale Serve identity for ws-control-ui without token/password credentials when allowTailscale is enabled, and the config/schema has no secondary-auth option.

## Solution Assessment

Unclear. The requested opt-in flag is plausible, but maintainers should first settle the layered-auth contract; the existing allowTailscale=false plus token/password workaround requires shared-secret auth but does not preserve Tailscale identity as an auth factor.
