## Summary

Keep open. Current main and v2026.6.11 fixed the explicit Tailscale Serve plus `auth.mode="none"` exposure gap, but they still do not provide an opt-in layered mode where verified Tailscale identity and token/password auth must both pass.

## What This Changes

The issue requests optional secondary token/password authentication, warnings, and docs for Tailscale Serve identity-auth deployments.

## Best Possible Solution

Define a maintainer-approved layered Gateway auth contract, then update config types/schema/help, WebSocket auth enforcement, warning or audit messaging, public docs, and focused auth tests together.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 lack a secondary-auth config/schema field, and the current WS Control UI auth path still accepts verified Tailscale identity without token/password when `allowTailscale` is enabled and no shared-secret auth is supplied.

## Solution Assessment

Unclear. The proposed flag is plausible, but maintainers should settle the durable layered-auth contract instead of adding a one-off config key around one auth branch.
