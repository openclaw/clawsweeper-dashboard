## Summary

Keep open. Current main and v2026.6.11 still support verified Tailscale Serve identity as a tokenless Control UI/WebSocket auth path, and the current config/schema has no optional secondary token/password layer; the related no-auth Serve exposure bug is fixed, but this layered-auth feature remains a security/product decision.

## What This Changes

Request optional secondary token/password authentication and clearer warnings/docs for Tailscale Serve identity-based Gateway access.

## Best Possible Solution

Define a maintainer-approved layered Gateway auth contract, then update config types/schema/help, WebSocket auth enforcement, audit or warning messaging, public docs, and focused auth tests together.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 accept verified Tailscale Serve identity for ws-control-ui without token/password credentials when allowTailscale is enabled; no live Tailnet run was performed in this read-only review.

## Solution Assessment

Unclear. The requested opt-in flag is plausible, but maintainers should settle the broader layered-auth contract instead of adding a one-off config key around one auth branch.
