## Summary

Keep open. Current main and the latest stable release document the tokenless verified Tailscale Serve identity path, but they still do not provide an optional secondary token/password layer on top of that identity check.

## What This Changes

Requests opt-in layered Gateway authentication and clearer warning/docs for Tailscale Serve identity so tailnet users can require token/password in addition to verified Tailscale identity.

## Best Possible Solution

Define a maintainer-approved layered Gateway auth contract, then update config types/schema/help, auth enforcement, warning or audit messaging, public docs, and focused tests together.

## Reproduction Assessment

Yes, at source level. Current main accepts verified Tailscale Serve identity for ws-control-ui without token/password when allowTailscale is enabled, and no current config/schema/auth path adds a secondary shared-secret requirement.

## Solution Assessment

Unclear. The requested opt-in flag is plausible, but maintainers should settle the broader layered-auth contract instead of adding a one-off key around one auth branch.
