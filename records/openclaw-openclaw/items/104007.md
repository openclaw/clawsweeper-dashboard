## Summary

The patch is focused, source-correct, and backed by strong tests and live Slack proof, but the protected `maintainer` label and intentional fail-closed upgrade behavior require explicit owner confirmation before merge.

## What This Changes

The PR makes Slack group-DM messages, slash commands, block actions, and system events authorize senders against the account-level `allowFrom` policy while excluding one-to-one pairing approvals.

## Best Possible Solution

Use the account-level Slack `allowFrom` list as the single MPIM sender policy across every ingress path, keep pairing approvals scoped to one-to-one DMs, and explicitly confirm that empty `allowFrom` intentionally fails closed for existing group-DM setups.
