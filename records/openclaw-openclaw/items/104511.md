The direct runtime transcript demonstrates the changed behavior, and exact-head CI is green or appropriately skipped; this PR remains useful and should stay open for normal maintainer review.

## What This Changes

The PR replaces prototype-chain presence checks for model `contextWindow`, `contextTokens`, `maxTokens`, `input`, and `reasoning` overrides with own-property checks, removes the inherited token-limit fallback, and adds regression coverage.

## Best Possible Solution

Land the own-property implementation after ordinary maintainer review, keeping the precedence as valid own explicit value, then valid implicit value, then omission; the repetitive regression cases may be consolidated if maintainers want a smaller test diff, but that is not a correctness blocker.

## Reproduction Assessment

Yes. On current main, an explicit model with a prototype-inherited positive token limit and no valid implicit limit reaches the final fallback and returns the inherited value even though the presence check should reject it.

## Solution Assessment

Yes. Enforcing own-property presence in the merge owner is narrower and safer than requiring every config, plugin, or programmatic caller to sanitize prototypes, and the current head preserves normal own explicit and implicit fallback behavior.
