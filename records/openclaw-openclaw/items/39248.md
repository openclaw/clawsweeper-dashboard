## What This Changes

The issue asks OpenClaw to fix `sessions_spawn` subagents that inherit `agents.defaults.sandbox.mode: "non-main"` and appear accepted but never start, log, or terminalize until timeout.

## Best Possible Solution

Define the owner-approved sandboxed-subagent startup failure contract, then prove both a successful defaults-level `non-main` spawn and a forced Docker startup failure that logs and terminalizes the child run.

Question: Should sandboxed subagent startup failures stay inside the accepted async `sessions_spawn` contract and terminalize/log as startup failures, or should `sessions_spawn` preflight sandbox startup before returning accepted?

Rationale: That choice affects the documented non-blocking spawn contract, gateway lifecycle events, session registry state, and the overlapping #58776 lifecycle design, so automation should not pick the product contract alone.

Owner confidence: high

Options:

- **Terminalize Async Startup Failure (recommended):** Keep `sessions_spawn` non-blocking and add a typed async startup-failure state with logging/session projection for Docker setup failures.
- **Preflight Sandbox Before Accept:** Start or validate the sandbox before returning accepted, trading clearer immediate failures for a compatibility change to the spawn contract.
- **Defer To Lifecycle Design:** Keep this issue open as the Docker proof case while #58776 settles the general lifecycle phases first.

## Solution Assessment
