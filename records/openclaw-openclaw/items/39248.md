## Label Justifications

## Summary

Keep open: current main still routes generated `sessions_spawn` child keys through the `non-main` sandbox path, accepts the child run before sandbox startup work, and lacks a merged path proving Docker startup failures become visible terminal session state instead of zero-progress runs.

## What This Changes

The issue asks OpenClaw to stop silently stalling sandboxed `sessions_spawn` subagents when `agents.defaults.sandbox.mode` is `"non-main"`.

## Best Possible Solution

Keep this as the sandbox-specific tracker, choose the startup-failure contract, then implement and live-prove successful and forced-failure Docker `non-main` `sessions_spawn` behavior on current main.
