## Summary

Keep open: current main still documents and accepts defaults-level `non-main` sandboxed subagent sessions, but I found no merged source fix or live Docker proof that this `sessions_spawn` path now starts correctly or terminalizes/logs forced sandbox startup failure. The open broader lifecycle issue and PR overlap the silent-start symptom, but they do not settle this sandbox-specific path.

## What This Changes

Issue requests that `sessions_spawn` with inherited `agents.defaults.sandbox.mode: "non-main"` start sandboxed subagents reliably or surface Docker startup failure instead of leaving accepted child sessions silent.

## Best Possible Solution

Keep the accepted async `sessions_spawn` contract, add one owner-approved startup-failure terminal state/logging path, and prove defaults-level `non-main` child startup plus forced Docker startup failure in a live run.
