## Summary

Keep open: current main still has the supported defaults-level `non-main` sandboxed subagent path and accepts agent runs before sandbox startup executes, with no merged or live-proven fix for the reported Docker-backed `sessions_spawn` initialization stall. The open lifecycle work overlaps the silent-start symptom, but it does not yet prove the sandbox-specific path.

## What This Changes

Report that `agents.defaults.sandbox.mode: "non-main"` can make `sessions_spawn` subagents return accepted while never initializing, producing no messages, tokens, transcript, or visible error until timeout.

## Best Possible Solution

Adopt one owner-approved startup failure contract for sandboxed subagents, then prove `sessions_spawn` with defaults-level `non-main` both starts successfully and terminalizes/logs a forced Docker startup failure.

- **Defer To Lifecycle PR:** Treat the open lifecycle PR as the design owner while keeping this issue as the sandbox-specific live proof case before closure.
