## Label Justifications

## Summary

Keep open: current main still has a supported `non-main` sandboxed subagent path where `sessions_spawn` can accept a child run before Docker startup, and no merged, live-proven fix yet settles the sandbox-specific silent initialization failure.

## What This Changes

Fix `sessions_spawn` so subagents inheriting `agents.defaults.sandbox.mode: "non-main"` initialize or fail visibly instead of stalling as accepted child runs.

## Best Possible Solution

Pick an owner-approved startup-failure contract, then add focused tests and live Docker proof that `non-main` sandboxed subagents either start normally or visibly terminalize with an actionable sandbox startup error.
