## Summary

Keep open: current main still supports `non-main` sandboxed subagent sessions, still accepts the child run before sandbox context startup, and still lacks a merged fix proving sandbox/Docker startup failures become visible terminal child-session state instead of a silent stall.

## What This Changes

The issue reports that `agents.defaults.sandbox.mode: "non-main"` makes `sessions_spawn` return accepted child runs that never initialize, log, write transcript state, or produce tokens.

## Best Possible Solution

Keep this as active core bug work until sandboxed native child startup either starts normally or records an actionable logged terminal failure in child session state when Docker or sandbox initialization fails.

## Reproduction Assessment

No live Docker reproduction was run. Source inspection gives a medium-confidence reproduction shape: `non-main` child keys enter sandbox context after the gateway accepted ack, and current main still lacks a proven startup-failure lifecycle path for that phase.

## Solution Assessment

Unclear pending maintainer review. The narrow end state is clear, but the best fix may require a product/API decision between lifecycle events, terminal-state reporting, retry semantics, and sandbox-specific failure surfacing.
