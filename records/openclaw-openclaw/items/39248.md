## Label Justifications

- `P1`: The report describes a broken core subagent workflow where accepted child sessions never start and eventually time out.
- `impact:session-state`: The affected behavior is subagent session lifecycle state: accepted child sessions remain running with no transcript or token progress.

## Summary

Keep open: current main still accepts sandboxed `sessions_spawn` runs before Docker sandbox startup is resolved, and no merged related change proves `non-main` subagents surface startup failure instead of sitting as running until timeout.

## What This Changes

Issue asks OpenClaw to stop `agents.defaults.sandbox.mode: "non-main"` from silently leaving `sessions_spawn` subagents accepted but uninitialized.

## Best Possible Solution

Keep this as the sandbox-specific tracker, choose the startup-failure contract, then implement and live-prove both successful and forced-failure Docker `non-main` `sessions_spawn` behavior.

Question: Should sandboxed `sessions_spawn` keep returning `accepted` and surface Docker startup failures asynchronously, or preflight enough sandbox startup work to reject before returning?

Rationale: The choice affects the public async spawn contract, session registry semantics, timeout behavior, and overlap with the broader lifecycle-event work, so automation should not pick it alone.

Likely owner: vincentkoc

Owner confidence: high

Options:

- **Terminalize Async Startup Failures (recommended):** Keep the accepted response contract and make Docker startup failure visible as typed terminal state in logs, session history, subagent status, and waits.
- **Preflight Sandbox Before Accept:** Move enough sandbox initialization before the accepted response to fail fast, accepting extra latency and compatibility review for existing callers.
- **Defer To Lifecycle Tracker:** Leave this sandbox-specific issue open while maintainers settle the broader lifecycle contract in https://github.com/openclaw/openclaw/issues/58776.

## Reproduction Assessment

Yes at source level, but not as a live Docker reproduction here; current main still classifies generated subagent keys as sandboxed under `non-main`, returns `accepted`, and resolves sandbox context inside the child run.

## Solution Assessment

Unclear pending maintainer intent; typed asynchronous startup failure appears least disruptive, but maintainers should choose that contract over pre-accept sandbox rejection before implementation.
