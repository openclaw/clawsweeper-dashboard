## Summary

Keep open: current main still supports defaults-level `non-main` sandboxed subagent sessions, and I found no merged fix or live proof that Docker-backed `sessions_spawn` now starts, logs, or terminalizes the reported startup failure path.

## What This Changes

The issue reports that `agents.defaults.sandbox.mode: "non-main"` causes `sessions_spawn` child sessions to be accepted but remain running with no messages, tokens, transcript, or gateway errors.

## Best Possible Solution

Add one owner-approved startup failure contract for sandboxed subagents, then prove `sessions_spawn` with defaults-level `non-main` both starts successfully and terminalizes/logs a forced Docker startup failure.

- **Terminalize async startup failure (recommended):** Keep the accepted async spawn contract, but emit/log a typed startup failure and prove registry, session history, and subagents list callers see it for Docker sandbox startup failures.

- **Defer to lifecycle redesign:** Let the broader lifecycle issue define the event contract while keeping this issue as the sandbox-specific live proof case.
