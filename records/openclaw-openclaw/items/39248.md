## Summary

Keep open: current main still supports `non-main` sandboxed subagent sessions and still accepts a child run before asynchronous sandbox startup, while no merged fix or live proof shows the Docker-backed `sessions_spawn` stall now starts normally or terminalizes visibly.

## What This Changes

The issue reports that `agents.defaults.sandbox.mode: "non-main"` causes `sessions_spawn` subagents to be accepted but never initialize, with no visible error output.

## Best Possible Solution

Add one owner-approved startup failure contract for sandboxed subagents, then prove `sessions_spawn` with defaults-level `non-main` both starts successfully and terminalizes/logs a forced Docker startup failure.
