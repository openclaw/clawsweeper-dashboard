## Summary

Keep open: current main and the latest release still support defaults-level `non-main` sandboxed subagent sessions, but there is no merged fix or live proof that Docker-backed `sessions_spawn` now starts correctly or terminalizes with a visible startup failure.

## What This Changes

The issue reports that `agents.defaults.sandbox.mode: "non-main"` causes `sessions_spawn` subagents to be accepted but then sit in a zero-token, no-message running state until timeout.

## Best Possible Solution

Keep one owner-approved startup contract: defaults-level `non-main` sandboxed subagents should either start normally or reach a visible terminal startup failure with logs/session state, proven by live Docker repro and focused lifecycle tests.
