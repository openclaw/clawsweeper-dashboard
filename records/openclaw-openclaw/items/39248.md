## Summary

Keep open: current main still supports `agents.defaults.sandbox.mode: "non-main"` for subagent session keys and still resolves Docker sandbox startup inside the child run path, but there is no merged fix or live Docker proof that the accepted-then-zero-token `sessions_spawn` stall now terminalizes or starts correctly. The broader lifecycle issue and open PR overlap the silent-startup symptom without closing this sandbox-specific failure mode.

## What This Changes

Report that defaults-level `sandbox.mode: "non-main"` can make Docker-backed `sessions_spawn` child runs return accepted but never initialize, leaving empty child sessions until timeout.

## Best Possible Solution

Add an owner-approved startup-failure contract for sandboxed subagents, then prove live Docker `non-main` spawn success plus forced Docker create/start/setup failure reporting through the chosen path.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should sandboxed subagent startup failures be reported through the accepted async run path with a typed terminal startup-failure state, or should `sessions_spawn` preflight sandbox startup before returning accepted?

Rationale: Both shapes can fix the zero-token hang, but they have different compatibility and lifecycle semantics for gateway callers, session state, and existing async spawn behavior.

Likely owner: steipete

Owner reason: The strongest current history signal is around subagent lifecycle and spawn planning, which owns the async-versus-preflight contract choice.

Owner confidence: high

Options:

- **Terminalize async startup failures (recommended):** Keep `sessions_spawn` async acceptance behavior and add a typed startup-failed terminal state plus visible logs/session metadata for Docker sandbox startup failures.
- **Preflight sandbox before accept:** Resolve and start the sandbox before returning `accepted`, making spawn failures immediate but changing the existing async contract and latency profile.
- **Defer to lifecycle PR only:** Let the broader lifecycle work define first-progress/startup-failed semantics before changing the sandbox-specific path, while keeping this issue as the Docker proof case.
