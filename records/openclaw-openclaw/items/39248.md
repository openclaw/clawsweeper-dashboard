## Summary

Keep open: current main still accepts sandboxed `sessions_spawn` runs before child sandbox startup, classifies generated child keys as `non-main` sandbox targets, and lacks a merged path proving Docker-backed child startup failures become visible terminal session state instead of zero-progress runs.

## What This Changes

The issue reports that `agents.defaults.sandbox.mode: "non-main"` causes `sessions_spawn` subagents to be accepted but never initialize or emit diagnostic output.

## Best Possible Solution

Keep this as the sandbox-specific tracker, choose the startup-failure contract, then implement and live-prove both successful and forced-failure Docker `non-main` `sessions_spawn` behavior on current main.
