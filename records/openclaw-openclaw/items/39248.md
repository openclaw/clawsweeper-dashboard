## Summary

Keep open: current main still has the documented `non-main` sandboxed `sessions_spawn` path, accepts child runs asynchronously, and has no merged fix that proves sandboxed child startup failures become visible instead of hanging until timeout.

## What This Changes

Fix `sessions_spawn` so subagents initialized under `agents.defaults.sandbox.mode: "non-main"` either start normally or fail visibly instead of staying accepted/running with no progress.

## Best Possible Solution

Keep this as the canonical sandbox-specific tracker, choose the startup-failure contract, then prove both normal and forced-failure Docker `non-main` `sessions_spawn` behavior on current main.
