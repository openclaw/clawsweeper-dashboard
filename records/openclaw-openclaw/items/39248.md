## Summary

Keep open: current main still supports defaults-level `non-main` sandboxed subagent sessions, accepts the run before sandbox context startup, and lacks a merged sandbox-specific proof that this `sessions_spawn` path now starts or terminalizes/logs Docker startup failure correctly. The broader lifecycle issue and open PR overlap the silent-start symptom, but they do not replace this sandbox-specific live proof case.

## What This Changes

The issue asks OpenClaw to fix `sessions_spawn` child sessions that are accepted but never initialize when `agents.defaults.sandbox.mode` is `"non-main"`.

## Best Possible Solution

Add one owner-approved startup failure contract for sandboxed subagents, then prove defaults-level `non-main` `sessions_spawn` starts successfully and a forced Docker startup failure logs and terminalizes the child run.

Options:

- **Terminalize Async Startup Failure (recommended):** Keep the accepted async contract and add typed/logged startup failure state that `subagents list`, session history, and gateway waits can observe.
- **Preflight Before Accept:** Validate enough sandbox startup before returning accepted, trading lower ambiguity for new latency and compatibility risk in callers.
- **Defer To Lifecycle Contract:** Make the broader lifecycle issue own the event contract, while keeping this issue as the required Docker-backed proof case.
