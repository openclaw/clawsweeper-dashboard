## Summary

Keep open: current main still supports the reported defaults-level `non-main` sandboxed `sessions_spawn` path, and no merged current-main fix or live Docker-backed proof shows that the child now starts or reaches a visible terminal sandbox failure. The broader lifecycle issue and open PR overlap the silent-hang symptom, but they do not supersede this sandbox-specific report.

## What This Changes

The issue reports that `agents.defaults.sandbox.mode: "non-main"` makes `sessions_spawn` accept a child subagent run that never initializes, emits no transcript or tokens, and eventually times out silently.

## Best Possible Solution

Keep this issue as the sandbox-specific proof case, choose one owner-approved startup-failure contract, and prove `sessions_spawn` under defaults-level `non-main` both starts normally and terminalizes/logs a forced Docker startup failure.

Options:

- **Terminalize async startup failure (recommended):** Keep the accepted `sessions_spawn` contract and add/log a typed terminal startup failure that registry, sessions UI, and waits can observe for Docker sandbox startup failures.
- **Preflight sandbox before accepted:** Move enough sandbox startup validation ahead of the accepted response so `sessions_spawn` rejects immediately, accepting extra latency and compatibility impact for callers.
- **Defer to lifecycle redesign:** Treat this issue as blocked by the broader lifecycle contract in https://github.com/openclaw/openclaw/issues/58776, while preserving this issue as the Docker `non-main` proof case.
