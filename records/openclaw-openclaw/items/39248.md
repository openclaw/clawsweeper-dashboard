## Summary

Keep open: current main and the latest release still support `non-main` sandboxed subagent sessions, still return accepted asynchronously for generated child runs, and still lack a merged startup-failure/first-progress lifecycle contract for the reported silent child-start stall.

## What This Changes

The issue reports that `agents.defaults.sandbox.mode: "non-main"` causes sandboxed `sessions_spawn` child runs to be accepted but never execute or report startup errors.

## Best Possible Solution

Keep this as the canonical sandbox-specific tracker, choose the startup-failure contract, then land a focused fix that makes failed sandbox startup visible in logs, session history, subagent status, and waits with live Docker proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should sandboxed `sessions_spawn` preserve the async accepted response and then terminalize failed child startup, or should it preflight enough sandbox startup work to reject before returning accepted?

Rationale: That choice changes the public async spawn contract, session/registry state, gateway waits, and the overlap with broader startup lifecycle work, so automation should not pick the permanent behavior alone.

Likely owner: steipete

Owner reason: The subagent registry/lifecycle history makes this the strongest available owner for the API behavior choice.

Owner confidence: medium

Options:

- **Terminalize Async Startup Failure (recommended):** Keep the accepted response contract and add typed/logged terminal startup failure state for child sessions and waits.
- **Preflight Sandbox Before Accept:** Move enough sandbox startup validation before acceptance to fail fast, accepting extra latency and upgrade review.
- **Resolve In Broader Lifecycle Work:** Keep this issue open while a maintainer-sponsored lifecycle PR covers both first progress and sandbox-start failure semantics.

## Reproduction Assessment

Yes at source level, but not as a live Docker reproduction here. Current main still routes generated subagent session keys through `non-main` sandbox classification, returns accepted asynchronously, and lacks a typed startup-failure projection for accepted child runs.

## Solution Assessment

Unclear pending maintainer intent. Terminalizing failed startup after acceptance looks least disruptive, but maintainers should choose that contract over pre-accept sandbox preflight before implementation.
