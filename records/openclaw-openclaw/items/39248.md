## What This Changes

The issue reports that `agents.defaults.sandbox.mode: "non-main"` makes Docker-backed `sessions_spawn` subagents accept a run but never initialize, produce messages, write transcripts, or log an actionable failure.

## Best Possible Solution

Adopt one owner-approved startup failure contract for sandboxed subagents, then prove defaults-level `non-main` `sessions_spawn` starts normally and terminalizes/logs a forced Docker startup failure.
