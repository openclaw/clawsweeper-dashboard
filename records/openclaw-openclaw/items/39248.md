## Label Justifications

- `P1`: The issue blocks core subagent orchestration for sandboxed `sessions_spawn` users by leaving accepted child runs apparently running with no visible progress or failure.
- `impact:session-state`: The reported failure leaves child session/run state stuck at zero tokens with no transcript or terminal error visible to the parent.

## Summary

Keep open: current main still supports `agents.defaults.sandbox.mode: "non-main"` for subagent sessions, but the sandboxed `sessions_spawn` path can still accept the child run before Docker startup and has no merged, live-proven startup-failure lifecycle/reporting contract. The overlapping lifecycle issue and PR do not close this sandbox-specific tracker.

## What This Changes

A supported `non-main` sandbox mode is reported to make `sessions_spawn` accept subagents that never emit output, tokens, transcript, or visible startup errors.

## Best Possible Solution

Pick one owner-approved startup-failure contract, then add focused source tests and live Docker proof that `non-main` sandboxed subagents either start or visibly terminalize with an actionable sandbox startup error.
