## Summary

Keep open: current main still matches the core reported shape where `sessions_spawn` child keys are sandboxed under `non-main`, the gateway acknowledges the run before sandbox startup, and no merged change proves Docker-backed subagent initialization failures become visible instead of hanging until timeout.

## What This Changes

The issue reports that `agents.defaults.sandbox.mode: "non-main"` causes `sessions_spawn` subagents to be accepted but never initialize, with no messages, tokens, transcript, or gateway error.

## Best Possible Solution

Keep this as the sandbox-specific tracker, choose the startup-failure contract, then implement and live-prove both successful and forced-failure Docker `non-main` `sessions_spawn` behavior on current main.
