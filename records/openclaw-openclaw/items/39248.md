## Summary

Keep open: current main still supports defaults-level `non-main` sandboxed subagent sessions, and the Docker-backed `sessions_spawn` startup stall is not proven fixed or superseded by a merged current-main change.

## What This Changes

The issue reports that `agents.defaults.sandbox.mode: "non-main"` makes `sessions_spawn` accept child sessions that never initialize, emit messages, write transcripts, or surface errors.

## Best Possible Solution

Add one owner-approved startup failure contract for sandboxed subagents, then prove defaults-level `non-main` `sessions_spawn` starts normally and terminalizes/logs a forced Docker startup failure.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should sandboxed subagent startup failures remain accepted asynchronously and then terminalize with a typed startup failure, or should `sessions_spawn` preflight sandbox startup before returning accepted?

Rationale: Both designs can fix the visible hang, but the choice changes the `sessions_spawn` acceptance contract, registry lifecycle state, gateway wait behavior, and the overlapping startup-silence work.

Likely owner: steipete

Owner reason: steipete has the strongest recent cross-surface history in subagent spawn, registry, gateway, and lifecycle code touched by this contract choice.

Owner confidence: high

Options:

- **Terminalize async startup failure (recommended):** Keep the accepted async spawn contract, but emit and persist a typed startup failure visible through subagent/session tools and gateway waits.
- **Preflight sandbox before accept:** Validate enough Docker sandbox startup before returning accepted, trading lower ambiguity for more latency and compatibility risk in the spawn call.
- **Defer to lifecycle contract:** Keep this issue as the sandbox-specific proof case while the broader startup lifecycle design is settled elsewhere.

## Reproduction Assessment

No high-confidence live current-main reproduction was established. The source path is clear: current main still routes defaults-level `non-main` child sessions into sandbox startup after the accepted gateway response.

## Solution Assessment

Unclear until maintainers choose the startup failure contract. The narrowest maintainable fix should align `sessions_spawn`, gateway wait/session state, subagent registry, and Docker sandbox startup proof instead of patching one observer path.
