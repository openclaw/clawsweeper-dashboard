## Summary

Keep open: current main still supports defaults-level `non-main` sandboxed `sessions_spawn` child sessions, still returns accepted before async sandbox context startup, and no merged/current-main proof shows this Docker-backed path now starts or terminalizes/logs startup failure correctly.

## What This Changes

The issue reports `agents.defaults.sandbox.mode: "non-main"` causing `sessions_spawn` subagents to be accepted but never start, with zero tokens, no transcript, and no gateway errors.

## Best Possible Solution

Add one owner-approved startup failure contract for sandboxed subagents, then prove defaults-level `non-main` `sessions_spawn` starts successfully and forced Docker startup failure logs and terminalizes the child run.
