## Summary

Keep open: current main still supports defaults-level `non-main` sandboxed subagent sessions and still accepts the child run before Docker sandbox startup is reached, but there is no merged fix or live Docker proof that this path now starts normally or terminalizes with a visible sandbox startup error. The broader lifecycle issue and PR overlap the silent-startup symptom, but they do not settle this sandbox-specific `sessions_spawn` report.

## What This Changes

Fix defaults-level `non-main` sandboxed `sessions_spawn` so Docker-backed child agents either initialize and run or fail visibly instead of remaining `running` with no messages, tokens, transcript, or logs.

## Best Possible Solution

Add one owner-approved startup failure contract for sandboxed subagents, then prove defaults-level `non-main` `sessions_spawn` both starts successfully and terminalizes/logs a forced Docker startup failure.

## Maintainer Decision

Kind: product_direction

Question: Should sandboxed subagent startup failures stay on the accepted-then-async `sessions_spawn` contract with a terminal startup failure state, or should sandbox startup be preflighted before returning accepted?

Rationale: Both shapes could fix the visible hang, but the choice affects lifecycle events, registry/session state, gateway wait behavior, and the overlapping startup-silence contract in https://github.com/openclaw/openclaw/issues/58776.

Likely owner: steipete

Owner reason: This owner has the strongest history across the `sessions_spawn`, sandbox, subagent lifecycle, and gateway surfaces affected by the decision.

Owner confidence: high

Options:

- **Terminalize async startup failure (recommended):** Keep the accepted async spawn contract, but emit/log a typed startup failure and prove registry, session history, subagents list, and gateway wait callers see it for Docker sandbox startup failures.
- **Preflight sandbox before accept:** Move enough sandbox startup validation ahead of the accepted response to reject immediately, accepting latency and compatibility changes for existing callers.
- **Defer to lifecycle contract:** Keep this issue as the sandbox-specific proof case while maintainers first settle the broader startup lifecycle design in https://github.com/openclaw/openclaw/issues/58776.
