## Summary

Keep open: current main still routes generated `sessions_spawn` child keys through the supported `non-main` sandbox path and returns the gateway `accepted` response before the child run performs sandbox startup, while no merged current-main or shipped fix proves the reported silent Docker-backed initialization stall is resolved.

## What This Changes

The issue reports that `agents.defaults.sandbox.mode: "non-main"` causes `sessions_spawn` subagents to be accepted but never initialize or emit errors.

## Best Possible Solution

Keep this as the sandbox-specific tracker, choose the startup-failure contract, then implement and prove visible/logged terminal state for forced Docker startup failure and normal `non-main` `sessions_spawn` behavior.
