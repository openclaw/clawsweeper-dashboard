## Summary

Keep open: current main still supports `agents.defaults.sandbox.mode: "non-main"` for subagent sessions, but sandboxed `sessions_spawn` can still dispatch the child before sandbox backend startup and there is no merged startup-failure lifecycle/session-state contract that would make this failure visible.

## What This Changes

The issue reports that `agents.defaults.sandbox.mode: "non-main"` causes sandboxed `sessions_spawn` subagents to be accepted but never initialize, emit tokens, create transcripts, or log a useful error.

## Best Possible Solution

Choose one owner-approved startup-failure contract, then add focused tests and live Docker proof that `non-main` sandboxed subagents either start or visibly terminalize with an actionable sandbox startup error.
