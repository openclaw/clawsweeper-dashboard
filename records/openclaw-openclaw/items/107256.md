## Summary

The linked OAuth defect remains valid, but the prior P1 blocker is still present at the unchanged reviewed head: this implementation moves an auth-manager refresh policy into a generic multi-provider helper and therefore broadens refresh timing beyond the failing manager path. Contributor-supplied after-fix real behavior proof is also still absent.

## What This Changes

The PR imports the auth manager’s five-minute refresh margin into `getOAuthApiKey` so credentials inside that window invoke the provider refresh method.

## Best Possible Solution

Keep `getOAuthApiKey`’s existing expired-only default and make the auth manager’s already-selected refresh path explicitly invoke or request an unconditional provider refresh under its lock, with regression coverage for both the manager path and unchanged direct-helper semantics.
