## Summary

This PR addresses a real refresh no-op, but the patch changes a shared OAuth helper’s expired-only contract instead of carrying explicit refresh intent through the auth-manager path. The prior blocking finding remains applicable, and contributor-supplied after-fix behavior proof is still missing.

## What This Changes

The PR makes `getOAuthApiKey` refresh credentials when they enter the auth manager’s five-minute pre-expiry margin.

## Best Possible Solution

Keep `getOAuthApiKey` expired-only by default, make the manager-owned fallback explicitly refresh after the manager has decided refresh is required, and cover both ordinary accessor behavior and forced manager refresh with focused tests.
