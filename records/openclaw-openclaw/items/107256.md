## Summary

The underlying Anthropic refresh bug is valid, but this PR changes the shared OAuth helper’s contract for every built-in provider instead of fixing the manager-owned fallback that incorrectly asks an expiry-gated helper to perform an already-decided refresh. The branch also lacks after-fix real behavior proof.

## What This Changes

Changes the generic `getOAuthApiKey` helper to refresh credentials within OpenClaw’s five-minute auth-manager margin instead of only after their stored expiry.

## Best Possible Solution

Keep `getOAuthApiKey` expiry-only, make the auth-profile refresh adapter call the resolved provider’s unconditional refresh operation after the manager has selected and locked the credential, and cover both the four-minute Anthropic case and a still-valid direct-helper call.
