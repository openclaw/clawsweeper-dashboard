## Summary

Keep open. The isolated cron stream-stall headline appears addressed by the run-lifecycle and cron idle-timeout work cited in the discussion, but two independently reported failures remain: main-session `systemEvent` payloads can disappear while the cron run reports success, and `cron wake` can return `{ok:true}` while the heartbeat fails. Those need current-version verification and separate, narrowly scoped ownership rather than closing this bundled report.

## What This Changes

Fix cron jobs whose main-session system events vanish, whose isolated AI runs stall during model streaming, or whose immediate wake command falsely reports success after a failed heartbeat.

## System Context

Cron jobs enter the scheduler as either main-session events or isolated agent turns, then invoke the agent runtime and optionally deliver a result to a channel. The affected paths determine whether a scheduled payload reaches the target session, whether a model stream terminates, and whether the wake API reports the actual heartbeat outcome.
