## Summary

Keep this issue open: current `main` still forwards QMD snippet text through the adapter without removing the QMD location envelope or complete MCP line-number sequences, and the same text is persisted into Dreaming recall state. The report identifies a concrete current bug with a bounded adapter-and-repair solution rather than a duplicate of the broader Dreaming-quality issue.

## What This Changes

Parse QMD transport metadata into structured line locations, return clean memory snippets, and repair contaminated short-term Dreaming recall records.

## Best Possible Solution

Add one strict normalization helper at the QMD adapter boundary for both CLI and mcporter results, preserve parsed locations in `startLine` and `endLine`, extend the memory-core repair path to rewrite affected stored recalls and concept tags once, and cover genuine numbered prose plus malformed or partial envelopes with regression tests.
