## Label Justifications

- `P1`: A stalled Discord metadata DNS or proxy preflight can block gateway startup indefinitely, breaking an active channel workflow until restart.

## Summary

This PR remains useful: the existing Discord gateway-info deadline does not cover SSRF-guard DNS/proxy preflight unless its abort signal is forwarded at the guard boundary, and the proposed design fixes that gap without adding configuration or a second production timer. The patch and after-fix proof support the behavior, with no blocking correctness or security finding.

## What This Changes

Forwards Discord gateway metadata cancellation into the SSRF guard, adds a timeout floor for unsignaled calls, threads the resolved timeout through plugin fetch construction, and adds regression coverage.

## Best Possible Solution

Keep one production deadline owner, forward its AbortSignal into the SSRF guard so preflight and request execution share cancellation, retain the resolved timeout only as an unsignaled floor, and preserve the focused stalled-preflight and hung-peer regressions.
