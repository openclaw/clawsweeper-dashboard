## Summary

Keep this PR open for a narrow repair: the shared deadline is the right root fix, but forwarding the existing `/gateway/bot`-specific timeout into broader Discord REST and media paths can break existing configurations after upgrade.

## What This Changes

The PR adds a timeout to the shared guarded Discord fetch, threads the resolved gateway-info timeout through normal and proxy paths, and adds timeout propagation and stalled-header coverage.

## Best Possible Solution

Give the shared guarded Discord fetch a bounded internal default while keeping `gatewayInfoTimeoutMs` scoped to `/gateway/bot`; introduce a separately named public REST timeout only through an intentional config-contract and upgrade change.
