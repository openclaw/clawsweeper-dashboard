## Summary

Keep open: this is still the canonical QMD symlink-loop robustness tracker, and current main does not yet contain an OpenClaw-side traversal guard or a clear QMD version/doctor policy that closes the reported failure mode.

## What This Changes

The issue requests that QMD memory indexing avoid breaking on workspace-visible temporary monorepos whose package-manager symlinks can expand into recursive Markdown paths.

## Best Possible Solution

Keep this issue open, recreate the symlink-loop fixture against current main and current npm-latest QMD, then either version-gate/doctor the fixed QMD scanner or add an OpenClaw-side pre-update guard that prunes before QMD traversal can recurse.
