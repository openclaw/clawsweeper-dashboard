## Summary

This PR should remain open: its inference-first and route-bound credential direction is well supported, but the current head still admits setup activation before it waits behind another Crestodian RPC, allowing configuration or credential mutation after the caller times out or cancels. The branch also conflicts with current main and needs a fresh exact-head review after repair. Likely related people: @steipete is the high-confidence feature owner; @zhangguiping-xydt is a medium-confidence adjacent Codex lifecycle contributor.

## What This Changes

The branch overhauls onboarding and Crestodian inference gating, binds Gateway credentials and UI handoffs to selected routes, isolates named-profile approval migrations, and extends the Codex runtime, plugin SDK, packaging, docs, and test surfaces.

## Best Possible Solution

Make setup activation fail synchronously whenever the shared Crestodian Gateway queue is occupied, or give activation a cancellation-aware non-queueing exclusive path, while preserving restart-drain accounting, inference verification, route-bound credentials, and profile isolation; then resolve conflicts and re-prove the final head.
