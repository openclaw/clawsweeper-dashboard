## Summary

This is a substantive provider-boundary fix, but the shared retry-default change can remove transient-failure recovery from callers that do not use OpenClaw’s outer failover loop; real provider behavior is also not demonstrated in the supplied evidence.

## What This Changes

The PR normalizes malformed message content, preserves reasoning replay, adjusts OpenRouter and Z.AI compatibility payloads, disables implicit OpenAI SDK retries, and surfaces HTTP response bodies in provider errors.

## Best Possible Solution

Keep the shared normalization, reasoning-replay, declarative compatibility, and bounded error-formatting work, but disable SDK retries only at app-owned call sites that demonstrably provide outer retry/failover and ensure arbitrary response bodies are redacted before reaching users.
