## Summary

Keep this PR open for normal merge review. The patch directly prevents core doctor from writing an unverified key into external-plugin configuration, matching the repository’s owner boundary that plugin-owned configuration repairs belong to the plugin; its supplied before/after migration output also shows the reported external-channel regression while retaining the bundled Telegram migration. The remaining consideration is an intentional compatibility tradeoff for any unregistered external plugin that had relied on this undocumented core write path.

## What This Changes

The PR changes the doctor upgrade migration so channels without bundled config-schema metadata are left unchanged instead of receiving a generated `groupAllowFrom` setting.

## System Context

During upgrades, the doctor command normalizes channel configuration by copying legacy sender allowlists into explicit group allowlists. It consults bundled channel schema metadata before writing, and the resulting configuration is later validated when the Gateway starts.

## Architecture Diagram

## Best Possible Solution

Adopt schema-verified core writes for bundled channels and keep external-plugin configuration migrations in the owning plugin’s doctor contract, with any affected plugin adding its own explicit upgrade repair if needed.
