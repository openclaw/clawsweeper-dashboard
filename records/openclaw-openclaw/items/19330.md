## Label Justifications

- `P2`: The issue is a source-backed privacy and correctness gap in multi-agent media handling, but it needs bounded security/product design rather than emergency repair.
- `impact:security`: Media intended for one agent can remain readable from a shared managed inbound root by another agent with filesystem access.
- `impact:session-state`: The reported and related examples involve agents selecting or processing media from the wrong agent, account, channel, or conversation context.

## Summary

Keep open: current main and the latest release still preserve a flat shared inbound-media contract across media saves, managed references, representative bundled channel downloads, and sandbox staging, so the reported cross-agent privacy/session-state gap remains unresolved.

## What This Changes

The issue requests scoped inbound media storage so media received for one agent or account is not readable or staged as shared media for another agent.

## Best Possible Solution

Define one canonical scoped inbound-media contract across storage, managed refs or a media index, channel/plugin save APIs, local access checks, sandbox staging, cleanup, docs, and regression tests.

- **Defer to media provenance design:** Keep this tracker open until maintainers choose a media-index or provenance schema rather than changing the filesystem layout first.

Yes, at source level. Current main still defaults media saves to the flat inbound bucket, representative channel saves use that bucket, scoped managed refs are rejected, and sandbox staging flattens filenames.

## Solution Assessment

Unclear as proposed. Account subdirectories are plausible, but the maintainable fix needs a single scoped media contract instead of a save-path-only change.
