## Summary

Keep open: current main and the latest release still use shared inbound media storage for representative channel media, still reject scoped inbound media references, and still stage sandbox media into flat paths. The related Feishu and channel-namespacing issues are narrower slices, and the direct implementation PR is closed unmerged.

## What This Changes

The issue requests agent- or account-scoped inbound media storage so media received by one agent is not visible to other agents through the shared media directory.

## Best Possible Solution

Define a maintainer-approved scoped inbound-media contract across save paths, managed references, sandbox staging, cleanup and retention, docs, compatibility, and explicit sharing semantics.

## Reproduction Assessment

Yes, at source level: current main still saves representative inbound media into a shared inbound bucket, rejects scoped managed refs, and stages sandbox media into flat media/inbound/<file> paths. I did not run a live multi-agent deployment, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Unclear as proposed: account-id subdirectories are plausible, but a save-time-only change would leave reference resolution, sandbox staging, cleanup, compatibility, and explicit sharing semantics incomplete. The best fix is a maintainer-approved scoped media contract across the pipeline.
