## Summary

Keep open: current main and v2026.6.11 still save representative inbound media into the shared inbound bucket, reject scoped nested inbound refs, and flatten staged media paths, so the central privacy/correctness problem remains unsolved.

## What This Changes

The issue requests per-agent or otherwise scoped inbound media storage so files received by one agent/channel are not pooled with media for other agents.

## Best Possible Solution

Define a maintainer-approved scoped inbound-media contract across save paths, managed references, sandbox staging, cleanup/retention, docs, compatibility, and regression coverage.

## Reproduction Assessment

Yes, at source level: current main still saves representative inbound media into a shared inbound bucket, rejects scoped managed refs, and stages sandbox media into flat media/inbound paths. I did not run a live multi-agent deployment, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Unclear as proposed: account-id subdirectories are plausible, but a save-time-only change would leave reference resolution, sandbox staging, cleanup, compatibility, and explicit sharing semantics incomplete. The best fix is a maintainer-approved scoped media contract across the pipeline.
