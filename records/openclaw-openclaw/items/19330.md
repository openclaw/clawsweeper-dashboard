## Label Justifications

- `P2`: The issue is a source-backed privacy and correctness gap in multi-agent media handling, but it needs bounded security/product design rather than emergency repair.
- `impact:security`: Media intended for one agent can remain readable from a shared managed inbound root by another agent with filesystem access.
- `impact:session-state`: The reported and related examples involve agents selecting or processing media from the wrong agent, account, or conversation context.

## Summary

Keep open: current main and latest release still preserve a shared flat inbound-media path across storage, managed references, representative channel downloads, and sandbox staging, so the reported cross-agent privacy/session-state gap remains unresolved.

## What This Changes

The issue requests scoped inbound-media storage so media received for one agent is not visible or selected by other agents in multi-agent deployments.

## Best Possible Solution

Define one canonical scoped inbound-media contract across storage, managed refs or a media index, channel/plugin save APIs, local access checks, sandbox staging, cleanup, docs, and regression tests.
