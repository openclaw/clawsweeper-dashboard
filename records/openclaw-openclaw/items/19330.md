## Label Justifications

- `P2`: The issue reports a real multi-agent privacy and correctness gap with limited deployment-specific blast radius.
- `impact:security`: Shared inbound media can expose private files received by one agent to another agent with filesystem media access.
- `impact:session-state`: Media intended for one routed agent or session can become visible to another agent/session through the shared media pool.
- `maturity:stable`: The issue affects Discord media handling, and `qa/maturity-scores.yaml` marks the Discord surface as M4 Stable.

## Summary

Keep open: current main and the latest release still preserve the shared inbound media contract, flat managed-media references, and flat sandbox staging path, so the reported cross-agent media privacy gap remains unresolved.

## What This Changes

The issue requests isolating inbound media by agent/account instead of storing all channel downloads in one shared `media/inbound` pool.

## Best Possible Solution

Keep this as the canonical core tracker and define a scoped managed-media contract across storage, channel saves, URI/path resolution, local-root access, sandbox staging, cleanup, docs, and regression coverage.
