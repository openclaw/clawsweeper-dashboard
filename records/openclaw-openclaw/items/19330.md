## Summary

Keep open: current main and the latest release still use a shared flat inbound media store for representative channel downloads, reject scoped managed inbound references, and flatten sandbox staging, so the cross-agent privacy/correctness gap remains. The directly linked implementation PR is closed unmerged, while the open Feishu and channel-namespacing reports are narrower slices rather than replacements.

## What This Changes

The issue requests a scoped inbound-media contract so media received for one agent/account is not exposed through the same flat inbound pool as other agents/accounts.

## Best Possible Solution

Define a maintainer-approved scoped inbound-media contract across save paths, managed references, sandbox staging, access checks, cleanup/retention, docs, compatibility, and explicit sharing, preserving or deliberately migrating existing flat media.

## Reproduction Assessment

Yes at source level: current main still saves representative inbound media into a shared inbound bucket, rejects scoped managed refs, and stages sandbox media into flat media/inbound/<file> paths. I did not run a live multi-agent deployment, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Unclear as proposed: account-id subdirectories are plausible, but a save-time-only change would leave reference resolution, sandbox staging, cleanup, compatibility, and explicit sharing semantics incomplete. The best fix is a maintainer-approved scoped media contract across the pipeline.
