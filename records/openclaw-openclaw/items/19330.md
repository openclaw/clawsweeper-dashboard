## Label Justifications

- `P2`: The issue is a real security/correctness gap in multi-agent deployments, but it needs product/security design rather than an emergency runtime fix.
- `impact:security`: Shared inbound media can expose sensitive files received by one agent to another agent with access to the same media root.
- `impact:session-state`: Flat inbound media can let an agent attach, transcribe, or reason over media from the wrong agent/session context.
- `maturity:stable`: The issue affects Discord inbound media handling, and `qa/maturity-scores.yaml` scores Discord as M4 Stable with Media and Rich Content LTS-supported.

## Summary

Keep open: current main and the latest release still leave representative inbound media in a shared `inbound` bucket, while managed-media URI resolution and sandbox staging still assume flat first-level inbound files. The related open items are narrower slices, and the closed implementation attempt was not merged, so this issue remains the canonical cross-channel media-isolation tracker.

## What This Changes

The issue requests per-agent or per-account scoping for inbound media so files received by one agent are not pooled with files for another agent.

## Best Possible Solution

Keep this issue as the canonical tracker and design one scoped inbound-media ownership contract that covers save callers, managed URI/path resolution, sandbox staging, cleanup, docs, and regression tests.

## Reproduction Assessment

Yes at source level: representative channel media saves still target the shared `inbound` bucket, managed media references reject scoped paths, and sandbox staging rewrites to a flat `media/inbound/<file>` path. I did not run a live multi-agent deployment repro in this read-only review.

## Solution Assessment

No, the issue's save-time account subdirectory proposal is only a plausible partial fix. The maintainable solution needs a single scoped media contract that also handles resolver semantics, sandbox staging, cleanup, compatibility, and explicit sharing behavior.
