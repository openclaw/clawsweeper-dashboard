## Label Justifications

- `P2`: The issue is a source-backed privacy and correctness gap in multi-agent media handling, but it needs a bounded security/product design rather than emergency repair.
- `impact:security`: Inbound files intended for one agent can remain readable from the same managed media root by another agent with filesystem access.
- `impact:session-state`: The reported and related examples involve agents selecting or processing media from the wrong agent, account, or conversation context.

## Summary

Keep open: current main and the latest release still preserve a shared flat managed inbound-media contract across representative save, reference, and staging paths, so the cross-agent privacy/session-state gap remains unresolved and needs a maintainer security-boundary decision.

## What This Changes

Request scoped inbound media storage so media sent to one agent/account/session cannot be read or staged as another agent's media.

## Best Possible Solution

Define one canonical scoped managed inbound-media contract across storage, media refs or media index, channel/plugin save APIs, local access checks, sandbox staging, cleanup, docs, and regression tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: What should the canonical inbound-media isolation boundary be across agents and channels: account-scoped, agent/session-scoped, tenant-aware, or explicit-share based?

Rationale: The source proves the shared flat pool remains, but choosing account, resolved agent, session, channel/chat, tenant, or indexed provenance is a security and compatibility decision automation should not invent.

Likely owner: steipete

Owner reason: The history most strongly routes the original inbound media and sandbox-staging contracts through this area.

Owner confidence: high

Options:

- **Adopt scoped managed media contract (recommended):** Define a core contract for scoped managed inbound media, then update bundled channels, resolvers, staging, cleanup, docs, and tests together.
- **Limit first step to account subdirs:** Use sanitized channel/account identifiers as the first isolation boundary, accepting that session/chat/tenant provenance remains follow-up work.
- **Defer for media provenance design:** Keep the tracker open until maintainers choose a broader media index or provenance schema for filesystem and resolver behavior.

## Reproduction Assessment

Yes, at source level. Current main still defaults media saves to the flat inbound bucket, representative channel saves use that bucket, scoped managed refs are rejected, and sandbox staging flattens filenames.

## Solution Assessment

Unclear: scoped storage is the right direction, but the best fix must cover the durable media-reference, sandbox-staging, access-control, compatibility, cleanup, and explicit-sharing contract rather than only changing save-time subdirectories.
