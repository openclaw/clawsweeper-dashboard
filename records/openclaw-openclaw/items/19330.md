## Label Justifications

- `P2`: The issue reports a bounded but real multi-agent media isolation gap that needs maintainer security/product design rather than emergency runtime repair.
- `impact:security`: A shared inbound media directory can expose media intended for one agent/account to another agent with filesystem access.
- `impact:session-state`: Flat inbound media can cause a different routed agent/session to pick up or process media from the wrong context.
- `maturity:stable`: The issue affects Discord inbound media/rich content, and the checked-in scorecard marks the Discord surface M4 Stable.

## Summary

Keep open: current main and `v2026.6.11` still use a shared flat inbound media contract, and the open related items are narrower slices rather than replacements for this broad cross-agent media isolation tracker.

## What This Changes

The issue requests isolating inbound media by agent, account, session, or similar scope so media received for one agent cannot be read or staged by another agent.

## Best Possible Solution

Keep this as the canonical broad tracker and define one scoped managed-media contract across storage, channel saves, URI/path resolution, sandbox staging, access checks, cleanup, docs, and regression tests.

- **Defer broad core change:** Keep only narrower channel-specific slices open until a maintainer sponsors a cross-channel core media-isolation design.

## Reproduction Assessment

Yes, from source inspection. Current main still routes representative inbound channel media through the flat `inbound` bucket, rejects scoped managed inbound references, and stages sandbox media into a flat `media/inbound` path; I did not run a live multi-agent deployment.

## Solution Assessment

Unclear as proposed. Scoped storage is the right direction, but the best fix must cover the durable media-reference, sandbox-staging, access-control, compatibility, cleanup, and sharing contract rather than only changing save-time subdirectories.
