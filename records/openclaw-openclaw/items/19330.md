## Summary

Keep open: current main and v2026.6.11 still use a shared inbound media bucket, reject scoped managed media references, and flatten staged sandbox paths, so the reported multi-agent privacy and correctness gap remains unresolved.

## What This Changes

Request scoped inbound media storage so media received for one agent/account cannot be read or staged as if it belonged to another agent.

## Best Possible Solution

Define a maintainer-approved scoped managed inbound-media contract across store writes, references, sandbox staging, cleanup/retention, docs, compatibility, and explicit sharing semantics.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Which scoped inbound-media ownership model should OpenClaw support for multi-agent deployments before implementation: account, resolved agent, session/tenant, channel/chat provenance, or an explicit sharing contract?

Rationale: The code path is clear, but choosing the wrong scope can either leave cross-agent leakage in place or break existing managed-media references and plugin/channel behavior.

Likely owner: steipete

Owner reason: The core media store, managed-reference, and staging history most strongly routes through this owner trail.

Owner confidence: medium

Options:

- **Define one scoped managed-media contract (recommended):** Use this issue as the broad design owner and implement storage, resolver, staging, cleanup, docs, and tests together.
- **Limit to account-scoped saves:** Implement the narrower account-ID directory approach, accepting follow-up work for sessions, tenants, channel provenance, and explicit sharing.
- **Reject core isolation for now:** Leave isolation to operator filesystem policy and close the related reports as not planned.

## Reproduction Assessment

Yes, at source level: current main still stores representative channel media in a shared inbound bucket, rejects scoped managed refs, and stages sandbox media into flat media/inbound paths. I did not run a live multi-agent deployment, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Unclear as proposed: account-ID subdirectories are plausible, but a save-time-only change would leave reference resolution, sandbox staging, cleanup, compatibility, and explicit sharing semantics incomplete.
