## Summary

Keep open: current main and v2026.6.11 still use a shared inbound media bucket, reject scoped managed media references, and flatten staged sandbox media paths, so the multi-agent privacy and correctness gap remains unresolved.

## What This Changes

Request per-agent or otherwise scoped inbound media storage so files sent to one agent are not visible to other agents sharing the same OpenClaw media store.

## Best Possible Solution

Define one scoped managed inbound-media contract across store writes, managed references, sandbox staging, access checks, cleanup/retention, docs, compatibility, and explicit sharing semantics.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which scoped inbound-media ownership model should OpenClaw support for multi-agent deployments before implementation: account, resolved agent, session/tenant, channel/chat provenance, or an explicit sharing contract?

Rationale: The source-level problem is clear, but choosing the wrong scope can either leave cross-agent leakage in place or break existing managed-media references, channel behavior, and compatibility for flat inbound files.

Likely owner: steipete

Owner reason: The core media store, managed-reference, and staging history most strongly routes through this owner trail.

Owner confidence: high

Options:

- **Define one scoped media contract (recommended):** Keep this issue as the broad design owner and implement storage, resolver, staging, cleanup, docs, and tests together.
- **Limit to account-scoped saves:** Implement the narrower account-ID directory approach while explicitly leaving sessions, tenants, channel provenance, and sharing as follow-up work.
- **Defer core isolation:** Document current flat inbound behavior and leave operators responsible for filesystem isolation, accepting the privacy gap for now.

## Reproduction Assessment

Yes, at source level: current main still stores representative channel media in a shared inbound bucket, rejects scoped managed refs, and stages sandbox media into flat media/inbound paths. I did not run a live multi-agent deployment in this read-only cleanup pass.

## Solution Assessment

Unclear as proposed: account-ID subdirectories are plausible, but a save-time-only change would leave reference resolution, sandbox staging, cleanup, compatibility, and explicit sharing semantics incomplete.
