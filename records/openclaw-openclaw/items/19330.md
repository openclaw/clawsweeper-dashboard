## Label Justifications

- `P2`: The issue describes a real multi-agent privacy and correctness gap, but it requires a scoped design decision rather than an urgent broken default for all users.
- `impact:security`: Shared inbound media can expose files sent to one agent/account to another agent with filesystem access.
- `impact:session-state`: Flat inbound staging can let an agent attach, transcribe, or reason over media from the wrong agent/session context.

## Summary

Keep open: current main and the latest release still use a shared inbound media store plus flat managed-reference and sandbox staging contracts, so the multi-agent media privacy gap remains unresolved and needs a security-boundary decision.

## What This Changes

Request per-agent or per-account isolation for inbound media so files received by one agent cannot be read or staged by another in multi-agent deployments.

## Best Possible Solution

Define one secure scoped inbound-media contract across the core media store, managed URI/path resolver, sandbox staging, bundled/plugin channel saves, cleanup, docs, and regression tests, with a clear migration or compatibility story for existing flat inbound files.

Options:

- **Design scoped media contract first (recommended):** Adopt a single account/agent/channel/session-aware media contract with explicit sharing and upgrade behavior before implementation.
- **Accept narrow account scoping:** Scope saves by channel account ID now, accepting that it may not cover multi-agent, multi-tenant, managed URI, and explicit-sharing cases without follow-up work.
- **Document current trust boundary:** Keep flat inbound storage as an operator-managed trust boundary and document that multi-agent isolation requires separate instances or filesystem roots.

## Reproduction Assessment

Yes for a source-level reproduction: current main still saves representative inbound media into the shared inbound store and stages managed media into flat media/inbound paths. I did not run a live multi-agent deployment, but the code path is clear.

## Solution Assessment

No for the proposed save-time-only account subdirectory as the full fix: it helps the ingest path but leaves resolver, staging, cleanup, compatibility, and sharing semantics unresolved. The better fix is a single scoped media contract with security and migration rules.
