## Label Justifications

- `P2`: The issue is a source-backed privacy and correctness gap in multi-agent media handling, but the remaining work needs bounded security/product design rather than emergency repair.
- `impact:security`: Media intended for one agent can remain readable from a shared managed inbound root by another agent with filesystem access.
- `impact:session-state`: The reported and related examples involve agents selecting or processing media from the wrong agent, account, or conversation context.

## Summary

Keep open: current main and v2026.6.11 still use a shared flat inbound-media path across core save, bundled channel download, managed-reference, and sandbox-staging surfaces, so the security and session-state gap remains unresolved.

## What This Changes

Request to isolate OpenClaw-managed inbound media per agent or account so multi-agent deployments do not share one flat `media/inbound` pool.

## Best Possible Solution

Define one canonical scoped inbound-media contract across storage, managed references or media index, channel/plugin save APIs, local access checks, sandbox staging, cleanup, docs, and regression tests.

## Solution Assessment

Unclear as proposed. Account subdirectories are plausible, but the maintainable fix needs a single scoped media contract instead of a save-path-only change.
