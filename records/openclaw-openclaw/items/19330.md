## Label Justifications

- `P2`: The issue reports a real source-backed multi-agent media privacy gap with limited blast radius, but it needs design/security review before implementation.
- `impact:security`: The reported failure mode is cross-agent access to private inbound media through a shared managed media root.
- `impact:session-state`: Media intended for one routed agent or session can become visible to another agent/session through shared storage and flat staging.
- `maturity:stable`: The issue affects Discord inbound media handling, and Discord is scored M4 Stable in qa/maturity-scores.yaml.

## Summary

Keep open: current main and the latest release still use a shared inbound media store, flat managed-media references, and flat sandbox staging, so the reported multi-agent media privacy gap remains unresolved and remains the broad tracker rather than a cleanup close.

## What This Changes

The issue requests isolating inbound media so files received for one agent are not stored in a shared pool readable by other agents.

## Best Possible Solution

Keep this as the canonical cross-channel media-isolation tracker and define one scoped managed-media contract across storage, channel saves, URI/path resolution, sandbox staging, local-root access, cleanup, docs, and tests.

Unclear as proposed. Scoped storage is the right direction, but the best fix must cover durable media references, sandbox staging, local access, cleanup, compatibility, and explicit sharing rather than only changing save-time subdirectories.
