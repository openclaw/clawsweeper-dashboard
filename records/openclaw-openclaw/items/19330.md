## Label Justifications

- `P2`: The issue is a source-backed privacy and correctness gap in multi-agent media handling, but it needs bounded security/product design rather than emergency repair.
- `impact:security`: Media intended for one agent can remain readable from a shared managed inbound root by another agent with filesystem access.
- `impact:session-state`: The reported examples involve agents selecting or processing media from the wrong agent, account, or conversation context.
- `maturity:stable`: The issue affects Discord inbound media handling, and the scorecard marks Discord M4 Stable with Media and Rich Content completeness Stable.

## Summary

Keep open: current main still uses a shared flat inbound-media contract across storage, representative channel downloads, managed-reference resolution, and sandbox staging, so the cross-agent privacy/session-state gap remains unresolved and this issue remains the broad canonical tracker.

## What This Changes

Request scoped inbound media storage so files received by one agent or account are not visible to other agents in multi-agent deployments.

## Best Possible Solution

Define one canonical scoped inbound-media contract across storage, managed refs or media index, channel/plugin save APIs, local access checks, sandbox staging, cleanup, docs, and regression tests.
