## Summary

Keep open: current main and v2026.6.11 still use a shared flat inbound media store for representative channel media, reject scoped `media://inbound` references, and flatten staged media paths. The prior implementation PR is closed unmerged, while the open Feishu and channel-namespacing reports are narrower slices rather than replacements.

## What This Changes

Request scoped inbound media storage, references, and sandbox staging so media sent to one agent or account cannot be read or selected by another.

## Best Possible Solution

Define a maintainer-approved scoped inbound-media contract across save paths, managed references, sandbox staging, cleanup/retention, docs, compatibility, and regression coverage.

## Reproduction Assessment

Yes, at source level: current main still saves representative inbound media into a shared inbound bucket, rejects scoped managed refs, and stages sandbox media into flat `media/inbound/<file>` paths. I did not run a live multi-agent deployment, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Unclear as proposed: account-id subdirectories are plausible, but a save-time-only change would leave reference resolution, sandbox staging, cleanup, compatibility, and explicit sharing semantics incomplete. The best fix is a maintainer-approved scoped media contract across the pipeline.
