## Label Justifications

- `P2`: The report describes a real multi-agent privacy/session-state gap, but the fix requires product/security boundary selection rather than an urgent one-line repair.
- `impact:security`: Inbound attachments for one agent can remain readable from the shared media pool by another agent with filesystem access.
- `impact:session-state`: Agents can pick up media from a different routed agent/session because the media store lacks scoped provenance and managed references.
- `maturity:stable`: The issue affects Discord inbound media, and `qa/maturity-scores.yaml` scores Discord as M4 Stable with Media and Rich Content coverage.

## Summary

Keep open: current main and the latest release still use a shared inbound media store and flat sandbox staging, so the reported multi-agent privacy/session-state gap remains unresolved and needs a maintainer security-boundary decision before implementation.

## What This Changes

The issue requests per-agent or per-account isolation for inbound media that is currently pooled in one shared media store.

## Best Possible Solution

Keep this as the canonical core media-isolation tracker until maintainers define a scoped inbound-media contract and update storage, provenance, reference resolution, staging, cleanup, docs, and regression coverage together.

Question: What identity should define the default inbound-media isolation boundary for multi-agent/channel deployments?

Rationale: Current source proves the flat store remains, but choosing account-, agent-, session-, or tenant-scoped paths affects security guarantees, plugin API shape, compatibility, cleanup, and explicit media-sharing behavior.

Likely owner: steipete

Owner confidence: high

Options:

- **Define a generic scoped media contract first (recommended):** Choose a core media identity/provenance contract, then update bundled/plugin media saves, managed URI resolution, sandbox staging, cleanup, docs, and regression coverage around that contract.
- **Use account-id directories only:** This is the narrowest implementation but may not match multi-tenant or multi-agent bindings where one account can route to multiple agents or where explicit sharing is needed.
- **Leave the flat store and document operator isolation:** This avoids compatibility churn but keeps the reported privacy and correctness failure mode as an operator responsibility.

## Reproduction Assessment

Yes for source-level reproduction: current main still writes representative inbound media to a flat `inbound` store and rejects nested managed inbound references. I did not run a live multi-agent media transfer in this read-only review.

## Solution Assessment

Unclear that the proposed account-id subdirectory alone is the best solution. A maintainer should first define the durable isolation identity and provenance contract, then implement storage, reference resolution, sandbox staging, cleanup, docs, and tests together.
