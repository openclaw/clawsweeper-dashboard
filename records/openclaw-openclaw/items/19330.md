## Summary

Keep open: current main and v2026.6.11 still use a shared inbound media store, shared media local roots, flat sandbox staging, and first-level-only managed refs, so the multi-agent privacy and correctness gap remains unsolved.

## What This Changes

Request per-agent isolation for inbound media so files received by one agent or account are not stored in a shared `media/inbound` pool visible to other agents.

## Best Possible Solution

Define a maintainer-approved scoped inbound-media ownership contract across save paths, managed references, local media roots, sandbox staging, cleanup, docs, compatibility, explicit sharing, and regression proof.

## Reproduction Assessment

Yes, at source level: current main still saves representative inbound media into a shared inbound bucket, exposes global media roots, rejects scoped managed refs, and stages sandbox media into flat `media/inbound` paths. I did not run a live multi-agent deployment, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Unclear as proposed: account-id subdirectories are plausible, but a save-time-only change would leave reference resolution, local media roots, sandbox staging, cleanup, compatibility, and explicit sharing semantics incomplete. The best fix is a maintainer-approved scoped media contract across the pipeline.
