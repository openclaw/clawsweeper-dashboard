## Label Justifications

- `P2`: The issue is a concrete multi-agent privacy and correctness gap with limited but real deployment blast radius, not an immediate crash loop or release-blocking setup failure.
- `impact:security`: Shared inbound media can expose sensitive files from one agent or trust boundary to another agent with filesystem access.
- `impact:session-state`: Flat inbound media can cause an agent/session to pick up media intended for a different agent, drifting the effective context.
- `maturity:stable`: The reported surface includes Discord inbound media handling, and the scorecard lists Discord as M4 Stable.

## Summary

Keep open: current main and the latest release still store representative inbound media in a shared flat `media/inbound` pool, reject scoped managed-media references, and stage sandbox media into flat paths, so the multi-agent privacy gap remains unresolved.

## What This Changes

Request scoped inbound media storage and staging so multi-agent deployments do not share one global inbound media pool.

## Best Possible Solution

Define one generic scoped inbound-media contract across core media storage, channel/plugin saves, managed references, sandbox staging, cleanup, and access checks, with explicit maintainer-approved compatibility behavior for existing flat inbound files.
