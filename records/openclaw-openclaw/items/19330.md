## Label Justifications

- `P2`: The issue is a source-backed privacy and correctness gap in multi-agent media handling, but it needs bounded security/product design rather than emergency repair.
- `impact:security`: Media intended for one agent can remain readable from a shared managed inbound root by another agent with filesystem access.
- `impact:session-state`: The reported and related examples involve agents selecting or processing media from the wrong agent, account, channel, or conversation context.
- `maturity:stable`: The issue affects Discord inbound media handling, and the checked-in maturity scorecard marks Discord as M4 Stable with stable Media and Rich Content completeness.

## Summary

Keep open: current main and the latest release still use a shared flat inbound-media contract across storage, managed refs, representative channel saves, and sandbox staging, so the cross-agent privacy/session-state gap remains unresolved.

## What This Changes

The issue requests scoped inbound media storage so media received for one agent/account cannot be discovered, selected, or staged by another agent.

## Best Possible Solution

Define one canonical scoped inbound-media/provenance contract across storage, managed refs or a media index, channel/plugin save APIs, access checks, sandbox staging, cleanup, docs, and regression tests.
