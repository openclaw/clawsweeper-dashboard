## Label Justifications

- `P2`: The issue reports a bounded but real multi-agent media isolation gap with privacy impact and no current merged fix.
- `impact:security`: Shared inbound media can expose private files received by one agent/account to another agent with filesystem access.
- `impact:session-state`: Media intended for one routed agent or session can become visible to another through the shared managed-media store.
- `maturity:stable`: The issue affects Discord inbound media handling, and the Discord surface is scored M4 Stable in qa/maturity-scores.yaml.

## Summary

Keep open: current main and the latest release still use a shared flat inbound media store and flat sandbox staging, so the cross-agent media privacy gap remains unresolved and still needs a maintainer security-boundary decision.

## What This Changes

The issue requests isolating inbound media storage so files received by one agent/account are not visible to other agents through the shared inbound media directory.

## Best Possible Solution

Define and implement a scoped managed-media contract across storage, channel saves, URI/path resolution, sandbox staging, local-media access, cleanup, docs, and regression tests while preserving or explicitly migrating existing flat inbound references.

## Solution Assessment

Unclear. Scoped storage is the right direction, but the proposed account-subdirectory-only fix is not proven to be the best solution until maintainers choose the media-reference, sandbox, access-control, cleanup, and sharing contract.
