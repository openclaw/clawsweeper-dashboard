## Label Justifications

- `P2`: The issue is a source-backed privacy and correctness gap in multi-agent media handling, but it needs bounded security/product design rather than emergency repair.
- `impact:security`: Media intended for one agent can remain readable from a shared managed inbound root by another agent with filesystem access.
- `impact:session-state`: The reported and related examples involve agents selecting or processing media from the wrong agent, account, or conversation context.

## Summary

Keep open: current main and v2026.6.11 still preserve a shared flat inbound-media contract across save, managed-reference, channel download, and sandbox-staging paths, so the cross-agent privacy/session-state gap remains unresolved.

## What This Changes

Request to isolate inbound media storage so media received for one agent/account/session is not pooled with media for other agents.

## Best Possible Solution

Define one canonical scoped inbound-media contract across storage, managed refs or media index, channel/plugin save APIs, local access checks, sandbox staging, cleanup, docs, and regression tests.

Unclear as proposed. Account subdirectories are plausible, but the maintainable fix needs a single scoped media contract instead of a save-path-only change.
