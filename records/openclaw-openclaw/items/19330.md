## Summary

Keep open: current main and the latest release still use a shared flat inbound media contract for representative media saves, managed references, and sandbox staging, so the multi-agent privacy gap remains unresolved.

## What This Changes

The issue requests scoped inbound-media isolation so media received by one agent or channel account cannot be read or staged for another agent from the shared `media/inbound` pool.

## Best Possible Solution

Define a maintainer-approved scoped inbound-media contract that carries sanitized channel/account or resolved agent scope through store, reference, staging, cleanup, docs, and bundled plugin callers while preserving a deliberate upgrade path for existing flat files.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: What scoped inbound-media isolation contract should OpenClaw support across the core media store, plugin SDK media saves, managed media refs, and sandbox staging?

Rationale: The code can technically write nested media subdirs, but choosing the permanent scope, URI shape, compatibility behavior, and fallback policy changes the security boundary for multi-agent deployments and plugin authors.

Likely owner: steipete

Owner reason: He has recent media-reference ownership signals and already participated in the issue review context for this surface.

Owner confidence: medium

Options:

- **Define a generic scoped media contract (recommended):** Use a core/plugin SDK contract for scoped inbound media, update bundled channels and sandbox staging together, and document the upgrade behavior for existing flat files.
- **Keep this as per-channel follow-ups:** Handle Feishu or Discord-specific isolation first, accepting that the broad shared-store privacy gap remains until a later core contract is chosen.
- **Keep the flat store and document limits:** Treat the shared inbound store as expected behavior and document that operators must isolate media access through workspaces or deployment boundaries.

## Reproduction Assessment

Yes, source-reproducible: current main still saves representative inbound media to `inbound`, rejects nested managed inbound refs, and stages files into flat `media/inbound` paths. I did not run a live multi-agent deployment, so this is source proof rather than a runtime reproduction.

## Solution Assessment

Unclear: the proposed account-ID subdirectory is plausible but not proven to be the best permanent boundary. A better maintainer-quality fix should choose the generic scope and update store, managed refs, channel/plugin callers, staging, cleanup, docs, and tests together.
