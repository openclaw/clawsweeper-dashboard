## Label Justifications

- `P2`: The issue reports a real but bounded multi-agent media isolation gap in shared inbound storage rather than an unusable runtime or confirmed emergency exploit.
- `impact:security`: The report describes one agent being able to access private inbound media intended for another agent through shared filesystem storage.
- `impact:session-state`: Media intended for one routed agent or session can become visible to another agent/session through the shared inbound media pool.
- `maturity:stable`: The issue affects Discord inbound media handling, and the checked-in maturity scorecard marks Discord as M4 Stable.

## Summary

Keep open: current main and the latest release still use shared flat inbound media storage, flat managed-reference resolution, and flat sandbox staging, so the reported cross-agent privacy gap remains unresolved; the closed implementation PR was not merged and the open related issues are narrower slices.

## What This Changes

Request per-agent or per-account isolation for inbound media so files received by one agent are not visible to other agents through the shared media store.

## Best Possible Solution

Define and implement a scoped managed-media contract across storage, bundled and plugin media saves, URI/path resolution, sandbox staging, local access checks, cleanup, docs, and regression tests while preserving or deliberately migrating existing flat inbound references.
