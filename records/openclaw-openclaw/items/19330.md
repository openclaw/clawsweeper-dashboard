- `P2`: The issue is a source-backed privacy and correctness gap in a bounded media/session surface, but it requires maintainer security/product design rather than emergency repair.
- `impact:security`: The reported failure mode is cross-agent access to sensitive inbound media through a shared managed media root.
- `impact:session-state`: Agents can select or process media that belongs to another agent or conversation, causing context/session attribution drift.

## Summary

Keep open: current main and the latest release still preserve flat shared inbound media storage and first-level inbound media references, while the direct isolation PR is closed unmerged. This remains the canonical broad security/session-state tracker and needs maintainer design before implementation.

## What This Changes

Request scoped or provenanced inbound media storage so files received by one agent/account/channel are not visible to other agents through a shared `media/inbound` pool.

## Best Possible Solution

Keep this issue as the canonical tracker and define one managed scoped inbound-media contract, then update save paths, media URI/access resolution, sandbox staging, cleanup, docs, and regression tests together.
