## Label Justifications

- `P2`: This is a real multi-agent privacy and correctness gap, but it needs a bounded security/product decision rather than emergency runtime recovery.
- `impact:security`: The report is about media intended for one agent being readable by another agent with access to the shared inbound media directory.
- `impact:session-state`: Cross-agent media pooling can cause one agent/session to process or reference media from a different routed agent/session.
- `maturity:stable`: The issue affects Discord media/rich-content behavior, and the Discord surface is scored M4 Stable in the maturity scorecard.

## Summary

Keep open: current `main` and the latest release still preserve a shared flat inbound-media path for representative channel downloads, managed media references, and sandbox staging, so the reported cross-agent privacy/session-state gap remains unresolved.

## What This Changes

The issue asks OpenClaw to isolate inbound media files per agent or account instead of storing all channel media in a shared `media/inbound` pool.

## Best Possible Solution

Define one canonical scoped inbound-media contract, then implement it across media save/read APIs, channel callers, managed refs, absolute-path checks, sandbox staging, cleanup, docs, and tests without adding a parallel long-lived fallback path.

Question: What identity should OpenClaw use as the canonical inbound-media isolation boundary for multi-agent deployments?

Rationale: The source problem is clear, but choosing agent id, channel account id, session/chat scope, or a tenant/account hierarchy changes the security boundary, compatibility behavior, and plugin SDK contract.

Likely owner: steipete

Owner reason: steipete has the strongest recent history across the core media reference, sandbox staging, and Discord media surfaces plus the prior maintainer review context.

Owner confidence: high

Options:

- **Agent-scoped contract (recommended):** Scope inbound media by resolved agent id after routing, preserving the documented agent isolation model but requiring media provenance to survive early channel ingest.
- **Account-scoped ingest contract:** Scope by channel account id at save time, which is easier for current monitors but only approximates agent isolation when accounts and agents are not one-to-one.
- **Tenant/chat/session hierarchy:** Design a richer namespace such as tenant/account/chat/session before implementation, which may solve more provenance needs but is broader and slower to land.

## Reproduction Assessment

Yes, by source inspection: representative channel saves still write to `inbound`, managed refs reject nested scoped IDs, and sandbox staging rewrites to flat `media/inbound/<basename>`. I did not run a live multi-agent channel setup.

## Solution Assessment

No, the proposed account-subdirectory approach is only a plausible partial fix. The best fix needs a maintainer-chosen isolation identity and a single scoped contract carried through save, resolve, stage, cleanup, docs, and tests.
