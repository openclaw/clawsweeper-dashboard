## Label Justifications

- `P2`: The issue is a source-backed privacy and correctness gap in multi-agent media handling, but it needs a bounded security/product design rather than emergency repair.
- `impact:security`: The reported failure mode lets media intended for one agent remain readable from a shared managed inbound root by another agent with filesystem access.
- `impact:session-state`: The concrete examples involve agents selecting or processing media from the wrong agent or conversation context.

## Summary

Keep open: current main and the latest release still preserve the shared flat inbound-media contract across save, managed-reference, and sandbox-staging paths, so the cross-agent privacy/session-state gap remains unresolved.

## What This Changes

The issue requests per-agent or per-account isolation for inbound media so media received for one agent is not stored in a shared pool readable by other agents.

## Best Possible Solution

Define one canonical scoped inbound-media contract across storage, managed refs or media index, channel/plugin save APIs, local access checks, sandbox staging, cleanup, docs, and regression tests.

Rationale: The current evidence proves the flat media pool remains, but choosing account, resolved agent, session, channel/chat, tenant, or an indexed provenance model is a security and compatibility decision automation should not invent.

Likely owner: steipete

Owner confidence: medium

Options:

- **Adopt managed scoped media contract (recommended):** Define a core contract for scoped managed inbound media, then update bundled channels, resolvers, staging, cleanup, docs, and tests together.
- **Limit scope to account subdirs:** Use sanitized channel/account identifiers as the first isolation step, accepting that session/chat/tenant provenance remains separate follow-up work.
- **Defer until media provenance design:** Keep this tracker open but wait for a broader media-index or provenance schema decision before changing the filesystem layout.

## Reproduction Assessment

Yes at source level. Current main still defaults media saves to the flat inbound bucket, representative channel saves use that bucket, scoped managed refs are rejected, and sandbox staging flattens filenames.

## Solution Assessment

Unclear as proposed. Account subdirectories are plausible, but the maintainable fix needs a single scoped media contract instead of a save-path-only change.
