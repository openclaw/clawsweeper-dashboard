Likely related people: charzhou is a low-confidence adjacent routing candidate from the merged `/v1/responses` client-tool forwarding work; psionski is a low-confidence issue participant who subscribed early.

## What This Changes

Expose caller-provided `/v1/responses` function tools to the native Codex app-server harness and return their model invocations as delegated `function_call` output items rather than executing them as OpenClaw-owned tools.

## System Context

The OpenResponses HTTP endpoint turns caller input, tool definitions, and tool-choice policy into an embedded agent attempt. The Codex extension then translates that attempt into an app-server dynamic-tool session whose terminal result feeds back into the HTTP response encoder.

## Architecture Diagram

flowchart LR

  C --> D[Codex app-server harness]
  D --> E[Dynamic tool surface]
  E --> F[Delegated client tool call]
  F --> G[Responses function_call output]

## Best Possible Solution

Define an explicit Codex terminal-delegation contract, then implement a narrow per-turn adapter that registers validated caller functions, records their invocation without executing them locally, stops the native turn deterministically, and proves both successful pinned calls and the existing prose-only fail-closed behavior.
