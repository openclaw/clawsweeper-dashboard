## Summary

Keep open: current main and the latest release still let malformed non-empty successful Discord API response bodies escape through raw `JSON.parse`, while this PR now narrowly converts that path to `DiscordApiError` and adds a colocated regression test. The earlier root proof artifact has been removed from the final diff, so I found no blocking review findings.

## What This Changes

The PR wraps Discord `requestDiscord` success-body JSON parsing in a `DiscordApiError` guard and adds a regression test for malformed successful JSON responses.

## Best Possible Solution

Land the narrow `requestDiscord` guard and colocated regression test once exact-head CI and mergeability gates are green.

## Reproduction Assessment

Yes. Current main and `v2026.6.11` both show raw `JSON.parse(text)` on non-empty successful Discord API responses, and the PR body includes terminal output from an after-fix proof using a malformed 200 response; I did not run tests because this review is read-only.

## Solution Assessment

Yes. Catching the parse failure inside `requestDiscord` is the narrow owner-boundary fix because every `fetchDiscord` caller uses that helper, and the existing retry policy already limits retries to status 429.
