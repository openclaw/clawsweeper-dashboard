## Summary

Keep open: current main and the latest release still leave successful Discord API response parsing as a raw `JSON.parse`, while this PR adds a narrow guard, regression coverage, and sufficient terminal proof with no blocking review findings.

## What This Changes

The PR wraps Discord `requestDiscord` successful-response JSON parsing in a `DiscordApiError` try/catch and adds a malformed-JSON regression test.

## Best Possible Solution

Land the narrow `requestDiscord` parse guard and regression test once a maintainer clears the human-review pause and exact-head checks are acceptable.

## Reproduction Assessment

Yes by source inspection: current main and `v2026.6.11` call raw `JSON.parse(text)` for non-empty successful Discord API response bodies, so a malformed HTTP 200 body would escape as `SyntaxError`. I did not run tests because this review is read-only; the PR body supplies after-fix terminal proof.

## Solution Assessment

Yes. Catching the parse failure inside `requestDiscord` is the narrow owner-boundary fix because `fetchDiscord` callers share that helper and the retry policy already limits retries to Discord 429 errors.
