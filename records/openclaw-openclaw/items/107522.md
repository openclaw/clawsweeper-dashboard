## Summary

Keep this issue open for current-main profiling, but do not implement the proposed freshness cache: OpenClaw already uses a persisted cold registry plus explicitly owned metadata snapshots and lookup tables, and its architecture deliberately forbids wall-clock discovery caches. A remaining bug is plausible only if tracing identifies a startup caller that discards those objects and reconstructs metadata. ([docs.openclaw.ai](https://docs.openclaw.ai/plugins/architecture-internals))

## What This Changes

Investigate reported synchronous plugin-directory rescanning during Gateway startup and reduce any confirmed redundant filesystem discovery work.

## Best Possible Solution

Capture a current-main startup trace and repeated benchmark first; if it identifies redundant metadata reconstruction, pass the existing PluginMetadataSnapshot or PluginLookUpTable through that caller rather than adding a freshness-based persistent discovery cache.
