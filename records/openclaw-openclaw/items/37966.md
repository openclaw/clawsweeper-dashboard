## Summary

Keep open. Current main and the latest release still drop explicit LiteLLM Claude cache retention before the Anthropic `cache_control` payload path, and the linked open PR is an active fix candidate rather than a merged implementation.

## What This Changes

The issue reports that explicit `cacheRetention` is ignored for LiteLLM-routed Anthropic/Claude models, so Anthropic prompt-cache `cache_control` markers never reach the proxied API payload.

## Best Possible Solution

Review and land or replace the linked PR with a narrow explicit-only LiteLLM Claude cache-control fix, regression tests, docs alignment, and redacted live provider proof when credentials are available.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, this is source-reproducible on current main: LiteLLM OpenAI-completions Claude does not pass the retention-family gate and `detectCompat` only enables Anthropic cache markers for OpenRouter. I did not run a live LiteLLM-to-Anthropic cache-hit probe.

## Solution Assessment

Yes, the narrow maintainable fix is to carry explicit retention through the existing resolver and OpenAI-completions cache-control seam for LiteLLM Claude only. The open linked PR targets that path, so the issue should wait for that PR to land or be replaced.
