## Summary

Keep open: current main ships a CLI-alias selection mitigation, but the broader plugin-loader lifecycle issue is not resolved because empty-plugin-scope paths still clear global harness state and registry restore is still clear-then-repopulate. The linked repair PR is open and conflicting, and the remaining question is the intended harness-preservation contract.

## What This Changes

The issue asks for plugin cache and harness registry reloads to stop dropping registered agent harnesses so Discord, cron, and gateway lane dispatch do not surface MissingAgentHarnessError.

## Best Possible Solution

Define and implement a maintainer-approved loader/gateway lifecycle contract that preserves required built-in or provider-owned harnesses across empty-scope reloads without keeping disabled plugin-owned harnesses alive, with focused regression coverage for both loader and gateway paths.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What harness-preservation semantics should OpenClaw use when a gateway or plugin reload resolves to an empty plugin scope?

Rationale: The code can be fixed mechanically only after maintainers choose whether empty-scope reloads preserve all harnesses, only built-in/provider-owned harnesses, or intentionally clear every plugin-owned runtime handle; that choice affects plugin disablement, security boundaries, and user-visible channel delivery.

Likely owner: vincentkoc

Owner reason: Vincent Koc has recent history in explicit plugin scope and gateway startup loader behavior, which is the central product boundary for this decision.

Owner confidence: high

Options:

- **Preserve only required provider harnesses (recommended):** Keep bundled or provider-owned harnesses available across empty-scope reloads while continuing to clear disabled third-party plugin-owned harnesses.
- **Preserve all previous harnesses:** Adopt the open repair PR's broader snapshot/restore behavior, accepting that explicit empty scopes may keep third-party harnesses live until a later full reload or restart.
- **Clear all and add readiness/retry:** Keep fail-closed empty-scope semantics but add readiness or bounded retry behavior so channel and cron dispatch do not surface transient MissingAgentHarnessError failures.

No high-confidence live reproduction was run in this read-only review. Source inspection shows current main still clears harness state on empty plugin scopes and uses non-atomic clear-then-restore, but the shipped CLI-alias mitigation may mask the original claude-cli Discord symptom.
