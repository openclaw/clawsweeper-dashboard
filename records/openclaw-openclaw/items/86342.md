## Summary

Keep open: current main and the latest release still clear process-global harnesses in loader/gateway empty-scope paths and restore harness snapshots non-atomically. The CLI-alias and Codex doctor slices are fixed elsewhere, but the broader harness lifecycle contract remains unresolved and the linked PR is still open/conflicting.

## What This Changes

The issue reports user-visible `MissingAgentHarnessError` failures when plugin cache or reload paths temporarily or permanently clear the global agent-harness registry during Discord, cron, or gateway agent turns.

## Best Possible Solution

Land an ownership-aware harness lifecycle fix that preserves only approved always-on harnesses, clears disabled or unscoped plugin-owned harnesses, covers loader and gateway empty-scope paths, and includes patched gateway proof for a channel or cron turn.

Rationale: Current source proves the lifecycle hazard, but choosing the permanent behavior changes plugin disablement, provider routing, and security-boundary semantics; automation should not pick that policy from the issue alone.

Owner confidence: high

Options:

- **Preserve Approved Always-On Harnesses (recommended):** Filter registry preservation to the approved always-on/core harness contract and keep disabled or unscoped plugin-owned harnesses cleared, with loader and gateway tests.
- **Restore All Prior Harnesses:** Allow every previous harness to survive an empty active registry, accepting the compatibility and security-boundary tradeoff explicitly.
- **Retry Dispatch Only:** Add bounded retry/backoff at dispatch while leaving registry semantics unchanged, but require safeguards so real missing-runtime states still surface clearly.
