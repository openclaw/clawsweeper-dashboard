## Summary

Keep open: current main and the latest release still clear the process-global harness registry during plugin loader and gateway empty-scope paths, while the direct candidate PR remains open, conflicting, and blocked on harness ownership semantics.

## What This Changes

The issue reports intermittent MissingAgentHarnessError failures when plugin loader cache or reload cycles temporarily or permanently clear the agent harness registry used by Discord, cron, and gateway agent turns.

## Best Possible Solution

Keep this as the canonical lifecycle bug and land an ownership-aware harness lifecycle fix that covers loader and gateway empty-scope paths, avoids exposing disabled plugin-owned harnesses, and includes regression plus patched gateway proof.

Rationale: Current main still clears the registry, but the obvious restore-all repair can change plugin disablement and empty-scope security semantics; automation cannot choose that product and ownership contract safely.

Options:

- **Preserve approved always-on harnesses (recommended):** Filter restoration to the maintainer-approved always-on/native provider contract and prove plugin-owned harnesses from disabled or unscoped plugins are cleared.

- **Clear all and recover elsewhere:** Keep empty-scope clears strict and solve user-visible failures with readiness, retry, or doctor/config repair paths instead of preserving harness registry entries.
