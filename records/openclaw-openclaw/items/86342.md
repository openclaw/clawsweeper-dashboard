## Summary

Keep open: current main and the latest release still clear the process-global harness registry on plugin-loader and gateway empty-scope paths, while the related candidate PR is open, conflicting, and blocked on the ownership semantics for restoring harnesses.

## What This Changes

This issue asks OpenClaw to stop `MissingAgentHarnessError` failures caused by plugin reload/cache cycles clearing and restoring the agent harness registry non-atomically.

## Best Possible Solution

Land or replace the candidate with an ownership-aware harness lifecycle fix that preserves only approved always-on harnesses, clears disabled or unscoped plugin-owned harnesses, covers loader and gateway empty-scope paths, and includes patched real gateway proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What harness ownership contract should OpenClaw enforce when plugin reload/startup resolves to an empty active scope?

Rationale: The bug is real, but restore-all preservation can keep disabled or unscoped plugin-owned harnesses callable, while unconditional clearing can break active channel or cron turns; the permanent contract is a maintainer product and security boundary decision.

Likely owner: steipete

Owner reason: This person introduced the pluggable harness registry and has the strongest path-history signal for the agent-runtime lifecycle contract.

Owner confidence: high

Options:

- **Preserve only approved always-on harnesses (recommended):** Filter restored harnesses to an explicit bundled/always-on contract and prove plugin-owned harnesses clear when their owner is disabled or out of scope.
- **Accept restore-all semantics:** Allow previous harnesses to survive empty active registries, but document and test that plugin disablement does not immediately revoke those harnesses.
- **Pause for broader lifecycle redesign:** Replace the global mutable registry with an ownership-aware or request-scoped lifecycle model before landing a narrow empty-scope patch.
