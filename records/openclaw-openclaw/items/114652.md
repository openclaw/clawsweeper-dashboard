## Summary

This PR addresses a distinct Windows `cmd` startup trust boundary and should remain open for maintainer handling. The patch is narrowly scoped, preserves the existing human-approval fallback, and the provided regression-first evidence is strong; however, the `maintainer` label prevents automated cleanup and the current review environment could not complete the required direct source and upstream-Codex inspection.

## What This Changes

The branch makes Windows `cmd` commands ineligible for automatic execution review unless they explicitly disable AutoRun with `/d`, invoke `/c` with a real payload, and use only recognized non-binding startup switches before that payload.

## System Context

OpenClaw’s auto-review path decides whether an execution request can be approved from the command text alone. Shell-wrapper resolution identifies command interpreters and blocks opaque or startup-sensitive forms so the gateway, node host, and Codex-backed execution paths fall back to a human approval request.
