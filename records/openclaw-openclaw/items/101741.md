## Summary

Keep this PR open: the LINE cache is unbounded on current main and the proposed cap is useful, but merge should wait for contributor real-behavior proof and a small follow-up to make the claimed LRU refresh behavior true.

## What This Changes

The PR adds a 1024-entry cap to the LINE `userProfileCache`, routes profile writes through `pruneMapToMaxSize`, resets that cache between send tests, and adds eviction coverage.

## Best Possible Solution

Land a plugin-local bounded LINE profile cache that refreshes hot entries consistently with sibling caches, backed by focused unit coverage and redacted real LINE gateway or live-output proof.
