## Summary

The PR is a focused, useful LINE memory-bound fix and should not be closed, but it still needs contributor real-behavior proof before merge. The prior cache-recency finding also remains: the implementation claims LRU semantics while cached hits return without refreshing Map insertion order.

## What This Changes

The PR caps the LINE plugin's in-process user profile cache at 1,024 entries using the shared Map pruning helper and adds regression coverage plus a test-only cache reset export.

## Best Possible Solution

Land the bounded LINE profile cache through the existing SDK helper after either refreshing cache-hit recency to match the LRU claim or narrowing the behavior to FIFO-on-write, with redacted real LINE runtime proof for the profile-cache path.

## Solution Assessment

Mostly yes: using the existing pruneMapToMaxSize plugin SDK helper is the right narrow owner-boundary fix. The remaining repair is to refresh valid cache hits before pruning, or explicitly stop promising LRU semantics and test the intended FIFO-on-write behavior.
