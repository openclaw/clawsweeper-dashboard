## Label Justifications

- `P1`: A reproduced authenticated QA race can falsely report runtime-parity success while leaving the release token-efficiency proof red.
- `impact:session-state`: The defect reads persisted session transcript and usage state before the assistant row is durable.

## Summary

Current main retains the reported race: the scenario accepts a transport-visible reply before verifying that the corresponding assistant row is durable in the persisted transcript. This is a recent, reproducible QA correctness bug, and the protected `maintainer` label requires explicit maintainer handling rather than automated cleanup.

## What This Changes

Make the webchat runtime-parity scenario wait for the expected assistant marker in the persisted transcript before declaring success and recording usage.

## Best Possible Solution

Add an explicit bounded expected-marker wait to the transcript-summary boundary, use the returned durable snapshot for both self-message routing checks and usage capture, and cover delayed file creation plus delayed assistant-row append without weakening the zero-usage gate.

## Reproduction Assessment

Yes. The issue provides an exact authenticated Testbox reproduction with zero-token and ENOENT evidence, and current main retains the same transport-success-then-single-transcript-read sequence.

## Solution Assessment

Yes. Waiting for the requested marker in the persisted transcript is the narrowest maintainable solution because that durable artifact is what routing and usage evaluation consume; relaxing the gate or retrying the whole scenario would mask the race.
