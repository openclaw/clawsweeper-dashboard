## Summary

Current main and release `v2026.6.11` already preserve custom OpenClaw state skill paths in the prompt, so the 2026.6.3 report is fixed by updating.

## What This Changes

The issue reports that managed skills are advertised as `~/.openclaw/skills/...` even when `OPENCLAW_HOME` points elsewhere, causing skill reads from the OS home directory.

## Best Possible Solution

Keep the shipped `v2026.6.11` behavior and ask affected users on `2026.6.3` to update rather than adding another skill-path fallback.

## Reproduction Assessment

Yes. The reported failure path is covered by source and regression-test evidence: a custom OpenClaw state/home root must keep the real `.../.openclaw/skills/.../SKILL.md` location instead of compacting to `~/.openclaw/skills/...`.

## Solution Assessment

Yes. Preserving configured managed skill roots before prompt path compaction fixes the incorrect model-visible path while still allowing safe `~` compaction when the OS home actually reaches the same file.
