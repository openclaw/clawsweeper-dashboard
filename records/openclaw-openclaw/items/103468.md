## Summary

The latest head still has the prior P1 blocker: it chooses the user-first read credential before branching, then uses that credential for Slack’s write-scoped native-DM lookup. The original environment-fallback bug is valid, but this branch is not merge-ready until token selection is operation-specific and real after-fix Slack behavior is shown.

## What This Changes

Replaces Slack conversation resolution’s manual token fallback with `resolveSlackOperationToken(account, "read")` and adds mocked mixed-token, bot-only, and no-token regression cases.

## Best Possible Solution

Branch before client creation: use `resolveSlackOperationToken(account, "write")` for native-DM `conversations.open` and `resolveSlackOperationToken(account, "read")` for `conversations.info`, then assert exact credentials and provide redacted live proof for both paths.
