## Summary

Current main and release v2026.6.11 include the lifecycleGeneration guard and regression test that prevent current-generation restart-recovery candidates from reopening completed sessions, so the reported Telegram context-loss path is implemented.

## What This Changes

The issue reports that a completed Telegram main session was silently reset by restart-recovery lifecycleGeneration handling before the configured idle timeout, causing session context loss.

## Best Possible Solution

Keep the shipped lifecycleGeneration guard and regression test; if a user still sees context reset, ask for a new report with current-version logs and the exact reset mode because the reported restart-recovery false positive is fixed.
