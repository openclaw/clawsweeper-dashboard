## Summary

Keep open: current main and v2026.6.11 include the lifecycle-generation guard that fixes the restart-recovery false positive, but the issue's remaining “idle window should win” expectation conflicts with documented daily-plus-idle reset semantics and needs maintainer direction.

## What This Changes

The issue reports a Telegram main-session context reset where restart-recovery metadata reopened a normally completed session before the configured idle timeout elapsed.

## Best Possible Solution

Keep the shipped lifecycle-generation guard, then have maintainers decide whether the remaining outcome should be documented daily-plus-idle behavior, a doctor/docs clarification, or a reset-policy compatibility change.
