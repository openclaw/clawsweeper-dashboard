## Summary

Keep this maintainer-authored, protected PR open for an explicit release-QA decision. The patch is internally consistent and has detailed real runtime-pair proof, but it intentionally narrows the required runtime-tool coverage guarantee from the formerly required report-only rows to three result-backed tools; that policy change should be accepted by the QA/release owners before merge.

## What This Changes

The PR changes QA Lab’s paired OpenClaw/Codex tool evidence so required coverage counts only tool calls linked to successful product results, while unavailable, known-gap, and report-only fixtures produce skips.

## System Context

QA Lab runs the same scenario through OpenClaw and Codex, captures each runtime’s transcript and tool evidence, then turns those cells into scenario outcomes and release-coverage reports. This PR changes the evidence threshold feeding those reports, not OpenClaw’s product runtime.

Keep result-backed coverage strict, retain skips for unsupported or report-only fixtures, and merge only after QA/release owners explicitly accept the three-tool required minimum or identify additional tool paths that need real result-backed fixtures.
