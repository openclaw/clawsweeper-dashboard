## Summary

Keep open: current main and the latest release still have a source-backed cron outcome path where produced assistant output can be overridden by fatal tool/run status and persisted as not delivered, and the related fix PR is open/conflicting rather than a merged canonical fix.

## What This Changes

The issue asks cron isolated agent runs to deliver produced assistant output when only an ancillary background tool fails, instead of persisting error/not-delivered state.

## Best Possible Solution

Define one isolated cron delivery/status contract that recovers explicitly non-terminal background or tool failures into diagnostics, preserves true fatal run-level failures, and then land one coordinated fix or repair the open candidate PR.

Rationale: Current code has multiple plausible signals: final assistant text, tool error payloads, run-level errors, failure signals, diagnostics, and delivery state; choosing which one wins can change alerts, failure counters, and message delivery.

Options:

- **Structured Recovery Contract (recommended):** Treat explicit non-terminal background/tool failures as warning diagnostics when final output is valid, while keeping typed run-level/fatal signals authoritative.
- **Broad Final Text Recovery:** Let final assistant-visible text recover most non-fatal tool payload errors, accepting the risk that some real terminal tool failures may be marked ok.
- **Strict Failure Option First:** Keep current conservative defaults and add or revive an opt-in fail-on-tool-failure/status contract before changing default recovery semantics.

## Solution Assessment
