## Summary

Keep open: current main and v2026.6.11 still preserve the source-level path where recovered cron output can be classified as an error/not-delivered result, and the related PRs are open/conflicting candidates rather than merged fixes.

## What This Changes

The issue asks OpenClaw to deliver produced cron or inter-agent output even when an ancillary backgrounded tool exits non-zero after the useful result exists.

## Best Possible Solution

Define one isolated cron delivery outcome contract that preserves true fatal run failures, records recovered process/tool failures as diagnostics or a degraded outcome, and still delivers valid final assistant or reply output.
