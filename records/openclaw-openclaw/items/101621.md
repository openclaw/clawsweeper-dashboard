## Summary

Keep open: current source still lets the structured mid-turn precheck signal become ordinary failure events before the later cleanup/recovery path runs, so the reported UI leak is not fixed on main. There is an open candidate PR for the same failure class, but its current approach still needs maintainer boundary review and stronger proof before this issue can close.

## What This Changes

The issue asks for mid-turn precheck control-flow recovery to stay silent and only surface an error if truncation or compaction retry also fails.

## Best Possible Solution

Handle the mid-turn control signal before generic failure streaming, or add a generic typed bubble-control contract, with regression coverage proving no intermediate error event is delivered when recovery succeeds and real gateway/MCP proof for the large-tool-output scenario.
