## Summary

Keep open: current main and the latest release still have a source-level path where a mid-turn precheck control-flow signal is converted into an assistant error event before the outer recovery code retries, so the reported UI leak remains plausible and actionable.

## What This Changes

The issue asks OpenClaw to prevent MidTurnPrecheckSignal from surfacing as a user-visible context-overflow error before internal truncation or compaction recovery finishes.

## Best Possible Solution

Land a narrow agent-runtime fix that prevents MidTurnPrecheckSignal from producing user-visible failure events before recovery, then add regression coverage proving a successful retry emits no intermediate context-overflow error.
