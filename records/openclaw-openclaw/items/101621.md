## Repair Work Prompt

Fix https://github.com/openclaw/openclaw/issues/101621. Current main leaks `MidTurnPrecheckSignal` as a visible assistant/lifecycle error because the tool-result guard throws from `transformContext`, while agent-core catches any loop rejection and calls `pushLoopFailure` before the embedded attempt recovery consumes `pendingMidTurnPrecheckRequest`. Implement a narrow internal control-flow path that interrupts the next provider call for mid-turn precheck without emitting `message_start`, `message_end`, `turn_end`, `agent_end`, `onBlockReply`, or lifecycle error output for the synthetic signal. Preserve the existing truncation/compaction retry behavior and only surface an error if recovery/retry actually fails. Prefer honoring the agent-core `transformContext` non-throw contract over adding UI-side filtering, and do not add a new config option or change the documented default-disabled setting. Add focused regression coverage that simulates the signal path and asserts no user-visible/lifecycle error payload is emitted before successful recovery.
