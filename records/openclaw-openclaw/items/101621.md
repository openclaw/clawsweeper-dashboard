## Summary

Keep open: current main still has the source-level path where `MidTurnPrecheckSignal` is thrown as an `Error` and generic agent-core failure handling can emit failure events before the later attempt-runner cleanup/recovery path runs. The linked fix PR is open and uses closing syntax for this issue, so the issue should close only after that PR or a successor lands with proof.

## What This Changes

The issue asks OpenClaw to keep `MidTurnPrecheckSignal` as internal control flow so successful mid-turn truncation or compaction retries do not first surface a false context-overflow error in the UI.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/101648 or a narrow successor that prevents nonterminal mid-turn precheck signals from emitting UI failure events, with live large-tool-output proof, then close this issue after merge.
