## Summary

Keep open: current main and v2026.6.11 still deliver forwarded exec approvals immediately and expose no hold/retract config or RPC. This is a valid approval-UX feature request, but it needs maintainer product and safety design before implementation.

## What This Changes

Request an opt-in `approvals.exec` hold window plus agent-accessible retraction of pending forwarded exec approvals before human delivery.

## Best Possible Solution

Design an opt-in approval hold/retract flow that keeps default instant delivery, fails open to human delivery on buffering errors, fails closed to execution on retraction, logs suppressed approvals, and updates config, schema, docs, tests, and native/Codex integration together.
