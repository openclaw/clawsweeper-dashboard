## Summary

Keep open: current main and v2026.6.11 still deliver forwarded exec approvals immediately and expose no `holdMs` config or agent-accessible retraction RPC. This is a real approval-UX feature request, but it needs maintainer design because it changes approval timing, Gateway protocol/config, audit behavior, and Codex/native approval contracts.

## What This Changes

Request adds an opt-in hold window for forwarded exec approval prompts plus an agent-accessible retraction action before prompt delivery.

## Best Possible Solution

Design an opt-in Gateway-owned hold/retract contract with default immediate delivery, audited retractions, fail-open human delivery on hold errors, fail-closed execution on retract, and matching config/schema/docs/client/Codex updates.
