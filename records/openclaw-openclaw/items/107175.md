## Summary

Keep this PR open, but do not merge the current head: the trusted-provenance direction is useful, while the proposed contract currently crosses message-batching and plugin data-access boundaries without preserving its security guarantees.

## What This Changes

The PR creates a gateway-generated inbound context containing message provenance, sender, conversation, raw text, and correlation data, then propagates it through agent runs, queues, tools, hooks, compaction, and the public plugin SDK.

## Best Possible Solution

Keep context creation host-owned and readonly, preserve one-to-one provenance through queueing or define an explicit ordered aggregate contract, expose only the minimum approved fields to capability-scoped plugin actions, and prove the final path with redacted live Discord runtime output.
