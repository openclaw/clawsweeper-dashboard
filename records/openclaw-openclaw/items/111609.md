## Summary

Keep this PR open: its bounded reader is a reasonable OOM mitigation for audit data, but applying the same truncating-prefix behavior to the replay ledger can make completed records beyond 32 MiB invisible and admit a duplicate claim. The head SHA is unchanged from the prior completed review, so its P1 replay-ledger blocker remains unresolved.

## What This Changes

The PR replaces unbounded Reef audit and replay JSONL reads with a 32 MiB chunked reader that warns and returns complete prefix records when a store exceeds the cap.

## Best Possible Solution

Use bounded prefix recovery only for audit history if that is acceptable; give FileReplayStore a separate fail-closed oversized/corrupt-ledger path that cannot treat unknown state as unclaimed, with an explicit maintainer-approved recovery or compaction flow.
