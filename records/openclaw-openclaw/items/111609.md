## Summary

This PR addresses a real OOM path, but the current replay-ledger recovery is unsafe: it rewrites a bounded prefix and can discard valid completed receipts after the 32 MiB limit, allowing those receipts to be claimed again. Keep it open for a narrow fail-closed replay repair; the audit-history bounded-prefix behavior can remain separate.

## What This Changes

The branch replaces unbounded Reef JSONL reads with a 32 MiB chunked reader, keeps a truncated audit prefix, and auto-compacts oversized replay ledgers on load.

## Best Possible Solution

Keep chunked bounded reads, retain best-effort truncation only for non-authoritative audit history, and make an oversized replay ledger fail closed without rewriting it until a full, integrity-preserving recovery workflow is explicitly designed and proven.
