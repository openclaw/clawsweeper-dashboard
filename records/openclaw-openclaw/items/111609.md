## Summary

Keep this PR open for a safety redesign: bounded reads solve the OOM concern, but truncating the shared replay ledger can make valid replay records beyond 32 MiB invisible after restart, weakening replay protection. The supplied terminal proof is useful for the new prefix-read behavior but does not cover records written beyond the cap.

## What This Changes

The PR replaces unbounded Reef JSONL reads with a 32 MiB chunked reader and returns complete prefix records with a warning when an audit or replay store exceeds that limit.

## Best Possible Solution

Keep the bounded reader for audit history if desired, but give replay state a fail-closed or otherwise lossless recovery path that never treats unscanned post-cap records as absent; add boundary tests for both a record before and after the cap.
