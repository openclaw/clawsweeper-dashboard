## Summary

The revised branch fixes the prior TOCTOU concern by enforcing the cap while reading, but it still turns pre-existing Reef audit or replay stores over 32 MiB into a hard runtime error without a defined retention, repair, or upgrade-recovery path. Keep this PR open for a maintainer decision on that persistent-store contract before merge.

## What This Changes

The PR replaces Reef JSONL `readFile` calls with a 32 MiB chunked reader and adds tests for rejecting oversized audit and replay stores.

## Best Possible Solution

Keep the bounded-read protection, then define Reef-owned retention and recovery semantics: safely compact or rotate eligible records and provide a plugin Doctor repair or equally explicit operator recovery path for existing oversized files, with fresh-install and upgrade coverage.
