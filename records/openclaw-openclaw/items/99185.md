## Summary

Keep open: current main still has a source-backed installed-index path that can omit configured `plugins.load.paths` workspace plugins, and the open fix candidate at https://github.com/openclaw/openclaw/pull/99196 uses closing syntax for this issue, so closing before merge would be premature.

## What This Changes

The issue reports that installing a managed npm plugin causes workspace plugins configured through `plugins.load.paths` to disappear from CLI and gateway plugin resolution as stale config entries.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99196, or an equivalent focused fix, so installed-index manifest reconstruction includes explicitly configured load-path plugins with scoping and bundled-path guards.

## Reproduction Assessment

Yes at source level: current main can select installed-index manifest reconstruction and then pass only index-derived candidates, which prevents `plugins.load.paths` discovery from running. I did not establish a live macOS managed-install reproduction in this read-only review.

## Solution Assessment

Yes: the best fix is in installed-index manifest registry reconstruction, not a config workaround, because docs already make load-path workspace plugins part of the plugin metadata scope.
