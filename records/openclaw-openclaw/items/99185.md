## Summary

Keep open: current main and the latest release still reconstruct the installed-index manifest registry from persisted index candidates only, so configured workspace plugins can still be omitted until the open closing PR lands.

## What This Changes

The issue reports that installing a managed npm plugin causes workspace plugins configured through `plugins.load.paths` to be treated as stale and dropped.

## Best Possible Solution

Review and land a focused version of the linked fix PR that keeps the persisted-index fast path while adding only explicitly configured load-path plugins with normal scoping and bundled-path filtering.

## Reproduction Assessment

Yes at source level: current main passes installed-index candidates into the manifest registry, and the callee skips normal `plugins.load.paths` discovery when candidates are supplied. I did not run the full managed npm install plus gateway restart scenario.

## Solution Assessment

Yes: the narrow fix belongs in installed-index manifest registry reconstruction, not in config validation, because docs treat `plugins.load.paths` as part of plugin metadata scope and the missing discovery happens before validation.
