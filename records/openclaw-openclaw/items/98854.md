## Summary

## What This Changes

The branch adds `stopChild?.()` to the fd-backed find tool's child-process error handler.

## Best Possible Solution

Keep the current cleanup/reject behavior unless a redesigned handler clears the stop hook before any kill retry and is backed by focused fd spawn/error and abort-path proof.

## Reproduction Assessment

Yes for the PR-introduced risk: current source plus Node v24.17.0's child_process implementation show `kill()` can emit `error` while `stopChild` is still defined. No high-confidence runtime reproduction was shown for the original cleanup-asymmetry claim.

## Solution Assessment

No. The added call is not the best fix because the error event also represents failed kill; the safer path is cleanup/reject-only or a redesign that clears the stop hook before any retry.
