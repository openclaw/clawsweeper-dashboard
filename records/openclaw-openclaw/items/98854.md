## Summary

## What This Changes

The PR adds a `stopChild?.()` call to the fd-backed find tool's child-process error handler.

## Best Possible Solution

Keep the find error handler cleanup/reject-only unless a targeted redesign clears the stop hook before any kill retry, and require focused runtime proof for the fd error path before merge.

## Reproduction Assessment

Yes for the PR-introduced defect: Node v24 source shows `kill()` can emit `error` synchronously, and current find abort handling calls `stopChild` before `settle` clears it. No high-confidence runtime proof exists for the contributor's original cleanup asymmetry.

## Solution Assessment

No. The added call is not the best fix because the error event also represents failed kill; the safer path is to keep cleanup/reject-only or redesign the stop hook with targeted failed-spawn and failed-kill proof.
