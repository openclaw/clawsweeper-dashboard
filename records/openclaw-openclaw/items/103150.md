## Summary

Keep this canonical maintainer-protected bug open: current main contains a partial provider-wide custom-endpoint guard, but availability still does not use the effective per-model route or the same credential evidence as runtime execution.

## What This Changes

Align OpenAI model availability and auth reporting with each model’s effective runtime API, endpoint, harness, and eligible credential sources.

## Best Possible Solution

Create one shared eligibility result from the resolved model API, endpoint, harness, and credential evidence, then consume it across runtime, compaction, model listing/status, onboarding, and doctor without exposing private runtime fields.
