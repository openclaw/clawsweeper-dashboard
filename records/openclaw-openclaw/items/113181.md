## What This Changes

Fix isolated cron jobs using `delivery.mode: "none"` so an agent-initiated WeChat message either delivers successfully or reports a visible failure instead of ending as an apparently successful run with `delivered=false`.

## System Context

Cron schedules an agent run and can either deliver its final output itself through `announce` or let the agent call a channel message tool under `delivery.mode: "none"`. This issue concerns the latter path, where isolated-session tool dispatch should report delivery success or failure back to the scheduled run and user-visible channel.

## Best Possible Solution

Reproduce the isolated-session `message(action="send")` path with the affected plugin, preserve the direct tool error in cron diagnostics, and repair the owning core or plugin boundary so a failed send cannot be reported as a clean successful run.
