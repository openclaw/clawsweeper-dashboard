## Summary

Keep open: current main and the latest release still expose plugin command handlers as generic context plus one returned payload, while Discord interaction responder controls remain internal to Discord-specific paths. The remaining work is a real plugin SDK/API-shape decision, not conservative cleanup.

## What This Changes

The issue requests Discord slash-command responder controls such as defer, reply, follow-up, and edit-reply inside plugin command handlers.

## Best Possible Solution

Define a narrow documented plugin-command responder capability, preferably generic with Discord as the first implementation, while preserving the existing returned-payload path for compatibility.
