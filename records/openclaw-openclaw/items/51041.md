## Summary

Keep open: current main and v2026.6.11 still expose plugin commands as `PluginCommandContext` plus one returned `PluginCommandResult`; Discord defer, reply, follow-up, and edit controls exist internally but are not bridged to plugin command handlers. The remaining work is valid, but it needs a public SDK/API shape decision before implementation.

## What This Changes

The issue requests Discord interaction-level response controls in plugin command handlers so plugins can mix ephemeral slash responses, visible follow-ups, and reply edits.

## Best Possible Solution

Add a narrow documented plugin-command responder capability, preferably generic with Discord implemented first, while preserving the existing returned-payload command path and routing/auth behavior.
