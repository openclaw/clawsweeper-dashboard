- `impact:message-loss`: Discord plugin commands cannot currently send a private slash acknowledgement plus a visible follow-up, so intended command output can be hidden from the conversation.

## Summary

Keep open: current main and v2026.6.11 still route Discord plugin slash commands through `PluginCommandContext` plus one returned `PluginCommandResult`; the requested responder controls are a real SDK/channel capability gap that needs maintainer API direction, not conservative cleanup.

## What This Changes

Expose Discord slash interaction responder controls such as defer, reply, follow-up, and edit-reply to plugin command handlers.

## Best Possible Solution

Define a narrow, documented plugin-command responder or channel capability, choose the generic-versus-Discord-specific API deliberately, and cover Discord guild/group-DM behavior with focused SDK and native-command tests.

## Reproduction Assessment

Yes, at source level: current main still types plugin command handlers as generic `PluginCommandContext` plus one returned `PluginCommandResult`, and Discord native commands deliver only that returned payload. I did not run live Discord because the missing public API is directly visible in the type and dispatch path.

## Solution Assessment

Unclear. A responder capability is the right class of solution, but maintainers should choose whether the permanent SDK surface is generic or Discord-specific before implementation.
