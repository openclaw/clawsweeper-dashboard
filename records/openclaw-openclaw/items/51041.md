## Summary

Keep open: current main and v2026.6.11 still expose Discord plugin slash commands as a generic `PluginCommandContext` plus one returned `PluginCommandResult`; the Discord reply/defer/follow-up/edit primitives exist internally but are not available to `api.registerCommand` handlers. This remains a valid plugin SDK/channel capability request, but it needs maintainer API direction before implementation.

## What This Changes

The issue requests interaction-level Discord slash response controls such as defer, reply, follow-up, and edit for native plugin command handlers.

## Best Possible Solution

Add a narrow documented plugin-command responder or channel capability, preferably generic with Discord as the first implementation, while preserving returned-`ReplyPayload` compatibility and existing authorization/routing behavior.
