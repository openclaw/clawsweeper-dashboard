## Summary

Keep open: current main and the latest release still expose plugin commands as a generic `PluginCommandContext` plus one returned `PluginCommandResult`; Discord reply, defer, follow-up, and edit-reply controls remain internal to Discord interaction paths. The request is valid and vision-aligned, but it needs a maintainer API-shape decision before implementation.

## What This Changes

Expose Discord slash-interaction response controls such as defer, reply, follow-up, and edit-reply to native plugin command handlers.

## Best Possible Solution

Add a narrow documented plugin-command responder or channel capability, preferably generic with a Discord implementation, while preserving returned-`ReplyPayload` compatibility and existing authorization/routing behavior.
