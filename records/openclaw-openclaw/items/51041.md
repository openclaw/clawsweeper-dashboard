## Summary

Keep open: current main and v2026.6.11 still expose native plugin commands as a generic `PluginCommandContext` plus one returned `PluginCommandResult`; Discord interaction primitives exist internally and on interactive callbacks, but not in `registerCommand` handlers. This remains useful work, but it changes a public Plugin SDK and Discord channel contract, so maintainer API direction is needed before implementation.

## What This Changes

Request to expose Discord slash-interaction defer, reply, follow-up, and edit controls to native plugin command handlers.

## Best Possible Solution

Add a narrow, documented plugin-command responder capability, preferably generic with a Discord implementation, while preserving current returned-payload behavior and command auth/routing.
