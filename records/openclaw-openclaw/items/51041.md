## Summary

Keep open: current main and the latest release still do not expose Discord interaction-level defer/reply/follow-up/edit controls to `registerCommand` handlers. The primitives exist inside the Discord runtime and for plugin interactive handlers, but adding them to plugin commands is a public SDK/channel contract decision, not conservative cleanup.

## What This Changes

Expose Discord slash-command interaction responder controls such as defer, reply, follow-up, and edit-reply to plugin command handlers.

## Best Possible Solution

Add a narrow, documented plugin-command responder capability, preferably generic with a Discord-backed implementation, while preserving returned-payload behavior and command auth/routing semantics.

Question: Should plugin command handlers get a generic command-responder capability, a Discord-specific `ctx.discord.respond` surface, or no new command responder API?

Rationale: The requested behavior expands a public plugin SDK and Discord channel contract, and the best permanent shape depends on maintainer direction about generic versus channel-specific plugin APIs.

Likely owner: huntharo

Owner confidence: medium

Options:

- **Prefer generic responder capability (recommended):** Add a typed command responder seam that Discord implements now and other native-command channels can adopt without channel-specific SDK drift.
- **Approve Discord-specific responder:** Expose `ctx.discord.respond` for this channel only, accepting a narrower immediate API with more long-term SDK surface risk.
- **Decline command responder API:** Keep plugin commands on returned `ReplyPayload` plus `suppressReply`, and document that mixed-visibility Discord flows need a channel/plugin-specific workaround.

## Reproduction Assessment

Yes, at source level: current main still types plugin command handlers as `PluginCommandContext` plus one returned `PluginCommandResult`, and the Discord native command path only delivers that returned payload. I did not run live Discord because the missing public API is directly visible in the type and dispatch path.

## Solution Assessment

Unclear. A responder capability is the right class of solution, but maintainers should choose whether the permanent SDK surface is generic or Discord-specific before implementation.
