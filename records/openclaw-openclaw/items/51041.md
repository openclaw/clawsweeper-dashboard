## Summary

Keep open: current main and the latest release still expose Discord plugin slash commands through the generic plugin command context plus one returned result, while Discord response controls exist only in internal native/interactive paths. The request is valid, but it changes public plugin SDK and Discord routing semantics, so it needs maintainer API direction rather than cleanup closure.

## What This Changes

Expose Discord slash-interaction response controls such as defer, reply, follow-up, and edit to plugin command handlers.

## Best Possible Solution

Add a narrow documented plugin-command response capability through the SDK, with a Discord implementation and focused tests, while keeping the returned ReplyPayload path compatible for existing plugins.

## Reproduction Assessment

Yes. Source inspection shows plugin command handlers receive PluginCommandContext and return one PluginCommandResult, while Discord responder primitives are only present in internal/native or interactive-callback paths.

## Solution Assessment

Unclear. The requested responder shape is plausible, but maintainers should decide whether the permanent SDK surface is Discord-specific or a generic command responder capability before implementation.
