## Summary

Keep open for a provider-owner decision before merge. The branch is a well-tested implementation, but it changes OpenClaw from its current documented credential-required OpenCode Zen flow to an undocumented credentialless mode; the upstream client source cited by the contributor is strong technical evidence, while the current upstream and OpenClaw docs still direct users to configure an API key.

## What This Changes

The PR adds model-aware synthetic authentication for OpenCode Zen so zero-input-cost catalog models receive the non-secret `public` key without configured credentials while paid or unknown models remain credential-gated.

## Best Possible Solution

Either explicitly adopt and document OpenCode Zen’s source-defined public-model contract, with a provider-owned ownership and review commitment, or retain the current API-key-only OpenClaw behavior until OpenCode publishes a stable user-facing anonymous-inference contract.
