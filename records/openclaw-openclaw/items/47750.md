## Summary

Keep open: current main and v2026.6.11 still only support non-interactive OpenAI setup through the API-key path, while OpenAI/Codex OAuth remains an interactive browser/device-code/manual-paste flow. The adjacent callback cleanup work is useful but does not implement the requested non-interactive OAuth setup contract.

## What This Changes

The issue requests a non-interactive way to configure the OpenAI/Codex OAuth provider, such as supplying an OAuth callback URL via environment variable.

## Best Possible Solution

Design an OpenAI-plugin-owned non-interactive OAuth import contract that preserves PKCE/state validation, avoids secret-bearing env/log exposure, documents the CLI/env behavior, and includes focused tests plus redacted real-flow proof.

## Reproduction Assessment

Yes, at source level: current main rejects non-TTY `models auth login`, rejects OpenAI OAuth from non-interactive setup because it lacks `runNonInteractive`, and documents only API-key automation. I did not run a live OAuth flow because the missing behavior is a setup surface rather than a runtime-only failure.

## Solution Assessment

Unclear. A raw callback-URL environment variable is one possible interface, but maintainers should choose the leak-resistant provider-owned code, token, callback, or auth-session contract before implementation.
