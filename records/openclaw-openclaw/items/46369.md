## Summary

Keep open: current main still removes only the cron job record, while base cron session rows can remain listed as non-run sessions. The related open PR addresses delayed guarded retention for orphaned base rows, but it does not fully settle the immediate delete-time Control UI ghost-session behavior.

## What This Changes

The issue asks for cron.remove to remove associated cron session-store entries so deleted jobs no longer appear as ghost sessions in the Control UI.

## Best Possible Solution

Adopt one owner-approved cron session lifecycle policy that clears deleted-job ghost sessions promptly while preserving live cron base rows and user preferences.
