## Summary

Keep open: current main and v2026.6.11 still remove only the cron job row, while base cron session rows remain outside the current `:run:` cleanup path. The open fork PR directly targets this issue and the open member PR for cron retention overlaps the same lifecycle boundary, so the next step is maintainer policy review rather than cleanup closure.

## What This Changes

The issue asks for `cron.remove` to clean deleted cron job config, run logs, and session-store rows so removed jobs stop appearing as ghost sessions in the Control UI.

## Best Possible Solution

Adopt one maintainer-approved cron session lifecycle policy that clears deleted-job ghost sessions promptly enough for the UI while preserving live cron base rows that carry user preferences.
