## Summary

Keep open: current main and v2026.6.11 still remove only the cron job row while base cron session rows remain outside both `cron.remove` and the `:run:`-only retention sweep. The linked cleanup work is still open, but the remaining choice is a cron/session lifecycle policy decision rather than a safe cleanup close.

## What This Changes

The issue asks for `cron.remove` to remove deleted cron jobs' session records and run artifacts so ghost sessions stop appearing in the Control UI.

## Best Possible Solution

Land one maintainer-approved cron session lifecycle policy that removes deleted-job ghost sessions while preserving live cron base rows that carry user preferences.

Yes, at source level. Current main shows `cron.remove` removes only the job record, isolated cron can use base `agent:<agentId>:cron:<jobId>` keys, and the current reaper/test boundary skips those base rows; I did not run a live mutating gateway repro in this read-only review.

## Solution Assessment

Unclear. Direct delete-time cleanup best matches the ghost-session report, but guarded ownership-aware retention is safer for broad base-row pruning, so maintainers should choose the lifecycle boundary before implementation.
