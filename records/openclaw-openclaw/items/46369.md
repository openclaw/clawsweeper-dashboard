## Summary

Keep open: current origin/main and v2026.6.11 still remove only the cron job row, while base cron session rows can remain listable and create ghost sessions. The remaining blocker is a maintainer choice between immediate delete-time cleanup and guarded retention/orphan cleanup.

## What This Changes

The issue asks for cron.remove to remove deleted-job session records and run-log artifacts so deleted cron jobs no longer appear as ghost sessions in the Control UI.

## Best Possible Solution

Adopt one owner-approved cron session lifecycle policy that clears deleted-job ghost sessions promptly while preserving live cron base rows and user preferences.
