## Label Justifications

- `P2`: The issue is a normal-priority cron/session cleanup bug with visible ghost sessions but no evidence of data loss, security bypass, or unusable runtime.
- `impact:session-state`: The stale records live in the agent session store and affect cron session visibility and lifecycle state.
- `impact:ux-friction`: Deleted cron jobs can remain visible as ghost sessions in the Control UI, creating avoidable confusion without fully blocking use.

## Summary

Keep open: current `main` and latest release `v2026.6.11` still remove only the cron job record, while the session reaper only prunes `:run:` cron session keys and skips base cron session rows. The issue overlaps with broader open retention work, but the direct deleted-job ghost-session behavior is not implemented on `main`.

## What This Changes

The issue requests that deleting a cron job also remove its run logs and associated session-store records so deleted jobs no longer appear as ghost sessions in the Control UI.

## Best Possible Solution

Define one ownership-aware cron/session cleanup policy that removes deleted-job artifacts without pruning active isolated cron base sessions, then implement it in the existing cron service or reaper path with focused regression tests.
