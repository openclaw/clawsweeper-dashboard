## Summary

Keep open: current main and v2026.6.11 still remove only the cron job row while base cron session records remain outside the reaper’s `:run:` filter. A direct cleanup PR is open but conflicting, and the overlapping guarded retention PR still needs maintainer acceptance of the cron/session lifecycle boundary.

## What This Changes

The issue reports that deleting a cron job leaves its session record in the session store, so deleted jobs still appear as ghost sessions in the Control UI dropdown.

## Best Possible Solution

Land one maintainer-approved cron session lifecycle path that clears deleted-job ghost sessions while preserving live cron base session state and any carried model/auth/label choices.

## Reproduction Assessment

Yes for source-level reproduction: current `cron.remove` removes only the job entry, and the current reaper only matches `:run:` session keys, leaving base cron session rows untouched.

## Solution Assessment

Unclear: direct delete-time cleanup is plausible, but the overlapping retention PR documents that live base cron rows can carry model/auth/label state, so maintainers need to choose the lifecycle boundary.
