## Summary

Keep open: current main and the latest release still remove only the cron job record, while base cron session rows can remain visible as stale Control UI sessions. The direct cleanup PR is open but conflicting, and the overlapping retention PR needs maintainer choice before this can be closed.

## What This Changes

The issue requests that deleting a cron job via `cron.remove` also clean up the deleted job's session record and related cron run artifacts.

## Best Possible Solution

Land a maintainer-approved cleanup that removes deleted-job cron session visibility without deleting live-job carried preferences, and document whether immediate removal, retention reaping, or both own the cleanup.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should deleted cron jobs lose their base cron session immediately on `cron.remove`, or should base-row cleanup happen only through the guarded orphan-retention reaper?

Rationale: Both choices are defensible: immediate cleanup fixes Control UI ghost sessions, while retention-only cleanup avoids erasing live-job preference state if the ownership boundary is wrong.

Likely owner: Gustavo Madeira Santana

Owner reason: The current cleanup boundary comes from the cron/session maintenance work he introduced and hardened.

Owner confidence: high

Options:

- **Pair direct remove with guarded reaper (recommended):** Make `cron.remove` purge only the removed job's cron session artifacts, and keep the reaper responsible for older orphan rows with live-job safeguards.
- **Retention-owned cleanup only:** Land the ownership-based reaper path and accept that deleted-job base sessions disappear after retention rather than immediately.
- **UI filters deleted jobs:** Leave stored session rows intact and make the Control UI hide cron sessions that no longer map to a live job, preserving history at the cost of stale storage.

## Reproduction Assessment

Yes from source inspection: current `cron.remove` only removes the job record, and the current reaper/test coverage intentionally skips base cron session keys. I did not run a live Control UI repro in this read-only review.

## Solution Assessment

No final solution is selected yet. A narrow fix should clean deleted-job cron session visibility while preserving live-job carried preferences, rather than blindly changing the reaper to delete every base cron key.
