## Summary

The prior permission-classification blocker remains on the unchanged head: the shell plan turns a failed stat into a successful missing marker whenever `test -e` and `test -L` are both false, but those predicates cannot distinguish absence from an inaccessible entry. The localized-missing bug is real and the structured-result direction is preferable, yet this branch still needs that correctness repair plus real-container proof.

## What This Changes

The PR replaces English sandbox `stat` stderr matching with a reserved stdout marker emitted after a failed stat and adds mocked regression coverage for missing paths, dangling symlinks, and other failures.

## Best Possible Solution

Have the command plan return a structured status that preserves the actual stat failure category—mapping only confirmed ENOENT to missing—then prove missing, dangling-symlink, and denied-lookup behavior in a real localized sandbox.

## Solution Assessment

No, not yet. A structured locale-independent result is the right architecture, but the proposed shell fallback is not an errno-safe way to identify true absence and should not replace one locale dependency with ambiguous failure classification.
