## Summary

Keep this PR open: the follow-up fixes the two prior review findings, but the new absence check can still convert an inaccessible-path failure into `null`, and the submitted proof remains mock-only.

## What This Changes

The PR replaces locale-specific sandbox `stat` stderr matching with a reserved missing-path marker emitted after `stat` fails and adds regression tests for missing paths, dangling symlinks, and other failures.

## Best Possible Solution

Keep the stat-first and dangling-symlink behavior, but classify ENOENT using an errno-bearing helper or deterministic `stat` result that cannot confuse inaccessible paths with absence, then prove missing, dangling-symlink, and permission cases in a real localized container.

Yes at source level: run the generated plan as a non-root user against a basename inside a non-searchable directory; `stat`, `test -e`, and `test -L` can all fail, causing the marker path to return `null`. A real container run was not supplied.

## Solution Assessment

No. The stat-first ordering is appropriate, but shell existence predicates are not a reliable structured ENOENT result; an errno-aware helper or deterministic stat diagnostic is safer and narrower.
