## Label Justifications

- `P1`: The patch addresses a broken ClickClack discussion workflow where one ordinary session reset can disable discussion access for every active discussion until a plugin reload or gateway restart.

## Summary

The patch follows the host lifecycle contract: session reset/delete invokes plugin runtime cleanup broadly, while this ClickClack registration owns process-stable state and should only tear it down for plugin-wide disable/restart. No concrete correctness defect was found, but the PR’s evidence remains mock- and harness-based rather than a live gateway reset, so it needs real behavior proof before merge.

## What This Changes

This PR changes ClickClack discussion lifecycle cleanup so session reset or deletion does not unregister the shared discussion-access provider or stop its reconciler for all discussion sessions.

## System Context

ClickClack discussions register a process-wide session-visibility provider and background reconciler through the plugin runtime lifecycle. Gateway session reset/delete fans out cleanup callbacks to the active plugin registry, so the callback must distinguish a single-session event from disable or registry restart.
