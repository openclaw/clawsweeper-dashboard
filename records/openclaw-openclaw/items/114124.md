## Summary

The patch has a plausible, narrowly scoped fix for a P1 ClickClack discussion outage: session-wide cleanup is invoked for every plugin, while this lifecycle owns process-wide registration. The updated PR body adds focused before/after registry evidence and a real gateway `sessions.reset` smoke, but it still does not observe a pre-existing ClickClack discussion remaining usable after reset or deletion; keep this PR open for that final real-behavior proof.

## What This Changes

This PR makes ClickClack discussion lifecycle cleanup ignore session reset and deletion reasons, while retaining teardown for plugin disable and restart.

## System Context

The ClickClack plugin registers a process-wide session-access provider and a discussion reconciler with the plugin host. Gateway session reset and deletion fan out lifecycle cleanup notifications to installed plugins; the registration decides whether that notification should affect process-wide ClickClack state.
