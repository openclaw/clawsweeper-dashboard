## Label Justifications

- `P1`: An unbounded synchronous probe can stall state and plugin database initialization, breaking startup for affected users.

## Summary

Keep open: current main still performs the fallback `mount` probe synchronously without a deadline, while this PR adds a bounded probe and conservative rollback-journal behavior with focused regression coverage. No concrete correctness or security defect was found in the patch.

Likely related people
- @vincentkoc — high confidence; introduced and merged the current network-filesystem SQLite policy that this PR hardens.

## What This Changes

Adds a one-second timeout to SQLite’s fallback `mount` classification probe and selects rollback journaling when that probe times out.

## Best Possible Solution

Keep the bounded fallback probe, conservatively select rollback journaling on timeout, and retain focused coverage for successful classification, ordinary failures, and timeout behavior.

Yes. Bounding the existing owner path and choosing rollback journaling when classification times out is narrower and safer than adding configuration, assuming the timeout remains an exceptional fallback rather than normal filesystem detection.
