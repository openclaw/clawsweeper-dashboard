## Label Justifications

- `P1`: The existing synchronous mount fallback can block state and plugin database startup, leaving a core startup workflow unavailable.

## Summary

Keep open: the patch improves ordinary stalled-child behavior, but its synchronous timeout cannot guarantee the hard database-startup deadline claimed by the PR.

## What This Changes

Adds a one-second timeout to SQLite filesystem mount classification and selects rollback journaling when the probe reports a timeout.

## Best Possible Solution

Make database opening independent of a synchronous `mount` subprocess by using prepared asynchronous or platform-native classification, with conservative rollback journaling when classification is unavailable, then prove the missing-proc startup path on a real supported host.

- **[P1] Remove the synchronous mount probe from database startup:** `src/infra/sqlite-wal.ts:188`
  - body: `execFileSync` does not provide the promised hard deadline: after its timeout sends `SIGKILL`, Node still waits until the child has fully exited. Move classification outside the synchronous startup path or conservatively use rollback journaling when no nonblocking classification is available.
