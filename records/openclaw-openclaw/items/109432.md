## Summary

Keep open: the previously reported P1 blocker remains at the current head because the timeout does not make a synchronous child-process probe a hard-bounded database-startup operation, and the submitted proof does not exercise that failure mode on a supported host.

## What This Changes

The PR adds a one-second timeout and conservative rollback-journal handling to fallback mount classification during SQLite startup, with expanded WAL policy tests.

## Best Possible Solution

Remove external synchronous process execution from the database-open path: classify with already-available native metadata or prepared facts, and select rollback journaling without launching `mount` when classification is unavailable; then prove startup and journal selection on a supported macOS/BSD environment.
