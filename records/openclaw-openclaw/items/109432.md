## Summary

Keep open: the prior P1 blocker remains. Final head still relies on synchronous `execFileSync`; Node waits for complete child exit after a timeout signal, so the central no-hang guarantee is not established. ([nodejs.org](https://nodejs.org/api/child_process.html?utm_source=openai))

## What This Changes

Adds a one-second timeout to fallback SQLite mount classification, selects rollback journaling on timeout, defers child-process/parser loading, and adds regression tests.

## Best Possible Solution

Remove the external synchronous command from database opening—either prepare filesystem classification asynchronously before opening SQLite or conservatively avoid the fallback command—while preserving WAL for positively classified local filesystems and proving the final path on a supported host.
