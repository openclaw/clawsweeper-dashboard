## Summary

The PR improves the common stalled-probe case, but it retains a synchronous child process on the database-open path, so it does not guarantee that a wedged mount probe cannot still block startup. The previous P1 finding remains unresolved on the latest head, and the fixture-based evidence does not prove the problematic child-termination behavior on a supported host.

## What This Changes

Adds a one-second timeout and conservative rollback-journal policy to fallback mount classification, defers mount-related loading, extracts SQLite lock-error helpers, and extends WAL policy tests.

## Best Possible Solution

Remove the synchronous subprocess from database open—use existing filesystem facts and conservatively select rollback journaling when classification is unavailable—then provide redacted supported-host terminal proof for normal local storage, network storage, and an unavailable classification path.
