## Summary

This PR remains necessary because current main still has the unbounded fallback probe, but the latest patch does not guarantee bounded startup: Node’s synchronous child-process API waits for the child to fully exit even after the timeout sends its kill signal. The previously reported P1 blocker therefore remains on the latest head, and the test-fixture proof does not demonstrate the wedged real-host condition the PR claims to eliminate.

## What This Changes

Adds a one-second timeout to fallback SQLite mount classification, chooses rollback journaling on timeout, defers probe dependencies, and adds timeout-policy regression tests.

## Best Possible Solution

Remove external process execution from the synchronous database-open path: carry an asynchronously prepared filesystem classification into SQLite setup, or immediately use conservative rollback journaling when proc-based classification is unavailable, with regression coverage for success, unknown, and failure paths plus redacted real-host startup proof.
