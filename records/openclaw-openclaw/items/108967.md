## Summary

This PR remains necessary because current main’s merged CJK launcher fix deliberately leaves ANSI/OEM-mismatched Windows locales unresolved; the current head extends that design without a concrete correctness defect after five prior review cycles and maintainer-authored refinements.

## What This Changes

The PR resolves the boot-time Windows OEM code page, declares and uses it for generated `.cmd` launchers, fails unsafe encodings closed, reuses the existing registry query path, and expands launcher and daemon regression coverage.

## Best Possible Solution

Land the OEMCP-based launcher path with explicit code-page declaration, exact round-trip verification, legacy marker readback, and clear fail-closed errors after the exact merged head passes Windows and compatibility gates.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. A real Turkish Windows 11 host with ACP 1254 and OEMCP 857 reproduces the current launcher corruption, and the patched production encoder and registry resolver produce a working launcher on that same path.

## Solution Assessment

Yes. Encoding the installer-resolved paths for the actual OEM page is narrower and safer than replacing them with environment-variable assumptions that would break custom npm prefixes, portable Node installations, and version managers.
