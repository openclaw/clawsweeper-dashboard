## Summary

Keep open: current main contains the earlier CJK-focused launcher fix, but the linked ANSI≠OEM Windows failure remains reproducible and this PR is a focused, well-supported candidate fix.

## What This Changes

The PR changes generated Windows `.cmd` launchers to use the boot-time OEM code page, reuses the existing registry-query path, and adds regression coverage for affected locales and launcher flows.

## Best Possible Solution

Land the OEM-based encoding path while preserving marked-launcher read compatibility and fail-closed round-trip checks, then allow the linked issue to close through the merge.

Yes. The PR documents a current-main failure and patched success on a real Turkish Windows 11 host with ACP 1254, OEMCP 857, and a non-ASCII profile path.

## Solution Assessment

Yes. Encoding the installer-resolved launcher paths for the console's boot-time OEM page is narrower and more compatible than substituting environment variables that would invalidate custom Node and npm installation paths.
