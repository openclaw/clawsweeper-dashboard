## Summary

This PR remains necessary because current main only covers locales where the prior ANSI approximation matches the console encoding. The OEMCP-based approach appears technically sound and has convincing live Turkish Windows proof, but maintainers should confirm the broader fail-closed upgrade behavior before merging.

## What This Changes

The PR resolves the Windows console OEM code page from the registry, uses it to encode generated `.cmd` launchers, and adds coverage for non-CJK OEM pages and compatibility behavior.

## Best Possible Solution

Keep the OEMCP-based encoder, marker-compatible decoder, and lossy-conversion rejection, then verify both fresh installation and forced upgrade on a real ANSI≠OEM Windows host before merge.
