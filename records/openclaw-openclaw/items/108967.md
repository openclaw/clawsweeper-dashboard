## Label Justifications

- `P0`: Affected users can install OpenClaw but cannot start the managed Gateway, leaving a first-run Windows path unusable.
- `merge-risk: 🚨 compatibility`: The encoder changes generated launcher bytes and can turn previously attempted UTF-8 launcher writes into explicit installation failures when content is not representable.
- `merge-risk: 🚨 availability`: An incorrect OEM mapping, registry result, or representability decision could prevent the managed Gateway launcher from being written or started.

## Summary

Keep this PR open as the active fix for the linked Windows startup blocker. The OEM-code-page approach addresses the gap left by the earlier CJK launcher fix, preserves resolved custom paths, has convincing Turkish Windows before/after proof, and introduces no discrete correctness or security finding.

## What This Changes

The PR changes generated Windows `.cmd` launchers to use the boot-time OEM code page, adds registry-backed OEM mappings and round-trip validation, and expands launcher regression coverage.

## Best Possible Solution

Land the OEM-based encoder after exact-head Windows checks, retain legacy marker decoding and the fail-closed round-trip contract, and track CP864 or CP1258 separately only if a safe encoding strategy and real-host reproduction become available.
