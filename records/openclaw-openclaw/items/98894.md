## Summary

Keep open: current main and the latest release still contain the reported source-level failure path, the issue has a protected maintainer label, and no merged or open pending-stdin/unhandled-rejection fix PR supersedes it.

## What This Changes

The issue reports that a claude-cli live-session timeout can reject the turn output promise while stdin writing is still pending, producing an unhandled rejection that exits the gateway.

## Best Possible Solution

Fix the local live-session promise ownership so timeout rejection is observed before any awaited stdin write, then add regression coverage for a stdin write callback that never fires across watchdog expiry.

## Reproduction Assessment

Yes, at source level: use a claude-stdio ManagedRun whose stdin.write callback never fires, let the no-output timer expire, and failTurn rejects outputPromise before it is awaited. I did not run a live stuck-child gateway repro in this read-only review.

## Solution Assessment

Yes. The best fix is local live-session promise ownership plus a regression test; globally suppressing FailoverError in the unhandled-rejection handler would mask the promise-lifecycle bug instead of fixing it.
