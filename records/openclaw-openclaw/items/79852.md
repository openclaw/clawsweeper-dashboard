## Summary

Keep open: the reported bug is valid and the proof is useful, but the patch is not merge-ready because it duplicates the session archive timestamp contract and only fixes reset archives with millisecond timestamps while current main also accepts deleted archives and optional-millisecond archive timestamps.

## What This Changes

This PR adds a memory-core parser for `.jsonl.reset.<timestamp>` filenames before the `fs.stat` fallback and adds two temporal-decay regression tests.

## Best Possible Solution

Route temporal decay through the shared session archive timestamp parser via an appropriate memory-host/core facade, cover reset and deleted archive forms, preserve live `.jsonl` mtime fallback, and refresh the branch before merge.

## Reproduction Assessment

Yes, at source level. Current main's `extractTimestamp` falls through to `workspaceDir` `fs.stat` for logical session archive paths and returns `null` on missing files, so indexed reset archive hits can skip temporal decay.

## Solution Assessment

No. Parsing archive timestamps before `fs.stat` is the right layer, but this implementation duplicates the existing archive contract and misses sibling accepted archive forms.
