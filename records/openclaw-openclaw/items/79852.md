## Summary

Keep open: the reported temporal-decay bug is real and the PR targets the right path, but it is not merge-ready because it duplicates the session archive timestamp contract and only covers reset archives with millisecond suffixes.

## What This Changes

The PR adds a memory-core temporal-decay parser for `.jsonl.reset.<timestamp>` session archive filenames and tests that reset archives decay and rank by filename timestamp.

## Best Possible Solution

Route temporal decay through the shared session archive timestamp helper or memory-host facade for all usage-counted archive forms before `fs.stat`, keep live `.jsonl` mtime fallback, and refresh against current main.

## Reproduction Assessment

Yes at source level: current main's `extractTimestamp` returns null when a logical `sessions/main/*.jsonl.reset.*` hit has no matching file under `workspaceDir`, so decay is skipped. I did not run tests because this review is read-only.

## Solution Assessment

No. Parsing archive timestamps before `fs.stat` is the right layer, but the best fix should reuse the shared parser and cover reset/deleted optional-millisecond archives instead of adding a duplicate reset-only contract.
