## Summary

Keep open: current main has a SQLite memory index, Markdown-backed durable memory files, short-term promotion into MEMORY.md, and Memory Wiki synthesis surfaces, but not the requested typed durable write resolver with classification, source-required dedupe/merge decisions, explicit conflict state, and revision history.

## What This Changes

This issue requests a conservative durable memory write pipeline with classification, source attachment, duplicate/conflict resolution, merge/update handling, and revision history before candidate memories are stored.

## Best Possible Solution

Define one owner for the active-memory write contract first, then implement SQLite-backed canonical records, resolver decisions, provenance/revision history, conflict review state, and Memory Wiki interaction tests together.
