## Summary

Keep open: current main still has Markdown-backed memory, memory search/get tools, short-term promotion, and an adjacent Memory Wiki layer, but not the requested durable write resolver with typed classification, source-required dedupe/merge decisions, conflict state, and revision history. The production-agent comment is useful design input, and the related Memory MVP items remain open rather than superseding this issue.

## What This Changes

Request to build a conservative durable memory ingestion write pipeline that classifies candidates, attaches source/provenance, dedupes or merges before write, and routes conflicts or low-confidence entries to review.

## Best Possible Solution

Define one plugin-owned active-memory write contract first, then implement the SQLite-backed record schema, resolver decisions, provenance/revision trail, conflict review path, and focused memory-core/Memory Wiki interaction tests together.
