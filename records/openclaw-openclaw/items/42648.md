## Summary

Keep open: current main has Markdown-backed memory files, SQLite search indexing, thresholded promotion, and a separate memory-wiki belief layer, but not the requested durable candidate write resolver with classification, required source attribution, dedupe/merge decisions, conflict state, and revision history.

## What This Changes

The issue requests a Memory MVP write pipeline that classifies candidate memories, attaches sources, dedupes or merges before durable write, and routes conflicts or low-confidence candidates to review.

## Best Possible Solution

Define one plugin-owned active-memory write contract first, then implement the SQLite-backed schema, resolver decisions, provenance and revision trail, conflict review path, and focused memory-core plus memory-wiki interaction tests together.
