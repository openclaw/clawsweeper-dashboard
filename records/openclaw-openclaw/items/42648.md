## Summary

Keep open: current main still has Markdown-file memory with search/get/promote, short-term promotion, and a separate memory-wiki belief layer, but it does not implement the requested durable write resolver with classification, source-required dedupe/merge, conflict state, and revision history. The production-agent comment is useful design input, especially around confidence scoring, aliases, and provenance chains, but it does not supersede the missing core memory design work.

## What This Changes

Build a Memory MVP write path that classifies candidate memories, attaches provenance, dedupes or merges before durable write, and surfaces conflicts with revision history.

## Best Possible Solution

Define the durable write resolver as a memory-plugin-owned design first, with canonical SQLite records, required source refs, explicit conflict/review states, revision history, and clear interaction with memory-wiki as an optional belief layer.
