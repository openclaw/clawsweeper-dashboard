## Summary

Keep open: current main still has Markdown-backed memory files, SQLite indexing, thresholded promotion, and a separate wiki belief layer, but not the requested durable candidate write resolver with classification, source-required dedupe/merge decisions, conflict state, and revision history.

## What This Changes

The issue requests a Memory MVP write pipeline that classifies candidate memories, attaches sources, dedupes or merges against existing records, and routes conflicts or low-confidence writes for review.

## Best Possible Solution

Define one plugin-owned active-memory write contract first, then implement the SQLite-backed schema, resolver decisions, provenance/revision trail, conflict review path, and focused memory-core plus memory-wiki interaction tests together.
