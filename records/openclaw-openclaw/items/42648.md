## Summary

Keep open: current main still has Markdown-backed memory files, memory_search/memory_get, short-term promotion into MEMORY.md, and a separate Memory Wiki claim layer, but not the requested typed durable write resolver with classification, source-required dedupe/merge decisions, conflict state, and revision history.

## What This Changes

The issue asks for a Memory MVP write pipeline that classifies candidate memories, attaches sources, dedupes/merges before durable writes, and routes conflicts or low-confidence/source-less candidates to review.

## Best Possible Solution

Define one plugin-owned active-memory write contract first, then implement SQLite-backed canonical records, resolver decisions, provenance/revision history, conflict review state, and Memory Wiki interaction tests together.
