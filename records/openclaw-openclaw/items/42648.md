## Summary

Keep open: current main and the latest release still provide Markdown memory files, search/indexing, short-term promotion into MEMORY.md, and a separate Memory Wiki layer, but not the requested durable write resolver with typed classification, source-required dedupe/merge decisions, conflict state, and revision history.

## What This Changes

Build a conservative Memory MVP write pipeline for candidate memory ingestion with classification, source attribution, dedupe, merge/update decisions, conflict handling, and revision history.

## Best Possible Solution

Define one plugin-owned active-memory write contract first, then implement the SQLite-backed canonical records, resolver decisions, provenance/revision trail, conflict review path, and memory-core/Memory Wiki interaction tests together.
