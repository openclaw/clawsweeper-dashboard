## Summary

Keep open: current main and the latest release still provide Markdown-backed memory search/promotion, a narrower LanceDB store path, and an adjacent memory-wiki belief layer, but not the requested durable write resolver with source-required classification, dedupe/merge, revision history, and conflict review. The w1tv production comment is useful design input around pending states, aliases, conflict handling, and provenance chains, but it does not make the OpenClaw implementation complete.

## What This Changes

Build a durable memory ingestion write pipeline that classifies candidates, attaches sources, dedupes or merges near matches, and routes contradictions to review before writing.

## Best Possible Solution

Define one active-memory write contract, then implement a SQLite-backed resolver with source-required provenance, revisions, conflict review, and explicit memory-core/wiki/plugin integration boundaries.
