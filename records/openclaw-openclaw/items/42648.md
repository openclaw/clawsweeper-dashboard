## Summary

Keep open: current main has Markdown-backed memory search/promotion, a narrower LanceDB store path, and an adjacent memory-wiki belief layer, but no durable write resolver that classifies candidates, requires source attribution, dedupes or merges globally, preserves revisions, and routes conflicts for review.

## What This Changes

The issue requests a Memory MVP write pipeline for candidate memory ingestion with classification, source attachment, dedupe/merge, conflict handling, revision history, and conservative write policy.

## Best Possible Solution

Define one plugin-owned active-memory write contract first, then implement a SQLite-backed resolver with source-required provenance, revisions, conflict review, and explicit memory-core/wiki integration boundaries.
