## Summary

Keep open: current main still has Markdown-backed memory search/promotion, memory-lancedb has a narrower store/forget path, and memory-wiki has an adjacent belief layer, but none provides the requested durable write resolver with source-required classification, global dedupe/merge, revision history, and conflict review. The w1tv comment adds useful production design input around pending states, aliases, conflicts, and provenance chains, but it does not make the OpenClaw implementation complete.

## What This Changes

Build a Memory MVP durable write pipeline that classifies candidate memories, attaches source attribution, dedupes or merges before storage, and routes conflicts for review.

## Best Possible Solution

Define one plugin-owned active-memory write contract, then implement a SQLite-backed resolver with source-required provenance, revisions, conflict review, and explicit memory-core/wiki integration boundaries.
