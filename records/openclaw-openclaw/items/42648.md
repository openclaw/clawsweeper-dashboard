## Summary

Keep open: current main still has file-backed memory search, thresholded dreaming promotion, an index SQLite schema, and adjacent memory-wiki provenance support, but it does not implement the requested durable candidate write resolver with typed classification, source-required dedupe/merge, conflict state, and revision history. The real-world implementation comment adds useful guidance around pending states, conflict semantics, and append-only provenance, but it reinforces that this needs product and ownership decisions rather than cleanup closure.

## What This Changes

Build a durable memory ingestion write path that classifies candidates, attaches sources, deduplicates or merges before storage, preserves revisions, and routes conflicts or low-confidence writes to review.

## Best Possible Solution

Define one plugin-owned active-memory write contract first, then implement the SQLite-backed schema, resolver decisions, provenance/revision trail, conflict review path, and focused memory-core plus memory-wiki interaction tests together.
