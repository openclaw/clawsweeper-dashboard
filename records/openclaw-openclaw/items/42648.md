## Summary

Keep open: current main has Markdown-backed memory, indexing, promotion, Memory Wiki, and a separate LanceDB memory_store, but not the requested active-memory write resolver with typed classification, source-required create/merge/conflict decisions, provenance-preserving revision history, and conflict review semantics.

## What This Changes

This issue requests a durable memory ingestion write pipeline that classifies candidate memories, attaches sources, dedupes or merges related records, and routes conflicts before storage.

## Best Possible Solution

Define one plugin-owned active-memory write contract first, then implement the SQLite-backed schema, resolver decisions, provenance/revision trail, conflict review path, and focused memory-core/Memory Wiki interaction tests together.
