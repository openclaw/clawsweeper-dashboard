## Summary

Keep open. Current main and v2026.6.11 still lack persisted cron pre/post/onError hooks or a conditional pre-agent gate; command cron jobs solve only the direct no-LLM script subset, while the remaining hook lifecycle is product- and security-sensitive.

## What This Changes

Requested cron job lifecycle hooks so scheduled jobs can run pre/post/error logic such as shell gates, webhooks, forced reminders, escalation, and conditional no-LLM execution.

## Best Possible Solution

Design a maintainer-approved additive cron hook or gate API spanning persisted job/protocol/CLI/UI/docs, with explicit trust, timeout, cancellation, logging, redaction, failure, and compatibility semantics while reusing command payloads and plugin hooks where they fit.

## Reproduction Assessment

Yes for source-level current-state verification: current main's cron types, protocol schemas, config schema, and execution paths do not accept or run the requested lifecycle hooks; this is a feature request rather than a broken existing behavior reproduction.

## Solution Assessment

Unclear as proposed. The user need is real, but maintainers need to choose the permanent boundary between command payloads, plugin hooks, and a persisted hook/gate API before implementation.
