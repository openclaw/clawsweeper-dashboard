## Summary

Keep open. Current main and the latest release still lack persisted cron pre/post/onError hooks or a conditional pre-agent gate, while adjacent command cron jobs solve only the direct no-LLM script subset; the remaining work is product- and security-sensitive.

## What This Changes

Request to add a persisted cron job hook lifecycle for pre-run gating, post-run handling, error handling, shell/webhook execution, and escalation-style automation.

## Best Possible Solution

Design a maintainer-approved cron gate or hook API that spans persisted job/protocol/CLI/UI/docs and includes explicit trust, timeout, cancellation, logging, redaction, and failure semantics while reusing command payloads and plugin hooks where they fit.

## Reproduction Assessment

Yes for source-level current-state verification: current main's cron types, protocol schemas, config schema, and execution paths do not accept or run the requested lifecycle hooks. This is a feature request rather than a broken existing behavior reproduction.

## Solution Assessment

Unclear as proposed. The need is well supported, but maintainers need to choose the permanent boundary between command payloads, plugin hooks, and a persisted cron hook/gate API before implementation.
