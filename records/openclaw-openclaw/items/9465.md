## Summary

Keep open. Current main and v2026.6.11 include command cron jobs for direct zero-LLM script runs, but they still do not implement persisted pre/post/onError cron hooks or a conditional pre-agent gate; the remaining shell/webhook lifecycle semantics need maintainer product and security review.

## What This Changes

The issue requests a cron job hook lifecycle that can run pre, post, and error hooks such as agent turns, system events, shell commands, or webhooks around scheduled execution.

## Best Possible Solution

Design and land a maintainer-approved additive cron hook or gate API across persisted job/schema, scheduled and manual execution paths, CLI/UI/docs/tests, with an explicit trust model and reuse of command payloads or plugin hooks where they already fit.

## Reproduction Assessment

Yes for source-level current-state verification: the persisted cron shape, protocol schemas, scheduled path, and manual path do not implement the requested lifecycle hooks. This is a feature request rather than a broken existing behavior reproduction.

## Solution Assessment

Unclear as proposed. The user need is real, but the broad shell/webhook lifecycle design needs a maintainer choice between command payloads, plugin hooks, and a persisted hook API before implementation.
