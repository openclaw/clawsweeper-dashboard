## Summary

Keep open. Current main supports command cron jobs for deterministic zero-LLM scripts, but it still does not implement the requested persisted pre/post/onError cron hook lifecycle or a conditional pre-agent gate, and the related hook implementation PRs were closed unmerged.

## What This Changes

The issue requests cron job hooks that can run pre, post, and error logic around scheduled execution for reminders, escalation, conditional execution, preprocessing, shell commands, and webhooks.

## Best Possible Solution

Land or explicitly reject a maintainer-approved cron hook/gate API that covers persisted job/protocol types, scheduled/startup/manual execution paths, CLI/UI/docs/tests, observability, and an explicit trust model while reusing command payloads or plugin hooks where they already fit.

## Reproduction Assessment

Yes, for source-level verification: the persisted cron shape, Gateway schemas, CLI/UI surfaces, and executor paths do not implement lifecycle hooks or a conditional pre-agent gate.

## Solution Assessment

Unclear as proposed; command cron is a useful partial alternative for zero-LLM scripts, but maintainers still need to choose the permanent boundary between command payloads, plugin hooks, and a persisted hook/gate API.
