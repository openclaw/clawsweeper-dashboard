## Summary

Keep open. Current main and v2026.6.11 support direct command cron payloads for some zero-LLM script jobs, but they still do not implement the requested persisted pre/post/onError cron hooks or conditional pre-agent gate, and the related implementation PRs were closed unmerged back to this canonical issue.

## What This Changes

Request to add a cron job hook lifecycle with pre, post, and error hooks for agent turns, system events, shell commands, and webhooks.

## Best Possible Solution

Design and land a maintainer-approved cron hook or gate API across persisted job/protocol types, scheduled/startup/manual execution paths, CLI/UI/docs/tests, with an explicit trust model and reuse of command payloads or plugin hooks where those already fit.

## Reproduction Assessment

Yes for source-level current-state verification: current main lacks persisted cron hook fields, Gateway schema support, and scheduled/startup/manual hook execution phases. This is a feature request rather than a broken existing behavior reproduction.

## Solution Assessment

Unclear as proposed. The user need is real, but maintainers need to choose the permanent boundary between command payloads, plugin hooks, heartbeat behavior, and a persisted hook/gate API before implementation.
