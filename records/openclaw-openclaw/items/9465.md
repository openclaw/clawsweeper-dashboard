## Summary

Keep open. Current main and v2026.6.11 have first-class command cron jobs for the direct zero-LLM script subset, but they still do not implement persisted pre/post/onError cron hooks or a conditional pre-agent gate; the related hook/preHook PRs are closed unmerged, so the remaining work is still product and security design.

## What This Changes

Request a persisted cron job hook lifecycle for pre/post/error custom logic, including shell, webhook, and agent-triggered gates before scheduled execution.

## Best Possible Solution

Land a maintainer-approved additive cron hook or gate API across persisted job/protocol types, scheduled/startup/manual execution paths, CLI/UI/docs/tests, and an explicit security model, while reusing command payloads and plugin hooks where those already fit.

## Reproduction Assessment

Yes for source-level current-state verification: current cron types, protocol schemas, and scheduled/startup execution paths show no persisted pre/post/onError hook lifecycle. This is a feature request rather than a broken existing behavior reproduction.

## Solution Assessment

Unclear as proposed. The user need is valid, but maintainers need to choose the durable boundary between command cron payloads, plugin observation hooks, and a new persisted hook/gate API before implementation.
