## Summary

Keep open. Current main has command cron jobs for deterministic zero-LLM scripts, but it still lacks the requested persisted pre/post/onError hook lifecycle and conditional pre-agent gate; the shell/webhook parts need maintainer product and security review.

## What This Changes

Request to add cron job hooks that run custom pre, post, and error logic such as agent turns, system events, shell commands, or webhooks around scheduled execution.

## Best Possible Solution

Land, narrow, or explicitly reject a maintainer-approved cron hook/gate API that covers persisted types, protocol schemas, all execution paths, CLI/UI/docs/tests, observability, and a clear trust model while reusing command payloads or plugin hooks where they already fit.

## Reproduction Assessment

Yes, source-level verification is high-confidence: the persisted cron shape, Gateway schemas, CLI/UI surfaces, and executor paths do not implement lifecycle hooks or a conditional pre-agent gate.

## Solution Assessment

Unclear as proposed. Command cron is a useful partial answer for zero-LLM scripts, but maintainers still need to choose the permanent boundary between command payloads, plugin hooks, and a persisted hook/gate API.
