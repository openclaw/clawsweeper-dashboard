## Summary

Keep open. Current main has direct command cron jobs for zero-LLM scripts, but it still lacks the persisted pre/post/onError hook and conditional pre-agent gating API requested here; related hook/preHook implementation PRs are closed unmerged, and the remaining shell/webhook semantics need maintainer product and security review.

## What This Changes

The issue requests a cron job hooks system with pre/post/onError/shouldRepeat lifecycle hooks and shell/webhook/agent/system-event hook execution options.

## Best Possible Solution

Design and land a maintainer-approved cron hook/gate API across persisted job and protocol schemas, scheduled/startup/manual execution paths, CLI/UI/docs/tests, with an explicit trust model and reuse of command payloads or plugin hooks where appropriate.

## Reproduction Assessment

Yes at source level: current cron job types, gateway schemas, and scheduled/startup execution paths omit persisted lifecycle hooks or a pre-agent gate, although this is a missing feature rather than a broken existing contract.

## Solution Assessment

Unclear: command cron jobs and observe-only plugin cron hooks cover adjacent use cases, but a first-class hook/gate API still needs maintainer product and security decisions before implementation.
