## Summary

Keep open. Current main still lacks persisted cron pre/post/onError hooks or a per-job pre-agent conditional gate; command cron and plugin hooks cover adjacent subsets, but not the requested public cron hook lifecycle, and shell/webhook hooks need maintainer product and security direction.

## What This Changes

The issue requests configurable cron job lifecycle hooks, including pre/post/error hooks and shell or webhook gates before scheduled agent execution.

## Best Possible Solution

Settle a maintainer-approved cron hook or deterministic gate API across persisted job/protocol schemas, scheduled/startup/manual execution paths, CLI/UI/docs/tests, and an explicit trust model, or explicitly route the capability to plugin/ClawHub surfaces if current extension points are sufficient.

- **Defer the feature:** Leave this as an acknowledged product gap until maintainers are ready to own the security model and public API surface.
