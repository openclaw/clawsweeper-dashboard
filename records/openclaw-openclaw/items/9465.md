## Summary

Keep open. Current main has command cron jobs for direct zero-LLM scripts, but it still does not implement persisted pre/post/onError cron hooks or a conditional pre-agent gate; the related hook PRs are closed unmerged and the issue remains product/security design work.

## What This Changes

Request to add persisted cron job lifecycle hooks for pre-run gating, post-run processing, error handling, retries, escalation, shell commands, and webhooks.

## Best Possible Solution

Design a maintainer-approved cron gate or hook API that reuses command payloads and plugin hooks where they fit, spans persisted job/protocol/CLI/UI/docs, and includes explicit trust, timeout, logging, redaction, and failure semantics.

## Reproduction Assessment

Yes for source-level current-state verification: current main's cron types, protocol schemas, config schema, and execution paths do not accept or run the requested lifecycle hooks. This is a feature request rather than a broken existing behavior reproduction.

## Solution Assessment

Unclear as proposed. The need is well supported, but maintainers need to choose the permanent boundary between command payloads, plugin hooks, and a persisted cron hook/gate API before implementation.
