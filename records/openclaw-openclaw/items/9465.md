## Summary

Keep open: current main and the latest release still lack persisted cron pre/post/onError hooks or a conditional pre-agent gate, while command cron and existing plugin hooks cover only adjacent subsets.

## What This Changes

The issue requests a cron job hooks system with pre, post, and onError lifecycle hooks that can run agent turns, system events, shell commands, or webhooks.

## Best Possible Solution

Design a maintainer-approved cron gate or hook API that spans persisted job/protocol/CLI/UI/docs and includes explicit trust, timeout, cancellation, logging, redaction, and failure semantics while reusing command payloads and plugin hooks where they fit.

## Reproduction Assessment

Yes for source-level current-state verification: current main's cron types, protocol schemas, config schema, and execution paths do not accept or run the requested lifecycle hooks.

## Solution Assessment

Unclear as proposed: the need is well supported, but maintainers need to choose the permanent boundary between command payloads, plugin hooks, and a persisted cron hook/gate API.
