## Summary

Keep open: current main has adjacent direct command cron jobs and observe-only plugin cron events, but it still lacks the persisted pre/post/onError lifecycle hooks and conditional pre-agent gate requested here, and the remaining shell/webhook semantics need maintainer product and security review.

## What This Changes

The issue requests persisted cron job lifecycle hooks that can run agentTurn, systemEvent, shell, or webhook logic before, after, or on error for scheduled jobs.

## Best Possible Solution

Design and land a maintainer-approved cron hook/gate API across persisted job and protocol schemas, scheduled/startup/manual execution paths, CLI/UI/docs/tests, with an explicit trust model and reuse of command payloads or plugin hooks where appropriate.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw core add a persisted cron lifecycle hook/gate API for pre/post/onError execution, including shell and webhook actions, or should this remain limited to command cron and plugin surfaces?

Rationale: The remaining work defines public cron config/protocol behavior and unattended code/network execution semantics, which automation cannot choose safely without maintainer intent.

Likely owner: steipete

Owner confidence: high

Options:

- **Approve a narrow core hook/gate API (recommended):** Define a small additive API with explicit security, timeout, logging, and failure semantics across all cron execution paths.
- **Extend plugin hooks first:** Keep cron job config smaller and add decision-capable plugin hooks only if current plugin surfaces cannot express the gate safely.
- **Do not add lifecycle hooks:** Treat command cron and observe-only cron_changed as the supported alternatives and close the remaining hook request as out of scope.

## Solution Assessment
