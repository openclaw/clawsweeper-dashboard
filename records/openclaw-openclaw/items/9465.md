## Summary

Keep open: current main and v2026.6.11 still lack persisted cron pre/post/onError hook semantics, and the remaining shell/webhook gate behavior needs product and security direction rather than cleanup closure.

## What This Changes

Requests persisted cron lifecycle hooks that can run pre, post, and error actions around scheduled jobs, including agent turns, system events, shell commands, and webhooks.

## Best Possible Solution

Settle a maintainer-approved cron hook or gate API across persisted job/protocol schemas, scheduled/startup/manual execution, CLI/UI/docs/tests, and an explicit trust model, or document the plugin/ClawHub boundary if core should not own it.
