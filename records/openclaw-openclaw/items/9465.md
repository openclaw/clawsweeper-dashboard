- `P2`: This is a meaningful cron automation enhancement with strong production use cases, but it is additive product work rather than an urgent regression or blocked first-run path.
- `impact:session-state`: The requested lifecycle hooks would alter scheduled agent execution state, skip/error outcomes, retries, and session/run lifecycle around cron jobs.

## Summary

Keep open. Current main and v2026.6.11 still lack a persisted cron pre/post/onError hook lifecycle; command cron covers some deterministic no-model jobs, but not hook phases around another cron payload, and all related implementation PRs are closed unmerged.

## What This Changes

The issue requests a first-class cron hook system for pre, post, and error phases, including shell, webhook, agent-turn, and system-event hook actions.

## Best Possible Solution

Define a maintainer-approved cron lifecycle contract or plugin API extension that covers persisted job shape, protocol schemas, scheduled/startup/manual/manual-run execution, CLI/UI/docs, validation, and a clear security model without duplicating command cron.

Options:

- **Approve a narrow lifecycle contract (recommended):** Define scoped pre/post/onError semantics with explicit operator authority, timeouts, output caps, redaction, audit logs, and failure/skip behavior before implementation.
- **Extend plugin hooks first:** Add a fail-capable or gate-capable cron plugin seam so optional hook logic can live outside core while cron remains the scheduler source of truth.
- **Keep current surfaces:** Treat command cron, failure alerts, webhooks, and observe-only plugin hooks as the supported answer and narrow or close the remaining request to documentation gaps.
