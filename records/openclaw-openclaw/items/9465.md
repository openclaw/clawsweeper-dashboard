## Summary

Keep open. Current main and v2026.6.11 have command cron jobs for direct zero-LLM scripts, but they still do not implement the persisted pre/post/onError hook lifecycle or conditional pre-agent gate requested here; the related hook implementation PRs are closed unmerged and the remaining shell/webhook behavior needs product and security review.

## What This Changes

Request to add per-cron lifecycle hooks that can run agent, system-event, shell, or webhook logic before, after, or on error around scheduled job execution.

## Best Possible Solution

Design and land a maintainer-approved cron hook or gate API that spans persisted job and protocol schemas, scheduled/startup/manual execution, CLI/UI/docs/tests, and an explicit trust model, reusing command payload and plugin hook primitives where they fit.

- **Sponsor scoped hook design (recommended):** Define a narrow persisted lifecycle/gate API with a security model and then implement it across cron runtime, protocol, CLI/UI, docs, and tests.
- **Narrow to existing command jobs:** Declare command payloads plus current plugin hooks sufficient for now and close or split hook-specific requests into smaller follow-ups.
- **Extend plugin hooks instead:** Keep per-job config lean and add only the generic plugin/runtime hook capability needed to gate or observe cron runs safely.

## Reproduction Assessment

Yes at source level: current cron job types, gateway schemas, and scheduled/startup execution paths omit persisted lifecycle hooks or a pre-agent gate. This is a missing feature rather than a broken existing behavior contract.

## Solution Assessment

Unclear: the requested hook system is plausible, but command cron jobs and observe-only plugin hooks already cover adjacent cases, so the best solution depends on a maintainer-approved product and security boundary.
