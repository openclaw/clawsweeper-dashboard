## Summary

Keep open: current main and the latest checked release still lack persisted cron pre/post/onError hooks or a conditional pre-agent gate, and the remaining work is a product/security-sensitive cron API decision rather than conservative cleanup.

## What This Changes

The issue requests a cron job hooks system with pre/post/onError lifecycle hooks and agentTurn, systemEvent, shell, and webhook hook kinds.

## Best Possible Solution

Design a maintainer-approved cron gate or hook API spanning persisted job, protocol, CLI, UI, docs, and runtime paths with explicit trust, timeout, cancellation, logging, redaction, and failure semantics while reusing command payloads and observe-only plugin hooks where they fit.

## Reproduction Assessment

Yes for source-level current-state verification: current main's cron types, protocol schemas, config schema, and execution paths do not accept or run the requested lifecycle hooks; this is a feature request rather than a broken existing behavior reproduction.

## Solution Assessment

Unclear as proposed: the need is well supported, but maintainers need to choose the permanent boundary between command payloads, plugin hooks, and a persisted cron hook/gate API before implementation.
