## Summary

Keep open. Current main and v2026.6.11 support direct command cron jobs for a narrower zero-LLM script path, but they still do not implement persisted pre/post/onError cron hooks or a conditional pre-agent gate, and the related hook PRs are closed unmerged.

## What This Changes

Add a cron job hook lifecycle that can run custom pre, post, and error logic such as shell/webhook gates, forced reminders, escalation, and conditional notifications around scheduled runs.

## Best Possible Solution

Design and land a maintainer-approved additive cron hook or gate API across persisted job/protocol types, scheduled/startup/manual execution paths, CLI/UI/docs/tests, with an explicit trust model and reuse of command payloads or plugin hooks where those already fit.

## Reproduction Assessment

Yes for source-level current-state verification: the persisted cron shape, Gateway protocol schemas, scheduled/startup/manual execution paths, and existing plugin hook surface do not implement the requested lifecycle hooks. This is a feature request rather than a broken existing behavior reproduction.

## Solution Assessment

Unclear as proposed. The user need is real, but maintainers need to choose the permanent boundary between command payloads, plugin hooks, and a persisted hook/gate API before implementation.
