## Summary

Keep open. Current main and the latest release still lack a persisted cron pre/post/onError hook lifecycle; command cron jobs now cover deterministic no-LLM jobs, but they do not provide per-job hook phases around agent execution, and the related implementation PRs are closed unmerged.

## What This Changes

The issue requests persisted cron job hooks that run pre/post/onError custom actions such as agent turns, shell commands, system events, and webhooks around scheduled execution.

## Best Possible Solution

Define a maintainer-approved, security-explicit cron lifecycle contract or plugin API extension that covers persisted job shape, protocol schemas, scheduled/startup/manual execution, CLI/UI/docs, and tests without duplicating command cron.

- **Plugin API first:** Extend plugin hooks or cron_changed into a safe gate surface before adding per-job core hook fields.
- **Keep current surfaces:** Treat command cron plus existing plugin hooks as the supported answer and close or narrow this issue to documentation gaps.

## Reproduction Assessment

Yes, source-level: current main can create command cron jobs, but persisted cron types and Gateway schemas do not accept hooks and due-job execution enters executeJobCoreWithTimeout without pre/post/onError phases. No live failure path is needed because this is a feature request.

## Solution Assessment

Unclear until maintainer direction. A narrow additive lifecycle may be the right solution, but current command payloads and plugin hooks cover some no-LLM and observation use cases, so the final design should avoid a second overlapping security surface.
