## Summary

Keep open. Current main and the latest release still lack persisted pre/post/onError cron hooks or a per-job conditional pre-agent gate; command cron jobs and plugin hooks cover adjacent subsets, but the requested shell/webhook lifecycle semantics still need maintainer product and security direction.

## What This Changes

Request adds a cron job hook lifecycle for pre, post, and error phases, including agentTurn, systemEvent, shell, and webhook hook actions for conditional runs, escalation, and forced reminders.

## Best Possible Solution

Settle a maintainer-approved cron hook or gate API across persisted job/protocol schemas, scheduled/startup/manual execution paths, CLI/UI/docs/tests, and an explicit trust model, or explicitly route the capability to plugins/ClawHub if current plugin hooks are sufficient.
