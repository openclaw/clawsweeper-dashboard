## Label Justifications

- `P1`: The issue describes a real top-level fan-out workflow that can park indefinitely until a user manually nudges it.
- `impact:message-loss`: The expected final synthesis message can be suppressed after the last child completion because no drain wake arrives.
- `impact:session-state`: The parent session can keep waiting even after all child sessions have settled, so its orchestration state drifts from runtime reality.

## Summary

Keep open: current main still lacks the top-level requester drain wake for this `sessions_yield` fan-out stall, and the open closing PR is the active fix candidate rather than a merged implementation.

## What This Changes

The issue requests a runtime wake for top-level sessions that spawn parallel subagents and yield, so the parent synthesizes once the last child settles without requiring a user nudge.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99396, or an equivalent top-level requester-settle wake through the announce pipeline, with coverage for delivered completions, give-up/suspension, and concurrent last-child settlement.

## Reproduction Assessment

Yes, at source level: the issue gives a concrete production timeline, and current main still has the zero-active prompt gap plus a descendant wake path gated to subagent run records. I did not run a live nondeterministic fan-out in this read-only review.

## Solution Assessment

Yes, a runtime drain wake is the best layer because prompt-only mitigation cannot create a turn after the parent is parked. The best next action is reviewing the linked fix candidate, not starting a second repair branch.
