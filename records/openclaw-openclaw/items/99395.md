- `impact:session-state`: The parent session can remain in an incorrect waiting state after all spawned child sessions have already settled.

## Summary

Keep open: current main still lacks the top-level requester drain wake, and https://github.com/openclaw/openclaw/pull/99396 is an open closing fix candidate, so the issue should remain open until that PR or an equivalent fix lands.

## What This Changes

The issue reports that top-level sessions using `sessions_yield` after parallel subagent fan-out can park permanently after all children settle instead of synthesizing without another user nudge.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99396, or an equivalent runtime-level top-level requester-settle wake through the announce pipeline with regression coverage for delivered, give-up, and concurrent last-child settle cases.

## Reproduction Assessment

Yes, at source level. The report gives a concrete production incident, and current main still has the zero-active active-context gap plus a descendant wake path gated to subagent run records rather than top-level requesters.

## Solution Assessment

Yes. A runtime wake is the right layer because prompt or active-context changes cannot create a turn once the parent is parked; the linked PR is the active implementation candidate rather than this issue needing a second repair branch.
