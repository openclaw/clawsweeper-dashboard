## Summary

Keep open: current main still lacks the top-level requester drain wake for this `sessions_yield` fan-out stall, and the linked open PR is the active closing fix candidate rather than a reason to close the issue before merge.

## What This Changes

The issue reports that a top-level `sessions_yield` parent that spawned parallel subagents can park forever after the last child settles because no all-descendants-settled wake is sent to registry-less top-level requester sessions.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99396, or an equivalent runtime-level top-level requester settle wake through the existing announce pipeline, with regression coverage for delivered, suspended, and raced completion paths.

## Reproduction Assessment

Yes at source level: the report gives a concrete live incident, and current main still drops active context at zero active while only waking run records with `wakeOnDescendantSettle`. I did not run the nondeterministic live fan-out reproduction in this read-only review.

## Solution Assessment

Yes: a runtime drain wake is the right layer because prompt-only mitigation cannot create a new turn after the parent has parked. The linked PR is the active implementation candidate, so a second repair branch from this issue would duplicate work.
