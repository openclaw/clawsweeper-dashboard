## Label Justifications

- `P1`: The issue reports a real fan-out workflow parking until manual re-entry after all children completed.
- `impact:session-state`: The parent session remains yielded/parked even after descendant completion, so runtime session state no longer drives the expected final turn.
- `impact:message-loss`: The final synthesized response is effectively suppressed until a human sends another message.

## Summary

Keep open: current main still lacks the top-level requester settle wake described here, and the open linked PR is the active candidate fix rather than a reason to close the issue before merge.

## What This Changes

The issue reports that top-level sessions waiting with `sessions_yield` after parallel subagent fan-out can park permanently because no final all-children-settled wake is emitted.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99396, or replace it with an equivalent core agents runtime fix that wakes top-level parked fan-out sessions after the last required child settles.

## Reproduction Assessment

Yes at source level, medium confidence: current main has the no-poll `sessions_yield` contract and nested descendant wake handling, but no top-level requester drain wake. I did not run a live N-way fan-out reproduction in this read-only review.

## Solution Assessment

Yes in direction: the fix belongs in the agents runtime wake path because prompt/context changes cannot create a new turn once the session is parked. The open linked PR is the current candidate implementation and should be reviewed on that basis.
