## Label Justifications

- `P1`: The issue describes a real top-level agent orchestration workflow that can park indefinitely until a user manually nudges it.
- `impact:session-state`: The parent session can remain in an incorrect waiting state after all spawned child sessions have already settled.
- `impact:message-loss`: The expected final synthesis message can be suppressed because no final wake arrives after the last child settles.

## Summary

Keep open: current main still lacks a top-level requester drain wake for this `sessions_yield` fan-out case, and the linked open PR remains the active closing fix candidate.

## What This Changes

Ensure top-level sessions that spawn parallel subagents and call `sessions_yield` get an all-children-settled wake so they synthesize without a user nudge.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99396, or an equivalent runtime requester-settle wake through the existing announce pipeline with coverage for delivered completions, give-up/suspension, and concurrent last-child settle races.

## Reproduction Assessment

Yes, at source level. The issue provides a concrete production incident, and current main still has the zero-active prompt gap plus a descendant wake path gated to subagent run records.

## Solution Assessment

Yes. A runtime wake is the right layer because prompt-only mitigation cannot create a turn once the parent is parked; the open closing PR is the best current fix path.
