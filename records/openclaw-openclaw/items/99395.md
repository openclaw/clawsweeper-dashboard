## Label Justifications

- `P1`: The issue describes a broken top-level agent fan-out workflow where real sessions can park indefinitely until a user nudges them.
- `impact:session-state`: The parent session can remain in an incorrect waiting state after all spawned child sessions have already settled.

## Summary

Keep open: current main still lacks the top-level requester drain wake described in this issue, and the linked open PR is the active closing fix candidate rather than a merged implementation.

## What This Changes

The issue reports that top-level sessions which spawn parallel subagents and wait with `sessions_yield` can park indefinitely because no all-descendants-settled wake is sent to registry-less requesters.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99396, or an equivalent runtime requester-settle wake through the existing announce pipeline, with coverage for delivered completions, give-up/suspension, and concurrent last-child settle races.

## Reproduction Assessment

Yes, at source level: current main has push-based `sessions_yield` completion semantics, a zero-active prompt-context gap, and only a run-record-gated descendant wake path. I did not run a live nondeterministic multi-child fan-out in this read-only pass.

## Solution Assessment

Yes, a runtime wake is the right layer because prompt context cannot create a new turn after the requester is parked. The open linked PR is the canonical implementation candidate, so the issue should stay open until it or an equivalent fix lands.
