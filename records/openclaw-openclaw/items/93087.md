## Summary

The patch is technically coherent and still necessary because current `main` continues to advertise and validate `grpc` while the diagnostics plugin refuses to start OTLP signals with that protocol. No contributor-facing defect remains, but retiring a shipped config value and automatically disabling affected telemetry requires explicit diagnostics/config owner approval before merge. ([github.com](https://github.com/openclaw/openclaw/blob/main/extensions/diagnostics-otel/src/service.ts))

## What This Changes

Restricts `diagnostics.otel.protocol` to `http/protobuf`, adds a doctor migration for legacy `grpc` configurations, aligns documentation and help, and expands validation, migration, and runtime coverage.

## Best Possible Solution

Approve one canonical HTTP/protobuf-only config contract with the bounded doctor migration and focused upgrade tests, then refresh the branch and merge; if maintainers intend to preserve `grpc`, pause this PR and implement the separate OpenTelemetry gRPC exporters instead.
