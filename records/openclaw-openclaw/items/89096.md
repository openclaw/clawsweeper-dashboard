## Summary

Keep open: the live macOS proof credibly demonstrates the intended LaunchAgent replacement case, but the patch removes the only pre-kickstart check for an unrelated process owning the configured port. That can make `kickstart -k` terminate a healthy managed gateway and then fail to rebind, especially for direct callers that do not perform the CLI readiness check.

Likely related people: `fuller-stack-dev` is the strongest routing candidate from recent merged work on the same LaunchAgent port-release module (medium confidence).

## What This Changes

The PR removes the macOS LaunchAgent restart precondition that rejects a still-busy gateway port before `launchctl kickstart -k`, and updates the corresponding launchd tests.

## Best Possible Solution

Keep stale cleanup and permit `kickstart -k` only when the remaining listener is verified as the current or immediately respawned target LaunchAgent; retain a clear pre-kickstart error for an unrelated owner and cover both paths with focused tests.
