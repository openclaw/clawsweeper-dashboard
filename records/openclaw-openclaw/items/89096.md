## Label Justifications

- `P1`: The proposed behavior can turn an existing pre-restart conflict into a managed-gateway outage for macOS users when the port owner is unrelated.

## Summary

Keep this PR open for maintainer review: the supplied macOS proof supports restarting a LaunchAgent that owns its own port, but removing every post-cleanup busy-port check can make an unrelated listener trigger a disruptive `kickstart -k` while direct callers still receive a completed restart without readiness confirmation.

## What This Changes

The PR removes the macOS LaunchAgent restart pre-kickstart port-busy failure and updates launchd regression tests to allow `kickstart -k` while the gateway port is busy.

## Best Possible Solution

Keep the managed-LaunchAgent busy-port path restartable, but retain a narrow non-managed-listener safeguard or make restart completion include a reliable readiness result for every caller before removing the generic failure path.
