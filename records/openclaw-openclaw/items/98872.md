## Summary

Keep open: current main and the latest release still use boundary-blind home-path replacement in terminal table cells, so the reported misleading `~2/project` style output remains a valid narrow bug.

## What This Changes

The issue reports that terminal table rendering rewrites sibling paths that merely share the effective home-directory string prefix.

## Best Possible Solution

Implement one boundary-aware home-path shortening rule for embedded display text, apply it to terminal-core table cells, and add regression coverage for exact-home, child-path, and sibling-prefix paths.

## Reproduction Assessment

Yes, source-level: current main maps each terminal table cell through a helper that globally replaces the home string, so `/home/alice2/project` would become `~2/project` when the home is `/home/alice`. I did not run tests because this review is read-only.

## Solution Assessment

Yes, the best fix is a narrow boundary-aware replacement in the shared terminal display helper, with aligned coverage for the existing shared utility helper if maintainers want consistent CLI diagnostics.
