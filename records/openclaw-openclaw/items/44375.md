## Label Justifications

- `P1`: Silent default-agent displacement can reroute live channel, heartbeat, and cron traffic away from the user's expected primary agent.
- `impact:security`: Unmatched traffic can be delivered into an unintended ACP runtime or workspace with different tools, credentials, and sandbox policy.
- `impact:message-loss`: Channel traffic without a matching binding can be delivered to a different agent than the user intended after adding one ACP agent.
- `impact:session-state`: Changing the fallback agent changes agent-scoped session keys and can strand existing `main` history, memory, and auth state.

## Summary

Keep open: current main and v2026.6.11 still choose `agents.list[].default` or the first listed agent before falling back to implicit `main`, so a single ACP agent can still become the default for unmatched traffic. The related open PRs cover adjacent explicit-main binding and hardcoded-main paths, but not this first-entry default-displacement policy.

## What This Changes

The issue asks OpenClaw to warn, preserve `main`, or require an explicit default when populating `agents.list` would silently displace the implicit main agent.

## Best Possible Solution

Adopt a maintainer-approved transition path that makes the default-agent change explicit at config-write/setup time, preserves or migrates existing `main` continuity when appropriate, and documents the chosen compatibility rule with focused routing and config tests.

Rationale: The viable fixes intentionally change documented routing semantics, warning behavior, or config-write UX, and automation should not choose that product/security contract without maintainer intent.

Likely owner: steipete

Owner confidence: high

Options:

- **Gate config writes with explicit default (recommended):** Keep the runtime parser compatible, but make CLI/UI/doctor flows prompt or fail when a first non-empty `agents.list` has no `default: true` and existing `main` state would be displaced.
- **Warn only:** Preserve first-entry fallback everywhere and add a high-visibility warning plus docs/doctor guidance for users adding their first listed agent.
- **Auto-preserve main:** Materialize `main` as the default when `main` state exists, protecting continuity but changing the meaning of first-entry-only configs.

## Reproduction Assessment

Yes. Source inspection shows a non-empty `agents.list` without `default: true` resolves the first entry as the default, and unmatched route fallback uses that agent; I did not run a live gateway because this review is read-only.

## Solution Assessment

Unclear until maintainers choose the policy. Warning, auto-preserving `main`, and requiring an explicit default each solve the foot-gun differently and carry different compatibility/security tradeoffs.
