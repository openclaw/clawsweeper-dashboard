## Label Justifications

- `P1`: Silent default-agent displacement can reroute live channel, heartbeat, and cron traffic away from the user's expected primary agent.
- `impact:session-state`: Changing the fallback agent changes agent-scoped session keys and can strand existing main-agent history, memory, and auth state.
- `impact:security`: Unmatched traffic can be delivered into an unintended ACP runtime or workspace with different tools, auth, and sandbox policy.
- `impact:message-loss`: Channel traffic without a matching binding can be delivered to a different agent than the user intended after adding one ACP agent.

## Summary

Keep open: current main and v2026.6.11 still route unmatched traffic to agents.list[].default or the first listed agent, so adding one ACP agent can still displace the implicit main agent. The related open PRs improve adjacent default-agent or explicit-main-binding paths, but none replaces this default-selection policy issue.

## What This Changes

The issue asks OpenClaw to prevent or warn about a single ACP entry in agents.list becoming the default route for unrelated traffic that previously used the implicit main agent.

## Best Possible Solution

Choose the default-routing compatibility policy, then apply it consistently across config writes, doctor guidance, routing behavior or warnings, docs, and focused regression coverage.

## Reproduction Assessment

Yes, source-level: current main still selects the first agents.list entry as the default when no default=true entry exists, and unmatched routing uses that value. I did not run a live gateway because this review is read-only.

## Solution Assessment

Unclear as a final implementation: warning, auto-preserving main, and requiring an explicit default each change documented routing semantics differently. The right fix needs a maintainer compatibility choice before code is changed.
