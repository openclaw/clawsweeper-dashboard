## Label Justifications

- `P1`: Silent default-agent displacement can reroute live channel, heartbeat, and scheduled traffic away from the user's expected primary agent.
- `impact:session-state`: Changing the fallback agent changes agent-scoped session keys and can strand existing `main` history, memory, and auth state.
- `impact:security`: Unmatched traffic can be delivered into an unintended ACP runtime or workspace with different tools, credentials, and sandbox policy.
- `impact:message-loss`: Channel traffic without a matching binding can be delivered to a different agent than the user intended after adding one ACP agent.
- `maturity:stable`: The issue affects Gateway runtime routing/delivery behavior, and the scorecard marks Gateway runtime as M4 Stable.

## Summary

Keep open: current main and the latest release still use `agents.list[].default` or the first listed agent as the unmatched-route fallback, and there is no merged maintainer-approved policy for warning, preserving implicit `main`, or requiring an explicit default when adding the first listed ACP agent.

## What This Changes

The issue requests a safer default-agent transition when adding an ACP agent to `agents.list` so unmatched traffic and existing `main` session continuity are not silently displaced.

## Best Possible Solution

Adopt a maintainer-approved transition that makes default-agent changes explicit in config/setup/doctor flows, preserves existing `main` continuity when appropriate, and documents the chosen compatibility rule with focused routing and session tests.

Options:

- **Gate With Explicit Default (recommended):** Keep runtime parsing compatible, but make config/setup/doctor flows warn or fail when a first non-empty `agents.list` has no explicit default and existing `main` state would be displaced.

- **Auto-Preserve Main:** Materialize or promote `main` as default when `main` state exists, protecting continuity while changing first-entry-only config meaning.

Yes, source-level. Current main resolves a non-empty `agents.list` without `default: true` to the first entry, and unmatched route fallback uses that agent; I did not run a live gateway because this cleanup review is read-only.

## Solution Assessment

Unclear until maintainers choose the policy. Warning, auto-preserving `main`, and requiring an explicit default each solve the foot-gun differently and carry different compatibility and security tradeoffs.
