## Label Justifications

- `P1`: Silent default-agent displacement can reroute live channel, heartbeat, and cron traffic away from the user's expected primary agent.
- `impact:session-state`: Changing the fallback agent changes agent-scoped session keys and can strand existing `main` history, memory, and auth state.
- `impact:security`: Unmatched traffic can be delivered into an unintended ACP runtime or workspace with different tools, auth, and sandbox policy.
- `impact:message-loss`: Channel traffic without a matching binding can be delivered to a different agent than the user intended after adding one ACP agent.

## Summary

Keep open: current main and the latest release still route unmatched traffic to `agents.list[].default` or the first listed agent, so adding one ACP agent can still displace the implicit `main` agent. The related open PRs address adjacent default-agent or explicit-main-binding paths but do not resolve this default-selection policy issue.

## What This Changes

The issue asks OpenClaw to warn, preserve `main`, or require an explicit default when `agents.list` is first populated so a bound ACP agent cannot silently become the fallback agent for all traffic.

## Best Possible Solution

Maintainers should choose a compatibility-safe default-agent policy, then update config-write or doctor diagnostics, routing docs, and regression coverage so adding a bound ACP agent cannot silently change the fallback agent without an explicit user decision.

Rationale: The source reproduces the foot-gun, but the available fixes change documented routing semantics, operator warnings, or config-write behavior in different ways.

Likely owner: steipete

Owner confidence: medium

Options:

- **Gate new list writes on explicit default (recommended):** Keep the current runtime fallback for compatibility, but make config-writing/setup/doctor paths warn or refuse first-time non-main `agents.list` writes unless `default: true` or explicit `main` is present.
- **Auto-preserve implicit main:** When OpenClaw writes the first non-main agent entry and `main` state exists, add `main` as the explicit default to preserve existing sessions by default.
- **Change runtime fallback semantics:** Require an explicit default for populated `agents.list` at runtime, accepting a broader compatibility break for stronger fail-closed behavior.

## Reproduction Assessment

Yes, source-level: a non-empty `agents.list` with no `default: true` resolves the first entry as the default, and unmatched route fallback uses that agent. I did not run a live gateway because this review is read-only.

## Solution Assessment

Unclear as a final implementation: warning, auto-preserving `main`, and requiring an explicit default each change documented routing semantics differently. The right fix needs a maintainer compatibility and security decision before code is changed.
