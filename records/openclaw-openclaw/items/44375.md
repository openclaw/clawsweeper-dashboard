## Label Justifications

- `P1`: The issue affects real routing for DMs, topic sessions, heartbeats, and crons and can silently move active users to the wrong agent.
- `impact:session-state`: Changing the default agent rekeys sessions and can orphan the user's existing `main` history and memory index.
- `impact:security`: Misrouted unmatched traffic can expose messages to an unintended agent identity or workspace.
- `impact:message-loss`: Unmatched channel traffic can be delivered to the wrong agent instead of the intended implicit main agent.

## Summary

Keep open: current main still resolves a non-empty `agents.list` with no `default: true` to the first listed agent, and unmatched routes still use that resolved default. The related open PRs address adjacent explicit-main and hardcoded-main paths, but they do not settle this default-selection policy.

## What This Changes

The issue requests that adding a non-main ACP agent to `agents.list` should not silently make it the default for all unmatched traffic, or should at least warn/require an explicit default.

## Best Possible Solution

Maintainers should decide the default-agent contract, then implement a bounded change that preserves explicit non-main defaults while adding an operator-visible warning, doctor check/fix, or explicit-default requirement for first-time `agents.list` population without `main` or `default: true`.

Rationale: The behavior is source-reproducible and security-sensitive, but every suggested fix changes config/default routing semantics for existing users.

Owner confidence: medium

Options:

- **Warn and doctor-repair implicit-main displacement (recommended):** Keep first-entry fallback for compatibility, but add config/doctor/operator warnings and a guided fix when `agents.list` has no explicit default and existing `main` state is present.
- **Require explicit defaults:** Make non-empty `agents.list` without one `default: true` invalid or fail-closed, which is clearer but may break existing configs on upgrade.
- **Keep current behavior documented only:** Treat first-entry fallback as intentional and document the explicit `main` workaround without code changes, accepting the current foot-gun.

## Reproduction Assessment

Yes, by source inspection: a config with a single non-main `agents.list` entry and no `default: true` still resolves that entry as the default, and unmatched routes use that default. I did not run a live gateway repro in this read-only review.

## Solution Assessment

Unclear: warning/doctor repair looks like the safest compatible direction, but the exact policy needs maintainer intent because requiring explicit defaults or auto-adding `main` changes the shipped config contract.
