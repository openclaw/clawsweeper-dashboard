- `P1`: Silent default-agent displacement can reroute live channel, heartbeat, and cron traffic away from the user's expected primary agent.
- `impact:session-state`: Changing the fallback agent changes agent-scoped session keys and can strand existing `main` history, memory, and auth state.
- `impact:security`: Unmatched traffic can be delivered into an unintended ACP runtime or workspace with different tools, credentials, and sandbox policy.

- `maturity:stable`: The issue affects Gateway runtime/session routing, and the scorecard marks Gateway runtime as M4 Stable.

## Summary

Keep open: current main and v2026.6.11 still resolve a non-empty `agents.list` to `default: true` or the first listed agent, then use that result for unmatched routing. The related open PRs cover adjacent explicit-main/default-agent consistency work, but none has merged a maintainer-approved policy for warning, preserving, or requiring an explicit default when implicit `main` would be displaced.

## What This Changes

The issue requests safer behavior when adding an ACP agent to `agents.list` would silently move fallback routing and session continuity away from implicit `main`.

## Best Possible Solution

Adopt a maintainer-approved transition that makes default-agent changes explicit in config/setup/doctor flows, preserves existing `main` continuity when appropriate, and documents the chosen compatibility rule with focused routing and session tests.
