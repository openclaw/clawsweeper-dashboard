## Label Justifications

- `P1`: Silent default-agent displacement can reroute live channel, heartbeat, and cron traffic away from the user's expected primary agent.
- `impact:security`: Unmatched traffic can be delivered into an unintended ACP runtime or workspace with different tools, credentials, and sandbox policy.
- `impact:message-loss`: Messages without a matching binding can be delivered to a different agent than the user intended after adding one ACP agent.
- `impact:session-state`: Changing the fallback agent changes agent-scoped session keys and can strand existing `main` history and memory state.

## Summary

Keep open: current main and v2026.6.11 still resolve a non-empty `agents.list` without `default: true` to the first listed agent, and unmatched routing uses that resolved default. This is a valid source-reproducible routing and security foot-gun, but the repair changes documented default-agent policy and needs maintainer direction.

## What This Changes

The issue requests warning, preservation, or explicit-default behavior so adding a single ACP agent to `agents.list` does not silently displace the implicit `main` agent for all unmatched traffic.

## Best Possible Solution

Adopt a maintainer-approved transition that makes default-agent displacement explicit at config-write/setup time, preserves existing `main` continuity when appropriate, and documents the chosen compatibility rule with focused routing and config tests.

Owner confidence: high

Options:

- **Gate config writes with explicit default (recommended):** Keep runtime parsing compatible, but make CLI/UI/doctor flows prompt or fail when a first non-empty `agents.list` has no `default: true` and existing `main` state would be displaced.
- **Warn only:** Preserve first-entry fallback everywhere and add high-visibility warning plus docs/doctor guidance for users adding their first listed agent.
- **Auto-preserve main:** Materialize `main` as the default when `main` state exists, protecting continuity while changing the meaning of first-entry-only configs.

## Reproduction Assessment

Yes. Source inspection shows a non-empty `agents.list` without `default: true` resolves the first entry as the default, and unmatched route fallback uses that agent; this review did not run a live gateway because it is read-only.

## Solution Assessment

Unclear until maintainers choose the policy. Warning, auto-preserving `main`, and requiring an explicit default each solve the foot-gun differently and carry different compatibility/security tradeoffs.
