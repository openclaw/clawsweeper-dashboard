## Label Justifications

- `P1`: Silent default-agent displacement can reroute live channel, heartbeat, and cron traffic away from the user's expected primary agent.
- `impact:session-state`: Changing the fallback agent changes agent-scoped session keys and can strand existing `main` history, memory, and auth state.
- `impact:security`: Unmatched traffic can be delivered into an unintended ACP runtime or workspace with different tools, credentials, and sandbox policy.
- `impact:message-loss`: Channel traffic without a matching binding can be delivered to a different agent than the user intended after adding one ACP agent.

## Summary

Keep open: current main and the latest release still choose `agents.list[].default` or the first listed agent before falling back to implicit `main`, so the reported default-agent displacement remains source-reproducible. The related open PRs are adjacent default-agent/binding fixes, not merged implementations of this first-entry fallback policy change.

## What This Changes

The issue requests a guardrail so adding an ACP-backed agent to `agents.list` for one binding does not silently make that agent the fallback default for all unmatched traffic.

## Best Possible Solution

Adopt a maintainer-approved transition path that makes default-agent changes explicit at config-write/setup time, preserves or migrates existing `main` continuity when appropriate, and documents the chosen compatibility rule with focused routing and config tests.

Owner confidence: high

Options:

- **Gate with explicit default (recommended):** Keep runtime parsing compatible, but make CLI/UI/doctor flows prompt or fail when a first non-empty `agents.list` has no `default: true` and existing `main` state would be displaced.
- **Warn only:** Preserve first-entry fallback everywhere and add high-visibility warning plus docs/doctor guidance for users adding their first listed agent.
- **Auto-preserve main:** Materialize `main` as the default when `main` state exists, protecting continuity but changing first-entry-only config meaning.

## Reproduction Assessment

Yes. Source inspection shows a non-empty `agents.list` without `default: true` resolves the first entry as the default, and unmatched route fallback uses that agent; I did not run a live gateway because this review is read-only.

## Solution Assessment

Unclear until maintainers choose the policy. Warning, auto-preserving `main`, and requiring an explicit default each solve the foot-gun differently and carry different compatibility/security tradeoffs.
