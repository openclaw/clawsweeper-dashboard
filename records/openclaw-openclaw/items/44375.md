## Label Justifications

- `P1`: The issue is source-reproducible and can silently reroute active channel traffic and automation to the wrong agent in real multi-agent setups.
- `impact:security`: Fallback routing can send private or operator-intended traffic to a newly configured ACP agent with a different workspace/runtime boundary.
- `impact:message-loss`: Unmatched DMs, topics, heartbeats, and cron traffic can be misrouted from the expected implicit `main` agent to the first listed agent.
- `impact:session-state`: The behavior rekeys conversations from `agent:main:*` to the new default agent and strands existing session and memory continuity.

## Summary

Keep open: current main and the latest release still make the first `agents.list` entry the default when no entry has `default: true`, so the reported implicit-`main` displacement remains. The related open PRs address adjacent explicit-main/default-agent consistency, but no merged fix has made the product decision for this foot-gun.

## What This Changes

The issue requests that adding an ACP or named agent to `agents.list` not silently replace implicit `main` as the default route for all unmatched traffic, or at least warn/require an explicit default.

## Best Possible Solution

Choose and implement a compatibility-safe default-agent policy that preserves existing explicit defaults, gives users a clear warning or migration path, and makes the `main` fallback/ACP binding story consistent across schema, doctor, routing, docs, and tests.
