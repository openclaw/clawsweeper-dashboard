## Summary

Keep open: current `main` and the latest release still route the iOS auth-step Retry Connection action through the saved last-known connection path, while the linked fixing PR is open and unmerged.

## What This Changes

The issue reports that iOS onboarding Retry Connection on the authentication step ignores edited manual host/token/password fields and can perform no retry at all.

## Best Possible Solution

Review and land the linked narrow fix, or an equivalent change, so manual auth-step retries use the current form input while discovered-gateway retries keep their saved-connection semantics.

## Reproduction Assessment

Yes. Source inspection shows Retry Connection calls `retryLastAttempt()`, which calls `connectLastKnown()` instead of the current manual token/password path; I did not run the simulator flow.

## Solution Assessment

Yes. The best fix is the narrow owner-boundary change: reuse the current manual connection/auth input path for manual auth-step retries and preserve saved/discovered retry behavior elsewhere.
