## Summary

Keep open: current main and v2026.6.11 still route iOS auth-step Retry Connection through the saved last-known connection path, while an open linked PR owns the proposed fix and should resolve the issue after review or merge.

## What This Changes

The issue reports that iOS onboarding Retry Connection on the auth step does not retry with edited gateway token, host, port, or TLS values.

## Best Possible Solution

Keep this issue open as the canonical report and resolve it by reviewing, landing, revising, or closing https://github.com/openclaw/openclaw/pull/99220.

## Reproduction Assessment

Yes from source: Retry Connection reaches retryLastAttempt(), which calls connectLastKnown() instead of the current manual token/password path. I did not run an iOS simulator reproduction in this read-only review, but the reporter and linked PR provide gateway-log evidence.

## Solution Assessment

Yes. The narrow maintainable fix is to send manual auth-step retries through the same current-field connectManual() path as Connect while preserving discovered-gateway saved reconnect behavior.
