The patch follows the existing rule that local coordination failures should abort model fallback and has no discrete code defect from the reviewed diff, but an external PR still needs redacted after-fix evidence from a real missing-image/provisioning run before merge, plus sandbox-owner review for the intentional compatibility change. Likely related people: steipete (high confidence) has the strongest current-main history on the sandbox context boundary.

## What This Changes

Wrap sandbox backend startup failures in a typed local provisioning error so model fallback stops after one failed sandbox attempt while explicit provider failures still use model fallback.

## System Context

A sandboxed agent resolves a workspace and starts its selected sandbox backend before executing a model attempt. Errors from that setup currently enter the model-fallback classifier; this PR identifies local provisioning failures so the run reports the backend error instead of retrying every configured model.

  E --> F[Fallback classifier]

  D --> H[Provider failure may use fallback]

## Best Possible Solution

Land a sandbox-owned typed provisioning boundary only after a real missing-image/backend-startup run shows one failed attempt with no fallback diagnostics and the sandbox owner accepts the intentional local-error fallback policy.
