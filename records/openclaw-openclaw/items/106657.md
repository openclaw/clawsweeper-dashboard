## Summary

This PR remains necessary: it targets the open sandbox fallback bug tracked at https://github.com/openclaw/openclaw/issues/106516, includes focused regression coverage and real Docker proof, and should stay open for sandbox code-owner confirmation of the error-classification boundary before merge.

## What This Changes

The branch wraps sandbox backend startup failures in a typed provisioning error so model fallback stops after one local sandbox failure while genuine provider failures can still use configured fallback models.

## System Context

Agent runs resolve a sandbox backend before executing a model attempt. Errors then reach the shared model-fallback classifier, which decides whether to try another configured model or surface the local runtime failure to the parent agent.

## Architecture Diagram

flowchart LR
  A[Agent run request] --> B[Sandbox backend setup]
  B --> C{Backend starts?}
  C -->|No| D[Typed provisioning error]
  D --> E[Fallback error classifier]
  C -->|Yes| F[Model attempt]
  F --> E
  E -->|Local provisioning| G[Stop and report actionable error]
  E -->|Provider failure| H[Try configured fallback]

## Best Possible Solution

Keep the typed error at the sandbox backend-creation boundary, retain the provider-precedence regression test, and land only after the sandbox code owner confirms that backend construction is always local provisioning rather than a provider attempt.
