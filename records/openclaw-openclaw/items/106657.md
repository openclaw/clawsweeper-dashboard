## Summary

This PR is still necessary: current main does not distinguish sandbox backend startup failures from model failures, while the linked report shows that the existing path retries the same local failure across every model candidate. The typed error and non-provider classification are a focused fit for the established failover boundary, with no concrete correctness or security defect found; merge should wait for after-fix live sandbox proof and successful exact-head checks.

## What This Changes

The PR adds a typed sandbox provisioning error, short-circuits model fallback for that error, and adds regression coverage for fallback accounting, provider precedence, and parent-visible failure output.

## Best Possible Solution

Keep the typed error at the sandbox backend startup boundary and the generic non-provider stop rule in model fallback, then land it after a real missing-image run proves one attempt, zero fallback transitions, and clear child-to-parent error propagation.
