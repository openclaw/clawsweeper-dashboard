## Label Justifications

- `P1`: The reported initialization conflict can suppress a dashboard reply during ordinary model switching, although the shipped fix removes the known race.
- `impact:message-loss`: The conflict occurs during reply initialization and can prevent the user's turn from receiving a response.
- `impact:session-state`: The report concerns unintended session identity rotation and competing updates to persisted model/session state.

## Summary

Current OpenClaw already keeps dashboard model choices as persistent overrides on the active session, and the reported false initialization-conflict race from version 2026.6.11 was fixed and shipped in v2026.7.1.

## What This Changes

Preserve one dashboard conversation session while changing its active model instead of creating a new session identity for each model selection.

## Best Possible Solution

Keep the current active-session override design and direct users reproducing the old race to upgrade to v2026.7.1 or later rather than adding transcript-stitching or a second continuity layer.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes for the reported 2026.6.11 source path: changing same-session metadata during guarded reply initialization could invalidate the full-row revision and produce the conflict. The merged regression test demonstrates that race and the fixed result.

## Solution Assessment

Yes. Keeping model selection as an override on the existing session and fixing false conflict detection at the shared session-accessor boundary is narrower and more maintainable than stitching multiple transcripts afterward.
