## Summary

This PR should remain open but is not merge-ready: it misidentifies `agentMeta.contextTokens` as usage data, although embedded runs populate that field from the active model’s context budget, so the reported missing-usage path can still persist the same model-window value.

## What This Changes

The PR removes the model-catalog fallback in the post-run session updater and only passes `agentMeta.contextTokens` when updating the persisted `contextTokens` field.

## Best Possible Solution

Keep the active model context budget as a distinct denominator, gate consumed-token updates and warnings on fresh `totalTokens` or prompt-estimate provenance, and add regression coverage for missing usage plus model changes so stale data cannot render a false full-context state.
