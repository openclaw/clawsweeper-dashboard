## Summary

Keep this PR open for revision: the reported false usage display is valid, but the patch removes established context-budget persistence instead of correcting the boundary between the model budget and fresh token usage. Current tests and documentation explicitly define `contextTokens` as the denominator or context window while `totalTokens` is usage, so removing configured and prepared budget fallbacks would regress new sessions and CLI-backed providers.

## What This Changes

The PR stops resolving and persisting configured model context budgets when agent runtime metadata lacks `contextTokens`, preserving an existing session value instead.

## Best Possible Solution

Keep `contextTokens` as the resolved model context budget, keep `totalTokens` as observed usage, and make status/UI consumers honor usage freshness so an absent or stale usage snapshot renders unknown rather than treating the budget as tokens consumed.
