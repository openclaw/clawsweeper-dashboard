## Summary

Keep open: current main and the latest release still use a hard-coded `A-Z_` prefix guard, while the helper API and adjacent tests support custom silent tokens elsewhere, so the reported streaming-prefix inconsistency remains real and narrow.

## What This Changes

The issue reports that streamed silent-token prefix suppression fails for custom silent tokens containing digits or punctuation because `isSilentReplyPrefixText` only allows `A-Z_`.

## Best Possible Solution

Update `isSilentReplyPrefixText` so allowed prefix characters are derived from the configured token while preserving the existing natural-language and generic-token false-positive guards, then add focused regression tests for digit and punctuation custom tokens.

## Reproduction Assessment

Yes, from source inspection: a focused unit case such as `isSilentReplyPrefixText("NOREPLY2", "NOREPLY2")` or `isSilentReplyPrefixText("NO-ANSWER", "NO-ANSWER")` would hit the current `[^A-Z_]` guard and return false before token matching. I did not run a repository test because this review is read-only and dependencies for test execution are absent.

## Solution Assessment

Yes, the narrowest maintainable fix is in `src/auto-reply/tokens.ts`; the streaming and typing call sites already pass the configured token through, so channel-specific rewrites or new configuration would be the wrong layer.
