## Summary

This PR addresses a real current-main scheduling defect, but the fan-out path still advances the agent schedule before subsequent commitment-only runs finish, so a slow commitment run can again leave `nextDueMs` in the past and immediately re-arm the timer; the posted arithmetic output also does not prove the patched runner in a real Gateway.

## What This Changes

The PR changes four post-run heartbeat schedule advances to use completion-time timestamps and adds a fake-clock regression test for a run crossing a cadence phase boundary.

## Best Possible Solution

Keep start-time bookkeeping for cooldown semantics, but compute each agent's next schedule only after all non-retryable heartbeat work for that dispatch—including commitment-only runs—has completed, with regression coverage for both primary and commitment-run delays.
