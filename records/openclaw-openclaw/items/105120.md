The PR changes four post-`runOnce` heartbeat schedule advances to use completion-time timestamps and adds a fake-clock regression test covering a run that crosses a cadence phase boundary.

## Best Possible Solution

Land the completion-time scheduling change after a real gateway run or instrumented runner execution shows a delayed heartbeat completing and the next due time remaining in the future without an immediate refire.
