## Summary

Close as ClawHub scope: a Podman sandbox backend is useful, but it is a backend-specific code plugin and current main already exposes the sandbox backend SDK plus an external sandbox-backend pattern, while VISION.md directs optional plugins out of core when existing seams suffice.

## What This Changes

The issue requests a first-class Podman agent sandbox backend, including plugin registration, Podman-specific config, lifecycle management, docs, and safety checks for rootless Podman sandboxes.

## Best Possible Solution

Publish a Podman sandbox backend as a ClawHub code plugin with a manifest, typed config schema, entrypoint, sandbox backend factory, lifecycle manager, install docs, and redacted live Podman smoke proof; only bring a narrow generic SDK or policy-observability gap back to core if the plugin cannot express it.
