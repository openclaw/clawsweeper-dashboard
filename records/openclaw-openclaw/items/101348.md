## Summary

Close as ClawHub/plugin scope: current main and the shipped sandbox SDK already provide the generic backend registration seam, no Podman-specific core API gap is demonstrated, and VISION.md directs optional runtime integrations to external plugins and ClawHub rather than bundled core.

## What This Changes

The issue requests a first-class Podman agent sandbox backend, preferably as a bundled plugin with Podman-owned configuration, lifecycle management, docs, and live smoke proof.

## Best Possible Solution

Publish and maintain the Podman sandbox backend as an external npm/ClawHub code plugin using `openclaw/plugin-sdk/sandbox`; open a narrow core issue only if that implementation proves a generic SDK, loader, or lifecycle gap.
