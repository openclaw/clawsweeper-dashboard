## Summary

Keep open: the user-visible `/compact` label bug is still present on current `main`, but the submitted branch is not safe to merge because it mixes context-window capacity into live usage token accounting and adds an overly broad JSONL byte-estimate fallback.

## What This Changes

The PR changes manual `/compact` reply formatting, forwards a token count into manual compaction, and adds a JSONL file-size fallback for displayed context usage.

## Best Possible Solution

Port the non-decreasing `/compact` label guard onto current `main` while keeping context budget and observed usage token accounting separate; add any stale-total fallback only behind a narrow tested contract.

## Reproduction Assessment

Yes, source-level: current `main` and the latest release still format `tokensBefore -> tokensAfter` whenever both fields are non-null, so a compact result like `0 -> 36` remains reproducible from the formatter branch without a live channel.

## Solution Assessment

No, not as submitted. The formatter guard is the right narrow fix, but forwarding context-window values as live usage and letting JSONL byte estimates override fresh totals is not the safest implementation path.
