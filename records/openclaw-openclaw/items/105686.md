## Label Justifications

- `P3`: The issue proposes a speculative authentication policy change without reproducing broken documented behavior.
- `impact:auth-provider`: The request would change provider credential eligibility, selection, and fallback behavior.

## Summary

Current main intentionally treats plain token credentials as usable until exact expiry, while refreshable OAuth credentials use a five-minute refresh margin. The report does not reproduce a violation of that contract, and the suggested one-minute check targets discovery rather than the shared runtime eligibility owner, so changing behavior requires an explicit auth-policy decision.

## What This Changes

Change token credential eligibility so credentials nearing expiration are rejected before agent execution.

## Best Possible Solution

Keep exact-expiry semantics unless auth owners intentionally define a shared early-expiry contract across runtime selection, discovery, probes, doctor, ordering, fallback, tests, and documentation; provider-aware minimum lifetime is preferable if only specific token contracts require it.

Rationale: Current code and canonical documentation deliberately distinguish plain token eligibility from refreshable OAuth timing, so early rejection changes a cross-path authentication and fallback contract.

Options:

- **Keep Exact Expiry (recommended):** Retain the current contract and use refreshable OAuth credentials when uninterrupted long-running operations require proactive refresh.
- **Add Shared Margin:** Define one global early-expiry rule and update every credential consumer, diagnostic surface, fallback path, test, and document consistently.
- **Use Provider Policy:** Allow provider-owned auth behavior to request a minimum remaining lifetime only where its token semantics justify early rejection.

## Reproduction Assessment

No. A token with one second remaining is accepted on current main, but that matches the documented contract, and the issue provides no provider-specific run or failing test showing the claimed downstream authorization failure.

## Solution Assessment

No. The proposed one-minute predicate is placed in a discovery converter rather than the shared eligibility owner and cannot represent variable operation duration or provider-specific token behavior.
