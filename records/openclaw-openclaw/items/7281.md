## Summary

Keep open: current main and the latest release still model hook mapping delivery as one channel/target, so the requested post-failure fallback chain remains unimplemented and still needs a maintainer product decision.

## What This Changes

The issue requests a new `fallbackChannel` or ordered `fallbackChannels` hook-mapping option so hook-generated delivery can try another channel after the primary channel send fails.

## Best Possible Solution

Define a typed hook delivery fallback policy and carry it through hook config/schema/help, mapping transforms, dispatch payloads, cron delivery, outbound failure handling, docs, and focused failover tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should hook mappings support automatic post-failure fallback delivery, and if so should the public contract be an ordered `fallbackChannels` chain, reuse cron `failureDestination`, or keep hooks single-target?

Rationale: The request adds public config and cross-channel delivery semantics; repository policy treats config/fallback additions as compatibility- and product-sensitive, and current code has several adjacent but different recovery mechanisms.

Likely owner: steipete

Owner reason: steipete has the strongest current hook-surface review signal and current-line ownership evidence for the product/config decision.

Owner confidence: high

Options:

- **Add Ordered Hook Fallbacks (recommended):** Add a typed ordered fallback list for hook mappings and attempt alternates only after a real primary delivery failure, with privacy/allowlist behavior and all-targets-failed reporting documented and tested.
- **Reuse Failure Destinations:** Model hook failover through the existing cron failure-destination concept if maintainers want one shared failure-routing abstraction rather than a new hook-specific field.
- **Keep Hooks Single-Target:** Keep hook mappings single-target and document `channel: "last"`, `bestEffort`, and failure notifications as the supported recovery surfaces.

## Reproduction Assessment

Yes, by source inspection rather than a live run. The requested fallback keys are absent from hook mapping types and rejected by strict schema, while hook dispatch and cron direct delivery carry one target.

## Solution Assessment

Unclear until maintainers choose the product contract. A fallback chain is plausible, but the best fix must settle ordered failover, `failureDestination` interaction, privacy/allowlist behavior, and failure reporting first.
