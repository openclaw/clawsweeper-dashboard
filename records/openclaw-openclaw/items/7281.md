## Summary

Keep open: current main and v2026.6.11 still model hook mapping delivery as one channel/target, so the requested post-failure fallback chain remains unimplemented and needs a maintainer product decision.

## What This Changes

The issue requests a `fallbackChannel` or ordered `fallbackChannels` hook-mapping option that retries alternate delivery channels after the primary `deliver: true` channel fails.

## Best Possible Solution

Define a typed hook delivery fallback policy and carry it through hook config/schema/help, mapping transforms, dispatch payloads, cron delivery, outbound failure handling, docs, and focused failover tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should hook mappings support automatic post-failure fallback delivery, and should the public contract be an ordered `fallbackChannels` chain, reuse cron failure destinations, or keep hooks single-target?

Rationale: This adds public config and cross-channel delivery semantics; repository policy treats fallback/config additions as compatibility- and product-sensitive, and current code already has adjacent recovery mechanisms with different meanings.

Likely owner: steipete

Owner reason: steipete has the strongest current issue-review signal and recent hook/config surface history.

Owner confidence: high

Options:

- **Add Ordered Hook Fallbacks (recommended):** Add a typed ordered fallback list for hook mappings and attempt alternates only after a real primary delivery failure, with privacy, allowlist, and all-targets-failed behavior documented and tested.
- **Reuse Failure Destinations:** Model hook failover through the existing cron failure-destination concept if maintainers want one shared failure-routing abstraction instead of a hook-specific field.
- **Keep Hooks Single-Target:** Keep hook mappings single-target and document `channel: "last"`, `bestEffort`, and failure notifications as the supported recovery surfaces.

## Reproduction Assessment

Yes, by source inspection rather than a live run. The requested fallback keys are absent from hook mapping types and rejected by strict schema, while hook dispatch and cron direct delivery carry one target.

## Solution Assessment

Unclear until maintainers choose the product contract. A fallback chain is plausible, but the best fix must settle ordered failover, `failureDestination` interaction, privacy/allowlist behavior, and failure reporting first.
