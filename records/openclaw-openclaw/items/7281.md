## Summary

Keep open: current main and the latest release still model hook delivery as one channel/target, so the requested post-failure fallback chain remains unimplemented and needs maintainer product direction.

## What This Changes

The issue requests configurable hook delivery fallback channels for hook mappings when the primary mapped delivery channel fails.

## Best Possible Solution

Define a typed hook fallback delivery policy, then carry it through hook config/schema, mapping resolution, dispatch payloads, CronDelivery, outbound delivery, docs, and regression tests without relying on selection-time fallback helpers.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should hook mappings support automatic post-failure fallback delivery, and if yes should the public config be an ordered fallbackChannels chain, reuse cron failureDestination, or avoid cross-channel failover?

Rationale: This adds public config and cross-channel delivery semantics, and repository policy treats fallback/config additions as product- and compatibility-sensitive.

Likely owner: steipete

Owner reason: steipete has both the hook mapping introduction history and prior review context on this exact issue.

Owner confidence: high

Options:

- **Add ordered fallbackChannels (recommended):** Add a typed ordered fallback list for hook mappings and attempt alternates only after a real primary delivery failure, with explicit docs and tests for all-targets-failed behavior.
- **Reuse cron failureDestination:** Route hook delivery through an existing failure-destination concept if maintainers want one shared failure-notification model instead of hook-specific failover.
- **Do not add cross-channel failover:** Keep hook mappings single-target and document failureDestination, bestEffort, and channel health as the supported recovery paths.

## Reproduction Assessment

Yes, by source inspection: the proposed fallback keys are absent from HookMappingConfig and rejected by strict schema, while dispatch creates one delivery target. I did not run a live disconnected-channel scenario because the missing config path is already source-reproducible.

## Solution Assessment

Unclear until maintainers choose the product contract. A fallback chain is plausible, but the best fix must settle ordered failover, failureDestination interaction, privacy/allowlist behavior, and failure reporting before implementation.
