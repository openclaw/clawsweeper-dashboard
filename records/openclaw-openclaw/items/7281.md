## Summary

Keep open: current main still has no hook-mapping `fallbackChannel` or `fallbackChannels` contract, and the existing fallback/failure-destination code covers adjacent pre-delivery selection or cron failure notification, not post-failure hook delivery failover.

## What This Changes

The issue requests a new hook mapping fallback delivery option so `deliver: true` hooks can try another channel after the configured primary channel fails.

## Best Possible Solution

Define a maintainer-approved typed hook fallback policy and carry it through hook config/schema, mapping transforms, hook dispatch, cron delivery, outbound failure handling, docs, and focused failover tests.
