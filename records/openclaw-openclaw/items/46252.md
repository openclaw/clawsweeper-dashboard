## Summary

Keep open: current main and the latest release include reset/deleted archives in the global aggregate, but per-session detail, cache, time-series, and log paths still resolve one active transcript and omit same-stem archives; the linked open PR remains the fix path.

## What This Changes

The issue asks for cost dashboard and `sessions.usage` accounting to include reset/deleted archived transcript lineage instead of counting only the active `.jsonl` file.

## Best Possible Solution

Land or replace the linked backend lineage fix so per-session summary, cache, time-series, and logs aggregate active plus reset/deleted same-stem transcripts while preserving `.bak` and checkpoint exclusion; split broader archive shapes into a separate tracked item if needed.

## Reproduction Assessment

Yes, at source level: current main resolves an active `<id>.jsonl` immediately and then scans only that single file for per-session summary, time-series, logs, and cache reads. An active transcript plus same-stem `.jsonl.reset.*` archive therefore reproduces the undercount path without needing a new feature or config option.

## Solution Assessment

Yes for the routing decision: the best fix is in the backend session usage lineage/cache owner path, not in the UI or a new setting. The open linked PR is the current candidate, but it needs refresh or replacement before this issue can close.
