## Summary

Keep open: current main fixed the global reset/deleted archive scan, but the per-session `sessions.usage` detail path still resolves a single transcript, prefers the active `.jsonl` when it exists, and then scans only that file. The remaining work is already owned by the open linked implementation candidate at https://github.com/openclaw/openclaw/pull/92610, which needs review, rebase, landing, or replacement.

## What This Changes

The issue reports that usage/cost views undercount spend after `/new` because reset/deleted JSONL archive transcripts are not included with the active session lineage.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/92610 with a bounded per-session lineage aggregation that merges active plus same-stem reset/deleted usage-counted transcripts for summaries, time series, logs, and cache paths while preserving `.bak` and checkpoint exclusion.
