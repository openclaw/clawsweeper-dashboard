## Label Justifications

- `P2`: This is a normal-priority user-visible usage accounting bug with bounded blast radius to dashboard and session usage reporting.
- `impact:session-state`: The issue mis-associates archived transcript lineage with the visible session usage state shown by the dashboard and sessions.usage APIs.
- `maturity:stable`: The affected Gateway runtime and Gateway RPC usage surface is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main only partially fixes the report. Global usage aggregation is archive-aware, but per-session summary, cache, time-series, and logs still resolve a single active transcript when it exists, and the open closing PR remains the fix candidate.

## What This Changes

The issue reports that usage and cost views undercount spend because reset/deleted archive transcripts created by `/new` or `/reset` are not consistently included with the visible session lineage.

## Best Possible Solution

Land or replace the backend lineage fix so per-session summary, cache, time-series, and logs aggregate active plus reset/deleted same-stem transcripts while preserving bak/checkpoint exclusion.

Yes, at source level. Current main resolves an active `<id>.jsonl` immediately and then scans only that one file for per-session summary, cache-backed summaries, time-series, and logs, so active-plus-reset archive usage is omitted.

## Solution Assessment

Yes for the routing decision. The fix belongs in the backend session usage lineage/cache path rather than the UI or a new setting; the linked PR follows that boundary but must be refreshed or replaced before closure.
