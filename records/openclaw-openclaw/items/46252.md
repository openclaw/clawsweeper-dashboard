## Summary

Keep open: current main and the latest release only partially solve the report. Global usage aggregation is archive-aware, but the per-session summary, cache, time-series, and logs paths still resolve a single active transcript when it exists, and the open linked PR remains the fix candidate.

## What This Changes

Include reset/deleted session archive transcripts in cost and usage reporting so `/new` or reset rotations do not undercount spend.

## Best Possible Solution

Land or replace the linked backend lineage fix so per-session summary, cache, time-series, and logs aggregate active plus reset/deleted same-stem transcripts while preserving bak/checkpoint exclusion; split broader archive-shape recovery into a separate tracked item if needed.

## Reproduction Assessment

Yes. At source level, current main resolves an active <id>.jsonl immediately and then scans only that one file for per-session summary, cache, time-series, and logs, so active-plus-reset archive usage is omitted.

## Solution Assessment

Yes for the routing decision. The fix belongs in the backend session usage lineage/cache path rather than the UI or a new setting; the linked PR follows that boundary but must be refreshed or replaced before closure.
