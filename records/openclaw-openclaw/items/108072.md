## Summary

Keep this PR open for a focused repair: the reported history-loss bug is real and the live proof is strong, but the proposed read loop still calculates its starting offset from the stale pre-open file size, so a sufficiently large compaction can continue to restore an empty history.

## What This Changes

Routes bounded CLI session-tail reads through the shared short-read loop, decodes only returned bytes, and adds stale-size regression coverage.

## Best Possible Solution

Open and stat one file handle, derive the bounded offset from that descriptor's authoritative size, read the header and tail from the same inode, and cover both modest and greater-than-window shrink races without changing the 5 MiB policy or parser semantics.
