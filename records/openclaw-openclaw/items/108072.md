## Label Justifications

- `P2`: This is a bounded but real session-history restoration defect affecting oversized CLI backend transcripts during concurrent rewrites or short reads.

## Summary

Keep this PR open for a narrow correction: decoding only the bytes read fixes ordinary short reads, but the tail offset still comes from the pre-open path stat, so a sufficiently large concurrent compaction can leave the positional read at or beyond EOF and still restore an empty history.

## What This Changes

Uses the shared bounded file-window reader for oversized CLI session transcripts, decodes only returned bytes, and adds shrink-during-read regression coverage.

## Best Possible Solution

Open the transcript first, obtain the authoritative size from that handle, compute the bounded start as `Math.max(0, openedSize - limit)`, retain actual-byte decoding, and cover both modest and greater-than-window shrink races.
