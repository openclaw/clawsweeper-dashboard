## Summary

This PR remains necessary: current `main` still accepts an arbitrary normalized `agentId` in `createGatewaySession` and reaches the session-store creation path without a configured-agent gate. The proposed pre-provision rejection matches the recently merged sibling policy for read/abort session operations, has focused regression coverage, and now includes credible redacted live Gateway RPC proof; no patch defect was found.

## What This Changes

The branch rejects unknown `agentId` values in gateway `sessions.create` before session-store provisioning and adds a regression test that verifies no agent directory, SQLite database, or registry row is created.

## Best Possible Solution

Rebase the focused gate onto current `main` and land it as the final `sessions.*` fail-closed boundary, with explicit agent configuration/creation remaining the only supported provisioning path.
