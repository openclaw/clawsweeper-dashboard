## What This Changes

The issue requests WebChat new sessions to retain or expose bounded recent same-channel conversation context instead of starting without access to the prior session.

## Best Possible Solution

Define a privacy-aware WebChat prior-session recall contract that can recover bounded recent same-user or same-channel context without silently broadening unrelated session transcript access.

## Reproduction Assessment

Yes at source level: current main creates a parent-linked new WebChat session, but session tools default to `tree` and only grant directional owner/spawn access. I did not run the full live WebChat click-plus or timeout flow.

## Solution Assessment

No for a silent visibility widening because that would weaken transcript privacy. The maintainable solution is a bounded, explicit WebChat continuity policy with tests for allowed prior-session recall and unrelated-session denial.
