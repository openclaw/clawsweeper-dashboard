## Summary

Keep open: current main still creates linked WebChat/dashboard child sessions, but model-facing session tools default to directional tree visibility and do not give the new child session automatic access to its parent or recent same-channel transcript. No merged fix or canonical duplicate was found, and the safe repair needs maintainer product/security direction because it changes transcript visibility.

## What This Changes

The issue asks for new WebChat sessions to retain or access recent same-channel conversation context instead of starting blind after plus-click or timeout.

## Best Possible Solution

Define a bounded, privacy-aware WebChat/session-continuity contract that can expose recent parent or same-channel context to the new session without globally widening model-facing session-tool visibility.

## Reproduction Assessment

Yes at source level: current main links new WebChat/dashboard sessions to a parent, while the default tree visibility is directional and blocks parent or recent same-channel history from the child. I did not run a live browser/WebChat repro in this read-only pass.

## Solution Assessment

No, simply broadening session visibility is not the best fix because it would weaken transcript privacy. The better solution is an explicit, bounded same-user or parent-session recall policy with denial tests for unrelated sessions.
