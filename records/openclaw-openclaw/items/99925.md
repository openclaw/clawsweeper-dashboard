## Summary

Keep open: current main and v2026.6.11 still default session tools to tree-scoped visibility, and WebChat-created child sessions only store a parent link without granting the child automatic model-visible access to the parent transcript. The issue is valid enough for maintainer follow-up, but the fix needs a privacy/security product decision rather than a narrow automated patch.

## What This Changes

Request WebChat new sessions to carry or expose recent same-channel conversation context instead of starting with no model-visible prior messages.

## Best Possible Solution

Design an opt-in same-owner or parent-session recall path that gives WebChat new sessions bounded, sanitized recent context while preserving safe `tools.sessions.visibility` defaults and auditable permission boundaries.

## Reproduction Assessment

Yes, at source level for the sessions_list/history visibility portion: current main creates a parent-linked WebChat child session but default tree visibility does not make the parent visible to that child. I did not run a live WebChat model turn to prove the full AI-blind symptom.

## Solution Assessment

Unclear. Changing `tools.sessions.visibility` globally is not the best fix; a bounded same-owner or parent-session recall design with explicit security policy is safer than making prior sessions broadly visible by default.
