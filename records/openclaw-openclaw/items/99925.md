## Summary

Keep open: current main still documents and enforces tree-scoped session tools, and WebChat’s New Chat path creates a linked dashboard session without automatically giving that new session parent or prior same-channel transcript recall. The report is real at the source level, but the right fix needs maintainer product/security direction because widening prior-session visibility can expose transcript context across session boundaries.

## What This Changes

Request WebChat new sessions to retain or safely recover recent same-user/same-channel conversation context, or let session tools read recent related sessions.

## Best Possible Solution

Define a privacy-aware WebChat session-continuity contract that can recover bounded prior same-user or parent-session context without silently broadening unrelated session-tool visibility.

## Reproduction Assessment

Yes at source level for the visibility restriction: current main defaults session tools to tree, New Chat stores parentSessionKey on the new dashboard session, and sessions_history/list still enforce tree-scoped access. I did not run a live WebChat click-plus or timeout scenario.

## Solution Assessment

No for a direct silent visibility widening, because that would be privacy-sensitive and could expose unrelated transcripts. The better solution is a maintainer-approved, bounded WebChat/session-family recall policy or explicit opt-in path with diagnostics.
