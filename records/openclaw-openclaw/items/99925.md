## Summary

Keep open: current main still defaults model-facing session tools to tree-scoped visibility, and that scope is directional from requester to spawned/owned rows, so a new WebChat session still cannot inspect the prior same-channel session by default. The source-level symptom is clear, but the repair needs maintainer direction because broadening transcript visibility is a privacy/security boundary change.

## What This Changes

The issue asks for new WebChat sessions to receive or retrieve recent same-channel conversation context instead of starting blind under default tree-only session visibility.

## Best Possible Solution

Define a bounded same-user, same-channel context bridge or explicit visibility scope that preserves clean-session and transcript privacy expectations, then cover allowed prior-context reads and unrelated-session denies in WebChat and session-tool tests.
