## Summary

Keep open: current main still creates WebChat dashboard sessions with parent linkage but default session-tool tree visibility remains directional, so the new child session does not automatically see or read the prior parent conversation. The remaining fix is privacy-sensitive product work, not conservative cleanup.

## What This Changes

The issue asks for WebChat new sessions to retain or retrieve recent prior same-channel conversation context instead of starting blind under default session-tool tree visibility.

## Best Possible Solution

Define a privacy-aware WebChat session-continuity contract that lets a new dashboard session retrieve bounded parent or family context without broad all-session transcript access.

## Reproduction Assessment

Yes at source level: current main links new WebChat dashboard sessions to a parent, but tree visibility only grants current/spawned ownership and sessions_history checks that guard before reading chat.history. I did not run the live browser click-plus or timeout scenario.

## Solution Assessment

No as a direct silent visibility widening, because that would be privacy-sensitive. The best path is a maintainer-approved bounded parent/family recall policy with explicit channel/account/reset boundaries and regression coverage.
