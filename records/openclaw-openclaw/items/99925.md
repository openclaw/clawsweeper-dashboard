## Summary

Keep open: current main and v2026.6.11 still default session tools to tree-scoped visibility, and the WebChat/new-session path does not provide safe automatic recall of the immediately previous same-channel session. The reported behavior is source-reproducible, but a fix needs maintainer product and security review because it changes prior-transcript visibility across session boundaries.

## What This Changes

The issue requests privacy-safe WebChat continuity so a newly started session can recover recent prior conversation context instead of being limited to the current tree-scoped session.

## Best Possible Solution

Define a bounded WebChat continuity contract that can recover recent same-user or same-channel context through session-history or memory primitives without silently granting unrelated session transcript access.

## Reproduction Assessment

Yes at source level for the restricted behavior: current main defaults session tools to tree, sessions_list filters by that scope, and sessions_history checks visibility before reading chat.history. I did not run a live WebChat click-plus or timeout reproduction.

## Solution Assessment

No to a direct silent visibility widening, because that would be a privacy-sensitive broadening of transcript access. The better solution is a maintainer-approved bounded recall policy for WebChat parent, reset-family, or same-channel context.
