## Summary

Keep open: current main and the latest release still default session tools to tree-scoped visibility, and WebChat New Chat records a parent link without automatically exposing the prior same-channel session history to the new session.

## What This Changes

The issue requests WebChat/session-tool continuity so a newly started WebChat session can recover recent prior conversation context from the same user/channel.

## Best Possible Solution

Define a privacy-aware WebChat continuity contract that can surface bounded prior same-user or same-channel context, or an explicit older-history-available indicator, without silently broadening unrelated session visibility.

## Reproduction Assessment

Yes at source level: current main defaults session tools to tree, WebChat New Chat only records a parentSessionKey, and sessions_history/chat.history do not automatically read the prior parent or same-channel session. I did not run a live WebChat timeout or click-plus scenario.

## Solution Assessment

No as a simple visibility widening: that would be privacy-sensitive and could leak unrelated transcript history. The better solution is a maintainer-approved, bounded WebChat parent/prior-session recall contract with clear diagnostics.
