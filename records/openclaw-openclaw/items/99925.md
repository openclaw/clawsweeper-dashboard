## Summary

Keep open: current main still creates WebChat follow-up sessions with parent linkage, but model-facing session tools default to tree visibility and only grant directional child access, so a new session cannot safely recover the prior parent conversation by default. The remaining fix is real but needs maintainer product and security review because it changes transcript visibility across session boundaries.

## What This Changes

The issue requests privacy-safe WebChat continuity so a newly started same-channel session can recover recent prior conversation context or use session tools across the prior session boundary.

## Best Possible Solution

Define a bounded WebChat session-continuity contract that can recover recent same-user or same-channel context without granting broad session-tool access to unrelated transcripts.

## Reproduction Assessment

Yes at source level: WebChat creates a parent-linked new session, but current main defaults session tools to tree visibility and the visibility guard does not grant reverse access from the child to its parent. I did not run the full live WebChat timeout or plus-button flow.

## Solution Assessment

No for silently widening tree visibility, because that would weaken transcript privacy. The best path is an explicit, bounded WebChat continuity policy with allow/deny tests for parent, same-channel, sibling, and unrelated sessions.
