## Summary

Keep open: current main and v2026.6.11 still default model-facing session tools to tree visibility and do not give a newly created WebChat session prior same-channel transcript context. The report is valid as a UX/session-continuity gap, but a safe fix needs maintainer product and security direction because it changes transcript visibility boundaries.

## What This Changes

Request bounded WebChat continuity so a new session can recover recent prior same-channel conversation context or safely list/read prior sessions.

## Best Possible Solution

Define a privacy-aware WebChat continuity contract that recalls bounded same-user or same-channel prior context without granting broad unrelated transcript access.

## Reproduction Assessment

Yes at source level: current main links the new WebChat session to its parent but tree visibility filters list/history access before the new session can read that prior transcript. I did not run the full live WebChat plus-button or timeout flow.

## Solution Assessment

No for a silent visibility widening because that would weaken transcript privacy. The maintainable path is an explicit, bounded WebChat prior-session recall policy with tests and security review.
