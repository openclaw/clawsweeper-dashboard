## Summary

Keep open: current main still defaults model-facing session tools to tree visibility and does not automatically provide a new WebChat session with recent prior same-channel context. The source-level restriction is clear, but a safe repair needs maintainer direction because it changes transcript visibility and privacy boundaries.

## What This Changes

Request that new WebChat sessions recover recent same-channel conversation context or expose prior same-channel sessions through `sessions_list`/`sessions_history` instead of being limited by tree visibility.

## Best Possible Solution

Define a privacy-aware WebChat session-continuity contract that can recover bounded recent same-user or same-channel context without silently broadening unrelated session transcript access.

## Reproduction Assessment

Yes at source level: current main defaults session tools to tree, `sessions_list` filters rows through that guard, and `sessions_history` checks visibility before `chat.history`. I did not run the full live WebChat new-session flow.

## Solution Assessment

No for a direct silent visibility widening because that would weaken transcript privacy. The maintainable path is a bounded, explicit WebChat prior-session recall policy with tests and security review.
