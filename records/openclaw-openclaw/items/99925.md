## Summary

Keep open: current main still defaults model-facing session tools to tree visibility and does not automatically provide a fresh WebChat session with bounded prior same-channel context. The source-level restriction is clear, but the repair changes transcript visibility and privacy boundaries, so it needs maintainer direction.

## What This Changes

Request that a newly started WebChat session recover or expose bounded recent prior conversation context from the same user/channel instead of requiring the model to reconstruct it through memory search.

## Best Possible Solution

Define a privacy-aware WebChat session-continuity contract that grants only bounded same-user or same-channel prior-session recall, with unrelated-session denials and live WebChat proof.

## Reproduction Assessment

Yes at source level: current main defaults session tools to tree, sessions_list filters rows through that guard, and sessions_history checks visibility before chat.history. I did not run the full live WebChat new-session flow.

## Solution Assessment

No for a direct silent visibility widening because that would weaken transcript privacy. The maintainable path is a bounded, explicit WebChat prior-session recall policy with tests and security review.
