## Summary

Keep open: current main and v2026.6.11 still leave a new WebChat/dashboard child session without reverse access to the prior parent or sibling transcript under default tree visibility, and a safe repair needs maintainer product/security direction because it changes prior-transcript visibility.

## What This Changes

The issue requests WebChat new-session continuity so a newly created same-user channel session can recover recent prior conversation context or access recent session history.

## Best Possible Solution

Define a privacy-aware WebChat continuity contract that provides bounded recent same-user or same-channel recall while keeping unrelated session transcripts denied by default.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 default session tools to tree visibility, filter sessions_list rows through that guard, and gate sessions_history before chat.history. I did not run the full live WebChat new-session flow.

## Solution Assessment

Unclear for the final product shape: silently widening session visibility is not the best fix because it weakens transcript privacy. The safer direction is a bounded WebChat prior-session recall policy with explicit allow and deny tests.
