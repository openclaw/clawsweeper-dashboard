## Summary

Keep open: current main still defaults session tools to tree-scoped visibility and does not automatically bridge a new WebChat session to the immediately prior same-channel conversation. The remaining work is real, but it changes transcript visibility and should stay in maintainer product/security review rather than a new autonomous fix lane.

## What This Changes

The issue requests prior same-channel WebChat context or session-history access when a newly started WebChat session would otherwise be isolated by tree-scoped session-tool visibility.

## Best Possible Solution

Define a privacy-aware WebChat/session continuity contract that can recover bounded recent same-user or same-channel context without silently broadening unrelated session history access.

## Reproduction Assessment

Yes at source level for the reported visibility restriction: current main defaults session tools to tree and filters history/list access before reading prior sessions. I did not establish a live WebChat click-plus or timeout reproduction in this read-only review.

## Solution Assessment

No as a direct silent visibility widening, because that would be privacy-sensitive and could expose unrelated transcripts. The better solution is a maintainer-approved WebChat prior-session recall policy with bounded history, same-user/same-channel checks, and clear diagnostics.
