## Summary

Keep open: current main still defaults session tools to tree-scoped visibility and does not provide a privacy-aware WebChat new-session recall path for the prior same-channel conversation. The report overlaps broader session-history and memory-continuity work, but the specific WebChat parent/prior-session visibility boundary remains unresolved.

## What This Changes

The issue asks for WebChat new sessions to regain recent same-channel conversation context, either through automatic context loading or broader sessions_list/sessions_history visibility.

## Best Possible Solution

Define a privacy-aware WebChat/session continuity contract that can recover bounded prior same-user or same-channel context without silently broadening unrelated sessions_list, sessions_history, or sessions_send access.

## Reproduction Assessment

Yes at source level for the visibility restriction: current main defaults session tools to tree, list/history enforce that scope, and docs require explicit widening for unrelated same-agent sessions. I did not run a live WebChat click-plus or timeout scenario.

## Solution Assessment

No as a direct silent visibility widening: that would be privacy-sensitive and could leak unrelated sessions. The better fix is a maintainer-approved recall/visibility policy with bounded history and clear same-user or same-channel rules.
