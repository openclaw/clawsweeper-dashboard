## Summary

This remains a useful candidate fix for the linked Anthropic retry bug, but the current head still shortens server cooldowns longer than 60 seconds, drops the HTTP status before the typed assistant result, and provides only automated stub/mock evidence.

## What This Changes

The PR parses Anthropic `Retry-After` responses, threads `retryAfterMs` through assistant errors, and uses it to schedule session auto-retries.

## Best Possible Solution

Preserve both HTTP status and the exact server cooldown through the typed assistant error, honor valid short cooldowns, and decline the in-turn retry or enter the normal fallback path when the advertised wait exceeds the permitted interactive wait rather than shortening it.
