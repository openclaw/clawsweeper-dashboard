## Summary

Keep this PR open: current main still drops Anthropic Retry-After metadata, so the fix is necessary, but the branch prematurely shortens long server cooldowns, does not carry the promised HTTP status into the final assistant error, and lacks after-fix real-session proof.

## What This Changes

The PR preserves Anthropic HTTP status and Retry-After metadata on transport errors, threads the cooldown into assistant messages, and uses it for agent auto-retry timing.

## Best Possible Solution

Thread both HTTP status and Retry-After through the generic transport error contract, reuse the shared rate-limit-window policy so long cooldowns stop or defer retries instead of being shortened, and prove a full AgentSession turn with redacted runtime output.
