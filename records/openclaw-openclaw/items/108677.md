## Summary

The metadata-plumbing approach is sound, but the latest head still converts provider cooldowns above 60 seconds into a 60-second same-session retry, contrary to OpenClaw’s long-window failover behavior. Contributor evidence remains test/mock-only.

## What This Changes

The PR extracts Anthropic HTTP status and Retry-After metadata, threads retry timing through assistant messages, and uses it for AgentSession auto-retry delays.

## Best Possible Solution

Preserve structured status and Retry-After metadata, honor short server waits in-session, and route waits above the existing 60-second threshold to the established auth-profile or model failover path with coverage for both branches.
