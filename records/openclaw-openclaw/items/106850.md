## Summary

Current `main` still misses the repository’s own parenthesized provider-error format, and this focused patch appears to restore transient session retry without reintroducing arbitrary mid-string status matching. The linked issue should remain open until this PR lands.

**Likely related people**
- `bugkill3r` — medium confidence; previously changed shared provider error presentation and status extraction callers.
- `altaywtf` — medium confidence; co-authored and reviewed the adjacent provider-error handling work.

## What This Changes

The PR adds anchored extraction of status codes from provider-prefixed `API error (NNN): …` messages and regression coverage for transient 5xx and permanent 4xx cases.

## Best Possible Solution

Land the anchored shared-parser fix after exact-head checks complete, while keeping non-parenthesized provider wrappers such as the Ollama form tracked separately in https://github.com/openclaw/openclaw/issues/55178.

Yes at source level: current `main` only extracts a status at the start of the string, while the built-in adapters place it inside an anchored `API error (NNN)` wrapper; the supplied production-classifier contrast returns false for the exact wrapped 500.

## Solution Assessment

Yes. Extending the shared extractor with a narrowly anchored recognized wrapper is more maintainable than changing three provider formatters independently and preserves the prior protection against arbitrary status substrings.
