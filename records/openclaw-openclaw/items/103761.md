- `P2`: This is a channel-specific opt-in improvement with bounded scope, but its current implementation changes default LINE group scheduling.
- `merge-risk: 🚨 compatibility`: Existing LINE groups that do not configure either new field are still routed through a new per-group serialization path.
- `merge-risk: 🚨 message-delivery`: Holding the per-group queue through the full agent turn can delay later webhook deliveries and increase retry or ordering changes for the same group.

## Summary

This PR remains useful, and the latest head fixes all previously reported queue/history races, but it introduces a new default-path regression: every LINE group turn is serialized through the pending-media lock even when neither new setting is enabled. The patch also still needs redacted real LINE behavior proof and explicit product acceptance for delayed cross-message media association.

## What This Changes

The PR adds opt-in LINE non-text mention gating, bounded pending-media retention, keyed same-group serialization, documentation, generated config metadata, and regression tests.

## Best Possible Solution

Apply keyed serialization only when the resolved LINE group has pending-media retention enabled or already owns queued media, preserve existing concurrency for all default groups, and prove the complete opt-in lifecycle in a real LINE group before merge.
