## Summary

One concrete branch-scope defect remains: the new no-installed-service warning treats every version change as evidence of a stale running gateway, while the branch neither establishes gateway liveness nor offers recovery appropriate to an unmanaged process. The `--no-restart` warning itself is useful and correctly placed, but the branch is behind a materially refactored current-main restart flow and still lacks after-fix full-CLI proof.

## What This Changes

The PR makes two version-changing restart-skipped update paths emit prominent gateway restart warnings and adds an npm-mode regression test for the `--no-restart` path.

## Best Possible Solution

Rebase onto current main, preserve the prominent version-changing `--no-restart` warning, and either remove the no-service warning or gate it on a known running gateway with recovery guidance suitable for an unmanaged process.
