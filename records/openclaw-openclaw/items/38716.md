## Summary

Keep open. Current main still lacks the requested Slack RTS/action-token path: Slack assistant-thread handling keeps thread context but not an `action_token`, Slack message actions do not advertise or dispatch `search`, and the adjacent Slack search PRs were closed unmerged and targeted legacy/user-token `search.messages` rather than `assistant.search.context`.

## What This Changes

Request Slack RTS support by extracting Slack assistant action tokens and exposing a read-only `assistant.search.context` search action.

## Best Possible Solution

Define and implement a Slack-plugin-owned RTS contract that captures the event-scoped token narrowly, exposes a typed read-only `assistant.search.context` action, documents scopes/privacy/rate limits, and proves live Slack behavior without credential leakage.

## Solution Assessment

Unclear until maintainers choose the contract. A typed Slack RTS action is plausible, but exposing or persisting raw action tokens outside a narrow Slack plugin boundary would not be the safest solution.
