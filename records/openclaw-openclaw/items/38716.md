## Summary

Keep open. Current main and the latest release still lack Slack RTS support: assistant events do not retain an action token, Slack does not advertise or dispatch a search action, and the related search/action-parity PRs were closed unmerged while maintainer discussion points this work back to this issue.

## What This Changes

The issue requests Slack Real-Time Search support by carrying Slack action tokens into an `assistant.search.context`-backed message or dedicated search action.

## Best Possible Solution

Land a narrow Slack-plugin RTS design that captures the Slack action token from the correct triggering event, keeps it ephemeral and redacted, exposes a typed read-only `assistant.search.context` action, preserves read-target privacy boundaries, and ships with docs, focused tests, and live Slack proof.

- **Reject workspace search for now:** Leave Slack on conversation history/thread reads only and close future search PRs unless a maintainer sponsors the privacy and scope model.

## Solution Assessment

Unclear until maintainers choose the security contract. A narrow Slack-plugin `assistant.search.context` action is the most maintainable shape, while raw token exposure or reviving legacy `search.messages` as a parallel path would be weaker.
