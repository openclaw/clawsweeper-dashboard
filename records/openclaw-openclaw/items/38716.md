## Summary

Keep open. Current main and the latest release still do not implement the requested Slack RTS path: assistant-thread handling stores Slack context but not `action_token`, Slack message actions do not advertise or dispatch `search`, and no Slack runtime calls `assistant.search.context`.

## What This Changes

The issue requests Slack Real-Time Search support by capturing Slack assistant action tokens and exposing an `assistant.search.context`-backed message/tool action.

## Best Possible Solution

Keep this open until maintainers approve a Slack-plugin-owned RTS design that captures the action token narrowly, exposes a typed read-only `assistant.search.context` action, documents scopes/privacy/rate limits, and proves live Slack behavior without credential leakage.

## Solution Assessment

Unclear as phrased. A typed Slack RTS action is plausible, but exposing or persisting the raw `action_token` outside a narrow Slack plugin boundary would not be the safest solution.
