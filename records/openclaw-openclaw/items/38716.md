## Summary

Keep open. Current main and the latest release still lack Slack RTS/action-token search, and the related legacy `search.messages` and broad action-parity PRs were closed without landing the requested `assistant.search.context` path.

## What This Changes

Request Slack RTS support by capturing assistant event `action_token`s and exposing a read-only Slack search action/tool backed by `assistant.search.context`.

## Best Possible Solution

Keep this as the canonical Slack-plugin RTS design issue: add a typed read-only `assistant.search.context` action only after maintainers define ephemeral token containment, search visibility guardrails, scope setup, docs, focused tests, and live Slack proof.

Options:

- **Add narrow RTS support (recommended):** Implement a Slack-owned, read-only RTS action that keeps action tokens ephemeral, redacted, thread/account-bound, and proven in a live Slack workspace.
- **Defer to external plugin:** Leave bundled Slack unchanged and require an external Slack search plugin or ClawHub package until maintainers want to own the RTS security contract.
- **Revive legacy message search:** Use `search.messages` user-token search instead, accepting that it is not the requested event-token RTS API and needs separate privacy/authorization review.

Unclear until maintainers choose the Slack RTS contract. A narrow plugin-owned `assistant.search.context` action is plausible, while raw token exposure or reviving legacy `search.messages` as a substitute is not the best default.
