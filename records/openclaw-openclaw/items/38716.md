## Summary

Keep open. Current main still lacks the requested Slack RTS path: assistant-thread handling keeps Slack context but no `action_token`, Slack action discovery/runtime/dispatch do not expose an RTS search action, and the related Slack search/action-parity PRs are closed unmerged and targeted `search.messages` or broader parity rather than `assistant.search.context`.

## What This Changes

Request Slack Real-Time Search support by extracting Slack assistant event `action_token` values and exposing `assistant.search.context` through a message or dedicated tool action.

## Best Possible Solution

Add a Slack-plugin-owned RTS implementation only after maintainer approval: capture the event-scoped action token narrowly, expose a typed read-only `assistant.search.context` action, document scopes/privacy/rate limits, and prove redacted live Slack behavior without logging or persisting raw credentials.
