## Summary

Keep this protected security issue open for explicit ACP/security-owner disposition. Current main does not expose the reported client-defined recursive filter or a session-mapper-to-SQL translation path; the narrower unresolved question is whether repeated replay of an existing ACP session needs its own work budget or rate limit.

## What This Changes

Assess and mitigate alleged denial-of-service risk from complex or repeated historical ACP log queries.

## Best Possible Solution

Benchmark repeated maximum-size existing-session replay through the real ACP loadSession path, then add a narrowly scoped per-client replay work budget only if that proof demonstrates meaningful resource exhaustion; do not add an AST analyzer to session-mapper.
