## Summary

Keep this protected security issue open for explicit security-owner disposition. Current main does not expose the reported recursive-filter mechanism: ACP replay uses bounded, parameterized equality lookups, and the named session mapper only resolves session identifiers; the remaining question is whether repeated existing-session replay loads need a separate availability control.

## What This Changes

Assess whether historical ACP replay queries need complexity validation, execution limits, and query-level rate limiting.

## Best Possible Solution

Keep replay reads restricted to parameterized exact identifiers and bounded storage; if authenticated replay flooding is considered in scope, add a narrow per-client load/read limiter at the ACP request boundary rather than an AST analyzer in `session-mapper.ts`.
