## Summary

Keep this protected security issue open for explicit security-owner disposition, although the reported arbitrary-filter mechanism does not match current main: ACP replay uses session identifiers, bounded fixed queries, ledger limits, and burst limiting for new sessions. The remaining question is whether repeated authenticated replay of an already-known session warrants additional defense-in-depth under OpenClaw’s trusted-operator model.

## What This Changes

The issue requests complexity limits, database timeouts, and rate limiting for allegedly client-defined historical-log filters in the ACP replay path.

## Best Possible Solution

Have a security owner run a measured current-main ACP replay PoC; if it shows material contention, add a bounded replay/concurrency or per-connection limiter at the translator or ledger boundary rather than an AST analyzer in `session-mapper.ts`.
