## Summary

Keep open: current main and v2026.6.11 still route Slack uploads through the shared optimizing media loader, and the remaining Slack upload-fidelity behavior needs a maintainer product/config decision.

## What This Changes

The issue requests a Slack upload behavior or opt-out that preserves original image files instead of applying image optimization that can change format or fidelity.

## Best Possible Solution

Choose and document the Slack media-fidelity contract, then implement it at the Slack upload boundary using the existing raw media loader or a deliberate policy with tests and live Slack proof.

## Reproduction Assessment

Yes, at source level: Slack uploads call loadOutboundMediaFromUrl, which uses loadWebMedia with image optimization enabled by default, and Slack config has no fidelity opt-out. I did not run a live Slack upload in this read-only review.

## Solution Assessment

Unclear. A Slack opt-out is plausible, but maintainers should first choose whether the best contract is raw-upload default behavior, a config option, per-call semantics, or a shared media-delivery policy.
