## Summary

Keep open: current main and v2026.6.11 still route normal Slack media delivery through the shared optimizing media loader, while Slack has no settled upload-fidelity contract equivalent to the Telegram/WhatsApp `forceDocument` path.

## What This Changes

The issue asks OpenClaw to preserve original image fidelity, or provide an opt-out, when agents upload images to Slack.

## Best Possible Solution

Reuse the existing per-call upload-fidelity semantics for Slack where possible, then add any Slack-wide default only if maintainers explicitly want deployment-level behavior and can preserve current defaults.
