## Summary

Keep open: current main and v2026.6.11 still route Slack `send` and `upload-file` media through the shared optimizing media loader, and Slack has no raw-upload or image-optimization opt-out, so the remaining work needs a maintainer product decision.

## What This Changes

Request a Slack upload-fidelity control so generated images and files can be uploaded without OpenClaw changing the original bytes or format.

## Best Possible Solution

Choose a default-off, documented Slack upload-fidelity contract in the Slack plugin, then thread it through outbound/message-tool media loading with focused tests and live Slack proof.

## Maintainer Decision

Required: true

Question: Should Slack uploads preserve original media bytes by default, expose a default-off raw-upload/optimization opt-out, or keep the current optimizing media pipeline and document a different workflow?

Rationale: This changes Slack media-delivery semantics and likely adds config/default behavior, which repository policy treats as compatibility-sensitive rather than a safe autonomous bug fix.

Likely owner: steipete

Owner reason: The decision spans shared media loading, config compatibility, and Slack delivery boundaries where this history is strongest.

Owner confidence: medium

Options:

- **Add Default-Off Fidelity Control (recommended):** Add a Slack-owned opt-in that bypasses image optimization for explicit uploads while leaving existing default behavior and oversize fallback policy intact.
- **Make Raw Upload Default:** Preserve original bytes by default for Slack uploads, accepting the upgrade risk that some previously optimized sends may fail or behave differently.
- **Keep Current Pipeline:** Document that Slack uploads use the shared media pipeline and close or narrow this only if maintainers do not want a fidelity contract.

## Reproduction Assessment

Yes, at source level: Slack uploads call `loadOutboundMediaFromUrl`, the shared loader defaults `optimizeImages` to true, and Slack has no upload-fidelity opt-out. I did not run a live Slack upload in this read-only review.

## Solution Assessment

Unclear. A Slack opt-out is plausible, but maintainers should first choose whether the right contract is raw upload by default, default-off config, message-tool semantics, or shared media policy.
