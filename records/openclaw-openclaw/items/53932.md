## Summary

Keep open: current main and v2026.6.11 still do not provide a reliable Slack upload-fidelity opt-out; generic `forceDocument` exists for hydrated attachment actions, but Slack `upload-file` still dispatches a file path through the optimizing media loader, so the remaining contract needs maintainer direction.

## What This Changes

Request to provide a Slack upload-fidelity opt-out so image uploads can avoid OpenClaw's image optimization path.

## Best Possible Solution

Have Slack honor one documented upload-fidelity contract, preferably the existing per-call `forceDocument`/`asDocument` path without changing defaults; add a channel-level default only if maintainers explicitly approve that product direction.
