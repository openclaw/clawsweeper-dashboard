## Summary

Keep open: current main and the latest release still leave Slack upload-fidelity behavior unsettled, with Slack file uploads using the shared optimizing media path unless callers hit a separate generic per-call force-document hydration path.

## What This Changes

The issue asks for a way to opt out of Slack image upload optimization so original image bytes and formats can be preserved.

## Best Possible Solution

Define Slack upload fidelity at the message-tool/channel boundary, preferably by honoring the existing per-call forceDocument/asDocument semantics first and adding any Slack-wide default only with explicit maintainer approval, docs, tests, and live Slack proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Slack media delivery honor the existing forceDocument/asDocument raw-upload contract, add a separate default-off Slack upload-fidelity setting, or keep the current optimizing pipeline as the supported behavior?

Rationale: The source gap is clear, but the permanent behavior affects Slack delivery semantics, config/API surface, and upgrade expectations.

Likely owner: steipete

Owner reason: The strongest current history spans shared media loading, Slack delivery, and config compatibility.

Owner confidence: high

Options:

- **Honor Per-Call Fidelity (recommended):** Wire Slack uploads so forceDocument/asDocument disables image optimization for explicit file/media sends while keeping current defaults unchanged.
- **Add Default-Off Slack Setting:** Add a Slack-owned account/channel setting for raw uploads with clear per-call override semantics, docs, and upgrade proof.
- **Document Current Behavior:** Keep the optimizing media pipeline as Slack's supported default and document when original bytes are or are not preserved.

## Reproduction Assessment

Yes, at source level: Slack upload paths still reach the shared media loader that defaults image optimization on, while only a separate generic forceDocument/asDocument path disables optimization for hydrated upload-file actions. I did not run a live Slack upload in this read-only review.

## Solution Assessment

Unclear until maintainers choose the contract. The narrowest maintainable path appears to be reusing the existing per-call forceDocument/asDocument semantics before adding any Slack-specific default.
