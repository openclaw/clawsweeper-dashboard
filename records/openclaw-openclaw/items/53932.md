## Summary

Keep open: current main and the latest release still route Slack file uploads through the shared optimizing media loader, and Slack has no raw-upload or image-optimization opt-out. The linked Slack opt-out PR was closed unmerged, and the broader force-document issue overlaps but does not replace this Slack-specific product decision.

## What This Changes

Request to let Slack uploads preserve original image bytes and format by disabling or opting out of shared image optimization.

## Best Possible Solution

Keep this as the canonical Slack upload-fidelity decision; once maintainers choose the contract, wire Slack uploads to an explicit raw/optimized policy with focused tests and live Slack proof.

## Reproduction Assessment

Yes, at source level: Slack uploads call loadOutboundMediaFromUrl, which uses loadWebMedia with optimizeImages defaulting to true, and Slack exposes no upload-fidelity opt-out. I did not run a live Slack upload in this read-only review.

## Solution Assessment

Unclear. A Slack opt-out is plausible, but enforcing upload-file alone is not enough on current main because upload-file still uses the optimizing loader; maintainers should first choose the public media-fidelity contract.
