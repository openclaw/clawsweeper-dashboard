## Summary

Keep open: current main and v2026.6.11 still route Slack media sends through the shared outbound media loader, where image optimization is the default, and Slack has no maintainer-selected upload-fidelity contract even though main now preserves some already-in-limit image formats.

## What This Changes

This issue asks Slack media uploads to preserve original image fidelity or expose an opt-out from OpenClaw's optimizing image loader.

## Best Possible Solution

Define a Slack upload-fidelity contract that preserves current defaults, preferably by honoring existing per-call `forceDocument`/`asDocument` first and adding any Slack-wide default only with explicit maintainer approval, docs, tests, and live Slack proof.

Yes, at source level: Slack `send` and `upload-file` media reach the shared loader that optimizes images by default, and Slack has no wired raw-upload or upload-fidelity contract. I did not run a live Slack upload in this read-only review.

## Solution Assessment

Unclear until maintainers choose the contract. The narrowest maintainable direction appears to be honoring the existing per-call `forceDocument`/`asDocument` semantics for Slack before adding any new Slack-specific config default.
