## Summary

Keep open: current main and the latest release still do not provide a Slack-specific way to opt out of outbound image optimization, and the linked Slack opt-out PR was closed unmerged while the broader force-document issue only partially overlaps.

## What This Changes

The issue requests a Slack media-delivery mode or opt-out that preserves original uploaded image bytes instead of allowing the shared image optimization pipeline to transcode or resize them.

## Best Possible Solution

Choose a Slack media-fidelity contract first, then implement it at the Slack outbound/message-tool boundary with focused tests and live Slack upload proof.

## Reproduction Assessment

Yes, at source level: Slack uploads call loadOutboundMediaFromUrl, which uses the optimizing loadWebMedia path by default, and Slack exposes no raw-upload opt-out. I did not run a live Slack upload in this read-only review.

## Solution Assessment

Unclear: a Slack opt-out is plausible, but maintainers should first choose whether the durable contract is raw upload by default, a new Slack config option, per-call forceDocument semantics, or the broader media-as-document policy tracked elsewhere.
