## Summary

Keep open: the browser client still reads successful HTTP JSON responses without a cap on current main, but this PR is not merge-ready because the new catch-all turns non-overflow stream, timeout, and abort read failures into a false size-limit service error, and the external proof is test-only.

## What This Changes

The PR adds a 1 MiB cap for successful browser-control JSON response reads in `fetchHttpJson` and extends the oversized-body regression test.

## Best Possible Solution

Keep the successful-JSON body cap, but make overflow handling specific via the bounded reader's `onOverflow` path and let timeout, abort, and stream failures continue through the existing browser fetch error classifier.

## Solution Assessment

No as submitted. Bounding successful JSON reads in `fetchHttpJson` is the right layer, but the implementation should preserve non-overflow read failures instead of reporting every read rejection as a size-limit service error.
