## Label Justifications

- `P0`: Merging as written can bypass an operator-configured host-command security gate, which meets the emergency security-bypass rubric.
- `merge-risk: 🚨 security-boundary`: The new direct terminal path permits host command execution without consulting the established exec deny or approval policy.
- `merge-risk: 🚨 compatibility`: Existing users may reasonably rely on their exec approval settings to constrain agent host execution, but this PR adds a parallel path that changes that effective behavior.

## Summary

Keep open for explicit security review: the new terminal path gives unsandboxed agents direct host-shell execution without honoring the existing exec approval or deny policy, and the PR provides test evidence rather than a demonstrated live co-attach flow.

## What This Changes

Adds agent-owned gateway PTY sessions, a core `terminal` agent tool, shared operator attachment, and Control UI ownership indicators.

## Best Possible Solution

Keep the agent-owned PTY and co-attach architecture, but make command and input execution honor the established exec deny/allowlist/approval semantics—or require an explicit, narrowly documented agent-terminal opt-in—and demonstrate the complete flow in a real Control UI setup.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should agent terminal command and input execution inherit the existing exec approval policy, or become a separately opted-in unrestricted host-shell capability?

Rationale: The patch intentionally creates a second RCE path with different authorization semantics; repository policy and tests cannot decide whether terminal enablement is meant to override an operator's existing exec deny or approval settings.

Likely owner: steipete

Owner confidence: high

Options:

- **Reuse exec approvals (recommended):** Require terminal commands and raw input that can execute shell actions to pass through the existing exec deny, allowlist, and approval contract.
- **Add explicit terminal opt-in:** Keep direct terminal input only behind a separate agent-terminal permission with clear setup, upgrade, and security documentation.
- **Accept unrestricted owner terminals:** Explicitly declare that enabling terminals grants unsandboxed owner agents direct host-shell execution regardless of exec approval settings.
