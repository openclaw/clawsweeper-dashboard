## Summary

This issue is still necessary: the bundled public-artifact loader continues to reject hardlinked files even after it has confined them to the OpenClaw package or bundled-plugin root. That makes legitimate Nix store deduplication break on-demand bundled capabilities such as image optimization and provider policy loading. The earlier pnpm hardlink report was closed, but it addressed bundled plugin manifests; this is a remaining public-artifact path with a materially different caller. Likely related people: `Sid-Qin` (low confidence, related boundary-hardening history) and `steipete` (low confidence, current project/security-direction routing).

## What This Changes

Allow bundled plugin public artifacts stored as legitimate hardlinks to load on NixOS without weakening the loader’s package-root containment checks.

## System Context

Bundled plugins expose small public runtime artifacts that core features load on demand, including media and provider-policy helpers. The loader resolves an artifact under the OpenClaw package or bundled-plugin root, validates the filesystem boundary, then imports the module for the calling feature.

## Architecture Diagram

flowchart LR
  A[Core feature request] --> B[Bundled public artifact resolver]
  B --> C[Package or bundled-plugin root]
  C --> D[Boundary-verified file open]
  D --> E[Identity revalidation]
  E --> F[Runtime module import]
  F --> G[Media or provider feature]

## Best Possible Solution

Keep hardlink rejection for untrusted or operator-controlled roots, but make the bundled public-artifact loader mirror the facade loader only after its canonical package/bundled-root resolution; add a regression test using a hardlinked artifact and preserve the existing containment and identity checks.
