## Summary

Keep open: current main still has useful session lineage metadata and Workboard/task primitives, but it does not implement the requested Control UI orchestration surface with a scalable agent-to-session-to-subagent hierarchy and safe bulk run controls.

## What This Changes

The issue requests a scalable Control UI orchestration surface for many concurrent agents/subagents, including hierarchy, active-first filters, bulk actions, row status metadata, and virtualization.

## Best Possible Solution

Keep this as the umbrella Control UI subagent-orchestration request and split it into reviewed slices: scalable read-only hierarchy first, then explicitly authorized bulk intervention and cleanup controls.

## Reproduction Assessment

Yes. Source inspection shows the requested gap on current main: Sessions renders a flat paginated table with delete-only bulk selection, no orchestration route, and no virtualized hierarchy.

## Solution Assessment

Unclear as one implementation. The direction is coherent, but maintainers need to choose the durable UI shape and bulk-operation semantics before a safe implementation PR.
