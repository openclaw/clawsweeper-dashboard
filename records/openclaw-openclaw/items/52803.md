## Summary

Keep open. Current main still lacks the requested browser orchestration board: navigation has no mission-board route, Sessions remains a flat paginated table with delete-only bulk actions, and Workboard can stop individual linked cards but does not replace a scalable parent-session/subagent hierarchy with bulk kill, steer, retry, and cleanup controls.

## What This Changes

Request a scalable Control UI orchestration view for agent/main-session/subagent hierarchy, active-first filtering, per-row runtime metadata, and bulk runtime controls.

## Best Possible Solution

Keep this as the umbrella Control UI runtime subagent-orchestration request, then split accepted work into read-only scalable hierarchy/status first and privileged bulk intervention controls after safety semantics are chosen.

## Reproduction Assessment

Yes for a source-level feature gap: current main can be checked in Sessions, Workboard, navigation, and docs source and does not render the requested hierarchy or bulk runtime controls. This is not a bug reproduction because no existing contract promises the surface.

## Solution Assessment

Unclear. The requested direction is coherent, but maintainers need to choose whether the best home is Sessions, Workboard, or a new Orchestration view and define safe bulk-action behavior.
