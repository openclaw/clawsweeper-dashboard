## Summary

Keep open: current main and the latest release still have the iMessage target-normalization fallback that can turn a bare hex chat identifier into a bogus phone number, and https://github.com/openclaw/openclaw/pull/99525 is an open closing-reference candidate fix rather than a merged implementation.

## What This Changes

The issue reports that bare 32-character iMessage group chat identifiers in cron delivery targets are normalized as bogus phone numbers instead of chat identifiers.

## Best Possible Solution

Review and either land or close https://github.com/openclaw/openclaw/pull/99525; this issue should remain the canonical bug report until that candidate fix is resolved.

## Reproduction Assessment

Yes from source: current main routes bare iMessage delivery targets through normalizers that fall back to normalizeE164, which strips the hex identifier into a bogus phone-number shape. No live iMessage cron run was performed in this read-only review.

## Solution Assessment

Yes: the maintainable fix belongs in the iMessage plugin-owned target normalizers and parser, and the open linked PR touches those exact duplicated surfaces with regression tests. The issue should not close until that PR is reviewed and merged or rejected.
