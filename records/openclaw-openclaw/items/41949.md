## Summary

Keep open. Current main and the latest release cap AI snapshots, support efficient mode, and apply a generic tool-result context guard, but they still do not define the requested default compact, goal-shaped browser read or compact post-action feedback contract; the linked FSB comment is useful prior art for that remaining product decision.

## What This Changes

The issue requests context-budget-aware browser interactions that avoid injecting full page content into model context and instead use compact, task-relevant page and action state.

## Best Possible Solution

Define the browser read/action contract first: compact goal-shaped output as the intended interactive default, explicit full/raw reads for escape hatches, compact action change reports, and proof across managed Playwright, Chrome MCP, raw CDP, and one noisy multi-step browser flow.

## Reproduction Assessment

No high-confidence live reproduction was run in this read-only review. Source inspection confirms the remaining contract gap: current browser snapshots are capped and configurable, but not universally compact, goal-shaped, or paired with compact action diffs.

## Solution Assessment

No, not as an autonomous bug patch. The maintainable path needs a maintainer decision on default compact browser reads, explicit full/raw escape hatches, and whether action responses should grow a compact change-report contract.
