## Summary

Keep open. Current main and v2026.6.11 include useful browser-output caps, efficient snapshot mode, and generic tool-result context guards, but they still do not make compact goal-shaped browser reads and post-action change reports the default interaction contract requested here.

## What This Changes

The issue requests browser interaction outputs to become context-budget-aware by default, with compact goal-shaped page reads and post-action state/change signals instead of repeated large page-content injection.

## Best Possible Solution

Define compact goal-shaped browser reads as the intended interactive default, keep explicit full/raw snapshot access, add compact post-action state or change signals, and prove the result on a noisy multi-step browser flow.
