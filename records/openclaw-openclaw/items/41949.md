## Summary

Keep open. Current main and v2026.6.11 have snapshot caps, optional efficient snapshots, and browser-agent guidance, but they still do not make compact goal-shaped reads or post-action change reports the default browser interaction contract requested here.

## What This Changes

The issue asks for browser interactions to avoid injecting large raw page or snapshot content into model context during multi-step browsing tasks.

## Best Possible Solution

Define a browser-owned compact-read contract that keeps raw or full page reads as an explicit escape hatch, returns small action-change reports after mutations, and validates noisy multi-step browser tasks before changing defaults.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should browser interactions default to compact, goal-shaped reads and post-action change reports, with raw or full page reads kept as an explicit escape hatch?

Rationale: Current code already has caps, an optional efficient mode, and browser-agent guidance, but making compact reads and action diffs the default changes the model-facing browser contract and compatibility expectations.

Likely owner: steipete

Owner confidence: high

Options:

- **Adopt compact browser defaults (recommended):** Make compact task-relevant browser output and small action change reports the default, with explicit raw or full snapshot requests for workflows that need the old shape.
- **Keep capped snapshots default:** Treat the current 40,000-character cap plus optional efficient mode and docs as the supported mitigation until stronger live evidence justifies a default change.
- **Fold into browser roadmap:** Track this under the broader browser automation field report and decide the default together with selector, stale-ref, and batch-action work.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Not from a live noisy-page run in this read-only review; source inspection does show that current snapshots can still return large model-visible page text and that action responses lack compact page-change reports.

## Solution Assessment

Is this the best way to solve the issue? The direction is plausible, but the best implementation needs maintainer-approved browser defaults: compact goal-shaped reads by default, explicit raw/full escape hatches, and live proof that the agent still has enough page state to act.
