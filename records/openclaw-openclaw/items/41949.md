## Summary

Keep open. Current main has useful partial mitigations for browser context pressure, but it does not fully solve the central request for default compact, goal-shaped browser reads with an explicit raw/full escape hatch; the linked FSB comment is useful prior-art context for the maintainer decision.

## What This Changes

The issue requests context-budget-aware browser tool output so large page snapshots do not fill model context during multi-step browser work.

## Best Possible Solution

Define a browser-plugin-owned contract where the default browser read is compact and task-shaped, raw/full page reads stay explicit, and focused tests plus live browser proof cover both fresh-install defaults and upgrade behavior.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw make compact, goal-shaped browser reads the default behavior, and if so what explicit raw/full escape hatch should remain for workflows that need complete page state?

Rationale: Current main has caps and an efficient mode, but turning this into the default model-facing browser behavior changes the browser tool contract and needs owner intent before an automated repair chooses semantics.

Likely owner: Peter Steinberger

Owner reason: Browser snapshot modes and bundled browser ownership history make this the best available product-boundary owner signal.

Owner confidence: medium

Options:

- **Compact default with raw escape hatch (recommended):** Make the default snapshot/read path compact and actionable, keep explicit full/raw AI/ARIA reads for workflows that need complete refs, and validate both paths with browser plugin tests and live proof.
- **Keep opt-in efficient mode:** Leave current defaults mostly intact and document when agents should use mode=efficient, maxChars, selector reads, and generic pruning for context-heavy browser workflows.
- **Track under broader browser roadmap:** Close this specific direction into the broader browser field report only if maintainers want a single umbrella to own action diffs, stale refs, viewport reads, and context shaping together.

## Reproduction Assessment

I did not run a live browser scenario to measure token growth or downstream action quality.

Unclear as a single source-only fix: current caps and action result shapes are useful partial mitigations, but the best permanent fix needs a maintainer-approved browser read contract with compact defaults and an explicit raw/full escape hatch.
