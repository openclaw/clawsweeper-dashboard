## Summary

Keep open: current main has capped AI snapshots, optional efficient role snapshots, and generic tool-result guards, but it still lacks the requested default compact, goal-shaped browser read contract and compact post-action change reports.

## What This Changes

The issue asks browser interactions to stop injecting excessive page content into model context and instead return compact, task-relevant browser state.

## Best Possible Solution

Define the browser tool contract so default interactive reads are compact and task-relevant, preserve explicit full/raw snapshot access, add compact post-action state/change signals, and prove it with noisy-page multi-step browser evidence.

- **Adopt compact browser defaults (recommended):** Make compact goal-shaped reads and small post-action change signals the default while preserving explicit full/raw snapshot access.
- **Keep capped snapshots:** Retain the current AI snapshot caps and opt-in efficient mode, treating further compaction as targeted follow-up work.
- **Defer to broader compaction:** Track this under broader context and tool-output compression architecture instead of browser-specific defaults.

## Reproduction Assessment

No live current-main reproduction was run; source inspection shows current browser snapshots and action results can still carry sizeable page text and only cap or efficient-mode it, so the exact context-exhaustion threshold still needs live proof.

## Solution Assessment

The current caps and efficient mode are partial mitigations, not the best final solution; the best fix is a maintainer-approved browser contract with compact default reads, action diffs, and a raw/full escape hatch.
