## Summary

Keep open. Current main and the latest release have size caps, opt-in efficient browser snapshots, role-snapshot compaction, and generic tool-result guards, but they still do not implement the requested default compact goal-shaped browser-read contract or compact post-action change-report behavior.

## What This Changes

The issue asks OpenClaw to make browser interactions context-budget aware so large page content does not crowd out multi-step agent reasoning.

## Best Possible Solution

Define compact goal-shaped browser reads as the intended interactive default, keep explicit full/raw snapshot access, add compact post-action state or change signals, and prove the result on a noisy multi-step browser flow.
