## Summary

Keep open. Current main and v2026.6.11 already have useful partial mitigations for browser context pressure, but they still do not settle the requested default compact, goal-shaped browser read contract with an explicit raw/full escape hatch; the FSB comment supports that direction rather than proving the issue is fully fixed.

## What This Changes

The issue asks OpenClaw to make browser interactions context-budget aware so large/noisy page content does not overwhelm multi-step agent context.

## Best Possible Solution

Define a browser-plugin-owned contract where default model-facing browser reads are compact and task-shaped, raw/full reads are explicit, and tests plus live browser proof cover both paths.
