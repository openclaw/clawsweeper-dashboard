## Summary

Keep open. Current main and v2026.6.11 include snapshot caps, opt-in efficient mode, browser skill guidance, and generic tool-result context guards, but they still do not implement the requested default compact, goal-shaped browser read contract or compact post-action change-report semantics.

## What This Changes

The issue requests browser interactions that send compact, task-relevant page state and action changes to the model instead of repeatedly injecting large page snapshots into context.

## Best Possible Solution

Define compact goal-shaped browser reads as the intended interactive default, keep explicit full/raw snapshot access, add compact post-action state or change signals, and prove the result on a noisy multi-step browser flow.
