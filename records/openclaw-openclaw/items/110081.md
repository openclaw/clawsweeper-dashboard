## Label Justifications

- `P1`: A broken SSH sandbox ref can currently disrupt Gateway startup or unrelated agent sandbox workflows, but the impact is limited to configured SSH sandbox users.
- `merge-risk: 🚨 compatibility`: Agents that previously reached ambient SSH credentials after an unresolved explicit ref will instead become unavailable after merge.
- `merge-risk: 🚨 security-boundary`: The patch changes which agent owns SSH credentials and where explicit-ref fallback is blocked before filesystem or network access.

## Summary

No blocking code defect is evident: the patch uses the existing degraded-owner model, applies the guard before SSH filesystem or network access, and adds focused scope and startup coverage. Keep this PR open for protected maintainer handling because the submitted evidence is test and CI based rather than a live two-agent SSH/Gateway run.

## What This Changes

The PR assigns SSH sandbox SecretRefs to effective agent owners and rejects unresolved credentials per agent before SSH or filesystem access without preventing healthy agents or Gateway startup.

## Best Possible Solution

Keep one canonical per-agent sandbox owner mapping from SecretRef collection through runtime and lifecycle operations, with explicit refs always failing closed for only the effective agent and shared scope consistently using default SSH settings.
