## Summary

Keep open: current main and v2026.6.11 still require the cron minute field to be literal `0`, and the open linked fork PR is unmerged and not maintainer-editable, so this needs maintainer adoption or replacement rather than cleanup close.

## What This Changes

The issue reports that cron schedules whose minute field includes minute 0 through step, list, or range syntax do not receive the default top-of-hour stagger.

## Best Possible Solution

Land one narrow core fix that parses cron minute fields for minute-zero inclusion in the stagger helper, preserves explicit `staggerMs: 0`, and adds focused coverage for helper, runtime defaulting, normalization, and doctor migration paths.
