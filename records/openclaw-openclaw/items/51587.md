## Summary

Keep open: current main and v2026.6.11 still require the cron minute field to be the literal `0`, so step/list/range schedules that include minute zero still miss the default stagger. An open cross-repo PR claims the fix but is unmerged and not maintainer-editable, so this issue remains the canonical tracker.

## What This Changes

The issue reports that cron schedules whose minute field includes zero via step, list, or range syntax do not receive the default top-of-hour stagger.

## Best Possible Solution

Land or replace the linked fix with a narrow core patch that parses Croner-compatible minute-zero fields, preserves explicit `staggerMs: 0`, and covers the helper plus create/defaulting, normalization, and doctor migration callers.
