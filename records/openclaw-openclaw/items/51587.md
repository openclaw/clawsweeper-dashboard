## Summary

Keep open: current main and v2026.6.11 still require the cron minute field to be the literal `0`, so step/list/range schedules that fire at minute zero still miss the default stagger. The linked cross-repo fix PR is open but unmerged and not maintainer-editable, and Hollychou924's comment usefully narrows the edge cases that a replacement or adopted fix should handle.

## What This Changes

The issue asks OpenClaw to treat Croner minute fields that include minute zero, such as `*/15`, `0,30`, and `0-30`, as eligible for the default cron stagger.

## Best Possible Solution

Review, land, or replace the open cross-repo fix PR with a narrow core patch that parses Croner-compatible minute-zero fields, preserves explicit `staggerMs: 0`, and covers helper, create/defaulting, normalization, and doctor migration behavior.

## Reproduction Assessment

Yes. Source inspection on current main shows `isRecurringTopOfHourCronExpr` requires `minuteField === "0"`, so minute fields like `*/15`, `0,30`, and `0-30` cannot receive the default helper result; I did not run tests because this review is read-only.

## Solution Assessment

Yes. The best fix is a narrow helper update in `src/cron/stagger.ts` with focused regression coverage on the helper and its defaulting/migration callers, not a new scheduler mode or config option.
