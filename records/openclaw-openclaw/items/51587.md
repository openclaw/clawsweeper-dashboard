## Summary

Keep open: current main and v2026.6.11 still require the cron minute field to be literal `0`, so the reported step/list/range minute-zero schedules still miss the default stagger. There is an open linked cross-repo PR proposing a fix, but it is unmerged and not maintainer-editable, so this needs maintainer adoption or replacement rather than cleanup closure.

## What This Changes

The issue requests that cron default-stagger detection treat step/list/range minute fields that include minute zero as recurring top-of-hour schedules.

## Best Possible Solution

Land one narrow core fix that parses minute-field inclusion of minute zero, preserves explicit `staggerMs: 0`, and adds focused coverage for the helper plus create/normalize/doctor default-stagger paths.
