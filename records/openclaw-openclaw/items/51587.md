## Summary

Keep open: current main and the latest release still require the cron minute field to be literal `0`, so step/list/range schedules that include minute zero still miss the documented default stagger. The linked fork PR at https://github.com/BingqingLyu/openclaw/pull/1175 is open but unmerged and not maintainer-editable, so this issue should remain the canonical tracker.

## What This Changes

The issue asks OpenClaw to apply default cron staggering to recurring schedules whose minute field includes zero via step, list, or range syntax instead of only literal `0`.

## Best Possible Solution

Land one narrow core fix in `src/cron/stagger.ts` that detects minute-zero inclusion, preserves explicit `staggerMs: 0`, and adds regression coverage through helper, create/default, normalization, and doctor migration paths.

## Reproduction Assessment

Yes at source level. On current main, `*/15 * * * *` leaves the minute field as `*/15`, so the helper's `minuteField === "0"` condition cannot pass; I did not run tests because this review is read-only.

## Solution Assessment

Yes. The narrow maintainable fix belongs in `src/cron/stagger.ts`, with focused regression coverage for the helper and its persisted/default-stagger callers rather than a broader scheduler policy change.
