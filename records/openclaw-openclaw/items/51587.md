## Summary

Keep open: current main and v2026.6.11 still require the cron minute field to be the literal `0`, so cron expressions such as `*/15 * * * *` or `0,30 * * * *` still miss the default anti-herd stagger. An open cross-repo PR claims the fix, but it is unmerged and not maintainer-editable, so this issue should stay open while maintainers review, adopt, replace, or close that PR.

## What This Changes

The issue requests that cron top-of-hour stagger detection recognize step, list, and range minute fields that include minute zero.

## Best Possible Solution

Review, land, or replace the open cross-repo fix with a narrow core patch that parses Croner-compatible minute-zero fields, preserves explicit `staggerMs: 0`, and adds regression coverage for helper, runtime defaulting, normalization, and doctor migration paths.
