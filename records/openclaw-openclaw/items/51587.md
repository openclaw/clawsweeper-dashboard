## Summary

Keep open: current `main` and the latest release still require the cron minute field to be literal `0`, so reported schedules such as `*/15 * * * *` and `0,30 * * * *` still miss the default stagger. An open cross-repository fix PR exists, but it is unmerged and not maintainer-editable, so this should stay open for maintainer adoption, replacement, or closure of that PR.

## What This Changes

The issue requests that cron top-of-hour stagger detection recognize valid minute fields that include minute zero, including step, list, and range expressions.

## Best Possible Solution

Land one narrow core fix that parses cron minute fields for minute-zero inclusion, preserves explicit `staggerMs: 0`, and adds focused coverage for helper, runtime defaulting, normalization, and doctor migration paths.
