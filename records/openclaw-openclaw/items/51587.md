## Summary

Keep open: current main and the latest release still require the cron minute field to be literal `0`, so step/list/range expressions that include minute zero still miss the default stagger; an unmerged non-maintainer-editable fork PR exists, so maintainers should resolve that path before a new repair lane starts.

## What This Changes

The issue requests widening cron default-stagger detection so minute fields that include minute zero, such as steps, lists, and ranges, receive the 5-minute top-of-hour stagger.

## Best Possible Solution

Land one narrow core fix that parses minute fields for minute-zero inclusion, preserves explicit `staggerMs: 0`, and adds focused coverage for the helper plus create/normalize/doctor default-stagger callers.
