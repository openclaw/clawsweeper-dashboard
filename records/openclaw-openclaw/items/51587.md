## Summary

Keep open: current main and the latest release still require the cron minute field to be literal `0`, so the reported step/list/range minute-zero schedules still miss the default stagger. The only open closing fix I found is an unmerged fork PR that is not maintainer-editable, so this needs maintainer adoption, replacement, or closure before cleanup can close the issue.

## What This Changes

The issue asks OpenClaw to recognize cron minute fields that include minute zero, such as steps, lists, and ranges, when applying the default top-of-hour stagger.

## Best Possible Solution

Land one narrow core fix in the cron stagger helper that detects minute-zero inclusion, preserves explicit `staggerMs: 0`, and adds focused coverage for helper, service defaulting, normalization, and doctor migration paths.
