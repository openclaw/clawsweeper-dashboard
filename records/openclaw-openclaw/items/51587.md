## Summary

Keep open: current main and the latest release still require the cron minute field to be literal `0`, so step/list/range schedules that fire at minute zero still miss the default stagger; the issue is already paired with an open closing PR, so cleanup should not close it or queue a separate fix yet.

## What This Changes

The issue asks for `isRecurringTopOfHourCronExpr` to recognize cron minute fields such as steps, lists, and ranges that include minute zero so top-of-hour staggering applies.

## Best Possible Solution

Land one narrow core fix that parses minute fields for minute-zero inclusion, preserves explicit `staggerMs: 0`, and adds focused coverage for helper, runtime default, normalization, and doctor migration paths after the open linked PR is resolved or adopted.
