## Summary

Keep open: current main and latest release `v2026.6.11` still require the cron minute field to be literal `0`, so the reported step/list/range minute-zero schedules still miss the default stagger. A linked fork PR exists as a candidate fix, but it is open, unmerged, and not maintainer-editable, so this issue should stay open for maintainer adoption, replacement, or PR review.

## What This Changes

The issue requests that recurring top-of-hour cron stagger detection recognize cron minute fields that include minute zero, not only the literal minute field `0`.

## Best Possible Solution

Adopt or replace the linked fork PR with a narrow core scheduler fix in `src/cron/stagger.ts`, adding regression coverage for minute-zero step, list, range, and 6-field cron cases while preserving explicit exact scheduling.

## Reproduction Assessment

Yes by source inspection: on current main, `isRecurringTopOfHourCronExpr` requires `minuteField === "0"`, so minute fields like `*/15`, `0,30`, and `0-30` cannot receive the default stagger.

## Solution Assessment

Yes. The narrow maintainable fix belongs in `src/cron/stagger.ts` with focused regression coverage on the helper and default-stagger callers, not in broader scheduler or product-policy changes.
