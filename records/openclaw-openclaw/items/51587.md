## Summary

Keep open: current main and the latest release still require the cron minute field to be literal `0`, so step/list/range schedules that include minute zero still miss the default stagger. There is an open cross-repo closing PR, but it is unmerged and not maintainer-editable, so cleanup closure would be premature.

## What This Changes

The issue requests widening cron top-of-hour stagger detection so minute fields such as `*/15`, `0,30`, and `0-30` receive the default anti-thundering-herd stagger when they fire at minute zero.

## Best Possible Solution

Land or adopt a narrow core fix in `src/cron/stagger.ts` that parses minute-field inclusion of zero, with focused coverage for the helper, service defaulting, normalization, and doctor migration paths.
