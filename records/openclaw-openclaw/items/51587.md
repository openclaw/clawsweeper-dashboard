## Summary

Keep open: current main and v2026.6.11 still require the cron minute field to be literal `0`, so step/list/range minute-zero schedules still miss the default stagger. An open cross-repo PR references the issue, but it is not merged into `openclaw/openclaw`, so this is not cleanup-closeable.

## What This Changes

The issue requests that cron top-of-hour stagger detection parse minute fields such as `*/15`, `0,30`, and `0-30` instead of only accepting the literal minute field `0`.

## Best Possible Solution

Land one narrow core fix in `src/cron/stagger.ts` that detects minute fields containing minute zero, preserves explicit `staggerMs: 0` and existing hour validation, and adds focused helper/runtime/normalization/doctor migration coverage.
