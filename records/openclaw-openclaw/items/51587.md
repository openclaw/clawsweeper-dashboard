## Summary

Keep open: current main and the latest release still require the cron minute field to be literal `0`, so step/list/range minute-zero schedules still miss the default stagger; the open linked fork PR is unmerged and not maintainer-editable, so this is not a cleanup close.

## What This Changes

The issue asks for `isRecurringTopOfHourCronExpr` to recognize cron minute fields that include minute zero via steps, lists, or ranges so those schedules receive the default stagger.

## Best Possible Solution

Land or adopt one narrow core fix in `src/cron/stagger.ts` that parses minute-zero inclusion, preserves explicit `staggerMs: 0`, keeps the existing recurring-hour guard, and adds focused regression coverage for helper and defaulting callers.
