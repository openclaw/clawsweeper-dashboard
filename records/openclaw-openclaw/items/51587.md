## Summary

Keep open: current main and the latest stable release still require the cron minute field to be the literal `0`, so step/list/range expressions that fire at minute zero still miss the default stagger. A linked fork PR claims the fix but is open, unmerged, and not maintainer-editable, so this issue should stay open until that work is adopted, replaced, or closed.

## What This Changes

The issue requests that `isRecurringTopOfHourCronExpr` recognize cron minute fields such as `*/15`, `0,30`, and `0-30` when they include minute zero.

## Best Possible Solution

Land or replace the linked fix with a narrow core patch that parses Croner-compatible minute-zero fields, preserves explicit `staggerMs: 0`, and adds focused coverage for helper/defaulting and migration callers.

## Reproduction Assessment

Yes. Source inspection on current main shows `isRecurringTopOfHourCronExpr` still requires `minuteField === "0"`, so minute fields like `*/15`, `0,30`, and `0-30` cannot receive the default helper result.

## Solution Assessment

Yes, with one caveat: the right fix is a narrow helper update in `src/cron/stagger.ts` plus focused regression coverage, but the exact parser should follow Croner strict syntax and settle wildcard/every-minute semantics.
