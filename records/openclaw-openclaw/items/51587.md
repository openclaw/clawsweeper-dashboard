## Summary

Keep open: current main and v2026.6.11 still require the cron minute field to be literal `0`, so step/list/range schedules that include minute 0 still miss the default stagger. A linked fork PR references the issue, but it is open, unmerged, unstable, and not maintainer-editable, so the issue should remain tracked until a maintainer-owned fix lands or that candidate is resolved.

## What This Changes

The issue asks for cron top-of-hour stagger detection to recognize minute fields such as steps, lists, and ranges that include minute 0.

## Best Possible Solution

Land one narrow core fix that detects minute-zero inclusion in cron minute fields, preserves explicit `staggerMs: 0`, and adds focused coverage for helper, create/patch, normalization, and doctor migration paths.
