## Summary

Keep open: current main and latest release still require the cron minute field to be the literal `0`, so step/list/range schedules that include minute zero still miss the default top-of-hour stagger. A linked cross-repo fix PR exists but is open, unmerged, and not maintainer-editable, so this issue should stay open until maintainers land, adopt, replace, or close that candidate.

## What This Changes

The issue requests that OpenClaw’s default top-of-hour cron stagger recognize Croner-compatible minute fields that include minute zero, such as step, list, and range expressions.

## Best Possible Solution

Review, adopt, or replace https://github.com/BingqingLyu/openclaw/pull/1175 with a narrow core fix that parses Croner-compatible minute-zero fields, preserves explicit `staggerMs: 0`, and adds regression coverage for the helper plus create/defaulting, normalization, and doctor migration callers.

## Reproduction Assessment

Yes. Source inspection on current main shows `isRecurringTopOfHourCronExpr` requires `minuteField === "0"`, so minute fields like `*/15`, `0,30`, and `0-30` cannot receive the default stagger result.

## Solution Assessment

Yes in direction. The best fix is a narrow `src/cron/stagger.ts` helper update with Croner-compatible parsing and focused regression coverage, not a new scheduler mode or config option.
