## Summary

Keep open: current `main` and the latest release still require the cron minute field to be the literal `0`, so step/list/range schedules that include minute zero still miss the default stagger. A linked fork PR claims the fix, but it is open, unmerged, and not maintainer-editable, so the issue should stay open until maintainers adopt, replace, or close that candidate.

## What This Changes

The issue asks for cron top-of-hour stagger detection to recognize cron minute fields that include minute zero through step, list, or range syntax.

## Best Possible Solution

Adopt or replace the open fork candidate with a target-repo PR that parses minute-zero inclusion and adds regression tests for step, list, and range expressions without changing explicit `staggerMs: 0` behavior.

## Reproduction Assessment

Yes. Source inspection on current main shows `isRecurringTopOfHourCronExpr` requires `minuteField === "0"`, so minute fields like `*/15`, `0,30`, and `0-30` cannot receive the default stagger; I did not run tests because this review is read-only.

## Solution Assessment

Yes. The best fix is a narrow helper update in `src/cron/stagger.ts` with focused regression coverage on the helper and its defaulting/migration callers, not a new scheduler mode or config option.
