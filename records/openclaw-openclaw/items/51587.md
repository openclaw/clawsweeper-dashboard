## Summary

Keep open: current `main` and the latest release still require the cron minute field to be the literal string `0`, so step/list/range minute-zero schedules still miss the default top-of-hour stagger. An open linked fork PR is a candidate fix, but it is unmerged and not maintainer-editable, so this should stay open for maintainer adoption or replacement rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to apply default top-of-hour cron staggering to cron minute fields that include minute zero, instead of only literal minute `0`.

## Best Possible Solution

Land one narrow core fix in `src/cron/stagger.ts` that parses minute-zero inclusion consistently with Croner semantics and adds focused coverage for the helper plus create/defaulting and migration callers.
