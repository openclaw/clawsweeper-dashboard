## Summary

Keep open: current main and the latest release still require the cron minute field to be the literal string `0`, so schedules like `*/15 * * * *` and `0,30 * * * *` still miss the default stagger. An open fork PR references this issue with a candidate fix, but it is outside the target repo and not maintainer-editable, so maintainer adoption or replacement is still needed.

## What This Changes

The issue reports that cron expressions whose minute field includes zero through steps, lists, or ranges do not receive the default top-of-hour stagger.

## Best Possible Solution

Adopt or replace the linked fork PR with a narrow core fix that parses minute fields for minute-zero inclusion, preserves explicit stagger overrides, and adds focused helper and service regression coverage.
