## Summary

Keep open: current main has a shared per-pair rate guard, but the documented budget does not cover a slow conversation that remains below its sliding-window limit. The requested behavior needs a maintainer decision on a minimal generic conversation-budget contract versus channel-owned policy before implementation.

## What This Changes

Add optional protection against slow bot-to-bot conversation loops that evade the existing rate-based PairLoopGuard.

## Best Possible Solution

Define one minimal, opt-in extension of the existing generic loop-protection contract for channels that can reliably report bot and human interaction facts, then implement channel adapters and focused long-window/interaction-reset tests rather than adding several overlapping guards at once.
