## Summary

Keep open: current main now has cron event-trigger scripts, which are useful related groundwork, but it still lacks first-class base/conditional interval scheduling and dynamic heartbeat cadence. This remains a product/API decision rather than conservative cleanup closure.

## What This Changes

Request a state-conditional cron/heartbeat cadence so jobs can use shorter or longer intervals when deadline, queue, or user-idle conditions change.

## Best Possible Solution

Keep this open for a maintainer-scoped scheduler decision: either document event triggers as the supported deadline-aware pattern, or design a narrow conditional cadence contract with explicit safe state sources, persistence, docs, and tests.
