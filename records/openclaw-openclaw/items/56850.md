## Summary

Keep open: current main and the latest release still expose static cron schedule and heartbeat cadence contracts only. The June field report and the external zeroclaw prototype show real demand, but this needs maintainer product/API design for condition evaluation, state ownership, persistence, and migration behavior before a fix PR is safe.

## What This Changes

Request conditional cron/heartbeat intervals that switch to a shorter or longer cadence when configured state predicates are true.

## Best Possible Solution

Define one canonical state-aware scheduler contract, or a plugin/API seam that can safely influence next wake timing, with schema, CLI, persistence, docs, migration, and focused cron/heartbeat coverage.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature request. Source inspection confirms current cron schedules and heartbeat intervals do not support state-conditional cadence selection.

## Solution Assessment

Unclear. `conditional_interval` is plausible, and existing hook/plugin seams can gate execution, but maintainers still need to choose whether the best boundary is core scheduler API, a plugin hook that can affect next wake timing, or a narrower cron-only contract.
