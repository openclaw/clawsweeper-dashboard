## Summary

Keep open: current main and v2026.6.11 still expose fixed cron and heartbeat cadence contracts only. The June field report reinforces the need, but this is a new public scheduler/config/state contract that needs maintainer product design before implementation.

## What This Changes

Request state-conditional cron or heartbeat intervals so deadline-, queue-, or activity-sensitive work can run sooner or less often than the base cadence.

## Best Possible Solution

Define one narrow state-aware scheduling contract first, including where conditions are evaluated, what state is allowed, how the next due time is persisted, and how cron, heartbeat, Gateway protocol, CLI, docs, and migration tests stay aligned.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature request. Source inspection gives high confidence that current main lacks state-conditional cron or heartbeat intervals.

## Solution Assessment

Unclear: the proposed `conditional_interval` YAML shape is plausible, but it is not proven to be the best API boundary. A maintainer-designed scheduler contract or explicit plugin/API seam is safer before implementation.
