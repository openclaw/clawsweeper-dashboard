## Summary

Keep open: current main and v2026.6.11 still expose static cron and heartbeat cadence contracts only, while the June field report and the closed external zeroclaw attempt show demand. This remains a product/API design item for safe condition evaluation, not cleanup closure.

## What This Changes

Allow cron or heartbeat schedules to switch intervals when state conditions such as deadlines, queue depth, user silence, or urgent alerts are true.

## Best Possible Solution

Keep this open until maintainers choose a narrow condition-aware scheduler contract or explicitly split the need into existing idle, retry, and phase/jitter trackers; any implementation should update cron schema/protocol/docs/tests and avoid unsafe arbitrary state expressions.
