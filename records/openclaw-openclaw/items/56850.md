## Summary

Keep open: current main and the latest release still expose static cron schedule forms and a single heartbeat cadence, while the June field report reinforces the state-aware scheduling need. This remains useful, but it is a new public scheduler/config/API design rather than a narrow bug fix.

## What This Changes

The issue requests conditional cron or heartbeat intervals that change cadence based on runtime state such as deadlines, queue thresholds, urgency, or user silence.

## Best Possible Solution

Define a maintainer-approved state-aware scheduling contract that covers cron and heartbeat ownership, condition evaluation safety, persisted shape, protocol/CLI/docs, migration behavior, and focused scheduler/heartbeat tests.
