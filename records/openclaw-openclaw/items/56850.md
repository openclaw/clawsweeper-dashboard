## Summary

Keep open: current main and the latest release still expose static cron and heartbeat cadence contracts only. The June field report adds useful real-world context, but the remaining work is a new public scheduling/API design that needs maintainer product judgment before implementation.

## What This Changes

The issue requests conditional cron or heartbeat intervals that choose a shorter cadence when runtime state, such as a deadline or activity threshold, matches a configured condition.

## Best Possible Solution

Design one narrow state-aware scheduling contract first, then implement it across cron protocol/schema, scheduler state, heartbeat interaction, docs, and upgrade-safe tests without adding ad hoc condition evaluation paths.
