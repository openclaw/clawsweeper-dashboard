## Summary

Keep open, but re-scope it from a loop report to a user-visible prompt-contamination and efficiency concern. The reporter’s follow-up establishes that the alleged repeated sessions were distinct Telegram messages, while the remaining report still describes smaller models surfacing meta-commentary about active-memory context; the current hidden-untrusted-prefix design appears intentional, so the correct mitigation needs an owner decision rather than an automatic fix.

## What This Changes

The issue requests that active-memory recall not distract weaker models or leak meta-commentary into replies when its recalled context is prepended to an inbound prompt.

## Best Possible Solution

Keep the hidden-untrusted trust boundary, then define and test a supported mitigation for models that visibly echo recall metadata—preferably an internal context-projection change or a clearly documented, upgrade-safe opt-in policy rather than model-size guessing alone.

## Maintainer Decision

Rationale: The reporter’s corrected trace establishes a quality problem but not a safe universal mechanism: switching trust roles conflicts with the existing security-oriented design, while gating or opt-in changes the feature’s compatibility contract.

Options:

- **Preserve boundary; define safe suppression (recommended):** Keep the hidden untrusted prefix and add a narrowly specified, tested way to skip recall for demonstrably affected agent/model configurations.
- **Retain current behavior:** Keep recall available for all configured agents and document that smaller models may visibly acknowledge untrusted context.
- **Redesign context projection:** Sponsor a broader runtime-context API that preserves untrusted provenance while making recall less likely to be rendered as conversational content.

## Reproduction Assessment

No high-confidence current-main reproduction is established. The supplied trace disproves the loop claim and provides one v2026.7.1 example of meta-commentary, but it does not yet isolate a repeatable current-main matrix across model, prompt, and active-memory configuration.

## Solution Assessment

Unclear. Keeping recalled text in an untrusted hidden prefix is an intentional trust-boundary design, so system-role injection and capability gating are not automatically safer than a narrowly specified suppression or context-projection solution.
