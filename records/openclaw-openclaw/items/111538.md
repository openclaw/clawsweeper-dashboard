## Summary

Keep open for targeted maintainer investigation: current documentation and the active-memory hook confirm that dynamic recall is prepended to the effective user prompt, but the supplied report does not yet establish what schedules each additional session cycle or whether the loop is caused by the hook rather than an upstream sender, retry, or cron path.

## What This Changes

The issue requests that the active-memory plugin avoid having recalled context treated as a prompt by smaller models and prevent the reported repeated session cycles.

## Best Possible Solution

Capture one current-main trace that correlates each new session with its inbound event or scheduler, compare it with active-memory disabled for that session, then make the narrowest plugin-boundary change that prevents recalled text from competing with the actual user request without adding a parallel prompt path.
