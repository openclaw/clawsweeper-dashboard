## Summary

Keep open. Request adds a `tools.sessions.visibility="allowlist"` mode plus a `tools.sessions.allowlist` session-key pattern array for selective cross-session access.

## Best Possible Solution

Define one maintainer-approved session authorization model, then implement the chosen shape across config schema/types, shared visibility checks, session tool callers, docs, and isolation tests while preserving current safe defaults.

## Reproduction Assessment

Yes for source verification, not as a bug reproduction. Current main can be checked in the schema, docs, and shared guard, and all still lack `allowlist` visibility or `tools.sessions.allowlist`.

## Solution Assessment

Unclear. A session-key allowlist is plausible for trusted group sharing, but maintainers should first choose whether the durable model is session-pattern based, per-capability, per-agent, A2A-specific, or a consolidated combination.
