## Summary

Keep open. Current main and v2026.6.11 still expose only `self`, `tree`, `agent`, and `all` session visibility, with no `allowlist` mode or `tools.sessions.allowlist`; the related open items cover broader per-capability, per-agent, sandbox, or A2A-send policy axes but do not replace this session-key pattern allowlist request.

## What This Changes

Request adds a `tools.sessions.visibility="allowlist"` mode plus `tools.sessions.allowlist` session-key patterns for trusted cross-session context sharing.

## Best Possible Solution

Define one maintainer-approved session authorization model, then update schema, types, the shared visibility guard, session tool callers, docs, and isolation tests while preserving current `self` and `tree` defaults.

## Reproduction Assessment

Yes for source verification, not as a bug reproduction. Current main and v2026.6.11 can be checked in the schema, docs, and shared guard, and all still lack `allowlist` visibility or `tools.sessions.allowlist`.

## Solution Assessment

Unclear. A session-key allowlist is plausible for trusted group sharing, but maintainers should first choose whether the durable model is session-pattern based, per-capability, per-agent, A2A-specific, or a consolidated combination.
