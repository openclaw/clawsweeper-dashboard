## What This Changes

The issue requests `tools.sessions.visibility="allowlist"` plus `tools.sessions.allowlist` session-key patterns for trusted cross-channel session sharing.

## Best Possible Solution

Choose one maintainer-approved session authorization model, then implement the selected allowlist semantics across schema, shared visibility checks, session tool callers, docs, generated config/help, and isolation tests without weakening the current `self` and `tree` defaults.

## Reproduction Assessment

## Solution Assessment

Unclear. A session-key allowlist is plausible for trusted group sharing, but maintainers should first choose whether the durable model is session-pattern based, per-capability, per-agent, A2A-specific, or a consolidated combination.
