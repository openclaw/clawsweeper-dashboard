Keep open. Current main and the latest release still support only the four existing `tools.sessions.visibility` modes, and the related open items are adjacent policy proposals rather than a replacement for this session-key pattern allowlist request.

## Best Possible Solution

Define one maintainer-approved session authorization model, then implement the chosen config shape across schema, shared visibility checks, session tool callers, docs, generated help, and isolation tests while preserving current `self` and `tree` defaults.
