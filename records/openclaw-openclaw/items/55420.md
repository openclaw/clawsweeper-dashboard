## Summary

Keep open. Current main and the latest release still expose only the four existing session visibility modes, and the requested session-key allowlist remains a security-sensitive public config/product decision rather than an implemented behavior.

## What This Changes

The issue requests a new `tools.sessions.visibility: "allowlist"` mode with `tools.sessions.allowlist` session-key glob patterns for trusted cross-channel session sharing.

## Best Possible Solution

Adopt one maintainer-approved session authorization model, then update schema, shared visibility checks, session tool callers, docs, generated help, and isolation tests without weakening current `self` and `tree` defaults.

## Reproduction Assessment

Yes for source verification, not as a bug reproduction. Current main and `v2026.6.11` can be checked in schema, docs, and shared guard code, and all still lack `allowlist` visibility or `tools.sessions.allowlist`.

## Solution Assessment

Unclear. A session-key allowlist is plausible for trusted group sharing, but maintainers should choose whether the durable model is session-pattern based, per-capability, per-agent, A2A-specific, or a consolidated combination.
