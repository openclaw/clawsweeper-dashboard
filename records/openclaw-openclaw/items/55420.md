## Summary

Keep open. Current main and v2026.6.11 still expose only the existing `self`, `tree`, `agent`, and `all` session visibility modes, and the related open items overlap broader per-capability, per-agent, sandbox, or A2A-send policy axes without replacing this session-key allowlist request.

## What This Changes

Request adds `tools.sessions.visibility: "allowlist"` plus `tools.sessions.allowlist` session-key glob or prefix patterns for trusted cross-session access without broad `agent` visibility.

## Best Possible Solution

Define one maintainer-approved session authorization model, then implement it across config schema/types, shared visibility checks, list/history/send/status callers, docs, and security-focused tests while preserving default `tree` isolation.

## Reproduction Assessment

Yes for source verification, not as a bug reproduction. Current main can be checked in the schema, docs, and shared guard, and all still lack `allowlist` visibility or `tools.sessions.allowlist`.

## Solution Assessment

Unclear. A session-key allowlist is plausible for trusted group sharing, but maintainers should first choose whether the durable model is session-pattern based, per-capability, per-agent, A2A-specific, or a consolidated combination.
