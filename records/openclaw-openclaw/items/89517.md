- `merge-risk: 🚨 compatibility`: The PR changes existing hot-mode file and RPC restart behavior for current deployments.

- `merge-risk: 🚨 availability`: Security-critical config edits can now restart a hot-mode gateway, while routine RPC writes can avoid a restart and leave runtime/process state inconsistent.

## Summary

Keep this PR open: the security-critical hot-mode restart carve-out is promising and final-head live proof is now supplied, but the RPC path change is not safe as written because config RPC writes refresh the active runtime snapshot before the reload decision runs, so routine restart-required `config.patch`/`config.apply` writes can leave restart-required config reflected in-process without a restart.

## What This Changes

The PR changes gateway hot-mode reload handling so security-critical auth/profile/provider-secret changes restart, routine hot-mode changes warn-and-keep, config RPC writes share that policy, and docs/tests describe the behavior.

## Best Possible Solution

Keep the security-critical hot-mode carve-out, but preserve direct restart for routine restart-required config RPC writes or add a mechanism that defers runtime snapshot activation until an explicit restart applies those settings.
