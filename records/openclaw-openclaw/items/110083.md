## Label Justifications

- `P0`: The PR targets a shipped upgrade crash loop that can leave the Gateway unusable, while the proposed precedence rule also touches persisted plugin state.
- `merge-risk: 🚨 compatibility`: The patch changes upgrade-time conflict resolution and automatically archives a legacy database that current releases leave available for recovery.
- `merge-risk: 🚨 session-state`: The new timestamp rule can retire a divergent plugin-state value when canonical and sidecar timestamps are equal.

## Summary

The fix direction is appropriate, but this PR can silently retire a genuinely divergent sidecar row when both rows have the same timestamp, and the supplied validation is test-only rather than an observed upgrade/startup run.

## What This Changes

Changes plugin-state sidecar migration to archive rows when canonical timestamps are equal or newer, updates the conflict diagnostic, and revises the focused migration tests.

## Best Possible Solution

Treat a row as satisfied only when all compared fields match or the canonical `created_at` is strictly newer; keep equal-timestamp divergent rows as conflicts, cover that case, and demonstrate a real v2026.6.11-to-current upgrade reaching readiness twice without changing the canonical value.
