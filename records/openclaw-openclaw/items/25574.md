## Summary

Keep open: current main and the latest release still emit config warnings directly without a warning-payload dedupe guard, and the issue is member-authored with an open linked maintainer PR that owns the fix path.

## What This Changes

The issue asks OpenClaw to log each stable config warning payload once instead of re-emitting the same warning on every config reload or CLI config load.

## Best Possible Solution

Land or replace the open maintainer PR with a narrow config-warning dedupe fix that covers load/write warning payloads, re-logs when warning content changes, and preserves current config compatibility.

## Reproduction Assessment

Yes for a source-level repro: disabled plugin config still creates the reported warning, and the current load/write paths still emit each warning payload without a warning-level dedupe guard. I did not run a live multi-hour gateway scenario in this read-only review.

## Solution Assessment

Yes on direction: deduping stable warning payloads at the config IO/logging boundary is the narrow maintainable fix. The current linked PR needs rebase or narrowing before it is the best landing vehicle.
