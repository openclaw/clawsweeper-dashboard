## Summary

Keep open: current main and v2026.6.11 still drop parsed OpenAI-compatible streamed tool calls when the stream ends without a final finish reason, and the open linked PR is the implementation candidate rather than a close reason before merge.

## What This Changes

The issue asks OpenClaw to execute valid streamed OpenAI-compatible `delta.tool_calls` when the provider omits a final `finish_reason` but ends the stream cleanly.

## Best Possible Solution

Review and land the open fix PR if maintainers accept clean SSE `[DONE]` plus native structured tool-call deltas as enough tool-use intent, while preserving fail-closed behavior for EOF-only and ambiguous streams.

## Reproduction Assessment

Yes at source level: current main parses streamed `tool_calls`, skips promotion without a finish reason, and then strips `toolCall` blocks because the stop reason is not `toolUse`. I did not run the reporter's live Evolink route in this read-only review.

## Solution Assessment

Yes, the best direction is a narrow transport fix that distinguishes clean SSE `[DONE]` from truncated EOF and applies only to native structured tool-call deltas. The open fix PR targets that boundary, so this issue should stay open until it lands or maintainers reject the compatibility contract.
