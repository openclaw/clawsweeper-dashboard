## Summary

Keep open: current main still intentionally shortens home-contained paths to `~/...` or `$OPENCLAW_HOME/...`, and the merged related fixes only addressed sibling-prefix corruption. The remaining request is a product/display contract choice, not an implemented bug fix.

## What This Changes

Require agent-visible file path output to use full absolute paths instead of home-relative `~/...` shorthand.

## Best Possible Solution

Define one central path-output contract for agent-visible replies and tool displays, then update shared helpers, prompts, docs, and tests consistently; if full paths should be optional, keep the current default and add a documented upgrade-safe mode.
