## Summary

Keep open: current main still intentionally shortens home-contained paths to `~/...` or `$OPENCLAW_HOME/...`, and the merged related fixes only repaired sibling-prefix corruption while preserving shorthand for real home paths. The remaining work is a path-display product contract decision, not an already-implemented bug fix.

## What This Changes

The issue requests that agent-visible file paths be shown as full absolute paths instead of home-relative `~` shorthand.

## Best Possible Solution

Define one explicit path-output contract for agent-visible replies and tool displays, then implement it centrally across shared helpers, UI/TUI renderers, docs, and tests; if full paths should be optional, add a documented upgrade-safe mode rather than ad hoc post-processing.
