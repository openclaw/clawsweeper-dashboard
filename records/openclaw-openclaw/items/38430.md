## Summary

Keep open: current main still intentionally emits home-relative display paths in agent/tool/TUI surfaces, and the merged related fix only stopped sibling-prefix path corruption while preserving `~/...` for real home paths. The remaining question is a product/display contract decision, not an already-implemented bug fix.

## What This Changes

The issue requests that agent responses expand home-directory shorthand such as `~/...` into full absolute file paths.

## Best Possible Solution

Define one explicit path-output contract for agent-visible replies and tool displays, then implement it centrally across the shared helpers and tests; if maintainers prefer full paths only as an opt-in, add a documented setting with upgrade-safe defaults instead of ad hoc post-processing.
