## Summary

Keep open: current main still intentionally shortens real home-contained paths to `~/...` or `$OPENCLAW_HOME/...`, and the merged related PRs only fixed sibling-prefix corruption while preserving shorthand. The remaining question is a product/display contract decision, not an implemented bug fix.

## What This Changes

The issue requests that agent-visible file paths use full absolute paths instead of `~` home shorthand.

## Best Possible Solution

Define one central path-output contract for agent-visible replies and tool displays; if full paths are desired, update the shared helpers, session renderers, terminal-core behavior, docs, and tests consistently after maintainer approval.
