## Summary

Keep open: current main and the latest release still intentionally shorten real home-contained paths to `~/...` or `$OPENCLAW_HOME/...`; the merged related fix only corrected sibling-prefix corruption, so the remaining full-absolute-path behavior is a product display-contract decision.

## What This Changes

The issue asks OpenClaw to stop emitting home-relative `~/...` file paths in agent-visible output and use full absolute paths instead.

## Best Possible Solution

Define one explicit user-visible path display contract, then implement it centrally across shared helpers, session/tool displays, prompts, and tests; if full paths are desired only for some users, use a documented opt-in with the current compact default preserved.
