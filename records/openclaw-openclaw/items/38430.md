Keep open: current main and v2026.6.11 still intentionally compact home-contained paths to `~` or `$OPENCLAW_HOME` across shared helpers and agent/session display surfaces. The related merged PRs fixed corrupted sibling-prefix shortening while preserving compact display, so the broader full-absolute-path request still needs a maintainer product decision.

## What This Changes

The issue asks OpenClaw to stop showing home-relative `~` shorthand in agent-visible file paths and use full absolute paths instead.

## Best Possible Solution

Define one central user-visible path-display contract, then update shared helpers, session/tool displays, terminal-core, SDK text exports, prompts, docs, and tests consistently if maintainers choose full paths or an explicit full-path mode.
