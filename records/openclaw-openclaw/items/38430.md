## Summary

Keep open: current main and the latest release still intentionally shorten home-contained paths to `~/...` or `$OPENCLAW_HOME/...` across display helpers, TUI session tool rendering, terminal display, auto-reply progress, and skill prompts. The merged related work fixes sibling-prefix corruption, but it deliberately preserves tilde shortening for real home paths, so the remaining request is a product/path-output contract decision rather than implemented cleanup.

## What This Changes

The issue requests that agent-visible file path references use full absolute paths instead of `~` home shorthand.

## Best Possible Solution

Maintainers should define the path-display contract by surface, then update only the accepted prompt/display helpers and tests; avoid a new env var unless maintainers explicitly want an opt-in mode.
