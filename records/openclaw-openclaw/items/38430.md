## Summary

Keep open: current main and the latest release still intentionally render home-contained paths as `~/...` or `$OPENCLAW_HOME/...`, and the merged related work only fixed corrupted sibling-prefix shortening. This needs a maintainer display-contract decision before code automation.

## What This Changes

The issue asks OpenClaw agent responses to use full absolute file paths instead of `~` home-directory shorthand.

## Best Possible Solution

Define one central user-visible path display contract, then update shared helpers, session/tool displays, prompts, docs, and tests consistently.

Question: Should OpenClaw keep compact home-relative path display by default, switch agent-visible paths to full absolute paths, or add an explicit full-path mode?

Rationale: Current source and tests intentionally shorten true home-contained paths, related fixes preserved that behavior, and changing it affects UX, privacy, prompts, docs, and possible config surface.

Likely owner: Peter Steinberger

Owner confidence: high

Options:

- **Keep Compact Default (recommended):** Preserve `~/...` and `$OPENCLAW_HOME/...` for true home-contained paths while continuing to fix corrupt or non-copyable path rewrites.
- **Switch Default To Full Paths:** Make agent-visible path output use full absolute paths everywhere and update helpers, prompts, docs, and regression tests consistently.
- **Add Full-Path Mode:** Keep the compact default but add a documented opt-in mode for users who need full absolute paths in responses and tool displays.

## Solution Assessment

No, not as currently suggested. A prompt-only or output post-processor could be too narrow because several shared helpers and tests intentionally encode compact home display, so maintainers should choose the display contract first.
