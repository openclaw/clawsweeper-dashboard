## Summary

Keep open: current main still intentionally emits home-relative path display in agent/tool/TUI surfaces, and the merged related fixes only prevent sibling-prefix corruption while preserving shorthand for real home-contained paths. The remaining issue is a product/display contract decision, not an already-implemented bug fix.

## What This Changes

The issue requests that OpenClaw agent-visible file paths use full absolute paths instead of home-relative `~/...` shorthand.

## Best Possible Solution

Define one central path-output contract for agent-visible replies and tool displays, then update shared helpers, prompts, docs, and tests consistently; if full paths should be optional, keep the current default and add a documented upgrade-safe mode.
