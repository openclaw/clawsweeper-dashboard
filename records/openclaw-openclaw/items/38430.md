## Summary

Keep open: current main still intentionally renders home-contained paths as `~/...` or `$OPENCLAW_HOME/...`, and the merged related fixes only prevent corrupt sibling-prefix shortening. The remaining work is a product/display-contract decision, not an already-implemented bug fix.

## What This Changes

The issue requests that agent responses use full absolute file paths instead of `~/...` home-relative shorthand.

## Best Possible Solution

Define one explicit path-output contract for agent-visible replies and tool displays, then implement it centrally across shared helpers, session/TUI surfaces, docs, and tests; if full paths should be optional, add an upgrade-safe documented mode instead of ad hoc post-processing.
