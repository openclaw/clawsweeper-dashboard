## Summary

Keep open. The report is a well-defined, source-reproducible bug: owner-qualified identity is available in skill status but is not carried into the bulk verdict target, and the documented bulk API has no owner-aware request field. The skill remains usable, so this is misleading operator-facing verification state rather than an outage. Cleanup closure is also prohibited because the author is a repository member and the issue has the protected `maintainer` label.

## What This Changes

Correct owner-qualified ClawHub verdict resolution so the Control UI displays the installed skill's clean security result instead of Unavailable.

## Best Possible Solution

Make owner-qualified identity canonical through `skills.securityVerdicts`: retain `ownerHandle`, add owner-aware bulk resolution in the ClawHub contract or a narrowly bounded single-verification fallback, and cover ambiguous-slug plus ordinary unqualified installations without changing the UI's verdict source of truth.

## Reproduction Assessment

Yes at the source-and-contract level: skill status retains the owner-qualified identity, the verdict collector omits it, and the documented bulk endpoint accepts only slug/version. A fresh current-main live gateway run was not performed, so this is classified as source-reproducible rather than independently reproduced.

## Solution Assessment

No, merely adding `ownerHandle` to OpenClaw's existing bulk payload is not sufficient under the published ClawHub API contract. The maintainable fix is coordinated owner-aware batch resolution or a focused fallback for owner-qualified not-found results, with regression coverage for both ambiguous and ordinary slugs.
