## Summary

Keep open: the patch looks like the right narrow code fix for the linked `sessions.usage` cache-reparse bug, but this external PR still lacks after-fix real gateway or Control UI proof showing the `rss_growth` warning no longer trips.

## What This Changes

The PR changes `sessions.usage` to group visible and hidden sessions by agent and call `loadSessionCostSummariesFromCache` once per agent instead of calling the single-session cache loader for each visible entry.

## Best Possible Solution

Land the narrow batched-loader fix after live gateway or Control UI proof shows `sessions.usage` no longer triggers the false `rss_growth` warning, while leaving broader Gateway usage-cost isolation to https://github.com/openclaw/openclaw/issues/86718.

## Reproduction Assessment

Yes, at source level: current main builds one visible-session cache-summary task per returned visible session, and each task reads the durable usage-cost cache. I did not run a live RSS replay, but the linked issue provides v2026.6.11 `limit=50` versus `limit=1` measurements that match this path.

## Solution Assessment

Yes for the narrow bug: reusing the existing batched cache loader is cleaner than adding a new cache layer or changing diagnostic thresholds. Merge readiness still depends on real after-fix behavior proof from a gateway or dashboard run.
