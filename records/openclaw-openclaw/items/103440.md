## Label Justifications

- `P1`: Current Google Chat handling can silently omit attachments and suppress an already-acknowledged message from the agent pipeline when an attachment download fails.
- `merge-risk: 🚨 availability`: The PR converts one capped media operation into a potentially larger synchronous batch without a demonstrated count or aggregate-byte limit.

## Summary

Keep open: current main clearly exhibits the reported Google Chat message-loss path and the patch appears functionally sound, but this external PR lacks required after-fix proof from a real Google Chat setup; processing the full attachment array also expands cumulative request work without a demonstrated batch boundary.

## What This Changes

The PR processes every Google Chat inbound attachment independently, preserves successful downloads in message order, logs individual failures, and adds regression tests for multi-attachment and partial-failure cases.

## Best Possible Solution

Keep the failure-isolating Google Chat-local loop and shared media-array contract, but demonstrate realistic multi-attachment behavior under the existing per-file limit and establish an explicit or evidence-backed batch boundary before landing.
