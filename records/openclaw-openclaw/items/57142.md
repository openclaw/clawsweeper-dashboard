## Summary

Keep open: current main and v2026.6.11 still only support slash-command textarea suggestions in the WebChat composer, with no custom-term source or non-slash match path. This is useful WebChat ergonomics work, but it needs maintainer product scoping for the shared suggestion UX and persistence/source boundary rather than conservative cleanup close.

## What This Changes

Request configurable custom-term autocomplete or suggestions in the WebChat chat input, especially for project terms used with dictation.

## Best Possible Solution

Define one shared, accessible composer suggestion contract and choose the canonical custom-term source before implementation, coordinating with adjacent @agent autocomplete and typo-assistance work.

## Reproduction Assessment

Yes, as a source-level absence check rather than a broken-existing-behavior repro. Current main has slash-only matching, a textarea composer, and no persisted WebChat custom-term source.

## Solution Assessment

Unclear. The requested UX is plausible, but a standalone config key or suggestions file is not proven to be the best fix until maintainers choose the shared composer suggestion and storage boundary.
