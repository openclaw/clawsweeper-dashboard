## Summary

This issue is still necessary: current main documents `planTool: false` as keeping `update_plan` off, but the registration helper lets an allowlist independently re-enable the tool before that false setting can control the assembled model tool set.

## What This Changes

Make `tools.experimental.planTool: false` suppress `update_plan` from the advertised agent tool schema rather than only preventing or rejecting its execution.

## Best Possible Solution

Make explicit `tools.experimental.planTool: false` a hard registration precondition, then add an assembled-tool regression that proves no allowlist or `coding` profile path can advertise `update_plan` while the flag is false.
