## Summary

Keep this PR open for a browser-owner decision on the intentional recovery contract. The patch removes the unsafe route-level adoption heuristics and carries backend outcomes instead, with direct Chrome/CDP route proof; the remaining question is whether returning a stale acted-on target when continuity is unprovable is the supported public behavior for existing callers.

## What This Changes

## Best Possible Solution

Adopt one documented browser-route contract: return an exact backend-owned target when it is provable, otherwise preserve the acted-on stale ID and require an explicit fresh tab selection; retain the deferred relay public-identity work as a separate contract change.
