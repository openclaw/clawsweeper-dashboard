Keep open: the patch fixes one real post-registration failure path, but the guarded cleanup still starts too late to close the linked Codex run-attempt cleanup bug, and the external PR has only mock/test proof so far.

## What This Changes

The PR extracts the Codex app-server turn cleanup into a helper, wraps active-run registration through completion in a `try/finally`, and adds a regression test for notifier construction throwing after registration.

## Best Possible Solution

Move the guarded cleanup boundary above all post-turn/start setup, or use a disposer stack that registers each resource when acquired, then add proof for both the notifier throw and an earlier post-acceptance throw path.

## Reproduction Assessment

Yes, at source level: current main and the PR head both have post-turn/start setup before the new guarded cleanup boundary, and `params.onExecutionPhase` can throw synchronously there. I did not run a live failing app-server attempt in this read-only review.

## Solution Assessment

No: this is a useful partial fix, but it is not the best final shape because the cleanup owner still starts after several post-acceptance operations. The safer fix is one cleanup boundary or disposer stack covering all resource ownership after client acquisition or at least all code after `turn/start` succeeds.
