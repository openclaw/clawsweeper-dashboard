## Summary

Keep this PR open: the patch is a focused hardening change and I found no line-level correctness defect, but the new 16 MiB fail-closed threshold is a compatibility decision maintainers should explicitly accept or tune before merge.

## What This Changes

Adds a module-local 16 MiB `maxPayload` cap to the OpenAI realtime voice backend WebSocket constructor.

## Best Possible Solution

Merge this owner-local cap only after maintainers accept 16 MiB as the intended realtime voice threshold, or tune the constant from representative vendor-frame evidence before merge.

## Reproduction Assessment

Yes, source-level: current main constructs the OpenAI realtime voice backend WebSocket without `maxPayload`, and `ws` 8.21.0 defaults that client option to 100 MiB. The PR body provides after-fix loopback output showing a 16 MiB+ frame rejected with close status 1009.

## Solution Assessment

Yes for the implementation shape: setting `maxPayload` at the owner-local OpenAI voice WebSocket constructor uses the dependency's built-in enforcement and avoids new config surface. The unresolved part is whether 16 MiB is the right maintained threshold for supported realtime voice sessions.
