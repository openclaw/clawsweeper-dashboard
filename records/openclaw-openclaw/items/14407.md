## What This Changes

The issue requests consistent show/hide controls for password, token, and API-key fields across web, desktop, iOS, and Android surfaces.

## Best Possible Solution

Implement reusable masked-by-default reveal controls per UI stack, reuse the existing Control UI sensitive-value pattern where practical, and leave any persisted visibility preference behind an explicit maintainer security/product decision.

## Reproduction Assessment

Yes, for source-level verification: current main still has credential fields without reveal controls in web Skills, macOS/iOS SwiftUI, and Android Compose surfaces. This proves the feature remains incomplete rather than reproducing a broken existing contract.

## Solution Assessment

No, not as a blanket persisted clear-text preference. The safer maintainable path is masked-by-default reveal controls using native UI primitives and existing Control UI patterns, with persistence decided separately by maintainers.
