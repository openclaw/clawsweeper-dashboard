## Summary

Keep open: current main still has partial web reveal controls, but the requested cross-platform credential reveal pattern remains missing on native and some credential-entry surfaces, and the linked implementation attempts are closed unmerged.

## What This Changes

The issue requests a cross-platform password/secret reveal toggle, with an eye icon and persisted visibility preference, for web, desktop, iOS, and Android credential fields.

## Best Possible Solution

Implement masked-by-default reusable sensitive-input reveal controls across web, macOS, iOS, and Android, reusing the existing web pattern where possible and persisting visibility only if maintainers approve the security tradeoff.

Rationale: The useful UX request is clear, but the proposed persistent clear-text preference changes how credentials can be exposed on shared, streamed, or recorded devices.

Options:

- **Ephemeral Reveal Only (recommended):** Implement per-field reveal controls that reset to masked by default and do not persist visibility state across sessions.
- **Persist Visibility Preference:** Allow local persistence of reveal state after maintainers explicitly accept the credential exposure tradeoff and define reset behavior.
- **Defer Broad Rollout:** Keep the existing partial web behavior and defer native/platform work until a full sensitive-field inventory is owned.

## Solution Assessment

No, not exactly as requested if the solution persists clear-text visibility by default. The safer maintainable path is reusable masked-by-default reveal controls with persistence decided separately by maintainers.
