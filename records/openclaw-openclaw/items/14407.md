## Summary

Keep open: current main and the latest release still only have partial web reveal controls, while web Skills API-key editing and multiple native credential-entry surfaces still lack the requested reveal pattern. The issue also needs maintainer security/product direction because the proposal includes persisted clear-text visibility behavior.

## What This Changes

The issue requests eye-icon show/hide controls for masked password, token, and API-key fields across web, desktop, iOS, and Android, including a persisted visibility preference.

## Best Possible Solution

Implement reusable masked-by-default reveal controls across web Skills/API-key and native credential fields, reset visibility per field/session unless persistence is explicitly approved, and cover touched surfaces with focused web/native tests.

- **Defer Broad Rollout:** Keep the existing partial web behavior until maintainers complete a credential-field inventory and platform plan.
