## Summary

Keep open: the requested cross-platform sensitive-input reveal pattern remains useful, while the known implementation attempts are closed unmerged and the proposed persisted visibility preference still requires explicit product and security direction.

## What This Changes

Add consistent show/hide controls for password, token, and API-key inputs across the Control UI and native companion apps.

## Best Possible Solution

Adopt reusable platform-native sensitive-input controls that are masked by default, reveal only through an explicit accessible action, keep visibility ephemeral unless maintainers approve persistence, and cover each inventoried web and native credential surface with focused UI proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should sensitive-input visibility always reset to masked on navigation or relaunch, or may any platform persist a user's clear-text visibility preference?

Rationale: The implementation mechanics are standard, but persistence changes the shoulder-surfing and accidental-disclosure posture and cannot be selected safely from code evidence alone.

Likely owner: steipete

Owner reason: Recent merged work and supplied history connect this person to the affected Control UI and native app surfaces, and they already reviewed this issue's scope.

Owner confidence: medium

Options:

- **Ephemeral reveal (recommended):** Keep every sensitive field masked by default and reset visibility when the field, view, or app lifecycle ends.
- **Session-scoped reveal:** Allow visibility to survive navigation within one active app session but reset on reload or relaunch.
- **Persistent preference:** Persist visibility across reloads or launches, accepting the increased accidental-disclosure risk.

## Reproduction Assessment

Yes at source level: existing reveal controls and uncovered sensitive-input surfaces are specifically identified, although no live cross-platform run was performed for this review.

## Solution Assessment

No: a persisted localStorage-style visibility preference is not the safest default; the narrower maintainable solution is a reusable, accessible, ephemeral reveal control using each platform's native secure-input pattern.
