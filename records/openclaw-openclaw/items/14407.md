## Summary

Keep open: current main has partial reveal controls in web gateway access/config, but Skills/API-key and native mobile/desktop credential fields still lack a consistent masked-by-default reveal pattern; the remaining behavior is security/product-sensitive because the requested persistent clear-text preference could expose secrets.

## What This Changes

Request to add consistent password/token/API-key visibility toggles across OpenClaw web, desktop, iOS, Android, and related credential entry surfaces.

## Best Possible Solution

Implement reusable masked-by-default sensitive-input reveal controls per UI stack, reuse the existing Control UI reveal pattern where possible, and treat persisted visibility as a separate security/product decision.

## Reproduction Assessment

Yes, source-level verification is high confidence: current main still has credential fields without reveal controls across web Skills, macOS/iOS SwiftUI, and Android Compose. This proves the requested feature remains incomplete rather than reproducing a broken existing contract.

## Solution Assessment

No, not as a blanket persisted clear-text preference. The safer maintainable path is reusable masked-by-default reveal controls, with any persistent visibility behavior decided explicitly by maintainers.
