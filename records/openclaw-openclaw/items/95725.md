## Label Justifications

- `P1`: The PR addresses a recurring cron regression where intentionally silent watcher jobs can fail every scheduled run and mask real failures with false `empty_response` status.

## Summary

Keep open for maintainer review: the patch is a clean executor-boundary fix with no concrete code findings and sufficient real-behavior proof, but it deliberately changes cron empty-reply policy for delivered and non-delivered jobs.

## What This Changes

The branch adds `allowEmptyAssistantReplyAsSilent: true` to both isolated cron `runCliAgent` and `runEmbeddedAgent` calls and adds a focused regression test for flag propagation.

## Best Possible Solution

Land one canonical executor-boundary fix after maintainers choose the all-cron silent-empty policy, then close or supersede the overlapping silent-cron PRs and keep broader per-job configuration work separate if still wanted.
