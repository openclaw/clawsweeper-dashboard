## Summary

Keep open: the patch is small, source-backed, and well-proven, but it deliberately changes cron empty-output semantics from failure to silent success, so maintainer acceptance and canonical-PR selection are still needed before merge.

## What This Changes

The branch passes `allowEmptyAssistantReplyAsSilent: true` from the isolated cron executor into both CLI and embedded runner calls, with regression tests for both handoffs.

## Best Possible Solution

Land one executor-boundary fix that applies the chosen silent-empty cron policy to both CLI and embedded paths, then close or redirect the competing related PRs; if maintainers want stricter semantics, revise this to a delivery-gated or per-job policy before merge.
