## Label Justifications

- `P1`: The patch would break an existing foreground CLI workflow for users who target a running container.
- `merge-risk: 🚨 compatibility`: A new unconditional 120-second deadline changes the behavior of existing `--container` command invocations.

## Summary

The PR should stay open, but its container-execution timeout is unsafe: `--container` forwards arbitrary CLI commands, including the documented foreground Gateway run, so the new 120-second deadline would terminate valid long-running commands. The DNS and plain-GitHub-helper changes remain plausible, but need a narrow container fix and after-fix runtime evidence.

## What This Changes

The branch adds default synchronous-process timeouts to DNS setup commands, container-targeted CLI execution, and plain GitHub CLI helpers.

## Best Possible Solution

Keep the container command itself unbounded, add a deadline only to short runtime-discovery calls such as Docker/Podman inspection, and add focused coverage proving foreground container commands retain their lifetime while unavailable runtime discovery fails promptly.
