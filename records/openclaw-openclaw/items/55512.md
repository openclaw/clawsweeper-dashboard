## Summary

Keep open. Current main and v2026.6.11 still use code-unit length for markdown code-table width and padding, while the open linked PR remains the implementation candidate but needs to be ported to the active markdown-core path.

## What This Changes

The issue requests CJK display-width-aware Markdown table rendering for Telegram and Discord so aligned code/table fallbacks do not shift wide characters.

## Best Possible Solution

Port display-width measurement and padding into `packages/markdown-core`, add focused CJK/emoji table tests, keep Telegram and Discord on the shared converter, and resolve the linked PR rather than restoring `src/markdown`.

## Reproduction Assessment

Yes. Source inspection shows current main still measures code-table cell width and padding with `cell?.text.length`, and Telegram plus Discord route table conversion through that shared renderer; I did not run a live Telegram or Discord repro.

## Solution Assessment

Yes for the shared-renderer direction, but not via the stale branch as submitted. The narrow maintainable fix belongs in `packages/markdown-core` with regression coverage, not by reviving removed `src/markdown` files.
