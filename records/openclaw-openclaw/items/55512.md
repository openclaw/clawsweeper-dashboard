Keep open. Current main and v2026.6.11 still pad markdown code-table columns with JavaScript string length, so the CJK display-width bug remains; the open linked PR is still the candidate fix but currently targets obsolete renderer paths.

## What This Changes

The issue requests CJK display-width-aware markdown table rendering for Telegram and Discord, with Discord converting unsupported raw tables into aligned code blocks.

## Best Possible Solution

Port display-width measurement and padding into `packages/markdown-core`, add focused CJK/emoji table tests, keep Telegram and Discord on the shared converter, and land or replace the linked PR before closing this issue.

Yes, source-level. Current main and v2026.6.11 still compute code-table widths and padding with `cell?.text.length`, while both channels route table conversion through that shared renderer.

## Solution Assessment
