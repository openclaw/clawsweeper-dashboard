## Summary

Keep open. Current main still measures Markdown code-table widths and padding with UTF-16 string length, so CJK/wide glyph alignment remains broken, and the open closing PR is still the active but conflicting implementation candidate.

## What This Changes

The issue requests CJK-aware Markdown table rendering for Telegram and Discord, including monospace/code table conversion where native GFM tables are unsupported.

## Best Possible Solution

Port display-width measurement and padding into `packages/markdown-core`, add focused CJK/emoji code-table regression tests, keep Telegram and Discord on the shared converter, and land or replace https://github.com/openclaw/openclaw/pull/55596 before closing this issue.

## Reproduction Assessment

Yes, source-level. Current main still measures and pads Markdown code-table cells with `cell?.text.length`, and Telegram plus Discord route table conversion through that shared renderer.

## Solution Assessment

Yes for the shared-renderer direction, but not through the stale linked branch as-is. The narrow maintainable fix belongs in `packages/markdown-core`, not by reviving deleted `src/markdown` files.
