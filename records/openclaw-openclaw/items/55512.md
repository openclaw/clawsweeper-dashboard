## Summary

Keep open. Current main still computes Markdown code-table column widths and padding with JavaScript string length, so CJK display-width alignment remains unfixed; Discord's raw-pipe fallback path is now converted through the shared table converter, but the shared converter still undercounts wide characters.

The issue reports CJK display-width misalignment in Markdown table rendering for Telegram and Discord.

## Best Possible Solution

Port display-width measurement and padding into `packages/markdown-core`, add focused CJK and emoji table tests, keep Telegram and Discord on the shared converter, and land or replace the linked implementation PR before closing this issue.
