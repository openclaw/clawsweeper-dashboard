## Summary

Keep open. Current main and the latest release still use UTF-16 string length for Markdown code-table width and padding, and the linked implementation PR remains open but conflicting against obsolete `src/markdown` paths.

## What This Changes

The issue asks OpenClaw to render Markdown tables with CJK-aware column widths in Telegram and Discord, including Discord code-block conversion instead of raw GFM pipes.

## Best Possible Solution

Port display-width measurement and padding into `packages/markdown-core`, add focused CJK/emoji code-table tests, keep Telegram and Discord on the shared converter, and close this issue only after the linked PR lands or is replaced.
