## Summary

Keep open. Current main and the latest release still use code-unit string length for Markdown code-table width and padding, so CJK display-width alignment remains unfixed; the linked implementation PR is still open but conflicting and targets removed renderer files.

## What This Changes

Request to fix Markdown table rendering so Telegram and Discord align CJK table columns by display width and use code-block-safe table output where native tables are unsupported.

## Best Possible Solution

Port display-width measurement and padding into `packages/markdown-core`, add focused CJK/emoji table tests, keep Telegram and Discord on the shared converter, and land or replace the linked PR before closing this issue.

## Reproduction Assessment

Yes, source-level. Current main still measures code-table cell width and padding with `cell?.text.length`, and both Telegram and Discord route Markdown table conversion through that shared renderer.

## Solution Assessment

Yes for the shared-renderer direction, but not via the stale linked branch as-is. The narrow maintainable solution is a markdown-core display-width fix with focused channel coverage, not restoring old `src/markdown` files.
