## Summary

Keep open. Current main and the latest release still compute Markdown code-table widths and padding with JavaScript string length, so CJK display-width alignment remains unfixed; the Discord raw-table part is partly addressed by current table conversion, but the shared code-table output is still not CJK-aware and the open linked implementation PR is conflicting.

## What This Changes

The issue requests CJK display-width-aware Markdown table rendering for Telegram and Discord, with Discord tables converted to monospace/code output instead of raw GFM pipes.

## Best Possible Solution

Port the display-width calculation and regression tests into `packages/markdown-core`, keep Telegram and Discord on the shared converter, refresh visible Telegram/Discord proof for the ported head, then close this issue after the linked PR or a credited replacement lands.

## Reproduction Assessment

Yes, source-level: the active markdown-core table renderer still measures CJK table cells with `cell?.text.length`, and Telegram plus Discord paths can reach that renderer. I did not run fresh live transport proof in this read-only review.

## Solution Assessment

Yes for the shared-renderer direction, but not via the stale linked branch as submitted. The narrow maintainable fix is a markdown-core display-width port with focused CJK/emoji table tests and channel-path validation.
