## Summary

Keep open. Current main and the latest release still use UTF-16 string length for Markdown code-table width and padding, so the CJK alignment bug remains even though Discord now routes tables through the shared converter; the open linked PR is still the implementation candidate but has not landed.

## What This Changes

The issue asks for CJK display-width-aware Markdown table rendering in Telegram and Discord, with Discord tables rendered as aligned code blocks instead of raw pipe text.

## Best Possible Solution

Port display-width measurement and padding into `packages/markdown-core`, add focused CJK/emoji Markdown table regression tests, keep Telegram and Discord on the shared converter, then land or replace the linked PR.
