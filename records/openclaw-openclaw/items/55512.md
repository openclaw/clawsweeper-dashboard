The issue reports CJK display-width misalignment in Markdown tables sent through Telegram and Discord.

## Best Possible Solution

Port the useful display-width logic from https://github.com/openclaw/openclaw/pull/55596 into `packages/markdown-core`, keep Telegram and Discord on the shared converter, and then review or close that PR based on the ported result.

Yes. Source inspection shows the shared Markdown code-table renderer still uses `cell.text.length` for width and padding, while Telegram and Discord route table fallback through that renderer.

## Solution Assessment

Yes for the shared-renderer direction, but not as a separate new repair lane while the linked PR remains open. The maintainable fix is a markdown-core port with focused regression tests, not a Telegram-only or Discord-only workaround.
