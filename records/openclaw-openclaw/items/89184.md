## Summary

Current main fixes the LINE account-resolution and webhook-registration paths well enough for this report: default-account credentials under `accounts.default` are resolved, configured named accounts default to enabled, and channel startup registers webhook routes against the gateway-owned plugin HTTP route registry. The fix is main-only; the latest checked release still has the old resolver shape.

## What This Changes

The issue reports that after upgrading to OpenClaw and `@openclaw/line` 2026.5.28, POST requests to `/line/webhook` return 404 even though the LINE plugin loads and starts.

## Best Possible Solution

Keep the current main LINE resolver and route-registration behavior, ship it in the next release, and use https://github.com/openclaw/openclaw/issues/94572 only for the broader runtime-loaded workspace-plugin route/service lifecycle gap.

## Solution Assessment

Yes. The owner-plugin resolver fix plus gateway-owned route registry wiring is the narrow maintainable solution for LINE webhook routes not registering; the unrelated runtime-loaded workspace-plugin route/service lifecycle gap remains tracked separately.
