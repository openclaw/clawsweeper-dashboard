Full review comments:

- **[P1] Move dashboard runtime state into SQLite/plugin KV:** `extensions/dashboard/src/store.ts:45-46`
  - body: This store seeds and writes `<stateDir>/dashboard/workspace.json` plus undo JSON files at runtime. Root policy requires OpenClaw-owned runtime state, registries, and caches to use the shared state DB, plugin KV, or another explicit SQLite owner unless a named product artifact/exception is approved; because this plugin is enabled by default, merging creates a new persisted data model and upgrade surface outside the canonical store.
  - confidence: 0.93
- **[P2] Honor the approved widget manifest entrypoint:** `ui/src/components/dashboard-custom-widget.ts:219`
  - body: `widget.json` requires and validates an `entrypoint`, but the UI read model drops that field and the iframe host always loads `index.html`. Any approved widget with a valid non-`index.html` entrypoint will be approved and served but render the wrong file or fail, so the manifest contract should carry `entrypoint` through `WidgetManifestView` and use it for the iframe `src`.
  - confidence: 0.88
- **[P2] Apply the widget CSP on route-owned 404s:** `extensions/dashboard/src/serve.ts:126-128`
  - body: `notFound()` handles malformed, pending, rejected, and missing widget requests under the unauthenticated route, but it omits `Content-Security-Policy` and `Referrer-Policy`; the new tests even assert CSP is absent on traversal 404s. The PR's security model says widget responses are locked down structurally, so route-owned 404s should set `WIDGET_CSP` as well as `nosniff`.
  - confidence: 0.86
