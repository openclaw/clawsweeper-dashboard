## Summary

Keep open: current main and v2026.6.11 still use raw manifest alias keys, while this PR fixes that documented case-insensitive alias behavior and preserves exact-key precedence. The patch looks correct, but because it can change provider/model selection for existing policy maps, maintainer acceptance of the routing compatibility effect is still needed before merge.

## What This Changes

Adds a shared model-catalog alias resolver that scans normalized manifest alias keys after exact normalized-key lookup, plus regression tests for fallback matching and precedence.

## Best Possible Solution

Merge the current head after maintainers accept applying the documented case-insensitive alias contract to the shared prepared policy-map lookup, with exact-key precedence preserved.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 index aliases by only the normalized input key, so a supplied policy map with alias key " GPT-5.4 " misses lookup for model "gpt-5.4".

## Solution Assessment

Yes. The PR fixes the shared lookup layer used by prepared policy maps while preserving exact normalized-key precedence; normalizing at collection time would risk changing duplicate-key collision semantics earlier.
