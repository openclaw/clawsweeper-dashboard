## What This Changes

## Best Possible Solution

## Reproduction Assessment

Yes, from source inspection. Current main indexes aliases by only the normalized input key, so a supplied policy map with alias key `" GPT-5.4 "` misses lookup for model `gpt-5.4`.

## Solution Assessment

Yes. The PR fixes the shared lookup layer used by prepared policy maps while preserving exact normalized-key precedence; normalizing at collection time would risk changing duplicate-key collision semantics earlier.
