## Summary

Keep open. This is a concrete Mattermost message-loss report with a configuration-specific path and production evidence; the related open reports share the draft-preview lifecycle but describe different later writers, so none is a safe canonical replacement. The reported one-chunk final versus multi-chunk control is a useful discriminator, but the exact final-write ordering still needs a current-main deterministic regression before closing or claiming a fix.

## What This Changes

Fix Mattermost preview streaming so an end-of-turn Active Memory verbose status cannot overwrite a finalized single-chunk assistant answer in the shared draft post.

## System Context

Mattermost preview streaming uses one temporary post for progress updates and may finalize a short assistant answer by editing that post in place. Agent verbose or plugin status payloads also flow through channel delivery, so their lifecycle must not reuse a post after it has become the visible final answer.

## Best Possible Solution

Make the Mattermost draft lifecycle treat a successfully finalized preview as an immutable visible answer: route a later verbose/plugin payload to a separate post, and add ordered regression coverage for both final→verbose and verbose→final delivery.
