- `merge-risk: 🚨 compatibility`: The PR adds a documented public Plugin SDK API whose access and delivery semantics become an upgrade-sensitive contract.

## Summary

This PR remains necessary: current evidence does not show the anonymous Talk-activity feed on `main`, and the related managed-session PRs explicitly describe themselves as independent. The raw-PCM concern from the earlier review is addressed, but the remaining public SDK design still lets every plugin subscribe to process-wide live Talk timing; that trust and compatibility boundary needs an explicit maintainer decision before merge.

## What This Changes

The PR adds `api.runtime.talk.watch` so plugins can observe anonymous Talk lifecycle, state, and speech-pulse events for ambient UI without receiving audio, transcripts, provider data, or session identifiers.

## System Context

Talk session controllers emit canonical voice-session events for Gateway and other realtime paths. This PR converts those events into an anonymous process-wide activity feed and exposes that feed through the Plugin SDK runtime for plugin UI consumers.

Rationale: The code can mechanically enforce either model, but choosing whether live conversation timing is globally visible is a durable Plugin SDK trust-policy decision.

Likely owner: RomneyDa

Options:

- **Scope the observer (recommended):** Require an explicit capability or owner/session grant and add tests proving unrelated plugins cannot observe another Talk session.
- **Approve global anonymous observation:** Keep the all-plugin observer, but document that process-wide Talk timing is intentionally available to every Plugin SDK consumer.
- **Defer the SDK surface:** Keep the internal activity mechanism out of the public runtime until the plugin trust model is settled.
