## Summary

Keep this PR open for maintainer review. The latest branch still publishes one process-wide Talk observer to every plugin runtime, so an unrelated plugin can infer private Talk lifecycle and speaking timing across sessions despite the redacted payload; the prior P1 boundary finding remains unresolved.

## What This Changes

This PR adds `api.runtime.talk.onActivity`, a Plugin SDK callback that emits anonymous Talk lifecycle, state, and speech-pulse events for ambient plugin UI such as avatars.

## System Context

Talk session controllers emit lifecycle and audio-turn events while handling voice conversations. This PR converts those events into a global anonymous activity feed and exposes that feed through every Plugin SDK runtime, where plugins can consume it for UI animation.

## Architecture Diagram

## Best Possible Solution

Keep ambient UI activity owner-scoped by default: expose events only to the plugin or session that owns the Talk interaction, or introduce an explicitly reviewed capability with documented trust and privacy semantics before publishing any broader observer.
