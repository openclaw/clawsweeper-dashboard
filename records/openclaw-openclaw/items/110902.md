## Summary

Keep this PR open for explicit maintainer handling. It introduces a new process-wide Plugin SDK observation surface, but the proposed gate trusts a capability string declared by the requesting plugin itself; that does not establish authorization for cross-session Talk timing metadata. The earlier P1 boundary concern remains present on the current head, and the `maintainer` label plus MEMBER authorship also exclude it from automated cleanup.

## What This Changes

Adds `api.runtime.talk.onActivity`, an anonymous process-wide Talk lifecycle, state, and speech-timing subscription for plugins that declare a manifest contract.

## System Context

Talk session controllers receive realtime voice events and this PR reduces them to anonymous activity notifications. The Plugin SDK resolver exposes those notifications to plugins, which can use them for ambient UI such as speaking indicators without receiving audio or transcript content.

## Architecture Diagram

flowchart LR
  A[Talk session events] --> B[Anonymous activity reducer]
  B --> C[Process-wide watcher stream]
  D[Plugin manifest contract] --> E[Plugin SDK resolver]
  E --> F[Plugin listener]
  C --> F
  F --> G[Ambient UI indicator]

## Best Possible Solution

Define process-wide Talk observation as either a trusted registry/install capability or an owner-scoped API, then expose the reduced event stream only through that confirmed boundary with regression coverage for an untrusted plugin declaration.
