The implementation deliberately strips audio and identifiers, but it still gives every plugin record a process-wide signal of unrelated Talk activity; the prior P1 concern remains at the current head, and the PR is maintainer-authored and labeled `maintainer`.

## What This Changes

This PR adds `api.runtime.talk.onActivity`, a Plugin SDK observer that streams anonymous Talk lifecycle, state, and speech-timing events to plugins for ambient interfaces such as avatars.

## System Context

Talk session controllers emit voice-session lifecycle and audio-timing events as conversations progress. This PR reduces those events into anonymous activity signals and forwards them through the Plugin SDK to plugin-provided UI behavior.

## Best Possible Solution

Keep the shared controller as the event source, but expose observation only through a maintainer-approved trust boundary: a declared capability for trusted plugins, or an owner-scoped/internal interface for the companion plugin rather than a universal SDK method.
