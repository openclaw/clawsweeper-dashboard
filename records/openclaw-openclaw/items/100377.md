## Label Justifications

- `merge-risk: 🚨 compatibility`: The diff removes wake-time bootstrap compatibility for explicit external heartbeat targets while only initial startup pre-activates them.

## Summary

Keep this PR open, but not merge-ready: the prior `target: last` blocker is fixed and the proof is better, but startup-only pre-activation does not cover live heartbeat config reloads, so newly configured external-plugin heartbeat targets can still lose delivery after `updateConfig`.

## What This Changes

The branch adds an `allowBundledFallback` resolver option, pre-activates configured heartbeat channel plugins at gateway startup, disables bootstrap/bundled fallback on explicit heartbeat wake-path resolution, preserves guarded bootstrap for session-derived routes, and updates heartbeat tests.

## Best Possible Solution

Run heartbeat plugin pre-activation in the same lifecycle that activates or updates effective heartbeat configs, keep repeated wake-loop bootstrap disabled, and add regression coverage for config reload to a default or per-agent external plugin target.

## Solution Assessment

No, not yet. Moving broad plugin scans off the heartbeat wake loop is the right direction, but the best fix must cover both initial startup and live config updates before removing explicit-target bootstrap.
