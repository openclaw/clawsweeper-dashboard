## Summary

Keep open: the PR fixes the central wake-loop latency shape, but it is not merge-ready because explicit external heartbeat targets can still be introduced after startup through hot config reload or a requested heartbeat override, and those paths are never pre-activated before the new no-bootstrap resolver path.

## What This Changes

The PR adds heartbeat channel plugin pre-activation, disables bootstrap and bundled fallback on explicit heartbeat target resolution hot paths, preserves guarded bootstrap for session-derived routes, and adds outbound resolver coverage.

## Best Possible Solution

Make heartbeat plugin preactivation run for every effective heartbeat config/update and explicit requested override before the no-bootstrap path is used, while keeping guarded bootstrap for session-derived routes.
