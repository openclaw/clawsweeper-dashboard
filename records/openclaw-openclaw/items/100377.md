## Label Justifications

- `P1`: The PR targets a real heartbeat wake-loop latency regression and the remaining defect can break external-plugin heartbeat delivery for accepted configs.
- `merge-risk: 🚨 compatibility`: Existing config validation accepts case-insensitive external heartbeat targets, while the new preactivation path only recognizes already-normalized strings.
- `merge-risk: 🚨 message-delivery`: A missed external target preactivation can make bootstrap-free heartbeat delivery resolve to no channel instead of sending the heartbeat reply.
- `merge-risk: 🚨 availability`: The PR intentionally moves heavy plugin registry scans from heartbeat ticks into startup/reload/override paths, changing where operators can observe stalls.

## Summary

Keep open: the hot-path direction and current-head proof are good, but the PR still misses case-insensitive external plugin heartbeat targets that current config validation accepts, which can skip preactivation and then drop delivery once bootstrap is disabled.

## What This Changes

This PR adds heartbeat external-plugin preactivation at runner startup/config update/override wakes, disables bootstrap and bundled fallback in heartbeat target resolution, preserves doctor bootstrap, and adds focused tests.

## Best Possible Solution

Normalize heartbeat target ids before preactivation classification, keep the no-bootstrap heartbeat hot path, and add a regression for a case-variant external plugin target accepted by config validation.
