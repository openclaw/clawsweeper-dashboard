## Summary

Keep open. The direction is right, but the current head has a blocking contract bug: heartbeat preactivation uses `isDeliverableMessageChannel`, which returns false for external plugin ids that are not already registered, so the exact targets that need preactivation are skipped while the heartbeat hot path disables bootstrap.

## What This Changes

The PR disables heartbeat-time plugin bootstrap and bundled fallback for explicit targets, adds lifecycle/requested-wake preactivation for external heartbeat channels, threads doctor opt-in bootstrap, and expands heartbeat/outbound tests.

## Best Possible Solution

Fix the external-target classifier against the real channel normalization contract, keep doctor opt-in bootstrap and `target:last` guarded bootstrap, then let maintainers decide whether lifecycle preactivation is the accepted compatibility boundary.
