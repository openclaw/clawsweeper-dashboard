## Summary

Keep open: the startup preactivation is the right direction, but it still does not fully replace current main's bootstrap compatibility for effective heartbeat plugin targets, and the PR still lacks real gateway heartbeat proof.

## What This Changes

The branch adds optional bundled-fallback skipping to outbound channel resolution, disables heartbeat hot-path bootstrap/fallback lookups, and adds startup preactivation for heartbeat channel plugins.

## Best Possible Solution

Move plugin activation off the wake tick by preactivating every effective heartbeat target at startup and config reload while preserving current bootstrap-backed delivery for registered and per-agent external channels.
