## Summary

Keep open: the latest commit fixes the previous scheduled-default preactivation gap, but targeted heartbeat wake overrides can still miss external-plugin delivery when the override supplies a new external target and inherits the configured recipient.

## What This Changes

The PR moves heartbeat external-plugin target resolution off the wake path by preactivating configured/requested targets, adds resolver flags to skip bootstrap and bundled fallback, preserves doctor and target:last bootstrap exceptions, and adds regression tests.

## Best Possible Solution

Preactivate the same effective heartbeat object that the targeted wake will pass to runOnce, keep doctor and target:last bootstrap exceptions, and land lifecycle preactivation only with upgrade proof for external-plugin targets.
