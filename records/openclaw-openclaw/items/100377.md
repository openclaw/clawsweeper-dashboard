## Label Justifications

- `P1`: The PR targets a real heartbeat wake-loop stall, but the current patch can break documented per-agent plugin-channel heartbeat delivery.
- `merge-risk: 🚨 compatibility`: The diff changes the heartbeat plugin compatibility path from wake-time bootstrap to startup pre-activation, and the startup hook currently misses per-agent heartbeat configs.
- `merge-risk: 🚨 message-delivery`: Per-agent external plugin heartbeat routes can resolve to no delivery after merge because the hot path no longer bootstraps and startup did not activate them.

## Summary

This PR should stay open because the startup pre-activation repair is incomplete: it only inspects the default heartbeat config, while documented per-agent heartbeat targets still run and would now lose the bootstrap path on the wake hot path. It also still needs real gateway behavior proof before merge.

## What This Changes

The branch adds heartbeat channel plugin pre-activation at gateway startup, adds an `allowBundledFallback` resolver option, changes heartbeat delivery target resolution to skip bootstrap and bundled fallback on the wake hot path, and updates outbound heartbeat tests.

## Best Possible Solution

Keep bootstrap off the repeated wake hot path, but pre-activate every effective heartbeat config the runner can schedule, including per-agent overrides, then require redacted real gateway proof for preserved delivery and latency.

## Solution Assessment

Is this the best way to solve the issue? No, not yet. Moving bootstrap out of the wake loop is the right direction, but the implementation must share or mirror the runner's effective heartbeat config selection so per-agent targets are pre-activated too.
