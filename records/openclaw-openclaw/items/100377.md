## Summary

Keep this PR open, but the current head still needs changes before merge: the targeted-wake repeat-bootstrap blocker was fixed, yet the new preactivation helper uses a channel-normalization helper whose real contract accepts unknown plugin ids, so explicit external-plugin heartbeat targets can still skip preactivation and then fail on the no-bootstrap hot path.

## What This Changes

The PR adds heartbeat plugin-channel preactivation at startup, config reload, and requested wake overrides; disables bootstrap and bundled fallback during heartbeat delivery resolution; preserves doctor and target:last bootstrap paths; and adds focused tests.

## Best Possible Solution

Use a detector that distinguishes bundled or already-standard channels from external plugin targets under the real channel-normalization contract, keep lifecycle preactivation plus the doctor and target:last exceptions, and add a regression that does not mock away normalizeDeliverableOutboundChannel semantics.
