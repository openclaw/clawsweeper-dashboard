## Label Justifications

- `P1`: The PR addresses a heartbeat wake-loop regression that can stall real channel delivery workflows for external-plugin targets.
- `merge-risk: 🚨 compatibility`: The diff changes explicit external-plugin heartbeat targets from wake-time bootstrap to lifecycle preactivation, affecting upgrade and reload behavior.
- `merge-risk: 🚨 message-delivery`: If an explicit external heartbeat target is not active before the no-bootstrap resolver runs, heartbeat delivery can fall through to no target.
- `merge-risk: 🚨 availability`: The current preactivation call can still trigger expensive plugin bootstrap during startup or config reload for disabled or non-deliverable heartbeat configs.

## Summary

Keep open: the no-bootstrap heartbeat hot-path fix is useful and the prior review blockers are mostly addressed, but the current head still pre-activates external targets before the runner knows whether a heartbeat is enabled and deliverable, so disabled or non-deliverable configs can still trigger plugin bootstrap during startup or reload.

## What This Changes

The PR moves external heartbeat plugin resolution out of delivery-target hot paths into lifecycle preactivation, preserves doctor/session-derived bootstrap exceptions, and adds focused outbound heartbeat tests.

## Best Possible Solution

Gate preactivation to the same enabled, effective heartbeat configs that will actually be scheduled and delivered, then let maintainers decide whether the lifecycle-preactivation compatibility boundary is acceptable.
