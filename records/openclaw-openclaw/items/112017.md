## Summary

This PR remains necessary: current `main` still converts a model-supplied `maxBytesMb` directly to bytes and lets a model-supplied `maxImages` raise the image-count gate without an upper bound. The patch is a focused, compatible hardening change and the prior threshold-coverage finding appears addressed, but the contributor still needs after-fix real behavior proof outside the Vitest harness before merge.

## What This Changes

The branch caps model-provided `maxBytesMb` and `maxImages` values for the image agent tool at 100, advertises those limits in its tool schema, logs clamps, and adds regression coverage.

## System Context

The image agent tool receives model-generated tool-call arguments, validates and normalizes them, then loads and processes referenced media before sending image content to a vision-capable model. The changed limits sit at that untrusted model-input boundary and bound downstream media loading and image-loop work without changing the operator-owned media-size default.

## Best Possible Solution

Keep the runtime caps at the model-tool boundary, preserve the uncapped operator `mediaMaxMb` fallback, and add a redacted live terminal or runtime transcript showing an oversized image-tool call is bounded before media processing.
