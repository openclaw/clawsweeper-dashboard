## Label Justifications

- `P2`: The bug deterministically corrupts some bash output, but only when terminal sequences cross callback boundaries and without broadly disabling bash execution or the core runtime.
- `impact:session-state`: Leaked control-sequence fragments are recorded in bash execution messages and can enter the agent transcript and model context.

## Summary

The issue remains necessary: current `main` sanitizes bash output independently per decoded callback, losing parser state when ANSI or OSC sequences cross chunk boundaries. The related merged PR explicitly excluded this case, and P2 remains proportionate to the deterministic but boundary-dependent output corruption.

## What This Changes

Make bash output sanitization invariant to ANSI and OSC control sequences being split across process-output chunks.

## Best Possible Solution

Add a bounded incremental ANSI and OSC sanitizer with explicit finalization in terminal-core, then give each bash accumulator one sanitizer instance so streamed chunks, final snapshots, and spill files receive identical sanitized bytes without buffering the full process output.

## Reproduction Assessment

Yes, at source level with high confidence: current `main` applies a complete-string sanitizer separately to each output callback, and the supplied split OSC and CSI cases necessarily lose control-sequence state between calls. No artifact-generating test was run during this read-only review.

## Solution Assessment

Yes in direction: bounded incremental parsing is the narrowest maintainable solution and preserves streaming and memory limits. The parser should be a reusable terminal-core contract rather than a bash-only regex workaround or full-output concatenation step.
