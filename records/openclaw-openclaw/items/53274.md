## Summary

Keep open: current main and v2026.6.11 still skip browser Control UI device identity when `crypto.subtle` is unavailable. The scope-preservation subissues are implemented, but the remaining request would change a documented Control UI auth/security boundary and needs maintainer security/product direction.

## What This Changes

Request to support browser Control UI device identity in LAN or reverse-proxy plain-HTTP contexts, with related fixes for bypass scope preservation and implied operator scopes.

## Best Possible Solution

Keep the implemented scope fixes, then have maintainers decide whether remote plain-HTTP browser identity remains rejected, becomes an explicit opt-in policy, or stays handled through HTTPS, trusted-proxy, Tailscale, and clearer diagnostics.
