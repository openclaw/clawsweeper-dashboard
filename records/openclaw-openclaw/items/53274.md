## Summary

Keep open: current main and v2026.6.11 still skip browser Control UI device identity when `crypto.subtle` is unavailable. The scope-preservation subissues are implemented, but the remaining request would change a documented Control UI auth/security boundary; the Moci link in the discussion is useful long-term identity context, not a direct replacement for this policy decision.

## What This Changes

The issue requests browser Control UI device identity generation without depending on Secure Context, with related fixes for scope handling in insecure LAN or reverse-proxy deployments.

## Best Possible Solution

Keep the implemented scope fixes, then have a maintainer/security decision choose whether remote plain-HTTP browser identity remains rejected, becomes an explicit opt-in policy, or is handled only through HTTPS, trusted-proxy, or Tailscale guidance.

## Reproduction Assessment

Yes. Source inspection shows current main skips browser device identity without `crypto.subtle`, and the gateway rejects remote device-less Control UI auth unless a named trust or bypass path applies.

## Solution Assessment

Unclear. The pure-JS identity change is mechanically plausible, but it is only the best fix if maintainers intentionally support persistent Control UI browser identity in plaintext remote contexts.
