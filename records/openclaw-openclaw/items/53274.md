## Summary

Keep open: current main and the latest release still skip Control UI browser device identity when WebCrypto is unavailable, so the central HTTP LAN/reverse-proxy request remains unresolved. The scope-preservation subissues are implemented, but removing the remaining secure-context boundary needs maintainer security/product direction.

## What This Changes

The issue requests Control UI device identity generation in non-secure browser contexts and scope preservation for device-auth bypass deployments.

## Best Possible Solution

Keep the landed scope fixes and have maintainers explicitly decide the remote plain-HTTP identity policy; if support is accepted, implement it as a narrow, tested opt-in or trusted-deployment mode rather than silently weakening the default secure-context boundary.

## Reproduction Assessment

Yes. Source inspection on current main and `v2026.6.11` shows the browser client skips device identity unless `crypto.subtle` exists, and the browser identity fingerprint still calls `crypto.subtle.digest`.

## Solution Assessment

Unclear. The proposed pure-JS hash and always-attempt identity path is mechanically plausible, but it is only the best solution if maintainers intentionally support persistent Control UI device identity in plaintext remote browser contexts; the safer direction is an explicit policy decision and narrow opt-in if accepted.
