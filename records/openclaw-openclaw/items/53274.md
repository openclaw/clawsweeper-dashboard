## Summary

Keep open: current main and v2026.6.11 still skip browser Control UI device identity when `crypto.subtle` is unavailable. The scope-preservation subissues are implemented, but the remaining request changes a documented browser Control UI security boundary and needs maintainer/security direction.

## What This Changes

The issue requests allowing browser Control UI device identity generation in non-localhost HTTP contexts and also reports scope-loss regressions around `dangerouslyDisableDeviceAuth`.

## Best Possible Solution

Keep the shipped scope fixes, then have maintainers decide whether remote plain-HTTP browser identity stays rejected, becomes an explicit operator-controlled exception, or is handled only through HTTPS, trusted-proxy, Tailscale, and warning guidance.
