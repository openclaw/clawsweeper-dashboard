## Summary

Keep open: current main supports managed stdio and configured WebSocket Codex app-server connections, but it does not implement a command-backed SSH/WebSocket-over-stream transport; the request is a new security-sensitive config/runtime mode that needs maintainer direction.

## What This Changes

Add a command-backed SSH transport for remote Codex app-server connections so OpenClaw can recreate the connection after disconnects.

## Best Possible Solution

Settle the remote Codex ownership direction first; if command-backed transport is accepted, implement it in the bundled Codex plugin with explicit command/args, `remoteWorkspaceRoot`, no-shell spawn, WebSocket-over-stream framing, incompatible-field rejection, docs, focused tests, and live SSH proxy proof.
