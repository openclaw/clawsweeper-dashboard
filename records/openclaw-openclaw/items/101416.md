## Summary

Keep open: current main only supports managed stdio and configured WebSocket for Codex app-server connections, while upstream Codex exposes a proxy byte stream that makes the proposal plausible. This is still a new security-sensitive config and transport mode that needs maintainer direction and is not superseded by the related local-app-server remote-execution design.

## What This Changes

Request adding a new `appServer.transport: "ssh"` command-backed Codex app-server transport that recreates remote byte-stream connections over a spawned command.

## Best Possible Solution

Settle the remote Codex ownership direction first; if accepted, implement a narrow experimental Codex plugin transport with explicit command and args, `remoteWorkspaceRoot`, no-shell spawn, WebSocket-over-stream framing, incompatible-field rejection, docs, focused tests, and live SSH proxy proof.
