## Summary

This remains a necessary, narrowly scoped Feishu bug: the message-end block path can recognize `NO_REPLY` as intentionally silent without recording that outcome for the no-visible-content fallback, causing misleading recovery text in a DM. No merged fix or canonical replacement was found.

## What This Changes

Fix Feishu DM dispatch so an exact `NO_REPLY` block-level silent skip does not trigger the no-visible-content fallback.

## Best Possible Solution

Track intentional silence as explicit turn-level delivery state, suppress the Feishu fallback only when the completed turn has no later visible or failed delivery, and cover both final and message-end block paths without weakening the normal DM empty-output safeguard.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: an exact `NO_REPLY` emitted through the message-end block path produces a block-level silent skip that Feishu's fallback bookkeeping does not retain. The issue also includes a matching production trace, though this review did not independently run a live Feishu DM.

## Solution Assessment

The proposed Feishu-local direction is safer than allowing empty direct-message replies globally. The implementation should use explicit intentional-silence state and prove that later visible output or delivery failure still controls fallback behavior.
