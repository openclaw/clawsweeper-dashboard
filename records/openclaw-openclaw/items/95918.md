  - body: This branch only calls `resolveBindingAccountId` when a second bind segment exists. That regresses the documented `--bind <channel>` behavior, which currently resolves plugin setup hooks, forced account binding, and multi-account fallback before writing the binding.
  - confidence: 0.91

  - body: This reinterprets every `feishu:<value>` bind as a group peer unless users switch to the new `account:` escape. The public syntax currently documents `<channel>:<account>`, so existing Feishu account names can silently stop matching the intended account.
  - confidence: 0.9
- **[P1] Do not treat setup account ids as peers:** `src/commands/agents.bindings.ts:295-305`
  - body: `buildChannelBindings` receives account IDs recorded during channel setup, but this branch converts Feishu account IDs into group peers. Interactive setup can therefore generate a peer binding when the user selected an account scope.
  - confidence: 0.86
- **[P2] Keep non-text heartbeat content from being pruned:** `src/auto-reply/heartbeat-filter.ts:339-340`
  - body: Removing the `hasNonTextContent` guard makes any non-text assistant content with HEARTBEAT_OK text look like a removable heartbeat ack. The linked heartbeat bug needs reasoning/thinking blocks ignored, not arbitrary media/tool-like content discarded from transcript context.
  - confidence: 0.84
- **[P3] Document the new bind grammar:** `src/commands/agents.bindings.ts:337-340`
  - body: The parser adds `feishu:account:<id>` and changes the meaning of `feishu:<value>`, but the agents CLI docs and help still describe only channel/account syntax. The accepted account-vs-peer grammar needs user-facing documentation before merge.
  - confidence: 0.82
