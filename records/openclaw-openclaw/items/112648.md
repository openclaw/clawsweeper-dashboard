## Summary

It introduces a new trusted plugin-runtime API that carries an opaque approval capability into native harness execution; the branch adds useful boundary checks, but this permanent SDK/security contract needs explicit owner direction and real after-fix behavior proof before merge.

## What This Changes

The PR extends plugin-owned subagent runs so trusted official plugins can route completion to a requester session and pass a short-lived approval grant into native agent harness attempts.

## System Context

A trusted plugin starts a worker subagent through the Gateway, which registers the run and later announces completion to a requester session. This change adds trusted routing and approval-capability fields at the plugin SDK boundary, carries them through Gateway admission and execution, and hands the approval value to embedded/native harnesses.

## Best Possible Solution

Define and approve a narrow, named approval-grant contract owned by the native-harness boundary, then prove in a real trusted-plugin run that it reaches only the intended harness attempt and that untrusted/public requests cannot alter completion routing or approval execution.
