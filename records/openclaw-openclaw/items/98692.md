## Summary

Keep this PR open for maintainer review: the updated branch is a focused Google embedding-batch hardening change with sufficient loopback terminal proof and no blocking patch findings, but the stricter output-file failure contract still needs maintainer acceptance before merge.

## What This Changes

The PR replaces unbounded Google embedding batch upload/create error reads with bounded readers and changes completed batch output downloads from whole-file buffering to per-line streaming with byte and record-count caps.

## Best Possible Solution

Land the bounded streaming parser if maintainers accept the strict output budgets; otherwise tune the record/blank-row tolerance while preserving bounded error reads and per-record cancellation.

## Reproduction Assessment

Yes at source level: current main uses response.text() for Google batch upload/create error bodies and completed output downloads, so hostile or faulty provider bodies can be buffered without the PR's bounds. I did not run a current-main OOM reproduction because this review is read-only, but the code path and PR loopback proof make the bug class clear.

## Solution Assessment

Yes for the fix shape: bounded error reads plus streaming JSONL at the Google batch output-file boundary is the narrow provider-local repair. The exact fail-closed budgets are a maintainer compatibility choice, not an automated code defect.
