## Summary

Keep this PR open: it is useful Google embedding-batch hardening with sufficient loopback proof, but the submitted streaming reader can still fail a completed batch when requested rows are followed by extra or blank output records.

## What This Changes

The PR bounds Google/Gemini embedding batch upload/create error reads, streams completed output JSONL with per-line and per-group limits, and adds focused regression tests.

## Best Possible Solution

Keep the bounded streaming shape, add early completion cancellation after all requested IDs are collected, and have maintainers accept or tune the remaining fail-closed limits before merge.

## Reproduction Assessment

Yes at source level: current main still uses unbounded text reads for Google upload/create error bodies and completed output downloads. The PR-introduced extra-row failure is also source-reproducible from the void callback plus maxLines budget.

## Solution Assessment

No as submitted: bounded error reads plus streaming JSONL is the right owner-local fix shape, but the Google reader should match the OpenAI sibling by stopping once all requested IDs are handled.
