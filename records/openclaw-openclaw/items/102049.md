## Summary

Keep open: this is a real fallback observability bug, but the PR only emits after a fallback chain succeeds, so failed chains and earlier multi-hop transitions can still remain invisible; contributor proof is also unit-test output only.

## What This Changes

The PR adds a successful-fallback diagnostic event emission in `src/agents/model-fallback.ts` and adds `has_fallback=true` to OTel `openclaw.model.failover` spans.

## Best Possible Solution

Emit the existing `model.failover` event for each failed-candidate-to-next-candidate transition with focused regression coverage, then require redacted real diagnostic/export proof before merge.
