## Label Justifications

- `P2`: The patch introduces a bounded but user-visible redirect latency regression in a network reliability path.

## Summary

Keep this PR open for a focused repair: the rejected-redirect cleanup is useful and the supplied loopback proof is credible, but the new awaited cancellation also delays successful redirects for up to 100 ms when a body cancellation never settles.

## What This Changes

The branch adds bounded cancellation of guarded redirect response bodies before redirect validation and adds unit and loopback integration coverage for rejected redirect paths.

## Best Possible Solution

Await bounded cancellation only on redirect paths that reject and release the dispatcher; preserve non-blocking, failure-swallowing cancellation for accepted redirects, then add a successful-redirect regression test with a pending cancel promise.
