## Summary

The PR is still necessary and appears correct: current `main` still accepts hexadecimal coordinate strings through permissive `Number()` coercion, while this branch aligns the HTTP route with the existing strict Browser CLI contract. The exact-head live Browser transcript directly proves both the accepted decimal click and rejected hex inputs, and no actionable defect or security concern remains.

Likely related people: `@vincentkoc` (high confidence, introduced the current normalization/parser surface) and `@steipete` (medium confidence, recent contributor on the same route file).

## What This Changes

The PR routes Browser `/act` click coordinates through the shared strict finite-number parser, removes the permissive numeric helper, and adds HTTP contract tests rejecting hexadecimal strings.

## Best Possible Solution

Land the canonical strict-parser change so both Browser CLI and direct HTTP callers accept finite decimal coordinates but reject hexadecimal syntax before any click dispatch.
