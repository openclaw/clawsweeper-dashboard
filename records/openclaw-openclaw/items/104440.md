## Summary

This PR is still necessary because current main accepts hexadecimal coordinate strings as numeric positions. The proposed fix is canonical, preserves valid decimal input, has convincing real-browser proof, and introduces no actionable correctness or security findings; keep it open for ordinary maintainer landing review.

## What This Changes

The PR routes Browser `/act` click coordinates through the shared strict finite-number parser, removes the obsolete permissive helper, and adds HTTP regression coverage for hexadecimal inputs.

## Best Possible Solution

Land the strict-parser reuse at the shared Browser request-normalization boundary so valid decimal strings remain supported and alternate numeric syntaxes are rejected before either Browser executor runs.
