## Summary

Keep this issue open: the report describes a concrete violation of the documented restart contract, and current-main inspection does not provide enough evidence that persisted same-ID registry entries are automatically invalidated when configured load paths change.

## What This Changes

Ensure a gateway restart loads the plugin from the current `plugins.load.paths` configuration instead of retaining a stale persisted path that requires manual registry refresh.

## Best Possible Solution

On each fresh gateway start, validate persisted registry entries against normalized canonical load paths and relevant manifest identity, rebuild or reject mismatched entries before runtime loading, emit actionable configured-versus-resolved path diagnostics, and cover the same-ID A-to-B upgrade path with a focused regression test without adding request-time filesystem polling or a new compatibility option.
