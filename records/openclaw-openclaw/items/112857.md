## Summary

This is a substantial new product and plugin-SDK direction, not a currently defined bug. Current main already has turn-local fallback chains, structured per-candidate failure/success observation, and operational notices, but it does not establish task capability contracts or a durable policy audit model; maintainers should first decide whether a generic cross-plugin admission/observation seam is worth supporting. Likely related people: steipete (high confidence) and vincentkoc (medium confidence).

## What This Changes

The issue requests an opt-in shadow mode that evaluates configured model-fallback candidates against managed-task capability contracts and writes an audit trail without changing which model handles a turn.

## System Context

OpenClaw resolves a selected model into a fallback candidate chain, runs candidates until one succeeds or the chain is exhausted, and emits structured fallback decisions for diagnostics and user-facing notices. The proposal would add task-owned policy evaluation and persistent audit data around those real fallback attempts.

## Architecture Diagram

flowchart LR
  A[Model configuration] --> B[Fallback candidate chain]
  B --> C[Fallback runner]
  C --> D[Provider attempt]
  D --> E[Fallback decision events]
  E --> F[Task policy plugin]
  F --> G[Shadow audit trail]
  D --> H[Reply or failure summary]

## Best Possible Solution

Keep task contracts, capability evidence, evaluation policy, and audit storage in an external code plugin; only add a narrow generic plugin event or pre-attempt observation seam after maintainers confirm that existing structured fallback decisions cannot support the required audit and that the seam has value beyond this plugin.
