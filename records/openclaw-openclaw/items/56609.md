- `P1`: The issue reports real transcript loss risk in session lifecycle behavior, but the remaining work needs a product/storage-contract decision rather than an immediate crash-loop/security emergency fix.

## Summary

Keep open: current main and the latest release still use `.jsonl.deleted.*` / `.jsonl.reset.*` archive names and still have retention and disk-budget paths that physically remove archive artifacts. The merged role-ordering reset fix closed one narrower hard-delete path, but it did not resolve this issue's broader naming and no-delete storage contract.

## What This Changes

The issue asks OpenClaw to stop using destructive-looking `.deleted` / `.reset` transcript archive names and to avoid physically deleting retained session transcript files.

## Best Possible Solution

Define an explicit session transcript lifecycle where retained transcripts use non-destructive names or an archive directory, default maintenance does not silently purge irreplaceable archives, and any physical deletion path is opt-in, documented, and migration-aware.

Rationale: Current code intentionally supports both retained archive files and physical cleanup, while this issue asks to change the product storage contract for user conversation history; automation cannot safely choose that policy or its migration surface.

Options:

- **Preserve By Default (recommended):** Rename or move retained transcript archives, stop default retention/disk-budget purge of those archives, and add explicit documented cleanup controls for operators who choose physical deletion.
- **Clarify Retention Contract:** Keep cleanup behavior but rename/docs/config split the states so operators can distinguish retained archives from physically deleted transcripts.
- **Keep Current Policy:** Leave `.deleted.*` and current cleanup semantics in place, accepting the reported confusion and data-loss risk as outside the core contract.

## Solution Assessment

No: a suffix-only rename would leave the retention and disk-budget deletion paths in place, so the best fix needs one lifecycle contract that covers naming, storage location, cleanup policy, docs, tests, and migration behavior.
