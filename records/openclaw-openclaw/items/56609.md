## Label Justifications

- `P1`: The issue reports irreversible real-world transcript loss tied to current archive naming and cleanup semantics that still exist on main and in the latest release.
- `impact:data-loss`: The requested change is about preventing retained session transcripts from being treated as disposable and later physically removed or lost.
- `impact:session-state`: The affected data is persisted session transcript lifecycle state across reset, delete, maintenance, archive cleanup, and disk-budget paths.

## Summary

Keep open: current main and latest release still use `.jsonl.deleted.*` and `.jsonl.reset.*` archive suffixes, and both archive-retention cleanup and disk-budget enforcement can still physically remove retained transcript artifacts. The merged role-ordering reset fix addressed one hard-delete path, but it did not resolve this issue's broader durable session archive contract.

## What This Changes

The issue requests durable session archive semantics by renaming `.deleted`/`.reset` transcript artifacts or moving them to an archive directory, and by avoiding physical deletion of session transcripts.

## Best Possible Solution

Define a maintainer-approved durable transcript archive contract, keep existing `.deleted.*` and `.reset.*` artifacts readable or migratable, then update new archive naming, cleanup defaults, disk-budget behavior, docs, and regression tests together.

## Reproduction Assessment

Yes, at source level: current main still produces `.jsonl.deleted.*` and `.jsonl.reset.*` archive names and has retention/disk-budget paths that physically remove archive artifacts. I did not run a live Gateway flow because the code and tests already prove the current semantics.

## Solution Assessment

No final implementation is selected yet. A rename-only patch would be too narrow because the shipped suffixes are part of parsers, tests, docs, memory/session tooling, cleanup behavior, and upgrade expectations.
