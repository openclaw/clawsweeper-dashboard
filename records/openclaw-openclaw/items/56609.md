## Label Justifications

- `P1`: The issue reports real transcript-durability risk and current code still has suffix and cleanup semantics that can lead to unrecoverable history loss.
- `impact:data-loss`: The report is about retained session transcripts being treated as disposable and physically lost.
- `impact:session-state`: The affected behavior is persisted session transcript lifecycle across reset, delete, maintenance, archive cleanup, and disk-budget paths.

## Summary

Keep open: current main and latest release still use `.jsonl.deleted.*` and `.jsonl.reset.*` archive names, and current maintenance/disk-budget code can still physically remove retained transcript artifacts. The merged role-ordering reset fix addressed one hard-delete path, but not this broader durable archive naming and retention policy.

## What This Changes

The issue requests durable session transcript archive semantics: stop using `.deleted.*`/`.reset.*` naming, preferably move archives to a dedicated archive area, and avoid physical deletion of session transcript files.

## Best Possible Solution

Define a maintainer-approved session transcript archive contract, keep or migrate existing `.deleted.*` and `.reset.*` files safely, then update naming, retention defaults, cleanup, disk-budget behavior, docs, and tests together.

## Reproduction Assessment

Yes, at source level: current main still creates `.jsonl.deleted.*` and `.jsonl.reset.*` archive names and still has retention/disk-budget paths that physically remove archived transcript artifacts. This read-only review did not run a live Gateway flow.

## Solution Assessment

Unclear as an implementation because the direction is valid but touches shipped filename and retention semantics. A rename-only patch would be too narrow without migration/compatibility, cleanup, disk-budget, docs, and test changes.
