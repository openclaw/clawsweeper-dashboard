## Summary

Keep open: current main and the latest checked release still use `.deleted.*`/`.reset.*` archive suffixes and can physically remove retained transcript artifacts through maintenance or disk-budget paths; a related hard-delete bug was fixed by #97544, but the broader archive naming and no-delete product contract remains unresolved.

## What This Changes

The issue requests replacing misleading session archive suffixes such as `.deleted.*`/`.reset.*` and preventing OpenClaw from hard-deleting session transcript files.

## Best Possible Solution

Define one durable transcript lifecycle contract with archive-oriented naming or storage, a doctor migration for existing suffixes, and explicit documented purge semantics for retention and disk-budget pressure.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw make retained session transcripts a durable archive contract that renames `.deleted.*`/`.reset.*` and removes automatic hard-deletion, or keep the current retention model with clearer wording?

Rationale: The code can implement either path, but the choice changes user storage guarantees, cleanup behavior, config semantics, and compatibility for existing archives and downstream tools.

Likely owner: steipete

Owner reason: Recent session product work makes this the best available owner for the product-level transcript lifecycle choice, with cleanup implementation details likely shared with archive-maintenance contributors.

Owner confidence: medium

Options:

- **Adopt durable archive semantics (recommended):** Rename future retained transcripts to archive-oriented names or locations, migrate existing suffixes with doctor, and require explicit purge semantics for any physical deletion.
- **Keep current retention semantics:** Leave `.deleted.*` and automatic cleanup in place, but document that the suffix means detached/retained until retention or disk budget removes it.
- **Split visible and physical retention:** Keep archive files but introduce separate visible-session and retained-transcript retention controls with a documented migration path.

Unclear without maintainer direction: a narrow suffix rename would not be enough because retention, disk budget, memory indexing, usage accounting, doctor, docs, and migration semantics all need one chosen lifecycle contract.
