## Summary

Keep open: current main and the latest release still emit `.jsonl.deleted.*` / `.jsonl.reset.*` archive names and still have retention and disk-budget paths that physically remove retained transcript artifacts. The role-ordering reset hard-delete was fixed by the merged related PR, but the broader durable archive naming and never-delete policy remains a product decision.

## What This Changes

The issue asks OpenClaw to stop using destructive-looking session archive names like `.deleted.*`, prefer `.archived.*` or an archive directory, and avoid any session transcript hard-delete path.

## Best Possible Solution

Define a maintainer-approved durable transcript archive contract, keep existing `.deleted.*` and `.reset.*` files readable or migratable, then update naming, retention, disk-budget behavior, docs, and tests together.

## Reproduction Assessment

Yes, at source level: current main still formats transcript archive names from `reset` and `deleted` reasons and still removes old or over-budget archive artifacts. I did not run a live Gateway flow because the source and tests already prove the current behavior.

## Solution Assessment

No concrete fix is selected yet. A rename-only change would be too narrow because shipped filename parsers, config retention, docs, memory/session tooling, cleanup, disk-budget behavior, and upgrade expectations all depend on the current suffixes.
