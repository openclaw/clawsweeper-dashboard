## Summary

Keep open: current main and the latest release still create `.jsonl.deleted.*` and `.jsonl.reset.*` archive names, and session maintenance and disk-budget paths can still physically remove retained transcript artifacts. The role-ordering reset fix closed one concrete hard-delete path, but the broader archive naming and no-delete storage contract remains unresolved and needs maintainer product direction.

## What This Changes

Request to replace destructive-sounding session archive suffixes and cleanup semantics with permanent archive-oriented transcript retention.

## Best Possible Solution

Define one durable transcript lifecycle contract: retained transcripts should use archive-oriented names or storage, old suffixes should migrate through doctor/backfill rather than runtime shims, and any physical purge should be explicit, documented, and upgrade-tested.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw replace the shipped `.deleted.*` and `.reset.*` transcript archive convention and physical cleanup behavior with a permanent archive naming/directory model, and what migration or purge policy should existing users get?

Rationale: Source inspection proves the current behavior, but choosing archive names, retained-transcript purge semantics, and migration behavior changes shipped filenames, config semantics, disk-budget behavior, docs, and downstream tooling expectations.

Likely owner: amknight

Owner reason: Recent archive-retention and disk-budget work makes this the best technical owner signal for the cleanup and purge-policy side of the decision.

Owner confidence: medium

Options:

- **Adopt archive terminology with migration (recommended):** Rename or move future retained transcripts, add doctor/backfill handling for old `.deleted.*` and `.reset.*` artifacts, and keep physical purge behind an explicit documented retention setting.
- **Keep behavior and clarify docs:** Leave current suffixes and cleanup behavior intact, but document that `.deleted.*` means detached until retention or disk-budget cleanup removes it.
- **Split terminology from purge policy:** Use https://github.com/openclaw/openclaw/issues/80263 for naming/config clarity and track the no-physical-delete policy as a separate durability decision.

## Solution Assessment

No for an automated direct rename: the direction is valid for transcript durability, but the best fix needs maintainer agreement on shipped suffix migration, archive directory layout, and explicit purge semantics before implementation.
