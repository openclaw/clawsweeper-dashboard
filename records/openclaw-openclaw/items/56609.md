## Summary

Keep open: current main still uses `.jsonl.deleted.*` and `.jsonl.reset.*` archive names, and both retention cleanup and disk-budget cleanup can physically remove retained session transcript artifacts. The merged role-ordering reset fix closed one hard-delete path, but the broader naming and no-delete policy requested here is still unresolved.

## What This Changes

The issue requests a durable session transcript lifecycle: replace `.deleted.*` and `.reset.*` naming with archive-oriented storage and ensure OpenClaw does not physically delete session transcripts by default.

## Best Possible Solution

Define a single durable transcript lifecycle contract: retained transcripts should use archive-oriented names or storage, old suffixes should migrate through doctor/backfill rather than runtime shims, and any physical purge should be explicit, documented, and upgrade-tested.

Options:

- **Adopt archive terminology with migration (recommended):** Rename or move future retained transcripts, add doctor/backfill handling for old `.deleted.*` and `.reset.*` artifacts, and keep physical purge behind an explicit documented retention setting.
- **Keep behavior and clarify docs:** Leave current suffixes and cleanup behavior intact, but document that `.deleted.*` means detached until retention removes it.
- **Split policy from terminology:** Use https://github.com/openclaw/openclaw/issues/80263 for naming/config clarity and track the no-physical-delete policy as a separate data durability decision.
