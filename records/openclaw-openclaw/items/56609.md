## Label Justifications

- `impact:data-loss`: The report is about retained transcript artifacts being treated as disposable and later lost or physically removed.

## Summary

Keep open: current main and the checked v2026.6.11 tag still use `.jsonl.reset.*` and `.jsonl.deleted.*`, and current retention/disk-budget paths can physically remove those archive files. The merged role-ordering fix only removed one hard-delete path, so the remaining durable-archive contract still needs maintainer product direction.

## What This Changes

The issue asks OpenClaw to stop using destructive-looking session transcript suffixes like `.deleted.*` and `.reset.*`, prefer archive terminology or an archive directory, and avoid hard-deleting session transcript files.

## Best Possible Solution

Define a maintainer-approved durable transcript archive contract, keep existing `.deleted.*` and `.reset.*` files readable or migratable, then update new archive naming, cleanup defaults, disk-budget behavior, docs, and tests together.

## Reproduction Assessment

Yes, at source level. Current main still produces `.jsonl.deleted.*` and `.jsonl.reset.*` archive names and has retention/disk-budget paths that physically remove archive artifacts; this read-only review did not run a live Gateway flow.

## Solution Assessment

No final best fix is selected yet. A rename-only change would be too narrow because current parsers, tests, docs, memory/session tooling, cleanup, disk-budget behavior, and upgrade expectations depend on the shipped suffixes.
