## Label Justifications

- `P1`: The issue reports real-world transcript loss and current main/release still have shipped archive naming and cleanup semantics that can remove retained transcripts.
- `impact:data-loss`: The requested change is about irreplaceable session transcripts being treated as disposable and later lost or physically removed.

## Summary

Keep open: current main and v2026.6.11 still use `.jsonl.deleted.*` and `.jsonl.reset.*` archive names, and current retention plus disk-budget paths can still physically remove those transcript artifacts. The merged fix at https://github.com/openclaw/openclaw/pull/97544 addressed one concrete hard-delete reset path, but it did not resolve this issue's broader archive naming and never-delete contract.

## What This Changes

Requests replacing destructive session archive terminology with durable archive semantics and preventing OpenClaw from physically deleting session transcript files.

## Best Possible Solution

Define a maintainer-approved durable transcript archive contract, keep or migrate existing `.deleted.*` and `.reset.*` files, then update new archive naming, retention/disk-budget policy, docs, and regression tests together.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still produce `.deleted.*`/`.reset.*` archive names and contain retention/disk-budget paths that physically remove archive artifacts; this read-only review did not run a live Gateway flow.

## Solution Assessment

No final fix is selected yet. A rename-only change would be too narrow because shipped parsers, memory/session tooling, cleanup behavior, docs, tests, and upgrade expectations all depend on the existing suffixes.
