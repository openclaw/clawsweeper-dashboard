## Summary

Keep open: current main and the latest release still create `.jsonl.deleted.*` and `.jsonl.reset.*` session artifacts, and cleanup paths can physically remove retained transcript files. The reported data-loss risk is real, but changing the durable transcript lifecycle, filename contract, and retention behavior needs maintainer product direction before an automated fix PR.

## What This Changes

The issue asks OpenClaw to stop treating retained session transcripts as deletable by renaming `.deleted.*`/`.reset.*` artifacts or moving them into a durable archive location and avoiding hard removal.

## Best Possible Solution

Define a maintainer-approved transcript lifecycle with durable archive naming or location, explicit retained-transcript retention and disk-budget policy, doctor/migration handling for existing archive files, and matching docs plus regression coverage.

Owner confidence: medium

Options:

- **Adopt durable archives (recommended):** Rename or relocate retained transcripts under a durable archive contract, disable hard removal by default, and add migration/doctor/docs/tests for existing archives.
- **Clarify but keep cleanup:** Keep physical cleanup available but split naming and retention knobs so retained transcripts are not described as deleted until they are actually removed.
- **Keep current lifecycle:** Leave `.deleted.*` and retention cleanup as-is and close this as an accepted operator-script/documentation risk.
