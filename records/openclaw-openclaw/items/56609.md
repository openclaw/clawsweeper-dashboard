## Summary

Keep open: current main and v2026.6.11 still create `.jsonl.deleted.*` and `.jsonl.reset.*` archives, and current retention plus disk-budget paths can physically remove session transcript artifacts. The merged role-ordering reset fix addressed one concrete hard-delete path, but the broader archive naming, migration, and purge-policy contract requested here remains unresolved.

## What This Changes

The issue asks OpenClaw to replace `.jsonl.deleted.*` and `.jsonl.reset.*` session transcript artifacts with archive-oriented naming or storage and to avoid physical transcript deletion.

## Best Possible Solution

Define one durable transcript lifecycle contract: retained transcripts should use archive-oriented names or storage, old suffixes should migrate through doctor/backfill rather than runtime shims, and any physical purge should be explicit, documented, and upgrade-tested.

Options:

- **Adopt archive terminology with migration (recommended):** Rename or move future retained transcripts, add doctor/backfill handling for old `.deleted.*` and `.reset.*` artifacts, and keep physical purge behind an explicit documented retention setting.
- **Keep behavior and clarify docs:** Leave current suffixes and cleanup behavior intact, but document that `.deleted.*` means detached until retention or disk-budget cleanup removes it.
- **Split naming from purge policy:** Use the narrower semantics issue for suffix/config terminology and track the no-physical-delete rule as a separate durability decision.
