## Label Justifications

- `P1`: The issue reports real irreversible transcript loss tied to current retained-session naming and cleanup semantics that still exist in main and the latest release.
- `impact:session-state`: The affected data is persisted session transcript lifecycle state across reset, delete, maintenance, archive cleanup, and disk-budget paths.

## Summary

Keep open: current main and v2026.6.11 still use `.jsonl.deleted.*` and `.jsonl.reset.*` archive names, and current retention plus disk-budget paths still physically remove those archive artifacts. This remains a real session-durability product decision, not stale cleanup or an implemented request.

## What This Changes

The issue asks OpenClaw to replace deletion-sounding session archive suffixes with clearer archive semantics and avoid hard removal of session transcript files.

## Best Possible Solution

Define a maintainer-approved durable transcript archive contract, then update naming, cleanup defaults, migration/compatibility handling, docs, and tests together.

## Reproduction Assessment

Yes, at source level: current main still creates `.jsonl.deleted.*`/`.jsonl.reset.*` archive names and has retention and disk-budget paths that physically remove archive artifacts. I did not run a live Gateway flow because the source and tests already prove the current behavior.

## Solution Assessment

No final implementation is selected yet. A rename-only patch would be too narrow because current parsers, tests, docs, memory/session tooling, cleanup, disk-budget behavior, and upgrade expectations depend on the shipped suffixes.
