## Label Justifications

- `P1`: The issue reports real-world irreversible loss of session transcripts, and current main plus the latest release still contain the naming and cleanup semantics behind that risk.
- `impact:data-loss`: The affected artifacts are the only durable copies of conversation transcripts after reset/delete/archive transitions and can be treated as disposable or physically removed.
- `impact:session-state`: The request concerns persisted session transcript lifecycle state across reset, delete, maintenance, archive cleanup, and disk-budget paths.

## Summary

Keep open: current main and the latest release still use `.jsonl.deleted.*` and `.jsonl.reset.*` archive names, and current retention plus disk-budget paths can still physically remove retained transcript artifacts. The merged role-ordering reset fix only addressed one hard-delete path, so the broader durable transcript archive contract still needs maintainer product direction.

## What This Changes

Requests replacing destructive session transcript archive naming with archive-oriented naming or storage and prohibiting physical removal of session transcript files.

## Best Possible Solution

Define a maintainer-approved durable transcript archive contract, keep existing `.deleted.*` and `.reset.*` files readable or migratable, then update new archive naming, cleanup defaults, disk-budget behavior, docs, and regression tests together.

## Reproduction Assessment

Yes, at source level. Current main still emits `.jsonl.deleted.*` and `.jsonl.reset.*` names and has retention and disk-budget code paths that physically remove matching transcript artifacts; this read-only review did not run a live Gateway flow.

## Solution Assessment

No final fix is selected yet. A rename-only change would be too narrow because current parsers, tests, docs, memory/session tooling, cleanup, disk-budget behavior, and upgrade expectations depend on the shipped suffixes.
