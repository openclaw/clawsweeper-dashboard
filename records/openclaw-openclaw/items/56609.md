## Label Justifications

- `P1`: The report is about transcript retention semantics that can lead to irreversible conversation-history loss in real deployments, but the remaining work is a product/upgrade decision rather than an emergency runtime outage.
- `impact:data-loss`: The issue reports lost session transcripts and asks OpenClaw to avoid naming or cleanup behavior that makes retained transcripts disposable.
- `impact:session-state`: The affected files are JSONL session transcripts used for conversation continuity, reset history, memory reprocessing, and session recovery.

## Summary

Keep open: current main still uses `.jsonl.deleted.*` and `.jsonl.reset.*` as core session archive names, and maintenance/disk-budget paths can still physically remove those artifacts. The merged role-ordering fix closed one hard-delete defect, but it did not implement this broader transcript-retention policy.

## What This Changes

The issue asks OpenClaw to stop using `.deleted.*` and `.reset.*` session transcript names and move to archive-oriented naming or storage so retained transcripts are not treated as disposable.

## Best Possible Solution

Define the canonical retained-transcript lifecycle in core: non-destructive archive naming/location, explicit retention controls, doctor migration for existing archive filenames if needed, and tests/docs covering reset, delete, cron/session maintenance, memory indexing, and disk-budget behavior.

Question: Should OpenClaw change the shipped session transcript archive contract from `.deleted.*`/`.reset.*` plus retention cleanup to a durable `.archived.*` or `sessions/archive/` model, and should archive transcripts ever be physically removed automatically?

Rationale: The current behavior is implemented across storage, maintenance, archive helpers, docs, and disk-budget cleanup; changing it affects existing on-disk data and operator expectations, so maintainer intent is required before a repair PR.

Likely owner: Peter Steinberger

Owner confidence: medium

Options:

- **Adopt durable archive semantics (recommended):** Rename or relocate retained transcripts, add migration/doctor coverage for existing archive files, and make physical deletion opt-in or separately configured.
- **Clarify current semantics only:** Keep `.deleted.*`/`.reset.*` and retention cleanup but document that these are retained artifacts only until maintenance or disk budget removes them.
- **Fix only concrete hard-delete paths:** Leave the naming policy unchanged and continue repairing narrow defects like the already-merged role-ordering reset unlink path.

## Solution Assessment

Unclear until maintainers choose the archive contract. A suffix-only rename is not the best fix by itself because shipped archives, retention rules, disk-budget cleanup, memory indexing, docs, and doctor migration need to stay coherent.
