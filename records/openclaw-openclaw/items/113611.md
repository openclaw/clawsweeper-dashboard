## Summary

This is a focused, plausible fix for the open Feishu configuration bug tracked at https://github.com/openclaw/openclaw/issues/111903. Current validation rejects uppercase `HTTPS://` before the plugin starts, while the runtime already accepts custom domains after removing trailing slashes; the patch makes the schema produce that canonical HTTPS form without adding a new setting. No patch defect or security concern was found. The branch is behind current `main`, so it should be refreshed and its remaining failed checks resolved before landing.

Likely related people: `m1heng` is the package-listed Feishu/Lark community contact (high confidence); `vincentkoc` is a recent adjacent contributor to the same configuration-schema surface (medium confidence).

## What This Changes

This PR changes Feishu custom-domain parsing so uppercase HTTPS schemes validate and normalize for top-level and per-account channel settings, with focused regression tests.

## System Context

The Feishu/Lark plugin validates `channels.feishu` configuration before creating channel clients. The validated domain is resolved into the Feishu SDK endpoint for each configured account, so rejection here prevents the channel from starting.
