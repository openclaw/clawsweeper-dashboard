## Summary

This PR has a strong bounded-read implementation direction, but it still changes the established HTTP `nextCursor` response from a numeric cursor to an opaque token without a response version or opt-in. Accepting old numeric cursors on input does not preserve clients that consume the returned cursor, so this protected gateway PR needs a maintainer decision before merge.

## What This Changes

The branch moves gateway HTTP/SSE visible-history pagination to bounded SQLite projection reads, introduces generation-aware opaque cursors, and exports the session-transcript runtime SDK subpath.

## Best Possible Solution

Keep bounded projection reads, but expose opaque pagination through a versioned or explicitly negotiated response contract while preserving the existing numeric response shape for legacy callers; then provide a redacted current-head Gateway/package-import run proving both paths.
