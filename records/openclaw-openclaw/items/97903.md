## Summary

Keep open: the PR is a focused and well-proven fix for accepted non-transient gateway disconnects, but it still leaves an accepted clean-close retry-exhaustion path able to fall through to the original-session embedded fallback.

## Best Possible Solution

Cover every accepted-then-closed path that can leave a detached gateway run before merge: non-transient closes should use the new fresh-session fallback, and exhausted transient accepted closes should not fall back on the original session either.
