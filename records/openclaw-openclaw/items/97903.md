## Summary

Keep this PR open: the core fresh-session direction is well scoped and now has real gateway proof, but the patch still loses the accepted-run signal across the transient retry wrapper, so a later retry failure can fall back onto the original session and leave the same duplicate-turn bug reachable.

## What This Changes

The PR propagates accepted gateway-run disconnects, routes that embedded fallback to a fresh `gateway-fallback-*` session, extends fallback metadata, and adds focused `agent-via-gateway` regression tests.

## Best Possible Solution

Keep the focused fresh-session fallback, but carry accepted-run context through the transient retry layer so every post-accept embedded fallback uses a `gateway-fallback-*` session; leave reattach-first recovery to the linked product-direction issue.
