## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still use manual numeric allowFrom setup, while related open items are broader or adjacent rather than a merged replacement for token-verified Telegram owner capture.

## What This Changes

The issue requests fresh Telegram setup to default to `dmPolicy: "allowlist"` and automatically populate `allowFrom` with the owner Telegram ID captured during onboarding.

## Best Possible Solution

Implement this as Telegram-owned onboarding: generate a short verification token, capture the matching numeric sender ID, write `dmPolicy="allowlist"` plus `allowFrom` for fresh private setup, and keep explicit pairing configs compatible with docs and tests.

## Reproduction Assessment

Yes. Source inspection of current main and v2026.6.11 shows Telegram still defaults to pairing, sends pairing challenges to unknown DMs, and uses manual numeric allowFrom setup rather than token-verified owner capture.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable path is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
