## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still rely on manual numeric allowFrom setup, while token-verified owner capture remains a security-sensitive product/default decision.

## What This Changes

The issue requests changing fresh Telegram setup to capture the owner's Telegram user ID and write dmPolicy="allowlist" with allowFrom instead of leaving pairing as the default.

## Best Possible Solution

Implement this as Telegram-owned onboarding: generate a short verification token, ask the intended owner to send it to the bot, capture the matching numeric sender ID, write allowlist config for fresh setup, and update schema/runtime/docs/tests while preserving explicit pairing-mode configs.

## Reproduction Assessment

Yes, source-level. Current main and v2026.6.11 still default Telegram dmPolicy to pairing, still issue pairing challenges to unknown DM senders, and still model setup as manual numeric allowFrom entry; I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable solution is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
