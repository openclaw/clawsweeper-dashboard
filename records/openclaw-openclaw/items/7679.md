## Summary

Keep open: current main and the latest release still default Telegram DMs to pairing and still rely on manual numeric allowFrom setup, while the linked work is broader or adjacent rather than a replacement for token-verified Telegram owner capture.

## What This Changes

The issue requests a safer Telegram first-run flow where setup captures the owner Telegram ID and writes dmPolicy="allowlist" plus allowFrom instead of defaulting DMs to pairing.

## Best Possible Solution

Implement this as Telegram-owned onboarding: generate a short verification token, ask the intended owner to send it to the bot, capture the matching numeric sender ID, write allowlist config for fresh setup, and update docs/tests while preserving explicit pairing-mode configs.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 still default Telegram dmPolicy to pairing and still model setup as pairing or manual numeric allowFrom entry. I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable path is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
