## Summary

Keep open: current main and the latest release still default Telegram DMs to pairing, still issue pairing challenges to unknown DM senders, and setup still asks for manual numeric allowFrom entry instead of token-verified owner ID capture. The request remains valid but needs maintainer product/security review because it changes fresh-setup trust semantics.

## What This Changes

The issue asks for Telegram onboarding to default fresh DM setup to allowlist mode by token-verifying and auto-capturing the owner Telegram ID.

## Best Possible Solution

A maintainer should choose the secure default shape, then implement Telegram-owned token-verified owner capture during onboarding, write dmPolicy="allowlist" plus allowFrom for the verified owner, update docs/schema/tests, and preserve explicit pairing-mode configs.

## Reproduction Assessment

Yes. Source and tests show current main defaults Telegram DM policy to pairing, sends pairing challenges to unknown DM senders, and setup asks for manual numeric allowFrom instead of token-verified owner capture.

## Solution Assessment

Unclear. Token-verified owner capture is a plausible secure implementation, but maintainers still need to decide the default trust semantics and upgrade boundary before code is queued.
