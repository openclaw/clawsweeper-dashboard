## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still issue pairing challenges to unknown DM senders, and still require manual numeric allowFrom entry instead of token-verified owner ID capture. The request remains valid, but it changes Telegram first-run authorization and upgrade semantics, so it needs maintainer product/security direction before implementation.

## What This Changes

The issue requests fresh Telegram setup to default to allowlist mode by capturing the owner Telegram ID during onboarding and writing it to allowFrom.

## Best Possible Solution

Implement a Telegram-owned onboarding path that displays a short verification token, captures only the matching numeric sender ID, writes dmPolicy="allowlist" plus allowFrom for fresh setup, and preserves explicit pairing-mode configurations.
