## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still require manual numeric allowFrom setup, while token-verified owner capture is a security-sensitive product decision.

## What This Changes

The issue asks Telegram setup to default to dmPolicy="allowlist" by capturing and storing the owner Telegram ID in allowFrom during onboarding.

## Best Possible Solution

Implement Telegram-owned token-verified owner capture during setup, write allowlist config for fresh setups, preserve explicit pairing-mode configs, and update schema/runtime/docs/tests together.
