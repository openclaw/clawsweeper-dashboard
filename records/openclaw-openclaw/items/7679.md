## Summary

Keep open: current main and v2026.6.11 still default omitted Telegram DM policy to pairing, still issue pairing challenges to unknown DM senders, and still require manually entered numeric allowFrom IDs instead of token-verified owner capture. The request remains useful, but it changes Telegram first-run authorization and default security semantics, so it needs maintainer product/security direction before implementation.

## What This Changes

Request fresh Telegram setup to default to dmPolicy="allowlist" by capturing the owner's numeric Telegram ID during onboarding.

## Best Possible Solution

Implement a Telegram-owned onboarding path that displays a short verification token, captures only the matching numeric sender ID, writes dmPolicy="allowlist" plus allowFrom for fresh setup, and preserves explicit pairing-mode configurations.
