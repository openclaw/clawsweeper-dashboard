## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and setup still requires manual numeric allowFrom entry, while the related issues/PRs are broader or adjacent rather than a replacement for token-verified owner capture.

## What This Changes

Request to make Telegram first-run DM access default to allowlist by capturing the owner Telegram ID during onboarding instead of defaulting to pairing.

## Best Possible Solution

Implement Telegram-owned onboarding that generates a short verification token, captures only the matching sender ID, writes dmPolicy="allowlist" plus allowFrom for fresh setup, and updates schema/runtime/docs/tests while preserving explicit pairing-mode configs.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 still default Telegram dmPolicy to pairing, still issue pairing challenges for unknown senders, and still model setup as manual numeric allowFrom entry. I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable path is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
