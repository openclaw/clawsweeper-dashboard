## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still require manual numeric allowFrom entry; the related open items are broader or adjacent, not replacements for this Telegram-specific verified owner-capture/default decision.

## What This Changes

This issue requests changing fresh Telegram setup from pairing-by-default to allowlist mode with the owner Telegram ID captured during onboarding.

## Best Possible Solution

Implement Telegram-owned onboarding that displays a short verification token, captures the sender only when that exact token is received, writes dmPolicy="allowlist" plus allowFrom for fresh setup, and preserves explicit pairing-mode configs with docs and tests.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 still default Telegram dmPolicy to pairing and still model setup as pairing or manual numeric allowFrom entry. I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable path is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
