## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still send pairing challenges to unknown DM senders, and still rely on manual numeric allowFrom entry rather than token-verified owner capture. The request is aligned with safer defaults, but it needs maintainer product/security review because a default flip alone can lock out fresh setups or change existing omitted-policy behavior.

## What This Changes

Request Telegram fresh setup to default DMs to allowlist mode by capturing the owner's numeric Telegram ID during onboarding.

## Best Possible Solution

Implement a maintainer-approved Telegram setup flow that verifies the intended owner with a short token, captures the matching numeric sender ID, writes dmPolicy="allowlist" plus allowFrom for fresh setup, and preserves explicit pairing compatibility for existing installs with docs and regression tests.

## Reproduction Assessment

Yes, at source level: current main still defaults omitted Telegram DM policy to pairing, sends pairing challenges to unknown DMs, documents pairing as default, and uses manual numeric allowFrom entry instead of verified owner capture. I did not run a live Telegram bot because this review is read-only.

## Solution Assessment

No, not as a blanket default flip or first-message capture. The best fix is verified fresh-setup owner enrollment plus a deliberate compatibility decision for existing omitted-policy installs.
