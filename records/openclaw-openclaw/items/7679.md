## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still use manual numeric allowFrom setup, while safe owner capture needs an explicit product/security decision.

## What This Changes

The issue asks for fresh Telegram setup to default DMs to allowlist by capturing the owner Telegram ID into allowFrom instead of leaving pairing as the default.

## Best Possible Solution

Implement Telegram-owned token-verified owner capture during setup, write allowlist config for fresh or implicit setups, preserve explicit pairing-mode configs, and update schema/runtime/docs/tests together.
