## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still issue pairing challenges to unknown DM senders, and still require manual numeric allowFrom entry instead of token-verified owner capture. The request remains valid, but it changes Telegram first-run trust and default authorization semantics, so it needs maintainer product/security direction before implementation.

## What This Changes

The issue requests Telegram setup/defaults to use allowlist mode with a verified owner Telegram ID instead of defaulting new bot DMs to pairing.

## Best Possible Solution

Implement Telegram-owned onboarding that displays a short verification token, captures only the matching numeric sender ID, writes allowlist mode for fresh setup, and preserves explicit pairing-mode configurations with docs and regression coverage.
