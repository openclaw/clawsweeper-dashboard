## Summary

Keep open: current main and v2026.6.11 still default omitted Telegram DM policy to pairing, still send pairing challenges to unknown DMs, and still use manual numeric allowFrom entry rather than token-verified owner capture during setup.

## What This Changes

Request that Telegram fresh setup default to allowlist by verifying and auto-capturing the owner Telegram ID into allowFrom instead of relying on pairing.

## Best Possible Solution

Implement a maintainer-approved Telegram setup flow that generates a short verification token, captures only the matching sender ID, writes dmPolicy="allowlist" plus allowFrom, and preserves explicit pairing compatibility with docs and regression tests.

## Reproduction Assessment

Yes, at source level: current main still defaults omitted Telegram DM policy to pairing, sends pairing challenges to unknown DMs, documents pairing as the default, and uses manual numeric allowFrom entry instead of verified owner capture. ## Solution Assessment

No, not as a blanket default flip or first-message capture. The maintainable solution is token-verified fresh-setup owner enrollment plus an explicit compatibility decision for existing omitted-policy installs.
