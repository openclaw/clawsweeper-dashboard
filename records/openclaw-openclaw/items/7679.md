## Summary

Keep open. Current main and the latest release still default Telegram DMs to pairing, setup still relies on manual numeric allowFrom entry, and the requested token-verified owner capture flow is not implemented; the issue remains valid but needs maintainer product/security direction before a fix PR.

## What This Changes

The issue requests safer Telegram first-run behavior by defaulting DMs to allowlist mode and capturing the intended owner Telegram ID during onboarding.

## Best Possible Solution

Add a Telegram-owned onboarding flow that generates a short verification token, captures only the matching sender's numeric Telegram ID, writes allowlist config for fresh setups, and preserves explicit pairing configs.

## Reproduction Assessment

Yes. Source inspection on current main reproduces the reported state: Telegram schema/runtime default to pairing, unauthorized DMs can receive pairing challenges, and setup/docs still require manual owner ID allowlisting instead of verified capture.

## Solution Assessment

No, changing only the default is not the best fix. The maintainable solution needs token-verified owner capture during Telegram setup plus compatibility handling for users who explicitly choose pairing.
