## Summary

Keep open: current main still defaults Telegram DMs to pairing, still issues pairing challenges for unknown DM senders, and still asks for manual numeric allowFrom entry instead of token-verified owner capture. Related open issues overlap but do not replace this Telegram-specific first-run owner enrollment request.

## What This Changes

Request fresh Telegram setup/default behavior to use allowlist mode with a verified owner Telegram ID instead of default pairing.

## Best Possible Solution

Implement a maintainer-approved Telegram setup flow that verifies the intended owner before writing dmPolicy="allowlist" and allowFrom, while preserving explicit pairing behavior for existing installs.

## Solution Assessment

No, not as a blanket default flip or first-message capture. The best fix is verified fresh-setup owner enrollment plus a deliberate compatibility decision for existing omitted-policy installs.
