## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still issue pairing challenges to unknown DM senders, and Telegram setup still collects manual numeric allowFrom IDs rather than token-verifying and auto-capturing the intended owner. This remains a valid security-default and onboarding request, but it needs maintainer product/security review before changing fresh-setup defaults or owner enrollment semantics.

## What This Changes

The issue requests changing fresh Telegram setup from default pairing mode to allowlist mode with a token-verified owner Telegram ID captured during onboarding.

## Best Possible Solution

Implement a Telegram-owned onboarding flow that displays a short verification token, captures only the matching sender's numeric Telegram ID, writes dmPolicy="allowlist" plus allowFrom, updates docs/tests, and preserves explicit pairing-mode configs for existing users.

## Reproduction Assessment

Yes, at source level: current schema/runtime still default Telegram DMs to pairing, tests cover the unauthorized pairing-challenge path, and setup/docs still model manual numeric allowFrom entry. I did not run a live Telegram bot because this review is read-only.

## Solution Assessment

Unclear as filed: safer Telegram defaults are aligned, but changing only the default is not enough because owner capture must be token-verified and upgrade compatibility must be defined.
