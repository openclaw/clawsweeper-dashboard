## Summary

Keep open: current main and the latest release still default Telegram DMs to pairing, still issue pairing challenges to unknown DM senders, and Telegram setup still collects a manual numeric allowlist rather than token-verifying and auto-capturing the owner ID. This remains a valid security-default and onboarding request, but it needs maintainer product/security review because changing fresh-setup defaults and owner capture can affect existing pairing-mode behavior.

## What This Changes

Request to make Telegram fresh setup/defaults use `dmPolicy: "allowlist"` with a verified owner Telegram ID in `allowFrom` instead of pairing by default.

## Best Possible Solution

Implement a Telegram-owned onboarding flow that shows a short verification token, captures only the matching sender's numeric Telegram ID, writes `dmPolicy: "allowlist"` plus `allowFrom`, and preserves explicit pairing-mode configs for existing users.

## Reproduction Assessment

Yes, at source level: current schema/runtime still default Telegram DMs to pairing, and tests cover the unauthorized pairing-challenge path. I did not run a live Telegram bot because this review is read-only.

## Solution Assessment

Unclear as filed: safer defaults are aligned, but changing only the default is not enough because owner capture must be token-verified and upgrade compatibility must be defined.
