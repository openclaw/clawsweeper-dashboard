## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still send pairing challenges to unknown DM senders, and still require manual numeric allowFrom entry rather than token-verified owner capture during onboarding.

## What This Changes

The issue requests a safer Telegram first-run flow that defaults DMs to allowlist mode by capturing the owner's Telegram ID during onboarding.

## Best Possible Solution

Implement this as Telegram-owned onboarding: generate a short verification token, require the intended owner to send it, capture that numeric sender ID, write dmPolicy="allowlist" plus allowFrom for fresh private setup, and keep explicit pairing configs compatible with updated docs and tests.

## Reproduction Assessment

Yes. Source inspection of current main and v2026.6.11 shows Telegram still defaults to pairing, sends pairing challenges to unknown DMs, and uses manual numeric allowFrom setup rather than token-verified owner capture.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable path is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
