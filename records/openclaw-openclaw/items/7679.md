## Summary

Keep open: current main and the latest release still default Telegram DMs to pairing and still rely on manual numeric allowFrom setup, while token-verified owner capture remains an unimplemented security-sensitive product decision.

## What This Changes

The issue requests changing fresh Telegram setup from pairing-mode DMs to an allowlist seeded with the verified owner Telegram user ID.

## Best Possible Solution

Implement this as Telegram-owned onboarding: generate a short verification token, require the intended owner to send it to the bot, capture the matching numeric sender ID, write allowlist config for fresh setup, preserve explicit pairing-mode configs, and update docs/tests together.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 still default Telegram dmPolicy to pairing, still issue pairing challenges to unknown DM senders, and still model setup as manual numeric allowFrom entry. I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable path is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
