## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still use manual numeric allowFrom setup, while token-verified owner capture remains a security-sensitive product/default decision.

## What This Changes

The issue requests changing Telegram first-run DM access from pairing by default to token-verified owner capture with dmPolicy="allowlist" and allowFrom set to the owner ID.

## Best Possible Solution

Implement Telegram-owned token-verified owner capture during fresh setup, write dmPolicy="allowlist" plus allowFrom for that owner, preserve explicit pairing-mode configs, and update schema/runtime/docs/tests together.
