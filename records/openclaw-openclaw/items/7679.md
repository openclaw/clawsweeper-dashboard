## Summary

Keep open: current main and the latest release still default Telegram DMs to pairing, still send pairing challenges to unknown DM senders, and still require manual numeric allowFrom entry instead of token-verified owner capture.

## What This Changes

The issue requests changing fresh Telegram setup to default to dmPolicy="allowlist" and automatically add the verified owner Telegram ID to allowFrom.

## Best Possible Solution

Implement this as Telegram-owned onboarding: generate a short verification token, require the intended owner to send that token to the bot, capture the matching numeric sender ID, write allowlist config for fresh setup, and update docs/tests while preserving explicit pairing-mode configs.

Yes, at source level: current main still defaults omitted Telegram DM policy to pairing, sends pairing challenges to unknown DMs, documents pairing as default, and uses manual numeric allowFrom entry instead of verified owner capture. ## Solution Assessment

No, not as a blanket default flip or first-message capture. The maintainable solution is verified fresh-setup owner enrollment plus a deliberate compatibility decision for existing omitted-policy installs.
