## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still use manual numeric allowFrom setup, while token-verified owner capture remains a security-sensitive default/product decision.

## What This Changes

The issue requests changing Telegram onboarding defaults from pairing to token-verified owner capture with dmPolicy="allowlist" and allowFrom populated from the owner Telegram ID.

## Best Possible Solution

Implement Telegram-owned onboarding that shows a short verification token, accepts only the matching Telegram message as owner proof, writes dmPolicy="allowlist" plus the numeric owner allowFrom for fresh setup, and preserves explicit pairing-mode configs with docs and regression coverage.

No for a literal default-only flip or blind first-message capture. The maintainable path is token-verified owner capture during Telegram setup with explicit pairing-mode compatibility and docs/tests updated together.
