## Summary

Keep open: current main and the latest checked release still default Telegram DMs to pairing, and the repository has not implemented a token-verified Telegram owner capture flow that seeds an allowlist by default. The request remains useful, but it changes access-control defaults and onboarding behavior, so it needs maintainer product and security review rather than an automatic fix.

## What This Changes

Request fresh Telegram setup to default DMs to allowlist by capturing a verified owner Telegram ID during onboarding.

## Best Possible Solution

Add a Telegram-owned setup flow that shows a short verification token, accepts only the sender who returns it, writes dmPolicy="allowlist" with allowFrom, and preserves explicit pairing behavior for existing installs unless maintainers approve a migration.

## Reproduction Assessment

Yes at source level: omitted Telegram dmPolicy still defaults to pairing, unauthorized DMs still enter the pairing challenge path, and setup/docs still require manual numeric allowFrom configuration rather than verified owner capture.

## Solution Assessment

A default-only change is not the best fix; the safer direction is verified owner enrollment plus explicit upgrade behavior for existing pairing-mode installs.
