## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still issue pairing challenges to unknown DM senders, and still require manual numeric allowFrom entry rather than token-verified owner capture. The request remains valid but changes the Telegram authorization boundary and first-run setup semantics, so it needs maintainer product/security direction before implementation.

## What This Changes

The issue requests changing fresh Telegram setup to default to dmPolicy="allowlist" by capturing the owner's numeric Telegram ID during onboarding.

## Best Possible Solution

Implement a Telegram-owned onboarding path that generates a short verification token, captures only the matching numeric sender ID, writes dmPolicy="allowlist" plus allowFrom for fresh setup, and preserves explicit pairing-mode configurations.
