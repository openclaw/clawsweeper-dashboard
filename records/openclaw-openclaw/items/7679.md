## Summary

Keep open: current main and v2026.6.11 still use pairing for an unset Telegram DM policy and require manual owner-ID enrollment. Broader bootstrap proposals overlap but do not replace this narrower Telegram trust-boundary decision, which needs maintainer product and security direction.

## What This Changes

Make fresh Telegram onboarding securely identify the owner and configure `dmPolicy: "allowlist"` with that owner’s numeric Telegram ID.

## Best Possible Solution

Implement Telegram-owned, challenge-token-verified first-owner enrollment that persists the existing allowlist fields after verification, preserves explicit pairing configurations, and proves fresh-install, interrupted-enrollment, and upgrade behavior.
