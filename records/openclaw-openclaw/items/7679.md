## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, setup still relies on manual numeric allowFrom entry, and related work only partially overlaps without implementing token-verified owner capture.

## What This Changes

The issue requests changing fresh Telegram setup from pairing-by-default to allowlist-by-default by capturing the owner's Telegram user ID into allowFrom during onboarding.

## Best Possible Solution

Implement Telegram-owned token-verified owner capture for fresh setup, write dmPolicy="allowlist" plus allowFrom for the verified owner, preserve explicit pairing configs, and update schema/runtime/docs/tests together.
