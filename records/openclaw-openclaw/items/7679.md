## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to `pairing` and still model setup as manual numeric `allowFrom` entry. The related issues overlap, but none replaces this Telegram-specific token-verified owner-capture/default decision.

## What This Changes

The issue requests changing fresh Telegram setup to default to `dmPolicy: "allowlist"` by capturing the owner Telegram ID during onboarding.

## Best Possible Solution

Implement this as Telegram-owned onboarding: generate a short verification token, ask the intended owner to send that token to the bot, capture the matching numeric sender ID, write `dmPolicy="allowlist"` plus `allowFrom` for fresh setup, and preserve explicit pairing-mode configs.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 still default Telegram `dmPolicy` to `pairing`, still send pairing challenges to unauthorized DMs under that policy, and still model setup as manual numeric `allowFrom` entry. I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable path is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
