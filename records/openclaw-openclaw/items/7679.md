## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still use manual numeric allowFrom setup, while token-verified owner capture remains a security-sensitive product/default decision.

## What This Changes

The issue requests Telegram fresh setup to default to dmPolicy="allowlist" and automatically capture the owner Telegram ID into allowFrom.

## Best Possible Solution

Implement Telegram-owned token-verified owner capture during setup: generate a short challenge, require the intended owner to send it, capture the matching numeric sender ID, write allowlist config for fresh setup, and preserve explicit pairing-mode configs.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 still default Telegram dmPolicy to pairing, still issue pairing challenges to unknown DM senders, and still model setup as manual numeric allowFrom entry. I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

No for a literal default-only flip or blind first-message capture. The maintainable path is token-verified owner capture during Telegram setup with explicit pairing-mode compatibility and docs/tests updated together.
