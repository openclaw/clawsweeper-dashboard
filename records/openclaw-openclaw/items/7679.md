## Summary

Keep open: current main and the latest release still default Telegram DMs to pairing, still issue pairing challenges for unknown DM senders, and still require manual numeric `allowFrom` entry rather than token-verified owner capture. The related open items overlap, but none is a merged or clearly canonical replacement for this narrow Telegram first-owner setup/default request.

## What This Changes

Request Telegram first-run setup to default DMs to `allowlist` and populate `allowFrom` from a verified owner Telegram ID.

## Best Possible Solution

Implement a Telegram-owned onboarding/default flow that generates a short verification token, captures only the matching Telegram sender, writes `dmPolicy="allowlist"` plus numeric `allowFrom`, and preserves explicit existing pairing configs.
