## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still use manual numeric allowFrom setup, while token-verified owner capture remains a security-sensitive product/default decision.

## What This Changes

The issue requests that Telegram setup default to dmPolicy="allowlist" by auto-capturing the owner Telegram ID into allowFrom during onboarding.

## Best Possible Solution

Implement Telegram-owned token-verified owner capture during setup, write allowlist config for fresh setups, preserve explicit pairing-mode configs, and update schema/runtime/docs/tests together.
