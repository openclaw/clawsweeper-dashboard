## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still model setup as manual numeric allowFrom entry, while the requested token-verified owner capture remains a security-sensitive product decision.

## What This Changes

The issue requests making Telegram first-run DM setup default to allowlist mode by capturing the owner Telegram ID during onboarding.

## Best Possible Solution

Make a maintainer product/security decision, then implement Telegram-owned onboarding that generates a short verification token, captures only the matching sender ID, writes dmPolicy="allowlist" plus allowFrom for that owner, and updates docs and regression tests while preserving explicit pairing configs.

## Reproduction Assessment

Yes, at source level: omit channels.telegram.dmPolicy and current schema/runtime still resolve Telegram DMs to pairing; unknown DM senders can reach the pairing challenge path. I did not run a live Telegram bot because this was a read-only review.

## Solution Assessment

Partly: allowlist-by-owner is the right security direction, but the safe implementation must be token-verified and explicit about upgrade semantics rather than blindly capturing the first inbound message.
