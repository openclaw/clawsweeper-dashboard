## Summary

Keep open: current main and the latest release still default Telegram DMs to pairing, still send pairing challenges to unknown DM senders, and still rely on manual numeric allowFrom entry rather than token-verified owner capture during onboarding.

## What This Changes

Request to make fresh Telegram setup default to dmPolicy="allowlist" by verifying and capturing the owner's numeric Telegram ID into allowFrom.

## Best Possible Solution

Implement a maintainer-approved Telegram onboarding flow that displays a short verification token, captures only the matching numeric sender ID, writes dmPolicy="allowlist" plus allowFrom, and preserves explicit pairing compatibility with docs and focused regression coverage.

## Reproduction Assessment

Yes, at source level: current main still defaults omitted Telegram DM policy to pairing, sends pairing challenges to unknown DMs, documents pairing as default, and uses manual numeric allowFrom entry instead of verified owner capture. I did not run a live Telegram bot because this review is read-only.

## Solution Assessment

No, not as a blanket default flip or first-message capture. The maintainable solution is verified fresh-setup owner enrollment plus a deliberate compatibility decision for existing omitted-policy installs.
