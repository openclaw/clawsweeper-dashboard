## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, while setup and docs still rely on manual numeric allowFrom entry rather than token-verified owner ID capture. The remaining work is useful but security- and compatibility-sensitive, so it needs maintainer product/security review rather than automatic cleanup.

## What This Changes

Request fresh Telegram setup to default to dmPolicy="allowlist" by capturing the owner Telegram ID during onboarding.

## Best Possible Solution

Implement Telegram-owned onboarding that displays a short verification token, captures only the matching DM sender ID, writes dmPolicy="allowlist" with allowFrom for that account, and updates schema/runtime/docs/tests while preserving explicit pairing configs.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 still default Telegram dmPolicy to pairing, still send pairing challenges to unknown DM senders, and still model setup as manual numeric allowFrom entry. I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

Yes, the token-verified owner-capture direction is the maintainable shape; changing only the default to allowlist is incomplete because allowlist requires a known owner ID, and blind first-message capture would create a race.
