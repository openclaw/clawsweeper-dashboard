## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still rely on manual numeric allowFrom setup, while token-verified owner capture is an unresolved security/product decision.

## What This Changes

The issue requests changing fresh Telegram setup/defaults so DMs use `dmPolicy: "allowlist"` with the owner Telegram user ID captured into `allowFrom`.

## Best Possible Solution

Implement Telegram-owned token-verified owner capture during setup, write allowlist config for fresh implicit setups, preserve explicit pairing-mode configs, and update schema/runtime/docs/tests with live Telegram proof.
