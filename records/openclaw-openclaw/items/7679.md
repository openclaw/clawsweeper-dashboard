## Summary

Keep open: origin/main still defaults Telegram DMs to pairing, still sends pairing challenges to unknown DM senders, and still uses manual numeric allowFrom setup rather than token-verified owner capture. The related open items overlap, but none is a merged replacement for this narrow Telegram first-owner setup/default request.

## What This Changes

The issue requests changing fresh Telegram setup from pairing-by-default to token-verified owner capture that writes dmPolicy="allowlist" and allowFrom for the captured owner ID.

## Best Possible Solution

Implement a Telegram-owned onboarding/default flow that generates a short verification token, captures only the matching Telegram sender, writes dmPolicy="allowlist" plus numeric allowFrom, and preserves explicit existing pairing configs.
