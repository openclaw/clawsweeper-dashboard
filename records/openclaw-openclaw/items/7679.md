## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still use manual numeric allowFrom setup, while token-verified owner capture remains a security-sensitive product decision.

## What This Changes

The issue requests changing Telegram setup/defaults so a fresh Telegram bot uses dmPolicy="allowlist" with the owner's numeric Telegram ID captured during onboarding.

## Best Possible Solution

Implement Telegram-owned onboarding that generates a short verification token, captures the matching numeric sender ID, writes allowlist config for fresh setup, and preserves explicit pairing-mode configs with docs and tests updated together.

## Reproduction Assessment

Yes. Source inspection of current main and v2026.6.11 shows Telegram still defaults omitted dmPolicy to pairing, still sends pairing challenges to unknown DMs, and still models setup as manual numeric allowFrom entry.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable solution is token-verified owner capture during Telegram setup, plus explicit compatibility for users who choose pairing mode.
