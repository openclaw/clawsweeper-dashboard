## Summary

Keep open: current main and v2026.6.11 still use Telegram pairing as the default and manual numeric allowFrom setup, while the related open work is overlapping rather than a merged replacement. The remaining change is security- and product-sensitive owner enrollment/default behavior.

## What This Changes

The issue requests changing Telegram setup/defaults from pairing mode to token-verified owner allowlist enrollment.

## Best Possible Solution

Implement a maintainer-approved Telegram onboarding path that generates a short verification token, captures only the matching sender ID, writes dmPolicy="allowlist" plus allowFrom, and preserves explicit pairing compatibility with docs and regression tests.

## Reproduction Assessment

Yes. At source level, omitting channels.telegram.dmPolicy still resolves to pairing, unknown DMs still take the pairing-challenge path, and setup/docs still use manual numeric allowFrom entry rather than token-verified owner capture.

## Solution Assessment

No as a blanket default flip or first-message capture. The maintainable solution is token-verified fresh-setup owner enrollment plus an explicit compatibility decision for existing omitted-policy installs.
