## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still issue pairing challenges to unknown DM senders, and still rely on manual numeric allowFrom setup; the requested token-verified owner capture remains a valid but security-sensitive product decision.

## What This Changes

The issue requests changing Telegram onboarding/default behavior from pairing to allowlist with the owner Telegram ID captured during setup.

## Best Possible Solution

Implement this as Telegram-owned onboarding: generate a short verification token, require the intended owner to send it to the bot, capture the matching numeric sender ID, write allowlist config for fresh setup, and preserve explicit pairing-mode configs.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 still default Telegram dmPolicy to pairing, still issue pairing challenges to unknown DM senders, and still model setup as manual numeric allowFrom entry. I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable path is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
