## Summary

Keep open: current main and the latest release still default Telegram DMs to pairing, still send pairing challenges to unknown DM senders, and still require manual numeric `allowFrom` entry rather than token-verified owner capture. The request is a valid security-default improvement, but it changes Telegram first-run trust and upgrade semantics, so it needs maintainer product/security review instead of an automatic cleanup close.

## What This Changes

The issue requests changing Telegram first-run DM setup from pairing mode to token-verified owner capture with `dmPolicy: "allowlist"` and the owner ID in `allowFrom`.

## Best Possible Solution

Implement this as Telegram-owned onboarding: generate a short verification token, ask the intended owner to send it to the bot, capture the matching numeric sender ID, write allowlist config for fresh setup, and update schema/runtime/docs/tests while preserving explicit pairing-mode configs.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 still default Telegram dmPolicy to pairing, still issue pairing challenges to unknown DM senders, and still model setup as manual numeric allowFrom entry. I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable path is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
