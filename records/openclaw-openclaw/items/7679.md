## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still send pairing challenges to unknown DM senders, and still require manual numeric allowFrom entry rather than token-verified owner capture during onboarding. Related open items overlap, but none is a merged canonical fix for this narrower fresh Telegram setup/default request.

## What This Changes

The issue requests changing fresh Telegram setup/defaults from pairing-mode DMs to token-verified owner capture with dmPolicy="allowlist" and allowFrom populated for the owner.

## Best Possible Solution

Implement a maintainer-approved Telegram setup flow that generates a short verification token, captures only the matching sender ID, writes dmPolicy="allowlist" plus allowFrom for that account, and preserves explicit pairing compatibility for existing installs with docs and regression tests.

No, not as a simple default flip or first-message capture. The best path is verified fresh-setup owner enrollment plus a deliberate compatibility decision for existing omitted-policy installs.
