## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and setup still asks for manual numeric allowFrom entry rather than token-verified owner capture. The request is aligned with security and first-run UX priorities, but it changes Telegram first-run trust and upgrade semantics, so it needs maintainer product/security direction before implementation.

## What This Changes

Requests Telegram fresh setup to use allowlist mode with a captured owner Telegram ID instead of defaulting to pairing.

## Best Possible Solution

Implement a Telegram-owned onboarding path that generates a short verification token, captures only the matching sender ID, writes dmPolicy="allowlist" plus allowFrom for fresh owner setup, and preserves explicit pairing-mode configurations.
