## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and manual numeric allowFrom setup, while the requested token-verified owner capture remains missing and security-sensitive.

## What This Changes

Request Telegram onboarding to default new private bots to allowlist mode by capturing the owner's numeric Telegram ID during setup.

## Best Possible Solution

Implement Telegram-owned setup that shows a one-time verification token, captures only the sender who sends that token, writes dmPolicy="allowlist" with that numeric ID for fresh setup, and documents/tests explicit pairing-mode compatibility.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 still default Telegram dmPolicy to pairing, still issue pairing challenges to unknown DM senders, and still model setup as manual numeric allowFrom entry. I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable path is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
