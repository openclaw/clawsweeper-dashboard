## Summary

Keep open: current main still defaults Telegram DMs to pairing, still sends pairing challenges to unknown DM senders, and still uses manual numeric allowFrom setup; the safe version of this request needs maintainer product/security direction for verified owner capture and upgrade behavior.

## What This Changes

The issue requests changing fresh Telegram setup from pairing-mode DMs to allowlist mode seeded with the owner Telegram ID captured during onboarding.

## Best Possible Solution

Implement a Telegram-owned, token-verified owner-capture setup path that writes dmPolicy="allowlist" and allowFrom for fresh setups while preserving explicit pairing-mode configs, then update schema/runtime/docs/tests together.
