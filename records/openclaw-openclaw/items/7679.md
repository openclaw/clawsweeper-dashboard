## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still use manual numeric allowFrom setup, while safe owner capture needs a product/security decision.

## What This Changes

The issue requests that Telegram onboarding default direct messages to allowlist mode by capturing the owner's Telegram ID during setup.

## Best Possible Solution

Implement Telegram-owned token-verified owner capture during setup, write allowlist config for fresh setups, preserve explicit pairing-mode configs, and update schema/runtime/docs/tests together.

- **Keep pairing as the default:** Document pairing as the intentional first-run default and leave owner-only Telegram access as explicit manual allowlist setup.

## Reproduction Assessment

Yes. At source level, current main and v2026.6.11 still default Telegram dmPolicy to pairing, still issue pairing challenges to unknown DM senders, and still model setup as manual numeric allowFrom entry; I did not run a live Telegram setup flow in this read-only review.

## Solution Assessment

No for a literal default-only flip or blind first-message capture. The maintainable path is token-verified owner capture during Telegram setup with explicit pairing-mode compatibility and docs/tests updated together.
