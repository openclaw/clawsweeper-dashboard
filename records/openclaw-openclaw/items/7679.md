## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still issue pairing challenges to unknown DM senders, and still require manual numeric allowFrom entry instead of token-verified owner ID capture. The request remains valid, but it changes Telegram first-run authorization and omitted-config upgrade semantics, so it needs maintainer product/security direction before implementation.

## What This Changes

Change Telegram setup/defaults so fresh bots use dmPolicy="allowlist" with the owner Telegram ID captured into allowFrom during onboarding.

## Best Possible Solution

Implement a Telegram-owned onboarding flow that displays a short verification token, captures only the matching numeric sender ID, writes dmPolicy="allowlist" plus allowFrom for fresh setup, and preserves explicit pairing-mode configurations.
