## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still issue pairing challenges to unknown DM senders, and setup still asks for manual numeric allowFrom entry rather than token-verified owner capture. Related open issues and PRs overlap, but none replace the focused Telegram owner-enrollment/defaults decision.

## What This Changes

The issue requests changing Telegram onboarding/default configuration from pairing-mode DMs to an allowlist seeded with the owner Telegram ID.

## Best Possible Solution

Implement a maintainer-approved Telegram onboarding path that generates a short verification token, captures only the matching sender ID, writes dmPolicy="allowlist" plus allowFrom, and preserves explicit pairing compatibility with docs and regression tests.

## Reproduction Assessment

Yes, at source level: omit channels.telegram.dmPolicy and current main resolves Telegram DMs to pairing, sends pairing challenges to unknown senders, and setup/docs still require manual numeric allowFrom entry. I did not run a live Telegram bot because this review is read-only.

## Solution Assessment

No, not as a blanket default flip or first-message capture. The maintainable solution is token-verified fresh-setup owner enrollment plus an explicit compatibility decision for existing omitted-policy installs.
