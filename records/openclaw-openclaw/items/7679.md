## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still use manual numeric allowFrom setup, while token-verified owner capture remains a security-sensitive default/onboarding decision.

## What This Changes

The issue requests fresh Telegram setup to default to owner-only allowlist mode by capturing the intended owner Telegram ID during onboarding.

## Best Possible Solution

Implement Telegram-owned token-verified owner capture during fresh setup, write dmPolicy="allowlist" plus allowFrom for that owner, preserve explicit pairing-mode configs, and update schema/runtime/docs/tests together.
