## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still send pairing challenges to unknown DM senders, and still require manual numeric allowFrom entry instead of token-verified owner capture during onboarding. The request remains valid, but it changes Telegram access-control defaults and first-owner enrollment, so it needs maintainer product/security review before implementation.

## What This Changes

The issue requests changing Telegram onboarding/defaults so a new setup uses `dmPolicy: "allowlist"` with the owner Telegram ID captured during setup instead of defaulting to pairing mode.

## Best Possible Solution

Implement verified Telegram owner enrollment during setup, then write explicit `dmPolicy: "allowlist"` and owner `allowFrom` for fresh setups while preserving explicit pairing behavior for existing configs.

## Reproduction Assessment

Yes, at source level: current main still defaults omitted Telegram DM policy to pairing, sends pairing challenges for unknown DMs in pairing mode, and documents pairing as the default. I did not run a live Telegram bot because this read-only review does not mutate setup or credentials.

## Solution Assessment

No, not as a blanket default flip or first-message capture. The safer solution is a token-verified fresh-setup owner enrollment flow plus an explicit compatibility policy for existing omitted-policy installs.
