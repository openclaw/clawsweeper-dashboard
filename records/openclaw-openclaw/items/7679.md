## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still issue pairing challenges to unknown DM senders, and setup/docs still model manual numeric allowFrom entry rather than token-verified owner capture. The related open items are useful context, but they are partial overlaps rather than a merged fix for this narrower Telegram onboarding/default request.

## What This Changes

Request to make Telegram fresh setup/defaults use allowlist mode with a verified owner Telegram ID captured into allowFrom instead of leaving pairing as the default.

## Best Possible Solution

Make a maintainer product/security decision for Telegram first-run trust, then implement token-verified owner ID capture in Telegram setup that writes dmPolicy="allowlist" plus allowFrom for fresh setups while preserving existing explicit pairing-mode configs.

## Reproduction Assessment

Yes, at source level: current main still defaults Telegram dmPolicy to pairing, sends pairing challenges to unknown DMs, and setup only writes allowlist after manual numeric allowFrom input. I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

Unclear as an implementation proposal: allowlist-by-default with verified owner capture is a plausible safer direction, but changing the default alone is not the best fix without a maintainer-approved token verification and upgrade-compatibility shape.
