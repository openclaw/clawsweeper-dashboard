## Summary

Keep open: current main still defaults Telegram DMs to pairing, still issues pairing challenges to unknown DM senders, and still asks for manual numeric allowFrom entry rather than token-verified owner capture during onboarding.

## What This Changes

Request fresh Telegram setup to default to allowlist mode by capturing the owner Telegram ID during onboarding and writing it to allowFrom.

## Best Possible Solution

Implement Telegram-owned onboarding that token-verifies the intended owner, writes dmPolicy="allowlist" plus numeric allowFrom for fresh owner setup, preserves explicit pairing-mode configs, and updates docs and tests.

## Reproduction Assessment

Yes, at source level: current main defaults Telegram dmPolicy to pairing, sends pairing challenges to unauthorized DMs, and setup still requires manual numeric allowFrom entry. I did not run a live Telegram bot because this review is read-only.

## Solution Assessment

Unclear as filed: the safer-default direction is sound, but the best fix must include token-verified owner capture and compatibility semantics rather than only flipping the default.
