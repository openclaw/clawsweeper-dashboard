## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still rely on manual numeric allowFrom setup, and still issue pairing challenges to unknown DM senders. The requested safer default is valid but needs a maintainer product/security decision because owner capture, first-run trust, and existing pairing-mode compatibility must be designed together.

## What This Changes

The issue requests Telegram fresh setup to capture the intended owner ID during onboarding and write `dmPolicy: "allowlist"` plus `allowFrom` instead of relying on default pairing.

## Best Possible Solution

Implement Telegram-owned token-verified owner capture during setup, write allowlist config for fresh setups, preserve explicit pairing-mode configs, and update schema/runtime/docs/tests together.
