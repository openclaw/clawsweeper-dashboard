## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still require manual numeric allowFrom entry; the related issues and open PRs are adjacent or broader, not a merged replacement for this Telegram-specific verified owner-capture/default decision.

## What This Changes

Request Telegram setup to default to dmPolicy="allowlist" by capturing the owner Telegram ID during onboarding instead of leaving fresh configs in pairing mode.

## Best Possible Solution

Implement this as Telegram-owned onboarding: generate a short verification token, capture the matching numeric sender ID, write dmPolicy="allowlist" plus allowFrom for fresh private setup, and keep explicit pairing configs compatible with docs and tests.

## Reproduction Assessment

Yes, at source level: current main still defaults Telegram dmPolicy to pairing, still sends pairing challenges to unauthorized DM senders, and still models setup as manual numeric allowFrom entry. I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable path is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
