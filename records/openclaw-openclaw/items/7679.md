## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still rely on manual numeric allowFrom entry, while token-verified owner capture remains missing and security-sensitive.

## What This Changes

The issue requests fresh Telegram setup to default to dmPolicy="allowlist" and automatically capture the owner's Telegram user ID into allowFrom.

## Best Possible Solution

Implement this as Telegram-owned onboarding: generate a short verification token, capture only the matching sender's numeric Telegram ID, write allowlist config for fresh setup, and preserve explicit pairing-mode configs with docs, tests, and live Telegram proof.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 still default Telegram DMs to pairing, still issue pairing challenges to unknown DM senders, and still model setup as manual numeric allowFrom entry; I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable path is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
