## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still use manual numeric `allowFrom` setup, while token-verified owner capture is a security-sensitive default/product decision.

## What This Changes

The issue requests changing fresh Telegram setup to default to `dmPolicy: "allowlist"` with the owner Telegram ID captured during onboarding.

## Best Possible Solution

Implement Telegram-owned token-verified owner capture during setup, write allowlist config for fresh implicit setups, preserve explicit pairing-mode configs, and update schema/runtime/docs/tests together.
