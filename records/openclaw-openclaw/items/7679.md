## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and still require manual numeric allowFrom entry, while the related issues cover broader or adjacent work rather than replacing this Telegram-specific verified owner-capture/default decision.

## What This Changes

The issue requests a safer Telegram first-run setup that defaults to allowlist mode by capturing the owner's Telegram ID during onboarding.

## Best Possible Solution

Implement this as Telegram-owned onboarding: generate a short verification token, capture the matching numeric sender ID, write dmPolicy="allowlist" plus allowFrom for fresh private setup, and keep explicit pairing configs compatible with docs and tests.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 still default Telegram dmPolicy to pairing and still model setup as pairing or manual numeric allowFrom entry. I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable path is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
