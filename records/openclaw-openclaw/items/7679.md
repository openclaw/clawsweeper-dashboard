## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, while onboarding still asks for manual numeric allowFrom entry rather than token-verified owner capture. The request is a valid security-default improvement, but it changes first-run trust and authorization semantics, so it needs maintainer product/security direction before implementation.

## What This Changes

Request Telegram setup/defaults to use dmPolicy="allowlist" with the owner Telegram ID captured during onboarding instead of continuing to default to pairing.

## Best Possible Solution

Implement a Telegram-owned onboarding path that generates a short verification token, captures only the matching sender ID, writes dmPolicy="allowlist" plus allowFrom for fresh owner setup, and preserves explicit pairing-mode configurations.
