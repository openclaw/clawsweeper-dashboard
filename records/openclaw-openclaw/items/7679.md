## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and setup still records manually entered numeric allowFrom IDs, while the related issues cover broader bootstrap or adjacent hardening rather than replacing this Telegram-specific verified owner-capture/default decision.

## What This Changes

Request Telegram setup/defaults to use dmPolicy="allowlist" with the owner's Telegram user ID captured during onboarding instead of defaulting fresh DMs to pairing.

## Best Possible Solution

Implement this as Telegram-owned onboarding: generate a short verification token, capture the matching numeric sender ID, write dmPolicy="allowlist" plus allowFrom for fresh private setup, and preserve explicit pairing-mode compatibility with docs and tests updated together.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 still default Telegram dmPolicy to pairing and still model setup as pairing or manual numeric allowFrom entry. I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

No for the raw suggested shape: a blind default flip or first-message capture is not the best fix. The maintainable path is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
