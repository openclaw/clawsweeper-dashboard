## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still issue pairing challenges for unknown DM senders, and setup still asks for manual numeric allowFrom entry rather than token-verified owner capture. Related open items overlap, but none replace this focused Telegram owner-enrollment and default-policy decision.

## What This Changes

Request that Telegram fresh setup default DMs to allowlist by capturing the owner Telegram ID during onboarding instead of leaving omitted dmPolicy in pairing mode.

## Best Possible Solution

Implement a maintainer-approved Telegram onboarding path that verifies a short owner token, captures only the matching numeric sender ID, writes allowlist config, and preserves explicit pairing compatibility with docs and regression tests.

## Reproduction Assessment

Yes, at source level: omit channels.telegram.dmPolicy and current main resolves Telegram DMs to pairing, sends pairing challenges to unknown senders, and setup/docs still require manual numeric allowFrom entry. I did not run a live Telegram bot because this review is read-only.

## Solution Assessment

No, not as a blanket default flip or first-message capture. The maintainable solution is token-verified fresh-setup owner enrollment plus an explicit compatibility decision for existing omitted-policy installs.
