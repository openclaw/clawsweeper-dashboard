## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still document pairing approval as the quick setup path, and still require manual numeric allowFrom entry rather than token-verified owner capture. The related open issues overlap, but none supersedes this Telegram-specific onboarding/default decision.

## What This Changes

The issue requests changing Telegram setup/defaults from pairing mode to verified owner allowlist mode with the owner Telegram ID captured during onboarding.

## Best Possible Solution

Add Telegram-owned onboarding that generates a short verification token, captures the matching numeric sender ID, writes dmPolicy="allowlist" plus allowFrom for fresh private setup, and updates docs/tests while preserving explicit pairing configs.

## Reproduction Assessment

Yes, at source level: current main still defaults Telegram dmPolicy to pairing and setup/docs/tests still model pairing or manual numeric allowFrom entry. I did not run a live Telegram onboarding path because this was a read-only review.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable solution is verified owner capture during Telegram setup plus compatibility for explicit pairing-mode configurations.
