## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still send pairing challenges to unknown DM senders, and still rely on manual numeric allowFrom entry instead of token-verified owner capture during onboarding.

## What This Changes

Request fresh Telegram setup to default to allowlist mode by capturing the owner’s Telegram user ID during onboarding.

## Best Possible Solution

Implement a maintainer-approved Telegram onboarding path that verifies the intended owner with a short token, writes dmPolicy="allowlist" plus the numeric owner allowFrom, and documents/tests fresh-install and existing-config behavior.

## Reproduction Assessment

Yes, at source level: current main still defaults omitted Telegram dmPolicy to pairing, sends pairing challenges to unknown DMs, documents pairing as default, and uses manual numeric allowFrom entry instead of verified owner capture. I did not run a live Telegram bot because this review is read-only.

## Solution Assessment

No as a blanket default flip or first-message capture. The best solution is verified fresh-setup owner enrollment plus a deliberate compatibility decision for existing omitted-policy installs.
