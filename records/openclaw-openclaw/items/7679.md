## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing and setup still relies on manual numeric allowFrom entry, while the requested token-verified owner capture is a security-sensitive product/default decision.

## What This Changes

The issue requests Telegram fresh setup to default to dmPolicy="allowlist" by capturing the owner's Telegram ID during onboarding and writing it to allowFrom.

## Best Possible Solution

Implement Telegram-owned token-verified owner capture during setup, write allowlist config for fresh setups, preserve explicit pairing-mode configs, and update schema/runtime/docs/tests together.
