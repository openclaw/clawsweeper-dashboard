## Summary

Keep open. Current main still documents Telegram DM pairing as the default and its setup wizard only accepts a manually supplied numeric user ID before writing an allowlist; it does not perform verified first-owner capture. This is a security-sensitive product decision because a global default change must preserve a safe first-run path and existing explicit pairing configurations.

## What This Changes

Make fresh Telegram setup establish a verified owner allowlist instead of leaving direct messages in the default pairing mode.

## System Context

The Telegram plugin’s setup wizard collects a bot token and DM-access settings, then saves the selected policy in OpenClaw configuration. Incoming Telegram DMs are subsequently gated by that saved policy, either starting the pairing flow or allowing only configured sender IDs.

## Architecture Diagram

flowchart LR
  A[Operator configures Telegram] --> B[Telegram setup wizard]
  B --> C[DM access policy]
  C --> D[Saved Telegram configuration]
  E[Incoming Telegram DM] --> F[DM access gate]
  D --> F
  F --> G[Pairing challenge]
  F --> H[Allowlisted owner access]

## Best Possible Solution

Define a Telegram-owned, token-verified owner-enrollment flow and decide whether it is an explicit setup choice or a post-pairing transition; persist the verified numeric ID in `allowFrom` while preserving explicit existing pairing-mode configurations.
