## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, and setup still writes allowlist only after manual numeric allowFrom entry. The safer owner-capture default remains useful, but it changes Telegram first-run authorization and needs maintainer product/security direction.

## What This Changes

The issue requests changing Telegram fresh setup/default behavior from dmPolicy="pairing" to dmPolicy="allowlist" with the owner Telegram ID captured during onboarding.

## Best Possible Solution

Implement a Telegram-owned onboarding path that displays a short verification token, captures only the matching sender's numeric ID, writes dmPolicy="allowlist" plus allowFrom for fresh owner setup, and preserves explicit pairing-mode configurations.
