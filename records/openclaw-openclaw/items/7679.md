## Summary

Keep open: current main and v2026.6.11 still default Telegram DMs to pairing, still issue pairing challenges to unknown DM senders, and still require manual numeric allowFrom entry rather than token-verified owner capture.

## What This Changes

The issue asks Telegram setup to default fresh DMs to allowlist mode and auto-capture the owner Telegram ID during onboarding.

## Best Possible Solution

Implement this as Telegram-owned onboarding: generate a short verification token, ask the intended owner to send that exact token to the bot, capture the matching numeric sender ID, write dmPolicy="allowlist" plus allowFrom for fresh setup, and preserve explicit pairing-mode configs with docs and tests.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 still default Telegram dmPolicy to pairing and still model setup as pairing or manual numeric allowFrom entry. I did not run a live Telegram onboarding flow in this read-only review.

## Solution Assessment

No, not as a blind default flip or first-message capture. The maintainable solution is token-verified owner capture during Telegram setup, with explicit pairing-mode compatibility and docs/tests updated together.
