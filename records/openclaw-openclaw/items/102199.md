## Summary

Keep open: current main keeps only a compact Telegram progress-summary bar after final delivery, but it still lacks the requested `keepOnComplete` schema option, full completed-draft retention, and checklist-style progress state. This remains a Telegram lifecycle/config product decision, not conservative cleanup.

## What This Changes

The issue requests an opt-in Telegram progress mode setting that preserves the completed progress draft, including checklist-style state, while sending the final assistant response as a separate normal message.

## Best Possible Solution

Have maintainers choose the Telegram finalization policy first; if accepted, implement a default-off full-retention or finalization option with schema/types/docs/UI hints, focused Telegram tests, and live Telegram proof while keeping the current compact-summary behavior as the default.
