## Summary

Keep open: current main now keeps a one-line Telegram progress summary and sends the final answer separately, but it still lacks the requested default-off `keepOnComplete` behavior, full completed progress draft retention, checklist-style completed/pending state, and config validation.

## What This Changes

The issue requests an opt-in Telegram progress-mode option to preserve the completed progress draft, including checklist-style state, while delivering the final assistant response as a separate normal message.

## Best Possible Solution

Have maintainers choose the Telegram finalization policy first; if accepted, implement a default-off preservation option that keeps current defaults, updates schema/types/docs, and proves the visible Telegram flow with focused tests plus live Telegram evidence.
