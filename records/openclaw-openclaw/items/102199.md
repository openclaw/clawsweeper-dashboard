## Summary

Keep open: current main now keeps a compact one-line Telegram progress summary, but it still does not implement the requested opt-in `keepOnComplete` behavior, full completed progress draft retention, or checklist-style completed/pending state.

## What This Changes

Add opt-in Telegram progress-mode behavior that preserves the completed progress draft after final delivery while sending the final assistant response as a separate normal message.

## Best Possible Solution

Maintainers should choose the Telegram finalization policy first; if accepted, implement a default-off option or finalization enum that preserves current one-line-summary defaults, updates schema/docs/tests, and proves the visible Telegram flow.
