## Summary

The current head still has both blockers from the prior review: sharing consent is not scoped by agent for global sessions, and overflow metadata is calculated after each stream has already been capped. The feature also remains merge-conflicted, lacks current-head gateway-backed isolation/resume proof, and needs explicit maintainer approval for the permanent privileged persistence contract.

## What This Changes

Adds a three-choice TUI local-shell consent flow, persists `!` and `!!` results as `bashExecution` transcript entries through a hidden operator-admin gateway method, replays them on resume, and controls model visibility with `excludeFromContext`.

## Best Possible Solution

Key consent by the canonical agent-plus-session identity, retain overflow facts before per-stream slicing, align the existing TUI/security documentation, resolve the current-main conflict without changing session ownership, and require exact-head gateway-backed isolation/resume proof before maintainers approve the permanent `!`/`!!` contract.
