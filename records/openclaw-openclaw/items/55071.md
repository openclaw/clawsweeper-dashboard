## Summary

Keep open: current main and the latest release still lack the requested `metadata.openclaw.activates.plugins` skill metadata contract, and plugin tool visibility is still driven by plugin activation plus static tool policy rather than matched-skill activation. The related work is useful groundwork, not a replacement for this design item.

## What This Changes

The issue requests a new `metadata.openclaw.activates.plugins` skill metadata field so matched skills can make selected plugin tools and plugin-bundled skills visible to the model on a per-turn basis.

## Best Possible Solution

Keep this as a maintainer-owned skill/plugin API design item and implement one generic activation contract only after reconciling it with the broader tool-schema, skill-graph, and deferred-schema trackers.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature/API request. Source inspection gives high-confidence evidence that current main and the latest release lack `metadata.openclaw.activates.plugins` and do not thread matched-skill activation into plugin tool assembly.

## Solution Assessment

Unclear. `activates.plugins` is a plausible design, but the best solution needs maintainer agreement on metadata semantics, deny/allow precedence, plugin manifest activation overlap, plugin-bundled skills, and prompt-cache stability.
