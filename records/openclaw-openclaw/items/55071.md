## Summary

Keep open: current main still lacks the requested `metadata.openclaw.activates.plugins` skill metadata contract and matched-skill plugin tool activation. General Tool Search now covers some token-overhead pressure, and https://github.com/openclaw/openclaw/pull/75983 added useful visibility diagnostics, but neither implements this proposed skill-driven plugin visibility model.

## What This Changes

The issue requests a new skill metadata contract, `metadata.openclaw.activates.plugins`, so matched skills can expose plugin tool schemas on demand per turn.

## Best Possible Solution

Keep this as a maintainer-owned skill/plugin API design item: either define a generic activation contract through skill parsing, snapshots, tool planning, docs, and tests, or explicitly close it in favor of Tool Search as the product direction.

## Reproduction Assessment

Not applicable as a user bug; this is a feature/API request. Source inspection gives a high-confidence absence proof for `activates.plugins` on current main.

## Solution Assessment

Unclear: `activates.plugins` is a plausible design, but current Tool Search overlaps the token-saving goal, so maintainers should choose the preferred product/API model before implementation.
