## Summary

Keep open: current main and v2026.6.11 still lack the requested `metadata.openclaw.activates.plugins` contract, and plugin tool visibility remains driven by manifest availability plus static tool policy rather than matched skill activation. The merged skills visibility work in https://github.com/openclaw/openclaw/pull/75983 is useful groundwork, but its author explicitly noted that it does not implement this proposal.

## What This Changes

The issue requests a new `metadata.openclaw.activates.plugins` skill metadata contract that conditionally exposes plugin tools and bundled skills when matched skills activate those plugins.

## Best Possible Solution

Keep this as a maintainer-owned skill/plugin API design item; if accepted, implement one generic activation contract across skill parsing, prompt snapshots, plugin tool planning, docs, and compatibility tests.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes, at source level: current main has no `activates` skill metadata field and plugin tool assembly uses static policy inputs rather than matched-skill activation.

## Solution Assessment

Is this the best way to solve the issue? Unclear; `activates.plugins` is plausible, but maintainers need to settle metadata semantics, deny/allow precedence, plugin SDK boundaries, and bundled-skill behavior before implementation.
