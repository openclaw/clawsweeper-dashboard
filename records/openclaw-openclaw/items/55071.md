## Summary

Keep open: current main and v2026.6.11 still lack the requested `metadata.openclaw.activates.plugins` contract, and plugin tools are still admitted from runtime plugin registration plus static allow/deny policy rather than matched-skill activation. The linked `skills check --agent` work is useful visibility groundwork, but its author explicitly noted it does not implement skill-driven plugin loading.

## What This Changes

The issue requests a new `metadata.openclaw.activates.plugins` skill metadata contract to expose plugin tools only when matched skills activate them.

## Best Possible Solution

Keep this as a maintainer-owned skill/plugin API design item and implement only after agreeing on one generic activation contract across skill parsing, snapshots, plugin tool planning, docs, and compatibility tests.
