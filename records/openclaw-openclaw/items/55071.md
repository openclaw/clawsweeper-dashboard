## Summary

Keep open: current main has partial tool-search and skills-visibility groundwork, but it still lacks the requested `metadata.openclaw.activates.plugins` contract and no matched-skill path controls plugin tool visibility per turn.

## What This Changes

Request adds skill-declared `metadata.openclaw.activates.plugins` semantics so matched skills can make plugin tools and bundled skills visible per turn.

## Best Possible Solution

Keep this as a maintainer-owned skill/plugin API design item and, if accepted, implement a generic activation contract through skill parsing, snapshots, request-time plugin tool planning, docs, and compatibility tests.

## Reproduction Assessment

Yes for source-level absence: current metadata types, parsing, snapshots, docs, and plugin tool assembly have no `activates.plugins` contract; this is a feature gap rather than a runtime bug reproduction.

## Solution Assessment

Unclear; `activates.plugins` is plausible, but the best fix needs maintainer agreement on metadata semantics, precedence with existing tool policy, plugin SDK boundaries, and bundled-skill behavior.
