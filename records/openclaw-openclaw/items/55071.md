## Summary

Keep open: current main still lacks the requested `metadata.openclaw.activates.plugins` contract and has no matched-skill plugin tool activation path. Tool Search and `skills check --agent` are useful adjacent surfaces, but they do not replace this public skill/plugin visibility design.

## What This Changes

The issue requests a new `metadata.openclaw.activates.plugins` skill metadata contract that would make plugin tool schemas visible only when matched skills activate those plugins.

## Best Possible Solution

Keep this open as the skill-driven plugin context-visibility design item and reconcile it with Tool Search, explicit tool allow/deny policy, and the plugin SDK deferred-schema tracker before implementation.

## Reproduction Assessment

Yes, at source level: current main parses `requires` metadata and builds policy-filtered plugin tool catalogs, but it does not parse or consume `metadata.openclaw.activates.plugins`. This is a missing feature rather than a broken existing behavior reproduction.

## Solution Assessment

Unclear: `activates.plugins` is a plausible shape, but the best solution needs maintainer decisions about Tool Search composition, plugin-level granularity, bundled skill activation, and allow/deny precedence.
