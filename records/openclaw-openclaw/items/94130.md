## What This Changes

The PR maps raw Anthropic `max_turns` stream stops to OpenClaw `length`, stores `provider_stop_reason` diagnostics, adds max-turn-specific incomplete-turn messaging, and separates internal retry-limit metadata from visible idle-timeout text.

## Best Possible Solution

Land the focused mapper-boundary fix after maintainer acceptance of the `length` plus raw-diagnostic semantics and ordinary latest-head CI completion.

## Reproduction Assessment

Yes, source-level: current main sends streamed Anthropic `message_delta.delta.stop_reason` through mappers that lack `max_turns` and throw on unknown reasons. I did not reproduce a live hosted Anthropic `max_turns` exhaustion event, and current SDK types do not list it as a standard Messages stop reason.

## Solution Assessment

Yes, with maintainer acceptance of the semantic choice: the mapper boundary is the right place to preserve raw provider context before runner finalization loses it. Expanding the public `StopReason` union or treating this as `error` would be broader and should be a maintainer decision, not an automatic repair.
