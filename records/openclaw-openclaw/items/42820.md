## Summary

Keep open: current main and v2026.6.11 fixed metadata-only poll padding, but the shared multi-action message tool still exposes poll fields and still rejects content-bearing poll fields on `message.send` before delivery. An external closing PR exists, but it is conflicting and is not a safe reason to close this issue.

## What This Changes

The issue asks for plain `message.send` with Feishu or other channels to ignore or avoid accidental poll fields so normal text and file sends are not rejected as poll creation.

## Best Possible Solution

Adopt a maintainer-approved shared message-tool contract, preferably action-scoped poll fields for send-capable schemas with focused send and poll regression coverage across Feishu or another non-poll channel plus a poll-capable channel.

Options:

- **Action-scope poll fields (recommended):** Expose poll creation fields only for poll actions or a channel-specific poll tool so models are not invited to fill them during plain sends while strict poll validation remains intact.
- **Send wins and strips:** Treat `action="send"` as authoritative and drop poll creation fields before delivery, maximizing send reliability but potentially hiding callers that meant to create a poll.
- **Keep strict content guard:** Continue rejecting content-bearing poll fields on send and require stronger live evidence before changing the shared tool contract.
