## Summary

Keep open: current main and the latest release fixed metadata/default poll false positives, but the central shared-schema issue still remains for content-bearing poll fields. The general `message` tool still exposes `pollQuestion`/`pollOption`, and `message.send` still rejects them before channel delivery; an open but conflicting closing PR also needs maintainer direction rather than cleanup closure.

## What This Changes

The issue requests that `message.send` stop failing when shared poll schema fields are auto-populated during normal Feishu or other channel sends.

## Best Possible Solution

Settle the message-tool contract, preferably by action-scoping poll fields out of plain send or by approving a narrow sanitizer, then land an updated fix with regression and live channel proof.
