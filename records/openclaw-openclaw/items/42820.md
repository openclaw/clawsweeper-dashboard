## Summary

Keep open: current main and the latest release narrowed the poll guard so metadata-only schema padding no longer blocks `message.send`, but the shared multi-action message schema still exposes poll creation fields and `send` still rejects before delivery when content-bearing poll fields are present. The open cross-repo PR that claims this issue is conflicting and stale, so it is not a safe canonical landing path by itself.

## What This Changes

The issue asks OpenClaw to prevent ordinary Feishu and other channel `message.send` calls with files from failing when shared poll schema fields leak into the send payload.

## Best Possible Solution

Keep the shipped metadata-padding fix, then land a maintainer-approved message-tool contract change: action-scoped poll schemas or send-time sanitization with focused regression coverage and live Feishu or Telegram send proof.
