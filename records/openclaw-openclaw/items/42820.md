## Summary

Keep open: current main and v2026.6.11 fixed metadata/default poll-padding false positives, but the shared multi-action `message` schema still exposes poll fields and `message.send` still rejects non-empty poll content before channel delivery. The remaining fix is a shared message-tool contract decision, not a cleanup close.

## What This Changes

The issue asks for plain Feishu and other channel `message(action="send")` calls with files or text to stop being blocked by poll fields exposed through the shared message-tool schema.

## Best Possible Solution

Land one maintainer-approved shared message-tool contract, preferably action/channel-scoping poll creation fields away from ordinary sends while preserving explicit `poll` validation, with Feishu or Telegram send-with-attachment regression proof.
