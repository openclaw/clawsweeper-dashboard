## Summary

Keep open: current main fixes schema-padded poll metadata/defaults, but Feishu still advertises a multi-action message schema that inherits shared poll fields, and `message.send` still rejects content-bearing poll params before channel delivery. The remaining work is a shared message-tool contract decision, not a safe stale cleanup close.

## What This Changes

The issue requests that generic `message.send` stop rejecting ordinary channel sends when poll-related fields from the shared message schema are present.

## Best Possible Solution

Land a maintainer-approved message-tool contract that keeps ordinary sends free of poll creation fields, preferably by action/channel-scoping poll fields away from `message.send` while preserving explicit `poll` validation and adding Feishu or Telegram send-with-attachment proof.

- **Strip poll fields on send:** Treat `action: send` as authoritative and remove poll creation fields before delivery, improving send reliability while potentially masking mistaken poll creation calls.
- **Keep strict content guard:** Preserve the current content-bearing rejection and close only if maintainers decide the metadata/default fixes are sufficient.
