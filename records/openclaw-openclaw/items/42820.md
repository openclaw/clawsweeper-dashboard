## Summary

Keep open: current main and v2026.6.11 fixed metadata-only poll padding, but the shared multi-action message schema still exposes poll fields and `message(action="send")` still rejects before delivery when non-empty `pollQuestion` or `pollOption` is present.

## What This Changes

The issue asks for plain Feishu and other channel `message(action="send")` calls, including file sends, to stop failing because poll fields from the shared message-tool schema were populated accidentally.

## Best Possible Solution

Keep the shipped metadata-padding fix, then have maintainers choose a durable message-tool contract: action-scoped poll schemas or explicit send-side normalization with focused Feishu/Telegram proof while preserving strict validation for real poll actions.
