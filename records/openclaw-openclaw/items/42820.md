## Summary

Keep open: current main and v2026.6.11 fixed schema-padded duration/metadata false positives, but the shared multi-action message schema can still expose poll fields and `message.send` still rejects content-bearing poll params before channel delivery. The remaining fix needs a maintainer choice for the model-facing send/poll contract.

## What This Changes

The issue asks OpenClaw to keep ordinary Feishu and other channel `message.send` calls from being blocked by poll fields exposed through the shared message tool schema.

## Best Possible Solution

Land a maintainer-approved contract, preferably action-scoping poll creation fields away from plain `message.send` while preserving explicit `poll` validation, with Feishu or Telegram attachment-send regression proof.

- **Keep content guard:** Preserve the current release behavior and close this only if maintainers decide the metadata/default fixes are sufficient.
