## Summary

Keep open: current main and v2026.6.11 fixed metadata-only poll padding, but the multi-action message schema still exposes poll creation fields and `message.send` still rejects before delivery when content-bearing poll fields are present.

## What This Changes

Reports that the generic `message` tool exposes poll fields on Feishu/plain sends, causing poll-guard rejection before file or message delivery when models auto-fill those fields.

## Best Possible Solution

Keep the shipped metadata-padding fix, then land a maintainer-chosen message-tool contract that either action-scopes poll fields out of ordinary sends or safely sanitizes accidental poll fields before delivery, with live Feishu or Telegram proof.

## Maintainer Decision

Required: true

Kind: product_direction

Rationale: Current main intentionally allows metadata-only padding but still rejects content-bearing poll fields on `send`; choosing between strict poll intent, stripping, and action-scoped schemas changes the public model-facing tool contract.

Likely owner: steipete

Owner confidence: medium

Options:

- **Action-scope poll schema (recommended):** Expose poll creation fields only for `action="poll"` or channel-specific poll tools so ordinary sends cannot be polluted by poll params.
- **Sanitize on send:** Keep the unified schema but strip poll creation fields from `action="send"` before the guard and channel dispatch.
- **Keep strict content-field rejection:** Treat non-empty poll question/options on `send` as real poll intent and require more live evidence before changing the contract further.

## Reproduction Assessment

Yes, source-level: current `runMessageAction` still throws the reported poll-action error when `send` includes non-empty `pollQuestion` or `pollOption`, and tests assert that behavior. A live current-main Feishu or Telegram repro after the metadata fix is still missing.

## Solution Assessment

Unclear: the shipped validator narrowing is a good partial fix, but the broader request needs a maintainer choice between action-scoped schemas, send-time sanitization, or preserving strict content-field rejection.
