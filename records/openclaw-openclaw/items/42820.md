## Summary

Keep open: current main and v2026.6.11 fixed the schema-padded metadata/default subset, but the shared message schema still exposes poll fields and `message.send` still rejects content-bearing poll params before channel delivery. The remaining fix is a shared message-tool contract choice, and the open closing PR is cross-repo, conflicting, and not a safe canonical landing path.

## What This Changes

The issue asks for normal Feishu and other-channel `message.send` calls with attachments to stop failing when shared poll schema fields are auto-populated.

## Best Possible Solution

Land one maintainer-approved contract for ordinary sends, preferably action/channel-scoping poll creation fields away from `message.send` while preserving explicit `poll` validation, with Feishu or Telegram send-with-attachment regression proof.

Options:

- **Action-scope poll fields (recommended):** Expose poll creation fields only for `poll` or channel-specific poll surfaces so plain sends cannot inherit them from the shared schema while strict poll validation remains intact.
- **Strip poll fields on send:** Treat `action: send` as authoritative and remove poll creation fields before delivery, improving send reliability while potentially masking a caller that meant to create a poll.
- **Keep strict content guard:** Preserve the shipped content-bearing rejection and close only if maintainers decide the metadata/default fixes are sufficient.
