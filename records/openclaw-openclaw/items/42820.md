## Summary

Keep open: current main and v2026.6.11 fixed metadata-only poll padding, but the shared multi-action `message` schema still exposes poll creation fields and `message.send` still rejects content-bearing poll fields before delivery; the linked fork PR is open but conflicting, so it is not a safe canonical landing path.

## What This Changes

The issue asks OpenClaw to make `message(action="send")` for Feishu and other channels tolerate or avoid accidental poll fields from the shared message-tool schema so normal text/file sends are not rejected as polls.

## Best Possible Solution

Keep the shipped metadata-padding fix, then settle the shared message-tool contract by action-scoping poll schema fields or sanitizing accidental poll params on send while preserving explicit poll validation.

Question: Should plain `message(action="send")` prevent models from seeing poll creation fields, strip accidental poll fields at runtime, or keep rejecting content-bearing poll fields as explicit poll intent?

Rationale: Current code intentionally accepts schema-padded poll metadata but still rejects non-empty poll content fields; changing that boundary affects shared channel delivery semantics across Feishu, Telegram, Discord, Slack, and other message-tool channels.

Options:

- **Action-scope poll fields (recommended):** Expose poll creation fields only for poll actions or channel-specific poll tools, reducing accidental model fill while keeping strict poll validation.
- **Strip poll params on send:** Treat action="send" as authoritative and drop poll fields before delivery, improving reliability but potentially masking poll-intent mistakes.
- **Keep strict guard:** Continue rejecting content-bearing poll fields on send and require schema discovery or callers to avoid generating them accidentally.

## Solution Assessment

Unclear: the shipped validator narrowing is a good partial fix, but the durable solution needs a maintainer choice between action-scoped schemas, send-side sanitization, or preserving strict poll-intent rejection.
