## Summary

Keep open: current main and v2026.6.11 fixed the metadata/default poll-padding subset, but the shared multi-action `message` schema still exposes poll fields and `message.send` still rejects content-bearing poll params before channel delivery. The issue is also paired with an open closing PR, so the right cleanup action is maintainer review rather than closure.

## What This Changes

Request to make Feishu and other channel `message.send` calls with normal messages or attachments stop failing because poll fields are exposed in the shared message-tool schema.

## Best Possible Solution

Keep the shipped metadata-padding fix, then make a maintainer-approved message-tool contract change: preferably action-scoped poll fields or send-time sanitization with focused regression coverage and live Feishu or Telegram send proof.
