## Summary

Keep open: current main and v2026.6.11 fixed metadata-only poll padding, but the shared multi-action message schema still exposes poll fields and `message.send` still rejects content-bearing poll fields before channel delivery.

## What This Changes

The issue asks for ordinary `message.send` calls with files or text to avoid failing when shared poll schema fields leak into Feishu, Telegram, or other channel sends.

## Best Possible Solution

Keep the shipped metadata-padding fix, then land a maintainer-approved action-aware message-tool contract so ordinary sends cannot be blocked by accidental poll fields while real poll creation remains strict.
