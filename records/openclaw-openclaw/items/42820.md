## Summary

Keep open: current main and the latest release fixed metadata-only poll padding, but the shared multi-action message-tool schema still exposes poll fields and `message.send` still rejects content-bearing poll fields before channel delivery.

## What This Changes

The issue requests that plain `message` tool `action: "send"` calls, especially Feishu send-with-file calls, not fail because poll fields are present in the shared tool schema.

## Best Possible Solution

Keep the shipped metadata-padding fixes, then make a maintainer-owned contract choice: action-scope or channel-scope poll fields away from plain sends, or intentionally normalize accidental poll fields before delivery while preserving strict validation for real poll actions.

Rationale: The current implementation intentionally fixed metadata padding but still treats non-empty poll content as a hard send blocker; changing that boundary affects the shared model-facing message-tool contract across Feishu, Telegram, Slack, Discord, and other channels.

Options:

- **Action-scope poll fields (recommended):** Expose poll creation fields only for poll-capable actions or channel-specific poll tools so normal sends do not invite accidental poll arguments.
- **Strip on send:** Treat `action="send"` as authoritative and drop poll creation fields before delivery, accepting the risk that wrong-action poll callers become quieter.
- **Keep strict guard:** Keep rejecting content-bearing poll fields on send and require stronger live evidence before changing the contract further.

## Solution Assessment

Unclear: the merged validator narrowing is a useful partial fix, but the best remaining solution needs maintainer choice between action-scoped schemas, send-side sanitization, or preserving strict poll-intent validation.
