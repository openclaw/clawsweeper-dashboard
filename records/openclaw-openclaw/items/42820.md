## Summary

Keep open: current main and the latest release fixed the metadata/default poll-padding subset, but the shared non-send-only `message` schema still exposes poll creation fields and `message.send` still rejects content-bearing poll params before Feishu or Telegram delivery. The open linked PR is still unmerged and conflicting, so this remains a maintainer contract decision rather than a cleanup close.

## What This Changes

The issue asks OpenClaw to stop ordinary `message(action="send")` file/message sends from being blocked by poll fields exposed through the shared message-tool schema.

## Best Possible Solution

Land one maintainer-approved shared contract: preferably action-scope poll creation fields away from ordinary `send`, or explicitly sanitize send-path poll fields while preserving real `poll` action validation, with Feishu/Telegram send+attachment and poll regression proof.

- **Keep strict guard:** Preserve the shipped content-bearing rejection and close only if maintainers decide the metadata/default fixes are sufficient.
