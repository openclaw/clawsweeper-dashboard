## Summary

Keep open: current `main` and `v2026.6.11` fixed metadata-only poll padding, but the shared model-facing `message` schema still exposes poll creation fields and `message.send` still rejects content-bearing poll fields before delivery. The open closing PR is conflicting and unmerged, so this issue remains the canonical maintainer-review item.

## What This Changes

The issue requests that ordinary `message.send` calls, especially Feishu and Telegram sends with files, not fail when poll-related fields are exposed or auto-populated from the shared message-tool schema.

## Best Possible Solution

Keep the shipped metadata-only carve-out, then make a maintainer-approved action-aware message-tool contract so ordinary sends do not expose or honor poll creation fields unless the caller is intentionally using the poll action.
