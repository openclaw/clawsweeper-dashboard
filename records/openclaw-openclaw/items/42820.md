## Summary

Keep open: current main and v2026.6.11 fixed metadata-only poll padding, but the shared multi-action message schema still exposes poll creation fields and `message.send` still rejects before delivery when content-bearing poll fields are present.

## What This Changes

The issue reports that generic message-tool poll fields can be auto-populated on normal `action: "send"` calls, causing Feishu/Telegram file or text sends to fail before delivery.

## Best Possible Solution

Keep the shipped metadata-padding fix, then have maintainers choose and land a durable message-tool contract: action-scoped schemas, action-aware sanitization, or an explicit decision that content-bearing poll params should keep failing on `send`.
