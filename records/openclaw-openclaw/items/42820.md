## Summary

Keep open: current main and the latest release fixed schema-padded poll metadata, but the shared multi-action message schema still exposes poll fields and `message.send` still rejects before delivery when non-empty `pollQuestion` or `pollOption` is present.

## What This Changes

The issue asks for normal Feishu and other channel `message.send` calls with attachments to stop failing when the shared poll schema causes accidental poll parameters on a plain send.

## Best Possible Solution

Keep the shipped metadata-padding fix, then land a maintainer-approved contract change with focused regression tests and live Feishu or Telegram send-with-attachment proof.

- **Keep strict content guard:** Leave current behavior in place and require new live evidence that models still emit content-bearing poll fields during plain sends.
