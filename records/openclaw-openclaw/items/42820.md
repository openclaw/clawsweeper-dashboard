## Summary

Keep open: current main and v2026.6.11 fixed metadata-only poll padding, but multi-action message tools still expose poll fields and `message.send` still rejects content-bearing poll fields before delivery.

## What This Changes

The issue requests that plain Feishu and other channel `message(action="send")` calls with attachments not be blocked by poll fields exposed through the shared message-tool schema.

## Best Possible Solution

Keep the shipped metadata-padding fix, then choose a durable shared message-tool contract: action-scoped poll schemas, channel-scoped poll tools, or explicit send-side normalization so plain sends cannot be blocked by schema-padded poll fields while real poll creation remains validated.

Rationale: The current code deliberately accepts metadata-only padding but still rejects non-empty poll content fields; changing that boundary affects the shared model-facing message-tool contract across Feishu, Telegram, and other channels.

Owner confidence: high

Options:

- **Action-scope poll fields (recommended):** Expose poll creation fields only for poll actions or channel-specific poll tools, reducing accidental model fill while preserving strict poll validation.
- **Strip on send:** Treat `action="send"` as authoritative and drop poll creation fields before delivery, improving reliability but potentially hiding wrong-action callers.
- **Keep strict guard:** Continue rejecting content-bearing poll fields on send and require stronger live evidence before changing the tool contract further.
