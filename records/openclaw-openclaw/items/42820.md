## Summary

Keep open: current main and v2026.6.11 fixed the schema-padded poll metadata false positives, but the shared multi-action message schema still exposes poll content fields and `message.send` still rejects them before channel delivery. The remaining work is a shared message-tool contract decision, not an implemented-on-main cleanup.

## What This Changes

The issue requests that ordinary Feishu and other channel `message.send` calls with files not be blocked by poll fields exposed through the shared message tool schema.

## Best Possible Solution

Keep the shipped metadata-padding fixes, then make a maintainer-approved message-tool contract change: action-scoped poll schemas or explicit send-time sanitization with focused regression coverage and live Feishu or Telegram send proof.

- **Strip on send:** Treat `action="send"` as authoritative and remove poll creation fields before delivery, improving send reliability while possibly masking mistaken poll calls.
- **Keep strict guard:** Preserve the shipped content-bearing rejection and require stronger live evidence before changing the shared message-tool contract.
