## Summary

Keep open: current main and v2026.6.11 fixed the metadata/default poll-padding false positive, but the shared multi-action message schema still exposes poll content fields and `message.send` still rejects those before channel delivery. The remaining choice is a maintainer product/API direction, not a proven implemented-on-main cleanup.

## What This Changes

The issue asks for `message.send` to avoid failing normal Feishu and other channel sends when poll-related fields appear in the shared message tool schema.

## Best Possible Solution

Keep the shipped metadata-padding fix, then make a maintainer-approved message-tool contract change: action-scoped poll schemas or send-time sanitization with focused regression coverage and live Feishu or Telegram send proof.
