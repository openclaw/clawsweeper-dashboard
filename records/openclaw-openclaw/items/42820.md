## Summary

Keep open: current main and v2026.6.11 fixed metadata-only poll padding, but the shared multi-action message schema still exposes poll fields and `message.send` still rejects content-bearing poll params before channel dispatch. The remaining work is a shared message-tool contract decision, and the open linked PR is conflicting rather than a safe canonical fix path.

## What This Changes

The issue asks for plain `message(action="send")` on Feishu and other channels to stop failing when poll fields from the shared message-tool schema appear in a non-poll send payload.

## Best Possible Solution

Land one maintainer-approved contract for ordinary sends, preferably action/channel-scoping poll creation fields away from `message.send` while preserving explicit `poll` validation, with Feishu or Telegram send-with-attachment proof.

Options:

- **Action-scope poll fields (recommended):** Expose poll creation fields only for `poll` or channel-specific poll surfaces so plain sends cannot inherit them from the shared schema while strict poll validation remains intact.
- **Strip on send:** Treat `action="send"` as authoritative and remove poll creation fields before delivery, improving send reliability while potentially masking a caller that meant to create a poll.
- **Keep strict content guard:** Preserve the shipped content-bearing rejection and require stronger live evidence before changing the shared message-tool contract.

## Solution Assessment

Unclear until maintainer direction: the metadata/default narrowing is a useful partial fix, but it does not settle whether the best long-term fix is action-scoped schema exposure, send-path sanitization, or preserving strict poll-intent rejection.
