## Summary

Keep open: current main and v2026.6.11 only mitigate metadata-only poll padding, while the shared message schema still exposes poll creation fields and `message.send` still rejects when content-bearing poll fields appear. The open fork PR that claims this issue is conflicting and not maintainer-modifiable, so it is not a safe cleanup-close target.

## What This Changes

The issue requests that the shared `message` tool let Feishu and Telegram `action: "send"` deliver normal text/file attachments without poll-schema fields tripping the poll-only guard.

## Best Possible Solution

Make the shared message tool action-aware: hide or ignore poll creation fields for normal sends, preserve strict validation under `action="poll"`, and land with focused regression tests plus live channel proof for at least one affected channel.

Options:

- **Narrow the send contract (recommended):** Strip or hide poll creation fields for `action="send"`, preserve `action="poll"` validation, and require regression plus live delivery proof before closing this issue.
- **Keep fail-closed poll intent:** Leave content-bearing poll fields as a hard `send` error and document that callers must avoid those fields or use model/tool routing that does not overfill them.
- **Defer to schema split:** Pause narrow runtime fixes and design per-action or per-channel message schemas before changing the shared guard semantics.
