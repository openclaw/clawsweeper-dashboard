Keep this PR open: current `main` still allows two concurrently admitted pre-auth `connect` handlers to reach the late registration boundary, so the proposed single-owner guard addresses a real remaining lifecycle race. The focused patch and regression coverage look directionally correct, but the external PR has only test-based claims in its body and needs inspectable after-fix live Gateway evidence before merge.

## What This Changes

This PR rejects a second authenticated client registration on the same Gateway WebSocket and adds regression tests for direct registration and two `connect` frames replayed during lazy handler loading.

## System Context

Gateway WebSockets receive an initial `connect` request, asynchronously authenticate and authorize it, then register one client object that owns presence and heartbeat cleanup. This change sits at that registration boundary and prevents parallel handshake finalizers from retaining more than one client for one socket.
