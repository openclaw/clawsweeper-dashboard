## Summary

Keep open for maintainer product review: current main and the latest stable release still define JSON5 `openclaw.json` as the canonical config-file contract, while the discussion reframes the main pain as safe programmatic mutation rather than a missing YAML parser.

## What This Changes

The issue requests `openclaw.yaml`/`openclaw.yml` support as an alternate config-file format alongside JSON5 `openclaw.json`.

## Best Possible Solution

Keep JSON5 canonical unless maintainers explicitly approve a YAML config contract; improve guidance toward `openclaw config set`, `openclaw config patch`, and comment-aware minimal edits for scripted changes.
