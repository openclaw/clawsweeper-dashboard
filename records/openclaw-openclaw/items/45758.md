## Summary

Keep open for maintainer product review: current main and the latest release still keep `openclaw.json` as the JSON/JSON5 config contract, while YAML/YML support would expand a stable core config surface rather than fix broken behavior.

## What This Changes

The issue requests support for `openclaw.yaml` or `openclaw.yml` as an alternative config file format alongside the current JSON5 `openclaw.json`.

## Best Possible Solution

Keep JSON/JSON5 canonical unless maintainers explicitly sponsor a YAML design with precedence, parser behavior, write-back format, doctor/upgrade behavior, docs, and tests; otherwise improve the supported CLI, Control UI, and `config.patch` guidance for comment-preserving edits.
