## Summary

Keep open for maintainer product review: current main still documents and implements JSON/JSON5 `openclaw.json` as the core config-file contract, while YAML/YML support would add a second parser, precedence rules, and write semantics rather than fix broken existing behavior.

## What This Changes

The issue requests `openclaw.yaml`/`openclaw.yml` support as an alternative to the current JSON/JSON5 `openclaw.json` config file.

## Best Possible Solution

Keep JSON5 as the sole config-file format unless maintainers explicitly approve a YAML design; meanwhile steer programmatic edits through `openclaw config` and `config.patch` so comments and structure are not lost by generic parse/dump tools.
