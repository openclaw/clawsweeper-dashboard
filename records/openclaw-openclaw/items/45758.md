## Summary

Keep open for maintainer product review: current main and the latest release still define JSON5 `openclaw.json` as the config-file contract, while the discussion reframes the practical pain as comment-safe config mutation rather than a missing parser.

## What This Changes

The issue requests YAML/YML support as an alternative config file format alongside the current JSON5 `~/.openclaw/openclaw.json`.

## Best Possible Solution

The desired end state is a maintainer-confirmed config-file policy: either keep JSON5 plus `openclaw config`/`config.patch` canonical, or approve YAML with tested precedence, parser, write-back, reload, docs, and upgrade behavior.
