## Summary

Keep open for maintainer product review: current main and the latest release still use a JSON/JSON5 `openclaw.json` config-file contract, and YAML/YML support would expand a compatibility-sensitive core config surface rather than fix broken existing behavior.

## What This Changes

The issue requests YAML/YML support as an alternative OpenClaw config file format while keeping JSON5 as the default.

## Best Possible Solution

Maintainers should decide the config-file product direction: keep JSON5-only and improve config.patch/CLI editing guidance, or accept a first-class YAML design with explicit precedence, write semantics, parser behavior, docs, and upgrade tests.
