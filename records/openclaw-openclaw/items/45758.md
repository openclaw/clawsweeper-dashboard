## Summary

Keep open for maintainer product direction: current main and the latest release still define JSON5 `openclaw.json` as the core config contract, while the discussion and docs point to `openclaw config`/`config.patch` as the narrower existing answer for comment-safe scripted edits.

## What This Changes

The issue requests YAML/YML support as an alternative OpenClaw config file format alongside the existing JSON5 `openclaw.json` contract.

## Best Possible Solution

Maintainers should either reaffirm JSON5 plus `openclaw config`/`config.patch` as canonical and document comment-safe scripted edits, or explicitly approve YAML with a tested precedence, parser, write-back, reload, docs, and migration plan.
