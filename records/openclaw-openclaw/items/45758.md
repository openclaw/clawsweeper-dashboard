## Summary

Keep open for maintainer product review: current main and the latest release still keep `openclaw.json` as the JSON/JSON5 config contract, while YAML/YML support would add a second stable core config format with parser, precedence, and write-back semantics.

## What This Changes

The issue requests `openclaw.yaml`/`openclaw.yml` as an alternative config file format alongside the current JSON5 `openclaw.json` format.

## Best Possible Solution

Keep JSON/JSON5 canonical unless maintainers explicitly sponsor a YAML design with precedence, parser, write-back, doctor/upgrade, docs, and tests; otherwise improve the supported CLI, Control UI, and `config.patch` guidance for comment-preserving edits.
