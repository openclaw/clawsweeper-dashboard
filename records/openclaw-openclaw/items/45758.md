## Summary

Keep open for maintainer product review: current main and the latest release still use `openclaw.json` with JSON/JSON5 parsing, and YAML/YML support would expand a stable core config contract rather than fix broken current behavior.

## What This Changes

The issue requests YAML or YML support as an alternative OpenClaw configuration file format.

## Best Possible Solution

Keep JSON/JSON5 canonical unless maintainers explicitly sponsor a YAML design with parser behavior, precedence, write-back format, doctor/upgrade behavior, docs, and tests; otherwise improve the supported CLI, Control UI, and `config.patch` guidance for comment-preserving edits.
