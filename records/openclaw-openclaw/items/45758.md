## Summary

Keep open for maintainer product review: current main and the latest release still define JSON5 `openclaw.json` as the core config-file contract, and adding YAML would expand a compatibility-sensitive config surface rather than fix broken existing behavior.

## What This Changes

The issue requests support for `~/.openclaw/openclaw.yaml` and `~/.openclaw/openclaw.yml` as alternative config file formats while keeping JSON5 as the default.

## Best Possible Solution

The desired end state is a maintainer-confirmed config-file policy: keep JSON5 plus `openclaw config`/`config.patch` canonical, or approve YAML with tested precedence, parser, write-back, reload, docs, and upgrade behavior.
