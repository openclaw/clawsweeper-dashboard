## Summary

Keep open for maintainer product review: current main and the latest release still define JSON5 `openclaw.json` as the config-file contract, while the discussion reframes the practical pain as comment-safe config mutation rather than a missing parser.

## What This Changes

The issue requests support for `~/.openclaw/openclaw.yaml` and `~/.openclaw/openclaw.yml` as alternative core config files alongside the existing JSON5 config.

## Best Possible Solution

The desired end state is a maintainer-confirmed config-file policy: keep JSON5 plus `openclaw config`/`config.patch` canonical, or approve YAML with tested precedence, parser, write-back, reload, docs, and upgrade behavior.
