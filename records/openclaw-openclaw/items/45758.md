## Summary

Current main still keeps JSON5 `openclaw.json` as the core config-file contract; the issue remains a product decision because YAML would add a second config format and the discussion points to `openclaw config`/`config.patch` as the safer answer for comment-safe edits.

## What This Changes

The issue requests support for `openclaw.yaml` or `openclaw.yml` as alternative config files alongside the current JSON5 `openclaw.json` contract.

## Best Possible Solution

Maintainers should explicitly choose between reaffirming JSON5 plus `openclaw config`/`config.patch` as the supported path, or approving YAML with a tested precedence, parser, write-back, reload, docs, and migration plan.
