## Summary

Keep open for maintainer product review: current main and the latest release still use `openclaw.json` with JSON/JSON5 parsing, and YAML/YML support would expand a stable core config contract rather than fix broken existing behavior.

## What This Changes

The issue requests support for `openclaw.yaml` or `openclaw.yml` as alternate user config files alongside the current `openclaw.json` JSON5 format.

## Best Possible Solution

Keep JSON/JSON5 canonical unless maintainers explicitly sponsor YAML with parser semantics, precedence, write-back behavior, doctor/upgrade handling, docs, and tests; otherwise improve the supported CLI, Control UI, and `config.patch` guidance for comment-preserving edits.
