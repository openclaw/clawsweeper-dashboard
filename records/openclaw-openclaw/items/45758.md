## Summary

Keep open for maintainer product review: current main and the latest release still use `openclaw.json` as the JSON/JSON5 config contract, and YAML/YML support would expand a stable core config surface rather than fix broken existing behavior.

## What This Changes

The issue requests `openclaw.yaml` or `openclaw.yml` support as an alternative to the current `openclaw.json` configuration file.

## Best Possible Solution

Keep JSON/JSON5 canonical unless maintainers explicitly sponsor a YAML design with precedence, parser behavior, write-back format, doctor/upgrade behavior, docs, and tests; otherwise improve the supported CLI, Control UI, and `config.patch` guidance for comment-preserving edits.
