## Summary

Keep open for maintainer product direction: current main and the latest release still define `openclaw.json` as the JSON/JSON5 config contract, and YAML/YML support would add a second stable config parser, discovery, precedence, and write-back path rather than fixing broken existing behavior.

## What This Changes

Request to support `openclaw.yaml` and `openclaw.yml` as alternative YAML config files alongside the canonical JSON5 `openclaw.json`.

## Best Possible Solution

Keep JSON/JSON5 canonical unless maintainers explicitly sponsor a YAML design with parser semantics, precedence, write-back format, doctor/upgrade behavior, docs, and tests; otherwise improve the supported CLI, Control UI, and `config.patch` guidance for comment-preserving edits.
