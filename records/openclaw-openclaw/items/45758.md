## Summary

Keep open for maintainer product review: current main and the latest release still use `openclaw.json` as the JSON/JSON5 config contract, while `openclaw.yaml`/`openclaw.yml` support would expand a stable core config surface rather than fix broken behavior.

## What This Changes

The issue asks OpenClaw to accept `openclaw.yaml` and `openclaw.yml` as alternate user config files while keeping `openclaw.json` as the default.

## Best Possible Solution

Keep JSON/JSON5 canonical unless maintainers explicitly sponsor a YAML design with parser, precedence, write-back, doctor/upgrade, docs, and test requirements; otherwise improve the supported CLI, Control UI, and `config.patch` guidance for comment-aware edits.
