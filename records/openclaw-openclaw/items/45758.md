## Summary

Keep open for maintainer product review: current main and the latest release still define a JSON5 `openclaw.json` config contract, while YAML support would add a second core config-file format rather than fixing a broken existing behavior.

## What This Changes

The issue requests support for `openclaw.yaml` and `openclaw.yml` as alternative config file formats while keeping JSON5 `openclaw.json` as the default.

## Best Possible Solution

Keep JSON5 `openclaw.json` canonical unless maintainers explicitly approve a YAML design that covers precedence, parsing, write-back, reload, doctor, docs, and upgrade behavior.
