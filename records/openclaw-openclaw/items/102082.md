## Summary

This PR remains necessary because current main does not suppress generic tool-progress Slack sends, and producer-owned typed intent is preferable to transport text inference. The current head fixes the earlier text-send and suppressed-delivery-state problems, but the public generic progress marker is still ignored for native Slack block segments, which can post and record progress chrome as a successful message.

## What This Changes

The PR adds a generic tool-progress ReplyPayload marker from Codex and changes Slack delivery to react to or suppress marked progress-only sends while preserving completed, failed, verbose, and semantic replies.

## Best Possible Solution

Keep the generic producer-owned progress marker, but enforce it across the complete Slack ReplyPayload renderer: pass it through native block and fallback sends, treat every suppressed result as non-delivery, and prove marked structured payloads plus unmarked semantic and final output on the exact repaired head.
