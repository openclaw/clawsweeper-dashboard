## Summary

The Slack suppression behavior is well-tested, but the patch introduces a second public transient-progress contract that bypasses the repository’s existing status-notice semantics. Codex tool progress is therefore suppressed by Slack while generic reply tracking, threading, block delivery, ACP, gateway, and other channel paths still classify it as ordinary answer content; the previous review blocker remains on the current head.

## What This Changes

The PR marks automatic Codex tool summaries with a new generic plugin-SDK progress kind, maps typed Slack progress to reactions or suppression, and prevents suppressed sends from advancing Slack delivery state.

## Best Possible Solution

Mark transient automatic Codex summaries with the existing `ReplyPayload.isStatusNotice` semantic field, keep any reaction choice as Slack-local presentation metadata, and prove the exact-head Codex-to-Slack lifecycle while preserving completed, failed, and explicit verbose output.
