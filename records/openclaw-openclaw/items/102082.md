## Summary

This PR remains necessary, but the current head still bypasses typed progress suppression for Slack native-block payloads, so marked progress chrome can reach `chat.postMessage`; the posted live evidence also predates the current head and does not exercise that defective path.

## What This Changes

The PR adds generic tool-progress metadata to the public reply-payload SDK, marks transient Codex tool summaries, and changes Slack progress sends into reactions or suppressed results while preserving normal delivery state.

## Best Possible Solution

Gate typed progress before Slack content-shape dispatch so text and native blocks share one suppression path, preserve the narrow Codex producer classification and suppressed-result accounting, and either explicitly approve/document the generic SDK contract or keep the signal runtime-internal.
