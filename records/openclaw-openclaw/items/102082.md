## Summary

The current head still has two P1 delivery defects from the latest review cycle: native Slack blocks bypass progress suppression, and explicit suppressed results are treated as successful delivery by dispatch callers. The approach is directionally sound, but this head is not merge-ready and the older live proof does not cover these paths.

## What This Changes

The PR adds a generic tool-progress marker to reply payloads, emits it for transient Codex tool summaries, and changes Slack to convert marked progress into reactions or suppressed sends without normal message-delivery bookkeeping.

## Best Possible Solution

Apply producer-owned progress intent before every Slack rendering branch, propagate suppressed sends as an explicit non-delivery outcome through normal and stream fallback callers, regenerate public SDK budgets from the final tree, and capture redacted live Slack proof on the final head.
