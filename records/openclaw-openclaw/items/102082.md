## Summary

This PR is still necessary because current `main` does not contain the Slack progress-suppression behavior, but the current head is not merge-ready: native Slack block payloads bypass the suppression gate and are still recorded as delivered. The producer-typed direction is preferable to text inference, subject to completing block-path handling and confirming the additive public plugin-SDK contract.

## What This Changes

The PR adds producer-typed tool-progress metadata, suppresses or reacts to progress-only Slack sends, and avoids delivery-state mutations for suppressed text replies.

## Best Possible Solution

Keep the producer-typed progress intent, but make typed suppression authoritative before native Slack block posting and propagate suppressed results as non-delivery through hooks, reply planning, fallback state, and thread participation.
