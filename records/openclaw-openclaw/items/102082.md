## Summary

The latest head still has a P1 delivery bug: typed progress payloads that render as Slack native blocks lose their progress intent, are posted with `chat.postMessage`, and are counted as delivered. The producer-owned generic marker is a sound direction, but the Slack invariant must cover every rendered representation and the rewritten exact head still needs live Slack proof.

## What This Changes

The PR adds a generic tool-progress reply marker, tags transient Codex tool summaries, and changes Slack to convert progress-only replies into reactions or suppress them without consuming delivery state.

## Best Possible Solution

Carry the typed progress intent through native block sends, make the Slack pre-send gate authoritative before every text, block, or media platform dispatch, and commit hooks, thread participation, latest-result, and reply-plan state only after a non-suppressed send; then provide redacted exact-head live Slack proof for block chrome and preserved terminal/semantic replies.
