## Summary

The current head still misses one delivery representation: typed progress payloads that materialize as native Slack blocks do not carry progress intent into `sendMessageSlack` and are unconditionally reported as delivered. Producer-owned generic intent is otherwise the right boundary, and the text-path changes are substantial, but this prior P1 blocker remains merge-blocking.

## What This Changes

The PR adds a generic tool-progress reply marker, converts eligible Slack progress sends into thread reactions or silent suppression, and avoids advancing delivery state for suppressed text sends.

## Best Possible Solution

Forward the existing typed progress intent through native block delivery, make the block result use the same suppressed-result handling as text, and prove that structured progress produces no Slack post or delivery-state mutation while ordinary semantic blocks still deliver.
