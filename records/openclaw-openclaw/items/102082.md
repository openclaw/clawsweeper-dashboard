## Summary

The Slack suppression and delivery-state work is well covered, but this PR still introduces a parallel public `tool-progress` reply semantic where the existing `isStatusNotice` contract already represents transient non-answer content; the posted live evidence also exercises an older direct-send path rather than a real Codex-to-Slack lifecycle on the exact current head.

## What This Changes

The PR marks transient Codex tool summaries as typed progress notices, suppresses or reaction-routes those notices in Slack, and prevents suppressed sends from advancing delivery state.

## Best Possible Solution

Mark transient Codex tool-start summaries with the canonical `isStatusNotice` field, keep reaction selection and suppression local to Slack, and provide redacted exact-head Codex-to-Slack proof showing starts are suppressed while completed, failed, verbose, and semantic replies remain deliverable.
