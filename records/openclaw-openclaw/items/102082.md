## Summary

This PR remains necessary because current main does not contain the Slack progress-chrome guard, but it is not merge-ready: the current head retains the prior separate-progress compatibility and shared-contract blockers, while the live proof covers an earlier head and a direct Slack send call rather than the affected end-to-end Codex-to-Slack modes.

## What This Changes

Marks automatic non-verbose Codex tool summaries as progress intent, converts or suppresses them in Slack, and prevents suppressed sends from advancing delivery, stream, reply-plan, hook, or thread-participation state.

## Best Possible Solution

Keep transient-versus-terminal classification at the producer, define one closed typed progress-intent contract in the Plugin SDK reply-payload surface, and let Slack react or suppress only when the effective streaming mode already provides another progress presentation.
