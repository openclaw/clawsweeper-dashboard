## Summary

This PR remains necessary but is not merge-ready: the current patch still does not carry typed progress intent through Slack’s normal reply-delivery path, and it suppresses the documented standalone-progress mode. ## What This Changes

The PR adds Slack-specific progress-chrome classification that converts thread-scoped tool progress into reactions, suppresses unthreaded progress sends, and adjusts suppressed-send delivery bookkeeping and tests.

## Best Possible Solution

Carry the generic typed progress intent through the normal reply-payload delivery path, suppress it only when the active Slack preview or progress draft owns that update, preserve explicitly configured standalone delivery, and prove all modes with an exact-head real agent turn.
