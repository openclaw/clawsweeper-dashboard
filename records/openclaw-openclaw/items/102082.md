The exact current head still bypasses its typed progress gate for Slack native-block segments: that branch omits the progress flags and unconditionally records delivery, so structured progress chrome can still post and mutate sent state. The producer-owned intent is sound, but this confirmed path defect blocks merge.

This PR adds a generic tool-progress reply-payload marker, emits it for transient Codex tool summaries, and makes Slack convert eligible progress to reactions or suppress it instead of posting chat messages.

## Best Possible Solution

Propagate the existing typed progress intent through native-block sends before any Slack platform call, treat suppression as non-delivery across hooks and state, and add both a progress-marked native-block regression and a semantic native-block control.
