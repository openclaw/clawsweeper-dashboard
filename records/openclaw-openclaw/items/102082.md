## Summary

The PR is still necessary because current main has no equivalent typed progress-suppression path, but it is not merge-ready: marked payloads containing native Slack blocks bypass the new guard and are recorded as delivered. The producer-owned progress intent is a sound direction, and the live Slack evidence is useful, but the current head needs a whole-payload fix plus exact-head proof.

## What This Changes

Adds a generic tool-progress reply-payload marker, marks transient Codex tool summaries with it, and changes Slack to react to or suppress marked progress sends without consuming normal reply state.

## Best Possible Solution

Classify progress once at the logical Slack reply boundary, before text, native-block, and media decomposition; then suppress or react exactly once without hooks or delivery-state mutation, while leaving semantic, completed, failed, and verbose payloads unchanged.
