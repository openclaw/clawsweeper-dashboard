This PR still has a P1 gap on the current head: typed progress payloads rendered as native Slack blocks lose the progress marker, can reach `chat.postMessage`, and are unconditionally counted as delivered. The text, media-caption, dispatch, thread-participation, and fallback fixes are otherwise coherent, and the redacted live Slack evidence demonstrates the central behavior on text sends; merge should wait for the native-block repair and an explicit owner decision on the new permanent Plugin SDK surface.

## What This Changes

The branch tags transient Codex tool summaries with generic progress intent, suppresses or reacts to Slack progress chrome, propagates suppressed-send state through Slack delivery bookkeeping, adds regression tests, and exports a new Plugin SDK constant and predicate.

## Best Possible Solution

Apply progress suppression uniformly to every Slack payload representation, including native blocks, then either keep the marker internal or explicitly approve, document, and contract-test a durable generic Plugin SDK progress-intent API.
