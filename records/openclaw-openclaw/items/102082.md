## Summary

The current head has strong live proof and a sound producer-typed suppression design, but it still drops that intent on Slack native-block sends, allowing progress chrome to post and consume delivery state. The branch is also currently conflicting with `main`, and the additive public plugin-SDK contract needs explicit owner confirmation before merge.

## What This Changes

This PR types transient Codex tool summaries as generic progress payloads, suppresses or reacts to them in Slack, and avoids treating suppressed sends as delivered.

## Best Possible Solution

Use one canonical typed progress intent produced only for transient tool summaries, forward it through every Slack text and native-block send, treat suppression as non-delivery everywhere, and retain the public SDK exports only after explicit owner approval of that permanent contract.
