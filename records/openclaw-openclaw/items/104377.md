- `impact:ux-friction`: Long formatted announcements can arrive with words cut in half and orphaned fragments.

## Summary

Current main still contains the reported two-stage chunking gap: Telegram Markdown is first chunked using render-aware source boundaries, then the sender renders each unit and independently hard-splits oversized HTML text. The issue is valid, narrowly repairable, and distinct from the older Telegram fallback reports.

## What This Changes

Fix Telegram cron announce delivery so rendered HTML expansion cannot re-split already word-safe Markdown chunks in the middle of words.

## Best Possible Solution

Carry the render-aware Telegram Markdown chunk plan through sending without a second independent text split, while retaining entity-, tag-, and surrogate-safe chunking for genuinely pre-rendered HTML and rich-message inputs.

Yes at source level with high confidence: current main contains the exact two-stage raw-Markdown then rendered-HTML chunking path, and the downstream text splitter lacks word-boundary backoff. A live Telegram run was not performed during this read-only review.

## Solution Assessment

No, adding whitespace backoff to the generic entity helper is not clearly the best solution. The narrower maintainable fix is to preserve the existing render-aware Markdown plan through transport while leaving raw-HTML safety behavior separately owned.
