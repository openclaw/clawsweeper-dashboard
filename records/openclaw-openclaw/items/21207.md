## Summary

Keep open. Current main and the latest release still expose scalar file/search tool inputs, lifecycle-style context-engine hooks, and `update_plan` progress recording rather than native batch inputs, AI-callable context block tools, or submitted-plan enforcement.

## What This Changes

The issue requests native batched tool calls, AI-callable context block save/load/unload/list tools, and opt-in submitted-plan enforcement for multi-step agent workflows.

## Best Possible Solution

Keep this as a product-design umbrella, then split accepted work into separate maintainer-reviewed tracks for batch-capable tool schemas, AI-callable context state, and runner-owned plan gating.

## Reproduction Assessment

Partly yes from source inspection: current file tools and managed web search still use scalar inputs, context management is lifecycle-based, and `update_plan` records progress rather than enforcing it. This is a feature gap rather than a failing current contract.

## Solution Assessment

No, not as one combined implementation. The maintainable path is to design batching, selective context state, and plan-gating contracts separately against current tool schemas, context-engine lifecycle, storage, and runtime boundaries.
