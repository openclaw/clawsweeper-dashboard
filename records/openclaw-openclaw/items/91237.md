## Summary

Keep open for maintainer review. Current main still limits implicit/env-driven one-hour Anthropic cache TTL to direct Anthropic and Vertex hosts, while this PR extends that behavior to verified OpenRouter routes; the narrow implementation is plausible and well-proven, but it intentionally changes cost behavior for existing `OPENCLAW_CACHE_RETENTION=long` users and leaves the current prompt-caching documentation inaccurate.

## What This Changes

The PR adds OpenRouter URL and verified default-route eligibility to the Anthropic cache-control resolver so implicit or env-driven long retention emits `ttl: "1h"`, with regression coverage for URL, default-route, and conservative negative cases.

## Best Possible Solution

Retain the verified-route boundary, explicitly approve OpenRouter as an implicit long-TTL target, update the public prompt-caching reference to describe the OpenRouter default and URL routes plus the one-hour cost tradeoff, then rebase and revalidate the exact head.
