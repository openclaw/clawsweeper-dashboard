## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Require exact member matches before using DM names:** `extensions/feishu/src/bot-sender-name.ts:141-143`
  - body: The new DM lookup uses the only returned chat member when no `member_id` matches the sender. Because this request is capped to one `page_size: 10` response while the existing chat helper models `page_token`/`has_more`, a partial or permission-scoped response can attribute the wrong human name in `BodyForAgent` and `SenderName`; only accept an exact match or page until the sender is found before falling back.
  - confidence: 0.9
- **[P1] Bound and prune sender-name caches:** `extensions/feishu/src/bot-sender-name.ts:31`
  - body: This adds `directMemberNameCache` and widens `senderNameCache` keys by account/app id, but PR-head lookups leave expired entries resident and add no max-size pruning. In high-cardinality Feishu accounts/chats/senders, those process-wide maps can grow for the lifetime of the process; preserve current-main expired-entry deletion and add a bounded eviction strategy for both caches.
  - confidence: 0.88
- **[P1] Validate direct-member permission URLs:** `extensions/feishu/src/bot-sender-name.ts:132-134`
  - body: The new chatMembers path returns a parsed permission error directly from API responses, and the existing body builder later interpolates `grantUrl` into agent-visible System text. `extractPermissionError` accepts the first `https://.../app/...` host from `msg`/`message`, so constrain this path to official Feishu/Lark hosts or suppress the URL before surfacing it.
  - confidence: 0.86
