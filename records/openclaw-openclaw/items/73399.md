## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Require exact member matches before using DM names:** `extensions/feishu/src/bot-sender-name.ts:141-143`
  - body: `chatMembers.get` is a paginated list API with `has_more`/`page_token`, and the generated SDK docs note item counts can differ from `page_size`. Using the only returned item when its `member_id` does not match `senderId` can attribute a Feishu DM to the wrong human in `BodyForAgent` and `SenderName`; require an exact match or page until the sender is found before returning a name.
  - confidence: 0.91
- **[P1] Bound Feishu sender-name caches:** `extensions/feishu/src/bot-sender-name.ts:30-31`
  - body: The PR adds `directMemberNameCache` and widens sender cache keys to account/chat/sender identifiers, but both are process-wide Maps without a max size and the new direct-member cache never deletes stale entries. Since these keys come from inbound Feishu events, long-running processes can grow memory with account/chat/sender cardinality; preserve current-main expiry cleanup and add a bounded eviction strategy for both caches.
  - confidence: 0.88
- **[P1] Validate grant URLs before agent text:** `extensions/feishu/src/bot-sender-name.ts:52-65`
  - body: `extractPermissionError` now accepts raw API result objects and still extracts any `https://.../app/...` URL, which the Feishu message body later embeds in agent-visible system text. The new DM lookup path propagates that guidance, so validate the host against Feishu/Lark domains or omit the URL before surfacing it.
  - confidence: 0.86
