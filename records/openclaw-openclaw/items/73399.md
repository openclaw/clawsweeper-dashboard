## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Require exact member matches before using DM names:** `extensions/feishu/src/bot-sender-name.ts:141-143`
  - body: `chatMembers.get` is a paginated list API, so a one-item response is not proof that the item is the sender. Falling back to the only returned member when `member_id` does not match `senderId` can put the wrong human name into Feishu agent context and session metadata; require an exact match or page until the sender is found before returning a name. ([open.feishu.cn](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/chat-members/get?utm_source=openai))
  - confidence: 0.92
- **[P1] Bound Feishu sender-name caches:** `extensions/feishu/src/bot-sender-name.ts:30-31`
  - body: The PR adds `directMemberNameCache` and widens sender cache keys to account/chat/sender identifiers, but both are process-wide Maps without a max size and the new direct-member cache never deletes stale entries. These keys come from inbound Feishu events, so long-running processes can grow memory with account/chat/sender cardinality; preserve current-main expiry cleanup and add a bounded eviction strategy for both caches.
  - confidence: 0.9
- **[P1] Validate grant URLs before agent text:** `extensions/feishu/src/bot-sender-name.ts:52-65`
  - body: This parser accepts any `https://.../app/...` URL from Feishu error text, and the resulting `grantUrl` is interpolated into an agent-visible System message. Since the PR broadens permission guidance to the new DM API path, validate Feishu/Lark Open Platform hosts before surfacing the URL so a remote error body cannot make the agent present an arbitrary admin-grant link.
  - confidence: 0.88
