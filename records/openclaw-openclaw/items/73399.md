## Review Findings

Full review comments:

- **[P1] Require member matches before using DM names:** `extensions/feishu/src/bot-sender-name.ts:141-143`
  - body: `chatMembers.get` returns member IDs and pagination metadata, but this fallback accepts the only returned member even when its `member_id` does not match `senderId`. A partial or permission-filtered response can attribute a DM to the wrong person; only accept a matching ID or page until the sender is found before falling back.
  - confidence: 0.9
- **[P2] Bound Feishu sender-name caches:** `extensions/feishu/src/bot-sender-name.ts:30-31`
  - body: This adds `directMemberNameCache` and widens the sender cache key to account/chat/sender scope, but neither Map has a max size or global prune pass. A long-running Feishu process can accumulate one entry per distinct inbound account/chat/sender; use bounded TTL eviction like the nearby group-name cache and cover it in tests.
  - confidence: 0.86
- **[P2] Validate grant URLs before agent text:** `extensions/feishu/src/bot-sender-name.ts:52-65`
  - body: The PR broadens permission-error extraction to raw Feishu API response objects, but the extracted URL still accepts any `https://.../app/...` value and is later shown in agent-facing system text. Constrain it to Feishu/Lark or the configured domain, or omit the URL.
  - confidence: 0.84
- **[P3] Remove the release-owned changelog entry:** `CHANGELOG.md:15`
  - body: Root policy says `CHANGELOG.md` is release-owned and normal PRs should keep release-note context in the PR body, squash message, or commit message. Drop this entry and let release generation add the final changelog text.
  - confidence: 0.85
