## Summary

Keep open: current main still performs fallible JSON serialization inside the Google stream catch path, so a circular non-Error rejection can replace the intended structured error event with a second exception. The paired OpenAI report identifies the same invariant, so one shared repair should cover both.

## What This Changes

Make Google provider stream error handling tolerate circular non-Error rejection values without interrupting stream termination.

## Best Possible Solution

Add one provider-layer unknown-error formatter that prefers `Error.message`, safely serializes ordinary values, and falls back to `String(error)`; use it in all matching stream catch paths and test circular non-Error rejections still emit one terminal error event and close the stream.
