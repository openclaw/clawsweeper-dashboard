## Summary

Keep open: current main and v2026.6.11 still intentionally flatten remote Markdown images and block remote Control UI image fetches, so this needs an explicit maintainer security/product decision rather than cleanup.

## What This Changes

The issue requests that Control UI chat markdown render remote `http`/`https` image URLs inline instead of flattening them to alt text.

## Best Possible Solution

Define the approved Control UI remote-media policy first, then either keep the current no-remote-fetch behavior or implement an approved renderer, CSP, docs, tests, and browser-proof update together.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should Control UI ever render remote `http`/`https` Markdown image URLs directly from chat content, and if so under what trust policy?

Rationale: Current source, tests, docs, and merged hardening deliberately prevent remote browser image fetches, while the requested UX improvement would change that security boundary.

Likely owner: drobison00

Owner reason: The unresolved choice is primarily the Control UI browser-fetch/CSP security policy that drobison00 most directly touched in merged history.

Owner confidence: high

Options:

- **Keep no-remote-fetch default (recommended):** Preserve the current default and require same-origin media, local blob/data images, or an explicit proxy/opt-in design before rendering remote images.
- **Allow direct remote images:** Accept the privacy/tracking tradeoff and update the renderer, sanitizer attributes, CSP, docs, tests, and real browser proof together.
- **Fold into inline media policy:** Let the broader inline-media design decide whether remote Markdown images belong in Control UI at all.

## Reproduction Assessment

Yes, at source level: current main routes Markdown images through a renderer that flattens non-data image URLs, and tests assert that behavior. I did not run live browser proof in this read-only review.

## Solution Assessment

No for the suggested renderer-only fix. The maintainable path needs an explicit remote-media trust policy and coordinated renderer, sanitizer, CSP, docs, tests, and browser proof rather than only allowing `http(s)` image `src` values.
