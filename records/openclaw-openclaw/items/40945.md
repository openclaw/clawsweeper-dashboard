## Summary

Keep open: current main and v2026.6.11 still intentionally flatten remote Markdown images and enforce a no-remote-fetch Control UI policy, so this needs maintainer product/security direction rather than cleanup closure.

## What This Changes

Control UI chat markdown is requested to render remote `http`/`https` image URLs inline instead of flattening them to alt text.

## Best Possible Solution

Define the approved Control UI remote-media policy first, then either keep the no-remote-fetch default or land coordinated renderer, sanitizer/CSP, docs, tests, and browser-proof updates together.

- **Allow direct remote images:** Accept the privacy and tracking tradeoff, then update the renderer, sanitizer attributes, CSP, docs, tests, and real browser proof together.
- **Fold into inline media policy:** Let the broader inline-media work decide remote Markdown images alongside audio/video and web-preview behavior.

## Reproduction Assessment

Yes, at source level: current main routes Markdown images through a renderer that flattens non-data image URLs, and tests assert that behavior. I did not run a live browser session in this read-only review.

## Solution Assessment

No for the suggested renderer-only fix. The maintainable path needs an explicit remote-media trust policy and coordinated renderer, sanitizer, CSP, docs, tests, and browser proof rather than only allowing `http(s)` image `src` values.
