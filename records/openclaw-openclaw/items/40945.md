- `P2`: This is a normal-priority Control UI UX and security-policy issue with real user impact but no outage, data loss, or crash evidence.
- `impact:security`: The requested behavior changes whether untrusted chat content can cause an operator browser to fetch arbitrary remote image URLs.

## Summary

Keep open: current main and v2026.6.11 still intentionally flatten remote Markdown images and the Control UI CSP/docs forbid remote browser image fetches, so this needs maintainer product/security direction rather than cleanup closure.

## What This Changes

Request to render remote http/https Markdown image URLs inline in Control UI/WebChat instead of flattening them to alt text.

## Best Possible Solution

Define the approved Control UI remote-media policy first; if approved, update the renderer, sanitizer/CSP, docs, tests, and browser proof together, otherwise keep the same-origin/data/blob behavior.
