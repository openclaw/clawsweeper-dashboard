- `P2`: This is a normal-priority Control UI UX and security-policy issue with real user impact but no outage, data loss, crash, or blocked first-run path.
- `impact:security`: The requested behavior changes whether untrusted chat content can cause an operator browser to fetch arbitrary remote image URLs.
- `impact:ux-friction`: Remote image Markdown currently degrades to alt text, so image-only model or chat output is less usable even though the user is not fully blocked.

## Summary

Keep open: current main and v2026.6.11 still intentionally flatten remote Markdown images and enforce a no-remote-image-fetch Control UI policy, so this is a product/security decision rather than cleanup closure.

## What This Changes

The issue requests rendering remote `http/https` Markdown image URLs inline in Control UI chat instead of flattening them to alt text.

## Best Possible Solution

Define the approved Control UI remote-media policy first; if remote images are approved, update the renderer, CSP, docs, tests, and browser proof together, otherwise preserve the same-origin/data/blob behavior.
