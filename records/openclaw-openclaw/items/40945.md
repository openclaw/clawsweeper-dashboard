## Summary

Keep open: current main and v2026.6.11 still deliberately flatten remote Markdown images and keep Control UI image fetches same-origin/data/blob only, so the requested behavior remains a product/security decision rather than conservative cleanup.

## What This Changes

The issue requests inline rendering for remote http/https Markdown image URLs in Control UI chat.

## Best Possible Solution

Define the approved Control UI remote-media policy first, then either keep the no-remote-fetch default or update renderer, sanitizer/CSP, docs, tests, and real browser proof together.

## Reproduction Assessment

Yes, at source level: current main routes Markdown images through a renderer that flattens non-data image URLs, and tests assert that behavior. I did not run live browser proof in this read-only review.

## Solution Assessment

No for the suggested renderer-only fix. The maintainable path needs an explicit remote-media trust policy and coordinated renderer, sanitizer, CSP, docs, tests, and browser proof rather than only allowing http(s) image src values.
