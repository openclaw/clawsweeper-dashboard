## Label Justifications

- `P2`: This is a normal-priority Control UI UX and policy issue with real user impact but no outage, data loss, crash, or release-blocking evidence.
- `impact:security`: The requested behavior changes whether untrusted chat content can cause an operator browser to fetch arbitrary remote image URLs.
- `impact:ux-friction`: Remote Markdown image content currently degrades to alt text instead of an inline image, creating avoidable Control UI chat friction without blocking setup or core runtime use.

## Summary

Keep open: current main and the latest release still intentionally flatten remote Markdown image URLs and block remote browser image fetches, so this needs a maintainer security/product decision rather than conservative cleanup.

## What This Changes

Request to render remote http/https Markdown image URLs inline in Control UI chat instead of flattening them to alt text.

## Best Possible Solution

Define the approved Control UI remote-media policy first, then either keep the current no-remote-fetch behavior or implement coordinated renderer, CSP, docs, tests, and browser-proof changes together.

Options:

- **Fold into inline-media policy:** Leave this focused issue open only until the broader inline-media work at https://github.com/openclaw/openclaw/issues/64607 explicitly accepts or rejects remote Markdown images.
