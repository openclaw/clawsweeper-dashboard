- `P2`: This is a normal-priority Control UI UX and policy issue with real user impact but no urgent outage, crash, or data-loss evidence.
- `impact:security`: The requested behavior changes whether untrusted chat content can cause an operator browser to fetch arbitrary remote image URLs.
- `impact:ux-friction`: Remote Markdown image content currently degrades to alt text instead of an inline image, creating avoidable Control UI chat friction without blocking setup or core runtime use.

## Summary

Keep open: current main and v2026.6.11 still intentionally flatten remote Markdown images and block remote image fetches, so this is a focused product/security decision rather than a conservative cleanup close.

## What This Changes

The issue asks for Control UI chat to render remote http/https Markdown image URLs inline instead of flattening them to alt text.

## Best Possible Solution

Define the approved Control UI remote-media policy first, then either preserve the current no-remote-fetch default or update the renderer, CSP, docs, tests, and real browser proof together.
