## Summary

Keep open: current main and v2026.6.11 still intentionally block remote Control UI markdown images, and changing that behavior needs maintainer product/security direction because the renderer, CSP, tests, and docs all encode the no-remote-fetch policy.

## What This Changes

The issue requests that Control UI chat render Markdown image tags with remote http/https image URLs inline instead of flattening them to alt text.

## Best Possible Solution

Define the approved Control UI remote-media policy first; if maintainers choose to allow remote images, update the renderer, sanitizer attributes, CSP, docs, tests, and real browser proof together, otherwise keep the same-origin/data/blob default and route users through structured media or proxy-backed previews.
