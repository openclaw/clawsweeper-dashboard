- `P2`: This is a normal-priority Control UI UX and security-policy issue with real user impact but no outage, data loss, or crash evidence.
- `impact:security`: The requested behavior changes whether untrusted chat content can cause an operator browser to fetch arbitrary remote image URLs.
- `impact:ux-friction`: Remote image Markdown currently degrades to alt text, so image-only model or chat output is less usable even though the user is not fully blocked.

## Summary

Keep open: current main and v2026.6.11 still flatten remote Markdown images and document a no-remote-image-fetch Control UI policy, so the requested behavior needs maintainer product/security direction rather than cleanup closure.

## What This Changes

Request remote http/https Markdown images to render inline in Control UI chat instead of flattening to alt text.

## Best Possible Solution

Define the approved Control UI remote-media policy first; if approved, update the renderer, sanitizer/CSP, docs, tests, and browser proof together, otherwise keep same-origin/data/blob-only rendering.
