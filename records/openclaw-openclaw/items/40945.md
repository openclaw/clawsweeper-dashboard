## Summary

Keep open: current main and the latest release still intentionally flatten remote Markdown images and reject remote browser image fetches, so this needs a maintainer product/security decision rather than conservative cleanup.

## What This Changes

Requests Control UI chat to render remote http/https Markdown image URLs inline instead of flattening them to alt text.

## Best Possible Solution

Define the approved Control UI remote-media policy first, then either keep the no-remote-fetch default or implement an approved renderer, CSP, docs, tests, and browser-proof update together.

## Solution Assessment

No for the suggested renderer-only fix. The maintainable path needs an explicit remote-media trust policy and coordinated renderer, sanitizer, CSP, docs, tests, and browser proof rather than only allowing http(s) image src values.
