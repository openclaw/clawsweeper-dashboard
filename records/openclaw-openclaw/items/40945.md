- `P2`: This is a normal-priority Control UI UX and security-policy issue with real user impact but no outage, data loss, or crash evidence.
- `impact:security`: The requested behavior changes whether untrusted chat content can cause an operator browser to fetch arbitrary remote image URLs.
- `impact:ux-friction`: Remote image Markdown currently degrades to alt text, so image-only model or chat output is less usable even though the user is not fully blocked.

## Summary

Keep open: current main and the latest release still intentionally flatten remote Markdown image URLs and enforce a Control UI no-remote-image-fetch policy, so the remaining work needs maintainer product/security direction rather than cleanup closure.

## What This Changes

Request to render remote http/https Markdown image URLs inline in Control UI chat instead of flattening them to alt text.

## Best Possible Solution

Define the approved Control UI remote-media trust policy first; if approved, update the renderer, sanitizer/CSP, docs, tests, and browser proof together, otherwise keep the same-origin/data/blob behavior.
