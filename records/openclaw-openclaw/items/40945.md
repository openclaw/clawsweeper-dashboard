## Summary

Keep open: current main and v2026.6.11 still intentionally block remote Control UI markdown images, and changing that behavior needs maintainer product/security direction because the renderer, CSP, docs, and tests all encode a no-remote-fetch policy.

## What This Changes

The issue requests rendering remote http/https markdown image URLs inline in Control UI chat instead of flattening them to alt text.

## Best Possible Solution

Define the approved Control UI remote-media policy first; if maintainers approve remote images, update the renderer, CSP, docs, tests, and real browser proof together, otherwise keep the same-origin/data/blob default and route previews through structured media or a controlled proxy.
