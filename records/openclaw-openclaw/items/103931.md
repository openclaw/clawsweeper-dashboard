## Label Justifications

- `P1`: A current core compaction workflow can silently replace older session context with a summary that its enabled quality audit still rejects.
- `impact:data-loss`: Successful compaction can discard older transcript content after accepting a candidate known to omit required information.
- `impact:session-state`: The retained compacted context can lose or misrepresent pending asks, decisions, constraints, and exact identifiers.

## Summary

Keep open: current main demonstrably accepts a final summary that still fails the enabled quality audit, but the correct terminal behavior needs an explicit reliability-versus-availability decision because unconditional cancellation can wedge oversized sessions.

## What This Changes

Change safeguard compaction so exhausted quality-audit retries do not silently accept a summary that still fails required structure, identifier, or pending-ask checks.

## Best Possible Solution

Define a bounded exhausted-audit outcome that never treats a rejected summary as an ordinary success, preserves session recoverability, exposes exact audit reasons, and covers repeated malformed output plus subsequent compaction behavior in regression tests.
