## Summary

Keep this PR open. The patch appears correct and CI is green, but the newly added validation remains mock-only: it verifies timeout option forwarding without demonstrating that a real response body which stalls after headers is cancelled and returns control.

## What This Changes

The PR applies 120-second response-header and 30-second body-idle deadlines to QQBot remote-media downloads, forwards the idle deadline through the built-in adapter, and updates focused tests.

## Best Possible Solution

Land the existing bounded-timeout wiring after a controlled HTTP server sends headers and one body chunk, then stalls, with redacted terminal output showing the QQBot adapter returns a timeout error after the idle deadline.
