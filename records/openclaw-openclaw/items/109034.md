## Summary

Keep this PR open for QQBot-owner review: the patch has credible live-path proof and no discrete correctness defect found, but it intentionally changes existing media-download failure behavior to fail after 30 seconds of body inactivity.

## What This Changes

The branch adds a shared QQBot 120-second response-header and 30-second body-idle timeout policy, applies it to adapter media reads and file downloads, and adds propagation coverage.

## Best Possible Solution

Accept the shared channel-owned 120s/30s timeout policy only after a QQBot owner confirms that failing stalled media transfers is the intended compatibility contract; then retain the single adapter-boundary policy and its regression coverage.
