## Summary

This PR remains necessary: it narrowly makes raw transcript cursors opaque and canonical while preserving OpenClaw-emitted continuation cursors. The supplied production SQLite-runtime proof is strong; the remaining maintainer check is whether accepting padded or otherwise equivalent cursor aliases was ever a supported SDK compatibility contract.

## What This Changes

The branch rejects raw transcript cursors unless both their base64url encoding and decoded envelope exactly round-trip through OpenClaw’s canonical encoder, with regressions for appended junk, padding, and extra fields.

## Best Possible Solution

Keep raw transcript cursors as opaque canonical tokens, retain the exact round-trip validation and regression coverage, and land after confirming no supported SDK contract promises permissive alias acceptance.
