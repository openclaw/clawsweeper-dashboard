## Summary

Keep this maintainer-labeled PR open for session-storage-owner review: the patch appears to reconcile an existing startup warning policy with doctor migration finalization, but it changes upgrade-time archival and failure-manifest behavior for persisted session stores.

## What This Changes

The branch centralizes session-SQLite migration warning classification and makes `entry_invalid` nonblocking for doctor import, archival, manifest status, and gateway-startup reporting.

## Best Possible Solution

Retain one shared warning classifier, with the session-storage owner explicitly confirming that all `entry_invalid` records may complete and archive a migration while remaining recoverable from the archived legacy store.
