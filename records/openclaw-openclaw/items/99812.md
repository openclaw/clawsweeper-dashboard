Keep this PR open for review, but it is not merge-ready: it improves several Google OAuth reads, yet the Vertex ADC path still leaves gzip decompression unbounded after the new wire cap and the PR body only provides test-output proof.

## What This Changes

The PR replaces unbounded Google OAuth JSON/arrayBuffer response reads with existing bounded SDK helpers in `extensions/google/oauth.project.ts`, `extensions/google/oauth.token.ts`, and `extensions/google/vertex-adc.ts`.

## Best Possible Solution

Use one coherent Google OAuth hardening path: bound Vertex ADC raw and decoded gzip output with focused regression proof, and coordinate the project/token parser-boundary changes with the existing tested parser PR.

## Reproduction Assessment

Yes from source inspection. Current main still reaches an unbounded `response.arrayBuffer()` in the Vertex ADC OAuth token refresh path, while the project/token JSON paths are already wire-capped by `fetchWithTimeout`.

## Solution Assessment

No. The PR is a plausible mitigation, but the best fix also caps decoded gzip output and includes focused oversized-response proof; the project/token parser changes should be coordinated with the existing tested parser-boundary PR.
