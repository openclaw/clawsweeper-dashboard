## Summary

This remains a distinct WebChat product request. The merged auto-scroll selector lets users choose how streaming output follows the viewport, but deliberately retains the “New messages” catch-up control; maintainers still need to decide whether that control may be hidden and what accessible recovery affordance replaces it.

## What This Changes

Add a WebChat preference to hide, replace, or otherwise customize the “New messages” catch-up indicator shown when new output arrives while the reader is away from the live tail.

## System Context

WebChat receives streaming chat updates and uses scroll state plus the persisted auto-scroll mode to decide whether to follow new output. When the user is not at the live tail, the UI exposes a “New messages” control so they can manually catch up.

## Architecture Diagram

flowchart LR
  A[Streaming chat output] --> B[Scroll scheduler]
  C[Persisted auto-scroll mode] --> B
  B --> D[Near-bottom decision]
  D --> E[New messages catch-up control]
  E --> F[Manual scroll to live tail]

## Best Possible Solution

Choose one persisted browser-local indicator policy that preserves an accessible manual return-to-live-tail action, then implement it in the existing WebChat settings, scroll scheduling, render path, and focused UI tests rather than adding a new gateway configuration option.
