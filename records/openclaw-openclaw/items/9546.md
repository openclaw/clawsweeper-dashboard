## Summary

Keep open. Current main still has auto-scroll modes but no separate WebChat New messages indicator preference; the landed auto-scroll selector intentionally preserves that button as the manual catch-up affordance, so the remaining request needs maintainer UX/config direction.

## What This Changes

The issue requests a WebChat option or setting to disable, replace, or customize the New messages notification banner.

## Best Possible Solution

Add a maintainer-approved browser-local WebChat new-message indicator mode that preserves an accessible jump-to-latest affordance and avoids retired WebChat config unless maintainers explicitly choose that surface.

## Reproduction Assessment

Yes, at source level: current main sets chatNewMessagesBelow when chat does not auto-stick, renders the New messages button from that state, and has no separate indicator preference in persisted UI settings or WebChat docs. I did not run live browser proof because this cleanup review is read-only and the source path is direct.

## Solution Assessment

No for the proposed openclaw.json WebChat shape because that config surface is retired. A browser-local persisted indicator setting is the narrower likely direction, but maintainers first need to choose the indicator and catch-up semantics.
