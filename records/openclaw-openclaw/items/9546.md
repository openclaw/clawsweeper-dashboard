## Summary

Keep open. Current main and v2026.6.11 still render the New messages control from scroll state without a separate disable, dismiss, or customize preference; the merged auto-scroll selector helps adjacent behavior but deliberately preserves this catch-up affordance.

## What This Changes

Request to add a WebChat setting or mode to disable, customize, or replace the New messages notification banner.

## Best Possible Solution

Add a maintainer-approved browser-local new-message indicator mode that preserves an accessible jump-to-latest affordance and keeps retired gateway.webchat config closed unless intentionally reopened.

## Reproduction Assessment

Yes, at source level. Current main sets chatNewMessagesBelow when chat does not auto-stick, renders New messages from that state, and has no separate persisted indicator preference or WebChat config key.

## Solution Assessment

Unclear until maintainers choose the UX surface. A browser-local persisted indicator setting is likely narrower than the proposed openclaw.json WebChat config, but the semantics need product approval first.
