## Summary

Keep open. Current main and the latest release have a persisted auto-scroll mode, but they still render the WebChat New messages button from scroll state with no dedicated disable, dismiss, or customization preference; the member discussion explicitly treats this as a separate UX/product decision.

## What This Changes

Request adds a WebChat option to disable, customize, or replace the New messages banner.

## Best Possible Solution

Add a maintainer-approved browser-local WebChat new-message indicator mode that preserves an accessible jump-to-latest affordance and avoids retired WebChat config unless maintainers explicitly choose that surface.

## Reproduction Assessment

Yes, at source level: current main sets chatNewMessagesBelow when chat does not auto-stick, renders the New messages button from that state, and has no indicator preference in persisted UI settings or WebChat docs. I did not run a live browser reproduction because the missing option is clear from source and docs.

## Solution Assessment

No for the proposed openclaw.json WebChat shape because that config surface is retired. A browser-local persisted indicator setting is the narrower likely direction, but maintainers first need to choose the indicator and catch-up semantics.
