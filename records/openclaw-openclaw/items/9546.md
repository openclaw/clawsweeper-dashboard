## Summary

Keep open. Current main and v2026.6.11 still render the WebChat New messages button from scroll state with no separate disable, dismiss, or customization preference; the merged auto-scroll and backscroll fixes overlap but intentionally preserve that catch-up affordance.

## What This Changes

Request a WebChat setting or configuration option to disable or customize the New messages notification banner.

## Best Possible Solution

Add a maintainer-approved browser-local WebChat new-message indicator mode that preserves an accessible jump-to-latest affordance and avoids retired WebChat config unless maintainers explicitly choose that surface.

## Reproduction Assessment

Yes, at source level: current main sets chatNewMessagesBelow when chat does not auto-stick, renders the New messages button from that state, and has no separate indicator preference in settings or docs. I did not run a live browser reproduction because this read-only review can prove the missing option from source and shipped docs.

## Solution Assessment

No for the proposed openclaw.json WebChat shape because that config surface is retired. A browser-local persisted indicator setting is the narrower likely direction, but maintainers first need to choose the indicator and catch-up semantics.
