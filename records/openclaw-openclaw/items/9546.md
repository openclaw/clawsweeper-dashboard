## Summary

Keep open. The merged auto-scroll selector addresses when WebChat follows streaming output, but intentionally preserves the separate “New messages” catch-up control; this issue still needs a maintainer decision on whether that affordance may be hidden and what accessible recovery path replaces it.

## What This Changes

Add a WebChat preference to hide, replace, or make less intrusive the “New messages” catch-up indicator.

## System Context

WebChat receives streaming agent output and applies a persisted auto-scroll policy before deciding whether the reader remains at the live tail. When the reader is away from the tail, the chat UI exposes a “New messages” control to return to current output.

## Architecture Diagram

flowchart LR
  A[Streaming agent output] --> B[WebChat scroll state]
  C[Persisted auto-scroll mode] --> D[Scroll policy]
  B --> D
  D --> E[Reader remains away from live tail]
  E --> F[New messages catch-up control]
  F --> G[Manual return to latest output]

## Best Possible Solution

Choose an explicit WebChat indicator policy, then implement it as a persisted UI preference alongside a discoverable manual return-to-latest action, with focused scroll/render coverage and user-facing documentation.
