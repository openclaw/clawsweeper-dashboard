## Summary

Keep open. Current main and latest release v2026.6.11 still render the WebChat New messages button from scroll state, while the merged auto-scroll work intentionally preserved that catch-up affordance; disabling or customizing the banner remains a separate UX/settings product decision.

## What This Changes

The issue requests a WebChat setting or behavior to disable, replace, or make less intrusive the New messages notification banner.

## Best Possible Solution

Add a maintainer-approved browser-local WebChat new-message indicator mode that preserves an accessible jump-to-latest affordance and avoids reopening gateway config unless explicitly chosen.

## Reproduction Assessment

Yes, at source level: current main and the latest release still derive the New messages button from `chatNewMessagesBelow`, and current tests show auto-scroll Off still sets that indicator. I did not run a live browser repro because this read-only review can prove the missing preference from source and docs.

## Solution Assessment

No for the proposed `openclaw.json` WebChat shape because current docs say that WebChat config section is retired. A browser-local persisted indicator setting is likely narrower, but maintainers need to choose the catch-up semantics first.
