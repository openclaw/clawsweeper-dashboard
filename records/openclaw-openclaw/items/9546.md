## Summary

Keep open. Current main and the latest release have a persisted WebChat auto-scroll mode, but they still intentionally preserve the New messages indicator as the manual catch-up affordance; the remaining request is a separate WebChat UX/settings product decision.

## What This Changes

The issue requests a WebChat option to disable, customize, or replace the New messages banner.

## Best Possible Solution

Keep the issue open for maintainer UX direction; if accepted, implement a browser-local WebChat indicator mode or dismiss behavior with focused scroll/render tests and docs, without changing the existing auto-scroll selector semantics.

## Reproduction Assessment

Yes for source behavior: current main traces from `scheduleChatScroll` setting `chatNewMessagesBelow` to `renderChat` showing the New messages button without an indicator preference. No live browser reproduction was run in this read-only cleanup pass.

## Solution Assessment

Unclear until maintainers choose the UX direction. A browser-local indicator preference or dismissible/non-intrusive indicator looks cleaner than resurrecting `gateway.webchat` config, because current docs say WebChat has no persisted config section.
