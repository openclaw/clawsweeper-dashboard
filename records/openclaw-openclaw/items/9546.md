## Summary

Current main and v2026.6.11 provide persisted auto-scroll modes and preserve backscroll, but still expose the floating New messages recovery action directly from scroll state without a visibility or presentation preference. The remaining request is valid WebChat ergonomics work, but hiding that action requires maintainer UX direction because it is the manual catch-up path when automatic scrolling is off.

## What This Changes

Add a WebChat preference to hide, replace, or reduce the prominence of the New messages indicator.

## Best Possible Solution

Keep the current visible behavior as the default and add a browser-local persisted presentation preference only after choosing a replacement recovery affordance; avoid adding an `openclaw.json` key for this UI-only choice.
