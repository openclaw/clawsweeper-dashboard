## Summary

Keep open. Current main and the latest release still preserve the New messages button as the manual catch-up affordance; the merged auto-scroll selector does not add a separate disable, dismiss, or customize mode for that indicator.

## What This Changes

The issue requests a WebChat setting or UX mode to disable, replace, or customize the New messages banner shown while reading chat content.

## Best Possible Solution

Add a maintainer-approved browser-local new-message indicator mode that preserves an accessible jump-to-latest affordance and keeps the retired gateway.webchat config surface closed unless intentionally reopened.

## Reproduction Assessment

Yes. Source inspection shows current main sets chatNewMessagesBelow when chat does not auto-stick, renders the New messages button from that state, and has no separate indicator preference in persisted UI settings or WebChat docs.

## Solution Assessment

No, not as the proposed openclaw.json WebChat config because that surface is retired. A browser-local persisted indicator setting is the narrower likely direction, but maintainers first need to choose the indicator and catch-up semantics.
