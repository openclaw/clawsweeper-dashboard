## Summary

Keep open. Current main and the latest release still show the WebChat New messages button from scroll state, while the merged auto-scroll selector intentionally preserved that button as the manual catch-up affordance; this remains a maintainer UX/settings decision rather than completed work.

## What This Changes

The issue requests a WebChat option or setting to disable, replace, or customize the New messages banner.

## Best Possible Solution

Add a maintainer-approved browser-local new-message indicator mode that preserves an accessible jump-to-latest affordance and keeps the retired gateway.webchat config surface closed unless intentionally reopened.

## Reproduction Assessment

Yes, at source level: current main sets chatNewMessagesBelow when chat does not auto-stick, renders the New messages button from that state, and has no separate indicator preference in persisted UI settings or WebChat docs. I did not run a live browser reproduction because the missing option is directly provable from source and docs.

## Solution Assessment

No, not as the proposed openclaw.json WebChat config because that surface is retired. A browser-local persisted indicator setting is the narrower likely direction, but maintainers first need to choose the indicator and catch-up semantics.
