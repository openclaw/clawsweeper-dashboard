## Summary

Keep open. Current main and the latest release still render the WebChat New messages button directly from scroll state; the merged auto-scroll work intentionally preserved that catch-up affordance, so disabling/customizing the banner remains a separate maintainer UX/config decision.

## What This Changes

The issue requests a WebChat setting or UX mode to disable, replace, or customize the New messages notification banner.

## Best Possible Solution

Add a maintainer-approved browser-local WebChat new-message indicator mode that preserves an accessible jump-to-latest affordance and avoids retired WebChat config unless maintainers explicitly choose that surface.

## Reproduction Assessment

Yes, at source level: current main sets chatNewMessagesBelow when chat does not auto-stick, renders the New messages button from that state, and has no indicator preference in persisted UI settings or WebChat docs. I did not run a live browser reproduction because this read-only review can prove the missing option from source and docs.

## Solution Assessment

No for the proposed openclaw.json WebChat shape because that config surface is retired. A browser-local persisted indicator setting is the narrower likely direction, but maintainers first need to choose the indicator and catch-up semantics.
