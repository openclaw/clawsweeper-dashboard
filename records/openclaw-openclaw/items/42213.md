## Summary

## What This Changes

The issue asks for Control UI chat to recover automatically when a long `chat.send` run has finished on the gateway but the UI missed the terminal event, so queued follow-up messages flush without another manual prompt.

## Best Possible Solution

Land or replace the linked current-main Control UI recovery so stale run state is cleared only after gateway/session terminal proof, queued messages flush afterward, and redacted browser/gateway proof covers the missed-terminal path.
