## Summary

Keep this issue open: current main confirms that browser screenshots create image-bearing tool results and that recent images remain in context, but it does not contain the reported `describeBrowserScreenshot()` failure fallback, and the claimed transformation of every later tool result still needs a live reproduction. The active related reports overlap without conclusively owning this specific browser-triggered failure.

## What This Changes

Prevent a browser screenshot image result from persisting in session context in a way that makes subsequent tool outputs unreadable or image-wrapped.

## Best Possible Solution

Keep the screenshot image available for its intended turn, preserve its text/path metadata, and add a focused regression path that proves later text tool results remain text; if persistence is the trigger, retire or mask the processed screenshot after consumption rather than removing screenshot vision support entirely.
