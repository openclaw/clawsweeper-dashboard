## Label Justifications

- `P1`: A documented DM isolation mode can collapse distinct Matrix direct senders into one transcript session, which is urgent despite non-default and homeserver-dependent exposure.
- `impact:security`: The reported failure can expose one Matrix peer's private DM transcript to another distinct peer.
- `impact:session-state`: Distinct peer identities can map to the same persisted session key under per-peer DM scopes, mis-associating transcript state.

## Summary

Keep open: current main and v2026.6.11 still lowercase direct-message peer IDs before building non-main DM session keys, while Matrix routes raw MXIDs into that path. The prior Matrix room/thread case-preservation work fixed channel/group keys only, so this remains a source-provable session-isolation and transcript-exposure bug.

## What This Changes

The issue reports Matrix and Signal direct-message session keys folding case-distinct peer IDs under per-peer DM scopes, causing transcript/session collision.

## Best Possible Solution

Matrix direct-peer session keys should preserve provider-owned identity case under non-main `dmScope` while leaving `main` and ordinary case-insensitive channels folded, with explicit legacy alias safeguards.

## Solution Assessment

Yes for the code layer: the narrow maintainable fix is to route direct peers through the existing opt-in case-preservation policy, then add regression coverage and legacy alias safeguards. Signal direct inclusion should wait for direct-ID contract proof if maintainers are not comfortable enrolling it with Matrix.
