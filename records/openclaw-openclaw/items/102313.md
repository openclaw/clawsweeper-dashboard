## Summary

Keep open: current main and v2026.6.11 still lowercase direct peer IDs before non-main DM session-key construction, and the Matrix plugin feeds raw sender MXIDs into that path. Prior Matrix room-id case preservation fixed channel/group keys only and explicitly left direct peers folded, so this is a real remaining session-isolation bug rather than a duplicate.

## What This Changes

The issue asks OpenClaw to preserve case for Matrix direct-message peer IDs when building non-main per-peer DM session keys.

## Best Possible Solution

Matrix direct-peer session keys should preserve provider-owned identity case under non-main `dmScope` while leaving `main` and ordinary case-insensitive channels folded, with upgrade-safe alias handling.

Yes, the narrow maintainable fix is to route Matrix direct peers through the same provider-owned case-preservation policy as channel/group peers, with focused legacy and migration safeguards. ## Repair Work Prompt

Fix the Matrix direct-message session-key case collision reported in https://github.com/openclaw/openclaw/issues/102313. On current main, `buildAgentPeerSessionKey` lowercases direct peer IDs before constructing `per-peer`, `per-channel-peer`, and `per-account-channel-peer` keys, while Matrix inbound/outbound routing passes raw MXIDs as `peer.kind: "direct"`; case-distinct Matrix identities can therefore share one DM transcript. Preserve Matrix direct peer identity case under non-main `session.dmScope` by reusing the existing case-preservation policy or another single canonical helper; do not change `dmScope: "main"` behavior and do not stop lowercasing ordinary case-insensitive channels. Before enrolling Signal direct IDs, inspect the Signal direct identity contract and only include it if source/dependency proof shows those IDs are case-sensitive. Add regression coverage for Matrix direct `@Alice`/`@alice` or domain-case MXIDs across all three non-main dmScopes, for group/channel behavior staying unchanged, and for Telegram/Discord-style channels still folding. If direct key preservation affects stored session lookup, delivery lookup, or migration, update those helpers with exact direct-identity proof rather than substring matching so legacy lowercased rows are neither cross-read nor deleted incorrectly. Do not edit `CHANGELOG.md`.
