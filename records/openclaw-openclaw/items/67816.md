## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve the auth-dir guard on timeout logout:** `extensions/whatsapp/src/auth-store.ts:303-305`
  - body: When the auth barrier times out, `forceClear` skips `shouldClearOnLogout`, so a caller-supplied `authDir` with no WhatsApp credentials still reaches the recursive `fs.rm(resolvedAuthDir, ...)` path. Keep timeout logout from becoming a recursive delete of arbitrary directories; layer the timeout behavior behind the managed-auth-dir/credential guard from current main or delete only known credential artifacts.
  - confidence: 0.88
- **[P1] Keep runtime checks when linked is unknown:** `extensions/whatsapp/src/status-issues.ts:72-74`
  - body: The PR intentionally omits `linked` during auth timeouts, but this early return stops before checking `healthState`, `running`, and `connected`. That makes WhatsApp status look clean while stale, reconnecting, logged-out, or disconnected runtime state is still present during the unstable-auth window.
  - confidence: 0.86
- **[P2] Pass account context to heartbeat auth deps:** `extensions/whatsapp/src/heartbeat.ts:8-10`
  - body: `checkWhatsAppHeartbeatReady` resolves the selected account and authDir, but the new dependency is invoked with no argument and the SDK type also has no account context. Account-aware test or plugin implementations cannot distinguish a non-default account, so keep the dependency signature account-aware or call the concrete helper with `account.authDir`.
  - confidence: 0.72
