## Summary

Keep this issue open. Current documentation defines manual runs as enqueue-first and `--wait` as polling the returned run id, but it does not prove that a completed isolated turn cannot be incorrectly recorded as a setup timeout or leave its running marker stale; the detailed report needs a current-version trace against that contract. ([docs.openclaw.ai](https://docs.openclaw.ai/cli/cron))

## What This Changes

The issue requests a fix for isolated `agentTurn` cron jobs where a manual run is recorded as a setup timeout even though the agent turn completes, leaving incorrect cron history and temporary running state.

## Best Possible Solution

Reproduce one isolated manual run on the current release with its returned run id, then make cron terminalization consume the authoritative run outcome exactly once and clear `runningAtMs` in the same completion path; add regression coverage for a completed turn whose enqueue or acknowledgement path is delayed.
