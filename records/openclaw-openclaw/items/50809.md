## Summary

Keep open. Current main and the latest release still do not implement the Android-node `sms.read` command or Android-device SMS ingress/reply channel; the shipped Twilio-backed SMS plugin only partially overlaps, so this remains a product and security decision rather than conservative cleanup.

## What This Changes

The issue requests an Android `sms.read` invoke command plus a node-mediated SMS channel with allowlisted inbound texts and Android-node outbound replies.

## Best Possible Solution

Keep this as the canonical Android-device SMS tracker, split `sms.read` from Android-node SMS channel ingress, and require a maintainer-approved security and channel-ownership design that coexists cleanly with the Twilio SMS plugin.

## Reproduction Assessment

Not applicable; this is a feature request rather than a broken existing behavior report. Source and release inspection give a high-confidence current gap: Android exposes `sms.send` and `sms.search`, while `sms.read`, `sms.received`, and Android SMS receiver ingress are absent.

## Solution Assessment

No, not as one combined automated change. The safer path is to split the Android read command from the Android-device channel/config/security decision and keep the existing Twilio SMS plugin as a separate provider-hosted channel unless maintainers choose a shared contract.
