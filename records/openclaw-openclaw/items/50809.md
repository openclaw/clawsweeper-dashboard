## Summary

Keep open. Current main and the latest release still lack an Android-node `sms.read` command and Android-device SMS ingress/reply channel; the existing `sms` channel is Twilio-backed, so the remaining work is a product and security-boundary decision rather than conservative cleanup.

## What This Changes

The issue requests an Android `sms.read` invoke command plus an allowlist-gated Android-node SMS messaging channel that routes inbound texts to agents and replies through `sms.send`.

## Best Possible Solution

Keep the current Twilio SMS plugin and Android `sms.search`/`sms.send` boundaries until maintainers choose a device-SMS design; if accepted, implement it as explicit opt-in with fail-closed sender policy, gateway command gating, Android permission UX, docs, and real-device proof.
