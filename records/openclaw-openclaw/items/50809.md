## Summary

Keep open. Current main still lacks the requested Android-node `sms.read` command and connected-device SMS ingress/reply channel; the existing Android `sms.search` tool and Twilio-backed SMS plugin are adjacent but do not satisfy the Android-device request.

## What This Changes

This issue requests an Android-node `sms.read` invoke command plus a connected-device SMS messaging channel with allowlisted inbound texts and SMS replies through a paired Android node.

## Best Possible Solution

Keep this as the focused Android-device SMS tracker, split a narrow security-reviewed `sms.read` command contract from the inbound/reply channel decision, and preserve the Twilio SMS plugin boundary unless maintainers choose a shared SMS model.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support Android-device SMS ingress/reply as a first-class channel, and if so should it reuse the existing `sms` channel/config surface or use a separate Android-device plugin/channel boundary?

Rationale: The remaining work crosses private Android SMS permissions, gateway node-event ingress, sender allowlists/pairing, outbound carrier-SMS authority, and the existing Twilio-owned `sms` channel namespace; automation cannot choose that product and security boundary safely.

Likely owner: steipete

Owner reason: The most central unresolved boundary is coexistence with the current Twilio-backed `sms` channel and OpenClaw's plugin/core scope policy, tied to steipete's recent SMS channel work.

Owner confidence: high

Options:

- **Split command and channel decisions (recommended):** Define a narrow dangerous/default-blocked Android `sms.read` command first, then separately design Android-device SMS ingress with fail-closed sender policy and a clear channel/config boundary.
- **Create a separate Android-device SMS channel:** Use a distinct channel or plugin identity for connected-device SMS so it does not conflict with the existing Twilio-backed `sms` channel semantics.
- **Decline Android-device SMS ingress:** Keep hosted Twilio SMS as the supported SMS channel and leave connected Android SMS limited to explicit node commands such as `sms.send` and `sms.search`.
