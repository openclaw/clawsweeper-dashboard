## Summary

Keep open. Current main and the latest release still expose Android `sms.send`/`sms.search` plus a separate Twilio-backed `sms` plugin, but they do not implement the requested Android `sms.read` command or Android-node SMS ingress/reply channel.

## What This Changes

The issue requests an Android `sms.read` invoke command and an Android-node-mediated SMS channel for inbound texts and SMS replies.

## Best Possible Solution

Keep this open as the Android-device SMS tracker, split `sms.read` from the inbound/reply channel design, and require maintainer-approved security and channel ownership boundaries before implementation.

- **Split and design first (recommended):** Define a narrow Android `sms.read` command contract separately from Android-device SMS channel ingress, then implement only after sender authorization, redaction, logging, and channel naming are approved.
- **Limit to read command:** Accept only a dangerous-by-default Android `sms.read` invoke command and defer inbound/reply channel behavior until a separate channel design is approved.
- **Keep hosted SMS only:** Leave the official `sms` channel as Twilio-backed and redirect Android-device SMS channel work unless a new plugin/API seam is explicitly sponsored.
