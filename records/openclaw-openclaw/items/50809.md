## Summary

Keep open. Current main and v2026.6.11 still lack the requested Android-node `sms.read` command and Android-device SMS ingress/reply channel; the existing Android `sms.search` command and the Twilio-backed `sms` plugin are adjacent but do not solve the device-SMS request.

## What This Changes

The issue requests an Android-node `sms.read` invoke command plus an allowlist-gated Android-device SMS messaging channel for inbound texts and outbound replies.

## Best Possible Solution

Keep this issue open as the Android-device SMS tracker, split `sms.read` from the inbound/reply channel decision, and require maintainer-approved security and ownership boundaries before implementation.

- **Do not add device SMS:** Close or narrow this to the existing Twilio SMS plugin if maintainers decide Android-device SMS privacy and carrier-send authority are out of scope.
