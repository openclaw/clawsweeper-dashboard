## Summary

Keep open. Current main and v2026.6.11 still lack the requested Android-node `sms.read` command and Android-device SMS ingress/reply channel; existing Android `sms.search` and the Twilio-backed SMS plugin are adjacent but do not solve this device-SMS request.

## What This Changes

Request adds an Android-node `sms.read` invoke command plus a node-mediated SMS messaging channel with inbound allowlisting and outbound replies through a connected Android device.

## Best Possible Solution

Keep this issue open as the Android-device SMS tracker, split `sms.read` from the inbound/reply channel decision, and require maintainer-approved security and ownership boundaries before implementation.

## Reproduction Assessment

Not applicable; this is a feature request rather than a broken existing behavior report. Source and release inspection give a high-confidence current gap: Android exposes `sms.send` and `sms.search`, while `sms.read`, `sms.received`, and Android SMS receiver ingress are absent.

## Solution Assessment

No, not as one combined automated change. The safer path is to split the Android read command from the Android-device channel/config/security decision and keep the existing Twilio SMS plugin as a separate provider-hosted channel unless maintainers choose a shared contract.
