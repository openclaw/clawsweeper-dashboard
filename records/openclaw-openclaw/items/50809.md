## Summary

Keep open. Current main and the latest release still lack the requested Android-node `sms.read` command and Android-device SMS ingress/reply channel; adjacent work covers Android `sms.search` and a Twilio-backed SMS plugin, but not this device-mediated SMS feature.

## What This Changes

Request to add an Android-node `sms.read` invoke command plus an Android-device SMS messaging channel with allowlist-gated inbound texts and SMS replies through the connected node.

## Best Possible Solution

Keep this as the canonical Android-device SMS tracker, split `sms.read` from Android-node SMS channel ingress, and require a maintainer-approved security/channel ownership design before implementation.

## Reproduction Assessment

Not applicable; this is a feature request rather than a broken existing behavior report. Source and release inspection give a high-confidence current gap: Android exposes `sms.send` and `sms.search`, while `sms.read`, `sms.received`, and Android SMS receiver ingress are absent.

## Solution Assessment

No, not as one combined automated change. The safer path is to split the Android read command from the Android-device channel/config/security decision and keep the existing Twilio SMS plugin as a separate provider-hosted channel unless maintainers choose a shared contract.
