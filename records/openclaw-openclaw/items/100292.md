## Summary

Keep open: current main still has a real Telegram reply-media failure mode when an absolute local `MEDIA:` path is outside the effective local-media roots, but broadening accepted host paths is a security/product decision already overlapping the open root-policy work.

## What This Changes

The issue asks OpenClaw to make Telegram `MEDIA:` directives for absolute local paths outside the default media roots either work through a supported root policy or fail with clearer documented behavior.

## Best Possible Solution

Keep the safe host-read boundary, add a clear Telegram/media failure reason for blocked `MEDIA:` paths, and let the canonical root-expansion policy be decided through the existing media-root or `tools.fs.roots` work.
