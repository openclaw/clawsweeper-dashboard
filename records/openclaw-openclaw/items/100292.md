## Summary

Keep open: current main still leaves the Telegram blocked-media path as a security-sensitive product decision, with configurable root expansion overlapping the open root-policy work and diagnostics still needing a clearer dropped-media reason than the generic reply warning.

## What This Changes

The issue asks OpenClaw to make Telegram `MEDIA:` directives for absolute local paths outside built-in media roots either work through a defined root policy or fail with clear diagnostics and documentation.

## Best Possible Solution

Keep the safe host-read boundary, add reasoned warn-level and user-visible diagnostics for dropped reply media, and let the canonical configurable-root contract be settled through the shared filesystem/media-root policy.
