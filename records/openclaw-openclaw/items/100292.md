## Summary

Keep open: current main and v2026.6.11 still gate reply `MEDIA:` local paths through the file-read/local-root security policy, and while dropped media now gets a generic `Media failed` warning, the requested reasoned diagnostics and configurable root policy remain unresolved.

## What This Changes

The issue asks OpenClaw to make Telegram reply `MEDIA:` directives for absolute host-local paths outside default media roots either work through a supported policy or fail with clear, documented diagnostics.

## Best Possible Solution

Keep the safe default host-read boundary, scope this issue to reasoned dropped-media diagnostics and user-visible attachment-unavailable feedback, and route persistent root expansion through one security-reviewed filesystem/media-root contract.

## Reproduction Assessment

Yes at source level: absolute local `MEDIA:` paths flow through reply media normalization, `loadWebMedia`, and `assertLocalMediaAllowed`, which rejects paths outside allowed roots and collapses failures to generic feedback. I did not run a live Telegram round trip in this read-only review.

## Solution Assessment

Unclear as a root-expansion fix: diagnostics are a narrow maintainable improvement, but broader absolute-path support should use the single approved filesystem/media-root policy rather than a Telegram-only escape hatch.
