## Summary

Keep open because current main has a policy-gated path for trusted host-local media, but Telegram still drops blocked or missing local `MEDIA:` attachments with only a generic user-visible failure and verbose-only diagnostics; the broader root/config policy overlaps with the open canonical root-policy issue.

## What This Changes

The issue requests that Telegram `MEDIA:` directives for absolute local paths outside the default media roots either work when policy permits the file or fail with actionable diagnostics instead of silently losing the attachment.

## Best Possible Solution

Keep the host-read boundary policy-gated, route configurable root expansion through https://github.com/openclaw/openclaw/issues/47002 or its successor, and make every dropped Telegram `MEDIA:` directive emit an actionable warning code/reason with a maintainer-approved user-visible notice policy.
