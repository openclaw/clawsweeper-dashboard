## Summary

Keep open: current main and v2026.6.11 still enforce the managed-root/file-read boundary for Telegram reply media and only emit generic or verbose failure feedback, while accepting broader absolute host paths remains a security-sensitive config/product decision already overlapping the canonical root-policy work.

## What This Changes

The issue requests clearer and/or configurable handling for Telegram `MEDIA:` directives that reference absolute local paths outside OpenClaw's default media roots.

## Best Possible Solution

Keep the safe host-read boundary, add reason-specific dropped-media diagnostics for Telegram reply media, and route persistent configurable roots through https://github.com/openclaw/openclaw/issues/47002 or the accepted shared filesystem-root contract.
