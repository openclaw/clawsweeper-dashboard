## Summary

Keep open: current main still gates Telegram reply MEDIA local paths through managed or agent-scoped media roots and drops blocked attachments with generic feedback, while configurable root expansion remains an unresolved security/product decision rather than an implemented fix.

## What This Changes

The issue asks for Telegram reply MEDIA directives with absolute local paths outside default allowed media roots to either work through a documented/configurable policy or fail with clearer diagnostics.

## Best Possible Solution

Keep the safe host-read boundary, add clearer Telegram/media failure feedback, and route persistent configurable roots through #47002 or the accepted shared tools.fs.roots design.
