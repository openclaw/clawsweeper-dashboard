## Summary

Keep open: current main still enforces a deliberate host-local media boundary and only surfaces dropped reply media through a generic failure path, while configurable root expansion remains an unresolved security/product decision already tracked by a related open issue.

## What This Changes

The issue asks OpenClaw to make Telegram reply `MEDIA:` local-path failures diagnosable and either document, configure, or align the host-local media root policy.

## Best Possible Solution

Keep the managed-root boundary by default, add reasoned warn-level diagnostics and a clear user-facing dropped-attachment notice for Telegram reply media, and route persistent host-root expansion through the canonical configurable-root decision.
