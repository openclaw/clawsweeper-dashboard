## Label Justifications

- `P2`: The issue affects Telegram outbound media delivery with a bounded but real user impact and requires product/security scoping rather than emergency handling.
- `impact:security`: Allowing additional host-local MEDIA paths changes which local files an agent can cause OpenClaw to read and upload.

## Summary

The issue should stay open because current main still rejects host-local Telegram MEDIA paths outside configured/default media roots, and the remaining fix requires a product/security choice about diagnostics versus a public root-expansion contract.

## What This Changes

The issue requests Telegram outbound MEDIA handling for absolute local paths outside OpenClaw-managed roots, either by allowing trusted roots or by failing with clearer user-visible guidance instead of a generic attachment failure.

## Best Possible Solution

Keep the default host-read boundary, add actionable Telegram/media diagnostics for blocked local MEDIA paths, and route persistent root expansion through the existing security-reviewed root-policy work.
