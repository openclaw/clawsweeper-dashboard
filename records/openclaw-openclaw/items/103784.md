## Label Justifications

- `P1`: A source-confirmed browser workflow race can outlive ordinary stop, reset, delete, reload, and Gateway shutdown operations for real users.
- `impact:crash-loop`: A late managed launch can survive runtime shutdown and leave an OpenClaw-owned browser child orphaned after state teardown.
- `impact:data-loss`: Reset or deletion can move or remove profile state while stale work remains able to publish or recreate browser ownership afterward.

## Summary

Current main still has the reported browser lifecycle race: unpublished managed launches and Chrome MCP work are outside the state observed by stop, reset, deletion, config reconciliation, and shutdown. No related issue, fixing PR, or later lifecycle commit owns the work, so this well-specified bug should remain open for a coordinated browser-plugin refactor.

## What This Changes

Replace fragmented per-profile browser start and cleanup branches with one generation-aware lifecycle actor covering stop, reset, deletion, config reconciliation, and shutdown.

## Best Possible Solution

Make one actor embedded in each `ProfileRuntimeState` the sole owner of lifecycle admission, generation cancellation, same-key start coalescing, terminal state, resource adoption, and serialized cleanup; migrate all existing promise and reconcile paths to it and validate managed, remote, existing-session, extension-relay, hot-reload, and shutdown behavior.

## Maintainer Decision

## Reproduction Assessment

Yes, at high confidence from source: defer `launchOpenClawChrome()`, call stop while `profileState.running` is null, then resolve launch; current main allows handle publication after stop has returned. This read-only review did not execute a runtime reproduction.

## Solution Assessment

Yes. A single per-profile lifecycle actor is the narrowest maintainable solution because all affected transitions mutate the same resource ownership; isolated booleans or route guards miss sibling paths, while a global operation mutex would unnecessarily serialize normal automation.
