## Label Justifications

- `P1`: The issue reports a production Linux gateway outage and repeated systemd restart failures on a stable gateway lifecycle path.
- `impact:crash-loop`: The reported failure mode is a watched gateway restart entering a missing-entrypoint crash loop until systemd stops retrying.

## Summary

Keep open: current main and v2026.6.11 still let `watch-node` signal the healthy gateway child before `run-node` proves the replacement build is ready. The reporter added redacted production logs, and two open PRs are candidate fixes, but neither has merged, so this issue should remain the canonical tracker.

## What This Changes

Fix source-checkout gateway hot reload so a git update or mid-rebuild `dist/` state cannot restart into missing build output and crash-loop the service.

## Best Possible Solution

Land one canonical repair that prepares or validates the current-checkout build before signaling the healthy gateway child, with regression coverage for failed or mid-flight rebuilds.

## Reproduction Assessment

Yes, source-reproducible: current main signals the watched child before `run-node` verifies the replacement build, and the reporter provided redacted systemd logs from the 2026-07-03 outage. I did not run a destructive live systemd/git-update reproduction.

## Solution Assessment

Yes, the right fix layer is the source watch/build restart boundary. The safest shape is transactional build or readiness validation before stopping the healthy child, not a restart-after-failure fallback.
