## Summary

Keep open: current `main` and latest release `v2026.6.11` still restart the watched gateway child without validating replacement `dist/` readiness first, and open linked PRs are candidates rather than merged fixes.

## What This Changes

The issue reports a gateway watch-mode crash loop when a live source checkout hot-reloads while `dist/` is missing or stale during rebuild.

## Best Possible Solution

Keep this issue as the canonical report and land one focused watcher lifecycle fix that validates replacement build readiness before stopping or restarting the healthy gateway child.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Not as a full live systemd/git-update replay in this read-only review; source inspection shows the watcher can signal the child before validating `dist/` readiness, and reporter logs match that failure mode.

## Solution Assessment

Is this the best way to solve the issue? Yes: the maintainable end state is a narrow watcher lifecycle guard aligned with `run-node` build freshness, covering missing entries, stale build stamps, and child-exit restarts.
