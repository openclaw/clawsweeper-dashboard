## What This Changes

The issue reports a production source-checkout hot-reload race where the gateway restarts into a half-built or missing `dist/` tree and crash-loops.

## Best Possible Solution

Land one narrow watch-node/run-node readiness fix that keeps the healthy gateway running until replacement build output and stamp freshness are proven, then close this issue and close or supersede the duplicate candidate PRs.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes for source inspection and reporter-supplied production logs: current watch mode can signal the running child before `run-node` verifies and rebuilds `dist/`, though I did not replay the full systemd outage locally.

## Solution Assessment

Is this the best way to solve the issue? The issue's requested direction is sound, but the best concrete fix should be selected from the open PRs after review: guard the restart boundary so watch mode does not stop a healthy gateway until replacement build output is ready and fresh.
