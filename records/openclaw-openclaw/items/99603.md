## Summary

Keep open: current main and the latest release still stop the watched gateway child before the replacement build is proven ready, and the two linked fix PRs are still open rather than merged.

## What This Changes

The issue asks gateway hot reload from source checkouts to avoid restarting into a half-built or missing `dist/` tree during a git update/rebuild.

## Best Possible Solution

Make source-checkout watch restarts transactional: prepare or validate the replacement build for the current checkout before stopping the healthy gateway child, with regression coverage for missing, stale, and mid-rebuild `dist/` states.

## Reproduction Assessment

Yes, source-reproducible: current main signals the watched child before `run-node` proves or rebuilds the replacement output, and the reporter supplied redacted production logs showing missing `dist` modules and systemd restart exhaustion. I did not run a destructive live systemd/git-update replay.

## Solution Assessment

Yes, the right boundary is the watcher/build lifecycle rather than plugin loading or update install code. The current open PRs are candidate fixes, but the best solution should prepare or validate the replacement build before stopping the healthy child.
