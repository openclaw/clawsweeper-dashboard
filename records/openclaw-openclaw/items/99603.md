## Label Justifications

- `P1`: The report describes a real production gateway outage caused by a source-checkout hot-reload restart loop on a stable gateway lifecycle path.
- `impact:crash-loop`: The failure mode is repeated missing-entrypoint gateway process exits until systemd stops restarting the service.
- `maturity:stable`: The affected Gateway runtime and Linux Gateway host lifecycle surfaces are M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and the latest release still have the source-watch restart ordering that can stop the healthy gateway child before a replacement build is known to have a valid `dist/entry.js`, and the issue now has open closing PR candidates that should be reviewed rather than auto-closing the report.

## What This Changes

The issue asks OpenClaw to prevent source-checkout hot reloads from restarting a systemd-managed gateway into a half-built or missing `dist/` tree.

## Best Possible Solution

Review and land one focused fix that verifies the replacement build and stamp before stopping the healthy gateway child, with regression coverage and live gateway:watch proof, then close this issue as implemented.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes from source inspection and reporter logs: run `gateway:watch` from a source checkout, make `dist/entry.js` missing or stale while a watched source change fires, and the current watcher can signal the healthy child before `run-node` rebuilds.

## Solution Assessment

Is this the best way to solve the issue? Yes: the narrow owner boundary is the watch-node/run-node build-readiness handoff, while a fully atomic build swap would be a stronger follow-up if maintainers want broader hardening.
