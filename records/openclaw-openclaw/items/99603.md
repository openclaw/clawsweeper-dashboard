## Summary

Keep open: current main and the latest release still stop the watched gateway child on relevant source changes without first proving the replacement `dist/` tree is runnable, and this issue already has open candidate PRs that should be reviewed or consolidated before closure.

## What This Changes

The issue asks OpenClaw to prevent source-checkout hot reload from restarting the gateway into a missing or half-built `dist/` tree during git updates or rebuilds.

## Best Possible Solution

Land one canonical watcher lifecycle fix that prepares or verifies the replacement build through the run-node build/runtime-postbuild contract before signaling the healthy gateway child, with regression coverage and redacted live `gateway:watch` proof.

## Reproduction Assessment

Yes for a source-level reproduction path: current main stops the watched child before proving the replacement dist tree is usable, and the reporter supplied redacted production logs showing the missing-entry crash loop. I did not reproduce the full destructive systemd/git-update race live.

## Solution Assessment

Yes, the right fix boundary is the watcher/run-node lifecycle rather than a new product surface. The best implementation should use the canonical build/readiness contract instead of an ad hoc entrypoint-only guard.
