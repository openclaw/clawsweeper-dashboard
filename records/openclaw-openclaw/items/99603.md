## Summary

Keep open: current main still has a plausible source-checkout watcher race where a watched source change stops the running gateway child before the replacement `run-node` child rebuilds and validates `dist/entry.js`. The related closed reports cover adjacent atomic update or missing-entrypoint failures, but I did not find a canonical open item that owns this specific gateway watch/rebuild crash-loop.

## What This Changes

The issue reports that a source-checkout hot reload can restart the gateway while `dist/entry.js` is missing during a git-triggered rebuild, causing a systemd crash loop.

## Best Possible Solution

Fix the source-watch rebuild boundary so a healthy gateway child stays running until replacement build output is complete and loadable, or the restart is refused with clear recovery guidance.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Not as a live reproduction in this read-only pass; source inspection shows the current watch/rebuild ordering can stop the running child before the replacement runner rebuilds and launches.

## Solution Assessment

Is this the best way to solve the issue? Yes, the maintainable fix should be in the source watch/build restart boundary, not in generic config reload or a new config knob.

## Repair Work Prompt

Fix the source-checkout `gateway:watch` rebuild/restart race reported in https://github.com/openclaw/openclaw/issues/99603. The expected behavior is that a watched source/git-head change must not stop a healthy gateway child until the replacement build output is complete and the root `dist/entry.js` entrypoint is present/loadable, or the restart should be refused and the existing child kept alive with clear logs. Keep the fix inside the source watch/build boundary (`scripts/watch-node.mjs` and/or `scripts/run-node.mjs`); do not add a new config/env option, do not change unrelated config hot-reload semantics, and do not edit `CHANGELOG.md`. Add focused regression tests for the ordering, including missing `dist/entry.js` or `git_head_changed` while a gateway child is already running.
