## Summary

Keep open: current main still restarts the watched gateway child without checking whether the replacement `dist/` tree is startable, and the open linked PRs are fix candidates rather than merged implementations.

## What This Changes

Prevent gateway watch hot-reload from restarting a healthy source-checkout gateway into a missing or half-built `dist/` during git updates or rebuilds.

## Best Possible Solution

Land one canonical watcher fix that defers process restart only when run-node readiness says required entry/runtime outputs are physically missing, with focused regression tests and live `gateway:watch` proof.

## Reproduction Assessment

Yes for source-level reproduction: current `watch-node` kills and restarts without a build-readiness guard while `run-node` treats missing `dist/entry.js` as a rebuild condition. I did not rerun the full systemd outage scenario locally.

## Solution Assessment

Yes, the best fix belongs at the watcher restart boundary and should reuse run-node readiness semantics instead of adding an unrelated supervisor workaround. A fully atomic build swap would be broader than needed for this crash-loop unless maintainers choose that as follow-up hardening.
