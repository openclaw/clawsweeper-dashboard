## Summary

Keep open: current main and the latest release still restart the watched gateway child before proving the replacement source-checkout build is ready, and the two open candidate PRs are not merged. ## What This Changes

The issue asks OpenClaw to prevent `gateway:watch` hot reload from restarting a healthy source-checkout gateway into a missing or half-built `dist/` tree after a git update.

## Best Possible Solution

Land one canonical fix that keeps the healthy gateway child running until current-checkout build and runtime artifacts are verified or atomically staged, then close this issue after the fix merges.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes from source and logs: current `watch-node` stops the child before `run-node` proves replacement build readiness, and the reporter supplied redacted systemd logs showing the missing-`dist` crash loop.

## Solution Assessment
