## Summary

Keep open: current main and the latest release still stop the watched gateway child before the replacement `run-node` path has completed a rebuild and then launched a valid entrypoint, so the reported source-checkout hot-reload crash-loop remains a plausible core gateway bug. The adjacent update/install reports and the merged HEAD-change rebuild PR cover related missing-`dist` cases, but none owns this specific watcher restart-into-half-built-tree race.

## What This Changes

The issue asks OpenClaw to make source-checkout gateway hot reload safe when a git update or rebuild temporarily removes `dist/entry.js`, so the gateway does not restart into a broken build and crash-loop.

## Best Possible Solution

Make source-checkout watch restarts transactional: validate or prepare the replacement build before stopping the healthy gateway child, then add regression coverage proving failed or mid-flight rebuilds do not take the gateway down.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Not as a live systemd reproduction in this read-only pass; source inspection shows the current watch/rebuild ordering can stop the running child before the replacement runner rebuilds and launches.

## Solution Assessment

Is this the best way to solve the issue? Yes: the narrow maintainable fix belongs in the source watch/build restart boundary, with atomic staging as a stronger variant if maintainers want to harden rebuild publication too.
