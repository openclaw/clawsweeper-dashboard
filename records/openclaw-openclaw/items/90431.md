## Summary

The current head is a coherent, well-proven implementation with no discrete correctness or security finding, but it intentionally gives existing paired nodes new default-on authority to add model-visible tools and skill instructions. Because this PR has a protected `maintainer` label and that upgrade-sensitive trust policy is not established by code or CI, it should remain open for an explicit maintainer decision.

## What This Changes

Adds node-hosted dynamic plugin tools, declarative MCP servers, and connected-node skills across the gateway protocol, node host, agent inventories, configuration, generated Swift models, documentation, and E2E validation.

## Best Possible Solution

Keep the connection-scoped protocol and native inventory integration, but default node tool and skill publication to off until an operator explicitly enables it, unless maintainers expressly approve pairing as sufficient publication authority for existing installations.
