- `impact:ux-friction`: The missing structured metrics leave live progress cards stuck on textual phase updates, causing avoidable user-facing uncertainty without fully blocking the run.

## Summary

Keep open: current main and the latest release still lack the requested structured progress metrics on the hook payloads, and VISION.md supports plugin API design when current plugin seams are insufficient. This remains a public Plugin SDK/API semantics decision, not stale cleanup.

## What This Changes

Request optional structured progress metrics on `before_tool_call`, `after_tool_call`, and `agent_end` hook payloads so plugins can render numeric live progress cards.

## Best Possible Solution

Define a producer-owned optional progress metric contract in the Plugin SDK, update hook types, runtime producers, docs, and focused tests together, and omit unknown values instead of guessing percentages.

## Reproduction Assessment

Yes, at source-contract level: current hook event types, producers, and docs omit the requested structured progress metric fields. A live Feishu card run is not needed to verify the missing public API field.

## Solution Assessment

Unclear as proposed: enriching hook payloads is plausible, but step totals, percent, ETA, and terminal success/failure semantics need maintainer agreement. The safer shape is producer-owned metrics with absent values when progress is unknown.
