## Summary

Keep open: current main and v2026.6.11 still omit structured numeric progress metrics from the requested plugin hook payloads. Related task-flow and turn-end hook work is adjacent, but it does not define step totals, percent, ETA, or terminal progress semantics for live cards.

## What This Changes

The issue requests optional structured progress metrics such as stepIndex, stepTotal, percent, and etaSec on before_tool_call, after_tool_call, and agent_end hook payloads for plugin live progress cards.

## Best Possible Solution

Define an optional producer-owned progress metrics contract, emit only authoritative values, document unknowns as absent, and test the affected hook producers plus docs/API baselines.

Rationale: This is feasible as an additive Plugin SDK change, but automation should not choose public progress semantics that could make plugin live cards show misleading completion state.

Options:

- **Define a narrow metrics contract (recommended):** Add optional metrics only where a producer has authoritative progress facts, document absent unknowns, and cover each producer with focused tests.
- **Use a separate progress event:** Create a dedicated progress hook/event so tool and terminal hooks remain unchanged and progress can evolve independently.
- **Keep current hooks unchanged:** Leave plugins to render phase/status progress from existing hook events until a stronger runtime progress model exists.
