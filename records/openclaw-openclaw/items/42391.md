## Summary

Keep open: refreshed review against current main and the latest release still shows no structured `metrics` contract on the requested plugin hook payloads, and the remaining question is Plugin SDK/product semantics rather than stale cleanup.

## What This Changes

The issue requests optional structured progress metrics on existing plugin hook payloads so live progress cards can render numeric completion.

## Best Possible Solution

Define optional producer-owned progress metrics in the Plugin SDK, wire them through all authoritative hook producers with tests/docs, and omit unknown values rather than fabricating percentages.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a producer-owned structured progress metrics contract to plugin hook events, and which runtime source owns `stepTotal`, `percent`, ETA, and terminal metrics across supported run paths?

Rationale: The implementation is feasible, but the public Plugin SDK semantics and progress source of truth are product/API decisions that automation should not invent.

Likely owner: vincentkoc

Owner reason: The nearest current-history ownership trail is public hook contract and hook context work, and this decision affects Plugin SDK semantics.

Owner confidence: high

Options:

- **Define a narrow metrics contract (recommended):** Add optional metrics only where the runtime can produce authoritative values, document unknown fields as absent, and cover active producers with focused tests.
- **Keep hooks event-based:** Leave plugins to derive progress from existing lifecycle and tool events, accepting text-only live cards until a stronger progress source exists.
- **Design a separate progress surface:** Create a dedicated progress event or agent-event projection instead of attaching percentages to tool and terminal hooks.

## Reproduction Assessment

Yes. Source inspection against current main reproduces the gap: the hook event types, producers, docs, and latest release omit the requested structured progress metric fields.

## Solution Assessment

Unclear as proposed. Enriching hook payloads is plausible, but step totals, percent, ETA, and terminal success/failure semantics need maintainer agreement; the safer shape is producer-owned metrics with absent values when progress is unknown.
