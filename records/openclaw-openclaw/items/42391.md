## Summary

Keep open: current main and the latest release still omit the requested structured progress metrics from the plugin hook payloads, and related open task-flow hook work does not cover `before_tool_call`, `after_tool_call`, or `agent_end` progress semantics. This remains a public Plugin SDK/product contract decision, not stale cleanup.

## What This Changes

Request to add optional `metrics` fields such as `stepIndex`, `stepTotal`, `percent`, and `etaSec` to existing plugin hook events for live progress-card rendering.

## Best Possible Solution

Define an optional producer-owned progress metrics contract in the Plugin SDK, emit only values the runtime can authoritatively know, update docs/tests across the hook producers, and leave unknown values absent rather than fabricated.

- **Design a separate progress event:** Introduce a dedicated progress event or agent-event projection instead of attaching percentages to tool and terminal hooks.
