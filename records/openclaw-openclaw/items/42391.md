## Summary

Keep open: current main and the latest release still omit the requested structured progress metrics from the public plugin hook payloads, and the Feishu live-card context points to a real UX gap rather than stale cleanup.

## What This Changes

The issue requests optional `metrics` fields on existing `before_tool_call`, `after_tool_call`, and `agent_end` hook payloads so plugins can render numeric live progress cards.

## Best Possible Solution

Define optional producer-owned progress metrics only where OpenClaw has authoritative values, document unknown values as absent, and cover the hook producers plus Plugin SDK docs/tests.

Options:

- **Define a narrow metrics contract (recommended):** Add optional metrics only where the runtime can produce authoritative values, document unknown fields as absent, and cover the relevant producers with focused tests.
- **Keep hooks unchanged:** Leave plugins to derive progress from lifecycle and tool events, accepting text-only or phase-only live cards where numeric progress is unknowable.
- **Design a separate progress event:** Create a dedicated progress event or projection instead of attaching percentages to existing tool and terminal hook payloads.

## Reproduction Assessment

Yes, source-reproducible: current hook types, producers, docs, and the latest release omit the requested structured progress fields. A live Feishu card run is not needed to verify the missing public API contract.

## Solution Assessment

Unclear as proposed: enriching hook payloads is plausible, but step totals, percentages, ETA, and terminal states need maintainer agreement. The safer shape is producer-owned optional metrics with absent values when progress is unknown.

- Adding `metrics` changes public Plugin SDK hook semantics and needs a consistent source of truth across tool and terminal hook producers.
- The Feishu live-card integration proves useful consumer demand, but it does not decide `stepTotal`, ETA, or terminal success/failure percentage semantics.
