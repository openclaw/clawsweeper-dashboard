## Summary

Keep open: current main and the latest stable release still omit the requested structured numeric progress metrics from plugin hook payloads, and the remaining work is a public Plugin SDK semantics decision rather than conservative cleanup.

## What This Changes

The issue requests optional `metrics` fields such as step counts, percent, and ETA on `before_tool_call`, `after_tool_call`, and `agent_end` hook events for plugin-rendered live progress cards.

## Best Possible Solution

Define a producer-owned optional progress metrics contract for plugin hooks, emit only authoritative values, document unknowns as absent, and cover each affected producer with focused SDK/docs tests.

- **Keep phase-only hooks:** Leave plugins to derive textual or phase progress from current tool and lifecycle hooks until a stronger progress source exists.
- **Create a separate progress event:** Design a dedicated progress event or agent-event projection instead of attaching percentages to tool and terminal hook payloads.
