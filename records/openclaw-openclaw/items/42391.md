## Summary

Keep open: current main and v2026.6.11 still do not expose `stepIndex`, `stepTotal`, `percent`, or `etaSec` on the requested plugin hook events, and the remaining work is a public Plugin SDK/product-semantics decision rather than stale cleanup.

## What This Changes

Request optional structured progress metrics on `before_tool_call`, `after_tool_call`, and `agent_end` hook payloads so plugin live cards can render numeric progress.

## Best Possible Solution

Define an optional producer-owned progress metrics contract, emit only authoritative values, document absent unknowns, and cover the affected hook producers with focused tests.

Options:

- **Define Narrow Metrics Contract (recommended):** Add optional metrics only where the runtime has authoritative values, with absent-value semantics and tests across the affected producers.
- **Keep Hooks Phase-Oriented:** Leave plugins to derive progress from existing tool and lifecycle hooks until a stronger source of truth exists.
- **Design Separate Progress Events:** Create a dedicated progress or process-event contract instead of attaching percentages to existing hook payloads.

## Solution Assessment

Unclear as proposed. Enriching existing hook payloads is plausible, but the best maintainable shape needs a producer-owned metrics contract and explicit absent-value semantics before implementation.
