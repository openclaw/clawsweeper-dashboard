## Summary

This issue should stay open: current main still advertises deferred OpenClaw dynamic tools through Codex `tool_search`, and Codex source says those deferred namespace tools should be searchable if they reach the runtime plan, but no current-main proof shows the reported connector-only `tool_search` failure is fixed or superseded by a merged follow-up.

## What This Changes

The issue reports that Codex app-server workers advertise deferred OpenClaw dynamic tools through `tool_search`, but `tool_search` resolves unrelated connector tools instead of OpenClaw session and code-intelligence tools.

## Best Possible Solution

Add a focused Codex app-server tool-surface preflight that proves advertised OpenClaw deferred tools are present in Codex's searchable runtime universe, then either keep them searchable or switch to a clearly tested safe/direct fallback when they are not.
