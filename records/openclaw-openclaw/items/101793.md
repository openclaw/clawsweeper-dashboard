## Summary

Keep open. Current main still has a source-backed path that treats Anthropic pre-tool text as commentary and suppresses it from channel-visible replies, and the linked fix PR is still open rather than merged.

## What This Changes

The issue reports Signal channel dropping assistant text that precedes a tool call in a `toolUse` turn while transcript/replay still treats that text as shared conversation history.

## Best Possible Solution

Land or revise the linked PR so suppressed pre-tool commentary stays private by default but is marked as undelivered in provider replay, with regression coverage for both hidden commentary and visible final replies.

Rationale: Current main has a credible harmful blind spot, but delivering all pre-tool text conflicts with the existing policy that protects messaging channels from internal narration leaks.

Owner confidence: medium

Options:

- **Mark suppressed text undelivered (recommended):** Keep commentary suppression for leak prevention while making provider replay tell the model that the text was not seen by the user.
- **Deliver selected pre-tool text:** Flush only confidently user-facing pre-tool text and add tests proving internal narration still cannot leak to channels.
- **Require explicit message delivery:** Document bare pre-tool text as private and require `message(action=send)` or an equivalent explicit send path for user-visible confirmations.

Unclear until maintainer direction, but the linked undelivered-marker approach is the best current direction because it preserves leak prevention while fixing the false shared-history problem.
