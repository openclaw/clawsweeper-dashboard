## Repair Work Prompt

Fix the shipped leading newline-separated `NO_REPLY` leak reported at https://github.com/openclaw/openclaw/issues/103735. Update the shared silent-token boundary so complete leading tokens separated from subsequent content by whitespace or newlines are removed, while preserving exact-token suppression, trailing-token stripping, glued-prefix handling, custom-token case-insensitivity, and substantive punctuation forms such as `NO_REPLY: explanation`, `NO_REPLY -- nope`, and `NO_REPLY—note`. Apply the same contract to ordinary reply normalization and pending-final/restart delivery. Add focused regression tests for the supplied multiline payload and a short whitespace-separated variant. Do not add configuration, change visible-reply modes, add Telegram-specific production logic, or edit `CHANGELOG.md`.
