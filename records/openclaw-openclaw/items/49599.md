## Summary

Keep open: current main and v2026.6.11 still lack a way to pass custom HTTP headers from shared Gateway CLI commands into the Gateway WebSocket client. The request is source-reproducible and fits remote Gateway operations, but it adds credential-bearing CLI/env/config surface that needs maintainer product and security review before implementation.

## What This Changes

Request support for custom HTTP headers on CLI WebSocket connections to remote gateways via a repeatable flag, environment variable, or remote Gateway config.

## Best Possible Solution

Define one secret-safe Gateway WebSocket header contract in the Gateway client package and `callGateway`, then expose only maintainer-approved CLI/env/config surfaces with redaction, SecretInput/env handling, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: current main has no shared Gateway CLI `--header` option, no header field in `GatewayRpcOpts`, `CallGatewayBaseOptions`, or `GatewayClientOptions`, and no `gateway.remote.headers` schema. I did not run a live Cloudflare Access repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product and security contract. The proposed owner boundary is plausible, but the exact flag/env/config precedence and secret-handling model should be approved before implementation.
