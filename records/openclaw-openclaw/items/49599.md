## Summary

Keep open: current main and v2026.6.11 still lack a supported way for Gateway CLI WebSocket clients to send custom HTTP headers, while the exact implementation PR is closed unmerged.

## What This Changes

Request custom HTTP headers for Gateway CLI WebSocket connections via a repeatable CLI flag, environment variable, and gateway.remote.headers config.

## Best Possible Solution

Define one secret-safe Gateway WebSocket header contract in packages/gateway-client and callGateway, then expose only approved CLI/env/config sources with redaction, SecretInput handling, docs, focused tests, and real proxy proof.
