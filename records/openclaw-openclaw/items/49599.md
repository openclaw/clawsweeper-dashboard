## Summary

Keep open: current main and v2026.6.11 still lack a supported way to pass custom HTTP headers on Gateway CLI WebSocket connections, and the exact implementation attempt is closed unmerged. The source gap is clear, but the requested CLI/env/config surfaces can carry proxy credentials, so this should stay in maintainer product/security review rather than be auto-implemented.

## What This Changes

The issue requests repeatable CLI, environment, and config support for custom HTTP headers on remote Gateway WebSocket connections so CLI commands can work behind authenticating reverse proxies such as Cloudflare Access.

## Best Possible Solution

Define one secret-safe Gateway WebSocket header contract in packages/gateway-client and callGateway, then expose only maintainer-approved CLI/env/config sources with redaction, SecretInput/env handling, docs, and focused tests.
