## Summary

Keep open: current main and the latest release still lack custom-header input and forwarding for shared Gateway CLI WebSocket connections. The need is source-proven and has external operator support, but the requested flag/env/config surfaces can carry credentials and need maintainer product and security review before implementation.

## What This Changes

The issue requests custom HTTP header support for remote Gateway CLI WebSocket connections via a repeatable flag, environment variable, and/or `gateway.remote` config.

## Best Possible Solution

Define one secret-safe Gateway WebSocket header contract in `packages/gateway-client` and `callGateway`, then expose only maintainer-approved CLI/env/config surfaces with redaction, SecretInput/env handling, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: current main exposes no shared Gateway CLI `--header` option, no headers on `GatewayRpcOpts`, `CallGatewayBaseOptions`, or `GatewayClientOptions`, and no `gateway.remote.headers` schema. I did not run a live Cloudflare Access repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product and security contract. The proposed owner boundary is plausible, but the exact flag/env/config precedence and secret-handling model should be approved before implementation.
