## Summary

Keep open: current main and v2026.6.11 still do not expose a supported way for Gateway CLI WebSocket clients to send custom HTTP headers, and the exact implementation PR is closed unmerged. The source gap is clear, but the requested flag/env/config surfaces can carry proxy-auth credentials and need maintainer product/security direction before implementation.

## What This Changes

The issue requests custom HTTP headers for remote Gateway CLI WebSocket connections through a repeatable CLI flag, an environment variable, and/or `gateway.remote.headers` config.

## Best Possible Solution

Define one secret-safe Gateway WebSocket header contract in the gateway-client/call boundary, then expose only maintainer-approved CLI/env/config sources with redaction, SecretInput handling, docs, and focused tests.
