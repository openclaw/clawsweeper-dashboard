## Summary

Keep open: current main and v2026.6.11 still lack custom-header input and forwarding for remote Gateway CLI WebSocket connections. The request is plausible, but it adds credential-bearing CLI/env/config surface and needs maintainer product/security approval before implementation.

## What This Changes

Request support for custom HTTP headers on remote Gateway CLI WebSocket connections via a repeatable flag, environment variable, and config.

## Best Possible Solution

Define one secret-safe Gateway WebSocket header contract in packages/gateway-client and callGateway, then expose only approved CLI/env/config surfaces with redaction, SecretInput/env handling, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: current main exposes no shared Gateway CLI --header option, no headers on GatewayRpcOpts, CallGatewayBaseOptions, or GatewayClientOptions, and no gateway.remote.headers schema. I did not run a live Cloudflare Access repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product and security contract. The proposed threading is plausible, but the exact flag/env/config precedence and secret-handling model should be approved before implementation.
