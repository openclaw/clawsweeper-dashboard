## Summary

Keep open: current `main` and `v2026.6.11` still lack custom-header support for Gateway CLI WebSocket connections, and both related implementation PRs are closed unmerged. The source gap is clear, but the requested CLI/env/config surface can carry credentials and needs maintainer product/security direction before implementation.

## What This Changes

The issue requests custom HTTP headers for remote Gateway CLI WebSocket connections via a repeatable CLI flag, environment variable, and `gateway.remote.headers` config.

## Best Possible Solution

Approve one minimal, secret-safe Gateway custom-header contract owned in `packages/gateway-client` and `src/gateway/call.ts`, then expose only the approved CLI/env/config sources with redaction, docs, and focused tests.
