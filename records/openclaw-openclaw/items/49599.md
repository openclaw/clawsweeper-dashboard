## Summary

Keep open: current main and the latest release still lack a shared Gateway CLI/WebSocket custom-header path. The related implementation PRs are closed unmerged, and the remaining work adds credential-bearing CLI/env/config surface that needs maintainer product and security review before implementation.

## What This Changes

Request custom HTTP header support for remote Gateway CLI WebSocket connections through a repeatable CLI flag, an environment variable, and gateway.remote config.

## Best Possible Solution

Define one secret-safe Gateway WebSocket header contract in packages/gateway-client and callGateway, then expose only approved CLI/env/config inputs with redaction, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: current main exposes no shared Gateway CLI --header option, no header field on GatewayRpcOpts or CallGatewayBaseOptions, no GatewayClientOptions header field, and no gateway.remote.headers schema. I did not run a live Cloudflare Access repro.

## Solution Assessment

Unclear until maintainers approve the product and security contract. The proposed owner boundary is plausible, but the flag/env/config precedence and secret-handling model should be settled first.
