## Summary

Keep open: this identifies a distinct retention-lifecycle gap after the merged per-job cron history cap, and choosing an orphan TTL versus generation/tombstone semantics needs maintainer direction before implementation.

## What This Changes

Add bounded retention for terminal cron task-ledger history whose source job has been deleted, while preserving the 2,000-run cap for existing jobs.

## Best Possible Solution

Define an authoritative-gateway orphan-history policy that retains existing and disabled jobs under the current cap, expires only confirmed deleted-job history after a conservative TTL, previews affected sources and rows, and treats same-ID recreation as continuity unless maintainers explicitly adopt generation tracking.
