## Summary

Current `main` already handles the central case: a non-terminal `agent.wait` timeout returns `accepted` with pending delivery and launches the delayed A2A follow-up, while terminal timeouts remain hard timeouts. This older conflicting branch adds a parallel history-read compensation path that is no longer needed and can weaken the terminal-timeout boundary.

## What This Changes

This PR adds a post-timeout history reread in `sessions_send` to return a late reply or accepted state instead of a timeout after `agent.wait` expires.

## Best Possible Solution

Keep the current delayed-A2A follow-up design, which preserves terminal timeout precedence and returns the canonical pending delivery state without adding a competing compensation read.
