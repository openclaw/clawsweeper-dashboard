## Summary

Keep open. Current main mitigates the direct Google/Gemini tagged-mode trigger and WhatsApp now routes replies through the shared sanitizer, but the shared strict fallback still source-reproduces the unclosed `<think>` plus `<final>` leak shape; the closest repair pull request is closed unmerged, so no current or shipped fix owns the remaining security-sensitive behavior.

## What This Changes

The issue asks to stop Gemini `<think>/<final>` reasoning tags from leaking into WhatsApp replies and to address the shared unclosed-reasoning fallback that can expose private reasoning.

## Best Possible Solution

Have a maintainer choose the strict-mode policy, then implement shared final-only recovery or fail-closed behavior with regression coverage across the shared sanitizer and WhatsApp delivery plus redacted live proof.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: For malformed tagged reasoning that opens `<think>` and later contains a `<final>` block without closing the thinking block, should strict delivery recover only the final content, suppress the payload, or keep the current fallback?

Rationale: The current fallback can expose private reasoning, but changing it affects security and message-loss semantics across all channels that use the shared sanitizer, so automation should not choose the boundary without maintainer intent.

Likely owner: steipete

Owner reason: He has the strongest current history on the shared reasoning/assistant-visible sanitizer boundary.

Owner confidence: high

Options:

- **Recover final-only content (recommended):** Update the shared sanitizer to prefer the later `<final>` body and drop earlier reasoning when strict mode sees an unclosed thinking tag.
- **Fail closed on malformed reasoning:** Suppress the whole malformed payload to avoid leakage, accepting possible empty replies for models that omit closing tags.
- **Keep current fallback:** Leave the current recovery behavior in place and accept the residual risk that malformed tagged output can leak private reasoning.

## Reproduction Assessment

Yes for the shared sanitizer source path, but not as a fresh live WhatsApp/Gemini run. Current code strips `<final>` tag markers before the strict unclosed-`<think>` fallback, so the fallback can return reasoning plus answer instead of final-only text.

## Solution Assessment

No, current main is only a partial solution. The merged direct-Gemini native-mode fix at https://github.com/openclaw/openclaw/pull/89379 reduces one trigger, but the shared strict fallback still needs a maintainer-approved final-only or fail-closed policy.
