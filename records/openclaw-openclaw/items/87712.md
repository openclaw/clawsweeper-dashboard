## Summary

Keep open. Current main mitigates the original direct-Gemini tagged-mode trigger and WhatsApp now routes replies through the shared sanitizer, but the shared strict fallback still returns post-`<think>` text after `<final>` markers are stripped, so the reported malformed-tag leak is not fully implemented away.

## What This Changes

The issue asks OpenClaw to stop Gemini `<think>/<final>` reasoning text from leaking through WhatsApp and related channel delivery after earlier Telegram-only fixes.

## Best Possible Solution

Keep the direct-Gemini native-mode behavior, then tighten the shared strict sanitizer so malformed `<think>` plus `<final>` text cannot return hidden reasoning, with focused tests for shared sanitizer and WhatsApp/history delivery profiles.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: For malformed text that opens `<think>` and contains `<final>` without a closing `</think>`, should strict delivery return only the final body, suppress the payload, or keep the existing recovery fallback?

Rationale: The source-level issue is clear, but the permanent behavior is a security/message-loss boundary shared by all channels and should not be chosen by cleanup automation.

Likely owner: steipete

Owner reason: The fallback behavior and several recent shared sanitizer changes trace to this owner, making them the best available reviewer for strict-mode semantics.

Owner confidence: high

Options:

- **Prefer final body when present (recommended):** Treat `<final>` as the visible boundary for this malformed shape, strip the reasoning prefix, and add regression tests for sanitizer and WhatsApp delivery.
- **Suppress malformed strict payloads:** Return empty text for unclosed `<think>` in strict delivery even when a final tag appears, prioritizing no reasoning leak over answer recovery.
- **Keep current recovery fallback:** Accept the current leak risk to preserve text after malformed open tags, and document the behavior as intentional.

## Reproduction Assessment

Yes for a source-level path: current `stripReasoningTagsFromText()` strips `<final>` markers before the strict unclosed-`<think>` fallback, which can return text after the opener. A fresh live WhatsApp/Gemini current-main run was not established.

Unclear until maintainer intent is set. The shared sanitizer is the right layer for the remaining cross-channel safety net, but strict-mode fallback semantics need a security/message-loss decision before automation changes them.
