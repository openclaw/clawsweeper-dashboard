## Summary

Keep open. Current main and v2026.6.11 mitigate the direct Google/Gemini tagged-mode trigger and keep WhatsApp on the shared sanitizer, but the strict reasoning-tag fallback described in the later comment is still present and can expose post-`<think>` text after `<final>` markers are stripped.

## What This Changes

The issue reports that Gemini `<think>/<final>` reasoning tags can still leak to WhatsApp after the earlier Telegram-only fix, especially with stale WhatsApp plugin versions and unclosed `<think>` fallback behavior.

## Best Possible Solution

Keep direct Google on native reasoning, then harden strict reasoning-tag sanitation so unclosed leading `<think>` cases never expose hidden text and recover only the `<final>` body when that boundary is present, with shared and WhatsApp delivery regressions.

- **Fail closed on malformed reasoning:** Return no visible text for this malformed shape, prioritizing no hidden-reasoning leakage over answer recovery.
- **Keep current fallback:** Accept the current risk that malformed leading reasoning can be delivered when recovering otherwise-empty replies.

## Reproduction Assessment

Yes at source level, but not with a fresh live WhatsApp run. The current strict stripper can return the content after an unclosed `<think>` when `<final>` markers have already been stripped, and WhatsApp delivery uses that sanitizer path.

## Solution Assessment

No, current main is only a partial fix. The direct Google native-mode change reduces the original trigger, but the shared strict fallback still needs maintainer-approved security semantics and regression coverage before this issue can close.
