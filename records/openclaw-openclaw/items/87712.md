## Summary

Keep open. Current main and the latest release mitigate the original direct-Gemini tagged-mode trigger and the Google baseUrl footgun, but the shared strict sanitizer still strips `<final>` boundaries before returning text after an unclosed `<think>` opener, so the security-sensitive unclosed `<think>` plus `<final>` leak path remains source-reproducible.

## What This Changes

The issue asks OpenClaw to stop Gemini `<think>/<final>` reasoning tags from leaking through WhatsApp and related channel delivery paths after the Telegram-only fix.

## Best Possible Solution

Keep the direct-Gemini native-mode mitigation, then land a maintainer-approved shared sanitizer or stream-parser fix for unclosed `<think>` plus `<final>` leakage with WhatsApp and Telegram regression coverage plus live channel proof.
