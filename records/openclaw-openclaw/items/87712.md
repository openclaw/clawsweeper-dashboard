## Summary

Keep open. Current main and v2026.6.11 mitigate the original stale WhatsApp plugin path and the direct Gemini tagged-mode trigger, but the shared strict sanitizer still returns all text after an unclosed reasoning opener after `<final>` markers are stripped, so the cross-channel reasoning leak remains.

## What This Changes

The issue asks OpenClaw to stop Gemini `<think>/<final>` reasoning tags or contents from leaking through WhatsApp and sibling channel delivery after the Telegram-only fix.

## Best Possible Solution

Land a focused shared sanitizer fix that treats `<final>` as the recoverable visible boundary for unclosed reasoning and proves WhatsApp/Telegram delivery, while keeping direct Gemini on native reasoning.
