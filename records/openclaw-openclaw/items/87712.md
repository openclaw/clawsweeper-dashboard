## Summary

Keep open. Current main mitigates the original direct-Gemini tagged-mode trigger, but the shared strict sanitizer still strips `<final>` markers before falling back to all text after an unclosed `<think>` opener, so the security-sensitive channel leak is not fully resolved.

## What This Changes

The issue requests fixing WhatsApp and sibling channel delivery so Gemini `<think>/<final>` reasoning tags, especially unclosed `<think>` plus `<final>` output, are never exposed to users.

## Best Possible Solution

Keep direct Gemini on native reasoning, then make a maintainer-approved shared sanitizer or stream-parser change that never leaks hidden reasoning and preserves final-answer text where that boundary is recoverable, with shared plus WhatsApp/Telegram regression coverage.
