## Summary

Keep open. Current main and v2026.6.11 mitigate the original direct-Gemini tagged-mode trigger and Google baseUrl footgun, but the shared strict sanitizer fallback still can return all text after an unclosed `<think>` opener after `<final>` markers are stripped, so the security-sensitive delivery leak is not fully resolved.

## What This Changes

The issue reports Gemini `<think>/<final>` reasoning text leaking through WhatsApp and later sibling channel delivery when reasoning tags are incomplete or mixed with native thinking.

## Best Possible Solution

Keep the current direct-Gemini native-mode and Google baseUrl fixes, then make a maintainer-approved shared sanitizer or stream-parser change for unclosed `<think>` plus `<final>` payloads with WhatsApp and sibling-channel regression coverage.
