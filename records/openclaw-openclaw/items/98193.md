## Summary

Keep open: current main and the latest release still filter MCP `toolFilter` entries against raw `listTools()` names while `openclaw mcp probe` reports projected namespaced tool names. The linked open PR at https://github.com/openclaw/openclaw/pull/98195 is the active fix candidate, so this issue should remain open until that PR lands or is replaced.

## What This Changes

The issue reports that MCP per-server include/exclude filters copied from probe-visible namespaced tool names can silently remove all tools from that server.

## Best Possible Solution

Review, repair, and land or replace https://github.com/openclaw/openclaw/pull/98195 with a narrow fix that accepts the names users see from probe, preserves raw-name filters, and warns when a non-empty include exposes no tools.

## Reproduction Assessment

Yes. Source inspection shows that current main filters raw `listTools()` names before projection while probe returns projected namespaced names, so a non-empty include list copied from probe can match zero tools without needing the credentialed MotherDuck service.

## Solution Assessment

Yes at the issue level. The narrow maintainable solution is to align filter matching and diagnostics with the probe-visible naming contract while keeping existing raw-name filters working; the linked PR is the current candidate but still needs review/repair before merge.
