## Summary

Keep open: current main and the latest release cover the compaction and memory-flush model override parts, but the normal success-path flush-then-reset mode is still missing and needs maintainer product/security direction.

## What This Changes

Request to add configurable compaction and memory-flush model overrides plus an opt-in mode that resets the session after a successful memory flush instead of compacting.

## Best Possible Solution

Keep the shipped model override behavior and decide a bounded opt-in reset-after-flush/reset-memory lifecycle policy with timeout, dedupe, audit or notice, and security boundaries before implementation.

Rationale: The source gap is clear, but choosing this behavior changes silent model execution, provider routing, session-state retention, and privacy/security semantics, so automation should not choose the permanent policy.

- **Design bounded reset-after-flush (recommended):** Approve an explicit opt-in lifecycle mode with timeout, duplicate-reset protection, durable-memory expectations, user or audit visibility, and security constraints before implementation.
- **Fold into reset-memory policy:** Track the remaining behavior under the open reset-memory issue so reset-time and compaction-time session rotation share one lifecycle contract.
- **Keep compaction as the supported path:** Decline automatic reset-after-flush and keep current model overrides plus compaction/exhaustion recovery as the supported maintenance behavior.
