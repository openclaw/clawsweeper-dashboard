## Summary

Keep open: current main has the compaction and memory-flush model override pieces, but the requested flush-then-reset mode is still absent and needs maintainer product/security direction before implementation.

## What This Changes

This issue requests cheaper model overrides for compaction and memory-flush housekeeping plus a configurable mode that flushes memory and resets instead of compacting.

## Best Possible Solution

Keep the shipped model override knobs, then define one maintainer-approved, default-off reset-after-flush policy aligned with reset-memory lifecycle work, including provider/auth, timeout, notification/audit, and no-reset-on-failed-flush constraints.

Options:

- **Design unified reset-memory policy first (recommended):** Keep this issue open and align compaction-threshold reset mode with reset-time memory work so explicit, daily, idle, and compaction-pressure resets share one bounded policy.
- **Add default-off resetAfterFlush:** Approve a narrow opt-in mode with explicit success criteria, provider/auth behavior, timeout, notification, and regression proof requirements.
- **Reject automatic reset after flush:** Keep compaction as the canonical context-preservation path and rely on model overrides, memory flush, and manual reset flows for cost control.

Unclear. The model override pieces are already solved, but flush-then-reset is only a plausible solution until maintainers choose reset timing, durable-memory sufficiency, provider/auth policy, and user-visible recovery semantics.
