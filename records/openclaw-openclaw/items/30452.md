## Summary

Keep open: current main and v2026.6.11 already cover the compaction and memory-flush model override portions, but the requested successful flush-then-reset mode is still absent and remains a compatibility-sensitive session lifecycle/config decision.

## What This Changes

The issue requests configurable housekeeping models for compaction and memory flush, plus an optional mode that resets the session after a successful memory flush instead of compacting.

## Best Possible Solution

Keep the shipped model override behavior and have maintainers design reset-after-flush as an explicit default-off lifecycle contract with tests for active runs, queues, subagents, transcript archival, channel continuity, and provider/auth routing.

## Reproduction Assessment

Yes for the remaining feature gap by source inspection: current main has no `resetAfterFlush` schema key and the memory-flush path persists metadata instead of resetting after success. This is not a bug reproduction because the item requests a new mode.

## Solution Assessment

Unclear until maintainers define the lifecycle contract; the shipped model overrides are the narrow cost-relief path, while reset-after-flush needs explicit state, safety, and upgrade boundaries.
