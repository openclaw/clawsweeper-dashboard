## Summary

Keep open: current main and v2026.6.11 already cover the compaction and memory-flush model override portions, but the requested successful flush-then-reset mode is still absent and remains a product/security decision.

## What This Changes

The issue requests cheaper configurable models for compaction and memory-flush housekeeping plus an opt-in mode that resets the session after a successful memory flush instead of compacting.

## Best Possible Solution

Keep the shipped model-override behavior and design one explicit opt-in reset-after-flush lifecycle policy, coordinated with the reset-memory lifecycle issue, before implementing the remaining mode.
