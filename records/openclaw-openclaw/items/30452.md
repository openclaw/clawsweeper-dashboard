## Summary

Keep open: current main already covers the compaction model override and memory-flush model override parts, but the requested flush-then-reset mode is still absent from the schema and runtime and needs a maintainer product decision around session-state and provider boundaries.

## What This Changes

The issue requests configurable compaction and memory-flush model overrides plus an optional flush-then-reset mode to reduce housekeeping cost for expensive agent sessions.

## Best Possible Solution

Keep the shipped model override behavior, then make one maintainer-approved reset/flush policy for compaction-threshold recovery that names the session-state, provider/auth, timeout, and user-notification semantics before adding another config knob.

## Reproduction Assessment

Yes for the source-level gap: current main has compaction and memory-flush model overrides, but no `resetAfterFlush` schema key or runtime path that resets after a successful flush. This is a feature request rather than a failing existing-behavior bug.

## Solution Assessment

Unclear: the model override portions are already solved, but flush-then-reset is only a plausible solution until maintainers choose the reset semantics, data-retention threshold, and provider/auth policy. A safer path may be to align it with the reset-lifecycle memory design in https://github.com/openclaw/openclaw/issues/45608 while preserving this compaction-threshold use case.
