## Summary

Keep open: current main and the latest release cover the compaction and memory-flush model override parts, but the requested flush-then-reset mode is still absent and remains a product-sensitive session lifecycle/config decision.

## What This Changes

The issue requests configurable cheaper models for compaction and memory-flush housekeeping plus an opt-in mode that flushes durable memory and resets instead of compacting.

## Best Possible Solution

Keep the shipped model overrides, then add any flush-then-reset behavior only as an explicit opt-in policy with defined resume, failure, provider/auth, and session-state semantics plus focused tests and docs.

## Reproduction Assessment

Yes for the missing capability: source inspection shows strict config support for `memoryFlush.model` but no `resetAfterFlush` or equivalent mode, and repository-wide search found no implementation. This is a feature gap, not a failing bug repro.

## Solution Assessment

No autonomous fix is best yet: the model override portions are already implemented, while the remaining flush-then-reset mode needs maintainer product direction because it changes session lifecycle and recovery semantics. A safe solution should be opt-in, explicit, and tested across flush success, flush failure, reset, compaction, and provider/auth routing.
