## Summary

Keep open: current main and v2026.6.11 already cover the compaction and memory-flush model override parts, but the requested normal success-path flush-then-reset mode is still absent and overlaps, without being fully superseded by, the open reset-memory policy issue.

## What This Changes

The issue requests configurable lower-cost models for compaction and memory flush, plus a flush-then-reset mode that skips compaction after durable memory is written.

## Best Possible Solution

Keep the shipped model-override behavior and make the remaining reset-after-flush behavior part of a maintainer-approved reset lifecycle policy, ideally coordinated with the open pre-reset memory preservation issue.
