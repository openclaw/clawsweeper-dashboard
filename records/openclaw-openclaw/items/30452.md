## Summary

Keep open: current main and the latest release already cover the compaction and memory-flush model override portions, but the requested flush-then-reset mode is still missing and needs maintainer product judgment because it changes session recovery behavior.

## What This Changes

The issue requests configurable housekeeping model overrides for compaction and memory flush, plus an optional mode that flushes durable memory and resets the session instead of compacting.

## Best Possible Solution

Keep the existing model override behavior, and have maintainers decide whether reset-after-flush belongs in core as an explicit session recovery policy with docs, tests, and upgrade-safe defaults.

## Reproduction Assessment

Yes for source-level feature-gap proof, not for a runtime bug: current source and docs show model overrides but no reset-after-flush config or behavior. The remaining request is a new mode rather than broken existing behavior.

## Solution Assessment

Unclear until maintainers decide the policy: the model-override pieces are already solved, but replacing compaction with reset after a flush is not obviously the safest default for all session types.
