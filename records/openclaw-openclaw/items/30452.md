## Summary

Keep open: current main and the latest release implement the compaction model override and memory-flush model override portions, but the requested flush-then-reset mode is still missing and remains a product/config/session-state decision rather than a cleanup close.

## What This Changes

The issue requests cheaper housekeeping controls for compaction and memory flush, including model overrides and an optional mode that flushes durable memory then resets instead of compacting.

## Best Possible Solution

Keep the shipped model overrides, then design a maintainer-approved opt-in reset-after-flush policy that is aligned with reset-lifecycle memory work and has clear config, docs, and session-state tests.

## Reproduction Assessment

Yes, as a source-level capability check: current main exposes `compaction.model` and `memoryFlush.model`, but the strict schema and source search show no `resetAfterFlush` mode. This is a missing feature/config path rather than a broken existing contract.
