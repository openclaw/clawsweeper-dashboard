## Summary

Keep open: current main and v2026.6.11 already cover the compaction and memory-flush model override parts, but the requested success-path flush-then-reset mode is still absent and needs maintainer product/security direction.

## What This Changes

The issue requests cheaper model overrides for compaction and memory-flush housekeeping plus an opt-in mode that resets the session after a successful memory flush instead of compacting.

## Best Possible Solution

Keep the shipped model-override behavior and design any reset-after-flush mode as an explicit, bounded reset-lifecycle policy coordinated with the open pre-reset memory preservation work.
