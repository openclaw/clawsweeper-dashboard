## Summary

## What This Changes

The issue requests cheaper model overrides for compaction and memory flush, plus an optional mode that flushes durable memory and then resets instead of compacting.

## Best Possible Solution

Keep the shipped model override support, then make a maintainer-owned decision on whether successful flush-then-reset belongs in core compaction policy, plugin/session lifecycle APIs, or a narrower linked design.

## Reproduction Assessment

Yes for the remaining capability gap by source inspection: `compaction.model` and `memoryFlush.model` exist, while `resetAfterFlush` or an equivalent reset policy is absent from schema, docs, runtime code, and related searches. This is not a bug reproduction; it is a verified missing feature surface.

## Solution Assessment

Unclear. A reset-after-flush mode may be useful, but the best solution needs maintainer judgment because it changes session lifecycle semantics and overlaps open pre-reset and memory-flush failure recovery work.
