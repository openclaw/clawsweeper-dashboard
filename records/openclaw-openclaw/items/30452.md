## Summary

Keep open: current main and the latest release cover the compaction and memory-flush model override parts, but the requested successful flush-then-reset mode is still absent and remains a product-sensitive session lifecycle/config decision.

## What This Changes

Request to add compaction and memory-flush model overrides plus a memoryFlush.resetAfterFlush mode that skips compaction after a successful durable memory flush.

## Best Possible Solution

Keep the shipped model overrides, then design reset-after-flush as an explicit default-off lifecycle contract coordinated with reset-time memory preservation, transcript archival, queues, subagents, and provider/auth routing.

## Reproduction Assessment

Yes. Source inspection is enough for this feature gap: current main has model override support, but no resetAfterFlush schema/type field and no successful-flush session reset path.

## Solution Assessment

Unclear. The shipped model overrides are the narrow cost-relief path; reset-after-flush may be useful, but maintainers need to define state, safety, and upgrade boundaries before it is the best solution.
