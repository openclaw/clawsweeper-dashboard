## Summary

Keep open: current main and the latest release already cover the compaction and memory-flush model override parts, but the requested flush-then-reset mode is still absent and needs maintainer product judgment because it changes session lifecycle behavior.

## What This Changes

The issue requests cheaper housekeeping controls through `compaction.model`, `memoryFlush.model`, and a `memoryFlush.resetAfterFlush` mode that flushes durable memory and then resets instead of compacting.

## Best Possible Solution

Keep the shipped model override surfaces, and handle the remaining reset-after-flush idea as an explicit opt-in session lifecycle design that is coordinated with https://github.com/openclaw/openclaw/issues/45608 and proven against transcript, tool, subagent, and provider-routing safety.

## Reproduction Assessment

Not applicable as a broken-behavior repro, but yes for a source-level feature gap: current main and the latest release contain the two model overrides, while schema/source/docs have no reset-after-flush mode. I did not run a live long-context agent session because this is read-only review.

## Solution Assessment

Unclear as an implementation direction: model overrides are already solved, but a hard reset after memory flush is not automatically the best or safest continuation strategy. The maintainable path is a maintainer-approved lifecycle design with explicit opt-in, timeout, consent, provider, and recovery semantics.
