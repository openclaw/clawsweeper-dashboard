## Label Justifications

## Summary

Keep open: current main and v2026.6.11 already implement the compaction and memory-flush model override pieces, but the normal success-path flush-then-reset mode is still absent and needs product/security review.

## What This Changes

The issue requests cheaper model overrides for compaction and memory flush plus an optional mode that resets the session after a successful memory flush instead of compacting.

## Best Possible Solution

Keep the shipped model-override behavior and design one explicit reset-after-flush lifecycle policy, coordinated with the open pre-reset memory preservation issue, before implementing the remaining mode.
