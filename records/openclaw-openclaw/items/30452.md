## Summary

Keep open: current main and v2026.6.11 cover the global compaction and memory-flush model override pieces, but there is still no configurable successful flush-then-reset mode that skips compaction.

## What This Changes

Request configurable cheaper model overrides for compaction and memory flush, plus an opt-in memoryFlush reset-after-flush mode that resets the session instead of compacting after a successful flush.

## Best Possible Solution

Keep the shipped model override fields, then decide whether to add an explicit opt-in reset-after-flush lifecycle mode with timeout, sandbox, audit, and success-only reset rules, or fold that policy into the broader reset-memory design.

Rationale: The missing behavior is clear in source, but choosing it affects session continuity, silent tool-capable memory writes, config defaults, provider routing, and security policy; automation should not pick that product boundary.

Likely owner: steipete

Options:

- **Approve a guarded opt-in mode (recommended):** Add a default-off reset-after-flush config with explicit success criteria, timeout/cancel behavior, sandbox limits, audit/logging, and regression coverage for provider/auth routing and session rollover.
- **Keep compaction after flush:** Treat pre-compaction memory flush as a durability aid only, keep compaction as the default recovery step, and close or narrow the reset-after-flush request as not planned.
- **Fold into reset-memory design:** Make https://github.com/openclaw/openclaw/issues/45608 the policy venue for reset-time memory preservation and split only the compaction-threshold trigger if maintainers want a separate implementation.
