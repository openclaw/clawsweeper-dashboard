## Summary

Keep open: current main and the latest release cover the compaction and memory-flush model override portions, but the requested successful flush-then-reset lifecycle mode is still absent and needs maintainer product review before any core config/session behavior is added.

## What This Changes

Requests configurable models for compaction and memory-flush housekeeping plus an opt-in mode that resets the session after a successful memory flush instead of continuing into compaction.

## Best Possible Solution

Keep the shipped model overrides and only add reset-after-flush as a maintainer-approved, default-off lifecycle contract with explicit tests for flush success, flush failure, active queues, subagents, transcript archival, channel continuity, and provider/auth routing.

## Solution Assessment

Unclear until maintainers define the lifecycle contract; the shipped model overrides are the narrow cost-relief path, while reset-after-flush needs explicit state, safety, and upgrade boundaries.
