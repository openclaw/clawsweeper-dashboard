## Summary

Keep open: current main implements the compaction and memoryFlush model override pieces, but it still has no `resetAfterFlush` or equivalent flush-then-reset mode, and that remaining behavior changes session-state and provider-routing semantics.

## What This Changes

The issue requests configurable model overrides for compaction and memory flush, plus a mode that flushes memory and resets the session instead of compacting.

## Best Possible Solution

Record the model override pieces as done, then narrow or split the remaining work around a maintainer-approved reset-after-flush design covering skip-compaction policy, active work safety, provider choice, and user recovery.

## Reproduction Assessment

Yes. Source inspection shows the model override knobs exist, while the strict config schema and runtime/docs search show no `resetAfterFlush` or equivalent reset mode on current main.

## Solution Assessment

Unclear as proposed. Reusing memoryFlush to reset instead of compacting may reduce cost, but it can discard live transcript, tool, and subagent state, so the final shape needs explicit maintainer policy and tests.
