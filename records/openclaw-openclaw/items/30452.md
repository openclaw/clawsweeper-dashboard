## Summary

Keep open: current main and the latest release cover the compaction and memory-flush model override parts, but the requested successful flush-then-reset lifecycle mode is still absent and no related open item fully owns that remaining behavior.

## What This Changes

The issue requests configurable cheaper models for compaction and memory-flush housekeeping plus an opt-in mode that flushes memory and resets instead of compacting.

## Best Possible Solution

Keep the shipped model overrides, then design reset-after-flush as an explicit default-off lifecycle contract with tests for successful flush, failed/aborted flush, queues, subagents, transcript archival, channel continuity, and provider/auth routing.
