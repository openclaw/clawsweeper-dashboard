## Summary

Keep open: current main and the latest release implement the compaction and memory-flush model override parts, but there is still no `memoryFlush.resetAfterFlush` or equivalent flush-then-reset mode. The remaining reset behavior overlaps https://github.com/openclaw/openclaw/issues/45608, but it is not fully superseded because this issue also asks for a threshold-triggered replacement for compaction.

## What This Changes

Request configurable compaction and memory-flush model overrides plus a mode that flushes durable memory and resets instead of compacting.

## Best Possible Solution

Keep the shipped model override support, then design the remaining reset-after-flush behavior alongside the reset-lifecycle memory work in https://github.com/openclaw/openclaw/issues/45608 before adding a new config mode.

## Reproduction Assessment

Yes for source-level verification of the remaining gap: current main exposes `compaction.model` and `memoryFlush.model`, while searches and schema inspection show no `resetAfterFlush` or flush-then-reset mode. I did not run an end-to-end cost or reset scenario in this read-only review.

## Solution Assessment

Unclear: the shipped model overrides are the right narrow solution for housekeeping model cost, but reset-after-flush needs maintainer design because blocking reset, background reset, pre-reset flush, and plugin lifecycle hooks have different state-loss and security tradeoffs.
