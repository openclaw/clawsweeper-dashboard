## Summary

Keep open: the shipped code now covers the compaction and memory-flush model override parts, but the requested successful flush-then-reset lifecycle mode is still absent and needs maintainer product review.

## What This Changes

The issue requests configurable model selection for compaction and memory flush, plus an opt-in memory-flush flow that resets the session instead of compacting after a successful flush.

## Best Possible Solution

Keep the shipped model overrides, then design reset-after-flush as an explicit default-off lifecycle contract with tests for active runs, queues, subagents, transcript archival, channel continuity, and provider/auth routing.

## Reproduction Assessment

Yes for source behavior, but not as a bug reproduction: current main has the model override fields and runtime handling, while targeted searches and the memory-flush path show no resetAfterFlush or successful flush-to-reset mode.

## Solution Assessment

Unclear until maintainers define the lifecycle contract; the shipped model overrides are the narrow cost-relief path, while reset-after-flush needs explicit state, safety, and upgrade boundaries.
