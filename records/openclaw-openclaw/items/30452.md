## Summary

Keep open: current main and the latest stable release cover the compaction and memory-flush model override pieces, but the requested successful flush-then-reset mode is still absent and needs maintainer product review.

## What This Changes

The issue requests configurable cheaper models for compaction and memory flush plus an opt-in flush-then-reset mode that skips compaction after durable memory is written.

## Best Possible Solution

Keep the shipped model overrides, then design reset-after-flush as an explicit default-off lifecycle contract with tests for successful flush, failed or aborted flush, active runs, queues, subagents, transcript archival, channel continuity, and provider/auth routing.

## Reproduction Assessment

Yes for source behavior, not as a bug repro: schema/runtime/docs show the two model overrides, and targeted search plus the memory-flush success path show no resetAfterFlush or flush-then-reset mode.

## Solution Assessment

Unclear until maintainers define the lifecycle contract; the shipped model overrides are a narrow cost-relief path, while reset-after-flush is session-state, safety, and config-sensitive.
