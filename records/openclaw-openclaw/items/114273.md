## What This Changes

The PR caches the gateway’s lazily loaded plugin HTTP and WebSocket handlers so later requests delegate directly to them instead of repeating the wrapper’s plugin-route registry check.

## System Context

The gateway accepts HTTP requests and WebSocket upgrades, then routes plugin traffic through lazy handlers when the active plugin registry exposes routes. This change affects the dispatch wrapper before the plugin HTTP/upgrade handlers perform their own route resolution and response handling.

## Architecture Diagram

flowchart LR

  C -- No --> D[Read active plugin route registry]
  D --> E[Load plugin route handler]
  C -- Yes --> E
  E --> F[Dynamic plugin route resolution]
  F --> G[HTTP response or upgraded socket]

## Best Possible Solution

Retain one lazy import boundary, delegate directly after successful handler creation, and add redacted real-gateway proof that exercises HTTP plus a WebSocket upgrade across the intended active-registry lifecycle.
