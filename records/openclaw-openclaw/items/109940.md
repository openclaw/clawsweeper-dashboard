## Summary

The prior command-failure stdout finding is fixed, but command stdout and stderr are still decoded one arbitrary Buffer chunk at a time before safe tail slicing, so split multibyte UTF-8 input can still become replacement characters.

## What This Changes

The PR exports the shared UTF-8 tail decoder, applies Unicode-safe tail slicing throughout Telegram Crabbox proof diagnostics, and adds boundary regression tests.

## Best Possible Solution

Decode each child stdout and stderr stream statefully with readable.setEncoding("utf8") or a per-stream StringDecoder before applying sliceUtf16Safe, then add a regression that splits an emoji's bytes across two chunks.
