## Summary

## What This Changes

The issue asks OpenClaw to classify Anthropic-shaped unprefixed `invalid_request_error` provider bodies as fallback-worthy format errors so configured model fallbacks are tried.

## Best Possible Solution

Land one narrow fix that classifies structured `invalid_request*` provider bodies after higher-priority reasons, updates result-level fallback behavior if needed, and keeps the thinking-signature root cause tracked separately.

Yes. Source inspection gives a high-confidence path: an assistant error with a raw unprefixed Anthropic JSON `invalid_request_error` body has no inferred status, no matching message classifier branch, and enters the unclassified retry path.
