## What This Changes

The issue requests that unprefixed Anthropic-style `invalid_request_error` JSON bodies classify as failover-worthy `format` errors so configured model fallbacks are attempted.

## Best Possible Solution

Land a narrow classifier fix through the linked PR, with regression coverage for unprefixed structured invalid-request bodies and for the embedded result-payload fallback path.

## Reproduction Assessment

Yes, source-reproducible: current main infers assistant HTTP status only from a leading status prefix, then the unprefixed structured `invalid_request_error` body falls through the message classifier to `null`. I did not run a live provider reproduction in this read-only review.

## Solution Assessment

Yes, the best fix is a narrow classifier change that maps structured `invalid_request` API error types to the existing `format` failover reason after more specific classifications, plus embedded result-payload coverage; creating another fix lane would duplicate the open PR.
