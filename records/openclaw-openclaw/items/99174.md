## Summary

Keep open. Current main still appears to miss the reported unprefixed Anthropic-style `invalid_request_error` body in the failover classifier, so the central user problem is not implemented or superseded.

## What This Changes

Anthropic-shaped invalid-request errors without a leading HTTP status are reported to bypass the configured model fallback chain and surface as terminal provider schema failures.

## Best Possible Solution

Patch the core failover classifier so structured provider schema rejections become fallback-worthy only after higher-specificity classifications are preserved, with focused regression tests around the exact raw Anthropic JSON shape.

## Solution Assessment

Yes, a narrow classifier fix looks like the right layer. It should avoid changing no-body 400 behavior and preserve context-overflow, auth, billing, rate-limit, and model-not-found precedence.
