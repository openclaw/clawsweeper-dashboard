## Summary

Keep open. Current main still lacks a structured `invalid_request_error` failover classification for unprefixed Anthropic-style JSON bodies, and https://github.com/openclaw/openclaw/pull/99184 is an open closing PR that owns the candidate fix.

## What This Changes

The issue reports that unprefixed Anthropic-style JSON `invalid_request_error` 400 bodies are unclassified by failover logic, causing same-model empty-error retries and bypassing configured model fallbacks.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99184 or an equivalent narrow classifier fix, then close this issue once the fix is on main.

## Reproduction Assessment

Yes from source inspection and the issue/PR evidence: the reported raw JSON body has no leading HTTP status and current main has no `invalid_request_error` failover branch. I did not run a live reproduction in this read-only pass.

## Solution Assessment

Yes, a narrow classifier/result-level fallback fix after higher-specificity reasons is the maintainable layer. The open PR is the current candidate, with compatibility review needed because it changes fallback behavior for some schema rejections.
