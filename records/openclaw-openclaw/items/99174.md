## What This Changes

The issue requests classifying unprefixed Anthropic-style `invalid_request_error` JSON bodies as fallback-worthy so configured model fallbacks are consulted.

## Best Possible Solution

Review and land one canonical narrow fix such as https://github.com/openclaw/openclaw/pull/99184, preserving higher-specificity classifications and allowing returned embedded `format` payloads to advance fallback.

## Reproduction Assessment

Yes. Source inspection shows the reported unprefixed JSON body has no leading status, no current structured `invalid_request_error` failover branch, and therefore reaches the same-model empty-error retry path.

## Solution Assessment

Yes. The best repair is a narrow classifier/result-fallback fix in the existing core failover boundary, with tests that preserve context-overflow, auth, billing, rate-limit, and no-body precedence.
