## Summary

Keep open: the patch is still useful and I found no blocking code finding, but merging it intentionally disables ws retained-part security limits for Discord gateway sockets and needs maintainer acceptance plus a clean merge-check state.

## What This Changes

The PR sets `maxBufferedChunks: 0` and `maxFragments: 0` on both Discord gateway WebSocket constructor paths and adds focused tests for the base, monitored, and proxy gateway cases.

## Best Possible Solution

Land the Discord-only receiver-limit override after maintainers accept the trusted-peer tradeoff and current merge checks are green; otherwise replace the two `0` values with maintainer-approved finite caps in the same constructor paths.

## Reproduction Assessment

Yes for the dependency mechanism: current main passes ws 8.21 defaults into Discord gateway sockets, and upstream ws enforces retained-part limits when those values are greater than zero. I did not independently run a full live OpenClaw Discord production repro that forces Discord's original fragmentation pattern.

## Solution Assessment

Yes as a narrow mitigation, subject to maintainer acceptance: the PR changes only the two Discord gateway constructor paths rather than downgrading ws globally or changing unrelated WebSocket users. The safer alternative is maintainer-selected finite caps if disabling the limits is not acceptable.
