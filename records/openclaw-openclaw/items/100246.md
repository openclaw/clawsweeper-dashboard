## Summary

Keep open: current main has pairing, allowlists, gateway/device auth, hook-token transforms, and plugin-owned webhook signature checks, but it does not provide the requested owner-key signed inbound-message gate before agent exposure. The remaining choice is a security-boundary product decision, not conservative cleanup.

## What This Changes

The issue requests an owner-key signed-message gate so channel inputs with invalid signatures are dropped before the agent sees them.

## Best Possible Solution

Prefer plugin-owned or hook-transform signature verification for channel-specific inputs, and add a narrow pre-routing SDK capability only if maintainers decide current hooks cannot keep unsigned content out of agent routing.
