## Summary

Keep open: this PR targets a valid linked auto-reply suppression bug, but the current patch is not mergeable because it can classify ordinary all-letter lead fragments of punctuated custom tokens as silent and drop visible streamed text.

## What This Changes

The PR widens `isSilentReplyPrefixText` and adds unit tests so custom silent tokens containing digits or hyphens can match streamed prefix fragments.

## Best Possible Solution

Make custom-token prefix suppression delimiter-aware or replay-safe: either wait until the prefix includes the token's distinguishing digit/punctuation, or buffer candidate prefixes and re-emit them if later chunks diverge into visible text.

## Reproduction Assessment

Yes. Current main is source-reproducible because `isSilentReplyPrefixText("NO-AN", "NO-ANSWER")` hits the hard-coded fragment character guard, and the PR regression is source-reproducible because `isSilentReplyPrefixText("HE", "HELP-QUIET")` would return true before any distinguishing punctuation appears.

## Solution Assessment

No. The helper-only token-character check is a plausible fix for the reported examples, but it is not the best fix because it reopens the false-positive prefix suppression that the existing underscore guard was designed to prevent.
