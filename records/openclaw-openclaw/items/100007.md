## Summary

Keep open: this PR is a focused fix for the linked custom silent-token prefix bug, and current main plus the latest release still have the hard-coded prefix guard that rejects digits and punctuation. I found no blocking correctness or security findings; this should stay on the normal maintainer review and merge path rather than be cleaned up.

## What This Changes

The branch updates `isSilentReplyPrefixText` to allow custom silent-token prefixes with digits or punctuation once the streamed prefix includes the token's non-letter character, and adds focused regression tests.

## Best Possible Solution

Land this narrow helper and regression-test fix, or an equivalent helper-level change, while keeping silent-token parsing centralized in `src/auto-reply/tokens.ts` instead of adding channel-specific workarounds.

## Reproduction Assessment

Yes. Current main's `isSilentReplyPrefixText` rejects any normalized fragment containing digits or punctuation before checking whether that fragment is a valid prefix of the configured custom token.

## Solution Assessment

Yes. The best fix is to repair the shared helper's prefix rule and cover the token alphabet cases in tests; channel-specific suppression logic would duplicate the same parsing contract.
