## Summary

This PR should stay open, but the current patch is not safe to merge: it assumes the bulk ClawHub endpoint supports `ownerHandle`, while the published endpoint contract accepts unique `{ slug, version }` pairs only and the linked bug report records that adding `ownerHandle` still returned `skill_not_found`. The new regression test proves a mocked contract rather than the actual external behavior, so the original misleading verdict remains unresolved.

## What This Changes

The branch forwards an installed ClawHub skill’s optional owner handle into bulk security-verdict requests and adds gateway regression tests plus terminal-proof artifacts.

## Best Possible Solution

Choose one supported owner-qualified resolution path: land a ClawHub bulk-endpoint contract change with live contract proof, or retain the documented bulk request and add a narrowly specified per-item `/verify` fallback for ambiguous/not-found owner-qualified installs with focused tests.
