- `merge-risk: 🚨 compatibility`: The new universal default changes effective timeout behavior for existing local, self-hosted, custom-provider, and batch configurations.
- `merge-risk: 🚨 availability`: Requests that legitimately need more than 120 seconds can begin failing after merge even though current configuration allows a longer budget.

## Summary

Keep this PR open for a focused repair. The finite hang bound and caller-signal composition address a real current-main availability bug, and the earlier cancellation-signal finding is resolved, but the universal 120-second floor can abort local or self-hosted embedding requests whose established timeout budget is 600 seconds.

## What This Changes

The PR adds a default timeout floor to memory-host remote HTTP requests, composes it with caller cancellation signals, and forwards per-call timeout overrides through `postJson`.

## Best Possible Solution

Keep the finite transport bound and signal composition, but derive or forward each caller's existing provider-specific request budget so hosted requests retain 120 seconds, local/self-hosted requests retain 600 seconds, explicit overrides win, and cancellation-only signals cannot disable the deadline.
