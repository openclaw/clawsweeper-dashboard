## Summary

Keep this PR open. The latest head resolves the prior self-hosted-budget finding by preserving the 600-second local floor, but hosted upload, polling, and download callers still do not select the intended 120-second floor, so their transports can remain active well beyond the established hosted operation budget.

## What This Changes

The PR adds provider-aware timeout constants to memory remote HTTP, composes the timeout with caller cancellation, forwards per-request timeout overrides through JSON POST helpers, and exports the constants through memory SDK barrels.

## Best Possible Solution

Make timeout selection caller-owned: pass the existing 120-second budget from every hosted provider upload, poll, download, and embedding path; preserve 600 seconds for local/self-hosted paths; always compose caller cancellation; and avoid public SDK exports unless an actual cross-boundary consumer requires them.
