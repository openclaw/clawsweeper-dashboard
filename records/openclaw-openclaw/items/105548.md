## Summary

Keep this PR open, but do not merge the reviewed head: the previously reported P1 remains because hosted memory requests still inherit the new 600-second local/self-hosted default instead of the established 120-second hosted budget.

## What This Changes

The branch adds provider-aware default timeouts to memory remote HTTP, forwards timeout overrides through `postJson`, exports the timeout constants through the host and plugin SDK surfaces, and adds hung-response regression coverage.

## Best Possible Solution

Keep a 600-second default only for local and self-hosted embedding paths, explicitly pass `MEMORY_REMOTE_HTTP_TIMEOUT_HOSTED_MS` from every hosted upload, embedding, and status-poll caller, and add caller-level tests proving both timeout tiers and caller cancellation composition.
