## Label Justifications

## Summary

Keep open. The prior hosted-timeout blocker remains on the unchanged reviewed head: hosted OpenAI, Voyage, and Google memory requests still inherit the 600-second local/self-hosted floor instead of the intended 120-second hosted floor.

Likely related people: @vincentkoc (medium confidence, recent ownership around memory remote HTTP) and @neeravmakwana (medium confidence, recent memory embedding timeout work).

## What This Changes

The PR adds provider-aware timeout constants to memory remote HTTP, applies a default local timeout floor, forwards optional overrides through `postJson`, exports the constants through the plugin SDK, and adds hung-response coverage.

## Best Possible Solution

Keep the 600-second default for local and self-hosted endpoints, explicitly pass `MEMORY_REMOTE_HTTP_TIMEOUT_HOSTED_MS` from every hosted provider query, upload, and polling path, and add caller-level tests proving both policy classes.
