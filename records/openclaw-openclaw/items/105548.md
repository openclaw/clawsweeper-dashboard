## Summary

Keep this PR open: the same-head P1 blocker remains because the new 120-second hosted budget is exported but not selected by the production hosted embedding callers, which still inherit the 600-second default.

## What This Changes

Adds provider-aware timeout floors to memory remote HTTP, forwards optional timeout overrides through `postJson`, exports the timeout constants through the plugin SDK, and adds hung-response regression coverage.

## Best Possible Solution

Keep the 600-second compatibility default for local/self-hosted endpoints, explicitly pass the 120-second constant from every hosted query, upload, submit, status-poll, and result-download caller, and test both provider classes at the caller boundary.
