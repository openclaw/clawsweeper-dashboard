## Summary

Keep this PR open: the current head still imposes a 120-second timeout on every remote-memory request, conflicting with the established 600-second budget for local and self-hosted embedding providers and potentially breaking slow but healthy indexing workflows.

## What This Changes

The PR adds a default timeout floor to memory-host remote HTTP requests, composes it with caller cancellation, and forwards per-call timeout overrides through `postJson`.

## Best Possible Solution

Keep one shared hang guard, but derive or propagate the existing provider-specific budget—600 seconds for local/self-hosted providers and 120 seconds for hosted providers—while preserving explicit overrides and composing caller cancellation signals.
