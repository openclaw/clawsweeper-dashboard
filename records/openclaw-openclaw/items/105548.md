## Summary

This PR remains necessary, but the prior P1 blocker is still present at the reviewed head: hosted production callers do not select the new hosted timeout, so they inherit the 600-second local/self-hosted floor instead of receiving the stated 120-second hang bound.

## What This Changes

Adds provider-aware default remote-memory HTTP timeouts, forwards `postJson` timeout overrides, exports the timeout constants through the plugin SDK, and adds hung-response regression coverage.

## Best Possible Solution

Keep timeout selection at the owner boundary: preserve the 600-second local/self-hosted floor, explicitly pass the existing hosted budget from every hosted upload/submit/poll/download path, retain caller-abort composition, and avoid public SDK exports unless an external plugin use case is demonstrated.
