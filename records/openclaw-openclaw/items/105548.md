## Summary

Keep this PR open, but do not merge the current head: the previously reported caller-wiring blocker remains, so known hosted requests inherit the 600-second local timeout instead of their established 120-second budget. The hang reproduction and transport-level fix are convincing; the remaining repair is narrow and mechanical.

## What This Changes

The PR adds provider-aware timeout floors to memory remote HTTP, composes them with caller cancellation, forwards per-request timeout overrides through JSON POST helpers, and exports the timeout constants through memory SDK barrels.

## Best Possible Solution

Retain the 600-second default for unknown and self-hosted endpoints, explicitly pass the 120-second budget from known hosted OpenAI, Voyage, and Google request paths, and use any authoritative remaining configured batch deadline where one already exists, with regression coverage for both policy classes.
