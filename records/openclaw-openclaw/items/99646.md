## Summary

Keep open: current main and v2026.6.11 still build the internal CLI reseed wrapper and import Claude CLI user transcript rows into chat.history without recognizing that wrapper, so the reported fake user bubble remains a valid gateway history bug.

## What This Changes

The issue asks OpenClaw to hide the internal CLI-runner reseed wrapper from user-visible chat history while preserving the actual user message.

## Best Possible Solution

Add a gateway-side CLI-history import/display sanitizer that recognizes OpenClaw reseed envelopes, hides the internal prior-history wrapper, preserves or deduplicates the actual `<next_user_message>` text, and covers it with focused CLI-history tests.

## Reproduction Assessment

Yes at source level: a Claude CLI transcript user row containing the reseed wrapper is parsed and merged into chat.history without marker detection, and current display sanitizers do not strip the wrapper tags. I did not run the full live Claude CLI/iOS reload path in this read-only review.

## Solution Assessment

Yes for the exact leak: gateway-side import/display filtering is the narrowest maintainable fix because it covers iOS, webchat, and any history-API client from one boundary. The fix should avoid changing the model-facing reseed prompt unless maintainers choose a deeper internal-message tagging contract later.
