## Summary

Keep open: current main and v2026.6.11 still build the internal CLI reseed wrapper and import Claude CLI user messages into chat history without recognizing that wrapper, so the reported user-visible fake message remains a valid gateway history bug.

## What This Changes

The issue requests hiding or stripping CLI-runner reseed and related synthetic Claude CLI messages from user-visible chat history while preserving the actual user message.

## Best Possible Solution

Add a gateway-side CLI-history import/display sanitizer that recognizes OpenClaw reseed envelopes, hides the internal prior-history wrapper, preserves or deduplicates the actual `<next_user_message>` text, and covers the behavior with focused CLI-history tests.

## Reproduction Assessment

Yes at source level: a Claude CLI transcript user row containing the reseed wrapper is parsed and merged into chat.history without marker detection, and current display sanitizers do not strip the wrapper tags. I did not run a live Claude CLI/iOS reload scenario in this read-only review.

## Solution Assessment

Yes, the best fix is gateway-side import/display filtering because that covers iOS, webchat, TUI embedded history, and any history-API client from one boundary. The fix should not change the model-facing reseed prompt itself unless maintainers want a deeper internal-message tagging contract later.
