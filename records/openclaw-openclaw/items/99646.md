## Summary

Keep open: current main still builds the internal CLI reseed wrapper and imports Claude CLI user rows into `chat.history` without recognizing that wrapper, and the direct closing fix PR is still open rather than merged.

## What This Changes

The issue reports that internal CLI reseed prompts are imported into chat history and rendered as user-visible messages.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/99653 or an equivalent gateway-side CLI history sanitizer that hides the reseed envelope while preserving the real `<next_user_message>` text.

## Reproduction Assessment

Yes. Current source builds the wrapper as the first CLI prompt and the Claude CLI history importer maps that persisted user entry directly into display history.

## Solution Assessment

Yes for the current fix direction: gateway-side CLI history import filtering is the narrowest boundary because it protects every history API client without changing the model-facing reseed prompt.
