## Summary

Keep open: current main still builds the Claude CLI raw-transcript reseed wrapper and imports persisted Claude CLI user rows into `chat.history` without recognizing that the wrapper is internal prompt scaffolding. The linked open pull request is the active fix candidate, so the issue should stay open until that PR merges or is closed.

## What This Changes

Reported bug where Claude CLI raw-transcript reseed prompts are imported into chat history and rendered as fake user messages instead of showing only the actual next user message.

## Best Possible Solution

Review and land or close https://github.com/openclaw/openclaw/pull/99653; the durable fix should sanitize OpenClaw reseed envelopes at the gateway CLI-history import boundary while leaving broader Claude placeholder lifecycle behavior to its own issues.

## Reproduction Assessment

Yes at source level: a Claude CLI transcript user row containing the reseed wrapper is parsed and merged into `chat.history` without marker detection. I did not run the full live Claude CLI/iOS reload path in this read-only review.

## Solution Assessment

Yes, the linked PR's gateway importer boundary is the narrowest maintainable place to fix the visible leak because it covers iOS, webchat, and any history API client without changing the model-facing reseed prompt.
