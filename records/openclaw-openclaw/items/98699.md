## Summary

Keep this PR open for normal merge review: current main still retypes numeric cron delivery thread IDs on SQLite reload, and the latest head uses the typed `job_json` config to preserve numeric and string identity without changing the SQLite column format. ## What This Changes

The branch changes cron delivery row decoding to recover `threadId` type from `job_json` when a split SQLite thread-id column exists, and adds store tests for numeric and numeric-looking string thread IDs.

## Best Possible Solution

Land the codec read-path fix after focused cron store validation and CI are green, with optional Telegram Desktop proof if maintainers want live transport confirmation.

## Solution Assessment

Yes. Using `job_json` as the typed config source is the narrowest maintainable fix because the writer already persists typed config alongside the split query column, avoiding a schema migration or second encoded column format.
