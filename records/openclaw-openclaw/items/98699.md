## Summary

Keep this PR open for maintainer review: the patch appears correct and well-proven, but it intentionally changes persisted cron row read precedence by treating `job_json.delivery.threadId` as the typed source before the split TEXT column.

## What This Changes

The PR changes cron SQLite delivery decoding to read `delivery.threadId` from typed `job_json` before falling back to the split TEXT column, and adds regression tests for numeric, string, and null-column round trips.

## Best Possible Solution

Land the type-preserving reader after maintainer upgrade-safety review confirms `job_json` is the canonical type source and the split TEXT column remains the legacy fallback.

## Reproduction Assessment

Yes. Current main writes numeric `delivery.threadId` through `String(...)` into a TEXT column and reads it back from that column, and the PR body includes before/after live output through the real store and delivery-plan resolver.

## Solution Assessment

Yes. Using the existing `job_json` config projection preserves string-versus-number identity without parsing ambiguous bare TEXT; a typed schema migration would be heavier for this narrow repair.
