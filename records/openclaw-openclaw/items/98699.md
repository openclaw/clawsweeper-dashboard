## Summary

Keep open for maintainer merge review: the latest patch addresses the prior string-coercion blocker, preserves typed cron thread IDs through the SQLite reader, and I found no blocking correctness or security findings.

## What This Changes

The PR changes the cron SQLite delivery reader to recover `delivery.threadId` from typed `job_json` before falling back to the TEXT split column, and adds cron store regression tests for numeric, string, and null-split-column round trips.

## Best Possible Solution

Land the type-preserving reader after normal maintainer and CI review, keeping `job_json` as the thread-id type source and the split TEXT column as the legacy fallback.

## Reproduction Assessment

Yes. Current main serializes `delivery.threadId` into a TEXT column with `String(...)` and reads it back as text, and the PR body includes before/after live output showing numeric `1008013` loading as string or missing before and as a number after.

## Solution Assessment

Yes. Using the existing `job_json` config projection preserves string-versus-number identity without parsing the ambiguous TEXT column; parsing the split column was the unsafe alternative rejected by the prior review.
