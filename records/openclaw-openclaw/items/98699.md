## Summary

This PR is still necessary: current main and the latest release both read the split TEXT `delivery_thread_id` back as a string, while the patch narrowly recovers the configured `string | number` type from `job_json` and covers the null split-column case. I found no blocking code findings, but the persisted-row compatibility and Telegram topic-delivery implications still need maintainer acceptance before merge.

## What This Changes

The PR changes cron SQLite delivery decoding to recover `delivery.threadId` type from `job_json` before falling back to the split TEXT column, and adds regression tests for numeric, numeric-looking string, same-text, and null-column rows.

## Best Possible Solution

Land the reader-side fix after maintainer compatibility review, keeping the SQLite schema and writer unchanged while using `job_json` only to recover the configured thread ID type.
