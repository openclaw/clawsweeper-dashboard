## Summary

Keep open: the PR fixes a real current-main numeric threadId persistence bug, but the patch guesses type from a TEXT column and can silently change existing numeric-looking string thread IDs after reload.

## What This Changes

The branch converts canonical safe-integer cron delivery thread IDs back to numbers when reading SQLite delivery columns and adds cron store regression tests.

## Best Possible Solution

Preserve original string-vs-number threadId identity across SQLite save/load, preferably by using the typed job_json sidecar when it matches the split column and falling back only for legacy rows without typed config data.

## Reproduction Assessment

Yes from source inspection: current main stores delivery.threadId in a TEXT column with String(...) and deliveryFromRow returns that TEXT value directly, so numeric inputs lose their numeric type after a SQLite round trip. I did not run tests because this review was read-only.

## Solution Assessment

No: the patch fixes the reported numeric case, but inferring type solely from delivery_thread_id is not the safest fix because the split TEXT column cannot distinguish original string "42" from number 42. The better fix should preserve the typed source when available or add typed persistence semantics.
