## Summary

Keep open: the cron persistence bug is real and the codec is the right boundary, but this patch parses every existing bare TEXT `delivery_thread_id` as JSON, so current-release rows with numeric-looking string thread IDs can change type on upgrade.

## What This Changes

The branch JSON-encodes cron delivery `threadId` in the SQLite delivery column, decodes it on load, and adds store tests for numeric and string thread IDs.

## Best Possible Solution

Preserve `threadId` type for new JSON-encoded rows while keeping legacy bare-text rows string-typed unless `job_json` or another explicit marker proves they were numeric.

## Reproduction Assessment

Yes. Source inspection shows current main writes `delivery.threadId` as bare text and the PR head parses that text as JSON on read, which reproduces the remaining upgrade bug for numeric-looking string IDs.

## Solution Assessment

No. JSON-encoding future writes is a good direction, but the read path is not the best fix until it distinguishes new JSON-scalar rows from legacy bare-text rows.
