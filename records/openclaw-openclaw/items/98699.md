## Summary

Keep open: the patch fixes the normal cron SQLite save/load round trip and has useful before/after proof, but it still drops typed numeric thread IDs for early SQLite rows where `job_json` carries the numeric value and `delivery_thread_id` is null.

## What This Changes

The PR changes cron SQLite delivery decoding to recover `delivery.threadId` type from `job_json` and adds store round-trip tests for numeric and numeric-looking string thread IDs.

## Best Possible Solution

Broaden the reader to honor typed `job_json.delivery.threadId` even when the split column is null, add an early SQLite row regression test, then land after focused cron store validation and required CI.

## Reproduction Assessment

Yes. Source inspection shows current main stringifies numeric `delivery.threadId` into a TEXT split column and reads it back as a string; the PR body also includes before/after live output from real SQLite-backed store and delivery-plan calls.

## Solution Assessment

No. Using `job_json` as the type oracle is the right boundary, but the implementation should also consult it when the split thread column is absent so early SQLite rows do not keep losing numeric topic IDs.
