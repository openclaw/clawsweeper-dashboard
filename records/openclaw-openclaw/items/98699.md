## Summary

Keep open: the force-pushed patch now preserves type for newly written rows, but it still parses existing bare-text SQLite thread IDs as JSON numbers, so upgrades can retype or truncate previously string thread IDs.

## What This Changes

The branch changes the cron SQLite delivery codec to JSON-encode `delivery.threadId`, decode it on load, and adds cron store regression tests for numeric and string thread IDs.

## Best Possible Solution

Preserve original string-vs-number identity for both new JSON-encoded rows and legacy bare-text rows, using typed `job_json` or another explicit compatibility marker before parsing legacy text as a number.

## Reproduction Assessment

Yes. Source inspection shows current main writes `delivery.threadId` as bare text and the PR head parses that text as JSON on read, which reproduces the remaining upgrade bug for numeric-looking string IDs.

## Solution Assessment

No. JSON-encoding new writes is a good direction, but the read path must also preserve legacy bare-text string IDs instead of treating every JSON-parseable text value as typed JSON.
