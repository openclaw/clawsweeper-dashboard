## Summary

Keep this PR open for maintainer review: the patch appears to be the narrow bug fix for cron SQLite thread-id type loss, and current main does not already contain it. The remaining concern is an intentional compatibility-sensitive read-semantics change for persisted cron rows, not a contributor-facing code defect.

## What This Changes

The PR changes cron SQLite delivery decoding to recover `delivery.threadId` from typed `job_json` before falling back to `delivery_thread_id`, with store regression tests for numeric, string, and null split-column round trips.

## Best Possible Solution

Land the type-preserving reader after maintainer upgrade-safety review, keeping `job_json` as the thread-id type source and the split TEXT column as the legacy fallback.

## Reproduction Assessment

Yes. Current main's source path writes numeric `threadId` as TEXT and reads it back from that TEXT column, and the PR body includes before/after live output showing the same failure and fix through the real store and delivery-plan resolver.

## Solution Assessment

Yes. Using the existing `job_json` config projection preserves string-versus-number identity without parsing ambiguous bare TEXT; a typed schema migration would be heavier for the same narrow repair.
