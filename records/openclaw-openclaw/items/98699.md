## Summary

Keep open for maintainer review. Current main still reloads numeric cron delivery thread IDs from the split TEXT column as strings, while this PR uses the stored config JSON to preserve string-versus-number identity and covers the current-write and null split-column cases; the remaining concern is accepting the persisted-row read precedence change before merge.

## What This Changes

The PR changes cron SQLite delivery decoding to read `delivery.threadId` from typed `job_json` before falling back to the split `delivery_thread_id` column, and adds focused cron store regression tests.

## Best Possible Solution

Land the type-preserving reader if maintainers accept `job_json` as the cron delivery thread-id type source, with the split TEXT column kept as the legacy fallback.

## Reproduction Assessment

Yes. Source inspection shows current main writes numeric `threadId` values to a TEXT column and reads that TEXT value back into the runtime job, and the PR body provides before/after live output for the same store and delivery-plan path.

## Solution Assessment

Yes. Reading the existing config JSON preserves string-versus-number identity without parsing ambiguous TEXT values, while a typed column or migration would be heavier for this narrow repair.
