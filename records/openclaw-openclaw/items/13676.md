## Summary

Keep open as the canonical product-design request: current main has adjacent sessions, workspaces, capability policy, sandbox constraints, and Workboard functionality, but still lacks a durable Project model, Projects dashboard route, project/session bindings, and a `projects.*` Gateway API. Recent maintainer-connected discussion explicitly retained this broader issue rather than closing it in favor of narrower requests.

## What This Changes

Add a first-class Project model and dashboard experience that binds sessions, workspaces, scoped tools or skills, and runtime constraints.

## Best Possible Solution

Define an additive core Project record with stable identity, metadata, workspace references, a home session and optional workstreams, then expose it through `projects.*` Gateway methods and a focused Control UI list/detail/switching flow; keep capability and runtime constraints informational until a separately reviewed enforcement contract can guarantee the claimed boundary.
