## Label Justifications

- `impact:auth-provider`: The requested behavior concerns how Browser Talk selects speech, TTS, and configured agent-provider paths.

## Summary

This remains a valid product request, not a current regression: Browser Talk is intentionally split from the managed-room `stt-tts` path. Supporting the requested local/split voice loop needs a maintainer choice about adding a browser-managed-room flow rather than loosening `talk.client.create` alone.

## What This Changes

Add a browser Talk path that can use speech-to-text, the configured agent model, and the configured Talk TTS provider instead of requiring a client-owned realtime speech provider.

## System Context

Talk has separate client-owned and Gateway-managed session shapes. Browser realtime negotiation uses a browser-owned provider transport, while `stt-tts` uses a Gateway-managed room that owns turn state and invokes the configured speech and agent paths.

## Architecture Diagram

flowchart LR
  Browser[Browser Talk UI] --> Choice{Talk session shape}
  Choice -->|Client-owned realtime| Realtime[Provider WebRTC or WebSocket]
  Choice -->|Requested local loop| Managed[Gateway-managed room]
  Managed --> STT[Speech-to-text provider]
  STT --> Agent[Configured agent model]
  Agent --> TTS[Configured Talk TTS provider]
  TTS --> Browser

## Best Possible Solution

If browser local/split voice is approved, add a distinct browser-managed-room STT/TTS flow that reuses the existing managed-room lifecycle; otherwise clearly label Browser Talk as realtime-only and separate its controls from native Talk TTS settings.
