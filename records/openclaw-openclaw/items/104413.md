## Summary

Keep open: current main still appears to mishandle an already-final no-route exec approval result for foreground CLI turns, so the documented deny fallback can fail to return a tool error and let the agent continue.

## What This Changes

Fix exec approval handling so an allowlist miss with no reachable approver promptly applies `askFallback=deny` instead of leaving the agent turn blocked until timeout.

## Best Possible Solution

Treat a registration response with `finalDecision: null` as final for every turn type and immediately apply the existing fallback, while returning `approval-pending` only for requests that remain genuinely unresolved.

Yes, at source level with high confidence: the gateway can return a final null decision for no route, but the foreground CLI path can return `approval-pending` instead of applying `askFallback` inline. A live packaged run would provide supplemental confirmation.

## Solution Assessment

Yes. Consuming the gateway's already-final registration result is the narrow owner-boundary fix; adding another timeout or configuration option would leave the lifecycle defect intact.
