## Summary

Keep open: current main and the latest release still route Microsoft Teams channel-thread replies into thread-suffixed sessions, and the requested channel-memory opt-out is a real Teams config/product decision rather than already-implemented behavior.

## What This Changes

The issue requests a supported Microsoft Teams channel/session policy so channel-bound agents can opt out of per-thread session isolation and keep canonical channel memory.

## Best Possible Solution

Keep per-thread isolation as the default, then add a Teams-owned explicit channel-vs-thread session policy with maintainer-approved scope, regression tests, and docs for the session-state tradeoff.

## Reproduction Assessment

Yes, at source level: current Teams channel replies pass the extracted thread id into a helper that appends a `:thread:` session suffix, and current config has no supported opt-out. I did not run a live Teams room reproduction in this read-only review.

## Solution Assessment

Yes to an opt-in Teams-owned policy that preserves per-thread behavior as the default; no to the local hotfix as a final solution because it would globally undo isolation. Maintainers still need to choose the exact schema scope before implementation.
