## Summary

Keep open: current main and v2026.6.11 still force Microsoft Teams channel-thread replies onto thread-suffixed sessions and expose no supported opt-out for channel-bound agents. This remains a real Teams session-state product/config decision rather than a stale duplicate or already-implemented request.

## What This Changes

The issue requests a Teams-owned configuration policy to keep channel-bound Microsoft Teams agents on the canonical channel session instead of always splitting channel thread replies into per-thread sessions.

## Best Possible Solution

Add an opt-in Teams session-routing policy that preserves the current per-thread default while allowing selected channel-bound agents or channels to use canonical channel memory.

## Reproduction Assessment

Yes for a source-level check: current main appends a Teams thread suffix whenever a channel reply has a thread root, and the schema has no opt-out field. No fresh live Teams room was run in this read-only review.

## Solution Assessment

Unclear until maintainers approve the product shape: the proposed per-team/per-channel policy mirrors existing replyStyle precedence, but it creates a new config/session-routing contract that needs an explicit default and upgrade posture.
