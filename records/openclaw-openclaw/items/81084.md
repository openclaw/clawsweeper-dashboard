## Summary

Keep open: current main and v2026.6.11 still force Microsoft Teams channel-thread replies onto thread-suffixed sessions and expose no supported opt-out for channel-bound agents; this remains a valid product/config decision, not a stale duplicate.

## What This Changes

Issue asks for Microsoft Teams channel-bound agents to opt out of per-thread session keys and keep replies in the canonical channel session.

## Best Possible Solution

Add a Teams-owned, opt-in channel/session routing policy that keeps the current per-thread default while allowing selected channel-bound agents or channels to use the canonical channel session.

## Reproduction Assessment

Yes for a source-level behavior check: current Teams channel replies with a thread root deterministically receive a `:thread:<id>` session suffix, while the config schema has no opt-out field. A live Teams production impact was reported, but this review did not run a fresh live Teams room.

## Solution Assessment

Unclear until maintainers approve the product shape: the proposed per-team/per-channel policy matches existing `replyStyle` precedence, but it adds config surface and must preserve the per-thread default.
