## Summary

Keep open: current main and the latest release still route Microsoft Teams channel-thread replies to thread-suffixed sessions, and there is no supported Teams channel-memory opt-out. This remains a real Teams session-state/config product decision, not conservative cleanup.

## What This Changes

Add a Microsoft Teams session-routing policy so selected channel-bound agents can keep channel-thread replies on the canonical channel session instead of per-thread sessions.

## Best Possible Solution

Keep per-thread isolation as the default, then add a Teams-owned explicit channel-vs-thread session policy with focused default/opt-out tests and docs for the memory-boundary tradeoff.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: current Teams channel replies pass conversationMessageId or replyToId into a helper that appends a thread suffix, and no Teams config field can disable it. I did not run a live Teams room reproduction in this read-only review.

## Solution Assessment

Yes in direction: an explicit opt-in Teams policy with per-thread behavior preserved as default is the maintainable solution. The local hotfix is not the best final shape because it globally removes isolation that fixed a real cross-thread bleed bug.
