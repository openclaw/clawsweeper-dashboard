## Summary

Keep open: the branch targets a real native hook relay pressure problem, but current main does not already contain this systemd scoping behavior and the proposed default wrapper can fail before OpenClaw relay policy runs.

## What This Changes

The PR wraps native hook relay commands in `systemd-run --user --scope` with fixed CPU, memory, and task limits on Linux when a user runtime and `systemd-run` path are detected.

## Best Possible Solution

Make systemd scoping opt-in or viability-checked and fail-safe, preserve hook stdin/stdout behavior, and keep the broader relay fan-out decision tied to https://github.com/openclaw/openclaw/issues/91009 and its stronger open fix candidates.

## Solution Assessment

No as submitted: a systemd scope may be a plausible mitigation, but the default path needs viability checks, fail-safe fallback, stdio proof, and real Linux behavior proof before it is the best fix.
