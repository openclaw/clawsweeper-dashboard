## Summary

Keep open: this is a focused draft for a real native hook relay pressure problem, but it is not merge-ready because it changes the default Linux hook command path without proving the systemd scope can start safely and preserve hook stdio.

## What This Changes

The PR wraps native hook relay commands in `systemd-run --user --scope` on Linux when a user runtime and `systemd-run` path are present, adds `OPENCLAW_SYSTEMD_RUN_PATH`, and adds one command-builder test.

## Best Possible Solution

Make any systemd scoping opt-in or viability-checked and fail-safe, preserve hook stdin/stdout behavior, and keep the broader relay fan-out decision tied to https://github.com/openclaw/openclaw/issues/91009 and its stronger open fix candidates.

## Reproduction Assessment

Yes for the PR-introduced defect by source inspection: the wrapper is selected from path presence, and Codex treats nonzero PreToolUse hook exits as failed hook runs without blocking. I did not run a live systemd user-scope failure reproduction.

## Solution Assessment

No as submitted: a systemd scope may be a plausible mitigation, but the default path needs viability checks, fail-safe fallback, stdio proof, and real Linux behavior proof before it is the best fix.
