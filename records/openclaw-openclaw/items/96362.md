## Summary

Keep open: the PR has a concrete native-hook process-isolation idea, but as submitted it can make Linux hook execution fail before OpenClaw’s relay policy runs and it still lacks after-fix real behavior proof.

## What This Changes

The PR wraps native hook relay commands in a Linux user `systemd-run --scope` wrapper with fixed CPU, memory, and task limits when a user runtime is available, and adds one command-builder test plus an env reset in the test cleanup.

## Best Possible Solution

Make the wrapper fail-safe and viability-checked before any default use, or make it an explicit maintainer-approved opt-in while the canonical relay fan-out work remains tracked separately.

## Reproduction Assessment

## Solution Assessment

No as submitted: `systemd-run --scope` is a plausible mitigation, but default-on wrapping needs viability checks, fail-safe fallback, and real Linux proof before it is the best fix.
