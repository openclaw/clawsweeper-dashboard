## Summary

Keep this PR open: it targets a real native hook relay pressure problem, but the proposed default Linux `systemd-run` wrapper can fail before OpenClaw relay policy runs and the external PR still lacks real Linux behavior proof.

## What This Changes

The PR wraps native hook relay commands in a Linux `systemd-run --user --scope` command when a user runtime and `systemd-run` path are detected, adds `OPENCLAW_SYSTEMD_RUN_PATH`, and adds one command-builder test.

## Best Possible Solution

Make systemd scoping opt-in or viability-checked with fail-safe fallback to the original relay command, preserve hook stdin/stdout semantics, and prove both scoped and fallback Linux behavior before merge.

## Reproduction Assessment

Yes for the PR-introduced defect: source inspection shows the wrapper is selected by path presence, and upstream Codex treats ordinary nonzero PreToolUse hook exits as failed hook runs without blocking. I did not run a live systemd user-scope failure reproduction.

## Solution Assessment

No as submitted: a systemd scope may be a plausible mitigation, but the default path needs viability checks, fail-safe fallback, stdio proof, and real Linux behavior proof before it is the best fix.
