## Summary

Keep this PR open: it targets a real native hook relay availability problem, but the branch changes the default Linux relay launcher in a way that can block OpenClaw relay startup before existing fallback policy runs, and it still lacks after-fix real Linux proof. Current main does not already implement this `systemd-run` wrapper, while related open work owns narrower relay fan-out mitigations with safer proof.

## What This Changes

The PR wraps native hook relay commands in `systemd-run --user --scope` on Linux when a user runtime and `systemd-run` path are present, adds `OPENCLAW_SYSTEMD_RUN_PATH`, and adds one command-builder test.

## Best Possible Solution

Make scoped relay execution opt-in or viability-checked with fail-safe fallback to the current direct relay command, then prove it on a real Linux user-runtime setup; otherwise prefer the narrower Codex relay gating work that reduces unnecessary subprocesses without changing the default launcher.

## Reproduction Assessment

Yes for the PR-introduced defect: source inspection shows the wrapper is selected by path presence, and Codex treats nonzero PreToolUse hook exits as failed hook runs without blocking. I did not run a live systemd user-scope failure reproduction.

## Solution Assessment

No as submitted. A systemd scope is a plausible mitigation, but the best fix needs an opt-in or fail-safe launcher path plus real Linux proof that hook stdio, approval behavior, and fallback behavior are preserved.
