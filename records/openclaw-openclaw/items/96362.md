## Summary

Keep open: this draft PR is not implemented on main and is not safely superseded by the open relay fan-out fixes because it proposes a distinct Linux systemd-scope mitigation, but the submitted patch remains unsafe without fail-safe wrapper behavior and real Linux proof.

## What This Changes

The PR wraps Linux native hook relay commands in a constrained `systemd-run --user --scope` command when a user runtime and `systemd-run` path are detected, and adds a command-builder unit test.

## Best Possible Solution

Keep the plain relay command as the default unless the systemd wrapper is made fail-safe or explicitly opt-in with maintainer-approved semantics and redacted Linux proof; otherwise prefer the narrower canonical relay fan-out PRs.

## Reproduction Assessment

Yes for the PR-introduced risk at source level: OpenClaw would select the wrapper by path/runtime presence, and Codex treats failed nonzero hooks as failed hook runs rather than OpenClaw fail-safe relay responses. No live Linux user-scope failure reproduction was run in this read-only review.

## Solution Assessment

No as submitted: systemd scoping is a plausible mitigation, but default activation needs viability checks, fail-safe fallback, or explicit opt-in plus real Linux proof before it is the best fix.
