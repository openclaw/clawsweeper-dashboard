## Summary

Keep open: the branch is a focused but unsafe landing candidate because it changes default Linux native hook execution before the relay's fail-closed responses can run, and the external PR still has no real behavior proof.

## What This Changes

The branch wraps Linux native hook relay commands in a constrained user `systemd-run --scope` when `systemd-run` and `XDG_RUNTIME_DIR` are detected, with a test for the generated command.

## Best Possible Solution

Make scope wrapping fail-safe and viability-checked before default use, or keep the original relay command as the default while maintainers choose the broader relay fan-out design.

## Reproduction Assessment

Yes for the PR-introduced defect: source inspection shows the wrapper is selected by path presence, while upstream Codex treats nonzero PreToolUse hook command exits as failed hooks without blocking. I did not run a live systemd user-scope failure reproduction.

## Solution Assessment

No as submitted: systemd scoping is a plausible mitigation, but default use needs viability checks, fail-safe fallback, and real Linux proof before it is the best fix.
