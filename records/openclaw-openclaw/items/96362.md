- `P1`: The PR targets a real Codex native hook relay pressure problem that can stall gateway workflows, but the submitted fix can also bypass hook policy on Linux wrapper failure.

## Summary

Keep this PR open: current main and the latest release still use the plain native relay command, but this branch changes the default Linux hook command in a compatibility- and security-sensitive path without a fail-safe wrapper or real Linux proof.

## What This Changes

The PR wraps native hook relay commands in `systemd-run --user --scope` on Linux when a user runtime and `systemd-run` path are present, adds an `OPENCLAW_SYSTEMD_RUN_PATH` override, and adds one command-builder unit test.

## Best Possible Solution

Make any systemd scoping opt-in or viability-checked and fail-safe with preserved hook stdio, or let the canonical relay fan-out PRs own the broader fix.

## Reproduction Assessment

Yes for the PR-introduced defect by source inspection: the wrapper is selected before `openclaw hooks relay` runs, and upstream Codex treats nonzero PreToolUse hook exits as failed hook runs without blocking. I did not run a live systemd user-scope failure reproduction.

## Solution Assessment

No as submitted: systemd scoping may be an acceptable mitigation, but it needs opt-in or a fail-safe viability check, stdio preservation proof, and real Linux behavior proof before it is the best fix.
