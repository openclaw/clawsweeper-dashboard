## Summary

Keep open, but not merge-ready: current main does not include this mitigation, and the branch changes default Linux native hook execution in a way that can bypass OpenClaw relay policy if the systemd wrapper fails before the relay starts.

## What This Changes

The PR wraps native hook relay commands in `systemd-run --user --scope` on Linux when a user runtime and `systemd-run` path are present, adds `OPENCLAW_SYSTEMD_RUN_PATH`, and adds a focused command-builder test.

## Best Possible Solution

Make any systemd scoping opt-in or viability-checked and fail-safe, preserve hook stdin/stdout behavior, and keep the canonical relay fan-out decision tied to https://github.com/openclaw/openclaw/issues/91009 and its stronger open fix candidates.

## Reproduction Assessment

Yes for the PR-introduced defect: source inspection shows the wrapper is selected by path presence, and upstream Codex treats nonzero PreToolUse hook exits as failed hook runs without blocking. I did not run a live systemd user-scope failure reproduction.

## Solution Assessment

No as submitted: a systemd scope may be a plausible mitigation, but the default path needs viability checks, fail-safe fallback, stdio proof, and real Linux behavior proof before it is the best fix.
