## Summary

Keep this PR open, but not merge-ready: current main and v2026.6.11 do not include the systemd scoping mitigation, so the branch still contains unique work, but the default Linux wrapper can fail before OpenClaw's relay policy runs and the external PR still lacks real Linux behavior proof.

## What This Changes

The PR wraps native hook relay commands in `systemd-run --user --scope` on Linux when `XDG_RUNTIME_DIR` and a `systemd-run` path are present, adds `OPENCLAW_SYSTEMD_RUN_PATH`, and adds one command-builder test.

## Best Possible Solution

Make any systemd scoping opt-in or viability-checked and fail-safe, preserve hook stdin/stdout behavior, and keep the broader relay fan-out decision tied to the canonical open issue and stronger open fix candidates.

## Reproduction Assessment

Yes for the PR-introduced defect: source inspection shows the wrapper is selected by path presence, and upstream Codex treats ordinary nonzero PreToolUse hook exits as failed hook runs without blocking. I did not run a live systemd user-scope failure reproduction.

## Solution Assessment

No as submitted: a systemd scope may be a plausible mitigation, but the default path needs viability checks, fail-safe fallback, stdio proof, and real Linux behavior proof before it is the best fix.
