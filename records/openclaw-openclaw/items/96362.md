## Label Justifications

- `P1`: The PR targets a real Codex native hook relay pressure problem that can stall gateway workflows, while the submitted fix can bypass hook policy on Linux wrapper failure.
- `merge-risk: 🚨 compatibility`: The diff changes the default Linux native hook command shape whenever a user runtime and `systemd-run` path are detected, and adds an env override.
- `merge-risk: 🚨 security-boundary`: A wrapper failure can prevent OpenClaw PreToolUse or PermissionRequest relay policy from running before Codex continues or falls back.
- `merge-risk: 🚨 availability`: If the constrained user scope or resource properties fail, Linux setups that previously ran the plain relay command can lose native hook relay execution.

## Summary

Keep open: the current head still has the prior P1 blocker where Linux systems can switch to a new systemd wrapper based only on path presence, and the PR still lacks real Linux scoped-relay and fallback proof.

## What This Changes

This PR wraps Linux native hook relay commands in `systemd-run --user --scope` when a user runtime and systemd-run path are detected, adds `OPENCLAW_SYSTEMD_RUN_PATH`, and adds one command-builder test.

## Best Possible Solution

Make systemd scoping opt-in or viability-checked with fail-safe fallback to the original relay command, preserve hook stdin/stdout semantics, and prove both scoped and fallback Linux behavior.
