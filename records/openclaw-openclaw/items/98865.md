## Label Justifications

- `P2`: Backup reliability and archive bloat affect live installations, but the blast radius is bounded to the backup CLI/state archive path.
- `impact:session-state`: The issue concerns volatile live agent/session runtime files that can race backup archive creation and affect restorable session-state archives.

## Summary

Keep open. Current main partially filters live backup state, but it still misses the requested agent runtime cache/shell snapshot and browser-cache classes, and the ENOENT race is only partially covered by an open related PR rather than implemented on main.

## What This Changes

The issue requests that backup archive creation skip volatile agent runtime, browser cache, retired archive, transient files, and tolerate ENOENT races while preserving durable state.

## Best Possible Solution

Fold the ENOENT behavior into the existing backup retry work, then add narrow volatile-filter coverage for disposable agent runtime, shell snapshot, browser cache/resource-cache, retired archive, and transient suffix paths with tests that prove durable state and SQLite snapshots stay included.

## Reproduction Assessment

Yes for source-level reproduction: current main's filter misses several requested path classes and the retry wrapper does not classify ENOENT as retryable. I did not run a live disappearing-file backup race in this read-only checkout.

## Solution Assessment

Yes, if implemented narrowly. The maintainable fix belongs in the existing backup volatile-filter and archiver retry path, while browser exclusions need path-specific coverage so durable profile state is not dropped.
