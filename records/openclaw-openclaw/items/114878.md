## Summary

This remains a useful, narrowly scoped fix for the linked Control UI locale-selection bug. Current main still maps Chinese browser languages through exact `zh-TW`/`zh-HK` equality, so `zh-Hant`, `zh-MO`, and mixed-case tags remain unresolved; the PR moves that decision into the existing locale registry and preserves saved locale preferences. The submitted Chromium proof is sufficient, but the branch needs a rebase onto current main and a resolved `check-test-types` failure before merge.

Likely related people:
- `steipete` — feature introducer (medium confidence); the existing exact-match Chinese locale rule appears to originate with commit `e1f3ded033ea7848d67ed5fbe7c7bf19e4430288`.

## What This Changes

The PR updates Control UI browser-language detection so Traditional Chinese script and region BCP 47 tags select the existing `zh-TW` translation bundle instead of `zh-CN`.

## System Context

During Control UI startup, the i18n manager first honors a saved locale and otherwise resolves `navigator.language` through the locale registry. The registry output determines which lazily loaded translation bundle the UI renders.
