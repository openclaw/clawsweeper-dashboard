## Summary

Keep open. Current main and v2026.6.11 still reset archived Discord thread sessions to stale persisted rows and deliberately preserve external channel/thread session entries; the requested cleanup path remains valid but needs a maintainer product decision before implementation.

## What This Changes

The issue requests automated cleanup or explicit deletion for Discord session entries whose backing Discord threads are archived, deleted, or inaccessible.

## Best Possible Solution

Design a maintainer-approved Discord orphan-session lifecycle with plugin-owned reachability checks, previewable candidates, revalidation before delete, explicit transcript retention, and clear operator or agent permissions.

## Reproduction Assessment

Yes. Source inspection shows archived Discord thread events reset matching session rows to updatedAt: 0, generic maintenance preserves external channel/thread rows, and the agent tool catalog still lacks delete or GC; I did not run a live Discord archive/delete scenario in this read-only review.

## Solution Assessment

Unclear as proposed. The need is valid, but choosing unconditional startup GC, an agent-facing delete tool, or TTL auto-expiry requires maintainer decisions about false positives, permissions, retention, and user-visible recovery.
