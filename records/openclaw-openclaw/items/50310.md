## Summary

Keep open: current main and the latest release still reset archived Discord thread sessions and preserve durable channel/thread rows, so the requested orphan cleanup remains product-sensitive session-state work rather than implemented behavior.

## What This Changes

The issue requests automatic or agent-accessible cleanup of stale Discord thread session records when backing Discord threads are archived, deleted, or inaccessible.

## Best Possible Solution

Design a product-approved Discord orphan lifecycle with previewable candidates, plugin-owned reachability checks, revalidation before deletion, explicit retention rules, and clear admin or agent permissions.

## Reproduction Assessment

Yes. Source inspection provides a high-confidence reproduction path: archived Discord threads call the reset helper, matching session rows are retained with `updatedAt: 0`, and `sessions_list` reads persisted rows; I did not run a live Discord archive/delete scenario in this read-only review.

## Solution Assessment

Unclear as proposed. Startup GC, an agent delete tool, and TTL expiry each make different safety and retention tradeoffs; a preview-first prune flow with plugin-owned reachability checks is the safer maintainable direction.
