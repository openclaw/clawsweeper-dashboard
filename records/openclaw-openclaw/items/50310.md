## Summary

Keep open. Current main still does not prune stale Discord thread session rows from agent-visible session listings: Discord archived-thread handling marks matching rows stale, generic maintenance deliberately preserves durable thread/channel rows, and agent tools do not expose session deletion.

## What This Changes

The issue requests automatic or agent-triggered cleanup of stale Discord thread session entries that remain after backing threads are archived or deleted.

## Best Possible Solution

Define maintainer-approved stale Discord session cleanup semantics, ideally as a preview/apply path with plugin-owned reachability checks, revalidation before delete, and explicit transcript-retention and permission rules.

## Reproduction Assessment

Yes from source inspection: current main exposes agent session listing but not agent deletion, Discord archived-thread handling marks matching rows stale, and generic maintenance protects durable channel/thread rows. I did not run a live Discord deletion scenario in this read-only review.

## Solution Assessment

Unclear. The requested options are plausible, but the best fix needs a maintainer decision on destructive cleanup policy, Discord reachability false positives, transcript retention, and whether agents should be allowed to delete sessions.
