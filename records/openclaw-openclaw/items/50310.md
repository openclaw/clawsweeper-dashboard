## Summary

Keep open. Current main and v2026.6.11 still reset or unbind archived/deleted Discord thread bindings without removing the durable session row, so the agent-visible orphan session problem remains and needs a maintainer product decision before destructive cleanup is added.

## What This Changes

The issue requests automatic or agent-invoked cleanup for stale Discord thread session rows whose backing Discord thread is archived, deleted, or inaccessible.

## Best Possible Solution

Define a preview-first Discord orphan lifecycle with plugin-owned reachability checks, revalidation before delete, explicit transcript retention rules, and clear admin or agent permissions before any destructive cleanup runs.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: archived Discord threads are reset to `updatedAt: 0`, `sessions.list` reads persisted rows, generic cleanup preserves external Discord channel/thread entries, and no model-facing delete/GC tool exists.

## Solution Assessment

Unclear as proposed. Startup GC, a new agent delete tool, and TTL auto-expiry each make different safety, retention, and permission tradeoffs; a preview-first prune flow with plugin-owned reachability and revalidation is the safer product shape.
