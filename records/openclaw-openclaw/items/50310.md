## Summary

Keep open. Current main still resets archived Discord thread sessions by marking rows stale, generic cleanup still preserves durable external conversation rows, and no agent-facing `sessions_delete` or `sessions_gc` tool exists; the remaining work needs a maintainer product decision rather than conservative cleanup closure.

## What This Changes

The issue requests automatic or agent-accessible cleanup of stale Discord thread session entries that remain in `sessions.json` and `sessions_list` after backing threads are archived or deleted.

## Best Possible Solution

Define a maintainer-approved Discord orphan-session lifecycle with plugin-owned reachability checks, previewable candidates, explicit transcript-retention rules, and clear admin or agent permissions before any destructive cleanup runs.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: archived Discord threads reset matching rows to `updatedAt: 0`, `sessions.list` reads persisted rows, and generic cleanup preserves Discord channel/thread rows. I did not run a live Discord archive/delete scenario in this read-only review.

## Solution Assessment

Unclear as proposed: the need is valid, but startup GC, a new agent delete tool, and TTL auto-expiry each make different safety and product tradeoffs. A preview-first prune flow with explicit reachability and retention semantics looks safer than automatic deletion by default.
