## Summary

Keep open. Current main and v2026.6.11 still reset archived Discord thread session rows instead of pruning them; agent-facing tools still lack delete/GC, and generic session cleanup preserves durable channel/thread rows, so the remaining work needs maintainer product decisions.

## What This Changes

Request automatic or agent-operable cleanup of stale Discord thread session rows that remain in `sessions.json` after backing threads are archived or deleted.

## Best Possible Solution

Design a maintainer-approved Discord orphan-session lifecycle with plugin-owned reachability revalidation, previewable delete candidates, explicit transcript retention, and clear operator or agent permissions before destructive cleanup runs.

## Reproduction Assessment

Yes. Source inspection shows archived Discord thread updates call `closeDiscordThreadSessions`, which patches matching persisted rows to `updatedAt: 0` while `sessions_list` continues to read stored session rows; I did not run a live Discord archive/delete scenario in this read-only review.

## Solution Assessment

Unclear as proposed. The need is valid, but unconditional startup GC, an agent-facing delete tool, and TTL auto-expiry each carry different safety and retention tradeoffs; preview-first plugin-owned revalidation looks safer.
