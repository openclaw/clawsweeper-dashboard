## Summary

Keep open: current main still resets Discord thread sessions and preserves durable external conversation rows, but it does not prune stale Discord-backed rows from `sessions_list` or expose an agent-facing delete/GC path.

## What This Changes

The issue requests automatic or agent-accessible cleanup for stale Discord thread session entries left in session listings after backing threads are archived or deleted.

## Best Possible Solution

Define a maintainer-approved Discord stale-session cleanup contract that previews and revalidates candidates, deletes through existing session lifecycle APIs, preserves transcript-retention semantics, and exposes operator or agent control only behind clear permissions.

Options:

- **Plugin-Owned Preview Cleanup (recommended):** Add a Discord-owned reachability check that previews stale candidates, revalidates before deletion, and uses `sessions.delete` lifecycle semantics for cleanup.
- **Dashboard Prune First:** Keep agents read-only and implement the broader explicit Dashboard prune UI/API first so humans approve destructive cleanup.
- **Hide Without Deleting:** Mark unreachable rows in listing or Dashboard output without deleting stored session state, preserving history but leaving cleanup manual.
