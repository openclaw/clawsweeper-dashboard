## Summary

Keep open. Current main has added admin session deletion and cleanup surfaces, but Discord thread archive handling still marks matching session rows stale rather than pruning them, and generic session maintenance deliberately preserves durable channel/thread rows; the remaining cleanup semantics need maintainer product direction.

## What This Changes

The issue requests automatic or agent-driven cleanup of stale Discord thread session entries that remain in persisted session state after backing threads are archived, deleted, or inaccessible.

## Best Possible Solution

Define a Discord-owned prune or doctor flow that safely identifies unreachable thread sessions, previews affected rows, preserves or archives transcript history, and requires explicit operator or maintainer-approved agent permission before deletion.

## Reproduction Assessment

Yes from source inspection: current Discord archive handling sets matching rows to `updatedAt: 0`, and generic session maintenance preserves durable thread/channel rows instead of pruning them. I did not run a live Discord reproduction, but the source path and tests are direct enough for high-confidence source reproduction.

## Solution Assessment

No final solution is selected yet. Startup GC, an agent delete tool, and TTL expiry all need a maintainer decision about Discord false positives, transcript retention, and who is allowed to remove durable session rows.
