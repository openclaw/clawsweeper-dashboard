## Summary

Keep open. Current main and v2026.6.11 still reset archived Discord thread session rows instead of pruning them, generic session maintenance preserves durable channel/thread rows, and the remaining cleanup semantics are product-sensitive rather than an already-implemented fix.

## What This Changes

The issue requests automatic cleanup or agent/operator deletion tooling for stale Discord thread sessions that remain listed after backing Discord threads are archived or deleted.

## Best Possible Solution

Define a maintainer-approved Discord orphan-session lifecycle with plugin-owned reachability checks, previewable candidates, immediate revalidation before deletion, explicit transcript-retention rules, and clear operator or agent permissions.

- **Agent or operator delete tool:** Expose a constrained deletion or GC action with explicit permissions and auditability, without background pruning by default.
- **Keep manual cleanup only:** Decline automatic orphan pruning for now and rely on explicit selected-session deletion or manual repair paths.

## Reproduction Assessment

Yes, at source level. Archived Discord thread updates reset matching session rows to `updatedAt: 0`, `sessions.list` reads preserved non-archived store rows, and current cleanup protects external channel/thread entries; I did not run a live Discord archive/delete scenario in this read-only review.

## Solution Assessment

Unclear as proposed. The need is valid, but unconditional startup GC, an agent-facing delete tool, and TTL auto-expiry have different safety and retention tradeoffs; a preview-first, plugin-owned prune flow looks safer than blind deletion.
