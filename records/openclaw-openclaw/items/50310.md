## Summary

Keep open. Current main and v2026.6.11 still mark archived Discord thread sessions stale rather than pruning their persisted session entries, and generic session maintenance deliberately protects durable channel/thread rows, so the requested cleanup remains product-sensitive work.

## What This Changes

The issue requests an automatic or admin cleanup path for stale Discord-backed session entries left behind after threads are archived or deleted.

## Best Possible Solution

Design a maintainer-approved Discord orphan-session lifecycle with plugin-owned reachability checks, previewable candidates, explicit retention rules, and clear operator or agent permissions before destructive cleanup runs.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: archived Discord thread updates reset matching session rows to `updatedAt: 0`, while `sessions_list` and generic maintenance continue to read and preserve persisted external conversation rows. I did not run a live Discord archive/delete scenario in this read-only review.

## Solution Assessment

Unclear as proposed. The need is valid, but unconditional startup GC, an agent-facing delete tool, and TTL auto-expiry each have different safety and retention tradeoffs; a preview-first prune flow with plugin-owned revalidation looks safer.
