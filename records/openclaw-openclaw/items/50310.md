## Summary

Keep open. Current main and the latest release still reset archived Discord thread sessions and preserve durable external conversation rows rather than pruning orphaned Discord session entries, so the requested cleanup remains real and needs a product/safety decision.

## What This Changes

The issue requests automatic cleanup or explicit deletion of stale Discord-backed session entries after Discord threads are archived, deleted, or become inaccessible.

## Best Possible Solution

Design a product-approved Discord orphan lifecycle with previewable candidates, plugin-owned reachability checks, explicit retention rules, and clear admin or agent permissions before any destructive cleanup runs.

Yes. Unclear as proposed. The need is valid, but startup GC, an agent delete tool, and TTL auto-expiry make different safety tradeoffs; a preview-first prune flow with plugin-owned reachability and explicit permissions is the safer maintainable direction.
