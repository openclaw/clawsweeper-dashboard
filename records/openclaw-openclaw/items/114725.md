Keep this PR open, but it is not ready to merge: the new SQLite read guard removes ownerless claims before the Doctor migration reads cards, so the migration cannot detect or normalize the legacy records it is intended to repair. The revised direction—migration rather than a permanent runtime authorization fallback—is the right boundary, but it needs a raw persisted-state scan plus focused proof. Likely related people: current-main Workboard ownership could not be established from the available read-only history access, so routing confidence is low.

## What This Changes

The PR adds a Workboard Doctor migration intended to normalize legacy stored claims without `ownerId`, and changes SQLite reads to discard those claims from runtime metadata.

## System Context

Workboard stores durable cards and claim state in its plugin-owned SQLite database. Doctor migrations are meant to upgrade persisted state into the current claim schema before Workboard tools and dispatch apply claim authorization rules.
