## Summary

Keep this PR open, but do not merge the current runtime fallback. The reported stuck-card path is plausible and is paired with the open canonical bug report at https://github.com/openclaw/openclaw/issues/114724; however, the branch makes persisted legacy claim data an ongoing runtime authorization format instead of migrating it at the Workboard storage/Doctor boundary. The PR also needs inspectable after-fix runtime proof before merge.

## What This Changes

The PR lets Workboard mutation and dispatch code treat claims lacking modern ownership and expiry fields as releasable by the card’s assigned agent or reclaimable after a longer timeout.

## System Context

Workboard stores durable cards and claim metadata in its plugin-owned SQLite database. Agent tools and dispatch both read a card’s claim to authorize mutations or reclaim stale work, so claim normalization affects every downstream card lifecycle action.

## Architecture Diagram

## Best Possible Solution

Add a Workboard-owned Doctor/migration repair that identifies legacy claims, deterministically normalizes them to the current claim contract or safely clears only claims that cannot be attributed, then keep runtime mutation and dispatch code canonical-only with focused migration and lifecycle regression tests.
