## Summary

Keep open for maintainer review: current main and v2026.6.11 still have unguarded `JSON.stringify` runtime output paths, while this PR applies a lightweight shared non-throwing serializer across the runtime and logger-backed sibling surfaces with focused tests and real-process proof.

## What This Changes

The PR adds a shared `safeJsonOutput` serializer and uses it for runtime, subsystem logger, and plugin SDK logger-backed JSON output, with regression tests for circular and null-prototype values.

## Best Possible Solution

Land this PR or an equivalent fix after maintainer review and required checks, preserving the lightweight shared serializer and coverage for circular and primitive-conversion failure paths.

## Reproduction Assessment

Yes. Source inspection shows current main passes unknown runtime output values directly to `JSON.stringify` in runtime, plugin SDK logger, and subsystem logger paths, which throws synchronously for circular object graphs; I did not run local tests in this read-only review.

## Solution Assessment

Yes. The latest shape is the narrow maintainable fix: it keeps the serializer in a lightweight utility, shares it across all three runtime output surfaces, and avoids the earlier full-runtime SDK import concern.
