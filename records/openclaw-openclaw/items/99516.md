## Summary

Keep open: the crash is real and the submitted behavior proof is useful, but the current helper location creates a plugin SDK boundary problem because a public compatibility subpath gains a value import of the full runtime module.

## What This Changes

The PR adds a non-throwing JSON output serializer and applies it to runtime, plugin SDK, and subsystem logger JSON output paths, with circular-value regression tests.

## Best Possible Solution

Keep the non-throwing serializer behavior, but move or reuse it in a lightweight utility so runtime, subsystem logging, and plugin SDK logger adapters can share it without broadening SDK module coupling.

## Reproduction Assessment

Yes. Current main directly stringifies unknown output values in runtime and logger-backed adapters, and circular values throw synchronously; the related PR review also documented the null-prototype fallback failure for the earlier mitigation.

## Solution Assessment

No. The fallback behavior is the right direction, but the helper should live in a lightweight shared utility or have explicit maintainer approval before changing the plugin SDK runtime-logger dependency graph.
