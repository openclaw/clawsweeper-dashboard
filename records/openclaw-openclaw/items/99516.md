## Summary

Keep open: the PR is a useful repair of the default runtime and plugin SDK logger path, but it is not merge-ready because a sibling logger-backed runtime still has the same unguarded JSON output failure.

## What This Changes

The PR adds a shared non-throwing JSON output helper and uses it from runtime output and the logger-backed plugin SDK runtime, with regression tests for circular values.

## Best Possible Solution

Use one non-throwing runtime JSON serializer across every `OutputRuntimeEnv.writeJson` implementation and cover the default, plugin SDK logger, and subsystem logger runtimes with focused tests.

## Reproduction Assessment

Yes from source. Current main directly stringifies unknown runtime JSON values, and a focused Node probe confirms circular values can throw before output is written.

## Solution Assessment

No. The helper shape is reasonable, but the patch is one-sided because `runtimeForLogger` still implements `OutputRuntimeEnv.writeJson` with direct `JSON.stringify` and is passed to gateway/channel runtime hooks.
