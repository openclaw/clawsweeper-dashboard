## Summary

Keep this PR open, but it is not merge-ready: current main and the latest release still have the unguarded runtime JSON path, while this patch catches output-sink failures as if they were serialization failures and leaves the exported logger-backed plugin SDK runtime on the same raw `JSON.stringify` surface.

## What This Changes

The PR wraps runtime JSON output serialization in fallback try/catch blocks and replaces the runtime helper tests with circular-value coverage.

## Best Possible Solution

Use one non-throwing runtime JSON serializer, compute the serialized string before calling stdout/logger sinks, and share that helper with the logger-backed plugin SDK runtime or explicitly test the intended boundary.

## Reproduction Assessment

Yes. Source inspection shows current main stringifies unknown runtime JSON values directly, and a circular object would throw before the output path can complete.

## Solution Assessment

No. The PR is a useful direction, but the best fix separates serialization fallback from output-sink failures and keeps the `OutputRuntimeEnv.writeJson` invariant aligned across sibling runtime implementations.

Full review comments:

- **[P2] Keep write failures out of the stringify fallback:** `src/runtime.ts:85`
  - body: This guard catches `writeStdout(...)` failures as well as `JSON.stringify` failures. `writeStdout` already swallows `EPIPE` and `EIO` and rethrows other write errors, but after this patch a non-pipe stdout failure can be converted into a fallback JSON write; compute the serialized string inside the guard, then call the output sink outside it.
  - confidence: 0.9
- **[P2] Share the JSON guard with logger-backed runtimes:** `src/runtime.ts:85`
  - body: `writeRuntimeJson` delegates to any `OutputRuntimeEnv.writeJson`, but the exported logger-backed runtime in `src/plugin-sdk/runtime-logger.ts` still stringifies directly. A plugin or monitor using that runtime can still crash on the same circular output, so move the fallback serializer into a shared helper or explicitly keep this PR scoped to the default stdout runtime with tests proving the boundary.
  - confidence: 0.84
