## Summary

Keep open. Current main and the latest release still have unguarded runtime JSON output paths, while this PR now addresses the earlier review blocker by sharing a lightweight non-throwing serializer across runtime, subsystem logging, and the plugin SDK logger adapter.

## What This Changes

The PR adds `safeJsonOutput` in `src/utils/safe-json.ts` and uses it for runtime, subsystem logger, and plugin SDK logger-backed JSON output serialization.

## Best Possible Solution

Land this PR or an equivalent fix after normal maintainer review and required checks, keeping the serializer in the lightweight utility module with coverage for ordinary circular and primitive-conversion failure cases.

## Reproduction Assessment

Yes. Source inspection shows current main passes unknown runtime output values directly to `JSON.stringify`, and JavaScript throws synchronously for circular object graphs; I did not run local tests because this review is read-only.

## Solution Assessment

Yes. The latest shape is the narrow maintainable fix: it preserves normal JSON output, adds a non-throwing fallback, and shares it from a lightweight utility rather than broadening the plugin SDK logger dependency graph.
