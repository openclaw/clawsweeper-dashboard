## Summary

Keep open: current main still has the circular JSON output crash, and this PR is a useful improvement over https://github.com/openclaw/openclaw/pull/99490, but the patch is not merge-ready because it catches output-sink failures as serialization failures and leaves an exported logger-backed runtime with the same direct stringify behavior.

## What This Changes

The PR changes `src/runtime.ts` and `src/runtime.test.ts` to add fallback JSON serialization for circular runtime output values and tests for ordinary circular and null-prototype circular cases.

## Best Possible Solution

Move the non-throwing serialization into a small shared helper, call stdout/logger sinks only after serialization has succeeded or fallen back, and apply or explicitly scope the same behavior for exported logger-backed runtimes.

## Reproduction Assessment

Yes. Source inspection shows current main stringifies unknown runtime JSON values directly, and a focused JavaScript probe confirms circular values throw before output is written.

## Solution Assessment

No. The PR is a good direction, but the best fix separates serialization fallback from output-sink failures and avoids splitting the `OutputRuntimeEnv.writeJson` invariant across implementations.

## Review Findings

Overall correctness: patch is incorrect

Full review comments:

- **[P2] Keep write failures out of the stringify fallback:** `src/runtime.ts:85`
  - body: This guard catches `writeStdout(...)` failures as well as `JSON.stringify` failures. `writeStdout` already swallows `EPIPE`/`EIO` and rethrows other write errors, but after this patch a non-pipe stdout failure can be converted into a fallback JSON write; compute the serialized string inside the guard, then call the output sink outside it.
  - confidence: 0.9
- **[P2] Share the guard with logger-backed runtimes:** `src/runtime.ts:84-85`
  - body: `writeRuntimeJson` delegates to any `OutputRuntimeEnv.writeJson`, but the exported logger-backed runtime in `src/plugin-sdk/runtime-logger.ts` still stringifies directly. A plugin or monitor using that runtime can still crash on the same circular output, so move the fallback serializer into a shared helper or explicitly keep this PR scoped to default stdout runtime with tests proving the boundary.
  - confidence: 0.84
