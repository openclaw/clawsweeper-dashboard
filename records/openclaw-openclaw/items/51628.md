- `impact:message-loss`: The reported recovery path can duplicate outbound Telegram messages or avoid replaying uncertain deliveries depending on the chosen recovery policy.

## Summary

Current main has durable guards for newly marked outbound sends and current Telegram transcript mirror idempotency, but the issue's legacy upgrade case remains: old Telegram delivery-queue JSON rows with ambiguous post-send `sendMessage` failures still migrate as pending rows without inferred unsafe recovery state, so the central duplicate replay risk is not fully fixed.

## What This Changes

The issue asks OpenClaw to prevent Telegram delivery queue recovery from replaying old ambiguous `sendMessage` replies and duplicating `delivery-mirror` transcript entries.

## Best Possible Solution

Add a doctor/state-migration or recovery rule that treats legacy Telegram pending rows with ambiguous post-send `sendMessage` errors as unsafe to replay, with focused tests that preserve current marked-row recovery and transcript mirror idempotency.
