## Summary

Keep open: current main protects newly marked post-send recovery rows and now scans stable mirror idempotency keys, but legacy delivery-queue JSON rows can still migrate/load with null `recovery_state`, bypass the marker-gated replay guard, and remain a real upgrade-policy gap.

## What This Changes

The issue asks OpenClaw to prevent ambiguous Telegram `sendMessage` recovery replays from duplicating visible replies and `delivery-mirror` transcript entries.

## Best Possible Solution

Classify, quarantine, or migrate legacy Telegram delivery-queue rows with missing `recoveryState`, then add restart-replay coverage proving no blind Telegram send replay and no duplicate delivery-mirror append.
