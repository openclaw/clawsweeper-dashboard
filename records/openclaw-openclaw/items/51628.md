## Summary

Keep open: current main protects newly marked ambiguous outbound sends and now dedupes Telegram transcript mirrors, but legacy pending Telegram delivery-queue rows can still migrate with no replay-safe recovery state and bypass the no-blind-replay guard.

## What This Changes

Telegram delivery queue recovery can replay old ambiguous sendMessage replies and duplicate delivery-mirror transcript entries.

## Best Possible Solution

Choose an upgrade policy for legacy ambiguous Telegram queue rows, then migrate, quarantine, or mark them unknown before recovery so startup never blindly resends non-idempotent sendMessage replies.

## Solution Assessment

Current main is the right direction for new sends, but the issue is not fully solved until legacy migrated rows get an explicit replay-safe upgrade policy and regression proof.
