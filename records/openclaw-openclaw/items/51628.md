## Summary

Keep open: current main fixes newly marked post-send recovery entries, but legacy Telegram delivery-queue rows imported without `recoveryState` still bypass the no-blind-replay guard and can reach recovery replay.

## What This Changes

The issue asks OpenClaw to stop Telegram delivery-queue recovery from replaying old ambiguous `sendMessage` replies and duplicating `delivery-mirror` transcript entries.

## Best Possible Solution

Keep this issue open until legacy Telegram queue rows are classified, quarantined, or migrated into a recovery state with regression coverage for no blind replay and transcript mirror dedupe.

## Reproduction Assessment

Yes at source level: a legacy Telegram queued delivery with network `lastError` and no `recoveryState` can migrate with null recovery state, inflate without `recoveryState`, bypass the guard, and reach recovery replay.
