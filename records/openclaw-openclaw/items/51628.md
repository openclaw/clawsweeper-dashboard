## Summary

Keep open: current main protects newly marked post-send queue states, but the reported legacy Telegram queue-row path can still import without recovery state and bypass the no-blind-replay guard.

## What This Changes

The issue requests a fix for Telegram delivery-queue recovery replaying old ambiguous sendMessage replies and adding duplicate delivery-mirror transcript entries.

## Best Possible Solution

Keep this issue open until legacy Telegram queue rows are classified, quarantined, or migrated with recovery state, with regression coverage for recovery replay and transcript mirror idempotency.

## Reproduction Assessment

Yes. Source inspection shows a migrated legacy Telegram queued delivery with network `lastError` and no `recoveryState` can remain unmarked, bypass the unknown-send guard, and reach the recovery delivery path; no live Telegram replay was run in this read-only review.

## Solution Assessment

No for closing. Current main fixes newer marked post-send states, and https://github.com/openclaw/openclaw/pull/87552 covers adjacent marked ambiguous recovery policy, but neither fully handles old unmarked Telegram queue rows from shipped releases.
