## Summary

Keep open: current main hardens newly marked post-send recovery rows and Telegram mirror idempotency, but legacy delivery-queue JSON rows can still migrate with null `recovery_state`, inflate without `recoveryState`, and bypass the replay guard.

## What This Changes

Request to stop Telegram delivery queue recovery from replaying ambiguous failed `sendMessage` replies and appending duplicate delivery-mirror transcript entries.

## Best Possible Solution

Classify, quarantine, or migrate legacy Telegram delivery-queue rows with missing `recoveryState`, then add restart-replay coverage proving no blind Telegram send replay and no duplicate delivery-mirror append.
