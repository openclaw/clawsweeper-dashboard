## Label Justifications

- `P1`: Whitespace-only credentials can break an established Bedrock workflow across streaming, discovery, embeddings, and Mantle for users relying on valid AWS fallback credentials.
- `merge-risk: 🚨 compatibility`: Merging changes process-wide environment behavior for existing gateways and any later AWS consumers or child processes.
- `merge-risk: 🚨 auth-provider`: The patch changes credential precedence and fallback behavior across every bundled Amazon Bedrock authentication path.

## Summary

Keep open for maintainer review: the bug remains on current main and the patch is well-proven with no concrete correctness defect, but permanently deleting shared AWS environment values is a compatibility and provider-auth choice that needs explicit Bedrock-owner approval.

## What This Changes

Normalizes whitespace-only Amazon Bedrock bearer, static, and session credential environment values before streaming, discovery, embeddings, inference-profile resolution, and Mantle IAM token generation resolve authentication.

## Best Possible Solution

Use one Bedrock-owned preparation contract across every client path; prefer a scoped AWS credential/token provider that ignores blanks, or explicitly approve and document one-time process-wide normalization if the SDK contract makes scoped handling impractical.
