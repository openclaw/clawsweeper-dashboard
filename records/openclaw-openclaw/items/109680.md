## Label Justifications

- `P1`: Whitespace-only AWS credentials can still block an existing Bedrock authentication workflow for users relying on the default credential chain.

## Summary

The prior P1 blocker remains on the current head: refreshing shared AWS files does not prevent whitespace-only static keys from being selected before profile, SSO, ECS, or IMDS credentials.

## What This Changes

The PR trims Bedrock bearer tokens and treats whitespace-only AWS bearer and static credential environment values as absent when deciding whether to refresh shared AWS configuration, with focused regression tests.

## Best Possible Solution

Normalize whitespace-only static AWS credential variables out of the Bedrock client’s effective credential source before SDK client construction, preserve profile/SSO/ECS/IMDS fallback, and prove both bearer-token and static-key paths in real runtime output.

## Reproduction Assessment

Yes from source for the remaining static-key failure: whitespace values remain visible to the SDK environment provider, which precedes profile, SSO, ECS, and IMDS sources. The PR’s live capture separately establishes the bearer-token symptom.

## Solution Assessment

No. Trimming bearer tokens is correct, but changing only the shared-config refresh predicate is too narrow because it leaves the SDK environment credential provider able to select whitespace static keys.
