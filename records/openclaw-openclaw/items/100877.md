## Summary

Keep open: the PR fixes the right hot-path performance problem, but the proposed `PRAGMA page_count` estimate changes ACP replay retention from ledger-scoped bytes to whole shared-database pages, which can trim replay history because of unrelated state.

## What This Changes

The PR replaces `estimateSqliteLedgerBytes`'s replay-table aggregate query with `PRAGMA page_count * 4096` in `src/acp/event-ledger.ts`.

## Best Possible Solution

Use ledger-scoped cheap accounting for ACP replay bytes, such as safe cached/incremental row accounting, and prove unrelated shared-state rows do not trigger ACP replay trimming.
