## Summary

The patch is technically coherent and the prior progress-callback blocker is covered on the current head, but merging still requires an explicit maintainer decision on the permanent plugin SDK contract and on treating an already-sent Telegram message as failed when topic proof is unavailable or mismatched.

## What This Changes

The PR adds provider-confirmed Telegram chat/topic metadata, a generic post-send plugin validation hook, and cron delivery handling that rejects unproven non-General topic sends.

## Best Possible Solution

Approve the generic hook only if post-send provider attestation is intended as a durable plugin contract; then land it with explicit sent-before-error/retry semantics and exact-head coverage for matching, missing, mismatched, General-topic, reaction-only, rich-fallback, and progress-result paths, otherwise keep the validation Telegram-internal.
