## Summary

Keep open: current main still does not expose an ordinary plugin-to-plugin Gateway method caller. The public dispatcher that exists today is intentionally limited to authenticated plugin HTTP routes, so this remains a Plugin SDK and Gateway authorization design item rather than conservative cleanup.

## What This Changes

Request to add a plugin SDK call surface so one plugin can invoke gateway methods registered by another plugin.

## Best Possible Solution

Keep this as the canonical design item for a narrow, authorized Plugin SDK inter-plugin Gateway-call contract with caller attribution, explicit exposure rules, docs, and contract tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose ordinary plugin runtime access to plugin-registered Gateway methods, and what authorization/API shape should carry plugin caller identity?

Rationale: This would change the public Plugin SDK and Gateway authorization boundary, so automation cannot safely choose between raw dispatch, allowlisted calls, or typed service/capability contracts.

Likely owner: vincentkoc

Owner reason: He authored the current dispatcher guard and current PluginRuntime shape on main, making him the strongest current-history routing candidate.

Owner confidence: high

Options:

- **Design a narrow authorized SDK contract (recommended):** Expose only approved methods or typed capabilities with plugin caller attribution, explicit authorization, docs, and contract tests.
- **Keep HTTP-route dispatch only:** Decline ordinary plugin-to-plugin Gateway calls and require plugins to use existing HTTP route or capability seams.
- **Expose raw Gateway dispatch:** Add a generic method-string caller and accept the larger security and compatibility surface as a maintainer-owned product decision.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows plugin Gateway method registration exists, but ordinary plugin runtime code still has no general caller; the only public dispatcher is reserved for authenticated plugin HTTP-route scopes.

## Solution Assessment

No for the raw callGatewayMethod(method, params) shape as proposed. The safer path is a maintainer-approved SDK contract with caller identity, explicit method exposure or allowlisting, authorization rules, lifecycle handling, docs, and contract tests.
