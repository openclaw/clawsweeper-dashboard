## Summary

Keep open: current main added a trusted-official-plugin Gateway request helper, but ordinary third-party plugin-to-plugin Gateway calls like the reported metabolism/stability use case still are not supported; the remaining work is a public Plugin SDK and security-boundary decision.

## What This Changes

The issue requests a public plugin SDK method for one plugin to invoke Gateway methods registered by the host or another plugin.

## Best Possible Solution

Keep this as the canonical design item for a narrow, authorized plugin-to-plugin or host Gateway-call contract that explicitly defines plugin eligibility, caller attribution, method exposure, docs, and contract tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should ordinary third-party plugins be allowed to invoke Gateway methods registered by other plugins, and if so should the API be raw method dispatch, allowlisted request, or typed service/capability contracts?

Rationale: The code already has trusted-only and HTTP-route-only dispatch paths, but expanding this to arbitrary plugin runtime code changes public SDK and security boundaries that automation cannot choose safely.

Likely owner: steipete

Owner reason: steipete landed the current constrained trusted Gateway seam and is the best available owner for deciding whether to broaden it.

Owner confidence: high

Options:

- **Design an authorized SDK contract (recommended):** Expose a narrow caller with explicit plugin eligibility, caller attribution, method exposure rules, docs, and contract tests.
- **Keep trusted-only Gateway requests:** Document that ordinary third-party plugins should use existing runtime events, HTTP routes, or future service contracts instead of Gateway RPC dispatch.
- **Expose raw method dispatch:** Allow plugins to call method strings directly and accept the broader compatibility and authorization surface as a product decision.

## Reproduction Assessment

Yes. Current source shows Gateway methods can be dispatched only from bundled/trusted official plugin runtime scopes or authenticated plugin HTTP routes, not from ordinary third-party plugin event/service code.

## Solution Assessment

No for the raw `api.callGatewayMethod(method, params)` shape as proposed. The safer fix is a maintainer-approved SDK contract with caller identity, explicit exposure rules, authorization checks, docs, and contract tests.
