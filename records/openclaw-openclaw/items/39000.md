## Summary

Keep open: current main and v2026.6.11 still lack an ordinary plugin-to-plugin Gateway method caller. The existing dispatcher is deliberately limited to authenticated plugin HTTP routes, so this remains a Plugin SDK product and security-boundary decision.

## What This Changes

Request to add a plugin SDK call-side API so plugins can invoke Gateway methods registered by other plugins from ordinary plugin runtime code.

## Best Possible Solution

Keep this as the canonical design item for a narrow, authorized Plugin SDK Gateway-call contract with caller attribution, explicit method exposure rules, docs, and contract tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should ordinary plugin runtime code be allowed to call plugin-registered Gateway methods, and what authorization/API shape should carry plugin caller identity?

Rationale: The requested API changes both the public Plugin SDK and Gateway authorization boundary, so automation cannot safely choose between raw dispatch, allowlisted calls, or typed service/capability contracts.

Likely owner: steipete

Owner reason: He has the strongest current history on the route-scoped Gateway dispatch contract and public SDK boundary.

Owner confidence: high

Options:

- **Design a narrow authorized SDK contract (recommended):** Expose only approved methods or typed capabilities with plugin caller attribution, explicit authorization, docs, and contract tests.
- **Keep HTTP-route dispatch only:** Decline ordinary plugin-to-plugin Gateway calls and require plugins to use existing HTTP route, runtime helper, or capability seams.
- **Expose raw Gateway dispatch:** Add a generic method-string caller and accept the larger security and compatibility surface as a maintainer-owned product decision.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows plugins can register Gateway methods, but ordinary plugin runtime/hooks/services still have no general caller; the only public SDK dispatcher is restricted to authenticated plugin HTTP-route scopes.

## Solution Assessment

No for the raw callGatewayMethod(method, params) shape as proposed. The safer solution is a maintainer-approved SDK contract with caller identity, explicit method exposure or allowlisting, authorization rules, lifecycle handling, docs, and contract tests.
