## Summary

Keep open: current main and the latest release still do not provide an ordinary plugin runtime caller for plugin-registered Gateway methods; the existing dispatcher is intentionally reserved for authenticated plugin HTTP routes, so the remaining work is an SDK and security-boundary design decision.

## What This Changes

Request to add a Plugin SDK API that lets one plugin call Gateway methods registered by another plugin for cross-plugin communication.

## Best Possible Solution

Keep this as the canonical design item for a narrow, authorized Plugin SDK inter-plugin or host Gateway-call contract with caller attribution, explicit exposure rules, docs, and contract tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose a plugin runtime caller for plugin-registered Gateway methods, and should that surface be raw method dispatch, an allowlisted request API, or typed service/capability contracts?

Rationale: The API shape changes the public Plugin SDK and Gateway authorization boundary, so automation cannot safely choose the permanent contract or security policy.

Likely owner: steipete

Owner reason: steipete introduced the existing route-scoped dispatch contract and is the strongest history match for this Gateway/Plugin SDK boundary.

Owner confidence: high

Options:

- **Design a narrow authorized SDK contract (recommended):** Expose only approved methods or typed capabilities with plugin caller attribution, authorization rules, docs, and contract tests.
- **Keep route-scoped dispatch only:** Decline ordinary plugin-to-plugin Gateway calls and document the current authenticated HTTP-route dispatch helper as the supported boundary.
- **Expose raw Gateway dispatch:** Add a generic method-string caller and explicitly accept the larger security and compatibility surface.

## Reproduction Assessment

Yes, at source level. Current main shows plugins can register Gateway methods, but ordinary PluginRuntime code has no gateway caller and the only public dispatcher is restricted to authenticated plugin HTTP-route scopes.

## Solution Assessment

No for the raw api.callGatewayMethod(method, params) shape as proposed. The safer path is a maintainer-approved SDK contract with caller identity, explicit method exposure or allowlisting, authorization rules, docs, and contract tests.
