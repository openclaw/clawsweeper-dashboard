## Summary

Keep open: current main and v2026.6.11 still lack an ordinary plugin runtime caller for plugin-registered Gateway methods; this remains a Plugin SDK and Gateway authorization design decision.

## What This Changes

Request a plugin-facing API for invoking plugin-registered Gateway methods from another plugin instead of relying on scoped api property sharing or parsing message context.

## Best Possible Solution

Keep this as the canonical design item for a narrow, authorized plugin-to-plugin or host Gateway-call contract with caller attribution, explicit method exposure, docs, and contract tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw expose ordinary plugin runtime access to plugin-registered Gateway methods, and should that surface be raw dispatch, an allowlisted request API, or typed service/capability contracts?

Rationale: The API shape changes the public Plugin SDK and the Gateway authorization boundary, so automation cannot safely choose the permanent contract or security policy.

Likely owner: steipete

Owner confidence: high

Options:

- **Design a narrow authorized SDK contract (recommended):** Expose approved methods or typed capabilities with plugin caller attribution, authorization rules, docs, and contract tests.
- **Keep only the route-scoped helper:** Decline ordinary plugin-to-plugin Gateway calls and document authenticated HTTP-route dispatch as the supported boundary.
- **Expose raw Gateway dispatch:** Add a generic method-string caller and explicitly accept the larger security and compatibility surface.

## Reproduction Assessment

Yes at source level. Current main shows plugins can register Gateway methods and the Gateway can route plugin handlers, but ordinary PluginRuntime code has no gateway caller and the only public dispatcher is restricted to authenticated plugin HTTP-route scopes.

## Solution Assessment

No for the raw callGatewayMethod(method, params) shape as proposed. The safer solution is a maintainer-approved SDK contract with caller identity, explicit method exposure or allowlisting, authorization rules, docs, and contract tests.
