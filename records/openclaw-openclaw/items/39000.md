## Summary

Keep open: current main adds a trusted-only `api.runtime.gateway.request` path, but the reported external plugin-to-plugin use case still remains outside the ordinary Plugin SDK. This is a real SDK gap, but the next step is maintainer product and security review, not an automated fix PR.

## What This Changes

The issue requests a Plugin SDK API for one plugin to call another plugin's registered Gateway method.

## Best Possible Solution

Keep this as the canonical design item for a narrow, authorized Plugin SDK inter-plugin Gateway-call contract with caller attribution, explicit exposure rules, docs, and contract tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose a plugin runtime caller for plugin-registered Gateway methods, and if so should it be raw dispatch, an allowlisted request API, or a typed service/capability contract?

Rationale: Current main intentionally limits Gateway requests to bundled or trusted official plugins, while this issue asks to extend the public SDK boundary to third-party inter-plugin communication.

Likely owner: steipete

Owner reason: He introduced the current dispatch entitlement boundary and is the strongest history match for the Plugin SDK/Gateway authorization decision.

Owner confidence: high

Options:

- **Design a narrow authorized SDK contract (recommended):** Expose only approved methods or typed capabilities with plugin caller attribution, explicit authorization, docs, and contract tests.
- **Keep trusted-only dispatch:** Decline ordinary external plugin Gateway calls and require plugins to use existing HTTP route, typed runtime helper, or plugin-specific capability seams.
- **Allow raw Gateway dispatch:** Expose a generic method-string caller and accept a much larger security and compatibility surface as an explicit product decision.

## Reproduction Assessment

Yes. Source inspection shows arbitrary external plugins still cannot call registered Gateway methods through the ordinary SDK; current main only provides trusted-only runtime Gateway requests and a route-scoped HTTP helper.

## Solution Assessment

No for the raw `callGatewayMethod(method, params)` shape as proposed. The safer path is a maintainer-approved SDK contract with caller identity, explicit method exposure or allowlisting, authorization rules, docs, and contract tests.
