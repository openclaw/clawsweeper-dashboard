## Summary

Keep open: current main still lacks an ordinary plugin-to-plugin Gateway method caller, and the existing dispatcher is deliberately restricted to authenticated plugin HTTP routes. This remains a public Plugin SDK and Gateway authorization design item, not conservative cleanup.

## What This Changes

Request to add a Plugin SDK call surface such as `api.callGatewayMethod(...)` so one plugin can invoke Gateway methods registered by another plugin.

## Best Possible Solution

Keep this as the canonical design item for a narrow, authorized Plugin SDK inter-plugin or host Gateway-call contract with caller attribution, explicit exposure rules, docs, and contract tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose ordinary plugin runtime access to plugin-registered Gateway methods, and what authorization/API shape should carry caller identity?

Rationale: The requested API changes the public Plugin SDK and Gateway authorization boundary, so automation cannot safely choose between raw dispatch, allowlisted calls, or typed service/capability contracts.

Likely owner: steipete

Owner reason: He authored and merged the existing route-scoped Gateway dispatch contract and docs, making him the strongest available owner for this boundary decision.

Owner confidence: high

Options:

- **Design a narrow authorized SDK contract (recommended):** Expose only approved methods or typed capabilities with plugin caller attribution, explicit authorization, docs, and contract tests.
- **Keep HTTP-route dispatch only:** Decline ordinary plugin-to-plugin Gateway calls and require plugins to use existing HTTP route or capability seams.
- **Expose raw Gateway dispatch:** Add a generic method-string caller and accept the larger security and compatibility surface as maintainer-owned product direction.

## Reproduction Assessment

Yes. Source inspection on current main shows plugins can register Gateway methods, but ordinary plugin runtime/hooks/services still have no general caller; the only public SDK dispatcher is restricted to authenticated plugin HTTP-route scopes.

## Solution Assessment

No for the raw `api.callGatewayMethod(method, params)` shape as proposed. The safer solution is a maintainer-approved SDK contract with caller identity, explicit method exposure or allowlisting, authorization rules, lifecycle handling, docs, and contract tests.
