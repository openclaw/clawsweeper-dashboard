## Summary

Keep open: current main partially exposes `api.runtime.gateway.request`, but it is explicitly limited to bundled or trusted official plugins and current tests reject arbitrary third-party plugins, so the external inter-plugin use case still needs product and security direction.

## What This Changes

The issue requests a plugin SDK API that lets one plugin invoke plugin-registered Gateway methods from another plugin.

## Best Possible Solution

Keep this as the canonical design item for a narrow, authorized plugin-to-plugin Gateway-call contract with caller attribution, explicit method exposure rules, docs, and contract tests.

- **Allow generic method dispatch:** Expose a broader method-string caller to external plugins while accepting a larger security and compatibility surface as an explicit maintainer decision.

## Solution Assessment

No for the raw `api.callGatewayMethod(method, params)` shape as proposed. The safer path is a maintainer-approved SDK contract with caller identity, explicit method exposure or allowlisting, authorization rules, docs, and tests.
