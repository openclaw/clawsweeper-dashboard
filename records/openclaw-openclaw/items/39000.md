## Summary

Keep open: current main now has a trusted-official `api.runtime.gateway.request` helper, but it intentionally rejects arbitrary external plugins, so the reported external plugin-to-plugin use case still needs a security-boundary/product decision.

## What This Changes

Request to add a Plugin SDK call surface so one plugin can invoke another plugin's registered Gateway RPC method instead of parsing message context or coupling to files.

## Best Possible Solution

Keep the trusted-official helper, then make an explicit maintainer decision on a narrow external inter-plugin contract with method exposure rules, caller attribution, docs, and contract tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose Gateway RPC calls from ordinary external plugins, and if so should that be a raw method-string request, a manifest-declared allowlist, or typed service/capability APIs?

Rationale: The remaining use case changes the public Plugin SDK authorization boundary; automation cannot safely choose which third-party plugins may invoke which Gateway methods or how sensitive/mutating methods are exposed.

Likely owner: steipete

Owner reason: He merged and co-authored the current trusted-only helper and is the strongest current history match for choosing the permanent Gateway/Plugin SDK boundary.

Owner confidence: high

Options:

- **Design a narrow external contract (recommended):** Expose only approved or manifest-declared methods/capabilities with caller attribution, scopes, trust-tier behavior, docs, and contract tests.
- **Keep trusted-official only:** Document that community plugins cannot use in-process Gateway RPC dispatch unless promoted to a trusted official install path.
- **Allow broad raw dispatch:** Expose a generic method-string caller to more plugins and accept the larger compatibility and security surface as a deliberate product decision.

## Reproduction Assessment

Yes. Source and tests on current main show plugins can register Gateway methods and trusted official plugins can call Gateway methods, but arbitrary external plugins are rejected from `api.runtime.gateway.request`.

## Solution Assessment

No for the proposed raw `api.callGatewayMethod(method, params)` shape. The safer solution is a maintainer-approved, narrow SDK contract that defines caller identity, allowed methods, trust tier, and documentation before broad external use.
