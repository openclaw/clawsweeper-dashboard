## Summary

Keep open: current main and v2026.6.11 still lack an ordinary plugin runtime caller for plugin-registered Gateway methods; the remaining work is a Plugin SDK and security-boundary design decision.

## What This Changes

The issue requests a Plugin SDK API that lets one plugin call another plugin's registered Gateway RPC method from ordinary plugin runtime code.

## Best Possible Solution

Keep this as the canonical design item for a narrow, authorized Plugin SDK inter-plugin or host Gateway-call contract with caller attribution, explicit exposure rules, docs, and contract tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose a plugin runtime caller for plugin-registered Gateway methods, and should that surface be raw method dispatch, an allowlisted request API, or a typed service/capability contract?

Rationale: The API shape changes the public Plugin SDK and plugin authorization boundary, so automation cannot safely choose the permanent contract or security policy.

Likely owner: steipete

Owner reason: steipete introduced the existing route-scoped dispatch contract and is the strongest history match for the Gateway/Plugin SDK boundary.

Owner confidence: high

Options:

- **Design a narrow authorized SDK contract (recommended):** Expose only approved methods or typed capabilities with plugin caller attribution, authorization rules, docs, and contract tests.
- **Keep the route-scoped helper only:** Decline ordinary plugin-to-plugin Gateway calls and document the current HTTP-route-only dispatch helper as the supported boundary.
- **Expose raw Gateway dispatch:** Add a generic method-string caller and explicitly accept the larger security and compatibility surface.

## Reproduction Assessment

Yes at source level. Current main shows plugins can register Gateway methods, but ordinary PluginRuntime code has no gateway caller and the only public dispatcher is restricted to authenticated plugin HTTP-route scopes.

## Solution Assessment

No for the raw callGatewayMethod(method, params) shape as proposed. The safer solution is a maintainer-approved SDK contract with caller identity, explicit method exposure or allowlisting, authorization rules, docs, and contract tests.
