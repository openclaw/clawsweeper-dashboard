## Summary

Keep open: current main and v2026.6.11 still do not expose an ordinary PluginRuntime or OpenClawPluginApi caller for plugin-registered Gateway methods; this remains a public Plugin SDK and Gateway authorization-boundary decision.

## What This Changes

Request to add a plugin-facing `api.callGatewayMethod()` or equivalent runtime surface so one plugin can call another plugin's registered Gateway RPC method.

## Best Possible Solution

Keep this as the canonical design item for a narrow, authorized Plugin SDK Gateway-call contract with plugin caller attribution, explicit method exposure rules, docs, and contract tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose plugin-to-plugin Gateway RPC calls, and if so should the permanent SDK surface be raw method dispatch, an allowlisted request API, or typed capability/service accessors?

Rationale: The requested API changes the public Plugin SDK and determines what Gateway methods plugin code may invoke, so automation cannot choose the authorization and compatibility contract safely.

Likely owner: Peter Steinberger

Owner reason: Peter introduced the existing route-scoped Gateway dispatch contract and has the strongest history signal for the Gateway/Plugin SDK boundary.

Owner confidence: high

Options:

- **Design a narrow authorized SDK contract (recommended):** Expose only approved plugin-callable methods or typed capabilities with caller attribution, method policy, docs, and contract tests.
- **Keep only the HTTP-route dispatcher:** Decline ordinary plugin-to-plugin Gateway calls and document the current authenticated-route helper as the supported boundary.
- **Expose raw Gateway dispatch:** Add a generic method-string caller and explicitly accept the larger security and compatibility surface.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 show plugin Gateway method registration and route-scoped dispatch, but no ordinary PluginRuntime or OpenClawPluginApi caller for another plugin to use.

## Solution Assessment

No for the raw `callGatewayMethod(method, params)` shape as proposed. The safer path is a maintainer-approved SDK contract with caller identity, explicit method exposure or allowlisting, authorization rules, docs, and contract tests.
