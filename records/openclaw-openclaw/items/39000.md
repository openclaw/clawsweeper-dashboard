## Summary

Keep open: current main now has a trusted `api.runtime.gateway.request` path, but it deliberately rejects arbitrary external plugins, so the reported third-party plugin-to-plugin use case still needs a maintainer product and security-boundary decision.

## What This Changes

Request to add a plugin API for one plugin to invoke Gateway methods registered by another plugin.

## Best Possible Solution

Keep the current trusted `api.runtime.gateway.request` contract as the base, then have maintainers decide whether external plugin-to-plugin calls should use trusted-official promotion, explicit method/capability allowlisting, or a typed service contract.
