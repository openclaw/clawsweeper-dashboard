## Summary

Keep open: current main and v2026.6.11 still do not provide an ordinary plugin runtime caller for plugin-registered Gateway methods. The existing dispatch helper is intentionally restricted to authenticated plugin HTTP routes, so the remaining work is a public Plugin SDK and security-boundary decision.

## What This Changes

Add a public plugin API such as `callGatewayMethod` so one plugin can invoke plugin-registered Gateway methods from ordinary plugin runtime code.

## Best Possible Solution

Keep this as the canonical design item for a narrow, authorized Plugin SDK gateway-call contract with caller attribution, explicit exposure or allowlist rules, docs, and contract tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose a plugin runtime caller for plugin-registered Gateway methods, and if so should it be raw dispatch, an allowlisted request API, or a typed service/capability contract?

Rationale: The implementation shape changes the public Plugin SDK and Gateway authorization boundary, so automation cannot safely choose the method policy, caller identity model, or permanence of the API.

Likely owner: steipete

Owner reason: He is the strongest current history match for the plugin architecture, `registerGatewayMethod`, and route-scoped dispatcher contract.

Owner confidence: high

Options:

- **Design a narrow authorized SDK contract (recommended):** Expose only approved methods or typed capabilities with plugin caller attribution, explicit authorization, docs, and contract tests.
- **Keep the route-scoped helper only:** Decline ordinary plugin-to-plugin Gateway calls and keep in-process dispatch limited to authenticated plugin HTTP routes.
- **Allow raw Gateway dispatch:** Expose a generic method-string caller while accepting the larger security and compatibility surface as a maintainer-owned product decision.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows plugins can register Gateway methods, but ordinary plugin runtime/hooks/services still have no general caller; the only public dispatcher is restricted to authenticated plugin HTTP-route scopes.

## Solution Assessment

No for the raw `callGatewayMethod(method, params)` shape as proposed. The safer solution is a maintainer-approved SDK contract with caller identity, explicit method exposure or allowlisting, authorization rules, lifecycle handling, docs, and contract tests.
