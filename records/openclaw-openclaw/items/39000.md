## Summary

Keep open: current main partially implements trusted-official `api.runtime.gateway.request` and live plugin method dispatch, but ordinary external plugins are still deliberately rejected, so the reported community plugin-to-plugin use case remains a security-boundary product decision.

## What This Changes

Request to let plugins invoke Gateway methods registered by other plugins, originally proposed as `api.callGatewayMethod()`.

## Best Possible Solution

Keep the trusted-official helper, then design a narrow external inter-plugin contract with manifest or capability declarations, caller attribution, scopes/sensitive-method policy, docs, and contract tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should ordinary external plugins be allowed to invoke plugin-registered or host Gateway methods, and if so should that access be raw, manifest-allowlisted, or exposed through typed service/capability APIs?

Rationale: This changes the public Plugin SDK authorization boundary, and automation cannot safely choose which third-party plugins may invoke which Gateway methods or how sensitive and mutating methods are exposed.

Likely owner: steipete

Owner reason: steipete merged the current trusted-only Gateway runtime helper and is the strongest history match for deciding the permanent Plugin SDK/Gateway authorization boundary.

Owner confidence: high

Options:

- **Design a narrow external contract (recommended):** Expose only approved or manifest-declared methods/capabilities with caller identity, trust-tier behavior, docs, and contract tests.
- **Keep trusted-official only:** Document that community plugins cannot use in-process Gateway RPC dispatch unless promoted to a trusted official install path.
- **Allow broad raw dispatch:** Expose a generic method-string caller to more plugins and accept the larger compatibility and security surface as a deliberate product decision.

## Reproduction Assessment

Yes. Source and tests on current main show the call side exists only for bundled or trusted official plugins, while the reported ordinary external plugin caller is rejected.

## Solution Assessment

No for the proposed raw `api.callGatewayMethod(method, params)` shape. The safer solution is a maintainer-approved narrow SDK contract that defines caller identity, allowed methods, trust tier, and docs before broad external use.
