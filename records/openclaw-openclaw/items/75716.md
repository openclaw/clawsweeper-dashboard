## Summary

Keep open: this is focused and well-proven, but it intentionally changes released Google Chat credential fallback behavior and still needs maintainer acceptance of that compatibility tradeoff before merge.

## What This Changes

The PR changes Google Chat service-account resolution so an unresolved `serviceAccountRef` fails before inline/file fallback, and resolved runtime SecretRefs remove the sibling ref before credential reads.

## Best Possible Solution

Land the plugin-owned resolver and secret-contract fix only after maintainers explicitly accept the fail-closed SecretRef precedence tradeoff, adding an upgrade aid first if compatibility is preferred.

## Reproduction Assessment

Yes at source level. Current main and v2026.6.11 return inline/file Google Chat credentials before checking sibling `serviceAccountRef`, while the PR head throws on the unresolved ref first and the docs state the ref takes precedence.

## Solution Assessment

Not yet as a mergeable solution. The plugin-owned resolver and secret-contract cleanup are the right layer if maintainers accept the compatibility change, but preserving shipped fallback or adding a doctor/audit/warning aid is safer if compatibility wins.
