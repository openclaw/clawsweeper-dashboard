## Summary

This should stay open: current main still opens the macOS Dashboard with a single resolved tunnel endpoint and origin-pinned native auth script, while endpoint-store changes are not observed by the Dashboard window. The protected `maintainer` label and the reload-vs-live-bridge fix choice make this a maintainer follow-up item rather than an auto-close or auto-fix candidate.

## What This Changes

The issue reports that the macOS Dashboard in remote SSH mode keeps using a dead forwarded localhost port after the tunnel restarts on a new port.

## Best Possible Solution

Keep this open and fix the macOS Dashboard owner path so an open remote-mode window observes endpoint changes, refreshes native auth for the new origin, and reloads or updates the page without requiring the user to reopen it.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should the macOS Dashboard recover from a tunnel endpoint change by reinjecting auth and reloading the WebView, or by adding a native-to-web live endpoint update bridge?

Rationale: Both approaches fix the stale-port bug, but they trade off implementation size, WebView auth lifecycle risk, and whether a new native bridge becomes a durable product contract.

Likely owner: steipete

Owner reason: They provided the concrete live reproduction and have the strongest current routing signal from merged macOS/dashboard history.

Owner confidence: high

Options:

- **Reload on endpoint change (recommended):** Subscribe in the Dashboard path, reinject native auth for the new origin, and reload the WebView when the resolved endpoint changes; this is the narrowest repair and easiest to prove.
- **Bridge live endpoint updates:** Expose an endpoint-update bridge to the running Control UI so it can reconnect without a full reload, accepting a broader native/web contract.
- **Coordinate with tunnel cleanup first:** Wait for the orphaned-tunnel cleanup to reduce port churn, while leaving the open Dashboard window stale-port failure unresolved until the Dashboard behavior is chosen.

## Reproduction Assessment

Yes for source reproduction: current main resolves and injects the Dashboard endpoint once, while `GatewayEndpointStore` can publish a new remote tunnel port that the Dashboard path does not observe. I did not run the live macOS SSH tunnel kill or sleep/wake scenario.

## Solution Assessment

Unclear until maintainers choose the UX shape. A reload after reinjecting native auth is the narrowest maintainable repair, while a live endpoint bridge may be smoother but creates broader product surface.
