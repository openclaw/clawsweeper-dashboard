## Summary

Keep this PR open: the durable-admission direction matches the canonical channel-ingress work, but the patch appears to bypass Slack’s configured inbound debounce for serialized drain records and the supplied evidence does not demonstrate a real Slack receive/crash/restart/replay cycle.

## What This Changes

The PR durably queues Slack Socket Mode, HTTP Events API, and relay events before acknowledgement, routes replay through the core ingress drain, and replaces earlier delivery caches with logical message dispatch deduplication.

## Best Possible Solution

Keep the core durable-ingress adapter, but preserve Slack’s configured debounce by coalescing available same-lane queue records into one turn while binding every included record to the resulting adoption lifecycle, then prove durable-before-ack and exactly-once restart replay on a real Slack transport.
