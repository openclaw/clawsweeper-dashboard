## Summary

Keep open: current main still lacks a landed provider-backed WebChat read-aloud action and a Gateway-backed editable mic-to-transcript composer flow. Two open PRs cover partial TTS and STT slices, but both still need maintainer/security review and proof before this broader issue can close.

## What This Changes

Request provider-backed WebChat voice support so read-aloud uses configured Gateway TTS and microphone input can use configured STT instead of browser-owned speech APIs.

## Best Possible Solution

Split the work into provider-backed TTS read-aloud through existing Gateway TTS/media-ticket contracts and batch editable STT through `tools.media.audio`, with credentials kept server-side and redacted real WebChat proof before merge.
