## Summary

Keep open: current main and v2026.6.11 still do not provide the requested provider-backed WebChat voice flow. Main has Gateway TTS and media-audio transcription primitives, plus playable audio attachments and realtime Talk, but it still lacks a per-message Gateway-backed Read aloud action and a one-click editable mic path through configured STT providers.

## What This Changes

Request to replace browser-only WebChat speech controls with provider-backed Gateway TTS and STT flows for self-hosted audio providers.

## Best Possible Solution

Keep this broad issue open as the umbrella, land the TTS Read aloud and Gateway-backed editable dictation slices through reviewed PRs, and reuse existing `messages.tts` plus `tools.media.audio` rather than adding `messages.stt`.
