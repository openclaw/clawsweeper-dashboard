## Summary

Keep open: current main removed the stale browser Read aloud and dictation controls and has Gateway voice primitives, but the requested provider-backed WebChat read-aloud and editable mic-capture workflows are still split across open, not-yet-landed TTS and dictation work.

## What This Changes

The issue requests WebChat STT/TTS controls that route through configured Gateway/provider audio paths instead of browser Web Speech APIs.

## Best Possible Solution

Keep this as the broad provider-backed WebChat voice tracker while landing narrower Gateway-backed Read aloud and editable batch dictation changes that reuse `messages.tts` and `tools.media.audio` without adding a parallel `messages.stt` config surface.
