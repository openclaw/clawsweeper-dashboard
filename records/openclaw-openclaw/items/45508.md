## Summary

Keep open: current main removed the stale browser-only speech controls and has Gateway voice primitives, but the requested provider-backed WebChat flow is still split across unlanded TTS and STT work. Closing this would lose the broader canonical context for WebChat honoring configured voice providers.

## What This Changes

The issue asks for WebChat voice controls to use configured gateway-backed TTS/STT providers instead of browser-only speech APIs, including self-hosted OpenAI-compatible audio stacks.

## Best Possible Solution

Keep this as the broad provider-backed WebChat voice tracker, split implementation into Gateway `tts.convert` Read aloud and Gateway/media-audio editable dictation, and avoid a parallel `messages.stt` config surface.
