## Summary

Keep open: current main and v2026.6.11 still lack a merged provider-backed WebChat read-aloud action and an editable mic capture path through the configured audio transcription pipeline; the related TTS and STT PRs remain open, partial, or conflicted.

## What This Changes

Request gateway-backed WebChat voice support so assistant read-aloud uses configured TTS and mic input can use self-hosted/batch STT instead of browser or OS speech paths.

## Best Possible Solution

Keep this as the broad WebChat provider-backed voice tracker, land or replace the TTS slice through existing Gateway TTS methods, and scope STT as editable batch push-to-talk using tools.media.audio with secrets kept server-side.
