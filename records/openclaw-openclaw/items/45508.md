## Summary

Keep open: current main still lacks a landed provider-backed WebChat read-aloud action and an editable mic capture/transcribe/send flow. The existing Gateway TTS and media-transcription pieces are useful, and two open PRs are partial candidates, but neither has landed and the STT/security UX boundary still needs maintainer direction.

## What This Changes

Request provider-backed WebChat voice support by routing read-aloud through configured TTS and mic input through Gateway STT instead of browser-only or realtime-only speech paths.

## Best Possible Solution

Split the work into provider-backed TTS read-aloud via existing Gateway TTS/media-ticket contracts and batch editable STT via `tools.media.audio`, with credentials kept server-side and redacted real WebChat proof before merge.
