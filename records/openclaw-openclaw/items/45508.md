## Summary

Keep open: current main no longer exposes the old browser Speech API read-aloud/dictation controls, but it still lacks a merged provider-backed WebChat Read aloud action and editable microphone capture through the configured audio transcription pipeline.

## What This Changes

The issue requests routing WebChat read-aloud and microphone voice input through configured gateway-backed TTS/STT providers instead of browser Speech APIs.

## Best Possible Solution

Split the work into narrow maintainer-approved slices: implement Read aloud through existing `messages.tts`/Gateway TTS with scoped media-ticket playback, and implement editable push-to-talk STT through `tools.media.audio` without introducing a parallel `messages.stt` config path.
