## Summary

Keep open: current main has Gateway TTS, playable WebChat audio attachments, Talk, and media-audio transcription primitives, but it still lacks a completed WebChat per-message Gateway-backed Read aloud action and a one-click/editable mic flow through the configured STT pipeline.

## What This Changes

The issue requests provider-backed WebChat voice input and output so configured TTS/STT providers are used instead of browser speech APIs.

## Best Possible Solution

Keep this issue as the canonical WebChat provider-backed voice umbrella, land a secure TTS Read aloud slice, and handle editable mic dictation as a separate Gateway/tools.media.audio flow without adding a parallel messages.stt config stack.
