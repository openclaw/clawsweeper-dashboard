## Summary

Keep open: current main has removed the stale browser-speech read-aloud/dictation controls and has Gateway voice primitives, but the requested provider-backed WebChat Read aloud and editable mic-capture workflow is still unresolved across partial open TTS and dictation work.

## What This Changes

## Best Possible Solution

Keep this as the broad provider-backed WebChat voice tracker while maintainers split implementation into a Gateway-backed Read aloud path using existing TTS RPCs and an editable batch dictation path using `tools.media.audio`, without adding a parallel `messages.stt` config surface.
