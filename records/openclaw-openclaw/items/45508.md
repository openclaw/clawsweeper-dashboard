## Summary

Keep open: current main removes the stale browser speech controls and has Gateway voice primitives, but the requested provider-backed WebChat Read aloud and editable mic-capture workflow is still split across open TTS and dictation work.

## What This Changes

The issue asks for WebChat Read aloud and microphone input to use configured Gateway TTS/STT providers instead of browser speech APIs.

## Best Possible Solution

Keep this as the broad provider-backed WebChat voice tracker while maintainers split implementation into a Gateway-backed Read aloud path using existing TTS RPCs and an editable batch dictation path using `tools.media.audio`, without adding a parallel `messages.stt` config surface.
