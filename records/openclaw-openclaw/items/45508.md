## Summary

Keep open: current main removed the old browser SpeechRecognition/read-aloud controls and can play audio attachments, but the central WebChat provider-backed voice request is still unfinished because no landed per-message Gateway Read aloud action or editable batch STT mic flow exists.

## What This Changes

Request to route WebChat Read aloud and microphone input through configured Gateway/provider TTS and STT paths instead of browser-owned speech APIs.

## Best Possible Solution

Keep this as the umbrella tracker, land or replace a narrow media-ticket-safe Gateway TTS Read aloud slice, and handle STT as a separate editable push-to-talk/batch transcription flow that reuses `tools.media.audio` unless maintainers choose Talk as the product answer.
