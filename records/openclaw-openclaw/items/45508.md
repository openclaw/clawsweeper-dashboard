## Summary

Keep open: current main has Gateway TTS, Talk, and audio-transcription primitives, and stale browser read-aloud is gone, but the requested WebChat flow is not fully landed. Per-message Gateway-backed read-aloud and editable provider-backed mic capture are still split across open follow-up work.

## What This Changes

Request to make Control UI/WebChat voice input and read-aloud use configured gateway-backed STT/TTS providers instead of browser speech APIs.

## Best Possible Solution

Keep this as the umbrella while maintainers split implementation: land Gateway-backed read-aloud against existing TTS config, and route editable batch dictation through `tools.media.audio` without adding `messages.stt` or exposing provider credentials.
