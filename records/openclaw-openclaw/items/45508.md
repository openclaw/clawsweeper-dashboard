## Summary

Keep open: current main has gateway TTS, audio playback, realtime Talk, and provider-backed media transcription primitives, but the requested WebChat flow is still not complete. The stale browser Speech API controls are gone, yet there is no landed per-message gateway-backed Read aloud action and no landed editable/batch microphone path through `tools.media.audio`.

## What This Changes

The issue requests routing WebChat read-aloud and microphone voice input through configured gateway/provider-backed TTS/STT instead of browser Web Speech APIs.

## Best Possible Solution

Keep this as the canonical WebChat voice-provider issue, land or replace the TTS Read aloud slice and the editable batch-dictation slice separately, and reuse `messages.tts` plus `tools.media.audio` without adding a parallel `messages.stt` config surface.
