## Summary

Keep open: current main and the latest release still lack a merged WebChat provider-backed read-aloud action and an editable mic capture path through the configured audio transcription pipeline; the active related PRs are partial and unmerged.

## What This Changes

The issue requests routing WebChat read-aloud and microphone input through configured Gateway-backed TTS/STT providers instead of browser speech paths.

## Best Possible Solution

Keep this as the canonical WebChat provider-backed voice tracker, land or replace the TTS slice through existing Gateway TTS methods, and scope STT as editable batch push-to-talk using tools.media.audio with secrets kept server-side.
