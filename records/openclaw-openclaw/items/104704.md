## Label Justifications

- `P1`: A successful account switch can silently corrupt the auth-profile identity mapping and leave real users operating under the wrong account state.
- `impact:data-loss`: The newly authenticated OAuth credential can overwrite a different account's existing profile record under the stale key.
- `impact:session-state`: The session remains associated with the previous authProfileOverride after a different account is authenticated.
- `impact:auth-provider`: The defect crosses OAuth identity, profile selection, and account-scoped cooldown or usage state.

## Summary

Keep open: current main still lets a stale session profile id replace the identity-derived profile id during Codex login, and the linked fix at https://github.com/openclaw/openclaw/pull/104706 remains open. The proposed direction is sound, but the shared channel `/login` path carries the same invariant and needs coverage or an explicit reason it is unaffected. Likely related people: @100yenadmin, @jalehman, and @obviyus with high confidence; @steipete with medium confidence.

## What This Changes

Prevent Telegram Codex login from storing a newly authenticated OpenAI account under the previously selected auth profile id.

## Best Possible Solution

Make provider-returned identity canonical for channel device login, then update the active session to the returned profile id after success across Telegram and the shared channel-login surface, with regression coverage for account switching and same-account reauthentication.
