## Summary

Keep open for maintainer review: the patch appears correct and the proof is sufficient, but changing Mattermost REST calls from unbounded waits to a 30s default timeout is a compatibility and message-delivery policy decision.

## What This Changes

Adds a 30s default timeout and per-request timeout override to the Mattermost REST client, with loopback regression coverage that preserves longer DM retry deadlines.

## Best Possible Solution

Land the shared Mattermost client timeout after maintainers accept the 30s default, keeping SSRF policy, caller aborts, and per-request DM retry overrides intact.
