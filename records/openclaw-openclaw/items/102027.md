## Summary

Keep this PR open: the follow-up commit fixes the prior DM retry timeout blocker, and the merge-ref evidence shows the Mattermost REST deadline is now wired through the shared timeout and SSRF helpers. The remaining question is an intentional compatibility tradeoff: every Mattermost REST/file/reaction/directory call now has a 30s default deadline, so maintainers should accept that policy before landing.

## What This Changes

Adds a 30s default timeout to the Mattermost REST client, wraps custom fetches with the same deadline, and adds loopback regression coverage including a DM retry timeout override.

## Best Possible Solution

Land the shared client timeout only if maintainers accept the 30s default as the Mattermost operator contract, with the DM retry override and focused regression coverage kept.
