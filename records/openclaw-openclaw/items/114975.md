## Summary

Keep open. This PR is the active candidate fix for the linked macOS retry-storm report, but it carries the protected `maintainer` label and changes the terminal recovery policy for app replacement; it needs macOS-owner confirmation plus real signed-bundle behavior evidence before merge.

## What This Changes

The branch bounds signed macOS app-replacement handoffs to three load-aware attempts, then either yields to a verified KeepAlive LaunchAgent or stops monitoring with an actionable recovery message.

## System Context

The macOS app replacement monitor detects a signed bundle replacing the running app, starts the replacement, and waits for authenticated readiness. Its handoff policy determines whether the monitor retries, yields restart ownership to LaunchAgent, or leaves the current app running for manual recovery.

## Architecture Diagram

flowchart TD
  A[Signed app bundle replacement] --> B[Replacement monitor]
  B --> C[Launch replacement and await authenticated readiness]
  C --> D{Handoff succeeds?}
  D -->|Yes| E[Replacement owns the app]
  D -->|No| F[Bounded retry and load-aware timeout]
  F --> G{Retry budget exhausted?}
  G -->|No| C
  G -->|Yes| H[Yield to verified supervisor or show manual recovery]

## Best Possible Solution

Land a single bounded-recovery policy only after a signed installed-bundle run demonstrates both terminal paths: verified LaunchAgent takeover and the unsupervised actionable manual-restart path.
