## Summary

Keep this issue open. Current main and the latest release ship a useful default-off package auto-updater, but the requested first-class workflow still lacks schedule/timezone selection, confirm or notify-only modes, channel-targeted notifications, and cross-restart old/new version plus changelog and health reporting.

## What This Changes

The issue requests a built-in auto-update workflow with configurable schedule, confirmation/silent/notify-only modes, and post-update notifications instead of user-authored cron jobs and BOOT.md state files.

## Best Possible Solution

Keep this as the canonical updater engine/workflow request and design a maintainer-approved, opt-in workflow on the safe update.run or external-updater path with schedule/timezone, confirm or notify-only modes, explicit silent mode, durable restart state, channel targeting, and old/new version plus changelog and health reporting.
