## Summary

Keep open: current main and v2026.6.11 include a default-off package auto-updater, but they still do not provide the requested scheduled approval workflow, notify-only mode, channel-targeted notifications, post-restart old/new reporting, or chat update surface.

## What This Changes

The issue asks for a first-class auto-update workflow with opt-in modes, scheduling, timezone handling, confirmation, channel notifications, and post-restart update reporting.

## Best Possible Solution

Keep this as the canonical updater engine/workflow tracker and design one supervised update workflow around `update.run` or the external-updater direction with approval modes, safe delivery, durable restart reporting, docs, schema/help, and focused tests.

## Reproduction Assessment

Not applicable: this is a feature request, not a broken existing behavior report. Source inspection shows current main lacks the requested workflow fields, approval modes, scheduler, notification flow, and chat update command surface.

## Solution Assessment

Unclear as proposed: the existing package updater is a useful foundation, but directly adding every requested field risks expanding a compatibility-sensitive config surface. The safer path is a maintainer-approved unified engine that separates scheduling, approval, delivery, and restart reporting without duplicating update execution.
