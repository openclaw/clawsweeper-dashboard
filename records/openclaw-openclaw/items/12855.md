## Summary

Keep open: current main and v2026.6.11 ship a useful default-off package auto-updater, but the requested scheduled approval workflow, notify-only mode, channel-targeted notification, post-restart old/new reporting, and chat update command are still missing. Related items either closed back to this issue or track adjacent updater safety surfaces rather than replacing this canonical workflow request.

## What This Changes

Request a built-in auto-update workflow with opt-in schedule, confirmation/silent/notify-only modes, channel notifications, and post-update reporting.

## Best Possible Solution

Keep this as the canonical updater workflow tracker and design one supervised update flow around `update.run` or the external-updater direction with approval modes, scheduling, safe delivery, durable restart reporting, docs, schema/help, and focused tests.

Not applicable: this is a feature request, not a broken existing behavior report. Source inspection gives high confidence that current main lacks the requested workflow fields, approval modes, scheduler, notification flow, and chat update command surface.

The best path is a maintainer-approved unified engine that separates scheduling, approval, delivery, and restart reporting without duplicating update execution.
