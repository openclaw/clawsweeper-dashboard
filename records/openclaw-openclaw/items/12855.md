## Summary

Keep open: current main and the latest release include a useful default-off package auto-updater, but they still do not implement the requested scheduled approval workflow, notify-only mode, channel-targeted notifications, post-restart old/new reporting, or chat-triggered update surface.

## What This Changes

The issue requests a first-class auto-update workflow with configurable scheduling, confirmation or silent modes, and post-update channel notification.

## Best Possible Solution

Keep this as the canonical updater engine/workflow tracker and design one supervised update workflow around update.run or the external-updater direction with approval modes, safe delivery, durable restart reporting, docs, schema/help, and focused tests.

## Reproduction Assessment

Not applicable; this is a feature request, not a broken existing behavior report. Source inspection shows current main lacks the requested workflow fields, approval modes, scheduler, notification flow, and chat update command surface.

## Solution Assessment

Unclear as proposed: the current package updater is a useful base, but directly adding every requested field risks expanding a compatibility-sensitive config surface. The safer path is a maintainer-approved unified engine that separates scheduling, approval, delivery, and restart reporting without duplicating update execution.
