Keep open: current main and the latest release still project unknown Codex item statuses as completed and can drop unknown or mismatched notifications without projector diagnostics. The issue is paired with an open closing PR, so the right cleanup path is to review and land or close that candidate before closing this issue.

## What This Changes

The issue asks OpenClaw to make the Codex app-server event projector fail closed on unknown item statuses and log unknown or mismatched notifications instead of silently treating them as success or dropping them.

## Best Possible Solution

Land the canonical Codex projector/runtime fix in https://github.com/openclaw/openclaw/pull/99287 once maintainer review accepts the fail-closed protocol-drift behavior and its regression coverage.

## Solution Assessment

Yes. The narrow maintainable solution is to repair the Codex app-server projector/runtime boundary, preserve known status and method behavior, and add focused tests for unknown statuses plus unknown or mismatched notifications.
