- `impact:session-state`: The projector maps native Codex turn notifications into OpenClaw attempt state, so fail-open status mapping and silent notification drops can make session or transcript state drift from the native run.

## Summary

Keep open: current main and the latest release still have the Codex projector status fallthrough, silent dispatch default, and silent turn-correlation drop paths, and I found no merged or open canonical fix replacing this issue. The related watchdog issue overlaps on unknown notifications but tracks a broader timeout problem, not this projector hardening request.

## What This Changes

The issue asks OpenClaw to harden Codex app-server event projection so unknown item statuses fail closed and unknown or mismatched notifications are logged instead of silently succeeding or disappearing.

## Best Possible Solution

Add closed projector diagnostics in the Codex app-server harness: unknown item statuses should become non-success with a warning, and unknown or mismatched notifications should produce redacted, rate-limited log context with regression coverage.

## Reproduction Assessment

Yes by source inspection, though not by executing a live harness repro in this read-only pass. A focused regression test can inject a current-turn unknown status, a current-turn unknown method, and a wrong-turn notification into the projector paths shown above.

## Solution Assessment

Yes, the requested direction is the narrow maintainable fix. Keep it inside the Codex app-server projector/correlation boundary, reuse existing `embeddedAgentLog` patterns, and avoid adding config or protocol surface.
