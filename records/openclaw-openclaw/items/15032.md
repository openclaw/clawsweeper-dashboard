## What This Changes

Request an enforced per-spawn allow/deny tool policy for sub-agents created by `sessions_spawn`.

## Best Possible Solution

Keep this as the canonical tracker and land or replace https://github.com/openclaw/openclaw/pull/78441 once maintainers accept the API shape, persistence model, unsupported-runtime behavior, docs, tests, and security-boundary semantics.

## Reproduction Assessment

Yes. Source inspection on current main shows the `sessions_spawn` schema, spawn params, child-session metadata, and policy resolver still have no caller-selected per-spawn tool restriction field.

## Solution Assessment

Yes at the owner-boundary level: `sessions_spawn` is the right core API point for an enforced child-session tool boundary. The exact V1 contract remains a maintainer product/security decision because allow-only, allow/deny, empty-list, persistence, ACP, and CLI semantics need to be accepted together.
