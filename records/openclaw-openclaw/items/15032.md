## Summary

Keep open: current main and v2026.6.11 still lack a public per-spawn tool restriction for `sessions_spawn`, and https://github.com/openclaw/openclaw/pull/78441 is an open, currently conflicting candidate fix rather than a merged replacement.

## What This Changes

Request an additive `sessions_spawn` per-spawn tool restriction API so child agents can run with narrower allowed or denied tool access.

## Best Possible Solution

Keep this issue as the canonical tracker, then land or replace https://github.com/openclaw/openclaw/pull/78441 after maintainers accept the API shape, persistence model, compatibility behavior, docs, tests, and security-boundary contract.

## Reproduction Assessment

Yes. Source inspection on current main shows the `sessions_spawn` schema, native spawn params, child-session metadata, and subagent policy resolver still have no caller-selected per-spawn tool restriction field.

## Solution Assessment

Yes at the owner-boundary level: `sessions_spawn` is the right core API point for an enforced child-session tool boundary. The exact contract remains a maintainer product/security decision because allow-only, allow/deny, empty-list, persistence, and unsupported-runtime semantics need to be accepted together.
