## What This Changes

Add a per-spawn `sessions_spawn` tool policy so each child session can enforce an allowlist, denylist, or zero-tool mode without changing other sub-agents' permissions.

## System Context

`sessions_spawn` creates a child agent session from a parent agent request. The requested policy must be parsed at spawn time, stored immutably with the child session, and applied whenever that child’s tools are assembled so later turns cannot regain restricted capabilities.

## Architecture Diagram

  F --> G[Restricted tool calls]

## Best Possible Solution

Land one additive, durable `sessions_spawn` policy contract after maintainer approval: preserve existing behavior when omitted, persist the child restriction immutably, enforce it at the final model-facing tool gate on every turn, and prove deny-wins and fail-closed behavior across supported runtimes.
