## Summary

Keep open: current main and v2026.6.11 still lack a public per-spawn tool restriction for `sessions_spawn`, and the active implementation candidate is open but not merged, currently conflicting, and still needs maintainer API/security acceptance.

## What This Changes

Request per-spawn allow/deny tool restrictions for `sessions_spawn` so child sub-agents can run with least-privilege tool access for untrusted-content workflows.

## Best Possible Solution

Keep this as the canonical tracker, then land or replace https://github.com/openclaw/openclaw/pull/78441 once maintainers accept the API shape, persistence model, fail-closed behavior, docs, tests, and security-boundary contract.

## Reproduction Assessment

Yes. Source inspection on current main shows the `sessions_spawn` schema, native spawn params, child-session metadata, and subagent policy resolver still have no caller-selected per-spawn tool restriction field.

## Solution Assessment

Yes at the owner-boundary level: `sessions_spawn` is the right core API point for an enforced child-session tool boundary. The exact shipped contract remains a maintainer product/security decision because allow-only, allow/deny, empty-list, persistence, ACP/CLI behavior, and unsupported runtime semantics need to be accepted together.
