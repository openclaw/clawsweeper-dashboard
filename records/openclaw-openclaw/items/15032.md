## Summary

Keep open: current main and v2026.6.11 still do not expose an enforced per-spawn tool policy for `sessions_spawn`, and the open implementation candidate has not merged yet.

## What This Changes

The issue requests a per-spawn allow/deny tool restriction for `sessions_spawn` so spawned child agents can run with a narrower enforced tool set than the parent.

## Best Possible Solution

Keep this as the canonical tracker until https://github.com/openclaw/openclaw/pull/78441 or a replacement lands with an accepted additive API, durable session policy, docs, tests, and security contract.

## Reproduction Assessment

Yes. Source inspection on current main shows the `sessions_spawn` schema, native spawn params, child-session metadata, and subagent policy resolver still have no caller-selected per-spawn restriction field.

## Solution Assessment

Yes at the owner-boundary level: `sessions_spawn` is the right core API point for an enforced child-session tool boundary. The exact shipped contract still needs maintainer product/security judgment because allow-only, allow/deny, empty-list, persistence, ACP, and fail-closed semantics must be accepted together.
