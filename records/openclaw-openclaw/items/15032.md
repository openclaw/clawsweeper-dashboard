## Summary

Keep open: current main and v2026.6.11 still lack a public per-spawn tool restriction on `sessions_spawn`; https://github.com/openclaw/openclaw/pull/78441 is a live implementation candidate with proof, but it is not merged and does not close this canonical security/API tracker.

## What This Changes

Add an optional per-spawn tool restriction parameter to `sessions_spawn` so spawned sub-agents can run with a narrower enforced tool set.

## Best Possible Solution

Keep this issue as the canonical tracker, then land or replace https://github.com/openclaw/openclaw/pull/78441 once maintainers accept the API shape, persistence model, compatibility behavior, and security-boundary contract.

## Reproduction Assessment

Yes. Source inspection on current main shows the `sessions_spawn` schema, native spawn params, child-session metadata, and policy resolver still have no caller-selected per-spawn tool restriction field.

## Solution Assessment

Yes at the owner-boundary level: `sessions_spawn` is the right core API point for an enforced child-session tool boundary. The exact shipped contract remains a maintainer product/security decision because allow-only, allow/deny, empty-list, persistence, and unsupported runtime semantics need to be accepted together.
