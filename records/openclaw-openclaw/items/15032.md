## Summary

Keep open: current main and the latest release still lack a public per-spawn tool restriction for `sessions_spawn`; https://github.com/openclaw/openclaw/pull/78441 is an open implementation candidate, but it is not merged and live metadata currently reports it as conflicting.

## What This Changes

Request an optional per-spawn tool restriction API for `sessions_spawn` so spawned child agents can run with caller-selected tool access.

## Best Possible Solution

Keep this as the canonical tracker, then land or replace https://github.com/openclaw/openclaw/pull/78441 after maintainers accept the API shape, durable session-policy semantics, compatibility behavior, and security-boundary contract.

## Reproduction Assessment

Yes. Source inspection on current main shows the `sessions_spawn` schema, native spawn params, child-session metadata, and policy resolver still have no caller-selected per-spawn tool restriction field.

## Solution Assessment

Yes at the owner-boundary level: `sessions_spawn` is the right core API point for an enforced child-session tool boundary. The exact shipped contract remains a maintainer product/security decision because allow-only, allow/deny, empty-list, persistence, and unsupported-runtime semantics need to be accepted together.
