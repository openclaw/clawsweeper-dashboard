## Summary

Keep open: current main and v2026.6.11 still do not expose a public per-spawn tool restriction for `sessions_spawn`, and the open candidate PR remains unmerged and needs maintainer API/security acceptance.

## What This Changes

The issue requests per-spawn tool allow/deny controls for sub-agents created through `sessions_spawn` so untrusted-content workers can be capability-restricted.

## Best Possible Solution

Keep this as the canonical tracker, then land or replace the candidate PR once maintainers accept the public API shape, durable policy model, unsupported-runtime behavior, docs, tests, and security-boundary contract.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 show no per-spawn policy carrier in the `sessions_spawn` schema, native spawn params, child-session metadata, or subagent policy resolver.

## Solution Assessment

Yes at the owner-boundary level: `sessions_spawn` is the right core API point for an enforced child-session tool boundary. The exact shipped contract still needs maintainer product/security judgment around allow/deny shape, persistence, empty lists, and unsupported runtimes.
