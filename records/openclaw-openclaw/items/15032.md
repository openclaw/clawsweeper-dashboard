## Summary

Keep open: current main and the latest release still do not expose a public per-spawn tool restriction for `sessions_spawn`, and the open candidate implementation at https://github.com/openclaw/openclaw/pull/78441 has not merged.

## What This Changes

The issue requests a per-call `sessions_spawn` tool policy so spawned sub-agents can be given narrower allow/deny tool access than their parent.

## Best Possible Solution

Keep this issue as the canonical tracker, then land or replace https://github.com/openclaw/openclaw/pull/78441 after maintainers accept the public API and security semantics for per-spawn child tool scoping.

## Reproduction Assessment

Yes. Source inspection of current main shows the `sessions_spawn` schema, native spawn params, child-session metadata, and subagent policy resolver still have no caller-selected per-spawn tool restriction field.

## Solution Assessment

Yes at the owner-boundary level: `sessions_spawn` is the right core API point for an enforced child-session tool boundary. The exact shipped contract remains a maintainer product/security decision because allow-only, allow/deny, empty-list, persistence, ACP handling, and CLI fail-closed semantics need to be accepted together.
