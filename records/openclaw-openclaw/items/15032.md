## Summary

Keep open: current main and v2026.6.11 still do not expose a per-spawn `sessions_spawn` tool restriction, and the open candidate PR has not merged yet.

## What This Changes

Request a per-call tool restriction API for `sessions_spawn` so spawned subagents can run with narrower tool access for least-privilege workflows.

## Best Possible Solution

Keep this as the canonical tracker, then land or replace https://github.com/openclaw/openclaw/pull/78441 once maintainers accept the API shape, persistence model, unsupported-runtime behavior, docs, tests, and security-boundary contract.

## Reproduction Assessment

Yes for the missing capability. Source inspection on current main shows the `sessions_spawn` schema, native spawn params, child-session metadata, and subagent policy resolver still have no caller-selected per-spawn tool restriction field.

## Solution Assessment

Yes at the owner-boundary level: `sessions_spawn` is the right core API point for an enforced child-session tool boundary. The exact shipped contract remains a maintainer product/security decision because naming, allow versus deny semantics, persistence, ACP handling, and fail-closed behavior need to be accepted together.
