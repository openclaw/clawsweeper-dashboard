## Summary

Keep open: current main and the latest release still have no model-callable `clear_goal` or `clearedGoals` history, and the public docs intentionally reserve clearing/replacement for `/goal` and reset controls. The related v02 prototype was closed so this issue could carry the maintainer product-direction decision first.

## What This Changes

Proposal to add a model-callable `clear_goal` tool that clears terminal or paused/limited goals and archives them in bounded `SessionEntry.clearedGoals` history.

## Best Possible Solution

Keep the current operator-only behavior unless the goal lifecycle owner explicitly approves model clearing; if approved, implement a terminal-only canonical-store rotation with metadata, docs, tests, and live agent-turn proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw permit a model-callable `clear_goal` tool for terminal or paused/limited session goals, and what retained-history contract should it have?

Rationale: The request changes a documented model/operator authority boundary and adds durable session history, so code inspection can prove the gap but cannot choose the product contract safely.

Likely owner: steipete

Owner reason: He introduced and merged the current core goals feature and public goal-tool contract that this issue proposes to change.

Owner confidence: high

Options:

- **Keep operator-only clearing (recommended):** Preserve the current contract where models can report `complete` or `blocked`, while clearing/replacement stays with `/goal`, `/new`, and `/reset`; future work could explore non-destructive model requests for operator confirmation.
- **Approve terminal-only clear_goal:** Allow a model tool only for a narrowly approved state set, preferably `complete` and `blocked`, and require a bounded canonical `SessionEntry` archive plus docs, mutation metadata, catalog coverage, and live proof.
- **Approve broader non-active clearing:** Allow clearing paused and limited goals too, but require explicit retention and operator-boundary language because this changes how stop-like states can be removed.

## Reproduction Assessment

Not applicable as a bug reproduction: current source and docs show the behavior is intentional, with clearing reserved for `/goal` and reset controls. The missing `clear_goal` and `clearedGoals` surfaces are source-verifiable on current main.

## Solution Assessment

Unclear until maintainers decide the authority boundary. The canonical-store archive is the right technical direction if the feature is approved, but the allowed states and history lifecycle are product decisions first.
