## Summary

Keep open: current `main` and the latest release still expose only `get_goal`, `create_goal`, and `update_goal`, while the public goal docs intentionally reserve clearing and replacement for operator/session controls. This remains a product-decision issue about whether to expand model authority and add retained cleared-goal session history.

## What This Changes

The issue proposes a model-callable `clear_goal` tool that clears non-active goals and archives them into bounded canonical session-store history.

## Best Possible Solution

A goal lifecycle owner should first approve or reject the model-authority change; if approved, implement terminal-only canonical session-store rotation with metadata, docs, tests, and real agent-turn proof, otherwise keep `/goal clear` operator-only.

- **Preserve operator-only clearing (recommended):** Keep the current contract and close or redirect future `clear_goal` implementation work toward a non-destructive model signal surfaced to the operator.
- **Approve a narrow model clear tool:** Allow `clear_goal` only for maintainer-approved non-active states, with canonical-store history, explicit retention semantics, and full metadata/docs/proof coverage.
- **Approve terminal-only clearing now, defer archive history:** Add a smaller model clear operation for `complete` and `blocked` goals while tracking retained history as a separate product decision.
