## Summary

Keep open: current main and the latest release still expose only `get_goal`, `create_goal`, and `update_goal`, and the public docs still reserve clearing/replacement for operator or session controls. This issue remains the canonical product-decision thread for whether to expand model authority and add retained cleared-goal session history.

## What This Changes

The issue proposes adding a model-callable `clear_goal` tool and bounded canonical `clearedGoals` session history so models can clear terminal goals before creating new ones.

## Best Possible Solution

Maintainers should decide the allowed model authority and retention contract before any v03 implementation adds a core tool or session archive shape.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw allow models to clear terminal or paused goals through a model-callable `clear_goal` tool, and what cleared-goal retention contract should core persist?

Rationale: Current docs reserve goal clearing and replacement for operator/session controls, while the proposal would expand model authority and add a new canonical session history surface.

Likely owner: steipete

Owner reason: The same person introduced core session goals and most recently changed goal controls, making them the best available owner for the product boundary choice.

Owner confidence: high

Options:

- **Keep operator-only clearing:** Preserve the current docs and require users or session controls to clear goals before a model can create a new one.
- **Allow terminal-only model clearing (recommended):** Approve a `clear_goal` tool only for terminal states with bounded canonical session history and no active-goal clearing.
- **Use operator confirmation:** Add a non-destructive model request or status flag that asks the operator to clear/archive the goal instead of letting the model remove it directly.
