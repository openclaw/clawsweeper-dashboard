## Summary

Keep open: current `main` still implements the documented operator-only clear path and has no model-callable `clear_goal` or retained `clearedGoals` archive. The remaining question is a product/security-boundary decision about model authority and session-history retention, not a stale implementation task.

## What This Changes

The issue proposes adding a model-callable `clear_goal` tool that moves non-active goals into bounded canonical session history before clearing the current goal.

## Best Possible Solution

A maintainer should decide the authority boundary first; if approved, the next PR should keep the canonical single-write archive design, define retention and retrieval semantics, and update tool metadata, docs, and real agent-turn proof together.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw allow a model-callable `clear_goal` tool to clear non-active session goals and retain cleared-goal history in canonical session state?

Rationale: Current docs and code intentionally reserve clearing/replacement for operator/session controls, while this proposal changes model authority and adds retained session history semantics.

Likely owner: steipete

Owner reason: He introduced the core goal contract and is the strongest history-backed owner for deciding whether the model-authority boundary should change.

Owner confidence: high

Options:

- **Keep operator-only clearing (recommended):** Preserve the current `/goal clear`, `/new`, and `/reset` boundary and consider a non-destructive model request or operator-confirmed archive workflow later.
- **Approve terminal-only `clear_goal`:** Allow a focused PR that clears only approved non-active states, writes bounded `SessionEntry.clearedGoals`, and updates mutation metadata, catalog, docs, tests, and live proof.
- **Approve a narrower state set:** Permit model clearing only for `complete` and possibly `blocked`, leaving paused and limited states operator-controlled to reduce authority drift.
