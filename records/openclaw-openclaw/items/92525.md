## Summary

Keep open: current main and the latest release still expose only `get_goal`, `create_goal`, and `update_goal`, while docs reserve goal clearing/replacement for operator/session controls. This remains a real product-direction question, not a stale cleanup candidate.

## What This Changes

The issue requests maintainer approval for a model-callable `clear_goal` tool that archives cleared goals in canonical session state before allowing a new model-created goal.

## Best Possible Solution

A maintainer should decide the authority boundary first; if approved, the implementation should be a focused core PR with terminal-only safeguards, canonical session-store history, catalog/mutation/docs/tests updates, and real agent-turn proof.

## Maintainer Decision

Question: Should OpenClaw allow a model-callable `clear_goal` tool for non-active session goals, and what clearable-state and retention contract should it expose?

Rationale: Current source and docs intentionally reserve clearing/replacement for operator/session controls, so changing it expands model authority and session-state retention semantics beyond a mechanical bug fix.

Likely owner: steipete

Owner reason: They introduced and merged the current core session-goal feature and documented model/operator boundary that this proposal would change.

Owner confidence: high

Options:

- **Keep Operator-Only Clearing (recommended):** Leave the current `get_goal`/`create_goal`/`update_goal` model surface unchanged until a feature owner explicitly sponsors a model-authority expansion.
- **Approve Narrow `clear_goal`:** Allow model clearing only for maintainer-approved states, likely `complete` and `blocked`, with bounded `SessionEntry` history and explicit docs/tests/proof.
- **Request Operator-Confirmed Archive:** Let the model signal that a goal is ready to clear while keeping the destructive clear/archive action behind `/goal`, UI, or another operator-confirmed path.

## Reproduction Assessment

Not applicable as a bug reproduction. Source and docs show the current behavior is intentional: model tools are limited to get/create/update, while clearing remains an operator/session control.

## Solution Assessment

Unclear until maintainers decide the model-authority boundary. The canonical-store archive is the right direction if the feature is approved, but states, retention, and retrieval semantics need product approval first.
