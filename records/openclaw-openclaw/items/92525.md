## Summary

Keep open: current main and the latest release still intentionally expose only `get_goal`, `create_goal`, and `update_goal`, while clearing remains an operator/session control. This issue remains the canonical product-direction thread for whether to expand model authority and add retained cleared-goal session history.

## What This Changes

Request to add a model-callable `clear_goal` tool that can clear approved non-active goal states while atomically archiving cleared goals in canonical session state.

## Best Possible Solution

Keep the current operator-only clearing contract until a maintainer explicitly approves a narrower model-authority design; if approved, implement it in one focused PR with canonical session-store history, mutation/catalog/docs/test updates, and real agent-turn proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw allow models to clear terminal or paused session goals through a new `clear_goal` tool, and if so which states and retention contract should be supported?

Rationale: The current source and docs intentionally reserve clearing, pausing, resuming, and replacing goals for operator/session controls, so adding model-callable clearing changes product authority rather than fixing a broken contract.

Likely owner: steipete

Owner reason: They introduced and merged the current core session-goals contract and are the strongest history-backed owner for deciding whether that model authority boundary should change.

Owner confidence: high

Options:

- **Keep operator-only clearing (recommended):** Preserve the current documented boundary where models can complete or block goals, and users clear them with `/goal clear` or reset controls.
- **Approve terminal-only clear_goal:** Add a model-callable clear tool for a maintainer-approved non-active state set, with bounded canonical session-store archive semantics.
- **Approve complete/blocked only:** Allow clearing only after model-reachable `complete` or `blocked` states while leaving paused and limit states operator-controlled.

## Reproduction Assessment

Not applicable as a bug reproduction: source and docs show the current model/tool behavior is intentional, with clearing reserved for `/goal clear` and reset controls. The requested work is a product capability change, not a current-main failure.

## Solution Assessment

Unclear until maintainer direction: the canonical-store archive is a better shape than the discarded JSONL sidecar, but the authority boundary, allowed states, retention, and retrieval semantics need approval before implementation.
