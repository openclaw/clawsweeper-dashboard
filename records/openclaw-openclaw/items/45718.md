## Summary

Keep open: current main and v2026.6.11 mitigate the older large `skillsSnapshot.prompt` duplication with prompt blobs, but `systemPromptReport` is still persisted per session entry and recent production data says that remaining field now dominates large stores.

## What This Changes

The issue asks OpenClaw to stop durable `sessions.json` bloat from repeated `skillsSnapshot` and `systemPromptReport` persistence.

## Best Possible Solution

Keep prompt-ref storage for large skill prompts, then replace full inline `systemPromptReport` persistence with a smaller canonical durable state for restart warning dedupe, avoiding a new ad hoc JSON sidecar.

## Maintainer Decision

Question: Should OpenClaw keep the full `systemPromptReport` inline in every session entry, or persist only the smaller restart/dedupe state needed from that report?

Rationale: Current tests intentionally preserve the report for warning dedupe, while production data shows that the same object now dominates large session stores; automation should not choose the durable metadata boundary alone.

Likely owner: steipete

Owner confidence: high

Options:

- **Persist Only Dedupe State (recommended):** Store the minimal warning-signature state needed after restart and omit or recompute large tools, skills, and prompt-report details from inactive session rows.
- **Keep Full Report Inline:** Accept larger `sessions.json` rows and rely on pruning, entry caps, and operator cleanup rather than changing the report durability contract.
- **Move Report To Canonical Store:** Move large report details out of the session index into an approved canonical store with cleanup semantics, instead of adding an unowned sidecar file.

## Reproduction Assessment

Yes from source for the remaining problem: successful runs with `systemPromptReport` still write that object into durable session entries, and the save path serializes it. I did not run a live long-duration store-growth reproduction.

## Solution Assessment

Unclear as an implementation path: prompt blobs are the right current fix for large skill prompts, but the remaining `systemPromptReport` bloat needs a maintainer-owned durability decision before a safe patch.
