## Summary

Keep open: current main and v2026.6.11 mitigate large `skillsSnapshot.prompt` duplication with content-addressed prompt blobs, but they still persist full `systemPromptReport` data per session row and the latest production data says that is now the dominant duplicated payload.

## What This Changes

The issue reports unbounded `sessions.json` growth from repeated `skillsSnapshot` and `systemPromptReport` payloads across agent runs.

## Best Possible Solution

Keep this focused tracker open until maintainers choose and implement a durable session-store shape that preserves minimal warning-dedupe/context-report state without duplicating bulky prompt-report payloads in every retained row.

Kind: product_direction

Question: What durable storage shape should replace inline per-session `systemPromptReport` while preserving bootstrap warning dedupe and context-reporting semantics?

Rationale: The remaining bug is source-supported and field-supported, but the current report metadata is intentionally load-bearing for warning dedupe and diagnostics, so automation should not choose the long-term data contract unilaterally.

Likely owner: steipete

Owner reason: This handle has the strongest history across the prompt-report-adjacent session-store path and the recent persisted skill-prompt mitigation.

Owner confidence: high

Options:

- **Persist Minimal Report State (recommended):** Store only the small warning-dedupe and current display fields in session rows, making bulky tools/skills/workspace report sections recomputable or diagnostic-only.
- **Use Out-Of-Line Report Blobs:** Move large repeated report sections to content-addressed storage and keep compact refs in `sessions.json`, similar to the skill-prompt mitigation.
- **Keep Inline Reports:** Retain the current inline report design and rely on retention/capping, accepting continued duplicated metadata in retained session rows.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 still persist per-session `systemPromptReport`, and current main still reads/parses the full session store. I did not run a long-duration live Gateway reproduction.

## Solution Assessment

No complete fix is on main: prompt blobs address the `skillsSnapshot.prompt` half, while full `systemPromptReport` data still persists per row. The best fix needs a maintainer-approved durable metadata policy before code repair.
