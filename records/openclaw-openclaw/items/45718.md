## Summary

Keep open: current main has mitigated the large `skillsSnapshot.prompt` duplication with prompt blobs, but it still persists a full `systemPromptReport` into session entries and recent production data says that report is now the dominant duplicated payload.

## What This Changes

This issue requests stopping `sessions.json` growth from repeated `skillsSnapshot` and `systemPromptReport` data across agent runs and sessions.

## Best Possible Solution

Persist only the compact warning-dedupe state or move bulky prompt-report diagnostics out of `sessions.json`, while keeping `sessions.json` as small session metadata and avoiding a new config knob.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: any command or cron run that returns `meta.systemPromptReport` persists that report into the session entry, and the current test asserts that behavior. I did not run a live Gateway reproduction because this review is read-only.

## Solution Assessment

No, the currently linked strip-`skillsSnapshot` approach is only a partial mitigation because current main already blob-dedupes skills prompts while the full report remains inline. The better fix is a maintainer-approved compact or out-of-line report persistence policy.
