## Summary

Keep open: current main and v2026.6.11 mitigate the skillsSnapshot prompt duplication with prompt blobs, but the remaining systemPromptReport payload is still persisted inline per session entry, matching the latest production data that this is now the dominant bloat source.

## What This Changes

The issue asks OpenClaw to stop sessions.json from accumulating duplicate skillsSnapshot and systemPromptReport data on repeated agent runs.

## Best Possible Solution

Persist only compact session state or refs needed for warning dedupe, keep /context diagnostics available through active or recomputed reports, and replace or revise the linked PR so systemPromptReport is not duplicated inline across inactive session entries.

- **Keep report inline for now:** Accept the sessions.json size cost until a broader database-first session migration or diagnostics redesign owns the storage shape.
- **Land skills-only mitigation:** Take the linked PR as a partial fix while leaving the systemPromptReport bloat tracked here or in a narrower follow-up.

## Reproduction Assessment

Yes, by source inspection and production data: current main still writes systemPromptReport into SessionEntry on interactive and cron completion, and v2026.6.11 has the same persistence path. I did not run a live long-duration bloat repro in this read-only review.

## Solution Assessment

No, the current partial mitigation is not the best complete fix because it externalizes skills prompts but leaves full systemPromptReport duplicated inline. The maintainable fix should separate compact durable warning/report state from heavyweight diagnostics before removing the inline payload.
