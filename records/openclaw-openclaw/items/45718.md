## Summary

Keep open: current main has already reduced the older large `skillsSnapshot.prompt` duplication with prompt blobs, but the remaining `systemPromptReport` payload is still deliberately persisted per session entry and recent production data says that field now dominates large stores.

## What This Changes

The issue reports unbounded per-session persistence of `skillsSnapshot` and `systemPromptReport` metadata in `sessions.json`.

## Best Possible Solution

Keep the prompt-blob mitigation for large skill prompts and define a smaller canonical durability path for the `systemPromptReport` state needed after restart, without adding another ad hoc JSON sidecar.

- **Move report out of line:** Store report details in a canonical non-index store with cleanup semantics, avoiding a new ad hoc JSON sidecar unless maintainers approve the storage shape.

Yes from source for the remaining problem: every successful run with `result.meta.systemPromptReport` assigns that object back into the `SessionEntry`, and the persistence path serializes the entry unless a maintainer changes the durability policy.

## Solution Assessment

Unclear: stripping or externalizing the remaining report is plausible, but current tests say warning dedupe depends on persisted `systemPromptReport`, so the best fix needs a maintainer-owned metadata durability decision.
