## Summary

Keep open: current main and the latest stable release mitigate the old duplicated `skillsSnapshot.prompt` payload with prompt blobs, but they still persist full `systemPromptReport` data per session row and still parse whole `sessions.json` files, matching the latest production report.

## What This Changes

The issue asks OpenClaw to stop `sessions.json` from growing through repeated per-session `skillsSnapshot` and `systemPromptReport` metadata.

## Best Possible Solution

Keep this tracker open until maintainers choose and implement a compact report-storage policy that preserves warning-dedupe semantics without duplicating full prompt-report payloads across retained session rows.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What durable `systemPromptReport` policy should OpenClaw use for `sessions.json` entries while preserving once-mode bootstrap warning dedupe?

Rationale: Current source intentionally persists the report for warning dedupe, while field data shows the full report now dominates session-store size, so automation cannot safely choose the storage semantics alone.

Likely owner: Peter Steinberger

Owner reason: He owns the strongest feature-history trail for prompt reports and the adjacent shipped prompt-blob mitigation.

Owner confidence: high

Options:

- **Persist Minimal Report State (recommended):** Store only the small warning-dedupe state in session rows and make bulky report sections recomputable or diagnostic-only.
- **Use Out-of-line Report Blobs:** Move large report payloads to content-addressed storage similar to skill prompts, with compact refs in session rows.
- **Retain Inline Reports:** Keep the current inline design and rely on pruning/capping, accepting continued duplicated metadata in retained rows.
