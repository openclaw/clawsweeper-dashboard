## Summary

Keep open: current main and v2026.6.11 mitigate the large `skillsSnapshot.prompt` duplication with prompt blobs, but `systemPromptReport` is still persisted into each durable session entry and recent field data says it is now the dominant duplicated payload.

## What This Changes

The issue requests preventing repeated per-session persistence of large `skillsSnapshot` and `systemPromptReport` metadata that bloats `sessions.json` and pressures session/context handling.

## Best Possible Solution

Store only minimal durable warning-dedupe state in session rows and move bulky prompt-report diagnostics to recomputation or content-addressed/out-of-line storage, with migration or doctor coverage for existing rows.

Rationale: Current source intentionally persists the report for warning dedupe, but field data shows the full report now dominates retained session rows; choosing minimal state versus out-of-line reports is a maintainer storage-policy decision.

Owner confidence: high

Options:

- **Persist Minimal Warning State (recommended):** Store only the warning-dedupe state needed across runs and stop retaining bulky tools, skills, and injected-file report sections in session rows.
- **Out-Of-Line Report Blobs:** Use content-addressed or session-scoped report blobs/refs similar to skill prompt blobs, preserving diagnostics without repeating them inline.
- **Keep Inline Reports:** Retain the current inline shape and rely on pruning/capping, accepting continued duplicated metadata in retained rows.

## Reproduction Assessment

Yes, at source level: current main still builds prompt reports and persists them into session entries after runs. I did not run a live long-duration Gateway soak in this read-only review.

## Solution Assessment

No current implementation is the full fix: prompt blobs address the `skillsSnapshot.prompt` half, while `systemPromptReport` still needs a smaller durable state or out-of-line diagnostic design.
