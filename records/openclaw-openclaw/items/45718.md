## Summary

Keep open: current main and the latest release have mitigated large `skillsSnapshot.prompt` duplication with prompt blobs, but `systemPromptReport` is still persisted per session entry and recent production data says it is now the dominant `sessions.json` payload.

## What This Changes

The issue asks OpenClaw to stop per-run accumulation of `skillsSnapshot` and `systemPromptReport` data in per-agent session stores.

## Best Possible Solution

Keep this focused tracker open until maintainers choose and implement a session-store policy that preserves needed warning-dedupe state without duplicating full `systemPromptReport` payloads across retained session rows.

## Reproduction Assessment

Yes at source level: current main still persists `systemPromptReport` through both agent-command and auto-reply session write paths. I did not run a live long-running Gateway soak in this read-only review.

## Solution Assessment

No, current main is only a partial solution: prompt blobs address `skillsSnapshot.prompt`, while full `systemPromptReport` objects remain durable per session row. The best fix needs a maintainer-approved metadata compaction or out-of-line storage policy that preserves warning dedupe.
