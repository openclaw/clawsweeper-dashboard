## Summary

Keep open: current main and v2026.6.11 mitigate the large `skillsSnapshot.prompt` duplication with prompt blobs, but they still persist full `systemPromptReport` payloads into durable session entries, matching the recent production data that this is now the dominant remaining `sessions.json` bloat.

## What This Changes

The issue asks OpenClaw to stop durable session rows from accumulating duplicated `skillsSnapshot` and `systemPromptReport` payloads on repeated agent runs.

## Best Possible Solution

Keep this focused tracker open until maintainers choose and land a durable session-metadata policy that preserves warning dedupe without duplicating full `systemPromptReport` payloads across retained rows.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 still persist `systemPromptReport` into durable session entries, while the issue discussion includes production data showing that payload dominates the store. I did not run a live long-running Gateway soak in this read-only review.

## Solution Assessment

No: current main is only a partial solution because prompt blobs address `skillsSnapshot.prompt`, while `systemPromptReport` still remains durable per session row. A safe fix needs a maintainer-approved compact durable warning-dedupe/report policy.
