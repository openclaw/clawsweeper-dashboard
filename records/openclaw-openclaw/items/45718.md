## Summary

Keep open: current main mitigates the large `skillsSnapshot.prompt` duplication with prompt blobs, but `systemPromptReport` is still persisted as full per-session metadata and recent field data says that is now the dominant retained payload.

## What This Changes

The issue reports unbounded `sessions.json` growth from repeated `skillsSnapshot` and `systemPromptReport` session metadata across agent runs.

## Best Possible Solution

Keep this focused tracker open until maintainers replace inline full `systemPromptReport` persistence with a compact durable warning-dedupe and diagnostics policy while retaining the current prompt-blob mitigation for `skillsSnapshot`.

Question: What durable session-store shape should replace inline full `systemPromptReport` storage while preserving warning dedupe and useful diagnostics?

Rationale: Current source intentionally persists prompt reports for warning dedupe, while field data shows the full report is now the dominant duplicated session-row payload; automation should not choose that durability contract alone.

Likely owner: steipete

Owner confidence: high

Options:

- **Persist Minimal Report State (recommended):** Store only the small warning-dedupe state in session rows and make bulky report sections recomputable or diagnostic-only.
- **Use Out-Of-Line Report Blobs:** Move large report payloads to content-addressed storage similar to skill prompts, with session rows keeping compact refs.
- **Keep Inline Reports:** Retain the current inline design and rely on pruning or caps, accepting continued duplicated metadata in retained rows.

## Reproduction Assessment

Yes for source reproduction: current main copies `result.meta.systemPromptReport` into durable `SessionEntry` rows and has a test preserving it for warning dedupe. I did not run a live long-running Gateway soak in this read-only review.

## Solution Assessment

No current implementation is a complete fix: prompt blobs address the `skillsSnapshot.prompt` duplication, but `systemPromptReport` remains full inline session metadata. The best fix needs a maintainer-approved compact durability policy rather than only stripping fields blindly.
