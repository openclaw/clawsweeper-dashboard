## Label Justifications

- `P1`: The issue reports real gateway CPU stalls, context overflow, wedge/OOM pressure, and broken agent/channel workflows on long-running deployments.
- `impact:session-state`: The affected data is duplicated persisted session metadata in sessions.json, including prompt/report state used across runs.

- `maturity:stable`: The issue affects Gateway runtime availability, and gateway-runtime is scored M4 Stable in qa/maturity-scores.yaml.

## Summary

Keep open: current main and v2026.6.11 mitigate the old large skillsSnapshot.prompt duplication with promptRef blobs, but current source still persists full systemPromptReport payloads into durable session rows, and recent field data says that is now the dominant session-store bloat.

## What This Changes

The issue requests bounded session persistence so skillsSnapshot and systemPromptReport do not repeatedly bloat agents/<agent>/sessions/sessions.json across runs.

## Best Possible Solution

Split the small durable warning-dedupe state from heavyweight prompt diagnostics, keep or extend the promptRef-style skills mitigation, and prove active-session diagnostics, stale-session compaction, upgrade behavior, and representative gateway store size under load.

Kind: product_direction

Question: Should OpenClaw stop persisting full inline systemPromptReport objects in session entries by splitting durable warning-dedupe state from heavyweight prompt diagnostics?

Rationale: The source path is clear, but the permanent shape affects durable session metadata, diagnostics, warning dedupe across restarts, and upgrade semantics; automation should not choose that policy alone.

Likely owner: steipete

Owner confidence: high

Options:

- **Split Compact State (recommended):** Persist only the small warning-dedupe state needed across restarts and make heavyweight prompt diagnostics transient, recomputable, or stored behind a compact reference.
- **Keep Inline Reports Temporarily:** Accept the sessions.json size cost until a broader session metadata or database migration owns diagnostics storage end to end.
- **Require Linked PR Expansion:** Treat the open linked fork PR as partial source work and require it to address systemPromptReport semantics before it can close this issue.

## Reproduction Assessment

Yes at source level: current main still writes systemPromptReport into durable session entries on interactive and cron paths while field reports show duplicated-payload pressure. I did not run a live long-duration bloat repro in this read-only review.

## Solution Assessment

No current implementation fully solves it: promptRef blobs address large skills prompts, but full prompt reports remain duplicated inline. The best fix needs a maintainer-approved compact durable state or reference design before removing the inline payload.
