## Summary

Keep open: current main and v2026.6.11 mitigate the large `skillsSnapshot.prompt` duplication with prompt blobs, but `systemPromptReport` is still persisted per session entry and recent v2026.6.10 field data says it is now the dominant `sessions.json` payload.

## What This Changes

The issue reports unbounded `sessions.json` growth because retained session entries duplicate `skillsSnapshot` and `systemPromptReport` metadata across agent runs.

## Best Possible Solution

Keep the issue open and land a maintainer-approved lightweight session-row policy that preserves warning dedupe while compacting, recomputing, or moving large `systemPromptReport` data out of retained rows.

Rationale: The code can clearly reproduce the remaining per-row report retention, but the fix must choose what prompt-report details remain durable, what is recomputed or stored out of line, and how existing warning-dedupe state survives upgrades.

Likely owner: steipete

Owner reason: Peter has the strongest feature-history and session-store ownership signal for both the prompt-report feature and the affected persistence paths.

Owner confidence: high

Options:

- **Lightweight row plus preserved dedupe (recommended):** Persist only the minimal warning-dedupe/current-summary state in session rows and move, truncate, or recompute bulky report sections with migration or compaction coverage.
- **Out-of-line report blobs:** Store full reports by content hash or session-scoped blob while rows keep references, accepting a new durable artifact lifecycle to manage cleanup and repair.
- **Keep inline with stronger retention:** Rely on pruning, caps, and cleanup to bound the index while accepting retained-row duplication for diagnostics and compatibility.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: current main and v2026.6.11 still persist `systemPromptReport` into durable session rows, while the skills prompt duplication is only partly mitigated by prompt blobs. I did not run a live multi-session soak.

## Solution Assessment

Is this the best way to solve the issue? Not yet: the current prompt-blob implementation is a good partial fix for `skillsSnapshot.prompt`, but it does not address the remaining `systemPromptReport` duplication. The best fix needs an explicit durable-metadata policy before implementation.
