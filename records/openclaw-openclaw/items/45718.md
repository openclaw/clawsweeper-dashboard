## Summary

Keep open: current main and v2026.6.11 mitigate the older skillsSnapshot.prompt duplication with promptRef blobs, but current code still persists full systemPromptReport payloads per session and recent field data says that is now the dominant session-store bloat.

## What This Changes

The issue asks OpenClaw to stop accumulating duplicate skillsSnapshot and systemPromptReport payloads in sessions.json across agent runs.

## Best Possible Solution

Persist only compact durable warning/report state or content-addressed refs for heavyweight prompt diagnostics, keep the promptRef skills mitigation, and prove active-session diagnostics plus upgrade behavior with focused tests and a representative gateway soak.

Options:

- **Split Compact State (recommended):** Persist only the small state needed across restarts and rebuild, reference, or omit heavyweight diagnostics outside the session index.
- **Keep Inline Reports:** Accept the sessions.json size cost until a broader database-first session migration or diagnostics redesign owns the storage shape.
- **Rework Skills-Only PR:** Treat the open linked fork PR as partial source work and require it to address systemPromptReport semantics before it can close this issue.

## Reproduction Assessment

Yes, at source level: current main still writes systemPromptReport into durable session entries on interactive and cron paths while field reports show the same duplicated-payload pressure. I did not run a live long-duration bloat repro in this read-only review.

## Solution Assessment

No, the current implementation is only a partial fix because promptRef blobs address large skills prompts while full prompt reports remain duplicated inline. The best fix needs a maintainer-approved compact durable state or ref design before removing the inline payload.
