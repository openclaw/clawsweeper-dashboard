## Summary

Keep open: current main and v2026.6.11 mitigate large `skillsSnapshot.prompt` duplication with prompt blobs, but they still persist full `systemPromptReport` data per session row and recent production data says that is now the dominant duplicated payload.

## What This Changes

This issue asks OpenClaw to stop unbounded `sessions.json` growth from repeated `skillsSnapshot` and `systemPromptReport` payloads across agent runs.

## Best Possible Solution

Keep this focused tracker open until maintainers choose a durable session-store shape that preserves minimal warning-dedupe/context-report state without duplicating bulky prompt-report payloads in every retained row.

Options:

- **Persist Minimal Report State (recommended):** Store only the small warning-dedupe and current display fields in session rows, making bulky tools/skills/workspace report sections recomputable or diagnostic-only.
- **Out-Of-Line Report Blobs:** Move large repeated report sections to content-addressed storage and keep compact refs in `sessions.json`, similar to the skill-prompt mitigation.
- **Keep Inline Reports:** Retain the current inline report design and rely on retention/capping, accepting continued duplicated metadata in retained session rows.

## Solution Assessment

No current implementation is the complete fix: prompt blobs address the `skillsSnapshot.prompt` half, while full `systemPromptReport` data still persists per row. The best fix needs a maintainer-approved durable metadata policy before code repair.
