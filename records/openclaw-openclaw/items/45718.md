## Summary

Keep open: current main mitigates the older `skillsSnapshot.prompt` duplication with prompt blobs, but the remaining `systemPromptReport` payload is still intentionally persisted per session entry and still has live runtime/API consumers.

## What This Changes

The issue reports unbounded `sessions.json` growth from per-session `skillsSnapshot` and `systemPromptReport` persistence that can cause context pressure and gateway stalls.

## Best Possible Solution

Persist only the small warning-dedupe state needed across restarts, or otherwise compact/move full report data out of per-session `sessions.json` entries while keeping usage/reporting consumers working.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw preserve the full `systemPromptReport` per session, persist only the warning-dedupe subset, or move report data out of `sessions.json` entirely?

Rationale: Current source and tests make `systemPromptReport` load-bearing for warning dedupe, while issue evidence shows the full report can dominate large stores; automation should not choose that storage contract alone.

Likely owner: steipete

Owner reason: The merged prompt-dedupe PR is the closest current-main feature-history signal for this session storage boundary.

Owner confidence: high

Options:

- **Persist only dedupe state (recommended):** Store `bootstrapTruncation.warningSignaturesSeen` durably and stop persisting bulky tools, skills, and workspace report sections per session.
- **Compact stale reports:** Keep full reports only for active or recent sessions and strip or summarize them during session maintenance for stale entries.
- **Move reports to a new store:** Design a canonical non-`sessions.json` store for context-weight/report details and migrate consumers such as the usage API to it.

## Reproduction Assessment

Yes at source level: current main still persists `systemPromptReport` per session entry, and the issue includes production measurements showing that field dominating `sessions.json`. No live gateway repro was run in this read-only review.

## Solution Assessment

No current implementation fully solves it: prompt blobs address the older `skillsSnapshot.prompt` duplication, but the remaining `systemPromptReport` payload is intentionally persisted and needs a narrower durable-state design.
