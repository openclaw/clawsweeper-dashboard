## Summary

Keep open: current main and v2026.6.11 mitigate the large `skillsSnapshot.prompt` duplication with prompt blobs, but the focused `systemPromptReport` bloat remains in the durable session-entry write paths and is backed by recent production data.

## What This Changes

The issue asks OpenClaw to stop repeated per-session persistence of bulky `skillsSnapshot` and `systemPromptReport` metadata that makes `sessions.json` grow until session context and gateway behavior degrade.

## Best Possible Solution

Keep the prompt-blob mitigation and add a maintainer-approved compact durable contract for prompt-report warning dedupe and diagnostics so retained session rows no longer duplicate full `systemPromptReport` payloads.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 still persist `systemPromptReport` into durable session entries, while the issue includes production data showing that payload dominates a large store. I did not run a live long-running Gateway soak in this read-only review.

## Solution Assessment

No: current main is only a partial solution because prompt blobs address `skillsSnapshot.prompt`, while `systemPromptReport` still remains durable per session row. A safe fix needs a maintainer-approved compact warning-dedupe/report policy rather than a blind strip.
