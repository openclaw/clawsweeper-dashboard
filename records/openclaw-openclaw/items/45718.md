## Summary

Keep open: current main and v2026.6.11 externalize large skills prompts, but full `systemPromptReport` payloads are still persisted per retained session entry, and recent field data confirms that is now the focused unresolved bloat source.

## What This Changes

The issue reports unbounded `sessions.json` growth from per-session `skillsSnapshot` and `systemPromptReport` payloads, with `systemPromptReport` remaining dominant after the skill-prompt mitigation.

## Best Possible Solution

Keep this as the focused `systemPromptReport` metadata tracker, preserve the existing skill-prompt blob mitigation, and design a minimal durable prompt-report representation or active-only/out-of-line storage with migration and cleanup proof.

Rationale: The source-level bug is clear, but choosing between active-only retention, truncation, out-of-line storage, or a minimal dedupe summary changes durable session metadata semantics and upgrade behavior.

Owner confidence: high

Options:

- **Persist Minimal Durable Summary (recommended):** Keep only the warning-dedupe and small diagnostic fields needed across restarts, and drop or externalize large `tools`, `skills`, and injected-file arrays from retained rows.
- **Out-of-line Full Reports:** Store full reports by content hash or session-scoped artifact and keep `sessions.json` as a lightweight index with explicit cleanup ownership.
- **Active-only Inline Reports:** Keep full reports only for active/current sessions and strip them from stale entries during maintenance or write-time compaction.

## Reproduction Assessment

Yes at source level: current main still writes full `systemPromptReport` objects into durable session entries, while current and related field reports show duplicated prompt reports dominating large `sessions.json` files. I did not run a long-duration live gateway soak in this read-only review.

## Solution Assessment

No current implementation fully solves the issue: skill prompt blobs are a good partial fix, but the remaining `systemPromptReport` storage policy needs maintainer direction before a durable code change.
