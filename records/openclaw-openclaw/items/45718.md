## Summary

Keep open: current main and the latest release mitigate the older large `skillsSnapshot.prompt` duplication, but `systemPromptReport` is still persisted in each session entry and recent production data says that field now dominates large `sessions.json` stores.

## What This Changes

The issue asks OpenClaw to stop unbounded session-store growth from repeated `skillsSnapshot` and `systemPromptReport` metadata in `sessions.json`.

## Best Possible Solution

Keep the prompt-blob mitigation and define a smaller canonical durability path for the report state needed after restart, then compact legacy session rows so `sessions.json` stays a lightweight index.

Options:

- **Persist Only Dedupe State (recommended):** Store the small `bootstrapTruncation.warningSignaturesSeen` state needed after restart and omit or rebuild large tools, skills, and prompt-report details from inactive session rows.
- **Keep Full Report Inline:** Accept the current session-store size tradeoff and handle bloat through pruning, caps, and live operational guidance instead of changing report durability.
- **Move Report To Canonical Storage:** Move detailed reports out of the per-session index behind the session storage boundary, with cleanup semantics and migration/compaction for existing rows.

## Reproduction Assessment

Yes from source: a successful run with `result.meta.systemPromptReport` still writes that object into the session entry, and the store serialization path persists it unless maintainers change the durability policy. I did not run a long-duration live soak in this read-only review.

## Solution Assessment

Unclear: prompt refs are the right partial fix for large skill prompts, but the remaining `systemPromptReport` payload needs a maintainer-owned decision about what report state must survive restarts.
