## Summary

Keep open: current main and v2026.6.11 mitigate the large `skillsSnapshot.prompt` duplication with prompt blobs, but `systemPromptReport` is still persisted per session row and recent production data says it is now the dominant `sessions.json` payload.

## What This Changes

The issue asks OpenClaw to stop unbounded session-store growth from repeated `skillsSnapshot` and `systemPromptReport` persistence.

## Best Possible Solution

Keep this focused tracker open until maintainers choose a durable session metadata policy that deduplicates, truncates, or moves `systemPromptReport` out of per-session rows while preserving warning dedupe and the existing skill-prompt mitigation.

## Reproduction Assessment

Yes at source level: current main still writes `systemPromptReport` into durable session entries in the agent command and auto-reply paths, and the discussion includes v2026.6.10 production data. I did not run a live Gateway soak.

## Solution Assessment

No: current main is only a partial solution because prompt blobs mitigate `skillsSnapshot.prompt`, while `systemPromptReport` still remains durable per session row. The open linked fork PR is not the best full fix because it intentionally preserves that remaining payload.
