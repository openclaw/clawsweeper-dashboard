## Summary

Keep open: current main and the latest release still persist full `systemPromptReport` payloads in durable session rows, while the large `skillsSnapshot.prompt` portion is only partially mitigated by prompt blobs.

## What This Changes

The issue asks OpenClaw to stop persisting repeated `skillsSnapshot` and `systemPromptReport` payloads per session row so `sessions.json` does not grow unbounded.

## Best Possible Solution

Design a durable prompt-report storage policy that keeps only minimal cross-restart warning/diagnostic state inline, externalizes or drops large repeated report sections, and includes cleanup proof for existing retained rows.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What durable `systemPromptReport` representation should OpenClaw keep in retained session entries?

Rationale: The source-level bug is clear, but choosing minimal inline summary, active-only retention, or out-of-line full reports changes session metadata semantics and diagnostic behavior.

Likely owner: steipete

Owner reason: This handle has the strongest history across the prompt-report feature and the adjacent persisted prompt-blob mitigation.

Owner confidence: high

Options:

- **Persist Minimal Durable Summary (recommended):** Keep only warning-dedupe and small diagnostic fields inline, and drop or externalize large `tools`, `skills`, and injected-file arrays from retained rows.
- **Store Full Reports Out Of Line:** Move full reports behind a content hash or session artifact and keep `sessions.json` as a lightweight index with explicit cleanup ownership.
- **Retain Full Reports Only For Active Sessions:** Keep the full report for the current active row but strip it from stale entries during write-time or maintenance compaction.

## Reproduction Assessment

Yes at source level: current main still writes full `systemPromptReport` objects into durable session entries, and related production comments show duplicated reports dominating large `sessions.json` files. I did not run a fresh long-duration gateway soak in this read-only review.

## Solution Assessment

No current implementation fully solves it: prompt-blob externalization is a good partial fix, but the remaining durable prompt-report policy needs a maintainer-chosen minimal, active-only, or out-of-line design.
