## Summary

Keep open: current main and v2026.6.11 mitigate the `skillsSnapshot.prompt` duplication with prompt blobs, but `systemPromptReport` is still built and persisted in each session row, matching the latest production data that prompt-report duplication is now the dominant retained payload.

## What This Changes

The issue requests stopping repeated per-session `skillsSnapshot` and `systemPromptReport` storage from causing unbounded `sessions.json` growth and gateway/context failures.

## Best Possible Solution

Store only compact warning-dedupe state in session rows and make bulky prompt-report sections transient, recomputable, or out-of-line, with migration/compaction and regression coverage across CLI, embedded, and gateway session-store paths.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What durable shape should replace inline per-session `systemPromptReport` storage while preserving bootstrap warning dedupe and compatibility?

Rationale: Current source intentionally persists the report for warning dedupe, while recent field data shows the full report now dominates retained session-store size; automation cannot choose that storage policy safely.

Likely owner: steipete

Owner reason: He introduced the prompt-report feature and authored the adjacent prompt-blob mitigation, making him the strongest routing owner for the storage-policy choice.

Owner confidence: high

Options:

- **Persist Minimal Report State (recommended):** Keep only small warning-dedupe fields in the session row and make bulky report sections diagnostic-only, transient, or recomputable.
- **Use Out-of-Line Report Blobs:** Move large report payloads to content-addressed storage with compact refs in session rows, similar to skill prompt blobs.
- **Retain Inline Reports:** Keep the current inline design and rely on pruning/capping, accepting duplicated prompt metadata in retained rows.

## Reproduction Assessment

Yes at source level: current main builds prompt reports, reads prior report state for warning dedupe, and persists `result.meta.systemPromptReport` into durable session entries. I did not run a live long-running Gateway soak.

## Solution Assessment

No current implementation is a complete fix: prompt blobs address `skillsSnapshot.prompt`, while full `systemPromptReport` remains durable per session row. The safer fix needs a maintainer-approved compact durability shape rather than wholesale deletion.
