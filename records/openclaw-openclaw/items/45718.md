## Summary

Keep open: current main and v2026.6.11 already reduce the old `skillsSnapshot.prompt` duplication with promptRef blobs, but full `systemPromptReport` payloads are still persisted per session entry and recent production data says that is now the dominant store bloat.

## What This Changes

The issue asks OpenClaw to stop unbounded `sessions.json` growth from repeated per-session `skillsSnapshot` and `systemPromptReport` persistence.

## Best Possible Solution

Persist only compact durable warning/report state or refs, keep promptRef mitigation for skills prompts, and prove active-session diagnostics plus upgrade behavior with focused tests and a representative gateway soak.

## Solution Assessment

No, the current implementation is only a partial fix: promptRef blobs address large skills prompts, but full prompt reports remain duplicated inline. The maintainable fix should separate compact durable warning/report state from heavyweight diagnostics before removing the inline payload.
