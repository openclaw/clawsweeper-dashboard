## Summary

Keep open: current main has largely mitigated the `skillsSnapshot.prompt` duplication with prompt blobs, but full `systemPromptReport` objects are still stored per retained session entry and recent field data shows that payload is now the focused unresolved bloat source.

## What This Changes

The issue requests bounded session-store persistence for `skillsSnapshot` and `systemPromptReport` so repeated agent runs do not grow `sessions.json` until context or gateway pressure appears.

## Best Possible Solution

Keep this as the focused `systemPromptReport` metadata tracker, preserve the existing skills prompt-blob mitigation, and implement a maintainer-approved minimal-summary, active-only, or out-of-line report policy with migration and cleanup proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What durable `systemPromptReport` storage policy should OpenClaw use for retained session entries without regressing warning dedupe or context diagnostics?

Rationale: The source-level bug is clear, but choosing between minimal summaries, active-only retention, and out-of-line full reports changes persisted session metadata semantics and upgrade behavior.

Likely owner: steipete

Owner reason: This handle is tied to the original prompt-report feature and the adjacent session metadata policy, making them the strongest owner for the durable-storage choice.

Owner confidence: high

Options:

- **Persist Minimal Durable Summary (recommended):** Keep only the small fields needed across restarts, such as warning-dedupe state, and omit or externalize large `tools`, `skills`, and injected-file arrays from retained rows.
- **Store Full Reports Out Of Line:** Move full prompt reports to content-addressed or session-scoped artifacts while keeping `sessions.json` as a lightweight index with explicit cleanup ownership.
- **Keep Full Reports Only For Active Sessions:** Strip full reports from stale or inactive entries during write-time or maintenance compaction while preserving them for the current session context.

## Reproduction Assessment

Yes at source level: current main still writes full `systemPromptReport` objects into durable session entries, and recent production data shows those objects dominating large `sessions.json` files. I did not run a long-duration live gateway soak in this read-only review.

## Solution Assessment

No current implementation fully solves it: prompt blobs are a good partial fix for `skillsSnapshot.prompt`, but the remaining `systemPromptReport` storage policy needs maintainer direction before a durable code change.
