## Summary

Keep open: current main and the latest release mitigate large `skillsSnapshot.prompt` duplication with prompt blobs, but `systemPromptReport` is still built and persisted per session entry, matching the latest production data that says this is now the dominant `sessions.json` payload.

## What This Changes

The issue asks OpenClaw to stop unbounded session-store growth from repeated `skillsSnapshot` and `systemPromptReport` metadata in `sessions.json`.

## Best Possible Solution

Keep the prompt-blob mitigation and implement a maintainer-approved session metadata policy that stores only durable warning-dedupe state inline while compacting, recomputing, or externalizing repeated `systemPromptReport` payloads for retained rows.

## Reproduction Assessment

Yes at source level: current main builds a prompt report for runs and persists it through both agent-command and auto-reply session-entry write paths. I did not run a live long-running Gateway soak to measure file growth on current main.

## Solution Assessment

No, current main is only a partial solution because prompt blobs address large `skillsSnapshot.prompt` duplication while `systemPromptReport` still remains durable per session row. The linked PR is not the best full fix because it intentionally preserves that remaining payload.
