## Summary

## What This Changes

The PR removes Calendar, Reminders, and Contacts permission request calls from iOS node service invoke paths, adds injectable authorization-status readers, and adds tests for `.notDetermined` permission-required errors.

## Best Possible Solution

Keep the Settings-owned permission prompt boundary, but merge only after real iOS proof shows both the prompt-free node error path and the explicit Settings grant recovery path.

## Reproduction Assessment

Yes at source level: current main clearly calls EventKit and Contacts request APIs from the affected node service paths when authorization is `.notDetermined`. I did not run a real iOS device or simulator reproduction in this read-only review.

## Solution Assessment

Yes, with a proof gap: moving prompts out of node services matches the existing Photos service invariant and the Settings permission owner. The safer pre-merge state is to prove the changed behavior in a real iOS app run because it intentionally changes first-use permission flow.
