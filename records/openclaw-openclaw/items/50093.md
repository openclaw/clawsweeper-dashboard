## Summary

Keep open. Current main and v2026.6.11 still skip stale WhatsApp `append` catch-up messages after a 60-second connect grace, have no `messaging-history.set` or per-chat backfill path, and the two open candidate PRs remain unmerged and proof/policy blocked.

## What This Changes

Request WhatsApp to backfill or reconcile missed group messages after Web reconnection instead of silently losing outage-window messages.

## Best Possible Solution

Land one maintainer-chosen WhatsApp plugin recovery policy with live proof: either bounded replay for eligible monitored chats through durable dedupe, or a clear unrecoverable-gap warning when backfill cannot be trusted.

## Reproduction Assessment

Yes, source-level: current main skips `append` messages older than the 60-second pre-connect guard, and the append-upsert test asserts a five-minute append is not delivered. I did not run a live WhatsApp outage replay in this read-only review.

## Solution Assessment

Unclear. The WhatsApp plugin is the right owner boundary, but maintainers still need to choose default replay, opt-in replay, or explicit gap warnings and require live WhatsApp proof.
