## Summary

Keep open. Current main contains the merged bounded catch-up fix for Baileys-delivered `append` events, but it still does not implement provider-side reconnect backfill for messages that WhatsApp/Baileys never emits, and the latest maintainer discussion explicitly leaves that gap open.

## What This Changes

The issue asks WhatsApp to backfill or report messages missed during a connection outage after the gateway reconnects.

## Best Possible Solution

Choose a WhatsApp-plugin recovery design that either processes bounded `messaging-history.set` data safely or emits explicit unrecoverable-gap diagnostics, with durable dedupe/read-receipt handling, no stale auto-reply by default, docs, and live WhatsApp proof.
