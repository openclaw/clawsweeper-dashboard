## Summary

Keep open. Current main has a merged partial fix for Baileys-delivered reconnect `append` events, but it still has no provider-side history/backfill listener for messages WhatsApp/Baileys never emits, and the latest maintainer discussion explicitly leaves this issue open for that remaining gap.

## What This Changes

The issue requests WhatsApp reconnect recovery that backfills or explicitly reports messages missed during outage windows for monitored chats.

## Best Possible Solution

Keep this as the canonical tracker and design a WhatsApp plugin-owned reconnect recovery policy: backfill eligible monitored chats only when provider history is reliable, otherwise emit an explicit unrecoverable-gap warning while preserving durable dedupe and read-receipt rules.
