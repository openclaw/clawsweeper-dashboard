## Summary

Keep open. Current main and the latest release still do not backfill WhatsApp messages missed during a reconnect window: stale `append` catch-up messages are marked read and skipped, no `messaging-history.set`/cursor backfill path is wired in the WhatsApp plugin, and the two open candidate PRs remain unmerged and proof/policy blocked.

## What This Changes

Request backfilling or explicit gap handling for WhatsApp messages missed during reconnect so monitored chats do not silently lose inbounds.

## Best Possible Solution

Keep this as the canonical WhatsApp reconnect missed-message tracker and land one plugin-owned bounded recovery policy with live proof: replay eligible monitored-chat messages when safe, dedupe before enqueueing, and emit a clear unrecoverable-gap warning when provider backfill cannot be trusted.

## Reproduction Assessment

Yes, source-level: current main skips `append` messages older than a 60-second pre-connect guard, and the append-upsert test asserts a five-minute append is not delivered. I did not run a live WhatsApp outage replay in this read-only review.

## Solution Assessment

Unclear. The WhatsApp plugin is the right owner boundary, but maintainers still need to choose default replay, opt-in replay, or explicit gap warnings and require live WhatsApp proof.
