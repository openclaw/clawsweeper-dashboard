## Summary

Keep open. Current main and the latest release have session-key cleanup, idle/cap sweeps, and narrower lifecycle cleanup for reset, cron, subagent, and rollover paths, but they still do not implement ownership-based cleanup of temporary primary-agent browser tabs at ordinary task completion.

## What This Changes

The issue requests automatic cleanup of browser tabs/windows opened temporarily for agent browser tasks after task completion.

## Best Possible Solution

Add run-owned temporary-tab tracking for primary-agent browser opens, define explicit preserve/user-owned semantics, and keep idle/cap cleanup as the fallback safety net.

Question: Should primary-agent task completion close only run-owned temporary browser tabs, and which user actions should preserve a tab?

Rationale: Current behavior intentionally keeps active primary-session tabs reusable, so changing the default needs maintainer intent around task terminal events, tab ownership, and user-preservation rules.

Owner confidence: high

Options:

- **Run-owned cleanup with preservation (recommended):** Track tabs created during a primary-agent run and close only those not explicitly foregrounded, pinned, or requested to be kept.
- **Keep idle/cap behavior only:** Treat the current cleanup model as sufficient and close this direction as not planned if immediate task-end cleanup is too surprising.
- **Opt-in strict cleanup:** Add a documented opt-in cleanup mode while preserving reusable-tab behavior by default.

## Reproduction Assessment

Yes. Source inspection shows browser-opened tabs are tracked by session and cleaned by idle/cap sweeps or selected lifecycle resets, while ordinary primary-agent task completion has no ownership-based cleanup hook.

## Solution Assessment

No. Blanket auto-close is not the best final shape; the maintainable solution is ownership-based cleanup for run-created temporary tabs with explicit preservation rules for user-owned pages.
