## Summary

Keep open. Current main has session-key tab tracking, idle/cap sweeps, and explicit cleanup for reset, cron, subagent, and rollover paths, but it still does not implement ownership-based closing of run-created primary-agent browser tabs at ordinary task completion.

## What This Changes

Request automatic cleanup of temporary browser tabs/windows opened for browser-driven agent tasks while preserving user-owned or explicitly kept pages.

## Best Possible Solution

Add run-owned temporary-tab tracking for primary-agent browser opens, define explicit preserve/user-owned semantics, and keep the existing idle/cap cleanup as the fallback safety net.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should primary-agent task completion close only run-owned temporary browser tabs, and which user actions should preserve a tab?

Rationale: Current source and docs intentionally keep active primary-session tabs reusable, so changing the default needs a product decision about terminal events, tab ownership, and preservation rules before implementation.

Likely owner: steipete

Owner reason: steipete has the strongest recent implementation and merge history on browser tab cleanup and the related reset cleanup boundary.

Owner confidence: high

Options:

- **Run-owned cleanup with preservation (recommended):** Track browser tabs created during a primary-agent run and close only those not explicitly foregrounded, pinned, or requested to be kept.
- **Keep idle/cap behavior only:** Treat the current reusable primary-tab model as sufficient and close or de-scope task-end auto-close if immediate cleanup is too surprising.
- **Opt-in strict cleanup:** Add a documented opt-in cleanup mode while preserving current reusable-tab behavior by default.

## Reproduction Assessment

Yes. Source inspection shows browser-opened tabs are tracked by session and cleaned by idle/cap sweeps or selected lifecycle resets, while ordinary primary-agent task completion has no ownership-based cleanup hook.

## Solution Assessment

No, a blanket close-after-task rule is not the best final shape. The safer fix is ownership-based cleanup for run-created temporary tabs with explicit preservation rules for user-owned pages.
