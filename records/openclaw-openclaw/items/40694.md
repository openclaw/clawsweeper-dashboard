- `impact:session-state`: The issue is about browser tab ownership, preservation, and cleanup state after an agent run completes.

## Summary

Keep open. Current main has session-tab tracking, idle/cap sweeps, reset cleanup, cron cleanup, and subagent lifecycle cleanup, but it still does not define primary-agent task-completion cleanup for run-owned temporary tabs with user-preservation semantics.

## What This Changes

Request automatic cleanup of browser tabs/windows opened temporarily for browser-driven tasks once the task completes, while preserving pages the user explicitly wants to keep.

## Best Possible Solution

Implement run-owned temporary-tab tracking for primary-agent browser opens, close only eligible run-owned tabs at the primary-agent terminal boundary, preserve user-requested or foregrounded tabs, and keep idle/cap cleanup as the fallback safety net.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should ordinary primary-agent task completion close run-owned temporary browser tabs by default, and what user actions should preserve a tab?

Rationale: Current behavior intentionally keeps active primary-session tabs reusable, so changing the default requires maintainer intent around the terminal event, ownership marker, and preservation contract.

Likely owner: steipete

Owner reason: steipete authored the current idle cleanup and reset cleanup boundaries most directly related to this product choice.

Owner confidence: high

Options:

- **Run-owned cleanup with preservation (recommended):** Track tabs created during a primary-agent run and close only those not explicitly foregrounded, pinned, or requested to be kept.
- **Keep idle/cap cleanup only:** Treat current reusable-tab behavior plus background cleanup as the product choice and close this direction as not planned.
- **Opt-in strict cleanup:** Add a documented opt-in cleanup mode while preserving reusable primary-session tabs by default.

## Reproduction Assessment

Yes, as a source-level reproduction. Browser opens are tracked by session, current primary cleanup is idle/cap based, and the lifecycle cleanup call sites cover reset, cron, and subagents rather than ordinary primary-agent task completion.

## Solution Assessment

No, a blanket auto-close is not the best shape yet. The maintainable solution is ownership-based cleanup for run-created temporary tabs with explicit preservation rules for user-owned pages.
