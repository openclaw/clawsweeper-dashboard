## Summary

Keep open. Current main and the latest release have session-tracked browser tabs, idle/LRU cleanup, subagent/cron lifecycle cleanup, and reset cleanup, but they still do not implement ownership-based closing of temporary primary-agent browser tabs at ordinary task completion.

## What This Changes

The issue requests default cleanup for temporary browser tabs/windows opened by browser automation after a task completes, while preserving tabs the user explicitly wants to keep.

## Best Possible Solution

Add run-owned temporary-tab tracking in the browser plugin, define explicit preserve/user-owned semantics, and keep the existing idle/cap cleanup as a fallback safety net.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should primary-agent task completion close only run-owned temporary browser tabs, and which user actions should preserve a tab?

Rationale: Current code intentionally keeps active primary-session tabs reusable, so changing the default requires maintainer intent about task terminal events, tab ownership, and user-preservation rules.

Likely owner: steipete

Owner reason: steipete has the strongest recent history on the existing browser cleanup mechanisms that the product decision would extend.

Owner confidence: high

Options:

- **Run-owned cleanup with preservation (recommended):** Track tabs created during a primary-agent run and close only those not explicitly foregrounded, pinned, or requested to be kept.
- **Keep idle/cap behavior only:** Treat the current reusable-tab model as sufficient and close the request as not planned if immediate task-end cleanup is too surprising.
- **Opt-in strict cleanup:** Add a documented opt-in cleanup mode while preserving current reusable-tab behavior by default.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: browser opens are tracked by session and cleaned by idle/cap sweeps or specific lifecycle resets, while ordinary primary-agent task completion has no run-owned temporary-tab cleanup hook.

## Solution Assessment

No, blanket auto-close is not the best final shape. The maintainable solution is ownership-based cleanup for run-created temporary tabs with explicit preservation rules for user-owned or foregrounded pages.
