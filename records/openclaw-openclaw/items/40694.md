## Summary

Keep open. Current main and v2026.6.11 still provide session-key lifecycle cleanup plus idle/LRU sweeps, but they do not implement ownership-based cleanup of temporary primary-agent browser tabs at ordinary task completion; the FSB-linked comment supports preserving user-owned tabs rather than blanket closing everything.

## What This Changes

The issue requests automatic cleanup of browser tabs/windows opened for temporary automation tasks once the task completes, while preserving tabs the user explicitly wants to keep.

## Best Possible Solution

Add run-owned temporary-tab tracking for primary-agent browser opens, define explicit preserve/user-owned semantics, and keep the existing idle/cap cleanup as the fallback safety net.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should primary-agent task completion close only run-owned temporary browser tabs, and which user actions should preserve a tab?

Rationale: Current code intentionally keeps active primary-session tabs reusable, so changing the default requires maintainer intent about task terminal events, tab ownership, and user-preservation rules.

Likely owner: steipete

Owner reason: steipete has the strongest recent history on tracked-tab cleanup and the shared browser lifecycle helper.

Owner confidence: high

Options:

- **Run-Owned Cleanup With Preservation (recommended):** Track tabs created during a primary-agent run and close only those not explicitly foregrounded, pinned, or requested to be kept.
- **Keep Idle/Cap Behavior Only:** Treat the current reusable-tab model as sufficient and close this as not planned if immediate task-end cleanup is too surprising.
- **Opt-In Strict Cleanup:** Add a documented opt-in cleanup mode while preserving current reusable-tab behavior by default.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: browser opens are tracked by session and current cleanup closes exact lifecycle keys or idle/excess primary tabs, while ordinary primary-agent task completion has no run-owned temporary-tab cleanup hook.

## Solution Assessment

No, blanket auto-close is not the best final shape. The maintainable solution is ownership-based cleanup for run-created temporary tabs with explicit preservation rules for user-owned or foregrounded pages.
