## Summary

Keep open. Current main and v2026.6.11 have session-key cleanup, reset/rollover cleanup, and idle/cap sweeps, but they still do not implement run-owned temporary-tab cleanup at ordinary primary-agent task completion.

## What This Changes

The issue requests automatic cleanup of temporary browser tabs/windows opened for one-off browser automation after task completion, while preserving pages the user explicitly wants to keep.

## Best Possible Solution

Add run-owned temporary-tab tracking for primary-agent browser opens, define explicit preserve/user-owned semantics, and keep the existing idle/cap cleanup as a fallback.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should primary-agent task completion close only run-owned temporary browser tabs, and which user actions should preserve a tab?

Rationale: Current behavior intentionally keeps active primary-session tabs reusable, so changing the default needs maintainer intent for task terminal events, run ownership, and user-preservation rules.

Likely owner: steipete

Owner reason: steipete has the strongest current and historical connection to the browser tab cleanup implementation and the most recent overlapping reset cleanup.

Owner confidence: high

Options:

- **Run-owned cleanup with preservation (recommended):** Track tabs created during a primary-agent run and close only those not explicitly foregrounded, pinned, or requested to be kept.
- **Keep idle/cap cleanup only:** Treat the current idle and max-tab cleanup model as sufficient and close this direction as not planned if task-end closure is too surprising.
- **Opt-in strict cleanup:** Add a documented opt-in mode for task-end cleanup while preserving reusable-tab behavior by default.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: browser opens are tracked by session, and current cleanup happens through idle/cap sweeps or selected lifecycle/reset paths, with no primary-agent task-completion ownership hook.

## Solution Assessment

No, a blanket auto-close is not the best final shape. The maintainable solution is ownership-based cleanup for run-created temporary tabs with explicit preservation rules for user-owned pages.
