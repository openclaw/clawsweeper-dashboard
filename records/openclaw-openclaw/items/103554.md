## Summary

The current-main source proves both pairing defects and still renders generic serialized input/output blocks, so the issue remains necessary. The deterministic pairing and semantic-rendering work fits the existing Control UI path, but model-generated titles add separate privacy, billing, gateway API, model-routing, and persistence decisions requiring maintainer direction; the protected `maintainer` label also prevents automated cleanup.

## What This Changes

Improve Control UI tool activity with kind-aware rows, diffs and aggregate summaries, correct call/result pairing for message-level IDs and parallel calls, and optional model-generated purpose titles.

## Best Possible Solution

Extend the canonical tool-card path with call-ID-indexed non-adjacent pairing, deterministic kind-aware labels, aggregate summaries, and persisted edit diffs where available; evaluate model-generated titles in a separate design with explicit privacy, billing, fallback, and cache rules.
