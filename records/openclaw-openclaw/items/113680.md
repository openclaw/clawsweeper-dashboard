## Summary

The schema change is a focused, plausible fix: current main still exposes the unanchored WhatsApp QR pattern, while llama.cpp’s converter explicitly rejects patterns not ending in `$`. The remaining merge gate is real after-fix behavior proof from the actual grammar-conversion or provider tool-catalog path; the added test and static predicate transcript are useful but do not demonstrate that integration.

## What This Changes

This PR changes the WhatsApp login tool’s QR data-URL schema pattern to require a nonempty PNG data URL with a fully anchored regular expression, and adds a regression test for the anchoring invariant.

## System Context

The WhatsApp plugin exposes `whatsapp_login` to an agent as a JSON Schema tool. Grammar-constrained local-model runtimes convert that schema before presenting the tool catalog, and the tool later passes a QR data URL back to the WhatsApp login flow.
