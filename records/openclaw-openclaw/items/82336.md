## Summary

Keep open. Current `main` still has the generic plugin-approval request/resolve path, not the requested host-bound external-verification resolver; the same author’s open implementation PR explicitly owns this tracker, so closing it or starting a duplicate repair lane would be premature.

## What This Changes

Add a narrow host-owned approval API so an external human-in-the-loop plugin can complete only its own verified protected-tool approval while OpenClaw retains authorization, lifecycle, and final allow/deny control.

## System Context

Plugin hooks can block a protected tool call and ask the Gateway to create an approval. This request adds an external-verification path in which the host validates a verifier’s exact attempt and decision before resuming or denying the blocked tool call.

  F --> G[Allow or deny tool continuation]
