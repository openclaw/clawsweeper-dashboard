## What This Changes

Expose a narrow host-owned approval seam so an external HITL plugin can complete verification for its own protected tool call while OpenClaw retains approval identity, authorization, lifecycle handling, and the final allow-or-deny decision.

## System Context

Plugin `before_tool_call` hooks can request an OpenClaw approval before a protected tool executes. The requested seam would let an external verifier complete only its host-bound attempt while the Gateway persists approval state and resumes or denies the tool call.

## Architecture Diagram

flowchart LR
  A[Protected tool call] --> B[Plugin approval hook]
  B --> C[Gateway-owned approval]
  C --> D[External verifier plugin]
  D --> E[Host-bound verification attempt]
  E --> F[Gateway authorization check]
  F --> G[Allow or deny tool call]

## Best Possible Solution

Use the open core PR as the single implementation path, retain host ownership of approval authorization and durable audit state, and require maintainer-approved security and compatibility review before merge; leave this tracker open until that PR lands.
