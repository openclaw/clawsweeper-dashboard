## What This Changes

Add a narrow host-owned plugin approval API that lets external HITL verifiers authorize only their exact protected-tool approval attempt while OpenClaw retains approval lifecycle and final resolution authority.

## System Context

A plugin’s `before_tool_call` hook can turn a protected agent action into a host-owned pending approval. The Gateway and clients present the approved choices, the external verifier completes its bound attempt, and the host then permits or denies the original tool call.

## Architecture Diagram

flowchart LR
  A[Protected tool call] --> B[Plugin hook requests approval]
  B --> C[Gateway owns pending approval]
  C --> D[Client shows verify or deny choices]
  D --> E[External plugin verifier]
  E --> F[Host validates bound completion]
  F --> G[Allow or deny tool continuation]

## Best Possible Solution

Review and land the linked core implementation as the single canonical path, retaining a narrow generic host seam while keeping World/AgentKit verification logic and secrets in the external plugin.
