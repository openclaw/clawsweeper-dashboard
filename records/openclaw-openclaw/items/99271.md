## What This Changes

The issue requests a single acquisition-aware cleanup path for `runCodexAppServerAttempt` so setup exceptions after turn acceptance cannot leak handlers, a shared-client lease, or active-run state.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/99747 or a replacement that puts all post-turn-accept resource acquisition under one acquisition-aware cleanup/disposer boundary with focused regression coverage.

## Reproduction Assessment

Yes. Source inspection shows post-turn resources are acquired before the cleanup `finally`, so a synchronous throw in that window can bypass the release path; I did not run a live failing Codex attempt.

## Solution Assessment

Yes. A single acquisition-aware cleanup boundary is the maintainable fix, and the open linked PR or a replacement should be reviewed and landed before closing this issue.
