## Summary

Keep open: current `main` still has the reported Codex app-server cleanup gap, and no related issue or PR supersedes this narrower exception-window leak.

## What This Changes

The issue asks for `runCodexAppServerAttempt` to use one protected, idempotent cleanup path so exceptions after turn acceptance cannot leak shared-client handlers, leases, or active-run state.

## Best Possible Solution

Refactor the Codex app-server attempt lifecycle so each acquired resource registers an idempotent disposer immediately and one protected cleanup path drains those disposers, with regression coverage for a throw after active-run registration.

## Reproduction Assessment

Yes by source inspection: a synchronous throw after `setActiveEmbeddedRun` but before the following `try` bypasses the `finally` that clears the active run. A focused regression test should inject that failure path rather than relying on live Codex behavior.

## Solution Assessment

Yes, the proposed disposer-stack direction appears to be the best maintainable fix because it removes duplicated lifecycle cleanup and closes the uncovered exception window without adding a user-facing mode.
