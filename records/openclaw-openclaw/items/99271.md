Keep open: current main still has duplicated cleanup paths and an unprotected post-`turn/start` setup window, so the reported Codex app-server handler/lease/active-run leak is source-reproducible and not already owned by an open fix PR.

## What This Changes

The issue requests refactoring Codex app-server attempt cleanup so all acquired resources release through one idempotent path that covers the window after `turn/start` acceptance.

## Best Possible Solution

Consolidate `runCodexAppServerAttempt` cleanup into one idempotent owner that covers client handlers, shared leases, sandbox state, hook relay state, abort/close listeners, steering queues, and active-run registration, with focused regression tests.

## Reproduction Assessment

Yes, at source level: current main shows handlers and leases acquired before turn acceptance, then setup code and `setActiveEmbeddedRun` execute before the `finally` that would clean them. I did not run a live failing attempt in this read-only review.

## Solution Assessment

Yes: a single idempotent disposer/finally boundary is the maintainable fix because the same resources are currently released in multiple places and the central bug is ownership of the lifecycle boundary.
