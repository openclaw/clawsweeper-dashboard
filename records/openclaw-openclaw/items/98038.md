## Summary

Keep open: current main appears to have fixed the private-LAN QR `auth=none`/`AUTH_TOKEN_MISSING` path, but the broader repeated iOS node reapproval loop is not proven fixed and current source still has a separate reapproval trigger when iOS reconnect declarations change.

## What This Changes

The issue reports that the iOS app fails to persist or reuse approved device/node auth across reconnects, causing a new node reapproval request after every app close/reopen.

## Best Possible Solution

Keep gateway reapproval for real command/capability upgrades, but stabilize the iOS node approval declaration across app restarts or move volatile availability fields out of the approval surface, then prove the result with a real iPhone LAN/VPN reconnect run.
