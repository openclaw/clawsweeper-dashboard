## Summary

Keep this open: current main contains the LAN QR bootstrap token persistence fix, but current source and tests still have a separate node reapproval path when the iOS app's declared capability, command, or permission surface changes across reconnects, and no current-main real iPhone LAN/VPN proof shows the reported loop is gone.

## What This Changes

The issue asks OpenClaw to persist and reuse the iOS app's approved device/node auth across close/reopen reconnects so the gateway does not require node reapproval every time.

## Best Possible Solution

Run a current-main real iPhone LAN/VPN reconnect proof first; if stored auth is still missing, fix OpenClawKit token persistence, and if auth is present but reapproval follows changed declarations, stabilize the iOS node declaration or design explicit in-app recovery without weakening gateway approval policy.
