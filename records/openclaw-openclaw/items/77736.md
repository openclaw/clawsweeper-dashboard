## Summary

Keep open: the patch is a focused, source-backed fix for explicit `web_search` provider routing, but it intentionally changes fail-closed behavior for an existing provider setting and needs maintainer acceptance before merge.

## What This Changes

The PR makes agent `web_search` pass the configured `tools.web.search.provider` through as an explicit provider, reloads plugin providers when runtime discovery misses that provider, adds regression tests, and documents hard-route behavior.

## Best Possible Solution

Land this after provider/runtime maintainers explicitly accept hard-route explicit-provider semantics, while keeping opt-in fallback chains in the separate product/API discussion.

## Reproduction Assessment

Yes, at source level. Current main can route an explicit configured provider through stale runtime metadata because the agent tool does not pass `providerId` and runtime provider loading does not recover a missing explicit provider from plugin discovery.

## Solution Assessment

Yes for the code shape, with one maintainer decision remaining. The PR keeps agent search runtime-first, moves explicit-provider recovery into the web-search runtime, preserves `web_fetch`, and leaves fallback-chain policy separate.
