## Summary

Keep open: current main and v2026.6.11 still parse cron `delivery.channel` as a string-only field and delete object-shaped channel refs, so explicit Telegram routing can still fall back to `last`; the open linked PR is the active fix path.

## Best Possible Solution

Rebase and prove the linked parser-boundary fix in https://github.com/openclaw/openclaw/pull/91162, keeping runtime `delivery.channel` canonical as a string while recovering legacy object-shaped input before scheduled delivery.
