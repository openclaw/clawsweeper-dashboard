## Summary

Keep open: current `origin/main` and `v2026.6.11` still parse cron `delivery.channel` as a string-only field, so object-shaped channel refs can be dropped before delivery planning falls back to `last`; the linked open pull request remains the active fix path.

## What This Changes

Cron jobs configured for Telegram delivery can lose an object-shaped `delivery.channel` during normalization and then route scheduled output through Feishu or another last-used channel.

## Best Possible Solution

Review, refresh, prove, and land https://github.com/openclaw/openclaw/pull/91162 or a narrow replacement that recovers `{ id }` to the canonical string before cron delivery planning, with regression and redacted multi-channel delivery proof.
