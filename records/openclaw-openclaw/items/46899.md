## Summary

Keep open: current main and the latest release still use string-only cron `delivery.channel` parsing, so the reported Telegram-to-Feishu misrouting path remains possible; the open closing PR should remain the active fix path.

## What This Changes

The issue reports cron delivery configured for Telegram losing its explicit channel and falling back to Feishu, causing scheduled message delivery failure.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/91162 or an equivalent parser-boundary fix that keeps runtime `delivery.channel` canonical as a string and proves Telegram-configured cron jobs deliver through Telegram when another channel is enabled.
