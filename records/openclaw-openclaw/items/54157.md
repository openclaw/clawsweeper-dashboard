## Summary

Keep open: current main and latest release still preserve zero cached-token prices in the active BytePlus and Volcengine/Doubao plugin manifests, while the same-repo fix attempts are closed unmerged and the remaining pricing values need maintainer/vendor confirmation.

## What This Changes

The issue asks for non-zero Doubao/BytePlus cached-token pricing so usage-cost reporting does not treat context cache reads and writes as free.

## Best Possible Solution

Land a narrow provider-plugin manifest update for both BytePlus and Volcengine/Doubao with vendor-backed USD-per-million cache pricing, focused regression tests, and no revival of the old core catalog files.

## Reproduction Assessment

Yes. Source inspection shows active provider manifests still carry zero cached-token pricing, and session cost estimation consumes those catalog cost fields; I did not run a live BytePlus or Volcengine billing scenario.

## Solution Assessment

Yes on the layer, but not on the old file paths from the report. The maintainable fix belongs in the current provider plugin manifests and focused tests, with exact values gated on vendor-backed maintainer confirmation.
