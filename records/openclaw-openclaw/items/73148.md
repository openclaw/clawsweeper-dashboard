## Summary

Close as implemented: current main and the shipped v2026.6.11 package use the Rastermill-backed image pipeline and root package dependency instead of the old nested sharp runtime path, so the reported missing-sharp install failure is no longer present.

## What This Changes

The issue reports that image optimization fails with an opaque error when packaged installs do not include the sharp native dependency.

## Best Possible Solution

Keep the shipped Rastermill-backed image backend; any new native-backend or provider-specific image failures should be tracked as focused follow-up issues.

## Reproduction Assessment

Yes. The historical failure is source-reproducible from the old package shape and reporter installs: the old optimizer imported sharp while published installs could omit it; current main no longer uses that path.

## Solution Assessment

Yes. Replacing the sharp-backed optimizer with a root-declared Rastermill backend is a cleaner durable fix than adding a sharp install hint for code that no longer imports sharp.
