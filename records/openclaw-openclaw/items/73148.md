## What This Changes

The issue reports that missing `sharp` makes image optimization fail with an opaque `Failed to optimize image` error and asks for clearer diagnostics and reliable dependency packaging.

## Best Possible Solution

Keep the shipped Rastermill-backed image processor and root dependency packaging; no additional OpenClaw core work is needed for this Sharp-specific failure.

## Reproduction Assessment

Yes. The issue body and current/history source evidence identify the old failure path: global installs could miss the private `sharp` runtime dependency and the old optimizer surfaced only `Failed to optimize image`.

## Solution Assessment

Yes. Replacing the Sharp backend with the shared Rastermill image processor and declaring it as a root runtime dependency is the maintainable fix for the reported packaging and opaque-error path.
