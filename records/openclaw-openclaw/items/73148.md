## Summary

Current main and released v2026.5.26 no longer use the missing `sharp` runtime path that caused this issue; image operations now use a root-declared Rastermill dependency, with structured backend-unavailable errors and regression coverage around optimizer failures.

## What This Changes

The issue reports that image optimization fails with an opaque `Failed to optimize image` error when packaged installs do not include the optional `sharp` dependency.

## Best Possible Solution

Keep the released Rastermill-backed image stack; any new image failures on v2026.5.26 or newer should be filed as fresh backend-specific reports with the new error text.

## Reproduction Assessment

Yes for affected historical releases: the report, comments, and related package issue show the root package lacked `sharp` while runtime code imported it. On current main and v2026.5.26+, the old sharp path is gone, so the reproduction now verifies as fixed rather than still failing.

## Solution Assessment

Yes. Replacing the shipped Sharp-backed path with a root-declared Rastermill backend is the durable package-boundary fix, and it is cleaner than adding a root `sharp` dependency for code that no longer imports Sharp.
