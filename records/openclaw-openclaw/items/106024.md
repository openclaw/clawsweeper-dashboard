## Summary

Keep this PR open, but do not merge it yet: serializing message callbacks addresses the reported Blob-versus-string race, while the unchanged close/error callbacks can still overtake the new promise chain and terminate the parser before queued completion frames are processed.

## What This Changes

The PR serializes ChatGPT Responses WebSocket frame decoding and adds a delayed-Blob ordering regression test.

## Best Possible Solution

Use one ordered per-socket event pipeline that drains all accepted message frames before applying close or error termination, cover delayed Blob plus queued completion plus eager close, and provide a redacted real WebSocket run showing the response completes without reordering.

## Reproduction Assessment

Yes at source level: dispatch a delayed Blob message, a text response.completed message, and then close the socket before the Blob promise resolves. The proposed test covers the first two events but not the terminal close that exposes the remaining race.

## Solution Assessment

No. Ordering only message callbacks is incomplete; the narrow maintainable fix is to order close and error termination behind all previously accepted message frames as part of the same event pipeline.
