## Summary

This remains a useful, focused fix: the current selector rescans the full commitment store for each qualifying due record, while the PR reuses one per-session count map without changing eligibility semantics. The patch has strong source-level regression coverage and no concrete correctness or security defect, but the external-PR proof gate still needs after-fix terminal timing from a real store run rather than tests alone.

## What This Changes

The PR replaces repeated rolling sent-count scans with one per-agent session-count aggregation reused by commitment selectors, and adds semantic and concentrated-session scaling tests.

## Best Possible Solution

Keep the bounded one-pass aggregation, obtain redacted before/after terminal timings using an actual temporary commitment store at the current base and patched head, and leave the broader JSON-to-SQLite doctor migration as a separately reviewed persistence change.
