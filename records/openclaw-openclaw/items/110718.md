## Summary

The proposed code-point truncation is mechanically safe, but the current treemap path sanitizes labels before truncation, so the reported malformed-Unicode rendering is not reachable in the shipped `/context map` flow. Keep this PR open for an owner decision rather than treating the helper-only change as a demonstrated user-facing fix.

## What This Changes

The PR exports `truncateLabel`, changes it from UTF-16-code-unit slicing to `Array.from` code-point truncation, and adds regression coverage for emoji, CJK, and boundary values.

## Best Possible Solution

Keep the existing ASCII-only treemap-label contract unless product owners want Unicode labels; if they do, broaden the sanitizer/render path deliberately and use grapheme-safe display truncation with a real `/context map` proof.
