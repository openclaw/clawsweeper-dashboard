## What This Changes

Reject edits and patches to existing files that are not valid UTF-8, preserving every original byte instead of silently rewriting invalid sequences during a whole-file write.

## System Context

OpenClaw coding tools read workspace files, transform requested text, and write the full result back through host, workspace, or sandbox filesystem operations. The edit and apply-patch paths also return a model-facing change summary, so lossy decoding can both corrupt disk bytes and hide the collateral mutation from the agent.

## Architecture Diagram

flowchart TD
  A[Agent edit or patch request] --> B[Host, workspace, or sandbox file reader]
  B --> C[Strict UTF-8 validation]
  C -->|valid text| D[Match and apply requested change]
  C -->|invalid bytes| E[Reject without writing]
  D --> F[Whole-file write]
  D --> G[Model-facing change summary]
  F --> H[Workspace file]

## Best Possible Solution

Create one strict UTF-8 decoding boundary for mutation of existing files, apply it to every edit and apply-patch backend before matching or writing, and add byte-preservation regressions for host plus each distinct workspace/sandbox reader contract.
