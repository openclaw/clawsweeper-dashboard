## Summary

Keep this issue open for targeted diagnostics: the reported duplicate responses are serious, but current main already deduplicates fallback candidates and returns immediately after a successful attempt, so the supplied time-grouped trajectory does not establish that the fallback loop caused the extra runs.

## What This Changes

Investigate and fix multiple agent runs and duplicate replies observed when an agent has an explicit model fallback chain.

## Best Possible Solution

Capture one affected turn with raw ordered trajectory records, gateway `model_fallback_decision` logs, run/session IDs, completion status fields, and delivery identifiers, then fix whichever caller or classifier schedules a second run after the first committed response rather than adding a new redundancy configuration mode.
