Keep open. Current main still allows an operator-authorized third-party Android notification to become a Gateway `notifications.changed` node-session event, and the remaining wrong-target outbound send boundary needs maintainer security/product direction before cleanup can close this.

## What This Changes

Prevent Android-forwarded native-channel notifications from creating duplicate node-session replies and wrong-target WhatsApp sends.

## Best Possible Solution

Keep this as the canonical maintainer item, choose a security-boundary fix that blocks native-channel notification echoes from causing unbound cross-channel sends, then validate with live Android plus WhatsApp proof and focused Android, Gateway, and outbound-policy tests.
