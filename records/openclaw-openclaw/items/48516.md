## What This Changes

## Best Possible Solution

Keep this as the canonical issue until maintainers choose and land a security-boundary fix that prevents native-channel notification echoes from creating node-session cross-channel sends, backed by live Android plus WhatsApp proof.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw enforce the fix primarily at outbound session/channel binding, Android native-package notification suppression, Gateway notification package filtering, or a layered combination?

Rationale: The remaining path crosses Android notification policy, Gateway node-session events, and possible heartbeat-driven outbound delivery; choosing the wrong owner could leave a cross-channel security gap or add brittle package/config policy.

Likely owner: Ayaan Zaidi

Owner reason: The core decision centers on the Gateway/node notification event path and its interaction with channel delivery authority.

Owner confidence: high

Options:

- **Harden outbound binding first (recommended):** Reject or constrain cross-channel sends from node notification or heartbeat sessions unless an explicit verified route binding exists, then use Android or Gateway filtering as defense in depth.
- **Suppress native packages in Android:** Default-block known native-channel Android package IDs, reducing duplicate inputs but requiring maintained package ownership policy.
- **Add Gateway package filtering:** Add server-side package filtering for notification events, which helps operators but adds config/default-surface and does not by itself settle outbound authority.

No live Android plus WhatsApp run was performed in this read-only review. Source inspection shows the necessary ingress path: an operator-allowed third-party Android notification can become a Gateway `notifications.changed` system event in a node session.

## Solution Assessment

Unclear. Android filtering alone is not the best proven fix because the outbound route-binding and heartbeat behavior still need a maintainer-owned security boundary decision.
