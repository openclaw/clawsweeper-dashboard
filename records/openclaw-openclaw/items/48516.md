## Summary

Keep open. Current main has partial Android notification-forwarding hardening, but it still allows operator-authorized third-party packages such as WhatsApp to become `notifications.changed` node-session system events, so the reported native-channel echo and cross-session send boundary is not proven fixed.

## What This Changes

The issue asks OpenClaw to prevent Android-forwarded native chat notifications from creating duplicate node-session events and cross-session outbound replies.

## Best Possible Solution

Keep this as the canonical maintainer item and choose a security-boundary fix that prevents native-channel notification echoes from creating node-session sends, with live Android plus WhatsApp proof and regression coverage across Android policy, Gateway notifications, and message-tool route binding.
