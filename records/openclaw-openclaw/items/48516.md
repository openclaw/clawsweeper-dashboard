## Summary

Keep open. Current main still lets allowed Android `notifications.changed` events become node-session system events and heartbeat wakes, while the recent merged Android work only blocks OpenClaw self-package forwarding and does not default-deny native channel app packages such as WhatsApp.

## What This Changes

The issue reports Android forwarded app notifications creating a duplicate node-session path that can send WhatsApp replies into the wrong group.

## Best Possible Solution

Choose one canonical safety boundary that prevents native-channel app notifications from waking unrelated node sessions, and pair it with outbound route binding so a node-scoped notification turn cannot send through an unrelated channel target.

## Reproduction Assessment

No high-confidence live reproduction was run in this review. Source inspection shows the remaining path: an allowed Android package can emit `notifications.changed`, and the gateway still enqueues it into a node session and wakes a heartbeat.

## Solution Assessment

Unclear as an implementation choice. Android self-package blocking is a useful partial mitigation, but the best fix likely needs maintainer direction across native-channel package ownership, gateway rejection, and outbound route binding.
