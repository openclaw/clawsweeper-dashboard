## Summary

Keep open. Current main still accepts Android notifications from operator-allowed third-party packages and turns them into node-session system events; the recent merged self-notification fix only closes OpenClaw app loops, not the reported native-channel echo and cross-session reply leak.

## What This Changes

The issue asks OpenClaw to prevent Android-forwarded native-channel notifications from creating duplicate cross-session replies to the wrong WhatsApp group.

## Best Possible Solution

Choose a single maintainer-approved boundary that suppresses native-channel notification echoes and prevents node-session outbound sends from targeting unrelated channel conversations, then back it with Android, gateway, and live WhatsApp proof.

## Reproduction Assessment

Yes, at source level: current Android and gateway code still accept allowed third-party notifications and enqueue them into node-session system events. The live WhatsApp plus Android duplicate-send path has not been re-run in this read-only review.

## Solution Assessment

No, current main is only a partial mitigation: it blocks OpenClaw self-notification loops but does not solve native-channel package echoes or node-session outbound target binding. The best fix needs maintainer choice among Android package policy, gateway rejection/dedupe, and outbound tuple enforcement.
