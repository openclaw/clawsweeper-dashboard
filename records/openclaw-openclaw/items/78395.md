## Summary

Keep this PR open for maintainer review: the patch appears to fix the shared fallback alias resolution bug, but it intentionally changes how existing providerless fallback strings can route when they match configured aliases, which is compatibility- and auth-provider-sensitive.

## What This Changes

The PR changes shared agent model allowlist construction so providerless fallback aliases resolve through the configured model alias index, with regression tests for model selection and `/models` picker data.

## Best Possible Solution

Land the shared fallback-resolution fix after maintainers explicitly accept alias-first providerless fallback routing as intended upgrade behavior, or pause until the broader CLI-runtime selector policy is settled.

## Reproduction Assessment

Yes. Current main still lacks alias-first fallback resolution in the shared allowlist helper, and the inspected Mantis baseline shows `/models openai-codex` listing the misplaced `opus-cli` row before the PR.

## Solution Assessment

Yes, with maintainer acceptance of the upgrade behavior. The fix is in the shared helper used by picker data and routing gates, scopes alias-first lookup to fallback inputs, and avoids a channel-only workaround.
