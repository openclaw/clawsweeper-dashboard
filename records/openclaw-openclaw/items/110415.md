## Summary

Keep this PR open: the parser still suppresses configured accounts whenever a non-literal filename segment normalizes to `default`, so an existing configured account such as `DEFAULT` cannot migrate its legacy allowFrom file and can still block readiness. Likely related people: smoe is the strongest history-based routing candidate for the adjacent default-account migration behavior.

## What This Changes

The PR normalizes legacy allowFrom filename account segments before configured-account matching and adds migration regressions for mixed-case names and uppercase `DEFAULT`.

## Best Possible Solution

Compare every safely normalized filename segment against configured account IDs first, then apply the bundled implicit-default fallback only when there was no configured match and the filename suffix is the literal canonical `default`.

## Solution Assessment

No. The proposed normalization is the right narrow direction, but suppressing all noncanonical `default` segments before configured-account matching is broader than needed; only the implicit fallback should require a literal canonical suffix.
