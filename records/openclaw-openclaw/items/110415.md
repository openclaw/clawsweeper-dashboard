## Summary

The account-key normalization addresses the reported migration mismatch, but this patch also broadens the bundled default-account fallback: an unconfigured `telegram-DEFAULT-allowFrom.json` now resolves as `telegram/default` and may be imported and deleted. That conflicts with the prior canonical-literal default contract and with this PR’s own stated matrix; it needs a narrow correction plus real after-fix migration proof before merge.

## What This Changes

The PR normalizes legacy allowFrom filename account segments with `safeAccountKey` before matching configured accounts and adds mixed-case migration fixtures.

## Best Possible Solution

Normalize filename segments only for configured-account matching; keep the implicit bundled default fallback restricted to the literal canonical `default` suffix, add a negative regression test for uppercase `DEFAULT`, and provide a redacted real migration-to-ready startup trace.
