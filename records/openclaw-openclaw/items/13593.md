## Summary

Keep open: current main still only partially covers cron observability; it tracks run state, counters, failure alerts, and run history, but still lacks all-outcome runtime logging, cron-aware health/readiness, and `openclaw cron list` warnings. The related implementation PRs are closed unmerged, so no canonical fix owns the remaining work.

## What This Changes

Add cron execution logging, health/readiness reporting, and CLI warnings for failed, skipped, overdue, or apparently healthy-but-not-running cron jobs.

## Best Possible Solution

Land one coordinated cron-observability design that adds bounded structured logs for every scheduled and manual outcome, annotates unhealthy cron list rows, and exposes cron health through a maintainer-approved probe surface.

## Reproduction Assessment

No live high-confidence reproduction of the original production silent-failure frequency was established in this read-only pass. The missing observability surfaces are source-reproducible on current main from the cron execution, CLI list, and probe/readiness code paths.

## Solution Assessment

Unclear until maintainers choose the public cron health/readiness contract. The logging and CLI-warning pieces are bounded, but a dedicated cron endpoint versus integration into existing probes is a product/API decision.
