## Summary

Keep open: current main still only partially covers cron observability. It records cron run state, error counters, failure alerts, and durable run-log rows, but the requested all-outcome runtime logs, cron-aware health/readiness surface, and `openclaw cron list` warnings are still missing; the overlapping implementation PRs are closed unmerged.

## What This Changes

The issue requests cron execution-attempt logging, cron-aware health reporting, and CLI warnings when jobs fail, skip, or become overdue.

## Best Possible Solution

Land one coordinated cron-observability design that adds bounded all-outcome runtime logs, unhealthy CLI annotations, and a maintainer-approved cron health/readiness surface while preserving existing counters, run history, and failure-alert behavior.

## Reproduction Assessment

No live high-confidence reproduction of the original production silent-failure frequency was established in this read-only pass. The missing observability surfaces are source-reproducible on current main from the cron execution, CLI list, and probe/readiness code paths.

## Solution Assessment

Unclear until maintainers choose the public cron health/readiness contract. The logging and CLI-warning pieces are bounded, but a dedicated cron endpoint versus integration into existing probes is a product/API decision.
