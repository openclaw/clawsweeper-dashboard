## Summary

This PR addresses a real embedded-agent delivery bug and includes credible redacted runtime proof, but its new error guard still leaves the terminal assistant’s reasoning text eligible for delivery when reasoning is enabled. Keep it open for that focused repair and a rebase/refresh against current `main`.

## What This Changes

The PR suppresses errored or aborted embedded-agent assistant answer text so provider failure content is not delivered as a completed final reply.

## System Context

Embedded-agent runs turn provider messages and streamed text into reply payloads for the originating channel or CLI caller. Terminal preparation selects the final assistant state and payload construction decides which answer, reasoning, media, and error items are delivered.

## Architecture Diagram

flowchart LR

  B --> C[Terminal preparation]
  C --> D[Payload builder]
  D --> E[Reply payloads]
  E --> F[Channel or CLI consumer]
  C --> G[Concise error outcome]
  G --> E

## Best Possible Solution

Use one terminal-error predicate for both answer and reasoning payload emission, add a reasoning-enabled regression test that proves no failed-run text is delivered, then rebase and refresh the focused runtime proof.
