## Summary

Keep this PR open: reusing the dispatch-start snapshot can change worker-context enrichment after cards are claimed or other board state changes during the same pass, and the added test does not establish the claimed output-equivalence contract. The PR also still lacks contributor-supplied after-fix evidence from a real multi-worker dispatch.

## What This Changes

The PR passes Workboard’s already loaded dispatch-board snapshot into worker-context construction to avoid one full-board read for each worker started in a dispatch batch.

## System Context

Workboard dispatch reads queued cards, claims eligible work, builds context for each worker, and then starts its workspace. The proposed optimization changes which board snapshot supplies parent-result and recent-assignee enrichment in those worker contexts.
