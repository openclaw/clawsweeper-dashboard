## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Restrict remote preloads to explicit image URLs:** `src/agents/pi-embedded-runner/run/images.ts:42`
  - body: `HTTP_URL_REGEX_SOURCE` matches every HTTP(S) URL, and the new scan feeds each match into `loadWebMedia` before discarding non-images. That turns ordinary prompt links into gateway network fetches, so restrict this to URLs that are clearly intended image refs or another explicit signal.
  - confidence: 0.92
- **[P1] Forward the configured SSRF policy:** `src/agents/pi-embedded-runner/run/images.ts:460-462`
  - body: The new `remote-url` branch passes only `maxBytes` to `loadWebMedia`, while existing remote media tool paths forward `resolveRemoteMediaSsrfPolicy(...)`. This ignores configured web-fetch SSRF policy for prompt-image preloads, so thread that policy through and pass it here.
  - confidence: 0.93
- **[P2] Keep HTTP URL dedupe case-sensitive:** `src/agents/pi-embedded-runner/run/images.ts:290-295`
  - body: `addRemoteUrlRef` uses `normalizeRefForDedupe`, which lowercases keys on Windows for filesystem paths. HTTP paths can be case-sensitive, so two distinct image URLs can collapse into one and drop image context.
  - confidence: 0.84
- **[P2] Do not mark skipped bracket URLs as seen:** `src/agents/pi-embedded-runner/run/images.ts:340-348`
  - body: When a bracket contains both a local path and URL, this branch adds the URL dedupe key even though it does not emit a `remote-url` ref. A later explicit repeat of the same URL is then suppressed and never loaded.
  - confidence: 0.82
- **[P3] Trim closing delimiters from URL refs:** `src/agents/pi-embedded-runner/run/images.ts:96-118`
  - body: The URL regex can include a closing `)` from parenthesized or Markdown-style text, and the sanitizer does not remove it. That makes the preload fetch the wrong URL path for common prompt formatting.
  - confidence: 0.78
