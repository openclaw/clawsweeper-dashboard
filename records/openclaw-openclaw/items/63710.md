## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Restrict URL preload before fetching arbitrary links:** `src/agents/pi-embedded-runner/run/images.ts:42`
  - body: `HTTP_URL_REGEX_SOURCE` matches every HTTP(S) URL, and the later full-prompt scan preloads each match through `loadWebMedia`. That means a normal prompt mentioning a docs page or other non-image link now triggers an outbound gateway fetch before the model call, adding latency and privacy exposure outside the stated explicit-image scope.
  - confidence: 0.9
- **[P1] Forward the configured SSRF policy:** `src/agents/pi-embedded-runner/run/images.ts:460-462`
  - body: The new `remote-url` branch calls `loadWebMedia` with only `maxBytes`, so the existing `ssrfPolicy` support used by remote media fetches is silently dropped on this new network path. Thread the configured policy through `detectAndLoadPromptImages`/`loadImageFromRef` before allowing prompt URLs to be fetched natively.
  - confidence: 0.93
- **[P2] Do not mark skipped bracket URLs as seen:** `src/agents/pi-embedded-runner/run/images.ts:340-348`
  - body: When a `[media attached: path | url]` bracket has a local path, this branch adds the bracket URL to `seen` even though it emits no `remote-url` ref. If the same URL is explicitly repeated later in the prompt, the full-prompt scan suppresses it and the remote image can still be lost if the local path cannot load.
  - confidence: 0.86
