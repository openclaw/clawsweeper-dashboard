Full review comments:

- **[P1] Restrict prompt URL preloading to image refs:** `src/agents/pi-embedded-runner/run/images.ts:42`
  - body: `HTTP_URL_REGEX_SOURCE` matches any HTTP(S) URL, so prompts that merely mention a web page or API endpoint will now trigger a gateway fetch before the non-image response is discarded. Keep this preload path limited to explicit image URLs or another maintainer-approved image boundary.
  - confidence: 0.93
- **[P1] Forward SSRF policy when loading remote refs:** `src/agents/pi-embedded-runner/run/images.ts:460-462`
  - body: The new `remote-url` branch calls `loadWebMedia` without any `ssrfPolicy`, so configured remote-media SSRF rules are not honored for this prompt-controlled fetch path. Thread the policy through the prompt-image loader before enabling remote URL preloads.
  - confidence: 0.91
- **[P2] Do not use filesystem dedupe for remote URLs:** `src/agents/pi-embedded-runner/run/images.ts:290-295`
  - body: `addRemoteUrlRef` reuses `normalizeRefForDedupe`, which lowercases keys on Windows for filesystem paths. HTTP URL paths can be case-sensitive, so two distinct remote image URLs can collapse into one and silently drop image context.
  - confidence: 0.86
- **[P2] Do not mark skipped bracket URLs as loaded:** `src/agents/pi-embedded-runner/run/images.ts:340-348`
  - body: When a `[media attached: path | url]` entry has a local path, this branch still adds the URL to `seen` even though it emits no remote ref. A later explicit repeat of the same URL in the user prompt is then suppressed, so the remote image can still be missing.
  - confidence: 0.82
