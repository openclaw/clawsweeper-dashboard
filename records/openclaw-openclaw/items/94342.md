## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Move the observer after the policy hook:** `src/infra/outbound/deliver.ts:1634-1658`
  - body: The new internal `message:sending` event fires before `applyMessageSendingHook`, but the typed `message_sending` hook can still rewrite or cancel the payload. That lets directory hooks observe or log content that is stale or intentionally blocked, so emit the observer only after the final pre-send decision and skip it on cancellation.
  - confidence: 0.92
- **[P1] Guard metadata reads when no reply payload exists:** `src/infra/heartbeat-runner.ts:1889`
  - body: `resolveHeartbeatReplyPayload` can return `undefined`, but this line passes `replyPayload` directly to `getReplyPayloadMetadata`, whose current signature requires an object. Guard the metadata lookup behind `replyPayload` so the no-reply case remains type-safe and does not depend on probing metadata for an absent payload.
  - confidence: 0.86
- **[P2] Preserve reasoning payloads during suppression:** `src/infra/heartbeat-runner.ts:1890-1893`
  - body: Current main only returns `ok-empty` when there are no `reasoningPayloads`, then later sends opted-in Thinking payloads. This new suppression branch returns before that fallthrough, so suppressing raw final text can also drop the opted-in reasoning payloads.
  - confidence: 0.88
- **[P2] Narrow or de-duplicate underscore dispatch:** `src/hooks/internal-hooks.ts:317-318`
  - body: Adding `${type}_${action}` as a generic third dispatch key changes every internal hook event, not only this compatibility case, and a handler registered under both forms will run twice. Normalize the specific HOOK.md compatibility key at load time or de-duplicate handlers before dispatch.
  - confidence: 0.82
