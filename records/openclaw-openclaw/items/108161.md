## Summary

Keep this PR open: the bounded-download implementation appears narrow and correct, and current main still lacks it, but the external-PR proof does not demonstrate the generated Slack desktop bootstrap actually exiting and logging a failure when a download stalls.

## What This Changes

The PR adds connection and transfer time limits to four QA Lab Slack desktop bootstrap downloads and strengthens generated-script assertions for those curl options.

## Best Possible Solution

Keep the direct curl deadlines, add `--retry-max-time 120` if 120 seconds is intended as the cumulative retry budget, and demonstrate the generated bootstrap exiting with a useful log under a controlled stalled-download condition.

## Maintainer Decision

## Reproduction Assessment

Yes from source, but not as a live current-main run: the four pre-patch curl commands have no finite transfer timeout, so a non-responsive download can hold the bootstrap indefinitely.

## Solution Assessment

Mostly yes: applying deadlines at the download calls is the narrow owner-local fix, but cumulative retry semantics should be made explicit and the full generated failure path still needs real proof.
