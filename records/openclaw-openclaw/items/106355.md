## Summary

This is a well-proven and directionally sound native Automations feature, but the latest exact-head review still has one blocking upgrade-compatibility defect: the iOS lite Skills decoder can discard the entire Skills overview when connected to an older Gateway that omits newly added blocker fields. The subsequent final commit only removes the root changelog entry, so the finding remains unresolved.

## What This Changes

The PR adds native iOS and Android Automations management parity, caller-scoped cron pagination revisions, and follow-up native Skills fixes across iOS, Android, and macOS.

## Best Possible Solution

Default absent `os` and `anyBins` fields during iOS lite-model decoding, include both categories in the derived missing/requirements predicates, and add a regression test that decodes the previous Gateway payload shape without losing Skills data.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, from source and the latest review: decode a `skills.status` payload whose `missing` object contains only the previously supported `bins`, `env`, and `config` fields. The new synthesized decoder requires `os`, causing the optional overview request to return no Skills data.

## Solution Assessment

No, not at the current head. Reusing the existing cron contract and adding native parity is the right architecture, but the Skills follow-up must preserve decoding of the previously shipped Gateway response shape.
