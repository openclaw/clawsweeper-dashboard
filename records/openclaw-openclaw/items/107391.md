## Summary

Keep this issue open. Current main still allows the macOS Skills model to cache its initial status without an automatic reconnect refresh, while the report shows the Gateway’s later authoritative status is eligible; the remaining work is a bounded native-app state-refresh bug, not the separate `system.which` payload issue.

## What This Changes

Refresh the macOS Skills availability state after the local node reconnects so an eligible skill no longer remains marked unavailable.

## Best Possible Solution

Have the visible Skills model perform one coalesced forced `skills.status` refresh when the canonical local-node availability generation advances, while preserving manual refresh and avoiding polling or duplicate binary-probe logic in Swift.
