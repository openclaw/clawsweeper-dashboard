## Summary

Current main still adds a plain-text output directive to delivery-enabled isolated cron prompts, including a tested path where non-message tools such as `read` remain allowed. That creates a credible conflict with API-level tool calling, while the reporter’s eight model experiments provide useful but not independently reproduced live evidence. Likely related people: @shakkernerd (high confidence, sustained isolated-cron runner work), @steipete (high confidence, major runner refactors and merges), and @obviyus (medium confidence, adjacent cron model/tool work).

## What This Changes

Remove or neutralize the isolated cron announce footer’s plain-text output directive so models continue making normal API-level tool calls before automatic delivery.

## Best Possible Solution

Replace output-format commands in both delivery-instruction branches with delivery-only guidance, preserve the external-recipient warning, and add regression coverage proving announce prompts never discourage tool use when any agent tools remain available.
