## Summary

Keep open. Current `main` still routes a complex exec command classified as mutating through the mutating-warning branch before it can reach exec suppression, while the focused test only proves suppression for an explicitly non-mutating exec result. The report is therefore a credible remaining policy gap, but its remedy needs an explicit safety decision so genuinely mutating shell failures do not become silent.

## What This Changes

The issue requests that benign read-only exec commands with non-zero exits and shell syntax such as pipelines, redirects, or globs not emit a user-visible failure warning merely because conservative mutation detection classifies them as mutating.

## Best Possible Solution

Define warning eligibility separately from recovery-oriented shell mutation classification, then add focused cases for completed non-zero read-only pipelines/globs and actual mutating exec failures so the latter remain visible.

Options:

- **Separate warning classification (recommended):** Define a narrow warning classifier for exec results and add regression coverage for benign non-zero read-only shell commands while preserving warnings for confirmed mutating actions.
- **Preserve fail-closed warnings:** Keep current behavior for syntactically complex exec commands and document that their warning visibility is intentional until reliable command semantics are available.
- **Use result status only:** Suppress warning payloads when the tool result contract says `completed`, even if an exit code is non-zero, after confirming that contract across all exec backends.

## Reproduction Assessment

Yes at the source-policy level: an exec-like error with `mutatingAction: true` reaches the earlier mutating branch, whereas the existing suppression test only uses `mutatingAction: false`. A live Telegram run was not needed to establish this direct policy path.

## Solution Assessment

Unclear. Reordering the exec branch alone would also suppress warnings for truly mutating shell commands; the safer fix is a maintainer-approved separation between warning semantics and conservative mutation/recovery semantics.
