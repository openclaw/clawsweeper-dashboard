## Label Justifications

- `P1`: Untracked background PTY process trees can accumulate helper processes and memory after restart/session loss, affecting real agent/process workflows.
- `impact:session-state`: The central failure is drift between OpenClaw's tracked session/process state and live OS process ownership.
- `impact:crash-loop`: The reported impact is repeated helper-process families consuming memory and destabilizing the gateway host.
- `impact:security`: Any fix must prove ownership before killing or reattaching live process trees that may hold credentials or cross session boundaries.

## Summary

Keep open: current main and the latest release still use process-local supervisor/background-session state, and the linked fix PR is open, conflicting, and explicitly covers only the in-process half rather than durable restart orphan reaping.

## What This Changes

The issue asks OpenClaw to prevent PTY-backed background exec runs from surviving restart or session-state loss as untracked orphan process trees.

## Best Possible Solution

Choose a maintainer-approved restart policy, then land or replace the linked work with durable OpenClaw-owned exec metadata, startup reconciliation, process-tree cleanup or re-registration semantics, and focused PTY/child/session tests.

Question: For OpenClaw-owned background PTY exec runs that survive gateway restart or session-state loss, should startup reconciliation kill stale process trees, re-register recoverable runs, or limit the fix to live in-process drift?

Rationale: The source-level gap is clear, but the permanent behavior affects operator expectations, session-state recovery, process ownership, and the security/availability boundary for killing live descendants after restart.

Owner confidence: high

Options:

- **Kill stale OpenClaw-owned runs on startup (recommended):** Persist enough ownership metadata to identify prior-epoch OpenClaw exec trees and terminate them conservatively during gateway startup or doctor repair.
- **Re-register recoverable runs:** Attempt to restore tracked sessions for live prior-epoch PTY runs, accepting a more complex state and identity contract to preserve work.
- **Only fix in-process drift:** Adopt the narrower linked-PR approach for same-process registry drift and leave cold-start orphan reaping to a separate design.
