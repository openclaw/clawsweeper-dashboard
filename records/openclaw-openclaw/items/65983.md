## Summary

Keep open: current main and the latest release still keep exec/process ownership in memory, and the open linked PR only mitigates in-process session drift rather than durable restart/session-loss orphan cleanup.

## What This Changes

The issue reports that background PTY exec process trees can survive gateway restart or session-state loss while OpenClaw no longer tracks them.

## Best Possible Solution

Define one core-owned supervisor lifecycle policy that durably records active PTY background ownership and reconciles restart/session loss, then land https://github.com/openclaw/openclaw/pull/66001 or a replacement that implements that policy.

Owner confidence: medium

Options:

- **Kill stale startup orphans (recommended):** On gateway startup, use durable PTY exec records to terminate previous-epoch process trees that OpenClaw cannot safely own anymore, favoring availability and predictable cleanup.
- **Reattach previous-epoch runs:** Persist enough metadata to rebuild process sessions after restart, preserving long-running work but accepting a more complex ownership and security model.
- **Land only in-process reconciliation:** Treat https://github.com/openclaw/openclaw/pull/66001 as a scoped mitigation and keep a separate issue for cold-start orphan reaping.

Yes, at source level: current main keeps supervisor and process-session state in memory, and the docs explicitly say sessions are lost on restart. I did not run a live restart/orphan-process reproduction in this read-only review.

## Solution Assessment

Unclear as a final fix. Durable ownership and startup reconciliation belong in core, but maintainers still need to choose the kill-versus-reattach policy; the linked PR is only a partial in-process mitigation.
