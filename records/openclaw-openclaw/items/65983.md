## Summary

Keep open: current main and the latest release still use process-local supervisor/background exec state, while the linked fix PR remains open, conflicting, and explicitly does not cover durable cold-start orphan reaping.

## What This Changes

The issue asks OpenClaw to prevent PTY-backed background exec runs from surviving gateway restart or session-state loss as untracked orphan process trees.

## Best Possible Solution

Define a core-owned durable supervisor lifecycle for PTY background exec ownership, choose kill versus reattach semantics, then land https://github.com/openclaw/openclaw/pull/66001 or a replacement that covers the chosen restart/session-loss policy.

Options:

- **Kill stale PTY trees on startup (recommended):** Prefer availability and bounded resource use by treating untracked PTY background runs from an older gateway epoch as stale and terminating their process trees with audit logging.
- **Reattach tracked-looking runs:** Persist enough metadata to re-register compatible live PTY runs after restart, accepting more complexity and possible stale-state ambiguity.
- **Hybrid with explicit policy:** Kill by default but allow a narrow documented opt-in for reattachable long-running work once maintainers define the public contract.

## Solution Assessment

Unclear as a final fix until maintainers choose kill versus reattach semantics. Durable ownership and startup reconciliation belong in core, while the linked PR is only a partial in-process mitigation.
