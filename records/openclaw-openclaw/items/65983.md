## Summary

Keep open: current main and the latest release still keep background exec/process ownership in process-local memory, while the linked fix PR remains open and only covers an in-process subset of the restart/session-loss problem.

## What This Changes

The issue requests durable ownership and startup reconciliation for PTY-backed background exec runs that can survive a gateway restart or session-state loss and become untracked process trees.

## Best Possible Solution

Persist active PTY background ownership in core and add startup/session-loss reconciliation after maintainers choose kill versus reattach semantics, then land the linked PR or a replacement with focused tests and real restart proof.

- **Land in-process mitigation only:** Use the open PR to clean drift inside a live gateway while leaving cold-start orphan reaping as a known follow-up gap.
