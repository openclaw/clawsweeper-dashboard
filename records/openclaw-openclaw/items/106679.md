## Summary

The reported infinite recursion does not match the bounded current fallback design: generic failures traverse the configured candidates once and then return success or throw the final error. The proposed global network-error short circuit would also defeat intentional fallback to a local or independently reachable provider.

## What This Changes

Prevent model fallback from repeatedly cycling through configured models when a provider-independent network failure occurs.

## Best Possible Solution

Keep the finite candidate traversal so independently reachable and local fallbacks remain usable; if logs later show repeated whole-chain invocations, fix the outer caller's retry budget or session scheduling with a focused reproduction rather than globally suppressing network-error fallback.
