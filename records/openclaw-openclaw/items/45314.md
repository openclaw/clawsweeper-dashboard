## Summary

Keep open: current main still has a source-level early-abort responsePrefix context gap, and https://github.com/openclaw/openclaw/pull/45315 is still the open closing PR rather than a merged fix.

## What This Changes

The issue reports that stop/abort replies with templated `messages.responsePrefix` values leak `{model}` and `{thinkingLevel}` instead of resolved runtime values.

## Best Possible Solution

Land or replace the linked fix with a focused implementation that supplies active model/thinking prefix context to both direct dispatcher and routed abort delivery paths, with regression coverage for templated prefixes.

## Maintainer Decision

## Reproduction Assessment

Yes, source-level: configure a templated `messages.responsePrefix`, trigger `stop` or `/stop` while a run is active, and fast-abort delivery can normalize the reply before model/thinking context is populated. I did not run a live WhatsApp or Telegram transcript in this read-only review.

## Solution Assessment

No, this is not solved on current main. The best fix should use active session/channel/runtime model state and carry it through routed abort delivery, not only rely on normal `onModelSelected` timing.
