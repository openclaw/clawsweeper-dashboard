## Summary

Keep open: current main and the latest release still allow early abort replies to normalize a templated responsePrefix without model/thinking context, and the same-repo linked fix PR is open rather than merged.

## What This Changes

The issue reports that early abort replies can display unresolved `messages.responsePrefix` template variables such as `{model}` and `{thinkingLevel}` instead of resolved runtime values.

## Best Possible Solution

Land or replace the linked PR with a focused fix that carries active provider/model/thinking prefix context into early abort replies and covers the `/stop` fast-abort path with regression tests.
