## Label Justifications

- `P2`: This is a normal-priority user-visible behavior bug with limited blast radius: abort replies can show raw template tokens but do not block setup, auth, runtime availability, or delivery entirely.
- `impact:session-state`: The failure comes from reply-prefix rendering not receiving the selected model/thinking state for the active session before an early abort reply is emitted.

## Summary

This issue should stay open: current main still has the source-level early-abort/template gap, and https://github.com/openclaw/openclaw/pull/45315 is an open linked candidate rather than a merged fix. The merged message-tool prefix work in https://github.com/openclaw/openclaw/pull/93639 fixes an adjacent outbound-send path, but it does not resolve this fast-abort reply path.

## What This Changes

Early stop or abort replies should resolve dynamic `messages.responsePrefix` variables such as `{model}` and `{thinkingLevel}` instead of sending literal placeholders.

## Best Possible Solution

Land a narrow fix that gives fast-abort replies the same safe responsePrefix context as normal replies, using selected or persisted/default session runtime metadata where valid and keeping broader message-tool selected-model parity in https://github.com/openclaw/openclaw/issues/39913.

## Reproduction Assessment

Yes at source level. Current main still sends the fast-abort reply before `onModelSelected` populates model/thinking context, and the template resolver leaves missing `{model}` / `{thinkingLevel}` values literal.

## Solution Assessment

Yes, fixing the early-abort prefix context is the narrow maintainable direction. The open linked PR is the active candidate, while https://github.com/openclaw/openclaw/issues/39913 should remain the broader message-tool prefix parity follow-up.
