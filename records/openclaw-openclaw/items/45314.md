## What This Changes

The issue reports that templated `messages.responsePrefix` variables such as `{model}` and `{thinkingLevel}` are sent literally on early abort replies.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/45315 with a narrow fix that carries active session/model prefix context into fast-abort direct and routed delivery, then close this issue from the merged fix.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: configure a templated `messages.responsePrefix`, trigger `stop` or `/stop` while a run is active, and the fast-abort reply can be normalized before model/thinking context is populated.

## Solution Assessment

Yes on keeping the issue open, not on closing it yet. The best fix should use active session/channel model context and routed-delivery prefix context rather than only suppressing templates or seeding config defaults.
