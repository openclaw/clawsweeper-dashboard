## What This Changes

The issue reports that configured response-prefix template variables such as `{model}` and `{thinkingLevel}` leak literally in early abort replies instead of being populated.

## Best Possible Solution

Land or replace the open linked PR with a fix that derives abort-prefix context from active session, channel, fallback, and catalog state where available, and passes that context through both direct and routed abort delivery.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: configure a templated `messages.responsePrefix`, trigger `stop` or `/stop` while a run is active, and the fast-abort reply can be normalized before model/thinking context is populated.

## Solution Assessment

No, this is not solved on current main. The best fix should use active session/channel/runtime model state and carry it through routed abort delivery, not only rely on normal `onModelSelected` timing.
