## Summary

This issue is still necessary: current main and the latest release still fork the local embedding worker without an explicit executable, while open candidate PRs for the stale Homebrew Cellar Node path are not merged yet.

## What This Changes

The issue asks OpenClaw to keep local embedding worker forks working after a Homebrew Node upgrade removes the Gateway process's original Cellar Node binary.

## Best Possible Solution

Land one narrow worker-side fix that passes a stable executable path or otherwise recovers from stale execPath ENOENT, keeps package boundaries clean, and includes focused regression coverage plus macOS/Homebrew proof when feasible.

## Reproduction Assessment

Yes, at source level. Current main omits execPath at the local worker fork call, and Node defaults child_process.fork to process.execPath when execPath is absent, matching the reported stale Homebrew Cellar ENOENT path.

## Solution Assessment

Yes, the best fix is a narrow worker launch repair that uses a stable executable or retries with one after ENOENT. A doctor-only warning would not restore fresh worker forks for a running Gateway.
