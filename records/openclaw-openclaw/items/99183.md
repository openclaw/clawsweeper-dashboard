## Summary

This issue is still necessary: current main and the latest release still fork the local embedding worker without an explicit executable, and several open PRs are candidate fixes rather than merged implementations.

## What This Changes

The issue reports local embedding worker fork failures after Homebrew removes the Node binary path retained in a running Gateway process.

## Best Possible Solution

Review and land one corrected, proof-positive memory worker execPath fix, then close this issue from the merged PR and supersede the remaining candidate branches.

## Reproduction Assessment

Yes, at source level: current main still forks the local embedding worker without `execPath`, and Node's `fork()` defaults that executable to `process.execPath`. I did not run a live Homebrew upgrade reproduction in this read-only review.

## Solution Assessment

Yes: the narrow maintainable fix belongs at the worker spawn boundary by passing a stable Node executable or retrying with one after stale-execPath ENOENT. A doctor-only warning would not restore fresh worker forks for an already-running Gateway.
