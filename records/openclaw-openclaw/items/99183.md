## Summary

This should stay open: current main and the latest release still fork the local embedding worker without an explicit executable, so Node can inherit a deleted Homebrew Cellar `process.execPath`. The remaining work is already owned by open candidate PRs, with https://github.com/openclaw/openclaw/pull/99541 currently the strongest reviewed lane pending macOS/Homebrew proof.

## What This Changes

The issue reports that Homebrew Node upgrades can delete the Gateway process's inherited Cellar Node binary, causing new local embedding worker forks to fail with ENOENT and degrade memory search.

## Best Possible Solution

Review and land one canonical linked fix that gives the local embedding worker a stable Node executable path or a correct ENOENT recovery path with regression coverage, then close this issue after merge.

## Reproduction Assessment

Yes, source-reproducible with high confidence: current main omits `execPath` at the worker fork call, and Node defaults `fork()` to `process.execPath`. I did not run a live Homebrew upgrade reproduction in this read-only review.

## Solution Assessment

Yes, the right fix is a narrow worker-launch repair, not a new feature or health-check-only workaround. The best path is to land one linked implementation that resolves or retries with a stable executable and proves the stale-Cellar case.
