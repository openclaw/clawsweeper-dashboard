## Summary

This issue is still necessary: current main and the latest release still fork the local embedding worker without an explicit executable, while multiple open PRs now own candidate fixes for the same stale Homebrew Node path failure.

## What This Changes

The issue reports that after Homebrew removes an upgraded Node Cellar binary, the Gateway's local embedding worker forks inherit a stale `process.execPath` and semantic memory workers fail with `ENOENT`.

## Best Possible Solution

Review and land one corrected candidate PR that supplies a stable executable path or safe retry for the local embedding worker, keeps memory-core degradation handling aligned, and includes focused stale-Cellar regression proof; then close this issue as implemented.

## Reproduction Assessment

Yes, at source level: current main's worker `fork()` omits `execPath`, and Node 24 defaults that executable to `process.execPath`, matching the deleted Homebrew Cellar path mechanism. I did not run a live macOS Homebrew upgrade reproduction in this read-only review.

## Solution Assessment

Yes, the right fix shape is narrow: make the worker fork use a stable executable or retry once with a resolved executable after stale-path `ENOENT`. A doctor or warning-only path would still leave fresh worker forks broken until restart.
