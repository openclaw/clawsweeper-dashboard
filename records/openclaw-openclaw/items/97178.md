## What This Changes

Prevent gateway installation and recovery from creating a user LaunchAgent when a same-label system LaunchDaemon already supervises the gateway.

## System Context

The gateway CLI installs and inspects macOS launchd services, which then supervise the gateway process and connected clients. A user-domain LaunchAgent and system-domain LaunchDaemon can otherwise independently restart the same gateway label and port.

## Architecture Diagram

flowchart LR
  A[Gateway CLI command] --> B[Launchd service inspection]
  B --> C[System and user domain check]
  C -->|No conflict| D[User LaunchAgent activation]
  C -->|Same-label system daemon| E[Refuse with recovery guidance]
  D --> F[Gateway process]
  F --> G[Connected clients]

## Best Possible Solution

Land a narrow cross-domain ownership guard for install, restart, and recovery, with clear remediation guidance; keep full system LaunchDaemon lifecycle management as separate product work.

## Maintainer Decision

- **Design full lifecycle support first:** Pause this guard until install, status, restart, stop, uninstall, Doctor, and privilege handling share one approved system/user launchd contract.
