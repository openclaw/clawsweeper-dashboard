## Label Justifications

- `P1`: The deterministic duplicate-supervisor state restart-loops the gateway and breaks connected-client workflows until an operator removes one service.
- `impact:crash-loop`: Two KeepAlive launchd managers repeatedly terminate and respawn gateway processes competing for the same port.
- `impact:message-loss`: Repeated gateway restarts disconnect clients and prevent reliable inbound or outbound message handling while the loop persists.
- `maturity:stable`: The issue affects the M4 Stable Gateway lifecycle and macOS Gateway host surfaces.

## Summary

Keep open. The reported system-versus-user launchd conflict remains a valid gateway availability bug, and the open proof-positive fix PR specifically owns the narrow repair but has not merged.

## What This Changes

Prevent `openclaw gateway install` from creating a gui-domain LaunchAgent when the same gateway is already supervised by a system-domain LaunchDaemon.

## Best Possible Solution

Land a focused guard that checks both the system launchd domain and `/Library/LaunchDaemons` before any user plist write or activation, while leaving full privileged system-daemon lifecycle support to the broader companion issues.

## Maintainer Decision

## Reproduction Assessment

Yes, there is a high-confidence reproduction path. Current-beta live output establishes the status false-negative, and the linked PR's unfixed-main negative control demonstrates that the resulting install writes the conflicting user LaunchAgent.

## Solution Assessment

Yes for the narrow bug. Checking the existing launchd owner before plist mutation or service activation is the smallest maintainable repair; adding full system LaunchDaemon installation and privileged lifecycle management belongs in separate product work.
