## Summary

Keep open: current main and v2026.6.11 still serialize scheduled heartbeat work through busy-lane deferral, wake retry, and the normal reply path, so the requested non-blocking heartbeat execution model is not implemented. The open retry PR only targets a narrower requests-in-flight cadence problem, not a separate heartbeat execution lane.

## What This Changes

The issue requests asynchronous or separate-lane heartbeat execution so inbound user messages are not delayed while heartbeat work runs.

## Best Possible Solution

Keep this as the broad tracker for a maintainer-approved heartbeat isolation model, while narrower retry-cadence and TaskFlow/session-lock issues remain separate canonical work.
