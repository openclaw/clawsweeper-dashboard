## Summary

Keep open: current main and the latest release still defer heartbeat work through the shared runner/wake path and await the normal reply execution path, so the requested independent/non-blocking heartbeat execution model is not implemented. The related open PR only targets the narrower retry-cadence overlap, not this broader isolation design.

## What This Changes

The issue requests non-blocking heartbeat execution so heartbeat work no longer delays normal message processing.

## Best Possible Solution

Keep this as the broad maintainer tracker for a heartbeat isolation model, while reviewing narrower retry-cadence work separately under https://github.com/openclaw/openclaw/issues/40611 and https://github.com/openclaw/openclaw/pull/89989.

## Reproduction Assessment

Yes at source level: current main defers heartbeat runs on busy main/session state and awaits the shared reply path. I did not establish a live transport reproduction of the exact reported delay duration.

## Solution Assessment

Unclear: a background worker or separate heartbeat lane is plausible, but maintainers first need to define the isolation contract for session state, delivery ordering, retries, and tool side effects.
