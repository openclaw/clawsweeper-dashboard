## Summary

Keep open: current main and v2026.6.11 still run heartbeat as an awaited heartbeat agent turn, with mitigations like `isolatedSession`, `lightContext`, busy deferral, and timeout controls but no non-blocking heartbeat execution lane. The open related PR only targets the narrower retry-cadence bug in https://github.com/openclaw/openclaw/issues/40611, so this remains a product and architecture decision.

## What This Changes

The issue requests non-blocking heartbeat execution, proposed as a background worker thread, so user message processing is not delayed while heartbeat checks run.

## Best Possible Solution

Keep this as the architecture tracker until maintainers choose whether heartbeat should get a separate execution lane and define its session, delivery, and tool-state isolation contract.
