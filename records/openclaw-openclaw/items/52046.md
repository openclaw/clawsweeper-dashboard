## Summary

Keep open: current main and latest release still run heartbeat as an awaited heartbeat agent turn with busy deferral and mitigation options, but not a non-blocking heartbeat execution lane. The remaining work is a core product/architecture decision, not a stale or already-implemented cleanup item.

## What This Changes

Request to run heartbeat checks without blocking the main message-processing path so user messages are not delayed while heartbeat work runs.

## Best Possible Solution

Keep this as the architecture tracker until maintainers decide whether heartbeat should get a separate execution lane and define the session, delivery, busy-state, and tool-side-effect contract.

## Solution Assessment

Unclear as an implementation: a worker thread is one plausible shape, but the best fix first needs an explicit heartbeat isolation contract across session state, delivery ordering, busy checks, and tool side effects.
