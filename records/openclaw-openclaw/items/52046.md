## Summary

Keep open: current main and v2026.6.11 still model heartbeat as awaited main-session work, not a separate non-blocking heartbeat execution lane. The related open PR only targets the narrower requests-in-flight retry cadence, so the central request remains a product and architecture decision.

## What This Changes

The issue requests non-blocking or background heartbeat execution so heartbeat checks do not delay user message processing.

## Best Possible Solution

Define a maintainer-approved isolated heartbeat execution contract covering lane choice, session ownership, delivery ordering, and tool side effects, while handling narrower retry-cadence work separately.
