## Summary

Keep open: current main and v2026.6.11 still run heartbeat as an awaited scheduled agent turn rather than a non-blocking heartbeat execution lane. Existing `isolatedSession` and `lightContext` reduce heartbeat cost, and https://github.com/openclaw/openclaw/pull/89989 only targets the narrower retry-cadence issue in https://github.com/openclaw/openclaw/issues/40611, so this remains a product/architecture decision.

## What This Changes

The issue requests moving heartbeat checks off the main message-processing path so user messages are not delayed while heartbeat work runs.

## Best Possible Solution

Define a maintainer-approved isolated heartbeat execution contract that preserves session/delivery ordering and tool safety, while handling narrower retry-cadence fixes through the existing linked heartbeat regression path.
