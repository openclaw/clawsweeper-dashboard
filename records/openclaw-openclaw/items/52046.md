## Summary

Keep open: current main and the latest release still serialize/defer heartbeat work through the shared heartbeat runner and wake retry path, while the related open PR only targets the narrower retry-cadence overlap rather than independent non-blocking heartbeat execution.

## What This Changes

## Best Possible Solution

Keep this as the broad tracker for a maintainer-approved heartbeat isolation model that preserves session state, delivery ordering, tool side effects, retry/admission semantics, and existing heartbeat tuning behavior.

## Solution Assessment

Unclear: a background worker or separate heartbeat lane is plausible, but the best fix needs a maintainer-defined isolation contract for session state, delivery ordering, retry behavior, and tool side effects.
