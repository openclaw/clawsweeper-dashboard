## Summary

Keep open: current main and the latest release still defer or retry heartbeat work through shared runner/wake paths and await the normal reply path, so the requested non-blocking heartbeat execution model is not implemented. The related open retry PR only addresses a narrower cadence problem, not a separate heartbeat execution lane.

## What This Changes

Request non-blocking heartbeat execution so heartbeat checks do not delay inbound message processing or cause duplicate user sends.

## Best Possible Solution

Keep this as the broad tracker for a maintainer-approved heartbeat isolation model, while the narrower retry-cadence regression remains owned by https://github.com/openclaw/openclaw/issues/40611 and https://github.com/openclaw/openclaw/pull/89989.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Partially: source inspection shows current main still defers/retries busy heartbeat work and awaits the normal reply path, but I did not establish a live transport reproduction of the exact 5-10 second delay.

## Solution Assessment

Is this the best way to solve the issue? Unclear: a background worker or separate heartbeat lane is plausible, but the best fix needs a maintainer-defined isolation contract for session state, delivery ordering, retry behavior, and tool side effects.
