## Summary

Keep open: current main and v2026.6.11 still use serialized heartbeat skip/retry and the normal reply path, so the requested non-blocking heartbeat execution model is not implemented. The open retry-cadence PR only addresses a narrower overlap with active conversations, not a separate heartbeat execution lane.

## What This Changes

Requested behavior is a non-blocking heartbeat execution model so heartbeat checks do not delay incoming message processing.

## Best Possible Solution

Keep this as the broad tracker for a maintainer-approved heartbeat isolation model, while https://github.com/openclaw/openclaw/issues/40611 and https://github.com/openclaw/openclaw/pull/89989 handle the narrower retry-cadence regression.
