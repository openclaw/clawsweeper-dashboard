## Summary

Keep open: current main and v2026.6.11 still implement heartbeat as serialized/backpressured agent work, not as a non-blocking heartbeat execution lane. The related open retry PR only addresses the narrower retry cadence regression, so this broader feature still needs maintainer product and architecture review.

## What This Changes

Requests a non-blocking or isolated heartbeat execution model so heartbeat checks do not delay user message processing.

## Best Possible Solution

Keep this as the broad tracker for a maintainer-approved heartbeat isolation model, while narrower retry cadence and idle gating work remain on their own canonical issues.
