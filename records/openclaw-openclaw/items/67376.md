## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Guard runtime clearing to the closing server:** `src/gateway/mcp-http.loopback-runtime.ts:29-30`
  - body: The patch clears the global runtime and all registered tokens unconditionally when any loopback server closes. If a new server starts before the old close callback runs, the old server can erase the new server's active token table and cause fresh backends to receive 401s.
  - confidence: 0.92
- **[P2] Revoke tokens even when backend cleanup fails:** `src/agents/cli-runner.ts:124-126`
  - body: The new token revocation runs after `preparedBackend.cleanup`; if that cleanup throws, the scoped bearer remains registered after run teardown. Put token revocation in its own `finally` so stale authorization state is removed regardless of backend cleanup errors.
  - confidence: 0.88
- **[P2] Clean up tokens on all prepare failures:** `src/agents/cli-runner/prepare.ts:145-153`
  - body: The token is registered before later preparation work runs, but only the bundle-MCP config call has a catch that unregisters it. Wrap the rest of preparation after token issuance so any later throw unregisters the bearer before returning the error.
  - confidence: 0.86

## Security Review

Status: needs_attention

Concerns:

- **[medium] Runtime clear can revoke a newer server:** `src/gateway/mcp-http.loopback-runtime.ts:29`
  - body: Unconditional runtime/token-table clearing can wipe tokens from a freshly started loopback server when an older server close finishes later.
  - confidence: 0.92
