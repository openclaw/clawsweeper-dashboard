Overall confidence: 0.94

Full review comments:

- **[P1] Bind the full loopback context to tokens:** `src/gateway/mcp-http.loopback-runtime.ts:7-12`
  - body: The new scoped token records only the old four-field tuple, but current main's MCP loopback context also includes session id, channel/thread/message ids, inbound audio, inbound-event kind, delivery mode, and explicit-target policy. A rebased fix needs those server-bound fields in the token scope so the gateway does not lose or leave unprotected the current tool-resolution context.
  - confidence: 0.96
- **[P1] Preserve GET and DELETE lifecycle auth:** `src/gateway/mcp-http.request.ts:73-76`
  - body: This branch rejects every non-POST /mcp request, but Codex's Streamable HTTP client sends the bearer on POST, DELETE teardown, and GET/SSE startup. With the scoped token path merged this way, a generated client can use tools over POST and still fail lifecycle requests with 405.
  - confidence: 0.95
- **[P2] Guard runtime clearing by the closing server:** `src/gateway/mcp-http.loopback-runtime.ts:30-32`
  - body: The new clear helper wipes activeRuntime and all registered tokens unconditionally. If an old close completes after another ensureMcpLoopbackServer call has started a fresh server, the old close can erase the new server's valid token table and cause 401s.
  - confidence: 0.92
- **[P2] Always revoke tokens after cleanup failures:** `src/agents/cli-runner.ts:124-126`
  - body: The token is unregistered only after preparedBackend.cleanup resolves. If cleanup throws, the finally block exits before unregisterMcpLoopbackToken runs, leaving a scoped bearer registered after the run is supposed to be torn down.
  - confidence: 0.9
- **[P2] Revoke issued tokens on later prepare errors:** `src/agents/cli-runner/prepare.ts:173-177`
  - body: The catch only covers prepareCliBundleMcpConfig. Any later prepare failure, such as docs-path or prompt preparation, skips unregistering the token that was already inserted into the process registry.
  - confidence: 0.88
