  - body: This scope only records the older session/account/channel/owner tuple. Current main also threads session id, channel/thread/message ids, inbound audio, inbound-event kind, delivery mode, and explicit-target policy into loopback tool resolution, so rebasing this patch either drops those contexts or keeps a spoofable header path for them.
  - confidence: 0.96
- **[P1] Keep lifecycle auth compatible with Streamable HTTP:** `src/gateway/mcp-http.request.ts:73-76`
  - body: The PR rejects every non-POST request with 405. Current Codex Streamable HTTP clients send the same configured bearer headers on POST, DELETE teardown, and GET/SSE startup, so this would break lifecycle requests or force a second auth path around the scoped token model.
  - confidence: 0.94
- **[P1] Guard runtime clearing to the closing server:** `src/gateway/mcp-http.loopback-runtime.ts:30-33`
  - body: `clearActiveMcpLoopbackRuntime()` clears the global runtime and every registered token without checking which server is closing. If an old close finishes after a new loopback server starts, valid fresh backends can lose their tokens and start failing authorization.
  - confidence: 0.92
- **[P2] Revoke tokens even when cleanup throws:** `src/agents/cli-runner.ts:124-127`
  - body: Token revocation runs after `preparedBackend.cleanup`, so a cleanup exception skips `unregisterMcpLoopbackToken` and leaves the bearer registered past run teardown. Put revocation in its own finally path so cleanup failures cannot preserve stale authorization.
  - confidence: 0.9
