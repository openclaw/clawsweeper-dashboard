Overall correctness: patch is incorrect

Overall confidence: 0.93

Full review comments:

- **[P1] Bind every current context field to scoped tokens:** `src/gateway/mcp-http.loopback-runtime.ts:7-12`
  - body: The new token scope only records four fields, but current main's loopback context also includes session id, channel/thread/message ids, inbound audio, inbound-event kind, delivery mode, and explicit-target policy. After rebase this either drops current behavior or forces those fields back through mutable headers, so the token-bound scope needs to carry the full current tuple.
  - confidence: 0.94
- **[P1] Guard runtime clearing to the closing server:** `src/gateway/mcp-http.loopback-runtime.ts:30-32`
  - body: `clearActiveMcpLoopbackRuntime()` clears the active runtime and whole token table unconditionally. If an old server finishes closing after a new server starts, it can revoke fresh tokens and cause valid loopback clients to get 401s until they re-register.
  - confidence: 0.92
- **[P2] Revoke the token even when cleanup fails:** `src/agents/cli-runner.ts:123-127`
  - body: The token is unregistered only after `preparedBackend.cleanup` succeeds. A cleanup exception skips revocation, leaving a bearer token registered after run teardown and growing the per-request token scan set.
  - confidence: 0.88
- **[P2] Clean up tokens on later prepare failures:** `src/agents/cli-runner/prepare.ts:173-177`
  - body: Only `prepareCliBundleMcpConfig` failures unregister the token. Later preparation steps, such as docs-path or prompt setup, can still throw before the cleanup handle is returned, leaving the scoped token registered in process memory.
  - confidence: 0.86
