## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.95

Full review comments:

- **[P1] Bind every current loopback context field:** `src/gateway/mcp-http.loopback-runtime.ts:7-12`
  - body: This token scope records only the older session/account/channel/owner tuple, but current main also carries session id, channel/thread/message ids, inbound audio, inbound event, delivery mode, and explicit-target policy into loopback tool resolution. A rebased fix needs the full current tuple to avoid leaving spoofable or stale context around the auth boundary.
  - confidence: 0.96
- **[P1] Accept scoped tokens on lifecycle requests:** `src/gateway/mcp-http.request.ts:73-76`
  - body: The validator rejects every non-POST request, but Codex Streamable HTTP sends the same bearer on POST, DELETE teardown, and GET/SSE startup. Scoped loopback tokens need to authenticate on all three paths or generated clients can list/call tools and then fail transport startup or teardown with 401/405 behavior.
  - confidence: 0.94
- **[P1] Guard runtime clearing to the server being closed:** `src/gateway/mcp-http.loopback-runtime.ts:30-32`
  - body: `clearActiveMcpLoopbackRuntime()` clears the global runtime and all registered tokens unconditionally. If a new loopback server starts while an older close is still draining, the old close can wipe the new server's token table and make fresh backends fail authorization.
  - confidence: 0.9
- **[P2] Revoke the token even when backend cleanup throws:** `src/agents/cli-runner.ts:124-127`
  - body: The new revocation runs after `await context.preparedBackend.cleanup?.()`, so a cleanup failure skips token unregistering. Wrap cleanup and unregister in nested `finally` blocks so teardown errors cannot leave a scoped bearer registered past the run.
  - confidence: 0.9
- **[P2] Revoke tokens on every post-registration prepare failure:** `src/agents/cli-runner/prepare.ts:173-177`
  - body: The prepare path unregisters only when `prepareCliBundleMcpConfig` rejects; later failures such as docs, skills, prompt, or execution preparation can still throw before the cleanup object is returned. Once the token is registered, the rest of preparation needs an outer error cleanup.
  - confidence: 0.88
