## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.94

Full review comments:

- **[P1] Bind every current loopback scope field:** `src/gateway/mcp-http.loopback-runtime.ts:7-12`
  - body: `McpLoopbackScope` only records the older session/account/channel/owner tuple, but current main also uses session id, channel/thread/message ids, inbound audio, inbound-event kind, delivery mode, and explicit-target policy when resolving loopback tools. A rebased fix needs to bind the full current tuple server-side, otherwise those fields remain client-controlled or get dropped.
  - confidence: 0.95
- **[P1] Guard runtime clearing by the server being closed:** `src/gateway/mcp-http.ts:117`
  - body: `clearActiveMcpLoopbackRuntime()` clears the global runtime and token table unconditionally. If an old server close races with a newly started server, the old close can wipe the fresh runtime's tokens and make valid backends start receiving 401s.
  - confidence: 0.93
- **[P2] Revoke the token when cleanup throws:** `src/agents/cli-runner.ts:124-126`
  - body: The new revocation runs after `await context.preparedBackend.cleanup?.()`. If cleanup throws, the `unregisterMcpLoopbackToken` call is skipped and a bearer token can remain live after run teardown.
  - confidence: 0.9
- **[P2] Unregister tokens on later prepare failures:** `src/agents/cli-runner/prepare.ts:173-177`
  - body: The catch only covers `prepareCliBundleMcpConfig`, but later preparation work can still throw before the returned context exposes cleanup. Wrap the post-registration preparation block so every failure path unregisters the token.
  - confidence: 0.88
