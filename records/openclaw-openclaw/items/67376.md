- **[P1] Bind every loopback context field to the token:** `src/gateway/mcp-http.loopback-runtime.ts:7-12`
  - body: `McpLoopbackScope` records only `sessionKey`, `accountId`, `messageProvider`, and `senderIsOwner`, but current main also routes session id, channel/thread/message ids, inbound audio, inbound event kind, reply-delivery mode, and explicit-target policy into tool resolution. After rebasing, those omitted fields would remain client-controlled or be dropped, leaving the auth boundary incomplete.
  - confidence: 0.95
- **[P1] Keep runtime clearing scoped to the server instance:** `src/gateway/mcp-http.loopback-runtime.ts:30-33`
  - body: `clearActiveMcpLoopbackRuntime()` clears the active runtime and token table unconditionally. If an old server close races a new `ensureMcpLoopbackServer()`, the old close can wipe the new server's tokens and make fresh backends start failing with 401s.
  - confidence: 0.92
- **[P2] Revoke tokens after cleanup failures too:** `src/agents/cli-runner.ts:122-125`
  - body: The new unregister call runs after `await context.preparedBackend.cleanup?.()`. If cleanup throws, token revocation is skipped and the bearer remains registered past run teardown.
  - confidence: 0.9
- **[P2] Revoke tokens on all prepare failures:** `src/agents/cli-runner/prepare.ts:173-177`
  - body: The `.catch()` only unregisters when `prepareCliBundleMcpConfig` fails. Any later preparation failure before the prepared context is returned leaves the just-issued token registered without a backend lifecycle cleanup path.
  - confidence: 0.86
