Full review comments:

- **[P1] Bind the full current loopback context:** `src/gateway/mcp-http.loopback-runtime.ts:7-13`
  - body: This branch's scoped token model covers only the older session/account/channel/owner tuple, but current main also passes session id, current channel/thread/message, inbound audio, inbound event kind, source reply delivery, and explicit-target policy through the same request context. Any adopted version needs to bind the full current tuple server-side or it leaves a competing spoofable context channel.
  - confidence: 0.93
- **[P1] Guard runtime clearing by server identity:** `src/gateway/mcp-http.loopback-runtime.ts:30-33`
  - body: `clearActiveMcpLoopbackRuntime()` clears the active runtime and token table unconditionally. If an old server close races a new `ensureMcpLoopbackServer()` startup, the old close can wipe the new server's registered tokens and make fresh backends get 401s.
  - confidence: 0.94
- **[P2] Always revoke after backend cleanup failures:** `src/agents/cli-runner.ts:124-126`
  - body: The new unregister call runs after `preparedBackend.cleanup`; if cleanup throws, token revocation is skipped and the bearer can stay registered past run teardown.
  - confidence: 0.9
- **[P2] Revoke scoped tokens on prepare failures:** `src/agents/cli-runner/prepare.ts:148-177`
  - body: The token is registered before later preparation work completes, but only the bundle-MCP config failure path revokes it. Later failures can leave a scoped bearer in the registry without any returned cleanup handle.
  - confidence: 0.86
