- `P2`: A growing durable usage-cost cache can create large local disk and IO pressure for high-churn users, but it does not make the core runtime unusable.
- `impact:other`: The issue concerns local runtime cache growth and disk/refresh cost outside the more specific impact taxonomy.
- `maturity:stable`: The affected Gateway usage RPC surface maps to Gateway runtime / Gateway RPC APIs and Events, which is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main still builds the durable usage-cost cache from every usage-counted transcript file, including reset/deleted archives, and only removes cache entries when the path disappears; the reported durable cache growth is not fixed by the older in-memory gateway cache cap.

## What This Changes

The issue asks OpenClaw to bound or prune `.usage-cost-cache.json` entries for deleted/reset transcript archives so high-churn session directories do not create permanently growing durable cache files.

## Best Possible Solution

Keep this open and implement a narrow durable-cache fix that reuses existing session maintenance retention for expired reset/deleted archives, avoiding a new usage-cost config surface unless maintainers explicitly choose one.

## Reproduction Assessment

Yes, at source level. A current-main reproduction would create a cached old `.jsonl.deleted.*` or `.jsonl.reset.*` archive that still exists on disk, run cache refresh, and observe the entry remains because the path is still in `livePaths`; no live test was run because this review is read-only.

## Solution Assessment

Yes for the retention part: the narrowest maintainable fix is in the durable usage-cache file listing/refresh path, reusing existing session maintenance retention. Adding new `sessions.usageCost.*` config or a correctness-changing cap should be deferred unless maintainers choose that policy.
