## Summary

Keep open: current main and v2026.6.11 still keep reset/deleted archive files in the usage-counted live set and only evict cache entries after the underlying file disappears, with no cache-level entry or byte cap visible in the usage-cost cache path.

## What This Changes

The issue requests bounded retention for the usage-cost cache so deleted/reset transcript archive entries cannot grow the cache indefinitely.

## Best Possible Solution

Define a bounded, retention-aware usage-cost cache policy in the canonical cache/storage layer, preserving archive-aware historical cost reporting while preventing retained archives from making generated cache state grow without limit.

## Reproduction Assessment

Yes, at source level. Current main includes reset/deleted archives in the usage-counted file list and evicts cache entries only when those paths disappear, with no cache-level cap found in the usage-cost cache implementation.

## Solution Assessment

Unclear as proposed. Retention-aware bounding is the right direction, but adding a new knob or dropping archived usage by default needs maintainer policy because it can conflict with historical cost accounting.
