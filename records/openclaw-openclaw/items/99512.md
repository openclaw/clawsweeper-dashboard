## Summary

Keep open: current main and v2026.6.11 still keep reset/deleted archive paths in the usage-cost cache live set, and the durable cache has no independent retention, entry, or byte bound. The issue is valid, but the permanent fix needs maintainer policy because archived transcripts are intentionally usage-counted to avoid underreporting spend.

## What This Changes

The issue asks OpenClaw to stop unbounded growth of `.usage-cost-cache.json` caused by retained reset/deleted transcript archives and the absence of a cache-level size cap.

## Best Possible Solution

Bound generated usage-cost cache state by reusing or explicitly aligning with existing session archive retention, preserving archive-aware spend reporting and avoiding new config surface unless maintainers decide current retention semantics cannot cover this cache.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still treat reset/deleted archives as usage-counted live paths and evict usage-cache entries only when those paths disappear; I did not run a live large-cache replay.

## Solution Assessment

No as proposed without maintainer choice. Retention-aware bounding is the right direction, but adding new usage-cost knobs or changing archive history semantics should be decided against the existing session maintenance policy and storage guidance.
