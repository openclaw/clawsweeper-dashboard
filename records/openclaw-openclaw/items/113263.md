## Summary

Keep open. This is a concrete Matrix-plugin ergonomics request, but changing expiry from redaction to persistent in-room command text needs an explicit privacy and security-default decision before implementation; current evidence does not show that main or the latest release already made that change.

## What This Changes

Change expired Matrix execution-approval prompts from redactions into in-place terminal-state edits that preserve the requested command for auditability.

## System Context

Matrix’s native approval adapter turns pending execution requests into room messages and later applies their terminal outcome. The expiry branch currently decides whether the original prompt is removed or updated, affecting room history, reaction bindings, and what reviewers can audit afterward.

## Architecture Diagram

flowchart LR

  B --> C{Decision before TTL?}
  C -->|Allowed or denied| D[Update prompt and clear reactions]
  C -->|Expired| E[Expiry terminal action]
  E --> F[Room timeline and audit history]
  D --> F

## Best Possible Solution

Decide the intended security posture for expired Matrix approvals first; if retention is approved, update the Matrix plugin’s existing terminal-update path and add focused expiry coverage without adding a config option unless distinct room policies are truly required.
