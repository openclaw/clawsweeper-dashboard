## Label Justifications

- `P2`: A shipped Telegram formatter bug removes navigation from a bounded class of otherwise valid messages.
- `impact:message-loss`: The outgoing Telegram message silently loses the user-authored link target.

## Summary

Keep this issue open: current main and v2026.6.11 both suppress intentional Telegram links when the visible label resembles a supported file reference, and no related issue or PR owns the remaining fix.

## What This Changes

Preserve intentional file-like links in Telegram while continuing to suppress parser-generated file-reference autolinks.

## Best Possible Solution

Add optional automatic-link provenance at the shared Markdown parser boundary, propagate it through IR transformations, suppress only proven automatic file-reference links in Telegram, and preserve direct HTML anchors whose origin is unknown.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from current-main source inspection: explicit and automatic file-like links collapse to the same MarkdownLinkSpan, and Telegram suppresses both. This read-only review did not run a live Telegram capture.

## Solution Assessment

No, restricting only the final anchor regex is incomplete because buildTelegramLink already removes the link earlier. The narrow maintainable solution is to preserve Markdown-it's automatic-link marker through the shared IR and use it at the Telegram rendering boundary.
