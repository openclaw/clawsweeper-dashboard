## Summary

Keep open: current main and the latest release still have daily/idle/manual reset, compaction, pruning, store maintenance, heartbeat isolation, and thread-binding max-age controls, but no normal-session max-age or max-turn rotation policy with safe continuity semantics.

## What This Changes

Requests configurable maximum session age and turn count so long-running agent sessions rotate automatically after preserving state.

## Best Possible Solution

Design one core session-lifecycle policy with canonical age/turn triggers, durable accounting, safe memory or continuity behavior, docs, and focused upgrade tests.

## Reproduction Assessment

Yes, at source level: current main lacks normal-session max-age/max-turn config, durable turn accounting, and reset freshness inputs for this policy. I did not run a six-day fleet reproduction because the requested policy is absent in source.

## Solution Assessment

Unclear until maintainers choose the public config, defaults, and continuity semantics. The likely owner is core session lifecycle, while thread-binding max-age, pruning, compaction, or plugin hooks alone do not satisfy the requested normal-session rotation.
