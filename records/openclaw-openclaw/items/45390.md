## Summary

Keep open: current main and v2026.6.11 still lack a normal-session max-age or max-turn rotation policy. The existing daily/idle reset, cache-TTL context pruning, session-store maintenance, and thread-binding max-age mechanisms are adjacent but do not provide the requested lifecycle cap for ordinary sessions.

## What This Changes

The issue requests configurable session max-age and max-turn limits that automatically rotate long-running agent sessions after preserving memory.

## Best Possible Solution

Design one core session-lifecycle policy with canonical config, durable age/turn accounting, safe pre-rotation continuity or memory behavior, docs, and focused upgrade tests.

## Reproduction Assessment

Yes, at source level: current main has daily/idle reset freshness, thread-binding max-age, session-store maintenance, and cache-TTL pruning, but no normal-session max-age or max-turn rotation policy. I did not run a six-day fleet reproduction because the requested policy is absent from current source.

## Solution Assessment

Unclear until maintainers choose the public config, defaults, and continuity semantics. The narrowest maintainable direction appears to be one core session lifecycle policy, not separate fixes in thread bindings or context pruning alone.
