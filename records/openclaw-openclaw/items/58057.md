## Summary

Keep open: current main and v2026.6.11 still only support static DM/group policy values plus static generic access groups, with Discord channel audiences as partial progress. The requested generic dynamic authorization path remains security-sensitive product/API work.

## What This Changes

Request dynamic inbound sender authorization for DM/group allowlists, including a resolver or hook mode and unknown-sender routing for iMessage/BlueBubbles-style deployments.

## Best Possible Solution

Define a maintainer-approved channel ingress or access-group authorization seam with fail-closed resolver semantics, bounded caching/timeouts, diagnostics, and docs, then wire iMessage/BlueBubbles through it without ad hoc policy values.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 only accept static DM/group policy values, and iMessage drops blocked senders before routing. This proves the requested feature is absent, not that current documented behavior is broken.

## Solution Assessment

Unclear. The user need is valid, but HTTP resolver, pre-allowlist hook, unknown-sender routing, and dynamic access-group membership are different security/API shapes that need maintainer selection.
