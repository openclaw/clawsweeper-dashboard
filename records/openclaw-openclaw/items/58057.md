## Summary

Keep open: current main and v2026.6.11 still only support static DM/group policy values plus static access groups and Discord-only dynamic channel audiences. The requested generic iMessage/HTTP identity resolver remains a real security-sensitive feature/API decision, not cleanup-close material.

## What This Changes

The issue requests dynamic sender/group authorization for channel allowlists, including resolver-backed `dmPolicy`/`groupPolicy` behavior and unknown-sender handling.

## Best Possible Solution

Define a maintainer-approved shared authorization seam, likely through channel ingress or access groups, so iMessage can use external identity lookup without ad hoc config rewrites or per-channel policy forks.

## Reproduction Assessment

Yes, for source-level absence: current main has no dynamic DM/group policy value, and the iMessage path drops or pairs unauthorized senders before dispatch. This proves the requested feature is missing, not that documented current behavior is broken.

## Solution Assessment

Unclear. The need is valid, but an HTTP resolver, a pre-allowlist hook, unknown-sender routing, and dynamic access-group membership are different security/API shapes that need maintainer selection before implementation.
