## Summary

Keep open: the current head still records byte-trigger retry metadata from the stale session entry when the compactor omits an unchanged session file, so the repeated-compaction loop can survive in the active-transcript path.

## What This Changes

This PR adds persisted SessionEntry byte-compaction retry metadata and a 1 MiB/10% growth guard to suppress repeated byte-triggered preflight compactions while preserving token-triggered compaction.

## Best Possible Solution

Record byte-trigger retry metadata against the active post-compaction transcript that was actually compacted, then land only after maintainers accept the growth-threshold suppression policy.

## Reproduction Assessment

Yes, at source level: current main recalculates the byte trigger every preflight with no memory of a prior byte-triggered compaction result. I did not run a live long-session reproduction in this read-only review.

## Solution Assessment

No as currently written: the PR is in the right owner boundary, but retry state must be keyed to the active post-compaction transcript file instead of falling back to a stale entry when the compactor omits unchanged result fields.
