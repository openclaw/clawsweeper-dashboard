## Summary

Keep open for maintainer review: the current patch reads as correct and the prior active-transcript retry-metadata finding is fixed, but it changes persisted session-state and byte-compaction retry policy, so it should land only after owner acceptance and normal merge gates.

## What This Changes

The branch adds byte-triggered preflight compaction retry metadata to SessionEntry and suppresses repeat byte-triggered retries for the same active transcript until the file, threshold, or material growth changes.

## Best Possible Solution

Land after maintainers accept the additive SessionEntry retry metadata and the 1 MiB/10% byte-growth hysteresis as the supported byte-compaction retry policy.

## Reproduction Assessment

## Solution Assessment

Yes, with maintainer policy acceptance. Persisting retry state on SessionEntry is the right owner boundary for suppressing repeated byte-triggered compactions across turns, and the PR also reserves the fields from plugin slots.
