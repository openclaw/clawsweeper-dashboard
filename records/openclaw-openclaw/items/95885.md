## Summary

Keep open: the PR is an active, clean, proof-backed bug fix for byte-triggered preflight compaction retry loops, and current main does not already contain the retry metadata or suppression behavior. I found no blocking correctness finding, but the change intentionally adds persisted session-state metadata, so maintainers should make the final session-state policy call before merge.

## What This Changes

The PR records byte-triggered preflight compaction retry metadata on `SessionEntry` and suppresses repeat byte-triggered compaction for the same active transcript until file, threshold, or material growth changes.

## Best Possible Solution

Land this localized preflight-compaction hysteresis after maintainers accept the persisted session-state policy and normal merge gates stay green.

## Reproduction Assessment

Yes. Current main has a source-level reproduction: if a byte-triggered compaction leaves the active transcript above `maxActiveTranscriptBytes`, the next turn sees the same byte condition and has no retry hysteresis before compacting again.

## Solution Assessment

Yes, with a maintainer policy check. The PR keeps the fix in the preflight compaction owner path, avoids adding another config knob, preserves token-triggered compaction, and records enough active-transcript state to distinguish stale retries from legitimate new growth.
