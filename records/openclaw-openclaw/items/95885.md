## Summary

Keep open: this is a focused bug-fix PR for a real source-level compaction loop risk. The patch appears correct and the previous active-transcript finding is fixed, but it changes persisted session state and byte-compaction retry policy, so maintainer review remains the right next step before merge.

## What This Changes

The PR adds byte-triggered preflight compaction retry metadata to `SessionEntry` and suppresses repeated byte-triggered retries for the same active transcript until the file, threshold, or material growth changes.

## Best Possible Solution

Land after maintainers accept the additive retry metadata and the 1 MiB/10% byte-growth hysteresis as the supported byte-compaction retry policy.

## Reproduction Assessment

Yes. At source level, current main recalculates the byte trigger on every preflight with no stored retry state, so an oversized active successor transcript can immediately trigger byte compaction again.

## Solution Assessment

Yes, with a maintainer policy check. Persisting retry state in `SessionEntry` is the right owner boundary for suppressing repeated preflight decisions across turns while preserving token-triggered compaction precedence.
