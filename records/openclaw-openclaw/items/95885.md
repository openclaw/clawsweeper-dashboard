## What This Changes

The PR adds byte-triggered preflight compaction retry metadata to `SessionEntry` and suppresses repeat byte compactions for the same active transcript until the threshold/file changes or the transcript grows materially.

## Best Possible Solution

Land only after maintainers accept the additive `SessionEntry` retry metadata and the 1 MiB/10% byte-growth hysteresis as the supported byte-compaction retry policy.

## Reproduction Assessment

Yes, at source level: current main recalculates the byte trigger on each preflight with no stored byte-compaction retry state, so an oversized successor transcript can immediately trigger again. I did not run a live long-session reproduction in this read-only review.

## Solution Assessment

Yes, this is the right owner boundary for a bounded fix: the PR keeps token compaction unchanged, persists retry state on `SessionEntry`, reserves plugin slot keys, and covers the same-file, active-file, threshold, and growth cases. The remaining question is maintainer acceptance of the exact hysteresis policy.
