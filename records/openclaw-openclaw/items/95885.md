## Summary

Keep open for maintainer review: the current head has no blocking code finding after the active-transcript retry metadata fix, but it intentionally adds persisted session-state metadata and a byte-growth retry policy that owners should accept before merge.

## What This Changes

The PR adds byte-triggered preflight compaction retry metadata to session entries and suppresses repeated byte-triggered compaction for the same active transcript until the file, threshold, or material growth changes.

## Best Possible Solution

Land after maintainers accept the additive SessionEntry retry metadata and the 1 MiB/10% byte-growth hysteresis as the supported byte-compaction retry policy.

## Reproduction Assessment

Yes. At source level, current main recalculates the byte trigger on every preflight with no stored retry state, so an oversized active successor transcript can immediately trigger byte compaction again.

## Solution Assessment

Yes, with a maintainer policy check. Persisting retry state in SessionEntry is the right owner boundary for cross-turn suppression, and the PR preserves token-triggered compaction while reserving the new plugin slot keys.
