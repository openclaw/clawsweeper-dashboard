## Summary

Keep open for maintainer review: the current head appears to fix the repeated byte-triggered preflight compaction loop without a concrete blocking defect, but it intentionally adds persisted session retry metadata and a new byte-growth hysteresis policy that owners should accept before merge.

## What This Changes

The PR adds byte-triggered preflight compaction retry state to `SessionEntry`, suppresses same-file/same-threshold byte retries until material transcript growth, and adds focused session/compaction tests.

## Best Possible Solution

Land after maintainers accept the additive `SessionEntry` retry metadata and the 1 MiB/10% byte-growth hysteresis as the supported byte-compaction retry policy.

## Reproduction Assessment

Yes. Source inspection shows current main recalculates the byte trigger each preflight without stored retry state, so an oversized active successor transcript can immediately trigger byte compaction again.

## Solution Assessment

Yes, with a maintainer policy check. Persisting retry state at the `SessionEntry`/preflight owner boundary is the narrow fix, and token-triggered compaction remains available when byte retry is suppressed.
