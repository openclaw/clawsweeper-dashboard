## Summary

Keep open: the PR is a useful narrow fix for byte-triggered compaction loops, but the current patch can record retry metadata against the original session entry instead of the active follow-up transcript when the compactor omits an unchanged sessionFile, leaving the loop unsuppressed in that edge.

## What This Changes

The PR adds SessionEntry retry metadata and a byte-growth hysteresis guard so byte-triggered preflight compaction is not retried for the same active transcript until material growth, file change, or threshold change.

## Best Possible Solution

Record byte-trigger retry metadata against the same active post-compaction transcript that was compacted, then land once maintainers accept the internal growth-threshold policy.

## Reproduction Assessment

Yes at source level: current main recalculates the byte trigger every preflight with no memory of a prior byte-triggered compaction result. I did not run a live long-session reproduction in this read-only review.

## Solution Assessment

No as currently written: when the active follow-up transcript file differs from the stored entry and compaction does not rotate it, retry state should be keyed to that active file instead of the stale entry fallback.
