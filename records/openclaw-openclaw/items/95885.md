## Summary

Keep open for maintainer review: the previous active-transcript retry-state blocker is fixed, and I did not find a new blocking code defect. The remaining decision is whether maintainers accept the additive persisted session metadata and 1 MiB/10% retry hysteresis policy before merge.

## What This Changes

The PR adds byte-triggered preflight compaction retry metadata to `SessionEntry` and suppresses repeated byte-triggered compaction for the same active transcript until the file, threshold, or material growth changes.

## Best Possible Solution

Land after maintainers accept the additive `SessionEntry` retry metadata and the 1 MiB/10% byte-growth hysteresis as the supported byte-compaction retry policy.

## Reproduction Assessment

Yes. At source level, current main recalculates the byte trigger on every preflight with no stored retry state, so an oversized active successor transcript can immediately trigger byte compaction again.

## Solution Assessment

Yes, with a maintainer policy check. The PR fixes the loop at the right owner boundary by persisting retry state in `SessionEntry`, reserving plugin slot keys, and preserving token-triggered compaction precedence.
