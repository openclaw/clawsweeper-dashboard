## Summary

Keep open for maintainer review: the patch looks correct and the previous active-transcript metadata finding is fixed, but it changes session-state retry policy and persists new SessionEntry metadata, so owners should explicitly accept that behavior before merge.

## What This Changes

The PR persists byte-triggered preflight compaction retry metadata on SessionEntry and suppresses another byte-triggered compaction for the same active transcript until the file, threshold, or material growth changes.

## Best Possible Solution

Land after maintainers accept the additive SessionEntry retry metadata and the 1 MiB/10% byte-growth hysteresis as the supported byte-compaction retry policy.

## Reproduction Assessment

Yes. At source level, current main recalculates the byte trigger on every preflight with no stored retry state, so an oversized active successor transcript can immediately trigger byte compaction again.

## Solution Assessment

Yes, with a maintainer policy check. The PR fixes the loop at the owner boundary by persisting retry state in SessionEntry, reserving plugin slot keys, and preserving token-triggered compaction precedence.
