## Summary

The patch appears correct and no current-head blocking finding remains, but it should stay open for maintainer acceptance because it changes session-state retry policy and adds persisted retry metadata that affects future byte-triggered compaction decisions.

## What This Changes

The PR adds persisted byte-triggered compaction retry metadata to `SessionEntry` and suppresses repeat byte-triggered preflight compaction for the same active transcript until the active file, threshold, or material growth changes.

## Best Possible Solution

Land after maintainers accept the additive session-entry metadata and `max(1 MiB, 10%)` byte-growth hysteresis as the byte-compaction retry policy.

## Reproduction Assessment

Yes. Source inspection of current main shows the byte trigger is recalculated from active transcript bytes with no retry memory, so an oversized successor transcript can immediately retrigger byte compaction.

## Solution Assessment

Yes, subject to maintainer policy acceptance. The patch fixes the loop at the session-entry owner boundary, preserves token-trigger precedence, and avoids adding a new config option.
