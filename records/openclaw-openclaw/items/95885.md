## What This Changes

The PR adds byte-triggered compaction retry metadata to session entries and suppresses repeated byte-triggered preflight compaction for the same active transcript until the file, threshold, or material byte growth changes.

## Best Possible Solution

Land after maintainers accept the additive SessionEntry retry metadata and the 1 MiB/10% byte-growth hysteresis as the intended non-Codex compaction policy.

## Reproduction Assessment

Yes, source-level: current main re-evaluates the byte trigger from active transcript bytes and threshold on every preflight without persisted retry state, so a compaction that leaves the active transcript above threshold can immediately trigger again.

## Solution Assessment

Yes, with maintainer policy acceptance: the PR fixes the non-Codex preflight owner path directly, reserves the new core session fields, and leaves Codex runtime compaction under Codex ownership.
