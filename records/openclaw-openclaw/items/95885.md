## What This Changes

The branch adds byte-triggered compaction retry metadata to `SessionEntry`, suppresses same-file/same-threshold byte retries until material growth, and adds focused regression coverage.

## Best Possible Solution

Merge this only after maintainers accept the session-state hysteresis policy, then rely on the focused tests and normal CI for the exact head.

## Reproduction Assessment

Yes. Current main has no byte-trigger retry state, so a transcript that remains above `maxActiveTranscriptBytes` after byte-triggered compaction can source-reproduce another byte-trigger on the next preflight check; the PR body also includes after-fix runtime output for first trigger, suppressed retry, and token-trigger precedence.

## Solution Assessment

Yes, with maintainer policy acceptance. The patch keeps token-triggered compaction unchanged and stores a small same-file/same-threshold guard near the compaction accounting boundary, which is the narrowest maintainable shape I found for this loop.
