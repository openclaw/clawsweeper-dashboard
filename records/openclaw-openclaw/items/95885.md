## Summary

The PR remains necessary and technically sound; the earlier active-transcript defect is fixed, but merging should wait for a session-state owner to accept the persisted retry contract and the 1 MiB/10% hysteresis policy.

## What This Changes

The PR persists byte-triggered compaction retry metadata on session entries and suppresses another byte-triggered preflight compaction for the same transcript until its file, threshold, or material byte growth changes, while preserving token-triggered compaction.

## Best Possible Solution

Land the existing implementation after a session-state owner explicitly accepts the additive retry metadata and the 1 MiB/10% material-growth rule as the supported byte-compaction retry policy.
