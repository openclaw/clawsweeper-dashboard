## Summary

Keep open for maintainer review: current main still has no byte-compaction retry memory, and this PR appears to fix that loop without blocking token-triggered compaction, but the persisted session-state hysteresis policy needs owner acceptance before merge.

## What This Changes

The PR records byte-triggered preflight compaction retry metadata on `SessionEntry` and suppresses repeated byte-triggered compaction for the same active transcript until the file, threshold, or material growth changes.

## Best Possible Solution

Land after maintainers accept the additive `SessionEntry` retry metadata and the 1 MiB/10% byte-growth hysteresis as the supported byte-compaction retry policy.

## Reproduction Assessment

Yes. At source level, current main recalculates byte-threshold compaction on every preflight from the active transcript size without persisted retry state, so an oversized successor transcript can immediately trigger byte compaction again.

## Solution Assessment

Yes, with a maintainer policy check. The PR fixes the loop at the non-Codex preflight/session-entry boundary, reserves plugin slot keys, preserves token-triggered compaction precedence, and avoids interfering with Codex-native auto-compaction ownership.
