## Summary

Keep open: the PR targets a real byte-triggered compaction loop, but the prior blocker is still present at the current head, so the retry metadata can be recorded against a stale session entry instead of the active transcript file.

## What This Changes

The PR adds persisted `SessionEntry` byte-compaction retry metadata and suppresses repeated byte-triggered preflight compactions until the active file, threshold, or transcript size changes materially.

## Best Possible Solution

Record byte-trigger retry metadata against the active post-compaction transcript file, add the stale-entry unchanged-file regression, then land only after maintainers accept the retry-suppression policy.

## Reproduction Assessment

Yes, at source level: current main recalculates the byte trigger every preflight with no memory of a prior byte-triggered compaction result. I did not run a live long-session reproduction in this read-only review.

## Solution Assessment

No as currently written: the owner boundary is plausible, but the retry state must be keyed to the active post-compaction transcript file instead of falling back to a stale entry when the compactor omits unchanged result fields.
