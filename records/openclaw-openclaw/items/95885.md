## Summary

Keep open for maintainer review: the patch fixes a source-reproducible repeated byte-triggered preflight compaction loop and I found no blocking correctness findings, but it intentionally changes persisted session-state behavior and plugin slot reservations.

## What This Changes

The PR adds persisted byte-triggered compaction retry metadata to `SessionEntry` and suppresses repeated byte-based preflight compaction for the same active transcript until the file, threshold, or material growth changes.

## Best Possible Solution

Land after maintainers accept the byte-compaction retry hysteresis and the additive `SessionEntry` metadata as the supported session-state policy.

## Reproduction Assessment

Yes, at source level. Current main recalculates the byte trigger on every preflight with no stored retry state, so an oversized active successor transcript can immediately trigger byte compaction again.

## Solution Assessment

Yes, with a maintainer policy check. Persisting retry state at the session entry/update boundary is the narrow owner-boundary fix; the remaining decision is whether the 1 MiB/10% hysteresis is the desired retry policy.
