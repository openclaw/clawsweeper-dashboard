## What This Changes

Adds persisted SessionEntry byte-compaction retry metadata and a growth hysteresis guard for repeated byte-triggered preflight compactions.

## Best Possible Solution

Record retry metadata against the actual active post-compaction transcript file, including unchanged active files omitted from the compactor result, then land after maintainer acceptance of the growth-threshold policy.

## Solution Assessment

No as currently written: the owner boundary is right, but retry state must be keyed to the active post-compaction transcript file rather than falling back to a stale entry when the compactor omits unchanged result fields.
