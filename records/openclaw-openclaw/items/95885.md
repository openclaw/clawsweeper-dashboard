## Summary

Keep open for maintainer review: no blocking patch defect remains after the prior active-transcript finding was fixed, but the PR changes durable session-state compaction policy and should get owner sign-off before merge.

## What This Changes

The branch stores byte-triggered preflight compaction retry metadata on `SessionEntry` and suppresses repeat byte-triggered compaction until the active transcript file, threshold, or material growth changes.

## Best Possible Solution

Land this after a maintainer accepts the file/threshold/growth retry policy for byte-triggered compaction; otherwise tune the hysteresis before merge while preserving token-triggered compaction behavior.

## Reproduction Assessment

Yes, source-level. Current main has no byte-trigger retry metadata and will re-evaluate the same oversized active transcript every turn, while the PR proof and tests exercise the real preflight decision path with a recording compactor.

## Solution Assessment

Yes, conditionally. Storing the last byte-triggered compaction state on the session entry is the narrowest existing owner boundary for this behavior, but maintainers still need to accept the exact material-growth policy before merge.
