## Summary

Keep open for maintainer review: the patch is a narrow, source-backed fix for byte-triggered preflight compaction retry loops, and I found no blocking code or security finding. The remaining decision is accepting the internal persisted retry metadata and 1 MiB or 10% growth hysteresis policy before merge.

## What This Changes

The PR adds byte-triggered preflight compaction retry metadata to SessionEntry, suppresses same-file/same-threshold retries until material transcript growth, and adds focused regression coverage.

## Best Possible Solution

Merge after maintainers accept the internal byte-compaction hysteresis policy and stored SessionEntry metadata; tune the constants first if the 1 MiB or 10% retry window is not the intended product behavior.

## Reproduction Assessment

Yes at source level: current main re-evaluates the active transcript byte threshold on every preflight without remembering that a prior byte-triggered compaction already ran for the same transcript. I did not run a live long-session reproduction in this read-only review.

## Solution Assessment

Yes, this is the narrowest maintainable fix I found: it keeps retry policy inside the preflight compaction/session-entry owner boundary and avoids a new public config knob. The only unresolved question is whether maintainers want these exact internal hysteresis constants.
