## Summary

## What This Changes

The branch adds byte-triggered compaction retry metadata to `SessionEntry`, suppresses repeated byte-triggered preflight compactions for the same active transcript until material growth, and adds focused runtime/session tests.

## Best Possible Solution

Land after maintainers accept the additive `SessionEntry` retry metadata and the 1 MiB/10% byte-growth hysteresis as the supported byte-compaction retry policy.

## Reproduction Assessment

Yes. At source level, current main recomputes the byte trigger on every preflight with no persisted retry state, and the PR body includes terminal proof showing first byte-trigger compaction, same-transcript suppression, and token-trigger compaction still running.

## Solution Assessment

Yes, with a maintainer policy check. Persisting retry state on `SessionEntry` is the right owner boundary for behavior that must survive turns, and the latest head records against the active transcript while preserving token-triggered compaction precedence.
