## Summary

Keep open: current main still lacks byte-trigger retry memory, and this PR appears correct with no remaining line-level findings, but it intentionally changes persisted session-state behavior and needs maintainer acceptance before merge.

## What This Changes

The PR adds byte-triggered preflight compaction retry metadata to session entries and suppresses repeated byte-triggered compaction for the same active transcript until the file, threshold, or material growth changes.

## Best Possible Solution

Land after maintainers accept the additive SessionEntry retry metadata and 1 MiB/10% hysteresis as the supported byte-trigger retry policy, with exact-head merge and CI gates green.

## Reproduction Assessment

Yes. Source inspection shows current main recalculates the byte trigger on every preflight with no stored retry state, so an oversized active successor transcript can immediately trigger byte compaction again.

## Solution Assessment

Yes, with a maintainer policy check. The PR fixes the loop at the session-entry owner boundary, reserves plugin slot keys, and preserves token-triggered compaction precedence.
