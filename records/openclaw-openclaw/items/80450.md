## Summary

Keep open: current main has requester-key completion routing and a durable subagent delivery queue, but it still does not expose or persist the explicit final-owner mode requested here, and the linked implementation PR closed unmerged. The remaining work is maintainer API/product direction, not conservative cleanup closure.

## What This Changes

The issue requests a first-class detached-longwork final-summary ownership contract so only one selected surface publishes the full final completion across origin, work, and update threads.

## Best Possible Solution

Keep this as the canonical design issue until maintainers choose the owning substrate, then land a focused change that reuses existing subagent delivery state and proves exactly one selected surface can publish the full final summary.
