## Summary

Keep open: current main has requester-key routing and durable pending-final delivery state, but it still lacks the explicit final-summary owner or durable delivery-obligation contract requested here; the linked implementation PR #80544 closed unmerged and the latest issue comment asks maintainers to choose the owning substrate.

## What This Changes

The issue requests an explicit ownership contract for detached or migrated long-running work so exactly one surface owns the full final summary and durable delivery obligation.

## Best Possible Solution

Have maintainers choose the owner-mode or durable-obligation contract and owning substrate, then land focused PRs that preserve existing same-thread defaults, persist the chosen owner, downgrade non-owner surfaces to pointer/status, document the API, and prove one full final reaches only the selected owner.
