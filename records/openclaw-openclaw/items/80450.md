## Summary

Keep open. Current main has requester/completion session-key routing, but not the explicit final-summary owner modes requested here; the closest implementation PR (#80544) was closed unmerged, so the maintainer product/API decision remains unresolved.

## What This Changes

Request first-class final-delivery ownership for detached or migrated long-running subagent work so exactly one intended surface publishes the complete final summary.

## Best Possible Solution

Keep this as a maintainer design issue, choose the durable final-delivery ownership substrate, then recut smaller PRs with compatibility-preserving defaults and real threaded-channel bridge-back proof.

Kind: product_direction

Question: Which substrate should own durable final-summary delivery for detached or migrated long-running subagent work: native subagent metadata, a broader pending-final/outbox delivery obligation, or a narrower channel-specific route contract?

Rationale: The source gap is real, but the permanent contract affects runtime API shape, session state, hook metadata, and message-delivery guarantees across sibling workflows, so automation should not choose the product boundary.

Likely owner: Jerry-Xin

Owner reason: The current requester/completion session-key split in this area comes from Jerry-Xin's merged #80242 work, making them the strongest code-history owner for deciding whether to extend or replace that contract.

Owner confidence: medium

Options:

- **Use a broader delivery-obligation substrate (recommended):** Define final-summary ownership in the durable pending-final/outbox path and have native subagents, background work, and channel bridges share that contract.
- **Keep it native-subagent scoped:** Add explicit native completion owner modes only for sessions_spawn/subagents and leave ACP/background/channel-specific delivery semantics to separate issues.
- **Defer to channel-specific repairs:** Avoid a generic owner contract for now and repair only the proven Discord or Slack route-loss cases as they are reproduced.
