## Summary

Keep open: current main and v2026.6.11 still have requester-key completion routing and pending-final delivery state, but not the explicit final-summary owner-mode contract this issue requests; the prior implementation PR closed unmerged as too broad, so this remains a maintainer API/product decision rather than cleanup closure.

## What This Changes

The issue requests an explicit ownership contract for detached or migrated long-running work final summaries so only one surface publishes the full completion.

## Best Possible Solution

Choose one durable owner substrate first, then land smaller focused changes that reuse existing subagent delivery/registry or task-ledger state, document the public contract, preserve current defaults unless explicitly changed, and prove exactly one selected owner receives the full final summary.
