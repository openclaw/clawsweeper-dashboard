## Summary

Keep open: current main and v2026.6.11 still only expose internal requester/session-key completion routing, not the explicit final-summary owner-mode or durable delivery-obligation contract requested here, and the linked implementation PR closed unmerged as too broad. The remaining blocker is maintainer product/API direction, not conservative cleanup closure.

## What This Changes

Request an explicit detached-longwork final-delivery ownership contract so exactly one surface owns the complete final summary and related child-session identity is durable across migration.

## Best Possible Solution

Keep this as the canonical design thread, choose the existing delivery/session-state substrate that owns durable final-delivery obligations, then land smaller proof-backed PRs that preserve current default routing while making the single full-final owner explicit.
