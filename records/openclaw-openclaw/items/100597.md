Full review comments:

- **[P2] Preserve task state in caught cron outcomes:** `src/cron/service/timer.ts:1296-1297`
  - body: This catch still handles `executeJobCoreWithTimeout` rejections after `taskRunId` and `activeJobMarker` have already been created. Returning both as `undefined` means `applyOutcomeToStoredJob` cannot finish the detached task row because `tryFinishCronTaskRun` returns when `taskRunId` is missing, so thrown cron runs can leave task ledger entries running instead of terminal. Keep the assigned values outside the try or carry them into the catch result.
  - confidence: 0.88
- **[P2] Gate setup-timeout recovery on finalized outcomes:** `src/cron/service/timer.ts:1396-1397`
  - body: `applyCompletedResult` can return early for a retired active marker, but this branch now only checks whether a recovery handler exists before setting `setupTimeoutNotified`, releasing unclaimed reservations, and notifying. Current main skips that recovery path when no current outcome was finalized, so after restart or generation advance this can run recovery for a stale outcome. Return a finalized-current signal and keep the existing gate.
  - confidence: 0.82
