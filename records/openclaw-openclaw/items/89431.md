## What This Changes

The issue reports that macOS Local CLI TTS using the documented `say` command does not produce audible speaker output when OpenClaw runs as a launchctl daemon/system user.

## Best Possible Solution

A maintainer should choose the supported macOS daemon-to-speaker contract: document a robust wrapper through existing Local CLI config, or add a plugin-owned macOS helper that discovers the active GUI user/session without hard-coded UIDs.
