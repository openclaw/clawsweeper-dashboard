## Summary

Keep open: current main and latest release still run Local CLI TTS by spawning the configured command from the Gateway process, and there is no built-in `launchctl asuser` or equivalent macOS speaker-session bridge. The related merged startup PR is useful context, but it only ensures configured speech-provider plugins start; the remaining issue is the supported macOS daemon-to-speaker contract.

## What This Changes

Request support for macOS Local CLI TTS to produce audible speaker output when OpenClaw is launched through launchctl outside the logged-in GUI audio session.

## Best Possible Solution

Choose and document the supported macOS daemon-to-speaker path, preferably a Local CLI wrapper using existing `command`/`args` unless maintainers sponsor a plugin-owned helper that discovers the active GUI session safely.
