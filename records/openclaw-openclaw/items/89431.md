## Summary

Keep open: current main and the latest release still run Local CLI TTS by spawning the configured command from the Gateway/LaunchAgent process, and the shipped docs still show `say -o` file synthesis without a supported GUI-session speaker bridge. The remaining question is the supported macOS daemon-to-speaker contract, not cleanup closure.

## What This Changes

The issue reports that macOS Local CLI TTS using `say` produces no audible speaker output when OpenClaw runs as a launchd daemon or system-user service.

## Best Possible Solution

Maintainers should choose and document the supported macOS daemon-to-speaker contract: use an existing Local CLI wrapper recipe without a hard-coded UID, or add a plugin-owned macOS helper with live launchd proof.
