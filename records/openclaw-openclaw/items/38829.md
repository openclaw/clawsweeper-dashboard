## Label Justifications

- `P2`: This is a normal-priority TUI live transcript bug with a restart or re-entry workaround and limited blast radius.
- `impact:session-state`: The running TUI view can fall out of sync with the current session transcript until the user reloads it.
- `impact:message-loss`: Messages appended from another surface are not visible in the live TUI even though they can appear later in history.

## Summary

Keep open: current main and the latest release still lack TUI handling for live `session.message` transcript events, and the open closing PR that targets this exact gap has not merged.

## What This Changes

Make the running OpenClaw TUI display new messages appended to the active session from web UI or other channels in real time instead of only after restart or re-entry.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/96252 if it remains the accepted narrow fix; keep broader opt-in cross-channel observer behavior tracked separately in https://github.com/openclaw/openclaw/issues/40678.
