## Summary

Keep open: current main and the latest release still do not route live `session.message` transcript events into the TUI renderer, and the linked implementation candidate has not merged.

## What This Changes

The issue asks for `openclaw tui` to display new messages appended from web UI or other channels in real time without leaving and reopening the session.

## Best Possible Solution

Land a reviewed and proven TUI `session.message` handler that refreshes the active session without disrupting local runs; use https://github.com/openclaw/openclaw/pull/96252 or a narrower replacement as the closing fix path.

## Solution Assessment

Yes, the best current path is the linked implementation candidate or an equivalent narrow TUI-side consumer, because the gateway already exposes the event and the missing behavior is in the TUI event/render path.
