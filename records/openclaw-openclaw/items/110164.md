## Summary

This PR should stay open but needs changes before merge: its bounded read allocates the full configured limit for every payload, so the 64 MiB default can make ordinary credential-add commands fail under memory pressure. The branch also needs after-fix real runtime evidence for the current head. Likely related people: QA Lab ownership could not be resolved from the available read-only evidence (low confidence).

## What This Changes

The PR replaces QA Lab credential payload stat-then-read handling with an opened-handle bounded read and adds tests for boundary-size, growth-race, and FIFO payload paths.

## Best Possible Solution

Read payloads incrementally in bounded chunks (or otherwise size retained buffers to bytes actually read), reject the first byte beyond the cap, preserve FIFO-safe validation, and provide a redacted current-head QA Lab command transcript proving small and oversized payload behavior.

No. The opened-handle overflow check addresses the race, but the one-shot `maxBytes + 1` buffer changes normal memory behavior; a bounded chunked reader is the narrower solution.
