## Label Justifications

- `P1`: A FIFO payload can make a credential-management command hang rather than fail with the documented regular-file error.
- `merge-risk: 🚨 availability`: The proposed file-open order can block the CLI indefinitely on a supported local-path input shape before validation occurs.

## Summary

Keep this PR open for one remaining P1 repair: the new opened-handle check still calls `fs.open()` on the untrusted path before it can reject a FIFO, so a FIFO with no writer can stall the credential command indefinitely. The bounded-read design and its boundary/growth coverage are otherwise directionally sound, and the supplied proof is positive.

## What This Changes

The PR replaces stat-then-read QA Lab credential payload loading with a capped read from an opened file handle and adds boundary-size and growth-race coverage.

## Best Possible Solution

Preserve the bounded opened-handle read, but use a non-blocking file-open/type-validation strategy that rejects FIFOs before waiting for a writer, with a focused regression test for that path.

No. The capped-handle-read approach fixes the size race, but opening before non-blocking type validation retains the previously identified FIFO hang; a non-blocking regular-file validation path is the narrower complete fix.
