## Summary

Keep this PR open, but do not merge the current head: the worker-runtime lazy-loading direction is well supported and the prior durable-provider reload finding appears fixed, while deferred retained-plugin cleanup can still delete the plugin generation loaded by the running Gateway during an install-triggered restart window. The PR also needs a clean rebase before final review.

## What This Changes

Defers retained managed-plugin cleanup and worker-environment runtime loading until after readiness, adds startup import-boundary and benchmark coverage, and changes the TypeScript LOC ratchet to tolerate base-only drift.

## Best Possible Solution

Keep the lazy worker-runtime and benchmark improvements, but run retained-generation cleanup only from a lifecycle point that proves the predecessor is closed or explicitly preserve both the process-loaded and newly indexed plugin generations, with a regression covering install during the idle delay; then rebase and coordinate the LOC repair with the canonical CI PR.
