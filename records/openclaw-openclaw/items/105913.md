## Label Justifications

## Summary

Keep this PR open for repair: the deferred startup work and benchmark evidence are useful, but the unchanged head still has a blocking hot-reload regression that can detach active durable workers from their provider plugin.

## What This Changes

The PR defers retained managed-plugin cleanup until post-readiness, lazily loads worker-environment modules, reuses startup snapshots, and filters non-duration metrics from gateway startup rankings.

## Best Possible Solution

Keep the deferred imports and post-ready cleanup, but fetch a fresh non-terminal durable-worker record snapshot whenever plugin state is rebuilt on hot reload and reserve the startup snapshot for readiness-scoped initialization, with a regression test covering a worker created after startup.
