## Label Justifications

- `P1`: Incorrect Mattermost target precedence can misroute visible replies in an active channel workflow.
- `merge-risk: 🚨 message-delivery`: A valid explicit reply target can be ignored, attaching an outbound post to a different thread root.
- `merge-risk: 🚨 compatibility`: The patch changes the established explicit `replyToId` precedence used by existing Mattermost callers.

## Summary

Keep this PR open, but do not merge it yet: the thread-context direction is useful, while the current send resolver overrides an explicit reply target whenever a valid thread target is also present, which can attach outbound messages to the wrong Mattermost root; the PR also supplies tests only, not after-fix proof from a real Mattermost setup.

## What This Changes

The PR separates Mattermost thread roots from generic reply targets, resolves child posts to their roots for outbound sends, and hydrates inbound thread starter and sender context.

## Best Possible Solution

Preserve explicit `replyToId` precedence, fall back to `threadId`, resolve only the selected candidate to its Mattermost root, cover the differing-valid-ID case at the final create-post boundary, and provide a redacted live thread send/receive transcript or recording.
