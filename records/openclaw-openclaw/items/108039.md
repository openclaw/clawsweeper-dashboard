## What This Changes

Separates Mattermost thread roots from generic reply ids, resolves child posts to root posts for outbound sends, and hydrates inbound thread-starter context.

## Best Possible Solution

Keep `threadId` as the authoritative prepared Mattermost root, resolve only generic `replyToId` values when no root is available, preserve the known root on lookup failure, and verify the complete inbound/outbound flow on a real Mattermost thread.
