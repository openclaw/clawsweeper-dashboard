## Summary

The PR addresses a still-relevant Mattermost bug: current `main` conflates transport thread roots with generic reply IDs and does not provide the requested inbound root context. The owner-plugin direction and regression coverage look coherent, but the external contribution has only mock/test evidence, so it needs real Mattermost behavior proof before merge.

## What This Changes

Separates Mattermost `threadId` from `replyToId`, resolves outbound post IDs to their thread roots, and hydrates inbound thread-starter and reply context.

## Best Possible Solution

Keep thread and reply identifiers distinct in the Mattermost plugin, canonicalize only the value sent as Mattermost `root_id`, preserve graceful context-hydration fallback, and prove threaded, top-level, attachment, and lookup-failure behavior on a real Mattermost instance.
