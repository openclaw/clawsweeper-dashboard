## Summary

Keep open: current main and v2026.6.11 still lack a native `registerMcpServer` Plugin SDK API, and the only direct implementation attempt is closed unmerged. The request remains useful as a plugin API design item, but it needs maintainer product and security approval because it would add a public plugin-managed process-launching surface.

## What This Changes

Request to add `api.registerMcpServer(...)` so plugins can register dynamic managed MCP servers for embedded OpenAI-backed runs.

## Best Possible Solution

A maintainer-sponsored design should either define a narrow, additive, validated stdio-only Plugin SDK MCP registration contract with lifecycle, precedence, workspace, operator-visibility, docs, and tests, or explicitly keep dynamic MCP exposure outside core until that security model is settled.
