## Summary

Keep open: current main and v2026.6.11 still lack a native Plugin SDK `registerMcpServer` API, while existing MCP support is bundle/config-based. The closed related PR is useful history but was not merged, and the linked `kevinslin/openai-apps` plugin is a concrete external motivator for a maintainer product/security decision.

## What This Changes

The issue requests a native Plugin SDK `registerMcpServer` surface so plugins can register managed MCP servers for embedded OpenAI-backed runs.

## Best Possible Solution

A maintainer-sponsored design should either add a narrow, additive, validated Plugin SDK MCP registration contract with an explicit security model, or decide that dynamic MCP exposure should remain outside core until that model is settled.

## Reproduction Assessment

Not applicable: this is a feature request, not a report of broken existing behavior. Source inspection shows current main has bundle/config MCP paths but no native `registerMcpServer` Plugin SDK method.

## Solution Assessment

Unclear until maintainer product and security review. A native Plugin SDK seam may be the right solution if bundle/config MCP cannot express dynamic account-state inventories, but the execution boundary needs explicit approval.
