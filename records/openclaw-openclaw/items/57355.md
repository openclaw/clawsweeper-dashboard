## Summary

Keep open: current main and the latest release still lack a native Plugin SDK `registerMcpServer` API, while the only directly related implementation PR is closed unmerged. The request remains a real Plugin SDK design item, but it needs maintainer product and security review because it would add a public plugin-managed stdio process-launching and tool-exposure surface.

## What This Changes

The issue requests a native Plugin SDK `registerMcpServer` API for plugins to register managed stdio MCP servers and expose dynamic runtime capabilities to embedded OpenAI-backed runs.

## Best Possible Solution

A maintainer-sponsored design should either add a narrow, additive, validated Plugin SDK MCP registration contract for dynamic plugin-owned inventories, or explicitly keep dynamic MCP exposure outside core until the security model is settled.

## Reproduction Assessment

Not applicable; this is a feature/API request, not a report of broken existing behavior. Source inspection shows the requested SDK method is absent from current main and v2026.6.11 while existing MCP support is bundle/config based.

## Solution Assessment

Unclear until maintainer product and security review. A native Plugin SDK seam may be the right solution if existing bundle/config MCP cannot express dynamic account-state inventories, but the execution boundary needs explicit owner approval.
