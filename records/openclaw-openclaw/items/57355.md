## Summary

Keep open: current main and v2026.6.11 still lack a native `registerMcpServer` Plugin SDK API, while the only directly related implementation PR is closed unmerged. The linked `kevinslin/openai-apps` plugin is useful motivation, but this remains a public Plugin SDK and process-launching security boundary decision rather than conservative cleanup.

## What This Changes

The issue requests a native Plugin SDK `registerMcpServer` API so plugins can register managed stdio MCP servers and project dynamic MCP capabilities into embedded OpenAI-backed runs.

## Best Possible Solution

A maintainer-sponsored design should either define a narrow additive SDK contract with validated stdio-only config, explicit security/operator visibility, precedence rules, workspace scoping, docs, and tests, or explicitly keep dynamic MCP registration outside core for now.
