## Summary

Keep open: current main and the latest release still lack a native `registerMcpServer` Plugin SDK lifecycle API, and the only direct implementation PR is closed unmerged. The request remains a valid plugin-API design item with a real external plugin motivation, but it needs maintainer product and security review because it would add a public plugin-managed MCP process-launching surface.

## What This Changes

Request to add a native `registerMcpServer` Plugin SDK API so plugins can register managed MCP servers and project dynamic app/tool inventories into embedded OpenAI-backed runs.

## Best Possible Solution

A maintainer-sponsored design should either define a narrow, additive, validated Plugin SDK MCP registration contract with clear security/precedence rules, or explicitly keep dynamic MCP exposure outside the public SDK until that model is settled.

## Reproduction Assessment

Not applicable; this is a feature/API request, not a report of broken existing behavior. Source inspection shows the requested SDK method is absent on current main and in v2026.6.11 while existing MCP support is bundle/config based.

## Solution Assessment

Unclear until maintainer product and security review. A native Plugin SDK seam may be the right solution if existing bundle/config MCP cannot express dynamic account-state inventories, but the process-launching boundary needs explicit approval.
