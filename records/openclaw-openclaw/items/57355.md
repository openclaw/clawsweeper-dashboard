## Summary

Keep open: current main and the latest release still lack a native `registerMcpServer` Plugin SDK API, while the only direct implementation PR is closed unmerged. The request remains a valid plugin API design item, especially given the external `kevinslin/openai-apps` motivation, but it needs maintainer product and security review because it would add a public plugin-managed process-launching surface.

## What This Changes

The issue requests a native Plugin SDK API for plugins to register managed stdio MCP servers that OpenClaw wires into embedded OpenAI-backed runs.

## Best Possible Solution

A maintainer-sponsored design should define a narrow, additive, validated Plugin SDK MCP registration contract only if bundle/config MCP and direct `registerTool` paths cannot cover the dynamic account-state inventory use case.

## Reproduction Assessment

Not applicable; this is a feature/API request rather than a report of broken existing behavior. Source inspection shows the requested SDK method is absent from current main and the latest release while existing MCP support is bundle/config based.

## Solution Assessment

Unclear until maintainer product and security review. A native Plugin SDK seam may be the maintainable solution for dynamic account-state MCP inventories, but it should not be implemented as an autonomous repair without deciding the public execution contract.
