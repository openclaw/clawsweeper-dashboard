## Summary

Keep open: current main and v2026.6.11 already support per-channel queue mode and per-channel debounce, and the Matrix mode-key gap was handled by https://github.com/openclaw/openclaw/pull/84104, but per-channel queue cap and drop policy are still not implemented.

## What This Changes

The issue requests per-channel overrides for queue debounce, cap, and drop while noting that per-channel mode is already supported.

## Best Possible Solution

Keep the current mode and debounce behavior, then add a backward-compatible canonical per-channel cap/drop shape only after maintainers choose the public config model and require schema, help, docs, and regression coverage.
