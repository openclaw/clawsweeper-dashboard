## Summary

Keep open: current main and the latest release still have the reported visible-session `sessions.usage` path that calls the single-session cache loader per returned session, and the open linked PR is a candidate fix rather than a reason to close before merge.

## What This Changes

The issue reports transient Gateway RSS spikes and false `rss_growth` memory-pressure warnings because dashboard-triggered `sessions.usage` repeatedly reads and parses `.usage-cost-cache.json` for visible sessions.

## Best Possible Solution

Land or replace the linked narrow batched-loader fix with live Gateway or dashboard proof that `sessions.usage` no longer trips false `rss_growth` warnings, while leaving broader usage-cache isolation to https://github.com/openclaw/openclaw/issues/86718.

## Reproduction Assessment

Yes, at source level: current main still builds one visible-session cache-summary task per returned visible session, and each task reads/parses the durable usage-cost cache. I did not rerun the live RSS replay, but the reporter supplied v2026.6.11 limit=50 versus limit=1 measurements that match this path.

## Solution Assessment

Yes for the narrow repair: reusing the existing batched cache loader per agent is the smallest maintainable fix for the repeated cache parsing. Raising diagnostics thresholds, changing reconnect policy, or solving the broader usage-cache isolation problem should stay separate.
