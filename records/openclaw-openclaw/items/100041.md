## Summary

Keep open: current main still loads visible `sessions.usage` rows through the single-session cache loader, which reads/parses the durable usage-cost cache per visible session, and https://github.com/openclaw/openclaw/pull/100054 is an open closing PR rather than a merged fix.

## What This Changes

Reports a Gateway/Control UI memory-pressure bug where `sessions.usage` repeatedly parses `.usage-cost-cache.json` during dashboard connect/reconnect, causing transient RSS spikes and false `rss_growth` warnings.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/100054 if it proves the dashboard/RPC RSS spike is gone; keep broader gateway isolation and threshold-policy work separate.

## Reproduction Assessment

Yes at source level, though I did not run a live RSS replay. Current main creates one visible-session cache-summary task per limited entry and each task reads/parses the durable cache; the reporter supplied v2026.6.11 limit=50 versus limit=1 RSS controls.

## Solution Assessment

Yes for the narrow repair: reusing the existing batched cache loader per agent, or an equivalent request-scoped cache snapshot, is the smallest maintainable fix. The issue should stay open until the linked PR lands with proof or maintainers choose a replacement path.
