- `impact:ux-friction`: False memory-pressure warnings advise operators to restart the gateway even though the reported spike is transient and self-recovers.
- `maturity:stable`: The issue affects Gateway runtime M4 Stable behavior, specifically the Stable Gateway RPC APIs and Events category covering usage and memory APIs.

## Summary

Keep open: current main and v2026.6.11 still use the per-visible-session `loadSessionCostSummaryFromCache` path for `sessions.usage`, and an open linked PR is already the candidate fix. The source path supports the reported transient RSS false-alarm behavior, but the fix has not merged, so this issue remains necessary.

## What This Changes

The issue reports transient RSS spikes from `sessions.usage` repeatedly reading/parsing the usage-cost cache during dashboard connect or reconnect.

## Best Possible Solution

Land or replace the linked narrow gateway repair so `sessions.usage` reuses the existing batched cache-summary loader for visible sessions, with regression coverage and live gateway/RSS proof that dashboard usage refresh no longer trips false `rss_growth` warnings.

## Reproduction Assessment

Yes from source inspection: current main still builds one visible-session cache-summary task per visible session, and each task calls the single-session loader that reads the usage-cost cache. I did not run a live RSS replay in this read-only review.

## Solution Assessment

Yes, the narrowest maintainable fix is to reuse the existing batched cache-summary loader for visible sessions. Raising diagnostics thresholds or changing dashboard reconnect behavior would mask or broaden the first repair instead of reducing the request-path allocation.
