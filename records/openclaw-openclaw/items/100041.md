## What This Changes

The issue reports transient gateway RSS spikes and false memory-pressure warnings when dashboard sessions.usage refreshes repeatedly parse the usage-cost cache.

## Best Possible Solution

Review and land a narrow fix such as https://github.com/openclaw/openclaw/pull/100054 that batches visible sessions.usage cache reads per agent while preserving current response semantics and regression coverage.

## Reproduction Assessment

Yes. Source inspection shows that sessions.usage with multiple visible sessions creates one cache-summary load task per limited entry, and each task invokes a single-session loader that reads and parses the usage-cost cache.

## Solution Assessment

Yes for the narrow repair. The best fix is to reuse the existing batched cache-summary loader or an equivalent request-scoped cache snapshot, rather than adding a diagnostics-threshold config knob or masking the warning.
