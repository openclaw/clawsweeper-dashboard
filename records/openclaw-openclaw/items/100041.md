## Summary

Keep open: current main still fans out `sessions.usage` cache loading per limited session, while the Control UI usage path requests session usage on dashboard refresh and the latest release shows the same shipped pattern. The report has concrete logs plus source-backed root cause evidence, so this is a narrow gateway usage performance bug rather than stale cleanup.

## What This Changes

The issue reports transient RSS spikes and false memory-pressure warnings when dashboard `sessions.usage` requests repeatedly parse the usage-cost cache and refresh stale transcript summaries.

## Best Possible Solution

Fix the gateway usage path so `sessions.usage` batches cache reads and stale-refresh requests per agent while retaining only summary data needed for the response; leave threshold config or reconnect debounce as separate follow-ups if still observed.

## Reproduction Assessment

Yes, source and reporter evidence give a high-confidence reproduction path: call `sessions.usage` with a non-trivial usage-cost cache and compare high versus low limits while sampling RSS. I did not run the live RSS sampling in this read-only pass.

## Solution Assessment

Yes for the central bug: reducing repeated cache parses and coalescing stale refresh work in the gateway usage path is the narrow maintainable fix. Exposing memory thresholds or debouncing UI reconnects would mask or broaden the issue and should not be the first repair.
