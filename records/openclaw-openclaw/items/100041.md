## Summary

Keep open: current main and latest release still route visible `sessions.usage` rows through one cache-summary load per included visible session, and that helper reads/parses the durable usage-cost cache on each call. The linked open PR is the right implementation candidate, but the issue should not close until that PR merges or is replaced.

## What This Changes

The issue asks OpenClaw to reduce `sessions.usage` transient memory pressure by batching or memoizing usage-cost cache reads during dashboard connect/reconnect usage loads.

## Best Possible Solution

Review and land or reject https://github.com/openclaw/openclaw/pull/100054; the preferred fix is to batch visible and hidden `sessions.usage` summaries per agent through the existing batched loader while leaving diagnostics-threshold and reconnect-policy changes separate.

## Reproduction Assessment

Yes at source level, though I did not run a live RSS replay. Current main still creates one cache-summary task per visible session and each helper reads/parses the durable cache; the reporter supplied v2026.6.11 `limit=50` versus `limit=1` RSS controls.

## Solution Assessment

Yes for the narrow fix direction. Reusing the existing batched per-agent helper is more maintainable than masking the alarm with new thresholds or adding a parallel memoization system, but the linked PR must merge before this issue is closed.
