## Summary

Keep open: current main and the latest release still have the source-level `sessions.usage` cache reparse path, and https://github.com/openclaw/openclaw/pull/100054 is an open linked candidate fix. This issue should stay open until that PR lands or maintainers choose a different narrow repair.

## What This Changes

The issue reports transient gateway RSS spikes and false memory-pressure warnings when dashboard `sessions.usage` refreshes re-read the usage-cost cache once per visible session.

## Best Possible Solution

Land the linked narrow repair, or an equivalent fix, that batches visible `sessions.usage` cache-summary reads per agent while leaving diagnostic-threshold and reconnect-policy changes to separate decisions.

## Reproduction Assessment

Yes, source-reproducible: current main still calls the single-session cache loader once per visible/included `sessions.usage` row, and that loader reads/parses the cache each time. I did not run the live RSS sampling experiment, so this is source proof rather than a measured reproduction.

## Solution Assessment

Yes, the best repair appears to be reusing the existing batched cache-summary loader for the visible-row path, because the hidden-row path already has the desired read-once-per-agent behavior.
