## Summary

Keep open: current main and the latest release still route visible `sessions.usage` rows through one cache-summary load per visible session, and an open linked PR is the candidate fix rather than merged implementation.

## What This Changes

The issue asks OpenClaw to stop routine dashboard `sessions.usage` calls from repeatedly parsing the usage-cost cache and causing transient memory-pressure false alarms.

## Best Possible Solution

Land or replace the linked PR with a focused fix that batches visible `sessions.usage` cache reads per agent, while keeping diagnostic-threshold and reconnect-policy changes separate.

## Reproduction Assessment

Yes at source level, though I did not run a live RSS replay. Current main still builds one visible-session cache-summary task per visible session, and each task reads/parses the durable cache; the reporter supplied release measurements comparing `limit=50` with `limit=1`.

## Solution Assessment

Yes for the narrow repair: reusing the existing batched per-agent cache loader is the smallest maintainable fix. The issue should not close until the linked PR lands or maintainers choose an equivalent replacement.
