## Summary

Keep open: current main and the latest release still route fixed workspace bootstrap files through a workspace-root `openRootFile` boundary, so symlink targets outside the workspace still collapse to `[MISSING]`. The remaining fix is a security/product boundary decision, and the open broader symlink PR explicitly does not fully settle this narrower `~/.openclaw` sibling-root policy.

## What This Changes

Allow workspace bootstrap symlinks to selected `~/.openclaw` sibling directories to load instead of being rendered as missing.

## Best Possible Solution

Keep this issue open until maintainers choose and land an explicit fixed-bootstrap symlink policy in the active fs-safe/OpenClaw reader path, with tests for allowed shared files and blocked private OpenClaw state roots.
