## Summary

Keep open: current main and the latest release still route fixed workspace bootstrap reads through a workspace-root fs-safe boundary, and rejected reads become missing bootstrap files. The remaining work is a deliberate security/product policy decision about whether selected out-of-workspace symlink targets may become startup prompt authority.

## What This Changes

The issue requests support for workspace bootstrap symlinks whose targets live under the broader OpenClaw state tree rather than inside the workspace root.

## Best Possible Solution

Land a maintainer-approved, narrow external-bootstrap symlink policy in the active openRootFile/fs-safe reader path, with tests for allowed shared files and rejected private OpenClaw state roots.
