## Summary

Keep open: current main and the latest release still route fixed workspace bootstrap files through a workspace-root fs-safe read, so a symlink target in a sibling `~/.openclaw` directory is still rejected and rendered as missing. A maintainer explicitly kept this issue open because the next fix needs an active fs-safe/OpenClaw wrapper policy plus security tests, and the open broader symlink PR only partially overlaps this `.openclaw` trust-policy question.

## What This Changes

The issue requests support for workspace bootstrap files symlinked from the workspace into sibling directories under `~/.openclaw` without showing those files as missing.

## Best Possible Solution

Define and land a maintainer-approved bootstrap-only symlink policy in the active `openRootFile`/fs-safe reader path, with regression tests for allowed shared knowledge-base files and rejected private OpenClaw state roots; if maintainers keep the strict boundary, surface a clear blocked-file diagnostic instead of `[MISSING]`.
