## Summary

Keep open: current main still routes fixed workspace bootstrap files through a workspace-root fs-safe boundary, and a maintainer explicitly kept this security-sensitive policy issue open after closing the old resolver PR as obsolete.

## What This Changes

The issue requests allowing workspace bootstrap-file symlinks to resolve to selected `~/.openclaw` sibling directories instead of rendering those files as missing.

## Best Possible Solution

Define a maintainer-approved policy in the active fs-safe/OpenClaw bootstrap reader path that allows only intended external bootstrap targets, rejects arbitrary OpenClaw state roots, and includes regression tests for both allowed symlink-hop reads and denied direct or sensitive paths.
