## Summary

Keep open: current main and the latest release still route fixed workspace bootstrap reads through a workspace-root fs-safe boundary and render rejected reads as missing. The requested exception remains a security/product decision, and the overlapping open symlink PR is not a merged or canonical fix for this specific trust-boundary issue.

## What This Changes

Allow workspace bootstrap files that are symlinks into sibling `~/.openclaw` subdirectories to load instead of being rendered as `[MISSING]`.

## Best Possible Solution

Choose an explicit bootstrap-only trust policy at the active fs-safe/OpenClaw wrapper boundary, then add regression coverage for allowed symlink hops, rejected direct `~/.openclaw` reads, and visible diagnostics when bootstrap files are skipped.
