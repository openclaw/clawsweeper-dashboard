## What This Changes

Fix Telegram sent-message cache persistence so recording one outbound message writes only that new cache entry instead of re-registering every cached entry.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/98775, or replace it with an equivalent narrow cache fix that writes only the newly recorded row while preserving the current namespace, TTL, and cap behavior.

## Reproduction Assessment

Yes from source: on current main, every `recordSentMessage` call reaches `persistSentMessages`, which loops over all cached messages and registers each one with the sync plugin-state store. I did not run a load repro because this read-only review already establishes the write-amplification path.

## Solution Assessment

Yes, the best fix is to persist only the newly recorded sent-message row because plugin-state already supplies per-entry TTL and namespace cap enforcement. The linked PR appears to target that boundary, so the issue should stay open for that PR review path.
