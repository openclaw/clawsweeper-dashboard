## Summary

Keep open. Current diagnostics expose warning and abort thresholds, while the requested automatic steer → nudge → abort policy remains a new core recovery feature; the related read-only diagnosis work is a useful prerequisite but does not provide recovery actions. A maintainer should choose the safety and product contract before implementation.

## What This Changes

Add a configurable diagnostics recovery ladder for stalled embedded sessions that steers first, then nudges, and aborts only after guarded rechecks.

## System Context

Gateway diagnostics observes session and embedded-run progress, classifies potentially stalled work, and currently applies conservative recovery such as aborting an embedded run or releasing a lane. The requested policy would add active session-control actions between observation and the existing abort path, affecting session continuity and possible channel-facing replies.

## Architecture Diagram

flowchart LR
  A[Session and embedded-run activity] --> B[Gateway diagnostics]
  B --> C[Stall classification and liveness checks]
  C --> D[Recovery policy]
  D --> E[Steer or nudge active session]
  D --> F[Abort run or release lane]
  E --> G[Session progress and user-visible reply]
  F --> G

## Best Possible Solution

Define a core-owned recovery policy that requires fresh Gateway liveness and read-only session diagnosis before escalation, uses existing session-control primitives with idempotent action state, preserves abort as the final fallback, and documents a single safe default rather than adding an unbounded set of timing knobs.

Rationale: This is a new automated recovery policy and configuration surface. The correct default, escalation timing, and whether diagnostic recovery may generate session-visible messages cannot be resolved safely from code alone.

Likely owner: openperf

Owner confidence: medium

Options:

- **Approve a guarded core ladder (recommended):** Define a small core policy with mandatory Gateway-liveness and diagnosis gates, persisted/idempotent escalation state, and abort retained as the final fallback.
- **Keep diagnostics observational:** Retain warning, diagnosis, and explicit operator actions while leaving automated recovery orchestration to deployments or plugins.
- **Defer until diagnosis lands:** Treat read-only diagnosis as the prerequisite and revisit active recovery after operators can reliably distinguish active, stale, and unsafe-to-act-on sessions.
