## Summary

Keep open: current main provides configurable abort-drain recovery and explicit operator `sessions.steer`, `sessions.send`, and `sessions.abort` controls, but not the requested automatic steer → nudge → abort policy. The remaining work is a compatibility- and safety-sensitive core product decision, especially because a recent related bug showed recovery can act on unreliable liveness telemetry.

## What This Changes

The issue requests a configurable automatic stuck-session recovery ladder that steers, then nudges, then aborts stalled embedded runs.

## Best Possible Solution

First land or adopt a bounded read-only diagnosis surface, then sponsor one owner-defined internal recovery policy with liveness gating, typed recovery events, strict per-session idempotency, and explicit channel-delivery semantics before adding any configuration knob.

## Risks / Open Questions

- Automatically steering or sending a nudge can mutate an active session and create user-visible channel output before the current abort threshold; the delivery, deduplication, and retry contract is not defined.

- Adding `diagnostics.stuckSessionRecovery` creates a new compatibility-sensitive configuration/default surface and requires a clear upgrade, operator-control, and observability contract.
