## Summary

The patch is technically sound, but current main already bounds SSH output through the shared 100 MiB sandbox limit; the remaining question is whether SSH should intentionally diverge to a 16 MiB per-stream contract. Likely related people: steipete and cxbAsDev have high-confidence history on the core SSH path and its recent process-output handling, with vincentkoc also connected through adjacent SSH maintenance.

## What This Changes

Replaces the shared 100 MiB sandbox command buffer limit for SSH commands with a private 16 MiB per-stream limit and adds focused tests for the smaller cap and error propagation.

## Best Possible Solution

Keep one shared sandbox output policy unless maintainers explicitly require a lower SSH ceiling; if SSH must differ, define whether the budget is per stream or combined, align the PR body and error contract, and cover simultaneous stdout/stderr output in tests and real proof.
