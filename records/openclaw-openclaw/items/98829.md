## Summary

Keep open for maintainer review: the patch is a focused availability fix with sufficient real behavior proof, but it intentionally changes large SSH/OpenShell helper output from successful buffering to byte-limit failure, so maintainers need to accept the output contract before merge.

## What This Changes

The PR adds a default 16 MiB combined stdout/stderr cap with an optional `maxOutputBytes` override to `runSshSandboxCommand`, plus focused Vitest coverage.

## Best Possible Solution

Land this chokepoint cap after maintainers accept the default fail-closed SSH/OpenShell output contract, or revise oversized handling to an approved truncate/stream policy before merge.

## Solution Assessment

Mostly yes. `runSshSandboxCommand` is the right chokepoint because core SSH and OpenShell helper commands route through it, but the exact fail-closed 16 MiB policy and SDK override should be maintainer-confirmed.
