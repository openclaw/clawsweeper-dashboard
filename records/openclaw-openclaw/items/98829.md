## Summary

## What This Changes

The PR adds a 16 MiB combined stdout/stderr cap to `runSshSandboxCommand` plus mocked Vitest coverage for normal, over-cap, partial-output, and post-cap behavior.

## Best Possible Solution

Land a CI-clean SSH output bound after maintainers approve the oversized-output policy, or revise the failure mode to an approved truncation/streaming behavior if outputs over 16 MiB must remain supported.

## Reproduction Assessment

## Solution Assessment

Is this the best way to solve the issue? Partly: `runSshSandboxCommand` is the right chokepoint for backend-managed SSH commands, but the merge-ready solution needs real SSH/OpenShell proof and an explicit maintainer decision on the hard 16 MiB fail-closed behavior.
