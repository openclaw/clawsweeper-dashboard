## Summary

Keep open: the patch now looks code-review clean and the real behavior proof is sufficient, but the hard 16 MiB fail-closed SSH output cap remains a compatibility contract that needs maintainer acceptance before merge.

## What This Changes

The PR adds a private 16 MiB combined stdout/stderr cap to SSH sandbox command buffering and adds focused tests for cap, kill, and partial-output behavior.

## Best Possible Solution

Land this bounded SSH helper guard if maintainers accept 16 MiB as the SSH backend output contract; otherwise revise the oversized-output behavior to truncate, stream, or expose a maintainer-approved policy before merge.

## Reproduction Assessment

Yes, source-level: current main buffers every SSH stdout/stderr chunk in arrays until process close, so a large-output remote command can grow gateway memory. I did not run a live SSH server repro in this read-only review.

## Solution Assessment

Partly: `runSshSandboxCommand` is the right chokepoint for this SSH backend memory-growth bug, and the implementation is focused. The remaining question is whether maintainers want the hard fail-closed cap as the permanent backend contract instead of truncation or streaming.
