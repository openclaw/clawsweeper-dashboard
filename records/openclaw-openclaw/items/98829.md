## Summary

Keep open: current main and the latest release still buffer SSH command stdout/stderr without a bound, and this PR is a focused availability fix with refreshed terminal proof and no blocking code findings. The remaining blocker is maintainer acceptance of the new hard 16 MiB fail-closed output contract because it can make existing oversized SSH/OpenShell commands fail instead of returning buffered output.

## What This Changes

The PR adds a private 16 MiB combined stdout/stderr cap to `runSshSandboxCommand` and new Vitest coverage for over-cap termination and partial output handling.

## Best Possible Solution

Land the bounded-output SSH helper once maintainers explicitly accept the 16 MiB fail-closed SSH/OpenShell output contract and the remaining CI stays green.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes from source inspection and the PR's negative-control proof: current main buffers every SSH stdout/stderr chunk until close, while the proof script shows a 20 MiB child output completing unbounded before the patch.

## Solution Assessment

Is this the best way to solve the issue? Yes as an availability mitigation at the SSH helper chokepoint, provided maintainers accept fail-closed behavior; if large outputs are a supported workflow, truncation or streaming would be the safer product direction.
