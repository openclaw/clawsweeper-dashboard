## Summary

Keep open: the patch is a focused availability hardening for unbounded SSH helper buffering with sufficient proof, but the hard 16 MiB fail-closed cap changes the SSH backend output contract and still needs maintainer acceptance before merge.

## What This Changes

Adds a 16 MiB combined stdout/stderr cap to `runSshSandboxCommand` and tests under-cap, over-cap, kill, and partial-output behavior.

## Best Possible Solution

Land this bounded SSH helper guard if maintainers accept 16 MiB as the SSH backend output contract; otherwise revise oversized-output behavior to truncate, stream, or expose an approved policy before merge.

## Reproduction Assessment

Yes, source-level: current main buffers every SSH stdout/stderr chunk in arrays until close, so a large-output remote command can grow gateway memory. The PR body also supplies real child-process proof and a negative control, but I did not run a live SSH server in this read-only review.

## Solution Assessment

Partly: `runSshSandboxCommand` is the right chokepoint and the implementation is focused. The remaining best-fix question is whether maintainers want hard rejection as the SSH contract instead of truncation or streaming.
