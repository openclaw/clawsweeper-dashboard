## Summary

## What This Changes

The PR changes provider failover classification so code-only OpenAI, Google-family, and Anthropic errors are handled by provider plugin hooks while core avoids reporting structured code signals as `empty_response`.

## Best Possible Solution

Land the provider-hook implementation after maintainer confirmation of the vendor code-to-reason semantics, keeping provider-native policy in plugins and generic code policy in core.

## Reproduction Assessment

Yes. Current main is source-reproducible: a structured provider failure with `code` but no message or numeric status returns `empty_response` before failover classification.

## Solution Assessment

Yes. The existing `classifyFailoverReason` provider hook is the narrowest maintainable seam; moving provider-native code tables into core would duplicate plugin-owned policy and drift from provider ownership.
