## Summary

This PR is still necessary and looks like the right owner-boundary fix: current main still short-circuits message-less structured provider failures as `empty_response`, while the PR lets structured code/errorType signals reach failover and keeps vendor-specific code policy in provider hooks.

## What This Changes

The PR keeps core failover code classification generic, skips the empty-response short-circuit for structured code/errorType signals, and maps OpenAI, Google-family, and Anthropic code-only provider errors in provider hooks with focused tests.

## Best Possible Solution

Land the provider-hook implementation after maintainer current-base review, keeping vendor-specific code policy in provider plugins and generic code policy in core.

## Reproduction Assessment

Yes. Current-main source shows message-less structured provider failures return `empty_response` before failover classification, and the PR discussion includes before/after production-function and regression-test proof.

## Solution Assessment

Yes. The existing provider hook seam is the narrowest maintainable fix; putting provider-native code tables in core would duplicate plugin-owned policy and risk drift.
