## Summary

Keep open: current main has meaningful partial session-name support through gateway labels, Control UI rename, CLI JSON rows, and the shared `/name` command, but the central CLI-friendly request is not complete because the text `openclaw sessions` listing still omits a friendly-name column and there is no first-class `openclaw sessions label` or rename command. The broader label-versus-title contract is also still being resolved in open related PRs, so this should stay as the canonical maintainer-tracked issue rather than spawning another autonomous fix.

## What This Changes

Add user-editable session labels or nicknames so sessions can be identified in the CLI, API, and related session UIs.

## Best Possible Solution

Settle the canonical session name contract first, then expose one consistent name through gateway create/list/patch/resolve, Control UI, chat commands, CLI JSON/text output, and a first-class CLI rename command.
