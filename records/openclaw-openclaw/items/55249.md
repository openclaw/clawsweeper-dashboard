## Summary

Keep open: current main now supports persisted session labels through Gateway APIs and `/name`, but the original request is still only partially implemented because the text `openclaw sessions` listing lacks a label/name column or label-preferred display, there is no CLI label subcommand, and open related PRs are still deciding the canonical `label` versus `title` contract.

## What This Changes

Request human-readable session labels or nicknames that can be set on sessions and shown in CLI, JSON, TUI/WebChat, and programmatic session surfaces.

## Best Possible Solution

Settle one canonical user-editable session naming contract, then finish the remaining CLI text/list subcommand and Control UI command surfaces around that contract without adding parallel writable name fields.
