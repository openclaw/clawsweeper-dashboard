## Summary

Keep open: current main has backend label storage, CLI JSON label projection, Control UI label editing, and the merged `/name` chat command, but it still lacks the requested first-class `openclaw sessions label` command and friendly label in the text `openclaw sessions` table. The remaining work overlaps with active title/label contract PRs, so this needs maintainer direction before a new repair lane.

## What This Changes

Request to let users assign persistent human-readable labels or nicknames to sessions and show them in session listings, CLI output, JSON, and related chat/programmatic flows.

## Best Possible Solution

Settle one canonical session naming contract, then complete one coherent surface across Gateway, Control UI/chat commands, and `openclaw sessions` text/JSON output without adding a competing name field.

Owner confidence: medium

Options:

- **Keep the existing label contract (recommended):** Use `label` as the durable field, keep `/name` as the primary chat command, and implement `/label` or CLI `sessions label` only as aliases that call the same Gateway patch path.

- **Narrow to Control UI only:** Land only the Control UI `/new <name>` and `/label` work and leave the broader CLI command/listing request open or explicitly out of scope.
