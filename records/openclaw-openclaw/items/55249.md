## What This Changes

Request to add persistent human-readable labels or nicknames for sessions and surface them in CLI, chat, UI, JSON, and programmatic session flows.

## Best Possible Solution

Settle the canonical session naming contract first, then expose one consistent name/title field through Gateway, Control UI, chat commands, and `openclaw sessions` text/JSON plus a CLI set/clear flow without adding competing semantics.

## Reproduction Assessment

Yes, source inspection gives a high-confidence path: current main lacks a `sessions label` CLI subcommand and the text table still displays the internal Key column without a friendly name column. Unclear as proposed: the requested direction is valid, but the best implementation depends on maintainer acceptance of `label` versus canonical `title` and how `/name`, `/label`, and named `/new` should coexist. A new fix PR should wait until that contract is settled or an existing PR lands.
