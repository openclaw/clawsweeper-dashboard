## Summary

Keep open: current main has useful session-label plumbing and the merged `/name` command, but the original cross-surface request is not complete because the CLI still lacks a label-setting command and friendly label/title table output, and the permanent `label` versus `title` contract is still under active review.

## What This Changes

Add persistent human-readable session labels or nicknames across CLI listings, programmatic session APIs, spawned/agent sessions, and optional auto-labeling.

## Best Possible Solution

Choose one canonical session naming contract, then land a focused implementation that covers CLI setting/listing, Gateway create/patch/list/resolve semantics, chat/UI display, and compatibility for existing `label` consumers.

## Reproduction Assessment

Yes. Source inspection shows `sessions.patch`, `sessions.create`, and `/name` can use `label`, but `openclaw sessions` still renders the raw Key column without a Label/Title column and there is no `openclaw sessions label` command documented or registered.

## Solution Assessment

No current implementation is complete. The best path is to settle the canonical `label`/`title` and `/name`/`/label` contract first, then implement the CLI and programmatic/listing gaps against that single contract.
