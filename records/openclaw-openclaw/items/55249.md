## Summary

Keep open: current main has partial session naming support, including persisted `label`, `/name <title>`, Control UI label editing, and label in CLI JSON rows, but it still lacks the requested friendly-name CLI text listing and first-class `openclaw sessions label` command; the remaining work is tied to the active label-versus-title product contract discussion.

## What This Changes

Add persistent human-readable labels or nicknames for sessions so users can set them and identify sessions across CLI, API, chat, and UI listings.

## Best Possible Solution

Settle the canonical `title` versus `label` contract, then expose one consistent session name through Gateway, Control UI, chat commands, and `openclaw sessions` text/JSON output, including a CLI set/clear flow if maintainers want that surface.

## Reproduction Assessment

Yes. Source inspection on current main shows labels are persisted and exposed in JSON/UI/chat paths, while the CLI text table still omits a friendly-name column and no `openclaw sessions label` subcommand is registered.

## Solution Assessment

No, current main is only a partial solution. The best path is a unified naming contract before adding or renaming CLI and chat surfaces.
