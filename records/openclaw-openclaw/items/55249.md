## Summary

Keep open: current main has substantial session-label plumbing, including label storage, Gateway APIs, Control UI label display/editing, CLI JSON label projection, and the merged `/name` command, but the requested CLI label command and friendly-name text listing are still incomplete and the canonical `label` versus `title` contract is under active review.

## What This Changes

The issue requests persistent human-readable session labels or nicknames that can be set for sessions and shown in session listings across CLI, API, and UI surfaces.

## Best Possible Solution

Settle the canonical session name field first, then expose it consistently in `openclaw sessions` text output and one CLI/chat naming command path without creating competing `label`, `title`, and `displayName` semantics.

Yes. Source inspection shows current main has label storage, Gateway API support, CLI JSON label projection, Control UI label editing, and `/name`, while the CLI text listing still omits a label/name column and the sessions CLI has no `label` subcommand.
