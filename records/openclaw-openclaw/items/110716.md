## Summary

Keep this PR open, but do not merge it as written: the added `stat()` check is only a snapshot and the subsequent unbounded `handle.readFile()` can still consume a file that grows after the check. The existing fs-safe root API already provides the pinned, size-bounded read contract this bridge needs. ([raw.githubusercontent.com](https://raw.githubusercontent.com/openclaw/openclaw/main/extensions/openshell/src/fs-bridge.ts))

## What This Changes

The PR adds a 100 MiB pre-read size check and a regular-file check to OpenShell sandbox file reads.

## Best Possible Solution

Read through the existing fs-safe root API with an explicit `maxBytes` value, retain the established pinned-read guarantees, add boundary regression coverage, and attach redacted after-fix runtime output showing a normal read succeeds while an oversized read is rejected.
