## Summary

Keep open. The prior P1 remains: the branch checks a file's size before calling an unbounded `FileHandle.readFile()`, so it does not actually enforce the claimed memory cap if the file grows after the check. It also needs real after-fix runtime proof before merge.

## What This Changes

Adds a 100 MiB pre-read size check and regular-file check to OpenShell sandbox file reads.

## Best Possible Solution

Read through the existing `fsRoot(...).read(relativePath, { hardlinks: "reject", maxBytes })` capability, retain the chosen explicit cap, and add focused normal-read, oversized-read, and growth-during-read coverage plus redacted live proof.
