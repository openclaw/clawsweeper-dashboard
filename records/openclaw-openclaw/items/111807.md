## Summary

This remains an actionable Claude CLI provider-contract bug: the documented `/think off` outcome cannot be inferred from omitting `--effort`, because Claude Code then applies its own effort default. The reported `adaptive` mismatch also needs confirmation against the current resolver, but the durable fix requires a maintainer decision on the honest Claude CLI semantics when upstream cannot express a true off state.

## What This Changes

Report that `claude-cli` maps `/think off` to no Claude Code `--effort` override, so the host default effort remains active despite the displayed OpenClaw level being `off`.

## Best Possible Solution

Define one honest Claude CLI profile: either expose only provider states whose effects Claude Code can enforce, or retain `off` only if OpenClaw can prove an upstream disable mechanism; then align the resolver, profile default, `/think` response, docs, and focused argv tests.
