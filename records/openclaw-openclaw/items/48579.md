## Summary

Keep open: current main still treats pruning and compaction as separate systems, `contextPruning.mode: "off"` only disables pruning, and `compaction.mode` still has no `off` or hard-limit-only mode. The older off-mode PR closed unmerged, and the remaining low-context compaction behavior overlaps broader active compaction-recovery work rather than being fixed on main.

## What This Changes

The issue requests clarification and a way to prevent low-context auto-compactions when pruning is disabled for large-context Anthropic sessions.

## Best Possible Solution

Define a maintainer-approved compaction policy that clearly separates pruning from compaction and, if desired, adds a documented hard-limit/off mode with upgrade-safe schema, docs, and regression coverage.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Partly: source shows `contextPruning.mode: "off"` cannot disable compaction and current `compaction.mode` lacks an off value, but the reported Anthropic live frequency was not reproduced here.

## Solution Assessment

Is this the best way to solve the issue? Not as a cleanup close; the best path is a maintainer-owned compaction policy/config change rather than treating pruning off as already disabling compaction.
