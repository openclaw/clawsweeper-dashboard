## Summary

Keep this open for a narrow ownership decision. Current main already shares MCP server construction, stdio transport, log routing, shutdown handling, and error normalization; the remaining adapter-specific startup prefixes are not established as a cross-pipeline diagnostics contract, so extracting another formatter is not yet clearly the best refactor.

## What This Changes

Consolidate startup diagnostic formatting used by the OpenClaw tools and Codex supervision MCP service adapters into a shared module.

## Best Possible Solution

Keep transport and error normalization in the existing shared MCP helper; extract a startup-diagnostic helper only if maintainers define stable fields and add focused tests proving both adapters need the same structure while preserving their identities.
