## Summary

Keep this open for a narrow product-boundary decision. Current main already centralizes MCP stdio transport, while the remaining service-specific prefixes and fatal-error callbacks preserve owner identity; the report does not establish that byte-identical diagnostics are a required contract, and its proposed core helper would cross the current core/plugin boundary.

## What This Changes

Consolidate the OpenClaw Tools and Codex Supervisor MCP diagnostic formatting into one shared formatter.

## Best Possible Solution

Keep the generic stdio transport shared and service identity local unless maintainers explicitly require normalized diagnostics; if they do, define a small structured diagnostics contract through an approved plugin SDK/runtime seam rather than importing a core `src/mcp` helper from the plugin.
