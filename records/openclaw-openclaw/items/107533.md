## Summary

Keep this open for a narrow maintainer decision. Current main already centralizes the shared MCP stdio transport, while each entry point deliberately supplies its own service identity and fatal-error callback; the issue does not establish that identical diagnostic text is a required cross-owner contract.

## What This Changes

Consolidate the fatal diagnostic formatting used by the OpenClaw tools and Codex supervision MCP server entry points.

## Best Possible Solution

Keep transport lifecycle logic centralized in `src/mcp/tools-mcp-stdio-server.ts` and retain service-specific fatal prefixes unless maintainers define a shared diagnostic contract; if they do, use a parameterized helper that preserves each adapter identity and exit behavior.
