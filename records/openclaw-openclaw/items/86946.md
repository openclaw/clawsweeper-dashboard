## Summary

Keep open: current main mitigates the stale-history UI replacement path, but the remaining durable `chat.send` contract is still unresolved because the gateway ACKs `started` before user-turn recorder setup and before fallback/runtime persistence can prove the send is durable or progressing.

## What This Changes

The issue asks for WebChat user submissions to stay visible, durable, and processed when `chat.send` ACKs before transcript/history persistence catches up.

## Best Possible Solution

Make the gateway `chat.send` contract explicit: after ACK, a WebChat user turn is durable or visibly progressing, or the user gets a visible/auditable failure, while keeping the current UI pending-message preservation.
