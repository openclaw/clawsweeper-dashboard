## Summary

Keeping #86946 open: current main has WebChat-side protection for stale history replacing optimistic user bubbles, but the Gateway still returns `chat.send` `started` before the durable user-turn persistence path is established, so the central accepted-message durability problem remains unresolved.

## What This Changes

The issue asks OpenClaw to prevent optimistic WebChat user sends from disappearing or being lost when `chat.history` is stale after `chat.send` acknowledges the turn.

## Best Possible Solution

Settle a current-main Gateway fix that defines and proves the durable `chat.send` boundary, preserves UI optimistic-tail protection, and covers stale history, busy same-session runs, restart/failure paths, and duplicate suppression.
