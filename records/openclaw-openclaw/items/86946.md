## Summary

Keep open: current main has strong UI-side protections against stale `chat.history` replacement, but the gateway still returns `chat.send` `started` before the user-turn transcript recorder/fallback durability path is established, and the open gateway-side candidate PR is unmerged and conflicting.

## What This Changes

The issue reports silent WebChat user-message loss when an optimistic send is acknowledged before the durable transcript catches up and later history reconciliation drops the local message.

## Best Possible Solution

Make the gateway `chat.send` contract explicit: after `started`, a WebChat user turn is durably visible or visibly failed, while preserving the current UI pending-message protections.
