## Summary

Keep open: current main and v2026.6.11 preserve more optimistic WebChat UI state, but the gateway still returns `started` before the user-turn recorder/fallback persistence boundary, and the direct gateway candidate PR remains open.

## What This Changes

The issue reports silent WebChat user-message loss when `chat.send` ACKs before the durable transcript/history path catches up.

## Best Possible Solution

Define and implement the `chat.send` durability contract so an accepted WebChat send is either durably visible/progressing or fails visibly, while retaining current optimistic-tail UI protection.
