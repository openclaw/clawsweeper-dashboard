## Summary

Keep open: current main and the latest release mitigate the UI full-replace/optimistic-tail loss path, but the central durable `chat.send` contract is still unresolved because the gateway sends `started` before user-turn recorder setup and persistence paths complete.

## What This Changes

The issue reports WebChat optimistic user messages disappearing and never being processed when `chat.send` acknowledges before durable transcript/history catches up.

## Best Possible Solution

Make the gateway `chat.send` contract explicit: after a `started` ACK, the WebChat user turn is durably visible or progressing, or the user receives a visible/auditable failure while the current UI pending-message preservation stays intact.
