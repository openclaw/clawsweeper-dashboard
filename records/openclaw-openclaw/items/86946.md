## Summary

Keep open: current main preserves more optimistic WebChat UI state, but `chat.send` still ACKs `started` before the shared user-turn recorder/fallback persistence boundary completes, and the active gateway-side candidate PR remains unresolved and conflicting.

## What This Changes

The issue reports WebChat optimistic user messages disappearing after `chat.send` acknowledges before the durable transcript is visible to `chat.history`.

## Best Possible Solution

Make the gateway `chat.send` contract explicit: after ACK, a WebChat user turn is durably visible/progressing or fails visibly and auditably, while keeping the current UI pending-message preservation.
