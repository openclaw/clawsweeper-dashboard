## Summary

Keep open: current main has UI-side protections for stale history and pending sends, but the gateway still acknowledges `chat.send` before the user-turn recorder/fallback persistence boundary, and the open gateway-side candidate PR remains unresolved.

## What This Changes

The issue asks OpenClaw to prevent WebChat user messages from disappearing or being silently dropped when `chat.send` returns before the durable transcript/history path catches up.

## Best Possible Solution

Define and implement a gateway contract where a `chat.send` ACK means the WebChat user turn is durably visible, guaranteed to progress, or visibly failed, while retaining current UI pending-message protection.
