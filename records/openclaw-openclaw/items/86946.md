## Summary

Keep open: current main protects the WebChat UI from stale `chat.history` replacement, but the gateway still returns `chat.send` `started` before the user-turn recorder/fallback persistence boundary is complete, and the open gateway candidate PR is still dirty and unresolved.

## What This Changes

The issue asks OpenClaw to prevent WebChat user submissions from disappearing or being dropped when `chat.send` ACKs before the durable transcript catches up.

## Best Possible Solution

Define and implement a durable WebChat `chat.send` contract: after ACK, the user turn is either visible/progressing in durable history or fails visibly, while preserving the current optimistic UI safeguards.
