## Summary

## What This Changes

The issue asks OpenClaw to prevent WebChat user messages from being silently lost when `chat.send` returns before durable transcript/history state catches up.

## Best Possible Solution

Maintainers should choose and land a durable WebChat `chat.send` contract: either a narrowed version of https://github.com/openclaw/openclaw/pull/80670 or a smaller Gateway change that makes persistence/error visibility explicit before users can lose a submitted turn.
