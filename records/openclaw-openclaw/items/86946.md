## Summary

Keep open: current main has fixed the client-side stale-history preservation path, but it still does not implement the durable `chat.send` ACK/progress guarantee requested by this issue, and the direct gateway-side candidate PR remains open.

## What This Changes

The issue reports that WebChat optimistic user messages can disappear and never be durably processed when `chat.send` acknowledges before `chat.history` includes the user turn.

## Best Possible Solution

Make the gateway `chat.send` contract explicit so an ACK means the user turn is durable or visibly failed, while retaining current UI pending-message preservation.
