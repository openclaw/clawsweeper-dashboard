## Summary

Keep open: current main has stronger WebChat client-side preservation for stale history reloads, but the remaining user problem is still the `chat.send` durability/progress contract, and the open gateway-side candidate is unresolved.

## What This Changes

The issue asks for WebChat user sends to survive stale `chat.history` reconciliation and never be acknowledged as started unless the user turn is durably visible, progressing, or visibly failed.

## Best Possible Solution

Define and implement the gateway `chat.send` contract so a started ACK means the WebChat user turn is durably visible or guaranteed to progress, with visible failure when that cannot be satisfied.
