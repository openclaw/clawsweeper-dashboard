## Summary

Keep open: current main mitigates the stale-history UI replacement path by preserving optimistic tail messages, but the central accepted-send durability problem remains because `chat.send` can still return `started` before the user turn is durably visible or safely queued, and the gateway-side candidate PR is still unresolved.

## What This Changes

The issue asks WebChat to stop losing accepted optimistic user sends when `chat.history` reloads before the durable transcript includes the user turn.

## Best Possible Solution

Define and implement a gateway-side `chat.send` contract where an ACKed WebChat user turn is either durably visible or safely queued before success, while retaining the current Control UI optimistic-tail preservation.
