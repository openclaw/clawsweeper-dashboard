## Summary

Keep open: current main and v2026.6.11 contain UI-side protections for stale WebChat history replacement, but the Gateway still returns `chat.send` `started` before the user-turn recorder/fallback persistence boundary, and the directly related Gateway fix PR remains open and conflicting.

## What This Changes

The issue asks OpenClaw to prevent WebChat user sends from disappearing or being dropped when `chat.send` acknowledges before `chat.history` or durable transcript state catches up.

## Best Possible Solution

Define one Gateway-owned `chat.send` contract: after `started`, a WebChat user turn is durably visible or clearly progressing, and failures become visible/auditable rather than silent.
