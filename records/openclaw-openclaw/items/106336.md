## Summary

Keep this PR open: the underlying LINE duplication bug is source-reproducible and the behavioral direction is sound, but the branch introduces a circular runtime dependency and provides only synthetic proof rather than an observed LINE delivery.

## What This Changes

The PR separates reply-token failure from later LINE push failure, tags visible partial-delivery errors, and adds regression coverage preventing already-delivered reply chunks from being pushed again.

## Best Possible Solution

Keep the separated reply-versus-overflow failure handling, move the visible-delivery error marker into a dependency-neutral LINE helper imported by both modules, and prove the controlled failure with a redacted real LINE transcript plus runtime logs.
