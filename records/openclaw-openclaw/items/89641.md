## Summary

Current main and stable v2026.6.11 now remove the reported default trigger: OpenClaw-managed `claude-cli` runs deny native `Bash(run_in_background:true)` and `Monitor` in both fresh and resumed argv, with regression coverage and release provenance from the merged fix PR.

## What This Changes

The issue requests fixing silent Telegram reply loss after Claude CLI native background Bash task-notification completion while the requester session is idle.

## Best Possible Solution

Keep the merged Anthropic plugin deny-list behavior and route future long-running command completion work through OpenClaw-owned wake paths rather than unsupported native Claude callbacks.

## Solution Assessment

Yes. The landed fix is the maintainable owner-boundary solution for the default path: Anthropic’s plugin disables unsupported Claude native background callbacks instead of adding Telegram-specific delivery shims for callbacks OpenClaw does not own.
