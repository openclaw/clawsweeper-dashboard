Full review comments:

- **[P2] Capture only the compaction timer:** `extensions/codex/src/app-server/compact.test.ts:868-870`
  - body: The `setTimeout` spy captures the first 1,000 ms timer while `vi.waitFor` is still running. Since `vi.waitFor` also uses a 1,000 ms timeout, a slow fake-client request can store the waiter's watchdog instead of the compaction completion timer, so triggering it does not exercise `turn/interrupt`. Scope the capture after the request is observed or avoid `vi.waitFor` while this spy is active.
  - confidence: 0.88
- **[P2] Avoid waitFor while collecting exec no-output timers:** `src/secrets/resolve.test.ts:290-294`
  - body: This test waits for `noOutputTimeouts.length >= 2` with `vi.waitFor` while the global spy records every 1,000 ms timeout. The waiter's own timeout can become the second entry before the exec resolver has re-armed its no-output timer, making `readPidFile` and `noOutputTimeouts.at(-1)` race or fire the wrong callback. Wait on a non-timer readiness signal or filter/capture only the resolver timer.
  - confidence: 0.9
- **[P2] Avoid waitFor while collecting policy no-output timers:** `src/security/install-policy.test.ts:259-263`
  - body: The install-policy test has the same timer collision: `vi.waitFor` runs under a global spy that captures all 1,000 ms timers, so its watchdog can satisfy the count before the policy command re-arms the intended no-output timer. That leaves the subsequent pid read and callback fire pointed at the wrong timer under slow spawn conditions.
  - confidence: 0.9
