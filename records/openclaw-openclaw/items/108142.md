## Summary

The accessibility goal is valid, but the patch updates the selected mode without moving DOM focus, so its new roving-tabindex behavior does not satisfy the intended composite-control keyboard pattern. The PR also needs a conflict refresh and after-fix browser proof before merge.

## What This Changes

Adds left/right arrow cycling and roving tab focus to the Control UI theme-mode selector.

## Best Possible Solution

Use native radio inputs styled as the segmented selector when practical; otherwise implement complete radio-group semantics and explicitly focus the newly selected option after each arrow key, with wraparound tests.

## Reproduction Assessment

Yes at source level: current main exposes all three mode buttons in the tab order, matching the reported inefficient keyboard path. A live browser reproduction was unavailable because the read-only shell sandbox failed before command execution.

## Solution Assessment

No. The custom roving-tabindex approach is incomplete because selection moves without focus; native radios, or a complete custom radio-group implementation with explicit focus transfer, would be more robust.
