## Summary

Keep open: current main and the latest release still do not expose ACP child tool calls, arguments, tool results, or thinking through `streamTo="parent"`; this remains a security-sensitive visibility/product decision rather than cleanup.

## What This Changes

The issue requests parent-visible ACP child progress for `streamTo="parent"`, including tool calls, tool results, arguments, and thinking updates.

## Best Possible Solution

Keep this as the canonical ACP parent-stream visibility tracker and define a bounded, redacted projection contract that reuses existing ACP tag visibility and channel progress settings before exposing any raw child internals.

Rationale: The requested data can include secrets, file paths, command output, and reasoning-like content, and current code intentionally separates sanitized ACP diagnostics from raw session-update data.

Options:

- **Define redacted projection (recommended):** Expose bounded summaries through existing ACP/channel visibility policy, with raw arguments, results, and thought hidden by default and covered by tests/docs.
- **Keep current scope:** Leave `streamTo="parent"` limited to assistant/commentary/status progress and direct detailed inspection to logs or richer session surfaces.
- **Add explicit raw verbose relay:** Forward raw tool and thought data only behind an explicit opt-in, accepting a larger security and privacy review burden.

Yes. Source inspection shows current main and `v2026.6.11` only relay assistant, preamble, selected status, and lifecycle progress to the parent; ACP tool-call, tool-result, and thought internals are not relayed.

## Solution Assessment

No. The raw forwarding sketch in the issue is not the safest fix; the maintainable path is a bounded redacted projection policy tied to existing ACP/channel visibility controls.
