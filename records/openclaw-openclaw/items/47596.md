## Summary

Keep open: current `main` still does not expose ACP child tool calls, raw arguments, tool results, or thinking through `streamTo="parent"`; the merged parent commentary/status work only partially overlaps, and the remaining visibility boundary is security-sensitive.

## What This Changes

The issue asks for ACP `streamTo="parent"` to expose child tool calls, arguments, tool results, and thinking/status progress to the parent session.

## Best Possible Solution

Define a bounded ACP parent-stream projection contract that emits redacted tool/progress summaries through existing progress and tag-visibility controls while keeping raw arguments, full results, and thinking hidden by default.

Options:

- **Define Redacted Projection (recommended):** Expose bounded tool/progress summaries through existing ACP tag visibility and channel progress policy, with raw args/results/thought hidden by default and covered by tests and docs.
- **Keep Current Scope:** Leave parent streams limited to assistant/commentary/status/lifecycle progress and direct detailed inspection to logs or richer session surfaces.
- **Add Explicit Full Relay:** Allow raw tool and thought visibility only behind an explicit opt-in, accepting a larger security and privacy review burden.

Yes, as a source-level behavior check rather than a strict bug repro. Current `main` still limits the ACP parent relay to assistant/commentary/status/lifecycle-style progress and leaves tool-call/update/thought internals out of parent-visible output.

## Solution Assessment

No, the issue's raw-forwarding sketch is not the best safe fix. The safer path is a redacted, bounded projection policy tied to existing ACP tag visibility and channel progress controls.
