## Summary

Keep open. Current main still routes Discord reactions as session system events, not as public plugin reaction hooks, and the remaining work is a public plugin API/product decision rather than conservative cleanup.

## What This Changes

Add public Hooks system support for Discord reaction add/remove events so plugins can automate reaction-driven workflows.

## Best Possible Solution

Define maintainer-approved observation-only reaction hooks, then wire Discord through the existing authorized reaction notification path with focused hook tests, docs, and explicit separation from reaction-triggered agent wakeups.
