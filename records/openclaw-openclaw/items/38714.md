## Summary

Keep open. Current main and the latest release still turn Discord reactions into routed system events, but they do not expose reaction add/remove events through the public plugin hook contract; the open wake-policy and broader SDK-event issues are adjacent, not replacements.

## What This Changes

Request to expose Discord reaction add/remove events through OpenClaw's plugin Hooks system so plugins can automate reaction-driven workflows.

## Best Possible Solution

Approve a generic observation-only reaction hook contract, then wire Discord through the existing authorized reaction notification path while keeping reaction-triggered agent wakeups in the separate wake-policy track.
