## Summary

Keep open. Current main and v2026.6.11 still expose Discord reactions as routed system events, not as public plugin reaction hooks; the open wake-policy PR is adjacent and does not replace the requested plugin hook API.

## What This Changes

Request to expose Discord reaction add/remove events through public plugin hooks so plugins can automate based on user reactions.

## Best Possible Solution

Define maintainer-approved observation-only reaction hooks with a shared payload, wire Discord through the existing authorized reaction notification path, and keep reaction-triggered agent turns in the separate wake-policy track.
