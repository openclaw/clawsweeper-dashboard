## Summary

Keep open. Current main and the latest release still accept Discord reactions as routed system events, but the public plugin Hooks contract has no reaction add/remove hook names or payload, so the requested automation surface remains real API/product work rather than cleanup-close material.

## What This Changes

The issue requests Discord reaction add/remove events to be exposed through the plugin Hooks system for reaction-driven automation.

## Best Possible Solution

Define an observation-only plugin reaction hook contract with explicit names, payload, and channel scope, then wire Discord reactions through it with docs and focused contract/monitor tests while preserving current notification filters.
