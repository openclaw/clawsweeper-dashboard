## Summary

Keep open. Current main and v2026.6.11 still expose accepted Discord reactions as routed system events, not as public plugin reaction hooks, and the open reaction-wake PRs are adjacent rather than a fix for the Hooks-system API request.

## What This Changes

Request to add Discord reaction add/remove events to the OpenClaw plugin Hooks system so plugins can automate reaction-driven workflows.

## Best Possible Solution

Define maintainer-approved observation-only reaction hooks, then wire Discord through the existing authorized reaction notification path with focused hook tests, docs, and clear separation from reaction-triggered agent wakeups.
