## Summary

Keep open. Current main and the latest release still convert Discord reactions into routed system events, while the public plugin hook contract has no reaction add/remove hook; the related wake-policy work is adjacent and does not replace plugin hook delivery.

## What This Changes

Request to expose Discord reaction add/remove events through the plugin Hooks system so plugins can automate reaction-driven workflows.

## Best Possible Solution

Define a maintainer-approved observation-only reaction hook contract, then wire Discord through the existing authorized reaction notification path while keeping reaction-triggered agent wakeups in the separate wake-policy track.
