## Summary

Keep open. Current main and v2026.6.11 still detect Discord reactions and enqueue routed system events, but they do not expose reaction add/remove events through the public plugin Hooks contract; related wake-policy and non-message-event items overlap but do not supersede this Discord hook API request.

## What This Changes

Request to expose Discord reaction add/remove events through OpenClaw's plugin Hooks system for reaction-driven automations.

## Best Possible Solution

Approve a generic observation-only reaction hook contract, then wire Discord through the existing authorized reaction notification path while keeping reaction-triggered agent wakeups in the separate wake-policy track.
