## Summary

Keep open. Current main still converts authorized Discord reactions into routed system events, while the public plugin hook contract and docs have no reaction add/remove hook; the open wake-policy PR is adjacent and does not replace plugin hook delivery.

## What This Changes

The issue requests public plugin Hooks support for Discord reaction add/remove events so plugins can react to user emoji reactions.

## Best Possible Solution

Define a maintainer-approved observation-only reaction hook contract, then wire Discord through the existing authorized reaction notification path while keeping reaction-triggered agent wakeups in the separate wake-policy track.
