## Summary

Keep open. Current main and the latest release still expose Discord reactions as routed system events, not as public plugin Hooks events; the adjacent wake-policy work is distinct from this requested hook API.

## What This Changes

The issue requests Discord reaction add/remove events in the plugin Hooks system so plugins can automate reaction-driven workflows.

## Best Possible Solution

Define maintainer-approved observation-only reaction hooks, then wire Discord through the existing authorized reaction notification path with focused tests and docs that keep it separate from reaction-triggered wakeups.
