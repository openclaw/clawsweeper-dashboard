## Summary

Keep open. Current main and v2026.6.11 still route accepted Discord reactions into queued system events, but the public plugin hook contract has no reaction add/remove hook names, handler map entries, runner surface, or docs; related wake-policy and inbound-activity work is adjacent and does not replace this request.

## What This Changes

Request to expose Discord reaction add/remove events through the plugin Hooks system so plugins can implement reaction-driven automation.

## Best Possible Solution

Define maintainer-approved observation-only reaction hooks, then wire Discord through the existing authorized reaction notification path while keeping reaction-triggered agent wakeups in the separate wake-policy track.
