## Summary

Keep open: current main and v2026.6.11 still expose Discord reactions only as queued system events, with no plugin hook name, handler map entry, runner method, or docs entry for reaction add/remove hooks; related wake-policy and external-channel event items overlap but do not supersede this plugin-hook request.

## What This Changes

Add plugin Hooks support for Discord reaction add/remove events so plugins can automate reaction-driven workflows.

## Best Possible Solution

Maintainers should bless a small observation-only reaction hook contract, likely generic across reaction-capable channels, then wire Discord after existing reaction authorization and notification gates with focused contract, listener, and docs coverage.

- **Use System Events Only:** Document reaction system events and heartbeat usage as the supported plugin path, avoiding a new hook but leaving this requested direct observation surface unimplemented.
