## Summary

Keep open. Current main and the latest release still route Discord reactions into session-scoped system events, but the public plugin hook contract has no reaction add/remove hook; the open Discord wake-policy PR is adjacent and does not replace this plugin API work.

## What This Changes

Add plugin Hooks support for Discord reaction add/remove events so plugins can automate on reactions instead of only seeing passive system events.

## Best Possible Solution

Define a maintainer-approved observation-only reaction hook contract, then wire Discord through the existing authorized reaction notification path while keeping reaction-triggered agent wakeups in the separate https://github.com/openclaw/openclaw/issues/17840 and https://github.com/openclaw/openclaw/pull/83169 track.
