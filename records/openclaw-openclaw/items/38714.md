## Summary

Keep open. Current main and v2026.6.11 still expose Discord reaction notifications as routed system events, not as public plugin reaction hooks; the related wake-policy PR and broader external-channel SDK issue are adjacent, so maintainer API direction is still needed.

## What This Changes

The issue requests Discord reaction add/remove events be exposed through the plugin Hooks system so plugins can automate on user reactions.

## Best Possible Solution

Define maintainer-approved observation-only reaction hooks, then wire Discord through the existing authorized reaction notification path with focused hook tests, docs, and explicit separation from reaction-triggered agent wakeups.
