## Summary

Keep open: current main and v2026.6.11 still expose Discord reactions only as routed system events, while the public plugin hook contract has no reaction hook names, handler map entries, runner, or docs; related wake-policy and generic inbound-activity work does not replace a plugin-observable reaction_added/reaction_removed API.

## What This Changes

Request to add plugin hook support for Discord reaction events so plugins can observe added and removed reactions directly.

## Best Possible Solution

Approve an observation-only reaction hook contract, then wire Discord reactions through the existing authorized listener while keeping reaction-triggered agent wake policy separate.
