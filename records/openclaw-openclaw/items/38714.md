## Summary

Keep open. Current main and v2026.6.11 still expose Discord reactions as routed system events, not as public hook events, and the related wake-policy work is adjacent rather than a replacement for plugin hook delivery; cedricjanssens' production workaround/proposal adds useful contract evidence but still needs maintainer API direction.

## What This Changes

Request to expose Discord reaction add/remove events through the public Hooks system so plugins can automate on user reactions.

## Best Possible Solution

Define a maintainer-approved observation-only reaction hook contract, then wire Discord through the existing authorized reaction notification path with focused tests and docs while keeping reaction-triggered agent wakeups in the separate wake-policy track.
