## Summary

Keep open. Current main and v2026.6.11 still expose Discord reactions only as routed system events, while the public plugin hook contract lacks reaction add/remove hook names, typed handler map entries, runner methods, and docs; the newer external-channel event issue is related but does not replace this concrete Discord hook request.

## What This Changes

Request to expose Discord reaction add/remove events through the plugin Hooks system so plugins can automate reaction-driven workflows.

## Best Possible Solution

Define maintainer-approved observation-only reaction hooks, then wire Discord through the existing authorized reaction notification path while keeping reaction-triggered agent wakeups in the separate wake-policy track.
