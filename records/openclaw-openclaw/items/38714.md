## Summary

Keep open. Current main and v2026.6.11 still detect Discord reactions only through the reaction notification/system-event path, while the public plugin hook contract has no reaction add/remove hook names, handler map entries, runner methods, or docs; the related open PRs cover wake policy or debounce activity rather than this plugin hook API.

## What This Changes

The issue requests plugin hook support for Discord reaction add/remove events so plugins can automate from user reactions instead of only seeing routed system events later.

## Best Possible Solution

Define a maintainer-approved observation-only reaction hook contract, then wire Discord through the existing authorized reaction notification path while leaving agent-turn wakeups in the separate wake-policy track.

## Reproduction Assessment

Yes, at source level. Current main handles Discord reactions and queues system events, but the public hook registry, handler map, runner, docs, and tests have no reaction add/remove hook path.

## Solution Assessment

Unclear until maintainers decide the public contract. Dedicated observation-only hooks look cleaner than overloading `message_received`, but names, payload shape, enrichment, and cross-channel scope still need approval.
