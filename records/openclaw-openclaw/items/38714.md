## Summary

Keep open. Current main and v2026.6.11 still expose accepted Discord reactions only as routed system events, while the public plugin hook names, handler map, runner surface, and docs have no reaction add/remove hook; the linked workaround and broader event/wake discussions are useful context but do not supersede this API request.

## What This Changes

Request support for Discord reaction add/remove events in the Hooks/plugin API so plugins can automate on reactions instead of only receiving passive system-event context.

## Best Possible Solution

Land a maintainer-approved observation-only reaction event contract, ideally generic across reaction-capable channels and emitted after existing channel authorization and reaction-notification filters, with plugin docs and focused Discord tests.
