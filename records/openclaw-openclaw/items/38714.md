## Summary

Keep open. Current main still handles accepted Discord reactions as routed system events, not as public plugin reaction hooks; the related wake-policy PR is adjacent and does not satisfy the requested Hooks-system API.

## What This Changes

The issue requests Discord reaction add/remove events to be exposed through the plugin Hooks system for reaction-driven automation.

## Best Possible Solution

Define maintainer-approved observation-only reaction hooks, then wire Discord through the existing authorized reaction notification path with focused hook tests, docs, and explicit separation from reaction-triggered agent wakeups.
