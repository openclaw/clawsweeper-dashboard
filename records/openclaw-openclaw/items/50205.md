## Summary

Keep open: current main and the latest release still lack a Google/Vertex request-label config contract or automatic payload injection, while the discussion and Google Cloud docs support a real billing-attribution need that requires maintainer product/config policy before implementation.

## What This Changes

The issue requests configurable request labels on Google/Gemini or Vertex generateContent calls so operators can attribute GCP billing costs by deployment or workload.

## Best Possible Solution

Approve a narrow Google provider contract for low-cardinality, non-sensitive labels, scoped to supported Vertex/Gemini request paths, with strict schema/types, docs, and tests proving config rejection/acceptance and outbound payload injection.

## Reproduction Assessment

Yes, at source level: current main has no `requestLabels` config field, the provider schema is strict, and the Google generateContent payload builder never adds `labels`. I did not run live provider calls because this read-only review only needed source and docs proof.

## Solution Assessment

Unclear as proposed: a raw `models.providers.google.requestLabels` field is plausible, but the best fix needs maintainer decisions on Vertex versus AI Studio scope, label validation, privacy/cardinality limits, and whether any dynamic OpenClaw labels are allowed.
