## Summary

Keep open: current main and the latest release still lack a Google/Vertex request-label config contract or payload injection, while the issue discussion and Google docs support a real billing-attribution use case that needs maintainer product/config policy before implementation.

## What This Changes

Request configurable Google/Vertex Gemini request labels in provider config so outbound generateContent calls can carry billing metadata.

## Best Possible Solution

Approve a narrow Google provider label contract for low-cardinality, non-sensitive labels, scoped to supported Vertex request paths, with schema/types, docs, and focused payload tests.

## Reproduction Assessment

Yes, at source level: current main has no requestLabels config field, the provider schema is strict, and the Google generateContent payload builder never adds labels. I did not run live provider calls because this read-only review only needed source and docs proof.

## Solution Assessment

Unclear as proposed: a raw models.providers.google.requestLabels field is plausible, but the best fix needs maintainer decisions on Vertex scope, label validation, privacy, and whether any dynamic OpenClaw labels are allowed.
