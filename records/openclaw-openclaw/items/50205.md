## Summary

Keep open: current main and the latest release still lack a Google/Vertex request-label config contract or payload injection, while the issue has a concrete operator billing use case and upstream Vertex documentation supports labels on generative API calls.

## What This Changes

Request support for configurable Google/Gemini or Google Vertex request labels so operators can attribute GCP billing costs per deployment or workload.

## Best Possible Solution

Keep this as the canonical request and, after maintainer approval, add a Vertex-only Google plugin label contract with validation, payload injection, focused schema/transport tests, docs, and a redacted live Vertex smoke.

## Reproduction Assessment

Yes. Source inspection shows the proposed `requestLabels` key is absent from the strict provider schema and the Google/Vertex request builder emits no `labels` field.

## Solution Assessment

Unclear until maintainers choose the contract. A provider-owned, Vertex-only label field is the likely maintainable path; a generic request-body escape hatch would be a riskier fit for the repository's config-surface policy.
