## Summary

Keep open: current main still has no supported Google/Vertex request-label config contract or automatic `labels` injection, and the remaining work is a real provider capability that needs maintainer product/config policy before implementation.

## What This Changes

Request configurable labels on outbound Google/Gemini generateContent requests so operators can attribute GCP billing by deployment or workload.

## Best Possible Solution

Approve a narrow Google provider contract for low-cardinality, non-sensitive labels, scoped to supported Gemini/Vertex request methods, with strict schema/types, docs, regression tests, and redacted live proof.

## Reproduction Assessment

Yes, at source level: current main has no `requestLabels` config field, the provider schema is strict, and the Google generateContent payload builder never adds `labels`. I did not run live provider calls because the missing source path is enough to verify the requested capability is absent.

## Solution Assessment

Unclear as proposed: a raw provider-level `requestLabels` key is plausible, but the best fix needs maintainer decisions on Vertex versus AI Studio scope, validation, privacy/cardinality limits, and whether any dynamic OpenClaw labels are allowed.
