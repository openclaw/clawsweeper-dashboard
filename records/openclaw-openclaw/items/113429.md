## Summary

Keep this PR open, but do not merge it as-is: the transient reset-token design does not give the delayed lifecycle cleanup a durable generation identity when delivery fails or is delayed, so the same retained physical session can still be retired incorrectly. The proposed replacement at https://github.com/openclaw/openclaw/pull/113796 addresses that boundary more directly, but it is not yet a safe superseding close target because its exact-head live proof is still incomplete.

## What This Changes

This PR passes a temporary reset token from retained-session reset flows through the agent harness and session-end hook so Codex can reopen its binding after `/new`, `/reset`, idle rollover, or daily rollover.

## System Context

OpenClaw reset flows retain a durable session ID so transcript history remains searchable, then notify registered agent harnesses and plugins about the old lifecycle ending. The Codex plugin maps that lifecycle to an app-server thread binding; it must retire stale generations without retiring the fresh successor that shares the retained session ID.

## Architecture Diagram

flowchart TD
  A[User reset or automatic rollover] --> B[OpenClaw session lifecycle]
  B --> C[Agent harness reset]
  C --> D[Codex binding state]
  B --> E[Delayed session-end hook]
  E --> F[Generation ownership decision]
  F --> G[Retire stale binding]
  F --> H[Allow fresh Codex thread binding]

## Best Possible Solution

Use an authoritative lifecycle generation/revision created by the session lifecycle and carried into Codex binding ownership, with upgrade coverage for legacy binding rows; then prove the exact branch on the real Telegram-to-Codex route and keep failure, delay, duplicate, and physical-rollover cases fail-closed.

## Solution Assessment

No. Exact in-process reset tokens improve the ordinary ordering path but are not the narrowest reliable owner boundary; a session-authored lifecycle generation/revision is the safer discriminator because it survives the asynchronous contract without treating hook delivery as authoritative state.
