## Summary

Keep this PR open for maintainer review. The proposed fix directly addresses the retained-session reset regression introduced by the durable reset design, has focused automated coverage and redacted live Telegram/Codex evidence, but it adds a permanent optional correlation field to two shared plugin lifecycle contracts and is behind current `main`; that shared API direction and exact merge-head behavior need confirmation before merge.

## What This Changes

The PR adds a one-shot runtime reset token so a Codex binding can be reopened after `/new` retains the same OpenClaw session ID, while unrelated or stale session-end events still retire the binding.

## System Context

A chat reset first calls registered agent harnesses, then emits a delayed session-end event to plugins. The Codex extension maps the OpenClaw session identity to a Codex thread binding, so it must distinguish an intentional same-ID reset from a stale lifecycle event that should fence the old generation.
