## Summary

Keep this PR open for owner review. The proposed one-shot correlation appears to fix the retained-session reset regression without weakening fail-closed generation fencing, and it includes strong route-level proof, but it extends the generic harness and plugin lifecycle contracts with a Codex-driven token whose permanent cross-plugin semantics need an explicit owner decision.

## What This Changes

The branch passes a transient reset token from retained-session reset paths through the agent harness and delayed session-end hook so Codex can reopen its thread binding after `/new`, `/reset`, `idle`, or `daily` rollover.

## System Context

OpenClaw preserves the physical session ID for durable reset boundaries, while the Codex app-server plugin keeps a separate thread binding for that session. Reset code runs registered harness cleanup before emitting a delayed lifecycle event; the plugin must distinguish a successful same-ID reset from stale or unrelated lifecycle ends before it decides whether to retain or retire the binding.

## Architecture Diagram

flowchart LR
  Reset[Durable session reset] --> Harness[Registered agent harness]
  Harness --> Token[One-shot reset token]
  Token --> End[Delayed session-end event]
  End --> Fence[Codex generation fence]
  Fence --> Rebind[Allow fresh thread binding]
  Fence --> Retire[Retire stale generation]

## Best Possible Solution

Keep the exact-token, fail-closed Codex repair, but have the reset and plugin-contract owners explicitly confirm that lifecycle correlation belongs on the generic hook surface and document or narrow that contract before merge.
