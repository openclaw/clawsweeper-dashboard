## Summary

Keep this PR open for maintainer review. The token correlation is a focused response to retained physical session IDs, but it expands shared lifecycle payloads and the supplied real-world proof covers an earlier head rather than the current `de5007a8` head.

## What This Changes

This PR passes a one-shot runtime reset token through reset handling and the Codex session-end hook so a same-ID `/new`, `/reset`, idle, or daily rollover can reopen its Codex thread binding without accepting unrelated delayed cleanup.

## System Context

OpenClaw's reset paths retain a physical session ID so SQLite transcript history remains continuous, then notify registered agent harnesses and plugins that the previous lifecycle ended. The Codex extension uses that lifecycle signal to retire or reopen its app-server thread binding before the next user message is routed to Codex.

  E --> F[Codex lifecycle decision]

## Best Possible Solution

Retain the bounded one-shot correlation approach only if the lifecycle owners approve the two shared payload additions, then add redacted exact-head Gateway/Codex evidence that shows reset followed by a successful reply and documents the delayed-event fence through focused regression coverage.
