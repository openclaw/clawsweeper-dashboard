## Summary

This is a focused fix for the retained-session `/new` regression and has strong targeted test, CI, and redacted live-route evidence. The remaining blocker is maintainer acceptance of the new optional shared lifecycle-correlation fields, which make reset-token semantics a contract for harness and plugin implementers rather than a Codex-only detail.

## What This Changes

The PR passes a one-shot runtime reset token from both OpenClaw reset paths through the agent harness and session-end hook so Codex can preserve only the matching same-session reset generation and bind a fresh thread on the next turn.

## System Context

OpenClaw reset flows keep the durable physical session ID so SQLite transcripts remain continuous, then notify registered agent harnesses and plugins about the lifecycle boundary. The Codex extension uses that boundary to retire or reopen its app-server thread binding before the next inbound turn resumes or starts a native Codex thread.

  E --> F{Exact same reset token?}
  F -->|Yes, same session| G[Allow fresh Codex binding]

  H --> I

## Best Possible Solution

Explicitly accept a narrowly documented generic in-process reset-correlation contract, keep the token transient and fail-closed as implemented, then rebase the PR and land it with the existing focused lifecycle coverage.
