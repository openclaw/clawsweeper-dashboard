## Summary

Keep open. Current main and the latest release still lack Signal `linkPreview` config, generated metadata/docs exposure, and native/container send pass-through, and the remaining work needs maintainer direction because it adds a config surface that overlaps link-preview metadata security and Signal primary-device behavior.

## What This Changes

Add a `channels.signal.linkPreview` setting and wire Signal link-preview configuration or explicit preview fields through the Signal JSON-RPC send path.

## Best Possible Solution

Add maintainer-approved Signal plugin support with default-safe compatibility semantics, explicit caller-provided preview-field pass-through, documented primary-device behavior, and no automatic metadata fetching unless the related security design permits it.
