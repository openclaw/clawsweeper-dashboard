## Summary

Keep open: current main still lacks a Ralph-style repeated same-prompt loop and any per-agent Ralph iteration default; the active iteration-budget PR overlaps the guardrail side but is open/conflicting and does not replace the specific STOP-driven continuation design.

## What This Changes

Request to add a per-agent Ralph loop iteration-limit config surface with explicit CLI, agent, global, and default precedence.

## Best Possible Solution

Define one OpenClaw-native continuation and budget contract that separates intentional repeated-prompt workflows from accidental tool loops, then expose the smallest typed config surface with documented precedence and terminal-outcome semantics.

## Reproduction Assessment

Yes, for the missing capability rather than a broken existing behavior: current source has no Ralph/repeated-prompt loop field, strict schemas reject unknown agent keys, and the resolver has no setting to propagate to the runner.

## Solution Assessment

Unclear as proposed. The user need fits agent-harness work, but Kimi-specific field names, STOP sentinels, and unlimited-loop behavior should wait for an OpenClaw-native continuation and budget contract.
