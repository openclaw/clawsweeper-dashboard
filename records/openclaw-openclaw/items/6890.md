## Summary

Keep open: current main and v2026.6.11 still lack a Ralph-style repeated same-prompt loop or per-agent `loop.max_ralph_iterations` default, and the existing `runRetries` and tool-loop detection surfaces do not provide the requested STOP-driven loop semantics or precedence chain.

## What This Changes

Request to add an agent-scoped Ralph loop iteration limit with CLI > agent > global/default precedence and matching runtime/docs/tests.

## Best Possible Solution

Define one OpenClaw-native continuation and iteration-budget contract that separates intentional repeated-prompt workflows from accidental tool loops, then expose the smallest typed config surface with documented precedence and runtime tests.

## Reproduction Assessment

Not applicable as a broken-behavior reproduction: this is a feature request. Source inspection confirms the requested capability is absent because strict current schemas reject the proposed agent key and the resolver has no Ralph/repeated-prompt loop value to propagate.

## Solution Assessment

Unclear as proposed. The user need fits agent-harness work, but Kimi-specific names, STOP sentinels, unlimited-loop semantics, and override precedence should wait for a maintainer-approved OpenClaw-native contract.
