## What This Changes

## Best Possible Solution

Define one OpenClaw-native continuation and budget contract, land the broader hard-budget work only if maintainers accept its config/API semantics, and separately decide whether Ralph-style repeated-prompt STOP loops belong in core.

## Reproduction Assessment

Yes for the source-level missing capability: current schemas omit and strictly reject the proposed loop surface, and the resolver/runtime have no setting to propagate. This is a feature request rather than a broken-behavior repro.

## Solution Assessment

Unclear as proposed. The need fits agent-harness reliability work, but Kimi-style field names, STOP sentinels, unlimited looping, and overlap with the iteration-budget PR need an OpenClaw-native product contract first.
