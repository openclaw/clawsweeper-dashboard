## Summary

Keep open: current main and v2026.6.11 still lack a Ralph-style repeated same-prompt loop and a per-agent Ralph iteration default; adjacent `runRetries` and `tools.loopDetection` cover retry/pattern guards, not the requested STOP-driven loop with explicit precedence.

## What This Changes

The issue requests an OpenClaw agent configuration surface for Ralph-style looping, including per-agent max iteration defaults and CLI > agent > global precedence.

## Best Possible Solution

Define one OpenClaw-native continuation and budget contract that separates intentional repeated-prompt workflows from accidental tool loops, then expose the smallest typed config surface with documented precedence and terminal-outcome semantics.

## Reproduction Assessment

Yes for the missing capability, not as a broken-behavior bug: current source has no Ralph/repeated-prompt loop field, strict schemas reject unknown agent keys, and the resolver has no setting to propagate to the runner.

## Solution Assessment

Unclear as proposed. The user need fits agent-harness work, but Kimi-specific field names, STOP sentinels, and unlimited-loop behavior should wait for an OpenClaw-native continuation and budget contract.
