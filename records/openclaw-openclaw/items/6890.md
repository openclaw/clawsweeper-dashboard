## Summary

Keep open: current main and the latest release still lack a Ralph-style repeated same-prompt loop and a per-agent Ralph iteration default. Existing `runRetries` and `tools.loopDetection` are adjacent guardrails, and the open iteration-budget PR is not merged and does not settle the requested STOP-driven loop semantics.

## What This Changes

Request adds a per-agent Ralph/repeated-prompt loop default with an iteration limit and documented precedence against CLI and global configuration.

## Best Possible Solution

Define one OpenClaw-native continuation and budget contract that separates intentional repeated-prompt workflows from accidental tool loops, then expose the smallest typed config surface with documented precedence and terminal-outcome semantics.

## Reproduction Assessment

Yes for source-level absence, not as a broken-behavior bug. Current source has no Ralph/repeated-prompt loop field, strict schemas reject unknown agent keys, and the resolver has no value to propagate to the runner.

## Solution Assessment

Unclear as proposed. The user need fits agent-harness work, but Kimi-specific field names, STOP sentinels, and unlimited-loop behavior should wait for an OpenClaw-native continuation and budget contract.
