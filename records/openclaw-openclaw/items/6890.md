## Summary

Keep open for product direction. The latest supplied current-main review still finds no STOP-driven repeated-prompt mode, while the open iteration-budget PR addresses runaway tool-calling rounds rather than the requested orchestration behavior. Prior maintainer-side discussion also explicitly kept this request open.

## What This Changes

Add a STOP-driven repeated-prompt agent loop with global and per-agent iteration limits and explicit CLI, agent, and global precedence.

## Best Possible Solution

Separate loop safety from orchestration: retain a generic opt-in hard budget for existing agent runs, and only add a Ralph-style controller after defining STOP detection, interruption/resume, transcript semantics, precedence, and the minimal generic runtime or plugin seam needed to host it.
