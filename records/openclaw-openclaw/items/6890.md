## Summary

Current main and v2026.6.11 provide defensive repeated-tool loop detection, but they do not provide the requested STOP-driven same-prompt run mode. The open iteration-budget PR is a strong but narrower circuit-breaker implementation, so this issue remains necessary for an explicit product decision rather than closing as implemented or superseded.

## What This Changes

Add a STOP-driven repeated-prompt agent mode with a configurable per-agent iteration default and defined runtime override precedence.

## Best Possible Solution

Keep defensive loop detection and iteration budgets as the canonical safety path; add proactive repeated-prompt execution only after maintainers define its lifecycle contract and decide whether a narrow plugin runtime seam or a core mode should own it.
