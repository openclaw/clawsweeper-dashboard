## Summary

Keep open for a maintainer product decision: current main and v2026.6.11 have safety-oriented loop detection and failure retries, but still lack the requested intentional same-prompt-until-STOP mode and its per-agent default; the open iteration-budget PR overlaps only the safety-limit portion.

## What This Changes

Add a configurable Ralph-style agent mode that repeats the same prompt until STOP, with a per-agent iteration limit and explicit CLI, agent, global, and default precedence.

## Best Possible Solution

Choose one explicit boundary: preferably add a narrow plugin/runtime run-loop API and publish Ralph mode as a plugin, or, if maintainers consider it a core harness capability, define a separate opt-in Ralph contract with interruption, state, precedence, and finite-limit semantics rather than folding it into tool-loop safety budgets.

Options:

- **Expose a plugin run-loop hook (recommended):** Add the smallest safe runtime API needed for a ClawHub plugin to own Ralph orchestration and per-agent plugin configuration.
- **Add an opt-in core mode:** Define and implement a distinct core Ralph contract with explicit STOP, interrupt, state, precedence, and bounded/unlimited semantics.
- **Decline native support:** Keep existing external supervisor and skill patterns as the supported approach without adding core or plugin API surface.

## Reproduction Assessment

Yes at source level: current main’s strict agent config, resolver, documented loop detection, and run-retry paths contain no same-prompt-until-STOP mode or equivalent per-agent default. This is an absence-of-capability check rather than a failing existing behavior reproduction.

## Solution Assessment

No, directly transplanting Kimi’s field and sentinel semantics is not yet the best OpenClaw solution. The project should first choose core versus plugin ownership and define OpenClaw-native STOP, interruption, state, precedence, and safety contracts.
