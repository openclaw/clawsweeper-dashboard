## Summary

Keep this PR open for a targeted correction before merge. The stale-schedule path is split correctly in `timer-outcomes.ts`, but the manual-run no-fire path converts `stale-preserve` back to `advance`, which can still overwrite an operator-edited schedule in the scenario the PR is intended to fix.

## What This Changes

The PR separates forced from stale cron schedule preservation, centralizes cron run-admission slot release, and relocates timer watchdog regressions to a focused test file.

## System Context

Cron jobs are admitted through a bounded run queue, execute an agent task, and then write the execution outcome back to the stored schedule. The changed code determines whether that outcome advances a schedule or preserves an operator edit before future timer processing and repair run.
