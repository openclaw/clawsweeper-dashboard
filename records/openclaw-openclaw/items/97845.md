## Summary

This PR addresses a real current-main sanitizer gap, but its new bare `<invoke>` stripping remains too broad: a full-line legitimate XML/example block outside Markdown code spans is indistinguishable from the degraded tool-call form and can be deleted from a user reply or persisted message. The contributor supplied convincing after-fix behavior proof for the reported namespaced leaks; the remaining blocker is the compatibility policy for unnamespaced markup.

## What This Changes

The branch adds `mm:` and bare/`antml:`/`mm:` attribute-style invoke-block stripping across visible-text and persisted-message paths, with shared Markdown code-region helpers and regressions.

## Best Possible Solution

Keep the namespaced `antml:`/`mm:` fix, but restrict unnamespaced stripping to an unambiguous wrapper or a maintainer-approved discriminator; preserve bare XML by default until its compatibility contract is explicitly chosen.
