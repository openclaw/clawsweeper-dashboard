## Summary

Keep open. Current main and the latest release still accept Gateway HTTP requests in `auth.mode="none"` before applying the browser Origin policy, while the WebSocket sibling path rejects disallowed Origins; because this changes a Gateway security boundary, it needs maintainer security review rather than cleanup close.

## What This Changes

The issue asks OpenClaw to reject browser-origin Gateway HTTP requests under `gateway.auth.mode="none"` when the `Origin` is not allowed, matching the WebSocket ingress behavior.

## Best Possible Solution

Apply one shared HTTP browser-Origin gate whenever an `Origin` header is present before accepting `auth.mode="none"`, preserve origin-less private-ingress clients, and add focused regression coverage for none-mode HTTP plus existing trusted-proxy and WebSocket parity.
