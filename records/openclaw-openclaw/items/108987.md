Keep validation in the shared Canvas payload parser, normalize only the intentionally accepted whitespace and missing padding, then decode and require the bytes to re-encode exactly to that normalized base64; cover non-zero-pad-bit inputs and prove an actual Canvas CLI or tool run rejects them before a real file write.

- **[P2] Reject encodings with non-zero pad bits:** `extensions/canvas/src/cli-helpers.ts:68`
  - body: This branch returns any alphabet-valid string whose length is divisible by four, so non-canonical values such as `Zh==` are accepted even though the same decoded byte re-encodes as `Zg==`. RFC 4648 requires unused pad bits to be zero, meaning node-controlled malformed data can still reach the snapshot write path. Decode the normalized value, compare `buffer.toString("base64")` with it, and add one- and two-padding regression cases.
