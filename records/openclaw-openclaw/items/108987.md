The PR canonicalizes Canvas snapshot base64 before CLI file writes or agent-tool image creation and adds regression coverage for malformed encodings.

## Best Possible Solution

Land the shared plugin-owned canonicalization boundary after refreshing the branch, preserving focused coverage for whitespace normalization, missing padding, non-zero pad bits, control characters, and both snapshot consumers.

## Reproduction Assessment

Yes. On current main, return `Zh==`, `Zm9=`, or a NUL-containing base64 string from a paired node's `canvas.snapshot`; the shared parser accepts the non-empty string and the CLI/tool paths pass it to Node's permissive base64 decoder.

## Solution Assessment

Yes. Validating once in the plugin-owned shared payload parser is narrower and less drift-prone than adding separate checks at the CLI and agent-tool write sites, and the decode/re-encode comparison correctly catches non-canonical pad bits.
