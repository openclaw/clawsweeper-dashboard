## Summary

Keep open: the current head still violates the established `create()` completion contract by returning a live record before worktree provisioning has completed. The previous P1 finding remains unchanged on the final head, and existing plugin/session consumers immediately treat the returned path as usable.

## What This Changes

The PR adds exact orphan detection and atomic path claims, moves normal worktree creation to claim before provisioning, and re-provisions eligible orphaned worktrees on retry.

## Best Possible Solution

Keep atomic path ownership, but add a canonical SQLite-backed claimed/provisioning/ready lifecycle, migrate existing rows as ready, and allow `create()`, owner lookup, and execution callers to return or use only ready worktrees.
