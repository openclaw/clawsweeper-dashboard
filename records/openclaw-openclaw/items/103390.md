- **[P1] Keep provisioning snapshots out of the ready restore path:** `src/agents/worktrees/service.ts:795-801`
  - body: A `provisioning` row is list-visible and `remove()` will snapshot it, but `restore()` then marks that snapshot `ready` after only copying included files; it never reruns `worktree-setup.sh`. If the process crashed mid-setup, or an operator removes the visible row while setup is still running, same-name `create()` restores a checkout missing create postconditions and exposes it as usable. Hard-delete provisioning claims on removal, or fully reprovision them before the ready flip, and cover a genuinely incomplete checkout rather than a fully-created row whose flag was changed in the registry. This was equally visible on the prior reviewed head; this review flags the late discovery explicitly.
