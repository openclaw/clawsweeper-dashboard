## Summary

The prior blocker remains on the latest head: a worktree removed while still provisioning can be snapshotted and later restored as `ready`, bypassing the provisioning postconditions this PR introduces. Likely related people: `steipete` introduced the managed-worktree lifecycle, and `yetval` recently added the run-lease/removal-claim lifecycle this patch composes with.

## What This Changes

The PR adds atomic managed-worktree path claims, persisted provisioning readiness with heartbeats, retried-create orphan adoption, and stale provisioning cleanup through shared removal claims.

## Best Possible Solution

Make provisioning claims cleanup-only: reject ordinary snapshot-backed removal and restoration for `readiness: provisioning`, while stale or missing provisioning claims continue through the dedicated claim-serialized no-snapshot reap path.
