## Summary

The PR addresses a valid current-main crash orphan with a strong atomic-claim/readiness design and substantial real behavior proof, but the exact head still lets an incomplete `provisioning` checkout pass through normal snapshot removal and return from restore as `ready`. That defeats the readiness invariant and should block merge until provisioning records are cleanup/recreate-only.

## What This Changes

The PR adds atomic managed-worktree path claims, persisted provisioning readiness with heartbeats, retried-create orphan adoption, stale-claim cleanup through shared removal claims, and an optional readiness field in gateway records.

## Best Possible Solution

Make `provisioning` records cleanup/recreate-only: their removal should claim exclusively, delete the worktree, branch, and row without a snapshot, and leave the name retriable; preserve snapshot/restore only for `ready` records.
