## Summary

Keep this PR open for a focused repair: the contributor has now supplied convincing live recovery proof, but the previously reported atomicity defect remains unchanged and survives GitHub’s current merge result. GC and a retried create can independently insert different records for the same physical worktree, splitting owner and lifecycle state.

## What This Changes

The PR adopts crash-orphaned managed worktrees during garbage collection and retried creation, re-provisions create-side adoptions, preserves caller ownership, and leaves foreign or detached worktrees untouched.

## Best Possible Solution

Preserve the exact managed path-and-branch identification and create-side reprovisioning, but make adoption a database-backed atomic claim so one canonical live registry record owns each physical worktree path; alternatively, keep GC preserve-only until that claim exists.
