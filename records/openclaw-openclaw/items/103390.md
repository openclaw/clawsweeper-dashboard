## Summary

The original crash-orphan bug remains valid and the branch takes the right architectural direction, but the latest head still permits an incomplete provisioning record to become a restorable ready worktree. The prior lifecycle blocker therefore remains after the rebase.

## What This Changes

The PR atomically claims managed-worktree paths before provisioning, persists provisioning readiness with heartbeats, adopts exact crash orphans on retry, and reaps dead claims through the shared removal lock.

## Best Possible Solution

Make provisioning removal destructive and non-restorable: reject ordinary snapshot removal for provisioning records or route them through the existing claim-aware reap helper, then add a deterministic test proving remove plus same-name create cannot restore an incomplete checkout as ready.
