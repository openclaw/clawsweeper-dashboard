## What This Changes

Prevent temporary OpenAI Responses reasoning items with `rs_tmp_*` IDs from being saved as replay signatures or sent again on later turns, while preserving their visible summaries and stable `rs_*` replay items.

## System Context

OpenAI Responses streaming converts provider output into assistant transcript blocks, including optional reasoning replay metadata. On a later agent turn, the Responses converters serialize that stored transcript back into provider input, so invalid transient reasoning state can persist across turns and cause repeated request failures.

  F --> G[Follow-up response or encrypted-content error]

## Best Possible Solution

Review and land the focused linked fix after confirming that both Responses implementations retain visible summaries and stable replay while excluding transient `rs_tmp_*` signatures, including signatures already present in older transcripts.
