## Summary

Keep open: current main already has a native Ollama `/api/chat` stream path that consumes `message.tool_calls`, and the docs warn that `/v1` can produce the reported JSON-text warning, but the issue still needs live confirmation of the reporter's active Ollama API, base URL, and runtime route before maintainers can decide whether this is unsupported configuration, a recovery/docs gap, or a native stream regression.

## What This Changes

The issue asks OpenClaw to consume Ollama's native `tool_calls` response field for local tool-using models instead of treating tool-call-shaped assistant text as an unreliable JSON-text fallback.

Confirm the user's actual `models.providers.ollama.api`, `baseUrl`, and emitted request URL with a live Ollama tool-call trace, then either document or improve the `/v1` recovery path or fix the native stream/runtime if it still drops structured tool calls.
