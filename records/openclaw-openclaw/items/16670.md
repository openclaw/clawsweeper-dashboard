## Summary

Keep open: current main still omits memory-embedding setup from onboarding/configure, while the requested mandatory policy remains unresolved; the original complete-memory-loss framing is now too broad because builtin keyword search works without embeddings.

## What This Changes

Add a dedicated onboarding step that configures a memory embedding provider, model, credential, and readiness check, preferably as a mandatory step.

## Best Possible Solution

Add a prominent, skippable Memory setup section that explains keyword-only versus semantic recall, reuses existing provider credentials or SecretRefs when valid, supports local providers, and offers a bounded readiness check with clear remediation.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should first-run onboarding require a working embedding provider, prominently offer it with an explicit skip, or leave embedding setup to diagnostics and later configuration?

Rationale: Current behavior supports keyword recall without embeddings, while mandatory remote credential collection, local-provider setup, SecretRef storage, and network probing each carry product and security tradeoffs that code inspection cannot decide.

Likely owner: Takhoffman

Owner reason: They are the assigned issue contact and already requested implementation follow-up, making them the best available owner for this product-policy choice.

Owner confidence: high

Options:

- **Prominent optional setup (recommended):** Add a first-class Memory step with provider, credential or SecretRef, and readiness guidance while allowing users to continue with clearly explained keyword-only recall.
- **Mandatory embedding gate:** Require a successful remote or local embedding configuration before onboarding completes, accepting the added credential, network, and setup burden.
- **Diagnostics only:** Keep onboarding unchanged and rely on doctor, memory status, and documentation to guide users after setup.

## Reproduction Assessment

Yes for the onboarding gap: current setup and configure documentation expose no memory-embedding section. No for the claimed complete loss of memory, because current builtin memory retains keyword search without embeddings.

## Solution Assessment

No—the mandatory gate is not yet established as the best solution. A prominent optional step with explicit keyword-only behavior, secure credential handling, and a bounded readiness check is the safer default pending maintainer direction.
