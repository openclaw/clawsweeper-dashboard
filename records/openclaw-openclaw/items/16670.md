## Summary

Keep open: current main and the latest release still lack a first-run or configure path for memory embedding provider/API-key readiness, while the mandatory-versus-optional setup policy remains a product decision.

## What This Changes

The issue requests making memory embedding provider and API-key setup a prominent mandatory onboarding wizard step.

## Best Possible Solution

Add a maintainer-approved memory setup/readiness path in onboarding and configure that uses the existing memorySearch and SecretRef/API-key surfaces, verifies readiness, and documents whether the step is mandatory, prominently optional, or diagnostic-only.

Options:

- **Prominent Optional Setup (recommended):** Add a visible but skippable memory setup/readiness step that configures existing memorySearch provider/model and API-key or SecretRef fields, then points users to memory status verification.
- **Mandatory Memory Gate:** Require users to configure embeddings or explicitly choose FTS-only before onboarding completes, improving recall readiness at the cost of setup friction and provider dependency.
- **Diagnostic Only:** Keep onboarding lean and rely on memory status, doctor, and docs, accepting that some users may discover memory readiness only after first use.
