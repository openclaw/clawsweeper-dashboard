## Summary

Keep open: current main and latest release still lack a dedicated memory embedding setup path in setup/onboarding/configure, and the requested mandatory behavior needs maintainer product judgment before implementation.

## What This Changes

The issue requests making memory embedding provider/model/API-key setup a mandatory part of the onboarding/setup wizard.

## Best Possible Solution

Add a maintainer-approved memory setup/readiness path in CLI onboarding and openclaw configure that configures agents.defaults.memorySearch safely, verifies readiness, and documents the chosen mandatory-versus-optional policy.

## Reproduction Assessment

Yes at source level: current setup, onboarding, and configure flows have no dedicated memorySearch section, credential prompt, or embedding readiness probe. I did not run a live wizard because read-only source inspection is enough to confirm the missing surface.

## Solution Assessment

Partly: a first-class memory setup/readiness flow is the maintainable direction, but making it universally mandatory is not established across local, FTS-only, provider-specific, and headless setup modes.
