## Summary

Keep open: current main and the latest release still lack a dedicated memory embedding provider/model/API-key or SecretRef step in setup, onboarding, or configure, and the request to make it mandatory remains a product/credential-UX decision.

## What This Changes

The issue requests making memory embedding provider, model, API-key, and readiness setup a mandatory or prominent onboarding step.

## Best Possible Solution

Add a maintainer-approved memory setup/readiness flow in CLI onboarding and openclaw configure that writes agents.defaults.memorySearch, handles API-key or SecretRef input safely, verifies readiness, and documents the chosen mandatory-versus-optional policy.

## Reproduction Assessment

Yes, at source level: current setup, onboarding, and configure flows have no dedicated memorySearch section, credential prompt, or embedding readiness probe. I did not run a live wizard because the read-only source path and release-tag comparison are enough to confirm the missing surface.

## Solution Assessment

Partly: a first-class memory setup/readiness flow is the maintainable direction, but making it universally mandatory is not yet established across local, FTS-only, provider-specific, and headless setup modes.
