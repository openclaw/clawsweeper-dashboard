## Summary

Keep open: current main still lacks a dedicated memory embedding setup/readiness path in setup, classic onboarding, configure, and the new Crestodian default onboarding; the mandatory-versus-optional policy remains a maintainer product decision.

## What This Changes

Request to add a prominent or mandatory onboarding step that configures memorySearch embedding provider/model credentials and verifies embedding readiness.

## Best Possible Solution

Add a maintainer-approved memory setup/readiness path in onboarding and configure that writes existing memorySearch or SecretRef config, verifies readiness, and documents the chosen mandatory-versus-optional policy.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should first-run onboarding/configure treat memory embedding setup as mandatory, prominently optional, or diagnostic-only, and what credential/probe UX should it use?

Rationale: The source gap is clear, but making embeddings mandatory can change first-run success, credential storage, provider cost, and daemon environment expectations, which are product and security-adjacent choices rather than a mechanical bug fix.

Likely owner: Takhoffman

Owner reason: Takhoffman is the current issue assignee and participated in the product-scope discussion on this exact report.

Owner confidence: medium

Options:

- **Prominent Optional Setup (recommended):** Add a visible but skippable memory setup/readiness path that configures existing memorySearch provider/model and SecretRef or API-key fields, then verifies with a probe or memory status guidance.
- **Mandatory Gate:** Require users to configure embeddings or deliberately choose FTS-only before completing onboarding, maximizing recall readiness at the cost of first-run friction and provider dependency.
- **Diagnostic Only:** Keep onboarding lean and rely on doctor, status, and Crestodian repair guidance, accepting that some users may still miss memory readiness until later.

## Reproduction Assessment

Yes at source level: current setup, classic onboarding, configure, and Crestodian setup lack a dedicated memorySearch credential or readiness step. I did not run the wizard because this review is read-only and source inspection is enough to confirm the missing surface.

## Solution Assessment

Partly: a first-class memory setup/readiness flow is the maintainable direction, but making it universally mandatory is not established across local, FTS-only, provider-specific, and headless setup modes.
