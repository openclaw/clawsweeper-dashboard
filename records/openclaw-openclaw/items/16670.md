## Summary

Keep open: current main and the latest release still do not provide a dedicated memory embedding setup path in setup, onboarding, or configure, and making that step mandatory remains a maintainer product decision.

## What This Changes

The issue requests a mandatory onboarding/setup step for configuring memory search embedding provider, model, credentials, and readiness verification.

## Best Possible Solution

Add a maintainer-approved memory setup/readiness flow in CLI onboarding and openclaw configure that writes agents.defaults.memorySearch, handles API-key or SecretRef input safely, verifies readiness, and documents the chosen mandatory-versus-optional policy.

## Reproduction Assessment

Yes at source level: current setup, onboarding, and configure flows have no dedicated memorySearch section, credential prompt, or embedding readiness probe. I did not run a live wizard because the read-only source path is enough to confirm the missing surface.

## Solution Assessment

Partly: a first-class memory setup/readiness flow is the maintainable direction, but making it universally mandatory is not yet established across local, FTS-only, provider-specific, and headless setup modes.
