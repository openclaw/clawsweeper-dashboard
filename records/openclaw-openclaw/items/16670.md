## Summary

Keep open: current main and the latest release still lack a dedicated memory embedding setup path in setup/onboarding/configure, and making that step mandatory remains a maintainer product decision rather than a cleanup close.

## What This Changes

The issue requests making memory embedding provider setup a prominent mandatory step in onboarding.

## Best Possible Solution

Add a maintainer-approved memory setup/readiness path in CLI onboarding and openclaw configure that safely configures agents.defaults.memorySearch and documents the chosen mandatory-versus-optional policy.

## Reproduction Assessment

Yes at source level: setup, onboarding, and configure still have no dedicated memorySearch section, credential prompt, or embedding readiness probe. I did not run a live wizard because read-only source inspection is enough to confirm the missing surface.

## Solution Assessment

Partly: a first-class memory setup/readiness flow is the maintainable direction, but making it universally mandatory is not established across local, FTS-only, provider-specific, and headless setup modes.
