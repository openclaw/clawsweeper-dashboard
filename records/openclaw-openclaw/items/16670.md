## Summary

Keep open: current main and the latest stable release still lack a dedicated memory embedding setup path in setup, onboarding, or configure, and making that step mandatory remains a product decision.

## What This Changes

Request to add a prominent or mandatory onboarding/configure step for `agents.defaults.memorySearch` provider, model, API-key or SecretRef setup, plus embedding readiness verification.

## Best Possible Solution

Add a maintainer-approved memory setup/readiness flow in CLI onboarding and `openclaw configure` that writes existing `agents.defaults.memorySearch` settings, handles API-key or SecretRef input safely, verifies readiness, and documents the chosen policy.

## Reproduction Assessment

Yes at source level: current setup, onboarding, and configure flows have no dedicated memorySearch section, credential prompt, or embedding readiness probe; no live wizard run was needed for this read-only review.

## Solution Assessment

Partly: a first-class memory setup/readiness flow fits the gap, but mandatory onboarding behavior still needs maintainer policy across local, FTS-only, provider-specific, and headless modes.
