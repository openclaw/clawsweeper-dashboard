## Summary

Keep open: current main and the latest release still lack a dedicated memory embedding setup path in setup, onboarding, or configure, and the requested mandatory behavior remains a maintainer product decision.

## What This Changes

The issue requests making memory embedding provider, model, API-key or SecretRef setup a prominent or mandatory onboarding step.

## Best Possible Solution

Add a maintainer-approved memory setup/readiness flow in CLI onboarding and openclaw configure that writes existing agents.defaults.memorySearch settings, handles API-key or SecretRef input safely, verifies readiness, and documents the chosen mandatory-versus-optional policy.

## Reproduction Assessment

Yes at source level: current setup, onboarding, and configure flows have no dedicated memorySearch section, credential prompt, or embedding readiness probe. I did not run a live wizard because read-only source inspection is sufficient to confirm the missing surface.

## Solution Assessment

Partly: a first-class memory setup/readiness flow is likely the maintainable direction, but making it universally mandatory is not yet established across local, FTS-only, provider-specific, and headless setup modes.
