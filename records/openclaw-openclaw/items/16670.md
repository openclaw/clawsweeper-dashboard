## Summary

Keep open: current main still lacks a memory embedding setup/readiness path, and the unresolved mandatory-versus-optional onboarding policy is a product decision rather than conservative cleanup.

## What This Changes

The issue requests making memory embedding provider, model, API-key or SecretRef setup a prominent or mandatory onboarding wizard step so cross-session memory does not silently fail when embeddings are unconfigured.

## Best Possible Solution

Add a maintainer-approved memory setup/readiness path in onboarding and configure that writes existing memorySearch or SecretRef config, verifies readiness, and documents the chosen mandatory-versus-optional policy.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should first-run onboarding and configure treat memory embedding setup as mandatory, prominently optional, or diagnostic-only, and what credential/probe UX should it use?

Rationale: The missing setup surface is clear in current main, but making embeddings mandatory changes first-run success, credential storage, provider cost, daemon environment expectations, and FTS-only/local workflows, which require maintainer product judgment.

Likely owner: Takhoffman

Owner reason: Takhoffman is the current issue assignee and participated in the product-scope discussion on this exact report.

Owner confidence: medium

Options:

- **Prominent Optional Setup (recommended):** Add a visible but skippable memory setup/readiness path that configures existing memorySearch provider/model and SecretRef or API-key fields, then verifies with a probe or memory status guidance.
- **Mandatory Memory Gate:** Require users to configure embeddings or explicitly choose FTS-only before completing onboarding, improving recall readiness at the cost of first-run friction and provider dependency.
- **Diagnostic Only:** Keep onboarding lean and rely on doctor, status, and Crestodian repair guidance, accepting that some users may still miss memory readiness until later.

Yes. Source inspection shows setup, classic onboarding, configure, and Crestodian setup lack a dedicated memorySearch credential or readiness step; I did not run the interactive wizard because this read-only review can confirm the missing surface from the orchestrators and section allowlist.

## Solution Assessment

Partly. A first-class memory setup/readiness flow is the maintainable direction, but making it universally mandatory is not established across local, FTS-only, provider-specific, and headless setup modes.
