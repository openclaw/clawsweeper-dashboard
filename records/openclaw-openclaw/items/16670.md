## Summary

Keep open: current main and v2026.6.11 still have memory docs, doctor guidance, and deep status probes, but setup/onboarding/configure do not provide a dedicated memory embedding provider/model/API-key or SecretRef setup path. The mandatory-vs-optional policy remains a maintainer product decision.

## What This Changes

The issue requests adding memory/embedding provider setup to onboarding so memory search is configured and verified during first-run setup.

## Best Possible Solution

Add a maintainer-approved memory setup/readiness path in CLI onboarding and openclaw configure that configures existing agents.defaults.memorySearch safely, verifies readiness, and documents the chosen mandatory-versus-optional policy.

## Reproduction Assessment

Yes, at source level: current setup, onboarding, and configure flows have no dedicated memorySearch section, credential prompt, or embedding readiness probe. I did not run the live wizard because read-only source inspection is enough to confirm the missing surface.

## Solution Assessment

Partly: a first-class memory setup/readiness path is the maintainable direction, but making it universally mandatory is not yet established across local, FTS-only, provider-specific, and headless setup modes.
