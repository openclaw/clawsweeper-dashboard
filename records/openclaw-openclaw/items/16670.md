## Summary

Keep open: current main still has memory configuration docs and diagnostics, but first-run onboarding and `openclaw configure` still lack a dedicated memory embedding provider/model/API-key or SecretRef setup path, and the mandatory-versus-optional behavior is a product decision.

## What This Changes

The issue requests a prominent, possibly mandatory onboarding step to configure and verify memory embedding setup for `memorySearch`.

## Best Possible Solution

Add a maintainer-approved memory setup/readiness path in onboarding and `openclaw configure` that uses the existing `memorySearch` and SecretRef surfaces, verifies readiness, and documents the chosen mandatory-versus-optional policy.

- **Prominent Optional Setup (recommended):** Add a visible skippable memory setup/readiness path that configures the existing provider/model and SecretRef or API-key fields, then verifies with a probe or memory status guidance.
