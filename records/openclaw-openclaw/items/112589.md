## What This Changes

This PR adds lease-authorized Gateway methods for external orchestrators to spawn subagents and read their session status, history, and metadata through a new persisted runtime contract.

## System Context

External orchestrators connect to the Gateway and request a lease before spawning a subagent; the Gateway authorizes the request, invokes the existing child-session runner, and projects the accepted session through list, status, and history reads. The PR also exposes this contract through the tools catalog and stores lease/replay/session snapshots in OpenClaw’s shared state database.

## Architecture Diagram

flowchart LR
  Client[External orchestrator] --> Gateway[Gateway RPC methods]
  Gateway --> Lease[Lease authorization and replay checks]
  Lease --> Runner[Existing subagent runner]
  Runner --> State[Shared SQLite runtime snapshot]
  State --> Reads[Session list status history]
  Gateway --> Catalog[Machine-readable capability catalog]

## Best Possible Solution

First decide whether lease-bound orchestration belongs in the core Gateway protocol or behind a plugin-specific integration seam; if core is approved, reduce it to a documented stable generic contract, correct the catalog metadata, and provide fresh-install plus restart/upgrade evidence for the persisted state.
