## Label Justifications

- `P2`: This is a normal-priority TUI ergonomics and multi-agent routing improvement with limited blast radius, not an urgent regression or crash.
- `impact:session-state`: The requested selector changes which agent session and workspace context the TUI attaches to at startup.

## Summary

Keep open: current main and latest release still do not expose a native `openclaw tui --agent <id>` startup selector. Existing full agent-scoped session keys, cwd workspace inference, and post-launch `/agent` switching are useful related paths, but they do not satisfy the requested arbitrary-directory startup flag.

## What This Changes

The issue requests a native `openclaw tui --agent <id>` startup flag so the TUI can start directly against a configured non-default agent from arbitrary directories.

## Best Possible Solution

Ship a focused additive TUI CLI design that validates `--agent <id>`, threads a typed startup agent id through TUI startup, preserves existing session/workspace behavior, and updates focused tests plus public TUI docs after precedence is decided.

## Reproduction Assessment

Yes. Source inspection on current main shows there is no `openclaw tui --agent` flag or startup-agent option, and the startup resolver cannot take an explicit agent id.

## Solution Assessment

Yes, if maintainers confirm the public CLI direction. A native startup selector is the maintainable user-facing surface for arbitrary directories, but it should be additive, validated, and explicit about precedence rather than treating two-part `agent:<id>` shorthand as a hidden alias.
