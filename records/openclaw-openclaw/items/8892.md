## Summary

Keep open: current main and the latest release still lack a native `openclaw tui --agent <id>` startup selector, and the existing agent-scoped session keys, cwd workspace inference, and post-launch `/agent` command do not fully cover arbitrary-directory startup selection.

## What This Changes

Requests a native `openclaw tui --agent <id>` startup flag that opens the TUI against a selected configured agent instead of relying on session names, cwd inference, or post-launch switching.

## Best Possible Solution

Ship a focused additive TUI CLI design that validates `--agent <id>`, threads a typed startup agent id through startup routing, preserves existing session and workspace behavior, and updates focused tests plus public TUI docs after precedence is decided.
