## Summary

Keep open: current main and v2026.6.11 provide agent-scoped session keys, workspace inference, and post-launch switching, but still lack the requested ergonomic `openclaw tui --agent <id>` startup selector. The remaining work is small, but adding a parallel public CLI selector requires a maintainer decision about whether it is worthwhile and how it interacts with existing startup-selection mechanisms.

## What This Changes

Add an `openclaw tui --agent <id>` option that starts the TUI with the selected agent’s model, workspace, persona, and session context.

## Best Possible Solution

Add `--agent <id>` only as a validated ergonomic front end to the canonical agent-scoped session path, with explicit conflict handling and precedence over workspace inference rather than introducing a second routing implementation.
