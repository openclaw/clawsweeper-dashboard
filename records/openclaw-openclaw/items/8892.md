## Label Justifications

- `P2`: This is a normal-priority TUI and multi-agent routing improvement with clear user value but limited blast radius.
- `impact:session-state`: The requested selector determines which agent session, workspace context, and remembered-session state the TUI attaches to at startup.
- `impact:auth-provider`: Selecting a different startup agent can change the first-turn model, provider, and auth profile routing.

## Summary

Keep open: current main and latest release still do not provide a native `openclaw tui --agent <id>` startup selector. The existing agent-scoped session keys, cwd workspace inference, and post-launch `/agent <id>` command are useful partial paths, but they do not cover starting the TUI against a chosen agent from an arbitrary directory.

## What This Changes

Request to add `openclaw tui --agent <id>` so a TUI session starts against a selected configured agent and uses that agent's model, workspace, context, and routing.

## Best Possible Solution

Ship a focused additive TUI CLI design that validates `--agent <id>`, threads a typed startup agent id through TUI startup, preserves existing session/workspace behavior, and updates focused tests plus public TUI docs after precedence is decided.
