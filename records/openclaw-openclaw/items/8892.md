## Label Justifications

- `P2`: This is a normal-priority TUI and multi-agent routing improvement with clear user value but limited blast radius.
- `impact:session-state`: The requested selector determines which agent session, workspace context, and remembered-session scope the TUI attaches to at startup.

## Summary

Keep open: current main and the latest release still do not provide a native `openclaw tui --agent <id>` startup selector. Agent-scoped session keys, cwd workspace inference, and post-launch `/agent <id>` switching are useful partial paths, but they do not satisfy the requested arbitrary-directory startup flag.

## What This Changes

Add a TUI startup flag that selects which configured agent handles the session, model/provider routing, and workspace context.

## Best Possible Solution

Add an additive `openclaw tui --agent <id>` startup selector after defining precedence, then thread the typed agent id through TUI startup and update focused TUI tests plus public TUI docs.

## Reproduction Assessment

Yes. Source inspection on current main and `v2026.6.11` shows `openclaw tui` has no `--agent` option, the TUI option type cannot carry one, and startup resolution only considers canonical agent-scoped session keys, cwd workspace inference, and the default agent.

## Solution Assessment

Yes, if maintainers confirm the public CLI direction. A native additive startup selector is the maintainable user-facing surface for arbitrary directories, but the precedence and routing semantics need product review first.
