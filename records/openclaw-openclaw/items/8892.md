## Summary

Current main solves the central request without a dedicated alias: a canonical `--session agent:<id>:<session>` value selects that agent at TUI startup, while launching inside a configured agent workspace also infers the agent. The dedicated `--agent` spelling remains absent, but the ability to open an interactive TUI with a non-default agent is implemented and shipped.

## What This Changes

Request a TUI startup flag that selects a configured agent and uses that agent’s model, workspace, and persona context.

## Best Possible Solution

Keep the canonical agent-scoped session key as the single startup-routing contract and improve its examples or validation if discoverability remains a concern, rather than adding a second overlapping selector.
