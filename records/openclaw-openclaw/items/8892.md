- `impact:session-state`: The requested selector determines which agent session, workspace context, and remembered-session state the TUI attaches to at startup.

## Summary

Keep open: current main and the latest release still do not provide a native `openclaw tui --agent <id>` startup selector. Existing agent-scoped session keys, cwd workspace inference, remembered sessions, and post-launch `/agent <id>` switching are useful but do not cover the requested arbitrary-directory startup flag.

## What This Changes

Request to add a native `openclaw tui --agent <id>` startup selector so the TUI starts on a selected agent's model, workspace, context, and session ownership.

## Best Possible Solution

Ship a focused additive TUI CLI design that validates `--agent <id>`, threads a typed startup agent id through TUI startup, preserves existing session/workspace behavior, and updates focused tests plus public TUI docs after precedence is decided.

## Reproduction Assessment

Yes. Source inspection on current main and `v2026.6.11` shows `openclaw tui` has no `--agent` option, the TUI option type cannot carry one, and startup resolution only considers canonical agent-scoped session keys, cwd workspace inference, and the default agent.

## Solution Assessment

Yes, if maintainers confirm the public CLI direction. A native additive startup selector is the maintainable user-facing surface for arbitrary directories, but precedence and routing semantics need product review first.
