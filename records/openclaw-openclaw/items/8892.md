## Summary

Keep open: current main and v2026.6.11 still lack the requested native startup selector, while existing agent-scoped session keys, workspace inference, remembered state, and post-launch switching do not provide the same explicit generic-directory CLI workflow. The implementation is bounded, but the public precedence rules require maintainer product approval.

## What This Changes

Add a TUI startup `--agent <id>` selector so a configured non-default agent owns the session, model, workspace, and context.

## Best Possible Solution

Add one validated startup agent selector at the CLI/TUI boundary, let it override cwd inference, reject conflicts with an agent-scoped session key, and preserve existing canonical session-key and interactive switching behavior.
