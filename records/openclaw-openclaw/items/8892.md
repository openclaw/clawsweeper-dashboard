## Summary

Keep open: current main and the latest release still lack a native `openclaw tui --agent <id>` startup selector, and the remaining work is a public CLI/session-routing product decision rather than conservative cleanup.

## What This Changes

Request a native `openclaw tui --agent <id>` flag so the initial TUI session is handled by a selected configured agent instead of the default agent.

## Best Possible Solution

Ship a focused additive TUI CLI design that validates `--agent <id>`, threads a typed startup agent id through startup, preserves existing session/workspace behavior, and updates focused tests plus public TUI docs after precedence is decided.
