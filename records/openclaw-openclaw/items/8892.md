## Summary

Keep open: current main and the latest release still lack a native `openclaw tui --agent <id>` startup selector, and the existing session-key, cwd workspace inference, and post-launch `/agent` paths only partially cover the requested arbitrary-directory startup workflow.

## What This Changes

Request adds an `openclaw tui --agent <id>` startup flag so the TUI begins on a selected configured agent with that agent's model, workspace, and context.

## Best Possible Solution

Ship a focused additive TUI startup selector after maintainers define precedence, validate unknown agent ids, preserve existing session/workspace behavior, and update focused tests plus public TUI docs.
