## Summary

Keep open: current main and the latest release still do not expose a native `openclaw tui --agent <id>` startup selector. Agent-scoped session keys, cwd workspace inference, and post-launch `/agent` switching are useful related paths, but they do not satisfy the requested arbitrary-directory startup flag.

## What This Changes

The issue requests a native `openclaw tui --agent <id>` startup selector so the TUI can launch directly against a configured non-default agent.

## Best Possible Solution

Ship a focused additive TUI CLI design that validates `--agent <id>`, threads a typed startup agent id through TUI startup, preserves existing session/workspace behavior, and updates focused tests plus public TUI docs after precedence is decided.

## Reproduction Assessment

Yes. Source inspection on current main shows `openclaw tui` has no `--agent` option, the TUI option type cannot carry one, and startup resolution only considers canonical agent-scoped session keys, cwd workspace inference, and the default agent.

## Solution Assessment

Yes, if maintainers confirm the public CLI direction. A native additive startup selector is the maintainable user-facing surface for arbitrary directories, but it should not be hidden in a two-part `agent:<id>` session alias.
