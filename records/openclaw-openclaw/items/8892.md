## Summary

Keep open: current main and the latest release still lack a native `openclaw tui --agent <id>` startup selector, while existing agent-scoped session keys, cwd inference, and `/agent` switching only partially cover the requested arbitrary-directory startup flow.

## What This Changes

Request to add `openclaw tui --agent <id>` so TUI startup can attach to a configured non-default agent.

## Best Possible Solution

Define an additive `openclaw tui --agent <id>` startup contract, validate the agent id, thread it through `TuiOptions` and `runTui`, preserve existing session/workspace behavior, and update focused TUI tests plus public docs.
