- `impact:auth-provider`: Selecting an agent changes the configured model and therefore can change the provider/auth profile used by the session.

## Summary

Keep this issue open for a maintainer product decision. The latest available review evidence says current TUI startup routing supports agent-scoped session keys, workspace-directory inference, and post-launch switching, but still lacks the requested explicit selector for starting a generic-directory TUI session on a chosen configured agent.

## What This Changes

Add `openclaw tui --agent <id>` so an interactive terminal session starts with the selected configured agent’s model, workspace, and project context.

## System Context

The TUI CLI collects startup options and opens an interactive session through the gateway or local runtime. Startup routing chooses an agent before the session resolves its model, workspace context, and persisted session state.

## Architecture Diagram

flowchart LR
  CLI[Terminal command] --> Options[TUI startup options]
  Options --> Selection[Choose initial agent]
  Session[Session key] --> Selection
  Workspace[Current workspace] --> Selection
  Selection --> Runtime[Agent runtime]
  Runtime --> Context[Model and workspace context]
  Context --> TUI[Interactive TUI session]

## Best Possible Solution

If maintainers sponsor the capability, add one typed and validated `--agent <id>` startup selector, document a single explicit precedence order, and cover selected-agent model/workspace/session routing without changing existing default startup behavior.
