## Label Justifications

- `P2`: This is a normal-priority TUI and multi-agent routing improvement with clear user value but limited blast radius.
- `impact:session-state`: The requested selector determines which agent session, workspace context, and remembered-session state the TUI attaches to at startup.

## Summary

Keep open: current main and the latest release still do not provide a native `openclaw tui --agent <id>` startup selector, and the remaining work is a public CLI/product decision rather than conservative cleanup.

## What This Changes

Request a TUI `--agent <id>` startup flag so a session can begin under a selected configured agent, model, workspace, and context instead of the default agent.

## Best Possible Solution

Ship a focused additive TUI CLI design that validates `--agent <id>`, threads a typed startup agent id through startup routing, preserves existing session and workspace behavior, and updates focused tests plus public TUI docs after precedence is decided.
