## Label Justifications

- `P2`: This is a normal-priority TUI and multi-agent routing improvement with clear user value but limited blast radius and existing partial workarounds.
- `impact:session-state`: The requested startup selector determines which agent session, workspace context, and remembered-session state the TUI attaches to at launch.
- `impact:auth-provider`: Selecting a different startup agent can change the first-turn model, provider, and auth profile routing.

## Summary

Keep open: current main and the latest release still lack a native `openclaw tui --agent <id>` startup selector, and the existing session-prefix, cwd workspace inference, and post-launch `/agent <id>` paths only cover partial workarounds.

## What This Changes

Request a native `openclaw tui --agent <id>` flag that starts the TUI against a selected configured agent, including that agent's model, workspace context, and auth/provider routing.

## Best Possible Solution

Ship an additive, validated TUI startup agent selector with explicit precedence semantics, focused TUI tests, and public docs once maintainers confirm the product behavior.

## Reproduction Assessment

Yes. Source inspection on current main and `v2026.6.11` shows no `openclaw tui --agent <id>` option, no `TuiOptions` carrier for it, and startup resolution only from canonical session keys, cwd workspace inference, or the default agent.

## Solution Assessment

Yes, if maintainers confirm the public CLI direction. A native additive startup selector is the narrow maintainable user-facing surface for arbitrary directories, but precedence and routing semantics need product review first.
