## Label Justifications

- `P2`: This is a bounded TUI ergonomics improvement with practical multi-agent impact but existing session-key, workspace, and in-TUI workarounds.
- `impact:session-state`: Startup selection determines which agent owns the TUI session key and transcript context.
- `impact:auth-provider`: Selecting the wrong startup agent can use a different configured model and provider routing chain than the user intended.
- `impact:ux-friction`: Users currently need a canonical agent-scoped session key, a matching workspace directory, or a post-launch switch instead of a direct startup selector.

## Summary

Keep open: current main supports agent-scoped session keys, workspace-based startup inference, and in-TUI agent switching, but it still has no dedicated `openclaw tui --agent <id>` selector. The remaining convenience feature is bounded, but adding a public CLI selector and defining its precedence requires TUI product-owner approval. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/cli/tui-cli.ts))

## What This Changes

Add an `--agent <id>` flag to start the TUI with a selected agent’s model, workspace, context, and session routing.

## Best Possible Solution

If the TUI owner approves the surface, add a validated `--agent <id>` selector whose explicit value wins over workspace inference, rejects conflicts with a differently scoped `--session`, and is covered in both CLI and startup-routing tests plus the TUI docs.
