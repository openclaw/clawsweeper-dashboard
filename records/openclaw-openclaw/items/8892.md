## Label Justifications

## Summary

Keep this issue open as the canonical request. Current main still offers workspace-based inference and explicit agent-scoped session keys, but it has no native `openclaw tui --agent <id>` startup selector; adding that selector is a public CLI routing decision that needs maintainer-set precedence.

## What This Changes

Add `openclaw tui --agent <id>` so an interactive TUI session starts on a selected configured agent and uses that agent’s model, workspace context, and session scope.

## System Context

The TUI CLI turns terminal options into an interactive chat connected to the Gateway or local runtime. Before chat starts, it chooses an agent, derives the session identity, then loads that agent’s model and workspace context.

## Architecture Diagram

flowchart LR
  A[Terminal command] --> B[TUI CLI options]
  B --> C[Startup agent selection]
  D[Session key and workspace] --> C
  C --> E[Interactive TUI session]
  E --> F[Gateway or local runtime]
  F --> G[Agent model and workspace context]

## Best Possible Solution

If maintainers approve the workflow, add one validated typed startup-agent selector resolved before session-key and workspace inference, document its precedence, and cover explicit selection, invalid ids, agent-scoped sessions, workspace inference, fresh sessions, and remembered-session behavior.
