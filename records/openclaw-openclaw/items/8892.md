## Label Justifications

- `P2`: This is a normal-priority TUI multi-agent routing improvement with limited blast radius, not an urgent regression or crash.
- `impact:session-state`: The requested selector changes which agent session and workspace context a TUI startup attaches to.
- `impact:auth-provider`: Selecting a different startup agent can change the model, provider, and auth profile used for the first TUI turn.

## Summary

Keep open: current main and the latest release still do not expose a native `openclaw tui --agent <id>` startup selector. Existing agent-scoped session keys, cwd workspace inference, and post-launch `/agent` switching are useful related paths, but they do not satisfy the requested arbitrary-directory startup flag.

## What This Changes

Add a native `openclaw tui --agent <id>` startup selector so a TUI session starts under a configured non-default agent's model, workspace, and context.

## Best Possible Solution

Ship a focused additive TUI CLI design that validates `--agent <id>`, threads a typed startup agent id through TUI startup, preserves existing session/workspace behavior, and updates focused tests plus public TUI docs after precedence is decided.

## Reproduction Assessment

Yes. Source inspection on current main shows `openclaw tui` has no `--agent` option, `TuiOptions` cannot carry one, and startup resolution only considers canonical agent-scoped session keys, cwd workspace inference, then the default agent.

## Solution Assessment

Yes, if maintainers confirm the public CLI direction. A native startup selector is the maintainable user-facing surface for arbitrary directories, but it should be additive, validated, and explicit about precedence rather than treating two-part `agent:<id>` shorthand as a hidden alias.
