## Summary

Keep open: current main and the latest release still do not provide a native `openclaw tui --agent <id>` startup selector, and the remaining work is a public CLI/product decision rather than conservative cleanup.

## What This Changes

Request to add `openclaw tui --agent <id>` so a TUI session starts against a selected configured agent instead of the default agent.

## Best Possible Solution

Ship a focused additive TUI CLI design that validates `--agent <id>`, threads a typed startup agent id through startup routing, preserves existing session and workspace behavior, and updates focused tests plus public TUI docs after precedence is decided.
