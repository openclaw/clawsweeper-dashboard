- `impact:session-state`: The requested selector determines which agent session, workspace context, and remembered-session state the TUI attaches to at startup.

## Summary

Keep open: current main and the latest release still do not provide a native `openclaw tui --agent <id>` startup selector. Existing agent-scoped session keys, cwd workspace inference, and post-launch `/agent <id>` switching are useful partial paths, but they do not fully satisfy selecting a configured agent from an arbitrary working directory at launch.

## What This Changes

Request a native `openclaw tui --agent <id>` flag that starts the TUI against a chosen configured agent, including that agent's model, workspace, and context.

## Best Possible Solution

Ship a focused additive TUI CLI design that validates `--agent <id>`, threads a typed startup agent id through TUI startup, preserves existing session/workspace behavior, and updates focused tests plus public TUI docs after precedence is decided.

## Reproduction Assessment

Yes. Source inspection on current main shows `openclaw tui` has no `--agent` option, the TUI option type cannot carry one, and startup resolution only considers canonical agent-scoped session keys, cwd workspace inference, and the default agent.

## Solution Assessment

Yes, if maintainers confirm the public CLI direction. A native additive startup selector is the maintainable user-facing surface for arbitrary directories, but precedence and routing semantics need product review first.
