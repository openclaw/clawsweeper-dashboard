## Summary

Keep open: current main and latest release still do not provide a native `openclaw tui --agent <id>` startup selector. Existing agent-scoped session keys, cwd workspace inference, and post-launch `/agent <id>` switching are useful workarounds, but they do not satisfy the requested arbitrary-directory startup flag and the issue is already labeled for maintainer product review.

## What This Changes

Request a native `openclaw tui --agent <id>` flag that starts the TUI directly against a selected configured agent, including that agent's model, workspace, and context.

## Best Possible Solution

Ship a focused additive TUI CLI design that validates `--agent <id>`, threads a typed startup agent id through TUI startup, preserves existing session/workspace behavior, and updates focused tests plus public TUI docs after precedence is decided.

## Reproduction Assessment

Yes. Source inspection on current main shows `openclaw tui` has no `--agent` option, the TUI option type cannot carry one, and startup resolution only considers canonical agent-scoped session keys, cwd workspace inference, and the default agent.

## Solution Assessment

Yes, subject to maintainer product confirmation. A native additive startup selector is the maintainable user-facing surface for arbitrary directories, but its precedence and routing semantics should be decided before implementation.
