## Summary

Keep open for a maintainer product decision: current TUI flows can start or switch to a non-default agent through an explicit agent-scoped session key and workspace inference, but they still do not provide the requested dedicated `--agent` CLI alias.

## What This Changes

The issue requests a public `openclaw tui --agent <id>` option to start an interactive TUI session with a configured non-default agent.

## Best Possible Solution

Keep the existing canonical agent-scoped session and workspace-inference paths; add `--agent` only if a maintainer explicitly wants a supported ergonomic alias with documented precedence and focused compatibility coverage.
