## Summary

Keep open: current main and latest release still do not provide a native `openclaw tui --agent <id>` startup selector. Existing agent-scoped session keys, cwd workspace inference, and post-launch `/agent <id>` switching are useful but do not fully cover the requested arbitrary-directory startup flag.

## What This Changes

The issue requests a new TUI startup flag, `openclaw tui --agent <id>`, to bind the interactive session to a configured non-default agent and its model, workspace, and context.

## Best Possible Solution

Ship a focused additive TUI CLI design that validates `--agent <id>`, threads a typed startup agent id through TUI startup, preserves existing session/workspace behavior, and updates focused tests plus public TUI docs after precedence is decided.

## Reproduction Assessment

Yes. Source inspection on current main shows `openclaw tui` has no `--agent` option, the TUI option type cannot carry one, and startup resolution only considers canonical agent-scoped session keys, cwd workspace inference, and the default agent.

## Solution Assessment

Yes, if maintainers confirm the public CLI direction. A native additive startup selector is the maintainable user-facing surface for arbitrary directories, but the precedence and routing semantics need product review first.
