- `P2`: This is a normal-priority TUI ergonomics and multi-agent routing improvement with limited blast radius, not an urgent regression or crash.
- `impact:session-state`: The requested selector changes which agent session and workspace context a TUI startup attaches to.

## Summary

Keep open: current main and latest release still lack a native `openclaw tui --agent <id>` startup selector. Agent-scoped session keys, cwd workspace inference, and post-launch `/agent` switching are useful related paths, but they do not satisfy the requested arbitrary-directory startup flag.

## What This Changes

Request to add `openclaw tui --agent <id>` so TUI startup can select a configured non-default agent, model/auth profile, session, and workspace context.

## Best Possible Solution

Ship a focused additive TUI CLI design that validates `--agent <id>`, threads a typed startup agent id through TUI startup, preserves existing session/workspace behavior, and updates focused tests plus public TUI docs after precedence is decided.

## Reproduction Assessment

Yes. Source inspection on current main shows `openclaw tui` has no `--agent` option, the TUI option type cannot carry one, and startup resolution only considers a canonical agent-scoped session key, cwd workspace inference, then the default agent.

## Solution Assessment

Yes, if maintainers confirm the public CLI direction. A native startup selector is the maintainable user-facing surface for arbitrary directories, but it should be additive, validated, and explicit about precedence rather than treating two-part `agent:<id>` shorthand as a hidden alias.
