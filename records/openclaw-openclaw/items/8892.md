## Label Justifications

- `P2`: This is a concrete, bounded multi-agent TUI improvement with limited blast radius, but current supported paths prevent it from being an urgent workflow failure.
- `impact:session-state`: The requested selector determines which agent identity, workspace, and agent-scoped session should own the interactive TUI conversation.
- `impact:auth-provider`: Selecting the wrong agent can select that agent’s configured model and provider routing rather than the intended configuration.
- `impact:ux-friction`: Users must discover and construct a three-part agent-scoped session key, use a matching workspace directory, or switch after launch instead of using the proposed intuitive flag.

## Summary

Keep open: current main supports direct non-default-agent TUI startup through canonical agent-scoped session keys, workspace inference, and in-TUI switching, but still lacks the requested dedicated `--agent` convenience flag. The remaining work is a bounded CLI ergonomics feature requiring product direction about whether another public selector is worthwhile.

## What This Changes

Add a native `openclaw tui --agent <id>` startup selector for a configured agent’s model, workspace, and session context.

## Best Possible Solution

Keep one durable startup-selection contract, preferably by improving discoverability of agent-scoped `--session` keys, or add `--agent` only as a validated shorthand with explicit conflict and precedence rules.

Rationale: The routing capability already exists, so adding another public CLI selector is an API and ergonomics choice rather than a missing runtime primitive.
