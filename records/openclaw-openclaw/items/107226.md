## Summary

Keep open: release v2026.7.1 can turn a working Codex-backed agent into a fail-every-turn state during routine update, and the linked open repair addresses only allowlist pruning while the reported readiness gap remains unresolved.

## What This Changes

Preserve or migrate Codex plugin intent during externalization upgrades and expose configured agents with missing harnesses through doctor and readiness diagnostics.

## Best Possible Solution

Doctor should preserve Codex intent, install the cohort-matched external plugin or present an in-product Fix action, verify registration with a real agent turn, keep liveness distinct, and visibly degrade detailed readiness/status for each configured agent whose required harness is unavailable.

- **Doctor-only enforcement:** Repair or block the configuration in doctor and startup while leaving gateway readiness semantics unchanged.
