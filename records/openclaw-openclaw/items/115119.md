## Summary

Keep this PR open for maintainer review. The proposed server-side fix consistently resolves an unassigned card to the configured default agent before building its per-agent SQLite session key and applying restricted-target checks, but the PR has only test/CI evidence and explicitly leaves the web UI “Run card” path with the same unscoped-key defect for a separate follow-up.

## What This Changes

The branch changes Workboard command and gateway dispatch so cards without an explicit agent run under the resolved default agent, with matching session storage and workspace authorization.

## System Context

Workboard accepts queued cards through commands and gateway methods, then launches a subagent worker. A worker’s session key selects its per-agent SQLite store, while workspace access selects its execution authority, so both must use the same resolved card owner.

## Architecture Diagram

flowchart LR
  A[Queued Workboard card] --> B[Command or gateway dispatch]
  B --> C[Resolve explicit or default agent]
  C --> D[Build agent-scoped session]
  C --> E[Resolve workspace authority]
  D --> F[Subagent worker run]
  E --> F
  F --> G[Card execution result]

## Best Possible Solution

Land the focused dispatcher repair once a redacted real Workboard dispatch proves that an unassigned card starts under a configured non-`main` default agent with matching session and workspace ownership, then track the UI-specific session-key path separately through the gateway-owned design.
