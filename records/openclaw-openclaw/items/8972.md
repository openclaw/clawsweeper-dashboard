## Summary

Keep open: current main and v2026.6.11 still treat Discord guild channel entries as exact id/name/slug keys, thread-parent fallbacks, or the literal `*`; glob keys like `ws-*` remain unimplemented and need a product/security decision.

## What This Changes

Request support for Discord guild channel allowlist patterns so dynamically created channels matching a glob can be admitted without per-channel config edits and restart churn.

## Best Possible Solution

Approve one Discord-owned pattern contract, then update the resolver/preflight path, exported types, Zod schema, docs/status/audit behavior, and focused tests while keeping category inheritance and hot reload separate.

## Reproduction Assessment

Yes. At source level, with a nonempty Discord guild `channels` map containing `ws-*`, a channel named `ws-task-1` has no exact id/name/slug, parent, or literal `*` match and resolves denied.

## Solution Assessment

Unclear until maintainers choose the permanent pattern syntax and authorization precedence. If approved, the narrowest maintainable path is a Discord-owned pattern tier in the existing allowlist resolver, not bundling category inheritance, hot reload, or sender access-list redesign into the same change.
