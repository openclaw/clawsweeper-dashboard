## Summary

Keep open: current main still treats Discord channel keys as exact id/name/slug entries plus the literal `*`, so pattern keys such as `ws-*` remain a missing authorization-sensitive config feature rather than an implemented behavior.

## What This Changes

The issue requests glob or wildcard pattern support for Discord guild channel allowlists so dynamically named channels can be covered without enumerating each channel ID.

## Best Possible Solution

Decide the public Discord channel authorization contract first, then implement a Discord-owned pattern matcher with explicit precedence, schema/docs/tests, and upgrade-safe examples if maintainers approve glob keys.
