## Summary

Keep open: current main and the latest release still treat Discord guild channel entries as exact id/name/slug, thread-parent, or literal `*` matches rather than glob patterns, and adding `ws-*` would change a security-sensitive message-ingress boundary.

## What This Changes

The issue requests glob or wildcard support for Discord guild channel allowlist entries so dynamically created channels can match without per-channel config edits and gateway restarts.

## Best Possible Solution

Keep this as the canonical Discord glob-pattern tracker and resolve it through a maintainer-approved allowlist contract covering syntax, precedence, schema/docs, audit/status behavior, and resolver/preflight tests.

Owner confidence: high

Options:

- **Approve narrow glob contract (recommended):** Add Discord-owned glob matching with explicit precedence, schema/types/docs, audit/status visibility, and focused ingress tests while keeping category inheritance and access-list redesign separate.
- **Defer to category/access redesign:** Keep this open but require maintainers to fold the dynamic-channel problem into https://github.com/openclaw/openclaw/issues/60582 or https://github.com/openclaw/openclaw/issues/69748 before implementation.
- **Reject new glob syntax:** Keep the exact-entry plus literal `*` model and document that dynamic workstreams should use the broad wildcard or the category/access-control trackers instead.

## Solution Assessment

Unclear until maintainers choose the public authorization contract. The implementation likely belongs in the Discord-owned allowlist/config path, but automation should not choose glob syntax, matching order, or security semantics on its own.
