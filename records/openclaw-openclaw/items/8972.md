## Summary

Keep open: current main and the latest release still resolve Discord guild channel entries as exact id/name/slug, thread-parent, normalized, or literal `*` matches, so glob keys such as `ws-*` remain an unresolved authorization-sensitive feature request.

## What This Changes

The issue requests Discord guild channel allowlist support for glob/wildcard keys such as `ws-*` so dynamically created matching channels can be admitted without per-channel config edits and gateway restarts.

## Best Possible Solution

Keep this as the canonical Discord glob-pattern tracker and resolve it through a maintainer-approved allowlist contract covering syntax, precedence, schema/docs, audit/status behavior, and resolver/preflight tests.

- **Fold into broader Discord access work:** Keep the dynamic-channel problem tied to https://github.com/openclaw/openclaw/issues/60582 or https://github.com/openclaw/openclaw/issues/69748 before implementation.
- **Reject glob syntax:** Keep exact entries plus the literal `*` model and document that dynamic workstreams should use broad wildcard, category inheritance, or future access-control work instead.
