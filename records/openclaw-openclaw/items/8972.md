## Summary

Keep open: current main and v2026.6.11 still support only exact channel id/name/slug matches, thread-parent fallback, and literal `*`; glob semantics remain distinct work and require a maintainer decision on authorization precedence.

## What This Changes

Add glob or wildcard matching to Discord guild channel allowlist entries so dynamically named channels can be admitted without per-channel config edits.

## Best Possible Solution

Adopt one documented Discord-owned glob contract reused by every authorization caller, with exact channel and thread-parent matches ahead of deterministic pattern matches and literal `*` last.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should Discord guild channel allowlists accept name globs, and if so what precedence and ambiguity rules should apply relative to exact channel, thread-parent, and literal `*` entries?

Rationale: The choice changes which Discord messages and interactions cross an authorization boundary, and several reasonable syntax and precedence designs cannot be selected safely from implementation evidence alone.

Likely owner: steipete

Owner reason: He introduced and unified the shared matcher whose authorization precedence would need to be extended or deliberately preserved.

Owner confidence: high

Options:

- **Add ordered name globs (recommended):** Support documented slug patterns after exact and thread-parent matching but before literal `*`, with deterministic specificity and explicit tie handling.
- **Prefer category inheritance:** Decline arbitrary name globs and use the category-level policy tracked by https://github.com/openclaw/openclaw/issues/60582 for dynamic channel groups.
- **Keep exact allowlists:** Retain exact id/name/slug entries plus literal `*` and require explicit configuration for each newly authorized channel.

## Reproduction Assessment

Yes, at source level: a configured `ws-*` key is treated as a literal record key and cannot match a `ws-task-1` channel through the current resolver. A live Discord run is unnecessary to establish this config behavior.

## Solution Assessment

Unclear pending maintainer intent: glob matching is a maintainable option only if one canonical Discord authorization matcher defines normalized input, precedence, ambiguity handling, audit metadata, and tests across all callers.
