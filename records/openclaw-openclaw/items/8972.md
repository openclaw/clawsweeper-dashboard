## Summary

Keep open: current main and the latest release still only support exact Discord channel keys, thread-parent fallback, and the literal `*` fallback, so glob keys remain missing and need maintainer product/security review.

## What This Changes

Request support for Discord channel allowlist entries that match dynamically created channels by glob/wildcard pattern instead of requiring exact channel entries and a gateway restart.

## Best Possible Solution

Approve and document one Discord-owned pattern contract, then update the resolver/preflight path, exported types, Zod schema, docs/status/audit behavior, and focused tests while keeping category inheritance and hot reload separate.

## Reproduction Assessment

Yes, at source level: with a nonempty Discord guild `channels` map containing `ws-*`, a channel named `ws-task-1` has no exact, normalized, parent, or literal `*` match and resolves denied. I did not run a live Discord repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the permanent pattern syntax and authorization precedence. If approved, the narrowest maintainable path is a Discord-owned pattern tier using the current config surface, not bundling category inheritance, hot reload, or sender access-list redesign into the same change.
