## Summary

Keep open: current main and v2026.6.11 still do not evaluate Discord guild channel keys as glob patterns, so `ws-*` remains unresolved authorization-sensitive product work rather than cleanup.

## What This Changes

Request adding glob or wildcard Discord guild channel allowlist entries such as `ws-*` so dynamically created matching channels can receive messages without per-channel config edits and restarts.

## Best Possible Solution

Keep this as the canonical Discord glob-pattern tracker until maintainers approve one allowlist contract covering syntax, precedence, schema/types/docs/status/audit behavior, and resolver/preflight tests.

Options:

- **Defer To Existing Redesigns:** Keep this open but require maintainers to fold the dynamic-channel problem into the category or access-control trackers before implementation.
- **Reject Glob Syntax:** Keep exact entries plus the literal `*` model and document that dynamic workstreams should use the broad wildcard or a separately approved category/access-control contract.

## Reproduction Assessment

Yes, at source level. A guild channel key like `ws-*` is never compared as a pattern against an incoming `ws-task-1` channel, so a non-empty channel map without an exact, parent, or literal `*` match resolves to denied.

## Solution Assessment

Unclear until maintainers choose the public authorization contract. The implementation likely belongs in the Discord-owned allowlist/config path, but automation should not choose glob syntax, matching order, or security semantics on its own.
