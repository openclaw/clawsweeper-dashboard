## Summary

Current main and the latest release still treat Discord channel keys as literal identifiers or names with parent and literal `*` fallback; no canonical replacement owns the distinct pattern request, and its authorization semantics still require maintainer direction.

## What This Changes

Add wildcard or glob-based Discord guild channel allowlist entries so dynamically created matching channels work without per-channel configuration changes.

## Best Possible Solution

Add an explicit Discord-owned pattern surface with deterministic authorization ordering, match metadata, schema/help/docs alignment, and regression coverage while preserving existing literal-key behavior.

Options:

- **Explicit Discord patterns (recommended):** Add a separate pattern map or typed pattern entries with deterministic ordering, denial behavior, documentation, and authorization tests.
- **Implicit glob keys:** Interpret wildcard characters in existing channel keys as patterns and accept the compatibility and ambiguity cost.
- **Keep exact-only:** Retain exact entries and literal `*`, using category inheritance or reload improvements for adjacent needs.
