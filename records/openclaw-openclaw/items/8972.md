## Summary

Keep open: current main and v2026.6.11 still lack Discord glob-pattern channel allowlist matching, and the remaining work changes an authorization-sensitive config surface that needs maintainer-approved syntax and precedence.

## What This Changes

Add glob or wildcard matching to Discord guild channel allowlist entries so dynamically created channels such as `ws-task-1` can be admitted without per-channel config edits.

## Best Possible Solution

Keep this as the canonical Discord glob-pattern tracker until maintainers approve one allowlist contract covering syntax, precedence, schema/docs, audit/status behavior, and resolver/preflight tests while keeping category inheritance and hot-reload issues separate.

## Reproduction Assessment

Yes, at source level. A guild channel key like `ws-*` is never compared as a pattern against an incoming `ws-task-1` channel, so a non-empty channel map without an exact, parent, or literal `*` match resolves to denied.

## Solution Assessment

Unclear until maintainers choose the public authorization contract. The implementation likely belongs in the Discord-owned allowlist/config path, but automation should not choose glob syntax, matching order, or security semantics on its own.
