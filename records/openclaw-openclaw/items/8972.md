## Summary

Current main and v2026.6.11 still interpret Discord guild channel keys as exact identifiers/names with thread-parent and literal `*` fallback only. No open or merged canonical issue or PR owns arbitrary pattern matching, and because this changes a stable channel’s inbound authorization semantics, it should remain open for an explicit maintainer security/product decision.

## What This Changes

Add glob or wildcard-based Discord guild channel allowlist entries so dynamically created matching channels can receive messages without per-channel config edits.

## Best Possible Solution

If maintainers approve this capability, add a dedicated Discord-owned pattern surface rather than silently globbing existing channel keys, with exact and thread-parent matches ahead of deterministic pattern matches, literal `*` last, visible match metadata, aligned type/schema/docs/status behavior, and focused allow/deny tests.
