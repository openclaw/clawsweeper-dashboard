## Summary

Keep open: current main and v2026.6.11 still only support exact Discord guild channel entries, thread-parent fallback, and the literal `*`; glob keys such as `ws-*` remain an unresolved authorization-sensitive config feature.

## What This Changes

Requests glob or wildcard pattern support for Discord guild channel allowlists so dynamically created matching channels can be admitted without per-channel config edits.

## Best Possible Solution

Keep this as the canonical Discord glob-pattern tracker until maintainers approve one allowlist contract covering syntax, precedence, config/schema/docs, audit/status behavior, and resolver/preflight tests.

- **Reject Glob Syntax:** Keep exact entries plus literal `*` and document that dynamic workflows should use wildcard, category inheritance, or another approved access-control design instead.

## Reproduction Assessment

Yes, at source level. A guild channel key like `ws-*` is never compared as a pattern against an incoming `ws-task-1` channel, so a non-empty channel map without an exact, parent, or literal `*` match resolves to denied.

## Solution Assessment

Unclear until maintainers choose the public authorization contract. The implementation likely belongs in the Discord-owned allowlist/config path, but automation should not choose glob syntax, matching order, or security semantics on its own.
