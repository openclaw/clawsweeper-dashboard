## Summary

Keep open: current main and v2026.6.11 still treat Discord guild channel keys as exact id/name/slug entries, thread-parent fallbacks, or the literal `*`; glob keys such as `ws-*` remain an unresolved authorization-sensitive feature.

## What This Changes

Add glob or wildcard pattern support to Discord guild channel allowlists so dynamically created matching channels can be authorized without per-channel config edits.

## Best Possible Solution

Keep this as the canonical Discord glob-pattern tracker until maintainers approve syntax and precedence, then implement it in the Discord allowlist/config contract with schema, docs, audit/status visibility, and ingress tests.

- **Reject Glob Syntax:** Keep exact entries plus the literal `*` model and document that dynamic workstreams should use broad wildcard, category inheritance, or another approved access-control design instead.

## Reproduction Assessment

Yes, at source level. A guild channel key like `ws-*` is never compared as a pattern against an incoming `ws-task-1` channel, so a non-empty channel map without an exact, parent, or literal `*` match resolves to denied.

## Solution Assessment

Unclear until maintainers choose the public authorization contract. The implementation likely belongs in the Discord-owned allowlist/config path, but automation should not choose glob syntax, matching order, or security semantics on its own.
