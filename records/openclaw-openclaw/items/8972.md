## Summary

Keep open: current main and the latest release still treat Discord guild channel keys as exact id/name/slug, parent, or literal `*` matches; glob keys such as `ws-*` remain unimplemented and need an explicit security/product decision before changing message ingress authorization.

## What This Changes

Request support for Discord guild channel allowlist entries that match dynamic channel names by glob or wildcard pattern.

## Best Possible Solution

Approve and document one Discord-owned pattern contract, then update the resolver/preflight path, exported types, Zod schema, docs/status/audit behavior, and focused tests while keeping category inheritance and hot reload as separate scopes.

## Reproduction Assessment

Yes, at source level: with a nonempty Discord guild `channels` map containing `ws-*`, a channel named `ws-task-1` has no exact, normalized, parent, or literal `*` match and resolves denied. I did not run a live Discord repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the permanent pattern syntax and authorization precedence. If approved, the narrow path is a Discord-owned pattern tier in the current allowlist resolver, not bundling category inheritance, hot reload, or sender access-list redesign into the same change.
