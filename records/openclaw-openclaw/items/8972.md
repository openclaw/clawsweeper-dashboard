## Summary

Keep open: current main still resolves Discord guild channel entries by exact id/name/slug, thread-parent fallback, and literal `*`; glob keys remain unimplemented and need a maintainer product/security decision.

## What This Changes

The issue requests glob or wildcard Discord guild channel allowlist entries so dynamically created channels can be admitted without per-channel config edits and restarts.

## Best Possible Solution

Approve and document one Discord-owned pattern contract, then update the resolver/preflight path, exported types, Zod schema, docs/status/audit behavior, and focused tests while keeping category inheritance and hot reload separate.

## Reproduction Assessment

Yes, at source level: with a nonempty Discord guild `channels` map containing `ws-*`, a channel named `ws-task-1` has no exact, normalized, parent, or literal `*` match and resolves denied. I did not run a live Discord repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the permanent pattern syntax and authorization precedence. If approved, the narrowest maintainable path is a Discord-owned pattern tier in the existing allowlist resolver, not bundling category inheritance, hot reload, or sender access-list redesign into the same change.
