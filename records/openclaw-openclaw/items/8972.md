## Summary

Keep open: current main and v2026.6.11 still resolve Discord guild channel allowlist entries by exact id/name/slug, one parent fallback, and literal `*`; the requested glob syntax remains missing and changes an authorization boundary that needs maintainer product/security review.

## What This Changes

The issue requests glob or wildcard support in Discord guild channel allowlist keys so dynamically created Discord channels can be admitted without per-channel config edits and restarts.

## Best Possible Solution

Maintain the issue as the glob-pattern tracker and resolve it through a maintainer-approved Discord allowlist contract that defines pattern syntax, precedence, schema/docs, and focused resolver/preflight tests.

## Reproduction Assessment

Yes, at source level: a guild channel key like `ws-*` is not compared as a pattern against an incoming `ws-task-1` channel, so a non-empty channel map without an exact, parent, or literal `*` match resolves to denied. I did not run a live Discord repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public authorization contract. The implementation should live in the Discord-owned allowlist/config path, but automation should not choose glob syntax, matching order, or security semantics on its own.
