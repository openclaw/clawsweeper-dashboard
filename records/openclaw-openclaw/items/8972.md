## Label Justifications

- `impact:security`: The requested pattern syntax would change which Discord guild channels are authorized to deliver messages to agents.
- `impact:message-loss`: Messages from intended dynamically created channels remain denied unless each channel is listed exactly or the broad literal wildcard is used.

## Summary

Keep open: current main and the latest stable release still treat Discord guild channel keys as exact id/name/slug entries, thread-parent fallbacks, or the literal `*` fallback; a key like `ws-*` is not evaluated as a glob, and adding that behavior changes a security-sensitive message-ingress boundary.

## What This Changes

The issue requests Discord guild channel allowlist glob or wildcard support so dynamically created channels can be admitted without per-channel config edits and gateway restarts.

## Best Possible Solution

Keep this issue open as the canonical Discord glob-pattern tracker and resolve it through a maintainer-approved allowlist contract covering syntax, precedence, schema/docs, audit/status behavior, and resolver/preflight tests.
