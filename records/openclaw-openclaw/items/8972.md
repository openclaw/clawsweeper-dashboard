## Summary

Keep open: current main and the latest release still match Discord guild channels by exact id/name/slug, thread parent, and literal `*`; the requested glob syntax remains missing and needs a security-sensitive config/product decision.

## What This Changes

Request support for Discord guild channel allowlist glob or wildcard patterns so dynamic Discord channels can be admitted without per-channel config edits and gateway restarts.

## Best Possible Solution

Approve and document one Discord-owned pattern contract, then update the resolver, preflight/status/audit surfaces, exported types, Zod schema, docs, and focused tests while keeping category inheritance and hot reload as separate decisions.

## Reproduction Assessment

Yes, at source level: with a nonempty Discord guild `channels` map containing `ws-*`, a channel named `ws-task-1` has no exact, normalized, parent, or literal `*` match and resolves denied. I did not run a live Discord repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the permanent syntax and authorization precedence. If approved, the narrowest maintainable path is a Discord-owned pattern tier in the existing allowlist resolver, not bundling category inheritance, hot reload, or sender access-list redesign into the same change.
