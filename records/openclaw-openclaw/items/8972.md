## Summary

Keep open: current main and the latest release still treat Discord guild channel keys such as `ws-*` as literal record keys, and adding glob matching would change a security-sensitive Discord message-ingress boundary.

## What This Changes

Request to add Discord guild channel allowlist glob or wildcard-pattern keys so dynamically created channels can be admitted without per-channel config edits and restarts.

## Best Possible Solution

Keep this as the canonical Discord glob-pattern tracker and resolve it through a maintainer-approved allowlist contract covering syntax, precedence, schema/docs, audit/status behavior, and resolver/preflight tests.

## Maintainer Decision

Required: true

Question: Should Discord guild channel allowlists support glob-pattern keys such as `ws-*`, and what precedence should those patterns have relative to exact channel entries, disabled entries, thread-parent fallback, category inheritance, and the literal `*` entry?

Rationale: Automation should not choose this because the new syntax changes a public Discord config surface and determines which guild messages can reach agents.

Likely owner: steipete

Owner confidence: high

Options:

- **Approve narrow glob contract (recommended):** Add Discord-owned glob matching with explicit precedence, schema/types/docs, audit/status visibility, and focused ingress tests while keeping category inheritance and access-list redesign separate.
- **Defer to category/access redesign:** Keep the dynamic-channel problem open but require maintainers to fold it into https://github.com/openclaw/openclaw/issues/60582 or https://github.com/openclaw/openclaw/issues/69748 before implementation.
- **Reject new glob syntax:** Keep the exact-entry plus literal `*` model and document that dynamic workstreams should use broad wildcard or the category/access-control trackers instead.

## Reproduction Assessment

Yes, at source level. A guild channel key like `ws-*` is never compared as a pattern against an incoming `ws-task-1` channel, so a non-empty channel map without an exact, parent, or literal `*` match resolves to denied.

## Solution Assessment

Unclear until maintainers choose the public authorization contract. The implementation likely belongs in the Discord-owned allowlist/config path, but automation should not choose glob syntax, matching order, or security semantics on its own.
