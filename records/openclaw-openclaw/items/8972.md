## Summary

Keep open: current main and v2026.6.11 still resolve Discord guild channel allowlist entries by exact id/name/slug, parent fallback, or the literal `*`; glob keys remain a security-sensitive public config feature that needs maintainer direction.

## What This Changes

The issue requests glob or wildcard Discord guild channel allowlist entries so dynamically created channels can be accepted without per-channel config edits and gateway restarts.

## Best Possible Solution

Keep this as the canonical Discord glob-pattern tracker until maintainers approve one allowlist contract covering syntax, precedence, schema/docs, audit/status behavior, and resolver/preflight tests.

- **Reject Glob Syntax:** Keep exact entries plus the literal `*` model and document that dynamic workstreams should use broad wildcard, category inheritance, or another approved access-control design instead.

Yes, at source level. A guild channel key like `ws-*` is never compared as a pattern against an incoming `ws-task-1` channel, so a non-empty channel map without an exact, parent, or literal `*` match resolves to denied.

## Solution Assessment

Unclear until maintainers choose the public authorization contract. The likely implementation belongs in the Discord-owned allowlist/config path, but automation should not choose glob syntax, matching order, or security semantics on its own.
