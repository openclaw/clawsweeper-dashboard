## Summary

Keep open: current main and the latest release still treat Discord guild channel allowlist keys as exact id/name/slug entries, thread-parent fallbacks, or the literal `*`; glob keys such as `ws-*` remain a security-sensitive config feature that needs maintainer direction.

## What This Changes

Request support for Discord guild channel allowlist glob/wildcard patterns such as `ws-*` so dynamically created matching channels do not need per-channel config edits and restarts.

## Best Possible Solution

Keep this as the canonical Discord glob-pattern tracker until maintainers approve one allowlist contract covering syntax, precedence, schema/types/docs/status/audit behavior, and resolver/preflight tests.

- **Reject Glob Syntax:** Keep exact entries plus the literal `*` model and document that dynamic workstreams should use the broad wildcard or the category/access-control trackers instead.

Unclear until maintainers choose the public authorization contract. The implementation likely belongs in the Discord-owned allowlist/config path, but automation should not choose glob syntax, matching order, or security semantics on its own.
