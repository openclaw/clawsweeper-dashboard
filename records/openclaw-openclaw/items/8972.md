## Summary

Keep open: current main and the latest release still treat Discord guild channel allowlist keys as exact channel id/name/slug entries, thread-parent fallbacks, or the literal `*`; glob keys such as `ws-*` remain an unresolved authorization-sensitive feature.

## What This Changes

The issue requests Discord guild channel allowlist support for glob or wildcard channel-name patterns so dynamically created matching channels can be admitted without per-channel config edits and restarts.

## Best Possible Solution

Approve one Discord-owned dynamic channel admission contract, then implement it with explicit precedence, schema/types/docs/audit updates, and resolver/preflight tests while keeping category inheritance and sender access-list redesigns on their canonical tracks.

- **Defer to category and access redesign:** Keep this issue open until the category-level and sender access-list decisions settle so dynamic channel admission is designed once.
- **Reject glob syntax:** Keep exact channel keys plus literal `*` and direct users to category-level config if maintainers prefer less ambiguous authorization semantics.
