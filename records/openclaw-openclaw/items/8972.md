## Summary

Keep this issue open. The requested wildcard grammar is a new Discord authorization capability rather than a defect with an established contract, and its matching precedence needs a maintainer decision before implementation can safely proceed.

## What This Changes

Add pattern-based Discord guild channel allowlist entries so dynamically created channels can be authorized without individually editing the channel map.

## System Context

Discord inbound messages are checked against guild and channel configuration before they enter the agent pipeline. The proposed pattern rules would sit inside that authorization decision and determine which dynamically named channels can deliver messages to an agent.

## Architecture Diagram

flowchart LR
  A[Discord inbound message] --> B[Guild configuration]
  B --> C[Channel identity and parent data]
  C --> D[Allowlist matching]
  D --> E[Authorization decision]
  E --> F[Agent message pipeline]

## Best Possible Solution

Define one Discord-owned dynamic-channel authorization model with stable-ID category rules where appropriate, and add a narrow documented pattern form only if it remains necessary; preserve exact-key and thread-parent behavior with explicit precedence and regression coverage.
