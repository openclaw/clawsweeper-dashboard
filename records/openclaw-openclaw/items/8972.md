## Summary

Keep open: current main and v2026.6.11 still treat Discord guild channel keys as exact id/name/slug entries, parent fallbacks, or the literal `*`; glob keys such as `ws-*` remain an unresolved authorization-sensitive feature.

## What This Changes

The issue requests glob or wildcard matching for Discord guild channel allowlist entries so dynamically created channels can be accepted without per-channel config edits and gateway restarts.

## Best Possible Solution

Keep this as the canonical Discord glob-pattern tracker until maintainers approve one allowlist contract covering syntax, precedence, schema/types/docs/status/audit behavior, and resolver/preflight tests.

Unclear until maintainers choose the public authorization contract. The implementation likely belongs in the Discord-owned allowlist/config path, but automation should not choose glob syntax, matching order, or security semantics on its own.
