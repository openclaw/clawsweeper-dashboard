## Summary

Keep open: current main and v2026.6.11 still only support exact id/name/slug, thread-parent, and literal `*` Discord channel allowlist matching; glob keys remain unresolved security-sensitive config behavior needing maintainer decision.

## What This Changes

The issue requests glob or wildcard support in Discord guild channel allowlists so dynamically created matching channels do not require per-channel config edits and restarts.

## Best Possible Solution

Approve one Discord-owned pattern contract covering syntax, precedence, schema/docs, audit/status visibility, and resolver/preflight tests before implementing glob matching.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Discord guild channel allowlists support glob-pattern keys such as `ws-*`, and what precedence should those patterns have relative to exact entries, disabled entries, thread-parent fallback, category inheritance, and the literal `*` entry?

Rationale: Pattern keys change a public Discord config surface and decide which guild messages can reach agents, so automation should not choose the authorization syntax or precedence.

Likely owner: steipete

Owner reason: steipete has the strongest recent history on the shared matcher and Discord allowlist surfaces affected by the decision.

Owner confidence: high

Options:

- **Approve narrow glob contract (recommended):** Add Discord-owned glob matching with explicit precedence, schema/types/docs, audit/status visibility, and focused ingress tests while keeping category inheritance and access-list redesign separate.
- **Fold into broader redesign:** Keep this blocked until maintainers decide whether category inheritance or the broader Discord access-control redesign should be the only dynamic-channel mechanism.
- **Reject glob syntax:** Keep exact entries plus literal `*` as the supported model and direct dynamic workflows to category inheritance or another approved access-control design.

## Reproduction Assessment

Yes, at source level. A `ws-*` channel key is stored as a normal record key and no current matcher compares it as a pattern, so a non-empty channel map without an exact, parent, or literal `*` match resolves to denied.

## Solution Assessment

Unclear until maintainers choose the public authorization contract. If approved, the narrow implementation belongs in the Discord-owned allowlist/config path, not as a generic unreviewed runtime wildcard change.
