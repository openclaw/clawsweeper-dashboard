## Summary

Current main and v2026.6.11 still expose exact Discord channel entries plus parent and literal `*` fallback, not name-pattern matching. The requested capability remains distinct from category inheritance and runtime config reload, but its authorization syntax and precedence require maintainer approval before implementation.

## What This Changes

Add wildcard or glob-based Discord guild channel allowlist entries so dynamically created matching channels can receive messages without per-channel configuration changes.

## Best Possible Solution

Define an explicit Discord-owned, bounded wildcard contract that reuses an existing safe repository matcher when suitable, applies exact and parent matches before patterns and literal `*`, exposes the matched rule in diagnostics, and proves newly created matching channels work without restart.

Options:

- **Add constrained patterns (recommended):** Support a documented wildcard subset after exact and parent matches but before literal `*`, with validation, diagnostics, and authorization regression coverage.
- **Use categories only:** Decline name patterns and make category inheritance the supported mechanism for dynamically created channel groups.
- **Retain exact matching:** Keep exact entries and literal `*` only, relying on per-channel updates or separate runtime reload tooling.
