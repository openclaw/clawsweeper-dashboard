## Summary

Keep open: current main and v2026.6.11 still resolve Discord guild channel allowlist entries by exact id/name/slug, parent fallback, and literal `*`; glob keys remain missing and would change a security-sensitive message ingress boundary.

## What This Changes

Request support for glob-style Discord channel allowlist entries so dynamically created matching channels can be accepted without per-channel config edits.

## Best Possible Solution

Keep this as the canonical Discord glob-pattern tracker and resolve it through a maintainer-approved allowlist contract covering syntax, precedence, schema/docs, audit/status behavior, and focused resolver/preflight tests.

## Reproduction Assessment

Yes, at source level: a guild channel key like `ws-*` is not compared as a pattern against an incoming `ws-task-1` channel, so a non-empty channel map without an exact, parent, or literal `*` match resolves to denied. I did not run a live Discord repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public authorization contract. The implementation likely belongs in the Discord-owned allowlist/config path, but automation should not choose glob syntax, matching order, or security semantics on its own.
