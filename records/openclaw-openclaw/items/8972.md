## Summary

Keep open: current main and latest release v2026.6.11 still treat Discord guild channel allowlist keys as exact id/name/slug entries, parent-thread fallbacks, or the literal `*`; glob keys such as `ws-*` are not implemented and the request changes a security-sensitive message ingress boundary.

## What This Changes

The issue requests glob or wildcard pattern support for Discord guild channel allowlist entries so dynamically created matching channels can be accepted without per-channel config edits and gateway restarts.

## Best Possible Solution

Keep this as the canonical Discord glob-pattern tracker and resolve it through a maintainer-approved allowlist contract covering syntax, precedence, schema/docs, audit/status behavior, and resolver/preflight tests.

## Reproduction Assessment

Yes. Source inspection shows a key like `ws-*` is never compared as a pattern against an incoming `ws-task-1` channel, so a non-empty channel map without an exact, parent, or literal `*` match resolves to denied.

## Solution Assessment

Unclear until maintainers choose the public authorization contract. The implementation likely belongs in the Discord-owned allowlist/config path, but automation should not choose glob syntax, matching order, or security semantics on its own.
