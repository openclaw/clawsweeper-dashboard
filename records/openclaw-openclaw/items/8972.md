## Summary

Keep open: current main and v2026.6.11 still only support exact Discord guild channel entries, normalized exact matches, thread-parent fallback, and the literal `*`; glob keys such as `ws-*` remain unresolved authorization-sensitive config work.

## What This Changes

Add glob or wildcard matching for Discord guild channel allowlist keys so dynamically named channels can be authorized without per-channel config edits and restarts.

## Best Possible Solution

Keep this as the canonical Discord glob-pattern tracker until maintainers approve one allowlist contract covering syntax, precedence, schema/types/docs, audit/status behavior, and resolver/preflight tests; keep category, hot-reload, and broader access-list work separate unless intentionally combined.

- **Reject Glob Syntax:** Keep exact entries plus literal `*` and document that dynamic workflows should use wildcard, category inheritance, or another approved access-control design instead.

## Reproduction Assessment

Yes, at source level. A guild channel key like `ws-*` is never compared as a pattern against an incoming `ws-task-1` channel, so a non-empty channel map without an exact, parent, or literal `*` match resolves to denied.

## Solution Assessment

Unclear until maintainers choose the public authorization contract. The implementation likely belongs in the Discord-owned allowlist/config path, but automation should not choose glob syntax, matching order, or security semantics on its own.
