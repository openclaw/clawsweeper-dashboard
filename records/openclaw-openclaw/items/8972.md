## Summary

Keep this issue open: current main and v2026.6.11 still support only exact channel id/name/slug matches, thread-parent fallback, and the literal `*` fallback. No canonical replacement owns glob matching, and the authorization syntax and precedence require maintainer product/security direction.

## What This Changes

Add pattern-based Discord guild channel allowlist entries so dynamically named channels can match without per-channel configuration edits.

## Best Possible Solution

If maintainers approve the capability, add one Discord-owned pattern contract used by inbound resolution, outbound authorization, audit/status, schema/types, and docs, with deterministic exact, parent, pattern, and literal-wildcard precedence plus collision and denial tests.

Options:

- **Add explicit patterns (recommended):** Introduce a dedicated pattern surface shared by all Discord authorization and audit paths with deterministic precedence and security regression coverage.
- **Prefer categories:** Use category-level authorization as the supported dynamic-channel grouping mechanism and retain exact channel keys.
- **Keep exact matching:** Retain exact channel entries and the literal `*` fallback, requiring operators to configure each admitted channel.

## Reproduction Assessment

Yes, at source level. A key such as `ws-*` is compared only through exact property lookup, so it cannot match `ws-task-1`; unmatched configured channels resolve to denied.

## Solution Assessment

No, directly treating ordinary map keys as globs without updating every authorization consumer or defining precedence is not the safest fix. A dedicated, shared pattern contract is the maintainable direction if maintainers approve the feature.
