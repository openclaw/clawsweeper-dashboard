## Summary

Keep open: current main and the latest release still only support exact, normalized, parent, and literal `*` Discord channel allowlist matching; glob-pattern support remains a new authorization-sensitive config contract.

## What This Changes

Add Discord guild channel allowlist keys such as `ws-*` so dynamically created matching channels can be admitted without per-channel config edits and gateway restarts.

## Best Possible Solution

Keep this as the canonical Discord glob-pattern tracker until maintainers approve one documented allowlist contract covering syntax, precedence, schema/docs, audit/status behavior, and resolver/preflight tests.

- **Fold into access-control redesign:** Keep this open but resolve dynamic channel admission through the category or broader Discord access-control trackers before implementation.
- **Reject glob syntax:** Keep exact entries plus the literal `*` entry and document that dynamic workflows should use wildcard, category inheritance, or another approved authorization design instead.

## Reproduction Assessment

Yes, at source level. A guild channel key like `ws-*` is never compared as a pattern against an incoming `ws-task-1` channel, so a non-empty channel map without an exact, parent, or literal `*` match resolves to denied.

## Solution Assessment

Unclear until maintainers choose the public authorization contract. The implementation likely belongs in the Discord-owned allowlist/config path, but automation should not choose glob syntax, matching order, or security semantics on its own.
