## Summary

Keep open: current main and v2026.6.11 still treat Discord guild channel keys as exact id/name/slug entries, parent fallbacks, or the literal `*`; glob keys such as `ws-*` remain an unresolved authorization-sensitive feature.

## What This Changes

Request support for glob or wildcard Discord guild channel allowlist keys such as `ws-*` so dynamically created channels can match without per-channel config edits and restarts.

## Best Possible Solution

Keep this as the canonical Discord glob-pattern tracker until maintainers approve one allowlist contract covering syntax, precedence, schema/types, docs, audit/status behavior, and resolver/preflight tests.

## Maintainer Decision

Rationale: Automation should not choose this because the new syntax changes a public Discord config surface and determines which guild messages can reach agents.

Owner confidence: high

Options:

- **Approve Narrow Glob Contract (recommended):** Add Discord-owned glob matching with explicit precedence, schema/types/docs, audit/status visibility, and focused ingress tests while keeping category inheritance and access-list redesign separate.
- **Fold Into Broader Discord Access Design:** Keep this open but require maintainers to resolve the dynamic-channel problem through https://github.com/openclaw/openclaw/issues/60582 or https://github.com/openclaw/openclaw/issues/69748 before implementation.
- **Reject Glob Syntax:** Keep exact entries plus the literal `*` model and document that dynamic workstreams should use the broad wildcard or the category/access-control trackers instead.

## Reproduction Assessment

Yes, at source level. A guild channel key like `ws-*` is never compared as a pattern against an incoming `ws-task-1` channel, so a non-empty channel map without an exact, parent, or literal `*` match resolves to denied.

## Solution Assessment

Unclear until maintainers choose the public authorization contract. The implementation likely belongs in the Discord-owned allowlist/config path, but automation should not choose glob syntax, matching order, or security semantics on its own.
