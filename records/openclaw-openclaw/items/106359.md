## Summary

This PR remains useful and has unusually strong live proof, but it should not merge until the resolver-ownership conflict is genuinely fail-closed: the current first-registration-wins behavior still lets plugin load order select the credential resolver. The permanent public plugin API and five-minute revocation SLA also need explicit security-owner acceptance. Likely related people are @vincentkoc for the original MCP runtime, @openperf for recent MCP lifecycle work, and @steipete for the plugin/security product boundary.

## What This Changes

The PR adds a public plugin SDK resolver for requester-bound MCP connections, requester-keyed runtime lifecycle management, and embedded/Codex harness delivery with documentation and regression tests.

## Best Possible Solution

Bind each requester-scoped resolver to an explicit server owner in plugin or manifest metadata—or disable the scoped server entirely when ownership conflicts—then obtain security-owner approval for the documented timeout and revocation SLA before rebasing and re-running focused plus live isolation proof.
