Full review comments:

- **[P1] Guard cleanup calls until their resources exist:** `extensions/codex/src/app-server/run-attempt.ts:3561-3565`
  - body: The widened `try` now begins before `abortListener`, `freezeRunTerminalOutcome`, and `handle` are assigned, but this `finally` still calls `removeEventListener`, `detachBackend`, and `clearActiveEmbeddedRun` with non-null assertions. A synchronous setup throw before those assignments will mask the original failure and can run cleanup with `undefined` instead of only releasing resources that were actually acquired.
  - confidence: 0.97
- **[P1] Preserve native PreToolUse failures before projector setup:** `extensions/codex/src/app-server/run-attempt.ts:1509-1514`
  - body: Current main queues or fallback-emits native PreToolUse failures until the projector exists; this callback now drops every failure reported before `projectorRef.current` is set. That loses native hook failure diagnostics on startup or early turn-start failure paths, which the cleanup refactor should not change.
  - confidence: 0.93
- **[P1] Forward native approval failure dispositions:** `extensions/codex/src/app-server/run-attempt.ts:2374-2386`
  - body: This approval path no longer passes `onNativeToolFailureDisposition` to `handleApprovalRequest`, so denied, cancelled, or timed-out native approvals are not recorded on the event projector. Existing approval-bridge tests cover these dispositions and the cleanup-window fix does not require dropping that projection.
  - confidence: 0.95
- **[P2] Preserve timeout and cancellation lifecycle metadata:** `extensions/codex/src/app-server/run-attempt.ts:3483-3487`
  - body: The PR removes `buildLifecycleTerminalMeta` and now emits only `aborted: true` for aborted success paths, dropping `status`, `stopReason`, `timeoutPhase`, and `providerStarted` that current tests expect for timed-out and cancelled Codex turns. Downstream lifecycle consumers lose the distinction between user cancellation and provider timeout.
  - confidence: 0.94
