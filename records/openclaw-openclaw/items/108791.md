## Summary

Keep this PR open for normal maintainer review: the modern PowerShell implementation matches the upstream per-read timeout contract, the focused tests and controlled live run support the fix, and no blocking correctness or security defect was found; maintainers should explicitly accept or further prove the legacy PowerShell total-timeout fallback before merge.

## What This Changes

The PR feature-detects PowerShell request-timeout support, applies per-read idle deadlines or legacy total deadlines to four portable Node/Git requests, and expands installer regression coverage.

## Best Possible Solution

Keep the shared feature-detected helper, retain per-read idle deadlines on PowerShell 7.4+, and merge only after the legacy 30/600-second total budgets are explicitly accepted or supported by representative Windows PowerShell 5.1 slow-download evidence.

The legacy TimeoutSec fallback is reasonable but needs explicit acceptance or representative PowerShell 5.1 proof because it changes slow-download behavior.
