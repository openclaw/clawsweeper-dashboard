## Summary

The patch remains a narrow, plausible fix for the open repeated-diagnostic bug, and the earlier credential-chain regression has been removed. It still lacks current-head real-host proof, and process-lifetime suppression needs owner acceptance because changed failure details can remain hidden until success or restart.

## What This Changes

Adds per-region, process-lifetime deduplication of failed Bedrock Mantle IAM-token diagnostics, resets suppression after successful token generation, exports the discovery config type, and adds exact-count regression coverage.

## Best Possible Solution

Keep IAM credential-chain retries unchanged and land a narrowly scoped diagnostic limiter only after redacted real-host proof confirms retries continue while logging is bounded, with the feature owner explicitly accepting the visibility cadence.

Rationale: Both policies are technically viable, but balancing log-spam prevention against evolving operator diagnostics requires product and operations intent that source correctness and CI cannot settle.

- **Use periodic reminder logging:** Replace the lifetime guard with a time-bounded limiter so persistent or changed failures become visible again without returning to per-request spam.

## Solution Assessment

Yes, conditionally. Limiting only the diagnostic is narrower and safer than gating discovery by environment credentials because it preserves the AWS default credential chain, but the suppression interval needs owner acceptance and real-host confirmation.
