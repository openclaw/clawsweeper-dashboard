The PR adds a dedicated lock around Android Talk Mode realtime tool-call state, dispatches cached completions outside that lock, bounds pending completion cache growth, and adds a regression test for terminal chat events arriving before run metadata.

## Best Possible Solution

## Reproduction Assessment

No live high-confidence reproduction was established in this read-only review. Source inspection shows current main can mutate realtime tool-call maps/sets from both gateway event handling and tool-call response paths without a shared lock.

## Solution Assessment

Yes, the proposed shape appears to be the narrow maintainable fix: keep related realtime tool state decisions under one local lock and dispatch gateway network I/O after releasing it. A broader gateway or Talk Mode redesign is not needed for this race, but the real device/emulator proof gap remains.
