## Summary

This PR is still useful because current main and the latest release both stringify runtime JSON output directly, but it is not merge-ready: the new catch path can still throw for values whose primitive conversion fails, so the circular-reference guard remains incomplete.

## What This Changes

The PR wraps `src/runtime.ts` runtime JSON output serialization in try/catch and falls back to serializing `String(value)` when `JSON.stringify` throws.

## Best Possible Solution

Add a shared non-throwing JSON output helper used by both runtime paths, with regression tests for ordinary circular values and primitive-conversion failures.

## Reproduction Assessment

Yes. Source inspection shows current main stringifies unknown runtime JSON values directly, and a focused Node probe shows the proposed fallback can still throw after a circular JSON failure.

## Solution Assessment

No. The PR is a plausible mitigation for simple circular objects, but the best fix is a non-throwing serializer or constant fallback that cannot rethrow inside the catch path.
