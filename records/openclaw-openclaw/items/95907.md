## Summary

Keep this issue open: current main and the latest release still only default `deleteAfterRun` for one-shot cron jobs, while isolated cron run cleanup remains gated on that flag. The open linked fix PR is still unmerged, and a competing open PR proposes the opposite one-shot-only contract, so this needs maintainer direction rather than cleanup closure.

## What This Changes

The issue asks for isolated recurring cron agent sessions to terminate or clean up once the cron run is recorded `ok` so they cannot continue consuming provider tokens.

## Best Possible Solution

Choose and land one reconciled cron lifecycle contract that bounds isolated cron sessions after completed runs for both new and existing persisted jobs, or explicitly rejects recurring delete-after-run with a compatible recovery path.
