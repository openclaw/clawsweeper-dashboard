## Summary

Keep open: current main still defaults `deleteAfterRun` only for one-shot cron jobs, so recurring isolated jobs can still finish as `ok` while the session cleanup helper skips deletion unless the flag is explicitly true. The linked fix PR is open and a competing open PR proposes the opposite lifecycle contract, so this needs maintainer direction rather than cleanup closure.

## What This Changes

The issue reports recurring isolated cron agent sessions continuing to consume model tokens for hours after the parent cron run is recorded as `ok`.

## Best Possible Solution

Land one reconciled cron lifecycle contract that either makes recurring isolated cleanup safe for new and existing jobs while preserving explicit `deleteAfterRun: false`, or explicitly rejects recurring delete-after-run with docs, UI/API alignment, and a recovery path.
