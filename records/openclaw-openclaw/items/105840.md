## Summary

This PR addresses a valid current-main reliability bug, but the implementation should be simplified around Node’s native stream flow-control contract and the external contribution still needs after-fix proof from a real proxy process before merge.

## What This Changes

The PR adds a response-forwarding lifecycle helper that pauses upstream reads on downstream backpressure, cancels upstream work after client disconnects, and adds focused proxy tests.

## Best Possible Solution

Forward the upstream response through Node’s native piping flow, keep preview capture as an independent observer, retain the proxy’s pre-header 502 and post-header abort behavior, and demonstrate the result with a real slow-client and client-abort proxy run.
