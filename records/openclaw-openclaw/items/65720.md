## Summary

Keep open: current main and v2026.6.11 still serve the Control UI from the in-process Gateway listener with no crash-survivor fallback, so this needs maintainer product and security architecture review rather than cleanup closure.

## What This Changes

Request to add a native Gateway crash-survivor static Control UI fallback, possibly behind a `gateway.serveStaticOnCrash`-style config option.

## Best Possible Solution

Have maintainers define the supported crash-resilience architecture first; if core owns it, implement a supervised rescue/static sidecar or documented supervisor contract with explicit auth, origin, TLS, config, docs, and upgrade tests.
