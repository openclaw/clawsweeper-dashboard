## Summary

Keep open: current main and the latest release still serve Control UI from the Gateway process itself, with no crash-survivor static fallback or public config contract. The requested behavior is a new availability architecture and security/config product decision, not a narrow bug fix.

## What This Changes

Request an opt-in Gateway crash fallback so the WebUI remains reachable as a static maintenance page after the Gateway process exits.

## Best Possible Solution

Define the supported crash-resilience model first: either a secure supervised rescue sidecar with explicit port handoff and auth/origin/TLS semantics, or a documented supervisor/reverse-proxy deployment pattern instead of an in-process toggle.
