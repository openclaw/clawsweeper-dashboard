## Summary

Keep open: current main and the latest release still serve the Control UI from the Gateway process itself, with only an in-page/static-asset fallback after HTML has loaded. The requested crash-survivor same-port fallback is a new availability architecture and security/config decision, not an implemented cleanup candidate.

## What This Changes

The issue asks for a Gateway crash-survivor static WebUI fallback so browser access remains available after the Gateway process exits.

## Best Possible Solution

Maintainers should first define whether core owns crash-survivor web availability; if it does, implement a supervised rescue/static sidecar or documented supervisor contract with explicit port handoff, auth/origin/TLS semantics, config schema, docs, and upgrade/restart proof.
