## Summary

Keep open: current main and v2026.6.11 still serve the Control UI from the in-process Gateway HTTP listener with no crash-survivor static fallback, so this remains a product/security architecture decision rather than conservative cleanup.

## What This Changes

The issue requests an opt-in Gateway crash fallback that keeps a static Web UI or maintenance page available on the Gateway port after the Gateway process exits.

## Best Possible Solution

Maintainers should first define the supported crash-resilience architecture, then either implement a supervised rescue/static sidecar with explicit security and upgrade semantics or document the external supervisor pattern as the supported path.
