## What This Changes

The PR treats a Discord nested reply payload whose ID differs from the message reference as invalid, replaces it with the canonical REST-fetched message, and omits reply context if that fetch fails.

## System Context

Discord inbound messages are hydrated before OpenClaw builds the agent-visible message context. This change validates reply metadata at that hydration boundary, then either supplies the canonical referenced message or prevents unrelated reply text from reaching the agent envelope.

## Best Possible Solution

Keep validation at the Discord hydration boundary, preserve the canonical-fetch-or-clear rule for mismatched reply data, and merge only after the branch is refreshed against current main and normal Discord-owner review confirms the fail-closed tradeoff.
