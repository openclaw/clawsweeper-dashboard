## What This Changes

This PR extracts each local manual-redirect HTTP exchange from guarded fetch into an internal dispatcher while leaving SSRF policy, DNS pinning, proxy routing, redirects, timeouts, and resource release in the existing guard loop.

## System Context

OpenClaw’s guarded-fetch subsystem validates each outbound URL and selects the safe transport route before performing HTTP I/O. The extracted dispatcher receives one already-authorized manual-redirect hop and returns its response to the guard, which remains responsible for redirect and security decisions.
