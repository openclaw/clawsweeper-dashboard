Full review comments:

- **[P1] Filter approval history through reviewer access:** `src/gateway/server-methods/approval.ts:352`
  - body: The bulk history handler still lists terminal rows without applying the per-record reviewer-device checks used by `approval.get` and `approval.resolve`. An `operator.approvals` client with no matching reviewer device can therefore read presentation, source-session, and resolver metadata for approvals outside its audience; pass the client context through the established access predicate before returning each row.

- **[P2] Keep generated history cursors within the schema limit:** `src/gateway/operator-approval-store.ts:234`
  - body: The cursor still embeds the full approval id, but approval ids are unbounded while history cursors are capped at 512 characters.   - confidence: 0.99

  - body: The generated metadata rewinds the catalog from 3421 keys to 3399 and the current i18n check fails, while the scoped UI workflow requires contributor PRs to update English plus the baseline instead of generated foreign-locale bundles. Remove the translated locale/TM churn and regenerate only the contributor baseline so existing translations are not dropped or desynchronized.
