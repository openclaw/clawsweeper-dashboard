## Summary

The core design is useful, and the retention, subtitle, and gateway-reset findings were addressed. However, the current head still appears to expose approval history without the existing per-approval reviewer-device checks and can generate cursors that its own 512-character protocol schema rejects; real Control UI behavior proof is also not inspectable yet.

## What This Changes

The PR adds a pending-approval sidebar chip, a paginated `approval.history` gateway RPC over the durable approval ledger, additive protocol attribution, generated client bindings, and a new Control UI approval-history page.

## Best Possible Solution

Keep the additive ledger-backed RPC and Control UI surface, but enforce the same per-record reviewer access contract as lookup and resolve, use a fixed-size keyset cursor, cover both with focused cross-device and long-id tests, and add redacted browser plus live-gateway proof before merge.
