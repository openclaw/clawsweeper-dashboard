## Summary

Keep open for maintainer security and architecture review: the reported synchronous fail-closed branch is consistent with the observed behavior, while current approval semantics and release notes establish that restrictive Claude native-tool use should have a usable approval path rather than requiring full bypass.

## What This Changes

Route Claude CLI native `can_use_tool` requests through a human approval flow when restrictive exec policy requires confirmation instead of denying them immediately.

## Best Possible Solution

Add an asynchronous, fail-closed native-tool approval bridge with exact request binding and authorized channel delivery, while preserving command-specific exec safeguards for Bash and covering allow, deny, timeout, cancellation, and unavailable-UI behavior.
