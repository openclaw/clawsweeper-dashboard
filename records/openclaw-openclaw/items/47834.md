## Summary

Keep open: current main still sends `before_tool_call` only the browser `act`/`type` input, while safe tab URLs are resolved inside or after browser routes; the credential-vault workaround is fail-secure but confirms the remaining security-sensitive plugin API gap.

## What This Changes

The issue asks OpenClaw to expose the current browser page URL to `before_tool_call` hooks for browser `act`/`type` actions, or provide an equivalent hook-time query path.

## Best Possible Solution

Add a narrow additive browser/plugin contract that gives pre-action hooks a policy-safe current tab URL for `act`/`type`, or an equivalent query helper, with tests for redacted/private URLs, existing-session profiles, and credential-domain checks.
