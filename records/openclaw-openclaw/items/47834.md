## Summary

Keep open: current main still passes browser `act`/`type` params to `before_tool_call` before the browser route resolves the active tab URL, and the reporter's fail-secure credential-vault workaround confirms this remains a security-sensitive plugin API gap.

## What This Changes

Request to expose the current browser page URL, or an equivalent query seam, to `before_tool_call` hooks for browser `act`/`type` actions.

## Best Possible Solution

Add a narrow, additive browser/plugin contract that gives pre-action browser policy hooks a policy-safe current tab URL for `act`/`type`, or an equivalent supported query seam, with docs and tests for blocked/private URLs and supported profiles.

Rationale: This changes the plugin API and security boundary for browser URLs; automation can implement a chosen contract, but should not pick URL leakage, redaction, and compatibility semantics by itself.

- **Keep plugin workaround only:** Leave URL caching and fail-secure behavior to credential plugins, accepting the cold-cache limitation and duplicated plugin complexity.
