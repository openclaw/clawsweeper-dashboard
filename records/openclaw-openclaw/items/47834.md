## Summary

Keep open: current main and the latest release still do not provide a policy-safe current browser URL to `before_tool_call` handlers before browser `act` or `type` runs, and the reporter's fail-secure credential-vault workaround shows this remains a real security-sensitive plugin API gap.

## What This Changes

The issue requests an additive browser/plugin hook capability that exposes the current page URL to `before_tool_call` handlers for browser `act` and `type` actions so credential domain checks can run before injection.

## Best Possible Solution

Define an additive, browser-owned hook-time current-URL contract for `act`/`type`, or an equivalent safe query seam, with URL policy reuse plus tests and docs for managed, proxy, existing-session, blocked, and redacted URL cases.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: browser `act`/`type` params are sent to `before_tool_call` before browser route code resolves and returns the active tab URL.

## Solution Assessment

Unclear. The requested capability is the right problem to solve, but maintainers should choose the narrow API and security policy shape before code is queued.
