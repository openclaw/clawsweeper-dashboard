## Summary

Keep open: current main and the latest release still do not provide a pre-action current browser URL to `before_tool_call` handlers for browser `act`/`type`, and the reporter's fail-secure credential-vault workaround shows a real security-sensitive plugin API gap remains.

## What This Changes

Request to expose the current browser page URL, or an equivalent query seam, to `before_tool_call` hooks for browser `act`/`type` actions so domain-pinning plugins can validate before injection.

## Best Possible Solution

Define a narrow, additive browser-owned hook-time current-URL contract for `act`/`type`, or an equivalent supported query seam, using the existing browser URL policy and covering managed, node-proxy, and existing-session profiles.
