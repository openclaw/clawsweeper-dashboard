## Summary

Keep open: current main still lacks a hook-time current browser URL for browser act/type calls, and the reporter's fail-secure credential-vault workaround confirms the remaining security-sensitive plugin API gap.

## What This Changes

The issue requests adding the browser's current page URL to before_tool_call params for browser act/type actions, or an equivalent query seam, so plugins can enforce domain pinning before credential injection.

## Best Possible Solution

Add a narrow, additive browser/plugin contract that gives pre-action browser policy hooks a policy-safe current tab URL for act/type, or an equivalent supported query seam, with docs and tests for blocked/private URLs and supported profiles.
