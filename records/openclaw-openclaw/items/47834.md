## Summary

Keep open: current main still sends browser `act` and `type` params to `before_tool_call` before the browser route resolves a policy-checked active tab URL, and the credential-vault workaround confirms the remaining security-sensitive plugin API gap.

## What This Changes

Expose the browser's current page URL, or an equivalent query seam, to `before_tool_call` hooks before browser `act` and `type` actions run.

## Best Possible Solution

Add a narrow additive browser/plugin contract that exposes only a policy-safe current tab URL before mutating `act` and `type`, with docs and regression tests for supported profiles and blocked/private URLs.

## Reproduction Assessment

Yes, at source level. The generic tool adapter runs `before_tool_call` on pending browser params before `tool.execute`, while `/act` resolves and returns the active URL only inside the browser route after that decision point.

## Solution Assessment

Unclear as an implementation. The capability is valid, but the best fix depends on maintainer/security choice of URL enrichment versus a typed query or context seam.
