## Summary

Keep open: current main still does not provide a policy-safe current browser URL to `before_tool_call` hooks before `browser` `act`/`type` execution, and the reporter's credential-vault workaround is useful but confirms the remaining security-sensitive plugin API gap.

## What This Changes

The issue requests a browser/plugin hook contract that exposes the current page URL, or an equivalent query path, for `before_tool_call` handlers on browser `act` and `type` actions.

## Best Possible Solution

Add a narrow, additive browser/plugin contract that gives pre-action hooks a policy-safe current tab URL for `act`/`type`, or an equivalent supported query seam, with docs and tests for private URL redaction, existing-session profiles, node proxy behavior, and credential-domain checks.
