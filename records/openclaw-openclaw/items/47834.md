## Summary

Keep open: current main still does not give `before_tool_call` handlers an authoritative current browser URL before `browser` `act`/`type` runs, and the reporter's fail-secure credential-vault workaround confirms the security-sensitive plugin API gap remains.

## What This Changes

Request to expose the active browser tab URL, or an equivalent query seam, to plugin `before_tool_call` handlers for browser `act`/`type` actions.

## Best Possible Solution

Add a narrow, additive browser/plugin contract that gives pre-action security hooks a policy-safe current tab URL for `act`/`type`, or an equivalent supported query seam, with docs and regression coverage for blocked/private URLs and supported browser profiles.

- **Keep Plugin Workarounds:** Leave URL caching and fail-secure cold-cache behavior to credential plugins, accepting duplicated complexity and restart limitations.

## Solution Assessment

Unclear. The requested capability addresses the right security gap, but maintainers should choose param enrichment versus a query helper and define URL redaction semantics before implementation.
