## Summary

Keep open: current main and the latest release still route browser `act`/`type` through generic `before_tool_call` without an authoritative current page URL; the credential-vault workaround is fail-secure but confirms the plugin API gap remains.

## What This Changes

Request to expose the active browser tab URL to `before_tool_call` hooks for browser `act`/`type` actions so credential plugins can enforce domain pins before injecting secrets.

## Best Possible Solution

Expose a narrow, additive, policy-checked current-page URL contract for browser `act`/`type` hooks, or an equivalent supported hook-time query seam, with docs and tests for managed, node-proxy, existing-session, and blocked/private URL cases.
