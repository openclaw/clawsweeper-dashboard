## Summary

Keep open: current main still does not expose an authoritative current browser URL to `before_tool_call` handlers before browser `act`/`type` execution, and the reporter's credential-vault workaround confirms a real security-sensitive plugin API gap remains.

## What This Changes

Request that browser `before_tool_call` hooks receive the current page URL, or an equivalent query seam, for browser `act`/`type` actions so credential plugins can enforce domain pins before injecting secrets.

## Best Possible Solution

Add a narrow, additive browser/plugin contract that gives pre-action browser policy hooks a policy-safe current tab URL for `act`/`type`, or an equivalent supported query seam, with docs and regression coverage for blocked/private URLs and supported browser profiles.
