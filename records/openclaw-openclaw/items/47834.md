## Summary

Keep open: current main still does not give `before_tool_call` hooks a policy-safe current browser URL for browser `act`/`type`, and the credential-vault workaround is fail-secure but leaves the security-sensitive plugin API gap unresolved.

## What This Changes

The issue requests a hook-time browser current-URL contract, or equivalent query helper, so domain-pinned credential plugins can verify the active page before injecting secrets.

## Best Possible Solution

Add a narrow, additive browser/plugin contract that gives pre-action hooks a policy-safe current tab URL for `act`/`type`, or an equivalent scoped query helper, with docs and tests for blocked/private URLs, existing-session profiles, and credential-domain checks.

- **Keep Plugin-Local Caching:** Leave core unchanged and require credential plugins to maintain fail-secure URL caches from navigate/open and after-tool-call results.

Unclear until maintainers choose the API shape. Native support is the right end state, but params enrichment versus a scoped query helper needs security-boundary review so route URL policy is not bypassed.
