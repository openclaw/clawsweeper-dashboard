## Summary

The patch correctly closes a real SQLite session-budget asymmetry and includes credible after-fix CLI proof, but it changes the default hard-budget retention policy for compaction and legacy backup artifacts. Keep this PR open for an explicit owner decision on that irreversible trade-off before merge.

## What This Changes

The PR makes SQLite session cleanup prune every archive type counted in physical disk usage before it evicts searchable historical session data, and documents and tests that ordering.

## System Context

OpenClaw session maintenance measures files beside the SQLite session store and enforces a disk budget. When usage is high, the maintenance pass prunes recoverable archives and, only if needed, evicts historical searchable session rows and their projections.

## Architecture Diagram

flowchart TD
  A[Session store and archive files] --> B[Physical disk measurement]
  B --> C{Over disk budget?}
  C -->|No| D[Keep current history]
  C -->|Yes| E[Prune counted archive files]
  E --> F{Below high-water mark?}
  F -->|Yes| G[Keep searchable sessions]
  F -->|No| H[Evict unreferenced historical sessions]

## Best Possible Solution

Adopt one explicit retention policy for counted `.bak` artifacts: if preserving searchable history is preferred, merge this ordering change with the documented hard-budget sacrifice order; if recovery backups must survive, keep them outside this deletion path and define how their disk cost is handled without silently evicting searchable sessions.
