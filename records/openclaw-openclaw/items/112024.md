## Summary

Keep this PR open for a narrow repair. The runtime clamp is the right boundary, but adding `maximum: 100` to the TypeBox tool schema makes the normal agent loop reject an oversized call before `execute()` can clamp it or emit the promised warning; the focused tests call `execute()` directly and therefore miss that production path. Likely related people: vincentkoc (medium confidence) and steipete (low confidence) from recent PDF/media-tool history.

## What This Changes

This PR caps the PDF agent tool’s model-provided `maxBytesMb` value at 100 MB, logs reductions, and adds regression tests for capped, configured, and below-cap values.

## System Context

The PDF agent tool receives model tool-call arguments, converts its size setting into the byte budget passed to media loading, then sends loaded PDFs to native provider analysis or local extraction. This change affects the model-argument validation and byte-budget boundary before either PDF-processing path runs.

## Architecture Diagram

flowchart LR

  B --> C[PDF tool execution]
  C --> D[Byte-budget selection]
  D --> E[Media loading]
  E --> F[Native analysis or extraction]
  F --> G[Agent response]

## Best Possible Solution

Keep the runtime clamp and warning, remove the schema-level maximum that prevents the clamp from running, correct the setting name to `agents.defaults.pdfMaxMb`, and add agent-loop plus real-PDF proof that an oversized model value loads under the 100 MB budget.
