## Label Justifications

- `P0`: The durable queue can deterministically accept a message and then lose both its local attachment and accompanying text during retry.
- `impact:data-loss`: Queue persistence retains a reference to producer-owned media that can disappear before recovery reads it.
- `impact:message-loss`: The unrecoverable media read causes the queued attachment and accompanying message text to be retried and ultimately dead-lettered.

## Summary

Current main still enqueues the stripped raw payload before `createOutboundPayloadPlan` materializes `MEDIA:` directives, so the reported durability gap remains source-reproducible. Keep this issue open because the linked, cleanly mergeable pull request is the active candidate fix and explicitly closes it.

## What This Changes

Ensure local attachments carried only by legacy `MEDIA:` text directives are copied into queue-owned storage before durable outbound enqueue and survive retry after the producer file disappears.

## Best Possible Solution

Land a focused fix that derives the queue copy’s effective local media through the existing outbound payload-plan authority before enqueue, lets the existing spool take custody, preserves raw input and copy-free live sends, and proves retry-after-source-deletion plus sensitive-media behavior.
