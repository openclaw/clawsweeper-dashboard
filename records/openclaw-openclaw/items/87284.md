## Summary

Keep open: current main has partial safeguards for stale Dashboard context display and empty manual compaction results, but ordinary `claude-cli` compaction is still intentionally backend-owned and no merged change proves Dashboard `/compact` can preserve or clearly recover an already over-cap Claude CLI transcript.

## What This Changes

The issue reports Dashboard context-meter and `/compact` failures that can silently lose Claude CLI session context after the native session exceeds the 1M-token cap.

## Best Possible Solution

Define and implement the maintainer-approved Claude CLI over-cap contract: either prove native carry-over, fail loudly with export/manual-prune guidance, or add a tested fallback recovery path while preventing empty checkpoints and cold-session rotation.

Options:

- **Fail loudly until native recovery is proven (recommended):** Keep ordinary Claude CLI compaction backend-owned, but make Dashboard and run-loop recovery refuse with clear export/manual-prune guidance and never rotate or checkpoint empty context.

- **Build OpenClaw fallback recovery:** Implement a tested OpenClaw-owned over-cap path that reads the native Claude transcript or uses a fallback model to summarize before any session rotation.
