## Summary

Keep open: current main has partial Dashboard and stale-meter safeguards, but ordinary Claude CLI compaction still deliberately defers to Claude Code/native ownership, so no merged fix proves Dashboard `/compact` can preserve or loudly recover an already over-cap Claude CLI transcript.

## What This Changes

This issue reports that Dashboard context usage and `/compact` can mislead users and lose Claude CLI session context once a long session crosses the native 1M-token cap.

## Best Possible Solution

Define and implement a Claude CLI over-cap recovery contract that either proves native context carry-over, fails loudly with export/manual-prune guidance, or uses a tested fallback without accepting empty checkpoints or rotating into a cold session.

Question: For ordinary Claude CLI sessions that are already near or over the native context cap, what should OpenClaw promise when Dashboard `/compact` is requested?

Rationale: Current source intentionally treats Claude CLI compaction as backend-owned, and the remaining choices affect session-state ownership, native transcript access, user recovery UX, and compatibility with Claude Code resume behavior.

Likely owner: anagnorisis2peripeteia

Owner confidence: high

Options:

- **Fail Loudly Until Native Recovery Is Proven (recommended):** Keep ordinary Claude CLI compaction backend-owned, but make Dashboard and run-loop recovery refuse with clear export/manual-prune guidance and never rotate or checkpoint empty context.
- **Accept Full Native Delegation:** Continue deferring to Claude Code only if maintainers obtain live proof that native compaction preserves resumable context past the cap and can surface trustworthy status to OpenClaw.
- **Build OpenClaw Fallback Recovery:** Implement a tested OpenClaw-owned over-cap path that reads the native Claude transcript or uses a fallback model to summarize before any session rotation.

## Reproduction Assessment

No live 1M-token Claude CLI session was reproduced here. Source inspection does show the current remaining boundary: ordinary Claude CLI compaction is a backend-owned no-op from OpenClaw while partial UI safeguards only report or suppress some stale states.

## Solution Assessment

No, current main is not a complete fix. The safest direction is a maintainer-approved native Claude CLI over-cap contract before implementation, because a fallback, fail-loud UX, or full native delegation each has different session-state guarantees.
