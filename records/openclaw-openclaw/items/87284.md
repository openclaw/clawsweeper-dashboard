## Summary

Keep open: current main has useful safeguards for stale Dashboard token display and empty manual compaction, but Claude CLI native compaction is still explicitly deferred and there is no accepted over-cap recovery contract for a Dashboard `/compact` request that is already past the native 1M cap.

## What This Changes

The issue reports that Dashboard context usage, the Compact button, and `/compact` can mislead users and lose Claude CLI session context once the native session exceeds the 1M-token cap.

## Best Possible Solution

Define and implement a tested Claude CLI over-cap contract for Dashboard compaction: either successful native recovery or a loud refusal with export/manual-prune guidance, with no empty summary checkpoint or silent session rotation.

- **Accept Provider-Owned Deferral:** Document that Claude CLI over-cap recovery is outside OpenClaw and close only after maintainers accept that Dashboard `/compact` may report no recovery for those sessions.
