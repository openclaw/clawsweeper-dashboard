Options:

- **Fail Loudly Until Native Recovery Is Proven (recommended):** Keep ordinary Claude CLI compaction backend-owned, but make Dashboard and run-loop recovery refuse with clear export/manual-prune guidance and never rotate or checkpoint empty context.
- **Accept Full Native Delegation:** Continue deferring to Claude Code only if maintainers obtain live proof that native compaction preserves resumable context past the cap and can surface a trustworthy status/result to OpenClaw.
- **Build OpenClaw Fallback Recovery:** Implement a tested OpenClaw-owned over-cap path that reads bounded native Claude transcript content or uses a fallback model to summarize before any session rotation.

## Reproduction Assessment

No live 1M-token current-main Claude CLI session was reproduced here; source inspection gives a high-confidence remaining path because Dashboard `/compact` calls `sessions.compact`, ordinary Claude CLI compaction defers to the backend, and embedded compaction can skip on `no real conversation messages`.

## Solution Assessment

Current main is not the complete fix; the UI and normal-turn overflow retry are useful mitigations, but the best solution needs a maintainer-approved manual compaction/recovery contract for native Claude CLI sessions.
