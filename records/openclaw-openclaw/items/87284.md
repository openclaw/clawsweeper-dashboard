## Label Justifications

- `P1`: The issue describes a broken long-lived Dashboard/Claude CLI workflow where real users can lose usable conversation context or remain over cap without clear recovery.
- `impact:data-loss`: The reported failure mode is a silent context wipe or inert summary after compaction/rotation, losing the prior conversation as usable agent context.
- `impact:session-state`: The affected surfaces are session transcripts, compaction checkpoints, token snapshots, and Claude CLI resume bindings drifting out of sync.

## Summary

Keep open: current main and the latest release include partial safeguards, but the central Claude CLI over-cap recovery path is still unresolved because ordinary claude-cli compaction is backend-deferred, Dashboard/webchat compaction is rejected as a session mutation, and related open work only covers narrower budget or resume-binding pieces.

## What This Changes

The issue requests fixes for the Dashboard context meter, Compact button, and `/compact` behavior so over-cap Claude CLI sessions do not silently lose or bypass context.

## Best Possible Solution

Define a maintainer-approved Claude CLI over-cap contract, align Dashboard meter and compact actions with it, and fail loudly or clear/reseed resume bindings when OpenClaw-managed compaction cannot safely carry context forward.

Kind: product_direction

Question: For over-cap or manually compacted Claude CLI sessions, should OpenClaw clear or reseed the Claude CLI resume binding from the compacted OpenClaw transcript, fully defer to Claude Code and show that limitation in Dashboard, or fail loudly with export/reset guidance?

Rationale: The current behavior crosses product semantics for backend-owned continuity, OpenClaw compaction checkpoints, and Dashboard recovery UX; source changes alone cannot decide which session-continuity contract existing users should get.

Likely owner: obviyus

Owner confidence: medium

Options:

- **Own Recovery At Compaction Boundaries (recommended):** After OpenClaw-managed manual compaction or detected over-cap failure, clear or reseed the Claude CLI binding so the next turn uses the compacted transcript, and fail loudly with export/reset guidance when that cannot be guaranteed.
- **Document Full Backend Deferral:** Keep Claude CLI continuity entirely backend-owned, hide or disable Dashboard compaction for that path, and explain that users must use reset/export when Claude Code itself cannot compact.
- **Wait For Narrow Linked Work:** Hold this issue behind #84593 and #93198 until maintainers can separate context-budget persistence from resume-binding invalidation and Dashboard UX.
