## Summary

Keep open: current main has partial UI and stale-meter safeguards, but ordinary `claude-cli` compaction still deliberately defers to backend-owned native compaction and no merged fix proves Dashboard `/compact` can preserve or loudly recover an already over-cap Claude CLI transcript.

## What This Changes

The issue requests that Dashboard context usage and `/compact` for Claude CLI sessions stop misleading users and never silently lose context after the native 1M-token cap is exceeded.

## Best Possible Solution

Define a Claude CLI over-cap recovery contract that either proves native context carry-over, fails loudly with export/manual-prune guidance, or uses a tested fallback, while keeping Dashboard compaction from writing empty checkpoints or rotating into a cold session.
