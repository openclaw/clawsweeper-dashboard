## Summary

This issue still needs a maintainer decision: current main exposes a supported direct model override, so the reported nested `webSearch.gemini` schema is not the right fix, but the default remains the dated `gemini-2.5-flash` model. The remaining question is whether to replace that default with a live-verified rolling Google model while retaining the existing direct override.

## What This Changes

Update Gemini-backed web search so users can select an accessible Gemini model and avoid relying on the dated hard-coded default.

## System Context

The bundled Google plugin implements the Gemini provider for OpenClaw’s web-search tool. Plugin configuration is validated, merged into the provider’s scoped settings, then used to choose the model sent to the Gemini API.

## Best Possible Solution

Keep `plugins.entries.google.config.webSearch.model` as the canonical override, document it where users configure web search, and—after live Google API verification—replace the dated fallback with a provider-supported rolling model if maintainers approve that policy.
