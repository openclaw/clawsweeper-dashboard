- `P2`: The issue describes meaningful safety and stability work with real operator impact, but it is a broad feature/design request rather than an urgent reproduced regression.

## Summary

Keep open: current main and the latest release still have only partial temp-root hardening, transcript-derived artifact APIs, workspace guidance, and volatile-state checks; they do not implement creation-time temp artifact classes/provenance, janitor semantics, or broad runtime-critical `/tmp` guardrails.

## What This Changes

The issue requests first-class temp artifact provenance, durable-path guardrails, cleanup semantics, and runtime-critical temp path checks.

## Best Possible Solution

Define a narrow core design where OpenClaw-owned temp provenance is SQLite-backed and doctor/runtime checks cover runtime-critical temp-backed paths, while workflow-specific audit/review classifications stay in plugins or ClawHub unless a missing core API is identified.
