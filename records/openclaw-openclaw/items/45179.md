## Summary

Keep open: current main has scoped temp-root hardening, workspace guidance, transcript-scoped artifact provenance, static temp-path checks, volatile-state doctor warnings, and narrow session temp cleanup, but it still lacks the requested creation-time temp artifact classes, durable provenance registry, janitor semantics, and broad runtime-critical temp-path guardrails.

## What This Changes

The issue requests a built-in model for classifying OpenClaw-created temp artifacts, routing durable outputs out of system temp, making cleanup aware of that provenance, and warning on runtime-critical paths under `/tmp` or `/private/tmp`.

## Best Possible Solution

Define a narrow core-owned design for runtime-critical temp-path safety and OpenClaw-created artifact provenance, backed by the existing SQLite state model, while leaving workflow-specific janitor classifications to plugins, skills, or ClawHub unless a missing core seam is proven.
