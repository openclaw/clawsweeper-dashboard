## Summary

Keep open: current main and v2026.6.11 have safe temp-root helpers and a narrow service-command temp check, but they still lack the requested artifact classification, provenance registry, janitor semantics, and broad runtime-critical temp-path auditing.

## What This Changes

Request to add temp artifact classification/provenance, cleanup awareness, durable-path defaults, and runtime-critical temp-path guardrails for agent-created artifacts.

## Best Possible Solution

Define a narrow design where core owns runtime-critical temp-path checks and any OpenClaw-owned provenance in SQLite/doctor, while workflow-specific audit or review classifications live in plugins, SDK seams, or ClawHub unless a missing core API is identified.
