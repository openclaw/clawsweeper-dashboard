## Summary

Keep open: current main has temp-root hardening, workspace-local scratch guidance, narrow static tmp-path checks, and focused doctor cleanup behavior, but it still lacks the requested creation-time artifact classes, provenance registry, janitor semantics, and broad runtime-critical `/tmp` guardrails.

## What This Changes

The issue requests built-in temp artifact provenance, durable-path routing, cleanup awareness, and runtime-critical temp-path guardrails for OpenClaw-created files.

## Best Possible Solution

Define a narrow core design for runtime-critical temp-path safety and OpenClaw-owned artifact provenance, backed by the existing SQLite state model, while leaving workflow-specific audit/review classifications to plugins or ClawHub unless a missing core seam is proven.
