## Summary

Keep open: current main has partial temp-path hardening and a doctor volatile-state warning, but it still lacks the requested creation-time artifact classes, provenance registry, durable promotion semantics, and janitor behavior. The direction is safety-aligned, but the core-vs-plugin and SQLite storage boundary needs maintainer product scoping before implementation.

## What This Changes

The issue requests built-in temp artifact classification, provenance metadata, cleanup semantics, and durable-path guardrails for OpenClaw-created files and runtime-critical paths that drift into system temp.

## Best Possible Solution

Define a narrow design where core owns runtime-critical temp-path checks and any OpenClaw-owned provenance as SQLite-backed state, while workflow-specific audit/review classifications live in plugins, SDK seams, or ClawHub unless a missing core API is identified.
