## Summary

Keep open: current main has secure temp-root helpers, private temp cleanup, transcript artifact APIs, and a static tracked-source temp-path scanner, but it does not implement the requested creation-time temp artifact classes, durable provenance registry, janitor cleanup semantics, or runtime-critical temp-backed path validation. The remaining work is meaningful but needs maintainer scope decisions because broad artifact provenance crosses core state storage, agent tool APIs, doctor/runtime guardrails, and plugin-vs-core ownership.

## What This Changes

Request to add built-in temp artifact provenance, durable-path routing, cleanup classification, and runtime-critical `/tmp` guardrails for OpenClaw-created or agent-created artifacts.

## Best Possible Solution

Define a narrow core-owned safety contract first: runtime/install/doctor should reject or repair post-reboot-critical temp-backed paths, while temp artifact provenance should use an explicit SQLite-backed or plugin-owned registry design with typed scratch/reproducible/durable semantics before janitor integration.
