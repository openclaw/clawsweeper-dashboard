## Summary

Keep open: current main and the latest release have temp-root hardening, workspace-only temp guidance, transcript artifact provenance, and targeted volatile-state checks, but they still lack the requested creation-time temp artifact classes, cleanup semantics, and broad runtime-critical temp-path guardrails.

## What This Changes

The issue asks OpenClaw to classify agent-created temp artifacts with provenance, route durable outputs out of temp, teach cleanup tooling those classes, and flag runtime-critical temp-backed paths.

## Best Possible Solution

Define a narrow design where core owns runtime/install/doctor temp-path safety and any OpenClaw-owned provenance in SQLite, while workflow-specific audit/review classifications use plugin, SDK, or ClawHub surfaces unless a missing core API is identified.
