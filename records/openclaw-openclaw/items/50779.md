## Summary

Keep open. Current main still drops direct tool-returned `{type:"image", data, mimeType}` blocks in the Control UI chat renderer, the focused linked fix PR is closed unmerged, and the broad inline-media issue is only a partial overlap rather than a replacement.

## What This Changes

Control UI should render image content blocks returned by tools inline in chat or expose an obvious preview affordance.

## Best Possible Solution

Add the narrow direct `data` plus `mimeType` image-block branch to the current Control UI chat image extraction path, cover it with focused regression tests, and leave broader audio/video/web-preview policy to the separate inline-media issue.

## Reproduction Assessment

Yes, by source inspection: the read/tool helpers emit direct `{ type: "image", data, mimeType }` blocks and current main's `extractImages()` ignores that shape. I did not run a live browser repro in this read-only review.

## Solution Assessment

Yes for the narrow bug boundary: the maintainable fix is to reuse the existing base64 image URL path for direct image blocks in the current renderer. The broader media-player and web-preview work should stay separate in https://github.com/openclaw/openclaw/issues/64607.
