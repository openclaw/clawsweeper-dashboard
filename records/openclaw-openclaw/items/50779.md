## Summary

Keep open. Current main and the latest release still do not render the direct `{ type: "image", data, mimeType }` blocks emitted by the read-tool path in Control UI chat/tool output, and the exact linked fix PR is closed unmerged rather than a current landing candidate.

## What This Changes

The issue asks for Control UI chat/tool output to render image blocks returned by tools such as `read` instead of showing only the text label.

## Best Possible Solution

Add a narrow Control UI normalization/rendering path for direct tool-result image blocks using the existing safe data-image renderer, preserve those images in expanded tool output where applicable, and keep broader inline media work in the umbrella issue.

## Reproduction Assessment

Yes, by source inspection. The read tool currently emits direct image blocks with `data` and `mimeType`, while the Control UI image and tool-card extraction paths do not preserve or render that shape.

## Solution Assessment

Yes for a narrow bug fix. The maintainable solution is to reuse the existing Control UI data-image rendering path for direct tool-result image blocks and avoid expanding this into broad media preview policy.
