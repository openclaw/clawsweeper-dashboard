- `impact:message-loss`: The transcript carries tool-returned image content, but Control UI chat drops the visible image representation for users.

## Summary

Keep open. Current main and v2026.6.11 still render `type: "image"` content only through `source.type === "base64"` or `url`, while the read/tool image paths emit direct `data` plus `mimeType` blocks that are dropped from Control UI chat.

## What This Changes

The issue asks Control UI chat to show images returned from tools inline or as an obvious preview instead of text-only tool output.

## Best Possible Solution

Add a narrow `extractImages()` branch that converts direct `{ type: "image", data, mimeType }` blocks through the existing data-URL image rendering path, with regression coverage and without expanding into broader audio/video/web preview work.

## Reproduction Assessment

Yes, by source inspection. The read/tool paths emit direct image blocks with `data` and `mimeType`, while current main's chat image extractor ignores that shape before rendering.

## Solution Assessment

Yes for the narrow bug boundary. The best fix is to reuse the existing chat image rendering path for direct tool-result image blocks and leave full inline media support to the broader feature issue.
