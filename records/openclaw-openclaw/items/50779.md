## Summary

Keep open. Current main and v2026.6.11 still drop the direct tool-result image block shape that the read/image helpers emit, and the focused repair PR is closed unmerged, so no active merged implementation now owns this narrow bug.

## What This Changes

The issue asks Control UI chat to render images returned by tool output inline or as an obvious preview instead of showing only text such as `Read image file [image/png]`.

## Best Possible Solution

Add direct `data` plus `mimeType` image extraction to the existing safe Control UI image renderer with focused regression coverage, while leaving remote image, audio/video, and web-preview policy to the broader media issue.

## Reproduction Assessment

Yes, as a source-level reproduction: tool/read paths emit direct `{type:"image", data, mimeType}` blocks, and current `extractImages()` ignores that shape. I did not run a live browser/Gateway reproduction in this read-only pass.

## Solution Assessment

Yes for the narrow bug: the maintainable fix is to make `extractImages()` recognize the existing direct image contract and add grouped-render tests. It should not expand into the broader remote media, audio/video, or web-preview request.
