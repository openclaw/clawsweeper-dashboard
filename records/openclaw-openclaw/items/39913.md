## Summary

Keep open: current main has the merged static and identity-token `responsePrefix` behavior for `message(action=send)`, but provider/model/full-model/thinking template parity is still intentionally skipped and remains the meaningful unresolved product contract.

## What This Changes

Request to make visible message-tool outbound sends honor `messages.responsePrefix` consistently with direct replies, including model/provider/thinking template provenance from the current attempt.

## Best Possible Solution

Define one visible-message prefix contract: propagate live attempt provider/model/thinking context into model-originated message-tool sends, or explicitly document selected-model variables as reply-path-only while keeping static and identity prefixes on tool sends.
