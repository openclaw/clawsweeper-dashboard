## Summary

Keep open: current main now applies static and identity `messages.responsePrefix` values to message-tool sends, but it still intentionally skips prefixes containing provider/model/thinking templates, which the discussion identifies as the remaining operator-visible parity gap.

## What This Changes

Apply configured `messages.responsePrefix` consistently to visible `message(action="send")` outbound sends, including provider/model/thinking template parity discussed in the issue comments.

## Best Possible Solution

Define the message-tool prefix contract, then carry the actual selected provider/model/full-model/thinking context into agent-originated sends while preserving unresolved-template skipping for CLI or out-of-run sends.
