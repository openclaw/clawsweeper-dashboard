## Summary

Keep open: current main has the merged static and identity-token `responsePrefix` behavior for `message(action=send)`, but provider/model/full-model/thinking template parity is still deliberately skipped and remains the meaningful unresolved part of the request.

## What This Changes

The issue requests consistent `messages.responsePrefix` handling, including model/provider/thinking templates, for visible `message(action=send)` outbound sends.

## Best Possible Solution

Define one visible-message prefix contract: either propagate live attempt provider/model/thinking context into message-tool egress, or explicitly document selected-model variables as reply-path-only while keeping static and identity prefixes on tool sends.
