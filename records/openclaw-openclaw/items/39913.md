## Summary

Keep open: current main applies static and identity `messages.responsePrefix` values to `message(action=send)`, but provider/model/full-model/thinking template parity is still intentionally skipped and needs a maintainer product/runtime decision.

## What This Changes

The issue asks for configured `messages.responsePrefix` to apply consistently to visible `message(action=send)` outbound sends, including the provider/model/thinking template values used on direct replies.

## Best Possible Solution

Define one visible-message prefix contract: either propagate live attempt provider/model/thinking context into message-tool egress, or explicitly document selected-model variables as reply-path-only while keeping static and identity prefixes on tool sends.
