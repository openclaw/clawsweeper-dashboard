## Summary

Keep open: current main fixes static and identity `responsePrefix` handling for message-tool sends, but provider/model/full-model/thinking template parity is still explicitly skipped and remains a product/runtime contract decision.

## What This Changes

The issue requests that `messages.responsePrefix` apply consistently to visible `message(action=send)` outbound sends, including template-based provenance prefixes.

## Best Possible Solution

Define one visible-message prefix contract: either propagate live attempt provider/model/thinking context into message-tool egress, or explicitly document those variables as reply-path-only while keeping static and identity prefixes on tool sends.
