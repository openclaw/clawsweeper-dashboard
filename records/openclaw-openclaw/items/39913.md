The issue requests applying configured `messages.responsePrefix` behavior consistently to visible outbound sends made through the `message` tool.

## Best Possible Solution

Define the message-tool prefix contract, then pass actual selected provider/model/full-model/thinking context into agent-originated visible sends while preserving unresolved-template skipping for out-of-run sends.
