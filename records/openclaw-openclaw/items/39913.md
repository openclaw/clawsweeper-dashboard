## Summary

Keep open: current main now applies static and identity `messages.responsePrefix` values to `message(action=send)`, but provider/model/full-model/thinking template parity is still deliberately skipped and needs a maintainer product/runtime decision.

## What This Changes

Apply existing `messages.responsePrefix` behavior consistently to visible `message(action=send)` outbound sends, including provenance templates such as provider, model, full model, and thinking level.

## Best Possible Solution

Define one visible-message prefix contract: either propagate live attempt provider/model/thinking context into message-tool egress, or explicitly document selected-model variables as reply-path-only while keeping static and identity prefixes on tool sends.
