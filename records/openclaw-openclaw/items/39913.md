## Summary

Keep open: current main now handles static and identity prefixes on message-tool sends, but it intentionally drops provider/model/full-model/thinking templates, so the remaining visible-provenance gap needs a maintainer contract decision.

## What This Changes

The issue asks for `messages.responsePrefix` to apply consistently to visible outbound sends made through `message(action="send")`, including dynamic provenance templates.

## Best Possible Solution

Define the message-tool prefix contract, then carry actual selected provider/model/full-model/thinking context into agent-originated sends while preserving the unresolved-template guard for out-of-run sends.
