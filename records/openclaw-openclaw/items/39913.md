## Summary

Keep open: current main applies static and identity `messages.responsePrefix` values to `message(action=send)`, but it deliberately skips provider/model/full-model/thinking templates because tool sends do not carry live selected-model context yet.

## What This Changes

The issue requests consistent `messages.responsePrefix` handling for visible message-tool outbound sends, including model/provider provenance templates added in the discussion.

## Best Possible Solution

Define one visible-message prefix contract: either propagate live attempt provider/model/thinking context into message-tool egress, or explicitly document selected-model variables as reply-path-only while preserving static and identity prefixes on tool sends.
