## Summary

Keep open: current main now applies static and identity `messages.responsePrefix` values to `message(action=send)`, but it intentionally skips provider/model/thinking template prefixes on tool sends, which is the remaining user-visible scope added in the issue discussion.

## What This Changes

The issue asks for `messages.responsePrefix` to be applied consistently to visible outbound sends made through the `message` tool.

## Best Possible Solution

Keep the merged static/identity prefix fix and make a maintainer decision on selected-model template parity; if accepted, thread current run provider/model/thinking context into visible message-tool sends without leaking raw unresolved templates.

## Reproduction Assessment

Yes. Source and tests on current main show that a static or identity prefix is applied, while a provider/model template prefix on `message(action=send)` is skipped because no live model-selection context is available there.

## Solution Assessment

Unclear. The current implementation is the right outbound-send layer for static prefix consistency, but maintainers still need to decide whether full provider/model/thinking template parity belongs in message-tool sends and how that context should be passed safely.
