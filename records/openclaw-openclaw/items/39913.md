## Summary

Keep open: current main implements static and identity prefixing for message-tool sends, but provider/model/thinking template parity is still deliberately skipped and needs maintainer direction.

## What This Changes

The issue requests applying `messages.responsePrefix` consistently to visible `message(action=send)` outbound sends, including selected provider/model/thinking template variables.

## Best Possible Solution

Define the message-tool prefix contract, then carry actual selected provider/model/thinking context into agent-originated sends while preserving unresolved-placeholder skipping for CLI or out-of-run sends.
