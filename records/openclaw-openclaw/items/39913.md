## Summary

Keep open: current main covers static and identity `responsePrefix` handling for message-tool sends, but selected provider/model/thinking template parity remains intentionally skipped and still needs maintainer direction.

## What This Changes

The issue requests that `messages.responsePrefix` be applied consistently to visible outbound sends made through `message(action="send")`, not only normal direct replies.

## Best Possible Solution

Define the message-tool prefix contract, then pass actual selected provider/model/full-model/thinking context into agent-originated sends while preserving unresolved-template skipping for CLI, cron, heartbeat, or other out-of-run sends.
