## Summary

Keep open: current main fixes the static and identity-template prefix drop on `message(action=send)`, but provider/model/thinking template parity is still deliberately skipped and remains a real contract decision for visible message-tool delivery.

## What This Changes

The issue asks OpenClaw to apply configured `messages.responsePrefix` consistently to outbound sends created by the `message` tool, including the same user-visible prefix behavior operators get on direct replies.

## Best Possible Solution

Define the message-tool prefix contract, then carry the actual selected run context into visible tool sends when available while keeping the current skip behavior for non-agent sends that genuinely lack model context.
