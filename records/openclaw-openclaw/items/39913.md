## Summary

Keep open: current main fixed static and identity `messages.responsePrefix` on `message(action=send)`, but provider/model/full-model/thinking template parity is still intentionally skipped and remains a product-boundary decision.

## What This Changes

The issue asks for `messages.responsePrefix` to apply consistently to outbound sends created by the `message` tool.

## Best Possible Solution

Define the message-tool prefix contract, then pass actual selected provider/model/full-model/thinking context into agent-originated visible sends while preserving unresolved-placeholder skipping for sends without run context.
