## Summary

Keep open: current main implements static and identity `responsePrefix` on message-tool sends, but it intentionally skips unresolved provider/model/thinking templates that the issue discussion still asks to support.

## What This Changes

The issue requests applying `messages.responsePrefix` consistently to visible outbound sends made through `message(action=send)`, including the same effective prefix/template behavior as direct replies.

## Best Possible Solution

Define the message-tool prefix contract, then either carry actual selected provider/model/thinking context into agent-originated sends while retaining the unresolved-template guard for out-of-run sends, or document static/identity-only behavior as intentional.
