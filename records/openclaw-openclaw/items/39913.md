## Summary

Keep open: current main fixes static and identity-token `responsePrefix` on `message(action=send)`, but provider/model/full-model/thinking template parity is still intentionally skipped and remains a real product-contract decision.

## What This Changes

The issue asks OpenClaw to apply configured `messages.responsePrefix` consistently to outbound sends produced by the `message` tool.

## Best Possible Solution

Define one visible-message prefix contract: either propagate live attempt provider/model/thinking context into message-tool egress, or explicitly document selected-model variables as reply-path-only while keeping static and identity prefixes on tool sends.
