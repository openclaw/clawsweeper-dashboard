## Summary

Keep open: current main fixed literal and identity `messages.responsePrefix` handling for `message(action=send)`, but current source and tests explicitly skip provider/model/full-model/thinking templates, so the remaining documented attribution behavior still needs a maintainer product/runtime decision.

## What This Changes

Request that visible message-tool outbound sends apply `messages.responsePrefix` consistently with direct replies, including configured attribution prefixes for cross-chat delivery.

## Best Possible Solution

Keep the landed static/identity prefix behavior and add a maintainer-approved current-run prefix context for visible message-tool sends, or explicitly document selected-model templates as unsupported on that path.
