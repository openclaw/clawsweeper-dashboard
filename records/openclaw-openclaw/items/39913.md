## Summary

Keep open: current main fixes static and identity `messages.responsePrefix` on `message(action="send")`, but provider/model/thinking template parity is still deliberately skipped and remains a product/runtime contract decision.

## What This Changes

The issue requests that configured `messages.responsePrefix` be applied consistently to outbound `message(action="send")` tool sends.

## Best Possible Solution

Define a narrow contract for agent-originated visible sends: preserve current static/identity behavior, and if maintainers accept model-provenance parity, thread the current run's provider/model/thinking context into message-tool sends while keeping CLI/off-run sends from leaking unresolved templates.
