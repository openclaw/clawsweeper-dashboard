## Summary

Keep open: current main now applies static and identity `messages.responsePrefix` values to `message(action=send)`, but it intentionally skips provider/model/modelFull/thinking template variables, so the remaining user-visible parity request still needs a product/runtime contract decision.

## What This Changes

Request `message(action=send)` outbound sends to apply `messages.responsePrefix` consistently with direct replies, including configured template variables.

## Best Possible Solution

Define one visible-message prefix contract: either propagate live attempt provider/model/thinking context into message-tool egress, or document selected-model variables as reply-path-only while keeping static and identity prefixes on tool sends.
