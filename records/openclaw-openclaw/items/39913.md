## Summary

Keep open: current main now applies static and identity `messages.responsePrefix` values to `message(action=send)`, but it deliberately skips provider/model/thinking template prefixes on tool sends, which is the remaining user-visible parity request from the discussion.

## What This Changes

The issue requests that configured `messages.responsePrefix` behavior apply consistently to outbound messages sent through the shared `message(action=send)` tool.

## Best Possible Solution

Keep the static/identity prefix behavior from the merged fix, then make an owner-approved design for selected-model template context on visible message-tool sends without leaking unresolved placeholders.
