## Summary

Keep open: current main fixes static and identity `responsePrefix` handling for message-tool sends, but provider/model/full-model/thinking template parity is still deliberately skipped and remains a real product-contract decision.

## What This Changes

The issue asks for `messages.responsePrefix` to be applied consistently to user-visible `message(action="send")` outbound sends, including dynamic model/provenance template variables raised in follow-up discussion.

## Best Possible Solution

Define the message-tool prefix contract, then carry actual selected provider/model/full-model/thinking context into agent-originated sends while preserving unresolved-placeholder skipping for sends without run context.
