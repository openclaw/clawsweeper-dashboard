## Summary

Keep open: current main fixed static and identity `responsePrefix` handling for message-tool sends, but provider/model/thinking templates are still intentionally skipped and need a maintainer product-boundary decision.

## What This Changes

The issue requests `messages.responsePrefix` be applied consistently to visible `message(action=send)` outbound messages, including provider/model/thinking template use cases.

## Best Possible Solution

Define the message-tool prefix contract, then carry actual selected provider/model/thinking context into agent-originated sends while preserving the unresolved-template guard for CLI or out-of-run sends.
