## Summary

Keep open: the report describes a real onboarding failure mode, and the current shell-environment implementation serves OpenClaw command execution rather than establishing a contract for shell-specific commands shown to users. The requested presentation policy needs a bounded maintainer decision, but it aligns with setup reliability and first-run UX.

## What This Changes

Add shell-aware or explicitly interpreter-targeted agent setup guidance so copy-pasteable credential commands do not silently assume Bash for users running another login shell.

## Best Possible Solution

Add one narrow agent-presentation contract: setup commands must either name and invoke their interpreter explicitly (for example, a clearly labeled `bash -lc` path) or ask/render for a supported target shell; add Fish coverage for credential setup guidance without adding a user config option.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw standardize agent-generated local setup snippets on explicit interpreter wrapping by default, with shell-native rendering only for a small supported set of detected or user-confirmed shells?

Rationale: Both approaches can prevent the reported failure, but they differ in portability, prompt complexity, cross-platform support, and how much host metadata should enter agent context.

Likely owner: steipete

Owner reason: The existing login-shell and gateway execution boundary has substantial recent ownership from this contributor.

Owner confidence: high

Options:

- **Use explicit interpreter targeting (recommended):** Require shell-specific setup snippets to state and invoke Bash or POSIX sh explicitly unless the user has selected a supported shell.
- **Add supported shell rendering:** Expose validated login-shell metadata and render native Bash, Zsh, Fish, and PowerShell snippets where supported.
- **Ask before shell-specific commands:** Have the agent ask for the user's target shell whenever it cannot safely provide interpreter-neutral guidance.

No high-confidence current-main end-to-end reproduction is available from the checked evidence. The reported Fish snippet is demonstrably invalid as pasted, and current source confirms that login-shell handling is part of execution-environment preparation rather than visible setup-command rendering.

## Solution Assessment

Unclear until the maintainer chooses the presentation contract. Explicit interpreter targeting is the narrowest safe default because it avoids treating a tool shell as the user's interactive shell while preserving a path to native renderers later.
