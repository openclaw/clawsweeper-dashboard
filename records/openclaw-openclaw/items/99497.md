## Summary

Keep open: current main and the latest release already have generic prompt-hook and next-turn injection seams, but Active Memory still explicitly runs only for user-triggered interactive chat sessions, so the requested opt-in non-user recall behavior remains unresolved and needs maintainer product/API direction.

## What This Changes

The issue requests opt-in agent-initiated context or lesson injection during non-user-triggered agent work such as long tasks, sub-agent orchestration, and cron agents.

## Best Possible Solution

Keep this open for a maintainer decision, then reuse the existing prompt-hook and next-turn injection seams with a narrow opt-in Active Memory non-user trigger policy instead of adding a broad orchestration layer.

## Reproduction Assessment

Yes, at source level: current Active Memory returns early for non-user triggers, and its tests assert heartbeat contexts do not run recall. I did not run an end-to-end live repro in this read-only review.

## Solution Assessment

No, not as the broad step-triggered, periodic, API, and lifecycle-hook menu in the issue. The safer path is a narrow maintainer decision around existing hook seams, explicit opt-in config, and Active Memory eligibility rules.
