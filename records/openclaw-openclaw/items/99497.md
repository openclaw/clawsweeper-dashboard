## Summary

Keep open: current main has generic hook and next-turn injection seams, but Active Memory still intentionally limits recall to user-triggered interactive sessions, so the requested opt-in non-user recall behavior remains unresolved and needs maintainer product/API direction.

## What This Changes

The issue requests opt-in automatic memory/wiki context injection during agent-initiated work such as sub-agent orchestration, long-running tasks, cron agents, and feedback loops.

## Best Possible Solution

Reuse the existing plugin prompt-hook and next-turn injection seams, then add a narrow opt-in Active Memory/wiki recall policy for approved non-user triggers instead of adding a default heavy orchestration layer.

## Reproduction Assessment

Yes, at source level: Active Memory rejects any hook context whose trigger is not `user`, and docs/tests state heartbeat/background/sub-agent/internal surfaces do not run active memory. I did not run an end-to-end live repro in this read-only review.

## Solution Assessment

No, not as the broad step/periodic/API proposal currently written. The best path is a narrow maintainer decision around existing hook seams and opt-in Active Memory/wiki behavior.
