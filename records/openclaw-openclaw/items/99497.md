## Summary

Keep open: current main still rejects non-user active-memory triggers, and the existing hook seams do not yet define the requested opt-in policy for agent-initiated recall.

## What This Changes

The issue requests opt-in automatic memory/context injection during agent-initiated work instead of only after user messages.

## Best Possible Solution

Reuse the existing plugin prompt-hook and next-turn injection seams, then add a narrow opt-in active-memory policy only after maintainers choose the allowed non-user triggers and safety bounds.

## Reproduction Assessment

Yes, at source level: active-memory rejects non-`user` prompt-build triggers before recall runs, and a heartbeat-triggered skip is covered by the current tests. I did not run an end-to-end live repro in this read-only review.

## Solution Assessment

No, not as the broad step/periodic/API proposal currently written. The maintainable path is a narrower product decision around existing hook seams, active-memory opt-in behavior, token limits, and prompt-safety handling.
