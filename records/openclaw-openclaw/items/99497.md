## Summary

Keep open: current main still gates Active Memory recall to user-triggered prompt builds, while the existing generic hook seams do not provide an opted-in non-user recall policy; this remains a maintainer product/API decision.

## What This Changes

Request an opt-in mechanism for agent-initiated context or lesson injection during non-user-triggered work such as cron runs, subagent orchestration, and long multi-step agent tasks.

## Best Possible Solution

Reuse the existing plugin prompt, next-turn injection, and heartbeat seams to add a narrow opt-in Active Memory policy for approved non-user triggers, with tests and docs covering trigger eligibility and token/prompt-safety bounds.

## Reproduction Assessment

Yes. Source inspection on current main shows Active Memory returns before recall unless the hook trigger is `user`, and the test suite asserts heartbeat contexts do not run recall.

## Solution Assessment

No, not as the broad step/periodic/API proposal currently written. The maintainable path is a narrow opt-in Active Memory or plugin API policy that reuses existing prompt and next-turn seams instead of adding a heavy orchestration layer.
