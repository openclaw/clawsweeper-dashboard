## Summary

Keep open: current main still gates Active Memory recall to user-triggered interactive persistent chat sessions, and the broader non-user injection request needs maintainer product/API direction before implementation.

## What This Changes

Request an opt-in mechanism for automatic memory/wiki context injection during agent-initiated work, not only user-message-triggered turns.

## Best Possible Solution

Keep this as a product/design item: prefer a narrow default-off Active Memory or plugin policy using existing prompt seams where possible, and add a new generic lifecycle or step seam only if the chosen trigger cannot be implemented through current hooks.

## Reproduction Assessment

Yes, at source level: current main returns early for non-`user` Active Memory triggers, and tests assert heartbeat contexts do not run recall. I did not run an end-to-end live repro in this read-only review.

## Solution Assessment

No, not as the broad step/periodic/API proposal currently written. The best path is a maintainer-approved, default-off trigger policy that reuses existing plugin prompt seams unless a concrete missing lifecycle hook is proven.
