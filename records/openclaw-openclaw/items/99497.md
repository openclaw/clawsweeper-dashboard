## Summary

Keep open: current main still gates bundled active-memory recall to user-triggered interactive sessions, while existing prompt-hook and next-turn injection seams do not yet provide the requested opt-in non-user memory injection policy.

## What This Changes

Requests an opt-in mechanism for automatic memory or lesson injection during agent-initiated turns such as subagent, heartbeat, cron, or long-running workflow steps.

## Best Possible Solution

Add a narrow opt-in active-memory or plugin-hook policy on the existing prompt-hook and next-turn injection seams, avoiding a new heavy orchestration layer unless maintainers choose that direction.

Yes, at source level: active-memory returns early for non-user triggers, and current tests assert heartbeat contexts do not run recall. I did not run an end-to-end live repro in this read-only review.

## Solution Assessment

No, not as the broad step/periodic/API/hook menu currently written. The best path is a narrow maintainer decision around existing hook seams, active-memory eligibility, and opt-in config or API behavior.
