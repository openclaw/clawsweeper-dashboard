## Summary

Keep open: current main and the latest release still implement active memory as an interactive user-triggered chat feature, while existing prompt and next-turn hook seams do not yet provide the requested opt-in non-user auto-recall policy.

## What This Changes

The issue requests an opt-in mechanism for memory or lesson context to be injected during agent-initiated turns rather than only user-message-triggered prompt builds.

## Best Possible Solution

Keep this open for a narrow plugin/API design that reuses existing prompt and next-turn injection seams while adding an explicit opt-in active-memory policy for approved non-user triggers.

## Reproduction Assessment

Yes, at source level: calling active-memory's `before_prompt_build` path with a non-user trigger reaches the eligibility gate and returns no recall context, and a current test asserts the heartbeat case. I did not run a live end-to-end repro in this read-only review.

## Solution Assessment

No, not as the broad step-triggered, periodic, API, or new lifecycle-hook proposal currently written. The best path is a narrow maintainer-approved opt-in policy on the existing active-memory and plugin hook seams.
