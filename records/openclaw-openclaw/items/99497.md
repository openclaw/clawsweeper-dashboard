## Summary

Keep open: current main has generic prompt/next-turn hook seams, but the bundled active-memory path still intentionally skips non-user triggers, so the requested opt-in non-user recall behavior remains unresolved.

## What This Changes

Requested opt-in automatic context or lesson injection during agent-initiated work such as subagent, cron, heartbeat, or long-running workflow turns.

## Best Possible Solution

Reuse the existing plugin prompt-hook and next-turn injection seams, then add a narrow opt-in active-memory policy for approved non-user triggers instead of adding a heavy new orchestration layer.

## Reproduction Assessment

Yes, at source level: active-memory returns early for non-`user` triggers, and tests assert heartbeat contexts do not run recall. I did not run an end-to-end repro in this read-only review.

## Solution Assessment

No, not as the broad step/periodic/API proposal currently written. The best path is a narrow product decision around existing hook seams and active-memory opt-in behavior.
