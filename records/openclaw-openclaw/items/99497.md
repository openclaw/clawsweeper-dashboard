## Summary

Keep open: current main has generic prompt-hook and next-turn injection seams, but Active Memory still deliberately skips non-user triggers, so the requested opt-in agent-initiated recall behavior remains unresolved and needs maintainer product/API direction.

## What This Changes

Request an opt-in mechanism for automatic memory/context injection during agent-driven turns such as subagent, heartbeat, cron, or long-running workflow steps.

## Best Possible Solution

Define a narrow opt-in Active Memory policy on top of the existing prompt-hook and next-turn injection seams, and extend lifecycle hooks only where the current plugin API cannot express the needed trigger safely.

## Reproduction Assessment

Yes, at source level: Active Memory returns no recall context for non-`user` triggers, and the current test suite asserts heartbeat contexts do not run recall. I did not run a live end-to-end reproduction in this read-only review.

## Solution Assessment

No, not as the broad step/periodic/API proposal currently written. The best path is a maintainer-approved, opt-in policy using existing hook seams first, with any new lifecycle hook shaped alongside the broader hook tracker.
