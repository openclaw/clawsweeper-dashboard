## Summary

Keep open: current main still keeps the Control UI shared gateway token session-scoped, reconnect sends no token when that session value and any readable device token are absent, and the v2026.6.11-to-main diff does not contain an Android background/resume auth fix. The remaining fix is security/product-sensitive because it changes how gateway auth survives mobile browser lifecycle events.

## What This Changes

The issue asks for Control UI WebChat on Android to reconnect after brief backgrounding using the existing authenticated state instead of prompting again for the gateway token.

## Best Possible Solution

Define and test a mobile-safe Control UI resume path, preferably device/session auth or explicit remember-device behavior, while keeping shared gateway tokens out of durable storage by default.

## Reproduction Assessment

Source-level yes for the missing-token failure path, but no for the exact Android background/resume storage-loss point in this pass. Current main makes the reported gateway error reproducible whenever the session-scoped Control UI token and readable device token are absent before reconnect.

## Solution Assessment

Unclear until maintainers choose the security boundary. The best fix is not durable shared-token localStorage by default; it should be a mobile-safe resume or device/session auth path with Android proof and credential-exposure review.
