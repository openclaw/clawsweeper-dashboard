## What This Changes

The issue reports Android mobile Control UI/WebChat losing gateway auth after brief backgrounding, reconnecting without a token, and prompting for the token again.

## Best Possible Solution

Define and test a mobile-safe Control UI resume path through paired device/session auth or explicit remember-device behavior while keeping shared gateway tokens out of durable storage by default.

Do we have a high-confidence way to reproduce the issue? Source-level yes for the missing-token failure when Control UI reloads or reconnects without a session token; no live Android background/resume repro was performed in this read-only review.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainers choose the security boundary; the best direction is a mobile-safe resume or paired-device/session auth path, not silent durable shared-token persistence.
