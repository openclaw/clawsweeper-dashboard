## Summary

Keep open: current main still keeps the Control UI shared gateway token session-scoped, reconnect sends no shared token once that session value is absent, and the v2026.6.11-to-main diff does not contain a mobile background/resume recovery fix. The remaining work is security-sensitive because the fix changes how browser-held gateway auth survives mobile lifecycle events.

## What This Changes

The issue reports that Control UI WebChat on Android mobile browsers loses or omits the stored gateway token after a short background/resume cycle and repeatedly prompts for re-authentication.

## Best Possible Solution

Define and test a mobile-safe Control UI resume path, preferably through paired device/session auth or explicit remember-device behavior, while keeping shared gateway tokens out of durable storage by default.

## Reproduction Assessment

Source-level yes for the missing-token failure: current main sends no shared token once the session-scoped UI token is absent, and gateway auth rejects that as token_missing. No live Android background/resume reproduction was run in this read-only pass.

## Solution Assessment

Unclear until maintainers choose the security boundary. The safest direction is not durable localStorage by default; it should be a mobile-safe resume or device/session auth path with Android proof and credential-exposure review.
