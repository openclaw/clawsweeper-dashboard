## Summary

Keep open: current main still keeps the Control UI gateway token session-scoped, so a reconnect after that session value disappears can still send no token and hit the reported `token_missing` gateway path. The release-to-main diff in the inspected auth/reconnect files does not contain a mobile background/resume fix, and the remaining work needs maintainer security/product direction plus live Android proof.

## What This Changes

The issue requests that mobile Control UI WebChat reconnect after brief Android backgrounding reuse prior authentication instead of prompting for the gateway token again.

## Best Possible Solution

Define and test a mobile-safe Control UI resume path, preferably through paired device/session auth or an explicit remember-device flow, while keeping shared gateway tokens out of durable storage by default.

## Reproduction Assessment

No high-confidence live reproduction for the full Android background case was established in this read-only pass. Source inspection does reproduce the gateway symptom: if the session-scoped token is absent before reconnect, the client sends no token and the gateway returns `token_missing`.

## Solution Assessment

Unclear until maintainers choose the security boundary. The best direction is not durable localStorage by default; it should be a mobile-safe resume or device/session auth path with Android proof and credential-exposure review.
