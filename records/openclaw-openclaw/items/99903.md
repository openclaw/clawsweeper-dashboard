## Summary

Keep open: current main still uses a session-scoped Control UI gateway token, the latest release-to-main diff does not show a mobile background-resume auth fix, and the report has detailed Android `authProvided=none` / `token_missing` evidence. The remaining fix is security-sensitive because it touches how long the gateway bearer or device auth state is stored, so this should be maintainer-owned rather than auto-repaired.

## What This Changes

The issue reports Control UI WebChat on Android losing gateway auth after brief backgrounding and reconnecting without a token, causing repeated `1008 token_missing` prompts.

## Best Possible Solution

Define and test a mobile-safe Control UI resume path, preferably via paired device/session auth or explicit remember-device behavior, while keeping shared gateway tokens out of durable storage by default.

## Reproduction Assessment

Yes at source level, but not as a live Android reproduction. Current main stores the shared token in sessionStorage and reconnects from `host.settings.token`; when that value is empty, the gateway returns the exact `token_missing` 1008 path shown in the report.

## Solution Assessment

Unclear. The narrow fix must preserve credential safety; silently persisting the shared token longer would be the wrong layer without maintainer approval, so the better direction is a device/session resume mechanism with Android proof.
