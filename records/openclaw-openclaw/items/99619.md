## Summary

The previous runtime-key matching concern is addressed and the new terminal proof is credible. However, the branch still treats configured-but-inactive model policies as stale even though the model map is also a supported selectable-model catalog, and it duplicates the runtime matcher inside doctor. These are blocking compatibility and maintenance defects; the protected `maintainer` label also requires explicit owner review of the default warning semantics.

## What This Changes

The PR adds a doctor lint check and default doctor health contribution that warn when active agent model references and explicit per-model `agentRuntime` policies do not match.

## Best Possible Solution

Share a canonical runtime-policy match helper with the agent runtime, warn only when an active model lacks the policy expected by effective configuration, treat inactive allowlisted model entries as valid, and prove both fresh and existing multi-model configurations before enabling the default health contribution.
