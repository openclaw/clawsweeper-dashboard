## Best Possible Solution

Keep the embedded TUI event subscriber fire-and-forget, but isolate and log handler failures without polluting the terminal or allowing an unhandled rejection to terminate the process.

## Reproduction Assessment

## Solution Assessment

Yes, this is a narrow acceptable fix: the event listener remains fire-and-forget while rejected handler work is observed and logged. Removing `async` would avoid this specific rejection shape but would rely on the event bus swallowing synchronous throws without the new diagnostic.
