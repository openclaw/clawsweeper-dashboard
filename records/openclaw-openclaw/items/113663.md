## Summary

Keep this PR open for merge review: it uses the existing provider-header seam to address a complete OAuth inference failure, and the submitted authenticated 426-versus-200 probe is meaningful after-fix evidence. The remaining decision is whether the new static header may intentionally accompany an operator’s overridden xAI OAuth base URL; that compatibility behavior is not settled by the focused tests. Likely related people: jzakirov, who supplied the endpoint investigation and proposed repair (low-confidence routing signal).

## What This Changes

This PR adds xAI’s required `x-grok-client-version` header to the live-discovery and fallback Grok OAuth provider configurations, with regression tests that keep the API-key route header-free.

## System Context

The xAI plugin creates provider configurations for either API-key access or a Grok subscription OAuth proxy. Those configurations are projected into agent runtime models, whose headers are merged into inference requests to the selected endpoint.
