## Summary

This PR addresses a real P1 xAI OAuth inference failure and includes credible redacted live HTTP proof, but it changes the protocol of every existing `models.providers.xai.baseUrl` override, not only the canonical Grok OAuth proxy. Keep it open until maintainers choose whether custom proxy overrides must remain header-free by default and the implementation preserves that boundary.

## What This Changes

The branch adds a fixed `x-grok-client-version: 0.1.202` header to both xAI OAuth provider catalog paths and tests the live-discovery, fallback, and API-key catalog results.

## System Context

The bundled xAI provider builds a model catalog after OAuth or API-key setup; the resolved provider configuration is then copied into runtime model request settings. This change affects the HTTP headers sent when an agent invokes an xAI OAuth model, while explicit `models.providers.xai` settings can override the provider endpoint.

## Best Possible Solution

Send the built-in Grok compatibility header only when the effective OAuth request target is the canonical `cli-chat-proxy.grok.com` endpoint; leave custom xAI base URLs unchanged unless an operator explicitly configures their own headers.
