## Summary

This PR addresses a real P1 xAI OAuth inference failure and remains necessary because current `main` still builds the Grok OAuth provider without the required request header. The prior configuration-composition blocker remains: a user’s existing `models.providers.xai.headers` replaces the catalog header during implicit-provider merging, so affected OAuth setups can still send no `x-grok-client-version`.

## What This Changes

The PR adds xAI’s required Grok client-version header to the OAuth subscription provider catalog, scopes it to the canonical Grok proxy, and adds catalog tests for discovery, fallback, and API-key routes.

## System Context

The bundled xAI plugin converts configured OAuth or API-key credentials into a model-provider catalog. That catalog is persisted into the agent model runtime, which resolves provider headers and sends inference requests to either xAI’s API endpoint or the Grok subscription proxy.
