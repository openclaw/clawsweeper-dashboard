## What This Changes

The issue asks OpenClaw to count nested Codex app-server `toolResult` block text/content during compaction token estimation so cut-point selection can actually drop summarized history.

## Best Possible Solution

Patch the existing compaction estimator to count nested `toolResult` and `tool_result` text/content payloads, add a focused Codex-shaped regression test, and leave broader safeguard policy work to its separate issue.

Yes from source inspection: current main creates and preserves nested Codex `toolResult` blocks while the compaction estimator counts only `text` and `image` blocks. A focused unit test can reproduce the zero-token estimate and cut-point collapse with the current transcript shape.

## Solution Assessment

Yes. The narrowest maintainable fix is to extend the existing content-block accounting path and add regression coverage for the Codex app-server transcript shape, without changing compaction defaults or Slack recovery policy.
