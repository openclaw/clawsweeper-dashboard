## Summary

Keep this PR open: the intended Mattermost DM reply metadata fix is useful, but the current patch still wires hydration to the thread/session id that current main deliberately suppresses for direct messages, and the supplied proof does not show a real after-fix Mattermost DM payload.

## What This Changes

The PR adds a Mattermost post fetch/cache, a reply-context helper, and tests so inbound Mattermost contexts can include `ReplyToBody` and `ReplyToSender`.

## Best Possible Solution

Separate reply metadata hydration from Mattermost thread/session routing, keep direct messages non-threaded by default, add monitor-level DM coverage, and require redacted live payload proof before merge.

## Reproduction Assessment

Yes, source-level. Current main intentionally returns `undefined` for direct-message `effectiveReplyToId`, and the PR passes that value into the new hydration helper, so the advertised DM reply lookup does not run for direct chats.

## Solution Assessment

No. The helper shape is plausible, but it should receive a separate reply-target metadata id instead of reusing the direct-message thread/session routing id.
