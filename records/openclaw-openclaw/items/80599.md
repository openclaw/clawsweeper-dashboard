## Summary

Keep this PR open, but it is not merge-ready: the new Mattermost reply-context hydration is wired to `effectiveReplyToId`, which is deliberately `undefined` for direct messages, so the advertised DM reply metadata path still does not run.

## What This Changes

The PR adds a Mattermost post fetch/cache, reply-context helper, and tests to populate `ReplyToBody` and `ReplyToSender` for reply targets in inbound Mattermost handling.

## Best Possible Solution

Separate reply metadata hydration from Mattermost thread/session routing, keep direct messages non-threaded by default, add monitor-level DM coverage, resolve conflicts, and require redacted live payload proof.

## Reproduction Assessment

Yes, source-level. Current main and the PR head return `undefined` for direct-message `effectiveReplyToId`, and the PR passes that value into the new hydration helper, so the advertised DM reply lookup does not run for direct chats.

## Solution Assessment

No. The helper shape is plausible, but it should receive a separate reply-target metadata id instead of reusing the direct-message thread/session routing id.
