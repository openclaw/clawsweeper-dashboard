## Summary

Keep open: the requested Mattermost DM reply metadata is still useful and not present on current main, but this PR is not merge-ready because it hydrates from `effectiveReplyToId`, which current main intentionally suppresses for direct chats, and the supplied proof does not show a real DM reply payload.

## What This Changes

The branch adds a Mattermost post fetch/cache, reply-context helper, and tests to populate `ReplyToBody` and `ReplyToSender` for reply targets in inbound Mattermost handling.

## Best Possible Solution

Separate reply metadata hydration from Mattermost thread/session routing, keep direct messages non-threaded by default, add monitor-level DM coverage, resolve conflicts, and require redacted live payload proof.

## Reproduction Assessment

Yes, source-level. Current main intentionally returns `undefined` for direct-message `effectiveReplyToId`, and the PR passes that value into the new hydration helper, so the advertised DM reply lookup does not run for direct chats.

## Solution Assessment

No. The helper shape is plausible, but it should receive a separate reply-target metadata id instead of reusing the direct-message thread/session routing id.
