## Summary

Keep open: current main and the latest release still take the strict managed-proxy branch through local `resolvePinnedHostnameWithPolicy()` before selecting the env proxy dispatcher, so the central proxy-only DNS failure remains valid.

## What This Changes

The issue asks for `fetchWithSsrFGuard` strict/default mode to skip local target DNS when OpenClaw's managed proxy lifecycle is active and the env proxy applies, while preserving strict direct-mode SSRF checks elsewhere.

## Best Possible Solution

Adjust `fetchWithSsrFGuard` so strict managed-proxy traffic that should use the env proxy performs only pre-DNS hostname and IP-literal checks before dispatch, while preserving direct-mode DNS pinning, `NO_PROXY` fallback behavior, configured-local-origin bypass policy, redirect revalidation, and focused regression coverage.

## Reproduction Assessment

Yes from source, not from a live run: with `OPENCLAW_PROXY_ACTIVE=1`, proxy env configured, and strict/default mode, current main enters `canUseManagedProxy` and calls `resolvePinnedHostnameWithPolicy()` before the env proxy dispatcher. A focused regression can use a failing `lookupFn` to prove the proxy is never reached.

## Solution Assessment

Unclear until security owner review: the lower-level fetch guard is the right boundary because many callers default to strict mode, but maintainers need to accept the managed proxy as the final DNS/IP enforcement boundary for this branch.
