## Summary

Keep open: current main and the latest release still perform local DNS resolution in the strict managed-proxy branch before dispatching through the env proxy, and the focused fixing PR is still open rather than merged.

## What This Changes

The issue requests that strict/default guarded fetches skip local DNS pinning only when the OpenClaw managed proxy lifecycle is active and the env proxy applies, while preserving direct-mode DNS pinning and pre-DNS SSRF checks.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/98951, or an equivalent maintainer-approved guarded-fetch fix, so active managed-proxy strict/default fetches skip local target DNS while direct strict mode, configured loopback bypass, blocked targets, and redirects remain covered.

## Reproduction Assessment

Yes from source inspection: current main defaults omitted mode to STRICT, then enters a managed-proxy branch that calls resolvePinnedHostnameWithPolicy before creating the env proxy dispatcher. I did not run a live proxy-only sandbox in this read-only review, but the code path and missing regression assertion are clear.

## Solution Assessment

Unclear until maintainer/security review of the linked PR finishes: the shared guarded-fetch layer is the right scope because many callers default to strict mode, but maintainers must accept the managed proxy as the target DNS and resolved-IP enforcement boundary for this branch.
