## Summary

Keep open: current main and the latest release still resolve target DNS inside the strict managed-proxy branch before creating the env proxy dispatcher, and the open linked fix PR has not merged yet.

## What This Changes

This issue requests that strict/default guarded fetches skip local DNS pinning only when the managed proxy lifecycle is active and the env proxy applies to the target.

## Best Possible Solution

Review and land or explicitly replace https://github.com/openclaw/openclaw/pull/98951; after that PR merges, close this issue as implemented with the merge commit and release provenance.

## Reproduction Assessment

Yes. From current source, strict/default mode with `OPENCLAW_PROXY_ACTIVE=1` and proxy env configured enters the managed-proxy branch and calls `resolvePinnedHostnameWithPolicy()` before creating the env proxy dispatcher.

## Solution Assessment

Mostly yes. The shared fetch guard is the right layer because many callers omit `mode` and default to strict, but the final fix still needs maintainer/security acceptance of proxy-owned DNS enforcement.
