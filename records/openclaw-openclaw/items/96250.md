## Summary

The latest head is a substantial improvement over the fixed 8192 MiB version, but it is not merge-ready: reinstalling feeds the service’s previously generated heap flag back as an explicit override, so the adaptive value becomes sticky after the first install and can be wrong after host or cgroup memory changes. The PR also lacks current-head real service proof for the adaptive install and new status/doctor reporting paths.

## What This Changes

Adds a constrained-memory-aware heap limit for managed Gateway services, preserves an installed heap flag, and reports the applied/default heap policy through gateway status and doctor.

## Best Possible Solution

Make auto-generated heap values recompute from the current service resource budget on regeneration while preserving only a distinguishable explicit operator choice, have status/doctor report that provenance accurately, and prove the latest head on a real managed service including a memory-limit change.
