## Summary

Keep this PR open: the runtime fix addresses a real current-main unbounded process-local cache, but the new eviction unit test needs a small tightening because it can pass without proving eviction.

## What This Changes

The PR adds a 4096-entry touch-on-read LRU cap to the private session-maintenance warning context cache and adds focused tests for eviction and changed warning contexts.

## Best Possible Solution

Keep the private bounded LRU cache, tighten the eviction regression test so it fails if eviction breaks, then land after normal exact-head gates.

Yes. Source inspection shows current main writes every new warned session context into a module-level Map with no size cap, and the reply-session maintenance caller can supply distinct session keys over time.

## Solution Assessment

Yes for the runtime code: a private bounded LRU map preserves the public API and the one-context-per-session dedupe model. The test should be strengthened because the current eviction assertion can pass for a context-change reason instead of an eviction reason.
