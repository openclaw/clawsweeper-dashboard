## Summary

Keep this draft PR open: it still converts a targetless `delivery.mode="announce"` request into an isolated job even though current delivery planning resolves that form through the contextual `last` target, and it lacks after-fix runtime delivery proof. The broader choice to reinterpret a `systemEvent` as an isolated agent turn also needs maintainer product direction.

## What This Changes

The PR changes unpinned `systemEvent` cron jobs with announce-style delivery into isolated `agentTurn` jobs and adds normalization coverage for an explicit Telegram target.

## Best Possible Solution

Define the supported system-event-plus-delivery contract, preserve validation for targetless announce requests unless maintainers explicitly support inherited routing, then add coverage and redacted live evidence showing creation, execution, and one delivery to the requested destination.
