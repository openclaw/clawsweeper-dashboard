## Summary

Keep open: current main and v2026.6.11 still lack WebChat/Control UI inline presentation projection, an authenticated click callback RPC, a Control UI button render/click path, and a settled capability/config policy. The issue remains the canonical tracker and should stay gated on maintainer product/security direction.

## What This Changes

Request to add WebChat/Control UI inline button support, including chat event payloads, click callback handling, rendering, and optional capability configuration.

## Best Possible Solution

Settle a v1 around shared typed presentation actions, sanitized final-only WebChat projection, an authenticated chat.callback RPC, and Control UI rendering/click state, while deferring webhook routing to a separate hardened design.

## Solution Assessment

Unclear until maintainers choose the public contract. The best-supported direction is typed presentation actions plus authenticated Gateway RPC, with legacy buttons and webhook routing deferred unless explicitly approved.
