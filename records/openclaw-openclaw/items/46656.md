## Summary

Keep open: current main still lacks WebChat/Control UI inline-button rendering, a click callback RPC, and a settled capability/config contract; the discussion now treats this issue as the canonical design tracker needing maintainer product and security direction.

## What This Changes

Request to add WebChat/Control UI inline button rendering, an authenticated callback path for clicks, and a capability/config contract for message presentation buttons.

## Best Possible Solution

Settle a shared presentation-based WebChat contract first, then implement final-only Control UI rendering plus an authenticated chat.callback RPC; defer webhook routing unless maintainers approve a separate hardened design.

Status: needs_attention

Summary: No patch is under review, but the requested callback and optional webhook surfaces are security-sensitive and need explicit design review before implementation.

Concerns:

- **[medium] Bind callbacks to authenticated session/action state:**
  - body: A chat.callback RPC must validate operator scope, session/message binding, typed action payloads, replay/idempotency, and clicked/disabled semantics so forged or stale clicks cannot trigger unintended agent actions.
  - confidence: 0.86
- **[medium] Defer or harden webhook routing:**
  - body: A configurable callbackWebhookUrl would add outbound HTTP and SSRF risk plus auth and secret-handling questions, so it should stay out of v1 unless maintainers approve a hardened design.
