## Summary

Keep open: current main and v2026.6.11 still lack WebChat/Control UI inline-button delivery, an authenticated `chat.callback` RPC, a WebChat capability/config contract, and Control UI rendering/click handling. The discussion keeps #46656 as the canonical tracker, but the first implementation needs maintainer product and security direction.

## What This Changes

Request WebChat/Control UI inline buttons with capability gating, final chat event presentation, callback RPC, and Control UI rendering/click handling.

## Best Possible Solution

Use shared `presentation` typed actions, expose sanitized final-only interactive blocks through chat events/history, add an authenticated `chat.callback` RPC for the same session, render clicked/disabled state in Control UI, and defer webhook routing.

## Reproduction Assessment

Yes at source level: current schemas, Gateway method registration, Control UI event/type/normalizer/render paths, and WebChat docs have no WebChat inline-button or callback path; no live UI repro was run because this is a read-only feature review.

## Solution Assessment

No, not as originally proposed with legacy `buttons` and optional webhook routing; the maintainable path is shared typed `presentation` actions plus an authenticated Gateway RPC, with webhook routing deferred or separately hardened.
