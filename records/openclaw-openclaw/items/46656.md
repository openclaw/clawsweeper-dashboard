Settle a v1 contract around shared typed presentation actions, authenticated `chat.callback`, final-only sanitized chat projection, and Control UI rendering before deciding whether any default-off WebChat capability config is needed.

## Reproduction Assessment

Yes, at source level: current main has no `chat.callback` method, no WebChat inline button/presentation projection in chat events, and no Control UI message item or click path for buttons. I did not run a live WebChat session because the missing source paths directly establish the feature gap.

## Solution Assessment

Unclear until maintainers choose the public contract. The best-supported direction is typed presentation actions over legacy `buttons`, authenticated Gateway RPC over a parallel HTTP endpoint, and deferred webhook routing.
