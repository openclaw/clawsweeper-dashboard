## Summary

Keep open: current main and v2026.6.11 still synthesize a large maxTokens fallback for configured fallback models and the OpenAI-completions transport still forwards that value as max_completion_tokens. This issue is now paired with active linked fix PRs, so it should stay open until one lands rather than queueing another competing repair.

## What This Changes

The issue asks OpenClaw to stop sending an invalid oversized max_completion_tokens value for custom Xiaomi MiMo model entries that omit maxTokens.

## Best Possible Solution

Land the cleanest narrow fix that stops invented output caps from reaching OpenAI-compatible providers when maxTokens is omitted, then close this issue as implemented with source and release proof.
