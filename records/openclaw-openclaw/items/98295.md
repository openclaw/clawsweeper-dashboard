## Summary

Keep open: current main still contains a source-visible path where missing custom model maxTokens can fall through to DEFAULT_CONTEXT_TOKENS and then be forwarded by the OpenAI-completions transport, and several open PRs with closing references already own candidate fixes.

## What This Changes

The issue reports that custom Xiaomi MiMo model rows without maxTokens can make OpenClaw send an oversized max_completion_tokens value that Xiaomi rejects.

## Best Possible Solution

Land one focused linked fix that prevents synthesized DEFAULT_CONTEXT_TOKENS from being sent as an output cap for custom OpenAI-compatible models without maxTokens, with regression coverage for model resolution and the outbound payload.
