## Summary

Keep open: current main and the latest release still have a source-reproducible path where configured custom Xiaomi/OpenAI-compatible models without `maxTokens` can receive `DEFAULT_CONTEXT_TOKENS` as a wire-facing output cap. Multiple open linked PRs already target this bug, so the issue should stay open until one canonical fix lands.

## What This Changes

The issue reports custom Xiaomi MiMo model rows without `maxTokens` causing OpenClaw to send an oversized `max_completion_tokens` value that Xiaomi rejects with HTTP 400.

## Best Possible Solution

Land one canonical resolver fix that prevents unconfigured custom-provider rows from sending a synthesized oversized output cap, then close or pause the duplicate candidate PRs.
