## Summary

Keep open: current main and the latest release still have a source-reproducible path where an omitted custom-model `maxTokens` becomes a synthesized `DEFAULT_CONTEXT_TOKENS` cap and is forwarded as `max_completion_tokens`. The remaining repair is already owned by open linked candidate PRs, with https://github.com/openclaw/openclaw/pull/98430 currently the cleanest proof-positive candidate.

## What This Changes

Prevent custom Xiaomi MiMo model entries without `maxTokens` from generating an over-limit `max_completion_tokens` request parameter.

## Best Possible Solution

Land one canonical resolver fix, preferably https://github.com/openclaw/openclaw/pull/98430 if maintainers accept its omitted-cap semantics, then close this issue as implemented.
