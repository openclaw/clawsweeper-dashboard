## Summary

The report does not match current `main`: gateway password authentication performs a constant-time comparison of two SHA-256 digests, not synchronous password key derivation, and the reported files do not exist. The discussion identifies a valid general Node.js concern, but provides no load trace or reproduction showing that this small comparison causes WebSocket timeouts.

## What This Changes

Replace allegedly synchronous password hashing and verification in gateway authentication with asynchronous execution to avoid login-related event-loop stalls.

## Best Possible Solution

Keep the current constant-time shared-secret comparison; if login bursts cause measurable stalls, open a new report with a current-version concurrency script, event-loop-delay profile, request rate, credential mode, and WebSocket disconnect evidence before changing the authentication primitive.
