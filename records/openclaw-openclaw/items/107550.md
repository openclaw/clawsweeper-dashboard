## Summary

Current main does not contain the reported password-hashing path: gateway passwords are directly compared as bounded UTF-8 byte strings with `timingSafeEqual`, without a password KDF, synchronous hashing loop, or thread-pool operation. The proposed async crypto conversion therefore targets behavior that is not present in the repository. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/security/secret-equal.ts))

## What This Changes

Investigate and replace allegedly synchronous gateway password hashing with asynchronous validation to prevent login bursts from blocking WebSocket clients.

## Best Possible Solution

Keep the current constant-time comparison; if gateway stalls are observed, open a new report with a current SHA, event-loop profile, login-load parameters, and a stack trace identifying the actual blocking function.

## Solution Assessment

No. Moving password hashing to async crypto or worker threads would solve a different implementation; any real event-loop stall should instead be profiled and fixed at the function actually consuming CPU.
