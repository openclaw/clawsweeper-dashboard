## Summary

The report does not match current or shipped gateway authentication: the named files and password-hashing path are absent, while password authentication performs a small constant-time SHA-256 comparison rather than a password KDF capable of causing the alleged starvation.

## What This Changes

Replace allegedly synchronous gateway password hashing with asynchronous validation to prevent authentication bursts from blocking active WebSocket clients.

## Best Possible Solution

Keep the current bounded constant-time shared-secret comparison; open a new performance report only if profiling on a current release shows measurable event-loop delay, including the tested version, load shape, event-loop-lag data, and stacks identifying the actual hot path.
