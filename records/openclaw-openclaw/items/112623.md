## Summary

This PR has focused coverage and credible after-fix runtime proof, but it intentionally changes the default system-prompt context for existing multi-agent sessions. Keep it open for an explicit maintainer decision on that orchestration policy rather than treating it as a routine bug fix.

## What This Changes

The PR adds a bounded `Recently Completed Subagents` block to later parent-agent prompts, documents the behavior, and tests recent-only, mixed, and overflow cases.

## System Context

The subagent registry records active and completed child runs for a parent session. The parent prompt currently receives active-child status; this PR would also pass a short, bounded set of recently completed child anchors into later parent turns so the parent can avoid repeating completed work.

## Architecture Diagram

  B --> C[Active and recent child lists]
  C --> D[Bounded prompt context]
  D --> E[Parent decides to spawn or yield]
  E --> F[Completion handoff and reply]

## Best Possible Solution

Adopt the bounded 30-minute, newest-eight completion-anchor block only if maintainers explicitly want default parent prompts to retain this short-lived orchestration memory; otherwise keep the active-only prompt and improve the existing completion-handoff or inspection path instead.
