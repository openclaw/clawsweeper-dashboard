## Summary

Keep open: current main and the latest release still expose xAI buffered TTS only, while the shared streaming TTS path skips providers without `streamSynthesize`; the linked implementation attempts were closed unmerged, so no canonical landed fix owns this yet.

## What This Changes

Request native xAI streaming TTS over `wss://api.x.ai/v1/tts` for OpenClaw streaming speech callers while preserving existing buffered xAI TTS behavior.

## Best Possible Solution

Add provider-local xAI `streamSynthesize` support with focused fake-WebSocket tests, docs that distinguish streaming TTS from realtime voice, and redacted live xAI proof before merge.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes for the source-level capability gap: current main has a streaming speech contract, but the xAI speech provider does not implement `streamSynthesize`.

## Solution Assessment

Is this the best way to solve the issue? Yes: the narrow maintainable path is an xAI-plugin-owned streaming implementation using the existing provider hook, not a core rewrite or realtime voice conflation.
