## Summary

Keep open: current main still lacks native xAI streaming TTS because the bundled xAI speech provider implements buffered and telephony synthesis only, and both closing PR attempts for this issue are closed unmerged.

## What This Changes

Request native xAI streaming TTS WebSocket support for OpenClaw speech-provider streaming callers while preserving existing buffered xAI TTS behavior.

## Best Possible Solution

Add a provider-local `streamSynthesize` implementation in `extensions/xai` for the native xAI `/v1/tts` WebSocket flow, with focused tests, docs, and live proof when credentials are available.

## Reproduction Assessment

Yes for the source-level feature gap: current main has a shared streaming TTS hook, but xAI does not implement `streamSynthesize`. This is not a broken existing-contract bug reproduction because xAI streaming TTS is currently documented as not exposed.

## Solution Assessment

Yes. The narrow maintainable solution is to add the existing streaming speech hook inside the xAI plugin, preserve buffered TTS, and keep it separate from xAI realtime voice.

## Repair Work Prompt

Implement native xAI streaming TTS for the existing speech provider contract. Add `streamSynthesize` in `extensions/xai/speech-provider.ts` and a provider-local helper in `extensions/xai/tts.ts` that connects only to the native xAI `wss://api.x.ai/v1/tts` endpoint, sends `text.delta` then `text.done`, decodes `audio.delta` chunks until `audio.done`, preserves release/timeout/error behavior, and keeps buffered `synthesize` and `synthesizeTelephony` unchanged. Do not add new config knobs, do not broaden custom `baseUrl` semantics, and avoid new runtime dependencies unless absolutely necessary and explicitly justified. Use the closed PRs https://github.com/openclaw/openclaw/pull/99868 and https://github.com/openclaw/openclaw/pull/99883 only as context, not as an automatic merge source. Update `docs/providers/xai.md` to distinguish streaming TTS from realtime voice and add focused tests for URL shape, event protocol, lifecycle/release behavior, timeout/error handling, and `streamSynthesize` integration. If live xAI credentials are available, include redacted smoke proof showing `text.delta`/`text.done` to `audio.delta`/`audio.done` with non-empty audio bytes; otherwise state that live proof is still missing.
