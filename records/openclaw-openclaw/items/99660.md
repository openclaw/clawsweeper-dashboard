## Summary

Keep open: current main and the latest release still expose xAI buffered TTS only; the shared streaming TTS hook exists, but xAI is skipped because its speech provider has no `streamSynthesize`, and the related implementation PRs closed unmerged.

## What This Changes

Request native xAI streaming TTS WebSocket support for OpenClaw's shared speech-provider streaming contract while preserving existing buffered xAI TTS.

## Best Possible Solution

Add a provider-local `streamSynthesize` implementation in `extensions/xai` for native `wss://api.x.ai/v1/tts`, with focused unit tests, docs that distinguish streaming TTS from realtime voice, and live-service proof when credentials are available.

## Reproduction Assessment

Yes for source-level verification, not as a bug reproduction: current xAI speech provider code lacks `streamSynthesize`, and the shared `textToSpeechStream` path skips providers without that hook.

## Solution Assessment

Yes. The narrow maintainable solution is to add the existing streaming speech hook inside the xAI plugin while preserving buffered TTS and keeping realtime voice out of scope.
