## Summary

Keep open: current main still has buffered xAI TTS and the shared streaming TTS hook, but the xAI speech provider does not implement `streamSynthesize`; the related same-purpose PRs were closed unmerged and do not currently own the remaining work.

## What This Changes

The issue requests native xAI streaming TTS WebSocket support for shared `textToSpeechStream` callers while preserving existing buffered xAI TTS behavior.

## Best Possible Solution

Add a provider-local xAI `streamSynthesize` implementation that uses the native TTS WebSocket contract, preserves buffered `synthesize`, updates focused tests/docs, and includes redacted live-service proof before merge.

## Reproduction Assessment

Yes from source inspection: current `main` has the shared `textToSpeechStream` path and skips providers without `streamSynthesize`, while the xAI provider only implements buffered and telephony synthesis.

## Solution Assessment

Yes, with proof requirements: implementing `streamSynthesize` inside the xAI plugin is the narrow owner-boundary fix, but it should not merge without live xAI WebSocket proof and native-host restriction coverage.
