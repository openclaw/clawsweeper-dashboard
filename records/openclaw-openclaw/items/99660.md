## Summary

Keep open: current main has buffered xAI TTS and the shared streaming speech contract, but the bundled xAI speech provider does not implement `streamSynthesize`, so streaming callers still skip xAI and fall back to file synthesis.

## What This Changes

The issue requests native xAI WebSocket streaming TTS support for `messages.tts.provider: "xai"` and `textToSpeechStream` callers without changing the existing buffered xAI TTS path.

## Best Possible Solution

Add an xAI-owned `streamSynthesize` implementation in the bundled xAI plugin using the existing speech provider streaming contract, with no new config knobs and docs that keep streaming TTS distinct from xAI realtime voice.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature request. Source inspection does give a high-confidence current-main check: xAI lacks `streamSynthesize`, so streaming speech callers cannot use native xAI streaming TTS today.

## Solution Assessment

Yes, the requested direction is the maintainable owner-boundary path: implement the existing `streamSynthesize` hook inside `extensions/xai` and keep the buffered REST TTS and realtime voice paths separate.
