## Summary

Keep open: current main still exposes xAI buffered TTS but not native streaming TTS, and the two same-scope PRs were closed unmerged. Adjacent xAI realtime voice and streaming transcription work does not implement the shared `streamSynthesize` TTS hook.

## What This Changes

Add native xAI streaming TTS WebSocket support for `messages.tts.provider: "xai"` streaming playback callers while preserving the existing buffered TTS path.

## Best Possible Solution

Implement `streamSynthesize` inside the xAI plugin using the native xAI TTS WebSocket protocol, preserve buffered TTS and telephony behavior, and require focused tests plus redacted live-service proof before merge.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature request. Source inspection gives a high-confidence current-main check: xAI lacks `streamSynthesize`, and the shared streaming path skips providers without that hook.

## Solution Assessment

Yes, the requested provider-local `streamSynthesize` implementation is the narrow maintainable path because the plugin SDK already has the hook and a sibling provider uses it. The remaining blocker is live xAI WebSocket proof and careful fallback behavior, not a new core API.
