## Summary

Keep this PR open: the test-portability idea is still useful because current main and v2026.6.11 still skip these refresh symlink tests on Windows, but the patch is not merge-ready because it probes Windows junction creation while enabling test bodies that still create `dir` symlinks, and the external real-behavior proof gate is still missing.

## What This Changes

The PR adds a directory-symlink capability probe to `src/skills/runtime/refresh.test.ts` and uses it to gate four refresh watcher symlink tests instead of skipping all Windows hosts.

## Best Possible Solution

Keep the test-portability direction, but use one directory-link helper or an exact capability probe for both the gate and every gated symlink setup, then add redacted real Windows/test-command proof.

## Reproduction Assessment

Yes for the review defect: source inspection shows the new Windows gate probes `junction` creation while the enabled test bodies still call `fs.symlink(..., "dir")`. I did not run a Windows host in this read-only review.

## Solution Assessment

No. The owner boundary is right for a test-only change, but the implementation should use one helper or exact capability for both the probe and the symlink creation instead of enabling tests with a different link type.
