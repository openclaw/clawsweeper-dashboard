Keep open: current main now supports macOS `sessions.create`, but it still owns one normal WebChat window and switches/closes that surface in place, so independent parallel desktop chat windows remain unresolved product work.

## What This Changes

The issue requests multi-window desktop session support so opening a new conversation window does not pause or replace an existing active session.

Define a maintainer-approved macOS window/session ownership model, then implement keyed WebChat window controllers that let one active run continue while another session opens, with native desktop proof.
