## Summary

Keep open: current main and v2026.6.11 still keep macOS WebChat to one normal window, and the shared native `/new` path still resets when create-session is unsupported, so the requested parallel desktop windows remain unresolved product work.

## What This Changes

Request multi-window desktop chat support so starting a new conversation window does not pause, reset, or interrupt existing active sessions.

## Best Possible Solution

Define the desktop session/window ownership model, then implement macOS WebChat windows keyed by session with `sessions.create` support and proof that one active run survives opening another chat window.
