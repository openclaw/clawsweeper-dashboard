## Summary

Keep open: current main still has the reported authorization/data-exposure path, and the latest release also contains the unscoped `/acp sessions` listing. This is a security-boundary bug, not stale cleanup.

## What This Changes

The issue reports that authorized non-owner command senders can use `/acp sessions` to enumerate gateway-wide ACP session metadata instead of only requester-scoped sessions.

## Best Possible Solution

Fix the security boundary so `/acp sessions` can no longer enumerate gateway-wide ACP sessions for authorized non-owners; the docs-aligned end state is a tested requester/current-session scoped listing, with owner-only gating as a safe fallback if scoping cannot be proven quickly.

Rationale: Both paths close the data exposure, but they have different compatibility and UX tradeoffs for authorized non-owner diagnostics, so security-boundary intent should be explicit before implementation lands.

Options:

- **Scope non-owner results (recommended):** Preserve the documented non-owner command by adding sender/session/account scoping to the listing path and regression coverage for a two-session cross-sender case.
- **Owner-gate sessions now:** Move `sessions` into the owner/admin-required ACP action set and update docs/tests, accepting that authorized non-owners lose this diagnostic command.
- **Keep gateway-wide visibility:** Only choose this if maintainers intentionally redefine `/acp sessions` as an owner/admin diagnostic and update the public contract accordingly.

## Reproduction Assessment

Yes, from source inspection: current main lets authorized non-owner `/acp sessions` reach the handler, and that handler queries all ACP session rows without requester scoping. I did not run the live chat flow in this read-only review.

## Solution Assessment

Unclear until maintainers choose the security policy, but the narrow docs-aligned fix is to scope the query to the requester/current bound session. A fail-closed owner gate is the safer hotfix if scoped ownership cannot be proven quickly.
