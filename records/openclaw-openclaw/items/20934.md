## Summary

Keep open. Current main and the latest release still do not provide REST-native `/v1/sessions/*` reset/status/compact/model/reasoning endpoints for HTTP integrations; existing Gateway RPC methods, adjacent history/kill HTTP helpers, the default-off admin HTTP RPC plugin, and related plugin reset work do not fully satisfy this request.

## What This Changes

The issue requests authenticated REST endpoints for HTTP API integrations to reset, inspect, compact, and update Gateway sessions without re-enabling slash-command dispatch in `/v1/chat/completions`.

## Best Possible Solution

Approve one narrow authenticated Gateway HTTP session-management contract that reuses existing session handlers, preserves default-deny slash-command behavior, documents the security boundary, and covers reset/status/compact/model/reasoning with route/auth/request/response tests.
