## Summary

Keep open. Current `origin/main` still lacks the requested REST-native `/v1/sessions/*` reset/status/compact/model/reasoning endpoints for HTTP integrations; existing WebSocket RPCs, adjacent session history/kill HTTP helpers, the default-off admin HTTP RPC plugin, and plugin reset work do not satisfy this public HTTP API request.

## What This Changes

The issue requests authenticated REST session-management endpoints for HTTP API integrations, covering reset, status, compact, model selection, and reasoning controls for sessions addressed by key.

## Best Possible Solution

Approve and implement a narrow authenticated Gateway HTTP session-management layer over existing session handlers, with operator-scope checks, reserved-key validation, route/auth tests, docs, and default-deny slash-command behavior preserved for chat completions.
