## Summary

Keep open. Current main and the latest release still lack the requested REST-native session reset/status/compact/model/reasoning endpoints, while the existing RPC/plugin surfaces and adjacent HTTP helpers only partially overlap and do not solve HTTP integrations using `/v1/chat/completions`.

## What This Changes

The issue requests authenticated REST session-management endpoints for HTTP API integrations to reset, inspect, compact, and update session-scoped model or reasoning settings.

## Best Possible Solution

Keep this issue open for a maintainer-approved Gateway HTTP session-management design that reuses existing typed `sessions.*` handlers/schemas, preserves default-deny slash-command handling, and documents/tests the auth and route contract.

## Reproduction Assessment

Yes. At source level, `/v1/chat/completions` dispatches as normal ingress input without trusted command authorization, and current main has no `/v1/sessions/*` REST alternative for reset/status/compact/model/reasoning.

## Solution Assessment

Unclear until maintainers confirm the product/security contract. The narrow maintainable shape is a thin authenticated adapter over existing Gateway session methods and schemas, not slash-command interpretation or duplicated session logic.
