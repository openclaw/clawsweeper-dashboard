## Summary

Keep open. Current main and the latest release still lack REST-native `/v1/sessions/reset`, `/status`, `/compact`, `/model`, or `/reasoning` endpoints for HTTP integrations; existing WebSocket RPCs, adjacent session history/kill HTTP helpers, the default-off admin HTTP RPC plugin, and plugin reset work do not resolve the requested public HTTP API surface.

## What This Changes

Request a REST session-management API for HTTP integrations using `/v1/chat/completions`, covering reset, status, compaction, model changes, and reasoning changes by session key.

## Best Possible Solution

Approve and implement a narrow authenticated Gateway HTTP session-management layer over existing session handlers, with operator-scope checks, reserved-key validation, route/auth tests, docs, and default-deny slash-command behavior preserved for chat completions.

- **Defer Mutating HTTP Controls:** Keep HTTP integrations on chat completions plus WebSocket/plugin surfaces until maintainers are ready to own a broader REST control-plane contract.
