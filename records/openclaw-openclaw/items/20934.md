## Summary

Keep open. Current main still lacks REST-native reset/status/compact/model/reasoning endpoints for HTTP integrations, and the linked plugin-reset and broader read-only REST work do not cover this mutating Gateway HTTP control surface.

## What This Changes

Request authenticated REST session-management endpoints for HTTP API clients using `/v1/chat/completions`.

## Best Possible Solution

Add a narrow authenticated Gateway HTTP session-management surface over existing session RPC/shared helpers, with explicit operator authorization, reserved-key handling, focused tests, and public HTTP docs.

## Reproduction Assessment

Yes. Source inspection against current main shows no `/v1/sessions` reset/status/compact/model/reasoning routes, while `/v1/chat/completions` still submits normal chat turns without `CommandAuthorized`.

## Solution Assessment

Unclear until maintainers approve the public HTTP API and security shape. The maintainable direction is a focused Gateway HTTP route layer over existing session methods, not re-enabling slash-command interpretation for HTTP chat.
