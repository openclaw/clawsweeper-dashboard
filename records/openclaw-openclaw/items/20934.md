## Summary

Keep open. Current main and v2026.6.11 still lack REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; existing Gateway RPCs, adjacent session history/kill HTTP helpers, the default-off admin HTTP RPC plugin, and plugin reset work only partially overlap.

## What This Changes

Expose authenticated REST session-management endpoints so HTTP API clients can reset, inspect, compact, and update model/reasoning settings for sessions.

## Best Possible Solution

Approve and implement a narrow authenticated Gateway HTTP session-management layer over existing session handlers, with operator-scope checks, reserved-key validation, route/auth tests, docs, and default-deny slash-command behavior preserved for chat completions.

## Reproduction Assessment

Yes for the reported gap. Source inspection shows current main has no /v1/sessions/reset, /status, /compact, /model, or /reasoning route, while the underlying Gateway session RPCs already exist.

## Solution Assessment

Unclear until maintainers approve the API and security shape. The maintainable direction is a focused authenticated HTTP route layer over existing session RPC/shared helpers, not re-enabling slash-command interpretation in /v1/chat/completions.
