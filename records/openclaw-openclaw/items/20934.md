## Summary

Keep open. Current main and v2026.6.11 still do not expose REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; existing WebSocket session RPCs, adjacent session kill/history HTTP helpers, the default-off admin HTTP RPC plugin, and plugin reset work do not satisfy this requested `/v1/sessions/*` API surface.

## What This Changes

Request REST-native session reset/status/compact/model/reasoning endpoints for HTTP API integrations using `/v1/chat/completions`.

## Best Possible Solution

Approve and implement a narrow authenticated Gateway HTTP session-management layer over existing session handlers, with operator-scope checks, reserved-key validation, route/auth tests, docs, and default-deny slash-command behavior preserved for chat completions.
