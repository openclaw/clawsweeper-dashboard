## Summary

Keep open. Current main and the latest release still lack REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; existing Gateway RPCs, adjacent session history/kill HTTP helpers, the default-off admin HTTP RPC plugin, and plugin reset work do not cover this requested public HTTP API surface.

## Best Possible Solution

Approve one narrow authenticated Gateway HTTP session-management shape over existing session handlers, preserve default-deny slash-command handling for chat completions, and document the operator/security contract.
