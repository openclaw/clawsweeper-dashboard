## Summary

Keep open. Current main and v2026.6.11 still lack REST-native `/v1/sessions/*` reset/status/compact/model/reasoning endpoints; existing Gateway RPCs, session history/kill HTTP helpers, and the opt-in admin HTTP RPC plugin are adjacent but do not satisfy the requested OpenAI-compatible HTTP integration surface.

## What This Changes

Request authenticated REST endpoints for HTTP integrations to reset, query, compact, and update session model/reasoning state without re-enabling slash-command interception.

## Best Possible Solution

Define a maintainer-approved authenticated Gateway HTTP session-management surface that reuses existing session RPC semantics, preserves default-deny slash commands, documents the security model, and adds route/auth/request/response coverage.

Rationale: The source gap is clear, but adding mutating session controls to the `/v1` HTTP surface changes a public integration and security boundary that automation should not choose alone.

Owner confidence: medium

Options:

- **Approve narrow `/v1/sessions/*` API (recommended):** Implement reset/status/compact/model/reasoning endpoints with explicit operator-scope mapping, docs, route tests, and no slash-command re-enablement.
- **Use admin HTTP RPC only:** Document the default-off admin HTTP RPC plugin as the supported trusted-host HTTP workaround and keep `/v1/chat/completions` focused on chat turns.
- **Approve reset/status first:** Start with status plus reset as the common workflow, then defer model/reasoning/compaction until the HTTP security model is proven.

## Reproduction Assessment

Yes for the API gap. Source inspection shows current main has no `/v1/sessions/*` management route, while `/v1/chat/completions` dispatches through the normal agent path without setting `CommandAuthorized`; I did not run a live curl path in this read-only review.

## Solution Assessment

Unclear until maintainers choose the API and security shape. A thin REST adapter over existing session RPCs is plausible, but the existing opt-in admin HTTP RPC plugin may be the preferred HTTP control-plane boundary.
