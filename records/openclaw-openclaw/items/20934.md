## Summary

Keep open. Current main and the latest release still do not expose REST-native session reset, status, compact, model, or reasoning endpoints for HTTP API integrations; existing Gateway session RPC methods and adjacent HTTP history/kill helpers do not satisfy the requested OpenAI-compatible HTTP control surface.

## What This Changes

Request an authenticated REST session-management surface for HTTP API clients using `/v1/chat/completions`, covering reset, status, compaction, model selection, and reasoning controls.

## Best Possible Solution

Define and implement a focused authenticated Gateway HTTP session-management surface that reuses existing session RPC/shared helper semantics, documents the operator-security contract, and keeps slash-command interception disabled on `/v1/chat/completions`.

## Reproduction Assessment

Yes, at source level. Current main has no `/v1/sessions/*` management route, while the existing HTTP chat path sends slash-like text into normal agent handling without setting `CommandAuthorized`.

## Solution Assessment

Unclear until maintainers approve the API and security contract. The narrow maintainable direction is a thin authenticated HTTP adapter over the existing session RPC/helpers, not behavioral slash-command parsing inside chat completions.
