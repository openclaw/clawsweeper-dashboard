## Summary

Keep open. Current main and v2026.6.11 still do not expose REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; the existing Gateway RPC methods, session history/kill HTTP helpers, and admin HTTP RPC plugin do not cover this requested `/v1` session-control surface.

## What This Changes

Request to add authenticated REST session-management endpoints for `/v1/chat/completions` HTTP integrations, covering reset, status, compaction, model, and reasoning controls by session key.

## Best Possible Solution

Approve one narrow authenticated Gateway HTTP session-management contract that reuses existing session handlers, preserves default-deny slash-command handling, documents the security boundary, and covers reset/status/compact/model/reasoning with route/auth/request/response tests.

- **Defer mutating HTTP controls:** Keep HTTP integrations on chat completions plus WebSocket/plugin surfaces until maintainers are ready to own a broader REST control-plane contract.
