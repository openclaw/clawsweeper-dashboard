## Summary

Keep open. Current main and v2026.6.11 still lack REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; related plugin reset and read-only REST work overlaps but does not resolve this dedicated mutating HTTP control-plane request.

## What This Changes

The issue requests authenticated REST session-management endpoints for HTTP API clients using `/v1/chat/completions`.

## Best Possible Solution

Approve one narrow authenticated Gateway HTTP session-management contract that reuses existing session handlers, preserves default-deny slash-command behavior, documents the security boundary, and covers reset/status/compact/model/reasoning with route/auth/request/response tests.
