## Summary

Keep open. Current main and checked release tag v2026.6.11 still lack REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; existing WebSocket RPCs, adjacent kill/history HTTP helpers, admin HTTP RPC, and plugin reset work do not satisfy the requested public `/v1/sessions/*` surface.

## What This Changes

Request REST endpoints for HTTP API clients to reset, inspect, compact, and change stable sessions used through `/v1/chat/completions`.

## Best Possible Solution

Approve and implement a narrow authenticated Gateway HTTP session-management layer over existing session handlers, with operator-scope checks, reserved-key validation, route/auth tests, docs, and default-deny slash-command behavior preserved for chat completions.
