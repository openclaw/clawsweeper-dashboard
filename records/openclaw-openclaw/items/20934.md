## Summary

Keep open. Current `main` and `v2026.6.11` still lack REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; existing Gateway RPC methods and adjacent kill/history HTTP helpers do not cover the requested mutating `/v1/sessions/*` API surface.

## What This Changes

Requested REST-native session management endpoints for HTTP API integrations using `/v1/chat/completions`.

## Best Possible Solution

Add a narrow authenticated Gateway HTTP session-management surface that maps reset/status/compact/model/reasoning to existing session RPC or shared helper semantics, enforces operator scopes, preserves default-deny slash-command handling, and updates route/auth/docs tests.

## Reproduction Assessment

Yes, at source level. Current `main` and `v2026.6.11` expose the underlying Gateway session RPC methods, but the HTTP router and public OpenAI-compatible docs still do not expose REST-native `/v1/sessions/*` reset/status/compact/model/reasoning routes.

## Solution Assessment

Unclear until maintainers approve the HTTP API and security shape. The best direction is a focused Gateway HTTP route layer over existing session RPC/helpers, not re-enabling slash-command interpretation for HTTP chat.
