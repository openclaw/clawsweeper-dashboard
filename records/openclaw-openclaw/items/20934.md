## Summary

Keep open. Current main and latest release still lack REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; existing WebSocket RPCs, adjacent session history/kill HTTP helpers, the default-off admin HTTP RPC plugin, and plugin reset work do not fully satisfy this requested public HTTP API surface.

## What This Changes

The issue requests authenticated REST-native HTTP endpoints for session reset, status, compaction, model switching, and reasoning control for `/v1/chat/completions` integrations.

## Best Possible Solution

Approve one public HTTP control-plane shape, then implement the chosen session-management path with explicit auth/scope checks, docs, and route-level tests while preserving default-deny slash-command behavior in chat completions.

## Solution Assessment
