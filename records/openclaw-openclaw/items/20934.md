## Summary

Keep open. Current main still has the underlying Gateway session RPCs and adjacent session history/kill HTTP helpers, but it does not expose the requested REST-native `/v1/sessions/*` reset/status/compact/model/reasoning endpoints for HTTP API integrations.

## What This Changes

The issue requests authenticated REST endpoints that let HTTP API integrations manage OpenClaw sessions without re-enabling slash-command dispatch in `/v1/chat/completions`.

## Best Possible Solution

Define a focused authenticated HTTP session-management surface, reusing existing session handlers or an approved admin HTTP RPC extension, with explicit operator-scope semantics, route tests, and public docs.

## Reproduction Assessment

## Solution Assessment

Yes for keeping it open, but not for automated implementation yet. The narrow maintainable direction is an authenticated adapter over existing session semantics, with maintainer-approved security and route shape first.
