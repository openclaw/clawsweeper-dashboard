## Summary

Keep open. Current main still lacks REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; the closed unmerged REST PR, the open plugin reset PR, and the broader read-only HTTP-query issue do not satisfy this mutating session-management request.

## What This Changes

The issue requests authenticated REST session-management endpoints for HTTP integrations to reset, inspect, compact, and update model/reasoning state for stable session keys.

## Best Possible Solution

Add a narrow authenticated Gateway HTTP session-management surface that reuses existing session RPC/shared helpers, enforces operator scopes and reserved-key validation, preserves default-deny slash-command handling for HTTP chat, and updates route/auth/docs tests.

## Reproduction Assessment

Yes. Source inspection shows current main has no `/v1/sessions/reset`, `/status`, `/compact`, `/model`, or `/reasoning` route, while the underlying Gateway session RPCs already exist.

## Solution Assessment

Unclear until maintainers approve the API and security shape. The maintainable direction is a focused authenticated HTTP route layer over existing session RPC/shared helpers, not re-enabling slash-command interpretation in `/v1/chat/completions`.
