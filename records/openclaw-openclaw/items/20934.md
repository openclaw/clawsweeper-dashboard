## Summary

Keep open. Current main and the latest release still expose session management through Gateway RPC and adjacent session history/kill HTTP helpers, but they do not provide the requested REST-native reset/status/compact/model/reasoning endpoints for HTTP API integrations.

## What This Changes

The issue requests authenticated REST session-management endpoints for clients using the OpenAI-compatible `/v1/chat/completions` HTTP API.

## Best Possible Solution

Keep this as the focused tracker for a reviewed, authenticated Gateway HTTP session-management surface that reuses existing `sessions.*` semantics, preserves default-deny slash-command handling, and ships with route/auth/docs tests.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: current main has no `/v1/sessions/*` HTTP handler while the Gateway RPC session operations exist.

## Solution Assessment

Yes for keeping it open, but implementation needs maintainer product/security approval. The maintainable fix is a thin authenticated HTTP adapter over existing session semantics, not re-enabling slash-command interpretation in chat completions.
