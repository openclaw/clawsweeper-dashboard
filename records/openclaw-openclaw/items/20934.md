## Summary

Keep open. Current main and the latest release still lack REST-native `/v1/sessions/*` session reset/status/compact/model/reasoning endpoints; the existing WebSocket/RPC methods and opt-in admin HTTP RPC plugin are adjacent but do not satisfy the requested public OpenAI-compatible HTTP integration surface.

## What This Changes

The issue requests authenticated REST endpoints for HTTP API integrations to reset, query, compact, and adjust OpenClaw sessions without re-enabling slash-command handling in `/v1/chat/completions`.

## Best Possible Solution

Define a maintainer-approved, authenticated Gateway HTTP session-management surface that reuses the existing session RPC semantics, preserves default-deny slash commands, documents the security model, and adds route/auth/request/response tests.
