## Summary

Keep open. Current main and v2026.6.11 still lack REST-native `/v1/sessions/*` reset/status/compact/model/reasoning endpoints for HTTP integrations; existing WebSocket/RPC session methods, adjacent history/kill HTTP helpers, and plugin-side reset work do not resolve the requested HTTP API surface.

## What This Changes

The issue requests REST-native session management endpoints for HTTP API integrations using `/v1/chat/completions`, including reset, status, compaction, model selection, and reasoning controls.

## Best Possible Solution

Approve and implement a narrow authenticated Gateway HTTP session-management API over existing session RPC/shared helper semantics, with explicit operator scopes and docs, while keeping `/v1/chat/completions` slash-command handling default-deny.
