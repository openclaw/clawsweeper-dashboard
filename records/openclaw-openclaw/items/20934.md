## Summary

Keep open. Current main and the latest release still lack the requested REST-native `/v1/sessions/*` management endpoints, while the underlying Gateway session RPCs and schemas exist; the remaining blocker is the approved HTTP security/product boundary, not stale implementation work.

## What This Changes

Request to add authenticated REST endpoints for HTTP API integrations to reset, inspect, compact, and update per-session model/reasoning state without re-enabling slash-command handling in `/v1/chat/completions`.

## Best Possible Solution

Approve and implement a narrow authenticated Gateway HTTP session-management API that reuses existing session RPC/shared helper semantics, preserves `/v1/chat/completions` command default-deny behavior, and documents/tests operation-specific scopes.
