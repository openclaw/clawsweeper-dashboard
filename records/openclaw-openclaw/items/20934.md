## Summary

Keep open: current main and the latest release still do not expose REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations, and the adjacent plugin reset work, default-off admin HTTP RPC plugin, and broader read-only REST issue do not replace this focused public HTTP control-plane request.

## What This Changes

The issue requests authenticated REST endpoints so `/v1/chat/completions` integrations can reset, inspect, compact, and change session-level model/reasoning state without re-enabling slash-command handling on the HTTP chat path.

## Best Possible Solution

Approve and implement a narrow authenticated Gateway HTTP session-management layer over existing session handlers, with operator-scope checks, reserved-key validation, route/auth tests, docs, and default-deny slash-command behavior preserved for chat completions.
