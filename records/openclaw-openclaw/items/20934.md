## Summary

Keep open. Current main and v2026.6.11 still lack REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; the remaining work is a real Gateway HTTP API gap, but the mutating control surface needs maintainer product and security approval before implementation.

## What This Changes

Request an authenticated REST session-management API for HTTP integrations using `/v1/chat/completions`, including reset, status, compact, model, and reasoning controls by stable session key.

## Best Possible Solution

Approve one narrow authenticated Gateway HTTP session-management contract that reuses existing session handlers, preserves default-deny slash-command behavior, documents the security boundary, and covers reset/status/compact/model/reasoning with route/auth/request/response tests.
