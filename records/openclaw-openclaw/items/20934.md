## Summary

Keep open. Current main and the latest release still lack REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations, while the related admin RPC/plugin reset work only partially overlaps and does not satisfy this mutating HTTP control-plane request.

## What This Changes

The issue requests authenticated REST session-management endpoints for HTTP clients using `/v1/chat/completions`.

## Best Possible Solution

Approve one narrow authenticated Gateway HTTP session-management surface that reuses existing `sessions.*` handlers, enforces operator-scope/security boundaries, preserves default-deny slash-command handling, and documents/tests the public contract.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 have no `/v1/sessions` reset/status/compact/model/reasoning routes, and `/v1/chat/completions` still builds ordinary agent command input without `CommandAuthorized`.

## Solution Assessment

Unclear until maintainers approve the API and security shape. The narrow maintainable direction is a focused HTTP route or approved admin HTTP RPC expansion over existing session handlers, not re-enabling slash-command interpretation for HTTP chat.
