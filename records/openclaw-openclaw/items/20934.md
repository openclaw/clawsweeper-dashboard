## Summary

Keep open: current main still has no REST-native session reset/status/compact/model/reasoning endpoints for HTTP API clients, while the exact REST PR is closed unmerged and the plugin-SDK reset work only covers plugin callers.

## What This Changes

The issue requests authenticated REST session-management endpoints for HTTP API integrations using `/v1/chat/completions`, including reset, status, compaction, model, and reasoning controls.

## Best Possible Solution

Define a focused authenticated Gateway HTTP session-management adapter over the existing session RPC/shared helper semantics, preserve default-deny slash-command handling for `/v1/chat/completions`, document the security contract, and coordinate with but not collapse into the broader read-only REST tracker.

## Reproduction Assessment

Yes, at source level: current main registers adjacent HTTP session history/kill routes and the OpenAI chat endpoint, but no requested `/v1/sessions/*` management routes. I did not run a live HTTP curl because the source gap is explicit and this review is read-only.

## Solution Assessment

Unclear until maintainers confirm the API and security contract. A thin HTTP adapter over existing session handlers is the maintainable direction; re-enabling slash-command interception on `/v1/chat/completions` would be the wrong security boundary.
