## Summary

Keep open. Current main and v2026.6.11 still lack REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; existing WebSocket RPC methods, the opt-in admin HTTP RPC allowlist, and the plugin reset PR do not cover this requested mutating HTTP session-management surface.

## What This Changes

Request to add authenticated REST session-management endpoints for HTTP API clients using OpenClaw's OpenAI-compatible HTTP surface.

## Best Possible Solution

Define a maintainer-approved authenticated Gateway HTTP session-management surface over existing `sessions.*` handlers, with operator-scope checks, route/auth/request/response tests, public docs, and preserved default-deny slash-command behavior for chat completions.

## Reproduction Assessment

Yes, at source level. Current main has no `/v1/sessions` reset/status/compact/model/reasoning routes, while `/v1/chat/completions` still sends ordinary ingress agent turns without `CommandAuthorized`.

## Solution Assessment

Unclear until maintainers approve the HTTP API and security shape. The maintainable direction is a narrow Gateway HTTP adapter or explicit admin HTTP RPC allowlist expansion over existing `sessions.*` handlers, not re-enabling slash-command interpretation for HTTP chat.
