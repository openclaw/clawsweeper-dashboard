## Summary

Keep open: current main and the latest checked release still do not provide REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; existing WebSocket session RPCs, session history/kill helpers, and the default-off admin HTTP RPC plugin only partially cover the need.

## What This Changes

Request dedicated HTTP API session-management endpoints for integrations that cannot safely use slash commands or WebSocket RPC.

## Best Possible Solution

Approve one narrow authenticated Gateway HTTP session-management surface backed by existing session handlers, with operator-scope checks, reserved-key protections, docs, and route-level tests.
