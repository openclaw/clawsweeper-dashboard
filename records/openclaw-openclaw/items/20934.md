## Summary

Keep open. Current main and v2026.6.11 still expose session controls through Gateway RPC and adjacent HTTP history/kill helpers, but not the requested `/v1/sessions/*` REST management surface; plugin reset work and the broader read-only REST issue do not satisfy this HTTP integration gap.

## What This Changes

Add authenticated REST endpoints so HTTP API clients can reset, inspect, compact, and update session model/reasoning state without re-enabling slash-command dispatch.

## Best Possible Solution

Implement a narrow, authenticated Gateway HTTP session-management API only after the operation set and scope model are approved; it should reuse existing session RPC/shared helper semantics and keep `/v1/chat/completions` slash commands default-deny.
