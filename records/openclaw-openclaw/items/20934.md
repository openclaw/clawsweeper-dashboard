## Summary

Keep open. Current main and the latest release still lack REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; adjacent plugin reset and broader read-only HTTP query work do not cover this mutating control-plane surface.

## What This Changes

The issue requests authenticated REST endpoints for HTTP API clients to reset, inspect, compact, and change settings for sessions used through `/v1/chat/completions`.

## Best Possible Solution

Define an approved authenticated Gateway HTTP session-management surface that reuses existing `sessions.*` handlers, preserves slash-command default-deny behavior, and ships with route/auth/request/response tests plus public docs.

## Reproduction Assessment

Yes. Source inspection on current main shows no `/v1/sessions` reset/status/compact/model/reasoning routes, while `/v1/chat/completions` remains an ordinary chat path without `CommandAuthorized`.

## Solution Assessment

Unclear until maintainers approve the API and security shape. The maintainable direction is a thin authenticated HTTP layer over existing session handlers, not re-enabling slash-command interpretation for HTTP chat.
