## Summary

Keep open. Current main and v2026.6.11 still lack REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; related plugin-SDK and read-only REST work only partially overlaps and does not close this focused mutable HTTP control-plane request.

## What This Changes

The issue requests authenticated REST endpoints for HTTP API clients to reset, inspect, compact, and change model/reasoning state for Gateway sessions.

## Best Possible Solution

Add a maintainer-approved authenticated Gateway HTTP session-management surface that maps to existing session RPC/helper semantics, documents the security boundary, and preserves default-deny slash-command behavior for `/v1/chat/completions`.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: current main has no requested `/v1/sessions/*` HTTP handler while the underlying `sessions.*` RPC methods and schemas exist.

## Solution Assessment

Yes for keeping it open; not for automated implementation yet. The maintainable direction is a thin authenticated HTTP adapter over existing session RPC/helper semantics, not re-enabling slash command interception or duplicating session logic.
