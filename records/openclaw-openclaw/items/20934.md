## Summary

Keep open. Current main and v2026.6.11 still expose OpenAI-compatible chat/models/embeddings/responses plus adjacent session kill/history HTTP helpers, but not the requested authenticated REST reset/status/compact/model/reasoning session-management surface.

## What This Changes

The issue requests REST-native session-management endpoints for HTTP API integrations using /v1/chat/completions.

## Best Possible Solution

Implement a focused authenticated Gateway HTTP session-management surface that maps to existing sessions.* semantics, keeps /v1/chat/completions slash commands default-deny, and adds route/auth/request/response tests plus public docs.

## Reproduction Assessment

Yes for source-level verification: current main has no /v1/sessions/* management handler while the underlying sessions.* RPC handlers and schemas exist. No live curl repro was run in this read-only review.

## Solution Assessment

Yes in direction, with maintainer product and security sign-off: a narrow authenticated HTTP mapping to existing sessions.* operations is a better fit than re-enabling slash-command interception on /v1/chat/completions or treating plugin reset as a REST substitute.
