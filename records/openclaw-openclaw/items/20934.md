## Summary

Keep open. Current main and v2026.6.11 still lack REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; the existing Gateway RPCs, session kill/history HTTP helpers, admin HTTP RPC plugin, and plugin reset work only partially overlap.

## What This Changes

Request REST-native session-management endpoints for HTTP clients using `/v1/chat/completions`, including reset, status, compact, model, and reasoning controls by session key.

## Best Possible Solution

Approve and implement a narrow authenticated Gateway HTTP session-management layer over existing session handlers, with operator-scope checks, reserved-key validation, route/auth tests, docs, and default-deny slash-command behavior preserved for chat completions.
