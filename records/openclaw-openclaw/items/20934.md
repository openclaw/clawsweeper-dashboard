## Summary

Keep open. Current main and v2026.6.11 still lack REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; existing WebSocket RPC, adjacent session kill/history HTTP helpers, default-off admin HTTP RPC, and plugin-side reset work do not cover the requested public HTTP API surface.

## What This Changes

The issue requests authenticated REST endpoints that let HTTP API integrations reset, inspect, compact, and update per-session model/reasoning state.

## Best Possible Solution

Approve one narrow authenticated Gateway HTTP session-management surface over existing session handlers, with operator-scope checks, reserved-key validation, route/auth/request/response tests, docs, and default-deny slash-command behavior preserved.
