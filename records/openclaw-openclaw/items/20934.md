## Summary

Keep open. Current main and v2026.6.11 still lack REST-native session reset/status/compact/model/reasoning endpoints for HTTP integrations; existing WebSocket RPCs, adjacent session history/kill HTTP helpers, the default-off admin HTTP RPC plugin, and plugin reset work do not cover this requested public HTTP API surface.

## What This Changes

The issue requests authenticated REST session-management endpoints for `/v1/chat/completions` integrations, including reset, status, compact, model, and reasoning controls.

## Best Possible Solution

Approve and implement a narrow authenticated Gateway HTTP session-management layer over existing session handlers, with operator-scope checks, reserved-key validation, route/auth tests, docs, and default-deny slash-command behavior preserved for chat completions.
