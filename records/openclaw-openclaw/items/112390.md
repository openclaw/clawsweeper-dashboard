## Summary

Keep this PR open. The provider-key boundary is the right place for URL-only canonicalization, but Firecrawl cache hits would return the first caller's raw `url` spelling to later callers of an equivalent URL, and the new public plugin-SDK helper needs an explicit owner decision before merge.

## What This Changes

Adds URL-dimension canonicalization to Firecrawl scrape and Tavily extract cache keys so case-only scheme and host variants can reuse provider cache entries.

## System Context

OpenClaw's web tools delegate fetching and extraction to provider plugins, each of which keeps an in-process result cache. A caller supplies URLs, the provider composes a cache key and either returns a cached provider result or makes an upstream request.

## Architecture Diagram

  F --> G[Store provider result]
  G --> E

## Best Possible Solution

Keep URL canonicalization at each provider-owned key boundary, preserve per-call response metadata on Firecrawl cache hits, add a regression test for that sequence, obtain approval for the narrow SDK export, and attach redacted real-provider proof before merge.
