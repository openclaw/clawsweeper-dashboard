## What This Changes

Canonicalizes case-insensitive URL scheme and host components in Firecrawl scrape and Tavily extract cache keys, while rebinding Firecrawl request-derived result URLs for the current caller on shared cache hits.

## System Context

OpenClaw’s web providers compose provider-specific cache keys before sending upstream HTTP requests. The changed path receives caller URLs, selects a cached or fresh provider result, and returns a result whose request-echo fields must remain accurate for the current caller.

## Architecture Diagram

flowchart LR

  Provider --> Key[Provider cache-key composition]
  Key --> Cache{Provider cache lookup}
  Cache -->|Miss| Upstream[Provider HTTP request]
  Upstream --> Stored[Stored provider result]
  Cache -->|Hit| Rebind[Rebind Firecrawl request fields]
  Stored --> Result[Returned provider result]
  Rebind --> Result

## Best Possible Solution

Keep URL canonicalization at each provider’s URL-valued key boundary, retain the Firecrawl cache-hit rebinding rule, and land only after an owner accepts the shared SDK helper as a supported plugin contract and the refreshed branch remains clean.
