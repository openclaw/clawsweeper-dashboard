## Summary

Keep open: current main and the latest release still only expose TTL-gated cache pruning, so continuously active sessions still lack a rolling or turn-age pruning trigger. The request is valid, but it needs maintainer API direction because it adds public context-pruning config and changes the cost-versus-context-retention contract.

## What This Changes

The issue requests rolling or turn-count-based context pruning so active sessions prune old tool results even when TTL inactivity never expires.

## Best Possible Solution

Choose one additive active-session pruning contract and implement it in the current agent-hooks context-pruning runtime with aligned schema, docs, and regression proof while preserving existing cache-ttl defaults.

## Reproduction Assessment

Yes, at source level: current main only accepts and wires cache-ttl pruning, and the context hook returns during a fresh TTL window before pruning. A live Opus cost reproduction is not needed to prove the missing active-session trigger.

## Solution Assessment

Unclear until maintainers choose the public trigger API. The narrow maintainable direction is one additive active-session pruning policy in the current context-pruning runtime, not reviving a closed stale PR as-is.
