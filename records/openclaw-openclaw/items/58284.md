## Summary

Keep open: current main and the latest release still only expose TTL-gated `cache-ttl` pruning, so active sessions that keep refreshing the cache window still lack a rolling or turn-age pruning trigger. The request is valid, but it needs maintainer API direction because the fix adds public context-pruning configuration and changes cost-versus-context-retention behavior.

## What This Changes

The issue requests an additive rolling or turn-based context-pruning trigger so old tool results can be trimmed during continuously active sessions instead of only after cache TTL expiry.

## Best Possible Solution

Choose one default-off pruning-trigger API, then implement it across config types, strict schema, runtime setup, docs, and focused source-level tests for both active-turn pruning and unchanged cache-ttl behavior.

## Reproduction Assessment

Yes for a source-level gap: current main only accepts and wires `cache-ttl`, and the hook skips pruning while the cache TTL window is fresh. I did not run a live Anthropic cost reproduction because the code path and docs already prove the missing rolling trigger.

## Solution Assessment

Unclear until maintainers choose the public API. A rolling trigger is plausible, but the best fix should be a single additive config contract that preserves current cache-ttl behavior and documents the cost/context tradeoff.
