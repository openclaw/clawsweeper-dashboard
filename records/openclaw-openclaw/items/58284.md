## Summary

Keep open: current main and v2026.6.11 still expose only TTL-gated `cache-ttl` pruning, and the new aggregate tool-result pressure compaction on main is adjacent rather than the requested turn-age rolling pruning contract. The issue remains valid but needs maintainer direction because the fix adds public context-pruning config and changes cost-versus-context-retention behavior.

## What This Changes

Request to add turn-age or rolling context pruning so old tool results can be trimmed during continuously active sessions instead of only after cache-TTL idle windows.

## Best Possible Solution

Choose one additive active-session pruning contract in the built-in context-pruning runtime, then align schema, docs, and focused regression coverage while preserving current `cache-ttl` defaults.

## Reproduction Assessment

Yes. Source inspection is enough: current main only accepts and wires `cache-ttl`, and the context hook returns during a fresh TTL window before pruning.

## Solution Assessment

Unclear until maintainers choose the public trigger API. The narrow maintainable path is an additive active-session pruning policy in the existing context-pruning runtime, not reviving a closed stale PR as-is.
