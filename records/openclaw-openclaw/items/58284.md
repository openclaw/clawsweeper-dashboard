## Summary

Keep open: current main and v2026.6.11 still only support TTL-gated cache pruning, so continuous active sessions still lack a rolling or turn-age trigger. The request is valid, but it needs maintainer API direction because it adds public context-pruning config and changes cost-versus-context-retention behavior.

## What This Changes

Request to add an active-session, turn-age or rolling pruning trigger for old tool results so pruning can run every turn instead of only after cache-TTL inactivity.

## Best Possible Solution

Choose one additive active-session pruning contract and implement it in the current context-pruning runtime with aligned schema, docs, and regression proof while preserving existing cache-ttl defaults.
