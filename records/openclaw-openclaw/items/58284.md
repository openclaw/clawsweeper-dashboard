## Summary

Keep open: current main and v2026.6.11 still only support TTL-gated cache pruning, so active sessions that keep sending turns inside the TTL window still lack a rolling or turn-age pruning trigger. The related rolling-mode attempts are closed unmerged, and the remaining work needs maintainer API direction because it adds public context-pruning config and changes the cost-versus-context-retention tradeoff.

## What This Changes

The issue requests turn-based or rolling context pruning so active sessions prune old tool results even when cache-TTL inactivity never expires.

## Best Possible Solution

Choose one additive active-session pruning contract and implement it in the current context-pruning runtime with aligned schema, docs, and regression proof while preserving existing cache-ttl defaults.

## Reproduction Assessment

Yes, at source level: cache-ttl is the only accepted and registered mode, and the context hook returns before pruning while the TTL window is fresh. A live Opus cost reproduction is not needed to prove the missing active-session trigger.

## Solution Assessment

Unclear until maintainers choose the public trigger API. The narrow maintainable direction is one additive active-session pruning policy in the current context-pruning runtime, not reviving a closed stale PR as-is.
