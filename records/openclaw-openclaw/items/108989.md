## Label Justifications

- `P1`: A provider interruption can currently appear as a successful empty agent response, hiding failure from the session and gateway flow.
- `merge-risk: 🚨 compatibility`: The shared Responses transport spans compatible provider routes, so global terminal-less EOF failure can change existing integrations at runtime.

## Summary

This PR addresses a real P1 false-success path and has convincing after-fix HTTP/SSE proof, but landing it still needs a maintainer decision on whether every OpenAI-compatible Responses backend must fail closed when EOF arrives without a terminal event. The linked issue remains open, and the competing PR is not yet a proof-positive canonical replacement.

## What This Changes

The branch tracks completed versus incomplete Responses SSE terminal events, maps incomplete responses to `length`, and converts terminal-less EOF into an error rather than a successful assistant output.

## Best Possible Solution

Choose and document one terminal-event contract for the shared Responses transport, then land one canonical implementation that prevents false successful persistence while adding focused coverage for compliant completion, incomplete completion, and known compatible-provider EOF behavior.
