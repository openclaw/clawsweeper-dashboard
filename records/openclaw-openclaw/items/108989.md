## Summary

Keep open: the patch appears correct and well-proven, but its fail-closed rule affects every configured `openai-responses` provider, including third-party compatible endpoints, so a maintainer should confirm that compatibility contract and select the canonical branch.

## What This Changes

The PR recognizes incomplete Responses SSE events, rejects streams ending without a terminal event, and adds regression coverage for completed, incomplete, failed, empty, and tool-use streams.

## Best Possible Solution

Adopt one canonical transport-boundary implementation that accepts completed, incomplete, and failed terminal outcomes, rejects bare EOF, and proves both native OpenAI and representative custom-compatible provider behavior before closing the sibling PR.
