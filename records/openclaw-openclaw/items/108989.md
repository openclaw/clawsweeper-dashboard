## Summary

Keep this PR open: the fix appears correct and has convincing real HTTP/SSE proof, but a maintainer must confirm the fail-closed compatibility boundary for all OpenAI-compatible Responses providers and select this branch over the competing implementation.

## What This Changes

The PR adds terminal-state handling for OpenAI Responses SSE streams so incomplete responses report length and streams ending without a terminal event fail instead of being finalized as successful.

## Best Possible Solution

Land one canonical terminal-state implementation at the shared Responses transport boundary, preserve `response.incomplete` as a successful length-limited result, fail genuinely unterminated streams before persistence, and explicitly accept or narrow the behavior for compatible proxy providers.
