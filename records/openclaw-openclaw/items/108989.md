## What This Changes

The PR changes OpenAI and Azure Responses streaming so EOF without `response.completed` produces an error, with regression tests for interrupted and normally completed streams.

## Best Possible Solution

Handle `response.completed`, `response.failed`, and `response.incomplete` according to the Responses event contract, preserve appropriate incomplete or length outcomes, and reserve the stream-interrupted error for EOF without any terminal response event.

## Reproduction Assessment

Yes at the source level: an async stream ending without any terminal event leaves the initialized `stopReason: "stop"` unchanged on current behavior. The PR's helper-level simulation supports that path, but it is not a live end-to-end reproduction.

## Solution Assessment

No. Detecting EOF without a terminal event is the right boundary, but tracking only `response.completed` conflicts with the official `response.incomplete` event and is not the narrowest correct implementation.
