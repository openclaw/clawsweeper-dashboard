## Summary

Keep this PR open for revision: the interrupted-stream diagnosis is valid, but the new guard treats the documented `response.incomplete` terminal event as an unterminated stream, converting legitimate incomplete responses into provider errors. The supplied proof also uses simulated events rather than an actual transport interruption.

## What This Changes

The PR tracks whether `response.completed` was observed, changes otherwise successful-looking end-of-stream results to errors, and adds focused parser tests.

## Best Possible Solution

Handle both `response.completed` and `response.incomplete` as terminal events, preserve incomplete reason and usage semantics, fail only when iteration ends without any terminal event, and prove the behavior through the real transport using a controlled SSE server or redacted live trace.
