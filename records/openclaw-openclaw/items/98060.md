## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P2] Do not advertise HTTP-only control methods as RPC:** `src/gateway/methods/core-descriptors.ts:63-66`
  - body: These descriptors are advertised through `listGatewayMethods()`/hello feature discovery, but the PR does not add matching `coreGatewayHandlers` entries for `contextEngine.*`. Clients can discover methods that are not actually dispatchable; either add real RPC handlers or keep these HTTP-only scope names out of the advertised core method table.
  - confidence: 0.9
- **[P2] Initialize context engines before resolving them:** `src/gateway/context-engine-control-shared.ts:326`
  - body: All current runtime paths call `ensureContextEnginesInitialized()` before `resolveContextEngine()` so the default `legacy` engine is registered. The new control dispatcher goes straight to `resolveContextEngine`, so a fresh gateway can return degraded/503 for capabilities or control until another path initializes context engines.
  - confidence: 0.87
- **[P2] Validate the rotate timestamp before echoing it:** `src/gateway/context-engine-control-shared.ts:234-245`
  - body: The sanitizer only trims `lastRotatedAt` and then exposes it on the HTTP response. Because this is a plugin-provided value on a security-sensitive operator endpoint, a faulty engine can leak an arbitrary path, secret-like text, or an unbounded string under that field despite the stated sanitized/bounded result contract; parse and bound it as an ISO timestamp before returning it.
  - confidence: 0.83
