## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.87

Full review comments:

- **[P1] Keep non-dispatchable methods out of discovery:** `src/gateway/methods/core-descriptors.ts:63-66`
  - body: `listGatewayMethods()` advertises every core spec whose `advertise` flag is not false, but dispatchable core descriptors are only created when `coreGatewayHandlers` has a handler. These four new `contextEngine.*` specs have no JSON-RPC handlers, so clients can discover methods that then fail as unknown. Either add dispatch handlers or keep the HTTP-only scope policy out of advertised core specs and add a regression test.
  - confidence: 0.91
- **[P2] Align the public ContextEngine control contract:** `src/context-engine/types.ts:469-472`
  - body: Adding `getControlCapabilities` and `control` changes the `ContextEngine` interface that plugins import through the SDK, but the supporting control request/result/capability types are not re-exported from the SDK and the SDK docs/baseline are not updated. Please either keep this seam internal or update the public SDK exports, docs, API baseline, and focused compatibility tests together.
  - confidence: 0.86
- **[P2] Canonicalize session keys before loading session ids:** `src/gateway/context-engine-control-shared.ts:306`
  - body: The endpoint accepts opaque keys such as `user:u1:chat`, but `resolveControlSessionId` indexes `store[params.sessionKey]` directly. Current session stores canonicalize bare keys into the agent namespace, so normal existing sessions will not resolve `sessionId` for the engine. Use the existing agent-store key resolver and add a store-backed test for an opaque key.
  - confidence: 0.83
