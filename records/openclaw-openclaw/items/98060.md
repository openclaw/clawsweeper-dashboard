## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Do not advertise RPC methods without handlers:** `src/gateway/methods/core-descriptors.ts:63-66`
  - body: These specs are picked up by `listGatewayMethods()`, but `createCoreGatewayMethodDescriptors()` only creates dispatch descriptors for specs that also exist in `coreGatewayHandlers`. This PR adds no `contextEngine.*` handlers, so Gateway clients will discover these RPC methods and then get `unknown method` when they call them. Either add the RPC handlers or keep these names out of the advertised core method table and use an internal scope map for the HTTP route.
  - confidence: 0.92
- **[P2] Return a sanitized error when capabilities fail:** `src/gateway/context-engine-control-shared.ts:379-381`
  - body: `getControlCapabilities()` can reject before the `try` around `engine.control`, which means the HTTP request-stage error path turns this control call into a generic 500 text response instead of the sanitized JSON error shape promised by the new API. Wrap capability resolution in the same controlled outcome path used for engine resolution/control failures.
  - confidence: 0.86
