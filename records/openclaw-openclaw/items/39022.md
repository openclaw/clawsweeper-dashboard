## Summary

Keep open: current main and v2026.6.11 still only support sticky session model overrides, while the requested N-turn `/model` lease with warning, auto-revert, and per-model turn-limit config remains a product/API decision. The related one-turn, fallback, and image-revert items overlap on temporary model routing but do not replace this broader multi-turn lease request.

## What This Changes

The issue requests `/model <name> --turns N` plus per-agent limits that warn near expiry and automatically revert to the session default model after N turns.

## Best Possible Solution

Define one additive session-owned model lease contract across `/model` and any exposed Gateway/session API, with explicit turn counting, warning/revert semantics, compatibility-safe config, docs, and focused tests for queues, cron, retries, fallbacks, auth profiles, and live switches.

Owner confidence: high

Options:

- **Specify a unified lease contract (recommended):** Define a maintainer-approved session lease design first, then implement `/model --turns N` and any Gateway/session API shape against that single contract.
- **Defer to one-turn API first:** Keep this issue open but require the one-turn override contract to settle before multi-turn leases are designed.
- **Do not add native leases:** Reject native turn leases and document manual `/model default`, model allowlists, or external operational policy as the supported cost-governance path.
