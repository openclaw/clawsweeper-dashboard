## What This Changes

This PR makes `openclaw config unset` reject attempts to remove plugin-index-managed `plugins.installs` records, matching the existing set, patch, and dry-run behavior.

## System Context

The configuration CLI parses a user-supplied config path, loads the canonical configuration, and writes a revised file for mutations. Plugin installation records are owned by the plugin index, so mutation commands must reject direct edits and direct users to plugin lifecycle commands instead.

## Best Possible Solution

Keep one shared prefix-based protection rule for plugin-index-managed records and land it after a redacted real CLI run shows that both a record path and the `plugins.installs` parent path fail before any config write while ordinary unset remains available.
