## Review Findings

Overall correctness: patch is incorrect

Full review comments:

- **[P1] Preserve non-manual stop semantics for reloads:** `src/gateway/server-reload-handlers.ts:124`
  - body: The new account restart path calls `stopChannel(name, accountId)` without `{ manual: false }`. On current main, `stopChannel` defaults to a manual stop and records the account in `manuallyStopped`, while the existing hot-reload channel restart path explicitly passes `{ manual: false }` so recovery and restart state are not suppressed. A rebased account-scoped reload needs the same non-manual stop semantics before this can safely replace whole-channel reloads.
  - confidence: 0.89
- **[P1] Keep default-account edits on whole-channel reload:** `src/gateway/config-reload-plan.ts:151`
  - body: This parser treats every `channels.<kind>.accounts.<accountId>.*` path as isolated, including `accounts.default.*`. The default account is an inheritance base for other configured accounts, so restarting only `default` can leave other accounts running with stale inherited settings; default-account and non-canonical/removed-account paths need to promote back to whole-channel restart.
  - confidence: 0.82
