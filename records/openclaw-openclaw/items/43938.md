Full review comments:

- **[P1] Include account restarts in the no-op check:** `src/gateway/config-reload-plan.ts:15-16`
  - body: The planner can now emit a plan where `restartChannels` is empty and `restartChannelAccounts` is non-empty, but the existing no-op detector only checks `restartChannels.size`. A config-file account-only change can therefore be treated as a no-op before this new handler path runs.
  - confidence: 0.87
- **[P1] Keep default-account changes on whole-channel restart:** `src/gateway/config-reload-plan.ts:156-158`
  - body: `channels.<kind>.accounts.default.*` is routed as a single-account restart here. Current channel helpers can use `accounts.default` as shared fallback data for other accounts, so restarting only `default` can leave other running accounts with stale inherited config.
  - confidence: 0.82
- **[P2] Preserve non-manual stop semantics for reloads:** `src/gateway/server-reload-handlers.ts:123-126`
  - body: The existing hot-reload path calls `stopChannel(..., { manual: false })`, but this new account restart path calls `stopChannel(name, accountId)` and gets the manager's manual-stop default. Stop failures or timeouts on a reload should not be recorded like an operator manually stopped the account.
  - confidence: 0.8
