## What This Changes

The PR adds account-scoped gateway reload planning and routes `channels.<channel>.accounts.<accountId>.*` changes through account-specific channel stop/start calls while preserving full-channel restarts for global or mixed changes.

## Best Possible Solution

Rebase or replace this as a current-main fix that carries channel/account restart targets through the planner and the newer reload handler while preserving full-channel precedence, active-work deferral, plugin-reload abort handling, and failure aggregation.

## Reproduction Assessment

## Solution Assessment

Yes as a direction, but not as this stale branch. Carrying account-scoped restart targets through the generic gateway planner is the narrow fix because `startChannel` and `stopChannel` already accept an optional account id, but the implementation must be rebased into the current reload-handler safety path.
