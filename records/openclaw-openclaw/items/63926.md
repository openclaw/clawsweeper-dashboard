## Summary

Keep open: current main has browser CLI/RPC/control primitives and a generic plugin-tab projection path, but it still lacks the requested browser-specific Control UI login handoff panel, same-tab/profile resume state, and structured manual-action flow. The discussion explicitly treats this as the canonical browser-login handoff tracker, with the linked FSB work useful as design context rather than a replacement.

## What This Changes

Request a visible Control UI browser panel for managed-browser login handoff, tab/status management, direct session access, and same-state agent resume after user login.

## Best Possible Solution

Design and ship an operator-scoped, read-only-first browser handoff surface with typed profile/tab context, explicit write controls, redaction, and same-state resume semantics coordinated with the broader browser-preview and plugin-UI work.
