## Summary

Keep open: current main and the latest release still have browser-control primitives and generic/plugin tab plumbing, but no browser-specific Control UI login-handoff panel or same-state resume surface. The issue discussion explicitly treats this as the canonical browser-login handoff tracker, and the remaining work needs product/security scoping before implementation.

## What This Changes

Requested a visible Control UI browser panel for managed-browser login handoff, active tab visibility, tab actions, direct session access, and agent resume after manual login.

## Best Possible Solution

Design a secured operator-scoped, read-only-first browser handoff surface with typed profile/node/tab context, explicit write controls, redaction, and same-state resume semantics coordinated with browser preview and plugin UI entry-point work.
