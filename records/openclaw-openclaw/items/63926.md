## Summary

Keep open: current main and v2026.6.11 still have browser CLI/RPC/control primitives, but no Control UI browser-login handoff route, sidebar entry, or panel. The issue discussion treats this as the canonical same-browser-state login handoff tracker, while related work is only partial overlap.

## What This Changes

The issue requests a visible Control UI browser/login handoff panel with browser status, active tabs, managed-session access, and same-state resume after manual login.

## Best Possible Solution

Design and ship an operator-scoped, read-only-first browser handoff surface with typed profile/tab context, explicit write controls, redaction, and same-state resume semantics coordinated with browser preview and plugin UI entry-point work.
