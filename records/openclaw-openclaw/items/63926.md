## Summary

Keep open: current main and the latest shipped release still have browser CLI/RPC primitives and generic plugin Control UI descriptor plumbing, but no browser-specific Control UI login handoff panel. The discussion treats this as the canonical same-browser-state login and resume surface; related preview/plugin UI work and the FSB ClawHub/plugin reference are useful context, not replacements.

## What This Changes

The issue requests a visible Control UI browser panel for managed-browser status, tabs, login handoff, tab actions, and same-state agent resume.

## Best Possible Solution

Design and ship an operator-scoped browser handoff surface with status and tab context, read-only visibility by default, explicit open/focus/close/write controls, redaction, and same-profile resume semantics coordinated with browser preview and plugin UI work.
