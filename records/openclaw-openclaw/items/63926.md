## Summary

Keep open: current main still has browser CLI/tool/RPC/tab primitives, but no visible Control UI browser-login handoff panel. The discussion also names this as the canonical same-browser-state login handoff tracker, so this needs maintainer product and security scoping rather than cleanup closure.

## What This Changes

Add a visible Control UI browser handoff panel for managed-browser login, tab/status visibility, and resuming agent work against the same browser session.

## Best Possible Solution

Define a security-reviewed, host-owned browser handoff surface with typed profile/tab context, read-only status first, explicit operator actions, redaction, and same-state resume semantics.

Options:

- **Design minimal host-owned handoff (recommended):** Add only the status, exact managed-session access, login-required state, and resume affordance needed for same-browser-state authentication first.
- **Wait for plugin UI infrastructure:** Defer implementation until generic plugin UI entry points settle, then decide whether browser management belongs as plugin-owned UI or core-hosted UI.
- **Decline core handoff panel:** Keep browser visibility outside the Control UI and accept that authenticated browser workflows remain harder to recover.

## Solution Assessment

Unclear as an implementation until maintainers choose the security and UX boundary; the best direction is a narrow browser-login handoff contract, not an unrestricted browser dashboard.
