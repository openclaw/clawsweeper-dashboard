## Label Justifications

## Summary

Keep open: current main has browser tool/CLI/RPC primitives and now has generic plugin-tab infrastructure, but the browser plugin still does not advertise or render a Control UI browser-login handoff panel. The discussion also explicitly treats this as the canonical same-browser-state login handoff tracker, with the FSB reference as useful design context rather than a replacement.

## What This Changes

Request a visible Control UI browser panel for managed-browser status, tabs, manual login handoff, and same-state agent resume.

## Best Possible Solution

Design and ship an operator-scoped browser handoff surface that reuses the existing browser.request/tab primitives, advertises the browser surface intentionally through a browser plugin tab or first-party route, defaults to read-only status where possible, and gates write/login-resume actions explicitly.
