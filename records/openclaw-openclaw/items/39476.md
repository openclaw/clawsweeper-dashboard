## What This Changes

The issue asks OpenClaw to prevent an A2A `sessions_send` target turn from calling `sessions_send` back to the requester and duplicating requester-visible messages.

## Best Possible Solution

Land or replace the narrow guard from https://github.com/openclaw/openclaw/pull/91161 so `sessions_send` A2A target turns cannot expose `sessions_send` again while normal sends and non-send inter-session handoffs remain intact.

Yes, source-reproducible: current main marks A2A target turns as `inter_session`/`sessions_send` and still builds the normal `sessions_send` tool for non-embedded target runs. A live Discord or Telegram two-agent run was not repeated in this read-only pass.

## Solution Assessment

Yes: the narrow maintainable fix is to hide only `sessions_send` during turns that are themselves processing a `sessions_send` A2A message. The broader one-way dispatch mode remains separately tracked in https://github.com/openclaw/openclaw/issues/44309.
