## Summary

Keep open: current main and the latest release still expose the reverse-call surface for A2A `sessions_send`, and the direct closing fix candidate is open but not merged.

## What This Changes

The issue reports duplicate requester-channel messages when an A2A target can call `sessions_send` back to the requester during the same handoff.

## Best Possible Solution

Land or replace the narrow guard from https://github.com/openclaw/openclaw/pull/91161 so `sessions_send` A2A target turns cannot expose `sessions_send` again while normal sends and non-send inter-session handoffs remain intact.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source-reproducible: current main marks A2A target turns as `inter_session`/`sessions_send` and still builds the normal `sessions_send` tool for non-embedded target runs. A live Discord two-agent run was not repeated in this read-only pass.

## Solution Assessment

Yes: the narrowest maintainable fix is to hide only `sessions_send` during turns that are themselves processing a `sessions_send` A2A message. The broader one-way dispatch semantic remains separately tracked in https://github.com/openclaw/openclaw/issues/44309.
