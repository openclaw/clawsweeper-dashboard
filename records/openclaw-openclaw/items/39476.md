## Summary

Keep open: current `main` and the latest release still expose `sessions_send` on A2A target turns, while the direct closing fix candidate is open but not merged.

## What This Changes

The issue reports duplicate requester-channel messages when an A2A target agent reverse-calls `sessions_send` back to the requester during `sessions_send` handling.

## Best Possible Solution

Land or replace the narrow guard from https://github.com/openclaw/openclaw/pull/91161 so `sessions_send` A2A target turns cannot expose `sessions_send` again while normal session tools and result delivery remain intact.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: current `origin/main` tags A2A target turns as `inter_session`/`sessions_send` and still exposes `sessions_send` in normal non-embedded tool construction. A live Discord two-agent run was not repeated in this read-only pass.

## Solution Assessment

Yes: the narrowest maintainable fix is to make `sessions_send` unavailable only during turns that are themselves processing a `sessions_send` A2A message. Broader one-way dispatch semantics are separately tracked by https://github.com/openclaw/openclaw/issues/44309.
