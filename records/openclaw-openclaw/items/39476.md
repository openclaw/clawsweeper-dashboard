## Summary

Keep open: current main and the latest release still expose `sessions_send` during A2A target turns, and https://github.com/openclaw/openclaw/pull/91161 is the open direct fix candidate rather than a merged implementation.

## What This Changes

The issue asks OpenClaw to prevent A2A target runs from using `sessions_send` back to the requester and duplicating requester-visible messages.

## Best Possible Solution

Land or replace the linked per-turn guard so A2A `sessions_send` target turns cannot reverse-call the requester, while preserving documented peer reply/announce behavior and leaving the broader one-way dispatch feature to https://github.com/openclaw/openclaw/issues/44309.
