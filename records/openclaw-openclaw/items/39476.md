## Summary

Keep open: current main and the latest release still expose `sessions_send` during A2A target turns, and the direct closing fix in https://github.com/openclaw/openclaw/pull/91161 is still open rather than merged.

## What This Changes

The issue asks OpenClaw to prevent an A2A `sessions_send` target turn from calling `sessions_send` back into the requester and duplicating visible channel messages.

## Best Possible Solution

Review, prove, and land or replace https://github.com/openclaw/openclaw/pull/91161 with a narrow per-turn guard that hides only `sessions_send` from A2A target turns while keeping normal sessions and other session tools available.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: `sessions_send` marks target turns as `inter_session` with `sourceTool='sessions_send'`, while the target's non-embedded tool list still includes `sessions_send`. I did not run a live Discord multi-agent repro in this read-only review.

## Solution Assessment

Yes, the best narrow fix is a code-level per-turn guard that suppresses `sessions_send` only for A2A target turns. Removing requester context alone is weaker because the target can still target visible agents or sessions by other identifiers.
