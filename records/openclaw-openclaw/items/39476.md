## Summary

## What This Changes

The issue requests a guard that prevents an A2A target turn from calling `sessions_send` back to the requester and duplicating channel-visible content.

## Best Possible Solution

Land a reviewed and proven version of the A2A tool-surface guard so inter-session turns from `sessions_send` cannot re-enter `sessions_send`, while preserving normal peer-session delivery and announce behavior.

## Solution Assessment

Yes. The narrowest maintainable fix is to suppress only `sessions_send` for the target turn whose provenance comes from `sessions_send`, rather than removing broader session tools or relying on prompt instructions.
