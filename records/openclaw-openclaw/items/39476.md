## Label Justifications

- `P1`: The issue reports duplicate requester-visible messages in core A2A `sessions_send` workflows affecting real channel use.
- `impact:message-loss`: The failure duplicates semantically similar A2A responses into the requester channel, which is a message-delivery correctness problem.

## Summary

Keep open: current main and the latest release still mark A2A turns as `sourceTool: "sessions_send"` while the normal non-embedded tool surface still includes `sessions_send`; https://github.com/openclaw/openclaw/pull/91161 is the direct open fix candidate but is not merged.

## What This Changes

The issue asks OpenClaw to prevent a target agent processing an A2A `sessions_send` turn from reverse-calling `sessions_send` back to the requester and duplicating requester-visible messages.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/91161, or an equivalent provenance-scoped guard that removes `sessions_send` only from `sessions_send`-routed target turns, with proof of one requester-visible delivery and no reverse duplicate.
