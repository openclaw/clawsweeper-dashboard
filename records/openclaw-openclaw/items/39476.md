## Label Justifications

- `P1`: The issue describes duplicate user-visible A2A channel delivery in production multi-agent workflows, with source-level evidence that the reverse-call path still exists.
- `impact:message-loss`: The reported failure is duplicate or misrouted channel message delivery from one logical A2A response.

## Summary

Keep open: current main still marks A2A target turns as `sourceTool: "sessions_send"` while the target's normal non-embedded tool set still includes `sessions_send`, and https://github.com/openclaw/openclaw/pull/91161 is an open closing fix candidate rather than a merged implementation.

## What This Changes

The issue reports that an A2A `sessions_send` target can reverse-call `sessions_send` back to the requester, causing duplicate visible channel messages and requester-session reinjection.

## Best Possible Solution

Land or replace the narrow guard from https://github.com/openclaw/openclaw/pull/91161 so sessions_send A2A target turns cannot expose `sessions_send` again, while preserving normal session tools and existing result delivery paths.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: current main tags A2A target turns as `inter_session`/`sessions_send` and still exposes `sessions_send` in normal non-embedded tool construction. A live Discord two-agent run was not repeated in this read-only pass.

## Solution Assessment

Yes: the narrowest maintainable fix is to make `sessions_send` unavailable only during turns that are themselves processing a `sessions_send` A2A message. Broader one-way dispatch semantics are a separate product feature tracked by https://github.com/openclaw/openclaw/issues/44309.
