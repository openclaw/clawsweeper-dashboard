## Summary

Keep open: current main and the latest release still route A2A target turns with `sourceTool: "sessions_send"` while exposing the normal `sessions_send` tool, so the reverse-call duplicate-delivery problem remains. The issue has an open closing PR that is the active narrow fix candidate, so this should stay canonical until that or an equivalent guard lands.

## What This Changes

The issue reports duplicate requester-visible messages when a `sessions_send` A2A target can call `sessions_send` back to the requester during the same handoff.

## Best Possible Solution

Land a provenance-scoped guard that removes `sessions_send` only from A2A target turns, with regression coverage and real A2A proof that normal peer announce behavior still works without duplicate requester-visible delivery.

## Reproduction Assessment

Yes at source level: current main marks A2A target turns as inter-session `sessions_send` input and still exposes the normal `sessions_send` tool to non-embedded target runs. I did not run a live Discord or multi-agent transport reproduction in this read-only review.

## Solution Assessment

Yes: a per-turn guard keyed off A2A `sessions_send` provenance is the narrowest maintainable fix for the reverse-call duplicate. The broader one-way dispatch mode remains separate product/API work tracked elsewhere and should not block this bug fix.
