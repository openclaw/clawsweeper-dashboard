The issue asks OpenClaw to prevent an A2A target session from reverse-calling sessions_send back to the requester and duplicating requester-visible output.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/91161 or an equivalent provenance-scoped guard that hides only sessions_send during sessions_send-routed A2A target turns, with real A2A proof that normal non-A2A sends still work.
