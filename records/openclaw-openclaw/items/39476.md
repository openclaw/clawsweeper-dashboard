## Label Justifications

- `P1`: The issue describes a user-facing A2A/session workflow that can duplicate channel messages and waste extra agent turns in production.
- `impact:session-state`: The failure is rooted in inter-session A2A requester/target session routing being re-entered with the wrong tool surface.
- `impact:message-loss`: The affected behavior is message delivery correctness: the requester channel can receive duplicate semantic replies from one A2A request.

## Summary

Keep open: current main and the latest release still expose `sessions_send` during `sessions_send`-routed A2A target turns, and the direct linked implementation candidate is still open rather than merged.

## What This Changes

The issue requests preventing A2A target agents from reverse-calling `sessions_send` back to the requester during an inter-agent send because the normal tool return path can already deliver the reply.

## Best Possible Solution

Land a narrow per-turn tool guard like https://github.com/openclaw/openclaw/pull/91161 after real A2A behavior proof, so `sessions_send`-routed target turns cannot call `sessions_send` back while ordinary turns keep the tool.
