## Summary

Keep open: current main and v2026.6.11 still reject ignored human-readable group-entry metadata, and the related WhatsApp work covers runtime name matching rather than cross-channel metadata.

## What This Changes

The issue asks for an optional ignored string metadata field on channel group config entries so numeric group IDs can be annotated for humans and agents.

## Best Possible Solution

Choose one canonical optional string metadata field, apply it consistently across relevant group-entry types, strict schemas, generated metadata, docs, and validation, preserve it through config load/write, and ignore it at runtime.

## Reproduction Assessment

Yes, at source level. Representative strict group-entry schemas and typed config surfaces still omit the requested descriptive field, so the proposed config shape remains unsupported on current main and v2026.6.11.

## Solution Assessment

Unclear until maintainers choose the public config contract. The maintainable solution is one canonical metadata field across schemas, types, generated metadata, docs, and tests rather than multiple aliases or a per-channel-only label.
