## Summary

Keep this issue open. Current main still validates Telegram group entries as behavior-only settings, while group documentation continues to show opaque ID keys; the requested display metadata is therefore missing. The related WhatsApp work is functionally different and cannot replace a display-only cross-channel config contract. Likely related people: steipete (high confidence) and vincentkoc (medium confidence).

## What This Changes

Add one optional display-only string field to channel group-entry configuration so people and configuration-editing agents can identify ID-keyed groups without changing runtime routing.

## System Context

Channel configuration maps stable group, room, or guild identifiers to per-group policy. The configuration schema and generated metadata feed `config.patch` and other config tooling, then channel runtimes read only the behavior settings when handling messages.

## Architecture Diagram

flowchart LR
  A[OpenClaw configuration] --> B[Channel group ID map]
  B --> C[Strict group-entry schema]
  C --> D[Config tooling and patch API]
  D --> E[Validated channel settings]
  E --> F[Group policy and message handling]

## Best Possible Solution

Adopt one clearly display-only field—preferably `label` to avoid collision with runtime group-name matching—through a shared group-entry contract, preserve it in validated config reads and writes, ignore it during routing, and cover representative built-in channels with schema and no-behavior-change tests.

## Solution Assessment
