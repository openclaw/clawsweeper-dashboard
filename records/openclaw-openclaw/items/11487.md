## Summary

Keep open: current main and the latest release still reject the requested ignored metadata field on nested channel group config entries, and the related WhatsApp work is a narrower runtime name-matching feature rather than this cross-channel config contract.

## What This Changes

Add a runtime-ignored optional string metadata field to channel group config entries so opaque group IDs can have human-readable labels.

## Best Possible Solution

Adopt one canonical descriptive string field, likely name, across the relevant schemas, types, generated metadata, docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.
