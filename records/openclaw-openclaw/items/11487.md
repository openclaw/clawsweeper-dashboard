## Summary

Keep this issue open: current main still rejects display-only fields on strict group-entry schemas, and choosing a permanent field name and cross-channel scope remains a maintainer product decision.

## What This Changes

Add an optional human-readable metadata field to stable-ID-keyed channel group configuration entries without changing their runtime behavior.

## Best Possible Solution

Adopt one display-only field—preferably `label` to distinguish it from runtime name matching—for the selected stable-ID-keyed group-entry contracts, then update schemas, types, generated metadata, docs, and validation coverage together while keeping routing and authorization based only on the existing keys.
