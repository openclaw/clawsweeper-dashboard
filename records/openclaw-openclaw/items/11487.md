## Summary

Current main and v2026.6.11 still reject descriptive metadata in strict group-entry schemas, while the related WhatsApp work addresses distinct runtime name matching. The feature remains useful, but its permanent field name and cross-channel scope need maintainer approval.

## What This Changes

Add optional human-readable metadata to opaque-ID-keyed channel group configuration entries.

## Best Possible Solution

Standardize one ignored `name` field only for applicable opaque-ID-keyed group or channel entry objects, preserve it through validated config reads and writes, and align types, schemas, generated metadata, docs, and focused acceptance tests without changing runtime matching or authorization.
