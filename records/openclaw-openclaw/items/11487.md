## Summary

Keep open: current main and the latest release still reject ignored human-readable metadata on strict channel group config entries, and the remaining blocker is a public config-contract choice rather than stale cleanup.

## What This Changes

The issue requests one optional ignored string metadata field, such as `name` or `label`, for group-like channel config entries.

## Best Possible Solution

Approve one canonical descriptive string field, likely `name`, then add it consistently to relevant schemas, exported types, generated metadata, docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.
