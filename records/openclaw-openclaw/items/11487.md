## Summary

The remaining blocker is maintainer agreement on the canonical field name and scope. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/config/zod-schema.providers-core.ts))

## What This Changes

Add an optional, runtime-ignored human-readable metadata field to channel group, room, or channel config entries keyed by opaque identifiers. ([github.com](https://github.com/openclaw/openclaw/issues/11487))

## Best Possible Solution

Adopt one shared metadata-only key—preferably `label`—on public opaque-ID group, room, and channel entry contracts, preserve it through config reads and writes, expose it through generated schema metadata, document it, and explicitly exclude it from routing, matching, and authorization.

- **Standardize `name` metadata:** Use `name` to align with account display-name conventions, while documenting and testing that it is not a runtime lookup key.
- **Keep comments and discovery tools:** Decline another config field and instead improve group-ID discovery or schema/UI presentation while relying on JSON5 comments for manual annotations.
