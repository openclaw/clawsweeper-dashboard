## Summary

Keep open: current main and v2026.6.11 still do not provide a cross-channel ignored descriptive metadata field on representative group/channel config entries, and the related WhatsApp work solves a different functional group-name matching problem.

## What This Changes

The issue requests an optional string metadata field such as `name`, `label`, or `description` on channel group config entries for human and agent readability.

## Best Possible Solution

Approve one canonical optional string metadata field and apply it consistently across relevant group-entry types, strict schemas, generated metadata, docs, and validation coverage while preserving the value through config load/write and ignoring it at runtime.

## Reproduction Assessment

Yes, at source level: representative strict group-entry schemas and typed config surfaces still omit the requested descriptive field, so the proposed config shape remains unsupported on current main and the latest release.

## Solution Assessment

Unclear until maintainers choose the public config contract. The maintainable solution is one canonical metadata field across schemas, types, generated metadata, docs, and tests rather than multiple aliases or per-channel-only labels.
