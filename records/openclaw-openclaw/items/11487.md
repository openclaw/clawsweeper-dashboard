## Summary

Keep open: current main and v2026.6.11 still omit the requested ignored descriptive group-entry metadata from representative strict schemas, TypeScript config types, generated config-derived docs, and public docs; the related WhatsApp work only partially overlaps on functional exact-name matching.

## What This Changes

Request adding one optional ignored string metadata field such as `name`, `label`, or `description` to group/channel config entries so numeric group IDs are readable for humans and agents.

## Best Possible Solution

Approve one canonical descriptive string field and apply it consistently across relevant group-entry types, strict schemas, generated channel config metadata, public docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.

## Reproduction Assessment

Yes, at source level: representative strict group-entry schemas and typed config surfaces still omit the requested descriptive field, so unrecognized metadata remains invalid without a live channel run.

## Solution Assessment

Unclear until maintainers choose the public config contract. The maintainable solution is one canonical metadata field across schemas, types, generated metadata, docs, and tests rather than multiple aliases or per-channel labels.
