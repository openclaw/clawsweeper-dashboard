Keep open: current main and the latest release still do not accept ignored human-readable group-entry metadata, and the only linked WhatsApp work solves a narrower runtime name-matching problem rather than this cross-channel config-contract request.

## What This Changes

The issue requests an optional ignored string field such as `name`, `label`, or `description` on channel group config entries so numeric group IDs can be labeled for people and agents.

## Best Possible Solution

Approve one canonical descriptive string field for relevant group-entry schemas, preserve it through config load/write, ignore it at runtime, regenerate metadata, update docs, and add validation coverage.
