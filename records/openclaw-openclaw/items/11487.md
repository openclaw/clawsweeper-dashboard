## Summary

Keep open: current main and the latest release still reject descriptive metadata on strict group-entry schemas, and the related WhatsApp work solves mutable-name runtime matching rather than this cross-channel metadata contract.

## What This Changes

The issue requests an optional ignored human-readable string field such as `name`, `label`, or `description` on channel group config entries.

## Best Possible Solution

Approve one canonical descriptive string field, likely `name`, and update the relevant group-entry types, strict schemas, generated metadata, public docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.
