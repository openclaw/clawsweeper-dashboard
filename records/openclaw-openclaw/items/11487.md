## Summary

Keep open: current main and v2026.6.11 still omit an ignored human-readable metadata field from representative strict group-entry config schemas, and the related WhatsApp work only partially overlaps by changing runtime name matching.

## What This Changes

The issue requests an optional `name`, `label`, or `description` string field on channel group config entries for human and agent readability.

## Best Possible Solution

Choose one optional string metadata field and apply it consistently across relevant group-entry types, strict schemas, generated channel config metadata, docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.

## Reproduction Assessment

Yes, at source level. Representative strict group-entry schemas and typed config surfaces still omit the requested descriptive field, so unrecognized metadata remains invalid without a live channel run.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable shape is one canonical metadata field across schemas, types, generated metadata, docs, and tests rather than per-channel labels or multiple aliases.
