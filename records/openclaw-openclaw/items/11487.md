## Summary

Keep open: current main and the latest release still reject the requested ignored human-readable group-entry metadata, while the related WhatsApp issue and PR only cover runtime group-name matching for one channel.

## What This Changes

The issue requests an optional human-readable metadata field such as name, label, or description on channel group config entries.

## Best Possible Solution

Choose one canonical optional string metadata field, then update the relevant strict schemas, exported config types, generated channel metadata, docs, and validation tests together while preserving the field through config load/write and ignoring it at runtime.

## Reproduction Assessment

Yes, at source level. Current strict representative group-entry schemas and typed config surfaces omit the requested descriptive field, so unrecognized metadata remains invalid without needing a live channel run.

## Solution Assessment

Unclear until maintainer product review: adding one optional string field is a plausible narrow implementation, but the best fix depends on the canonical field name and whether all relevant channel group-entry surfaces should accept it together.
