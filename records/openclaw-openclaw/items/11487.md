## Summary

Keep this issue open: the requested display-only metadata remains a cross-channel public config-contract decision, and the related WhatsApp name-matching work is intentionally functional and does not replace it. A maintainer should choose the canonical field name and supported entry scope before implementation.

## What This Changes

Add an optional display-only string field to channel group configuration entries so opaque group IDs can be annotated without changing runtime behavior.

## Best Possible Solution

Adopt one clearly display-only field—preferably `label` to avoid runtime-name ambiguity—only if maintainers want it consistently supported on the selected channel group-entry contracts, with schema/type/metadata/docs coverage and no runtime matching semantics.
