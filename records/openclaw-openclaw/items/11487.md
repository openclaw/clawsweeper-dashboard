## Summary

Keep open: current main and the latest release still do not accept an ignored human-readable metadata field on strict nested channel group config entries, and the related WhatsApp work is only a narrower runtime name-matching path.

## What This Changes

Request to add one optional string metadata field, such as `name`, `label`, or `description`, to channel group config entries for human and agent readability.

## Best Possible Solution

Approve one canonical descriptive string field, likely `name`, then update the relevant group-entry schemas, TypeScript types, generated metadata, public docs, and validation coverage while preserving the field through config load/write and ignoring it at runtime.
