## Summary

Keep open: current main still lacks a consistent inert metadata field for channel group entries, and the remaining question is a public cross-channel config decision rather than stale or superseded work.

## What This Changes

Add one optional human-readable metadata field to channel group configuration entries without changing runtime group behavior.

## Best Possible Solution

If maintainers approve the surface, reserve one semantically inert field such as `label` for descriptive metadata, add it consistently to the applicable group-entry contracts and generated metadata, preserve it during config round trips, document it, and leave all existing functional `name` matching unchanged.
