## Summary

Keep open: current main and the latest release still reject human-readable metadata on nested channel group config entries, and the related WhatsApp work is narrower functional group-name matching rather than this cross-channel config contract.

## What This Changes

The issue requests an optional runtime-ignored string field such as `name`, `label`, or `description` on channel group config entries.

## Best Possible Solution

Approve one canonical descriptive string field, likely `name`, and apply it consistently across relevant group-entry schemas, types, generated metadata, docs, and validation while preserving it through config load/write and ignoring it at runtime.
