## Summary

Keep open: current main and v2026.6.11 still reject ignored human-readable metadata on representative group config entries, and the related WhatsApp work is a different runtime name-matching feature rather than this cross-channel metadata contract.

## What This Changes

Request to add one optional string metadata field, such as `name` or `label`, to channel group config entries so numeric or platform-specific group IDs are readable for humans and agents.

## Best Possible Solution

Choose one canonical optional string metadata field and add it consistently to relevant group-entry types, strict schemas, generated metadata, docs, and validation while preserving it through config load/write and ignoring it at runtime.

## Reproduction Assessment

Yes, at source level: representative strict group-entry schemas, TypeScript config types, generated metadata, and docs still omit the requested descriptive field on current main and v2026.6.11.

## Solution Assessment

Unclear until maintainers choose the public config contract. The maintainable path is one canonical metadata field across schemas, types, generated metadata, docs, and tests, not multiple aliases or a per-channel-only label.
