## Summary

Keep open: current main and v2026.6.11 still reject an ignored human-readable metadata field on representative channel group config entries, and the related WhatsApp work only partially overlaps because it changes runtime group-name matching rather than cross-channel metadata.

## What This Changes

Request to add one optional ignored string metadata field, such as `name` or `label`, to channel group config entries so numeric group IDs are readable by people and agents.

## Best Possible Solution

Choose one canonical optional string metadata field and apply it consistently across relevant group-entry types, strict Zod schemas, generated metadata, docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.

## Reproduction Assessment

Yes, at source level: representative strict group-entry schemas and typed config surfaces still omit the requested descriptive field, so the proposed config shape remains unsupported on current main and v2026.6.11.

## Solution Assessment

Unclear until maintainers choose the public config contract. The maintainable solution is one canonical metadata field across schemas, types, generated metadata, docs, and tests rather than multiple aliases or a per-channel-only label.
