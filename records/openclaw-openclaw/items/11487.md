## Summary

Keep open: current main and the latest release still do not accept ignored descriptive metadata inside channel group config entries, and the related WhatsApp work only covers functional exact-name matching for one channel.

## What This Changes

The issue requests an optional human-readable `name`/`label`/`description` string field on group config entries across channel types.

## Best Possible Solution

Approve one canonical descriptive string field, likely `name`, then update the relevant schemas, types, generated channel metadata, docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.
