## Summary

Keep open: current main and latest release still reject ignored human-readable group-entry metadata, and the linked WhatsApp issue/PR only cover runtime name matching rather than the requested cross-channel metadata field.

## What This Changes

Add an optional ignored string metadata field such as `name` or `label` to channel group config entries so numeric or platform-specific group keys are easier to identify.

## Best Possible Solution

Choose one canonical optional string metadata field, add it consistently to relevant group-entry types, strict schemas, generated metadata, docs, and validation, and preserve it through config load/write while ignoring it at runtime.

## Reproduction Assessment

Yes, at source level: representative strict group-entry schemas, TypeScript config types, generated metadata, and docs still omit the requested descriptive field on current main and v2026.6.11.

## Solution Assessment

Unclear until maintainers choose the public config contract; the maintainable path is one canonical metadata field across schemas, types, generated metadata, docs, and tests, not multiple aliases or a per-channel-only label.
