## Summary

Keep open: current main and v2026.6.11 still do not accept a human-readable metadata field on strict nested channel group config entries, and the related WhatsApp work is a narrower runtime name-matching feature rather than this cross-channel ignored-metadata contract.

## What This Changes

The issue requests one optional ignored string metadata field such as `name`, `label`, or `description` on channel group config entries.

## Best Possible Solution

Approve one canonical descriptive string field, likely `name`, then update the relevant group-entry schemas, TypeScript types, generated metadata, docs, and validation coverage while preserving the field through config load/write and ignoring it at runtime.
