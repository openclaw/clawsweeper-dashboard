## Summary

Keep open: current main and the latest release still reject the requested ignored human-readable metadata field on strict channel group entries, and the linked WhatsApp work is a narrower runtime name-matching feature rather than the cross-channel config metadata contract.

## What This Changes

The issue requests an optional descriptive string field such as `name`, `label`, or `description` on channel group config entries.

## Best Possible Solution

Approve one canonical descriptive string field, likely `name`, then update the relevant group-entry schemas, TypeScript types, generated metadata, public docs, and validation coverage while preserving the field through config load/write and ignoring it at runtime.
