## Summary

Keep open: current main and the latest release still omit an ignored descriptive metadata field from strict channel group-entry schemas, typed config surfaces, generated channel schema metadata, and docs; the related WhatsApp work overlaps on readability but solves a different runtime matching problem.

## What This Changes

The issue requests an optional ignored human-readable name, label, or description string on channel group config entries so group IDs in openclaw.json are easier for people and agents to identify.

## Best Possible Solution

Approve one canonical descriptive string field and apply it across relevant group-entry types, strict Zod schemas, generated metadata, docs, and validation tests while preserving and ignoring it at runtime.

## Reproduction Assessment

Yes, at source level. Current strict representative group-entry schemas and typed config surfaces omit the requested descriptive field, so unrecognized metadata remains invalid without needing a live channel run.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable shape is one canonical metadata field across schemas, types, generated metadata, docs, and tests rather than per-channel labels or multiple aliases.
