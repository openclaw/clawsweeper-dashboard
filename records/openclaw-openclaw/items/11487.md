## Summary

Keep open: current main and the latest release still reject ignored human-readable metadata on strict channel group entries, while the related WhatsApp item is a narrower runtime name-matching feature rather than this cross-channel config contract.

## What This Changes

The issue requests an optional ignored string field such as `name`, `label`, or `description` on channel group config entries so opaque numeric IDs are easier for humans and agents to maintain.

## Best Possible Solution

Choose one metadata key and add it consistently to the strict group-entry schemas, exported types, generated config metadata, validation tests, and public docs while preserving the value through config load/write and ignoring it at runtime.
