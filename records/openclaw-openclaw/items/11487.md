## Summary

Keep open: current main and the latest release still reject ignored human-readable metadata on nested channel group config entries, and the open WhatsApp follow-up is narrower functional group-name matching rather than this cross-channel config metadata contract.

## What This Changes

The issue requests an optional ignored string metadata field such as `name`, `label`, or `description` on channel group config entries so numeric group IDs can be annotated for humans and agents.

## Best Possible Solution

Approve one canonical descriptive string field, likely `name`, then add it consistently to relevant schemas, exported types, generated metadata, docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.
