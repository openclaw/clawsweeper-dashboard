## Summary

Keep open: current main and the latest stable release still reject ignored descriptive metadata on strict channel group config entries, and the remaining blocker is a public config-contract choice rather than conservative cleanup.

## What This Changes

The issue requests one optional string metadata field, such as `name` or `label`, on channel group config entries for human and agent readability.

## Best Possible Solution

Approve one canonical descriptive string field, likely `name`, then add it consistently to relevant schemas, exported types, generated metadata, docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.
