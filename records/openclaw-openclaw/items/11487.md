## What This Changes

The issue requests an optional ignored string metadata field, such as `name` or `label`, on channel group config entries.

## Best Possible Solution

Approve one canonical optional string metadata field for group/channel entries, then update schemas, types, generated metadata, docs, and validation coverage while preserving the field and ignoring it at runtime.

## Reproduction Assessment

Yes, at source level. Current strict representative group-entry schemas and typed config surfaces omit the requested field, so `name` or `label` metadata remains invalid without a live channel run.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable shape is one canonical metadata field across schemas, types, generated metadata, docs, and tests rather than per-channel labels or multiple aliases.
