Keep open: current main and the latest release still reject ignored descriptive metadata on representative strict group-entry schemas, while the related WhatsApp issue and PR solve a different runtime name-matching problem.

## What This Changes

Request an optional metadata-only string field such as `name` or `label` on channel group config entries for human and agent readability.

## Best Possible Solution

Approve one canonical metadata-only string field and apply it consistently across relevant group-entry types, strict schemas, generated metadata, docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.
