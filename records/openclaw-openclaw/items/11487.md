## Summary

Keep open: current main and the latest release still do not accept an ignored human-readable metadata field on strict channel group config entries, and the linked WhatsApp work is a narrower runtime group-name matching path rather than this cross-channel config metadata contract.

## What This Changes

Request to add one optional human-readable string field, such as `name`, `label`, or `description`, to channel group config entries for people and agents editing `openclaw.json`.

## Best Possible Solution

Approve one canonical descriptive string field, likely `name`, then update the relevant group-entry schemas, TypeScript types, generated metadata, public docs, and validation coverage while preserving the field through config load/write and ignoring it at runtime.
