## Summary

Keep open: current main and the latest release still do not accept a human-readable metadata field on representative strict channel group config entries, and the linked WhatsApp work is a narrower runtime name-matching path rather than this cross-channel config metadata contract.

## What This Changes

Add an optional ignored string metadata field such as `name`, `label`, or `description` to channel group config entries so opaque group IDs are easier for humans and agents to identify.

## Best Possible Solution

Approve one canonical optional metadata field, likely `name`, then add it consistently to relevant group-entry schemas, exported types, generated metadata, docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.
