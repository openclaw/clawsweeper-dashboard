The issue requests an optional ignored string field such as `name`, `label`, or `description` on channel group config entries for human and agent readability.

## Best Possible Solution

Approve one canonical descriptive string field and apply it consistently across relevant group-entry schemas, exported config types, generated metadata, docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.

## Reproduction Assessment

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable path is one canonical metadata field across schemas, types, generated metadata, docs, and tests rather than multiple aliases or per-channel labels.
