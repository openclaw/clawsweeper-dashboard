## Summary

Current main still rejects user-authored metadata on representative strict group-entry schemas, and no related issue or PR supersedes the broad inert-metadata request. Keep this open for a maintainer decision because the unresolved question is whether to add a public cross-plugin config field or improve discovered-name tooling instead.

## What This Changes

Add an optional inert human-readable field to channel group configuration entries.

## Best Possible Solution

Adopt a canonical optional `label` string owned by each applicable channel plugin, preserve it through config parsing and writing, keep stable IDs authoritative, regenerate configuration metadata, document its inert semantics, and add schema plus round-trip tests; if maintainers reject more config surface, enhance config or directory tooling to display discovered names beside stable IDs instead.
