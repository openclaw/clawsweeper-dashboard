Keep open: current main and the latest release still reject nested group-entry metadata, and the related WhatsApp group-name work is a narrower runtime-matching change rather than this ignored metadata contract.

## What This Changes

Requests an optional runtime-ignored human-readable metadata field, such as `name`, `label`, or `description`, on channel group config entries.

## Best Possible Solution

Choose one canonical descriptive string field, likely `name`, then add it consistently to group-entry schemas, exported types, generated metadata, docs, validation coverage, and the explicit config mutation policy if agents are allowed to set it; runtime behavior should ignore it.
