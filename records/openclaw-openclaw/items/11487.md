## Summary

Keep open: current main and the latest release still reject ignored human-readable metadata on strict channel group config entries, and the related WhatsApp work is narrower runtime name matching rather than this cross-channel config contract.

## What This Changes

Request to accept one optional human-readable metadata string on channel group config entries so opaque group keys can be labeled without changing runtime behavior.

## Best Possible Solution

Approve one canonical descriptive string field, likely name, then update the relevant group-entry schemas, TypeScript types, generated metadata, public docs, and validation coverage while preserving it and ignoring it at runtime.
