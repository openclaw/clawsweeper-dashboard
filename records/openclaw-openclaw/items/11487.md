Keep open: current main and the latest release still do not accept an ignored human-readable metadata field on channel group-entry config, and the related WhatsApp issue/PR only cover functional WhatsApp group-name matching, not this cross-channel config-contract request.

## What This Changes

The issue requests an optional ignored string metadata field such as `name` or `label` on channel group config entries for human and agent readability.

## Best Possible Solution

Approve one canonical descriptive string field and apply it consistently across relevant group-entry types, strict schemas, generated metadata, docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.

## Reproduction Assessment

Yes, at source level. Representative strict group-entry schemas and typed config surfaces omit the requested descriptive field, so unrecognized metadata remains invalid without needing a live channel run.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable shape is one canonical metadata field across schemas, types, generated metadata, docs, and tests rather than per-channel labels or multiple aliases.
