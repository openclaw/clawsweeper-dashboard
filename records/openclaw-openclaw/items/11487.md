## Summary

Keep open: current main and the latest release still do not accept an ignored human-readable metadata field on strict channel group entries, and the related WhatsApp item is a narrower runtime name-matching feature rather than this cross-channel config metadata contract.

## What This Changes

Add an optional ignored string metadata field such as `name`, `label`, or `description` to group/channel config entries so opaque group IDs are easier for humans and agents to identify.

## Best Possible Solution

Choose one canonical optional string metadata key and add it consistently to strict group/channel entry schemas, TypeScript types, generated config metadata, docs, and config load/write preservation while keeping runtime behavior unchanged.
