## Summary

Keep open: current main and v2026.6.11 still omit the requested ignored descriptive metadata field from representative strict group schemas, TypeScript config types, generated config metadata, and group docs. The related WhatsApp issue and PR only partially overlap because they handle mutable runtime name matching, not cross-channel metadata-only labels.

## What This Changes

Add an optional ignored string metadata field such as `name`, `label`, or `description` to group/channel config entries so numeric room IDs can be self-describing.

## Best Possible Solution

Approve one canonical descriptive string field and add it consistently across relevant group-entry types, strict schemas, generated metadata, docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.

## Reproduction Assessment

Yes, at source level. Representative strict group-entry schemas and typed config surfaces still omit the requested descriptive field, so unrecognized metadata remains invalid without needing a live channel run.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable path is one canonical metadata field across schemas, types, generated metadata, docs, and tests rather than several aliases or per-channel one-offs.
