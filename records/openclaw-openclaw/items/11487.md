## Summary

Keep open: current main and v2026.6.11 still omit the requested ignored descriptive group-entry metadata from representative strict schemas, TypeScript config types, generated metadata, and docs; the related WhatsApp group-name work only partially overlaps because it changes runtime matching rather than adding metadata-only labels.

## What This Changes

The issue asks OpenClaw to accept one optional ignored string metadata field such as `name`, `label`, or `description` on channel group config entries.

## Best Possible Solution

Choose one canonical optional string metadata field and apply it consistently across relevant group-entry types, strict schemas, generated metadata, docs, and validation while preserving it through config load/write and ignoring it at runtime.

## Reproduction Assessment

Yes, at source level: representative strict group-entry schemas and typed config surfaces still omit the requested descriptive field, so unrecognized metadata remains invalid without a live channel run.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable solution is one canonical metadata field across schemas, types, generated metadata, docs, and tests rather than per-channel labels or multiple aliases.
