## Summary

Keep open: current main still rejects the requested ignored descriptive metadata on representative strict group-entry schemas and types, the latest release has the same gap, and the related WhatsApp issue/PR only cover functional runtime name matching for one channel.

## What This Changes

Add an optional ignored string metadata field such as `name` or `label` to channel group config entries so numeric group IDs can be human- and agent-readable.

## Best Possible Solution

Approve one canonical descriptive string field, add it consistently to relevant group-entry types, strict schemas, generated metadata, docs, and validation tests, preserve it through config writes, and ignore it at runtime.

## Reproduction Assessment

Yes, at source level: adding `name` or `label` to representative group entries would hit strict schemas that do not declare the field. A live channel run is not needed to prove the current config-contract gap.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable path is one canonical metadata field across schemas, types, generated metadata, docs, and tests, not multiple aliases or per-channel labels.
