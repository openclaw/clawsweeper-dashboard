## Summary

Keep open: current main and the latest release still reject the requested ignored human-readable group-entry metadata, and the related WhatsApp issue/PR only covers functional WhatsApp name matching rather than cross-channel metadata.

## What This Changes

Add an optional string metadata field such as `name` or `label` to channel group config entries so numeric room IDs can be annotated for humans and agents.

## Best Possible Solution

Choose one canonical optional string metadata field and apply it consistently across relevant group-entry types, strict schemas, generated metadata, docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.

## Reproduction Assessment

Yes, at source level: representative strict group-entry schemas and typed config surfaces still omit the requested descriptive field, so the proposed config shape remains unsupported on current main and v2026.6.11.

## Solution Assessment

Unclear until maintainers choose the public config contract. The maintainable solution is one canonical metadata field across schemas, types, generated metadata, docs, and tests rather than multiple aliases or a per-channel-only label.
