## Summary

Keep open: current main and v2026.6.11 still do not accept an ignored human-readable metadata field on strict channel group config entries, and the related WhatsApp issue/PR only cover runtime exact-name matching for one channel.

## What This Changes

Add an optional ignored string metadata field such as `name`, `label`, or `description` to channel group config entries.

## Best Possible Solution

Approve one canonical descriptive string field, likely `name`, then update relevant group-entry schemas, TypeScript types, generated metadata, docs, and validation coverage while preserving the field through config load/write and ignoring it at runtime.
