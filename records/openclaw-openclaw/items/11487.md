## Summary

Keep open: current main and the latest release still omit a cross-channel ignored descriptive field on representative strict group-entry schemas, while the related WhatsApp work only covers functional exact-name matching for one channel.

## What This Changes

Request an optional string `name`, `label`, or similar metadata field on channel group config entries for human and agent readability.

## Best Possible Solution

Approve one canonical descriptive string field and apply it consistently across relevant group-entry types, strict schemas, generated metadata, docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.

## Reproduction Assessment

Yes, at source level: representative strict group-entry schemas and typed config surfaces still omit the requested descriptive field, so unrecognized metadata remains invalid without a live channel run.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable path is one canonical metadata field across schemas, types, generated metadata, docs, and tests rather than several aliases or per-channel labels.
