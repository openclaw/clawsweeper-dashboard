## Summary

Keep open: current main and the latest release still reject metadata-only `name`/`label`/`description` fields in representative strict group-entry config schemas and typed config surfaces, while the related WhatsApp work only covers runtime name matching.

## What This Changes

The issue requests one optional string metadata field on channel group config entries so people and agents can identify opaque group IDs without changing runtime behavior.

## Best Possible Solution

Approve one canonical descriptive string field and apply it consistently across relevant group-entry schemas, types, generated metadata, docs, and validation coverage while preserving it through config load/write and ignoring it at runtime.
