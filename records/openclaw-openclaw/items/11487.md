## Summary

Keep open: current main still rejects inert human-readable metadata in representative strict group schemas. JSON5 comments and `channels resolve` mitigate parts of the usability problem but do not provide persistent schema-visible metadata, while the linked WhatsApp issue and PR implement security-sensitive runtime name matching rather than this request.

## What This Changes

Add an optional inert human-readable metadata field to channel group configuration entries keyed by opaque identifiers.

## Best Possible Solution

Standardize one optional `name` string for group or room entries keyed by opaque identifiers, add it through each owning channel schema and type, preserve it through config reads and writes, keep routing and authorization keyed exclusively by the existing identifier, regenerate config metadata, and document and test its inert semantics.
