## Summary

Keep open: current main and the latest release still do not accept an ignored human-readable metadata field on nested channel group config entries, and the related WhatsApp work is narrower functional group-name matching rather than this cross-channel config metadata contract.

## What This Changes

The issue requests an optional string field such as `name`, `label`, or `description` on channel group config entries so numeric group IDs can be identified by humans and agents without changing runtime behavior.

## Best Possible Solution

Approve one canonical descriptive string field, likely `name`, then update the relevant group-entry schemas, TypeScript types, generated metadata, public docs, and validation coverage while preserving the field through config load/write and ignoring it at runtime.
