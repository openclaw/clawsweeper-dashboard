## Summary

Keep open: current main still lacks persistent schema-visible metadata for opaque channel group entries. JSON5 comments and `openclaw channels resolve` improve manual lookup, but neither gives agents a validated identifier that survives programmatic config edits; the linked WhatsApp work is a distinct runtime name-matching feature.

## What This Changes

Add one optional inert human-readable string field to channel group configuration entries.

## Best Possible Solution

Define one optional inert metadata field for the selected opaque-ID group-entry contracts, preserve it through config reads and writes, expose it consistently in types and generated schema metadata, document it, and prove it has no runtime policy effect.

Rationale: The canonical field name and cross-channel scope become public configuration contract and documentation decisions; source inspection cannot determine the intended long-term product shape.

Likely owner: steipete

Owner confidence: high

Options:

- **Use scoped `name` metadata (recommended):** Add optional `name` only to group-entry contracts whose keys are opaque provider identifiers, with consistent schema, type, metadata, docs, and preservation tests.
- **Use universal `name` metadata:** Add optional `name` to every channel group or channel-entry contract for maximum consistency, accepting a broader public surface.
- **Keep existing lookup paths:** Decline persistent metadata and continue relying on JSON5 comments and supported `channels resolve` lookups.

## Reproduction Assessment

Yes at source level: representative strict current-main group schemas omit the proposed metadata property, so adding it to a group entry is rejected as an unknown key. No runtime reproduction is necessary to establish that schema behavior.

## Solution Assessment

Unclear pending product direction: an inert metadata property is the narrowest persistent solution, but adding it to every channel shape is broader than necessary. Scoping one canonical field to opaque-ID entries is safer than independent channel-specific additions.
