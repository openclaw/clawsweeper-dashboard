Keep open: current main and the latest release still reject a cross-channel ignored `name`/`label` metadata field on representative strict group config entries, while the related WhatsApp work only covers functional name matching for one channel.

The issue requests an optional human-readable metadata field for channel group config entries.

## Best Possible Solution

Approve one canonical descriptive string field, likely `name`, then update relevant group-entry schemas, exported types, generated channel config metadata, public docs, and validation coverage while preserving the field through config load/write and ignoring it at runtime.
