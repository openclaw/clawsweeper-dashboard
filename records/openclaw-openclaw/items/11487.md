## What This Changes

The issue requests one optional string metadata field such as `name`, `label`, or `description` on channel group config entries so humans and agents can identify numeric group IDs.

## Best Possible Solution

Choose one canonical optional string metadata field, then update all relevant strict schemas, exported config types, generated channel metadata, docs, and validation tests in one coordinated config-contract change.

## Reproduction Assessment

Yes, at source level: current strict group-entry schemas omit `name`, `label`, and `description`, so those metadata keys remain invalid even before runtime behavior is reached.

## Solution Assessment

Unclear until maintainer product review: adding one optional string field is a plausible narrow implementation, but the best fix depends on the canonical field name and whether all channel group-entry surfaces should accept it together.
