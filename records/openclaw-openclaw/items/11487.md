## What This Changes

The issue requests an optional string metadata field such as `name` or `label` on channel group config entries so numeric group IDs are easier for people and agents to identify.

## Best Possible Solution

Choose one canonical descriptive string field and apply it consistently across strict schemas, TypeScript types, generated config metadata, docs, and validation coverage while keeping runtime behavior unchanged.

## Reproduction Assessment

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable path is one canonical metadata field across schemas, types, generated metadata, docs, and tests rather than multiple aliases or per-channel labels.
