## Summary

Keep open: current main and the latest release still do not accept a runtime-ignored human-readable metadata field on most channel group config entries; the open WhatsApp group-name work is narrower runtime matching, not this cross-channel config metadata contract.

## What This Changes

The issue requests an optional `name`, `label`, or `description` string on channel group config entries so opaque group IDs can be documented in `openclaw.json`.

## Best Possible Solution

Approve one canonical descriptive string field, likely `name`, then update the relevant group-entry schemas, TypeScript types, generated metadata, public docs, and validation coverage while preserving the field through config load/write and ignoring it at runtime.
