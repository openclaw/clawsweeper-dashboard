## Summary

This PR remains necessary: its reply-metadata contract is not on current `main`, and the branch has focused coverage plus previously accepted transport proof. It should stay open for an owner decision on whether runtime-only turns may place channel-derived reply context in the active system-prompt path, rather than treating that security boundary as an ordinary mechanical merge.

## What This Changes

The branch adds structured current-turn reply identifiers, carries inbound reply context through embedded and CLI runtime paths, and keeps persisted/transcript user prompts free of reply metadata.

## Best Possible Solution

Adopt one explicit, audited untrusted runtime-envelope contract for reply bodies across normal and runtime-only turns, while keeping only transport-authenticated identifiers in structured trusted metadata and proving the same result through a live Telegram reply flow.

## Solution Assessment
