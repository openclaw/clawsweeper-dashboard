## Summary

Keep this PR open for an explicit security-boundary decision: its runtime-only path moves channel-supplied reply text into system prompt context, despite the stated goal of keeping reply bodies untrusted.

## What This Changes

The PR adds structured inbound reply identifiers and routes current-turn reply context through embedded and CLI runtime paths while preserving clean user and transcript prompts.

## Best Possible Solution

Split canonical reply identifiers from untrusted quoted/body context, keep all channel-provided text on an untrusted runtime/custom-message path, and add runtime-only coverage proving system prompts contain no reply body.
