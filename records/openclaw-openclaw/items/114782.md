Keep this issue open. It is protected by the `maintainer` label and is explicitly paired with an open draft implementation PR, so the remaining question is the intended long-term plugin-manifest contract rather than an independently actionable cleanup.

## What This Changes

Add an optional, versioned `hostIntegrationBundle` declaration to plugin manifests so one external host plugin can expose a deterministic inventory of related contributions before its runtime code loads.

## System Context

OpenClaw discovers plugin manifests before loading plugin runtime and turns enabled declarations into loader-owned registry records. This request would extend that manifest-to-registry path with an atomic host-bundle inventory while leaving activation and runtime authority with each contribution owner.

## Architecture Diagram

  C --> D[Loader-owned registry snapshot]
  D --> E[Bundle inventory consumers]

  F --> G[Contribution owners]

## Best Possible Solution

Have the plugin owner define whether host-bundle inventory is a durable core manifest contract, then review the linked PR against that chosen API boundary and compatibility plan.
