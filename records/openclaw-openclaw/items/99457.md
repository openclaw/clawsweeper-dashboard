- `impact:message-loss`: The affected path can mark an inbound group message processed before it reaches the agent runtime.

## Summary

Keep open: current main still has the reported dispatch gap, because plugin-bound `missing_plugin`/`no_handler` fallback suppresses any unmentioned group/channel turn before consulting the effective always-on mention policy.

## What This Changes

The issue reports that plugin-bound fallback can mark unmentioned always-on group messages processed instead of dispatching them to the agent session.

## Best Possible Solution

Use the existing effective group mention-policy resolver in the plugin-bound fallback path so mention-required rooms still suppress unmentioned fallback, while always-on rooms continue into normal agent dispatch.

## Reproduction Assessment

Yes, from source inspection: an unmentioned group/channel message with a plugin-owned binding and a `missing_plugin` or `no_handler` claim returns before normal dispatch whenever `ctx.WasMentioned === false`. The high-confidence gap is that this branch never checks whether the effective route policy has `requireMention: false`.

## Solution Assessment

Yes, the best fix is narrow: gate `plugin_binding_fallback_unmentioned` on the resolved mention policy instead of raw mention state alone. That keeps current mention-required suppression and explicit command bypass while restoring always-on group dispatch.
