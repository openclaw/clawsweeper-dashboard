## Summary

Keep open: current main and v2026.6.11 still complete unmentioned group/channel plugin fallback based only on `WasMentioned`, and the open linked PR is a candidate fix rather than a merged implementation.

## What This Changes

Ensure plugin-bound `missing_plugin`/`no_handler` fallback does not drop unmentioned group messages when the route allows always-on unmentioned dispatch.

## Best Possible Solution

Gate plugin fallback suppression on the resolved effective mention policy, preserve mention-required suppression, allow always-on routes into agent dispatch, and cover mention-required, always-on, and explicit-command cases with focused tests.

## Reproduction Assessment

Yes. Source inspection on current main shows an unmentioned group/channel plugin fallback returns before normal dispatch whenever `ctx.WasMentioned === false`, and shipped v2026.6.11 contains the same branch.

## Solution Assessment

Yes for the issue direction: the narrow fix is to use the effective mention policy in the fallback branch. The open linked PR needs that policy-aware shape rather than unconditional fallthrough before it can safely close the issue.
