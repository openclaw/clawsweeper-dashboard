## What This Changes

Add active-provider quota-window percentages, such as GitHub Copilot Premium/Chat, to per-response `/usage` footers.

## Best Possible Solution

Review and repair https://github.com/openclaw/openclaw/pull/96339, then land it if maintainers accept the bounded provider-usage lookup; otherwise redesign around cached or preloaded quota snapshots.

## Reproduction Assessment

Yes: source inspection on current main shows `/usage` reply footers format local token/cache/cost data only, while `/status` separately loads provider quota windows. I did not run a live provider session in this read-only review.

## Solution Assessment

Yes for the implementation direction: reusing the generic provider-usage loader and formatter keeps provider-specific fetching in plugin-owned seams. The remaining choice is whether the bounded per-reply lookup in the linked PR is acceptable or should become cached/preloaded quota state.
