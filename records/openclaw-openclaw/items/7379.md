## Summary

Keep open. Current main and the latest release still do not append provider quota windows to the per-response `/usage` footer, and the remaining implementation path is already owned by the open linked PR at https://github.com/openclaw/openclaw/pull/96339.

## What This Changes

The issue requests adding active-provider quota windows, especially GitHub Copilot Premium/Chat percentages, to the per-response `/usage` footer.

## Best Possible Solution

Review and repair https://github.com/openclaw/openclaw/pull/96339, or land a narrow replacement that reuses the generic provider-usage formatter while keeping provider-specific fetching plugin-owned and bounded.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes: source inspection on current main shows `/usage` reply footers format local token/cache/cost data only, while `/status` separately loads provider quota windows.

## Solution Assessment

Is this the best way to solve the issue? Yes, the best direction is the generic provider-usage footer bridge attempted by the linked PR; cached or preloaded quota snapshots would be safer only if maintainers reject an awaited bounded lookup in reply delivery.
