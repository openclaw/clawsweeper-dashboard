## What This Changes

Add active-provider quota windows, including GitHub Copilot Premium and Chat remaining percentages, to the existing per-response `/usage` footer.

## System Context

The reply pipeline turns an agent result and a session’s `/usage` mode into the footer delivered through the active channel. Provider plugins already expose quota windows for status reporting; this request would make a compact, provider-neutral quota summary available to the reply-footer path without moving provider-specific fetching into core.

## Architecture Diagram

  D[Provider plugin quota data] --> E[Provider usage snapshot]
  E --> F[Quota summary formatter]
  C --> G[Composed response footer]
  F --> G
  G --> H[Channel reply delivery]

## Best Possible Solution

Define a generic, lifecycle-owned provider-usage snapshot contract, then have the existing reply-footer formatter append its compact summary only for the maintainer-approved `/usage` modes; keep provider fetching and Copilot-specific window mapping inside plugins, document omit-on-unavailable behavior, and add reply/footer regression coverage.
