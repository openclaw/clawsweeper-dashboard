## What This Changes

The issue requests adding active-provider quota percentages, especially GitHub Copilot Premium/Chat remaining percentages, to per-response `/usage` footers.

## Best Possible Solution

Review and repair https://github.com/openclaw/openclaw/pull/96339, then land it if maintainers accept the bounded provider-usage lookup; otherwise redesign around cached or preloaded provider quota snapshots.

## Reproduction Assessment

Yes. Source inspection on current main shows `/usage` reply footers format local token/cache/cost or usage-template data only, while `/status` separately loads provider quota windows.

## Solution Assessment

Yes for the implementation direction: reusing the generic provider-usage loader and formatter keeps provider-specific fetching in plugin-owned seams. The remaining choice is whether maintainers accept a bounded per-reply lookup or prefer cached/preloaded quota state.
