## Summary

Keep open. Current main and v2026.6.11 still do not append provider quota windows to the per-response `/usage` footer, and the issue is paired with the open implementation candidate at https://github.com/openclaw/openclaw/pull/96339.

## What This Changes

The issue requests adding GitHub Copilot Premium/Chat quota percentages to the per-response `/usage` footer.

## Best Possible Solution

Review and repair https://github.com/openclaw/openclaw/pull/96339, or land a narrow replacement that reuses the generic provider-usage formatter while keeping provider-specific fetching plugin-owned and bounded.

## Reproduction Assessment

Yes, source inspection on current main is a high-confidence reproduction path: `/usage` reply footers format local usage data only, while `/status` separately loads provider quota windows. I did not run a live GitHub Copilot account in this read-only issue review.

## Solution Assessment

Yes, the linked generic provider-usage footer bridge is the best direction if maintainers accept a bounded per-reply lookup. A cached or preloaded quota snapshot would be the safer alternative if reply delivery must avoid provider probes.
