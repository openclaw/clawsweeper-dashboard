## Summary

Keep open for a maintainer product decision: current OpenClaw documentation still limits per-response `/usage` footers to tokens, cost, context, model, and session data, while provider quota windows remain a separate provider-usage surface. Likely related people: steipete (high confidence) for provider-usage/status ownership, with vincentkoc and sliverp as adjacent reply-footer contributors.

## What This Changes

Add the active provider’s quota windows, including GitHub Copilot Premium and Chat percentages when available, to enabled per-response `/usage` footers.

## System Context

The reply runner appends a compact usage footer after an agent response according to the session’s `/usage` mode. Provider plugins expose quota-window data for status and CLI views, but the current per-response footer contract does not consume that data.

## Architecture Diagram

flowchart LR

  B --> C[Usage footer formatter]
  C --> D[Reply footer]
  E[Provider plugin] --> F[Provider quota snapshot]
  F --> G[Status and CLI usage views]
  G --> H[Quota window display]
  F -. requested new input .-> C

## Best Possible Solution

Define a lifecycle-owned, bounded cached provider-quota snapshot and a generic optional footer summary seam; have `/usage` render that prepared snapshot without triggering a provider lookup on the reply hot path, with explicit mode and omission semantics.

Options:

- **Add it to tokens and full:** Show the same prepared quota summary for both enabled footer modes, accepting a denser `tokens` footer contract.
- **Keep quota in status views:** Retain the current separation and decline per-response provider quota display to avoid another footer data lifecycle.

## Solution Assessment
