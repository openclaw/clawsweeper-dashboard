## Summary

Keep open. Current main and v2026.6.11 still omit provider quota windows from per-response usage footers, all four direct implementation PRs closed unmerged, and no viable replacement currently owns the work; implementation should wait for a maintainer decision on how quota state enters the reply hot path.

## What This Changes

Add active-provider premium and quota percentages to per-response `/usage tokens` and `/usage full` footers.

## Best Possible Solution

Extend the generic reply-usage contract with an optional prepared active-provider quota summary, populated through provider/plugin ownership and rendered without request-time provider rediscovery.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should provider quota become part of the generic reply-usage contract, and must it use prepared or cached provider state rather than a fresh lookup after every response?

Rationale: The capability is feasible and vision-aligned, but maintainers must choose the hot-path lifecycle, polling frequency, and latency policy before implementation.

Likely owner: steipete

Owner confidence: high

Options:

- **Use prepared quota state (recommended):** Add optional active-provider quota data to the generic reply-usage contract and render it in enabled footers without a fresh reply-time lookup.
- **Fetch after each reply:** Perform a bounded provider quota lookup during footer assembly and omit the field on timeout or failure.
- **Keep quota on demand:** Leave provider quota in `/status` and keep response footers local-only.

## Reproduction Assessment

Yes at the source level: current main and v2026.6.11 format reply usage without provider quota, while the status and provider paths already expose quota windows. No live provider run was needed to confirm the missing capability.

## Solution Assessment

No, the previously proposed reply-time provider fetch is not clearly the best fix; the newer generic reply-usage contract should own prepared quota data if maintainers approve the feature.
