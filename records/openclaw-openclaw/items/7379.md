## Summary

Keep open for a maintainer product decision. The requested per-response quota display remains distinct from the existing `/status` provider-usage path, while all direct implementation pull requests in the supplied context were closed unmerged; the remaining question is whether reply footers may perform quota loading or must render only a lifecycle-owned cached snapshot.

## What This Changes

Add active-provider quota-window text, including GitHub Copilot Premium and Chat percentages when available, to `/usage` response footers.

## Best Possible Solution

Define a generic provider-usage snapshot owned outside the reply hot path, then have `/usage` render its compact shared summary only when that snapshot is available; keep provider fetching and credentials inside the provider/plugin owner and add focused footer plus failure/timeout coverage.
