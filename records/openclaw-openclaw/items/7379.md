## Summary

Keep open. Current main still does not append provider quota windows to per-response usage footers, no open or merged PR owns the exact request, and the most recent proof-sufficient candidate was closed unmerged by its contributor rather than rejected by a maintainer. The remaining question is whether automatic quota display is worth adding and how to avoid repeated provider discovery or network work during reply finalization.

## What This Changes

Add active-provider quota percentages such as GitHub Copilot Premium/Chat to per-response `/usage` footers.

## Best Possible Solution

If maintainers approve automatic quota display, feed a prepared or lifecycle-cached generic provider-usage snapshot into footer rendering, keep vendor fetching in the provider plugin, omit quota on missing, failed, or stale data, and cover both `/usage tokens` and `/usage full` without adding a Copilot-specific core path.
