Keep open. Current main still does not append provider quota windows to per-response `/usage` footers, and the issue is already paired with the open implementation candidate at https://github.com/openclaw/openclaw/pull/96339.

## What This Changes

Add active-provider premium/chat quota percentages to `/usage tokens` or `/usage full` reply footers when provider usage windows are available.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/96339, or replace it with the same narrow generic footer bridge that reuses provider-usage formatting while keeping provider fetching plugin-owned and bounded.

## Reproduction Assessment

Yes. Source inspection on current main shows `/usage` reply footers format local token/cache/cost data only, while `/status` separately loads provider quota windows.

## Solution Assessment

Yes, the best direction is the linked generic provider-usage footer bridge; it should remain bounded and plugin-owned, with maintainer acceptance of the reply-path lookup tradeoff.
