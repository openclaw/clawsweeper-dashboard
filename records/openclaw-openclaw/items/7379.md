## Summary

Keep open. Current main and the latest release still do not append provider quota windows to per-response `/usage` footers, and the issue is already paired with the open implementation candidate at https://github.com/openclaw/openclaw/pull/96339.

## What This Changes

Request to show active-provider quota windows, such as GitHub Copilot Premium and Chat percentages, in the per-response `/usage` footer.

## Best Possible Solution

Review and repair https://github.com/openclaw/openclaw/pull/96339, then land it if maintainers accept the bounded reply-path quota lookup; otherwise replace it with a cached/preloaded provider quota design.

## Reproduction Assessment

Yes. Source inspection on current main shows `/usage` reply footers format local token/cache/cost data only, while `/status` separately loads provider quota windows.

## Solution Assessment

Yes, the best current path is the generic provider-usage footer bridge in the linked PR because it keeps provider-specific fetching in the plugin-owned usage seam; a cached quota design is the safer alternative only if maintainers reject an awaited bounded lookup during reply delivery.
