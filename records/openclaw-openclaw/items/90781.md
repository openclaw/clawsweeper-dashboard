## Summary

Keep open: a fresh v2026.7.1 live reproduction shows completed narratives are still missed during message read-back, and current main retains the path that writes a fallback when no assistant text is visible. The linked pull requests remain open and address different portions of the problem rather than providing a merged fix.

## What This Changes

Prevent memory-core dreaming from discarding successfully generated narratives, improve empty-result diagnostics, and visibly distinguish fallback diary entries.

## Best Possible Solution

Make successful subagent completion provide a run-scoped durable output/read barrier, or add a keyed API that waits for that run’s assistant message; then retain a bounded, visibly marked fallback with actionable failure diagnostics and validate slow-model, queued-phase, and archived-session cases.

Rationale: Both approaches can address the symptom, but they establish different ownership and security boundaries; the open pull requests currently implement only plugin-local portions without resolving that architectural choice.

Options:

- **Fix the generic completion contract (recommended):** Make successful run completion guarantee that the run’s assistant output is durably readable, then keep memory-core on the standard session API.
- **Add plugin-local recovery:** Have memory-core poll by run identity and recover from a supported trajectory or archived-session API without changing generic completion semantics.
- **Land diagnostics separately:** Merge the diagnostic improvement as a partial observability fix while keeping the root data-loss issue open for a separate lifecycle repair.

## Reproduction Assessment

Yes at source level: current main retains the empty-read fallback path, and independent live reports reproduce persisted assistant text becoming visible only after memory-core has already written the fallback. A controlled current-main run was not performed during this read-only review.

## Solution Assessment

No, diagnostics alone are not the best fix because they leave valid generated narratives discarded. The preferred repair is a durable run-output read contract, with explicit fallback marking and diagnostics as secondary safeguards.
