## Summary

Keep this PR open: it contains useful hardening and broad automated coverage, but paired-node bridge recovery can still authorize audio from retained health after a failed refresh, and untargeted recovery can select a locale-blocked meeting tab ahead of a usable one. It also still lacks after-fix signed-in Meet or paired-node runtime proof; the protected `maintainer` label requires human handling.

## What This Changes

The branch changes meeting-bot transcript cursor retention, Google Meet tab recovery ranking, and browser/paired-node talkback readiness and bridge recovery behavior.

## Best Possible Solution

Invalidate browser health when paired-node refresh fails, recover a bridge only from a successful current unmuted observation, rank usable preferred meeting tabs ahead of merely normalized tabs, and add redacted live signed-in Meet or paired-node evidence for blocked-then-recovered talkback.
