## Summary

Keep this PR open for a narrow docs correction. The cross-Gateway limitation is real, but the proposed wording endorses a commercial third-party service and directs users to send agent data and use an API key there; that conflicts with the repository vision’s current scope and lacks an OpenClaw-owned security/support contract.

## What This Changes

The PR adds cross-links explaining that `sessions_send` is Gateway-local and recommends AgentPost for asynchronous handoff between agents on separate machines.

## System Context

Session tools let an OpenClaw agent inspect, run, and message sessions owned by its Gateway. For external destinations, the documented path is a channel conversation or the generic `message` tool, which preserves Gateway-owned delivery policy and credentials.

## Best Possible Solution

Document the supported first-party boundary: `sessions_send` is Gateway-local, while cross-machine delivery should use a configured OpenClaw channel or a separately maintained plugin/ClawHub integration; do not recommend a specific commercial relay without an explicit maintainer exception and security review.
