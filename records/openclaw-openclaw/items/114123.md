## Summary

Keep this PR open, but it still needs the prior security blocker resolved: the new guidance describes an unauthenticated inbound mailbox for agent work without documenting sender authentication, authorization, replay limits, or untrusted-input handling.

## What This Changes

The PR documents an asynchronous HTTP mail pattern for agents on separate Gateways and links that guidance from the webhook/cron documentation.

## System Context

`sessions_send` delivers work between sessions on one Gateway, while webhooks accept inbound HTTP work when a Gateway can be safely reached. This documentation proposes an external mailbox between those paths for delayed cross-Gateway handoff, which can ultimately feed untrusted network input into agent work.

## Architecture Diagram

flowchart LR
  Sender[Sender agent] --> Mailbox[Hosted mailbox or relay]
  Mailbox --> Receiver[Receiver polling client]
  Receiver --> Validation[Authentication and input validation]
  Validation --> Gateway[Receiver Gateway]
  Gateway --> Agent[Target agent work]
  Agent --> Reply[Optional reply handoff]

## Best Possible Solution

Keep the cross-Gateway documentation only after it explicitly requires authenticated and authorized sender requests, bounded/replay-resistant message handling, and validation before mailbox data reaches an OpenClaw agent; otherwise remove the prescriptive mailbox recipe and retain only the existing safe webhook and plugin/community pointers.
