## Label Justifications

- `P2`: A malformed Discord API response can cause a misleading successful operator probe, but the effect is limited to the Discord probe path rather than normal message delivery or runtime availability.

## Summary

This PR remains necessary: the current Discord probe path accepts a JSON response through the platform decoder, which can replace malformed UTF-8 bytes before the bot identity is recorded. The proposed bounded-reader decode makes that malformed-byte case follow the existing malformed-response failure path, and the supplied loopback proof exercises the production `probeDiscord()` entry point with both invalid and valid controls.

## What This Changes

The branch decodes bounded Discord `/users/@me` probe bytes with fatal UTF-8 handling before JSON parsing and adds a regression test for malformed bytes.

## Best Possible Solution

Keep the probe’s bounded response reader and make its UTF-8 decoding fatal before JSON parsing, preserving the valid-response behavior covered by the regression test.

## Solution Assessment

Yes. Fatal UTF-8 decoding at the existing bounded byte-reader is the narrowest owner-local fix: it rejects corrupt bytes before parsing without changing valid Discord probe responses or adding configuration.
