## Summary

The PR addresses a real current-main decoding bug with a narrow, compatible change: the existing decoder accepts malformed UTF-8 by inserting replacement characters before JSON parsing, while the proposed fatal decoder routes that response through the established malformed-response failure path. The supplied loopback proof exercises the production `probeDiscord()` fetch seam and shows both rejection of invalid bytes and preservation of a valid control response; no patch defect was identified.

## What This Changes

The PR changes Discord’s bounded `/users/@me` probe decoder to reject malformed UTF-8 before JSON parsing and adds a regression test for that response.

## Best Possible Solution

Merge the bounded fatal UTF-8 decode with the regression test so Discord probes never report a silently corrupted bot identity as successful.
