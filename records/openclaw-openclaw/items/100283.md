Full review comments:

- **[P2] Keep queued voice turns pending until delivery completes:** `apps/ios/WatchApp/Sources/WatchInboxView.swift:1125`
  - body: `sendChatMessage` returns the command id before the async WatchConnectivity send result is known, so voice turns start this 90-second timeout even when the command falls back to queued delivery. If the command reaches the phone late and the phone then waits for the run/reply, the tracker can cancel before `watch.chat.completion` arrives and the spoken reply is dropped.
  - confidence: 0.9
- **[P2] Avoid matching queued voice turns by substring:** `apps/ios/Sources/Model/NodeAppModel.swift:3621`
  - body: When the exact `runId:user` row is missing, `entry.text.contains(submittedText)` can anchor short dictated text like `ok` to a later unrelated user row after `submittedAtMs`. The following assistant lookup can then speak that later turn's reply for the Watch command; use a stronger queued-turn marker or avoid substring anchoring.
  - confidence: 0.89
- **[P2] Stop fallback reply search at the next user turn:** `apps/ios/Sources/Model/NodeAppModel.swift:3624-3626`
  - body: After choosing a user row, the fallback scans all later rows and returns the first terminal assistant message, even if another user turn appears first. In interleaved iPhone/Watch use this can speak the assistant response for the later user turn; bound the search to the current turn before accepting a reply.
  - confidence: 0.88
- **[P2] Route voice UI strings through native i18n:** `apps/ios/WatchApp/Sources/WatchInboxView.swift:1090-1093`
  - body: The new `Speaking reply…` / `Waiting for spoken reply…` states and voice-button accessibility labels are returned through computed properties that are not present in `apps/.i18n/native-source.json`; the only new inventory hit is `Message OpenClaw`. Localized watchOS builds would show the new voice states in English unless these strings use an extracted/localized path or the extractor is updated.
  - confidence: 0.92
- **[P2] Remove the release-owned changelog entry:** `CHANGELOG.md:27`
  - body: `CHANGELOG.md` is release-owned in this repo; normal feature PRs should carry release-note context in the PR body or commit message. Adding this entry directly can leave generated release notes duplicated or stale, so remove it from the feature branch.
