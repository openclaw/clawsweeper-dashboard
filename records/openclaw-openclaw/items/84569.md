## Summary

Current main now addresses the reported WhatsApp long-turn stall at the run/dispatch layer: long self-hosted model silence is bounded, stale reply runs force-release as `run_stalled`, and empty terminal failures get a normal user-visible fallback payload. The fix is current-main-only and not in the latest stable release yet.

## What This Changes

The issue reports that long WhatsApp-originated model calls can leave queued messages behind a stalled session and end with an incomplete turn whose fallback reply is never delivered.

## Best Possible Solution

Keep the current run-lifecycle implementation on main, close this concrete incident as fixed there, and let the broader durable fallback contract continue in https://github.com/openclaw/openclaw/issues/87561.
