## Label Justifications

- `P1`: The reported failure broke a real WhatsApp agent workflow by leaving user messages queued behind stalled model work with no visible reply.
- `impact:session-state`: The issue concerns session lanes, stuck active runs, queued follow-up turns, and terminal run attribution.
- `impact:message-loss`: The user-visible symptom is that the final fallback or reply never reaches the WhatsApp conversation.

## Summary

Current main implements the central fix: long/stale reply runs are bounded and released as `run_stalled`, self-hosted model streams get finite idle watchdogs, and terminal empty/error run outcomes are routed through normal final reply delivery. The fix is current-main-only; latest release `v2026.6.11` predates the `run_stalled` registry path.

## What This Changes

The issue asks for WhatsApp long model calls and incomplete turns to produce a visible fallback reply instead of leaving queued session state and no delivered response.

## Best Possible Solution

Ship the current run-lifecycle stack, keep broader cross-channel durable fallback semantics in https://github.com/openclaw/openclaw/issues/87561, and reopen only with fresh logs from a release containing the main fix.

## Solution Assessment
