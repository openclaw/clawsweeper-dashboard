## Summary

Keep open: current main partially improves the long-run stall path, but the WhatsApp final fallback delivery path still suppresses `isError` payloads before a user-visible send, so the central silent-reply problem remains source-reproducible.

The issue reports WhatsApp long model calls stalling a session and ending with no delivered fallback or reply.

## Best Possible Solution

Make WhatsApp deliver sanitized final fallback/error text through both inbound final delivery and routed outbound payload paths, while preserving suppression for non-final tool/progress/internal errors and keeping PR 102160’s run-lifecycle protections.
