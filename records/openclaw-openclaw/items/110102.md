## Summary

Keep this PR open: it adds a useful narrow bridge, but a direct authenticated Gateway caller can currently supply arbitrary `contextTokens` that plugins may treat as authoritative, and the PR still lacks inspectable exact-head real-behavior proof. The permanent plugin capability contract also needs feature-owner confirmation before merge.

## What This Changes

The branch adds descriptor-allowlisted session actions and optional chat navigation for sandboxed plugin tabs through a parent-owned `MessagePort` bridge, plus a `contextTokens` field on plugin session actions.

## Best Possible Solution

Keep the bridge narrowly descriptor-allowlisted, resolve context-window facts from Gateway-owned session/model state rather than RPC input, then document and prove the finalized capability contract with an exact-head opaque-iframe mutation and navigation run.
