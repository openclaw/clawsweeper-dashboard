## Summary

Keep this PR open, but do not merge it yet: the narrowly scoped bridge fits the existing sandboxed-tab design, while the new caller-supplied context-window value creates an authoritative-data flaw and the external PR does not include inspectable after-fix real-browser proof.

## What This Changes

Adds descriptor-gated session actions and chat navigation to sandboxed plugin tabs through a parent-owned MessagePort bridge, while extending the plugin action context with the active session and context-window size.

## Best Possible Solution

Keep the explicit action allowlist, independent navigation opt-in, parent-fixed plugin identity, and absence of a generic fetch/token bridge, but derive context-window facts from the canonical Gateway session/model and require exact-head browser proof covering allowed, denied, stale-frame, navigation, and no-capability cases before approving the public contract.
