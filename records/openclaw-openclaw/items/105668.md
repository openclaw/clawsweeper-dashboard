## Summary

Current main still waits for the periodic interval before the first channel-health evaluation, leaving the reported post-grace recovery blind spot. No related issue or viable PR currently owns this missing initial evaluation, and the repair is narrow enough for a focused fix.

## What This Changes

Run the channel health monitor’s first recovery evaluation when startup grace expires instead of waiting for the five-minute periodic interval.

## Best Possible Solution

Use one lifecycle-owned schedule that runs first at startup-grace expiry, then continues at the configured cadence without overlap while preserving unref, abort, stop, shutdown, cooldown, and reload-handoff behavior.
