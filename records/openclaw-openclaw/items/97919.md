## Summary

Keep open: current main and v2026.6.11 mitigate the native Claude `Bash(run_in_background:true)` and `Monitor` paths by denying them, but the broader Workflow-backed survival plus durable completion-delivery contract remains unresolved and is still represented by open related design issues.

## What This Changes

Ensure in-turn background work under `claude-cli` either survives turn boundaries and delivers completions through a durable origin route, or is explicitly denied instead of being silently killed.

## Best Possible Solution

Define one OpenClaw-owned longwork lifecycle contract for `claude-cli`: unsupported native/background affordances fail closed, and any supported detached work carries a durable origin snapshot plus queued completion delivery.

Rationale: Current main has already chosen fail-closed behavior for two native Claude tools, but the remaining Workflow-backed path crosses runtime ownership, plugin/skill exposure, durable session delivery, and compatibility expectations.

Options:

- **Define Durable OpenClaw Longwork (recommended):** Keep native unsupported tools denied while designing a supported detached-work path with persisted origin and queued completion delivery.
- **Deny All Unsupported Native Longwork:** Treat `claude-cli` as foreground/live-session only and block any native Workflow-style affordance that promises post-turn completion without an OpenClaw delivery route.
- **Support Native Claude Background Work:** Invest in a persistent or detached host for Claude-native background jobs and prove completion delivery across turn boundaries before exposing it.
