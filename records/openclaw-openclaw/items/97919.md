## Summary

Keep open: current main and the latest release still have the claude-cli cleanup path that closes the live session and cancels its process tree after a turn, while the existing Bash/Monitor denial only partially mitigates the reported background-work class and does not settle Workflow-backed survival or durable delivery.

## What This Changes

The issue requests a reliable claude-cli in-turn background-work contract so Workflow, native background work, and Workflow-backed skills either survive turn boundaries and deliver completions or are explicitly refused.

## Best Possible Solution

Define one maintainer-approved claude-cli longwork contract: either deny unsupported post-turn native background work with visible diagnostics, or boundedly drain/detach it with an origin snapshot, durable completion queue, and explicit failure delivery, coordinated with https://github.com/openclaw/openclaw/issues/102172 and the broader lifecycle umbrella.
