## Summary

The issue is valid and still necessary: current main permanently consumes the snapshot slot after a transient read or write failure, no linked fix exists, and the repair is narrow enough for one focused PR.

## What This Changes

Allow pre-update config snapshot creation to retry after transient read or write failure without losing once-per-process deduplication.

## Best Possible Solution

Store a shared in-flight or completed snapshot operation per resolved config path, remove failed operations so later calls retry, and add read-failure, write-failure, and concurrent-call regression coverage.
