## Summary

Keep open. Current main and the latest release still authorize channel-originated config writes only by channel/account, while the requested per-DM/group/topic policy would add a security-sensitive public config and SDK contract that needs maintainer design.

## What This Changes

Request to add per-context `configWrites` overrides for DMs, groups, and conversation types across channel plugins instead of only channel/account gates.

## Best Possible Solution

Add a generic context-scoped config-write policy at the shared channel/plugin contract, then have each multi-context channel map DM, group, topic, or thread identity into that policy with schema, docs, and regression coverage.

## Reproduction Assessment

Yes for the missing-capability claim. Current source, tests, schemas, docs, and latest release expose channel/account `configWrites` only, not per-DM/group/topic policy.

## Solution Assessment

Unclear as proposed. The security need is valid, but the exact cross-channel config shape and SDK contract need maintainer design before implementation.
