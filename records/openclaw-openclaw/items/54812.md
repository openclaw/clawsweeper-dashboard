## Summary

Keep open. Current main and v2026.6.11 still model channel-originated config-write permission at channel/account scope only; the requested per-DM/group/topic policy remains a security-sensitive public config and SDK design item, not an implemented cleanup candidate.

## What This Changes

The issue requests per-context `configWrites` permission controls so different DMs, groups, or conversation contexts can allow or deny channel-originated config writes independently.

## Best Possible Solution

Add a generic, backward-compatible context-scoped config-write policy at the shared channel/plugin contract, then let each multi-context channel map DM, group, topic, thread, or conversation identity into that policy with docs, schema coverage, and regression tests.

## Reproduction Assessment

Yes for the missing capability: current source exposes channel/account config-write authorization only, not DM/group/topic context-specific policy. No live channel run is needed to prove that this public config surface is absent.

## Solution Assessment

Unclear as proposed. The security need is valid, but the exact cross-channel config shape, inheritance rules, deny precedence, migration behavior, and SDK contract need maintainer design before implementation.
