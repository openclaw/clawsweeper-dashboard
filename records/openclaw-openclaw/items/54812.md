## Summary

Keep open. Current main and the latest release still model channel-originated config writes at channel/account scope only; the requested DM/group/topic context policy remains a security-sensitive public config and SDK design decision.

## What This Changes

The issue requests per-context config-write authorization so one channel can allow config mutations in trusted DMs or admin groups while denying them in client groups.

## Best Possible Solution

Define a shared context-scoped config-write policy at the channel/plugin SDK boundary, then have each multi-context channel map DM, group, topic, or thread identity into that policy with schema, docs, and contract tests.
