## Summary

Keep open. Current main and the latest release still authorize channel-originated config writes only by channel/account, while the requested per-DM/group/topic policy is a security-sensitive config and SDK design change that needs maintainer direction.

## What This Changes

The issue requests `configWrites` controls per DM, group, or conversation context across channel types instead of only channel/account scope.

## Best Possible Solution

Design one shared context-scoped config-write policy at the channel/plugin boundary, then adopt it in multi-context channel schemas, docs, and contract tests with explicit inheritance and migration rules.

## Reproduction Assessment

Yes for the missing-capability claim: current source, schema, docs, and tests expose channel/account `configWrites` only, not per-DM/group/topic policy. No live channel run is needed to prove the config surface is absent.

## Solution Assessment

Unclear as proposed. The security need is valid, but the exact cross-channel config shape, inheritance rules, deny precedence, migration behavior, and SDK contract need maintainer design before implementation.
