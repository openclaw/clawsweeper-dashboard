## Summary

Keep open. Current main and v2026.6.11 still gate channel-originated config writes only by channel/account, while the requested per-DM/group/topic policy is a security-sensitive public config and SDK design change.

## What This Changes

Request per-context configWrites permissions for multi-context channels so trusted DMs or admin groups can write config while client groups cannot.

## Best Possible Solution

Define one generic context-scoped config-write policy contract, then let each multi-context channel map DM, group, topic, or thread identity into it with schema, docs, and contract tests.

## Reproduction Assessment

Yes for the missing-capability claim: current source, schemas, docs, and contract tests expose channel/account configWrites only, not per-DM/group/topic policy. No live channel run is needed to prove the config surface is absent.

## Solution Assessment

Unclear as proposed. The security need is valid, but the exact cross-channel config shape, inheritance rules, deny precedence, migration behavior, and SDK contract need maintainer design before implementation.
