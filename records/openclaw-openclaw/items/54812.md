Keep open. ## What This Changes

Request per-context `configWrites` permissions for DMs, groups, topics, or conversations across channel types instead of the existing channel/account-level gate.

## Best Possible Solution

Design a generic context-scoped config-write policy in the shared channel/plugin contract, then have multi-context channels map DMs, groups, topics, or threads into it with schema, docs, migration guidance, and contract tests.

## Solution Assessment

Unclear as proposed. The security need is valid, but the exact config shape, inheritance rules, deny precedence, migration behavior, and SDK contract should be chosen at the shared channel/plugin boundary before implementation.
