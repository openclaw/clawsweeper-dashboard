## Summary

Keep open. Current main and the latest release still authorize channel-originated config writes only at channel/account scope, while the requested per-DM/group/topic policy is a security-sensitive public config and SDK design change that needs maintainer direction before implementation.

## What This Changes

The issue requests per-DM/per-group config write permissions for multi-context channels instead of the current channel-level `configWrites` setting.

## Best Possible Solution

Add a shared context-scoped config-write authorization contract at the channel/plugin boundary, then update schemas, docs, and contract tests so multi-context channels inherit safely from channel/account defaults into explicit DM/group/topic/thread overrides.

## Reproduction Assessment

Yes for the missing-capability claim: current source, tests, docs, and the latest release expose channel/account `configWrites` only, not per-DM/group/topic policy. No live channel run is needed to prove the config surface is absent.

## Solution Assessment

Unclear as proposed. The security need is valid, but the exact cross-channel config shape, inheritance rules, deny precedence, migration behavior, and SDK contract need maintainer design before implementation.
