## Summary

Keep open. Current main and v2026.6.11 still authorize channel-originated config writes only by channel/account scope, while this request needs a security-sensitive per-conversation policy design across channel schemas, command gates, docs, and SDK helpers.

## What This Changes

The issue requests per-context `configWrites` permissions for DM, group, and other conversation contexts across channel types.

## Best Possible Solution

Design a generic context-scoped config-write policy contract, then let each multi-context channel map DM, group, topic, or thread identity into that policy with schema, docs, and regression coverage.

## Reproduction Assessment

Yes for the missing-capability claim: current source exposes channel/account `configWrites` only, and the command gates do not pass conversation identity. No live channel run is needed to prove the config surface is absent.

## Solution Assessment

Unclear as proposed. The security need is valid, but the cross-channel config shape, inheritance rules, deny precedence, migration behavior, and SDK contract need maintainer design before implementation.
