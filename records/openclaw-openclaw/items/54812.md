## Summary

Keep open. Current main and the latest release still authorize channel-originated config writes only by channel/account, while the requested per-DM/group/topic policy is a security-sensitive new config and SDK design that needs maintainer direction.

## What This Changes

Request per-context `configWrites` permissions so multi-context channels can grant config writes in trusted DMs or admin groups while denying them in client groups.

## Best Possible Solution

Define a shared context-scoped config-write policy at the channel/plugin SDK boundary, then let each multi-context channel map DM, group, topic, or thread identity into that policy with schema, docs, and contract tests.
