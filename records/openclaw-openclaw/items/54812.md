## Summary

Keep open. Current main and v2026.6.11 still authorize channel-originated config writes only at channel/account scope, while the requested per-DM/group/conversation policy would add security-sensitive public config and SDK semantics that need maintainer design.

## What This Changes

Request per-context configWrites permissions so operators can allow config writes in trusted DMs or admin groups while denying them in client/business groups across channel types.

## Best Possible Solution

Design a generic channel-origin context authorization contract that preserves the existing channel/account defaults, defines DM/group/thread precedence, updates schema/docs/doctor/tests, and lets channel plugins provide normalized context facts without one-off per-channel policy.

## Reproduction Assessment

Yes at source level. Current source and the latest release expose channel/account configWrites only, and the strict DM/context schemas do not accept the requested per-context permission keys.

## Solution Assessment

Unclear. The direction is plausible, but the proposed literal config shape is not yet proven to be the best API across built-in and plugin channels; maintainers should choose the generic security contract first.
