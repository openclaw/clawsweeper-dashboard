## Summary

Keep open. Current main and v2026.6.11 still authorize channel-originated config writes only at channel/account scope, while the requested per-context policy is a security-sensitive public config and SDK contract that needs maintainer design.

## What This Changes

The issue requests per-DM, per-group, or per-context config-write permissions instead of only channel-level `configWrites`.

## Best Possible Solution

Add a shared context-scoped config-write policy contract, then let each multi-context channel map DM, group, topic, or thread identity into that contract with schema, docs, and regression coverage.
