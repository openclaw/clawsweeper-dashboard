## Summary

Keep open. Current main and the latest release still authorize channel-originated config writes only at channel/account scope, while the requested per-context policy is security-sensitive public config/API design that needs maintainer direction before implementation.

## What This Changes

Request adding per-DM, per-group, or per-conversation `configWrites` permissions across channel types instead of only channel/account-level config-write gating.

## Best Possible Solution

Add a generic context-scoped config-write policy in the shared channel/plugin contract, then let multi-context channels map DM, group, topic, or thread identity into that policy with schema, docs, and regression coverage.

## Reproduction Assessment

Yes, source-reproducible for the missing capability: current policy, command gates, schemas, tests, and docs expose channel/account `configWrites` only. No live channel run is needed to prove the requested config surface is absent.

## Solution Assessment

Unclear as proposed. The security need is valid, but maintainers should choose a generic shared policy shape rather than adopting the exact `dmConfigWrites` and `groups.*.configWrites` proposal one channel at a time.
