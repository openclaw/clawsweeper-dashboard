## Summary

Keep open. Current main and v2026.6.11 still authorize channel-originated config writes at channel/account scope only; the requested DM/group/topic context policy remains a security-sensitive public config and SDK design item.

## What This Changes

Request per-context `configWrites` permissions so multi-context channels can allow config writes in operator DMs or admin groups while denying them in client groups.

## Best Possible Solution

Add a generic context-scoped config-write policy at the shared channel/plugin contract, then let each multi-context channel map DM, group, topic, or thread identity into that policy with schema, docs, and regression tests.

## Reproduction Assessment

Yes. Source inspection shows current config-write authorization, command gates, schemas, docs, and tests only expose channel/account scope, so the requested per-context policy surface is absent.

## Solution Assessment

Unclear as proposed. The security need is valid, but the exact cross-channel config shape, inheritance rules, denial messages, migration behavior, and SDK contract need maintainer design before implementation.
