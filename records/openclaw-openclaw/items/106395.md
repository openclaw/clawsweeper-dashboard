## Summary

This PR remains necessary because current main still launches each asynchronous 10-second device-pair notification poll without guarding the previous poll. The proposed single-flight lifecycle fix appears correct with no actionable patch finding, but the external contribution still needs after-fix real Gateway and Telegram behavior proof before merge. ## What This Changes

The PR adds a service-lifetime single-flight guard around device-pair notification polling and regression coverage for delayed, rejected, and restarted polls.

## Best Possible Solution

Keep one service-lifetime poll in flight across stop/start, prove delayed real Telegram delivery produces one reminder and later polling resumes, and confirm the underlying list/send path has bounded completion or add that bound at its owning request or adapter layer.
