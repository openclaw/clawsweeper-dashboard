## Summary

Keep open: current main and the latest release still have an unguarded migration config merge path reachable from Hermes migration-import data, and the security-sensitive SDK helper should be hardened with maintainer review.

## What This Changes

The issue asks OpenClaw to block prototype-polluting keys in migration-import config patch merging, matching sibling config writers.

## Best Possible Solution

Add the shared blocked-key guard to the migration config patch merge/write boundary, cover direct helper behavior plus Hermes provider/MCP/skill imports, and keep normal safe config merges unchanged.
