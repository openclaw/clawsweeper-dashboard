## Label Justifications

- `P2`: This is a valid low/medium security hardening bug in onboarding migration import with limited blast radius and no emergency bypass evidence.
- `impact:security`: The issue concerns a CWE-1321-style prototype-pollution primitive from imported external config into live OpenClaw config objects.
- `maturity:stable`: The affected onboarding migration path maps to `cli-install-update-onboard-doctor`, which is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and the latest release still have an unguarded migration config patch merge path reachable from imported Hermes configuration, while sibling config writers already block prototype-bearing keys.

## What This Changes

The issue requests a prototype-pollution guard for migration config patch merging in the public plugin SDK helper used by onboarding migration imports.

## Best Possible Solution

Add shared blocked-key handling to the migration config patch helper and cover direct helper plus Hermes provider, MCP, and skill-key imports without changing unrelated migration behavior.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should migration config patch helpers reject affected items or silently drop `__proto__`, `constructor`, and `prototype` keys when imported config contains them?

Rationale: The primitive is clear, but the exact failure mode becomes a security and compatibility contract for bundled and third-party migration providers.

Likely owner: steipete

Owner reason: The earliest migration-provider and onboarding-flow commits in the live PR metadata are by steipete, making him the best available owner for the SDK-helper contract choice.

Owner confidence: medium

Options:

- **Guard the SDK helper (recommended):** Block prototype-bearing keys in `mergeMigrationConfigValue` and path creation, with focused tests for direct helper and Hermes-imported provider/MCP/skill keys.
- **Sanitize provider imports only:** Filter unsafe names in Hermes and sibling migration providers, leaving the shared helper contract unchanged but less comprehensively protected.
- **Accept trusted-import risk:** Document migration imports as trusted input and leave the current primitive in place.

Yes. Source inspection confirms external Hermes map keys can become migration patch keys and reach `mergeMigrationConfigValue`, which writes them with bracket assignment and no blocked-key guard.

## Solution Assessment

Yes, with a maintainer choice on failure mode. The narrowest durable fix is in the shared migration config patch helper rather than only sanitizing one provider.
