- `impact:security`: The report concerns a CWE-1321 prototype-pollution primitive from imported external config into OpenClaw config objects.
- `maturity:stable`: The affected onboarding migration path falls under the M4 Stable `cli-install-update-onboard-doctor` maturity feature.

## Summary

Keep open: current main and the latest release still have an unguarded migration config merge path reachable from Hermes migration-import data, while sibling config writers already block prototype-bearing keys.

## What This Changes

The issue requests hardening migration-import config patch merging so `__proto__`, `constructor`, and `prototype` keys cannot mutate live object prototypes during onboarding imports.

## Best Possible Solution

Add a shared blocked-key guard to the migration config patch merge/write helpers, cover direct helper behavior plus Hermes provider/MCP/skill imports, and keep normal safe config merges unchanged.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: a Hermes config key named `__proto__` can flow into a migration patch value and then through `writeMigrationConfigPath` where the recursive merge assigns it by bracket notation. I did not run the full interactive onboarding UI in this read-only review.

## Solution Assessment

Yes, the best fix is a narrow migration-helper guard using the existing `isBlockedObjectKey` pattern, with regression tests for direct helper merging and Hermes-imported provider/MCP/skill keys.
