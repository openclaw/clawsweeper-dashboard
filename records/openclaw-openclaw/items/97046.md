## Summary

The updated commit resolves all three prior review findings, but the PR still has two P1 runtime/security defects: it forwards a placeholder credential through the provider API-key path, and it unions tool permissions across all configured Gee endpoints instead of scoping them to the active turn. The current head also conflicts with main and lacks live hosted-runtime proof.

## What This Changes

Adds a Gee-owned runtime envelope and prepared-facts flow across Codex startup, embedded-agent tools, authentication, compaction, failover diagnostics, and persisted thread bindings.

## Best Possible Solution

Define a provider-neutral host-runtime contract that supplies one validated active endpoint/session capability set, resolves its credential reference through a host-owned request transport at provider egress, and persists only validated resumable facts while preserving standalone behavior.
