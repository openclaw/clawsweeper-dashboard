## Summary

Keep open: current main has partial Codex timeout and stuck-session recovery fixes, but the July 4 field evidence matches a still-present source gap where gateway daily reset/provider-owned freshness only recognizes CLI bindings while Codex app-server state lives in a sidecar, so final delivery can still be lost when the listener is cut.

## What This Changes

The issue reports channel-triggered embedded agent runs wedging or dropping final delivery after Codex app-server/listener, recovery, reset, or lane lifecycle races.

## Best Possible Solution

Make Codex app-server sidecar bindings first-class provider-owned session state for implicit reset decisions and serialize reset, listener teardown/registration, completion salvage, and visible retry/failure delivery as one contract.

## Reproduction Assessment

No live current-main repro was run, but the source-backed path is clear: Codex sidecar bindings are not recognized by the provider-owned daily reset exemption, and upstream Codex drops turn completion when no per-turn queue is registered.

## Solution Assessment

No; a Codex-only watchdog is only a partial mitigation, while the best fix is a shared reset/listener/recovery contract that preserves provider-owned Codex state and surfaces one retryable channel outcome when recovery cannot safely deliver.
