## Summary

Keep open: current main has partial Codex timeout, output-recovery, and session-reset work, but source and the July 4 live report still show unresolved Codex sidecar/listener lifecycle gaps that can lose channel replies after a reset or stalled embedded run.

## What This Changes

Request to prevent Codex app-server and channel embedded runs from wedging silently after turn, listener, or reset stalls, preserving or surfacing replies instead of losing messages.

## Best Possible Solution

Define one shared lifecycle contract that serializes lazy resets with active Codex listener/turn ownership, recognizes or migrates Codex sidecar bindings into provider-owned session freshness, and delivers either recovered output or one visible retryable failure to the originating channel.

## Reproduction Assessment

No live current-main repro was run, but the latest v2026.6.11 field report plus current source show a plausible Codex sidecar daily-reset gap and remaining active-request watchdog gates.

## Solution Assessment

No; the original Codex-only turn-progress watchdog is only a partial mitigation, and the remaining best fix is at the shared session reset, Codex sidecar, listener lifecycle, and channel-visible recovery boundary.
