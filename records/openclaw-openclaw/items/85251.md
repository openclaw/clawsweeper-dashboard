## Summary

## What This Changes

Issue #85251 requests bounded recovery and visible failure handling when embedded Codex/app-server or channel-agent runs accept work and then stop producing deliverable replies.

## Best Possible Solution

Land a shared session/run recovery contract that treats Codex app-server bindings as provider-owned or serializes reset with listener lifecycle, caps hung in-flight app-server requests, and emits one visible retry/failure outcome instead of silent message loss.

## Reproduction Assessment

No live current-main repro was run, but current source plus the latest v2026.6.11 report give a medium-confidence source path for Codex sidecar reset/listener loss and active-request-gated watchdog suppression.

## Solution Assessment

No; the original Codex-only turn watchdog is only a partial mitigation, while the best fix needs a shared session reset, listener, recovery, and visible delivery policy across embedded runtimes and channels.
