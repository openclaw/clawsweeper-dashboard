## Summary

Keep open: current main has partial stuck-recovery improvements, but a July 4, 2026 field report on 2026.6.11 plus current source still support a remaining Codex app-server binding/listener reset gap that can discard composed replies.

## What This Changes

The issue asks OpenClaw to bound and recover embedded Codex/app-server stalls so accepted channel turns do not silently wedge or lose final replies.

## Best Possible Solution

Define a shared lifecycle contract that treats Codex app-server sidecar bindings as provider-owned state during implicit resets, serializes reset/teardown against listener attach, and emits one channel-visible retry or failure outcome when recovery discards a run.

## Reproduction Assessment

No live current-main repro was run, but the latest 2026.6.11 field report plus current source make the reset-sidecar/listener gap source-reproducible with medium confidence.

## Solution Assessment

No, the original Codex-only turn watchdog is too narrow; the best fix is a shared session reset, listener ownership, and channel recovery policy.
