## Summary

Keep open: current main has partial Codex timeout and stuck-session recovery work, but the latest live report still maps to unresolved session-listener and provider-owned reset gaps where Codex thread state lives outside the current reset exemption.

## What This Changes

The issue asks OpenClaw to prevent embedded Codex/channel runs from going silent after accepted turns and to recover or visibly fail the originating channel message instead of losing it behind wedged session state.

## Best Possible Solution

Define one gateway/Codex session lifecycle contract that preserves active provider-owned thread bindings through implicit resets, serializes reset with listener teardown/start, and delivers or clearly fails the originating channel message after recovery.

## Reproduction Assessment

No live current-main reproduction was run, but source inspection gives a medium-confidence path for the remaining gap: Codex provider-owned state is sidecar-backed while implicit reset exemptions check only CLI bindings, and current recovery remains after-the-fact.

## Solution Assessment

No as originally framed; a Codex-only turn watchdog is a partial mitigation, while the best fix must cover reset/listener ownership and recovery delivery semantics without weakening protection for legitimate active runs.
