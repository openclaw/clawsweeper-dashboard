## Summary

Keep open: current main contains several partial Codex timeout and stuck-session recovery fixes, but the latest live report and current source still show a remaining Codex sidecar/session-reset lifecycle gap that can cut the listener and lose a completed channel reply.

## What This Changes

Fix Codex and shared embedded-run stalls where channel-originated turns stop consuming progress or completion and leave user messages without a visible reply until recovery or restart.

## Best Possible Solution

Define one provider-owned session lifecycle contract that includes Codex sidecar ownership, serializes reset/teardown with listener registration, and guarantees either delivery salvage or one visible retryable failure in the originating channel.

## Reproduction Assessment

Yes, source-reproducible at medium confidence: current main still checks only entry CLI bindings for provider-owned freshness while Codex app-server ownership lives in a reset-cleared sidecar; the exact listener-loss race was not live-replayed here.

## Solution Assessment

No, current main is only a partial solution because Codex turn watches and stale-run recovery do not make implicit daily reset sidecar handling or post-abort channel delivery safe.
