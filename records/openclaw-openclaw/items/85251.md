## Summary

Keep open: current main has partial Codex turn-watch and stuck-session recovery fixes, but the latest 2026.6.11 field report plus source inspection still point to an unresolved Codex sidecar/session-reset/listener lifecycle race that can lose a completed reply.

## What This Changes

The issue requests bounded recovery for Codex app-server and shared embedded-run/channel lanes that go silent after turn start, without waiting for the full stuck-session window or dropping the user reply.

## Best Possible Solution

Define one shared lifecycle contract that serializes reset/teardown against Codex listener registration, preserves or deliberately migrates provider-owned sidecar bindings, salvages completed replies when safe, and sends one visible retryable failure when recovery cannot deliver.
