## Summary

Keep open: current main has partial Codex and stuck-session recovery fixes, but the latest field repro plus source inspection show a remaining reset/listener gap where the provider-owned daily reset exemption only sees store-entry CLI bindings while Codex app-server continuity lives in a sidecar.

## What This Changes

The issue asks OpenClaw to prevent Codex app-server and shared embedded-run channel lanes from wedging silently after a turn starts, including bounded recovery and a visible retry or failure outcome.

## Best Possible Solution

Keep this as the umbrella tracker until OpenClaw has a shared contract that preserves or safely tears down Codex sidecar-backed sessions across reset, consumes terminal Codex completions when available, and sends exactly one visible retryable failure when recovery cannot deliver.

## Reproduction Assessment

No high-confidence current-main live repro was run, but source inspection plus a v2026.6.11 field repro give a medium-confidence path: implicit daily rollover can treat a Codex sidecar-backed session as non-provider-owned, rotate/delete listener state, and later abort instead of delivering a completed reply.

## Solution Assessment

No, the original Codex-only synthetic `turn/error` watchdog is not the best complete fix; Codex upstream uses terminal `turn/completed` statuses, and OpenClaw needs a shared session-reset, listener, recovery, and channel-visible retry contract.
