## Summary

Keep open: current main contains partial watchdog and recovery fixes, but the July 4 field report on 2026.6.11 points to a remaining Codex sidecar/listener and lazy daily-reset race that can still discard completed replies and leave channel users silent.

## What This Changes

The issue reports Codex app-server and shared embedded-run/channel-lane stalls that can leave accepted user messages without a delivered reply until recovery or manual intervention.

## Best Possible Solution

Treat this as a shared session-lifecycle recovery bug: make Codex app-server sidecar bindings participate safely in reset/freshness, serialize reset against active listener teardown, and ensure stuck aborts either salvage completed output or send one visible channel failure before releasing the lane.

## Reproduction Assessment

No live current-main repro was run, but the code path is source-reproducible at medium confidence: the daily reset exemption is cliSessionBindings-based while Codex app-server thread state is stored in a transcript sidecar, and the issue has fresh 2026.6.11 live field evidence.

## Solution Assessment

No, the original Codex-only turn watchdog is only a partial mitigation; the better fix is a shared reset, listener, recovery, and channel-notification contract that preserves or safely abandons completed turns.
