## Summary

Keep open: current main has fixed several older recovery subcases, but the latest v2026.6.11 field evidence and current source still show a Codex sidecar/session-reset/listener lifecycle gap that can discard completed replies and leave channel lanes silent.

## What This Changes

The issue reports embedded Codex/shared agent runs that accept channel work but stop delivering progress or terminal replies until stuck-session recovery aborts, causing silent message loss.

## Best Possible Solution

Keep this as the umbrella maintainer item until OpenClaw preserves Codex terminal listener ownership across lazy reset/recovery, treats sidecar-backed Codex bindings as provider-owned where appropriate, and emits one retryable channel-visible failure when recovery cannot deliver safely.

## Reproduction Assessment

Source-reproducible with medium confidence, but not live-reproduced on current main; current source keeps Codex app-server binding in a sidecar while provider-owned reset detection only checks session-entry CLI bindings, matching the July 4 field report.

## Solution Assessment

No, the original Codex-only turn watchdog is too narrow; the best fix spans session reset policy, Codex listener registration and teardown, stuck recovery, and channel-visible failure handling.
