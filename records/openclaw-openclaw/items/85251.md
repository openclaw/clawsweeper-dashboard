## Summary

Keep open: current main has useful recovery and Codex completion fixes, but the July 4 field repro on v2026.6.11 plus current source show the provider-owned reset exemption still only recognizes store CLI bindings, not Codex app-server sidecar ownership, so the reported listener/session-loss class is not proven fixed.

## What This Changes

Report that Codex app-server-backed channel turns can silently lose their completion listener or final delivery around embedded-run/session lifecycle recovery, leaving users without a reply until stuck-session recovery aborts.

## Best Possible Solution

Keep the issue open until Codex app-server sidecar-owned sessions are protected from implicit rollover and completed output after listener loss is either preserved or visibly failed/retried.

## Reproduction Assessment

No live current-main repro was run here; source inspection plus the July 4 v2026.6.11 field report gives a medium-confidence path where implicit daily reset checks store cliSessionBindings while Codex app-server ownership lives in a .codex-app-server.json sidecar.

## Solution Assessment

No, the original Codex-only turn watchdog is only a partial mitigation; the better fix is to define provider-owned Codex sidecar reset/listener ownership and recovery semantics for completed output after listener loss.
