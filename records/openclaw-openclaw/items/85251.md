## Summary

Keep open: current main has partial Codex turn-watch and stuck-session recovery fixes, but the latest 2026.6.11 field report maps to a still-uncovered reset/listener lifecycle gap where Codex sidecar ownership is outside the provider-owned reset exemption and stuck-abort finalization still suppresses composed assistant output.

## What This Changes

Reported bug: channel-triggered embedded agent turns can lose final replies when Codex app-server or shared session lifecycle state stops delivering completion events until stuck recovery aborts.

## Best Possible Solution

Make Codex app-server thread bindings part of the session reset/lifecycle ownership model and ensure recovery either safely delivers composed final output or emits one visible retryable failure before admitting new channel work.

## Reproduction Assessment

No live current-main repro was run, but source inspection matches the latest field sequence: daily reset can rotate/archive the transcript without treating the Codex sidecar as provider-owned, and final delivery is gated off after stuck abort.

## Solution Assessment

The original Codex-only watchdog is insufficient; the remaining best fix is a shared session lifecycle and recovery contract across provider-owned bindings, listener teardown, and channel-visible failure delivery.
