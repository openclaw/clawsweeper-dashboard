## Summary

Keep open: current main has partial Codex timeout and stuck-session recovery fixes, but the latest v2026.6.11 field evidence plus source inspection still show a provider-owned Codex sidecar/reset/listener lifecycle gap that can discard a completed reply and leave channel users silent.

## What This Changes

Fix channel-triggered Codex or embedded-agent runs that wedge after turn start, tool work, recovery, or session reset so users receive either the completed reply, a retryable failure, or a clean next turn.

## Best Possible Solution

Keep this issue open until one owner-approved lifecycle design makes Codex sidecar ownership, session reset, listener subscription, stuck abort recovery, and channel-visible retry/failure delivery atomic enough that completed replies are not discarded.

## Reproduction Assessment

Yes, at source-reproducible medium confidence: live comments give concrete release evidence and current source shows the sidecar-only Codex binding is outside the provider-owned reset exemption, but I did not run a live gateway repro.

## Solution Assessment

No, the original Codex-only turn watchdog is only a partial mitigation; the better fix is a shared session/listener/recovery contract that handles provider-owned sidecars, stale active work, and one visible retryable channel outcome.
