## Label Justifications

- `P1`: A configured timeout is meant to unblock queued interactive turns, but the current design can introduce concurrent same-session plugin maintenance under the same failure condition.
- `merge-risk: 🚨 compatibility`: The PR changes the documented context-engine `maintain()` contract from host serialization to possible same-session re-entrancy.
- `merge-risk: 🚨 session-state`: The host fence does not cover plugin-owned session state that an overlapping prior maintenance call may still mutate.
- `merge-risk: 🚨 availability`: A non-re-entrant plugin can deadlock, fail, or remain wedged when a configured timeout admits overlapping maintenance work.

## Summary

This PR addresses a real deferred-maintenance stall and supplies credible runtime proof, but its latest head still releases the per-session maintenance lane while the timed-out plugin `maintain()` call can continue. The resulting concurrent same-session invocation is a breaking plugin-contract change that host-side transcript/task fencing does not make safe, so this needs a maintainer-approved serialization or cancellation design before merge.

## What This Changes

The branch adds an opt-in timeout for deferred context-engine maintenance, fences late host-owned writes after timeout, documents a new `maintain()` concurrency expectation, and throttles repeated `session.stalled` warnings.

## System Context

After an agent turn, OpenClaw can schedule context-engine maintenance in a session-specific background lane; later turns wait on that lifecycle so they read a consistent session. The PR adds a configured deadline intended to free queued foreground work, while the context-engine plugin and host transcript/task state continue through separate ownership paths.

## Best Possible Solution

Keep same-session plugin maintenance single-flight after a timeout—by retaining an invocation barrier or coalescing successor work until the abandoned call settles—or introduce an explicitly designed cancellable plugin contract before allowing a second invocation.
