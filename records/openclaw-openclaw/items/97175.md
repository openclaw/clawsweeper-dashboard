## Summary

Keep this PR open for maintainer review: it has strong runtime proof and an opt-in configuration surface, but its timeout path intentionally permits concurrent same-session `ContextEngine.maintain()` calls for already-installed plugins. That is a plugin lifecycle compatibility decision, not a safe automatic merge or repair decision.

## What This Changes

The PR adds an opt-in timeout and late-side-effect fence for deferred context-engine maintenance, documents the new compaction setting and `maintain()` concurrency behavior, and throttles repeated `session.stalled` warnings.

## Best Possible Solution

Define and approve a backward-compatible post-timeout lifecycle: preserve same-session plugin serialization for existing engines, or introduce an additive cancellation/coalescing contract with an explicit compatibility plan before allowing a released lane to start another `maintain()` call.
