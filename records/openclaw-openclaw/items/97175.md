## Summary

Keep this PR open for an explicit context-engine owner decision. The patch appears technically correct and has convincing real-runtime proof, but merging would establish a new public timeout setting and a permanent contract that releases the lane while non-cooperative plugin work may continue; forty prior ClawSweeper cycles on successive heads likewise found no line-level defect and consistently routed this contract choice to maintainers.

## What This Changes

Adds an opt-in per-task timeout for deferred context-engine maintenance, fences late runtime-owned side effects, coordinates in-flight transcript persistence, throttles repeated stalled-session warnings, and adds configuration, documentation, and regression coverage.

## Best Possible Solution

Adopt the bounded recovery only with an explicit owner-approved abandonment contract: keep it disabled by default, retain the runtime transcript/task fences and persistence checkpoint, and document that context-engine plugins must tolerate a timed-out `maintain()` call continuing after its lane is released.
