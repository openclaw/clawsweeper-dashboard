## Summary

Keep this PR open for maintainer product review. It solves a real same-session liveness problem and includes credible after-fix runtime logs, but its timeout deliberately changes the existing public context-engine contract: an installed engine may now see overlapping same-session `maintain()` calls after an operator enables the new setting, while host fencing cannot protect plugin-private locks, subprocesses, caches, or external side effects.

## What This Changes

This PR adds an opt-in configuration timeout for deferred background context-engine maintenance, fences late host transcript/task writes after timeout, documents a re-entrant `maintain()` expectation, and throttles repeated stalled-session warnings.

## System Context

After a turn, OpenClaw can queue background context-engine maintenance on a per-session lane before later turns proceed. The PR inserts a configurable queue timeout into that path, then uses a fence to stop late host-owned transcript and task-state writes while a stalled plugin call may still be unwinding.

## Best Possible Solution

Define an additive, explicit context-engine capability for cancellation or safe concurrent maintenance, keep existing engines on serialized maintenance semantics, and enable lane release only for engines that opt in and have focused upgrade coverage.
