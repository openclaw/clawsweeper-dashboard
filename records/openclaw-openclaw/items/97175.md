## Label Justifications

- `P1`: The target defect can block queued interactive session turns for minutes despite a healthy model.
- `merge-risk: 🚨 session-state`: A queue timeout can release the session while the original maintenance worker remains active, and a later rerun may overlap its plugin and transcript lifecycle.
- `merge-risk: 🚨 availability`: Overlapping or repeatedly timed-out maintenance workers can retain plugin locks or background work while later turns continue to schedule more maintenance.
- `merge-risk: 🚨 compatibility`: The PR adds a public configuration key whose timeout semantics affect existing context-engine plugin behavior when operators enable it.

## Summary

Keep this PR open for maintainer review: current main still lacks a maintenance-specific task timeout, and the submitted live runtime trace convincingly shows the intended liveness improvement, but the timeout cleanup can treat a still-running worker as finished and start a coalesced rerun concurrently on the same context-engine instance.

## What This Changes

The branch adds an opt-in deferred context-engine maintenance timeout with late-side-effect fencing and persistence ordering protection, documents the new setting, and throttles repeated `session.stalled` warnings.

## Best Possible Solution

Separate the foreground liveness barrier from the active-worker/coalescing state: release queued turns after the timeout and guarded persistence checkpoint, but do not launch a same-session maintenance rerun until the timed-out worker has actually settled or a maintainer-approved cancellation contract exists.
