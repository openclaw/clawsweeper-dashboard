- `merge-risk: 🚨 compatibility`: The PR adds a configuration surface and changes the behavioral expectations of existing context-engine plugins.

## Summary

This PR addresses a real P1 session-liveness problem and includes credible runtime proof, but the current head still changes the public context-engine contract so a timed-out `maintain()` may overlap a new same-session call. Host-side fencing protects OpenClaw-owned transcript and task writes, not plugin-owned locks, state, or external effects; the prior P1 blocker therefore remains unresolved.

## What This Changes

The branch adds an opt-in timeout for deferred background context-engine maintenance, fences late host-side writes after timeout, documents a new engine concurrency expectation, and throttles repeated stalled-session warnings.

## System Context

Deferred context-engine maintenance runs after an agent turn and is queued per session before later turns can read and continue that session. This PR changes how a timed-out maintenance task releases the lane, affects transcript/task state handling, and adds an operator-facing compaction setting.

## Best Possible Solution

Keep the opt-in timeout for user-turn liveness, but preserve at-most-one in-flight plugin `maintain()` invocation per session by retaining a core-owned invocation tail or coalescing successor maintenance until the timed-out call settles; do not make re-entrancy a new requirement for installed engines without explicit SDK direction.
