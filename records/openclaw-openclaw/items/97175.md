## Summary

The exact-head patch is technically coherent, well tested, and backed by convincing live gateway logs, with no discrete correctness or security finding. It still needs context-engine owner approval because it introduces a permanent core configuration key and shared queue callback while the timeout remains disabled by default and cannot cooperatively stop plugin-owned work.

## What This Changes

Adds an opt-in deferred context-engine maintenance timeout, late-side-effect fencing and persistence checkpoints, a shared command-queue timeout callback, stalled-session warning backoff, documentation, and regression coverage.

## Best Possible Solution

Adopt one host-owned timeout and cancellation contract for deferred maintenance—preferably a finite safety budget with cooperative abort or equivalent serialization—retain the transcript fence/checkpoint protections, and add a tunable config key only if maintainers confirm operators need that permanent surface.
