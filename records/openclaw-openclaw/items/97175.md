## Label Justifications

- `P1`: A wedged deferred-maintenance task can block queued interactive turns, and the proposed fix currently risks breaking active context-engine workflows under that failure mode.
- `merge-risk: 🚨 compatibility`: The PR adds a configuration key and changes the public ContextEngine maintenance concurrency expectation for existing plugins.
- `merge-risk: 🚨 session-state`: It changes the ordering of maintenance, foreground reads, transcript rewrites, and task terminal updates on a session timeout.
- `merge-risk: 🚨 availability`: Releasing a session lane before plugin maintenance settles can create a live overlap or lock contention in the plugin runtime.

## Summary

Keep this PR open, but it still has the prior P1 blocker: timing out releases the per-session lane while the old plugin-owned `maintain()` call continues, then changes the public contract to require existing engines to tolerate overlap. The host fence protects host-owned transcript/task writes, not engine-owned locks or state, so the patch can turn a session-liveness fix into concurrent same-session plugin maintenance without an explicit compatible SDK contract.

## What This Changes

This PR adds an opt-in timeout and late-write fence for deferred context-engine maintenance, documents a new maintenance-concurrency expectation, and throttles repeated stalled-session warnings.

## System Context

After an agent turn, OpenClaw may schedule context-engine maintenance on a session-specific background lane; later turns wait on the relevant session barrier before reading state. This PR bounds the background task and fences host-owned transcript/task writes after timeout, but the plugin's `maintain()` call can still be running when later work is admitted.

## Best Possible Solution

Keep same-session plugin maintenance serialized after a timeout—coalesce or retain an invocation tail for a still-running call while allowing the foreground turn to proceed—or introduce a deliberately designed, additive cancellation contract before permitting overlapping `maintain()` calls.
