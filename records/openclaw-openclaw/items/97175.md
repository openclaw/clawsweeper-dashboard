## Summary

Keep this PR open for maintainer review rather than closing it: it presents a technically coherent, proof-backed repair for the reported session stall, but enabling the new timeout deliberately changes the existing ContextEngine SDK execution guarantee from effectively serial same-session maintenance to potentially concurrent maintenance after a timeout. The host fence protects transcript and task writes, not plugin-private locks, state, or external effects; that compatibility direction needs an explicit owner decision before merge.

Likely related people: Jerry-Xin authored the proposed implementation and its eight commits, so they are the best available technical contact for this branch (low confidence as a current-main ownership signal).

## What This Changes

This PR adds an opt-in per-task timeout for deferred background context-engine maintenance, fences host-owned late writes after timeout, documents the resulting `maintain()` concurrency contract, and throttles repeated stalled-session warnings.

## System Context

After an agent turn, OpenClaw may run context-engine maintenance in a per-session deferred lane before a later foreground turn can proceed. This PR makes that lane optionally time out, releases queued work, and blocks delayed host transcript/task mutations from the still-running maintenance worker.

## Best Possible Solution

Choose and document the permanent ContextEngine contract before merge: either preserve per-engine same-session serialization after a timeout, or explicitly accept re-entrant maintenance as a supported SDK behavior and provide a compatibility path that lets existing engines safely opt in or declare support.
