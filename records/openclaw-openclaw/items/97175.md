## Label Justifications

- `P1`: A timed-out maintenance worker can coexist with a newly admitted same-session maintenance run, risking an urgent regression in interactive session progress and plugin behavior.
- `merge-risk: 🚨 compatibility`: The new timeout option changes the lifecycle observed by third-party context-engine plugins when operators opt in.
- `merge-risk: 🚨 session-state`: Concurrent or late maintenance work can conflict with the session/transcript lifecycle even though the proposed fence blocks selected writes.

## Summary

Keep this PR open: the prior P1 blocker remains on the latest head. Releasing the timed-out lane restores foreground liveness, but the non-cooperative maintenance worker can still run; the scheduler must not admit a second same-session maintenance run until maintainers choose and define the timeout-afterlife contract.

## What This Changes

The PR adds an opt-in per-task timeout and late-side-effect fence for deferred context-engine maintenance, documents the setting, and throttles repeated `session.stalled` warnings.

## Best Possible Solution

Separate the foreground wait barrier from a per-session abandoned-worker coalescing record: release the queued user turn at timeout, but do not start another maintenance invocation for that session until the prior worker settles unless maintainers define a safe supersession contract.
