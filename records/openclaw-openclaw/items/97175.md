## Summary

Keep open: the patch is well-proven and has no discrete correctness finding, but context-engine ownership must confirm the permanent lifecycle contract before merging a new public timeout setting and generic queue callback around work that continues after timeout.

## What This Changes

Adds an opt-in timeout for deferred context-engine maintenance, fences late host-owned state changes, protects transcript persistence ordering, throttles stalled-session warnings, and adds related configuration, documentation, and tests.

## Best Possible Solution

Use one owner-approved, host-owned maintenance cancellation contract that bounds user-visible blocking, preserves same-session transcript ordering, and either cooperatively aborts plugin work or explicitly defines what may outlive timeout; avoid leaving the normal recovery path dependent on a newly discovered opt-in setting if a safe default can be established.
