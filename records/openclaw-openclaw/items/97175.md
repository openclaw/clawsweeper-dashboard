## Summary

This PR still needs maintainer review before merge: its timeout releases the session lane while the non-cooperative maintenance worker can continue running, and the current design does not establish whether subsequent same-session maintenance must remain coalesced until that worker settles or be governed by a new cancellation contract.

## What This Changes

The branch adds an opt-in deferred context-engine maintenance timeout with late-side-effect fencing, persistence ordering checks, and throttled `session.stalled` warnings.

## Best Possible Solution

Retain one same-session deferred-maintenance owner until the timed-out worker settles, or introduce an explicit context-engine cancellation/ownership contract that safely permits replacement before releasing coalescing.

Options:

- **Define cancellable replacement semantics:** Add a documented cancellation/ownership contract for context engines, then permit a timed-out worker to be replaced only after that contract fences all relevant plugin effects.
