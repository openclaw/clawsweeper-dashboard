## Summary

Keep this PR open: it solves the lane-liveness symptom and has credible runtime proof, but it still makes an existing context-engine call overlap its same-session successor after timeout. The host fence protects OpenClaw-owned transcript and task writes, not plugin-owned persistence, locks, or external effects; changing the public engine contract to require re-entrancy is a P1 compatibility regression. Likely related people: steipete is the low-confidence API/product routing candidate; Jerry-Xin is the current proposal author, not attributed as owner of current-main behavior.

## What This Changes

The branch adds an opt-in timeout for deferred context-engine turn maintenance, fences late host-side writes after timeout, adds shutdown abort handling, documents an engine concurrency expectation, and throttles repeated stalled-session warnings.

## System Context

After an agent turn, OpenClaw can schedule context-engine maintenance on a per-session background lane before the next same-session turn proceeds. That worker calls a plugin-owned engine and may update transcript and task state, so its lifecycle affects both interactive responsiveness and session consistency.

## Architecture Diagram

flowchart LR
  A[Completed agent turn] --> B[Deferred maintenance scheduler]
  B --> C[Per-session maintenance lane]
  C --> D[Context-engine plugin maintenance]
  D --> E[Transcript and task state]
  C --> F[Next same-session turn]
  G[Timeout or shutdown] --> C
  G --> E

## Best Possible Solution

Keep plugin invocation serialization core-owned after a timeout: unblock the user turn, but retain an invocation tail or coalesce a later maintenance request until the abandoned engine call settles. Do not make existing context engines re-entrant as the price of enabling the timeout.
