## Summary

Keep this PR open for maintainer review. The opt-in timeout, fence, and supplied container proof address the reported stall, but the timeout releases the lane while the plugin worker can remain alive; the PR still needs an explicit same-session contract for whether a later deferred maintenance request is suppressed, replaces the timed-out run, or may overlap it. Likely related people: dripsmvcp is a medium-confidence adjacent contributor through the closely related deferred-maintenance work; ownership of the current main lifecycle could not be verified because read-only shell inspection was unavailable.

## What This Changes

The branch adds an opt-in deferred-maintenance timeout and late-side-effect fence, documents the new compaction setting, and throttles repeated stalled-session warnings.

## Best Possible Solution

Define one canonical post-timeout lifecycle for a session, then encode it in the deferred-maintenance registry: either retain coalescing until the abandoned worker settles, explicitly supersede it with a generation/fencing contract, or prohibit another deferred run until a documented recovery boundary.
