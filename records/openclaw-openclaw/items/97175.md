## Summary

This PR addresses the still-open deferred-maintenance stall reported by https://github.com/openclaw/openclaw/issues/96703 with credible real-runtime evidence and focused regression coverage, but its new persistent timeout policy and abandoned-worker lifecycle need an explicit maintainer decision before merge.

## What This Changes

Adds an opt-in per-task timeout, late-side-effect fence, persistence checkpoint, and stalled-session log backoff for deferred context-engine turn maintenance.

## Best Possible Solution

Adopt a maintainer-approved, opt-in timeout policy only if core should own the fence and shutdown lifecycle; retain the default-unbounded compatibility mode and require focused upgrade and late-side-effect coverage before merge.
