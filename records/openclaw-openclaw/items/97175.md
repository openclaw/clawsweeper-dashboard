## Summary

The exact-head re-review confirms the prior session-state blocker remains unchanged: the timeout can release the next same-session turn after a transcript persist has started but before it settles. The original wedge is well proven and the bounded timeout is useful, but this ordering defect must be repaired before merge; the permanent config and generic queue-hook contracts also need area-owner acceptance.

## What This Changes

The PR adds an opt-in per-task timeout and late-side-effect fence for deferred context-engine maintenance, throttles repeated stalled-session diagnostics, and adds related config, docs, and regression tests.

## Best Possible Solution

Release the maintenance execution lane at the configured timeout, but retain a separate same-session settlement barrier until any transcript persistence already started by that worker completes; cover the timeout-during-persist ordering and obtain area-owner acceptance for the new public config and queue-hook contracts.
