## Summary

This PR remains necessary because current main still leaves deferred turn maintenance unbounded, and the supplied live proof convincingly demonstrates the primary stall and timeout behavior. It is not merge-ready: the exact head clears the same-session maintenance checkpoint when the queue times out even if transcript persistence has already started and remains in flight, so the next turn can still wait behind or race stale maintenance state.

## What This Changes

The PR adds an opt-in per-task timeout and late-side-effect fence for deferred context-engine maintenance, stalled-session warning backoff, a new compaction config key, a generic command-queue timeout hook, documentation, and regression tests.

## Best Possible Solution

Keep the upgrade-safe opt-in behavior only if owners approve it, but retain the same-session maintenance checkpoint until every transcript mutation already started by the timed-out run has settled and released its lock.
