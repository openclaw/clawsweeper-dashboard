## Summary

This PR remains necessary and has strong real-runtime proof, but it should not merge yet: the timeout can release the same-session read checkpoint while a transcript persistence operation that already started is still in flight. The new public timeout and shared queue-hook contract also need explicit context-engine owner approval after that race is fixed.

## What This Changes

Adds an opt-in timeout for deferred context-engine turn maintenance, fences late task and transcript effects, throttles repeated stalled-session warnings, and adds configuration, documentation, and regression coverage.

## Best Possible Solution

Keep the queued same-session foreground read blocked until every transcript persistence operation already started by the timed-out maintenance run has safely settled, while still fencing new writes and terminal task updates; then obtain context-engine owner approval for the permanent timeout/config and queue-hook contract.
