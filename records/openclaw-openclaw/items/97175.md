## Summary

This PR has strong real-runtime evidence and a focused host-side fence, but it intentionally changes the ContextEngine lifecycle contract: after an opt-in timeout, a second same-session `maintain()` may start while the first is still running. That compatibility decision needs explicit owner approval before merge; no new line-level defect is established in this review cycle.

## What This Changes

Adds an opt-in deferred context-engine maintenance timeout, fences host-owned late writes and task updates after it fires, documents the resulting `maintain()` concurrency expectation, and throttles repeated stalled-session warnings.

## System Context

After an agent turn, OpenClaw may queue context-engine maintenance behind a per-session lane before a later turn can proceed. The scheduler, transcript rewrite path, task registry, and diagnostics together determine whether a wedged maintenance run delays a queued user message or can safely be released.

## Architecture Diagram

  D --> E[Transcript and task-state updates]
  C --> F[Next same-session user turn]
  D --> G[Session stalled diagnostics]

## Best Possible Solution

Keep the opt-in host-side timeout and fence only if the context-engine owners explicitly accept concurrent same-session `maintain()` calls as the public contract; otherwise preserve same-session coalescing until the abandoned worker settles or introduce an owner-approved cancellation contract.
