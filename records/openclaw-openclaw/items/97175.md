## Summary

This PR addresses a real P1 deferred-maintenance stall with strong live proof, but it still releases the same-session read checkpoint while a transcript persist admitted before timeout may be in flight. The earlier SQLite-specific concern does not apply on the exact head because background maintenance is forced through the runtime transcript path; the remaining read-checkpoint race blocks merge.

## What This Changes

The PR adds an opt-in per-task timeout and late-side-effect fence for deferred context-engine maintenance, throttles repeated stalled-session warnings, and adds a config key, generic queue timeout callback, docs, and regression tests.

## Best Possible Solution

Release the maintenance lane at timeout, but track transcript persistence admitted before the timeout separately and keep the same-session read checkpoint until that persistence settles; then retain the new config and queue API only with explicit owner acceptance.
