## Summary

Keep open: current main still has the reported unbounded maintenance path, but the exact PR head remains unsafe because timeout cleanup can release the same-session read checkpoint while a transcript persist has already started and is still in flight. This is the same unresolved blocker raised in prior review cycles, not a new late finding.

## What This Changes

The PR adds an opt-in per-task timeout and late-side-effect fence for deferred context-engine maintenance, throttles repeated stalled-session warnings, and adds the related config, documentation, and regression coverage.

## Best Possible Solution

Retain the opt-in timeout, but separate lane/task release from transcript-read ownership: keep a per-session persistence barrier until every rewrite already started by the timed-out worker settles, then allow the next same-session read and preserve the fence for all later side effects.
