## Summary

Keep this PR open, but do not merge it yet. The opt-in timeout and host-side fence address the reported stall and the PR includes credible runtime proof, but the final diff explicitly changes the ContextEngine contract so a timed-out plugin `maintain()` call may overlap a successor call for the same session; host-side fencing cannot protect plugin-owned locks, storage, or external effects. The prior P1 serialization blocker therefore remains unresolved.

## What This Changes

This PR adds an opt-in timeout and late-write fence for deferred context-engine maintenance, documents a re-entrant maintenance contract for plugins, and throttles repeated stalled-session warnings.

## System Context

Deferred context-engine maintenance runs after an agent turn and uses a per-session command lane before subsequent turns proceed. The scheduler calls a plugin-owned maintenance operation, while OpenClaw persists transcript/task updates and releases queued user turns through the same session flow.

## Architecture Diagram

flowchart LR
  Turn[Completed agent turn] --> Scheduler[Deferred maintenance scheduler]
  Scheduler --> Lane[Per-session maintenance lane]
  Lane --> Engine[Plugin maintenance call]
  Lane --> Timeout[Optional task timeout]
  Timeout --> Fence[Late host-write fence]
  Engine --> State[Transcript and task state]
  Lane --> NextTurn[Queued user turn]

## Best Possible Solution

Keep the opt-in timeout and host-write fence, but preserve the existing effective at-most-one plugin maintenance invocation per session in core: retain an invocation tail or coalesce follow-up maintenance until the abandoned call settles, without imposing a new re-entrancy requirement on installed engines.
