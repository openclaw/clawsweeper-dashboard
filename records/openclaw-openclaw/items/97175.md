## Summary

The exact PR head still has both previously reported P1 lifecycle defects: timeout release can end the same-session checkpoint before an already-admitted transcript persist settles, and the SQLite rewrite path bypasses the timeout fence. The original stall is valid and the supplied runtime proof is strong for the demonstrated file-backed path, but the patch is not safe to merge until both persistence races are repaired; maintainers must then decide whether the new config and generic queue callback should become permanent contracts.

## What This Changes

The PR adds an opt-in timeout and late-side-effect fence for deferred context-engine maintenance, throttles repeated stalled-session warnings, and adds a config key, generic queue timeout callback, docs, and regression tests.

## Best Possible Solution

Keep one same-session maintenance checkpoint until every transcript mutation admitted before timeout has settled, apply the fence to both file-backed and SQLite persistence immediately before authoritative writes, and then either explicitly approve the new config/queue contracts or narrow the implementation to existing private timeout policy.
