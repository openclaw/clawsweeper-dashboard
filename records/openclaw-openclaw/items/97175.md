## Summary

The latest head still releases the same-session read checkpoint before persistence already admitted by the timed-out worker has settled, and the newly rebased SQLite rewrite path bypasses the timeout predicate entirely. The primary live proof is strong, but these session-state defects and the permanent config/shared queue API choice block merge.

## What This Changes

The PR adds an opt-in per-task timeout and late-side-effect fence for deferred context-engine turn maintenance, throttles repeated stalled-session warnings, and adds configuration, documentation, and regression coverage.

## Best Possible Solution

Release maintenance queue capacity at timeout while retaining a separate per-session mutation barrier until every admitted file-backed or SQLite transcript write settles, then explicitly approve or narrow the new configuration and shared queue callback contracts.
