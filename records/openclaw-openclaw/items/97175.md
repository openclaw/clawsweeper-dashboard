## Summary

Keep this PR open for an explicit context-engine owner decision. The exact-head patch appears technically coherent, has convincing live behavior proof, green broad CI, and no discrete actionable correctness finding, but it establishes new configuration, shared queue-callback, persistence-fencing, and process-signal contracts; because the timeout is disabled by default, the reported stall also remains unchanged for operators who do not discover and enable the setting.

## What This Changes

The PR adds an opt-in timeout for deferred context-engine maintenance, fences late task and transcript side effects, coordinates in-flight persistence, throttles stalled-session warnings, and documents/tests the new setting.

## Best Possible Solution

Use one maintainer-approved host-owned cancellation contract for deferred context-engine maintenance: define whether the bound is safely enabled by default or intentionally operator-opt-in, reuse the existing compaction timeout/AbortSignal seam where practical, retain file-and-SQLite late-write fencing, and prove both same-session recovery and clean shutdown before merge.
