## Summary

The latest head is a patch-identical rebase of the previously reviewed stack, so both P1 persistence-ordering defects remain: timeout cleanup drops the same-session barrier while admitted file persistence may still settle, and the SQLite rewrite branch never receives the timeout fence. The live proof convincingly demonstrates the primary JSONL path, but it does not make these sibling races safe; the new config and shared queue callback also remain durable contracts requiring owner acceptance.

## What This Changes

The PR adds an opt-in per-task timeout and late-side-effect fencing for deferred context-engine maintenance, throttles repeated stalled-session warnings, and adds one config key, one generic queue timeout callback, docs, and regression tests.

## Best Possible Solution

Keep the opt-in upgrade behavior, but use one session-owned lifecycle barrier that remains visible until every file-backed and SQLite mutation admitted before timeout settles, rejects new side effects after timeout, and receives explicit owner approval for the config and shared queue contracts.
