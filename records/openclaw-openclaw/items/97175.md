## Summary

This PR remains necessary and has strong proof of the original session stall, but it is not merge-ready: the exact head still releases the same-session barrier while an admitted file persist may be running, and its SQLite rewrite path bypasses the timeout fence. The focused correctness repairs are suitable for the repair lane, while maintainers must separately approve or narrow the permanent config and queue API contracts.

## What This Changes

The PR adds an opt-in timeout and late-side-effect fencing for deferred context-engine maintenance, throttles repeated stalled-session warnings, and adds configuration, documentation, and regression coverage.

## Best Possible Solution

Use one session-owned lifecycle that retains the foreground barrier through every file-backed and SQLite mutation admitted before timeout, releases queued work only after those writes settle or are atomically cancelled, and then either explicitly approves or narrows the proposed public/shared timeout surfaces.
