## Summary

Likely related people: steipete (adjacent agent/runtime owner, low confidence).

## What This Changes

This PR adds an opt-in per-task timeout and late-side-effect fence for deferred context-engine maintenance, documents the new setting, and throttles repeated stalled-session warnings.

## Best Possible Solution

Separate foreground-turn liveness from maintenance scheduling: release the read barrier at timeout, but retain a bounded timeout-afterlife state that coalesces later same-session maintenance requests until the old worker settles or an explicitly chosen cancellation/retry policy takes over.

## Maintainer Decision

Required: true

Kind: product_direction

Question: After a configured maintenance timeout releases the session lane, should OpenClaw preserve same-session maintenance coalescing until the non-cooperative worker settles, or intentionally allow a replacement maintenance run to overlap it?

Rationale: The queue can release a timed-out promise but cannot forcibly stop plugin-owned `maintain()` work; choosing between deferred retry, overlap, or an SDK cancellation contract sets the persistent session-state and plugin compatibility semantics.

Likely owner: steipete

Owner reason: This is a core queue/session lifecycle and plugin-contract decision rather than a mechanical test or documentation change.

Owner confidence: low

Options:

- **Preserve coalescing after timeout (recommended):** Keep a timeout-afterlife marker that lets foreground turns proceed while later maintenance triggers coalesce until the old worker settles, then schedule at most one follow-up run.
- **Permit overlapping retry:** Release the lane and allow the next trigger to start a replacement maintenance worker even while the original worker remains alive, accepting plugin-lock and ordering risk.
- **Define cancellable maintenance:** Add a separately designed context-engine cancellation contract before enabling retries, so timeout can request cooperative termination rather than leaving detached work alive.

## Solution Assessment

No. The branch correctly fences many late writes, but it needs an explicit timeout-afterlife coalescing policy so releasing the lane does not permit overlapping same-session maintenance workers.
