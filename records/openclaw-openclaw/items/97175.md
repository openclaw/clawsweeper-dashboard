## Label Justifications

- `P1`: The PR addresses a real multi-minute same-session stall that can block queued user messages in an active agent workflow.
- `merge-risk: 🚨 compatibility`: Merging creates a new public config setting and generic queue callback whose defaults and semantics become long-lived compatibility contracts.
- `merge-risk: 🚨 session-state`: An incorrectly fenced or overlapping timed-out maintenance worker could rewrite or otherwise act on session state after the foreground turn resumes.
- `merge-risk: 🚨 availability`: Timed-out plugin work can continue outside the released lane and may retain locks, I/O, or resources even though queued session work proceeds.

## Summary

Keep open: the exact-head patch has no supported actionable defect and includes convincing live proof, but merging it requires context-engine owner approval because it creates public timeout policy and intentionally releases a session lane before a non-cooperative plugin worker has exited.

## What This Changes

Adds an opt-in timeout for deferred context-engine turn maintenance, fences late host-owned transcript and task-state writes, throttles repeated stalled-session warnings, and documents and tests the new configuration.

## Best Possible Solution

Land an owner-approved context-engine timeout contract that explicitly defines the default, operator discoverability, late host-write fencing, and lifecycle of non-cooperative workers; retain the new config and generic queue hook only if those are the intended permanent ownership boundaries.
