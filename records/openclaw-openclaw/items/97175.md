## Summary

Keep this PR open: its timeout and host-side fence address the reported queue wedge, but the current design still changes existing context-engine maintenance from same-session serial execution to possible overlap after a timeout. Documenting that new requirement does not preserve compatibility for installed plugins that rely on their previous single-flight lifecycle.

## What This Changes

This PR adds an opt-in timeout for deferred background context-engine maintenance, fences late host-side transcript and task writes, documents a new `maintain()` concurrency expectation, and throttles repeated stalled-session warnings.

## System Context

After an agent turn, OpenClaw can schedule context-engine maintenance on a per-session lane before later turns proceed. That worker calls a plugin-owned `maintain()` implementation and may update transcript and task state, so releasing the lane while that call continues affects both session liveness and plugin lifecycle safety.

## Architecture Diagram

  D --> E[Transcript and task updates]

  G[Opt-in timeout] --> C

## Best Possible Solution

Keep user-turn liveness separate from plugin invocation ownership: release the session lane on timeout, but retain a per-session maintenance invocation barrier so another `maintain()` call cannot begin until the abandoned call settles; only adopt concurrent invocation as a deliberate, versioned plugin-contract decision.
