## Summary

Keep open: current main and the latest release have stronger built-in config validation, SecretRef preflight, base-hash guarded writes, and agent config-write allowlisting, but they still do not expose the requested synchronous plugin/API-level pre-persistence config veto. This remains a security-sensitive plugin API/product decision, and the issue discussion already kept it tied to the config validation/mutation RFC direction.

## What This Changes

Request a synchronous `config:pre-apply` plugin/API hook that can inspect and reject pending gateway config writes before they are persisted.

## Best Possible Solution

Define a documented synchronous config-write interception seam invoked by `config.set`, `config.patch`, `config.apply`, and shared config mutation helpers after pending config computation plus built-in validation/preflight, but before persistence, with typed rejection and tests proving rejected writes leave disk and active runtime config unchanged.
