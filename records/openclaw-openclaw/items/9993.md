## Summary

Keep open: current main has built-in config validation, SecretRef preflight, destructive-array guards, and an agent-facing config allowlist, but it still does not provide the requested synchronous plugin-facing pre-apply veto before persisted config writes.

## What This Changes

The issue requests a synchronous config pre-apply hook that can validate and reject pending gateway config changes before persistence.

## Best Possible Solution

Define a documented synchronous config-write interception contract that runs after candidate config computation and built-in validation/preflight but before persistence across `config.set`, `config.patch`, `config.apply`, and shared mutation helpers, with typed rejection and tests proving rejected writes leave disk and active runtime config unchanged.
