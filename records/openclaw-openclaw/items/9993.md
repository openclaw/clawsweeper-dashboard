## Summary

Keep open. Current main and the latest release have adjacent config validation, SecretRef preflight, base-hash guarded writes, protected agent-side config paths, and the existing `config-guard` workaround is useful, but there is still no mandatory synchronous plugin/API-level config pre-apply veto before config mutations are persisted.

## What This Changes

Request a synchronous `config:pre-apply` hook that lets plugins validate and reject Gateway config mutations before persistence.

## Best Possible Solution

Define a narrow documented config-write interception seam that runs after built-in validation and SecretRef preflight but before persistence across config.set, config.patch, config.apply, and shared mutation helpers, with typed rejection and regression tests proving disk and active runtime config stay unchanged on rejection.

## Reproduction Assessment

Yes at source level: current hook names/docs lack a config pre-apply hook, and config.set/config.patch/config.apply validate or preflight before committing through the shared write path. I did not run a live crash repro because the central item is a feature/API seam request.

## Solution Assessment

Unclear until maintainer design review. A synchronous pre-persistence config-write veto is the right class of solution, but the durable design needs explicit security, lifecycle, and owner-boundary semantics first.
