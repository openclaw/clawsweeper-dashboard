## Summary

Keep open. Current main has guarded config RPC writes and built-in validation/preflight, but it still lacks the requested synchronous plugin-facing config pre-apply veto before persisted config mutations.

## What This Changes

The issue requests a synchronous `config:pre-apply` plugin hook/API that can inspect current and pending config and reject `config.patch` or `config.apply` before disk persistence.

## Best Possible Solution

Design a documented synchronous config-write interception API that runs after pending config computation and built-in validation/preflight but before persistence across all shared config mutation paths.

Rationale: The remaining work defines a public plugin/security boundary around persisted config mutation, so automation should not choose the hook contract or failure semantics without maintainer intent.

Options:

- **Design the API first (recommended):** Define a documented config-write hook contract covering all config mutation paths, with explicit ordering, typed reject results, actor metadata, and regression tests before implementation.
- **Keep built-in guards only:** Close or defer the plugin veto and rely on schema validation, SecretRef preflight, base-hash writes, and the agent config-write allowlist instead.
- **Limit to agent tool writes:** Add a narrower interception point only for agent-issued `config.patch` and `config.apply`, accepting that other config writers will not be covered.

Keeping this open is the best current outcome because wrapper scripts and `before_tool_call` cannot cover all config writers or define the required public plugin/security contract.
