- `impact:crash-loop`: The issue reports bad config causing the gateway to crash or repeatedly fall back until a human repairs the file.
- `maturity:stable`: The affected Gateway runtime config mutation surface maps to an M4 Stable maturity feature.

## Summary

Current main still lacks the requested synchronous plugin/API-level veto before config mutations are persisted, even though adjacent validation, SecretRef preflight, base-hash guarding, destructive-array checks, and agent tool path allowlisting now reduce the original crash class. The issue should remain open as a product/security-sensitive plugin API gap rather than being treated as an already-implemented bug fix.

## What This Changes

The issue requests a config pre-apply hook that lets validators inspect current and pending config and reject config.patch/config.apply writes before persistence.

## Best Possible Solution

Coordinate this through the config validation/mutation RFC and add one documented synchronous config-write interception contract that covers config.set, config.patch, config.apply, and shared config mutation helpers after built-in validation/preflight but before persistence.

- **Reject plugin veto for now:** Close this direction and rely on built-in validation plus guarded agent tools, accepting that external validators cannot forcibly intercept all config writes.
