## Summary

Keep open. Current OpenClaw validates Gateway config writes and restricts agent-driven config mutations, but its public plugin hook catalog still has no synchronous pre-persistence configuration veto. This is an additive, security-sensitive Plugin SDK direction that needs an explicit lifecycle and trust-policy decision rather than a mechanical repair.

## What This Changes

Add a rejectable plugin hook that can inspect a computed configuration change before Gateway or other OpenClaw-owned writers persist it.

## System Context

Gateway configuration changes arrive from operator RPC, CLI, UI, and other OpenClaw-owned mutation paths, then pass schema and secret preflight before being written and reloaded. The requested hook would add plugin policy enforcement between pending-config computation and persistence.

## Architecture Diagram

flowchart LR
  A[Config clients and tools] --> B[Gateway config mutation]
  B --> C[Pending configuration]
  C --> D[Schema and secret preflight]
  D --> E[Plugin policy decision]
  E --> F[Atomic config write]
  F --> G[Gateway reload or restart]

## Best Possible Solution

Define one documented, typed Plugin SDK interception contract for all intended OpenClaw-owned configuration writers after built-in validation/preflight and before persistence, with bounded synchronous decisions and tests that rejected writes leave disk and active runtime state unchanged.
