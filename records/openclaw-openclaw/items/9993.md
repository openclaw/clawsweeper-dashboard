## Summary

Keep open: current main and v2026.6.11 have stronger built-in config validation, SecretRef preflight, base-hash guarded writes, and agent-tool guardrails, but they still do not provide the requested synchronous plugin-facing pre-apply veto before persisted config mutations.

## What This Changes

The issue requests a public `config:pre-apply` hook that lets validators inspect and reject pending gateway config writes before `config.patch` or `config.apply` persists them.

## Best Possible Solution

Design a documented synchronous config-write interception point for `config.set`, `config.patch`, `config.apply`, and shared mutation helpers after pending config computation plus built-in validation/preflight but before persistence, with tests proving rejection leaves disk and active runtime config unchanged.
