## Summary

Keep open. Current main has built-in config validation, SecretRef preflight, base-hash/destructive-array guards, and agent-facing config write allowlists, but it still lacks the requested mandatory synchronous plugin/API-level veto before config mutations are persisted; the linked config-guard repo is a useful workaround, but it remains bypassable unless the agent voluntarily calls it.

## What This Changes

Request a synchronous config pre-apply hook that lets plugins validate and reject config.set, config.patch, and config.apply changes before persistence.

## Best Possible Solution

Define a maintainer-approved config mutation interception contract invoked by config.set, config.patch, config.apply, and shared mutation helpers after pending-config computation plus built-in validation/preflight, but before persistence, with typed rejection and regression tests proving disk and runtime config remain unchanged on rejection.

## Reproduction Assessment

Yes, from source. The hook catalog and config write paths on current main show built-in validation/preflight but no mandatory plugin/API-level pre-persistence config veto.

## Solution Assessment

Yes as a direction, but not as an automatic fix. A synchronous config-write interception point is the right seam if external validators must be impossible to bypass, while wrapper scripts and before_tool_call remain too narrow.
