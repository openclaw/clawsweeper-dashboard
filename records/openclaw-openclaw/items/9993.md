## Summary

Current main has stronger built-in config safety, but it still lacks the requested mandatory synchronous plugin/API-level veto before persisted config mutations, so this remains real product/API work rather than conservative cleanup.

## What This Changes

Request a synchronous config pre-apply hook that can inspect current and pending config and reject gateway config.patch/config.apply writes before persistence.

## Best Possible Solution

Define a documented synchronous config-write interception API at the plugin/runtime boundary, invoked after pending config computation and built-in validation/preflight but before persistence, with typed rejection and regression coverage proving rejected writes leave disk and active runtime config unchanged.

Options:

- **Design the veto API in the RFC (recommended):** Keep this open and resolve hook shape, actor metadata, SecretRef/preflight ordering, fail-closed behavior, recursion rules, and shared-helper coverage through the config validation/mutation RFC before implementation.
- **Limit to core validation only:** Decline the plugin veto API and continue strengthening built-in validation, SecretRef preflight, allowlists, and doctor repair paths while accepting that external validators cannot be mandatory.
- **Keep validators as optional packages:** Ask contributors to keep config guards as skills/plugins without a core pre-apply seam, which preserves core size but does not solve the bypass described here.

## Reproduction Assessment

Yes, from source inspection: current main has config validation, base-hash guarded writes, SecretRef preflight, and agent-tool restrictions, but no PluginHookName or config mutation call site exposes a synchronous pre-persistence config veto. I did not run a live crash scenario because the remaining gap is a feature/API seam rather than a narrow current-main bug reproduction.

## Solution Assessment

Unclear until maintainer design review. The requested hook is a plausible direction, but the maintainable solution should be coordinated with the config validation/mutation RFC and cover config.set, config.patch, config.apply, shared mutation helpers, and plugin runtime config writes rather than only one Gateway method.
