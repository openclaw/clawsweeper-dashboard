## Summary

Keep open: current main has config schema validation, SecretRef preflight, base-hash guarded writes, and agent-tool restrictions, but it still lacks the requested synchronous plugin/API veto point before config writes are persisted.

## What This Changes

The issue requests a `config:pre-apply` hook that lets validators inspect and reject pending `config.set`, `config.patch`, or `config.apply` changes before disk persistence.

## Best Possible Solution

Define a documented synchronous config-write interception API that runs after pending config computation and built-in validation/preflight but before persistence, covers all config write paths, and returns a typed reject result without mutating disk or active runtime state on rejection.
