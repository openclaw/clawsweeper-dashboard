## Summary

Keep open. Current main has built-in config validation, SecretRef preflight, guarded writes, destructive-array protection, and an agent config-write allowlist, but it still lacks the requested synchronous plugin/API-level pre-persistence veto for config mutations; the linked `jzOcb/config-guard` project is useful external prior art but remains optional and bypassable.

## What This Changes

Add a synchronous `config:pre-apply` hook/API so validators can inspect and reject pending config writes before they are persisted.

## Best Possible Solution

Design a documented synchronous config-write interception API that runs after pending config computation and built-in validation/preflight but before persistence across all shared config mutation paths, with typed rejection and regression tests proving rejected writes leave disk and active runtime config unchanged.
