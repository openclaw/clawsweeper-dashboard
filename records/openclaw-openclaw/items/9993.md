## Summary

Keep open: current main and the latest release have built-in config validation, SecretRef preflight, base-hash guarded writes, and agent-tool guards, but they still do not expose the requested synchronous plugin-facing veto before config mutations are persisted.

## What This Changes

The issue requests a synchronous plugin-facing `config:pre-apply` hook that can inspect and reject pending gateway config mutations before they are persisted.

## Best Possible Solution

Define a documented synchronous config-write interception seam invoked after pending config computation and built-in validation/preflight but before persistence, covering `config.set`, `config.patch`, `config.apply`, and shared config mutation helpers with tests proving rejection leaves disk and active runtime config unchanged.

Options:

- **Design a guarded config-write veto (recommended):** Approve a narrow hook/API contract with current and pending config, changed paths, actor metadata, base hash, typed reject result, timeout/recursion rules, and tests for all config write paths.
- **Keep validation in core/doctor only:** Reject plugin veto power for now and continue adding built-in validators, doctor checks, and agent-tool allowlists for known dangerous config changes.
- **Route through a broader preflight RFC:** Keep this issue open as a dependency of a wider config validation/mutation framework that also covers boot-time preflight and rollback behavior.

Yes at source level: current main's hook catalog lacks a config-write hook, and `config.set`/`config.patch`/`config.apply` commit after validation and SecretRef preflight without a rejectable plugin call.
