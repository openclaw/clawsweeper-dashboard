## Summary

Keep open: current main and the latest release have important config-write safeguards, but they still do not expose the requested synchronous plugin/API veto before persisted config writes.

## What This Changes

The issue requests a synchronous config pre-apply hook that lets validators inspect and reject gateway config changes before they are written.

## Best Possible Solution

Define a documented config-write interception contract that runs after pending config computation and built-in validation/preflight, before persistence, across config.set, config.patch, config.apply, and shared config mutation helpers.

## Reproduction Assessment

Yes for the source-level API gap: current main can be traced from config.patch/config.apply through validation and SecretRef preflight to persistence without a config pre-apply plugin hook. This is a feature/API gap rather than a runnable failing test.

## Solution Assessment

Yes directionally, but not as a one-off RPC hook; the maintainable solution is a reviewed plugin API contract that covers the shared config mutation boundary and documents ordering and rejection semantics.
