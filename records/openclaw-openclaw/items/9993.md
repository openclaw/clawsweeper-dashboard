## Summary

Keep open. Current main and the latest release have stronger built-in config validation, SecretRef preflight, destructive-array guards, and agent-tool allowlists, but they still do not expose the requested mandatory synchronous plugin/API veto before config writes persist.

## What This Changes

Request a `config:pre-apply` hook that lets validators inspect and block pending config changes before `config.patch` or `config.apply` writes them.

## Best Possible Solution

Define a maintainer-approved typed config mutation interception contract invoked by `config.set`, `config.patch`, `config.apply`, and shared mutation helpers after pending-config validation/preflight but before persistence, with typed rejection and unchanged-disk/runtime regression tests.

Options:

- **Design the config-write veto API (recommended):** Define a typed pre-persistence hook with explicit ordering, timeouts, redaction/SecretRef rules, actor metadata, fail-closed behavior, and coverage across config.set, config.patch, config.apply, and shared mutation helpers.
- **Keep validation built in only:** Reject the public hook direction and continue improving core validation, doctor, and gateway-tool guards while external validators remain advisory tools that agents must call explicitly.
- **Fold into broader preflight RFC:** Defer this hook until the broader validation/preflight framework chooses one boundary for boot-time checks, config writes, and plugin-owned validators.

## Solution Assessment

Yes as a direction, but not as an automatic fix. A synchronous config-write interception point is the right seam if external validators must be impossible to bypass, while wrapper scripts and `before_tool_call` remain too narrow.
