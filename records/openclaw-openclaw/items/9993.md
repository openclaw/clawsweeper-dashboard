## Summary

Keep open: current main and the latest release have built-in config validation, SecretRef preflight, base-hash guarded writes, and agent-tool config guards, but they still do not provide the requested synchronous plugin-facing pre-apply veto before persisted config mutations.

## What This Changes

Request a synchronous `config:pre-apply` hook/API that can inspect and reject pending config writes before `config.set`, `config.patch`, or `config.apply` persist them.

## Best Possible Solution

Design a documented synchronous config-write interception point that runs after pending config computation and built-in validation/preflight but before persistence across RPC and shared mutation helpers.
