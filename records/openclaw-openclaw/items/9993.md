## Summary

Keep open. Current main and the latest release have adjacent safeguards for config writes, but still do not expose the requested synchronous plugin/API-level pre-apply veto; the reporter's config-guard workaround is useful, but the gateway write path can still bypass it.

## What This Changes

The issue requests a synchronous config pre-apply hook that lets validators inspect and reject pending `config.patch` or `config.apply` changes before config is persisted.

## Best Possible Solution

Keep this open and define a narrow, documented config-write interception seam that runs after built-in validation/preflight and before persistence across RPC and shared mutation helpers.

## Reproduction Assessment

Yes for the source-level API gap: current main exposes config write validation and hook catalogs, and they do not include a config pre-apply plugin veto. I did not run the crash incident because this is primarily a feature/API seam request, not one deterministic current-main bug.

## Solution Assessment

Unclear until maintainer product/security review. A synchronous config-write interception point is the right class of solution, but the durable API must cover shared mutation helpers and define trust, redaction, timeout, and failure semantics.
