## Summary

The requested plugin veto remains absent on current main, and adjacent issues do not own the same behavior; this should stay open for an explicit security and plugin-API decision rather than automated implementation.

## What This Changes

Requests a synchronous plugin-facing pre-apply hook that can reject configuration changes before they are persisted.

## Best Possible Solution

Define one typed, documented pre-commit policy seam in the shared config mutation layer, with redacted context, bounded execution, explicit ordering, recovery bypass rules, and tests proving rejection leaves disk and runtime state unchanged.

- **Keep validation core-owned:** Do not grant plugin veto authority; continue adding generic built-in validation and protected-path rules while external validators remain advisory.
