## Summary

Keep open: current main has guarded config writes, validation, SecretRef preflight, and a tool-call hook, but it still lacks the requested synchronous plugin/API-level config pre-apply veto before config mutations are persisted.

## What This Changes

Request a synchronous config pre-apply hook that lets plugins or policy code inspect and reject pending config.set/config.patch/config.apply mutations before persistence.

## Best Possible Solution

Define one documented config-write interception seam after built-in validation/preflight and before persistence, covering config.set, config.patch, config.apply, and shared mutation helpers with typed rejection and no disk/runtime change on rejection.

## Reproduction Assessment

Yes, source inspection shows the public hook catalog lacks a config pre-apply hook and the config write handlers persist through shared writers without a plugin rejection point.

## Solution Assessment

Unclear until maintainer design review: a pre-persistence hook is the right class of solution, but its public API, trust model, ordering, failure mode, and coverage must be decided before implementation.
