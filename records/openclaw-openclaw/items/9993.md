## Summary

Keep open: current main has guarded config writes, schema validation, SecretRef preflight, and agent-tool allowlist checks, but it still lacks the requested synchronous plugin/API-level config pre-apply veto before config mutations are persisted.

## What This Changes

The issue requests a synchronous config pre-apply hook that can validate and veto gateway config mutations before persistence.

## Best Possible Solution

Define one documented config-write interception seam after built-in validation/preflight and before persistence, covering config.set, config.patch, config.apply, and shared mutation helpers with typed rejection and no disk/runtime change on rejection.

## Reproduction Assessment

Yes. Source inspection shows the public hook catalog lacks a config pre-apply hook and the config write handlers persist through shared writers without a plugin rejection point.

## Solution Assessment

Unclear until maintainer design review. A pre-persistence hook is the right class of solution, but its public API, trust model, ordering, failure mode, and coverage across shared writers need a maintainer decision.
