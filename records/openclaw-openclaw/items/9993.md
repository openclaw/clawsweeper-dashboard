## Summary

Keep open: current main has built-in config validation, SecretRef preflight, base-hash guarded writes, and config.patch safety checks, but it still lacks the requested synchronous plugin/API-level pre-apply veto before config mutations are persisted.

## What This Changes

Request a synchronous config pre-apply hook that receives current and pending config and can block gateway config.patch/config.apply writes before persistence.

## Best Possible Solution

Design a narrow, documented config-write interception seam that runs after built-in validation and SecretRef preflight but before persistence across config.set, config.patch, config.apply, and shared mutation helpers, with typed rejection and regression tests proving rejected writes leave disk and runtime state unchanged.

## Reproduction Assessment

Yes, at source level: current main's hook catalog and config write paths can be inspected and they do not expose a config pre-apply hook. I did not run a crash repro because the remaining request is a new interception seam rather than one deterministic runtime crash.

## Solution Assessment

Unclear until maintainer design review. A synchronous config-write veto is the right class of solution, but the durable shape needs explicit security, ordering, timeout, and shared-helper coverage decisions.
