## Summary

Keep open: current main and the latest release have built-in config validation, SecretRef preflight, base-hash guarded writes, and agent-tool mutation guards, but they still do not expose the requested synchronous plugin-facing pre-apply veto before persisted config writes.

## What This Changes

The issue requests a synchronous plugin/API pre-apply hook that can validate and reject pending gateway config changes before they are persisted.

## Best Possible Solution

Design a documented synchronous config-write interception contract that runs after pending config computation and built-in validation/preflight but before persistence across Gateway RPC and shared mutation helpers.

Options:

- **Design the API first (recommended):** Keep this issue open, settle hook ordering and metadata in maintainer design, then implement the agreed SDK contract with regression tests proving rejection leaves disk and active runtime config unchanged.
- **Rely on built-in validation:** Decline a plugin veto API and rescope safety work to schema validation, SecretRef preflight, semantic model/provider validation, baseHash guards, destructive-array checks, and agent-tool allowlists.
- **Limit interception to agent writes:** Add a narrower guard around model-initiated gateway config writes while accepting that CLI, setup, Control UI, and shared helper writes remain outside the plugin veto path.
