## Summary

Keep open: current main has built-in config validation, SecretRef preflight, base-hash checks, destructive-array guards, and an agent-tool allowlist, but it still does not expose the requested synchronous plugin/API-level config pre-apply veto before persistence. This remains a real security-sensitive plugin API gap that needs maintainer product/security direction.

## What This Changes

Request a synchronous `config:pre-apply` hook that lets plugins or skills inspect and reject pending gateway config changes before `config.patch` or `config.apply` writes them.

## Best Possible Solution

Define a documented synchronous config-write interception API that runs after pending config computation plus built-in validation/preflight and before persistence, covers all config write paths, and returns a typed rejection without mutating disk or active runtime config.
