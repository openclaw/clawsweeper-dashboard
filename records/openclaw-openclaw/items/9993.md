## Summary

Keep open. Current main has built-in config validation, SecretRef preflight, base-hash guarded writes, destructive-array protection, and an agent-tool allowlist, but it still lacks the requested mandatory synchronous plugin/API-level config pre-apply veto before config mutations are persisted.

## What This Changes

Request a synchronous config pre-apply hook that can validate and veto gateway config changes before persistence.

## Best Possible Solution

Define a maintainer-approved config mutation interception contract that covers config.set, config.patch, config.apply, and shared mutation helpers after pending-config computation plus built-in validation/preflight, but before persistence.

## Reproduction Assessment

Yes, from source: current main has built-in config validation and SecretRef preflight, but the hook catalog and config write path show no mandatory plugin/API-level pre-persistence config veto.

## Solution Assessment

Yes as a direction, but it needs maintainer design first: a public synchronous config-write interception point is the right seam if external validators must be impossible to bypass, while wrapper scripts and before_tool_call remain too narrow.
