## Summary

Keep open. Current main has adjacent config validation, SecretRef preflight, guarded writes, and a tool-call hook, but it still lacks the requested synchronous plugin/API-level config pre-apply veto before config mutations are persisted.

## What This Changes

Add a synchronous config pre-apply hook that can inspect current and pending config and reject config.set/config.patch/config.apply writes before persistence.

## Best Possible Solution

Define a narrow, documented config-write interception seam that runs after built-in validation/preflight and before persistence across config.set, config.patch, config.apply, and shared mutation helpers.

## Reproduction Assessment

Yes for the source-level API gap: current hook names and config write paths can be inspected on main, and they do not expose a config pre-apply hook. I did not run a crash repro because this is a feature/API seam request rather than one deterministic runtime bug.

## Solution Assessment

Unclear until maintainer design review. A synchronous config-write veto is the right class of solution, but the durable design needs explicit security and lifecycle semantics before implementation.
