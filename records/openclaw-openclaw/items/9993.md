## Summary

Keep open: current main and the latest release have stronger config validation, SecretRef preflight, base-hash checks, destructive-array guards, and an agent config-write allowlist, but they still do not expose the requested synchronous plugin/API-level config pre-apply veto before persistence.

## What This Changes

The issue requests a synchronous config pre-apply hook that lets plugins or validators inspect and reject gateway config mutations before they are written.

## Best Possible Solution

Define a documented synchronous config-write interception point after pending config computation and built-in validation/preflight, before persistence, covering config.set/config.patch/config.apply and shared mutation helpers with typed reject results and regression tests proving rejected writes leave disk/runtime state unchanged.

## Reproduction Assessment

Unclear until maintainer design review. A pre-persistence interception point is the right boundary for the reported gap, but the final implementation must be a documented plugin/security contract rather than an ad hoc hook around one RPC method.
