## Summary

Keep open. Current OpenClaw has strict schema validation, guarded config RPC writes, rejected-write preservation, and Doctor recovery, but the requested mandatory plugin-facing pre-persistence veto is still absent from the public hook catalog. This is a security-sensitive Plugin SDK contract and should follow the linked config validation/mutation RFC rather than be dispatched as a mechanical fix.

## What This Changes

Add a synchronous, rejectable plugin hook that receives the current and pending configuration before `config.set`, `config.patch`, or `config.apply` persists a change.

## System Context

Gateway configuration RPCs let the Control UI, CLI, and agents compute and persist configuration updates. Those writes feed hot reload and gateway restart behavior, so a plugin veto here would sit between built-in validation/preflight and durable configuration storage.

## Architecture Diagram

flowchart LR
  A[CLI, Control UI, or agent] --> B[Gateway config RPC]
  B --> C[Compute pending configuration]
  C --> D[Schema and secret preflight]
  D --> E[Requested plugin veto seam]
  E --> F[Atomic config write]
  F --> G[Hot reload or restart]
  D --> H[Rejected write and Doctor recovery]

## Best Possible Solution

Define one documented Plugin SDK config-write interception contract at the shared mutation boundary, after OpenClaw has computed and preflighted the pending configuration but before persistence, then prove every supported writer shares it and rejected changes preserve both disk and active runtime state.

- **Limit enforcement to agent tools:** Use existing tool interception for agent-originated changes only, accepting that non-tool writers remain outside the policy boundary.
