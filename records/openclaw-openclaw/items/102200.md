## Label Justifications

- `P1`: The report describes a latest-release regression that breaks every multi-turn tool-calling Ollama Cloud agent after the first tool call.
- `impact:session-state`: The failure occurs when replaying prior assistant tool-call history into the next provider turn.
- `impact:auth-provider`: The affected behavior is provider-specific Ollama Cloud/OpenAI-compatible request shaping for tool calls.

## Summary

Close as implemented on current main: the Ollama OpenAI-compatible replay path now preserves Chat Completions tool-call arguments as JSON strings, while the latest release named in the report still predates that fix.

## What This Changes

The issue asks OpenClaw to stop sending Ollama Cloud/OpenAI-compatible second-turn `tool_calls.function.arguments` as JSON objects and preserve the required JSON string shape.

## Best Possible Solution

Keep the current-main Ollama wrapper fix and ship it in the next release; users on v2026.6.11 need a newer main build or release to get the repair.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes for v2026.6.11: the issue includes captured wire evidence and the release source still mutates OpenAI-compatible replay arguments into objects. I did not run a live Ollama Cloud credentialed repro, and current main no longer has the failing source path.

## Solution Assessment

Yes. The current-main fix is the narrow maintainable solution: remove the extra OpenAI-compatible Ollama argument-object mutation while keeping native Ollama object normalization and tests for both contracts.
