## Summary

Keep open: current main does not provide requester-scoped MCP transport resolution, and the request introduces a security-sensitive plugin SDK and authorization boundary that requires explicit maintainer direction; the protected `maintainer` label independently prevents automated cleanup.

## What This Changes

Add a plugin SDK hook that resolves MCP server transport per trusted requester and isolates MCP runtime reuse by channel, account, and sender identity.

## Best Possible Solution

Approve a single generic plugin-owned resolver only after defining the security contract: use a typed trusted requester key, isolate transport/runtime ownership by that key, fail closed when requester context is absent, never log or fingerprint returned credentials, apply the invariant across every MCP consumer, and document that shared-channel transcripts remain shared.

Rationale: The missing requester dimension is source-supported, but the permanent plugin SDK contract and the distinction between tool authorization and transcript visibility are product and security decisions that automation cannot safely choose.

Likely owner: Mathias Bynens

Owner confidence: high

Options:

- **Approve requester-scoped MCP (recommended):** Design one generic resolver with requester-keyed runtime ownership, credential redaction, and fail-closed behavior when trusted requester context is unavailable.
- **Require sender-isolated sessions:** Permit per-user MCP credentials only when the conversation session and transcript are also isolated by sender, trading group-thread continuity for a stronger boundary.
- **Keep MCP operator-scoped:** Retain static MCP transports and direct provider plugins to implement requester-aware REST tools through existing tool context.

## Solution Assessment

Unclear pending maintainer intent: a generic plugin hook is the appropriate ownership direction, but the exact proposal is not yet proven to be the best complete solution across runtime lifecycle, shared-transcript semantics, SDK compatibility, and all MCP consumers.
