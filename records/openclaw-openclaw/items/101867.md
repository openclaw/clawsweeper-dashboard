## Summary

Keep open: current main still settles subagent lost-context and termination paths through registry completion bookkeeping without a stable diagnostic event or OTel span that downstream trace consumers can detect.

## What This Changes

The issue requests telemetry for spawned subagent death or termination so trace consumers can identify failed process/session name, exit or termination reason, and a stable event kind.

## Best Possible Solution

Add a maintainer-approved trusted diagnostic event for subagent terminal states and map it to OTel with stable kind/reason fields, redacted identifiers, and registry/exporter tests.
