## Summary

Keep open: current main and the latest release still lack a stable subagent-death diagnostic event or OTel mapping, while related open issues cover death/delivery causes rather than this observability contract.

## What This Changes

The issue requests a stable telemetry signal when a spawned subagent dies or is terminated, including the session/process name, termination reason, and detectable marker.

## Best Possible Solution

Add a maintainer-approved trusted diagnostic event for subagent terminal states and map it to OTel with stable kind/reason fields, redacted identifiers, and focused registry/exporter tests.
