## Summary

Keep open: current main and the latest release still do not implement a supported Feishu `ignoreFileContent` setting, while the Feishu inbound path still downloads media and projects saved media paths into the agent turn. This needs a maintainer product decision on the supported attachment-context policy before a repair PR should be queued.

## What This Changes

Requested a Feishu attachment-context opt-out so file messages produce placeholders instead of downloaded content in model context.

## Best Possible Solution

Define a Feishu-owned attachment-context policy with a backward-compatible default, per-account/top-level schema and docs, placeholder-only behavior when disabled, and focused tests proving no download or MediaPaths reach the agent in that mode.
