## Summary

Keep open: current main and the latest release still do not implement a supported Feishu `ignoreFileContent` setting, while the Feishu inbound media path still downloads file/media resources and passes saved media facts into the shared agent context builder. This remains a Feishu attachment-ingestion product/config decision rather than cleanup that can be closed.

## What This Changes

The issue asks for Feishu file messages to be represented as placeholder-only context when `ignoreFileContent` is enabled, instead of downloading file content into model context.

## Best Possible Solution

Define a supported Feishu attachment-ingestion policy, keep current downloads as the compatibility default, and add schema/docs/tests for a placeholder-only opt-out if maintainers want that behavior.
