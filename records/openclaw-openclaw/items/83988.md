## Summary

Keep this PR open: it addresses a valid current-main Telegram TTS bug, but the latest head introduces a compile-blocking reference to an unimplemented dispatcher observer, and the available live proof predates the substantial delivery-recovery changes.

## What This Changes

The PR adds a captioned-final-text channel capability and changes ACP and non-ACP final-mode TTS delivery to defer Telegram text, caption voice notes, preserve media, and recover text after failed or cancelled delivery.

## Best Possible Solution

Keep one generic typed captioned-voice capability, implement its missing per-payload failure observer in the dispatcher with focused regression coverage, rebase cleanly, and prove exact-head Telegram always, tagged, media, cancellation, and failure behavior before landing.
