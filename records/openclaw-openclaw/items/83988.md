## Summary

The latest commit fixes the prior ACP canceled-send blocker, but the non-ACP recovery still uses aggregate final outcome counters: a captioned voice can succeed, then an unrelated later final can fail or be canceled and trigger duplicate fallback text. The PR remains useful and necessary because current main does not implement captioned-final TTS, but it is not merge-ready until that defect, exact-head proof, and public capability direction are resolved.

## What This Changes

The PR adds a `captionedFinalText` channel capability, enables it for Telegram, and changes ACP and non-ACP final-mode TTS delivery to defer text into voice-note captions, preserve rich payloads, and recover text after unsuccessful sends.

## Best Possible Solution

Track the outcome of each captioned voice specifically—or enforce and test a compatible single-final invariant—then rebase, provide current-head Telegram proof, and obtain owner approval for the public capability and Telegram default.
