## Summary

Keep this PR open: current main still takes the pre-TTS visible-text settlement path, while this branch proposes a plausible repair but needs maintainer acceptance of its new public channel capability and current-head Telegram proof for the changed delivery paths.

## What This Changes

The branch adds a `captionedFinalText` channel capability, enables it for Telegram, and defers eligible final-mode TTS text across ACP and standard reply dispatch so voice-note captions replace text-before-audio churn.

## Best Possible Solution

Accept a single documented channel capability only if maintainers want it as a stable SDK contract, then land it with current-head Telegram proof for always mode, tagged directives, media preservation, and failed/cancelled voice fallback.
