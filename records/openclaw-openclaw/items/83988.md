## Summary

Keep this PR open: the patch is a plausible fix for the Telegram final-mode TTS churn bug and I found no discrete code-review blocker, but it still needs maintainer acceptance of the new public channel capability/default plus current-head live Telegram proof for the visible paths it changes.

## What This Changes

Adds a `captionedFinalText` channel TTS capability, opts Telegram into it, and changes ACP plus generic final-mode TTS dispatch to defer/suppress visible text until it can be delivered as a voice-note caption with fallback handling, docs, and tests.

## Best Possible Solution

Land this only after maintainers explicitly accept `captionedFinalText` as the public channel capability/default for Telegram and current-head live Telegram proof shows always-mode captioned final TTS, tagged directive-only captioning, media preservation, and fallback behavior; otherwise narrow or split the capability direction from the bug fix.

## Reproduction Assessment

Yes at source level: current main settles or sends visible text before final-mode TTS audio on the ACP and generic dispatch paths. I did not run a live Telegram reproduction in this read-only review.

## Solution Assessment

Yes, this appears to be the right owner boundary because core dispatch owns the text-vs-final-media ordering while Telegram owns caption support. It is not yet the best merge-ready solution until maintainers accept the new capability/default and current-head real Telegram proof covers the changed visible paths.
