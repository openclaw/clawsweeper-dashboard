## Summary

Keep this PR open: current main still contains the reported final-mode TTS ordering problem, and this remains the canonical candidate fix. The implementation has strong regression coverage and useful prior live screenshots, but the latest head materially changes cancellation, asynchronous-failure, and per-payload recovery behavior without exact-head Telegram proof, while the new extension-facing delivery contract still needs explicit owner acceptance.

## What This Changes

The PR adds a captioned-final-text channel capability and changes ACP and non-ACP final-mode TTS delivery to defer Telegram text, caption voice notes, preserve media, and recover text after failed or cancelled voice delivery.

## Best Possible Solution

Keep the generic typed capability only if the channel/API owner confirms bundled caption delivery as Telegram's canonical final-mode behavior, then require exact-head Telegram proof for always mode, tagged directives, media preservation, and visible fallback outcomes before landing; track any optional separate-delivery preference through https://github.com/openclaw/openclaw/issues/42539 rather than adding an unreviewed config surface here.
