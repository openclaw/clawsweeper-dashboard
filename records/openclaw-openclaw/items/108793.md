## Summary

Keep this PR open for revision: it removes the unconditional Codex label, but the replacement still derives an execution runtime from a model-provider name, so it can record incorrect metadata and leaves inherited runs unresolved.

## What This Changes

The PR infers Workboard execution engines from explicit provider strings, adds an `unknown` engine variant and dynamic execution-id suffix, and renders the new value in the Control UI.

## Best Possible Solution

Carry the canonical resolved agent runtime, provider, and model from the Gateway run-start result into Workboard—or update from the authoritative task/session record immediately after start—then derive the display engine from the runtime id rather than provider-name heuristics.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: current main hardcodes `engine: "codex"` and the `:codex` suffix before starting a worker, so any inherited non-Codex runtime produces incorrect metadata. No live current-main run was performed in this read-only review.

## Solution Assessment

No. Replacing a hardcoded runtime with provider-name inference is not the best fix because provider and execution runtime are separate identities; Workboard should consume authoritative resolved run metadata.
