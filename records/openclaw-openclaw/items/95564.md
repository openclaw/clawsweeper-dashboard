## Summary

Keep open: current main still posts OpenAI Codex token exchange and refresh through strict guarded fetch, so the PR addresses a real auth-provider bug, but merge should wait for maintainer acceptance of OAuth credential proxy routing plus a small supported-helper/test cleanup.

## What This Changes

Adds env-proxy routing flags to the OpenAI Codex OAuth token POST helper used by authorization-code exchange and token refresh.

## Best Possible Solution

Land the focused OAuth token helper fix using `withTrustedEnvProxyGuardedFetchMode`, add exchange/refresh assertions, and have maintainers explicitly accept env-proxy routing for OpenAI OAuth credential POSTs.

## Reproduction Assessment

Yes. Source inspection shows current main’s shared OAuth token helper uses strict guarded fetch without trusted env-proxy mode, and the PR screenshots show the matching unsupported-region token exchange failure before the patch.

## Solution Assessment

Mostly yes. The shared token POST helper is the right narrow fix location for browser OAuth exchange and refresh, but the best merge shape should use the current helper, add focused tests, and explicitly consider adjacent device-code auth POSTs.
