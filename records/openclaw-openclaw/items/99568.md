## Summary

Keep open. The patch is a focused Android bug fix with no blocking findings: current main and v2026.6.11 still allow the app package through the shared allowlist policy helper, while this PR centralizes self-package rejection for both live callback policy evaluation and queued outbox reauthorization.

## What This Changes

The PR changes Android notification forwarding policy so the app’s own package is rejected even when present in allowlist mode, and adds focused policy and SecurePrefs regression tests.

## Best Possible Solution

Land the centralized policy guard once maintainers accept that Android self-notification forwarding is unsupported, while keeping broader native-channel notification ownership work tracked separately.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 can return true for the app package in allowlist mode because the shared helper only checks the configured package set. I did not run a local Android repro in this read-only review, but the PR body now supplies after-fix emulator/Gateway proof.

## Solution Assessment

Yes. Centralizing self-package rejection in NotificationForwardingPolicy is the best fix shape because it covers both live listener policy evaluation and queued outbox reauthorization; a callback-only guard would leave the shared policy path inconsistent.
