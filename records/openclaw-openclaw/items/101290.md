## Summary

Keep open: current main and latest stable release still expose mutable shared-state DB open/checkpoint paths from CLI/status/probe surfaces, while related work only covers adjacent durability or recovery issues rather than this live-gateway ownership bug.

## What This Changes

The issue asks OpenClaw to prevent read-only health/status/stability CLI invocations from mutating or corrupting the shared SQLite state database while the gateway is active.

## Best Possible Solution

Make health/status/stability prefer running-gateway RPC and ensure any CLI fallback file access while a gateway owns the state DB is read-only and no-maintenance, with an explicit maintainer-approved single-writer or lease model for repair paths.

Kind: product_direction

Question: Should the shared state DB policy be RPC-first/no-maintenance CLI access, a stricter single-writer gateway lease, or both?

Rationale: Source confirms mutable CLI-side DB open paths, but the durable fix changes ownership between gateway RPC observability, doctor migrations, plugin-state probes, and operator recovery behavior.

Likely owner: steipete

Owner reason: The choice cuts across the DB-first runtime-state architecture introduced in PR #78595 and current gateway/CLI ownership boundaries.

Owner confidence: high

Options:

- **RPC-first plus no-maintenance CLI (recommended):** Status, health, and stability should ask the running gateway first, and fallback file opens while the gateway is active should be read-only with no journal or checkpoint pragmas.
- **Single-writer gateway lease:** The gateway should own the state DB write/maintenance lease, and non-gateway processes should fail closed or route through gateway APIs for writes and maintenance.
- **Forensic harness first:** Pause implementation until the reporter's corrupt DB bundle and a native runtime harness confirm the precise OpenClaw helper/runtime interaction.

## Reproduction Assessment

Source-reproducible, but not live-reproduced: current main still exposes mutable shared-state DB open/checkpoint paths from CLI/status/probe surfaces, while the corruption race itself is supported by reporter forensics rather than a deterministic throwaway repro.

## Solution Assessment

No final fix is selected yet; RPC-first/no-maintenance matches the source boundary and reporter preference, but maintainers should decide whether a gateway single-writer lease is also required before implementation.
