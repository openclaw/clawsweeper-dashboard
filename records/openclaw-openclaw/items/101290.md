## Summary

Keep open: current main and the latest stable tag still have shared-state SQLite openers that configure WAL maintenance and diagnostic paths that can mutate/checkpoint the state DB, while the reporter has supplied fresh forensic context and the related merged work only covers adjacent durability or handle-lifecycle issues.

## What This Changes

The issue asks OpenClaw to prevent CLI health/status/stability startup or preflight paths from modifying or corrupting the live shared state database while a gateway is running.

## Best Possible Solution

Adopt a maintainer-approved DB ownership policy: health/status/stability should use gateway RPC or read-only no-maintenance file access while a gateway owns the DB, and doctor/repair write or checkpoint paths should require an explicit maintenance/lease boundary with regression proof.

Options:

- **RPC-first plus no-maintenance fallback:** Status, health, and stability use the running gateway when available, and any fallback open while a gateway is active must be read-only with no journal, checkpoint, or migration side effects.
- **Gateway lease plus RPC-first probes (recommended):** The gateway owns write and maintenance access through an explicit lease, while CLI probes route through RPC and doctor/repair paths require maintenance mode or a released lease.
- **Forensic harness before implementation:** Pause code changes until maintainers inspect the sanitized corrupt DB bundle and validate a native runtime harness for the reported race.

## Solution Assessment
