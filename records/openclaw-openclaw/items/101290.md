## Summary

Keep open: current main and the latest release still expose shared-state SQLite openers that configure WAL/checkpoint maintenance from CLI-adjacent health/status paths, while the live issue remains an unresolved P0 data-corruption report requiring maintainer direction rather than cleanup closure.

## What This Changes

The issue reports that routine CLI health/status/stability invocations can mutate or checkpoint the live shared SQLite state DB while the gateway is running, leading to corruption under write load.

## Best Possible Solution

Make health/status/stability prefer running-gateway RPC and ensure any CLI fallback file access while the gateway owns the state DB is read-only and no-maintenance, with a maintainer-approved single-writer or lease model for repair paths.

Question: Should OpenClaw make shared-state access RPC-first/no-maintenance for CLI health surfaces, enforce a stricter gateway single-writer lease, or require forensic harness proof before choosing the DB ownership policy?

Rationale: The current source path confirms mutable CLI-side shared DB open/checkpoint behavior, but the permanent fix changes ownership boundaries for gateway observability, doctor migrations, plugin-state probes, and operator recovery.

Likely owner: steipete

Owner confidence: high

Options:

- **RPC-first plus no-maintenance CLI (recommended):** Status, health, and stability should ask the running gateway first, and fallback file opens while the gateway is active should be read-only with no journal or checkpoint pragmas.
- **Single-writer gateway lease:** The gateway should own the shared state DB write and maintenance lease, with non-gateway processes failing closed or routing through gateway APIs for writes and maintenance.
- **Forensic harness first:** Pause implementation until the reporter's corrupt DB bundle and a native runtime harness confirm the exact helper/runtime interaction under load.

## Reproduction Assessment

Source-reproducible, but not live-reproduced: current main still exposes mutable shared-state DB open/checkpoint paths from CLI/status/probe surfaces, while the corruption race itself is supported by reporter forensics rather than a deterministic throwaway repro.

## Solution Assessment

Unclear as a final fix: RPC-first/no-maintenance matches the source boundary and reporter preference, but maintainers should decide whether a gateway single-writer lease is also required before implementation.
