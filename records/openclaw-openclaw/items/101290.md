## Summary

Keep open: current main and latest release still route shared state DB opens through normal WAL/checkpointing and schema/migration-capable paths, while the reported data-loss failure needs a maintainer-owned DB access contract rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to prevent CLI health/status/stability startup paths from mutating or checkpointing the shared SQLite state DB while a gateway is running.

## Best Possible Solution

Define a gateway-owned shared DB access contract: health/status/stability prefer RPC while the gateway is running, file fallbacks are read-only with no WAL maintenance or migrations, and malformed DBs are preserved or quarantined with focused stress proof.

Options:

- **RPC-first, no-maintenance CLI (recommended):** Make health/status/stability prefer the running gateway and allow only read-only, no-checkpoint, no-migration file access while a gateway lease is active.
- **Single-writer lease first:** Have the gateway own write and WAL-maintenance access through an explicit lease, with other processes refusing writer-style shared DB opens while it is held.
- **Recovery-first quarantine:** Add malformed openclaw.sqlite preservation/quarantine before prevention work, improving recovery while leaving the CLI/gateway maintenance race as follow-up.
