## Summary

Keep open: current main has moved some health/stability paths to Gateway RPC, but local `gateway status` still reaches installed-plugin reads through the shared state DB opener that configures WAL and checkpoint maintenance, so the reported live-gateway SQLite ownership/data-corruption problem is not fully solved.

## What This Changes

Ensure CLI health/status/stability checks cannot mutate or corrupt the live shared SQLite state database while a gateway is running.

## Best Possible Solution

Make running-gateway health/status/stability paths RPC-first and ensure any CLI file open while the gateway owns the state DB is read-only with no `journal_mode`, `wal_checkpoint`, or doctor migrations; consider a gateway/shared-state lease for single-writer enforcement.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw solve this by making CLI diagnostics strictly RPC-first/no-maintenance when a gateway owns the shared state DB, or by adding a broader single-writer lease for all non-gateway openers?

Rationale: Both paths affect shared SQLite ownership, CLI observability, doctor migrations, and recovery behavior, so automation should not choose the permanent product boundary without maintainer intent.

Likely owner: steipete

Owner reason: Broad runtime-state SQLite ownership traces to PR #78595 and the decision is an architecture/product boundary rather than a local line fix.

Owner confidence: medium

Options:

- **RPC-first diagnostics with no-maintenance fallback (recommended):** Prefer Gateway RPC for status/health/stability and make any direct CLI fallback read-only with no WAL or migration side effects while a gateway is active.
- **Gateway-owned single-writer lease:** Add a broader lease/sentinel so non-gateway processes refuse read-write state DB access or WAL maintenance while the gateway owns the store.
- **Wait for deterministic live repro:** Keep current opener behavior and request a runtime-specific harness first, accepting ongoing production corruption risk until the race is reproduced.

## Reproduction Assessment

No deterministic live reproduction was established here; the report has strong forensic evidence and current source shows a remaining CLI status path that can open the shared DB through normal WAL maintenance while the gateway is running.

## Solution Assessment

The reporter's RPC-first/no-maintenance direction is the best-supported starting point, with a broader single-writer lease as the maintainer-level choice for closing the whole class.
