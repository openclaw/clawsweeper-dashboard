## Summary

Keep open: current main still has shared-state SQLite open paths that configure WAL/checkpoint maintenance from non-gateway CLI/status surfaces, and the issue has a fresh reporter follow-up plus protected P0/data-loss triage rather than a merged fix or canonical replacement.

## What This Changes

The issue reports that routine CLI health-check commands can open and mutate the shared SQLite state database while a gateway is running, with observed state DB corruption under macOS load.

## Best Possible Solution

Define a gateway-owned shared-state DB access contract: health/status/stability should prefer RPC while the gateway is running, file fallbacks should be read-only with no WAL maintenance or migrations under an active gateway owner, and malformed DBs should be preserved or quarantined before recovery.

Options:

- **RPC-first, no-maintenance CLI (recommended):** Make health/status/stability use the running gateway when available and allow only read-only, no-checkpoint, no-migration file access while a gateway owner is active.
- **Single-writer lease:** Have the gateway own write and WAL-maintenance access through an explicit lease, with every other process refusing writer-style shared-state DB opens while it is held.
- **Recovery first:** Land preserve/quarantine/fresh-state recovery for malformed openclaw.sqlite first, then separately address concurrent CLI/gateway maintenance prevention.
