## Summary

Keep open: current main and v2026.6.11 still have shared-state SQLite open paths that run normal WAL maintenance and can be reached from CLI/gateway diagnostic paths, while the related merged WAL/fullfsync and startup-migration work does not settle the live-gateway DB ownership bug.

## What This Changes

The issue reports repeated shared SQLite state corruption after routine CLI health/status/stability probes ran while a gateway was writing the same database.

## Best Possible Solution

Define a gateway-owned shared DB access contract: CLI health/status/stability should prefer RPC to the running gateway, any file fallback should be read-only with no WAL maintenance or migrations while the gateway owns the store, and malformed DBs should be preserved or quarantined with stress proof on macOS and Linux.
