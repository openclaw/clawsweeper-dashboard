## Summary

Keep open: current main and v2026.6.11 still expose shared state DB openers that configure WAL maintenance and diagnostic write/checkpoint paths outside a gateway-owned policy, while the reporter supplied strong production forensics but no deterministic throwaway repro yet.

## What This Changes

The issue asks OpenClaw to stop routine CLI health/status/stability startup paths from mutating or checkpointing the live shared SQLite state DB while a gateway is running.

## Best Possible Solution

Make health/status/stability prefer running-gateway RPC and ensure any fallback state access while the gateway owns the DB is read-only and no-maintenance, with an explicit maintainer-approved lease or maintenance mode for doctor and repair paths.

Rationale: Source confirms mutable CLI-side DB open/checkpoint paths, but the durable fix changes ownership across gateway RPC observability, doctor migrations, plugin-state probes, operator recovery, and upgrade behavior.

Likely owner: steipete

Owner confidence: high

Options:

- **RPC-first plus no-maintenance fallback (recommended):** Status, health, and stability use the running gateway first, and file fallback while a gateway owns the DB is read-only with no journal or checkpoint pragmas.
- **Gateway single-writer lease:** The gateway owns the shared DB write and maintenance lease, and non-gateway processes fail closed or route through gateway APIs for writes and maintenance.
- **Forensic harness first:** Pause implementation until the reporter's bundle or a native runtime stress harness confirms the exact helper/runtime interaction before selecting the policy.

## Reproduction Assessment

No high-confidence deterministic live repro is available yet. Source inspection does show the unsafe ownership path: current main still has shared DB openers that configure WAL maintenance and diagnostic probe writes/checkpoints outside a gateway-owned lease.

## Solution Assessment

Unclear until maintainers choose the DB ownership policy. RPC-first/no-maintenance is the narrowest likely fix for the reported commands, but a single-writer lease may be the better class-level repair.
