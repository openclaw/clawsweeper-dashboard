## Summary

Keep open: current main still has shared SQLite opener/checkpoint paths and plugin-state diagnostic writes, while the merged related PRs only cover adjacent WAL durability, startup migration, and handle-lifecycle work rather than the CLI/live-gateway ownership bug.

## What This Changes

The issue reports that routine CLI health/status/stability commands can open and mutate the shared SQLite state database while a gateway is running, plausibly corrupting live state under concurrent write load.

## Best Possible Solution

Make health/status/stability prefer running-gateway RPC and guarantee any fallback file access while a gateway owns the state DB is read-only and no-maintenance, with a maintainer-approved lease or maintenance-mode policy for doctor/repair paths.

Rationale: Source confirms mutable/checkpointing shared-state open paths remain, but the durable fix changes product ownership between gateway observability, doctor migrations, plugin-state diagnostics, and operator recovery.

Owner confidence: high

Options:

- **RPC-first plus no-maintenance fallback (recommended):** Status, health, and stability should ask the running gateway first, and fallback file opens while the gateway is active should be read-only with no journal or checkpoint pragmas.
- **Add a single-writer gateway lease:** The gateway should own write and WAL maintenance access to the shared state DB, with non-gateway processes failing closed or using gateway APIs unless an explicit maintenance mode is active.
- **Forensics before direction:** Pause code changes until the reporter's corrupt DB bundle and a native runtime harness prove the exact OpenClaw SQLite interaction.
