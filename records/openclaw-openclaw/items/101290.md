## Summary

Keep open: current main partially narrows the reported health/status path, but shared state/plugin-index openers still use the normal WAL-maintenance SQLite path and the issue’s gateway-owned/no-maintenance database access contract is not implemented.

## What This Changes

The issue reports macOS shared state DB corruption during routine CLI health/status/stability checks against a running gateway and asks for safe read-only/RPC-first access or single-writer ownership.

## Best Possible Solution

Define one gateway-owned shared SQLite access contract: routine CLI health/status/stability use Gateway RPC when live, direct file fallbacks are read-only and no-maintenance, and doctor/migration/quarantine flows are explicit recovery modes.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw solve this by making routine CLI health/status/stability RPC-first with no-maintenance read-only fallbacks, or by adding a stronger gateway-owned single-writer lease for shared state DB access?

Rationale: Both approaches can address the reported data-loss class, but they have different compatibility impact for diagnostics, doctor migrations, recovery, and operator workflows while the gateway is running.

Likely owner: steipete

Owner reason: This person is the strongest shared-state history signal and the issue discussion names the product decision as needing their direction.

Owner confidence: high

Options:

- **RPC-first/no-maintenance CLI (recommended):** Make routine health/status/stability prefer the running gateway and only allow direct file reads that disable WAL maintenance and migrations while the gateway owns the DB.
- **Single-writer gateway lease:** Have the gateway hold an explicit state DB ownership lease and make all other writer or maintenance-capable opens fail closed or route through the gateway.
- **Forensic harness first:** Pause implementation direction until the sanitized bundle or native better-sqlite3 stress harness proves the specific corrupting interaction.

## Reproduction Assessment

No deterministic current-main repro is available, but there is a credible source-level path: shared state/plugin-index readers can still open the DB through WAL maintenance while the gateway owns the same store. The reporter’s production forensics and vanilla SQLite control raise confidence, but a disposable native harness is still missing.

## Solution Assessment

Unclear until the maintainer chooses the ownership model. RPC-first/no-maintenance CLI fallback is the narrowest compatibility-preserving direction, while a gateway-owned single-writer lease is broader and may better eliminate the whole class.
