## Summary

Issue #101290 should stay open because current main still lets CLI/status and diagnostic paths open the shared state SQLite database through the normal WAL-maintained opener, and related merged PRs only harden adjacent WAL or handle-lifecycle cases rather than establishing a no-maintenance/RPC-first boundary while the gateway owns the DB.

## What This Changes

The issue asks OpenClaw to prevent CLI startup preflight, status, health, and stability commands from corrupting a live shared state SQLite database while the gateway is running.

## Best Possible Solution

Make health/status/stability prefer running-gateway RPC and ensure any CLI fallback while the gateway owns the state DB is read-only/no-maintenance, with a maintainer-approved single-writer or offline-maintenance lease for doctor and repair paths.
