## Summary

Keep open: current main and the latest release still allow CLI health/status-style startup paths to open the shared state database through the normal WAL-maintenance opener, and the related reports cover adjacent or overlapping SQLite corruption work rather than this specific live-gateway ownership bug.

## What This Changes

Ensure read-only CLI health/status/stability invocations cannot perform WAL maintenance, migrations, or writes against the shared OpenClaw state SQLite database while the gateway is running.

## Best Possible Solution

Define a gateway-owned shared-state contract: CLI health/status/stability use RPC when the gateway is running, direct file fallback is read-only with no WAL maintenance or migrations under a gateway lease, and malformed DBs are quarantined with focused stress proof.
