## Label Justifications

- `maturity:stable`: The affected Gateway runtime, CLI, and macOS Gateway host surfaces map to M4 Stable entries in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main still has CLI/status paths that can reach the shared state database through the normal WAL/checkpointing opener, and the related SQLite reports are adjacent recovery or durability work rather than a fix for this live-gateway ownership bug.

## What This Changes

The issue reports that health/status/stability CLI startup can open the live shared SQLite state database while the gateway is writing, leading to malformed `openclaw.sqlite` incidents.

## Best Possible Solution

Define a gateway-owned shared DB contract: status/health/stability use RPC when the gateway is running, file fallback is read-only with no WAL maintenance or migrations under a gateway lease, and malformed DBs are quarantined before recovery.

Required: true

Kind: product_direction

Question: Should CLI health/status/stability avoid direct shared-state DB WAL maintenance while a gateway is running, and should OpenClaw enforce that through RPC-first/no-maintenance file fallback, a single-writer lease, or recovery-only mitigation?

Rationale: The source boundary is clear, but the fix changes CLI observability, doctor migrations, gateway ownership, and data-recovery semantics for a persisted shared store.

Likely owner: steipete

Owner reason: The shared SQLite state database introduction is the strongest ownership signal for choosing the DB ownership and recovery contract.

Owner confidence: high

Options:

- **RPC-first/no-maintenance CLI (recommended):** Make health/status/stability prefer the running gateway and allow only read-only, no-checkpoint, no-migration file access while a gateway lease is active.
- **Single-writer lease first:** Have the gateway own write and WAL-maintenance access through an explicit lease, with other processes refusing writer-style shared DB opens while it is held.
- **Recovery-first only:** Add quarantine and recovery for malformed `openclaw.sqlite` first while leaving prevention of concurrent CLI/gateway maintenance as follow-up work.

## Reproduction Assessment

No deterministic current-main live reproduction was established; source inspection confirms the relevant status/startup paths can still reach the shared DB opener with WAL/checkpoint and migration-capable behavior while a gateway owns the store.

## Solution Assessment

Unclear as an automated fix; RPC-first/no-maintenance CLI appears safest, but maintainers must choose the DB ownership and recovery contract before implementation.
