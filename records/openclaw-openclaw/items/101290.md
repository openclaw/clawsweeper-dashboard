## Summary

Keep open: current main and the latest stable release still allow CLI/startup paths to open the shared state database with WAL pragmas, migrations, and checkpoints, so the reported live-gateway ownership bug is not fixed by adjacent SQLite durability work.

## What This Changes

The issue asks OpenClaw to stop routine CLI health/status/stability invocations from mutating or corrupting the live shared SQLite state database while the gateway is running.

## Best Possible Solution

Make the running gateway own shared-state writes and WAL maintenance, route health/status/stability through Gateway RPC, and require explicit lease-aware maintenance mode for doctor or repair paths that must mutate state.

- **Forensics before implementation:** Pause code changes until the reporter's corrupt DB bundle and a native OpenClaw SQLite harness confirm the exact bundled-runtime failure mode.
