## Summary

Keep open: current main and v2026.6.11 still have mutable shared-state SQLite open/checkpoint paths from CLI startup, plugin-state probe, and state-migration preflight surfaces, so the reported live-gateway corruption class is not implemented away.

## What This Changes

The issue reports that routine CLI health/status/stability invocations can touch and corrupt the live shared OpenClaw SQLite state DB while a gateway is running.

## Best Possible Solution

Make health/status/stability prefer running-gateway RPC and ensure any CLI fallback while a gateway owns the DB is read-only and no-maintenance, with a maintainer-approved lease or maintenance-mode policy for repair paths.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw fix this as RPC-first/no-maintenance CLI access, a stricter single-writer shared-state DB lease, or a staged combination of both?

Rationale: The source path is clear, but the durable fix changes ownership across gateway RPC, CLI recovery, doctor migrations, plugin-state probes, and operator repair behavior.

Likely owner: steipete

Owner reason: The decision cuts across the DB-first runtime-state architecture introduced in PR https://github.com/openclaw/openclaw/pull/78595 and current gateway/CLI ownership boundaries.

Owner confidence: high

Options:

- **RPC-first plus no-maintenance CLI (recommended):** Status, health, and stability should ask the running gateway first, and fallback file opens while the gateway is active should avoid journal, checkpoint, and migration side effects.
- **Single-writer gateway lease:** The gateway should own shared-state write and maintenance access, with non-gateway processes failing closed or routing through explicit gateway/maintenance APIs.
- **Forensic harness first:** Pause implementation until the reporter's preserved DB bundle and a native runtime harness confirm the exact helper/runtime interaction.

## Reproduction Assessment

Source-reproducible, but not live-reproduced: current main still exposes mutable shared-state DB open/checkpoint paths from CLI/status/probe surfaces, while the actual corruption race depends on reporter forensics rather than a deterministic throwaway run.

## Solution Assessment

No final fix is selected yet; RPC-first/no-maintenance is the narrowest immediate safety improvement, but maintainers should decide whether a broader gateway single-writer lease is also required.
