## Summary

Keep open: current main and v2026.6.11 still let CLI/status paths open the shared state DB through the normal WAL/checkpointing opener, and related issues/PRs cover adjacent recovery, session-lock, or macOS durability work rather than this live-gateway ownership bug.

## What This Changes

Reported bug where routine CLI health/status/stability invocations can touch the live shared SQLite state DB while the gateway is writing, leading to malformed `openclaw.sqlite` and data loss.

## Best Possible Solution

Define a gateway-owned shared DB access contract: health/status/stability use RPC when the gateway is running, file fallbacks are read-only with no WAL maintenance or migrations, and malformed DBs are preserved/quarantined with focused regression and live stress proof.

- **Recovery-first only:** Add quarantine/fresh-state recovery for malformed `openclaw.sqlite` first, while leaving prevention of concurrent CLI/gateway maintenance as separate follow-up work.
