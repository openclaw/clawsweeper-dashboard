## Summary

Keep open: current main and v2026.6.11 still contain the shared state opener/WAL maintenance path, and gateway status can read installed-plugin records from the managed service state DB while a gateway is running. The report is serious and source-plausible, but the prevention and recovery shape needs maintainer direction plus live or forensic proof before repair work should start.

## What This Changes

The issue reports possible live state DB corruption triggered by CLI health/status startup preflight while a gateway is actively writing the shared SQLite store.

## Best Possible Solution

Define a gateway-owned shared DB access contract: health/status/stability prefer RPC while the gateway is running, any file fallback is read-only with no WAL maintenance or migrations, and malformed DBs are preserved or quarantined with focused regression and live stress proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw make the running gateway the sole owner of shared state DB write/WAL-maintenance access, and should CLI status/health/stability use RPC-first read-only behavior while that owner is active?

Rationale: The source boundary is clear enough to keep the issue open, but the fix changes CLI observability, doctor migration timing, gateway ownership, and recovery behavior for a persisted data-loss class store.

Likely owner: steipete

Owner reason: The shared SQLite state DB introduction is the strongest history signal for the gateway/CLI ownership contract decision.

Owner confidence: high

Options:

- **RPC-first/no-maintenance CLI (recommended):** Make status/health/stability prefer Gateway RPC and allow only read-only, no-checkpoint, no-migration file inspection while a gateway ownership signal is active.
- **Single-writer lease first:** Add an explicit gateway lease so non-gateway processes refuse writer-style shared DB opens before broader CLI behavior is refactored.
- **Recovery-first hardening:** Implement malformed DB detection, preservation, and quarantine first while tracking prevention as a separate follow-up.

## Solution Assessment

Unclear as an automated fix: RPC-first/no-maintenance CLI looks like the best prevention direction, but the permanent solution needs a maintainer-approved ownership and recovery contract rather than a one-line checkpoint change.
