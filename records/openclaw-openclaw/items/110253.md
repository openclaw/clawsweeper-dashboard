## Summary

Keep this PR open for a benchmark-contract correction: the Windows CPU end sample occurs after readiness, so work performed while the synchronous CIM query starts can be attributed to startup CPU and can produce false hot-CPU gate results. Likely related people: the current benchmark-area owner could not be established from the available read-only inspection.

## What This Changes

The PR adds Windows CIM-based process-tree CPU and RSS collection to the gateway startup benchmark, while moving Windows sampling outside the elapsed-startup timer.

## Best Possible Solution

Preserve a CPU measurement that is anchored to the gateway’s ready boundary—prefer a child-side CPU snapshot emitted with the ready signal; otherwise leave Windows CPU gating unavailable rather than report a misleading startup value.
