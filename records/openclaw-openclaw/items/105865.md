- **[P1] Scrub ambient credentials before enabling worker exec:** `src/worker/worker.runtime.ts:151`
  - body: The worker advertises a zero-standing-credentials boundary but enables `exec` and `process` while their subprocesses inherit the worker's ambient environment. A launcher carrying `OPENAI_API_KEY`, `GITHUB_TOKEN`, `SSH_AUTH_SOCK`, or similar values therefore lets the model read or use those secrets and return them over transcript/live-event RPCs; enforce a scrubbed allowlist in the worker or pass an explicit safe environment to every local shell tool.
  - confidence: 0.99
- **[P2] Reserve stdout for the worker result protocol:** `src/cli/command-catalog.ts:323`
  - body: `runWorkerCommand` emits the orchestrator's machine-readable result on stdout, but this command policy does not claim protocol stdout. Startup, tool, or agent diagnostics can therefore be mixed into the JSON response; set the worker command's protocol-stdout policy like the existing node-worker path.
  - confidence: 0.96
- **[P2] Validate workspaceDir as a path, not an identifier:** `src/worker/launch-descriptor.ts:126`
  - body: Applying the worker identifier limit to `workspaceDir` rejects valid absolute checkouts in deeply nested worktree or temporary paths before the later filesystem validation runs. Give paths their own bounded string check and retain the absolute-path, existence, and realpath protections.
  - confidence: 0.97
