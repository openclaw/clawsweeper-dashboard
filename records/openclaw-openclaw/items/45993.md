## Summary

Keep open: current main and v2026.6.11 still lack same-product cross-platform `migrate export/import`; the existing `migrate` surface imports from other agent systems, `backup` is create/verify only, and the related implementation work is closed, unmerged, partial, or still risky.

## What This Changes

Request adds `openclaw migrate export/import` for cross-platform OpenClaw workspace migration with selective export, path adaptation, explicit secret/env handling, memory merge policy, and dependency checks.

## Best Possible Solution

Keep this as the canonical cross-platform OpenClaw migration tracker until maintainers choose a safe first-party archive/export/import contract coordinated with the existing provider-based `migrate` and local backup surfaces.

Owner confidence: medium

Options:

- **Design Minimal Core Migration Contract (recommended):** Define a preview-first first-party export/import or backup-restore contract with safe extraction, explicit secret/session policy, path remapping, conflict handling, rollback, and focused tests before implementation.
- **Keep Restore User-Driven:** Enhance `backup create` with safer platform-targeted output, conversion, verification, and docs while avoiding automated archive writes into live state.
- **Route Most Scope To Plugins:** Keep core to backup verification and plugin/API seams while recommending ClawHub/plugin solutions for sync, cloud backup, and optional restore workflows unless a missing core API is proven.
