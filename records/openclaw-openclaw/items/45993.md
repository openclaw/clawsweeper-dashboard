## Summary

Keep open: current main and the latest release still provide provider-based imports plus local backup create/verify, not the requested same-product cross-platform export/import workflow, and the remaining work needs maintainer product and security scoping.

## What This Changes

Add cross-platform `openclaw migrate export` and `openclaw migrate import` commands for selective OpenClaw workspace, config, memory, skills, and secret-aware machine migration.

## Best Possible Solution

Define a preview-first, trust-scoped migration/restore contract that coordinates `migrate` and `backup`, with explicit secret/session policy, platform path mapping, rollback/conflict handling, and security tests before implementation.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw core own automated same-product archive import/restore, or should core stay limited to backup export, platform conversion, verification, and manual restore guidance?

Rationale: This choice determines CLI namespace, archive trust boundaries, secret/session portability, destructive write policy, and whether the open implementation candidates should proceed in core or be reshaped around backup/manual restore.

Likely owner: gumadeiras

Owner reason: They have backup safety history and already raised the restore security-boundary concern in the prior implementation discussion.

Owner confidence: high

Options:

- **Scope a minimal native import contract (recommended):** Define a preview-first core export/import lifecycle with canonical target validation, secret/session policy, rollback/conflict handling, and focused security tests before accepting implementation work.
- **Prefer backup export or convert plus manual restore:** Keep automated restore out of core for now and improve backup output, platform targeting, verification, and docs so users can migrate safely without a destructive importer.
- **Route optional extras outside core:** Keep core to missing APIs and let plugins, skills, or ClawHub packages own optional cloud, scheduled, encrypted, or workspace-specific migration flows.
