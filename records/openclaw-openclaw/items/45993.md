## Summary

Keep open: current main and v2026.6.11 still provide provider-based imports plus local backup create/verify, not the requested OpenClaw-to-OpenClaw cross-platform export/import workflow. An open fork PR still claims to close this issue, but it is conflicting and the same-repo attempt was closed unmerged after maintainer product/security concerns, so this issue remains useful as the canonical decision point.

## What This Changes

Add `openclaw migrate export` and `openclaw migrate import` for selective, cross-platform migration of OpenClaw config, credentials, workspace, memory, sessions, and related state.

## Best Possible Solution

Keep this as the canonical cross-platform OpenClaw-to-OpenClaw migration tracker until maintainers choose a preview-first core export/import or backup-convert/manual-restore contract with archive validation, path remapping, secret/session policy, rollback, and docs.
