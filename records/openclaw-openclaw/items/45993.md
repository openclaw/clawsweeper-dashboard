## Summary

Keep open: current main and v2026.6.11 still provide provider-based imports plus local backup create/verify, not the requested same-product cross-platform export/import workflow. There is an open linked implementation candidate, but the remaining product and security scope is still unsettled.

## What This Changes

Request to add cross-platform OpenClaw-to-OpenClaw `migrate export` and `migrate import` commands with selective state export, path remapping, secret handling, config merging, and dependency checks.

## Best Possible Solution

Define a preview-first core recovery contract that either adds a tightly scoped import/restore flow with archive validation, path remapping, secret/session policy, rollback, and docs, or explicitly chooses safer backup conversion plus manual restore guidance.
