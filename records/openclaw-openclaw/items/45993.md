## Summary

Keep open: current main and the latest release still provide provider-based imports plus local backup create/verify, not the requested OpenClaw-to-OpenClaw cross-platform export/import workflow, and the remaining work needs product and security direction before implementation.

## What This Changes

The issue requests `openclaw migrate export` and `openclaw migrate import` commands for portable cross-platform migration of config, workspace files, skills, memory, sessions, paths, and secrets.

## Best Possible Solution

Choose a conservative core migration contract first: either extend backup with platform-targeted export/convert plus clearer user-driven restore, or approve a preview-first import path with strict archive validation, secret policy, rollback, docs, and security tests.
