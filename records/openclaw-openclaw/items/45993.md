## Summary

Keep open: current main still has provider-based imports and local backup create/verify, not the requested OpenClaw-to-OpenClaw cross-platform export/import workflow. The issue is useful, but it needs maintainer product and security scoping before implementation.

## What This Changes

The issue requests `openclaw migrate export` and `openclaw migrate import` commands for selective cross-platform migration of config, workspace, skills, memory, sessions, paths, dependencies, and secret handling.

## Best Possible Solution

Keep this as the canonical cross-platform OpenClaw-to-OpenClaw migration tracker until maintainers define either a preview-first core export/import contract or a conservative backup-convert plus manual-restore workflow with archive validation, path remapping, secret/session policy, rollback, and docs.
