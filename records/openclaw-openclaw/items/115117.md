## Summary

Keep this issue open. The supplied trace identifies a shared payload-classification gap: a synthesized `missing_tool_result` warning can lack the non-terminal marker, so channel final-reply gates may treat it as terminal and suppress the subsequent assistant answer. The open Mattermost PR addresses the already-marked warning flow, but does not establish coverage for this unmarked core branch.

## What This Changes

Classify synthesized missing-tool-result warnings as non-terminal so a recoverable tool warning cannot prevent the later assistant reply from reaching Discord or other gated channels.

## System Context

The embedded agent runner converts tool outcomes into outbound reply payloads, which channel plugins use to manage streaming drafts and decide when a final reply has begun. A wrong terminal/non-terminal classification can make a channel suppress the actual assistant response even though the agent run continues.

## Architecture Diagram

flowchart TD
  A[Native tool call] --> B[Embedded agent runner]
  B --> C[Tool warning payload]
  C --> D[Non-terminal classification]
  D --> E[Channel draft and final gate]
  E --> F[Assistant final payload]
  F --> G[Delivered channel reply]

## Best Possible Solution

Make the runner emit one explicit non-terminal classification for every recoverable tool-warning origin, then add ordered warning→real-final regression coverage for the shared payload contract and each channel that gates final delivery.
