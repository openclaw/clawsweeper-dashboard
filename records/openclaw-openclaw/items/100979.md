## What This Changes

The issue reports that Discord queued sends failing during a full network outage remain marked `send_attempt_started` and are moved to failed on reconnect because Discord lacks unknown-send reconciliation.

## Best Possible Solution

Land one canonical fix that keeps provable pre-dispatch network failures replayable while preserving the duplicate-send guard for true unknown-after-send cases; https://github.com/openclaw/openclaw/pull/101024 currently looks like the cleaner shared path if maintainers accept its narrow error boundary.
