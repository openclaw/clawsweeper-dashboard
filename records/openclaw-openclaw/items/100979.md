## Summary

Keep open: current main and v2026.6.11 still retain the `send_attempt_started` marker after pre-result outbound failures, Discord does not expose unknown-send reconciliation, and recovery refuses replay, so the reported full-outage message-loss gap remains.

## What This Changes

Reports that Discord outbound sends attempted during a full network outage are dropped on reconnect because durable recovery sees `send_attempt_started` and Discord cannot reconcile unknown sends.

## Best Possible Solution

Preserve the no-blind-replay guard for genuinely ambiguous post-send states, but make this outage path recoverable through a proof-backed pre-dispatch failure classification or a Discord `reconcileUnknownSend` implementation with regression and live Discord proof.
