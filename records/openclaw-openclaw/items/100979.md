## Summary

Keep open. Current main still has the reported recovery shape: queued sends are marked `send_attempt_started`, generic failure preserves that marker, recovery refuses blind replay without `reconcileUnknownSend`, and the Discord outbound adapter does not declare that reconciliation capability.

## What This Changes

This issue requests that Discord durable outbound messages that fail during a full network outage remain recoverable on reconnect instead of being failed from `send_attempt_started` state without Discord reconciliation.

## Best Possible Solution

Fix the durable delivery lifecycle so provable pre-dispatch/connect-phase failures stay replayable, or add Discord `reconcileUnknownSend` with idempotent message identity; keep the existing duplicate-send guard for true unknown-after-send cases.
