## Summary

This PR remains necessary: current `main` still lets a startup friend reconciliation rejection escape before Reef activates, while the already-merged periodic-loop repair only contains later reconcile failures. The new lifecycle boundary preserves the required reconcile → activation → inbox ordering and supplies focused live-run proof, so this is ready for normal Reef-owner review rather than cleanup or a separate repair job.

## What This Changes

Moves Reef’s startup friend reconciliation into `runReefChannelLifecycle`, adds an `onReady` activation hook, and tests that startup failures are contained without changing successful startup ordering.

## Best Possible Solution

Land the focused lifecycle change after normal Reef-owner review, retaining the shared non-fatal reconcile policy and the explicit reconciliation-before-activation ordering tests.
