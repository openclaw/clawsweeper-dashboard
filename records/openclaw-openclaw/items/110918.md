## Summary

This PR remains necessary: current main still performs startup reconciliation as a fail-fast step, while the prior merged Reef recovery work addressed the periodic path. The patch is technically coherent and its live 429 relay transcript supports the intended recovery, but allowing startup with persisted peer keys is an intentional availability-versus-delivery-staleness policy that needs Reef-owner acceptance before merge.

## What This Changes

The branch routes Reef startup reconciliation through the lifecycle, continues startup for classified retryable relay failures, normalizes transient transport failures, and adds lifecycle and transport tests.

## Best Possible Solution

Keep one lifecycle-owned reconciliation policy and merge it only after the Reef owner explicitly confirms that retryable startup failures should activate using persisted peer keys while the periodic loop retries.
