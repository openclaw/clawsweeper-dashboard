## Summary

Keep this issue open for targeted Control UI and gateway-auth review. ## What This Changes

Fix Control UI rendering of local assistant media in password-authenticated gateways when the browser fetch to the assistant-media endpoint lacks usable authentication.

## System Context

Control UI renders assistant `MEDIA:` references by checking permitted local roots and then requesting metadata or bytes from the Gateway's assistant-media endpoint. The gateway authorization result determines whether the UI can render or download the referenced local file.

## Architecture Diagram

flowchart LR

  C --> D[Authenticated assistant-media request]
  D --> E[Gateway media authorization]
  E --> F[File metadata or media bytes]
  F --> G[Attachment preview or download]

## Best Possible Solution

Trace the existing Control UI login, WebSocket, and assistant-media authorization flows, then reuse the narrowest already-established browser credential path; add a password-mode regression test proving both metadata and media retrieval without introducing a second secret-distribution channel.
