## Summary

Keep this draft open for human ownership review, not merge. The durable-before-cleanup concern is credible and the PR has focused failure evidence, but its new sweep rule derives retirement from a successor row that is not a durable ownership fence; that can discard an older run while its completion delivery is still pending and can lose the retry trigger if the successor disappears.

## What This Changes

The branch moves superseded subagent-run persistence ahead of transcript and attachment deletion, restores the in-memory entry after a write failure, and makes later sweeps retry terminal superseded runs.

## System Context

The subagent registry tracks active and terminal child runs in memory and in the shared SQLite state database. Lifecycle completion, restart restoration, sweep maintenance, completion delivery, and artifact cleanup all consume that registry, so retirement must preserve their shared ownership and delivery invariants.

## Best Possible Solution

Define and implement one durable retirement ownership model—either conditional row-level operations or an enforced single registry writer—with an explicit monotonic session generation/fence and completion delivery lifecycle independent of artifact cleanup; then add restart, concurrent-writer, successor-removal, distinct-owner, orphan-recovery, and pending-delivery coverage.
