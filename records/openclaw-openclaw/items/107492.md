## Summary

The reported hotspot does not match current main: OpenClaw only probes candidate CA bundle paths while preparing Node startup environment, and Node loads `NODE_EXTRA_CA_CERTS` when the process launches rather than for each HTTPS connection. No OpenClaw certificate parsing or request-time hook exists in this path. citeturn5view0turn17search0turn9search0

## What This Changes

Cache extra CA certificate parsing at process startup to avoid alleged synchronous filesystem and parsing work on every HTTPS connection.

## Best Possible Solution

Keep the startup path unchanged; if measurable HTTPS latency remains, open a new report with a current-main profile showing repeated filesystem calls or certificate parsing stacks attributable to OpenClaw.
