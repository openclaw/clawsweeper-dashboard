## Summary

The reported per-connection certificate parsing does not match current main: OpenClaw only resolves an accessible CA bundle path, while Node loads `NODE_EXTRA_CA_CERTS` when the process starts rather than for each HTTPS connection. 

## What This Changes

Avoid alleged repeated synchronous parsing of extra CA certificates on each HTTPS connection by loading and caching certificates during startup.

## Best Possible Solution

Keep the current startup-only path resolution unchanged; if latency is observed, open a new report with a current-main profile or stack trace identifying the actual repeated filesystem or TLS work.
