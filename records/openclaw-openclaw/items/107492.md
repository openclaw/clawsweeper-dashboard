## Summary

Keep open only for a bounded profiling decision. Current main does not parse CA certificates in this module or on each connection: it synchronously checks a short list of bundle paths during CA auto-discovery, while Node documents that `NODE_EXTRA_CA_CERTS` is loaded when the process launches. The remaining uncertainty is whether the reported workload exposes some different repeated synchronous TLS path. Likely related people: steipete, GodsBoy, and alkor2000, based on the merged history of this bootstrap behavior. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/bootstrap/node-extra-ca-certs.ts))

## What This Changes

Investigate whether extra CA certificates are synchronously reparsed for every HTTPS connection and cache them during startup if necessary.

## Best Possible Solution

Capture a bounded current-main profile of parallel HTTPS connections with filesystem and stack attribution; change OpenClaw only if repeated synchronous work appears in an OpenClaw-owned frame, otherwise close the report as unsupported.
