## Summary

Current main does not contain the reported per-connection certificate parsing path: the bootstrap helper only probes fixed CA-bundle paths and returns a filename for startup environment configuration, while its tests cover startup detection rather than HTTPS request handling.

## What This Changes

Avoid repeatedly reading and parsing extra CA certificates by resolving them once during process startup and reusing the result.

## Best Possible Solution

Keep the current startup-only path resolution; if synchronous CA reads are observed in a real workload, open a new report with a current-version CPU profile or stack trace identifying the actual reader and request call path.

## Reproduction Assessment

No. Current main has no certificate-content read, parser, or per-connection call path in the named bootstrap helper; it only performs bounded path-access probes during startup environment resolution.

## Solution Assessment

No. Caching parsed certificates in node-startup-env.ts would introduce a second certificate-loading mechanism for behavior that current OpenClaw does not implement; profiling should first identify any real repeated reader.
