## Summary

This issue remains necessary: current main still interprets `image_0` as a workspace-relative file, and the directly linked candidate fix remains open. WebChat already sends the image natively and separately persists transcript media, so the defect is handling a model-generated prompt identifier rather than a missing media-store copy.

## What This Changes

Map WebChat image attachments so the image tool receives a usable reference instead of treating `image_0` as a nonexistent workspace file.

## Best Possible Solution

Keep native prompt images as the canonical model input, reject only well-defined generated prompt-image identifiers before filesystem resolution, and add regression tests for both the guidance response and unchanged valid path behavior.

## Reproduction Assessment

Yes. The reporter observed the matching error on v2026.6.11, though this review did not perform a live run.

## Solution Assessment

No, mapping model-generated indices directly to transcript storage is not the best solution because it would create an unstable cross-layer registry. The narrower fix is to recognize defined prompt-image identifiers at the image-tool boundary and preserve native prompt-image handling.
