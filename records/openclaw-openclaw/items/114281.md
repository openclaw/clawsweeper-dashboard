## What This Changes

This PR changes Workboard so aggregate decomposition records provenance without blocking execution by default, while adding an explicit hard-dependency mode, diagnostics, legacy SQLite repair, gateway/tools APIs, tests, and documentation.

## System Context

Workboard turns agent decomposition requests into parent and child cards stored in plugin-owned SQLite state. Card-link metadata feeds lifecycle checks, claiming/completion, diagnostics, the web UI event log, and Doctor migrations for existing installations.

## Best Possible Solution

Preserve the established behavior for omitted-mode existing data and callers unless a maintainer explicitly approves an upgrade policy, and restrict Doctor repair to records with durable, record-level evidence that the links came from legacy decomposition rather than an intentional hard dependency.
