## Summary

Keep open: current main and the latest release still lack a supported `cron add --id` creation path, and the same-repo custom-ID implementation PRs have all closed unmerged. The remaining work is a public cron CLI/Gateway/API contract decision, not a stale or already-implemented request.

## Best Possible Solution

Land a maintainer-approved current-main implementation that threads optional safe create IDs through CLI, Gateway protocol, cron normalization/service collision handling, generated clients, docs, and agent cron tool policy while preserving UUID defaults.
