## What This Changes

The issue requests an optional `openclaw cron add --id` flag so users can create cron jobs with stable, human-readable IDs.

## Best Possible Solution

Land a maintainer-approved current-main implementation that threads optional safe IDs through the CLI, Gateway protocol, service create path, generated clients, agent-tool cron creation, docs, and focused tests while preserving UUID defaults and rejecting collisions.
