## Summary

Keep open: current main and v2026.6.11 still lack a supported create-time custom cron job ID path, and the remaining work is an additive public cron CLI/Gateway contract decision rather than cleanup-closeable stale work.

## What This Changes

The issue requests an optional `openclaw cron add --id <id>` path so operators can create stable human-readable cron job IDs instead of always receiving generated UUIDs.

## Best Possible Solution

Land a maintainer-approved additive cron create contract that preserves default UUID generation while threading validated optional IDs through CLI, Gateway protocol, service creation, generated clients, docs, and focused tests.
