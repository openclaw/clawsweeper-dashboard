## Summary

Keep open: current main and v2026.6.11 still lack a supported create-time custom cron job ID path, and the only open implementation candidate is an external fork PR that needs maintainer adoption or replacement.

## What This Changes

The issue requests an optional `openclaw cron add --id <id>` flag so cron jobs can be created with stable human-readable IDs instead of auto-generated UUIDs.

## Best Possible Solution

Land or replace the open fork implementation with a maintainer-approved current-main PR that adds a safe optional ID through cron create surfaces while preserving UUID defaults.
