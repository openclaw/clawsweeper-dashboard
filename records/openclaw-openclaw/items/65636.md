## Summary

Keep open: current main and v2026.6.11 still do not expose a supported `cron add --id` create path, and the open linked implementation candidate is unmerged and conflicting, so the user-visible request still needs maintainer product/API review.

## What This Changes

The issue requests an optional `openclaw cron add --id <id>` flag so operators can create cron jobs with stable human-readable IDs instead of generated UUIDs.

## Best Possible Solution

Land a maintainer-approved current-main implementation, either by repairing the linked PR or by sponsoring a narrow replacement, that threads optional safe IDs through CLI, Gateway protocol, service creation, docs, and agent-tool schema while preserving UUID defaults.
