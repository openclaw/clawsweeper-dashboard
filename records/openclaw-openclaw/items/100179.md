## What This Changes

The branch decouples Control UI mobile pairing setup-code publication from pending-device refresh and adds an E2E regression that defers `device.pair.list` while the QR appears.

## Best Possible Solution

Land this narrow overlay publish-order fix after normal maintainer review and required checks, keeping setup-code rendering independent from pending-device refresh.

## Reproduction Assessment

Yes. On current main, a mocked Gateway can defer `device.pair.list` while `device.pair.setupCode` resolves; source shows `openDevicePairSetup` waits for both before publishing the non-loading snapshot, and the dialog renders a spinner while `loading && !setup`.

## Solution Assessment

Yes. The overlay is the right layer because it owns both setup-code and pending-count publication, and letting the already-guarded pending refresh publish separately is narrower than changing gateway methods or rendering state.
