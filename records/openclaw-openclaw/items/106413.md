## Summary

The reported edge case is outside the supported date-stamp contract: this private helper receives canonical runtime-generated `YYYY-MM-DD` stamps, where zero is invalid for year, month, or day. The patch does not fix a reachable startup-context bug and weakens the invalid-stamp fallback by allowing zero components to normalize into different dates.

## What This Changes

The PR changes startup-context date parsing to accept zero-valued parsed components and reject only `NaN`.

## Best Possible Solution

Keep the existing guard for the canonical internal stamp path; if arbitrary stamps ever become supported, add full `YYYY-MM-DD` shape and calendar-range validation rather than treating zero components as valid.
