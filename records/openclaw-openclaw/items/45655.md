## Summary

Keep open. Current main partially addressed the old input-modality limitation, but it still has no chat-model output-modality contract for Poe image/video-output models; the supported media path is separate `image_generate`/`video_generate` tooling, so the reported misleading selection/fallback behavior still needs maintainer product direction.

## What This Changes

Request clear handling for Poe media-output models: reject unsupported image/video-output chat models or add runtime/schema support so they do not fail with invalid payloads or fallback silently.

## Best Possible Solution

Define a generic media-output contract: either fail configured chat selection with a clear unsupported-output diagnostic, or represent image/video output through generation-provider capabilities and output-modality metadata with docs and upgrade-safe tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw reject non-text-output models when they are configured as chat/session models, or add first-class output-modality metadata and runtime support for image/video output?

Rationale: Both paths are plausible, but the choice changes public config semantics and provider/tool ownership, so automation should not pick it from source inspection alone.

Likely owner: steipete

Owner reason: The decision crosses provider/model config, docs, and media-generation direction where recent history shows repeated ownership.

Owner confidence: medium

Options:

- **Reject unsupported chat output now (recommended):** Add a clear diagnostic for image/video-output models selected as chat/session models and direct users to `image_generate` or `video_generate` until first-class support exists.
- **Add output-modality support:** Extend config/catalog metadata and runtime/channel rendering so selected models can intentionally produce image/video outputs in session flow.
- **Docs-only clarification:** Document that media generation must use the generation tools while leaving current custom-provider behavior unchanged, accepting continued runtime confusion.

## Solution Assessment
