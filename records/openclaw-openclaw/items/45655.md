## Summary

Keep open. Current main and v2026.6.11 still do not define an output-modality contract for configured chat models; media generation remains routed through separate `image_generate` and `video_generate` provider-tool paths, so the Poe media-output confusion is not fully solved.

## What This Changes

The issue asks OpenClaw to either reject Poe image/video-output chat models with clear diagnostics or add first-class image/video-output model support.

## Best Possible Solution

Define one explicit product contract: reject media-output chat models with clear diagnostics and docs for now, or add output-modality metadata plus generation-provider/channel delivery support as a first-class runtime path.
