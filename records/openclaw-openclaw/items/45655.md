## Summary

Keep open. Current main and the latest release still separate chat-model selection from image/video generation tools, and no configured chat-model output-modality contract exists to reject or support Poe media-output models cleanly.

## What This Changes

The issue asks OpenClaw to either support Poe image/video-output model refs in chat/session runtime or reject them with clear diagnostics instead of malformed requests or fallback confusion.

## Best Possible Solution

Define one explicit media-output contract: reject unsupported chat/session media-output model refs with clear diagnostics and docs, or support them through provider-owned image/video generation capabilities and output-modality metadata.

## Reproduction Assessment

Partially yes. Source inspection shows the structural gap on current main: configured chat models carry input metadata only, while image/video generation is routed through separate tools; the exact live Poe HTTP 400 and Telegram fallback path was not reproduced here.

## Solution Assessment

Unclear. Explicit rejection is a good short-term mitigation, but the best fix depends on maintainer direction for whether media-output model metadata belongs in chat model config/catalogs or only in media-generation provider capabilities.
