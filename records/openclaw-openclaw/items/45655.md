## Summary

Keep open: current main still has no chat/session model output-modality contract for Poe image/video-output models, and the remaining work is a maintainer product/API decision rather than a conservative cleanup close.

## What This Changes

The issue requests explicit rejection, clearer diagnostics, or first-class runtime support for Poe image/video-output models that can be configured or selected but fail or fall back in the text-centric session runtime.

## Best Possible Solution

Adopt a provider-neutral unsupported-output diagnostic for chat/session model selection now, and design any first-class image/video output support later through explicit output-modality metadata plus generation-provider and channel contracts.

- **Design output-modality support:** Extend config/catalog metadata and runtime/channel handling so selected models can intentionally produce image/video outputs in session flow.
- **Clarify docs only:** Document the current tool-driven media path while leaving custom-provider chat selection behavior unchanged.
