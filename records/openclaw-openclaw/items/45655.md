## Summary

Keep open: current main still lacks a chat/session output-modality contract for custom provider models, so the reported Poe image/video-output behavior remains a real provider-routing and UX gap rather than stale or already fixed.

## What This Changes

The issue asks OpenClaw to either clearly reject unsupported Poe media-output models in chat/session runtime or add first-class image/video-output model support.

## Best Possible Solution

Define an explicit output-modality contract: keep chat/session models text-output-only with clear unsupported-media-output diagnostics for selected media-output refs, and route supported generation through image_generate/video_generate unless maintainers choose a broader first-class media-output model API.
