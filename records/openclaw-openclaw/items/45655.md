## Summary

Keep open: current main has fixed part of the input-modality schema story, but it still lacks a chat/session output-modality contract for custom provider models, so Poe image/video-output selections can still be misleading without a maintainer product/API decision.

## What This Changes

The issue requests either first-class support or explicit diagnostics for Poe image/video-output custom provider models that are accepted in configuration but fail or fall back at runtime.

## Best Possible Solution

Define a generic output-modality contract: keep normal chat/session models text-output-only with clear unsupported-media-output diagnostics unless maintainers choose a broader media-output model API that routes through image_generate/video_generate and channel delivery.
