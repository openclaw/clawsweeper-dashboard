## Summary

Keep open. Current main still lacks a chat/session output-modality contract for configured Poe-style media-generation models, while existing image/video generation is handled through separate tool/provider capability paths; this needs maintainer product/API direction rather than conservative cleanup closure.

## What This Changes

The issue asks OpenClaw to either clearly reject Poe image/video-output model refs configured as chat models or support them without invalid payloads or silent fallback.

## Best Possible Solution

Define a generic media-output contract: reject unsupported chat/session media-output refs with clear diagnostics and docs now, and route actual image/video generation through provider-owned image_generate/video_generate capabilities unless maintainers approve broader output-modality support.

- **Track only input-modality fixes separately:** Let the open input-modality work proceed while keeping this issue open for the distinct output-model contract decision.
