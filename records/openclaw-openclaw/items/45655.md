## Summary

Keep open: current main and the latest release still lack a chat-model output-modality contract for Poe image/video-output models, while the supported media-generation path is separate `image_generate` and `video_generate` tooling; the remaining change is a maintainer product/API decision.

## What This Changes

The issue asks OpenClaw to either reject unsupported Poe image/video-output models clearly in chat/session runtime or add first-class media-output model support.

## Best Possible Solution

Adopt a provider-neutral unsupported-output diagnostic for chat/session model selection now, and design any first-class image/video output support later through explicit output-modality metadata plus generation-provider and channel contracts.
