## Summary

Keep open: current main still lacks a chat/session output-modality contract for custom provider models, so Poe image/video-output models can still look like normal chat model refs even though generation is documented through separate media tools.

## What This Changes

Request to clarify or support Poe media-output custom provider models so image/video-output refs either route correctly or fail with clear unsupported-media diagnostics.

## Best Possible Solution

Define an explicit output-modality contract: keep normal chat models text-output only with clear unsupported-media-output diagnostics for selected media-output refs, and route supported generation through provider-backed image_generate and video_generate unless maintainers choose a broader media-output model API.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw reject media-output provider model refs in chat/session runtime with a clear diagnostic, or add first-class output-modality metadata that routes them through media generation?

Rationale: Both choices change public provider/model semantics: diagnostic-first needs a reliable way to identify output-only models, while first-class support requires broader provider, tool, response, and channel contracts.

Likely owner: steipete

Owner reason: The input-modality preservation work and adjacent provider/config history make this the best available owner signal for deciding the next public contract.

Owner confidence: medium

Options:

- **Diagnostic-first contract (recommended):** Treat media-output models as unsupported chat/session models for now, add clear errors and docs, and leave generation on image_generate/video_generate.
- **First-class media-output models:** Add output modality metadata and route image/video-output refs through media generation with channel delivery support.
- **Defer to provider plugins:** Keep core behavior unchanged until a Poe or generic media provider plugin proves the missing API surface.

## Reproduction Assessment

Yes, at source level: current main still has no output-modality field for custom chat models and documents media generation through separate tools. I did not run a live Poe Nano Banana/Veo/Sora repro in this read-only review.

## Solution Assessment

No, a schema-only rejection is not clearly the best fix because current main deliberately accepts wider input metadata. The maintainable path is a maintainer-chosen output-modality contract plus diagnostics, docs, and focused tests.
