## Summary

Keep open: current main still lacks a chat/session output-modality contract for custom provider models, so Poe image/video-output models can look selectable even though media generation is routed through separate image/video tool providers.

## What This Changes

The issue asks OpenClaw to either clearly reject unsupported Poe image/video-output chat models or add first-class media-output routing/support for them.

## Best Possible Solution

Define an explicit output-modality contract: keep normal chat models text-output only with a clear unsupported-media-output diagnostic for selected media-output refs, and route supported generation through provider-backed `image_generate` and `video_generate` capabilities unless maintainers choose a broader first-class media-output model API.
