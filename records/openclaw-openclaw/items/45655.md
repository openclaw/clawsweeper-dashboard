## Summary

Keep open: current main still lacks output-modality metadata or validation for chat/session custom provider models, so Poe image/video-output refs are not clearly supported or clearly rejected. Dedicated image/video generation exists through separate tools, but that does not resolve the reported custom-provider chat model ambiguity.

## What This Changes

Request to either reject unsupported Poe image/video-output chat models with clear diagnostics or add first-class image/video output support to session runtime and model metadata.

## Best Possible Solution

Define the public output-modality contract first: preferably keep chat/session models text-output-only for now, add explicit unsupported media-output diagnostics and docs pointing users to imageGenerationModel/videoGenerationModel, and reserve full session media outputs for a sponsored design.
