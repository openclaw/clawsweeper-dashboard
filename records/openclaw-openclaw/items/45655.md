## Summary

Keep open. Current main and the latest release still lack a configured chat-model output-modality contract: custom provider model rows can carry richer media input metadata, but session runtime model execution remains text-output oriented while image/video generation is routed through separate provider tools and model settings.

## What This Changes

The issue asks OpenClaw to either reject unsupported Poe image/video-output models with clear diagnostics or implement proper media-output routing for those models.

## Best Possible Solution

Define one configured-model media contract: keep chat model selection text-output only with clear unsupported-media diagnostics, and route supported image/video generation through image/video provider contracts unless maintainers explicitly choose first-class media-output chat models.

## Reproduction Assessment

Yes, at source level: current main still has no configured chat-model output-modality contract while media generation runs through separate image/video provider settings. No, for the exact live Poe backend error: that still needs a credentialed Poe/Telegram reproduction.

## Solution Assessment

Unclear. Short-term explicit unsupported-media diagnostics are plausible, but the best maintainable fix needs a maintainer decision on whether output modality belongs in configured model metadata, media-generation provider contracts, or both.
