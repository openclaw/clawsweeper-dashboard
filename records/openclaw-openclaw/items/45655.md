## Summary

Keep open: current main fixed part of the input-modality schema story, but it still has no chat/session output-modality contract for custom provider models, so the Poe image/video-output fallback and unclear-runtime behavior remains a real product/API gap.

## What This Changes

The issue asks OpenClaw to either support Poe image/video-output models in runtime or reject/report them clearly instead of accepting them as normal chat models and failing or falling back later.

## Best Possible Solution

Define a generic output-modality contract: keep chat/session models text-output-only with clear unsupported-media-output diagnostics unless maintainers choose a broader media-output model API that routes through image_generate/video_generate and channel delivery.
