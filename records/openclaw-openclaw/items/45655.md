## Summary

Keep open. Current main and v2026.6.11 still lack a configured chat-model output-modality contract for Poe-style media-output models; media generation is routed through separate image/video provider tools, while chat model execution remains text-output-centric.

## What This Changes

Request clear support or rejection for Poe image/video-output models configured under `models.providers`, including Nano Banana image generation and Veo/Sora video generation fallback behavior.

## Best Possible Solution

Define one configured-model output/runtime contract: keep chat model selection text-output-only with clear unsupported-media diagnostics, and route supported image/video generation through provider capability contracts and docs.

## Reproduction Assessment

Yes, source-level reproduction is strong for the missing output-modality contract and split image/video tool routing. I did not run a live Poe credentialed Telegram reproduction, so the exact HTTP 400 and fallback symptoms remain reporter-provided.

## Solution Assessment

Unclear. Explicit rejection is the best short-term direction, but maintainers need to choose whether output modality belongs in configured model metadata, provider tool contracts, or a Poe-specific media-generation plugin path.
