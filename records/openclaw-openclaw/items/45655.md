## Summary

Keep open: current main still lacks a public output-modality contract or diagnostic for custom provider chat models, so Poe image/video-output refs remain a provider/model semantics decision rather than an implemented fix.

## What This Changes

The issue requests clear rejection or first-class support for Poe image/video-output models configured under `models.providers`.

## Best Possible Solution

Define an explicit output-modality contract: keep chat/session models text-output only with clear unsupported-media-output diagnostics for image/video refs, while routing generation through `image_generate` and `video_generate`, unless maintainers choose first-class media-output model support.
