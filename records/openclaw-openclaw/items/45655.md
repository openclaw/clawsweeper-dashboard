## Summary

Keep open. Current main and v2026.6.11 still have no chat-model output-modality contract for configured Poe-style media-output models; image/video generation is handled through separate tool/provider capability surfaces, so this needs a maintainer product/API decision before implementation.

## What This Changes

The issue requests explicit support or rejection for configured Poe image/video-output model refs that are selectable as chat models but fail or fall back at runtime.

## Best Possible Solution

Define one generic media-output contract: either reject unsupported chat/session media-output refs with clear diagnostics and docs, or route them through provider-owned image/video generation capabilities with explicit output-modality metadata.

## Reproduction Assessment

Partially yes. Source inspection shows the structural gap on current main: configured chat models carry input metadata only while image/video generation uses separate tool model configs; the exact live Poe HTTP 400 and Telegram fallback were not reproduced here.

## Solution Assessment

Unclear. Explicit rejection is a reasonable short-term mitigation, but the best fix depends on maintainer direction for whether media-output metadata belongs in chat model config/catalogs or only in media-generation provider capabilities.
