## Summary

Keep open. Current main and the latest release still lack a configured chat-model output-modality contract for custom Poe-style media-output models; image and video generation exist through separate provider/tool surfaces, while chat model config and runtime selection remain input-centric.

## What This Changes

The issue asks OpenClaw to either support Poe image/video-output models through the runtime or reject them clearly instead of allowing malformed requests or fallback.

## Best Possible Solution

Define one configured-model output/capability contract: keep chat model selection text-output only with clear unsupported-media diagnostics, and route supported image/video generation through image/video provider contracts, docs, and any required schema or doctor migration.

## Reproduction Assessment
