## Summary

Keep open. Current main and v2026.6.11 still lack a chat/session output-modality contract for custom provider models, while media generation is routed through separate image/video tool model settings.

## What This Changes

The issue requests clear rejection or first-class runtime support for Poe image/video-output models that can be configured as chat models but fail or fall back at runtime.

## Best Possible Solution

Define one maintainer-approved media-output contract: either reject unsupported chat/session media-output model refs with clear diagnostics and docs, or support them through provider-owned image/video generation capabilities with explicit output metadata.

## Reproduction Assessment

Partially yes. Source inspection shows the structural gap on current main, but the exact live Poe HTTP 400 and Telegram fallback path was not reproduced here.

## Solution Assessment

Unclear. Explicit rejection is a good short-term mitigation, but the best fix depends on whether maintainers want media-output metadata in chat model config/catalogs or only in provider-owned media-generation capabilities.
