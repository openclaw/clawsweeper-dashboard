## Summary

Keep open: current main still lacks a chat/session output-modality contract for custom provider models, so Poe image/video-output refs can look like normal chat models even though supported media generation is routed through separate tools.

## What This Changes

The issue asks OpenClaw to either reject Poe image/video-output models with a clear unsupported-media-output diagnostic or add first-class runtime support for those media-output models.

## Best Possible Solution

Define an explicit output-modality contract: keep normal chat models text-output only with clear unsupported-media-output diagnostics for selected media-output refs, and continue routing supported generation through provider-backed `image_generate` and `video_generate` unless maintainers choose a broader media-output model API.
