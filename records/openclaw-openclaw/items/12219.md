## Summary

Keep open: current main and v2026.6.11 still expose SKILL.md/frontmatter skills, ClawHub trust checks, install policy, and generic before_install/before_tool_call hooks, but not the requested versioned skill.yaml permission manifest with install consent, audit/trust grades, signing, and attestation.

## What This Changes

The issue requests a standard skill.yaml permission manifest so skills can declare network, filesystem, shell, and credential needs for user review, audit, signing, and attestation.

## Best Possible Solution

Keep this open for maintainer security/product design around one versioned skill permission and trust contract coordinated with ClawHub verification, install/update consent, audit reporting, signing, attestation, and runtime enforcement hooks.

## Reproduction Assessment

Yes. Source inspection of current main and v2026.6.11 shows SKILL.md metadata, ClawHub verification, install policy, and generic hooks, but no standardized skill.yaml permission manifest or install consent/audit workflow.

## Solution Assessment

Unclear as a final implementation path. The direction is well motivated, but maintainers still need to choose schema placement, trust roots, declared-versus-enforced semantics, signing/attestation authority, and coordination with broader capability work.
