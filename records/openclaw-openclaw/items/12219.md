## Summary

Keep open: current main and v2026.6.11 still have SKILL.md/frontmatter metadata, ClawHub trust checks, install policy, and generic plugin hooks, but not the requested standardized skill.yaml permission manifest with install consent, audit/trust grades, signing, or attestation. The linked external package, ClawHub skill, fork, and open PR are useful prior art or partial candidates, not a complete OpenClaw contract replacement.

## What This Changes

The issue requests a standardized `skill.yaml` permission manifest for skills, including permission review before install, audit/trust scoring, signing, and attestation.

## Best Possible Solution

Define one versioned skill permission and trust contract coordinated with ClawHub verification, install/update consent, audit reporting, signing/attestation, and runtime enforcement hooks.

## Reproduction Assessment

Yes, as a source-level feature gap: current main and v2026.6.11 expose SKILL.md metadata, ClawHub trust checks, install policy, and hooks, but no standardized skill.yaml permission manifest or skills audit/consent workflow.

## Solution Assessment

Unclear as a final implementation path. The direction is aligned, but maintainers need to decide schema placement, declared-versus-enforced semantics, ClawHub/signing/attestation roots, and coordination with related capability and supply-chain issues before implementation.
