## Summary

Keep open: current main and the latest release still expose SKILL.md/frontmatter metadata, ClawHub trust checks, operator install policy, and generic hooks, but not the requested standardized skill permission manifest with install-time consent, audit/trust grades, signing, or attestation. The related RFCs, external implementations, and open PR are useful prior art or partial candidates, not a merged complete replacement.

## What This Changes

The issue requests a standardized `skill.yaml` permission manifest with install-time review, audit/trust scoring, signing, and attestation for skills.

## Best Possible Solution

Define one maintainer-approved, versioned skill permission and trust contract coordinated with ClawHub verification, install/update consent, audit reporting, signing/attestation, and runtime enforcement hooks.
