## Summary

Keep open: current main and v2026.6.11 still have SKILL.md/frontmatter metadata, ClawHub trust checks, operator install policy, and generic install/tool-call hooks, but not the requested standardized skill.yaml permission manifest with install-time consent, skills audit/trust grades, signing, or attestation. The linked external package, ClawHub skill, fork, and open PR are useful prior art or partial candidates, not a complete OpenClaw contract replacement.

## What This Changes

The issue requests a standard skill.yaml permission manifest for skills, including install review, audit/trust reporting, signing, and attestation concepts.

## Best Possible Solution

Define one versioned skill permission and trust contract coordinated with ClawHub verification, install/update consent, audit reporting, signing/attestation, and runtime enforcement hooks.
