## Summary

Keep open: current main and v2026.6.11 still lack the requested skill permission manifest, install/update consent review, audit/trust surface, signing, and attestation contract. The linked external package, ClawHub skill, fork, and open/closed related PRs are useful prior art, but none is a merged replacement for the core product/security decision.

## What This Changes

The issue requests a standardized `skill.yaml` permission manifest for skills, plus install-time review, audit/trust reporting, signing, and attestation semantics.

## Best Possible Solution

Adopt a maintainer-approved, versioned skill permission/trust model that coordinates SKILL.md metadata, ClawHub, install/update consent, audit/trust reporting, signing/attestation, and runtime/plugin hook enforcement.
