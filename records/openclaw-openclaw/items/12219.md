## Summary

Keep open: current main and v2026.6.11 still lack the requested standardized skill permission manifest, install-time consent/audit flow, trust scoring, signing, and attestation contract. The linked open-source package, ClawHub skill, fork, RFC, and open PR are useful prior art, but they do not complete this OpenClaw-owned security boundary.

## What This Changes

Request to add a standardized skill permission manifest for skills, including permission review, audit/trust reporting, signing, and attestation.

## Best Possible Solution

Adopt a maintainer-approved, versioned skill permission manifest path that starts with a clear audit/consent contract and separately stages ClawHub scanning, signing/attestation, and runtime enforcement hooks.

- **Adopt staged audit-only manifest (recommended):** Define a small versioned skill permission vocabulary first, expose it in status/install-policy surfaces, and track consent, enforcement, signing, and attestation as explicit follow-ups.
- **Design full enforcement first:** Pause implementation until maintainers settle default-deny runtime enforcement, approval UX, update diffs, and migration behavior together.
- **Keep manifest outside core:** Treat external packages and ClawHub scan pages as the primary permission surface unless a missing core API is proven.

## Solution Assessment

Unclear. A standalone skill.yaml may be useful, but the best maintainable path likely needs a staged maintainer-approved contract that aligns skill metadata, ClawHub trust surfaces, plugin hooks, and future enforcement.
