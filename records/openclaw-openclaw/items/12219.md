## Summary

Keep open: current main still has SKILL.md/frontmatter metadata, ClawHub verification/trust checks, operator install policy, and generic plugin hooks, but not the requested standardized skill permission manifest with install-time consent, audit/trust grades, signing, or attestation. The linked external package, ClawHub skill, fork, RFC, and open PR are useful prior art or partial candidates rather than a complete OpenClaw contract.

## What This Changes

The issue requests a standardized `skill.yaml` permission manifest for skills, including install-time review, auditing, signing, trust scoring, and attestation.

## Best Possible Solution

Define one versioned skill permission and trust contract coordinated with ClawHub verification, install/update consent, audit reporting, signing/attestation, and runtime enforcement hooks.
