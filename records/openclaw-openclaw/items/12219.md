## Summary

Keep open: current main has SKILL.md/frontmatter metadata, ClawHub trust checks, install policy, and generic plugin hooks, but still lacks a standardized skill permission manifest with install consent, audit/trust grades, signing, or attestation. The linked external tooling and related issues are useful prior art, not a complete OpenClaw contract replacement.

## What This Changes

Request a standardized skill permission manifest with install-time review, audit/trust scoring, signing, and attestation for skills.

## Best Possible Solution

Define one versioned skill permission and trust contract coordinated with ClawHub verification, install/update consent, audit reporting, signing/attestation, and runtime enforcement hooks.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 expose SKILL.md metadata, ClawHub trust checks, install policy, and hooks, but no standardized skill.yaml permission manifest or skills audit/consent workflow.

## Solution Assessment

Unclear as a final implementation; maintainers need to decide schema placement, declared-vs-enforced semantics, ClawHub/signing/attestation roots, and coordination with #12678, #74594, #10827, and #12507.
