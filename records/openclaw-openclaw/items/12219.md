## Summary

Keep open: current main and v2026.6.11 still expose SKILL.md/frontmatter metadata, ClawHub trust verification, install policy, and generic plugin hooks, but not the requested skill.yaml permission manifest, install-time consent, skills audit/trust grades, signing, or attestation. The discussion includes useful prior art from @ellistevo/openclaw-secure, shell-security-ultimate on ClawHub, and globalcaos/tinkerclaw, but those are complementary rather than a merged OpenClaw contract.

## What This Changes

The issue requests a standardized skill.yaml permission manifest with install-time review/audit, trust scoring, signing, and attestation for skills.

## Best Possible Solution

Keep this open for maintainer security/product design of one versioned skill permission and trust contract coordinated with https://github.com/openclaw/openclaw/issues/12678, ClawHub verification, install/update consent, audit reporting, signing, attestation, and runtime enforcement hooks.

## Reproduction Assessment

Yes, source-reproducible: current main and v2026.6.11 expose SKILL.md metadata, ClawHub trust verification, install policy, and generic hooks, but no standardized skill.yaml permission manifest or skills audit/consent workflow.

## Solution Assessment

Unclear as a final implementation path: the direction fits the security gap, but maintainers still need to choose schema location, trust roots, declared-versus-enforced semantics, and how signing/attestation compose with broader capability work.
