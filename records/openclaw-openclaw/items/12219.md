## Summary

Current main and v2026.6.11 add useful ClawHub verification and risk visibility, but they do not implement the requested standardized capability, consent, enforcement, signing, and attestation contract. The issue should remain open for explicit product and security design rather than autonomous implementation.

## What This Changes

Standardize declarative skill permissions and connect them to install/update consent, audit reporting, signing, attestation, and runtime enforcement.

## Best Possible Solution

Adopt one versioned capability vocabulary in the existing canonical skill metadata unless a migration case for a separate manifest is proven, then stage inspection, install/update diffs and consent, enforceable runtime mediation, and cryptographic provenance as distinct reviewed phases shared with ClawHub.
