## Summary

Keep open: current main and v2026.6.11 still use SKILL.md/frontmatter metadata, ClawHub trust checks, install policy, and generic hooks, but not the requested versioned skill.yaml permission manifest with install consent, audit/trust grades, signing, and attestation. The issue discussion also includes useful prior art from @ellistevo/openclaw-secure, shell-security-ultimate on ClawHub, and globalcaos/tinkerclaw, but those are complementary rather than an OpenClaw core/plugin-API contract.

## What This Changes

Request a standardized skill.yaml permission manifest with install-time consent, audit/trust reporting, signing, attestation, and ClawHub integration for skills.

## Best Possible Solution

Keep open for maintainer security/product design around one versioned skill permission and trust contract coordinated with ClawHub verification, install/update consent, audit/trust reporting, signing, attestation, and runtime enforcement hooks.

## Reproduction Assessment

Yes, source-reproducible: current main and v2026.6.11 expose SKILL.md metadata, ClawHub verification, install policy, and hooks, but no standardized skill.yaml permission manifest or skills audit/consent workflow.

## Solution Assessment

Unclear as a final implementation path: the direction is well motivated, but maintainers still need to choose schema placement, trust roots, declared-versus-enforced semantics, signing/attestation authority, and coordination with broader capability work.
