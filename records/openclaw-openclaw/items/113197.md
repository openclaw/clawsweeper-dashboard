## Summary

Keep this PR open for maintainer review: the direct-entry plumbing is sound for the positional form, but the documented `--channel <id>` form still takes the non-interactive path because `--channel` itself makes `hasFlags` true. The patch therefore does not deliver one of its stated user-facing behaviors and needs a small caller-boundary correction plus coverage.

## What This Changes

This PR makes an explicitly selected channel enter its guided setup immediately, preserves picker-first setup when no channel is selected, and ensures exact channel IDs win over colliding aliases.

## System Context

`openclaw channels add` converts Commander CLI arguments into either guided or non-interactive channel setup. The guided flow resolves the selected channel, installs or loads its setup plugin when necessary, runs that channel’s configuration prompts, and then returns users to the picker when they go Back.

## Best Possible Solution

Derive wizard direct entry from an explicit selected channel plus the absence of other channel-owned setup inputs, then add focused coverage for positional selection, channel-only `--channel`, and `--channel` with non-interactive credentials.
