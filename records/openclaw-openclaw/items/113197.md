## Summary

Keep this PR open for maintainer review rather than merge it as a routine fix. It intentionally changes the documented interactive CLI contract from “preselect a channel, then retain guidance” to “immediately begin that channel’s setup,” which can remove an expected intermediate confirmation for existing users; the safer path needs an explicit product decision and compatibility-preserving interface.

## What This Changes

This PR makes `openclaw channels add <channel>` and `openclaw channels add --channel <channel>` enter the selected channel’s guided setup immediately, while preserving the picker-first flow when no channel is selected.

## System Context

The Channels CLI parses interactive and flag-driven channel setup requests, then passes selected-channel state to the shared setup wizard. The wizard resolves installed or catalog channel plugins, runs channel-owned configuration, and returns users to the picker when they back out of a channel-specific step.

## Best Possible Solution

Preserve picker-first behavior for existing positional and `--channel` invocations, and add a clearly named opt-in direct-entry mode only if maintainers want immediate channel setup as a supported CLI workflow.
