## Summary

Keep this PR open: the guarded restore design appears coherent and does not bypass apply-time scanning, but the complete recovery flow still lacks real after-fix proof, the public Gateway/lifecycle contract remains undocumented, and maintainers must confirm that quarantined content may re-enter the editable pending state.

## What This Changes

The PR adds an operator-admin restore method that rescans quarantined Skill Workshop proposals, exposes scan findings in the Control UI, blocks applying non-clean proposals, and adds the corresponding Android protocol method.

## Best Possible Solution

Use pending as an editable recovery state only after a fresh rescan, retain the non-clean scan and block Apply until revision produces a clean result, document that lifecycle and Gateway method, and prove the full browser flow before merge.
