## Summary

Keep open: the reported `detail` JSON shape is still not recognized as a structured API error on current main, and the remaining silent handling for unconfigured OpenAI/Codex failures is a provider-routing product decision rather than a completed fix.

## What This Changes

The issue asks OpenClaw to stop forwarding OpenAI/Codex provider errors into Telegram chat when the user has not configured OpenAI or Codex.

## Best Possible Solution

Recognize top-level `detail` payloads at the shared error boundary, then define tested no-reply versus generic-error behavior for unconfigured OpenAI/Codex failures while preserving internal diagnostics.
