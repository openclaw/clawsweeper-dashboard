## What This Changes

The issue asks OpenClaw to prevent OpenAI Codex/FastAPI-style provider errors from leaking into user-facing Telegram chat, especially when the user has not configured Codex or OpenAI.

## Best Possible Solution

Recognize top-level `detail` payloads at the shared error boundary, then define tested no-reply versus generic-error behavior for unconfigured Codex/provider failures while preserving internal diagnostics.
