## Summary

Close: current main and the inspected latest release route assistant error delivery through a safe user-facing formatter, so the reported raw OpenAI/Codex `detail` JSON no longer reaches user chat.

## What This Changes

The issue requests that OpenAI/Codex provider errors, especially top-level `detail` JSON from unconfigured Codex paths, stop leaking verbatim into Telegram chat.

## Best Possible Solution

Keep the shipped delivery-boundary suppression; if maintainers want parser-specific `detail` wording or a different silent-provider policy, handle that as a new narrow product proposal.
