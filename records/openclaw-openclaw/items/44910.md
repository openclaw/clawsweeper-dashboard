## Summary

Keep open: current main prevents the exact raw `detail` JSON from reaching normal user-facing error delivery, but the shared parser still does not understand top-level `detail` payloads and the requested silent handling for unconfigured Codex/provider failures is still an unresolved product decision.

## What This Changes

The issue requests that OpenAI/Codex provider errors, especially top-level `detail` payloads from unconfigured providers, not appear in Telegram or other user chat.

## Best Possible Solution

Land or supersede the shared formatter parser fix, then make an explicit provider-routing policy for unconfigured Codex failures: no-reply/suppress versus generic diagnostic, with Telegram/user-facing delivery coverage and internal diagnostics preserved.
