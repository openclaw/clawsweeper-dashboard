## Summary

Keep open: current main and the latest release still do not recognize top-level string `detail` API error payloads, and the remaining choice between generic error text and silent no-reply for unconfigured Codex/provider failures needs maintainer policy direction.

## What This Changes

The issue asks OpenClaw to prevent Codex/OpenAI provider errors, especially top-level `detail` JSON payloads from unconfigured providers, from being forwarded into user chat.

## Best Possible Solution

Recognize top-level string `detail` payloads in the shared assistant-error formatter, then define tested routing behavior for unconfigured Codex/provider failures so user chats receive no raw JSON while internal diagnostics remain available.
