## Summary

Keep open: current main still does not recognize top-level string `detail` API error payloads, and the broader request to silently suppress unconfigured Codex/provider failures remains a maintainer policy choice.

## What This Changes

The issue asks OpenClaw to stop forwarding OpenAI/Codex provider errors, including `detail` JSON payloads from apparently unconfigured provider paths, into Telegram user chat.

## Best Possible Solution

Recognize top-level `detail` payloads at the shared error boundary, then add owner-approved routing tests that define when unconfigured Codex/provider failures become no-reply versus safe generic user copy.
