## Summary

Keep open: current main and the latest release still do not recognize top-level string `detail` API error payloads, and the linked open fork PR is a partial parser fix rather than a merged resolution for the unconfigured-provider suppression behavior.

## What This Changes

The issue asks OpenClaw to stop forwarding raw OpenAI Codex-style provider errors to Telegram/user chat when the user has not configured or selected that provider.

## Best Possible Solution

Review, land, or replace the linked parser fix, then make a maintainer decision for unconfigured-provider failures: silent no-reply, generic user-facing error, or internal diagnostics only.
