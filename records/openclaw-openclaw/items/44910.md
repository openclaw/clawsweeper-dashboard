## Summary

Keep open: current main has a generic user-facing error wrapper, but top-level string `detail` payloads are still not recognized as structured API errors and the unconfigured-provider suppression behavior remains a maintainer policy choice.

## Best Possible Solution

Recognize top-level `detail` payloads at the shared error boundary, then add owner-approved tests for no-reply versus generic-error behavior when unconfigured Codex/provider failures occur.
