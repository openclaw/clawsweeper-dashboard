- `impact:message-loss`: The reported failure pollutes user chat with provider/runtime error output instead of delivering the intended safe assistant response behavior.

## Summary

Keep open: current main and the latest release still do not classify or extract top-level string `detail` API payloads, and silent handling for unconfigured Codex/provider failures remains an unresolved provider-routing policy decision.

## What This Changes

The issue asks OpenClaw to stop forwarding unconfigured OpenAI/Codex provider errors, especially top-level `detail` JSON payloads, into Telegram or other user chat.

## Best Possible Solution

Recognize top-level `detail` payloads in the shared assistant error formatter and define tested routing behavior for unconfigured Codex/provider failures while preserving internal diagnostics.
