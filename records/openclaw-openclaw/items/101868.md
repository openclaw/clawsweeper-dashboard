- `maturity:stable`: The issue affects gateway-visible blocked run lifecycle and recovery behavior, and `gateway-runtime` is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and v2026.6.11 still end exhausted embedded-agent context-overflow recovery with a transient blocked result and manual `/reset` or `/new` guidance, while auto-rotation or durable blocked-state persistence requires a maintainer-owned recovery policy.

## What This Changes

Request automatic one-shot recovery or a durable blocked-overflow marker when embedded-agent context-overflow recovery exhausts compaction/truncation and would otherwise require manual `/reset` or `/new`.

## Best Possible Solution

Adopt one maintainer-approved recovery policy: persist an operator-visible overflow-blocked state first, then add guarded one-shot rotation only if replay safety, loop caps, and docs are settled.

Rationale: The current code and docs intentionally preserve the session mapping after failed overflow recovery, while the requested change chooses new core session recovery and durable state semantics for autonomous agents.

Owner confidence: high

Options:

- **Persist blocked state first (recommended):** Add a durable overflow-blocked marker plus operator-visible recovery affordance without silently replaying the pending turn on a new session.
- **Guarded one-shot rotation:** Rotate and replay once only after compaction and truncation are exhausted, with replay-safety gates and a per-session loop cap.
- **Keep manual recovery:** Keep the documented `/reset` or `/new` contract and improve only logs, diagnostics, docs, or UI visibility.

## Reproduction Assessment

Yes, at source level: current main still returns a blocked context-overflow result with `/reset` or `/new` guidance after overflow recovery is exhausted, and the session store has no durable overflow-blocked marker. I did not run a live oversized-session reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the recovery policy. A persisted blocked marker is the least disruptive path; automatic rotation is plausible but must prove replay safety and avoid conflicting with model fallback or compaction-timeout repairs.
