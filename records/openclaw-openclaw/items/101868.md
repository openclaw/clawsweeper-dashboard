## Summary

Keep open: current main and the latest release still end exhausted embedded-agent context-overflow recovery with a blocked result and manual `/reset` or `/new` guidance, while the requested auto-rotation or durable blocked marker remains a core recovery-policy decision.

## What This Changes

The issue requests automatic one-shot session rotation or a persisted blocked-overflow marker when embedded-agent overflow recovery reaches the give-up branch.

## Best Possible Solution

Adopt one maintainer-approved recovery policy: persist an explicit overflow-blocked state with visible operator recovery first, and add guarded one-shot rotation only if replay safety, loop caps, and docs are settled.

Options:

- **Persist blocked state first (recommended):** Add a durable overflow-blocked marker plus operator-visible recovery affordance without silently replaying a turn on a new session.
- **Guarded one-shot rotation:** Rotate and replay once only after compaction and truncation are exhausted, with replay-safety gates and a per-session loop cap.
- **Keep manual recovery:** Keep the documented `/reset` or `/new` contract and improve only visibility, diagnostics, or docs.

## Solution Assessment

Unclear until maintainers choose the recovery policy. A persisted blocked marker is the least disruptive path; automatic rotation is plausible but must prove replay safety and avoid competing with model fallback or compaction-timeout repairs.
