## Summary

Keep open: current main and v2026.6.11 still exhaust embedded-agent overflow recovery by returning a blocked context-overflow result with manual `/reset` or `/new` guidance, while the requested durable marker or one-shot rotation needs a core session-recovery policy decision.

## What This Changes

Request automatic one-shot session rotation or a durable blocked-overflow marker when embedded-agent context-overflow recovery gives up.

## Best Possible Solution

Adopt one maintainer-approved recovery policy: persist an explicit overflow-blocked state with a visible recovery surface first, and add guarded one-shot rotation only if replay safety, loop caps, and docs are settled.

Rationale: The current docs and code intentionally preserve the session mapping and ask for manual recovery, while the issue asks to change core recovery and durable session-state semantics for autonomous agents.

Owner confidence: high

Options:

- **Persist blocked state first (recommended):** Add a durable overflow-blocked marker plus an operator-visible recovery affordance without silently replaying a turn on a new session.
- **Guarded one-shot rotation:** Rotate and replay once only after compaction and truncation are exhausted, with replay-safety gates and a per-session loop cap.
- **Keep manual recovery:** Keep the documented `/reset` or `/new` contract and improve only visibility, diagnostics, or docs.

## Solution Assessment

Unclear until maintainers choose the recovery policy. A persisted blocked marker is the least disruptive path; automatic rotation is plausible but must prove replay safety and avoid competing with model fallback or compaction-timeout repairs.
