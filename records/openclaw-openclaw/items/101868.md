## Summary

Keep open: current main and v2026.6.11 still end exhausted embedded-agent overflow recovery with a blocked result and manual `/reset` or `/new` guidance, while the requested auto-rotation or durable overflow marker changes core session recovery policy.

## What This Changes

Request automatic one-shot session rotation or a durable overflow-blocked marker when embedded-agent context-overflow recovery gives up.

## Best Possible Solution

Choose one core recovery contract: persist an explicit overflow-blocked state with operator-visible recovery first, and add guarded one-shot rotation only if replay safety, loop caps, and docs are settled.

Options:

- **Persist blocked state first (recommended):** Add a durable overflow-blocked marker plus an operator-visible recovery affordance without silently replaying a turn on a new session.
- **Guarded one-shot rotation:** Rotate and replay once only after compaction and truncation are exhausted, with replay-safety gates and a per-session loop cap.
- **Keep manual recovery:** Keep the documented `/reset` or `/new` contract and improve only diagnostics, visibility, or docs.

## Reproduction Assessment

Yes, at source level: current main still returns a blocked context-overflow result with `/reset` or `/new` guidance after overflow recovery is exhausted, and the durable session entry has no explicit overflow-blocked marker. I did not run a live oversized-session scenario in this read-only review.

## Solution Assessment

Unclear until maintainers choose the recovery policy. A persisted blocked marker is the least disruptive path; automatic rotation is plausible but must prove replay safety and avoid competing with model fallback or compaction-timeout repairs.
