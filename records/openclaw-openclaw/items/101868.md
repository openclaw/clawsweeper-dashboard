## Summary

Keep open: current main and v2026.6.11 still exhaust embedded-agent overflow recovery into a transient blocked result with manual `/reset` or `/new` guidance, and the requested durable marker or one-shot auto-rotation needs maintainer-owned recovery semantics.

## What This Changes

Request automatic one-shot session rotation or a durable overflow-blocked marker when embedded-agent context-overflow recovery gives up.

## Best Possible Solution

Choose one recovery contract: durable overflow-blocked marker with visible recovery first, with guarded one-shot rotation only if replay safety and loop caps are approved.

Rationale: The current code and docs intentionally preserve the session mapping and require manual `/reset` or `/new`; changing that affects core replay, session state, and operator recovery semantics.

Options:

- **Persist blocked state first (recommended):** Add a durable overflow-blocked receipt and operator-visible recovery action without automatically replaying the pending turn on a new session.
- **Guarded one-shot rotation:** Rotate and replay once after exhausted overflow recovery only with explicit replay-safety gates, loop caps, and tests for duplicate side effects.
- **Keep manual recovery:** Retain documented `/reset` or `/new` recovery while improving diagnostics, docs, or UI visibility for blocked overflow sessions.

## Solution Assessment

Unclear until maintainers choose policy; persisting a blocked-overflow receipt is the narrowest safer first step, while automatic rotation must prove replay safety and avoid duplicate side effects or messages.
