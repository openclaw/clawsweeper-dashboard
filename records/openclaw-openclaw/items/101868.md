## Summary

Keep open: current main and the latest release still end exhausted embedded-agent overflow recovery with a transient `livenessState: "blocked"` result and manual `/reset` or `/new` guidance, while no linked issue or PR owns the exact auto-rotation or persisted blocked-marker decision.

## What This Changes

The issue requests automatic one-shot session rotation, or at least a durable blocked-overflow marker, when embedded-agent context-overflow recovery reaches the give-up branch.

## Best Possible Solution

Adopt a maintainer-approved recovery policy: persist an explicit overflow-blocked state with a visible recovery surface first, and add guarded one-shot rotation only if replay safety, loop caps, and docs are settled.

Yes, at source level: current main still returns a blocked context-overflow result with `/reset` or `/new` guidance after overflow recovery is exhausted, and the session-store type has no durable `livenessState` marker. I did not run a live oversized-session repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the recovery policy. A persisted blocked marker is the least disruptive path; automatic rotation is plausible but must prove replay safety and avoid competing with model fallback or compaction-timeout repairs.
