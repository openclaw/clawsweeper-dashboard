## Summary

Keep open: current main and v2026.6.11 still end exhausted embedded-agent overflow recovery with a transient blocked result and manual reset/new guidance, while the requested auto-rotation or durable blocked marker remains a core session-recovery product decision.

## What This Changes

The issue asks for embedded-agent context-overflow give_up to either auto-rotate once from compaction state or persist a blocked-overflow marker instead of staying wedged until manual reset.

## Best Possible Solution

Adopt one maintainer-approved recovery policy: persist an explicit overflow-blocked state with visible recovery first, and add guarded one-shot rotation only if replay safety, loop caps, and docs are settled.

Unclear until maintainers choose the recovery policy. A persisted blocked marker is the least disruptive path; automatic rotation is plausible but must prove replay safety and avoid competing with model fallback or compaction-timeout repairs.
