## Summary

Keep open: current main and v2026.6.11 still end exhausted embedded-agent overflow recovery with a blocked context-overflow result and manual `/reset` or `/new` guidance, so the requested auto-rotation or durable marker remains unresolved and needs maintainer policy.

## What This Changes

The issue requests automatic one-shot session rotation or a durable blocked-overflow marker when embedded-agent context-overflow recovery gives up.

## Best Possible Solution

Define a single overflow give-up recovery contract: at minimum persist an explicit overflow-blocked state and operator-visible recovery affordance, adding guarded one-shot rotation only after replay safety and loop caps are settled.

## Maintainer Decision

Question: Should exhausted embedded-agent context-overflow recovery persist a durable blocked-overflow state, auto-rotate and replay the pending turn once, or keep manual recovery with better visibility?

Rationale: Current source and docs intentionally preserve the session mapping after failed overflow recovery, while the issue asks to change core session recovery and durable state behavior for autonomous agents.

Likely owner: steipete

Owner confidence: high

Options:

- **Persist blocked state first (recommended):** Add a durable overflow-blocked marker plus operator-visible recovery affordance without silently replaying a turn on a new session.
- **Guarded one-shot rotation:** Rotate and replay once only after compaction and truncation are exhausted, with replay-safety gates and a per-session loop cap.
- **Keep manual recovery:** Keep the documented `/reset` or `/new` contract and improve only visibility, diagnostics, or docs.

## Reproduction Assessment

Yes, at source level: current main still returns a blocked context-overflow result with `/reset` or `/new` guidance after overflow recovery is exhausted. I did not run a live oversized-session reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the recovery policy. A persisted blocked marker is the least disruptive path; automatic rotation is plausible but must prove replay safety and avoid competing with model fallback or compaction-timeout repairs.
