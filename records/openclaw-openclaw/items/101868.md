## Summary

Keep open: current main and v2026.6.11 still end exhausted embedded-agent overflow recovery with a transient blocked result and manual `/reset` or `/new` guidance, while the requested auto-rotation or durable marker needs a core session-recovery product decision. Adjacent open issues and PRs cover model fallback, compaction timeouts, irreducible overflow, or stuck recovery, but none is a merged or safe canonical replacement for this exact give_up recovery contract.

## What This Changes

The issue requests automatic embedded-agent session recovery, or at least a persisted marker, when context-overflow recovery reaches the give_up branch and currently leaves the session blocked until manual reset.

## Best Possible Solution

Choose one durable core recovery policy: persist an explicit overflow-blocked state with an operator-visible recovery surface first, and add guarded one-shot rotation only if replay safety, loop caps, and docs are settled.

Options:

- **Persist blocked state first (recommended):** Add a durable overflow-blocked marker plus visible recovery affordance without silently replaying a turn on a new session.
- **Guarded one-shot rotation:** Rotate and replay once only after compaction and truncation are exhausted, with explicit side-effect and loop-cap gates.
- **Keep manual recovery:** Retain the documented `/reset` or `/new` contract and improve only diagnostics or docs visibility.

## Reproduction Assessment

Yes, at source level for the current behavior: current main still returns a blocked context-overflow result with `/reset` or `/new` guidance after overflow recovery is exhausted, and the durable session entry type still has no explicit overflow-blocked marker. This is not a failing test of an established auto-rotation contract; it is a confirmed gap against the requested recovery behavior.

## Solution Assessment

Unclear until maintainers choose the recovery policy. A persisted blocked marker is the least disruptive path; automatic rotation is plausible but must prove replay safety and avoid competing with model fallback or compaction-timeout repairs.
