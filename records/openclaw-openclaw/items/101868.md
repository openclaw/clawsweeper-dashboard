## Summary

Keep open: current main and the latest release still end exhausted embedded-agent context-overflow recovery with a blocked result and manual `/reset` or `/new` guidance, while the requested auto-rotation or durable marker remains a core recovery-policy decision.

## What This Changes

Request automatic one-shot session rotation or a durable blocked-overflow marker when embedded-agent context-overflow recovery gives up.

## Best Possible Solution

Adopt one maintainer-approved overflow recovery contract, preferably a durable overflow-blocked marker plus an operator-visible recovery surface before adding guarded one-shot rotation and replay.

Options:

- **Persist blocked state first (recommended):** Add a durable overflow-blocked marker plus visible operator recovery affordance without silently replaying a pending turn on a new session.
- **Guarded one-shot rotation:** Rotate and replay once only after compaction and truncation are exhausted, with replay-safety gates and a per-session loop cap.
- **Keep manual recovery:** Keep the documented `/reset` or `/new` contract and improve only diagnostics, surfacing, or docs.

I did not run a live oversized-session reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the recovery policy. A persisted blocked marker is the least disruptive path; automatic rotation is plausible but must prove replay safety and avoid conflicting with fallback and compaction-timeout repairs.
