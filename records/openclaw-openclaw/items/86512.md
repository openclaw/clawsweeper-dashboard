## Summary

Keep open: current main and v2026.6.11 mitigate part of the regression by moving provider-auth warming off the main thread, but normal gateway startup still schedules the provider-auth warm sweep by default. The remaining default-on versus hook-only/default-off behavior is already covered by an open maintainer PR and needs a maintainer product/upgrade decision.

## What This Changes

The issue reports a v2026.5.22 gateway CPU and API-latency regression after startup, attributed to provider-auth state prewarming, and requests backgrounding, timeout/progress control, or an opt-out.

## Best Possible Solution

Choose one canonical provider-auth startup contract, preferably hook-only/default-off with explicit opt-in for eager warming, prove fresh-start and upgrade behavior on affected gateway hosts, then close this issue after the accepted change reaches main.
