## Summary

Current main still exposes a documented plugin-tab path that can fail with 401 under token authentication, and the open closing PR requires focused security-boundary review before this issue can close.

## What This Changes

Make external Control UI tabs render gateway-authenticated plugin HTTP routes without exposing shared credentials or weakening direct route authentication.

## Best Possible Solution

Land a narrowly scoped authenticated launch-session or host-mediated proxy design that binds short-lived authority to the intended plugin route, preserves bounded operator scopes and sandboxing, keeps direct unauthenticated requests at 401, and includes real-browser plus cross-plugin isolation proof.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should external plugin tabs receive narrowly delegated HTTP authority through the linked PR's signed HttpOnly launch cookie, or should the host use a different authenticated proxy/session mechanism?

Rationale: This choice creates a new browser-to-Gateway credential-delegation boundary, so cookie scope, replay, CSRF behavior, route ownership, and operator-scope semantics require explicit maintainer security intent.

Likely owner: vincentkoc

Owner reason: The available history connects this person most directly to both Gateway authorization and plugin registry boundaries affected by the decision.

Owner confidence: medium

Options:

- **Approve bounded launch session (recommended):** Use a short-lived signed HttpOnly session only after proving plugin-root binding, minimal scopes, expiry, replay limits, browser behavior, and continued unauthenticated denial.
- **Require host-mediated proxy:** Keep plugin routes free of delegated cookies and route iframe requests through a host-owned authenticated proxy with equivalent path and scope confinement.
- **Withdraw authenticated tab contract:** Document external tabs as public or plugin-auth-managed only, which avoids delegation complexity but breaks the currently documented gateway-route integration.

## Reproduction Assessment

Yes at source level: the documented external-tab path becomes a plain iframe GET, while token-authenticated plugin HTTP routes require HTTP credentials and therefore return 401. A live current-main run was not performed in this read-only review.

## Solution Assessment

Unclear pending security review: a path-scoped short-lived HttpOnly session is a plausible narrow fix, but it is the best solution only if cookie confinement, replay, CSRF, scope propagation, and cross-plugin isolation are proved against alternatives such as a host-mediated proxy.
