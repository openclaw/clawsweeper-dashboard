## Summary

Keep this issue open: current main still renders an advertised external plugin tab by assigning the descriptor path directly to a sandboxed iframe, while the documented SDK contract says that path may be a plugin HTTP route; under token/password Gateway auth, the frame therefore has no authenticated HTTP handoff. The focused closing PR is still open, and its credential-handoff design needs security review and real Tailscale/token-auth browser proof before the issue can close. ([github.com](https://github.com/openclaw/openclaw/blob/main/ui/src/pages/plugin/plugin-page.ts))

## What This Changes

Make documented external Control UI plugin tabs render Gateway-authenticated plugin HTTP routes without exposing or weakening the shared Gateway credential.

## Best Possible Solution

Provide one canonical, short-lived, same-origin launch-session mechanism bound to the advertised plugin identity, canonical route root, negotiated operator scopes, and strict expiry; keep direct unauthenticated requests at 401 and prove the complete flow in a real browser through Tailscale Serve under token and password auth.
