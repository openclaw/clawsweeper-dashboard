## Summary

Keep open: current main and the latest release still lack stable `before_tool_call` action classification or hook-level input provenance, and the remaining design is a public Plugin SDK security-policy boundary rather than stale cleanup.

## What This Changes

The issue requests optional `before_tool_call` hook fields for stable action classification and input provenance so security-policy plugins can avoid brittle tool-name mappings.

## Best Possible Solution

Settle one additive plugin-facing policy-facts contract that coordinates action or capability taxonomy with safe provenance fields, then implement it with SDK docs, API baseline updates, and focused tests across core, plugin-tool, Gateway/MCP, and native hook paths.
