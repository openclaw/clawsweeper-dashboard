## Summary

Keep open: current main and v2026.6.11 still do not expose stable before_tool_call action classification or hook-level input provenance. Related work covers useful slices, but no merged or safe canonical item fully owns this combined Plugin SDK/security-policy contract.

## What This Changes

Request optional PluginHookBeforeToolCallEvent fields for action classification and input provenance so policy plugins can make stable security, audit, and compliance decisions without tool-name mapping.

## Best Possible Solution

Settle one additive plugin-facing policy-facts contract that coordinates action or capability taxonomy with safe provenance fields, then implement it with SDK docs and focused tests across core, plugin-tool, MCP/Gateway, and native hook paths.
