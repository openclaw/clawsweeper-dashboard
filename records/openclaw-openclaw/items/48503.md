## What This Changes

The issue requests optional action classification and input provenance fields on the plugin `before_tool_call` hook event so security-policy plugins can avoid brittle tool-name mappings.

## Best Possible Solution

Define one additive, documented Plugin SDK policy-facts contract for before_tool_call that aligns action/capability taxonomy with a bounded provenance shape, then add focused hook, trusted-policy, SDK baseline, and docs coverage after maintainer security approval.
