## Summary

Keep open: current main still exposes only tool, run, and path facts to `before_tool_call`, not stable action classification or hook-level input provenance; related security-matrix, capability, and external-content work remains partial or open and does not replace this public Plugin SDK contract.

## What This Changes

Request to enrich `before_tool_call` hook events with optional action classification and input provenance for security policy plugins.

## Best Possible Solution

Define one additive plugin-facing policy-facts contract covering action or capability taxonomy and safe provenance fields, then implement it across core, plugin, client, and MCP tool paths with SDK docs, API baselines, and focused tests.
