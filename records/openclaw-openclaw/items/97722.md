## Summary

Fresh review should keep PR #97722 open: the macOS WebChat direction is well scoped and has credible native proof, but the patch regresses the shared/default chat pending timeout from the current 120 seconds to 30 seconds for every transport that does not override the new protocol property.

## What This Changes

The PR separates macOS WebChat request ACK timing from assistant-run waiting by adding an agent.wait path, a macOS-only five-minute run budget, and shared ChatViewModel transport-driven pending timeouts with Swift coverage.

## Best Possible Solution

Preserve the existing 120-second shared/default pending timeout, keep only macOS WebChat opted into 300 seconds, and retain the new agent.wait completion refresh path.
