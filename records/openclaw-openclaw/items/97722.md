## What This Changes

This PR splits macOS chat's short WebSocket ACK wait from the assistant run budget, waits for non-terminal chat sends through `agent.wait`, raises the shared Swift pending-run budget to five minutes, and adds Swift regression tests.

## Best Possible Solution

Land the macOS timeout split after maintainer review accepts the longer Swift pending budget, with iOS/Android parity tracked separately if needed.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: current main sends a 30000 ms macOS `chat.send.timeoutMs` and uses the same value for the request wait, while the reported slow first reply needs a longer run budget.

## Solution Assessment

Yes, this is the best fix shape for the macOS bug: it keeps the ACK wait short, moves the assistant run budget into the `chat.send` payload, and reuses the existing `agent.wait` terminal-result contract instead of adding protocol or config surface.
