## Summary

This PR remains useful and reviewable: current main still uses the short macOS chat-send timeout as both request ACK wait and assistant run budget, while the PR separates those budgets and reuses the existing `agent.wait` contract. ## What This Changes

This PR changes macOS chat send timeout handling, adds macOS `agent.wait` completion waiting, raises the shared Swift pending-run timeout to five minutes, and adds Swift regression tests.

## Best Possible Solution

Merge the macOS timeout split once maintainers accept the five-minute native pending budget, with Talk Mode scope and iOS/Android parity explicitly accepted or tracked separately.

## Solution Assessment

Yes for the macOS WebChat bug: the PR keeps the ACK wait short, moves the assistant run budget into the existing `chat.send.timeoutMs` payload, and reuses the existing `agent.wait` contract. The remaining concern is timeout policy/scope, not a discrete patch defect.
