## Summary

This remains a well-evidenced Gateway performance bug on current main: same-version startup still loads and traverses migration code before using the completed checkpoint, while runtime-plugin prewarm still waits ten seconds. The issue is actively assigned and has the protected `maintainer` label, so it should remain open for owner-led repair rather than cleanup closure or autonomous promotion.

## What This Changes

Avoid reloading completed startup migrations on same-version Gateway restarts and begin runtime-plugin prewarming promptly after readiness.

## Best Possible Solution

Consult the lightweight version checkpoint before importing doctor migration code, retain a config-only validation path when the checkpoint is current, and start the existing cancellable runtime-plugin prewarm immediately after readiness without adding another config or environment surface.
