## Summary

The PR still needs maintainer handling: it improves local-loopback auth diagnostics, but it also changes shipped unresolved-auth behavior to fail closed and leaves daemon status able to run restart-health after a synthetic auth failure.

## What This Changes

The PR adds `failureReason` propagation and synthetic failed probe results across gateway status/probe, top-level status scan, and daemon status when required local loopback auth cannot be resolved.

## Best Possible Solution

Keep the local-loopback diagnostic improvement only after gateway/auth owners accept the fail-closed upgrade behavior or the shipped warning-plus-probe default is preserved, and make daemon status avoid restart-health probing after synthetic auth failures.

## Reproduction Assessment

Yes. The remaining blockers are source-reproducible: PR head synthesizes auth failures for unresolved local credentials, and daemon status still enters restart-health when that synthetic RPC result is not ok.

## Solution Assessment

No as-is. The local-loopback fail-fast is a plausible diagnostic improvement, but the best fix must settle the fail-closed compatibility choice and cover daemon status end to end.
