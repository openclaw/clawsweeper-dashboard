## Summary

This PR has strong real-behavior evidence and resolves the earlier mechanical regressions, but it still replaces the shipped local-probe fallback with a fail-fast result for existing required-auth configurations whose configured credential cannot resolve. That compatibility policy needs an explicit gateway/auth-owner decision before merge; it should not land by default as a bug fix.

## What This Changes

The branch makes local loopback gateway, daemon, and top-level status probes synthesize an actionable auth-resolution failure instead of attempting an unauthenticated WebSocket probe when required local credentials are unavailable.

## Best Possible Solution

Keep the current local probe as the default compatibility path while surfacing the unresolved-credential diagnostic, unless a gateway/auth owner explicitly chooses fail-fast and defines the upgrade and recovery contract for existing installations.
