## What This Changes

The PR makes local loopback gateway, daemon, and top-level status commands return an actionable credential-resolution failure instead of attempting an unauthenticated WebSocket probe when required local credentials are unavailable.

## System Context

Gateway status commands resolve credentials from configuration and the local device state, then probe a configured or explicitly supplied WebSocket endpoint. Their result feeds CLI and daemon diagnostics that operators use to decide whether a gateway is reachable and healthy.

## Best Possible Solution

Have a gateway/auth owner choose the default: preserve the existing local probe and surface the credential diagnostic alongside it, or explicitly accept fail-fast semantics with documented upgrade behavior and focused coverage for both the chosen default and paired-device cases.
