Full review comments:

- **[P1] Preserve shipped probe behavior by default:** `src/gateway/probe-auth.ts:134-142`
  - body: Returning `failureReason` here changes configured-but-unresolved local credentials from the documented warning-plus-probe behavior into an immediate failed status/probe result. Existing installs whose SecretRef is unavailable in the command environment can stop reaching an otherwise healthy local gateway, so this needs owner-accepted upgrade behavior or a default-compatible strict path.
  - confidence: 0.88
- **[P2] Skip restart health after synthetic auth failures:** `src/cli/daemon-cli/status.gather.ts:674-675`
  - body: When this branch creates a synthetic RPC failure, `rpc.ok` remains false and the later restart-health block still calls `inspectGatewayRestart`, which performs its own loopback `probeGateway` without the resolved safe probe-auth path. That can still produce the probe this change is trying to avoid, so skip restart-health or pass safe auth when `rpcFailureReason` is used.
  - confidence: 0.9
- **[P3] Use a non-probe warning for fail-fast results:** `src/gateway/probe-auth.ts:141-142`
  - body: The unresolved-SecretRef warning still says the command is `probing without configured auth credentials`, but callers now skip `probeGateway` when the paired `failureReason` is present. Split the fail-fast warning text so CLI and JSON output do not claim a probe happened.
  - confidence: 0.78
