## Summary

The Feishu Auto-TTS bug is valid and the metadata-based suppression change is directionally correct, but this PR is not merge-ready: it updates only one of two Feishu suppression paths, unnecessarily expands the shared outbound adapter API, conflicts with current `main`, and provides no real Feishu behavior proof.

## What This Changes

The PR makes Feishu voice-text suppression depend on TTS supplement visibility metadata so fresh Auto-TTS replies send text plus voice while already-streamed replies send voice only.

## Best Possible Solution

Rebase onto current `main`, keep supplement metadata inside Feishu-private helpers, update both outbound and reply-dispatcher suppression paths, preserve native voice-only behavior, and demonstrate both visibility states in a real Feishu chat.
