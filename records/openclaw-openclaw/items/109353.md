## Summary

Keep open for a narrow plugin-contract decision: current main intentionally does not broadcast `inbound_claim` for ordinary core-owned traffic, but the documented `before_agent_run` hook already supports blocking channel-originated embedded runs before model input. Maintainers should decide whether to clarify the existing hook boundary or add an earlier interception contract. Likely related people: @steipete (high confidence, conversation-binding path) and @gfzhx (medium confidence, pre-dispatch hook history). ([formatika.de](https://www.formatika.de/index.jsp?content=source&detail=products%2FSources%2Fformale+Sprachen%2FJAVA%2Fopenclaw%2Fsrc%2Fauto-reply%2Freply%2Fdispatch-from-config.test.ts))

## What This Changes

Allow plugins to inspect and suppress ordinary inbound messages before the embedded agent processes them.

## Best Possible Solution

Document `inbound_claim` as binding-owned if that scope is intentional, add a channel-originated embedded-run example for transcript-safe suppression with `before_agent_run`, and only add a new pre-routing hook if maintainers confirm that routing or queue interception must happen earlier.

Rationale: Current tests deliberately keep global `inbound_claim` off ordinary traffic, while current docs provide a later transcript-safe blocker; changing the earlier boundary affects plugin ordering, routing ownership, failure policy, and potentially multiple plugins claiming the same message.

Options:

- **Clarify and use before_agent_run (recommended):** Keep `inbound_claim` binding-owned, document that scope, and provide a tested `before_agent_run` pattern for suppressing self-echoes before model input.
- **Broadcast inbound_claim globally:** Invoke the existing global runner for ordinary traffic and define priority, timeout, failure, reply-delivery, and multi-plugin claim semantics as a public plugin contract.
- **Add a distinct pre-routing hook:** Preserve `inbound_claim` ownership semantics while adding a narrowly named hook for global suppression or routing before canonical session selection.

## Reproduction Assessment

Yes at source level: the current dispatch test explicitly verifies that ordinary non-bound traffic does not call the global `runInboundClaim`. ## Solution Assessment

No, unconditionally broadcasting `inbound_claim` is not yet proven to be the best fix because it changes an intentional ownership boundary. The narrowest current solution is `before_agent_run` plus accurate hook-scope documentation, unless maintainers confirm a need for interception before routing.
