## Summary

The current head fixes the previously reported timeout-recovery regression and cleanly moves active crash-loop ownership to the channel manager, but it also makes retry exhaustion terminal even though current main explicitly tests bounded health-monitor revival after give-up. That availability policy needs gateway-owner confirmation, and this external PR still has only deterministic test proof rather than after-fix evidence from an installed channel setup.

## What This Changes

The PR adds a closed manager-versus-monitor recovery-ownership contract, skips health-monitor resets and restarts during active backoff or terminal give-up, preserves timed-out stop recovery, and adds composed gateway lifecycle tests.

## Best Possible Solution

Keep the manager authoritative for active crash-loop backoff, then explicitly choose and document the post-give-up availability policy; whichever canonical branch remains should prove terminal give-up or separately budgeted revival together with timed-out stop recovery in a redacted installed-runtime run.
