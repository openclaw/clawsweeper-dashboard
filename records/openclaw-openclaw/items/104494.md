## Summary

This PR needs revision before merge. Its ownership contract fixes the reported give-up conflict, but it also suppresses the second start required to recover a timed-out channel task when the runtime retains a positive reconnect-attempt count.

## What This Changes

The PR adds a recovery-ownership query to the channel manager and makes the health monitor skip restart and attempt-reset actions during active crash-loop backoff or terminal give-up.

## Best Possible Solution

Derive recovery ownership from canonical manager facts that explicitly distinguish task-backed crash-loop backoff from `recoveryStopTimedOut`, then cover both paths with a composed manager-plus-monitor regression test.
