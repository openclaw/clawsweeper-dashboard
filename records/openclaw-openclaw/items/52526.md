## Summary

Keep open. Current main and the latest release still persist CLI assistant text through the `before_message_write` hook path while returning `agent --json` payloads from the original CLI output text, and the linked fix PR targets removed runner files rather than the live CLI path.

## What This Changes

The issue asks for `agent --json` payloads to reflect the finalized assistant text after `before_message_write` hooks, matching the persisted transcript.

## Best Possible Solution

Make the live CLI JSON result path consume the finalized assistant message accepted by the transcript write-hook path, with explicit no-leak behavior for hook-blocked replies.

## Reproduction Assessment

Yes, at source level. Current main persists CLI assistant text through `beforeMessageWrite`, then builds returned JSON payloads from the original CLI output text; I did not run a live plugin/CLI reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose blocked-hook JSON semantics. The best implementation should retarget the current CLI runner and transcript seam rather than the stale pi-runner PR path.
