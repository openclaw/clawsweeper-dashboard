## Summary

Keep open. Current main still returns CLI JSON payload text from the raw CLI output while transcript persistence applies `before_message_write`, and the related open PR targets a removed runner tree rather than the current CLI path.

## What This Changes

The issue asks for `agent --json` to return the finalized assistant message after `before_message_write` hooks instead of pre-hook CLI output.

## Best Possible Solution

Make the current CLI JSON result path consume the same finalized assistant accepted by the transcript write-hook path, with explicit non-leaking behavior for hook-blocked replies.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: When `before_message_write` rewrites or blocks a CLI assistant message, what should `agent --json` expose to callers?

Rationale: The current behavior can leak text that a plugin blocked or rewrote before transcript persistence, but changing JSON output for blocked writes is a public CLI/result contract decision.

Likely owner: steipete

Owner reason: He merged the original hook feature and was explicitly pulled into this issue's maintainer timeline for the policy-sensitive follow-up.

Owner confidence: medium

Options:

- **Return finalized or suppressed output (recommended):** Use the post-hook assistant text for rewrites and return a structured suppressed/blocked result without raw text when the hook blocks persistence.
- **Thread hook output into JSON only:** Run or thread the same hook result into the JSON builder without re-reading the transcript, but still define blocked-output shape before implementation.
- **Keep transcript-only semantics:** Leave `before_message_write` as persistence-only and document that `agent --json` may expose raw CLI output, accepting the security tradeoff.

## Reproduction Assessment

Yes, at source level. Current main persists CLI assistant text through `beforeMessageWrite` and then builds returned `payloads` from raw `output.text`; I did not run a live plugin/CLI reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose blocked-hook JSON semantics. The best implementation should retarget the current CLI runner and transcript seam rather than the stale pi-runner PR path.
