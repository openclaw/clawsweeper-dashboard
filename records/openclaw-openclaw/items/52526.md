## Summary

Keep open. Current main and the latest release still persist CLI assistant text through the `before_message_write` transcript hook but build `agent --json` payloads from raw CLI output, so the reported JSON/transcript mismatch remains valid.

## What This Changes

The issue requests that `agent --json` return the finalized assistant message after `before_message_write` hooks, matching the persisted transcript.

## Best Possible Solution

Make the current CLI JSON result path consume the same finalized assistant message accepted by the transcript write-hook path, with explicit non-leaking behavior for hook-blocked replies.

## Reproduction Assessment

Yes, at source level. Current main persists CLI assistant text through `beforeMessageWrite` and then builds returned `payloads` from raw `output.text`; I did not run a live plugin/CLI reproduction in this read-only review.

## Solution Assessment
