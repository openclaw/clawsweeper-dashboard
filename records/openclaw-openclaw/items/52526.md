## Summary

Keep open. Current main and the latest release still build `agent --json` payloads from raw CLI output while transcript persistence applies `before_message_write` separately; the related PR is open, conflicting, and targets removed pi-runner files.

## What This Changes

The issue asks for `agent --json` payloads to return the same post-`before_message_write` finalized assistant text that is persisted to the session transcript.

## Best Possible Solution

Update the current CLI result path to consume the same finalized assistant message accepted by transcript persistence, with explicit non-leaking behavior for hook-blocked replies.

## Reproduction Assessment

Yes, at source level. Current main applies `before_message_write` to transcript append and then returns `payloads` from `resultParams.output.text`; current tests also assert raw payload output when the hook blocks transcript persistence.

## Solution Assessment

Yes for the central result-parity direction, but the exact implementation needs maintainer judgment for blocked-hook output. The stale pi-runner PR is not the best fix because current main uses `src/agents/cli-runner.ts`.
