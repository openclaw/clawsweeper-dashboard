## Summary

Keep open. Current main still persists CLI assistant output through `before_message_write` while `agent --json` payloads are assembled from the original CLI output text, and the live candidate PR targets a removed runner tree rather than the current CLI path.

## What This Changes

The issue requests that `agent --json` return the same finalized assistant text that `before_message_write` writes to the session transcript.

## Best Possible Solution

Make the current CLI JSON result path return the finalized post-hook assistant text, and define a non-leaking JSON result shape for hook-blocked assistant output.
