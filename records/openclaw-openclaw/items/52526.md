## Summary

Keep open. Current main and the latest release still assemble `agent --json` payloads from raw CLI output while transcript persistence applies `before_message_write` separately, so the reported JSON/transcript mismatch remains; the open related PR targets a removed `pi-embedded-runner` path and is not a current-main fix.

## What This Changes

Ensure `agent --json` returns the finalized assistant message after `before_message_write` hooks instead of the pre-hook CLI output.

## Best Possible Solution

Make the current CLI JSON result path consume the same finalized assistant message accepted by the transcript write-hook path, with explicit non-leaking behavior for hook-blocked replies.

## Reproduction Assessment

Yes, at source level. Current main persists CLI assistant text through `beforeMessageWrite` and then builds returned `payloads` from raw `output.text`; I did not run a live plugin/CLI reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose blocked-hook JSON semantics. The best implementation should retarget the current CLI runner and transcript seam rather than the stale pi-runner PR path.
