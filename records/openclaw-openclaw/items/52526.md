## Summary

Keep open. Current main still has a source-level mismatch: CLI assistant persistence runs through `before_message_write`, but the `agent --json` result payload is built from the original CLI output text, and the linked PR is an obsolete conflicting candidate rather than a current-main fix.

## What This Changes

The issue requests that `agent --json` return the finalized assistant message after `before_message_write` hooks, matching the persisted transcript.

## Best Possible Solution

Make the current CLI JSON result path consume the finalized assistant message accepted by the transcript write-hook path, with explicit non-leaking behavior when the hook blocks output and focused regression coverage.
