## Summary

Keep open. Current main and the latest release still persist CLI assistant output through `before_message_write` while returning `agent --json` payloads from the raw CLI output, so the JSON/transcript mismatch remains valid.

## What This Changes

The issue requests that `agent --json` return the finalized assistant text after `before_message_write` hooks, matching the persisted transcript.

## Best Possible Solution

Make the current CLI JSON result path consume the same finalized assistant message accepted by transcript write hooks, with explicit non-leaking behavior for hook-blocked replies and focused regression plus live proof.

## Reproduction Assessment

Yes, at source level. Current main persists CLI assistant text through `beforeMessageWrite` and then builds returned payloads from raw `output.text`; I did not run a live plugin/CLI reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose blocked-hook JSON semantics. The best implementation should retarget the current CLI runner and transcript seam rather than the stale pi-runner PR path.
