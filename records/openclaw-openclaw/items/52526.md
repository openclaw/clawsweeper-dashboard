## Summary

Keep open. Current main and the latest release still build CLI JSON payloads from raw CLI output after separately persisting through `before_message_write`, and the linked PR targets the removed pi-runner tree rather than the current CLI path.

## What This Changes

Make `agent --json` return the finalized assistant message after `before_message_write` hooks, matching the persisted transcript instead of raw pre-hook text.

## Best Possible Solution

Make the current CLI JSON result path consume the same finalized assistant message accepted by the transcript write-hook path, with explicit non-leaking behavior for hook-blocked replies.

## Reproduction Assessment

Yes, at source level. Current main persists CLI assistant text through `beforeMessageWrite` and then builds returned `payloads` from raw `output.text`; I did not run a live plugin/CLI reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose blocked-hook JSON semantics. The best implementation should retarget the current `src/agents/cli-runner.ts` and transcript seam rather than the stale pi-runner PR path.
