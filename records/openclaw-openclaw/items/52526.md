## Summary

Keep open: current main still builds `agent --json` payloads from raw CLI output after separately attempting transcript persistence through `before_message_write`, so the reported JSON/transcript mismatch remains and the open related PR is not a viable current-main fix.

## What This Changes

The issue asks for `agent --json` to return the finalized assistant message after `before_message_write` hooks, matching the persisted transcript instead of stale pre-hook text.

## Best Possible Solution

Make the current CLI JSON result path consume the same finalized assistant message accepted by the transcript write-hook path, with explicit non-leaking behavior for hook-blocked replies.

- **Return only finalized hook output (recommended):** For rewrites, return the post-hook assistant text; for blocks, suppress raw assistant text and use a clear blocked/silent result shape with regression coverage.

- **Defer to broader hook unification:** Leave this issue open until the broader lifecycle-hook architecture chooses one result-finalization seam across CLI, Gateway, and channels.
