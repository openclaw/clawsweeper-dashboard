## Summary

Keep open. Current main and the latest release still build CLI JSON payloads from raw CLI output after separately applying `before_message_write` on the transcript append path, and the only linked fix PR is conflicting and targets removed pi-runner files rather than the live CLI runner.

## What This Changes

The issue asks for `agent --json` to return the finalized assistant message after `before_message_write` hooks, matching the persisted session transcript.

## Best Possible Solution

Make the current CLI JSON result path consume the finalized assistant message accepted by the transcript write-hook path, with explicit non-leaking behavior for hook-blocked replies.

## Reproduction Assessment

Yes, at source level. Current `main` persists CLI assistant text through `beforeMessageWrite` and then builds returned `payloads` from raw `output.text`; I did not run a live plugin/CLI reproduction in this read-only review.

## Solution Assessment

Unclear. A targeted current-main CLI result fix is the right boundary, but maintainers should first decide blocked-hook JSON semantics so raw text is not leaked after a hook block.
