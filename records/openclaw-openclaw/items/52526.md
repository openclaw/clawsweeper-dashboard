## Summary

Keep open. Current `origin/main` still builds CLI JSON `payloads` from raw CLI output after transcript persistence applies `before_message_write`, the latest release has the same result shape, and the only related PR targets a removed runner tree rather than the current CLI path.

## What This Changes

The issue asks for `agent --json` payload text to match the finalized assistant message after `before_message_write` hooks instead of returning pre-hook raw assistant text.

## Best Possible Solution

Make the current CLI JSON result path consume the same finalized assistant accepted by the transcript write-hook path, with explicit non-leaking behavior for hook-blocked replies and focused regression coverage.

Question: When `before_message_write` rewrites or blocks a CLI assistant message, what should `agent --json` expose to callers?

Rationale: The current behavior can leak text that a plugin blocked or rewrote before transcript persistence, but changing blocked-output shape is a public CLI/result contract and security-boundary choice.

Likely owner: steipete

Owner confidence: medium

Options:

- **Return finalized or suppressed output (recommended):** Use post-hook assistant text for rewrites and return a structured non-leaking blocked/suppressed result when the hook blocks persistence.
- **Thread hook output without transcript reread:** Expose the same hook result directly to the JSON builder, but still define the blocked-output contract before implementation.
- **Keep transcript-only semantics:** Document `before_message_write` as persistence-only and accept that `agent --json` may expose raw CLI output despite hook rewrites or blocks.
