## Summary

Keep open. Current main and the latest release still build `agent --json` payloads from raw CLI output while transcript persistence applies `before_message_write` separately, and the open related PR targets the removed `pi-embedded-runner` tree rather than the current CLI path.

## What This Changes

The issue reports that `agent --json` returns raw pre-hook assistant payload text instead of the assistant message finalized by `before_message_write` transcript hooks.

## Best Possible Solution

Make the current CLI JSON result path use the same finalized assistant message accepted by the transcript write-hook path, and define non-leaking output for hook-blocked replies.

## Reproduction Assessment

Yes, at source level. Current main persists CLI assistant text through `beforeMessageWrite` and then builds returned `payloads` from raw `output.text`; I did not run a live plugin/CLI scenario in this read-only review.

## Solution Assessment

Unclear until maintainers settle blocked-hook JSON semantics. The best fix should target the current `src/agents/cli-runner.ts` and transcript seam rather than the stale pi-runner PR path.
