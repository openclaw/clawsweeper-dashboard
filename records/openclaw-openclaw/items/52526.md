## Summary

Keep open. Current main and the latest release still assemble CLI JSON payloads from raw CLI output after separately persisting through `before_message_write`, so the JSON/transcript mismatch remains and the stale related PR does not supersede this issue.

## What This Changes

The issue reports that `agent --json` can return pre-hook assistant text instead of the `before_message_write`-finalized assistant message persisted to the session transcript.

## Best Possible Solution

Make the current CLI JSON result path consume the same hook-finalized assistant message accepted by the transcript seam, with explicit safe behavior for hook-blocked replies and regression coverage for rewrite and block cases.
