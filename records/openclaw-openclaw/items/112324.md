## Summary

The PR remains necessary: its submitted real-WebSocket evidence shows the current browser client can leave an unbounded Control UI request pending after a gateway goes silent, while this branch closes the dead transport and reconnects without interrupting the healthy-tick control case. The branch is behind current `main` and has an unfinished/failed CI surface, so it should stay open for rebase and current-head validation rather than be closed or auto-merged.

## What This Changes

This PR adds a browser-side gateway tick watchdog and real-transport regression coverage so Control UI requests do not remain pending after a silent gateway connection.

## System Context

The Control UI browser client sends Gateway protocol requests over a WebSocket and passes responses and events to UI features such as MCP app calls. The watchdog records inbound activity after the gateway hello exchange and closes a silent transport so the existing reconnect supervisor can reject stranded work and establish a new connection.
