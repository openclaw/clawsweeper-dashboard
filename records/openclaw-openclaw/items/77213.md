## Summary

The latest head should remain open: it fixes the startup-wide outage, but still breaks established automatic credential fallback and non-interactive reuse of SecretRef-backed profiles; the protected `maintainer` label also requires explicit maintainer handling.

## What This Changes

The PR isolates unresolved auth-profile SecretRefs during Gateway activation, materializes per-agent runtime auth snapshots, and propagates typed unavailable-owner errors through provider and agent-run auth resolution.

## Best Possible Solution

Keep owner-scoped startup isolation, but make unavailable profiles terminal only for an explicitly locked selection; automatic auth order should continue to healthy profiles and existing env/config fallbacks, while non-runtime setup gets a separate direct SecretRef resolver and focused regression coverage.
