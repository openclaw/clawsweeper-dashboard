## Summary

The PR has strong proof for keeping the Gateway ready when an auth-profile SecretRef fails, but the current head still changes documented automatic profile fallback and introduces setup-time, inherited-agent, and in-process credential-recovery regressions.

## What This Changes

Isolates stale auth-profile SecretRefs during runtime activation, publishes per-profile unavailable state, and makes request-time auth consume materialized runtime credentials.

## Best Possible Solution

Keep startup isolation, but distinguish runtime requests from setup callers, preserve documented auto-profile rotation and main-agent inheritance, and invalidate degraded state when the profile no longer references the failed SecretRef.
