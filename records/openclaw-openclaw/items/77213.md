## Label Justifications

- `P1`: The patch can turn one stale auth profile into an immediate failed agent request even when a healthy configured backup exists.
- `merge-risk: 🚨 compatibility`: Existing auth.order and auto-profile pools would change from ordered fallback to terminal failure on the first degraded SecretRef.
- `merge-risk: 🚨 auth-provider`: The patch changes credential selection and fallback behavior across provider-auth resolution paths.

## Summary

The prior P1 blocker remains: the current head makes an unavailable SecretRef terminal even for auto-selected profile candidates, while the documented contract rotates through healthy same-provider profiles and reserves strict failure for user-pinned profiles. ([docs.openclaw.ai](https://docs.openclaw.ai/model-failover?utm_source=openai))

## What This Changes

The PR assigns auth-profile SecretRefs to agent-scoped runtime owners, isolates failed owners during Gateway startup, and propagates typed unavailable errors through model-auth and agent-run credential resolution.

## Best Possible Solution

Keep owner-scoped startup degradation, but continue automatic candidate rotation for auth.order and auto-pinned profiles; return the typed terminal error only for an explicitly user-pinned profile, with live startup-and-request proof for both paths. ([docs.openclaw.ai](https://docs.openclaw.ai/model-failover?utm_source=openai))
