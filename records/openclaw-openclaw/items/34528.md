## Summary

Keep open: current main and the latest release still synthesize Feishu reaction-suffixed message IDs and pass raw reply targets into Feishu API `message_id` paths; the open same-repo candidate fix is https://github.com/openclaw/openclaw/pull/77653, so this issue should close only after that PR or a replacement lands.

## What This Changes

The issue requests stripping Feishu synthetic `:reaction:<emoji>:<uuid>` suffixes before those message IDs are used in Feishu API calls.

## Best Possible Solution

Land or replace the open Feishu plugin fix so API-bound message IDs are normalized to the base Feishu `om_*` ID while synthetic reaction IDs remain available for internal dedupe and session identity.
