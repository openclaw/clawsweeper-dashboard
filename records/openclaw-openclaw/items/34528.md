## Summary

Keep open: current main and the latest release still have a source-level Feishu path where synthetic reaction IDs can reach Feishu API `message_id` parameters, and https://github.com/openclaw/openclaw/pull/77653 is an open implementation candidate rather than a merged fix.

## What This Changes

The issue asks Feishu to strip OpenClaw's synthetic `:reaction:<emoji>:<uuid>` suffix before using a message ID in Feishu API calls.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/77653 with a narrow Feishu plugin fix that preserves internal synthetic reaction IDs for turn identity while normalizing every Feishu API-bound message ID to the base open message ID.
