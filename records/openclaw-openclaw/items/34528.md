## Summary

Keep open: current main and the latest release still have a source-level path where Feishu reaction synthetic IDs can reach Feishu API `message_id` parameters, and the open same-repo closing PR remains the implementation candidate rather than a merged fix.

## What This Changes

The issue reports that Feishu reaction synthetic message IDs with `:reaction:<emoji>:<uuid>` suffixes are passed to Feishu API endpoints and rejected with 400 invalid `open_message_id` errors.

## Best Possible Solution

Keep this issue open until the canonical Feishu normalization PR lands or is replaced by one narrow Feishu-owned fix that preserves synthetic IDs internally but normalizes base open message IDs at every Feishu API boundary.

## Reproduction Assessment

Yes, at source level: current main creates Feishu reaction synthetic IDs with a `:reaction:` suffix and can route caller-provided message IDs into Feishu API `path.message_id` fields without normalization. I did not run a live credentialed Feishu reaction flow in this read-only review.

## Solution Assessment

Yes: the best fix is Feishu-local API-boundary normalization that strips the synthetic suffix only before Feishu API calls while preserving suffixed IDs for internal dedupe and session uniqueness. The open closing PR is the current candidate, but it still needs refresh and real behavior proof before merge.
