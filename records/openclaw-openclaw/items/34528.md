## Summary

Keep open: current main and the latest release still create Feishu synthetic reaction IDs with a suffix and can pass those IDs into Feishu API message_id fields, while the same-repo candidate fix remains open and unmerged.

## What This Changes

The issue asks OpenClaw to strip Feishu synthetic reaction suffixes from message_id values before using them in Feishu API calls.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/77653 so internal synthetic reaction IDs remain available for dedup/session identity while every Feishu API-bound open-message ID is normalized to the base Feishu message ID.

## Solution Assessment

Yes. Normalizing only Feishu API-bound open-message IDs while preserving synthetic IDs for internal event identity is the narrow maintainable fix direction; current main lacks that normalization and the open linked PR targets it.
