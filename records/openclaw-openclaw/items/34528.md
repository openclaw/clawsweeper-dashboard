## Summary

Keep open: current main and latest release still allow Feishu reaction synthetic IDs to reach Feishu API message_id parameters, and an open same-repo closing PR remains the implementation candidate rather than a merged fix.

## What This Changes

The issue requests stripping OpenClaw's synthetic `:reaction:<emoji>:<uuid>` suffix before Feishu API calls while preserving the synthetic ID for internal reaction handling.

## Best Possible Solution

Keep this issue open until https://github.com/openclaw/openclaw/pull/77653 lands or is replaced by a narrow Feishu-owned normalization fix that covers all API-bound message_id paths and preserves internal synthetic reaction ids.

## Reproduction Assessment

Yes, at source level: current main creates Feishu reaction synthetic IDs with a `:reaction:` suffix and can route that value into Feishu API `path.message_id` fields without normalization. I did not run a live Feishu tenant reproduction in this read-only review.

## Solution Assessment

Yes: the best fix is Feishu-local API-boundary normalization that strips only the synthetic suffix before Feishu API calls while preserving suffixed IDs for internal dedupe and session uniqueness. The open closing PR is the current candidate, but it needs refresh and real behavior proof before merge.
