## Label Justifications

- `P2`: The bug breaks Feishu reaction-triggered replies and API-backed actions for affected channel users, but it is scoped to one plugin path.
- `impact:message-loss`: A reaction-triggered Feishu turn can fail to deliver a visible reply or action when the suffixed synthetic ID is sent to Feishu.

## Summary

Keep open: current main and the latest release still expose a Feishu path where synthetic reaction IDs can reach Feishu API `message_id` parameters, and the open same-repo closing PR is an implementation candidate rather than a merged fix.

## What This Changes

The issue asks Feishu API-bound message IDs to strip OpenClaw's synthetic `:reaction:<emoji>:<uuid>` suffix while preserving synthetic IDs for internal reaction event identity.

## Best Possible Solution

Land or replace the canonical Feishu plugin fix so internal synthetic IDs remain unique for turns and dedupe while every Feishu API-bound message ID is normalized to the base open message ID.

## Reproduction Assessment

Yes. The current source still creates suffixed Feishu reaction IDs and forwards caller-provided message IDs into Feishu API `path.message_id` fields without normalization; I did not run a credentialed live Feishu tenant flow in this read-only review.

## Solution Assessment

Yes. The best fix is a Feishu-local API-boundary normalizer that strips only the synthetic reaction suffix before Feishu API calls while preserving internal suffixed IDs for turn identity and dedupe.
