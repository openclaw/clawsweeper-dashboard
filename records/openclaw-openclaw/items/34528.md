## Summary

Keep open: current main and the latest release still have a source-level path where Feishu synthetic reaction IDs can reach Feishu API `message_id` parameters, and https://github.com/openclaw/openclaw/pull/77653 is an open closing fix candidate rather than a merged implementation.

## What This Changes

Strip Feishu synthetic `:reaction:<emoji>:<uuid>` suffixes before using message IDs in Feishu API calls while preserving the synthetic IDs for internal reaction turns.

## Best Possible Solution

Keep this issue open until the canonical Feishu normalization PR lands with proof, or until maintainers close that PR and replace it with one narrow Feishu-owned normalizer fix.

## Reproduction Assessment

Yes, at source level: current main creates a suffixed Feishu reaction synthetic ID and can route `ctx.messageId` into Feishu reply/message API paths without normalization. I did not run a live credentialed Feishu tenant flow in this read-only review.

## Solution Assessment

Yes: the best fix shape is to preserve synthetic IDs for OpenClaw dedupe/session state but normalize to the base Feishu open message ID at Feishu API boundaries. The open canonical PR is attempting that owner-local fix and should be reviewed or replaced, not bypassed by a new issue repair job.
