## Summary

Keep open: current main and latest release still have a source-level Feishu path where synthetic reaction IDs can reach Feishu API `message_id` parameters, and https://github.com/openclaw/openclaw/pull/77653 is an open implementation candidate rather than a merged fix.

## What This Changes

Feishu reaction events can generate synthetic `message_id` values with `:reaction:<emoji>:<uuid>` suffixes that should not be sent back to Feishu API `message_id` parameters.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/77653 with a narrow Feishu plugin fix that preserves internal synthetic reaction IDs for turn identity while normalizing every Feishu API-bound message ID to the base open message ID.

## Maintainer Decision

## Reproduction Assessment

Yes, at source level. Current main still synthesizes `om_*:reaction:*` IDs and can forward raw message IDs into Feishu API `path.message_id` fields, though I did not run a credentialed live Feishu tenant flow.

## Solution Assessment

Yes. The best fix is a Feishu-local API-boundary normalizer that strips only OpenClaw's synthetic reaction suffix before Feishu calls while preserving internal suffixed IDs for turn identity and dedupe.
