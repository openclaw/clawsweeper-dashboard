## Summary

Keep open: current main and the latest release still expose the Feishu reaction-suffix API path, and the open same-repo closing PR is an implementation candidate rather than a merged fix.

## What This Changes

The issue asks OpenClaw to strip Feishu synthetic `:reaction:<emoji>:<uuid>` suffixes from API-bound message IDs while preserving valid base open message IDs.

## Best Possible Solution

Review, refresh, and land or replace the open Feishu normalization PR so synthetic reaction IDs remain internal while every Feishu API-bound message ID uses the base `open_message_id`.

## Reproduction Assessment

Yes. Current source creates Feishu reaction synthetic IDs with a `:reaction:` suffix and can route those IDs into Feishu API `message_id` parameters without normalization; I did not run a credentialed live Feishu tenant flow in this read-only review.

## Solution Assessment

Yes. The best fix is a Feishu-local API-boundary normalizer that strips only the synthetic reaction suffix before Feishu API calls while preserving internal suffixed IDs for turn identity and dedupe.
