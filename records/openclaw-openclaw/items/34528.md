## Summary

Keep open: current main and the latest release still have a source-level path where a Feishu reaction synthetic ID can become the Feishu reply target, and the same-repo closing PR is still open rather than merged.

## What This Changes

The issue requests stripping Feishu synthetic reaction suffixes from Feishu API-bound message IDs while preserving synthetic IDs for internal reaction turns.

## Best Possible Solution

Land a narrow Feishu plugin fix that normalizes API-bound open message IDs while keeping synthetic reaction IDs for internal dedupe/session identity, then close this issue after the merge.

## Reproduction Assessment

Yes at source level: generate a Feishu reaction event without `reply_target_message_id`; current main creates a suffixed synthetic `message_id`, defaults the reply target to it, and passes it to Feishu reply APIs. I did not run a live Feishu tenant repro in this read-only sweep.

## Solution Assessment

Yes: keeping this issue open is the right cleanup decision until the linked closing PR merges. The maintainable fix should normalize only Feishu API-bound IDs, not remove synthetic reaction IDs from internal event identity.
