## Summary

Keep open: current main and v2026.6.11 still have a source-level path where Feishu synthetic reaction IDs can reach Feishu API `message_id` parameters, and the remaining implementation path is the open candidate at https://github.com/openclaw/openclaw/pull/77653.

## What This Changes

Feishu reaction-generated synthetic message IDs should be normalized before Feishu API calls so reaction-triggered replies and actions use the base `open_message_id`.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/77653 with a narrow Feishu plugin fix that preserves internal synthetic reaction IDs for turn identity while normalizing every Feishu API-bound message ID to the base open message ID.

Yes. The best fix is a Feishu-local API-boundary normalizer that strips only OpenClaw's synthetic reaction suffix before Feishu calls while preserving internal suffixed IDs for turn identity and dedupe.
