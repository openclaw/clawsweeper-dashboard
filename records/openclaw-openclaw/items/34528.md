The issue asks Feishu to strip OpenClaw's synthetic `:reaction:<emoji>:<uuid>` suffix before using reaction message IDs in Feishu API calls.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/77653 so internal synthetic reaction IDs remain available for dedup/session identity while every Feishu API-bound open-message ID is normalized to the base Feishu message ID.
