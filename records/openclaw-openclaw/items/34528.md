## Summary

Keep open: current main and the latest release still have a Feishu source path where synthetic reaction IDs can reach API-bound `message_id` parameters, and https://github.com/openclaw/openclaw/pull/77653 remains the open unmerged closing fix candidate.

## What This Changes

The issue requests stripping OpenClaw's synthetic `:reaction:<emoji>:<uuid>` suffix from Feishu message IDs before calling Feishu APIs.

## Best Possible Solution

Refresh or replace the open Feishu fix candidate, keep the Feishu-owned API-boundary normalizer, and add redacted real Feishu proof showing reaction-triggered replies/actions use the base Open Message ID while synthetic IDs remain internal.

## Reproduction Assessment

Yes. Source inspection shows a Feishu reaction event can produce a suffixed synthetic `message_id`, the bot path can use that as the reply target, and current Feishu API calls pass the target through without normalization.

## Solution Assessment

Yes, the best fix shape is Feishu-local API-boundary normalization, not removing synthetic IDs from internal dedupe/session identity. The open linked PR owns that direction, so this issue should stay open until that PR lands or is replaced.
