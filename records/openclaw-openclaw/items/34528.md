## What This Changes

The issue reports that Feishu reaction synthetic message IDs with a `:reaction:<emoji>:<uuid>` suffix are passed to Feishu APIs, causing invalid `open_message_id` 400 errors.

## Best Possible Solution

Land or replace the Feishu plugin fix so internal synthetic reaction IDs remain available for dedupe/session identity while every Feishu API-bound open-message ID is normalized to the base Feishu message ID.
