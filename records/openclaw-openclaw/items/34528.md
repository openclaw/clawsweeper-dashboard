## Label Justifications

- `P2`: This is a scoped Feishu plugin bug affecting reaction-triggered delivery rather than a whole-core outage.
- `impact:message-loss`: A Feishu reaction-triggered turn can fail to deliver the intended reply or API-backed action when a suffixed synthetic message ID is sent to Feishu.

## Summary

Keep open: current main and the latest release still have a source-level path where Feishu reaction synthetic IDs can become API-bound message IDs, and https://github.com/openclaw/openclaw/pull/77653 remains the open closing fix candidate rather than a merged implementation.

## What This Changes

Feishu reaction events can create synthetic message IDs with a `:reaction:<emoji>:<uuid>` suffix that later reach Feishu API calls expecting the base Open Message ID.

## Best Possible Solution

Keep this issue open until the canonical Feishu normalization PR lands with proof, or close that PR and replace it with one narrow Feishu-owned fix that normalizes IDs at API boundaries while preserving synthetic IDs internally.

## Reproduction Assessment

Yes at source level: current main still creates suffixed Feishu reaction synthetic IDs and can use `ctx.messageId` as the default API-bound reply target. I did not run a live credentialed Feishu flow in this read-only review.

## Solution Assessment

Yes: the best fix is still an owner-local Feishu normalizer that preserves synthetic IDs for internal dedupe/session identity but strips them before Feishu API calls. The open closing PR is the current candidate for that path.
