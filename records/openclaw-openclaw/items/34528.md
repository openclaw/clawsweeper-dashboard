## Summary

Keep open: current main and the latest release still create suffixed Feishu synthetic reaction IDs and can pass them into Feishu API `message_id` fields. The open same-repo candidate fix is https://github.com/openclaw/openclaw/pull/77653, so this issue should close only after that PR or a replacement lands.

## What This Changes

The issue reports that Feishu reaction synthetic message IDs with `:reaction:*` suffixes are reused in Feishu API calls and rejected with 400 responses.

## Best Possible Solution

Land or replace the open Feishu plugin fix so internal synthetic reaction IDs remain available for dedup/session identity while every Feishu API-bound open-message ID is normalized to the base Feishu message ID.
