## Summary

Keep open: current main and the latest release still create Feishu reaction-suffixed synthetic message IDs and can pass raw reply targets into Feishu API `message_id` parameters; the open same-repo fix candidate is https://github.com/openclaw/openclaw/pull/77653, so this issue should close only after that PR or a replacement lands.

## What This Changes

Reported Feishu reaction events generate synthetic `message_id` values with a `:reaction:` suffix that later reach Feishu API calls and are rejected with 400 errors.

## Best Possible Solution

Land or replace the open Feishu plugin fix so OpenClaw preserves synthetic reaction IDs for internal dedupe/session identity while normalizing every Feishu API-bound open message ID to the base Feishu `om_*` ID.
