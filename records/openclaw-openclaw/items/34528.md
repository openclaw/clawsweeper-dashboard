## Summary

Keep open: current main and the latest release still allow a Feishu synthetic reaction message ID to flow into Feishu API `message_id` paths, and the open same-repo fixing PR is an implementation candidate rather than a merged fix.

## What This Changes

The issue asks OpenClaw to strip Feishu synthetic `:reaction:<emoji>:<uuid>` suffixes before using message IDs in Feishu API calls.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/77653 with a narrow Feishu plugin fix that preserves internal synthetic IDs for turn identity while normalizing every Feishu API-bound message ID to the base open message ID.

## Solution Assessment

Yes. The best fix is a Feishu-local API-boundary normalizer that strips only OpenClaw's synthetic reaction suffix before Feishu calls while preserving internal suffixed IDs for turn identity and dedupe.
