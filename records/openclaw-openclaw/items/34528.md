Feishu reaction-triggered synthetic message IDs with a `:reaction:` suffix should be stripped or normalized before Feishu API `message_id` calls.

## Best Possible Solution

Land or replace the open Feishu plugin fix so internal synthetic reaction IDs remain available for dedupe/session identity while every Feishu API-bound open-message ID is normalized to the base Feishu message ID.
