## Label Justifications

- `P2`: This is a bounded Feishu channel bug that can break reaction-triggered replies/API calls but does not make the core runtime unusable.
- `impact:message-loss`: Reaction-triggered Feishu replies or lookups can fail with 400 responses when a suffixed synthetic ID is used as an API message ID.

## Summary

Keep open: current main and v2026.6.11 still preserve Feishu reaction synthetic IDs with the `:reaction:<emoji>:<uuid>` suffix and can pass that value into Feishu `message_id` API parameters; the open same-repo fix PR remains the implementation candidate, not a merged fix.

## What This Changes

The issue asks OpenClaw to strip Feishu reaction suffixes from synthetic message IDs before using them in Feishu API calls.

## Best Possible Solution

Keep the synthetic reaction ID for OpenClaw-internal dedupe/session identity, but normalize to the base Feishu open message ID at every Feishu API boundary with focused regression coverage.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: a reaction event creates a suffixed synthetic `message_id`, `ctx.messageId` preserves it, and the reply path can send it as Feishu `path.message_id`; I did not run a live Feishu tenant repro.

## Solution Assessment

Yes, the reported fix direction is the narrow maintainable path, but it is not implemented on current main. The best shape is boundary normalization, not removing synthetic IDs, because internal dedupe/session routing still needs unique reaction turns.
