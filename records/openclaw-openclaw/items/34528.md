## What This Changes

The issue reports Feishu reaction synthetic `message_id` values leaking into Feishu API calls instead of using the base Open Message ID.

## Best Possible Solution

Keep this issue open until https://github.com/openclaw/openclaw/pull/77653 lands with adequate proof, or until maintainers replace it with one focused Feishu-owned normalizer that preserves synthetic IDs internally and uses base Open Message IDs at Feishu API boundaries.

## Solution Assessment

Yes: the maintainable fix is to preserve synthetic IDs for OpenClaw dedupe/session state but normalize to the base Feishu Open Message ID at Feishu API boundaries. The open linked PR is attempting that owner-local shape and should remain the review path.
