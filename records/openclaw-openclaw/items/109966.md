## Summary

The current head still has a concrete reconnect defect: clients can treat an empty, incomplete `activeRunIds` list as terminal evidence and erase a valid active plan. The earlier retryable-lifecycle finding is not repeated, but this current-head blocker and missing after-fix real behavior proof prevent a pass; the protected `maintainer` label also keeps final handling explicit.

## What This Changes

Adds per-run plan snapshots to gateway in-flight chat recovery and reconciles them after reconnect or refresh in the web, Apple, and Android chat clients.

## Best Possible Solution

Keep the established `inFlightRun` recovery pipeline, but make every client preserve same-run plans while `hasActiveRun` is true and the ID set is empty or incomplete; clear only on explicit empty snapshots, authoritative terminal state, confirmed different-run ownership, or scope reset, then prove a real reconnect on at least one client.
