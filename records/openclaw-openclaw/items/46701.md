## Summary

Keep open: current main and v2026.6.11 still treat a non-allowlisted Telegram group sender as a silent authorization denial, while the requested sender-facing reply would change a security-sensitive group authorization boundary and needs maintainer product/security direction.

## What This Changes

The issue requests a Telegram group allowlist denial reply that tells unauthorized senders how to contact an admin and includes their Telegram user ID.

## Best Possible Solution

Define a Telegram-owned, opt-in denied-sender notice that is topic-aware, rate-limited, privacy-documented, configurable for admin-contact wording, and keeps silent fail-closed behavior as the default unless maintainers choose otherwise.
