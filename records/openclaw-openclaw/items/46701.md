## Summary

Keep open: current main and the latest release still silently deny ordinary Telegram group messages from non-allowlisted senders, and adding sender-facing denial replies needs explicit product/security direction before implementation.

## What This Changes

Request that Telegram send a friendly admin-contact auto-reply with the sender's numeric Telegram user ID when `groupPolicy`/`groupAllowFrom` denies a group sender.

## Best Possible Solution

Define a Telegram-owned, opt-in denied-sender notice with topic-safe delivery, per-sender cooldown, configurable admin-contact wording, documented raw-ID behavior, and silent denial as the default unless maintainers choose otherwise.
