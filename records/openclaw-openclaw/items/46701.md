## Summary

Keep open: current main and the latest release still deny non-allowlisted Telegram group senders silently, and the requested visible reply changes Telegram authorization UX, spam-amplification behavior, raw ID disclosure, and likely config surface.

## What This Changes

The issue requests an automatic Telegram group reply for senders blocked by `groupAllowFrom`/`groupPolicy`, including instructions to contact an admin with their Telegram user ID.

## Best Possible Solution

Define a Telegram-owned, opt-in denied-sender notice with topic-aware delivery, per-sender cooldown, configurable admin-contact text, documented raw-ID handling, and default silent fail-closed behavior unless maintainers choose otherwise.
