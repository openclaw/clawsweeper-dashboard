## Summary

Keep open: current main and v2026.6.11 still block non-allowlisted Telegram group senders by returning from the group-deny path without the requested onboarding reply. Related Telegram/group-security issues cover owner notifications, unknown-group warn/leave, audit visibility, or broader group pairing, but none replaces this exact sender-facing authorization notice; the remaining blocker is product/security direction for opt-in behavior, rate limiting, and ID disclosure.

## What This Changes

The issue requests a Telegram group auto-reply for senders rejected by `groupAllowFrom`/`groupPolicy`, including admin-contact instructions and the sender's Telegram user ID.

## Best Possible Solution

Add a Telegram-owned, default-silent, explicit opt-in unauthorized-group-sender notice that is topic-aware, rate-limited, privacy-documented, configurable for safe wording/admin contact, and tested separately from DM pairing and native command auth replies.

## Reproduction Assessment

Yes, at source level: a Telegram group sender not matching `groupAllowFrom` reaches `group-policy-allowlist-unauthorized`, and the handler returns before any reply dispatch. Existing tests assert zero replies for the blocked group-sender path.

## Solution Assessment

Unclear as requested: the auto-reply addresses a real onboarding cliff, but making it default would be risky. The safer direction is an explicit, rate-limited Telegram policy with documented privacy behavior and configurable admin-contact wording.
