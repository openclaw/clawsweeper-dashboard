## Summary

Keep open: current main and the latest release still silently drop Telegram group messages from senders rejected by groupAllowFrom/groupPolicy, and this is not fully covered by the broader owner-audit or group-pairing issues. The next step is maintainer product/security direction because a sender-facing denial reply changes a fail-closed authorization boundary into visible group output.

## What This Changes

The issue requests a Telegram group onboarding reply for users blocked by groupAllowFrom/groupPolicy, including their Telegram user ID and admin-contact guidance.

## Best Possible Solution

Define a Telegram-owned, opt-in denied-sender notice with topic-safe delivery, cooldown/rate limiting, configurable admin-contact wording, documented raw-ID handling, and silent denial as the default unless maintainers choose otherwise.
