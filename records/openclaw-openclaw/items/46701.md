## Summary

Keep open: current main and v2026.6.11 still silently reject non-allowlisted Telegram group senders, and adding a sender-facing reply changes a security-sensitive authorization boundary that needs maintainer product/security direction.

## What This Changes

The issue requests a Telegram group reply that tells non-allowlisted senders how to contact an admin with their Telegram user ID.

## Best Possible Solution

Define a Telegram-owned opt-in denied-sender notice with topic-safe delivery, per-sender cooldown, configurable admin-contact wording, documented raw-ID handling, and silent denial as the default unless maintainers choose otherwise.
