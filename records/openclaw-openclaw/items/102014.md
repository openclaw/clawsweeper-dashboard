## Summary

Keep open: current main still records normal-path `session.ended` immediately after `model.completed` and before attempt cleanup, so the reported timestamp behavior remains plausible from source. The attached patch zip in the discussion was not needed for this verdict; source inspection confirms the lifecycle placement issue without executing untrusted attachments.

## What This Changes

The issue reports that trajectory `session.ended` timestamps match the final `model.completed` timestamp instead of the actual session shutdown time.

## Best Possible Solution

Move `session.ended` emission to the real post-cleanup lifecycle boundary while preserving terminal status data, then add focused coverage proving it is emitted after cleanup work rather than immediately after model completion.

## Solution Assessment

Yes, the best fix is to record `session.ended` at the real attempt cleanup boundary using already-computed terminal data, not to add exporter-side timestamp rewriting or a new configuration knob.
