## Summary

Keep open. Current main still lacks a stdin stream error listener in the Docker sandbox helper, while this PR routes stdin through the same first-error-and-terminate lifecycle already used for stdout/stderr, with focused regression coverage and real behavior proof; I found no blocking findings.

## What This Changes

The branch adds stdin stream error handling to `execDockerRaw` and updates Docker sandbox tests/mocks so stdin, stdout, and stderr stream errors reject and terminate the Docker child.

## Best Possible Solution

Land this narrow boundary fix after required exact-head CI completes, keeping Docker stdio failure handling centralized in `execDockerRaw`.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current main has no stdin stream error listener in `execDockerRaw`, while Node defines child stdin as a Writable stream that can emit `error`; the PR body also reports a live injected-stdin-error proof run.

## Solution Assessment

Yes. The best fix is to attach stdin to the existing first-error Docker stream lifecycle at the low-level helper, because per-caller handling would duplicate process-state rules and leave sibling Docker callers inconsistent.
