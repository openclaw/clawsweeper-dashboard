## Summary

No blocking findings. The PR is still necessary because current main handles stdout/stderr stream errors in `execDockerRaw` but not stdin; the branch extends the same first-error lifecycle to stdin and has focused regression plus live-output proof.

## What This Changes

The PR attaches Docker child stdin stream errors to the existing stdio first-error handler and updates Docker sandbox tests/mocks to cover stdin, stdout, and stderr rejection with child termination.

## Best Possible Solution

Land this narrow helper-level fix after required exact-head CI and maintainer review, keeping Docker stdio failure handling centralized in `execDockerRaw`.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current main has no stdin stream error listener in `execDockerRaw`, while Node defines child stdin as a Writable stream that can emit `error`; the PR body also reports a live injected-stdin-error proof run.

## Solution Assessment

Yes. The best fix is to attach stdin to the existing first-error Docker stream lifecycle at the low-level helper, because per-caller handling would duplicate process-state rules and leave sibling Docker callers inconsistent.
