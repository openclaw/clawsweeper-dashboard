## Label Justifications

- `P0`: The PR targets a released upgrade crash-loop that can make the Gateway unusable, but the recovery must not introduce stale memory state.
- `merge-risk: 🚨 compatibility`: The change alters how existing upgraded databases resolve divergent persisted legacy and canonical rows and when legacy tables are dropped.

## Summary

The prior proof gap is resolved, but the patch can create a mixed canonical/legacy index: a conflicting canonical source row may remain while non-colliding legacy chunks for that source are inserted, allowing stale legacy text to remain searchable.

## What This Changes

Changes same-file legacy memory-index migration to preserve canonical rows on identity collisions, import non-colliding legacy rows, drop legacy tables, and retain rollback for uncopyable rows.

## Best Possible Solution

When any same-file identity has divergent values, keep the canonical index as one coherent unit by rolling back or avoiding all legacy inserts, then drop the superseded legacy tables; retain structural-failure rollback and add a conflicting-file plus distinct-stale-chunk regression.
