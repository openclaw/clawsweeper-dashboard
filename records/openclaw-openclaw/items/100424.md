## Summary

Keep open: current main and v2026.6.11 still route IPv6-only pinned DNS answers through the SSRF guarded-fetch dispatcher, and the linked fixing PR is open, unmerged, and already reviewed as not merge-ready.

## What This Changes

The issue reports that an IPv6-only DNS result on a host without IPv6 routing can emit an unhandled socket error from the SSRF guarded fetch path and kill the gateway process.

## Best Possible Solution

Fix the shared SSRF guarded-fetch dispatcher so IPv6-only connection failures reject as normal fetch/tool errors while preserving DNS pinning for direct, env-proxy, and explicit-proxy paths, then land the linked or replacement PR with Linux/Docker proof.
