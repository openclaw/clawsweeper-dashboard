- `maturity:stable`: The issue affects `gateway-runtime` and `linux-gateway-host`, both listed as M4 Stable by the maturity shortlist.

## Summary

Keep open: current main and v2026.6.11 still route IPv6-only DNS answers through the SSRF pinned dispatcher, so the reported gateway-killing socket-error path is not proven fixed by the earlier dual-stack mitigation.

## What This Changes

The issue requests that SSRF-guarded outbound fetches reject IPv6-only socket failures as fetch/tool errors instead of letting an unhandled TLSSocket error terminate the gateway process.

## Best Possible Solution

Fix the shared SSRF guarded-fetch dispatcher so IPv6-only connection failures reject and clean up like normal fetch failures while preserving DNS pinning and private-network blocking.
