## What This Changes

The issue reports that SSRF-wrapped outbound fetches can emit an unhandled TLSSocket error for IPv6-only DNS answers on IPv4-only hosts, killing the gateway instead of returning a rejected fetch/tool error.

## Best Possible Solution

Repair the shared SSRF guarded-fetch dispatcher so IPv6-only connection failures reject without process exit while preserving DNS pinning and private-network blocking, then land it with live or equivalent focused proof.
