- **[P1] Preserve Codex install records from setup ensure:** `src/crestodian/setup-inference.ts:357-362`
  - body: When the Codex candidate requires install or repair, `ensureCodexRuntimePluginForModelSelection` returns the config containing install records and load metadata, but this branch discards it and only enables `codex` on the current config. That can persist the Codex-routed default model without the durable plugin record needed for the first post-onboarding run to load the harness.
  - confidence: 0.9
- **[P2] Reset AI setup when the gateway target changes:** `apps/macos/Sources/OpenClaw/OnboardingView+Actions.swift:8-14`
  - body: This prior blocker is still present. After one target verifies successfully, changing to local or another remote gateway leaves the same `aiSetup.connected` and one-shot `startIfNeeded()` state in place, so the new target can skip its own live inference check and reach chat unverified.
  - confidence: 0.91
- **[P2] Roll back manual keys on persistence failures:** `src/crestodian/setup-inference.ts:364-372`
  - body: This prior blocker is still present. For manual API keys, the profile is staged before the live test, but failures after the test succeeds, such as `updateConfig` or `applySetup` throwing, leave the newly staged profile behind and can overwrite a previous working key.
  - confidence: 0.9
- **[P2] Mark setup activation as a control-plane write:** `src/gateway/methods/core-descriptors.ts:71`
  - body: This prior blocker is still present. `crestodian.setup.activate` runs a long live model test and then mutates gateway-wide config/auth state, but without `controlPlaneWrite: true` it bypasses the shared write budget used by config/auth mutations.
  - confidence: 0.89
- **[P2] Gate manual activation on all busy states:** `apps/macos/Sources/OpenClaw/OnboardingAISetup.swift:259-263`
  - body: This prior blocker is still present. Manual submission only checks `manualTesting`, and the button is not disabled by `isBusy`; if the manual form is visible while a candidate retry starts, a second activate RPC can race it, and manual testing also skips the window close confirmation.
  - confidence: 0.87
- **[P2] Use the staged auth store for manual tests:** `src/crestodian/setup-inference.ts:478-491`
  - body: Manual API keys are staged under the configured default agent directory, but the verification run is launched as `agentId: "crestodian"` without passing that same agentDir. On installs whose default agent is not Crestodian's runtime agent, the live test can miss the key that was just staged and reject a valid manual key.
  - confidence: 0.84
- **[P2] Stage manual keys under a temporary profile:** `src/crestodian/setup-inference.ts:411-414`
  - body: The current staging path upserts `${provider}:manual` before verification passes, so an existing selected manual profile is replaced while the test is in flight and unrelated runs can read the unverified key. Stage under a unique temporary profile and promote it only after the activation is durably committed.
  - confidence: 0.86
