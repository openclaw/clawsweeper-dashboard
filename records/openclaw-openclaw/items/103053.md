## Summary

The issue remains valid on current `main`: `/mcp show` still serializes configured MCP server objects into reply text without redacting credential-bearing fields or routing sensitive output away from groups. This should stay open and be handled as a security-sensitive fix path.

## What This Changes

The issue requests that `/mcp show` stop exposing raw MCP server credentials in group/channel replies by redacting sensitive fields, routing sensitive output privately, or both.

## Best Possible Solution

Redact secret-bearing MCP fields before rendering `/mcp show` output, and use the existing private-route pattern for group invocations so group replies never contain raw server definitions.
