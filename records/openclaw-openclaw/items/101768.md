## Summary

Keep open: current main still drops protocol-valid zero values from SDK normalized event IDs, and the latest release has the same behavior. The fix is narrow and source-proven, but it still needs an implementation PR with focused regression coverage.

## What This Changes

The issue asks OpenClaw to preserve protocol-valid zero `seq` values in SDK normalized gateway event IDs so replay/dedupe identity stays stable.

## Best Possible Solution

Preserve finite zero values in `normalizeGatewayEvent()` IDs while omitting only absent optional parts, with a focused regression test for `seq: 0` and `ts: 0`.

## Repair Work Prompt

Fix the SDK normalized gateway event ID construction so protocol-valid zero sequence values are preserved. In `packages/sdk/src/normalize.ts`, replace Boolean-based ID part filtering with logic that skips only absent optional values while retaining numeric `0` for `event.seq` and payload `ts`. Add a focused regression test in `packages/sdk/src/normalize.test.ts` that calls `normalizeGatewayEvent()` with an agent event using `seq: 0`, `runId: "r1"`, `sessionKey: "main"`, and `ts: 0`, then asserts the generated ID includes the leading zero sequence component. Do not change gateway protocol schemas, SDK public type names, or unrelated event classification behavior.
