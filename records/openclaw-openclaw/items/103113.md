## What This Changes

Repairs web-fetch provider resolution so an unavailable provider retained only in runtime metadata falls back to the current auto-detected provider, while explicit provider requests remain strict and provider-facing credential metadata is normalized only for that fallback.

## System Context

Web fetch chooses a provider from explicit request parameters, saved runtime metadata, or automatic discovery, then passes provider-facing runtime metadata to the selected provider's tool implementation. This change affects whether stale remembered provider state disables web fetch and what credential-selection context the recovered provider receives.
