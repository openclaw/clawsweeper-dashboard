## Summary

Keep open: the PR is a focused fix in the right resolver path, but it is not merge-ready because the new fallback can select the auto-detected provider while still passing stale `runtimeMetadata.selectedProvider` to provider code. The PR also has unit/mock proof only, not after-fix real `web_fetch` behavior proof.

## What This Changes

The PR changes shared web provider resolution and tests so stale runtime-selected web-fetch providers can fall back to auto-detection while direct `providerId` requests remain strict.

## Best Possible Solution

Make provider selection and provider-facing runtime metadata coherent: when stale runtime metadata falls back to auto-detect, pass metadata that reflects the actual selected provider or omits the stale selection, then add redacted live/terminal proof of the `web_fetch` recovery path.

Yes from source inspection: current main chooses `runtimeMetadata.selectedProvider` before auto-detect and returns null if that stale id is not in the available providers. I did not run the PR's regression test in this read-only review.

## Solution Assessment
