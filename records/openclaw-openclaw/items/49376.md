## Summary

Keep open: current main and the latest stable release still lack a configurable main-LLM retry/backoff contract, while existing code only covers adjacent cron retry, auth-profile rotation, short-window rate-limit retry, and provider-operation retry helpers.

## What This Changes

The issue requests configurable retry/backoff for main LLM requests on transient provider errors such as overloaded, server, network, and timeout failures.

## Best Possible Solution

Define one maintainer-approved LLM retry contract, then wire schema, docs, runtime retry behavior, idempotency and fallback ordering, user-visible retry status, and focused tests together.
