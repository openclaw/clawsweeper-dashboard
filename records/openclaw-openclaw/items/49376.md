## Summary

Keep open: current main has provider failover, SDK retry-after caps, and lower-level transient retry helpers, but it still lacks the requested public retry/backoff contract for main LLM conversation requests; the open related PR is partial and still needs maintainer API/runtime direction.

## What This Changes

Requests configurable agent/global or provider-level LLM retry with backoff for transient overloaded, server, timeout, and network errors on main conversation requests.

## Best Possible Solution

Define one maintainer-approved main-LLM retry contract, then wire it through config schema/types, runtime idempotency guards, fallback ordering, docs, generated config baselines, and focused provider-overload tests.
