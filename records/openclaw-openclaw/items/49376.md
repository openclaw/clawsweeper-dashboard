## Summary

Keep open: current main and v2026.6.11 still lack the requested configurable main-LLM retry/backoff contract, and the related open PRs are partial groundwork rather than a safe replacement for this canonical product/API thread.

## What This Changes

Request an agent-level or global configurable retry-with-backoff policy for main LLM requests on transient provider errors such as overloaded, 5xx, network, and timeout failures.

## Best Possible Solution

Settle the opt-in retry contract, then implement it in the embedded runner/fallback layer with additive config schema, docs, focused tests, upgrade-safe defaults, idempotency safeguards, and clear interaction with SDK retry caps, auth cooldowns, and model fallback.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature/config request. Source and docs inspection shows the requested configurable main-LLM retry policy is absent on current main and v2026.6.11.

## Solution Assessment

Unclear until maintainers choose the product contract. An opt-in retry policy is plausible, but it must fit existing SDK retry caps, auth-profile cooldowns, model fallback, timeout behavior, idempotency, and notification semantics.
