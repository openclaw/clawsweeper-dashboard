## Summary

Keep open: current main and v2026.6.11 still do not expose a configurable main-LLM retry/backoff policy. Existing cron retry, SDK retry caps, auth-profile overloaded rotation/backoff, and same-model short-window retries cover adjacent paths only; open related PRs are partial and do not replace this product/API tracker.

## What This Changes

Request to add configurable retry-with-backoff for main LLM requests on transient provider errors such as overloaded, 5xx, network, and timeout failures.

## Best Possible Solution

Define a maintainer-approved LLM retry contract, then implement schema, runtime wiring, docs, and focused tests for transient classes, idempotent limits, auth-profile rotation, and fallback interaction.
