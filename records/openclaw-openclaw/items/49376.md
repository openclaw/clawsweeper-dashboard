## Summary

Keep open: current main still lacks a public, configurable main-LLM retry/backoff contract for overloaded/5xx/network failures; existing code covers adjacent auth-profile rotation, short-window same-model rate-limit retry, session/provider SDK retry settings, and cron retry.

## What This Changes

The issue requests an agent-level or global configurable retry policy for main LLM requests on transient provider errors such as overloaded/529, 5xx, network, and timeout failures.

## Best Possible Solution

Define one maintainer-approved LLM retry contract, then wire schema, docs, runtime retry/fallback ordering, idempotency guards, user-visible retry status, and focused upgrade tests together.
