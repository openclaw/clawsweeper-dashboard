## Summary

Keep open: current main and v2026.6.11 still lack a configurable main LLM retry/backoff policy. The code has adjacent retry paths for cron, channel delivery, auth-profile rotation, short-window rate limits, and provider fetch timeouts, but the requested public retry contract remains unlanded and overlaps active partial work.

## What This Changes

Request to add configurable retry with backoff for main LLM provider calls on transient errors such as overloaded, server_error, network, and timeout.

## Best Possible Solution

Define one maintainer-approved LLM retry contract, then implement schema, docs, runtime wiring, and tests across transient classification, idempotent retry limits, auth-profile rotation, and fallback interaction.
