## Summary

Keep open: current main and v2026.6.11 still do not expose a configurable main-LLM retry/backoff policy. Existing auth cooldowns, cron retry, SDK retry-after caps, and short-window same-model retry cover adjacent paths only, while the open related PRs are partial/product-direction work rather than a landed public contract.

## What This Changes

Request to add agent-level or global configurable LLM retry/backoff for transient provider errors such as overloaded, server_error, network, and timeout.

## Best Possible Solution

Define a maintainer-approved LLM retry contract, then implement schema, docs, runtime wiring, and focused tests that cover transient classes, idempotent retry limits, auth-profile rotation, and fallback interaction.
