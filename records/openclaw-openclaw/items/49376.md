Keep open: current main and v2026.6.11 still do not expose a configurable main-LLM retry/backoff contract, and the active related PRs only cover partial slices of timeout, cooldown, or internal retry behavior.

## What This Changes

The issue requests an agent-level or global configurable retry/backoff policy for transient LLM provider failures such as overloaded, 5xx, network, and timeout errors.

## Best Possible Solution

Define one maintainer-approved LLM retry contract, then implement schema, docs, runtime wiring, upgrade behavior, and focused tests across transient classification, idempotent retry limits, auth-profile rotation, and fallback interaction.
