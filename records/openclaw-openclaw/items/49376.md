## Summary

Keep open: current main and v2026.6.11 still do not expose the requested configurable main-LLM retry/backoff contract; existing SDK retry knobs, cron/channel retry, auth-profile rotation, and fallback behavior are adjacent but not a complete public policy for overloaded/5xx/network recovery.

## What This Changes

The issue requests an agent/global configurable retry-with-backoff policy for main LLM requests on transient overloaded, 5xx, and network errors.

## Best Possible Solution

Define one maintainer-approved opt-in LLM retry contract, then implement schema, docs, runtime wiring, upgrade behavior, and focused tests across transient classification, idempotency, auth-profile rotation, model fallback, Retry-After, max-total caps, and user notification behavior.
