## Summary

Keep open: the PR fixes byte accounting after a text-only fallback has already been read, but it is not merge-ready because capped text-only responses can still force full string allocation before `maxBytes` is enforced.

## What This Changes

The PR changes `readResponseText()` to UTF-8 encode text-only fallback results before truncation and adds a multibyte regression test.

## Best Possible Solution

Make capped reads rely on a stream or byte-buffer source; when `maxBytes` is set and only `text()` exists, fail closed or require a bounded byte source, with tests proving `text()` is not called before enforcement.

## Reproduction Assessment

Yes. Source inspection at the PR head shows `readResponseText()` still awaits `res.text()` before checking `maxBytes`, so a text-only foreign response can reproduce the remaining full-allocation path.

## Solution Assessment

No. The byte accounting improvement is useful, but the best fix must enforce the cap before reading or explicitly fail closed when no bounded byte source exists.
