## Summary

Keep open: the PR improves returned byte counting and UTF-8 truncation, but it still calls `response.text()` before checking `maxBytes`, so it does not provide the bounded-read availability guarantee claimed for text-only Response-like objects.

## What This Changes

The PR changes `readResponseText`'s text-only fallback to encode/decode UTF-8 bytes for `maxBytes` truncation and adds a multibyte regression test.

## Best Possible Solution

Use a maintainer-approved bounded-source policy for capped text-only fallbacks, preferably skipping `text()` when no bounded byte source exists, with regression coverage that proves the unbounded method is not called.

## Reproduction Assessment

Yes. Source inspection of the PR head shows a text-only Response-like object with `maxBytes` reaches `await res.text()` before any byte cap is enforced.

## Solution Assessment

No. Post-read UTF-8 truncation fixes returned length accounting, but the best bounded-read fix must avoid calling `text()` when the caller requested a byte cap and no bounded byte source is available.
