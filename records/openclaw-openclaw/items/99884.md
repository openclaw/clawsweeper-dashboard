## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.82

Full review comments:

- **[P1] Bound the body before calling text():** `src/agents/mcp-http-fetch.ts:86`
  - body: The no-Content-Length path still calls `await response.text()` before the 16 MiB check runs. Undici's body consumer fully reads before resolving, so a hostile text-only foreign response can still allocate the oversized body and OOM before this truncation happens; the added test only proves the returned text was shortened after that allocation. The fix needs to avoid `.text()` unless a strict under-cap byte length is trusted, or fail closed for bodyless responses that cannot be streamed safely.
  - confidence: 0.93
- **[P2] Measure the cap in bytes:** `src/agents/mcp-http-fetch.ts:87-92`
  - body: The new limit is named and messaged as bytes, but `text.length` and `slice()` count UTF-16 code units. A non-ASCII body can pass the `<= 16 MiB` check while producing a UTF-8 `Response` body larger than 16 MiB, so any retained text fallback should enforce the cap with byte length and byte-safe truncation.
  - confidence: 0.86
