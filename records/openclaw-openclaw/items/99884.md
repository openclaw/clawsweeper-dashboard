## Summary

Keep open: the latest head still does not solve the central bounded-read bug because the text-only fallback calls `response.text()` before enforcing `maxBytes`, so the full body can already be allocated.

## What This Changes

The PR modifies `readResponseText` to byte-count and truncate the text-only fallback after `response.text()`, and adds a regression test for byte-boundary truncation.

## Best Possible Solution

Restore a pre-read guard for capped text-only fallbacks, or use a maintainer-approved bounded-source policy; do not merge post-read truncation as an OOM fix.

## Reproduction Assessment

Yes. Source inspection of the current PR head shows a text-only Response-like object with `maxBytes` reaches `await res.text()` before any byte cap is enforced.

## Solution Assessment

No. The latest diff is only a post-read truncation, while the narrow maintainable fix must avoid an unbounded `text()` call when the caller requested a byte cap.
