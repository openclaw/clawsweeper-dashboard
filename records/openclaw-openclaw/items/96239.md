## Summary

Keep open: current main and v2026.6.11 partially mitigate the Feishu ordering problem by preserving the assistant answer before an error final, but current source and tests still allow an answer plus extra exec warning, and the exact false `configuration file` stdout-to-`lastToolError` trigger is not proven or owned by a narrower canonical item.

## What This Changes

The issue reports that Feishu gateway replies can show a warning card before the real final reply when recovered or false exec/tool-warning state is surfaced on an otherwise successful turn.

## Best Possible Solution

Keep the Feishu answer-preservation behavior, then fix the narrow false/recovered `lastToolError` path so successful read-only exec output does not create an extra user-visible warning while real unresolved mutating failures remain visible.
