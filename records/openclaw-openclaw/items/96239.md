## Summary

Keep open for maintainer follow-up. The prior review says the Feishu ordering defect was fixed in v2026.6.11, but the remaining question—when a recovered or ambiguous mutating-tool error may become a user-visible warning alongside a successful final answer—still has no current-main live trajectory or narrower canonical issue.

## What This Changes

The issue requests that successful Feishu agent turns do not place a false or recovered tool-error warning ahead of the agent’s actual final reply.

## System Context

Embedded-agent tool results are retained as run artifacts, which gateway payload assembly may convert into user-visible warnings. The Feishu plugin then delivers those warnings and the final answer as chat cards, so warning policy and payload order directly affect what the user sees first.

## Architecture Diagram

flowchart LR
  A[Agent tool execution] --> B[Run artifacts and terminal outcome]
  B --> C[Gateway warning and reply assembly]
  C --> D[Feishu reply dispatcher]
  D --> E[Streaming card and final reply]
  E --> F[User conversation]

## Best Possible Solution

Obtain one redacted current-main trajectory that shows the warning payload and final successful answer, then make gateway emit a warning only for a confirmed terminal failure or an explicitly unrecovered mutating action; Feishu should preserve the final answer as the primary user-visible outcome.
