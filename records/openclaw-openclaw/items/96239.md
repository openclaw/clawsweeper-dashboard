## What This Changes

The issue requests that successful Feishu agent turns avoid a spurious tool-warning card that can appear alongside or ahead of the actual final reply.

## System Context

An agent turn produces tool outcomes and final text, then the gateway turns them into reply payloads for the Feishu streaming-card dispatcher. Tool-error classification determines whether an additional user-visible warning accompanies an otherwise successful answer.

## Architecture Diagram

flowchart LR
  A[Feishu direct message] --> B[Gateway agent turn]
  B --> C[Tool outcome classification]
  C --> D[Final reply payload assembly]
  D --> E[Feishu streaming-card dispatcher]
  E --> F[Agent answer]
  E --> G[Optional tool warning]

## Best Possible Solution

Use structured tool outcome and mutation evidence—not stdout wording—to decide whether a warning is user-visible; after a successful final answer, surface only actionable confirmed failures and ensure any retained diagnostic cannot displace the answer.
