## Summary

Keep open: current main and v2026.6.11 preserve the Feishu answer before a later warning, but the reported false or recovered `lastToolError`/mutating-warning policy is still unresolved and no merged or open related item fully owns the exact `configuration file` stdout case.

## What This Changes

The issue reports that a successful Feishu agent turn can surface a leading exec warning card from retained `lastToolError` before the actual reply when stdout resembles configuration-file text.

## Best Possible Solution

Keep the Feishu answer-first coalescing behavior, then settle a narrow policy that clears or suppresses false or recovered read-only exec warnings without hiding real unresolved mutating failures.
