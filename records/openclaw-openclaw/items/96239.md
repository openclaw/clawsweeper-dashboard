## Summary

Keep open: current main has a Feishu mitigation that preserves the answer when a later error final arrives, but the remaining recovered or false `lastToolError` warning policy is still active and the reported `cat ~/...` command shape still fails the read-only classifier.

## What This Changes

The issue asks OpenClaw to stop surfacing a leading Feishu warning card for successful agent turns where a read-only exec result or recovered tool state is misclassified as a mutating tool error.

## Best Possible Solution

Define one recovered-tool-warning contract, then add focused agent payload and Feishu dispatcher coverage plus live Feishu proof that the final answer remains primary and false read-only warnings do not preempt it.
