## Summary

Keep open: current `main` still has a source-level path where a retained mutating exec-style `lastToolError` adds a separate user-visible warning after a successful assistant reply, while the merged Feishu ordering fix only partially covers the visible ordering symptom.

## What This Changes

The issue reports that successful Feishu/Gateway turns can show a tool-warning card before the real assistant reply when a recovered or false-positive exec/tool condition remains in `lastToolError`.

## Best Possible Solution

Preserve warnings for real unresolved mutating side effects, but clear or suppress false/recovered exec warnings and ensure Feishu never visually leads with a warning over an already committed assistant answer.

- **Keep current safety-first policy:** Leave broad warning visibility in place and rely on narrower classifier fixes, live repro evidence, or explicit config to handle false positives.
