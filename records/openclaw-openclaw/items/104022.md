## Summary

Keep this PR open for revision: it addresses payloads that are already empty at the cron dispatcher, but the reported Telegram exception occurs when a textless structured payload survives that filter and the Telegram adapter later attempts an empty send. The added regression therefore does not exercise the production failure boundary, and the patch can leave the reported cron delivery failure unchanged.

## What This Changes

The PR makes isolated cron direct delivery fall back to non-empty output, summary, or synthesized text when projected payloads normalize to no sendable content.

## Best Possible Solution

Reproduce the real structured payload through generic outbound delivery and Telegram's payload adapter, then add the cron summary only when that adapter's effective visible payload would otherwise be empty, while preserving supported structured content and silent-token behavior.
