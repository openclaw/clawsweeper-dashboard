## Summary

Keep open. Current main and the latest release have Gateway auth, `operator.write` gating, session visibility/A2A allowlists, and inter-session provenance, but they still do not provide per-message HMAC/token sender verification, replay protection, verifier failure behavior, or key lifecycle for `sessions_send`; the IdentyClaw ClawHub plugin/skill is useful workaround evidence, not a core close reason.

## What This Changes

Request to add per-message HMAC/token sender authentication for inter-agent `sessions_send` so receiving sessions can verify the claimed sender and reject forged messages.

## Best Possible Solution

Define one maintainer-approved inter-session trust contract that composes provenance, sender authorization, replay protection, key lifecycle, scoped tokens, plugin workarounds, docs, and upgrade-safe defaults before implementation.
