## Summary

Keep open. Current main and latest release still provide Gateway caller auth, `operator.write` scoping, session visibility checks, and inter-session provenance, but not the requested per-message HMAC/token sender verification, replay protection, verifier, or key lifecycle; the IdentyClaw ClawHub plugin/skill is useful workaround evidence, not a core close reason.

## What This Changes

Request HMAC/token-based mutual authentication for `sessions_send` messages, ideally with per-agent configurability for which sessions require sender verification.

## Best Possible Solution

Define one maintainer-approved inter-session trust contract that composes provenance, sender authorization, replay protection, key lifecycle, scoped tokens, plugin workaround guidance, docs, and upgrade-safe defaults before implementation.

## Reproduction Assessment

Yes, source-level: current main and `v2026.6.11` expose `sessions.send` with provenance and Gateway scopes but no HMAC/signature/nonce verifier path. I did not run a live exploit reproduction.

## Solution Assessment

Unclear; HMAC is a plausible minimum, but maintainers need to choose the auth contract, token/key lifecycle, sender graph semantics, replay behavior, and compatibility defaults before a fix PR is safe.
