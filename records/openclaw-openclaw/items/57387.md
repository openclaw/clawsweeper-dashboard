## Summary

Keep open. Current main and latest v2026.6.11 have Gateway caller auth, operator.write gating, session visibility, agent-to-agent allow rules, and inter-session provenance, but not the requested per-message HMAC/token sender verification, replay protection, verifier, or key lifecycle; the KinthAI and IdentyClaw comments are useful real-world/workaround evidence, not a core close reason.

## What This Changes

The issue requests per-message HMAC or token-based mutual authentication for inter-agent sessions_send traffic.

## Best Possible Solution

Define one maintainer-approved inter-session trust contract that composes provenance, sender authorization, replay protection, key lifecycle, scoped tokens or hooks, docs, and upgrade-safe defaults before implementation.

## Reproduction Assessment

Yes at source level: current main shows sessions_send provenance and access checks but no HMAC/signature/token verifier in the tool payload, protocol schema, or gateway handler. I did not run a live exploit because this is a security feature/design request rather than a narrow regression.

## Solution Assessment

Unclear: HMAC is a plausible minimum, but maintainers need to choose the security model, token/key lifecycle, sender graph semantics, default compatibility behavior, and whether this belongs in core gateway verification, plugin hooks, or both.
