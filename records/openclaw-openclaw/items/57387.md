## Summary

Keep open. Current main and v2026.6.11 have Gateway caller auth, `operator.write` scope, session visibility/A2A allowlists, and inter-session provenance, but they still do not provide the requested per-message HMAC/token sender verification, replay protection, verifier, or key lifecycle; the IdentyClaw plugin/skill comment is useful workaround evidence, not a core close reason.

## What This Changes

Request per-session HMAC/token sender verification for `sessions_send`, with receiving-session verification and optional per-agent policy.

## Best Possible Solution

Define one maintainer-approved inter-session trust contract that composes provenance, sender authorization, replay protection, key lifecycle, scoped tokens, plugin workarounds, docs, and upgrade-safe defaults before implementation.
