## Summary

Keep open. Current main still provides Gateway auth, `operator.write` gating, session visibility/A2A allowlists, and inter-session provenance, but not the requested per-message HMAC/token sender verification, replay protection, verifier, or key lifecycle; the IdentyClaw plugin/skill is useful workaround evidence, not a core close reason.

## What This Changes

The issue requests HMAC or token-based sender verification for inter-agent `sessions_send` messages so recipients can authenticate the claimed sender session.

## Best Possible Solution

Define one maintainer-approved inter-session trust contract that composes provenance, sender authorization, replay protection, key lifecycle, scoped tokens, plugin workarounds, docs, tests, and upgrade-safe defaults before implementation.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 expose provenance, visibility/A2A allowlists, and Gateway `operator.write` scope, but no per-message signature, HMAC, nonce, sender token, verifier, or key lifecycle. I did not run a live exploit reproduction.

## Solution Assessment

Unclear; HMAC is plausible, but maintainers need to choose the security model, token/key lifecycle, sender graph semantics, replay handling, and compatibility behavior before a fix PR is safe.
