## Summary

Keep open. Current main and v2026.6.11 still provide Gateway caller auth, session visibility checks, and inter-session provenance, but they do not provide cryptographic per-message sender verification or replay protection for `sessions_send`; the IdentyClaw plugin/skill comment is useful workaround evidence, not a core close reason.

## What This Changes

Request HMAC/token-based mutual authentication for `sessions_send` so receiving sessions can verify the claimed sender session and optionally require it per agent.

## Best Possible Solution

Define a maintainer-approved inter-session trust contract that composes provenance, sender authorization, replay protection, key lifecycle, scoped tokens, plugin workarounds, docs, and upgrade-safe defaults before implementation.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 expose provenance, visibility, and `operator.write` caller scope, but the `sessions.send` schema and handler have no HMAC/signature/nonce/verifier fields. I did not run a live exploit reproduction because the missing contract is visible in source.

## Solution Assessment

Unclear; HMAC is a plausible minimum, but maintainers need to choose the security model, token/key lifecycle, sender graph semantics, replay handling, and compatibility behavior before a fix PR is safe.
