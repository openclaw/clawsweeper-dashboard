## Summary

Keep open. Current main and latest release have gateway caller auth, `operator.write` method scoping, session visibility/A2A allowlists, and inter-session provenance labels, but they still do not implement per-message HMAC/token sender verification, replay protection, verifier semantics, or key lifecycle for `sessions_send`.

## What This Changes

Request HMAC/token-based mutual authentication for `sessions_send` so receiving sessions can verify the claimed sender and optionally enforce per-agent auth.

## Best Possible Solution

Define one maintainer-approved inter-session sender-auth contract that composes provenance, sender authorization, replay protection, key lifecycle, scoped tokens, plugin workarounds, docs, and upgrade-safe defaults before implementation.

## Reproduction Assessment

Yes, source-level. Current main and v2026.6.11 expose provenance and allowlist gates, but the `sessions_send` schema and send path have no HMAC/signature/nonce/sender-token verifier.

## Solution Assessment

Unclear. HMAC is a plausible mechanism, but maintainers need to choose the security model, token/key lifecycle, sender graph semantics, and compatibility behavior before a fix PR is safe.
