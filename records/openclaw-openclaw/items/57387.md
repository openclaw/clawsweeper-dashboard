## Summary

Keep open. Current main and v2026.6.11 provide inter-session provenance, session visibility/send policy, and `operator.write` Gateway authorization for `sessions.send`, but they do not implement per-message HMAC/token sender verification, replay protection, receiver verification, or key lifecycle; the IdentyClaw ClawHub plugin/skill is useful workaround evidence, not a core close reason.

## What This Changes

Request per-session HMAC/token mutual authentication for inter-agent `sessions_send`, ideally configurable per agent.

## Best Possible Solution

Define one maintainer-approved inter-session trust contract that composes provenance, sender authorization, replay protection, key lifecycle, scoped tokens, plugin workarounds, docs, and upgrade-safe defaults before implementation.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 expose provenance and allowlists but no cryptographic sender verification or replay-proof `sessions_send` payload; no live exploit reproduction was run.

## Solution Assessment

Unclear; HMAC is plausible, but maintainers need to choose the security model, token/key lifecycle, sender graph semantics, and compatibility behavior before a fix PR is safe.
