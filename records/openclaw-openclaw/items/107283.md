## Summary

This PR should remain open but is not merge-ready: it mistakes `status: "completed"` for command success, even though the exec adapter uses that status for normally terminated processes while preserving a non-zero exit code. The unchanged prior P1 finding remains valid, and the PR body still provides only test evidence rather than live channel proof. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/agents/bash-tools.exec.ts?utm_source=openai))

## What This Changes

Changes `isToolResultError()` to ignore finite non-zero exit codes when the tool-result status is `completed`, with corresponding classifier test updates.

## Best Possible Solution

Preserve non-zero exits as error-visible by default and introduce an explicit typed signal for accepted exit codes or expected non-zero outcomes, then test both classifier behavior and visible channel delivery.
