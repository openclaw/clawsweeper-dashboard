## Summary

Keep open: the prior P1 correctness blocker remains on the unchanged head. A `completed` exec status means the process finished normally, not that its non-zero result was successful, so this patch can hide genuine command failures from channel fallback warnings; real behavior proof is also still absent.

## What This Changes

Changes `isToolResultError()` to ignore finite non-zero exit codes when the tool-result status is `completed`, with corresponding classifier test updates.

## Best Possible Solution

Keep non-zero exits error-classified by default, add a typed exec-owner signal for explicitly accepted exit codes or benign outcomes, and verify both quiet accepted exits and visible genuine failures through the channel payload path.

- **Suppress every completed non-zero exit:** Adopt this PR's broad rule and accept that normally exited command failures will no longer trigger the fallback warning.
- **Keep the current policy:** Continue warning for all non-zero exits and require commands expecting non-zero results to normalize them explicitly, such as through shell control flow.

## Solution Assessment

No. Treating every completed process as successful is too broad; the narrow maintainable solution needs an explicit accepted-exit or benign-outcome signal while retaining failure classification by default.
