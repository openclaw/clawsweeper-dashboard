## Summary

Keep this PR open for revision: the proposed guard mistakes normal process termination for command success and would suppress real failed-exec warnings across Discord and Telegram. The linked issue is valid, but this implementation is overbroad and still lacks after-fix channel proof.

## What This Changes

The PR changes `isToolResultError()` to ignore finite non-zero exit codes when the result status is `completed`, with corresponding classifier test updates.

## Best Possible Solution

Represent an expected non-zero outcome explicitly at the exec result boundary, or apply narrowly owned command semantics, while preserving generic non-zero failure detection for ordinary commands.

- **[P1] Preserve failures from normally exited commands:** `src/agents/tool-result-error.ts:118-120`
  - body: `status: "completed"` means the process reached an ordinary exit, not that the command succeeded: the exec runtime assigns it to nearly every exit code and separately reports `Command exited with code N`.
