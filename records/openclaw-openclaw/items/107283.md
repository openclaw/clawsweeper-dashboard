## What This Changes

Changes `isToolResultError()` to ignore finite non-zero exit codes when the tool-result status is `completed`, with corresponding classifier test updates.

## Best Possible Solution

Exec results should carry an explicit expected-nonzero outcome signal, or another narrowly defined semantic contract, while generic finite non-zero exits remain classified as failures.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should expected non-zero command outcomes use a new explicit result contract, or should OpenClaw intentionally stop warning for every normally terminated non-zero exec result?

Rationale: The runtime's existing `completed` status cannot distinguish benign command-specific outcomes from genuine failures, so choosing the permanent warning semantics requires maintainer intent.

Likely owner: Swader

Owner reason: Recent work owns the shared tool-error warning and agent message-filtering path where this semantic decision becomes user-visible.

Owner confidence: high

Options:

- **Add explicit expected-exit semantics (recommended):** Keep generic non-zero exits as failures and suppress warnings only when the execution layer explicitly marks that outcome as expected.
- **Suppress all normal non-zero exits:** Accept that any process reaching a normal exit will not trigger a channel warning, including ordinary command failures.

## Reproduction Assessment

Yes from source inspection: normal process termination produces `status: "completed"` even with a non-zero exit code, and the classifier controls downstream warning delivery. The PR still lacks live after-fix channel proof.

## Solution Assessment

No; `completed` represents how the process terminated, not whether its command semantics succeeded, so the proposed guard is broader than the reported benign cases.
