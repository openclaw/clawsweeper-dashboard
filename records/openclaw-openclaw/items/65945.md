## Summary

Keep open: current main and the latest release still do not support auto-forwarding Node `agent.request` image attachments, and the requested behavior is a new security-sensitive media relay contract rather than conservative cleanup.

## What This Changes

Allow Node-originated `agent.request` image attachments to be delivered to the target IM user when `deliver` is true without requiring the agent reply to include media.

## Best Possible Solution

Decide a narrow opt-in protocol design for Node media relay with authorization, limits, audit, and agent override semantics, or keep media forwarding on the existing direct send and message-tool surfaces.

Options:

- **Approve explicit opt-in relay (recommended):** Add a protocol field only with target authorization, channel capability checks, size/type limits, audit, and agent override/suppression semantics.

- **Defer to plugin/channel design:** Keep this issue open only for a broader channel or plugin API discussion if current direct-send surfaces are insufficient.

## Reproduction Assessment

Yes. Source inspection on current main shows `agent.request` attachments become `images`/`imageOrder` for agent input, while outbound delivery is planned only from agent reply payload media.

## Solution Assessment

Unclear. A narrow explicit opt-in relay could be maintainable, but automatic fallback forwarding would be the wrong default until maintainers settle the trust boundary and overlap with direct send/message-tool media delivery.
