- `P2`: This is a concrete gateway/media delivery enhancement with limited blast radius but non-trivial product and security scoping.
- `impact:security`: The request would let Node-originated media cross a credentialed IM delivery boundary without an agent-authored media reply unless a safe opt-in contract is designed.
- `impact:message-loss`: The reported user impact is that images supplied on a delivered Node agent request are not sent to chat unless the agent explicitly echoes media.
- `maturity:stable`: The affected Gateway RPC/event ingress belongs to the M4 Stable `gateway-runtime` surface in the checked-out maturity scorecard.

## Summary

Keep open: current main still treats Node `agent.request` image attachments as agent input, while visible IM media delivery only uses agent-authored reply or media payloads; auto-forwarding would add a new security-sensitive Gateway media relay contract.

## What This Changes

Request an opt-in way for Node `agent.request` image attachments with `deliver: true` to be forwarded to the target IM user even when the agent does not echo the image.

## Best Possible Solution

If accepted, add a narrow explicit opt-in relay contract with target scoping, authorization, media limits, audit and suppression rules, tests, and docs; otherwise keep agent/message-tool media as the supported delivery path.
