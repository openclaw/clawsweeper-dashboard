## Summary

Keep open: current `main` and `v2026.6.11` still treat Node `agent.request` image attachments as agent input, not as auto-forwarded chat media, and the remaining request is a new security-sensitive delivery contract that needs maintainer product direction.

## What This Changes

The issue requests an opt-in or fallback path that forwards Node `agent.request` image attachments to a chat recipient when `deliver: true`, even when the agent does not include media in its reply.

## Best Possible Solution

If maintainers want this, add a narrow explicit opt-in Gateway protocol/API contract with authorization, target scoping, limits, audit, and agent override semantics; otherwise document direct send or message-tool media delivery as the supported relay path.
