## Summary

Keep open: current main and the latest release still parse Node `agent.request` attachments for agent input only, and the requested node-to-chat media relay is a new security-sensitive delivery contract that needs maintainer product direction.

## What This Changes

The issue requests automatic forwarding of Node `agent.request` image attachments to IM users when `deliver: true` even when the agent reply does not include media.

## Best Possible Solution

Approve a narrow explicit opt-in node media relay contract with authorization and delivery semantics, or keep `agent.request` attachments as agent input and use existing direct send/message-tool media paths for dumb relay cases.
