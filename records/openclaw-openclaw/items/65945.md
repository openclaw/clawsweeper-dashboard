## Summary

Keep open: current main and v2026.6.11 still keep Node `agent.request` attachments as agent input, while delivered chat media comes only from the agent reply/direct-send payload path. The remaining request is a new security-sensitive gateway/media delivery contract, so it needs maintainer product and security direction rather than cleanup closure.

## What This Changes

The issue requests an opt-in or fallback behavior that relays Node `agent.request` image attachments to the target chat when `deliver` is true.

## Best Possible Solution

Approve a narrow explicit opt-in media-relay protocol only if maintainers want `agent.request` to become a relay surface; otherwise document direct `send` or message-tool media delivery as the supported path.
