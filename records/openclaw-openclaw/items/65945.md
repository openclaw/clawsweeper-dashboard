## Summary

Keep open: current main and the latest release still keep Node `agent.request` attachments as agent/model input, while outbound IM delivery is built only from the agent reply payload; the remaining request is a new security-sensitive media relay contract.

## What This Changes

Request to add explicit or fallback `agent.request` behavior that forwards Node-provided image attachments to the chosen IM target when `deliver: true`, even if the agent reply contains only text or no reply.

## Best Possible Solution

Approve a narrow explicit opt-in protocol/API design with authorization, limits, audit, channel capability checks, and agent override semantics, or keep media forwarding on the existing agent-authored message-tool/reply-payload/direct-send surfaces.
