## Summary

Keep open: current main and v2026.6.11 still treat Node `agent.request` attachments as agent input, while outbound chat delivery only sends media present in the agent reply payloads. The requested auto-forward behavior is a new security-sensitive protocol and delivery contract, not conservative cleanup.

## What This Changes

Request to add an opt-in or fallback path that forwards Node `agent.request` image attachments to the target IM channel when `deliver: true`, even if the agent does not include media in its reply.

## Best Possible Solution

Land a maintainer-approved explicit media relay contract with authorization, limits, audit, transcript receipts, and agent override semantics, or keep the current agent-controlled reply media and direct message-send surfaces as the supported relay paths.
