## Summary

Keep this PR open for a narrow repair: the shared object-envelope reader is the right boundary and Firecrawl’s documented v2 Search/Scrape success payloads are objects, but the branch passes an unsupported third argument to that helper. The patch therefore fails typechecking as written; removing that argument instead would silently reduce Firecrawl Scrape’s existing 64 MiB response allowance to the generic 16 MiB cap.

## What This Changes

The branch switches Firecrawl Search and Scrape to the shared top-level-object JSON reader and adds regressions for `null` and array HTTP 200 bodies.

## Best Possible Solution

Extend the shared object-envelope reader with the same optional byte-limit argument as the generic reader, forward it unchanged, and retain Firecrawl’s 64 MiB Scrape limit while rejecting non-object successful envelopes.
