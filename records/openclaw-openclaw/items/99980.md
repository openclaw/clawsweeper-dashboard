## Summary

Current main still reproduces the reported behavior, and no duplicate or implemented fix owns the reversed-bounds semantics. The issue is narrow enough for a focused repair: update the helper and its colocated tests, with a caller scan because the helper is broadly re-exported.

## What This Changes

The issue reports that sliceUtf16Safe returns a non-empty swapped-bounds substring when end is before start instead of matching String.prototype.slice by returning an empty string.

## Best Possible Solution

Make sliceUtf16Safe preserve String.prototype.slice ordering semantics after index normalization, while retaining surrogate-boundary adjustment for valid slices and tail slices.

## Reproduction Assessment

Yes. A direct current-main Node import of src/shared/utf16-slice.ts reproduced sliceUtf16Safe('hello', 4, 1) returning 'ell' while native String.prototype.slice returns ''.

## Solution Assessment

Yes. The narrowest maintainable fix is to remove the swapped-bounds behavior and update the helper test to assert empty output for reversed normalized bounds while preserving surrogate-safe edge adjustment.
