The issue asks for `sliceUtf16Safe` to return an empty string when the normalized end bound is before the start bound, matching `String.prototype.slice`.

## Best Possible Solution

Land a narrow main-only fix in `src/shared/utf16-slice.ts` with updated unit tests that make reversed bounds return `""` while preserving existing UTF-16 boundary guarantees.

## Reproduction Assessment

Yes from source inspection, though no test was run in this read-only review. The current helper normalizes `start=4,end=1`, swaps the bounds, and returns the middle substring instead of the empty native-slice result.

## Solution Assessment

Yes. The maintainable fix is to change the helper contract at the source and update its focused unit tests, rather than adding caller-side guards around each use.
