## Summary

Keep open: current main still permits restart catch-up to replay stale cron slots without a schedule-activation boundary, and the broader stop/delete/emergency-cancel behavior remains only partially covered by task-run cancellation rather than a documented operator control.

## What This Changes

The issue asks for cron/outbound message delivery to respect the intended schedule after restarts and for operators to be able to stop or cancel unexpected in-flight scheduled sends.

## Best Possible Solution

Land or replace the schedule-activation replay fix, then add a documented operator-visible cancellation path that aborts in-flight cron sends without relying on process kills or hidden task ids.
