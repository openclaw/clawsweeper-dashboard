## Summary

Keep open: current main still replays persisted past-due cron slots on startup, and the linked schedule-activation repair is an open conflicting PR that only covers part of this report. The delete/stop/emergency halt behavior remains a separate product boundary decision.

## What This Changes

The issue reports WhatsApp cron jobs replaying outside configured hours after gateway reconnection, plus ineffective stop/delete controls for active sends.

## Best Possible Solution

Land or replace the schedule-activation boundary for restart catch-up, then add a maintainer-approved operator-visible halt path that cancels active cron/outbound sends without changing unrelated channel policy.
