## Summary

The current-main parser still accepts the malformed bracket adjacency, and the same author has opened a narrow linked fix PR; keep this issue open until that PR is reviewed and merged.

## What This Changes

Reject config paths where bare text follows a bracket segment without a `.` or another bracket, while preserving valid dotted and consecutive-bracket forms.

## Best Possible Solution

Land a parser-level fail-fast check with focused regression coverage for malformed post-bracket text and valid dotted, root-bracket, escaped-key, and consecutive-bracket forms, so every config get/set/unset/batch caller shares one strict grammar.
