Keep this PR open: it is the active implementation candidate for the linked diagnostic-accounting bug, not an obsolete or superseded change. The focused code and QA scenario preserve `message.queued` visibility while separating active-run steering from real queued-turn backlog; however, the prior real-behavior-proof gate is still unmet because the PR body states an after-fix Gateway result without attaching redacted terminal output, logs, recording, or another inspectable runtime artifact.

## What This Changes

The PR changes embedded-agent diagnostics so messages accepted by an active run remain observable but do not inflate the session backlog that liveness reports after the run finishes.

## System Context

The embedded agent runner accepts follow-up messages while a session is already processing, then records diagnostic events used by liveness and recovery consumers. This change decides whether those accepted steering messages count as separate queued turns when the session later transitions to idle.
