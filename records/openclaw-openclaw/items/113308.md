## Summary

Keep open for maintainer handling. This is a concrete Windows SQLite-path bug with a deliberately broader owner boundary than the already-open backup-verification report, and the `maintainer` label plus MEMBER authorship require explicit maintainer judgment rather than automated cleanup.

## What This Changes

Normalize ordinary filesystem SQLite locations for Windows long paths across OpenClaw’s global, agent, maintenance, migration, doctor, and plugin-owned state stores while preserving `file:` URI, temporary, and `:memory:` semantics.

## System Context

OpenClaw persists global and agent state in SQLite databases used by gateway startup, doctor, migration, maintenance, and plugin state APIs. Filesystem locations flow into Node’s SQLite bindings; the proposed fix would classify locations before those opens so Windows-specific VFS normalization affects only real paths.

## Best Possible Solution

Adopt one narrowly scoped location-classification and Windows-VFS normalization contract at the SQLite owner boundary, use it for all filesystem-backed opens and `VACUUM INTO`, and provide any plugin-facing access through an approved shared package/API rather than core internals.
