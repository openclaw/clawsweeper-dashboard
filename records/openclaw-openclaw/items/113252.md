## Summary

Keep this issue open: it describes a production-confirmed Workboard scheduling starvation path, and the linked implementation PR remains open rather than merged. The next useful action is to review and land or resolve that PR; closing the issue first would hide the remaining merge decision.

## What This Changes

Fix Workboard dispatch capacity accounting so expired claims and stale active state do not indefinitely block ready cards for the same agent across boards.

## System Context

The Workboard plugin stores cards and claims, then its dispatcher selects ready cards and starts agent work while enforcing per-owner capacity. Claim and execution state feed the capacity decision, which determines whether queued work reaches the agent runtime.

## Architecture Diagram

flowchart LR

  B --> C[Dispatcher]
  C --> D[Owner capacity check]
  D --> E[Ready-card selection]
  E --> F[Agent work start]
  C --> G[Dispatch result and diagnostics]

## Best Possible Solution

Land a focused Workboard fix that shares the stale-claim reclaimability rule between cleanup and dispatcher capacity accounting, retains the grace-period contract, and preserves regression coverage for the cross-board same-owner case.
