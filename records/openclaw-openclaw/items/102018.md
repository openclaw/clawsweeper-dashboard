## Summary

Keep open: current main still lacks a `session.ended` diagnostic/OTel export path, so `run.completed` error spans can be marked correctly while `session.ended` itself remains outside diagnostics-otel error counting. The related end-reason issue overlaps, but it does not cover the OTel error-span counting gap by itself.

## What This Changes

The issue requests telemetry changes so failed `session.ended` spans with OTel `status.code=2` are counted as OTel error spans and include a useful end reason.

## Best Possible Solution

Define one canonical session-terminal telemetry contract that derives OTel span status/message and `openclaw.end_reason` from existing terminal outcome data, exports it through diagnostics-otel and trajectory, and coordinates the end-reason enum with https://github.com/openclaw/openclaw/issues/102019.
