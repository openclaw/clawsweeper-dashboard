## Summary

Keep this PR open: current main and the latest release still lose the resolved skill key before snapshot env injection, while this branch is a viable focused fix for the linked bug. I found no blocking code-review defect, but the serialized-snapshot and env/API-key compatibility surface still needs maintainer review plus a branch refresh with fresh checks before merge.

## What This Changes

The branch adds optional `skillKey` metadata to runtime and persisted skill snapshots, persists it during workspace snapshot building, uses it for snapshot env override lookup, refreshes old snapshots missing the field, and adds focused regression tests.

## Best Possible Solution

Land this PR or an equivalent canonical fix after it is refreshed and current-head checks pass, then let the linked bug close and keep narrower duplicate PRs closed.

## Reproduction Assessment

Yes. Source inspection on current main shows snapshots store only display `name`, while `applySkillEnvOverridesFromSnapshot()` resolves `skills.entries` by that display name; a skill whose `metadata.openclaw.skillKey` differs from its name will miss its configured env/API key.

## Solution Assessment

Yes. Persisting an optional resolved key in snapshots, using `skillKey ?? name` for snapshot lookup, and refreshing old snapshots missing the field is the narrow owner-boundary fix; adding a new config option or broad doctor migration would be heavier than needed.
