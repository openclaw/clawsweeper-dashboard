## What This Changes

The PR adds optional `skillKey` metadata to runtime and persisted skill snapshots, uses it for snapshot env override lookup, refreshes old snapshots missing the field, and adds focused regression tests.

## Best Possible Solution

Land this PR or an equivalent canonical fix after current-base refresh and fresh validation, then close the linked bug and leave the narrower duplicate attempts superseded.

## Reproduction Assessment

Yes. From source inspection, current main builds snapshots without the resolved key and then resolves snapshot env config by display `name`, missing config under `skills.entries.<skillKey>` when the display name differs.

## Solution Assessment

Yes. Persisting an optional resolved `skillKey`, using `skillKey ?? name`, and refreshing old snapshots is the narrow maintainable fix; bumping the prompt format would be broader than needed because the prompt text did not change.
