## What This Changes

The branch adds optional `skillKey` to runtime and persisted skill snapshot entries, stores it when building snapshots, uses it for snapshot env overrides, refreshes old snapshots missing the field, and adds focused regression tests.

## Best Possible Solution

Land this PR or an equivalent canonical fix after current-head checks pass, then close the linked bug and leave the closed narrower duplicate PRs closed.

## Reproduction Assessment

Yes. From current-main source inspection, snapshots store only the display `name` and snapshot env overrides resolve `skills.entries` by that display name, so a skill whose `metadata.openclaw.skillKey` differs from its name misses the configured API key/env entry.

## Solution Assessment

Yes. Persisting the resolved key, using `skillKey ?? name`, and refreshing old persisted snapshots missing the field is narrower and safer than bumping prompt format or trying to hydrate the metadata later.
