## What This Changes

The PR adds optional `skillKey` to runtime and persisted skill snapshots, writes the resolved key during snapshot building, uses it for snapshot env override lookup, refreshes old snapshots missing it, and adds regression coverage.

## Best Possible Solution

Land this PR or an equivalent canonical fix after rebase/fresh checks and maintainer acceptance of the snapshot/env lookup compatibility change, then close the linked bug and leave narrower duplicates closed.

## Reproduction Assessment

Yes. Current main source shows snapshots store only display `name` and snapshot env override lookup resolves `skills.entries` by that name, so a skill whose display name differs from `metadata.openclaw.skillKey` misses config stored under the documented key.

## Solution Assessment

Yes. Persisting an optional resolved `skillKey`, using `skillKey ?? name`, and rebuilding old snapshots missing the field is the narrowest maintainable fix; bumping prompt format or reparsing skills at each env lookup would be broader than needed.
