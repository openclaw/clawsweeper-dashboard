## What This Changes

The branch adds optional `skillKey` metadata to skill snapshot types, persists it in workspace snapshots, uses it for snapshot env override lookup, refreshes old snapshots missing the field, and adds focused regression tests.

## Best Possible Solution

Land this PR or an equivalent canonical fix after it is refreshed against current main, the targeted skill snapshot tests and current-head CI pass, and the linked bug is closed by the merge.

## Reproduction Assessment

Yes. Source inspection on current main shows workspace snapshots store only display `name`, while snapshot env overrides look up `skills.entries` by that display name even though docs and non-snapshot loading use `metadata.openclaw.skillKey` when present.

## Solution Assessment

Yes. Persisting the resolved key, using `skillKey ?? name`, and forcing refresh for persisted snapshots missing the field is narrower and safer than bumping the prompt format or trying to hydrate the metadata later.
