## Summary

Keep open: current `main` still drops `skillKey` from skill snapshots and still resolves snapshot env overrides by display name, while this PR is a scoped candidate fix with compatibility coverage. The patch looks correct, but it should stay in maintainer review until the branch is refreshed and current-head checks are green.

## What This Changes

The PR adds optional `skillKey` to runtime and persisted skill snapshots, writes it during workspace snapshot construction, uses it for snapshot env override lookup, refreshes older snapshots missing the field, and adds regression tests.

## Best Possible Solution

Land this PR or an equivalent canonical fix after branch refresh and current-head checks, preserving the optional `skillKey` field plus old-snapshot refresh compatibility behavior.

## Reproduction Assessment

Yes. Current `main` stores only display `name` in `SkillSnapshot.skills[]` and resolves snapshot env config by `skill.name`, while docs and loading paths use `metadata.openclaw.skillKey` when present.

## Solution Assessment

Yes. Persisting the resolved key, using `skillKey ?? name`, and refreshing old persisted snapshots missing the field is narrower and safer than bumping prompt format or trying to hydrate metadata after the snapshot has already lost it.
