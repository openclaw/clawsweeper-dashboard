## What This Changes

The PR persists optional `skillKey` on runtime and persisted skill snapshots, uses it for snapshot env override lookup, refreshes old snapshots missing the field, and adds focused regression tests.

## Best Possible Solution

Land this PR or an equivalent canonical fix after current-head checks are refreshed and passing, preserving the resolved skillKey in snapshots, snapshot env lookup by skillKey, and old persisted snapshot refresh behavior.

## Reproduction Assessment

Yes from source inspection: current main serializes only the skill display name into snapshots and later looks up config by that name, so `skills.entries.<skillKey>` is missed when the display name differs.

## Solution Assessment

Yes: persisting the resolved key at snapshot build time and using `skillKey ?? name` is the narrow owner-boundary fix because direct loading already uses `resolveSkillKey`; old persisted snapshots need the refresh guard added by this PR.
