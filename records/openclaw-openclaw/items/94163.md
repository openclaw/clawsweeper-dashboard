## Label Justifications

- `merge-risk: 🚨 compatibility`: The diff changes serialized skill snapshot metadata and forces refresh of older snapshots missing the new optional field.

## Summary

Keep open: this is a focused, viable fix for the linked skill snapshot env override bug, and current main plus the latest release still miss the resolved skill key in snapshot-based env lookup. No blocking patch defect surfaced in this read-only review, but the serialized snapshot and credential-injection compatibility surface still needs maintainer review plus fresh checks after rebasing onto current main.

## What This Changes

The PR adds optional `skillKey` fields to runtime and persisted skill snapshots, writes the resolved key into workspace snapshots, uses it for snapshot env override lookup, refreshes old snapshots missing the field, and adds regression tests.

## Best Possible Solution

Land this PR or an equivalent canonical fix after rebasing onto current main and passing fresh checks, preserving the optional `skillKey` field and old-snapshot refresh coverage before closing the linked bug.

## Reproduction Assessment

Yes. Source inspection shows current main builds snapshots without the resolved `skillKey` and then resolves snapshot env config by display `skill.name`, so config under `skills.entries.<skillKey>` is missed when the display name differs; I did not run tests because this review is read-only.

## Solution Assessment

Yes. Persisting the resolved key in the snapshot producer, using `skillKey ?? name` in the snapshot consumer, and refreshing old snapshots is the narrow owner-boundary fix; a lookup-only fallback cannot recover `name != skillKey` from an already stripped snapshot.
