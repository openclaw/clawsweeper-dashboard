## What This Changes

The PR adds optional `skillKey` metadata to runtime and persisted skill snapshots, uses it for snapshot env/API-key lookup, refreshes older snapshots missing the field, and adds focused regression tests.

## Best Possible Solution

Land this PR or an equivalent canonical fix after rebase and fresh current-head checks, then close the linked bug and leave the closed duplicate PRs superseded.

## Reproduction Assessment

Yes. Source inspection shows current main builds snapshots without the resolved key and then resolves snapshot env config by `skill.name`, while docs require `metadata.openclaw.skillKey` to key `skills.entries` when present.

## Solution Assessment

Yes. Persisting the resolved key, using `skillKey ?? name`, and forcing refresh of older snapshots missing the field is the narrow owner-boundary fix; bumping the prompt format or trying to hydrate this metadata later would be broader.
