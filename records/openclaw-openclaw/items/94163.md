## What This Changes

The branch adds optional `skillKey` to skill/session snapshots, persists it from workspace skill metadata, uses it for snapshot env override lookup, refreshes old snapshots missing it, and adds focused regression tests.

## Best Possible Solution

Land this or an equivalent narrow linked fix after refreshing against current main, preserving the optional `skillKey` field, snapshot refresh guard, and producer/consumer/upgrade regression coverage.

## Reproduction Assessment

Yes. Source inspection on current main shows a skill snapshot stores only display `name`, and `applySkillEnvOverridesFromSnapshot()` looks up `skills.entries` by that display name, so a configured `metadata.openclaw.skillKey` is missed.

## Solution Assessment

Yes. Persisting an optional resolved `skillKey`, consuming `skillKey ?? name`, and refreshing old snapshots missing the field is the narrow owner-boundary fix; bumping the prompt format would be broader than needed because prompt text did not change.
