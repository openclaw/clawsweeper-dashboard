## Summary

This is a fresh, concrete report of a foreground-only polling loop that the earlier hidden-tab fix does not claim to cover. The reported beta build already included that hidden-tab fix, and current-main behavior has not been reproduced or disproved, so this issue should remain open for a focused lifecycle investigation rather than be closed as implemented or duplicated.

## What This Changes

Fix Control UI session-catalog refresh scheduling so an active foreground sidebar honors its 5-second changed and 30-second stable cadence instead of repeatedly polling at request-completion latency.

## System Context

The Control UI sidebar uses the Gateway WebSocket to request session-catalog rows for its live session list. Browser visibility, focus, catalog-change signals, and request completion determine when the next catalog refresh is scheduled, which affects Gateway request load and logs.

## Architecture Diagram

flowchart LR
  Browser[Foreground Control UI] --> Sidebar[Session sidebar live state]
  Visibility[Visibility and focus events] --> Sidebar
  GatewayEvents[Catalog change and reconnect events] --> Sidebar
  Sidebar --> Scheduler[Adaptive refresh scheduler]
  Scheduler --> RPC[sessions.catalog.list request]
  RPC --> Gateway[Gateway session catalog]
  Gateway --> Response[Catalog response]
  Response --> Scheduler

## Best Possible Solution

Trace every current foreground refresh trigger into the session-catalog scheduler, ensure completion only consumes a genuinely coalesced pending refresh, and add a regression case that proves stable and changed foreground cadences remain 30 and 5 seconds respectively under slow responses.
