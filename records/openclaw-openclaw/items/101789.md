## Summary

Keep open: current main still has no board-scoped Workboard Control UI filter, while Workboard cards, tools, Gateway RPC, and store APIs already carry board ids, so this remains a narrow UI feature rather than a backend gap.

## What This Changes

Add a Board dropdown filter to the `/workboard` Control UI so operators can scope visible cards to one board alongside the existing view, priority, agent, search, and archive filters.

## Best Possible Solution

Add a first-party board selector to the existing Workboard toolbar using `workboard.boards.list` or card-derived board ids, apply it before the current view/priority/agent/search predicates, and keep the change scoped to Workboard UI state, i18n, and focused tests.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: current Workboard loads all cards, applies archived/agent/query/priority/view filters, and renders no board selector or board-id predicate. A mixed two-board card set will still render together unless another existing filter happens to separate it.

## Solution Assessment

Yes, the best fix is a narrow Control UI extension that reuses the existing Workboard board/card APIs instead of adding a new backend, config surface, or separate plugin path.
