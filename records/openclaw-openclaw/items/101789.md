## Summary

Keep open: current main still renders the Workboard toolbar without a board-scoped filter, while the store, MCP tools, and gateway already support board ids and board summaries, so the remaining work is a narrow Control UI feature rather than a backend gap.

## What This Changes

Add a Board dropdown filter to the `/workboard` Control UI so cards can be scoped to one Workboard board alongside the existing view, priority, agent, archive, and search filters.

## Best Possible Solution

Add a first-party board selector to the existing Workboard toolbar, using board summaries when available and falling back to card board ids, with regression coverage for mixed-board card visibility.

## Reproduction Assessment

Yes, at source level: renderWorkboard loads all cards, applies archived/agent/query/priority/view filters, and renders only the existing three dropdown filters. A two-board card set would still be shown together because no current predicate scopes by `metadata.automation.boardId`.

## Solution Assessment

Yes, the narrowest maintainable solution is to extend the existing Workboard toolbar/filter state using the already-available board list/card list gateway methods. The closed accidental board-filter PR should not be reused because it bundled unrelated agent/config changes and was closed unmerged.
