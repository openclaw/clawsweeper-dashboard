## Summary

Keep open: current main and the latest release still lack a board-scoped Workboard Control UI filter, while the Workboard backend, CLI, and board summary gateway methods already support board ids.

## What This Changes

Add a Board dropdown filter to the `/workboard` Control UI so operators can scope visible cards to one board alongside existing view, priority, and agent filters.

## Best Possible Solution

Add a first-party Board selector to the Workboard toolbar using `workboard.boards.list` plus card metadata fallback, apply it before the existing card grouping/counts, and cover mixed-board visibility with focused Control UI tests.

Required: false

## Reproduction Assessment

Yes, at source level: current `renderWorkboard` loads all cards and filters by archived state, agent, query, priority, and view preset, but never by `metadata.automation.boardId`. A two-board card set would still render together in the same columns.

## Solution Assessment

Yes, the narrowest maintainable path is to extend the existing Workboard toolbar/filter state and use the already available board list/card list gateway methods. The closed accidental board-filter PR should not be reused because it bundled unrelated agent/config changes and was closed unmerged.
