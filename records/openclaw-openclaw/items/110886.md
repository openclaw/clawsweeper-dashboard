## Summary

Keep this PR open: it extends the already-merged gateway/web session-cut feature to native chat, but the current branch still has concrete destructive-action, history-reconciliation, authorization, and stale-result handling defects, and it has only test/CI-style evidence rather than inspectable native after-fix proof.

## What This Changes

The branch registers existing session rewind/fork protocol schemas for native code generation and adds per-user-message rewind and fork actions, transports, localization, and Swift tests for the macOS and iOS chat UI.

## Best Possible Solution

Make native rewind match the established web safety contract: confirm the operation, hide or disable it without the required authorization, replace history canonically after rewind, retain returned drafts across stale navigation, and serialize message mutations before adding redacted native runtime proof.

Full review comments:

- **[P1] Replace rewind history canonically:** `apps/shared/OpenClawKit/Sources/OpenClawChatUI/ChatViewModel+SessionActions.swift:390-391`
  - body: After the gateway has cut the transcript, this invokes `refreshHistoryAfterRun`, whose reconciliation is designed to retain optimistic trailing user messages absent from the incoming history. That can keep turns removed by rewind visible; load the rewound transcript through a canonical replacement path instead.
  - confidence: 0.98
- **[P1] Confirm before dispatching rewind:** `apps/shared/OpenClawKit/Sources/OpenClawChatUI/ChatView.swift:1117`
  - body: This button immediately starts a destructive rewind. The merged web client confirms the equivalent operation, so native users need an equivalent confirmation before the RPC can cut the active transcript.
  - confidence: 0.98
- **[P2] Gate rewind on native admin capability:** `apps/shared/OpenClawKit/Sources/OpenClawChatUI/ChatView.swift:1111-1124`
  - body: The button is available for every persisted user message, but `sessions.rewind` requires `operator.admin`. Connections without that scope receive an authorization failure after a destructive-looking menu action; hide or disable it until the client can authorize the RPC.
  - confidence: 0.91
- **[P1] Persist the rewound draft before stale return:** `apps/shared/OpenClawKit/Sources/OpenClawChatUI/ChatViewModel+SessionActions.swift:380-384`
  - body: The RPC completes before this session-staleness guard, but the returned `editorText` is applied only afterward. If navigation wins the race, the source session is rewound and its recovered draft is discarded; store it for the initiating session before returning.
  - confidence: 0.95
- **[P2] Persist the fork draft on stale navigation:** `apps/shared/OpenClawKit/Sources/OpenClawChatUI/ChatViewModel+SessionActions.swift:404-414`
  - body: A fork can be created successfully after the user changes sessions. Preserve its returned composer text under the created session key before taking the staleness fallback, otherwise opening the newly listed fork loses the message text needed to continue it.
  - confidence: 0.91
- **[P2] Serialize pending message mutations:** `apps/shared/OpenClawKit/Sources/OpenClawChatUI/ChatView.swift:1117-1156`
  - body: Neither action marks a message-level mutation as in flight, so reopening the context menu while a slow request is pending can dispatch duplicate forks or overlapping session mutations. Disable both actions until the pending rewind or fork completes.
  - confidence: 0.94
