## Summary

This PR addresses a valid Zalo Personal hang, but it is not merge-ready: two sibling read-only lookup paths remain unbounded, while the new timeout around side-effecting voice delivery can report failure without cancelling the underlying send and invite duplicate retries.

**Likely related people**

- `@nohat` — high confidence; recently maintained Zalouser outbound delivery through the `sendPayload` adapter rollout.
- `@suminhthanh` — medium confidence; introduced the original bundled Zalo Personal integration.

## What This Changes

Adds 12-second `withTimeout` guards to several Zalo Personal account, friend, group, member, voice-upload, and voice-send API calls, plus controlled hanging-promise tests.

## Best Possible Solution

Apply one named timeout policy to every read-only account, friend, group, and member lookup, but leave outbound upload/send calls unchanged unless the dependency provides cancellation or an idempotency mechanism that prevents ambiguous delivery; cover both remaining lookup paths and the outbound boundary with focused tests and real runtime evidence where feasible.

- **[P1] Avoid timing out side-effecting voice sends without cancellation:** `extensions/zalouser/src/zalo-js.ts:1275-1278`
  - body: `withTimeout` only stops waiting for the already-started Promise; it does not cancel `uploadAttachment` or `sendVoice`. Remove these two wrappers unless the real transport can be aborted or the operation is made idempotent.
  - confidence: 0.98
