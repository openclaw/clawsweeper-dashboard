## Summary

Keep open: current main and v2026.6.11 still provide automatic pruning, truncation, compaction, reset, and delete paths, but no caller-directed clear/archive/recover operation for stable tool-result entries. The remaining work is a core session/context lifecycle product decision, not a conservative cleanup close.

## What This Changes

The issue requests a way to manually purge tool results from active context after they are no longer needed, potentially through CLI, agent-callable, or tool-call lifecycle surfaces.

## Best Possible Solution

Define one canonical session/context lifecycle contract for stable tool-result release or archival, then expose approved CLI, agent, and tool-call adapters over that contract with explicit auth, persistence, replay, and recovery semantics.
