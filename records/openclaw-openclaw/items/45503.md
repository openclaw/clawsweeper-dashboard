## Summary

Keep open: current main and v2026.6.11 still provide automatic TTL pruning, overflow/tool-result truncation, compaction, reset, and delete, but not caller-directed clear/archive/recover for a stable tool-result entry. The older duplicate was already consolidated here, while the open overflow-recovery issue and PR address automatic recovery ordering rather than manual lifecycle control.

## What This Changes

Manual clearing or archival of large transient tool results from active context before automatic TTL pruning or compaction runs.

## Best Possible Solution

Define one canonical core session/context lifecycle operation for stable tool-result release or recoverable archival, then expose CLI, agent, and tool-call adapters only after persistence, replay, authorization, and recovery semantics are settled.

- **Recoverable archive contract (recommended):** Add one canonical operation that removes selected tool results from active model context while retaining a recoverable/auditable reference for replay and later use.
- **Destructive clear contract:** Allow explicit deletion or placeholder rewriting of selected tool results, accepting that some workflows may need to refetch lost state.
- **No new core API:** Keep relying on pruning, truncation, compaction, reset, and delete, and close or defer manual lifecycle control as out of scope.
