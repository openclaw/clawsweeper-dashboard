## Summary

Keep open: current main and v2026.6.11 still only provide automatic TTL/pressure pruning, truncation, compaction, reset, and delete paths, not a caller-directed clear/archive/recover operation for a stable tool-result entry.

## What This Changes

Manual tool-result context clearing is requested so large transient tool outputs can be purged before automatic TTL expiry.

## Best Possible Solution

Define one canonical session/context lifecycle contract for stable tool-result release or archival, then expose approved CLI, agent, and tool-call adapters over that contract with explicit auth, persistence, replay, and recovery semantics.
