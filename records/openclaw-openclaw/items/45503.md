## Summary

Keep open: current main and the latest release still provide policy-driven cache-TTL pruning, overflow/tool-result truncation, full-session compaction, reset, and delete, but not a caller-controlled clear/archive/recover contract for a stable tool-result entry. The related duplicate was already consolidated into this issue, while the overflow-recovery issue and PR address automatic recovery ordering rather than manual lifecycle control.

## What This Changes

The issue requests a manually controlled way to purge or archive individual tool results from active context before automatic TTL or overflow pruning runs.

## Best Possible Solution

Define a core context lifecycle contract for stable tool-result identifiers with explicit clear versus archive/recover semantics, then expose it through the narrowest CLI/agent/plugin surface that preserves transcript and prompt-cache invariants.

## Reproduction Assessment

Not applicable: this is a feature request, not a bug under an existing contract. Source and docs inspection show the current mechanisms are automatic pruning, truncation, compaction, reset, and delete, with no manual result-id lifecycle control.

## Solution Assessment

Unclear: a raw delete-by-id command is only one possible shape, and the discussion already raises archive/recover and checkpoint tradeoffs. The best next step is a maintainer product/API decision before a fix PR.
