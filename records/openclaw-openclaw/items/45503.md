## Label Justifications

- `P2`: Large short-lived tool results can bloat context and cost, but existing pruning, truncation, compaction, reset, and delete paths partially mitigate the impact.
- `impact:session-state`: The request changes which tool-result state remains active, hidden, rewritten, or recoverable across later session turns.

## Summary

Keep open: current main and the latest checked release still provide automatic pruning, truncation, compaction, reset, and delete paths, but no caller-directed clear/archive/recover operation for stable tool-result entries.

## What This Changes

Request a manual way for users, agents, or tool calls to purge large short-lived tool results from active context before TTL pruning or compaction.

## Best Possible Solution

Define one canonical session/context lifecycle contract for stable tool-result release or archival, then expose approved CLI, agent, and tool-call adapters over that contract with explicit auth, persistence, replay, and recovery semantics.
