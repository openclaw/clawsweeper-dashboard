## Label Justifications

- `P2`: Large short-lived tool results can waste context and cost, but existing pruning, truncation, compaction, reset, and delete paths partially mitigate the impact.
- `impact:session-state`: The request changes which tool-result state remains active, rewritten, archived, or recoverable across later session turns.

## Summary

Keep open: current main and v2026.6.11 still provide automatic cache-TTL pruning, pressure truncation, and session-wide compact/reset/delete paths, but not a caller-directed clear/archive/recover operation for a specific tool result. This remains a product/API design issue rather than a small bug fix.

## What This Changes

Request a CLI, agent-callable, or tool-call-level way to manually purge specific tool results from active context once they are no longer needed.

## Best Possible Solution

Define one canonical session/context lifecycle contract for stable tool-result release or archival, then expose approved CLI, agent, and tool-call adapters over that contract with explicit authorization, persistence, replay, and recovery semantics.
