## Summary

Keep open: current main and v2026.6.11 still provide automatic TTL pruning, overflow truncation, compaction, reset, and delete paths, but no caller-directed clear/archive/recover operation for a stable tool-result entry.

## What This Changes

The issue requests a manual way to purge or archive specific tool results from active context before automatic TTL or overflow pruning runs.

## Best Possible Solution

Define one canonical session/context lifecycle contract for stable tool-result release or archival, then expose approved CLI, agent, and tool-call adapters over that contract with explicit auth, persistence, replay, and recovery semantics.
