## Label Justifications

## Summary

Keep open: current main and v2026.6.11 still provide automatic TTL/pressure pruning, truncation, compaction, reset, and delete paths, but not a caller-directed clear, archive, or recover operation for a stable tool-result entry.

## What This Changes

Request a way to manually purge or release tool results from active context once their output is no longer needed.

## Best Possible Solution

Define one canonical session/context lifecycle contract for stable tool-result release or archival, then expose approved CLI, agent, and tool-call adapters over that contract with explicit auth, persistence, replay, and recovery semantics.

- **Implement Narrow Destructive Clear:** Add only a targeted clear-by-id operation, accepting that recovery and audit semantics are intentionally minimal.
