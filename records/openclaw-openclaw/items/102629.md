## Reproduction Assessment

Yes. Current main's restart-handoff `normalizeText` uses raw `slice(0, maxLength)`, so a 199-code-unit prefix followed by an emoji crosses the 200-code-unit cap and can leave a lone surrogate; the PR adds a persisted row/read-back regression for that boundary.

## Solution Assessment

Yes. Using the existing `truncateUtf16Safe` helper at the single restart-handoff text normalization boundary is the narrowest maintainable fix; changing only the gateway RPC normalizer would miss persisted rows, and custom slicing would duplicate the shared helper.
