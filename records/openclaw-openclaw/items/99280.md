## Summary

Current main no longer has the live config-health sidecar writer that made the warning permanent: Node config health writes SQLite only, the macOS runtime keeps config health process-local, and merged PR https://github.com/openclaw/openclaw/pull/99039 removed the known sidecar recreation loop after the latest stable release.

## What This Changes

The issue reports a permanent, unresolvable config-health legacy-migration warning caused by legacy JSON state being regenerated and compared against SQLite as raw serialized JSON on every CLI invocation.

## Best Possible Solution

Keep the current-main implementation: config-health runtime state remains SQLite-backed or process-local, while old `logs/config-health.json` files stay a legacy migration input only.

## Reproduction Assessment

No for current main: I did not run the full CLI flow, but source and regression tests show current main no longer recreates `logs/config-health.json` from the inspected core or macOS runtime paths. The report remains credible for v2026.6.11, which predates the merged fix.

## Solution Assessment

Yes. Removing the live sidecar writer and keeping config-health state in SQLite/process memory is the narrow database-first fix; changing the legacy migration comparator is no longer necessary for the central unresolvable regeneration loop.
