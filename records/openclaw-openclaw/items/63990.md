## Summary

Keep open. Current main and the latest release still expose a single resolved memorySearch provider/model/fallback and one canonical memory index, while this request asks for broad multi-index ingestion, routing, config, migration, and observability work that needs maintainer product direction.

## What This Changes

The issue requests first-class per-model memory embedding indexes with active/fallback index routing so embedding provider failover never mixes vector spaces.

## Best Possible Solution

Keep this as the canonical maintainer design tracker for memory-core multi-index failover, decide the config/storage/migration/status contract first, and let the narrower fallback-latch bug remain separately owned.
