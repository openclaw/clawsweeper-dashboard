## Summary

Keep open: current main still provides a single scalar `memorySearch` provider/model/fallback path plus identity guards, not the requested per-model indexes, dual ingestion, active/fallback index routing, or index coverage/status surface. The issue remains a valid feature/API design tracker rather than a stale or implemented item.

## What This Changes

Request first-class per-model memory indexes with dual ingestion, model-aware active/fallback routing, status observability, and backward-compatible `memorySearch` configuration.

## Best Possible Solution

Keep this as the canonical maintainer design tracker, define the memory-core versus plugin-API boundary first, then implement per-model index storage, ingestion, routing, status, and migration as one explicit compatibility plan.
