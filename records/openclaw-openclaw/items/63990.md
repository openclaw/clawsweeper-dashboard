## Summary

Keep open: current main and v2026.6.11 still expose scalar `memorySearch` provider/model/fallback plus one canonical memory index. The existing identity guard prevents mixed vector-space search, but the requested per-model indexes, dual ingestion, active/fallback index routing, and per-index status surface remain unimplemented and need maintainer product/API direction.

## What This Changes

Request first-class multi-index embedding memory so each embedding model has its own index, coordinated ingestion, model-aware query routing, and safe failover without mixing vector spaces.

## Best Possible Solution

Keep this as the canonical maintainer design tracker for model-aware memory indexes, define the config/storage/migration/status and plugin-API contract first, and let narrower fallback recovery bugs proceed separately.
