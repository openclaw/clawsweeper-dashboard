## Summary

Keep open: current main and v2026.6.11 still expose a single memory-search provider/model/fallback and one canonical memory index. The existing identity guard prevents mixed vector-space search, but the requested per-model indexes, dual ingestion, active/fallback index routing, and status surface remain unimplemented and require maintainer product/API direction.

## What This Changes

The issue requests multi-index embedding memory with one vector index per embedding model, explicit active/fallback index routing, coordinated ingestion, observability, and backward-compatible config.

## Best Possible Solution

Keep this as the canonical maintainer design tracker for model-aware memory indexes, define the config/storage/migration/status and plugin-API contract first, and let narrower fallback recovery work proceed separately.
