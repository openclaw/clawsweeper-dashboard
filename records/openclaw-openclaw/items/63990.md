## Summary

Keep open: current main and v2026.6.11 still expose a single `memorySearch` provider/model/fallback and one canonical memory index. The existing identity guard prevents mixed vector-space search, but the requested per-model indexes, dual ingestion, active/fallback index routing, and status surface remain unimplemented and need maintainer product/API direction.

## What This Changes

Request first-class multi-index embedding memory so each embedding model has its own index, coordinated ingestion, active/fallback routing, and observability.

## Best Possible Solution

Keep this as the canonical maintainer design tracker for model-aware memory indexes, define the config/storage/migration/status and plugin-API contract first, and let the narrower fallback recovery bug proceed separately.
