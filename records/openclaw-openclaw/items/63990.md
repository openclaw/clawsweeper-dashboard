## Summary

Keep open: current main and v2026.6.11 still expose scalar memorySearch provider/model/fallback settings and one canonical memory index. The existing identity guard prevents mixed vector-space search, but the requested per-model indexes, dual ingestion, active/fallback index routing, and status surface remain unimplemented product/API work.

## What This Changes

The issue requests first-class multi-index embedding memory so each embedding provider/model can use its own index, ingestion state, query routing, failover policy, and observability without mixing vector spaces.

## Best Possible Solution

Define a maintainer-approved memory-index contract that keeps a canonical chunk source, persists one vector index per embedding identity, exposes active/fallback index state, and preserves existing single-index configs through an explicit migration or doctor path.
