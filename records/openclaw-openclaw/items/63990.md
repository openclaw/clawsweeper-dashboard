## Summary

Keep open: current main and v2026.6.11 still expose a single `memorySearch` provider/model/fallback and one builtin memory index. The existing identity guard prevents mixed vector-space search, but the requested per-model indexes, coordinated ingestion, active/fallback index routing, and index status surface remain unimplemented and need maintainer product/API direction.

## What This Changes

The issue requests first-class multi-index memory embeddings with per-model indexes, dual ingestion, active/fallback index routing, observability, and backward-compatible config.

## Best Possible Solution

Adopt a maintainer-approved memory-core design that keeps one canonical chunk source, stores per-model vector indexes with explicit identity and readiness, routes queries to exactly one compatible active/fallback index, and includes doctor/migration/status coverage for existing single-index installs.
