## Summary

Keep open: current main and v2026.6.11 still expose a single memorySearch provider/model/fallback and one canonical memory index. The existing identity guard prevents mixed vector-space search, but the requested per-model indexes, dual ingestion, active/fallback index routing, and status surface remain unimplemented and need maintainer product/API direction.

## What This Changes

The issue requests first-class multi-index embedding memory with one index per embedding model, coordinated ingestion, explicit active/fallback index routing, observability, and backward-compatible config migration.

## Best Possible Solution

Keep this as the canonical maintainer design tracker for model-aware memory indexes, define the config/storage/migration/status and plugin-API contract first, and let narrower fallback recovery bugs proceed separately.
