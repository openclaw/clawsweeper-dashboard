## Summary

Keep open: current main and v2026.6.11 still expose a single memory-search provider/model/fallback and one canonical memory index. The current identity guard prevents unsafe mixed-vector search, but the requested per-model indexes, dual ingestion, active/fallback index routing, and index status surface remain unimplemented and require maintainer product/API direction.

## What This Changes

The issue requests first-class multi-index memory search with one embedding index per model, model-aware failover, coordinated ingestion, status/metrics, and backward-compatible config.

## Best Possible Solution

Keep this as the canonical maintainer design tracker for model-aware memory indexes, define the config/storage/migration/status and plugin-API contract first, and let narrower fallback recovery bugs proceed separately.
