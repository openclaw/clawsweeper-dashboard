## Label Justifications

- `P1`: Incorrect success status and exit code can cause active shell scripts and CI jobs to accept incomplete agent work as completed.
- `merge-risk: 🚨 compatibility`: The branch intentionally changes the process exit status returned to existing callers for resolved terminal gateway outcomes.

## Summary

This PR addresses the linked current P1 bug with detailed live-provider proof and focused regression coverage; the remaining merge question is whether OpenClaw should intentionally make all resolved `timeout`, `error`, and `cancelled` gateway responses produce a nonzero CLI exit code.

## What This Changes

The branch derives resolved gateway run responses from the normalized terminal outcome and sets `openclaw agent` to exit nonzero after writing timeout, error, or cancelled results.

## Best Possible Solution

Adopt one documented terminal gateway CLI contract: successful terminal completion exits 0, while timeout/error/cancellation outcomes are visibly non-successful after complete output is emitted; explicitly confirm whether cancellation should share exit code 1 or retain a signal-specific convention.
