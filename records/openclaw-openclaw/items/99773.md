## Summary

Keep open: current main still clears nearby hot-reload model/provider caches without clearing the embedded-agent discovery cache, and three open PRs are already competing candidate fixes for the same root cause. The issue should remain open until maintainers pick and land one canonical fix.

## What This Changes

The issue reports that config hot reload can leave include-defined models out of the running gateway model registry, producing intermittent `Unknown model` failover errors until restart.

## Best Possible Solution

Land one narrow fix that clears or otherwise invalidates the embedded-agent model discovery cache during the existing hot-reload model-state reset, with regression coverage for include-backed models surviving a hot reload.

## Reproduction Assessment

No, not as a live run in this review. Source inspection gives a credible reproduction path because hot reload updates runtime config and resets nearby model/provider caches while `DISCOVERY_STORE_CACHE` can keep returning a registry built before the include-backed model config was present.

## Solution Assessment

Yes, a cache invalidation in the existing hot-reload model-state reset appears to be the narrowest maintainable fix. The alternative of adding new config or restart-only behavior would be broader than needed, while open PRs already target the owner-boundary cache reset path.
