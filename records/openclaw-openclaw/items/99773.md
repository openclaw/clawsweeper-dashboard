## Summary

Keep open: current main still supports include-resolved config reloads and refreshes some model/provider runtime state, but source inspection does not prove that embedded-agent model discovery caches are invalidated when include-backed `models.providers` snapshots change or are regenerated after hot reload.

## What This Changes

The issue reports that config hot reload can make include-backed `models.providers` models disappear from the running gateway registry, causing `Unknown model` failover errors until restart.

## Best Possible Solution

Make hot reload publish or invalidate one canonical include-resolved model discovery snapshot for gateway lanes, with regression coverage proving include-backed `models.providers` survive unrelated config reloads.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Not yet; source inspection shows a plausible cache invalidation gap, but this read-only pass did not establish a live daemon repro or a failing regression test.

## Solution Assessment

Is this the best way to solve the issue? Yes for the likely direction: fix the model discovery snapshot/cache boundary after resolved-config reload, rather than adding a fallback that accepts unknown models.
