## Summary

Keep open: current main still lacks embedded-agent model discovery cache invalidation during hot reload, and the issue now has strong reporter logs plus open fix PRs rather than an implemented fix on main.

## What This Changes

The issue reports that gateway hot reload can leave include-defined model providers out of the running embedded-agent model registry, causing registry-layer unknown-model failover failures until restart.

## Best Possible Solution

Review and land one canonical narrow fix, preferably the proof-positive cache-invalidation PR, that clears embedded-agent discovery caches during hot reload and includes an include-backed regression test; then close this issue as implemented.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes for source-level reproduction: warm discoverCachedAgentStores with one resolved config, apply a hot reload with include-backed models, and current main has no discovery-cache reset or config fingerprint to force a fresh registry.

## Solution Assessment

Is this the best way to solve the issue? Yes: invalidating the embedded-agent discovery cache at the existing hot-reload model-state reset boundary is the narrow owner-boundary fix; accepting unknown models or adding provider-side fallback would address the wrong layer.
