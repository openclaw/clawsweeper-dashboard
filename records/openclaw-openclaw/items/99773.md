## Summary

Keep open: current main resolves includes during config reload and resets some provider/model runtime caches, but the code inspected does not prove that already-cached embedded-agent model registries are invalidated when include-backed model providers are used after a hot reload. The report remains a plausible gateway/model snapshot bug, separate from the related hot-reload crash-loop and prior allowlist issue.

## What This Changes

Config hot reload should preserve models supplied through includes and `OPENCLAW_INCLUDE_ROOTS` so running gateway fallback/model resolution matches a fresh CLI config load.

## Best Possible Solution

Make hot reload publish one canonical resolved config/model discovery snapshot for all gateway lanes, or invalidate/rebuild embedded-agent model discovery caches when `models.providers` changes, then add an include-backed hot-reload regression test.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Partly: source inspection shows resolved include config can be applied while embedded-agent discovery caching is not keyed on the resolved model-provider config, but I did not establish a failing live or unit reproduction in this read-only pass.

## Solution Assessment

Is this the best way to solve the issue? The best fix is likely cache/snapshot invalidation at the model discovery boundary, not a fallback that accepts unknown models; it should prove CLI and gateway use the same include-resolved config after hot reload.
