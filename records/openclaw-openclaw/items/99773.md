## What This Changes

The issue reports that config hot reload can leave include-defined models out of cached in-memory registries, causing `FailoverError: Unknown model` until a gateway restart.

## Best Possible Solution

Land one canonical focused fix that clears the embedded-agent model discovery cache during the existing hot-reload model-state reset, then close the duplicate candidate PRs and this issue from the merged fix.

## Reproduction Assessment

Yes, source inspection gives a high-confidence path: warm `DISCOVERY_STORE_CACHE`, apply a config hot reload that rebuilds include-expanded `models.providers`, then observe embedded-agent model resolution reuse the stale cache because current `main` does not clear it. I did not execute the live daemon reproduction in this read-only review.

## Solution Assessment

Yes, invalidating the embedded-agent discovery cache from the existing hot-reload model-state reset path is the narrowest maintainable fix. It avoids a new config option, provider-specific fallback, or steady-state polling.
