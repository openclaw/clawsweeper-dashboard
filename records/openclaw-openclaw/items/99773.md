## Summary

Keep open: current main and the latest shipped release still do not clear the embedded-agent model discovery cache during gateway hot reload, while this issue now has open candidate PRs that should be reviewed and landed before closure.

## What This Changes

The issue reports that gateway hot reload can leave include-defined models out of cached in-memory model registries, causing `Unknown model` failover errors until restart.

## Best Possible Solution

Land one canonical narrow PR that resets the embedded-agent model discovery cache during gateway hot reload, then close this issue with the merge commit and release provenance.

## Reproduction Assessment

Partly: source inspection gives a high-confidence stale-cache path and the reporter added redacted production logs, but I did not run a live current-main gateway reproduction. Current main can reuse cached embedded-agent stores whose fingerprint omits resolved `models.providers`, while hot reload does not clear that cache.

## Solution Assessment

Yes: the best fix shape appears to be a narrow production reset of the embedded-agent discovery cache from the existing hot-reload model-state reset path. The remaining maintainer decision is which duplicate open PR to land, not whether this issue should close now.
