## Summary

Keep open: current main and the latest release still reset the gateway model catalog/provider auth state on hot reload without clearing the embedded-agent discovery cache, while the reporter added logs consistent with stale per-lane model registries. Open PRs already target the fix, so the right cleanup is to review and land one canonical cache-invalidation PR rather than close this issue now.

## What This Changes

The issue reports that gateway hot reload can leave include-defined models out of cached in-memory model registries, causing post-reload failover errors until a restart.

## Best Possible Solution

Keep this issue open until one canonical PR, preferably a narrow cache-invalidation branch with include-root hot-reload proof, lands and GitHub closes it as fixed.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes for source-level reproduction: current main can reuse embedded-agent discovery cache entries that are not keyed on resolved model-provider config, and the reporter supplied production logs for the hot-reload failure. I did not run a live gateway reproduction in this read-only review.

## Solution Assessment

Is this the best way to solve the issue? Yes: clearing the process-local embedded-agent discovery cache from the existing hot-reload model-state reset path is the narrow owner-boundary fix; changing failover behavior or adding steady-state polling would be broader and less direct.
