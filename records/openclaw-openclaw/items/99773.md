## What This Changes

The issue reports that config hot reload can drop include-defined models from the running gateway’s in-memory model registry, causing `Unknown model` failover errors until restart.

## Best Possible Solution

Land one focused hot-reload cache-invalidation PR, preferably the proof-sufficient narrow branch, then close this issue from the merged commit.

## Reproduction Assessment

Yes, at source level: current main reuses `DISCOVERY_STORE_CACHE` across hot reloads while the cache fingerprint omits resolved include-backed `models.providers`. The reporter also supplied production logs showing the same model IDs rejected by the running gateway while a restart cleared the condition.

## Solution Assessment
