## Summary

This PR remains necessary: the linked bug is still represented by the cron-only runner gates on the reviewed base, while the branch moves the documented pre-model claim point into both canonical runners and prevents duplicate execution across fallbacks. The focused tests and reported live claim/fall-through evidence support the approach, and recent direct maintainer participation means this should proceed through normal review rather than cleanup closure.

## What This Changes

The branch makes `before_agent_reply` run once for supported user, heartbeat, and cron turns in embedded and CLI runners, removes the earlier auto-reply invocation, preserves turn context, and adds regression coverage.

## Best Possible Solution

Keep one permission-gated runner-level interception path that receives the documented cleaned user message, preserves channel and sender identity, runs before backend allocation, and deduplicates all fallback attempts within the admitted turn.
