## Summary

Keep open because the reported bug is valid and the runner-level ownership is directionally sound, but the patch introduces a blocking compatibility regression in the public hook event payload.

## What This Changes

The PR moves `before_agent_reply` interception into embedded and CLI runners for user, heartbeat, and cron turns, deduplicates execution across fallbacks, and removes the earlier auto-reply call site.

## Best Possible Solution

Keep runner-level dispatch and once-per-turn fallback deduplication, but thread the normalized post-inline-action user body separately from the model prompt into both runners and cover the complete auto-reply-to-runner path for embedded and CLI execution.

## Solution Assessment

No, not as submitted. Moving ownership to the canonical runners and deduplicating fallbacks is the right shape, but the normalized hook input must remain separate from the model-facing prompt.
