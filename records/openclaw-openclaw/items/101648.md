## Summary

Keep open: the PR has the right bug-fix direction and now has adequate terminal proof, but it is not merge-ready because the new control-flow branch suppresses the false error by returning before the run emits terminal lifecycle settlement that session and compaction-retry code depends on.

## What This Changes

The PR marks `MidTurnPrecheckSignal` as an agent-core control-flow error and makes `Agent.handleRunFailure` skip synthetic failure events for marked errors, with Agent-level tests for suppression and normal errors.

## Best Possible Solution

Suppress the false `MidTurnPrecheckSignal` error while still emitting a clean non-error terminal lifecycle settlement, or catch the signal at the embedded-runner boundary, so retry recovery and session subscribers settle normally.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: current main throws `MidTurnPrecheckSignal` after recording a pending request, and generic `Agent.handleRunFailure` currently turns rejected runs into failure events before the attempt runner processes the pending recovery request. I did not run the full Gateway+MCP large-output reproduction in this read-only review.

## Solution Assessment

No: suppressing the false error is the right direction, but returning before clean terminal settlement drops the lifecycle boundary used by session and compaction retry code. The best fix should suppress error forwarding while preserving `turn_end`/`agent_end` settlement or handle the signal inside the embedded runner.
