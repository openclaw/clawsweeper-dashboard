## Summary

Keep open: the PR targets the right false context-overflow error leak, but the current settlement branch can emit `agent_end` after the loop has already emitted a new `turn_start`, leaving session and extension lifecycle consumers without a matching `turn_end`.

## What This Changes

The PR adds an internal control-flow sentinel to `MidTurnPrecheckSignal`, teaches `Agent.handleRunFailure` to skip synthetic failure events for that sentinel, and adds agent-core tests for control-flow and real-error handling.

## Best Possible Solution

Keep the sentinel/error-suppression idea only if the control-flow path also preserves a coherent turn lifecycle, either by catching before the follow-up `turn_start` opens or by emitting a clean non-error `turn_end` before `agent_end`.
