## Summary

Keep open: the PR fixes the false error-event path in agent-core, but the current settlement still emits a normal `agent_end` before the embedded retry/compaction path handles the pending mid-turn precheck, which can leave subscribers seeing a misleading terminal state instead of an internal retry.

## What This Changes

The PR marks `MidTurnPrecheckSignal` with an agent-core control-flow sentinel, skips synthetic failure forwarding for that sentinel in `Agent.handleRunFailure`, emits a clean `agent_end`, and adds agent-core regression tests.

## Best Possible Solution

Keep the control-flow error suppression, but make the mid-turn precheck exit distinguishable from a real terminal run before embedded retry/compaction continues, with AgentSession or embedded subscriber coverage proving no error, abandoned, or stale terminal event leaks.
