## Summary

Keep open: this PR fixes null-body and declared-oversized Content-Length cases, but no-reader responses without a trusted Content-Length still fall through to whole-body `arrayBuffer()`, so the linked availability bug remains.

## What This Changes

The branch exports `readResponsePrefix`, routes `readResponseBodySnippet` through it for no-reader responses, adds a null-body and Content-Length guard, and extends HTTP error-body tests.

## Best Possible Solution

Make `maxBytes` a real memory-read bound for every no-reader fallback, likely by failing closed unless a strict trusted Content-Length proves the body is under limit, then add regression tests and redacted terminal proof for missing and malformed header cases.
