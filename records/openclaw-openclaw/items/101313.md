## Summary

Keep open: the strict parsing blocker is fixed at the current head, but the no-reader path still trusts Content-Length and calls `arrayBuffer()` before truncation, so an understated header can still materialize an oversized body. The external proof gate also remains mock-only because the provided evidence is focused unit-test output, not a real after-fix runtime transcript.

## What This Changes

The branch exports `readResponsePrefix`, routes `readResponseBodySnippet` through it, adds Content-Length-gated no-reader fallback handling, and expands infra tests.

## Best Possible Solution

Make the no-reader fallback fail closed before any whole-body read, or convert it to a genuinely bounded stream source, then add real after-fix proof that oversized and understated no-reader responses cannot allocate beyond the cap.
