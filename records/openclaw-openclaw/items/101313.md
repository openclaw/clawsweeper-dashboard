## Summary

Keep this PR open: the patch is close, but the no-reader guard still uses loose `Content-Length` parsing, so malformed values can bypass the fail-closed path and reach `arrayBuffer()`. The contributor’s proof is also unit-test output only, which is useful validation but not real behavior proof for an external PR.

## What This Changes

The PR exports and reuses `readResponsePrefix`, adds a Content-Length-gated no-reader fallback, and adds regression tests for `readResponseBodySnippet` and `readResponsePrefix`.

## Best Possible Solution

Make the no-reader fallback fail closed using a strict non-negative Content-Length parser before any whole-body read, keep the streaming path unchanged, and add direct proof for malformed and oversized no-reader responses.
