## Summary

Keep this issue open: current main still suppresses primary probes for an active WHAM subscription reset window when fallbacks exist, but the report does not prove that the originally blocked model recovered, so the permanent bounded-reprobe policy needs maintainer direction. ([github.com](https://github.com/openclaw/openclaw/raw/refs/heads/main/src/agents/model-fallback.ts))

## What This Changes

Re-evaluate long WHAM subscription-limit blocks before their reported reset when a healthy fallback otherwise prevents the preferred OpenAI model from being retried.

## Best Possible Solution

Use a model/profile-scoped half-open state for stale WHAM blocks: probe at a bounded cadence, re-arm on the same model's 429, and clear only after that model succeeds or an authoritative model-scoped snapshot reports availability.

Options:

- **Add bounded model-scoped probes (recommended):** Periodically retry only the blocked model/profile and re-arm the recorded block when the upstream still returns a subscription-limit response.
- **Keep reset authoritative:** Retain the current behavior and document that early account or sibling-model recovery does not invalidate the blocked model's reset deadline.
- **Require same-model proof first:** Wait for the model-scoping work and a live post-block `gpt-5.5` success before selecting a permanent probe policy.

## Reproduction Assessment

Yes for the reported skip behavior: current source deterministically avoids early probes for active WHAM reset windows when fallbacks exist. No high-confidence reproduction yet proves that the originally blocked GPT-5.5 model itself had recovered.

## Solution Assessment

Unclear: bounded reprobes are a plausible recovery mechanism, but the safest permanent solution is model/profile-scoped and should be calibrated against same-model live proof and the related model-scoping change.
