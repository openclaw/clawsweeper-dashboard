## Summary

Keep open: the underlying bug is valid, but the current head still treats an explicitly invalid port as absent, allowing setup to succeed while retaining an existing port or falling back to 8080; the posted evidence also does not exercise the real setup path.

## What This Changes

The PR replaces Signal setup’s direct numeric port coercion with the shared TCP-port parser and adds focused tests for valid, absent, and malformed port strings.

## Best Possible Solution

Keep the shared parser, but reject every non-empty malformed, fractional, zero, or out-of-range port through Signal’s existing setup validation hook before configuration mutation; omit the field only when no port was supplied.
