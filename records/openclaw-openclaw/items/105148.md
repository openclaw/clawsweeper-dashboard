## Summary

Keep open: the root cause is real, but the patch treats an explicitly invalid port as absent, allowing setup to succeed with the default port instead; the submitted proof also does not exercise the actual setup path.

## What This Changes

The PR parses Signal’s optional setup HTTP port and includes it only when it is an integer from 1 through 65535.

## Best Possible Solution

Reject explicit malformed `httpPort` values through the setup adapter validator, reuse the plugin SDK’s `parseTcpPort`, and cover valid, absent, and invalid inputs with focused adapter tests and real setup-path proof.
