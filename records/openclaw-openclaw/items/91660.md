## Summary

The PR remains useful and reviewable: current main still passes the resolved memory embedding model into adapters but returns an adapter-created empty `provider.model` unchanged, while this branch normalizes that value at the creation boundary and adds focused regression coverage. I found no blocking correctness or security finding, but the change intentionally affects memory index/provider identity for previously broken empty-model states, so maintainer upgrade-risk acceptance is still the gating decision.

## What This Changes

The branch changes `createWithAdapter()` in `extensions/memory-core/src/memory/embeddings.ts` to reuse the resolved embedding model and backfill an empty returned `provider.model`, with regression tests for empty, preserved, and upgrade identity cases.

## Best Possible Solution

Land the creation-boundary backfill if maintainers accept the memory identity upgrade behavior, keeping the fix centralized in provider creation rather than adding downstream fallbacks.
