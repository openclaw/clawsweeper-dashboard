## Label Justifications

- `P1`: The PR fixes a broken Codex/OpenClaw coding workflow where filesystem discovery falls back to shell approval when only filesystem tools are allowed.

## Summary

Keep open for maintainer review: source inspection and contributor live output show a real Codex dynamic-tool gap, but this PR intentionally changes `group:fs` policy semantics, sandbox directory-listing boundaries, and plugin SDK public surface, so it should not auto-merge without explicit maintainer acceptance and final exact-head checks.

## What This Changes

The PR adds `grep`, `find`, and `ls` to core coding tool construction/catalog, routes them through sandbox filesystem bridges, aligns `group:fs` policy/docs, and updates regression coverage plus the plugin SDK surface budget.

## Best Possible Solution

Land this only after maintainers explicitly accept the expanded filesystem policy/security boundary and public-surface growth; otherwise split discovery into explicit tool names or a separate filesystem-discovery group before merge.

## Reproduction Assessment

Yes. Current main's Codex dynamic-tool path calls `createOpenClawCodingTools`, and that coding factory omits `grep/find/ls`; the PR body also includes after-fix live output showing those tools constructed with runtime tools denied.

## Solution Assessment

Mostly yes. Adding the tools at the canonical coding factory/catalog and sandbox bridge boundary is more maintainable than a Codex-only shim, but the expanded policy/API boundary needs maintainer acceptance.
