## Summary

Keep open: current main has startup-sidecar readiness, `/readyz`, restart deferral, and stale-process cleanup, but the broader partial-reload contract remains unresolved because `sessions.resolve` can still report missing sessions rather than a shared degraded/reloading state. The open WebChat PR addresses a narrower recovery-notice subset, not the full macOS launchd partial-reload and Control UI resilience problem.

## What This Changes

The issue asks OpenClaw to handle macOS launchd plugin/config maintenance without exposing a broken partial Gateway reload state to Control UI or requiring `doctor --fix` for recovery.

## Best Possible Solution

Define one Gateway degraded/reload/draining state that Control UI and session RPCs consume, keep launchd restart recovery deterministic, and treat the open WebChat notice PR as a scoped subset unless maintainers choose a broader recovery design.
