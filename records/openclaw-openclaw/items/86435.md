## Summary

Keep open: current main and v2026.6.11 still have the reported partial-reload shape where readiness exists as a probe, but `sessions.resolve` can still return plain `No session found` and Control UI does not have one shared degraded/reloading contract for this macOS launchd recovery path.

## What This Changes

The issue asks for macOS launchd plugin/config maintenance to avoid leaving Control UI and session RPCs in a partially alive, misleading reload state that may require `doctor --fix` to recover.

## Best Possible Solution

Define one Gateway reload/readiness state that `sessions.resolve` and Control UI consume, keep macOS launchd restart recovery deterministic, and validate the behavior with a live managed-Gateway replay while treating the WebChat notice PR as a narrower subset.
