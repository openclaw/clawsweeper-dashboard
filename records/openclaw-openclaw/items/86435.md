## Summary

Keep open: current main has useful readiness, restart-deferral, stale-process cleanup, and startup-unavailable pieces, but it still does not give Control UI and `sessions.resolve` one shared degraded-state contract for the macOS launchd partial-reload window. The linked WebChat item and candidate PR cover a narrower restart-notice path, not the full plugin/config maintenance recovery problem.

## What This Changes

The issue asks for more deterministic macOS launchd gateway reload/restart behavior when live plugin/config maintenance leaves Control UI and session APIs in a partial state.

## Best Possible Solution

Define one gateway reload readiness contract for deferred restart, startup sidecars, incomplete plugin/channel sets, and stale launchd handoff; make Control UI and session RPCs degrade through that contract, then prove it with focused tests and live macOS launchd evidence.
