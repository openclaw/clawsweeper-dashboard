## Summary

Keep open: current main has restart deferral, stale-process cleanup, `/readyz`, and startup-unavailable pieces, but the central Control UI and `sessions.resolve` degraded-state contract remains unresolved; the open WebChat PR is a narrower notice fix, not a full macOS launchd partial-reload recovery solution.

## What This Changes

The issue asks for macOS launchd plugin/config maintenance to avoid leaving Gateway and Control UI partially alive with misleading session-resolution failures and doctor-only recovery.

## Best Possible Solution

Define a single Gateway reload/readiness state that `sessions.resolve` and Control UI consume, keep restart recovery deterministic under launchd, and validate the full plugin/config maintenance path with a live macOS managed-Gateway replay.
