## Summary

Keep open: current main has useful `/readyz`, startup-unavailable, restart-deferral, and stale-process cleanup pieces, but it still does not provide one shared partial-reload/degraded-state contract that `sessions.resolve` and Control UI consume during macOS launchd/plugin maintenance. The linked WebChat PR covers a narrower recovery-notice subset and is still open, so this issue remains the broader tracker.

## What This Changes

The issue asks OpenClaw to keep macOS launchd Gateway plugin/config maintenance from exposing a partially alive Control UI and to recover with clear degraded-state session behavior instead of requiring `doctor --fix`.

## Best Possible Solution

Define one Gateway reload/readiness state that `sessions.resolve` and Control UI can consume, make launchd restart recovery deterministic around stale processes and active sessions, and validate it with a live macOS managed-Gateway replay.
