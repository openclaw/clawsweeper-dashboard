## Summary

Keep open: current main has readiness probes, startup retry handling, restart deferral, and stale-process cleanup, but it still lacks a shared partial-reload/degraded-state contract for Control UI and `sessions.resolve`.

## What This Changes

The issue asks for macOS launchd Gateway plugin/config maintenance to recover deterministically and surface a clear reload/degraded state instead of broken Control UI, misleading `No session found` errors, or `doctor --fix` as the escape hatch.

## Best Possible Solution

Define one Gateway reload/readiness state consumed by `sessions.resolve`, Control UI startup/history paths, and restart recovery, then validate it with a live macOS launchd-managed Gateway replay.
