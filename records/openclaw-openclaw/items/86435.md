## Summary

Keep open: current main and v2026.6.11 still have partial restart/readiness pieces rather than one shared degraded-state contract that Control UI and `sessions.resolve` consume during plugin/config reload. The open WebChat PR covers a narrower missing-notice subset, not the full macOS launchd partial-reload recovery problem.

## What This Changes

The issue asks OpenClaw to keep macOS launchd plugin/config maintenance from exposing a partially reloaded Gateway as a broken Control UI/session state.

## Best Possible Solution

Define a shared Gateway degraded/reloading state for plugin/config reload and restart deferral, make session RPCs and Control UI surface it instead of misleading session-missing errors, keep launchd restart recovery deterministic, and validate with a managed macOS replay.
