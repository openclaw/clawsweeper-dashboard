## Summary

Keep open: current main and the latest release still have partial mitigations rather than one shared degraded-state contract for Gateway reload readiness, Control UI, and `sessions.resolve`. The related WebChat issue and open PR cover a narrower missing-notice subset and do not supersede this broader macOS launchd partial-reload recovery problem.

## What This Changes

The issue reports that macOS launchd plugin/config maintenance can leave Gateway partially reloaded while Control UI remains reachable with misleading session and connection failures.

## Best Possible Solution

Define one Gateway reload/readiness state that `sessions.resolve` and Control UI can consume, return retryable degraded-state errors instead of misleading missing-session errors during partial reloads, keep restart recovery deterministic under launchd, and validate the flow with a live macOS managed-Gateway replay.
