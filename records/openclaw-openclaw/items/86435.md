## Summary

Keep open: current main has useful readiness probes, startup-unavailable handling, restart deferral, and adjacent WebChat fixes, but the broad partial-reload contract is still missing because `sessions.resolve` can still report `No session found` instead of a shared reload/degraded state.

## What This Changes

The issue asks OpenClaw to make macOS launchd Gateway plugin/config reloads recover deterministically and surface a clear Control UI/session degraded state instead of a misleading partial-liveness failure.

## Best Possible Solution

Define one shared Gateway reload/readiness state that `sessions.resolve` and Control UI consume, keep launchd restart recovery deterministic, and validate it with a live macOS managed-Gateway replay while treating the WebChat notice PR as only a subset fix.
