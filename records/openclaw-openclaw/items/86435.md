## Summary

Keep open: current main has readiness probes, startup-unavailable handling, restart deferral, and restart-recovery pieces, but it still does not define one shared partial-reload/degraded-state contract for Control UI and `sessions.resolve`. The related WebChat issue and open PR cover a narrower no-notice/recovery subset, not the full macOS launchd partial-reload and restart-recovery problem.

## What This Changes

The issue asks OpenClaw to make macOS launchd plugin/config maintenance recover deterministically and show a clear Control UI degraded/reloading state instead of partial liveness, `sessions.resolve` `No session found`, and recovery via `doctor --fix`.

## Best Possible Solution

Define one Gateway reload/readiness degraded-state contract consumed by `sessions.resolve` and Control UI, keep launchd restart recovery deterministic, and validate it with a live macOS managed-Gateway replay; treat the WebChat transcript-notice PR as a narrower subset only.
