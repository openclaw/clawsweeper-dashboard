Full review comments:

- **[P2] Reserve announce run IDs for backend callers:** `src/gateway/session-lifecycle-state.ts:197`
  - body: This is a late finding from re-reading the same head: `idempotencyKey` is public Gateway input and `agent` uses it directly as `runId`, but this patch treats any `announce:` run ID as an announce delivery. A public caller can therefore start a normal human turn with `idempotencyKey: "announce:..."`; if the gateway restarts, `recoverRestartAbortedMainSessions` will classify it as announce-only and skip the human restart recovery. Please reserve the `announce:` prefix for backend/internal announce calls, similar to the existing exec-approval followup guard, or persist the announce marker from trusted handoff context instead of raw run ID text.
