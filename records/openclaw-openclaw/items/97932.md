## Summary

Keep open: the PR is a useful, well-proven fix for the announce recovery cascade, but the current head has a blocking namespace bug because it treats any `announce:` run id as delivery-only without reserving that public idempotency-key prefix.

## What This Changes

The PR adds a shared subagent announce handoff classifier, disables tools for announce completion handoffs across embedded, CLI, and Codex native paths, persists announce recovery state, and skips human restart recovery for interrupted announce deliveries.

## Best Possible Solution

Reserve the announce idempotency/run-id namespace for backend announce handoffs, or persist `announceLastRun` from authenticated handoff metadata, add a public-prefix regression, then land after maintainers accept the recovery state.
