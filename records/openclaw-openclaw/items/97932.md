## Summary

Keep this PR open: it is a useful, well-proven fix for the Telegram subagent announce restart cascade, but it is not merge-ready because the new announce recovery state trusts a caller-controlled run-id prefix.

## What This Changes

The PR adds a shared subagent completion announce classifier, disables tools for announce handoffs across embedded/CLI/Codex-native paths, persists announce-run lifecycle state, and skips human restart recovery for interrupted announce delivery turns.

## Best Possible Solution

Keep the unified announce classifier and tool-free handoff design, but make the announce recovery marker non-spoofable by reserving the announce idempotency namespace for trusted internal callers or deriving it from trusted announce provenance, with regression coverage for a normal run using an `announce:` idempotency key.
