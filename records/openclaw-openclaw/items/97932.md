## Label Justifications

- `P1`: The PR fixes a real broken Telegram/subagent restart workflow and currently has a blocking session recovery regression risk.

## Summary

Keep open: this is a useful bugfix with strong Telegram proof, but the new restart-recovery discriminator currently trusts a caller-controlled run-id prefix and needs a narrow fix before merge.

## What This Changes

The branch adds a shared subagent announce classifier, disables tools for announce handoffs across agent execution paths, tracks announce runs in session lifecycle state, and adds regression tests for restart recovery and tool isolation.

## Best Possible Solution

Keep the tool-free announce delivery and restart-recovery behavior, but make the announce recovery marker non-forgeable by reserving or validating the `announce:` namespace for trusted internal handoffs or by carrying an explicit internal run kind.

## Solution Assessment

No, not yet: the tool-free announce approach is the right owner-boundary shape, but the restart discriminator must not rely only on a caller-controlled idempotency prefix. The narrow fix is to reserve/validate the namespace for trusted internal handoffs or persist a non-forgeable announce marker.
