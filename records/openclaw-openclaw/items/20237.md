## Summary

Keep open: current main still only partially covers this feature request, with cron editing/history, delete-after-run, Web Push settings, and inline context usage present, but no shared in-app notification queue, actionable cron-result popup layer, or snooze/reschedule flow.

## What This Changes

Request to add a native Control UI notification/toast system with actionable cron-result popups, inline cron management and snooze controls, one-shot cron UI, and context pressure monitoring with flush prompts.

## Best Possible Solution

Define one shared connected-Control-UI notification/action contract first, then wire cron-result popups and context-pressure compact actions into that model with explicit snooze/reschedule semantics.
