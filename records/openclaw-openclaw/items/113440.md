## Summary

Keep open for maintainer design review. Current main has a top-level `before_tool_call` hook, but the requested resolved-operation pre-effect gate would create a new security-sensitive plugin contract across several tool owners; no evidence shows that contract already exists or that a narrow automated fix is safe.

## What This Changes

Add a generic plugin authorization hook that receives redacted, resolved facts for nested tool operations immediately before their external effect.

## System Context

OpenClaw builds an agent tool set for each run, then wraps model-visible tools with the existing plugin hook before execution. Individual tools may resolve a more concrete exec target, node action, MCP target, or plugin-owned effect after that wrapper has run.

## Architecture Diagram

flowchart LR
  A[Model tool call] --> B[Existing top-level plugin hook]
  B --> C[Tool-specific resolution]
  C --> D[Requested resolved-operation gate]
  D --> E[Exec or node effect]
  D --> F[MCP or plugin effect]
  E --> G[External system]
  F --> G

## Best Possible Solution

Define one owner-approved, versioned resolved-operation authorization contract with an explicit coverage matrix, redacted event schema, scope semantics, and cross-harness integration tests before implementing any participating path.
