## Summary

The revised head correctly resolves both prior review findings by rejecting malformed explicit overrides and requiring HTTP(S), but it introduces a new merge-blocking disclosure: both validation errors echo the full configured URL, which may contain credentials or sensitive query parameters.

## What This Changes

The PR changes shared ElevenLabs base URL normalization to reject malformed and non-HTTP(S) explicit overrides while retaining the default for absent or blank values, and adds focused helper tests.

## Best Possible Solution

Keep the centralized plugin-owned HTTP(S) validation, but omit the configured value from errors or use an approved redacted representation, with a regression test proving credential-bearing URLs are not disclosed.
