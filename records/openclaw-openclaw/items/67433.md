Overall confidence: 0.88

Full review comments:

- **[P1] Keep wait-mode retries idempotent:** `src/gateway/server/hooks-request-handler.ts:313-315`
  - body: This branch disables the replay cache whenever `waitForResult` is true, so a client retry with the same `Idempotency-Key` starts another isolated agent run. The existing hook idempotency contract was added to prevent repeated authenticated deliveries from launching duplicate privileged runs; wait-mode needs an equivalent in-flight/completed replay contract or a maintainer-approved replacement before merge.
  - confidence: 0.89
- **[P2] Return sessionKey on async replay responses:** `src/gateway/server/hooks-request-handler.ts:337`
  - body: The cached async branch now claims to keep the replayed response consistent with a fresh async response, but it omits `sessionKey` while the fresh branch returns it. Callers that retry a successful async request will see a degraded response shape compared with the first response and the documented new contract.
  - confidence: 0.86
- **[P2] Bound hook result and error payloads:** `src/gateway/server/hooks-request-handler.ts:388`
  - body: The new response path forwards `outputText` directly as `result`, and error paths forward raw error strings. `RunCronAgentTurnResult.outputText` is explicitly not truncated, so authenticated hook callers can receive arbitrarily large or overly detailed agent output unless this API adds a byte cap/redaction envelope.
  - confidence: 0.8
