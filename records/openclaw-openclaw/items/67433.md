- **[P1] Keep idempotency effective for wait-mode retries:** `src/gateway/server/hooks-request-handler.ts:313-315`
  - body: `waitForResult` currently disables the replay cache, so a client retry after a timeout or lost response with the same idempotency key will dispatch a second isolated agent run instead of joining or replaying the first result. That regresses the existing `/hooks/agent` dedupe contract and can duplicate downstream session side effects unless maintainers explicitly make wait-mode retries caller-owned.
  - confidence: 0.88
- **[P2] Return a consistent async replay response:** `src/gateway/server/hooks-request-handler.ts:382-388`
  - body: Fresh non-wait requests now return `status: "accepted"` and `sessionKey`, but replay hits still return only `{ ok, runId }`. Idempotent retries should not get a degraded response shape for the same accepted run; either cache enough response data to return the same shape or keep the fresh async shape compatible with replay.
  - confidence: 0.82
- **[P2] Bound and sanitize returned agent output:** `src/gateway/server/hooks-request-handler.ts:372-388`
  - body: The new `result` and `error` fields return agent output and failure text directly through external hook ingress. Since `RunCronAgentTurnResult.outputText` is explicitly not truncated, this needs a documented maximum and redaction/sanitization contract before the endpoint exposes it as a machine-readable API.
  - confidence: 0.84
