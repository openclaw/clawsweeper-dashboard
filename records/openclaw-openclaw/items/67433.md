- **[P2] Preserve sessionKey on idempotent async replays:** `src/gateway/server/hooks-request-handler.ts:337`
  - body: Fresh async `/hooks/agent` responses now include `sessionKey`, and the docs advertise that shape, but cached idempotent replays still return only `ok`, `status`, and `runId`. Store the resolved session key in the replay cache or avoid documenting it as part of the stable async response so retries do not get a degraded contract.
  - confidence: 0.92
- **[P1] Keep idempotency for wait-mode retries:** `src/gateway/server/hooks-request-handler.ts:313-315`
  - body: Setting `replayKey` to `undefined` for `waitForResult` means a client retry with the same idempotency key starts a second isolated agent run, undoing the `/hooks/agent` replay protection for the new mode. Waiting calls need replay state that can return or locate the original result, or an explicit maintainer-approved security/API exception.
  - confidence: 0.86
- **[P2] Bound returned agent output before exposing it:** `src/gateway/server/hooks-request-handler.ts:388`
  - body: The response forwards `outputText` directly as `result`, but the upstream cron result type says this text is not truncated. Add a byte or character cap, or return a narrow envelope, so an authenticated hook caller cannot force unbounded response bodies through the gateway result path.
  - confidence: 0.78
