## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Keep idempotency active for wait-mode retries:** `src/gateway/server/hooks-request-handler.ts:313`
  - body: Setting `replayKey` to `undefined` when `waitForResult` is true means a retry with the same `Idempotency-Key` starts a fresh isolated agent run. The existing hook replay behavior was added in https://github.com/openclaw/openclaw/pull/44438 to avoid repeated authenticated deliveries fanning out privileged runs; wait mode should wait on or replay the same terminal result unless maintainers explicitly choose a new security contract.
  - confidence: 0.88
- **[P2] Return sessionKey on replayed async responses:** `src/gateway/server/hooks-request-handler.ts:337`
  - body: The comment says the replayed shape stays consistent with a fresh async response, and fresh async responses plus docs include `sessionKey`, but this cached branch only sends `ok`, `status`, and `runId`. A caller retrying an async request with an idempotency key gets a degraded response shape, so the replay cache should store the resolved session key or the fresh/docs contract should not promise it.
  - confidence: 0.86
- **[P2] Bound returned agent output before exposing it:** `src/gateway/server/hooks-request-handler.ts:388`
  - body: This response reflects `outputText` directly to the external hook caller as `result`, while errors are also returned verbatim on nearby 500 paths. Because this expands hook ingress into a result-readback surface, the PR needs a maintainer-approved envelope with size limits and redaction/sanitization before merge.
  - confidence: 0.74
