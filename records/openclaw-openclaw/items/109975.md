## Summary

This PR should not merge as written: the shared Google OAuth HTTP wrapper already consumes the bounded network response and releases its SSRF transport before returning a buffered in-memory `Response`, so the proposed calls do not fix the claimed connection or file-descriptor leak. The same redundancy was identified in an earlier review cycle and remains at the current head.

## What This Changes

Adds best-effort response-body cancellation before retrying failed Google OAuth project polling and before throwing on a failed onboarding response.

## Best Possible Solution

Keep bounded response consumption and network-resource release centralized in `fetchWithTimeout`, and leave its callers responsible only for interpreting the returned buffered response.
