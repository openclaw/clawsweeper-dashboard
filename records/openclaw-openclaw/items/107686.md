## Summary

This is a useful cost-optimization idea, but current OpenClaw already exposes the provider-neutral model-selection hook needed to implement it as an optional plugin, and repository vision directs optional capabilities away from core. The discussion’s OpenRouter suggestion is valid for users comfortable with that service, while ClawXRouter demonstrates that an open, provider-flexible implementation is also feasible outside core. ([raw.githubusercontent.com](https://raw.githubusercontent.com/openclaw/openclaw/main/src/plugins/hook-before-agent-start.types.ts))

## What This Changes

Requests automatic task-, cost-, availability-, capability-, and performance-aware selection among multiple language models.

## Best Possible Solution

Keep core’s generic `before_model_resolve` contract and publish a provider-neutral routing code plugin through ClawHub, potentially adapting the existing ClawXRouter work rather than creating another core routing policy. ([raw.githubusercontent.com](https://raw.githubusercontent.com/openclaw/openclaw/main/src/plugins/hook-before-agent-start.types.ts))
