## Summary

Keep this PR open for maintainer review. The reported startup regression has credible after-fix gateway proof, but the patch makes core treat an opaque plugin-owned `webSearch.omitAuth` shape as a security-relevant signal for bypassing full secrets preparation; that needs an explicit, owner-approved plugin/core contract before merge.

## What This Changes

The branch allows a selected keyless host-proxied web-search plugin to use the gateway secrets fast path when its plugin entry sets `config.webSearch.omitAuth: true`, while credential-bearing and unsupported web configurations continue through full preparation.

## System Context

At gateway startup, OpenClaw first decides whether configuration can use a lightweight secrets snapshot or must load the full secrets and web-tool resolver. This PR changes that eligibility decision for selected plugin-based web search, affecting both cold-start work and credential-resolution boundaries.

## Architecture Diagram

  C -->|Eligible| D[Minimal secrets snapshot]

  D --> F[Gateway becomes ready]

## Best Possible Solution

Agree and document a generic plugin SDK or manifest capability for declaring a selected keyless web-search provider as safe for the secrets fast path, then have core consume that stable contract; otherwise retain the full resolver for plugin-owned web-search configuration.
