## Summary

This PR should stay open: it targets a real source-reproducible sandbox audit false positive, but the proposed prefix check can also classify malformed 127-prefixed hosts as loopback and the external branch still lacks after-fix Docker/sandbox proof.

## What This Changes

The branch widens the sandbox browser audit's Docker publish-host loopback check from exact `127.0.0.1` to any normalized host string beginning with `127.`.

## Best Possible Solution

Use canonical IP parsing for the audit helper so real 127/8 and IPv6 loopback hosts pass while malformed or non-loopback Docker publish hosts still emit the critical finding, backed by regression tests and real Docker/sandbox proof.

## Solution Assessment

No, not as written: widening to 127/8 is the right direction, but string-prefix matching is not the best security-audit implementation. The safer fix is to reuse the shared loopback IP parser and add focused audit coverage.
