## Label Justifications

- `P0`: The issue reports a network-reachable authentication bypass on a voice-call WebSocket that can accept forged media for an active call.
- `impact:security`: The affected behavior is an unauthenticated WebSocket media-stream boundary with possible call audio injection or transcript exposure.

## Summary

Keep open: current main still validates `/voice/stream` start frames with a Twilio-only token check and then accepts any active non-Twilio provider call id, so this is a live security-boundary report rather than conservative cleanup.

## What This Changes

Require authenticated media-stream WebSocket start frames for non-Twilio voice-call providers instead of accepting any active provider call id.

## Best Possible Solution

Fail closed for `/voice/stream` unless the active provider has a per-call stream credential verifier; if non-Twilio media-stream support is intended, add provider-owned token generation, validation, and regression coverage before accepting starts.
