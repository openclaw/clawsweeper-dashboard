## Summary

Keep open: current main still resolves an allowed elevated session with no explicit `elevatedDefault` to `on`, and omitted per-call `elevated` then routes through elevated target resolution to gateway instead of sandbox.

## What This Changes

The issue asks for elevated exec to remain sandbox-by-default unless elevation is explicitly requested, and for `/elevated ask` to support opt-in host execution rather than session-wide host routing.

## Best Possible Solution

Settle the elevated security contract, then align default resolution, exec routing, system prompt text, docs, and regression tests so sandboxed exec only leaves the sandbox through the chosen explicit elevation path.

Options:

- **Default Off Elevated Contract (recommended):** Unset `agents.defaults.elevatedDefault` resolves to `off`, and host exec requires an explicit directive or per-call elevation path.
- **Keep Current Host-Default Contract:** Preserve `on` as the default for allowed elevated sessions and update docs/support guidance to make the sandbox escape explicit.
- **Add Separate Opt-In Mode:** Keep current `on`/`ask` semantics but add a distinct sandbox-default mode for per-call elevated host execution.

Yes. Source inspection on current main shows allowed elevated sessions still fall back to `on`, and omitted per-call `elevated` then resolves to elevated gateway exec.

## Solution Assessment

Unclear. Defaulting unset elevated access to `off` is the safer security shape, but redefining `/elevated ask` or changing shipped defaults needs maintainer approval because existing operators may rely on the current behavior.
