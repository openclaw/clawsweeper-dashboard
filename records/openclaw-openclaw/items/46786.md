Keep open: current main and the latest stable release still default allowed elevated sessions to active host-exec routing, while the direct default-off fix is closed unmerged, so this needs maintainer security/product judgment rather than cleanup closure.

## What This Changes

The issue asks for elevated exec enablement to preserve sandbox routing for ordinary `exec` calls and make host elevation opt-in per call or explicit session choice.

## Best Possible Solution

Make a maintainer-owned security decision, then align the elevated fallback, `/elevated ask` semantics, system prompt, docs, and regression coverage in one focused change.

Question: Should OpenClaw change the implicit elevated session default from `on` to `off`, and should `/elevated ask` remain a host-with-approval alias or become sandbox-by-default per-call opt-in elevation?

Rationale: The source-reproducible behavior crosses the sandbox boundary, but the current docs intentionally define `/elevated ask` as `on` and changing defaults may affect existing trusted-operator workflows.

Likely owner: steipete

Owner confidence: high

Options:

- **Default implicit elevation off, keep ask alias (recommended):** Change only the no-explicit-default fallback to `off`, preserve documented `/elevated ask` host-with-approval behavior, and update docs/tests for the safer default.
- **Redefine ask as per-call opt-in:** Make `/elevated ask` keep sandbox exec as the default and route only `exec(elevated: true)` to host with approvals, accepting a larger behavior-contract change.
- **Keep current behavior:** Treat `tools.elevated.enabled` as an explicit opt-in to session-level host exec by default and close the issue only after clarifying any docs that imply otherwise.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: allowed elevated sessions fall back to `on`, omitted `exec.elevated` inherits active elevation, and active elevation resolves sandboxed `auto` exec to `gateway`; I did not run a live Docker scenario in this read-only review.

## Solution Assessment

Unclear pending maintainer decision. Defaulting the implicit elevated level to `off` is the narrowest fix for the silent sandbox bypass, but changing `/elevated ask` semantics is a broader security/product contract choice.
