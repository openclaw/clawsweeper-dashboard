## Summary

Keep open: current main and v2026.6.11 still allow an enabled elevated session to fall back to an active `on` level, and active elevated exec still resolves sandboxed `exec` to the gateway host. The direct default-off fix attempt is closed unmerged, so this remains a security/product decision rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to keep sandbox exec as the default when elevated mode is enabled and make host elevation explicit per call or session.

## Best Possible Solution

Make a maintainer-owned security call, then align the elevated default, `/elevated ask` semantics, system prompt text, docs, and focused regression coverage in one change.

Question: Should OpenClaw change the implicit elevated session default from `on` to `off`, and should `/elevated ask` remain a host-with-approval alias or become sandbox-by-default per-call opt-in elevation?

Rationale: The narrow default-off fix improves sandbox safety, but both default behavior and `/elevated ask` semantics are operator-facing security contracts documented by current main.

Likely owner: steipete

Owner reason: steipete has the strongest recent history across the elevated docs, directive path, and exec approval behavior involved in this decision.

Owner confidence: high

Options:

- **Default implicit elevation off, keep ask alias (recommended):** Change only the no-explicit-default fallback to `off`, preserve documented `/elevated ask` host-with-approval behavior, and update docs/tests for the safer default.
- **Redefine ask as per-call opt-in:** Make `/elevated ask` keep sandbox exec as the default and route only `exec(elevated: true)` to host with approvals, accepting a larger behavior-contract change.
- **Keep current behavior:** Leave `tools.elevated.enabled` as an opt-in to session-level host exec by default and close this as intended behavior after clarifying docs.

## Reproduction Assessment

Yes. Source inspection is a high-confidence reproduction path: allowed elevated sessions still fall back to `on`, omitted exec calls inherit active elevated mode, and elevated target resolution selects the gateway host; I did not run a live Docker scenario in this read-only review.

## Solution Assessment

Unclear pending maintainer decision. Defaulting the implicit elevated level to `off` is the narrowest fix for the silent sandbox routing change, but redefining `/elevated ask` from its documented alias behavior is a broader security/product contract change.
