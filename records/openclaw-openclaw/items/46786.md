## Summary

Keep open: current main and the latest release still allow an elevated-enabled, allowed session with no explicit `elevatedDefault` to resolve to active elevated execution, so non-explicit exec calls can leave the sandbox. The remaining choice is a security/default contract decision, not cleanup-close material.

## What This Changes

The issue requests that enabling `tools.elevated` preserve sandbox exec by default and make host elevation explicit per call or per intentional session setting.

## Best Possible Solution

Maintainers should choose one elevated security contract, preferably default-off unless explicitly configured, then align directive resolution, exec routing tests, system prompt text, and docs around that contract.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should enabling `tools.elevated` for an allowed sender keep sandbox exec as the default unless elevation is explicit, or should the current session-wide elevated-by-default behavior remain supported?

Rationale: This controls the sandbox-to-host exec boundary and can affect existing operator workflows, so automation should not choose the default or redefine `/elevated ask` without maintainer intent.

Likely owner: steipete

Owner reason: The strongest history signal for this contract is the elevated ask/full mode and exec default work authored by steipete.

Owner confidence: high

Options:

- **Default-Off Elevated Contract (recommended):** Unset `agents.defaults.elevatedDefault` resolves to `off`, with `/elevated on|ask|full` or `exec(elevated: true)` as explicit ways to leave the sandbox.
- **Keep Current Session-Wide Behavior:** Document and preserve that allowed elevated sessions default to host exec and that `/elevated ask` is host exec with approvals.
- **Add Separate Opt-In Mode:** Preserve current `on` and `ask` semantics but add a separate explicit mode for sandbox-by-default plus per-call elevation.

## Reproduction Assessment

Yes. Source inspection on current main shows allowed elevated sessions still fall back to `on`, and omitted per-call `elevated` then routes through elevated target resolution to gateway.

## Solution Assessment

Unclear until maintainers choose the security contract. A default-off fix appears safest, but redefining shipped default and `/elevated ask` behavior needs maintainer approval.
