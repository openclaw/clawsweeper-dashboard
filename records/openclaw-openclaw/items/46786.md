## Label Justifications

- `P1`: A sandboxed exec workflow can silently route to the gateway host for allowed elevated sessions, which is an urgent security-default regression with a workaround.
- `impact:security`: The issue is about sandbox isolation and elevated host-execution policy.

## Summary

Keep open: current main and v2026.6.11 still default allowed elevated sessions with no explicit configured/session level to `on`, and active elevated exec maps sandboxed `auto` exec to the gateway host. The direct default-off PR was closed unmerged, and the open per-agent default PR does not fix the implicit default or settle the `/elevated ask` contract.

## What This Changes

The issue requests safer elevated exec defaults so enabling `tools.elevated` does not route ordinary sandbox exec to the gateway, plus a true per-call opt-in elevation mode.

## Best Possible Solution

Make the implicit no-directive elevated level `off`, add regression coverage and docs/status prompt alignment, then handle any per-call-only elevated mode as an explicit maintainer-approved contract.
