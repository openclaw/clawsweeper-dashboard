## Summary

Keep open: current main and v2026.6.11 still allow an elevated-enabled session with no explicit level to become active elevated routing, and active elevated routing still sends implicit sandbox exec to the gateway host. The direct default-off fix attempt is closed unmerged, so the remaining work needs a maintainer security/product decision rather than cleanup closure.

## What This Changes

The issue reports that enabling allowed elevated exec makes implicit sandboxed exec route to the gateway and asks for sandbox-default, opt-in elevation semantics.

## Best Possible Solution

Make a maintainer-owned security/product decision, then align the elevated default, /elevated ask semantics, per-call elevation behavior, system prompt text, docs, and regression coverage in one focused change.

Yes. Source inspection on current main shows allowed elevated sessions fall back to "on", active on/ask levels make omitted exec calls elevated, and elevated target resolution chooses the gateway host.

## Solution Assessment

Unclear pending maintainer decision. Defaulting implicit elevation to off is the narrowest fix for the silent sandbox bypass, but changing /elevated ask from its documented alias behavior is a product/security contract choice.
