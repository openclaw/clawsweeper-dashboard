## Summary

Keep open: current main and the latest stable release still resolve allowed elevated sessions with no explicit level to active elevated routing, and active elevated routing still sends implicit sandboxed exec to the gateway host. The direct default-off fix attempt is closed unmerged, so the remaining work needs maintainer security/product judgment rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to keep sandbox exec as the default when elevated exec is enabled and to make elevation opt-in for non-elevated exec calls.

## Best Possible Solution

Make a maintainer-owned security/product decision, then align the elevated default, `/elevated ask` semantics, per-call elevation behavior, system prompt text, docs, and regression coverage in one focused change.

## Reproduction Assessment

Yes. Source inspection on current main shows allowed elevated sessions fall back to `"on"`, active `on`/`ask` levels make omitted exec calls elevated, and elevated target resolution chooses the gateway host.

## Solution Assessment

Unclear pending maintainer decision. Defaulting the implicit elevated level to off is the narrow fix for the silent sandbox bypass, but changing `/elevated ask` from its documented alias behavior is a security/product contract decision.
