## Summary

Keep open: current main still lets an allowed elevated session with no explicit level fall back to active elevated routing, and active elevated routing still sends implicit sandboxed exec to the gateway host. The direct default-off PR was closed unmerged, and the remaining decision is security/product policy rather than cleanup-close material.

## What This Changes

The issue requests that sandbox exec remain the default when elevated mode is enabled, with gateway execution available only through explicit per-call or session-level elevation.

## Best Possible Solution

Make a maintainer-owned security/product decision, then align the elevated default, /elevated ask semantics, per-call elevation behavior, system prompt text, docs, and regression coverage in one focused change.

## Reproduction Assessment

Yes. Source inspection on current main shows allowed elevated sessions fall back to "on", "on" and "ask" become active elevated mode, and active elevated mode resolves implicit exec to gateway instead of sandbox.

## Solution Assessment

Unclear pending maintainer decision. Defaulting the implicit elevated level to off is the narrow fix for the silent sandbox bypass, but redefining /elevated ask conflicts with current docs and should be decided with the exec policy boundary.
