## Summary

Keep open: current main and v2026.6.11 still resolve an allowed elevated session with no explicit `elevatedDefault` to `on`, and `ask` still means host exec with approvals rather than sandbox-by-default opt-in elevation.

## What This Changes

The issue asks for enabling elevated mode to preserve sandbox exec by default and route to gateway only for explicit elevated calls or explicit session/default elevation.

## Best Possible Solution

Settle the elevated security contract once, then align directive resolution, exec routing tests, system prompt text, and docs so enabling elevated cannot silently change sandbox routing unless maintainers intentionally keep that behavior.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should `tools.elevated.enabled` with an allowed sender keep sandbox exec as the default unless elevation is explicit, or should current session-wide elevated-by-default behavior remain the supported contract?

Rationale: Both choices affect the exec sandbox security boundary and existing operator workflows, so automation should not choose the default without maintainer intent.

Likely owner: steipete

Owner reason: The clearest history signal for the current elevated default path is his exec-tool split and follow-up elevated-default gating change.

Owner confidence: medium

Options:

- **Default-off elevated contract (recommended):** Unset `agents.defaults.elevatedDefault` resolves to `off`; `/elevated on|ask|full` and `exec(elevated: true)` remain the explicit ways to leave the sandbox.
- **Keep current session-wide behavior:** Document and preserve that allowed elevated sessions default to host exec, including `/elevated ask` as host exec with approvals.
- **Add an opt-in-only mode:** Preserve current `on`/`ask` semantics but add a separate explicit mode for sandbox-by-default plus per-call elevation.

## Reproduction Assessment

Yes. Source inspection on current main shows allowed elevated sessions still fall back to `on`, and omitted per-call `elevated` then routes through elevated target resolution to gateway.

## Solution Assessment

Unclear. A default-off fix is the safest security shape, but redefining `/elevated ask` or changing shipped defaults needs maintainer approval because existing operators may rely on the current session-wide behavior.
