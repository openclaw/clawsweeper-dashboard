## Summary

Keep this PR open for maintainer review: it has credible live Docker proof and a focused implementation, but it changes the meaning of an explicitly permitted reserved-path bind without a confirmed owner decision; the prior proof-script exit-status finding also remains unresolved.

## What This Changes

The branch drops Docker, browser, and filesystem-bridge user binds whose container destinations collide with protected read-only skill mounts, adds coverage, and adds a Docker create/inspect proof script.

## Best Possible Solution

Confirm that protected read-only skill mounts always outrank even explicitly allowed reserved-target binds, then keep this filtering design, document the consequence of the existing break-glass setting, test both the normal and opted-in paths, and make the proof script fail on failed assertions.
