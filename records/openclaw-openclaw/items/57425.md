## Summary

Keep open. Current main and v2026.6.11 include meaningful partial restart protection, restart continuations, main-session recovery, subagent recovery, and some delivery recovery, but the umbrella still has unresolved cron retry semantics, durable drain-window message replay, readiness/config policy, and end-to-end recovery-through-delivery behavior.

## What This Changes

The issue requests graceful gateway restart behavior that warns before interrupting active work, preserves or replays drain-window messages, recovers interrupted sessions and subagents, and retries cron work after restart.

## Best Possible Solution

Keep this as the graceful-restart umbrella and land or split narrower maintainer-approved designs for durable inbound/followup replay, cron retry or skipped-run policy, restart readiness defaults, and recovery-through-delivery proof.

## Reproduction Assessment

No high-confidence live reproduction covers the full umbrella in this review. Source inspection does reproduce central remaining slices: drain-window enqueues still fail with GatewayDrainingError, and interrupted cron runs are marked failed rather than durably retried.

## Solution Assessment

Unclear as one implementation. Current main's safe restart, main-session recovery, subagent recovery, and restart continuations are useful partial fixes, but the manifest format, cron retry policy, readiness defaults, inbound replay, and config surface still need maintainer product direction.
