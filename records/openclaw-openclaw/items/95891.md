## Summary

Keep open: the native MiniMax-M3 path is documented to use proper Anthropic thinking blocks, but this issue concerns the distinct `opencode-go` proxy path, whose provider-specific stream handling remains scoped to other model families. The two same-title PR attempts were closed unmerged, and the newer native `minimax-portal/MiniMax-M3` report is related but does not establish that this proxy-specific behavior is fixed. Likely related people: moktamd (medium confidence) for the merged MiniMax streaming-leak mitigation lineage.

## What This Changes

Prevent `opencode-go/minimax-m3` from sending proxy-returned reasoning text as normal channel-visible content when it uses the Anthropic Messages transport.

## System Context

OpenClaw provider plugins turn an agent’s selected model and thinking level into a provider-specific streaming request, then normalize returned blocks for channel delivery. The opencode-go plugin owns request shaping for OpenCode Go’s proxy endpoint; untyped reasoning returned as text can otherwise flow through the generic output path to Telegram and other channels.

  F --> G[Channel delivery]

## Best Possible Solution

Capture a redacted real OpenCode Go MiniMax-M3 Anthropic-stream response, then add a narrowly provider-owned opencode-go wrapper or normalization path that guarantees only final assistant text reaches channels while preserving a nonempty final response for the supported thinking modes.
