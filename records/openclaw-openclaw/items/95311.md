## Summary

Keep open for a provider-owner decision: the patch is technically coherent and well-proven, but it establishes a new public compat contract and changes existing DeepSeek prompt shaping by default. The competing config-free PR does not currently provide a safer canonical landing path.

Likely related people: `vincentkoc` and `steipete` have the strongest history around prompt-cache boundaries and provider compatibility; `Alix-007` has recent adjacent OpenAI-completions transport work.

## What This Changes

Adds a DeepSeek-defaulted `compat.disableBoundaryAwareCache` setting that retains a stable leading system-prompt prefix and moves volatile below-boundary instructions to a trailing system/developer message.

## Best Possible Solution

Adopt the DeepSeek-only stable-prefix strategy with an explicit `false` escape hatch if the provider owner approves the compat contract, keep other prefix-cache providers opt-in until proven, and land it rebased with the existing payload, config, and regression coverage intact.
