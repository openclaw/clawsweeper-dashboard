## Summary

This PR addresses a still-present DeepSeek prompt-cache cost regression with convincing live API evidence and no concrete correctness defect, but it needs provider-owner approval because it establishes a permanent public compatibility key and changes the default DeepSeek request layout.

## What This Changes

Adds `compat.disableBoundaryAwareCache`, defaults it on for DeepSeek, and moves the dynamic below-boundary prompt suffix to a trailing instruction-role message so the leading system prefix remains cacheable.

## Best Possible Solution

Approve a single documented prefix-cache compatibility contract only if provider owners accept the trailing instruction carrier as DeepSeek's permanent default, then land it with explicit opt-out coverage and green exact-head checks.
