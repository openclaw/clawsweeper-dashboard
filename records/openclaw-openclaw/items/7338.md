## Summary

Keep open: current main and the latest release still lack opt-in, domain-scoped agent-origin attestation for arbitrary outbound HTTP requests, and the remaining work is a security/product design decision rather than a stale or implemented request.

## What This Changes

The issue requests optional OpenClaw agent attestation headers, preferably signed and domain-scoped, for outgoing HTTP requests and skill-related calls.

## Best Possible Solution

Define the trust model and exact outbound paths first, then implement an opt-in, domain-scoped attestation contract with privacy-preserving defaults, schema/docs, and tests for allowlisted injection plus non-leakage.

## Reproduction Assessment

Not applicable: this is a feature request rather than a bug report. Source and release inspection show the requested attestation surface is still absent.

## Solution Assessment

Unclear until maintainers choose the trust model. A signed, opt-in, domain-scoped design is directionally safer than static global headers, but existing provider attribution is not a complete solution for arbitrary external requests.
