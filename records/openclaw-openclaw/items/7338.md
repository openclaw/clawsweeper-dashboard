## Summary

Keep open: current main and v2026.6.11 still do not provide general opt-in, domain-scoped agent attestation headers or signed attestations for arbitrary outbound HTTP requests. Existing provider attribution, custom provider headers, and trust-verification plugin hooks are adjacent but narrower, so this remains a product/security design item rather than cleanup-closeable work.

## What This Changes

The issue requests opt-in OpenClaw agent attestation headers or signed attestations on outbound HTTP requests for agent-only external services.

## Best Possible Solution

Keep this open for maintainer product/security design, then implement one opt-in, domain-scoped attestation contract with privacy-preserving defaults, schema/docs, and tests for allowlisted injection plus non-leakage after the trust model is approved.

## Reproduction Assessment

Not applicable: this is a feature request rather than a bug report. Source and release inspection show the requested general attestation surface is absent in current main and v2026.6.11.

## Solution Assessment

Unclear as an implementation path until maintainers choose the trust model. A signed, opt-in, domain-scoped design is safer than static global headers, but existing provider attribution is not a complete solution for arbitrary external requests.
