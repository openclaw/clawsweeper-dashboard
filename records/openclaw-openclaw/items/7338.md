## Summary

Keep this protected feature request open for maintainer-led product and security design. The existing review and discussion distinguish provider-specific attribution from the requested general external-request attestation, and the current item still needs an explicit trust, privacy, and egress-scope decision.

## What This Changes

Request opt-in, domain-scoped static or cryptographic headers that let external services attest that a request originated from an OpenClaw agent.

## Best Possible Solution

Approve a narrow attestation design first: define the security guarantee and covered egress paths, then implement opt-in allowlisted delivery with non-leakage tests, privacy-preserving defaults, and explicit key-management documentation.
