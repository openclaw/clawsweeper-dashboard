## Summary

Keep open. Current main and v2026.6.11 still lack opt-in, domain-scoped agent attestation for arbitrary outbound HTTP requests, and the adjacent provider-attribution and provider-request-header surfaces are narrower than the requested security boundary.

## What This Changes

The issue requests opt-in OpenClaw agent attestation headers for outbound HTTP requests so external services can distinguish agent-originated traffic from direct human API calls.

## Best Possible Solution

Define a maintainer-approved trust model and outbound scope first, then implement a privacy-preserving opt-in attestation contract with domain allowlists, schema/API coverage, docs, and non-leakage tests.
