## Summary

Keep open. Current main and the latest release still lack opt-in, domain-scoped agent attestation for arbitrary outbound HTTP requests; existing provider attribution and provider request-header surfaces are narrower transport features, and this remains a security/product design item.

## What This Changes

The issue requests optional static or cryptographic OpenClaw agent attestation headers for outbound HTTP requests, with skill metadata and user-configurable domain allowlists.

## Best Possible Solution

Define the trust model and outbound scope first, then implement a privacy-preserving opt-in attestation contract with domain allowlists, docs, schema/API coverage, and tests proving allowlisted injection plus non-leakage.

- **Move to plugin or ClawHub:** Require external services to use plugin, skill, or service-level handshakes unless a missing generic core API is identified and approved.
