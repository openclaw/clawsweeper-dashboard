## Summary

Current main and v2026.6.11 still lack general outbound agent attestation, and no related item supersedes this request; the remaining work requires an explicit security and product decision about the claim, key ownership, privacy model, and covered request paths.

## What This Changes

Add optional, domain-scoped static or cryptographic agent attestation to external HTTP requests, potentially configured globally or through skill metadata.

## Best Possible Solution

Define the exact claim and supported request boundary first, then prefer service-owned plugin authentication or a generic allowlisted signing hook for controlled OpenClaw HTTP clients over universal implicit headers.

- **Service-owned plugin authentication (recommended):** Use a dedicated plugin or custom tool whose service owns keys, claims, audience, verification, and domain policy.

- **Core attestation standard:** Define and maintain an OpenClaw issuer, key lifecycle, claim format, replay protections, and explicit cross-path coverage.
