## Summary

Keep open. Current main and v2026.6.11 still lack opt-in, domain-scoped agent attestation for arbitrary outbound HTTP requests, and existing provider attribution/request-header surfaces are narrower transport features rather than a general agent-origin attestation contract.

## What This Changes

The issue requests optional OpenClaw agent attestation headers or signed attestations for outbound HTTP requests, with user or skill configuration and domain scoping.

## Best Possible Solution

Define the trust model and outbound scope first, then implement a privacy-preserving opt-in attestation contract with domain allowlists, schema or API coverage, docs, and non-leakage tests.
