## Summary

Keep open: current main and the latest release still lack a general opt-in, domain-scoped agent-origin attestation surface for arbitrary outbound HTTP requests. Existing provider headers, provider attribution, policy attestation, and plugin trust hooks are adjacent but do not solve signed or static agent-origin attestation for external services, so this remains a product and security design item.

## What This Changes

Request to add opt-in OpenClaw agent attestation headers or signed tokens for outbound external HTTP requests, with domain scoping and optional skill/config metadata.

## Best Possible Solution

Define the trust model and exact outbound paths first, then implement an opt-in, domain-scoped attestation contract with privacy-preserving defaults, schema/docs, and tests for allowlisted injection plus non-leakage.

## Reproduction Assessment

Not applicable: this is a feature request rather than a bug report. Source and release inspection show the requested attestation surface is absent in current main and v2026.6.11.

## Solution Assessment

Unclear until maintainers choose the trust model. A signed, opt-in, domain-scoped design is directionally safer than static global headers, but existing provider attribution and static model-provider headers are not a complete solution for arbitrary external requests.
