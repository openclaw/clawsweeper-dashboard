## Summary

Keep open. Current main and v2026.6.11 still lack general opt-in, domain-scoped agent attestation for outbound HTTP requests; provider attribution, provider request headers, trusted-proxy auth, and plugin hooks are narrower surfaces, so this remains a product/security design item.

## What This Changes

The issue requests opt-in OpenClaw agent attestation headers or signed tokens for outbound HTTP requests so external services can distinguish agent-originated calls from direct human/API clients.

## Best Possible Solution

Define a maintainer-approved trust model and outbound scope first, then implement a privacy-preserving opt-in attestation contract with domain allowlists, schema/API coverage, docs, and non-leakage tests.
