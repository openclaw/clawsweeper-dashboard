## Summary

Keep open: current main and the latest release still lack a general opt-in, domain-scoped agent-origin attestation surface for outbound HTTP requests. Existing provider attribution, sender identity hook context, and trust-provider plugin hooks are adjacent but do not provide static or signed attestation headers for external services.

## What This Changes

The issue requests optional OpenClaw agent attestation headers, preferably signed and domain-scoped, for external HTTP requests made by agents, skills, or tools.

## Best Possible Solution

Define the trust model and exact outbound paths first, then implement an opt-in, domain-scoped attestation contract with privacy-preserving defaults, schema/docs, and tests for allowlisted injection plus non-leakage.

## Reproduction Assessment

Not applicable: this is a feature request rather than a bug report. Source and release inspection show the requested attestation surface is absent in current main and v2026.6.11.

## Solution Assessment

Unclear until maintainers choose the trust model. A signed, opt-in, domain-scoped design is directionally safer than static global headers, but existing provider attribution and plugin trust hooks are not complete solutions for arbitrary external requests.
