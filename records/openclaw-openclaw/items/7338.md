## Summary

Keep open. Current main and v2026.6.11 still lack opt-in, domain-scoped agent-origin attestation for arbitrary external HTTP requests; existing provider attribution and provider request headers are narrower transport features, while the issue remains a product/security design tracker.

## What This Changes

The issue requests optional agent attestation headers on outbound HTTP requests so external services can verify OpenClaw agent-originated traffic.

## Best Possible Solution

Keep this open for maintainer product/security design, then implement a privacy-preserving opt-in attestation contract with explicit outbound scope, domain allowlists, non-leakage tests, docs, and any required plugin/config API changes.

## Reproduction Assessment

Not applicable: this is a feature request rather than a broken existing behavior report. Source and release-tag inspection show the requested attestation surface is absent in current main and v2026.6.11.

## Solution Assessment

Unclear: adding headers directly is not yet proven to be the best solution because trust, privacy, signing, audience, and outbound path scope remain unsettled. The safer path is design approval first, followed by a narrow opt-in implementation with allowlist and non-leakage proof.
