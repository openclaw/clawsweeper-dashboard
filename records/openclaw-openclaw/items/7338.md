## Summary

Keep open. Current main and release v2026.6.11 still lack general, opt-in agent-origin attestation for external HTTP requests, and the unresolved identity, privacy, signing, and outbound-scope choices require maintainer security direction.

## What This Changes

Requests opt-in, domain-scoped headers or cryptographic attestations that let external services identify outbound requests as originating from an OpenClaw agent.

## Best Possible Solution

Define an audience-bound service or operator identity contract first, then add the narrowest plugin-owned request seam needed for approved domains, with anti-replay, key lifecycle, redirect, privacy, and non-leakage proof.

- **Service-specific authentication only:** Keep authentication in each plugin or service through API keys or OAuth without making a general OpenClaw identity claim.
