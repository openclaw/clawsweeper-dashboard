## Summary

Keep open: current main still lacks a general opt-in, domain-scoped agent attestation surface for outbound HTTP requests, and the requested identity/signing/privacy behavior remains a product and security design decision rather than a conservative cleanup close.

## What This Changes

The issue requests opt-in agent attestation headers for outgoing HTTP requests, including domain allowlists, static or signed identity material, and skill/config metadata for when attestation is required.

## Best Possible Solution

Define the trust model and exact outbound paths first, then implement an opt-in, domain-scoped attestation contract with privacy-preserving defaults, schema/docs coverage, and tests for allowlisted injection plus non-leakage.

## Reproduction Assessment

Not applicable as a bug reproduction; source and docs inspection show current main lacks the requested general outbound attestation surface.

## Solution Assessment

No current implementation is ready to close this; provider attribution and provider-header proposals are adjacent but do not solve arbitrary external request attestation or its security model.
