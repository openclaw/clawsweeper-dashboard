## Summary

Keep open. Current main and v2026.6.11 still lack opt-in, domain-scoped agent-origin attestation for arbitrary external HTTP requests; existing provider attribution and provider request headers are narrower model-provider transport features, while this remains a security/product design tracker.

## What This Changes

The issue requests optional OpenClaw agent attestation headers or signed claims on external HTTP requests, with user config, domain allowlists, and possible skill metadata support.

## Best Possible Solution

Keep this open for explicit product/security design, then implement a privacy-preserving opt-in attestation contract with clear outbound scope, allowlisted injection, non-leakage tests, docs, and any needed plugin/config API changes.

## Reproduction Assessment

Not applicable: this is a feature request rather than a broken existing behavior report. Source and release inspection confirm the requested attestation surface is absent in current main and v2026.6.11.

## Solution Assessment

Unclear: static headers or a signed JWT may be part of the solution, but the trust model, privacy defaults, and exact outbound paths are not settled. Existing provider request headers are too narrow to solve arbitrary external agent-origin attestation.
