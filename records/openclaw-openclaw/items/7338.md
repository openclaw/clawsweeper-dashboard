## Summary

Keep open. Current main and v2026.6.11 still lack opt-in, domain-scoped agent-origin attestation for arbitrary external HTTP requests; related provider-header and trust-hook work is narrower and does not close the security/product design question.

## What This Changes

The issue requests opt-in OpenClaw agent-origin attestation headers, preferably signed and domain-scoped, for external HTTP requests made by agents or skills.

## Best Possible Solution

Keep this as the canonical product/security design tracker until maintainers define the trust model and outbound-request boundary, then implement a privacy-preserving opt-in attestation contract with allowlisted injection, non-leakage tests, docs, and any needed plugin/config API changes.
