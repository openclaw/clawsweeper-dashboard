## Summary

Keep open. Current main and v2026.6.11 still do not implement opt-in, domain-scoped agent-origin attestation for arbitrary external HTTP requests; existing provider attribution, provider request headers, workspace/policy attestations, and sessions_send identity metadata are adjacent but do not solve the requested external-service verification problem.

## What This Changes

The issue requests opt-in, domain-scoped OpenClaw agent attestation headers or signed tokens for outbound external HTTP requests.

## Best Possible Solution

Keep this issue open for explicit product/security design, then implement a privacy-preserving opt-in attestation contract with clear outbound scope, domain allowlisting, non-leakage tests, docs, and any needed plugin/config API changes.

## Reproduction Assessment

Not applicable: this is a feature request, not a broken existing behavior report. Current-main and latest-release source inspection show the requested outbound attestation surface is absent rather than failing.

## Solution Assessment

Unclear: direct static headers or signed JWTs may be viable, but they are not proven to be the best solution until maintainers settle the trust model, privacy defaults, signing authority, and exact outbound paths.
