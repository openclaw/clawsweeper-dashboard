## Summary

Keep open. Current main and v2026.6.11 still lack general opt-in agent-origin attestation for arbitrary external HTTP requests; the existing provider attribution and provider request-header work is narrower, and this remains a security/product design item.

## What This Changes

The issue requests opt-in, domain-scoped static or cryptographic attestation headers for external HTTP requests made by OpenClaw agents and skills.

## Best Possible Solution

Define the trust model and outbound scope first, then implement a privacy-preserving opt-in attestation contract with domain allowlists, non-leakage tests, docs, and any needed plugin/config API changes.

## Reproduction Assessment

Not applicable: this is a feature request rather than a broken existing behavior report. Source and release inspection show the requested attestation surface is absent in current main and v2026.6.11.

## Solution Assessment

Unclear: adding headers directly is not yet proven to be the best solution because the signing, verifier, privacy, and outbound-scope contracts are unsettled. The safer path is maintainer design approval before implementation.
