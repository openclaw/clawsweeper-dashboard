## Summary

Keep open: current main and the latest release still lack a general opt-in, domain-scoped agent attestation surface for arbitrary outbound HTTP requests. Existing provider attribution, plugin hooks, and related trust threads are adjacent, but they do not settle the requested identity, signing, privacy, config, or outbound-request semantics.

## What This Changes

Requests optional static or signed OpenClaw agent attestation headers for external HTTP requests, with domain allowlisting and possible skill metadata configuration.

## Best Possible Solution

Keep this as a maintainer product/security design tracker until OpenClaw has one opt-in, domain-scoped attestation contract with privacy-preserving defaults, clear static-versus-signed semantics, schema/docs, and tests for allowlisted injection plus non-leakage.

Not applicable: this is a feature request rather than a bug report. Source inspection on current main and v2026.6.11 shows the requested attestation surface is absent.

## Solution Assessment

Unclear until maintainers choose the trust model. A signed, opt-in, domain-scoped design is safer than global static headers, while existing provider attribution and plugin hooks solve only adjacent narrower cases.
