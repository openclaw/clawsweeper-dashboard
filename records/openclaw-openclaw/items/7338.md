## Summary

Keep open. Current main and v2026.6.11 still do not provide opt-in, domain-scoped agent-origin attestation for arbitrary external HTTP requests; existing provider attribution and provider request headers are narrower model-provider transport features, while the issue remains a product/security design tracker.

## What This Changes

The issue requests optional static or cryptographic OpenClaw agent attestation headers for outbound HTTP requests, with user/skill configuration and domain allowlisting.

## Best Possible Solution

Keep this open for explicit product/security design, then implement a privacy-preserving opt-in attestation contract with clear outbound scope, allowlisted injection, non-leakage tests, docs, and any needed plugin/config API changes.

## Reproduction Assessment

Not applicable: this is a feature request rather than a broken existing behavior report. Source and release inspection show the requested attestation surface is absent in current main and v2026.6.11.

## Solution Assessment

Unclear: adding headers directly is not yet proven to be the best solution because the trust model, signing authority, privacy defaults, and exact outbound paths are unsettled. The safer path is design approval first, then a narrow opt-in implementation with allowlist and non-leakage proof.
