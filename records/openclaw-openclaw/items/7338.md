## Summary

Keep open. Current main and v2026.6.11 still lack opt-in, domain-scoped agent attestation for arbitrary outbound HTTP requests; existing provider attribution, plugin hooks, and related trust/manifest work are narrower surfaces, so this remains a product/security design item.

## What This Changes

Request to add opt-in OpenClaw agent attestation headers or signed tokens for outbound HTTP requests, with config and optional skill metadata controls.

## Best Possible Solution

Define the maintainer-approved trust model and outbound scope first, then implement a privacy-preserving opt-in attestation contract with domain allowlists, static-versus-signed semantics, docs, schema coverage, and non-leakage tests.

Options:

- **Design Core Attestation Contract (recommended):** Define opt-in domain-scoped static and signed semantics, key and audience handling, docs, schema coverage, and non-leakage tests before implementation.
- **Keep Attribution Provider-Scoped:** Treat current provider attribution and provider request-header controls as the supported path and decline general arbitrary-HTTP agent attestation for now.
- **Route Through Plugins Or Service Handshakes:** Require external services to use plugin, skill, MCP, or service-level handshakes unless maintainers approve a missing generic core API.
