## Summary

Keep open: current main and the latest release still lack a general opt-in, domain-scoped OpenClaw agent attestation surface for arbitrary outbound HTTP requests. Existing provider attribution, skill metadata, and plugin hook/trust work are adjacent but do not solve signed or static agent-origin attestation for external services, so this remains a product/security design item.

## What This Changes

The issue requests optional static or cryptographic agent attestation headers, plus per-skill or domain-scoped configuration, for OpenClaw-originated external HTTP requests.

## Best Possible Solution

Define the trust model and exact outbound paths first, then implement an opt-in, domain-scoped attestation contract with privacy-preserving defaults, schema/docs, and tests for allowlisted injection and non-leakage.

## Reproduction Assessment

Not applicable: this is a feature request rather than a bug report. Source and release inspection show current main and v2026.6.11 lack the requested agent-attestation surface.

## Solution Assessment

Unclear until maintainers choose the trust model. A signed, opt-in, domain-scoped design is directionally safer than static global headers, but existing provider attribution and plugin trust hooks are not complete solutions for arbitrary external requests.
