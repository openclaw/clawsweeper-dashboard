## Summary

Keep open. Current main and the latest release still lack opt-in, domain-scoped agent attestation for arbitrary outbound HTTP requests; existing provider attribution and provider request headers are narrower transport features, and this remains a security/product design item.

## What This Changes

Request opt-in static or cryptographic OpenClaw agent attestation headers for outbound HTTP requests, with domain allowlists and optional skill metadata.

## Best Possible Solution

Define the trust model and outbound scope first, then implement a privacy-preserving opt-in attestation contract with domain allowlists, docs, schema/API coverage, and tests proving allowlisted injection plus non-leakage.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature/security design request rather than broken existing behavior. Source and release-tag inspection show the requested attestation surface is absent in current main and v2026.6.11.

## Solution Assessment

Unclear: static headers and signed JWTs are plausible options, but maintainers still need to settle trust, privacy, signing, audience, key rotation, and outbound-scope semantics before implementation.
