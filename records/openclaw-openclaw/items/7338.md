## Summary

Keep open: current main and v2026.6.11 still lack opt-in, domain-scoped agent-origin attestation for arbitrary outbound HTTP requests. The related sender-header PR was closed unmerged, and existing provider attribution, policy attestations, and plugin trust hooks do not solve the requested signed or static external-request attestation surface.

## What This Changes

The issue requests optional static or signed OpenClaw agent attestation headers for outbound HTTP requests, optionally scoped by domain and skill metadata.

## Best Possible Solution

Define the trust model and exact outbound paths first, then implement an opt-in, domain-scoped attestation contract with privacy-preserving defaults, schema/docs, and tests for allowlisted injection plus non-leakage.

## Reproduction Assessment

Not applicable: this is a feature request rather than a bug report. Source and release inspection show the requested outbound attestation surface is absent in current main and v2026.6.11.

## Solution Assessment

Unclear until maintainers choose the trust model. A signed, opt-in, domain-scoped design is directionally safer than static global headers, but existing provider attribution and policy attestations are not a complete solution for arbitrary external requests.
