## Summary

Keep open. Current main and the latest checked release still lack a general, opt-in, domain-scoped agent-origin attestation mechanism for outbound HTTP requests; the existing provider-attribution, provider-header, web_fetch, and skill metadata surfaces are narrower and do not settle the requested trust model.

## What This Changes

The issue requests signed or otherwise verifiable agent attestation headers for outbound requests so receiving services can make identity, policy, and audit decisions.

## Best Possible Solution

Define the trust model and outbound scope first, then implement opt-in domain-scoped attestation with privacy defaults, schema/API coverage, docs, and non-leakage tests.
