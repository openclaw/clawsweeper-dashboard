## Summary

Keep open. Current main and the latest release still lack a general opt-in, domain-scoped agent-origin attestation surface for outbound HTTP requests; existing provider attribution and related sender-header proposals are narrower, so this remains a product/security design item.

## What This Changes

The issue requests opt-in OpenClaw agent attestation headers or signed tokens for outbound HTTP requests so external services can distinguish OpenClaw agents from humans or other clients.

## Best Possible Solution

Define a maintainer-approved trust model and outbound scope first, then implement a privacy-preserving opt-in attestation contract with domain allowlists, schema/API coverage, docs, and non-leakage tests.
