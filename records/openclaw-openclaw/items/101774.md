## Summary

Keep open: the PR addresses a real unbounded marketplace manifest read on current main, but the patch currently converts every `readRegularFile` failure into `Marketplace manifest too large`, so small symlinks, non-files, missing/raced paths, or permission failures get a false user-visible diagnostic. The external proof is also only focused test output, which is supplemental rather than real behavior proof.

## What This Changes

This PR adds a 16 MiB cap to plugin marketplace manifest reads by switching `loadMarketplaceFromManifestFile` to `readRegularFile` and adds an oversized-manifest regression test.

## Best Possible Solution

Keep the bounded read, classify oversize separately from other fs-safe read failures, add regression coverage for both paths, and require a redacted CLI/live transcript before merge.

No. The helper choice is the right layer, but the catch-all error handling is too broad; the best fix keeps the cap while preserving distinct structured errors for non-size filesystem failures.
