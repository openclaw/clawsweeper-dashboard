- `impact:auth-provider`: The affected state is provider auth-profile cooldown routing and model choice for OpenAI/Codex OAuth profiles.

## Summary

Keep open: current main and v2026.6.11 still apply WHAM `subscription_limit` blocks profile-wide, and the open linked PR is the active fix candidate. This issue should close only after that PR or an equivalent replacement lands.

## What This Changes

The issue reports that WHAM `subscription_limit` blocks are stored and enforced profile-wide instead of being scoped to the model that exhausted quota.

## Best Possible Solution

Review and land or replace https://github.com/openclaw/openclaw/pull/99810; once an equivalent fix is merged, close this issue against that commit.

## Reproduction Assessment

Yes. Source inspection gives a deterministic repro by triggering or seeding a WHAM `subscription_limit` block and checking `isProfileInCooldown` for a different `forModel`; current main discards or ignores `blockedModel`, so the sibling model remains blocked.

## Solution Assessment

Yes. Reusing the existing `blockedModel` field and mirroring the established `cooldownModel` gate is the narrow owner-boundary fix; adding config or provider-specific fallback policy would be broader than needed.
