Keep open: current main and v2026.6.11 still apply WHAM `subscription_limit` blocks profile-wide, and the open linked PR is the active fix candidate. This issue should close only after that PR or an equivalent replacement lands.

## What This Changes

The issue requests model-scoped handling for OpenAI/Codex `subscription_limit` auth-profile blocks so one quota-limited model does not suppress sibling models sharing the same OAuth profile.

## Best Possible Solution

Review and land or replace the active linked PR, then close this issue against the merge commit that fixes auth-profile block scoping.

## Reproduction Assessment

Yes. Source inspection gives a deterministic current-main reproduction by seeding or triggering a WHAM `subscription_limit` `blockedUntil` on one model and checking `isProfileInCooldown` for a different `forModel`; current main discards or ignores `blockedModel`, so the sibling model remains blocked.

## Solution Assessment

Yes. Reusing the existing `blockedModel` field and mirroring the established `cooldownModel` gate is the narrow owner-boundary fix; a richer per-model block map would be a larger stored data-model change and is not required before keeping this issue open for the linked PR.
