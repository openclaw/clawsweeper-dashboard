## Summary

Keep open: current main still has the reported failure path, and multiple open PRs now reference this issue as candidate fixes. The issue should close only after one narrow fix lands and proves `doctor --fix` treats shell-completion profile write failures as a warning.

## What This Changes

`openclaw doctor --fix` should not exit 1 when optional shell-completion installation cannot write to a read-only shell rc file.

## Best Possible Solution

Land one narrow PR that catches profile write failures at the doctor shell-completion boundary, emits a clear Shell completion warning, preserves fatal behavior for explicit `openclaw completion --install`, and adds regression coverage plus scratch-HOME proof.

## Reproduction Assessment

Yes. Reporter logs show the EACCES exit, and current source shows `--fix` auto-approves the completion install, calls `installCompletion`, and lets profile write errors escape the doctor flow.

## Solution Assessment

Yes. The narrow maintainable fix is to catch permission/profile write failures in `doctorShellCompletion` because shell completion is optional there, while keeping the explicit completion installer strict.
