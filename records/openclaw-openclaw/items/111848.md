## Summary

Keep open: both current `main` and the latest release pin the Claude ACP adapter version whose own `query()` environment omits the settings-file environment that its settings contract says should be visible to queries. This is an extension-dependency bug, not a core gateway fix, and it needs an explicit owner decision on upstream remediation versus a temporary plugin-local patch. ([raw.githubusercontent.com](https://raw.githubusercontent.com/openclaw/openclaw/v2026.7.1/extensions/acpx/package.json))

## What This Changes

The issue requests that the Claude ACP adapter pass `settingsManager.getSettings().env` into the spawned query environment so settings-file compaction variables reach custom-model sessions without relying on inherited process state.

## Best Possible Solution

Have the upstream Claude ACP adapter merge and release the environment-propagation correction, then update ACPX to that release with a focused regression test; carry a narrowly scoped ACPX-local dependency patch only if maintainers need the fix before upstream publishes it.
