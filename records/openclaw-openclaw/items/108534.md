## Label Justifications

- `impact:session-state`: The persisted conversation loses the attachment-to-message association needed to continue processing the same document.

## Summary

The report remains necessary: current Feishu ingestion carries downloaded-media fields into the active turn, but the persisted agent-facing body does not retain a durable attachment identity, so truncated documents can become nondeterministic on follow-up turns. The broader shared-directory issue overlaps but does not replace this narrower session-provenance bug.

## What This Changes

Persist a trusted, durable Feishu attachment reference in agent/session context so later turns can reopen a downloaded document after inline content is truncated.

## Best Possible Solution

Store an opaque, session-scoped attachment record in the canonical SQLite state, bind it to the inbound message and routed agent, render a trusted managed reference into Feishu context, and add truncation plus follow-up-turn tests without requiring directory scans or raw-path guessing.

## Reproduction Assessment

No live current-main run was performed, but yes at source level: Feishu passes media paths as transient context fields while its persisted agent-facing body omits attachment provenance, matching the reported follow-up failure.

## Solution Assessment

No—the local workaround of embedding a raw path is not the best permanent fix. A managed, agent-bound attachment reference with explicit retention and authorization is safer and avoids creating a second source of truth.
