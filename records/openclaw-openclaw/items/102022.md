## Summary

Keep open: the PR targets the right Lobster parser surface, but it is incomplete because ordinary `run` can still enter managed TaskFlow parsing when `flowStateJson` is schema-injected; real behavior proof is also mock-only.

## What This Changes

The PR changes the Lobster plugin tool parser to stop treating schema-default `flowExpectedRevision` as a managed TaskFlow signal and adds two regression tests.

## Best Possible Solution

Normalize schema-injected blank/default managed-flow fields before mode selection, select managed run only from intentional controller/goal fields and managed resume only from `flowId`, then prove both ordinary run and resume through the real tool.
