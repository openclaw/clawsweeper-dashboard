## Label Justifications

- `P1`: The issue describes a broken yielded-parent workflow where real users can be stuck until a refresh, external poke, or restart after child completion.
- `impact:session-state`: The parent session can remain wedged or drift from completed child task state after `sessions_yield`.
- `impact:message-loss`: Completion events or final parent replies can fail to surface to Matrix, Telegram, browser, or other channel users even after child work completes.

## Summary

Keep open: current main has useful partial delivery paths, but it still does not provide one canonical ACP/native yielded-parent resume contract, and two open PRs cover only narrower slices of this bug.

## What This Changes

Issue requests reliable ACP/native yielded parent wake-up when child sessions complete, without requiring manual refresh, heartbeat-only wakeups, or external user pokes.

## Best Possible Solution

Keep this issue as the canonical yielded-parent wake contract until maintainers land a cross-runtime continuation path that covers ACP completion, native subagent completion, blocked/expired delivery, route-resume behavior, and heartbeat-disabled deployments.

## Reproduction Assessment

Yes, at source level: docs define `sessions_yield` as push-based completion waiting, while current ACP and task fallback paths still queue system events and rely on heartbeat-style wake delivery. I did not run a live Matrix/Telegram/browser reproduction in this read-only pass.

## Solution Assessment

No, current main is not the complete solution: heartbeat relay, task terminal fallback, and recent announce-delivery fixes are useful partial paths, but they do not form one owner-approved ACP/native yielded-parent resume contract.
