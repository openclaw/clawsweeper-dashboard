## Label Justifications

- `P1`: The issue describes a broken yielded-parent workflow where real users can stay stuck after child completion until a refresh, external poke, or timeout.
- `impact:session-state`: The parent session can remain wedged or drift from completed child task state after `sessions_yield`.

## Summary

Keep open: current main has useful partial wake paths, but the documented yielded-parent completion contract is still not fully covered across ACP, native subagents, blocked/give-up outcomes, and heartbeat-disabled delivery. The open linked PRs are narrow slices and should be reviewed without closing this canonical issue yet.

## What This Changes

The issue reports that yielded parent sessions do not reliably resume after ACP or subagent child completion, leaving users stuck until a refresh or later inbound activity.

## Best Possible Solution

Keep this issue as the canonical yielded-parent wake thread until maintainers land one cross-runtime continuation contract that covers ACP task completion, native subagent completion, blocked/give-up outcomes, and heartbeat-disabled deployments.

## Reproduction Assessment

Yes, at source level: docs define `sessions_yield` as the push-based completion waiting primitive, while current main still has heartbeat-gated event delivery and native subagent terminal suppression. I did not run a fresh live Matrix, Telegram, or browser reproduction in this read-only review.

## Solution Assessment

No, current main is not the complete solution: the heartbeat relay, descendant-settle wake, and recent announce-delivery fixes are useful partial paths but do not form one owner-approved ACP/native yielded-parent resume contract. The best fix should land through the linked narrow PRs only if they fit the broader contract maintainers choose.
