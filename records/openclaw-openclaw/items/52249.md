## Summary

Keep open: current main has partial repairs, but it has not implemented the broad yielded-parent wake contract. Source still shows the ACP parent relay depending on the heartbeat wake handler, and the live related PRs are narrower candidates rather than a merged fix for the whole ACP/native parent-resume problem.

## What This Changes

The issue asks OpenClaw to resume yielded parent sessions automatically when ACP or native child work completes, instead of leaving the parent stuck until refresh, timeout, or another inbound message.

## Best Possible Solution

Keep this as the canonical broad yielded-parent wake issue until maintainers define the cross-runtime contract; the end state should be heartbeat-independent parent continuation with regression coverage for ACP `streamTo: "parent"`, native `sessions_spawn` plus `sessions_yield`, blocked/give-up delivery, and real channel routing.
