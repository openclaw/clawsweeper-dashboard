## Label Justifications

- `P1`: The issue describes a broken yielded parent workflow affecting real agent/channel users who must refresh or manually poke the session after child completion.
- `impact:session-state`: The parent session can remain yielded or wedged after the child has completed, leaving runtime state out of sync with the visible workflow.
- `impact:message-loss`: Child completion events may be delayed, queued, or not surfaced to the user-facing channel until later inbound activity.

## Summary

Keep open: current main still has heartbeat-dependent and partial yielded-parent wake paths, while the documented `sessions_yield` behavior expects child completions to arrive as the next model-visible message without polling or a manual poke. The open candidate PRs cover narrower ACP and blocked-subagent slices, so this issue remains useful as the canonical maintainer decision point.

## What This Changes

The issue asks for yielded parent sessions to resume automatically after ACP or native child completion instead of remaining stuck until refresh or another inbound message.

## Best Possible Solution

Define and land a maintainer-approved parent continuation/yield-wait contract that covers ACP and native child completions without depending on optional heartbeat polling, with regression coverage for heartbeat-off, active requester, blocked delivery, and normal successful completion paths.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction model: current completion paths queue session events and request heartbeat, while `heartbeat-wake` returns when no handler is registered. Multiple issue comments also report current-release ACP and native subagent cases where completion does not promptly wake the yielded parent.

## Solution Assessment

Unclear as a single patch until maintainers choose the owner boundary. The best fix should be a unified yield/parent-continuation wake path rather than another one-sided ACP-only or blocked-only workaround.
