## Label Justifications

- `P1`: Broken yielded-parent continuation can leave real user ACP or native subagent workflows stuck until refresh, manual poke, or timeout.
- `impact:session-state`: The parent session can remain yielded or wedged after a child reaches terminal state, drifting from the actual child run state.
- `impact:message-loss`: Child completion events or replies can fail to surface back to the parent-visible channel, matching the reported lost-completion behavior.

## Summary

Keep open: current main still lacks a single yielded-parent wake/resume contract for this failure class. ACP parent streaming remains coupled to heartbeat wake behavior, native subagent blocked/give-up delivery is still only covered by open candidate work, and no merged main implementation covers the full ACP/native parent-continuation problem.

## What This Changes

The issue requests reliable automatic resumption of yielded parent sessions after ACP or native child completion, without refresh, manual poke, or heartbeat-only coupling.

## Best Possible Solution

Land an owner-approved cross-runtime continuation contract that covers ACP task completion, native subagent completion, retry-limit and expiry give-up, heartbeat-disabled deployments, and duplicate or misrouted delivery prevention.

## Reproduction Assessment

Yes at source level: docs promise push-based sessions_yield completion, but current ACP relay still depends on heartbeat wake and native blocked/give-up delivery remains open in candidate work; I did not run the live Matrix or Telegram scenario.

## Solution Assessment

Current main is not the full solution; existing task and announce fixes are useful slices, but an ACP-only or blocked-delivery-only change would leave sibling native and heartbeat-disabled paths unresolved.
