## Label Justifications

- `P1`: The issue describes a broken yielded-parent workflow where real users can be stuck until a refresh, external poke, or restart after child completion.
- `impact:session-state`: The parent session can remain wedged or drift from completed child task state after `sessions_yield`.
- `impact:message-loss`: Completion events or final parent replies can fail to surface to Matrix, Telegram, browser, or other channel users even after child work completes.

## Summary

Keep open: current main has useful partial wake paths, including a merged descendant-settle fix, but it still does not provide the requested cross-runtime yielded-parent resume contract for ACP and native child completions, especially heartbeat-disabled and blocked-delivery cases.

## What This Changes

The issue requests reliable automatic resumption of yielded parent sessions when ACP or native child completion events arrive.

## Best Possible Solution

Keep this as the canonical yielded-parent wake/resume thread until maintainers land one cross-runtime continuation contract covering ACP task completion, native subagent completion, blocked/give-up outcomes, and heartbeat-disabled deployments.

## Reproduction Assessment

Yes at source level: docs define `sessions_yield` as the push-based completion waiting primitive, while current main still has heartbeat-gated ACP/system-event paths, suppressed native subagent terminal fallback, and no explicit yield-wait resume primitive. I did not run a live Matrix, Telegram, or browser reproduction in this read-only pass.

## Solution Assessment

No, current main is not the complete solution: the merged descendant-settle path and open ACP/blocked-delivery PRs are useful partial repairs, but they do not yet form one owner-approved ACP/native yielded-parent resume contract.
