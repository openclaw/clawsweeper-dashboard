## Label Justifications

- `P1`: The issue describes a broken yielded-parent workflow where real users can be stuck until a refresh, external poke, or restart after child completion.
- `impact:session-state`: The parent session can remain wedged or drift from completed child task state after `sessions_yield`.
- `impact:message-loss`: Completion events or final parent replies can fail to surface to Matrix, Telegram, browser, or other channel users even after child work completes.

## Summary

Keep open: current main still has only partial yielded-parent wake paths, while the documented `sessions_yield` contract expects child completions to arrive without polling or a manual poke. The live candidate PRs cover narrower ACP and blocked-subagent slices, so they should be reviewed without closing this canonical issue yet.

## What This Changes

The issue requests fixing yielded parent sessions so ACP and native child completion events wake and resume the parent without a manual refresh or external user message.

## Best Possible Solution

Keep this issue as the canonical thread until maintainers land one cross-runtime yielded-parent continuation contract that covers ACP task completion, native subagent completion, blocked/give-up outcomes, and heartbeat-disabled deployments.

## Reproduction Assessment

Yes, at source level: docs define `sessions_yield` as the push-based completion waiting primitive, while current main still has heartbeat-gated ACP/system-event paths, suppresses non-cancelled native subagent terminal delivery, and lacks the requested yield-wait resume primitive. I did not run a live Matrix/Telegram/browser reproduction in this read-only pass.

## Solution Assessment

No, current main is not the complete solution: the heartbeat relay, task terminal event queue, and recent announce-delivery fixes are useful partial paths but do not form one owner-approved ACP/native yielded-parent resume contract. The best fix should land through the linked narrow PRs only if they fit the broader contract maintainers choose.
