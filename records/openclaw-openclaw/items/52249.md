## Summary

Keep open: current main has replaced the old direct-resume relay with system-event and active-queue paths, but the broader yielded-parent wake contract is still not fully settled and two open PRs cover important remaining ACP/subagent slices.

## What This Changes

The issue asks OpenClaw to make yielded parent sessions wake and continue automatically when ACP or native child/subagent completion is delivered, without requiring a UI refresh or later inbound poke.

## Best Possible Solution

Choose one canonical yield/wake contract that covers ACP terminal task completion and native subagent completion or blocked delivery without depending solely on optional heartbeat, then land the relevant linked PRs or replace them with one focused maintainer-approved fix plus regression coverage.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Source inspection and issue comments give a credible reproduction path: yielded parent completion relies on system events plus heartbeat/queue wake, and disabled or missing wake paths can leave events unprocessed; I did not run a live current-main reproduction in this read-only review.

## Solution Assessment

Is this the best way to solve the issue? Not yet clear: current main contains partial fixes, while the best path should be a maintainer-approved owner-boundary wake contract at task completion or announce delivery rather than another heartbeat-only workaround.
