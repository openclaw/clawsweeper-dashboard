## Label Justifications

- `P1`: Active release validation is failing for frozen candidates, and the proposed repair leaves one documented release workflow broken.

## Summary

The release-validation design is mostly sound, but the documented direct release-branch dispatch path still does not authorize the compatibility gate, so frozen candidates can continue failing current-only checks.

## What This Changes

This PR updates release workflows and helper scripts to authenticate frozen release branch heads, capability-gate legacy checks, attribute GitHub-generated release merges to their merger, and retry prerelease extension tests once.

## Best Possible Solution

Use one normalized, exact-SHA-verified release-context value derived from either the direct canonical ref or the helper’s explicit context, and pass it to child CI while keeping tags, arbitrary SHAs, PRs, and main fail-closed.

Yes from source: dispatch Full Release Validation with a canonical release branch in the existing `ref` input and leave `target_context_ref` empty; the child CI receives only the SHA and cannot enable release-candidate compatibility.

## Solution Assessment

No, not yet. Exact-head authentication is the right boundary, but the implementation must normalize both documented direct branch dispatches and SHA-pinned helper dispatches into that boundary.
