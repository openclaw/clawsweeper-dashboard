## Label Justifications

- `P1`: The missing Control UI fallback can break an ordinary remote session-creation workflow during a client/server version mismatch.
- `merge-risk: 🚨 compatibility`: Older remote Gateways reject the new closed-schema field, while the Control UI has no fallback request path.
- `merge-risk: 🚨 session-state`: The new parameter controls whether a parent receives a terminal lifecycle event and therefore affects persisted parent-owned session state.

## Summary

The lifecycle split is a focused fix for a real session-state bug and includes strong live gateway evidence, but the Control UI now always sends the new closed-schema field without the precise older-gateway retry implemented for TUI and Android. That can make a newer Control UI unable to create a child session against an older remote Gateway, so this PR needs that compatibility path before merge.

## What This Changes

The PR adds an optional `succeedsParent` field to `sessions.create`, uses `false` for Control UI and Android detached children, uses `true` for TUI `/new`, and documents, types, and tests the lifecycle distinction.

## Best Possible Solution

Keep the explicit lifecycle disposition, add the same narrow closed-schema fallback to the Control UI request path with focused coverage, then land only after confirming the public Gateway contract and upgrade behavior.
