## Summary

Keep this PR open, but it is not merge-ready: the explicit parallel-child disposition still loses to the earlier main-session reset-in-place path, so selected main-session Control UI/Android New Chat requests can retain the parent-ending behavior this PR intends to prevent. Current main’s Codex consumer guard mitigates the original binding failure, but the proposed producer-level lifecycle contract remains meaningful and needs the protected maintainer review after that defect is fixed.

## What This Changes

The PR adds an optional `succeedsParent` lifecycle disposition to `sessions.create`, using it for parallel Control UI/Android children and successor TUI `/new` sessions while updating protocol models, SDK types, tests, and docs.

## Best Possible Solution

Make explicit `succeedsParent: false` win before any keyless main-session reset-in-place decision, add a regression test for the selected-global/main DM scope used by Control UI and Android, then have the lifecycle owner confirm the public successor-versus-parallel API contract.
