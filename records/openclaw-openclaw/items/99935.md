Full review comments:

- **[P1] Route explicit setup flags through a supported path:** `src/commands/onboard.ts:32-39`
  - body: This predicate only forces the classic wizard for `--classic`, flow, remote mode, import, or auth choice, but `register.onboard.ts` still passes gateway port/bind/auth/token, daemon, skip, node-manager, and provider option values. Because `runConversationalOnboarding` forwards only `workspace`, an interactive command such as `openclaw onboard --gateway-port 19000` or `--no-install-daemon` now takes the conversational path and applies quickstart defaults instead of the requested public setup options.
  - confidence: 0.91
- **[P2] Require full setup before calling onboarding ready:** `src/crestodian/onboarding-welcome.ts:18-19`
  - body: A config that only has a valid default model satisfies this condition, so the first-run welcome skips the seeded `setup` proposal and says the agent is ready even though workspace, gateway auth/defaults, and the setup acknowledgement may still be missing. The old wizard completion gate was tied to setup completion, so this needs a stronger configured signal or a continued setup proposal.
  - confidence: 0.85
- **[P2] Run channel post-write hooks from chat setup:** `src/crestodian/chat-engine.ts:94-103`
  - body: `setupChannels` only collects plugin `afterConfigWritten` work when callers pass `onPostWriteHook` and later drain it after the config commit; `channels add` does this, and Matrix encrypted accounts rely on that hook for recovery/bootstrap setup. This new chat-hosted path calls `setupChannels` and immediately writes the config without collecting or running those hooks, so the chat can report a channel configured while required post-write setup never ran.
  - confidence: 0.9
- **[P2] Respect paused local gateways before starting chat:** `apps/macos/Sources/OpenClaw/OnboardingView+CrestodianSetup.swift:35`
  - body: The removed wizard path checked `AppStateStore.shared.isPaused` before starting local setup, but this new guard only checks that the CLI is installed. Since `GatewayConnection.request` auto-recovers local failures by calling `GatewayProcessManager.shared.setActive(true)`, opening the Crestodian page while OpenClaw is paused can restart the local gateway instead of respecting the paused setup state.
  - confidence: 0.86
- **[P2] Keep the app timeout above the server turn:** `apps/macos/Sources/OpenClaw/OnboardingCrestodianChat.swift:72-75`
  - body: The gateway engine allows a Crestodian agent-loop turn to wait up to 180s, and the embedded run itself may use 120s. The macOS client request times out at exactly 120,000ms, so a cold local model can make the app show an error while the server-side setup turn continues; raise the client timeout above the server deadline or lower the server deadline for this RPC.
  - confidence: 0.88
