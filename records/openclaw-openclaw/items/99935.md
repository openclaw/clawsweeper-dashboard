- **[P1] Reject npm-prefixed local plugin targets:** `src/crestodian/operations.ts:371-373`
  - body: `validateCrestodianPluginInstallSpec` only rejects `file:`, URLs, and local paths when they start the whole string, so an approved `plugin-install` for `npm:file:../pkg` or `npm:https://example/pkg.tgz` still reaches `runPluginInstallCommand`, which strips `npm:` before npm resolution. That bypasses the PR's package-only Crestodian restriction for arbitrary package code; validate the inner `npm:` target before executing.
  - confidence: 0.96
- **[P1] Preserve the existing workspace default:** `src/crestodian/onboarding-welcome.ts:53-55`
  - body: For a valid config that already has `agents.defaults.workspace` but still needs setup, this welcome seeds `DEFAULT_WORKSPACE` instead of the configured workspace, and accepting setup writes that value back through `applyLocalSetupWorkspaceConfig`. That regresses the classic quickstart behavior and can silently move an existing user to the default workspace.
  - confidence: 0.94
- **[P2] Run channel post-write hooks from chat setup:** `src/crestodian/chat-engine.ts:94-103`
  - body: The chat-hosted `connect <channel>` path calls `setupChannels` and writes config without providing `onPostWriteHook` or draining `runCollectedChannelOnboardingPostWriteHooks`. Channels such as Matrix rely on `afterConfigWritten` for bootstrap, so the chat can report setup complete while required post-write work never ran.
  - confidence: 0.93
- **[P2] Respect paused local mode before starting chat:** `apps/macos/Sources/OpenClaw/OnboardingView+CrestodianSetup.swift:35-51`
  - body: This guard starts the `crestodian.chat` RPC whenever local onboarding reaches the page after CLI install. In local mode the shared `GatewayConnection.request` path auto-recovers failures by calling `GatewayProcessManager.shared.setActive(true)`, so simply opening the page can reactivate a gateway the user intentionally paused.
  - confidence: 0.9
- **[P2] Keep the app timeout above server turns:** `apps/macos/Sources/OpenClaw/OnboardingCrestodianChat.swift:72-75`
  - body: The app times out `crestodian.chat` at exactly 120 seconds, but the server chat engine can wait 180 seconds for an agent-loop turn and the embedded run itself is allowed 120 seconds. A slow local turn can therefore show an app error while the server-side setup turn continues.
  - confidence: 0.88

  - body: Late finding: this code was unchanged since the previous reviewed head, but the reset/session contract makes the issue concrete. Each new `CrestodianAgentSession` gets a unique session id while all of them reuse `state/crestodian/sessions/agent.jsonl`, so a new session or `reset: true` can still load prior assistant history into the embedded loop.
  - late: true
