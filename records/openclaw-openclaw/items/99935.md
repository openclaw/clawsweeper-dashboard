Full review comments:

- **[P1] Route explicit onboard flags through a supported path:** `src/commands/onboard.ts:32-39`
  - body: Interactive runs such as `openclaw onboard --gateway-port 19000` no longer force the classic wizard and `runConversationalOnboarding` only forwards `workspace`, so the Crestodian setup later applies quickstart defaults with `opts: {}`. That silently drops existing public setup flags for gateway auth, port, daemon, bootstrap, and channel behavior instead of preserving the documented contract.
  - confidence: 0.93
- **[P2] Require full setup before declaring onboarding ready:** `src/crestodian/onboarding-welcome.ts:17-19`
  - body: This check treats any valid config with a default model as fully configured, so a user with a minimal model-only config receives the ready welcome instead of the first-run setup proposal. That skips the workspace bootstrap, gateway defaults, and security acknowledgement that this new onboarding path is supposed to apply.
  - confidence: 0.86
- **[P2] Run channel post-write hooks from chat setup:** `src/crestodian/chat-engine.ts:94-103`
  - body: The chat-hosted channel setup writes the returned config directly without passing or draining `onPostWriteHook`, unlike the existing `channels add` path. Adapters with required post-write work, such as Matrix encrypted-account bootstrap, can be reported as configured while their setup never runs.
  - confidence: 0.91
- **[P2] Respect paused local mode before starting chat:** `apps/macos/Sources/OpenClaw/OnboardingView+CrestodianSetup.swift:30-35`
  - body: This local onboarding guard only checks that the CLI is installed before issuing `crestodian.chat`. Local gateway requests auto-recover by reactivating the GatewayProcessManager, so opening this page can restart a gateway the user intentionally paused instead of preserving the old paused wizard behavior.
  - confidence: 0.88
- **[P2] Keep the app timeout above the server turn:** `apps/macos/Sources/OpenClaw/OnboardingCrestodianChat.swift:72-75`
  - body: The macOS client times out the chat request at 120 seconds, while the gateway chat turn can wait 180 seconds and the embedded model run itself may consume the full 120 seconds. A cold or slow local model can therefore show an app error while the server-side setup turn is still running.
  - confidence: 0.84
