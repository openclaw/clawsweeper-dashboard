## What This Changes

The PR makes ACP prompts rejected after prolonged Gateway outages emit an acceptance-aware interruption into both the live session-update stream and replay ledger before returning the protocol error.

## Best Possible Solution

Keep the single durable interruption, but make accepted post-grace completion observable through the same ACP session—preferably by reconciling it into the ledger—and add a regression covering completion after rejection; if that is intentionally out of scope, direct the notice to the specific Gateway surface where completion can actually be checked.
