## Summary

Keep open: the central fix is well targeted and has credible live proof, but a previously streamed partial response can run directly into the new interruption label because both are consecutive ACP agent-message chunks. This is a narrow pre-merge repair rather than a reason to close the PR.

## What This Changes

The PR records an acceptance-aware ACP interruption message in the live update stream and replay ledger before rejecting a pending prompt after a prolonged Gateway outage.

## Best Possible Solution

Emit the durable interruption through the existing session-update ledger with explicit separation after prior assistant output, while preserving acceptance-aware guidance, prompt retirement before awaits, and one-shot replay semantics.
