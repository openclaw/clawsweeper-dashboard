## Label Justifications

- `P2`: Automatic rollover memory persistence affects real session continuity, but the affected surface is bounded to session rollover, hooks, and bundled session-memory behavior.
- `impact:session-state`: The issue is about previous session entries, transcripts, and memory continuity across daily/idle reset boundaries.
- `impact:data-loss`: The reported behavior can silently discard conversation context before bundled session-memory or an equivalent hook has a chance to persist it.

## Summary

Keep open. Current main and v2026.6.11 still leave automatic daily/idle rollovers on the session lifecycle hook path while bundled session-memory persists only manual command reset events; the secondary hook-config schema mismatch is fixed, and the remaining work is already represented by an open candidate PR that needs maintainer contract/proof review.

## What This Changes

The issue requests a session reset hook or equivalent persistence surface so bundled session-memory and custom hooks can preserve context before daily or idle auto-resets clear a session.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/61675 or a maintainer-approved replacement that persists session-memory on automatic daily/idle rollover, documents the chosen hook contract, and adds focused daily plus idle regression coverage.

## Reproduction Assessment

Yes, at source level: current main can mark daily/idle sessions stale and capture previousSessionEntry, then only emits session_end/session_start while session-memory listens to command:new and command:reset. I did not run a live rollover because this review is read-only.

## Solution Assessment

Unclear pending maintainer product/API choice. A reset persistence hook is a plausible solution, but maintainers still need to choose whether the durable contract is synthetic command actions, automatic before_reset, a typed session reset event, or session_end-based memory behavior.
