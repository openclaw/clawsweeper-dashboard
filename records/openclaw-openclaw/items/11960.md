## Label Justifications

- `P2`: Automatic reset can silently omit durable memory capture, but transcripts are archived and the impact is bounded to session continuity rather than core availability.
- `impact:data-loss`: Important outgoing-session context may never be written to durable memory before automatic rollover and later archive pruning.
- `impact:session-state`: The gap occurs at the daily and idle session lifecycle boundary and affects continuity between the outgoing and replacement session.

## Summary

Current main still rotates stale daily and idle sessions without exposing that boundary to the bundled session-memory internal hook; the secondary hook-config schema problem is fixed, but the primary persistence gap remains and an open implementation still needs proof plus a lifecycle-contract decision.

## What This Changes

Requests a reset lifecycle hook so automatic daily and idle session rollover can persist the outgoing session context, plus support for hook-specific configuration keys.

## Best Possible Solution

Create one lifecycle-owned pre-reset path that receives the outgoing entry and reason, runs typed before_reset plus a clearly named internal session reset event exactly once before or safely across archive rotation, lets session-memory persist marked-untrusted transcript content, and covers daily, idle, explicit-reset, and no-double-fire scenarios.

## Risks / Open Questions

- Reusing command events for automatic rollover could blur the command/lifecycle contract and expose misleading command actions to existing hooks.
- The chosen path must emit exactly once: explicit /new and /reset already use reset-hook handling, so a shared rollover path can otherwise double-save memory.
- The outgoing transcript must remain readable across archive rotation while preserving existing session_end/session_start ordering and avoiding races with active transcript writers.
- Automatically persisting raw prior-session text broadens memory-poisoning and prompt-replay exposure, so saved content needs the existing untrusted-transcript handling and security review.
- The active implementation lacks sufficient after-fix real-environment proof, so unit tests alone do not establish that memory files are produced correctly through actual daily and idle rollover.
