## Summary

Keep open. Current `main` still captures and archives the previous entry for implicit daily/idle rollovers but does not dispatch the internal reset hook or plugin `before_reset` surface that manual resets use; bundled `session-memory` consequently still ignores those automatic rollovers. The secondary hook-config validation problem is already resolved through an open-ended per-hook schema. The community workaround of an external memory layer is useful, but it cannot receive a reliable reset-boundary signal. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/auto-reply/reply/session.ts))

## What This Changes

Add an automatic daily/idle session-reset lifecycle hook so built-in and custom memory handlers can persist the previous session before or during rollover.

## System Context

Inbound messages enter reply-session initialization, which decides whether the stored session is fresh or must roll over. Manual reset commands dispatch internal and plugin reset hooks, while automatic stale rollovers currently archive the old transcript and begin the replacement session without that equivalent persistence surface.

## Architecture Diagram

flowchart LR
  A[Inbound message] --> B[Session freshness check]
  B -->|Manual new or reset| C[Manual reset hook dispatch]
  B -->|Daily or idle stale| D[Automatic rollover]
  C --> E[Internal and plugin hooks]
  D --> F[Archive prior transcript]
  E --> G[Session-memory persistence]
  F --> H[New session starts]

## Best Possible Solution

Choose and document one additive automatic-reset contract, then route daily and idle rollovers through it with the prior entry/transcript and reason, update `session-memory`, and add regression coverage for automatic and manual paths.

- **Add a typed automatic-reset lifecycle event (recommended):** Introduce a distinct, documented event carrying `daily` or `idle` reason and previous-session context, then make `session-memory` subscribe to it.
- **Extend existing reset hooks:** Preserve the existing hook names but add an explicit automatic reason/context so listeners can distinguish command and rollover resets.
- **Keep persistence owner-specific:** Limit the change to bundled session-memory and defer a general workspace-hook API until a wider lifecycle design is approved.
