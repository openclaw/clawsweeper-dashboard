## Label Justifications

- `P2`: Automatic rollover can silently omit memory persistence, but the impact is bounded to session continuity and has active implementation work.
- `impact:data-loss`: The issue concerns conversation context being discarded without the configured persistence hook running.
- `impact:session-state`: Daily and idle rollover currently create a new session without preserving state through the reset hook surface.

## Summary

Current main still captures and rotates stale daily/idle sessions without invoking the manual reset persistence surfaces, while the hook-entry schema mismatch is fixed; keep this issue open behind the active implementation and a maintainer lifecycle-contract decision.

## What This Changes

Add a persistence hook for automatic daily and idle session rollovers, and allow hook-specific configuration such as `session-memory.messages`.

## Best Possible Solution

Adopt one canonical automatic-rollover dispatch path that supplies the prior entry and transcript plus a typed daily/idle reason, preserves existing lifecycle ordering, avoids manual-reset double fires, and covers daily, idle, fresh-session, and explicit-reset cases.
