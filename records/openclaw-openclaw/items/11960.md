## Summary

Keep open. Current main still leaves automatic daily/idle rollover on the session_end/session_start lifecycle path, while reset-specific internal hooks and before_reset remain manual-command-only and bundled session-memory still filters to command:new/command:reset; https://github.com/openclaw/openclaw/pull/61675 is an open unmerged candidate, not implementation proof.

## What This Changes

The issue requests a session reset hook or equivalent persistence surface so bundled session-memory and custom hooks can persist context before automatic daily or idle session resets clear prior context.

## Best Possible Solution

A maintainer-approved implementation should persist bundled session-memory on automatic daily/idle rollover using the selected hook contract, preserve manual reset semantics and typed lifecycle hooks, and include focused daily plus idle regression coverage.

## Reproduction Assessment

Yes, at source level. Current main can capture a previous daily/idle stale session and then run only session_end/session_start while bundled session-memory only reacts to command:new and command:reset.

## Solution Assessment

Unclear pending maintainer product/API choice. A reset persistence hook is a plausible solution, but maintainers still need to choose whether the durable contract is synthetic command actions, automatic before_reset, a new typed session reset event, or session_end-based memory behavior.
