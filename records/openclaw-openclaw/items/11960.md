## Summary

Keep open. Current main and the latest release still keep bundled session-memory on the manual command hook path only; the hook config schema mismatch is fixed, but automatic daily/idle rollover still needs a maintainer-approved reset persistence contract and the active candidate PR has not landed.

## What This Changes

The issue requests a hook event or equivalent reset-persistence surface so automatic daily and idle session resets can preserve session memory before context is cleared.

## Best Possible Solution

A maintainer-approved implementation should persist bundled session-memory on automatic daily/idle rollover using the selected hook contract, preserve manual reset semantics and typed lifecycle hooks, and include focused daily plus idle regression coverage.

## Reproduction Assessment

Yes, at source level. Current main captures a previous daily/idle stale session and then runs only session_end/session_start while bundled session-memory reacts only to command:new and command:reset.

## Solution Assessment

Unclear pending maintainer product/API choice. A reset persistence hook is plausible, but maintainers still need to choose whether the durable contract is synthetic command actions, before_reset on automatic rollover, a new typed session reset event, or session_end-based memory behavior.
