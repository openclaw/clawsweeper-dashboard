## Summary

Current main still lacks the requested automatic reset persistence surface: daily/idle lazy rollovers emit normal session lifecycle hooks while bundled session-memory remains command-only. The related schema/config mismatch is already fixed, but the central auto-reset hook behavior is still owned by an open, conflicting candidate PR and needs maintainer API direction before cleanup closure.

## What This Changes

Request a reset lifecycle or pre-reset hook path so bundled and custom memory hooks can persist session context before automatic daily or idle session resets.

## Best Possible Solution

Land PR #61675 or a maintainer-approved replacement that persists bundled session-memory on daily/idle rollover, preserves manual reset semantics, uses a clear typed lifecycle contract, and adds focused daily/idle regression coverage.

## Reproduction Assessment

Yes from source inspection: a stale daily/idle session on the next inbound message follows the lazy rollover path that emits `session_end`/`session_start`, while bundled session-memory only handles `command:new` and `command:reset`.

## Solution Assessment

Unclear as a final design: the desired persistence behavior is valid, but maintainers still need to choose the permanent hook/API contract rather than accepting any one synthetic event shape by default.
