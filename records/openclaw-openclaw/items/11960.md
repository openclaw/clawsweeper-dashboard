## Summary

Keep open. Current main and v2026.6.11 still leave automatic daily/idle rollovers on the session lifecycle hook path while bundled session-memory only persists on manual command events; the secondary hook-config schema mismatch is fixed, but the reset persistence contract still needs maintainer selection and an unmerged candidate PR remains open.

## What This Changes

Request a session reset hook or equivalent reset-persistence surface so bundled session-memory and custom hooks can save context before automatic daily/idle resets clear a session.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/61675 or a maintainer-approved replacement that persists session-memory on automatic daily/idle rollover, documents the chosen hook contract, and adds focused daily plus idle regression coverage.

## Reproduction Assessment

Yes, at source level. Current main can capture previousSessionEntry for daily/idle stale rollover, then run only session_end/session_start while bundled session-memory filters to command:new and command:reset.

## Solution Assessment

Unclear pending maintainer product/API choice. A reset persistence hook is a plausible solution, but maintainers still need to choose whether the durable contract is synthetic command actions, automatic before_reset, a typed session reset event, or session_end-based memory behavior.
