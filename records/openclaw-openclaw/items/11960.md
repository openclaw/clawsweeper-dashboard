## Summary

Keep this issue open. Current main still handles daily and idle rollover as a session lifecycle transition but does not expose the requested internal reset-dispatch surface for bundled `session-memory`; the secondary hook-entry configuration mismatch was already addressed. The overlapping open PR is a candidate implementation, but maintainers still need to choose the durable lifecycle contract before landing it or a replacement.

## What This Changes

Request an automatic-reset hook so daily and idle session rollovers can preserve the previous session’s memory, plus hook-specific configuration support for `session-memory`.

## System Context

Inbound messages enter session initialization, which decides whether the stored session is still fresh under daily or idle reset policy. A rollover carries prior-session metadata into archive and lifecycle handling; a memory hook needs a typed pre-reset or rollover signal there to persist the old context before the new session proceeds.

## Architecture Diagram

flowchart LR
  A[Inbound message] --> B[Session initialization]
  B --> C{Daily or idle session stale?}
  C -- No --> D[Reuse active session]
  C -- Yes --> E[Capture and archive prior session]
  E --> F[Reset lifecycle dispatch]
  F --> G[Session-memory persistence]
  G --> H[New session starts]

## Best Possible Solution

Adopt one documented, typed automatic-reset lifecycle contract at the session owner boundary, pass the previous entry and reset reason needed by memory consumers, preserve explicit-reset single delivery, and add focused daily and idle rollover regression coverage.
