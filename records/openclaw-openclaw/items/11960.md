## Summary

Keep open. Current main and v2026.6.11 still leave automatic daily/idle rollovers on the session_end/session_start lifecycle path while bundled session-memory only reacts to command:new and command:reset; the schema mismatch is fixed, but the reset-persistence hook contract still needs maintainer selection and an unmerged candidate PR remains open.

## What This Changes

The issue requests a plugin-visible session reset or before-reset hook so session-memory and custom hooks can persist context before automatic daily/idle resets, plus hook-specific config validation support.

## Best Possible Solution

A maintainer-approved implementation should persist bundled session-memory on automatic daily/idle rollover through the chosen reset hook contract, preserve manual reset and lifecycle semantics, and add focused daily plus idle regression coverage.

## Reproduction Assessment

Yes, at source level. Current main can roll a stale daily/idle session into a new session while only emitting session_end/session_start, and bundled session-memory still listens only to command:new and command:reset.

## Solution Assessment

Unclear pending maintainer product/API choice. A reset persistence hook is a plausible solution, but maintainers still need to choose whether the durable contract is synthetic command actions, before_reset on automatic rollover, a new typed session reset event, or session_end-based memory behavior.
