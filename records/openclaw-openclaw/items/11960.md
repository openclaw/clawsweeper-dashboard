## Label Justifications

- `P2`: The issue affects automatic rollover memory persistence with real context-loss impact, but the affected surface is bounded to session-memory and hook lifecycle behavior.
- `impact:data-loss`: Daily or idle rollover can discard useful conversation context before session-memory has a chance to persist it.

## Summary

Keep open. Current main still has the automatic daily/idle rollover gap: the old session entry is captured and lifecycle hooks fire, but bundled session-memory still only handles command new/reset; the secondary hook-config schema mismatch is fixed, and the remaining work needs maintainer selection of the reset hook contract.

## What This Changes

Request a session reset hook or equivalent persistence surface so session-memory and custom hooks can save context before automatic daily or idle resets clear a session.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/61675 or a maintainer-approved replacement that persists session-memory on daily/idle rollover, keeps manual reset behavior single-fired, documents the chosen hook contract, and adds focused daily plus idle regression coverage.
