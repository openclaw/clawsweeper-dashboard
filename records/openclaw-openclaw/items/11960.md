## Summary

Keep open. Current main and the latest release still leave bundled session-memory on the manual command hook path only; the secondary hook-config schema mismatch is fixed, but automatic daily/idle rollover still needs a maintainer-approved reset persistence contract. The issue discussion and live related items show an open candidate PR, so the right cleanup is to keep this canonical tracker open until that PR or a replacement lands or is explicitly rejected.

## What This Changes

The issue requests a session reset or before-reset hook surface so automatic daily/idle resets can persist the previous session before it is cleared, plus hook-specific config keys for session-memory.

## Best Possible Solution

A maintainer-approved implementation should persist bundled session-memory on automatic daily/idle rollover using the selected hook contract, preserve manual reset semantics and typed lifecycle hooks, and include focused daily plus idle regression coverage.

## Reproduction Assessment

Yes, at source level. Current main can capture a previous daily/idle stale session and then run only session_end/session_start while bundled session-memory only reacts to command:new and command:reset.

## Solution Assessment

Unclear pending maintainer product/API choice. A reset persistence hook is a plausible solution, but maintainers still need to choose whether the durable contract is synthetic command actions, before_reset on automatic rollover, a new typed session reset event, or session_end-based memory behavior.
