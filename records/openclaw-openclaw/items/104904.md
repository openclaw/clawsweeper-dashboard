## Summary

The PR remains necessary because current main still has the reported Groq output-reservation behavior, but the exact head is not merge-ready: its fallback treats missing max-token provenance as an implicit default even though the plugin declares compatibility with older hosts that cannot supply that field. The live proof is strong, but maintainers should choose this approach over the competing shared-transport candidate before the compatibility repair lands.

## What This Changes

The branch adds a Groq-specific one-time retry for exact TPM-limit HTTP 413 responses, removes tools and caps only the fallback request at 1,024 tokens, and adds max-token source provenance to runtime model resolution.

## Best Possible Solution

Make absent provenance non-recoverable or raise the plugin host/API floor, then retain only the provider-scoped or shared-transport fix selected by the provider/runtime owner.
