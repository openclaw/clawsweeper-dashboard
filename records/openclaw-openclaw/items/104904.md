## Summary

This PR has strong provider-level proof and a narrow recovery design, but it still needs a compatibility-contract repair before merge: the new fallback relies on `maxTokensSource`, while the Groq plugin continues to advertise host compatibility with releases that do not provide that field. On those supported hosts, the intended recovery never activates for the discovered default model.

## What This Changes

The branch adds a Groq/Llama-3.3-70b-specific retry for a narrowly matched TPM HTTP 413, removes tool-related payload fields, caps the retry at 1,024 output tokens, and tracks whether the resolved output cap came from configuration or discovery.

## Best Possible Solution

Keep the provider-scoped recovery, but either raise the Groq plugin’s declared host/API minimum to the first release that guarantees `maxTokensSource` or add a demonstrably safe older-host path that preserves explicit configured caps; then prove both the older-host contract and current-host fallback behavior.
