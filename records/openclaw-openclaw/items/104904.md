## Summary

The latest head resolves the two previous compatibility findings and includes convincing live Groq proof, but recovery still requires a non-empty tool list. Because the implicit 32,768-token completion reservation alone exceeds the reported 12,000 TPM tier, a tool-less request can receive the targeted 413 without reaching the fallback.

## What This Changes

The PR adds a Groq/model/error-scoped retry that removes tools and caps fallback output at 1,024 tokens after an oversized TPM 413, with focused provider tests.

## Best Possible Solution

Keep the narrow provider/model/error-scoped approach, but retry every matching implicit-budget TPM 413 regardless of tool presence; remove tool fields when present, always apply the 1,024-token fallback cap, and add a no-tools regression case.
