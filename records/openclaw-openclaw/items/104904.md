## Label Justifications

- `P1`: The linked released-version reproduction shows the default Groq agent workflow failing immediately for real users.
- `merge-risk: 🚨 compatibility`: The new bundled `supportsTools: false` default can silently remove tools from existing higher-tier Groq setups and requires new operator configuration to restore them.

## Summary

The oversized-request bug is real and the provider-scoped 1,024-token default is well placed, but this branch also globally disables tools for a model that Groq documents as tool-capable. That silently removes an existing agent capability for higher-tier users on upgrade, even when they already configured an explicit output-token budget, so the PR needs a compatibility-preserving tool-budget design or explicit maintainer acceptance before merge.

## What This Changes

The PR adds a 1,024-token default request budget for `groq/llama-3.3-70b-versatile`, marks that catalog model as not supporting tools by default, and adds focused plugin tests.

## Best Possible Solution

Keep the provider-owned 1,024-token default, but make tool suppression conditional on the default/base-tier budget so an explicit output-token override preserves the model's existing tool-capable agent surface; add focused tests for fresh default behavior and upgrade/configured behavior.
