## Summary

Keep open: current main and the latest release still contain the broad bare-remember matcher, so the reported plain-memory false positive remains source-reproducible; two open linked PRs already own candidate fix paths and should be reviewed, refreshed, or replaced instead of opening another repair lane.

## What This Changes

The issue asks OpenClaw to stop treating plain memory statements like "I'll remember that" as unscheduled reminder commitments and to avoid suppressing the guard based on unrelated existing cron jobs.

## Best Possible Solution

Land or replace a focused linked PR that excludes plain memory promises while preserving genuine reminder-action phrases; keep cron-success and session-state fixes on their separate tracks.

## Reproduction Assessment

Yes, at source level: current main's regex includes bare `remember`, and `runReplyAgent` appends the note when that match has zero successful cron adds and no same-session cron coverage. I did not run a live agent turn in this read-only review.

## Solution Assessment

Yes on direction: the narrow maintainable fix is to adjust the existing reminder-guard matcher and add regression coverage. The broader cron-suppression behavior should stay on the related cron-success/session-state tracks.
