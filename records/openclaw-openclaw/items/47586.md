## Summary

Keep open: current main and the latest release still include the broad bare-`remember` matcher, so the plain-memory false positive remains source-reproducible; two open same-repository PRs already target this issue and should be reviewed, adopted, or replaced rather than spawning another repair lane.

## What This Changes

The issue asks OpenClaw to stop appending the unscheduled-reminder note to plain memory or knowledge-retention replies and to handle cron suppression more precisely.

## Best Possible Solution

Land or replace a focused linked PR that excludes plain memory promises while preserving genuine reminder-action phrases, and keep cron-success/session-state fixes on their separate tracks.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source-level: current main's regex includes bare `remember`, and the reply runner appends the note when that match has zero successful cron adds and no same-session cron coverage. I did not run a live agent turn in this read-only review.

## Solution Assessment

Yes on direction: the narrow maintainable fix is to adjust the existing reminder-guard matcher and add regression coverage. The broader cron-suppression behavior should remain on related cron-success/session-state tracks unless maintainers choose to bundle it deliberately.
