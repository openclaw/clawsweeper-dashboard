## Summary

Keep open: current main and the latest release still include the broad bare-`remember` matcher, so the plain-memory false positive remains source-reproducible; two open same-repository PRs already target this issue and should be reviewed, adopted, or replaced rather than spawning another repair lane.

## What This Changes

The issue reports that the reminder guard treats plain memory statements like "I'll remember that" as reminder commitments and appends an unscheduled-reminder note.

## Best Possible Solution

Land or replace a focused linked PR that excludes plain memory promises while preserving genuine reminder-action phrases, and keep cron-success/session-state fixes on their separate tracks.

## Maintainer Decision

## Reproduction Assessment

Yes. Source inspection shows the current regex still includes bare `remember`, and the reply runner appends the note when that match has zero successful cron adds and no same-session cron coverage.

## Solution Assessment

Yes on direction. The narrow maintainable fix is to adjust the existing reminder-guard matcher and add regression coverage; broader cron-suppression behavior should remain on related cron-success/session-state tracks unless maintainers deliberately bundle it.
