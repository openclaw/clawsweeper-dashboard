## Summary

Keep open: current main and the latest release still include the broad bare-`remember` reminder matcher, so the memory-statement false positive remains source-reproducible; two same-repo PRs already target the issue but are still open and unmerged.

## What This Changes

The issue asks to stop the reminder guard from treating plain memory-retention statements such as “I'll remember your preference” as temporal reminder commitments.

## Best Possible Solution

Review and land or adopt one of the open same-repo PRs that narrowly removes bare `remember` from the commitment matcher, keeps `remember to ...` reminder intent, and adds focused positive and negative guard tests; keep broader cron suppression fixes in the related cron/session issues.
