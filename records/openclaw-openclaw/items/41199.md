## Summary

Keep open. Current main and shipped releases fixed the `sessions_send` mixed-selector failure and the metadata-only poll-padding failure, but the shared `message(action="send")` path still rejects content-bearing poll fields and the remaining contract is already tracked by the narrower open issue at https://github.com/openclaw/openclaw/issues/42820.

## What This Changes

The issue reports two model-facing tool schema conflicts: `sessions_send` calls with both `sessionKey` and `label`, and `message(action="send")` calls polluted by poll parameters.

## Best Possible Solution

Keep the shipped `sessions_send` and metadata-padding fixes, and let https://github.com/openclaw/openclaw/issues/42820 be the canonical place to decide and validate the remaining `message` tool schema/guard contract.
