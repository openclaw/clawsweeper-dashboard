## Summary

Keep open. Current main and v2026.6.11 fix the `sessions_send` selector conflict, but the shared `message(action="send")` poll-field contract still has a source-visible failure path and is already tracked by a narrower open issue.

## What This Changes

The issue reports that agent communication tools expose optional parameters that models overfill, causing `sessions_send` and `message(action="send")` calls to fail before delivery.

## Best Possible Solution

Keep the shipped `sessions_send` precedence fix, then resolve the remaining shared message-tool contract through https://github.com/openclaw/openclaw/issues/42820 with action-scoped schemas or explicit send-side normalization.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For plain `message(action="send")`, should OpenClaw prevent models from seeing poll content fields in the send schema, strip accidental poll fields at runtime, or keep rejecting content-bearing poll fields as explicit poll intent?

Rationale: Current code intentionally accepts schema-padded poll modifiers but still rejects non-empty poll content fields; changing that boundary affects shared channel delivery semantics across Discord, Telegram, Feishu, Slack, and other message-tool channels.

Likely owner: gumadeiras

Owner reason: Their merged poll gating and schema-consistency work is the strongest history signal for the shared send/poll contract boundary.

Owner confidence: high

Options:

- **Action-scope poll fields (recommended):** Expose poll creation fields only for poll actions or channel-specific poll tools, reducing accidental model fill while preserving strict poll validation.
- **Strip on send:** Treat `action="send"` as authoritative and drop poll fields before delivery, improving reliability but potentially masking poll intent mistakes.
- **Keep strict guard:** Continue rejecting content-bearing poll fields on send and require stronger live evidence before changing the tool contract further.

## Reproduction Assessment

Yes, at source level: current main still throws before delivery when `message(action="send")` includes non-empty `pollQuestion` or `pollOption`. I did not establish a live current-main model/channel reproduction showing that models still emit those content fields after the metadata-padding fix.

## Solution Assessment

Unclear: the current validator narrowing and `sessions_send` precedence repair are good partial fixes, but the durable remaining solution depends on a maintainer choice between action-scoped schemas, send-side sanitization, or preserving the strict poll-intent guard.
