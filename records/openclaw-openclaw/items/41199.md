Rationale: The remaining behavior crosses the model-facing message-tool schema, shared outbound validation, and channel delivery contract, so automation should not choose the permanent contract without maintainer intent.

Options:

- **Action-scope poll fields (recommended):** Expose poll creation fields only for `poll` or channel-specific poll surfaces so plain sends cannot inherit them from the shared schema while strict poll validation remains intact.
- **Strip on send:** Treat `action="send"` as authoritative and remove poll creation fields before delivery, improving send reliability while potentially masking a caller that meant to create a poll.
- **Keep strict guard:** Preserve the shipped content-bearing rejection and require stronger live evidence before changing the shared message-tool contract.
