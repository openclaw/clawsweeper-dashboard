## Summary

Keep this PR open: requester identity is captured when a tool set is created, but the active-run steering path can accept a later sender without rebuilding that context. That lets a lower-privileged sender inherit the initiating owner’s requester facts in the documented authorization hook, so the patch is not safe to merge yet.

## What This Changes

The PR adds optional host-derived requester identity facts to the public plugin `before_tool_call` context and forwards them through managed coding tools and Codex native hook relays.

## Best Possible Solution

Bind immutable host-derived requester facts to every queued or steered input, rebuild or refresh both managed and native hook contexts from that turn, and add a regression proving that a lower-privileged steering sender cannot inherit an owner’s tool authority.
