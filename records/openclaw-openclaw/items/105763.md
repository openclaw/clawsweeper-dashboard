## Label Justifications

- `P2`: The issue blocks a non-default Docker authentication layout but has documented default-path and symlink or wrapper workarounds.
- `impact:auth-provider`: The immediate failure is that the Claude CLI subprocess cannot locate the operator's authenticated credential directory.
- `impact:security`: Changing this behavior affects which credential, hook, plugin, and instruction tree a managed Claude subprocess trusts.
- `impact:ux-friction`: The current error reports only that Claude is not logged in and does not explain that OpenClaw deliberately removed the configured environment variable.

## Summary

Keep open for an explicit security-boundary decision: current and shipped behavior intentionally removes `CLAUDE_CONFIG_DIR`, so this is not a regression, but the Docker authentication failure exposes a legitimate need for a safe, discoverable custom-root workflow.

## What This Changes

Support a non-default Claude Code configuration and credential directory for Docker-hosted `claude-cli` backend runs.

## Best Possible Solution

Keep ambient environment scrubbing, but if custom roots are supported, add one explicit Anthropic-plugin-owned trusted config-root setting with path validation, Docker mount guidance, a visible diagnostic, and fresh-install plus upgrade tests.

- **Keep Default Root Only:** Preserve the existing boundary and improve diagnostics and Docker documentation to require the persisted `/home/node/.claude` layout or an operator-owned wrapper.
- **Restore Ambient Inheritance:** Let the gateway environment redirect Claude Code configuration, accepting the broader hook, plugin, and credential injection risk.

## Solution Assessment

No—the requested ambient inheritance is not the safest solution because that variable redirects more than credentials. An explicit trusted config-root setting or a clearly documented default-root workflow is narrower and preserves the security boundary.
