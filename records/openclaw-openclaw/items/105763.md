## Label Justifications

- `P2`: The authentication failure affects an optional CLI backend in custom Docker configurations, but an explicit backend environment override and default-path mount are available.
- `impact:auth-provider`: The reported failure concerns Claude CLI credential discovery and authentication routing.
- `impact:security`: Automatic inheritance would reopen a deliberately hardened configuration, hook, plugin, and authentication-context redirection boundary.

## Summary

The reported behavior is intentional shipped security hardening rather than a Docker-specific defect: OpenClaw removes inherited Claude configuration-root overrides but permits trusted, explicit backend environment configuration.

## What This Changes

Make Docker-provided `CLAUDE_CONFIG_DIR` propagate automatically to the `claude-cli` backend subprocess.

## Best Possible Solution

Keep inherited config-root stripping and set `CLAUDE_CONFIG_DIR` through the trusted `agents.defaults.cliBackends["claude-cli"].env` surface, or mount credentials at Claude CLI’s default user path.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, from source: current main deliberately places `CLAUDE_CONFIG_DIR` in the Claude backend’s inherited-environment removal list, so the reported fallback to `~/.claude` is expected.

## Solution Assessment

No, unconditional inheritance is not the best solution because it reverses shipped security hardening; an explicit backend environment override is the narrow supported path.
