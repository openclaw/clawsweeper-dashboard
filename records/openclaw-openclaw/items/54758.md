## Summary

Keep open. ## What This Changes

The PR changes Control UI WebSocket close handling so pending RPC requests receive structured `GatewayRequestError` data for connect-handshake failures instead of a generic close error.

## Best Possible Solution

Rebase the Control UI fix onto `ui/src/api/gateway.ts` and `ui/src/api/gateway.node.test.ts`, preserve startup-retry and close-callback behavior, then land if maintainers accept the Control UI error-shape change and decide whether gateway-client parity is follow-up work.

## Solution Assessment

Yes after rebase. Reusing `GatewayRequestError` at the existing `flushPending` boundary is the narrowest Control UI fix, while sibling `packages/gateway-client` parity is a maintainer scope choice rather than a definite patch defect.
