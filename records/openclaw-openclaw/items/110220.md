## Summary

Keep this PR open for maintainer review: it fixes the reported RPC-cancellation attribution, but its new task-status helper can classify a hard timeout as cancelled when the timeout is expressed by `timeoutPhase` rather than `stopReason`. The `maintainer` label also requires explicit human handling.

## What This Changes

The branch changes Gateway async agent-run task attribution so RPC aborts are recorded as cancelled without a `gateway_draining` timeout phase, while preserving timeout protocol responses.

## Best Possible Solution

Derive tracked-task terminal status from the shared normalized agent terminal outcome, then add a regression that covers an aborted completion carrying a hard timeout phase without an explicit timeout stop reason; remove the release-owned changelog entry.

## Solution Assessment
