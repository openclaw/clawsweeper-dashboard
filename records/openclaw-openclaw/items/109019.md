## Summary

Keep this PR open: the token distinguishes who wrote a surviving record, but not whether that attempt had already committed successfully before a later persistence error. That can delete a live plugin target while durable configuration still references it; the revised branch also still lacks contributor-supplied execution evidence for its new real SQLite/filesystem proof test.

## What This Changes

## Best Possible Solution

Make cleanup conditional on an explicit persistence-phase outcome proving that config commit failed and SQLite rollback left the current record behind; preserve targets after post-commit or refresh failures, then demonstrate both paths with real SQLite and filesystem execution.
