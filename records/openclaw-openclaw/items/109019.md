- `merge-risk: 🚨 compatibility`: The branch changes a persisted install-record contract and uses that value to decide whether an existing plugin target is retained or deleted.

## Summary

This PR remains necessary for the double-fault cleanup case, but it still deletes a target when a persistence call reports an error after the install record has already committed. A matching token proves record identity, not that rollback failed; the cleanup must be limited to a confirmed rollback-residue outcome before merge.

## What This Changes

Adds a per-install attempt token to persisted managed-plugin install records and uses it during failed-install cleanup to distinguish stale records from records owned by another process.

## Best Possible Solution

Keep the attempt token, but make the persistence boundary return or throw a distinct confirmed-rollback-residue outcome; invoke target cleanup only for that outcome and add real SQLite/filesystem proof for both cleanup and post-commit preservation.
