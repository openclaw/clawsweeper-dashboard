## Label Justifications

- `P2`: This is a normal-priority cron message-delivery bugfix with a narrow code change and limited blast radius.
- `merge-risk: 🚨 compatibility`: The PR changes behavior for existing direct cron service callers that create current/session jobs without explicit delivery.
- `merge-risk: 🚨 message-delivery`: The new default can cause future current/session cron jobs to send announce delivery where direct service creation previously produced no initial delivery.

## Summary

Keep open: the patch is a narrow, source-supported alignment of direct cron service default delivery with the existing current/session cron delivery invariant, but the intentional create-time default change still needs maintainer acceptance before merge.

## What This Changes

The PR expands `resolveInitialCronDelivery` so omitted delivery for `isolated`, `current`, and `session:<id>` agentTurn/command cron jobs resolves to `{ mode: "announce" }`.

## Best Possible Solution

Land the helper alignment if maintainers accept announce-by-default for omitted delivery on session-like cron jobs, ideally with a focused regression test for direct `createJob` or `resolveInitialCronDelivery`.

## Reproduction Assessment

Yes. Source inspection on current main shows `resolveInitialCronDelivery` returns announce only for `isolated`, while `createJob` uses that helper and sibling normalize/delivery-plan paths already classify `current` and `session:<id>` as announce-default output jobs.

## Solution Assessment

Mostly yes. The patch touches the direct helper that causes the inconsistency and preserves explicit delivery, though a focused regression test or shared predicate would make the fix stronger.
