## Summary

Keep open. The latest head appears to have repaired the earlier invalid test-fixture blocker, and the helper change matches current sibling cron semantics, but it still changes persisted create-time delivery defaults and overlaps an open cron default-policy PR that maintainers should resolve before merge.

## What This Changes

The PR expands cron initial delivery resolution so omitted delivery on `current` and `session:<id>` agent/command jobs is stored as `announce`, and adds focused resolver tests.

## Best Possible Solution

Land the helper/test alignment only after maintainers confirm announce remains the intended default for detached current/session cron targets; otherwise fold this consistency fix into the broader cron default-policy path.

## Reproduction Assessment

Yes for the narrower inconsistency: current main stores undefined delivery for direct `createJob` calls using `current` or `session:<id>`, while normalization and runtime delivery planning already treat those targets as announce-capable. I did not execute tests because this was a read-only review.

## Solution Assessment

Yes, with a policy caveat. The helper is the right owner boundary for persisted create-time delivery, but maintainers still need to confirm the announce default against the adjacent silent-default proposal.
