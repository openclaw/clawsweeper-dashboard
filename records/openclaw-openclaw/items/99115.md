## Summary

Keep open. The branch is a focused consistency fix for direct cron service creation, but it is not a conservative cleanup close: current main still stores no create-time delivery for direct `current`/`session:<id>` calls, while adjacent open work is arguing for the opposite silent-default policy.

## What This Changes

The PR changes cron initial delivery resolution to default omitted delivery to `announce` for `current` and `session:<id>` targets, and adds resolver tests for target/payload combinations.

## Best Possible Solution

Land this only if maintainers confirm `announce` remains the intended default for current/session cron targets; otherwise coordinate it with the broader cron default-policy work.

## Reproduction Assessment

Yes for the narrower persisted-default mismatch: source inspection shows direct CronService creation stores undefined delivery for `current` and `session:<id>` on current main. The broader claim that runtime announcements are missed is less direct because runtime delivery planning already treats omitted delivery for those targets as announce.

## Solution Assessment

Yes, with a policy caveat. The helper is the right owner boundary for direct create-time persistence if `announce` remains the intended default, but the adjacent silent-default proposal means maintainer confirmation is needed before merge.
