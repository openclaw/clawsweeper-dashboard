## Summary

Keep open: the latest head removes the earlier invalid test fixtures and the helper change looks correct, but it changes shipped direct-create delivery-default behavior and overlaps with an open cron default-policy PR that maintainers should reconcile before merge.

## What This Changes

The PR broadens `resolveInitialCronDelivery` so `current` and `session:<id>` agentTurn/command cron jobs with omitted delivery get `{ mode: "announce" }` like `isolated` jobs.

## Best Possible Solution

Land the helper alignment with focused regression coverage only if maintainers affirm announce-by-default remains canonical; otherwise fold persistent-target handling into the broader cron delivery-default decision.

## Reproduction Assessment

Yes, source-reproducible: current main and `v2026.6.11` only default initial delivery for `isolated`, while the direct create path uses that helper and sibling cron paths already classify `current` and `session:<id>` as announce-capable detached output jobs.

## Solution Assessment

Yes for the current announce-default policy: the helper is the narrow owner-boundary fix. It still needs maintainer default-policy review because another open PR argues for silent cron defaults instead.
