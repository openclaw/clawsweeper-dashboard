## Label Justifications

- `P2`: This is a valid but bounded cron announcement bug affecting specific direct and declarative creation paths rather than an unusable core workflow.
- `merge-risk: 🚨 compatibility`: Merging changes omitted-delivery persistence for existing direct or declarative `current` and `session:*` callers from no delivery to implicit announce.
- `merge-risk: 🚨 message-delivery`: The changed default determines whether cron results are announced, and a wrong or drifting predicate can suppress or unexpectedly emit messages.

## Summary

The reported inconsistency is real and the patch is directionally correct, but the current head still duplicates the delivery-default target policy across cron paths, while the live run exercises normalized CLI creation rather than the changed direct-service/declarative boundary. Keep this PR open for a cron contract-owner decision and exact-path proof.

## What This Changes

This PR makes omitted delivery default to announce for direct-service `current` and `session:*` agent-turn or command cron jobs and adds helper, persistence, and declarative-convergence tests.

## Best Possible Solution

Define one named cron delivery-default policy with explicit `isolated`/`current`/`session:*` semantics, consume it from normalized and direct-service creation, preserve explicit delivery plus `main` and `systemEvent` behavior, and prove a current-head direct or declarative creation through persistence and delivery.
