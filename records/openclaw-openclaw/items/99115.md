## Summary

This PR has a focused, proof-backed implementation and no remaining mechanical review finding, but it changes the direct-service delivery-default contract. A cron contract owner should explicitly decide whether `CronService.add` callers using `current` or `session:*` must receive the same announce default as normalized creation paths before merge.

## What This Changes

The branch centralizes cron detached-delivery classification and applies announce defaults for direct-service `current` and `session:*` agent-turn or command jobs.

## Best Possible Solution

Document and approve one canonical cron creation contract: normalized, direct-service, and declarative paths should either all apply the same announce default for detached-like targets or preserve the existing direct-service distinction with an explicit boundary and tests.
