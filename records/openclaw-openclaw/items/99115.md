## Label Justifications

- `P2`: This is a normal-priority cron message-delivery bugfix with a narrow source change and limited blast radius.
- `merge-risk: 🚨 compatibility`: The PR changes a create-time default for direct cron job creation, which can alter behavior for callers that omitted delivery config.
- `merge-risk: 🚨 message-delivery`: The changed default can cause future `current` and `session:<id>` cron jobs to send announce delivery where direct service creation previously produced no initial delivery.

## Summary

Keep open: this is a focused cron bugfix that current main has not fully covered at the direct service layer. The patch aligns `resolveInitialCronDelivery` with existing normalization, delivery-plan, and job-validation semantics, but maintainers should notice that it intentionally expands a create-time message-delivery default and does not add focused regression coverage.

## What This Changes

The PR expands `resolveInitialCronDelivery` so cron jobs created with `current` or `session:<id>` targets and agent/command payloads get default `{ mode: "announce" }` delivery when delivery is omitted.

## Best Possible Solution

Accept the direct-service default alignment once maintainers are comfortable with announce-by-default for omitted delivery, preferably with a focused regression test for `current` and `session:<id>`.

## Reproduction Assessment

Yes. Source inspection on current main shows `resolveInitialCronDelivery` returns announce only for `isolated`, while direct `createJob` uses that helper and sibling cron paths already classify `current` and `session:<id>` as session-like output jobs.

## Solution Assessment

Mostly yes. The patch touches the direct helper that causes the inconsistency and preserves explicit delivery, though a focused regression test would make the merge shape stronger.
