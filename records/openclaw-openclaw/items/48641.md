## What This Changes

The issue reports allowlisted Discord DMs being silently dropped while outbound DMs and guild channel messages still work.

## Best Possible Solution

Choose and document the Discord multi-account DM authorization contract, then implement that contract with focused account-merge/preflight tests and a visible diagnostic path for configured senders that are denied.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should Discord account-scoped allowFrom override the global allowFrom list, merge with it, or use an explicit inheritance mode for multi-account DMs?

Rationale: The linked fix would restore the reporter's global allowlist expectation but also broadens per-account authorization for users who rely on account-level allowFrom as a restriction boundary.

Likely owner: Peter Steinberger

Owner reason: Peter has the most recent current-main ownership across the Discord docs, account merge, and shared allowlist helper touched by this decision.

Owner confidence: medium

Options:

- **Keep Override Semantics (recommended):** Preserve the documented security boundary and fix the user experience through clearer diagnostics or explicit per-account configuration guidance.
- **Merge Global And Account Lists:** Treat top-level allowFrom as a true global allowlist, accepting that per-account lists can no longer narrow it without another config shape.
- **Add Explicit Inheritance Mode:** Keep current override by default and add an intentional config or doctor-guided migration for users who want union behavior.

## Reproduction Assessment

Yes, at source level: account allowFrom is selected before parent allowFrom, so a sender only in the top-level list can be denied for an account with its own list. I did not establish a live Discord DM reproduction in this read-only cleanup pass.

## Solution Assessment

Unclear; the obvious union fix is not necessarily the best solution because it broadens an authorization boundary that current docs and tests preserve. The best fix needs maintainer confirmation of the intended multi-account allowlist contract before implementation.
