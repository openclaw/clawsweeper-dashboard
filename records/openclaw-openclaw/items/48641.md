## What This Changes

Have maintainers define the Discord root-versus-account DM authorization contract, then update allowlist resolution, denied-DM diagnostics, docs, tests, and live multi-account DM proof to match it.

Options:

- **Preserve Account Narrowing (recommended):** Keep account-scoped allowFrom as the default security boundary and fix this issue through explicit per-account configuration, diagnostics, docs, or doctor guidance.
- **Union Root And Account Lists:** Allow root-listed users through account DMs too, which addresses the reported root cause but broadens access for accounts that were intentionally narrowed.
- **Add Explicit Inheritance Policy:** Introduce a documented opt-in inheritance mode only if maintainers want both root convenience and account-specific narrowing despite the extra config surface.

No high-confidence live reproduction was established. Source inspection shows account-level allowFrom takes precedence over root allowFrom and unauthorized DMs return before routing, which reproduces the suspected failure class but not the exact multi-account live drop.

## Solution Assessment

No for the direct union fix: it is plausible but not clearly the best solution because it widens account authorization. The safer path is a maintainer security-contract decision before implementation.
