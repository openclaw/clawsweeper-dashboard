## Summary

Keep open: current main and v2026.6.11 still preserve Discord account-scoped `allowFrom` precedence, the closed union PR is not a safe superseding fix, and the remaining fix needs a maintainer security-contract decision.

## What This Changes

The issue asks OpenClaw to stop silently dropping inbound Discord DMs from an allowlisted user in a multi-account Discord configuration where outbound DMs and guild messages work.

## Best Possible Solution

Have maintainers define the Discord root-versus-account DM authorization contract, then implement that contract with focused precedence tests, docs updates, denied-DM diagnostics, and live multi-account DM proof.

Options:

- **Preserve Account Narrowing (recommended):** Keep account-scoped `allowFrom` as the default narrowing boundary and address this issue through explicit account configuration, diagnostics, or a separately approved migration.
- **Union Root And Account Lists:** Allow root-listed users through account DMs too, which addresses the reported root cause but broadens access for accounts that were intentionally narrowed.
- **Add Explicit Inheritance Policy:** Introduce a documented opt-in inheritance mode only if maintainers want both root convenience and account-specific narrowing.

## Solution Assessment

No for the direct union fix: it is plausible but not clearly the best solution because it widens account authorization. The safer next step is a maintainer decision on the root-versus-account contract before implementation.
