## Summary

Keep open: current main and v2026.6.11 still preserve Discord account-scoped `allowFrom` precedence, and the closed direct merge/union repair was abandoned because it would change Discord DM authorization semantics.

## What This Changes

The issue reports Discord inbound DMs from an allowlisted user being dropped with no logs in a multi-account Discord setup while outbound DMs and guild messages work.

## Best Possible Solution

Define the Discord multi-account DM authorization contract first, then implement the chosen behavior with account-level tests, docs/status diagnostics, and live multi-account DM proof while preserving restrictive account overrides unless maintainers explicitly choose additive global allowlists.

Options:

- **Preserve restrictive account overrides (recommended):** Keep account `allowFrom` as the limiting scope when set, and fix the user pain through effective-allowlist diagnostics, docs, status, and live-proofed routing guidance.
- **Make root allowFrom additive:** Merge root and account `allowFrom` for Discord accounts, accepting that existing account-restricted bots may become reachable by globally allowlisted users.
- **Add an explicit inheritance mode:** Introduce a documented, migrated policy knob for additive versus restrictive account allowlists, at the cost of new config surface and upgrade complexity.
