## Summary

Keep open: current main and v2026.6.11 still preserve Discord account-scoped DM allowlist precedence, and the remaining fix is an authorization-contract decision rather than a safe cleanup close.

## What This Changes

The issue reports that allowlisted inbound Discord DMs are silently dropped in multi-account Discord configurations while outbound DMs and guild messages work.

## Best Possible Solution

Have maintainers define the Discord root-versus-account DM authorization contract, then implement it with focused precedence tests, docs updates, denied-DM diagnostics, and live multi-account DM proof.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should Discord account-scoped allowFrom replace the root allowlist, as current docs/tests say, or should root and account allowFrom be unioned for inbound DMs?

Rationale: The obvious union repair may fix one reported failure mode but broadens who can start DM agent sessions for accounts that currently narrow root access.

Likely owner: steipete

Owner reason: The decision sits in the shared DM allowlist and Discord account config path where current blame and recent feature history point most strongly to steipete.

Owner confidence: high

Options:

- **Preserve account narrowing (recommended):** Keep account-scoped allowFrom as the default narrowing boundary and improve diagnostics/setup guidance for DMs that hit the wrong account or missing account allowlist.
- **Union root and account lists:** Allow root-listed users through account DMs too, but document and test the broader authorization semantics as an intentional compatibility break.
- **Add an explicit opt-in mode:** Keep current default semantics and add a documented account-level inheritance/union switch only if maintainers want both behaviors.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Partly: source inspection proves account-level allowFrom takes precedence over root allowFrom and denied DMs return before routing, but I did not establish a live multi-account Discord DM reproduction.

## Solution Assessment

Is this the best way to solve the issue? No for the direct union fix: it is plausible, but not clearly best because it widens account authorization; the security contract should be chosen first.
