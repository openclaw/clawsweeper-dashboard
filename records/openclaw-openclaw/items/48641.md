## Summary

Keep open: current main and v2026.6.11 still preserve Discord account-scoped `allowFrom` precedence, and the closed direct repair was abandoned because it would change Discord DM authorization semantics.

## What This Changes

Fix Discord inbound DMs from allowlisted users being dropped in multi-account setups where outbound DMs and guild channel messages still work.

## Best Possible Solution

Define the Discord multi-account DM authorization contract first, then implement the chosen behavior with account-level tests, docs/status diagnostics, and live multi-account DM proof.

## Maintainer Decision

Kind: security_boundary

Question: Should Discord root `allowFrom` be an additive global allowlist for every account, or should account-scoped `allowFrom` remain a restrictive override that only inherits root when unset?

Rationale: The direct code repair would change who can DM account-scoped Discord bots, so automation should not choose the authorization boundary without maintainer/security intent.

Likely owner: steipete

Owner reason: Recent Discord DM access and shared allowlist resolver history points to this person as the best available owner for the security-sensitive contract choice.

Owner confidence: high

Options:

- **Preserve restrictive overrides (recommended):** Keep account `allowFrom` as the limiting scope when set, and address the user pain through diagnostics, docs, status output, and live-proofed routing guidance.
- **Make root allowFrom additive:** Merge root and account `allowFrom` for Discord accounts, accepting that globally allowlisted users may reach accounts that were previously narrower.
- **Add explicit inheritance mode:** Introduce a documented policy knob for additive versus restrictive account allowlists, with migration and upgrade tests for both modes.

## Reproduction Assessment

Yes at source level, but not as a live current-main Discord repro. A user present only in root `channels.discord.allowFrom` is denied when the receiving account has its own `allowFrom`; the exact multi-account DM drop still needs live proof.

## Solution Assessment

No, the simple union-style fix is only a plausible fix because it changes the Discord authorization boundary. The best path is a maintainer-approved contract plus focused tests, docs, diagnostics, and live Discord proof.
