## Summary

Keep open: current main and v2026.6.11 still preserve Discord account-scoped allowFrom precedence, while the direct fix PR is closed unmerged and would change authorization semantics.

## What This Changes

The issue reports that Discord inbound DMs from an allowlisted user are silently dropped while outbound DMs and guild messages still work.

## Best Possible Solution

Have maintainers define the Discord DM account-inheritance and multi-account ownership contract, then implement that contract in the Discord plugin with focused precedence tests, docs updates, and live DM proof.

## Reproduction Assessment

Partly. Source inspection shows account-level allowFrom takes precedence over root allowFrom and denied DMs can return null before routing, but I did not establish a live current-main Discord DM repro for the exact multi-account report.

## Solution Assessment

No. The closed union PR was plausible but not clearly the best fix because it would widen account-scoped authorization; maintainers should choose the security contract before a repair branch changes behavior.
