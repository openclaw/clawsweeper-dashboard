## Summary

This issue remains necessary: current documentation exposes approver routing and approval-policy controls but no resolved-outcome delivery setting, and the linked open PR is only a candidate implementation. Its deferred edit mode means maintainers should first confirm the intended shared approval-delivery contract rather than close this request before a reviewed implementation lands.

## What This Changes

Add a configurable resolved exec-approval outcome policy so channel timelines can suppress the extra Allowed/Denied echo or, where supported, update the original approval prompt.

## System Context

Exec approvals turn a command request into an operator decision and project the prompt through channel adapters before execution continues. The requested setting would control the terminal decision notification that follows that approval flow, affecting shared approval delivery and channel timelines.

## Architecture Diagram

flowchart LR
  A[Exec command needs approval] --> B[Shared approval lifecycle]
  B --> C[Channel approval prompt]
  C --> D[Operator allows or denies]
  D --> E[Outcome delivery policy]
  E --> F[Channel timeline or prompt update]
  D --> G[Command proceeds or is denied]

## Best Possible Solution

Define one shared terminal-outcome policy for exec and plugin approvals, preserve the existing delivered-message behavior by default, support explicit suppression where safe, and add update mode only with durable per-delivery identifiers plus channel capability handling.
