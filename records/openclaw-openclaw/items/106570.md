## Label Justifications

- `P1`: A provider connection failure can itself break the terminal error path, leaving an active agent stream hung or rejected instead of failing cleanly.
- `impact:crash-loop`: The catch block can throw a second unhandled serialization exception and prevent graceful stream termination during network failures.
- `impact:auth-provider`: The defect is in the OpenAI-compatible provider stream path and affects provider failure propagation.

## Summary

Current main still uses fallible `JSON.stringify(error)` inside the OpenAI Completions stream catch path, so a circular non-Error rejection can replace the original provider failure with a serialization exception and leave consumers without a terminal stream event. The closely related Google-provider report identifies the same root cause and should be fixed in the same focused change.

## What This Changes

Make provider stream error handling tolerate circular non-Error rejection values without losing the terminal error event or stream closure.

## Best Possible Solution

Add one provider-neutral unknown-error formatter that preserves `Error.message`, returns strings directly, attempts JSON serialization for structured values, and falls back safely to `String(error)` when serialization fails or returns no text; use it in both affected provider catch paths and cover circular values plus terminal stream completion.
