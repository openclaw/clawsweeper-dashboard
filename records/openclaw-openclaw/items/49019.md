## Summary

Keep open: current main and v2026.6.11 still expose an async-only `POST /hooks/agent` contract, while the direct implementation candidate at https://github.com/openclaw/openclaw/pull/67433 remains open for product and security review.

## What This Changes

Request an opt-in synchronous result-return mode for `POST /hooks/agent`, with optional announcement suppression, so external automations can avoid `sessions_history` polling or enabling `sessions_send` over HTTP.

## Best Possible Solution

Review https://github.com/openclaw/openclaw/pull/67433 as the canonical implementation candidate and land a maintainer-approved API/security shape, or record a maintainer decision that this hook result-return mode should not be core.

## Reproduction Assessment

Not applicable as a bug reproduction, but the feature gap is source-reproducible: current main and v2026.6.11 lack `waitForResult`, `announceToMain`, and `resultMode`, and `/hooks/agent` returns only a run id.

## Solution Assessment

Unclear until maintainer review. Extending `/hooks/agent` is a plausible narrow solution, but the final response shape, timeout/replay behavior, and security envelope need maintainer product and security decisions.
