## Summary

Keep open: current main and the latest release still expose `POST /hooks/agent` as an async run-id response, while the direct implementation candidate remains open and needs maintainer product/security review before this API should be accepted.

## What This Changes

The issue requests an opt-in blocking/result-return mode for `POST /hooks/agent` so authenticated external automations can receive a deterministic agent result without polling session history.

## Best Possible Solution

Keep this issue as the canonical product/security decision point, review https://github.com/openclaw/openclaw/pull/67433, and either land a maintainer-approved hook result contract or explicitly reject/narrow the API direction.

## Reproduction Assessment

Yes, source-reproducible: current main parses no `waitForResult`/`announceToMain` fields and the `/hooks/agent` handler returns only `{ ok: true, runId }`. The latest release tag `v2026.6.11` shows the same async-only contract.

## Solution Assessment

Unclear as a final product solution: adding a result-return mode to `/hooks/agent` is plausible and has an open implementation candidate, but maintainers still need to settle the API shape and security hardening before this is the best supported contract.
