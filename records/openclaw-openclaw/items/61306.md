## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Move mission persistence into SQLite:** `src/claw/service.ts:68-70`
  - body: This introduces durable Claw runtime state as `mission-state.json`, `control-state.json`, and `AUDIT_LOG.jsonl` under `workspace/missions`. OpenClaw's runtime state policy requires OpenClaw-owned state/cache to live in SQLite/shared state, plugin KV, agent DB, or a designed SQLite schema; landing these sidecars would create migration and session-state debt before Claw even ships.
  - confidence: 0.95
- **[P1] Validate mission IDs before resolving paths:** `src/claw/service.ts:1717-1718`
  - body: Gateway callers can pass any non-empty `missionId`, and `resolveMissionDir` joins it directly under the missions root. A value containing `..` or path separators can escape `workspace/missions` and drive state/audit/artifact operations against unintended paths, so this needs generated-ID validation or normalized containment before any filesystem access.
  - confidence: 0.92
- **[P1] Preserve the HTTP/1 pinned dispatcher helpers:** `src/infra/net/ssrf.ts:430-447`
  - body: This path replaces the existing `createHttp1*` helpers with raw Undici `Agent`/`ProxyAgent` construction. Those helpers enforce `allowH2: false` and proxy TLS policy for guarded SSRF dispatchers; bypassing them can re-enable HTTP/2 or drift from the pinned-lookup security assumptions.
  - confidence: 0.9
- **[P1] Reject preflight reruns outside waiting states:** `src/claw/service.ts:3780-3781`
  - body: `rerunPreflight` mutates lifecycle state without checking the current mission status first. Calling it for `done`, `cancelled`, `running`, or `verifying` missions can move them back to `awaiting_approval`/`awaiting_setup`, resurrecting terminal missions or overwriting active state.
  - confidence: 0.88
- **[P2] Use effective browser plugin activation:** `src/claw/service.ts:600-602`
  - body: `isBrowserPluginEnabled` only returns true for an explicit `plugins.entries.browser.enabled === true`, but the bundled browser plugin is enabled by default unless explicitly disabled. Default configs would be marked as missing browser plugin readiness and browser-required missions can be incorrectly blocked.
  - confidence: 0.86
