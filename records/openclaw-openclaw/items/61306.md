## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.82

Full review comments:

- **[P1] Move mission persistence into SQLite:** `src/claw/service.ts:1774`
  - body: The PR writes mission state and control state as JSON files under the workspace mission directory. OpenClaw runtime state is SQLite-first, so shipping this creates a second durable state store for mission/session continuity instead of using the shared state DB or a designed SQLite owner/schema.
  - confidence: 0.89
- **[P1] Validate mission IDs before resolving paths:** `src/claw/service.ts:1717-1718`
  - body: RPC-supplied mission IDs are passed into `resolveMissionDir` and joined under the missions root without a generated-id check or normalized containment guard. A crafted ID with path separators can make later read/write paths target files outside the intended mission directory.
  - confidence: 0.84
- **[P1] Preserve the HTTP/1 pinned dispatcher helpers:** `src/infra/net/ssrf.ts:426-430`
  - body: This replaces the current pinned SSRF dispatcher helpers with direct Undici constructors. Those helpers enforce `allowH2: false`; bypassing them can re-enable HTTP/2 on guarded requests and weaken the pinned-lookup security assumptions.
  - confidence: 0.86
- **[P2] Use effective browser plugin activation:** `src/claw/service.ts:600-602`
  - body: The readiness check only accepts `plugins.entries.browser.enabled === true`, but the bundled browser plugin is enabled by default when the config entry is unset. Default installations can be incorrectly blocked as if browser support is disabled.
  - confidence: 0.79
- **[P2] Skip malformed audit log lines:** `src/claw/service.ts:3846-3847`
  - body: `getAudit` parses every JSONL line directly, so one truncated or corrupt audit line makes the entire mission audit request fail. Operators should lose only the bad record, not the whole audit feed.
  - confidence: 0.75
