## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.87

Full review comments:

- **[P1] Validate mission IDs before resolving paths:** `src/claw/service.ts:1717-1718`
  - body: `missionId` comes from RPC as any non-empty string and is then joined into the mission directory. A value with `..` or path separators can escape the missions root and target an arbitrary `mission-state.json` path, including through non-admin read endpoints such as audit/artifact reads. Reject IDs that do not match the generated mission-id format or enforce normalized containment before any read/write.
  - confidence: 0.9
- **[P1] Keep pinned dispatchers on HTTP/1 helpers:** `src/infra/net/ssrf.ts:430-432`
  - body: This branch constructs raw Undici dispatchers for pinned SSRF-guarded requests. Current main routes these through `createHttp1*` helpers so guarded networking keeps HTTP/1-only and proxy/TLS policy; dropping that wrapper can re-enable transport behavior the guard intentionally disables.
  - confidence: 0.86
- **[P1] Re-check mission status after verifier returns:** `src/claw/service.ts:3092-3101`
  - body: The verifier result is applied to the stale in-memory mission record after `runMissionAgent` completes. If an operator pauses or cancels the mission while the verifier is in flight, this can still mark it done or move it back to running, overwriting the control action; reload and validate the current mission status before persisting verifier/helper/runner outcomes.
  - confidence: 0.84
- **[P2] Use the SQLite Task Flow store for mission state:** `src/claw/service.ts:1774`
  - body: The new runtime writes mission state, control state, and audit data to workspace JSON/JSONL files. OpenClaw's current task/flow and control-plane state is SQLite-backed, so adding a parallel durable store skips existing backup, doctor, migration, and consistency paths; keep markdown files derived and put canonical mission state in the existing store.
  - confidence: 0.8
