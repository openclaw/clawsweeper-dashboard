## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Keep pinned dispatchers on HTTP/1:** `src/infra/net/ssrf.ts:430-432`
  - body: `createPinnedDispatcher` now constructs raw Undici dispatchers, bypassing the current `createHttp1*` helpers that force `allowH2: false`. Guarded SSRF fetches rely on those HTTP/1-only dispatchers, so this can re-enable HTTP/2 on a security-sensitive path.
  - confidence: 0.92
- **[P1] Isolate failed recovery before mission cycles:** `src/claw/runtime.ts:76`
  - body: If `recoverInterruptedMissions()` throws for one bad mission, this catch aborts the whole drain before `runMissionCycles()` and leaves `state.recovered` false. Every wake retries recovery and can prevent unrelated queued or active missions from progressing.
  - confidence: 0.88
- **[P1] Revalidate mission state after agent runs:** `src/claw/service.ts:2922`
  - body: The runner/helper/verifier paths mutate the same in-memory `state` after `runMissionAgent(...)` returns, without reloading the mission first. If an operator pauses or cancels while the agent call is in flight, the stale state can overwrite that control action and resume or complete the mission unexpectedly.
  - confidence: 0.86
- **[P1] Gate preflight reruns by mission status:** `src/claw/service.ts:3781`
  - body: `rerunPreflight` rewrites mission status without first checking that the mission is in a preflight/setup state. A direct RPC can move running, done, or cancelled missions back to awaiting approval/setup, desynchronizing terminal or active lifecycle fields.
  - confidence: 0.84
- **[P2] Return before reading limit after invalid missionId:** `src/gateway/server-methods/claw.ts:373`
  - body: `readRequiredString` already sends an error response when `missionId` is invalid, but the handler still reads `limit`, whose validator can send a second error response. Split the guards so one request cannot call `respond` twice.
  - confidence: 0.93
- **[P2] Use effective browser plugin activation:** `src/claw/service.ts:600-602`
  - body: The browser plugin is bundled with `enabledByDefault: true`, but Claw treats it as enabled only when config explicitly says `plugins.entries.browser.enabled === true`. Default valid installs can therefore block browser-required missions as though the plugin were disabled.
  - confidence: 0.82
- **[P2] Skip malformed audit records:** `src/claw/service.ts:3847`
  - body: `getAudit` parses every JSONL line with a bare `JSON.parse`, so one truncated audit append makes the whole audit feed fail. Mission audit history should skip or surface the bad record without hiding all valid entries.
  - confidence: 0.79
