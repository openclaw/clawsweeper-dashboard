## Summary

Keep this PR open for normal review: the proposed wiring is a focused repair for an existing Google Meet probe path and preserves the default timeout, but its evidence is mock/test-only and does not yet demonstrate the changed command through a real Gateway/plugin setup.

## What This Changes

Adds an explicit `--timeout-ms` / `timeoutMs` override for Google Meet `test-speech`, carrying it from the CLI and tool Gateway calls into the runtime probe while retaining the existing default wait.

## System Context

Google Meet live probes start from the CLI or agent tool, pass through the Gateway plugin handler, join or inspect a meeting session, then poll Chrome audio-bridge health for observed speech output. This change affects the request deadline that governs how long the speech probe can wait before returning its result.

  E --> F[Verified, timed out, or manual-action result]

## Best Possible Solution

Keep the existing default timeout and land this narrow request-level override only after a redacted live Gateway/CLI or agent-tool run proves that an explicit timeout reaches the Google Meet plugin and produces a real probe response.
