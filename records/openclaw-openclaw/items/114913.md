## Summary

Keep this issue open for maintainer direction. The report identifies a plausible recall-availability gap: a cold primary embedding request can consume the tool deadline even though a populated SQLite FTS index could return lexical results, but the proposed per-primary budget and fallback semantics add a new compatibility-sensitive retrieval policy rather than proving an existing contract is broken.

## What This Changes

Add a bounded primary-embedding phase for memory search so a timeout can return existing SQLite FTS results, identify them as lexical, and preserve caller cancellation.

## System Context

Memory search accepts an agent tool query, obtains a query embedding from the configured provider, and uses the local memory index to retrieve relevant chunks. The requested change would let the retrieval path use the existing lexical FTS index when embedding generation exceeds an internal budget, before the outer tool deadline expires.

## Best Possible Solution

Define one bounded, internal retrieval-timeout policy in the memory owner plugin: preserve semantic/hybrid retrieval when the primary embedding completes, return clearly labeled FTS-only results on that policy timeout, and add focused coverage for cold, warm, abort, and unavailable-FTS cases.
