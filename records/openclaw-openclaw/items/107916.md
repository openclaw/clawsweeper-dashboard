## Label Justifications

- `P1`: Repeated usage scans reportedly stall a live Gateway for 15–28 seconds, drive severe memory pressure, and have already caused production restarts and lost turns.
- `impact:crash-loop`: The reported transient heap and RSS pressure caused two watchdog-driven Gateway restarts in one day.
- `impact:message-loss`: Gateway restarts during active work reportedly lost in-flight agent turns.

## Summary

Keep open: current main still relies on transcript-file freshness for durable usage-cache reuse, so actively appended transcripts remain an unresolved hot path. Recent work reduced cache size and bounded some concurrent loading, but does not establish incremental tail parsing or isolation from the Gateway process; this fresh report provides concrete latency, heap-pressure, restart, and lost-turn evidence.

## What This Changes

Fix `sessions.usage` so actively written append-only session transcripts do not require repeated full-file parsing that stalls and pressures the Gateway.

## Best Possible Solution

Use a canonical per-agent incremental aggregate—preferably in the agent SQLite store under repository storage policy—that records a verified transcript byte offset and running rollups, consumes only complete appended JSONL records, detects truncation or replacement, and keeps `sessions.usage` request work bounded without adding a new config or environment knob.
