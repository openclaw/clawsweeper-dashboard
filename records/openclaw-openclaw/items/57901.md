- `P2`: This is a normal-priority bug in a documented compaction model-routing config with limited blast radius and an open fix PR.
- `impact:session-state`: Safeguard compaction controls long-session summaries and context continuity, so using the wrong model can degrade session state.
- `impact:auth-provider`: The ignored override can prevent compaction from using the configured provider/model and associated auth path.

## Summary

Keep open: current main and the latest v2026.6.11 release still route safeguard LLM compaction through the active session model path, while an open linked PR is the candidate fix and should be reviewed or narrowed before this issue closes.

## What This Changes

Safeguard compaction should honor `agents.defaults.compaction.model` instead of using the active session model when the two differ.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/73704 or an equivalent focused fix that reuses the shared compaction target resolver for safeguard registration, prefers the resolved runtime model, and preserves regression coverage for no-override fallback and provider/auth changes.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: with safeguard compaction enabled and a configured `agents.defaults.compaction.model`, current main registers the session model in safeguard runtime and the hook prefers `ctx.model`. I did not run a live provider compaction session.

## Solution Assessment

Yes, the linked shared-resolver fix is the best owner-boundary direction because it resolves the compaction target before safeguard runtime registration and then lets the runtime model win in the hook. The issue should stay open until that PR or an equivalent focused fix merges.
