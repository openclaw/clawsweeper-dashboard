## Summary

Keep open: current main and the latest release still describe a single Gateway-owned control plane with embedded/local agent execution, and the open related PR is only a subagent placement contract slice. The issue remains a broad product, security, session-state, and message-delivery architecture decision rather than a cleanup close candidate.

## What This Changes

The issue requests splitting Gateway control-plane duties from per-agent compute/runtime processes, including local-split and distributed deployment modes with per-agent isolation, lifecycle, scaling, and secret boundaries.

## Best Possible Solution

Keep this as the canonical architecture RFC until maintainers choose a staged design that preserves embedded mode, formalizes runtime protocol/auth/secret/session contracts, and links narrower implementation issues or PRs to that plan.
