## Summary

Keep open: current main has model/runtime selection, embedded and CLI runtime seams, and Gateway restart/recovery primitives, but not the requested distributed control-plane/runtime split or per-agent compute lifecycle. The closest active work is a partial execution-backend placement slice, so this remains a product, security, session-state, and channel-delivery architecture decision rather than a cleanup-close candidate.

## What This Changes

The issue requests splitting the Gateway into a control plane and separately deployable per-agent runtimes with lifecycle commands, a runtime protocol, isolation, and deployment modes.

## Best Possible Solution

Keep this RFC as the design anchor until maintainers choose a phased contract, then land narrow slices only after the runtime protocol, worker identity, session ownership, upgrade path, and channel-delivery guarantees are explicit.
