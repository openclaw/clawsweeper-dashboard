## Summary

Keep open: current main and the latest release still implement one Gateway-owned control plane with embedded/local agent execution, while related work covers narrower worker-isolation, execution-placement, Kubernetes-auth, cron, or horizontal-scaling slices rather than the full control-plane/runtime split.

## What This Changes

The issue proposes splitting the Gateway control plane from per-agent compute runtimes, including per-agent lifecycle, protocol, deployment modes, isolation, and resource profiles.

## Best Possible Solution

Keep this as the canonical distributed-runtime RFC and require a maintainer-approved protocol, trust model, lifecycle semantics, session migration plan, and first milestone before implementation.
