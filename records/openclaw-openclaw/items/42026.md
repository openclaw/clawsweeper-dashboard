## Summary

Keep open: current main and the latest release still use a single Gateway-owned control plane with embedded/local agent execution, while the related open PRs are partial slices rather than a merged distributed runtime. This remains a broad product, security, session-state, and migration design item, with useful operator discussion from TinyTb and markthebest12 supporting the need for per-agent lifecycle work.

## What This Changes

The issue requests splitting `openclaw gateway` into a lightweight control plane and separate per-agent compute runtimes with local-split and distributed deployment modes.

## Best Possible Solution

Keep this as the broad canonical RFC, and split implementation only after maintainers choose the runtime protocol, trust model, lifecycle semantics, session migration strategy, and first milestone boundaries.

## Reproduction Assessment

Not applicable as a feature RFC. Source and docs inspection confirms the requested capability remains missing: current main and v2026.6.11 still use a single Gateway-owned runtime model and service-wide restart path.

## Solution Assessment

Unclear as a final implementation. The control-plane/runtime split is plausible and supported by operator evidence, but maintainers still need to choose the protocol boundary, trust model, lifecycle semantics, and how this relates to execution-placement and worker-isolation slices.
