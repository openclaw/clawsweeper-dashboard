## Summary

Keep open: current main and v2026.6.11 still document and implement a single Gateway-owned control plane with embedded/local agent execution, while related work only covers narrower worker-isolation, execution-placement, or Kubernetes-auth slices.

## What This Changes

The issue requests a distributed runtime architecture that separates Gateway control-plane responsibilities from per-agent compute runtimes with local-split and remote deployment modes.

## Best Possible Solution

Keep this as the canonical distributed-runtime RFC and require a maintainer-approved protocol, trust model, lifecycle semantics, session migration plan, and first milestone before implementation.
