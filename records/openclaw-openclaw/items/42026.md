## Label Justifications

- `P2`: This is a meaningful production architecture and reliability feature, but it is broad product/security design work rather than an urgent shipped regression or outage.
- `impact:security`: The requested split changes process isolation, worker trust, secret scoping, workspace access, and runtime authentication boundaries.
- `impact:message-loss`: The proposal explicitly targets avoiding dropped or interrupted channel connections and in-flight sessions during gateway restarts or per-agent failures.
- `impact:session-state`: The design would move ownership of session metadata, transcript state, runtime health, cancellation, and recovery across process or host boundaries.
- `maturity:stable`: The issue affects the M4 Stable Gateway runtime surface, including lifecycle, protocol, security, and control-plane behavior.

## Summary

Keep open: current main and v2026.6.11 still implement Gateway-owned embedded/local agent execution rather than a first-class split control plane plus per-agent runtime compute layer. Related work is useful but partial: https://github.com/openclaw/openclaw/issues/82017 and https://github.com/openclaw/openclaw/pull/84758 cover a subagent placement slice, while the broader runtime, secret, session, channel delivery, and lifecycle contract still needs maintainer product and security direction.

## What This Changes

The issue proposes splitting `openclaw gateway` into a lightweight control plane and separately deployable per-agent runtimes for isolation, scaling, and independent lifecycle management.

## Best Possible Solution

Keep this RFC as the broad architecture umbrella, then have maintainers approve a phased design that starts with a narrow protocol/lifecycle contract and explicitly links narrower execution-backend, K8s auth, cron HA, and per-agent lifecycle trackers.
