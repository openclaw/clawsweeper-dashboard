- `P2`: The RFC targets production reliability and isolation for larger deployments, but it is a broad architecture proposal rather than an urgent shipped regression.

- `impact:message-loss`: The issue cites Gateway restarts and channel drops interrupting in-flight messages and sessions.
- `maturity:stable`: The RFC affects Gateway runtime lifecycle, RPC, channel routing, and restart behavior, and `gateway-runtime` is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and v2026.6.11 still use embedded/local agent execution and whole-Gateway lifecycle surfaces, while the related worker/runtime-backend PRs are partial and unmerged. This remains a maintainer product and security-boundary decision, not a cleanup-close candidate.

## What This Changes

The issue requests a first-class split between a Gateway control plane and separately runnable per-agent compute runtimes.

## Best Possible Solution

Keep this RFC open as the broad architecture tracker, decide a narrow Phase 0/1 control-plane/runtime contract and security model, and treat related backend/worker PRs as partial review inputs rather than replacements.
