## Summary

Keep open: current main and v2026.6.11 still expose a single Gateway-centered runtime with embedded/ACP seams, not a per-agent runtime protocol. The related execution-backend PR is narrower and unmerged, and the worker-runtime experiment was closed, so this remains a product/security architecture decision rather than cleanup-close material.

## What This Changes

The issue proposes splitting OpenClaw Gateway into a control plane plus per-agent runtime processes with embedded, local-split, and distributed deployment modes.

## Best Possible Solution

Keep this issue as the architecture decision record, and let smaller implementation PRs land only after maintainers choose the protocol, security boundary, session ownership model, and backward-compatible rollout shape.
