- `impact:message-loss`: The motivation includes Gateway restarts dropping channel connections and interrupting in-flight user-visible work across agents.
- `maturity:stable`: The requested split affects the M4 Stable Gateway runtime surface, especially Gateway lifecycle, protocol, and control-plane responsibilities.

## Summary

Keep open: current main and v2026.6.11 still use a Gateway-owned control plane with embedded/local agent execution, while the related open PRs are partial slices rather than a merged distributed runtime. This remains a broad product, security, session-state, and migration design item with useful operator evidence in the discussion.

## What This Changes

The issue requests splitting the monolithic gateway into a control plane and separate per-agent runtime processes for independent lifecycle, isolation, scaling, and failure domains.

## Best Possible Solution

Keep this as the broad architecture RFC and split implementation only after maintainers choose the runtime protocol, trust model, lifecycle semantics, session migration strategy, and first milestone boundaries.
