## Label Justifications

- `P2`: The RFC describes meaningful production reliability, security, and scaling architecture work, but it is broad design work rather than an urgent confirmed regression.
- `impact:session-state`: Distributed per-agent runtimes would change session ownership, active-run tracking, transcript state, and recovery across process boundaries.
- `impact:security`: The request changes isolation, secret scoping, workspace access, worker trust, and network/tool execution boundaries.
- `impact:message-loss`: The Gateway/runtime split would affect channel routing, outbound delivery, in-flight sessions, and reconnection behavior during runtime restarts.
- `maturity:stable`: The issue touches Gateway runtime, scored M4 Stable in qa/maturity-scores.yaml, even though Agent Runtime itself is M3.

## Summary

Keep open: current main and v2026.6.11 still use a Gateway-owned control plane with embedded/process-local agent execution, while related worker/runtime-backend work is partial, unmerged, or intentionally closed rather than a replacement for this RFC.

## What This Changes

Request to split OpenClaw Gateway into a control plane and separate per-agent runtime processes, containers, or VMs with lifecycle, routing, health, and deployment modes.

## Best Possible Solution

Keep this as the broad distributed-runtime RFC and have maintainers choose the protocol, trust/auth, session ownership, lifecycle, migration, and first milestone before implementation.

## Risks / Open Questions

- A distributed runtime protocol introduces worker registration, authentication, authorization, revocation, replay, secret-scoping, network-exposure, and audit decisions.
