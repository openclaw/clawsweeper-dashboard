## Label Justifications

- `P2`: This is a meaningful production architecture and reliability feature, but it is not a confirmed urgent regression or emergency.
- `impact:session-state`: The proposal changes per-agent runtime ownership, in-flight session lifecycle, transcript storage, and recovery semantics.
- `impact:security`: The issue explicitly targets infrastructure-level agent isolation, per-agent secret scoping, process boundaries, and runtime trust.
- `impact:message-loss`: The motivation includes Gateway restarts dropping channel connections and interrupting user-visible work across agents.
- `maturity:stable`: The issue affects the M4 Stable Gateway runtime surface, especially Gateway lifecycle, protocol, security, and control-plane responsibilities.

## Summary

Keep open: current main and latest stable release still use Gateway-owned channel/control-plane ingress with embedded or local runtime execution, and the related open worker/placement work is partial rather than a merged distributed runtime.

## What This Changes

Request to split `openclaw gateway` into a lightweight control plane plus per-agent runtimes with protocol, lifecycle, deployment, scaling, and isolation support.

## Best Possible Solution

Keep this as the broad distributed-runtime design tracker, use #82017/#84758/#78164 as narrower slices, and define phased protocol, trust, lifecycle, and migration contracts before shipping worker or Kubernetes runners.

## Security Review

Status: needs_attention

Summary: The issue is security-sensitive because a distributed runtime protocol would create new worker trust, credential scoping, authorization, and network boundaries.

Concerns:

- **[high] Define distributed runtime trust boundaries:**
  - body: A per-agent runtime protocol needs explicit authentication, authorization, secret scoping, registration, revocation, replay resistance, and failure handling before replacing embedded runtime ownership.
  - confidence: 0.9
- **[medium] Preserve session and delivery integrity:**
  - body: Moving agent compute out of the Gateway can expose or mis-associate transcript, channel, and session state unless ownership, leases, terminal state, and retry semantics are designed first.
