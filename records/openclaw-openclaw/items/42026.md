- `impact:session-state`: The proposal changes per-agent runtime ownership, in-flight session lifecycle, transcript storage, and recovery semantics.

- `impact:message-loss`: The motivation includes Gateway restarts dropping channel connections and interrupting in-flight user-visible work across agents.

## Summary

Keep open: current main and v2026.6.11 still use a single Gateway-owned control plane with embedded/local agent execution, and the related open work covers narrower placement or isolation slices rather than replacing this distributed-runtime RFC.

## What This Changes

The issue requests a core architecture split between a lightweight Gateway control plane and separate per-agent runtime compute processes for lifecycle, isolation, scaling, and operability.

## Best Possible Solution

Keep this as the broad distributed-runtime RFC and require a maintainer-approved protocol, trust model, lifecycle, session migration, and first milestone before implementation.
