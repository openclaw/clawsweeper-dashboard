## Summary

Keep open: current main and v2026.6.11 still document and implement a single Gateway-owned control plane with embedded/local agent execution, while the related open PRs are partial slices rather than a merged distributed runtime. This remains a broad product, security, session-state, and migration design item with useful operator evidence in the discussion.

## What This Changes

Request to split the monolithic Gateway into a lightweight control plane and separate per-agent runtime processes or containers with protocol, lifecycle, scaling, and isolation support.

## Best Possible Solution

Keep this as the broad architecture RFC and split implementation only after maintainers choose the runtime protocol, trust model, lifecycle semantics, session migration strategy, and first milestone boundaries.
