## Summary

Keep open: current main and v2026.6.11 still describe one Gateway-owned control plane with embedded/local agent execution, while the related open execution-backend PR is only a partial subagent placement slice. This remains a broad product, security, session-state, and message-delivery architecture decision, not conservative cleanup.

## What This Changes

The issue proposes splitting Gateway control-plane duties from per-agent compute runtimes so agents can run in isolated processes, containers, VMs, or remote workers.

## Best Possible Solution

Keep this as the canonical architecture RFC until maintainers choose a staged design that preserves embedded mode and defines runtime protocol, auth, secret, session, delivery, config, and upgrade contracts.
