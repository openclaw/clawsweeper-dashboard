## Summary

Keep open: current main and v2026.6.11 still document and implement a Gateway-owned control plane with embedded/local agent execution, and the related open PRs are partial worker-placement or worker-isolation slices rather than a merged distributed runtime. The discussion adds useful operator evidence, but this remains a broad product, security, protocol, session-state, and migration design item.

## What This Changes

The issue requests splitting `openclaw gateway` into a lightweight control plane and separate per-agent runtime processes or workers for isolation, lifecycle, scaling, and fault-boundary reasons.

## Best Possible Solution

Keep this as the broad architecture RFC and split implementation only after maintainers choose the runtime protocol, trust model, lifecycle semantics, session migration strategy, and first milestone boundaries.
