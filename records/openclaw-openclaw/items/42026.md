## Summary

Keep open: current main and v2026.6.11 still implement and document a single Gateway-owned runtime with embedded agent execution, while the related runtime-placement and Kubernetes-auth work covers narrower slices rather than the full control-plane/per-agent-runtime split.

## What This Changes

The issue requests a distributed OpenClaw agent runtime that separates Gateway/control-plane duties from per-agent compute/runtime execution.

## Best Possible Solution

Keep this as the canonical distributed-runtime RFC and require a maintainer-approved local-split milestone covering protocol, trust, lifecycle, session ownership, channel delivery, and upgrade behavior before implementation.
