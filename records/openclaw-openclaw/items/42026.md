## Summary

Keep open: current `main` still documents and implements a single Gateway-centered runtime with embedded/ACP execution seams, while the closest distributed-runtime work is partial and unmerged. This remains a product, security, compatibility, and architecture decision rather than a cleanup-close candidate.

## What This Changes

The issue requests splitting OpenClaw into a lightweight Gateway control plane and separately deployable per-agent runtimes for isolation, scaling, and independent lifecycle management.

## Best Possible Solution

Keep this issue as the architecture decision record for distributed agent runtime, and let smaller implementation PRs land only after maintainers choose the protocol, security boundary, session ownership model, and backward-compatible rollout shape.
