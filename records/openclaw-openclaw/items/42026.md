## Summary

Keep open: current main and v2026.6.11 still use a Gateway-owned control plane with embedded/local agent execution, while the active related PRs are partial slices rather than a merged distributed runtime. This remains a broad product, security, session-state, and migration design item with useful operator evidence in the discussion.

## What This Changes

The issue requests splitting OpenClaw Gateway into a control-plane process and separate per-agent compute runtimes with local-split and distributed deployment modes.

## Best Possible Solution

Keep this as the broad architecture RFC and split implementation only after maintainers choose the runtime protocol, trust model, lifecycle semantics, session migration strategy, and first milestone boundaries.
