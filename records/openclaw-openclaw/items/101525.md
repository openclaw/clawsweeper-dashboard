## Summary

Keep this PR open for normal review and landing. Current main still dereferences `reaction.chat`, the branch now tests the real registered handler, and I found no blocking code or security findings; the caveat is that upstream Telegram/grammY types mark `chat` required, so this is defensive hardening rather than a live-proven malformed Telegram update.

## What This Changes

Adds an early return in the Telegram `message_reaction` handler when `ctx.messageReaction.chat` is missing and adds a registered-handler regression test for that path.

## Best Possible Solution

Land the narrow guard and registered-handler regression if maintainers accept the defensive payload shape; avoid broader Telegram parsing changes unless real malformed update evidence appears.
