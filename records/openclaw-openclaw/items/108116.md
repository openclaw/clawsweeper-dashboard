## Summary

The previous body-read timeout finding is fixed at the current head: the resolver now records when its deadline fires, aborts the fetch signal used through body consumption, and converts the resulting rejection to the existing miss/fallback path. Current `main` still has an unbounded `fetch` plus `res.blob()` promise, so this focused PR remains necessary and appears ready for ordinary maintainer review once required checks finish. citeturn19view1turn18search0turn18search2

## What This Changes

Adds a 30-second abort deadline and graceful miss fallback for managed outgoing-image preview fetches, with UI regression coverage and a real stalled-response proof harness.

## Best Possible Solution

Land the client-owned fetch deadline and fallback with the focused regression coverage after the branch is refreshed and required checks complete; a server-only timeout would not independently bound browser-side header or body stalls.
