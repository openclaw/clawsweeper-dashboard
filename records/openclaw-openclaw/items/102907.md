## Label Justifications

- `P2`: The issue describes a provider request-shaping bug that can break Azure model calls, but it has a limited provider-specific blast radius and a documented cache-disable workaround.
- `impact:auth-provider`: The affected behavior is provider/model request routing for Azure OpenAI Responses and can make a configured model endpoint fail with HTTP 400.

## Summary

Keep open: current main still sends `prompt_cache_key` by default on the Azure OpenAI Responses payload path, while existing policy and docs show this is an intentional native-route default that needs a maintainer choice before changing.

## What This Changes

The issue requests that Azure OpenAI Responses stop sending `prompt_cache_key` to Azure endpoints or deployments that reject that parameter with HTTP 400.

## Best Possible Solution

Decide the Azure Responses prompt-cache default, then implement the narrowest compat path with regression coverage and docs instead of globally removing prompt-cache hints from all native Azure routes.
