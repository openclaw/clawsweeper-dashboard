## Summary

Keep open: current `main` still sends `prompt_cache_key` on Azure OpenAI Responses requests when cache retention is not disabled, while current docs and tests intentionally treat Azure OpenAI as a native route that keeps prompt-cache hints. The report is plausible but lacks the exact Azure deployment, model, API version, and redacted 400 body needed to safely change the default.

## What This Changes

The issue reports that Azure OpenAI Responses can return HTTP 400 when OpenClaw sends `prompt_cache_key` to Azure endpoints that do not support that field.

## Best Possible Solution

Keep Azure prompt-cache behavior aligned with supported Azure docs, and add a narrow compat gate, diagnostic, or docs update only after a specific Azure route proves it rejects the field.
