## Summary

Keep open: current main and v2026.6.11 still allow the TUI session picker to show a transcript-derived title before displayName, and the transcript title extractor still returns gateway-injected inbound metadata text without using the existing inbound metadata sanitizer. The same-repo fix PR was closed as superseded, while the remaining fork PR is open but conflicting, so this issue still needs maintainer routing rather than cleanup close.

## What This Changes

The issue reports that TUI `/sessions` titles show gateway-injected `Sender (untrusted metadata)` text instead of useful display names or sanitized user text.

## Best Possible Solution

Land or adopt one narrow Gateway fix that strips inbound metadata during title extraction, threads the computed row displayName through both sync and async derived-title hydration, and leaves broader title-quality or column-width changes to separate follow-up work.
