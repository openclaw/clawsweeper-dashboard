## What This Changes

The issue asks for TUI session titles to strip gateway-injected inbound metadata and prefer the outer session display name before transcript-derived text.

## Best Possible Solution

Land or adopt one narrow Gateway fix that strips inbound metadata before title extraction and threads computed displayName through both sync and async derived-title hydration, with focused regression coverage and real Gateway/TUI proof.

## Reproduction Assessment

Yes, at source level: current main's TUI requests derived titles and prefers `derivedTitle`, while Gateway title extraction returns first-user text without using the inbound metadata sanitizer. I did not run a live TUI/Gateway scenario in this read-only review.

## Solution Assessment

Yes. The best fix is the narrow gateway/session-title boundary, not broad persisted-message stripping; the broad persistence PR was closed because it was lossy and did not fix this title path.
