## Summary

Keep open: current main and the latest release still derive TUI/session-list titles from the unstripped first user transcript message before falling back to the row display name, so gateway-injected inbound metadata can still become the visible title. The direct same-repo fix was closed unmerged and the remaining fork PR is open but conflicting, so this needs maintainer routing rather than cleanup close.

## What This Changes

The issue requests that TUI `/sessions` and `sessions_list` stop using gateway-injected inbound metadata as the session title and instead prefer explicit/display names or sanitized user text.

## Best Possible Solution

Fix the gateway session-title path so derived titles prefer explicit/display metadata and strip inbound metadata before using transcript text, with regression coverage for both sync/async `sessions_list` and the TUI picker fallback.
