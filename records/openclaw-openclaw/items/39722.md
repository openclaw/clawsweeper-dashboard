## Summary

Keep open: current main still lets Gateway/TUI session titles derive from unstripped first-user transcript text, and both sync and async session-list hydration still call `deriveSessionTitle(entry, fields.firstUserMessage)` without threading the computed row display name. The open fork PR is an implementation candidate, not a reason to close this issue before a fix lands.

## What This Changes

The issue reports that TUI session lists show gateway-injected inbound metadata as the session title instead of the outer display name or sanitized user text.

## Best Possible Solution

Keep this issue open until a narrow gateway title fix strips inbound metadata during title extraction and threads computed row display metadata through both sync and async derived-title hydration paths.

Yes, source-level reproduction is high-confidence: the TUI asks for derived titles and renders them first, while Gateway extracts raw first-user transcript text without the inbound metadata sanitizer. I did not run a live TUI/Gateway session in this read-only review.

## Solution Assessment
