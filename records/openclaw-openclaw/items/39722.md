## Summary

Keep open: current main still lets the TUI session picker prefer a derived title built from transcript text, and the title extractor still does not apply the inbound metadata sanitizer before returning the first user message. The same-repo direct fix was closed unmerged, and the remaining open fork PR is conflicting, so this needs maintainer routing instead of cleanup closure.

## What This Changes

The issue asks for TUI session lists to stop using gateway-injected inbound metadata as session titles and to prefer usable display names for gateway sessions.

## Best Possible Solution

Land or adopt one narrow Gateway fix that strips inbound metadata during title extraction and threads computed row displayName through both sync and async derived-title hydration, with focused regression coverage and real TUI/Gateway proof.
