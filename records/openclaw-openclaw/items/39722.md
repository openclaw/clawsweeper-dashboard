## Summary

Keep open: current main and the latest release still allow the TUI picker to prefer a transcript-derived title while the transcript title extractor does not strip gateway-injected inbound metadata, and the remaining direct fix path is an open but conflicting fork PR rather than merged code.

## What This Changes

The issue reports that TUI `/sessions` can show gateway-injected `Sender (untrusted metadata)` text as the session title instead of a display name or sanitized user message.

## Best Possible Solution

Land or adopt one narrow Gateway fix that strips inbound metadata during title extraction and threads computed row displayName through both sync and async derived-title hydration, with focused regression coverage and real TUI/Gateway proof.

## Reproduction Assessment

Yes, at source level: current main extracts first-user-message text without the inbound metadata sanitizer, then the TUI picker renders `derivedTitle` before `displayName`. I did not run a live TUI/Gateway scenario in this read-only review.

## Solution Assessment

Yes, the narrow Gateway/session-title boundary is the best fix shape; broad persisted-message sanitization was explicitly closed as the wrong layer, while broader title-quality work belongs to separate product decisions.
