## Summary

Keep open: current main still derives Gateway/TUI session titles from raw first-user transcript text without stripping inbound metadata, and the computed row display name still is not passed into either title-hydration path. The open fork PR is an implementation candidate, not a reason to close the issue before a fix lands.

## What This Changes

The issue reports TUI `/sessions` showing gateway-injected inbound metadata as session titles because derived titles use raw transcript text and miss computed session display names.

## Best Possible Solution

Land or reject an up-to-date fix that strips inbound metadata before title derivation and threads clean computed display metadata through both Gateway session-list hydration paths.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: the TUI asks for derived titles and prefers them, while Gateway title extraction returns raw first-user transcript text without the inbound metadata sanitizer. I did not run a live TUI/Gateway session in this read-only review.

## Solution Assessment

Yes, the best fix is the narrow Gateway title display path: strip inbound metadata during title extraction and pass the already-computed display metadata into title derivation. Rewriting persisted user messages was separately rejected as the wrong boundary.
