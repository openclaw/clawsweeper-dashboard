## Summary

Keep open: current main and v2026.6.11 still let the TUI session picker prefer a transcript-derived title whose extractor does not strip injected inbound metadata, while the computed row displayName is not threaded into the Gateway-derived title path. The direct same-repo fix PR is closed unmerged and an open fork PR is conflicting, so maintainers need to choose the branch path before another fix is queued.

## What This Changes

The issue reports that TUI `/sessions` displays gateway-injected untrusted metadata as session titles because derived titles use unstripped first-user transcript text and ignore the computed row displayName.

## Best Possible Solution

Land or adopt one narrow Gateway fix that strips inbound metadata during title extraction and threads computed row displayName through both sync and async derived-title hydration, with focused regression coverage and real TUI/Gateway proof.
