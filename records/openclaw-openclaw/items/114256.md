## Summary

Keep this PR open for maintainer review rather than closing it: it has a concrete P1 runtime-admission defect, and the protected `maintainer` label requires explicit human handling. Both newly added guards decide Bun support through `process.getBuiltinModule`, but Bun’s current Node-process reference documents that API as unimplemented; a Bun build can therefore provide `node:sqlite` yet still be rejected before OpenClaw starts.

## What This Changes

This PR permits Bun runtimes that provide `node:sqlite`, removes execa’s buffered-output encoding under Bun to avoid a spawn failure, and updates Bun installation documentation.

## System Context

OpenClaw’s launcher and runtime guard run before the CLI or Gateway loads the application, rejecting runtimes that do not meet the SQLite requirement. The shared process-execution boundary then starts child commands for features such as Doctor, so its output contract affects command results throughout the product.

## Architecture Diagram

flowchart LR

  Launcher --> Admission[Runtime capability check]
  Admission -->|accepted| CLI[CLI and Gateway startup]
  Admission -->|rejected| Error[Startup guidance]
  CLI --> Process[Child-process boundary]
  Process --> Commands[Doctor and other commands]
  Commands --> Output[Normalized command output]

## Best Possible Solution

Define one verified Bun capability contract that tests the actual runtime’s ability to load and use `node:sqlite`, apply that same contract in both startup guards, and prove text and binary child-process behavior on the exact supported Bun build before documenting experimental support.
