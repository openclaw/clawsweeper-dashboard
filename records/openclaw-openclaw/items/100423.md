## Summary

Keep open: current main still reports only the configured sandbox `workspaceRoot` in `sandbox explain`, while the runtime uses the agent workspace as the effective `/workspace` host root for `workspaceAccess: rw`.

## What This Changes

The issue requests that `openclaw sandbox explain --agent` report or clarify the real host workspace mount when an agent uses `workspaceAccess: rw`.

## Best Possible Solution

Teach `sandbox explain` to distinguish the configured sandbox workspace root from the effective workspace or mount table, reusing existing sandbox status and mount helpers while preserving current runtime behavior.
