## Summary

Keep open: this is a focused candidate fix for a real voice-call status bug, but the patch is not merge-ready because the new fallback only scans the newest 100 history snapshots and the external PR proof is unit-test-only.

## What This Changes

This PR adds a voice-call status fallback that checks persisted call history after active manager misses and adds tool get_status regression tests for newest-snapshot selection.

## Best Possible Solution

Use a status-only persisted lookup that searches retained records newest-first by callId or providerCallId, add regression coverage for older retained records and all status surfaces, require redacted real status proof, and track transcript retrieval as a separate maintainer/API decision if needed.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: finalize or restart past a call so it is persisted and removed from active maps, then query status by call id while only active lookups are used on current main. I did not run a live carrier call in this read-only review.

## Solution Assessment

No. The status-only fallback is the right layer, but the implementation should search the retained persisted store newest-first instead of only the newest 100 history snapshots; transcript retrieval should be a separate explicit surface if maintainers want it.
