## Summary

Keep open: the PR targets a real source-reproducible voice-call status bug, but the new fallback only searches the newest 100 history rows even though the retained store can hold more, so direct status lookup can still report a persisted completed call as missing. It also still needs after-fix real behavior proof from a redacted runtime or live status flow before merge.

## What This Changes

The PR changes the voice-call gateway, tool, and legacy status lookups to fall back from active in-memory calls to persisted call history, with regression tests for newest-snapshot selection and missing records.

## Best Possible Solution

Use a status-specific persisted lookup that resolves the newest retained call snapshot by call id or provider call id across the retained store, keep it status-only, and require redacted runtime/live proof before merge.

## Reproduction Assessment

Yes from source inspection: current main persists terminal call records and removes them from active indexes, while the status paths only query active manager lookups before returning found:false. I did not run a live telephony flow in this read-only review.

## Solution Assessment

No. The status-only fallback is the right layer and the PR handles newest-snapshot ordering within the returned history, but direct id lookup should search the retained persisted store instead of only the newest 100 history rows.
