## Summary

Keep open: the PR is aimed at the right voice-call status surfaces, but it still resolves persisted calls by scanning only recent history and still lacks real after-fix behavior proof from an evicted or restarted completed-call lookup.

## What This Changes

The PR adds persisted-history fallback for voice-call gateway, tool, legacy, and CLI status lookups when completed calls are no longer in memory.

## Best Possible Solution

Use one shared status-only persisted lookup that searches retained records by callId or providerCallId across gateway, tool, legacy, and CLI status readers, while keeping manager getCall methods active-only and treating transcript retrieval as a separate follow-up if maintainers want that API.
