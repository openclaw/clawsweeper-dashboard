## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P2] Preserve all media receipt ids:** `extensions/discord/src/send.outbound.ts:414-415`
  - body: This aggregation pushes only `lastMediaResult.id` for each batch, but `sendDiscordMedia` can return multiple `platformMessageIds` when a media caption spills into follow-up text messages. Replacing the helper's receipt list with only batch ids drops those follow-up ids from durable delivery metadata; append each result's `platformMessageIds` instead of only `.id`.
  - confidence: 0.91
- **[P2] Aggregate payload batch receipts before returning:** `extensions/discord/src/outbound-payload.ts:143`
  - body: `sendDiscordMediaBatch` overwrites `lastResult` for every overflow batch and returns only the final send. A payload with more than ten `mediaUrls` can emit multiple Discord messages but expose receipt metadata for only the last batch, so durable delivery loses the earlier batch ids; collect and return a combined receipt/result for all batches.
  - confidence: 0.92
- **[P2] Keep overflow follow-ups out of reply threads:** `extensions/discord/src/outbound-payload.ts:104`
  - body: The non-first single-file overflow branch calls `resolveDiscordMediaDeliveryOptions`, which resolves `replyTo` again. With an explicit or non-single-use reply target, an 11th attachment follow-up can be posted as a reply even though the PR contract and the other batch branches keep reply references on the first batch only; pass media options without resolving `replyTo` for non-first batches.
  - confidence: 0.84
- **[P3] Remove the lint-blocking else branch:** `extensions/discord/src/send.outbound.ts:343`
  - body: CI is failing `eslint(no-else-return)` on this `else` after the preceding branch returns. This is a narrow changed-file blocker; drop the `else` and keep the existing text-send body after the media branch returns.
  - confidence: 0.95
