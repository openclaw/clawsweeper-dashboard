  - body: `sendDiscordComponentMessage` now throws on `mediaUrls.length > 1` before checking whether the component spec downgrades to a classic message. The new classic-mode test on this PR passes two `mediaUrls`, so this guard prevents the path the test expects to forward to `sendMessageDiscord`.
  - confidence: 0.9
- **[P2] Batch plain mediaUrls before fallback:** `extensions/discord/src/outbound-payload.ts:178-186`
  - body: The new batch helper only runs inside the native components/embeds/filename branch. A normal payload with text plus `mediaUrls` and no Discord-specific channelData still returns through `sendTextMediaPayload`, which sends each URL through scalar `sendMedia`, so the common case for the linked feature remains unimplemented.
  - confidence: 0.92
- **[P2] Forward mediaUrls from Discord action entrypoints:** `extensions/discord/src/send.outbound.ts:41`
  - body: Adding `mediaUrls` to the low-level send options does not make the public Discord `send` or `sendMessage` actions accept it. Those action handlers still read only `mediaUrl`/`media`/`path`/`filePath`, so callers using `mediaUrls` through the action surface will not reach this new code.
  - confidence: 0.88
- **[P2] Retry each overflow batch independently:** `extensions/discord/src/outbound-payload.ts:100-113`
  - body: `sendDiscordMediaBatch` wraps one `sendMessageDiscord` call in the high-level retry helper, but `sendMessageDiscord` can post multiple batches for more than ten files. If a later batch hits a retryable error after the first batch succeeded, the outer retry can repost the earlier attachments and duplicate delivery.
  - confidence: 0.86
