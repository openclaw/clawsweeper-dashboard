## Summary

Keep open: the Discord multi-attachment feature is useful and still not on main, but the current head still breaks implicit first-mode reply semantics when a video batch is split into caption and media sends.

## What This Changes

The PR adds Discord `mediaUrls` support across action, runtime, payload, send, component, docs, and tests, batching up to 10 files per Discord message and splitting overflow.

## Best Possible Solution

Keep the Discord-owned multi-attachment batching path, but gate the media-only video leg's reply like the existing single-video split and update the focused regression to assert `reply` semantics.
