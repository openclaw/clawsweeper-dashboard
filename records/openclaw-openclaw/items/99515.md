## What This Changes

This PR adds a `mediaUrls` option to `sendMessageDiscord`/`sendDiscordMedia`, tests direct multi-file batching, and commits a live Discord proof script.

## Best Possible Solution

Land a Discord-owned batching implementation that preserves `mediaUrls` from action/outbound payloads through REST upload, splits overflow safely, preserves reply/chunk/component/media access behavior, and keeps live proof out of the source tree.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 route Discord uploads through scalar `mediaUrl` helpers and one-file REST bodies. I did not run a live Discord bot round trip in this read-only review.

## Solution Assessment

No: this PR is a plausible low-level slice, but it is not the best fix because it does not wire `mediaUrls` through the public action/outbound paths where the issue occurs. The maintainable fix is a Discord-owned batch path that starts at the real user-facing inputs and proves grouped delivery.
