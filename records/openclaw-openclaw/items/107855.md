## Summary

Current main still derives the Simple Channels card’s connection state from configuration presence rather than live status, so the reported bug remains valid. The issue should stay open while its linked closing PR is reviewed and either landed or closed.

**Likely related people**
- `arkyu2077` — high confidence; authored the linked candidate fix for this exact behavior.

## What This Changes

Make the Control UI Simple Channels card distinguish configured channels from channels that are actually connected according to the live Gateway status snapshot.

## Best Possible Solution

Use the live channels-status snapshot as the authoritative connection state, retain a distinct configured-but-not-connected presentation, and cover connected, disconnected, degraded, error, and missing-snapshot behavior without adding another configuration surface.

## Reproduction Assessment

Yes at source level: current main deterministically maps every non-empty channel configuration to `connected: true`, and the card counts and styles that value as connected. A live browser reproduction was not run during this read-only review.

## Solution Assessment

Yes in direction: consuming the existing live channels snapshot and separating “Configured” from “Connected” is the narrowest maintainable repair. The linked PR still needs current-base review and real UI proof before merge.
