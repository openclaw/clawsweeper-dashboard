## Summary

Keep open: current main and v2026.6.11 still document plaintext-compatible credential storage with opt-in SecretRefs, while active config and auth-profile persistence do not provide a native encrypted-at-rest credential model.

## What This Changes

The issue requests encrypted-at-rest storage for credentials and sensitive OpenClaw configuration, using a keychain or master-password style model while preserving compatibility.

## Best Possible Solution

Adopt a maintainer/security-approved credential-at-rest design covering openclaw.json, config backups, SQLite auth-profile storage, doctor migration, key management, recovery, and rotation while keeping SecretRefs as a supported mitigation.
