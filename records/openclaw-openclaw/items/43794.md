## Summary

Keep open: current main still supports plaintext credential persistence, while SecretRefs and process-local sentinels are opt-in mitigations rather than native encrypted-at-rest storage. Related PRs either closed unmerged, moved optional resolver work to ClawHub, or only improved runtime egress handling, so the central security design remains unresolved.

## What This Changes

The issue requests encrypted-at-rest handling for sensitive OpenClaw credentials in local config and auth stores, with keychain or master-password decryption and backward-compatible migration.

## Best Possible Solution

Adopt a maintainer/security-approved credential-at-rest design covering openclaw.json, the per-agent SQLite auth store, backups and legacy files, SecretRefs, doctor migration, recovery, rotation, and unattended startup.
