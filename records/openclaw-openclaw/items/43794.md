## Summary

Keep open: current main and v2026.6.11 still support plaintext credential persistence, while SecretRefs and process-local sentinels are opt-in mitigations rather than native encrypted-at-rest storage. The related resolver/sealing PRs are closed unmerged or partial, so the central security design remains unresolved.

## What This Changes

The issue requests encrypted-at-rest storage for OpenClaw credentials, API keys, and tokens, preferably via OS keychain or master-password backed migration.

## Best Possible Solution

Adopt a maintainer/security-approved credential-at-rest design covering openclaw.json, the per-agent auth database, backups and legacy files, SecretRefs, doctor migration, recovery, rotation, and unattended startup.
