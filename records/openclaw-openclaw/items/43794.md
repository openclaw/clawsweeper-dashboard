## Summary

Keep open: current main and v2026.6.11 still only provide file permissions plus opt-in SecretRefs, while config and auth persistence can still store plaintext credential material; the remaining work needs maintainer security/product design.

## What This Changes

Request native encrypted-at-rest storage for sensitive OpenClaw credentials, including config tokens/API keys and migration-compatible keychain or master-password handling.

## Best Possible Solution

Adopt a secops-approved credential-at-rest design covering openclaw.json, config backups, SQLite auth-profile storage, doctor migration, key management, recovery, and rotation while keeping SecretRefs and ClawHub resolver packages as supported mitigations.
