## Summary

Keep open: current main and the latest release still leave native encrypted-at-rest credential storage unresolved; SecretRefs and file permissions mitigate exposure but do not implement the requested keychain or master-password-backed encryption path.

## What This Changes

The issue asks OpenClaw to encrypt tokens and API keys stored at rest in config/auth files using keychain or master-password-backed decryption with backward-compatible migration.

## Best Possible Solution

Adopt a security-approved credential-at-rest design that covers openclaw.json, auth-profile SQLite storage, plaintext residue/backups, doctor migration, key management, recovery, unattended service startup, and rotation while keeping SecretRefs as a supported mitigation.
