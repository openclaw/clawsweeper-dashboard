## Summary

Keep open: current main and v2026.6.11 still support plaintext credential storage, with SecretRefs as an opt-in mitigation rather than native encrypted-at-rest credential storage; the remaining work needs maintainer security/product design.

## What This Changes

The issue requests native encrypted-at-rest storage or keychain-backed migration for credentials currently stored in OpenClaw config and auth-profile files.

## Best Possible Solution

Adopt a maintainer/security-approved credential-at-rest design that covers openclaw.json, config backups, SQLite auth-profile storage, doctor migration, key management, recovery, and rotation while keeping SecretRefs as a supported mitigation.
