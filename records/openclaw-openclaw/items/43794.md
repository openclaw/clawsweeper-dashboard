## Summary

Keep open: current main has opt-in SecretRefs, audit/apply scrubbing, process-local sentinels, and permission guidance, but it still allows plaintext credential persistence and does not provide native encrypted-at-rest config/auth credential storage. The directly related implementation attempts were closed unmerged or routed to ClawHub, while the closed duplicate points back to this issue as the canonical tracker.

## What This Changes

Request native encrypted-at-rest storage for config and auth credentials, using keychain or master-password decryption with backward-compatible migration.

## Best Possible Solution

Design a security-owned credential-at-rest plan for the current SQLite/auth/config/SecretRef/doctor boundary, with explicit key management, migration, recovery, rotation, audit proof, and no plaintext downgrade path.
