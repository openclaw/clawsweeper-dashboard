## Summary

Keep open: current main and v2026.6.11 still support plaintext credential storage, while SecretRefs are opt-in mitigation and the open auth-store sealing PR is only a partial, security-sensitive candidate.

## What This Changes

Request encrypted-at-rest storage for sensitive OpenClaw credentials in config/auth files, backed by system keychain or master-password style key management with backward-compatible migration.

## Best Possible Solution

Land a maintainer/security-approved credential-at-rest design that covers openclaw.json, the active SQLite auth-profile store, migration/doctor repair, key management, recovery, and rotation while keeping SecretRefs as a supported mitigation.

## Reproduction Assessment

Yes, as a source-level missing-capability check. Current source and docs show plaintext storage remains supported, SecretRefs are opt-in, and active auth-profile payloads are persisted as JSON in SQLite rather than encrypted envelopes.

## Solution Assessment

Unclear. The request targets a real security gap, but maintainers still need to choose the key-management model, migration path, recovery behavior, and rotation guarantees before implementation.
