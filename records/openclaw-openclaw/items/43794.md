## Summary

Keep open: current main and v2026.6.11 still support plaintext credential storage with SecretRefs as an opt-in mitigation, while the remaining encrypted-at-rest design is security- and compatibility-sensitive.

## What This Changes

Request encrypted-at-rest storage for OpenClaw credentials in config/auth files, preferably through OS keychain or master-password backed migration.

## Best Possible Solution

Define a maintainer-approved encrypted-at-rest credential strategy covering key management, doctor migration, recovery, rotation, SecretRef compatibility, and regression proof before landing code.
