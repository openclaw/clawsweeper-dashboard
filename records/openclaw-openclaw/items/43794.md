## Summary

Keep open: current main and v2026.6.11 still support plaintext-compatible config and auth-profile persistence, while SecretRefs are opt-in mitigation rather than the requested encrypted-at-rest credential model.

## What This Changes

Request encrypted-at-rest storage and migration for OpenClaw credentials in config, gateway/channel secrets, and provider auth stores using keychain or master-password style protection.

## Best Possible Solution

Adopt a security-approved credential-at-rest design covering openclaw.json, backups, SQLite auth profiles, doctor migration, key custody, recovery, and rotation while keeping SecretRefs as a supported mitigation.
