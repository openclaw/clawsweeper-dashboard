## Summary

Keep open: current main and v2026.6.11 still allow plaintext credential storage, with SecretRefs as an opt-in mitigation rather than native encrypted-at-rest storage, and the remaining work needs maintainer security/product design.

## What This Changes

The issue requests encrypted-at-rest handling for stored credentials in OpenClaw configuration and auth profile files.

## Best Possible Solution

Adopt a maintainer/security-approved credential-at-rest design that covers openclaw.json, config backups, SQLite auth-profile storage, doctor migration, key management, recovery, and rotation while keeping SecretRefs as a supported mitigation.

- **Land partial auth-store sealing first:** Use the open auth-store sealing work as a stepping stone while keeping this issue open for openclaw.json, backups, active SQLite storage, and key-management coverage.
