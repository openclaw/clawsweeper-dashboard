## Summary

Keep open: current main and v2026.6.11 still support plaintext credential storage, with SecretRefs as an opt-in mitigation rather than native encrypted-at-rest credential storage, and the remaining work needs maintainer security/product design.

## What This Changes

The issue requests encrypted-at-rest handling for sensitive OpenClaw credentials currently stored in config and auth persistence.

## Best Possible Solution

Adopt a maintainer/security-approved credential-at-rest design that covers openclaw.json, config backups, SQLite auth-profile storage, doctor migration, key management, recovery, and rotation while keeping SecretRefs as a supported mitigation.
