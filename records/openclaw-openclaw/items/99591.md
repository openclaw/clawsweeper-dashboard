## Summary

## What This Changes

The PR allows Android's invoke error parser to treat digits as valid code-prefix characters and adds a regression test for `A2UI_HOST_UNAVAILABLE`.

## Best Possible Solution

Land this narrow parser/test fix after the PR is ready for review and includes redacted real Android/gateway invoke evidence showing a digit-containing code stays specific instead of becoming `UNAVAILABLE`.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: current main rejects `A2UI_HOST_UNAVAILABLE: ...` because the parser predicate disallows digits while Android emits that exact code. I did not run tests because this review is read-only.

## Solution Assessment

Yes, this is the narrowest maintainable fix: preserve the existing parser shape, allow digits in canonical code prefixes, and cover the affected A2UI code. Changing producers would duplicate policy and still leave other digit-containing codes vulnerable.
