## Summary

This item remains necessary because current main lacks a hard recovery boundary for a process-scoped guarded Telegram lane. The branch has sufficient real-process proof and no remaining concrete correctness defect, but its cross-plugin lifecycle contract requires explicit owner direction before merge.

## What This Changes

The PR detects persistently wedged Telegram spool handlers, exposes a channel snapshot restart-required signal, and routes it through supervised gateway replacement with a persisted rolling restart budget.

## Best Possible Solution

Approve the generic snapshot contract only if channels are intentionally allowed to request bounded supervised gateway replacement; if approved, retain the current hard-boundary design and document its plugin lifecycle semantics, otherwise move the signal to a narrow Telegram-owned injected seam without weakening the lane guard.
