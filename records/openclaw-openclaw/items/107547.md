## What This Changes

The PR detects Telegram spool handlers that remain wedged after abort, publishes a restart-required health signal, schedules a supervised gateway process restart, and persists the per-account escalation budget in SQLite.

## Best Possible Solution

Use a hard process boundary that never releases a still-running lane handler, with restart-surviving per-account limits; retain the generic snapshot field only if the channel lifecycle owner explicitly accepts it as the permanent cross-channel contract.
