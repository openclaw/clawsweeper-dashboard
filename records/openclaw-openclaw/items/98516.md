## Summary

Keep open: this is a protected maintainer-labeled sandbox lifecycle feature/config request, and current main has sandbox scopes, prune/recreate, registry state, and session reset/delete cleanup for other runtimes, but not the requested opt-in owner-scoped sandbox runtime/workspace cleanup contract.

## What This Changes

The issue requests an opt-in managed lifecycle that reuses session-owned ephemeral sandboxes during an owner lifetime and cleans their runtime, browser, registry, and non-shared workspace state on reset/delete or terminal child-session cleanup.

## Best Possible Solution

Keep this open for maintainer design, then implement a default-off sandbox lifecycle option that reuses existing registry/recreate/removal primitives and adds focused reset/delete/terminal-child cleanup coverage for runtimes, browser runtimes, registry entries, and non-shared workspaces.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature request for a lifecycle contract. Source inspection confirms current main has the underlying sandbox/session primitives but no requested opt-in owner cleanup setting or hook.

## Solution Assessment

Yes on direction, but not automation-ready as-is. The maintainable path is to add a narrow default-off lifecycle on top of existing sandbox registry/removal primitives, with maintainer sign-off on config, safety, and upgrade behavior.
