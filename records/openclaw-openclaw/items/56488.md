## Summary

Keep open: current main and v2026.6.11 still match the source-level failure shape, and the closest main-repo fix is still the open PR at https://github.com/openclaw/openclaw/pull/81572 rather than a merged implementation.

## What This Changes

The issue reports successful one-shot `kind: "at"` cron jobs with `deleteAfterRun: true` remaining runnable and repeatedly spawning isolated sessions instead of being deleted.

## Best Possible Solution

Review, rebase, and land https://github.com/openclaw/openclaw/pull/81572 or replace it with a narrow scheduler fix that promptly finalizes successful one-shot outcomes and prevents terminal `at` jobs left in the store from being selected again.

## Reproduction Assessment

Yes, at source level. The normal timer path still omits the terminal one-shot guard and ordinary successful outcomes are applied only after the due-job worker batch drains; no live repro was run in this read-only review.
