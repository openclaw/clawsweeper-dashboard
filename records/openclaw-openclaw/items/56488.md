## What This Changes

The issue asks for successful one-shot `kind: "at"` cron jobs with `deleteAfterRun: true` to be removed after the first scheduled run instead of retriggering from a past `nextRunAtMs`.

## Best Possible Solution

Land or replace a focused scheduler fix that finalizes successful one-shot outcomes promptly and prevents terminal `at` jobs left in the store from being selected again by the normal timer path, with regression coverage for the reported `deleteAfterRun` success case.
