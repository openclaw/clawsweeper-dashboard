## Summary

Keep this PR open: the prior P1 blocker remains on the unchanged reviewed head because durable wakes are queued as generation-unfenced `systemEvent` entries, allowing an old wake to cross a session reset and reach the replacement session; the broader durable-runtime direction also still needs explicit sponsorship.

## What This Changes

The cumulative branch adds an opt-in durable runtime, persisted coordination and inspection surfaces, and a final startup handoff that queues resolved wakes into an owning session’s internal delivery queue.

## Best Possible Solution

Sponsor the durable-runtime direction explicitly, then bind each resolved wake to the authoritative session generation and reject or supersede delivery when that generation changes, with focused enqueue-reset-recovery tests and fresh-install/upgrade proof before landing the stack in order.
