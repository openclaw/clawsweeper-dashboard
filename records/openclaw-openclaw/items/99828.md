## Summary

Keep open. The linked Slack parser bug is real and the PR is in the right plugin boundary, but the patch flips all multi-colon directives to last-colon parsing, which can break existing callback values that contain colons, and the external PR still has only test-output proof rather than real behavior proof.

## What This Changes

The PR changes Slack interactive reply choice parsing and adds regression tests so button labels containing time-style colons keep the full label while using the trailing segment as the value.

## Best Possible Solution

Make the multi-colon directive grammar explicit before merge: either preserve existing colon-containing callback values while supporting time labels, or get maintainer approval and tests/docs for intentionally moving legacy directives to last-colon semantics.

## Reproduction Assessment

Yes, from source inspection: current main splits a button choice at the first colon, so a label containing `9:00` becomes truncated and the value starts with the minutes. I did not execute the package path because this review is read-only.

## Solution Assessment

No as written. The last-colon split fixes the reported time-label case, but it also changes existing colon-containing callback values, so the best fix needs compatibility coverage or an explicit maintainer-approved grammar change.
