## Summary

Keep open. The PR targets a real Slack directive parser bug, but the global last-colon split can corrupt existing callback values that contain colons, and the contributor proof is only a unit-test run rather than real Slack/package behavior proof.

## What This Changes

This PR changes Slack legacy interactive reply parsing to strip optional style suffixes first and split remaining button/select choice text at the last colon, with regression tests for time labels and single-colon entries.

## Best Possible Solution

Land a Slack parser fix that preserves existing colon-containing callback values while fixing time-style label colons, with regression tests and redacted Slack or packaged-runtime proof.

## Reproduction Assessment

Yes from source inspection: current main uses the first colon as the delimiter, so `9:00` in a label shifts `00:` into the callback value. I did not execute a current-main failing test because this review is read-only.

## Solution Assessment

No. The patch fixes the timestamp-label case, but a global last-colon split is not the safest solution because it can corrupt existing colon-containing callback values unless maintainers explicitly change the legacy grammar.

- **[P1] Preserve values that already contain colons:** `extensions/slack/src/interactive-replies.ts:54`
  - body: The shipped parser treats everything after the first `:` as the value, so `[[slack_buttons: Open:https://example.com]]` currently produces label `Open` and value `https://example.com`. Splitting at the last colon turns that into label `Open:https` and value `//example.com`, corrupting existing callbacks while fixing time labels. Please add coverage and a parser rule or explicit maintainer-approved contract that does not silently break colon-containing values.
