## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.99

Full review comments:

- **[P1] Do not relabel unsupported image bytes as PNG:** `packages/ai/src/utils/mime-type.ts:23`
  - body: Returning `image/png` for every unknown MIME value changes only the metadata; `item.data` and `part.data` remain the original bytes. A BMP, SVG, TIFF, corrupt payload, or omitted MIME therefore becomes a data URL that claims PNG but is not PNG, so the provider can still reject it or interpret it incorrectly. Reject the content with a clear error, preserve the original value where the adapter permits it, or actually transcode the bytes before changing the MIME type.
  - confidence: 0.99
- **[P1] Preserve Google-supported HEIC and HEIF inputs:** `packages/ai/src/utils/mime-type.ts:9-14`
  - body: This shared allowlist is also applied to Google, but Gemini supports `image/heic` and `image/heif`; both are converted to a false `image/png` label here. Make validation provider-specific and cover Google-supported formats in conversion tests so existing phone-photo inputs continue to work. The Google contract also does not make this four-type set a safe universal intersection.
  - confidence: 0.99
