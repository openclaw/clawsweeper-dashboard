## Summary

Keep this PR open, but do not merge it yet: it correctly centralizes the five-minute claim-reclaimability rule, but the dispatcher still counts a reclaimable card as busy whenever its status or execution remains `running`. That leaves the reported cross-board starvation in place for the common abandoned-running-card path; the submitted regression only covers a `review` card.

## What This Changes

The PR reuses Workboard’s claim-expiry grace rule in dispatcher owner-capacity accounting and adds a cross-board test for a reclaimable claimed review card.

## System Context

The bundled Workboard plugin persists cards and temporary worker claims in SQLite, then its dispatcher selects ready cards for subagent runs. Dispatch is globally limited per owner across boards, while stale-claim cleanup is board-scoped, so both paths need the same definition of an active claim.

## Architecture Diagram

flowchart LR
  Cards[Persisted Workboard cards] --> Dispatch[Board dispatch request]
  Dispatch --> Cleanup[Selected-board stale-claim cleanup]
  Cards --> Capacity[Global owner-capacity accounting]
  Claims[Claim expiry and grace period] --> Cleanup
  Claims --> Capacity
  Capacity --> Selection[Ready-card selection]
  Selection --> Runs[Subagent worker runs]

## Best Possible Solution

Make the owner-capacity predicate account for a reclaimable claim before treating the card’s running status or execution as active capacity, while preserving capacity for genuinely live running or review work; add focused coverage for a stale foreign-board running card and a live-running control case.
