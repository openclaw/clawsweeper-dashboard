## Summary

This PR remains necessary but is not ready to merge: the new page-share sink is registered only by the eager browser plugin service, while the default lazy Gateway path can create a relay without registering that sink, making ordinary page shares return the gateway-required error. The earlier selection-privacy finding appears addressed; the remaining blocker is the default lifecycle path.

Likely related people: `steipete` is the recent contributor across the page-share implementation commits, with low-confidence ownership routing pending broader merged-history attribution.

## What This Changes

The branch adds popup, context-menu, and keyboard-shortcut sharing of selected or extracted Chrome page content to the main OpenClaw session through the extension relay.

## Best Possible Solution

Register and clear the page-share sink at the default lazy Gateway service boundary, then prove popup, shortcut, and context-menu delivery on a default configuration as well as the intentional node-hosted rejection.
