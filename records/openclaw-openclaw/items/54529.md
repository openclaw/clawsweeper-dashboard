## Summary

Keep open. Current main has improved Telegram polling with isolated ingress and Bot API root normalization, but the central local Bot API migration problem is not fully solved: polling offsets are still keyed by account/token rather than endpoint, and startup still treats non-network `deleteWebhook` failures such as `400: Logged out` as fatal.

## What This Changes

The issue reports that Telegram self-hosted Bot API `apiRoot` polling can receive raw updates but drop inbound dispatch, reuse incompatible update offsets, and crash-loop on `deleteWebhook` during migration.

## Best Possible Solution

Keep this as the canonical local Bot API migration tracker; implement endpoint-aware offset/reset handling and a narrow logged-out cleanup rule, then prove inbound dispatch and outbound reply delivery against a live local Bot API server.
