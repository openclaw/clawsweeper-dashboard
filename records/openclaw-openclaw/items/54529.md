## Summary

Keep open. Current main and the latest release still key Telegram polling offsets by account/token rather than `apiRoot`, while startup still treats non-network `deleteWebhook` failures such as `400: Logged out` as fatal; the remaining fix needs maintainer policy and live local Bot API proof.

## What This Changes

The issue reports self-hosted Telegram Bot API `apiRoot` inbound updates being dropped, stale offsets after endpoint switches, and fatal `deleteWebhook` logged-out startup loops.

## Best Possible Solution

Keep this as the canonical local Bot API migration tracker; choose endpoint-aware offset/reset ownership, add narrow logged-out startup handling, and prove inbound dispatch plus outbound reply delivery against a live local Bot API server.
