## Summary

Keep open. Current main and the latest release still key Telegram polling offsets by account/token rather than `apiRoot`, and polling startup still only continues past recoverable network `deleteWebhook` failures, so the local Bot API migration/drop path remains unresolved.

## What This Changes

The issue reports that Telegram `channels.telegram.apiRoot` local Bot API polling receives updates but does not dispatch them to agent sessions, reuses stale offsets across endpoint switches, and can crash-loop on `deleteWebhook` during migration cooldown.

## Best Possible Solution

Keep this as the canonical local Bot API migration tracker; add endpoint-aware offset/reset handling plus a narrowly scoped logged-out cleanup rule, then prove inbound dispatch and outbound reply delivery against a live local Bot API server.
