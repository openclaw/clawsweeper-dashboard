## Summary

Keep open. Current main and the latest release still preserve Telegram update offsets by account/token rather than API root, then pass that watermark into the configured local `getUpdates` endpoint; `deleteWebhook` also still only continues past recoverable network failures, so the local Bot API migration case needs maintainer policy and live proof before a fix PR is safe.

## What This Changes

The issue requests reliable dispatch for Telegram inbound updates when `channels.telegram.apiRoot` points at a local Bot API server, including endpoint-scoped offsets and non-fatal local migration webhook handling.

## Best Possible Solution

Keep this as the canonical local Bot API migration tracker; define endpoint-switch offset/reset policy and a narrow `400: Logged out` cleanup rule, then prove inbound dispatch and outbound reply delivery against a live local Bot API server.
