## Summary

Keep open. Current main still does not key Telegram polling offsets by `apiRoot`, and polling startup still treats non-network `deleteWebhook` failures such as `400: Logged out` as fatal; the remaining fix needs maintainer policy and live local Bot API proof.

## What This Changes

The issue asks for self-hosted Telegram Bot API polling through `channels.telegram.apiRoot` to dispatch inbound updates, reset or scope update offsets across endpoint changes, and avoid a `deleteWebhook` crash loop during local Bot API migration.

## Best Possible Solution

Keep this as the canonical local Bot API migration tracker; add endpoint-aware offset/reset handling and a narrow logged-out cleanup rule, then prove inbound dispatch and outbound reply delivery against a live local Bot API server.
