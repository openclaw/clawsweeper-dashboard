## Summary

Keep open. Current main supports Telegram `apiRoot`, but it still reuses update offsets by account/token rather than endpoint and still treats non-network `deleteWebhook` failures such as `400: Logged out` as fatal, so the local Bot API migration bug is not fully resolved.

## What This Changes

Fix Telegram local Bot API `apiRoot` migration so inbound updates dispatch to agent sessions, endpoint changes do not reuse incompatible offsets, and startup does not crash-loop during the Telegram `logOut` cooldown.

## Best Possible Solution

Keep this as the canonical local Bot API migration tracker, define endpoint-aware offset reset or partitioning plus a narrow `400: Logged out` startup rule, and prove inbound dispatch plus outbound reply delivery against a live local Bot API server.
