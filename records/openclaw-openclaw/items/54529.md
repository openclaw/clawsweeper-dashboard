## Summary

Keep open. Current main still keys Telegram update offsets by account/token rather than `apiRoot`, and startup still treats non-network `deleteWebhook` failures like `400: Logged out` as fatal; the remaining fix needs maintainer policy plus live self-hosted Bot API proof.

## What This Changes

The issue asks OpenClaw to make Telegram `channels.telegram.apiRoot` local Bot API migration dispatch inbound updates, reset or scope stale update offsets, and avoid a startup crash loop during Telegram `logOut` cooldown.

## Best Possible Solution

Keep this as the canonical local Bot API migration tracker; implement endpoint-aware offset handling plus a narrow logged-out cleanup rule, then prove inbound dispatch and outbound reply delivery against a live local Bot API server.
