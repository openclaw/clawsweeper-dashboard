## Summary

Keep open. Current main and v2026.6.11 have repaired the isolated-ingress raw-update dispatch path, but Telegram offset state is still account/token keyed rather than apiRoot keyed, and polling startup still treats a non-network deleteWebhook 400 such as Logged out as fatal; the remaining local Bot API migration behavior needs maintainer policy plus live proof.

## What This Changes

Report that Telegram local Bot API apiRoot polling can receive updates but fail inbound dispatch, reuse incompatible update offsets, and crash-loop on deleteWebhook during logOut migration.

## Best Possible Solution

Keep the current isolated-ingress dispatch repairs, then add endpoint-aware offset invalidation or migration and a narrow logged treatment for the local Bot API logOut cooldown, backed by live self-hosted Bot API proof.
