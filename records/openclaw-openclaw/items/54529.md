## Summary

Keep open. Current main still lacks endpoint-aware Telegram update-offset state and still treats non-network `deleteWebhook` failures as retry-or-exit startup failures, so the local Bot API migration report remains actionable but needs maintainer policy and live proof before an automated fix.

## What This Changes

The issue asks OpenClaw to make Telegram local Bot API `apiRoot` polling dispatch inbound updates, reset incompatible offsets on endpoint changes, and avoid crash-looping on `deleteWebhook` during logOut migration.

## Best Possible Solution

Keep this as the canonical local Bot API migration tracker, define endpoint-switch offset/reset policy plus narrow `400: Logged out` handling, then prove inbound dispatch and outbound replies against a live local Bot API server.
