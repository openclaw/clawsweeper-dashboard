## Summary

Keep open: current main still lacks apiRoot-aware Telegram polling offsets and still treats non-network deleteWebhook failures as fatal, so the reported local Bot API migration problem is not safely closable.

## What This Changes

The issue asks OpenClaw to make Telegram self-hosted Bot API apiRoot migration reliably dispatch inbound updates, handle stale update offsets, and avoid deleteWebhook startup loops.

## Best Possible Solution

Keep this as the canonical local Bot API migration tracker, then add endpoint-aware offset/reset handling and a narrowly scoped logged-out cleanup rule with live self-hosted Bot API proof for inbound dispatch and reply delivery.
