## Summary

Keep open. Current main supports `channels.telegram.apiRoot`, but the remaining report is still actionable because Telegram polling offset identity is account/token-scoped rather than endpoint-scoped, and startup `deleteWebhook` still treats non-network Bot API failures as retry/exit conditions.

## What This Changes

The issue asks for local Telegram Bot API `apiRoot` polling to dispatch inbound updates reliably, reset or scope update offsets when endpoints change, and avoid a startup crash loop during `logOut` migration cooldown.

## Best Possible Solution

Add endpoint-aware Telegram offset identity or migration in plugin-owned state/doctor code, and pair it with a narrow, tested local-Bot-API migration path for `deleteWebhook`/`logOut` plus live proof that spooled updates dispatch.
