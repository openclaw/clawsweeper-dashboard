## Summary

Keep open. Current main still lacks endpoint-aware Telegram update offset state and still treats non-network `deleteWebhook` failures as retry/exit conditions, so the local Bot API migration report remains actionable but needs maintainer policy and live proof before a fix PR.

## What This Changes

The issue reports that Telegram inbound updates from a custom local Bot API `apiRoot` can be received by polling but not dispatched, with stale update offsets and fatal `deleteWebhook` handling during migration.

## Best Possible Solution

Keep this as the canonical local Bot API migration tracker, define endpoint-switch offset/reset policy and narrow `400: Logged out` handling, then prove inbound dispatch and outbound reply delivery against a live local Bot API server.

## Reproduction Assessment
