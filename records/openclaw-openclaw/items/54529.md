## Summary

Keep open. Current main still carries account/token-scoped Telegram update offsets across `apiRoot` changes and still treats non-network `deleteWebhook` failures such as the reported `400: Logged out` as startup-fatal, so the local Bot API migration bug is not fully implemented or superseded.

## What This Changes

The issue asks OpenClaw to make Telegram local Bot API `apiRoot` migration dispatch inbound updates reliably, reset or scope incompatible polling offsets, and avoid a fatal `deleteWebhook` loop during `logOut` cooldown.

## Best Possible Solution

Keep this as the canonical local Bot API migration tracker; add endpoint-aware offset/reset handling and a narrow logged-out cleanup rule, then prove inbound dispatch and outbound reply delivery against a live local Bot API server.
