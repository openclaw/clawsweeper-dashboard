## Summary

Keep open: this is a narrow, likely-correct Mantle provider hardening PR with sufficient after-fix proof, but maintainers still need to accept the new timeout and body-size boundary before merge.

## What This Changes

The PR adds a 30s abort signal and a 4 MiB bounded JSON reader to Amazon Bedrock Mantle model discovery, with regression tests for timeout wiring and oversized response fallback.

## Best Possible Solution

Land the provider-local bounded discovery fix once maintainers accept the 30s and 4 MiB Mantle catalog boundary; keep broader provider-catalog sweeps separate.

## Reproduction Assessment

Yes, at source level: current main fetches Mantle `/v1/models` without an abort signal and then calls `response.json()` on the success body. I did not run a live repro during this read-only review, but the PR body includes after-fix local HTTP proof for normal, oversized, and stalled paths.

## Solution Assessment

Yes. Reusing the existing bounded response reader inside the Mantle provider boundary plus a fetch abort signal is the narrow maintainable fix; the only maintainer decision is whether the 30s and 4 MiB limits are the right product boundary.
