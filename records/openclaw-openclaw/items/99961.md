## Summary

No blocking findings; this should stay open for normal maintainer merge review rather than cleanup close. The patch is a narrow Bedrock Mantle discovery hardening with sufficient local HTTP proof, with the remaining merge consideration being the intentional timeout/body-cap compatibility boundary.

## What This Changes

The PR adds a 30-second abort signal and 4 MiB bounded response reader to Amazon Bedrock Mantle model discovery, plus focused tests for timeout and oversized responses.

## Best Possible Solution

Land the provider-local bounded discovery fix once maintainers accept the 30s/4 MiB catalog boundary; keep broader dynamic-catalog policy or configurable discovery semantics in their existing provider-catalog threads.

## Reproduction Assessment

Yes, at source level. Current main calls Mantle /v1/models without an AbortSignal and then uses response.json(), so a stalled request or oversized successful JSON body has no provider-local bound in this module.

## Solution Assessment

Yes. Reusing the existing plugin-sdk response limiter inside the Mantle provider boundary is the narrow maintainable fix; the readProviderJsonResponse alternative would not cover the stalled-fetch path and defaults to a broader 16 MiB provider JSON cap.
