## Summary

Keep this PR open for review: the Mantle discovery hardening is directionally useful, but it still needs real behavior proof and maintainer acceptance of the new 4 MiB / 30s fail-soft boundary. Related open PRs overlap with the bounded JSON portion, but they do not cleanly supersede this PR because this one also adds timeout behavior.

## What This Changes

The PR adds a 30 second AbortSignal timeout and a 4 MiB bounded JSON reader to Amazon Bedrock Mantle model discovery, then updates discovery tests to use real Response bodies.

## Best Possible Solution

Use one canonical Mantle discovery hardening path that keeps discovery bounded, preserves fail-soft fallback, justifies or aligns the JSON cap and timeout, and includes real local-server proof for normal, oversized, and stalled responses.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Source-level yes: current main calls response.json() on successful Mantle discovery responses, which can buffer an oversized body, but I did not run a live or local stalled-response reproduction in this read-only review.

## Solution Assessment

Is this the best way to solve the issue? Unclear as submitted: the plugin-owned location is right, but the final fix should either align with the shared provider JSON cap/helper or clearly justify the tighter 4 MiB cap and prove the timeout path in a real setup.
