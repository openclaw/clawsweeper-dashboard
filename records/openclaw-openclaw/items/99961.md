## Summary

Keep open: this is a focused Bedrock Mantle provider bugfix that is not already on current main, and the patch appears correct after checking the Mantle discovery path, provider registration, shared response limiter, sibling live-catalog behavior, PR proof, and CI. The only maintainer-facing concern is the intentional new 30s/4 MiB discovery boundary, which can make very slow or oversized Mantle catalogs fall back to cache or empty results instead of waiting longer.

## What This Changes

The PR adds a 30-second abort signal and a 4 MiB bounded response reader to Amazon Bedrock Mantle model discovery, with regression tests for the timeout signal and oversized response fallback.

## Best Possible Solution

Land the provider-local bounded discovery fix once maintainers accept the 30s/4 MiB catalog boundary; keep broader dynamic-catalog policy or configurable discovery semantics in their existing provider-catalog threads.

## Reproduction Assessment

Yes, at source level. Current main calls Mantle `/v1/models` without an AbortSignal and then uses `response.json()`, so a stalled request or oversized successful JSON body has no provider-local bound in this module.

## Solution Assessment

Yes. Reusing the existing plugin-sdk response limiter inside the Mantle provider boundary is the narrow maintainable fix; adding a new config knob or duplicating live-catalog infrastructure would be broader than this bug requires.
