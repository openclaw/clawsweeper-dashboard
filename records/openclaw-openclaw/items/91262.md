## Summary

Keep open: the PR addresses a real, still-present `pnpm build` source-checkout failure on Node builds without native TypeScript stripping, and I found no blocking correctness finding in the narrow build-all fallback.

## What This Changes

The PR rewrites build-all `node --experimental-strip-types <script>.ts` steps to `node --import tsx <script>.ts` when the current Node binary lacks native TypeScript stripping, and adds regression coverage for fallback and passthrough cases.

## Best Possible Solution

Land the narrow build-all fallback if maintainers accept build-all as the supported source-checkout build path, and track direct package-script compatibility separately only if that wider guarantee is desired.

## Reproduction Assessment

Yes. Source inspection shows current main still invokes `--experimental-strip-types` for build-all `.ts` steps and passes those args unchanged, and the PR body includes real affected-host proof where `process.features.typescript` was false.

## Solution Assessment

Yes for the reported `pnpm build` path. `resolveBuildAllStep` is the build-all command-selection boundary, and this is narrower than rewriting every package script or changing the repo-wide TypeScript execution policy.
