## Summary

Keep open: current main and the latest release still invoke build-all TypeScript script steps through native strip-types only, while the PR's merge result narrowly adds a fallback with focused tests and sufficient live proof. I found no blocking correctness or security finding.

## What This Changes

The branch rewrites build-all `node --experimental-strip-types <script>.ts` steps to `node --import tsx <script>.ts` when the active Node binary lacks native TypeScript stripping, and adds regression coverage.

## Best Possible Solution

Merge the focused build-all fallback after normal maintainer and check gating, and track wider direct-script compatibility separately only if maintainers want that broader source-build guarantee.

## Reproduction Assessment

Yes. Source inspection shows current main still passes `--experimental-strip-types` directly to build-all `.ts` node steps, and the PR body supplies live output from a Node build where `process.features.typescript` is false.

## Solution Assessment

Yes for the reported `pnpm build` path. `resolveBuildAllStep` is the existing command-selection boundary, and the PR is narrower than rewriting package scripts or changing the whole build runner.
