## Summary

Keep this issue open: its same-author implementation candidate remains open, while the proposed configuration, durable once-state, and redirect-failure behavior need explicit product and security direction before the broader policy can be accepted.

## What This Changes

Add a `messages.operationalReplies` policy that can keep runtime notices visible, suppress them, send each once per source session, or redirect them away from external source chats.

## System Context

OpenClaw's agent and channel delivery paths turn runtime outcomes such as model fallbacks, heartbeat messages, and plugin-binding failures into source-chat replies. The proposed policy would sit before delivery so operators can prevent operational details from reaching an external recipient while retaining a controlled operator-facing path.

## Best Possible Solution

Approve one narrow, documented operational-notice contract only after maintainers choose the redirect-failure behavior, define the persisted once-state lifecycle, and require source-chat plus operator-session proof across representative delivery paths; then land the linked implementation or a reduced replacement.
