## Summary

Keep this PR open, but do not merge the current head: the Linux first-run dashboard can remain permanently in its reduced onboarding shell after the memory dialog closes, and the branch is currently conflicted with main. The core reuse and cross-platform intent are strong, but the first-run exit path and complete real-behavior proof need resolution before landing.

## What This Changes

The branch adds detection-gated Claude Code, Codex, and Hermes memory import offers to CLI, macOS, and Linux/Control UI onboarding, centralizes memory-only migration policy, and adds Hermes copy-based memory import support.

## Best Possible Solution

Keep one shared memory-only migration engine, but make onboarding mode an explicit host-owned lifecycle that exits to the normal dashboard in-product after empty, Skip, Continue, success, or advisory failure; then rebase and prove completed CLI, Linux, and macOS first-run flows on the exact head.
