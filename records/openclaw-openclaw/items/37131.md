## Summary

Keep this open as the canonical direct-invoke umbrella: current main and v2026.6.11 already cover HTTP /tools/invoke, Gateway RPC tools.invoke, SDK oc.tools.invoke, cron command execution, and skill command-dispatch-to-tool, but the remaining host-filesystem, exec-class, CLI/slash, cron-tool-call, and startup-readiness surfaces still need explicit maintainer security/product decisions.

## What This Changes

The issue requests a deterministic way to invoke OpenClaw tools directly from slash commands, CLI scripts, and cron jobs without an LLM round trip.

## Best Possible Solution

Keep this umbrella open while maintainers decide which remaining surfaces belong in core and land only narrow, documented, default-denied direct-invoke paths with real upgrade and security proof.
