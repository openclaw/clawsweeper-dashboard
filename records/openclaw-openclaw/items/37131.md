## Summary

Keep open: current main and v2026.6.11 already cover HTTP `/tools/invoke`, SDK/RPC `tools.invoke`, and zero-LLM cron command jobs, but the original request still includes unresolved host filesystem, exec, chat/slash, CLI, and generic cron direct-tool scope that needs maintainer security/product direction.

## What This Changes

The issue requests a direct tool invocation surface that can execute explicit tool calls from chat, CLI, cron, or SDK/API callers without an LLM round trip.

## Best Possible Solution

Keep this as the canonical umbrella while maintainers land, narrow, or reject the remaining direct-invoke surfaces behind explicit owner, policy, audit, documentation, and proof gates.
