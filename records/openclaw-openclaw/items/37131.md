## Summary

Keep open: current main and v2026.6.11 already provide HTTP `/tools/invoke`, SDK/RPC `tools.invoke`, direct skill-command dispatch, and command cron slices, but the broader request still includes high-risk exec, host filesystem, session/control-plane, generic slash-command, CLI, and cron `toolCall` surfaces that need maintainer product and security direction.

## What This Changes

Request to add deterministic direct tool invocation from chat, slash command, CLI, and cron without routing every known tool call through an LLM turn.

## Best Possible Solution

Keep this as the canonical umbrella while maintainers land, narrow, or reject each remaining direct-invoke surface behind explicit Gateway auth, owner identity, policy, audit, docs, and upgrade-safety gates.
