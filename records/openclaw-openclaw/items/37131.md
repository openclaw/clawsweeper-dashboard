## Summary

Keep open: current main and v2026.6.11 already cover the HTTP `/tools/invoke`, Gateway RPC `tools.invoke`, SDK invoke, and direct cron `command` slices, but the broader slash/CLI, generic cron tool-call, host-filesystem, and high-risk exec-class surfaces still need explicit maintainer security/product direction.

## What This Changes

Request to invoke OpenClaw tools directly from chat/slash commands, CLI, cron payloads, and explicit tool args without an LLM turn.

## Best Possible Solution

Keep this as the canonical umbrella while maintainers land, narrow, or reject remaining direct-invoke surfaces behind explicit owner identity, policy, audit, docs, and upgrade-safety gates.
