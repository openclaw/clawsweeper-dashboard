## Summary

Keep open: current main and the latest release cover important slices of direct invocation through HTTP, RPC/SDK, command cron, and skill slash-command dispatch, but the broader request still includes high-risk host execution, filesystem, session, generic slash/CLI, and startup-readiness surfaces that need maintainer product and security direction.

## What This Changes

The issue requests a way to invoke OpenClaw tools directly from chat, slash commands, CLI, cron, SDK, or HTTP without an LLM round trip.

## Best Possible Solution

Keep this as the canonical umbrella while maintainers land, narrow, or reject each remaining direct-invoke surface behind explicit Gateway auth, owner identity, tool policy, audit, docs, and upgrade-safety gates.
