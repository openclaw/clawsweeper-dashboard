## Summary

Keep this issue open. Recent production evidence on v2026.7.1 and the source-correlated report indicate that the foreground reply fence still treats unrelated group messages sharing a session target as potential supersession, so a completed answer can be withheld and then silently lost. The open bounded-wait PR addresses a related delay geometry, not the remaining group-message identity contract.

## What This Changes

Fix automatic group-reply delivery so completed answers to distinct inbound messages are not suppressed by a newer visible reply, and make any intentional suppression observable to operators.

## System Context

Inbound WhatsApp group messages start reply dispatches that share a session target. Before a completed payload is sent, the foreground reply fence decides whether a newer visible delivery supersedes it; that decision determines whether the channel receives the reply or the completed result remains dashboard-only.

## Architecture Diagram

flowchart LR
  A[WhatsApp group mentions] --> B[Inbound reply dispatches]
  B --> C[Foreground reply fence]
  C --> D{Same reply identity\nor shared group target?}
  D --> E[Channel delivery]
  D --> F[Suppress as stale]
  E --> G[Visible WhatsApp reply]
  F --> H[Dashboard-only completed run]

## Best Possible Solution

Define group-chat supersession around an inbound-message identity: keep direct-chat target freshness unless evidence requires otherwise, give distinct group messages independent fences, preserve explicit same-message supersession where it exists, and emit an info-level cancellation record with the fence identity and reason.

## Solution Assessment

A group-only per-inbound-message boundary is the narrowest apparent mitigation, but maintainers must first confirm the intended supersession rule for genuinely replacing prompts.
