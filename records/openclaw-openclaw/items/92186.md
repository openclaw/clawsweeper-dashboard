## What This Changes

Fix automatic visible replies so concurrent WhatsApp group messages cannot silently cancel a completed reply for an earlier, distinct inbound message.

## System Context

The auto-reply dispatcher creates outbound payloads for inbound channel turns and runs a foreground reply fence immediately before delivery. The fence uses delivery visibility to suppress stale replies; its scope determines whether one group participant's newer reply can cancel another participant's completed reply.

## Architecture Diagram

flowchart LR
  A[WhatsApp group messages] --> B[Inbound reply dispatch]
  B --> C[Agent turns]
  C --> D[Queued reply payloads]
  D --> E[Foreground reply fence]
  E --> F{Visible newer reply?}
  F -->|Yes| G[Suppress older payload]
  F -->|No| H[Deliver quoted reply to WhatsApp]

## Best Possible Solution

Define a group-chat-specific foreground-fence contract that prevents unrelated inbound messages from suppressing each other, retain deliberate freshness behavior only where it is explicitly intended, add cancellation observability, and validate concurrent replies in a real WhatsApp group before release.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For group chats, should a newer visible reply be allowed to suppress a completed reply for a different inbound message, or must freshness be isolated per inbound message?

Rationale: The source-correlated recurrence includes different topics from the same sender, so sender scoping is insufficient; choosing between per-message isolation, a narrower group rule, or target-level supersession changes the product's conversation-ordering contract.

Likely owner: cavit99

Owner reason: The merged fence implementation is the direct provenance trail for the contract now requiring clarification.

Owner confidence: medium

Options:

- **Use group per-message fences (recommended):** Isolate group-chat foreground fences by inbound message while retaining the existing target-level behavior for direct chats.
- **Keep target-level freshness:** Retain current suppression semantics and accept that an earlier completed group reply may be discarded after a newer visible reply.
- **Adopt another explicit group policy:** Define a documented group-specific supersession rule before implementing a scoped fence change.

## Reproduction Assessment

Yes, at source level: the supplied current-release incident traces a completed older group turn through the target-scoped foreground fence until a newer visible turn marks it stale. A live two-message WhatsApp group run remains the appropriate final confirmation.

## Solution Assessment

Unclear: per-sender isolation is disproved by the new same-sender/different-topic recurrence, and per-message isolation appears narrower, but maintainers must first choose the group supersession contract it establishes.
