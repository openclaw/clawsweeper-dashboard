## Summary

Keep this PR open: the stdin CLI input is a useful additive feature and current main does not provide `--message-stdin`, but the branch needs a bounded stdin read and public after-fix CLI proof before merge.

## What This Changes

The PR adds `openclaw agent --message-stdin`, wires stdin message resolution into gateway and local agent dispatch, and updates agent CLI docs and tests while keeping existing `--message-file` behavior.

## Best Possible Solution

Keep the additive stdin option, but bound stdin bytes before accumulation using the same input-size policy as message files, then add redacted terminal proof from a real `openclaw agent --message-stdin` run.

## Reproduction Assessment

Yes from source inspection: the new stdin reader stores every chunk and concatenates the full stream before validation, so an oversized pipe can exhaust memory. I did not run an OOM repro because the risky path is clear and destructive to exercise directly.

## Solution Assessment

No as currently written. The CLI boundary is the right layer for stdin support, but the implementation should bound stdin reads before buffering and include real CLI smoke proof before merge.
