## Summary

Keep open: current main and the latest release still carry the reported browser/CDP SSRF policy mismatch, and the failure is source-reproducible. The fix should stay with maintainer/security review because it changes how the browser distinguishes CDP control-plane trust from page-navigation allowlists.

## What This Changes

Fix browser SSRF control-policy handling so `navigate` does not self-block loopback CDP when `browser.ssrfPolicy.hostnameAllowlist` is non-empty.

## Best Possible Solution

Route Playwright connection and target lookup through a scoped CDP-control policy while preserving strict page-navigation and redirect checks, with regression tests for local loopback, remote CDP, and non-matching page hosts.
