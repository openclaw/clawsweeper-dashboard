## Summary

Keep open: current main and v2026.6.11 still carry the reported browser/CDP SSRF policy mismatch, and the failure is source-reproducible. The fix should get maintainer review because it relaxes a security-sensitive control-plane check that current tests partially encode in the opposite direction.

## What This Changes

The issue requests that browser CDP control-plane hostname grants work when `browser.ssrfPolicy.hostnameAllowlist` is non-empty, so `navigate` does not self-block on loopback CDP after `open` succeeds.

## Best Possible Solution

Route Playwright connection/session lookup through a scoped CDP-control policy while keeping the original browser navigation policy for requested URL, redirect, and final-page checks; add focused regression coverage for `navigate` with a non-empty `hostnameAllowlist` plus remote/external CDP guard preservation.
