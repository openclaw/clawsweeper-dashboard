## Summary

Keep open: current main and v2026.6.11 still carry the reported browser/CDP SSRF policy mismatch, and the failure is source-reproducible. The fix should stay maintainer-owned because it changes a browser SSRF control-plane boundary and existing tests partially encode the stricter behavior.

## What This Changes

The issue reports that `browser navigate` can self-block CDP control traffic when `browser.ssrfPolicy.hostnameAllowlist` is non-empty because `withAllowedHostname` only appends to `allowedHostnames`.

## Best Possible Solution

Route Playwright connection and target lookup through a scoped CDP-control policy while keeping the original navigation policy for requested URLs, redirects, and final-page checks; add focused regression coverage for `navigate` with a non-empty `hostnameAllowlist` plus remote/external CDP guard preservation.
