## Summary

Keep open: current main and v2026.6.11 still carry the browser/CDP SSRF policy mismatch, and the reported failure is source-reproducible. The repair should stay behind maintainer security-boundary review because it changes how browser CDP control traffic is exempted from page-navigation SSRF policy.

## What This Changes

The issue reports that `browser navigate` fails with a non-empty `browser.ssrfPolicy.hostnameAllowlist` because the loopback CDP control-plane allowance updates only `allowedHostnames`.

## Best Possible Solution

Route Playwright connection, target lookup, and CDP session operations through a scoped CDP-control policy while keeping the original browser navigation policy for requested URL, redirect, and final-page checks; add regression coverage for this `hostnameAllowlist` case plus remote-CDP guard preservation.
