## Summary

Keep open. Current main and v2026.6.11 still have a source-reproducible browser SSRF/control-plane gap: the loopback CDP helper adds only `allowedHostnames`, while the shared resolver still rejects the CDP host when `hostnameAllowlist` is non-empty.

## What This Changes

The issue reports that browser `navigate` fails when `browser.ssrfPolicy.hostnameAllowlist` is non-empty because the CDP loopback helper updates only `allowedHostnames`.

## Best Possible Solution

Keep page-navigation SSRF checks strict, but ensure Playwright page-selection/CDP connection work for local managed loopback uses the profile-scoped CDP control policy, with regression coverage for `hostnameAllowlist` plus `navigate`.

Yes, source-reproducible. Current main shows `navigateViaPlaywright` can pass the browser navigation policy into `getPageForTargetId`, where loopback CDP validation adds only `allowedHostnames` and the shared resolver still rejects a non-matching `hostnameAllowlist`.

## Solution Assessment

Unclear until maintainers choose the security boundary. The narrowest maintainable direction appears to be routing CDP selection through the profile-scoped control policy, not broadening shared SSRF allowlist semantics.
