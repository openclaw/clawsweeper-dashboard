## Label Justifications

- `P1`: Authorized Control UI users can be blocked from viewing generated image artifacts, breaking a real user-facing workspace workflow.

## Summary

Keep this PR open: the linked bug is credible, but the current patch is not merge-ready because it defeats the intended managed-media lazy-loading boundary and does not include inspectable after-fix behavior proof.

## What This Changes

The PR adds paired Control UI device-token authorization for managed image HTTP reads and resolves protected managed image URLs into base64 artifact-download responses.

## Best Possible Solution

Keep managed-image records and authorization protected, but resolve artifact bytes through a lightweight or explicitly lazy runtime boundary, preserve the current owner and operator.read checks, and provide redacted end-to-end Control UI proof for both allowed and rejected requests.
