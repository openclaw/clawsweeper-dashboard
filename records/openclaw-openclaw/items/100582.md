## Summary

Keep open: the PR is still necessary and appears correct. Current main routes every ClickClack `replyToId` through the thread-reply endpoint, while this branch preserves real thread context and sends top-level channel/DM replies as ClickClack quote-replies with live proof and focused tests.

## What This Changes

The PR changes ClickClack outbound routing and HTTP payloads so top-level channel/DM replies use `quoted_message_id`, while explicit thread context still uses thread replies.

## Best Possible Solution

Land the focused ClickClack routing fix after ordinary maintainer and exact-head CI review, keeping thread replies only for explicit thread context and using quote-replies for top-level channel/DM replies.
