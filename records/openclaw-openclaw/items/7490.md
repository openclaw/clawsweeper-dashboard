## What This Changes

Request to add optional per-agent description metadata and include it in `agents_list` so orchestrators can select sub-agents dynamically.

## Best Possible Solution

Review and either land or explicitly reject the linked PR’s narrow behavior: expose trimmed nonblank configured descriptions through authorized `agents_list` results with docs, tests, and prompt-size/security guardrails.

Yes, at source level: current main accepts `agents.list[].description`, but `agents_list` builds returned entries without reading or emitting that property. ## Solution Assessment

Yes for the implementation shape: the narrow remaining fix is to thread trimmed nonblank configured descriptions into `agents_list` and document/test omission of blank values.
