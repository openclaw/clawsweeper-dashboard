## What This Changes

The request asks OpenClaw to support per-agent `description` metadata in config and return it from `agents_list` so orchestrators can choose sub-agents dynamically.

## Best Possible Solution

Review https://github.com/openclaw/openclaw/pull/75225 and either land the bounded `agents_list` description output with docs/tests, narrow its visibility, or explicitly reject that metadata boundary.

## Reproduction Assessment

Yes, at source level. Current main accepts `agents.list[].description`, but `agents_list` builds entries without reading or emitting that property.

## Solution Assessment

Yes if maintainers accept the metadata boundary: extending the existing allowlist-aware `agents_list` response is narrower than prompt injection or a hardcoded catalog. The safer alternative is to gate or narrow description visibility before merge.
