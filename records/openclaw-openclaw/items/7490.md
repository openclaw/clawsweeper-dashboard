## Summary

Keep this issue open because the requested runtime discovery behavior is not yet on current main and an open, proof-backed implementation candidate explicitly closes it.

## What This Changes

Add configured per-agent descriptions to the `agents_list` response so an orchestrator can choose an allowed sub-agent by specialty.

## System Context

OpenClaw reads configured agents and the requesting agent’s sub-agent allowlist to build the `agents_list` tool result. Orchestrators use that result to select targets for `sessions_spawn`, so an agent description must flow from canonical configuration into the allowed-agent output.

## Architecture Diagram

flowchart LR

  B --> C[Agents list tool]
  A --> C
  C --> D[Allowed agent roster]
  D --> E[Orchestrator agent]
  E --> F[Sub-agent session spawn]

## Best Possible Solution

Adopt a bounded optional description as part of the allowed-agent discovery contract, then rebase and land the focused implementation with tests for nonblank inclusion, blank omission, and unchanged output for existing configurations.
