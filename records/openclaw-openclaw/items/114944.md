## Summary

Keep this PR open for maintainer review. The patch is a focused repair for ambient credential takeover and preserves the established distinction between explicit/stored credentials and automatically discovered credentials, but it deliberately makes some existing pinned-provider setups fail with missing authentication instead of using a conflicting ambient fallback; the protected `maintainer` label requires an explicit acceptance of that compatibility change.

## What This Changes

The PR makes a provider’s existing `models.providers.<id>.auth` pin reject incompatible ambient external-CLI and synthetic credentials while leaving stored profiles and explicitly requested profile bindings eligible.

## System Context

OpenClaw builds an agent auth plan from stored profiles, explicit bindings, environment credentials, external CLI imports, and plugin-generated credentials. This PR places the provider auth-pin check at the ambient-import boundary before those credentials can influence agent or embedded-run provider routing.

## Best Possible Solution

Treat the configured auth pin as authoritative for ambient credential discovery, land the focused filtering behavior if maintainers accept the fail-closed upgrade contract, and keep stored profiles, explicit bindings, and environment-backed credentials governed by their existing precedence rules.
