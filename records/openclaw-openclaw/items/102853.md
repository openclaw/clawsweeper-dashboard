## Summary

This is a well-proven security hardening patch, but it remains blocked on an explicit maintainer decision about whether OpenClaw may own the new generic atomic-replacement mode semantics locally or must first move them into `@openclaw/fs-safe`.

## What This Changes

The PR replaces direct `auth.json` bootstrap writes with atomic replacement and adds local async/sync wrappers that avoid final-path chmod symlink races while preserving requested modes.

## Best Possible Solution

Choose one long-term owner for no-follow exact-mode atomic replacement: preferably add the descriptor-based mode guarantee to `@openclaw/fs-safe`, then keep OpenClaw as a thin delegating consumer; alternatively explicitly approve this local wrapper as the supported temporary owner and track upstream convergence.
