## Label Justifications

- `P2`: This is a bounded local credential-storage hardening change with meaningful security and compatibility implications but no evidence of an active widespread outage.
- `merge-risk: 🚨 compatibility`: Changing shared replacement mode semantics can affect existing callers that depend on exact modes, fallback behavior, or custom filesystem adapters.
- `merge-risk: 🚨 auth-provider`: `AuthStorage` is the default credential backend for agent sessions, so an incorrect replacement change could affect persisted authentication state.
- `merge-risk: 🚨 security-boundary`: The patch mitigates symlink-following writes and chmod operations while establishing a new local boundary around a shared filesystem-safety dependency.

## Summary

Keep this PR open for an explicit security-boundary decision. The patch has focused regression coverage and credible on-disk before/after proof, but it changes the atomic-replacement permission contract through an OpenClaw wrapper rather than resolving that contract in `@openclaw/fs-safe` itself.

## What This Changes

The branch changes `auth.json` bootstrap to use atomic replacement and wraps async/sync atomic replacement to avoid final-path chmod races while preserving requested file modes.

## Best Possible Solution

Choose one owner for exact-mode, no-final-path-chmod atomic replacement: preferably add the capability to `@openclaw/fs-safe` and reduce OpenClaw to delegation, or explicitly approve this narrow wrapper as the temporary OpenClaw-owned hardening boundary with its regression tests retained.
