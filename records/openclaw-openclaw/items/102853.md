## Summary

This PR remains necessary: it addresses a credential-file symlink-follow risk and includes credible before/after terminal proof, but its expanded replacement wrapper changes the ownership boundary for shared `@openclaw/fs-safe` behavior. A security-boundary owner should decide whether OpenClaw may carry that wrapper temporarily or whether the capability must be fixed and released upstream first.

## What This Changes

The branch routes missing `auth.json` bootstrap through atomic replacement and wraps async/sync fs-safe replacement calls to avoid final-path chmod symlink races while preserving requested file modes.

## Best Possible Solution

Choose a single owner for no-follow exact-mode replacement: preferably add and release the capability in `@openclaw/fs-safe`, then keep OpenClaw on a thin delegation path; alternatively explicitly approve this wrapper as a temporary documented local hardening layer with focused shared-caller coverage.
