## Summary

Keep open: the direct auth.json bootstrap hardening and latest copy-fallback mode coverage are useful, but the async wrapper now resolves preserved modes before fs-safe's serialized replace queue, so concurrent replaceFileAtomic callers can restore a stale mode. The PR also still needs secops approval for changing a shared security-sensitive, plugin-facing replacement helper.

## What This Changes

The PR routes missing auth.json bootstrap through atomic replacement and wraps shared async/sync atomic file replacement helpers to avoid final-path chmod through swapped symlinks while preserving requested modes.

## Best Possible Solution

Preserve fs-safe's serialized mode-resolution semantics while avoiding followable final-path chmod, add a concurrency regression for preserveExistingMode, and then get secops approval for the wrapper-versus-fs-safe ownership choice.
