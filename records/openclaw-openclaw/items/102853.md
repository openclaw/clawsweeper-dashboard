## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.84

Full review comments:

- **[P2] Keep pre-rename chmod best-effort:** `src/infra/replace-file.ts:137`
  - body: The fs-safe helper currently catches final `chmod` failures as best-effort, so replacements can still succeed on filesystems that reject POSIX chmod. Moving exact-mode correction into `beforeRename` makes `handle.chmod(mode)` a hard failure whenever the temp mode needs correction, which can break shared callers such as 0644 baseline writes or preserved-mode replacements under restrictive umasks. Please preserve the best-effort behavior while still avoiding chmod on the swappable final path.
  - confidence: 0.84
- **[P2] Do not fchmod injected sync descriptors with real fs:** `src/infra/replace-file.ts:154`
  - body: `ReplaceFileAtomicSyncFileSystem` is still exported through the plugin SDK, but this new mode-correction path opens the temp file through the injected filesystem and then calls Node's real `fs.fchmodSync` on that descriptor. A wrapped or virtual filesystem cannot satisfy this contract because `fchmodSync` is not part of the injected type, so sync callers can fail even though they provide all required fs-safe operations. Keep the chmod operation on the same filesystem contract or extend the contract explicitly with tests.
  - confidence: 0.82
