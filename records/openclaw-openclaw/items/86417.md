## Summary

Keep open: current main and v2026.6.11 still scope `OPENCLAW_NO_AUTO_UPDATE` to configured background auto-update applies, while supervised `update.run` can still start a managed-service handoff and schedule an update restart. The remaining work is a maintainer product-contract decision, not stale cleanup.

## What This Changes

The issue asks OpenClaw to document and enforce an operator kill-switch for macOS launchd Gateway `update.run` restarts that create `gateway-update` handoffs.

## Best Possible Solution

Maintainers should decide the kill-switch scope, then either gate Gateway-originated managed `update.run` handoffs before handoff creation and restart scheduling with docs/tests, or explicitly document that `update.run` is outside the auto-update kill-switch and leave restart reliability to the broader launchd handoff tracker.
