## Summary

Keep open: current main and the latest release still scope `OPENCLAW_NO_AUTO_UPDATE` to configured startup/background auto-update applies, while supervised Gateway `update.run` can still create a managed launchd handoff and schedule an `update.run` restart. The remaining blocker is maintainer confirmation of the kill-switch contract, not stale cleanup.

## What This Changes

The issue asks for macOS launchd Gateway `gateway-update` / `update.run` restarts to be documented and optionally blocked by the auto-update kill-switch for headless supervised deployments.

## Best Possible Solution

Maintainers should define the kill-switch scope, then either gate supervised `update.run` handoffs before handoff creation and document that scope, or keep explicit `update.run` outside the kill-switch and document the operational workaround clearly.
