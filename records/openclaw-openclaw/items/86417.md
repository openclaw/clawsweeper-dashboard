## Summary

Keep open: current main and the latest stable release still separate the documented `OPENCLAW_NO_AUTO_UPDATE` background-auto-update kill-switch from the supervised Gateway `update.run` handoff path, so the requested operator contract is not implemented. The remaining blocker is maintainer product direction on whether that env var should become a hard stop for control-plane update restarts.

## What This Changes

The issue asks OpenClaw to document and honor an auto-update kill-switch for macOS launchd-managed Gateway restarts triggered by the `gateway-update` `update.run` path.

## Best Possible Solution

Maintainers should choose the kill-switch contract, then either gate Gateway-originated managed `update.run` handoffs before restart scheduling and update docs/tests, or document `OPENCLAW_NO_AUTO_UPDATE` as background-only while resolving update.run launchd reliability under https://github.com/openclaw/openclaw/issues/85246.
