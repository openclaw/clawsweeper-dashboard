## Summary

Keep open: current main and v2026.6.11 still scope `OPENCLAW_NO_AUTO_UPDATE` to configured startup/background auto-update applies, while supervised Gateway `update.run` can still create a managed handoff and schedule an `update.run` restart. This is a maintainer product-contract decision, not stale cleanup.

## What This Changes

Request to document and enforce an operator kill-switch for macOS launchd Gateway package/update.run restarts.

## Best Possible Solution

Maintainers should settle the kill-switch scope; if it should block headless update restarts, gate supervised `update.run` before managed-service handoff and update docs/tests, otherwise document explicit `update.run` as outside the env switch and keep launchd reliability work on the canonical handoff tracker.
