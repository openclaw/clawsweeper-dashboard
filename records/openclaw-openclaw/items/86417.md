## Summary

Keep open: current main and the latest stable release still scope `OPENCLAW_NO_AUTO_UPDATE` to configured startup/background auto-update applies, while supervised Gateway `update.run` can still create a managed handoff and schedule an `update.run` restart. This remains a maintainer product-contract decision, not stale cleanup.

## What This Changes

The issue requests a documented and reliable way for supervised/headless macOS Gateway operators to prevent `gateway-update` / `update.run` restart handoffs, preferably by honoring `OPENCLAW_NO_AUTO_UPDATE=1`.

## Best Possible Solution

Maintainers should decide the kill-switch contract, then either gate Gateway-originated managed `update.run` handoffs before restart scheduling and update public docs, or explicitly document that operator-triggered `update.run` is outside `OPENCLAW_NO_AUTO_UPDATE` and leave reliability work to the launchd update-run trackers.
