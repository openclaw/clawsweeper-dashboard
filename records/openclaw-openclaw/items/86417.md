## Summary

Keep open: current main still treats `OPENCLAW_NO_AUTO_UPDATE` as a startup/background auto-update kill-switch, while supervised Gateway `update.run` can still create a launchd managed-service handoff and schedule an `update.run` restart. This is a real source-level gap, but the remaining blocker is maintainer product direction for explicit control-plane update semantics.

## What This Changes

The issue requests a documented and honored kill-switch for macOS launchd Gateway package/background update restarts initiated through the gateway-update `update.run` handoff path.

## Best Possible Solution

Maintainers should define the operator contract for supervised Gateway updates, then either keep `OPENCLAW_NO_AUTO_UPDATE` scoped to background auto-update with clearer docs/UI wording, or add an explicit control-plane update-restart disable path with focused launchd/global-install tests.

- **Extend the env kill-switch to update.run:** Make control-plane `update.run` return a no-op or safe-command response when the env var is set, with launchd/global-install regression tests.
