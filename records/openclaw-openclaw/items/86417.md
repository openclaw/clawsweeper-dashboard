## Summary

Keep open: current main and the latest release still allow supervised Gateway `update.run` to start a launchd managed-service handoff and schedule an `update.run` restart, while `OPENCLAW_NO_AUTO_UPDATE` only gates configured startup/background auto-update. This remains a product contract decision, not stale cleanup.

## What This Changes

The issue asks OpenClaw to document and honor an auto-update kill-switch for macOS launchd Gateway restarts triggered through the `gateway-update`/`update.run` path.

## Best Possible Solution

Maintainers should define the kill-switch contract, then either gate supervised Gateway-originated `update.run` handoffs before restart scheduling and update the public docs, or explicitly document `update.run` as outside the kill-switch and keep launchd handoff reliability under the broader update-run issue.
