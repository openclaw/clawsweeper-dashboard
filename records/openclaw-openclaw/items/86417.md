## Summary

Keep open: current main and the latest release still keep `OPENCLAW_NO_AUTO_UPDATE` scoped to configured background auto-update applies, while supervised Gateway `update.run` can still start a managed handoff and schedule an `update.run` restart. The remaining question is maintainer product direction for the kill-switch contract, not stale cleanup.

## What This Changes

The issue asks OpenClaw to document and optionally honor the existing auto-update kill-switch for macOS launchd Gateway `update.run` restart handoffs.

## Best Possible Solution

Decide the kill-switch scope, then either gate Gateway-originated managed `update.run` handoffs before restart scheduling and update docs/tests, or explicitly document `update.run` as outside the auto-update kill-switch and leave launchd handoff reliability under the broader updater issues.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should `OPENCLAW_NO_AUTO_UPDATE=1` suppress explicit Gateway control-plane `update.run` managed handoffs, or only configured background auto-update applies?

Rationale: Current code and docs intentionally separate configured auto-update applies from explicit operator/admin `update.run`; changing that scope affects update policy, restart behavior, and operator expectations.

Likely owner: vincentkoc

Owner reason: vincentkoc introduced the kill-switch behavior and has recent updater/restart context around this exact contract boundary.

Owner confidence: high

Options:

- **Extend the kill-switch to update.run (recommended):** Treat the env var as a supervised/headless no-package-restart policy and block Gateway-originated managed `update.run` handoffs before scheduling the restart.
- **Keep the current narrow scope:** Document that `OPENCLAW_NO_AUTO_UPDATE` only blocks configured background applies and that explicit `update.run` remains an operator/admin restart path.
- **Add a separate explicit policy:** Keep the current env var narrow and introduce a clearer future policy surface for blocking control-plane package updates in managed services.
