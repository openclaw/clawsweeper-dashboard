## Summary

Keep open: current main and latest release still split the kill-switch contract from explicit control-plane `update.run`; `OPENCLAW_NO_AUTO_UPDATE` suppresses configured background auto-update applies, while supervised `update.run` can still start a managed handoff and schedule an `update.run` restart.

## What This Changes

The issue asks OpenClaw to document and honor an auto-update kill-switch for macOS launchd Gateway restart handoffs created by the Gateway update path.

## Best Possible Solution

Maintainers should decide the kill-switch scope, then either gate supervised `update.run` managed handoffs before they are created and update docs/tests, or explicitly document `update.run` as outside the kill-switch and point headless operators to the supported disablement path.

Options:

- **Extend the existing kill-switch (recommended):** Treat the env var as a package-update restart kill-switch across configured auto-update and supervised `update.run`, returning an explicit disabled result before creating a handoff.

- **Design a separate control-plane update policy:** Leave the existing env var unchanged and add a maintainer-approved policy surface for disabling or approval-gating explicit `update.run`.
