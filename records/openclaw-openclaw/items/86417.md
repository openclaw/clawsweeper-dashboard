## Summary

Keep open: current main and the latest release still scope `OPENCLAW_NO_AUTO_UPDATE` to configured startup/background auto-update applies, while supervised Gateway `update.run` can still create a managed handoff and schedule an `update.run` restart. This remains a product-contract decision about the kill-switch scope, not stale cleanup.

## What This Changes

The issue requests a documented, reliable kill-switch for launchd-managed Gateway package/background update restarts, preferably by honoring `OPENCLAW_NO_AUTO_UPDATE=1` before `gateway-update`/`update.run` handoffs are created.

## Best Possible Solution

Maintainers should decide the kill-switch contract, then either gate supervised Gateway-originated `update.run` handoffs with a clear refusal/status response and docs/tests, or explicitly document the env var as auto-update-only and keep launchd handoff reliability under the broader update-run tracker.
