## Summary

Keep open: current main and v2026.6.11 still scope `OPENCLAW_NO_AUTO_UPDATE` to configured startup/background auto-update applies, while supervised Gateway `update.run` can still create a managed handoff and schedule an `update.run` restart. The remaining work is a maintainer product contract decision, not stale cleanup.

## What This Changes

The issue asks OpenClaw to document and honor an auto-update kill-switch for macOS launchd-managed Gateway package/update.run restarts.

## Best Possible Solution

Maintainers should decide the kill-switch scope, then either gate supervised Gateway `update.run` handoffs before restart scheduling and update docs/tests, or explicitly document that `update.run` is outside the kill-switch and keep launchd reliability under the broader tracker.

Owner confidence: high

Options:

- **Extend kill-switch to managed update.run (recommended):** Gate supervised `update.run` handoffs before creating the handoff or scheduling restart, and document the env var as an operator hold for headless managed updates.
- **Document current split:** Keep `OPENCLAW_NO_AUTO_UPDATE` scoped to configured automatic applies and make docs state that explicit `update.run` remains allowed.
- **Add a separate explicit hold:** Introduce a distinct opt-in operator hold for control-plane update restarts, avoiding a meaning change for the existing auto-update env var.
