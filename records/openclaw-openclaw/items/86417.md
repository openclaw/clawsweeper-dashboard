## Summary

Keep open: current main and v2026.6.11 still limit `OPENCLAW_NO_AUTO_UPDATE` to startup/background auto-update applies, while supervised Gateway `update.run` can still start a managed handoff and schedule an `update.run` restart. The remaining work is a maintainer product-contract decision about whether that existing env kill-switch should also block explicit control-plane update restarts.

## What This Changes

The issue requests a documented and reliable operator kill-switch for macOS launchd Gateway package/background update restarts, preferably by honoring `OPENCLAW_NO_AUTO_UPDATE=1` before `gateway-update`/`update.run` restart handoffs are created.

## Best Possible Solution

Maintain a clear operator contract: either make `OPENCLAW_NO_AUTO_UPDATE=1` block Gateway-originated managed `update.run` handoffs before restart scheduling and document/test that scope, or explicitly document that it only disables configured background auto-update applies and keep launchd handoff reliability under the broader update-run trackers.

Options:

- **Extend the kill-switch to Gateway update.run (recommended):** Gate supervised managed `update.run` handoffs before restart scheduling when `OPENCLAW_NO_AUTO_UPDATE=1`, update docs, and require launchd proof for the resulting no-restart behavior.
- **Keep the kill-switch background-only:** Document that `OPENCLAW_NO_AUTO_UPDATE=1` only blocks configured auto-update applies and direct operators to avoid `update.run` or use broader launchd handoff fixes for explicit update requests.
- **Introduce a separate explicit-update policy:** Leave `OPENCLAW_NO_AUTO_UPDATE` as-is and design a new operator policy for control-plane updates, but treat that as a broader config/product change.
