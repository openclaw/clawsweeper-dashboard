## Summary

Keep open: current main and v2026.6.11 still scope `OPENCLAW_NO_AUTO_UPDATE` to configured startup/background auto-update applies, while supervised Gateway `update.run` can still create a managed handoff and schedule an `update.run` restart. This is a real operator-control gap, but the remaining blocker is maintainer product direction on the kill-switch contract rather than stale cleanup.

## What This Changes

The issue requests a documented, reliable way for macOS launchd/headless Gateway operators to disable Gateway package/background update restarts, preferably by honoring `OPENCLAW_NO_AUTO_UPDATE=1` before `gateway-update` creates a restart handoff.

## Best Possible Solution

Define the kill-switch scope first; if accepted, gate supervised Gateway-originated managed `update.run` handoffs before sentinel/restart scheduling, update the public docs and focused tests, and require live macOS launchd proof.

Question: Should `OPENCLAW_NO_AUTO_UPDATE=1` suppress Gateway control-plane `update.run` managed-service handoffs on launchd/headless deployments, or remain limited to configured `update.auto` background applies?

Rationale: The code boundary is clear, but changing the env variable would broaden a documented background-auto-update kill-switch into explicit control-plane update behavior that may be user- or UI-triggered.

Likely owner: Peter Steinberger

Owner reason: The decision is product/API scope for updater and Gateway restart behavior, and Peter's history covers both the core updater foundation and Gateway update restart flow.

Owner confidence: medium

Options:

- **Extend the existing kill-switch (recommended):** Block supervised Gateway-originated managed `update.run` handoffs before the restart handoff is created when `OPENCLAW_NO_AUTO_UPDATE=1`, while leaving explicit shell `openclaw update` available.
- **Keep the current split:** Document that `OPENCLAW_NO_AUTO_UPDATE` only blocks configured `update.auto` applies and leave explicit `update.run` reliability under the broader launchd update-run tracker.
- **Add a separate explicit-update guard:** Keep the current env semantics and introduce a new documented operator policy for disabling Gateway/UI/agent-triggered package update restarts.
