## Summary

Keep open: current main and the latest release still scope `OPENCLAW_NO_AUTO_UPDATE` to startup/background auto-update applies, while supervised Gateway `update.run` can still start a managed handoff and schedule an `update.run` restart. The remaining work is a maintainer product contract decision, not stale cleanup.

## What This Changes

The issue asks OpenClaw to document and enforce an operator kill-switch for macOS launchd Gateway `gateway-update` and `update.run` restarts.

## Best Possible Solution

Maintainers should decide the kill-switch scope, then either gate managed Gateway `update.run` handoffs before handoff creation and update docs/tests, or explicitly document `update.run` as outside the kill-switch and leave broader launchd handoff reliability to the related update-run tracker.
