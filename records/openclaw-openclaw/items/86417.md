## Summary

Keep open: current main and the latest release still split the contract so `OPENCLAW_NO_AUTO_UPDATE` suppresses configured background auto-update applies, while supervised Gateway `update.run` can still start a managed handoff and restart under launchd. This is still a product contract decision, not stale cleanup.

## What This Changes

The issue asks OpenClaw to document and honor an operator kill-switch for macOS launchd Gateway update restarts, preferably by making `OPENCLAW_NO_AUTO_UPDATE=1` block Gateway-originated `update.run` handoffs.

## Best Possible Solution

Maintainers should decide the kill-switch scope, then either gate Gateway-originated managed `update.run` handoffs before restart scheduling and update docs/tests, or document explicit `update.run` as outside the kill-switch and keep the broader launchd handoff reliability work on the canonical related tracker.
