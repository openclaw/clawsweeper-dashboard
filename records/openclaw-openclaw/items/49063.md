- **[P1] Require explicit channel authorization:** `extensions/telegram/src/bot-native-commands.ts:333-344`
  - body: For channel posts with `useAccessGroups` disabled and no `commands.allowFrom`, this branch passes an empty authorizer list into command gating, which allows the command even though the PR's stated boundary is explicitly allowed chats. That opens native/plugin command execution in any Telegram channel the bot can read under open access-group mode.
  - confidence: 0.9
- **[P1] Use sender_chat for channel allowlists:** `extensions/telegram/src/bot-native-commands.ts:227-228`
  - body: Channel posts usually identify the posting channel via `sender_chat`, but this auth path only fills `SenderId` from `msg.from`. When `commands.allowFrom.telegram` or owner allowlists are configured, the group-like auth context will not fall back to `From`, so intended channel identities can be rejected or mis-evaluated.
  - confidence: 0.88
- **[P1] Keep channel callbacks on channel auth/session:** `extensions/telegram/src/bot-handlers.runtime.ts:1142-1143`
  - body: Once channel native commands can show inline keyboards, callbacks from those messages still classify `chat.type === "channel"` as non-group and flow through direct-chat authorization/session state. That can drop `/models` follow-ups unless the clicking admin is separately DM-authorized, or update the admin's direct session instead of the channel session.
  - confidence: 0.86
