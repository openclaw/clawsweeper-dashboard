Full review comments:

- **[P1] Require an explicit channel command authorization source:** `extensions/telegram/src/bot-native-commands.ts:333-344`
  - body: When `useAccessGroups` is false and `commands.allowFrom` is unset, channel posts use an empty authorizer list. The shared gate treats that as allowed in `configured` mode, so any channel where the bot can see `/status` can execute native/plugin commands instead of only explicitly allowed chats.
  - confidence: 0.87
- **[P1] Normalize sender_chat before allowFrom checks:** `extensions/telegram/src/bot-native-commands.ts:602`
  - body: Switching command handlers to `ctx.msg` lets channel_post updates reach auth, but this path still derives the sender only from `msg.from`. Telegram channel posts usually carry the posting channel in `sender_chat`, and command auth does not use the group `From` value as a sender fallback, so configured `commands.allowFrom` or owner allowlists can reject the intended channel identity.
  - confidence: 0.82
- **[P1] Keep channel callbacks on the channel session:** `extensions/telegram/src/bot-native-commands.ts:860`
  - body: This makes channel plugin commands reachable, but inline-button callbacks are still handled by code that classifies `chat.type === "channel"` as non-group/direct. Commands that emit buttons can therefore drop follow-ups or mutate the clicking user's direct session instead of the channel conversation.
  - confidence: 0.78
