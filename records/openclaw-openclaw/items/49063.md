## Summary

## What This Changes

The PR changes Telegram native/plugin slash command handlers to read `ctx.msg`, treats `channel_post` messages as group-like command contexts, and adds channel-post authorization and keying tests.

## Best Possible Solution

Land only after the channel_post command path reuses current channel authorization/session semantics, maintainers decide the sender-scoped channel policy, and redacted Telegram proof covers allowed, denied, allowFrom, and callback flows.

## Reproduction Assessment

## Solution Assessment

No. Switching to `ctx.msg` is necessary, but the current PR is too one-sided because it does not carry over the existing channel_post authorization, sender_chat identity, and callback/session semantics.
