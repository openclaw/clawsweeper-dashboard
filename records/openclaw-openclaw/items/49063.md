## Summary

Keep open: current main still uses `ctx.message` for Telegram native/plugin slash-command handlers, so the reported `channel_post` command gap is not implemented on main; however, this branch is not merge-ready because it conflicts with main, bypasses the newer centralized ingress authorization path, leaves channel callback/session behavior unsafe, and lacks inspectable live Telegram proof.

## What This Changes

The branch changes Telegram native/plugin slash-command handlers to read `ctx.msg`/`channel_post`, authorize explicitly configured channel chats, and adds focused Telegram command authorization and keying tests.

## Best Possible Solution

Rebase and implement `channel_post` native/plugin command ingress through the current Telegram ingress resolver, with a maintained `allowFrom` policy, callback/session parity, focused tests, and redacted live Telegram proof.
