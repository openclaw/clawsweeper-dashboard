Full review comments:

- **[P1] Require an explicit channel authorizer:** `extensions/telegram/src/bot-native-commands.ts:333-356`
  - body: When `useAccessGroups` is false and `commands.allowFrom` is unset, channel posts pass an empty authorizer list into the shared configured-mode gate. That gate allows when nothing is configured, so any readable channel can invoke slash commands instead of only explicitly allowed chats.
  - confidence: 0.9
- **[P1] Normalize sender_chat before allowlist checks:** `extensions/telegram/src/bot-native-commands.ts:227-246`
  - body: This channel-post path still derives `SenderId` and `SenderUsername` only from `msg.from`. Telegram channel posts usually carry the posting identity in `sender_chat`, so `commands.allowFrom` and owner allowlists cannot see the intended channel identity.
  - confidence: 0.88
- **[P1] Keep channel callbacks on the channel session:** `extensions/telegram/src/bot-native-commands.ts:602`
  - body: Switching native handlers to `ctx.msg` makes channel commands that emit inline buttons reachable, but callback handling still treats `chat.type === "channel"` as non-group/direct context. Those follow-ups can be dropped or mutate the wrong session.
  - confidence: 0.84
