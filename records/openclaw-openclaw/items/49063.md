Full review comments:

- **[P1] Require explicit channel authorization:** `extensions/telegram/src/bot-native-commands.ts:344`
  - body: For channel posts with `useAccessGroups=false` and no `commands.allowFrom`, this branch passes an empty authorizer list into `configured` mode, which resolves to allow. That makes slash commands executable from any bot-readable channel instead of only explicitly allowed chats, so require an explicit channel authorizer or reuse the existing channel_post ingress gate.
  - confidence: 0.93
- **[P1] Populate sender_chat before allowFrom checks:** `extensions/telegram/src/bot-native-commands.ts:227-228`
  - body: This path derives command identity from `msg.from` only, but Telegram channel posts usually carry the channel identity in `sender_chat`; the ordinary channel_post pipeline synthesizes that before auth. With `commands.allowFrom` or owner allowlists configured, intended channel commands can be rejected because the allowed channel identity is never presented to command auth.
  - confidence: 0.91
- **[P1] Keep channel callbacks in channel context:** `extensions/telegram/src/bot-native-commands.ts:602`
  - body: Enabling `channel_post` commands also enables native/plugin commands that return inline keyboards, but the existing callback handler still treats `chat.type === "channel"` as non-group and resolves auth/session state through direct-message rules. Channel command follow-ups can be dropped or associated with the clicking admin's direct session unless callback routing is updated or interactive channel replies are blocked.
  - confidence: 0.89
