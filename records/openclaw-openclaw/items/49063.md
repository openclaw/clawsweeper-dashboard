## Summary

Keep open: this PR is paired with the still-open authorization policy issue at https://github.com/openclaw/openclaw/issues/49062 and contains useful candidate work, but it is not merge-ready because the channel_post command path still has authorization/session blockers and lacks real Telegram proof.

## What This Changes

This PR changes Telegram native and plugin slash command handlers to read `ctx.msg`/`channel_post`, routes channel posts through group-like command authorization, and adds channel-post command/keying tests.

## Best Possible Solution

Repair this as one Telegram policy change: require explicit channel gating, define sender_chat/allowFrom semantics with the canonical issue, keep callback/session routing channel-aware, add focused tests, and attach redacted live Telegram proof before merge.
