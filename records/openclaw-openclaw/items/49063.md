Full review comments:

- **[P1] Require explicit channel authorization:** `extensions/telegram/src/bot-native-commands.ts:333-357`
  - body: When `isChannelPost` is true and `useAccessGroups` is false, this branch passes an empty authorizer list into `resolveCommandAuthorizedFromAuthorizers(..., modeWhenAccessGroupsOff: "configured")`, whose no-config fallback is allow. That means a `/...` post in a channel can run without the explicit channel allow boundary promised by the PR whenever `commands.allowFrom` is unset.
  - confidence: 0.88
- **[P1] Populate sender_chat before allowFrom checks:** `extensions/telegram/src/bot-native-commands.ts:227-247`
  - body: The channel-post path still derives `senderId` and `senderUsername` only from `msg.from`, but Telegram channel posts normally identify the posting channel through `sender_chat`. As a result, deployments that use `commands.allowFrom` or owner-style command allowlists can reject intended channel posts even when the posting channel is the allowed identity.
  - confidence: 0.78
- **[P1] Keep channel callbacks in channel context:** `extensions/telegram/src/bot-native-commands.ts:333-341`
  - body: Authorizing channel-post commands also enables native/plugin commands that render inline buttons, but the sibling callback path still treats `chat.type === "channel"` as non-group and resolves authorization/session state from the clicking user's direct context. That can drop follow-ups or mutate the wrong session for interactive channel commands such as model selection.
  - confidence: 0.74
