Full review comments:

- **[P1] Require an explicit channel authorizer:** `extensions/telegram/src/bot-native-commands.ts:333-344`
  - body: For channel posts, this branch returns an empty `commandAuthorizers` list whenever `useAccessGroups` is false. The shared configured-mode gate treats that as open access, so a `/status` post in any readable Telegram channel is authorized when `commands.allowFrom` is unset, contrary to the PR's explicit-allowed-chat boundary.
  - confidence: 0.9
- **[P1] Populate sender_chat before allowFrom checks:** `extensions/telegram/src/bot-native-commands.ts:227-247`
  - body: Channel posts usually carry their actor in `sender_chat`, but this auth path still derives `senderId` and `senderUsername` only from `msg.from`. Deployments using `commands.allowFrom`, owner allowlists, or per-channel sender allowlists can therefore reject the intended channel identity or skip the same sender rules used by the regular channel_post pipeline.
  - confidence: 0.86
- **[P1] Keep channel callbacks on the channel session:** `extensions/telegram/src/bot-native-commands.ts:602`
  - body: Switching handlers to `ctx.msg` makes channel native commands with inline buttons reachable, but the callback handler still treats `chat.type === "channel"` as non-group/direct. Commands such as model menus can then drop follow-up clicks unless the clicking admin is DM-authorized, or resolve state against the admin's direct session instead of the channel session.
  - confidence: 0.82
