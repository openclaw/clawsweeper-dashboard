## Summary

Keep open: current main handles default-marked inherited cron `toolsAllow` safely for CLI runs, but the corrected report still matches an unresolved agent-side null-clear/creator-policy trap and a security-sensitive decision about how to handle stale or restricted allow-lists.

## What This Changes

The issue asks OpenClaw to stop silent agent-side cron `toolsAllow` no-ops and prevent inherited cron tool policies from creating CLI-backed jobs that cannot run.

## Best Possible Solution

Preserve the explicit CLI fail-closed guard, make restricted agent-side null clears return an explicit diagnostic instead of silently re-capping, and add only maintainer-approved narrow repair for provably stale default caps.
