## Summary

Keep open: current main already fixes the default `toolsAllow` failure for CLI-backed cron runs, but the model-facing cron tool still rewrites an explicit `toolsAllow: null` clear back into a creator-surface default when a creator allowlist is present, so the recovery path in this report is still actionable.

## What This Changes

The issue asks for isolated `agentTurn` cron jobs to stop retaining an auto-stamped `toolsAllow` that CLI backends cannot enforce, especially when `toolsAllow: null` is intended to clear it.

## Best Possible Solution

Keep the current default-marker CLI behavior, then make the cron tool preserve `toolsAllow: null` as an explicit clear signal so the service can delete the stored allowlist instead of re-stamping it.
