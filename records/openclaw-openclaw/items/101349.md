## Summary

Keep open: current main fixes the default-marker path for new/marked cron jobs, but the corrected issue still matches a source-reproducible residual where agent-side `toolsAllow: null` is recapped under restricted creator policy and flagless/stale cron allow-lists can still reach the CLI fail-closed guard.

## What This Changes

The issue asks OpenClaw to handle agent-created isolated cron jobs whose inherited `toolsAllow` policy cannot be enforced by `claude-cli`, and to make blocked agent-side clearing explicit instead of silent.

## Best Possible Solution

Preserve the explicit CLI fail-closed guard, add a maintainer-approved narrow repair or doctor path for stale auto-default cron caps, and make restricted agent-side clear attempts return an explicit error or documented safe clear path.
