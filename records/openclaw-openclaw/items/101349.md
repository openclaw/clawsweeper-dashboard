## Summary

Keep open: current main fixed the original default-marker CLI failure, but the report matches a still-unresolved residual state where flagless regression-window cron `toolsAllow` values can still reach the CLI fail-closed guard, while the agent-facing null-clear path is intentionally re-capped under a restricted creator surface.

## What This Changes

The issue reports that isolated `agentTurn` cron jobs for the `claude-cli` backend keep or recreate `toolsAllow` despite omitted/null payloads, causing scheduled runs to fail before execution.

## Best Possible Solution

Preserve the explicit CLI `toolsAllow` fail-closed guard, and add a maintainer-approved narrow repair path for stale auto-default cron caps, such as doctor/operator repair or a clearly scoped API/CLI behavior that does not clear explicit restrictions.
