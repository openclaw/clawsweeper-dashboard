## Summary

Keep this open: current main has the CLI default-marker mitigation, but the reported `toolsAllow: null` clear semantics are still split between the raw cron service and the model-facing cron tool, and changing that boundary needs a maintainer security decision.

## What This Changes

The issue reports that isolated cron `agentTurn` jobs get a default `toolsAllow`, cannot clear it with a null patch, and then fail when routed through the `claude-cli` backend.

## Best Possible Solution

Preserve the creator-surface security cap, but make clear semantics explicit: operator/raw Gateway clears should remain supported, restricted model-facing clears should either be rejected with a clear message or converted into a default-marked cap that the CLI path safely drops, and existing flagless broken jobs should have a documented or doctor-backed recovery path.
