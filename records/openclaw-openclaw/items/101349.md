## Summary

Current main already prevents the reported CLI-backend cron failure: auto-stamped default `toolsAllow` caps are marked as defaults and dropped before CLI execution, while explicit restrictions still fail closed and raw service updates can clear `toolsAllow` with `null`. The fix is current-main-only; it is not in v2026.6.11.

## What This Changes

The issue asks for isolated `agentTurn` cron jobs using a CLI backend to stop failing when default `toolsAllow` is auto-injected and `toolsAllow: null` appears not to clear it.

## Best Possible Solution

Keep the current main behavior and ship it: default cron tool caps remain marked and safe for CLI backends, while explicit per-cron restrictions continue to fail closed unless an embedded runtime is used.
