## Summary

Keep open: current main handles marked inherited defaults and preserves explicit restrictions, but the corrected report still has two actionable parts: restricted agent-side `toolsAllow: null` presents as a successful no-op, and a deterministic claude-cli capability mismatch can terminate the fallback chain. The open targeted PR addresses only the misleading clear behavior, while the July 16 production report shows the runtime/failover half still affects scheduled jobs. citeturn10view2turn1view0

## What This Changes

Make restricted agent-created cron policy updates report an explicit clear rejection and prevent claude-cli tool-policy incompatibility from unnecessarily terminating an otherwise viable provider fallback chain.

## Best Possible Solution

Land the explicit restricted-clear rejection, then keep claude-cli fail-closed for that candidate while classifying its deterministic `toolsAllow` incompatibility as a permanent, non-auth failover reason so another enforceable runtime can run the job.
