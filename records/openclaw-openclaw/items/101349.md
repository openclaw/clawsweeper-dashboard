## Summary

Keep open: current main fixed the ordinary default-marker cron/CLI failure and direct service null-clears, but flagless regression-window cron `toolsAllow` values can still reach the CLI fail-closed guard, while agent-tool null clears are intentionally re-capped under the creator tool surface.

## What This Changes

The issue asks OpenClaw to stop auto-injected cron `toolsAllow` values from breaking isolated `agentTurn` jobs on CLI backends and to provide a safe clear or repair path.

## Best Possible Solution

Preserve explicit CLI `toolsAllow` fail-closed behavior and add a maintainer-approved narrow repair path for stale auto-default cron caps, such as trusted CLI/API/doctor repair that can distinguish defaults from explicit restrictions.
