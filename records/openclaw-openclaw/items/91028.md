## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Mask credentials through Lobster's final env merge:** `extensions/lobster/src/lobster-runner.ts:313-314`
  - body: This deletes Gateway credential keys from `ctx.env`, but pinned Lobster builds the actual runtime env as `{ ...process.env, ...ctx.env }`. Absent keys do not mask values already in `process.env`, so `OPENCLAW_URL`/token values can still reach workflow shell steps; carry explicit sanitized overrides through the final runtime env and test that path.
  - confidence: 0.92
- **[P2] Preserve llm-task auth and model policy:** `extensions/lobster/src/lobster-tool.ts:277-288`
  - body: The adapter calls `runEmbeddedAgent` directly with only provider/model/timeout, while `llm-task` resolves plugin defaults, auth profiles, allowed models, thinking policy, stream params, token limits, and schema validation first. Reuse that policy path or document an approved replacement before exposing this provider.
  - confidence: 0.88
- **[P1] Avoid shadowing Lobster's HTTP openclaw provider:** `extensions/lobster/src/lobster-tool.ts:323-326`
  - body: Lobster resolves `ctx.llmAdapters[provider]` before its built-in HTTP providers, so registering a direct adapter as `openclaw` changes `llm.invoke --provider openclaw` in embedded runs. Use a distinct provider id or get maintainer approval and docs for that compatibility change.
  - confidence: 0.85
