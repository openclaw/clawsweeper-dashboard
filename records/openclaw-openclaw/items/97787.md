## Summary

This PR remains necessary because current main does not preserve Feishu post-markdown single newlines, but it is not merge-ready: its limit fallback restores the reported cramped rendering for newline-heavy messages, and the branch has no real Feishu after-fix proof. The proof-positive sibling is currently conflicting, so it is not a safe superseding close target.

## What This Changes

The PR adds Feishu-local post-markdown newline materialization with fence and raw-table preservation, threads account configuration into sends, and falls back to unmaterialized text when expansion exceeds the configured chunk limit.

## Best Possible Solution

Normalize Feishu post text once after routing and table conversion, rechunk normalized sends within the configured limit with reply metadata only on the first continuation, reject oversized normalized edits explicitly, and prove the complete path in a real Feishu client or API sandbox.
