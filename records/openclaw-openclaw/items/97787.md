## Summary

This PR remains useful but is not merge-ready: the current head fixes post-expansion rechunking for direct sends, yet non-card reply paths still length-chunk text before `sendMessageFeishu`, so a fenced block crossing the limit loses its opening-fence context and the new per-chunk materializer can insert blank lines inside code. The proof-positive sibling PR is currently conflicting with failing checks, so it is not a safe canonical target for closing this PR as superseded.

## What This Changes

Adds Feishu post-markdown single-newline materialization, account-aware rechunking for expanded sends, edit-length guarding, and regression tests for prose, tables, fences, mentions, and limits.

## Best Possible Solution

Table-convert and materialize complete non-card Feishu post markdown exactly once before chunking, then pass explicitly pre-normalized chunks to the final sender while preserving first-chunk-only reply and mention metadata.
