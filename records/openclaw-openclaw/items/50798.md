## Summary

Keep open: current main still lacks a supported visible coordinator-to-ACP-thread delivery contract that avoids creating main Discord thread-session metadata. Related fixes cover reply mirroring and ACP task completion delivery, but not the initiating visible instruction path or the proxy-only session-state/security boundary.

## What This Changes

Request a supported visible coordinator-to-ACP-thread delivery path that posts into a Discord-bound ACP session without creating main Discord thread sessions.

## Best Possible Solution

Add one explicit, authorized visible ACP-thread delivery contract that posts the coordinator instruction to the intended Discord thread, bypasses main-session metadata only for that call, preserves normal mirroring elsewhere, and includes focused source tests plus live Discord/ACP proof.

Rationale: The code can support several shapes, but choosing between sessions_send visibility, message proxy-only delivery, or an ACP-bound-thread exclusion changes public API semantics, sender authorization, bot-loop behavior, and upgrade expectations.

Owner confidence: high

Options:

- **Add sessions_send visible mode (recommended):** Add a narrow visible delivery mode to sessions_send for authorized ACP-bound targets, with proof that it posts visibly without recording a main Discord thread session.
- **Add proxy-only message send:** Add an explicit message proxy-only path that bypasses outbound session recording only for authorized proxy sends while leaving ordinary message sends unchanged.
- **Decline core API change:** Keep this as plugin/community orchestration work and document that core does not support visible coordinator-to-worker proxy sends without session metadata side effects.

## Reproduction Assessment

No live dual-account Discord ACP reproduction was run. Source inspection gives a high-confidence way to verify the central gap: current schemas lack visible/proxyOnly, sessions_send injects internally with deliver:false, and message sends still prepare outbound mirror metadata.

## Solution Assessment

Unclear until maintainer direction is chosen. A narrow sessions_send visible mode looks safer than a broad ACP-bound-thread exclusion, but the API and authorization boundary need explicit product/security approval first.
