## Summary

Keep open: current main still lacks a supported visible coordinator-to-ACP-thread send or proxy-only Discord delivery path, while the adjacent ACP reply-delivery work only covers worker output returning to a bound thread.

## What This Changes

Request a supported way for coordinator agents to send visible instructions into ACP thread-bound Discord sessions without creating main-agent Discord thread session metadata.

## Best Possible Solution

Maintainers should choose one narrow visible ACP-thread delivery contract that posts the coordinator instruction through an authorized account while bypassing main-session metadata only for that explicit path.

## Reproduction Assessment

No live dual-account Discord ACP reproduction was run. Source inspection does give a high-confidence code-level reproduction of the missing capability: current schemas and tools lack the requested visible/proxy-only fields, and outbound sends still create mirror session metadata.

## Solution Assessment

Unclear; the issue's proposed options are plausible but not yet a maintainer-approved best fix. The safest path is to choose the API and trust boundary first, then implement the smallest contract with focused tests and live Discord/ACP proof.
