## Summary

Keep open: current main and the latest release still lack a supported visible coordinator-to-ACP-thread send or proxy-only Discord delivery contract, and the remaining choice is a product/security API decision rather than stale cleanup.

## What This Changes

The issue requests a visible coordinator-to-ACP Discord thread delivery path that avoids creating main-agent Discord thread session metadata.

## Best Possible Solution

Add one explicit, authorized visible ACP-thread delivery contract that posts the coordinator instruction to the intended Discord thread, bypasses main-session metadata only for that call, preserves normal mirroring elsewhere, and includes focused source tests plus live Discord/ACP proof.

Rationale: The code can support more than one narrow fix shape, but choosing between a sessions_send API extension, a message proxy-only path, or an ACP-bound-thread exclusion rule changes public API semantics, upgrade behavior, and security boundaries.

Likely owner: steipete

Options:

- **Define Narrow Visible ACP Send (recommended):** Add an explicit sessions_send-style visible delivery mode scoped to authorized ACP-bound sessions and prove it does not create unintended main-session metadata.
- **Define Proxy-Only Message Send:** Add a message/gateway send bypass for authorized proxy delivery while preserving normal outbound mirroring for every other send path.
- **Decline Core API For Now:** Keep the relay pattern plugin-owned or ClawHub-owned, accepting that the current core surfaces cannot fully avoid the reported session-stub side effect.
