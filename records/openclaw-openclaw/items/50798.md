## Summary

Keep open: current main still lacks a supported visible coordinator-to-ACP-thread send path and still records outbound Discord session metadata for normal sends, so the central route-pollution problem remains a product/security API decision rather than cleanup-ready stale work.

## What This Changes

The issue requests a visible agent-to-agent delivery path into ACP-bound Discord threads without creating extra main-agent Discord thread sessions.

## Best Possible Solution

Maintainers should choose one explicit visible proxy-delivery contract, keep normal outbound session metadata intact by default, and require tests plus live Discord ACP proof that the chosen path posts visibly without creating an extra main Discord thread session.

## Reproduction Assessment

No live reproduction was run, but source inspection gives a high-confidence current-main reproduction of the missing capability: neither sessions_send nor Gateway send accepts the requested visible/proxy-only control, and normal outbound sends still write session metadata.

## Solution Assessment

Unclear as a final product choice. The requested behavior is valid, but maintainers need to choose the durable API and authorization boundary before implementation because the three proposed options affect different core routing and security surfaces.
