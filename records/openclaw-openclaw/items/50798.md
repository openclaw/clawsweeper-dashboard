## Summary

Keep open: current main still lacks a supported visible coordinator-to-ACP-thread instruction path or a proxy-only Discord send that avoids main-session route metadata creation; adjacent ACP reply-delivery work does not close this product/API gap.

## What This Changes

Request a visible coordinator-to-worker message path for ACP thread-bound Discord sessions without creating `agent:main:discord:channel:<thread_id>` route/session stubs.

## Best Possible Solution

Maintainers should choose one narrow visible proxy-delivery contract with explicit authorization semantics, then require tests proving visible post delivery, no extra main Discord thread session stub, preserved normal mirroring elsewhere, and redacted live Discord ACP proof.

## Reproduction Assessment

No live reproduction was run, but source inspection shows the current missing contract: `sessions_send` is internal/non-delivered input and outbound Discord sends still ensure session metadata.

## Solution Assessment

No single proposed option is clearly best yet; the correct fix depends on maintainer choice of API surface, authorization boundary, and how narrowly metadata creation may be bypassed.
