## Summary

Keep open: current main and the latest stable release still lack a supported visible coordinator-to-ACP-thread send path or proxy-only Discord delivery mode, and the merged ACP thread-delivery work only covers a narrower terminal-completion path.

## What This Changes

The issue requests visible coordinator-to-ACP-thread delivery for Discord A2A workflows without creating main-agent Discord thread session metadata.

## Best Possible Solution

Maintainers should choose one narrow visible ACP-thread delivery contract, then require tests and live Discord/ACP proof that it posts the coordinator instruction to the intended thread without creating unintended main-session metadata.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which visible coordinator-to-ACP-thread delivery contract should OpenClaw support without creating main Discord channel-session metadata?

Rationale: The choices alter public tool/API semantics, session ownership, and Discord account authorization, so code inspection cannot safely choose the product boundary without maintainer intent.

Likely owner: steipete

Owner reason: steipete has the strongest history across sessions_send, outbound mirroring, Discord route handling, and the product/security boundary that this decision touches.

Owner confidence: high

Options:

- **Add visible sessions_send semantics (recommended):** Expose an explicit visible A2A send that posts the coordinator-authored instruction to the target ACP-bound route while preserving target-session ownership.
- **Add proxy-only message delivery:** Allow a message or gateway send to bypass outbound main-session mirroring only for an authorized proxy call with strict account and thread checks.
- **Defer to plugin orchestration:** Keep core behavior unchanged and require supervised A2A orchestration to live in plugins unless a narrower core API gap is approved.

## Reproduction Assessment

No live dual-Discord-account ACP reproduction was run, but current source and v2026.6.11 verify the requested visible/proxy-only fields are absent and existing sends still use internal delivery or outbound session mirroring.

## Solution Assessment

No single proposed option is clearly best yet; maintainers need to choose whether the contract belongs on sessions_send, message/gateway send, or a narrower Discord/ACP routing policy.
