## Summary

Keep open: current main still lacks a supported visible coordinator-to-ACP-thread send path or proxy-only Discord delivery mode, and adjacent ACP reply-delivery work does not solve the initiating visible instruction path without main-session metadata creation.

## What This Changes

The issue requests visible coordinator messages into ACP-bound Discord worker threads without creating `agent:main:discord:channel:<thread_id>` sessions.

## Best Possible Solution

Maintainers should choose one narrow visible ACP-thread delivery contract, then require tests and live Discord/ACP proof that it posts the coordinator instruction to the intended thread without creating unintended main-session metadata or weakening bot/account authorization.

## Reproduction Assessment

No live dual-Discord-account ACP reproduction was run, but current source verifies the requested visible/proxy-only fields are absent and existing sends still use internal delivery or outbound session mirroring.

## Solution Assessment

No single proposed option is clearly best yet. Option A changes sessions_send semantics, Option B changes message/gateway send semantics, and Option C changes Discord/ACP routing policy, so maintainers should choose the API and trust boundary first.
