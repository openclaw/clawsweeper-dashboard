## Summary

Keep open: current main and v2026.6.11 still lack the requested supported visible coordinator-to-ACP-thread send or proxy-only Discord delivery mode, while related ACP delivery work only covers narrower reply/completion routing cases.

## What This Changes

The issue requests a visible coordinator-to-ACP Discord thread delivery path that avoids creating or routing through a main Discord channel session.

## Best Possible Solution

Maintainers should choose one narrow visible ACP-thread delivery contract, document its authorization rules, and require tests plus live Discord/ACP proof that the coordinator instruction appears in the intended thread without unintended main-session metadata.

## Maintainer Decision

Kind: product_direction

Question: Which visible coordinator-to-ACP-thread delivery contract should OpenClaw support without creating main Discord channel-session metadata?

Rationale: The options change public tool/API semantics, session ownership, Discord account authorization, and bot-loop behavior, so code inspection alone cannot choose the durable product boundary.

Likely owner: steipete

Owner reason: steipete has the strongest combined history across sessions_send, gateway send schemas, outbound mirroring, and routing/product boundary work.

Owner confidence: high

Options:

- **Add visible sessions_send semantics (recommended):** Expose an explicit visible A2A send that posts the coordinator-authored instruction to the target ACP-bound route while preserving target-session ownership.
- **Add proxy-only message delivery:** Allow an authorized message or gateway send to bypass outbound main-session mirroring only with strict account, thread, and binding checks.
- **Defer to plugin orchestration:** Keep core behavior unchanged and require supervised visible A2A orchestration to live in plugins unless a narrower core API gap is approved.

## Reproduction Assessment

No high-confidence live reproduction was run. Source inspection confirms the requested visible/proxy-only fields are absent on current main and the latest release, and normal sends still use internal delivery or outbound session mirroring.

## Solution Assessment

Unclear as a final implementation choice. The issue is real, but maintainers need to choose whether the narrow contract belongs on sessions_send, gateway/message send, or a Discord/ACP routing rule before code is the best fix.
