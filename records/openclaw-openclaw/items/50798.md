## Summary

Keep open: current main still lacks a supported visible coordinator-to-ACP-thread send or proxy-only Discord delivery contract, and the related merged/open work covers reply or terminal delivery rather than the initiating visible instruction path without main-session metadata creation.

## What This Changes

The issue requests visible coordinator-to-ACP-thread messaging for ACP Discord sessions without creating `agent:main:discord:channel:<thread_id>` session metadata.

## Best Possible Solution

Add one explicit, authorized visible ACP-thread delivery contract that posts the coordinator instruction to the intended Discord thread, bypasses main-session metadata only for that call, preserves normal mirroring elsewhere, and includes focused source tests plus live Discord/ACP proof.

Rationale: The code can support several narrow fixes, but selecting between a sessions_send extension, a proxy-only message send, or an ACP-bound-thread exclusion changes public API semantics, compatibility behavior, and security boundaries.

- **Define Proxy-Only Message Send:** Add a `message` or gateway-send bypass for authorized proxy delivery while preserving normal outbound mirroring for every other send path.
- **Decline Core API For Now:** Keep the workaround/plugin direction and document that current core does not support proxy-visible ACP coordination without session metadata side effects.

No live dual-account Discord ACP reproduction was run, but current source gives a clear reproduction of the central gap: no visible/proxy-only schema fields, internal-only sessions_send delivery, and normal outbound session metadata writes.

## Solution Assessment

No single proposed option is clearly best yet; a narrow visible ACP delivery contract looks safer than a broad ACP-bound-thread exclusion, but maintainers need to choose the public API and authorization boundary first.
