## Summary

Keep open: current main still lacks a supported visible coordinator-to-ACP-thread send or proxy-only Discord delivery contract, and the remaining choice is a product/security boundary rather than stale cleanup.

## What This Changes

Request a supported visible coordinator-to-ACP-thread delivery path that avoids creating main Discord thread session metadata.

## Best Possible Solution

Define one narrow authorized visible ACP-thread delivery contract that posts the coordinator instruction to the intended Discord thread, bypasses main-session metadata only for that call, preserves normal message mirroring elsewhere, and ships with source tests plus redacted live Discord/ACP proof.

- **Define Narrow Visible ACP Send (recommended):** Add an explicit sessions_send-style visible mode scoped to authorized ACP-bound sessions and prove it avoids unintended main-session metadata.
- **Define Proxy-Only Message Send:** Add a message/gateway send bypass for authorized proxy delivery while preserving normal outbound mirroring everywhere else.
- **Decline Core API Change:** Keep this in plugin/community space and document that current plugin workarounds cannot bypass main-session metadata without a future core seam.

## Solution Assessment

Unclear until maintainers choose the API and security boundary. A narrow explicit visible ACP delivery contract looks safer than a broad ACP-bound-thread exclusion, but either direction needs owner-approved semantics and proof.
