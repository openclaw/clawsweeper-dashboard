## What This Changes

The PR removes the second best-effort registry snapshot write after subagent task setup and adds queued and running regression tests that assert one persistence call per registration.

## System Context

The subagent registry records each queued or running child-agent run before OpenClaw creates detached task work and starts gateway completion handling. Persisted registry updates feed cleanup and wait flows, so their ordering determines both durable run state and listener wakeups.

## Architecture Diagram

  C --> D[Create queued or running task]

  F --> G[Wait for completion]

## Best Possible Solution

Keep the single durable write if the direct source pass confirms that no registry mutation or subscriber-required notification can occur between it and sweeper startup; retain the focused one-write regression coverage.
