## Summary

This is a useful optional Slack feature, but the current head is not merge-ready: it performs file I/O in the Home-event hot path, fails to publish the documented default fallback when Slack rejects a custom payload, leaves generated config metadata stale, and has changed-file lint failures. The PR also lacks after-fix proof from a real Slack workspace.

## What This Changes

The PR adds configurable inline or file-backed Slack App Home views with account-level overrides, validation, fallback behavior, documentation, and tests.

## Best Possible Solution

Use one canonical Slack App Home configuration path, resolve any file-backed input outside the event hot path, and retry once with the built-in view when Slack rejects a custom payload.
