## Summary

Keep open: current main and v2026.6.11 still route `sessions_send` turns as `inter_session`/`message_tool_only`, still teach exact skip/no-reply control tokens, and still suppress those exact tokens before visible channel delivery. The open requester-return-path PR and broader structured handoff issue overlap, but neither has merged as the canonical fix for this WhatsApp explicit-delivery symptom.

## What This Changes

Issue requests that explicit WhatsApp `inter_session` delivery requests produce a normal channel message instead of being suppressed by `REPLY_SKIP`, `ANNOUNCE_SKIP`, or `NO_REPLY` heuristics.

## Best Possible Solution

Keep this issue as the WhatsApp/source-reply acceptance case and land a maintainer-approved A2A fix that preserves stable prompt keys, gives explicit delivery requests a message-tool source-reply path, and coordinates typed handoff semantics with the broader structured handoff issue.
