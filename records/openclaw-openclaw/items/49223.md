## Summary

Keep open: current main still routes `sessions_send` target turns as `inter_session` with `message_tool_only`, still teaches `REPLY_SKIP`/`ANNOUNCE_SKIP`, and still suppresses exact skip or `NO_REPLY` tokens before visible delivery. The open requester-return-path PR is a plausible fix candidate, and the broader structured handoff issue overlaps, but neither has merged as the canonical fix for this WhatsApp explicit-delivery symptom.

## What This Changes

The issue reports that explicit WhatsApp `inter_session` delivery requests can be suppressed as `REPLY_SKIP`, `ANNOUNCE_SKIP`, or `NO_REPLY` instead of posting a normal group reply.

## Best Possible Solution

Keep this issue as the WhatsApp/source-reply acceptance case and land a maintainer-approved A2A fix or repaired successor PR that distinguishes explicit delivery intent from coordination chatter, preserves prompt-cache and security boundaries, and adds regression coverage forbidding silent-token suppression for the explicit-delivery case.
