## Label Justifications

- `P2`: The issue describes a real, bounded sessions_send/WhatsApp delivery failure that needs maintainer review but is not an emergency runtime outage.
- `impact:message-loss`: The central symptom is a requested group message being suppressed as a skip/no-reply token instead of being delivered to the channel.

## Summary

Keep open: current main and the latest release still treat `sessions_send` target turns as generic `inter_session` input, still teach skip/no-reply control tokens, and still suppress those tokens before visible channel delivery. The open requester-return-path PR and broader structured handoff issue overlap, but neither is a merged canonical fix for this WhatsApp explicit-delivery symptom.

## What This Changes

The issue requests that explicit WhatsApp `inter_session` delivery requests emit the intended group message instead of being suppressed as `REPLY_SKIP`, `ANNOUNCE_SKIP`, or `NO_REPLY`.

## Best Possible Solution

Review and either repair/land or explicitly supersede https://github.com/openclaw/openclaw/pull/97311, then align the final behavior with https://github.com/openclaw/openclaw/issues/33478 so explicit delivery intent outranks skip tokens without reintroducing ping-pong or duplicate delivery.
