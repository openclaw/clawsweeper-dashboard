## Summary

Keep open: current main still injects `sessions_send` target turns as `inter_session`, still teaches `REPLY_SKIP` and `ANNOUNCE_SKIP`, and still suppresses exact silent/control tokens before visible delivery. The nearest open PR is a plausible candidate, but it is unmerged and the durable fix still needs maintainer choice because it changes model-facing A2A delivery semantics.

## What This Changes

The issue asks OpenClaw to stop suppressing explicit WhatsApp inter-session delivery requests as `REPLY_SKIP`, `ANNOUNCE_SKIP`, or `NO_REPLY` when the target should emit a normal channel message.

## Best Possible Solution

Keep this as the WhatsApp/source-reply acceptance case and land a maintainer-approved A2A fix or repaired successor PR that distinguishes explicit delivery intent from coordination chatter, preserves prompt-cache and security boundaries, and adds regression coverage forbidding silent-token suppression for explicit delivery.
