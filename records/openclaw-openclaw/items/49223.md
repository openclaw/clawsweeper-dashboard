## Label Justifications

- `P2`: The issue describes a bounded sessions_send delivery reliability problem that can suppress expected channel output without making the core runtime unusable.
- `impact:message-loss`: The reported failure mode silently drops an intended outbound group message when a control-token path wins over delivery intent.

## Summary

Keep open: current main and v2026.6.11 still model `sessions_send` as generic `inter_session` data with no delivery-intent field, still teach skip/no-reply control tokens, and still suppress exact control replies before announce/channel delivery. Related structured handoff issues overlap but do not replace this WhatsApp explicit-delivery symptom.

## What This Changes

Requests that explicit `inter_session` delivery requests to WhatsApp group sessions produce normal channel messages instead of being suppressed by `REPLY_SKIP`, `ANNOUNCE_SKIP`, or `NO_REPLY`.

## Best Possible Solution

Define a maintainer-approved `sessions_send`/inter-session delivery-intent contract that preserves legitimate silent coordination while making explicit channel delivery requests produce normal outbound messages, with focused A2A and WhatsApp-like group regression coverage.

## Reproduction Assessment

No high-confidence live WhatsApp reproduction was established in this read-only review. Source inspection gives a medium-confidence path: current main routes `sessions_send` as generic `inter_session`, invites skip tokens, and suppresses exact non-deliverable replies before channel delivery.

## Solution Assessment

No current implementation is ready to close this. The best fix needs maintainer choice between prompt narrowing, an explicit delivery-intent signal, or folding the behavior into the broader structured A2A handoff contract.
