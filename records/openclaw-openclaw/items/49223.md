## Summary

Keep open: current main and v2026.6.11 still route `sessions_send` target turns as generic `inter_session` messages, still teach exact skip/no-reply control tokens, and still suppress those tokens before visible channel delivery. Related handoff and dispatch-mode issues overlap, but none supersedes this WhatsApp explicit-delivery symptom.

## What This Changes

The issue asks OpenClaw to stop treating explicit WhatsApp inter-session channel-delivery requests as coordination chatter that may be suppressed with `REPLY_SKIP`, `ANNOUNCE_SKIP`, or `NO_REPLY`.

## Best Possible Solution

Define a maintainer-approved `sessions_send`/inter-session delivery-intent contract that preserves legitimate silent coordination while making explicit channel delivery requests produce normal outbound messages, with focused A2A and WhatsApp-like group regression coverage.

## Reproduction Assessment

No live high-confidence WhatsApp reproduction was run in this read-only review. Source inspection gives a medium-confidence reproduction path: current main routes `sessions_send` as `inter_session`, invites skip tokens, and suppresses exact non-deliverable replies before channel delivery.

## Solution Assessment

No current implementation is ready to close this. The best fix needs maintainer choice between prompt narrowing, a typed delivery-intent signal, or folding the behavior into the broader structured A2A handoff contract.
