## Summary

Keep this PR open. The shared avatar-cache direction addresses a real Control UI consistency problem, but the new authenticated image loader appears able to forward the connected Gateway credential to an absolute cross-origin profile avatar URL, creating a bearer-token disclosure path that must be closed before merge.

## What This Changes

The branch routes roster, profile, and chat avatars through a shared revision-aware blob cache so protected Gateway avatars load once and remain consistent across Control UI surfaces.

## System Context

Control UI receives presence and profile avatar URLs from the connected Gateway, resolves them for several UI surfaces, and renders either an image or readable initials. This PR inserts an authenticated browser fetch and cache between avatar resolution and those rendered images.

## Best Possible Solution

Keep authenticated blob fetching limited to normalized avatar routes on the exact connected Gateway origin, render non-Gateway absolute URLs without Gateway credentials or reject them, then add regression coverage for a hostile cross-origin URL and attach redacted after-fix browser or terminal proof.
