## Summary

Keep open. This is a fresh, narrowly described Control UI regression with a concrete selected-agent creation path; the supplied context does not establish that current main already carries the reported form-owner fix or that a merged PR owns it.

## What This Changes

Cron page creation paths for new, suggested, and immediately run tasks should include the selected agent in the `cron.add` request while leaving All Agents unbound and preserving an existing job’s agent on clone.

## System Context

The Control UI Cron page collects the selected agent and task-form values, then sends a `cron.add` request to the Gateway. The Gateway uses that job identity when scheduled work later chooses the agent/session to execute.

## Architecture Diagram

flowchart LR
  A[Selected Control UI agent] --> B[Cron task form]
  C[Suggested schedule or Create and Run] --> B
  B --> D[cron.add request]
  D --> E[Gateway cron service]
  E --> F[Stored scheduled job]
  F --> G[Selected agent execution]

## Best Possible Solution

Thread the selected agent through every new-job submission path in the Cron UI, retain omission for All Agents, preserve the source agent for cloned jobs, and lock those cases with focused UI request-payload regressions.
