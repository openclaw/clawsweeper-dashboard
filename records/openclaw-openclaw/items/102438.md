- **[P2] Adopt the locked relog winner during CAS recovery:** `src/agents/auth-profiles/oauth-manager.ts:502`
  - body: The recovery path first reloads the store outside the lock, and only enters the locked update when that snapshot still has the same OAuth identity. If a user reauthenticates to a different account after that reload but before `updateAuthProfileStoreWithLock` runs, the updater returns false, `saved` stays false, and this line returns `null`, so `doRefreshOAuthTokenWithLock` still throws even though the canonical store now contains a usable relogged credential. Use the store returned by the locked update, or move the same/different-identity decision wholly under the lock, and add a regression for that interleaving.
