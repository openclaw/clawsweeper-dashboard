## Summary

Keep open: current main still builds staged merge inputs as fresh synthetic user messages, and the LLM-facing serializer does not expose timestamps or source chunk labels, so a narrow compaction fix remains useful. I found adjacent compaction work, but no canonical duplicate or merged fix for this exact staged-merge metadata gap.

## What This Changes

The issue reports that staged compaction merge passes convert partial summaries into unlabeled synthetic user messages with fresh timestamps, losing source chunk chronology and origin metadata.

## Best Possible Solution

Annotate staged merge inputs with LLM-visible chunk order and source range metadata, then add a focused test proving the final merge call receives those labels without adding config or broad compaction architecture changes.
