## Summary

Keep this PR open, but do not merge yet: the revised cleanup now races `bot.stop()` with the runner shutdown even though grammY documents the runner handle as the shutdown owner, and the branch still lacks after-fix evidence from a real Telegram polling session.

## What This Changes

The PR replaces serial Telegram polling stop waits with one concurrent 15-second cleanup barrier and adds lease-handoff regression coverage.

## Best Possible Solution

Make the grammY runner handle the sole concurrent-polling shutdown barrier, retain the lease until that stop settles or the bounded deadline expires, and perform any demonstrably necessary bot-level cleanup only after the runner can no longer poll; then provide redacted live logs showing a stop and replacement-monitor handoff without a 409.
