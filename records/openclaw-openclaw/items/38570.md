The issue asks for sessions_send agent-to-agent prompt context to include the requester agent's configured identity name so the receiver does not infer the wrong sender.

## Best Possible Solution

Add the configured requester identity name to all initial, reply, and announce A2A prompt phases while preserving session placeholders and leaving routing/delivery behavior unchanged.
