## Summary

Keep open: current main still has a plausible voice-call/session lifecycle gap, and I did not find a merged fix or canonical replacement for this exact hangup-aborts-`sessions_spawn` behavior. The remaining decision is whether ordinary voice-call hangup should decouple already-starting independent child work from the parent call lifecycle.

## What This Changes

Request that voice-call hangup stop aborting already-starting `sessions_spawn` child sessions before the child run is accepted.

## Best Possible Solution

Define the lifecycle contract first, then make `sessions_spawn` child acceptance and registration survive ordinary voice-call hangup while explicit session reset/delete/stop still interrupt safely.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should ordinary voice-call hangup allow independent `sessions_spawn` work that has begun child initialization to survive, and should that decoupling live in the gateway/subagent lifecycle rather than in the voice-call plugin?

Rationale: The code shows a plausible abort and acceptance-order race, but deciding that hangup differs from explicit stop/reset changes product cancellation semantics across session lifecycle and subagent ownership.

Likely owner: steipete

Owner reason: steipete has the strongest recent history across session lifecycle, voice-call response, and subagent-adjacent runtime changes.

Owner confidence: high

Options:

- **Decouple accepted child spawn in gateway lifecycle (recommended):** Treat voice-call hangup as ending the call surface while preserving already-starting independent child work, with regression coverage that explicit stop/reset still cascades.
- **Add plugin-local grace during finalize:** Let the voice-call plugin wait briefly for embedded tool completion during teardown, accepting a narrower fix that may not cover other voice or lifecycle paths.
- **Keep hangup cancellation semantics:** Document the cron/background-work workaround and close this as intended behavior if maintainers want hangup to cancel all in-flight call work.

## Reproduction Assessment

Yes at source level, but not as a live hangup proof: voice responses run with lifecycle-admission abort signals, tools inherit the embedded-run abort, and `sessions_spawn` only records accepted children after the child gateway run returns.

## Solution Assessment

Unclear until maintainers choose the lifecycle boundary; a narrow gateway/subagent lifecycle fix is likely better than adding a new config knob or relying only on a voice-plugin grace timer.
