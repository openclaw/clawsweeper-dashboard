## Summary

Keep open: current main still shows a plausible voice-call/subagent lifecycle gap, and I did not find a merged fix or canonical replacement item for hangup-aborting `sessions_spawn` child startup. The remaining decision is whether phone-call hangup should behave differently from explicit stop/reset once child work is being spawned.

## What This Changes

The issue asks OpenClaw to keep independent `sessions_spawn` child work alive when a voice call hangs up instead of aborting it with the parent voice lane.

## Best Possible Solution

Define the hangup lifecycle contract, then add a bounded fix so accepted or initializing `sessions_spawn` children survive call teardown while explicit stop/reset paths still cascade, with a focused regression test and live voice-call proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should voice-call hangup preserve `sessions_spawn` child startup independently from the parent voice run, and should that be solved in the gateway/tool lifecycle or the voice-call plugin?

Rationale: Current docs establish non-blocking subagents and explicit `/stop` cascading, but they do not define whether a phone hangup is a stop event or a transport teardown that should spare accepted background work.

Likely owner: steipete

Owner reason: `steipete` is the strongest voice-call ownership signal and can route the final boundary decision to subagent/gateway owners if needed.

Owner confidence: high

Options:

- **Define Hangup-Safe Spawn Decoupling (recommended):** Treat hangup as transport teardown, keep deliberate stop/reset cascading, and implement the narrow lifecycle boundary where accepted or in-flight child startup can finish.
- **Keep Hangup As Stop:** Declare current cascading cancellation expected for voice calls and document that background work must be queued through cron or another detached path.
- **Use Plugin Grace Timeout:** Add a voice-call-local wait/grace path before teardown, accepting more timing complexity and a weaker cross-channel contract.

## Reproduction Assessment

No high-confidence runnable reproduction yet. Source inspection shows the plausible voice-lane abort and child-spawn acceptance path, but a live hangup or focused failing test is still missing for current main.

## Solution Assessment

Unclear until maintainers choose the lifecycle boundary. A gateway/tool-level accepted-spawn decoupling looks cleaner than a plugin-local grace timer if it preserves deliberate stop/reset semantics.
