## What This Changes

This PR adds opt-in Gateway readiness criteria, a public plugin readiness registration API, canonical readiness output across HTTP/RPC/status, and an `openclaw ready` command.

## System Context

Gateway readiness currently reports whether startup and channel runtime are healthy through `/ready` and `/readyz`. This PR would turn that fixed probe into a versioned readiness result that can include operator-selected core checks and bounded plugin-owned observations, then project it through Gateway and CLI status surfaces.
