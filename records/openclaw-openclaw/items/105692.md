## Summary

Close because current main does not share the cooldown-probe set across agents, tenants, auth stores, or fallback invocations, and the provider-level check runs only after every eligible profile for that provider and model is already cooldowned. The proposed profile-keyed change would instead undo an intentional and shipped safeguard against repeated slow probes across same-provider model fallbacks.

## What This Changes

Change cooldown-probe throttling from one transient probe per provider per fallback run to profile-scoped probe keys.

## Best Possible Solution

Keep the shipped one-transient-probe-per-provider-run invariant; if a distinct locked-profile or model-scoped case exists, file a new report with a current-main configuration showing an independently eligible credential being skipped.
