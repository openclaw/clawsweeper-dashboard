## Summary

Current main does not share the disputed throttle across tenants, agents, auth stores, or fallback invocations. The provider-level key is an intentional safeguard applied only after every eligible profile for that provider and model is cooldowned, so the proposed profile key would weaken established recovery behavior rather than correct the claimed isolation failure.

## What This Changes

Scope transient cooldown-probe consumption by provider and auth profile instead of provider alone during model fallback.

## Best Possible Solution

Keep the shipped one-transient-probe-per-provider-run invariant and investigate the distinct healthy-profile state disagreement in https://github.com/openclaw/openclaw/issues/105514 without adding profile-keyed repeated probes.

## Maintainer Decision

Required: false

## Reproduction Assessment

No. Current main creates the throttle Set per fallback invocation, loads profiles from the invocation's agent-scoped auth store, and reaches the disputed guard only after all eligible profiles for that provider and model are cooldowned.

## Solution Assessment

No. Provider/profile composite keying would permit repeated transient probes across same-provider model candidates and reverse the deliberate stall-prevention contract without demonstrating that a healthy or independently owned credential is skipped.
