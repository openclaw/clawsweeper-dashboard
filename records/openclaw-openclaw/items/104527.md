## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.99

Full review comments:

- **[P1] Persist the user-scoped Codex home across replacements:** `src/fleet/cell-profile.ts:281-284`
  - body: Fleet mounts `.openclaw` and `.config/openclaw` but not `$CODEX_HOME` or `~/.codex`. Native user-scoped Codex account, config, plugins, and threads therefore disappear on `fleet upgrade`, despite the stated per-cell Codex ownership. Persist a cell-owned Codex home and set `CODEX_HOME`, or explicitly prevent user-scoped Codex state in cells.
  - confidence: 0.99
- **[P1] Preserve the inspected image user during upgrade:** `src/fleet/service-support.runtime.ts:175-195`
  - body: `resolveContainerUser` preserves only numeric `uid:gid` values. The official image reports the named user `node`, so an upgrade by a non-root docker-group operator recreates both replacement and rollback containers as the host UID, which cannot read the uid-1000-owned 0700 mounts. Preserve named image users or map the official `node` identity to uid/gid 1000.
  - confidence: 0.99
- **[P2] Skip host ports already occupied outside Fleet:** `src/fleet/registry.ts:119-124`
  - body: Automatic allocation considers only ports recorded in `fleet_cells`. If another process or unrelated container already binds 19100, create fails, releases the reservation, and the next automatic create selects 19100 again. Probe host availability while allocating or retry the next port after a bind conflict.
  - confidence: 0.98
- **[P2] Add the documented Docker host-gateway mapping:** `src/fleet/cell-profile.ts:277-280`
  - body: Linux Docker cells join only the dedicated bridge, so the documented `host.docker.internal` route to host-side Ollama or LM Studio is unavailable. Add Docker's `--add-host=host.docker.internal:host-gateway` mapping while leaving Podman behavior runtime-specific.
  - confidence: 0.99
