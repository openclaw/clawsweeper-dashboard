## Summary

This issue is still necessary: current main creates the subagent session from the card’s agent identity but persists both the execution engine and default execution ID as Codex. The closed related report describes the same unresolved metadata defect for Claude; current source shows it was not fixed, so this open issue is the usable canonical report for the remaining work.

## What This Changes

Correct Workboard execution metadata so it identifies the runtime that actually executes a dispatched card instead of always recording Codex.

## Best Possible Solution

Make Workboard record a resolved runtime/provider identity returned by dispatch, or add a distinct agent-target field; update the execution schema, stored-ID policy, and cross-runtime dispatch coverage together rather than equating `agentId` with the actual executor.

## Reproduction Assessment

No live current-main run was performed, but source inspection provides a high-confidence path: dispatch a card with an `agentId`, then compare the agent-scoped session key with the unconditionally persisted Codex execution metadata.

## Solution Assessment

No: deriving `engine` directly from `card.agentId` can still misidentify the actual runtime because an agent ID and resolved provider/harness are different concepts. The repair should define and persist the resolved execution identity or a separate routing field.
