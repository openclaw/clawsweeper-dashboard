## Summary

Keep open: current main and v2026.6.11 still lack the requested per-autoJoin `sessionChannelId` field and automatic Discord text transcript/reply delivery. The shipped `voice.agentSession.target` surface partially solves shared session routing, but it is a global voice setting and voice ingress still suppresses automatic text delivery.

## What This Changes

Request adds an optional Discord voice `autoJoin.sessionChannelId` setting to route voice-session transcripts and replies to a paired text channel while audio playback continues in the voice channel.

## Best Possible Solution

Choose one canonical Discord voice text-bridge design, then land a revised implementation with typed config, validated delivery target, best-effort text mirroring, docs, and focused tests for default audio-only and mirrored text behavior.

## Reproduction Assessment

Yes, by source inspection: current main lacks `autoJoin.sessionChannelId`, strict config validation accepts only `guildId` and `channelId`, and voice agent turns still use `deliver: false`. I did not run a live Discord voice session in this read-only review.

## Solution Assessment

Unclear. A per-autoJoin field is plausible, but current main already has `voice.agentSession.target`, so maintainers should decide whether to extend that surface or add a distinct per-entry text mirror target.
