## Summary

Keep open: current main and the latest release still lack the requested per-autoJoin text-channel target and automatic Discord text delivery for voice transcripts/replies. The existing `voice.agentSession` target covers shared session routing, but it is a different global surface and the voice agent path still runs with `deliver: false`.

## What This Changes

Requests an optional Discord voice `autoJoin` text-channel session target that mirrors voice transcripts and agent replies into a paired text channel while keeping audio playback in voice.

## Best Possible Solution

Choose one canonical Discord voice bridge design, then land a reviewed implementation with typed config, explicit text-delivery semantics, same-guild target validation, docs, and tests for both default audio-only behavior and text-mirrored behavior.

Options:

- **Extend `voice.agentSession` with mirroring semantics (recommended):** Use the existing target-session surface as the canonical bridge and add explicit opt-in transcript/reply delivery behavior there.
- **Accept per-autoJoin `sessionChannelId`:** Support fixed-room voice/text pairs directly on autoJoin entries, at the cost of a second routing concept beside `voice.agentSession`.
- **Do not add automatic mirroring:** Keep `voice.agentSession` as session routing only and require agents or tools to post Discord text explicitly when desired.

## Solution Assessment

Unclear. A per-autoJoin field is plausible, but maintainers should first decide whether automatic text mirroring belongs on that new per-entry surface or on the existing `voice.agentSession` target design.
