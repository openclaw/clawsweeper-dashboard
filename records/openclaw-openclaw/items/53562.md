## Summary

Keep open: current main and v2026.6.11 still lack the requested per-auto-join `sessionChannelId` field and automatic Discord text transcript/reply delivery. `voice.agentSession` partly solves target-session routing, and https://github.com/BingqingLyu/openclaw/pull/1341 is an open linked candidate, but the remaining config and delivery behavior still needs maintainer product/security review.

## What This Changes

Request adding an optional Discord voice `autoJoin.sessionChannelId` configuration field that routes auto-joined voice transcripts and replies into a paired text channel while keeping voice playback.

## Best Possible Solution

Choose one canonical Discord voice text-bridge design, then land a revised implementation with typed config, docs, same-guild text-channel validation, explicit Discord delivery targeting, mention handling, and focused voice/delivery tests.

Yes. Source inspection shows current main and v2026.6.11 only accept `guildId` and `channelId` for `voice.autoJoin`, and the Discord voice ingress path still uses `deliver: false`; I did not run a live Discord voice session.

## Solution Assessment

Unclear. A per-autoJoin field is plausible, but current main already has global `voice.agentSession` target routing, so maintainers should first choose the canonical config and text-delivery semantics.
