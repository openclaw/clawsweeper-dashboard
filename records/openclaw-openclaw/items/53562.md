Keep open: current main and v2026.6.11 have a partial `voice.agentSession` route for Discord voice turns, but the requested companion text-channel transcript/reply delivery is still missing because voice ingress still uses `deliver: false` and `voice.autoJoin` has no `sessionChannelId` field. ## What This Changes

The issue requests an optional Discord voice auto-join text-channel routing field so voice transcripts and replies can be delivered to a companion text session.

## Best Possible Solution

Settle the Discord voice bridge contract around the existing `voice.agentSession` target model or an explicitly justified per-autoJoin mapping, then land one reviewed implementation with text transcript/reply delivery, docs, and focused Discord voice tests.
