## Summary

Keep open: current main and the latest release still lack the requested per-auto-join `sessionChannelId` field and automatic Discord text transcript/reply delivery. `voice.agentSession` now covers target-session routing, but the remaining mirroring behavior still needs maintainer product and security direction.

## What This Changes

The issue requests Discord voice `autoJoin` entries to accept a companion text-channel target so voice transcripts and replies can also appear in text while audio playback continues.

## Best Possible Solution

Choose the canonical Discord voice bridge design, then land a revised implementation with typed config, same-guild text-target validation, explicit delivery semantics, mention policy, docs, and focused Discord voice/delivery tests.

## Reproduction Assessment

Yes, by source inspection. Current main and `v2026.6.11` type/schema `autoJoin` entries only as `guildId` plus `channelId`, and the Discord voice agent turn still sets `deliver: false`; no live Discord voice run was attempted in this read-only review.

## Solution Assessment

Unclear. A per-autoJoin field is plausible, but current main already has global `voice.agentSession` target routing, so maintainers should first choose the canonical config, delivery, validation, and mention semantics.
