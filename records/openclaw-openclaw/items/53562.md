## Summary

Keep open: current main and the latest release still lack the requested per-autoJoin `sessionChannelId` config and automatic Discord text transcript/reply delivery. The existing `voice.agentSession` target path partly solves shared session routing, but it is a different global surface and voice turns still run with `deliver: false`; the linked implementation candidates are unmerged and need maintainer product/security review.

## What This Changes

Add optional Discord voice `autoJoin.sessionChannelId` routing so a fixed voice room can mirror STT transcripts and agent replies into a paired text channel while audio playback continues in voice.

## Best Possible Solution

Choose the canonical Discord voice bridge design, then land a revised implementation with typed config, explicit delivery target semantics, same-guild text-channel validation, best-effort mirroring, docs, focused tests, and redacted live Discord proof.
