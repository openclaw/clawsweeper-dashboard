## Summary

Keep open: current main and v2026.6.11 still lack the requested per-autoJoin `sessionChannelId` field and automatic Discord text transcript/reply delivery. The linked open fork PR is an implementation candidate, but it is conflicting and the remaining design touches public Discord voice config, delivery targeting, and mention/security semantics.

## What This Changes

Request to let Discord voice `autoJoin` entries route voice-derived transcript and reply text to a paired text channel while audio playback continues in the voice channel.

## Best Possible Solution

Choose one canonical Discord voice bridge design, then land a revised implementation with typed config, explicit delivery target semantics, same-guild text-channel validation, mention/security policy, docs, and focused tests for both default audio-only and mirrored text behavior.
