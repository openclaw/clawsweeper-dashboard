## Summary

Keep open: current main and the latest release still do not expose `autoJoin[].sessionChannelId` or automatically deliver Discord voice transcripts/replies into a paired text channel. The shipped `voice.agentSession` target path partially solves session routing, but the requested text mirroring remains a product/security decision rather than implemented behavior.

## What This Changes

Request to add per-autoJoin Discord voice `sessionChannelId` routing so spoken turns use a paired text-channel session and produce visible transcript/reply text while voice playback continues.

## Best Possible Solution

Choose one canonical Discord voice bridge design, then land a revised implementation with typed config, explicit delivery target semantics, same-guild text-channel validation, mention handling, docs, and focused Discord voice/delivery tests.

## Reproduction Assessment

Yes for the missing requested behavior: current main and `v2026.6.11` still type/schema `autoJoin` entries as only `guildId` plus `channelId`, and voice agent turns still use `deliver: false`. I did not run a live Discord voice session in this read-only review.

## Solution Assessment

Unclear: a per-autoJoin field is plausible, but current main already has global `voice.agentSession` target routing, so maintainers should choose the canonical bridge config and text-delivery semantics before implementation.
