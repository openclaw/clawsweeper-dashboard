## Summary

Keep open: current main and latest release still lack the requested per-autoJoin `sessionChannelId` field and automatic Discord text transcript/reply delivery. Current `voice.agentSession` target routing partially addresses shared session state, but it is a different global config surface and `deliver: false` still suppresses automatic text delivery.

## What This Changes

The issue requests an optional Discord voice `autoJoin.sessionChannelId` setting so voice transcripts and replies can route to a paired text channel while audio remains in the voice channel.

## Best Possible Solution

Choose one canonical Discord voice bridge design, then land a revised implementation with typed config, explicit delivery target semantics, same-guild text-channel validation, mention/security handling, docs, and focused tests for default audio-only and text-mirrored behavior.

## Reproduction Assessment

Yes, by source inspection: current main lacks `autoJoin.sessionChannelId`, strict config validation accepts only `guildId`/`channelId`, and voice agent turns still set `deliver: false`. I did not run a live Discord voice session in this read-only review.

## Solution Assessment

Unclear. A per-autoJoin field is plausible, but current main already has global `voice.agentSession` target routing, so maintainers should first choose whether to extend that surface or add a distinct per-entry bridge target.
