## Summary

This PR should remain open because its happy path is well proven, but an overloaded target is disconnected before receiving `socket.drain`, with no defined reconnect or state-resynchronization contract. That unresolved behavior is a merge-blocking Gateway protocol decision.

## What This Changes

The PR adds a read-scoped `socket.drain` Gateway event for session teardown, targets both session-event and matching session-message subscribers, and uses close-on-overflow delivery for that event.

## Best Possible Solution

Keep the targeted drain notification, but define a bounded Gateway-owned overflow contract and prove authoritative client recovery—preferably an explicit disconnect reason followed by reconnect and full session-state resynchronization.
