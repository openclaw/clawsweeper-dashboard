## Summary

Keep open: current main still lacks the requested drain notification path, but this PR is not merge-ready because it adds a public Gateway event whose slow-consumer behavior can close existing session subscribers and whose client contract is not documented in the public protocol docs.

## What This Changes

The PR adds read-scoped `socket.drain` Gateway broadcasts for session reset/delete/new teardown, routes them to session event and message subscribers, exposes message-subscriber lookup on the request context, and adds gateway coverage.

## Best Possible Solution

Land this only after the Gateway event contract is documented and the slow-consumer semantics are either kept compatible by default or explicitly approved with focused saturated-buffer proof.

## Reproduction Assessment

Yes, from source inspection rather than a live repro: current main does not register or emit `socket.drain`, and lifecycle `sessions.changed` broadcasts only reach broad session subscribers with `dropIfSlow: true`. The PR’s own tests and logs cover normal after-fix delivery, not the saturated-buffer case.

## Solution Assessment

No, not yet: routing drains from the mutation path is a plausible owner-boundary fix, but the current patch leaves the public event contract undocumented and changes slow-client behavior without proof or maintainer approval. The safer path is to preserve existing slow-consumer behavior by default or document and test the intentional availability tradeoff.
