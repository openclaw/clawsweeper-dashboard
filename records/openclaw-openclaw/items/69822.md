## Summary

Keep this PR open for Gateway-owner review. The original session-eviction delivery improvement is concrete, but the branch still disables the gateway’s slow-subscriber safety bound and now also carries separate OpenAI-compatible admission behavior that needs exact-head real-run evidence or separation.

## What This Changes

The branch adds `socket.drain` delivery to session-message subscribers during reset/delete flows, while also retaining gateway work admission for detached OpenAI-compatible HTTP runs and mapping drain failures to HTTP 503 responses.

## Best Possible Solution

Define one bounded recovery contract for `socket.drain`—for example disconnecting slow subscribers and requiring a normal session resync—then keep that behavior isolated from the OpenAI-compatible admission fixes unless both paths receive exact-head runtime proof.
