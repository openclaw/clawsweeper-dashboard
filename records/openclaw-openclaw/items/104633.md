## Summary

This is a focused, technically correct root-cause fix with credible real CLI proof and no review defect. Keep it open for an explicit maintainer compatibility decision because merging will make hexadecimal and other non-decimal prefixed timeout tokens fail where current releases accept them.

## What This Changes

The PR changes MCP `--timeout` and `--connect-timeout` parsing to accept only finite decimal/scientific tokens and adds regression coverage that invalid hexadecimal input cannot create or mutate configuration.

## Best Possible Solution

Establish decimal/scientific notation as the supported MCP timeout flag contract, keep validation in the common CLI input helper, and retain regression coverage for rejection-before-write plus accepted decimal/scientific values.
