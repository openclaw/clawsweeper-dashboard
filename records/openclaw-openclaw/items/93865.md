## Repair Work Prompt

Repair the Mattermost cold-thread backfill concurrency defect in this PR. Under the default zero inbound debounce, same-thread posted events can overlap; `backfillMattermostThreadHistoryForMonitor` currently writes the session marker before the awaited fetch completes, so an overlapping turn skips recovery and dispatches without context. Add per-history-key in-flight coordination or another narrow mechanism that makes overlapping same-session turns await one bounded fetch, while preserving one-attempt-per-session semantics after success, empty response, timeout, or failure; preserve stored-session rotation, pending-marker adoption, admission ordering, marker eviction, and the bounded Mattermost request.
