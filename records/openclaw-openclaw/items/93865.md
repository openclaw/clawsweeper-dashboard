## Summary

Keep open: this is a real Mattermost thread-context recovery fix, but the current patch is not merge-ready because failed or timed-out backfill attempts are not marked as serviced, so a slow or erroring Mattermost thread endpoint can be retried on every same-session follow-up.

## What This Changes

The branch adds a Mattermost thread fetch helper, session-gated monitor backfill, and tests so cold thread history can be seeded from the server after restart or session reset.

## Best Possible Solution

Record one attempted backfill per thread history key and stored session id even on fetch failure or timeout, keep the current success/session gating, and land one canonical Mattermost plugin PR for the recovery behavior.

## Reproduction Assessment

Yes, at source level. Current main keeps Mattermost thread history in a process-local map, builds context from that map, and has no server-thread fetch before dispatch; I did not run a live Mattermost repro in this read-only review.

## Solution Assessment

No as submitted. The Mattermost plugin boundary and stored-session gate are the right shape, but the failure path must mark an attempted session so a slow or erroring server is not retried on every same-session follow-up.
