## What This Changes

The PR adds a Mattermost thread-history fetch helper, backfills cold thread context before inbound dispatch using the stored thread session id as the gate, and expands tests for cold start, reset, no-refetch, timeout, and failed-fetch behavior.

## Best Possible Solution

Land one canonical Mattermost plugin fix that backfills thread context only on recovery, keeps same-session follow-ups off the server path, and retires the sibling candidate branches after maintainer selection.

## Reproduction Assessment

Yes. Current main keeps Mattermost thread history in a process-local map and builds inbound context from that map with no server-thread fetch, so restart or session-clear leaves the recovery turn without prior thread context.

## Solution Assessment

Yes, with maintainer selection still needed. The Mattermost plugin is the right owner boundary, and this branch improves the recovery gate by using the stored thread session id and marking failed attempts before fetch; the remaining question is which open candidate PR should be canonical.
