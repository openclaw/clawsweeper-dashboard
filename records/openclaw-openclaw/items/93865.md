## Summary

The recovery design is well targeted and backed by strong live Mattermost proof, but the new bounded request exceeds Mattermost’s hard page-size limit for supported high history settings, causing cold-thread recovery to fail for those configurations. After that mechanical fix, a Mattermost owner should confirm the deliberate awaited first-turn latency and one-attempt-per-session failure policy.

## What This Changes

The PR adds session-aware Mattermost server thread-history backfill for cold inbound thread turns, including bounded fetches, stale-session and concurrency coordination, marker eviction, and focused tests.

## Best Possible Solution

Cap or paginate the thread request within Mattermost’s 200-post contract, add a regression test for `historyLimit >= 200`, preserve the stale-session and concurrent-turn protections, then refresh the branch and obtain Mattermost owner approval for the awaited one-attempt-per-session policy.
