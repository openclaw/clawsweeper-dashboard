## Summary

The prior P2 blocker remains on the unchanged reviewed head: the new Mattermost thread request forwards `historyLimit + 1` without clamping it to the server's documented 200-item page maximum. The live Docker proof is strong and the session-aware owner boundary is reasonable, but merge should wait for that mechanical repair plus Mattermost-owner acceptance of the intentional cold-turn latency and one-attempt-per-session failure behavior.

## What This Changes

Adds session-aware Mattermost thread-history recovery from the server for cold inbound thread turns, with bounded timeouts, in-flight coordination, marker eviction, and regression coverage.

## Best Possible Solution

Clamp `perPage` to 200 with focused coverage for oversized limits, preserve chronological reconstruction, then land only after the Mattermost owner explicitly accepts the bounded cold-turn wait and no-retry-until-session-rotation policy.
