## Summary

The patch addresses a real prefix-bypass bug in the Swift auth retry path, but it is not merge-ready because the replacement parser also trusts `0.0.0.0` and `::`, widening the stored-device-token retry boundary, and the external real behavior proof gate is still unmet.

## What This Changes

The PR replaces the Swift Gateway auth-retry loopback prefix check with `LoopbackHost.isLoopbackHost` and adds a regression test for `127.attacker.example`.

## Best Possible Solution

Keep the prefix-bypass hardening, but use a retry-specific Swift host classifier that accepts real loopback hosts while rejecting `127.attacker.example`, `0.0.0.0`, and `::`, then add real behavior proof before merge.

## Reproduction Assessment

Yes for source reproduction: current main uses `host.hasPrefix("127.")` in the Swift device-token retry trust gate, so `127.attacker.example` is accepted before this patch. I did not run the Swift regression test or a live Gateway retry scenario in this read-only review.

## Solution Assessment

No, not as written: reusing the shared parser fixes the prefix bypass but is too broad for this auth boundary because it also trusts `0.0.0.0` and `::`. The better fix is a retry-specific loopback classifier or a parser split with tests for both prefix-bypass and unspecified-address cases.
