## Summary

Keep this PR open but not merge-ready: it fixes the `session.ended` timestamp direction with sufficient live proof, but it moves the only trajectory flush after cleanup, so a hanging cleanup can strand all queued trajectory events in memory.

## What This Changes

The PR defers embedded-runner `session.ended` trajectory recording until after cleanup, captures terminal status for that later event, derives cleanup failures as `error`, and flushes after the final event.

## Best Possible Solution

Keep the no-new-event F3 shape, but use a two-phase flush: flush queued trajectory events before cleanup, then record `session.ended` after cleanup and flush again.
