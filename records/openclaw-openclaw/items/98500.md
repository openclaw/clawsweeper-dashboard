## Summary

Keep this PR open: current main and the latest release still use an unbounded success-path JSON read for Google Meet OAuth tokens, while the patch is a narrow plugin-local hardening change with focused tests and added terminal proof. The remaining maintainer-visible question is accepting the 256 KiB fail-closed OAuth cap and deciding whether the local HTTP proof is enough without a credentialed live Google OAuth exchange.

## What This Changes

The PR changes Google Meet OAuth token success responses to be read through a 256 KiB bounded reader and adds oversized-response plus normal-response tests.

## Best Possible Solution

Land the plugin-local bounded read after maintainers accept the 256 KiB fail-closed cap and either accept the local HTTP proof or request credentialed Google OAuth smoke proof.

## Reproduction Assessment

Yes, source-reproducible. Current main calls response.json() on the Google Meet OAuth token success path, and the PR adds an oversized Response test through the refresh-token path; I did not run tests because this review is read-only.

## Solution Assessment

Yes, this is the narrow maintainable fix shape. It stays in the Google Meet plugin-owned OAuth helper, reuses the public Plugin SDK bounded-response seam, and leaves token validation, config, and API shape unchanged.
