## Label Justifications

- `P2`: The proposed repair addresses a bounded reliability race that can duplicate heartbeat work or delay targeted wake delivery during handler replacement.
- `merge-risk: 🚨 message-delivery`: The patch changes how in-flight and unattempted heartbeat wake requests are serialized and handed to a replacement lifecycle.

## Summary

This PR remains necessary: current `main` still uses one shared `running` flag and resets it when a replacement wake handler is registered, which permits a retired completion to alter the replacement lifecycle. The submitted generation-owned state is a focused repair with current-head production-entry proof and focused regression coverage; it needs routine maintainer review and a base refresh, not cleanup closure.

## What This Changes

The PR makes each heartbeat wake execution belong to the handler generation that started it, preventing a replaced handler's stale completion from clearing the active handler's slot, timer, retry, or remaining queued wakes.

## System Context

Heartbeat requests from timers, commands, hooks, and background work enter a shared coalescing queue before the active gateway heartbeat handler runs them. A handler replacement during restart or configuration lifecycle changes must transfer only unattempted wake work without allowing retired async work to mutate the new handler's scheduling state.
