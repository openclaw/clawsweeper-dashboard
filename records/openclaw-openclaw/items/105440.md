## Summary

The issue is valid and still necessary: current main and v2026.6.11 reject generic ZIP bytes masquerading as images but trust audio/video extensions over the same bytes. The safe fix is to preserve explicit ZIP-derived document exceptions while rejecting generic-container conflicts for media families, with focused regression tests.

## What This Changes

Make generic-container MIME fallback consistent so extension or header hints do not misclassify ambiguous bytes across image, audio, and video formats.

## Best Possible Solution

Restrict generic-container extension/header refinement to an explicit set of compatible container-derived document formats, and let generic sniffed bytes override image, audio, and video claims with regression coverage for each family.
