## Summary

Keep open. Current main and the latest release still expose mutable, priority-ordered plugin hooks with only coarse prompt/conversation gates, so hook-chain provenance, per-handler mutation audit, and per-hook integrity/permission policy remain unresolved security-boundary design work.

## What This Changes

The issue requests cryptographic integrity checks, audit logging, and per-hook permission controls for mutable plugin hook chains.

## Best Possible Solution

Define host-owned hook provenance and redacted mutation-audit semantics, distinguish in-process plugins from any future isolated-plugin IPC boundary, then add a compatible per-hook permission policy with docs and focused runtime/config tests.
