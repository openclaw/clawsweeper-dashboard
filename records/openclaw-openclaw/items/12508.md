- `impact:security`: The issue concerns plugin trust boundaries, tamper detection, hook permission gating, and auditability of security-relevant mutations.
- `impact:session-state`: The affected hooks can rewrite tool parameters, persisted messages, outbound content, and agent/tool context seen by later handlers or storage.

## Summary

Keep open. Current main and the latest release still expose mutable, priority-ordered plugin hooks with only coarse prompt/conversation gates, so hook-chain provenance, mutation audit, and per-hook permission/integrity policy remain unresolved security-boundary design work.

## What This Changes

The issue requests host-owned integrity checks, audit logging, and permission policy for mutable plugin hook chains to detect or prevent message tampering.

## Best Possible Solution

Define host-owned hook provenance and redacted mutation-audit semantics, distinguish in-process plugins from any future isolated-plugin IPC boundary, then add a compatible per-hook permission policy with docs and focused runtime/config tests.

Question: What hook-chain security model should OpenClaw support for mutable plugin hooks: host-owned audit/provenance for current in-process plugins, integrity checks across a future isolated-plugin IPC boundary, or per-hook permission gating first?

Rationale: The source gap is clear, but implementing checksums, audit logs, or per-hook allowlists would encode plugin trust-boundary and compatibility policy that current source and docs do not settle.

Likely owner: vincentkoc

Owner confidence: high

Options:

- **Define audit and trust boundary first (recommended):** Document the threat model, redaction/retention rules, and compatibility plan before changing hook runner behavior or config.
- **Ship redacted audit first:** Add host-owned audit events for modifying hooks while deferring checksum enforcement and per-hook allowlists.
- **Defer checksums to isolated IPC:** Keep checksum enforcement blocked on process-isolation work so integrity checks protect a real host/plugin boundary.
