## Summary

Keep open. Current main and v2026.6.11 still expose mutable, priority-ordered plugin hook paths with only coarse prompt/conversation gates, so the requested hook provenance, mutation audit, and per-hook permission model remains security-sensitive product design work.

## What This Changes

The issue requests hook-chain integrity protection, per-hook tamper detection or audit logging, and finer hook permission controls for plugin message mutations.

## Best Possible Solution

Define host-owned hook provenance and redacted mutation-audit semantics, distinguish in-process from isolated-plugin trust boundaries, then add a compatible per-hook permission policy with docs and focused runtime/config tests.
