## Summary

Keep open. Current main and the latest release still have mutable, priority-ordered plugin hooks with coarse prompt/conversation gates, but no hook-chain integrity state, per-handler mutation audit, or per-hook allowlist; the remaining work is security-sensitive plugin-runtime design rather than stale cleanup.

## What This Changes

The issue requests tamper-evident plugin hook execution, hook modification audit logging, and per-hook permission declarations for mutable hook chains.

## Best Possible Solution

Define a host-owned hook provenance and redacted mutation-audit model, distinguish in-process native plugins from any isolated-plugin IPC boundary, then add a compatible per-hook permission policy with docs and focused runtime/config tests.
