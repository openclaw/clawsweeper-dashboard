## Summary

Keep this PR open for a maintainer decision on the newly exposed public SDK helper’s invalid-input contract. The patch is internally consistent and has sufficient real behavior proof, but it deliberately changes direct callers from receiving a number to receiving an exception.

## What This Changes

The branch changes `resolvePollMaxSelections` to reject zero- and one-option polls and adds regression coverage for invalid and valid selection-count cases.

## Best Possible Solution

Document and adopt one canonical public SDK contract: either make `resolvePollMaxSelections` enforce the same minimum-two-options invariant as `normalizePollInput`, or keep it computation-only and require callers to normalize before use.
