## Summary

Keep open: current main and the latest release still build Android `system.notify` notifications without a deeplink/contentIntent path, and the remaining work is a security/product decision rather than cleanup. The broader Android URL-launch issue partially overlaps, but it does not replace this notification-tap contract.

## What This Changes

Request Android `system.notify` notifications to support a deeplink/contentIntent so tapping the notification can open an intended action surface.

## Best Possible Solution

Define a narrow Android notification-tap contract, preferably sharing the allowlisted deeplink policy from the broader URL-launch discussion or restricting taps to OpenClaw-owned deep links, then implement Android/gateway tests and docs.
