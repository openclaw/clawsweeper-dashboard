## Summary

Keep this PR open for repair: the new NaN guard runs only after sequence ordering, so a malformed candidate with a higher sequence still bypasses timestamp validation and can replace the saved snapshot.

## What This Changes

The PR makes equal-sequence signed hosted catalog feeds count as rollback when either parsed `generatedAt` timestamp is invalid.

## Best Possible Solution

Validate an incoming signed feed's timestamp before sequence short-circuits, define safe handling for invalid saved timestamps, and cover both invalid sides plus lower, equal, and higher sequence cases.
