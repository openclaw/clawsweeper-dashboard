## Summary

This PR addresses a real P1 tool-argument corruption report with strong gateway proof, but the decoder still rewrites valid escaped code strings that happen to contain a colon, literal `\n`, and indentation. Keep it open for a narrow compatibility repair before merge.

## What This Changes

The branch unconditionally wraps embedded-agent streams to repair selected tool-call argument strings whose double-escaped newline, tab, or carriage-return sequences match a code-block-shaped regex.

## Best Possible Solution

Constrain repair to a representation that can distinguish confirmed double-escaped transport corruption from valid language string literals, and add regressions for escaped indented multiline values in both write content and exec command arguments.
