## Summary

Keep open: this is a plausible security hardening direction, but it is not merge-ready because the new guard only blocks a missing Content-Length and still lets a non-streaming response with a false small Content-Length buffer through `.text()` before the post-read cap runs.

## What This Changes

The PR adds a missing-Content-Length fail-closed guard before the non-streaming hosted plugin catalog response `.text()` fallback.

## Best Possible Solution

Fail closed on all non-streaming hosted catalog responses, or replace the fallback with a truly bounded reader, and add focused regressions for missing and false small Content-Length cases before merge.

## Reproduction Assessment

Yes from source inspection. The PR still reaches `response.text()` whenever `hasStreamingResponseBody` is false and Content-Length is present, so a false small header leaves the unbounded read shape intact.

## Solution Assessment

No. Requiring a header is only a partial mitigation; the maintainable fix is to reject non-streaming bodies or use a reader that enforces the byte cap before buffering.
