## Summary

Keep this PR open: the DeepInfra video and DeepSeek fixes are useful and convincingly proven, but the current head still silently changes the meaning of the shipped `nativeBaseUrl` setting, so an owner-approved upgrade contract is required before merge.

## What This Changes

Moves DeepInfra text-to-video generation to its asynchronous OpenAI-compatible videos API with live model discovery, tags DeepSeek-family models with the DeepSeek thinking dialect, and updates focused tests and provider documentation.

## Best Possible Solution

Use the OpenAI-compatible video endpoint for the default and canonical `baseUrl` path, while preserving explicitly configured `nativeBaseUrl` native-route semantics—or providing an explicit plugin-owned migration/deprecation path—and cover both fresh installs and upgrades with focused tests.

## Solution Assessment

No, not yet: moving the default path and adding the DeepSeek dialect are appropriate, but silently translating an explicitly configured native endpoint is not the safest upgrade solution. Preserve that explicit contract or migrate it visibly.
