## Label Justifications

- `P1`: A current Signal lifecycle regression can suppress replies for inbound events already accepted before shutdown or reconnect teardown.
- `impact:message-loss`: The abort ordering silently discards an accepted Signal inbound batch before reply delivery.

## Summary

Current `main` still contains the Signal shutdown race: teardown aborts the lifecycle before tracked event tasks drain, and the debouncer then discards an accepted batch at its initial flush. No canonical replacement issue or fix PR was found, and the protected `maintainer` label requires explicit handling.

Likely related people: @steipete (high confidence, lifecycle follow-up author and merger) and @cxbAsDev (high confidence, original retry implementation author).

## What This Changes

Fix Signal monitor shutdown so an inbound event accepted before teardown completes its initial flush instead of being silently dropped.

## Best Possible Solution

Allow each Signal event already accepted by the SSE callback to attempt its initial flush once, while retaining abort cancellation for conflict retry waits and subsequent attempts, with focused tests proving both shutdown invariants.
