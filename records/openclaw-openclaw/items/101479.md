## Summary

The previous P1 blocker remains on head `2ce089d3e490412026ea426ceaabf35095ed01dc`: switching from `fs.readFile` to the full-mode reader removes one whole-file string allocation, but that reader retains the complete parsed transcript index and constructs a complete message array, so the stated OOM prevention is incomplete. The correct bound must be shared with the Gateway reset implementation because both expose the same public `before_reset` plugin payload.

## What This Changes

The PR routes command reset-hook transcript loading through the shared asynchronous full-mode reader and forwards `storePath` through normal and fallback reset callers.

## Best Possible Solution

Define a documented recent-message byte and message budget for `before_reset`, apply it to both command and Gateway reset paths, preserve archive and custom-store resolution, and add payload-contract tests plus redacted peak-memory evidence across increasing valid transcript sizes.
