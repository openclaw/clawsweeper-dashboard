## Summary

Keep open: current main still uses unbounded reset-hook transcript reads, so the OOM fix is useful, but this branch is not merge-ready because it can drop plugin-visible `before_reset` messages for large transcripts and can skip archived-transcript recovery after switching to fs-safe reads.

## What This Changes

The branch adds a 16 MiB capped reset-hook transcript reader, rewires reset-hook tests to mock it, and adds an oversized-transcript command-path regression test.

## Best Possible Solution

Use the existing streaming/indexed transcript reader for command reset hooks, preserve archived transcript fallback for fs-safe missing-file errors, and keep the OOM protection without changing the plugin-visible payload contract.

Yes from source inspection: current main calls `fs.readFile` on reset-hook transcript files before parsing, so a very large JSONL file is buffered. I did not run an OOM repro, but the PR body now includes terminal proof through the actual command hook path for the oversized case.

## Solution Assessment

No: bounded IO is the right direction, but the proposed raw cap empties plugin payloads and misses fs-safe `not-found` archive fallback. The safer fix is to reuse the streaming/indexed transcript reader and preserve missing-file recovery.
