## Summary

The PR fixes the direct whole-file read and preserves custom-store resolution, but its replacement still retains transcript-proportional parsed index, cache, and hook message arrays, so the central OOM-prevention claim remains incomplete. The latest head does not change the previously reviewed full-mode call, and the plugin-facing payload semantics need an owner decision before the narrow repair can be finalized.

## What This Changes

The PR routes command reset-hook transcript loading through the shared asynchronous session reader and forwards `storePath` through normal and fallback reset callers.

## Best Possible Solution

Adopt one explicit bounded `before_reset` contract for both command and Gateway resets—preferably a documented recent-tail array with total byte and message caps—avoid retaining a full cached transcript index for this path, and prove flat peak-memory behavior across increasing transcript sizes.
