## Summary

Keep this PR open, but it is not merge-ready: the current head still fixes the OOM risk by replacing large valid reset-hook transcripts with an empty `before_reset` payload, which changes plugin-observable behavior when a transcript crosses the new cap.

## What This Changes

The PR caps command reset-hook transcript reads at 16 MiB with `readRegularFile`, returns empty `before_reset` messages on oversized or unreadable transcripts, and adds reset-hook regression coverage.

## Best Possible Solution

Use the existing async session transcript reader/index for command reset hooks, preserving large-session payloads and reset-archive behavior while avoiding whole-file buffering, then require non-test behavior proof.
