## Summary

Keep open: the central OOM-prevention claim is not met because the full reader still retains the complete parsed transcript and message payload in memory. This blocker was equally visible at the previous reviewed head, so it is reported as a late finding rather than new author churn.

## What This Changes

The PR routes before-reset transcript loading through the shared asynchronous full transcript reader and forwards custom session store paths through normal and fallback reset-hook callers.

## Best Possible Solution

Define a compatibility-safe bounded contract for `before_reset` messages—preferably a documented recent-message window with explicit byte and message ceilings—then implement it without caching a complete runaway transcript while preserving archive fallback and custom-store resolution.
