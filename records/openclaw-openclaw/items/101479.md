## Summary

Keep this PR open, but the previous blocker still applies: the memory-safety goal is valid, while the current 16 MiB `readRegularFile` cutoff changes plugin-visible `before_reset` payloads by returning `messages: []` for large valid transcripts instead of using the existing streamed transcript reader.

## What This Changes

The branch replaces reset-hook transcript `fs.readFile` calls with a 16 MiB `readRegularFile` cap and updates reset-hook tests for archived and oversized transcripts.

## Best Possible Solution

Route command reset-hook transcript loading through the existing session transcript reader/index, keep reset-archive fallback behavior, and require redacted actual reset-hook path proof before merge.
