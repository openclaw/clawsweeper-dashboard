## Summary

Keep open: current main and the latest release still have uncapped command reset-hook transcript reads, so the bug is real, but this PR head is not merge-ready because it turns valid transcripts over 16 MiB into `messages: []` for `before_reset` plugins and the new proof only exercises the helper, not the reset-hook path.

## What This Changes

The PR caps command `before_reset` transcript reads at 16 MiB with `readRegularFile` and updates reset-hook tests for oversized and archived transcript handling.

## Best Possible Solution

Route command reset-hook transcript loading through the existing session transcript reader/index with reset-archive fallback, preserving plugin payloads while avoiding whole-file buffering, then add redacted non-test proof of the reset-hook path.
