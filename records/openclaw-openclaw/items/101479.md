## Summary

Keep open: the refreshed patch is a reasonable owner-boundary fix and preserves the archived-transcript `ENOENT` fallback, but this external PR still needs real behavior proof and maintainer-visible acceptance of the hard 16 MiB empty-message behavior before merge.

## What This Changes

The PR switches `before_reset` transcript loading from unbounded `fs.readFile` to a 16 MiB `readRegularFile` cap and updates reset-hook tests for oversized and archived transcript cases.

## Best Possible Solution

Land a bounded transcript read that preserves archived fallback behavior and includes real reset-hook proof; if maintainers need payload continuity for huge transcripts, use a bounded window instead of empty messages.
