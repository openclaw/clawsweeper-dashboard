## Summary

Keep open: this draft PR adds useful managed-policy coverage for gateway node commands, but the check is not merge-ready because it can miss denied commands that are allowed through paired/approved node surfaces, and after-fix real behavior proof is missing.

## What This Changes

Adds a policy doctor rule, shape validation, evidence scanning, tests, and policy coverage metadata for `gateway.nodes.denyCommands` against explicit `gateway.nodes.allowCommands` entries.

## Best Possible Solution

Make the policy rule enforce the same command-deny invariant the runtime documents: denied policy command IDs should be blocked even when commands are available through defaults, pairing approvals, or explicit config, with focused tests and redacted terminal proof of the doctor output.

## Reproduction Assessment

Yes, at source level: the PR filters policy findings through evidence derived from `gateway.nodes.allowCommands`, while current runtime also admits approved live/paired node commands into the allowlist. I did not run the test suite because this review is read-only.

## Solution Assessment

No, not as currently shaped: observing explicit `allowCommands` is useful but too narrow for a policy named as a node-command deny rule. The safer fix is to enforce the runtime deny invariant or deliberately narrow the exposed policy contract.
