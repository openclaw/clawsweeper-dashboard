## Summary

The narrow parser and classifier behavior is well demonstrated, but the patch accepts a synthetic result as a completed CLI turn even though a reused Claude live session can emit that same result before the real answer. The current head therefore needs a live-session-safe completion design before merge. citeturn16search0turn10search0

## What This Changes

The PR recognizes two exact Claude CLI `<synthetic>` placeholder messages, propagates a marker through CLI output and run metadata, and classifies marker-only turns as fallback-worthy `empty_result` outcomes with parser, runner, and classifier tests.

## Best Possible Solution

Handle synthetic results at the Claude live-session turn boundary: distinguish an intermediate notification or reseed result from a truly terminal no-output result, wait for the real same-process result under a bounded lifecycle rule, and emit `empty_result` only after that rule proves no visible answer will arrive; retain the parser marker as supporting metadata and add a persistent-session regression proving no cross-turn output misassociation.
