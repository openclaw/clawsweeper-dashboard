## Summary

Keep open and block merge: production evidence shows the same synthetic placeholder can be an intermediate reused-session event before a later real answer, so treating every marker-only turn as terminal fallback can abandon or duplicate in-flight work. ([github.com](https://github.com/openclaw/openclaw/issues/99131))

## What This Changes

The PR detects two Claude CLI `<synthetic>` placeholder messages, preserves a marker through buffered and streaming parsing, adds a terminal reply kind, and classifies marker-only runs as fallback-worthy empty results.

## Best Possible Solution

Keep the parser marker as metadata, but let the Claude live-session owner decide its meaning: continue reading and preserve a reused process when the placeholder is transient, and invoke fallback only after a confirmed terminal no-output outcome; cover fresh, reused, late-answer, explicit-silent, and channel-delivery cases.
