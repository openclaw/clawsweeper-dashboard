## Summary

## Best Possible Solution

Land a narrowed fix that lets exact synthetic placeholders bypass generated silent `NO_REPLY` handling, preserves explicit model-authored `NO_REPLY`, and adds regression coverage for `allowEmptyAssistantReplyAsSilent=true` before maintainers accept the fallback semantics.

## Reproduction Assessment

## Solution Assessment

No, not yet. Parser-to-runner metadata is the right boundary, but the PR must keep exact synthetic placeholders out of the generated silent-reply path while preserving explicit `NO_REPLY` behavior.
