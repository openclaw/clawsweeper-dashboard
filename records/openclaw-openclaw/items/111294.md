## Summary

Keep open: the UTF-8-boundary approach fixes the tested tail-start case, but its per-append decoder can silently drop a valid character when a process stream splits that character across adjacent data chunks.

## What This Changes

The PR replaces direct UTF-8 decoding of bounded release-check output tails with a boundary-aware decoder and adds stdout/stderr coverage for a multibyte character at the retained-tail start.

## Best Possible Solution

Keep raw bounded bytes for each stdout/stderr stream until capture completion, then decode the final retained suffix from a valid UTF-8 boundary and cover a multibyte character split across separate process writes.
