## What This Changes

This PR replaces Android PermissionRequester’s pre-registered ActivityResult launcher pool with requestCode-keyed ActivityCompat requests, forwards MainActivity permission callbacks, and updates Robolectric timeout tests.

## Best Possible Solution

Land the requestCode-based permission requester after redacted real Android runtime proof shows repeated timeout recovery and late-callback isolation on the current head.

## Reproduction Assessment

Yes from source inspection: current main leaves timed-out no-callback requests occupying the four pre-registered launcher slots, so repeated timeouts can exhaust the pool and hit `permission request launcher busy`. I did not run Android runtime proof because this review is read-only.

## Solution Assessment

Yes, this appears to be the best code shape: keying pending requests by platform requestCode removes the finite slot pool and directly isolates late callbacks. The remaining blocker is proof of the real Android callback path, not a different implementation direction.
