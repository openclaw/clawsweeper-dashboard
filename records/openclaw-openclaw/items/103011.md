The PR replaces the Android PermissionRequester ActivityResult launcher pool with requestCode-keyed ActivityCompat requests, forwards MainActivity permission callbacks, and updates Robolectric timeout regression tests.

## Best Possible Solution

## Reproduction Assessment

Yes, from source inspection: current main leaves timed-out no-callback requests occupying the four pre-registered launcher slots, so repeated timeouts can exhaust the pool and hit `permission request launcher busy`. I did not run an Android runtime repro because this review is read-only.

## Solution Assessment

Yes, this appears to be the best code shape: requestCode-keyed pending requests remove the finite launcher pool and isolate late callbacks better than clearing and reusing launcher slots. The remaining blocker is real Android runtime proof, not a different implementation layer.
