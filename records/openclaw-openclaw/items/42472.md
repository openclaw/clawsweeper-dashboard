## Summary

Keep open: current main still strips NO_REPLY and delivers generic mixed trailing text, and the checked tests pin that behavior; the landed punctuation, reasoning-prefixed, and cron fixes are narrower than this issue's requested shared delivery/security policy change.

## What This Changes

The issue requests reply post-processing that suppresses an entire model reply when NO_REPLY appears in mixed output instead of stripping only the token.

## Best Possible Solution

Define one maintainer-approved silent-intent classifier for mixed NO_REPLY payloads, preserve legitimate substantive replies, then apply that contract consistently across reply normalization, outbound delivery, cron, and streaming/turn-level paths with focused regression and real channel proof.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw broaden NO_REPLY suppression for mixed trailing or own-line payloads, and where should the boundary be between silent-intent text and legitimate substantive replies that mention or append the token?

Rationale: Current main deliberately preserves some substantive trailing-token replies, while this issue asks for broader suppression to prevent internal text leaks; that is a shared message-delivery and security contract choice rather than a mechanical cleanup close.

Likely owner: steipete

Owner reason: The decision spans shared reply delivery and security/product policy, and steipete has recent landing/routing history on adjacent silent-token classifier work.

Owner confidence: medium

Options:

- **Adopt Classifier-Based Suppression (recommended):** Define a shared classifier that suppresses internal or silent-intent mixed payloads, preserves legitimate substantive replies, and applies consistently across delivery paths.
- **Use Blanket Trailing Or Own-Line Suppression:** Suppress any reply ending with a trailing or own-line NO_REPLY token, accepting that some currently visible substantive replies may be dropped.
- **Keep The Current Narrow Policy:** Document that only token-only, punctuation-only, and reasoning-prefixed silent payloads are suppressed, then close or retarget broad suppression requests.

## Reproduction Assessment

Yes, source-reproducible: normalizeReplyPayload strips a trailing NO_REPLY token from mixed content and returns the remaining text, and tests currently assert that behavior. I did not run a live channel repro because this review is read-only.

## Solution Assessment

No for a blanket suppress-if-contains rule. The safer solution is a maintainer-approved classifier that suppresses internal or silent-intent payloads while preserving legitimate substantive replies before changing shared delivery semantics.
