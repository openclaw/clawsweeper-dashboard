## Summary

Keep open: current main and the latest release still preserve generic substantive-looking text before a trailing `NO_REPLY` in shared final-reply delivery, while narrower reasoning-prefixed, punctuation-wrapped token-only, and cron synthesized cases have partial fixes. The remaining work is a shared message-delivery/security policy decision, not conservative cleanup.

## What This Changes

The issue requests shared reply post-processing that suppresses an entire model response whenever `NO_REPLY` appears after visible text, instead of stripping only the sentinel.

## Best Possible Solution

Maintainers should define a shared silent-reply contract, then update the shared classifier/normalizer and outbound/cron tests so final-line or explicit silent-intent leaks are suppressed while legitimate mixed-content replies stay deliverable.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should the shared reply pipeline suppress the whole message for generic prefix text followed by `NO_REPLY`, or keep delivering substantive-looking prefixes except for narrower reasoning, cron, and token-only cases?

Rationale: Current source and tests deliberately preserve some substantive trailing-token replies, while this issue asks to turn the same shape into full suppression for security and noise reduction; automation cannot safely choose that message-delivery boundary.

Likely owner: steipete

Owner reason: Recent merged follow-up commits and PR reviews shaped the current narrow shared suppression boundary.

Owner confidence: high

Options:

- **Define A Narrow Shared Silence Rule (recommended):** Suppress whole messages only for an explicit final-line or silent-intent boundary that maintainers document, with tests for both suppression and preserved substantive replies.
- **Adopt Broad Contains Suppression:** Treat any `NO_REPLY` occurrence as a whole-message suppressor, accepting the message-loss risk for text that previously delivered after token stripping.
- **Preserve Current Split Behavior:** Keep the current reasoning-prefixed, punctuation token-only, and cron-specific fixes, then close or re-scope this issue as not planned for generic mixed content.

## Reproduction Assessment

Yes. Source inspection and current tests show the shared normalizer strips `NO_REPLY` from substantive-looking trailing-token replies and returns the remaining prefix; no tests were run in this read-only review.

## Solution Assessment

Unclear. The requested suppress-if-present rule would solve the leak class but is broader than the current tested contract, so the maintainable fix needs an explicit maintainer-approved silence-intent boundary.
