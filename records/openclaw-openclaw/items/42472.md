## Summary

Keep open: current main still preserves ordinary mixed trailing NO_REPLY text in the shared normal reply and outbound payload paths, while merged fixes cover narrower token-only punctuation, reasoning-prefixed, and cron-specific cases. The remaining request is a product/security boundary decision because blanket suppression would intentionally drop some replies that current tests keep visible.

## What This Changes

The issue requests suppressing an entire model reply when a NO_REPLY sentinel appears after leaked preamble text.

## Best Possible Solution

Define one maintainer-approved silent-intent classifier for mixed NO_REPLY payloads, preserve legitimate substantive replies, and apply that contract consistently across reply normalization, outbound delivery, cron, and streaming with regression and real channel proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw broaden NO_REPLY suppression for mixed trailing or own-line payloads, and where should it draw the boundary between silent-intent preamble text and legitimate substantive replies that mention or append the token?

Rationale: Current main intentionally preserves some substantive trailing-token replies, while this issue asks for broader suppression to prevent internal text leaks; that is a shared message-delivery and security contract choice rather than a mechanical cleanup close.

Likely owner: steipete

Owner reason: This decision spans shared reply delivery, exported matcher behavior, and security/product policy, and steipete has recent central-file and landing history on this surface.

Owner confidence: high

Options:

- **Adopt Classifier-Based Suppression (recommended):** Define a shared classifier that suppresses internal or silent-intent mixed payloads, preserves legitimate substantive replies, and applies consistently across delivery paths.
- **Use Blanket Trailing/Own-Line Suppression:** Suppress any reply ending with a trailing or own-line NO_REPLY token, accepting that some currently visible substantive replies may be dropped.
- **Keep The Current Narrow Policy:** Document that only token-only, punctuation-wrapped token-only, JSON, reasoning-prefixed, and scoped cron silent payloads are suppressed, then retarget or close broad suppression requests.

## Reproduction Assessment

Yes, source-reproducible: normalizeReplyPayload strips a trailing NO_REPLY token from ordinary mixed content and returns the remaining text, and tests currently assert that behavior. I did not run a live channel repro because this review is read-only.

## Solution Assessment

No for a blanket suppress-if-contains rule. The safer path is a maintainer-approved classifier that suppresses internal or silent-intent payloads while preserving legitimate substantive replies before changing shared delivery semantics.
