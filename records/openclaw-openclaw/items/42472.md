## Summary

Keep open: current main and the latest release still preserve generic substantive-looking text before a trailing `NO_REPLY`, while narrower reasoning-prefixed and punctuation-wrapped token-only leak cases have been fixed. The remaining behavior is the canonical mixed/partial silent-reply policy decision, not cleanup-closeable evidence.

## What This Changes

The issue requests suppressing an entire auto-reply payload whenever model output contains or ends with `NO_REPLY`, rather than stripping only the sentinel and delivering preceding text.

## Best Possible Solution

Define one maintainer-approved shared silent-reply classifier for mixed-content `NO_REPLY` handling, then apply it consistently across final normalization, outbound delivery, history/display filtering, and regression tests while preserving whichever legitimate mixed-content cases maintainers choose to keep.

Options:

- **Adopt a narrow shared classifier (recommended):** Suppress reasoning, silent-intent, and internal-summary payloads consistently while preserving ordinary substantive replies that only mention or accidentally end with `NO_REPLY`.
- **Suppress any trailing sentinel:** Treat any trailing or own-line `NO_REPLY` as whole-payload silence, accepting possible loss of legitimate replies that current tests preserve.
- **Keep current semantics:** Leave generic mixed-content behavior unchanged and limit cleanup to already-fixed narrower token-only and reasoning-prefixed leaks.

## Solution Assessment
