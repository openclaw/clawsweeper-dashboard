## Summary

Keep open: current main and v2026.6.11 still preserve substantive mixed trailing `NO_REPLY` payloads by stripping the token and delivering the prefix, while cron-specific and reasoning-prefixed variants are partially covered. The remaining request changes a shared reply-delivery/security contract and has an open conflicting implementation candidate, so it needs maintainer product/security review rather than cleanup close.

## What This Changes

The issue asks for the NO_REPLY post-processing contract to suppress an entire model reply when the token appears after earlier text, instead of stripping only the token and delivering the prefix.

## Best Possible Solution

Make one maintainer-owned decision for the shared NO_REPLY delivery contract, then align token classification, final reply normalization, directive parsing, cron exceptions, and tests to that contract.
