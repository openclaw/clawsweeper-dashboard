## Summary

Keep open: current main and the latest release still preserve generic substantive-looking text before a trailing `NO_REPLY`, while narrower reasoning-prefixed and punctuation-wrapped token-only leak cases have been fixed. The remaining request is a shared message-delivery/security policy decision, not cleanup-closeable evidence.

## What This Changes

Request to suppress the entire auto-reply payload when model output contains substantive-looking text before a trailing or own-line `NO_REPLY` sentinel.

## Best Possible Solution

Define one shared silent-reply classifier that suppresses confidential internal or silent-intent payloads across final/outbound paths while preserving legitimate mixed-content replies unless maintainers explicitly choose privacy-over-delivery semantics.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw broaden `NO_REPLY` handling to suppress otherwise substantive text before a trailing or own-line sentinel, or keep the current mixed-content-preserving behavior except for narrower reasoning/silent-intent and token-only cases?

Rationale: Current main and the latest release intentionally preserve ordinary substantive text before trailing `NO_REPLY`, while the reported leak class is security-sensitive; automation cannot choose the privacy-versus-message-delivery boundary without maintainer product/security intent.

Likely owner: steipete

Owner reason: He merged the recent overlapping token-classifier fixes and is the clearest routing owner for the remaining policy boundary.

Owner confidence: high

Options:

- **Adopt a narrow shared classifier (recommended):** Suppress reasoning, silent-intent, and internal-summary payloads consistently across delivery paths while preserving ordinary substantive replies that only mention or accidentally end with `NO_REPLY`.
- **Suppress any trailing sentinel payload:** Treat any trailing or own-line `NO_REPLY` as whole-payload silence, accepting possible loss of legitimate replies that current tests preserve.
- **Keep current semantics:** Leave the generic mixed-content behavior unchanged and close or retitle this issue to the already-merged narrower leak classes.

## Reproduction Assessment

Yes from source inspection: current `normalizeReplyPayload` strips a trailing `NO_REPLY` from generic substantive text and returns the remaining text, and adjacent tests assert that behavior. I did not run tests because this was a read-only review.

## Solution Assessment

Unclear: broad whole-payload suppression would address the reported leak, but it conflicts with current mixed-content tests and compatibility expectations. A narrower shared classifier is the safer maintainable direction unless maintainers explicitly choose broad privacy-over-delivery suppression.
