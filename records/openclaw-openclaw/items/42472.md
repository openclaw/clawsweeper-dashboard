## Summary

Keep open: current main and the latest release still strip a generic trailing NO_REPLY and deliver the preceding text, while tests deliberately preserve some substantive trailing-token replies. The linked open fork PR targets this issue but is unmerged and conflicting, so maintainers still need to choose the suppression contract.

## What This Changes

The issue asks OpenClaw to suppress the entire model reply when a response contains or trails the NO_REPLY sentinel, instead of delivering the pre-token text.

## Best Possible Solution

Define one maintainer-approved silent-intent classifier for mixed NO_REPLY payloads, preserve legitimate substantive replies, and apply that contract consistently across reply normalization, outbound delivery, cron, and streaming or turn-level paths with focused regression proof.

- **Keep the narrow policy:** Document that only token-only, punctuation-only, reasoning-prefixed, and scoped cron cases are suppressed, then retarget broad suppression requests.

Yes, source-reproducible: current normalizeReplyPayload strips a trailing NO_REPLY token from generic mixed content and returns the remaining text, and current tests assert that behavior. I did not run a live channel repro because this is a read-only cleanup review.

## Solution Assessment

No, not as a blanket suppress-if-contains rule. The safer solution is a maintainer-approved classifier that suppresses internal or silent-intent payloads while preserving legitimate substantive replies before changing shared delivery semantics.
