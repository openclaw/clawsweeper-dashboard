## Summary

Keep open: current main still strips trailing NO_REPLY from generic mixed-content replies and delivers the remaining text, while shipped and merged related fixes cover narrower token-only, punctuation-wrapped, reasoning-prefixed, or cron-specific cases rather than this broad policy request.

## What This Changes

The issue requests a shared reply-pipeline rule that suppresses an entire model response when NO_REPLY appears after leaked preamble text.

## Best Possible Solution

Define one maintainer-approved silent-intent classifier for mixed NO_REPLY payloads, preserve legitimate substantive replies, and apply that contract consistently across reply normalization, outbound delivery, cron, and streaming or turn-level paths with focused regression proof.

Rationale: Current main deliberately preserves some substantive trailing-token replies while the issue asks for broader suppression to avoid internal text leaks, so this changes a shared message-delivery and security boundary rather than a purely mechanical bug fix.

Likely owner: steipete

Owner confidence: medium

Options:

- **Adopt classifier-based suppression (recommended):** Define a shared classifier that suppresses internal or silent-intent mixed payloads while preserving legitimate substantive replies, then reuse it across delivery paths.
- **Use blanket trailing or own-line suppression:** Suppress any reply ending with a trailing or own-line NO_REPLY token and accept that some currently visible substantive replies may be dropped.
- **Keep the current narrow policy:** Document that only token-only, punctuation-only, reasoning-prefixed, and scoped cron cases are suppressed, then retarget broad suppression requests.

## Reproduction Assessment

Yes, source-reproducible: current normalizeReplyPayload strips a trailing NO_REPLY token from generic mixed content and returns the remaining text, and tests assert that behavior. I did not run a live channel repro because this is a read-only review.

## Solution Assessment

No, not as a blanket suppress-if-contains rule. The safer solution is a maintainer-approved classifier that suppresses internal or silent-intent payloads while preserving legitimate substantive replies before changing shared delivery semantics.
