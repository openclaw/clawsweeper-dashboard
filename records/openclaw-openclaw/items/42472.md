## Summary

Keep open: current main and the latest release still preserve generic mixed trailing-token replies by stripping `NO_REPLY` and delivering the remaining text, while a linked open fork PR is unmerged and conflicting. The remaining work is a maintainer-owned message-delivery/security contract decision, not conservative cleanup.

## What This Changes

The issue requests suppressing the entire auto-reply when generated output includes or trails a `NO_REPLY` sentinel after visible text.

## Best Possible Solution

Define one maintainer-approved silent-intent classifier for mixed `NO_REPLY` payloads, preserve legitimate substantive replies, and apply that contract consistently across reply normalization, outbound delivery, cron, and streaming or turn-level paths with focused regression proof.

Rationale: Current main deliberately preserves some substantive trailing-token replies while this issue asks for broader suppression to avoid internal text leaks, so this is a shared message-delivery and security contract decision rather than mechanical cleanup.

Owner confidence: high

Options:

- **Adopt classifier-based suppression (recommended):** Define and reuse a shared classifier that suppresses internal or silent-intent mixed payloads while preserving legitimate substantive replies.
- **Use blanket trailing-token suppression:** Suppress any reply ending with a trailing or own-line `NO_REPLY` token and accept that some currently visible substantive replies may be dropped.
- **Keep the narrow policy:** Document that only token-only, punctuation-wrapped, reasoning-prefixed, and scoped cron cases are suppressed, then retarget broad suppression requests.

## Reproduction Assessment

Yes, source-reproducible: current `normalizeReplyPayload` strips a trailing `NO_REPLY` token from generic mixed content and returns the remaining text, and current tests assert that behavior. I did not run a live channel repro because this is a read-only cleanup review.

## Solution Assessment

No, not as a blanket suppress-if-contains rule. The safer solution is a maintainer-approved classifier that suppresses internal or silent-intent payloads while preserving legitimate substantive replies before changing shared delivery semantics.
