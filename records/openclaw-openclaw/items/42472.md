## Summary

Keep open: current main still strips and delivers generic substantive-looking text before a trailing `NO_REPLY`, while merged work only covers narrower reasoning-prefixed, punctuation-wrapped token-only, and cron delivery cases. The remaining behavior is a shared message-delivery/security policy decision, and an open linked fix PR exists but is conflicting and not a safe canonical resolution yet.

## What This Changes

The issue asks OpenClaw to suppress an entire assistant reply when model output includes preceding text followed by `NO_REPLY`, instead of stripping the token and delivering the prefix.

## Best Possible Solution

Maintainers should define and document the shared silent-reply contract, then update the shared classifier/normalizer and focused tests while preserving the narrower cron, reasoning-prefixed, and punctuation token-only fixes.

Rationale: Current source and tests deliberately preserve some substantive trailing-token replies, while this issue asks to convert that shape into full suppression for leak prevention; automation cannot safely choose the message-loss versus leak-prevention boundary.

Options:

- **Define Narrow Shared Suppression (recommended):** Suppress whole messages for a maintainer-approved final-line or silent-intent boundary, document it, and add tests for both suppressed leaks and preserved substantive replies.
- **Adopt Broad Contains Suppression:** Treat any `NO_REPLY` occurrence as a whole-message suppressor, accepting compatibility and message-loss risk for text that previously delivered after token stripping.
- **Preserve Current Split Behavior:** Keep the reasoning-prefixed, punctuation token-only, and cron-specific fixes, then close or re-scope this request as not planned for generic mixed content.
