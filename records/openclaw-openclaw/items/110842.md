## Summary

Keep this PR open, but the current patch is incorrect: flushing the streaming decoder during session adoption turns a valid UTF-8 sequence that continues after adoption into replacement characters, recreating the corruption at the exact handoff boundary. The submitted Vitest output is useful regression coverage but is mock-only rather than real Control UI terminal proof.

## What This Changes

The PR changes terminal startup input to use a per-tab streaming `TextDecoder`, adds a decoder flush API, invokes it at session adoption and tab disposal, and adds UTF-8 chunking tests.

## Best Possible Solution

Keep one streaming decoder alive across session adoption, drain only complete buffered text at adoption, add a handoff-boundary regression test, and then provide redacted evidence from a real Control UI terminal paste.

## Reproduction Assessment

Yes, from source: feed the initial bytes of a multi-byte UTF-8 scalar while no session is present, adopt a session, then feed the remaining bytes. The added no-argument decoder flush at adoption finalizes the partial scalar before it can be completed.

## Solution Assessment

No. Streaming decoding is the right direction, but ending the stream at session adoption defeats it for chunks that cross that lifecycle boundary; decoder state must remain live until later input or true stream termination.
