## Summary

The streaming per-tab decoder and adopt-without-flush approach address the reported UTF-8 corruption, and the refreshed live Gateway/PTY transcript is meaningful after-fix proof. However, the new dispose path flushes an incomplete decoder sequence into a still-live terminal session as U+FFFD, so this PR needs one narrow teardown correction before merge.

## What This Changes

The PR replaces shared non-streaming terminal-startup decoding with a per-tab streaming `TextDecoder`, retains state across session adoption, flushes on tab disposal, and adds terminal-panel and Control UI regression coverage.

## Best Possible Solution

Keep the streaming decoder open across session adoption, but discard incomplete decoder state on tab disposal rather than delivering a replacement character; add a focused regression proving disposal sends no terminal input for partial UTF-8 bytes.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source: with a bound session, feed an incomplete UTF-8 prefix such as `E4 B8` and dispose the tab; `decoder.decode()` finalizes it as U+FFFD and the helper routes it to `terminal.input`. The reported pre-bind split-character corruption is also directly represented by the base implementation’s non-stream decode path.

## Solution Assessment

No, not fully. Streaming decode and retaining state across adoption are the right minimal repair, but flushing decoder state through terminal input on disposal introduces a new invalid-character delivery path; disposal should discard incomplete bytes.
