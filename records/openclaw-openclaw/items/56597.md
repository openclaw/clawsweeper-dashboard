## Summary

Keep open. Current main and latest release v2026.6.11 still persist authorized `/exec` session fields and resolve them ahead of config-derived defaults; the merged ACP cache fix at https://github.com/openclaw/openclaw/pull/82237 fixed a related stale-runtime-handle path but not this persisted session precedence.

## What This Changes

The issue asks OpenClaw to stop Discord session-level `/exec` overrides from indefinitely shadowing later global `tools.exec` security config changes after a session resumes.

## Best Possible Solution

Define the canonical `/exec` session precedence policy, then implement a tested migration, doctor repair, reset path, or bounded-precedence change so stricter operator security config can be enforced without ambiguous stale session state.
