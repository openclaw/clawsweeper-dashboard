Keep open. Current main and latest release still persist and prefer `/exec` session fields before config-derived defaults, while docs and tests show that persistence is intentional enough that maintainers need to choose the security/reset policy before changing precedence.

## What This Changes

The issue asks OpenClaw to stop persisted Discord `/exec` session fields from overriding later global `tools.exec` security config changes.

## Best Possible Solution

Define whether operator global or agent exec policy is an upper bound for stored session defaults, then update resolver, persistence, docs, tests, and any reset or doctor path to enforce that policy consistently.
