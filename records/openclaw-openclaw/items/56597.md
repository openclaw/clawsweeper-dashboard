The issue requests that Discord `/exec` session defaults stop overriding later global exec security configuration after resumes or restarts.

## Best Possible Solution

Define the canonical `/exec` precedence and reset policy, then implement a tested session-state migration or reset path that lets operator security policy take effect without accidentally breaking documented session defaults.

## Solution Assessment

Unclear. A simple resolver-order change is plausible, but current docs and tests describe `/exec` as persistent session state, so the safer solution needs maintainer-approved policy plus migration or reset handling for existing stored entries.
