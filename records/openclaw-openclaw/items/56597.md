## Summary

Keep open. Current main and latest release still persist authorized `/exec` session defaults and resolve stored session exec fields ahead of agent defaults, while current docs/tests describe that as session state; the remaining decision is security/product policy, not cleanup closure.

## What This Changes

The issue asks OpenClaw to stop persisted Discord session `/exec` overrides from shadowing later global `tools.exec` security configuration changes.

## Best Possible Solution

Define the canonical `/exec` precedence and reset policy, then implement a tested session-state migration or reset path that lets operator security policy take effect without accidentally breaking documented session defaults.
