## Summary

Keep open. Current main and v2026.6.11 still persist authorized `/exec` session fields and resolve them before configured defaults, while the related ACP cache fix did not change this session-precedence path.

## What This Changes

The issue asks OpenClaw to stop persisted Discord per-session exec directive values from overriding later global exec security configuration changes.

## Best Possible Solution

Define `/exec` session precedence as a security boundary, then implement clamping, clearing, doctor repair, or an operator reset path so stricter operator config can be enforced without surprising existing sessions.
