## Summary

Keep open. Current main and latest release still persist authorized `/exec` session fields and resolve stored session exec values before config-derived defaults, while the merged ACP cache fix only covered an adjacent stale-runtime-handle path.

## What This Changes

The issue asks OpenClaw to stop Discord sessions from indefinitely reusing persisted per-session `/exec` overrides after global exec security config changes.

## Best Possible Solution

Define the canonical `/exec` session precedence and reset policy, then implement a tested migration, doctor repair, reset path, or precedence change so operator security config can be enforced without silently breaking intentional per-session defaults.
