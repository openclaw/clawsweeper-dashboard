Keep open. Current main and the latest release still persist authorized `/exec` session fields and resolve stored session values before config-derived defaults; the merged ACP cache fix addressed a related stale-config path, not this persisted session-state precedence issue.

## What This Changes

The issue asks OpenClaw to stop Discord sessions from letting persisted per-session `/exec` directives shadow later global `tools.exec` security changes.

## Best Possible Solution

Define the canonical `/exec` precedence and reset policy, then implement a tested migration or operator-facing reset path so stricter operator security config can take effect without silently breaking intentional session defaults.

## Reproduction Assessment

Yes, by source inspection: current main writes authorized `/exec` fields into `SessionEntry` and later resolves those stored fields before config-derived defaults. I did not run a live Discord gateway restart in this read-only review.

## Solution Assessment

Unclear. A resolver-order change is plausible, but current docs and tests intentionally describe `/exec` as persistent session state, so the best fix needs maintainer-approved precedence plus migration or reset behavior.
