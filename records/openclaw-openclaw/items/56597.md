## Summary

Keep open. Current main and v2026.6.11 still persist authorized `/exec` fields in session state and resolve stored session values before config-derived defaults; https://github.com/openclaw/openclaw/pull/82237 fixed the related ACP runtime-cache stale-config path but did not change this session precedence behavior.

## What This Changes

The issue asks for Discord `/exec` session overrides not to keep shadowing later global exec security config changes after a gateway restart.

## Best Possible Solution

Define operator exec policy as the upper bound for resumed channel sessions, then add focused persistence, reset, and upgrade coverage so old session fields cannot silently weaken later config.
