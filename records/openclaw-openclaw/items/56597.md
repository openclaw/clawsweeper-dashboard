## Summary

Keep open. Current main and latest release still persist `/exec` fields in session entries and resolve stored session values before config-derived defaults; because docs and tests describe this as per-session state, a fix needs a maintainer security/product decision rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to prevent persisted per-session `/exec` directives from shadowing later global `tools.exec` security/config changes in Discord sessions.

## Best Possible Solution

Define the canonical `/exec` precedence and security-floor policy, then implement tested reset/migration behavior so stricter operator exec policy can take effect without surprising existing session users.
