## Summary

Keep open. Current main and latest release still persist authorized `/exec` session fields and resolve stored session exec policy before config-derived defaults; the related ACP cache fix does not address this auto-reply/session precedence path.

## What This Changes

The issue asks for Discord session `/exec` directives to stop indefinitely overriding later global `tools.exec.*` security or allowlist changes after a session resumes.

## Best Possible Solution

Define the canonical `/exec` session precedence and reset policy, then implement tested clamp, reset, migration, or doctor behavior so operator security config can be enforced without silently breaking intentional session defaults.
