## Summary

Keep open. Current main and v2026.6.11 still persist `/exec` session fields and resolve those stored values before config-derived defaults; the related ACP cache fix addressed an adjacent stale-config path, but this remaining behavior needs a maintainer security/product decision.

## What This Changes

The issue asks for Discord `/exec` per-session directives to stop indefinitely overriding later global exec security config changes.

## Best Possible Solution

Define the intended security precedence for persisted `/exec` session defaults, then implement a tested reset or migration path that lets stricter operator config take effect without accidentally breaking authorized session-default workflows.
