## Summary

Keep open. Current main and latest release still persist authorized `/exec` values in session entries and resolve those stored values before config-derived defaults; the remaining question is a security/product policy decision, not conservative cleanup.

## What This Changes

The issue asks OpenClaw to stop persisted Discord session `/exec` overrides from shadowing later global `tools.exec` security configuration changes.

## Best Possible Solution

Define the canonical `/exec` precedence and reset policy, then implement tests and docs so operator security changes can invalidate or clear stale session exec overrides without accidentally breaking intended per-session defaults.
