## Summary

Keep open. Current main and latest release still persist authorized `/exec` values in session state and resolve those stored values before config-derived defaults; because docs and tests now describe this as per-session behavior, changing it needs maintainer security/product direction rather than cleanup closure.

## What This Changes

Request that Discord sessions respect later global `tools.exec` policy changes instead of letting persisted per-session `/exec` overrides shadow them indefinitely.

## Best Possible Solution

Define the canonical `/exec` precedence and reset policy, then implement a tested session-state migration, doctor repair, or reset path that lets operator exec-security changes take effect without silently breaking documented session defaults.
