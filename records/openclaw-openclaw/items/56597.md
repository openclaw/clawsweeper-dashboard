## Summary

Keep open. Current main and v2026.6.11 still persist `/exec` session fields and resolve stored session values ahead of config-derived defaults, while current docs/tests make that behavior intentional enough to require a security/product decision before changing it.

## What This Changes

The issue asks OpenClaw to prevent Discord session-stored `/exec` defaults from shadowing later global exec-security configuration changes.

## Best Possible Solution

Define operator exec policy as the safety boundary, then implement a tested session-state migration or reset path that preserves intentional `/exec` defaults only when they cannot weaken later config.
