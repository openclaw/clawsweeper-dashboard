## Summary

Keep open. Current main and latest release v2026.6.11 still persist authorized `/exec` values into `SessionEntry` and resolve those stored values ahead of config-derived defaults; the merged ACP cache fix covers a related stale-runtime-handle path, but not this remaining precedence/reset policy.

## What This Changes

The issue requests that Discord session `/exec` overrides stop indefinitely shadowing later global `tools.exec` security configuration changes.

## Best Possible Solution

Define the canonical `/exec` precedence and reset policy, then implement a tested session-state migration, doctor repair, or reset path that lets operator security policy take effect without accidentally breaking documented session defaults.
