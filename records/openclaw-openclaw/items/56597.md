## Summary

Keep open. Current main and latest release v2026.6.11 still persist authorized `/exec` session fields and resolve stored session values before config-derived defaults, while the related ACP cache fix only addressed runtime-handle freshness.

## What This Changes

The issue requests changing Discord session exec directive persistence so old per-session `/exec` values do not indefinitely override later global `tools.exec` security policy changes.

## Best Possible Solution

Define `/exec` session precedence so current global, agent, and host-approval policy remain the enforceable safety boundary, then implement the chosen clamp/reset/migration path with focused session and Discord-routing coverage.
