## Summary

Keep open. Current main and latest release still persist `/exec` session fields and resolve them ahead of agent/global exec defaults; https://github.com/openclaw/openclaw/pull/82237 fixed a related ACP runtime-cache stale-config path but not this session precedence.

## What This Changes

The issue asks for Discord `/exec` session overrides not to keep overriding changed global exec security configuration indefinitely.

## Best Possible Solution

Define the exec policy contract explicitly: global/agent config and host approvals should be the safety floor, with a reset, doctor, or migration path for persisted session overrides if maintainers change the semantics.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should persisted `/exec` session defaults be allowed to loosen current global or agent exec policy after config changes, and what reset or migration behavior should existing sessions get?

Rationale: Current docs and tests intentionally treat `/exec` as persisted session state, but the report shows that this can undermine operator expectations for global exec security changes.

Likely owner: Peter Steinberger

Owner reason: Peter introduced the `/exec` session override contract and later added the focused coverage that currently encodes the precedence behavior.

Owner confidence: high

Options:

- **Make config the safety floor (recommended):** Keep `/exec` as a session convenience, but prevent persisted session values from loosening current global/agent policy and add cleanup coverage for existing stored fields.
- **Keep current session contract:** Retain persisted `/exec` precedence and document that hard revocation must use tool policy, host approvals, or an explicit session reset path.
- **Expire exec overrides on config changes:** Track a config signature and clear or ignore stored exec fields when relevant `tools.exec` settings change.

## Reproduction Assessment

Yes, from source inspection: current main writes `/exec` values into `SessionEntry` and resolves those fields before agent/global defaults. I did not run a live Discord restart, so this is source-reproducible rather than tool-reproduced.

## Solution Assessment

Unclear until maintainers choose the security contract. Reordering precedence or stopping persistence is plausible, but current docs and tests make persisted `/exec` session defaults intentional, so the best fix needs a policy decision and upgrade/reset handling.
