## Summary

Keep open. Current main and latest release v2026.6.11 still persist authorized `/exec` values into session state and resolve those stored values ahead of config-derived defaults, so the reported security/session-state behavior remains a maintainer policy decision rather than cleanup-close material.

## What This Changes

This issue asks OpenClaw to stop persisted Discord `/exec` session overrides from continuing to trump later `tools.exec` config changes.

## Best Possible Solution

Define the canonical /exec security precedence as an operator-controlled policy, then implement a tested session-state migration or reset path so stricter global or agent config takes effect for existing Discord sessions.
