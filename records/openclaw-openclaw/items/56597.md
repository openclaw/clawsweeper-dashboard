## Summary

Keep open. Current main and v2026.6.11 still persist `/exec` fields in session state and resolve stored session values before config-derived defaults, while current docs and tests describe this as per-session behavior, so this needs a maintainer security/product decision rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to stop persisted Discord/session `/exec` exec overrides from shadowing later global `tools.exec` security and allowlist config changes.

## Best Possible Solution

Define the canonical `/exec` precedence and reset policy, then implement a tested session-state migration or reset path that lets operator security policy take effect without accidentally breaking documented session defaults.
