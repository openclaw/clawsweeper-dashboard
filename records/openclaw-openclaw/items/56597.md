## What This Changes

The issue requests that Discord `/exec` session overrides stop indefinitely shadowing later global `tools.exec` security/default changes.

## Best Possible Solution

Define and document canonical exec precedence/reset semantics, then implement a tested migration or reset path so stricter operator config can take effect without unintentionally breaking authorized `/exec` session defaults.

## Solution Assessment

Unclear. A simple precedence flip is plausible, but current docs and tests intentionally describe `/exec` as persistent session state, so the best fix needs maintainer-approved security policy plus migration/reset handling.
