## Summary

Keep open. Current main and v2026.6.11 still persist `/exec` directive fields in session state and layer them above global exec config, but docs/tests also treat `/exec` as a persistent per-session default, so resolving this needs an explicit maintainer security/product decision.

## What This Changes

The issue requests that Discord session-stored exec directive values stop overriding later global `tools.exec` policy changes indefinitely.

## Best Possible Solution

Adopt a maintainer-approved exec override lifecycle that distinguishes explicit persistent session overrides from transient channel directives, with docs/tests and a Doctor or operator reset path for existing persisted exec fields if global policy should tighten old sessions.

Options:

- **Preserve Overrides With Reset (recommended):** Keep documented persistent session overrides, but add/clarify operator audit, Doctor, or reset guidance for clearing stale exec fields after policy changes.
- **Make Channel Exec Ephemeral:** Stop persisting channel-origin exec directives or clear them on restart/config generation so global policy automatically regains control.
- **Global Policy Wins:** Change resolver precedence so global or agent exec policy can tighten stored session exec values, accepting the compatibility break for prior session defaults.
