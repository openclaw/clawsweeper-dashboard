## Summary

Keep open. Current main and latest release still persist authorized `/exec` defaults in session state and resolve them before config-derived defaults; the related ACP fix at https://github.com/openclaw/openclaw/pull/82237 addressed a separate runtime-cache freshness path, not this persisted session precedence behavior.

## What This Changes

The issue asks OpenClaw to stop persisted Discord `/exec` session directives from overriding later global exec-security configuration changes.

## Best Possible Solution

Define an enforceable `/exec` precedence and reset contract so operator security config cannot be silently shadowed by old channel-session state.
