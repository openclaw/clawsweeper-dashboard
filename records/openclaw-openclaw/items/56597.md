## Summary

Keep open. Current main and the latest release still persist `/exec` fields in session entries and resolve stored session values before config-derived defaults, while current docs/tests describe `/exec` as durable per-session state; resolving this needs a maintainer security/product decision rather than conservative cleanup close.

## What This Changes

The issue asks OpenClaw to stop Discord session-stored `/exec` policy fields from shadowing later global `tools.exec` security configuration changes.

## Best Possible Solution

Define the canonical `/exec` precedence and reset policy, then implement tested migration or reset semantics so operator security config can take effect without requiring manual session deletion.
