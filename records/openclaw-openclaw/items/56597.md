## Summary

Keep open. Current main and latest release v2026.6.11 still persist `/exec` session fields and resolve stored session values before config-derived defaults, while docs/tests now describe that as per-session behavior; changing it needs a maintainer security/product decision rather than cleanup close.

## What This Changes

The issue asks OpenClaw to stop Discord session-stored `/exec` overrides from indefinitely overriding later global `tools.exec` security and safeBins changes.

## Best Possible Solution

Define the `/exec` security precedence contract, preferably making global/agent hardening authoritative over stored session exec defaults and providing a migration, doctor, or reset path for existing entries.

Question: Should stored per-session `/exec` defaults be allowed to loosen the current global or per-agent exec security policy after config changes?

Rationale: Current code, docs, and tests make persistent session overrides intentional, but the reported behavior affects an exec security boundary and changing precedence would be a compatibility-sensitive policy decision.

Owner confidence: high

Options:

- **Make config hardening authoritative (recommended):** Treat global/per-agent exec security as an upper bound for stored session overrides, add regression coverage, and provide a reset or doctor path for existing persisted exec fields.
- **Keep persistent session overrides:** Preserve the current contract and improve docs/diagnostics so operators use tool policy deny or session reset when they need to revoke old `/exec` defaults.
- **Add reset without precedence change:** Keep `/exec` precedence as-is but add an operator-visible way to clear stored exec defaults for selected sessions or channels.
