## Summary

Keep open. Current main and latest release still persist authorized `/exec` session defaults and apply stored session exec fields over global config; the related merged ACP cache fix addresses a different stale-runtime-handle path, not this remaining session-state/security-precedence question.

## What This Changes

The issue asks for Discord `/exec` session defaults not to indefinitely override later global `tools.exec` security config changes.

## Best Possible Solution

Pick and document one explicit exec precedence contract; if operator config should be authoritative, clear or ignore stored session exec fields on config changes and cover Discord/gateway resume with regression tests.
