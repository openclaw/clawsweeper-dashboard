## Summary

Keep open. Current main and v2026.6.11 still persist authorized `/exec` session fields and resolve stored session exec values before config-derived defaults; the merged related ACP cache fix does not address this per-session precedence path.

## What This Changes

The issue asks OpenClaw to stop Discord sessions from letting persisted per-session `/exec` overrides shadow later global exec-security config changes.

## Best Possible Solution

Define the canonical `/exec` precedence and reset policy so operator security hardening cannot be silently shadowed by stale session state, then implement migration/reset coverage for existing persisted entries.
