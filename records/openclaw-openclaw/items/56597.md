## Summary

Keep open. Current main still persists `/exec` fields on session entries and resolves stored session exec values before per-agent/global exec defaults, while docs/tests describe `/exec` as a per-session behavior, so this needs maintainer security/product direction rather than cleanup close.

## What This Changes

The issue asks OpenClaw to stop persisted Discord session exec directives from overriding later global exec security configuration changes.

## Best Possible Solution

Maintainers should decide the permanent precedence contract for session `/exec` overrides versus global or per-agent exec policy, then update source, docs, and regression tests together.
