## Summary

Keep open. Current main and v2026.6.11 still persist `/exec` fields in session entries and resolve stored session values before config-derived defaults, while docs/tests describe that as per-session behavior; this needs a maintainer security/product decision rather than cleanup close.

## What This Changes

The issue asks OpenClaw to stop stale Discord per-session `/exec` overrides from outliving global exec-policy config changes.

## Best Possible Solution

Define the canonical `/exec` precedence and reset policy, then implement a tested session-state migration or reset path that lets operator security policy take effect without silently breaking documented session defaults.
