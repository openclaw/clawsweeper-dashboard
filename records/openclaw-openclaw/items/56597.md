## Summary

Keep open. Current main and latest release v2026.6.11 still persist authorized `/exec` defaults in session entries and resolve those stored values ahead of config-derived defaults; current docs/tests treat this as a session-level contract, so cleanup should wait for a maintainer security/product decision.

## What This Changes

The issue asks OpenClaw to prevent Discord session-stored `/exec` directives from continuing to override global `tools.exec` policy after config changes or gateway restarts.

## Best Possible Solution

Maintainers should choose one exec-precedence contract, then implement it with docs and regression coverage so operator-owned deny/tool policy remains authoritative and any retired session `exec*` fields are cleared through doctor or an explicit session reset path.
