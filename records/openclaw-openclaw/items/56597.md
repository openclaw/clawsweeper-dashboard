## Summary

Keep open. Current main still persists authorized session-level exec directives and applies session/per-run exec policy after global and agent config; the merged ACP cache PR fixed a related stale-runtime-handle path, not this persisted `/exec` precedence question.

## What This Changes

The issue asks for Discord/global exec security config changes to override previously persisted per-session `/exec` directives instead of carrying old exec settings forward across restarts.

## Best Possible Solution

Define a maintainer-approved exec policy hierarchy where global/admin security policy and host approvals remain non-bypassable, then update session `/exec` persistence, reset or migration behavior, tests, and docs to match that contract.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should persisted per-session `/exec` defaults be allowed to override later global `tools.exec.*` config changes for Discord and other channel sessions?

Rationale: Current source and tests treat `/exec` as a durable session default, while the report asks to make administrator/global security config take precedence; that is a security-boundary and compatibility choice.

Likely owner: steipete

Owner reason: Recent history ties this person to the current directive/session implementation and adjacent docs/tests.

Owner confidence: high

Options:

- **Global policy floor (recommended):** Keep `/exec` as a session convenience only when it stays within the current global/admin policy, and add focused reset/migration/tests/docs for older persisted fields.
- **Keep durable session override:** Accept the current behavior as intentional, document that existing sessions can retain `/exec` defaults until reset, and add operator-facing inspection or reset guidance.
- **Make `/exec` ephemeral:** Stop persisting exec directives entirely so config changes win after restart, accepting a breaking change for users who expect durable session exec defaults.

## Reproduction Assessment

Yes, at source level. Current main persists authorized `/exec` fields on SessionEntry and later resolves them ahead of configured agent/global defaults, so a stored session value can continue to affect later Discord turns.

## Solution Assessment

Unclear. Removing persistence, changing precedence, or adding reset/migration can all solve the report, but the best fix depends on the maintainer's security and compatibility decision for `/exec` session defaults.
