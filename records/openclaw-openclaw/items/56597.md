## Summary

Keep open. Current main and latest release v2026.6.11 still persist authorized `/exec` defaults into session state and prefer those stored fields over config-derived defaults, while the related merged ACP cache fix did not touch this source path. The remaining question is a security-sensitive product decision about whether operator exec policy should bound or reset older per-session values.

## What This Changes

The issue reports Discord per-session `/exec` directives persisting in session state and overriding later global exec security config changes.

## Best Possible Solution

Define the canonical `/exec` precedence and reset policy, then implement a tested migration, doctor repair, reset path, or resolver change so operator security config can be enforced without silently breaking intentional per-session defaults.
