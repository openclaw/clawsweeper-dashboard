## Summary

Keep open. Current main and the latest release still preserve `/exec` session fields and resolve them ahead of config-derived exec defaults, so the reported behavior remains real, but changing it is a security-sensitive session-policy decision rather than a conservative cleanup close.

## What This Changes

The issue asks OpenClaw to stop persisted Discord/session `/exec` overrides from masking later global `tools.exec.*` configuration changes.

## Best Possible Solution

Define one supported lifecycle for `/exec` session overrides, then implement it with matching docs, focused regression tests, and an operator-friendly reset or doctor path for clearing stale exec overrides.

Owner confidence: medium

Options:

- **Preserve compatibility plus add reset (recommended):** Keep persistent `/exec` defaults as the default contract, but add a clear operator reset/doctor/session-patch path and docs for clearing stale exec overrides after policy changes.
- **Make config authoritative:** Change precedence so changed global or agent `tools.exec.*` policy overrides stored session exec fields, accepting an upgrade behavior change for users relying on persistent session defaults.
- **Stop persisting `/exec`:** Treat `/exec` as ephemeral turn/session runtime state only, which is simpler for security posture but breaks the current documented persistence model most aggressively.
