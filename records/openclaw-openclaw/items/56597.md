## Summary

Keep open. Current main and latest release still persist and apply `/exec` session overrides ahead of config-derived defaults; a related ACP cache fix only addressed a different stale-config path, and resolving this needs maintainer security/product direction because current docs/tests describe durable per-session `/exec` state.

## What This Changes

The issue asks for Discord sessions to stop carrying persisted `/exec` host/security/ask/node overrides across global `tools.exec` config changes.

## Best Possible Solution

Make an explicit maintainer-approved security contract for `/exec` session state, with docs/tests and an operator-safe reset or repair path so global policy can be enforced without manual session-store edits.
