## What This Changes

Adds `openclaw models auth clear-cooldown <profile-id>` so an operator can clear persisted failure windows for one saved auth profile after an upstream billing or usage condition recovers early.

## System Context

OpenClaw records provider-auth cooldown and failure state so model routing can avoid repeatedly selecting an unavailable profile. This command updates that persisted state through the locked auth-profile store, then tells the operator to refresh the Gateway’s in-memory bookkeeping before the next provider selection.

## Architecture Diagram

flowchart TD
  A[Provider billing or usage recovers] --> B[Saved auth profile remains locally blocked]
  B --> C[Operator runs clear-cooldown command]
  C --> D[Locked persisted auth-state update]
  D --> E[Safe Gateway restart]
  E --> F[Next request re-evaluates provider availability]

## Best Possible Solution

Adopt a single supported recovery path only after confirming whether this explicit profile-scoped CLI command is preferable to a Doctor, Control UI, or automatic-probe recovery surface, and retain the command’s narrow locked-store and credential-preserving behavior if accepted.
