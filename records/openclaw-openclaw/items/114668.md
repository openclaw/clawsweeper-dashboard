## Summary

Keep this PR open: it addresses a real Microsoft Foundry metadata regression, but the new table classifies an undocumented canonical ID as known and the PR has only test/static evidence, not an after-fix Foundry discovery run. The owner-plugin boundary is appropriate; tighten the capability contract and add redacted live proof before merge.

## What This Changes

The PR replaces Microsoft Foundry’s generic token fallback for discovered GPT deployments with model-specific context and output limits, including a Responses API budget for GPT-5.5.

## System Context

The bundled Microsoft Foundry plugin discovers deployments and writes provider-model metadata into the user configuration. Agent context compaction and output budgeting consume that metadata, so incorrect limits can compact conversations early or cap replies below the deployed model’s capacity.
