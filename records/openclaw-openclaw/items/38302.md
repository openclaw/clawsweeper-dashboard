## Summary

Keep open: current main and the latest release still lack an account-level Slack native command naming contract, while the two linked implementation PRs were closed unmerged. The corroborating user comment supports the multi-agent Slack need, but the remaining blocker is maintainer product/API direction.

## What This Changes

The issue requests account-specific Slack native slash-command names or prefixes so multiple OpenClaw Slack apps can register separately targetable commands in the same workspace.

## Best Possible Solution

Choose one Slack account-level native naming contract, implement it in the Slack plugin registration and dispatch paths without changing existing defaults, and prove fresh setup plus upgrade behavior with focused tests and live Slack smoke evidence.

Rationale: The fix adds a user-visible Slack account config/API surface and the closed implementation attempts show a real design fork that automation should not choose by itself.

Owner confidence: high

Options:

- **Implement explicit nativeNames (recommended):** Add validated per-account command-key to native-name mapping with duplicate/format checks, registration, dispatch, docs, and Slack native command tests.
- **Implement constrained nativePrefix:** Add prefix sugar only with strict lowercase slug validation and no broad fallback stripping if maintainers prefer the simpler operator UX.
- **Document unsupported duplicates:** Leave runtime unchanged and document that multiple Slack apps in one workspace must not register identical native command names.

## Reproduction Assessment

Yes. Source inspection shows current main has no account-level Slack native naming field, its strict schema rejects the proposed config, and registration/lookup are provider-scoped; I did not run live Slack workspace proof.

## Solution Assessment

Unclear until maintainers choose the product contract. Prefixing is plausible, but a validated explicit nativeNames mapping appears safer because it avoids implicit alias behavior and matches the later unmerged PR direction.
