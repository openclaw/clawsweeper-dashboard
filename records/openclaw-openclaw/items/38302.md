## Summary

Keep open: current main and v2026.6.11 still lack an account-level Slack native-command naming contract, so multi-app Slack slash-command collisions remain. The linked implementation attempts are closed unmerged, and the remaining blocker is choosing the supported config/API shape.

## What This Changes

The issue requests per-account Slack native slash-command names, originally via a `nativePrefix`, so multiple Slack apps in one workspace can target separate OpenClaw agents without duplicate command-name collisions.

## Best Possible Solution

Adopt one validated account-level Slack native command naming contract, likely explicit nativeNames mapping unless maintainers deliberately choose prefix sugar, and cover registration, dispatch, arg-menu callbacks, docs, and schema validation in one focused Slack plugin change.

Options:

- **Implement Constrained nativePrefix:** Add prefix sugar with strict lowercase slug validation and no broad dash-stripping fallback, accepting simpler setup but a second naming abstraction.
- **Document Unsupported Duplicate Names:** Leave runtime unchanged and document that multiple Slack apps in one workspace must not register identical native command names.

Unclear until maintainers choose the product contract. Prefixing is plausible, but the prior PR discussion and config-surface policy make a validated explicit `nativeNames` mapping the safer default direction.
