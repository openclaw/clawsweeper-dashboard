## Label Justifications

- `P2`: The issue affects real multi-agent Slack deployments but is a bounded feature/config decision rather than an emergency outage.
- `impact:message-loss`: Duplicate Slack native slash command names can cause Slack commands to reach the wrong app, so the intended agent may not receive the command.
- `impact:session-state`: The ambiguous commands named in the report include reset, compact, and stop, which directly affect agent/session state.

## Summary

Keep open: current main still has no account-level Slack native command naming contract, so the reported multi-app slash-command collision remains. The two implementation attempts were closed unmerged, and the remaining blocker is the product/API choice between explicit per-account native names, constrained prefix sugar, or documenting duplicate Slack native names as unsupported.

## What This Changes

The issue requests account-level Slack native slash-command prefixes so multi-agent Slack apps can register distinct commands such as `/oz-reset` and `/dross-reset`.

## Best Possible Solution

Adopt one validated account-level Slack native command naming contract in the Slack plugin, likely explicit `nativeNames` mapping unless maintainers deliberately choose constrained prefix sugar, and cover registration, dispatch, arg-menu callbacks, docs, and schema validation together.

- **Document unsupported duplicate names:** Leave runtime unchanged and document that multiple Slack apps in one workspace must not register identical native command names.
