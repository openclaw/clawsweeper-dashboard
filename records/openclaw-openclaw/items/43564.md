## Label Justifications

- `P2`: This is a normal-priority feature/design issue with bounded but real impact on ACP child-session context and security semantics.
- `impact:session-state`: The request changes what skill context is attached to spawned ACP sessions and how that context may interact with resume and prompt history.
- `impact:security`: The request would forward local skill material into external harness prompts, requiring explicit redaction, isolation, and authority semantics.
- `maturity:stable`: The request touches the M4 Gateway runtime `sessions.*` and tool/skill API surface even though ACP external-runtime behavior is less mature.

## Summary

Keep open: current main and v2026.6.11 still do not expose a `sessions_spawn` skill selector, ACP skill-context payload, rendered prompt carrier, or audit/redaction contract, and the related Codex/native prompt-contract issue only partially overlaps this ACP-specific feature request.

## What This Changes

Request ACP `sessions_spawn` to optionally inject selected OpenClaw skill context into spawned ACP agent sessions.

## Best Possible Solution

Define a narrow opt-in ACP skill-context contract with explicit skill ids, redaction/audit metadata, prompt-layer semantics, resume behavior, tests, and docs before implementation.

Owner confidence: high

Options:

- **Limit first pass to explicit skill ids:** Allow only per-call `skills: [...]` injection initially and defer `auto` and default sets until observability and security behavior are proven.
- **Decline core injection:** Keep ACP harnesses isolated from OpenClaw-rendered skills and direct users to harness-native skills, MCP bridges, or plugin workflows instead.
