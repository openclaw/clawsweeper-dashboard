## Label Justifications

- `P2`: This is a normal-priority feature/design issue with bounded but real impact on ACP child-session context and security semantics.
- `impact:session-state`: The request changes what skill context is attached to spawned ACP sessions and how that context may persist, resume, or diverge from the parent session.
- `impact:security`: The request would forward local skill material into external harness prompts, requiring explicit redaction, isolation, and authority semantics.

## Summary

Keep open: current main and the latest stable release still lack an ACP `sessions_spawn` skill selector or typed skill-context carrier, and the remaining work is a product/security contract decision rather than conservative cleanup.

## What This Changes

The issue requests optional rendered OpenClaw skill context injection for ACP `sessions_spawn` sessions, including explicit, automatic, or default skill selection.

## Best Possible Solution

Define an audited ACP skill-context contract first, preferably explicit skill ids before auto/default selection, then wire it through `sessions_spawn`, ACP runtime types, observability, docs, and tests.

- **Defer core injection:** Keep ACP children isolated from OpenClaw-rendered skill content for now and steer users to harness-native skills, MCP bridges, or plugin workflows.

## Solution Assessment

Unclear as proposed. Explicit skill ids look like the narrowest safe first step, while automatic and default injection need maintainer decisions about privacy, observability, token cost, and Codex/native parity.
