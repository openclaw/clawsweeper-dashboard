## Label Justifications

- `P2`: This is a normal-priority feature/design issue with bounded but real impact on ACP child-session context and security semantics.
- `impact:session-state`: The request changes what skill context is attached to spawned ACP sessions and how that context may interact with resume and prompt history.
- `impact:security`: The request would forward local skill material into external harness prompts, requiring explicit redaction, isolation, and authority semantics.
- `maturity:stable`: The requested `sessions_spawn` contract touches the stable Gateway runtime/tool API surface while also crossing less-mature ACP external-runtime behavior.

## Summary

Keep open: current main and v2026.6.11 still have no ACP `sessions_spawn` skill selector, rendered skill-context carrier, or audit/redaction metadata, and #95058 only partially overlaps the broader prompt-contract parity problem.

## What This Changes

Request optional OpenClaw skill context injection for ACP `sessions_spawn`, including explicit, automatic, or default skill selection and rendered prompt delivery to ACP child sessions.

## Best Possible Solution

Define a narrow, audited ACP skill-context contract first, preferably explicit opt-in skill ids with redaction/audit metadata, before adding schema, runtime, docs, and parity tests.

- **Decline core injection:** Keep ACP harnesses isolated from OpenClaw-rendered skills and direct users to harness-native skills, MCP bridges, or plugin workflows instead.
