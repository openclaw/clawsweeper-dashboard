- `P2`: This is a normal-priority feature/design issue with bounded but real impact on ACP child-session context and security semantics.
- `impact:session-state`: The request changes what skill context is attached to spawned ACP sessions and how that context may persist, resume, or diverge from the parent session.
- `impact:security`: The request would send local trusted skill material into external ACP harness prompts, requiring explicit redaction, isolation, and authority semantics.

## Summary

Keep open: current main and v2026.6.11 still lack a `sessions_spawn(runtime: "acp")` skill selector or ACP skill-context carrier, and the remaining work needs a maintainer-approved product/security contract rather than cleanup closure.

## What This Changes

Request to let `sessions_spawn(runtime: "acp")` inject selected, automatic, or default OpenClaw skill context into ACP child sessions.

## Best Possible Solution

Define one ACP skill-context contract covering explicit/default/auto selection, redaction, observability, prompt layer, resume behavior, and Codex-native skill interaction, then update `sessions_spawn`, ACP runtime types, docs, and focused tests together.
