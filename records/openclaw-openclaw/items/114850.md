## Summary

The branch identifies a real recovery problem, but its unconditional failed-to-local transition also applies after the state machine has entered reconciliation. That can bypass the existing worker-to-local synchronization boundary, so this needs a narrow lifecycle guard and real cloud-worker proof before merge.

## What This Changes

The PR makes a cloud-worker session run locally on its next turn after its placement reaches the failed state, and documents that recovery behavior.

## System Context

Cloud-worker placement is a durable gateway state machine that routes each session turn either to a remote worker or the local gateway. Placement transitions coordinate worker teardown and workspace reconciliation before later turns resume from the authoritative local session.

## Architecture Diagram

flowchart LR
  A[Incoming session turn] --> B[Read durable placement]
  B --> C{Placement state}
  C -->|active worker| D[Run on cloud worker]
  C -->|local| E[Run on gateway]
  D --> F[Drain and reconcile workspace]
  F --> G[Resume local or worker placement]
  C -->|failed| H[Recovery decision]

## Best Possible Solution

Differentiate pre-worker dispatch/bootstrap failures from post-worker or reconciliation failures; automatically return only the former to local, and preserve the existing drain/reconcile recovery contract for the latter before accepting another local turn.
