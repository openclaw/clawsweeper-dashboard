## Summary

The revised patch addresses the prior reconciliation-boundary concern by limiting automatic local recovery to failures before worker ownership. It should remain open for a redacted real cloud-worker recovery trace before merge; the current body provides focused mock/static validation only.

## What This Changes

The PR lets a cloud-worker session recover from a pre-worker dispatch or bootstrap failure by returning its durable placement to local execution on the next turn, while preserving worker-owned failures for reconciliation.

## System Context

Cloud-worker placement records decide whether an agent turn executes on a remote worker or the gateway host. The placement store, turn launcher, and reconciliation flow must preserve remote workspace ownership until worker-produced changes are safely reconciled.

## Architecture Diagram

flowchart LR
  A[Incoming agent turn] --> B[Read durable placement]
  B --> C{Placement state and ownership}
  C -->|Failed before worker ownership| D[Reclaim placement to local]
  D --> E[Execute turn on gateway host]
  C -->|Failed after worker ownership| F[Drain and reconcile workspace]
  F --> G[Safe worker recovery]
  C -->|Active worker| H[Execute turn remotely]

## Best Possible Solution

Keep the guarded `failed -> local` path only for placements that never reached worker ownership, retain reconciliation for worker-owned failures, and attach redacted live proof of a failed bootstrap followed by a successful local turn before merge.
