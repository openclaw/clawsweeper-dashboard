## Summary

This PR is still necessary because current main and the latest release do not have the late-dispatch proof scenario, but it is not merge-ready: the forced late-final path can still leave Telegram status reactions in the error state, and the PR body explicitly lacks exact-path real Telegram proof.

## What This Changes

The branch adds a gated Telegram private-QA late-dispatch fault hook, a `--proof-scenario late-dispatch-after-final` proof-runner mode, Mantis prompt guidance, and fallback/retry tests for Telegram dispatch cleanup after visible output.

## Best Possible Solution

Align fallback, retry, and status reactions on delivered-final semantics, then land the private proof hook only with exact-path Telegram proof or explicit maintainer acceptance of the proof gap.

## Reproduction Assessment

Yes at source level: current main sends the generic Telegram fallback on `dispatchError`, and PR head can inject a late dispatch error after final delivery. No live forced-path Telegram proof was supplied or run in this read-only review.

## Solution Assessment

No as-is: the proof hook is a plausible harness, but the patch leaves final status reactions tied to `dispatchError` after a visible final reply. The safer fix is to align status with the same delivered-final boundary and then prove the exact path.
