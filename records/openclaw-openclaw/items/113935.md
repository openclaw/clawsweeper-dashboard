## Label Justifications

- `P1`: Affected non-Codex ACP sessions can fail before their first turn whenever inherited or spawn-time thinking values are not accepted by the backend.

## Summary

Keep this PR open for normal merge review. Its narrowly scoped core safeguard is consistent with the existing best-effort treatment of optional pre-turn controls: a backend’s rejected thinking value no longer prevents the turn, while required controls and explicit user configuration writes still fail normally.

## What This Changes

ACP (Agent Client Protocol) session setup now treats a backend rejection of an automatically applied thinking value as an optional-control failure and continues the agent turn.

## System Context

Before an ACP agent turn starts, the control plane derives runtime options from the stored session and applies them to the selected backend. This path validates backend capabilities, writes optional tuning controls such as thinking, then starts the turn or reports a required-control failure.

## Architecture Diagram

flowchart LR

  B --> C[Backend capabilities]
  C --> D[Apply pre-turn controls]
  D --> E[ACP backend]
  E --> F[Start agent turn]
  D --> G[Required-control failure]

## Best Possible Solution

Land the focused generic control-plane guard with its regression tests so automatic optional thinking hints cannot abort ACP turns, while keeping adapter-specific value translation and explicit configuration errors at their existing boundaries.
