## Summary

Keep open: current main has adjacent provider-refusal diagnostics and fallback plumbing, plus documented operator scopes and exec approvals, but it still does not define the requested trusted-operator contract that separates model soft refusal from SSH/tool/auth failure for authorized operational diagnostics.

## What This Changes

Request to distinguish model soft refusals from tool/auth failures and let explicitly authorized read-only operational diagnostics proceed under a trusted-operator policy.

## Best Possible Solution

Define a security-reviewed trusted-operator diagnostics path that records whether a turn stopped due to model refusal, authorization denial, or tool failure, while biasing read-only diagnostics toward execution only inside existing tool, exec, and operator-scope permissions.
