## Summary

Keep open: current main only addresses a narrow Anthropic Fable 5 direct API-key refusal fallback, while the broader trusted-operator SSH/read-only diagnostics behavior and refusal-vs-auth/tool-failure observability remain unresolved and require maintainer security/product direction.

## What This Changes

The issue asks OpenClaw to reduce model soft refusals for explicitly authorized read-only infrastructure diagnostics and make model refusal, authorization denial, and tool failure distinguishable.

## Best Possible Solution

Define a narrow, security-reviewed trusted-operator diagnostics contract that records model refusal versus auth/tool failure and biases authorized read-only infrastructure diagnostics toward execution only inside existing operator scopes, tool policy, and exec approval boundaries.
