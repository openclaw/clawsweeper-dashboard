## Summary

Keep open: current main has several adjacent mitigations, including execution-bias prompting, strict-agentic recovery, raw trace diagnostics, direct tool-invocation envelopes, and a Claude Fable 5 provider-level refusal fallback, but it still does not define the broader trusted-operator contract requested here.

## What This Changes

Requests a trusted-operator execution and diagnostic path so authorized operational tasks are not confused with model soft refusals, authorization denials, or tool failures.

## Best Possible Solution

Define a maintainer-approved trusted-operator contract that separates tool failure, authorization denial, provider refusal, and model soft refusal while keeping read-only diagnostics easier only inside explicit operator/tool-policy boundaries.

## Reproduction Assessment

No, not for the full issue: the discussion describes intermittent SSH/admin soft refusals but does not include a concrete transcript, provider/model, config, or live reproduction path. Source inspection does confirm adjacent refusal and diagnostics paths that explain part of the symptom space.

## Solution Assessment

No, current main is not the complete solution: it has useful partial mitigations, but the best fix is a product/security design that reuses operator scopes, tool policy, trace diagnostics, and provider refusal handling instead of adding an ad hoc prompt tweak.
