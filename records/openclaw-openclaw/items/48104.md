## Summary

Keep open: current main has a narrow Anthropic Fable 5 refusal fallback and useful refusal diagnostics, but it still does not define the broader trusted-operator contract for authorized SSH/read-only infrastructure diagnostics or fully distinguish model soft refusal from auth/tool failure.

## What This Changes

The issue requests clearer model-refusal, permission, and tool-failure separation plus safer execution bias for explicitly authorized read-only operator diagnostics such as SSH troubleshooting.

## Best Possible Solution

Define a narrow, security-reviewed trusted-operator diagnostics contract that records model refusal versus auth/tool failure and biases read-only infrastructure diagnostics toward execution only inside existing operator scopes, tool policy, and exec approval boundaries.
