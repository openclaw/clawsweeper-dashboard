## Summary

Keep open: this is a useful bug-fix attempt, but it is not merge-ready because it raises the inner Skill Workshop apply approval window to 300s while current Codex main-thread and side-thread dynamic-tool calls still default to a 90s outer watchdog. The timeout policy is also security-sensitive because it controls how long generated-skill apply approval remains actionable.

## What This Changes

The branch adds a 300000ms timeout override for `skill_workshop` `apply` approval requests in `src/skills/workshop/policy.ts`.

## Best Possible Solution

Choose one Skill Workshop approval timeout contract, then align the core approval TTL, Codex main/side dynamic-tool watchdogs, focused tests, and live approval-path proof around that contract.

## Reproduction Assessment

Yes, at source level: default Skill Workshop approval can wait 120s plus gateway grace while Codex dynamic-tool calls default to a 90s watchdog. This PR raises only the inner approval window to 300s, so the same mismatch remains unless outer watchdogs change too.

## Solution Assessment

No. The proposed change is only a plausible inner-timeout adjustment; the best fix must align the approval TTL with every outer tool-call watchdog, or keep the approval TTL within the existing watchdog and land the narrower Codex timeout repair.
