## Summary

Keep open: current main and the latest release still contain the resolver path that lets a job-level channel-shaped failure destination without `mode` inherit a global webhook mode, and the two closing PRs are still open candidate fixes rather than merged implementations.

## What This Changes

The issue reports that cron failure alerts can be dropped when a job-level channel-shaped failure destination without `mode` is resolved over a global webhook failure destination.

## Best Possible Solution

## Solution Assessment

Yes. The resolver is the right boundary because it produces the wrong mode before gateway dispatch chooses announce versus webhook; the fix should keep explicit webhook and to-only webhook inheritance intact.
