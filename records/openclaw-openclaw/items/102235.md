## Summary

Keep open: current main and the latest release still have the resolver/dispatcher path that can route a job-level channel-shaped failure destination into the inherited global webhook mode, and two open PRs now explicitly target this issue.

## What This Changes

The issue requests that a cron job-level channel-shaped failure destination without an explicit mode resolve as announce/channel delivery instead of inheriting a global webhook failureDestination mode.

## Best Possible Solution

Review and land one narrow linked PR, preferably one that covers both the resolver and gateway dispatch path, then close this issue as implemented.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: current main overlays job channel/to fields without entering the job-mode reconciliation branch, then the dispatcher treats the resulting `#alerts` target as an invalid webhook URL. I did not run a live gateway/channel send in this read-only review.

## Solution Assessment

Yes, the best fix is a narrow resolver change with regression coverage that preserves to-only webhook overrides while treating channel-shaped no-mode overrides as announce. The linked PRs are the right place to finish that fix rather than opening another repair job.
