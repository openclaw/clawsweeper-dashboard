## Summary

Keep open: current main and v2026.6.11 still have the resolver path that lets a job-level channel-shaped failureDestination inherit a global webhook mode, and the strongest fix path is still an open linked PR at https://github.com/openclaw/openclaw/pull/102445.

## What This Changes

A cron job's channel-shaped failureDestination without mode should resolve as announce instead of inheriting a global webhook mode and dropping the failure alert.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/102445 or an equivalent resolver-level fix, then let this issue close through the merged closing reference.

## Reproduction Assessment

Yes. Source inspection reproduces the path: current main overlays a job channel/to failureDestination over a global webhook default without resetting mode, then the dispatcher treats the chat target as an invalid webhook URL.

## Solution Assessment

Yes. The best fix belongs in resolveFailureDestination because that is where the wrong mode is produced before the gateway dispatcher chooses announce versus webhook.
