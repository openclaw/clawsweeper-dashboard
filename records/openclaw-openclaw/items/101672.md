## Summary

Keep open: current main and the latest release still miss the literal `openai` owner case, so a stale auto fallback persisted as `providerOverride: "openai"` can remain invisible to `doctor --fix --deep`. The report is source-reproducible, but the permanent owner boundary for canonical OpenAI route-state cleanup needs maintainer direction before repair.

## What This Changes

Fix `doctor --fix --deep` so it detects and clears stale auto session route state persisted with `providerOverride: "openai"` when the configured agent route no longer uses OpenAI/Codex.

## Best Possible Solution

Add maintainer-approved doctor ownership for canonical OpenAI auto fallback route state, with regression coverage for literal `providerOverride: "openai"` outside a non-OpenAI configured route and explicit/user OpenAI pins preserved.
