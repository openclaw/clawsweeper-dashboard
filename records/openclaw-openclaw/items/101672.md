Fix `doctor --fix --deep` so auto-sourced session route drift with `providerOverride: "openai"` is detected and repaired when the configured agent route is no longer OpenAI/Codex.

## Best Possible Solution

Add focused doctor coverage for literal `openai` auto session route state at the chosen owner boundary, with tests that clear stale auto pins for non-OpenAI configured routes while preserving explicit user OpenAI selections and existing legacy `openai-codex` migrations.
