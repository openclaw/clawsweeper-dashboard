## Summary

Keep open: current `main` and the latest release still miss the literal `openai` ownership case, so the reported doctor no-op remains plausible from source. The bug is actionable, but the exact owner boundary for canonical OpenAI route-state cleanup needs maintainer direction before an automated repair changes provider ownership.

## What This Changes

The issue requests that `doctor --fix --deep` clear stale auto session routing overrides when the persisted fallback provider is the canonical literal `openai`.

## Best Possible Solution

Add focused doctor ownership for canonical OpenAI auto fallback route state at the correct plugin boundary, with regression coverage for `providerOverride: "openai"` plus `modelOverrideSource: "auto"` when the configured route is non-OpenAI, while preserving explicit/user OpenAI pins.
