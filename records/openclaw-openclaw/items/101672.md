## Summary

Keep open: current `main` and the latest release still omit literal `openai` from the doctor session-route owner metadata, while the repair logic only clears auto model overrides for provider ids claimed by an owner. The issue is source-reproducible, but the permanent owner boundary needs maintainer direction before changing provider/session repair ownership.

## What This Changes

The issue reports that doctor session-route repair misses stale OpenAI runtime/model overrides because no session-route owner claims the literal `openai` provider id.

## Best Possible Solution

Add focused doctor ownership for canonical OpenAI auto-fallback route state at the right boundary, with regression coverage for `providerOverride: "openai"` plus `modelOverrideSource: "auto"` when the configured route is non-OpenAI, while preserving explicit user OpenAI selections.
