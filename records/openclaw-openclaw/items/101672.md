## Summary

Keep open: current main still lacks a doctor owner for literal `openai` auto session-route state, and no merged replacement covers this exact repair gap. The source path supports the reported doctor no-op, but the OpenAI-vs-Codex ownership boundary needs maintainer direction before automation changes provider ownership.

## What This Changes

Ensure `doctor --fix --deep` detects and clears stale auto-sourced session route pins that persist `providerOverride: "openai"` outside the configured model/runtime route.

## Best Possible Solution

Choose the canonical owner for literal `openai` auto route-state repair, then add focused doctor coverage for `providerOverride: "openai"` plus `modelOverrideSource: "auto"` when the configured route is non-OpenAI, preserving explicit/user OpenAI selections.
