## Summary

Keep open: current `main` and the latest release still omit the literal `openai` provider id from the session route-state ownership metadata, while the doctor scanner only clears auto overrides for providers claimed by an owner. The earlier ClawSweeper keep-open verdict still holds; the remaining choice is the correct ownership boundary for canonical OpenAI route-state repair.

## What This Changes

The issue reports that `doctor --fix --deep` cannot clear persisted auto `providerOverride: "openai"` session routing drift because no doctor session-route owner claims the literal `openai` provider id.

## Best Possible Solution

Add maintainer-approved doctor ownership for canonical OpenAI auto fallback route state, with regression coverage for `providerOverride: "openai"` on a non-OpenAI configured agent while preserving explicit user OpenAI selections.
