## Label Justifications

- `P1`: A real user reported production agents silently staying pinned to the wrong provider/model while the standard doctor repair could not clear the stale route state.
- `impact:session-state`: The failure is persisted session route metadata drifting away from the configured agent model/runtime and surviving repair.

## Summary

Keep open: current main and the latest release still omit literal `openai` from the Codex doctor route-state owner list, while the repair scanner only clears auto overrides whose provider is claimed by an owner. The bug is source-reproducible, but the permanent owner boundary needs maintainer direction before changing provider ownership.

## What This Changes

The issue reports that `openclaw doctor --fix --deep` does not clear stale auto session route overrides persisted as `providerOverride: "openai"`, leaving sessions pinned to the wrong OpenAI Codex runtime/model.

## Best Possible Solution

Choose the canonical owner for literal `openai` session route state, then add a focused doctor regression that stale auto `openai/gpt-*` overrides are cleared for non-OpenAI configured agents without adding a local config override surface.
