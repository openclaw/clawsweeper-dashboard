## Summary

## What This Changes

The PR changes Android manual gateway URL resolution so blank TLS ports default to 18789 for non-`.ts.net` hosts while preserving 443 for Tailscale hosts, and updates Connect tab hints and resolver tests.

## Best Possible Solution

Sync native i18n inventory, fix the complete-URL hint mismatch, and land the iOS-aligned default only after maintainer acceptance of the 443-to-18789 blank-port default and real Android proof are added.

## Reproduction Assessment

Yes, source-reproducible: current main resolves a blank TLS manual port to 443 for a bare non-tailnet host, while the iOS parity test expects 18789 for that case. I did not run Android locally because this review is read-only.

## Solution Assessment

Mostly: centralizing the blank-port decision in `GatewayConfigResolver` is the right owner boundary because Connect, Settings, and onboarding all call the resolver. The PR still needs i18n sync and hint alignment for complete URL inputs before it is the best mergeable fix.
