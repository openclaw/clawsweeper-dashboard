## Summary

Keep open; the merge gate is a good QQBot-local fix for the reported bubble fragmentation and the PR has strong live proof, but the new fallback retries original chunks after any merged-send error, which can duplicate delivery when the first POST may already have reached QQ.

## What This Changes

The PR adds a QQBot outbound merge step that collapses safe-size markdown chunks into one send and retries the original chunks if the merged send fails.

## Best Possible Solution

Merge safe-size QQBot chunks before dispatch, but retry original chunks only for deterministic QQ validation rejections that prove the merged message was not delivered.

## Reproduction Assessment

Yes from source and reporter logs: current main chunks QQBot markdown and sends every chunk as its own QQ API message, though I did not run a live before-state QQ session myself.

## Solution Assessment

Not yet; the merge-at-send-boundary shape is appropriate, but the fallback retry must be constrained before this is the best fix.
