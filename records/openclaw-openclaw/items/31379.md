## Label Justifications

- `P2`: This is a normal-priority Control UI discovery issue with limited blast radius and no evidence of broken message delivery.
- `impact:ux-friction`: Users can lose visible setup and discovery cards for built-in channels after enabling only a custom channel plugin, forcing workaround knowledge without fully blocking progress.
- `maturity:stable`: The issue touches the Gateway-hosted Control UI and channel status surface, and Gateway runtime is scored M4 Stable in the maturity scorecard.

## Summary

Keep open: current main and v2026.6.11 still treat a non-empty `channelMeta` or `channelOrder` snapshot as the complete Channels card list, so a custom-only channel snapshot can still hide built-in discovery cards. The open fork PR with closing syntax is the active implementation candidate, so this issue should stay open until maintainers land, adopt, or close that candidate.

## What This Changes

The issue requests that the Control UI Channels settings page keep built-in channel cards visible alongside custom channel plugins.

## Best Possible Solution

Land or replace the linked UI resolver fix so snapshot-provided custom channels stay first, missing built-in channel cards are appended once, and regression coverage proves custom-only and mixed-order snapshots without changing backend status semantics.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: a snapshot whose `channelMeta` or `channelOrder` contains only a custom id such as `icenter` causes `renderChannels()` to render only that id.

## Solution Assessment

Yes. The narrow maintainable fix is to merge the UI resolver's snapshot ids with the built-in channel order, preserving backend loaded-plugin semantics while keeping built-in discovery cards visible.
