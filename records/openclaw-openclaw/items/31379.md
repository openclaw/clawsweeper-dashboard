## Summary

Keep open: current main still lets a custom-only channel snapshot become the entire Channels settings card list, while a linked open fork PR contains the focused resolver/test candidate but needs maintainer adoption or replacement before it can land upstream.

## What This Changes

The issue requests that the Control UI Channels settings page always render built-in channel cards alongside custom channel plugins.

## Best Possible Solution

Land or replace the linked UI resolver fix so snapshot-provided custom channels stay first, missing built-in discovery cards are appended once, and regression coverage proves custom-only and mixed-order snapshots without changing backend status semantics.
