## Label Justifications

- `P2`: This is a normal-priority Control UI discovery bug with limited blast radius and no evidence of broken message delivery.
- `impact:ux-friction`: Users can lose visible setup/discovery cards for built-in channels after enabling only a custom channel plugin, forcing workaround knowledge without fully blocking progress.

## Summary

Keep open: current main and the latest release still let a custom-only `channelMeta` or `channelOrder` become the complete Channels card list, so built-in channel cards can still disappear. An open fork PR already carries the candidate fix, so maintainers should review, adopt, or replace that path before starting another repair job.

## What This Changes

The issue asks the Channels settings page to keep built-in channel cards visible when backend snapshot order/meta contains only custom channel plugins.

## Best Possible Solution

Land or replace the linked UI resolver fix so snapshot-provided custom channels stay first, missing built-in discovery cards are appended once, and regression coverage proves custom-only and mixed-order snapshots without changing backend status semantics.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Source inspection shows `renderChannels()` renders exactly the IDs returned by `resolveChannelOrder()`, and that resolver treats a custom-only `channelMeta` or `channelOrder` snapshot as complete.

## Solution Assessment

Yes. The narrow maintainable fix is to merge the UI resolver's snapshot IDs with the built-in channel order, preserving backend loaded-plugin semantics while keeping built-in discovery cards visible.
