## Label Justifications

- `P2`: This is a normal-priority Control UI discovery bug with limited blast radius and no evidence of broken message delivery or setup-wide blocking.
- `impact:other`: Users can lose visibility of built-in channel setup cards after enabling only a custom channel plugin.
- `maturity:stable`: The issue affects Control UI under Gateway runtime Hosted Web Surface, which is part of the M4 Stable Gateway runtime scorecard.

## Summary

Keep open: current main and v2026.6.11 still treat a custom-only `channelMeta` or `channelOrder` snapshot as the complete Channels card list, so built-in cards can still disappear. The open linked fork PR is the active implementation candidate, so maintainers should review, adopt, or replace that patch rather than start a new repair job.

## What This Changes

The issue requests that the Control UI Channels settings page merge built-in channel cards with custom channel plugins instead of rendering only the backend snapshot-provided channel list.

## Best Possible Solution

Land, adopt, or replace the linked UI resolver fix so snapshot-provided custom channels stay first, missing built-in discovery cards are appended once, and focused regression coverage proves custom-only and mixed-order snapshots without changing backend status semantics.

## Reproduction Assessment

Yes. Source-level reproduction is high-confidence: a custom-only `channelMeta` or `channelOrder` snapshot returns only that id, and `renderChannels()` maps that exact list to visible cards.

## Solution Assessment

Yes. The narrow frontend resolver merge is the best maintainable shape because it preserves backend loaded-plugin status semantics while appending missing built-in discovery cards with de-duplication.
