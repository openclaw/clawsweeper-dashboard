## Label Justifications

- `P2`: This is a normal-priority Control UI channel discovery bug with limited blast radius and no evidence of message delivery or runtime breakage.
- `impact:ux-friction`: Users who enable only a custom channel plugin can lose the in-product built-in channel setup cards and need avoidable guessing or support to rediscover them.
- `maturity:stable`: The issue affects Control UI under the Gateway runtime Hosted Web Surface, which is scored M4 Stable in the maturity scorecard.

## Summary

Keep open: current main and the latest release still let a custom-only `channelMeta` or `channelOrder` snapshot become the complete Channels card list, so built-in discovery cards can disappear. The open linked fork PR is an implementation candidate with closing syntax, so the issue should remain open until maintainers land, adopt, replace, or close that candidate.

## What This Changes

The issue requests fixing the Channels settings page so custom channel plugin snapshots do not suppress built-in channel discovery cards.

## Best Possible Solution

Land or replace a UI resolver fix that appends missing built-in channel IDs to snapshot-provided custom IDs with de-duplication, focused regression tests, and real Control UI proof while leaving backend status/plugin loading semantics unchanged.

## Reproduction Assessment

Yes, source-level: a snapshot whose `channelMeta` or `channelOrder` contains only a custom channel is returned as the complete render list by `resolveChannelOrder()`, and `renderChannels()` maps only that list to cards. I did not run a live browser reproduction in this read-only review.

## Solution Assessment

Yes, the narrow UI resolver merge is the best maintainable fix: preserve backend loaded-plugin status semantics, keep custom snapshot channels first, and append missing built-in discovery cards once.
