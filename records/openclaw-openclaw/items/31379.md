## Label Justifications

- `P2`: This is a normal-priority Control UI discovery problem with limited blast radius and no evidence of broken message delivery or setup data loss.
- `impact:ux-friction`: Users can lose visibility of built-in channel setup cards after enabling only a custom channel plugin, creating avoidable discovery and support friction.
- `maturity:stable`: The affected Control UI surface maps to Gateway runtime Hosted Web Surface, and Gateway runtime is scored M4 Stable in the maturity scorecard.

## Summary

Keep open: current main and v2026.6.11 still treat a custom-only `channelMeta` or `channelOrder` snapshot as the complete Channels card list, so built-in cards can still disappear. An open fork PR with closing syntax remains the active implementation candidate, so this issue should stay open until maintainers land, adopt, or replace that fix.

## What This Changes

Show built-in channel cards on the Control UI Channels settings page even when the gateway snapshot only reports custom channel plugins.

## Best Possible Solution

Land or replace the linked UI resolver fix so snapshot-provided custom channels stay first, missing built-in discovery cards are appended once, and focused regression coverage proves custom-only and mixed-order snapshots without changing backend status semantics.

## Reproduction Assessment

Yes, source-level: `renderChannels()` maps exactly the `resolveChannelOrder()` output to channel cards, and the resolver returns a custom-only `channelMeta` or `channelOrder` list as complete. I did not run a live browser reproduction in this read-only review.

## Solution Assessment

Yes, the narrow frontend resolver merge is the best maintainable shape: preserve backend loaded-plugin status semantics, keep custom channels first, and append missing built-in discovery cards with de-duplication.
