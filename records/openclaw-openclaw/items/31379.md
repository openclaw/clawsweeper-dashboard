## Summary

Keep open: current main and the latest release still use the snapshot channel list as the complete Channels page render list, so the reported built-in-card disappearance remains source-reproducible. A still-open cross-repository PR references this issue as its fix candidate, so this issue should remain the canonical tracker until that PR is reviewed and landed or closed/replaced.

## What This Changes

The issue requests that the Control UI Channels settings page show bundled built-in channel cards even when a custom channel plugin is the only loaded channel.

## Best Possible Solution

Keep this issue as the canonical tracker and land a narrow UI resolver fix that appends missing built-in channel ids after snapshot-provided custom ids, with focused unit coverage and real Control UI proof.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes by source inspection: a custom-only non-empty `channelMeta` snapshot causes `resolveChannelOrder()` to return only custom ids, so built-in cards are not rendered. I did not run a live Control UI scenario in this read-only review.

## Solution Assessment

Yes, the best fix shape is a frontend-only deduped merge of snapshot-provided channels plus the built-in fallback list; it preserves backend plugin loading behavior while restoring built-in channel discovery.
