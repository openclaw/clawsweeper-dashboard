## Label Justifications

- `P2`: This is a normal-priority Control UI bug with limited blast radius: channel discovery/configuration is confusing after adding a custom channel, but core runtime is still usable.
- `impact:ux-friction`: The Channels settings page hides built-in channel setup cards in a custom-plugin configuration, adding avoidable setup and discovery friction.

## Summary

Keep open: current main and the latest release still let a custom-only `channelMeta` or `channelOrder` drive the entire Channels page render list, so built-in channel cards can disappear; the same-repo fix PRs are closed unmerged, and the only open linked PR is an external fork candidate rather than an implemented fix.

## What This Changes

The issue asks for the Control UI Channels settings page to show built-in channel cards alongside custom channel plugins even when the gateway snapshot only reports loaded custom channels.

## Best Possible Solution

Land a focused UI resolver fix that appends missing built-in channel IDs after snapshot-provided custom IDs with de-duplication, a regression test, and real Control UI proof while leaving backend plugin loading unchanged.
