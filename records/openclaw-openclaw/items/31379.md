## Label Justifications

- `P2`: This is a normal-priority Control UI discovery bug with limited blast radius and no evidence of broken message delivery or data loss.
- `impact:other`: Users can lose visibility of built-in channel setup cards after enabling only a custom channel plugin.
- `maturity:stable`: The issue affects Gateway runtime Hosted Web Surface / Control UI behavior, which is scored M4 Stable with Stable category scores.

## Summary

Keep open: current main and v2026.6.11 still use the snapshot-provided channel order as the complete Channels card list, so a custom-only `channelMeta` or `channelOrder` can still hide built-in channel cards. The issue is already paired with an open fork implementation candidate that uses closing syntax, so maintainers should adopt, land, or replace that candidate rather than start another repair lane.

## What This Changes

The issue requests that the Control UI Channels settings page render built-in channel cards alongside loaded custom channel plugins.

## Best Possible Solution

Land or replace the linked UI resolver fix so snapshot-provided custom channels stay first, missing built-in discovery cards are appended once, and focused regression coverage proves custom-only and mixed-order snapshots without changing backend status semantics.

## Reproduction Assessment

Yes, source-level: `renderChannels()` maps exactly the `resolveChannelOrder()` output to rendered cards, and the resolver returns a custom-only `channelMeta` or `channelOrder` list as complete. I did not run a live browser reproduction in this read-only review.

## Solution Assessment

Yes, the narrow frontend resolver merge is the best maintainable shape: preserve backend loaded-plugin status semantics, keep custom channels first, and append missing built-in discovery cards with de-duplication.
