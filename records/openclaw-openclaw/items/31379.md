## Label Justifications

- `P2`: This is a normal-priority Control UI discovery bug with limited blast radius and no evidence of broken message delivery.
- `impact:ux-friction`: Users can lose visible setup/discovery cards for built-in channels after enabling only a custom channel plugin, creating avoidable confusion and workaround knowledge.

## Summary

Keep open: current main and the latest release still treat snapshot `channelMeta` or `channelOrder` as the complete Channels card list, so a custom-only channel snapshot can still hide built-in channel discovery cards. The remaining work is already paired with an open fork PR, so maintainers should review, adopt, or replace that candidate rather than start another fix lane.

## What This Changes

Request that the Control UI Channels page show built-in channel cards alongside custom channel plugin cards instead of rendering only the snapshot-provided order.

## Best Possible Solution

Land or replace the linked UI resolver fix so snapshot-provided custom channels stay first, missing built-in discovery cards are appended once, and regression coverage proves custom-only and mixed-order snapshots without changing backend status semantics.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Source inspection shows `renderChannels()` renders exactly the IDs returned by `resolveChannelOrder()`, and that resolver treats a custom-only `channelMeta` or `channelOrder` snapshot as complete.

## Solution Assessment

Yes. The narrow maintainable solution is to merge the UI resolver's snapshot IDs with the built-in channel order while keeping backend loaded-plugin semantics unchanged.
