- `impact:ux-friction`: Users can lose visible setup/discovery cards for built-in channels after enabling only a custom channel plugin, forcing workaround knowledge without fully blocking progress.

## Summary

Keep open: current main and v2026.6.11 still let a custom-only `channelMeta` or `channelOrder` snapshot become the complete Channels card list, so built-in channel cards can still disappear. A linked open fork PR already carries closing syntax for this issue, so the clean maintainer path is to review, adopt, or replace that candidate rather than start another repair lane.

## What This Changes

The issue asks for the Control UI Channels settings page to keep showing built-in channel cards when a custom channel plugin is the only loaded channel.

## Best Possible Solution

Land or replace the linked UI resolver fix so snapshot-provided custom channels stay first, missing built-in discovery cards are appended once, and regression coverage proves custom-only and mixed-order snapshots without changing backend status semantics.

## Reproduction Assessment

Yes, source-level. Current main renders exactly the IDs returned by `resolveChannelOrder()`, and that resolver treats a custom-only `channelMeta` or `channelOrder` snapshot as complete.

## Solution Assessment

Yes. The narrow maintainable fix is to merge the UI resolver's snapshot IDs with the built-in channel order, preserving backend loaded-plugin semantics while keeping built-in discovery cards visible.
