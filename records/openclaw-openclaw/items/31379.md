- `P2`: This is a normal-priority Control UI discovery bug with limited blast radius and no evidence of broken runtime or message delivery.
- `impact:ux-friction`: Users can lose visible setup and discovery cards for built-in channels after enabling only a custom channel plugin, forcing workaround knowledge without fully blocking progress.

## Summary

Keep open: current main and the latest release still treat a custom-only `channelMeta` or `channelOrder` as the complete Channels card list, so built-in discovery cards can disappear. The open cross-repository PR at https://github.com/BingqingLyu/openclaw/pull/544 has closing syntax for this issue, so maintainers should review, adopt, or replace that path instead of starting a duplicate repair job.

## What This Changes

The issue requests that the Control UI Channels settings page render built-in channel cards alongside custom channel plugin cards even when the backend snapshot only lists loaded custom channels.

## Best Possible Solution

Land or replace a UI-only resolver fix that appends missing built-in discovery cards after snapshot-provided custom channels, de-duplicates IDs, adds regression coverage for custom-only and mixed-order snapshots, and leaves backend `channels.status` semantics unchanged.
