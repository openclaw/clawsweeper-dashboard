## Summary

Keep open. Current main and the latest release still leave direct inbound Feishu `interactive` message events on the raw-content fallback path, while the merged related parser work explicitly covered fetched/quoted cards and did not close this broader inbound/card-action payload problem.

## What This Changes

The issue asks OpenClaw to parse inbound Feishu interactive card content, including card text and interactive component values, instead of exposing only a type marker, placeholder, or raw payload.

## Best Possible Solution

Keep this as the broad Feishu interactive-card parsing tracker, reuse the existing Feishu card parser for direct inbound `interactive` messages, and resolve callback-field plus merge_forward payload details through the narrower linked items after maintainers choose a stable contract.
