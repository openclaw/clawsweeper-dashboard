## Summary

Keep open. Current main and the latest release still leave direct inbound Feishu `message_type: "interactive"` events on the raw-content path, while related fixes only cover fetched/quoted card parsing or narrower callback and merge_forward work.

## What This Changes

Requested Feishu plugin support to parse inbound Interactive Card content, including card text, buttons, options, and form values, instead of surfacing only a type marker or placeholder.

## Best Possible Solution

Keep this as the broad Feishu interactive-card parsing tracker, centralize reusable card parsing in the Feishu plugin, and resolve callback-field and merge_forward subsets through their narrower linked items or merged replacements.

## Reproduction Assessment

Yes, source-level: direct inbound Feishu `message_type: "interactive"` events call `parseMessageContent`, which has no interactive branch and returns raw content. I did not run a live Feishu tenant reproduction in this read-only review.

## Solution Assessment

Unclear as a single implementation: reusing the existing Feishu interactive-card parser for direct inbound messages is likely right, but the broader callback/form/select payload contract needs maintainer product judgment and should coordinate with the narrower open issues.
