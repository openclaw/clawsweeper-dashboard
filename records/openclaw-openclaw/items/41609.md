## Summary

Keep open. Current `main` and `v2026.6.11` still leave direct inbound Feishu `interactive` messages on the raw-content path, while https://github.com/openclaw/openclaw/pull/72397 only covers fetched/quoted cards and the remaining callback-field and merge-forward subsets are tracked separately.

## What This Changes

Requested support for parsing and exposing Feishu Interactive Card text, button/options, and form content from inbound message events.

## Best Possible Solution

Define a Feishu plugin-owned agent-visible card payload contract, reuse the existing card parser for direct inbound `interactive` messages, and keep callback-field plus merge_forward details aligned with the narrower linked items.
