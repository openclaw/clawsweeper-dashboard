## Summary

Keep open. Current main and v2026.6.11 still leave direct inbound Feishu `interactive` messages outside the reusable card parser, while merged related work covers fetched/quoted card reads and open siblings cover narrower callback-field and merge_forward gaps.

## What This Changes

The issue requests Feishu interactive-card message parsing so agents can see card text, button/select labels and values, and form input data instead of placeholders or raw payloads.

## Best Possible Solution

Keep this as the broad Feishu interactive-card tracker, define the plugin-owned card/action payload contract, wire direct inbound cards to the existing parser, and coordinate callback-field and merge_forward details through their narrower linked issues.
