## Summary

Keep open. Current main and v2026.6.11 still leave direct inbound Feishu interactive-card events on the raw-content path, while related merged/open work only covers quoted/fetched cards, card-action fields, or merge_forward subsets.

## What This Changes

The issue requests parsing inbound Feishu Interactive Card content, including card text, button/options data, and form values, instead of exposing only a placeholder or type identifier.

## Best Possible Solution

Keep this as the broad Feishu interactive-card tracker, reuse the existing card parser for direct inbound interactive events, and review or replace the narrower callback and merge_forward PRs after maintainers choose a stable agent-visible payload contract.
