## Summary

Keep open. Current main and the latest release still leave direct inbound Feishu interactive-card events on the raw-content path, while merged fixes only cover fetched/quoted reads and outbound card sending; the open items at https://github.com/openclaw/openclaw/issues/43202, https://github.com/openclaw/openclaw/issues/77909, and https://github.com/openclaw/openclaw/pull/94995 cover narrower slices rather than replacing this canonical tracker.

## What This Changes

The issue requests Feishu interactive-card message and callback parsing so agents can see card text, button/dropdown selections, and form input values.

## Best Possible Solution

Define the Feishu card ingestion contract, then land a staged Feishu plugin fix that reuses the existing card parser for direct inbound interactive messages while keeping card-action fields and merge_forward behavior on their narrower tracked paths.
