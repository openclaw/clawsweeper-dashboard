## Summary

Keep this open: current main and the latest release still expose only `memorySearch.local.contextSize` for local llama.cpp embeddings, not the requested `maxThreads` CPU-thread tuning path. The implementation shape is narrow, but it adds a public config knob, so it needs maintainer product/API approval before ClawSweeper queues a fix PR.

## What This Changes

The issue requests a new `memorySearch.local.maxThreads` config option that would be forwarded to `node-llama-cpp` when initializing local embeddings.

## Best Possible Solution

If approved, add optional `memorySearch.local.maxThreads` with no default behavior change, validate and document it, carry it through memory config/provider option types, and pass it only to `getLlama` for the official local llama.cpp provider.
