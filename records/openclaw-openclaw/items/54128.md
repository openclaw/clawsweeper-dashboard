## Summary

Keep this open: current main and the latest release still do not expose or forward `memorySearch.local.maxThreads`; the adjacent `contextSize` work is useful precedent but does not solve CPU thread tuning. The remaining decision is whether OpenClaw should add this new public local-embedding config knob.

## What This Changes

The issue requests a new `memorySearch.local.maxThreads` option for local node-llama-cpp embeddings so users can tune or limit CPU thread usage during memory indexing.

## Best Possible Solution

If approved, add `memorySearch.local.maxThreads` as an advanced optional llama.cpp provider setting with no default behavior change, schema/help/docs coverage, config-resolution forwarding, node-llama facade support, and focused passthrough tests.

- **Decline the config expansion:** Keep node-llama-cpp thread selection implicit and direct users needing thread control to external embedding providers or custom plugin ownership.
- **Defer for broader local tuning design:** Hold this until maintainers decide whether CPU, GPU, NUMA, and related llama.cpp runtime controls should be exposed together.
