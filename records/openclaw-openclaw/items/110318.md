## Summary

Keep open: current main already relays provider tool calls back to the owning Gateway Talk client and accepts results, but it has no documented client-scoped declaration mechanism for additional relay tools. The request is a real new protocol/product capability, not a bug fix or duplicate of the related catalog request. ([github.com](https://github.com/openclaw/openclaw/blob/main/docs/gateway/protocol.md))

## What This Changes

The issue requests a client-declared realtime-tool mechanism for Gateway-relay Talk sessions so device-local actions can be offered to the selected provider and completed through the existing relay result path.

## Best Possible Solution

Add a typed, client-scoped declaration to the gateway-relay session-create contract—rather than a global config list—only if maintainers approve its trust and ownership model; validate names and object schemas, preserve the two built-ins, and document the additive protocol behavior.
