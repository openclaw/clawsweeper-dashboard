## Label Justifications

- `P1`: The defect causes normal streamed Gateway requests from OpenAI-compatible clients to fail during active use while equivalent non-streaming requests succeed.

## Summary

This PR addresses a concrete Gateway streaming regression with a narrow lifecycle fix: it keeps the existing root-work admission alive for the detached run, then releases it from that run’s existing cleanup path. The submitted before/after terminal evidence is credible and the patch introduces no apparent security or API-surface concern; it remains open for normal maintainer review while CI completes.

## What This Changes

The PR retains Gateway root-work admission for detached streamed OpenAI-compatible chat and responses runs, releasing that continuation when each run finishes.

## System Context

OpenClaw’s Gateway exposes OpenAI-compatible streaming HTTP endpoints that start an agent run and emit server-sent events to the client. Gateway work admission tracks active roots during draining; the detached streaming run needs its own retained root admission so later session or lane work remains valid until that run completes.

## Architecture Diagram

flowchart LR
  Client[Streaming OpenAI-compatible client] --> Endpoint[Gateway HTTP streaming endpoint]
  Endpoint --> Admission[Root-work admission]
  Endpoint --> DetachedRun[Detached agent run]
  Admission --> HandlerReturn[HTTP handler returns]
  DetachedRun --> Continuation[Retained admission continuation]
  Continuation --> SubordinateWork[Session and lane admissions]
  SubordinateWork --> Stream[Completed streamed response]
  DetachedRun --> Release[Release continuation on run completion]

## Best Possible Solution

Keep the retain-and-release continuation pattern in both streaming endpoints, with a focused lifecycle regression test when practical that lets the handler return before the agent run requests subordinate admission.
