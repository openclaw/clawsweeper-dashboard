Request a provider-level `models.providers.<id>.enabled` flag so users can temporarily disable model providers while preserving their config and status visibility.

## Best Possible Solution

Approve one shared provider eligibility contract that defaults omitted values to enabled, preserves disabled config blocks, and consistently gates schema, models.json planning, fallback, catalog/listing, status/probe output, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: the current strict provider config type/schema does not include `enabled`, and planning, fallback, catalog/status paths consume configured providers without a disabled-provider eligibility gate. I did not run a live config because this review is read-only.

## Solution Assessment

Unclear pending maintainer product direction. A provider-level flag is plausible, but the best implementation should be one shared eligibility contract rather than scattered per-consumer filters.
