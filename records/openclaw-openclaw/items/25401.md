Keep open: current main and the latest release still lack a provider-level disable contract, and the two direct implementation PRs are closed unmerged. The remaining work is useful, but it needs maintainer direction for the new public config surface and disabled-primary/fallback semantics.

## What This Changes

The issue requests a provider-level `models.providers.<id>.enabled` boolean so configured model providers can be temporarily disabled without deleting their config.

## Best Possible Solution

Approve one shared provider eligibility contract that defaults omitted values to enabled and applies consistently across schema, models.json planning, fallback, catalog/listing, status/probe output, docs, and tests.

## Reproduction Assessment

Yes, at source level: current main omits `enabled` from the strict provider type/schema and consumes configured providers in planning, fallback, catalog, and status paths without an eligibility gate. I did not run a live config because this review is read-only.

## Solution Assessment

Unclear pending maintainer product direction. A provider-level flag is plausible, but the best implementation should be a shared provider eligibility contract rather than scattered per-consumer filters.
