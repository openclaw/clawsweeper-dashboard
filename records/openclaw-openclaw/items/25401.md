## Summary

Keep open: current main and the latest release still lack a supported provider-level disable contract; only an isolated SecretRef collector checks `enabled !== false`, while schema, model planning, fallback, catalog, docs, and status output do not. Both implementation attempts are closed unmerged, so the remaining blocker is maintainer product direction for a new public config/provider-routing option.

## What This Changes

Request adds a provider-level `models.providers.<id>.enabled` boolean so configured providers can be disabled without deleting their config.

## Best Possible Solution

A maintainer-approved provider eligibility contract should default omitted values to enabled and consistently gate schema, models.json planning, fallback, catalog/listing, status/probe output, docs, and focused tests.
