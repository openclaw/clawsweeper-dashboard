## Summary

Keep this issue open: current main and the latest release still do not provide a provider-level `models.providers.<id>.enabled` contract, and the two linked implementation attempts are both closed unmerged.

## What This Changes

The issue requests an optional provider-level `models.providers.<id>.enabled` flag that preserves provider config while excluding disabled providers from model generation, fallback resolution, configured catalogs, and status output.

## Best Possible Solution

Add one documented provider-level disable contract, defaulting to enabled, that preserves config while consistently excluding disabled providers from generated models config, fallback/candidate selection, configured catalog views, and status/probe output.
