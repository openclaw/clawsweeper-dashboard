## Summary

Keep open: current main and v2026.6.11 still lack the requested provider-level disable contract, and both known implementation attempts are closed unmerged. The remaining work is a product/config decision because it adds public config surface and changes provider fallback semantics.

## What This Changes

The issue requests a provider-level `models.providers.<id>.enabled` flag that preserves config while excluding disabled providers from model resolution, fallback lists, catalogs, and status output.

## Best Possible Solution

Approve one shared provider eligibility contract that defaults omitted values to enabled and consistently gates schema, models.json planning, fallback, catalog/listing, status/probe output, docs, and focused tests.

Yes, at source level: the current strict provider config type/schema does not include `enabled`, and planning, fallback, catalog, and status paths consume configured providers without a disabled-provider eligibility gate. I did not run a live config because this review is read-only.

## Solution Assessment

Unclear pending maintainer product direction. A provider-level flag is plausible, but the maintainable solution should be one shared provider eligibility contract rather than scattered per-consumer filters.
