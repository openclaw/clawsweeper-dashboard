## Summary

Keep open. Current main and the latest release still do not expose a provider-level `models.providers.<id>.enabled` contract, both known implementation attempts are closed unmerged, and the remaining work needs a maintainer decision on the public config and fallback semantics.

## What This Changes

Request adding an optional `models.providers.<id>.enabled` boolean that preserves provider config while excluding disabled providers from model generation, fallback, catalog, and status paths.

## Best Possible Solution

Approve one shared provider eligibility contract that defaults omitted values to enabled, preserves disabled config blocks, and consistently gates schema, planning, runtime selection, fallback, catalog/listing, status/probe output, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: current main's strict provider config type/schema does not include `enabled`, and planning, fallback, catalog, and status paths consume configured providers without a disabled-provider eligibility gate. I did not run a live config because this review is read-only.

## Solution Assessment

Unclear pending maintainer product direction. A provider-level flag is plausible, but the best implementation should be a shared provider eligibility contract rather than scattered per-consumer filters.
