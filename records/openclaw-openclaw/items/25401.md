Keep open: current main and v2026.6.11 still do not provide the requested provider-level disable contract, and adding it is a config/provider-routing product decision rather than conservative cleanup.

## What This Changes

The issue requests a `models.providers.<id>.enabled?: boolean` config flag that preserves provider config while excluding disabled providers from model generation, fallback routing, catalogs, and status output.

## Best Possible Solution

Approve one shared provider eligibility contract that defaults omitted values to enabled and consistently gates schema, models.json planning, fallback, catalog/listing, status/probe output, docs, and focused tests.
