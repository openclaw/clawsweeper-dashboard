## Summary

Keep open: current main and the latest release still lack a provider-level disable contract, and the two implementation PRs that referenced this issue are closed unmerged. The remaining work is a public config and provider-routing product decision, not conservative cleanup.

## What This Changes

The issue requests an optional `models.providers.<id>.enabled` flag that preserves provider config while excluding disabled providers from model generation, fallback, catalogs, and status output.

## Best Possible Solution

Approve one shared provider eligibility contract that defaults omitted values to enabled and consistently gates schema, models.json planning, fallback, configured catalogs, status/probe output, docs, and focused tests.
