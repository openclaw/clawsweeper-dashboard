## Summary

Keep open: current main and v2026.6.11 still do not define or honor a provider-level `models.providers.<id>.enabled` contract, and both known implementation attempts are closed unmerged. The remaining work is a feature/config-surface decision, not an already-implemented cleanup item.

## What This Changes

Add a provider-level `models.providers.<id>.enabled` flag so a configured model provider can be disabled without deleting its config block.

## Best Possible Solution

Define one documented provider eligibility contract that defaults omitted values to enabled, preserves disabled config blocks, and consistently gates schema, models.json planning, fallback, catalog/listing, status/probe output, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: the current strict provider config type/schema does not include `enabled`, and planning, fallback, catalog, and status paths consume configured providers without a disabled-provider eligibility gate. I did not run a live config because this review is read-only.

## Solution Assessment

Unclear pending maintainer product direction. A provider-level flag is plausible, but the maintainable fix should be a shared provider eligibility contract rather than scattered per-consumer filters.
