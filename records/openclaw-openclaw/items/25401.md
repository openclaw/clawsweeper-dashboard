## What This Changes

The issue requests a provider-level `models.providers.<id>.enabled` flag so a provider can be disabled while preserving its saved config.

## Best Possible Solution

Approve one shared provider eligibility contract that defaults omitted values to enabled, preserves disabled config blocks, and consistently gates schema, planning, fallback, catalog/listing, status/probe output, docs, and tests.

## Reproduction Assessment

Yes, at source level: the current strict provider type/schema omits `enabled`, and planning, fallback, catalog, and status paths consume configured providers without a disabled-provider eligibility gate. I did not run a live config because this review is read-only.

## Solution Assessment

Unclear pending maintainer product direction. A provider-level flag is plausible, but the best implementation should be a shared provider eligibility contract rather than scattered per-consumer filters.
