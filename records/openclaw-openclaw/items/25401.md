## Summary

Keep open. Current main and v2026.6.11 still do not define or honor a provider-level `models.providers.<id>.enabled` contract, and the known implementation PRs for this exact feature are both closed unmerged.

## What This Changes

The issue requests a provider-level `models.providers.<id>.enabled` config flag to temporarily disable a model provider without deleting its config block.

## Best Possible Solution

Approve one shared provider eligibility contract that defaults omitted values to enabled, preserves disabled config blocks, and consistently gates schema, planning, runtime resolution, fallback, catalog/listing, status/probe output, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: current main's strict provider type/schema does not include `enabled`, and planning, fallback, catalog, and status paths consume configured providers without a disabled-provider eligibility gate. I did not run a live config because this review is read-only.

## Solution Assessment

Unclear pending maintainer product direction. A provider-level flag is plausible, but the maintainable fix should be a shared eligibility contract rather than scattered per-consumer filters.
