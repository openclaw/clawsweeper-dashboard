## Summary

Keep open: current main and latest release still do not define a provider-level `models.providers.<id>.enabled` contract, and the two known implementation PRs were closed unmerged. The remaining work is a real provider-management feature, but it needs maintainer approval for the new public config surface and disabled-primary/fallback semantics.

## What This Changes

Request a `models.providers.<id>.enabled?: boolean` config flag that preserves provider config while excluding disabled providers from model generation, fallback, catalog, and status paths.

## Best Possible Solution

Approve one shared provider eligibility contract that defaults omitted values to enabled, preserves disabled config blocks, and consistently gates schema, planning, fallback, catalog/listing, status/probe output, docs, and tests.

## Reproduction Assessment

Yes, at source level: current main lacks the provider-level type/schema field and the routing, fallback, catalog, and status paths consume configured providers without a disabled-provider gate. I did not run a live config because this review is read-only.

## Solution Assessment

Unclear pending maintainer product direction. A provider-level flag is plausible, but the best implementation should be a shared eligibility contract rather than scattered per-consumer filters.
