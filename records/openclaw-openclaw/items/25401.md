## Summary

Keep open. Current main still lacks a generic provider-level disabled contract, and the remaining work is a product/config decision because it would add public config surface and define fallback behavior.

## What This Changes

The issue requests `models.providers.<id>.enabled` so a configured model provider can be temporarily disabled without deleting its config block.

## Best Possible Solution

Approve one shared provider eligibility contract that defaults omitted values to enabled, preserves disabled config blocks, and consistently gates schema, planning, runtime resolution, fallback, catalog/listing, status/probe output, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: current main's provider config type/schema omit `enabled`, and planning, fallback, configured catalog, and status paths consume configured providers without a disabled-provider eligibility gate. I did not run a live config because this review is read-only.

## Solution Assessment

Unclear pending maintainer product direction. A provider-level flag is plausible, but the maintainable fix should be one shared eligibility helper/contract rather than scattered consumer-specific filters.
