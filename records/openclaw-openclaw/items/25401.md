## Summary

Keep open: current main and the latest release still do not provide a provider-level disable contract, and the remaining blocker is maintainer product direction for a new config/provider-routing surface.

## What This Changes

Request a `models.providers.<id>.enabled` flag that preserves provider config while excluding disabled providers from model generation, fallback selection, catalog/status output, and related provider routing.

## Best Possible Solution

Define one shared provider eligibility contract that defaults omitted values to enabled and consistently gates schema, models.json planning, fallback, configured catalogs, status/probe output, docs, and focused tests.
