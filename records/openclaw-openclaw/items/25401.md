## Summary

Keep open: current main and v2026.6.11 still lack the requested provider-level disable contract, both known implementation PRs are closed unmerged, and adding this config/provider-routing surface needs maintainer product direction rather than conservative cleanup.

## What This Changes

The issue requests an optional provider-level `models.providers.<id>.enabled` config flag to temporarily disable a configured model provider while preserving its config.

## Best Possible Solution

Define one documented provider eligibility contract that defaults omitted values to enabled and gates schema, models.json planning, fallback, configured catalogs, auth/probe visibility, status output, docs, and tests consistently.
