## Summary

Keep open: current main and v2026.6.11 still do not define a provider-level `models.providers.<id>.enabled` contract, the two known implementation attempts are closed unmerged, and the remaining work needs a maintainer decision for the public config surface and disabled-primary/fallback semantics.

## What This Changes

The issue requests an optional `models.providers.<id>.enabled` flag that preserves provider config while excluding disabled providers from model resolution, fallback, and status output.

## Best Possible Solution

Approve one shared provider eligibility contract that defaults omitted values to enabled, preserves disabled config blocks, and consistently gates schema, models.json planning, fallback, catalog/listing, status/probe output, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: the current strict provider config type/schema does not include `enabled`, and planning, fallback, catalog, and status paths consume configured providers without a disabled-provider eligibility gate. I did not run a live config because this review is read-only.

## Solution Assessment

Unclear pending maintainer product direction. A provider-level flag is plausible, but the best implementation should be a shared provider eligibility contract rather than scattered per-consumer filters.
