## Summary

Keep this PR open for normal maintainer review: it is the active, proof-backed candidate for the large SQLite session-store stall reported in https://github.com/openclaw/openclaw/issues/112240. The final head addresses the two previously raised cache-isolation concerns, but its new freshness contract still warrants owner review before merge.

## What This Changes

This PR caches parsed SQLite session listings, adds lightweight paginated results for gateway callers, and invalidates cached data after session-store mutations to avoid repeated whole-store parsing on large installations.

## System Context

Gateway and session-management callers enumerate persisted session metadata from each agent’s SQLite database. The new cache sits on that listing path, deciding whether to reuse parsed entries or reload rows before the gateway and session APIs consume them.
