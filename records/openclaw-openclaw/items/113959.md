## Summary

Keep this PR open, but it is not ready to merge. A late review found that the warm full-list path intentionally returns mutable cache-owned session entries, contradicting the cache module’s default clone-on-read contract; any caller mutation can contaminate later listings until invalidation. The branch also still needs inspectable after-fix real gateway proof and a rebase because GitHub reports a conflicted merge state.

## What This Changes

The PR adds cache-coherent SQLite session-entry listing, mutation invalidation, lightweight projections, pagination, and regression tests to reduce gateway stalls with large session stores.

## System Context

OpenClaw stores each agent’s session metadata in SQLite. Gateway and session APIs read that data for listings and mutate it during lifecycle updates, so the session-store cache sits between persisted state and gateway/UI consumers.

## Architecture Diagram

## Best Possible Solution

Preserve cache isolation on every public mutable list result—either clone at the API boundary or redesign the cached value as an immutable/read-only snapshot—then add a regression test that mutates a returned full-list entry and proves the next cached list remains unchanged; rebase and provide redacted real-gateway proof before merge.
