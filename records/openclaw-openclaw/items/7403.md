## Summary

Keep open: current main still lacks the requested enforceable Private/Secret/Incognito session contract, and the remaining work is security- and product-sensitive rather than stale cleanup.

## What This Changes

Add a Private Mode for demos and shared use that suppresses workspace context, avoids durable memory/history writes, and exposes UI/session controls.

## Best Possible Solution

Keep this as the canonical tracker and design one additive private/ephemeral session contract across Gateway protocol, SessionEntry/session store/transcripts, bootstrap/memory/compaction/plugins, channel triggers, and Control UI, with tests proving private sessions neither read private context nor write durable history.

Options:

- **Design a cross-layer private session contract (recommended):** Add an explicit private/ephemeral session marker and require every durable context, memory, transcript, plugin, channel, diagnostics, and UI path to honor it before exposing the mode.
- **Limit scope to context suppression:** Expose a narrower demo-only mode that disables bootstrap/context injection but does not promise no persistence, with UI copy that avoids a privacy guarantee.
- **Defer until session storage redesign:** Keep the issue open but block implementation until the broader session/transcript persistence architecture can support an enforceable no-write mode cleanly.
