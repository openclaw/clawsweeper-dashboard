## Summary

Keep open: current main and the latest release still lack an enforceable Private/Secret/Incognito session contract. The existing context-injection and memory-search controls do not provide the requested per-session no-read/no-write/no-history guarantee, so this should remain the canonical tracker for maintainer design.

## What This Changes

The issue requests a Mission Control Private Mode that suppresses workspace context, avoids durable session and memory persistence, and uses temporary scratch state for demos or private sessions.

## Best Possible Solution

Keep this as the canonical tracker and design one additive private/ephemeral session contract across Gateway protocol, SessionEntry/session store/transcripts, bootstrap/memory/compaction/plugins, channel triggers, and Control UI, with regression tests proving private sessions neither read private context nor write durable history.

## Reproduction Assessment

Yes at source level: current session protocol, config, and store paths have no private/no-persist field, and session creation still initializes durable metadata plus transcript state; no live private-mode session can be run because no such flag exists.

## Solution Assessment

Yes for triage: keeping this issue open is the best current outcome because prompt-only, config-only, or UI-only changes would falsely promise privacy without a cross-layer enforcement contract. The implementation itself still needs maintainer-approved security and product design.
