## Summary

Keep open: current main still lacks an enforceable Private/Secret/Incognito session contract, and the existing context-injection control only suppresses bootstrap context rather than durable transcript, session-store, memory, channel, artifact, log, or UI persistence.

## What This Changes

Issue #7403 requests a Private Mode toggle that suppresses workspace context, avoids durable session and memory traces, uses temporary scratch state, and shows the mode in Mission Control.

## Best Possible Solution

Define one additive core private-session contract and enforce it through Gateway protocol, session storage, transcript creation, memory/compaction indexing, plugin/channel artifacts, and Control UI before presenting it as a privacy feature.

Owner confidence: medium

Options:

- **Design shared private-session contract (recommended):** Add one additive private-session mode with explicit no-context/no-persist semantics that every storage, memory, plugin, channel, and UI path must honor.

- **Defer with documented mitigations:** Keep the issue open and document current partial controls such as contextInjection:"never" without claiming private sessions.

## Solution Assessment

Yes for triage: keeping this open for design is the best path because contextInjection:"never" is too narrow to guarantee private session storage, memory, plugins, artifacts, or channel behavior.
