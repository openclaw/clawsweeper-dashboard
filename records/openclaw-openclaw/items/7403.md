## Summary

Current main still lacks an enforceable private-session boundary, and the discussion plus closed duplicates confirm this issue remains the canonical tracker; it needs an explicit maintainer product and security decision before implementation.

## What This Changes

Add a per-session private or ephemeral mode that suppresses workspace context and prevents durable conversation, memory, and workspace writes, with Control UI activation and indication.

## Best Possible Solution

Define one additive private-session contract with explicit loss-on-restart and residual-metadata semantics, then enforce it across session stores/transcripts, bootstrap and memory, tools and artifacts, plugins/channels, and Control UI with end-to-end negative persistence tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: What guarantee should OpenClaw advertise and enforce for private sessions: transcript-only non-persistence, or a comprehensive no-private-workspace-read and no-durable-content-write boundary across core and plugins?

Rationale: Source inspection proves the capability is missing, but only maintainers can define the threat model, allowed operational metadata, provider/network behavior, channel activation policy, and whether plugins must fail closed when they cannot honor the mode.

Likely owner: steipete

Owner reason: The prior canonical review and recent session/memory lifecycle work make this the strongest available owner for the cross-cutting product and security decision.

Owner confidence: high

Options:

- **Comprehensive private session (recommended):** Create a per-session contract that blocks private workspace and memory reads plus durable content writes, allowing only narrowly documented operational metadata.
- **Transcript-only ephemeral session:** Keep transcripts in memory but explicitly exclude workspace access, tools, plugins, logs, media, and provider traffic from the guarantee.
- **Decline an incognito guarantee:** Retain context-injection, retention, and deletion controls and document that OpenClaw does not provide an enforceable private-session boundary.

## Reproduction Assessment

Yes at source level: current main has no private or ephemeral session contract, and normal session creation enters durable session-store and transcript paths. This reproduces a missing capability rather than a failing existing behavior.

## Solution Assessment

No, a Control UI toggle by itself is not the best solution; it must be a presentation of one core-enforced session policy with clearly defined coverage and failure semantics.
