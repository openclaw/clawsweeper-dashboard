## Summary

Keep open: current main and the latest release still lack an enforceable Private/Secret/Incognito session contract; existing context-injection, retention, and policy controls are partial mitigations, not the requested no-read/no-write/no-history guarantee.

## What This Changes

Add a Mission Control Private Mode that suppresses workspace and memory context, uses temporary session memory, avoids touching workspace/session files, and resumes normal context when disabled.

## Best Possible Solution

Keep this as the canonical tracker and design one additive private/ephemeral session contract across Gateway protocol, SessionEntry/session store/transcripts, bootstrap/memory/compaction/plugins, channel triggers, and Control UI, with tests proving no private-context reads or durable history writes.

## Reproduction Assessment

Yes, at source level: current session schemas and creation paths have no private/no-persist field and still create durable session entries plus JSONL transcript state. I did not run a live private-mode session because current main has no private/session-persist flag to exercise.

## Solution Assessment

Yes for triage: keeping this issue open is the best current outcome because prompt-only, config-only, or UI-only changes would falsely promise privacy without a cross-layer enforcement contract. The implementation still needs maintainer-approved security and product design.
