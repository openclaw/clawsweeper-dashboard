## Summary

Keep open: current main and the latest release still lack an enforceable Private/Secret/Incognito session contract; the existing context-injection controls reduce prompt context but do not stop durable session metadata, JSONL transcripts, memory/compaction persistence, plugin state, or UI/channel exposure.

## What This Changes

Request a Mission Control Private Mode that suppresses workspace/memory context, avoids durable session history, uses temporary scratch memory, and exposes session privacy state in the UI.

## Best Possible Solution

Keep this as the canonical tracker and design one additive private/ephemeral session contract across Gateway protocol, SessionEntry/session store/transcripts, bootstrap/memory/compaction/plugins, channel triggers, and Control UI, with tests proving no private-context reads or durable history writes.

## Reproduction Assessment

Yes, at source level: current session schemas and creation paths have no private/no-persist field and still create durable session entries plus JSONL transcript headers. I did not run a live private-mode session because current main has no private/session-persist flag to exercise.

## Solution Assessment

Yes for triage: keeping this open is the best current outcome because prompt-only, config-only, or UI-only changes would falsely promise privacy without a cross-layer enforcement contract. The implementation itself still needs maintainer-approved security and product design.
