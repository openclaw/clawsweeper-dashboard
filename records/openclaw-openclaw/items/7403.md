## Summary

Keep open: current main still lacks an enforceable Private/Secret/Incognito session contract; existing context-injection controls only suppress bootstrap/context files and do not prevent durable session metadata, transcript creation, memory indexing, or UI/channel exposure.

## What This Changes

Add a Mission Control Private Mode that suppresses workspace context, prevents durable session/history/memory persistence, uses temporary scratch memory, and shows an active private-state indicator.

## Best Possible Solution

Define one additive core private-session contract and enforce it through Gateway protocol, session storage, transcript creation, memory/compaction indexing, plugin/channel artifacts, and Control UI before presenting it as a privacy feature.

Owner confidence: high

Options:

- **Design a shared private-session contract (recommended):** Add a single additive private-session mode with explicit no-context/no-persist semantics that every storage, memory, plugin, channel, and UI path must honor.
- **Narrow to context suppression only:** Ship a smaller, clearly named context-suppression mode if maintainers do not want to promise no durable history or memory writes yet.
- **Defer with documented mitigations:** Keep the issue open and document current partial controls such as contextInjection:"never" without claiming private sessions.

## Reproduction Assessment

Yes at source level: current session protocol, config, SessionEntry, and transcript creation paths have no private/no-persist field, while memory indexing still consumes session transcripts. A live private-mode run is not possible because current main exposes no such mode to exercise.

## Solution Assessment

Yes for triage: keeping this issue open for maintainer design is the best path because contextInjection:"never" is too narrow to guarantee private session storage, memory, or channel behavior. The implementation should wait for a single enforceable privacy contract rather than land partial toggles.
