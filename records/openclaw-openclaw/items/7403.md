## Summary

Current main and v2026.6.11 still lack an enforceable per-session private/no-persist contract, and closed duplicates confirm this remains the canonical product and security tracker.

## What This Changes

Add a private session mode that omits personal workspace context, prevents durable history or memory writes, and exposes a Control UI toggle and indicator.

## Best Possible Solution

Define an additive, session-scoped private contract enforced at every core and plugin persistence boundary, then expose only accurately named UI and channel controls with regression proof that sensitive context is neither loaded nor durably written.

Options:

- **Full ephemeral contract (recommended):** Make private state session-scoped, authorized, and enforced across workspace context, transcripts, memory, tools, plugins, diagnostics, exports, and channel integrations.
- **Context-only demo mode:** Offer a clearly weaker demo mode that suppresses bootstrap context without claiming no persistence or history.
- **Decline the guarantee:** Retain current agent-wide context controls and avoid presenting a misleading private-session mode.

## Reproduction Assessment

Yes at source level: sessions.create has no privacy parameter, and its canonical creation helper unconditionally initializes a SQLite transcript and persists session metadata; v2026.6.11 has the same missing capability.

## Solution Assessment

No, a Mission Control toggle or reuse of agent-wide contextInjection alone is not the best fix because it would leave transcript, memory, plugin, tool, and other persistence paths outside the claimed guarantee.
