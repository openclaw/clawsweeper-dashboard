## Summary

Keep open: current main and the latest release still lack an enforceable Private/Secret/Incognito session contract. The existing contextInjection setting can suppress bootstrap context, but it does not provide the requested program-level no-read/no-write/no-history guarantee across session metadata, transcripts, memory, tools, channels, and Control UI.

## What This Changes

Request to add a Private Mode for demos/content creation that suppresses workspace and memory context and prevents durable session persistence while active.

## Best Possible Solution

Keep this as the canonical Private/Secret/Incognito mode tracker and design an additive core session privacy contract across Gateway protocol, SessionEntry, transcript/session storage, bootstrap and memory flows, tool/media persistence, channel triggers, and Control UI indicators, with regression proof for no private-context reads and no durable private-history writes.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? For this feature request, runtime reproduction is not the right frame; the absence is source-reproducible because current main lacks private/ephemeral/no-persist fields while sessions still create durable transcript and store entries.

## Solution Assessment

Is this the best way to solve the issue? The goal is sound, but a simple Mission Control toggle alone is not the best fix; the maintainable solution is an enforceable session contract that every persistence and context path consumes.
