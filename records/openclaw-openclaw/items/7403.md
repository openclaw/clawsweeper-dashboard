## Label Justifications

- `P2`: This is a normal-priority privacy/session-state feature request with important security implications but no current regression or blocked setup path.
- `impact:security`: The request is about preventing personal context, transcripts, memory files, and other sensitive session data from being exposed or persisted.
- `impact:session-state`: The requested behavior changes session creation, transcript durability, memory/scratchpad state, and cross-session history semantics.

## Summary

Keep open. Current main and the latest release still lack an enforceable Private/Secret/Incognito session mode: the protocol, session config, persisted session row, transcript creation, memory-flush paths, and Control UI row model have no shared private/no-persist contract.

## What This Changes

Request a Mission Control Private Mode that suppresses workspace/persona/memory context, prevents durable session history and memory writes, and shows a visible private-session indicator.

## Best Possible Solution

Keep this as the canonical tracker and design one additive private/ephemeral session contract that spans Gateway protocol, `SessionEntry`, transcript/store writes, memory and compaction gates, plugin/session context, channel triggers, and Control UI indication.
