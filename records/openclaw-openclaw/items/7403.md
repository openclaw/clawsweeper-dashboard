## Summary

Keep open: current main still lacks an enforceable Private/Secret/Incognito session contract; existing context-injection controls can reduce prompt context, but they do not provide the requested no-read, no-write, no-history privacy guarantee.

## What This Changes

The issue requests a Mission Control Private Mode that suppresses workspace context and prevents persistent session or memory writes for demo and content-creation sessions.

## Best Possible Solution

Keep this as the canonical tracker and design one additive private/ephemeral session contract across Gateway protocol, SessionEntry/session store/transcripts, bootstrap/memory/compaction/plugins, channel triggers, and Mission Control UI.

Owner confidence: medium

Options:

- **Design core private session contract (recommended):** Define an additive private/ephemeral session marker that every persistence, memory, plugin, channel, and UI path must enforce before exposing a user-facing toggle.
- **Narrow to context-only demo mode:** Ship a smaller demo-mode toggle that suppresses bootstrap context but explicitly does not promise no history, no memory, or no disk persistence.
- **Reject core mode for now:** Close or defer the feature until maintainers decide a core privacy boundary is worth the compatibility, UX, and testing cost.

Yes, at source level: current main has no private/no-persist session field, while session creation still initializes durable session metadata and a JSONL transcript header. I did not run a live private-mode session because current main has no private/session-persist flag to exercise.
