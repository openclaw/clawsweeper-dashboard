## Summary

Keep open: current main still lacks an enforceable Private/Secret/Incognito session contract; existing context-injection and pruning controls do not stop durable session metadata, JSONL transcript creation, memory flushes, plugin state, or UI/channel exposure.

## What This Changes

Request adds a Private Mode toggle/contract for demo and content-creation sessions that suppresses workspace context and prevents private session state from being read from or written to durable storage.

## Best Possible Solution

Keep this as the canonical tracker and design one additive private/ephemeral session contract across Gateway protocol, SessionEntry/session store/transcripts, bootstrap/memory/compaction/plugins, channel triggers, and Control UI, with regression tests proving private sessions neither read private context nor write durable history.

- **Defer or reject the feature:** Close the feature direction and document existing mitigations such as contextInjection, pruning, and manual cleanup as non-private-mode alternatives.
