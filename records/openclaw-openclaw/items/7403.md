## Summary

Keep open: current main still lacks an enforceable Private/Secret/Incognito session contract; existing context-injection controls only suppress bootstrap prompt input and do not prevent durable session, transcript, memory, plugin, channel, or UI persistence.

## What This Changes

The issue requests a user-visible Private Mode for demos and shared use that suppresses workspace context and prevents private-session reads, writes, and durable history.

## Best Possible Solution

Define one additive core private-session contract and enforce it through Gateway protocol, session storage, transcript creation, memory/compaction indexing, plugin/channel artifacts, and Control UI before presenting it as a privacy feature.

## Maintainer Decision

Question: What exact Private Mode contract should OpenClaw guarantee across context reads, transcript/session storage, memory/compaction, plugin artifacts, channel history, logs, and Control UI?

Rationale: The request creates a user-visible privacy/security boundary across multiple owners, and current main has no single session mode or field that downstream paths can enforce safely.

Likely owner: steipete

Owner reason: steipete already handled the canonical review and has the strongest combined product/security and session-surface routing signal in the live issue and git history.

Owner confidence: high

Options:

- **Design shared private-session contract (recommended):** Add one additive private-session mode with explicit no-context and no-persist semantics that storage, memory, plugin, channel, and UI paths must honor.
- **Narrow to context suppression only:** Ship a clearly named context-suppression mode if maintainers do not want to promise no durable history, memory, or plugin artifact writes yet.
- **Defer with documented mitigations:** Keep the issue open and document current partial controls such as contextInjection:"never" without claiming private sessions.

## Reproduction Assessment

Yes at source level: current main has no private/no-persist field in session protocol, config, SessionEntry, Control UI session creation, or transcript creation paths; a live private-mode run is not possible because no such mode exists.

## Solution Assessment

Yes for triage: keeping this open for design is the best path because contextInjection:"never" is too narrow to guarantee private session storage, memory, or channel behavior.
