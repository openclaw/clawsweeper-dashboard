## Summary

Keep open: current main still lacks an enforceable Private/Secret/Incognito session contract; existing context-injection controls can reduce bootstrap prompt context, but they do not stop durable session metadata, JSONL transcripts, memory/compaction persistence, plugin state, or UI/channel exposure.

## What This Changes

The issue requests a Mission Control Private Mode that suppresses workspace context and prevents private-session memory/history persistence.

## Best Possible Solution

Keep this as the canonical tracker and design one additive private/ephemeral session contract across Gateway protocol, SessionEntry/session store/transcripts, bootstrap/memory/compaction/plugins, channel triggers, and Control UI, with tests proving private sessions neither read private context nor write durable history.

## Reproduction Assessment

Yes, at source level: current main has no private/no-persist session field, and session creation still initializes durable session metadata plus a JSONL transcript header. I did not run a live private-mode session because current main has no private/session-persist flag to exercise.

## Solution Assessment

Yes for triage: keeping this issue open is the best current outcome because prompt-only, config-only, or UI-only changes would falsely promise privacy without a cross-layer enforcement contract. The implementation itself still needs maintainer-approved security and product design.
