## Summary

Keep open: current main and v2026.6.11 still lack an enforceable per-session private/no-persist contract, and the closed duplicates plus unmerged partial PR confirm this remains the canonical product and security tracker.

## What This Changes

Add a per-session private mode that suppresses workspace context and prevents durable transcript, memory, and session-state persistence.

## Best Possible Solution

Carry one closed private-session policy through protocol, SessionEntry, transcript/history, compaction, bootstrap and memory, plugins, tools/media, channel routing, and Control UI, reusing the existing transcript non-persist seam rather than creating a parallel session stack.

Question: What exact no-read/no-write/no-persist threat model and activation scope should OpenClaw guarantee for private sessions?

Rationale: The requested security promise crosses workspace reads, transcript and metadata persistence, memory, compaction, plugins, tools, media, channels, and UI; current code cannot determine whether the intended product is demo-only context suppression, transcript-only ephemerality, or a comprehensive private session.

Likely owner: steipete

Owner reason: Current session protocol and lifecycle ownership plus the prior canonical review route this cross-cutting product and security decision most strongly here.

Owner confidence: high

Options:

- **Full private session (recommended):** Guarantee no private workspace or memory reads and no durable transcript, metadata, compaction, plugin-index, tool, or media writes for an explicitly private session.
- **Demo-only context mode:** Suppress bootstrap context for presentation use while clearly making no no-persistence guarantee.
- **Transcript-only ephemeral mode:** Disable JSONL transcript writes while explicitly allowing other session state and artifacts to persist.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 expose normal context and persistence paths but no complete per-session private-mode contract. This is a clearly observable feature gap rather than a failing established behavior.

## Solution Assessment

Yes in direction, but not yet in contract detail: the narrowest maintainable solution is one end-to-end session policy using existing owner seams. A context-only toggle or transcript-only flag would not meet the program-level guarantee established by the discussion.
