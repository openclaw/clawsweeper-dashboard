## Summary

Keep open: current main and v2026.6.11 still lack an enforceable Private/Secret/Incognito session contract; the existing context-injection control is only a partial context suppression tool, not a no-read/no-write/no-history guarantee.

## What This Changes

The issue requests a Mission Control Private Mode that suppresses workspace context, avoids persistent session/memory writes, and shows private-session state in the UI.

## Best Possible Solution

Define one additive core private-session contract and enforce it through Gateway protocol, session storage, transcript creation, memory/compaction indexing, plugin/channel artifacts, diagnostics/logging, and Control UI before presenting it as a privacy feature.

- **Narrow To Context Suppression:** Ship only a clearly named context-suppression mode if maintainers do not want to promise no durable history, memory writes, or artifact retention yet.

## Reproduction Assessment

Yes, at source level: current session protocol, config, SessionEntry, transcript creation, memory indexing, and UI row surfaces have no private/no-persist field. A live private-mode run is not possible because current main exposes no such mode to exercise.

## Solution Assessment

Yes for triage: keeping this issue open for maintainer design is the best path because contextInjection:"never" is too narrow to guarantee private session storage, memory, channel, artifact, or diagnostic behavior. The implementation should wait for a single enforceable privacy contract rather than land partial toggles.
