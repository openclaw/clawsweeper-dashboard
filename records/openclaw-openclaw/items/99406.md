## Summary

Keep open: current main still builds completion choices and dispatch paths from `command.name()` only, while the CLI registers Commander aliases that users can type. The related help-description work at https://github.com/openclaw/openclaw/pull/98999 overlaps the discovery surface but does not make shell completion alias-aware.

## What This Changes

The issue requests alias-aware shell completion for zsh, bash, fish, and PowerShell so accepted CLI aliases complete and continue nested completion.

## Best Possible Solution

Make completion generation consume each command's primary name plus `aliases()` through shared helpers, preserving nested completion after alias path segments and adding regression tests for all four shells.

## Reproduction Assessment

Yes, at source level: current completion generation enumerates `name()` only while the same command tree registers aliases that Commander accepts. I did not run the CLI or source shell scripts in this read-only review.

## Solution Assessment

Yes. A generic helper that expands command names to primary name plus aliases, and uses alias-aware path variants for fish/PowerShell and dispatch cases for zsh/bash, is the narrow maintainable fix.
