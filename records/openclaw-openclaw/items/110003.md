## Summary

The timeout approach and supplied live socket proof are useful, but the branch imports the guard from a non-public plugin-SDK subpath. That can let a source-checkout test pass while the packaged Telegram plugin cannot resolve the import, so this needs an SDK-owner decision and repair before merge.

## What This Changes

The PR replaces manual Mini App auth JSON-body reading with a bounded request-body guard and adds a raw TCP regression test for incomplete requests receiving a 408 and closed socket.

## Best Possible Solution

Keep the bounded 408-before-close behavior, but implement it through an established public ingress API: either deliberately expose and test a stable guard entrypoint, or move the ordering fix into the existing public bounded JSON-body reader and consume that API from Telegram.
