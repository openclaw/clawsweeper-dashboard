## Summary

Keep open: current main and v2026.6.11 still map Slack `message_changed` and `message_deleted` into session-scoped system events, and the requested `ignoreSubtypes` config field is still absent; this remains a valid Slack config/policy decision rather than a cleanup close.

## What This Changes

The issue requests a Slack `channels.slack.ignoreSubtypes` config key that can drop selected Slack edit/delete subtype events before they wake an agent session.

## Best Possible Solution

A maintainer-approved Slack edit/delete event policy; if accepted, add a narrow documented opt-in Slack plugin config field that defaults to current behavior and drops only approved subtypes before system-event context is queued.
