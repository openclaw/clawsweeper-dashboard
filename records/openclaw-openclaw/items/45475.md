## Summary

Keep open: current main and the latest release still route Slack `message_changed` and `message_deleted` through the system-event path, and the requested `ignoreSubtypes` config surface does not exist. The remaining work is real but needs maintainer product direction because it adds public Slack config and chooses edit/delete event policy.

## What This Changes

Request to add a Slack `ignoreSubtypes` config key so selected Slack subtypes such as `message_changed` and `message_deleted` are dropped before waking an agent session.

## Best Possible Solution

Approve a narrow Slack-owned opt-in subtype filter, then implement it in the event layer before authorization/enqueue with schema, type, docs, and regression coverage while preserving current defaults unless maintainers choose a default policy change.
