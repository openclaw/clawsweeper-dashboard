## Summary

Keep open: current main and the latest release still intentionally convert Slack `message_changed` and `message_deleted` events into session-scoped system events, and the requested opt-in `ignoreSubtypes` Slack config key does not exist. The remaining blocker is maintainer product direction for a new public Slack config surface, not source uncertainty.

## What This Changes

The issue requests an opt-in Slack config key that drops selected Slack message subtypes, especially `message_changed` and `message_deleted`, before they enqueue system events or wake sessions.

## Best Possible Solution

Maintainers should decide the Slack edit/delete event policy; if approved, implement an opt-in Slack plugin config key in schema/types/UI/docs and short-circuit configured edit/delete subtypes before system-event enqueue with focused tests.

## Reproduction Assessment

Yes, at source level: current main resolves `message_changed` and `message_deleted` through the Slack subtype handler and the tests assert that `message_changed` enqueues a system event. I did not run a live Slack workspace reproduction in this read-only review.

## Solution Assessment

Unclear until maintainer direction: an opt-in event-layer drop list is a plausible narrow implementation, but the new public Slack config key and exact subtype policy need product approval first.
