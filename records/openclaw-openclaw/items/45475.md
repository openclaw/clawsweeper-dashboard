## Summary

Keep open: current main and v2026.6.11 still intentionally map Slack `message_changed` and `message_deleted` into session-scoped system events, and there is still no `ignoreSubtypes` Slack config key. The request is valid from source inspection, but it adds public Slack config surface and needs maintainer product direction before implementation.

## What This Changes

Request a per-Slack-channel `ignoreSubtypes` config key that drops selected Slack message subtypes before they wake an agent session.

## Best Possible Solution

Decide the Slack edit/delete event policy explicitly; if accepted, add a narrow Slack plugin config field with schema, docs, and regression tests that short-circuits only approved subtype system events before session wake.

Rationale: The source-level problem is clear, but OpenClaw policy sets a high bar for new config keys and this choice changes public Slack event semantics.

Options:

- **Add opt-in ignoreSubtypes (recommended):** Add a narrow Slack plugin config key for approved subtype suppression while preserving existing default behavior and special Assistant/thread-broadcast paths.
- **Change default policy:** Drop edit/delete events by default, which reduces unwanted wakeups but may remove existing observability for users relying on those system events.
- **Keep current behavior:** Leave edit/delete as system events and document prompt or operational guidance instead of adding config surface.
