## Summary

Keep open: current main and v2026.6.11 still route Slack `message_changed` and `message_deleted` through subtype system-event enqueueing, and there is still no `ignoreSubtypes` Slack config surface. This remains a valid but product-sensitive config feature rather than conservative cleanup-close material.

## What This Changes

Add a Slack channel config key that can drop configured Slack message subtypes before they wake an agent session.

## Best Possible Solution

Decide Slack edit/delete event policy explicitly; if accepted, add a narrow Slack plugin config field with schema, docs, and regression tests around an event-layer short-circuit.

## Reproduction Assessment

Yes. Source inspection shows ordinary Slack edit/delete events resolve a subtype handler and enqueue a session-scoped system event on current main; no live Slack Socket Mode run was performed in this read-only review.

## Solution Assessment

Unclear. The proposed `ignoreSubtypes` key is a plausible narrow opt-in path, but maintainers first need to choose the desired Slack edit/delete policy and public config surface.
