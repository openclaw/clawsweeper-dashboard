Keep open: current main and v2026.6.11 still route Slack message edit/delete subtypes into session-scoped system events, and the requested Slack ignoreSubtypes config surface is absent. This remains a valid Slack feature request, but it needs maintainer product/config policy before implementation.

## Best Possible Solution

A maintainer-approved Slack edit/delete event policy; if accepted, add a narrow opt-in Slack plugin config field with schema, docs, and regression tests that drops only approved subtypes before session context is queued.
