## Summary

Keep open: current main and v2026.6.11 still route Slack `message_changed` and `message_deleted` through the Slack system-event path, and the requested `ignoreSubtypes` config key is not present. The adjacent `thread_broadcast` problem is already fixed, but this remaining edit/delete suppression request needs maintainer product direction for a new Slack config surface.

## What This Changes

The issue requests a public Slack channel `ignoreSubtypes` config key to drop selected Slack message subtypes before they enqueue system events or wake agent sessions.

## Best Possible Solution

Decide the Slack edit/delete event policy explicitly; if accepted, add a narrow Slack plugin config field with schema, docs, and regression tests that short-circuits only the approved subtype system events before session wake.

## Reproduction Assessment

Yes. Source inspection shows ordinary Slack edit/delete events still resolve a subtype handler and enqueue a session-scoped system event on current main; I did not run a live Slack Socket Mode reproduction in this read-only review.

## Solution Assessment

Unclear. The proposed `ignoreSubtypes` key is a plausible narrow opt-in path, but it is not the best fix until maintainers choose the desired Slack edit/delete event policy and public config shape.
