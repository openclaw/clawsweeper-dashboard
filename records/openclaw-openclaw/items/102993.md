## Summary

Keep this PR open: it fixes the central mixed-case canonical input bug, but the patch still folds provider-native mapped payload labels when the mapped value is an uppercase canonical word, which can send the wrong reasoning effort for existing OpenAI-compatible provider configs.

## What This Changes

The PR changes OpenAI reasoning-effort normalization to match canonical effort names case-insensitively while adding tests for canonical casing, disabled values, and one provider-native mapped value.

## Best Possible Solution
