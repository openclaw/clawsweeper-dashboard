## Summary

Keep open: current main and v2026.6.11 still drop `accountId` before `/hooks/agent` reaches cron delivery, while the open linked PR is the exact implementation candidate and has not merged.

## What This Changes

The issue requests preserving `/hooks/agent` `accountId` through hook payload normalization and cron delivery so multi-account channel delivery resolves the correct account.

## Best Possible Solution

Review, update, and land or replace the linked fix PR so `/hooks/agent` reuses canonical cron delivery normalization, preserves `accountId`, and has regression plus redacted real multi-account delivery proof.

## Reproduction Assessment

Yes, at source level: `normalizeAgentPayload()` ignores `payload.accountId` and `dispatchAgentHook()` builds cron delivery without it while the cron path can carry it. I did not run a live WhatsApp multi-account setup in this read-only review.

## Solution Assessment

Yes, the best fix direction is to reuse or match canonical cron delivery normalization so hook-created jobs carry `accountId`; this issue should remain open until the linked PR or a replacement lands.
