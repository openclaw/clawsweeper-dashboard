- `P1`: Accepted hook requests can report success while failing delivery in multi-account channel setups, which is a broken real user workflow.
- `impact:message-loss`: The reported symptom is a `/hooks/agent` success response with no delivered channel message.

## Summary

Keep open: current main and v2026.6.11 still drop `accountId` before `/hooks/agent` creates the cron delivery job, and the open linked fix PR has not landed. Because that PR uses closing syntax for this issue, this issue should stay open until that PR is reviewed, refreshed, landed, or replaced.

## What This Changes

The issue reports that `POST /hooks/agent` loses `accountId` before cron delivery, breaking multi-account channel routing for WhatsApp and similar channels.

## Best Possible Solution

Land or replace the linked fix so `/hooks/agent` preserves `accountId` into canonical cron delivery, covers hook normalization/dispatch tests, and updates hook API docs if `accountId` becomes a supported payload field.

## Reproduction Assessment

Yes. Current main shows a source-level reproduction: `normalizeAgentPayload()` ignores `payload.accountId`, and `dispatchAgentHook()` builds cron delivery without an account selector.

## Solution Assessment

Yes. The best fix direction is to feed hook dispatch through the canonical cron delivery shape or otherwise preserve `accountId` into `CronDelivery`, rather than keeping a separate hand-built path that diverges from cron normalization.
