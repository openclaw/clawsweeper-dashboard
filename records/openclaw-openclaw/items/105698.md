## Summary

Close because the reported callback-order race does not occur on current main under either supported Node runtime tested: the buffered pong clears heartbeat state before the delayed interval runs, and missed interval periods do not accumulate as proposed.

## What This Changes

Change the gateway WebSocket heartbeat to tolerate event-loop stalls by using elapsed pong time instead of a one-missed-pong boolean.

## Best Possible Solution

Keep the current one-missed-pong heartbeat and investigate any real `heartbeat-timeout` incident using close-cause logs, event-loop delay metrics, client identity, and a supported-version minimal reproduction.
