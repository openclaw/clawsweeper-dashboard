## Summary

Supported-runtime probes do not reproduce the reported false timeout: missed interval periods coalesce, and a pong buffered during server event-loop blocking is processed before the overdue heartbeat callback. The proposed failure mechanism is therefore not supported by current Node 22/24 behavior.

## What This Changes

The issue proposes replacing the gateway's one-missed-pong WebSocket heartbeat with an elapsed-time threshold to tolerate event-loop stalls.

## Best Possible Solution

Keep the current one-missed-pong heartbeat; investigate any real `heartbeat-timeout` incident using gateway close-cause logs, event-loop delay metrics, client identity, and a supported-version minimal reproduction.

## Solution Assessment

No. The proposed last-pong threshold would weaken the established half-open connection cleanup contract and relies on interval callbacks accumulating during a stall, which the runtime probes disproved.
