## Summary

Keep open: this is a detailed, source-consistent stable-release regression. Current main detects an unsupported package runtime before mutation and can repair plugin links afterward, but the available code does not establish an atomic handoff that upgrades an already-installed managed Node runtime, rewrites version-pinned shell state, and relinks plugins before gateway restart. citeturn4view1turn11view2

## What This Changes

Make managed updates replace stale embedded-Node references and plugin peer links atomically, or provide an automatic, clearly surfaced recovery path.

## Best Possible Solution

Use a stable managed launcher and an atomic installer-owned handoff that upgrades Node, core, service paths, and plugin peer links before restart, with rollback and an in-product Fix/Repair action if convergence fails.

Options:

- **Atomic installer handoff (recommended):** Have the updater invoke a versioned, verified installer protocol that replaces the managed Node and core roots, repairs service/plugin links, validates readiness, and rolls back as one transaction.
- **Fail before mutation:** Detect an unsupported managed Node before changing core state and present a visible installer repair action that completes the upgrade outside the running updater.
- **Document manual recovery:** Keep updater and installer independent and rely on terminal recovery instructions, accepting continued release-blocking friction for managed users.
