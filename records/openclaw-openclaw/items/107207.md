## Label Justifications

- `P0`: An ordinary stable managed update leaves the CLI and Gateway unusable and requires shell configuration edits plus multiple repair commands to recover.
- `impact:ux-release-blocker`: A managed-install user cannot complete or recover the update through an in-product flow and must understand PATH files, embedded runtimes, doctor, and plugin repair.
- `impact:crash-loop`: The Gateway cannot start while its runtime and plugin peer link target incompatible or stale installation roots.
- `impact:message-loss`: The failed WhatsApp plugin and unavailable Gateway suppress channel messaging until manual recovery completes.

## Summary

Keep open: this is a fresh, actionable stable-release regression in the managed update path, and the available current-main docs and related history do not establish an atomic embedded-Node upgrade or automatic peer-link recovery that prevents the reported outage.

## What This Changes

Make managed macOS updates replace stale embedded-Node references and plugin peer links, or fail safely with an automatic, visible recovery path.

## Best Possible Solution

For local-prefix managed installs, preflight the target release's Node requirement before mutating the package, hand off atomically to the managed installer when the embedded runtime must change, preserve a versionless runtime entrypoint, then relink and smoke-test official plugins and refresh the Gateway service before reporting success; failures should expose an in-product Fix or Doctor action rather than requiring shell edits.
