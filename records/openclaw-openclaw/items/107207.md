## Label Justifications

- `P0`: A stable update leaves the managed CLI and gateway unusable, with recovery requiring shell-profile edits and several internal repair commands.
- `impact:crash-loop`: Gateway startup remains blocked by migration and plugin-link failures until the installation is manually repaired.
- `impact:message-loss`: The WhatsApp plugin cannot load while its OpenClaw peer link targets the obsolete embedded runtime package.
- `impact:ux-release-blocker`: A community user cannot recover through the normal update flow and must understand PATH ordering, edit a shell profile, and run multiple terminal repair commands.

## Summary

Keep open: this is a detailed stable-release update regression, and current main only partially covers it. The updater can target a managed service package root and repair plugins after core update, while the sibling installer now uses a supported Node default, but there is no proven atomic path that upgrades an existing embedded runtime, handles version-pinned shell state, resumes plugin relinking, and restores the gateway without manual intervention.

## What This Changes

Make managed local-prefix updates migrate the embedded Node runtime, active CLI/service references, and plugin peer links together instead of leaving a partially upgraded installation.

## Best Possible Solution

Provide one guided managed-update recovery action that detects an install-cli local prefix, upgrades the installer-owned Node target and stable symlink, rebinds the canonical OpenClaw/service root, repairs plugin peer links, verifies gateway readiness, and rolls back cleanly; detect version-pinned shell PATH entries and offer a visible Doctor/Fix flow rather than requiring profile edits.
