## Summary

Keep this PR open for revision: the unbounded-read hardening is necessary, but the proposed 64 KiB cap is nearly reached by current ripgrep release metadata and could break automatic helper installation; the stronger duplicate branches are currently conflicted, so none safely supersedes this PR yet.

## What This Changes

The PR replaces the tools manager’s unbounded GitHub release JSON read with a 64 KiB bounded read and adds declared-length and streamed-overflow cancellation tests.

## Best Possible Solution

Use the existing bounded response reader with an owner-local cap that has substantial measured headroom for both configured repositories—1 MiB is already implemented and proven in related work—then validate normal and oversized real tool-resolution paths after refreshing the chosen branch onto current main.
