## Summary

This PR remains necessary because current main still clears activated plugin runtime stores before fallible discovery and manifest loading, while the branch adds a narrow rollback using the existing transaction snapshot machinery. The regression case, real entry-point before/after proof, and successful relevant CI support normal maintainer review and landing; no actionable correctness or security defect was found.

## What This Changes

Snapshots activated plugin process-global registrations before reload clearing, restores them when an activating load aborts, centralizes the clear helper with the transaction utilities, and adds regression coverage.

## Best Possible Solution

Land the transaction-scoped rollback after refreshing the branch against current main, preserving the prior active registrations whenever discovery or manifest loading aborts while leaving successful activation semantics unchanged.
