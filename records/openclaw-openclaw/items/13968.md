## Summary

Keep open: current main still reads and caches HEARTBEAT.md before run-kind filtering, and the docs still define normal-run HEARTBEAT.md injection when heartbeat guidance is enabled. The related tiered-bootstrap and lightweight-heartbeat work overlaps, but none fully owns this focused pre-load/cache optimization.

## What This Changes

Request run-kind-aware bootstrap loading so HEARTBEAT.md is skipped before disk reads, cache snapshots, hooks, and prompt injection on non-heartbeat turns.

## Best Possible Solution

Keep this open for a maintainer-approved run-kind-aware loader/cache contract that skips HEARTBEAT.md before load/cache/hook/prompt injection on ordinary non-heartbeat turns while preserving it for actual heartbeat runs.

## Reproduction Assessment

Yes. Source inspection on current main traces loadWorkspaceBootstrapFiles to getOrLoadBootstrapFiles and resolveBootstrapFilesForRun and shows HEARTBEAT.md is still loaded before later run-kind filtering.

## Solution Assessment

Unclear. The loader/cache layer is the right boundary for the requested savings, but the exact isHeartbeat/runKind API and default behavior need maintainer approval because they change the normal-run heartbeat guidance contract.
