## Summary

Keep open: current main still reads and snapshots HEARTBEAT.md before run-kind filtering, and the public docs still describe HEARTBEAT.md as visible in ordinary default-agent runs when heartbeat guidance is enabled. The related tiered-bootstrap work is broader and does not replace this focused on-demand loading request.

## What This Changes

The issue requests run-kind-aware bootstrap loading so HEARTBEAT.md is skipped for non-heartbeat runs instead of being loaded on every message.

## Best Possible Solution

Define one maintainer-approved run-kind-aware bootstrap loader/cache policy that skips HEARTBEAT.md for ordinary non-heartbeat default runs before disk reads, snapshots, hooks, and prompt injection while preserving real heartbeat runs and updating docs/tests.

## Reproduction Assessment

Yes, from source inspection rather than a live run: current main’s workspace loader includes HEARTBEAT.md and the cache snapshots the raw file set before run-kind filters can remove it. The tests also do not define the requested ordinary non-heartbeat default-run skip.

## Solution Assessment

Unclear. The loader/cache layer is the right technical layer for the requested savings, but removing HEARTBEAT.md from ordinary default runs needs a maintainer-approved contract because current docs say that guidance can be present.
