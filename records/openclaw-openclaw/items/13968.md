## Summary

Keep open: current main and the latest release still read and cache HEARTBEAT.md before run-kind filtering, and the related tiered-bootstrap work preserves HEARTBEAT.md in normal main sessions by default. The remaining work is real but needs maintainer product judgment because it changes the normal prompt/context contract.

## What This Changes

The issue requests loading HEARTBEAT.md only for heartbeat runs instead of every normal workspace bootstrap load.

## Best Possible Solution

Define one run-kind-aware bootstrap loading and cache policy that skips HEARTBEAT.md for ordinary non-heartbeat default runs before reads, snapshots, hooks, and prompt injection, while preserving real heartbeat runs and updating docs/tests.

## Reproduction Assessment

Yes, at source level: current main still loads and snapshots the raw bootstrap set before run-kind filtering can remove HEARTBEAT.md. I did not run a writable test harness because this is a read-only review.

## Solution Assessment

No, not as only passing an isHeartbeat flag through the two named functions. The maintainable fix needs one shared run-kind-aware policy across loader, cache, hooks, prompt injection, docs, and focused tests.
