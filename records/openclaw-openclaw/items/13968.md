## Summary

Keep open: current main and the latest release still eagerly load and cache HEARTBEAT.md before run-kind filtering, while docs still allow normal default-agent runs to receive HEARTBEAT.md when heartbeat guidance is enabled. The remaining work is a prompt/context contract decision, not a conservative cleanup close.

## What This Changes

Request on-demand HEARTBEAT.md loading so non-heartbeat turns skip that workspace file and heartbeat runs still receive it.

## Best Possible Solution

Define one run-kind-aware bootstrap loading/cache policy that excludes HEARTBEAT.md from default non-heartbeat runs before disk reads and snapshots only if maintainers accept the prompt-contract change, then align hooks, docs, and focused tests.

## Reproduction Assessment

Yes, at source level. Current main still reads and snapshots HEARTBEAT.md before run-kind filtering, and normal default-agent runs still keep it when heartbeat guidance is enabled.

## Solution Assessment

No, the two-function isHeartbeat proposal is too narrow by itself. The maintainable solution needs one shared run-kind policy before loader/cache snapshots, hook processing, prompt injection, docs, and tests.
