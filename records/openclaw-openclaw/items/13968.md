## Summary

Keep open: current main and the latest release still read and cache HEARTBEAT.md before run-kind filtering, and docs still allow normal default-agent runs to receive HEARTBEAT.md when heartbeat guidance is enabled. The remaining work is a product/prompt-contract decision, not a cleanup close candidate.

## What This Changes

Request to load HEARTBEAT.md only for heartbeat runs so ordinary messages avoid unnecessary workspace-context cost.

## Best Possible Solution

Define one run-kind-aware bootstrap loading/cache policy that excludes HEARTBEAT.md from default non-heartbeat runs before disk reads and cache snapshots, preserves real heartbeat and lightweight behavior, and updates docs plus focused tests.

## Reproduction Assessment

Yes, at source level. Current main still reads and snapshots HEARTBEAT.md before run-kind filtering, and normal default-agent runs still keep it when heartbeat guidance is enabled.

## Solution Assessment

No as written; passing only an isHeartbeat flag through the two named functions is too narrow. The maintainable fix needs a shared run-kind-aware policy across loader, cache, hooks, prompt injection, docs, and tests.
