Keep open: current main and the latest release still read and cache HEARTBEAT.md before run-kind filtering, and the normal-run docs still allow HEARTBEAT.md when heartbeat guidance is enabled. ## What This Changes

The issue requests on-demand HEARTBEAT.md loading so non-heartbeat turns skip heartbeat-only workspace context before raw bootstrap reads, cache snapshots, hooks, and prompt injection.

## Best Possible Solution

Define one run-kind-aware bootstrap loading and cache policy that skips HEARTBEAT.md for ordinary non-heartbeat default runs before reads, snapshots, hooks, and prompt injection, while preserving real heartbeat runs and updating heartbeat docs plus focused tests.

## Reproduction Assessment

Yes. Source inspection on current main shows HEARTBEAT.md is still read through the raw bootstrap loader and session cache before any run-kind filter can remove it.

Unclear. The proposed run-kind-aware loader/cache path is plausible, but removing HEARTBEAT.md from ordinary enabled default-agent runs changes the documented prompt/context contract and needs maintainer product agreement.
