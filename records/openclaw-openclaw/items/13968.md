## Summary

Keep open: current main and v2026.6.11 still read/cache HEARTBEAT.md before run-kind filtering, and the open tiered-bootstrap work does not replace this focused on-demand HEARTBEAT.md request.

## What This Changes

The issue requests loading HEARTBEAT.md only for heartbeat runs instead of reading and injecting it during ordinary non-heartbeat turns.

## Best Possible Solution

Have maintainers confirm the normal-run HEARTBEAT.md contract, then implement a run-kind-aware loader/cache path that skips HEARTBEAT.md before disk reads, session snapshots, hooks, and prompt injection for non-heartbeat default runs while preserving it for heartbeat runs.

## Reproduction Assessment

Yes, at source level: current main clearly reads and snapshots HEARTBEAT.md before run-kind filtering, and docs still permit it in normal enabled default-agent runs. I did not run a live token-measurement reproduction because this was a read-only cleanup review and the source path is explicit.

## Solution Assessment

Unclear as an implementation direction until maintainers decide the behavior contract. The likely best technical shape is the proposed run-kind-aware load/cache boundary, but the current documented normal-run HEARTBEAT.md visibility makes this a product decision before an automated fix PR.
