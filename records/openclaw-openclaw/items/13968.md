## Summary

Keep open: current main still reads and snapshots the fixed workspace bootstrap set, including HEARTBEAT.md, before run-kind filtering, and the documented non-Codex default still allows HEARTBEAT.md in normal runs when heartbeat guidance is enabled.

## What This Changes

The issue requests loading HEARTBEAT.md only for heartbeat runs instead of reading and injecting it for ordinary non-heartbeat messages.

## Best Possible Solution

Define one run-kind-aware bootstrap loading/cache policy that skips HEARTBEAT.md for ordinary non-heartbeat default runs before reads, cache snapshots, hooks, and prompt injection, while preserving real heartbeat runs and updating docs/tests.

## Reproduction Assessment

Yes, at source level. Current main still reads and snapshots HEARTBEAT.md before run-kind filtering, and normal default-agent runs still keep it when heartbeat guidance is enabled.

## Solution Assessment

No, not as only threading an isHeartbeat flag through the two named functions. The maintainable fix needs one shared run-kind-aware policy across loader, cache, hooks, prompt injection, docs, and tests.
