## Summary

Keep open: current main and v2026.6.11 still read and cache HEARTBEAT.md before run-kind filtering, and docs still allow HEARTBEAT.md in ordinary default-agent runs when heartbeat guidance is enabled. The open tiered-bootstrap work at https://github.com/openclaw/openclaw/pull/22439 overlaps but preserves HEARTBEAT.md in the default main-session path, so it does not close this focused request.

## What This Changes

Request run-kind-aware workspace bootstrap loading so HEARTBEAT.md is skipped for ordinary non-heartbeat messages and kept for actual heartbeat runs.

## Best Possible Solution

Define one shared run-kind-aware bootstrap loading/cache policy that skips HEARTBEAT.md for ordinary non-heartbeat default runs before reads, cache snapshots, hooks, and prompt injection, while preserving real heartbeat runs and updating docs/tests.

## Reproduction Assessment

Yes, at source level. Current main still reads and snapshots HEARTBEAT.md before run-kind filtering, and normal default-agent runs still keep it when heartbeat guidance is enabled.

## Solution Assessment

No, not as only passing an isHeartbeat flag through the two named functions. The maintainable fix needs one shared run-kind-aware policy across loader, cache, hooks, prompt injection, docs, and tests.
