## Summary

Keep open: current main and latest release still read and cache HEARTBEAT.md before run-kind filtering, while docs still define normal-run HEARTBEAT.md injection when heartbeat guidance is enabled.

## What This Changes

Request to load HEARTBEAT.md only for heartbeat runs instead of reading and injecting it during ordinary non-heartbeat messages.

## Best Possible Solution

Define one run-kind-aware bootstrap loading/cache policy that skips HEARTBEAT.md for ordinary non-heartbeat runs before disk reads, cache snapshots, hooks, and prompt injection, while preserving heartbeat runs and updating docs/tests.

## Reproduction Assessment

Yes, at source level. Current main still reads and snapshots HEARTBEAT.md before run-kind filtering, and normal default-agent runs still keep it when heartbeat guidance is enabled.

## Solution Assessment

No, not as only passing an isHeartbeat flag through the two named functions. The maintainable fix needs one shared run-kind-aware policy across loader, cache, hooks, prompt injection, docs, and tests.
