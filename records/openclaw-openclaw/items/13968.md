## Summary

Keep open: current main and the latest release still read and snapshot `HEARTBEAT.md` before run-kind filtering, and the broader tiered-bootstrap work does not currently replace this focused default-run skip request.

## What This Changes

Request to load `HEARTBEAT.md` only for heartbeat runs instead of including it in ordinary non-heartbeat bootstrap context.

## Best Possible Solution

Define one run-kind-aware bootstrap loading/cache policy that skips `HEARTBEAT.md` for ordinary non-heartbeat default runs before reads, cache snapshots, hooks, and prompt injection, while preserving real heartbeat runs and updating docs/tests.

## Reproduction Assessment

Yes, at source level. Current main still reads and snapshots `HEARTBEAT.md` before run-kind filtering, and normal default-agent runs still keep it when heartbeat guidance is enabled.

## Solution Assessment

No, not as only passing an `isHeartbeat` flag through two named functions. The maintainable fix needs one shared run-kind-aware policy across loader, cache, hooks, prompt injection, docs, and tests.
