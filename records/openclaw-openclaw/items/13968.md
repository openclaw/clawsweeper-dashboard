## Summary

Keep open: current main and the latest release still load and cache HEARTBEAT.md before run-kind filtering, while docs still allow HEARTBEAT.md in normal default-agent runs when heartbeat guidance is enabled, so the requested on-demand behavior remains missing and product-sensitive.

## What This Changes

The issue requests run-kind-aware bootstrap loading so HEARTBEAT.md is skipped for ordinary non-heartbeat turns and loaded only for heartbeat runs.

## Best Possible Solution

Define one run-kind-aware loader/cache policy that skips HEARTBEAT.md for ordinary non-heartbeat default runs before reads, cache snapshots, hooks, and prompt injection, while preserving real heartbeat runs and updating docs/tests.

## Reproduction Assessment

Yes, at source level. Current main's loader and cache read the raw HEARTBEAT.md entry before run-kind filtering; no live turn was executed because this review was read-only.

## Solution Assessment

No, not as only passing an isHeartbeat flag through the two named functions. The maintainable fix needs a shared run-kind-aware policy across loader, cache, hooks, prompt injection, docs, and tests.
