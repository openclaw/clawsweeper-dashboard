## Summary

Keep open: current main and the latest release still read and cache HEARTBEAT.md before run-kind filtering, so the requested default non-heartbeat skip remains missing and product-sensitive.

## What This Changes

Issue requests loading HEARTBEAT.md only for heartbeat runs instead of injecting it into ordinary non-heartbeat messages.

## Best Possible Solution

Define one run-kind-aware bootstrap loader/cache policy that skips HEARTBEAT.md for ordinary non-heartbeat default runs before reads, cache snapshots, hooks, and prompt injection, while preserving real heartbeat runs and updating docs/tests.

## Reproduction Assessment

Yes, at source level. Current main still reads and snapshots HEARTBEAT.md before run-kind filtering, and normal default-agent runs still keep it when heartbeat guidance is enabled.

## Solution Assessment

No, not as only passing an isHeartbeat flag through the two named functions. The maintainable fix needs a shared run-kind-aware policy across loader, cache, hooks, prompt injection, docs, and tests.
