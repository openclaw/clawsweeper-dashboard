## Summary

Keep open: current main and v2026.6.11 still load and cache HEARTBEAT.md before run-kind filtering, while normal default-agent runs may still include heartbeat guidance when enabled.

## What This Changes

Request run-kind-aware bootstrap loading so HEARTBEAT.md is skipped for ordinary non-heartbeat messages and kept for real heartbeat runs.

## Best Possible Solution

Define one run-kind-aware bootstrap loader/cache policy that skips HEARTBEAT.md for ordinary non-heartbeat default runs before reads, snapshots, hooks, and prompt injection, while preserving real heartbeat runs and updating docs/tests.

## Reproduction Assessment

Yes, at source level. Current main still reads and snapshots HEARTBEAT.md before run-kind filtering, and normal default-agent runs can still keep it when heartbeat guidance is enabled.

## Solution Assessment

No, not as only passing an isHeartbeat flag through the two named functions. The maintainable fix needs one shared run-kind-aware policy across loader, cache, hooks, prompt injection, docs, and tests.
