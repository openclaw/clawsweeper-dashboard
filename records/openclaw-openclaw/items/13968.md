## Summary

Keep open: current main and v2026.6.11 still read/cache HEARTBEAT.md before run-kind filtering, and the open tiered-bootstrap PR preserves default main-session HEARTBEAT.md loading rather than solving this focused on-demand request.

## What This Changes

Request to skip HEARTBEAT.md for ordinary non-heartbeat runs by making bootstrap loading/cache resolution run-kind aware.

## Best Possible Solution

Define one run-kind-aware bootstrap loading/cache contract that skips HEARTBEAT.md for ordinary non-heartbeat runs before reads, snapshots, hooks, and prompt injection, while preserving real heartbeat and lightweight behavior and updating docs/tests.

## Reproduction Assessment

Yes, at source level: current main clearly reads and snapshots HEARTBEAT.md before run-kind filtering, and docs still permit it in normal enabled default-agent runs. I did not run a live token-measurement reproduction in this read-only cleanup review.

## Solution Assessment

Unclear as proposed: the source gap is real, but the best fix needs a maintainer decision on default behavior versus an explicit selection/tier contract. A final post-load filter alone is not sufficient because it would not avoid the read/cache cost.
