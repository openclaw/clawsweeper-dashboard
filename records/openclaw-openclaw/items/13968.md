## Summary

Keep open: current main and the latest release still read and cache HEARTBEAT.md before run-kind filtering, and the current docs still allow HEARTBEAT.md in ordinary default-agent runs when heartbeat guidance is enabled.

## What This Changes

Request to skip loading HEARTBEAT.md for ordinary non-heartbeat runs and load it only for real heartbeat runs.

## Best Possible Solution

Define one run-kind-aware bootstrap loader/cache contract that skips HEARTBEAT.md before reads, snapshots, hooks, and prompt injection for ordinary non-heartbeat runs while preserving real heartbeat runs, then update docs and focused tests.

## Reproduction Assessment

Yes. Source inspection shows HEARTBEAT.md is still part of the fixed raw bootstrap loader and cache path before run-kind filtering, and the docs still define normal-run injection when heartbeat guidance is enabled.

## Solution Assessment

Unclear until maintainers decide the product contract. The requested pre-load skip is the right technical shape for the stated savings, but it changes documented normal-run HEARTBEAT.md visibility and should not be replaced by a final post-load filter or a competing broad tier mechanism.
