## Summary

Keep open: current main and the latest release still read and cache HEARTBEAT.md before run-kind filtering, and the public heartbeat docs still allow HEARTBEAT.md in ordinary default-agent runs when heartbeat guidance is enabled. The open tiered-bootstrap work overlaps but preserves default main-session behavior, so it does not close this focused request.

## What This Changes

Request to skip HEARTBEAT.md for non-heartbeat runs by threading heartbeat/run-kind state into bootstrap file loading and caching.

## Best Possible Solution

Decide one bootstrap context contract, then implement run-kind-aware loading/cache behavior before raw reads and snapshots, preserve real heartbeat/lightweight behavior, and update heartbeat docs plus focused bootstrap/cache tests.

## Reproduction Assessment

Yes, source-reproducible: current main shows HEARTBEAT.md in the raw workspace bootstrap entries, the cache loads that raw set, and run-kind filtering happens afterward. I did not run tests because this review is read-only, but the call path is direct in source.

## Solution Assessment

Unclear as a product decision: the proposed isHeartbeat-aware load path is the right layer for the requested savings, but it changes the documented normal-run HEARTBEAT.md contract. Maintainers should choose between this narrow default change and a broader tiered/context-selection contract before implementation.
