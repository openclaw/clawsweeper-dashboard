## Summary

Keep this PR open for maintainer review. The SQLite-only runtime direction is necessary—current main still loads legacy auth paths and imports shared OAuth material—but the exported SDK deprecations need an explicit compatibility decision for callers that pass noncanonical paths to `AuthStorage.create(path)` or construct `FileAuthStorageBackend` directly.

## What This Changes

The branch makes per-agent SQLite the only steady-state auth-profile store, adds Doctor migration and archival for legacy JSON credential sources, and introduces SQLite-backed SDK deprecation adapters.

## System Context

Agent sessions, gateway startup, and provider authentication all consume agent-scoped credentials and auth-routing state. The change moves retired JSON sources behind a Doctor migration boundary, then supplies SQLite-backed state to provider resolution and session SDK consumers.
