## Summary

Keep this PR open. Current `main` still serializes Feishu streaming updates in the reply dispatcher, so the central stale-update drain remains unaddressed; this branch’s session-owned latest-wins approach is a plausible narrow fix. The branch is currently conflicted with `main`, and the live claim needs directly inspectable current-head evidence before merge.

## What This Changes

This PR removes the Feishu reply dispatcher’s secondary FIFO so the existing streaming-card session can coalesce pending full-content snapshots and avoid replaying stale updates after generation completes.

## System Context

Feishu reply dispatch receives agent partial and final replies, starts a streaming CardKit session, and sends card updates. The streaming session then throttles and applies CardKit updates before the dispatcher closes or discards the card at the end of the reply.

## Best Possible Solution

Rebase onto current `main`, retain the single session-owned queue design, and attach redacted direct evidence from a real Feishu run showing that a long reply reaches its final card state without a post-generation stale-update drain.
