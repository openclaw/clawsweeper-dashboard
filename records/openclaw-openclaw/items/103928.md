## Summary

This PR remains necessary because current main still serializes every cumulative Feishu snapshot through a second dispatcher FIFO. The proposed single-owner queue is exact-head live-proven, cleanly mergeable, and has no actionable correctness or security finding; it should stay open for ordinary Feishu owner review and merge gating.

## What This Changes

Removes the Feishu reply dispatcher’s secondary partial-update FIFO so cumulative snapshots enter the session-owned latest-wins queue directly, with blocked-update and close/discard regression coverage.

## Best Possible Solution

Land the session-owned latest-wins queue with the existing full cumulative payload behavior and the new blocked-update, close, and discard regression coverage.
