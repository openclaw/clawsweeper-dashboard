## Summary

This PR addresses a plausible session-visibility bug, but its new alias allowance leaves `sessions_send` able to target the caller through an alias and wait behind its own active lane. It also needs after-fix real behavior proof beyond focused unit tests before merge.

## What This Changes

The PR preserves normalized main/current aliases in session-tool context and passes them to list, history, and send visibility checks so supported aliases are accepted as the current session.

## Best Possible Solution

Use one normalized current-session alias set for both the pre-dispatch self-target rejection and the subsequent visibility guard, add a regression test for aliased `sessions_send`, and attach redacted after-fix runtime evidence showing the alias is rejected before dispatch.
