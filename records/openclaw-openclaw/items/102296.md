## Risks / Open Questions

- Claw removal can leave session-store entries for the deleted agent because it invokes the config mutation helper without the canonical session purge.
- The dry-run and `planIntegrity` contract does not visibly bind removal of channel bindings and `tools.agentToAgent.allow` references, so consent may omit real downstream mutations.
- A concurrent Claw add or ownership adoption can occur after the final package-reference read but before uninstall completes, allowing a newly shared plugin or skill to be removed.
- Root-only status enumeration hides orphaned workspace and package ownership rows, weakening partial-state diagnosis and recovery.
- Successful removal currently lacks a durable redacted tombstone, so operators may lose the evidence needed to explain which role and resources previously existed.
- The PR remains part of an open RFC stack with an open prerequisite, so landing order and permanent lifecycle semantics are not yet settled.
