## Summary

Keep open: current main still returns a signal-qualified shared OTLP endpoint unchanged before constructing each enabled exporter, so metrics and logs can inherit the traces URL. The related signal-specific endpoint work provides an explicit override path but does not fix the shared-endpoint fallback.

## What This Changes

Fix diagnostics-otel so a shared OTLP endpoint ending in one signal path does not route other enabled signals to that same path.

## Best Possible Solution

Update the diagnostics-otel shared-endpoint fallback to derive the requested signal path from a signal-qualified shared endpoint when routing another signal, while preserving explicit per-signal endpoints and query/fragment handling.

## Reproduction Assessment

Yes at source level. With a shared endpoint ending in `/v1/traces` and metrics or logs enabled, the current URL resolver returns that traces endpoint unchanged for every requested signal path.

## Solution Assessment

Yes. A small plugin-local fix in the URL resolution path plus focused regression coverage is narrower than adding new config, because per-signal endpoint config already exists.
