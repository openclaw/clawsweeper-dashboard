## Summary

Keep this open: current main and the latest release still preserve a shared signal-qualified OTLP endpoint before applying the requested metrics or logs path, so the reported multi-signal misrouting remains valid and narrow.

## What This Changes

The issue reports that diagnostics-otel misroutes metrics and logs to a shared OTLP endpoint that already ends in /v1/traces when multiple telemetry signals are enabled.

## Best Possible Solution

Update the diagnostics-otel shared-endpoint fallback so a shared signal-qualified endpoint is normalized to the requested signal path, while explicit per-signal endpoints remain exact overrides and docs/tests describe the rule.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: configure the shared endpoint as `.../v1/traces` with traces, metrics, and logs enabled, and metrics/logs inherit that exact URL before their requested paths are applied. This read-only review did not run a live collector or test command.

## Solution Assessment

Yes. The narrow maintainable fix is in the diagnostics-otel URL resolver/caller tests and docs, not a new config surface, because signal-specific endpoint overrides already exist.
