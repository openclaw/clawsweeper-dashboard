## Summary

Keep this issue open: current `main` and the latest release still reuse a signal-qualified shared OTLP endpoint before considering the requested metrics/logs path, so the reported multi-signal misrouting remains valid.

## What This Changes

The issue asks OpenClaw to stop routing metrics and logs to a trace-qualified shared OTLP endpoint when multiple diagnostics OTEL signals are enabled.

## Best Possible Solution

Change the diagnostics-otel shared-endpoint fallback so a signal-qualified shared endpoint is normalized to the requested signal path, while explicit per-signal endpoints remain exact overrides and docs/tests describe the rule.

## Reproduction Assessment

Yes. A source-level reproduction is clear: configure `diagnostics.otel.endpoint` as `.../v1/traces` with traces, metrics, and logs enabled, and the resolver returns the trace URL before applying the metrics/logs path.

## Solution Assessment

Yes. The best fix is a narrow diagnostics-otel resolver and regression-test change, not a new config surface, because per-signal endpoint overrides already exist.
