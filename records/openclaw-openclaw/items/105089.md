## Summary

The resource-exhaustion bug is real and the shared bounded reader is appropriate for `user_list`, but the chatbot POST path introduces an avoidable compatibility regression by making HTTP 200 success depend on the size of a response body that OpenClaw does not use. This PR should stay open for that focused repair and then receive owner confirmation of the remaining user-list limits.

## What This Changes

The PR adds byte and total-read limits to Synology Chat chatbot POST and `user_list` responses, aborts oversized streams, preserves cache fallback, and adds overflow regression tests.

## Best Possible Solution

Resolve chatbot delivery from the HTTP status without buffering its unused body, terminate or discard that body safely, retain bounded parsing and cache fallback for `user_list`, and have a Synology-area owner accept or recalibrate the remaining user-list limits.
