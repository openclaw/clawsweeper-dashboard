## What This Changes

## Best Possible Solution

Keep the doctor-owned EACCES downgrade, but let `installCompletion` create missing profiles, downgrade only real permission failures, fix the remediation command to `completion --install`, and add regression coverage for both read-only existing profiles and absent fresh profiles.

## Reproduction Assessment

Yes. The linked issue and current source show `doctor --fix` auto-approves shell-completion install, then `doctorShellCompletion` awaits `installCompletion`, which wraps profile write EACCES as a fatal error.

## Solution Assessment

No. The doctor boundary is the right place to degrade optional completion failures, but duplicating writability logic before the installer bypasses the installer’s existing missing-profile creation contract.

Full review comments:

- **[P2] Preserve missing-profile completion installs:** `src/commands/doctor-completion.ts:259`
  - body: This guard treats every `fs.access(W_OK)` failure as an unwritable profile. On fresh zsh, fish, or PowerShell setups the profile commonly does not exist yet, and current `installCompletion` handles that by creating the parent directory and profile before writing. Returning here makes `doctor --fix` skip a supported first-time install path and show a misleading not-writable warning; let the installer run and downgrade actual EACCES instead, or distinguish ENOENT from permission errors.
  - confidence: 0.94
- **[P3] Use the supported completion install command:** `src/commands/doctor-completion.ts:220`
  - body: The new notes tell users to run `openclaw completion install`, but the CLI exposes `openclaw completion --install` and the docs use that flag form. On the EACCES path this gives users an invalid recovery command, so both new notes should point at the supported command.
  - confidence: 0.9
