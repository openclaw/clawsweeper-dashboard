## Summary

The patch is a clean additive enhancement with convincing ordinary-spawn proof, but it creates an agent-facing session-state contract that should be explicitly confirmed for every accepted native spawn mode before merge. The implementation updates both ordinary and collector acceptance exits, while the posted live run demonstrates only the ordinary child-session path; the prior review’s fork-semantics question therefore remains material.

## What This Changes

This PR returns the durable child-session UUID as `sessionId` and aliases `sessionKey` to `childSessionKey` in accepted native `sessions_spawn` results, then documents and tests that result shape.

## System Context

Native sub-agent spawning prepares a child session, writes its durable identity into the session store, and returns an immediate acceptance payload to the parent agent. The parent can later use that identity with session inspection and session-state event records.

## Architecture Diagram

flowchart LR
  Parent[Parent agent] --> Spawn[Native sub-agent spawn]
  Spawn --> Prepare[Create or fork child session]
  Prepare --> Store[Persist durable child identity]
  Prepare --> Accept[Accepted spawn result]
  Accept --> Parent
  Store --> Inspect[Session inspection and state events]

## Best Possible Solution

Establish `sessionId` as one documented durable-ID contract across ordinary, forked, and collector native spawns, with focused persisted-identity coverage for the unproven modes and validation on the refreshed merge head.
