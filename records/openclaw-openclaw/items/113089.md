## Summary

This PR remains necessary: the proposed `sessionId` field is not on current main and the branch provides an additive way for parent agents to identify a spawned child’s durable session without parsing `childSessionKey`. The contributor supplied focused tests and redacted live proof that the returned ID matches persisted child state; the remaining decision is whether OpenClaw wants to make that agent-tool return field a supported public contract.

## What This Changes

The PR adds a durable child `sessionId` and a `sessionKey` alias to accepted native `sessions_spawn` results, with documentation and focused spawn-flow coverage.

## System Context

The sub-agent spawn path creates a child agent session, persists its session state, and immediately returns an accepted result to the parent agent. Parent orchestration then uses the returned identifiers to observe the child, retrieve its session data, and receive its completion handoff.

## Architecture Diagram

  E --> F[Session lookup and sub-agent coordination]

## Best Possible Solution

Adopt one documented, additive accepted-spawn identity contract: preserve `childSessionKey`, retain `sessionKey` as its alias, and return the durable child `sessionId` only after confirming its semantics across regular and forked native spawns.
