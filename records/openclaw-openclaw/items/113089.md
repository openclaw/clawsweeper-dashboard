## What This Changes

The branch returns the durable child `sessionId` and a `sessionKey` alias in accepted native `sessions_spawn` results, and documents and tests that additive payload shape.

## System Context

Agent parents call `sessions_spawn` to start a child run. The spawn subsystem creates or forks a persisted child session, launches the run through the gateway, and returns an acceptance payload that lets the parent track the child and resolve its stored state.

## Architecture Diagram

flowchart LR
  Parent[Parent agent] --> Request[sessions_spawn request]
  Request --> Prepare[Prepare new or forked child session]
  Prepare --> Persist[Persist child session identity]
  Persist --> Launch[Launch child run]
  Launch --> Accepted[Accepted spawn payload]
  Accepted --> Lookup[Parent session or transcript lookup]

## Best Possible Solution

Adopt one documented durable-session identity contract for accepted spawns, then add focused regression coverage that compares the returned UUID with the persisted child identity for fresh, forked, and collector acceptance paths before merge.
