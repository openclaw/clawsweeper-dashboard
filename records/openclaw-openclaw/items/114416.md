## Summary

This PR addresses a source-confirmable inconsistency between Bun package-manager detection and update-status dependency markers. The proposed preference for Bun’s current `bun.lock` format, while retaining `bun.lockb`, is a bounded fix with credible real-install proof; it should remain open for current-main refresh and normal maintainer merge review.

## What This Changes

Updates `openclaw update status` to use Bun’s text `bun.lock` when present, retaining `bun.lockb` as the legacy fallback, and adds coverage for text-only, binary-only, and dual-lockfile installs.

## System Context

The update-status subsystem inspects an installed OpenClaw package root to identify its package manager and decide whether dependencies are healthy. Its dependency marker result is presented by the CLI so operators can distinguish healthy, missing, and stale installations.
