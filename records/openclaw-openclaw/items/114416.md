## Summary

Keep this PR open for normal review: current `main` still hard-codes `bun.lockb`, while Bun’s documented current lockfile is `bun.lock`. The narrow patch aligns dependency-status marker selection with the existing package-manager detector, but it still needs contributor-provided real behavior proof from a Bun installation before merge.

## What This Changes

This PR makes `openclaw update status` use Bun’s current text lockfile (`bun.lock`) when present, while continuing to support legacy `bun.lockb` installations.

## System Context

The update-status command resolves the installed OpenClaw root, detects its package manager, then compares the package manager’s lockfile with the installed dependency marker to report dependency health. Its result feeds the CLI table and JSON output used by operators deciding whether an installation is current, missing dependencies, or stale.
