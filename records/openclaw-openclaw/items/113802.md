## Summary

Keep this PR open: it addresses a real Goal-budget accounting bug and includes credible live proof, but the current head still leaves the first run uncharged when a fresh session-token total already exists at Goal creation. The previous ClawSweeper P1 finding remains applicable to the unchanged head, so this needs a narrow accounting repair before merge.

## What This Changes

This PR adds persisted Goal token cursors so Goal budgets establish a post-creation session-token baseline and charge later positive usage deltas without mutating read-only status projections.

## System Context

Goals are persisted on session entries and use session token snapshots to enforce a per-goal token budget. Agent-run finalization writes the latest session metadata, after which Goal status and tools project the stored accounting state to CLI and TUI users.

## Best Possible Solution

When a usable fresh token snapshot exists at Goal creation, persist it immediately as both the Goal baseline and cursor; retain deferred baselining only for stale or absent creation-time totals, with focused coverage for the first-run charge and legacy persisted Goals.
