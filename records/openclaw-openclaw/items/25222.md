## Summary

Keep open: current main and v2026.6.11 still queue same-session followups without an immediate channel-visible busy/status acknowledgement, cancel/new-session guidance, or stable busy reason payload. The source gap is clear, but the remaining work needs maintainer product direction before implementation.

## What This Changes

The issue requests a fast user-visible busy/status reply, optional cancel/new-session guidance, heartbeat behavior, and stable busy-reason metadata when a same-session message arrives during an active long-running response.

## Best Possible Solution

Implement one generic active-session busy/status contract across queue policy, runner return payloads, dispatch, and channel presentation, with conservative channel-safe text, typed optional actions, stable reason metadata, and focused queue/runner/dispatch/channel coverage.

## Maintainer Decision

Question: Should OpenClaw add a generic busy-session acknowledgement by default, make it opt-in/configurable, and which portable cancel/new-session actions and busy reason fields should be part of the contract?

Rationale: The source gap is clear, but adding user-visible status text, configuration, and cross-channel actions changes product UX and compatibility expectations across messaging surfaces.

Likely owner: steipete

Owner reason: Peter has the strongest history on queue policy and queued-followup behavior that this product decision would change.

Owner confidence: high

Options:

- **Conservative Default Acknowledgement (recommended):** Add short default busy text without destructive actions by default, and expose typed optional cancel/new-session actions only where channels can render them safely.
- **Opt-In Configurable Acknowledgement:** Add the same core contract behind explicit messages.queue configuration so existing deployments preserve silent enqueue behavior unless operators enable it.
- **Defer To Channels:** Keep core enqueue behavior unchanged and ask channel/plugin owners to implement local busy UX, accepting inconsistent behavior across channels.
