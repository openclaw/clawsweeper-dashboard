## Summary

Keep open: current main and the latest release still enqueue or steer busy same-session turns without the requested scripted busy reply, cancel/new-session guidance, or stable busy reason payload; the existing typing/status cue is only a partial mitigation.

## What This Changes

The issue requests an immediate channel-visible session-busy reply, optional cancel/new-session actions, heartbeat/status behavior, and busy reason metadata when a message arrives while the target session is locked.

## Best Possible Solution

Implement one generic active-session busy/status contract across queue policy, runReplyAgent, dispatch, and channel presentation, with conservative channel-safe text, typed optional actions, stable reason metadata, and focused queue/runner/dispatch/channel coverage.

Rationale: The missing source path is clear, but visible status text, configuration/defaults, and cross-channel cancel/new actions change product UX and compatibility expectations across messaging surfaces.

Likely owner: steipete

Owner confidence: high

Options:

- **Conservative default (recommended):** Add a short default busy acknowledgement with no destructive action by default, and expose typed optional cancel/new-session actions only where channels can render them safely.
- **Opt-in configuration:** Add the same core contract behind explicit messages.queue configuration so existing deployments preserve silent enqueue behavior unless operators enable it.
- **Channel-local UX:** Keep core enqueue behavior unchanged and let channel/plugin owners implement local busy UX, accepting inconsistent behavior across channels.

## Reproduction Assessment

Yes, at source level: active same-session followups can resolve to enqueue-followup, runReplyAgent returns undefined after enqueue, and dispatch maps that to no final channel reply. I did not run a live chat reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the UX and config contract. The maintainable direction is a generic core/channel busy-status contract rather than a Telegram-only bridge patch or another isolated delivery workaround.
