## Label Justifications

- `P2`: This is a normal-priority cross-channel UX/session-state improvement with clear source evidence and bounded but real user impact during long-running turns.
- `impact:session-state`: The request concerns active session locks, queued followups, busy reasons, and visible state while a session run is in flight.
- `impact:message-loss`: The silent enqueue path can make same-session user messages appear ignored or dropped until later queue handling.
- `impact:ux-friction`: Users can continue only by waiting, retrying, or guessing whether the bot is busy, stuck, or ignoring them.

## Summary

Keep open: current main and the latest release still enqueue active same-session followups without an immediate scripted busy/cancel reply, and the related receipt PR is closed unmerged while the overlapping busy-ack issue was closed back to this canonical tracker.

## What This Changes

Request an immediate channel-visible busy/status reply, with optional cancel or new-session guidance, when a user sends another message to a session that already has an active long-running turn.

## Best Possible Solution

Implement one generic active-session busy/status contract across queue policy, runner return payloads, and dispatch, with channel-safe text/actions, stable reason metadata, and focused queue/runner/dispatch/channel coverage.

## Reproduction Assessment

Yes, at source level: active same-session followups resolve to enqueue-followup, runReplyAgent returns undefined, and dispatch converts that to no channel-visible replies. I did not run a live chat reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the UX and config contract. The maintainable direction is a generic cross-channel busy/status contract, not a Telegram-only bridge patch or another isolated delivery workaround.
