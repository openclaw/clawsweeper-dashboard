## Summary

Keep open: current main and the latest release still queue active-session followups without the requested immediate scripted busy reply, cancel/new-session guidance, or stable busy reason payload. The closed implementation PR is unmerged, and the remaining open related issue covers adjacent HTTP session serialization rather than this channel-visible UX contract.

## What This Changes

Add a channel-visible busy/status acknowledgement with optional cancel and new-session guidance when a message arrives for an already active session lane.

## Best Possible Solution

Add a generic active-session busy acknowledgement contract around queue policy, runReplyAgent, and dispatch, with maintainer-chosen defaults/config, stable busy reason metadata, portable action guidance, and focused queue plus channel-path tests.
