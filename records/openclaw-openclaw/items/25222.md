- `P2`: This is a normal-priority cross-channel UX/session improvement with clear source evidence but no full setup blocker, security emergency, or outage severity.
- `impact:session-state`: The request concerns active session locks, queued followups, busy reasons, and state visibility while a session run is in flight.
- `impact:message-loss`: The silent enqueue path can make same-session user messages appear ignored or dropped until later queue handling.
- `impact:ux-friction`: Users can proceed only by waiting, retrying, or guessing whether the bot is busy, stuck, or ignoring them.

## Summary

Keep open: current main still has no scripted channel-visible busy acknowledgement, cancel/new-session guidance, or stable busy reason payload for same-session messages queued behind an active run. Adjacent work improved typing/status cues and TUI queued-turn cancellation, but it does not satisfy this cross-channel UX contract.

## What This Changes

Add an immediate channel-visible busy reply with optional cancel/new-session guidance when a message arrives while the same session is locked by a long-running response.

## Best Possible Solution

Implement one generic active-session busy/status contract across queue policy, runReplyAgent, dispatch, and channel presentation, with conservative channel-safe text, typed optional actions, stable reason metadata, and focused queue/runner/dispatch/channel coverage.

- **Diagnostics First:** Expose busy reason and queued/steered state in diagnostics or status surfaces first, and defer chat-visible acknowledgement until the noise policy is settled.
