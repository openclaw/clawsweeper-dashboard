- `impact:message-loss`: The current silent enqueue path can make same-session user messages appear ignored or dropped until later queue handling.

## Summary

Keep open: current main and v2026.6.11 still enqueue same-session followups without an immediate busy/status reply, cancel/new-session guidance, or stable busy reason payload; the remaining work needs a cross-channel UX and config decision.

## What This Changes

Request an immediate channel-visible busy/status reply, optional cancel/new-session actions, and busy reason metadata when another message arrives during an active same-session run.

## Best Possible Solution

Implement one generic active-session busy/status contract across queue policy, runner payloads, dispatch, and channel presentation with conservative text, typed optional actions, stable reason metadata, and regression coverage.

- **Conservative default (recommended):** Add a short default busy acknowledgement with no destructive action by default, plus typed optional cancel/new-session actions where channels can render them safely.
- **Opt-in configuration:** Add the same core contract behind explicit messages.queue configuration so existing deployments preserve silent enqueue behavior unless operators enable it.
- **Channel-local implementations:** Leave core queue behavior unchanged and ask channel or plugin owners to implement local busy UX, accepting inconsistent behavior across surfaces.
