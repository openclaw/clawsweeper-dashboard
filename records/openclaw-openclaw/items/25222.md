## Summary

Keep open: current main and v2026.6.11 still have queueing, steering, and typing/status cues, but not the requested immediate scripted busy reply with cancel/new-session guidance or stable busy reason metadata.

## What This Changes

The issue requests an immediate channel-visible busy/status response, optional cancel/new-session actions, and busy reason metadata when a message arrives while the same session is locked by a long-running model response.

## Best Possible Solution

Define a generic core active-session busy-reply contract that can return channel-safe status text, optional typed /stop and /new actions, and stable busy reason metadata while preserving existing queue/steer/drain behavior.
