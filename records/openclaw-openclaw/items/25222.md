## Summary

Keep open: current main and the latest release still enqueue same-session busy messages without the requested scripted busy reply, cancel/new-session guidance, or stable busy reason payload, so this remains a valid product/UX request rather than a cleanup close.

## What This Changes

The issue requests an immediate channel-visible session-busy/status response, with optional cancel/new-session actions and busy reason metadata, when a user sends another message during an active same-session run.

## Best Possible Solution

Implement one generic active-session busy/status contract across queue policy, runReplyAgent, dispatch, and channel presentation, with conservative channel-safe text, typed optional actions, stable reason metadata, and focused queue/runner/dispatch/channel coverage.

- **Channel-Local UX:** Keep core enqueue behavior unchanged and let channel or plugin owners implement local busy UX, accepting inconsistent behavior across channels.
