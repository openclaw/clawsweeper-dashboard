## Summary

Keep open: current main and v2026.6.11 still queue busy same-session followups without a scripted busy reply, cancel/new-session guidance, or stable busy reason payload. The remaining work is real, but default behavior, config shape, and portable action semantics need maintainer product direction before implementation.

## What This Changes

The issue requests an immediate user-visible busy/status reply, optional cancel or new-session guidance, and stable busy reason handling when a message arrives for a locked or long-running session.

## Best Possible Solution

Implement one generic active-session busy/status contract across queue policy, runReplyAgent, dispatch, and channel presentation, with conservative channel-safe text, typed optional actions, stable reason metadata, and focused queue/runner/dispatch/channel coverage.
