## Summary

Keep open: current main and the latest release still enqueue same-session followups without a channel-visible busy acknowledgement, cancel/new-session guidance, or stable busy reason payload, so the central UX request remains necessary.

## What This Changes

Request an immediate scripted busy/status reply, optional cancel/new-session actions, typing/status continuity, and busy reason metadata when a user messages a locked active session.

## Best Possible Solution

Keep this as the canonical core UX request and design one generic active-session busy-reply contract around queue policy, runReplyAgent, and dispatch, with channel-safe text/actions and focused cross-path tests.
