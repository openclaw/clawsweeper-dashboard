## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: The edit path always sends `schedule.kind = "cron"` with an `expr`, but current cron jobs can be `at`, `every`, `cron`, or `on-exit`. Saving an existing non-cron job from this UI can rewrite or reject its schedule even when the user edits unrelated fields.
  - confidence: 0.91
- **[P1] Send supported verbose levels:** `apps/linux/src/section_sessions.c:176-184`
  - body: The verbose selector sends `none`/`low`/`high` to `sessions.patch`, but the gateway parser only accepts `off`/`on`/`full`. This makes verbose changes from the Linux app fail validation at runtime.
  - confidence: 0.9
- **[P2] Resolve local logs from session IDs:** `apps/linux/src/section_sessions.c:264-266`
  - body: This local transcript probe builds `<store_dir>/<session-key>/transcript.jsonl`, while current gateway transcript resolution is based on `sessionId`/`sessionFile` candidates in the sessions directory and per-agent paths. The Log button will miss normal local transcripts and fall back to the dashboard unnecessarily.
  - confidence: 0.87
- **[P2] Read channel account labels from name:** `apps/linux/src/gateway_data.c:262`
  - body: Channel account snapshots expose the friendly account label as `name`, not `displayName`. Reading the old field leaves `display_name` empty for normal gateway responses, so connected accounts fall back to less helpful IDs in the UI.
  - confidence: 0.86
- **[P2] Bracket IPv6 literals before composing URLs:** `apps/linux/src/gateway_config.c:1153-1155`
  - body: `gateway_config_dashboard_url` interpolates the host directly into `scheme://host:port`, so IPv6 literals such as `::1` produce malformed URLs like `http://::1:18789/`. Bracket IPv6 hosts before launching dashboard or transcript URLs.
  - confidence: 0.83
