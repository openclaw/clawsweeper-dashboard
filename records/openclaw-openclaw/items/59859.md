Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: The edit path always saves `patch.schedule` as `{kind:"cron", expr}` even though current cron jobs can be `every`, `at`, or `on-exit`; saving an existing non-cron job from the Linux app can fail validation or rewrite its schedule when the user only edits metadata.
  - confidence: 0.93
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/test_seams.c:42-47`
  - body: `session:<id>` is a valid cron target, but this mapper treats it as unknown index 0; the save path then sends `isolated`, so editing an existing session-targeted job silently retargets it away from the intended session.
  - confidence: 0.92
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-178`
  - body: The Linux UI sends `none`/`low`/`high` for `sessions.patch.verboseLevel`, but the current gateway accepts `off`/`on`/`full` or `null`; these updates are rejected at runtime, so users cannot change verbose behavior from this app.
  - confidence: 0.94
- **[P2] Emit null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-150`
  - body: Selecting the default model row passes `NULL`, but this helper omits the `model` field entirely; the gateway only clears the override when `model:null` is present, so the UI reports an update while leaving the old model override in place.
  - confidence: 0.9
- **[P3] Add Linux app labeler coverage:** `.github/labeler.yml:139-147`
  - body: This PR adds a new `apps/linux` app surface, but the labeler still has no `app: linux` rule. Root policy requires new app/doc surfaces to update labeler and GitHub labels so future Linux app changes route correctly.
  - confidence: 0.88
