Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Preserve cron schedule variants on edit:** `apps/linux/src/section_cron.c:274-275`
  - body: The edit save path always sends `patch.schedule` as `{kind: "cron", expr: ...}`. Current cron jobs can be `every`, `at`, or `on-exit`, so saving an unrelated edit for those jobs can rewrite the schedule shape or fail validation; this prior ClawSweeper blocker is still present at the current head.
  - confidence: 0.91
- **[P1] Preserve session-scoped cron targets:** `apps/linux/src/test_seams.c:42-47`
  - body: Valid cron targets include `session:<id>`, but the mapping treats any unknown target as the first combo option and later saves it as `isolated`. Editing a session-scoped job can silently retarget it away from the intended session; this prior ClawSweeper blocker remains unchanged.
  - confidence: 0.89
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-184`
  - body: The verbose combo sends `none`, `low`, or `high`, but the server parser accepts `off`, `on`, `full`, or null. Users changing verbose behavior from the Linux app will get rejected `sessions.patch` requests until the UI maps to the supported values.
  - confidence: 0.9
- **[P2] Send null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-150`
  - body: Choosing the default model path passes `NULL`, but the mutation helper omits `model` entirely when it is null. The server only resets the session model when `model: null` is present, so the Linux UI cannot clear an existing model override.
  - confidence: 0.86
- **[P3] Add Linux app labeler coverage:** `apps/linux/README.md:1`
  - body: This PR introduces a new first-class `apps/linux` surface, but the branch does not add matching labeler coverage. Future Linux app issues and PRs will continue to be misrouted under generic app/gateway labels unless `.github/labeler.yml` is updated before merge.
  - confidence: 0.82
