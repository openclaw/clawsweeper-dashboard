## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: The edit save path always sends `schedule_kind = "cron"`, so saving an existing `every`, `at`, or `on-exit` job rewrites or invalidates its schedule even when the user only changes metadata. Keep the existing schedule variant unless the UI explicitly changes it.
  - confidence: 0.93
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/test_seams.c:42-48`
  - body: `session:*` is a valid cron target, but this helper maps unknown targets to the fixed combo default and the edit path saves that back as an isolated/new target. Editing a session-scoped job can silently retarget it away from the intended session.
  - confidence: 0.91
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:175-184`
  - body: The verbose dropdown sends `none`, `low`, and `high`, but `sessions.patch` accepts verbose overrides as `off`, `on`, or `full`. These updates are rejected at runtime, so users cannot change verbose behavior from this UI.
  - confidence: 0.9
- **[P2] Send null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-151`
  - body: Selecting the default model passes `NULL`, but `mutation_sessions_patch` omits `model` when the pointer is null. The gateway only clears a model override when `model: null` is present, so the UI cannot clear an existing override.
  - confidence: 0.89
- **[P3] Add Linux app labeler coverage:** `.github/labeler.yml:139-148`
  - body: Root policy requires new app surfaces to update `.github/labeler.yml`, but this PR adds `apps/linux/**` without an `app: linux` label rule. Add the Linux app/docs glob so future PRs route to the right app label.
  - confidence: 0.82
