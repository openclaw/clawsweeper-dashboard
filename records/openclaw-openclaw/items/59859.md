## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: When saving an edited job, this path always sends `schedule_kind = "cron"` and the mutation helper serializes only `{kind, expr}`. Current gateway jobs can use `at`, `every`, `cron`, or `on-exit`, so opening and saving a non-cron job can rewrite, reject, or change its schedule even when the user only edits metadata.
  - confidence: 0.94
- **[P1] Preserve session-scoped cron targets:** `apps/linux/src/test_seams.c:42-48`
  - body: `session:<id>` is a valid cron target, but this mapper treats every unknown target as index 0 and the edit save path maps index 0 back to `isolated`. Editing a session-scoped job can silently retarget it away from the intended session.
  - confidence: 0.93
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:175-184`
  - body: The sessions verbose dropdown sends `none`, `low`, and `high`, but `sessions.patch` validates verbose overrides as `off`, `on`, or `full`. These updates will be rejected at runtime, so users cannot change session verbose behavior from the Linux app.
  - confidence: 0.92
- **[P2] Send null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-151`
  - body: The default model row stores `NULL`, but `mutation_sessions_patch` omits `model` whenever the pointer is null. The gateway clears an override only when the patch explicitly contains `model: null`, so selecting the default row becomes a no-op.
  - confidence: 0.9
- **[P3] Add Linux app labeler coverage:** `.github/labeler.yml:184-209`
  - body: This PR creates a new `apps/linux/**` app surface, but the app labeler still only routes Android, iOS, macOS, and web UI paths. Add Linux app label routing, plus the matching label if maintainers choose that name, so future Linux companion changes route correctly.
  - confidence: 0.86
