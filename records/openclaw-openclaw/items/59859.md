## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve cron schedule variants on edit:** `apps/linux/src/section_cron.c:274-275`
  - body: The edit save path always sends `patch.schedule` as `{ kind: "cron", expr: ... }`, but current cron jobs can be `at`, `every`, `cron`, or `on-exit`. Saving an existing non-cron job after editing unrelated fields can rewrite the schedule shape or fail validation, so the dialog needs to preserve unsupported variants or avoid patching schedule unless it can represent them.
  - confidence: 0.92
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/section_cron.c:264-265`
  - body: The edit dialog reduces the target to a fixed combo index and then writes only `main`, `current`, or `isolated`, while the gateway contract also supports `session:<id>`. Opening and saving a job bound to a concrete session can silently retarget it away from that session.
  - confidence: 0.9
- **[P2] Send supported verbose values:** `apps/linux/src/section_sessions.c:176-178`
  - body: This maps the verbose selector to `none`/`low`/`high`, but `sessions.patch` accepts normalized `off`/`on`/`full` values. Verbose changes from the Linux UI will be rejected by the gateway instead of updating the session.
  - confidence: 0.9
- **[P2] Serialize null when clearing model overrides:** `apps/linux/src/gateway_mutations.c:148-150`
  - body: Choosing the default model passes `NULL`, and `mutation_sessions_patch` omits `model` whenever the pointer is null. The gateway uses `model: null` as the clear operation and treats omission as no change, so users cannot clear an existing model override from this UI.
  - confidence: 0.88
- **[P2] Resolve local session logs from session IDs:** `apps/linux/src/section_sessions.c:265-266`
  - body: The Log action builds `<storeDir>/<session-key>/transcript.jsonl`, but current gateway transcript resolution uses the session id/session file candidates under the sessions directory. Normal local transcripts will be missed and the UI will fall back to the dashboard even when a local file exists.
  - confidence: 0.84
- **[P3] Add Linux app labeler coverage:** `.github/labeler.yml:184-208`
  - body: Root policy requires new app surfaces to update `.github/labeler.yml`, but the labeler currently has app rules for Android, iOS, macOS, and web UI only. Add an `app: linux` rule for `apps/linux/**` and the Linux platform docs so review routing does not stay under the wrong app label.
  - confidence: 0.86
