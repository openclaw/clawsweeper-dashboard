## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve non-cron schedules when editing jobs:** `apps/linux/src/section_cron.c:274-275`
  - body: `cron.update` supports `at`, `every`, `cron`, and `on-exit` schedules, but this save path always serializes the edited job as `{ kind: "cron", expr: ... }`. Opening an existing `every`, `at`, or `on-exit` job and saving unrelated fields can fail validation or rewrite the job’s runtime schedule.
  - confidence: 0.93
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/test_seams.c:47`
  - body: Valid cron targets include `session:<id>`, but this mapper treats every unknown value as the New Session row, which the save path sends back as `isolated`. Editing a job with a persistent session target therefore silently retargets it away from the intended session.
  - confidence: 0.91
- **[P2] Send supported verbose levels:** `apps/linux/src/section_sessions.c:176-178`
  - body: `sessions.patch` validates verbose overrides as `off`, `on`, or `full`, but the Linux dropdown sends `none`, `low`, and `high`. Those updates are rejected by the gateway, so users cannot change verbose behavior from this app.
  - confidence: 0.94
- **[P2] Serialize null when clearing model overrides:** `apps/linux/src/gateway_mutations.c:148-150`
  - body: Selecting the default model passes `NULL`, but this helper omits the `model` field entirely. The gateway uses `model: null` to clear a saved override, so the UI cannot return a session to the default model once an override exists.
  - confidence: 0.89
- **[P3] Add labeler coverage for the Linux app:** `apps/linux/README.md:1`
  - body: This PR introduces a new `apps/linux` app surface, but the app labeler still only covers Android, iOS, macOS, and web UI. Future Linux-app changes would miss the app ownership label required by repo policy.
  - confidence: 0.86
