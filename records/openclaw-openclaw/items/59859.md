  - body: This adds `LINUX_APP` to the PR branch's old `src/gateway/protocol` registry, but current main validates gateway client ids from `packages/gateway-protocol/src/client-info.ts`, and that registry still lacks `openclaw-linux`.   - confidence: 0.92
- **[P1] Use the shared SQLite identity and auth store:** `apps/linux/src/device_identity.c:343-349`
  - body: Current main treats `identity/device.json` as legacy doctor-import input and stores device identity/auth rows in `state/openclaw.sqlite`, but this runtime reads or creates that JSON identity file and pairs it with a JSON device-token store. That can mint a Linux-only identity/token outside the migration, pairing, backup, and security boundary.
  - confidence: 0.9
- **[P1] Send supported verbose levels:** `apps/linux/src/section_sessions.c:176-184`
  - body: `sessions.patch` accepts verbose values `off`, `on`, `full`, or `null`, but this UI sends `none`, `low`, or `high`. A user changing the Verbose dropdown from the Linux Sessions view will get a gateway validation failure instead of updating the session.
  - confidence: 0.95
- **[P2] Store companion product state in the approved runtime store:** `apps/linux/src/product_state.c:33-36`
  - body: Connection mode, onboarding completion, and heartbeat intent are durable OpenClaw-owned runtime state, but this writes them to a new `openclaw-companion/product-state.ini` sidecar. That bypasses the shared state DB/doctor/backup contract and needs either SQLite storage or an explicit maintainer-approved migration boundary.
  - confidence: 0.86
