## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: When an existing job is edited, this path always sets `schedule_kind = "cron"`; the mutation helper then emits `schedule: { kind, expr }`. Jobs created elsewhere with `kind: "every"` or `kind: "at"` will be rewritten or rejected when a user saves an unrelated edit, so the edit flow needs to preserve the original schedule shape unless the user explicitly changes it.
  - confidence: 0.91
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/test_seams.c:42-47`
  - body: The reverse mapper returns index 0 for unknown targets, and index 0 serializes back to `isolated`. Since `session:<id>` is a valid cron target, opening and saving such a job will silently retarget it away from the intended session. Preserve opaque session targets or add an explicit UI representation for them.
  - confidence: 0.9
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-184`
  - body: The Verbose combo sends `none`/`low`/`high`, but the current gateway parser accepts `off`/`on`/`full` or null. These updates will fail validation at runtime, so the Linux app cannot change session verbose behavior until the UI maps to the server contract.
  - confidence: 0.88
- **[P2] Send null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-151`
  - body: Selecting the default model passes `NULL` into `mutation_sessions_patch`, but this helper omits the `model` member instead of serializing JSON null. The gateway only clears a model override when `model: null` is present, so the default row becomes a no-op for sessions with an override.
  - confidence: 0.86
- **[P3] Add Linux app labeler coverage:** `.github/labeler.yml:184-209`
  - body: This branch adds a new top-level app surface under `apps/linux`, but `.github/labeler.yml` still only has app labels for Android, iOS, macOS, and web-ui. Add an `app: linux` rule for `apps/linux/**` so future PRs route to the right app surface instead of falling through to gateway/web labels.
  - confidence: 0.82
