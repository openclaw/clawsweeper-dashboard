## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: The edit save path always serializes the patch as `schedule.kind = "cron"`. Existing jobs can be `at`, `every`, `cron`, or `on-exit`, so opening a non-cron job and saving unrelated edits can rewrite or invalidate its schedule instead of preserving the current variant.
  - confidence: 0.93
- **[P1] Preserve session-scoped cron targets:** `apps/linux/src/section_cron.c:351-352`
  - body: The edit dialog maps any unrecognized `sessionTarget` to combo index 0, and the save path writes index 0 back as `isolated`. Valid `session:<id>` targets therefore get silently retargeted when a user saves the job, even for unrelated edits.
  - confidence: 0.91
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-178`
  - body: The session verbose dropdown sends `none`, `low`, and `high`, but the gateway parser accepts only `off`, `on`, or `full` for `verboseLevel`. Those updates will be rejected instead of changing the session verbosity.
  - confidence: 0.94
- **[P2] Send null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-151`
  - body: Choosing the default model row passes `NULL`, but `mutation_sessions_patch` omits the `model` field when the pointer is null. The gateway uses JSON `null` to clear a model override and treats an omitted field as no change, so the UI cannot clear an existing override.
  - confidence: 0.92
- **[P3] Add Linux app labeler coverage:** `.github/labeler.yml:200-209`
  - body: This PR adds a new first-class app under `apps/linux`, but the labeler still only maps Android, iOS, macOS, and web UI app surfaces. Root policy requires new app surfaces to update labeler coverage so future changes route to the right owners.
  - confidence: 0.84
