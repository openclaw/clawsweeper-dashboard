## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve cron schedule variants on edit:** `apps/linux/src/section_cron.c:274-275`
  - body: The edit-save path always serializes `patch.schedule` as `{ kind: "cron", expr: ... }`. Existing `every`, `at`, or `on-exit` jobs returned by the gateway will be rewritten or rejected even when the user only edits metadata; the server contract accepts those variants and preserves them today.
  - confidence: 0.92
- **[P1] Preserve session-scoped cron targets:** `apps/linux/src/section_cron.c:264-266`
  - body: The edit dialog maps the current `sessionTarget` through a fixed four-option combo. Valid gateway targets like `session:project-alpha` fall through to the default index and are later saved back as a built-in target, so saving an unrelated field silently retargets the job.
  - confidence: 0.88
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-184`
  - body: The Linux UI sends `none`, `low`, and `high` as `verboseLevel`, but `sessions.patch` normalizes only `off`, `on`, or `full`. These updates will be rejected at runtime, so the verbose selector cannot actually change session verbosity.
  - confidence: 0.93
- **[P2] Send null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-150`
  - body: Selecting the default model gives `mutation_sessions_patch` a NULL model, and the helper omits `model` entirely. The gateway uses explicit `model: null` to clear an existing override, so this UI path leaves the old model override in place.
  - confidence: 0.9
- **[P3] Add Linux app labeler coverage:** `.github/labeler.yml:200-208`
  - body: This PR creates a new `apps/linux` app surface, but the labeler still only has Android, iOS, macOS, and web UI app entries. New app surfaces need label ownership so future PRs route correctly.
  - confidence: 0.82
