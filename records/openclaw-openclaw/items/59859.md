## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: The edit save path always sends `schedule.kind = "cron"` with an `expr`, so editing an existing `every` or `at` job rewrites its schedule shape or fails validation even when the user changes only metadata. Preserve the original schedule variant unless the user explicitly changes it.
  - confidence: 0.92
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/section_cron.c:351-352`
  - body: Valid cron targets include `session:<id>`, but the edit dialog maps unknown targets to index 0 and then saves index 0 back as `isolated`. Editing a session-scoped job would silently retarget it away from the intended session.
  - confidence: 0.9
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-184`
  - body: The verbose dropdown sends `none`/`low`/`high`, but the server normalizer accepts `off`/`on`/`full`. These updates will be rejected or ignored, so users cannot reliably change verbose behavior from the Linux app.
  - confidence: 0.88
- **[P2] Send null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-150`
  - body: The default model choice stores `NULL`, but the mutation helper only emits `model` when the pointer is non-NULL. Selecting the default therefore cannot clear an existing per-session model override, even though the gateway schema accepts `model: null`.
  - confidence: 0.87
- **[P3] Add Linux app labeler coverage:** `apps/linux/README.md:1`
  - body: This PR introduces a new app surface under `apps/linux`, but `.github/labeler.yml` has no Linux app rule. Add matching labeler coverage so future Linux app changes are routed like Android, iOS, macOS, and web UI changes.
  - confidence: 0.82
