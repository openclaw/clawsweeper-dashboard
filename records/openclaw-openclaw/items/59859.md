## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: This edit path always sends `patch.schedule` as `{ kind: "cron", expr: ... }`, but current cron jobs may be `at`, `every`, or `on-exit`. Saving an unrelated edit to one of those jobs will rewrite or invalidate its schedule instead of preserving the existing variant.
  - confidence: 0.91
- **[P1] Keep session-scoped cron targets:** `apps/linux/src/test_seams.c:47`
  - body: Valid cron targets include `session:<id>`, but this mapper treats every unknown value as the New Session row, which saves back as `isolated`. Editing a session-scoped job therefore retargets it away from its intended session even when the target was not changed.
  - confidence: 0.9
- **[P2] Send valid verbose levels to sessions.patch:** `apps/linux/src/section_sessions.c:176-184`
  - body: The verbose selector sends `none`, `low`, and `high`, but `sessions.patch` validates verboseLevel through the current `off`/`on`/`full` contract. These updates will be rejected, so users cannot change verbose mode from the Linux app.
  - confidence: 0.88
- **[P2] Resolve local logs from sessionId paths:** `apps/linux/src/section_sessions.c:266`
  - body: The local log probe uses `<store-dir>/<session-key>/transcript.jsonl`, while current transcript resolution is based on `sessionId`/`sessionFile` direct files under the sessions directory. This makes the advertised local-first log opening miss normal transcripts and fall back to the dashboard.
  - confidence: 0.84
- **[P2] Read channel account labels from name:** `apps/linux/src/gateway_data.c:262`
  - body: Channel account snapshots expose their friendly label as `name`, but this parser reads `displayName`. Normal `channels.status` responses will lose account labels and show account ids instead.
  - confidence: 0.86
