## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Preserve non-cron schedules when editing jobs:** `apps/linux/src/section_cron.c:270-275`
  - body: The edit save path always sends `schedule.kind = "cron"` with `expr`, so saving an existing `every`, `at`, or `on-exit` job rewrites or rejects its schedule even when the user only edits metadata. Carry the original schedule variant through the dialog or omit `schedule` unless it is explicitly changed.
  - confidence: 0.95
- **[P1] Preserve session-scoped cron targets:** `apps/linux/src/test_seams.c:42-47`
  - body: Valid `session:<id>` cron targets are treated as unknown, selected as the fallback row, and then saved back as `isolated`. That silently retargets session-bound jobs during ordinary edits, so the UI needs to preserve unsupported-but-valid target values or avoid patching them.
  - confidence: 0.94
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:175-184`
  - body: The sessions verbose combo sends `none`, `low`, and `high`, but `sessions.patch` parses verbose overrides through the current `off`/`on`/`full` contract. These requests are rejected, so users cannot successfully change verbose behavior from this UI path.
  - confidence: 0.93
- **[P2] Send null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-151`
  - body: Selecting the default model row passes `NULL`, and `mutation_sessions_patch` then omits `model` entirely. The server treats omitted as no change and explicit JSON null as clear-to-default, so the UI cannot remove an existing session model override.
  - confidence: 0.92
- **[P3] Add Linux app labeler coverage:** `apps/linux/README.md:1-3`
  - body: This PR introduces `apps/linux/**`, but `.github/labeler.yml` only labels Android, iOS, macOS, and web UI app surfaces. Add a Linux app label entry so future Linux companion changes receive the expected area routing.
  - confidence: 0.88
