## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274`
  - body: `CronJobPatchSchema` accepts `at`, `every`, `cron`, and `on-exit` schedules, but this edit path always sends `schedule.kind = "cron"` with `expr`. Opening an existing `every`/`at`/`on-exit` job and saving even an unrelated metadata change can rewrite the schedule or fail validation. Preserve the original schedule variant unless the user explicitly changes it.
  - confidence: 0.93
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/test_seams.c:47`
  - body: The gateway accepts cron targets like `session:<id>`, but this mapper treats any unrecognized value as index 0 and the save path serializes that back as `isolated`. Editing a job bound to a specific session can silently retarget it away from that session. Represent session-scoped targets or omit `sessionTarget` when unchanged.
  - confidence: 0.92
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-178`
  - body: The session patch parser accepts verbose values `off`, `on`, `full`, or `null`, but the Linux combo sends `none`, `low`, and `high`. Those updates are rejected by the gateway, so changing verbose behavior from this UI path does not work. Map the combo to the current contract and update the request-shape test accordingly.
  - confidence: 0.91
- **[P2] Emit null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-150`
  - body: The UI represents “Session default” as a NULL model id, but `mutation_sessions_patch` only writes the `model` field when the pointer is non-NULL. Since the gateway schema uses explicit `model: null` to clear a saved override, selecting the default sends no change and leaves the override in place. Track clear-model intent separately and serialize JSON null.
  - confidence: 0.9
- **[P3] Add Linux app labeler coverage:** `.github/labeler.yml:200-206`
  - body: Root policy requires new app surfaces to update `.github/labeler.yml` and GitHub labels, but the app labeler block only covers Android, iOS, macOS, and web-ui. Without an `app: linux` rule for `apps/linux/**` and the Linux docs path, future Linux companion changes will miss the intended routing label.
  - confidence: 0.86
