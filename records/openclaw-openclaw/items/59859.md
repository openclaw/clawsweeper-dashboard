## Review Findings

Overall confidence: 0.9

Full review comments:

- **[P1] Preserve cron schedule variants on edit:** `apps/linux/src/section_cron.c:274-276`
  - body: The edit path always rebuilds `patch.schedule` as `{kind:"cron", expr}` even when `cron.list` returns `every`, `at`, or `on-exit` schedules. Saving an unrelated edit from the Linux UI can rewrite or invalidate existing jobs instead of preserving their current schedule shape.
  - confidence: 0.96
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/test_seams.c:47`
  - body: `sessionTarget` values like `session:<id>` are valid gateway cron targets, but this mapper sends any unknown target through index 0 and then serializes it as `isolated`. Editing a session-scoped job retargets it away from its session even when the user changes another field.
  - confidence: 0.95
- **[P2] Send valid verbose override values:** `apps/linux/src/section_sessions.c:176-184`
  - body: The sessions UI sends `none`/`low`/`high` for `verboseLevel`, while the gateway parser only accepts `off`/`on`/`full`. These patches are rejected, so the Linux app cannot update session verbose behavior.
  - confidence: 0.94
- **[P2] Send null when clearing a session model:** `apps/linux/src/gateway_mutations.c:148-150`
  - body: Selecting the default model passes NULL into `mutation_sessions_patch`, but that helper omits the `model` member when the pointer is NULL. The gateway clears an override only when `model: null` is present, so this UI path cannot clear a saved session model override.
  - confidence: 0.94
- **[P3] Add labeler coverage for the Linux app:** `.github/labeler.yml:200-206`
  - body: Root policy requires new app surfaces to update `.github/labeler.yml`, but current labeler rules cover Android, iOS, macOS, and web UI only. Without an `apps/linux/**` rule, future Linux app changes will miss app-area routing.
  - confidence: 0.88
