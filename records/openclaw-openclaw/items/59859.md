## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve non-cron schedules when saving edits:** `apps/linux/src/section_cron.c:270-275`
  - body: The edit path always sends `schedule.kind = "cron"` and writes the textbox into `expr`. Current cron jobs may be `at`, `every`, `cron`, or `on-exit`, so saving an existing non-cron job from the Linux UI can rewrite its schedule shape or fail validation even when the user only edits metadata.
  - confidence: 0.95
- **[P1] Preserve session-scoped cron targets:** `apps/linux/src/section_cron.c:351-352`
  - body: The edit dialog maps the current target through a fixed combo and serializes the selected index back to `isolated`/`main`/`current`. Valid `session:<id>` targets are not represented, so opening and saving such a job silently retargets it away from the intended session.
  - confidence: 0.92
- **[P2] Send supported verbose levels:** `apps/linux/src/section_sessions.c:175-184`
  - body: The Linux sessions UI sends `none`, `low`, or `high` as `verboseLevel`, but the Gateway parser accepts only `off`, `on`, `full`, null, or omission. These updates are rejected at runtime, so the Verbose selector cannot actually change session verbose behavior.
  - confidence: 0.96
- **[P2] Send explicit null when clearing the model:** `apps/linux/src/gateway_mutations.c:148-151`
  - body: Selecting the Default model passes `NULL`, but this helper omits `model` when the pointer is null. Gateway sessions.patch uses explicit `model: null` to clear a stored override and omission as no change, so the Default selection cannot reset an existing model override.
  - confidence: 0.94
- **[P2] Resolve local logs from session IDs:** `apps/linux/src/section_sessions.c:264-266`
  - body: This local transcript probe builds `<store-dir>/<session-key>/transcript.jsonl`, while Gateway transcript files are resolved from `sessionId`/`sessionFile` candidates such as `<sessionsDir>/<sessionId>.jsonl`. In normal installs the Log button misses existing local transcripts and falls back to the dashboard unnecessarily.
  - confidence: 0.88
- **[P2] Bracket IPv6 hosts before composing URLs:** `apps/linux/src/gateway_config.c:1153-1155`
  - body: `gateway_config_dashboard_url` interpolates `config->host` directly into `scheme://host:port`. For IPv6 literals like `::1`, this produces malformed URLs such as `http://::1:18789/`, breaking dashboard and transcript handoffs for IPv6-based setups.
  - confidence: 0.88
- **[P3] Add Linux app labeler coverage:** `.github/labeler.yml:139-147`
  - body: Root policy requires new app surfaces to update labeler routing, but the new `apps/linux/**` tree has no `app: linux` entry. As submitted, Linux app PRs are mislabeled as web UI/gateway work instead of routing to a Linux app surface.
  - confidence: 0.87
