## Review Findings

Overall correctness: not a patch

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: The edit save path always sends `schedule.kind = "cron"`, so opening an existing `every`, `at`, or `on-exit` job and saving unrelated fields rewrites the schedule shape or fails validation. Preserve the original schedule variant unless the user explicitly changes the schedule type.
  - confidence: 0.94
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/test_seams.c:47`
  - body: Valid cron targets include `session:<id>`, but this mapping treats any unrecognized target as index 0, which the save path serializes as `isolated`. Editing an existing session-scoped job can silently retarget future runs away from the intended session.
  - confidence: 0.92
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-178`
  - body: The UI sends `none`, `low`, and `high` as `verboseLevel`, but `sessions.patch` only accepts the on/off/full family. Verbose changes from the Linux Sessions view will be rejected by the gateway until the dropdown maps to supported values.
  - confidence: 0.91
- **[P2] Send null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-150`
  - body: Selecting the default model produces a null pointer, but `mutation_sessions_patch` omits the `model` field instead of sending JSON null. Since the gateway uses `model: null` to clear a saved override, users cannot return a session to the default model from this UI.
  - confidence: 0.9
- **[P3] Add Linux app labeler coverage:** `apps/linux/README.md:1`
  - body: Adding a first-class `apps/linux/**` surface should also add a matching `app: linux` labeler rule; otherwise future Linux-only changes are mislabeled or missed by app-owner triage.
  - confidence: 0.86
