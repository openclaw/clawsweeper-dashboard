Overall correctness: patch is incorrect

Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: The edit save path always sends `schedule.kind: "cron"` with an `expr`, so saving an existing `every` or `at` job from this UI rewrites the schedule shape even when the user only changes metadata. Keep the original schedule variant unless the UI explicitly supports changing it.
  - confidence: 0.93
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/test_seams.c:42-48`
  - body: `session:*` is a valid cron target, but this mapper treats unknown values as index 0 and later serializes that back to `isolated`. Editing a session-scoped job will silently retarget it away from its intended session.
  - confidence: 0.91
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-178`
  - body: The gateway parser accepts `off`, `on`, `full`, or `null` for `verboseLevel`, but this UI sends `none`, `low`, and `high`. Verbose updates from the Linux app will be rejected until the dropdown maps to the gateway contract.
  - confidence: 0.92
- **[P2] Send null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-151`
  - body: Selecting the default model row produces a null model pointer, but `mutation_sessions_patch` omits the field instead of sending JSON null. Because the gateway clears model overrides only when `model` is present and null, users cannot return a session to the default model from this UI.
  - confidence: 0.9
- **[P3] Add Linux app labeler coverage:** `.github/labeler.yml:200-208`
  - body: This PR adds a new `apps/linux` surface, but the labeler still only routes Android, iOS, macOS, and web UI app changes. Add an app labeler entry for Linux so follow-up changes get the right ownership and triage labels.
  - confidence: 0.86
