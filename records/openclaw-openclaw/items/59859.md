## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: The edit save path always serializes `schedule.kind = "cron"` with `expr`, so saving an existing `every`, `at`, or `on-exit` job rewrites or invalidates its schedule even when the user edits unrelated metadata. Preserve the original schedule variant unless the UI explicitly changes it.
  - confidence: 0.93
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/section_cron.c:351-352`
  - body: Valid cron targets include `session:<id>`, but the combo maps unrepresented targets through a built-in selection and later saves that back. Editing a session-scoped job can silently retarget it away from the intended session.
  - confidence: 0.91
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-184`
  - body: The verbose selector sends `none`/`low`/`high`, while the server normalizer accepts `off`/`on`/`full`; session verbose updates from this UI path fail validation or get ignored.
  - confidence: 0.9
- **[P2] Send null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-150`
  - body: The default model choice passes `NULL`, but the helper omits `model` whenever the pointer is null. Since `sessions.patch` uses `model: null` to clear overrides, selecting Default cannot clear an existing session model override.
  - confidence: 0.89
- **[P3] Add Linux app labeler coverage:** `apps/linux/README.md:1`
  - body: This PR adds a new app surface under `apps/linux`, but current labeler rules only cover Android, iOS, macOS, and web UI. Add Linux app labeler coverage so future changes route consistently.
  - confidence: 0.82
