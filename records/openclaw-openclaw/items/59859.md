Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: Saving an edited job always sends `schedule.kind = "cron"` with `expr`, regardless of the existing schedule variant. Current gateway cron jobs can be `at`, `every`, `cron`, or `on-exit`, so a metadata-only edit can rewrite or invalidate non-cron jobs.
  - confidence: 0.92
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/test_seams.c:42-47`
  - body: Unknown targets, including valid `session:<id>` cron targets, map to index 0 and save back as `isolated`. Editing a job with a session-scoped target can silently move it away from the intended session.
  - confidence: 0.91
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-184`
  - body: The verbose dropdown sends `none`/`low`/`high`, but `sessions.patch` accepts normalized verbose values `off`/`on`/`full`. Those UI updates will be rejected instead of changing the session verbose setting.
  - confidence: 0.89
- **[P2] Emit null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-150`
  - body: Selecting the default model row passes a NULL model into `mutation_sessions_patch`, but that helper omits the `model` field whenever the pointer is NULL. The server uses explicit null to clear an override, so the old session model can remain set.
  - confidence: 0.86
- **[P3] Add labeler coverage for the Linux app:** `apps/linux/README.md:1`
  - body: This PR introduces `apps/linux/**` as a new app surface, but `.github/labeler.yml` has no Linux app mapping. Add the labeler entry so future Linux companion changes route to the right app label.
