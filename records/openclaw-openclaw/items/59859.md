## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Preserve non-cron schedules when editing jobs:** `apps/linux/src/section_cron.c:274-275`
  - body: The edit save path always sends `schedule.kind: "cron"` with an `expr`, but current cron jobs can be `at`, `every`, `cron`, or `on-exit`. Saving an existing non-cron job after an unrelated edit can rewrite or invalidate when it runs, so carry the original schedule variant or block unsupported edits.
  - confidence: 0.93
- **[P2] Preserve session-scoped cron targets:** `apps/linux/src/test_seams.c:47`
  - body: Unknown targets map to the `New Session` index and are later serialized as `isolated`, but valid gateway cron targets include `session:<id>`. Editing a session-scoped job would silently retarget it away from the intended session.
  - confidence: 0.89
- **[P2] Resolve local logs from session IDs:** `apps/linux/src/section_sessions.c:264-266`
  - body: This local transcript probe builds `<storeDir>/<session-key>/transcript.jsonl`, while the gateway resolver uses the session id and optional session file under the sessions directory. The PR already parses `sessionId`, so using the key here will usually miss existing local transcripts and fall back to the dashboard or fail offline.
  - confidence: 0.9
- **[P2] Bracket IPv6 hosts before composing URLs:** `apps/linux/src/gateway_config.c:1034-1040`
  - body: `config->host` can be an IPv6 literal from `gateway.host` or `customBindHost`, but these URL builders interpolate it directly as `%s://%s:%d`. That produces malformed URIs like `http://::1:18789` for health, WebSocket, and dashboard handoffs.
  - confidence: 0.88
