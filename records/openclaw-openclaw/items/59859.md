## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.83

Full review comments:

- **[P1] Preserve non-cron schedules when editing jobs:** `apps/linux/src/section_cron.c:274-275`
  - body: The branch parses `schedule.kind`, but the edit save path always sends a cron patch. Saving an existing `every` or `at` job from the Linux app can rewrite its schedule shape or fail validation even when the user only edits metadata; preserve the original schedule variant or make unsupported variants read-only.
  - confidence: 0.91
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/test_seams.c:42-47`
  - body: Valid cron targets include `session:<id>`, but this mapper treats every unknown target as index 0, which later serializes as `isolated`. Editing a session-scoped job will silently retarget it away from its intended session; preserve `session:<id>` or avoid saving `sessionTarget` when unchanged.
  - confidence: 0.9
- **[P2] Send supported verbose levels:** `apps/linux/src/section_sessions.c:176-178`
  - body: The Linux session dropdown sends `none`/`low`/`high`, but the gateway normalizes verbose overrides as `off`/`on`/`full`. These updates will be rejected by `sessions.patch`, so map the UI values to the accepted contract before dispatch.
  - confidence: 0.92
- **[P2] Serialize null when clearing model overrides:** `apps/linux/src/gateway_mutations.c:148-150`
  - body: Selecting the default model resolves to a NULL model id, but the mutation helper omits the `model` field entirely. The server only clears overrides when `model: null` is present, so the default selection becomes a no-op for sessions with an override.
  - confidence: 0.88
- **[P3] Add labeler coverage for the Linux app:** `.github/labeler.yml:139-148`
  - body: This PR adds a new app surface under `apps/linux`, but `.github/labeler.yml` still has no Linux app label mapping. Add an `apps/linux/**` route so future companion changes are not misrouted as only web UI or gateway work.
  - confidence: 0.82
