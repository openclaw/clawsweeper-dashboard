## Review Findings

Overall correctness: not a patch

Overall confidence: 0.9

Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: When saving an edited job, this path always builds `schedule_kind = "cron"` and the mutation helper serializes only `{kind, expr}`. Current gateway jobs can use `at`, `every`, `cron`, or `on-exit` schedules, so opening and saving a non-cron job can rewrite, reject, or change its schedule even if the user only edits metadata. Preserve the original schedule variant and fields unless the UI explicitly changes schedule type.
  - confidence: 0.94
- **[P1] Preserve session-scoped cron targets:** `apps/linux/src/test_seams.c:42-48`
  - body: `session:<id>` is a valid `CronSessionTarget`, but this mapper treats every unknown target as index 0; the edit save path maps index 0 back to `isolated`. Editing a session-scoped job can therefore silently retarget it away from the intended session. Keep session-scoped targets round-trippable or make them read-only unless the user chooses a replacement.
  - confidence: 0.93
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:175-184`
  - body: The sessions verbose dropdown sends `none`, `low`, and `high`, but `sessions.patch` validates verbose overrides as `off`, `on`, or `full`. These updates will be rejected at runtime, so users cannot change session verbose behavior from the Linux app until the mapping uses the gateway-supported values.
  - confidence: 0.92
- **[P2] Send null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-151`
  - body: The default model row stores `NULL`, but `mutation_sessions_patch` omits the `model` member whenever the pointer is null. The gateway clears an override only when the patch explicitly contains `model: null`, so selecting the default row becomes a no-op and cannot clear a previous session model override.
  - confidence: 0.9
- **[P3] Add Linux app labeler coverage:** `.github/labeler.yml:184-209`
  - body: This PR creates a new `apps/linux/**` app surface, but the app labeler still only routes Android, iOS, macOS, and web UI paths. Add a Linux app label route, and the matching label if maintainers choose that name, so future Linux companion changes get owner-visible routing.
  - confidence: 0.86
