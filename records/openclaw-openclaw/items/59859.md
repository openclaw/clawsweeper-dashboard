## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: The edit path always serializes the saved schedule as `{ kind: "cron", expr: ... }`. Jobs created as `every` or `at` can be rewritten or rejected even when the user only edits metadata, so preserve the original schedule variant unless the user explicitly changes schedule type.
  - confidence: 0.94
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/section_cron.c:351-352`
  - body: Valid cron targets can be `session:<id>`, but this combo maps unknown targets to index 0 and later saves that as `isolated`. Editing an existing session-scoped job can silently retarget it away from the intended session.
  - confidence: 0.92
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-184`
  - body: The session verbose control sends `none`/`low`/`high`, while the gateway parser accepts `off`/`on`/`full`. These updates will fail validation instead of changing the session's verbose behavior.
  - confidence: 0.91
- **[P2] Send null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-150`
  - body: Choosing the default model stores a null local value, but `mutation_sessions_patch` omits the `model` field whenever it is null. The gateway needs `model: null` to clear an existing override, so users cannot reset a session back to the default model from this UI.
  - confidence: 0.89
- **[P3] Add Linux app labeler coverage:** `apps/linux/README.md:1`
  - body: This PR creates a new top-level app surface under `apps/linux`, but the labeler rules do not include that path. Future Linux app changes will not get the expected app label routing required for new app surfaces.
  - confidence: 0.83
