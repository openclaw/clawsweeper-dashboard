## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: Editing a job always sends `schedule.kind: "cron"` with `expr`, so saving an existing `every`, `at`, or `on-exit` job rewrites or invalidates its schedule even when the user only edits metadata. The patch needs to keep the original schedule variant unless the UI explicitly changes it.
  - confidence: 0.93
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/test_seams.c:42-48`
  - body: `session:<id>` is a valid cron target on main, but this mapping treats unknown targets as index 0 and the edit save path converts that back to `isolated`. Editing a session-scoped job can silently retarget it away from the intended session.
  - confidence: 0.9
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-184`
  - body: The Sessions verbose selector sends `none`, `low`, and `high`, but `sessions.patch` parses verbose overrides as `off`, `on`, or `full`. These updates are rejected by the gateway, so users cannot change verbose behavior from the Linux app.
  - confidence: 0.91
- **[P2] Emit null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-150`
  - body: The default model row stores `NULL`, but `mutation_sessions_patch` omits the `model` member when the value is null. Current gateway code clears the override only when `model: null` is present, so choosing the default model sends a no-op instead of clearing the saved override.
  - confidence: 0.88
- **[P3] Add Linux app labeler coverage:** `.github/labeler.yml:200-208`
  - body: Root policy requires new app surfaces to update `.github/labeler.yml` and GitHub labels, but this PR adds `apps/linux/**` without an `app: linux` labeler entry. Maintainers will lose automatic routing for future Linux app changes.
  - confidence: 0.86
