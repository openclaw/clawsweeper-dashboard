## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Preserve non-cron schedules on edit:** `apps/linux/src/section_cron.c:270-275`
  - body: The edit path always sends `patch.schedule` as `{kind:"cron", expr:...}`. Current cron jobs can be `at`, `every`, `cron`, or `on-exit`, so saving an existing non-cron job from this UI can rewrite or reject its schedule even when the user edits unrelated fields.
  - confidence: 0.94
- **[P1] Keep session-scoped cron targets on edit:** `apps/linux/src/section_cron.c:264-266`
  - body: The edit dialog reduces `sessionTarget` to a four-option combo and then serializes the selected index back through `session_target_from_index`. Valid targets include `session:<id>`, so editing a session-scoped job can silently retarget it to a generic target.
  - confidence: 0.9
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:175-184`
  - body: The sessions UI sends `none`, `low`, and `high` as `verboseLevel`, but the gateway parser accepts `off`, `on`, and `full`. Verbose changes from the Linux app will be rejected instead of updating the session.
  - confidence: 0.95
- **[P2] Send explicit null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-151`
  - body: Selecting the default model passes `NULL`, and `mutation_sessions_patch` omits the `model` member when it is null. The gateway uses `model: null` to clear a stored override, so this path becomes a no-op and users cannot return a session to inherited model selection.
  - confidence: 0.9
- **[P3] Add Linux app labeler coverage:** `.github/labeler.yml:184-208`
  - body: This PR adds a new `apps/linux/**` app surface, but `.github/labeler.yml` still only routes android, ios, macos, and web-ui app changes. Future Linux app PRs will miss the app label required by the repo routing policy.
  - confidence: 0.86
- **[P2] Bracket IPv6 hosts before composing dashboard URLs:** `apps/linux/src/gateway_config.c:1151-1155`
  - body: `gateway_config_dashboard_url` interpolates `config->host` directly into `scheme://host:port`. IPv6 literals such as `::1` produce invalid URLs like `http://::1:18789/`, breaking dashboard and log handoffs for reachable IPv6 gateway configs.
  - confidence: 0.83
