## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Preserve cron schedule variants when editing jobs:** `apps/linux/src/section_cron.c:274-275`
  - body: The edit save path always serializes `patch.schedule` as `kind: cron`, but Gateway cron jobs can be `at`, `every`, `cron`, or `on-exit`. Saving an existing non-cron job can therefore fail validation or rewrite when the job runs even if the user only edits metadata.
  - confidence: 0.94
- **[P1] Preserve session cron targets during edits:** `apps/linux/src/section_cron.c:351-352`
  - body: The target combo collapses unrecognized targets to an index that is later saved as `isolated`, while valid Gateway targets include `session:<id>`. Editing a session-scoped cron job can silently retarget it away from the intended session.
  - confidence: 0.93
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-184`
  - body: The Sessions UI sends `none`, `low`, and `high`, but `sessions.patch` accepts verbose overrides as `off`, `on`, `full`, or null. These updates are rejected by Gateway validation, so users cannot change verbose behavior from the Linux app.
  - confidence: 0.91
- **[P2] Send null when clearing the session model:** `apps/linux/src/section_sessions.c:205-206`
  - body: Selecting the default model passes NULL, and the mutation helper omits `model` when the pointer is null. Gateway only clears an existing model override when `model: null` is explicitly present, so this UI path leaves the old override in place.
  - confidence: 0.9
- **[P3] Add Linux app labeler coverage:** `apps/linux/meson.build:11`
  - body: This PR adds a new `apps/linux` surface, but labeler routing still covers only the existing Android, iOS, macOS, and web app surfaces. Root policy requires new app surfaces to update label routing, so future Linux PRs would miss the correct app label.
  - confidence: 0.82
