## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Preserve existing cron schedule variants:** `apps/linux/src/section_cron.c:274-275`
  - body: The edit save path always builds `schedule.kind = "cron"` from the textbox. Current gateway cron jobs can be `at`, `every`, `cron`, or `on-exit`, so saving an existing non-cron job from this UI rewrites or invalidates its schedule even when the user edits only metadata.
  - confidence: 0.94
- **[P1] Preserve session-scoped cron targets:** `apps/linux/src/test_seams.c:42-47`
  - body: Valid cron targets include `session:<id>`, but the combo helper maps any unknown target to index 0 and the save path sends that back as `isolated`. Editing a session-scoped job therefore silently retargets it away from the intended session.
  - confidence: 0.92
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-184`
  - body: The verbose dropdown emits `none`, `low`, and `high`, while the gateway normalizes only `off`, `on`, and `full` for `sessions.patch.verboseLevel`. Selecting these Linux values is rejected by the server, so the UI cannot update verbose behavior reliably.
  - confidence: 0.91
- **[P2] Send null when clearing the session model:** `apps/linux/src/gateway_mutations.c:148-151`
  - body: The default model row stores a NULL model id, but `mutation_sessions_patch` only serializes `model` when the pointer is non-NULL. Selecting the default row therefore sends no model field, leaving the existing model override in place instead of clearing it with `model: null`.
  - confidence: 0.9
- **[P3] Add Linux app labeler coverage:** `.github/labeler.yml:200-208`
  - body: This PR introduces a new `apps/linux` application surface, but the repository labeler still has app rules for Android, iOS, macOS, and web-ui only. Add an `app: linux` rule for `apps/linux/**` so future companion changes route correctly.
  - confidence: 0.88
