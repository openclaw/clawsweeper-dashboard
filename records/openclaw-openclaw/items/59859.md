## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.84

Full review comments:

- **[P1] Preserve existing cron schedule and target shape:** `apps/linux/src/section_cron.c:270-276`
  - body: The edit save path always writes a cron schedule and combo-derived sessionTarget, but current jobs can be at/every/on-exit and can target session:<id>. Saving an unrelated edit can therefore fail validation or rewrite when the job runs; preserve unsupported schedule/target variants or block editing them.
  - confidence: 0.9
- **[P2] Send supported verbose override values:** `apps/linux/src/section_sessions.c:176-184`
  - body: The Sessions verbose combo sends none/low/high, but sessions.patch accepts off/on/full through parseVerboseOverride. These updates will be rejected at runtime, so users cannot change verbose behavior from the Linux app.
  - confidence: 0.92
- **[P2] Let empty skill secret updates reach the gateway:** `apps/linux/src/section_skills.c:133-134`
  - body: Returning on an empty entry prevents sending the backend's delete signal for apiKey/env values. The gateway treats empty strings as credential cleanup, so stale API keys and env overrides cannot be cleared from this UI.
  - confidence: 0.91
- **[P2] Require an install option before skills.install:** `apps/linux/src/section_skills.c:88`
  - body: on_install can call mutation_skills_install with a null installId, and the helper omits installId in that case. The current legacy skills.install schema requires a non-empty installId, so the button can send an invalid request and appear to no-op.
  - confidence: 0.86
