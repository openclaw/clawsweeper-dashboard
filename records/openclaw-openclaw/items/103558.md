## Summary

Keep open, but narrow the direction: current main already supports configured model allowlisting, direct aliases, per-model parameters, session-only Telegram switching, active marking, and explicit scope confirmation; it does not render user-defined aliases as an ordered one-screen picker or define a safe contract for bundling auth, fallback, reasoning, and runtime settings. Likely related people: steipete (high confidence), bugkill3r (high confidence), and Takhoffman (medium confidence).

## What This Changes

Requests named, configurable LLM profiles that can be switched per Telegram session through a curated button and command interface.

## Best Possible Solution

Add the smallest generic curated-selection layer—preferably ordered user-facing display metadata on existing configured model entries—and expose it through portable model actions, while continuing to persist canonical provider/model session overrides; defer multi-setting profile bundles until a separate cross-runtime contract is approved.
