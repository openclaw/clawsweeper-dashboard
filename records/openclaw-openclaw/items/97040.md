## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Gate the Herdr sidecar through plugin enablement:** `src/tui/tui.ts:529-534`
  - body: This PR adds `herdr-state` as a bundled plugin, but `runTui()` starts the sidecar from `HERDR_PANE_ID` before config is loaded and never checks the plugin activation decision. That means `plugins.enabled=false`, `plugins.deny`, an allowlist, or `plugins.entries.herdr-state.enabled=false` cannot disable the behavior even though the manifest declares a default-on plugin. Please either gate startup through resolved plugin policy or make the feature explicitly core-owned instead of presenting it as plugin-owned.
  - confidence: 0.9
- **[P2] Match pane-gone errors without the command line:** `src/tui/herdr-state-sidecar.ts:42`
  - body: `execFile` rejection messages include the invoked command, so a transient `herdr pane read` or `report-agent` failure can satisfy this regex before stderr proves the pane is gone. This was visible in the earlier reviewed head too; please match a narrower Herdr diagnostic such as `pane not found` from stderr/stdout so transient CLI failures warn and retry instead of permanently stopping the bridge.
  - late: true
  - confidence: 0.82
