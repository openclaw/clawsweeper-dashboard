## Summary

This request is still necessary: current Control UI documentation exposes browser Web Push subscription and a manual test notification, but not an automatic notification when the initiating chat run reaches a terminal outcome. The narrowest fit is an opt-in Control UI preference rather than a new general Gateway notification policy.

Likely related people: BunsDev is a medium-confidence recent Control UI/chat routing candidate; steipete is a low-confidence adjacent Web Push routing candidate.

## What This Changes

Request an optional browser notification when a long-running Control UI chat response completes.

## Best Possible Solution

Add a browser-local, opt-in Control UI preference that notifies only for terminal outcomes of runs initiated by that browser, suppresses alerts while the relevant chat is visible, and reuses the existing Web Push/service-worker path; keep inbound-channel notifications as a separately designed trigger.
