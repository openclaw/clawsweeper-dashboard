## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Use promptCacheKey for ZAI cache affinity:** `extensions/zai/stream.ts:34-42`
  - body: This wrapper always copies `options.sessionId` into `X-Session-Id`. Current main keeps `promptCacheKey` separate from transcript/session identity, and the embedded-runner tests cover stable cache keys across rotating session ids, so recurring runs can send the wrong ZAI affinity key and miss the intended sticky-cache behavior.
  - confidence: 0.88
- **[P2] Replace x-session-id variants before injecting:** `extensions/zai/stream.ts:40-42`
  - body: Spreading `options.headers` before adding `X-Session-Id` leaves an existing `x-session-id` key in place. Header normalization is case-insensitive and combines those as `old, new`, so ZAI may receive a malformed or non-sticky routing key.
  - confidence: 0.93
- **[P2] Reject invalid header values before injection:** `extensions/zai/stream.ts:21`
  - body: `isInjectableSessionId` accepts non-empty strings that are not valid HTTP header values, such as a value containing NUL. When that reaches `Headers`/`Request`, construction throws before the ZAI request is sent, so the wrapper needs real header-value validation before setting `X-Session-Id`.
  - confidence: 0.84
- **[P3] Drop the release-owned changelog edit:** `CHANGELOG.md:21`
  - body: Normal PRs should not edit `CHANGELOG.md`; release generation owns that file. Keep the release-note context in the PR body or squash message and remove this direct changelog change.
  - confidence: 0.95
