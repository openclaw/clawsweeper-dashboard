Overall correctness: patch is incorrect

Full review comments:

- **[P1] Use an opaque affinity key for X-Session-Id:** `extensions/zai/stream.ts:34`
  - body: Current main carries `promptCacheKey` as provider prompt-cache affinity distinct from transcript/session identity, and isolated cron hashes that key specifically to avoid sending raw local session labels upstream. This wrapper ignores that contract and sends `options.sessionId` directly to ZAI, so the provider receives raw OpenClaw session identifiers even when an opaque affinity key is available.
  - confidence: 0.89
- **[P2] Reject invalid header values before injection:** `extensions/zai/stream.ts:21`
  - body: `isInjectableSessionId` accepts any non-empty trimmed string, including `\r`/`\n`. Node's `Headers` rejects those values before dispatch, so a caller-provided session id that was previously harmless can now fail ZAI requests immediately.
  - confidence: 0.96
- **[P2] Replace existing session headers before setting the new one:** `extensions/zai/stream.ts:40-42`
  - body: Spreading `options.headers` and then adding `X-Session-Id` leaves an existing `x-session-id` key in place. Header normalization is case-insensitive and combines those into a comma-joined value, which can defeat sticky routing or be rejected by the provider.
  - confidence: 0.95
- **[P3] Drop the release-owned changelog entry:** `CHANGELOG.md:21`
  - body: Root policy says `CHANGELOG.md` is release-owned and normal PRs should carry release-note context in the PR body or squash message instead. This direct changelog edit should be removed before merge.
  - confidence: 0.87
