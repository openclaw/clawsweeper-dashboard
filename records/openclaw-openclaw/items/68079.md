## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Use an opaque affinity key for the provider header:** `extensions/zai/stream.ts:43`
  - body: `sessionId` is documented as session identity, with `promptCacheKey` kept distinct for provider cache affinity. Sending the raw value as `X-Session-Id` exposes OpenClaw session identity to ZAI on every request, so this needs an approved opaque provider-affinity value or an explicit maintainer decision before merge.
  - confidence: 0.89
- **[P2] Replace existing session headers case-insensitively:** `extensions/zai/stream.ts:41-43`
  - body: If `options.headers` already contains `x-session-id`, this spread leaves both casings in the object and `Headers` normalizes them into a comma-joined value such as `old, new`. That can break sticky routing or be rejected by ZAI, so remove any existing `x-session-id` key case-insensitively before setting the provider value.
  - confidence: 0.92
- **[P2] Reject header-invalid session IDs before injection:** `extensions/zai/stream.ts:17-20`
  - body: `isInjectableSessionId` accepts any non-empty string under the length cap, including `\r`, `\n`, or NUL characters. Fetch/Undici rejects those header values with `TypeError`, turning a valid ZAI call into a pre-dispatch failure once this wrapper injects the value.
  - confidence: 0.91
- **[P3] Drop the release-owned changelog edit:** `CHANGELOG.md:21`
  - body: OpenClaw release generation owns `CHANGELOG.md`; normal PRs should keep release-note context in the PR body or squash message. This direct edit will create release-note churn and should be removed from the branch.
