Full review comments:

- **[P1] Use an opaque affinity key for the provider header:** `extensions/zai/stream.ts:42`
  - body: This copies raw `options.sessionId` into a new provider-facing `X-Session-Id` header. Agent session IDs are stable OpenClaw identifiers, so this needs either an explicit maintainer-approved ZAI privacy contract or an opaque bounded affinity key before it is sent to the provider by default.
  - confidence: 0.86
- **[P2] Replace existing session headers case-insensitively:** `extensions/zai/stream.ts:40-42`
  - body: Spreading `options.headers` and then adding `X-Session-Id` leaves an existing `x-session-id` key in place. Fetch `Headers` normalizes those into one comma-joined value, which can defeat stickiness or trigger provider rejection; remove any existing session-id header case-insensitively before setting the ZAI value.
  - confidence: 0.91
- **[P2] Reject invalid header values before injection:** `extensions/zai/stream.ts:21`
  - body: `isInjectableSessionId` accepts non-empty strings with control characters, but Fetch/Undici rejects values such as `abc\nxyz` when headers are normalized. Validate against the HTTP header value contract before copying `sessionId` into `X-Session-Id`.
  - confidence: 0.9
- **[P1] Rebase without dropping GLM-5.2 reasoning effort:** `extensions/zai/index.ts:137-154`
  - body: The PR head's `wrapZaiStreamFn` only handles disabled/preserved thinking, while current main also maps GLM-5.2 thinking levels to `reasoning_effort`; GitHub reports the branch dirty. Rebase this wrapper so the new header layer composes with, rather than replaces, the current GLM-5.2 behavior.
  - confidence: 0.82
- **[P3] Drop the release-owned changelog edit:** `CHANGELOG.md:18`
  - body: Normal PRs should keep release-note context in the PR body or squash message; release generation owns `CHANGELOG.md`. Remove the direct changelog change from this branch.
  - confidence: 0.88
