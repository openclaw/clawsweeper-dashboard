Full review comments:

- **[P1] Use an approved opaque ZAI affinity key:** `extensions/zai/stream.ts:42`
  - body: This copies the raw OpenClaw `sessionId` into a provider-facing header on every ZAI request. Please either switch to a maintainer-approved opaque affinity key or document explicit maintainer approval for exposing raw session identifiers to ZAI.
  - confidence: 0.85
- **[P2] Replace existing session headers case-insensitively:** `extensions/zai/stream.ts:40-43`
  - body: Spreading existing headers and then adding `X-Session-Id` leaves a caller-provided `x-session-id` in place; Fetch header normalization combines them into a comma-joined value such as `old, new`, which can break sticky routing or be rejected by the provider.
  - confidence: 0.9
- **[P2] Reject invalid header values before injection:** `extensions/zai/stream.ts:18-21`
  - body: The validator accepts control characters, so a session id containing `\n`, `\r`, or NUL reaches `X-Session-Id` and fails during request header construction before the ZAI call is sent. Reject header-invalid values before adding the header.
  - confidence: 0.88
- **[P3] Drop the release-owned changelog edit:** `CHANGELOG.md:19`
  - body: OpenClaw release generation owns `CHANGELOG.md`; normal PRs should keep release-note context in the PR body or squash message instead of editing the generated changelog directly.
  - confidence: 0.95
