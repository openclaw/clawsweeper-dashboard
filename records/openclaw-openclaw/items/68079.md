  - body: This writes `options.sessionId` directly into a third-party provider header for every sessioned ZAI call.   - confidence: 0.87

  - body: The PR head predates current-main ZAI GLM-5.2 thinking support and GitHub reports the branch as dirty/conflicting.   - confidence: 0.84
- **[P2] Reject invalid header values before dispatch:** `extensions/zai/stream.ts:21`
  - body: `isInjectableSessionId` accepts non-empty strings with `\r` or `\n`, but Fetch/Undici header normalization rejects those values before the request is sent. Filter header-invalid control characters before copying the value into `X-Session-Id`.
  - confidence: 0.91
- **[P2] Replace existing session header before injecting:** `extensions/zai/stream.ts:40-42`
  - body: Spreading `options.headers` and then adding `X-Session-Id` can leave an existing `x-session-id` key in the same object. Header normalization treats names case-insensitively and can combine them into `old, new`, breaking the sticky-routing key; remove any existing key case-insensitively before setting the canonical one.
  - confidence: 0.9
- **[P3] Drop the release-owned changelog edit:** `CHANGELOG.md:21`
  - body: Normal PRs should carry release-note context in the PR body or squash message; `CHANGELOG.md` is generated during release. Remove this direct changelog edit so release generation remains the single source of truth.
  - confidence: 0.8
