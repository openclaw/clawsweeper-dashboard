## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Use the prompt-cache affinity key for the provider header:** `extensions/zai/stream.ts:34`
  - body: This wrapper always reads `options.sessionId` and sends it as `X-Session-Id`. Current cache-affinity callers can pass an opaque `promptCacheKey`, and the webchat/cron tests assert those keys do not contain local session labels, so ZAI traffic would leak the raw transcript/session id and ignore the approved affinity key. Resolve the header value from `promptCacheKey` first, falling back only if maintainers explicitly allow raw session ids.
  - confidence: 0.9
- **[P2] Reject invalid header bytes before injection:** `extensions/zai/stream.ts:21`
  - body: `isInjectableSessionId` accepts any non-empty trimmed string, including control characters. Fetch/Undici rejects values such as `abc\nxyz` when headers are normalized, so a caller-provided session id can make an otherwise valid ZAI request fail before dispatch; validate against HTTP header-value rules before setting the header.
  - confidence: 0.91
- **[P2] Replace existing session headers case-insensitively:** `extensions/zai/stream.ts:40-42`
  - body: The merge keeps any existing `x-session-id` from `options.headers` and then adds `X-Session-Id`. Header normalization is case-insensitive and combines those values into `old, new`, which can break sticky routing or provider-side validation; remove or replace existing variants case-insensitively before setting the final header.
  - confidence: 0.89
- **[P1] Rebase over the current ZAI reasoning wrapper:** `extensions/zai/index.ts:154`
  - body: Current main's `wrapZaiStreamFn` includes GLM-5.2 `reasoning_effort` handling, but this PR head is based on the older wrapper and GitHub reports it as conflicting with main. Rebase and compose the session header around the current stream function so the GLM-5.2 thinking behavior is preserved.
  - confidence: 0.86
