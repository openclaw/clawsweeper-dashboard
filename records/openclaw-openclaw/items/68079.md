Full review comments:

- **[P1] Use an approved opaque affinity key:** `extensions/zai/stream.ts:42`
  - body: This forwards the raw OpenClaw `sessionId` to ZAI as a third-party request header by default. `sessionId` is the logical agent/session identity passed through stream options, and the PR has no maintainer-approved privacy contract for exposing that stable identifier; use an approved provider-scoped opaque cache key or make the raw-id policy explicit before merge.
  - confidence: 0.88
- **[P2] Reject header-invalid session IDs:** `extensions/zai/stream.ts:21`
  - body: `isInjectableSessionId` accepts any non-empty trimmed string, so values containing `\r`, `\n`, or other invalid header bytes are copied into `X-Session-Id`. Fetch/Undici rejects newline header values before sending the request, so a malformed caller-provided session id can break otherwise valid ZAI calls.
  - confidence: 0.9
- **[P2] Replace existing session headers case-insensitively:** `extensions/zai/stream.ts:40-42`
  - body: The wrapper spreads existing headers and then adds `X-Session-Id`, leaving an existing `x-session-id` key in place. Header normalization is case-insensitive and can collapse those into a comma-joined value such as `old, new`, which defeats the sticky-routing key or causes provider rejection.
  - confidence: 0.86
- **[P3] Drop the release-owned changelog edit:** `CHANGELOG.md:21`
  - body: Root policy makes `CHANGELOG.md` release-owned for normal PRs. Keep this release-note context in the PR body or squash message and remove the direct changelog change so release generation can own the final entry.
  - confidence: 0.95
