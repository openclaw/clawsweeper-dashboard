## Summary

Keep open. Current main and v2026.6.11 still require users to configure plugin-specific settings separately from installation; the requested setup capability remains useful, but third-party authority to mutate core configuration needs an explicit product and security contract first.

## What This Changes

Requests a plugin-manifest field that automatically applies validated configuration changes during plugin installation.

## Best Possible Solution

Add a constrained plugin setup-intent contract with allowlisted targets, preview and confirmation or skip controls, transactional validation, conflict-specific merge rules, durable provenance, uninstall guidance, and coverage across CLI, Gateway, ClawHub, npm, git, local, include-backed, and immutable-config install paths.
