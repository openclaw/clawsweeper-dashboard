## Summary

Keep open. Current main and v2026.6.11 still lack a general plugin-manifest setup intent that can configure core settings during installation, but unrestricted automatic deep merging would cross plugin trust, user-consent, and configuration-ownership boundaries that require maintainer direction.

## What This Changes

The issue requests a plugin manifest field that automatically applies plugin-required core configuration during installation.

## Best Possible Solution

Define one typed, allowlisted plugin setup-intent API that uses guarded config writes, displays the proposed diff, requires explicit apply or skip consent, validates before commit, records provenance, and provides reinstall and uninstall recovery guidance.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should third-party plugin installation be allowed to request core configuration changes, and which single consented setup API should own that authority?

Rationale: Current installation deliberately limits configuration mutations to plugin-owned enablement and install state, while existing broader patches occur in interactive provider setup; expanding this authority requires explicit product and security intent.

Likely owner: steipete

Owner reason: The central install-persistence and guarded configuration-mutation architecture traces most directly to this contributor's commits.

Owner confidence: high

Options:

- **Unified typed setup intents (recommended):** Add one allowlisted setup-intent contract for tool, service, provider, and hook plugins with visible diffs, explicit consent, validation, provenance, and recovery guidance.
- **Interactive setup hook only:** Require plugins to expose a post-install setup step that returns guarded changes instead of declaring mutations in the manifest.
- **Keep manual configuration:** Do not grant plugins authority over core configuration and retain plugin-specific setup documentation or CLI commands.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 lack a general manifest-to-install configuration intent payload and persistence path. This is a capability gap rather than broken established behavior.

## Solution Assessment

No, unrestricted automatic deep merging is not the best solution because it can hide security choices and overwrite user settings; a typed, consented setup-intent contract is narrower and safer.
