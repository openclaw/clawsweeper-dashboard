## Summary

Keep open: current main still lacks a manifest-level install-time config intent path, and the requested raw deep-merge behavior needs maintainer product/security design before implementation.

## What This Changes

The issue requests a plugin manifest `configPatch` field that `openclaw plugins install` would merge into user config during install and disclose to the operator.

## Best Possible Solution

Define a documented, constrained install-time plugin config intent contract with allowed surfaces, validation before write, visible diff and skip behavior, conflict/list rules, uninstall guidance, and tests across every install route.

## Reproduction Assessment

Yes, at source level. A manifest containing `configPatch` would currently be ignored because manifests do not parse it, install results cannot carry it, and install persistence only records/enables plugins.

## Solution Assessment

No for the raw deep-merge proposal as written. The maintainable solution is a constrained config-intent contract that keeps setup explicit, validates before commit, and records provenance for later review or uninstall guidance.
