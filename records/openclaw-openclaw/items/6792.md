## Summary

Keep open. Current main and v2026.6.11 still lack an executable general plugin install-time configuration contract, and the remaining work requires a maintainer-approved trust, consent, conflict, and recovery model.

## What This Changes

Add a manifest-declared install-time configuration intent so plugin installation can safely set required OpenClaw configuration.

## Best Possible Solution

Define typed, bounded setup intents in the canonical manifest-first control plane, apply them through the existing validated config/install-record transaction, show an explicit diff with consent or skip behavior, and record provenance and recovery guidance.

Options:

- **Transactional bounded intents (recommended):** Add typed approved operations to canonical setup metadata and apply them atomically with install records after required diff review and consent.
- **Owner-specific setup only:** Keep installation limited to enablement and records, with shared configuration performed by provider, channel, or plugin-specific setup flows.
- **Raw automatic patch:** Deep-merge arbitrary manifest objects into shared configuration during plugin installation.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 both have descriptive setup metadata but no executable install-time configuration intent in the manifest, install result, or persistence path.

## Solution Assessment

No, unrestricted automatic deep merge is not the best solution. A bounded transactional operation model integrated with the canonical setup and config-commit paths is safer and avoids a competing source of truth.
