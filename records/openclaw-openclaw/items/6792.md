## What This Changes

The issue requests a plugin manifest `configPatch` field that `openclaw plugins install` would apply automatically to user config during install.

## Best Possible Solution

Define an auditable install-time plugin config-intent contract with allowlisted surfaces, validation before commit, visible diff and skip behavior, conflict and array semantics, uninstall provenance, docs, and install-route tests.

## Reproduction Assessment

Yes for the source-level gap: current main has no manifest `configPatch` field, install result carrier, or install persistence hook for manifest-declared config mutation. No runtime reproduction is needed because this is a missing contract proposal rather than broken implemented behavior.

## Solution Assessment

Unclear as proposed. The ergonomic goal fits the plugin setup surface, but a raw arbitrary deep-merge from manifests is not the best shape without an allowlisted, auditable config-intent contract.
