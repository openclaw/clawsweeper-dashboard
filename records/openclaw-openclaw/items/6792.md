## Summary

Keep open: current main and the latest release still lack a manifest-level install-time config intent contract, and the remaining work is a product/security design decision rather than conservative cleanup.

## What This Changes

The issue requests a manifest-level `configPatch` field that `openclaw plugins install` would apply automatically to user configuration during plugin installation.

## Best Possible Solution

Define a documented, auditable install-time plugin config-intent contract with allowed or classified writable surfaces, pre-commit validation, visible diff and skip/confirm behavior, conflict and array semantics, uninstall provenance, and coverage across all install routes.

## Reproduction Assessment

Not applicable as a runtime bug, but yes for source-level proof: current main has no manifest `configPatch` field, install result carrier, or install persistence hook for manifest-declared config mutation.

## Solution Assessment

Unclear as proposed. A safe manifest-level setup contract fits the need, but raw deep-merge writes are not the best shape until maintainers define trust boundaries, confirmation/skip UX, conflict behavior, and provenance.
