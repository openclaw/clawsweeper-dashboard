## Label Justifications

- `P3`: This is a useful but non-urgent plugin setup/API design request rather than a current broken core workflow.
- `impact:data-loss`: The requested install-time config mutation could overwrite persisted `openclaw.json` keys or user-managed arrays if conflict semantics are wrong.

## Summary

Keep open: current main and v2026.6.11 still lack a manifest-level install-time config intent contract, and the remaining work is a product/security decision about third-party config mutation rather than conservative cleanup.

## What This Changes

Requests a manifest-level `configPatch` or equivalent config intent so plugins can declare config changes for `openclaw plugins install` to apply automatically.

## Best Possible Solution

Define a documented, auditable manifest config-intent contract with validation before commit, operator-visible diff and skip behavior, scoped permissions for sensitive paths, conflict/array rules, and uninstall guidance across every install route.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw add manifest-declared install-time config intent for third-party plugins, and what path limits, confirmation, conflict/array behavior, provenance, and uninstall guidance must it require?

Rationale: This changes plugin installation from enabling package metadata to allowing package metadata to mutate persisted user configuration, which crosses product, upgrade-safety, and security boundaries that source inspection cannot decide.

Likely owner: steipete

Owner reason: They already framed this issue as product/security follow-up and have recent manifest/install documentation history.

Owner confidence: high

Options:

- **Define Guarded Config Intent (recommended):** Approve a narrow manifest contract that validates against current config, shows a diff with a skip path, records provenance, and limits or classifies sensitive paths before writing.
- **Keep Manual Setup For Now:** Reject manifest-driven writes and keep plugins using docs, setup flows, provider auth, or explicit `openclaw config patch` until a safer contract is designed.
- **Tie It To Trust Metadata:** Require ClawHub or package trust metadata before a plugin can request install-time config mutation.
