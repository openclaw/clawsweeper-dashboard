## Summary

Keep open for a maintainer-owned product and security decision. The requested install-time manifest contract remains materially different from the existing plugin install state flow and provider-auth setup patches; an arbitrary deep merge would give third-party packages authority to overwrite user configuration without a settled consent, scope, conflict, or provenance model.

## What This Changes

Add a plugin-manifest `configPatch` capability that would apply declared OpenClaw configuration changes when a plugin is installed.

## Best Possible Solution

If maintainers want to reduce setup friction, define a constrained declarative config-intent contract limited to documented plugin-owned targets, with a reviewed diff and skip path, validation before commit, deterministic array/conflict behavior, and install provenance; otherwise retain explicit plugin setup flows rather than accepting arbitrary manifest writes.
