## Summary

Keep open: current main and the latest release still lack a manifest-level install-time config patch or safer config-intent contract, and the remaining work is a product/security design decision rather than a narrow missing implementation.

## What This Changes

The issue requests a plugin manifest field that lets `openclaw plugins install` apply documented configuration changes automatically during plugin installation.

## Best Possible Solution

Define a documented, auditable install-time plugin config-intent contract with allowed surfaces, validation before commit, operator-visible diff/skip behavior, conflict and array semantics, install provenance, uninstall guidance, and tests across install routes.

## Reproduction Assessment

Not applicable as a bug reproduction, but yes for source-level proof: current main has no manifest `configPatch` field, install result carrier, or install persistence hook for manifest-declared config mutation.

## Solution Assessment

Unclear as proposed: the ergonomics goal is valid, but raw deep-merge from third-party manifests is not the best final contract without explicit trust boundaries, conflict handling, confirmation, and provenance.
