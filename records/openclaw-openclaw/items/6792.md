## Summary

Keep open: current main and v2026.6.11 still lack a manifest-level install-time config patch or config-intent contract, and the only direct implementation PR closed unmerged with unresolved safety questions around plugin-authored config mutation.

## What This Changes

The issue requests a manifest-level install-time `configPatch` contract so plugins can automatically apply required OpenClaw configuration during installation.

## Best Possible Solution

Define a documented, auditable install-time plugin config-intent contract instead of accepting arbitrary silent manifest writes: validate before commit, show a diff with a skip path, define conflict and array behavior, record provenance for uninstall guidance, cover all install routes, and update public manifest/plugin docs and regression tests.

## Reproduction Assessment

Not applicable as a bug reproduction, but yes for source-level proof: current main has no manifest `configPatch` field, install result carrier, or install persistence hook for manifest-declared config mutation.

## Solution Assessment

Unclear as proposed. The feature is aligned with plugin setup ergonomics, but a raw deep-merge `configPatch` is too broad unless maintainers first define trust boundaries, conflict behavior, confirmation/skip UX, and provenance.
