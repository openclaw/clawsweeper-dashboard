## Summary

Keep open: current main and the latest release still lack a manifest-level install-time config intent contract, and the remaining work is a product/security decision about third-party plugin-authored config mutation rather than stale cleanup.

## What This Changes

Request to let plugin manifests declare an install-time `configPatch` that `openclaw plugins install` applies to user configuration automatically.

## Best Possible Solution

Define an auditable install-time plugin config-intent contract with allowlisted surfaces, validation before commit, operator-visible diff and skip behavior, explicit conflict and array semantics, provenance for uninstall guidance, docs, and tests across every install route.

## Reproduction Assessment

Not applicable as a bug reproduction, but yes for source-level proof: current main has no manifest `configPatch` field, install result carrier, or install persistence hook for manifest-declared config mutation.

## Solution Assessment

Unclear as proposed. The ergonomic goal fits the plugin setup surface, but raw arbitrary deep-merge from manifests is not the best shape without an allowlisted, auditable config-intent contract.
