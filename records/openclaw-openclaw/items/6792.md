## Summary

Keep open: current main and v2026.6.11 still only support provider-auth-scoped configPatch, not a manifest-level install-time config intent path, and the direct implementation attempt closed unmerged with the main product/security questions unresolved.

## What This Changes

Request to let plugin manifests declare an install-time configPatch that plugin install applies to user configuration automatically.

## Best Possible Solution

Define a documented, auditable install-time plugin config-intent contract that validates before commit, shows a diff with a skip path, defines conflict and array behavior, records provenance for uninstall guidance, and covers every plugin install route.

## Reproduction Assessment

Not applicable as a bug reproduction, but yes for source-level proof: current main has no manifest configPatch field, install-result carrier, or install persistence hook for manifest-declared config mutation.

## Solution Assessment

Unclear as proposed. The goal fits plugin setup ergonomics, but raw deep-merge configPatch is not the best shape until maintainers define allowed paths, conflict behavior, confirmation/skip UX, and provenance.
