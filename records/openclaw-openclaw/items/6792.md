## Summary

Keep open: current main still lacks a general manifest-declared install-time configuration path, but unrestricted deep merging would cross a product and security boundary by letting third-party package metadata overwrite persisted operator choices. The remaining work requires an explicit maintainer decision rather than a narrow implementation patch.

- **steipete** — recent plugin-management contributor and prior reviewer of this issue (high confidence).

## What This Changes

Add a plugin-manifest contract that applies required configuration automatically during plugin installation.

## Best Possible Solution

Add a typed, ownership-scoped plugin setup-intent contract with a visible diff, explicit confirmation or skip path, validation before commit, conflict rules, recorded provenance, and uninstall guidance; do not permit arbitrary silent root-config merges.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should third-party plugin manifests be allowed to mutate persisted user configuration during installation, and if so which paths, consent flow, and rollback obligations are permitted?

Rationale: The request would expand package metadata from declarative discovery into write authority over operator-owned configuration, and repository policy requires that security-sensitive convenience remain explicit and operator-controlled.

Likely owner: steipete

Owner reason: Recent plugin-management implementation history and the prior issue review make steipete the strongest available routing candidate for this product and security decision.

Owner confidence: high

Options:

- **Typed setup intents (recommended):** Permit only ownership-scoped setup operations with preview, confirmation, validation, provenance, conflict handling, and a skip path.
- **Arbitrary configPatch:** Allow validated root-config deep merges from manifests and accept the broader overwrite, conflict, and cleanup surface.
- **Keep configuration explicit:** Retain plugin-owned interactive setup or documented manual configuration without install-time manifest mutation.

## Reproduction Assessment

Yes for the capability gap: current-main source shows that the manifest and install persistence paths have no general manifest-declared configuration mutation. This is a feature request rather than a failing existing-behavior reproduction.

## Solution Assessment

No—the proposed unrestricted deep merge is not the safest solution because it creates competing ownership over persisted configuration. A typed, consented, auditable setup-intent contract is the narrower maintainable direction.
