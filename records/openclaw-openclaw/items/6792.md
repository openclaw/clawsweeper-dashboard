## Summary

Keep open: current main and v2026.6.11 still lack a manifest-level install-time config intent contract, and the remaining work is a product/security boundary decision rather than conservative cleanup.

## What This Changes

Request to let plugin manifests declare an install-time config patch or config intent so plugin installs can update required user config automatically.

## Best Possible Solution

Define a documented, auditable plugin install config-intent contract with validation, operator-visible diff and skip behavior, scoped sensitive-path handling, conflict and array rules, provenance, and uninstall guidance.

Rationale: This changes plugin install from enabling package metadata to letting third-party metadata request persisted user config changes, which crosses product, upgrade-safety, and security boundaries that automation cannot choose alone.

Owner confidence: high

Options:

- **Define guarded config intent (recommended):** Approve a narrow manifest contract that validates against current config, shows a diff with a skip path, records provenance, and classifies or limits sensitive paths before writing.
- **Keep manual setup for now:** Reject manifest-driven writes and keep plugins using docs, setup flows, provider auth, or explicit openclaw config patch commands until a safer contract is designed.
- **Gate through package trust:** Require ClawHub/package trust metadata or a plugin setup flow to carry any install-time config request before core accepts it.
