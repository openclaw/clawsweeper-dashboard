## Summary

Keep open: current main still lacks a manifest-level install-time config patch or equivalent config-intent contract, and the remaining work is a product/security design decision rather than conservative cleanup.

## What This Changes

The issue requests an `openclaw.plugin.json` manifest field that lets `openclaw plugins install` apply validated user-config changes automatically during plugin installation.

## Best Possible Solution

Define a documented, auditable install-time plugin config-intent contract that validates before commit, shows a diff with a skip path, limits or classifies writable surfaces, records provenance for uninstall guidance, covers all install routes, and updates manifest/plugin docs plus regression tests.

## Reproduction Assessment

Not applicable as a runtime bug, but yes for source-level proof: current main has no manifest `configPatch` field, install result carrier, or install persistence hook for manifest-declared config mutation.

## Solution Assessment

Unclear as proposed. The feature direction fits plugin setup ergonomics, but raw deep-merge manifest writes are not the best safe shape until maintainers define trust boundaries, conflict behavior, confirmation/skip UX, and provenance.
