## Summary

Keep open: current main and v2026.6.11 still lack a manifest-level install-time config patch or config-intent contract, and the direct implementation PR was closed unmerged with unresolved safety questions.

## What This Changes

Add a manifest-level `configPatch` or equivalent install-time config intent so plugin installs can apply required user configuration automatically.

## Best Possible Solution

Define a documented, auditable install-time plugin config-intent contract that validates before commit, shows an operator-visible diff with a skip path, constrains sensitive paths, records provenance, and covers every install route with tests.

## Reproduction Assessment

Not applicable as a bug reproduction, but yes for source-level proof: current main has no manifest `configPatch` field, install result carrier, or install persistence hook for manifest-declared config mutation.

## Solution Assessment

Unclear as proposed. Manifest-declared setup intent is likely the right boundary, but raw deep-merge `configPatch` is not the best form until maintainers define allowed paths, consent, conflict handling, and provenance.
