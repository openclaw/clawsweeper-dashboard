## Summary

Keep open: current main and the latest release still do not implement a manifest-level install-time config patch or safer config-intent contract, and the only direct implementation attempt closed unmerged with unresolved security and overwrite semantics.

## What This Changes

The issue asks OpenClaw to let plugin manifests declare install-time config changes that `openclaw plugins install` can apply automatically.

## Best Possible Solution

Define a documented, auditable install-time plugin config-intent contract with allowlisted surfaces, validation before commit, visible diff/skip UX, conflict and array rules, uninstall provenance, all install routes, docs, and regression coverage.

## Reproduction Assessment

Yes for source-level proof, not as a runtime bug reproduction: current main has no manifest `configPatch` field, no install-result carrier, and no install persistence hook for manifest-declared config mutation.

## Solution Assessment

Unclear as proposed. A raw deep-merge `configPatch` is too broad until maintainers define trust boundaries, allowed paths, confirmation/skip behavior, conflict handling, array semantics, and uninstall provenance.
