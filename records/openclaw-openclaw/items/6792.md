## Summary

Current main and v2026.6.11 still require plugin-specific configuration separately from installation. The request remains useful and vision-aligned, but arbitrary third-party manifest deep-merges would cross user configuration and security boundaries without a settled consent, conflict, provenance, and recovery contract.

## What This Changes

Add a plugin-manifest contract that can propose and apply required OpenClaw configuration during plugin installation.

## Best Possible Solution

Define constrained, typed install-time config intents with allowlisted operations, an explicit diff and skip or confirmation path, pre-commit validation, deterministic conflict rules, durable provenance, uninstall guidance, and parity across every supported install route.

Options:

- **Constrained config intents (recommended):** Add typed, auditable setup operations with explicit user review, validation, provenance, and recovery rather than accepting arbitrary JSON deep-merges.

- **Keep configuration explicit:** Reject manifest-driven config mutation and improve Control UI and CLI guidance so users apply security-sensitive changes themselves.
