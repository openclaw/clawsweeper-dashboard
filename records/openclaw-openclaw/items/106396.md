## Summary

The concurrency guard is a focused and plausible fix with no remaining line-level correctness defect, but this external PR still lacks after-fix provider-backed behavior proof and does not establish that every provider hangup promise settles or times out.

## What This Changes

The PR adds a call-ID-keyed in-flight guard to the voice-call stale-call reaper and regression coverage showing retries resume after the pending hangup settles.

## Best Possible Solution

Keep the per-call guard, prove with an installed Gateway and controlled provider simulator that a stalled hangup cannot overlap and that failure or timeout releases the guard for retry; if any provider can remain pending indefinitely, add a bounded hangup timeout before merge.
