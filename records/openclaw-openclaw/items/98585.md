## Summary

Keep open: current main still has an actionable approval-queue bug. The Control UI removes the active approval after a successful resolve but does not refresh the gateway pending lists when the local queue becomes empty, so a missed requested event can still leave a pending approval invisible; the linked fix PR was closed unmerged.

## What This Changes

The issue asks for exec/plugin approval surfaces to stay open or advance to the next pending item after one approval is resolved.

## Best Possible Solution

Fix the approval clients so resolve actions are item-scoped, refresh pending exec/plugin approvals after the last local item is dismissed, and serialize native macOS prompts without changing the gateway protocol.

## Reproduction Assessment

Yes, as a source-level repro: resolve the only locally queued approval while the gateway still has another pending approval from a missed requested event; current `handleExecApprovalDecision` removes the local item and does not refresh the lists on success. I did not run a live UI/macOS scenario in this read-only pass.

## Solution Assessment

Yes, the best fix is a narrow client repair: keep approval decisions tied to the active id, use the existing list/replay contract to refill the queue after final local dismissal, and serialize native macOS prompts. Changing the gateway protocol is not needed.
