## Summary

Keep open: current main and v2026.6.11 support Telegram native approval delivery and the existing `/elevated full` exec bypass path, but not a scoped trusted-owner group approval bypass; the remaining request relaxes a privileged approval boundary and needs maintainer product/security direction.

## What This Changes

The issue requests an opt-in Telegram group mode that lets explicitly allowlisted owners bypass approval gates for configured privileged tool classes with audit marking.

## Best Possible Solution

Decide the approval-boundary policy first, then either document existing `tools.exec.mode: "full"` and `/elevated full` as the supported trusted-owner workflow or implement a disabled-by-default shared policy with explicit sender, group, tool-class, destructive-operation, audit, docs, and Telegram proof semantics.
