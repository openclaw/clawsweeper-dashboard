Keep open. Current main and the latest checked release still do not provide a scoped Telegram trusted-owner approval bypass, and the remaining work is a security-sensitive product/config decision rather than conservative cleanup.

## What This Changes

The issue requests an opt-in Telegram group mode that lets explicitly allowlisted owners bypass approval-gated shell, cron, config, runtime, or filesystem actions with audit logging and scoped safety rules.

## Best Possible Solution

Design a maintainer-approved shared trusted-owner execution policy that composes with Telegram group authorization, exec/elevated policy, native approvals, tool-class gates, destructive-operation handling, audit records, docs, and Telegram proof.

Likely owner: steipete

Owner confidence: medium

Options:

- **Design shared trusted-owner policy (recommended):** Add a disabled-by-default policy with explicit sender, allowlisted group, tool-class, destructive-operation, audit, docs, and regression-test semantics across the existing approval stack.
- **Keep existing approval model:** Decline the bypass and document that operators who want no prompts should use existing full elevated and host approval policy deliberately.
- **Add Telegram-only shortcut:** Implement the proposed Telegram config directly, accepting a smaller patch but higher risk of policy drift from shared approvals and elevated execution.

## Solution Assessment
