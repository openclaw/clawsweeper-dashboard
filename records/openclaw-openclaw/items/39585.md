## Summary

Keep open: current main and the latest release support Telegram native approval routing and `/elevated full`, but they do not implement a scoped trusted-owner bypass for approval-gated Telegram group actions; the remaining work changes a privileged approval boundary and needs product/security direction.

## What This Changes

Request an opt-in Telegram group trusted-owner mode or policy matrix that can bypass approval prompts for configured runtime, filesystem, cron, or config actions with audit and destructive-operation safeguards.

## Best Possible Solution

Decide the approval-boundary policy first, then either document the existing `/elevated full` and native approval routing as the supported trusted-owner workflow or implement a disabled-by-default shared policy with explicit sender, group, tool-class, destructive-operation, audit, docs, tests, and Telegram proof.
