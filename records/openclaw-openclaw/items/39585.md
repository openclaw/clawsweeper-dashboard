## Summary

Keep open. Current main and v2026.6.11 still route Telegram owner IDs into approval authorization and delivery, not into a scoped trusted-owner approval bypass, and adding that bypass would change a security boundary plus config surface.

## What This Changes

The issue requests an opt-in Telegram trusted-owner/group/tool-class mode that can bypass approval prompts for privileged actions while preserving audit and destructive-operation safeguards.

## Best Possible Solution

Design a maintainer-approved shared trusted-owner execution policy that composes with Telegram group authorization, exec/elevated policy, plugin approvals, protected config flows, destructive-operation handling, audit records, docs, and Telegram proof.
