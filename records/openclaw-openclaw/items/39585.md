## Summary

Keep open: current main and v2026.6.11 have Telegram native approval routing, owner approvers, and `/elevated full`, but not the requested trusted-owner approval bypass; adding it would relax a privileged approval boundary and needs maintainer product/security direction.

## What This Changes

The issue requests an opt-in Telegram group mode that lets explicitly allowlisted owners bypass approval prompts for configured privileged tool classes, with audit logging and safety limits.

## Best Possible Solution

Decide the approval-boundary policy first, then either document existing elevated/full policy as the supported trusted-owner workflow or implement a disabled-by-default shared policy with group, owner, tool-class, destructive-op, audit, docs, and Telegram proof.
