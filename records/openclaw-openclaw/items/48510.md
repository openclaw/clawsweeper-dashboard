## Summary

Keep open: current main still lacks declared behavioral capability descriptors on the core tool type, plugin tool metadata, before_tool_call payloads, trusted-policy dispatch, and Gateway tool projections. The related work remains open or adjacent, not a merged replacement for this focused public SDK/security-policy contract.

## What This Changes

The issue requests optional structured capability descriptors on tool definitions so policy and audit plugins can reason about tool behavior without brittle tool-name matching.

## Best Possible Solution

Define one additive, documented advisory tool-capability descriptor contract, project it through tool inventory and hook policy surfaces, and keep declarations separate from host authorization or explicit grants.
