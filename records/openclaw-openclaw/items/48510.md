## Summary

Keep open: current main still lacks declared behavioral capability descriptors on tool definitions, plugin tool metadata, hook payloads, trusted-policy dispatch, and Gateway tool projections; the related open work is adjacent rather than a merged replacement.

## What This Changes

The issue requests optional per-tool behavioral capability descriptors so policy, onboarding, audit, and hook consumers can reason about tool actions without brittle tool-name matching.

## Best Possible Solution

Design one additive, documented policy-facts contract for behavioral tool capability descriptors, project it through tool inventory and hook policy surfaces, and keep declarations advisory unless host authorization or explicit grants enforce them.

- **Keep As Security Matrix Input Only:** Use the Security Matrix/audit model as the canonical consumer and avoid adding a general-purpose public descriptor field until that PR lands and owners approve the vocabulary.
