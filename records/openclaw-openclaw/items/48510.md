## Summary

Keep open: current main still lacks the requested per-tool behavioral capability descriptors, and the adjacent open security/permission items are related design work rather than a merged replacement.

## What This Changes

Request to add optional behavioral capability descriptors to tool definitions so plugins and policy hooks can reason about external reads, persistence writes, external sends, privileged execution, and autonomous actions without brittle tool-name matching.

## Best Possible Solution

Design one additive public Plugin SDK and Gateway protocol contract for behavioral tool capability descriptors, project it through catalog/effective inventory and policy hook events, and document that declarations inform policy without replacing host authorization or unknown-by-default handling.
