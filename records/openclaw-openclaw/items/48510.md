## Summary

Keep open: current main and v2026.6.11 still lack a behavioral tool-capability descriptor contract on tool definitions, plugin tool metadata, hook/trusted-policy payloads, and Gateway tool projections; the related open issues overlap but do not replace this focused Plugin SDK/security design request.

## What This Changes

The issue requests optional capability descriptors on tool definitions so plugins, policy, permissions, documentation, and audit code can reason from stable behavior metadata instead of tool-name lists.

## Best Possible Solution

Define one additive, versioned tool-behavior descriptor contract, project it through core and plugin tool definitions, hook/trusted-policy payloads, inventories, Gateway schemas, docs, and tests, and keep declarations advisory unless a separate host authorization or grant layer enforces them.
