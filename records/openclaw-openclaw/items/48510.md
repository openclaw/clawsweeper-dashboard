## Summary

Keep open: current main and the latest release still lack optional tool capability descriptors in the core tool type, plugin tool metadata, hook/trusted-policy payloads, effective inventory, and Gateway catalog schemas; related work overlaps but does not replace this focused public SDK/security-design request.

## What This Changes

The issue requests optional behavioral capability descriptors on tool definitions so policy, audit, onboarding, and documentation can reason about tool effects without name-based allowlists.

## Best Possible Solution

Define one additive, documented policy-facts contract for tool behavior descriptors, project it through tool definitions, plugin metadata, hook/trusted-policy payloads, inventories, and Gateway schemas, and keep declarations advisory unless host authorization or explicit grants enforce them.
