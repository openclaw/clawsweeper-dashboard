## Summary

Keep open: current main still lacks the requested tool behavior capability descriptors across tool definitions, plugin tool metadata, before_tool_call/trusted-policy payloads, effective tool inventory, and Gateway tool catalog projections; related open items overlap but do not replace this focused API design request.

## What This Changes

The issue requests optional capability descriptors on tool definitions so policy plugins can reason about tool behavior without hardcoded tool-name lists.

## Best Possible Solution

Define one additive, documented policy-facts contract for tool behavior descriptors, project it through tool definitions, plugin metadata, hook/trusted-policy payloads, inventories, and Gateway schemas, and keep declarations advisory unless host authorization or explicit grants enforce them.
