## Summary

Keep open: current main still lacks per-tool behavioral capability descriptors, and the related open issues and Security Matrix PR are adjacent design work rather than a merged replacement.

## What This Changes

The issue requests optional capability descriptors on tool definitions so policy, audit, and hook code can reason about tool behavior without brittle tool-name lists.

## Best Possible Solution

Design one additive public contract for behavioral tool capability descriptors, project it through tool catalog/effective inventory and policy hook events, and document that declarations inform policy without replacing host authorization or unknown-by-default handling.

## Reproduction Assessment

Yes. This is source-reproducible as an API gap: current main exposes tool names, params, identity hints, risk, tags, and derived paths, but not declared behavioral capability descriptors.

## Solution Assessment

Unclear as a final implementation shape. Optional descriptors are plausible, but the best fix needs maintainer-approved taxonomy, unknown/default semantics, and coordination with adjacent capability and provenance proposals.
