## Summary

Keep open: current main and the latest release still lack the requested behavioral capability descriptor contract on tool definitions, plugin tool metadata, before_tool_call/trusted-policy payloads, and Gateway tool inventory schemas. The related open issues and PR overlap on provenance, classifications, permissions, egress intent, and Security Matrix facts, but none is a merged replacement for this focused public SDK/security-policy surface.

## What This Changes

The issue requests optional capability metadata on tool definitions so policy plugins can reason about tool behavior without brittle tool-name matching.

## Best Possible Solution

Define one additive advisory tool-capability descriptor contract with unknown-by-default semantics, then project it consistently through tool definitions, plugin metadata, Gateway inventory, trusted policies, and before_tool_call with docs and contract tests.

Rationale: The change would make self-declared tool behavior metadata a public SDK and security-policy input, and it overlaps multiple open capability, provenance, permissions, audit, and Security Matrix proposals that automation cannot reconcile safely.

Likely owner: 100yenadmin

Owner confidence: high

Options:

- **Approve advisory descriptor contract (recommended):** Define optional unknown-by-default descriptors and project them through tools, plugin metadata, Gateway inventory, trusted policies, and before_tool_call while documenting that declarations are advisory and not grants.
- **Fold into broader permissions:** Keep this blocked behind the default-deny capability-permission model so descriptor facts ship only with grants, consent, and enforcement semantics.
- **Start with Security Matrix vocabulary:** Use the Security Matrix runtime-fact model as the first canonical consumer before exposing a general public descriptor field.

Yes for the source-level API gap: current main can be inspected to show that central tool, plugin metadata, hook, trusted policy, and Gateway inventory surfaces lack the requested descriptor contract. This is not a runtime failure repro because the issue requests new public metadata capability.

## Solution Assessment

Unclear until maintainer review: optional descriptors are plausible and aligned, but the best fix needs an owner-approved taxonomy, trust model, and coordination with adjacent capability/provenance work.
