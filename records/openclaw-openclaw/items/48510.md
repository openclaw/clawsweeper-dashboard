## Summary

Keep open: current main and the latest checked release still do not expose the requested optional tool capability descriptors, and the related issues/PRs are adjacent consumers or overlapping design work rather than a replacement implementation.

## What This Changes

The issue requests optional, unknown-by-default tool capability descriptors for tool definitions so policy plugins and before_tool_call hooks can reason about security-relevant tool behavior.

## Best Possible Solution

Define one additive, documented policy-facts contract for tool behavior descriptors, project it through core/plugin tools, metadata, tools.catalog/effective, before_tool_call/trusted policies, and tests, with declarations advisory and unknown-by-default unless host authorization explicitly enforces them.
