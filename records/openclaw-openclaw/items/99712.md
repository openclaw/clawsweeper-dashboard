## Summary

Keep open: current main still has source-level empty-payload exits in both the direct reply and queued follow-up paths, and the issue is already paired with open candidate PRs that should be reviewed instead of closing the report early.

## What This Changes

The issue requests a visible fallback/error reply when an interactive direct or channel turn completes with no renderable assistant payload and no successful source-channel delivery.

## Best Possible Solution

Land one canonical linked PR that adds a shared empty-interactive-reply guard across direct and queued follow-up paths while preserving explicit silent and side-effect-only completions.

## Solution Assessment

Yes: the best fix shape is a shared final-output guard at the reply-runner boundary, because both direct reply and follow-up delivery share the same visible-output invariant and already have the needed silent-policy and committed-delivery evidence nearby.
