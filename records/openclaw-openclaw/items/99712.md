## Summary

Keep open: current main and the latest release still have source-level paths that can finish an interactive turn with no outbound payload, and the linked candidate fix at https://github.com/openclaw/openclaw/pull/99716 is still open with failed Telegram proof rather than a merged fix.

## What This Changes

The issue asks OpenClaw to synthesize a visible fallback reply when an interactive non-silent direct/channel turn completes with no deliverable assistant payload or confirmed source-channel side effect.

## Best Possible Solution

Revise, land, or replace https://github.com/openclaw/openclaw/pull/99716 with a central runner final-output invariant that emits a visible fallback for interactive non-silent empty completions while preserving heartbeat, cron, message-tool-only, and confirmed side-effect exceptions.

Yes at source level: current `runReplyAgent`, `followup-runner`, and embedded-runner finalization can return no payload for the reported empty completion shape. I did not run a live Telegram reproduction in this read-only review.

## Solution Assessment
