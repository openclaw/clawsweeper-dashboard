## Summary

Keep open: current main and the latest release still allow direct and queued follow-up interactive turns to finish with no visible reply when the final run result has no deliverable payload and the narrow configured-fallback failure helper does not apply. The issue is already paired with multiple open fix PRs, so the cleanup path is to review and land one canonical candidate rather than close or queue another repair.

## What This Changes

Interactive direct/channel turns can complete with no renderable assistant payload and no visible fallback reply, silently dropping the user-visible response.

## Best Possible Solution

Land one canonical fix that adds a shared direct and follow-up final-output invariant: interactive non-silent empty completions without committed delivery should emit a visible failure payload, while heartbeat, cron, explicit silence, message-tool-only, approval, spawn, compaction, and already-delivered side-effect paths remain quiet.

## Reproduction Assessment

Yes at source level: current main returns `undefined` or bare `return` from the direct and follow-up empty-payload exits when the narrow configured-fallback failure helper does not apply. I did not run a live Telegram reproduction in this read-only review.

## Solution Assessment

Yes: the best fix is a shared reply-finalization guard at the direct and follow-up boundaries, because those paths already have the final payload, silent-policy, and committed-delivery evidence. A channel-only or Codex-only fix would be too narrow.
