## Label Justifications

- `P1`: An accepted interactive channel turn can complete without any user-visible reply, making real direct-channel workflows appear hung.
- `impact:message-loss`: The central failure is a completed turn with no assistant payload, no source delivery, and no outbound message to the user.
- `impact:session-state`: The issue can leave later direct-session messages queued behind a lane whose prior turn reached terminal state without visible progress.

## Summary

Keep open: current main and v2026.6.11 still have a source-reproducible empty-completion path where Codex can return `assistantTexts: []` with no `promptError`, and `runReplyAgent` returns no outbound payload unless the narrow configured-backend fallback branch applies.

## What This Changes

The issue requests a visible fallback for interactive, non-silent direct/channel turns that finish with no assistant payload and no source-channel delivery.

## Best Possible Solution

Add a runner-level guard that turns empty, non-silent, interactive source-channel completions without source delivery into a visible failure/fallback payload, while preserving intentional silent and already-delivered turns.

## Reproduction Assessment

Yes at source level: current main can preserve a completed empty Codex result, and the final reply path returns `undefined` when no payloads exist unless the narrow fallback-backend guard triggers. I did not run a live Telegram reproduction in this read-only review.

## Solution Assessment

Yes: the runner final-payload path is the narrowest maintainable fix location because it already has the run, silent-policy, fallback, and delivery-evidence facts. Fixing this in Telegram or the Codex projector alone would be one-sided and could miss sibling channels or non-Codex empty completions.
