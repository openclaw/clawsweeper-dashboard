## What This Changes

The issue requests a visible fallback or failure payload when a non-silent interactive direct/follow-up turn finishes with no renderable assistant output and no committed source-channel side effect.

## Best Possible Solution

Review and land one canonical linked PR that covers both `runReplyAgent` and `createFollowupRunner`, preserves explicit silent and side-effect-only cases, and includes focused regression coverage plus real channel proof where practical.

## Solution Assessment

Yes, the requested final-output guard is the right layer because it has the final payload list plus silent-policy and committed-delivery evidence. The embedded runner handles several raw empty-attempt cases, but the auto-reply/follow-up boundary still needs this defensive invariant.
