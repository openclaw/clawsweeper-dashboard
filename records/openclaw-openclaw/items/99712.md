## Summary

Keep open: current main and the latest release still have source-level empty-payload exits in both the direct reply runner and queued follow-up runner, and this issue is already paired with open candidate PRs that should be reviewed instead of closing the report early.

## What This Changes

The issue asks OpenClaw to synthesize a visible fallback for non-silent interactive direct/channel turns that finish with no assistant payload and no successful source-side delivery evidence.

## Best Possible Solution

Review and land one canonical linked PR that covers both `runReplyAgent` and `createFollowupRunner`, preserves explicit silent and side-effect-only cases, and adds focused regression coverage plus real channel proof where practical.

## Reproduction Assessment

Yes at source level: current main still returns no payload from the direct and follow-up finalization paths when `runResult.payloads` is empty and no narrow fallback-model failure applies. I did not run the live Telegram reproduction.

## Solution Assessment

Yes, the requested final-output guard is the right layer because it has the final payload list plus silent-policy and committed-delivery evidence. The embedded harness already classifies empty terminal results, but the auto-reply and follow-up boundaries still need the visible-output invariant.
