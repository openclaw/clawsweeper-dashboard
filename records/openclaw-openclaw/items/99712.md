## Summary

Keep open: the embedded runner now has partial incomplete-turn protection, but current main and v2026.6.11 still let `runReplyAgent` and follow-up delivery return silently when the final `runResult.payloads` array is empty and no fallback-model failure is known.

## What This Changes

Interactive user turns should synthesize a visible fallback and fail the reply operation when a completed run has no visible payload, no successful source-channel delivery, and no explicit silent policy.

## Best Possible Solution

Add a central auto-reply/follow-up final-output invariant: interactive non-silent empty run results without committed delivery should return a visible error payload, fail the reply operation, and preserve existing heartbeat, cron, silent, and committed source-delivery exceptions.

## Reproduction Assessment

Yes at source level: current `runReplyAgent` and follow-up delivery still return without a payload when a mocked or runtime-produced `runResult.payloads` is empty, no fallback notice exists, and no configured fallback-model failure is known.

## Solution Assessment

Yes for the remaining gap: the embedded runner is already the right lower-layer owner for attempt facts, but auto-reply finalization still needs a defensive invariant because it sees the final run result plus silent and delivery evidence.
