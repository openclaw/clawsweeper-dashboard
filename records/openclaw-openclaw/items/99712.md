## Summary

Keep open: current main still has source-level empty-payload exits in the direct reply and queued follow-up paths, and the issue is already paired with open candidate PRs that should be reviewed instead of closing the report early.

## What This Changes

The issue asks OpenClaw to synthesize a visible fallback for interactive direct/channel turns that complete with no renderable assistant payload, no prompt error, and no committed source-channel delivery.

## Best Possible Solution

Review and land one canonical linked PR that covers both `runReplyAgent` and `createFollowupRunner`, preserves explicit silent and side-effect-only cases, and adds focused regression coverage plus real channel proof where practical.

## Reproduction Assessment

Yes, at source level: current main still returns no payload from the direct and follow-up finalization paths when `runResult.payloads` is empty and no narrow fallback-model failure applies. I did not run the live Telegram reproduction.

## Solution Assessment

Yes, the requested final-output guard is the right layer for the remaining gap because it has the final payload list plus silent-policy and committed-delivery evidence. The embedded runner already handles many raw empty attempts, but the auto-reply/follow-up boundary still needs a defensive invariant.
