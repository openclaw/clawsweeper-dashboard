Keep open: current main still has source-level empty-payload exits in both the direct reply and queued follow-up paths, and this issue is already paired with open closing PRs that should be reviewed instead of closing the report or queueing another fix job.

## What This Changes

The issue requests a visible fallback for interactive direct/channel turns that finish without an assistant payload, committed source delivery, explicit silence policy, or prompt error.

## Best Possible Solution

Land or reject one linked PR that adds a shared auto-reply finalization guard for both direct replies and queued follow-ups while preserving explicit silent and committed side-effect cases.

## Solution Assessment

Yes, the requested shared guard at the auto-reply finalization boundary is the maintainable fix shape because both direct replies and queued follow-ups can currently drop empty terminal results. The best route is to review the existing linked PRs and land the one that covers both paths and the silent exceptions.
