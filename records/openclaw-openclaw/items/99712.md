## Summary

Keep open: current main still has source-level empty-payload exits in `runReplyAgent` and `createFollowupRunner`, and the open linked PRs are candidate fixes rather than merged implementation evidence.

## What This Changes

Interactive direct/channel turns should surface a visible fallback when a non-silent user-originated run completes with no deliverable assistant payload or committed source-channel delivery.

## Best Possible Solution

Merge a single canonical fix that centralizes the empty interactive final-output invariant for both `runReplyAgent` and follow-up delivery, then close this issue from the merged PR.

## Reproduction Assessment

Yes at source level: current main still has direct-reply and follow-up branches that return no payload when `runResult.payloads` is empty and no configured fallback failure applies. I did not run the live Telegram/Codex scenario.

## Solution Assessment

Yes: the best fix is a final auto-reply/follow-up invariant because that layer has the final payload list, silent policy, and source-delivery evidence. A lower embedded-runner-only fix would miss normalized empty delivery cases at the channel boundary.
