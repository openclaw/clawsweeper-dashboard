## Summary

Keep this PR open: it targets a real outbound message-ordering bug and has useful Telegram proof, but the current patch is not merge-ready because it derives an unbounded serializer lane from raw pre-adapter inputs after durable queue writes have already raced.

## What This Changes

The branch adds an in-memory outbound DeliverySerializer around platform delivery plus unit coverage for same-key ordering, cross-key concurrency, failures, synchronous throws, and cleanup.

## Best Possible Solution

Move the ordering guarantee to a canonical durable-delivery lane that includes normalized account, recipient, and thread/topic identity, covers enqueue plus platform send ordering, and bounds waits with abort/stall handling before rerunning sibling-channel tests and Telegram proof.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Derive the lane from the canonical delivery target:** `src/infra/outbound/deliver.ts:1274`
  - body: This key uses raw `accountId` and `to` and omits the effective thread/topic, while the channel adapters canonicalize the real destination later. Equivalent targets such as Signal aliases or prefixed recipients can bypass the lock, and Discord/Telegram thread sends can be over- or under-serialized, so the ordering fix is not reliable across supported channels.
  - confidence: 0.91
- **[P1] Acquire ordering before durable queue writes can race:** `src/infra/outbound/deliver.ts:1278`
  - body: The serializer is entered only after `enqueueDelivery(...)` has completed. If an earlier same-recipient call has a slower queue write than a later call, the later call reaches the serializer first and can still deliver before the earlier message, which breaks the FIFO guarantee this PR is meant to add.
  - confidence: 0.86
- **[P1] Bound serializer waits on aborts and stalled sends:** `src/infra/outbound/deliver.ts:1278`
  - body: The new chain waits forever for the prior same-key promise. A stalled platform path such as the Discord webhook `fetch()` can now wedge every later delivery for that lane until process restart, and aborted formatted sends can sit behind the lock before their abort checks run.
  - confidence: 0.88
