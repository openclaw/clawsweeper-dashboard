  - body: Current main already has `enqueueKeyedTask` / `KeyedAsyncQueue` for exactly this Promise-tail pattern. Adding a second local serializer in the hot outbound path creates drift for failure isolation and cleanup behavior; rebase and use the shared primitive or move it to a core-owned helper.

  - body: This key is raw `channel:accountId:to` and is created after `enqueueDelivery`, so an earlier call with a slower queue write can still lose the race to the serializer.   - confidence: 0.9

  - body: Once a send enters this lane, every later same-key delivery waits for the prior platform call to settle. A stalled webhook/fetch or an already-aborted queued send can wedge later replies for that recipient until restart, so the lane needs timeout/abort-aware release or failure handling.
