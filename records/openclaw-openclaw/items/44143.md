## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Derive lanes before enqueue from canonical targets:** `src/infra/outbound/deliver.ts:1274`
  - body: This remains from the previous review: the mutex key is built from raw `channel`, `accountId`, and `to`, and the lock is first acquired only after `enqueueDelivery`. An earlier same-target send can lose the queue-write race to a later send, and adapters later canonicalize the real destination, so equal chats can still deliver out of order while unrelated threads may block each other. Derive and acquire the lane from canonical account, recipient, and thread identity before queue I/O or platform send.
  - confidence: 0.9
- **[P2] Bound serialized waits on aborts and stalls:** `src/infra/outbound/deliver.ts:1278-1279`
  - body: This remains from the previous review: the serializer releases the key only after `deliverOutboundPayloadsCore` settles. A hung Discord webhook fetch or an adapter path that does not observe aborts can now hold the key forever, blocking every later reply to that chat; before this patch those later sends could still proceed. Add abort-aware waiting and a bounded stall policy before serializing production traffic.
  - confidence: 0.86
