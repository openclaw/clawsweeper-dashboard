## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Derive lanes from canonical delivery targets:** `src/infra/outbound/deliver.ts:1274`
  - body: The new mutex key is built from raw channel, accountId, and to values before channel adapters normalize the actual destination. Signal strips prefixes such as signal:, Discord thread sends are delivered as channel:<threadId>, and account IDs normalize to default/lowercase forms, so equivalent chats can bypass serialization while distinct threads can block each other. Derive the lane key from the canonical account plus delivered recipient/thread identity.
  - confidence: 0.9
- **[P2] Bound same-target waits on aborts and stalls:** `src/infra/outbound/deliver.ts:1278-1279`
  - body: Wrapping the whole platform send in a per-key mutex means one stalled adapter call now blocks every later same-target delivery until it resolves or the process restarts. This is observable on current paths because Discord webhook sends use fetch without an abort signal. Add abort-aware waiting and a bounded stall policy before serializing production traffic.
  - confidence: 0.84
