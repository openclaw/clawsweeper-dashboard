## Summary

Keep this PR open, but it is not merge-ready: the Telegram proof is convincing and current main does not contain this general outbound serializer, but the patch duplicates the existing keyed queue primitive, keys lanes from raw non-canonical delivery inputs, and can wedge later same-target deliveries behind stalled or canceled sends.

## What This Changes

This PR adds an in-memory outbound delivery serializer around `deliverOutboundPayloadsCore` plus tests for per-key FIFO delivery, error handling, sync throws, and queue cleanup.

## Best Possible Solution

Implement one canonical outbound delivery lane using the shared keyed queue helper, keyed from normalized channel/account/thread target facts, with abort/timeout behavior and focused regression coverage across Telegram, Discord, and Signal delivery paths.

Full review comments:

- **[P1] Reuse the existing keyed queue primitive:** `src/infra/outbound/delivery-serializer.ts:9-12`
  - body: This adds a new Promise-chain queue even though current main already has `enqueueKeyedTask`/`KeyedAsyncQueue` for exactly this per-key async serialization pattern. Keeping a second queue implementation will drift on cleanup/error/timeout semantics; wrap the shared helper with outbound-specific key construction instead.
  - confidence: 0.91
- **[P1] Derive lanes from canonical delivery targets:** `src/infra/outbound/deliver.ts:1272`
  - body: The serializer key is built from raw `channel`, `accountId`, and `to`, before channel-owned normalization and without `threadId`. Signal strips prefixes and normalizes targets, Discord can route a thread as the real peer, and account IDs are normalized by channel account resolvers, so equivalent chats can bypass the lock while distinct threads can block each other.
  - confidence: 0.88
- **[P2] Bound serialized waits on aborts and stalls:** `src/infra/outbound/deliver.ts:1276`
  - body: Once this wraps same-target sends, any hung predecessor blocks later messages for that target. That is observable today because Discord webhook sends use bare `fetch` without a signal/timeout and formatted adapter contexts do not receive the outbound `abortSignal`, so a stalled or canceled send can wedge the queue until restart.
  - confidence: 0.84
