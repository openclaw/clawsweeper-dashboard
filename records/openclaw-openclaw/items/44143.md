Full review comments:

- **[P1] Use the shared keyed queue helper:** `src/infra/outbound/delivery-serializer.ts:9-10`
  - body: Current main now has `enqueueKeyedTask` / `KeyedAsyncQueue`, merged specifically to remove repeated per-key FIFO serializers. Adding a new `DeliverySerializer` reintroduces the drift that shared helper eliminated, so wire this through the shared queue or move any missing policy into that helper instead.
  - confidence: 0.88
- **[P1] Derive lanes from canonical delivery targets:** `src/infra/outbound/deliver.ts:1274`
  - body: The new mutex key is built from raw `channel`, `accountId`, and `to` values before adapters normalize the actual destination. Signal strips prefixes such as `signal:`, Discord thread sends are delivered by thread identity, and account ids normalize to default forms, so equivalent chats can bypass serialization while distinct threads can block each other. Derive the lane key from canonical account plus delivered recipient/thread identity.
  - confidence: 0.9
- **[P2] Bound same-target waits on aborts and stalls:** `src/infra/outbound/deliver.ts:1278-1279`
  - body: Wrapping the whole platform send in a per-key mutex means one stalled adapter call now blocks every later same-target delivery until it resolves or the process restarts. This is observable on current paths because Discord webhook sends use `fetch` without an abort signal, and formatted adapter paths expose abort support that core does not forward. Add abort-aware waiting and a bounded stall policy before serializing production traffic.
  - confidence: 0.84
