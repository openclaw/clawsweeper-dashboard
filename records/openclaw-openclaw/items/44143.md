## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Reuse the existing keyed queue primitive:** `src/infra/outbound/delivery-serializer.ts:9-13`
  - body: This adds a second per-key Promise-tail queue even though `src/plugin-sdk/keyed-async-queue.ts` already provides and tests the same serialization primitive. Keeping a parallel serializer will make rejection cleanup, cancellation, and future queue semantics drift across two implementations; reuse the existing helper and add only outbound-specific lane derivation around it.
  - confidence: 0.84
- **[P1] Derive lanes before enqueue from canonical targets:** `src/infra/outbound/deliver.ts:1274`
  - body: The mutex key is built from raw `channel`, `accountId`, and `to`, and it is first acquired only after `enqueueDelivery`. An earlier same-target send can lose the queue-write race to a later send, and adapters later canonicalize the real destination, so equal chats can still deliver out of order while unrelated threads may block each other. Derive and acquire the lane from canonical account, recipient, and thread identity before queue I/O or platform send.
  - confidence: 0.9
- **[P2] Bound serialized waits on aborts and stalls:** `src/infra/outbound/deliver.ts:1278-1279`
  - body: The serializer releases the key only after `deliverOutboundPayloadsCore` settles. A hung Discord webhook fetch or a formatted send whose abort signal is not forwarded can now hold the key forever, blocking every later reply to that chat; before this patch those later sends could still proceed. Add abort-aware waiting and a bounded stall policy before serializing production traffic.
  - confidence: 0.86
