## Summary

This PR adds an in-memory per-channel/account/recipient delivery serializer around outbound delivery plus unit tests for FIFO ordering, cross-target concurrency, errors, synchronous throws, and cleanup.

Overall confidence: 0.88

Full review comments:

- **[P1] Reuse the existing keyed queue helper:** `src/infra/outbound/delivery-serializer.ts:9-13`
  - body: This adds a second per-key promise-tail implementation even though current main already exposes `KeyedAsyncQueue`/`enqueueKeyedTask` and core already imports that primitive elsewhere. Keeping a parallel delivery mutex means future queue fixes, hooks, and cleanup behavior can drift in this hot path; wire outbound serialization through the existing helper instead.
  - confidence: 0.9
- **[P1] Acquire canonical lanes before queue writes:** `src/infra/outbound/deliver.ts:1274-1278`
  - body: The lane is computed from raw `params.channel/accountId/to` and acquired only after `enqueueDelivery(...)` has completed. If two same-target sends race and the earlier send has a slower queue write, the later send can still enter the serializer first; adapter-normalized account, recipient, and thread targets can also bypass or over-share the raw key. Derive the canonical lane before enqueueing and use the actual delivery route.
  - confidence: 0.88
- **[P2] Bound queued waits on aborts and stalled sends:** `src/infra/outbound/deliver.ts:1278`
  - body: A same-target send now waits indefinitely for the previous `deliverOutboundPayloadsCore` call before its own abort checks run. Current Discord webhook sends use a bare fetch without a timeout/signal, so one stalled platform request can hold the recipient lane and block every later reply until restart; the serializer needs abort/stall-safe release behavior.
  - confidence: 0.82
