## Summary

Keep this PR open, but do not merge it yet: it correctly moves teardown toward deleting only OpenClaw-managed resources, while its new namespace-existence check can turn an RBAC authorization failure into a successful no-op. The linked report remains the canonical bug, and the branch needs both that repair and real Kubernetes evidence.

## What This Changes

Changes the Kubernetes teardown script and documentation so `--delete` removes OpenClaw’s Kustomize-managed resources and Secret while preserving a custom or shared namespace.

## System Context

The Kubernetes helper script creates a namespace, Secret, and Kustomize-managed OpenClaw resources for a gateway deployment. Its teardown mode receives the selected namespace and should remove only those OpenClaw resources without affecting other workloads in that namespace.

## Architecture Diagram

## Best Possible Solution

Delete the Kustomize-managed resources and `openclaw-secrets` directly with namespace-scoped, idempotent deletes; let genuine authorization or API failures surface, and prove the behavior in a disposable cluster with an RBAC role that cannot read Namespace objects.
