## Summary

Keep this PR open. The patch directly addresses the reported destructive teardown path and follows the Kustomize resource boundary, but it still needs real Kubernetes-cluster evidence and a maintainer decision on preserving an explicit full-namespace teardown mode for users who relied on the documented old behavior.

## What This Changes

The PR changes Kubernetes teardown to delete OpenClaw’s Kustomize-managed resources and Secret in the selected namespace instead of deleting the whole namespace.

## System Context

`scripts/k8s/deploy.sh` creates a namespace, applies the Kustomize-managed OpenClaw workload, and creates an independently managed Secret. Its delete mode is the operator-facing teardown path, so it must remove OpenClaw resources without unexpectedly affecting other workloads in a shared namespace.

## Architecture Diagram

flowchart LR
  A[Operator runs delete command] --> B[Kubernetes deploy script]
  B --> C[Selected namespace]
  C --> D[Kustomize-managed OpenClaw resources]
  C --> E[OpenClaw Secret]
  D --> F[OpenClaw workload removed]
  E --> F
  C --> G[Namespace and unrelated workloads retained]

## Best Possible Solution

Make resource-only teardown the safe default, document the retained namespace clearly, and add a separately named destructive namespace-removal mode only if maintainers want to preserve full cleanup for dedicated namespaces; validate the chosen contract on a real Kind or equivalent cluster.
