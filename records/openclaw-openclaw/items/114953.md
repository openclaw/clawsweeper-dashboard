## Summary

This PR remains necessary: current `main` still deletes the entire selected Kubernetes namespace, while the linked report documents that this removes unrelated workloads in a shared namespace. The patch is a narrow, plausible fix with no discrete correctness defect found in the reviewed diff, but it needs after-fix proof on a real Kubernetes cluster and a maintainer decision confirming that `--delete` should now retain the namespace for every namespace value, including the default.

## What This Changes

The PR replaces namespace deletion in the Kubernetes teardown script with deletion of the Kustomize-managed OpenClaw resources plus the OpenClaw Secret, and updates teardown documentation and tests.

## System Context

OpenClaw’s Kubernetes helper creates a namespace and deploys the bundled Kustomize resources into the namespace selected by `OPENCLAW_NAMESPACE`. Its teardown mode currently hands lifecycle control to `kubectl`; this change narrows that operation to OpenClaw resources so shared namespaces and their unrelated workloads remain intact.

## Best Possible Solution

Make namespace retention the canonical safe teardown behavior only after maintainer confirmation, document that an explicit separately named destructive cleanup is required for namespace removal, and attach redacted Kind or equivalent real-cluster teardown proof showing OpenClaw resources are removed while an unrelated workload remains.
