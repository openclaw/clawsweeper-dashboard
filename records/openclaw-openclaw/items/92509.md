## Summary

Keep open: this targets a real memory-core durability failure, but the current patch still treats the checkpoint as successful without reading SQLite's result row, and its test only proves that some checkpoint happened during sync rather than proving the new live-DB post-publish checkpoint or crash window.

## What This Changes

## Best Possible Solution

Keep the post-publish live-DB checkpoint idea, but make it result-aware, add a regression that proves the live DB metadata survives without close-time checkpoint replay, and coordinate it with the broader memory reindex race fix.

## Reproduction Assessment

Yes, at source level: current main publishes rebuilt memory metadata into the live DB after the shadow DB is closed, and no live-DB checkpoint exists before the manager continues. I did not run a hard-kill OpenClaw reproduction for the latest PR shape.

## Solution Assessment

No as-is. The post-publish checkpoint is the right layer for this durability hardening, but the patch must read the checkpoint result and the tests must prove live-DB crash durability rather than only observing any checkpoint call.
