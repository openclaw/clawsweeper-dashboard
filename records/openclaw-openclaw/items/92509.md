## Summary

Keep this PR open, but the current branch is not merge-ready: the runtime checkpoint is added to `writeMeta()`, while current main calls `writeMeta()` against the shadow reindex DB and only later publishes rows into the live per-agent DB. That leaves the live publish crash window unresolved.

## What This Changes

This PR adds a `PRAGMA wal_checkpoint(TRUNCATE)` call after memory-core `writeMeta()` and adds WAL checkpoint tests for per-agent memory DB metadata.

## Best Possible Solution

Move the durability barrier to the live per-agent DB publish path, inspect the checkpoint result there, and prove the actual OpenClaw reindex/publish path survives the targeted crash window.

## Reproduction Assessment

Partly. The author supplied standalone Node SQLite hard-kill output, and source inspection shows the current main shadow-build/live-publish window, but I did not run a hard-kill repro against current main or this branch.

## Solution Assessment

No. The durability idea is useful, but this implementation checkpoints the shadow DB; the maintainable fix is to checkpoint and verify the live target DB after publication.
