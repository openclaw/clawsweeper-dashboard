Full review comments:

- **[P2] Check the checkpoint result before claiming durability:** `extensions/memory-core/src/memory/manager-sync-ops.ts:2802`
  - body: `PRAGMA wal_checkpoint(TRUNCATE)` can report `busy` or leave frames uncheckpointed without giving this code a useful signal through `exec()`. Because the catch block also treats thrown checkpoint failures as non-fatal, `sync()` can proceed through the same crash window this PR is meant to close. Use `prepare(...).get()` and require a completed checkpoint, or surface a clear warning/failure when the live DB is still not durable.
  - confidence: 0.87
- **[P2] Make the test observe the live DB checkpoint:** `extensions/memory-core/src/memory/manager.wal-checkpoint.test.ts:139`
  - body: This assertion only counts any `PRAGMA wal_checkpoint(TRUNCATE)` during `sync()`. Current main already checkpoints the shadow DB when `closeMemoryDatabase(tempDb)` runs inside `sync()`, so this can pass without proving a checkpoint on `originalDb` after `publishMemoryDatabaseTables()`. The regression needs to distinguish the live connection or copy/read the main DB before manager close so it fails for the actual crash window.
  - confidence: 0.82
