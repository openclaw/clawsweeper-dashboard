Keep open: the post-publish checkpoint targets a real memory-index durability gap, but the patch still treats SQLite checkpoint execution as success without inspecting the result and the supplied proof does not exercise the current OpenClaw live-DB crash window.

## What This Changes

The PR adds a post-publish `PRAGMA wal_checkpoint(TRUNCATE)` call to memory-core’s full reindex path and adds WAL checkpoint coverage for the per-agent memory database.

## Best Possible Solution

Keep the post-publish checkpoint concept, but make it result-aware and add proof that the live per-agent DB metadata survives a crash before close.

## Reproduction Assessment

No high-confidence OpenClaw hard-kill reproduction is present for the latest PR shape. The WAL-only metadata failure is source-plausible and supported by copied SQLite proof, but it does not exercise the current post-publish live DB path.

## Solution Assessment

No. The post-publish checkpoint location is the right layer, but the implementation should inspect SQLite’s checkpoint result and the regression proof should fail on current main.
