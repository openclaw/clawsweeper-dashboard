## Summary

Keep open: current main and v2026.6.11 still expose split memory backend, QMD, scalar plugin-slot, and compaction memory-flush controls, while https://github.com/openclaw/openclaw/pull/88504 only covers the role-slot slice and remains unmerged.

## What This Changes

The issue asks for a coherent memory-management contract so users do not see divergent SQLite, QMD Markdown, or disabled-memory behavior across setups.

## Best Possible Solution

Define one maintainer-approved memory contract covering backend selection, active memory plugin ownership, automatic flush/write behavior, workspace or agent storage scope, and doctor migration, then coordinate it with the open role-slot and Memory MVP tracks.
