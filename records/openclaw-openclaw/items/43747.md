## Summary

Keep open: current main and v2026.6.11 still expose split memory backend, QMD, scalar memory-plugin slot, and compaction memory-flush controls, while the related role-slot PR is open and only covers part of the broader memory-management consistency request.

## What This Changes

The issue asks for a coherent memory-management contract so builtin SQLite, QMD Markdown flushes, disabled memory, and workspace or agent scoping behave predictably across users.

## Best Possible Solution

Settle one maintainer-approved memory contract covering backend selection, active memory plugin ownership or roles, automatic flush/write behavior, and upgrade migration, then land the implementation through the existing role-slot and memory MVP tracks.
