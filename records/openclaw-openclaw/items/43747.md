## Summary

Keep open: current main and v2026.6.11 fix the old single `main.sqlite` symptom, but the broader memory-management contract is still split across backend config, plugin-slot ownership, QMD settings, and compaction memory flush behavior; the related role-slot PR is still open and does not fully close this broader request.

## What This Changes

The issue asks for a strict, unified memory-management contract so builtin SQLite, QMD daily Markdown, and disabled or misconfigured memory behave predictably across users.

## Best Possible Solution

Settle one maintainer-approved memory contract that covers backend selection, active memory plugin ownership, automatic flush/write behavior, and upgrade migration, then land it through the existing role-slot and memory MVP work instead of adding an isolated memory knob.
