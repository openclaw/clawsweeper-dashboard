## Summary

Keep open: current main and v2026.6.11 still expose separate memory backend, QMD, single memory-plugin slot, and compaction memory-flush controls, so the broader request for a coherent memory-management contract remains unresolved.

## What This Changes

The issue asks OpenClaw to make memory behavior consistent across builtin SQLite memory, QMD daily files, and disabled or misconfigured memory states.

## Best Possible Solution

Settle one maintainer-approved memory contract covering backend selection, active memory plugin roles, automatic flush/write behavior, per-agent storage, docs, and upgrade migration, then land it through the existing role-slot and Memory MVP tracks.
