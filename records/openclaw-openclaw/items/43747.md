- `impact:ux-friction`: Different users can see SQLite indexing, daily Markdown files, or no apparent memory behavior, creating avoidable setup and team-consistency confusion.

## Summary

Keep open: current main and v2026.6.11 still expose separate memory backend, memory plugin slot, memory-search provider, and compaction flush controls, while the open role-slot PR only addresses part of the broader memory consistency problem.

## What This Changes

The issue asks OpenClaw to make memory behavior consistent across builtin SQLite, QMD daily Markdown, disabled/misconfigured memory, and proposed unified memory mode/config semantics.

## Best Possible Solution

Define one maintainer-approved memory contract covering backend selection, active memory plugin ownership, automatic flush/write behavior, storage layout, and doctor migration, coordinated with the open role-slot and Memory MVP work.
