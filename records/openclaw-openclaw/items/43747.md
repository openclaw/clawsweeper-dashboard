## Summary

Keep open: current main and v2026.6.11 have improved one symptom by moving builtin memory indexes to per-agent SQLite, but they still expose separate memory backend, memory plugin slot, QMD, and compaction memory-flush surfaces rather than the unified memory-management contract requested here.

## What This Changes

The issue requests a strict, unified memory-management contract so builtin, QMD, mixed memory behavior, and workspace/agent storage are understandable and consistent.

## Best Possible Solution

Settle one maintainer-approved memory contract that explains backend selection, active memory plugin ownership, automatic flush/write behavior, and upgrade migration, then land it through the existing role-slot and memory MVP work rather than adding another standalone memory knob.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still expose separate memory.backend, plugins.slots.memory, memory.qmd.*, and compaction memoryFlush surfaces; I did not run a live three-user reproduction.

## Solution Assessment

Unclear as proposed. A single memory.type field may be too narrow for the active plugin-slot and memory-write lifecycle problems, so the best path is a maintainer-approved contract that coordinates the open role-slot and memory MVP work with doctor/docs coverage.
