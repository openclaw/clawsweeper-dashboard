## Summary

Keep open: current main and v2026.6.11 still expose separate builtin/QMD backend config, a single scalar memory plugin slot, and an independent compaction memory-flush path, so the reported memory-management inconsistency is not resolved by current code.

## What This Changes

The issue asks for a coherent memory-management contract so builtin SQLite, QMD Markdown, and disabled or misconfigured memory states behave predictably across users, possibly through explicit memory mode configuration.

## Best Possible Solution

Define one maintainer-approved memory contract covering backend selection, active memory plugin ownership, automatic flush/write behavior, storage layout, and doctor migration, then route implementation through the existing role-slot and Memory MVP tracks.
