## Summary

Keep open: current main and the latest release still expose split memory backend, QMD, plugin-slot, and automatic flush controls, so the reporter's request for a coherent memory-management contract is still unresolved.

## What This Changes

The issue asks OpenClaw to define a consistent memory-management model across builtin SQLite memory, QMD Markdown memory, automatic memory flushes, and plugin-owned memory behavior.

## Best Possible Solution

Settle one maintainer-approved memory contract covering backend selection, active memory plugin ownership, automatic flush/write behavior, and upgrade migration, then land it through the existing role-slot and Memory MVP tracks.
