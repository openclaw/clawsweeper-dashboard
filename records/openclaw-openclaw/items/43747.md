## Summary

Keep open: current main and the latest release still expose separate builtin/QMD backend, memory plugin slot, memorySearch, and compaction flush controls, while the broader coherent memory contract remains a product/API decision with only partial open implementation paths.

## What This Changes

The issue requests a coherent, configurable memory-management contract so builtin SQLite memory, QMD daily Markdown memory, and disabled or misconfigured memory do not diverge unpredictably across users.

## Best Possible Solution

Settle one maintainer-approved memory contract covering backend selection, active memory plugin ownership, automatic flush/write behavior, operator-facing memory surfaces, and upgrade migration, then close this issue after the chosen implementation path lands.
