## Summary

Keep open: current main and v2026.6.11 still expose separate builtin/QMD backend selection, a single active memory plugin slot, and automatic daily Markdown memory flush behavior, so the broader consistency problem is not implemented yet.

## What This Changes

The issue asks for one clear memory-management contract so teams do not see divergent SQLite indexing, daily Markdown/QMD memory files, or disabled-looking memory behavior across setups.

## Best Possible Solution

Settle one maintainer-approved memory contract that covers backend selection, active memory plugin ownership, automatic flush/write behavior, docs, and doctor migration, then land it through the existing role-slot and memory MVP work instead of adding an isolated config knob.
