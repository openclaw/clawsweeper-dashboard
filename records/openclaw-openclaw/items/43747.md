## Summary

Keep open: current main and the latest release still expose separate builtin/QMD backend, memory plugin slot, QMD, and compaction memory-flush surfaces, while the broader unified memory-management contract requested here remains unsettled.

## What This Changes

The issue requests a coherent memory-management contract because users observed SQLite memory, QMD daily Markdown memory, and no apparent memory behavior across different setups.

## Best Possible Solution

Settle one maintainer-approved memory contract that explains backend selection, active memory plugin ownership, automatic flush/write behavior, and upgrade migration, then land it through the existing role-slot and memory MVP work rather than adding another standalone memory knob.
