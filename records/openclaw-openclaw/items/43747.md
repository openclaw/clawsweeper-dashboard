## Summary

Keep open: current main and v2026.6.11 still expose separate memory backend, QMD, memorySearch, plugin-slot, and compaction-flush surfaces; per-agent SQLite storage fixes one old symptom but not the requested unified memory contract.

## What This Changes

The issue asks for one predictable memory-management contract so built-in SQLite memory, QMD daily files, and disabled memory do not vary unexpectedly across users.

## Best Possible Solution

Define a maintainer-approved memory mode or role contract that reconciles backend selection, memorySearch, QMD, compaction flush, plugin ownership, workspace scoping, docs, and doctor migration before changing runtime behavior.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 still have no `memory.type` contract and keep backend, memorySearch, QMD, plugin-slot, and compaction-flush behavior as separate surfaces. I did not run a live three-install comparison.

## Solution Assessment

Unclear. The proposed `memory.type` switch is plausible, but the best fix needs maintainer direction across config shape, backend behavior, workspace storage, plugin ownership, docs, and migration.
