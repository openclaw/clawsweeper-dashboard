- `impact:session-state`: The request affects durable memory, recall, QMD indexing, compaction flushes, plugin ownership, and agent/session context continuity.
- `impact:ux-friction`: Different setups can visibly produce SQLite indexes, daily Markdown memory files, or no apparent recall, creating avoidable team setup confusion.

## Summary

Keep open: current main and the latest release still expose separate backend, QMD, plugin-slot, and compaction memory-flush controls, so the request for a coherent memory-management contract remains unresolved and needs maintainer product/API direction.

## What This Changes

The issue asks OpenClaw to define a consistent memory-management contract across builtin SQLite memory, QMD Markdown memory, disabled memory, per-workspace storage, and user-facing configuration.

## Best Possible Solution

Settle one maintainer-approved memory contract covering backend selection, active memory plugin ownership, automatic flush/write behavior, and upgrade migration, then land it through the existing role-slot and Memory MVP tracks.
