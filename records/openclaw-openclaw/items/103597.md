## Summary

A P1 correctness defect remains in the revised Memory Core logic: non-empty target namespaces are treated as proof that the entire legacy source was imported, so incomplete memory state can become a non-blocking notice. The producer-owned warning/notice boundary is preferable to consumer string matching, but this PR is not merge-ready until completion is explicit and real gateway behavior is shown.

## What This Changes

The PR moves idempotent Matrix, Memory Core, and Workboard SQLite migration skips from warnings to notices while retaining partial Memory Core targets and differing Workboard rows as warnings.

## Best Possible Solution

Give each producer an explicit, testable convergence invariant: Matrix existing-target skips and Workboard equal-value rows may be notices, while Memory Core should use a durable completion record or exact source-to-target coverage and keep every partial, conflicting, or uncertain state as a warning.
