## Summary

Keep open: current main has the active/non-streaming steering runtime fix, but the ordinary Discord/bound-thread ingress path can still serialize same-session messages before they reach active-run queue policy, so the central user problem is not fully implemented.

## What This Changes

The issue requests that messages sent in Discord and other chat-bound ACP/sub-agent sessions steer the running agent while work is active instead of waiting for a later turn.

## Best Possible Solution

Land or replace a coordinated admission-layer fix that lets same-session Discord and bound ACP/sub-agent messages reach active-run queue policy while preserving ordering, route isolation, and active/non-stopped runtime steering checks.
