- `P1`: The issue affects an active agent/channel workflow where user steering messages can miss the running ACP or sub-agent turn during real chat use.
- `impact:message-loss`: Messages intended for the running turn can be delayed into later follow-up handling instead of delivered to the active turn at the intended boundary.

## Summary

Keep open: current main has partial active/non-streaming and Codex `turn/steer` support, but Discord inbound jobs still serialize by session or route key before processing, so ordinary bound-thread messages can still wait behind the running turn. The open candidate PR targets the remaining admission layer, but it is conflicting and has unresolved session-state/message-delivery semantics.

## What This Changes

Requests that messages sent in Discord bound ACP or sub-agent threads be delivered to the active running agent as steering input instead of waiting until the turn ends.

## Best Possible Solution

Refresh or replace the admission/ingress fix so same-session Discord ACP and sub-agent thread messages reach active-run queue policy while preserving current active/not-stopped steering, terminal-session recovery, no-visible fallback behavior, and channel ordering guarantees.
