## Summary

Keep open: current main has the active-run steering path once a prompt reaches queue policy, but Discord-bound ordinary messages can still serialize by session key before that policy is evaluated, and the related fixes are only partial or still open.

## What This Changes

The issue requests live user input from Discord threads and other chat surfaces to steer active ACP or sub-agent sessions instead of waiting until the current turn finishes.

## Best Possible Solution

Keep the issue open until maintainers land or replace a coordinated ingress/admission fix that lets safe same-session Discord and ACP-bound messages reach active-run queue policy without misrouting first turns, cross-thread messages, or sub-agent state.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: Discord enqueues by resolved session key before dispatch reaches active-run queue policy, and the current queue-policy bypass is gated on queuedFollowupLifecycle that Discord does not pass. I did not run a live Discord ACP session in this read-only cleanup review.

## Solution Assessment

Unclear as an automated fix: the desired behavior is right, but the best implementation must be chosen at the channel ingress/admission boundary so it preserves first-turn setup, thread routing, and active session ownership. The open candidate PR is relevant but still needs maintainer coordination and refresh.
