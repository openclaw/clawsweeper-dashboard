## Summary

Keep open: current main has partial runtime/Codex steering support, but ordinary Discord/bound-thread messages can still wait behind channel or reply-operation admission before active-run queue policy can steer them.

## What This Changes

The issue requests live inbound steering for running ACP and sub-agent sessions from Discord and similar chat surfaces so thread messages can reach the active agent turn instead of waiting for turn completion.

## Best Possible Solution

Refresh or replace the admission-layer fix so same-session Discord ACP and sub-agent thread messages can reach active-run queue policy while preserving terminal recovery, route/thread safety, and explicit fallback semantics.
