## Summary

Keep open: current main has a merged partial steering fix, but the broader Discord/chat ACP admission problem remains. The issue overlaps canonical https://github.com/openclaw/openclaw/issues/48003 and open admission work in https://github.com/openclaw/openclaw/pull/89238, so this needs maintainer direction rather than a new autonomous fix PR.

## What This Changes

Request to let Discord/chat messages reach running ACP or sub-agent sessions mid-turn instead of waiting until the current turn finishes.

## Best Possible Solution

Land or replace a narrow maintainer-approved admission design that lets eligible same-session chat messages reach the active-run steering path during ACP/sub-agent turns while preserving queue modes, channel ordering, and session/thread isolation.

Is this the best way to solve the issue? The product direction is aligned for existing thread-bound sessions, but the final implementation path should be coordinated through the canonical issue and open admission PR rather than a separate autonomous fix.
