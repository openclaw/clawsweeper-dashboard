## Summary

Keep open: current main fixed the runtime-side active/non-streaming steer gate, but the ordinary Discord/bound-message admission path can still hold messages before they reach active-run queue policy, and the remaining work is already represented by an open candidate PR that needs maintainer coordination.

## What This Changes

The issue asks for messages sent in Discord or other chat threads during running ACP or sub-agent sessions to steer the active turn instead of waiting until the current turn finishes.

## Best Possible Solution

Land or replace the active-turn admission fix from https://github.com/openclaw/openclaw/pull/89238 so same-session Discord and bound ACP/sub-agent messages reach queue policy while preserving active-run lifecycle, routing, and fallback semantics.
