## Summary

Keep open: current main has the active/non-streaming steering gate, but ordinary Discord and bound ACP thread messages still have to pass through channel/admission serialization before active-run queue policy, and the remaining work is already tied to an open canonical issue and conflicting candidate PR.

## What This Changes

The issue requests that messages sent in a Discord or other chat thread during a running ACP or sub-agent session be delivered to that active session instead of waiting for the current turn to finish.

## Best Possible Solution

Land or replace a coordinated admission-layer fix that lets same-session Discord and bound ACP messages reach active-run queue policy while preserving the current active/not-stopped runtime steering checks and channel ordering guarantees.
