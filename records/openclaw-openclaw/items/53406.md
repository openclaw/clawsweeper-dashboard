## Summary

Keep open: current main has explicit ACP and Codex steering support plus a partial active/non-streaming runtime fix, but ordinary Discord/bound-thread input can still be serialized before it reaches active-run queue policy. The remaining behavior overlaps the broader open queue-steering issue and an open conflicting candidate PR, so it needs maintainer coordination rather than cleanup closure.

## What This Changes

The issue asks for messages sent in Discord or other chat-bound ACP/sub-agent sessions to steer the running session while work is in progress instead of waiting for the current turn to finish.

## Best Possible Solution

Refresh or replace the admission/ingress fix so same-session Discord ACP and sub-agent thread messages reach active-run queue policy while preserving active/not-stopped steering, terminal-session recovery, no-visible fallback behavior, and channel ordering guarantees.
