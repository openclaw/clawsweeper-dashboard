## Summary

Keep open: current main fixed the inner active/non-streaming steering gate, but Discord same-session inbound messages still enter the channel run queue before reply queue policy can steer a running ACP/sub-agent turn.

## What This Changes

Allow Discord thread messages and other chat-surface input to steer running ACP/sub-agent sessions instead of waiting until the active turn finishes.

## Best Possible Solution

Keep the issue open until maintainers land or replace a coordinated admission-layer fix that lets same-session Discord ACP/sub-agent messages reach the active-run steering path without regressing queue serialization safety.

## Reproduction Assessment

Yes at source level: Discord same-session inbound jobs are serialized before processDiscordMessage reaches queue-steer policy, and the queue test asserts a second same-session message waits for the first queued run.

## Solution Assessment

No complete current solution: #98126 fixed active non-streaming injection once a message reaches reply handling, but the Discord admission path still needs a coordinated fix such as #89238 or a successor.
