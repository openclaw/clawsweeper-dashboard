## Label Justifications

- `P1`: The issue affects an active agent/channel workflow where user steering messages can miss the running ACP or sub-agent turn during real chat use.
- `impact:session-state`: The failure depends on whether an inbound message is associated with the correct active session/thread and active-run queue policy.

## Summary

Keep open: current main has the runtime-side active/non-streaming steering fix, but ordinary Discord bound-thread messages still enter the Discord run queue and reply-operation admission path before active-run queue policy can steer them.

## What This Changes

Allow normal messages in Discord and other chat-bound ACP or sub-agent sessions to steer the running agent instead of waiting for the current turn to finish.

## Best Possible Solution

Land or replace a coordinated admission-layer fix that lets same-session Discord and bound ACP messages reach active-run queue policy while preserving active/not-stopped steering checks and channel ordering guarantees.
