## Summary

Keep open: current main has the active/non-streaming steering fixes and documented ACP steering commands, but ordinary Discord/thread-bound messages still pass through serialized channel and admission paths before active-run queue policy, and the remaining work is already entangled with a conflicting candidate PR and fallback/session-state semantics.

## What This Changes

Allow messages in Discord and other chat threads for running ACP or sub-agent sessions to steer the active agent immediately instead of waiting for the current turn to finish.

## Best Possible Solution
