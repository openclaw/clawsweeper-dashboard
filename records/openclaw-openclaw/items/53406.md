## Summary

Keep open: current main has the runtime-side active/non-streaming steering fix, but ordinary Discord and bound-thread messages still pass through keyed channel serialization and a narrow reply-admission bypass before they can reach active ACP/sub-agent queue policy.

## What This Changes

The issue asks for Discord and other chat messages sent in an active ACP or sub-agent thread to steer the running session instead of waiting for a later turn.

## Best Possible Solution

Land or replace a coordinated admission-layer fix that lets same-session Discord and bound ACP/sub-agent messages reach active-run queue policy while preserving current active/non-stopped steering checks and channel ordering guarantees.
