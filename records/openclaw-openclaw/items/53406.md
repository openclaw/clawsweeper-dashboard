## Summary

Keep open: current main has active/not-stopped runtime steering and Codex `turn/steer` support, but Discord inbound jobs still serialize by session key through the channel run queue before dispatch, so normal thread messages can still wait behind the active turn instead of reaching the steering queue.

## What This Changes

Allow normal messages in a Discord thread-bound ACP or sub-agent session to steer the running agent mid-turn instead of waiting for the active turn to finish.

## Best Possible Solution

Keep this open as the Discord ACP/sub-agent active-steering tracker until maintainers land a post-context, active-session-aware ingress path that preserves channel ordering and replay guarantees.

## Reproduction Assessment

Yes. Source inspection shows Discord same-session messages still enter a per-session channel run queue before reply-layer active steering can run, while the documented queue contract expects eligible messages to reach the active runtime.

## Solution Assessment

Unclear as a final implementation path. The runtime active/not-stopped fix is the right partial direction, but maintainers still need to choose the safe Discord ingress/admission shape across ACP, sub-agent, replay, and ordering boundaries.
