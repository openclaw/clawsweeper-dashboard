## Label Justifications

- `impact:session-state`: The failure depends on associating the inbound message with the correct active session, thread binding, and active-run queue policy.

## Summary

Keep open: current main fixes the active/non-streaming runtime steering gate, but ordinary Discord and bound ACP thread messages still need a coordinated ingress/admission fix before they reliably reach active-run queue policy.

## What This Changes

The issue requests that ordinary Discord and other chat-thread messages steer running ACP and sub-agent sessions instead of waiting until the active turn finishes.

## Best Possible Solution

Land or replace a coordinated admission-layer fix that lets same-session Discord and bound ACP messages reach active-run queue policy while preserving active/not-stopped runtime steering checks, stale-operation recovery, and channel ordering guarantees.
