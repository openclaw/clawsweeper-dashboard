## Summary

Keep open: current main fixes the active/non-streaming runtime steering gate and Codex `turn/steer` forwarding, but ordinary Discord and bound ACP thread messages still pass through channel and reply-admission serialization before active-run queue policy can run.

## What This Changes

The issue asks OpenClaw to let Discord and other chat-surface messages steer active ACP/sub-agent sessions instead of waiting behind busy session queues.

## Best Possible Solution

Refresh or replace the admission-layer fix so same-session Discord and bound ACP/sub-agent messages can reach active-run queue policy while preserving active/not-stopped steering, no-visible fallback behavior, terminal-session recovery, and channel ordering guarantees.
