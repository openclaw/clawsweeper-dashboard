## Summary

Keep this PR open, but do not merge the current patch: it introduces a new undocumented 1 MiB limit only for file input, so previously accepted file-based patches can fail while equivalent stdin input remains accepted. The focused tests are useful, but the permanent input-size contract needs maintainer confirmation and real CLI proof.

## What This Changes

The PR adds a pre-read regular-file and 1 MiB size check to `config patch --file`, plus oversized and normal-file tests.

## Best Possible Solution

Define one documented config-patch input limit, implement it through a shared bounded reader for both file and stdin modes, retain a final byte-cap check, and prove oversized, normal, non-regular, and equivalent stdin behavior with real CLI output.
