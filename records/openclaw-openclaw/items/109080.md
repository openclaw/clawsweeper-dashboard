## Summary

This PR fixes policy forwarding for the initial Vydra submission, but its asynchronous job-status requests still bypass the resolved dispatcher and private-network policy; the previously reported P1 remains unfixed at the same head SHA.

## What This Changes

The branch sanitizes `models.providers.vydra.request` and passes it to Vydra's shared provider HTTP configuration resolver.

## Best Possible Solution

Use the existing guarded provider polling helper, or an equivalent bounded local helper, so Vydra API submission and job-status polling share the resolved transport policy while generated-media downloads remain deliberately headerless and separately scoped.
