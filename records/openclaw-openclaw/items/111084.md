## Summary

This issue remains necessary: the documented hook contract distinguishes prompt-time context injection from transcript writes, but it does not establish whether `showInjected` must keep the injected bytes out of in-memory history. The reported cache regression is credible enough to retain, while the session and plugin-contract boundary needs a current-main source trace before selecting a repair.

## What This Changes

Request that context shown through `showInjected` remain ephemeral rather than being retained in session history and later provider requests.

## Best Possible Solution

Define `showInjected` as a presentation-only behavior and construct injected text at the prompt-build boundary so persisted session messages and provider-history replay retain the clean user prompt; add a regression test that compares multi-turn serialized prefixes with the option enabled and disabled.
