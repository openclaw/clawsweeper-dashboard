## Label Justifications

- `P2`: The bug has a limited macOS remote-mode blast radius but can leak SSH processes and make remote Gateway connectivity unreliable.
- `impact:crash-loop`: Repeated rejected launches can leave child SSH processes and consume remote connection capacity, causing process-level availability degradation.
- `maturity:stable`: The affected `macos-gateway-host` taxonomy feature is currently scored M4 Stable.

## Summary

Keep open. Current main and v2026.6.11 both contain the reported startup ordering, and the merged orphan-reaping work only mitigates the later cleanup stage; the protected `maintainer` label requires explicit maintainer handling.

**Likely related people**
- `steipete` — high confidence; assigned owner and principal recent contributor to the macOS tunnel lifecycle.
- Devin Robison — medium confidence; recent contributor to the SSH tunnel implementation and its security constraints.

## What This Changes

Prevent rejected duplicate macOS app processes from initializing Gateway connectivity or spawning remote SSH tunnels before singleton acceptance.

## Best Possible Solution

Make singleton acceptance own one canonical post-launch startup hook, keep connectivity singletons inert until that hook, and add regression coverage proving a duplicate remote launch activates the existing app without invoking tunnel creation.
