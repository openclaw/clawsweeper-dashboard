Keep this PR open, but it is not merge-ready: the intended FTS fallback matches the documented memory contract, while the implementation misses the normal non-throwing missing-credentials path and the submitted evidence is test-only rather than real behavior proof.

## What This Changes

The PR changes memory-core to use FTS-only search when an optional embedding provider cannot initialize and permits read-only keyword searches against an existing semantic index.

## Best Possible Solution

Derive optional-provider fallback eligibility from a typed provider requirement/result rather than an exception-only string prefix, support both thrown and non-throwing optional failures, preserve explicit-provider fail-closed behavior, and prove fresh plus existing-index behavior in a real CLI setup.
