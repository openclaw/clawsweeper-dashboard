## Label Justifications

- `P1`: The proposed behavior addresses a broken memory search/index workflow for users relying on the optional default embedding provider without configured credentials.
- `merge-risk: 🚨 compatibility`: Existing users would see successful but potentially stale FTS results where the current paused-index behavior prevents those results.
- `merge-risk: 🚨 session-state`: The fallback reads an existing memory index while synchronization is blocked, which can make indexed memory state lag behind workspace memory files.

## Summary

Keep this PR open for maintainer review: the patch and real CLI evidence support the optional-provider fallback, but allowing searches against an existing semantic index after sync is deliberately refused changes the freshness contract and needs an explicit owner decision.

## What This Changes

The branch converts unavailable optional embedding providers to FTS-only memory mode, keeps explicit providers fail-closed, and permits read-only FTS searches of existing semantic indexes when credentials later disappear.

## Best Possible Solution

Make the supported contract explicit: either retain the existing pause until embeddings return, or land the read-only FTS fallback with a clear stale-index status and user recovery path.
