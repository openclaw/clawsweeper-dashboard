## Summary

Keep open: this is a focused bug-fix PR, but it still awaits `response.text()` before applying `maxBytes`, so it does not fix the linked no-reader availability problem. Current main already truncates the returned snippet, but the pre-truncation whole-body read remains the real issue.

## What This Changes

The PR changes the no-reader branch of `readResponseBodySnippet` to encode the result of `response.text()`, slice it to `maxBytes`, strip trailing replacement characters, and adds a standalone proof script.

## Best Possible Solution

Revise the no-reader capped path so it never calls whole-body `text()` or `arrayBuffer()` before the cap, using the existing `src/agents/tools/web-shared.ts` fail-closed pattern or another truly bounded source, with a Vitest regression that spies those methods are not invoked.
