## Summary

Keep this issue open. The approvals-first/config-second flow is shipped, and current main still abandons rollback when a concurrent approvals write changes the file hash. The linked approval-race PR provides the appropriate locked transaction seam, but its published head still ignores a failed whole-file restore, so this distinct compensation bug remains unfixed.

**Likely related people**
- @steipete — high confidence; recent contributor to the approvals transaction redesign and active linked PR.
- @Takhoffman — high confidence; introduced the local exec-policy synchronization and rollback flow.

## What This Changes

Make failed local `exec-policy` synchronization remove only its own approvals-policy changes while preserving concurrent edits and explicitly reporting compensation failure.

## Best Possible Solution

Implement conservative field-aware compensation within the locked approvals transaction: preserve unrelated concurrent socket, agent, and allowlist edits; revert command-owned policy fields only when ownership is provable; never make independently changed policy more permissive; and combine compensation persistence failure with the original config error.
