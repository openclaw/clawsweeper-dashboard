- `merge-risk: 🚨 compatibility`: The new allowlist can change behavior for existing templated session keys whose rendered IDs contain characters outside the proposed regex.

## Summary

Keep this PR open: the hardening is aimed at a real gateway hook session-routing risk, but the current patch silently converts invalid rendered session keys into an absent key, so the request can still dispatch on the default or generated session instead of failing closed. The PR also does not include after-fix real webhook behavior proof.

## What This Changes

The branch adds a post-render regex allowlist for mapped webhook `sessionKey` templates and returns `undefined` when the rendered key contains disallowed characters.

## Best Possible Solution

Reject invalid rendered mapping session keys with a structured 400 before dispatch, add focused regression coverage for invalid and valid mapped webhook cases, and include redacted live `/hooks/<mapping>` proof.
