## Summary

Keep this PR open, but do not merge it yet: the proposed recovery path has a blocking delivery-deduplication defect, and the available evidence does not demonstrate safe behavior in a real Codex app-server session.

## What This Changes

The PR adds a one-attempt internal continuation for agent turns that end with executed tools and no visible assistant response.

## Best Possible Solution

Continue the existing Codex thread only when all tool items are complete, skip recovery when a messaging tool already committed delivery, and make the recovery attempt incapable of dispatching tools before proving the path with a redacted live trajectory.
