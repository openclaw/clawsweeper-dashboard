## Summary

Keep open: current main and the latest release still expose additive prompt/context hook mutations only, so plugins cannot replace the submitted user prompt. The remaining work is a maintainer-owned plugin API and security-boundary decision rather than conservative cleanup.

## What This Changes

The issue requests a plugin hook result field that lets `before_agent_start` replace the current user prompt before the model call.

## Best Possible Solution

Choose one documented prompt-replacement contract, then implement it consistently across prompt-build runners with precedence rules, `allowPromptInjection` behavior, docs, and regression coverage.

- **Reject prompt replacement:** Keep plugin prompt hooks additive-only and direct oversized-prompt mitigation to context-engine, memory, or provider-side controls.

Unclear as proposed: `promptOverride` only on legacy `before_agent_start` is too narrow. The maintainable solution should define the prompt-build contract, legacy compatibility, security filtering, and cross-runner behavior together.
