## Summary

Keep open: current main and v2026.6.11 still expose only additive prompt/context hook mutations, so plugins cannot replace the submitted user prompt. The remaining work is a maintainer-owned plugin API and security-policy decision, especially because broader mutating LLM-hook work is still open and not a safe canonical replacement yet.

## What This Changes

Request to let plugin prompt-build or legacy before_agent_start hooks replace the effective user prompt before the model call.

## Best Possible Solution

Choose one documented prompt-replacement contract, then implement it consistently across prompt-build runners with precedence rules, allowPromptInjection/security behavior, docs, and regression coverage.

## Reproduction Assessment

Yes at source level: current hook result types, merge logic, docs, and embedded/CLI runner paths expose no prompt replacement field or behavior. I did not run a live agent repro because the feature gap is directly visible in source.

## Solution Assessment

Unclear as proposed: promptOverride on legacy before_agent_start is plausible, but the best long-term solution needs a maintainer choice across before_prompt_build, legacy compatibility, and the overlapping mutating llm_input design.
