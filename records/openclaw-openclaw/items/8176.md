## Summary

Current main and the latest checked release still expose only additive prompt/context hook results, so the requested plugin prompt replacement capability remains missing and needs an intentional plugin API and security-boundary decision before implementation.

## What This Changes

Issue #8176 requests a plugin hook capability that can replace the user prompt, not just prepend or append context.

## Best Possible Solution

Define one documented prompt replacement contract across embedded, CLI, and Codex paths, with explicit merge precedence, allowPromptInjection filtering, tests, and docs rather than adding a legacy-only override.

Options:

- **Add prompt-build replacement contract (recommended):** Extend before_prompt_build as the canonical plugin API, optionally bridge legacy before_agent_start, and enforce allowPromptInjection and precedence across all runners.
- **Use broader LLM interception:** Resolve this through the llm_input/llm_output modifying hook direction and keep before_prompt_build additive-only.
- **Reject prompt replacement:** Keep plugins limited to additive context/system prompt changes and document that full prompt replacement is intentionally unsupported.
