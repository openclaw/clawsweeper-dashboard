## Summary

Keep open: current main still exposes additive prompt/context and system-prompt hook fields only, so plugins cannot replace the submitted user prompt through `before_prompt_build` or legacy `before_agent_start`; related direct attempts are closed unmerged and the broader open LLM interception PR is not a safe canonical fix yet.

## What This Changes

The issue requests a plugin hook result field that can replace the effective user prompt before an agent model call.

## Best Possible Solution

Keep this issue as the canonical tracker until maintainers either approve and document a prompt replacement API across `before_prompt_build` plus legacy `before_agent_start`, choose the broader `llm_input` boundary instead, or explicitly reject the capability.

## Reproduction Assessment

Yes. Source inspection on current main shows the hook result types, merge logic, embedded runner, CLI runner, Codex harness helper, and public docs all support additive/system prompt fields but no user-prompt replacement path.

## Solution Assessment

Unclear as a final implementation direction. A replacement field is plausible, but maintainers need to decide whether this belongs on `before_prompt_build`/legacy `before_agent_start` or the broader `llm_input` boundary, with explicit policy and ordering semantics.
