## Summary

Keep open: current main and v2026.6.11 still expose only additive context/system-prompt mutation for prompt hooks, with no user-prompt replacement field or runner path. The remaining work is a public plugin API and security/product decision, not a completed main-branch fix.

## What This Changes

Add a plugin hook result that lets `before_agent_start` or prompt-build logic replace the current user prompt before model submission.

## Best Possible Solution

Approve one documented prompt-replacement contract across `before_prompt_build` and legacy `before_agent_start`, including precedence, `allowPromptInjection` filtering, runner coverage, docs, and regression tests, or explicitly reject the capability in favor of another hook boundary.

## Reproduction Assessment

Yes, source-level: the hook types, merge logic, embedded runner, CLI runner, Codex harness helper, and docs expose additive context/system-prompt fields but no user-prompt replacement path.

## Solution Assessment

Unclear until maintainers choose the API boundary; a replacement field is plausible, but the best fix must settle naming, precedence, original-versus-effective prompt visibility, `allowPromptInjection`, observability, and cross-runner behavior.
