## What This Changes

The issue requests a plugin hook result field that can replace the current user prompt before model submission, with context prepend/append applied around the effective prompt.

## Best Possible Solution

Keep this as the canonical tracker until maintainers approve and document a user-prompt replacement contract across `before_prompt_build` and legacy `before_agent_start`, or explicitly choose another interception boundary such as LLM-input hooks.

## Reproduction Assessment

Yes, source-level: the current hook result types, merge logic, embedded runner, Codex harness helper, release tag, and docs all show additive context/system-prompt support but no user-prompt replacement path.

Unclear until maintainers choose the API and trust boundary. A replacement field is plausible, but the final shape must settle naming, precedence, cross-runtime behavior, and security filtering before implementation.
