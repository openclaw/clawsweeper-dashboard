## Summary

Keep open: current main and v2026.6.11 still expose additive prompt/context hook mutations only, so plugins cannot replace the submitted user prompt. The remaining work is a plugin API and security-boundary decision rather than conservative cleanup.

## What This Changes

The issue requests an optional hook result field that lets `before_agent_start` or its prompt-build successor replace the effective user prompt before model submission.

## Best Possible Solution

Choose one documented prompt-replacement contract, then implement it consistently across prompt-build runners with precedence rules, `allowPromptInjection` behavior, docs, and regression coverage.

## Reproduction Assessment

Yes, at source level: current hook result types, merge logic, docs, and embedded/CLI prompt paths expose no prompt replacement field or behavior. I did not run a live context-limit repro because the missing API is directly visible in source.

## Solution Assessment

Unclear as originally proposed: adding `promptOverride` only to legacy `before_agent_start` is too narrow. The maintainable solution should define the `before_prompt_build` contract, legacy compatibility, security filtering, and cross-runner behavior together.
