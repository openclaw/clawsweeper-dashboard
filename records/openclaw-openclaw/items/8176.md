## Summary

Keep open for a maintainer product and security decision. The last completed review found no public user-prompt replacement contract across the shared hook paths, while the later merged Codex work establishes adjacent prompt-hook behavior rather than proving the requested cross-runtime authority is complete.

## What This Changes

Add an opt-in plugin hook result that can replace the effective user prompt before an agent sends it to a model.

## System Context

Plugin prompt hooks run after OpenClaw receives a user message and before an agent harness assembles the model request. Their result affects the PI, CLI, and Codex execution paths that send prompts to providers.

## Architecture Diagram

flowchart LR
  A[User message] --> B[Plugin prompt hooks]
  B --> C[Prompt mutation policy]
  C --> D[Prompt assembly]
  D --> E[PI, CLI, and Codex harnesses]
  E --> F[Model request]
  B --> G[Audit and regression tests]

## Best Possible Solution

Adopt one documented, policy-gated prompt-replacement contract at the typed before_prompt_build boundary, define deterministic multi-plugin precedence and audit semantics, adapt the legacy hook only as compatibility requires, and prove identical behavior in every supported harness.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should installed plugins be granted a public, policy-gated ability to replace the user-authored prompt, and if so should that authority live in before_prompt_build with legacy before_agent_start adapted only for compatibility?

Rationale: This is an additive plugin SDK capability that can redact or truncate user intent before provider submission, so implementation cannot safely choose its authority, precedence, and security/audit contract without maintainer direction.

Likely owner: EVA

Owner reason: The plugin-hook contract history most directly covers the shared API and merger decisions required here.

Owner confidence: medium

Options:

- **Approve a typed replacement contract (recommended):** Add one policy-gated replacement field to before_prompt_build, define precedence and audit behavior, and carry it through every supported harness.
- **Keep hooks additive:** Retain prepend/append and system-context mutation only, directing redaction or truncation to another explicit host-owned seam.
- **Defer pending a broader prompt-policy design:** Pause the request until maintainers define a unified contract for prompt mutation, provenance, and plugin trust boundaries.
