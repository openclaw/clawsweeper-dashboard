## Summary

Current main and the latest release still support only additive user-context and system-prompt mutations; no supported hook can replace the submitted user prompt, and all direct implementation candidates are closed unmerged. The item remains necessary as the canonical security-sensitive plugin API decision.

## What This Changes

Allow `before_prompt_build` and legacy `before_agent_start` hooks to replace the current user prompt before additive context wrapping and model submission.

## Best Possible Solution

If maintainers approve whole-prompt mutation, add one replacement field to the shared `before_prompt_build` contract, constrain it with `allowPromptInjection`, use highest-priority-first precedence, apply prepend/append context around the replacement, and cover embedded, CLI, and Codex paths with contract, ordering, policy, and runtime tests.
