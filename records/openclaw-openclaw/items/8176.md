## Summary

Keep open. Current main and v2026.6.11 still provide additive prompt mutations and a final-prompt blocking hook, but no public hook contract that replaces the submitted user prompt. The capability fits OpenClaw’s plugin direction, while silent user-intent rewriting needs a maintainer-approved security and cross-harness contract.

## What This Changes

Allow `before_prompt_build` and legacy `before_agent_start` plugin hooks to replace the submitted user prompt before model invocation.

## Best Possible Solution

Add a phase-specific replacement field to `before_prompt_build`, inherited only for legacy compatibility by `before_agent_start`, and land it only with explicit permission, precedence, audit/transcript, image-handling, context-accounting, and PI/CLI/Codex parity semantics plus public documentation and regression coverage.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: May an installed plugin with prompt-injection permission silently replace the current user prompt, and if so what precedence and audit/transcript semantics must every runner enforce?

Rationale: The existing API intentionally permits additive prompt mutation, but full replacement grants materially greater authority over user intent and affects security, observability, transcript truth, and cross-harness compatibility.

Likely owner: steipete

Owner reason: This person authored the latest substantive review framing the unresolved security and cross-harness product decision.

Owner confidence: medium

Options:

- **Add guarded replacement (recommended):** Extend `before_prompt_build`, inherit it in the legacy hook, reuse the established prompt-injection policy, and require deterministic precedence plus audit and cross-harness tests.
- **Require a separate privilege:** Add replacement only behind a distinct plugin capability if maintainers judge additive injection and full intent rewriting to be different trust levels.
- **Keep hooks additive:** Reject replacement and document `before_agent_run` blocking or a context-engine implementation as the supported response to oversized current prompts.

## Reproduction Assessment

Yes at source level: return a replacement-shaped value from a prompt-build hook and the current result contract, merger, and documented runner behavior preserve the original prompt. No live provider reproduction was needed to establish that the capability is absent.

## Solution Assessment

Unclear until maintainers choose the security contract. A field on the phase-specific `before_prompt_build` API with legacy inheritance and complete runner parity is safer than wiring only `before_agent_start` in the embedded runner.
