## Label Justifications

- `P2`: This is a normal-priority plugin API enhancement with real context-limit and redaction use cases, but it is not an active outage or regression.
- `impact:security`: Letting plugins replace or redact the current user prompt changes the model-input trust boundary and needs explicit security semantics.

## Summary

Keep open: current main and v2026.6.11 still lack user-prompt replacement in `before_prompt_build` or legacy `before_agent_start`; related PRs are closed unmerged or broader and not a safe canonical fix, so this remains a plugin API and security-boundary decision.

## What This Changes

Request to let plugins replace the current user prompt from prompt-build hooks so context-management plugins can truncate or redact oversized prompts before the model call.

## Best Possible Solution

Define one maintainer-approved prompt replacement contract, probably on `before_prompt_build` with legacy `before_agent_start` compatibility, including `allowPromptInjection` handling, ordering, runner parity, docs, and regression coverage; otherwise explicitly reject replacement and document the supported additive/blocking alternatives.

## Reproduction Assessment

Yes for the source-level feature gap, not as a bug reproduction: current main and v2026.6.11 expose only additive prompt context and system prompt mutations, with no prompt replacement field or runner path.

## Solution Assessment

Unclear until maintainers decide the API and security boundary. A narrow replacement field may be the right contract, but it needs coordinated behavior across prompt-build merging, embedded runner, CLI runner, Codex harness, policy filtering, docs, and tests.
