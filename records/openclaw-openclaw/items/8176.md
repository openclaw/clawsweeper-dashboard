## Summary

Keep open: current main and the latest release still only support additive prompt/context mutations for `before_prompt_build` and legacy `before_agent_start`, so the requested user-prompt replacement capability remains missing and security-sensitive.

## What This Changes

Add a plugin hook result field that lets `before_prompt_build` or legacy `before_agent_start` replace the current user prompt before prepend/append context is applied.

## Best Possible Solution

Choose one documented prompt-replacement contract and implement it consistently across embedded, CLI, and harness runners with precedence rules, `allowPromptInjection` behavior, docs, and regression coverage.

- **Reject replacement:** Keep prompt hooks additive-only and direct oversized-prompt mitigation to context-engine/provider-boundary mechanisms instead.
