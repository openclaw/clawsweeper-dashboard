## Summary

Keep open: current main and the latest release still support additive prompt context and system-prompt hook fields, but there is no public hook result or runner path that replaces the submitted user prompt. The related direct PRs are closed unmerged, and the broader open LLM interception PR is still a separate product/security review path.

## What This Changes

Request to let prompt-build or legacy before_agent_start plugin hooks replace the submitted user prompt before prepend/append context is applied.

## Best Possible Solution

Keep this as the canonical tracker until maintainers approve and document a prompt replacement contract for before_prompt_build and legacy before_agent_start, or explicitly choose another interception boundary such as modifying LLM input hooks.

## Reproduction Assessment

Yes, source-level: current hook result types, merge logic, embedded runner, Codex harness helper, latest release tag, and docs all show additive context/system-prompt support but no user-prompt replacement path.

## Solution Assessment

Unclear until maintainers decide the API and trust boundary. A replacement field is plausible, but the best implementation must settle naming, precedence, allowPromptInjection filtering, auditability, docs, and whether broader LLM-input hooks should own this instead.
