## Summary

Keep open: current main and v2026.6.11 still support additive prompt context and system-prompt hook fields only, so plugins cannot replace the submitted user prompt through `before_prompt_build` or legacy `before_agent_start`. The linked direct PRs are closed unmerged, and the broader LLM interception PR is open but unmerged and not a current-main implementation.

## What This Changes

Request an opt-in plugin hook result that can replace the submitted user prompt before model submission.

## Best Possible Solution

Keep this as the canonical tracker until maintainers approve and document a user-prompt replacement contract across `before_prompt_build` and legacy `before_agent_start`, or explicitly route the capability to another LLM interception boundary.

## Reproduction Assessment

Yes, source-level: current hook result types, merge logic, embedded runner, CLI runner, Codex bridge, and docs all show additive context/system-prompt support but no user-prompt replacement path. A live provider run is not needed to confirm this missing API surface.

## Solution Assessment

Unclear until maintainers decide the API and trust boundary. A prompt replacement field is plausible, but the best implementation must settle naming, precedence, `allowPromptInjection`, auditability, and whether broader LLM-input hooks should own this instead.
