## Summary

Keep open. Current main and v2026.6.11 still expose only additive user-context and system-prompt mutations; direct prompt-replacement PRs closed unmerged. The capability fits OpenClaw’s plugin direction, but granting plugins authority to rewrite user intent needs an explicit security and cross-harness contract.

## What This Changes

Requests a plugin hook result field that can replace the submitted user prompt before model invocation.

## Best Possible Solution

Add one canonical replacement field to before_prompt_build, inherited only for legacy compatibility, gated by allowPromptInjection, with higher-priority-first precedence and identical replacement-then-prepend/append behavior across embedded PI, CLI, and Codex; preserve the original transcript and document the model-visible divergence with focused tests.
