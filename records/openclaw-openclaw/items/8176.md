## Summary

Keep open: current main and the latest checked release still only support additive context/system-prompt changes from `before_prompt_build` and legacy `before_agent_start`; no public plugin hook field or runner path can replace the user prompt. The remaining work is a plugin API and security policy decision, especially with the broader but still-open mutating LLM-hook PR overlapping the same design space.

## What This Changes

Request to let plugin prompt-start hooks replace the current user prompt instead of only prepending or appending context.

## Best Possible Solution

Make a maintainer-reviewed plugin API decision, then implement one documented prompt-replacement contract across embedded, CLI, and Codex paths with security policy, ordering, compatibility tests, and docs.

## Reproduction Assessment

Yes at source level: the current hook result types, merge logic, and runner call sites expose no prompt replacement field or behavior.

## Solution Assessment

Unclear as proposed: prompt override is a plausible capability, but the best permanent API needs maintainer choice across `before_prompt_build`, legacy `before_agent_start`, and the overlapping mutating LLM-hook design.
