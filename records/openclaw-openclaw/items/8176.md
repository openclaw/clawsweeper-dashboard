## Label Justifications

- `P2`: This is a normal-priority plugin API enhancement with clear source evidence but no urgent regression, outage, or data-loss impact.

## Summary

Keep open: current main and latest release still support additive prompt context and system-prompt mutation only, not replacing the submitted user prompt through `before_prompt_build` or legacy `before_agent_start`. The remaining work is a public plugin API and security-boundary decision, not conservative cleanup.

## What This Changes

Request to let plugin prompt-build/start hooks replace the effective user prompt so plugins can truncate or redact oversized current prompts before model submission.

## Best Possible Solution

Keep this as the canonical tracker until maintainers approve and document a user-prompt replacement contract across shared hook surfaces, or explicitly choose a different LLM interception boundary.

## Reproduction Assessment

Yes, source-level: current hook result types, merge logic, embedded runner, CLI runner, Codex harness bridge, and docs all show additive context/system-prompt support but no user-prompt replacement path. I did not run a live provider scenario because the feature gap is directly visible in source.

## Solution Assessment

Unclear until maintainers decide the public API and trust boundary. A prompt replacement field is plausible, but the best implementation must settle naming, precedence, `allowPromptInjection` behavior, observability, and whether broader LLM-input hooks should own this instead.
