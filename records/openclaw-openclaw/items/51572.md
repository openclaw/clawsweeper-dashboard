## Summary

Keep open: current main and v2026.6.11 still limit bundled session-memory to command:new and command:reset, while automatic daily/idle rollover and session-store maintenance prune remain separate lifecycle paths. The report has active user corroboration and workaround evidence, but the fix needs maintainer direction on lifecycle contract, async deadlines, dedupe, and transcript-retention policy.

## What This Changes

Request to extend bundled session-memory finalization from manual command events to automatic daily/idle reset and maintenance prune before context is discarded.

## Best Possible Solution

Define a maintainer-approved lifecycle contract for memory finalization before automatic rollover and destructive maintenance prune, with bounded async behavior, privacy/retention rules, docs, and regression coverage.

## Reproduction Assessment

Yes. Source inspection shows current main can rotate daily/idle sessions and prune stale store entries while bundled session-memory handles only internal command:new and command:reset events; no live gateway run was performed because this review is read-only.

## Solution Assessment

Unclear. The requested semantics are valid, but the best permanent fix depends on maintainer choices for the lifecycle event shape, timeout behavior, plugin boundary, and privacy semantics.
