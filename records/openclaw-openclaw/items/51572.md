## Summary

Keep open: current main and latest release still leave bundled session-memory on the command-only path while automatic daily/idle rollover and maintenance pruning use separate lifecycle or cleanup paths, and the related PRs only cover partial, unmerged implementations.

## What This Changes

Request that session-memory or an equivalent lifecycle hook fire before automatic session reset and maintenance prune so session context can be preserved.

## Best Possible Solution

Define one maintainer-approved lifecycle contract that covers daily/idle rollover and destructive maintenance prune before context becomes unavailable, with bounded async behavior, privacy rules, docs, and regression coverage.

## Reproduction Assessment

Yes. Source inspection shows bundled session-memory only handles command:new and command:reset while automatic daily/idle rollover and stale-store pruning follow separate paths without that hook.

## Solution Assessment

Unclear as a final implementation because the desired behavior is valid, but maintainers must choose the hook contract, ordering, timeout, and privacy semantics before a durable fix.
