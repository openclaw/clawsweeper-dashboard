## Summary

Keep open: current main has typed session lifecycle hooks for some rollover paths, but bundled session-memory still only handles command:new/command:reset and maintenance pruning still removes stale entries without a pre-delete memory finalization path.

## What This Changes

The issue requests lifecycle coverage so session-memory or an equivalent memory hook fires during reset, rollover, and prune paths before context is discarded.

## Best Possible Solution

Define one lifecycle-safe memory finalization contract covering explicit reset, idle/daily rollover, and pre-delete maintenance pruning, with bounded async behavior, dedupe, privacy/retention docs, and regression tests.

## Reproduction Assessment

Yes, source-level: bundled session-memory handles only command:new/reset while typed session lifecycle and maintenance pruning are separate paths; no live gateway run was performed in this read-only review.

## Solution Assessment

Unclear: extending the bundled hook is plausible, but maintainers need to choose whether the durable contract should be bundled session-memory, typed plugin lifecycle, a pre-prune event, or an agentic memory flush path.
