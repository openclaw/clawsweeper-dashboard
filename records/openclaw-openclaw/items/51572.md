## Summary

Keep open: the reported daily/idle-reset gap still has a concrete current-release report, while the linked open PR covers only the reset slice and the requested pre-prune finalization needs an explicit lifecycle, ordering, and plugin-contract decision.

## What This Changes

Request that session-memory preservation run before automatic session resets and maintenance pruning, rather than only on compaction or command-driven resets.

## Best Possible Solution

Define one documented session-finalization contract with reasoned daily/idle reset and pre-prune paths, a bounded awaitable preservation window before destructive deletion, and regression coverage for archive lookup and duplicate-capture cases.
