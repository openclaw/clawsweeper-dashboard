## Label Justifications

- `P2`: The issue affects session-memory reliability for automatic lifecycle paths, but the remaining work needs design and security selection rather than emergency repair.
- `impact:session-state`: The report is about automatic session rollover and session-store prune paths ending a session without memory finalization.

## Summary

Keep open: current main and v2026.6.11 still gate bundled session-memory to command-driven /new and /reset, while automatic daily/idle rollover and maintenance prune do not run the requested memory finalization path. Related open PRs cover only slices of the lifecycle and are not merged.

## What This Changes

Request to fire session-memory or an equivalent memory-finalization hook before automatic idle/daily resets and maintenance prune, not only command-driven reset paths.

## Best Possible Solution

Define one maintainer-approved memory-finalization lifecycle for automatic rollover and destructive prune, with bounded async deadlines, privacy/retention semantics, docs, and regression coverage.
