- `impact:session-state`: The reported gap concerns daily/idle rollover and pruning paths that can discard context before memory finalization runs.

## Summary

Keep open: current main still limits bundled session-memory to command/new reset events while automatic daily/idle rollover and maintenance prune follow separate lifecycle paths. Related issues and one open PR cover pieces, but no merged or safe canonical item covers the full reset-plus-prune memory-finalization contract.

## What This Changes

Request to run session-memory-style memory capture before automatic daily/idle session rollover and maintenance pruning, not only manual reset/compaction paths.

## Best Possible Solution

Define a maintainer-approved, bounded memory-finalization lifecycle for automatic daily/idle rollover and maintenance prune, then wire session-memory or plugin hooks with privacy, dedupe, docs, and regression coverage.

## Reproduction Assessment

Yes. Source inspection shows current main can rotate daily/idle sessions and prune stale store entries while bundled session-memory handles only internal command:new and command:reset events.

## Solution Assessment

Unclear. The requested behavior is valid, but the best fix depends on a maintainer-chosen lifecycle contract, timeout behavior, privacy semantics, and whether this belongs in bundled session-memory or the plugin hook API.
