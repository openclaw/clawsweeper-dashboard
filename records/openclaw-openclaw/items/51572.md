## Summary

Keep open: current main and the latest checked release still do not make the bundled session-memory hook run for automatic daily/idle rollover or destructive session-store pruning, and the remaining fix needs a maintainer-defined lifecycle/API contract.

## What This Changes

The issue requests firing session-memory before automatic reset and prune paths so session context can be preserved before it is discarded.

## Best Possible Solution

Define one pre-loss session lifecycle contract that covers explicit reset, automatic daily/idle rollover, destructive store prune, shutdown where feasible, and compaction, then wire session-memory or plugin memory owners through that contract with bounded async behavior and privacy-safe payloads.

## Reproduction Assessment

Yes. Source inspection shows session-memory only handles command:new/command:reset, while automatic daily/idle rollover and maintenance pruning are separate lifecycle paths that do not trigger that bundled hook.

## Solution Assessment

Unclear. The requested behavior is valid, but the best fix should be a maintainer-chosen lifecycle contract rather than a narrow one-off session-memory call in each destructive path.
