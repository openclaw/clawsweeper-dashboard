## Label Justifications

- `P2`: The issue affects session-memory reliability for automatic lifecycle paths, but the fix needs design/security selection rather than emergency repair.
- `impact:session-state`: The reported gap is about session rollover and prune paths discarding context before memory finalization runs.
- `impact:data-loss`: Users relying on session-memory can lose transcript context when stale sessions reset or prune without a preservation hook firing.
- `impact:security`: The requested automatic capture would persist more transcript content, so privacy and retention boundaries are part of the issue.

## Summary

Keep open: current main and v2026.6.11 still do not run session-memory on automatic daily/idle rollover or maintenance prune. The active reset PR only covers daily/idle reset and remains unmerged, so the prune/finalization lifecycle design is still unresolved.

## What This Changes

Request to make the bundled session-memory/finalization hook run when sessions auto-reset by idle/daily policy or are pruned by maintenance, before context is discarded.

## Best Possible Solution

Define one maintainer-approved memory-finalization lifecycle for automatic rollover and destructive prune, with bounded async deadlines, privacy/retention semantics, docs, and regression coverage; land or replace the reset-only PR only if its hook contract is accepted.

## Reproduction Assessment

Yes, at source level. Current main shows session-memory exits for non-command or non-new/reset actions, daily/idle rollover emits typed session_end instead, and maintenance prune removes entries without a session-memory hook.

## Solution Assessment

Unclear. The desired behavior is valid, but the best fix should define a typed lifecycle/pre-prune contract and security defaults instead of only replaying command hooks; the active reset PR is partial and unmerged.
