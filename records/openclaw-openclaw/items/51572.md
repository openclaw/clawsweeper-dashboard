## Label Justifications

- `P2`: The issue affects session-memory reliability for users with persistent agents, but it needs bounded design work rather than an emergency runtime repair.
- `impact:session-state`: The reported gap is about session rollover and pruning paths discarding context before memory finalization can run.

## Summary

Keep open: current main and the latest release still do not run bundled session-memory finalization for automatic daily/idle rollover or destructive session-store pruning, and recent comments confirm this remains an active memory-loss pain point. The gap is source-reproducible, but the permanent fix needs maintainer choice on lifecycle hook shape, async deadline, and privacy/retention behavior.

## What This Changes

Request that session-memory or equivalent memory finalization run before automatic idle/daily session rollover and maintenance pruning, not only current lifecycle triggers.

## Best Possible Solution

Define a maintainer-approved lifecycle contract for memory finalization before automatic daily/idle rollover and destructive maintenance prune, with bounded async behavior, privacy and dedupe rules, docs, and regression coverage.

## Reproduction Assessment

Yes. Source inspection shows current main can rotate daily/idle sessions and prune stale store entries while bundled session-memory handles only internal command:new and command:reset events; I did not run a live gateway scenario because this review is read-only.

## Solution Assessment

Unclear until maintainers choose the lifecycle contract. The requested behavior is valid, but the best permanent fix depends on reset/prune event shape, timeout behavior, plugin ownership, and privacy semantics.

## Risks / Open Questions

- Maintainers still need to choose the lifecycle contract: extending command hooks, using before_reset/session_end, adding a pre-prune event, or defining a new memory-finalization surface all have different API and compatibility costs.
- Automatic transcript persistence before reset/prune can change privacy and retention behavior because content that is currently discarded may start being written to memory files.
- A pre-prune hook needs bounded async deadline, dedupe, and failure semantics; otherwise destructive maintenance could either block too long or still delete context before memory extraction completes.
