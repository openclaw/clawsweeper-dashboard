## Label Justifications

- `P2`: The issue affects session-memory reliability for automatic lifecycle paths, but it is a bounded feature/design gap rather than an active core outage.
- `impact:session-state`: The requested behavior concerns session rollover, transcript finalization, and memory continuity across session boundaries.
- `impact:data-loss`: Users relying on session-memory can lose useful transcript context when stale sessions reset or prune without memory finalization.
- `impact:security`: Automatically saving reset/prune transcripts can expand sensitive transcript retention and needs explicit privacy boundaries.

## Summary

Keep open: current main still only runs bundled session-memory for command-style new/reset events, while daily/idle rollover and session-store maintenance prune can end or delete session state without that memory-finalization hook. The open reset PR covers only daily/idle rollover and is unmerged, so prune and the durable lifecycle contract remain unresolved.

## What This Changes

Request firing session-memory when context is about to be lost through automatic daily/idle reset or maintenance prune.

## Best Possible Solution

Define one pre-destruction session finalization contract for manual reset, daily/idle rollover, and maintenance prune, with transcript availability, bounded async deadlines, retention/privacy semantics, dedupe guarantees, docs, and no-double-fire regression tests.
