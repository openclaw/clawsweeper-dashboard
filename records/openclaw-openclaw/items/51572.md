## Label Justifications

- `P2`: The issue affects session-memory reliability for automatic lifecycle paths, but it is bounded to memory/session behavior and needs design selection rather than emergency repair.
- `impact:session-state`: The reported gap is about session rollover and maintenance prune paths discarding context before memory finalization runs.
- `impact:data-loss`: Users relying on session-memory can lose transcript context when stale sessions reset or prune without the bundled hook firing.

## Summary

Keep open: current main and v2026.6.11 still leave bundled session-memory command-scoped, while automatic daily/idle rollover and maintenance prune use separate lifecycle/maintenance paths that do not run that hook. The KeepMyClaw, Cophy Runtime, and cron workaround comments are useful evidence that users are solving around the gap, but they do not replace an OpenClaw lifecycle contract.

## What This Changes

The issue requests session-memory finalization when sessions reset through idle/daily rollover or are pruned by maintenance, not only on existing command-scoped hook paths.

## Best Possible Solution

Define one maintainer-approved memory-finalization lifecycle for automatic rollover and destructive prune, with bounded async deadlines, privacy/retention semantics, docs, and regression coverage for the bundled hook or plugin API.

## Reproduction Assessment

Yes. Source inspection on current main shows the bundled handler only accepts command:new/command:reset, while daily/idle rollover emits typed session lifecycle hooks and maintenance prune removes stale entries without invoking that hook.

## Solution Assessment

Unclear. The requested behavior is valid, but the best fix needs a maintainer-selected lifecycle contract rather than replaying command hooks into every reset/prune path by default.
