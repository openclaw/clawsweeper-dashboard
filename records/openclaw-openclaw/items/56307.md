## Summary

Keep open. Current main has moved past the exact old Feishu hardcode example, but it still does not auto-inject `thread` or `mode` from channel/plugin metadata; the remaining work is a plugin SDK and session-routing product decision.

## What This Changes

Request to add channel-plugin threading policy so `sessions_spawn` can auto-inject thread/session parameters for subagent spawns instead of requiring model-supplied technical parameters.

## Best Possible Solution

Define one maintainer-approved channel-owned spawn policy contract, coordinate it with the non-thread persistent-session decision, then update SDK types, `sessions_spawn` schema/execution, channel metadata, docs, and focused tests.

## Reproduction Assessment

Yes, at source level. Current main derives `thread` only from explicit tool input, rejects `mode="session"` without that flag, and lacks the requested channel auto-injection contract.

## Solution Assessment

Unclear. A plugin-owned policy seam fits OpenClaw's architecture, but the exact fields, defaults, and interaction with related persistent-session and binding-preset issues should be chosen before implementation.
