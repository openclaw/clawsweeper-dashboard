## Summary

Keep open. Current main and the latest release still require explicit `thread: true` and have no channel-declared auto-injection contract for `sessions_spawn`; this remains a plugin SDK/session-routing product decision, not conservative cleanup.

## What This Changes

The issue requests channel plugin metadata so `sessions_spawn` can automatically inject subagent `thread: true` and `mode: "session"` parameters without hardcoded channel names or prompt instructions.

## Best Possible Solution

Define one maintainer-approved channel-owned session/thread spawn policy contract, then update the SDK surface, `sessions_spawn` schema/execution, channel metadata, docs, and focused tests together.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still derive `thread` only from explicit tool input, reject `mode="session"` without that flag, and lack the requested channel auto-injection contract.

## Solution Assessment

Unclear. A plugin-owned policy seam fits OpenClaw's architecture, but the exact fields, defaults, and interaction with related persistent-session and Telegram visibility decisions should be chosen before implementation.
