## Summary

Keep open. Current main and v2026.6.11 still do not implement channel-declared auto-injection for `sessions_spawn`, and the remaining work is a compatibility-sensitive SDK/session-routing product decision rather than cleanup-closeable.

## What This Changes

Request to add channel-declared threading policy so subagent spawning can automatically choose thread/session parameters without hardcoded channel names.

## Best Possible Solution

Define one maintainer-approved channel-owned session/thread policy contract, then update the SDK surface, `sessions_spawn` schema/execution, channel metadata, docs, and focused tests in line with the broader persistent-session decision.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a channel-declared auto-injection policy for `sessions_spawn` thread/session parameters, or should this wait for the broader persistent-session/thread-binding contract?

Rationale: The source gap is clear, but choosing defaults and SDK shape changes public plugin behavior and can alter routing, persistence, and message delivery for existing users.

Likely owner: steipete

Owner reason: The most recent core refactor moved this behavior into core and defines the architecture any new policy would extend.

Owner confidence: high

Options:

- **Design unified SDK/session policy first (recommended):** Settle the thread-binding and persistent-session contract across current and child-placement channels before implementing auto-injection fields or defaults.
- **Keep explicit tool parameters only:** Leave models/operators responsible for `thread` and `mode` until a stronger product need justifies implicit routing changes.
- **Queue a narrow auto-injection implementation:** Add a small channel metadata policy now, accepting that later session-decoupling work may revise the API.

## Reproduction Assessment

Yes, at source level. Current main derives thread binding from explicit `params.thread === true`, rejects session mode without that flag, and lacks the requested channel auto-injection contract.

## Solution Assessment

Unclear. A channel-owned policy seam fits OpenClaw's plugin architecture, but the proposed boolean pair is not obviously the best shape compared with the current SessionBindingAdapter path and the broader work in https://github.com/openclaw/openclaw/issues/53548.
