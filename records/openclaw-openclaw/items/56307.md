## Summary

Keep open. Current main and v2026.6.11 still require explicit `thread: true` for thread-bound `sessions_spawn`, do not auto-inject `thread` or `mode` from channel metadata, and the remaining work is a plugin SDK/session-routing product decision rather than cleanup-closeable.

## What This Changes

The issue requests a channel plugin threading policy so channel metadata can drive automatic `sessions_spawn` subagent `thread` and `mode` parameter selection.

## Best Possible Solution

Define one maintainer-approved channel-owned session/thread policy contract, then update the SDK surface, `sessions_spawn` schema/execution, channel metadata, docs, and focused tests alongside the broader persistent-session decisions.

## Reproduction Assessment

Yes, at source level. Current main derives `thread` only from explicit tool input and rejects `mode="session"` unless that flag is set, while the requested channel auto-injection contract is absent.

## Solution Assessment

Unclear as a final implementation. A plugin-owned policy seam fits the architecture, but the exact fields, defaults, and interaction with non-thread persistent sessions need maintainer product/API review before implementation.
