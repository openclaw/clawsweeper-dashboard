## Summary

Keep open. Current main and v2026.6.11 still do not provide channel-declared auto-injection for `sessions_spawn`; the remaining work is a plugin SDK/session-routing product decision, not cleanup-closeable.

## What This Changes

The issue requests channel plugin threading policy metadata so `sessions_spawn` can auto-inject subagent `thread` and `mode` parameters without hardcoded channel names.

## Best Possible Solution

Define one maintainer-approved channel-owned session/thread policy contract, then update the SDK surface, `sessions_spawn` schema/execution, channel metadata, docs, and focused tests alongside the broader persistent-session decision.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 derive `thread` only from explicit tool input, reject `mode="session"` without that flag, and lack the requested channel auto-injection contract.

## Solution Assessment

Unclear. A plugin-owned policy seam fits OpenClaw's architecture, but the exact fields, defaults, and interaction with https://github.com/openclaw/openclaw/issues/53548 should be chosen before implementation rather than added as a one-off boolean pair.
