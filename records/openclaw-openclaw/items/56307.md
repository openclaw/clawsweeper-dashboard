- `impact:session-state`: The requested policy affects whether spawned subagents become persistent thread-bound sessions and how follow-up state is associated.

## Summary

Keep open. Current main and the latest release still require explicit `thread: true` for thread-bound `sessions_spawn`, the requested channel-owned auto-injection contract is not present in the plugin SDK, and this remains a plugin/session-routing product decision rather than cleanup-closeable.

## What This Changes

The issue requests a channel plugin policy/schema that lets channels declare when `sessions_spawn` should auto-inject `thread: true` and `mode: "session"` for subagent spawning.

## Best Possible Solution

Define one maintainer-approved channel session/thread policy contract, then update the SDK surface, `sessions_spawn` schema/execution, channel metadata, docs, and focused tests in that single direction.

Owner confidence: high

Options:

- **Design a narrow channel policy seam (recommended):** Add a maintainer-approved SDK/session policy that expresses when a channel may default subagent spawns into thread-bound sessions, then migrate bundled channels and docs together.
- **Fold into persistent-session decoupling:** Keep this open as dependent on the broader decision in https://github.com/openclaw/openclaw/issues/53548 before adding any auto-injection behavior.
- **Keep explicit parameters only:** Document that agents must request `thread: true` and `mode: "session"` explicitly, avoiding any automatic channel-specific spawn behavior.

## Reproduction Assessment

Yes, at source level. Current main derives `thread` only from explicit tool input, rejects native `mode="session"` without that flag, and lacks the requested channel auto-injection contract.

## Solution Assessment

Unclear. A channel-owned policy seam fits the architecture, but the exact fields, defaults, and interaction with persistent sessions should be decided before implementation.
