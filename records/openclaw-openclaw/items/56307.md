## Summary

Keep open. Current main and v2026.6.11 still require explicit `thread: true` for thread-bound `sessions_spawn` and do not provide a channel-declared auto-injection contract; this remains a plugin SDK/session-routing product decision rather than cleanup-closeable.

## What This Changes

The issue requests a channel plugin threading policy so channels can declare automatic `sessions_spawn` thread/session parameter injection for subagents.

## Best Possible Solution

Define one maintainer-approved channel-owned session/thread policy contract, then update the SDK surface, `sessions_spawn` schema and execution, channel metadata, docs, and focused tests alongside the broader persistent-session decision.

## Reproduction Assessment

Yes, at source level. Current main derives thread binding only from explicit tool input and rejects `mode="session"` without that explicit flag, so omitted model parameters are not auto-injected by channel policy.

## Solution Assessment

Unclear. A channel-owned policy seam fits OpenClaw's plugin architecture, but the exact fields, defaults, and interaction with related persistent-session proposals should be chosen before implementation.
