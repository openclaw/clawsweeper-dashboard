## Label Justifications

- `P2`: This is a normal-priority channel/session orchestration improvement with real workflow impact but no current outage or emergency.
- `impact:session-state`: The requested policy changes whether spawned subagents become persistent thread-bound sessions and how follow-up state is associated.
- `impact:message-loss`: Incorrect or missing thread/session binding can misroute, suppress, or hide subagent replies and follow-up messages.

## Summary

Keep open. Current main and v2026.6.11 still require explicit `thread`/`mode` spawn parameters, so the remaining work is a compatibility-sensitive plugin SDK and session-routing design rather than cleanup-closeable work.

## What This Changes

Requested channel plugin threading policy metadata so `sessions_spawn` can auto-apply subagent thread/session parameters without hardcoded channel ids.

## Best Possible Solution

Define one maintainer-approved channel-owned spawn/thread policy contract, then update the SDK surface, `sessions_spawn` schema/execution, channel metadata, docs, and focused tests alongside the broader persistent-session decision.

## Reproduction Assessment

Yes, at source level. Current main derives thread binding only from explicit tool input and rejects `mode="session"` without that flag, so the requested channel policy injection is observably absent.

## Solution Assessment

Unclear. A plugin-owned policy seam fits OpenClaw's architecture, but the exact fields, defaults, and interaction with https://github.com/openclaw/openclaw/issues/53548 should be chosen before implementation.
