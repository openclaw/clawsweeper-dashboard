## Summary

Keep open. Current `main` and the latest release still hardcode bootstrap context ordering and classify only `HEARTBEAT.md` as dynamic below the prompt-cache boundary, so the requested operator-controlled dynamic-file/order surface remains a real product/API decision rather than implemented cleanup.

## What This Changes

The issue requests configurable bootstrap context file ordering and dynamic-file classification so frequently changing workspace files can be placed after the prompt-cache boundary.

## Best Possible Solution

A maintainer should choose one prompt-cache/context API shape first, then implement a narrow config-backed dynamic classification/order mechanism with unchanged defaults, schema/help/docs, and fresh-install plus upgrade tests.
