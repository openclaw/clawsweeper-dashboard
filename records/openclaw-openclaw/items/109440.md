## Summary

Keep open: the deterministic self-block is valid and strongly proven, but the proposed job-ID exemption is broader than one execution and can bypass another active marker belonging to the same job.

## What This Changes

The PR lets a `wakeMode:"now"` main-session cron run ignore its own active marker while preserving the heartbeat busy guard for other cron work.

## Best Possible Solution

Capture the exact marker returned by `markCronJobActive`, thread that internal marker identity to the heartbeat guard, exclude only that marker, and add coverage proving that a second marker with the same job ID still blocks.
