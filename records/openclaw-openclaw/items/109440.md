## Summary

The diagnosis is strong, but this head should not merge yet: the exemption is keyed by job id even though cron lifecycle accounting uses tokenized marker identity, and the submitted evidence is integration-test proof rather than a real after-fix run.

## What This Changes

Threads an owning cron job identifier through the gateway heartbeat path, discounts that job from the cron busy guard, and adds regression coverage for synchronous `wakeMode:"now"` delivery.

## Best Possible Solution

Keep the synchronous wake fix, but thread the exact `CronActiveJobMarker` identity or token from the executing run through the internal gateway/heartbeat seam, discount only that current marker, add a generation-replacement regression test, and attach a redacted live `wakeMode:"now"` cron run showing payload delivery before merge.
