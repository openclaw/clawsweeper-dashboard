## Summary

Keep open. A July 20, 2026 report reproduces the audit failure after a real provider request on OpenClaw 2026.7.1-2, while the issue discussion also identifies generated plugin catalog snapshots as a possible credential-persistence sibling; the merged earlier `models.json` fix therefore does not yet establish that the observable problem is resolved. Likely related people: VibhorGautam is the strongest routing candidate from the earlier merged fix, with medium confidence.

## What This Changes

Prevent generated `models.json` and related provider catalog snapshots from persisting resolved provider credentials as bare `apiKey` strings while preserving runtime provider authentication.

## Best Possible Solution

Trace every generated provider snapshot, ensure no resolved secret value is serialized, retain only an existing non-secret marker or omit the field where consumers do not need it, and add an end-to-end migration → restart → provider request → audit regression test.
