## Summary

Keep open: current `main` and latest stable still contain the allowlist-plan approval gate that can prompt after an allowlist match, while the public exec docs still describe `ask: "on-miss"` as direct execution for matches. The issue is valid enough to retain, but the fix crosses the exec approval security boundary and needs maintainer direction before automation changes behavior.

## What This Changes

The issue reports that macOS allowlist exec commands requiring shell handling prompt instead of auto-running under `ask: "on-miss"`, even when the allowlist match is detected.

## Best Possible Solution

Keep fail-closed approval for genuinely unenforceable shell payloads, restore documented `on-miss` direct execution only for macOS command shapes the planner can bind safely, and document or improve warnings for the remaining command-shape limitations.

Rationale: The user impact is real, but the current gate is deliberately tied to a security boundary that prevents raw shell execution when executable binding or shell expansion cannot be made stable.

Likely owner: pgondhi987

Owner reason: The strongest recent macOS shell-wrapper allowlist ownership signal is the merged hardening work in this area.

Owner confidence: high

Options:

- **Repair safe planner-bound cases (recommended):** Teach the macOS/POSIX planner to bind common safe shapes such as absolute argv and narrowly modeled tilde/path forms, keep prompt-only behavior for unbound shell payloads, and add Darwin regression proof.
- **Document fail-closed limitation:** Keep the current approval gate and update exec approval docs plus warning text so operators can convert automation to argv-clean commands intentionally.
- **Allow raw matched shell commands:** Let allowlist matches run even when no enforced command can be materialized, accepting a broader shell-resolution trust boundary.

## Solution Assessment

Is this the best way to solve the issue? Unclear until a maintainer chooses the security boundary; the best fix is likely narrow planner support for enforceable macOS shapes plus docs for any prompt-only cases, not a raw allowlist bypass.
