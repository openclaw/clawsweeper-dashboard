## Summary

Keep open: the issue is no longer a total Darwin allowlist failure, but current main still prompts for matched shell-shaped POSIX commands when OpenClaw cannot render an enforced command, which conflicts with the documented `ask: "on-miss"` contract for allowlist matches. This needs maintainer/security-boundary direction rather than cleanup closure.

## What This Changes

The issue requests restoring or documenting Darwin gateway exec behavior where matched allowlist commands that require shell expansion or shell syntax prompt instead of auto-executing under `security: "allowlist"` with `ask: "on-miss"`.

## Best Possible Solution

Restore direct execution only for Darwin/POSIX allowlist matches that can be safely materialized into an enforced command, keep explicit approval for genuinely unenforceable shell text, and make the warning/docs name the command-shape limitation.
