## Summary

Keep open: current main still contains the allowlist-plan approval gate that can prompt after a Darwin allowlist match when OpenClaw cannot rebuild an enforceable POSIX command, and the latest reporter update narrows the remaining problem to shell-shaped commands such as tilde paths, pipes, chains, and redirections. The existing security label also makes this unsuitable for automatic cleanup closure.

## What This Changes

Issue reports that Darwin allowlist exec commands requiring shell interpretation prompt instead of auto-executing under `ask: "on-miss"`.

## Best Possible Solution

Keep the fail-closed security boundary for genuinely unenforceable shell plans, then have maintainers choose either a narrow audited Darwin rewrite for common safe forms such as tilde-expanded script paths or clearer docs and warning text that name the command-shape limitation.
