## Summary

Keep open: current main and the reported v2026.6.11 release still contain the plan-miss approval path that can prompt after an allowlist match, and the reporter’s later command-shape isolation matches the POSIX enforced-command renderer’s fail-closed handling of shell expansion. I found adjacent Windows and wrapper-parser work, but no merged fix or canonical duplicate for the Darwin shell-shaped allowlist behavior.

## What This Changes

Issue reports that macOS allowlist exec commands requiring shell parsing still prompt for approval despite matching the allowlist, conflicting with documented on-miss behavior.

## Best Possible Solution

Restore documented on-miss behavior only for Darwin commands whose resolved executable and arguments can be made enforceable, keep prompt-only behavior for genuinely unenforceable shell forms, and document/warn with the specific rejected command shape.
