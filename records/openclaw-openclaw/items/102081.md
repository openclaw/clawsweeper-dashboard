## Summary

Keep open: current main and v2026.6.11 still gate matched gateway shell-shaped commands behind approval when an enforced plan cannot be built, while the docs say `ask: "on-miss"` prompts only on allowlist misses. The reporter's latest update narrows the remaining problem to command-shape handling on Darwin, which is a real exec security-boundary decision rather than stale cleanup.

## What This Changes

The issue asks for Darwin gateway exec allowlist matches with `ask: "on-miss"` to auto-execute when matched, or for the command-shape limitation to be documented clearly.

## Best Possible Solution

Preserve direct execution for Darwin allowlist matches that can be safely materialized into an enforced plan, keep explicit approval for genuinely unenforceable shell shapes, and document any intentional command-shape limits with targeted Darwin regression proof.
