## Summary

Keep open: current main still has the gateway exec approval path that can turn a successful allowlist match into an explicit approval prompt when the matched command cannot be rendered as an enforced shell-free command. The reporter's narrowed Darwin command-shape repro matches the source behavior, and there is no merged fix or canonical duplicate to close against.

## What This Changes

This issue reports that Darwin gateway exec allowlist matches requiring shell expansion or wrapper syntax prompt for approval instead of auto-executing under the documented allowlist/on-miss behavior.

## Best Possible Solution

Keep this open until maintainers choose the security-boundary behavior, then either implement a narrow tested Darwin-safe command-shape path or document that shell-shaped allowlist matches require explicit approval with clearer diagnostics.
