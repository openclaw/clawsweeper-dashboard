## Summary

Keep open: current main still contains the gateway allowlist-plan approval gate that can prompt after an allowlist match when a POSIX/macOS command cannot be rendered into an enforced command, and the public docs still describe `on-miss` as prompting only on allowlist misses. This needs maintainer/security-boundary direction rather than cleanup closure.

## What This Changes

The issue reports that macOS gateway exec allowlist matches which require shell interpretation prompt instead of auto-executing under `allowlist`/`on-miss`.

## Best Possible Solution

Preserve direct execution for allowlist matches only when OpenClaw can safely materialize an enforced command or an exact durable grant, and improve diagnostics/docs for shell-shaped commands that must stay approval-gated.
