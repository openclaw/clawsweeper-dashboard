## Summary

Keep open: current main still turns matched allowlist commands into approval prompts when the gateway cannot build an enforced shell command, while the docs still promise that `ask=on-miss` runs allowlist matches directly. I found no merged Darwin/macOS fix or canonical duplicate for the narrowed shell-shaped-command failure.

## What This Changes

The issue requests fixing or documenting macOS gateway exec allowlist behavior where shell-shaped allowlist matches prompt instead of auto-executing under `ask=on-miss`.

## Best Possible Solution

Restore documented `on-miss` semantics only for Darwin command shapes OpenClaw can enforce safely, and document or improve diagnostics for shell forms that must still require explicit approval.
