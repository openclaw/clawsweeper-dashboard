## Label Justifications

- `P2`: This is a normal-priority Plugin SDK/context-engine improvement with important security semantics but no current production outage while unmerged.

- `merge-risk: 🚨 security-boundary`: The change defines how untrusted historical context is separated from current user input, which is a prompt-authority boundary.

## Summary

Keep open: the PR is a useful implementation of the requested reference-context lane, but it is not merge-ready because it advertises `reference-context` for every Codex app-server host while OpenClaw still supports custom app-server versions back to 0.125.0, where the app-server protocol has no `additionalContext` field.

## What This Changes

The PR adds `AssembleResult.referenceContext`, a `reference-context` host capability, Codex app-server `additionalContext` projection, validation, docs, and Plugin SDK surface baseline updates.

## Best Possible Solution

Land a version-aware reference-context contract: only advertise the capability when the connected Codex app-server supports `additionalContext`, or intentionally raise the app-server minimum with upgrade docs/tests, while keeping embedded hosts rejected until they have an equivalent non-message lane.

## Solution Assessment

No. The Codex `additionalContext` projection is the right boundary for managed Codex 0.142.4, but this is not the best safe merge shape until support is gated against the actual app-server version or the supported minimum is raised deliberately.
