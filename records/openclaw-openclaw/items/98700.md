## Label Justifications

- `P2`: This is a normal-priority Plugin SDK/context-engine improvement with important security semantics but no current production outage while unmerged.
- `merge-risk: 🚨 compatibility`: Merging as-is can leave existing custom Codex app-server setups accepted while silently missing the new reference-context protocol field.
- `merge-risk: 🚨 session-state`: The lane carries historical session/reference context, and misadvertised support can omit or stale that context across turns.
- `merge-risk: 🚨 security-boundary`: The change defines how untrusted historical context is separated from current user input, which is a prompt-authority boundary.

## Summary

Keep open: the PR is useful and the managed Codex 0.142.4 proof is strong, but it still advertises `reference-context` to every accepted Codex app-server even though OpenClaw supports older custom app-server versions without `turn/start.additionalContext`. That remains a version, public SDK, and prompt-authority contract blocker before merge.

## What This Changes

The PR adds `AssembleResult.referenceContext`, a `reference-context` host capability, Codex app-server `additionalContext` projection, validation, docs, and Plugin SDK baseline updates.

## Best Possible Solution

Land a version-aware reference-context contract: advertise the capability only when the connected Codex app-server supports `additionalContext`, or deliberately raise the app-server minimum with docs and tests, while keeping embedded hosts rejected until they have an equivalent non-message lane.

## Reproduction Assessment

Not applicable as a bug reproduction; this PR adds a new public Plugin SDK/context-engine lane. Source inspection shows current main lacks the lane, and the PR body provides live-output proof for the managed Codex 0.142.4 path.

## Solution Assessment

No. The Codex `additionalContext` projection is the right boundary for managed Codex 0.142.4, but this is not the best safe merge shape until support is gated against the actual app-server version or the supported minimum is raised deliberately.
