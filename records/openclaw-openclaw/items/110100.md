## Summary

Keep open: current main still starts Reef recovery from process-local progress before opening the live socket, and this fresh maintainer-labeled PR is the linked fix. The plugin-owned design and focused coverage look sound with no concrete correctness or security defect found, but its durable delivery semantics and connection lifecycle still warrant exact-head checks and Reef-owner review before merge.

## What This Changes

The PR makes Reef open its live socket before backlog catch-up, persist identity-bound inbox progress after successful handling, buffer live frames during recovery, and surface recovery failures through channel status.

## Best Possible Solution

Keep a single Reef-owned recovery pipeline that opens the socket first, serializes bounded live traffic behind validated REST catch-up, advances durable progress only after each successful entry, and proves restart, overflow, cancellation, and reconnect behavior against the exact merge head.
