## Summary

This PR is still necessary to review rather than close, but it is not merge-ready: it changes ACP launch/runtime-control and yield semantics without real ACP/Foreman after-fix proof, and source inspection shows two blocking provider/session contract regressions.

## What This Changes

The branch adds Claude/Gemini ACP launch-time model injection, skips several Claude/Gemini runtime config replays, passes `agentSessionKey` into `sessions_yield`, and changes no-callback yield calls from errors into yielded results.

## Best Possible Solution

Preserve any dependency-backed launch-time model support only after runtime-only controls are applied or clearly rejected, keep yield success tied to an actual interruption/hand-off contract, refresh the branch, and add real ACP/Foreman proof before merge.

## Reproduction Assessment

Yes for the PR-introduced risks from source inspection: the diff shows skipped Claude/Gemini runtime controls and no-callback yield success. No for the original Foreman dispatch fix, because the PR includes tests only and no real ACP/Foreman after-fix run.

## Solution Assessment

No. Launch-time model injection may be part of the fix, but silently treating unsupported runtime controls and no-callback yield calls as success is not the narrowest maintainable ACP/session contract without maintainer approval and proof.
