## Summary

Keep this PR open, but do not merge the current patch: the prior P1 blocker remains. The proposed condition bypasses the established account-recovery ladder for all transport-owning harnesses, even though Codex and Copilot can receive genuinely distinct credentials whose quota state may differ.

## What This Changes

The PR changes prompt-stage failover policy so harness-owned rate-limit and billing errors skip auth-profile rotation and proceed directly to model fallback, with focused tests and a proof script.

## Best Possible Solution

Keep account recovery ahead of model recovery: rotate to a genuinely distinct eligible harness credential, then trigger configured model fallback only after account candidates are unavailable or exhausted, or after a typed harness result proves credential rotation cannot help.
