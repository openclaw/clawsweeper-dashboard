## Label Justifications

- `P1`: Affected Codex-backed agent runs fail before producing a response on plugin-heavy beta installations.
- `impact:auth-provider`: The failure occurs in the Codex provider/runtime binding path and prevents the selected model route from starting.

## Summary

Current main still persists variable-size dynamic-tool and user-MCP fingerprints in one Codex binding value, so plugin-heavy runs can exceed the store limit and fail before responding. This protected beta blocker should remain open while the directly linked fix PR resolves its typecheck blocker and lands.

## What This Changes

Prevent Codex app-server thread bindings from exceeding the plugin-state per-value limit when tool or MCP fingerprints are large.

## Best Possible Solution

Land a corrected bounded deterministic fingerprint implementation that preserves `[]` for empty tools, safely rotates bindings when legacy raw fingerprints first differ, and proves large dynamic-tool and user-MCP surfaces with focused tests and the reported real Codex smoke path.
