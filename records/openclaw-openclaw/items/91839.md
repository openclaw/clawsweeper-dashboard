## Summary

Keep open. Current main has partial model_not_found fallback hardening, but it still does not cover the reported `Model not available` wording and the subagent announce path still contains bounded retry/give-up plus requester/child `chat.history` reads, so an implemented-on-main close would overstate the fix.

## What This Changes

The issue reports that a terminal provider model-not-available error during subagent completion/announce can trigger repeated chat.history control-plane calls and gateway event-loop starvation instead of a bounded model failure.

## Best Possible Solution

Keep this as a maintainer-owned stability item until OpenClaw either classifies the reported terminal provider wording into a bounded non-retryable or fallback path and proves announce/history calls stay bounded, or deliberately splits the remaining work into linked canonical issues for provider wording, subagent wake, config validation, and gateway starvation recovery.
