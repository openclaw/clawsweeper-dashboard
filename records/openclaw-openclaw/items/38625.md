## Summary

Keep open: current main and v2026.6.11 still lack version metadata on the unauthenticated health probes and still do not expose update execution over HTTP. The version half overlaps an open narrower tracker, while the HTTP update endpoint remains a security-sensitive product decision.

## What This Changes

The issue requests adding runtime version metadata to Gateway health JSON and an authenticated HTTP endpoint for host package-manager updates.

## Best Possible Solution

Split the concerns: keep the public version metadata contract on https://github.com/openclaw/openclaw/issues/91795, and expose update execution only through a maintainer-approved opt-in admin surface that preserves auth, audit, rate-limit, restart, and handoff guarantees.

Rationale: The request expands privileged host package-update and restart authority from existing CLI/WebSocket/control-plane paths to an HTTP surface, so automation cannot choose the permanent security and API boundary safely.

Likely owner: steipete

Owner confidence: high

Options:

- **Split version and design HTTP update first (recommended):** Keep version metadata in the narrower tracker and require maintainer-owned security/API design before exposing update execution over HTTP.
- **Expose update.run through Admin HTTP RPC:** Add a narrow allowlisted Admin HTTP RPC wrapper with explicit trusted-ingress, auth, audit, rate-limit, and managed-handoff proof requirements.
- **Decline HTTP update execution:** Keep update execution limited to existing CLI/WebSocket/control-plane paths and document that fleet tools should use those or an external orchestrator.

## Reproduction Assessment

Yes, at source level. Current main’s /health and /healthz serializer still returns only { ok: true, status }, and Admin HTTP RPC allowlists update.status while omitting update.run; no /admin/update route or requested response shape exists.

## Solution Assessment

No, not as one automatic combined change. Version reporting is a narrow additive public contract, but HTTP-triggered updates should reuse or wrap update.run only after maintainers approve the security boundary and API shape.
