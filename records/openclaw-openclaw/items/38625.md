## Summary

Keep open: current main and the latest release still lack version metadata on `/health` or `/healthz`, and the existing Admin HTTP RPC plugin exposes `update.status` but deliberately does not expose `update.run`. The version-only half overlaps an open narrower issue, while HTTP-triggered update authority remains a security-sensitive product/API decision.

## What This Changes

The issue requests adding running-version metadata to gateway health responses and adding an authenticated HTTP endpoint that can trigger host updates.

## Best Possible Solution

Let https://github.com/openclaw/openclaw/issues/91795 carry the narrow public version metadata decision, and separately decide whether the opt-in Admin HTTP RPC plugin or a dedicated authenticated HTTP endpoint may expose update execution with explicit scope, rate-limit, audit, docs, and upgrade tests.

## Reproduction Assessment

Yes, at source level. Current main’s `/health` and `/healthz` serializer returns only `{ ok: true, status }`, and Admin HTTP RPC allowlists `update.status` while omitting the existing `update.run` RPC.

## Solution Assessment

No, not as one automatic combined change. Version reporting is a narrow additive API contract, but HTTP-triggered updates should reuse or wrap `update.run` only after maintainers approve the security boundary and public API shape.
