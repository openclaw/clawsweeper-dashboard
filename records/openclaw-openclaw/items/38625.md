## Summary

Keep open: current main and v2026.6.11 still do not expose runtime version on `/health` or `/healthz`, and the requested HTTP update execution endpoint remains a security-sensitive Gateway product/API decision. The version-only portion is already tracked by https://github.com/openclaw/openclaw/issues/91795, but no single canonical item safely owns the broader authenticated update endpoint request.

## What This Changes

Request adding a `version` field to Gateway health responses and an authenticated HTTP update endpoint with optional target-version pinning for fleet tooling.

## Best Possible Solution

Split the concerns: keep the public health version contract in https://github.com/openclaw/openclaw/issues/91795, and expose update execution only through a maintainer-approved opt-in admin surface that reuses `update.run` or an external-updater boundary safely.

Rationale: The request expands host package-update and restart authority from existing Gateway control-plane paths to an HTTP surface and adds target-version semantics that current `update.run` does not support.

Options:

- **Split and design first (recommended):** Keep version metadata in the narrower canonical issue and require a maintainer-owned security/API design before adding HTTP update execution.
- **Expose through Admin HTTP RPC:** Add `update.run` or a narrow wrapper to the default-off Admin HTTP RPC plugin with explicit trusted-ingress, auth, audit, rate-limit, handoff, and target-version proof requirements.
- **Decline HTTP update execution:** Keep update execution limited to CLI/WebSocket/control-plane paths and document that fleet tools should use those or an external orchestrator.

## Reproduction Assessment

Yes, at source level: current `/health` and `/healthz` serialize only `{ ok: true, status }`, and tests assert that shallow body. The update surface exists as privileged gateway RPC, while Admin HTTP RPC allows only `update.status`, not `update.run`.

## Solution Assessment

No, not as one automatic combined endpoint. Version reporting is a narrow additive public contract, but HTTP-triggered updates should reuse or wrap `update.run` only after maintainers approve the security boundary, API shape, and target-version semantics.
