## Summary

Keep open: current main and v2026.6.11 still keep the HTTP health probe shallow and the existing admin HTTP RPC plugin does not expose `update.run`, so the combined fleet version/update request is not implemented. The version-only part overlaps https://github.com/openclaw/openclaw/issues/91795, but the HTTP update orchestration part remains a security/product decision.

## What This Changes

The issue requests adding version metadata to Gateway health JSON and an authenticated HTTP admin update endpoint for fleet update orchestration.

## Best Possible Solution

Use https://github.com/openclaw/openclaw/issues/91795 for the version-field decision, and if maintainers approve HTTP update orchestration, expose `update.run` through the existing default-off `admin-http-rpc` route with an explicit allowlist, docs, tests, and proof rather than adding an always-on endpoint.
