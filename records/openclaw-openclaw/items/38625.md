## Summary

Keep open: current main and v2026.6.11 still return only shallow `/health` and `/healthz` JSON, and the existing Admin HTTP RPC plugin exposes `update.status` but not `update.run`. The version half overlaps a narrower open issue, while HTTP-triggered update authority remains a security and product-boundary decision.

## What This Changes

Request to add runtime version metadata to Gateway health responses and add an authenticated HTTP endpoint for triggering host updates.

## Best Possible Solution

Split the concerns: let the narrower version-metadata issue define the public health/version field set, and only expose update execution over an opt-in trusted admin HTTP surface after maintainers approve the security contract.

## Maintainer Decision

Kind: security_boundary

Question: Should OpenClaw expose update execution to Gateway-authenticated HTTP callers, and should that use a new `/admin/update` endpoint or an intentional Admin HTTP RPC wrapper around `update.run`?

Rationale: The request expands host package-update and restart authority from existing CLI/WebSocket/control-plane paths to an HTTP surface, which requires maintainer intent for auth scope, ingress assumptions, auditability, rate limiting, and failure behavior.

Likely owner: steipete

Owner reason: steipete has the strongest shared history across Admin HTTP RPC, Gateway update flow, and adjacent version resolution.

Owner confidence: high

Options:

- **Split and design first (recommended):** Keep version metadata in the narrower tracker and require a maintainer-owned security/API design before exposing update execution over HTTP.
- **Expose through Admin HTTP RPC:** Add `update.run` or a narrow wrapper to the disabled-by-default Admin HTTP RPC plugin with explicit private-ingress, auth, audit, rate-limit, and handoff proof requirements.
- **Reject HTTP update execution:** Keep update execution limited to existing CLI/WebSocket/control-plane surfaces and document that fleet tools should use those or an external orchestrator.

## Solution Assessment

No, not as one automatic combined change. Version reporting is a narrow additive public contract, but HTTP-triggered updates should reuse or wrap `update.run` only after maintainers approve the security boundary and API shape.
