## What This Changes

## Best Possible Solution

Split the concerns: use https://github.com/openclaw/openclaw/issues/91795 for the public version metadata contract, and expose update execution over HTTP only through an approved, opt-in trusted admin surface that reuses `update.run` safely.

Rationale: The request gives network callers host update and restart authority, while current code intentionally exposes only `update.status` over Admin HTTP RPC and keeps `update.run` on the Gateway control-plane RPC surface.

Owner confidence: high

Options:

- **Split and defer HTTP update authority (recommended):** Keep the version metadata decision in the narrower tracker and require a maintainer-approved security/API design before exposing update execution over HTTP.
- **Expose via Admin HTTP RPC:** Add `update.run` or a narrow wrapper to the default-off admin HTTP RPC plugin with private-ingress, auth, audit, rate-limit, target-version, and handoff proof requirements.
- **Reject HTTP update execution:** Keep update execution limited to the existing CLI/WebSocket/control-plane paths and document that fleet tools should use those or an external orchestrator.
