## Summary

Keep open: current main still returns shallow `/health` and `/healthz` JSON without version metadata, and the existing authenticated update machinery is only available through Gateway RPC, not through a dedicated `POST /admin/update` or the opt-in Admin HTTP RPC allowlist. The version half partially overlaps the canonical open version-metadata issue, but the HTTP update surface remains a separate product and security decision.

## What This Changes

Request to add running-version metadata to the gateway health response and add an authenticated HTTP admin update endpoint for fleet tooling.

## Best Possible Solution

Use https://github.com/openclaw/openclaw/issues/91795 for the version-only contract, and make this issue the maintainer decision surface for whether fleet update orchestration should be exposed through the opt-in Admin HTTP RPC route, a dedicated endpoint, or kept on existing WebSocket/CLI paths.

Question: Should OpenClaw expose host update execution to HTTP fleet tooling, and if so should it be through the opt-in Admin HTTP RPC allowlist or a dedicated `POST /admin/update` endpoint?

Rationale: Current main intentionally keeps health probes shallow and keeps `update.run` out of the Admin HTTP RPC allowlist; changing either surface affects public metadata and trusted operator control-plane security.

Likely owner: Peter Steinberger

Owner confidence: high

Options:

- **Version only, no HTTP update yet (recommended):** Keep the version metadata decision on https://github.com/openclaw/openclaw/issues/91795 and defer or reject HTTP-triggered updates until a stronger security design is approved.
- **Expose update.run through Admin HTTP RPC:** Add `update.run` to the existing opt-in `/api/v1/admin/rpc` allowlist with explicit private-ingress docs, tests, rate-limit coverage, and update/restart proof.
- **Design a dedicated update endpoint:** Create a purpose-built `POST /admin/update` contract only if maintainers want a simpler fleet API separate from generic Admin HTTP RPC.

## Solution Assessment

Unclear until maintainers choose the security boundary. The most maintainable path is likely to reuse the existing version resolver and existing `update.run` implementation, but the public metadata field set and HTTP exposure shape need approval first.
