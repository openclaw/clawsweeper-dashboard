## Summary

Keep open: current main and v2026.6.11 still return shallow `/health` and `/healthz` payloads without version metadata, and the existing opt-in Admin HTTP RPC surface exposes `update.status` but not `update.run`. The version half is partially covered by a narrower open tracker, while HTTP-triggered update execution remains a security-boundary and product/API decision.

## What This Changes

Add runtime version metadata to health responses and add an authenticated HTTP endpoint that can trigger host package updates for fleet orchestration.

## Best Possible Solution

Split the concerns: keep the public version metadata decision on the narrower open version tracker, and expose update execution over HTTP only if maintainers approve an opt-in trusted operator contract, likely by deliberately extending Admin HTTP RPC rather than adding a parallel one-off endpoint.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose update execution over a gateway-authenticated HTTP surface for fleet tools, and if so should that be a dedicated `/admin/update` contract or an allowlisted Admin HTTP RPC wrapper around `update.run`?

Rationale: The source gap is clear, but the requested endpoint would give network callers host package-update and restart authority while the current trusted Admin HTTP RPC surface deliberately omits `update.run`.

Likely owner: steipete

Owner reason: This is the strongest routing match across Admin HTTP RPC, Gateway HTTP security docs, update docs, and version helper history.

Owner confidence: high

Options:

- **Defer HTTP update authority (recommended):** Keep version metadata discussion in the narrow tracker and require a maintainer-owned security/API design before exposing update execution over HTTP.
- **Expose through Admin HTTP RPC:** Allow or wrap `update.run` only on the default-off Admin HTTP RPC surface with explicit private-ingress, auth, audit, rate-limit, handoff, and failure-mode documentation and tests.
- **Reject HTTP update execution:** Keep update execution limited to CLI/WebSocket/control-plane paths and document that fleet tools should use those surfaces or an external orchestrator.

## Solution Assessment

No, not as one automatic combined change. Version reporting is a narrow additive public contract, but HTTP-triggered updates should reuse or wrap `update.run` only after maintainers approve the security boundary and API shape.
