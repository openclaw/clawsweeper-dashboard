## Summary

Keep open: the version-in-health half overlaps the open version-metadata tracker, but the authenticated HTTP update surface is not implemented or fully superseded. Current main has `update.run` over Gateway RPC and an opt-in admin HTTP RPC plugin, but that plugin intentionally allowlists only `update.status`, so exposing host updates over HTTP still needs maintainer security/product direction.

## What This Changes

Request adds runtime version metadata to Gateway health responses and an authenticated HTTP endpoint to trigger OpenClaw updates for fleet tooling.

## Best Possible Solution

Resolve version metadata in the canonical version-only issue, and if maintainers approve HTTP-triggered updates, expose `update.run` through the existing admin HTTP RPC contract with focused docs, auth/rate-limit tests, and upgrade proof rather than adding a bespoke `/admin/update` endpoint.
