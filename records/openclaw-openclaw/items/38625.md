## What This Changes

Request to add runtime version metadata to Gateway health responses and add an authenticated HTTP endpoint that can trigger host package updates.

## Best Possible Solution

Split the concerns: keep the version metadata contract in https://github.com/openclaw/openclaw/issues/91795, and expose update execution only through a maintainer-approved, opt-in trusted admin HTTP surface that reuses `update.run` or the external-updater direction safely.

Question: Should OpenClaw expose Gateway update execution to HTTP-authenticated operator callers, and if so should that be a new `/admin/update` endpoint or an allowlisted Admin HTTP RPC wrapper around `update.run`?

Rationale: The request expands host package-update and restart authority from existing Gateway control-plane paths to an HTTP surface, and also asks for target-version semantics that current `update.run` does not support.

Likely owner: steipete

Owner reason: This is a product/security boundary decision across Gateway update flow and Admin HTTP RPC, both areas tied to this owner history.

Owner confidence: medium

Options:

- **Split and design first (recommended):** Keep version metadata in the narrower canonical issue and require a maintainer-owned security/API design before adding HTTP update execution.
- **Expose through Admin HTTP RPC:** Add `update.run` or a narrow wrapper to the disabled-by-default Admin HTTP RPC plugin with explicit trusted-ingress, auth, audit, rate-limit, handoff, and target-version proof requirements.
- **Decline HTTP update execution:** Keep update execution limited to CLI/WebSocket/control-plane paths and document that fleet tools should use those or an external orchestrator.

## Reproduction Assessment

Yes, at source level. Current main’s `/health` and `/healthz` serializer still returns only `{ ok: true, status }`, and Admin HTTP RPC allowlists `update.status` while omitting `update.run`.

## Solution Assessment

No, not as one automatic combined endpoint. Version reporting is a narrow additive public contract, but HTTP-triggered updates should reuse or wrap `update.run` only after maintainers approve the security boundary and API shape.
