## Summary

Keep open: current main still does not expose runtime version metadata from `/health` or `/healthz`, and the HTTP-triggered update endpoint remains a security-sensitive product decision rather than a narrow code cleanup. The version half is narrower and already tracked by https://github.com/openclaw/openclaw/issues/91795, while remote update orchestration overlaps broader updater work in https://github.com/openclaw/openclaw/issues/77511 and https://github.com/openclaw/openclaw/issues/12855.

## What This Changes

Request to add runtime version metadata to gateway health responses and add an authenticated `POST /admin/update` endpoint for package-manager-driven updates.

## Best Possible Solution

Split the work: resolve the health-version contract in the narrower open observability issue, and keep remote update execution behind an explicit maintainer-approved admin/updater design with security review and upgrade proof.
