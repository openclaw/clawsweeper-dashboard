## Summary

Keep open: current main and v2026.6.11 still expose Gemini managed web_search as an API-key path, while ADC support exists on the separate google-vertex model-provider transport. The request is a valid Google auth/provider feature, but the durable web_search API shape needs maintainer direction before implementation.

## What This Changes

Request ADC-based Google Enterprise/Vertex authentication for Gemini web_search instead of API-key-only Google Search grounding.

## Best Possible Solution

Add maintainer-approved ADC-backed web_search support inside the Google plugin/provider boundary, reusing the existing Vertex ADC helpers with focused docs and tests for both API-key and ADC search paths.

## Reproduction Assessment

Yes, by source inspection: current main's Gemini web_search credential resolver accepts API-key-style inputs only and returns missing_gemini_api_key when none are present. I did not run a live Google Enterprise ADC web_search request, so this is source-reproducible rather than runtime-reproduced.

## Solution Assessment

Unclear: ADC support belongs in the Google plugin boundary, but maintainers should choose whether the permanent API is a google-vertex web_search provider, a Gemini webSearch auth mode, or provider-auth linkage before implementation.
