## Summary

Keep this protected security report open for explicit Gateway security-owner disposition. Current main does not use the reported `command-parser.ts`/Zod path: the WebSocket handler parses JSON directly, validates Gateway protocol frames, and dispatches authenticated requests. `JSON.parse()` with reserved keys does not by itself prove prototype pollution; the missing evidence is a concrete unsafe merge, assignment, or property-resolution sink. Likely related people: joshavant for recent Gateway security-boundary work, vincentkoc for recent WebSocket/runtime changes, and steipete for extensive history on the handler.

## What This Changes

Audit whether untrusted Gateway WebSocket JSON can cause prototype pollution and, if confirmed, reject dangerous prototype-bearing payloads at the canonical protocol boundary.

## Best Possible Solution

Add focused regression coverage that sends top-level and nested reserved keys through connect and representative authenticated requests, asserts that prototypes and authorization-relevant lookups remain unchanged, and only if a sink is proven adds centralized fail-closed rejection with an explicit protocol error rather than silently dropping fields.
