## Summary

Keep this protected security report open for explicit security-owner disposition. Current main parses Gateway frames directly in the WebSocket message handler and validates them before dispatch, not through the reported `command-parser.ts`/Zod path; however, the available report still lacks a concrete parse-to-mutation sink proving prototype pollution. Likely related people: joshavant for the documented Gateway/security ownership area, vincentkoc for recent Gateway/security work, and steipete for extensive history on the WebSocket handler.

## What This Changes

Investigate and, if necessary, harden incoming Gateway WebSocket command parsing against prototype-pollution payloads.

## Best Possible Solution

Have a Gateway security owner privately trace representative and generic request parameters through method validation and mutation helpers, add a focused regression probe asserting that crafted keys cannot alter any prototype, and harden the narrow shared boundary only if a reachable sink is confirmed.
