Keep this protected security report open for explicit Gateway security-owner disposition, but the reported exploit chain is not currently established: current main parses JSON directly, uses TypeBox protocol validators rather than the alleged Zod command parser, and no prototype-mutating sink is identified. Likely related people: joshavant for recent Gateway auth-boundary work, vincentkoc for recent Gateway runtime work, and steipete for extensive handler history.

## What This Changes

Investigate and, if necessary, harden Gateway WebSocket parsing against reserved prototype keys in attacker-controlled request frames.

## Best Possible Solution

Add a focused security regression probe that sends reserved keys through both the unauthenticated connect path and representative authenticated method validators, asserts that prototypes remain unchanged and unknown fields fail closed, and introduce centralized sanitization only if that probe demonstrates a real cross-method sink.
