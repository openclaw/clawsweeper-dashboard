## Summary

Keep this protected security report open for explicit Gateway security-owner disposition. Current main parses frames directly in the WebSocket message handler and validates them with TypeBox/Ajv rather than the reported `command-parser.ts`/Zod path; plain `JSON.parse()` alone does not establish prototype pollution, but a targeted audit is still needed to exclude a later unsafe merge or assignment sink. Likely related people: joshavant for recent Gateway security-boundary work, vincentkoc for recent WebSocket handling changes, and steipete for extensive history on the handler.

## What This Changes

Determine whether hostile Gateway WebSocket JSON can cause prototype pollution, and reject or disconnect clients that send dangerous prototype keys if the vulnerability is reproducible.

## Best Possible Solution

Privately exercise crafted authenticated frames against handlers that merge, clone, patch, or persist request parameters; add a regression at the narrow parse-to-sink boundary if mutation is demonstrated, otherwise document the negative audit and close the report rather than introducing an unproven global parser rule.
