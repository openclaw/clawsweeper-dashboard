## Summary

Keep this protected security report open for explicit Gateway security-owner disposition, but the reported exploit chain is not established: current inbound frames are parsed in the WebSocket message handler and passed through TypeBox-backed frame and parameter validators, while `JSON.parse()` alone does not mutate prototypes. ([github.com](https://github.com/openclaw/openclaw/raw/refs/heads/main/src/gateway/server/ws-connection/message-handler.ts))

## What This Changes

Investigate and harden the Gateway against alleged prototype pollution from `__proto__` or `constructor` keys in inbound WebSocket JSON frames.

## Best Possible Solution

Privately test a minimal WebSocket payload against current main, trace schema-valid parameters through the authenticated dispatcher and plugin method boundary for unsafe merge/assignment sinks, then either patch the concrete sink with regression coverage or close the report as a non-vulnerability.
