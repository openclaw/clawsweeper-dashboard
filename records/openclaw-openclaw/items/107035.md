## Summary

Keep this protected security report open for focused maintainer triage, but the reported vulnerability is not currently demonstrated: the Gateway parses frames in `src/gateway/server/ws-connection/message-handler.ts`, validates them through closed TypeBox protocol schemas rather than permissive Zod objects, and the report identifies no assignment or merge sink that would turn parsed keys into prototype pollution. citeturn8view0turn10view0

## What This Changes

Investigate and harden Gateway WebSocket command parsing against prototype-pollution keys in incoming JSON payloads.

## Best Possible Solution

Add a focused security regression probe that submits own `__proto__` and `constructor` properties through parsing, envelope validation, and representative core/plugin dispatch while checking prototypes before and after; harden only an identified unsafe sink rather than globally rewriting parsed JSON.
