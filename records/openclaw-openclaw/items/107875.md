## Summary

The latest head fixes the prior cache-commit ordering blocker: candidate hook resolution no longer mutates the active cache, accepted startup and hot reloads advance one generation, and stale in-flight imports cannot republish into the new cache. No discrete correctness defect remains, but the current-head `check-test-types` failure must be resolved or shown unrelated before merge.

Likely related people: `ThomsenDrake` for the original hooks feature history and `steipete` for subsequent hook-transform security and runtime work; both are medium-confidence routing candidates.

## What This Changes

The PR adds generation-based invalidation for gateway hook-transform modules at accepted startup and hot-reload commit edges, with rejected-reload and overlapping-import regression coverage.

## Best Possible Solution

Keep a single lifecycle-owned transform generation, advance it only when startup or hot reload accepts the hooks snapshot, preserve the active generation on rejected candidates, block stale imports from repopulating newer generations, and land only after exact-head type and gateway checks pass.
