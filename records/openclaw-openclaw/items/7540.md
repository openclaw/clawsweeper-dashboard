## Summary

Current main still ignores Baileys inbound call events, and no canonical issue or merged change replaces this request. Keep it open for a maintainer decision because the useful implementation boundary is clear, but consent, authorization, retention, storage, and agent exposure for sensitive call metadata remain product/security choices.

## What This Changes

Add detection of Baileys WhatsApp voice/video call events so agents can treat calls as contact activity.

## Best Possible Solution

Implement a minimal, opt-in WhatsApp-plugin call-activity event after approving access rules; start with transient typed events, and add SQLite-backed history only if maintainers define a durable retention and query contract.
