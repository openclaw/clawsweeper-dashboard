## Summary

Keep open. Current main still does not consume inbound Baileys call events, and the merged outbound MeowCaller capability is a separate workflow. The feature is viable inside the WhatsApp plugin, but maintainers must choose between transient event delivery and durable contact history because those models have substantially different privacy, identity, retention, storage, and API contracts.

## What This Changes

Add optional handling of Baileys WhatsApp call events so agents can account for voice and video calls as contact activity.

## Best Possible Solution

Define an opt-in, WhatsApp-plugin-owned transient activity path that sanitizes and authorizes Baileys call updates before exposing a documented event; add durable per-contact history only through a separately approved canonical SQLite state model with retention and deletion controls.

Question: Should WhatsApp call activity be exposed only as transient sanitized events, or persisted as durable per-contact history for reminder workflows?

Rationale: Transient event delivery and durable relationship history have materially different privacy, identity, retention, deduplication, storage, migration, deletion, and public API requirements that cannot be selected safely from implementation details alone.

Owner confidence: high

Options:

- **Transient Events Only (recommended):** Add opt-in sanitized call-status events inside the WhatsApp plugin without retaining per-contact call history.
- **Durable Contact History:** First design a canonical SQLite activity model with identity resolution, retention, migration, deletion, and user-control contracts.
- **Decline Call Tracking:** Leave Baileys call metadata unconsumed if the privacy and long-term maintenance costs exceed the optional reminder value.

## Reproduction Assessment

Yes at source level: the exact pinned Baileys package exposes `call: WACallEvent[]`, while current main has no production `call` listener or call-event processing path. This read-only review did not perform a live incoming-call trace.

## Solution Assessment

No, not as proposed in full. Subscribing to the event is technically appropriate, but directly adding `callsToday` or `lastCallWith` would prematurely create a sensitive durable state contract; a sanitized transient event is the narrowest maintainable starting point.
