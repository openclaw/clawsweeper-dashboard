## Summary

Keep open: current main and v2026.6.11 still do not consume Baileys inbound call events, and the merged MeowCaller work only adds outbound requester-bound calling, so this remains a WhatsApp-plugin product/security feature.

## What This Changes

Request to subscribe to Baileys WhatsApp call events and expose sanitized call activity so calls count as contact, not only messages.

## Best Possible Solution

Implement this inside the WhatsApp plugin as an opt-in, sanitized WACallEvent activity path that applies the existing account, DM/group, self-chat, allowlist, and privacy boundaries before exposing activity to agents or plugins.

## Reproduction Assessment

Yes for the source-level gap: current main subscribes to WhatsApp message, connection, and group events but not Baileys call events, while the pinned dependency exposes the event. No live WhatsApp call flow was run.

## Solution Assessment

Unclear as a final product shape. The WhatsApp plugin is the right owner boundary, but maintainers still need to choose one opt-in sanitized activity surface rather than adding ad hoc session metadata plus a parallel tool API.
