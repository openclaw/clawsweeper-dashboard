## Summary

Keep open for a maintainer product and privacy decision: current WhatsApp documentation exposes only an experimental outbound MeowCaller tool, not inbound Baileys call activity, so the central request remains unmet. Likely related people: steipete is the strongest routing candidate (high confidence) from the WhatsApp-plugin history and prior issue scoping.

## What This Changes

Add opt-in support for receiving inbound WhatsApp/Baileys call events and exposing appropriately sanitized contact activity to agents.

## Best Possible Solution

Define a narrowly scoped, opt-in inbound-call activity contract in the official WhatsApp plugin: normalize only the metadata agents need, enforce the same account and authorization boundaries as inbound messages, decide retention explicitly, and expose it through one documented hook or tool surface with focused privacy tests.

- **Design durable contact activity:** First define retention, identity mapping, deletion, and agent-session semantics before storing calls as relationship history.
- **Decline inbound call exposure:** Keep the existing outbound requester-bound call capability only and document that inbound call tracking is intentionally unsupported.

## Solution Assessment

Unclear until maintainers choose the privacy, retention, and public event contract. Adding a raw Baileys listener alone is not the best fix because it would not define safe agent exposure or contact-history semantics.
