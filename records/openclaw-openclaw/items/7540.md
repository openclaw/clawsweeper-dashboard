## Summary

Keep open: current main and the latest release still do not subscribe to inbound Baileys WhatsApp `call` events. The merged MeowCaller work is useful adjacent outbound-call support, but it does not cover the requested inbound call-event/contact-history path, and the remaining implementation needs product and security review.

## What This Changes

Add WhatsApp/Baileys inbound voice/video call event detection so call activity can count as contact history, not only messages.

## Best Possible Solution

Implement this inside the official WhatsApp plugin with an explicit opt-in, a Baileys `call` listener, sanitized `WACallEvent` normalization, existing DM/group/self-chat/access-control privacy boundaries, documented exposure through a session/activity or hook/tool surface, and focused tests/docs.

## Reproduction Assessment

Yes for a source-level reproduction: current main registers WhatsApp message, connection, and group listeners but no Baileys `call` listener, while the pinned Baileys package exposes `call: WACallEvent[]`. I did not run a live WhatsApp call event.

## Solution Assessment

Unclear until maintainers choose the privacy/product surface. The best shape is plugin-owned inbound call-event handling, not the existing outbound MeowCaller tool or the separate PSTN voice-call plugin.
