## Summary

Current `main` still does not consume Baileys inbound call events, and no related issue or merged PR owns that remaining behavior; the merged MeowCaller work is outbound-only. Keep this issue open for a maintainer product/privacy decision before implementation.

Likely related people:

- Vincent Koc — adjacent WhatsApp inbound and access-control contributor (medium confidence).

## What This Changes

Add opt-in ingestion of Baileys WhatsApp call events so sanitized call activity can contribute to agent-visible contact context.

## Best Possible Solution

Add an opt-in, WhatsApp-plugin-owned, access-filtered ephemeral activity event with a minimal normalized payload; defer persistent call history or a query tool until maintainers approve a retention and user-control model.

Options:

- **Ephemeral sanitized event (recommended):** Emit an opt-in, access-filtered activity event with minimal fields and no persistent call history.

- **Defer call ingestion:** Wait for a general contact-activity product model before consuming Baileys call events.

## Solution Assessment

No, the issue's broad alternatives are not yet the best final design. The WhatsApp plugin is the correct owner, but an ephemeral sanitized event is safer and narrower than immediately adding persistent session metadata or a broad query action.
