## Summary

Keep open: current main and the latest release still do not subscribe to Baileys WhatsApp call events, and the remaining work is a valid WhatsApp-plugin feature that needs product/security direction before implementation.

## What This Changes

Add WhatsApp/Baileys call-event detection so WhatsApp voice/video calls can count as contact activity alongside messages.

## Best Possible Solution

Keep this open for a WhatsApp-plugin-owned, opt-in sanitized call-activity path that applies the existing account, DM/group, self-chat, allowlist, and privacy boundaries before exposing contact activity to agents or plugins.

## Reproduction Assessment

Yes for the current source gap: current main subscribes to WhatsApp message, connection, and group events but not Baileys call events, while the pinned dependency exposes the event. No live WhatsApp call flow was run.

## Solution Assessment

Unclear as a final product shape. The WhatsApp plugin is the right owner boundary, but maintainers still need to choose one opt-in sanitized activity surface instead of adding ad hoc session metadata plus a parallel tool API.
