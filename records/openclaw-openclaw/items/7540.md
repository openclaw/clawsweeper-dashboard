## Summary

Keep open: current main and the latest release still do not subscribe to inbound Baileys WhatsApp call events, and the merged MeowCaller work is outbound requester-bound calling only.

## What This Changes

The issue requests subscribing to Baileys WhatsApp `call` events and exposing sanitized call activity so WhatsApp calls can count as contact activity.

## Best Possible Solution

Implement this inside the WhatsApp plugin as an opt-in, sanitized `WACallEvent` activity path that applies existing account, DM/group, self-chat, allowlist, and privacy boundaries before exposing one documented agent or plugin surface.

## Reproduction Assessment

Yes for the source-level gap: current main subscribes to WhatsApp message and connection events but not Baileys call events, while the pinned dependency exposes the event. No live WhatsApp call flow was run.

## Solution Assessment

Unclear as a final product shape. The WhatsApp plugin is the right owner boundary, but maintainers still need to choose one opt-in sanitized activity surface instead of adding ad hoc session metadata plus a parallel tool API.
