## Summary

Keep open: current WhatsApp plugin code still registers credential and connection handlers but no Baileys `call` listener, and the merged MeowCaller work covers requester-bound outbound calls rather than inbound call activity. The request needs a maintainer decision on consent, retention, identity/access filtering, and how sanitized activity reaches agents before implementation can proceed.

## What This Changes

Add inbound WhatsApp/Baileys call-event tracking so sanitized call activity can count as contact activity for OpenClaw agents.

## Best Possible Solution

Define an opt-in WhatsApp-plugin contract that normalizes only the needed call activity, applies existing account/self/DM-group/allowlist privacy rules before persistence or agent exposure, and documents exactly which statuses count as contact.
