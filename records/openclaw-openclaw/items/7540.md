## Summary

Current main and the latest release still do not consume Baileys inbound call events, and no related issue or PR owns that remaining work. The request fits the WhatsApp plugin, but implementation should wait for a maintainer choice between transient call events and durable contact history because those paths have materially different privacy, storage, identity, and API contracts.

## What This Changes

Add opt-in ingestion of Baileys WhatsApp call events so agent workflows can account for calls as contact activity.

## Best Possible Solution

Implement a transient, sanitized, access-controlled call-event path inside the WhatsApp plugin first; design durable contact history only as a separately approved canonical data model and query contract.
