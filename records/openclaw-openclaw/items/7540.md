## Summary

Keep this issue open. The supplied current-main reviews found no Baileys `call` listener or documented call-activity surface, while the merged MeowCaller work is explicitly requester-bound outbound calling rather than inbound WhatsApp call observation. This needs a maintainer decision on consent, retention, access filtering, and the supported agent-facing contract before implementation.

## What This Changes

Add WhatsApp call-event observation so agents can treat approved incoming or outgoing WhatsApp calls as contact activity alongside messages.

## System Context

The bundled WhatsApp plugin owns the Baileys socket and turns allowed inbound transport events into OpenClaw channel activity. A call-event feature would receive call metadata from that socket, apply the plugin's privacy and account boundaries, then expose a deliberately limited activity signal to agents or plugin hooks.

## Architecture Diagram

flowchart LR

  B --> C[WhatsApp plugin]
  C --> D[Account and privacy filtering]
  D --> E[Sanitized call activity]
  E --> F[Documented agent or hook surface]
  F --> G[Contact-aware automation]

## Best Possible Solution

Define a minimal opt-in WhatsApp-plugin contract for sanitized call activity, including allowed statuses, consent and retention rules, account/DM/group filtering, and one documented agent or hook surface; then implement it with focused tests and user-facing docs.
