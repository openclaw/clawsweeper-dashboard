## Summary

Keep open. Current main and v2026.6.11 make pinned session model state visible and provide `/model default`, and reset paths clear auto fallback pins, but explicit and legacy user model pins are still intentionally preserved across restart and `/new`/`/reset`; the remaining reset, precedence, or bulk-clear behavior needs maintainer product review.

## What This Changes

Request to prevent session-level `modelOverride` from silently outliving default model config changes across gateway restarts and `/new`, with clear visibility and reset behavior.

## Best Possible Solution

Keep the user-vs-auto override distinction, then let maintainers choose an explicit bulk reset, doctor/reconcile, or visibility path for clearing persisted user pins without silently changing precedence.

## Reproduction Assessment

Yes, from source. Current reset code and tests show auto fallback overrides are cleared while explicit and legacy user model overrides are intentionally preserved across `/new`/`/reset`; no live gateway restart repro was run in this read-only pass.

## Solution Assessment

No for an unconditional config-precedence or reset-clear change. The best path is a maintainer-approved clear/reconcile behavior that preserves intentional user pins while making stale state visible and recoverable.
