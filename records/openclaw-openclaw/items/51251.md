## Summary

Keep open: current main and v2026.6.11 intentionally preserve explicit and legacy session model pins across reset/restart, while docs/status now make the pin visible and `/model default` clears the current session. ## What This Changes

The issue asks for session-level model overrides set by `/model` to stop silently outliving config default changes and fresh sessions, or to become clearly visible and resettable.

## Best Possible Solution

Use a maintainer-approved source-aware resolver/reset design: keep exact user pins visible, preserve shipped compatibility, and add explicit scoped reset or reconcile behavior only after tests, docs, and doctor semantics are aligned.

## Solution Assessment

No for an unconditional clear or config-precedence change: current docs/tests treat explicit session selections as exact user intent. The better path is a maintainer-approved reset/reconcile behavior that keeps user intent visible and clearable without silently discarding pins.
