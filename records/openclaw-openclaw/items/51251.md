## Summary

Keep open: current main and v2026.6.11 already make session pins visible, provide `/model default`, and clear auto-created fallback pins on reset, but explicit and legacy user model pins are still preserved by design. The remaining bulk-clear or precedence change is compatibility-sensitive product work rather than a cleanup close.

## What This Changes

The issue requests preventing persisted session-level model/provider overrides from silently overriding changed config defaults across restarts and `/new`, or adding clear/reset visibility for those overrides.

## Best Possible Solution

Keep the explicit user-vs-auto override distinction, and make any broader bulk reset, reconcile, or config-precedence behavior a maintainer-approved model/session recovery surface with focused upgrade proof.

## Reproduction Assessment

Yes. Current source and tests show explicit or legacy user model overrides are intentionally preserved across reset/restart semantics while auto-created fallback pins are cleared; I did not run a live gateway repro in this read-only review.

## Solution Assessment

No for an unconditional clear or config-precedence change. The maintainable path is a maintainer-approved reset/reconcile behavior that keeps user intent visible and clearable without silently discarding explicit pins.
