## Summary

Keep open: current main and the latest release now make pinned session model state visible and provide `/model default`, and reset paths clear auto-created fallback pins, but explicit user and legacy model pins are still intentionally preserved across reset/restart. The remaining bulk-clear or precedence change is compatibility-sensitive product work, not a safe cleanup close.

## What This Changes

The issue reports that a session-level `/model` override persists across gateway restarts and new-session flows, hiding later config-default model changes.

## Best Possible Solution

Keep the explicit user-vs-auto override distinction unless maintainers approve a broader reset/reconcile surface for bulk clearing or changed precedence across session/auth state.

## Reproduction Assessment

Yes. Current source and tests show explicit or legacy user model overrides are intentionally preserved across `/new`/`/reset`, while auto-created fallback pins are cleared; I did not run a live gateway repro in this read-only review.

## Solution Assessment

No for an unconditional clear or config-precedence change: current docs/tests treat explicit session selections as exact user intent. The better path is a maintainer-approved reset/reconcile behavior that keeps user intent visible and clearable without silently discarding pins.
