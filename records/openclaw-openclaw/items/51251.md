## Summary

Keep open: current main and v2026.6.11 implement visibility, `/model default`, and reset cleanup for auto-created fallback pins, but explicit and legacy session model pins are still intentionally preserved across restarts and resets. The remaining bulk-clear, reconcile, or precedence change is compatibility-sensitive product work, not implemented-on-main cleanup.

## What This Changes

Request to stop stale session-level `modelOverride` from silently out-prioritizing changed config defaults and to provide reset or visibility for session model pins.

## Best Possible Solution

Preserve the explicit user-vs-auto override distinction by default, keep the visible `/model default` clear path, and let maintainers decide a narrow bulk reset, reconcile command, or shared resolver path for the remaining stale session state.

## Reproduction Assessment

Yes from source: current code, docs, and tests show explicit and legacy `modelOverride` values survive reset/restart while auto fallback pins are cleared; I did not run a live gateway repro.

## Solution Assessment

Current main is a partial and safer solution because it adds visibility, `/model default`, and auto-fallback cleanup; an unconditional clear or config-precedence change is not clearly best until maintainers decide explicit and legacy pin semantics.
