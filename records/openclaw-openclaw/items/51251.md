## Summary

Keep open: current main and v2026.6.11 make user-pinned session models visible, provide `/model default`, and clear auto-created fallback pins, but explicit user and legacy model pins are still intentionally preserved across restart and reset. The remaining bulk-clear, reconcile, or precedence change is compatibility-sensitive product work, with broader tracking in https://github.com/openclaw/openclaw/issues/28965 and https://github.com/openclaw/openclaw/issues/87957.

## What This Changes

The issue asks OpenClaw to stop or clearly surface persisted session model overrides when config defaults change, especially across gateway restart and `/new`.

## Best Possible Solution

Keep the explicit user-vs-auto override distinction until maintainers define a reset/reconcile surface for clearing persisted pins, then implement it consistently across chat reset, gateway reset, status/docs, and the shared resolver work.

## Reproduction Assessment

Yes, source-level: seed a persisted session with a user or legacy `modelOverride`, then trigger `/new` or gateway reset; current code preserves that pin while status shows how to clear it. I did not run a live gateway restart reproduction in this read-only pass.

## Solution Assessment

No for an unconditional clear or config-precedence change: current docs and tests treat explicit session selections as user intent. The better solution is a maintainer-approved reset/reconcile path that clears pins deliberately without silently discarding valid per-session choices.
