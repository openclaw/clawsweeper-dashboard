## Summary

Keep open: current main has fixed the auto-fallback part and now exposes per-session model state better, but explicit and legacy `/model` pins are still intentionally preserved across reset/restart, so the remaining bulk-clear or precedence change is a compatibility-sensitive product decision.

## What This Changes

The issue requests that stale session-level model overrides stop silently taking precedence over changed config defaults, especially after gateway restart or `/new`.

## Best Possible Solution

Maintainers should choose the persisted-override policy explicitly, likely keeping intentional session pins while adding a clear bulk reset/reconcile or doctor path and keeping status surfaces honest about override source.

## Reproduction Assessment

Yes for the remaining current behavior by source inspection: a session entry with `modelOverrideSource: "user"` or a legacy `modelOverride` is preserved through reset/restart paths. I did not run a live gateway reproduction in this read-only review.

## Solution Assessment

No, not as an automatic bugfix: making config defaults outrank explicit session pins or clearing all pins on `/new` would change a currently documented contract. The safer path is an explicit maintainer-approved clear/inherit/reconcile behavior with tests and docs.
