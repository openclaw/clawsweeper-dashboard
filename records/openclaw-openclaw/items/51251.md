## Summary

Keep open: current main and v2026.6.11 already make model pins visible, provide `/model default`, and clear auto-created fallback pins on reset, but explicit and legacy user model pins are still intentionally preserved. The remaining bulk-clear, reconcile, or config-precedence behavior is compatibility-sensitive product work rather than a cleanup close.

## What This Changes

The issue requests clearer and safer handling of persisted session-level model overrides after config default changes, gateway restarts, and `/new` resets.

## Best Possible Solution

Keep user-selected model pins explicit and visible, and have maintainers choose a scoped bulk reset, reconcile, or invalid-provider cleanup path that does not silently discard intentional selections.

## Reproduction Assessment

Yes at source level: current source and tests intentionally preserve explicit or legacy user model pins across reset/restart semantics while clearing auto fallback pins. I did not run a live gateway restart with real providers in this read-only review.

## Solution Assessment

No for an unconditional config-precedence or clear-on-restart change; that would conflict with the documented strict user-selection contract. A narrower maintainer-approved reset/reconcile behavior is the safer solution.
