## Summary

Keep open. Current main and the latest release now document and expose pinned session model state and clear auto-fallback pins on reset, but explicit or legacy user model pins are still intentionally preserved across reset/restart; the remaining bulk-clear or precedence change is compatibility-sensitive product work.

## What This Changes

The issue asks OpenClaw to stop persisted session model overrides from silently masking changed configured defaults, or to make them visible and clearable.

## Best Possible Solution

Keep the explicit user-vs-auto override contract, and add a maintainer-approved reset/reconcile surface if OpenClaw should bulk-clear or reprioritize persisted session selections.

## Reproduction Assessment

Yes, from source. Current reset code and tests show explicit or legacy user model overrides are preserved across new/reset paths while auto fallback pins are cleared.

## Solution Assessment

No for an unconditional clear or config-precedence change. The maintainable path is a visible, explicit reset/reconcile behavior that does not silently discard intentional user pins.
