## Summary

Keep open: current main and v2026.6.11 already make stale pins visible, provide `/model default`, and clear auto-created fallback pins on reset, but explicit and legacy user model pins still intentionally persist. The remaining bulk-clear or config-precedence behavior is compatibility-sensitive product work, not a cleanup close.

## What This Changes

The issue asks OpenClaw to stop stale session-level model/provider overrides from silently outranking changed config defaults, with reset, visibility, and bulk-clear behavior.

## Best Possible Solution

Keep the explicit user-vs-auto override distinction, then add a maintainer-approved reset/reconcile recovery surface for clearing persisted model/provider pins without silently discarding user intent.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction of the remaining state: explicit or legacy user model pins are preserved across reset/restart semantics while auto-created fallback pins are cleared. I did not run a live Gateway repro in this read-only review.

## Solution Assessment

No, an unconditional clear or config-takes-precedence change is not clearly the best fix because it can erase intentional session pins. The safer solution is a maintainer-approved reset/reconcile path with explicit user-facing semantics.
