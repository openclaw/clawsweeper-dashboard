## Summary

Keep open: current main and v2026.6.11 expose pinned model state and provide `/model default`, and reset paths clear auto-sourced fallback pins, but explicit and legacy session model pins are still intentionally preserved across reset/restart. The remaining bulk-clear, default-precedence, or reconcile behavior is compatibility-sensitive product work rather than a safe cleanup close.

## What This Changes

The issue asks OpenClaw to stop or expose sticky per-session model overrides so config default changes and new sessions are not silently masked.

## Best Possible Solution

Keep the explicit user-vs-auto override distinction, and add a maintainer-approved reset/reconcile or bulk-clear surface that makes stale pins clearable without silently discarding intentional session selections.

## Reproduction Assessment

Yes. Current source and tests show explicit or legacy user model overrides are intentionally preserved across `/new` and sessions.reset, while auto-created fallback pins are cleared; I did not run a live gateway repro in this read-only review.

## Solution Assessment

No for an unconditional clear or config-precedence change. Current docs/tests treat explicit session selections as user intent, so the better fix is a maintainer-approved reset/reconcile behavior that keeps pins visible and explicitly clearable.
