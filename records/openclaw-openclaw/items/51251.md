## Summary

Keep open: current main and v2026.6.11 make pinned session model state visible, provide `/model default`, and clear auto-created fallback pins on reset, but explicit user and legacy model pins are still intentionally preserved across reset/restart. The remaining bulk-clear or precedence change is compatibility-sensitive product work rather than a safe cleanup close.

## What This Changes

The issue asks OpenClaw to stop persisted session model overrides from silently masking updated config defaults after gateway restarts or new-session flows.

## Best Possible Solution

Keep the explicit user-vs-auto override distinction unless maintainers approve a broader reset/reconcile surface for bulk clearing or changed precedence across persisted session/auth state.

## Reproduction Assessment

Yes at source level: current reset code and tests show explicit or legacy model overrides survive reset while auto fallback overrides are cleared. I did not run a live gateway session in this read-only review.

## Solution Assessment

No for an unconditional clear or config-precedence change: current docs/tests treat explicit session selections as exact user intent. The better path is a maintainer-approved reset/reconcile behavior that makes persisted pins visible and clearable without silently discarding them.
