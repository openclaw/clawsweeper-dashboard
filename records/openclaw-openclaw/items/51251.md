## Summary

Keep open: current main and v2026.6.11 already make pinned session models visible, support `/model default`, and clear auto-created fallback pins on reset, but explicit and legacy user model pins are still deliberately preserved across reset/restart semantics. The remaining bulk-clear or config-precedence change is compatibility-sensitive product work, not a conservative cleanup close.

## What This Changes

The issue asks OpenClaw to stop or expose stale persisted session model overrides after default model changes and gateway restarts, especially for `/new` sessions.

## Best Possible Solution

Keep the explicit user-versus-auto override distinction, and add a maintainer-approved recovery surface such as bulk session model reset, model reconcile, or doctor/status guidance with focused upgrade proof.
