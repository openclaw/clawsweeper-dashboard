## Label Justifications

- `P1`: A deterministic regression leaves affected cron scripts unkillable and permits stale completion effects after a gateway restart.
- `impact:message-loss`: A retired script result can still enqueue a late notification or wake after its scheduler generation is discarded.
- `impact:other`: The failure also breaks operator cancellation control for a running cron task.

## Summary

Keep this regression open: the report identifies a concrete lifecycle gap in the recently merged cron script-payload path, and the `maintainer` label requires explicit maintainer handling rather than automated cleanup.

## What This Changes

Fix main-target cron script payloads so detached executions can be cancelled, are retired across scheduler generations, and cannot emit stale notify or wake effects after restart.

## Best Possible Solution

Use one canonical cron execution classification: register cancellation for detached script runs regardless of `sessionTarget`, retire their active ownership on scheduler-generation changes, and gate notify/wake processing on current cancellation and generation ownership with focused regressions.
