## Summary

Keep this PR open: the proposed retry classification is reasonable for the embedded-agent path, but it leaves the active Pi embedded failover helper with the same unclassified TLS error, so the stated provider/model recovery remains inconsistent across supported agent runtimes.

## What This Changes

Classifies Node's TLS certificate alternate-name error as a retryable failover condition and adds a regression assertion for the embedded-agent error helper.

## System Context

OpenClaw's agent runtimes turn provider transport errors into failover reasons that drive profile rotation or model fallback. Both the newer embedded-agent helper and the Pi embedded helper perform this classification before the runner decides whether to recover or surface an error.

## Architecture Diagram

  D --> E[Recovered response or surfaced error]
  F[Pi embedded helper] --> C

## Best Possible Solution

Apply the same narrowly scoped code classification to both active embedded error helpers, add equivalent regression coverage for each path, and retain normal certificate validation rather than weakening TLS checks.
