## Label Justifications

- `P2`: The issue affects normal Control UI usability for long WebChat sessions but does not block setup, auth, or core runtime availability.
- `impact:message-loss`: Older stored chat messages are not fetched into the Control UI view once the session exceeds the fixed history request window.
- `impact:session-state`: The visible WebChat session state can drift from the durable transcript because older context remains inaccessible in the active UI.
- `impact:ux-friction`: Affected users currently need a fragile bundled-asset patch or another workaround to see more history after updates.

## Summary

Keep open: current main still fetches only one 100-message Control UI history page, and the same-author linked PR is open and unmerged. The broader pagination direction remains a maintainer product choice rather than a cleanup-close candidate.

## What This Changes

The issue asks Control UI WebChat to expose older chat history beyond the initial 100 fetched messages, either by increasing the limit, adding pagination, or making the limit configurable.

## Best Possible Solution

Keep the initial Control UI history payload bounded and add an explicit older-history loading path using the existing chat.history pagination contract, unless maintainers intentionally accept the 500-message fixed-window mitigation after proof.
