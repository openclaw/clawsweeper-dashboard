## Summary

Keep open: current main still fetches only one 100-message Control UI history page, local top-scroll expansion only reveals already fetched messages, and the linked candidate PR is open and unmerged. The remaining decision is whether maintainers want a larger fixed window or proper offset-based older-history loading.

## What This Changes

The issue requests that Control UI WebChat make older chat history beyond the initial 100 messages reachable, either through a larger limit, pagination, or a supported setting.

## Best Possible Solution

Keep the initial history request bounded, then add a visible load-older path that uses chat.history offset/hasMore pagination, unless maintainers explicitly choose a coordinated larger fixed fetch and render window with tests and browser proof.
