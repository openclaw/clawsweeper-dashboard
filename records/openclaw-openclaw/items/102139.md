## Summary

Keep open: current main and the latest release still fetch a fixed 100-message Control UI history window, and the open same-author PR is only an unmerged candidate mitigation while the broader pagination direction still needs maintainer choice.

## What This Changes

The issue asks Control UI/WebChat to stop stranding older chat history behind the hardcoded 100-message initial fetch, preferably through load-older pagination or an intentional limit policy.

## Best Possible Solution

Land a bounded older-history pagination path using the existing `chat.history` offset contract, or explicitly accept and test a coordinated fixed-window policy across fetch, render, and docs.
