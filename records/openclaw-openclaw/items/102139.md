## Summary

Keep open: current main and the latest tagged release still cap Control UI history to a single 100-message fetch/render window, and the linked implementation PR is open and unmerged. The report is source-reproducible, but maintainers still need to choose between a larger fixed initial batch and offset-based older-message pagination.

## What This Changes

The issue requests that Control UI stop limiting chat history to a single 100-message page, either by increasing the limit, adding older-message pagination, or exposing a setting.

## Best Possible Solution

Preserve a bounded initial history load and add a visible older-history paging path using the existing `chat.history` offset contract, unless maintainers explicitly accept a larger fixed window after proof.
