## Label Justifications

- `P2`: The issue affects Control UI access to older chat messages but has a bounded WebChat surface and an open linked candidate PR.
- `impact:message-loss`: Messages older than the first 100 are not fetched into the Control UI history view even though the gateway can page them.
- `impact:ux-friction`: Users must patch bundled JavaScript or accept missing older history because there is no in-product load-more path.

## Summary

Keep open: current main still caps the Control UI chat-history request at 100 messages and the linked candidate PR is open rather than merged, so the central pagination/history-depth problem remains unresolved.

## What This Changes

The issue requests a Control UI WebChat history flow that can show more than the initial 100 fetched messages, preferably by offset-based load-more pagination rather than only progressive rendering of the first batch.

## Best Possible Solution

Keep this issue open until the linked PR is reviewed, merged, or replaced by a Control UI history design that uses the existing chat.history offset contract for explicit older-message loading.
