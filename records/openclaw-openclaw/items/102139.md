## Summary

Keep open: current main still loads only one bounded Control UI chat-history page, and the linked closing PR remains open and unmerged. The central choice is whether maintainers want a larger fixed batch or real older-message pagination.

## What This Changes

The issue requests a way for Control UI/WebChat to expose chat history beyond the current fixed 100-message initial load.

## Best Possible Solution

Preserve a bounded initial history load, then add an explicit load-older path that uses the existing chat.history offset metadata unless maintainers intentionally accept a coordinated fixed-window change with matching render behavior and proof.
