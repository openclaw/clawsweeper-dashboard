## Summary

Keep open: current main and the latest stable release still load only one fixed 100-message Control UI history window, while the linked candidate PR is open and maintainers still need to choose a larger fixed window versus offset-based load-older pagination.

## What This Changes

The issue asks Control UI WebChat to expose older chat-history messages beyond the current 100-message startup window, either by a larger limit, pagination, or configuration.

## Best Possible Solution

Keep the issue open until maintainers either land a bounded load-older pagination path using the existing chat.history offset contract or explicitly accept a proven larger fixed window as the intended Control UI behavior.
