## Summary

Keep open: current main still loads only one bounded Control UI chat-history page and the same-author linked PR is open with closing syntax, while the broader pagination path remains unmerged and needs maintainer direction.

## What This Changes

Request to make Control UI/WebChat expose older chat history beyond the hardcoded 100-message initial load, preferably via load-more pagination or another supported limit strategy.

## Best Possible Solution

Add a bounded older-history loading path in Control UI using the current `chat.history` offset/hasMore contract while keeping the initial payload bounded; accept a larger fixed batch only if maintainers explicitly choose that UX tradeoff with matching render-cap tests and proof.
