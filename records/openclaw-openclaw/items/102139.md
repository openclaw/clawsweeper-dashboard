## Label Justifications

- `P2`: The issue affects normal Control UI usability for long sessions, but it does not block setup, auth, or core runtime availability.
- `impact:message-loss`: Older stored chat messages are not fetched into the Control UI view once the session exceeds the fixed request window.
- `impact:ux-friction`: Affected users must patch bundled assets or use a fragile workaround to see more history after updates.

## Summary

Keep open: current main still requests only the first 100 Control UI chat-history messages, and the linked implementation PR is open and unmerged. The report is source-reproducible, but maintainers need to choose whether a larger fixed batch is acceptable or whether the issue requires offset-based older-message pagination.

## What This Changes

The issue requests that Control UI/WebChat stop limiting chat history to the initial 100 fetched messages by adding older-message pagination, raising the request limit, or exposing a supported setting.

## Best Possible Solution

Preserve the bounded initial history load for stability, then add an explicit older-history loading path that pages with `chat.history` offsets unless maintainers intentionally accept a larger fixed limit as the desired product behavior.
