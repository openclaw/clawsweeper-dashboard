- `impact:message-loss`: Older stored chat messages are not fetched into the Control UI view once the session exceeds the fixed request window.

## Summary

Keep open: current main still requests only one Control UI chat-history page with a hardcoded 100-message limit and no offset, and the linked candidate PR is open rather than merged. The remaining decision is whether to accept a larger fixed batch or require older-message pagination.

## What This Changes

The issue requests that Control UI history loading stop being capped at the first 100 fetched messages, preferably via older-message pagination or an intentional higher/configurable limit.

## Best Possible Solution

Keep the initial load bounded, then add an explicit older-history path that uses `chat.history` offsets from a Load more or scroll-to-top interaction unless maintainers deliberately accept a larger fixed cap as the product behavior.
