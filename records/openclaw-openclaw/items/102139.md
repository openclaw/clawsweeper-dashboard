## Summary

Keep open: current main still loads one no-offset Control UI history page and the visible loaded-history window is capped at 100 messages. The same-author linked PR is open, and the broader pagination direction is already tracked by an open canonical issue plus an unmerged candidate PR.

## What This Changes

The issue requests that Control UI chat history stop being capped at the first 100 fetched messages by increasing the batch, adding older-message pagination, or exposing a setting.

## Best Possible Solution

Land or replace the bounded load-older pagination path so Control UI can request older chat.history pages via offset/hasMore while preserving bounded initial payloads and intentional render-window behavior.
