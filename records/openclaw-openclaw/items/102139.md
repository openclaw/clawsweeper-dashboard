## Summary

Keep open: current main and the latest release still use a fixed 100-message Control UI history request and a 100-message render cap, while the linked one-line PR is open and unmerged. The remaining choice is whether maintainers accept a larger fixed batch or require bounded load-older pagination.

## What This Changes

The issue requests a supported way for Control UI/WebChat to access older chat-history messages beyond the current fixed 100-message initial fetch.

## Best Possible Solution

Keep the initial history payload bounded, then add an explicit load-older pagination path using the existing `chat.history` offset contract unless maintainers intentionally accept a coordinated larger fixed window with matching render behavior and proof.
