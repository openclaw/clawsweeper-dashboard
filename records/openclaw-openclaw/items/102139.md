## Summary

Keep open: current main still makes Control UI/WebChat load one fixed 100-message history page, and the linked same-author fix PR is open and unmerged. The remaining decision is whether maintainers want a larger fixed batch as a mitigation or bounded older-message pagination using the existing `chat.history` offset contract.

## What This Changes

The issue requests that Control UI stop stranding chat history at a fixed 100-message initial fetch by adding older-message loading, raising the limit, or exposing a supported setting.

## Best Possible Solution

Preserve a bounded initial history load, then add an explicit older-message loading path that pages with the current `chat.history` offset/hasMore contract unless maintainers intentionally accept a larger fixed window as the product behavior.
