## Summary

Keep open: current main and the latest stable release still have a fixed 100-message Control UI history load, and the same-author linked PR is open and unmerged. Backend offset support now exists on main, so the remaining decision is whether to accept a larger fixed batch or require a load-older UI that uses pagination.

## What This Changes

The issue asks Control UI WebChat to avoid losing access to older chat history beyond the hardcoded initial 100-message window, either by raising the limit, adding pagination, or exposing a setting.

## Best Possible Solution

Keep the initial payload bounded and add an explicit older-history loading path using the existing Gateway `chat.history` offset metadata unless maintainers intentionally accept the linked fixed-limit mitigation.
