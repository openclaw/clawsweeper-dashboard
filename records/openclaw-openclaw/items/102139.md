## Summary

Keep open: current main still fetches only one 100-message Control UI history page, and the linked candidate PR is open and unmerged. The remaining choice is whether to accept a larger fixed batch or require real older-message pagination.

## What This Changes

The issue requests a way for Control UI/WebChat to access chat history older than the current hardcoded 100-message initial load.

## Best Possible Solution

Keep the initial load bounded and add an explicit load-older path in Control UI that pages through chat.history, with focused UI/Gateway tests and browser proof before closing this issue.
