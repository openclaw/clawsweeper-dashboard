## Summary

Keep open: current main still loads only one bounded Control UI history page with a 100-message request/render cap, and the linked PR is open and unmerged. The issue is source-reproducible, but the fix direction still needs maintainer choice between accepting a larger fixed window and implementing older-message pagination.

## What This Changes

The issue requests that Control UI WebChat stop stranding older session messages behind the hardcoded 100-message initial history window.

## Best Possible Solution

Keep the initial history load bounded and add an explicit older-history loading path that uses the existing chat.history offset contract, unless maintainers intentionally accept a larger fixed window after real Control UI proof.
