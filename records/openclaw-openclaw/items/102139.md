## Summary

Keep open: current main still opens Control UI WebChat with a fixed 100-message history request/render window, and the same-author linked PR is open and unmerged. The broader WebChat scrollback work is already tracked by a canonical issue and pagination PR, but this paired issue should not be closed while its closing PR is still under review.

## What This Changes

The issue requests older Control UI WebChat history access beyond the initial 100-message batch, either by raising the limit, adding pagination, or making the limit configurable.

## Best Possible Solution

Use bounded load-older pagination from Control UI against the existing chat.history offset contract, unless maintainers explicitly accept a larger fixed initial window after real UI responsiveness proof.
