## Summary

Keep open: current main and v2026.6.11 still intentionally reject remote plain-HTTP Control UI sessions without device identity, and the remaining Docker/homelab request needs maintainer security/product direction rather than cleanup closure.

## What This Changes

The issue requests a usable path for Docker/VPS/homelab users who hit the Control UI HTTPS-or-localhost device-identity requirement over non-local plain HTTP.

## Best Possible Solution

Maintain the secure default, then have maintainers choose an explicit product path: better in-product setup/Doctor recovery for HTTPS or local access, or a clearly named opt-in plaintext-LAN mode with security warnings and focused tests.

## Reproduction Assessment

Yes. Source inspection shows a non-local plain-HTTP browser lacks the Control UI device identity path, and the gateway rejects the resulting device-less operator session unless break-glass or trusted-proxy conditions apply.

## Solution Assessment

Unclear. A mechanical crypto fallback or bypass switch is plausible, but it is only the best fix if maintainers intentionally support persistent browser identity or token-only Control UI use over remote plaintext HTTP.
