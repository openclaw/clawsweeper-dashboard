## Summary

Keep open: current main has partial Control UI and Gateway mitigations, but the source paths can still issue `sessions.list` and `chat.history` from Dashboard events, and there is no current-main live trace or merged fix proving this flood is resolved.

## What This Changes

The issue reports idle Control UI Dashboard WebSocket traffic repeatedly issuing expensive `sessions.list` and continuous `chat.history` requests, degrading Gateway responsiveness.

## Best Possible Solution

Capture a current-main Dashboard WebSocket trace with per-method latency, then fix the measured source with request coalescing/backoff and/or Gateway list-cost reduction without regressing chat freshness or active-run reconciliation.

## Reproduction Assessment

No high-confidence live reproduction was run. Source inspection shows current-main Dashboard event paths that can still issue `sessions.list` and `chat.history`, but the reported idle flood rate and 8-21s list latency need a live trace.

## Solution Assessment

Unclear as a final fix. Throttling could help, but current main already has partial debounce and in-flight coalescing, so the best repair should be based on measured UI event source and backend list cost.
