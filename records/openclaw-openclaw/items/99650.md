## Summary

Keep open: current main has meaningful mitigations for the Control UI and Gateway session/history hot paths, but the source still has Dashboard/Overview and WebSocket event paths that can issue `sessions.list` and `chat.history`, and there is no merged fix or live current-main proof that fully resolves the reported idle flood and 8-21s session-list latency.

## What This Changes

The issue reports an idle Control UI Dashboard WebSocket connection repeatedly calling `sessions.list` and `chat.history`, saturating the Gateway event loop and degrading responsiveness.

## Best Possible Solution

Keep this open until maintainers capture a live Dashboard/Gateway trace and then choose a bounded fix: stronger Control UI event coalescing/minimum refresh intervals, cheaper paginated/cached Gateway session rows and history reads, or both if the trace shows both layers contribute.

## Reproduction Assessment

No; we do not have a high-confidence live reproduction on current main. Source inspection does confirm the relevant current-main request paths for Overview `loadSessions`, debounced `sessions.changed` reloads, and selected-session `chat.history` reloads, but not the reported 8-21s latency or exact idle flood cadence.

## Solution Assessment

Unclear; UI throttling alone may be only a band-aid if `sessions.list` latency scales with session count, while backend work alone may not prevent repeated requests. The best path is to profile the live request timeline first and then fix the smallest layer or combination of layers proven by that trace.
