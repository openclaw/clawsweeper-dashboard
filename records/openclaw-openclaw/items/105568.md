## Summary

Current main still has separate native and TypeScript node runtimes, and the open narrow parity PR does not implement the requested single-node worker architecture. The proposal remains necessary and aligned, but its protected label and security-, identity-, packaging-, and lifecycle-sensitive ownership shift require an explicit maintainer product decision.

**Likely related people:** steipete is the high-confidence feature owner across both runtimes; vincentkoc and soloclz are medium-confidence routing candidates for node-host lifecycle and compatibility behavior.

## What This Changes

Make the macOS app node a single Gateway-visible capability superset by running the CLI node-host command runtime as an exact-version app-owned worker.

## Best Possible Solution

After the narrow parity PR is resolved, extract a transport-independent TypeScript node command runtime with explicit initialize, readiness, manifest, invoke, update, and shutdown contracts; package its exact version with the app, keep the app as the sole Gateway identity and lifecycle owner, retain Swift only for native capabilities and authenticated app execution, and remove overlapping Swift policy only after signed-app upgrade and failure-mode proof.
