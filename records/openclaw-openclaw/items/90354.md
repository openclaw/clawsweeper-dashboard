## Summary

Keep open: current main and the latest release still only enforce the memory-flush write target and append-only mode; they do not bound, validate, dedupe, or report structured daily-memory append outcomes. A linked candidate fix exists, but it is still open and currently conflicting, so this issue should remain the canonical tracking item until maintainers decide and land the runtime contract.

## What This Changes

Request bounded, pre-mutation validation for `trigger: "memory"` appends to `memory/YYYY-MM-DD.md`, including size and line limits, duplicate or scaffold rejection, telemetry, and possibly a validation hook.

## Best Possible Solution

Land or replace the linked candidate with a narrow built-in daily-memory guard at the existing append wrapper, avoiding shell-style validator hooks or new config surface unless maintainers explicitly approve a secure typed extension point.
