## Summary

Keep open: current main and the latest release still only enforce the memory-flush target path plus append-only writes, while the bounded validation/dedupe behavior is still owned by an open, unmerged candidate PR and needs maintainer product/security review.

## What This Changes

Request bounded and validated pre-compaction memory-flush append semantics for `memory/YYYY-MM-DD.md`, including size limits, validation/dedupe, silent handling, and telemetry.

## Best Possible Solution

Adopt a narrow built-in daily-memory guard at the existing memory-flush write wrapper, preserve non-daily memory-flush behavior, and treat shell/plugin validator hooks as a separate security-reviewed API design.
