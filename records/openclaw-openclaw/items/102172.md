## Label Justifications

- `P1`: The report describes a broken agent/channel workflow where turn-end cleanup can silently kill in-flight model-spawned work for real users.
- `impact:data-loss`: The reported SIGKILL can leave CLI-spawned work half-written with no terminal result surfaced to the operator.
- `impact:message-loss`: The report says no task notification or terminal tool result reaches the parent/channel after the child work is killed.
- `impact:session-state`: The issue concerns claude-cli live-session lifecycle, native tool state, and parent-visible session context drift.

## Summary

Keep open: current main and v2026.6.11 still have the reported claude-cli cleanup/cancel/process-tree kill path, and the related open issues cover sibling symptoms rather than superseding this lifecycle decision.

## What This Changes

The issue asks OpenClaw to stop silently killing claude-cli-spawned background grandchildren at turn end, or at least add telemetry for that cleanup path.

## Best Possible Solution

Choose and implement an explicit claude-cli lifecycle contract: bounded defer plus telemetry if native background work should be supported, or clearer parent-visible failure/documentation if OpenClaw should keep fail-closed cleanup.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should claude-cli turn-end cleanup remain fail-closed for the whole CLI process tree, or should OpenClaw add a bounded defer/opt-out path when Claude-native background grandchildren are still running?

Rationale: The source and shipped release confirm the reported kill path, but changing it affects orphan prevention, process cleanup safety, config surface, and whether native Claude tools may outlive a normal OpenClaw turn.

Likely owner: Vincent Koc

Owner reason: Recent blame/log history for all central lifecycle files points to this contributor.

Owner confidence: medium

Options:

- **Add bounded defer plus telemetry (recommended):** Skip turn-end live-session cleanup only when reliable in-flight background-child evidence exists, cap the drain window, and log/surface pending child state before any forced cleanup.
- **Telemetry only:** Keep fail-closed cleanup semantics but snapshot/log process-tree grandchildren and surface a parent-visible failure signal so silent drops become diagnosable.
- **Keep current cleanup:** Treat Claude-native background work as unsupported under OpenClaw-managed claude-cli turns and document that durable work must use OpenClaw exec/process or external orchestration.

## Reproduction Assessment

Yes from source inspection for the cleanup path, but not from a live end-to-end repro here: current main and v2026.6.11 still route cleanup through managed-run cancellation and process-tree SIGTERM/SIGKILL.

## Solution Assessment

Unclear until maintainers choose the lifecycle contract; bounded defer with telemetry appears safer than an unconditional opt-out because it preserves orphan control while making native background work explicit.
