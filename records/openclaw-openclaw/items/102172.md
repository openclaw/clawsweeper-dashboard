## Label Justifications

- `P1`: The issue describes a real agent/channel workflow where background work can be killed at turn end without a visible failure signal.
- `impact:data-loss`: The reported process-tree kill can discard partially completed Workflow or tool output before it is persisted or summarized.
- `impact:message-loss`: The channel can receive a normal turn result while the expected later Workflow notification or completion payload never arrives.
- `impact:session-state`: The failure is a divergence between OpenClaw's run/session lifecycle and the Claude CLI child process tree's in-flight work.

## Summary

Keep open: current main and v2026.6.11 still close claude-cli live sessions at run end by cancelling the managed run and signaling the process tree, while the open sibling issues are related rather than superseding this lifecycle/config decision.

## What This Changes

Request to add claude-cli lifecycle opt-out and telemetry so Workflow or other native background CLI grandchildren are not silently killed when turn-end cleanup closes the live session.

## Best Possible Solution

Define a bounded claude-cli lifecycle contract that detects pending native background work, emits operator/model-visible telemetry, and only defers process-tree cleanup behind an explicit capped policy while preserving fail-closed orphan cleanup by default.
