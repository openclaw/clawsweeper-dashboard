## Label Justifications

- `P1`: The report describes a real Claude CLI channel workflow where background tool work is killed at turn end without a model-visible failure signal.
- `impact:message-loss`: The central failure is missing task-notification or tool-result style feedback after the Workflow runtime is killed.

## Summary

Keep open: current `main` and the latest release still follow the reported Claude CLI cleanup path, and the remaining choice is the maintainer-approved lifecycle contract for native CLI background descendants rather than a cleanup close.

## What This Changes

The issue asks OpenClaw to stop silently reaping Claude CLI-spawned background or long-running tool grandchildren at turn cleanup, or at least surface telemetry when cleanup kills them.

## Best Possible Solution

Define a maintainer-approved Claude CLI live-session lifecycle contract that keeps process-tree cleanup safe while preventing a turn from looking cleanly finished when owned native tool grandchildren are still running, or at least surfaces a typed failure/telemetry signal before reaping them.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Claude CLI live-session cleanup remain unconditional at turn end, or should OpenClaw add a bounded drain/telemetry contract for in-flight CLI-owned background grandchildren?

Rationale: Source confirms the reported behavior, but changing it affects process-tree cleanup guarantees, orphan prevention, session truth, and possibly new config/default surfaces; automation should not choose that product contract unilaterally.

Likely owner: obviyus

Owner reason: The choice centers on the warm Claude CLI live-session behavior introduced by obviyus and likely needs that area owner's lifecycle direction.

Owner confidence: high

Options:

- **Adopt bounded drain plus telemetry (recommended):** Detect in-flight CLI-owned background children, defer cleanup only within a bounded ceiling, and surface any forced cleanup to the parent/session.
- **Telemetry first:** Keep unconditional cleanup for now, but snapshot/log or otherwise surface killed grandchildren so the silent failure class becomes observable before changing lifecycle behavior.
- **Document unsupported native background work:** Keep cleanup as the contract and route users to OpenClaw exec/process or detached task surfaces for background work that must survive a turn boundary.

## Reproduction Assessment

Yes at source level: current `main` still follows the cleanup-to-cancel-to-process-tree-signal path, and the reporter supplied two live repro rounds. I did not run a live Claude Workflow reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the lifecycle contract: a raw config opt-out is plausible but risky, while a bounded drain plus typed failure/telemetry signal better preserves cleanup safety.
